## Codegen, memory & runtime (Track B)

- **`std:atomic` and a tested multi-worker pattern (#9677, aillu; plumb's queued ask).** Ten `self`-first wrappers over the existing atomics intrinsics on a `Buf` word — `atomicLoadI32`, `atomicStoreI32`, `atomicAddI32`, `atomicSubI32`, `atomicAndI32`, `atomicOrI32`, `atomicExchangeI32`, `atomicCompareExchangeI32`, `atomicWaitI32` (`"woken" | "not-equal"`), `atomicNotify` — each range-checked against its `Buf`. `docs/guide/workers.md` answers, from probes, the three multi-instance questions: top-level code runs in every instance (so it must not write shared memory), `std:buffer`'s pointer lives in the shared memory (instances never overlap), and `--shared-memory` alone exports a memory while `--import-memory --shared-memory` imports one. `tests/vl_shared_memory_bands_test.ts` runs the guide's owner/helper band sum with 0–3 helper Workers bit-identical to a serial model, and its generation barrier across four. No compiler change; existing programs' bytes do not move.
