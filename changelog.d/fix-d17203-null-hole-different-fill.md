## Codegen, memory & runtime (Track B)

- **Fixed D17203, D17204 and D17206** (clause 1): a binding `let m = null` read before a later write fills it with another record now runs inside a function. The read is `null`, and it is delivered as each destination's own null: a plain or annotated binding, a value `if`, a list and a union box. These were invalid wasm, and at an `In | Out | null` destination a wrong `false`. A function reading such a module binding, whose value `if` was typed before the write, is re-asked at the fill. It keeps running where the fill fits, and is otherwise a check error naming the join and asking for an annotation (coordinator ruling, DECISIONS.md). Fixed D17206 too: in a loop, a binding written with an object literal kept the read at the loop's top narrowed to `null`, although the second pass reads the first pass's record. That read is now the binding's open hole, as it already was for a named value. Filed D17205: a `??` over such a read, and an alias of it, are still wrong at emit.
