### D452 — a write-effect summary has no vocabulary for an index sub-path, so an aliasing call over-retires
**loud check reject where a REFINED rule would run · STILL A REFINEMENT, and now a tractable
one: D451 was its unnamed precondition and landed at #2007. Priced below, deliberately not
built.**

    function src(): i32[] | null { return [1, 2] }
    function look(ys: (i32[] | null)[]) { print(ys.length) }
    function body() {
      const xs: (i32[] | null)[] = [src()]
      if xs[0] != null {
        look(xs)
        print(xs[0].length)
      } else { print(0) }
    }
    body()
    // [ERROR]: 'xs[0]' was narrowed by a guard, but the call to 'look' on line 6 can write
    //          it — re-test 'xs[0]' after the call

**Control** (the identical program with a FIELD narrowing instead of a cell — prints `1` then
`2`, because the summary CAN say `look` writes no field):

    type W = { f: i32[] | null }
    function look2(w: W) { print(1) }
    const w: W = { f: src() }
    if w.f != null { look2(w)   print(w.f.length) }

* The two spellings differ only in the separator of the narrowing key, and they get opposite
  verdicts, because `callInvalidatesReal` refines a `.` sub-path by `fnWriteEffects` and
  cannot refine a `[` one — `placeSubPath` (typecheck.vl) builds `pfx = root + "."` and so
  answers `""` for an index target, and a callee that writes `ys[0]` records nothing while a
  callee that writes nothing records the same thing. Both re-verified on `2f1f0621`. The rule
  fails CLOSED, which is the right direction and the reason this is a refinement.
* **D451 WAS ITS PRECONDITION, AND NOTHING SAID SO.** Measured by lifting
  `callInvalidatesReal`'s `keyHasPrefix(key, ak + "[")` leg — not the refinement, but the only
  way to see what the emitter does with the narrowing the refinement would preserve — on the
  base compiler and on the D451 landing:

  | witness | base + lift | D451 landing + lift |
  | --- | --- | --- |
  | this row's own (`i32[]` cell) | runs `1`/`2` | runs `1`/`2` |
  | the same over `new i32` (a BOX cell) | **check-clean INVALID WASM** | runs `1`/`7` |
  | the same over `i32[][][]` | **check-clean INVALID WASM** | runs `1`/`2` |

  So before #2007, refining this rule would have converted a loud reject into check-clean
  invalid wasm for exactly the seven reps D451 covered — the refinement's cost was partly
  NEGATIVE and the row recorded only that the precise rule was "not yet written". It is
  wholly positive now. The two lifted cells are curated as `d452_alias_box_cell` and
  `d452_alias_arr3_cell` and must keep taking their loud check reject until the refinement
  lands, at which point the gate reports them as `→ runs` with the answers recorded there.
* **What closing it takes, priced.** Four edits: an Index arm in `placeSubPath` producing a
  distinguished `[]` component (`ys[0] = …` under root `ys` → `"[]"`, `o.xs[0] = …` under `o`
  → `"xs[]"`), which flows to both its callers (the write leg and the argument-forwarding
  leg); a normalisation in `pathHitsAny` so a QUERY component `[0]` matches the summary
  component `[]` and never matches a field name; and `callInvalidatesReal`'s `[` leg consulting
  `fnWriteEffects` under that normalisation instead of returning true. The `weSums` cycle and
  fixpoint machinery is untouched — the vocabulary widens, the walk does not.
* **The cost is not the four edits, it is the grading.** This rule fails OPEN if the summary is
  wrong, and after D451 the failure is no longer a loud reject: a callee that writes `ys[i]`
  and records nothing now yields check-clean invalid wasm or a trap. It therefore needs its own
  soundness population before it can be believed — nested writes, a write through a free
  variable, a second aliasing parameter, and a recursive cycle — which is the same shape as the
  four `tests/cases/soundness/index-place-narrowing-*.vl` files #2003 had to write, and the
  reason it is priced here rather than built.
* The cost of NOT closing it is bounded and unchanged: any call receiving the array retires the
  cell, so the idiom that pays is `const t = xs[0]` before the call (verified: that spelling
  runs `1`/`2` today).
