# IR-N3 batch 2: variadic push, and the unrolled copy's hoisted iterable (2026-11-23, lane IR-N3)

Two mechanisms, one commit each, stacked on #9638.

## The variadic push (`method push`, 36 tests/cases functions)

`xs.push(a, b)` is legacy's `emitPushMany`. The receiver is staged into the run's frame slot. The
arguments are built as one literal at the receiver's list build (`spreadRunLit`), and the
receiver grows once, with the run copied in by one `array.copy`.

- `wasmEmit.vl`: `emitPushMany` is split into exported phases, which it calls itself.
  - `pushManyRecvOf`: the call's receiver.
  - `pushManyOpen`: the kind, wrapper, backing and frame slots, asked before the receiver as
    before.
  - `pushManyRecvTail`: the receiver's recover and stage.
  - `pushManyTail`: the bulk append and its value.
  - `pushManyRunBuild`: the run's list build, asking no type or slot.
  - `pushManyRunLit(callIx, fnIx)`: the run node, minted once per call and instance, so legacy
    and the IR build one node. Its holder is noted again on every ask, as `spreadRunLit` notes
    it.
- `ir.vl`: `RListPushMany { pmV, pmL, pmAt }`, in the list family.
- `ir_build.vl` `pushManyRhs`: the receiver, then the run built by `arrayLit` at
  `pushManyRunBuild`, typed at the receiver's list. A receiver payload cast, a run rep other than
  the receiver's, or a valued `if` in the run is a named miss.
- `ir_lower_ref.vl`: `pushManyOpen`, the receiver, `pushManyRecvTail`, the run, `pushManyTail`,
  as a value or a statement.
- `ir_verify.vl`: both operands are lists, the value an `i32`; the keyed case `push-many-of-i32`
  is refused under rule 2.

`pushRunLits`, the run memo, takes no row in `scripts/memo-generation-rows.json` (queue ruling
on the pre-review). It is an AST-node reuse keyed by (call, instance), and a hit re-runs the holder
note a fresh mint makes, so no answer it holds can lag a pass.

A spread run (`push(...ys)`) stays a miss (`array spread unrecorded`): the run node is minted at
emission, after the collect walk that records a spread's slots.

## A `for` iterable literal in an unrolled copy

Legacy's full unroll (`emitRangeUnrolled`) emits the body once per copy, with its range variable
bound to the copy's constant (`urSlot`, `urVal`). `arrLitHoistGlobal` then hoists `[i, i]` once per
copy. The IR's own unroll had no such binding, so the same question declined, and the IR built the
literal inline where legacy reads a global.

- `wasmEmit.vl`: `urBindConst(idx, v)` and `urUnbind` are the push and pop `emitRangeUnrolled`
  does; `urDepth` is the stack's depth.
- `ir_lower.vl` `hoistInRangeCopy`: each element of a `for` iterable literal that reads a range
  variable held as an immediate is bound, the hoist is asked, and every binding is undone before it
  returns, with no early exit between. `irRangeCopyHoistSelfTest` reports the depth change across a
  miss; the host test wants 0.
