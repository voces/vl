# IR-N3 batch 3: a variadic push's spread run, and a record's `push` field (2026-11-23, lane IR-N3)

## A spread in a variadic push (`array spread unrecorded`)

`xs.push(a, ...ys)` appends legacy's run literal of its arguments (`pushManyRunLit`, batch 2). The
run is minted at emission, after the collect walk that records a spread literal's slot ordinals,
so it is unrecorded: legacy's `emitArrSpread` keys its group and join slots by the emission
sequence `liKinds.length` (codes 20, 21 and `widenTmpSlot(2000 + 2·seq)`, the F1 note's fallback).

- `ir_build.vl` `spreadLit`: the `spreadSlotIdOf(ix) < 0` refusal is gone. The lowering
  (`spreadList`) reads `seq` at the point legacy's arm reads it, before the first group, and the
  shadow's byte comparison holds on every function the change claims.
- The temp of a minted literal holds its build's type (`arrayLit`'s `bt`, the receiver's list for
  a push run), since no checker stamp reaches it; a recorded literal keeps its own type.

## A record's function field named `push` (d16567_field_arities)

Batch 2's dispatch sent every `push` call with other than one argument to `pushManyRhs`, which
refused a record receiver, so `a.push()` on a record's function field lost the closure call it had
(`closureCallRhs`). Both push dispatches now require a list receiver; the miss sentence
`member call on a record field` leaves the compiler. The loss was deterministic: with or without
an added unused function the cell was uncovered on master, and mode 6 shows no order row.

## Legacy tails the IR calls

- `spreadGroupStash`, `spreadJoinGroups`: a spread literal's group stash and join, now also for an
  unrecorded run (unchanged; `spreadList` already called them).
- `liKinds` (state): `spreadList` reads `liKinds.length` as the emission sequence `seq` of an
  unrecorded literal, before the first group, where legacy's `emitArrSpread` reads it. Lowering
  reads it; the builder does not (coordinator ruling 2026-11-23).
