# D15975 PR 2: `===`/`!==` lower to reference identity, 2026-11-14

Lane E. The second of the three PRs in `2026-11-13-d15975-identity-design.md`, built on step 1
(`2026-11-14-d15975-identity-check.md`). It deletes step 1's bridge emit refusal and closes
D15975. `==` on functions (PR 3) follows.

## What changed

- **Emitter** (`emitIdentityBin`, `compiler/wasmEmit.vl`):
  - Records, lists and maps: both operands are emitted as references and compared with
    `ref.eq`; `!==` adds `i32.eqz`.
  - Unions: a union operand reads the payload slot of its box and casts it to `eqref`, so the
    box is never what is compared (ruling 2). A `null` arm's payload is null, and `ref.eq`
    holds two nulls equal.
  - Function values: compared as `==` compares them, which is already identity (declaration
    and environment). The node is swapped to `==` for the length of that one emit.
  - The closure-eq reservation (`leqScanExpr`, `cloEqNoteBin`) now also notes an identity
    compare, so that path has its frame.
- **The box test follows the representation, not the narrowed type.** A union `let` narrowed
  by an assignment or an `is` test still pushes its box, so the payload read keys on
  `unionBoxStoreTyOf` as well as on the operand's type, and on the union only, never a nullable
  the read was narrowed out of. The matrix's record-union `local_assign` cell was silent
  (`other`) until this was right.
- **Checker.** `x === null` / `x !== null` (a null literal operand) is rewritten to the `==` /
  `!=` null test before its operands are checked, so the existing narrowing, dead-test warning
  and lowering apply unchanged.
- **Lint.** The new `identity-null-test` hint names the `==` spelling. It reads the operator
  token, so it fires on a checked tree as well as on a fresh parse. It is in
  `docs/spec/diagnostics.md` and `lint-rule-scope.md`.
- **Bookkeeping.**
  - The bridge site and its `live-sites.json` row are gone.
  - The probe `identity-eq-record.vl` now runs.
  - D15975 is closed with a `Want:` block.

- **New cases:** `identity-eq-reference-reps`, `identity-eq-union-nullable-fn`,
  `identity-eq-narrowed-union-operand` and `lint/identity-null-test-hint`.
- **Hand probe:** generic instances, un-annotated parameters, capturing closures, nullable
  functions and list elements all answer correctly.
- **Witness:** D15975 `runs`, as filed. `--live-sites`: 1 of 1 LIVE (D14082).
- **Sweep** (fixpoint seeds on both sides, base master `f7758db99` + #7933): 24,312 programs.
  - 0 `runs → not-runs`, 0 bytes-only movers, 0 new traps.
  - 5 output movers, all `→ runs`: D15975's witness and the four new cases.
  - The hint case is a `check_reject` on master, since `p.x` after `p === null` does not narrow
    there.
- **Generics.** `same<T>(a, b) { a === b }` called at `i32`, or `loose(a, b)` at `string`, is
  refused by the instance's re-check: "`===` compares identity, and `i32` has none". It is a
  check error, so no instance reaches `ref.eq` on a scalar. The ruling places that error at
  the call, on the offending argument (A13's inferred operator constraint). Today it sits at
  the body's operator: a position to move, not a soundness gap.
