# Step 7 L6: a recursive alias with list or map arms binds to its expansion's row (D14742), 2026-11-11

The union registry census (`2026-11-11-step7-union-registry-census.md`, cut order item 4) found
71 rows in 64 programs whose canonical key an earlier row already holds. All of them are D14742's
pair: a recursive alias (`Json`, `J`, `P`, `KL`, `KM`, `T`, `V`) beside the inline row its
expansion registered first. `collectDeclaredUnion` bound an alias to an existing row only when
its arms were scalars, literals or records. An alias with a list or map arm kept its own row,
because the alias's own registration is where those arms were marked.

The base is #7152 (cut order item 3) on master `12ceb7b4`.

## Changed

- **An alias whose arms are scalars, literals, lists, maps or `null` binds to the row its
  canonical key finds when that row has no variants** (`collectDeclaredUnion`, with
  `unionArmsAreScalarsOrContainers`). It then marks the row's value atoms, ref-list arms and
  map arms off the declared type (`markValueUnionAtoms`, `markRefArrayArms`,
  `markMapUnionArms` with the row's member set). Sites 87, 102 and 103 ask the canonical key
  since #7152, so they read the bound row's arms.
- **A function arm still keeps its own row.** No program in the census needs it to bind.
- **D14742 is closed.** Its witness prints `3` and `2`.

## The reading

A probe compiler, built in the scratchpad and never refreshed into a seed, counted the
registered rows. Over the 146 `tests/cases` programs that import `std:json` or declare a recursive
list alias, 34 programs register fewer rows: one fewer in most of them, and two or three fewer
where several aliases share one type (`maps/recursive-alias-map-into-union.vl` 13 → 11,
`types/nullable-over-a-union-that-boxes.vl` 11 → 8). In each pair, the bound row has no variants,
so the variant count and every tag stay the same.
