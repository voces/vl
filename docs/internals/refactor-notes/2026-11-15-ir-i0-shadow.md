# IR step I0: types, verifier and a phase-A shadow, 2026-11-15

Lane I. This is step I0 of `ir-design-2026-11.md` §5.3, in the scope agreed with the L1 design lane. Measured on fixpoint seeds:
master `1020438b5` and this branch.

## What landed

- `compiler/ir.vl` (386 lines): the §1.2 node set, the per-function arena (`IrFn`) and a printer
  (`irFnText`).
  - There are 20 right-hand sides and 15 statements; §1.2's `SBr`/`SReturn` value is an `brHas`/`rtHas` flag beside the operand.
  - A rep is an `emit_rep.vl` tree node (`repNodeOfTy`), read as a `RepNode` (`repNodeAt`,
    `repNodeKids`) and matched with no `_` arm. A node index is valid only within the tree's rebuild epoch, so it is never kept
    across one. Lane H's arm-aware id is the stable key (agreed with lane E).
  - `RCoerce` is not in the union yet: it lands at I3 with `coercionAt` and its first caller.
- `compiler/ir_verify.vl` (644 lines): rules 1–7 of §2. Rule 8 arrives with I2's list builder,
  rule 9 with the first pass that moves a check.
  - A verdict names the rule, the node and the reason. The verifier never reports through
    `emitFail`.
  - It is linear: a nested body's exit undoes its own definitions from a log.
  - A valued function must leave its body on every path (rule 5). A global's load and store are checked against the rep `IrFn` records for it (rule 2). A switch takes at most one default (rule 7).
  - The arms for records, lists, casts, tags, maps and closures have no input until the steps that build them (I2–I7). An exhaustive match needs them, but "verified" does not cover them.
- `compiler/ir_build.vl` (737 lines): a phase-A builder over I1's set, which is constants, `PrimOp`,
  locals, `if`/`while`/`break`/`continue`/`return`, `&&`/`||`, direct calls of declared,
  capture-free functions, and globals. Any other construct or rep leaves the function
  uncovered, with a counted reason.
  - The rep tree gives `void` the flat `i32` rep. The builder therefore takes `never`'s
    `RNoValue` for a void result.
  - The builder misses where it would build wrong IR that the verifier cannot see:
    - a tail `if` or loop whose arms yield values (I1 builds it with `siOut`);
    - an operator whose operand is typed at anything but a signed or float primitive or `boolean`. A `PrimOp` carries no signedness until I1 adds it, and the unsigned types share i32's and i64's reps;
    - a global store or load whose rep is not the global's.
  - `shortCircuit`'s local has no wasm slot (`vSlot` -1). At I1 it maps onto legacy's scratch slot, or the function stays unclaimed.
  - The tree's rebuild count (`repNodeGen`) is read before the build and after the verdict. If it moved, the function counts as `rep epoch moved` and no verdict is taken. It never moved on the self-compile.
- **The seam.** `emitFuncCode` calls `irShadowFn` after a function's legacy lowering, but only when the shadow
  is armed. It builds the function, verifies it and discards it. Nothing is claimed, so there is no dual emit
  and no `irClaimed` table yet.
- **Arming.** `irShadowArm` and `irShadowCorrupt` are seed exports. The native host arms the shadow under
  `VL_IR_SHADOW=1` and prints one `[ir] <path>: <n>\t<row>` line per row. The variable is a cache
  bypass. A verifier failure's row carries the printed function.
- `tests/vl_ir_shadow_test.ts` has five tests.
  - A program inside the set builds and verifies, and its armed output equals its unarmed output.
  - Two failing controls must fire: a swapped rep must fail rule 3, and a deleted temp definition must fail rule 4.
  - A program outside the set is uncovered by reason, among them a valued tail `if`.
  - Each hand-built case in `ir_selftest.vl` fails the rule it breaks: rules 1 to 7, a fall-through (rule 5) and a mismatched global store (rule 2).

## Review amendments applied

- `RCoerce` is left out of the union until I3.
- The verifier checks rules 1–7. Rule 8 arrives with the list builder.
- There is one hand-built case per rule, in `ir_selftest.vl`.
- The review's blocking findings are fixed: the valued tail `if` or loop, the signedness of operands, and global reps. So are its smaller ones: the result's closed rep, the epoch guard, the second default arm, and the slot and coverage notes above.
- The builder threads each body explicitly, so the phase-state census counts no hidden global for it.
