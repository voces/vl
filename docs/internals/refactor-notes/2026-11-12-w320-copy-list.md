# The fresh-call copy widens a list of numbers into a list of a wider number, 2026-11-12

Lane w320, stacked on #7385. Checker gate plus emit.

**The gap.** A kept maker `function mk() { { xs: [4] } }` delivered at `{ xs: i64[] }` needs its
list copied with each element widened. The copy gate (`recCopyBoxesAt`) admitted scalars, boxes and
nested records, not a list field, so the call was refused (named cell `d15247_i64_list_field`).

**The change.** `recCopyBoxesAt` (check_fit_rules.vl) admits a list field whose element widens
exactly (`recNumWidens`). The copy level (wasmEmit.vl) widens that field's list on the stack after
reading it (`emitScalarListWidenTop`), at any depth of the copy path (`rcScalarListElem`). The source
is a fresh call's record, so the widened list is the only one; nothing else holds the old one.

**Graded.** `scripts/capability-probes/matrix/kept-maker-delivery-list.matrix.vl`: 0 of 128 ran on
#7385's seed; now 122 of 122 graded, 6 owed refusals, 0 silent. The owed six are the held-binding
cells in both faces: `i32[] is not i64[] … a container never widens implicitly`, since a copy of a
named binding's mutable list at `J` would split it. A list of lists (`i64[][]`) is still refused.
