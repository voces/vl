# IR: the valued integer switch, 2026-11-23

Lane IR-N4, control flow; stacked on the control-flow batch. `ifExprShapeWhy` answered `int
match` for every integer-`match` head, so the IR refused all of them. A diag seed that counts the
gate at the head showed most heads have a plan that declines (too sparse, too few arms), which
legacy writes as the plain chain.

## Change

- `SIntSwitch` gains `isOut`, the out a valued switch's frame carries. It is built at a scalar head
  join where `ifExprSwitchMay` (a new wasmEmit export that `emitIfExprAsLink` now calls for its
  mode-2 gate) holds, the join's valtype is `ifExprJoinVt`'s, and the plan has an `else`. The
  lowering types the outer block by the out, walks each arm with the out as its arm out, and pushes
  it live after `end`, as `valuedBlock` does. The verifier's `endsWriting` covers each arm and the
  else; it reads only IR nodes.
- `ifExprShapeWhy` says `int match` only where the plan takes the chain, or where the scrutinee is
  not a plain place. `refIfLink` refuses a switch only where `emitIfExprRefLink` takes one: no
  chain null, and a plan with an else.
- `declaredVar` (rule 10) requires a slot, so a valued `if`'s slotless out is not a loop value's
  binding.
- A for-in over a list literal inside an unrolled range copy is a named miss. Legacy pools the
  copy's constant literal as a global and reads it with `global.get`; the IR builds the list. That
  mismatch already stood on master for a plain `if`; this change would have exposed it in
  tests/cases.
