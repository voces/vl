# D16205: a number literal an integer binding cannot hold asks the widening join, 2026-11-14

Lane G.

Take `pick<T>(a: T, b: T)` called as `pick(one, 0.5)` with `one: i32`. A number literal binds its
variable after the values beside it (D3541), so `T` was bound at `i32` before `0.5` was seen. The
literal was barred from asking the widening join a typed value asks, so the call was refused, while
`pick(0.5, one)` and `pick(one, h)` with `h: f64` ran. The D2459 ruling says order must not decide
the instance.

## Change (`check_calls`, `check_relate_core`, net compiler lines +5; pin-helper delta 0)

- `bgWidenAskSet` also takes whether the argument is a number literal. The widening-join arm of
  the argument binding declines a literal only when the binding beside it is a float.
- The lossless edges start at `i32` or `f32` (`numWidens`). A float binding holds any number
  literal, which adapts to it (D3541, D3418), so `mix(x, 0.1)` with `x: f32` stays `f32[]`. An
  `i32` binding holds neither `0.5` nor `5000000000`, so either literal widens it, to `f64` or
  `i64`.
- The first attempt let every literal ask. It widened `f32` beside a float literal, so D3418,
  D3541 and two `tests/cases` fixtures moved. That is why a literal is declined beside a float.
