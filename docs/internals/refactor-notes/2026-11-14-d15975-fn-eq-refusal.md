# D15975 PR 3: `==` on functions is a check error, 2026-11-14

Lane E. The third of the three PRs in `2026-11-13-d15975-identity-design.md`, built on the identity
flag (`2026-11-14-d15975-identity-flag.md`), which gives `===` exact `==` parity first. It implements the owner's 2026-11-14 ruling (DECISIONS
A15): `==` is refused exactly when both operands can hold a function in the same position.

## `==` on two function-holding operands (`fnEqRefused`, `compiler/check_identity.vl`)

`tyFnPosition` names where a type can hold a function: `fn` (itself or a nullable of one),
`arm`, `field` or `elem`. It is guarded against recursive types. `==`/`!=` is refused when both
operands can hold one, unless an operand's type already carries an earlier error. The message
names the position and the record field, and advises `===` where both operands have an
identity, else narrowing. `cb == null`, `u == 5` and a record with no function field keep `==`
(`tests/cases/operators/eq-function-legal-shapes.vl`). Every refused position is pinned in
`tests/cases/operators/error-eq-function-positions.vl`.
