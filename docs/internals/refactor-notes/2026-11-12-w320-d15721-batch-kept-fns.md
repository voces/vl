# A program on a shared compiler instance starts with none of the last program's kept functions, 2026-11-12

Lane w320. Stacked on #7364 (D15721's row), which is on #7363 (the `batch-*.vl` witness
convention). Check only.

**The defect (D15721).** `recKeptFnDecl` holds the last pass's kept functions, and the emitter
reads it. `recKeptFnNote` rewrites it partway through each pass, so a program's first pass read
the previous program's list. Its entries are declaration node indices. A later program with a
function at the same index was then treated as kept at the previous program's record, and its
literal was stamped there. Only `vl check --batch --codegen` (and any shared-instance compile)
reaches this.

**The change.** `checkProgram` (check_pins.vl) starts each program with `recKeptFnReset`, plus
`recBuildReset` (the build tables, which no reset emptied between programs) and empty arm-adoption
queues (`recObjLits`, `recArmListLits`, left queued when the last drain ran before the last push).

**How it was found.** A container-size probe over every checker and emitter module at the victim's
start was silent (the list is rewritten before it is read). What found it was logging, in program
2, `recBuildPush`'s callers, `callBuiltTy` and `litRepTyAt`'s answers, and `repStamp`'s writes to
the literal's node. The write came from `recObjLitBuild` via `repStampListBuilt`, reading `mk()`
as built at `J`.
