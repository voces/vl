# D16366, D16367: a lone literal is its one-member set at a list field and a map key, 2026-11-15

Lane G.

Two clause-2 refusals found while ablating D16360 and D16362, both bucket (f). They are new rows,
so the clause-2 map does not list them, and the fix is local in each. A literal union already
works at both places; a lone literal is a `TyLit`, not a union, so the rule never reached it.
Every other container slot stores a lone string literal as its one-member set (D7446, D7449).

## Change (net compiler lines +17; pin-helper delta 0)

- D16366 (`emit_shape_intern`): `nfcIsIntLitUnion` takes a lone `i32` integer literal, so
  `{ f: 7[] }` is an `i32` list field. A lone one past `i32` is coded at its base, an
  `i64` list.
- D16367 (`check_types`, `check_ty_rep`, `check_member_call`, `check_operators`):
  - `mkMapTy` and `tyPinKey`, the key's one writer, store a lone string-literal key as its
    one-member set, as `mkMapTy` already stored the value.
  - `mapKeyRepTy` answers that set's `i32` hash.
  - The three usage pins (`.set`, `.add`, `m[k] = v`) record the key's delivery at the pinned
    set, as D16360 records a first value's.
