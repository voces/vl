# L2 S3.0: one body-order stamp on every bound, 2026-11-16

The first step of the S3 plan (`2026-11-16-l2-s3-plan.md`), marked **identical**. S3.3's solver
walks a callee's bounds in body order, so every bound needs a stamp from one counter.
- Before: only `BND_LET` and `BND_BM` carried one, `cstrSeqNext` (D2218), which the pin pass
  compares to apply a body's writes in check order.
- Now `bndPush` stamps `seq` on every kind from `bndSeq` in `check_iface.vl`, and `cstrSeqNext`
  goes.

## Why it is identical

- **The pin pass's comparison is unchanged.** It reads `seq` only between a `BND_BM` and a
  `BND_LET` row. The old counter advanced only on those two kinds; the new one advances on every
  push. Both are monotonic in push order, so any two let/bm rows compare the same way.
- **Nothing else reads `seq`.** S3.3 will be its first other reader.
- **Rollback is as before.** Like `cstrSeqNext`, `bndSeq` is reset per program and not rolled
  back, so a stamp is never reused after a probe's truncate.
- **Stamping in `bndPush`** writes the field of the record about to be logged (`b.seq = …`). A
  variant that passed `seq: bndStamp()` in each of the nine literals built a seed 485 bytes
  larger; it is not used.
