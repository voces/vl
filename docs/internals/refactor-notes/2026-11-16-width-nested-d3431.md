# Width subtyping at nested depth (D3431, owner ruling (b)), 2026-11-16

Lane WIDTH. The D4054 slot and parameter rewrites now take an existing record that is wider only
inside a nested record (`recNestedWidthPair`, `check_obj_shape.vl`) exactly as they take a flat
wider one.

## What changed

- `objShapeAdapterless` classifies a non-literal source whose every destination field is typed
  alike or is itself such a nested width fit as the field-dropping pair (not D938's "unrelated by
  design" width-field pair), so `objShapeAdapterlessErr` notes it as a slot candidate and the
  dropped-field list names the path (`pet.purr`).
- `wsCandidateAt` admits the pair for a declared record parameter, so the parameter is made
  generic and instantiated at the record.
- `recPend` (D2996's queue) skips the pair: D2996 governs only fields whose storage differs.
- `recDropPlans` (D15093) steps aside for a fresh literal binding whose own layout a use needs,
  which is the D3431 witness: that binding is taken at its own type through the slot face.
- Slot face: an argument is a delivery the checker judges (`slotUse`), a pending parameter rewrite
  a drop leaves is the width phase's (`check_pins.vl` re-runs it after the slot phase), and a write
  through a dropped slot that misfits its real layout keeps the drop and is refused naming that
  layout (`slotWriteWords`). The fresh-literal hint builds nested records fresh.
