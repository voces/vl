# Type hash-cons stage 6b: the delivery walk's breadth cap goes, D16769 (lane H), 2026-11-16

`elabSlotReadDeliveries`, `elabLoopVarDeliveries` and `elabRetSlotOn` (`emit_elab.vl`) each kept a
`seen` list of the (binding or function, path) keys they had walked, and also stopped once that
list held more than 32 entries, answering "delivers nothing" for the rest. The keys already bound
the walk: a key is walked once per query, and there are finitely many. The 32 is gone, so the walk
ends when every reachable key has been walked. Lane SLOT, which owns the delivery walk, agreed; its
part E deletes the walk later.

A fan-out grid (alias, return and argument chains, one binding read by many, and module-level
alias chains, at 30, 33, 64 and 128 links, with an `f64` and an `i32` instance) moved no program,
so on master the trips never decided an outcome. The grid did find a different limit:
`mfrChainDescend` (`mfr_shadow.vl`) stops at 24 hops and refuses a generic function taken as a
value at the end of a 25-alias chain or a 128-deep return chain. That is D16737, the next batch.
