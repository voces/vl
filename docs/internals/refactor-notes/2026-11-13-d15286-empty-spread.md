# D15286: an empty list literal spread contributes nothing at every spread position, 2026-11-13

Lane E. The coordinator picked it as the highest-value open soundness row no lane held. The only
open clause-1 row, D14803, waits on an owner ruling. The other rows with clause-1 titles (D15198,
D15199, D15806, D15808, D15872) now grade as loud check refusals: D15806 is a refutation pin, the
rest refusals the design owes.

## Defect

`...[]` was a loud emit refusal (`a spread's source is not a list this rep knows`) at every spread
position:
- `push(...[])`, `push(2, ...[])`, `push(...([]))`;
- `[1, ...[]]` annotated or not, `[...[]]`, `["a", ...[]]`, `[p, ...[]]`;
- `f(...[])` and `f(1, ...[])` into a rest parameter.

A typed empty binding (`...e`) ran, and so did `[1, ...[2], ...[]]`.

## Mechanism

`spreadDestKind` took the list kind from the first spread source's type. An untyped `[]` has none.
When another source carries a kind, the empty group already emits correctly; only the kind
discovery failed. A push's spread literal is synthesized from its arguments and has no type of its
own. `checkListPushArgs` typed a spread literal from the receiver only when it had an element type.

## Changed

- `spreadDestKind`: when no source yields a kind, it falls back to the literal's own list type.
- `checkListPushArgs`: an empty `[]` push source is typed at the receiver's list type
  (`recordCtxTy`/`nodeTySetGrow`, as a spread literal holding functions already is), on the paren
  node too.
