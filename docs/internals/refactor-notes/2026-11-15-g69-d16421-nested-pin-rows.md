# D16421: a body's open lists written into a call-site list join the call's pin rows, 2026-11-15

Lane G, stacked on D16365 (#8232).

`function f(a) { a.push([]); a[0].push(0.5); return a[0][0] }` with `const v = f([])` built an
invalid module, and `const w: string = f([])` checked clean.

## Mechanism

At the call, `pinBmCstrElems` replays the body's deferred pushes. A value pins only an open list
written at the call (`callSiteOpenListRows`). The first push pins the argument's element with
the body's own `[]`. `a[0].push(0.5)` then targets that inner list, which is not a call-site row,
so it stays open and the call's result reads as a hole.

## Change (`check_demands`, net compiler lines +30; pin-helper delta 0)

- `pinRowsAddOpenLists`: when a deferred push pins a call-site list's element, the open lists
  in that element join the pin rows, bare or in a record's fields, depth 4. A later write to
  them pins them as the direct spelling does.
- Only below the callee's declaration, and once pass 2 has checked its body (`grow`). Above the
  declaration the record spelling is refused by the monomorphizer (D16424). There, pinning the
  field alone built an invalid module, which `decl-order-ab.vl` showed as three new silent
  movers.
