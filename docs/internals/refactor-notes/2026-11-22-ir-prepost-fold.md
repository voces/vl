# IR order check: the early build runs unarmed, and the order check folds into the shadow, 2026-11-22

T12 (coordinator). #9508 (T10) added `$VL_IR_SHADOW=6`, which builds each function where a claim
builds it, before legacy emits it, and builds it again afterwards, as the shadow does. Its early
build ran armed. So an armed check that legacy had already written the function failed it:
`legacyPlainAgrees` (`emitProgram: internal: the IR's plain closure call disagrees with legacy's`).
Every program with such a call failed to compile under mode 6, often after printing some of its
rows. `ir-prepost.vl` read `vl check`'s exit 1 as a verdict, so every row past the failure was
lost without a red. That covers every program importing a `std:array` function that takes a
closure, such as `sort`; IR-N9 reported it at `std:array:261`.

## The 1,448 programs mode 6 lost on #9508

defect) and its failure kept as a `prepost differs: the early build failed the compile` row. Each

tests/cases programs. By directory: 696 `closures/`, 199 `generics/`, 127 `functions/`, 39

`soundness/`, 14 `structs/`, and fewer elsewhere. Every row reads `the IR's plain closure call
disagrees with legacy's`.

An earlier count of 407 took only the programs that print rows under mode 1 and none under mode
6. It missed the programs that print some rows before failing, such as
