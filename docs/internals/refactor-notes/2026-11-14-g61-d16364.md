# D16364: a module container keeps the container it was hoisted at, 2026-11-14

Lane G.

Pass 1.5 declares every module binding before any body is checked, so a function declared above
`const xs = []` reads `xs` at the open list the hoist's quiet pre-pass checked. Pass 2 checked
the initializer again and minted a second open list. `xs.push(1.5)` pinned that one, so the body's
`xs` was never pinned. It was laid out as an `i32` list, and `print(xs[0] + 1.0)` trapped the
compiler, reading `tyAt(-1)` in `sameNumeric`.

## Change (`check_statements`, net compiler lines +34; pin-helper delta 0)

- `letHoistedOpenCtn`: a module binding whose initializer is a `[]`, `Map()` or `Set()` keeps
  the container it was hoisted at, where both are still open, and the literal's node takes it too.
- Two narrowings came from grading:
  - **Both containers still open.** The quiet pre-pass checks a module lambda's body, which can
    pin the hoisted container: a read-only alias takes the default. That moved two `d16121`
    named cells, runs → check reject.
  - **The literal or constructor only.** A call initializer's hoisted row is the callee's.
    Adopting it moved 3 cells in each of 8 `lk-empty-*` and `empty-list-shared-*` templates,
    runs → SILENT.

## Still open

The row's witness reads through `const v = xs` in the body. That alias is read-only, so
`defaultReadOnlyContainer` pins the shared row to `i32` while the body is checked, before the
top-level push. Deferring the default only moves the refusal to the body's scope-close check. Both
are check order, beside D16301.
