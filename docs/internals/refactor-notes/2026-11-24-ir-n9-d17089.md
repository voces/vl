# IR coverage: a staged root reads above the roots staged below it (2026-11-24, lane IR-N9, D17089)

`stageLead` (ir_lower.vl) writes the operands pending below a valued `if` before it opens, each
root left on the stack for its later reader. A root whose definition reads a stack value (a call
on an earlier `if`'s value) read it at the enclosing floor, where an earlier root still on the
stack sat lowest, so `liveTake` refused: `stack value read out of order`. While a root is staged
the reader starts past the run of roots already on the stack from the floor up (`rootsFloor`,
held in `lwRootRun`, stacked in `lwRootRuns` as `lwFloors` stacks the floor, reset per function,
and carried in the fragment frame (`lwSave`/`lwRestore`), since a legacy tail a root writes may
lower a door fragment that resets it); those roots stay below, as legacy
leaves them. The order rule is the pure `liveTakeOk`, which `liveTake` and the keyed
`irStageFloorSelfTest` share: a value above a run of roots is taken, one above a non-root (or a
non-root over a root) is still refused (`tests/vl_ir_shadow_test.ts`).
