# IR I8b part 2: the union return sink, shared, 2026-11-16

Lane IR-C. Part 1 (`2026-11-16-ir-i8b-box.md`) left a function whose union result legacy builds in
its shared return sink as a named miss (`union return sink`). On part 1's tree that miss held 609
corpus functions alone. This part lowers the sink the way legacy writes it. `CLAIMED` stays empty,
and no emitted byte moves.

## What landed

- **A return in a sinking function** (`fnUses.unionSink`) whose value the box writer just closed
  with `struct.new $uBox` (`uBoxNewIsLast`) pops the box into the sink pair (`uBoxSinkToPair`) and
  branches to the exit block. Legacy's `emitUnionRetSink` makes the same test on the same bytes.
  Both helpers are now exported from `wasmEmit.vl` and shared, not copied.
- **The exit block is wrapped round the body after it is written** (`sinkClose`), as legacy's
  `emitFuncCode` closes a sinking body: the body gains a leading `block` with no result, and the
  span rows shift by its two bytes. After the block's `end`, the pair is read back and boxed once.
- **A delivered call is not boxed** (`box of a call`, a named miss). On one corpus function
  (`emitListIdxBackRef`'s shape), legacy's ladder boxes the call as the `null` unit where the IR
  reads an `i32`, and mode 3 differed. The cause is not traced yet; the miss keeps every claimed
  byte identical until it is.
