# L2 S3 plan: one solver at the call, 2026-11-16

S3 of `l2-inferred-interfaces-design.md` §8 is the step that makes a call solve its callee's
scheme (§4.1). Today that call replays the callee's tables. This note is the plan: the PR
sequence, the rows each PR grades, what it depends on, and D15161 re-ablated. Docs only. No S3
code starts until lane STORE has removed `fnTagRedecide` and the coordinator says so.

## Where S3 starts

- **S2 is done** (#8500, #8518, #8529, #8538, #8545). Every constraint table is a kind of `Bound`
  on its owner's `Iface` (`compiler/check_iface.vl`, `BND_PRINT` … `BND_ARG`). A call reads the
  callee's rows merged with module scope's, through `bndNextRow`.
- **The replay is unchanged.** `callFtyPinCstrs` (`check_calls.vl:2604`, 360 lines) still runs the
  steps in a fixed order. The same validators are also called from four other sites:
  - `fsbRecheckOne` and `declCstrsAtBinding` (`check_assignable.vl`);
  - `judgeHoleLambdaAt` (`check_calls.vl`);
  - `ufcsRevalidatePins` (`check_member_call.vl`).

  Each sets the owner modes around the calls (`substSelfOwnerSet`, `substNestModeSet`,
  `cstrOwnedStrictSet`, `cstrSetOwnersSet`): 26 sites in `check_calls.vl`, 18 in
  `check_assignable.vl`.
- **One walk keeps scanning every row.** `validateBinCstrs` asks `gnotDeadAtPin` of each row before
  the ownership test, and that call can mint arena types. S2 left the walk as it was (#8545), so the
  solver is where it changes.
- **The scheme closes at the loud body check** (design §3.2, M3's census). Mono's per-instance
  re-check (`RB_MONO`) still produces the per-instance coercion records (M3's caveat in §10), and
  S3 keeps it.

## The dependency on lane STORE

`fnTagRedecide` (`check_fn_tag.vl:547`) re-runs the tag decision after elaboration, at
`emit_sections.vl:8028` and `:8038`. That is a second storage decision. The design (§10) requires
one decider, and requires that the solver never decide storage. S3's arrow rule produces closed
per-shape signatures of a hole function parameter's calls. If storage is still re-decided after
elaboration, a bundle-or-not choice made over those signatures could be overturned at emit. So:
- S3.0, S3.1 and S3.2 below are storage-free in substance, since they move no decision. They still
  wait, as the brief requires.
- S3.4's arrow and contextual-lambda PRs depend on STORE in substance, and must not land before it.

## D15161, re-ablated

The design (§6.2) asked for this before S3 grades the row. Run at master `078e4116`; the table is
now in the row itself.

| ingredient removed | outcome | needed? |
| --- | --- | --- |
| `inc0` (one function value) | still refuses | no |
| the differing result | still refuses | no |
| the function values (a map of `i32`) | still refuses | no |
| the declaration order (`run` below the call) | runs, prints `1.5` | **yes** |
| the parameter (read in the binding's own scope) | runs, prints `1.5` | **yes** |
| the hole (both annotated) | runs, prints `1.5` | **yes** |
| the hole on the binding only (parameter annotated) | check passes, loud emit reject | **yes** |

What it changes for S3:
- **D15161 is a container row, not an arrow row.** Its refusal is the read-only map floor
  (`maps/error-infer-param-map-not-pinned.vl`), and function values are incidental. S3.4a claims
  it, not S3.4d.
- **The floor is order-dependent.** Declared after the call, the same programs run, because the
  call has pinned the hole before the body is read. Filed as [D16714](../inventory/D16714.md).
  This is the S1/S3 boundary: §3.1 orders callees first, and that order is what exposes the floor.
  The floor was measured as hiding 10 wasm traps and 1 wrong output when it was added, so S3.4a
  must re-run that population when it lifts the floor.
- **A neighbouring spelling fails at emit with an `internal:` message.** Annotating only the
  parameter does it: [D16715](../inventory/D16715.md), a slot holding two hole functions with
  different results at one delivered function type. It is a container-of-functions delivery, so
  S3.4a re-grades it. If the fix is storage, it moves to S3.4d.
