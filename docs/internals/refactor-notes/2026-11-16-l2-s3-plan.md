# L2 S3 plan: one solver at the call, 2026-11-16

S3 of `l2-inferred-interfaces-design.md` §8 is the step that makes a call solve its callee's
scheme (§4.1). Today that call replays the callee's tables. This note is the plan: the PR
sequence, the rows each PR grades, what it depends on, the records agreed with lane STORE, and
D15161 re-ablated. Docs only. The arrow rule (S3.4d) is STORE's and lands in stages, each keeping
one storage decider (below).

## Where S3 starts

- **S2 is done** (#8500, #8518, #8529, #8538, #8545). Every constraint table is a kind of `Bound`
  on its owner's `Iface` (`compiler/check_iface.vl`, `BND_PRINT` … `BND_ARG`). A call reads the
  callee's rows merged with module scope's, through `bndNextRow`.
- **The replay is unchanged.** `callFtyPinCstrs` (`check_calls.vl:2604`, 360 lines) still runs the
  steps in a fixed order. The same validators are also called from four other sites:
  - `fsbRecheckOne` and `declCstrsAtBinding` (`check_assignable.vl`);
  - `judgeHoleLambdaAt` (`check_calls.vl`);
  - `ufcsRevalidatePins` (`check_member_call.vl`).

  Each sets the owner modes around the calls (`substSelfOwnerSet`, `substNestModeSet`,
  `cstrOwnedStrictSet`, `cstrSetOwnersSet`): 26 sites in `check_calls.vl`, 18 in
  `check_assignable.vl`.
- **One walk keeps scanning every row.** `validateBinCstrs` asks `gnotDeadAtPin` of each row before
  the ownership test, and that call can mint arena types. S2 left the walk as it was (#8545), so the
  solver is where it changes.
- **The scheme closes at the loud body check** (design §3.2, M3's census). Mono's per-instance
  re-check (`RB_MONO`) still produces the per-instance coercion records (M3's caveat in §10), and
  S3 keeps it.

## The dependency on lane STORE

`fnTagRedecide` (`check_fn_tag.vl:547`) re-runs the tag decision after elaboration, at
`emit_sections.vl:8028` and `:8038`. That is a second storage decision. The design (§10) requires
one decider, and requires that the solver never decide storage. S3's arrow rule produces closed
per-shape signatures of a hole function parameter's calls. If storage is still re-decided after
elaboration, a bundle-or-not choice made over those signatures could be overturned at emit. So:
- STORE's order: its shadow (#8507) has merged. Next come its producer sources, then a switch per
  class, then `fnTagRedecide`'s deletion.
- S3.0 to S3.3 and S3.4a to S3.4c move no storage decision, so they need nothing from STORE and
  start now (coordinator, 2026-11-16).
- S3.4d (arrow) is STORE's, staged so there is never a second decider (coordinator's ruling,
  2026-11-16). The earlier line "S3.4d must not land before `fnTagRedecide` is deleted" was
  circular, because STORE's remaining late flips (classes T, G, S and the P residue) need S3.4d's
  per-call-shape results first. The stages:
  1. S3.4d-1 is the solve only. The arrow rule writes per-call-shape member results as `SetBind`
     solver output beside `InstReq`. Nothing reads them for storage, so it is byte-identical.
  2. S3.4d-2 onward take one class per PR. `fnTagDecide` reads the results, and that class's
     branch of `fnTagRedecide` is deleted in the same PR.
  3. The last such PR deletes `fnTagRedecide`. S3.4e (contextual lambdas) follows.
- The boundary (agreed with STORE, 2026-11-16):
  - STORE owns the `BK_ARROW` solver tables (per call shape: callee, set, member results), the
    call-site consumers in `check_fn_tag.vl` and `check_set_bind.vl`, and the `fnTagRedecide`
    deletions.
  - L2 owns body order, the `seq`-ordered rule walk (`solveRules`, S3.4a), the other rules
    (S3.4b, S3.4c), S3.5 and S3.6.
  - The arrow rule plugs into S3.4a's walk. It adds its kinds to `ruleKinds`, adds an arm to
    `solveRule`, and deletes the validator it replaces. It needs nothing from S3.4b or S3.4c.

## The records STORE's producer writes (agreed with STORE, 2026-11-16)

STORE builds the check-time producer of set-binding facts as the first slice of S3's solver: the
call's instantiation of a `BK_ARROW` bound. S3 adopts its records unchanged.
- **`HandBack` is a `Bound` kind, `BND_HANDBACK`, on the owner's `Iface`.** A declaration hands back
  its parameter: every value it returns is that parameter's. `on` is the parameter's type, `a` its
  position, `site` the body, `fn` the owner. It is a body fact, so it is checked once and belongs
  in the scheme.
- **`SetBind` is call-keyed solver output, not part of the `Iface`.** It is kept beside `InstReq`,
  because an `Iface` is checked once and instantiated per call, so it cannot hold a row that
  differs per caller. It is flat, in `Bound`'s scalar fields, one row per (call, parameter, set),
  as the design's §4.3 records:
  - `site` is the call, `fn` the callee;
  - `a` is the parameter position, `on` the parameter's type;
  - `b` is the set;
  - `c` is the caller's parameter a handed-on argument reads (the `BK_INST` edge), or -1 when the
    argument carries the set itself. The caller's declaration is the one enclosing `site`, so the
    row needs no field for it.

  It holds nothing about storage, member results at the call shape, or instance keys.
- **The parameter is a position, not a type variable.** `Iface` has no `vars` yet, and a position
  stays valid after S3.
- A call through a set inside an instance is not stored. It is the join of a `SetBind` with the
  parameter's `BK_ARROW` bounds (their `site`s).

**Body order lands per kind in S3.4a–c** (coordinator, 2026-11-16). Each validator is one loop over
its kind's rows, with its own state and early stops (`validateNestCstrs` and `validateIsCstrs` stop
at the first error, `validateMemCstrs` accumulates `told0`). Walking bounds by `seq` across kinds
would first need all eleven split into per-row functions, which the S3.4 rules then delete. So each
S3.4 rule PR moves its own kind onto a per-row rule in the `seq`-ordered solver loop, deletes the
validator it replaces in the same PR, and lists its moved diagnostics, as S3.3 would have.

S3.4's remaining kinds (`BND_LET`, `BND_BM`, `BND_RET`, `BND_BIN`, `BND_NEST`, `BND_PRINT`) keep
today's judgement, `assignableExpr` and the operator and print tables, but are called by the
solver. They need no rule of their own, so S3.6 can retire their replay without grading.

Every S3 PR runs §8's gates: two refreshes cmp-identical, `regress.vl` 0 runs → not-runs,
`decl-order-ab.vl` with no new clause-1 mover, the full gate, and the 227 hole and inferred
matrices losing no `runs` cell. An **identical** PR also fingerprints byte-identically against its
predecessor's fixpoint seed, both taken from one worktree: 25 programs embed their own path. A
**graded** PR runs `check-filed-witnesses --strict` on the rows it claims, plus each row's
annotated spelling and its declarations-first order (design §6.3).

The instance rows (§6.1: D15041, D16272, D16423, D16425, D3286, D4173, D4719, D4883) are S4's, and
D1968 is too. None is claimed here.

## D15161, re-ablated

The design (§6.2) asked for this before S3 grades the row. Run at master `078e4116`; the table is
now in the row itself.

| the hole on the binding only (parameter annotated) | check passes, loud emit reject | **yes** |

What it changes for S3:
- **D15161 is a container row, not an arrow row.** Its refusal is the read-only map floor
  (`maps/error-infer-param-map-not-pinned.vl`), and function values are incidental. S3.4a claims
  it, not S3.4d.
- **The floor is order-dependent.** Declared after the call, the same programs run, because the
  call has pinned the hole before the body is read. Filed as [D16714](../inventory/D16714.md).
  This is the S1/S3 boundary: §3.1 orders callees first, and that order is what exposes the floor.
  The floor was measured as hiding 10 wasm traps and 1 wrong output when it was added, so S3.4a
  must re-run that population when it lifts the floor.
- **A neighbouring spelling fails at emit with an `internal:` message.** Annotating only the
  parameter does it: [D16715](../inventory/D16715.md), a slot holding two hole functions with
  different results at one delivered function type. It is a container-of-functions delivery, so
  S3.4a re-grades it. If the fix is storage, it moves to S3.4d.
