# IR verifier: a packed list literal's elements (2026-11-20, lane IR4)

The per-arm door measurement after #9202 found 11 `node-in array: miss verifier rule 2` rows in
the `u8` arm (`tests/cases/arrays/u8-union-scalar-arm.vl`, `tests/cases/std/fs-write.vl`). The IR
builder produced a fragment its own verifier rejected. The miss was caught, and nothing shipped:
those functions miss earlier as whole functions, and mode 5 claims none of them.

## Mechanism

`arrayLit` deliberately builds a packed list's elements as plain i32s, which its backing
truncates. The lowering writes them and then `arrLitPackedShortTail`, which is legacy's own packed
build. The verifier's `RMakeList` rule required every element at the list's element rep. That rep
is `u8` wherever the list's rep is the packed one, as for a literal delivered into a
`u8[] | i32` union, so those fragments were refused.

## Fix

`RMakeList` admits an i32 element where the element rep is `u8`, which is the builder's documented
contract. A door miss on a verifier rule now carries the verifier's message
(`verifier rule 2: an element's rep is not the list's`). That message is how this one was found.
