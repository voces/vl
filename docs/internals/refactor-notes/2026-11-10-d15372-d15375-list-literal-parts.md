# A fresh record binding as a list part is built where the list is; a generic call's part refuses, 2026-11-10

D15372 closes (runs). D15375 closes at its target, a check reject at the call's part. D15652 is
filed for the capability left over: a call's fresh record as a part.

**The gap.** `const r = { f: 7 }; const ws = [...xs, r]`, with `xs`'s records built at the wider
`J`, built invalid wasm. `recListLitBuild` left `r` out of the refusal, because a fresh binding can
be built where the list is, but nothing built it there, so the list stayed unbuilt. `const o =
id({ f: 1 }); [xs[0], o]` with `id` generic also built invalid wasm. Its part waited on the rep
row, and once the rep rows ran the table no longer held `xs[0]`'s build. So both parts read as
their own storage, and neither the stamp nor the refusal fired.

**The change.**

- check_fit_rules.vl: `recHeldLitPartStamp` stamps the literal of the fresh record `const` (or
  unwritten `let`) that a part reads at the list's build, and refuses its other own-storage
  deliveries (`recHeldAsgStamp`), as D15237 does for a push.
- check_bind_adopt.vl: `recListLitBuild` uses it for each own part. A part waiting on a rep row is
  judged now with the other parts when a held part pins the list. It is then refused with the
  call message already in place for a plain function's call.

**Graded** (master `2e71e5a1` → now):
- D15372's repro: invalid wasm → runs `7`.
- The other D15372 spellings run: `[xs[0], r]`, `r` before the spread, `r` inside a function, `r`
  as an unwritten `let`, and `r` also read or handed to a hole function at its own type.
- D15375's repro, the direct `[xs[0], id({ f: 2 })]` and a hole function's held call: invalid
  wasm → check reject at the call.

**Not shipped.** Delivering a call part with `recAdoptNote` (as `recHeldBindAdopt` does for a held
call) runs `[xs[0], os0()]` and `const o = os0(); [xs[0], o]`. But when a maker's call is held at
its own type too, it traps the compiler in `recStoresAgree`, and it does not build a generic's
call. That is D15652.
