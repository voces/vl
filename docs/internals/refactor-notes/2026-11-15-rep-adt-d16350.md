# Rep ADT stage 3, D16350: an instance's anonymous row at the instance's types, 2026-11-15 (lane E)

This is the prerequisite for step 3c of [the stage 3 design delta](2026-11-15-rep-adt-stage3-design.md).
The [3a shadow](2026-11-15-rep-adt-stage3a-shadow.md) left 4 field rows whose storage type has no
rep. Before 3c, the coordinator asked a question: does a template's own anonymous row ever reach
emission?

## Two kinds of row behind the 4 mismatches

Emitted-code use was counted with a scratch counter, never committed. It wraps every read of
`sHeapIdx` in the code emitters: `emit_bytes`, `wasmEmit`, `emit_classify`, `emit_eq_rows`,
`emit_fn_scans`, `emit_obj_lit_fits`, `emit_ref_list_kinds`, `emit_union_atoms` and
`emit_union_casts`.

| cell | rows | minted in | emitted-code uses | what it is |
|---|---|---|---|---|
| `d15270_generic_mk` | 1 | an instance of `mk` | 11 | the instance's own row, its field `x` recorded at the template's `T` |
| `d681_refused_spelling_pin` | 3 | the whole-program pass | **0** | the generic templates' own rows. Each instance uses its own shape row (`{x:i32,y:i32}` 22 uses, `{x:i32}` 19, `{x:f64}` 19). |

- **The first kind is [D16350](../inventory/D16350.md).** An instance's row carried the template's
  open storage type. Its codes followed the instance only for primitives, so a list or record
  instance was refused at emit.
- **The second kind is a template's own row.** It reaches the type section and no emitted code.

## The change

**`anonMintRowFor` (`emit_collect.vl`).** For a field whose template type is open, it reads the
closed type the elaboration recorded for that instance: `elabNodeTyAt`, keyed by the instance key.
It uses that type for:
- the field's storage type;
- its code, through `nameFieldCodeTy`, after D15554's primitive rule;
- a record field's row, through `anonStructRowOfTy`, the type half of `anonFieldStructRow`
  (`emit_classify.vl`), split out.

A field whose template type is already closed keeps its path.

**A template's own row, known by its mint.** The 3a shadow (`emit_fc_shadow.vl`) inverts the
existing mint maps:
- `sLitMintRow` (literal → row) and `sLitMintFn` (literal → minting instance);
- `sLitIdRow`, a tagged set's id row, which is always an instance's.

A template row is an anonymous row that some literal mints at instance -1, that no instance's mint
shares, and whose field has no rep. The shadow buckets it as `template`, not as a mismatch, and 3c
will assert the same. The fact needs no new compiler table: a per-row column first added for it
raised the phase-state census.

Two attempts to mark the template row by a type test over-marked:
- "a field value's own type is open" marked rows used in 566 programs;
- "the storage type contains a type variable" marked used rows too. A closure field with a
  generic signature has a rep.

**For 3c.** On the corpus, every emitted row's storage type now has a rep. A row whose field has no
rep is a template's own row, known by its minting instance, and no emitted code uses it. 3c's
derivation answers it by that kind and asserts the rest. Deleting the unused template rows from the
type section is a later, byte-moving cleanup, not part of 3c.
