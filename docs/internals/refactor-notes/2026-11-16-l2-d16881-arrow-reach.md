## What decides the refusal

D16881's witness, one ingredient removed at a time:

| ingredient changed | outcome | needed? |
| --- | --- | --- |
| `const ll = id2([half, inc0])` removed | runs, `4 1.5` | **yes** |
| `const ll = [half, inc0]` (no generic holds it) | runs, `4 1.5` | **yes**: a generic instance holds the list |
| `const ll = id2(half)` (a lone member) | runs, `4 1.5` | **yes**: the list of the set |
| one call of `app`, a runtime index (`o.l[i]`, `i` = 1), holder kept | emit refusal | no: one instance is enough |
| the two calls in the same order, index 0, holder kept | runs, `4 4` | the static index is what saves it |
| the same order, a runtime index (`i` = 0), holder kept | emit refusal | **yes**: the constant index |
| two orders, a runtime index, holder removed | runs, `1.5 4` | no: the orders alone are fine |

So the refusal is decided by:
1. **A tag decision.** A generic instance holding the list of the set forces the set's tag
   decision, so the instance of `app` keeps the members at one signature.
2. **Mono's value flow.** `monoFlowReadSet` turns a constant index over a literal into a direct
   call. That is the only reason D16878's same-order spelling runs.

Neither the number of instances of `app` nor their keys decide it.

## What follows for moving the refusal to check

- (1) is available at check: `elabPrepare` settles the tag decision, as D16881's row measured.
- The callee's closed signature at an instance is the instance vector (#8836) substituted into
  the callee's type, and the arrow facts give each member's result there.
- (2) is not available at check. A check-time refusal built from (1) and the arrow facts alone
  refuses the same-order spelling, which runs today (runs → not-runs). The coordinator's rule
  forbids that.

So D16881 needs mono's static read resolution (a constant index into a literal held through
a parameter) answered at check, or moved into the elaboration, before the refusal can move. That
is a value-flow question, not an instance-enumeration one.
