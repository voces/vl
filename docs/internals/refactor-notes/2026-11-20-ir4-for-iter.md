# IR list literals: a `for` walk's literal iterable at the door (2026-11-20, lane IR4)

This is step 1 of the f32 sequence, the `for iterable` class, built as IR-REV's option (b).

## The decision is a predicate; the hoist is a plan

Legacy's `emitForInList` used to set `gForIterLit` around emitting its iterable. `forLitHoist`
read that flag, so the decision depended on the walk being emitted at the time. A fragment
lowered at the door could not see it, and the IR missed `array for iterable`.

- **The predicate.** `arrLitIsForIter(arrIx)` now asks whether the literal is the
  `unwrapParen(fiIter)` of some `ForIn`. It scans the arena on demand, memoised in `forIterLits`
  and reset with the emitter's state. `gForIterLit` is deleted.
- **The plan.** `forLitHoist` is now `forLitHoistPlan`, which writes no instruction. It returns
  the module list's global, `-1` (build as usual) or `-2` (failure).
- **One entry point.** `arrLitHoistGlobal(arrIx, fnIx, arm)` picks the element form for the f64,
  string and i32 arms. It is an exhaustive match over `ArrLitArm`.
- **Who calls it.** Legacy's three arms call it and emit a `global.get`. So does the IR's
  `makeList`: when it returns a global, the IR skips the elements and reads that global. A hoisted
  literal whose lowered element is not an immediate misses as `for iterable element` (2 sites).

## Why the predicate's population is the flag's

The old flag was set by `emitForInList` alone, for a non-map iterable, at `unwrapParen(iterIx)`.
The predicate holds for every `ForIn` whose `unwrapParen(fiIter)` is an `ArrayLit`. Here is every
other path that lowers a `ForIn` iterable, and why none of them reaches a hoisting arm (f64,
string, i32):

- **`emitListUnionFor` and `emitMapUnionFor`** emit the iterable with `emitExpr`. Both are gated
  on `exprUnion(fiIter)`: `luForUnionIter` gates the first and `lmForUnionArms` the second. A list
  literal's own type is one list type, never a union, so neither path sees one.
- **`listFitShadowIsRef`** returns before anything is emitted.
- **A map walk (`mapRecv >= 0`)** goes to `forInMapList`. Its iterable is a map, not a list literal.
- **The IR's own lowering of a claimed function's `for` walk** reaches `makeList`, which asks the
  same predicate and the same plan. Mode 3 is byte-identical.

A nested inner literal and a call-argument literal are not `fiIter` itself, so neither the flag
nor the predicate holds for them. So the two sets are the same. The 0-differ A/B below measures
that, but it does not replace the argument.
