# D17566: a hole receiver's `?.` field under `??`, planned at the instance's record row (lane COV-UNION, 2026-11-25)

## Mechanism

`print(v?.d ?? 0)` in `function g(v)`, instanced at `A = { d: i32 | null }`: every `??` plan
legacy and the IR share (`coalNextArmOf`, `coalOptArmOf`, `coalFieldPlanOf`) reads the
template's hole types, so legacy refuses and the IR missed (`coalesce nulRef none`, then
`coalesce optional next`). The annotated `g(v: A)` takes the field arm (`coalFieldPlanOf`), whose
bytes are the target.

`coalFieldPlanOf`'s decision is now `coalFieldPlanAt`, taking the receiver node, the field name
and the struct row (or narrowed variant) as arguments; `coalFieldPlanOf` passes what it passed
(`structIndexOfExpr`), so legacy's bytes do not move. `coalFieldPlanOfOpt` asks it for a `?.`
receiver at a given row. The IR's `coalBox` takes the field arm on the `opt` rung where the
receiver's checked type holds a type variable and its rep at the instance is a non-null record
(`optRecvInstanceRow`, the row `structIndexOfTy(repTyOf(rep))`); `coalField` and the lowering's
`coalUnionField` read an `OptMember` receiver at that row. The unused `recvAgain` is removed.
