# L2: a declared type parameter's binding joins with a later f64 argument, 2026-11-17

[D15041](../inventory/D15041.md), the residue of D2459's numeric join, now closed.

## What refused it

`mix(u, v)` in `w2<U>(u: U, v: f64)`: the template binds `T` at `U` from `u`, then meets `v: f64`.
`U` is no number, so no join is asked, and the call is typed `U[]`, silently dropping the `f64`. The
instance `w2<i32>` re-checks with `u: i32`, where D2459's join would give `f64`. But an instance
joins only a call its template joined (`callNumJoined`): joining in the instance alone handed back
`f64` from a call the template typed `U[]`, which built invalid wasm when it was tried. So the
instance refused instead.

The un-annotated spelling, `w2(u, v: f64)`, already ran: the hole `u` binds eagerly, and the template
types the call `f64[]`.

## The change

`bindGenWalk`'s widening arm also fires when the variable's earlier binding is the body's own type
parameter and the new argument is a non-literal `f64` (`bgWidensDeclaredParam`). `f64` is the widest
number: `i32 ⊔ f64 = f64`, and `i64` joins no float. So the join is `f64` at every instance whose
parameter joins it, and is refused at any other. The template re-checks the call at `T = f64` and
marks it joined; the instance's re-check then joins too, and both agree.
