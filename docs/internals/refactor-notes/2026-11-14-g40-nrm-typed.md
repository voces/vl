# D16052: a niche-nullable map value's inner member is read by type, 2026-11-14

Lane G. `nulRefMapValInnerOfTy` (emit_shape_rows) took a map value union's atoms through
`unionArmsOfTy`: the label's row, else `msMemberAtomsOfSet` of its type's set. For a set with
no row, that second leg reads `msFreeAtoms`. It returned the single non-null atom's spelling.

- Two callers tested only `!= ""`.
- `emitMapValSlot` passed the spelling as `bare`, the name `ensureRefElemTys` mints the vals
  ref-list row under.

`nulRefMapValHasInner` replaces it and returns a boolean. It counts the non-null members of
the type's keyed row, else of its set. `emitMapValSlot` names the row from the inner type with
the ref-list layer's own `rlMintNameOfTy(tyPeelNul(kindTy))`, which `rlInternOfTy` already uses.
`unionArmsOfTy` and `unionArmsOfSetTy` have no callers left and are deleted.

## Probe

Over 24,020 programs, 206 programs make 25,167 calls.

| check | result |
| --- | --- |
| single-non-null answer, atom count vs typed count | 0 disagreements |
| `string` test, atom vs type | 0 disagreements |
| the inner member's arena index ≠ `tyPeelNul(ty)` | 11 programs; harmless, since the classification already read `tyPeelNul(ty)` |
| `rlMintNameOfTy(tyPeelNul(kindTy))` vs the atom, where it becomes `bare` (85 programs, 1,276 calls) | equal except for function-typed members, 9 programs |

The function-typed difference is `((i32)=>i32)` where the atom was `(i32)=>i32`. That
parenthesised form is the one the ref-list layer stores such rows under. The witnesses I could
run print byte-identical output before and after:

- `store-null-nullable-value-map.vl`
- `diamond-record-deep.vl`
