# IR coverage: the memory-management intrinsics as `RMemOp` (2026-11-21, lane IR-N7)

After the memory accesses (#9310), the `tests/cases` census's `intrinsic none` still held the
memory-management intrinsics, about 700 functions summed per callee name: `__heap_base__` 264,
`__memory_size__` 91, `__memory_fill__` 90, `__memory_grow__` 89, `__memory_copy__` 89 and
`__heap_limit__` 88. Most are std's `Buf` and allocator helpers, counted once in every test that
imports them. Legacy wrote them in five arms of `emitCallCoreIdent`: each operand as it stands, then
one instruction, a heap-window `global.get`, or the shared flag's constant.

## Change

- **One plan, one tail (wasmEmit.vl).** `memOpCallNamed` is the routing (the spelling, with no
  binding owning the name). `memOpPlanOf` gives the arm, a closed set `MemOpArm` (`size`, `grow`,
  `fill`, `copy`, `heapBase`, `heapLimit`, `shared`), and legacy's arity and missing-heap-window
  failures verbatim. `memOpTail` writes the arm's instruction. Legacy's five arms are one,
  `emitCallCoreMemOp`, and `emitHeapWindowRead` and `emitCallCoreMemBulk` are gone. The names are
  disjoint from every arm between their old positions, so moving the size, grow, heap and shared
  arms up to the bulk pair's position changes no routing.
- **`RMemOp { moArgs, moAt }`**: the verifier holds every operand at i32, and the result at i32,
  or no value for the bulk pair. As a statement, a non-void op's value is dropped, as
  `emitCallStmtIdent` drops it.
- **Named misses:** `memory op plan`, `memory op operand coercion` and a short-circuit operand.

## Measured

Stacked on #9310. The PR body has the census rows, taken against #9310's merged head with fixpoint
seeds on both sides. On `tests/cases/memory`, `std` and `loops`, covered = matched rose 5,555 →
5,878. The row `tests/ir-shadow-rows/mem-op.vl` has 7 functions, one per arm and a discarded
grow; all 7 are `intrinsic none` on the base seed and covered and matched here.
