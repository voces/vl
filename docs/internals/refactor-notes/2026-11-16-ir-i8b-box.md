# IR I8b+N1 part 1: boxed nullables, the box through legacy's writer, 2026-11-16

Lane IR-C. I8b, which retires `boxSeat`, and N1, the boxed nullable rep, ship as one step. A box
op with no rep to deliver into unblocks nothing on its own. The census on I8a's tree counted 0
functions held by `box delivery` alone, and 1,179 corpus functions held by box delivery together
with boxed nullable reps. The design is `2026-11-16-ir-i8-coercion-ops.md`. `CLAIMED` stays empty,
and no emitted byte moves.

## What landed

- **The boxed nullable rep (discipline 4: `{tag, payload}`) is a value rep** for variables,
  parameters, results and temps. It is admitted only at that discipline. The atom, niche and
  sentinel disciplines are N2 and N3.
- **`RToBox { v, at }`.** `deliver` appends it where the destination is a boxed nullable and the
  checker records a box at the node (`boxOwedAt`).
- **The value hole.** `RToBox` lowers by running legacy's `emitUnionBoxArg` unchanged, its value
  supplied by the IR's operand.
  - `emitExpr` answers the node `irHoleIx` names by calling the IR's writer. This is the
    substitution `isRecvStagedIx` already makes for a staged receiver.
  - The whole box ladder stays one writer: retag, wide arm, map arms and scalar coercion. It was not
    split arm by arm, because that would have rewritten hundreds of legacy lines.
  - The IR's writer is a hook (`irHoleWrite`), installed by `irRefInstall` like the other IR
    hooks, not a parameter of `emitBoxAroundHole`. See *Cost* below.
  - `emitBoxAroundHole` is the hole's one setter. A writer that asks for the value other than once
    leaves the function unlowered. A hole open at a function's start fails the build. §10 records
    the hole as a temporary seam, deleted when the ladder moves to the IR.
  - The coordinator accepted the hole on four conditions: one setter, the use-count fallback plus
    a stale-hole assert, the §10 record, and grading on corpus identity and mode 3.
- **The union return sink is a named miss** (`union return sink`). A function whose union result
  legacy builds in its shared return sink (`fnUnionRetSinkOk`) pops each returned box into a pair
  of locals and branches to one `struct.new` at the end. That is a return-site writer outside the
  box ladder. Without this miss, 72 corpus functions differed in their locals. Sharing the sink is
  part 2: it holds 609 corpus functions alone.

## Cost: two spellings that cost the self-compile 4% each

The first build of this step cost +8.5% L2 fuel. Every tree was compiled by one fixed compiler, so
the rise is in compiling the new source, not in the new compiler. `vl check` fuel is flat, so it
lands after the checker. Ablation on the tree found two causes, each about 4%:

| ablation (fixed compiler, fuel compiling the tree) | fuel |
|---|---:|
| I8a part 2 tree | 95,234,391,672 |
| first build: `emitBoxAroundHole(…, write: () => i32): i32`, and `let lwHoleOpnd: Opnd` | 102,841,358,360 |
| the `Opnd` global replaced by an `Rhs[]` | 99,047,912,079 |
| also the writer not passed (so not reachable) | 95,422,535,902 |
| as landed: the writer a hook installed by `irRefInstall` | 95,413,803,308 |

- **A closure parameter on a function with an annotated return** makes the compiler a concrete
  higher-order program (`monoHasConcreteHOFParam`). The mono pass's callback specialization, skipped
  for the compiler until then, now runs on every self-compile: a guest profile shows `monomorphize`
  rising from 52 samples to 862, under `monoFlowReads`, `monoPruneTemplates` and `monoProgTopMark`.
  The compiler's existing hook setters leave their return unannotated, which is why they never
  tripped it.
- **A module `let` of union type `Opnd`** cost about 2G to assign and 2G to hold. That mechanism was
  not traced; holding the open box as an `Rhs[]`, a shape `ir_lower` already keeps, avoids it.

Neither trap is named anywhere a lane would read it before writing such a spelling. Both show up only
in the L2 fuel gate.
