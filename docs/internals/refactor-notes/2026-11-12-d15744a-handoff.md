# D15744 (a) handoff: a top-level `const` lambda returning a bundle, 2026-11-12

Half (b) (the binding inside a function) shipped in #7421. This branch (`w318-d15744a`, WIP)
is half (a): `const g = () => lap((a) => a + 1)` at the top level, its call used as a bundle.

## The change on this branch

- `elabCalleeFn` (emit_elab.vl) admits a top-level binding, not only one inside a function.
- `topLambdaRecordFe` (emit_classify.vl): the lifted function of the lambda a top-level `const`
  read is bound to, where it returns a record of members. `cloCallSigKey` keys a call through it
  at `cloSigKeyExt(fe)`, and `emitCallRefUnder` (wasmEmit.vl) picks the member after the call
  with `emitBundleResultPick`.

The five top-level spellings in D15744's row run. The position matrix does not hold:
`scripts/capability-probes/matrix/lambda-bundle-returner.matrix.vl` runs 25 of 48 and builds
**17 SILENT** cells: `argument`/ann, `struct_field_init`/ann, `struct_field_assign` (both),
`array_element`/ann, `array_element_assign` (both), `array_push` (both), `global_assign`/ann,
`map_value`/ann, `map_set`/ann, `return_inferred`/ann, `return_annotated` (both),
`two_instances` (both). The in-function and bundle-copy matrices hold (42/48 and unchanged).

## Ablation (probes in a scratch seed, never in `build/`)

- In those cells the call `g()` is not a closure call: it resolves by name to a DIRECT call to
  the lifted lambda (`emitDirectCall`), so `topLambdaRecordFe`'s pick in `emitCallRefUnder` never
  runs. `emitBundleResultPick` there finds the call marked kept whole: `keep=1`, `m=-2`.
- The named-function spelling of the same cell (`function g() { return lap((a) => a + 1) }`)
  runs. Its calls are elaborated through its instance (`elabRetRecordKeepsNote`, keep site 6);
  the lambda's go through the plain-call note (`elabPlainCallsNote`, keep site 5), which leaves
  the outer `g()` kept whole in these delivery positions instead of noting its member.

## Candidate fixes

1. Give a top-level lambda returner the instance route: let `elabRetRecordKeepsNote` /
   `elabRetCallRecord` take a lambda `elabCalleeFn` admits (they test `fnName != ""`), so its
   calls get the member facts a named returner's do.
2. Or make the plain-call note (`elabPlainCallsNote` → `elabResultMemberWith`,
   `elabArgRecordWith`) note the member for a delivery position, as the instance note does, so
   the outer call is not kept whole where one member is used.

Grade either on all three matrices (`lambda-bundle-returner`, `-in-function`,
`bundle-copy-handed`): 0 SILENT and 0 runs → not-runs, beside D15744's five spellings.
