# Rep: a rowless record narrowed to one union arm is stored as that arm (IR-C1, D17400, D17402)

D14890's rule (`recNarrowRecordOf`, check_bind_adopt.vl) builds a `null`-field record literal
such as `{ r: null }` as the one union arm it is narrower than (`Circle` in `Circle | Sq`), and
`recArmLitsAdopt` stamps it there. The containers that hold it stayed at the literal's own type,
which has no row of any kind: an un-annotated map's value type (D17400) and an outer record's
field type (D17402). Their storage lookups dead-ended and the emitter refused.

## The change

- `repVariantShapeRowOf` (emit_rep.vl): a record type with no row of its own, declared or a
  literal's, answers the variant row of its one narrow arm (`recNarrowArmOf`). The mv slot then
  classifies and mints the value as the arm, as an annotated `{[string]: Circle}` already did.
- `sFieldTgtStructIdx` (emit_atom_kinds.vl): such a field takes the arm's struct row.
- A type that has a row of its own keeps it. An un-annotated parameter holding the literal is the
  witness for this: its argument is built at the literal's own row.

No new rep rule, and no row is minted. The type's own rep (`rtOfObj`) is unchanged: redirecting it
to the arm broke that parameter spelling (an invalid module), so the redirect sits only where the
lookup had no answer.

## Legacy tails the IR calls

None new. A (the 3 `{ r: null }` cells beside both a plain `Dot` and the arm `Circle`) is a
separate family: there `recNarrowRecordOf` is -1 by design, and this change does not reach it.
