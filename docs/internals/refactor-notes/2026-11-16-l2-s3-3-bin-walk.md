# L2 S3.3: the binary-operator validator reads only the callee's rows, 2026-11-16

The fourth step of the S3 plan (`2026-11-16-l2-s3-plan.md`). `validateBinCstrs` was the one
validator S2 left walking every recorded row (#8545). It asked `gnotDeadAtPin` of each row before
the ownership test, and that call can mint arena types, so skipping rows might have moved type
indices. It now walks `bndNextRow` like the other ten: the callee's rows merged with module scope's,
in order. Its `gnotDeadAtPin` questions are asked only of the rows the ownership test keeps.

`tests/cases`, `distilled/cells` and `distilled/named`). The arena types those skipped questions
could mint were never read by anything that reaches output.

## Body order across kinds: not in this step

The plan put a second change in S3.3: walk a callee's bounds in body order (`seq`, S3.0) across
kinds, instead of kind by kind. Each validator is one loop over its kind, with its own state and
early stops:
- `validateNestCstrs` and `validateIsCstrs` stop at the first error;
- `validateMemCstrs` accumulates `told0` across rows.

Interleaving them means first splitting all eleven into per-row functions, which S3.4's rules then
replace. So body order lands inside S3.4 instead (coordinator's call, recorded in the S3 plan): one
kind per rule PR, each moving its kind into a `seq`-ordered loop, deleting the validator it replaces
and listing its moved diagnostics.
