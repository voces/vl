# Step 7, lane H: D16062 PR 1, one value-union verdict read off the rep tree's boxing decision, 2026-11-13

D16062: the same type got a different value-union verdict depending on which
site asked, because each site graded the rendered spelling its own speller
wrote. The rule now is the runtime's own boxing decision, asked of the type.

## The rule

`valueBoxOfTy(ty)` (emit_rep) holds when two things are true:

- the rep tree lowers `ty` as a union `box` or a boxed `nul` (discipline 4);
- every arm, nested unions flattened and `null` aside, has a value box tag
  (`boxTagOfTy >= 0`).

A literal arm rides at its tag: a string literal or string-literal union as a
string, a number at its base. A struct, map or ref-list arm makes a struct
union, not a value union.

## One source

`rtOfUnion`'s ladder is now `unionRepClassOfTy`, a pure function of the type.
`rtOfUnion` builds its nodes from that answer, and `valueBoxOfTy` reads the same
answer, so the two cannot drift. `rtNulDiscOf` is now `nulDisciplineOfTy`,
shared the same way. `btGo`'s function arm reads `fnTagTyIsTagged` instead of
`repOfTy`. That is the same answer, without the tree.

The tree memoizes per type. A first candidate asked `repTreeOfTy` itself from
collect-phase sites and lost 255 programs: "a record type's rep changed during
emit, from a plain struct to a union arm". Asking the classifiers instead pins
nothing. rep-fuzz is exact after the factoring.

## Class A, held for PR 2

`valueBoxRowOfTy` is the rule minus one class: a numeric literal set with `null`
(`N | null` over `N = 1 | 2`). The tree boxes it, but no row is registered under
it yet. Today the spelling and inferred-return sites call it a value union, and
the `isValueUnionTyOr` sites do not. Measured both ways on full sweeps:

| class A at every site    | programs lost                                                   |
| ------------------------ | --------------------------------------------------------------- |
| a value union (the rule) | 16, mostly `??` "not supported yet" and validation traps        |
| not a value union        | 8, the D16062 witnesses D2491 and D11241, and the `num12` cells |

So PR 1 keeps both groups' answers for this class. PR 2 makes its consumers
agree: row naming, `??` and null tests. The class leaves `valueBoxRowOfTy`
there, and the wrapper goes with it.
