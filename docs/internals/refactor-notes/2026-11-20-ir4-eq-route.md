# One `==`/`!=` route, `eqRouteOf` (2026-11-20, lane IR4)

Legacy's `==`/`!=` dispatch was an inline ladder spread across three functions:
`emitBinExprNode`, `emitBinLitEq` and `emitBinRefOps`. The IR asked a restatement of part of that
ladder, `listEqRouteOf`, which legacy never consumed. #9302 would have added a second
restatement, `eqNumericRouteOf`. The coordinator and IR-REV vetoed that as a duplicate decision
and chose option (a): make the decision once, and have every reader ask it. This PR changes no IR
behaviour.

## What changed

- **`EqRoute` / `eqRouteOf` (wasmEmit) is the one decision.**
  - It has 25 arms, in the old ladder's order: identity mixed and ref, numeric union, dead null,
    `null == null`, scalar map read, union-union, union-left, union-right, atom fold, static and
    ids, nul-none, no lowering, unresolved generic rep, xrep, nullable niche, string, list, null
    test, variant and struct equality, record refused, closure, numeric.
  - Each arm's test is the predicate its writer already read.
  - Three of the old ladder's predicates cannot hold for `==`/`!=`: `exprIsStrConcat` and
    `binConcatRepUnresolved` need `+`, and `exprIsStrOrder` needs an ordering. `binIdent` is set
    only by `===`/`!==`, which `mkBinary` folds into `==`/`!=`, so identity is inside the route.
- **Legacy consumes it.** `emitBinExprNode` now begins with `==`/`!=` → `emitEqRoute`, a `_`-less
  `match` whose arms are the old branch bodies, moved. Deleted:
  - `emitBinLitEq` entirely, since it held only `==` arms;
  - `emitBinExprNode`'s `==`-only blocks;
  - `emitBinRefOps`'s `==`-only blocks.
- **Two writers that decided while emitting now take pure plans.**
  - `scalarMapEqPlanOf` (`none | pair | read | box`, plus kind, read and other) reproduces each of
    the old declines, and the writers take the plan:
    - a kind mismatch;
    - a pair that is not two `Index` reads;
    - a read that is not an `Index`;
    - a box failing `scalarMapBoxEqOk`;
    - the other operand's atom kind.
  - The null test's claim is `nulTestClaims`: `binNulTestOf`, then a `_`-less `match` over
    `nulTestArmOf`, with `instMap` asking `instMapIsNullReadOf`. That is
    `emitInstMapReadIsNull`'s shape check factored out pure; the writer uses it too.
  - A writer reached against its route is an `emitFail` that says "eqRouteOf and its writer
    disagree (…)": an internal guard, not a capability refusal.
- **`listEqRouteOf` is `==/!= && eqRouteOf(...) == "list"`.** Its restated body is gone.
- **The atom plan's `none` maps to null** (`atomEqRouteOf`), not to a route a later arm could
  mistake for an answer.
- **Lint:** `EqRoute` and `ScalarMapEqArm` are in `lint.vl`'s `klSets`, and `smArm` is in
  `klFields`.
