# IR: control-flow batch 4, 2026-11-23

Lane IR-N4, control flow. Base: master 3db525436. Legacy writes every case below already; the IR
now builds the same bytes.

## Change

- **A range loop over a hoisted list header.** `emitForRangeStmt` opens `loopHoistOpen` after the
  bounds and before the loop variable, and keeps it open across whichever arm it writes (rolled,
  unrolled, partial). `forRangeRolledBlock` now answers `hoisted` last, after the wrap check, and
  the builder takes it. The lowering opens the same rows through `irLoopOpenHook` at the range's
  outer block (rolled, unrolled) or its `SRangeLoop` (partial, wrap exit). A continue block inside
  the loop is built at the body node, so only the outer block opens the hoists.
- **A `for` walk over a list of closures.** `forInElemPlain` admits the `closure` element kind:
  legacy's walk reads the closure struct ref into the loop variable whole, as it does a record's.
- **A range proven over its list's length.** `emitForRangeStmt` opens `rangeProofOpen` after the
  hoists; a hoisted list read (`emitListIdxGuardHoisted`, through the `*ListGetTail` tails the IR
  already calls) then skips its guard for the proven index. `forRangeRolledBlock` answers `proven`
  after the wrap check, the builder takes it, and the loop-open hook opens the proof after the
  hoists. The hook returns `LoopOpened { loHoists, loProofs }`, and the close hook closes each.

## Soundness: an index the proof does not cover keeps its guard

Each witness is uncovered on master (`for range hoisted` or `for range proven`) and covered and
matched on this branch, with byte-identical output under both seeds:

- `for i in 0 to xs.length { s += xs[i] }` (off by one): traps under both; each read keeps
  `i32.ge_u` and `unreachable`.
- `for i in 0 until n { s += xs[i] + xs.length }` with `n` one past the length (hoisted, not
  proven): prints 15, then traps under both.
- `for i in 0 until xs.length { s += xs[i]; xs.pop() }` (the bound is read once and the list
  shrinks): traps under both.
- Control, `for i in 0 until xs.length { s += xs[i] }`: prints 6 and 0 under both; no guard.
