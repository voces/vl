# IR cutover C2i: the atom rep (coverage step), 2026-11-16

Lane IR-C. This is a coverage step under the `ir-design-2026-11.md` §10 exemption. The blocker census
sized it: on C2h's tree, `callee signature` held 1,013 corpus functions alone, and 1,011 of those
were a callee whose parameter is a literal-union atom. `CLAIMED` stays empty, and no emitted byte
moves.

## What landed

- **The atom rep is a value rep.** A literal-union value, an interned atom id in an i32, may be a
  variable, a parameter, a result or an argument.
- **A string literal carries its rep** in `OStr.osRep`. The rep is either the string, or the atom of
  the literal's destination, which `strLitTakesAtom` and `ctxTyAt` decide. Legacy's literal arm is
  now one shared function, `emitStrLitAt`. It writes the interned id or the string, and the IR's
  `OStr` lowering calls it.
- **An atom compare is a named miss**, `atom compare`. Legacy's `emitBinLitEq` does more than one
  thing before it writes `i32.eq`:
  - it folds two operands typed at single literals to a constant;
  - it spells a literal beside an atom as the member it equals (`memberLexOfValue`);
  - it routes union compares first;
  - it writes `!=` as `i32.eq; i32.eqz`.

  A plain eq/ne over atom ids diverged from legacy in the shadow, so the IR does not build atom
  compares until that ladder is shared.
