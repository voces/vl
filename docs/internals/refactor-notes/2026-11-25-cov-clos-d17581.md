# D17581: a stored function slot delivered at `F | null` (2026-11-25, lane COV-CLOS)

This is item (2) of the coordinator's next-items order. COV-CLOS filed D17581 in #10097.

## Mechanism

`monoStoredSlotFnTy` (emit_mono.vl) instances each function stored in a slot at the one closed
function type the elaboration delivers the slot at (`monoSlotDeliveryTy`, which reads the slot
class's signature `eplSlotSig`). For an un-annotated `Map()` holding a hole function, read at an
annotated `((a: i32) => i32) | null`, that signature is the read's delivery type including the map
miss's `| null`. The lookup demanded a bare `TyFunc`, so it refused with "a function slot pinned at
one signature has no one closed type" even though `vl check` accepts the program (clause 1).

`monoSlotDeliveryTy` now takes `stored`. At the stored-slot caller, a delivery at `F | null` is read
as `F`. The cell caller and the list caller pass `false` and keep the exact type, because a cell or
list element typed `F | null` may hold `null`, and retyping its cell to `F` would be wrong.

This is not an IR claim. The refusal fires in the monomorphizer, which runs before either emitter,
so no claim can avoid it. After the fix the IR claims each position. Only programs that reached the
refusal change: with `stored` false, every other caller is untouched, and a non-nullable signature
is read as before.

* `tests/cases/maps/map-read-at-twin-closure-rep-positions.vl` gains the annotated binding,

  they were stale before this change.
