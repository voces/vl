# D16206: a number delivered to a wider numeric parameter is delivered at that parameter's type, 2026-11-14

Lane G.

Take `function w2(u, v: f64) { return mix(u, v)[0] / 4.0 }`, with `mix<T>(a: T, b: T): T[]` and a
caller handing `u` an `i32`. The template binds `T` at `f64`, since the hole `u` adapts to `v`.
The caller closes `u` at `i32`. Mono pinned `mix`'s parameter from `u`'s own instance type, so the
instance was `mix(i32, i32): f64[]`, `w2` handed it an `f64`, and the module failed to validate.

## Change (`emit_elab`, net compiler lines +3; pin-helper delta 0)

- `elabArgDeliveredTy` already answered, per instance, the type a call delivers an argument at
  where that is not its own: a record built or widened at its parameter, or a literal built at it.
  It now also answers the parameter's type when the argument's own number widens losslessly into
  it (`numWidens`, the checker's D2459 edge list).
- Mono reads that fact through the existing path (`monoArgClosedTyIn`). No mono arm is added, and
  the call site's widening follows from the pin.
