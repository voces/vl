# A literal binding built wider, stored into a container pinned at its own type, is that container's type mismatch, 2026-11-11

Lane w320. Base is master. Check only; closes D15718 as refused by design.

**The ruling.** An un-annotated container is pinned by its first store. `const o = { f: 4 }` handed
to a `J[]` is a `J`. So `m.set("b", { f: 5 }); m.set("a", o)` stores a `J` into a `{f: i32}` slot.
`const o: J` gets the same refusal there and runs in the other order, so the design owes the
refusal. Building the map at `J` whatever the order would make the un-annotated spelling more
permissive than the annotated one.

**The change.** `recStoreMismatchMsg` (check_fit_rules.vl) words the refusal of a binding's
`.set`, `.push` or index store as that container's own mismatch, plus the binding's note:
`set: expected {f: i32}, got J (`o` holds only a literal, …)`. `recBuiltStoresRefuse` and the
kept-store refusals that reach a store (`recKeptOwnMsgAt`) use it. Every other refusal is
unchanged. Moved fixture messages: three `@error-at` lines, at the same positions.

**Graded.** `literal-binding-built-wider-store.matrix.vl`: the after-literal map set, index write
and push are `// owed:` refusals in both faces, citing the annotated twin. `capability-matrix.vl`
learns `// owed: X`, which marks a refusal owed in both faces.
