# L3 A2: a lambda's declared record parameter takes the row slot

**Change.** `wsCalleeDecl` (`check_width.vl`), which names the declaration a call's record-width
candidate belongs to, answered a top-level function's name only. It now follows an `Ident` callee
through a binding bound once to a lambda (`cwFramedNode`, `cwKeyOfRoot`, `cwLambdaDeclOf`, the
path `callDeclFnIx` already takes). Nothing else changes: the rewrite gives the lambda's parameter
a type parameter bound by its record, the slot `fnDeclPushTyParams` binds and prints as the
record, and each call instances the lambda at its row.

**Design.** Three options went to the coordinator (2026-11-15):
- (1) a per-call-site closure specialisation;
- (2) an accessor-view parameter, the storage half's mechanism, held for D16401 and D16402;
- (3) the implicit row variable through the hole-lambda machinery, chosen.

Building (3) as a hole respelling ran every position but hovered the parameter as its demand
shape (`{name: _}`), since a hole binds no declaration slot yet. Giving the lambda the type
parameter a function gets, measured by the same programs, runs them and hovers `P`, with no
lambda-specific code.
