# Step 7, lane H: `identFnTypeAnnNameOfRead` answers a boolean; its `ann` thread is dead, 2026-11-13

`identFnTypeAnnNameOfRead` rendered a binding's function-type NAME, but all four
callers used the name only as a gate — "does this binding carry a function
type".

## What the callers asked

- `emit_mono` 23072, 23074: `identFnTypeAnnNameOfRead(n.callFn, ctx) == ""` — a
  `const` call's callee is monomorphized per call unless the binding is
  annotated.
- `emit_mono` 22654: `let atn = identFnTypeAnnNameOfRead(n.binLeft, ctx)`, then
  the string is only tested against `""` to choose between the annotated and the
  pin-inferred delivery; the spelling that followed came from
  `monoConcreteFnTyName` / `monoPlacePinNameTys`, never from `atn`.
- `emit_classify` 13544: `cloCallSigKeyTy` tested `an != ""` and then re-derived
  the key from the node's own type (`identFnTypeAnnNodeOfRead`, `sigKeyOfTy`),
  never from `an`.

So the renderer is now `identReadIsFnAnnotated`, returning `boolean`. Five of
its six arms answer `true` directly; one keeps its emptiness test, because a
probe found it load-bearing.

## The one arm that still tests a name

A probe over 24,219 programs counted, per arm, how often the render was reached
and how often it was empty behind its guard:

| arm                                   | reached | empty render |
| ------------------------------------- | ------- | ------------ |
| local annotation (`tyIsFuncType`)     | 136     | 0            |
| local nullable-closure (`nulCloFlag`) | 3       | 0            |
| call-init (`ini is Call`)             | 36      | 6            |
| `??`-init                             | 19      | 0            |
| ref-list closure element              | 15      | 0            |
| global/module annotation              | 173     | 0            |

Only the call-init arm renders empty while its arena test passes — a function
type the arena holds but cannot spell. There `identFnTypeAnnNameOfRead` returned
"" and fell through to the arms below, so `identReadIsFnAnnotated` keeps
`nodeTyName(d.letInit) != ""` to fall through alike. The other five tested a
name that was never empty, so they answer `true`.

## The dead `ann` thread

`identFnTypeAnnNameOfRead`'s rendered name was also carried as `ann` through six
mono delivery functions (`monoNoteBindDelivery`, `…At`, `…Call`,
`monoDeliverCallAt`, `monoDeliverCallRets`, `monoNoteRetDeliveriesAt`) and never
read — each reads `annTy`, the type beside it. The parameter is removed from all
six, with it the two `monoSigFnTyName(pins[0] + ";")` and one
`monoSlotPinAnn(...)` producers that fed it, and `monoSigFnTyName` itself (its
only other caller was one of those), folded into `monoSigFnTyNameRet`.
