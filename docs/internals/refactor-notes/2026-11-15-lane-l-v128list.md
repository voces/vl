# 2026-11-15 — lane L: a flat `v128` list kind

- `v128list` joins `VKind`, `ListKind` and `ArrNewKind`. Adding it made the checker name every
  `_`-less match that had to answer it: 59 `VKind` sites plus the others. 44 took it in an
  existing group; the rest got their own arm.
- Types: the `fa128`/`fl128` pair (`TSK_V128_ARRAY`/`TSK_V128_LIST`), read off the interner's own
  table, so the pair adds no mint state to the phase-state census. Wiring:
  - `scalarListWrap`/`Back`/`Used`/`Blocktype` take `"v128"`;
  - `rtPrimListVKind`, `arrNewDefaultKind`, `listIdxKindOf` and the if-arm list kind map a
    `v128` element to `v128list`;
  - `emitArrV128` builds a literal, chunked past `NEW_FIXED_MAX`;
  - a v128 push quad (bit 8192) is reserved only when used, so no other frame base moves.
- The field code is `FC_V128_LIST`, derived through `fieldCodeOfListRep`, as rep stage 3c
  expects. The armed shadow (`VL_REP_SHADOW=1`) reads `repAB/field … agree` on vector-list
  field rows.
- Built on the element-kind refactor (#8414). The store, push, `.length`, the hoisted-loop
  wrapper and the map/filter/slice source and destination types read one element kind from
  the rep, through `numListElemOf`. Three per-kind if-chains (`mfSrcTysOf`, `mfDstTysOf`,
  `.slice`) collapsed the same way here.
- The checker's `tyNestsV128` stops counting a flat list, but still refuses a list of vector
  lists and `F32x4[] | null`: neither has a rep yet (no ref-list element kind, no nullable
  twin). The map value is refused as before.
- Net compiler lines +206 over #8414, so +183 against master with its −23. That is just past
  the design's +120 to +200 estimate. No new `emit_mono.vl` functions (908).
- `v128-list.matrix.vl`, `--before` master and `--after` this branch: 68 of 82 run, 0 silent,
  0 runs→not-runs. The 14 others are the list delivered into a list or a map value, both
  still refused at check.
- `v128-list-generic.matrix.vl`, the open type-parameter template: 38 of 48 run, 20 skipped
  (no TEST), and the other 10 are the same deferred faces.
- `v128-struct-field.matrix.vl` still runs 82 of 82.
- Perf: the design's baseline (100k vectors × 100 update passes, `-O3`, median user CPU of 10)
  was rerun. `F32x4[]` takes 0.048 s (0.036–0.093) and 13 MB. `{ v: F32x4 }[]` takes 0.044 s
  and `Buf` lanes 0.022 s on the same box; neither list allocates in the loop. The design's
  "at or near `Buf`" projection did not hold: every list access keeps its bounds guard (load
  the backing, load the length, compare), which `Buf`'s unchecked loads skip. The flat list
  matches the record-list spelling, and its gain is the spelling `F32x4[]` itself.
