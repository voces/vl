### D13280 — `?.` over a union of records whose shared field is a nullable scalar builds invalid wasm

**check-clean invalid wasm · clause 1 · open · `type mismatch: expected i32, found (ref $6); $6 is union box` inside `F` · pre-existing on master `247fb2679` · found closing [D13080](D13080.md), whose hole rewrite declines this pin · filed 2026-10-25 against master `247fb2679`**

Repro:

    type A = { k: i32 | null, x: i32 }
    type B = { k: i32 | null, y: string }
    function F(u: A | B | null) {
      const r = u?.k
      print(r ?? -1)
    }
    const a: A | B | null = { k: 3, x: 1 }
    const b: A | B | null = null
    F(a)
    F(b)
    // vl check: rc 0.  vl run: the emitted module failed to validate inside `F`: type mismatch: expected i32, found (ref $6); $6 is `union box`

Want:

    3
    -1

#### Mechanism

From the code path, not ablated to a line. The rewrite of `u?.k` over a nullable union of
records (`recUnionGuard`, emit_rewrite.vl) builds `if u != null { u.k } else { null }` at the
field's nullable type. Over a union, `u.k` is the shared-field dispatch, which hands the field
out as the boxed `i32 | null`, and the `??` or binding that reads the guard expects the scalar
the one-record path gives. The read without `?.` (`u.k ?? -1` on `A | B`) refuses loudly at emit
instead, so both faces of a nullable scalar shared field lack a lowering.
