### D3846 — a function whose tail is a call through a capture cell (`d[0](x)`) is inferred void, so its caller reads a result that is not there

**check-clean invalid wasm · found closing D3845 (`l3`) · filed 2026-10-08 against master `52c8e492d`**

Repro:

    function f(x: string) {
      const c = (y: string) => y + "C"
      const e = (y: string) => y + "E"
      let d = c
      const g = () => d(x)
      d = e
      d(x)
    }
    print(f("a"))
    // vl check: rc 0.  vl run: invalid module inside the module's top-level code, `expected (ref $type) but nothing on stack`

Want:

    aE

#### Mechanism

Not yet located. `computeVoidFns` asks `stmtIsTailValue` of the tail, and for a callee that
is no identifier it decides by the call's resolved `$fnsig` (`cloCallSigKey`). For the cell
read `d[0]` that key is empty, so the tail counts as a statement and `f` is void. Binding the
result (`const r = d(x); r`) or annotating `f`'s return runs. The lambdas' annotations do not
matter: annotated, it fails the same way on master.

#### Ablation

| ingredient removed | outcome | needed? |
| --- | --- | --- |
| the tail call (`const r = d(x); r`) | runs | **yes** |
| a return annotation on `f` (`: string`) | runs | **yes** |
| the capture (`const g = …` removed) | runs | **yes** |
