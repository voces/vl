### D3830 — two nested `<U>` generics of the same name in different functions share their `$N` instance names, so a call reaches the other one's instance

**check-clean invalid wasm · found closing D3826 · filed 2026-10-08 against master `cab1ee907`**

Repro:

    function outer(x: i32) {
      function inner<U>(u: U) { print(u) }
      inner(1)
      inner("a")
    }
    function first(x: string) {
      function inner<U>(u: U) { print(x) }
      inner(1)
      inner(2.5)
    }
    outer(7)
    first("s")
    // vl check: rc 0.  vl run: invalid module inside `first`, `expected (ref $type), found f64`

Want:

    1
    a
    s
    s

#### Mechanism

Not yet located. The likely shape, read and not yet probed: each template names its later
instances `inner$1`, `inner$2`, … by its own count, so both templates mint an `inner$1`, and
`first`'s renamed call resolves to `outer`'s. No capture is needed. Renaming either nested
function runs.
