### D9951 — a list literal of records handed to an un-annotated parameter loses the field's function type when another record of an un-annotated function shares the field name

**closed · runs, prints `3` · was loud emit reject, `vl check` rc 0, `emitProgram: callee is not a function name`, clause 2 · found closing [D9647](D9647.md) · filed 2026-10-22 against master `c4fbdc8d1` · closed by binding a list pin over an `#anon` row at the argument's closed type when the row's own type was first minted through a hole (`monoSynthPinRef`, emit_mono.vl), the list twin of the bare-row rule in `monoMakeInstanceParams` · fixture `closures/hole-fn-record-list-literal-beside-shared-field-record.vl`, which holds both grading-list cells, new matrix `hole-fn-record-list-element-shared-field` 45 → 46 of 46, `hole-fn-record-list-element` unchanged at 43 of 46 · a `for` over the parameter instead is [D2197](D2197.md)'s check reject**

Repro:

    function inc5(a) { return a + 1 }
    const r = { f: inc5 }
    function use6(v) { print(v[0].f(3)) }
    use6([{ f: (x: i32): i32 => x }])
    // vl check rc 0.  vl run: emit error: emitProgram: callee is not a function name

#### Mechanism

An `#anon` row is keyed by field names and codes, so `r`'s record and the lambda's record share
one row, and the row's arena type is the first literal's: `{f: inc5}`, whose field still holds
the hole. The pin of `use6`'s parameter is `#anon0[]` with the argument's closed type
`{f: (i32) => i32}[]` beside it, but `monoSynthPinRef` resolved the list spelling through
`monoAnonRowListTy` to the row's open type and ignored the closed one, so the instance's `v[0]`
read as `_` and `v[0].f` had no function to call. The bare row (`use6({ f: … })`) already took
the closed type in that case; the list spelling did not. With `r` declared after the call, the
lambda's record minted the row and it ran. With the element relayed (`t(v[0])`) the same pin
refused as `index access but array type not collected`.

#### Ablation

| ingredient removed | outcome | needed? |
| --- | --- | --- |
| the hole in `inc5` (`inc5(a: i32): i32`) | runs | **yes** |
| the shared field name (`r = { g: inc5 }`) | runs | **yes** |
| the list (`use6({ f: … })`, `v.f(3)`) | runs | **yes** |
| the hole in the parameter (`v: { f: (a: i32) => i32 }[]`) | runs | **yes** |
| the list literal, bound first (`const l = [...]; use6(l)`) | still refuses | no |

#### Grading list

Two list literals of records of two different un-annotated functions handed to one parameter
(`use5([{ f: inc5 }]); use5([{ f: inc6 }])`), and to two parameters relaying the element to
two field calls (`use5([{ f: inc5 }]); use6([{ f: inc6 }])` with `t5(v[0])`, `t6(v[0])`). Both
refuse on master and with [D9647](D9647.md) closed, the second as `index access but array type
not collected`; each runs alone.
