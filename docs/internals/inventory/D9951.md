### D9951 — a list literal of records handed to an un-annotated parameter loses the field's function type when another record of an un-annotated function shares the field name

**loud emit reject · `vl check` rc 0 · `emitProgram: callee is not a function name` · clause 2 · found closing [D9647](D9647.md) · present on master `c4fbdc8d1` · filed 2026-10-22 against master `c4fbdc8d1`**

Repro:

    function inc5(a) { return a + 1 }
    const r = { f: inc5 }
    function use6(v) { print(v[0].f(3)) }
    use6([{ f: (x: i32): i32 => x }])
    // vl check rc 0.  vl run: emit error: emitProgram: callee is not a function name

#### Mechanism

Not yet located. The record `r` is never read, so what joins it to the call is its type alone:
both records are typed through the field name `f`, the open record of `inc5` and the lambda's
record meet at one `#anon` row, and the list parameter's element read then has no function type
at `v[0].f`. With the element relayed (`t(v[0])`) the same family refuses as `index access but
array type not collected`.

#### Ablation

| ingredient removed | outcome | needed? |
| --- | --- | --- |
| the hole in `inc5` (`inc5(a: i32): i32`) | runs | **yes** |
| the shared field name (`r = { g: inc5 }`) | runs | **yes** |
| the list (`use6({ f: … })`, `v.f(3)`) | runs | **yes** |
| the hole in the parameter (`v: { f: (a: i32) => i32 }[]`) | runs | **yes** |
| the list literal, bound first (`const l = [...]; use6(l)`) | still refuses | no |

#### Grading list

Two list literals of records of two different un-annotated functions handed to one parameter
(`use5([{ f: inc5 }]); use5([{ f: inc6 }])`), and to two parameters relaying the element to
two field calls (`use5([{ f: inc5 }]); use6([{ f: inc6 }])` with `t5(v[0])`, `t6(v[0])`). Both
refuse on master and with [D9647](D9647.md) closed, the second as `index access but array type
not collected`; each runs alone.
