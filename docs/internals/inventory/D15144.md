### D15144 — a returned bundle parameter whose result is called at two signatures, or handed on, has no record to hold it

**closed 2026-11-03 — the repro now RUNS. Was: loud emit reject · clause 2 · `a function returning a parameter called at two signatures is called where its result is not used at one of them` · filed 2026-11-03 against master `e2207958`**

Repro:

    function lap(f) {
      print(f(2.5))
      print(f(3))
      return f
    }
    function go(k: i32) {
      const r = lap((a) => a + k)
      print(r(4))
      print(r(1.5))
    }
    go(1)

Want:

    3.5
    4
    5
    2.5

#### Mechanism

`lap` returns its parameter's record. A `const` holding it, called at two signatures or handed
on, needs the record itself as a value. The elaboration now notes, per holder and instance, the
record it holds whole (`elabHolderRecordAt`) and the member each call through it takes
(`elabThroughMemberAt`). Emit types the holder's slot and a capture of it at the record's row,
and selects the member at each call. A hand of the holder, or of the call itself, to a parameter
called at the same signatures passes the record (`elabCallArgRecordSigs`), and a hand to a
one-closure parameter passes its member. Design: `docs/internals/bundle-record-value-2026-11.md`.
