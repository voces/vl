### D15144 — a returned bundle parameter whose result is called at two signatures, or handed on, has no record to hold it

**loud emit reject · clause 2 · `a function returning a parameter called at two signatures is called where its result is not used at one of them` · filed 2026-11-03 against master `e2207958`**

Repro:

    function lap(f) {
      print(f(2.5))
      print(f(3))
      return f
    }
    function go(k: i32) {
      const r = lap((a) => a + k)
      print(r(4))
      print(r(1.5))
    }
    go(1)
    // vl check: rc 0.  vl run: emitProgram: a function returning a parameter called at two signatures is called where its result is not used at one of them

#### Mechanism

`lap` returns its parameter's record, and the caller takes one member at the call
(`elabCallResultMember`). A holder called at two signatures needs the record itself as a
value: a local of the record's type, calls through it that select, and every place it can be
handed on. That is a capability of its own, and its design note comes first.

#### Ablation

| ingredient removed | outcome | needed? |
| --- | --- | --- |
| `r(1.5)` (one signature) | runs | **yes** |
| `lap`'s call at `2.5` (one signature in `lap`) | runs | **yes** |

#### Grading list

The handed-on spelling: `function keep(g) { print(g(4)) }` and `const r = lap((a) => a + k);
keep(r)`, which refuses at the same call.
