### D6472 — a lambda reached through a `let` alias, called with a generic whose hole it calls at two types, is refused at emit

**loud emit reject · `vl check` rc 0 · clause 2 · CAPABILITY: the same program with `const k = lap` runs ([D6420](D6420.md)) · found closing [D6420](D6420.md) · filed 2026-10-18 against master `b21da3d5d`**

Repro:

    function id(a) { return a }
    const lap = (g) => { print(g(1) + 1); return g("s") }
    let k = lap
    print(k(id))
    // vl check: rc 0 (a hint: `let` never reassigned).  vl run: emitProgram: cannot take the generic function `id` as a value — a function value carries ONE signature, and parameter `a` is un-annotated (it would default to i32)

Want:

    2
    s

#### Mechanism

From the ablation only. The emitter's callee resolution follows `const` aliases only, since a
`let` may be written after the alias reads it; a `let` alias never written reaches the hole
call as a function value with one signature, refused on the value path rather than the
alias path [D6420](D6420.md) closed.
