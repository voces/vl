### D16020 — a record literal holding a tagged set is built at its own fields' row, which the type its reference keys does not name

**closed 2026-11-13 — the witness runs `4 4` armed as well as unarmed · the literal reads its row by its stored type, and an `#anonN` pin reads its literal's row by type identity · was a refutation pin, failing only under `VL_OPAQUE_SNAMES=1` · filed 2026-11-13 against master `739db770`**

Repro:

    function inc1(a) { return a + 1 }
    function inc4(a) { return a + 1 }
    const m = Map()
    m["k"] = { xs: [inc1] }
    const mv = m["k"]
    if mv != null { print(mv.xs[0](3)) }
    function take(p) { print(p.xs[0](3)) }
    const hl = [inc4]
    take({ xs: hl })
    // vl run: 4 4, armed and unarmed.

Want:

    4
    4

#### Mechanism

`take`'s parameter is reached through `retStructRowIndex`. Unarmed, its `#anonN` label names the
row the argument literal was built at, so parameter and argument agree. Armed, the label is opaque.
The typed rung answers instead: the row of the record type that `monoTagMapRepTy` stores the
tagged set at (`{xs: i32[]}`). But the literal `{ xs: hl }` is still built at the row
`structIndexOfObjCtx` derives from its own fields, so the call passes one row where the
parameter expects the other. Before the typed rung landed, armed failed one step earlier, as
`ref valtype with no interned shape`. The label rung now answers only when it disagrees with
the typed rows. Over the population that happens in 9 programs, and all 9 run on the label's
answer and break without it. The rung is a loud floor where no type keys the row at all
(`emitFail`, unreached in the population).

#### Ablation

| spelling | unarmed | armed |
| --- | --- | --- |
| witness | runs `4 4` | invalid module (master: emit error) |
| argument `[inc4]` inline in the literal | runs `4 4` | invalid module (master: emit error) |
| without the map half | runs `4` | runs `4` |
| literal bound to a `const` first, then passed | runs `4 4` | runs `4 4` |
| `inc1`/`inc4` annotated | runs `4 4` | runs `4 4` |
| `take`'s parameter annotated | runs `4 4` | runs `4 4` |

The literal must be passed directly, and the map must make the set tagged. Annotating either
side lets the type key the row the literal is built at.

#### Grading list

Closed by two type reads that replace label reads.
- `structIndexOfObjCtxGo` builds a tagged literal at the row of its stored type
  (`tagRepTyFn`), the row `retStructRowIndex` already answered for the parameter.
- An `#anonN` parameter pin keeps its literal's type (`synthTypeRefFb`'s fallback), and
  `retStructRowIndex` finds the anonymous row recorded at that type.

The 9 programs whose label disagreed with the typed ladder now take that identity row. All 9
are byte-identical to master unarmed and run armed. The label is still read for a pin forwarded
from another instance's parameter, which holds no literal type: [D16021](D16021.md).
`tests/cases/generics/union-of-records-arm-holding-type-param-built-at-instance.vl` still exits
70 armed; it is a different family.
