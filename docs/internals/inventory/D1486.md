### D1486 — a `!=` test on a literal discriminant narrows NOTHING, in either branch, while the `==` test with an `else` narrows both

**loud check reject · clause 2 · `field 'h' is not on every member of Shape — narrow with `is` first` · the `==` spelling of the identical two-arm complement runs · filed 2026-09-03 against master `cdfdc14e`**

Repro (five lines; rejected at 5:33):

    type Circle = { kind: "circle", r: f64 }
    type Rect = { kind: "rect", w: f64, h: f64 }
    type Shape = Circle | Rect
    const s: Shape = { kind: "rect", w: 2.0, h: 3.0 }
    if s.kind != "circle" { print(s.h) }

#### Mechanism

`pushDiscrimNarrow` reads the surviving type the CHECKER banked at the condition node
(`isParentTyIxOf` / `isParentElseTyIxOf`), so the emitter side is already complement-aware —
the `else` arm of an `==` test narrows correctly and prints. What has no complement is the
CHECKER's own discriminant analysis at a `!=` operator: neither branch of a `!=` receives a
narrowing, so the THEN branch (which should be exactly the surviving arm) and the ELSE branch
(which should be exactly the tested arm) both fail with the same "not on every member"
diagnostic.

**THE REFUSAL'S ADVICE IS UNAVAILABLE AT THE INLINE-ARM SPELLING.** `narrow with `is` first`
works for a named arm — `!(s is Circle)` runs and prints — but an inline arm has no name to
test, so for `type Shape = {kind:"circle",r:f64} | {kind:"rect",w:f64,h:f64}` the message
names a fix the program cannot express. The only spelling left is inverting to `==` with an
`else`. That interaction is why this row is filed beside [D1473](#d1473) rather than folded
into it: D1473's close made the `==` direction work at the inline spelling and did not touch
this one.

#### Ablation

| ingredient removed | outcome | needed? |
| --- | --- | --- |
| the `!=` (`if s.kind == "circle" { s.r } else { s.h }`) | runs, prints `3` | **yes** — the rescue |
| the `!=` (`if !(s is Circle) { s.h }`, named arms only) | runs, prints `3` | **yes** — unavailable at inline arms |
| the named arms (inline `type Shape = {…} \| {…}`) | rejects, same message | no — both spellings |
| the `f64` discriminant field (an `i32` tag `k: 1` / `k: 2`) | rejects, same message | no |
| the statement form (an early `return` inside a function) | rejects, same message, BOTH branches | no |
| the two arms (a three-arm union, `!=` leaving two) | rejects, same message | no — but a two-survivor set is a separate question |

#### Grading list

Both rescues must keep running. The close must narrow BOTH branches of the `!=` — the
early-return witness rejects in each direction, so a fix that only serves the THEN branch
leaves half the row — and must be graded at the INLINE-arm spelling, where no `is` rescue
exists, as well as at named arms. The three-arm case (a `!=` leaving TWO survivors) is a
member-SET narrowing rather than a single survivor and may correctly stay refused; say which
when the row closes.
