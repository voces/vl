### D6110 — a `const` hole lambda passed by name to a hole parameter the callee calls or never reads has no monomorphization pin

**loud emit reject · `vl check` rc 0 · clause 2 · found closing [D5935](D5935.md) · filed 2026-10-17 against `f3ea6a58f`, the D5932 head**

Repro:

    function lap(g, x) { return g(x) }
    const f = (n) => 0 - n
    print(lap(f, 4))
    // vl check: rc 0.  vl run: emitProgram: monomorphize: unsupported argument type for `g` in a call to `lap`

Want:

    -4

#### Mechanism

From the ablation only. The same lambda written in the argument position runs (D5935), and a
named generic `neg` in place of `f` runs, so the pin is found for a lambda literal and a
function declaration but not for a `const` binding of a hole lambda read as a value.
