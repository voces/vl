### D4843 — a hole lambda called through a capture cell, then written back into that cell directly, is refused as not settled

**loud emit reject · `vl check` rc 0 · clause 2 · OPEN · found by the mutate-then-read probes of lane SC's L1 step 6 (refused before and after it) · filed 2026-10-15 against `bf9a09dd4` (#3815's head)**

Repro:

    function f(n: i32) {
      const c = (y) => y + 1
      const g = (y) => y * 2
      let d = c
      print(d(n))
      function w(): i32 { d = g; 0 }
      w()
      d = c
      print(d(n))
    }
    f(5)
    // vl check: rc 0.  vl run: the captured binding `d` is written with a function value whose type at this binding is not settled

Want:

    6
    6

#### Mechanism

Not yet ablated past the program. The refusal is `monoCellValueFail`, reached when the direct
write `d = c` is coerced into the cell after `c` already has its instance from the call
`d(n)`: the cell path re-takes a value that has already been delivered and finds no
concrete signature. It is the same sentence as D3959 and as §(f) step 6's case (a), and may
share their fix (make the cell coerce idempotent over a delivered instance, or let the
cell's `e` pin deliver the write alone).
