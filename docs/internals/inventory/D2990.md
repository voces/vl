### D2990 — a record handed to a WIDER declared record through a Map store, a capture or a return is stored unconverted

**closed · was check-clean invalid wasm, identical on master `4dc94bd23` and on #3250 · the D2933 use walk now follows a store into an element or field place (`rsPlaceStoreTy`), so the literal is built at the place's declared record · the un-annotated-return face is [D2996](D2996.md), which needs a ruling, and a lambda whose last statement is the store is [D2994](D2994.md) · fixture `tests/cases/objects/record-literal-widened-store-delivery.vl` · found by the #3250 review grid · filed 2026-09-28**

Repro:

    type D = { v: f64 }
    const x: i32 = 3
    const c: {[string]: D} = Map()
    const o = { v: x }
    c["k"] = o
    // vl check: rc 0.  vl run: invalid module — type mismatch at the map store

#### Mechanism

A store `place = o` (a map value, a list element, a field) was not a position the D2933 use
walk followed: `rsElemUseSafe` answered every non-name assignment "safe", so `o` kept its own
row and was stored where the place's row is expected. The walk now reads the place's declared
type (a map's value type, else the place's checked type) as a delivery, like a parameter's.
As filed: `o` is checked as `{v: i32}`, and the checker lets that
record into `D` (`i32` widens to `f64`). The literal is built at its own `i32` record, because
`x` is not a literal the scan can adopt, and nothing converts it when it is delivered. The D2933
use walk (`objLitBindDestRow`) re-seats a binding at a declared destination only at the
positions it follows (a parameter, an annotated binding, a declared return, an object-literal
field, an annotated list literal). A Map store, a capture and an un-annotated return are not
among them. A record is shared, not converted, so either the literal is built at the
destination's record or the delivery is refused.
