**closed · runs, prints `4 3 30`, with the split plan off too · was structural: `f(add)` with `f = if c { p } else { q }` runs `p` and `q` at `add`'s tagged set, and mono pins each member's hole at that call; the elaboration ran both instances but recorded neither for the call, so mono read the argument's own set type (`monoArgTaggedFnTy`) · found grading [D15177](D15177.md), whose deletion of that read made this witness and `closures/inline-hole-fn-list-indexed-and-summed-handed-hole-fn.vl` loud emit rejects with the split plan off · filed 2026-11-04 against master `0e695a39` · closed 2026-11-04: a call through a function value records the member instance it ran at the root too (`elabValCallNote`), its producer keeps a set's binding (`elabSetCallRows`, `elabSetBinding`), and `elabCallParamBoundTy` answers a call with no instance of its own from the member instance it ran, mapping mono's declaration through `elabSrcDecl`; `monoArgTaggedFnTy` is deleted**

Repro:

    function add(a, b) { return a + b }
    function p(g) {
      print(g(1.5, 2.5))
      return g(1, 2)
    }
    function q(g) { return g(10, 20) }
    function main(c: boolean) {
      const f = if c { p } else { q }
      print(f(add))
    }
    main(true)
    main(false)

Want:

    4
    3
    30

#### Mechanism

Mono resolves a call whose callee is a join or a list element to the member it runs and pins that
member's hole parameters at the call. The elaboration's instance of the member was minted by
`elabSetCallRows`, but three things kept mono from reading it: the producer gave up on an argument
typed at a tagged set (`elabTyClosed` alone), `elabValCallNote` dropped every note made at the
root, and the reader matched the call's own instance only. With the split plan on, the plan covered
the call; with it off, deleting the argument read refused `add` as a generic value.
