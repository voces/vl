#### Mechanism

`klIndexFns` gave the last function `klFnHi = klLnStart.length - 1`, the last line of the
FILE. `klRecordLadder` then asked `klTailNames(s, klGLast[g], klFnHi[f])` whether the
ladder's tail names what it excludes, and that walk ran past the function's closing brace
into the module's own top-level statements — where `klLineCallsAny` saw `print(holed(…))`
and read the call as a delegating default. The same over-wide range applied between two
functions, since the previous function's end was only clamped to the next HEADER, not to
its own closing brace. `klFnEnd` walks the braces from the header instead, falling back to
the old answer when they never balance.

The status line is the one the grader's vocabulary offers. Its outcomes describe what a
PROGRAM does, and this witness compiles and runs identically before and after — the defect
is a diagnostic that did not appear. `runs today and must keep running` pins the half the
grader can see; the finding itself is pinned by the `tail-control` / `tail-toplevel` pair
in `tests/vl_kind_ladder_test.ts`, which differ by one line.
