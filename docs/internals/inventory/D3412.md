### D3412 — a `<T>` instantiated at two map types reads a bound map field as a plain `i32` map, so an atom prints its id

**check-clean silently wrong · clause 1 · open · found by the #3318 review's two-instance grid (`g3/*_bound_tparam`) · the same on master `8df60e472` · filed 2026-09-30 against master `8df60e472`**

Repro:

    type AB = "a" | "b"
    type R = { m: {[i32]: AB} }
    function mk(): R {
      const v: {[i32]: AB} = Map()
      v[3] = "b"
      { m: v }
    }
    type S = { m: {[i32]: i32} }
    function mk2(): S {
      const v: {[i32]: i32} = Map()
      v[3] = 7
      { m: v }
    }
    function use<T>(p: T) {
      const e = p.m
      print(e[3])
      print(e[9])
    }
    use(mk())
    use(mk2())

Want:

    b
    null
    7
    null

#### Mechanism

Not traced past the ablation. With one call, or with the field read in place (`p.m[3]`), the
receiver resolves: the program's one banked pin covers the first, the exact instance's binding
(`exactDerivedPinTyOf`) the second. A binding `e` of the field under two pins has neither: the
bank collapses the two pins to none, and `e`'s recorded type is not a derivation the exact
binding resolves. So the read takes the plain `i32` map's reading and prints the atom's id.

#### Ablation

| ingredient changed | outcome | needed? |
| --- | --- | --- |
| drop `use(mk2())` | prints `b`, `null` | **yes** (two pins) |
| `function use(p)`, the hole | prints `b`, `null`, `7`, `null` | **yes** (`<T>`) |
| `print(p.m[3])`, no binding of the field | prints `b`, `null`, `7`, `null` | **yes** (the bound receiver) |
