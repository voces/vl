#### Mechanism

Field code 0 holds `i32`, `boolean` and a string literal set's atom alike, and a field read
formats by its row's recorded field type. `anonValueFitsField` matched a literal to an
anonymous row by name and code only, so `{ f: 4 }` took `{ f: true }`'s row. The rendered-shape
reader, `annShapeIndexOf`, had the same blind spot, which the annotated generic
`const o: { f: T } = { f: v }` reached at `g(true); g(4)`, and so did the render resolver
`structIndexOfTypeName` once other `f` rows were in the module. `declRowScalarFits` let a literal
set take a declared `boolean` or `i32` row. An anonymous row's atom field took any string
literal. A literal delivered straight to an un-annotated parameter recorded the parameter's
open hole as its row type (`anonRowTyIx`), so even a lone `p({ f: true })` printed `1`. All
four readers now ask one comparator (`code0KindOf`: `i32`, `boolean`, string literal set).
An atom field, anonymous or declared, takes only a string literal among its members. So
`type R = { k: "a" | "b" }` no longer captures `{ k: "zz" }` (it printed `b`). It no longer
captures `{ k: s }` with `s: string` either, which was invalid wasm. And `h({ f: "a" })` into an
un-annotated `h` beside a declared `{ f: Kab }` no longer refuses with `print of a literal-union
atom whose type carries no member texts`. A row whose context type is an open hole records
the literal's own shape. The field-set scan (`structRowOfObjFieldSetK`) splits code-0 kinds
and compares a nested record field canonically, and a nested row a declared row would capture
must agree on every self-contained field code: `{ w: { f: "q" } }` beside `type W = { w: { f:
i32 } }` was invalid wasm on master and runs now.
