### D2789 — a generic instantiated at a list of records, whose body captures a loop variable in a closure, is refused for its parameter type

**closed 2026-10-20 by lane mono-rows · runs, prints `1` · was loud emit reject · clause 2 · the D4710 cause: the instance's parameter annotation for the `#anonN[]` pin resolved to no type by name; `monoSynthPinRef` (`emit_mono.vl`) types it at the row's list · pins: `tests/cases/generics/generic-list-param-of-inferred-record-list.vl` and its annotated twin, which carry the record-copy cell too · identical on master `781f68091` · filed 2026-09-27 from the #3209 review**

Repro:

    function run<T>(xs: T[]) {
      for x in xs {
        const f = () => x
        return f()
      }
      xs[0]
    }
    print(run([{ v: 1 }, { v: 2 }]).v)
    // vl check: rc 0.  vl run: emitProgram: only i32, i64, f64, f32, boolean, struct, union, array, or string parameters are supported

#### Mechanism

Not localised. The refusal is `emit_sections.vl`'s parameter valtype floor, reached for the
instance at `T = {v: i32}`. The concrete twin (`xs: R[]` with `type R = { v: i32 }`) runs, and
so does the generic at `T = string`, so the instance's parameter or its closure's env field is
typed from a pin spelling the floor does not classify.

#### Ablation

| ingredient removed | outcome | needed? |
| --- | --- | --- |
| the generic (`run(xs: R[])`) | runs | **yes** |
| the record element (`run(["p", "q"])`) | runs | **yes** |
| a copy (`const c = x; () => c`, or `fs.push(() => c)`) | the same refusal | no |

#### Grading list

The review's record-copy cells (`fs.push(() => c)` over `[{ v: 1 }, { v: 2 }]`).
