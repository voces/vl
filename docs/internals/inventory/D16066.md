### D16066 — a propagating `as` over a nullable struct, list or map has no lowering, where the string one runs

**loud emit reject · clause 2, CAPABILITY: `emitProgram: \`as P\` over a \`P | null\` propagates the null to the caller, and only the trapping and coalescing forms are lowered for that operand` after `vl check` rc 0 · the same cast over a `string | null` runs ([D12461](D12461.md)), as do `as!` and `as?` over the same struct, list and map cells ([D1812](D1812.md), [D12460](D12460.md)) · filed 2026-11-14 against master `752e43c87`**

Repro:

    type P = { a: i32 }
    function f(x: P | null): i32 | null {
      const p = x as P
      return p.a
    }
    print(f({ a: 3 }) ?? -1)
    print(f(null) ?? -1)
    // vl check: rc 0.  vl run: emitProgram: `as P` over a `P | null` propagates the null to the caller

Want:

    3
    -1

#### Mechanism

`emitAsNulNiche` (`compiler/wasmEmit.vl`) lowers `as!` (`ref.as_non_null`) and `as?` (the identity)
for every wired ref-niche payload. It lowers the propagating `as` only for a `string` payload: a
block typed at the string's non-null heap, `br_on_non_null` out of it, else the enclosing
function's null through the union sink. Any other payload reaches the `emitFail`. The O5 ruling
(error-handling-design.md §O5) makes the program legal, and its return type admits the
propagated `null`.
