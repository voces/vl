### D16959 — [CLOSED 2026-11-18] a generic call whose list parameter is handed a union of list types leaves the type parameter open, so its result fits any destination

**closed 2026-11-18 · now a loud check reject, the refusal the design owes; was a loud emit reject · clause 1 · fixed in check_calls.vl: `openArgTyParamRefused` refuses a call whose union argument reaches a list, record or map parameter naming a type parameter the call leaves unbound (or bound only to itself), unless the union stores as one map or list · fixtures `tests/cases/generics/error-union-of-lists-leaves-type-param-open.vl`, `error-union-of-records-leaves-type-param-open.vl`, `union-of-lists-narrowed-binds-type-param.vl` · the twin-list half is [D16963](D16963.md) · found measuring [D2772](D2772.md) · filed 2026-11-18 against master `11fb86413` by lane F1**

Repro:

    const q: string[] | i32[] = [1, 2]
    function first<T>(xs: T[]): T { return xs[0] }
    const a: boolean = first(q)
    print(a)
    // vl check: cannot infer type parameter `T` in this call to `first`: its argument is `string[] | i32[]`

#### Mechanism

Not localised. Handed `string[] | i32[]`, the call binds no `T`: `first(q)` keeps the result type
`T`, which is assignable to every destination, and `wrap<T>(xs: T[]): T[]` keeps `T[]`. The checker
therefore accepts `boolean` here, though the value is a string or an `i32`. Monomorphization then has
no `T` to pin and refuses the call. A design ruling decides what the call should mean, run per
arm or refused at check ([D2772](D2772.md)); either way `T` must not stay open after the call.

#### Ablation

| ingredient changed | outcome | needed? |
| --- | --- | --- |
| `q: i32[]`, one list type | check refuses `i32` into `boolean` | **yes** (the union of list types) |
| `q: i32[] \| i32[]`, one element type | check refuses | **yes** (two element types) |
| `gid<T>(x: T)` over `string \| i32` | check refuses `string \| i32` into `boolean` | **yes** (`T` under a list) |
| a second argument `at<T>(xs: T[], d: T)` with `d = 3` | check refuses | **yes** (no other argument binds `T`) |
| a union of maps through `{[string]: T}` | `T[]` stays open (the refusal names `T[]`) | no: a map element leaves it open too |
| `q` from a call returning `string[] \| i32[]` | the same | no |
| `const a = first(q)`, then `const b: boolean = a` | the same | no |

#### Grading list

The D2772 witness and its neighbours (`first`, a `for` over the parameter, a three-list union), and
the map spelling above.

#### Fix

The same open `T` reached a record parameter: `kk<T>(x: { k: T })` given `A | B` was built at the
unbound default `i32`, so a `{ k: "s" }` argument trapped, and `const z: boolean = kk(r)` printed
`true`. A map union failed at emit as a list union did. All three are refused at the call now. Before
the fix, no file under `tests/cases`, the distilled corpus, std or the capability probes reached the
refusal outside the twin-map union `D15540` settles, which binds as its one map and keeps running.
