### D3522 — `is string` (or `is i32`) over a literal union of a string and an integer member is refused as "not a variant", while `is "s"` runs

**closed 2026-10-03 — the witness prints `str` then `num` · was a loud check reject, clause 2 · found by the #3340 review's 88-cell call grid · filed 2026-10-03 against master `b2238d2c6`, closed by lane LC against master `f6e17953b` · fixture `tests/cases/unions/litunion-is-base-type.vl`**

Repro:

    type T0 = 1 | "s"
    function g(x: T0) {
      if x is string { print("str") } else { print("num") }
    }
    g("s")
    g(1)
    // vl check: "`is` check type 'string' is not a variant of T0"

Want:

    str
    num

#### Mechanism

Confirmed, three faults on one path. (1) The `is` gate took the check type to be a member by
identity. `litBaseMeetTy` now answers the literal members whose base IS the named primitive
(`string` names `"s"`, `i32` names `1`, `i64` names `9000000000`), and the test narrows to them
as a literal-set overlap does (D2205). A primitive that is the base of no member (`f64`,
`boolean`) is still refused. (2) The emitter's tag test read the banked overlap, and an integer
literal has no arm tag; a test spelled as a primitive whose overlap has that base now tests the
base's tag. (3) The else of a test over a box of three literals or more (`1 | 2 | "s"`) pushed
no narrowing, so the else read the box where an `i32` was owed: check-clean invalid wasm on
master for `is "s"` too. `litBoxElseBase` narrows the else to the one base every survivor has.

#### Ablation

| ingredient changed | outcome | needed? |
| --- | --- | --- |
| `is "s"` for `is string` | runs, `str` | **yes** (a base type as the check type) |

| `is i32` for `is string` | still refused | no (the base) |
| a call result bound un-annotated, `const z = f("s")` | still refused | no (the position) |
