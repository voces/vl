### D3522 — `is string` (or `is i32`) over a literal union of a string and an integer member is refused as "not a variant", while `is "s"` runs

**loud check reject · clause 2 · open · found by the #3340 review's 88-cell call grid · the same on master `b2238d2c6` · filed 2026-10-03 against master `b2238d2c6`**

Repro:

    type T0 = 1 | "s"
    function g(x: T0) {
      if x is string { print("str") } else { print("num") }
    }
    g("s")
    g(1)
    // vl check: "`is` check type 'string' is not a variant of T0"

Want:

    str
    num

#### Mechanism

Not confirmed. The `is` gate takes the check type to be a member of the union by identity, and
`T0`'s members are the literal types `1` and `"s"`, not their bases. The base `string` names
exactly the members whose base it is, so the test is a well-formed narrowing the check refuses.
The literal spelling `is "s"` and a union of bases (`i32 | string`) both run.

#### Ablation

| ingredient changed | outcome | needed? |
| --- | --- | --- |
| `is "s"` for `is string` | runs, `str` | **yes** (a base type as the check type) |
| `type T0 = i32 | string` | runs, `str` | **yes** (literal members) |
| `is i32` for `is string` | still refused | no (the base) |
| a call result bound un-annotated, `const z = f("s")` | still refused | no (the position) |

#### Grading list

`is string` and `is i32` over `1 | "s"` and over `9000000000 | 1 | "s"` (the boxed set, D3491),
in an `if` and a `match`, at a parameter, a binding and a call result.
