### D3975 — the checker accepts a hole-lambda `let` called at one type and, after a closure writes a generic into it, delivered at another

**closed by the owner ruling of 2026-10-15 (one closure per call type, DECISIONS.md) · was loud emit reject · found in review of #3501 (`rv3501/b03`, `a06`, `n04`) · filed 2026-10-10 against master `56f77d80f`**

Repro:

    function cs(f: (s: string) => void, s: string) { f(s) }
    function other<V>(v: V) { print("O"); print(v) }
    function main() {
      let k = (x) => { print("L"); print(x) }
      const flip = () => { k = other }
      k(1)
      flip()
      cs(k, "s")
    }
    main()
    // vl check: rc 0.  vl run: L 1 O s (master refused it in the emitter)

Want:

    L
    1
    O
    s

#### Mechanism

The checker pins a hole lambda's binding at its first use. `k(1)` pins `k` at `(i32) => void`,
and a later delivery `cs(k, "s")` at `(string) => void` should be refused at check time, as it is
when the delivery comes first (`b03c`: `argument 1: expected (string) => void, got (i32) => void`)
or when the closure writes a concrete function (`b03f`: `cannot assign (string) => void to
(i32) => void`). When the closure writes a generic (`k = other`) the delivery is accepted, and the
emitter refuses the one binding at two signatures (D3939's rule). Master printed `L 1 O s` only
because `flip` ran first; other orders trap. The owner ruled that the program compiles
instead: `k` holds one closure per call type (`compiler/fn_split.vl`), and the delivery stores
the instance at `(string) => void` by value.

#### Ablation

| ingredient changed | outcome | needed? |
| --- | --- | --- |
| the delivery before the call (`b03c`) | check reject | **yes** |
| the closure writes a concrete `qs` (`b03f`) | check reject | **yes** |
| no closure write, so no cell (`b03d`) | runs, `L 1 L s` | **yes** |
| the delivery at `boolean` (`a06`) or `f64` (`n04`) | the same emit reject | no |

#### Grading list

`rv3501/a06` and `rv3501/n04`, the same order with the delivery at `(b: boolean) => void` and at
`(x: f64) => void`: the checker should refuse both at the delivery.
