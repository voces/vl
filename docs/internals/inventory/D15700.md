### D15700 — a hole its function never calls, handed on in a `const` record to a callee that calls the field at two types, is refused at emit

**closed 2026-11-12, runs and prints `2` `5` · was loud emit reject, clause 2, `a generic function taken as a value reaches no call that fixes its type — annotate the destination's function type` · found closing D15649 · filed 2026-11-11 against master `94b382ce` · closed by a rewrite before the elaboration (`inlineConstRecArgs`, emit_rewrite.vl): a `const` record literal whose fields read only unwritten un-annotated parameters, read once as a positional argument of a named call, is written into that argument, so it is delivered where it is built as the literal written in place is (D15649) · fixture `tests/cases/functions/hole-handed-on-in-const-record-called-at-two-types-runs.vl`**

Repro:

    function dbl(v) { return v + v }
    function call0(r, x) {
      print(r.f(1))
      print(r.f(x))
    }
    function both(g) {
      const r = { f: g }
      call0(r, 2.5)
    }
    both(dbl)

Want:

    2
    5

#### Mechanism

The literal written as the argument is built per instance at the callee's parameter, which the
late tag decision makes a set record; the `const`'s literal was minted before that decision at
its own row, so the binding and the parameter disagreed (two rows, `{f: i32}` and `#anon1`).

Before the close: D15649's close makes a call through a field of a record literal handed straight to
the callee name the set to the late decision; a `const` of the literal is not forwarded
(`holeBindArgListsHole` and `elabRecLitFwdTargets` follow a record only as the argument itself,
[D15639](D15639.md)), so `call0` takes `r` at a closure record called at two types.
