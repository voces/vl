### D17051 — an un-annotated record literal holding a generic function keeps the open `(T) => T` in its rep, though legacy stores it on the instance's struct heap

**runs today and must keep running · IR rep defect · the program runs; an IR record retag of it would be unsound, so the IR leaves the argument a named `argument coercion` miss · found by lane IR-M1's RRowRetag lowering check · filed 2026-11-22 against master `2934a5208`**

Repro:

    type G = { g: i32 }
    function k<T>(x: T): T { return x }
    function show(o: G) { print(o.g) }
    const r = { f: k, g: 7 }
    show(r)
    // vl run: prints 7. Under VL_IR_SHADOW=2 the start body is `uncovered argument coercion`:
    // the argument's rep is `{f: (T) => T, g: i32}`, field `f` a closure of `unsup` kids; the
    // parameter's is `{f: (i32) => i32, g: i32}`; both types sit on one struct heap.

Want:

    7

#### Mechanism

The record literal's rep is built from its own literal type, whose field `f` still names the
generic `k`'s open `(T) => T`, so `rtGo` gives the closure's parameter and result `RUnsup`. Legacy
stores the record on the struct heap of the instance the parameter names (`recordHeapOfTy` agrees
for both types), where `f` is `(i32) => i32`. The two reps cannot lower to the same valtypes
(`repsLowerAlike` in `compiler/ir.vl`), so the IR may not retag one as the other: the argument's
rep, not the storage, is wrong. The instance the heap takes is the hole's default (`i32`), or the
type a call of `r.f` pins (`string` in `objects/const-record-field-of-generic-called-direct-and-read-under-is.vl`).

#### Ablation

| ingredient | outcome | needed? |
| --- | --- | --- |
| `k` generic (`function k(x: i32): i32` instead) | covered: the field's rep is the closure the heap stores | **yes** |
| `r` un-annotated (`const r: H = …` with `H = { f: (x: i32) => i32, g: i32 }`) | covered | **yes** |
| a call `r.f(1)` or `r.f("s")` before `show(r)` | same miss, at the call's instance | no |
| module scope (`r` inside a `main()` instead) | same miss in `main` | no |
