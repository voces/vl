### D3428 — a negative constant stored into a `u8` element truncates to its low 8 bits, which the exact-constant ruling says a destination that cannot hold it refuses

**check-clean silently wrong · needs an owner ruling: does a negative integer literal (and so a negative constant) at a `u8` element refuse, as one past 255 does? · the same on master `5e277ab52` · found by the exact-constant grid's `u8` column · filed 2026-09-30 against master `5e277ab52`**

Repro:

    const K = -2147483648
    const xs: u8[] = [K]
    print(xs[0])
    // PRINTS 0

#### Mechanism

A `u8` element takes a literal by the literal's own rule: past 255 it is refused ("the literal
256 does not fit a `u8` element"), but a negative literal is admitted and stored truncated (`-7` is
249, `-2147483648` is 0). A constant is its literal at every read (ruling C), and the
literal-binding grid pins `-7` into a `u8` element as running with 249, so the exact-constant fold
keeps that rule rather than refusing on its own. Ruling A's "a use whose destination cannot hold
the exact value is a check error" says otherwise for every negative value. Recommendation: refuse a
negative literal at a `u8` element exactly as one past 255 is, since `x as u8` is the spelling of
the wrap, and update the literal-binding grid's `u8` column with it.

#### Ablation

| spelling | outcome |
| --- | --- |
| `[-7]` into `u8[]` | `249` |
| `[256]` into `u8[]` | refused |
| `[K]`, `const K = 255 + 1` | refused, as the literal `256` is |
| `[K]`, `const K = 0 - 7` | `249` |
