### D4063 — an importer may assign an imported `let`, and the write lands in the exporter's binding

**open · check-clean silently wrong value: a write the design forbids is accepted and changes another module's state · found writing `docs/spec/modules.md` (lane SPEC) · filed 2026-10-11 against master `98a4ed71b`**

Repro:

    // file: c.vl
    export let count = 0
    export function get(): i32 { count }
    // file: main.vl
    import { count, get } from "./c"
    count = 5
    print(get())
    // vl check: rc 0.  vl run: rc 0
    // PRINTS 5

#### Mechanism

`docs/internals/modules-design.md` §5, decided direction 4 (owner-reviewed): exports are
live references and "the imported name is **read-only** (no reassigning another module's
`let`)". The checker refuses an assignment to an imported `const` with the const message,
but an imported `let` binds in the importer as the exporter's own mutable global, so the
assignment type-checks and the emitted `global.set` writes the exporter's variable.

#### Ablation

| variant | outcome |
| --- | --- |
| imported `let`, `count = 5` | accepted, the exporter's `get()` returns 5 (wrong) |
| imported `let`, `count += 1` | accepted (wrong) |
| imported `const`, `K = 5` | refused, "cannot reassign `const` K" (right) |
| imported `const` record, `cfg.n = 9` | runs, prints 9 (right: a field write) |
| re-exported `let` imported through the re-exporting module | accepted (wrong) |

#### Grading list

The two-file repro should be refused at `count = 5`, with a message saying an imported
binding is read-only and naming the exporting module. The field write and the exporter's
own writes (`bump()` in `docs/spec/modules.md` §M2.2) must keep running.
