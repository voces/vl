### D7144 — a record of a type-parameter `let` copy that a closure writes has no struct type

**closed 2026-10-19 by lane L1 · runs, prints `4` · was a loud emit reject · `vl check` rc 0 · clause 2 · two holes: the instance re-makes the literal over the capture cell's retyped read after the collect pass minted rows, typed closed, and the closed case minted no row (`mintPinnedObjLit` now interns it); and a copy `const v = b` of the cell has no walk to a parameter, so its pin reads the instance's binding of its type parameter (`pinnedValTyOf`) · pins: `tests/cases/closures/typaram-let-copy-closure-written-in-record.vl` (direct, copied, annotated; i32, f64 and string instances) · found closing [D7100](D7100.md) · the same on master `8e787a973` · filed 2026-10-19 against master `8e787a973`**

Repro:

    function mid<H>(a: H, c: H) {
      let b = a
      const w = () => { b = c }
      w()
      const r = {f: b}
      print(r.f)
    }
    mid(3, 4)
    // vl check: rc 0.  vl run: emitProgram: object literal but no struct type declared

Want:

    4

#### Mechanism

Two holes. The lambda-pin pass re-makes `{f: b}` over the capture cell's retyped read after
`collectAnonShapes` has minted rows, so the new literal is typed `{f: i32}` with no row, and
`mintPinnedObjLit` returned early for a closed type. And for `const v = b; {f: v}` the pin walk
(`pinnedValTyOf`) found no parameter through the cell read, so it now reads a bare type
variable at the instance's binding of it.
