### D3871 — a union of two same-SHAPED records `A | B` resolves un-narrowed method dispatch and a generic's method call to its FIRST member, so a `B` value typed `A | B` answers with `A`'s method

**closed (2026-10-08, lane SC) · now a loud check reject at the parse stage, the module merge's `Duplicate binding "d"` · was check-clean silently wrong · found by the rv3461 review of #3454–#3461 (c/c29.vl and neighbours) · decided by the owner's ruling on D3870 · filed 2026-10-08 against master `862c99b79` · pins: `tests/cases/modules/error-overload-same-shape-records/`**

Repro:

    // file: r1.vl
    export type A = { x: i32 }
    export function d(self: A): string { "RA" }
    // file: r2.vl
    export type B = { x: i32 }
    export function d(self: B): string { "RB" }
    // file: entry.vl
    import { A, d } from "./r1"
    import { B, d } from "./r2"
    function h<T>(x: T): string { x.d() }
    const b: B = { x: 2 }
    function f(v: A | B): string { v.d() + h(v) }
    print(f(b))
    // vl check: rc 0 (hints only).  vl run: rc 0
    // PRINTS RARA

Want:

    vl check: Duplicate binding "d"

#### Mechanism

`A` and `B` have one field set, and the owner ruled (D3870) that records are structural: they
are one type, so `A | B` is `A`, and a `d(self: A)` beside a `d(self: B)` is two bindings of one
name over one receiver class. The merge's overload check (`modOvCheckSet`) gave each declared
record its own head class by name, so the pair stood and the union's first member answered for
both. Two declared records of one shape, the same field names with each field's type spelled
alike or naming records of one shape, are now one head class (`modOvRecHeadsSameShape`), and
the pair is the duplicate binding any same-class pair is. A newtype (`new { … }`) keeps its own
class, and records of different shapes still overload.

#### Grading list

The narrowed spelling prints `RB` today, but `is` between same-shape records tests only the shape
(D3870), so a `v is A` guard on the same `b` is the control to run with it: the close has to say
what `is` answers there before it can say what the call answers. Programs that run correctly today
and must keep running: `h(b)` and `b.d()` on a plainly `B`-typed value, the `B | A` ordering, and
the different-shape union, which stays a loud check reject. Grade it at the annotated `f(v: A | B)`
above and at a parameter whose union type is inferred.
