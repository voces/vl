### D3083 — a hole function's `.filter` callback that reads its element is invalid wasm at a `string[]` pin, with no capture

**closed 2026-09-28 — the witness prints `b` · was check-clean invalid wasm · `monoCloneLambdaSubst` pins a hole instance's lambda through the instance's hole binding, and the template every instance cloned is pruned (`monoLamSlotIsHoleTemplate`) · grid rows graded against master `d408f2da4`, 0 runs lost · fixture `tests/cases/generics/hole-callback-reads-element-and-captures.vl` · first filed as: check-clean invalid wasm · clause 1 · the no-capture sibling of [D3067](D3067.md), found by the #3269 review · the same on master `67ca68cf3` · filed 2026-09-28 against master `67ca68cf3`**

Repro:

    function g(h) {
      return h.filter((e) => e != "a")
    }
    const b: string[] = ["a", "b"]
    print(g(b)[0])
    // vl check: rc 0.  vl run: invalid module inside `__lambda_0`, expected (ref $type), found i32

Want:

    b

#### Mechanism

A hole function's callback lambda is typed at the hole's variable, and the lambda clone (`monoCloneLambdaSubst`) substituted only through the parameter binding, which for a hole function is empty: the callback kept the template's `i32` element. The clone now joins the instance's hole binding (`monoJoinBinding`), so its parameter and return are annotated at the pin, and a template every instance cloned is pruned (`monoLamSlotIsHoleTemplate`), since its body still reads the `i32` element and would not validate.

#### Ablation

| ingredient changed | outcome | needed? |
| --- | --- | --- |
| `(e) => true` | prints `a` | **yes** (the element read) |
| `function g<T>(h: T[])` with `(e) => e != e` | runs | **yes** (the hole) |
| an `i32[]` pin with `(e) => e != 1` | runs | **yes** |
| the clone without the hole binding, or without the prune | invalid wasm | **yes** (the fix, both halves) |
