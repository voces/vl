### D3083 — a hole function's `.filter` callback that reads its element is invalid wasm at a `string[]` pin, with no capture

**check-clean invalid wasm · clause 1 · open · the no-capture sibling of [D3067](D3067.md), found by the #3269 review · the same on master `67ca68cf3` · filed 2026-09-28 against master `67ca68cf3`**

Repro:

    function g(h) {
      return h.filter((e) => e != "a")
    }
    const b: string[] = ["a", "b"]
    print(g(b)[0])
    // vl check: rc 0.  vl run: invalid module inside `__lambda_0`, expected (ref $type), found i32

Want:

    b

#### Mechanism

Not localised past the ablation. The lambda is emitted with an `i32` element parameter where the
instance's receiver holds strings, so the element's string compare does not fit. A callback that
never reads its element (`(e) => true`) runs, which is why D3067's ablation read the capture as
the ingredient; this witness captures nothing. The monomorphizer's per-instance callback pin
(`monoPinMapLambdas`) is the likely place both rows meet.

#### Ablation

| ingredient changed | outcome | needed? |
| --- | --- | --- |
| `(e) => true` | prints `a` | **yes** (the element read) |
| `function g<T>(h: T[])` with `(e) => e != e` | runs | **yes** (the hole) |
| an `i32[]` pin with `(e) => e != 1` | runs | **yes** |
