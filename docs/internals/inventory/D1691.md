### D1691 — the `| null` niche's element ladder has NAMED empty arms for a nested-list and a map element, so an inferred `i32[][] | null` field gets no code while its non-null twin gets one

**loud emit reject · filed 2026-09-06 against master `ddc4b852a` · D1663's residue: the
code-28 element ladder is narrower than the code-5 one it mirrors · 0 corpus cells**

Repro:

    function nul(): i32[][] | null { return [[7]] }
    function two() {
      const box = { xs: nul() }
      const l = box.xs
      if l != null { print(l[0][0]) }
    }
    two()
    // vl check: rc 0.  vl run: emit error,
    // emitProgram: object literal matches no struct

Its non-null twin — `function plain(): i32[][]` and `print(box.xs[0][0])` — runs and prints
`7`, at the same seed, with nothing else changed.

#### Mechanism

`anonNulFieldCodeOfTy` codes a `TyArray` inner through `anonNulListFieldCodeOfElem`, whose
ladder over the element type carries NAMED empty arms for `TyArray`, `TyMap` and `TyNullable`
— "no cell has graded their nullable field rep yet, so they refuse loudly rather than take
code 28 on trust". The named default is the ladder rule working as intended; the gap is that
the code-5 twin admits all three, and has since D1688 built `anonRefListElemKeyOf` for
elements no `sNames` row names. So the literal takes no field code at all, the holder is
minted no row, and the sentence a user reads (`object literal matches no struct`) is two
readers away from the ladder arm that declined.

The grid, one element kind per row, each cell the SOLO holder so no twin collision is in play,
graded on master `ddc4b852a` and unchanged by D1663's close:

| element | `X[]` field (code 5) | `X[] \| null` field (code 28) |
| --- | --- | --- |
| a declared struct `A` | runs `7` | runs `7` |
| a closure `(i32) => i32` | runs `7` | runs `7` |
| a self-recursive struct `Node` | runs `7` | runs `7` |
| a nested list `i32[]` | runs `7` | **emit rejects** |
| a map `{[string]: i32}` | runs `7` | **emit rejects** |
| a nullable ref `A \| null` | runs `7` | **emit rejects** |
| a union arm `Shape` | emit rejects (a different gap: `field access receiver is not a struct` at BOTH codes) | emit rejects, same sentence |

**The nested-list and map arms are two lines, and that is measured, not estimated.** Replacing
the two empty arms with `return 28` moves four cells (`i32[][] | null` and
`{[string]: i32}[] | null`, solo and beside a differently-named sibling) from emit reject to
`runs`, with the same output as their code-5 twins. The `TyNullable` arm does NOT move — a
nullable ELEMENT list has its own family and folds onto a different code, which is what its
own arm already says. **That two-line edit is deliberately NOT in D1663's PR**: widening a
gate is the step that converts a loud refusal into invalid wasm at every position it was not
wired for, so it owes the position matrix
`scripts/capability-probes/matrix/anon-struct-twin-holders-nullable-list-field.matrix.vl`
re-run over a nested-list and a map element, in both faces, before it lands.
