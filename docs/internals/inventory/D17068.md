### D17068 — a union `==` evaluates its operand only inside the box's tag-matched arm

**closed 2026-11-23 by lane IR-S1 · now runs, `false` `true` `2` · was check-clean silently wrong · an operand with effects is read once, in source order, ahead of the tag test, with the box beside it (`emitUnionEqStaged`); the null legs read an operand left of a staged box first; each nesting level takes its own slots · pin: `tests/cases/eval-order/union-compare-operand-runs-once.vl` · filed 2026-11-23 against master `53f48d79`**

Repro:

    type U = i32 | string
    let m = 0
    function f(): string {
      m = m + 1
      return "s"
    }
    function g(u: U) { return u == f() }
    print(g(1))
    print(g("s"))
    print(m)

Want:

    false
    true
    2

#### Mechanism

`emitUnionConcreteEq`'s plain and stashed arms (`unionEqTagTail`, then `unionEqPayloadTail` and
the operand inside the `if`) read the operand only when the box's tag selects the operand's arm.
A box holding another arm answers `0` and never evaluates the operand, so its effects are lost.
The IR builds the same plan (`unionConcreteEqPlanOf`, `unionEqStashPlanOf`), so it does the same.
An operand with a null leg (D17065) is read ahead of the tag test and is not affected.
