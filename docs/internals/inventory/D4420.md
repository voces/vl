#### Mechanism

Calling a hole `a(...)` records each argument against `?arg.<j>.<a>` and types the result
`?ret.<a>` (`checkCallNode`, `compiler/typecheck.vl`). At `take(same)` the pin bound `a` to
`same`'s open signature `(k: T) => T`, so both derived holes resolved to `T`: the body was
never checked at an instance, and the monomorphizer found a pin carrying a type variable
(`recordedParamPinName` answers "") and an argument it never instanced. Two ill-typed
siblings were check-clean for the same reason (`const r: i32 = a("x")`, and `r + 1` over
`const r = a("x")`). `instGenFnHolePins` now instantiates the generic at the pin from the
argument rows the body recorded against the hole, before the validators and `callBindNote`;
`monoHoleGenFnPin` (`compiler/emit_mono.vl`) reads that binding back with `callBindTyOf` and
coerces the argument to it. Calls that disagree, or an argument still open, keep the
generic binding (D4421).
