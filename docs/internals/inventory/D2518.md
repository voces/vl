### D2518 — a map or set method name on an un-annotated parameter forces a map even when a `self`-function of that name is in scope

**closed 2026-09-25 — the witness prints `true` · was loud check reject, clause 2 · filed 2026-09-25 against master `54fcaf5d8` from the #3161 review · fixture `tests/cases/generics/member-call-hole-self-fn-no-map-demand.vl`**

Repro:

    function get(self: Set<i32>, k: i32): boolean { self.has(k) }
    function f(x) { x.get(4) }
    const s = Set<i32>()
    s.add(4)
    print(f(s))
    // filed: argument 1: parameter is used as a map but nothing in the body pins its key or value — add a type annotation

#### Mechanism

`checkMemberCallNode` turns a hole receiver into the hole's demanded map the moment it meets a
map/set method name (`holeMapMethod`: `get`/`set`/`has`/`delete`/`add`/`keys`/`values`), and into
a list for `push`/`pop`/`map`/`filter` (`holeArrMethod`), before any `self`-function is
considered. With `get(self: Set<i32>, …)` in scope the demanded map could never be satisfied by
the `Set` the call site passes, and with `add(self: {[i32]: boolean}, …)` the demand minted a
`Set` a boolean map could not satisfy. The close (`holeMethodIsSelfFn`) leaves the hole open
when a `self`-function of that name is in scope, so the call is typed against it and the call
site's pin picks the built-in, a field or the function for its own argument
([D2517](D2517.md)). `map`/`filter` still demand a list: the pin cannot state a callback's
parameter type. A site the emitter cannot re-dispatch per instance — a local copy of the
parameter, or a closure ([D2520](D2520.md)) — keeps the demand too, so its built-in runs as on
master (`tests/cases/generics/member-call-mutating-builtin-through-local.vl`).

#### Ablation

| ingredient removed | outcome | needed? |
| --- | --- | --- |
| the function (`get` absent) | the same refusal, correctly: a `Set` has no `get` | **yes** |
| the un-annotated parameter (`x: Set<i32>`) | prints true | **yes** |
| the `Set` flavour (`add(self: {[i32]: boolean}, …)` with `x.add(3)`) | refused: expected Set<i32>, got {[i32]: boolean} | no |
| `<T>` in place of the hole (`f<T>(x: T)`) | the same refusal | no |
