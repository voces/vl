### D2424 — a deferred call-argument constraint is keyed on the type parameter's NAME, so one generic's demand refuses a sibling's call

**closed 2026-09-25 — the witness runs and prints `5` then `x` · was a loud check reject (`argument of type string flows into \`toString\` expecting i32 | i64 | boolean | f64`), clause 2 · found grading D2344, filed 2026-09-25 against master `a277bf7b0` · fixture `tests/cases/generics/arg-constraint-scoped-to-its-callee.vl`**

Repro:

    import { toString } from "std:fmt"
    function show<T>(c: T) { return toString(c) }
    function third<T>(_a: i32, b: T): T { return b }
    print(show(5))
    print(third(1, "x"))
    // vl check (as filed): rc 1, argument of type string flows into `toString` expecting
    // i32 | i64 | boolean | f64 (the call's argument types). Now prints 5 then x.

#### Mechanism

A generic body that hands its type parameter to a concrete parameter (`toString(c)`) cannot judge
the demand, so it records `(T, i32 | i64 | boolean | f64)` in `argCstrAt`/`argCstrExp`, and every
generic call re-asks it under its own binding. The list had no owner, and `substTyDeep` matches a
`TyVar` by name, so `third(1, "x")` — which binds a `T` of its own to `string` — adjudicated
`show`'s demand. The binary-op, print, return, let and member lists already carry an owner column
for exactly this reason (`cstrOwnedBy`); the argument list now does too (`argCstrFn`), stamped with
`cstrOwnerTop()` and filtered at the pin, and, as `validateBinCstrs` does, it re-records a demand
under the caller's hole only when the callee is named.

An interpolation hole is the common way to reach it: `"\{c}"` desugars to the same `toString`
call, so any `<T>` that interpolated its parameter made every other `<T>` in the program refuse a
`string`, a record or a list binding. The D2344 fixture tripped on it eleven times.

#### Ablation

| ingredient changed | outcome (as filed) | needed? |
| --- | --- | --- |
| `third<U>` | runs | the shared name: **yes** |
| no call to `show` | same refusal | no |
| `show` interpolates (`"\{c}"`) | same refusal | no |
| `third(1, 5)` | runs | a binding outside the demand: **yes** |
| the direct true positive `function f<T>(x: T) { g(x) }`, `g(n: i32)`, `f("s")` | refuses, before and after | the scoping keeps it |

#### Grading list

The same body's own demand must keep refusing at a direct call, a nested generic call
(`outer<U>(y: U) { f(y) }` with `outer("s")`) and a call through `const h = f`; all three refuse
before and after. The method spelling and a generic function value never adjudicate the list at
all, which is [D2425](D2425.md).
