### D15547 — a `Map()` held in a list, handed to an un-annotated parameter, has no argument type when only the callee pins the map

**loud emit reject · `vl check` rc 0 · clause 2 · `monomorphize: unsupported argument type for a` (`monoArgTyFail`, emit_mono.vl) · found grading [D15546](D15546.md)'s siblings · filed 2026-11-08 against master `dc29cbb8`**

Repro:

    function t(a) {
      a[0]["k"] = 41
      print(a[0]["k"] ?? 0)
    }
    t([Map()])

Want:

    41

#### Mechanism

Not traced. The callee's `a[0]` is an element hole of `a` (`HD_ELEM`), which
`holeKidMapDemands` does not follow into the argument's element, so the list's map stays
open. D15546 closed the record-field twin by following `HD_FLD`.

#### Ablation

| ingredient removed | outcome | needed? |
| --- | --- | --- |
| the hole parameter (`const xs = [Map()]`, the store on `xs[0]`) | runs, `41` | **yes** |
| the binding (`const xs = [Map()]; t(xs)`) | still refuses | no |
| the open map (`[Map<string, i32>()]`) | runs, `41` | **yes** |
| the store (`print(a.length)` alone) | still refuses | no |

#### Grading list

The record-held forms `t({ f: [Map()] })` and `t([{ f: Map() }])` refuse the same way. The
store-free spelling `print(a.length)` should become the `cannot infer a type` check reject,
as the record-field twin did in D15546.
