### D15547 — a `Map()` held in a list, handed to an un-annotated parameter, has no argument type when only the callee pins the map

**closed 2026-11-08 · runs, prints `41` · was loud emit reject, `monomorphize: unsupported argument type for a` (`monoArgTyFail`, emit_mono.vl), `vl check` rc 0 · clause 2 · closed by pinning the argument's map from the callee's store through the element, as D15546 did through a field (`holeKidMapDemands` follows an element read's derived hole, check_demands.vl); the store-free spelling is now a check reject naming the path (`cannot infer a type for 'xs[i]'`) or the argument written in place · fixtures `maps/list-held-map-pinned-by-callee-store.vl`, `maps/error-list-held-map-never-pinned.vl`, `maps/error-list-held-maps-two-value-types.vl` · found grading [D15546](D15546.md)'s siblings · filed 2026-11-08 against master `dc29cbb8`**

Repro:

    function t(a) {
      a[0]["k"] = 41
      print(a[0]["k"] ?? 0)
    }
    t([Map()])

Want:

    41

#### Mechanism

The callee's `a[0]` is a hole derived from `a` (`HD_ELEMV`, the read; `HD_ELEM`, the storage),
and the store into it gives that hole a map demand. Element holes were not kids of their base,
so `holeKidMapDemands` never asked their demands against the argument and the list's `Map()`
stayed open. Element holes are now kids, and one is asked against the argument's `aElem`.
The store-free half: `holeArgIsInlineMapSource` now sees through a list literal, and
`recOpenMapPath` through a list element, so an open map no write types takes the binding's
`cannot infer a type` refusal. A local `const xs = [Map()]; print(xs.length)` was an emit reject
(`ref valtype with no interned shape`) and takes the same refusal.
