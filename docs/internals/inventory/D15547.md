### D15547 — a list literal's refused trial delivery beside an `==` left its elements' box records at the other list's union

**closed · 1 delivery of the box shadow (`lists/list-literal-eq-across-element-storages`) · filed 2026-11-08 against master `4409492f`**

Repro:

    const n: (i32 | null)[] = [1, null]
    print(n == [1.0, null])

Want:

    true

#### Mechanism

`eqLitDeliver` (D15091) asked `assignableExpr(lit, own, other)` to decide whether the literal is
built at the other operand's list type. That call stamps as it goes: the `null` element fits
`i32 | null` and its box record was written there before `1.0` refused the whole delivery. The
literal is then built at its own `(f64 | null)[]`, so its record said `i32 | null` while the
element is boxed as `f64 | null`. The emitter read the site's union, so the program ran; a
delivery reading the record would have built the wrong box. Closed by asking the fit quietly
first and stamping only a delivery that holds.

#### Ablation

| ingredient removed | outcome | needed? |
| --- | --- | --- |
| `1.0` spelled `1` (the delivery holds) | record and site agree, `i32 \| null` | **yes** |
| the `null` element | no element is boxed, nothing recorded | **yes** |
| `==` (a binding `const m: (i32 \| null)[] = [1.0, null]`) | loud check reject | **yes** |
