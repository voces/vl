### D16590 — a generic function at a field of a record literal argument is not bound by the destination, as one handed directly is

**loud emit reject · clause 2 · open · `vl check` rc 0 · `emitProgram: a generic function taken as a value reaches no call that fixes its type — annotate the destination's function type` · the record-literal-argument face of [D16410](D16410.md) · cell `record_arg` of `generic-fn-record-result-bound-by-destination.matrix.vl` · filed 2026-11-15 against master `c8f0324da`**

Repro:

    function gid<A>(x: A): A { x }
    function unbox<A>(r: { f: (x: A) => A }): (x: A) => A { r.f }
    const k: (x: f64) => f64 = unbox({ f: gid })
    print(k(1.5))
    // vl check: rc 0.  vl run: emit error, a generic function taken as a value reaches no call that fixes its type

Want:

    1.5

#### Mechanism

`dstBindOpenFnTyParams` (`check_assignable.vl`) binds a callee type parameter from the destination
where each parameter naming it is a function type handed an open function (`dstOnlyOpenFnArgsName`).
`unbox`'s parameter is a record type whose field is the function type, so `A` is not bound; the
record literal's `gid` then reaches the emitter with no call fixing its instance. A list literal
argument (`first([gid])`) already runs, so the record field is the missing position.
