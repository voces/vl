### D1305 — the COLLECT pass reserves an array literal's list type from the module NAME table, so a shadowing local's element type is never reserved

**loud emit reject · `vl check` rc 0, then `emitProgram: array literal but list type not collected` · clause 2 · was a silent miscompile before #2447 (invalid wasm on a program `vl check` accepts) — D705 fixed the CLASSIFIER's frame-blindness and this is the same blindness one pass earlier, in `collectA`, which walks the arena FLAT and has no `fnIx` to be frame-aware with · found 2026-09-03 by D705's own sibling matrix (`pos_elem`)**

Repro:

    const sh: string = "hi"
    function leg(): i32 {
      const sh = 7
      const xs = [sh]
      return xs[0]
    }
    print(leg())
    // vl check rc 0. vl run:
    // emitProgram: array literal but list type not collected

#### Mechanism

`collectA` is a flat `while i < P.nodes.length` walk, so its array-literal arm asks
`arrLitIsStr(i, -1)` — fnIx `-1`, deliberately, because the walk does not know which
function the node sits in. At `-1` the frame guard `identBoundInFrame` cannot see the local
`sh`, so the element still classifies as a STRING and `slUsed` is reserved instead of
`lUsed`. The EMIT pass then classifies the same literal with the real `fnIx`, wants the i32
list, and finds no reservation. Both halves are now individually correct about the type;
they disagree because only one of them is given the frame. The fix is a node→enclosing-
function answer the collect walk can afford — not another classifier arm.
