### D14551 — a list of a union over same-shape twin-record lists takes its rep from the spelling, which the arena row merges

**closed 2026-10-27 · runs, prints `false` · was a refutation pin for deleting `recordUnMemTys`'s last spelling path · filed 2026-10-27 against master `ffe16aa08` · fixed: an inline union row records the arena type its registrar renders when the spelling's re-parse has fewer members (`mintInlineUnion`, emit_collect.vl), so the list's element finds its row by canon id; the twin-record spelling path (`unionHasTwinRecordList`, `listOfTwinRecord`) and `mintInlineUnion`'s twin lone-literal rung are deleted · pins: `tests/cases/generics/nullable-fold-nominal-lists-and-literal-box.vl`**

Repro:

    type Rec = { x: i32 }
    type Rec2 = { x: i32 }
    const rl: Rec[] | null = [{ x: 7 }]
    const r2: Rec2[] | null = [{ x: 8 }]
    function G<A, B>(k: i32, a: A, b: B): (A | null) | B {
      if k == 0 { return a }
      if k == 1 { return b }
      return null
    }
    const w = [G(1, r2, rl)]
    print(w[0] == null)

Want:

    false

#### Mechanism

`recordUnMemTys` (`compiler/emit_rep.vl`) fills a union row's member columns from canon,
except when `unionHasTwinRecordList` (`compiler/check_program.vl`) finds a member that is a
list of a record with a same-shape twin (D3503). For `Rec2[] | null | Rec[] | null`, canon
has two members (`Rec2[]`, `null`), because the arena merges the two same-shape lists as the
structural-records ruling says it should, while the spelling has four atoms. The rep of the
list `w` is still keyed on the four-atom spelling, so with canon's two members `emitIndex`
(`compiler/wasmEmit.vl`) finds no array member for `w[0]`'s receiver. The fix is to key the
list-of-union rep on the arena row. After that the twin branch, the last spelling path, can
be deleted.

The fix found the cause one step earlier. The list's element is the arena union
`(Rec2[] | null) | (Rec[] | null)`, and `repOfArray` asks for its row by canon id. The row
was minted by `registerInlineUnionOfChild`, which passes no `ty`, so `mintInlineUnion`
re-parsed the spelling. The re-parse dedupes the twin lists to `Rec2[] | null`, a different
canon id. The row now records the element type the registrar renders whenever the re-parse
has fewer members than it. Taking the rendered type for every row instead failed 32
`tests/cases` fixtures (generic applications, `??` merged rows, nested inline literals), so
the re-parse stays the row's type wherever it keeps every member.
