### D1242 — [CLOSED 2026-09-03] an INFERRED anonymous struct whose field holds a union value: the mint had no field code for a union, so the literal got no row at all

**runs, prints `5` — CLOSED 2026-09-03 by giving `anonFieldCode` the code-16 arm its
DECLARED twin has, plus the companion column that admits it (`anonUnionFieldName` /
`anonFieldElemName`) · clause 2 · the position matrix goes **19 of 28 → 40 of 40, 0 silent**,
and a 13-cell face grid 4 → 12 · zero `runs` lost, `gate.sh` green on all 19**

Repro (runs, prints `5`):

    const u: i32 | null = 5
    const w = { f: u }
    print(w.f ?? 0)

#### Mechanism

`collectAnonShapes` mints an `#anon` row only if EVERY field value has a code, and
`anonFieldCode` gated both of its rungs on `anonTySpellable` — which is `nodeTyName(v) != ""`
read off the type, and `nodeTyName` deliberately spells no union and no nullable. So a
literal with a union-valued field got **no row**, `structIndexOfObj` answered -1, and
`emitObjLitNode`'s fallback for a row-less literal in a union-declaring program is
`emitUnionBox` — whose `objVariantName` answers `""`. That is why a program with no union
TYPE in it received a message about union VARIANTS: the sentence belonged to the fallback,
not to the defect.

The declared twin `type W = { f: i32 | null }` never took that path: `fieldCodeOfSpelling`
codes the field 16 through `isValueUnionName`, and `shapeFieldElemName` records the member
set beside it. `anonUnionFieldName` is that pair asked of the TYPE — three rungs, in the
declared ladder's own order: the arena's `fieldCodeOfTy == 16` with `isValueUnionName` over
the render; `unionRowOf` for a registered union on either registry column (`isUName` reads
the ALIAS names only, and `tyToEmitName` renders an alias as its MEMBER SET, so the two
spellings never met); and `unRowOfCanon`, which keys on the canonical type id and so finds a
declared union whose render is structural.

**AND MINTING THE ROW EXPOSED A SECOND DEFECT, WHICH THE FIX HAD TO CARRY.**
`anonValueFitsField`'s union-box leniency (`sc == 16 { return true }`) is about the ATOMS a
`{tag, anyref}` holds. With the inner row now minted, `{ f: { f: u } }` merged its OUTER
literal onto the INNER row — both field-name sets are `{f}` — and the code-16 field accepted
the nested struct, so reading `w.f` found a box where a struct ref is stored. The refutation
is `unionSetCanHoldStruct`: a nested object literal fits a box only where the field's own
member set has a variant arm. Refutation-only, so an unregistered set answers YES.
