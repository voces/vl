### D3334 — an un-annotated `string`, `i32`, `null` join passed to a generic builds invalid wasm

**closed 2026-10-26 · runs, prints `x` `4` `null` · fixed when `monoArgTyName` began reading an argument's pin from its closed type before its binding and rep rungs; the mechanism is not traced past that · was check-clean invalid wasm, clause 1 · filed 2026-09-30 · pin: `tests/cases/generics/inferred-string-int-null-join-into-generic.vl`**

Repro:

    function show<U>(v: U) {
      print(v)
    }
    function g(a0: string, a1: i32, k: i32) {
      const r = if k == 0 { a0 } else if k == 1 { a1 } else { null }
      show(r)
    }
    g("x", 4, 0)
    g("x", 4, 1)
    g("x", 4, 2)
    // vl check: rc 0.  vl run: invalid module inside `g` (expected (ref $type), found (ref $type))

Want:

    x
    4
    null

#### Mechanism

Not localised past the ablation. The join is the value union `string | i32 | null`, and the
argument pins `show` at a spelling whose box row is not the one the binding was built as: the
annotated binding runs, and so does the same join with its `i32` arm first, so the two sides
most likely name the member set in two orders (a box's tags are positional).
