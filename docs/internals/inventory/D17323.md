### D17323 — a binding annotated with a type parameter bound to a generic function closes that type parameter at its first call, so a second call shape is refused at check

**loud check reject · clause 2 · filed 2026-11-25 against master `1bede247` by lane N10 · found probing D17117**

Repro:

    function same<T>(k: T): T { return k }
    function other<T>(k: T): T { return k }
    function mid<F, G>(a: F, a1: G) {
      let b: F = a1
      print(b(3))
      print(b("y"))
    }
    mid(same, other)
    // vl check: argument 1: expected i32, got string (the call of `b` in `mid`, at 6:11)

Want:

    3
    y

#### Mechanism

`F` is bound to `same`'s generic type, which any call shape may instance. The binding `b: F`
closes `F` at the first call through it, so a later call at another shape is refused as an
argument mismatch. The same program with the binding unannotated runs, and so does `a1` called
at two shapes directly: the type parameter stays generic there. The design permits this program,
so the refusal is the check's.

#### Ablation

| ingredient removed | outcome | needed? |
| --- | --- | --- |
| the annotation: `let b = a1` | runs, prints `3` / `y` | **yes** |
| the binding: `a1(3)` and `a1("y")` | runs | **yes** |
| the second call shape: `b(3)` twice | runs | **yes** |

#### Grading list

The hand-on spelling must run too. There, `F` is closed by `a("x")`, and `b` is handed to
`call<H>(h: H) { print(h(9)) }`: `let b: F = a1; print(a("x")); call(b)` with `mid(same, twice)`.
Today it is refused at check, `argument 1: expected string, got i32 (the call of `h` in `mid`)`;
it runs with `let b = a1`, with `call(a1)`, or with `a` called at `i32`.
