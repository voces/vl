### D17323 — a binding annotated with a type parameter bound to a generic function closes that type parameter at its first call, so a second call shape is refused at check

**loud emit reject · `the compiler cannot yet lower this statement (call of a non-declaration)` · clause 2 · `vl check` rc 0 · was loud check reject (`argument 1: expected i32, got string`), moved check → emit 2026-11-28 by COV-CLOS-3: the unread default no longer closes `F`, and the IR lowers the call through `closureCallRhs` rather than the tag dispatch · filed 2026-11-25 against master `1bede247` by lane N10 · found probing D17117**

Repro:

    function same<T>(k: T): T { return k }
    function other<T>(k: T): T { return k }
    function mid<F, G>(a: F, a1: G) {
      let b: F = a1
      print(b(3))
      print(b("y"))
    }
    mid(same, other)
    // vl check: rc 0.  vl run: emit error at 6:15, "cannot yet lower this statement (call of a non-declaration)"

Want:

    3
    y

#### Mechanism

The check half is closed. `a` is unread, so `pinUnreadGenFnArgs` pinned `same` at the `i32`
default and wrote that instance over `F`. `b`'s calls, which are `F`'s rows, were then judged at
`(i32) => i32`. The pin now instances the value only, so `F` keeps the open signature and each
call through `b` is asked at its own arguments (coordinator ruling, DECISIONS.md "A binding
annotated with a type parameter has that parameter's type at the instance").

What remains is the IR's. `{other}` is tagged and the template call has its dispatch arms, but the
instance clone of `b(3)` is noted through no set (`monoTagSetAt` reads `-1`, the elaboration's
walk type carries none), so `closureCallRhs` finds no key. With `a("x")` beside the calls it runs.

#### Ablation

| ingredient removed | outcome | needed? |
| --- | --- | --- |
| the annotation: `let b = a1` | runs, prints `3` / `y` | **yes** |
| the binding: `a1(3)` and `a1("y")` | runs | **yes** |
| the second call shape: `b(3)` twice | runs | **yes** |

#### Grading list

The hand-on spelling must run too. There, `F` is closed by `a("x")`, and `b` is handed to
`call<H>(h: H) { print(h(9)) }`: `let b: F = a1; print(a("x")); call(b)` with `mid(same, twice)`.
Today it is refused at check, `argument 1: expected string, got i32 (the call of `h` in `mid`)`;
it runs with `let b = a1`, with `call(a1)`, or with `a` called at `i32`.

The fix is [D17878](D17878.md)'s call-row split: the instance's per-call table keeps one type per
parameter, read both as the unread value's instance and as `F`'s binding.
