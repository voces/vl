### D15609 — a hole function called directly at one type and handed on inside a list literal to a callee that calls the element at another is refused by the checker

**loud check reject · clause 2 · `argument 1: expected i32, got string (the call of \`f\` at the call's argument types)` · the hand-on at both types inside the literal runs since [D15566](D15566.md), and the second hand-on bare (`call0(g, "s")`) runs · found closing D15566 · filed 2026-11-09 against master `d4901c70`**

Repro:

    function id(v) { return v }
    function call1(f, x) { print(f(x)) }
    function call0(fs, x) { call1(fs[0], x) }
    function run(g) {
      call1(g, 5)
      call0([g], "s")
    }
    run(id)

Want:

    5
    s

#### Mechanism

Not traced. The checker types `run`'s hole `g` from its direct use at `i32` and then checks the
listed hand-on's call against that one signature, where a hand-on bare is taken at each call's
own types.
