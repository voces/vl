### D3477 — a nested block as a function's last statement does not give the function its value

**loud check reject · clause 2 · open · `not all code paths return a value` on a legal program · found 2026-10-03 · filed against master `e5ff25ff9`**

Repro:

    function f(id: i32): i32 { { id } }
    print(f(3))
    // vl check: rc 1, `not all code paths return a value in 'f'`

Want:

    3

#### Mechanism

The return-completeness check reads a function body's last statement as a value only when it is
an expression, an `if`/`else` chain, a `match` or a labelled block; a plain nested block
statement is none of those, so the body looks as if it falls through. The owner ruling on
labelled blocks makes a block's tail its value, so the same braces in tail position owe the
function its value. Re-run on master `e5ff25ff9` with the refreshed seed: refused at `vl check`
and `vl run` alike, with the span on the whole outer body.

#### Ablation

| ingredient changed | outcome | needed? |
| --- | --- | --- |
| a statement before the tail inside the inner block (`{ print(1); id }`) | still refuses | no |
| two levels of nesting (`{ { id } }`) | still refuses | no |
| a statement before the nested block (`const x = 1; { id + x }`) | still refuses | no |
| a trailing `;` after the block (`{ id };`) | still refuses | no |
| the same block as a lambda body (`(id: i32): i32 => { { id } }`) | still refuses | no |
| the block inside an `if` branch (`if id > 0 { { id } } else { 0 }`) | runs, prints `3` | **yes**: the branch is read as a value, the function body is not |
| a labelled block (`@B { break @B id }`, and `@B { id }`) | runs, prints `3` | **yes**: the label is what makes it a value |
| `{ return id }` as the nested block | runs, prints `3` | no (control: the return is explicit) |
| `let x = { id }` (value position) | refuses `expected i32, got {id: i32}` | the braces read as an object literal here; a one-name block is ambiguous, a different row if anything |

#### Grading list

`{ { id } }` and the lambda spelling above; the `if`-branch spelling must keep printing `3`;
`function f(id: i32) { { id } }` (no annotation) must infer `i32` rather than `void`, which it
reads as today (`print expects a value, got void`).
