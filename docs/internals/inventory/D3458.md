### D3458 — a generic identity around an `if` join, delivered to a union holding the record, builds invalid wasm even fully annotated

**check-clean invalid wasm · clause 1 · open · pre-existing, the same on master `028dedb33` · found by the #3325 review (the annotated twins `f64__iddj__union__t`, `two__iddj__union__t`) · filed 2026-09-30 against master `028dedb33`**

Repro:

    type R = { v: f64 }
    function idd<T>(x: T): T { x }
    const q: R = { v: 7 }
    const d: R | string = idd(if true { q } else { { v: 2 } })
    if d is R { print(d.v / 2) }
    // vl check: rc 0.  vl run: invalid module in the top-level code

Want:

    3.5

#### Mechanism

Each ingredient alone runs; only the three together fail. The identity is instantiated at the
join's type, and the join's `else` literal is built for that instance, while the union
destination boxes what the identity returns. The ablation places the disagreement between
the join's member row inside the identity call and the union's box of `R`; it is not yet
confirmed by disassembly.

#### Ablation

| ingredient changed | outcome | needed? |
| --- | --- | --- |
| `idd(q)` (no join) | prints `3.5` | **yes** |
| `const d: R = idd(if …)` (no union) | prints `3.5` | **yes** |
| `const d: R \| string = if … { q } …` (no identity) | prints `3.5` | **yes** |
| a second field `s: string` on `R` | the same invalid wasm | no |
