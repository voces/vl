### D4052 — a WRITTEN `void` as a list element, map value or union member passes `vl check`, though the design rules `void` non-storable

**loud emit reject · clause 2 (the checker owes the refusal) · found writing `docs/spec/types.md` (lane SPEC) · related to D1993 · filed 2026-10-11 against master `1df3c8f91`**

Repro:

    function f(): void { }
    const xs: void[] = []
    xs.push(f())
    print(xs.length)
    // vl check: rc 0.  vl run: emitProgram: only i32[] arrays and struct/union element
    // arrays are supported

#### Mechanism

DECISIONS.md §"`void` is a real type in the lattice" (ruled 2026-08-18) point (d): `void`
stays non-storable, with no `void[]`, no `void | i32` and no void map value. The checker
enforces this for a record field (`field 'v' expects a value, got void`). It does not check
a `void` written inside a list type, a map's value type or a union annotation. Such
programs pass `vl check` and fail in the emitter, or, for the union, compile until the
binding is read. D1993 is the inferred face, where an `if` joins `void | T`. This row is
the written annotation.

#### Ablation

| spelling | check | outcome |
| --- | --- | --- |
| `const xs: void[] = []` + push | rc 0 | emit reject, message above |
| `function f(xs: void[]): i32 { xs.length }` (never called) | rc 0 | emit reject, same message |
| `const m = Map<string, void>()` | rc 0 | emit reject, `unsupported map value type …` |
| `let x: void \| i32 = 3` | rc 0 | runs; `print(x)` later is refused `print expects a value, got void \| i32` |
| `type R = { v: void }` with a value | rc 1 | `field 'v' expects a value, got void` |

#### Grading list

Each spelling in the ablation, plus `void` as a generic argument to a storing type
(`Box<void>` with `type Box<T> = { v: T }`), which must not be refused where it only
instantiates a return (point (c) of the same ruling).
