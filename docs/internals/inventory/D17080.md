### D17080 — a structural bound's member is satisfied by the overload set's first-imported candidate only, so the other instance types are refused

**closed 2026-11-23 · was a loud check reject (order-dependent; swapping the imports flips which call is refused) · filed 2026-11-23 against master `1d35bb97`**

#### Mechanism

`checkBoundsAtCall` asks `witnessOf` for each method member, and `witnessOf` resolved the
member's name with `ufcsAliasInScope`, the module scope's single rename row. For a name the
module binds to a receiver-overload set (O1) that row is one candidate, the first imported,
so only that candidate's `self` type could satisfy the bound. The member call `x.mn(y)` itself
resolves through `ovPickFor(row, recvTy)`, which picks by the receiver's head class. The fix
asks `ovPickFor` for the instance type when the call site's module binds the member to a set;
a type no candidate takes keeps the "no `mn(…)` in scope" refusal, and a type several take is
refused with the member call's own ambiguity message.

#### Grading list

`tests/cases/modules/overload-bound-satisfied-by-set{,-swapped}` (both import orders),
`overload-bound-satisfied-by-three` (three candidates), `err-overload-bound-no-candidate`
(no candidate: refused), `err-overload-bound-ambiguous` (two candidates take a wider record).
