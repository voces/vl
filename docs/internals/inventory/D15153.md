### D15153 — a map `.get` on a record-valued map field read through an un-annotated parameter is lowered as a plain call

**closed 2026-11-03 by lane column-G1 · runs, prints `7` · was loud emit reject, clause 2 · filed 2026-11-03 against master `a29da2f2d` by lane column-G1, found grading [D15098](D15098.md)'s position matrix**

Repro:

    type R = { r: i32 }
    type A = { g: Map<string, R> }
    function take(a) {
      const v = a.g.get("x")
      print(v?.r ?? 0)
    }
    const g: Map<string, R> = Map()
    g.set("x", { r: 7 })
    const x: A = { g: g }
    take(x)
    // vl check: rc 0.  vl run: emitProgram: callee is not a function name

Want:

    7

#### Fix

`monoPinMemberCall` (`compiler/emit_mono.vl`) rewrote `m.get(k)` into the read `m[k]` only for a
receiver that is a pinned parameter. A receiver the instance's elaboration types as a map
(`elabWalkTy`) now reads the same way, so the member chain, a local copy of the map and a local
copy of the parameter all run, as the `a.g["x"]` spelling already did. [D3414](D3414.md), filed
earlier, is the same mechanism through a binding and closed with it.

#### Mechanism

The call `a.g.get("x")` reaches `emitCallCore` (`compiler/wasmEmit.vl`) as a call of a member
rather than a map method, and falls to its last refusal. The map's `.get` is recognised when
the parameter is annotated, when the value is `i32`, and when it is spelled `a.g["x"]`, so the
ingredients are the un-annotated parameter and the record value. Not traced further.

#### Ablation

| ingredient changed | outcome | needed? |
| --- | --- | --- |
| `a: A` | runs | **yes** (the un-annotated parameter) |
| the value `i32` (`Map<string, i32>`) | runs | **yes** (the record value) |
| `a.g["x"]` instead of `.get("x")` | runs | **yes** (the `.get` spelling) |
| `a.g.has("x")` | runs | **yes** (`.get`) |
| the map bound first, `const m = a.g` then `m.get("x")` | still refused | no |
| the record an arm of a union, or held by a struct | still refused | no |
