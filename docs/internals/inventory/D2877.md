### D2877 — a union of lists delivered into the same union is refused as a container widening

**closed 2026-09-27 · was loud check reject, clause 2, on master `460a67010` · found by the D2874 grid · filed 2026-09-27 · fixture `tests/cases/unions/list-union-into-same-union.vl`**

Repro:

    function mk(b: boolean): f64[] | i32[] {
      if b { return [1.5] }
      [1, 2]
    }
    const u: f64[] | i32[] = mk(false)
    if u is i32[] { print(u[1]) }

Want:

    2

#### Mechanism

`listWidenWalk` asked the destination union first: for each destination member that accepts the
WHOLE source union it walked the source into that member. `f64[] | i32[]` is assignable to
`f64[]` (the numeric element widens), so the walk delivered the source's `i32[]` into `f64[]`,
refused the copy, and no other destination member accepted the whole source to clear it. A
union source into a union destination is now delivered member by member, each to a member that
accepts it, the order `objShapeAdapterless` already used. A genuine widening (`i32[] | string[]`
into `f64[] | string[]`) is still refused.

#### Ablation

| ingredient removed | outcome | needed? |
| --- | --- | --- |
| the numeric element pair (`string[] \| i32[]`) | runs | **yes** |
| the union source (`const u: f64[] \| i32[] = [1, 2]`) | runs | **yes** |
| the annotation (`const u = mk(false)`) | runs | **yes** |
| the element kind (`Sq[] \| Circ[]`, a record width pair) | still refused | no |

#### Grading list

A parameter, a return and a record field of the same union; `i32[] | string[]` into
`f64[] | string[]`, which must keep refusing.
