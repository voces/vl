### D16221 — a record of an un-annotated function returned by a call into a `const` annotated with a closed record type, handed to a parameter also handed a record of an annotated lambda of another result, builds an invalid module

**closed · runs, prints `4` · was check-clean invalid wasm, clause 1 · fixed 2026-11-14: a call inside a function built at two instances takes no one callee type from a literal's slot outside it · the record-holder sibling of [D16124](D16124.md) · filed 2026-11-14 against master `293074baf`**

Repro:

    function inc0(a) { return a + 1 }
    function take(a) { return a.f(3) }
    const other = take({ f: (x: i32): f64 => 1.5 })
    function mk() { return { f: inc0 } }
    const v: { f: (a: i32) => i32 } = mk()
    print(take(v))

Want:

    4

#### Mechanism

`elabLitSlotCallees` gives each call a literal's function slot reaches one callee type, keyed by
the call node. `mk`'s `{ f: inc0 }`, delivered through `v`, reaches `a.f(3)` in `take`, and the
call was given `(i32) => i32`. But `take` is built at two instances, and the other one
(`take(other)`) receives the lambda's record, whose closed slot is never recorded, so nothing
marked the conflict. `elabInstNodeTy` reads that per-node type ahead of the instance's own, and
the `f64` instance called through `(i32) => i32`. A call inside a function the elaboration builds at
two or more instances, reached by a literal that lies outside that function, now takes no one
callee type (`-2`), so each instance reads its own. A literal inside the instanced function is
copied into each instance and reaches that instance's call alone, so it keeps the type: a first cut
without that exemption broke D7202's and D15472's witnesses (named set
`d16221-callee-ty-per-instance`).
