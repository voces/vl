### D15753 — a function's returned value join of two maps of un-annotated functions, bound at an annotated map, is refused at emit

**closed · runs, prints `1.5` · was loud emit reject, clause 2 (a containment of clause-1 invalid wasm) · fixed 2026-11-14: an un-annotated map result whose tail is typed open takes the shape the tail is built at, and the return's storage check reads the signature's slot · filed 2026-11-12 against master `784c38bf`**

Repro:

    function inc0(a) { return a + 1 }
    function half(a) { return a / 2.0 }
    const fnMap = Map()
    fnMap.set("a", inc0)
    fnMap.set("b", half)
    const m2 = Map()
    m2.set("a", half)
    const k = [1].length > 0
    function deliver() {
      return if k { m2 } else { fnMap }
    }
    const v: { [string]: (a: f64) => f64 } = deliver()
    const g = v.get("a")
    if g != null { print(g(3)) }

Want:

    1.5

#### Mechanism

`deliver`'s recorded result and its tail's checked type are both a map whose value function still
holds a hole, which reads as the mono map. The join is built at the arms' shared closure map, so
`retStorageMismatch` refused the return. `inferredRetMapSlotCore` now reads an open-typed tail at
`mapShapeOfExpr` (the shape it is built at), `cloRetValSlot` already takes that slot for an open
recorded result (D16124), and `retStorageMismatch` compares a map against `cloRetValSlot`, the
slot the signature carries, rather than the return column.
