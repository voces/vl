### D4192 — a null-only list literal as a `??` default builds no list, annotated or not

**closed 2026-11-14 · runs, prints `1` · was a loud emit reject, clause 2, ``??` over a list whose default is a list of another storage builds no single list at this type argument` · closed by grading a literal default at the storage it is built at (`coalListDefaultClash`, `wasmEmit.vl`) · filed 2026-10-12 against master `040ff8a3d` · found by the review of [D1832](D1832.md)'s close; a sibling of [D4190](D4190.md)**

Repro:

    function g(): (i32 | null)[] | null { return null }
    const xs = g() ?? [null]
    print(xs.length)
    // vl check: rc 0.  vl run (before the close): emit error at 2:24.

Want:

    1

#### Mechanism

The checker already delivers the default to the `??`'s result, `(i32 | null)[]`, and stamps the
literal with it (`adoptLitAt`), so `emitArr` builds `[null]` at that storage. The emit guard
`coalListDefaultClash` read the literal's own `null[]` type instead of the stamp, so it refused a
default that would have built as one list. It now reads a literal's list rep at the type it is
built at (`tyListRep(arrLitTyAt(...))`); a bound default keeps its own rep, and a `null[]`
binding is still the design's check reject (D5520).
