### D17079 — `?.` over an `if` join of hole-typed parameters is refused at the template, which reads the union `_ | _ | T` as a non-object

**loud check reject · clause 2 · filed 2026-11-23 against master `1d35bb971`**

Repro:

    function g(a0, a1, k: i32) {
      const v = if k == 0 { a0 } else if k == 1 { a1 } else { { n: 7 } }
      print(v?.n)
    }
    const x0: { n: i32 } | null = null
    const x1: { n: i32 } = { n: 2 }
    g(x0, x1, 0)
    // vl run: member access '?.n' on non-object _ | _ | {n: i32}

Want:

    null

#### Mechanism

`checkOptMemberNode` has a bare-hole arm (`optMemberHoleTy`, an `HD_OFLD` read each pin re-asks)
and a concrete-union arm (`sharedUnionFieldTy`). A union holding a hole takes neither, so the
template refuses before any instance is asked. Adding the per-member arm to the checker is not
enough by itself. A prototype gave each hole member its own `HD_OFLD` and each record member its
field. The checker then accepted the program, but `vl run` trapped with `null reference`:
`optLeafArmOf` took the `nonNull` arm, so `?.` became a plain field read with no receiver test.
The close needs the instance's `?.` type to keep the `null` that one arm binds.

#### Ablation

| ingredient changed | outcome | needed? |
| --- | --- | --- |
| `print(a0?.n)` (no join) | runs | **yes** |
| `a0: { n: i32 } \| null, a1: { n: i32 }` annotated | runs | **yes** |
| neither argument null (`g` called with two records) | refuses | no |
| two arms `a0` / `a1` | refuses (`_ \| _`) | no |

#### Grading list

The prototype's spelling with `k` = 1 and with no null argument (both printed the right value),
and `const r = v?.n` then `print(r)` (trapped under the prototype).
