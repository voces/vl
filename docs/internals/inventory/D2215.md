### D2215 — an unused type alias changes how an un-annotated record literal's list field is laid out, so a store into it stops building

**loud emit reject · clause 2 · the same family as [D2208](D2208.md) (a declared alias's shape captures an anonymous literal) · filed 2026-09-23 against master `327b15510`**

Repro:

    type Circle = { r: i32 }
    type Sq = { s: i32 }
    type Shape = Circle | Sq
    type H = { xs: Shape[] }
    const cs: Circle[] = [{ r: 7 }]
    const o = { xs: [{ r: 1 }] }
    o.xs = cs
    o.xs[0] = { r: 99 }
    print(cs[0].r)
    // vl check rc 0; vl run: emit error, covariant list delivery (master: an invalid module).
    // Delete the unused `type H` line and it runs, printing 99.

#### Mechanism

Not yet ablated past the rows below. `o` is an un-annotated record literal, typed
`{xs: {r: i32}[]}`, and `H` is never used. With `H` declared, the literal's anonymous row is laid
out as `H`'s (a `Shape[]` field), so `o.xs = cs` becomes a `Circle[]` delivered into a `Shape[]`
slot, which takes the D791 copy the write to `o.xs[0]` then forbids. Without `H`, the row is its
own and the store is a plain share. A declaration nothing references should not change a
program's meaning; [D2208](D2208.md) is the literal-union twin, where a declared alias's member
set captured an un-annotated join.

#### Ablation

| spelling | outcome | needed? |
| --- | --- | --- |
| the witness | emit reject | — |
| without `type H` | runs, prints 99 | the alias: **yes** |
| `H = { xs: Circle[] }` | runs | the widening field: **yes** |
| without `o.xs[0] = …` | runs, through the copy | the write: only for the loudness |

#### Grading list

The witness must print 99 with `H` declared, as it does without it.
