### D4684 — an inferred return of `.map` over a callback PARAMETER returning a record has no element row

**loud emit reject · clause 2 · D2303's parameter-callback spelling, still refusing after D2303's fix (`rep-descriptor-campaign.md` §13.16) · filed 2026-10-14 against branch `rep-l2-stage5`**

Repro:

    type A = { v: i32 }
    type B = { w: i32 }
    function toB(a: A): B { return { w: a.v + 1 } }
    function go(f: (a: A) => B, xs: A[]) { return xs.map(f) }
    print(go(toB, [{ v: 4 }])[0].w)
    // vl check: rc 0.  vl run: emitProgram: ref valtype with no interned shape

Want:

    5

#### Mechanism

Not yet ablated past the table. The callback is a parameter, so neither a lambda's nor a named
function's record names the result row during return inference. Naming the row from the call's
arena element type (`B`) was tried and is not enough: the refusal holds, so no `B` ref-list row
is interned for this `.map` at all when nothing annotates the return.
