### D4684 — an inferred return of `.map` over a callback PARAMETER returning a record has no element row

**closed 2026-10-14 — the witness runs and prints `5` · was loud emit reject · clause 2 · `mfStructResultRowName` named the result row only from a lambda's or a named function's record, and a callback parameter is neither; it now reads the row from the parameter's closure signature (`mfCallbackCloKey`) · fixture `tests/cases/lists/map-record-result-callback-param.vl` · D2303's parameter-callback spelling (`rep-descriptor-campaign.md` §13.16) · filed 2026-10-14 against branch `rep-l2-stage5`**

Repro:

    type A = { v: i32 }
    type B = { w: i32 }
    function toB(a: A): B { return { w: a.v + 1 } }
    function go(f: (a: A) => B, xs: A[]) { return xs.map(f) }
    print(go(toB, [{ v: 4 }])[0].w)
    // vl check: rc 0.  vl run: emitProgram: ref valtype with no interned shape

Want:

    5

#### Mechanism

`mfStructResultRowName` answered "" whenever `mfCallbackFe` found no function entry for the
callback, which is every callback held in a parameter or closure value. The row was there all
along (the filed claim that no `B` row is interned was wrong): the parameter's closure
signature key names it, as its result slot.

| ingredient removed | outcome | needed? |
| --- | --- | --- |

| the parameter as the callback (`(a) => f(a)` instead of `f`) | runs, prints 5 | **yes** |
| the record result (`f: (a: A) => i32`) | runs | **yes** |
| an annotated `: B[]` return | runs | **yes** |
