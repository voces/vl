### D14381 — a list literal whose elements the record solve builds at a wider record still needs `arrLitBuild`'s keep of the caller's build pair

**runs today and must keep running · refutation pin filed 2026-10-26 against master `641c18ca1` with #4902 applied · witness `tests/cases/soundness/covariant-record-field-read-only-runs.vl`; the Repro below is its minimal form**

Repro:

    function sum(ps: { x: i32 | string }[]) {
      for e in ps {
        if e.x is i32 { print(e.x) }
      }
    }
    const xs = [{ x: 6 }, { x: 7 }]
    sum(xs)
    print(xs[0].x + xs[1].x)

Want:

    6
    7
    13

#### Mechanism

#4901 deleted the emitter's thread-keep. #4902 puts back one rung of it in `arrLitBuild`
(wasmEmit.vl): when `recBuildRowOf` builds the literal's first element at another record,
the function returns null, and the literal keeps the build pair of its caller.

Here is what happens without that rung. The record solve builds each element at the
parameter's element row `{ x: i32 | string }`, which is `recBuildElemTyOf`. The binding is laid
out as a list of that row. But `xs` is also read at its own type, so the literal's checker
type (`litRepTyAt`) stays `{ x: i32 }[]`. `listBuildOfTy` then names the own-row list, and the
array is check-clean invalid wasm: `array.new_fixed` expects `(ref null {x: i32})` but finds a
`struct.new` of the wider row.

The missing fact is a list-level build type for the literal. The checker records where each
element is built and does not record the list type those elements make. Once the solve
records the literal's own build type, as `recBuildTyOf` does for a record literal,
`arrLitBuild` can read it and the keep can go.

#### Ablation

The "without the keep" rows are graded on a seed built from #4902 with the rung removed.

| ingredient removed | outcome without the keep | needed? |
| --- | --- | --- |
| the keep itself | check-clean invalid wasm, both witnesses | **yes** |
| `sum(xs)`, the wider delivery | runs | **yes** |
| the own-type read `print(xs[0].x + xs[1].x)` | runs | **yes** |
| the second element (`[{ x: 6 }]`) | runs | **yes** |
