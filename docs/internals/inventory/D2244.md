### D2244 — an explicit generic `T[] | null` parameter, narrowed, reads its element at the i32 rep

**closed 2026-09-23 — the witness runs and prints `7` · was check-clean invalid wasm (`print(a[0])` dispatched to `__print_i32__` over the `i64` backing), clause 1, for every element but `i32` · fixed with D2238 by the same rung: a narrowed read whose recorded type is a type-parameter list takes the list kind of the instance's own binding · found by the #3081 review · filed against master `f2234c2e5` · fixture `tests/cases/lists/narrowed-nullable-list-hole-param.vl` (`genFirst`)**

Repro:

    function take<T>(a: T[] | null) { if a != null { print(a[0]) } }
    const p: i64[] | null = [(7 as i64)]
    take(p)
    // vl check: rc 0.
    // vl run (as filed): Error: invalid module … inside `take`. Now prints 7.

#### Mechanism

D2238's mechanism with a declared type parameter in place of a hole. Every instance shares the
narrowed `a` node, whose recorded type is `T[]`, and no scalar-list classifier reads a list kind
off a type variable, so the element fell to `i32`. The instance's own parameter annotation is
the substituted `i64[] | null`, the nullable scalar-list niche, and
`narrowedHoleNulScalarListKind` now accepts a non-null `TyArray` carrying a type variable as a
narrowed read of it, exactly as it accepts the `hole minus null` of D2238.

Use grid, `take<T>(a: T[] | null)` with an `i64`, `f64`, `f32`, `string` or `i32` element ×
print, `+`, interpolation, binding, `.length`, return (`: T | null`), call argument (through an
`f: (T) => void`): 9 of 34 RUNS before, 33 of 34 after. The one left interpolates a `string`
element, [D2241](D2241.md). Two instances in one module (`i64` with `f64`, `f64` with
`string`) were invalid wasm and print both values now.
