### D4977 — an instance called with a `[]` literal folds an `is K[]` over an empty disjoint list to false

**closed 2026-10-15 — now prints `10` then `0` · was check-clean silently wrong, clause 1 · pin: `tests/cases/generics/is-list-in-literal-pinned-instance-tests-emptiness.vl` · pre-existing on master `e2efbc0af` · found on lane D4911 A/B-ing the unbound-parameter default for #3868 · the D4551 default is observable here: an `f64` default build prints `10` then `0` · related to D4771, D4911, D4551 · filed 2026-10-15**

Repro:

    function s<T, U>(a: T[]) {
      const q: U[] = []
      if q is f64[] { print(q.length + 10) }
      print(a.length)
    }
    s([])
    // PRINTS 0

Want:

    10
    0

#### Mechanism

An instance bound by a `[]` argument is not an exact instance, so `exactOperandTyOf` answered -1 and `emitListEmptyFitIs` fell back to the static fold; the receiver type is now read through `instanceTyOf`, which also reads the instance's pin and hole bindings. `q` is empty, so by D4771 `q is f64[]` holds whatever `U` is. Under the `i32`
default the instance should test `q`'s emptiness (D4910), and does when the call is `s([1])`
or `s(e)` with `e: string[]`. Called with the literal `[]` the arm is skipped, so the answer
depends on the default: an `f64` default folds the test true.

#### Ablation

| change | outcome | needed? |
| --- | --- | --- |
| `s([1])` for `s([])` | prints `10`, `1` | **yes** |
| `const e: string[] = []` and `s(e)` | prints `10`, `0` | **yes** |
| drop `T` and `a` (`s<U>()`, `s()`) | prints `10`, `0` | **yes** |
| test `a is f64[]` on the `[]` argument itself (`s<T>(a: T[])`) | prints `0`, want `10` then `0` | no, it misses too |

#### Grading list

- `function s<T>(a: T[]) { if a is f64[] { print(10) } print(a.length) }` with `s([])`: want `10`, `0`.
- Re-run with `MONO_UNBOUND_TY_PARAM_DEFAULT = "f64"`: the outputs must not change.
