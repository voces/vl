### D1775 — a `type` ALIAS whose body is a negation type reps as a union BOX while its value stays a bare scalar, so `const x: N = 5` is check-clean invalid wasm; the inline spelling `const x: !string = 5` runs

**closed 2026-09-06 — the witness prints `5` · was check-clean invalid wasm,
`type mismatch: expected (ref $type), found i32` · found 2026-09-06 by the ROADMAP re-grade
while grading A4 (negation types) · clause 1 · residue [D1773](D1773.md) · fixture
`tests/cases/unions/negation-alias-transparent.vl`**

Repro:

    type N = !string
    const x: N = 5
    print(x)
    // vl check: rc 0.  vl run: prints 5.
    //           type mismatch: expected (ref $type), found i32 (at offset 0x94)

#### Mechanism

`wasm-dis` on the emitted module names it in one line:

    (global $global$0 (mut (ref $1)) (i32.const 5))

with `$1` the union box `(struct (field i32) (field anyref))`. The global's declared type is
the BOX and its initialiser is a bare `i32.const 5`, so the two disagree at the only place
the value lives. The checker is right to accept the program — `5` is not a `string`, so it
satisfies `!string` — and the rep classifier is what disagrees with it: reading the ALIAS's
body it answers "union" (a negation carries member structure) where the value is a scalar.
Named-vs-inline is the discriminator, which is the "two spellings, print the rep" shape: the
declared alias is what routes the annotation through the union rep, and the inline spelling
never reaches it.

#### Mechanism

`wasm-dis` on the failing face reads

    (type $1 (struct (field i32) (field anyref)))
    (global $global$0 (mut (ref $1)) (i32.const 5))

— the union box holding a bare `i32.const 5`. An instrumented build printed the arm that chose
it: `PROBE globalunion ann=[N] annIsUnion=Y tyIsNeg=n`. So `N` is in the union REGISTRY, and
`globalCellKind`'s `letIsUnion` arm gives it the box.

It is in the registry because it is not transparent. `collectU` skips a one-member alias that
denotes its member — that is what keeps `type Id = i32` from minting a union row — and
`isTransparentAlias` asks `singleAliasMemberTyIx`, a ladder over the MEMBER's arena kind with
arms for `TyPrim`, `TyFunc`, `TyArray`, `TyMap`, `TyObj`, a union alias and a nullable. It had
**no `TyNeg` arm**, so a negation member fell past every one, the alias registered, and the
cell became a box a scalar initializer cannot fill. A negation is a checker-only refinement
with no rep of its own — `emit_classify`'s element ladder says exactly that — so the arm
returns the member and the value keeps the rep its own type gives it.

The ladder's bare `-1` is now a named default (`aliasMemberNotTransparent`), which is what the
`kind-ladder-incomplete` rule asks of a ladder gaining an arm.
