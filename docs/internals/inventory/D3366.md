### D3366 — a `??` arm in an `else if` chain with a member literal builds invalid wasm at a literal-union pin

**closed 2026-10-26 · runs, prints `c` then `a` · fixed when `monoArgTyName` began reading an argument's pin from its closed type before its binding and rep rungs; the mechanism is not traced past that · was a loud emit reject, clause 2 (`unsupported argument type for x in a call to show`), and before 2026-10-20 check-clean invalid wasm · filed 2026-09-30 · pin: `tests/cases/generics/coalesce-arm-in-else-if-chain-at-literal-union-pin.vl`, with the two-arm `if` beside it**

Repro:

    type K = "a" | "b" | "c"
    function show<T>(x: T) { print(x) }
    function g(a, b, c: boolean) {
      show(if c { a ?? 5 } else if !c { b } else { "c" })
    }
    const u: K = "c"
    const w: K = "a"
    g(u, w, true)
    g(u, w, false)
    // vl check: rc 0.  vl run: invalid module inside `g`

Want:

    c
    a

#### Mechanism

Not localised past the ablation. The chain joins the `a ?? 5` arm (`K | i32` at the pin, a box)
with `b` and the member literal `"c"`, and the instance builds one arm as a string ref where the
join reads an `i32`. D3303's hole typing is not the cause: the `<T>` spelling is invalid the
same way.

#### Ablation

| ingredient changed | outcome | needed? |
| --- | --- | --- |
| `function g<T>(a: T, b: T, …)` | the same invalid wasm | no |
| `a` in place of `a ?? 5` | runs (D3303's elif cells) | **yes** (the `??`) |

#### Grading list

The D3303 generator's `g0308` (`<T>`) and `g0392` (hole).
