### D8280 — a `null` handed to an un-annotated or generic parameter through a binding or a nested generic call is pinned `i32` at the call

**check-clean invalid wasm · clause 1 · found closing [D8182](D8182.md) · the same on master `82bf510a3` · filed 2026-10-20 against master `82bf510a3`**

Repro:

    function t(v) {
      print(v)
    }
    const n = null
    t(n)
    // vl check: rc 0.  vl run: invalid module in the top-level code, expected i32, found nullref

Want:

    null

#### Mechanism

Not traced. The validator says the call site pushes a `nullref` where the instance's
parameter is an `i32`. The instance is built at `i32`, the rep a bare `null` shares a pin with.
A literal `null` argument builds the instance at `null` and runs. A binding typed `null`, or a
generic parameter handed on, does not, so the pin at the call (emit_mono.vl) seems to read the
argument's spelling rather than its type.

#### Ablation

| ingredient changed | outcome | needed? |
| --- | --- | --- |
| `t(null)` directly | runs | **yes**, the binding |
| `let n = null` | invalid wasm | no |
| `const n: i32 \| null = null` | runs | **yes**, the `null`-typed binding |
| `if v is i32 { … } else { … }` in place of `print(v)` | invalid wasm | no |
| `function t<T>(v: T)` with the `is i32` body | loud emit reject, `is` test but no union type declared | no, a second refusal |
| `function u<T>(v: T): boolean { v is i32 }` called as `u(v)` from `t<T>(v: T)`, `t(null)` | invalid wasm inside `t` | no, the nested generic spelling |
| `t(null)` inside a function `w()` | runs | **yes** |

#### Grading list

The nested generic spelling in the ablation, and the generic `is` spelling's emit reject.
