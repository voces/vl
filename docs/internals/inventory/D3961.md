### D3961 — a `let` seeded with a generic function and written with another generic traps when called

**closed 2026-10-11 by lane SC (D3979), with D4156, D4157 and D4158 · runs · pins: `tests/cases/functions/let-of-generic-written-generic-called-runs.vl`, `tests/cases/functions/let-of-generic-written-lambda-called-runs.vl`, `tests/cases/closures/let-of-generic-written-with-generic-called.vl` · was loads then traps · found by the D3960 matrix (`gen_generic_*`, 24 cells) · filed 2026-10-10 against master `eb81bdd89`**

Repro:

    function inner<U>(u: U) { print("I"); print(u) }
    function other<V>(v: V) { print("O"); print(v) }
    function main() {

#### Mechanism

`monoWalk`'s Call arm resolves a call through an un-annotated written `let` to its seed
(`identClosureFeAt`), instances the seed at the call and keeps the `call_ref`. The generics
WRITTEN to the `let` were never instanced at that signature, so the write stored the generic's
default stub, `(structref)` with an empty body, and the call trapped on it. Deliveries such as
`ci(k, 1)` already re-instanced the writes (`monoCoerceWrittenLet`, D3930); the close does the
same after a call instances a written binding's seed, at module scope and in a function alike.
