### D8943 — an un-annotated function handed to a generic `(T) => R` parameter has no monomorphization pin for `R`

**loud emit reject · clause 2, present on master `30ff8d9b5` · filed 2026-10-21 against master `30ff8d9b5`**

Repro:

    function inc(a) { return a + 1 }
    function apply<T, R>(h: (T) => R, x: T): R { return h(x) }
    const r = apply(inc, 3)
    print(r)
    // vl run: emitProgram: monomorphize: unsupported argument type for `h` in a call to `apply`

#### Mechanism

Not traced; the refusal is in the monomorphizer (`emit_mono.vl`), outside lane L1. The
checker accepts the call. The same `apply` with one type parameter, `(T) => T`, runs and
prints `4`, so the defect is `R` being bound only through the handed function's result.

#### Ablation

| ingredient removed | outcome | needed? |
| --- | --- | --- |
| `R` (`h: (T) => T`, returning `T`) | runs, `4` | **yes** |
| `a: i32` on `inc` | runs, `4` | **yes** |
| a widening body (`a / 2.0` for `a + 1`) | same emit refusal | no |

#### Grading list

`const r: i32 = apply(half, 3)` with `half(a) { return a / 2.0 }`: the same emit refusal,
which the checker owes as `f64 doesn't fit in i32` once `R` binds to `f64`.
