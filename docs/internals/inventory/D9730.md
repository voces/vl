### D9730 — a list of inline records of an un-annotated function handed to an un-annotated parameter also handed another record list traps calling the field

**closed · runs, prints `4` `4` · was trap after load, `vl check` rc 0, `indirect call type mismatch`, clause 1 · found closing [D9640](D9640.md) · present on master `e8163edd5` · filed 2026-10-22 against master `e8163edd5` · closed with [D9644](D9644.md): the list's element is left open and pinned at the field call (`monoRecListFieldCalledAtHole`, `monoOpenFnRecSrcPin`, emit_mono.vl) · fixture `closures/hole-fn-inline-record-list-beside-other-record.vl`**

Repro:

    function inc5(a: i32): i32 { return a + 1 }
    function inc6(a) { return a + 1 }
    function take(a) { print(a.f(3)) }
    const e5 = { f: inc5 }
    const xs5 = [e5]
    take(xs5[0])
    const xs6 = [{ f: inc6 }]
    take(xs6[0])
    // vl check rc 0.  vl run: prints 4, then wasm trap: indirect call type mismatch in take$1

#### Mechanism

The flow table sees no call through the slot of `xs6`, so the list was typed at the uncalled
default `(i32) => i32` ([D9100](D9100.md)) and `inc6` stored as the stub an uncalled function
gets, whose type is not `(i32) => i32`. With a second record reaching `take`, `a.f(3)` is not
rewritten to a direct call and the indirect call reaches the stub.

#### Ablation

| ingredient removed | outcome | needed? |
| --- | --- | --- |
| the first call (`take(xs5[0])`) | runs, `4` | **yes** |
| the hole in `inc6` (`inc6(a: i32): i32`) | runs, `4` `4` | **yes** |

#### Grading list

Both records written inline in their lists; the first record of an un-annotated function bound
to a `const` and listed.
