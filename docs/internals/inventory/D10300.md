### D10300 — a `let` list of a generic, pushed the same generic, has no signature at a call through an element

**closed · runs, prints `7`, `w` · was loud emit reject, `vl check` rc 0, `a function value's signature is not known at this call — the type it was given takes fewer parameters than the call passes`, clause 2 · CAPABILITY: the same program with `const ws` prints `7`, `w` · found closing [D10190](D10190.md) · present on master `d5ec7f160` and `e811cd6da` · filed 2026-10-22 against master `d5ec7f160` · closed: the list a literal initializes is owned by an un-annotated `let` that is never assigned whole, as by a `const` (`monoFlowListOwner`, emit_mono.vl), so the push of the same generic is one the flow plan's reads already count · fixture `closures/let-list-of-generic-pushed-same-called-at-two-types.vl` · new matrix `fn-value-generic-let-list-pushed-same-at-two-types-open` 0 → 14 of 46 · residue: [D10342](D10342.md) (a call through the pushed element that is not the first thing its statement runs, `let` and `const` alike)**

Repro:

    function id<T>(x: T): T { x }
    let ws = [id]
    ws.push(id)
    print(ws[1](7))
    print(ws[1]("w"))
    // vl check rc 0.  vl run: emit error: emitProgram: a function value's signature is not known at this call — the type it was given takes fewer parameters than the call passes

Want:

    7
    w

#### Mechanism

`monoFlowListOwner` (emit_mono.vl) owned a list literal only through an un-annotated `const`,
so for a `let` the D9441 push arm of `monoFlowUsePlanAt` declined the push and the flow plan
dropped the binding: the element read reached the call with no instance at all. A `let` never
assigned whole holds the one literal for its whole life, as a `const` does.

#### Ablation

| ingredient removed | outcome | needed? |
| --- | --- | --- |
| `const ws` instead of `let ws` | runs | **yes** |
| `ws.push(id)` | runs | **yes** |
| `ws[0]` instead of `ws[1]` at both calls | same refusal | no |
