### D9595 — a list a generic is pushed into, spread into a list then written with a non-generic, refuses the source list called at two types

**loud emit reject · `vl check` rc 0 · `a list holding a generic function is called through its elements at more than one type` · clause 2 · found closing [D9482](D9482.md) · present on master `49a7d0b10` · filed 2026-10-22 against master `49a7d0b10`**

Repro:

    function id<T>(x: T): T { x }
    function inc(x: i32): i32 { x + 1 }
    const xs = []
    xs.push(id)
    const ys = [...xs]
    ys[0] = inc
    print(ys[0](2))
    print(xs[0](2))
    print(xs[0]("s"))
    // vl check rc 0.  vl run: emit error: emitProgram: a list holding a generic function is called through its elements at more than one type, so its elements have no one instance — annotate the list's element type

Want:

    3
    2
    s

#### Mechanism

A spread of a pushed list ties the two lists' roots (`mfrTied`, emit_mono.vl, D9482), so the
write of `inc` into `ys` declines `xs`'s read plan too, and `xs`, called at two types, reaches
`monoPinListElems` with two pins. The tie is what keeps a written host sound; separating the
lists would need the host typed at the written value while the source stays open.

Still refuses after the close of [D9791](D9791.md) and [D9853](D9853.md) (2026-10-22): those
follow a binding that only ever holds one generic, and `ys` holds `inc` too, so no flow source
names one generic here. What it needs is a converting copy at the spread, not a wider source.
