### D17283 — an unbounded generic reading a literal-set field its layout family stores as a string, at the literal set, emits an i32 where the string is

**closed 2026-11-25 by SOUND · runs, prints `circle` `2` · was check-clean invalid wasm, clause 1, inside `kindOf` · `strLitTakesAtom` (wasmEmit.vl), which gates `emitExpr`'s string-to-atom hook, answered false for a node with no recorded contextual type, and a generic body records none, so the `T = A` instance's read of the family's string field was returned raw where the result holds the atom; in a generic instance it now takes the delivery's type at the instance (`ctxTyAt`), as the non-generic read does · pinned by `tests/cases/generics/generic-read-of-family-string-literal-field.vl` · found by IR-V3 verifying #9970, filed by lane IR-N8 · filed 2026-11-24 against master `8695362aa`**

Repro:

    type K = "circle" | "round"
    type A = { kind: K, r: i32 }
    type B = { kind: string, r: i32 }
    function mk(n: i32): A | B {
      if n == 0 { return { kind: "round", r: 1 } }
      return { kind: "zz", r: 2 }
    }
    function kindOf<T>(x: T): K { return x.kind }
    const a: A = { kind: "circle", r: 1 }
    print(kindOf(a))
    print(mk(1).r)
    // vl run: circle 2  (was: invalid module inside `kindOf`, expected i32, found the string)

Want:

    circle
    2

#### Mechanism

`B` beside `A` in `A | B` makes the layout family store `A.kind` as the string
(D14752). The `T = A` instance reads that string off `x` and returns it where its result, the
literal set, is held as the atom's `i32`. The ablation fixes the ingredients.

| ingredient removed | outcome | needed? |
| --- | --- | --- |

| the result at `string`: `kindOf<T>(x: T): string` | runs | **yes** |
| the result annotation: `kindOf<T>(x: T)`, inferred | still invalid | no |
