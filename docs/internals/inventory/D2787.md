### D2787 — a join of two type-parameter values read inside the generic body is built at one pin's scalar

**check-clean invalid wasm · identical on master `781f68091` and `f6db92e0d` · filed 2026-09-27 from the #3209 review**

Repro:

    function f<A, B>(a: A, b: B, k: boolean) {
      const r = if k { a } else { b }
      print(r)
    }
    f(1, "b", false)
    f(1, "b", true)
    // vl check: rc 0.  vl run: invalid module inside `f`, expected i32, found (ref $type)

#### Mechanism

Not localised. Since D2760 the join types `A | B`, which the pin substitutes to `i32 | string`,
a value box. At a numeric pair it re-joins at the pin (`i32` and `f64` give `f64`) and runs.
At a non-numeric pair the instance still lowers the value `if` at the scalar blocktype of one
arm and stores the string into it. No spelling of this shape ran on either earlier master:
the returned-binding spelling (`const r = …; r`, printed by the caller) was invalid wasm on
both, and is a loud emit reject (`narrowed union atom has no value box`) since D2760.

#### Ablation

| ingredient removed | outcome | needed? |
| --- | --- | --- |
| the read in the body (`r` returned from its binding, printed by the caller) | invalid wasm on master, a loud emit reject with D2760 | no |
| the binding (`if k { a } else { b }` as the tail, printed by the caller) | runs | **yes** |
| the non-numeric pair (`f(1, 2.5, …)`) | runs | **yes** |
| the second type parameter (`f<T>(a: T, b: T, …)`) | runs | **yes** |

#### Grading list

The same body with `if r is string` in place of `print(r)`, and the annotated return
`function f<A, B>(a: A, b: B, k: boolean): A | B { const r = if k { a } else { b }; r }`,
which is still invalid wasm.
