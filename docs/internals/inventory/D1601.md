### D1601 — `vl check` graded imported std under the COMPILER's comment rubric and reported the findings against the consumer's file

**closed (fixed) — the four comment codes skip a std module, and a non-error located in a `std:` module is withheld from `vl check` unless `--include-std` is passed (a count is always announced; std ERRORS are never withheld) · glean's `tools/*.vl` + `src/*.vl` went from 1,461 warnings, 1,094 of them inside std, to 367, every one in glean's own files · reported by the glean session, VL-014, `~/glean/docs/vl-issues.md` · filed 2026-09-04 against master `0f922630`**

Repro (the FLOOR — a two-line consumer of std that must check CLEAN; the defect's own
witness is the transcript below, and the graded pins are `tests/vl_check_std_diag_test.ts`
and `tests/vl_comment_budget_test.ts`):

    import { toString } from "std:fmt"
    print(toString(42))
    // vl check: rc 0, "Checked 1 file, no errors." — and no diagnostic located in std

#### Mechanism

Two independent mechanisms produced the same symptom, and only fixing both empties the
report.

**The compiler's comment rubric was applied to std.** `comment-block-too-long`,
`comment-shouting`, `comment-history` and `comment-measurement-uncited` implement
`docs/internals/comment-style.md`, which is explicitly the rubric for `compiler/*.vl`. std
has its own consumer-facing rubric — `std-comment-audience`, `std-api-review.md` §4 — and
`compiler/lint.vl` already scoped THAT rule TO std by the module path the driver sets.
Nothing scoped the four the other way, so every std module was graded twice, under a rubric
whose own advice ("put the number in an inventory row") is meaningless to a consumer.
`commentBudget` now consumes the same `scaPath` and returns early on `scaIsStd`.

**And a check reported diagnostics the target's author cannot act on.** A `vl check` target
resolves its whole module graph and the lint tier runs per module, so every
`import … from "std:…"` put std's source in the report — attributed correctly to `std:fmt`,
and useless. `cliDiagStdHidden` withholds a non-error whose owning module key starts with
`std:`; it counts nowhere while withheld (tally, `--severity` gate and `--json` array all
skip it), `--include-std` restores it, and a withheld run says so on stderr in both human
and `--json` mode. `std:` is the spelling an IMPORT resolves to, so `vl check std/fmt.vl` —
std's own author, and `scripts/lint-self.sh`'s `std/` run — is unaffected.

Before, on master `0f922630`:

    $ vl check imp.vl
    [WARNING]: a comment line shouts — two or more words in capitals in a row … at std:str:39:1
    [WARNING]: comment block of 5 lines exceeds the 4-line budget … at std:fmt:156:1
    [WARNING]: a comment line shouts … at std:str:229:1
    [WARNING]: a comment line shouts … at std:str:246:1
    [WARNING]: a comment line narrates history ("no longer") … at std:fmt:454:3
    [WARNING]: a comment line shouts … at std:fmt:582:1
    Found 0 errors, 6 warnings.

After:

    $ vl check imp.vl
    Checked 1 file, no errors.

#### Ablation

| ingredient removed | outcome | needed? |
| --- | --- | --- |
| the four codes' std scope (mechanism 1 only) | 6 → 0 on the witness; 1,461 → 367 across glean | **yes** — all 1,094 std warnings were rules 2/3/5 |
| the `std:` diagnostic filter (mechanism 2 only) | 0 on the witness; any OTHER std finding still reaches the consumer | **yes** — an unused binding in std still gated a consumer's build at `--severity info` |
| the target's own import of std | nothing was ever reported | **yes** — the graph walk is what puts std in the report |
| `--include-std` | the std findings come back, gate included | no — it is the escape hatch, not the mechanism |

#### Grading list

* `vl check std/fmt.vl` and `scripts/lint-self.sh`'s `std/` run must still gate on
  `std-comment-audience` — the two rubrics are now disjoint, not both off.
* A std ERROR must stay visible with no flag: the toolchain being broken is not the
  consumer's warning to hide.
* `--json` must drop the same set the human renderer drops, and still announce the count
  on stderr, so the two exit codes cannot diverge.
* `scripts/comment-budget.py` walks `compiler/` only; a `std/` row in its baseline can
  never fall again, because the lint no longer produces the count.
* The LSP is NOT affected and needs no twin fix: `wasmChecker.lint` is single-file over the
  open document, so no std module is ever linted through it, and `wasmChecker.check` yields
  the error tier, which this row keeps visible. It also sets no module path, so a std file
  opened in the editor is graded by neither rubric — a separate, pre-existing gap.
