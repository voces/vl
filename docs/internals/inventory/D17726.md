#### Mechanism

The map's slot holds `lap`'s record of one closure per signature, `(f64) => f64` and
`(i32) => i32`. D17700's close builds `dbl` stored there as that record: its closure at its own
member, and at the other, where the coordinator's ruling (bundle-record unit, (e)) has it
unreachable by typing. The checker types `h` as the open `(_) => _` and accepts `h(3)`, which
takes the `(i32) => i32` member, and `dbl` is no `(i32) => i32`: its result is `f64`. So the
program the design permits (`dbl(3)`, an `i32` widened to `f64`, prints `6`) reaches a member that
is not its call. The holder call refuses at emit, so nothing traps. A close is either the checker
refusing a call at a signature some stored function lacks, or a member that adapts the stored
function (its argument widened, its result the call's own type) instead of an unreachable one.
