### D6390 — a `const` alias of a never-assigned `let` lambda, called with a generic whose hole it calls at two types, is refused at emit

**loud emit reject · `vl check` rc 0 · clause 2 · CAPABILITY: the same program through `const lap` runs, and so does the `let` called by its own name · the split plan follows an alias only to a `const` lambda (`fsFnAliasInit`, `fn_split.vl`) · found closing [D6351](D6351.md) · filed 2026-10-18 against master `c4326408f` on lane L3's `l3-d6351`**

Repro:

    function id(a) { return a }
    let lap = (g) => { print(g(1) + 1); return g("s") }

    // vl check: rc 0.  vl run: emitProgram: a generic function is passed to a function value whose parameter type names a type parameter this closure does not bind, so no instance of it can be chosen — call the function value from the generic function's own body, or pass a function of a concrete type

#### Mechanism

From the ablation only. The checker follows the alias to the lambda and judges it at both
instances ([D6351](D6351.md)), so the program is check-clean. The split plan follows an alias
only when its initializer is a `const` lambda, so `k` reaches mono with one signature.
