### D8202 — a generic identity over a function that returns an identity over a fresh call is built at the declared record of the call's fields

**check-clean invalid wasm · `vl check` rc 0 · clause 1 · open · present on master `be738c9f0` · the same program prints `15` once the unused `type Col` is deleted · found closing [D8020](D8020.md) · filed 2026-10-20 against master `be738c9f0`**

Repro:

    type Col = { r: i32, g: i32 }
    type J = { r: i32 | null, g: i32 }
    function idn<T>(v: T): T { v }
    function mk() { { r: 15, g: 1 } }
    function wrap() { idn(mk()) }
    const m: J = idn(wrap())
    print(m.r ?? 0)
    // vl check: rc 0.  vl run: invalid module, a `Col` found where a `J` is expected

Want:

    15

#### Mechanism

The checker accepts the delivery of `idn(wrap())` into `J`, and `mk`'s literal is still built
at `Col`, which spells its fields. `wrap`'s result is an identity call, not a literal, so neither
D8020's checker adoption (which follows one pass-through argument to a fresh call) nor its
emitter rung (`monoRebuiltLitRetName`, which needs every returned value to be an object literal)
reaches the two levels. The outer instance is taken at `J` while the value it is handed is a
`Col`.
