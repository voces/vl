### D14536 — an index read narrowed past `null` is non-null because the checker typed it so, not because the emit narrowing stack holds its place key

**runs today and must keep running · a Step 6 pin: the emit stack's second answer is deleted · filed 2026-10-27 against master `3dfab7325`**

Repro:

    const xs: (string | null)[] = ["ab", null]
    if xs[0] != null { print(xs[0].length) }
    const bs: (boolean | null)[] = [true, null]
    if bs[0] != null { print(bs[0]) }
    const ms: Map<string, string> = Map()
    ms["k"] = "abc"
    if ms["k"] != null { print(ms["k"].length) }

Want:

    2
    true
    3

#### Mechanism

`indexPlaceNonNull` (`emit_ty_canon.vl`) answered whether an index read `xs[0]` was narrowed
past `null` by rendering the place key and asking the emit narrowing stack
(`narrowVariantFor`). Its eight callers (the nullable string and ref-list reads, the nullable
boolean element and map value, the atom and string map reads) now ask the checker's read type
(`nodeTyProvesNonNull`), and the function is deleted. A build that failed loudly wherever
the two answers differed found no read the stack proved non-null and the checker did not, over
the 5,707 fixtures that mention `null`, `is` or a map; a build answering from the checker alone
printed identically to the stack's on all of them.
