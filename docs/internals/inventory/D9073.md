### D9073 — a generic whose result names a type parameter no parameter binds is accepted as a `.map` callback

**loud emit reject · `vl check` rc 0 · clause 2 · the direct call `cnst(3)` is refused by the checker, `cannot infer type parameter `U``, so the checker owes the same refusal here · found closing [D9004](D9004.md) · present on master `26a6dc669` · filed 2026-10-21 against master `26a6dc669`**

Repro:

    function cnst<T, U>(t: T): U[] { return [] }
    const ys = [3].map(cnst)
    print(ys.length)
    // vl run: emitProgram: ref valtype with no interned shape

#### Mechanism

Not traced. `memberCallMapFilterTy` (check_member_call.vl) binds the callback's parameter at
the element, which binds `T` and leaves `U` open, and nothing refuses a result still naming
the callback's own unbound parameter. A refusal there has to tell the callback's own type
parameters from an enclosing generic's, which a `.map(g)` over `g: (x: T) => R` inside a
generic legitimately leaves open.

#### Ablation

| ingredient removed | outcome | needed? |
| --- | --- | --- |
| `.map`, for the direct call `cnst(3)` | check refuses | **yes** |
| the inferred destination, for `const ys: string[][] = ...` | emit refuses, `unsupported .map/.filter element type` | no |
