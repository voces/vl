### D15907 — a hole lambda's bundle in an un-annotated slot, read through a `const`, read off a map, or both handed and called, is refused at emit

**closed 2026-11-12, runs and prints `5` `2.5` · was loud emit reject · clause 2 · `emitProgram: monomorphize: unsupported argument type for \`b\` in a call to \`take\`` · found closing [D15903](D15903.md) · filed 2026-11-12 against master `96590b46` · closed in the elaboration: a slot's `const` holder, or a map value's holder under a null test, may be handed whole to a parameter its callee takes the record at (`elabSlotHolderOk`, `elabSlotNulHolderOk`), and each slot hand records the argument as delivering the record (`elabArgRecs`), which mono pins the parameter from (emit_elab.vl) · fixture `tests/cases/closures/hole-lambda-bundle-slot-read-held-and-handed.vl` · still refused: a record literal's field both handed whole and called through, filed as [D15910](D15910.md)**

Repro:

    function lap(f) {
      f(2.5)
      f(3)
      return f
    }
    function take(b) {
      print(b(4))
      print(b(1.5))
    }
    const w = { f: lap((a) => a + 1) }
    const v = w.f
    take(v)

Want:

    5
    2.5

#### Mechanism

The slot note (`elabSlotRecordNote`) keeps the record whole for a read handed directly
(`take(w.f)`, D15903) or a `const` holder only called through (`elabSlotHolderOk`). Letting
that holder's hand through in the elaboration alone did not run: `take`'s parameter gets no
signatures through the holder, so mono still refuses.

#### Ablation

| spelling | outcome |
| --- | --- |
| `take(w.f)` | runs |
| `const v = w.f`, `v` called at both signatures | runs |
| `const v = w.f`, `take(v)` | refuses (mono) |
| `take(w.f)` and `w.f(9)` | refuses (internal binding type) |
| `m["k"] = lap(…)`, `const mv = m["k"]`, `take(mv)` under a null test | refuses (mono) |
