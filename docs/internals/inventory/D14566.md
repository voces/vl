### D14566 — a local holding a call that returns another call's fresh record is stored at the record's declared row

**closed · filed 2026-10-27 as check-clean invalid wasm against master `b9dd7ef88` (`type mismatch: expected (ref $1), found (ref $0); $1 is Col … $0 is J` inside `f`) · found building D14434's global-storage slice, whose type-built global slot showed the same miss · closed by reading a call's built record through every returned leaf: `letCallHeldTy` follows a leaf that is itself a call (`callBuiltTy`) and peels a generic identity whose sole argument pins `T` (`solePinPeel`), and `letNamedHeldTy` keeps a binding of such a call apart from its declared row (`letHoldsCallBuilt`), emit_classify.vl · fixture `soundness/record-fresh-call-through-wrapper-into-local.vl`**

Repro:

    type Col = { r: i32, g: i32 }
    type J = { r: i32 | null, g: i32 }
    function mkR() { { r: 20, g: 1 } }
    function dl() { return mkR() }
    function f() {
      const d = dl()
      const dj: J = d
      print(dj.r ?? 0)
    }
    f()

Want:

    20

#### Mechanism

The checker builds `mkR`'s literal at `J`, the record it is delivered into. The local `d`
took its storage type from `letCallHeldTy`, which read only the literal leaves of the called
function. `dl`'s only leaf is another call, so the local fell back to the call's type, whose
declared record is `Col`, and the `J` the call returned was stored into a `Col` cell.
