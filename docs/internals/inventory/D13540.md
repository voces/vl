### D13540 — an `if` of hole functions bound to a `const` inside a function with an un-annotated parameter, passed to a parameter called at two types, is refused at emit

**loud emit reject · `vl check` rc 0 · clause 2 · CAPABILITY: the same function with its parameter annotated, `function g(c: boolean)`, runs, and so does the choice passed directly, `both(if c { inner } else { ask })` · open · `monomorphize: unsupported argument type for `f` in a call to `both`` · found closing [D13461](D13461.md) · pre-existing on master `3b12820b5` · filed 2026-10-25 against master `3b12820b5`**

Repro:

    function both(f) {
      print(f("a"))
      return f(1)
    }
    function inner(s) { return s }
    function ask(s) { return s }
    function g(c) {
      const h = if c { inner } else { ask }
      both(h)
    }
    g(false)
    // vl check: rc 0.  vl run: emitProgram: monomorphize: unsupported argument type for `f` in a call to `both`

Want:

    a

#### Mechanism

Not ablated to a line. The un-annotated parameter is the ingredient, not the condition reading
it: a condition reading a module `let` instead still refuses while any parameter of `g` is
un-annotated. A prediction from the code path: `g`'s calls are then planned as a copy's calls,
and `fsPlanHoles` (fn_split.vl) declines a copy's call handing a name declared inside the copy
(D6706), which the bound `const` is.
