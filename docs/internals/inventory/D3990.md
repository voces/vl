### D3990 — `filled(n, null)` delivered to a `(T | null)[]` destination inferred `null[]`

**closed 2026-10-10 by lane CK · runs · was loud check reject · clause 2 · found by the diderven consumer (`DV-402`) · filed 2026-10-10 against master `e5128703a` · pins: `tests/cases/arrays/filled-null-typed-by-destination.vl`, `tests/cases/arrays/error-filled-null-into-non-null-element.vl`**

Repro:

    import { filled } from "std:array"
    type Item = { n: i32 }
    type Character = { equip: (Item | null)[], hp: i32 }
    function main() {
      const c: Character = { equip: filled(3, null), hp: 1 }
      c.equip[0] = { n: 5 }
      print(c.equip.length)
    }
    main()
    // vl check: a {equip: null[], hp: i32} cannot be delivered as Character here: the assignment on line 6 writes a widened field

Want:

    3

#### Mechanism

A call to a generic delivered to a typed destination binds a type parameter from that destination
when its arguments are literals the destination's binding holds (`dstTyParamAdapts`), but only
number literals qualified, so a `null` argument bound `T` to the null type and the call built a
`null[]`. A bare `null` argument now binds `T` from the destination whenever the substituted
parameter holds `null`. The emitter pins that argument at the declared record's nullable name
(`nulRecNominalName`), as a binding annotated with it is pinned.
