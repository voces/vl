### D16818 — a maker's lambda bound to a local `const` and returned is lifted at `i32`, whatever its parameter is pinned at

**open · check-clean invalid wasm · clause 1 (`vl check` rc 0, no diagnostic) · the local-binding spelling of [D16815](D16815.md) and [D16817](D16817.md) · filed 2026-11-16 against master `fae99e93f`**

Repro:

    function adder(n) {
      const f = (a) => a + n
      return f
    }
    const x = adder(1.5)
    print(x(2.0))
    // vl check: rc 0.  vl run: invalid module, top-level code: type mismatch: expected i32, found f64

Want:

    3.5

#### Mechanism

Not traced. One call pins `n` at `f64`, yet the call through `x` reads a closure built at `i32`.
In the plumbing classes the local `const f`, read in the maker's instance, finds no instance of its
lambda (`eplRebuildLeaf`: no member instance under the program root), so its slot stays open; a
lookup under the instance being read (`EPL.k`) instead turned a running neighbour invalid.

#### Ablation

| ingredient changed | outcome | needed? |
| --- | --- | --- |
| the call at `i32` (`adder(2)`, `x(3)`) | runs, `5` | **yes**: a pin other than the default |
| the lambda returned directly (`return (a) => a + n`) | runs, `3.5` | **yes**: the local binding |
| a parameterless lambda (`const f = () => n`) | runs | **yes**: the lambda's own parameter |
| a second, unused call `adder(2)` first | the same invalid module | no |
| a second binding at `i32`, called (`const v = adder(2)`, `v(3)` first) | loud emit reject, `parameter 1 of type _` | no: the outcome moves |
