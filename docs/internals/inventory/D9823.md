### D9823 — a function with a `null`-typed parameter is refused as a function value

**loud emit reject · `vl check` rc 0 · `emitProgram: a function value's signature is not yet supported — parameter `p` of type `null` has no representation in the function-value ABI; annotate and call it as a named function instead` · clause 2 · found closing [D9772](D9772.md) · present on master `260b24edd` · filed 2026-10-22 against master `260b24edd`**

Repro:

    function g(p: null): i32 { 5 }
    const gg = g
    print(gg(null))
    // vl check rc 0.  vl run: emit error: pnone.vl:2:7: emitProgram: a function value's signature is not yet supported — parameter `p` of type `null` has no representation in the function-value ABI; annotate and call it as a named function instead

#### Mechanism

The `nulnone` rep has no `$fnsig` token (`repSigTokOfKind`, emit_rep.vl), so the signature has
no function-value key. Running it needs a token for the null-only value, which as a
parameter can be any nullable reference the call site passes `ref.null` into.

#### Ablation

| ingredient removed | outcome | needed? |
| --- | --- | --- |
| the alias, `print(g(null))` | runs, `5` | **yes** |

#### Grading list

The alias above, and `g` handed to a parameter of type `(p: null) => i32`.
