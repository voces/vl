### D9790 — a copy of a copy of an un-annotated function parameter called at two types refuses

**closed · runs, prints `abc` `8` · was loud emit reject, `vl check` rc 0, `monomorphize: \`a\` is called at two instances of the function handed to it`, clause 2 · found closing [D9653](D9653.md) · filed 2026-10-22 against master `33eaa5294` · closed by a hole copy whose further copy is read at two keys taking one slot per key from it (`fsHoleCopyKeys`, fn_split.vl) · fixture `closures/hole-copy-chain-called-at-two-types.vl` · with [D9791](D9791.md), [D9792](D9792.md) and [D9853](D9853.md) closed**

Repro:

    function id<T>(x: T): T { x }
    function take(a) {
      const v = a
      const w = v
      print(w("abc"))
      print(w(7) + 1)
    }
    take(id)
    // vl check rc 0.  vl run: emit error: emitProgram: monomorphize: `a` is called at two instances of the function handed to it in a call to `take`

Want:

    abc
    8

#### Mechanism

A copy of a hole parameter that is read at two keys gets one slot per key, each written from
that key's parameter (D6530, `fsHoleCopyKeys` in fn_split.vl). A further copy (`const w = v`)
is accepted only when it is read at one key (`fsHoleCopyKey`, D6520). Here `w` is read at two
keys, so `v`'s keys come back bad and the split declines. Passing `w`'s keys up to `v` alone
was tried and did not run: the let plan writes a copy's per-key slots only from the
parameter's slots, not from another copy's (`fsLaneSet`, `fsPlanMember`).
