### D2897 — a hole function's nested lambda called at two parameter types in one instance builds invalid wasm

**check-clean invalid wasm · clause 1 · found by #3231's review (`a14.vl`) · the same on master `8e10ef58b` · filed 2026-09-27 against master `8e10ef58b`**

Repro:

    function mk(x, z) {
      const c = (y) => y
      print(c(x))
      print(c(z))
    }
    mk("s", "t")
    mk(2.5, 3.5)
    mk("a", 1.5)
    // vl check: rc 0.  vl run: invalid module inside `mk`

Want:

    s
    t
    2.5
    3.5
    a
    1.5

#### Mechanism

Not localised. The third instance calls one lambda at `string` and at `f64`. Alone it runs, so
the shared body copes with two call types in one instance; beside other instances it does not,
and a per-instance pin (the approach pulled from [D2854](D2854.md)) has no single type to take
here. The first two instances alone are D2854's shape.

#### Ablation

| ingredient changed | outcome | needed? |
| --- | --- | --- |
| drop `mk("a", 1.5)` | still invalid (D2854) | no |
| drop both other instances (`mk("a", 1.5)` alone) | runs | **yes** |
