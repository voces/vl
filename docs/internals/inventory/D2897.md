### D2897 — a hole function's nested lambda called at two parameter types in one instance builds invalid wasm

**closed 2026-09-27 — the filed repro prints its six lines · closed with [D2854](D2854.md): each instance owns its calls, and each call is its own lambda instance · found by #3231's review (`a14.vl`) · the same on master `8e10ef58b` · filed 2026-09-27 against master `8e10ef58b`**

Repro:

    function mk(x, z) {
      const c = (y) => y
      print(c(x))
      print(c(z))
    }
    mk("s", "t")
    mk(2.5, 3.5)
    mk("a", 1.5)
    // master: vl check rc 0.  vl run: invalid module inside `mk`

Want:

    s
    t
    2.5
    3.5
    a
    1.5

#### Mechanism

[D2854](D2854.md)'s: the lambda was already instantiated per call, so the third instance's two
calls reached two lambda instances; what failed was that the calls were one node shared by all
three instances of `mk`, renamed by whichever instantiated last. A single per-instance pin (the
approach pulled from D2854) had no one type to take here; per-call instances need none.
