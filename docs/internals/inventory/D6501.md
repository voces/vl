### D6501 — [CLOSED 2026-10-18] a generic named function bound to an annotated `const k: (x: T) => …` in a generic body instanced at two types is refused at emit

**closed 2026-10-18 by lane L1 · runs, prints `4 q` · was loud emit reject · the checker's function-value adapter (`fvaAdapt`) rewrote the shared delivery `id` in place while the body's `let` constraints were re-validated at one call's pin (`litPinAssignable`), so every instance read the `i32` adapter; a delivery re-validated at a pin is now left for the instances · the `const`, `let` and `void`-result spellings run · matrices unchanged · pins: `tests/cases/generics/generic-fn-value-at-body-type-param-two-instances.vl` · clause 2 · CAPABILITY at filing: the un-annotated alias `const k = id`, the direct `id(a)` and an annotated lambda all run at both instances (lane L1) · found closing [D6483](D6483.md) · filed 2026-10-18 against master `4d1802f96`**

Repro:

    function id<T>(x: T): T { return x }
    function f<T>(a: T): T { const k: (x: T) => T = id; return k(a) }
    print(f(4))
    print(f("q"))
    // vl check: rc 0.  vl run: emitProgram: a lambda-lifted local function was taken as a value

Want:

    4
    q

#### Mechanism

From the ablation only. The annotation makes `k` a function-typed binding of the body's
`T`; at two instances of `f` the binding needs one function value per instance and the
emitter reaches the lifted-function floor instead of building it.
