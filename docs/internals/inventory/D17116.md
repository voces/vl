### D17116 — a `K | null` place compared to a value-union call that writes it is read after the call

**closed 2026-11-24 by S2 · runs, prints `false` · was check-clean silently wrong, clause 1, legacy (the claimless build answers the same) · a union compare whose operand is left of a box with effects reads the operand once, before the box, on the null legs (`nulOperandStaged`) and on the plain arm (`unionEqStagedPlanOf`'s `unionEqSideMoves`), in legacy and the IR alike · owner S2 · found by V7 verifying #9854 · filed 2026-11-24 against master `1784a86d`**

Repro:

    type K = "a" | "b"
    type U = i32 | K | null
    let gk: K | null = null
    function setG(k: K | null, r: U): U { gk = k; return r }
    print(gk == setG("a", "a"))
    // vl check: rc 0.  vl run: prints true

Want:

    false

#### Mechanism

The left operand is a `K | null` place and the right a call returning the value-union box `U`.
Legacy's union compare reads the place after the call (the null leg's test and the decode each
re-read it), so it sees the call's write. The null legs parked the operand ahead of the box only
when the operand was no place (`unOpStaged`), and the plain arm, taken once the place is narrowed
non-null, staged the two sides only when the operand had effects (D17068). Neither asked whether the
box, evaluated first, could write the place. The IR reads the same two plans.

#### Sweep at the fix

The operand `K | null`, `string | null` or `boolean | null` at a global, a field, an element and a
captured local, compared to a `U` call that writes it; `==` and `!=`, the operand null and non-null
before the call (non-null narrows it to the plain arm), and the call first as a control. Want
`false false false true false false false false false false`:
