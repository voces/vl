### D4307 — a `let` written with an `if` expression mixing a generic function and a concrete lambda is refused at emit

**loud emit reject · clause 2 · found closing D4013 (lane SC, fn-value-flow §(f) step 3; `sc3/q/a4`) · filed 2026-10-13 against master `3f7d6e27f` with #3622 applied**

Repro:

    function inner<U>(u: U) { print("I"); print(u) }
    function other<V>(v: V) { print("O"); print(v) }
    function main(c: boolean) {
      let f = other
      f = if c { inner } else { (n: i32) => { print("L"); print(n) } }
      f(4)
    }
    main(true)
    main(false)
    // vl check: rc 0.  vl run: emitProgram: a generic function taken as a value reaches no call that fixes its type

Want:

    I
    4
    L
    4

#### Mechanism

D4013's close instances a written `let`'s `if` expression only when every arm names a declared
generic (`monoValueNamesGenerics`). With a concrete lambda in one arm the binding stays off that
path, and the generic arm is never given the lambda's type.
