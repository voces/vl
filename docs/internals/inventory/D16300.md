### D16300 — a `??` whose default is a literal of another storage builds an invalid module when the call that binds its result comes before the function's declaration

**closed 2026-11-14 by lane J · runs, prints `1` · was check-clean invalid wasm, clause 1 · `tests/cases/functions/coalesce-list-default-call-before-declaration.vl` · found from [D12455](D12455.md)'s witness while mapping the open clause-2 rows onto architecture items · filed 2026-11-14 by lane J against master `089d6e0b`**

Repro:

    const a: boolean[] | null = null
    const y = pc(a)
    function pc(xs: boolean[] | null) { xs ?? [1] }
    print(y.length)
    // vl check: rc 0.
    // vl run: invalid module, `the emitted module failed to validate`.

Want:

    1

#### Mechanism

The return-inference pre-passes check `pc`'s body quietly, before pass 2. There, the element `1`
of the default `[1]` had no recorded node type yet, and `litElemSrcTy` handed that `-1` sentinel to
`assignableExpr` as the element's source type. `assignable` reads a negative type as "accept", so
`[1]` fitted `boolean[]` and the `??` typed as its left side, `boolean[]`. Pass 2's own check of
`pc` gets the true join, `boolean[] | i32[]`, but a `const` checked before it (a call earlier in the
source) had already been typed from the pre-pass return, and its cell was built as a plain list
while the call returned the union box. `litElemSrcTy` now falls back to the literal's own element
type (`i32`) when the element has no record, as it already did for a hole-bearing one, so the
pre-pass and pass 2 agree and the order no longer matters.

#### Ablation

| ingredient changed | outcome | needed? |
| --- | --- | --- |
| `pc` declared before the call | runs, prints `1` | **yes** (the order) |
| `print(pc(a).length)`, no binding (generic `pc`) | check reject, the owed `??` join | **yes** (the binding) |
| default `[]` instead of `[1]` | runs, prints `0` | **yes** (a literal of another storage) |
| `a: i32[] \| null` (one storage) | runs | **yes** |
| `pc<T>(xs: T[] \| null)` generic | invalid module the same way | no |
| inside a function `p` calling `pc` (D12455's neighbour) | invalid module the same way | no |

#### Grading list

The generic spelling (`pc<T>`) and the spelling inside a caller `p(t: boolean, c: boolean)` with
`let a` written under `if c`, both with `pc` declared after the call. With `pc<T>` declared first,
the call keeps its owed check reject.
