### D16130 — a hole parameter handed two different functions, one of them a lambda returning a generic, has no closure type: its call names an unknown function

**loud emit reject · clause 2 · found by lane I prototyping D16077's close (branch `i-d16077-hole-param-maker`) · filed 2026-11-14 against master `b8b695bf`**

Repro:

    function inc(x) { x + 1 }
    function run(f) { return f()(41) }
    print(run(() => inc) + run(() => inc))
    // vl run: emitProgram: call to unknown function

Want:

    84

#### Mechanism

Two calls hand `run`'s parameter two lambdas, so the function-set path keys `run` per lambda
(`Fn#<node>`) and lowers each argument as a member of a tagged set. On master this is D16077's
refusal. The prototype of D16077's close gives `run` a closure-typed parameter instead, and with
both in play the argument was lowered as a set id where the instance took a closure: invalid
wasm. The prototype therefore closes only a lambda that is the one argument its parameter is
ever handed, and even that broke for two callees (D16133). Closing this means building
the tagged set's members at their closed types.
