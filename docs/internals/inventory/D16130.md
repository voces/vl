#### Mechanism

Two calls hand `run`'s parameter two lambdas, so the function-set path keys `run` per lambda
(`Fn#<node>`) and lowers each argument as a member of a tagged set. D16077's closing of a
lambda's hole type gives `run` a closure-typed parameter instead, and with both in play the
first argument was lowered as a set id where the instance took a closure: invalid wasm. So
the closing applies only to a lambda that is the one argument its parameter is ever handed
(`elabLamSoleArg`). With two, the program refuses as it did before. Closing this means building
the tagged set's members at their closed types.
