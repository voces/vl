#### Mechanism

The claim attempt asked `readRepOf(r)` while the elaboration is inside an arm. There
`elabNodeTyAt(r)` names that arm's list rather than the join, so the read rep is `K`'s atom
(`atom9`). The read-rep memo (`readRepOf`, `emit_classify.vl`) stores that answer (D17243). When the
claim refuses, legacy's `emitIndex` is served it: `exprUnion(r)` and then `armSiteReads(r[0])` are
false, and `idxArmOf` falls through to "none". With the memo hit bypassed, the same fallback builds,
and `readRepOf(r)` answers `union` as in the claimless build.
