### D13061 — a generic's declared `T[][]` result at a union or nullable pin is refused as an unsupported array element

**loud emit reject · clause 2 · open · `emitProgram: only i32[] arrays and struct/union element arrays are supported`, with no source position · found closing [D3154](D3154.md), at the return position of its nested literal · the same on master `0adbf4b86` · filed 2026-10-25 against master `0adbf4b86`**

Repro:

    function mk<T>(x: T): T[][] { [[x]] }
    const v: i32 | null = 4
    print(mk(v).length)
    // vl check: rc 0.  vl run: emitProgram: only i32[] arrays and struct/union element arrays are supported

Want:

    1

#### Mechanism

Not localised. The literal is not the ingredient: the body `const l = [[x]]; return l` refuses
the same way. Leaving the result un-annotated (`function mk<T>(x: T) { [[x]] }`) runs, so the
instance builds the value. What fails is lowering the declared `T[][]` result at a
union-leaf pin. That shares two ingredients with [D13060](D13060.md), `T[][]` in the signature
and a union leaf, but it has not been shown to be the same mechanism.

#### Ablation

| a record pin `P` | prints `1` | **yes** (a union or nullable leaf) |
| an `i32 \| string` pin | the same emit reject | no |

#### Grading list
