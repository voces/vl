### D6000 — a module binding of a hole function returned through a hole, called at a second type inside a function, is lowered at the function's other instance

**closed 2026-10-17 by lane L1 · runs, prints `3` then `v` · was check-clean invalid wasm · clause 1 · the global-init pre-pass now declares a module binding whose type is an open function type, so a body checked before the binding reads that type instead of the placeholder, and the call is lowered at the binding's own instance · pins: `tests/cases/closures/module-binding-of-hole-fn-called-in-earlier-function.vl`, `tests/cases/closures/error-module-binding-of-hole-fn-misused-in-earlier-function.vl` · found closing [D5972](D5972.md) · the same on master `200c89ff8` · filed 2026-10-17 against master `200c89ff8`**

Repro:

    function fw(f) { return f }
    function id(x) { return x }
    print(id(3))
    function g() {
      print(q("v"))
    }
    const q = fw(id)
    g()
    // vl check: rc 0.  vl run: the emitted module failed to validate inside `g`: type mismatch: expected i32, found (ref $type)

Want:

    3
    v

#### Mechanism

From the ablation only. A read of `q` inside a function finds no signature of its own for
`fw(id)`; when `id` has another instance (`id(3)`), the call is lowered at that instance's
`i32` signature, and with none the call refuses. A function-local `const q = fw(id)`, or a
read at module scope, runs.

Found closing it: the order is the ingredient. With `const q` declared above `g` the witness
ran. Declared below, `g`'s body is checked before pass 2 reaches `q`, and the global-init
pre-pass (`globalInitPrePass`, `check_top_level.vl`) left `q` as the hoist's placeholder because
its type `(x: T) => T` carries a hole. An ill-typed call (`q("v") + 1`, or a wrong arity) was an
emit refusal in that order and a check reject in the other; both are now a check reject in
both orders. A maker returning an explicit generic (`const q = mk()`) and an arrow-lambda `g`
had the same order dependence and run too.
