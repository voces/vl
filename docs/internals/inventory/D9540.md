### D9540 — a returned generic handed to an un-annotated parameter that calls it at two types refuses

**closed 2026-10-22 by lane-D9480 · runs, prints `21` and `a` · was loud emit reject, `monomorphize: unsupported argument type`, `vl check` rc 0 · clause 2 · CAPABILITY: the generic handed over directly runs at both types · closed by letting the checker mark the hole split for a call that always returns one declared function (`constRetFnName`, check_calls.vl) and the hole plan hand such a call once, then the generic by name per further key (`fsPlanHoles`, `fsPlanHoleRewrites`, fn_split.vl) · fixture `closures/hole-fn-param-handed-call-returning-generic.vl` · found closing [D9432](D9432.md) · present on master `1cf53e320` · filed 2026-10-22 against master `1cf53e320`**

Repro:

    function id<T>(x: T): T { x }
    function deliver() { return id }
    function take(a) {
      print(a(21))
      print(a("a"))
    }
    take(deliver())
    // vl run: emitProgram: monomorphize: unsupported argument type for `a` in a call to `take`

Want:

    21
    a

#### Mechanism

`take(id)` runs at both types because the hole parameter `a` is split into one parameter per
type it is called at (D5611): the checker marks the split (`holeFnSplitAt`, from
`judgeFnArgHoleCalls`, check_calls.vl) and fn_split hands the argument once per parameter.
The checker marked the split only for an argument naming a declared function, so for
`take(deliver())` the monomorphizer never asked fn_split for it and refused in
`monoArgTyFail`; fn_split's `fsPlanHoles` also declined any argument that was not a name or a
lambda. A call whose every `return` names one generic (`fsConstRet`) is now marked and
planned: it is handed as itself to the first parameter, so it runs once, and the generic by
name to the rest.

#### Ablation

| ingredient removed | outcome | needed? |
| --- | --- | --- |
| `deliver` (`take(id)`) | runs, `21`, `a` | **yes** |
| the second call type (`a(21)` only) | runs | **yes** |
| the generic's function-typed parameter (`app<T>(f: (x: T) => T, x: T)` refuses the same way) | still refuses | no |
