### D9540 — a returned generic handed to an un-annotated parameter that calls it at two types refuses

**loud emit reject · clause 2 · `vl check` rc 0 · CAPABILITY: the generic handed over directly runs at both types · found closing [D9432](D9432.md) · present on master `1cf53e320` · filed 2026-10-22 against master `1cf53e320`**

Repro:

    function id<T>(x: T): T { x }
    function deliver() { return id }
    function take(a) {
      print(a(21))
      print(a("a"))
    }
    take(deliver())
    // vl run: emitProgram: monomorphize: unsupported argument type for `a` in a call to `take`

Want:

    21
    a

#### Mechanism

Not traced. `take(id)` runs at both types, so a generic handed over directly gets a copy per
pin. Past `deliver`'s return, the slot holds two closed pins, and `monoCoerceRetAtPin` sends it
to `monoAskRetCopies`. The argument still reaches `take`'s monomorphizer without a type it can
instance `a` at.

#### Ablation

| ingredient removed | outcome | needed? |
| --- | --- | --- |
| `deliver` (`take(id)`) | runs, `21`, `a` | **yes** |
| the second call type (`a(21)` only) | runs | **yes** |
| the generic's function-typed parameter (`app<T>(f: (x: T) => T, x: T)` refuses the same way) | still refuses | no |
