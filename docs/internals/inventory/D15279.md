### D15279 — an unbound call's returned record, its function field called at two types, builds an invalid module

**closed · runs · was check-clean invalid wasm · clause 1 · `type mismatch: expected i32, found f64` · one call type runs · found grading D15273 · filed 2026-11-04 against `lane/g2-d15273` with D15273 · closed by the record solve declining a literal two field calls build at different storages**

Repro:

    function id1(a) { return a }
    function mk() { return { f: id1 } }
    print(mk().f(7))
    print(mk().f(7.5))

Want:

    7
    7.5

#### Mechanism

Each field call `mk().f(…)` built the literal its receiver reads at the call's closed instance
on the spot (`holeRecAdopt`), so of two calls at two types the second won: the literal's
closure was built at `(f64) => f64`, both calls went through it, and the first call's `f64`
result was printed as an `i32`. A bound receiver did not miss, because the record solve's
settle (`recAdSettle`) already declined a binding two calls close at different records. The
literals now queue beside those bindings and the settle declines a literal two calls build at
different storages the same way; the rest adopt after the solve.
