### D705 — a module-scope STRING shadowed by a function-local of another rep: the USE picks its arm from the module table

**check-clean invalid wasm · `vl check` rc 0, then `Invalid input WebAssembly code at offset 283: type mismatch: expected (ref $type), found i32` · CITED SINCE 2026-08-31 AND NEVER FILED — `tests/cases/generics/error-pin-global-shadowed-by-local.vl` says "IT IS FILED (D705)" and no row existed; written 2026-09-03 against master `2fb8b271` from the citation and re-measured · THE GENERIC IN THAT CITATION IS NOT AN INGREDIENT, and the STRUCT half of its sentence is false today**

Repro:

    const sh: string = "hi"
    function leg() {
      const sh = 7
      print(sh)
    }
    leg()
    // vl check rc 0 (one redundant-annotation hint).
    // vl run: Invalid input WebAssembly code at offset 283:
    // type mismatch: expected (ref $type), found i32

#### Mechanism

Disassembled (`wasm-dis`, function[4] `leg`), the local's OWN slot is right and the USE's is
not. `leg` declares `(local $0 i32)` and `(local $1 (ref $2))`; the body is
`(local.set $0 (i32.const 7))` — the shadowing `const`, correctly an i32 — followed by
`(local.set $1 (local.get $0))`, an i32 written into a string slot, and then the STRING print
loop: `struct.get $2 0/1/2` for the bytes, offset and length, `__print_char__` per byte,
`__print_str_flush__`. So the emitter did not mis-type the binding; it chose `print`'s STRING
arm, and that arm's scratch is what the i32 lands in. The arm is chosen from the module-scope
`sh: string`, which the function-local `const sh` never displaces. The same happens at a
non-`print` use (`sh + 1` inside a function returning i32 is invalid wasm at offset 286), so
`print` is the vehicle and not the mechanism. **The exact classifier call site is NOT named
here — this row records what the emitter produced, measured, and stops there.**
