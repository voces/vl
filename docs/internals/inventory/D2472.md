### D2472 — a writer a callee runs as a function value is not charged to the call

**closed 2026-09-25 — now a loud check reject (`'o.v' is no longer narrowed to i32: the call to
'call1' on line 6 may reassign it`) · was loads then traps, clause 1 · filed and closed against
master `dec16071c`, found by the review of #3159 (25 cells of its generated grid) · fixture
`tests/cases/soundness/callback-writer-charged-at-call-reject.vl`**

Repro:

    type O = { v: i32 | string }
    function wf(x: O) { x.v = "s" }
    function call1(x: O, f: (O) => void) { f(x) }
    const o: O = { v: 1 }
    if o.v is i32 {
      call1(o, wf)
      print(o.v + 1)
    }
    // vl check: rc 0.  vl run: wasm trap: cast failure

#### Mechanism

`call1` calls its function parameter, whose target no write summary of `call1` can see. The
free-variable and parameter legs read `call1`'s own body, and the only write lives in the function
value it runs, so `wf`'s write of `x.v` was charged nowhere and the narrowing survived the call.

| --- | --- | --- |

| the call through `f` (`wf(o)` directly) | loud check reject | **yes** |
| module scope (the same lines inside a function) | traps the same | no |

#### Close

D2461's write shapes: a call of a function's own parameter `i` is `@i` in its summary, and a call
site charges what its argument there writes. A call back into a summary still being computed (an

any of them; a read-only cycle still keeps the narrowing
(`tests/cases/soundness/recursive-callback-*.vl`).
