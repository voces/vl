**closed 2026-10-19 by lane L1 · runs, prints `3 4 7` · was loud emit reject · the copy of the read runs as the statement before the one holding the call whenever only name and literal reads evaluate before the call on the way up (`monoFlowCallStmtOf`/`monoFlowRunsFirstIn`, emit_mono.vl): a `let` or `return` value, an `if` condition, an operand, an argument · pin: `tests/cases/closures/hole-fn-list-computed-index-call-as-value.vl` · a call after other evaluation is [D7483](D7483.md) · `vl check` rc 0 · clause 2 · CAPABILITY: the same call as a statement runs `3 4` ([D7182](D7182.md)) · found closing [D7182](D7182.md) · the same on master `622d88f2c` · filed 2026-10-19 against master `622d88f2c`**

    function add(a, b) { return a + b }
    function apply2(g) {
      print(g(1, 2))

Want:

    3
    4
    7

#### Mechanism

D7182's close points a computed-index callee at the list's one generic only when the call
stands as a statement, because the copy of the read that keeps the index's evaluation and
its bounds check runs as the statement before it. A call in a value position had no
statement slot found for that copy, so mono left the read alone and the floor refused it. The
close walks up from the call to its statement, through every parent where nothing but name and
literal reads evaluates before the call, and runs the copy before that statement.
