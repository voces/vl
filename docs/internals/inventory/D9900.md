### D9900 — a nested list of an un-annotated function, read through a variable row index and at a second type, is refused as nested

**loud emit reject · `vl check` rc 0 · `nested arrays are not supported` · clause 2 · found closing [D9760](D9760.md) · present on master `23ac8244a` · filed 2026-10-22 against master `23ac8244a`**

Repro:

    function inc(a) { return a + 1 }
    const u = [[inc]]
    let i = 0
    print(u[i][0](3))
    print(u[0][0](2.5))
    // vl check rc 0.  vl run: emit error: emitProgram: nested arrays are not supported

Want:

    4
    3.5

#### Mechanism

Not traced. From the ablation only: a literal row index runs, so the flow-read rewrite
(`monoFlowReadsRound`, emit_mono.vl) is the likely place, where `u[i]` names no one row literal and
the list would keep [D9711](D9711.md)'s uncalled stub element.

#### Ablation

| ingredient removed | outcome | needed? |
| --- | --- | --- |
| the variable index, for `u[0][0](3)` | runs, `4` `3.5` | **yes** |
| the nesting (`const u = [inc]`, `u[i](3)`) | runs, `4` `3.5` | **yes** |
| the second type, for `u[0][0](2)` | runs, `4` `3` | **yes** |

#### Grading list

The same read inside a `for i in 0..u.length` loop; a list of two rows.
