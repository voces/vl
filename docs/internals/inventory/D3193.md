### D3193 — a generic or hole instance calling a record's field function whose result is a literal union prints the member's atom

**closed · `anyLitUnionUsed` counts a literal union that is a function type's result, bare or as a record's field, so the instance's atom classifiers are not switched off · fixture `tests/cases/generics/instance-call-of-literal-union-field-function.vl` · was check-clean silently wrong · clause 1 · pre-existing, the same on master `36d233f66` · found by the #3286 review (`rv3286-2159/g2/k0287_s7_i32_none_generic.vl` and seven siblings) · filed 2026-09-29 against master `36d233f66`**

Repro:

    type R = { v: i32, f: () => "a" | "b" }
    function F<Z>(z: Z) { print(z.f()) }
    const r: R = { v: 1, f: () => "a" }
    F(r)
    // PRINTS 0

Want:

    a

#### Mechanism

`anyLitUnionUsed` gates every atom classifier (`gLitUnionUsed`), and it saw a literal union
only as a node's type, a record field or a map value. Outside an instance, or at an annotated
parameter, the call node itself is typed `"a" | "b"`, which is enough. Inside one the call is
typed at a hole, and the only other mention is the function type's result, so the gate stayed
off and `print`, `==` and a `string` return read the atom as an `i32`. The gate now counts a
function type whose result is a literal union. A `| null` result is not counted: switching the
classifiers on for it moved master runs to invalid wasm, and it is [D3198](D3198.md). The same program at a `| null` field also needs
[D3192](D3192.md)'s read.

#### Ablation

| ingredient changed | outcome | needed? |
| --- | --- | --- |
| `print(r.f())` at module scope, no function | prints `a` | **yes** (an instance) |
| `function F(z: R)` | prints `a` | **yes** |
| `function F(z)`, a hole | prints `0` | no |
| `R` without `v` | prints `0` | no |
