Repro:

    function half(a) { return a / 2.0 }

Want:

#### Mechanism

`monoHeldRecordListAt` (`emit_mono.vl`) re-pins a bound record-list literal at the slot store's
element type (`elabSlotTyAt`) when the literal's element type is open (`monoTyOpen`). For a list
of a tagged set's records the element is closed: the set is read through its id, at the rep the
checker stamped. `monoTyOpen` asked that through `fnTagHoldsTy(t, 4)` and
`monoTyOpenUntagged(t, 4)`, and the second answers "open" when its budget runs out. At four
records the walk spends its budget one level above the set's field. The element read as open,
the binding was pinned at the slot fact `{a: {b: {c: {d: {f: (i32) => f64}}}}}` (one member's
closure, not the set), and `collectAnnShapes` interned that annotation's chain before
`heldListElemAlias` ran. The alias found the own element already had a row and declined, so the
global and the array were typed by the closure chain while the literals were built on the
stamped `i32` chain. At three records the walk reached the set's field and answered closed.

The close raises both budgets to 16, the bound `tyReachesHole` beside them already uses. Corpus:
`tests/cases`+`std` 6,930 of 6,930 modules and distilled 8,905 of 8,905 cells byte-identical
(fixpoint seeds, master `2f28e2ae2`); only programs nesting the set four or more records deep move.

D16731 and D16732 do not share this mechanism. Raising every emit `fnTagHoldsTy` budget to 16,
and the checker's two record-literal budgets (`fnTagRecLitsOnly`, `fnTagHeldRecLit`) to 16, moves
neither: depth seven still emits the leaf as a closure value (`emitClosureValue` under
`emitObj`), and depth eight is still refused by the checker.
