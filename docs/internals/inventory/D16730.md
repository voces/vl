**closed 2026-11-16 · runs, prints `4` `1.5` · was check-clean invalid wasm, `type mismatch: expected (ref null $type), found (ref $type)` · clause 1 · found by the type hash-cons 6a depth-cap census (probing D15805's bound-list case past the depths it tested) · filed 2026-11-16 against master `350eab14e` · fixed by `fnTagHeldNote` (check_elab_cap.vl) stamping the bound list literal with the binding's rep, which the literal's own concrete type at depth four and deeper had displaced, and by `collectAHeldRep` (emit_collect.vl) interning the held list's ref-list slot for a nested record element, which only a flat one had, so the binding's cell is typed at the row its records are built on · depths five and six run too; [D16731](D16731.md) and [D16732](D16732.md) are other mechanisms and stay open · fixture `closures/record-list-fn-field-two-results-bound-deep.vl`**

    function half(a) { return a / 2.0 }

#### Mechanism

Measured with temporary probes. At depth four the array literal has a concrete type of its own
(`litRepTyAt`: the closure-leaf chain), where at depth three it has none and follows the binding, so
`arrLitListBuild` built it at the closure-leaf row while the records were built on the stamped
`i32`-leaf row. Stamping the literal too left one more mismatch: the binding's cell row comes from
`letRefListSlot`, whose held-rep rung found no ref-list slot for the stamped element
(`rlSlotOfTy` -1), because `collectAHeldRep` interned that slot only for a flat record element.

- **The checker stamps the same at depths three and four.** A scratch trace in `fnTagHeldNote`
  (`check_elab_cap.vl`) shows the binding stamped at the rep whose leaf field is the set's `i32` id
  (`recs` true, from `fnTagRecLitsOnly` at scope 8). The array literal itself is left unstamped
  (`recs` false at scope 1). Both depths read the same.
- **Emit holds two list rows at depth four.** `--names` plus `wasm-dis` show both:
  - the list's own type, a chain of five records whose leaf field holds a closure;
  - the stamped rep, the same chain with an `i32` leaf.

  The global and the array literal are typed by the first; the record literals are built on the
  second. At depth three the module holds only the stamped chain.
- **`heldListElemAlias` (`emit_collect.vl`) aliases one level.** It maps the own type's element row
  to the rep's row, but not the rows nested below it. The open question is which emit path interns
  the own type's deeper rows at depth four and types the global from them. The candidates are
  `letHeldTyOf` → `letLitHeldTy` (`emit_classify.vl`) and the other `heldRepOf` readers.
- **No depth cap is the cut.** A cap-counting scratch seed, which counts each `depth`/`budget`
  comparison, finds that between depths three and four only `fnTagHoldsTy` changes count (4 hits
  to 26). Its callers pass 4, 6, 8 or 16. Making it unbounded with a visited set leaves depth four an
  invalid module, so that mismatch is not the cause.
- **`fnTagHasSplitFieldIn`'s depth is D15805's scope, not this cut.** It is 1 for a returned literal
  and 8 for a bound one.
