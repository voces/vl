### D16730 — a bound list literal whose records hold un-annotated functions of different result types four to six levels deep builds an invalid module

**check-clean invalid wasm · clause 1 · found by the type hash-cons 6a depth-cap census (probing D15805's bound-list case past the depths it tested) · filed 2026-11-16 against master `350eab14e`**

Repro:

    function inc0(a) { return a + 1 }
    function half(a) { return a / 2.0 }
    const xs = [{ a: { b: { c: { d: { f: inc0 } } } } }, { a: { b: { c: { d: { f: half } } } } }]
    print(xs[0].a.b.c.d.f(3))
    print(xs[1].a.b.c.d.f(3))
    // vl check: rc 0.  vl run: invalid module, "type mismatch: expected (ref null $type), found (ref $type)"

Want:

    4
    1.5

#### Mechanism

Not yet located. [D15805](D15805.md) made a bound list's nested records run by building them at
the list's rep (`fnTagHeldRecLit`, `fnTagHasSplitFieldIn`, `check_elab_cap.vl`). Its witnesses nest
one to three levels and run. The same program with the function field four, five or six records
deep passes `vl check` and emits a module whose top-level code stores a non-null reference where
the slot is typed nullable. The census's own depth caps on that path are 8, so the cut at four
comes from elsewhere on the build path.
