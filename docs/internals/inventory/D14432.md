### D14432 — a binding of a map entry of a set of un-annotated functions refuses its map value

**loud emit reject · `vl check` rc 0 · clause 2 · CAPABILITY: the entry read through `??` without a binding runs, and so does the annotated face · deleted by union rows keyed by member reps (Step 7 final slice, D14551 lane) · found building the container write-join · filed 2026-10-27 against master `efb1a8105` · pinned by `tests/cases/maps/error-fn-set-map-get-binding.vl`**

Repro:

    function inc(x) { return x + 1 }
    function dbl(x) { return x + x }
    const m = Map()
    m.set("a", inc)
    m.set("b", dbl)
    const g = m.get("b")
    if (g != null) {
      print(g(2))
      print(g(2.5))
    }
    // vl check rc 0, vl run: emitProgram: unsupported map value type

Want:

    4
    5

#### Mechanism

The map's writes join to one set {inc, dbl}, whose tag rep is the i32 id. A `??` over an
entry reads the id directly. A binding of the entry holds `F | null`. The nullable lowering
reads the inner value's rep, so `F | null` over a tagged set is the boxed `i32 | null`, but the
box needs a value-union row and none is registered: `registerInlineUnionGo` admits a row by
its spelling (`isValueUnionName`), and a member's atom offset comes from its spelling
(`valueAtomKind`), where every function-set type spells alike and reads as the closure atom.
So `ftNulOk` leaves a set whose entry is bound untagged, and the map refuses its value. With
the binding accepted, the witness inside a function body (`function run() { ... }` around the
same lines) is check-clean invalid wasm: the local is typed as a stale box index, the map read
stores the raw i32 id, and the narrowed call reads the box local as the id
(`expected (ref $7), found i32`). When union rows are keyed and minted by member reps,
`ftNulOk` accepts the binding and this row closes.
