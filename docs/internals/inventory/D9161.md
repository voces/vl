### D9161 — a `const` bound to an `if` of two generic functions whose condition calls a function refuses when called at two types

**loud emit reject · `vl check` rc 0 · clause 2 · CAPABILITY: the same binding with a pure condition runs ([D9120](D9120.md)) · found closing [D9120](D9120.md) · present on master `4121cc9a7`, where it built an invalid module · filed 2026-10-21 against master `4121cc9a7`**

Repro:

    function idg<T>(t: T): T { return t }
    function kg<T>(t: T): T { return t + t }
    let n = 0
    function pick(): boolean { n = n + 1
      return n > 0 }
    const h = if pick() { kg } else { idg }
    print(h(3))
    print(h("x"))
    print(n)
    // vl run: emitProgram: a binding of an `if` choosing generic functions is delivered at two function types — annotate the binding

#### Mechanism

[D9120](D9120.md)'s close gives each call type its own copy of the choice, which re-evaluates
the condition once per copy. With a condition that calls a function that may write, the copies
could choose differently and `pick` would run more than once, so the split declines
(`fsPureRead`, fn_split.vl) and the refusal stays. Running it needs the condition evaluated once
into a hidden binding the copies read, or a binding that holds one value per instance of the
chosen generic.
