#### Mechanism

[D9120](D9120.md)'s close gives each call type its own copy of the choice, which re-evaluates
the condition once per copy. With a condition that calls a function that may write, the copies
could choose differently and `pick` would run more than once, so the split declines
(`fsPureRead`, fn_split.vl) and the refusal stays. Running it needs the condition evaluated once
into a hidden binding the copies read, or a binding that holds one value per instance of the
chosen generic.
