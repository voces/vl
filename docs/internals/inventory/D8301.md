### D8301 — a literal-building function delivered into two records of different field storage is built at one of them

**now a loud check reject · was check-clean invalid wasm · clause 1, present on master `82bf510a3` · made loud by `recSitesLandApart` (check_fit_rules.vl), each delivery refused as "only a fresh record widens" · running it is a build per landing, the same as [D8302](D8302.md) · fixture `soundness/error-fresh-call-landing-two-storages.vl` · found closing [D8201](D8201.md) · filed 2026-10-20 against master `82bf510a3`**

Repro:

    type J = { r: i32 | null, g: i32 }
    type K = { r: i32 | null, g: i32 | null }
    function mk() { { r: 15, g: 1 } }
    const a: J = mk()
    const b: K = mk()
    print(a.r ?? 0)
    print(b.g ?? 0)
    // vl check: rc 0.  vl run: the emitted module failed to validate inside the module's top-level code

Want:

    15
    1

#### Mechanism

Each delivery queues `mk` to be built at its own destination, `J` and then `K`, and the two
re-seats disagree. The pending-row pass judges conflicting deliveries of a `let` declaration
(`recKeptConflicts`, check_program.vl), not those of a function, so both are kept and `mk` is
built at one row while the other binding reads it as its own. check_program.vl is outside lane
L1's file boundary.

Made loud in `recAdoptNote` (check_fit_rules.vl): before a call or a pass-through identity is
queued for a build at its landing, `recSitesLandApart` asks whether another call site of the
same function is queued to land on different field storage. If one is, the delivery is refused
at the function's own row (`recRefuseAtOwnRow`), at every position the fixture lists.
