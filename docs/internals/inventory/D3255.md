### D3255 — an uninitialized `let y: Map<…>` trapped the compiler in `letIsSet`

**closed 2026-09-29 (`letIsSet` in `compiler/emit_query.vl` reads a `let`'s initializer only when it has one) · was a compiler trap, clause 1 · filed against master `d48a56b17`**

Repro:

    function h(n: i32): i32 {
      const o = Map<string, i32>()
      o["a"] = n
      let y: Map<string, i32>
      y = o
      y["a"] ?? -1
    }
    print(h(4))
    // was: the compiler itself trapped (out of bounds array access), letIsSet <- letMapShapeOf
    // now: prints 4

Want:

    4

#### Mechanism

`letIsSet` asked the set-ness of the initializer's arena type only behind a `letInit >= 0`
guard, and then read `P.nodes[d.letInit]` unguarded to look for a `Set()` call, so a map
binding declared with no initializer read `P.nodes[-1]`. A loop or labelled-block value of
map type lowers through exactly such a binding, so every map-valued loop trapped too.

#### Ablation

| ingredient removed | outcome | needed? |
| --- | --- | --- |
| the missing initializer (`let y: Map<string, i32> = o`) | runs | **yes** |
| the map type (`let y: i32`) | runs | **yes** |
