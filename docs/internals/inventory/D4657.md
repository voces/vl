### D4657 — a call through a function value is never a tail call

**closed 2026-10-14 · runs — the witness prints `1000000` · a function-value call (`call_indirect`) arms the tail-call cursor, and the rewrite writes `return_call_indirect` · fixture `tests/cases/functions/tail-call-depth-void-union-indirect.vl` · was trap after load (call stack exhausted) · filed 2026-10-14 against master `43c852e79`**

Repro:

    function step(n: i32, acc: i32): i32 {
      if n == 0 { return acc }
      const f = step
      return f(n - 1, acc + 1)
    }
    print(step(1000000, 0))
    // vl check: rc 0.  was, vl run: wasm trap, call stack exhausted in `step`

#### Mechanism

A call through a function value lowers to `call_indirect` through the function table
(`emitCallRefUnder`, and `emitCapturedCall` for a captured one). Only direct calls armed the
tail-call cursor, so the rewrite never saw these. Both sites now arm it with the call's type
index and table (`tailCallTable`), and the rewrite writes `return_call_indirect` in place of
`call_indirect` and `return`. A void caller is still declined.
