#### Mechanism

A statement block retires, after each statement, the narrowings a write in it falsified
(`pushPostGuardNarrow`); the prelude of an if-expression arm is lowered statement by statement
by `emitIfArmOpen`, which skipped that step. So `x` stayed narrowed to `i32` past `x = null`, the
re-test `x != null` folded to `true` (`narrowExcludesNull`), and the read cast a null box. The
checker had retired it, which is why `vl check` passed. The prelude now runs the same
before and after steps a block does, and the arm's close drops what the prelude pushed while
keeping what it retired. The same mechanism made D2589's nested re-test
(`x != null && ((… x = null …) && x != null)`) trap once D2052 let that arm lower.
