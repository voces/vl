### D3229 — a hole instance's call of a field holding a bound function value reads its result at the `i32` sink

**closed · `exprString` and `exprIsF64` read the hole's pin for a field call whose field function is not a lambda the resolver finds, the rung #3289 added for D3203 · fixture `tests/cases/generics/hole-call-bound-function-field.vl` · was check-clean invalid wasm · clause 1 · found by the #3290 round-2 review (`rv3290-4029/gF2`, `f0039`, `f0040`, `f0058`, `f0059`) · filed 2026-09-29 against master `94670f728`, closed on master `313a071b4`**

Repro:

    function h(z) {
      print(z.f())
    }
    const g0: () => string = () => "s"
    h({ k: 0, f: g0 })

Want:

    s

#### Mechanism

`fieldClosureFeOfRecv` finds the lambda a field literal holds, not a bound function value, and
the call's own node records the hole, so `exprString` and `exprIsF64` answered false and `print`
took the `i32` sink over a string or `f64` result. Both fall back to the pin, as the
`Ident`-callee arm already did (D3117); #3289 landed the same rung for D3203.

#### Ablation

| ingredient changed | outcome before the close | needed? |
| --- | --- | --- |
| field holds `() => "s"`, a lambda | prints `s` | **yes** (a bound function value) |
| a declared record `R` holding `g0` | invalid wasm | no |
| `const s: string = z.f()` | prints `s` | **yes** (a classifier-driven sink) |
| result `i64` or `string \| null` | loud emit reject (keyed only for scalar or string) | not this row |
