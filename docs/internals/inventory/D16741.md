### D16741 — an annotated list of records nested five deep with an `i64` leaf from a literal builds a module that does not parse

**closed 2026-11-16 · runs, prints `3000000007` · fixed by lane AE4: `numLitAdoptDeep` follows a literal at any depth and `tyHoldsNonI32Num` walks a type to any depth, so the literal is built as an `i64` · was check-clean malformed wasm · clause 1 · fixture `tests/cases/soundness/deep-literal-leaf-rep.vl` · found closing [D16731](D16731.md) · filed 2026-11-16 against master `71ff99b49`**

Repro:

    const zs: { a: { b: { c: { d: { e: i64 } } } } }[] = [{ a: { b: { c: { d: { e: 7 } } } } }]
    print(zs[0].a.b.c.d.e + 3000000000)
    // vl check: rc 0.  vl run on master: "failed to parse WebAssembly module … constant expression required: non-constant operator: visit_i64_extend_i32_s"

Want:

    3000000007

#### Mechanism

The literal `7` adopts its destination's `i64` width through `recordRepTyAdopt` and
`numLitAdoptDeep`, both handed a budget of six levels from the list. Five records and the list
spend it, so `7` stayed an `i32` and the global's initialiser widened it with `i64.extend_i32_s`,
which a constant expression may not hold. Both walks follow the literal's own nodes and now take
no budget; their gate, `tyHoldsNonI32Num`, walks the type with a visited list instead of a depth.
