### D2207 — a named function with a `u8[]` parameter, taken as a function value, emits a module that fails to validate

**closed 2026-09-24 by D2296 — the witness prints `5` · was check-clean invalid wasm, clause 1 · the grading list below runs too · found by the std API review of #3064 · filed 2026-09-23 against master `6de01ea58`**

Repro:

    function w(p: string, d: u8[]): i32 { return p.length + d.length }
    const f: (string, u8[]) => i32 = w
    print(f("ab", [1, 2, 3]))
    // vl check: rc 0.  vl run (as filed): invalid module, `expected (ref $type), found
    // (ref $type)`. Now prints 5.

#### Mechanism

The literal `[1, 2, 3]`, not the parameter, was the ingredient: a list literal passed to a
function value built the list its own elements name (`i32[]`) because the value call threaded no
build code, which D2296 fixes; an annotated `u8[]` local as the argument ran, and a `u8[]`
result through `const g = r` prints `299` for `g(300)[0] + g(1)[1]`. The filing follows. The
un-annotated binding `const f = w` fails the same way, while the same
shape over an `i32[]` parameter, or over a `u8[] | B` one narrowed in the body, runs and
prints `5`, so the packed `u8[]` parameter in the function-value signature is the suspected
ingredient.

#### Grading list

`const f = w` (no annotation); the call with an annotated `u8[]` local in place of the
literal; a `u8[]` RESULT in place of the parameter.
