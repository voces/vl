### D2863 — a narrowed record argument to an un-annotated parameter, beside a same-layout row of another field kind, reads the other row

**closed 2026-10-05 by [D3693](D3693.md)'s close — the witness prints `true`, `4` · was a loud emit reject (`a record argument's fields name a row that holds another field kind, and a record is shared rather than converted`), clause 2, and before that check-clean invalid wasm on master `1df19732b` · found grading [D2762](D2762.md)'s union positions · filed 2026-09-27**

Repro:

    function p(o) { print(o.f) }
    const a = { f: true }
    p(a)
    function pick2(c: boolean) {
      if c { return { f: 4 } }
      null
    }
    const u2 = pick2(true)
    if u2 != null { p(u2) }
    // vl check: rc 0.  master: emit error (the refusal above)
    // Was: invalid module inside `p$1` — expected (ref null $type), found (ref $type)

Want:

    true
    4

#### Mechanism

The narrowed `u2` pins `p` by its rendered spelling, `{f:i32}`, not by an anonymous row handle.
The rendered-spelling reader (`structIndexOfTypeName`) matches the first row of that layout,
which is `a`'s `{ f: true }` row, so the instance's body reads `o.f` from that row (and formats it
as a boolean) while its signature and caller carry `pick2`'s own row. The monomorphizer now
refuses a pin whose spelling names a row whose minting type disagrees with the argument's type
on a code-0 field kind (`anonRowKindsAgree`), and only when the instance's body names the
parameter at all (a read, an alias, a copy or a capture): an instance that never touches it
builds and runs as on master (`function p(o) { print("x") }`). A correct build needs the pin to name the
argument's own row; the rendered-spelling readers do not split code-0 kinds because a hole
constructor's record cannot choose between split rows ([D2841](D2841.md), [D2850](D2850.md)). [D2866](D2866.md) is the same shape at annotated rows, which this refusal does not ask.
