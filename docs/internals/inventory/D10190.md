### D10190 — a `slice` copy of a list holding a generic, itself called at two types, has no one instance

**loud emit reject · `vl check` rc 0 · `a list holding a generic function is called through its elements at more than one type, so its elements have no one instance` · clause 2 · CAPABILITY: the copy spelled `[...xs]` prints `2`, `s`, `5`, `q` · found closing [D10082](D10082.md) · present on master `9ca7e7751` · filed 2026-10-22 against master `9ca7e7751`**

Repro:

    function id<T>(x: T): T { x }
    const xs = [id]
    const ys = xs.slice(0)
    print(xs[0](2))
    print(xs[0]("s"))
    print(ys[0](5))
    print(ys[0]("q"))
    // vl check rc 0.  vl run: emit error: emitProgram: a list holding a generic function is called through its elements at more than one type, so its elements have no one instance — annotate the list's element type

Want:

    2
    s
    5
    q

#### Mechanism

The close of [D10082](D10082.md) keeps a sliced list's literal reading through its element slot,
so every call through the copy is a pin on that slot. With the copy called at two types the slot
takes two pins and `monoPinListElems` refuses. The spread copy works because the flow pass
expands `[...xs]` into the literal's elements, which `slice` has no arm for (`mfrSliced`, emit_mono.vl). On master the
refusal reads `a generic function taken as a value reaches no call that fixes its type`.
Left open by the lane that closed [D10202](D10202.md) and [D10204](D10204.md): an emit
mechanism the checker changes there do not reach.
