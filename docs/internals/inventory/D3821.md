### D3821 — a generic `self`-function called through `?.` pins its `T[]` parameter from the receiver's nullable spelling

**loud emit reject · filed 2026-10-07 against master `2ed2f0596` (found by lane DG, SP-052)**

Repro:

    import { reverse } from "std:array"
    function pick(xs: f64[] | null): f64 {
      const ys = xs?.reverse()
      if ys == null { return -1.0 }
      ys[0] * 2.0
    }
    print(pick([2.5, 1.25]))
    print(pick(null))
    // vl check: rc 0.  vl run: emitProgram: monomorphize: expected an array argument for `self` in a call to `reverse`

Want:

    2.5
    -1

#### Mechanism

The monomorphizer pins the call's `self` argument by its spelling (`monoArgPinName`), and the
receiver of an optional call is still the nullable binding there: `f64[] | null` is not an
array spelling, so the `T[]` arm in `emit_mono.vl` refuses it. The `?.` guard
(`drwOptGuard`, `emit_rewrite.vl`) only proves the receiver non-null inside the non-null
arm, and the pin is not read through that guard.

#### Ablation

| ingredient removed | outcome | needed? |
| --- | --- | --- |
| the `?.` (a non-null receiver, `xs.reverse()`) | runs | **yes** |
| the generic `self` (a `self: f64[]` function) | runs | **yes** |
| a lambda argument | still refuses (this witness has none) | no |

#### Grading list

`xs?.sorted((a, b) => a < b)` over `f64[] | null`, the generic `?.` spelling of SP-052, which
checks clean since SP-052's fix and refuses here.
