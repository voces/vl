### D17382 — a scalar list's `.pop()` or `.get(i)` `?? d` stored as a union box takes the fused element read

**closed 2026-11-24 · runs, prints `6` · was check-clean invalid wasm · clause 1 · `vl check` rc 0 · fixed in emit_plan_null.vl: `coalArmOf`'s fused `popOr` (`coalPopOrFits`) and `listGetOr` arms now leave a `??` stored as a union box (`exprUnion`) to the general arms · pins: `tests/cases/lists/pop-get-or-result-rep-<i32|f64|i64|f32|boolean|atom>.vl` and `pop-or-call-default-once.vl` · found by verifier V2 on lane IR-D1's PR2 (#9898), legacy's arm · filed 2026-11-24 against master `4a0d6ba55`, pre-existing**

Repro:

    function go(av: i32[], bv: i32[]) {
      const r = av.pop() ?? bv.get(1)
      print(r ?? -1)
    }
    go([], [5, 6, 7])
    // vl check: rc 0.  vl run: invalid module inside `go`: expected i32, found (ref $4); $4 is `union box`

Want:

    6

#### Mechanism

`coalArmOf` sends `xs.pop() ?? d` and `xs.get(i) ?? d` over a scalar list to legacy's fused
checked read, which yields the element's scalar or the default in its place. For an `f32` or `i64`
list it asked that the `??` result be the element's prim; for an `i32` list (both arms) and an
`f64` list (the `.get` arm) it asked nothing, so a result stored as a union box (kept nullable, or
joined with a string) wrote the default's box where the element's scalar is expected.
