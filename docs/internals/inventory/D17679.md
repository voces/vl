### D17679 — an empty list delivered to a generic's `V[][] | string` parameter from inside a function traps at the `is f64[][]` test

**open · now a loud emit reject · clause 2 · `the compiler cannot yet lower this statement (box ladder)` · an I8 holdout (`scripts/ir-i8-census/holdouts.tsv`)**

Before I8: trap after load · clause 1 · the in-function face of [D15763](D15763.md), whose top-level spelling prints `1` · found by COV-IS while picking a `box ladder` witness · filed 2026-11-26 against master `2dd28397e`

Repro:

    function probe<V>(v: V[][] | string) {
      if v is f64[][] { return 1 }
      return 0
    }
    function pr() { return probe([]) }
    print(pr())
    // vl check: rc 0.  vl run: wasm trap, cast failure in `probe` (with VL_IR=0 too)

Want:

    1

#### Mechanism

The box plan's nested-list rung (`holeBoxPlanOf`, `compiler/emit_plan_union.vl`) builds the `[]`
only where its own ref slot, `arrLitRefSlotAtTy(literal, fnIx)`, is the union's one nested-list
arm, `unionNestedArrayArmSlot`. Inside `pr` the literal's slot, keyed by `pr`'s frame, is not that
arm, so the plan falls to the ladder: the guard that turned the trap into this refusal. Building
the literal at the union's nested arm instead (`armLit` at that slot) traps again, because the
`is f64[][]` in `probe`'s instance reads the list-arm slot of that instance's `V`, which is
neither of the two.

The missing fact is the list-arm slot of the callee instance's parameter union at this call: the
slot `probe<V>`, instantiated at `pr`'s call, reads `V[]` at, keyed per call (the per-call
instance keying of #10610). With it, the box builds the empty list at that slot under that arm's
tag, and the test reads the same arm.
