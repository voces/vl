### D17679 — an empty list delivered to a generic's `V[][] | string` parameter from inside a function traps at the `is f64[][]` test

**closed 2026-11-28 — the in-function face takes the top-level delivery: an open argument the frame's own key does not type reads at the instance its callee reaches (`monoArgInstFe`, recorded for a call in any frame), so the `[]` is built at the union's nested-list arm · the I8 holdout leaves the list · closed by COV-CALL**

Before I8: trap after load · clause 1 · the in-function face of [D15763](D15763.md), whose top-level spelling prints `1` · found by COV-IS while picking a `box ladder` witness · filed 2026-11-26 against master `2dd28397e`

Repro:

    function probe<V>(v: V[][] | string) {
      if v is f64[][] { return 1 }
      return 0
    }
    function pr() { return probe([]) }
    print(pr())
    // was: vl check rc 0, then a wasm trap (cast failure in `probe`); then the `box ladder` refusal

Want:

    1

#### Mechanism

Closed (COV-CALL, 2026-11-28). The frame lost the reader, not a slot: `monoInstantiate`
(emit_mono.vl) recorded an open argument's callee instance (`monoArgInstFe`) only for a call at
module scope, and `elabNodeTyAt` (emit_elab.vl) read it only for `fnIx` -1. Inside `pr` the
literal's type was then -1 (`arrLitTyAt`), so its slot was not the union's nested arm and the box
plan fell to the ladder. Both now record and read it for a call in any frame, wherever the frame's
own key does not type the argument; no frame-specific rung. Witnesses: `named/d17679_*` (in a
function, in a nested one, in a lambda, in an instanced and a generic caller).

#### Mechanism at filing

The box plan's nested-list rung (`holeBoxPlanOf`, `compiler/emit_plan_union.vl`) builds the `[]`
only where its own ref slot, `arrLitRefSlotAtTy(literal, fnIx)`, is the union's one nested-list
arm, `unionNestedArrayArmSlot`. Inside `pr` the literal's slot, keyed by `pr`'s frame, is not that
arm, so the plan falls to the ladder: the guard that turned the trap into this refusal. Building
the literal at the union's nested arm instead (`armLit` at that slot) traps again, because the
`is f64[][]` in `probe`'s instance reads the list-arm slot of that instance's `V`, which is
neither of the two.

The missing fact is the list-arm slot of the callee instance's parameter union at this call: the
slot `probe<V>`, instantiated at `pr`'s call, reads `V[]` at, keyed per call (the per-call
instance keying of #10610). With it, the box builds the empty list at that slot under that arm's
tag, and the test reads the same arm.

Trace (I8-PREP, 2026-11-28, routed to COV-CALL; nothing landed). Instrumented at
`holeBoxPlanOf`'s nested-list rung: in `pr`'s frame the union is `i32[][] | string` (`V`
defaulted to `i32`), its nested arm is slot 1 (`unionNestedArrayArmSlot`), and the literal's own
slot (`arrLitRefSlotAtTy`) is -1, so the rung falls to the ladder; under it `arrLitTyAt` /
`litRepTyAt` give the literal no type at all in `pr`. Two places close an open-typed argument
only for a module-scope call: `monoInstantiate` records `monoArgInstFe` only when `ctx < 0`, and
`litRepTyAt`'s "parameter its call closes" rung `elabArgTyAt(ix, k)` returns -1 for every `k < 0`,
so the root key (-1, which a function that is no instance, like `pr`, also reads under) never
reaches `elabCallInstFrom`. Widening either (recording the arguments in any frame that is no
instance, or letting `elabArgTyAt` take the root key) did not move the refusal; with the
Mechanism above (the instance's `is f64[][]` reads a third slot), the fix is the per-call
instance keying of #10610.
