### D2394 — a closure reassigning a local `(i32 | f64)[]` from a list literal is invalid wasm inside the closure

**check-clean invalid wasm · clause 1 · pre-existing on master `3ab3c402f` · filed 2026-09-25
against `3ab3c402f`, found reviewing [D2387](D2387.md)/[D2388](D2388.md) (#3143)**

Repro:

    function f(): string {
      let c: (i32 | f64)[] = [1, 2.5]
      const k = () => { c = [3.5, 4] }
      k()
      "\{c.length}"
    }
    print(f())
    // vl check: rc 0.  vl run: invalid module inside `k`: type mismatch: expected (ref null $type), found (ref $type)

#### Mechanism

The closure's store of a fresh list literal into the boxed union-element list is emitted with a
rep the cell does not hold. The literal is the ingredient: the same list delivered through a
`const d: (i32 | f64)[]` binding runs, and so does the assignment outside a closure. Not yet
localised further.

#### Ablation

| ingredient removed | outcome | needed? |
| --- | --- | --- |
| the closure (`c = [3.5, 4]` inline) | prints `2` | **yes** |
| the list literal (`c = d`, `const d: (i32 \| f64)[]`) | prints `2` | **yes** |
| the mixed literal (`[3.5, 4.5]`) | still invalid wasm | no |
| the f64 member (`(i32 \| string)[]`, `c = ["b", 4]`) | prints `2` | **yes** |
| a second level of nesting (`(i32 \| f64)[][]`, `c = [[3.5, 4]]`) | still invalid wasm | no |
| the function frame (module scope) | still invalid wasm, inside `k$m0` | no |
