### D14910 — a generic's `const l = [x]` has an `i32` cell kind while its instance holds a list

**runs today and must keep running · 4 name reads in 2 files, graded on the emitted local · filed 2026-11-01 against master `6850065c`**

Repro:

    function f<T>(x: T) {
      const l = [x]
      for e in [l[0]] { print(e) }
    }
    const t: boolean | null = true
    f(t)
    const i: i32 = 1
    f(i)

Want:

    true
    1

#### Mechanism

`letCellKind` answers `i32` for `l` when asked from the instance's frame after monomorphize,
while the instance `$f` holds `l` as `(local $1 (ref $4))`, a list. The storage column
(`readRepOf`) reads the cell kind, so it names no list here, and `exprListRepOf` falls back to
its type ladder, which answers `list`; the program is right only because that ladder answers.
Deleting the ladder's name rungs would move these reads onto the wrong cell kind, so this row
must close before that deletion.

#### Ablation

Not yet ablated. Measured: the name-read shadow on master `6850065c` finds these 4 reads, and
only these, where the cell kind is `i32` after monomorphize and the ladder names a list; the
emitted `$f` and `$g` were read with `wasm-dis`.
