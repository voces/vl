### D3483 — an object- or array-pattern assignment `{ a: a } = o` is check-clean and refused at emit as "not a simple name"

**loud emit reject · clause 2, the checker owes the refusal · open · VL has no destructuring assignment · found 2026-10-03 · filed against master `e5ff25ff9`**

Repro:

    type P = { a: i32, b: i32 }
    function f(o: P): i32 { let a = 0; let b = 0; { a: a, b: b } = o; a + b }
    print(f({ a: 1, b: 2 }))
    // vl check: rc 0.  vl run: `emitProgram: assignment target is not a simple name`

#### Mechanism

The parser accepts an object literal (or array literal) on the left of `=`, the checker types the
assignment without asking what the target is, and `emitAssign` matches the target against
`Ident` / `Index` / `Member` only, falling to its floor. Whether VL ever grows destructuring is a
language decision; today there is none, so the refusal belongs at `vl check` with a sentence that
says so, not at emit with a mechanism name. The same shape as D1089 (a parenthesised target),
except there the target WAS a simple name and the fix was to run; here no program is owed.

#### Ablation

| ingredient changed | outcome | needed? |
| --- | --- | --- |
| one field only (`{ a: a } = o`) | same emit refusal | no |
| shorthand (`{ a, b } = o`) | same emit refusal | no |
| an array pattern (`[a] = o` over `i32[]`) | same emit refusal | no: the family is any literal target |
| the annotation on `f` | irrelevant, same refusal | no |

#### Grading list

The three spellings above must all end at the same `vl check` refusal, and `(a) = 5` (D1089) and
`a = o.a` must keep running.
