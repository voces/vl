### D2639 — `m[k] = null` into a map whose value is not nullable is checked against the read type `V | null`

**loud emit reject · clause 2 (a module that failed to validate at `a2d2ca88f`, loud since `979323f83`) ·
pre-existing on master · found by the D2506 grid's `mapidx × global written in a function ×
earlier write` cells · filed 2026-09-26 against master `979323f83`**

Repro:

    const c: {[string]: i32} = Map()
    function w() {
      c["n"] = null
    }
    w()
    print(c.has("n"))
    // vl check: rc 0.  vl build: emitProgram: bare null needs a struct-typed context

#### Mechanism

The `=` arm checks an index store against the TARGET's read type, and a map read is `V | null`
(a miss), so `null` is assignable into every map. `.set(k, null)` checks against the value slot
`V` and refuses (`set: expected i32, got null`), so the two write spellings disagree. The emitter
then has no rep for the `null` in a scalar or `string` slot and refuses; at `a2d2ca88f` the
store from inside a function into a module global built a `nullref` into an `i32` slot, invalid
wasm. A record value slot is a nullable ref at the wasm level, so that spelling RUNS today and
stores a `null` the type says cannot be there.

**Ruling asked:** is `m[k] = null` on a map whose value excludes `null` a type error, as
`.set(k, null)` is? Recommendation: yes — check the store against the value slot `V`, the rule
`.set` already applies. The price is every program that runs today by storing `null` into a
record-valued map, which the type already forbids.

#### Ablation

| ingredient removed | outcome | needed? |
| --- | --- | --- |
| the store moved out of `w` to module scope | still refuses | no |
| `c["n"] = null` spelled `c.set("n", null)` | check refuses `set: expected i32, got null` | **yes** — the index spelling |
| the value type `i32` replaced by a record `C` | runs, prints `true` | **yes** — a value slot with no null |
| `c`'s annotation removed, `c["v"] = 4` written first | still refuses | no |

#### Grading list

* `type C = { a: i32 }`, `const c: {[string]: C} = Map()` then `c["n"] = null` (runs today;
  refused under the recommendation), and the same with `{[string]: string}`.
* The D2506 grid's `mapidx × earlier` inferred cells (the scalar and string values refuse, the
  record and union values run).
