### D15230 — a `??` record-literal default for a read of a map whose values are built wider is check-clean invalid wasm

**check-clean invalid wasm · `vl check` rc 0 · clause 1 · open, target `4` · found grading [D15188](D15188.md) · filed 2026-11-04 against master `dc27d0a9` · handed to the destringify lane**

Repro:

    type J = { f: i32 | null }
    function mk() { { f: 4 } }
    const m = Map()
    m.set("a", mk())
    const wm: {[string]: J} = Map()
    wm.set("a", mk())
    const b = m.get("a") ?? { f: 1 }
    print(b.f)

Want:

    4

#### Mechanism

`mk`'s result is built at `J` (the `wm.set` delivery widens it), so `m`'s values are stored at
`J`'s row. The `??` default `{ f: 1 }` is built at its own `{f: i32}`, and the join of the two
arms does not validate. `recCoalesceLitBuilt` builds such a default at the read's record only
where the whole `??` is handed to a parameter that takes the rep.

#### Ablation

| ingredient removed | outcome | needed? |
| --- | --- | --- |
| the widening `wm` (no `J` delivery) | runs | **yes** |
| the `??` literal default (`m.get("a")?.f ?? 0`) | runs | **yes** |
| `.get` (index read `m["a"] ?? { f: 1 }`) | still invalid wasm | no |
