### D2508 — a `for` over an empty list literal does not bind its loop variable, so a body that reads it is refused

**loud check reject · filed 2026-09-25 against master `d29a9d220`**

Repro:

    for x in [] { print(x) }
    print("done")
    // vl check: undeclared identifier 'x'.  Should run the body zero times and print `done`.

#### Mechanism

Not yet located. The element type of `[]` is an empty hole with nothing to pin it, and the
for-in arm appears to skip binding the loop variable when the iterable's element type is
unknown, rather than binding it at a hole (or at `never`, since the body cannot run).

#### Ablation

| ingredient removed | outcome | needed? |
| --- | --- | --- |
| the body's read of `x` (`print(1)`) | runs, prints `done` | **yes** |
| the literal (`const e: i32[] = []; for x in e`) | runs, prints `done` | **yes** |

#### Grading list

`for x, i in [] { print(i) }` (the second binding), and `for x in [] { const y: i32 = x }` —
which type the body sees `x` at is part of the fix.
