### D2508 — a `for` over an empty list literal does not bind its loop variable, so a body that reads it is refused

**closed · runs, prints `done` · was loud check reject · filed 2026-09-25 against master `d29a9d220` · closed 2026-11-14 on master `495c1ff80`: a list literal iterated in place takes the read-only container default, as an un-annotated binding nothing writes does (`defaultReadOnlyContainer`, `checkForInNode`, check_statements.vl) · fixture `loops/for-in-empty-list-literal.vl` · neighbours filed open: [D16272](D16272.md) (a call's empty list), [D16273](D16273.md) (an empty literal inside one)**

Repro:

    for x in [] { print(x) }
    print("done")
    // vl check: undeclared identifier 'x'.  Should run the body zero times and print `done`.

Want:

    done

#### Mechanism

The element type of `[]` is a hole (-1) nothing pins, and `declareDecl` at -1 binds nothing,
so the body's read of `x` is undeclared. An un-annotated binding of `[]` that nothing writes
takes the read-only default (`i32`) at its declaration; a literal iterated in place is such a
container and took none.

#### Ablation

| ingredient removed | outcome | needed? |
| --- | --- | --- |
| the body's read of `x` (`print(1)`) | loud emit reject, `unsupported for-in iterable` (before this close) | no |
| the literal (`const e: i32[] = []; for x in e`) | runs, prints `done` | **yes** |

#### Grading list

`for x, i in [] { print(i) }` (the second binding), and `for x in [] { const y: i32 = x }` —
which type the body sees `x` at is part of the fix.
