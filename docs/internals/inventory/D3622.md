### D3622 — an `as` cast over a masked or shifted integer was graded by its operand's TYPE, so `(v & 255) as u8` owed a null it can never produce

**closed 2026-10-04 — the witness prints `112` · was loud check reject (`as u8` propagates null out of the enclosing function) · extends D3588's constant rule with three bounds read off the operand's shape · sunpa SP-035 · fixtures `tests/cases/numerics/as-cast-bounded-operand.vl`, `tests/cases/numerics/error-as-cast-unbounded-operand.vl` · filed 2026-10-04 against master `7eeb9e8c3`**

Repro:

    const px: u8[] = []
    let v = 70000
    px.push((v & 255) as u8)
    print(px[0])

Want:

    112

#### Mechanism

`checkCastNode`'s numeric arm asked `numCastCanFail(source type, domain)`, and `i32 → u8` can
fail, so every bare `as u8` of a non-constant owed the enclosing function a `null`, even where
the operand's shape holds it in `0..255`. The close (`castBoundDecide`) asks, after D3588's
constant rule, for the least `b` with the operand in `0 .. 2^b - 1` (`castBoundBits`), and a
cast whose domain holds that range (8 bits for `u8`, 31 for `i32`) becomes the `as%` it then
equals: the type is the target in every mode and the emitter lowers the wrap with no range test.
The rewrite is permanent, so every rule must hold at both integer widths. The rules, each sound
by two's complement alone:

* a constant in `0 .. 2^31 - 1` (non-negative at both widths) is below `2^bitlen`; a radix
  pattern counts only as a lone literal, since a tree over one is read at its use's width;
* `a & c` is in `0 .. c` when either side is so bounded — a non-negative operand clears the sign
  bit and can only clear more, so `(x & 0xFF) & y` is bounded whatever `y` is;
* `a >>> k` with a literal `k` in `1 .. 63` is below `2^(64-k)`. No rule reads the operand's
  width, because an inferred one can still change after the cast is decided: a `let` later
  stored an `i64`, a global retyped by a function, a type parameter pinned at both widths, an
  un-annotated lambda parameter. An `i32` shift is bounded tighter (by `2^(32-k)`, or at a pin
  where the count is taken modulo 32, by the same `2^(64-k)`), so `x >>> 24` reaches `u8` only
  through a mask (`(x >>> 24) & 0xFF`) and `x >>> 56` over an `i64` reaches it alone;
* `a % c` over a bounded `a` stays in `0 .. a` (the remainder takes the dividend's sign and is no
  larger), and below `c` when `c` is a positive constant.

A negative mask, a mask read from a variable, `|`, `>>`, and `%` over an operand that may be
negative are not rules, so those casts stay fallible. The fallible-cast refusal's `as%` note now
reads "or `as%` to keep its low bits", and is offered only for an integer operand and an
integer target (a float operand, a union and a non-number pin cannot take `as%`).

side, `0xFFFFFFFF`, `-1`, `-256`, `(0 - 1)`, a variable mask, a literal-const mask, `(x & 0xFF) &

target × binding, argument, return, record field, element push, lambda, module global, `as!` and
`as?`, six runtime values each including negatives — graded every cell against Python's
two's-complement value: 0 mismatches. Against master: 406 cells check reject → runs, 0 runs lost.

decided; review of the first candidate (which bounded `>>>` at the operand's width as first
checked) found `let a = 5; a = 1099511627776; (a >>> 24) as? u8` printing `0` where master
prints `null`. A second, 432-cell grid holds those spellings — a `let` retyped by a store, a
