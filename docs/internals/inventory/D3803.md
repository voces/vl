#### Mechanism

D3767 made a local passed as `unit`'s `fallback` a field use when the call takes `unit`'s
result twin, but recognised that only when the call's own result was read by a `struct.get`
or set into a field-only local. The plan already gives the result twin to a producer call
whose result is an argument of a field-only parameter (`plan_context` puts it in `r_calls`)
and to one that is an arm of a merge held as fields (`take_merge`), so the analysis now
accepts those two uses too: `field_use` on the call, and `arm_held`, the merge-arm test the
local's own arm case already used, lifted into one closure both read.
