### D15032 — a lambda that captures an instance's parameter, written to a slot of a generic's value in a generic body called at two types, is check-clean invalid wasm

**check-clean invalid wasm · clause 1 · `vl check` rc 0, `vl run`: `the emitted module failed to validate inside w$1: type mismatch: expected i32, found (ref $2)` · found closing D12212 (its grading list's capturing lambda) · filed 2026-11-02 against master `4f6f62f6d`**

Repro:

    function id<U>(x: U): U { x }
    const fs = [id]
    function w<T>(t: T) {
      fs[0] = (x) => {
        print(t)
        return x + x
      }
      print(fs[0](2))
      print(t)
    }
    w(1)
    w("s")

Want:

    1
    4
    1
    s
    4
    s

#### Mechanism

Not probed. The lambda captures `t`, whose type is the instance's `T`, and `w$1` (`T = string`)
builds a capture or a call that reads the `string` where an `i32` is expected. D12212 was the
same program with `id`'s parameter named `T`; with that name capture closed, the two spellings
now fail the same way (one trapped before).
