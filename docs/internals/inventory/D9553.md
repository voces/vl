### D9553 — a returned list of un-annotated functions handed to an un-annotated parameter, beside a second read of it at another type, has no argument type

**closed 2026-10-22 by lane-D9553 · runs, prints `6` `2.5` · was loud emit reject, `monomorphize: unsupported argument type for `a``, no position, `vl check` rc 0 · clause 2 · closed by asking for a copy of the called function per pin wherever a call's result is left open because its returned literal's slot takes two pins, the argument included (`monoAskSplitRetCopies` from `monoCloseRetFnTy`, emit_mono.vl), so each call reads its own copy · fixture `closures/hole-fn-list-returned-read-at-two-types.vl` · with [D9601](D9601.md) and [D9602](D9602.md) closed, [D9600](D9600.md) left open · found closing [D9504](D9504.md) · filed 2026-10-22 against master `6b307f6ac`**

Repro:

    function inc(a) { return a + 1 }
    function dbl(a) { return a * 2 }
    function deliver() { return [inc, dbl] }
    function take(a) { print(a.map((f) => f(3))[1]) }
    take(deliver())
    const u = deliver()
    print(u.map((f) => f(1.25))[1])
    // vl check rc 0.  vl run: emit error: emitProgram: monomorphize: unsupported argument type for `a` in a call to `take`

Want:

    6
    2.5

#### Mechanism

Traced, and the close confirmed it. The call handed to `take` is typed at what `deliver` returns only while the returned
literal's element slot takes one pin (`monoCloseRetFnTy`/`monoRetSlotsSplit`, emit_mono.vl); with
a second read at `f64` the slot takes two, the literal stays open, and `take`'s instance is
minted at an open argument. [D9450](D9450.md)'s copy of `deliver` per pin is asked only for a
binding or an element read at the pin, not for a call delivered as an argument.
