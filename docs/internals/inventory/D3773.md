### D3773 — `vl check` sorts a module graph's diagnostics by line alone, so files interleave and warnings bury an error

**closed, now a loud check reject listed errors first, module by module (lane DX) · filed 2026-10-06 against master `e2443d6b2`**

Repro:

    // file: sizes.vl
    export function width(): i32 { return "wide" }
    // file: entry.vl
    import { width } from "./sizes"
    function h() { return nope }
    print(width())
    print(h())
    // master: sizes.vl:1 printed before entry.vl:2, between whatever other files' lines 1
    // and 2 hold; in sunpa the one error sat after four unused-import warnings in game.vl

#### Mechanism

`cliDiagLess` (cli.vl) compared `(line, col)` and nothing else, though the report for a module
graph carries every module's diagnostics in one list. Line 95 of `obstacles.vl` sorted between
lines 83 and 172 of `game.vl`, and warnings, which outnumbered errors 17 to 1 in sunpa's report,
sorted ahead of an error on a later line. The order is now errors first, then module index, then
line and column. The LSP publishes per document and the editor orders them, so only the CLI had
this.

#### Ablation

| report | master order | fixed order |
| --- | --- | --- |
| sunpa, `groundHeight` import removed | 4 warnings, the error, 12 warnings | the error, 17 warnings |
| two independent errors in two files | by line across files | by file, then line |

#### Grading list

`tests/cases/modules/err-two-independent-errors/`. The check-reject fixtures grade the set of
messages, not their order; the CLI order was read by hand on sunpa.
