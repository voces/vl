#### Mechanism

The cell of an un-annotated `let` inside a function comes from the local ladder, whose
`letBindRepClaims` rung reads the binding's rep off its type. A module global's cell comes from
`globalCellKindGo`, a separate ladder with no such rung, which falls back to `globalKind`'s
guess from the initializer. The two answer different kinds for the same type. Adding the
local's rung to the global ladder, just before `globalKind`, gives the global above the local's
`boolean | null` kind, which the global storage paths do not hold: the module fails to validate
(`expected i32, found (ref null $type)`). The same happens in the other 18 files of the
ablation. The fix is one producer of a binding's cell kind that both scopes read, not a rung
added to either ladder.
