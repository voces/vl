Repro:

    function id<T>(x: T): T { x }
    function inc(x: i32): i32 { x + 1 }
    function main() {
      const xs = []
      xs.push(id)
      const ys = [...xs]
      ys[0] = inc
      print(ys[0](2))
      print(xs[0](2))
      print(xs[0]("s"))
    }
    main()
    // vl run: type error: cannot assign (i32) => i32 to (string) => string (the callee's body at the call's argument types)

Want:

    3
    2
    s

#### Mechanism

The write of `inc` into a list whose element is the generic's own `(T) => T` is a deferred
constraint row (`letCstr` for an index write, `bmCstr` for a `push`/`set`), re-validated at
every later call under that call's type-variable bindings. Type variables bind by name, so
any call binding `id`'s `T` adjudicates it: here `xs[0]("s")`, through the other list, and
equally `const f = id; f("s")` or a plain `id("s")`. It is not about the spread or about
`main`; the lines at module scope ran only because no call there bound `T` while the row
was live.

The close skips the row at a call that cannot reach the written container: the receiver is a
`let`/`const` binding whose every read writes into it, calls one of its elements, binds a
`.get` that is only called or compared with `null`, reads its length, or is handed to a
top-level function that only writes into it, and the call is not one of those element calls.
A call through the written container (`ys[1]("s")`), a loop over it, an alias of it, or an
alias of its `.get` still refuses.
