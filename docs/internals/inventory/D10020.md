### D10020 — a pushed list spread into a copy the body of a function then writes with a non-generic is typed at the write by the checker

**loud check reject · `cannot assign (i32) => i32 to (string) => string (the callee's body at the call's argument types)` · clause 2 · CAPABILITY: the same lines at module scope print `3`, `2`, `s` since [D9595](D9595.md) · found closing [D9595](D9595.md) · present on master `00cbfe00b` · filed 2026-10-22 against master `00cbfe00b`**

Repro:

    function id<T>(x: T): T { x }
    function inc(x: i32): i32 { x + 1 }
    function main() {
      const xs = []
      xs.push(id)
      const ys = [...xs]
      ys[0] = inc
      print(ys[0](2))
      print(xs[0](2))
      print(xs[0]("s"))
    }
    main()
    // vl run: type error: cannot assign (i32) => i32 to (string) => string (the callee's body at the call's argument types)

Want:

    3
    2
    s

#### Mechanism

Not traced. The refusal is the checker's, at the call `main()`: the body is re-checked at its
call, where the un-annotated `xs` takes its element type from its last read, `xs[0]("s")`, and
the spread copies that type into `ys`, so the write of `inc` no longer fits. At module scope
the same lines reach the emitter, where the flow pass keeps the two lists apart. These are the
`fn_body` and `local_assign` cells of matrix `fn-value-generic-spread-copy-written-open`.

#### Ablation

| ingredient removed | outcome | needed? |
| --- | --- | --- |
| the enclosing `main` (lines at module scope) | runs, `3`, `2`, `s` | **yes** |
| the write `ys[0] = inc` | runs | **yes** |
