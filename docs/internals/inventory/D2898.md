### D2898 — an un-annotated list-literal local of a hole-typed value builds an `i32` list at a union or list pin

**closed 2026-09-27 — the filed repro prints `fs` · closed by annotating such a local per instance at the list its pin names · found working [D2854](D2854.md) (the `twice`/`elem` cells of this lane's grid) · the same on master `089c6ff56` · filed 2026-09-27 against master `089c6ff56`**

Repro:

    function mk(x) {
      const r = x
      const xs = [r]
      return xs[0]
    }
    const vfs: f64 | string = "fs"
    const w0 = mk(vfs)
    if w0 is f64 { print(w0 / 2.0) } else { print(w0) }
    // master: vl check rc 0.  vl run: invalid module inside `mk` — expected i32, found (ref $type)

Want:

    fs

#### Mechanism

The local `xs` takes its rep from the literal's recorded type, which in the template is the
hole's variable wrapped in a list, and no instance binding substitutes a hole; the build fell to
the scalar `i32` list and stored the union's box into it. `monoCloneBody` now synthesizes the
annotation (`monoHoleListLitAnn`) from the literal's type read at the instance's holes, where
the element is a value union or a list. A scalar element already built its own list and is
left alone; a record element is the loud `struct array elements are not supported` on both
seeds; a `string | null` element is [D2899](D2899.md).
