### D2984 — an interpolated element of a `<T>` list at a literal-union pin renders its atom id

**closed 2026-09-28 — the filed repro prints `<b>` · was check-clean silently wrong, clause 1, the same on master `59cf3b639` · closed in the monomorphizer: a call or node an explicit instance rebuilds from an interpolation hole was no longer marked as one (`tplHole`), so the hole's atom took the `i32` render; `monoKeepTplHole` carries the mark to the rebuilt node · fixture `tests/cases/generics/interp-generic-list-element-at-literal-union-pin.vl` · filed 2026-09-28 against master `4dc94bd23`**

Repro:

    type AB = "a" | "b"
    function f<T>(x: T[]) {
      print("<\{x[0]}>")
    }
    const v: AB[] = ["b"]
    f(v)
    // vl check: rc 0.  vl run: prints `<0>`

Want:

    <b>

#### Mechanism

The close: the interpolation's atom test reads the `tplHole` mark, which a rebuilt node lost.
Before it, not localised. The interpolation's element conversion reads the explicit instance's element as an
`i32` rather than the atom. The same read in `print(x[0])` prints `b`, and so does every
neighbouring spelling below, so the interpolation's own atom test is the one that misses the pin.

#### Ablation

| ingredient changed | outcome | needed? |
| --- | --- | --- |
| the hole in place of `<T>` (`function f(x)`) | prints `<b>` | **yes** |
| a scalar `f<T>(x: T)` interpolating `x` | prints `<b>` | **yes** |
| `const y = x[0]` then `"<\{y}>"` | prints `<b>` | **yes** |
| `print(x[0])` | prints `b` | **yes** |

#### Grading list

The LU2 grid's `E_e3_g` and `S_s5_g` rows (`scratchpad/LU2/gen.py`). A nullable pin is a check
reject in both (interpolating a nullable value), which is the design.
