### D1968 — an un-annotated NESTED named function whose recursion needs the binding-group fixpoint is refused: only top-level functions are re-inferred until their return settles

**loud check reject · `operator '+' is not defined for _ | null and i32`, clause 2 (the annotated spelling and the top-level spelling both run) · filed 2026-09-22 against master `0eb92ecea` plus [D1966](D1966.md)'s close, found grading it**

Repro:

    function main() {
      function m(k: i32) {
        if (k <= 0) { return null }
        const r = m(k - 1)
        if (r == null) { return k }
        return r + k
      }
      print(m(3) ?? -1)
    }
    main()
    // vl check: operator '+' is not defined for _ | null and i32
    // annotated `: i32 | null`, or `m` at top level: prints 6

#### Mechanism

A self-call inside an un-annotated function resolves to its PENDING return: `checkCallOnFuncTy`
hands back `inferObserved`, the join of the returns seen so far. At top level that provisional
answer is corrected by the suppressed pre-pass, which re-infers every member of `topUnannotFns`
until the returns stop moving. A nested function is never in that set, so it is checked once: at
`m(k - 1)` only `return null` has been seen, `r` types as `null`, and `r + k` after the `== null`
guard is refused. [D1966](D1966.md)'s close made a nested function bind its pending signature
before its body, which is what lets base-case-first recursion (`fact`, a `null`-then-value
chain) run; the fixpoint is the part it does not have.

#### Ablation

| ingredient removed | outcome | needed? |
| --- | --- | --- |
| nesting (`m` moved to top level) | runs, prints `6` | **yes** |
| the return annotation added (`: i32 \| null`) | runs, prints `6` | **yes** (inference) |
| the use of the call's result (`return m(k - 1)` directly) | runs | **yes** |
| `null` base case → `return 0` (an `i32` chain) | runs, prints `6` | **yes** |

#### Grading list

The call made through a lambda in the body (`const g = (q: i32) => m(q)`, then `1 + g(k - 1)`),
which reports `cannot infer a return type for ''` nested and prints `3` at top level. Not this
row: two nested functions calling each other (`ev` / `od`) is `undeclared identifier` for the
LATER one even when both are annotated, because a nested declaration is not hoisted in its block —
a scoping question, not an inference one, and a ruling before it is a fix.
