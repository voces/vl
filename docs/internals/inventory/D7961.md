### D7961 — an un-annotated `??` over a hole's nullable-number map read with a nullable-number default builds invalid wasm

**closed 2026-10-20 by lane L6b · runs, prints `5` · was check-clean invalid wasm · clause 1 · the hole instance boxed a result that was already the `i32 | null` box, and a re-associated chain's minted inner link carried no type, so its `if` took an `i32` block type; `coalHoleNulNumRead` now keeps the box as the join's own rep, and the lowering types the desugared `if` at the box · pin: `tests/cases/literal-unions/coalesce-map-read-joins-atom.vl` · filed 2026-10-20 against master `aec7a5332`**

Repro:

    type R = { a: {[i32]: i32 | null} }
    function mk(): R {
      const a: {[i32]: i32 | null} = Map()
      a[3] = 2
      a[4] = 5
      { a: a }
    }
    function use(p) { print(p.a[9] ?? p.a[4] ?? p.a[3]) }
    use(mk())
    // vl check: rc 0.  vl run: invalid module, expected i32, found (ref $N) union box

Want:

    5

#### Mechanism

The map's value type is already the nullable number's box, so `m[k] ?? d` with a nullable
number default is that box, with the read as its `then` arm. In the hole instance the
`??` node is an unbound type variable, so `exprUnionBin`'s mv-slot rung boxed it again,
and the consumer received a box where it expected the payload. The chain is not the
ingredient: the two-link spelling fails the same way.
