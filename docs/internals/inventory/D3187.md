### D3187 — a literal-union atom forwarded through two hole parameters reaches a `string | null` callback parameter unwidened

**closed 2026-11-02 by lane column-G1 · runs, prints `b` · was check-clean invalid wasm (on master `5c9e06b0` `unknown local 5: local index out of bounds` inside `G`; filed as `expected (ref null $type), found i32`) · clause 1 · `emitCallRef` widens an atom argument into a `string` or `string | null` parameter of a function value, and `sigParamTakesAtomStr`, which reserves the widening's scratch frame for that call, counted only `string` and a box, so the widening wrote a local the function never declared; the scan now counts `string | null` too · fixture `tests/cases/literal-unions/atom-forwarded-through-hole-params-to-nullable-string.vl` (two and three hops, a `K | null` value, `null`) · the `fw_p3_vk` and `fw_p3_nl` cells of the HF grid (`ni-work/hf`) · filed 2026-09-29 against master `a6cb22568`**

Repro:

    type K = "a" | "b"
    function G(h, v) {
      return h(v)
    }
    function H(g, w) {
      return G(g, w)
    }
    const s: K = "b"
    print(H((x: string | null) => x, s))
    // vl check: rc 0.  vl run: invalid module inside `G`, expected (ref null $type), found i32

Want:

    b

#### Mechanism

Not localised past the ablation. The direct spelling `G((x: string | null) => x, s)` runs, so
the atom-to-string widening at a hole callee's argument is taken where the argument's own type is
known at the call and not where it arrives through a second hole.

#### Ablation

| ingredient changed | outcome | needed? |
| --- | --- | --- |

| `(x: string) => x` | the same invalid module when filed; runs on master `5c9e06b0` | no |
| `const s: string = "b"` | prints `b` | **yes** (the atom) |
