### D2730 — a record literal in an `if` arm builds its own shape's row, not the destination's, and its union-of-maps field is not retagged

**closed 2026-09-26 — the repro RUNS and prints `1` · was check-clean invalid wasm · 11 of the lane's 13 annotated join cells (binding, argument, `return`, field, list element, capture, `match` arm, local, parameter and global assignment, `else if`) · filed 2026-09-26 against master `90b63b840`**

Repro:

    type A = {[string]: string}
    type B = {[string]: string | null}
    function mkA(): A { const m: A = Map(); m["k"] = "x"; m }
    function uA(): A | B { mkA() }
    type Sx = { f: B | string }
    function g(sel: i32) {
      const sx: Sx = if sel == 0 { { f: uA() } } else { { f: "s" } }
      const v = sx.f
      if v is B { print(v.length) } else { print(v) }
    }
    g(0)

#### Mechanism

Two halves. The `if`'s struct blocktype was read off the then arm (`structIndexOfExpr`), and
`{ f: uA() }` has a row of its own, `{ f: A | B }`, whose field is not the destination's
`B | string` box, so both arms were built as that twin and stored into an `Sx` cell. And the
checker records the map retag (`recordMapUnbox`) through a record literal only when the
delivered node IS the literal, so the arm's `A`-tagged box would have reached the field
unretagged. Closed by building an object-literal arm at the destination row when one is
seeded (`ifExprRefSlot`), seeding a struct cell's row at a local, parameter and global
assignment as its declaration does, and walking the tails of a value `if`, `match` or block
before the list and record arms of `recordMapUnbox`.
