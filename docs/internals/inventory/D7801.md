### D7801 — a multi-root `vl check` banked no target from an importer's check that had a type error, so one error re-checked every module under every root that reached it

**closed 2026-10-20 by lane S5 · runs, prints `2` · no wrong value, a cost row · `wiBankWhole` (compiler/driver.vl) banks a target from a check with type errors when every error is placed in the target's import closure G, and the bank carries those errors and rc 2 · diagnostics byte-identical to master on every graph measured · filed against master `67bf5a0a9`**

Repro:

    // file: lib.vl
    export function f(x: i32): i32 { x + 1 }
    // file: mid.vl
    import { f } from "./lib"
    export function g(x: i32): i32 { f(x) * 2 }
    // file: main.vl
    import { g } from "./mid"
    print(g(0))
    // The cost needs an error: put one in lib.vl's body and `vl check .` re-checks lib and mid
    // under main, then again for mid, then again for lib.

Want:

    2

#### Mechanism

`modCompile` returned 2 on a type error before `wiBankWhole` ran, so no importer's check with
an error banked anything. Every root that reached the error re-checked its whole closure. A
check with type errors now banks target t when:

- every error is placed in a module, and that module is in G(t);
- no message keeps a merge spelling (`#`, `$`), and no two errors share a position, since the
  report orders errors at one position by check order;
- no message names a type declared outside G (`wiDiagNamesOut`; a union renders by an outside
  declaration's name, the mask-4096 witness);
- the clean check's guards pass. The deep-`is` second pass never runs on a check with errors,
  in either check, so its sites do not decline.

An instance of an imported generic reports at the importer's outermost call, so an error an
importer's instance makes is placed outside G and declines the target as `dirty`. A target
whose G holds no error, while the check has errors outside it, still declines `dirty`, and so
does every target of a check holding an error no module places (an unknown type name in a
signature is one).
