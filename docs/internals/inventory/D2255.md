#### Mechanism

`mvListValKind` maps a list-valued map slot's inner element kind to the value list's rep, and
it had no rung for the packed byte list (`rlElemKindTbl` 11), so a `u8[]`-valued map answered
"not a list". Its two build sites, the store (`emitMapSetValExpr`) and the `??` default
(`emitMapValDefault`), then threaded no list kind and a non-empty `[1, 2]` built the default
i32 list into a `(ref null $u8wrap)` vals cell. Every consumer that already had a `u8list` or
`nulu8list` arm downstream of it — `mvNulListValKind`, `letNulMapReadValKind`, the `.values()`
loop variable — was dead for the same reason, which is why the nullable read and the loop
refused loudly. The fix is the rung plus the `u8list` → build kind 10 arm at both build sites.
An empty `[]` ran before: the checker pins its hole to the destination's element (D2209).
