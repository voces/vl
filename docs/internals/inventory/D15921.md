### D15921 — a list a function frame binds from a call's record, of records whose function field holds un-annotated functions returning different types, captured by a closure that calls through it, is refused at emit

**closed 2026-11-12, runs and prints `5.5` · was a loud emit reject, `emitProgram: field access receiver is not a struct`, clause 2 · closed by `capturedRefListSlot` (`emit_classify.vl`) falling back to the capture's env-field slot where the binding's type keys no row · found by w320 beside [D15804](D15804.md) · filed 2026-11-12 against master `22d35fe47`**

Repro:

    function inc0(a) { return a + 1 }
    function half(a) { return a / 2.0 }
    function mk() { return { a: [{ f: inc0 }, { f: half }] } }
    function fr() {
      const c = mk().a
      const f = () => { print(c[0].f(3) + c[1].f(3)) }
      f()
    }
    fr()

Want:

    5.5

#### Mechanism

Traced. The two functions' different results leave the list's type `{f: (_) => _}[]`, which keys
no ref-list row; the frame's local holds the row the list was built at (slot 0). In the frame,
`refListCellSlotOfRead` finds that row through the local (`declaredRefArraySlot`). In the
closure, `c` is a capture, and `capturedRefListSlot` re-derived the slot from the parent
binding's type alone, so it answered -1. The element `c[1]` then had no struct row. The env
field itself is typed from the local's own slot (`captureValStructIdx`, through `letCellSlot`),
so the reader now falls back to that slot (`capturedCompanionSlot`), kind-gated, when the type
keys none.

#### Ablation

| spelling | outcome |
| --- | --- |
| the witness | runs, `5.5` (was a loud emit reject) |
| no closure, `print(c[0].f(3) + c[1].f(3))` in `fr` | runs, `5.5` |
| at module scope, the closure kept | runs, `5.5` |
| one result type, `half(a) { return a * 2 }` | runs, `10` |

With the fix, the witness runs. So do a nested closure, a reassigned `let`, a loop over the
capture (`a ref list's element row does not resolve` before), a returned closure, and an element
bound inside the closure (the same second message before). The fixture is
`tests/cases/closures/frame-list-of-fn-records-of-different-results-captured-by-closure.vl`.
