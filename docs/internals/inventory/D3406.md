**closed · fixture `tests/cases/loops/loop-value-interpolation.vl` · was a loud check reject naming an internal error (`internal: an interpolation hole's renderer was not merged`) · the #3315 review's `k5` · filed and fixed 2026-09-30 against master `8df60e472`**

#### Mechanism

The merge renames every reference to a module-level name, including the interpolation
renderer `$tpl$render`, by walking statements (`modRwStmt`) and, for expressions, `modRwExpr`.
The expression walk routed an `if` and a `match` in value position back to the statement walk,
but not a `while`, `for` or labelled block, which since loop values can stand there too. Their
bodies kept the unrenamed name, and the checker reached the renderer's floor. The expression
walk now routes a loop to the statement walk as it does an `if`. A loop statement was always
walked, so only value-position loops moved.
