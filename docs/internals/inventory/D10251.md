### D10251 — a list literal whose element is a generic read out of a list, handed straight to a generic function, is refused by emit as an internal error

#### Mechanism

The close of [D10204](D10204.md) binds a generic call's type variables from a list-literal
argument after the other arguments when an element is an open function (`argOpenMeetsTyVar`,
check_generic_args.vl). It recognises an element that names a generic, directly or through a
`const`, but not one read out of a list, a field or a call's return, so the literal still binds
`U` to `id`'s own type variable. This is the five un-annotated cells (`return_inferred`,
`struct_field_init`, `array_element`, `map_value`, `map_set`) of the
fn-value-generic-list-literal-arg-* matrices.

#### Ablation

| `run<i32>(...)` | runs, `2` | **yes** |
