### D15000 — a parenthesised radix tree the fold leaves to its use's width, delivered at `i64`, is extended as though it were `i32`

**check-clean invalid wasm · clause 1 · found closing [D14990](D14990.md) · the same on master `a48eddb4d` · filed 2026-11-02 against master `a48eddb4d`**

Repro:

    const w: i64 = (0x7FFFFFFF << 2)
    print(w)
    // vl check: rc 0.  vl run: invalid module in the module's top-level code,
    // "type mismatch: expected i32, found i64"

Want:

    8589934588

#### Mechanism

The tree inside the parentheses is computed at the destination's `i64` (`i64.shl` over two
`i64.const`s), and the delivery then wraps it in `i64.extend_i32_s`: the `Paren` keeps the
`i32` type the first, context-free check gave the tree, while the tree under it was re-typed at
the destination. Unparenthesised, the delivery reads the re-typed root and runs.

#### Ablation

| ingredient changed | outcome | needed? |
| --- | --- | --- |
| no parentheses, `const w: i64 = 0x7FFFFFFF << 2` | prints `8589934588` | **yes** |
| the parentheses inside, `(0x7FFFFFFF << 2) + 0` | prints `8589934588` | **yes** (the root is the `Paren`) |
| `(0x7FFFFFFF * 0x7FFFFFFF)`, `(-1 / 0xFFFFFFFF)` | the same invalid module | no (any kept-whole tree) |
| a destination of `f64` | runs | **yes** |

#### Grading list

The `f64` twin, a parenthesised tree at an `i64` argument, return and field, and a doubled
`((…))`.
