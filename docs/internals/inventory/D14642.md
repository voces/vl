### D14642 — a numeric literal `is` test compares at the literal's lexeme width, not the receiver's

**closed · runs, prints `false`, `false`, `true` · was check-clean invalid wasm, clause 1 · `emitNumLitEq` takes its compare from the receiver's width (`exprScalarWidth`): `i64` compares at `i64`, `i32` at `i32` where the value fits, a float receiver refuses loudly pending [D3689](D3689.md)'s ruling, and any other receiver never holds the literal · fixture `literal-unions/numeric-literal-is-at-receiver-width.vl` · filed 2026-10-28 against master `70326a63e`**

Repro:

    function g<T>(x: T) { x is 2 }
    print(g("s"))
    function w<T>(x: T) { x is 5000000000 }
    print(w(2))
    print(w(5000000000))

Want:

    false
    false
    true

#### Mechanism

`emitNumLitEq` built the literal at the width its lexeme fits (`i32.const` for `2`,
`i64.const` past 2^31) and compared it with the receiver, whatever the receiver's type. A
`string` pin and an `i32` pin tested against a literal past 2^31 each fed the compare a value
of another valtype. The direct spellings are refused at check (`q is 5000000000` over an `i32`
"can never match"); the generic body is legal at its template, so the instance answers.
