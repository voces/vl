### D12100 — a type parameter inferred from a scalar argument, beside a record arm, mints no value box for the scalar

**closed 2026-10-31 — the filed repro RUNS and prints `1` · a composite parameter riding type parameters pins at the type the elaboration gives it at the call (`monoElabCompositeTy`, emit_mono.vl) before `monoPinTyParamComposite` · fixture `tests/cases/generics/composite-param-pins-at-elaboration-type.vl` · was: loud emit reject · filed 2026-10-24 against master `492ea9482`**

Repro:

    type C = {x: i32}

    function g<T>(v: T | C) {
      print(1)
    }

    const n: i32 = 3
    g(n)
    // vl check: rc 0.  vl run: emitProgram: union atom has no value box

Want:

    1

#### Mechanism

The instance's parameter is the union `i32 | C`, a box row with a record arm and a scalar arm.
When `T` is bound by inference from the argument, the scalar arm's value box is never minted
for the instance, and the delivery at the call refuses. Writing the type argument (`g<i32>(n)`)
binds the same `T` and runs, so the gap is in the inferred binding's registration, not the type.
