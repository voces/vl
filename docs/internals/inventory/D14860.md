### D14860 — a closure that ends in a store of a written `let` of generics returns the stored function, which no tagged set can hand back as an id

**loud emit reject · 1 witness, the result-used face of the 10 closure-written binding-fallback cells (`captured-cell-*`, `closure-written-let-*`, `captured-written-let-of-generic-called-at-two-types` under `tests/cases/closures/`) · filed 2026-11-01 against master `70d45e59`**

Repro:

    function inner<U>(u: U) {
      print("I")
      print(u)
    }
    function other<V>(v: V) {
      print("O")
      print(v)
    }
    function main() {
      let k = inner
      const flip = () => {
        k = other
      }
      k(1)
      const g = flip()
      g(true)
      k("s")
    }
    main()
    // vl check: rc 0.  vl run: emit error, `k` holds functions called at more than one argument type

#### Mechanism

`k` is written from a closure, so `elabFnLetTy` keeps its initialiser's type
(`cwLetWrittenInClosure`) and the split plan cannot split a binding whose closure-returned
value is called at a third type. Reading `k` as its set instead (lifting that rule) tags the
set, and `other` in `k = other` becomes a tagged leaf that emits its member id. But the store
is `flip`'s body tail, so `flip` returns it, and `flip`'s result is `other`'s own function
type, not the set: the emitter gives `flip` a closure result and stores the id into it, which
is check-clean invalid wasm. `ftCommit` marks only top-level declarations with
`fnTagRetMark`. The close is a closure whose tail store is a tagged id returning that id
(an i32 result, `fnTagRetMark` for a lambda, and callers reading it as one), or the store's
value re-read as the closure; only then does the closure-written rule come off.
