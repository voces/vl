### D16219 — a wider row forwarded through a generic function to a declared record parameter is refused at the pin

**closed 2026-11-15 · runs, prints `a` · was a loud check reject, clause 2, `an object value of shape … flowing into P drops the field …` at the forwarding call · closed by noting the width candidate at the record-widen pin (`rcwPinWidthNote`, `check_demands.vl`) · found by lane I in L3 PR A · filed 2026-11-15 against master `3d526470a`**

Repro:

    type P = { name: string }
    function show(p: P) { print(p.name) }
    function fwd<T>(t: T) { show(t) }
    const v = { age: 3, name: "a" }
    fwd(v)
    // vl check (before the close): rc 1, the field-dropping refusal at `show(t)`

Want:

    a

#### Mechanism

A delivery whose source is typed at a type parameter, `show(t)` in `fwd<T>`, leaves a
record-widen pin (D2060), which each call of `fwd` re-asks with `T` bound (`validateRcwPins`).
At `fwd(v)`, the pin found `{age, name}` into `P` and refused it, before the width phase could
make `show`'s parameter generic: the pin knew neither the call nor the parameter. The pin now
records the parameter its delivery fills, as (declaration, position), filled by
`callFtyArgAssign` onto the rows its argument's check appended and carried when a pin moves out
to a caller's;
a wider row there is noted as a width candidate (`rcwPinWidthNote`), as at a direct call.
