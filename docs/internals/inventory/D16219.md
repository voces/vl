#### Mechanism

The record-width rewrite notes a parameter as a candidate where a call's argument is checked
(`callFtyArgAssign`) or a member call's receiver is (`ufcsCheckRecvSeam`). A call inside a
generic or hole body is re-asked at the pin (`validateArgCstrs` → `argCstrFitsAt`), which runs
before the width phase, and its constraint row carries the callee's name but not the parameter's
position, so it refuses where it should note the candidate. A2: the parameter-position column on
the row, and the note at the re-ask.
