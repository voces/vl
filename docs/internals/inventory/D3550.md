### D3550 — a message-carrying `__trap__` in a function nothing calls still declares the four print host imports in a plain build

**runs today and must keep running · the defect is the MODULE'S IMPORT LIST, which the grader does not measure: a plain `vl build` of the witness declares `imports.__print_i32__`, `__print_bool__`, `__print_char__` and `__print_str_flush__`, and the same module without the trap declares none · `-O` removes them, but the seed is built plain, so this is what keeps the compiler from importing `std:array` (`std:array.filled` holds such a trap) · found by lane BI (`builtin-methods-to-std.md` prerequisite 4) · filed 2026-10-03 against master `fae55dec2`**

Repro (`vl run` prints nothing and exits 0; `vl build` then `wasm-dis` shows four imports):

    function trapIfNeg(n: i32): i32 {
      if n < 0 { __trap__("negative") }
      n
    }
    export function count(xs: i32[]): i32 { return xs.length }

#### Mechanism

The trap's message is rendered through the print family. Those imports are declared when the
merged program CONTAINS a message-carrying `__trap__`, not when a reachable function calls
one, so an uncalled helper, or an imported module's unused export, puts them in the module.
A module that must load with no host imports (the seed) therefore cannot import any std
module holding such a trap, whichever of its functions it uses. The witness's imports were
read with `./node_modules/.bin/wasm-dis` on a plain `vl build`.

#### Ablation

| ingredient removed | imports in a plain build | needed? |
| --- | --- | --- |
| nothing (the witness) | 4 | — |
| the trapping function | 0 | **yes** |
| the message: `__trap__()` | 0 | **yes** |
| the plain build: `vl build -O` | 0 | **yes** — binaryen drops the unused imports |
| the local helper: `import { indexOf } from "std:array"` and one call of it | 4 | no — `filled`'s trap is enough |
| the same, `-O` | 0 | **yes** |

#### Grading list

`import { indexOf } from "std:array"` with a plain build must declare no import; a REACHABLE
message trap must still declare (and print through) the imports it needs.
