### D17752 — an un-annotated local read from a record field of a lone string-literal type is held as an i32

**check-clean invalid wasm · clause 1 · `vl check` rc 0 · `type mismatch: expected i32, found (ref $0)` (`string`) · 2 cells: `lone-literal-result-of-generic-fn-value`, `struct_field_init` annotated and `struct_field_assign` un-annotated · filed 2026-11-27 against master `2f420604f` by I8-PREP (sibling sweep of the closure matrices)**

Repro:

    type __W = { f: "a" }
    const w: __W = { f: "a" }
    const v = w.f
    print(v + "x")
    // vl check: rc 0.  vl run: the emitted module failed to validate

Want:

    ax

#### Mechanism

Not traced: the local `v` takes the field's lone-literal type and is given an i32 slot (the rep a
lone literal folds to), while the field read pushes the string. `print(v)` on the same local is a
loud emit reject, `the compiler cannot yet lower this statement (print operand rep)`.

#### Ablation

| ingredient removed | outcome | needed? |
| --- | --- | --- |
| the local (`print(w.f + "x")`) | prints `ax` | **yes** |
| the field (`const xs: "a"[] = ["a"]; const v = xs[0]`) | prints `ax` | **yes** |
| the field type widened to `string` or `"a" \| "b"` | prints `ax` | **yes** (a lone literal) |
| `const v: "a" = w.f` annotated | prints `ax` | **yes** |
| a second field `n: i32` | still invalid | no |
| a call result (`const v = k()`, `k(): "a"`) in place of the field | prints `ax` | **yes** |
