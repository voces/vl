### D14303 — `n is Tag` over an inline union with a generic-application member folds false

**closed · runs, prints `4` then `9` · was check-clean silently wrong, the `is Tag` arm skipped · test `tests/cases/generics/union-member-generic-application-is-arm.vl` · filed 2026-10-26 against master `2f9786dae`**

Repro:

    type Box<T> = { v: T }
    type Tag = { t: i32 }
    let n: Box<i32> | Tag = { t: 4 }
    if n is Tag { print(n.t) }
    let o: Box<i32> | null = null
    o = { v: 9 }
    if o != null { print(o.v) }
    // PRINTS 9

Want:

    4
    9

#### Mechanism

The same registration gap as D14300: with no variant box for the inline union, `n` has no
tag for `is Tag` to read, and the arm is skipped. The canon rewrite in D14300 registers the
box. A declared alias naming the same union anywhere in the module registers it too, which
is why the gap needs the inline spelling alone.

#### Ablation

| ingredient removed | outcome | needed? |
| --- | --- | --- |
| the `o` binding and its read | prints nothing | no |
| a declared `type U = Box<i32> \| Tag` added before `n` | prints `4` `9` | **yes** |
| `Box<i32>` replaced by a declared `type Bx = { v: i32 }` | prints `4` `9` | **yes** |

#### Grading list

`alias-union-generic-application-nullable-twin.vl`, the declared-alias spelling with a
nullable record of the arm's shape beside it.
