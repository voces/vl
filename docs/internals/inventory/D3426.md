### D3426 — a 64-bit literal beside a type-parameter operand builds invalid wasm at an `i32` pin

**closed 2026-09-30 — now a loud check reject at the pin (`argument 1: i32 cannot hold the 64-bit operand it meets (the body of `g` computes with it and a 64-bit value)`), the refusal the direct spelling `(x: i32) + 6442450944` owes at its return · a `g<i64>` instance is unchanged · fixture `tests/cases/generics/error-wide-constant-at-i32-pin.vl` · was check-clean invalid wasm · clause 1 · found by the exact-constant lane beside D2712, whose tree folds to this literal · filed 2026-09-30 against master `5e277ab52`**

Repro:

    function g<T>(x: T): T { x + 6442450944 }
    print(g<i32>(0))
    // vl check: rc 0. vl run: invalid module, `type mismatch: expected i32, found i64` inside `g`

#### Mechanism

The body is checked once with `T` open, so `x + 6442450944` records only the operator's own
deferred constraint, which `binOpDefinedFor` answers for `i32 + i64` as the widening it is at a
direct spelling. The instance is then emitted with an `i32` operand and an `i64.const` beside it.
The checker now records a second constraint (`OP_LITFIT`) when an integer literal typed `i64` meets
a type-parameter operand, and the pin refuses a type narrower than 64 bits.
