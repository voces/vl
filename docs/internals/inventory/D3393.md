### D3393 — a record whose list field's element has two spellings is delivered between them as invalid wasm

**check-clean invalid wasm · clause 1 · open · found by the #3314 review's `grid2` (`struct_alias__rec_list_*`, `u_alias__rec_list_*`) · the same on master `4ff12b994` · filed 2026-09-30 against master `4ff12b994`**

Repro:

    type P = { x: i32, y: i32 }
    function F(): { x: i32, y: i32 } { return { x: 1, y: 7 } }
    const s: { f: (() => { x: i32, y: i32 })[] } = { f: [F] }
    const d: { f: (() => P)[] } = s
    print(d.f[0]().y)
    // vl check: rc 0.  vl run: invalid module: type mismatch

Want:

    7

#### Mechanism

Not localised past the ablation. The two record types spell one element type two ways (`P`
against its own field list, or `Circle | Sq` against `Shape`), and the checker accepts the
delivery as the same type. The two holders are built as different struct rows, and the
delivery hands one row where the other is declared. The function in the list is not an
ingredient: a list of the records themselves fails the same way. Neither is the function type's
signature, which is identical on both sides, so this is not the [D3073](D3073.md) adapter's
case.

#### Ablation

| ingredient changed | outcome | needed? |
| --- | --- | --- |
| both holders spell the element `P` | runs, prints `7` | **yes** (two spellings) |
| a bare list, `(() => {x, y})[]` delivered as `(() => P)[]` | runs, prints `7` | **yes** (a record holder) |
| the field holds one function, not a list | runs, prints `7` | **yes** (a list field) |
| `{ f: {x: i32, y: i32}[] }` delivered as `{ f: P[] }`, no function | the same invalid wasm | no |
| `Circle \| Sq` against `Shape` in the function's result | the same invalid wasm | no |
