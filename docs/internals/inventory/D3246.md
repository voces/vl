**closed · owner rulings (B), then B′ + C "for now", 2026-09-29: a literal `let` takes its type from its whole deliveries and its stores within its kind, and a literal `const` is its literal at every read; conflicting uses of a `let` are refused naming both · fixtures `tests/cases/numerics/literal-binding-infers-from-uses.vl`, `literal-binding-conflicting-uses.vl`, `literal-binding-annotation-redundant.vl`, `literal-binding-widened-reads.vl`, `literal-binding-literal-stores.vl`, `literal-binding-part-deliveries.vl`, `literal-binding-generic-argument.vl`, `literal-const-copies.vl`, `literal-const-shadows-function.vl`, `literal-const-default-and-arm-width.vl`, `literal-binding-compound-literal-store.vl`, `tests/cases/inference/hole-guarded-return-union-sum.vl`, `tests/cases/scope/literal-const-read-above-declaration.vl`, `tests/cases/match/const-arm-copied-literal.vl`, `tests/cases/modules/literal-binding-export-own-module/`, `literal-binding-std-constant/`, `literal-binding-export-const-per-use/`, `tests/lsp_wasm_checker_test.ts` (a literal const read hovers per use and stays a reference; a read above the declaration is a reference) · grid `scripts/capability-probes/literal-binding-grid.py`, 594 cells · was a loud check reject (`cannot assign i64 to i32 — s … has no annotation, so its literal defaulted to i32`) · plumb PL-054, PL-056 · filed and fixed 2026-09-29 against master `5182fd822`**

Repro:

    function sum(xs: i64[]) {
      let s = 0
      for x in xs { s += x }
      s
    }
    print(sum([3000000000, 2, 3]))
    const h = 0.5
    function lerp(a: f32): f32 { a * h + 7.0 }
    print(lerp(1.0))
    // was: vl check refused both — `s` defaulted to i32, `h` to f64

Want:

    3000000005
    7.5

#### Mechanism

The checker typed an un-annotated literal binding from its initializer alone, so `s` was `i32`
and the `i64` store into it was refused, however plainly the program meant `i64`. A `let` now
takes its type from its whole deliveries and its stores (a solve over recorded uses, then a
re-check with the type written as its annotation); a `const` is rewritten into its literal at
each read, so `h` is the `f32` 0.5 where an `f32` is wanted.
DECISIONS.md §"A literal binding takes its type from its uses".

| `const h: f32 = 0.5` | runs | **yes** (the missing annotation) |
