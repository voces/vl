### D5590 — an index into a built-in list is charged with every declared index operator's writes

**closed 2026-10-17 — the witness prints `b7` · was a loud check reject, clause 2 · found from eardstap EV-009 · filed 2026-10-17 against master `44ed9635a` · fixture `tests/cases/soundness/builtin-index-keeps-narrowing-beside-user-operator.vl`**

Repro:

    type Box = { kind: "a" | "b" | "c" }
    function "[]="(self: Box, _i: i32, _v: i32) { self.kind = "a" }
    function "[]"(self: Box, i: i32): i32 { if self.kind == "a" { 0 } else { i } }
    type Intent = { kind: "a" | "b" | "c", n: i32 }
    function fill(xs: i32[]) { xs[0] = 7 }
    function act(i: Intent, xs: i32[]): string {
      if i.kind == "a" { return "a" }
      fill(xs)
      match i.kind { "b" => "b\{xs[0]}", "c" => "c" }
    }
    print(act({ kind: "b", n: 1 }, [0]))

Want:

    b7

#### Mechanism

`opSiteDecls` (`check_callee.vl`) answers an index site with no banked operator by falling
back to every declared `"[]"` / `"[]="`, so `xs[0] = 7` on an `i32[]` was charged with
`Box`'s `"[]="` and its write of `self.kind`, and `fill` was judged able to write `i.kind`.
An index whose receiver is already typed as a list, map or string runs the built-in, so it
now dispatches to no declaration. A receiver typed by a type variable still takes the
fallback, since a pin may bind it to a record.
