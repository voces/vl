### D2899 — a list literal of a hole-typed `null` at a `string | null` pin traps on a null reference

**closed 2026-09-27 — the filed repro prints `null` · was check-clean trap after load, clause 1, the same on master `0284dc2a8` · closed by annotating the local at its nullable element list and re-making the literal at that type, and by reading a push receiver's element off the instance's annotation · found working [D2854](D2854.md) (the `nnul` cells of this lane's grid) · filed 2026-09-27 against master `089c6ff56`**

Repro:

    function mk(x) {
      const xs = [x]
      return xs[0]
    }
    const vnn: string | null = null
    const w0 = mk(vnn)
    if w0 != null { print(w0) } else { print("null") }
    // vl check: rc 0.  vl run: wasm trap: null reference, in `mk`

Want:

    null

#### Mechanism

The list literal's element is typed at the hole's variable, which no instance binding
substitutes, so the build read the rep off the template and cast the element to a non-null
string. `monoHoleListLitAnn` ([D2898](D2898.md)'s rung) now also takes a nullable element, and
for one the literal is re-made with its instance type recorded (the annotation alone does not
reach the build). A `.push` on that local read the receiver's element off the shared `Ident`
(a type variable), so `arrElemInstTy` now reads an annotated local's element when the pin's is a
variable; without it `xs.push(x)` of a `null` still trapped.

#### Ablation
