**closed 2026-11-03 by lane column-G1 · runs, prints `1` · was a loud emit reject, clause 2, filed 2026-11-03 against master `6c4f44440` · wider than filed: any non-mono map field on the arm refused, recursion or not (`Map<string, string>` included), because the holder's twin check in `collectS` compares the two rows' map slots and `collectA` interned them only later; `collectS` now interns the named arm's map slots first, through the one intern `collectA` uses, reading the arm table through the accessors that follow it across its adoption · the same read fixed `variantFieldElemName`, which read the struct table before adoption: two arms of one field set with a map field trapped the compiler and now run ([D15099](D15099.md)) · fixture `tests/cases/unions/struct-holding-arm-with-map-field.vl` · position matrix `struct-holding-arm-with-map-field` · record-valued and nullable-valued maps still refuse, [D15098](D15098.md) · found closing [D15095](D15095.md)**

#### Mechanism

`collectS` codes `Q.o` through `armFieldStructRow`, whose twin check compares the map field of
the arm's row with its twin row's by mv slot (`uFieldMapShape`, `sFieldMapShape`). Both fall
to a find-only lookup, and `collectA`, which interns the slots, runs after `collectS`.
