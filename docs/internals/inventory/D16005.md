### D16005 — an `==` test's `else` over an un-annotated parameter keeps the parameter open, so a literal demand there pins the parameter itself

**closed 2026-11-13 by deferring the `==` complement's remainder over a hole to the pin, as the `is` complement's is (`HD_GNOT`, `pushLitEqFactAt` in `check_narrow_flow.vl`) · was loud check reject · clause 2 · found closing [D16004](D16004.md) · filed 2026-11-13 against master `7b0b9d8ac`**

Repro:

    type Color = "red" | "green"
    function mkC(): Color { return "green" }
    function onlyGreen(g: "green") { print(g) }
    function take(p) {
      if p == "red" { print(1) } else { onlyGreen(p) }
    }
    take(mkC())
    // vl check: cannot compare "green" with "red" — not a member of the union
    // Should print green; annotating `p: Color` does.

Want:

    green

#### Mechanism

The `is` complement over an open parameter defers to the pin as an `HD_GNOT` remainder for a
non-record tested type (D1243). The `==` complement over an open parameter has no such remainder. In the `else` arm `p` stays the parameter's own hole, so the argument demand
`onlyGreen(p)` asks the hole for `"green"`. At the pin, that pins the parameter to `"green"`,
and the `then` arm's `p == "red"` is refused as a comparison outside the parameter's members.

#### Ablation

| ingredient removed | outcome | needed? |
| --- | --- | --- |
| the missing annotation — `p: Color` | prints `green` | **yes** |
| the `else` arm's literal demand — `print(p)` | prints `green` | **yes** |

#### Close

The false side of a literal equality over a hole now pushes a deferred remainder,
`mkDerivedHole(HD_GNOT, …, lit, cur)`, under the same `holeElseRemainderOk` gate the `is`
complement uses. At the pin it subtracts the literal from the parameter's type. The literal demand
in the arm asks the remainder, not the parameter, so the parameter is not pinned to it.
