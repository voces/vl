### D7763 — calling the result of an un-annotated generic identity over a function value has no interned signature

**loud emit reject · clause 2 · `vl check` rc 0 · found 2026-10-20 while pinning D7762 · filed against master `573358403`**

Repro:

    function id<T>(x: T) { return x }
    function h(n: i32) { return n + 1 }
    print(id(h)(2))
    // vl check: rc 0.  vl run: emitProgram: a function-value call has no interned signature — its result type `` has no representation in the function-value ABI

Want:

    3

#### Mechanism

Not yet located. The call's callee is itself a call to the generic `id`, whose return is
inferred rather than declared. The emitter finds no function-value signature for that callee.
It reports an empty result type, so the instance's return type is not what the call site reads.

#### Ablation

| ingredient changed | outcome | needed? |
| --- | --- | --- |
| `h` annotated `: i32` or `: f64` | still refuses | no |
| `h` a `const` lambda | still refuses | no |
| `h` declared after the call | still refuses | no |
| `id` annotated `: T` | runs, `3` | **yes** |
| `const k = id(h)` then `k(2)` | runs, `3` | **yes** (the direct call of the call) |
| `const k: (n: i32) => i32 = id(h)` then `k(2)` | runs, `3` | **yes** |

#### Grading list

The same call with `id`'s argument a lambda literal, and with two type parameters
(`ap<T, R>(h: (x: T) => R) { return h }`).
