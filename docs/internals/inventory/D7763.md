### D7763 — calling the result of an un-annotated generic identity over a function value has no interned signature

**closed 2026-10-20 by lane L1 · runs, prints `3` · was loud emit reject · clause 2 · `vl check` rc 0 · CAPABILITY: the annotated `: T` and the bound `const k = id(h)` spellings run · a bare-`T` inferred return pinned at a function type is recorded at that function type rather than the function-pin placeholder (`monoFnBoundTyOf` → `synthTypeRefFb`, emit_mono.vl) · pins: `tests/cases/functions/generic-identity-fn-value-called-in-place.vl`, matrices `generic-identity-fn-value-called` and `generic-identity-fn-value` · found 2026-10-20 while pinning D7762 · filed against master `573358403`**

Repro:

    function id<T>(x: T) { return x }
    function h(n: i32) { return n + 1 }
    print(id(h)(2))
    // vl check: rc 0.  vl run: emitProgram: a function-value call has no interned signature — its result type `` has no representation in the function-value ABI

Want:

    3

#### Mechanism

Located by trapping the first write of the empty function type into the node-type column.
The instance of `id` at `T := (n: i32) => i32` gets its return annotation from the bare-`T`
arm of `monoMakeInstanceRetChecked` (emit_mono.vl), which spelled the pin as a `$fnsig` key
and recorded the node's type by parsing that name back (`synthTypeRefTy(name, -1, -1)`). A
`$fnsig` key does not parse to a type, so the node took the function-pin placeholder, a
`TyFunc` with no parameters and no result. The call of `id(h)` read that placeholder as its
callee's type and found no signature. A binding (`const k = id(h)`) keys the callee by its
own name, and a declared `: T` takes another arm, so neither read the placeholder. The arm
now hands the closed function type `T` is bound to as the fallback (`monoFnBoundTyOf`,
`synthTypeRefFb`), the route a parameter pin already takes.

#### Ablation
