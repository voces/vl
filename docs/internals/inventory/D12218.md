### D12218 — a function parameter that is also read as a value makes the per-type parameter split decline

**loud emit reject · `vl check` rc 0 · `emitProgram: monomorphize: a function parameter handed on to `a` in a call to `mid` is called there at a type it does not take` · clause 2 · CAPABILITY: without the list read the program runs (D3975) · found surveying emit refusals for L3 family (d) · filed 2026-10-24 against master `b8e223f93`**

Repro:

    function same<T>(k: T): T { k }
    function mid<F>(a: F, b: F, n: i32) {
      print(a("x"))
      print(b(n))
      const fs = [a]
      print(fs.length)
      if n > 0 { mid(b, a, n - 1) }
    }
    mid(same, same, 1)

#### Mechanism

`fn_split.vl` closes D6423 and D6762 by giving a function parameter called at two types one
parameter per type. Its plan declines when the parameter is also read as a value (a list
literal `[a]`, a closure capturing `a`), and the monomorphizer then falls back to its
one-signature rule and refuses. Both shapes the split closed come back with that one extra
line.

#### Ablation

| ingredient removed | outcome | needed? |
| --- | --- | --- |
| `const fs = [a]` | runs, `x 1 x 0` | **yes** |
| the list read replaced by a closure (`const k = () => a`) | still refuses | no |

#### Grading list

D6762's shape with a list read of the second parameter, which refuses at the sibling site
(`parameter `a1` of `mid` is called at two function types that no parameter per type
separates`): `function mid<F, G>(a: F, a1: G) { let b: F = a1; print(a("x"));
print(twice(a1)); const fs = [a1]; print(fs.length) }`, and the same with `const k = () => a1`.
