### D2355 — a user program could call the std-internal build intrinsic `__memory_shared__()`

**closed 2026-09-24 — now a loud check reject (`'__memory_shared__' is internal to std;
build-dependent code is not a user feature yet`, anchored at the call) · was accepted with no
refusal: `vl check` rc 0, and the call lowered to whatever the build decided (`false` unless
`--shared-memory`, folded away entirely inside an else-less `if`) · owner ruling 2026-09-24,
option (a) · filed against master `5c97d7e32` · fixtures
`tests/cases/memory/memory-shared-default-build.vl`,
`tests/cases/memory/memory-shared-user-definition-reserved.vl`,
`tests/cases/memory/memory-shared-shadowed-by-parameter.vl`**

Repro:

    print(__memory_shared__())
    // vl check (as filed): rc 0.  vl run (as filed): `false`, or `true` under `--shared-memory`.

#### Mechanism

`__memory_shared__()` was declared in `defaultScope` (`typecheck.declareBuiltinNames`) with no
scope restriction, so any module could call it: `checkCallNode` recorded every call the checker
resolved to the intrinsic (not a shadowed local) in `memSharedCalls`, and `foldMemShared`
folded an else-less `if` on it before the emitter ever asked who wrote it. `driver.
checkMemSharedOrigin`, run once after each `checkProgram` call (single-source, per-module and
the `jwSecondPass` re-check alike), accepts a call as std when the owning module's key
satisfies `modKeyIsStd` (`std:` only from a real specifier), OR the call is in the ENTRY and
`checkEntryPath` (the raw path staged fresh on every check — a bare no-import compile never
populates `modKeys` at all) resolves, through `checkOriginKeyOf`, to something starting `std/`.

`checkOriginKeyOf` is a stricter twin of #3122's `lintScopeKeyOf`, not a reuse of it: a
RELATIVE `checkEntryPath` is joined with `vlCwd` (staged by the host — `cli_pump` and
`stage_program`, the build/run compile path, alike — from `std::env::current_dir()`) and
normalized before being judged against the staged checkout root, never trusted by spelling
alone. `lintScopeKeyOf` itself is UNCHANGED: it still trusts a relative key as-is, because the
style findings it scopes (`compiler-no-interpolation`, `std-comment-audience`) are not a
capability, and three of #3122's own tests stage a bare `std/x.vl` with no real checkout
around it to unit-test that scoping. The two functions diverge exactly where the review found
the gap: `cd /tmp/proj && vl check std/evil.vl` (a relative path from an unrelated project)
used to pass `checkMemSharedOrigin` for the same reason it correctly still passes
`lintScopeKeyOf`, and now does not.

#### Ablation

| ingredient removed | outcome | needed? |
| --- | --- | --- |
| the call being TOP-LEVEL (moved inside a function, a loop, or an `if`/`else`) | still refused, same message | no |
| the module being a plain file (imported through a `std:` specifier instead) | runs — `std:buffer` itself calls it three times | **yes** |
| the parameter shadow (`function f(__memory_shared__: () => boolean)`) | an ordinary call through the parameter, never reaches `memSharedCalls` | no |
| checking `std/buffer.vl` bare, by path, with no import (`vl check std/buffer.vl`, or the editor opening it) | refused — a leaf std file has no import to reach `modKeyIsStd` through, so `checkEntryPath` is load-bearing | **yes** |
| the same bare check from an absolute path outside any VL checkout | still refused — `checkOriginKeyOf` finds no checkout root to strip | no |
| a RELATIVE `std/evil.vl`, run from an unrelated project's own root (`cd /tmp/proj && vl check std/evil.vl`) | still refused, once `vlCwd` is joined in — was accepted before this round | **yes** |
| `vl build`/`vl run` on `std/buffer.vl` as a bare entry (no `cli_pump`, no directory walk) | now agrees with `vl check` — `stage_program` stages `checkEntryPath`/`vlCwd`/`vlCheckoutRoot` too | **yes** |

#### Grading list

The redefinition refusal (D2263-adjacent, `intrinsicNameRefusal`) is independent and still
fires first when a user also declares `function __memory_shared__()`; both errors are asserted
together in `memory-shared-user-definition-reserved.vl`. `std:buffer`'s own three call sites,
and both shared/unshared builds working end to end, are the positive control —
`tests/vl_shared_memory_test.ts`. The bare-entry case (`vl check std/buffer.vl`, and the same
file opened directly in the editor) is `scripts/lint-self.sh`'s own std/ pass (no message
filter needed) and `tests/lsp_wasm_checker_test.ts`; its negative controls — an absolute path
outside any checkout, and a relative one from an unrelated project's own root, on both the CLI
(file and directory-walk forms) and the LSP — are `tests/vl_shared_memory_test.ts` and
`tests/lsp_wasm_checker_test.ts`. The check/build/run agreement on `std/buffer.vl` is its own
test in `tests/vl_shared_memory_test.ts`.
