### D2355 — a user program could call the std-internal build intrinsic `__memory_shared__()`

**closed 2026-09-24 — now a loud check reject (`'__memory_shared__' is internal to std;
build-dependent code is not a user feature yet`, anchored at the call) · was accepted with no
refusal: `vl check` rc 0, and the call lowered to whatever the build decided (`false` unless
`--shared-memory`, folded away entirely inside an else-less `if`) · owner ruling 2026-09-24,
option (a) · filed against master `5c97d7e32` · fixtures
`tests/cases/memory/memory-shared-default-build.vl`,
`tests/cases/memory/memory-shared-user-definition-reserved.vl`,
`tests/cases/memory/memory-shared-shadowed-by-parameter.vl`**

Repro:

    print(__memory_shared__())
    // vl check (as filed): rc 0.  vl run (as filed): `false`, or `true` under `--shared-memory`.

#### Mechanism

`__memory_shared__()` was declared in `defaultScope` (`typecheck.declareBuiltinNames`) with no
scope restriction, so any module could call it: `checkCallNode` recorded every call the checker
resolved to the intrinsic (not a shadowed local) in `memSharedCalls`, and `foldMemShared`
folded an else-less `if` on it before the emitter ever asked who wrote it. The fix adds
`driver.checkMemSharedOrigin`, run once after each `checkProgram` call (single-source,
per-module and the `jwSecondPass` re-check alike): for every entry in `memSharedCalls` it
resolves the call's owning module through `modOfTok(nodeToks[ix])` and accepts it as std when
either the module's key satisfies `modKeyIsStd` (a `std:` specifier is the only way a key
starts with `std:`, `modResolveSpecifier`), OR the call is in the ENTRY and `checkEntryPath`
(the raw path `cli.vl`/the LSP stage on every check, since a bare no-import compile never
populates `modKeys` at all) relativizes, via `lintScopeKeyOf` (#3122's checkout anchor), to
something starting `std/`. A user file living under a directory named `std/` still does not
qualify: `lintScopeKeyOf` only strips a prefix it can prove is this checkout's own root, so an
unrelated project's `std/` (or one reached with no checkout root staged at all) declines.

#### Ablation

| ingredient removed | outcome | needed? |
| --- | --- | --- |
| the call being TOP-LEVEL (moved inside a function, a loop, or an `if`/`else`) | still refused, same message | no |
| the module being a plain file (imported through a `std:` specifier instead) | runs — `std:buffer` itself calls it three times | **yes** |
| the parameter shadow (`function f(__memory_shared__: () => boolean)`) | an ordinary call through the parameter, never reaches `memSharedCalls` | no |
| checking `std/buffer.vl` bare, by path, with no import (`vl check std/buffer.vl`, or the editor opening it) | refused — a leaf std file has no import to reach `modKeyIsStd` through, so `checkEntryPath` is load-bearing | **yes** |
| the same bare check from a project whose own folder is named `std/` (no VL checkout there) | still refused — `lintScopeKeyOf` finds no checkout root to strip | no |

#### Grading list

The redefinition refusal (D2263-adjacent, `intrinsicNameRefusal`) is independent and still
fires first when a user also declares `function __memory_shared__()`; both errors are asserted
together in `memory-shared-user-definition-reserved.vl`. `std:buffer`'s own three call sites,
and both shared/unshared builds working end to end, are the positive control —
`tests/vl_shared_memory_test.ts`. The bare-entry case (`vl check std/buffer.vl`, and the same
file opened directly in the editor) is `scripts/lint-self.sh`'s own std/ pass (no message
filter needed) and `tests/lsp_wasm_checker_test.ts`; its negative control (a user file under an
unrelated `std/` folder) is asserted on both the CLI and the LSP.
