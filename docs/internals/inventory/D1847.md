#### Mechanism

[D1736](D1736.md)'s rule gives a write two effects — retire the fact it falsified, and
re-narrow the place to the member it wrote — and only the FIRST reached the path channel.
`retireNarrowingsForWrite` marked the overlay entry (`npInvBy[i] = atIx`) and banked the
place's DECLARED type at the assignment node, which the emitter's `retireNarrowFor` mirrored.
The bare-name arm did more: it shadowed the written member in the current scope and banked
that member, which `pushNarrowWriteReNarrow` selects out of the declared set.

The close is that arm's path twin, both halves. The checker banks `writeReNarrowTy` of the
place's declared type instead of the declared type itself and pushes a fresh `npKeys` entry
carrying it — AFTER the retirement walk, since an entry pushed inside it would be re-tested by
the same loop. The emitter's Member and Index arms retire as before and then push the banked
member, reading the field's own union name (`memberUnionFieldNameRead`,
`indexElemUnionName`) for the set to select out of. Lifetimes match by construction: the
retirement is in place on both sides, and the push pops with the block on both sides.
