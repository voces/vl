### D5971 — a block-local function returning a generic, capturing a local, called at two types through two results, gets no copy

**loud emit reject · `vl check` rc 0 · clause 2 · found closing [D5662](D5662.md) · filed 2026-10-17 against master `7497c0982`**

Repro:

    function k<T>(x: T): T { return x }
    function main() {
      let y = 7
      function mk() {
        print(y)
        return k
      }
      const a = mk()
      print(a(1))
      const b = mk()
      print(b("s"))
    }
    main()
    // vl check: rc 0.  vl run: emitProgram: a function-value call has no interned signature — parameter 1 of type `` has no representation in the function-value ABI

Want:

    7
    1
    7
    s

#### Mechanism

D5662's close copies a block-local function only when it reads nothing local
(`fsReadsNoLocal`), because the copy is placed after the module statement. Placing it in the
block right after `mk` instead (tried while closing D5970) still refuses, and regresses D5662's
own no-capture spelling: block-local scope (`lfFnAt`, `emit_local_scope.vl`) is lexical over a
post-order arena, and the reparsed copy's nodes are appended past the root, so no read in the
block is in the copy's scope. The same program with a second hand-written `mk2` beside `mk`
runs and shares the cell (`8 1 9 s` with `y` written between the calls), so a copy is sound;
what is missing is a copy whose scope row stands where the original's does, as a
monomorphizer clone's does (`lfNoteClone`).
