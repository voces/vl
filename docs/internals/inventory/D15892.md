### D15892 — a fresh call's record field delivered at a union of two records sharing its field names is refused, the copy finding no one member

**loud check reject, clause 2, `this value is built as W where line 7 delivers it, and it is handed on here at its own type …` · D14385's interim refusal, reached because `recUnionRecMember` picks the member by field names and finds two · found closing [D14385](D14385.md) · filed 2026-11-12 against master `5211c279e`**

Repro:

    type A = { x: i32 }
    type B = { x: string }
    type W = { r: A | B }
    function one() { { r: { x: 1 } } }
    const a = one()
    print(a.r.x + 1)
    const w: W = one()
    print(w.r is A)

Want:

    2
    true

#### Mechanism

The copy's rule builds a record field delivered at a union of records at the one member with the
record's field names (`recUnionRecMember`, check_fit_rules.vl). `A` and `B` share `x`, so there
are two and the field is not admitted. The copy's rule (`recCopyBoxesAt`) would admit `{ x: i32 }`
into `A` and not into `B`, so the member is decidable by the rule rather than by names.

| `B = { y: string }` | runs (one member by names) |

#### Grading list

The list spelling (`[{ r: { x: 1 } }]` at `W[]`), and two members both admitting the record
(`A = { x: i32 }`, `B = { x: i64 }`), where the member must be the one the checker's own
delivery picks.
