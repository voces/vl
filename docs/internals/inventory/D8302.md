### D8302 — a literal-building function whose calls land on different field storage is refused beside a declared record of its fields

**loud check reject · clause 2 · open · present on master `82bf510a3` · the same program prints `4` twice once the unused `type II` is deleted · the ambient specimens of `tests/vl_check_skip_test.ts` · found closing [D8201](D8201.md) · filed 2026-10-20 against master `82bf510a3`**

Repro:

    type II = { f: i32 }
    type J = { f: i32 | null }
    function mk() { { f: 4 } }
    const xj: J = mk()
    const k = mk()
    print(xj.f ?? 0)
    print(k.f)
    // vl check: {f: i32} is not J: they store field `f` differently ... only a fresh record widens

Want:

    4
    4

#### Mechanism

`mk` is one function body, so it builds one record row. D8201 lets several calls share the
build at the destination when every call is delivered to the same field storage
(`recSitesLandAt`, check_fit_rules.vl). Here the second call is delivered nowhere: `k` reads
`mk`'s own row, so the build at `J` cannot serve it. `mk`'s literal stays at its own row, `II`
names that row, and `recBuiltAtDeclared` refuses the delivery into `J`. Running it needs either
a build per landing (a clone of `mk` for each storage) or `k` typed at the row it is built at.

#### Ablation

| change | outcome | needed? |
| --- | --- | --- |
| delete `type II` | prints `4` twice | **yes** |
| delete `const k = mk()` | prints `4` | **yes**, the second call |
| `const k: II = mk()` | still refuses | no |

#### Grading list

A call at `Col` beside one at `J` (`const a: J = mk()` and `const c: Col = mk()`), and a call at
`{ r: f64, g: i32 }` beside one at `J`. The five ambient specimens of
`tests/vl_check_skip_test.ts` use this shape, so a close has to move them to another program
whose check depends on an ambient row.
