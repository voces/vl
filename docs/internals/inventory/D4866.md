### D4866 — a call's return re-check records one instance's destination on a generic body's shared list literal

**closed · `recordElemRepArrayLit` records nothing under a pin's re-check (`litPinN` bound) · fixture `tests/cases/generics/generic-list-literal-shared-by-nullable-instance.vl` · was check-clean invalid wasm · clause 1 · found by L2 §13.31's `f64list -> list` notes · filed and closed 2026-10-15 against master `489615e1b`**

Repro:

    function wrap<U>(u: U): U[] { [u] }
    const nb: string | null = null
    print(wrap(nb)[0])
    print(wrap(7)[0])
    // vl check: rc 0.  vl build: invalid module inside `wrap$1`: type mismatch: expected
    // (ref null $2), found i32; $2 is `string`

Want:

    null
    7

#### Mechanism

`validateRetCstrs` re-asks a generic's deferred return constraint at each call's bindings
through `litPinAssignable`, which runs `assignableExpr` on the body's own return literal
`[u]`. `recordElemRepArrayLit` then stamped the instance's `(string | null)[]` on that
literal, a niche-nullable element being one it records. The literal is one node shared by
every instance, so the `i32` and `f64` instances built an i32 list into a slot typed as the
string-ref list. The un-annotated return has no deferred constraint and was never re-asked.
