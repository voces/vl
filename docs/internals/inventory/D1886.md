outcome the mechanism below names · 2 of the 16 disagreements in a 200-pair `narrowing` sample

Repro:

    type Circle = { kind: "circle", r: f64 }
    type Rect = { kind: "rect", w: f64, h: f64 }
    type Shape = Circle | Rect
    function mkval(): Shape {
      return { kind: "rect", w: 2.0, h: 3.0 }
    }
    function pass<T>(x: T): T { return x }
    function srcOf(): Shape { return pass(mkval()) }
    function go() {
      const arr: Shape[] = [srcOf()]
      if arr[0].kind == "rect" { print(arr[0].w) } else { print(0) }
    }
    go()
    // vl check: rc 0.  vl run: emitProgram: field access but no struct type declared
    // Should print 2; binding `const s = arr[0]` first does.

#### Mechanism

**The narrow is on a PLACE that is re-read.** `arr[0].kind` and `arr[0].w` are two index reads
of one element, so the narrowing the `==` establishes is banked against the first and the field
read asks the second. Binding the element once (`const s = arr[0]`) is the `fusion: bound`
face, and it runs.

**Its inline spelling is a different outcome, and the worse one.** With every type expanded and
no declared name anywhere, the same program is `vl check` rc 0 and then

    the emitted module failed to validate inside `go`:
    type mismatch: expected (ref null $type), found (ref $type)

so the family spans clause 2 and clause 1 and a close owes both. Five filed rows carry the
`field access but no struct type declared` sentence (D14, D40, D66, D220, D1031) and **all five
are CLOSED** — the message is shared, the mechanism is not.
