### D16104 — a write of a wider record into a name, used as a value after an operand its right-hand side changes, builds an invalid module

**check-clean invalid wasm · clause 1 · `vl check` reports 0 errors and the module fails to validate: `type mismatch: expected (ref $1), found (ref $0)` (`B` against `A`) · found beside [D16103](D16103.md) · filed 2026-11-14 against master `1b5ee5499`**

Repro:

    type A = { x: i32 }
    type B = { x: i32, y: i32 }
    function yOf(q: B): i32 { return q.y }
    let k = 0
    function nb(): B { k = k + 1; return { x: k, y: k * 10 } }
    let a: A = { x: 0 }
    print(k + yOf(a = nb()))

Want:

    10

#### Mechanism

D2398 moves a value-position write to a wider name ahead of its statement so the statement reads
the value at its own type. `k` is read before the write and `nb()` writes it, so the move is
declined (`asvMoves`), and the value is lowered as the name's re-read (`assignTargetReReads`),
which reads `a` at `A` where the call wants `B`. That rung asks no question of the two types, so
the mismatch reaches the validator.
