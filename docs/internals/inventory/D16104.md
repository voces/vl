### D16104 — a write of a wider record into a name, used as a value after an operand its right-hand side changes, builds an invalid module

**closed · runs, prints `10` · was check-clean invalid wasm, clause 1: `vl check` reported 0 errors and the module failed to validate, `type mismatch: expected (ref $1), found (ref $0)` (`B` against `A`) · fixed 2026-11-14: the write moves ahead of its statement after the operands read before it are spilled, and a name re-read is never taken for a record stored at another record · found beside [D16103](D16103.md) · filed 2026-11-14 against master `1b5ee5499`**

Repro:

    type A = { x: i32 }
    type B = { x: i32, y: i32 }
    function yOf(q: B): i32 { return q.y }
    let k = 0
    function nb(): B { k = k + 1; return { x: k, y: k * 10 } }
    let a: A = { x: 0 }
    print(k + yOf(a = nb()))

Want:

    10

#### Mechanism

D2398 moves a value-position write to a wider name ahead of its statement so the statement reads
the value at its own type. `k` is read before the write and `nb()` writes it, so the move is
declined (`asvMoves`), and the value is lowered as the name's re-read (`assignTargetReReads`),
which reads `a` at `A` where the call wants `B`. That rung asks no question of the two types, so
the mismatch reaches the validator.

#### Closed (2026-11-14)

D2398's walk (`assignValueSpill`, `compiler/emit_rewrite.vl`) records the slot each passed
operand was read from. When a value-position write it would move is held back by an operand
read before it (a name the right-hand side may write, or any operand that is not a name), the
passed operands are spilled ahead in source order (`asvSpillPassed`) and the write then moves.
A `const` read needs no spill. Where no move is possible, a name's re-read is no longer taken
for a named record stored at another record (`asgNameHoldsOtherRecord`), so the write is
refused loudly rather than built invalid; a write under a short-circuit operand is that residue,
[D16105](D16105.md). Graded on `scripts/capability-probes/matrix/wider-record-write-after-read.matrix.vl`:
0 of 54 to 54 of 54; 52 of the cells were check-clean invalid modules before.
