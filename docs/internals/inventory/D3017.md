### D3017 — an un-annotated local holding a generic call's result inside a `<T>` instance refuses to print at a literal-union pin

**closed 2026-09-28 — the filed repro prints `a` · was a loud emit reject, clause 2, the same on master `6c2dafc0b` · closed by reading a call's members off its callee's result in the declaration walk (`litAtomMemberTyAt` asks `callResultAtomTyAt` of a call whose recorded type is a type variable or unknown), the rung `litAtomWidenTexts` already had for a call read directly but not for a local initialised by one; the interpolation's `literal-union string widening with no members` and the loop-variable twin `const r = id(e); print(r)` close with it · fixture `tests/cases/generics/generic-call-local-at-literal-union-pin.vl` · filed 2026-09-28 against master `59cf3b639`**

Repro:

    type LS = "a" | "b"
    function g<T>(x: T): T { return x }
    function f<T>(x: T) { const y = g(x)
      print(y) }
    function go() {
      const v0: LS = "a"
      f(v0)
    }
    go()
    // vl check: rc 0.  vl run: emit error, print of a literal-union atom whose type carries no member texts

Want:

    a

#### Mechanism

`exprIsLitAtom` claims `y` as the atom, and `litAtomWidenTexts` finds its members through
`litAtomMemberTyAt`, which walks an un-annotated local to its initializer. The initializer is a
call the instance shares with its generic body, recorded as the caller's type parameter, and the
walk had rungs for an index read and an identifier but none for a call, so it answered -1. The
callee's instance carries the substituted return annotation (`LS`), which `callResultAtomTexts`
already read for a call printed directly (`print(g(x))`).
