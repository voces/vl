### D9320 — a `const` bound to a `match` of generic functions whose scrutinee calls evaluates it once per call type

**closed · runs, prints `which` once, then `6` `xx` `1` · was check-clean wrong evaluation, `which` printed twice and `n` read `2` · `vl check` rc 0 · clause 1 · found closing [D9161](D9161.md) · present on master `bc09f9670` · filed 2026-10-21 against master `bc09f9670` · closed with D9161: a scrutinee the check bound to `$scrut<match>` is read as impure by `fsPureRead` (fn_split.vl), so the split evaluates it once before the binding instead of copying it per type · fixture `closures/fn-choice-bound-impure-cond.vl`**

Repro:

    function idg<T>(t: T): T { return t }
    function kg<T>(t: T): T { return t + t }
    let n = 0
    function which(): i32 {
      n = n + 1
      print("which")
      return 2
    }
    const h = match which() {
      1 => idg,
      2 => kg,
      _ => idg,
    }
    print(h(3))
    print(h("x"))
    print(n)

#### Mechanism

The check binds a computed scrutinee to `const $scrut<match>` and lowers the `match` to an `if`
chain testing that name, so the split's purity test (`fsPureChoice`) read a plain name and
copied the choice per call type. The copy is parsed again from the source tokens, which spell
the original `which()`, so each type's copy called it again.

#### Ablation

| ingredient removed | outcome | needed? |
| --- | --- | --- |
| the call in the scrutinee, `match k` over a `const k` | runs, scrutinee read twice with no effect | **yes** |
| the second call, `h("x")` | runs, `which` once | **yes** |
