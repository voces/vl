### D1766 — `print` of an else-less `if` with a STRING arm is check-clean invalid wasm, where the same `if` with an `i32` arm is D1745's loud refusal

**check-clean invalid wasm · clause 1 · filed 2026-09-06 against master `cc7f6140b` · found grading the `live-sites` drift [D1745](D1745.md) caused · [D1733](D1733.md)'s family at the NULL join instead of the string-plus-numeric one · 0 corpus cells**

Repro:

    print(if true { "a" })
    // vl check: rc 0.  vl run: exit 70,
    // the emitted module failed to validate inside the module's top-level code:
    // type mismatch: expected (ref $type), found (ref null $type)

Bind it first — `const b = if true { "a" }` then `print(b)` — and the same join prints `a`.

#### Mechanism

Predicted from the ablation, not probed. [D1733](D1733.md) closed `print`'s DIRECT route for a
join by making `exprUnion`'s if-expression arm ask the node's own recorded type instead of the
THEN arm alone. An else-less `if` records `string | null`, which is not a value-union BOX but
the `nulstr` NICHE — a `(ref null $str)` over the same heap the non-null kind is `(ref $str)`
over — so it takes a different route, and the one `print` emits still wants the non-null ref.
The numeric arms of the same shape reach [D1745](D1745.md)'s box mint instead and refuse
LOUDLY, which is why one else-less `if` carries two classes decided by the arm's rep.

**Declaring the union does not help, and that is what separates it from D1745.** With
`type S = string | null` present the witness is unchanged; D1745's whole difference is that
declaring the union mints the box. So this is not the same missing mint reached at a different
arm — the box is not what a niche needs.
