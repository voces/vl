### D14440 — an un-annotated record literal whose shape is a union arm's has two rows, one for its binding and one for a generic instance's parameter

**runs today and must keep running · 1 fixture (`generics/pin-inline-shape-no-struct-row`) · filed 2026-10-26 against master `641c18ca1`**

Repro:

    type Circle = { r: i32 }
    type Wide = { r: i64 }
    type Sq = { s: i32 }
    type Shape = Circle | Sq
    type WideU = Wide | Sq
    function idg<T>(x: T): T { return x }
    function exactTwin() {
      const c = { r: 7 }
      print(idg(c).r)
    }
    exactTwin()

Want:

    7

#### Mechanism

Master builds `c` (type `{r: i32}`) at `Wide`'s `{mut i64}` row: the instance `idg<{r: i32}>`
takes its parameter and result row from `paramStructIndex` → `structIndexOfTypeNameTy`, whose
widened field-set scan adopts `{r: i32}` into the first row whose fields it fits, and the local
follows the same scan. Step 7 slice 3 gives the local `repOfTy({r: i32})`, `Circle`'s variant
row `{mut i32}`, while the parameter still comes from the scan, so the call passes a
`(ref $Circle)` where `(ref $Wide)` is expected and the module does not validate. One shape has
two rows; the fix is the parameter reading `repOfTy` too (rep-driven parameters), not a rung at
the binding.
