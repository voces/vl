### D16472 — the native host prints 2⁻²⁴ with 17 digits, because its shortest-round-trip walk tries only the half-to-even candidate at each precision

**check-clean silently wrong · clause 1 (`vl check` rc 0) · `scripts/vl-host/src/main.rs` `shortest_sci` · found by fuzz-nightly run 43686086648 (oracle leg, `ar_s26_0112`) · filed 2026-11-15 against master `6015bf3ed`**

Repro:

    const x: f64 = 5.9604644775390625e-8
    print(x)
    // PRINTS 5.9604644775390625e-8

Want:

    5.960464477539063e-8

#### Mechanism

`print` renders the shortest decimal that round-trips, as JS `String(v)` does (DECISIONS, host
float printing). `shortest_sci` walks precisions upward and takes the first `{:.*e}` rendering that
parses back to `v`. At each precision that rendering is the one candidate rounded half-to-even.
2⁻²⁴ is a power of two, so the doubles below it are half as far apart as the ones above. At 16
digits the half-to-even candidate `5.960464477539062e-8` is the one that does not round-trip, and
the other neighbour, `5.960464477539063e-8`, which does, is never tried. The walk then returns the
17-digit exact value. The JS host prints `5.960464477539063e-8`, so the two hosts disagree.
