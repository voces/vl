### D15730 — a `{ k: null }` literal at an inline `{ k: 1 | 2 | null }` builds at its own `nullref` row, not the annotation's box row

**closed 2026-11-12, runs and prints `9` · was check-clean invalid wasm, clause 1 · the registry half is #7332 (`regUnionNameOfTy` answers `i32|null` for `1 | 2 | null`), the field half `anonNullFieldBox` stores the `null` value in that box · test `tests/cases/structs/null-field-at-inline-numeric-literal-union.vl` · found by the step-7 field-code lane · filed 2026-11-11 against master `35c9f65a`**

Repro:

    function f(o: { k: 1 | 2 | null, n: i32 }): i32 { o.k ?? 9 }
    print(f({ k: null, n: 1 }))
    // vl check: rc 0.  vl run: the emitted module failed to validate inside `f`

Want:

    9

#### Mechanism

The literal is typed at the annotation, but `structIndexOfObjCtx` finds no row for it, so it mints
its own `#anon` row. That row stores `k` at code 37, a `nullref` slot. The `null` value is not
stamped with its destination field type (`nodeRepStamped` is false), so `anonFieldCode`'s
null-unit rung answers `FC_NUL_NONE`. The annotation's row stores `k` in the union box (code 16),
and the parameter is typed at that row. With `i32 | null`, the literal finds the annotation's row.
With the alias spelling, the union is registered and the literal builds there.

Measured and reverted: coding the `null` field at the literal's own field type (code 16) reaches
`union box atom test on a union with no recorded members`. The inline `1 | 2 | null` has no
union-registry row, so the fix needs the registry to hold the inline set's members.

The binding face, `const m: { k: 1 | 2 | null } = { k: null }`, gives the global the literal's
row. `m.k ?? 7` then lowers through the D962 desugar. Its condition folds to `0`, but its
then-arm still reads the `nullref` field as an `i32`. `let w = …; w.k = 2` stores an `i32` into it.

Closed: The literal's `null` field is no longer coded `FC_NUL_NONE` when the literal is typed at a field
that holds more than `null`. `anonNullFieldBox` (`emit_collect.vl`) asks `regUnionNameOfTy` of the
literal's own field type. Since #7332 that answers the value row `i32|null` for `1 | 2 | null`,
and the field is stored in that box. The literal's row then matches the annotation's, so the
binding, the parameter, a `let` store, a list element and a return all build at the box layout.
`string | null`, `i32 | null` and the alias spelling are unchanged.
