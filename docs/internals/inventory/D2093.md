### D2093 — a field bound's refusal offers a `x(self: V, …)` function as a fix, and that function does not satisfy a field bound

**closed 2026-09-22 — now a loud check reject that names only the stored field and points at the method bound · diagnostics quality · filed 2026-09-22 against master `7b16d43ab` from property-access-design.md §G3, found by the getters/effects persona review · fixture `tests/cases/constraints/error-field-bound-self-function.vl`**

Repro:

    type V = new { a: f32 }
    function x(self: V) { return self.a * 2.0 }
    function useX<T: { x: f32 }>(t: T) { return t.x }
    const v: V = { a: 1.5 }
    print(useX(v))
    // vl check, filed: V does not satisfy `{x:f32}`: no `x` — the bound needs a field of that
    // type or a `x(self: V, …)` function in scope at this call
    // vl check, closed: V does not satisfy `{x:f32}`: no field `x: f32` — a field bound is
    // satisfied only by a stored field; to accept a `x(self: V)` function, bound on `{ x(): f32 }`

#### Mechanism

`checkBoundsAtCall` raised one sentence for every unsatisfied bound member, field or method.
For a method member (`{ x(): f32 }`) both halves are true: `witnessOf` accepts a field of the
function type or a `self`-function in scope. For a field member (`{ x: f32 }`) the witness is
ordinary structural assignability of a stored field, so the `self`-function half was false:
the witness above has exactly that function in scope and is still refused, which is correct
per `DECISIONS.md` (a field bound is a layout demand). The close gives the field member its own
sentence, naming the field and its type and pointing at the method bound the function does
satisfy. The method-member sentence is unchanged; `error-bound-unsatisfied-at-call.vl` pins it.
