### D16828 — `?.` over a `const` bound to `null` passes check and is refused at emit

**loud emit reject · ``emitProgram: `??` over this nullable value is not supported yet — narrow it first, e.g. `if v != null { … }` `` · clause 2 · `vl check` rc 0 · found grading [D16338](D16338.md) for L2 S3.4c · filed 2026-11-16 against master `eb968582`**

Repro:

    const a = null
    print(a?.f ?? 0)
    // vl check: rc 0.  vl run: the refusal above, at the `??`

Want:

    0

#### Mechanism

Not located yet. The checker answers `?.` differently by spelling when the receiver's type is only
`null`. A `const` bound to `null` passes, while `let a = null` and a bare `null?.f` are refused at
check as `member access '?.f' on non-object null`. Without the `??`, the emitter refuses the read
itself (`` `?.` receiver is not a struct chain``). The un-annotated parameter of D16338 meets the
check's refusal at the `null` instance. Whether `?.` over a value typed only `null` is a program
the design permits, reading `null`, is the open question, and it decides which side moves.

#### Ablation

| spelling | outcome |
| --- | --- |
| the witness (`const a = null`) | check passes, loud emit reject at `??` |
| `const v = a?.f` then `print(v == null)` | check passes, loud emit reject at `?.` |
| `a: { f: i32 } \| null = null` | runs, prints `0` |
| `let a = null` | loud check reject, `member access '?.f' on non-object null` |
| `null?.f ?? 0` | loud check reject, the same |
