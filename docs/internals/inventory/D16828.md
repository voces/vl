### D16828 — `?.` over a `const` bound to `null` passes check and is refused at emit

**closed 2026-11-16 — the witness runs and prints `0` · was: loud emit reject · ``emitProgram: `??` over this nullable value is not supported yet`` · clause 2 · `vl check` rc 0 · found grading [D16338](D16338.md) for L2 S3.4c · filed 2026-11-16 against master `eb968582`**

Repro:

    const a = null
    print(a?.f ?? 0)
    // vl check: rc 0.  vl run: the refusal above, at the `??`

Want:

    0

#### Mechanism

Ruled legal (ruling (a)): `?.` over a value typed only `null` reads `null`, and its `??` takes the
fallback. The rewrite (`drwWalkBin`, `compiler/emit_rewrite.vl`) folds `x?.f ?? d` and
`x?.f(…) ?? d` to `d` where the receiver is a re-readable read typed `null`, or a binding
initialised `null` whose read is `null` with nothing else inferred (`drwNullOnlyRecv`); the
call's arguments are never evaluated. Folding the bare read to a null literal built an invalid
module for a binding of it, so the bound read is [D16841](D16841.md). The checker half, which lets
`let a = null` and `null?.f` through, is lane L2's.
