### D17810 — a bound list of a generic function delivered whole at a wider-result list keeps the function's own signature, and the call through the destination traps

**loads then traps · clause 1 · `wasm trap: indirect call type mismatch` at `z[0](3)` · `vl check` rc 0 · the list face of D17756 · filed 2026-11-28 against master `711e77a85` by I8-PREP (D17800's grading)**

Repro:

    function __half<T>(x: T): f64 { return x / 2.0 }
    const b = [__half]
    const z: ((x: i32) => i32 | f64)[] = b
    print(z[0](3))
    // vl check: rc 0.  vl run: wasm trap: indirect call type mismatch

Want:

    1.5

#### Mechanism

The check accepts `b` delivered whole at the wider list. The elaboration takes that destination as
`b`'s slot fact (D17800's close takes a delivered fact for any holder kind whose classes' calls
agree), but nothing builds the literal's element there. D17756's check-side adaptation
(`fvaAdapt` in check_assignable.vl, the bound re-point) and mono's instancing at a delivered slot
(`monoStoredSlotFnTy`) read only a map's `v` slot. So `__half` keeps its `(i32) => f64` closure,
and the call is made at `(i32) => i32 | f64`. Extending mono's slot and `letDeliveredSlotTy` to a
list's `e` slot alone does not move it: each element written into the list also needs adapting,
as a map's writes are.
