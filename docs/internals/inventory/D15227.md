### D15227 — two returns of lists of un-annotated functions of different results, called through an element, build an invalid module

**closed · runs, prints `1.5` · was check-clean invalid wasm, `type mismatch` inside the function · clause 1 · found closing [D15209](D15209.md) · filed 2026-11-04 against master `32fb1ac0` · closed 2026-11-04: the return and arm join notes a list of functions, at any depth of lists, beside each side's set as it notes a record field (`elabFnArmJoinAt`, check_elab_cap.vl), so the tag decision decides the sides' smaller sets with the join's and every literal holds the join's ids · fixture `tests/cases/closures/returned-lists-of-fns-of-different-results-called-through-element-runs.vl`**

Repro:

    function inc0(a) { return a + 1 }
    function half(a) { return a / 2.0 }
    function pick(b: boolean) { if b { return [inc0] } return [half] }
    print(pick(false)[0](3))

Want:

    1.5

#### Mechanism

The return join of `(_) => i32`-shaped and `(_) => f64`-shaped members does not give one function type whose set [D15209](D15209.md) can union, so neither literal is built at a shared row and the result's list type disagrees with one of them; a single literal of both is kept apart by `listJoinApart`, which the return join has no counterpart of.

Located 2026-11-04 with a counter probe in the tag decision, validated on `return [inc0, half]`,
which tags. The witness declines in `ftPlan` because a member has no leaf at the join's set: each
literal's element is typed at its own one-member set, and nothing tied those sets to the join's.
`elabFnArmJoinAt` records that tie (`fnWidenSrcTo`/`fnWidenSrcFrom`, read by
`fnWidenedSourceSets`), but stopped at a list. It now walks a list whose leaves are functions; a
list of records stays out, built at its own rows (D15290).
