### D15576 — a hole parameter handed a generic, passed on to a generic's function parameter at one type and called directly at another, is typed at the first

**loud check reject · `argument 1: expected i32, got string` · clause 2 · `take(id)` with both uses passed on (D10382) or both direct runs · found closing [D10382](D10382.md) · filed 2026-11-08 against master `4a1d010d`**

Repro:

    function id<T>(x: T): T { x }
    function run<U>(f: (x: U) => U, u: U): U { f(u) }
    function take(a) {
      print(run(a, 2))
      print(a("ab").length)
    }
    take(id)
    // vl check: argument 1: expected i32, got string

Want:

    2
    2

#### Mechanism

The parameter solve (`solveUnannotParams`, check_fn_decl.vl) takes the one function type the hole
flows into, `(i32) => i32`. D10382's rule leaves a hole unsolved only when it flows into two
different function types, and a direct call records no flow, so the direct call at `string` is
checked against the solved type.
