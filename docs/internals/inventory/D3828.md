### D3828 — a nested `<U>` generic whose tail `if` recurses in one arm and calls a void function in the other is given a result, and traps at `unreachable`

**closed (2026-10-08, lane SC) · was loads then traps · found closing D3826 · filed 2026-10-08 against master `cab1ee907` · pins: `tests/cases/generics/nested-generic-tail-recursion-void.vl`**

Repro:

    function outer(x: i32) {
      function inner<U>(u: U, n: i32) {
        if n > 0 { inner(u, n - 1) } else { print(x) }
      }
      inner(1, 2)
    }
    outer(7)
    // vl check: rc 0.  vl run: prints 7, then `wasm trap: wasm unreachable instruction executed` in `inner`

Want:

    7

#### Mechanism

The checker types `inner` void; the emitter decides it again in `computeVoidFns`, from whether
the body's tail is a value. A generic or hole-parameter `inner` that captures is lowered as a
closure, so its instance's recursive call is a call through that closure, whose signature is
the instance's own and not yet void. That made the tail a value and the instance
`(result i32)`, and the void arm fell through to the trap. While a function is classified, a
call to itself in tail position, by name or through its closure, is now taken as void
(`tailSelfFnIx`), so the instance is void unless another arm yields a value.
