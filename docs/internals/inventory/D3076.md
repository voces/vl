### D3076 — a literal-union value narrowed out of a `K | i32` box and handed to an un-annotated lambda is passed as the box

**closed · a value call whose parameter token is the plain `i` takes a literal-union argument as its atom, since only an un-annotated hole pinned there can make that token · fixture `tests/cases/closures/lambda-narrowed-literal-arg.vl` · was check-clean invalid wasm · clause 1 · the generic twin is [D3098](D3098.md) · the same on master `67ca68cf3` · filed 2026-09-28 against master `67ca68cf3`, closed 2026-09-28 against master `e1e40ac99`**

Repro:

    type K = "a" | "b"
    const zz: (K | i32)[] = ["a", "b", 3]
    const f = (w) => w == "a"
    for e in zz { if !(e is i32) { print(f(e)) } }
    // vl check: rc 0.  vl run: invalid module in the top-level code: type mismatch: expected
    // i32, found (ref $type)

Want:

    true
    false

#### Mechanism

`emitCallRef` lowers an argument as a literal-union atom only when `cloCallParamLitUnion` finds a
literal union in the callee's checker type. An un-annotated lambda's parameter there is a hole,
so the answer was 0 and the narrowed walk variable went in as its box, while the instance the pin
built takes the `i32` atom. The key's `i` token cannot tell an atom from an `i32`, but the
argument can: a literal-union argument into an `i` parameter is the atom, the one conversion the
checker allows there, so the call now seeds the literal-union context from the argument's own
type (`tyIsLitUnion`).
