### D9011 — an un-annotated function giving `i32` is accepted at a function type returning `f64`, and its call is invalid wasm

**closed 2026-11-12 · runs, prints `4` (an `f64`; `f(3) / 8` prints `0.5`) · the owner's D15896 ruling admitted an `i32` result at an `f64`-result function type, which the delivery's adapter converts, so this row's refusal is lifted (fixtures `closures/hole-fn-i32-result-at-f64-fn-type.vl`, `closures/hole-fn-i32-result-at-f64-param.vl`) · was a loud check reject, `cannot assign (_) => _ to 'f' of type (a: i32) => f64`, and before that check-clean invalid wasm, `vl check` rc 0, `type mismatch: expected f64, found i32` · clause 1 · found closing [D9007](D9007.md) · filed 2026-10-21 against master `464f33df4`**

Repro:

    function inc0(a) { return a + 1 }
    let f: (a: i32) => f64 = inc0
    print(f(3))

Want:

    4

#### Mechanism

The refusal below is superseded by [D15896](D15896.md): `fnSlotRetAssignable` admits an exact
numeric widening of the result, and `fvaAdapt`'s adapter converts it.

The annotated spelling (`inc0(a: i32)`, or `: i32` on its result) is refused,
`cannot assign (i32) => i32 to 'f' of type (a: i32) => f64`: a concrete function type relates
its result and parameters through `fnSlotAssignable`, which refuses a numeric widening, because
a function value is stored as it is and nothing converts what it returns. `genericFnAssignable`,
the arm for a function with hole parameters, compared the result its body gives at the
target's parameters ([D8160](D8160.md)) with the plain `assignable`, which lets `i32` widen to
`f64`. It now uses `fnSlotAssignable` for the result and for each concrete parameter, so the
hole spelling is refused exactly as the annotated one. A lambda judged at the target type is
not this relation: its `i32` result converts inside its own body, and it keeps running.

#### Grading list

The parameter position, `function w(f: (a: i32) => f64) { return f(3) }` with `w(inc0)`,
loaded and trapped (`indirect call type mismatch`) and is now refused,
`argument 1: expected (i32) => f64, got (_) => _`; the returned position is refused the same
way. A hole function with a concrete parameter, `g(a: f64, b)` at `(a: i32, b: f64) => f64`,
