### D9011 — an un-annotated function giving `i32` is accepted at a function type returning `f64`, and its call is invalid wasm

**check-clean invalid wasm · `vl check` rc 0 · `type mismatch: expected f64, found i32` · clause 1 · found closing [D9007](D9007.md) · present on master `464f33df4` · filed 2026-10-21 against master `464f33df4`**

Repro:

    function inc0(a) { return a + 1 }
    let f: (a: i32) => f64 = inc0
    print(f(3))
    // vl check rc 0.  vl run: the emitted module failed to validate: type mismatch: expected f64, found i32

#### Mechanism

Not traced. The annotated spelling (`inc0(a: i32)`, or `: i32` on its result) is refused,
`cannot assign (i32) => i32 to 'f' of type (a: i32) => f64`. The hole function's body is
judged at the target's parameters and its `i32` result is accepted at `f64`, but nothing
converts it: the function value is stored as it is and the call reads an `i32` where it
declared an `f64`. This is the opposite direction of [D8160](D8160.md), a body widening to
`f64` accepted at `i32`.

#### Ablation

| ingredient removed | outcome | needed? |
| --- | --- | --- |
| the hole on `a` (`inc0(a: i32)`) | loud check reject | **yes** |
| the call `f(3)` (`print(1)`) | runs, `1` | **yes** |
| `let` for `const` | still invalid wasm | no |
| a lambda (`const f: (a: i32) => f64 = (a) => a + 1`) | runs, `4` | **yes** |

#### Grading list

The parameter position, `function w(f: (a: i32) => f64) { return f(3) }` with `w(inc0)`,
loads and traps (`indirect call type mismatch`) on the same master, and must be graded with
this row.
