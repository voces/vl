### D2637 — a parenthesised void call as a statement is lowered as a discarded value, and drops a value that was never pushed

**closed 2026-09-26 — the witness prints `11`, `12`, `13` · was check-clean invalid wasm, clause 1 · found in review of [D2635](D2635.md) (#3185) · pre-existing on master `50c627ce4` · fixture `tests/cases/statements/parenthesised-void-call-statement.vl`**

Repro:

    function g(x: i32) { print(x) }
    function f() {
      (g(11))
      g(12)
    }
    f()
    (g(13))
    // vl check: rc 0.  On master: invalid module — type mismatch: expected a type but nothing on stack

#### Mechanism

The emitter's statement ladder (`emitStmt`) lowers a bare `Call` through `emitCallStmt`, which
knows a void call leaves nothing. A `Paren` statement fell through to the discarded-value arm,
`emitExpr` and then `drop`, and `stmtIsTailValue` answered true for every `Paren`, so a void
call in parentheses was dropped as if it had a value, and a function whose tail was one was
classified as returning a value. The close peels the parentheses of a call in both places, so
the parenthesised call is lowered and classified as the call itself.
