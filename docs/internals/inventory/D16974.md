### D16974 — a `Set` handed to an un-annotated parameter read by `.has` is refused as not a map

**loud check reject · clause 2 · found by the capability-matrix rot sweep (`generic-tail-join-locals-set.matrix.vl`, `argument` un-annotated) · filed 2026-11-18 against master `bb90aa849` by lane F1**

Repro:

    function take(a) { print(a.has(1)) }
    const s: Set<i32> = Set()
    s.add(1)
    take(s)

Want:

    true

#### Mechanism

The parameter's `.has` call is inferred as a map's, so the argument check expects a map: "argument
1: expected a map, got Set<i32>". A `Set` has `.has` too, and the same call annotated at
`Set<i32>` runs.

#### Grading list

The repro, the parameter re-bound first (`const v = a`), and the set handed through a generic join.
