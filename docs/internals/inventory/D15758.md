### D15758 — a map of an un-annotated function needed at two signatures, read through a returned value, is refused at emit

**open · loud emit reject · `emitProgram: a function-value call has no interned signature` · clause 2 · the same map read by its own name, through a list or a `const` alias runs since D15757's close, as does the returned map when the function is needed at one signature · found by lane w321 closing D15757, grading `pinned-map-of-hole-fn-read-through-a-holder.matrix.vl` · filed 2026-11-12 against master `d303c9bcd`**

Repro:

    function half(a) { return a / 2.0 }
    const m1 = Map()
    m1.set("a", half)
    const m4 = Map()
    m4.set("a", half)
    const ws: ({ [string]: (a: f64) => f64 })[] = [m1]

#### Mechanism

Not yet traced. `half` is needed at `(f64) => f64` through `ws` and at `(i32) => f64` through `m4`,
and `m4` pins at the second. The call `mk()` returns `m4`, but the read `mk().get("a")` is a read of
`mk`'s result, which D15757's retyping does not follow: it follows a binding, a list element and a
`const` alias. The refusal names a mechanism, not a contract.
