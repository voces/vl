### D3190 — a call through a record field reads the first literal of its row's closure type, where two anonymous literals share the row with different signatures

**closed · a field call outside a generic instance checks the closure it types by against the checker's type of the receiver, and inside one against the instance's pin binding (`instRecvFieldFnTy`, `pinSubOperandTyOf`) · fixture `tests/cases/structs/anonymous-records-with-field-functions-of-two-signatures.vl` · was check-clean silently wrong · clause 1 · found by the RF3 lane while ablating D3180 · the same on master `36d233f66` · no declared record needed · filed and closed 2026-09-29 against master `36d233f66`**

Repro:

    const a = { v: 1, f: () => true }
    const xs = [{ v: 2, f: () => 11 }]
    print(xs[0].f())
    print(a.f())
    // printed true, then true, on master

Want:

    11
    true

#### Mechanism

Two anonymous literals sharing field names share one row whatever their closures' signatures
are, which is sound for the layout, since a closure's rep does not name its signature.
`fieldClosureFeOfRecv` types the call `xs[0].f()` by a closure it finds among the literals of
the receiver's row, and the first one is `a`'s `() => boolean`, so the result printed as a
boolean. D3110 made it check that closure against the receiver's type, but only inside a
generic instance. It now asks the checker's receiver type everywhere else, and inside an
instance also the pin binding for a receiver no other channel binds (a value read back from a
`{[string]: Z}` map).

#### Ablation

| ingredient changed | outcome | needed? |
| --- | --- | --- |
| `a` removed | prints `11` | **yes** (a first literal of another signature) |

| delivered through an annotated `{[string]: { v: i32, f: () => i32 }}` map | prints `true` on master | no |
