### D14943 — a lambda reached through a hole parameter, calling an un-imported UFCS `toString`, trapped the compiler in `vl check`'s emit passes

**now a loud check reject (`'toString' is not imported`) since #5870 · was compiler trap (`out of bounds array access` in `slotLetDecl`) at master `5e26d500` and `420eda99` · clause 1 · `vl run` on master refuses at emit instead (`unsupported argument type for k in a call to use`) · filed 2026-11-02 against master `4e73b063`**

Repro:

    function id(a) { return a }
    const lap = (g) => { const x = g(1); return x.toString() }
    function use(k) { return k(id) }
    print(use(lap))
    // vl check: rc 1, 'toString' is not imported.  Before #5870: the compiler trapped.

#### Mechanism

The backtrace on a named seed built from `420eda99` runs `checkSrc` → `emitProgram` →
`computeRetInference` → `criClassify` → `exprIsStrConcat` → `exprString` → `declaredString`
→ `declaredSlotOf` → `slotLetDecl`. That read takes a node id from `localDeclIx` and calls
`nodeAt` on it, and the id lies past the arena. `slotLetDecl` bounds the slot but not the id
the slot holds. The registry is reset at each `emitProgram`, so the id was written in the same
compile, by a node the arena no longer holds. #5870 removed the checker's split requests, so
`vl check` now stops at the instance's type error, and no emit pass runs to reach the read.
The read itself is unchanged: this row closes when a program that still reaches it is graded
again, or when `slotLetDecl` is shown unreachable with a stale id.
