### D2513 — at module scope, a `??` initialiser over a nullable scalar global that a statement assigned is invalid wasm

**check-clean invalid wasm · clause 1 · pre-existing, identical on master `54fcaf5d8` · found by #3165's review grid · filed 2026-09-25 against master `54fcaf5d8`**

Repro:

    let vv: i32 | null = null
    vv = 1
    const v31 = vv ?? -1
    print(v31)
    // vl check: rc 0.  vl run: invalid module, type mismatch: expected (ref null $type), found i32

#### Mechanism

Not traced. After `vv = 1` the checker narrows `vv` to `i32` for the reads that follow, and a
`??` then has a non-null left side; the initialiser lowers as though the operand were still
the nullable global's `(ref null $box)` cell while the narrowed read produced the bare `i32`.
Inside a function, and as a `??` in a statement or an assignment rather than a module
binding's initialiser, the same program runs, so the disagreement is in how a module
binding's initialiser (lowered in the start function) sees the post-assignment narrowing.
A prediction to grade, not a trace.

#### Ablation

| ingredient removed | outcome | needed? |
| --- | --- | --- |
| the program inside a function | prints `1` | **yes** — module scope |
| `vv = 1` removed (initialised `1`) | prints `1` | **yes** — an assigning statement |
| `vv = null` instead of `vv = 1` | prints `-1` | **yes** — a non-null assignment |
| `print(vv ?? -1)` instead of the binding | prints `1` | **yes** — a module binding's initialiser |
| `let v31 = 0; v31 = vv ?? -1` | prints `1` | **yes** — as above |
| a `string \| null` global | prints `a` | **yes** — a scalar box |
| an `f64 \| null` global (`vv = 1.5`, `?? -1.0`) | still invalid | no |

#### Grading list

* The `f64 | null` spelling.
