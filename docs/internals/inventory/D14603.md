#### Mechanism

`emit_base`'s module-frame tables (`moduleBindsLoopVar`, `moduleLocalLetOf*`, built by
`mlvBuild`) and `parentLetOf(blockIx, name)` resolve a binding from its spelling. Every
reader that holds the read node now asks its declaration instead (`bodyLetOfRead`,
`fnLetOfRead`, `moduleLocalLetOfRead`, `globalLetOfDeclRead`). What still asks by name is
the capture analysis, which carries only the captured name: `emit_capture_frames`
(`parentBindingOf` and its module arm), `emit_sig_tokens`' capture-type rungs,
`emit_local_scope`'s module-capture predicates and `frameChainBindsName`. The two blocks
above bind `r` twice at module scope, so a by-name answer has to be positioned; a
declaration answers each capture without that.

What is left has two deletion targets:

* **(a) the monomorphiser's residue**, the `emit_mono` readers that still ask a body or the
  module frame by spelling. Target: a4cf's M1 (the instance call table), after which these
  readers hold an instance's read and ask its template's declaration.
* **(b) the capture core**: `emit_capture_frames`' `parentBindingOf` and its module arm
  (`moduleLocalLetOfAt`, `parentLetOf`), `emit_sig_tokens`' `frameBindingNode`,
  `emit_list_rep`'s `frameChainBindsName` and `emit_local_scope`'s module-capture
  predicates. Target: E1, the per-function captured-declaration list read from
  `identDeclOf` (waits on D14602 and M1/M2).

The emitter's union and initialiser readers in `emit_classify` and `emit_union_atoms` read
the declaration and are no longer part of this floor. The callee resolution in
`fnIndexOfInScopeAt` is recorded on D14601, which has the same deletion target.
