#### Mechanism

Three recovery types misled what came after them. A bare `as` whose propagated miss the enclosing
return cannot carry answered `TY_ERR`, though the conversion itself is valid and names its type; it
now answers the target (`checkCastUnionArm`, the numeric arm, check_operators.vl). A numeric
intrinsic decided its width from every operand, so an operand typed `TY_ERR` (or a non-numeric
primitive) dropped `min`/`max`/`abs` to the f64 overload; such an operand now decides nothing, and a
call with none left, or the wrong arity, answers `TY_ERR` (`numIntrCallTy`, check_calls.vl;
`intMinMaxOperands`, check_leaf_steps.vl). An un-annotated function whose returned value was an
earlier error's `TY_ERR` added "cannot infer a return type"; it is now withheld when the body raised
an error and made no call to a still-pending return (`fnDeclBodyReported`, check_fn_decl.vl), so
a recursion with no base case still reports beside an unrelated error.

#### Grading list

`min(zzz, n)` at i32 and i64, `sqrt(zzz) + x` at f32, `min(!n, n)`, `sqrt(n, n)`, `abs(u as i32)`,
a union operand's `max(x as i32, 3)`, `return n + zzz` in an un-annotated function, and the same
body plus a base-case-less self call (still two errors).
