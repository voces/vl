### D17722 — a map read of a tagged function set's id, handed straight to an un-annotated parameter the callee null-tests and calls, has no instance argument type

**loud emit reject · clause 2 · `emitProgram: monomorphize: unsupported argument type for `g` in a call to `callIt`` · filed 2026-11-27 against master `3a8246bde` (lane COV-CLOS, a position probe of RTagClo/RCloTag #10536)**

Repro:

    function inc(a) { return a + 1 }
    const m = Map()
    m["k"] = inc
    function callIt(g, x) { if g != null { print(g(x)) } }
    callIt(m["k"], 3)
    // vl check: rc 0.  vl run: monomorphize: unsupported argument type for `g` in a call to `callIt`

Want:

    4

#### Mechanism

The argument is a map read typed `F | null`, `F` a tagged set's function type. The callee's
un-annotated `g` is null-tested and called, so its instance needs the argument's type, and the
monomorphizer finds none for a map read of a tagged set at a hole parameter. The same call with
`g` annotated runs, and so does handing `inc` itself. Bound to a `const` first, the read gets
past the monomorphizer and stops at the IR's `null test operand`, a second gap.

#### Ablation

| ingredient removed | outcome | needed? |
| --- | --- | --- |

| the map read (`callIt(inc, 3)`, no null test) | runs, prints `4` | **yes** |
| the call of `g` (`print(g == null)` only) | runs, prints `false` | **yes** |
| `x` annotated `i32` alone | still refuses | no |
| the read bound to a `const` first | refuses, `null test operand` | no (another gap) |
