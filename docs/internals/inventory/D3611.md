### D3611 — a return set of two type parameters and `null` is read by its caller at the widened number type

**check-clean silently wrong · clause 1 · the `return`-statement face of [D3591](D3591.md) · found by lane HL's grid (22 wrong cells of its `ret` helper) · filed 2026-10-04 against master `c473889d1`**

Repro:

    function G<A, B>(k: i32, a: A, b: B) {
      if k == 0 { return a }
      if k == 1 { return b }
      null
    }
    const x: f64 = 2.5
    const y: i32 = 4
    print(G(1, x, y) is f64)
    // PRINTS true

Want:

    false

#### Mechanism

`joinTys` takes `paramNullJoin` for a type parameter beside a nullable one, and that join is never
marked kept apart, so the call's substitution re-joins `f64 | i32 | null` by widening to
`f64 | null`. With a tail `if` instead of `return` statements the instance refuses (D3591); here
nothing refuses, and the `i32` arrives as an `f64`. Marking the join apart (with its deferred-join
twin in `apartHoleJoins`) makes the caller read `f64 | i32 | null`, but then D3591's readers
(`==`, list literals, `??` in a hole body) trap or build invalid wasm, so lane HL left it.

#### Ablation

| ingredient changed | outcome | needed? |
| --- | --- | --- |
| no `null` return | prints `false` | **yes** |
| a tail `if … else { null }` | D3591's refusal | no: the same join |
| pins `f64`, `f64` | prints `true`, correctly | **yes**: two number types |
