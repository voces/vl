### D1689 — two anonymous holders sharing a field NAME whose ref-list ELEMENTS differ take one anonymous row, and the second holder's read runs off the first one's layout

**closed 2026-09-06 — an anonymous row's named-heap field matches only when the ELEMENT
agrees, so the second holder mints its own row · filed against master `37b6f175b` · residue
D1674 · 0 corpus cells**

Repro:

    type A = { r: i32 }
    type B = { q: i32, tag: string }
    function as1(): A[] { return [{ r: 7 }] }
    function bs1(): B[] { return [{ q: 4, tag: "a" }] }
    function one() {
      const box = { xs: as1() }
      print(box.xs[0].r)
    }
    function two() {
      const box = { xs: bs1() }
      print(box.xs[0].q)
    }
    one()
    two()
    // vl check: rc 0.  vl run: prints 7 then 4

#### Mechanism

An anonymous literal with no row of its own is minted one by `anonMintRowFor`, and WHICH
literals have one is `structIndexOfObjCtxGo`'s answer: a scan matching field NAMES and their
storage CODES. Two holders whose only field is a ref list are both one code-5 field named
`xs`, so the second holder twinned onto the first's row — and a code-5 field's element is not
part of the code, it lives beside the row in `sFieldElemName`.

The close puts the element into that match, at both readers that map a literal to a row.
`anonValueFitsField` already refuted a code-15 nested-struct field whose target row
disagreed; it now refutes every field code whose slot is a `(ref [null] <heap>)` the code
alone does not name — `fieldCodeRefsElemHeapC`, the very predicate `structRowOfObjFieldSet`
applies on the type side — plus a union-box field, whose member set is its identity because
box tags are positional. `shapeFieldTypeCompatK`, the twin that resolves a rendered SHAPE
NAME to a row, gets the same arm for codes 5 and 28; without it an un-annotated `Map()`
carrier still delivered a correctly-minted row's value against the other row. Refutation
stays one-sided at both: an element neither side can name keeps the lenient match, which is
what an empty array literal needs.

The filed refusal was the mild outcome. Of fifteen paired element and field spellings graded
on the filed seed, the filed message covered two; **seven were check-clean invalid wasm** and
one a check-clean **cast trap** at run time. No spelling produced a wrong printed value — the
two wrappers are distinct wasm types, so a mismatch is caught by the validator rather than
read.
