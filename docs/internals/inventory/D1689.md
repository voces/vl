### D1689 — two anonymous holders sharing a field NAME whose ref-list ELEMENTS differ take one anonymous row, and the second holder's read runs off the first one's layout

**loud emit reject · filed 2026-09-06 against master `37b6f175b` · D1688's residue, and older
than it: the same collapse is reachable with plain STRUCT elements on master · 0 corpus cells**

Repro:

    type A = { r: i32 }
    type B = { q: i32, tag: string }
    function as1(): A[] { return [{ r: 7 }] }
    function bs1(): B[] { return [{ q: 4, tag: "a" }] }
    function one() {
      const box = { xs: as1() }
      print(box.xs[0].r)
    }
    function two() {
      const box = { xs: bs1() }
      print(box.xs[0].q)
    }
    one()
    two()
    // vl check: rc 0.  vl run: emit error,
    // emitProgram: unknown struct field in field access

#### Mechanism

An anonymous literal with no row of its own is minted one by `anonMintRowFor`, keyed by its
field NAMES and their storage CODES. Two holders whose only field is a ref list are both one
code-5 field named `xs`, so the second holder twins onto the first's row — and a code-5 field's
element is not part of that identity, it lives beside the row in `sFieldElemName`. The second
holder's read then resolves `q` against a row whose element is `A`, which has no such field.

Nothing about the ELEMENT'S rep is the ingredient. D1688 made the mint admit a union-box,
nullable-ref, nested-list and map element, which is what makes the collapse reachable at those
spellings too; it is reachable with plain struct elements on master and on every seed since
D1443 built the code-5 field. The annotated face runs at every element rep, because each
annotation pins its holder to its own declared shape rather than to a minted twin.
