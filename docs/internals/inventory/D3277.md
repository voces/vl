### D3277 — a parameter default naming a module `const` that holds a function is substituted as a nullable ref, so the defaulted call is invalid wasm

**check-clean invalid wasm · open · clause 1 · found by the #3300 review · the same on master `296e1141d` · filed 2026-09-29 against master `296e1141d`**

Repro:

    const DF = (x: i32): i32 => x + 1
    function dflt(v: i32, f: (i32) => i32 = DF) { f(v) }
    print(dflt(1))
    // vl check: rc 0.  vl run: invalid module in the top-level code:
    // type mismatch: expected (ref $type), found (ref null $type)

Want:

    2

#### Mechanism

Not localised past the ablation. A default is substituted at each call site, and the
substituted read of the module global `DF` arrives as the global's `(ref null …)` where the
parameter takes a non-null closure ref. The same global passed explicitly, `dflt(1, DF)`, gets
its non-null cast and runs, so the substitution path skips the cast the argument path applies.

#### Ablation

| ingredient changed | outcome | needed? |
| --- | --- | --- |
| `dflt(1, DF)` — the default not used | runs, `2` | **yes** (the substitution) |
| `dflt(1, (x: i32): i32 => x * 10)` | runs, `10` | **yes** |
| the call inside a function, not at top level | the same invalid module | no |
| `const DF = inc` over a declared `function inc` | the same invalid module | no (the lambda is scenery) |

#### Grading list

The witness, the call from inside a function, and the `const DF = inc` spelling.
