### D16476 — a read of a deep `is` receiver in the right operand of its `&&` is refused at the re-check

**open · loud check reject · `member access '.length' on non-object boolean | f64 | string | Json[] | {[string]: Json} | null` · clause 2 · found closing [D16475](D16475.md), looking for a refusal only the second pass raises · filed 2026-11-15 against master `314123b83` · witness of the second-pass parity in `tests/lsp_prepared_memo_wasm_test.ts` and `tests/vl_check_within_test.ts` · bucket (f), a local fix: D1190's substitution covers an arm block, not the operand its `&&` narrows (by ablation, 2026-11-15)**

Repro:

    type Json = null | boolean | f64 | string | Json[] | { [string]: Json }
    let g: Json = ["a"]
    const b = g is string[] && g.length > 0
    print(b)
    // vl check: member access '.length' on non-object boolean | f64 | string | Json[] | {[string]: Json} | null

Want:

    true

#### Mechanism

The first pass narrows `g` in the right operand of `g is string[] && …`, as it does for any `is`.
The deep `is` rewrite ([D1190](D1190.md), `jwRewriteSite`) routes the test through the generated
predicate and binds the converted copy only in the arm block the test guards (`jwArmBlockOf`). The
right operand of the `&&` is no arm, so its `g` is left as the raw place, and the re-check reads it
at the declared `Json`.

#### Ablation

| ingredient changed | outcome | needed? |
| --- | --- | --- |
| the union shallow (`string[] \| null`) | runs | **yes** (a deep `is`) |
| the `&&` as an `if` test, `if g is string[] && g.length > 0 { … }` | still refuses | no |
| the read moved into the `if` arm | runs | **yes** (the `&&` operand) |

#### Grading list

- `||` after a negated test (`!(g is string[]) || g.length > 0`).
- A `?:`-free spelling: the same read inside a `match` guard, if one narrows.
- The two editor tests above need another second-pass witness once this closes.
