### D3798 — a `const` wider than `i32` used as a `??` default over an `i32 | null` operand is an overflow error, while its annotation is hinted redundant

**loud check reject · clause 2 · the two-faces trap · found writing D3795's fixture (lane S5) · filed 2026-10-07 against master `a37097b64`**

Repro:

    const big = 5000000000
    const l: (i32 | null)[] = [null, 4]
    print(l[0] ?? big)
    // vl check: constant 5000000000 overflows i32

Want:

    5000000000

#### Mechanism

Not traced to the line. A `const` takes its type per use (owner ruling, 2026-09-30), and the
`??` default position hands it the operand's `i32`, which the literal does not fit. The direct
literal (`l[0] ?? 5000000000`) runs and prints `5000000000`, and so does the annotated spelling
`const big: i64 = 5000000000`. On that spelling `vl check` hints `redundant type annotation:
\`big\` is inferred as \`i64\``, so following the hint turns a running program into this error.
A `??` default is a join, not a use that demands a type, so the const should probably type there
as the direct literal does. That reading of the ruling is for the owner to confirm.

#### Ablation

| ingredient changed | outcome | needed? |
| --- | --- | --- |
| the literal written in place of `big` | runs, prints `5000000000` | **yes** |
| `const big: i64 = 5000000000` | runs, with the redundant-annotation hint | **yes** |
| operand a `const x: i32 \| null = null` binding | the same overflow error | no |
| `let big = 5000000000` | refuses: the use "needs `i32`" | no |
