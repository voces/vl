### D3798 — a `const` wider than `i32` used as a `??` default over an `i32 | null` operand is an overflow error, while its annotation is hinted redundant

**closed (diagnostic fix, lane DG) · was loud check reject on the un-annotated spelling the hint led to · clause 2 · fixture `tests/cases/lint/redundant-annotation-coalesce-default.vl` · found writing D3795's fixture (lane S5) · filed 2026-10-07 against master `a37097b64`**

Repro:

    const big: i64 = 5000000000
    const l: (i32 | null)[] = [null, 4]
    print(l[0] ?? big)
    // vl check: rc 0, and no longer hints `big`'s annotation redundant.

Want:

    5000000000

#### Mechanism

The hint is decided per binding from its initializer, and an annotated literal binding defers it
to the solve (`lbiRedundant`, typecheck.vl), which knew nothing of a `??` default read. Without
the annotation such a read is delivered at the left operand's type (`cexDeliver`), which need not
hold the literal: `const big = 5000000000` then refuses with `constant 5000000000 overflows i32`.
Closed as a diagnostic fix: `lbiNoteCoalDefault` marks an annotated literal binding read as a `??`
default whose type differs from the operand's, and `lbiRedundant` does not hint it. The fixture
covers `const` and `let`, an `f64` constant, a negated read, and a control whose annotation
matches the operand and keeps its hint.

Still open, for the owner: the un-annotated spelling still refuses, while the literal written in
place (`l[0] ?? 5000000000`) runs. A `const` takes its type per use (ruling 2026-09-30), and the
`??` default position hands it the operand's `i32`. A `??` default is a join, not a use that
demands a type, so the const should probably type there as the direct literal does.

#### Ablation

| ingredient changed | outcome | needed? |
| --- | --- | --- |
| the literal written in place of `big` | runs, prints `5000000000` | **yes** |
| `const big = 5000000000`, un-annotated | `constant 5000000000 overflows i32` | **yes** |
| operand a `const x: i32 \| null = null` binding | the same overflow error | no |
| `let big = 5000000000` | refuses: the use "needs `i32`" | no |
