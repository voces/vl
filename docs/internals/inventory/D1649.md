### D1649 — `export` before a statement that declares no name was accepted, exported nothing, and `vl fmt` deleted the token

**now a loud check reject, raised at the parse stage so `vl check` prints `(parse error)` · closed 2026-09-05 · the accepted form was a check-clean no-op (`export 55` graded rc 0 and exported nothing) that `vl fmt` then rewrote to `55`, silently editing the file · fixed by refusing the keyword in `parseStmt` when no declaration follows · found beside D1648**

Repro (before: `vl check` rc 0, and `vl fmt` printed `55` with the keyword gone; now: a parse
error naming the contract, and `vl fmt` leaves the file untouched):

    export 55
    print(1)
    // vl check: [ERROR]: `export` needs a declaration to name — a `let`, `const`, `function` or `type`

#### The rule

**`export` is a visibility modifier on a declaration, so it must be followed by something that
binds a name.** `parseStmt` consumed the keyword unconditionally and dropped it from the AST,
which made three things true at once and all of them wrong: `export 55` checked clean, it
exported nothing (there was no name to export), and `vl fmt` — which prints from the AST —
re-emitted the statement without the token, so `vl fmt -w` silently turned the user's mistake
into a different program.

The refusal is at the parse stage because that is where a modifier's placement is decided, and
because it makes the formatter's guarantee TOTAL rather than per-printer: `formatSrc` bails on
any parse diagnostic, so the file is returned untouched and no token can be deleted, for every
statement form at once. The keyword is still consumed after the diagnostic, so the statement
itself parses and reports nothing further — one error, not a cascade.

**A formatter never deletes a token.** That is the property this row exists to keep, and it is
why the fix is not "print `export` in eight statement printers": eight printers is eight places
to forget, and a parse-stage refusal covers the ones nobody thought of.

#### Ablation

`vl check` and `vl fmt`, graded against master's fixpoint and the candidate's. `kept` is
whether the keyword survives `vl fmt`.

| ingredient | before | after |
| --- | --- | --- |
| `export 55` | check rc 0, fmt rc 0, **token deleted** | check rc 1 names the contract, fmt rc 2, token kept |
| `export print(1)` | check rc 0, fmt rc 0, **token deleted** | check rc 1, fmt rc 2, token kept |
| `export (x: i32) => x` | check rc 0, fmt rc 0, **token deleted** | check rc 1, fmt rc 2, token kept |
| `export if true { print(1) }` | check rc 0, fmt rc 0, **token deleted** | check rc 1, fmt rc 2, token kept |
| `export while false { }` | check rc 0, fmt rc 0, **token deleted** | check rc 1, fmt rc 2, token kept |
| `export 55` inside a function body | check rc 0, fmt rc 0, **token deleted** | check rc 1, fmt rc 2, token kept |
| `export export const x = 1` | rc 1, `expected an expression but found EXPORT` | rc 1, names the contract |
| `export * from "./m"` | rc 1, `expected an expression but found STAR` | rc 1, the contract error first, then the STAR one |
| `export const x = 1` (control) | rc 0, kept | rc 0, kept |
| `export let x = 1` (control) | rc 0, kept | rc 0, kept |
| `export function f(): i32 { … }` (control) | rc 0, kept | rc 0, kept |
| `export type T = { a: i32 }` (control) | rc 0, kept | rc 0, kept |
| `export flat type F = { a: i32 }` (control) | rc 0, kept | rc 0, kept |
| `export { g } from "./m"` (control) | the re-export path | unchanged — `parseProgram` takes it first |
| `export extern function h(): i64` (control) | rc 0 | unchanged — `parseProgram` takes it first |

The five declaration controls and the two module-level `export` forms are the boundary of the
rule and are all unmoved. The ingredient is not the statement kind: it is whether the next
token opens a declaration.
