### D3220 — a hole callee called with more arguments than the pinned function takes is refused at emit (was invalid wasm)

**open · loud emit reject · clause 2 · was a module that failed validation until the closure-env param became per-function, and the direct call it lowers to now refuses an operand surplus · found by the #3287 split-head review (`rv3287s-4099`, `p3/a1`) · the same on master `94670f728` · filed 2026-09-29 against master `94670f728`**

Repro:

    function H(h) {
      return h(1, 2)
    }
    print(H((x: i32) => x))
    // vl check: rc 0.  vl run: emitProgram: a call passes more arguments than the function it
    // calls takes

Want:

    check reject: the direct call `((x: i32) => x)(1, 2)` is refused for its arity

#### Mechanism

Not localised. A call of a hole records no arity, so the pin is never asked whether the pinned
function takes two arguments; the instance then calls it with two.

#### Ablation

| ingredient changed | outcome | needed? |
| --- | --- | --- |
| `h(1)` | prints `1` | **yes** (the extra argument) |
| `((x: i32) => x)(1, 2)`, no hole | check reject | **yes** (the hole) |
