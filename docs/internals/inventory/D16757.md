### D16757 — an unused function that relays a generic maker withdraws the maker from twinning

**loads then traps · `vl check` rc 0, `wasm trap: indirect call type mismatch` · clause 1 · found closing [D16710](D16710.md) · the generic face of the unused relay [D16711](D16711.md) met through its instance path · filed 2026-11-16 against master `6356d3e7d`**

Repro:

    function k<T>(x: T): T { return x }
    function mk() { return k }
    const o = mk()
    const of: f64 = o(2.5)
    function deliver() { return mk() }
    const v: (x: i32) => i32 = mk()
    print(v(41))
    // vl check: rc 0 (unused function).  vl run: wasm trap, indirect call type mismatch

Want:

    41

#### Mechanism

`fvaMakerCoverCheck` withdraws a maker from twinning when any read of it takes no closed result.
`deliver` is never called, so `fvaRelayRows` gives it no result and the `mk` read in its body
takes none, which withdraws `mk` for the call at `v` too. Treating an unread relay as dead needs
an exported function (callable by the host) kept out of that rule.
