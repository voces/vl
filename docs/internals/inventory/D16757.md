### D16757 — an unused function that relays a generic maker withdraws the maker from twinning

**closed · runs, prints `41` · was loads then traps, `vl check` rc 0, `wasm trap: indirect call type mismatch` · clause 1 · a relay nothing can run (not exported, not read as a value, called only from the returns of relays nothing can run) asks for no instance through the maker calls it returns (`fvaRelayDeadReads`, check_assignable.vl), so it no longer withdraws the maker from twinning · an exported unused relay keeps the conservative answer · fixture `closures/generic-maker-beside-unused-relay.vl` · found closing [D16710](D16710.md) · filed 2026-11-16 against master `6356d3e7d`**

#### Mechanism

`fvaMakerCoverCheck` withdraws a maker from twinning when any read of it takes no closed result.
`deliver` is never called, so `fvaRelayRows` gives it no result and the `mk` read in its body
takes none, which withdraws `mk` for the call at `v` too. The read now counts as covered when its
relay can never run: no export (the host could call one), no read as a value, and no call except
from the returns of other such relays.
