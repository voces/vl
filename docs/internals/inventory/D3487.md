### D3487 — a generic's return join folds a `null` into a join of two type parameters, so the null arm fails the caller's cast at a pin

**closed 2026-10-03 — the witness prints `1`, `s`, `null` · was loads then traps, clause 1 · found while grading D3485 · D3116 is the hole-spelling sibling (since fixed) · filed against master `e5ff25ff9` · 2026-10-03, closed against master `59d72ed63` · fixture `tests/cases/generics/two-param-join-keeps-null-arm.vl`**

Repro:

    function two<A, B>(k: i32, a: A, b: B) { if k == 0 { a } else if k == 1 { b } else { null } }
    print(two(0, 1, "s"))
    print(two(1, 1, "s"))
    print(two(2, 1, "s"))
    // vl check: rc 0.  prints `1`, `s`, then `wasm trap: cast failure` at the third call

Want:

    1
    s
    null

#### Mechanism

The return inference joins the arms in order: `A` beside `B` is the union `A | B`, and that union
beside `null` reached `joinTys`' mutual-assignability collapse, where a union holding a declared
type parameter accepts `null` (the parameter does, until a pin binds it), so the join stayed
`A | B`. At `(i32, string)` the caller typed the call `i32 | string` while the instance built the
null-tagged box, and the caller's narrowing cast failed. The null-first spelling (`if k == 2 {
null } else …`) joined `null` with a bare parameter first, where `joinTyParamNull` already keeps
it (D2533), so it ran. The fix is that rule for a union: `paramJoinDropsNull` refuses the collapse
when it would drop a null into a side holding a declared parameter and no null, and
`paramNullJoin` keeps the null as a flat member, the shape the null-first spelling has, so a pin
binding a parameter to `T | null` substitutes to one union.
