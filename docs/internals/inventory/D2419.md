### D2419 — the value of an assignment into a value-union box is typed at the right side's type when no member of the box is that type

**closed 2026-09-25 by [D2398](D2398.md)'s close — the witness prints `8` · was check-clean
invalid wasm, clause 1 · filed 2026-09-25 against master `a277bf7b0`, the residue of
[D2391](D2391.md)'s close**

Repro:

    let v: f64 | string = "a"
    function k() { v = 7 }
    print(k() + 1)
    // vl check: rc 0.  vl run: invalid module, top-level code: type mismatch: expected i32, found (ref $type)

#### Mechanism

The prediction below did not hold: the close keeps the value at the right side's type, as
DECISIONS.md's assignment-as-expression rule says, and moves the write instead.
[D2398](D2398.md)'s close moves a value-position or value-tail write whose name's storage
type is not the value's ahead as `const t = e; v = t`, so the value is `t`, an `i32`, and the
box's `f64` member holds the stored `7.0`. The grading list's `K | i32` tail prints `b`.

The checker types `v = 7` at `i32`, the right side's type, while the value is stored as the
box's `f64` member. D2391's close reads the value back narrowed to the member the checker
named, and here the checker named no member, so the re-read stays the box while `k`'s caller
takes an `i32`. The same holds for a literal-union member (`v: K | i32`, `v = "b"`), whose
value the checker types at the literal and the close declines deliberately. A prediction: the
checker typing the value at the member the right side is built at, as #3144 does for a
non-union place, closes both, since the narrowed re-read then has a member to name.
