### D3923 — a generic function whose body is ill-typed at the type it is delivered at builds invalid wasm

**closed 2026-10-15 by lane SC (L1 step 7, first part) · now a loud check reject · was check-clean invalid wasm · clause 1 · the refusal names the PIN (`a(7)`), not `len`: `a` prints its type parameter here · pins: `tests/cases/generics/error-generic-fn-value-at-enclosing-type-param.vl` (binding, argument, store and list-literal positions), `tests/cases/generics/generic-fn-value-at-enclosing-type-param.vl` (the well-typed spellings run) · found in review of #3487 (`rv3487/q13_bind_illtyped`; q03, q11, q12, q14 the other positions, all five now check reject) · filed 2026-10-09 against master `dacc580c8`**

Repro:

    function len<U>(y: U) { print(y) }
    function a<T>(x: T) {
      const f: (t: T[]) => void = len
      f([x])
    }
    a(7)
    // vl check: rc 0.  vl run: the emitted module failed to validate

Want:

    a check error at `len`: `print` takes no `i32[]`

#### Mechanism

Closed by `genFnValueCstrsAt` (typecheck.vl): a generic delivered where every type variable of
the destination belongs to the enclosing generic now defers `len`'s own constraints to that
generic, as a direct call in its body would, so `a(7)` re-asks them at `T = i32`. A list literal
argument is re-delivered at its bound type once the call's substitution is final. As filed:
`len`'s body is ill-typed at `U = T[]` (a list printed), but `len` is delivered as a
value, and a generic's deferred demands are re-checked only at its calls, not at a value delivery
whose type names the enclosing generic's `T`. The program passes check and the instance is built
anyway. The binding position is invalid wasm on master. D3913 and D3916 move the call-argument
(q03, q14) and store (q11, q12) positions from a loud refusal or a trap to the same invalid wasm:
a recorded price of those closes, not a regression of a working program.
