### D2373 — a `??` joining two nullable records of different types lowers as one record's niche

**closed 2026-09-26 — the filed repro RUNS and prints `true` · was check-clean invalid wasm, clause 1 · found grading [D2267](D2267.md)'s close · filed 2026-09-24 against master `f9c3f41e2`**

Repro:

    type A = { r: i32 }
    type B = { q: string }
    function mkA(): A | null { return null }
    function mkB(): B | null { return { q: "b" } }
    function go() {
      const x = mkA() ?? mkB()
      print(x is B)
    }
    go()
    // vl check: rc 0.  vl run: invalid module, inside `go`:
    // "type mismatch: expected (ref null $type), found (ref null $type)"

#### Mechanism

The join is `A | B | null`, which no declaration names, so `coalesceNicheJoinsToBox` finds no
union for it and the `??` takes the niche lowering: a `br_on_non_null` block typed at `A`'s
`(ref null $A)` whose fallthrough is `mkB()`'s `(ref null $B)`. The binding's cell is `A`'s
niche too. The box is what the join needs, and the box needs a registered union to tag `B` in,
which is the unregistered-join question [D2260](D2260.md) asks for a union-and-record join.

A close attempt (lane U, 2026-09-25, not landed) registered the join by giving the binding the
annotation that spells its type, `A|B|null` from `tyToNominalName`, inside
`collectInlineUnionsIn`. The witness then printed `true`, but the synthesized annotation is not
equivalent to a written one: with an unused `type C = { z: f64 }` declared, `mkA`'s own
`A | null` result was emitted at `C`'s heap type (`(ref null $0)`, one slot off), and without
`C` the both-null case trapped with `cast failure` at the `is A` test. The same program with the
annotation written in source runs in both cases, so the difference is in how the synthesized
row is registered relative to the checker's own inferred-let row (`inferLetCount`,
`registerInferLetMixedUnion`), which the next attempt should grade first.

The close takes the single-producer route rather than a synthesized annotation: the checker
records the type of every `??` or value `if` whose join is a union of two or more members with
a struct among them (`noteInferJoin`, and the binding route's `tyIsStructBearingUnion`, which
now admits an all-struct join), and the emitter mints each row from that arena type through the
same `registerInferredUnionTy` the inferred binding uses. Four classifiers then had to agree
that a `??` joining a niche to another type is the box and not the operand's niche or row:
`exprNullableStruct`, `exprVariantIndex`, `structIndexOfExpr` (each declines) and `exprUnion`
(claims it). A left-nested chain `(a ?? b) ?? d` is re-associated at emit time into
`a ?? (b ?? d)`, two fresh nodes that now take the chain's own union, and every classifier asks
the chain's FIRST operand for the niche (`coalesceChainLeftmost`), so a non-null last default no
longer folds the whole chain to the default's row. And the three decliners ask the `??`'s
result type alone (`coalesceResultIsBox`), not whether its first operand is a niche: a
scalar-nullable first operand (`i32 | null`, `f64 | null`, `string | null`, `boolean | null`)
joined to a record is the box too, and before that `is A` folded to the default's row and
answered `true` for the scalar (found by the review of #3173; pinned by
`coalesce-scalar-nullable-into-record-join.vl`). Last, a same-record join nested in a record
join (`mkB(p) ?? (mkA(q) ?? mkA(s))`, or `mkA(q) ?? mkA(s)` as a value `if` arm) is `A`'s niche,
which `exprNullableVariant` had no `??` rung to say, so `exprVariantIndex` named `A`'s row and
the box took the arm's tag over a null payload: with every operand null, `== null` answered
`false`. The variant twin now carries the struct twin's rung, and `exprVariantIndex` declines a
nullable result (pinned by `coalesce-record-join-nested-null.vl`).

#### Ablation

| ingredient removed | outcome | needed? |
| --- | --- | --- |
| inference (`const x: A \| B \| null = …`) | runs, `true` | **yes** |
| the call operand (`const a = mkA()` first, then `a ?? mkB()`) | still invalid | no |
| function scope (the same two lines at module scope) | still invalid | no |
| a declaration naming the join elsewhere (`function h(x: A \| B \| null)`) | runs | **yes** |
