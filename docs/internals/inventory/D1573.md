### D1573 — a released `vl` read `std/` off the FILESYSTEM, so the binary on PATH paired a master seed with a checkout 37 commits behind, silently

**closed (fixed) — std is now generated into the binary (`scripts/vl-host/src/std_embedded.rs`, `deno task gen-std`) and a distribution build resolves `$VL_STD` → embedded, never the filesystem; a pin is ONE file · was a tooling hazard with NO diagnostic: the host walked the EXE's ancestors for a `std/` and took the first one · closes glean's VL-022 and VL-007 (a copied `dist/vl` could not find std at all) · reported by the glean session, VL-022, `~/glean/docs/vl-issues.md` · filed 2026-09-03 against master `4490423c`, landed on `292380ff`**

Repro (the FLOOR — a `std:` chain that must keep resolving; the defect's own witness is a
shell transcript, below, and is gated by `tests/vl_std_cmd_test.ts` and ci-embed-seed):

    import { stdSmoke } from "std:seed"
    import { sorted } from "std:array"

    const xs = sorted([3, 1, 2], (a, b) => a < b)
    print(stdSmoke() + xs[0])

#### Mechanism

`std_candidates()` pushed `<exe dir>/std` and then EVERY ancestor of the exe, taking the
first directory holding `array.vl` and `test.vl`. `~/vl/dist/vl` therefore read `~/vl/std`
— and `~/vl` sits on branch `wk13`, 37+ commits behind the master the embedded seed was
built from. The seed and std are one version-locked artifact; nothing compared them, and
nothing printed a word. The consumer's own summary:

> `~/vl/dist/vl` embeds a compiler seed built from master, but the host resolves `std:` by
> walking the executable's ancestors, so it reads `~/vl/std` — and `~/vl` is a checkout on
> branch `wk13`, 37+ commits behind master (vl-cb, 2026-09-03). Anyone using the PATH alias
> is compiling with a std that was never tested against that seed, and nothing warns.

The fix is the owner's ruling (DECISIONS.md §"std ships inside the binary; a pin is one
file; development overrides are explicit and announced"): the binary carries std, a
DISTRIBUTION build (`--features embed-seed`) consults no directory unless told to, and when
it is told to it says so on stderr and in `vl --version`.

#### Controls

The release binary, run from `/tmp` with no `std/` or `build/` in any ancestor:

    $ cd /tmp/vl1573/work && /tmp/vl1573/pin/vl run a.vl     # imports std:array, std:fmt, std:json
    sorted 123
    json true

`$VL_STD` still wins, and both the announcement and `--version` name it — the digest of the
std in use sits beside the digest the binary was built with, so a pairing like the one above
is a line you read rather than a silence:

    $ VL_STD=/tmp/vl1573/mystd vl --version
    vl: using std from $VL_STD (/tmp/vl1573/mystd)
    vl 0.1.0 (host ABI 2)
    commit:  <the commit this binary was built from>
    seed:    embedded (2076521 bytes) — embedded in this binary
    std:     /tmp/vl1573/mystd (11 modules, f70c6223d90e6b02) — $VL_STD override
             embedded std is bac8331c776325ff (11 modules) — this binary is running a std it was not built with

An OLD two-file pin (binary + `std/` beside it, the layout glean used) keeps running and is
told once that its second file is now inert:

    $ /tmp/vl1573/oldpin/vl run a.vl
    note: ignoring the `std/` beside this binary — this `vl` carries its own std (`vl std --hash`).
          Delete it, or set $VL_STD to use it deliberately.
    sorted 123
    json true
