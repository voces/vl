### D15300 — a value `if` choosing between record literals that hold different un-annotated functions in a field is refused at emit

**closed · runs, prints `2`, `2.5` · was loud emit reject `emitProgram: cannot take the generic function id1 as a value — a function value carries ONE signature` · clause 2 · the same choice of the bare functions ran · the same records in a list ran · found grading D15277 · filed 2026-11-04 against master `bd1aa74b7` · closed with D15290**

Repro:

    function id1(a) { return a }
    function id2(a) { return a }
    const c = 1 > 0
    const r = if c { { f: id1 } } else { { f: id2 } }
    print(r.f(2))
    print(r.f(2.5))

Want:

    2
    2.5

#### Mechanism

Two things, both measured on the fn-tag plan. The arm join (`joinArmTys`) unioned function
sets only at the top level, so the choice's record carried the first arm's set; it now joins
through records as a function's returned values do (`elabFnJoinDeepTy`, D15209), and notes each
arm's set in a record field beside the joined one (`elabFnArmJoinNote`, read by
`fnWidenedSourceSets`), so each arm's set is decided with the join's. And an arm's tail record
was no holder (D15290's mechanism); the choice now is.
