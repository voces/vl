### D16045 — a sub-word field of a `flat` record reads as its storage type, not as a widened `i32`

**closed 2026-11-13 · a sub-word field reads as `i32`, as a `u8[]` element does · was loud check reject · clause 2 · a print of the bare field runs · filed 2026-11-13 against master `57cda2b6`**

Repro:

    flat type P = { a: u8, c: i32 }
    const p: P = { a: 200, c: 7 }
    print(p.a + 1)

Want:

    201

#### Mechanism

A member read of a `flat` field types as the field's declared type, and a sub-word field's type
is the storage type `u8` (every width resolves to `u8`, D15978). `u8` is not a value type, so
arithmetic and an `i32` destination refuse it. A `u8[]` element read already types as `i32`. The
owner ruling (a) on D15978 makes a read widen the narrowed value back to `i32`.

#### Ablation

| ingredient changed | outcome | needed? |
| --- | --- | --- |
| `print(p.a)` with no arithmetic | runs, `200` | **yes** (a value use) |
| `const n: i32 = p.a` | refused, `cannot assign u8 to 'n' of type i32` | no |
| `const x = p.a` then `x + 1` | refused, the same `+` message | no |
| `a: i16` with `100`, `p.a + 1` | refused, the same message naming `u8` | no |
