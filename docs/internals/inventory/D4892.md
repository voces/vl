### D4892 — a written `let` of two generics, one with a union parameter, is called through the other's instance

**closed 2026-10-16 — now prints `W 5 true` · was loads then traps (`indirect call type mismatch`) · each write of a written `let` is adapted at every call type its binding is called at, by the checker's function-value adapter · pins: `tests/cases/closures/written-let-of-generics-written-with-fixed-union-parameter.vl`, `tests/cases/closures/written-let-of-generics-written-with-fixed-union-parameter-two-types.vl` · found while closing D3975 · filed 2026-10-15 against master `5be21bb0a`**

Repro:

    function s<A, B>(a: A, b: B) { print("S") }
    function w<B>(a: i32 | string, b: B) { print("W"); print(a); print(b) }
    function main() {
      let k = s
      k = w
      k(5, true)
    }
    main()
    // vl check: rc 0.  was: wasm trap: indirect call type mismatch

Want:

    W
    5
    true

#### Mechanism

`k` is pinned at `(i32, boolean) => void` from its call. `w`'s first parameter is a union, so
its instance takes a boxed `i32 | string` and its signature is not the pin's, yet the write
stored it in `k` unadapted and the indirect call trapped. The checker's adapter (`fvaAdapt`,
`check_assignable.vl`) boxes the argument, but declined at the write because `k`'s type was
still a hole there. Now each marked binding's owner row keeps the nodes of its writes
(`fsbOwnRhs`, `check_bind_rows.vl`), and when a call through the binding re-asks a write's
constraints (`fsbRecheckOne`), `fsbAdaptWrites` rewrites that write into an adapter at the call's
argument types whenever a parameter the write fixes takes another rep there. Composed with
D3975's per-call-type slots, `k(5, true)` and `k("x", 2)` each get their own adapted instance.
