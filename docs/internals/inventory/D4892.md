### D4892 — a written `let` of two generics, one with a union parameter, is called through the other's instance

**loads then traps · found while closing D3975 · filed 2026-10-15 against master `5be21bb0a`**

Repro:

    function s<A, B>(a: A, b: B) { print("S") }
    function w<B>(a: i32 | string, b: B) { print("W"); print(a); print(b) }
    function main() {
      let k = s
      k = w
      k(5, true)
    }
    main()
    // vl check: rc 0.  vl run: wasm trap: indirect call type mismatch

Want:

    W
    5
    true

#### Mechanism

`k` is pinned at `(i32, boolean) => void` from its call. `w`'s first parameter is a union,
so its instance takes a boxed `i32 | string` and its signature is not the pin's, yet the write
stores it in `k` unadapted and the indirect call traps. With both functions concrete the
checker refuses the write. D3975's split declines a binding written with such a function, so
the row is the same on master and after it.

#### Ablation

| ingredient changed | outcome | needed? |
| --- | --- | --- |
| `w`'s first parameter `i32` | runs, `W 5 true` | **yes** |
| `s` and `w` both concrete | check reject, `cannot assign (i32 \| string, boolean) => void to (i32, boolean) => void` | **yes** |

#### Left open by L1 (2026-10-16)

Still traps on master `502f8daa8`. D5061's close banks a pinned signature on a read. This row
needs an adapter at the write: `w`'s instance takes a boxed `i32 | string`, so storing it in a
binding pinned at `(i32, boolean)` needs a wrapper that boxes the argument, or a refusal at the
write. No pin choice can supply either, so the row needs its own design.
