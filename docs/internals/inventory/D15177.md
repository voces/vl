### D15177 — a tagged function handed to a hole the elaboration binds to the set's type is delivered as a closure, so mono pins it by the argument instead of the binding

**runs today and must keep running · structural: for `fw(add)` the elaboration binds `fw`'s hole to `add`'s tagged set type, while the call delivers `add` as a closure; mono's `monoPinHoleParam` pins the hole from the argument's own type (`monoArgTaggedFnTy`) to cover the disagreement, where a list or map of a tagged set is pinned from the binding · found closing [D15174](D15174.md) · filed 2026-11-04 against master `400855c23` plus the D15174 PR**

Repro:

    function fw(f) { return f }
    function add(a, b) { return a + b }
    const p = fw(add)
    print(p(1, 2))

Want:

    3

#### Mechanism

The elaboration's binding of the hole (`elabCallParamBoundTy`) is the set's own function type, the
rep a member's id has, while the delivery at the call is the closure the bare function value is
built as. Pinning the hole from the binding, as D15174's PR does for a list or map of the set's
ids, regressed this witness, [D6002](D6002.md) and [D15039](D15039.md) to invalid wasm, so the bare
function keeps the argument-derived pin. A close makes the binding name what the call delivers,
and deletes `monoArgTaggedFnTy`.
