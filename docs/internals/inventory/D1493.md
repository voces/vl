### D1493 — a bare union-ALIAS spelling keys as its own NAME while its row keys as the members, because the mint and the query use two different expansions

**runs today and must keep running · 128 of 992 residual `name-only` reaches · filed 2026-09-03 against master `fd95c79f`**

Repro:

    type K0 = "a" | "b"
    const m: {[string]: K0} = Map()
    m["p"] = "a"
    const got: K0 = m["p"] ?? "b"
    print(got)
    // prints a. The `K0` row is keyed `string|string`; the query key for `K0` is `K0`.

#### Mechanism

`canonUnionKeyText` expands a union-ALIAS atom only when the expansion is MULTI-atom, and it
takes that expansion from `unionAliasMembers`, which renders through `tyToEmitName` — whose atom
dedup collapses a litunion's `string|string` to one atom. So the guard declines and the alias
NAME stands as its own key. The ROW, meanwhile, was minted by `collectU`'s `UnionDecl` arm on
`udSet`, the declaration's member list, which is NOT deduped and reads `string|string`. One
spelling, two producers, two keys — so a query holding the bare alias name reaches no row.

Measured with the step-4b(c) seam on `registerMapValUnion`'s recursion (`riu/mapVal`): **128
`name-only` reaches** over the 2,790-program corpus, 108 of them a self-referential `Json`-shaped
alias and 20 a litunion alias, plus **12 `differ`** which are 4a's miss #3 (`null`'s position)
arriving at the same seam.

**The obvious alignment is refused, measured.** Expanding a declared alias through
`canonUnionKeyTextOfTy` — the 4a producer, which does not dedupe — takes `tykey-agree` from
2,422 to 2,427 and `riu/mapVal`'s `name-only` toward 0, and it fuses `K|f64` with `KB|f64` and
`SA|SB` with `OA|OB`: `keySweep/merge-diffset` 0 → 2. That renderer softens a `TyLit` to its base
at `RC_UNION_KEY`, so pushing declared aliases through it re-imports exactly the
literal-softening merge §2 disqualified `repCanonId` for and step 3 rejected the full canon
render for. The expansion the key needs is the DECLARATION's member list without any softening,
and neither renderer in the tree is that.
