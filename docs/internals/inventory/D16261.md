### D16261 — an un-annotated lambda called with a `never` call's result is pinned at two types

**closed 2026-11-15 · runs, prints `3` · was a loud emit reject, clause 1 (check passes, then emit fails internally), `emitProgram: internal: parameter `x` of `__lambda_0` is pinned at another type than the elaboration's at this call` · mono reads the elaboration's `never` binding and spells the default (`emit_mono.vl`) · filed 2026-11-14 against master `c522f8dd`**

Repro:

    function fail(): never { __trap__() }
    function k(n: i32): i32 {
      const f = (x) => x
      if n > 5 { f(fail()) }
      n
    }
    print(k(3))

Want:

    3

#### Mechanism

The lambda's parameter takes `never` from its one call. The elaboration and the monomorphizer's
pin (`emit_mono.vl`, the `pinned at another type than the elaboration's` refusal) settle it at
different types, and the emitter refuses the disagreement as internal. Found beside D16260.

#### Ablation

| ingredient removed | outcome | needed? |
| --- | --- | --- |
| `fail()` as the argument (`7` instead) | runs, prints `3` | **yes** |
| the `if` around the call | still refuses | no |

#### Closed

A parameter the elaboration binds at `never` takes no value, so it has no pin spelling of its own,
and mono's two pin rungs had nothing to compare (the hole's: `pinned at another type than the
elaboration's`) or nothing to spell (the type parameter's: `unsupported argument type`). Both now
read the elaboration's `never` and spell the instance's default, as a type parameter bound at
`never` already does (D15530); the call never runs past its argument. The cells are the
`d16261-never-argument-pin` named set: the witness, the generic face, a named un-annotated
function, a `__trap__()` argument, top level, two calls and the result used, all printing `3`.
