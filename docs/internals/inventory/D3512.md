### D3512 — a literal union whose integer members span two widths is refused by arithmetic, ordering and an inferred return, where a one-width union and `i32 | i64` both run

**loud check reject · clause 2 · open · ruled 2026-10-03 (the operator half types at the common width, `i64`) · found by lane LU while closing D3491 · the same on master `878f6ebe8` · filed 2026-10-03 against master `878f6ebe8`**

Repro:

    type D = 9000000000 | 1
    function g(): D { return 1 }
    function f() { return g() }
    print(f())
    // vl check: "'f' infers the union return type D — type-valid, but an inferred return of
    // this shape is not yet supported by codegen; annotate the return type"

#### Mechanism

Two refusals, probably two mechanisms; one row because both are the same union. The inferred
return floors in `typecheck.vl`'s un-annotated-return gate: `valueUnionRetName` declines a
union with literal leaves and `numLitUnionHasBase` declines two bases, so nothing banks the
`i32 | i64` box that every annotated position lowers `D` as since D3491. That half is a
capability: the recorder needs the box's name. The operator half (`x + 1` is "operator '+'
is not defined for D and i32", `x < 2` "comparison expects numeric operands") is
`softenLitTy` declining two bases while `numUnionMembersOf` takes only primitive members.

**Ruled (owner, 2026-10-03): `x + 1` over a mixed-width LITERAL union types at the common
width, `i64`, because literals adapt.** The set is a constraint on values rather than a join of
runtime types, so it softens to the narrowest base holding every member, as a one-width set
softens to its base. Not implemented with D3491: the operand already converts out of its box at
the member it holds (`njWidensOut`), so the close is the checker's softening plus that
conversion at an operator operand.
