### D2760 — a join of two different declared type parameters collapses to one of them, so an instance binding them apart reads the other side as it

**closed 2026-09-27 — the repro RUNS and prints `b` · was a loud check reject, `return type mismatch: expected i32[], got string[]` at the pin, for a program with no mismatch; the un-annotated face was check-clean invalid wasm · filed 2026-09-27 against master `f6db92e0d`, from the #3181 review**

Repro:

    function w<A, B>(a: A, b: B, k: boolean): A[] | B[] {
      if k { [a] } else { [b] }
    }
    const r = w(1, "b", false)
    if r is string[] { print(r[0]) } else { print(r[0]) }

#### Mechanism

Inside a generic body a type variable is assignable to anything, both ways, so `joinTys` and
`sameVariantTy` found `A[]` and `B[]` mutually assignable and collapsed the join to `A[]`. The
body's type then said `A[]`, the call site substituted it to `i32[]`, and the pin's re-check of
the declared `A[] | B[]` return compared `string[]` against it. Un-annotated, the instance
returned an `i32[]` it was not. Closed by joining two differently named declared type
parameters under a list element or nullable wrapper (`tyParamsPart`) as a union; a hole (`?…`) is
inference and still collapses. At a pin such a union re-joins its substituted members as the
non-generic join would (`tpJoinUnions`, `rejoinMembers`), so `A[] | B[]` at `i32` and `f64` is
`f64[]`, as D2716 makes the direct join. Two BARE parameters keep master's collapse: each
instance stores that join in its pin's own cell, and a union there met a bind position that
cannot box it (`f(1.5 as f32, 7, …)` through `const r = if …; return r`, which master prints).

#### Ablation

| ingredient removed | outcome | needed? |
| --- | --- | --- |
| the second type parameter (`w<T>(a: T, b: T, …)`) | runs | **yes** |
| the list constructor (`if k { a } else { b }`) | the collapse, as on master | **yes** |
| the return annotation | check-clean invalid wasm on master; now the inferred list-union floor below | no |

The un-annotated face (`w` with no return annotation, `w(1, "b", false)[0]`) now refuses as its
concrete twin does: `'w' infers the union return type A[] | B[] — … not yet supported by
codegen`, the inferred-list-union return floor both spellings share, and `[0]` on the union is
the design's own `cannot index non-array i32[] | string[]`.
