### D2493 — two union members that share one map rep answer `is` for the first: `{[string]: boolean} | {[string]: i32}` holding the i32 map prints `bool`

**check-clean silently wrong · found by #3158's review · identical on master · filed 2026-09-25 against master `0a0d24ac9`**

Repro:

    function f(x: {[string]: boolean} | {[string]: i32}) {
      if x is {[string]: boolean} { print("bool") } else { print("i32") }
    }
    const b: {[string]: i32} = Map()
    f(b)
    // PRINTS bool

#### Mechanism

A map arm in a union box is told apart from another by its representation (its map struct
and value slot), not by its declared type. A map whose value is one i32 cell (`boolean`,
`i32`, an i32-backed literal union, `boolean | null`) is the one mono map struct, so two such
arms get one tag and `is` answers true for both. `{[string]: string} | {[string]: i32}` runs,
because a string value takes its own slot. `Set<K>` is the same mono struct, which is why #3158
refuses a union holding a set and such a map (`setMapUnionClashMsg`). Giving each such arm a
distinct heap type (a declared subtype of the mono map struct), or a distinct tag, closes this
row and lifts that refusal.
