### D2493 — two union members that share one map rep answer `is` for the first: `{[string]: boolean} | {[string]: i32}` holding the i32 map prints `bool`

**closed 2026-09-26 — the filed repro RUNS and prints `i32` · was loud check reject (the D2519 lane's test-site refusal), and before that check-clean silently wrong · each map TYPE that shares a map struct with another union arm owns a box tag, so `is`, a `match` arm and `as` test the member, not the struct · the `Set<K>` half stays refused and is D2673 · filed 2026-09-25 against master `0a0d24ac9`**

Repro:

    function f(x: {[string]: boolean} | {[string]: i32}) {
      if x is {[string]: boolean} { print("bool") } else { print("i32") }
    }
    const b: {[string]: i32} = Map()
    f(b)
    // PRINTS bool

Want:

    i32

#### Mechanism

A map arm in a union box is told apart from another by its representation (its map struct
and value slot), not by its declared type. A map whose value is one i32 cell (`boolean`,
`i32`, an i32-backed literal union, `boolean | null`) is the one mono map struct, so two such
arms get one tag and `is` answers true for both. `{[string]: string} | {[string]: i32}` runs,
because a string value takes its own slot. `Set<K>` is the same mono struct, which is why #3158
refuses a union holding a set and such a map (`setMapUnionClashMsg`). Giving each such arm a
distinct heap type (a declared subtype of the mono map struct), or a distinct tag, closes this
row and lifts that refusal.

#### Close

A per-module band of box tags above the value-atom band, one per extra map TYPE among the
union arms that share a mono map struct (`mapTwinNote`, sized at collect by `markMapUnionArms`,
read by `uAtomBandTop`). The first type of each struct keeps the struct's own tag, so a module
with no such pair is byte-identical. Every box site tags from the member the value's STATIC type
is (`mapBoxTagOf`), the test side from the pattern's type (`isArmTagOfTy`), and both check-time
(`mapTwinTestMsg`) and emit-time (`mapTwinTagFail`) refusals are gone. `as` out of a box to any
map arm had no lowering at all and now has one (`tests/cases/maps/as-map-arm.vl`).

The `Set<K>` pair is not closed here: the emitter spells a Set as `{[K]: boolean}`, so a union
of the two collapses to one atom before any tag is chosen. Lifting its refusal alone printed
`set` for the map. That is D2673.

A numeric literal-union value reps as its base, so `{[K]: 1 | 2}` and `{[K]: i32}` are one box
member, not two: they share one tag, a test between them is refused at check as before, and a
generic test whose instance holds both, or was pinned at the other, is refused at emit. Beside a
map of another representation the literal-union map runs (`maps/literal-union-map-beside-other-map.vl`).
