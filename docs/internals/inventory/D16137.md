### D16137 — a joined record of un-annotated functions handed to an un-annotated parameter, bound to a `let` the callee re-points to another record, is refused at emit

**loud emit reject · `emitProgram: this record `if` stores functions of different signatures in one field, and a call through the joined record is lowered at one of them` · clause 2 · open · in [D16133](D16133.md)'s class: the callee's written literal must be built at a set decided only after its caller hands the argument in · found by lane I closing [D15920](D15920.md) · filed 2026-11-14 against master `85ffe40f8`**

Repro:

    function inc0(a) { return a + 1 }
    function half(a) { return a / 2.0 }
    function two() { [1, 2].length }
    function __take(a) {
      let v = a
      print(v.f(3))
      v = { f: half }
      print(v.f(4))
    }
    const r = if two() < 5 { { f: inc0 } } else { { f: half } }
    __take(r)

Want:

    4
    2

#### Mechanism

The mint facts' parameter walk (`elabConstParamAlias`, `emit_elab.vl`) reads through an
un-annotated `let` only while nothing re-points it. Letting it read through the re-pointed `let`
is not enough on its own. The decision after the elaboration then tries the set and declines it
at `ftPlan`'s late guard (`mintSetPartial`, `check_fn_tag.vl`): after the write, `v.f(4)` calls
through the callee's own literal `{ f: half }`, which no caller binds. The literal's build has to
take the parameter's tagged set, and that set is decided only after the caller hands the argument
in. That is a build decision needed after its consumer, D16133's class. Without the tag, the
joined record is built as closures and refused by #7517's floor.
