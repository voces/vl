### D16137 — a joined record of un-annotated functions handed to an un-annotated parameter, bound to a `let` the callee re-points to another record, is refused at emit

**closed 2026-11-14 · runs, prints `4` `2` · was a loud emit reject, `emitProgram: this record `if` stores functions of different signatures in one field, and a call through the joined record is lowered at one of them` · closed by the elaboration's store fact (D16133's ruling, option (ii), stage 2) · in D16133's class, a decision made after its consumer · found by lane I closing [D15920](D15920.md) · filed 2026-11-14 against master `85ffe40f8`**

Repro:

    function inc0(a) { return a + 1 }
    function half(a) { return a / 2.0 }
    function two() { [1, 2].length }
    function __take(a) {
      let v = a
      print(v.f(3))
      v = { f: half }
      print(v.f(4))
    }
    const r = if two() < 5 { { f: inc0 } } else { { f: half } }
    __take(r)

Want:

    4
    2

#### Mechanism

The callee's literal `{ f: half }` carries its own one-member set, and the parameter's set is
decided only after the caller hands the join in. The close keys the late fact in the
elaboration. `elabLetLitWrites` lets the mint facts' alias walk read through a `let` whose every
write after its initializer is a record literal. `elabMintStoresAt` notes the alias
(`mintAliasNote`) and each literal as stored at the call's instance set (`mintStoreNote`), when
every function the literal names is a member of that set. The late decision reads the fact
(`ftStoredAt`, `check_fn_tag.vl`): the store arms of `ftHoldCtxOk` accept the literal, the
written-literal arm of `ftScan` takes its fields as leaves of the set, and `ftTry` stamps the
literal at the holder's rep. Two instances that note one literal at different sets mark it `-2`,
and the set is declined: a loud refusal ([D16213](D16213.md)).
