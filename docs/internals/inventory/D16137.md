### D16137 — a joined record of un-annotated functions handed to an un-annotated parameter, bound to a `let` the callee re-points to another record, is refused at emit

**loud emit reject · `emitProgram: this record `if` stores functions of different signatures in one field, and a call through the joined record is lowered at one of them` · clause 2 · open · found by lane I closing [D15920](D15920.md) · filed 2026-11-14 against master `85ffe40f8`**

Repro:

    function inc0(a) { return a + 1 }
    function half(a) { return a / 2.0 }
    function two() { [1, 2].length }
    function __take(a) {
      let v = a
      print(v.f(3))
      v = { f: half }
      print(v.f(4))
    }
    const r = if two() < 5 { { f: inc0 } } else { { f: half } }
    __take(r)

Want:

    4
    2

#### Mechanism

The mint facts' parameter walk (`elabConstParamAlias`, `emit_elab.vl`) reads through an
un-annotated `let` only while nothing re-points it, since a write gives the binding a record
the parameter's callers never handed in. Here the write stores a member of the joined set, so
the binding's value stays within the set, but no rule decides the written record into the
parameter's set. The joined record is then built as closures and refused by #7517's floor.
