### D7381 — an un-annotated list whose element is an `if` choosing between generic functions, inside a generic called at two types, is refused

**closed 2026-10-20 by lane L1 · runs, prints `a 3 b s` · was loud emit reject · `vl check` rc 0 · clause 2 · CAPABILITY: the same list in a non-generic function runs ([D7380](D7380.md)), and so does `[a]` in the generic · each instance types the list's element reads at its own pin, as a record field's already were (`monoPinListElems` → `monoRetypeSlotReads`, emit_mono.vl) · pins: `tests/cases/closures/generic-fn-list-element-in-generic-body-at-two-types.vl`, `tests/cases/closures/hole-fn-list-element-in-hole-body-at-two-types.vl`, matrix `generic-fn-if-list-in-generic-body-open` · a hole element whose result is its own hole is [D7840](D7840.md) · found closing [D7380](D7380.md) · present on master `622d88f2c` · filed 2026-10-19 against master `622d88f2c`**

Repro:

    function a<V>(v: V) { print("a"); print(v) }
    function b<V>(v: V) { print("b"); print(v) }
    function g<T>(x: T, c: boolean) {
      const fs = [if c { a } else { b }]
      fs[0](x)
    }
    g(3, true)
    g("s", false)
    // vl check: rc 0.  vl run: emitProgram: a function value's signature is not known at this call — the type it was given takes fewer parameters than the call passes

Want:

    a
    3
    b
    s

#### Mechanism

The slot's pin depends on the instance (`x: T`), so `monoDeclPathPinsPerInstance` holds and
`monoPinListElems` returned before typing anything: the instances share the list's nodes, and
the element read kept the arms' unpinned type, which takes no parameter. The fix instances the
elements at each instance's own pin and notes the read's type per instance
(`monoNoteFieldReadTy`), the table `cloCallSigKey` reads first; a shared annotation is still
never written. A hole element takes the pin's parameters and its own closed result.
