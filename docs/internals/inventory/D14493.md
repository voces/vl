### D14493 — a record literal whose field names match a declared union's arm builds at that arm, not at its own type

**closed 2026-10-27 · runs today and must keep running · fixed by narrowing the emitter's field-name arm scan for a literal whose checker row matches no arm (`objVariantNameCtx`): it keeps an arm only where every number field is stored as the arm stores it, otherwise the literal builds at its own row, and a delivery into the union copies it onto the member the checker names (`recAdLanding`, `unionArmLandingForStructExpr`) · was a wrong value in a function and check-clean invalid wasm at module scope · clause 1 · filed 2026-10-27 against master `1558e9ab0` · pins: `tests/cases/soundness/record-literal-field-name-twin-of-union-arm.vl`, `tests/cases/soundness/record-fresh-call-into-union-destination.vl`**

Repro:

    type R = { v: f64 }
    type U = R | string
    const e0 = { v: 3 }
    print(e0.v / 2)
    function f() {
      const e1 = { v: 3 }
      print(e1.v / 2)
    }
    f()
    // master: invalid module at module scope (f64.convert_i32_s in a constant expression);
    // inside `f` alone it prints 1.5

Want:

    1
    1

#### Mechanism

The checker types `{ v: 3 }` as `{v: i32}`, so `e1.v / 2` is integer division. The emitter chose
the literal's union arm in three steps: the checker's row, then omitted fields, then the first
arm whose field NAMES matched, with an `i32` value fitting an `f64` field. That last step was a
second producer: declaring `U` made the literal build at `R`, and the read then divided an `f64`.
Nothing in the program delivers `e1` into `U`. Each fresh delivery now builds at its own
destination. A literal whose checker row is no arm keeps that row unless the name-matched arm
stores every number field at the same kind; `{ r: null }` into `{ r: i32 | null }` still builds
at the arm, since no value read off it changes.
