### D15541 — a hole bound at a function list's type, in place of its table-index rep, reads a tagged set's ids as closure refs

**runs today and must keep running · REFUTATION PIN · check-clean invalid wasm under a candidate that binds a hole parameter at its argument's type where the pin is a function list's table-index rep (rowintern's T1, refused) · filed 2026-11-07 against master `c3f6eac95`**

Repro:

    function inc0(a) { return a + 1 }
    function dbl(a) { return a * 2 }
    function half(a) { return a * 1.5 }
    function take(a) { return a.map((f) => f(3)) }
    const g = [inc0, dbl]
    print(take(g)[1])
    const r = take([inc0, dbl])

Want:

    6

#### Mechanism

`[inc0, dbl]` is a list of a tagged function set, stored as the set's `i32` ids. Mono's rebuild
binds `take`'s hole `?take.0` at `i32[]`, the list's table-index rep, and the `map` callback calls
each `f` through the set's dispatch. A candidate that binds the hole at the argument's own type,
`((i32) => i32)[]`, types the callback's `f` as a closure ref while the list still holds ids, and
the module fails to validate inside `take`: `expected (ref $type), found i32`. The binding is
right as a type; the rep layer has no fact that names the set the elements are ids of.

#### Ablation

Greedy line removal from `hole-fn-list-map-result-returned-from-param.vl`, keeping a line removed
only while the candidate still fails to validate and master still runs, leaves the witness above:
both calls are needed, the one through the binding `g` and the inline `take([inc0, dbl])`. A
single call, `print(take([inc0, dbl])[1])`, runs under both, as does `take` indexing the list
directly (`a[1](3)`).
