### D4957 — a numeric list field narrowed by `is K[]` is delivered as `K[]` and aliased

**closed · now a loud check reject · was check-clean silently wrong value (clause 1) · related to D4928 and D4945 (a narrowed list delivered as `K[]`) · found closing D4945 · filed 2026-10-15 against master `e2efbc0af` · pins: `tests/cases/soundness/list-element-narrowing-field-is-not-a-delivery-reject.vl`, `list-element-narrowing-field-reads-run.vl`**

Repro:

    type K = 0 | 1
    type O = { xs: i32[] }
    const o: O = { xs: [0, 1] }
    let k: K[] = []
    if (o.xs is K[]) {
      k = o.xs
    }
    o.xs[0] = 5
    print(k[0])
    // vl check: 'o.xs' is narrowed by `is` only for reading its elements; it is still
    // declared i32[] and a later write may widen it, so it cannot be delivered as K[]. Copy it
    // with 'o.xs.map((x) => x)'

#### Mechanism

D4928 and D4945 make a numeric literal-set `is` on a bare name narrow element reads only. A
member place kept the older by-name narrowing, which retypes `o.xs` itself as `K[]`, so the
assignment delivered the list object `o` still holds at its declared `i32[]`, and the store
through `o.xs` after the guard reached `k`.

#### Close

Owner ruling (c) on #3792 at every place: the element-only narrowing (typecheck.vl,
`elemRecvPrefix`, `elemKeyBase`, `narListDeliveryErr`) keys a field path (`o.xs`, `p.o.xs`) and
a literal-subscript place (`xss[0]`) as it keys a bare name. Their element reads type as `K`,
a store or push of a `K` keeps the narrowing standing, a store of a wider value retires it
(`o.xs[0] = 5` under the guard was `cannot assign i32 to K`), and delivering the place where
`K[]` is wanted is the D4928 check error naming the place and its `map` copy. A string field
under `t.ss is S[]` now narrows its element reads too, where it was refused at the first read.

The position matrix
`scripts/capability-probes/matrix/is-list-field-element-narrow-delivery.matrix.vl` grades
every annotated face as the D4928 refusal; the un-annotated `struct_field_init` face, which was
check-clean invalid wasm, now runs.

#### Ablation

| ingredient changed | outcome | needed? |
| --- | --- | --- |
| `const xs: i32[] = [0, 1]` bare name in place of `o.xs` | the D4928 check error | **yes** (a member place) |
| `string[]` field with `S = "a" \| "b"` | `cannot assign string[] to S[]` | **yes** (a numeric element) |
| `k = o.xs.map((x) => x)` | a separate list, prints 0 | **yes** (delivered by reference) |
| `o.xs[0] = 5` removed | prints 0, right | **yes** (a later write) |
