### D4957 — a numeric list field narrowed by `is K[]` is delivered as `K[]` and aliased

**check-clean silently wrong value · clause 1 · related to D4928 and D4945 (a narrowed list delivered as `K[]`) · found closing D4945 · filed 2026-10-15 against master `e2efbc0af`**

Repro:

    type K = 0 | 1
    type O = { xs: i32[] }
    const o: O = { xs: [0, 1] }
    let k: K[] = []
    if (o.xs is K[]) {
      k = o.xs
    }
    o.xs[0] = 5
    print(k[0])
    // vl check: rc 0.  vl run: prints 5, a value no K holds
    // PRINTS 5

#### Mechanism

D4928 and D4945 make a numeric literal-set `is` on a bare name narrow element reads only. A
member place keeps the older by-name narrowing, which retypes `o.xs` itself as `K[]`, so the
assignment delivers the list object `o` still holds at its declared `i32[]`, and the store
through `o.xs` after the guard reaches `k`.

#### Ablation

| ingredient changed | outcome | needed? |
| --- | --- | --- |
| `const xs: i32[] = [0, 1]` bare name in place of `o.xs` | the D4928 check error | **yes** (a member place) |
| `string[]` field with `S = "a" \| "b"` | `cannot assign string[] to S[]` | **yes** (a numeric element) |
| `k = o.xs.map((x) => x)` | a separate list, prints 0 | **yes** (delivered by reference) |
| `o.xs[0] = 5` removed | prints 0, right | **yes** (a later write) |
