### D1430 — a member call on an UN-ANNOTATED parameter is rewritten onto a `self`-function whose receiver type no instantiation can have

**check-clean invalid wasm · clause 1 · CLOSED 2026-09-03 (`drwAnyInstanceTakesField` asks the
call sites for the un-annotated spelling too) · found 2026-09-03 while routing an unbounded
`<T>` onto the hole (D1431) · ZERO corpus cells**

Repro:

    type Boxed = { tag: () => string }
    type Circle = { r: f64 }
    function tag(self: Circle): string { "C" }
    function g(x) { x.tag() }
    const b: Boxed = { tag: () => "fld" }
    print(g(b))
    // vl check: rc 0.  vl run: Invalid input WebAssembly code at offset 387:
    //   type mismatch: expected (ref $type), found (ref $type)
    // Should print fld.

#### Mechanism

`dispatchRewrite` runs before monomorphization, so `drwWalk` meets `x.tag()` while `x` is
still an inference hole. Its UFCS arm reads `si < 0 && !recvHasField` as "no field, so UFCS",
and `drwAnyInstanceTakesField` exists to correct that by asking what the CALL SITES pass. That
predicate opened with `if fn.fnTyParams.length == 0 { return false }` — an un-annotated
parameter declares no type parameters, so the question was never asked and the call was
rewritten to `tag(x)`, handing a `Boxed` to a function that takes a `Circle`.

The `<T>` spelling of the same program was already right, because it has `fnTyParams`. That
asymmetry is D1431's, one pass later: an un-annotated parameter is a generic too.

#### Ablation

| ingredient removed | outcome | needed? |
| --- | --- | --- |
| the free `tag(self: Circle)` | prints `fld` | **yes** |
| the un-annotated `x` (annotate `x: Boxed`) | prints `fld` | **yes** |
| `Circle` → `Boxed` on the `self` parameter | prints `sf`, correctly | **yes** |
| the `<T>` spelling instead of the hole | prints `fld` | **yes** |
