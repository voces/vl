### D9630 — a `!= null` test of an `i64`- or `f64`-valued map read does not narrow the read, where an `i32`- or `string`-valued map narrows

**loud check reject · clause 2 · CAPABILITY: the same program over `{ [string]: i32 }` or `{ [string]: string }` prints its value · found closing [D9620](D9620.md) (its matrix's `map_value_place` cells) · present on master `54fb716a1` · filed 2026-10-22 against master `54fb716a1`**

Repro:

    const m: { [string]: i64 } = Map()
    m["k"] = 7
    if m["k"] != null {
      const w: i64 = m["k"]
      print(w + 1)
    }
    // vl check: cannot assign i64 | null to 'w' of type i64

Want:

    8

#### Mechanism

Not traced. The map twin of the index-place narrowing channel ([D1025](D1025.md)) keys
`m["k"]` and narrows it for an `i32` or `string` value; a 64-bit value, integer or float, is
not narrowed, so the read keeps `i64 | null`. A nested comparison of the read (`m["k"] > 3`)
refuses with "comparison expects numeric operands, got i64 | null and i32" for the same reason.

#### Ablation

| ingredient changed | outcome | needed? |
| --- | --- | --- |
| the value type `i32` or `string` | runs | **yes** |
| the value type `f64` (`7.5`) | same refusal, naming `f64 \| null` | no |
| a nested `if m["k"] == 7` around the binding | same refusal | no |

#### Grading list

`i64`, `f64` and `u64` values; a `const` and a `let` binding of the narrowed read; the read
compared, passed to an `i64` parameter, and returned from an annotated function.
