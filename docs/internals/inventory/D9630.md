### D9630 — a `!= null` test of an `i64`- or `f64`-valued map read does not narrow the read, where an `i32`- or `string`-valued map narrows

**closed · runs, prints `8` · was loud check reject, clause 2 · CAPABILITY: the same program over `{ [string]: i32 }` or `{ [string]: string }` prints its value · found closing [D9620](D9620.md) (its matrix's `map_value_place` cells) · filed 2026-10-22 against master `54fb716a1` · closed by narrowing a map cell's read at every value width (`placeMapCellTy`, check_tp_bound.vl): the guard probes the key, so a stored `0` is present and a missing key is not · fixture `maps/narrowed-wide-value-read.vl`, matrices `narrowed-wide-map-read` (`i64`) and `narrowed-f64-map-read` (`f64`), 0 → 62 of 62 each, and `hole-i64-literal-arith` 64 → 66 of 66**

Repro:

    const m: { [string]: i64 } = Map()
    m["k"] = 7
    if m["k"] != null {
      const w: i64 = m["k"]
      print(w + 1)
    }
    // vl check: cannot assign i64 | null to 'w' of type i64

Want:

    8

#### Mechanism

`placeMapCellTy` (check_tp_bound.vl) answered -1 for a map whose value is `i64`, `f64` or
`f32`, because a miss on such a map reads a numeric zero rather than a `null`, so the read
was never keyed for narrowing. The guard does not read the value: the `!= null` test of a
map place lowers to a key probe, so a stored `0` and a missing key were always told apart.
Dropping the exclusion lets the place narrow at every value width.

#### Grading list

`i64` and `f64` values (`u64` is not a type today); a `const` and a `let` binding of the
narrowed read; the read compared, passed to an `i64` parameter, and returned from an
annotated function; a stored `0` and a missing key.
