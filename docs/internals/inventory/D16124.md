### D16124 — a map of a hole function returned by an un-annotated function, bound annotated beside a lambda of the same signature, builds an invalid module

**closed · runs, prints `3` · was check-clean invalid wasm, clause 1 · fixed 2026-11-14: an un-annotated map result recorded open takes the shape its calls read · the same before and after #7995 · found grading `pinned-map-of-hole-fn-one-signature.matrix.vl` (`return_inferred`, annotated) · filed 2026-11-14 against master `29d333d9`**

Repro:

    function half(a) { return a / 2.0 }
    const m4 = Map()
    m4.set("a", half)
    const g: ((a: i32) => f64) | null = (a: i32) => 1.5
    function deliver() {
      return m4
    }
    const v: { [string]: (a: i32) => f64 } = deliver()
    const h = v.get("a")
    if g != null && h != null { print(g(3) + h(3)) }

Want:

    3

#### Mechanism

`deliver`'s result valtype came from `cloRetValSlot`, which keyed a map result off
`fnRecordedRetTy`: the checker's open `{[string]: (_) => _}`, whose shape is the mono map. Its
calls (`fnRetMapShapeAt` → `inferredRetMapSlot`) and its returned value read the tail's closed
`{[string]: (i32) => f64}`, the closure-valued map the pin gives `m4`. The two shapes met at the
return. Now an un-annotated map result recorded open takes `inferredRetMapSlot`'s shape, so the
signature, the return and the calls name one map.
