### D16124 — a map of a hole function returned by an un-annotated function, bound annotated beside a lambda of the same signature, builds an invalid module

**check-clean invalid wasm · clause 1 · the same before and after #7995 · found grading `pinned-map-of-hole-fn-one-signature.matrix.vl` (`return_inferred`, annotated) · filed 2026-11-14 against master `29d333d9`**

Repro:

    function half(a) { return a / 2.0 }
    const m4 = Map()
    m4.set("a", half)
    const g: ((a: i32) => f64) | null = (a: i32) => 1.5
    function deliver() {
      return m4
    }
    const v: { [string]: (a: i32) => f64 } = deliver()
    const h = v.get("a")
    if g != null && h != null { print(g(3) + h(3)) }

#### Mechanism

Not yet traced. `m4`'s function slot is reached by no call the elaboration sees: the only call is
through `deliver()`'s result bound at an annotated type. `half` is built at its uncalled stub,
while the read-back call goes through the `$fnsig` the lambda `g` interns at `(i32) => f64`, and
`deliver`'s return does not validate: it expects one map struct and finds another (`(ref $5)` against `(ref $8)`). Without `g`, no signature matches, and the same program runs
and prints `1.5`.
