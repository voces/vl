### D14731 — a call in a list literal handed to a generic over the list keeps its record at its own row while another call of the same function delivers it as a declared record

**open · check-clean invalid wasm, clause 1 · the list face of [D14530](D14530.md), through a generic rather than an index · filed 2026-10-31 against master `ef8c85e1`**

Repro:

    type Circle = { r: i32 | null }
    function sink(_x: Circle) { }
    function first<T>(xs: T[]): T { xs[0] }
    function mkcall() { { r: null } }
    sink(mkcall())
    const y = first([mkcall()])
    print(y.r ?? 3)

Want:

    3

#### Mechanism

`sink(mkcall())` asks for `mkcall`'s record at `Circle`. The record solve counts the call in the
list literal as stored at its own row: `recReadInPlace` follows an element only out of a literal
that is indexed in place ([D14531](D14531.md)), and a list handed to `first<T>(xs: T[])` is a
generic's argument, which no sole-pin rule names. The two builds disagree, so `mkcall` is built at
its own row and `sink` receives it as `Circle`. Invalid on line 5. `reverse([mkcall()])[0]` from
`std:array` is the same shape.
