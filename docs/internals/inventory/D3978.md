### D3978 — a call through a list element holding a written `let` alias of a generic does not constrain the value, which a later delivery sets

**check-clean silently wrong · clause 1 · found in review of #3505 (`rv3505/r5/f01`, `f02`, `f07`) · filed 2026-10-10 against master `e5128703a`**

Repro:

    function inner<U>(u: U) { print("I"); print(u) }
    function other<V>(v: V) { print("O"); print(v) }
    function cb(f: (b: boolean) => void, b: boolean) { f(b) }
    function main() {
      let r = inner
      const fs = [r]
      fs[0](3)
      r = other
      cb(r, true)
    }
    main()
    // vl check: rc 0.  vl run: prints I true O true

Want:

    I
    3
    O
    true

#### Mechanism

Not located. D3977's list pin follows only elements that name a generic by name or through
never-written aliases; `r` is written after the list reads it (`r = other`), so the list keeps the
generic's unpinned value, the element call pins nothing, and the delivery `cb(r, true)` instances
`inner` at `boolean` for the list's element too. Pinning the list at its element calls would be
wrong for the same reason in the other direction once `r` is written before the list reads it
(`rv3505/r5/g04`), which is refused.

| `r` a module-scope `let` (`r5/f07`) | prints `I true O true` | no |
