### D16376 — a parenthesised value `if` joining a radix constant with an i32 value, beside an i64 operator peer, emits invalid wasm

**check-clean invalid wasm · `type mismatch: expected i32, found i64` · 1 of 21 reduced programs of the oracle's arithmetic fuzz (8 seeds) · found by the independent oracle (`scripts/oracle/fuzz.sh`) · filed 2026-11-15 against master `6c486842e`**

Repro:

    const c = true
    const v5: i32 = 3
    const v2: i64 = 5
    print((if c { 0x7 } else { v5 }) + v2)
    // vl check: rc 0.  vl run: invalid module, type mismatch: expected i32, found i64

Want:

    12

#### Mechanism

The typed arm makes the join i32, and the i64 peer widens it. The decimal spelling of the same
arm (`7`) does so and prints `12`. With a radix constant arm, the parenthesised `if` is emitted
as i32 but read as i64, the way [D16374](D16374.md)'s all-constant `if` is. The radix arm seems
to make the join look constant-tailed to one side and typed to the other.

#### Ablation

| ingredient removed | outcome | needed? |
| --- | --- | --- |
| the radix spelling (`{ 7 }`) | prints `12` | **yes** |
| the i64 peer (`v2: f64 = 5.0`) | prints `12` | **yes** |
| the parentheses: bind first (`const x = if c { 0x7fffffff } else { v5 }`, then `x + v2`) | runs | **yes** |
| an i64 destination instead (`const y: i64 = if c { 0x7fffffff } else { v5 }`) | runs | no, a sibling |
| which side the peer is on (`v2 + (…)`) | still invalid | no |

#### Grading list

`0x7fffffff` and `0xFFFFFFFF` in the radix arm, a `match`, and D16374's spellings.
