### D17161 — the IR misses a read of a `null`-typed binding delivered to a `string | null` or `boolean | null` destination

**runs today and must keep running · an IR coverage defect · filed 2026-11-24 against master `b8dcfc1ba` by lane IR-N2 (found in [D17160](D17160.md)'s record-field witness)**

Repro:

    function f(): string | null {
      const g = null
      return g
    }
    print(f() == null)
    // VL_IR_SHADOW=1 vl run: `f` is `uncovered null unit read rep`

Want:

    true

#### Mechanism

Legacy writes a read of a `null` unit binding on the `nulnone` arm as its destination's null
(`emitNullAt`). The IR's twin in `ir_build.vl` (the local, global and capture read arms, and
`nulUnitPlaceRead`) builds it only when `nullOwnAt` names an owner whose null
`nullOwnRepFits` the destination's rep; for a `string | null` or `boolean | null` destination it
does not, and the read is the named miss `null unit read rep`. A nullable record destination fits
and is covered.

#### Ablation

| ingredient changed | outcome | needed? |
| --- | --- | --- |
| `return null` (the literal, not a binding) | covered | **yes**, a binding |
| the binding a parameter `g: null`, a module `const g = null`, or a record field `{ tag: g }` | still `null unit read rep` | no |
| destination `boolean \| null` | still `null unit read rep` | no |
| destination `P \| null` for a record `P` | covered | **yes**, a scalar nullable |
| destination `i32 \| null` | `uncovered box of a null` (another arm) | — |
