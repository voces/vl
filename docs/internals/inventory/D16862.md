### D16862 — a callee's failed bound names its body site as `line:col` text, with no structured related location, and none at all across modules

**loud check reject · the refusal is correct; the gap is the diagnostic's shape · filed 2026-11-16 against master `9648a5f2a` (L2 S3.5)**

Repro:

    function inc(x) { return x + 1 }
    print(inc("a"))
    // vl check: argument 1: operator '+' is not defined for string and i32 (`inc` applies '+' to parameter `x`, at 1:26)

The refusal at the call is correct. What is missing is a related location the CLI, the LSP and the
cases oracle all carry as data, rather than `at 1:26` in the text; and with `inc` exported from
another module, the text carries no site at all.

#### Mechanism

S3.5 (choice 1, wording B) reports a failed bound at the call and names the body site in the
message text (`, used at L:C`, `atCallWhere` in `compiler/check_at_call.vl`). `T.diags` has no
related-location field, so the site is text only. `siteAtSuffix` leaves it out when the body sits
in another module than the call, because a bare `L:C` there would read as the call's own file.

#### Ablation

| ingredient changed | outcome | needed? |
| --- | --- | --- |
| `inc` exported from `lib.vl`, called from `main.vl` | the message names no site | **yes** (another module) |
| `inc(x: i32)` annotated | refused at the argument by the direct check, no body site | **yes** (the hole) |

#### Grading list

  structured note moves them out of the message text.
- The LSP's diagnostic `relatedInformation`, and `tests/support/casesWasmOracle.ts`.
