### D15113 — two unbound record literals of one un-annotated function and another field, called through the field at two signatures, are refused at emit

**loud emit reject · `emitProgram: a function value is called at two signatures, and the closure it holds was built for one: this call passes a wider number than its i32 parameter` · clause 2 · open · each literal alone runs, and the same two records bound runs · found closing D15206 · filed 2026-11-03 against #6148's branch `d3ae7d29` plus D15206's close**

Repro:

    function inc0(a) { return a + 1 }
    print({ f: inc0, n: 1 }.f(3))
    print({ f: inc0, n: 1 }.f(2.5))

Want:

    4
    3.5

#### Ablation

| spelling | outcome |
| --- | --- |
| the witness | loud emit reject |
| the `f64` literal alone | runs, `3.5` |
| `const a = {…}; const b = {…}; a.f(3); b.f(2.5)` | runs, `4 3.5` |

#### Mechanism

Not yet ablated. The likely mechanism is that the two literals are adopted at one record whose `f`
is `(i32) => i32` (`nodeRepTyIxOf`), so D15206's pin builds `inc0` at `i32` for both. The bound twin
runs because each binding's reads pin its own field.
