### D12601 — a phantom alias parameter forwarded through a generic has no instance argument type at the inner call

**closed 2026-10-31 — the filed repro RUNS and prints `8` · a composite parameter riding type parameters pins at the type the elaboration gives it at the call (`monoElabCompositeTy`, emit_mono.vl) before `monoPinTyParamComposite` · fixture `tests/cases/generics/composite-param-pins-forwarded-phantom-alias.vl` · was: loud emit reject · clause 2 · CAPABILITY, the program is type-valid · open · site `emit_mono.vl`, `` monomorphize: unsupported argument type for `<param>` in a call to `<fn>` `` · found by lane L3 closing [D12470](D12470.md) · present on master `1a747b413` · filed 2026-10-24 against master `1a747b413`**

Repro:

    type Rows<T> = { base: i32, count: i32 }
    function stride<T>(_self: Rows<T>) { return 7 }
    function outer<T>(r: Rows<T>): i32 { return stride(r) + 1 }
    const st: Rows<i32> = { base: 1000, count: 4 }
    print(outer(st))
    // vl check: rc 0.  vl build: unsupported argument type for `_self` in a call to `stride`

#### Mechanism

Inside `outer`'s instance the argument `r` is typed `Rows<T>` with `T` already bound, but the
phantom `T` leaves no trace in the record `Rows<_>` resolves to, so the inner call to `stride`
cannot name the argument's type at its instance and is refused.

#### Ablation

| ingredient changed | outcome | needed? |
| --- | --- | --- |
| `Rows<T>` uses `T` (`x: T[]`) | runs | **yes** (the phantom parameter) |
| `flat type F` in place of `i32` | the same refusal | no |
| `stride(st)` called directly | runs | **yes** (the forwarding generic) |
