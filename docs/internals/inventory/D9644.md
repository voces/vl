### D9644 — a list element record of an un-annotated function and an element of an annotated record list handed to one un-annotated parameter has no interned call signature

**closed · runs, prints `4` `0.5` · was loud emit reject, `vl check` rc 0, `emitProgram: a function-value call has no interned signature`, clause 2 · found closing [D9570](D9570.md) · filed 2026-10-22 against master `9e81d3ee3` · closed by leaving such a list's element open when its one read is handed to an un-annotated parameter whose body calls each function field at closed arguments (`monoRecListFieldCalledAtHole`, emit_mono.vl), so `monoOpenFnRecSrcPin` instances the function at that call · fixture `closures/hole-fn-inline-record-list-beside-other-record.vl` · closed with [D9640](D9640.md) and [D9730](D9730.md)**

Repro:

    type R = { f: (a: i32) => f64 }
    function inc0(a) { return a + 1 }
    function take2(a) {
      print(a.f(3))
    }
    const xs = [{ f: inc0 }]
    take2(xs[0])
    const ys: R[] = [{ f: (a: i32): f64 => 0.5 }]
    take2(ys[0])
    // vl check rc 0.  vl run: emit error: emitProgram: a function-value call has no interned signature

#### Mechanism

The flow table sees no call through the slot `e`/`f.f` of `xs`, because the call happens in the
body of an un-annotated parameter, so `monoPinListRecords` typed the list at the uncalled
default `(i32) => i32` ([D9100](D9100.md)) and `inc0` got the stub an uncalled function gets.
Alone, `a.f(3)` is rewritten to `inc0(3)` and the stub is never called; with `ys` the literals
reaching `take2` disagree, the call stays indirect, and nothing interned its signature.
