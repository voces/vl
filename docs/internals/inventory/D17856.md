### D17856 — an un-annotated function's hoisted signature is minted with a pending return that the inference writes into the row in place

**runs today and must keep running · refactor target: S2b keeps a function row minted with `RET_PENDING` out of the intern table because this writer patches it (coordinator ruling) · filed 2026-11-28 against master `8109888ab` · owner COV-IS**

Repro:

    function f(x: i32) { return x + 1 }
    print(f(2))
    // vl check: rc 0.  vl run: 3

Want:

    3

#### Mechanism

The top-level hoist (`check_top_level.vl`, `declareDecl(six, s.fnName, mkFuncTy(hpt, hret))`)
mints the signature with `RET_PENDING` when the return is inferred; `finishInferredReturn`
(`check_inferred_return.vl`, `bt.fnRet = inferred`) and the `if`-join re-bank in
`check_relate_core.vl` (`bt.fnRet = res`) then write the bound row in place, so every holder of
the row reads the inferred return. On the self-compile 6,859 hoisted rows are minted pending and
all are patched. A row shared by structure would carry one function's return to another's
holders. The close mints the finished signature as a row of its own and re-binds it.

Every un-annotated function in `tests/cases/functions/`.
