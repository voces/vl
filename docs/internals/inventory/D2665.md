### D2665 — a tail `if` whose arms assign a map cell and a nullable-map cell has no map result

**loud emit reject · `emitProgram: bare null needs a struct-typed context` · found grading D2662 · filed 2026-09-26 against master `2e4ed7b7d`**

Repro:

    type S = { a: i32 }
    function mkR(v: i32): {[string]: S} {
      const m: {[string]: S} = Map()
      m["a"] = { a: v }
      return m
    }
    let gd: {[string]: S} | null = null
    let gc: {[string]: S} = mkR(1)
    function fc(c: boolean) {
      if c { gc = mkR(8) } else { gd = mkR(7) }
    }
    const r = fc(false)
    const v = r["a"]
    if v != null { print(v.a) }
    // vl check: rc 0.  vl run: emit error at `v != null`

#### Mechanism

The checker types `fc`'s result as the map, since each arm's assignment yields its right side.
The emitter's arm join (`ifTailAssignName`) mints one representative cell only when the arm
cells agree, and a `map` cell and a `nulmap` cell differ in kind, so the join declines. The
fallback rungs have no map shape for a tail `if` of assignments, so `r` becomes the mono map
and the read of `r["a"]` is not a struct. A straight tail `gd = mkR(7)` into the same nullable
cell runs and prints `7`. So does the same `if` over two non-null cells, since D2662.
