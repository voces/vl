#### Mechanism

Traced on close: the anonymous row's code-5 field records its element's row name
(`anonFieldElemName`), and the code-5 arm returned `""` for an EMPTY literal before the arena
rung that reads the recorded element type, so the field row carried no element and no type
(`sFieldElemTyIx` -1) and `sFieldRefSlot` found nothing. With that arena rung reached, a second
order fact showed: a holder minted BEFORE its pushed element's literal keyed the element by its
nominal render, and the element's own row then minted under another name, so the holder's
literal matched no row (`object literal field count does not match struct`; `{ xs: [] }` then
`const q = { x: 1 }` refused while the reverse order ran). `collectAnonShapes` now mints a
holder whose empty-list field holds a record after every other literal
(`anonHolderAwaitsElemRow`), inner holders first: a holder whose element is another late
holder's record waits a round for that row (`{ xs: [] }` holding `{ ys: [] }` holding
`{ a: 1 }`, the #3398 review's witness, refused at both scopes until then). The
hole-parameter twin of that nesting is [D3745](D3745.md), still open. The filing's reading follows.

Not traced to the line. The push pins the element through `r.c`, the record's field type, and
the checker is satisfied. The emitter's struct row for the literal's shape records the field as
a ref list (code 5) whose element row `sFieldRefSlot` cannot find, so `pushFieldStorage` refuses.
Every ref element does it (a record, a union, `i32 | null`, and D2506's `_ | null` filled to any
`T`), and no scalar one does (`i32`, `f64`, `string` run), which points at the element row being
interned under a key the field's lookup does not ask. A non-empty literal (`{ c: [{ a: 1 }] }`)
and an annotated binding (`const r: { c: C[] } = { c: [] }`) both run.
