#### Mechanism

A function type's `$fnsig` key spelled its result with `tyToEmitName`, about `7·2^depth`
characters, and looked the row up by that spelling (`sigRetTokOfTy` → `annRetKindTy` →
`structIndexOfTypeName`). Past 4096 characters `repNameCanonId` declines, so the nested-field
compare of the field-set scan answers true and the scan takes the first `{l, r}` row, `A1`.
The call was keyed `i>s1;` and `call_indirect` used `A1`'s functype. Parameters already had an
arena rung (`sigDeclRecTokOfTy`); results did not. The loud face came from the same lookup
in `structIndexOfCallExpr`, which named `A1` as the receiver of `g()(5)` or `fs[0](5)`, so
the eleventh `.l` found no field. Both now keep the render's answer that the result is a
struct and take the row from the type: its declared name's row when the type's rep slot
agrees, or the rep slot of a record with no name (the element of a list of an aliased
function type), declining when another row could share it (`sigRowHasNoTwin`,
`sigRowHasNoArmTwin`).
