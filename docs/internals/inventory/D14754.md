### D14754 — an un-annotated binding of a join of literal-bound consts is typed by their literal set but stored as a string

**runs today and must keep running · refutation pin: switching `emitExpr`'s string-to-atom hook from `ExpCtx.litUnion` to the closed contextual type lowers this join's arms as atoms into a string local · filed 2026-11-01 against master `8f56525b`**

Repro:

    const A = "x"
    const B = "y"
    function main(c: boolean) {
      const M = if c { A } else { B }
      print(M)
    }
    main(true)
    main(false)

Want:

    x
    y

#### Mechanism

The join's value leaves record the join's type, `"x" | "y"`, as their contextual type, and
`repOfTy` of that set is the i32 atom. The binding `M` is stored as a string (`(local $1 (ref
$0))`), so the arms must lower as strings, which today they do only because the delivery flag
is off. A reader that asks the contextual type turns each arm into an atom. One side is wrong:
either the binding is stored as the set it is typed, or the join of two const reads is typed
`string` as the same join of literals is.

#### Ablation

| ingredient removed | outcome | needed? |
| --- | --- | --- |
| the const reads (`if c { "x" } else { "y" }`) | the leaves' record widens to `string`, agreeing with the storage | **yes** |
| the binding's absence of annotation (`const M: "x" \| "y"`) | `M` is stored as the atom, agreeing with the type | **yes** |
