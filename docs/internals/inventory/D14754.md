### D14754 — a value read out of a built container, handed to a hole parameter that stores, captures or returns it, refuses

**closed · now runs, prints `4` then `4` · was loud check reject, clause 2 · filed 2026-11-01 against master `1d98f35a` · closed 2026-11-01 against master `8ab2cf7d`: a returned by-rep parameter takes the rep where the call's result is read for a field or handed on by rep (`recRetTakesRep`) · fixture `soundness/built-container-read-returned-by-rep-runs.vl` · binding, storing and capturing the value are [D14810](D14810.md)**

Repro:

    type J = { f: i32 | null }
    function mk() { { f: 4 } }
    function back(r) { return r }
    const wideJ: J = mk()
    const xs = [mk()]
    print(back(xs[0]).f)
    print(wideJ.f ?? 0)
    // vl check: this {f: i32} is stored at J, ... type-valid but not supported yet

#### Mechanism

`xs`'s elements are built at `J`. A by-rep instance (D14532) serves a hole parameter that is only
read or written for a field (`recParamTakesRep`), and the instance's own reads take the rep.
Storing the parameter in a literal's field, capturing it in a closure, or returning it hands the
`J` on to a position typed `{f: i32}` outside the instance's field reads. `recBuiltReadRefuse`
refuses those deliveries.

#### Ablation

| ingredient removed | outcome | needed? |
| --- | --- | --- |
| `back` reads `r.f` instead of returning `r` | runs | **yes** |
| `const wideJ: J = mk()` | runs | **yes** |
| a generic `back<T>(r: T): T` in place of the hole | still refuses | no |
