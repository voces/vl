### D16493 — pinning a generic's function-typed parameter asks the write-scan index about a lambda minted after it was built, and the compiler traps

**closed 2026-11-15 · now a loud emit reject · was compiler trap, clause 1 · `vl run`: `emitProgram: monomorphize: unsupported argument type for `g` in a call to `compose``, [D16412](D16412.md)'s sentence, as every neighbouring spelling gets · closed by two readers' fixes: `elabTopFn`, `elabModuleLam` and `elabEnclosingFn` (emit_elab.vl) treat a node minted after the write-scan index as one it does not describe, and `monoBindArenaFullTys` (emit_mono.vl) reports a binding that disagrees with an earlier closed one, which `monoPinTyParamComposite` refuses for a function-typed parameter · test `generics/error-hole-fn-instance-composed-with-generic.vl` · found by the independent oracle's higher-order generator (fuzz cells `ho_s3_0015`, `ho_s9_0097`) · filed 2026-11-15 against master `d31ab4440`**

Repro:

    function hid(x) { x }
    function gid<A>(x: A): A { x }
    function app<A, B>(f: (x: A) => B, x: A): B { f(x) }
    function compose<A, B, C>(f: (x: A) => B, g: (x: B) => C): (x: A) => C { (x: A) => g(f(x)) }
    print(hid("a"))
    print(compose(gid, hid)(5))
    print(app(gid, 7))
    // vl check rc 0; vl run: emit error, unsupported argument type for `g` in a call to `compose`

Want:

    a
    5
    7

#### Mechanism

`monoPinAnnotatedParam` pins `compose`'s `f`/`g` from the argument's held type, which
`elabHeldValTy` reaches through `elabHeldFnTy`; that asks `elabModuleLam` whether the held lambda
sits at module level, and `elabModuleLam` reads `cwIxParent` through `cwIxCovers`. The lambda it
asks about was minted after the write-scan index was built (an instance made by the earlier
`app(gid, 7)` or `hid("a")` instantiation), and `cwIxCovers` traps on such a read by design rather
than answer from a column that cannot describe the node. The minted node is `hid$1`, the instance
`hid("a")` made. Answering from its source (`nodeSrc`) makes a closed instance look demandable at
another signature, so the readers do not ask: a minted node is not top-level, not module-level,
and not reached by the parent table (`-2`). Building the index after elaboration has no point to
build at, since the monomorphizer mints instances while elaboration is still asked about them.

Behind the trap, `hid` is held at its one instance, `(string) => string`, while `gid` binds
`compose`'s `B` at `i32`. `monoBindArenaFullTys` kept the first binding and dropped the second
without a word, so `compose` was instanced with `g` at a type its argument is not, and the module
failed to validate. It now reports the disagreement, and a function-typed parameter refuses.
