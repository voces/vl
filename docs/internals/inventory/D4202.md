### D4202 — `!= null` after a literal test over `M | null` reads the box where the checker leaves literals of one kind

**closed 2026-10-12 by lane CK · runs · was check-clean invalid wasm · found reviewing #3577 · filed 2026-10-12 against master `0bf4c3bb6` · pins: `tests/cases/literal-unions/null-compare-after-literal-test.vl`**

Repro:

    type M = 1 | "a" | "b"
    function pm(i: i32): M {
      if i == 0 { return 1 }
      if i == 1 { return "a" }
      "b"
    }
    function f(i: i32) {
      const x: M | null = if i > 5 { null } else { pm(i) }
      if x is 1 { print(x + 1) } else if x != null { print(x + "?") }
    }
    f(1)

Want:

    a?

#### Mechanism

The else of `x is 1` over `1 | "a" | "b" | null` pushed no emitter narrowing, so the later
`!= null` complement gave the emitter `i32 | string` while the checker typed `x` as `"a" | "b"`.
Both null-compare sites in `compiler/emit_classify.vl` now ask `nullCmpLitBase`: when every
non-null member is a literal of one base, the value narrows to that base.

#### Ablation

| variant | outcome before |
| --- | --- |
| as filed | invalid wasm |
| drop `else if x != null` (plain `else`) | refused, `null` still a member |
| `K \| null` with `K` all strings | runs |
| `1 \| 2 \| "a" \| null` | runs, the base is mixed |

#### Grading list

The `== null` else and `x == 1 || x == null`.
