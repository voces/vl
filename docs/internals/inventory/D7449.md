### D7449 — an un-annotated `[]` first written a one-literal value stores the atom into a `string` list

**closed 2026-10-20 by lane L6 · runs, prints `x=circle` · was check-clean invalid wasm · clause 1 · an open container's pin from a lone string literal is its one-member set (`cnhPinTy` takes `strLitAsSet`), as `mkArrayTy` and `mkMapTy` store a declared one, so the pinned list is the atom list its element already is · pin: `tests/cases/maps/one-literal-map-value-delivery.vl` · found closing [D7446](D7446.md) · present on master `573358403` · filed 2026-10-20 against master `573358403`**

Repro:

    type C = { kind: "circle", r: i32 }
    function mkC(n: i32): C { { kind: "circle", r: n } }
    const xs = []
    xs.push(mkC(2).kind)
    print("x=" + xs[0])
    // vl check: rc 0.  vl run: invalid module, expected (ref $1), found i32; $1 is `string`

Want:

#### Mechanism

`kind: "circle"` is a record field of one literal, an atom since [D7340](D7340.md). The
`[]`'s pin took the value's type as written, a bare `TyLit`, which softens to `string` at
the list's rep, so the push stored the atom into a string list. The same pin of an
un-annotated `Map()` read its value back as the atom niche once [D7446](D7446.md) made a
nullable inner of one literal its set, which the capability matrix
`one-literal-field-widen-to-string` showed as two new SILENT cells before this close.
