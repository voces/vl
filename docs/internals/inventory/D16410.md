### D16410 — a generic function handed to a generic's `(x: A) => A` parameter, its `A` taken only from the destination, is delivered as its `i32` instance

**loads then traps · clause 1 · open · `wasm trap: indirect call type mismatch` · a sibling of [D4122](D4122.md) (`sel<F>(f: F)`), the function-typed parameter is the new ingredient · found by the independent oracle's higher-order generator (`scripts/oracle/gen_hof.ts`, cases 12 and 13) · filed 2026-11-15 against master `33ef972d7`**

Repro:

    function gid<A>(x: A): A { return x }
    function sel<A>(f: (x: A) => A): (x: A) => A { return f }
    const k: (x: f64) => f64 = sel(gid)
    print(k(1.5))
    // vl check: rc 0.  vl run: wasm trap: indirect call type mismatch, at `print(k(1.5))`

Want:

    1.5

#### Mechanism

Nothing at the call `sel(gid)` binds `A` but the destination's `(x: f64) => f64`. The value
stored in `k` is called through the `f64` signature, but it is not an `f64` instance of
`gid`; the `i32` destination runs, so the instance taken is `i32`'s. From the ablation; the
instance's signature has not been printed.
