### D16410 — a generic function handed to a generic's `(x: A) => A` parameter, its `A` taken only from the destination, is delivered as its `i32` instance

**closed 2026-11-15 by lane K · runs, prints `1.5` · was loads then traps, clause 1, `wasm trap: indirect call type mismatch` · owner ruling 2026-11-15: the destination binds a callee type parameter no argument binds · `dstBindOpenFnTyParams` (check_assignable.vl), asked from `checkCallOnFuncTy` (check_calls.vl) · fixture `generics/generic-fn-at-generic-fn-param-bound-by-destination-runs.vl`, matrix `generic-fn-at-generic-fn-param-bound-by-destination.matrix.vl` · a sibling of [D4122](D4122.md) · found by the independent oracle's higher-order generator (`scripts/oracle/gen_hof.ts`, cases 12 and 13) · filed 2026-11-15 against master `33ef972d7`**

Repro:

    function gid<A>(x: A): A { x }
    function sel<A>(f: (x: A) => A): (x: A) => A { f }
    const k: (x: f64) => f64 = sel(gid)
    print(k(1.5))
    // master: vl check rc 0, vl run: wasm trap: indirect call type mismatch.  now: prints 1.5

Want:

    1.5

#### Mechanism

Nothing at the call `sel(gid)` binds `A` but the destination's `(x: f64) => f64`. The value
stored in `k` is called through the `f64` signature, but it is not an `f64` instance of
`gid`; the `i32` destination runs, so the instance taken is `i32`'s. From the ablation; the
instance's signature has not been printed.

#### Grading list

The witness at `f64`, `i64` and `string`, at each of the three destinations above (an annotated
`const`, an annotated parameter, a re-pointed `let`), must print the argument; `gen_hof.ts`
cases 12 and 13 at `--stmts 1` grade the set. The two `i32` faces, which run on master because
the instance defaults to `i32`, are the named cells `d16410_dest_i32` and `d16410_call_i32`
(`distilled/named/`, block `d16410-accidental-default`): a refusal of this row may not stop them.

#### Fix

The destination's type is walked against the callee's generic result (`bindGenWalk`) and binds
each type parameter no argument binds, when every parameter naming it is a function type handed
a generic function or one with an un-annotated parameter, and no other argument binds a type
parameter of that slot. A result-only type parameter (`mk<T>(): T[]`, [D9073](D9073.md)) is
outside this rule and stays refused. With no destination ([D16411](D16411.md), [D16412](D16412.md))
nothing changes.
