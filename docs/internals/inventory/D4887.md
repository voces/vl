### D4887 — a record literal whose field is a type parameter's list mints no row in a generic instance

**closed · was a loud emit reject (`emitProgram: object literal but no struct type declared`), identical on master `b8dc4604d` · fixture `tests/cases/generics/generic-complement-list-delivery-positions.vl` (`plain`) · filed 2026-10-15**

Repro:

    function g<T>(v: T[]) {
      const r = { xs: v }
      print(r.xs[0])
    }
    g(["d"])
    g([5.5])

Want:

    d
    5.5

#### Mechanism

`mintPinnedObjLit` (D3032) mints an instance's row for a literal whose field is a bare type
parameter, binding it from the field value's pin. A field at `T[]` is neither that nor a
union, so it fell through and minted nothing. Such a field now mints the record substituted
through the instance's own bindings, as a union field already did (D2906). The row match
(`pinRowFits`) already compared any field holding a type parameter by its pin.

#### Ablation

| ingredient removed | outcome | needed? |
| --- | --- | --- |
| the type parameter (`v: string[]`) | runs | **yes** |
| the list (`v: T`, printing `r.xs`) | runs | **yes** |
| the second instance (`g(["d"])` alone) | still refused | no |
