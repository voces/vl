### D1608 — calling a captured function value falls off the callee ladder into `call to unknown function`

**closed · filed 2026-09-05 against master `4b0af3a4` · closed against `153760e1`**

`identIsBoundClosure` grew the capture rung it lacked. All 12 grid cells now run, plus 8 more
the grading list named; 106 of 106 graded matrix cells over two position templates, 0 silent
and 0 `runs` lost; capability probes 142/149 → 143/149.

Repro:

    function go() {
      const inner = (n: i32) => n + 5
      const outer = (n: i32) => inner(n)
      print(outer(50))
    }
    go()
    // vl check: rc 0.  vl run: emitProgram: call to unknown function

#### Mechanism

`emitCall`'s identifier-callee ladder (`compiler/wasmEmit.vl`, the `target < 0` arm) asks
`fnIndexOfInScopeChain` for a lifted function, then `exprIsClosure(c.callFn, fnIx)` for a
closure-valued binding, then the numeric intrinsics, and ends at
`emitFail("emitProgram: call to unknown function")`. A name bound in the ENCLOSING frame — a
capture, read at every other use through `emitCapturedRead` off the env struct — resolves to
no lifted function and is not recognised by the closure arm, so the walk reaches the floor. The
refusal is a fall-through, not a judgement: `vl check` returns 0, so this is a clause-2
violation by construction.

MEASURED, the declining rung is one level below the one named above. Instrumenting the floor
to print what it receives gave, for the witness:

    D1608RUNG name=inner fnIx=14 fe=2 target=-1 fnIndexOf=-1 exprIsClosure=F
              identIsBoundClosure=F capturedKindOf=closure cloCallSigKey=[i>i] caps=[inner,]

`capturedKindOf` — the classifier that TYPED the env field — already answered `closure`, and
`cloCallSigKey` already resolved the callee's `$fnsig`, so `emitCallRef` had everything it
needed. What declined was `identIsBoundClosure`, the binding ladder `exprIsClosure`'s `Ident`
arm delegates to: it has rungs for a narrowed arm, a closure param, a nullable param, a
declared local slot and an arena parent-let, and no rung for a CAPTURE. `exprNulClosure`
already asked `capturedKindOf` for the nullable half of the same question, which is what
makes the missing rung a hole rather than a design line. The fix adds it below the local
rungs, so a same-named local of the frame still shadows.

The taint follows the VALUE, not the name: rebinding the capture to a fresh local inside the
lambda (`const g = inner; g(n)`) refuses at the `g(n)`, which is what rules out "the captured
spelling is unresolvable" and leaves "the closure predicate cannot see through a capture".

#### Ablation

Every row is `vl check` rc 0. `outer` is the lambda, `inner` the function value it captures.

| spelling | outcome |
| --- | --- |
| capture a lambda, call it in the lambda (the witness) | **emit reject** |
| capture a function-typed local bound to a named function, call it | **emit reject** |
| the same with the local un-annotated (`const inner = add5`) | **emit reject** |
| capture a function-typed PARAMETER, call it | **emit reject** |
| capture it, rebind to a local inside the lambda, call the rebind | **emit reject** |
| call the same local in its OWN frame, uncaptured | runs, 55 |
| read the capture and PASS it as an argument, never call it | runs, 55 |
| capture a STRUCT and call its closure field (`b.op(n)`) | runs, 55 |
| read a module GLOBAL closure inside the lambda and call it | runs, 55 |
| declare a closure-valued local INSIDE the lambda and call it | runs, 55 |
| call the lambda's OWN function-typed parameter | runs, 55 |
| capture an `i32` and use it (capture itself) | runs, 55 |

Needed: the callee being a value that reached this frame as a CAPTURE, and the use being a
CALL. Not needed: the annotation, the value being a named function rather than a lambda, the
lambda body's shape, or the closure arriving as a parameter rather than a local.
