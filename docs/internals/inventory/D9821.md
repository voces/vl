#### Mechanism

The destination is annotated, as the message asks. The same program with `f: (x: T) => T`
and no `null` call ran and printed `30`. The pin that fixes `T` from the destination
(`monoSlotPinAnn`, emit_mono.vl) split the destination's parameter list at every comma, so
`((x: i32) => i32) | null` was read as the wrong number of parameters. It also had no spelling
for a nullable function parameter as a closed type. The close splits at top-level commas only
(`monoSigPinsTop`) and spells the nullable function (`monoConcreteNulFnTyName`). This is a
different root from [D9820](D9820.md)'s.
