### D9821 — a generic with a nullable function parameter returned by an un-annotated function is refused at an annotated destination

**loud emit reject · `vl check` rc 0 · `emitProgram: a generic function taken as a value reaches no call that fixes its type — annotate the destination's function type` · clause 2 · found closing [D9772](D9772.md) · present on master `260b24edd` · filed 2026-10-22 against master `260b24edd`**

Repro:

    function g<T>(f: ((x: T) => T) | null, x: T): T { if f != null { return f(x) } x }
    function __deliver() { return g }
    const v: (f: ((x: i32) => i32) | null, x: i32) => i32 = __deliver()
    print(v((x: i32) => x + 1, 2) * 10 + v(null, 5))
    // vl check rc 0.  vl run: emit error: ri.vl:2:31: emitProgram: a generic function taken as a value reaches no call that fixes its type — annotate the destination's function type

#### Mechanism

Not traced. The destination is annotated, as the message asks. The same program with
`f: (x: T) => T` and no `null` call runs and prints `30`, so the copy of the return that fixes
`T` from the destination does not read a nullable function parameter. That path is in
emit_mono.vl. Whether this shares [D9820](D9820.md)'s root is a prediction, not a measurement.

#### Ablation

| ingredient removed | outcome | needed? |
| --- | --- | --- |
| the `\| null` and the `v(null, 5)` call | runs, `30` | **yes** |
| `__deliver`, for `const v: (…) => i32 = g` | runs, `35` | **yes** |
