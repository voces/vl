### D5344 — an un-annotated `Map()` whose value is a record literal with an empty list field has no value rep

**closed · was loud emit reject · `vl check` rc 0 · clause 2 · found closing D5282 · filed 2026-10-17 against master `cd07cb6a8`**

Repro:

    const m = Map()
    m["k"] = { v: 1, kids: [] }
    const x = m["k"]
    if x != null { print(x.v) }
    // vl check: rc 0.  vl run: emitProgram: unsupported map value type (no rep for a union-member struct, a nullable list over an unnamed element rep, ...)

Want:

    1

#### Mechanism

The checker admits an empty `[]` as a record literal's field value and leaves its element an
open hole (`{ v: i32, kids: _[] }`). `flushUninferred` grades only a binding whose own type is
the hole, so nothing ever defaulted it or refused it. The emitter then had no element rep for
the field, so the record interned no row: a binding said `object literal but no struct type
declared`, and a map holding it had no value rep. The Map is the population's largest face,
not its cause.

Fixed in the checker. `objFieldHolesToI32` (`check_narrow_flow.vl`) runs at program end, after
every pin, and defaults such a hole to `i32`, as `__array_new_default__` already does. Nothing
stores an element into the list, so no read can tell the default apart; a later `push` still
pins the element first. `==` now makes each operand the other's destination
(`checkEqualityBinNode`), so `{ v: 1, kids: [] } == same` pins `kids` at `N[]` and does not take
the default. Graded by `record-lit-empty-list-field.matrix.vl` (28 un-annotated cells refused
before, 64 of 64 run after), `recursive-record-eq.matrix.vl` (3 map cells refused before, 66 of
66 after) and `tests/cases/structs/record-lit-empty-list-field.vl`. D5470 and D5471 are the two
neighbours this fix does not reach.
