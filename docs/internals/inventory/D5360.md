#### Mechanism

From the ablation only. The inferred return of `mk` is `k`'s open `(T) => T`, and `h(1)` binds
it at `(i32) => i32`, but the bare `return k` is emitted as a value of the generic's stub: no
pin of `mk`'s return slot reaches the `return`. D5062's close carries a pin across an inferred
return for a WRITTEN `let` of a generic (`monoRetypePinCalls`); a bare `Ident` naming the
generic is not that route.

The close: `ffIdent` banks the class of a named function's read under the read node, so its
pins are asked as a binding's are (`monoSlotPinName`). `monoWalk`'s `return` arm, in a function
with no declared result, delivers a declared generic at the one pin past the return and types
each call taking that pin at it (`monoCoerceRetAtPin`). A second defect stood behind the first,
for concrete functions too: `collectFnValUse` never counted `return f` as a function-value use,
so a call through the result had no interned signature. An alias returned bare is
[D5400](D5400.md); the result handed to an un-annotated parameter is [D5401](D5401.md).
