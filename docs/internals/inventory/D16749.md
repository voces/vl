### D16749 — two maps of records whose function-field sets share a member pin the shared field at no one closed type

**closed 2026-11-16 — the witness runs and prints `1.5` then `6` · was: loud emit reject · clause 1 (check accepts what emit refuses) · found closing [D16743](D16743.md) · filed 2026-11-16 against master `d14f2c88c`**

Repro:

    function inc0(a) { return a + 1 }
    function half(a) { return a / 2.0 }
    function dbl(a) { return a * 2 }
    const m = Map()
    m.set("a", { f0: inc0 })
    m.set("b", { f0: half })
    const r = m.get("b")
    if r != null { print(r.f0(3)) }
    const n = Map()
    n.set("a", { f0: inc0 })
    n.set("b", { f0: half })
    n.set("c", { f0: dbl })
    const q = n.get("c")
    if q != null { print(q.f0(3)) }
    // vl check: rc 0.  vl run: emit error, "emitProgram: internal: a function slot pinned at one signature has no one closed type the elaboration delivers it at"

Want:

    1.5
    6

#### Mechanism

The sets `{inc0, half}` (`m`) and `{inc0, half, dbl}` (`n`) were tagged apart. Planning the
smaller set first met its member names in `n`'s record literals, written into a map of the wider
set's records, and `ftRecIntoMap` (`compiler/check_fn_tag.vl`) took such a literal only into a
map of the set's own records: it now takes one into a map of a wider set's records and decides
the two together (`ftHolderListOfWider`, as a list of records of a wider set already did).
Planning the wider set first tagged it alone, and the smaller set's plan then met the same names
in `n`'s literals, built at the wider set's record: a field of a record literal built at another
tagged set's record is that set's leaf now (`ftOtherTail`). [D16811](D16811.md) is the list
spelling, which built an invalid module.

#### Grading list

- The wider map first, index writes (`m["a"] = { f0: inc0 }`), a loop over the map, a third map
  of a still wider set: run.
- A second, uncalled field (`{ f0: inc0, g: dbl }`): still refused, as a generic value
  ([D16202](D16202.md)'s family).
