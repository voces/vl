### D8381 — a record literal through a generic identity into a union member pins the identity at a declared record outside the union that shares the field names

**check-clean invalid wasm · `vl check` rc 0 · clause 1 · open · present on master `cd64d5faa` · found writing the D8320 matrix's generic template · filed 2026-10-20 against master `cd64d5faa`**

Repro:

    type J = { r: i32 }
    type N = { r: i32 | null }
    function idn<T>(v: T): T { v }
    const a: J | string = idn({ r: 5 })
    if a is J { print(a.r) }
    // vl check: rc 0.  vl run: invalid module, "expected (ref null $5), found (ref $3)": the union box expected, `N` found

Want:

    5

#### Mechanism

`monoArgPinName` (`emit_mono.vl`) pins the argument `{ r: 5 }`. Its D8021 rung asks
`variantRowOfTy` of the literal's rep type, which is the anonymous `{r: i32}` and not `J`'s
declared index, so it answers `-1`. The variant rung answers `-1` too, and the struct rung's
`structIndexOfExpr` then returns row 0, which is `N`, by the field-name set. So `idn` is
instanced at `N`, and its `N` result goes into `J | string`'s box slot raw. `N` is never used.
The cause sits in the mono pin ladder, outside the emit-collect lane.
