### D3826 — a nested `<U>` generic that captures its enclosing function's parameter has one instance per `U` pin, shared by every instance of the enclosing function

**closed 2026-10-08 by lane SC · was check-clean invalid wasm · found in review of #3425 · filed 2026-10-08 against master `cab1ee907` · pins: `tests/cases/generics/nested-generic-capture-per-enclosing-instance.vl` · residue [D3827](D3827.md), [D3828](D3828.md), [D3829](D3829.md), [D3830](D3830.md)**

Repro:

    function outer<T>(x: T) {
      function inner<U>(u: U) {
        const g = () => { print(x); print(u) }
        g()
      }
      inner(1)
    }
    outer(7)
    outer("s")
    // vl check: rc 0.  vl run: invalid module inside `outer$1`, `expected i32, found (ref $type)`

Want:

    7
    1
    s
    1

#### Mechanism

`monoCloneLambdaSubst` clones a nested function per instance of its enclosing generic, so each
clone takes its own env struct (D1780, D943), but it skips a nested function that declares
its own type parameters: those are instantiated by `monoInstantiate` at their call sites. That
instance is keyed on the callee and its own pins only, and it keeps the template's frame
(D2749). `outer$1`'s `inner(1)` therefore hits the instance `outer`'s call minted, whose env
holds `x` at `i32`, and builds that env with a string.

The close keys such an instance on the enclosing instance it is called from as well, and hangs
it off that frame (`monoNestedCallFrame`, `emit_mono.vl`). Only a capturing nested generic
called directly from an enclosing instance other than the template's own frame is keyed; a
frame-keyed instance never takes the template's slot, which keeps the template's frame for
that frame's own first instance. A call from a function nested deeper still shares the
template frame's instance ([D3827](D3827.md)).
