### D2701 — a join of two maps that store alike is the wider map, so `is` against the narrower one is false for a value built as it

**closed 2026-11-02 by lane column-G1 under the owner's ruling · runs, prints `true` · was check-clean silently wrong, clause 1 · ruling (2026-11-02): a join of two different map types is their union, `is` refines it from the member's tag (D2690's per-type tags already give it), and what every member supports keeps working on the union without narrowing, so no running program breaks · `joinWidensMap` keeps any two map types apart except two that spell one storage over a numeric literal union and its base; the map-union reads already ran through the `is` chain, and the writes `r[k] = v`, `.set` and `.delete` are rewritten to it, each arm checking the value against its member's own value type · DECISIONS.md "A join of two different map types is their union" · fixture `tests/cases/maps/join-of-two-map-types-is-their-union.vl` · the `isn` cells of the #3194 review's join grid for the same-storage pairs (`str_strnul`, `bool_boolnul`, `circ_circnul`, `arr_arrnul`) · filed 2026-09-26 against master `1a3088c65`**

Ruled 2026-11-02: every join of two distinct map types is their union (see the status line and DECISIONS.md).

Repro:

    function mk(): {[string]: string} {
      const m: {[string]: string} = Map()
      m["a"] = "x"
      return m
    }
    function mkw(): {[string]: string | null} {
      const m: {[string]: string | null} = Map()
      return m
    }
    const c = mk().length > 0
    const r = if c { mk() } else { mkw() }
    print(r is {[string]: string})
    // PRINTS false

Want:

    true

#### Mechanism

D2666 made a join of two maps whose keys or values store differently their union, and kept the
join of two that store alike as the wider map, so the join above types `r` as
`{[string]: string | null}`. A bare map carries no member tag, so `is {[string]: string}` can
only be answered from the static type, and answers false. The same join over a pair that
stores differently (`{[string]: string}` and `{[string]: i32}`) is a union, and prints `true`.

The question for the owner: should every join of two distinct map types be their union, now
that D2690's per-type tags can tell two maps of one struct apart? That makes this `true`, but
every map operation on the un-narrowed join (`r.length`) then needs a narrowing first
(`field 'length' is not on every member`), so programs that run today would stop. The
alternative keeps the join and has the checker refuse an `is` whose type the operand's static
map type already contains. Recommendation: the refusal, because it costs no running program.

#### Ablation

| ingredient removed | outcome | needed? |
| --- | --- | --- |
| the same storage (`{[string]: i32}` for the second map) | prints `true` | **yes** |
| the join (`const r: {[string]: string} \| {[string]: string \| null} = mk()`) | prints `true` | **yes** |
