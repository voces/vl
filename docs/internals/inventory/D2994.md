### D2994 — a lambda whose last statement stores a record literal into a wider declared record's place also returns it at the literal's own type

**closed · runs · was a loud emit reject, before that check-clean invalid wasm · `o` adopts `D`, so the lambda's tail store returns a `D` · fixture `tests/cases/objects/record-literal-store-in-lambda-tail-adopts.vl` · closed 2026-09-30**

Repro:

    type D = { v: f64 }
    const x: i32 = 3
    const c: {[string]: D} = Map()
    const o = { v: x }
    const f = () => { c["k"] = o }
    f()
    // vl check: rc 0.  vl run: emitProgram: this record is handed on here at its own type, and
    // elsewhere to a declared record type of the same field names that stores them differently

#### Mechanism

A store is an expression, and a lambda's block body returns its last statement's value, so
the checker types `f` as returning `{v: i32}`, the literal's own record. The map store builds
`o` at `D`'s record (D2990), and one record cannot be both, so the use walk refuses the return.
A `function f() { c["k"] = o }` declaration returns `void` for the same body and runs. The
close is either a checker rule that a store statement is no lambda's value (the named form's
rule; a language question), or building the lambda's return at the stored row.

#### Ablation

| ingredient removed | outcome | needed? |
| --- | --- | --- |
| the store as the LAST statement (`print("stored")` after it) | runs | **yes** |
| the lambda (a `function f()` declaration) | runs | **yes** |
| the map (a `D[]` element store `xs[0] = o`) | same refusal | no |
| the capture of `c` (the map declared inside the lambda) | same refusal | no |

#### Record covariance (2026-09-30)

The destination stores a numeric field at another width or kind, so under the record-covariance ruling the literal-holding binding or function is not adopted and the program keeps its master behaviour until the owner rules on [D3339](D3339.md) (DECISIONS.md "Record covariance: only a fresh value widens").

#### Close under the D3339 ruling (2026-09-30)

Closed by the owner's ruling D3339 (A): a literal-holding binding adopts a record that stores a number at another width or kind, fully (DECISIONS.md "Record covariance: only a fresh value widens"). `o` adopts `D` at the map store, so the store's value, and the lambda's inferred result, are `D`; there is no second storage to refuse.
