### D15326 — a holder of a returned record of members, stored into a field the adoption closed at one function type, refuses at emit

**closed 2026-11-04 by this PR (lane bundle) — the repro now RUNS and prints the Want below: the store takes the record's member of the field's closure type, by the rule a hand to a parameter of one closure type takes. Was: loud emit reject · clause 2 (`emitProgram: a function returning a parameter called at two signatures is called where its result is not used at one of them`) · found grading [D15324](D15324.md)'s copy-only cell · filed 2026-11-04 against master `4aca8ae14`**

Repro:

    function lap(f) {
      const _a = f(2.5)
      const _b = f(3)
      return f
    }
    const u = lap((a) => a + 1)
    const w = { f: u }
    print(w.f(4))

Want:

#### Mechanism

The one call through `w.f` is the checker's only adoption demand (`holeFieldCallAdopt`), so `w` is
pinned at `{f:(i32)=>i32}`: the field holds one closure, not the record. The slot fact declines an
annotated binding, and nothing else gave the holder `u` a fact, so its call had no member and emit
refused it. A call stored there directly runs, because its value is stored and the member is
picked at the store (`callResultMember`).

The slot fact now handles that binding: a holder read stored into a field the binding's type
closes at one function type takes the record's member of that type (`elabSlotStoreMemberNote`). The
member is chosen by `elabRecMemberAt`, the rule `elabHandMemberOf` uses for a hand, so there is no
second picker. The holder is recorded only when every read of it is that store or a call through
it at the record's signatures, and the store emits that member (`emitBundleMemberPick`, shared
with a hand). It lands with [D15324](D15324.md)'s producer fix: alone, it would honour that
adoption's one-signature pin where a copy's call at the other signature is invisible to it, and
run that call through the wrong member (D15324 records the program).
