### D15017 — a hole function writing its parameter into a `let` of generics, called only through another function's parameter, refuses at emit

**runs today and must keep running · was a loud emit reject, `vl check` rc 0, `emitProgram: monomorphize: parameter 'a' of 'take' is called at two function types that no parameter per type separates`, clause 2 · found building D15053's escape fixture · filed 2026-11-02 against master `5451eb66` · closed 2026-11-02, with the split plan on and off: the decision reads what reaches `take` through a parameter only ever called (`ftReachHandSets`, check_fn_tag.vl), so the write `b = a` holds `{id}`'s id · fixture `closures/written-let-written-hole-param-reached-through-called-param.vl`**

Repro:

    function id<T>(x: T): T {
      print("I")
      x
    }
    function take(a) {
      let b = id
      b = a
      print(b("s"))
      print(b(7))
    }
    function via(f, g) { f(g) }
    via(take, id)

Want:

    I
    s
    I
    7

#### Mechanism

The split plan copies `take`'s binding per hand when `take` is called directly, but here `take`
is reached only through `via`'s parameter `f`, so no direct call keys a copy and the one
binding meets both call types. D15053's check-time fact did not apply either: `take` is handed
on as a value, so the direct calls the check saw are not all of them. The fix follows the hand:
`take`'s one reference is an argument to `via`'s un-annotated `f`, every read of which is the callee
of a call, and that call hands `take` `via`'s own `g`, whose direct calls the check saw.
