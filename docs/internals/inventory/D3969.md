### D3969 — a generic with a value return written to a `let` of a void generic traps when called or delivered

**closed · now a loud check reject, `cannot write 'retV' to 'k': called at (i32) it returns i32, where 'inner', also written to it, returns void` · DESIGN (owner ruling 2026-11-05 (Q5, W-split): a `let` holding a function that returns nothing cannot be written with one that returns a value, or the other way round, in either order) · was loads then traps, then ran from 2026-10-10 until the ruling · found in review of #3500 (`rv3500/r5/f_gen_retV`) · filed 2026-10-10 against master `56f77d80f`**

Repro:

    function inner<U>(u: U) { print("I"); print(u) }
    function retV<V>(v: V): V { print("R"); print(v); v }
    function main() {
      let k = inner
      k = retV
      k(3)
    }
    main()
    // vl check: rc 0.  vl run: wasm trap: indirect call type mismatch

#### Mechanism

Not located. `retV` fits `k`'s type `<U>(u: U) => void` with its result discarded. The written
generic is instanced at the call's signature `(i32) => void` as D3961's close (#3517) instances it, but
its instance returns `i32`, and no adapter drops the result, so the slot holds a function of
another signature.

#### Ablation

| ingredient changed | outcome on master | needed? |
| --- | --- | --- |
| `const g: (n: i32) => void = k; g(3)`, delivered | traps | no |
| `k = other`, a void generic | runs once #3517 closes D3961 | **yes** |

#### Close

The binding's own call coerces each generic written to it at the call's type (`monoCoerceWrittenLetTys`);
where that type returns nothing and the generic's instance returns a value, mono notes the value for a
void twin (`monoNoteVoidTwin`), and `synthVoidTwins` mints one at the call's parameter types, as it does
for the checker's non-generic seam. Fixture, until the ruling: `tests/cases/generics/generic-value-return-written-to-void-generic-let.vl`, now `generics/error-generic-value-return-written-to-void-generic-let.vl`.
The delivered spelling in the ablation (`const g: (n: i32) => void = k`) is check-clean invalid wasm on
master, before and after, and is [D14785](D14785.md).

#### Ruling

Refused by design, owner ruling 2026-11-05 (Q5, W-split): a `let` holding a function that returns nothing cannot be written with one that returns a value, or the other way round, in either order. The annotated spelling already refused a void function written to a `let` whose type returns a value; `holeLetJudge` (check_relate_core.vl) now judges a member whose signature returns nothing as `void` against every member that returns a value, in both orders, so the hole and generic spellings agree with it (D15015).
