### D3037 — a record literal nesting a literal with a type-parameter field gets no row at the instance's pins

**check-clean invalid wasm · 36 cells of the D3032 position grid at the `outer` position, and 24 at the `nest` position with two instances · identical on master `3a71bb1f9` · found grading [D3032](D3032.md) · filed 2026-09-28 against master `3a71bb1f9`**

Repro:

    type X = { k: i32, n: i32 }
    function g<T>(x: T): T {
      const w = { v: { k: x, n: 1 } }
      w.v.k
    }
    print(g("s"))
    // vl check: rc 0.  vl run: invalid module, inside `g`: type mismatch: expected i32, found (ref $type)

Want:

    s

#### Mechanism

D3032's per-instance mint (`mintPinnedObjLit`) binds only a field whose checked type IS a type
parameter, so the inner `{ k: x, n: 1 }` gets its row and the outer `{ v: … }`, whose field is
a record carrying the parameter, gets none. The outer literal then resolves to a row built
from the template's type. The same scope leaves a literal inside a function nested in the
instance unminted (the walk stops at a nested function), which shows with two instances. The
close is to bind the pins through nested literal values, and to walk a nested function
against the instance that lifts it.
