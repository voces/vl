    function kg<T>(t: T): T { return t + t }

#### Mechanism

The inner `if on { idg } else { kg }` carries the set {idg, kg}, the same set `a` holds, and it
is the tail of an arm of `d`'s join, which carries {tg, idg, kg}. The one-member deferral rule
(a member name that is a tail of another set's join follows that set) covers a member NAME,
not a nested JOIN, so the two sets are decided independently and the call through `a` loses
its signature. A fix would extend the same join rule to any node carrying a set at a tail of
another set's join, with the inner set's ids mapped into the outer set's.
`closures/fn-choice-bound-impure-else-if.vl` reaches it through its `a` and `d` bindings.
