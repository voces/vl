### D16651 — a map walk's call does not pin a hole function written into a field of a map value stored from a call or a binding

**loud emit reject · `cannot take the generic function dbl as a value — … No call site pins dbl` · clause 2 · open · `vl check` rc 0 · the sentence is false: the walk calls the field it was written to · found closing [D16237](D16237.md) · filed 2026-11-15 against lane-m/d16237 (#8458), whose map-walk fix it is the remainder of**

Repro:

    function inc(n) { return n + 1 }
    function dbl(n) { return n * 2 }
    function mk() { return { f: inc } }
    const m = Map()
    m["a"] = mk()
    const r = m["a"]
    if r != null { r.f = dbl }
    for k, e in m { print(e.f(3)) }
    // vl check: rc 0.  vl run: emit error at `r.f = dbl`, no call site pins `dbl`

Want:

    6

#### Mechanism

The walk's value variable reaches the map's value slot (D16237), and the field write lands at
`m` / `[]` / `f`, as with a literal value, which runs. What differs is the stored value: a call's
result or a binding rather than a record literal. The walk does not pin a write below such a value,
while a key read of the same map (`m["a"]` bound, then called) does, and a list holding the same
value walked by `for e in xs` does.

It has two halves, found by lane R1:

- **The check half.** `elabCalleeTargets`' field read (`cwSlotWrittenValues` over `m` / `[]` /
  `f`) answers -1 on a call-stored value, because `cwSlotDescend` follows a Call only inside the
  `cwFollowCalls` window (D15562). That -1 also drops the alias write `r.f = dbl`, so `e.f`'s
  targets are `{inc}`. Opening the window at that read gives `{inc, dbl}`, with 0 corpus cells
  differing.
- **The delivery half.** With the window open, no instance is delivered to `r.f = dbl`. That is
  the `elabSlotDeliveries` face, lane S's 2b.

The window is load-bearing. Deleting it, so that `cwSlotDescend` always follows calls, is vetoed:
1 corpus cell is lost (`closures/call-result-fn-field-list-read-straight-into-param.vl`) and 3
differ (`closures/generic-fn-in-unannotated-map.vl`, `closures/hole-fn-in-unannotated-map.vl`,
`closures/hole-fn-list-returned-read-at-two-types.vl`).
