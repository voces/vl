### D1972 — `__trap__()` does not end a path, so a guard arm that traps does not narrow the code after it

**closed 2026-09-22 (owner ruling 2026-09-22: a call that never returns ends a code path, via a `never` type; `__trap__` and any function DECLARED `: never` reach the shared `stmtAlwaysExits`) · was a loud check reject, clause 2 · residue of D1970's grid (every `__trap__` cell) · credit: plumb PL-007 follow-up (`~/plumb/docs/vl-issues.md`) · filed against master `a8a104432` · fixtures `tests/cases/functions/never-call-ends-path.vl`, `tests/cases/functions/never-call-in-value-position-traps.vl`, `tests/cases/functions/error-never-function-can-return.vl`, `tests/cases/functions/error-never-outside-return-type.vl`, `tests/cases/functions/error-never-value-stored.vl`, `tests/cases/functions/error-unannotated-trapping-function-does-not-narrow.vl`, `tests/cases/lint/unreachable-after-never-call.vl`, `tests/cases/modules/never-imported/`**

Repro:

    type IoError = { msg: string }
    function f(x: i64 | IoError): i64 {
      if x is IoError {
        __trap__("io")
      }
      x * 2
    }
    print(f(3 as i64))
    // was: vl check rc 1, `operator '*' is not defined for i64 | IoError and i32`
    // now: prints 6

#### Mechanism

`stmtAlwaysExits` recognised only `return`/`break`/`continue` and the compound statements built
from them, and `__trap__` was an ordinary `void` call to the checker. The fix gives the rule one
more arm: a call statement whose type is `never`. The checker types `__trap__(…)` as `never`,
resolves a declared `: never` return (the only position the spelling is legal), and marks each
never-typed call in `callNever`; the parse-only lint marks calls by name instead. The if-arm
divergence test now runs after each arm is checked, since the mark is made while checking it.
The emitter lowers a `: never` function with no result and follows each never-typed call with
`unreachable`, which is what lets one stand in a value-position arm. Inference never produces
`never`: an un-annotated trapping function stays `void` (DECISIONS.md, "A call that never
returns ends a path").

#### Ablation

A 175-cell grid: 5 terminators (`__trap__()`, `__trap__("r")`, a `: never` `fail`, a `: never`
`die` that calls `fail`, and an UN-annotated trapping function as the control) × 5 directions
(`is` guard, `== null` guard, else-arm exits, definite assignment, top-level guard) × 5 positions
(direct, after a prelude, bare block, both arms of a nested `if`, every arm of a `match`), plus
10 value positions (if-expression, fn tail `if`, fn tail call, `match` arm, f64 join, string
join, struct join, call argument, annotated binding, and one where the arm is taken). Graded on
the base seed with the never-free prelude for the `__trap__` rows:

| terminator | guard directions (`is`, `null`, DA, top) | else-arm exits | value positions |
| --- | --- | --- | --- |
| `__trap__()` / `__trap__("r")` | check reject → runs (20 + 20) | check reject, unchanged (D1971) | 8 → runs, 1 → traps as it must, 1 runs → runs |
| `: never` `fail` / `die` | not spellable → runs (20 + 20) | unchanged (D1971) | 9 → runs, 1 → traps |
| un-annotated trapping fn | check reject, unchanged (by design) | unchanged | unchanged |

No `runs` cell was lost, and the distilled corpus moved no cell (it holds no `__trap__` cell).

#### Grading list

Both arities and both return spellings are in the grid; the lint warns after `fail(…)` and
`__trap__("…")`; an imported `: never` function narrows (`tests/cases/modules/never-imported/`).
Storing a never value was check-clean invalid wasm for a moment in this change's own
development (`const a = __trap__()` then `const s: string = a`) and is now refused, with an
annotated binding still accepted. Review of #3029 found a `never` function used as a VALUE
(`[fail]`, `const g = fail; [g, g]`, `call<T>(f: () => T)` pinned by `call(fail)`) was invalid
wasm or an emit refusal: the function TYPE kept a `never` result the reps had no name for. It
now renders as `void` there (`tests/cases/functions/never-function-value.vl`,
`never-generic-pin-traps.vl`). The same review found the parse-only lint marked a call through a
parameter that shadowed a `: never` function (`lint/never-name-shadowed-by-param-no-warn.vl`).
Residue: a `: never` body ending in `while true` (D2025, falls out of D1973), a function TYPE
spelled `(…) => never` (D2026), an `extern` declaring `never` (D2027).
