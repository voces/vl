### D1667 — seven emitter pre-passes walk a `.` receiver and not a `?.` one, so whatever frame the receiver needs goes unreserved

**closed 2026-09-05 — the witness runs · was check-clean invalid wasm (`unknown local 0: local
index out of bounds`, exit 70) · filed 2026-09-05 against master `8725c61a8` from
#2681's witness sample · probe `scripts/capability-probes/optchain-over-fn-value-call-result.vl`
· fixture `tests/cases/expressions/optchain-receiver-scratch-frames.vl`**

Repro:

    type B = { y: i32 }

    function mk(): B | null { { y: 7 } }

    const g = mk
    print(g()?.y == null)
    // was: vl check rc 0, then exit 70, unknown local 0. Now prints false.

#### Mechanism

`emitOptChainIsNull` lowers a `?.` receiver exactly as `emitMem` lowers a `.` one, so the
scratch frame the receiver needs is the enclosing function's. The reservation pre-passes
each carry a `Member` arm and no `OptMember` one, so the receiver is never walked:
`blockHasCallRef`, `exprHasArrNew`, `exprHasStrOp`, `exprPopBits`, `exprHasMapOp`, `mfScan`
and `liftFnsInExpr`. The first four have no "frame not reserved" floor, so the body ran
`local.set` against a local the vector never declared. `exprHasCoalesceCall`,
`collectMemberPopRefSlotsExpr` and `leqScanExpr` already had the arm, which is what made
this a set with three members taught and seven not, rather than a decision anyone took.

The filed guess — that the reservation is missing only for a call-result receiver — was one
walker of seven; the ingredient is the `?.`, not what the receiver holds.

#### Ablation

One cell per pre-pass, each the only use of its own frame in its own frame, graded before
and after on the same tree:

| `?.` receiver holds | pre-pass | before | after |
| --- | --- | --- | --- |
| a call through a function value | `blockHasCallRef` | invalid wasm, `unknown local 0` | runs |
| a struct-field closure call | `blockHasCallRef` | invalid wasm, `unknown local 0` | runs |
| `__array_new__(2, 5)` | `exprHasArrNew` | invalid wasm, `unknown local 0` | runs |
| `sv().slice(1, 3)` | `exprHasStrOp` | invalid wasm, `unknown local 4` | runs |
| `xs.pop() ?? 0` | `exprPopBits` | invalid wasm, `unknown local 3` | runs |
| `m.keys().length` | `exprHasMapOp` | `.keys() scratch frame not reserved` | runs |
| `xs.map(inc).length` | `mfScan` | `.map/.filter scratch frame not reserved` | runs |
| a lambda argument | `liftFnsInExpr` | `function literal not lifted` | runs |
| the annotation on the binding | — | invalid wasm either way | no |

#### Grading list

`print(g()?.y ?? 0)` is still the loud `` `??` over this nullable value is not supported yet ``
— `optRecvReReadable` declines a call receiver, and that refusal is real for `??`, which
re-reads the receiver. Filed as D1670.

The `?.` receiver is evaluated TWICE whenever the leaf field is itself a nullable struct
(`emitOptChainIsNull` emits it for the null test and `emitOptChainValue` again for the field
read), so a side-effecting receiver runs twice. That is unchanged by this row and reproduces
at the direct-call spelling on master. Filed as D1671.
