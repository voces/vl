### D1667 — an inline call through a function VALUE, read with `?.`, emits a body that reads a local it never reserved

**check-clean invalid wasm · filed 2026-09-05 against master `8725c61a8` · found while measuring D1666 · probe `scripts/capability-probes/optchain-over-fn-value-call-result.vl`**

Repro:

    type B = { y: i32 }

    function mk(): B | null { { y: 7 } }

    const g = mk
    print(g()?.y == null)
    // vl check: rc 0.  vl run: exit 70, the emitted module failed to validate inside the
    // module's top-level code: unknown local 0: local index out of bounds

#### Mechanism

`?.` lowers by stashing its receiver in a scratch local and re-reading it for the null test
and the field read. The receiver here is a CALL through a function value, and the reservation
that gives that stash a slot is not made on this path — the emitted body references local 0
in a frame that declares none, so the module fails to validate. The direct call and the
pre-bound call result both lower through paths that do reserve, which is why the defect needs
the call to be BOTH through a value and INLINE under the `?.`.

Both faces are silent: annotating the binding as `const g: () => B | null = mk` produces the
identical module and the identical validator sentence, so the rep is not what inference is
getting wrong.

#### Ablation

| ingredient removed | outcome | needed? |
| --- | --- | --- |
| the value binding (`print(mk()?.y == null)`) | runs, prints `false` | **yes** |
| the inline call (`const t = g()` then `t?.y == null`) | runs, prints `false` | **yes** |
| the annotation on the binding (`const g: () => B \| null = mk`) | still invalid wasm | no |
| the plain binding, replaced by a struct-FIELD closure receiver | still invalid wasm | no |

#### Grading list

The struct-field face is the same defect and must be re-graded with the fix:

    type B = { y: i32 }
    type H = { mk: () => B | null }
    const h: H = { mk: () => { const b: B | null = { y: 1 }
      b } }
    print(h.mk()?.y == null)

Also re-grade the `??` spelling of the witness — `print(g()?.y ?? 0)` is a LOUD refusal today
(`` `??` over this nullable value is not supported yet ``), so a fix that only moves this row
from silent to that message has not closed it.
