### D7761 — demand inference entering a recursion group at the member with the base case gives its partner no return type

**runs today and must keep running · prints `0` · only reachable with `inferReturnsPrePass`'s whole-module sweep removed, where it is `loud check reject` (`cannot infer a return type for 'rest'`) · clause 2 · 18 functions of `vl check compiler std scripts` are this shape, `emit_base.vl`'s `monoBindUnionRest` / `monoBindFromAnn` among them · pin: `tests/cases/inference/recursion-group-entered-at-base-case.vl` · filed against master `573358403`**

Repro:

    print(b(3))

    function rest(n: i32) {
      b(n - 1)
    }

    function b(n: i32) {
      if n > 0 { return 0 }
      return rest(n)
    }

Want:

    0

#### Mechanism

Demand inference settles a forward callee by checking it first (`checkCallOnFuncTy`). That
needs an order with the callee before the caller, and a cycle has none. Here the first read
demands `b`, `b` demands `rest`, and `rest`'s call back to `b` is in-cycle. That call gives
`TY_ERR`, so `rest` gets the real `cannot infer` error and is marked body-checked. `b` then
settles on its base case, but nothing infers `rest` again. The pre-pass hides this because its
first sweep infers every un-annotated function quietly, and its tentative fixpoint settles the
cycle before any real check. That sweep now covers only functions on a cycle of the mention
graph (`compiler/check_infer_groups.vl`), so the fixpoint is the only part that remains.

#### Ablation

Pre-pass off. Master with the pre-pass runs every row.

| witness | outcome |
| --- | --- |
| as filed (first read at `b`, before both declarations) | `rest` cannot infer |
| the read moved after both declarations, `rest` declared first | runs |
| the read moved after both declarations, `b` declared first | `b` cannot infer |
| no read of either | runs |
| `rest` returns `b(n - 1)` explicitly | `rest` cannot infer |
| three members (`a → b → c → a`, base case in `c`) | `a` and `b` cannot infer |
| the cycle closed through a method call (`self.down()` / `.up()`) | `up` cannot infer |

What decides it is the order in which members are entered, not the source order alone.
