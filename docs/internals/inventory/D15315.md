### D15315 — a nested shared field of a union of records, read through an un-annotated parameter, is refused at emit

**open · loud emit reject · `emitProgram: \`??\` over this nullable value is not supported yet — narrow it first` · clause 2 · the annotated parameter and a generic identity run · found closing D15314 · filed 2026-11-04 against master `e5a65514b`**

Repro:

    type H = { f: i32 | null }
    type K = { h: { f: i32 } }
    type J = { h: H }
    const k: K = { h: { f: 4 } }
    const u: K | J = k
    function take(a) { print(a.h.f ?? 0) }
    take(u)

Want:

    4

#### Mechanism

Not yet ablated past the grid below. In the instance pinned at `K | J` the checker types `a.h`
as `{f: i32} | H` (D15314), but the read's own node type is the parameter's hole, and the emit
paths that lower the union's field read and its `??` take that node type rather than the
instance's, so they find neither a box plan nor a struct row. That is the per-instance node-type
gap `docs/internals/mono-pin-survey-2026-11.md` group A retires: readers ask `elabNodeTyAt(ix,
inst)` instead of the hole's own type.

#### Ablation

| ingredient removed | outcome | needed? |
| --- | --- | --- |

| the nested record (`K = { f: i32 }`, `J = { f: i32 \| null }`) | runs | **yes** |
| a generic identity instead (`take<T>(a: T): T`) | runs | **yes** |
| the `??` (`const x = a.h; print(x.f ?? 0)`) | still refused (`field access receiver is not a struct`) | no |
