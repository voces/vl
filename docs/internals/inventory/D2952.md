### D2952 — a literal-union member stored in a value union with `i32` prints its atom id

**closed 2026-09-28 · was check-clean silently wrong, clause 1, on master `03dcbcfac` · the concrete twin of the CK lane's `"a" | "b"` pin cells · fixture `tests/cases/literal-unions/inferred-join-beside-a-scalar.vl`**

Repro:

    type K = "a" | "b"
    function g(a: K, c: boolean) {
      const r = if c { a } else { 5 }
      r
    }
    const k: K = "a"
    print(g(k, true))

Want:

    a

#### Mechanism

The join of `K` and `i32` is the flat union `"a" | "b" | i32`. Its emitter name is `K|i32`, a
value union with a literal-union arm, which the annotated spelling boxes. But the inference
hooks name a join through `valueUnionRetName`, which walks leaf atom kinds, and a literal leaf
has none. So an un-annotated binding, return, join and list element all declined the box and
kept the atom id in an `i32`. Closed by `valueUnionRetName` falling back to the emitter name when
it groups the literals into an arm, and by the joins, returns and list literals that meet such
a union registering and reserving for it as they do for any value union. Four emit sites
follow: an inline join registers its row, a join over that row is the box, the string frame
the atom's widening needs is reserved for a join or an inferred return, and a list literal of
the union is a box list.

#### Ablation

| ingredient removed | outcome | needed? |
| --- | --- | --- |
| the `i32` arm (`if c { a } else { a }`) | prints `a` | **yes** |
| the literal union (`a: string`) | prints the string | **yes** |
| the return (`print(if c { a } else { 5 })`) | prints `0` | no |
| `i32` for `f64`, `i64` or `boolean` | the same, or invalid wasm | no |
| the annotation (`const r: K \| i32 = …`) | prints `a` | **yes** |
