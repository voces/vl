### D2952 — a literal-union member stored in a value union with `i32` prints its atom id

**check-clean silently wrong · clause 1 · open · the concrete twin of the CK lane's `"a" | "b"` pin cells · filed 2026-09-28 against master `e9fdc10d9`**

Repro:

    type K = "a" | "b"
    function g(a: K, c: boolean) {
      const r = if c { a } else { 5 }
      r
    }
    const k: K = "a"
    print(g(k, true))
    // PRINTS 0

Want:

    a

#### Mechanism

Not localised past the ablation. The join `K | i32` boxes the `K` member as its atom id (an
`i32`), and `print` over the box dispatches on the member tag. For this member it prints the
payload as a number instead of the atom's text. The same happens through a list
(`[if c { a } else { 5 }][0]`), a binding printed directly (`const r = …; print(r)`) and a `match`.

#### Ablation

| ingredient removed | outcome | needed? |
| --- | --- | --- |
| the `i32` arm (`if c { a } else { a }`) | prints `a` | **yes** |
| the literal union (`a: string`) | prints the string | **yes** |
| the return (`print(if c { a } else { 5 })`) | prints `0` | no |

#### Grading list

The CK grid's generic `"a" | "b"` pin cells (`lit`, `nest`, `match`, `listlit` joins). Once
the generic join is typed `T | i32` (D2906), those cells print this row's `0` in place of
master's `b`. Both answers are wrong.
