### D1865 — dogfood: a map delivered into a RECURSIVE union refuses when its type is spelled through an alias, and runs at the inline spelling of the same type

**closed 2026-09-07 · filed against master `678f578e3`**

Repro:

    type V = f64 | string | { [string]: V }
    type VMap = { [string]: V }

    function name(v: V): string {
      if v is f64 { return "number" }
      if v is string { return "string" }
      "object"
    }

    const m: VMap = Map()
    m["a"] = 1.0
    print(name(m))
    // PRINTS object

#### Mechanism

TWO ingredients, and the row's first filing named only one. The alias alone is harmless: the
same shape over a NON-recursive union ran at the alias spelling all along. Recursion alone is
harmless too: the same recursive union ran when the map's type was spelled inline. It was the
PAIR that refused, and it broke in two places at once.

A bare map alias is a TRANSPARENT one (`singleAliasMemberTyIx`'s `mt is TyMap` arm), so
`type M = { [string]: i32 }` is rewritten to its member and never reaches the emitter as a
name. A RECURSIVE one cannot be, so `VMap` arrives as a one-member `TyUnion` wrapper over the
map, and every classifier that reads the SPELLING answers wrongly for it: `nameIsMap("VMap")`
is false, and `mapValNameOf("VMap")` slices no value out of one identifier.

The ARM half. `unionHasMapArmSlot` asked `unMemIsMap` of the wrapper, which is a `TyUnion`, so
an alias-spelled arm was not a map arm at all. It now peels a one-member wrapper on the ARENA
before asking, and takes an alias-spelled arm's key and value off that row rather than its
name — the peel is on the arena and never on the render, because re-rendering the spelling
re-enters the alias's own recursion.

The VALUE half, and it was NOT where either the row or the first fix attempt looked. The
checker's alias resolution is correct: `VMap`'s map value already points at the DECLARED `V`
row. The twin was minted downstream, in `mvShapeOfMapNameArmTy`, which resolved the map value
by slicing it out of the rendered spelling while the caller was already holding the banked
arena row and passing it as an arm hint only. Slicing an inline union out of a rendered
recursive alias mints an ANONYMOUS union that is the declared one UNROLLED ONE LEVEL — a
genuinely different graph, which is why `repCanonId` separated the two rows and
`mvCanonRepOf` was right not to merge them. The fix is one argument: the banked row stands in
for the row the value name would have resolved to. `ensureRefElem`'s map-element arm takes the
same row for the same reason.

**The capability was CHECK-CLEAN INVALID WASM, not a loud refusal, at almost every position.**
The row's witness happens to land on the one delivery that refused out loud.
`scripts/capability-probes/matrix/recursive-alias-map-into-union.matrix.vl` grades 62 cells:
before, **62 of 62 SILENT**; after, **53 RUNS and 9 SILENT**, with `runs -> not-runs` 0 and no
cell worse. The nine that remain are D1866.
