### D1865 — dogfood: a map delivered into a RECURSIVE union refuses when its type is spelled through an alias, and runs at the inline spelling of the same type

**loud emit reject · filed 2026-09-07 against master `678f578e3`**

Repro:

    type V = f64 | string | { [string]: V }
    type VMap = { [string]: V }

    function name(v: V): string {
      if v is f64 { return "number" }
      if v is string { return "string" }
      "object"
    }

    const m: VMap = Map()
    m["a"] = 1.0
    print(name(m))
    // vl check: rc 0.  vl run: emitProgram: a map value is not a supported union member — use a struct member instead

#### Mechanism

TWO ingredients, and the row's first filing named only one. The alias alone is harmless: the
same shape over a NON-recursive union runs at the alias spelling, for an `i32`-valued map and
for a ref-valued one alike. Recursion alone is harmless too: the same recursive union runs when
the map's type is spelled inline, and a narrowed read of it answers — `v is { [string]: V }`
then `v.size` prints `2`. It is the PAIR that refuses.

A bare map alias is a transparent one (`singleAliasMemberTyIx`'s `mt is TyMap` arm), so
`type M = { [string]: i32 }` is rewritten to its member and never reaches the emitter as a
name. A RECURSIVE one is not, so `VMap` survives into the emitter, where every map classifier
reads the spelling: `nameIsMap("VMap")` is false and `mapValNameOf("VMap")` slices no value
out of one identifier. Both sides of the box then break, and they break differently, which is
why the message is one sentence over two mechanisms. Instrumenting `emitUnionCoerce`'s map arm
against this witness reads, for the value's own map slot and the first map arm the union
offers:

| spelling | value slot | first map arm's slot |
| --- | --- | --- |
| value aliased, arm inline | 1 | 0 |
| value inline, arm aliased | 0 | none — no arm classifies as a map |
| both aliased | 0 | none |

So an aliased ARM is invisible to `unionHasMapArmSlot` altogether, and an aliased VALUE interns
a second map-value slot for a type the arm already interned, which `mvCanonRepOf` does not
merge. The refusal's own sentence is false of the feature it names — a map value IS a supported
union member — and "use a struct member instead" tells an author to change their data model
when the fix that works is to delete a `type` line.

It is `std:json`'s whole write path: `Json` is recursive and its object arm is
`{ [string]: Json }`, so `toJson(m)` refuses the moment the map's type is given a name, which
is what a reader of that module's header would write. That makes it the write-side twin of
D1864's read side.

#### Ablation

| ingredient removed | outcome | needed? |
| --- | --- | --- |
| the alias — `const m: { [string]: V } = Map()`, arm inline | runs; the narrowed read of `.size` prints `2` | **yes** |
| the recursion — `type Box = {v: i32}` over `f64 \| string \| { [string]: Box }`, value aliased | runs, prints `object` | **yes** |
| the recursion, at an `i32`-valued map — `type M = { [string]: i32 }`, value aliased | runs, prints `object` | **yes** |
| moving the alias to the ARM instead of the value (recursion kept) | refuses identically | no |
| the map WRITE — the same program with an empty map | refuses identically | no |
| the user union — the same shape over `std:json`'s `Json` and `toJson` | refuses identically | no |

#### Grading list

The three running controls are the row's boundary and must keep running: the inline spelling
under recursion (including the narrowed `.size` read, which is what says the box is real and
not an accidental fall-through), and the aliased spelling without recursion at both an `i32`-
and a ref-valued map. A fix that closes this by making a recursive map alias transparent must
be graded against the renderer, since expanding `VMap` to `{[string]:V}` re-enters `V`; a fix
that peels the alias in the emitter's map classifiers owes BOTH sides — the arm side
(`unionHasMapArmSlot`) and the value-intern side, because closing only the arm leaves the two
slots unmerged. `std:json`'s `toJson` over a program-built object is the second witness and a
close owes it. D1864 is the read-side row over the same two types and must be graded beside
this one.
