### D3381 — a generic function held without a concrete function type is called uninstantiated

**check-clean invalid wasm · clause 1 · open · needs a ruling · found by the `fn-value-generic-instance` matrix's un-annotated face · the same on master `3291e99e1` · filed 2026-09-30 against master `3291e99e1`**

Repro:

    function show<T>(x: T) { print(x * 3) }
    const c = show
    const f = () => {
      const v = c
      v(2)
    }
    f()
    // vl check: rc 0.  vl run: invalid module, inside `f`: type mismatch: expected structref

Want:

    6

#### Mechanism

A generic named as a value is instantiated where it meets a concrete function type
([D3112](D3112.md): the adapter's direct call). `const c = show` meets none: `c` holds the
generic itself, typed `(T) => void`, and there is no single instance to build. The call `v(2)`
binds `T := i32` for the checker only; the emitter builds the value at no instance, and the
positions the matrix grades fail five ways (invalid wasm through a capture or a block, a trap
through `return` or `push`, and the emit refusals `a function-value call has no interned
signature` and `monomorphize: unsupported argument type`).

**Ruling asked:** is a generic function value that no concrete function type instantiates legal?
Recommendation: refuse it at check where the value is bound or returned without a function type
(`const c: (i32) => void = show` is the fix the message names). An instance per call site would
need the value to carry every instance it is ever called at, which a stored value cannot know.

#### Ablation

| ingredient changed | outcome | needed? |
| --- | --- | --- |
| `const c: (i32) => void = show` | runs, prints `6` | **yes** (no concrete type) |
| `c(2)` called directly at module scope | runs, prints `6` | **yes** (a rebinding or capture) |
| `function deliver() { return show }`, then `const v: (i32) => void = deliver()` | traps | no (the same family through a return) |
