#### Mechanism

A string literal union is one interned atom per member set. It renders in the member order,
or under the alias name, of whichever spelling the check interned first. A merged check of
several roots can intern another spelling first than a root's own check does. That holds when
the other spelling lives outside the served closure G, and also when it lives inside G and a
different import order reaches it first. So the text of a report row or a type error that
renders such a set could differ between the served answer and the root's own check.
`wiRowsIn` (driver.vl) read only whether a word of the row was declared outside G, and the
error half read only outside names, so both passed these.

Measured on the master seed `4f88700a9`, each as a multi-root `vl check` against each root
alone:

| spelling that differs | where it lives | what moved |
| --- | --- | --- |
| `"b" \| "a"`, no alias | main, outside G | an rcoal row, also inside `{[string]: "y" \| "x"}` |
| `"b" \| "a"`, no alias | g2, inside G | an rcoal row, and the error `cannot assign "a" \| "b" …` |
| `type L2 = "q" \| "p"` beside `type L1 = "p" \| "q"` | g1 and g2, inside G | the error renders `L2` merged, `L1` alone |

Not order-sensitive, each measured SAME: a numeric literal union (`1 | 2`), `i32 | string`
and `P | Q` even beside declared aliases of the same set, record field order, two same-shape
records in G (each renders its own name), and an anonymous record.

The close is `wiLitOrderIn` (driver.vl). It declines the root when a row or, in a check with
errors, an error placed in G holds a member list with a string literal (`" | ` or ` | "`), or
a word naming a union alias that G alone declares and whose set holds a string literal
(`ihNameIsLitUnion`, iface_hash.vl, read from the arena). An alias declared outside G is
already declined by the outside-word test. Mask 32768 (`WI_NO_LIT_ORDER`) serves each of the
three witnesses unsoundly in `tests/vl_check_within_test.ts`. A numeric-union row is a
must-serve control.
