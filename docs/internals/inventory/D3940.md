### D3940 — a generic function delivered as an element of a nullable-function list literal or push traps

**closed 2026-10-10 by lane SC · runs · was loads then traps · pins: `tests/cases/generics/generic-function-in-nullable-function-list-literal.vl` · found in review of #3494 (`rv3494/k_list_lit_single`, `j_list_*`) and #3493 (`rv3493/f3`; `f3b` is the control) · filed 2026-10-10 against master `00bf1871f`**

Repro:

    function b<U>(y: U) { print("G"); print(y) }
    function a<T>(x: T) {
      const l: (((t: T) => void) | null)[] = [b]
      const e = l[0]
      if e != null { e(x) }
    }
    a("s")
    // vl check: rc 0.  vl run: wasm trap: indirect call type mismatch

Want:

    G
    s

#### Mechanism

The list-literal coercion (`monoCoerceFnValueName`'s `ArrayLit` arm) recursed into the elements
only for an array whose element is a bare function type, so `[b]` at a `((t: T) => void) | null`
element never instanced `b`, and the call took the default instance. The arm now also recurses
for a nullable function element (`nullClosureArrElem`), delivering each element at the non-null
function type; the `null` elements are untouched. The push half (f3) was closed on master by
the time of the fix: a push delivers through D3929's rung, whose `Ident` arm peels `| null`
(D3932).
