### D2886 — an if-expression joining an `i32` arm and a literal-union element reads the literal as `0`

**check-clean silently wrong · clause 1 · found by the #3229 review · the same on master `8e10ef58b` · filed 2026-09-27 against master `8e10ef58b`**

Repro:

    function mk(b: boolean): i32[] | ("x" | "y")[] {
      if b { return [1] }
      ["y"]
    }
    const w = mk(false)
    const e: i32 | "x" | "y" = if w is i32[] { w[0] } else { w[0] }
    print(e)
    // PRINTS 0

Want:

    y

#### Mechanism

Not localised past the ablation. The else arm reads a literal-union list's element, an interned
atom id, and the join delivers it into `i32 | "x" | "y"` as though it were the `i32` member, so
the atom's id prints as a number. D2874's list-union rewrite is this spelling, so it declines a
union with a literal element until this is fixed.

#### Ablation

| ingredient removed | outcome | needed? |
| --- | --- | --- |
| the value position (`if w is ("x" \| "y")[] { print(w[0]) }`) | runs, prints `y` | **yes** |
| the annotation on `e` | prints `0` | no |

#### Grading list

`for v in mk(false) { print(v) }` and `mk(false)[0]` once D2874 lets the literal element through.
