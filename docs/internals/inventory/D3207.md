### D3207 — a contextual lambda does not adopt a one-literal result type, `"a"` or `"a" | null`

**loud check reject · clause 2 · pre-existing, the same on master `94670f728` · found by the D3198 grid (`nlu1_*` cells) · filed 2026-09-29 against master `94670f728`**

Repro:

    const g: () => "a" | null = () => "a"
    print(g() ?? "n")
    // vl check: cannot assign () => string to 'g' of type () => "a" | null

#### Mechanism

`finishInferredReturn`'s literal-union adoption arms ask `tyIsLitUnion`, which declines a one-
member literal, so the lambda keeps its softened `() => string` and the assignment is refused.
The body `() => null` against the same type adopts nothing either and reaches the emitter as a
bare `null` (`bare null needs a struct-typed context`). The rep a one-literal `| null` takes has
to be decided before an adoption arm can pin it.

#### Ablation

| lambda annotated `(): "a" \| null => "a"` | runs | **yes** (the contextual lambda) |
| `const x: "a" \| null = "a"` | runs | **yes** (a function result) |
