### D4672 — a function value whose signature names the `null` unit type has no function-value ABI token

**closed · runs, prints `true` · was loud emit reject, `vl check` rc 0, clause 2 · probe `scripts/capability-probes/null-unit-function-value.vl` · filed 2026-10-14 against master `1c1740512` · closed by the `null`-type `$fnsig` token `Z` (`repSigTokOfKind`, emit_rep.vl), read off the arena type through the rep layer · fixture `closures/fn-value-nullable-map-null-bool-sig.vl` · with [D9823](D9823.md) closed; a lambda whose un-annotated result is `null` still refuses ([D9921](D9921.md))**

Repro:

    function f(x: null) { print(x == null) }
    const h = f
    h(null)
    // vl check: rc 0.  vl run: emitProgram: a function value's signature is not yet supported — parameter `x` of type `null` has no representation in the function-value ABI

Want:

    true

#### Mechanism

A closure's `$fnsig` is spelled from one token per parameter and result
(`repSigTokOfKind`, `emit_rep.vl`), and the `nulnone` kind D4550 gave a direct call has no
token there, so `cloSigKeyExt` answers "" and the binding is refused. A direct call `f(null)`
runs; the gap is only the value ABI.

#### Ablation

| spelling | outcome |
| --- | --- |
| `const h = f; h(null)` over `f(x: null)` | refuses |
| a lambda `(x: null) => 1` called through its binding | refuses |
| `f(null)` called directly | runs |
| `f(x: i32 \| null)` as a value | runs |

#### Grading list

A `null` result token too (`function g(): null` as a value), and a `null` parameter of a
closure captured into a struct field. A lambda returning `null` (`const cl = () => nothing()`,
probe `null-unit-closure-return.vl`) and a `.map`/`.filter` callback over a `null[]` refuse as
well, each at its own message.
