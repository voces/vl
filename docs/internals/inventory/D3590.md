### D3590 — `e is L` over an `i64` literal union, where `e` is not a re-readable place, folds to `false` without evaluating `e`

**closed 2026-10-04 — the witness prints `true`, `false`, `true` · was check-clean silently wrong, clause 1 · the `i64` residue of [D3570](D3570.md) · filed 2026-10-03 against master `7073d9d03` · fixture `tests/cases/literal-unions/numeric-is-once-read-receiver-i64.vl`**

Repro:

    type B = 5000000000 | 6000000000
    type C = 1 | 3000000000
    function fi(x: i64): i64 { x }
    function fm(): i64 { 1 }
    print(fi(5000000000) is B)
    print(fi(7) is B)
    print(fm() is C)
    // vl run: false, false, false

Want:

    true
    false
    true

#### Mechanism

Two ingredients, both in the emitter's numeric literal-union `is` arm. A receiver that is not a
re-readable place was read once into a slot only at an `i32` base; an `i64` base now reads it into
a fresh `i64` lazy-frame slot (`numLitOnceSlot`) and compares each member with `i64.eq`. And a
literal union over two widths (`1 | 3000000000`) has no single base (`numLitUnionBaseName` is ""),
so even a re-readable `i64` place (`const z: i64 = 1; z is C`) fell to `monoStaticIsResult`'s name
fold and answered `false`; an `i64` receiver now compares at `i64` against every member
(`tyIntLitWideTexts`). An `i32` receiver over such a union is refused by the checker:
[D3655](D3655.md).
