### D14080 — a rewrite-minted annotation is read unsubstituted in an instance's re-check, so the un-annotated face binds a different type parameter

**closed · runs, prints `0` twice · was two elaboration instances of `len` where one is owed (`T = null` for `() => x`, `T = i32` for `(): U | null => x`), both printing `0` · closed in check_relate_core.vl: `mintedAnnTy` reads a minted annotation at the instance's type-parameter bindings, and the three raw `luAnnTy` reads go through it · test `tests/vl_minted_annot_test.ts` · filed 2026-10-26 against master `2f8428da3`**

Repro:

      const t = f()
      if t == null { 0 } else { 1 }

Want:

#### Mechanism

The binding code was right and was handed two different arguments. The first pass rewrites the
un-annotated `() => x` into a function-value adapter (D10241) whose annotations `fvaAnnot` types
through `luAnnTy` with the open `U`. In the re-check at `U = null`, `resolveAnnotAt`,
`nameToTyAnn` and `letDeclResolveAnnot` returned that minted type as it was and never applied the
instance's bindings. A written annotation is resolved under those bindings. So the adapter kept
`$fv: () => U` and the result `U | null`. The inner `() => x` adopted `() => U` and bound `U` to
itself, and `len` received `() => U | null` and bound `T = U`, which is `null`. The annotated face
received `() => null`, and D10211's default bound `T = i32`. At `U = i32` the faces agreed only
because the argument `() => i32` bound the adapter's `U`.
