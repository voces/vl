### D1476 — a captured binding whose initialiser is a PROJECTION of a struct (`xs[0]`, `box.it`) is typed at the capture as an i32: check-clean invalid wasm, and annotating the binding is the whole fix

**closed · found 2026-09-03 by `scripts/day-one/sample.py --seed 61 --axis init_vs_assign`
pair 3 against master `cdfdc14e` · closed against `2c70883c`**

`letInitCellKind` and `captureValStructIdx` grew paired arena rungs, and the field projection
its own `nulstruct` split. All 13 cells of the grid run, both projection shapes among them.

Repro (`vl check` rc 0; `vl run` fails to compile the module in `go`):

    function go() {
      const srcArr = [{ name: "ada", n: 3 }]
      const held = srcArr[0]
      const get = () => held
      const v = get()
      print(v.n)
    }
    go()
    // vl check: rc 0.  vl run: WebAssembly translation error in function `go`
    //   type mismatch: expected i32, found (ref $type)

#### Mechanism

The capture of `held` is typed from the binding, and a binding whose initialiser is a
PROJECTION — an array index or a struct-field read — carries no committed rep at that point,
so the capture falls to `captureValKind`'s i32 default and the closure's frame declares an i32
where the fat struct arrives. A CALL initialiser (`const held = mk()`) commits the rep and
runs; an annotation on the binding commits it too. This is the same default D1244 fixed for a
module-scope block local, reached through the initialiser rather than through the scope.

MEASURED at `captureValKind`, for the three faces at once:

    D1476RUNG name=held letType=-1 KIND=i32     isStructOfTy(init)=T structIndexOfExpr(init)=-1 captureValStructIdx=-1
    D1476RUNG name=held letType=7  KIND=struct  isStructOfTy(init)=T structIndexOfExpr(init)=-1 captureValStructIdx=0
    D1476RUNG name=held letType=-1 KIND=struct  isStructOfTy(init)=T structIndexOfExpr(init)=0  captureValStructIdx=0

The rows are the un-annotated projection, the annotated twin and the literal initialiser.
**`isStructOfTy` of the initialiser's arena type is TRUE in all three** — the checker knew the
struct throughout. The kind falls to `i32` only in the first, and its SLOT is -1 there too:
the annotated twin gets its slot from the annotation and the literal from
`structIndexOfExpr`, and a projection carries neither. So the fix is two paired arena rungs,
never one — a kind whose companion index stays -1 is a different refusal, not half a fix
(D21's rule, and this row is where it bites).

**The FIELD projection needed a third thing, and the message is what said so.** With the two
rungs, `box.it` moved from `expected i32, found (ref $type)` to `expected (ref $type), found
(ref null $type)` — real progress, and still invalid. A nested-struct field read reads back
`(ref null $S)`, because the lowering folds `inner: S` and `inner: S | null` onto one code-15
hop, so its cell is the NULLABLE struct. The `Index` projection has no such hop and keeps the
bare one. Reading the second message rather than re-reading the first is what separated them.

**The annotation is the whole difference, which is why only a paired instrument sees it.**
Every fixture in this family annotates its captures; the un-annotated spelling had not been
written. Note also which scope is healthy: plain module scope RUNS and the function body does
not, the reverse of D1244's shape, so "module scope is the broken one" is not the rule here.
