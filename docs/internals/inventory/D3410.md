### D3410 — an effectful `null` argument to a generic function is check-clean invalid wasm at every position, while the literal `null` is a loud reject

**check-clean invalid wasm · clause 1 · open · a `T` bound by a `null`-typed call result is emitted as an `i32` slot and the `nullref` value is delivered into it · found by the #3315 review (`rv3315-25182`, `y1`-`y4`) · the same on master `5e277ab52` · filed 2026-09-30 against master `5e277ab52`**

Repro:

    function nf() {
      print("n")
      null
    }
    function idg<T>(x: T): T {
      print("g")
      x
    }
    idg(nf())
    // vl check: rc 0.  vl run: invalid module in the top-level code,
    // `type mismatch: expected i32, found nullref`

#### Mechanism

A prediction, read off the ablation. The argument's type is `null`, so `T` binds to the null
type; the instance's parameter and result slots are laid out as `i32` (the rep a bare `null`
gets when it has no struct-typed context, [D1888](D1888.md)) while the argument expression is a
call that really returns a `nullref`. The literal `idg(null)` never gets that far: the emitter
refuses it (`bare null needs a struct-typed context`), so the call form is the loud reject's
escape, not a different defect. Effects are not the ingredient (the pure `nf` fails the same
way at a statement); they decide only whether the BINDING position is loud or invalid, because
a pure null-returning call is folded to the literal.

so the two spellings agree. [D1888](D1888.md) is the literal's row.
