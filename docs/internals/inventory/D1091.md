### D1091 — `vl check --fix` moved 159 of 1,198 corpus fixtures `runs -> not-runs`: the compiler's own autofix for `redundant type annotation` deleted load-bearing annotations

**closed 2026-09-03 by COMPILING every candidate rewrite before it reaches the disk: the sweep
goes `159 runs -> not-runs` to `2`, both survivors a module that VALIDATES and traps at RUN
time · and closed a SECOND time by D1470, which retired this row's own excuse — the repro it
filed as correctly refused now RUNS · re-measured over `tests/cases/` (2,804 files); the filed
numbers were 165 of 1,093**

Repro — `vl check` hinted that `: i32[]` was redundant; `vl check --fix` deleted it; the result
is this, which the SAME checker then refused. It now prints `0`:

    function mk(len: i32) {
      return __array_new_default__(len)
    }
    const zs = mk(6)
    print(zs[0])

It USED to say `[ERROR]: cannot infer a type for 'zs' — add a type annotation`, and this row
filed that as correct: "the annotation is the only place in the program that says what the
element type is". **That was wrong, and it is the one claim here worth keeping.**
`__array_new_default__(n)` fills every slot with the element's zero, so an unpinned hole is not
underdetermined the way `const xs = []` is — `emit_classify.vl` had been answering `i32` for it
since the intrinsic existed. The checker now gives the same answer ([D1470](#d1470)), and the
program the autofix wrote runs. `--fix` still declines to write it, for the separate reason that
the annotation is what a READER needs.

#### Mechanism

Three, and they are different sizes. Measured by replaying each of the 507 candidate edits
inside the 159 broken files ALONE and grading it — 231 were culprits:

| why the annotation was load-bearing | culprit edits | closed by |
| --- | --- | --- |
| the EMITTER cannot lower the un-annotated spelling (`check` is clean) | 79 loud + 31 silent | not closable here — this is the goal's own population |
| the annotation was the CONTEXTUAL type its own initializer was checked against | 52 | [D1442](#d1442) — the hint is gone |
| the type exists nowhere else (40 lambda params + 3 container holes) | 43 | [D1442](#d1442) / correctly kept — but see [D1470](#d1470): one of the three container holes was NOT one, the emitter held its answer all along, and this bucket's name is the reason nobody checked |
| the rewrite did not PARSE — the span ate a generic bound | 7 | [D1441](#d1441) |
| an unused `type` alias of the shape rescues it (registration) | 15 | [D1443](#d1443) closes the list-of-anonymous-struct half |
| a VALID module that traps or misprints at run time | 4 | out of reach: verifying that means RUNNING the program |

**The framing that "category one is shape registration" was wrong by an order of magnitude.**
Only 15 of 231 are rescued by an unused `type` declaration; the other 110 emitter cells are
`bare null needs a struct-typed context`, `monomorphize: unsupported argument type`,
`nested struct fields are not supported` and a long tail with no single mechanism.

**The safety net is generic, at the `--fix` driver, and it is not a `check`.** `check` alone
waves through 87 of the 159, because the annotation is load-bearing for the EMITTER far more
often than for the checker. The ladder is `cliFixVerdict`: all edits at once (one compile, and
it holds on 1,109 files), then — only if that failed — the ORIGINAL (a file that did not build
before cannot have been broken by an edit), then greedy from the empty known-good set. Cost:
one extra compile+validate per file that has edits, `2.9s -> 49s` over `tests/cases`.
