**closed 2026-10-19 by lane L1 · runs, prints `1` · was loud emit reject · `vl check` rc 0 · clause 2 · CAPABILITY: the same program with `exclaim(s: string)` runs, and `g(exclaim)` runs ([D6881](D6881.md)) · the unread-parameter argument walk takes an `if` as each of its arms' values, and a parameter the callee calls takes an `if` naming generics in every arm at the type the checker binds it · pins: `tests/cases/closures/hole-fn-if-to-hole-param.vl`, `tests/cases/closures/hole-fn-if-bound-called-compared.vl` · found closing [D6981](D6981.md) · present on master `4ad81c0e0` · filed 2026-10-19 against master `4ad81c0e0`**

Repro:

    function exclaim(s) { return s + "!" }
    function g(p) { print(1) }
    g(if true { exclaim } else { exclaim })
    // vl check: rc 0.  vl run: emitProgram: monomorphize: unsupported argument type for `p` in a call to `g`

Want:

    1

#### Mechanism

An argument handed to an un-annotated parameter nothing reads takes the stub of the hole
functions it can be (`monoInertArgFns`), which followed a name, a binding and a call but not an
`if`, so the call had no argument type to instance `g` at. The walk now takes an `if` with an
`else` as each of its arms' values (`monoIfArmValuesOf`). A parameter the callee does call was
refused the same way; `monoHoleGenFnTy` now accepts an `if` naming generics in every arm, so it
takes the closed type the checker binds the parameter at, as a bare name does.
