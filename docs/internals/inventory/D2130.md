### D2130 — a module global initialised by a closure call re-derives the closure's signature key on every read, walking the closure's whole body each time

**runs today and must keep running · residue of D2017's close · filed 2026-09-23 against master `7cb12a61d` + D2017**

Repro (runs, prints `1600`):

    const k = 1000
    const g = (y: i32) => if y == 0 { k } @@repeat(400, "else if y == 1 { k + 1 } ")@@else { -1 }
    let acc = g(0)
    @@repeat(600, "acc = acc + 1; ")@@
    print(acc)
    // vl check: rc 0.  vl build: rc 0 after 0.54 s CPU with D2017 closed (3.2 s before it),
    //           where `function g` in place of the closure builds in 0.02 s.

#### Mechanism

Each read of `acc` asks what its initialiser returns: `calleeRetKindSid` → `cloSigKeyExt` →
`fnSigKeyOf(g)` → `cloRetKindOf` / `cloRetValKind`, and the un-annotated return is found by
`firstValuedReturn` / `firstValuedReturnIf` walking g's body. Nothing keeps the answer, so a
body of n nodes read by m statements costs n × m. On a 2,000-arm `match` closure with 900
reading statements the profile is 89% inclusive under `firstValuedReturn`, reached from
`startFnDetectScratch` and `leqScanExpr` among others.

`vl build` CPU (s) of a `match` closure of n arms, then `let acc = g(3)` and m statements
`acc = acc + …`, 2026-09-23, D2017 closed:

| n arms × m statements | 500 × 3,600 | 2,000 × 900 | 2,000 × 3,600 |
| --- | ---: | ---: | ---: |
| closure | 3.91 | 3.77 | 15.11 |
| `function g` (control) | | | 0.19 |

#### Ablation

| ingredient changed | outcome | needed? |
| --- | --- | --- |
| `function g` in place of the closure | 0.02 s | **yes** (the closure) |
| `let acc = 0`, reading `g(0)` once at the end | 0.03 s | **yes** (a global whose initialiser calls the closure) |
| m or n quartered | cost falls ~4x either way | **yes** (bilinear in both) |

D2017's witness and `tests/vl_scaling_shape_test.ts`'s `closure body length` pair, whose fill
deliberately reads no global set from `g`; a guard for this row would be that pair's `fill`
reading `let acc = g(3)` instead.
