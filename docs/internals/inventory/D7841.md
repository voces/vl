### D7841 — a join of hole functions whose bodies call the handed function at different sets of types is refused

**loud emit reject · `vl check` rc 0 · clause 2 · CAPABILITY: a neighbouring spelling runs (the ablation) · found closing [D7183](D7183.md) · present on master `5d224f614` · filed 2026-10-20 against master `5d224f614`**

Repro:

    function add(a, b) { return a + b }
    function apply2(g) {
      print(g(1, 2))
      print(g(1.5, 2.5))
    }
    function apply3(g) { print(g(10, 20)) }
    const fs = [apply2, apply3]
    for f in fs { f(add) }
    // vl check: rc 0.  vl run: emitProgram: a generic function is passed to a function value whose parameter type names a type parameter this closure does not bind

Want:

    3
    4
    30

#### Mechanism

Probed against the D7183 close. The split plans every function the call reaches at the union of
their keys (`fsPlanHoles` through `fsListGroupPars`), so `apply3`, which calls `g` at `i32` only,
keeps one parameter while `apply2` gets two, and the elements no longer share a function type. The
element read is then refused at the type-parameter floor. A close gives a function that never
reads a split slot that slot anyway, typed from its siblings, as `monoElemParamTys` already does
for a parameter its body never reads.
