#### Mechanism

A lambda body is checked where it is written, under the path narrowings live there, and the
emitter replays them into the lifted body (`capNarrowRecord`). The lambda runs later. For a bare
name D2402's close decides whether the capture can be falsified before the lambda runs: only a
function that writes the binding can, and one exists or not. A field, element or map value can
be written by any code holding an alias of its object, after the function that made the lambda
has returned, so no analysis of that function bounds it. D2402's close refuses the in-function
case (a writing call after a nested function read the path); an escaping lambda is not refused.

#### Ablation

| ingredient removed | outcome | needed? |
| --- | --- | --- |
| the write `o.v = null` | runs, prints `3` | **yes** |
| the escape (the lambda called inside `f`, before any write) | runs | **yes** |
| the path (a bare local `v`, no function writes it) | runs, no writer can exist | **yes** |

#### Grading list

The index-cell (`xs[0]`) and map-value (`m["a"]`) spellings; a lambda stored in a struct field
rather than returned; the same with the write done by a function the caller calls.

All four graded with the close, and each is now the same loud check reject at the read inside
the lambda. Before it the map-value spelling was a loud emit reject (`'.length' on a receiver the
emitter cannot classify`) and the other three loaded then trapped. A closure assigned to a module
`let`, or handed to a function that stores it, refuses the same way.

#### Close

Owner ruling (a), 2026-09-25: a closure that escapes the function making it loses every captured
field, element and map-value narrowing; one used only locally by name keeps it, under D2402's
per-call check. Inside a nested function, a path narrowing made by an enclosing function reads at
its declared type (`crPathCaptureLost`, asked by `narrowedPathTy` and `narrowedPathInvBy`) when a
function between the two escapes — has no handle and is not a callback that runs inside the call
it is handed to, or its handle is used other than as a callee in the body that makes it
(`crFnEscapesAt`, the D2402 escape test) — and a refused read there gains a note naming the
function (`crLostNote`). A re-test inside the escaping closure narrows again and runs. The
owner's stated ideal is smarter: keep the narrowing when no write of that path can happen before
the closure runs. That needs the flow analysis ROADMAP A6c defers.
