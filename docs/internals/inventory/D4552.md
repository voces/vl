### D4552 — a body function returning a type parameter no call binds is refused, or invalid wasm unread

**loud emit reject · 3 hand probes · filed 2026-10-13 against master `eb2603843`**

Repro:

    function opT<T, U>(a: T[]) {
      const g = (x: i32): U[] => []
      return g(1).length + a.length
    }
    const a = [1]
    print(opT(a))
    // vl check: rc 0.  vl run: emitProgram: '.length' on a receiver the emitter cannot classify

#### Mechanism

The neighbour of the rule `checkRetTyParamBound` now applies to a body function's PARAMETER:
no parameter of `opT` names `U`, so an inferred call leaves it unbound, and here it reaches
the emitter through a body function's RETURN type instead. With the result read (`.length`)
the emitter refuses; with it only bound (`const r = g(1)`) the module fails to validate
inside `g` (`expected i32, found (ref $type)`).

#### Ablation

| ingredient removed | outcome | needed? |
| --- | --- | --- |
| the lambda, as a nested `function g(x: i32): U[]` | still refuses | no |
| the `.length` read (`const r = g(1)`) | check-clean invalid wasm | no |
| the inferred call (`opT<i32, i32>(a)`) | runs, prints 1 | **yes** |

#### Grading list

`opT<i32, i32>(a)` must keep running; re-grade the `const r = g(1)` spelling, which is the
clause-1 face of the same row.
