### D15922 — a maker that binds a list of records holding a function and returns it in a record is refused at emit when a call reads through the returned record

**closed 2026-11-12, runs and prints `4` · was a loud emit reject, `emitProgram: ref-list field element type is not interned`, clause 2 · closed by `sFieldRefSlot` (`emit_shape_rows.vl`) finding the row it mints for an anonymous element holding a type parameter, and minting a closed element holding a function under its declared type · found by w320 beside [D15804](D15804.md) · filed 2026-11-12 against master `22d35fe47`**

Repro:

    function inc0(a) { return a + 1 }
    function mk() {
      const xs = [{ f: inc0 }]
      return { a: xs }
    }
    print(mk().a[0].f(3))

Want:

    4

#### Mechanism

Traced. The type section reads the returned record's field `a` before any function body, so
`sFieldRefSlot` (`emit_shape_rows.vl`) mints the element's ref-list row there. Inline or
returned bare, the list's own row exists by then. Two branches missed:

- An unannotated function leaves a type parameter in the element. That branch minted the row
  under the element's stored name and then looked it up by that name. An anonymous record's name
  has no rep key, so the lookup missed a row it had just minted.
- An annotated function leaves the element closed. `rlRowMint` declines any element that holds a
  function, so nothing minted it. The branch now falls back to `rlArmRowMint`, which mints the
  element under its declared type, as a union arm's ref list does.

The two-function spelling of different results is a separate defect, filed as
[D15883](D15883.md).
