### D9064 — an un-annotated function whose result differs from its parameter, read back from an un-annotated `Map()` through a binding, is called at a guessed signature

**closed 2026-10-21 by lane-D9064 · runs, prints `1.5` · was loud emit reject, `a function-value call has no interned signature`, `vl check` rc 0 · clause 2 · closed by typing the stored function at its own result where it is pinned (`monoStoredSlotFnTy`, emit_mono.vl) and retyping the calls through each read of the map, its aliases and its loop variables to that type (`monoRetypeCallsAt`, `monoCalleeFnTyThrough`, emit_mono.vl) · fixture `closures/hole-fn-in-unannotated-map-read-back.vl` · residue [D9311](D9311.md) · found closing [D4579](D4579.md) and [D9040](D9040.md) · present on master `16cf779bd` (as `unsupported map value type`) · filed 2026-10-21 against master `16cf779bd`**

Repro:

    function half(a) { return a / 2.0 }
    const m = Map()
    m.set("b", half)
    const x = m.get("b")
    if x != null { print(x(3)) }
    // vl check rc 0.  vl run: emit error: a function-value call has no interned signature — no function value of type `(i32)=>i32` reaches this call

#### Mechanism

Not traced. The map now takes `{[string]: (a: i32) => f64}` from its write (D9040), and
the read's binding `x` is retyped at that value (`monoRetypeMapReads`, emit_mono.vl),
but the call `x(3)` still asks for `(i32) => i32`, a signature no stored function has.
The same `x(3)` at `inc0`, whose result is its parameter's type, runs.
