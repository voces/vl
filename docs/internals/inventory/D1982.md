### D1982 — a function value that takes or returns an F32x4 has no closure-ABI token, so the emitter refuses it

**loud emit reject · clause 2 · filed 2026-09-22 against master `a8a104432`, found by SIMD S3's position matrix**

Repro:

    import { F32x4, splatF32 } from "std:simd"
    function twice(f: (F32x4) => F32x4, v: F32x4): F32x4 { return f(f(v)) }
    const _r = twice((a: F32x4): F32x4 => a + a, splatF32(1.0))
    // vl check: rc 0.  vl run: emitProgram: a function value's signature is not yet
    //   supported — parameter `a` of type `v128` has no representation in the function-value ABI

#### Mechanism

`repSigTokOfKind("v128")` returns `""`, so no `$fnsig` is interned for a signature with a
vector parameter or result, and `emitClosureValue`'s floor refuses it. The same holds for a
lambda returning a vector (`() => v + v`) and for passing `addF32x4` as a value. A closure
that only CAPTURES a vector and returns a scalar runs (fixture
`tests/cases/simd/f32x4-positions.vl`): the env field is a plain `v128` struct field there,
so this row is about the call ABI, not captures.

#### Grading list

A lambda returning a vector (annotated and inferred), a vector-parameter lambda, a named
std function passed as a value (`addF32x4`), and a vector-returning lambda captured into
another closure.
