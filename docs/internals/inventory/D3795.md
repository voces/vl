### D3795 — `??` over a nullable scalar list element unboxes at the RESULT's kind, so a wider default casts the element's box to the wrong one

**closed · was loads then traps · clause 1 · found grading D3744 (lane S5) · fixture `tests/cases/lists/nullable-scalar-element-coalesce-wider-default.vl` · filed 2026-10-07 against master `a37097b64` · closed by lane S5**

Repro:

    import { toString } from "std:fmt"
    const l: (i32 | null)[] = [null, 4]
    print((l[1] ?? 1.5).toString())
    // vl check: rc 0.  vl run: wasm trap: cast failure

Want:

    4

#### Mechanism

The D1828 arm of `emitCoalesceGo` (wasmEmit.vl) unboxes a `(T | null)[]` element. It took ONE kind
from the `??` node's type and used it for the block type, the value-box cast and the default. A
wider default makes the result wider than the element (`i32 | null ?? 1.5` is an `f64`), so the arm
cast the element's `i32` box to the `f64` value box and trapped. The arm now unboxes at the
element's own kind (its type with `null` removed) and widens with `emitScalarWiden`. It declines
when `scalarKindWidens` does not admit the pair.

#### Ablation

| ingredient changed | outcome before | needed? |
| --- | --- | --- |
| default `0`, the element's own kind | runs, prints `4` | **yes** |
| `l.get(1) ?? 2.5` | traps the same | no |
| default an `i64` binding | traps the same | no |
| element bound first (`const e = l[1]`, `e ?? 1.5`) | runs, prints `4` | **yes**, the element read |

#### Grading list

* After the fix, these print the right values: `4`, `1.5` (the null hit), a `.get` hit, a `.get`
  out of range, and the `i64` default. `(f32 | null)[]` with an `f32` default and
  `(f64 | null)[]` are unchanged.
