### D17301 — `??` over an assignment of `null` refuses as a nullable value it cannot coalesce

**closed 2026-11-25 · runs, prints `d`, claimed and claimless · was a loud emit reject (clause 2), "`??` over this nullable value is not supported yet" · fixed in emit_classify.vl and emit_plan_null.vl: `coalLhsIsNulUnit` names an assignment whose value is the `null` unit (`asgYieldsNullLit`, `asgYieldsNulHole`) beside `exprIsNulNone`, so `coalArmOf` takes its `nulnone` arm (the store runs for effect, then the default) and the classifiers answer about the default (`coalesceNulNoneDefaultIx`) · pins: `tests/cases/null/coalesce-over-null-assignment-{witness,positions}.vl`, matrix `coalesce-over-null-assignment.matrix.vl` · filed 2026-11-24 against master `fd2d6cd6` by IR-N9, found while grading D17120's `??` cell; closed by lane IR-N11**

Repro:

    function f() {
      let n: string | null = "x"
      print((n = null) ?? "d")
    }
    f()
    // vl check: no errors.  vl run: rc 0, prints the line below.

Want:

    d

#### Mechanism

`coalArmOf` sends a `null`-typed left operand to its `nulnone` arm, which runs the operand for its
effect and then emits the default (D1576), through `exprIsNulNone`. An assignment whose value is
the `null` unit, `n = null`, is not one of `exprIsNulNone`'s producers. So it fell to the generic
refusal. `coalesceNulNoneDefaultIx`, which makes a classifier answer about the default (so `print`
takes the default's arm), asked the same question. Routing only the arm would have left `print`
classifying an `i32` over a string ref.

Still refused, beyond this row: an assignment of a `null`-valued call into a cell that is not the
never-filled hole, `let n: null = null; (n = same(null)) ?? d` and the same into `i32 | null`. That
value is not the literal `asgYieldsNullLit` names; it is #10004's `asgYieldsNulNoneValue`.
