### D3933 — a function argument to a generic's nullable function parameter over its type parameter is refused

**closed · runs, prints `none` `2.5` at a lambda and `null`; a generic's lambda over its own type parameter runs too · was loud emit reject, `vl check` rc 0, `emitProgram: monomorphize: unsupported argument type …`, clause 2 · clause 2 · found by D3932's position matrix (`d3932/m/arg__*`) · filed 2026-10-10 against master `99611fdd8` · closed by binding the type parameter from the argument's arena type against the parameter's, walking the two together, rather than matching the argument's spelling (`monoBindArenaWalk`, `monoPinTyParamComposite`, emit_mono.vl) · fixture `generics/generic-arena-bind-map-and-alias.vl` · closed with [D9820](D9820.md)**

Repro:

    function take<V>(f: ((v: V) => void) | null, v: V) { if f != null { f(v) } else { print("none") } }
    function a(x: f64) {
      take(null, x)
      take((t: f64) => print(t), x)
    }
    a(2.5)
    // vl check: rc 0.  vl build: emitProgram: monomorphize: unsupported argument type for `f` in a call to `take`

Want:

    none
    2.5

#### Mechanism

Not located. The monomorphizer binds a type parameter from an arrow parameter's argument only
where the annotation is an arrow; `((v: V) => void) | null` is a nullable, so `V` is bound from
nothing at `f` and the pin is refused. A `null` argument alone runs. A generic function value
handed to such a parameter inside a generic refuses the same way.
