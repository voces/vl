### D10702 — a hole-function loop inside a generic, handed a lambda, is refused beside another call handed a lambda

**closed 2026-10-23 by lane L1 · runs, prints `3 30 2` · built: a closure-list slot's key answers for a list of functions over an inference hole only when it takes the element's parameter count (`arrSlotSigKeyOf`, emit_classify.vl, read by the loop-variable rung and both indexed-call rungs) · pins: `tests/cases/closures/hole-fn-list-in-generic-*-beside-*.vl`, `hole-fn-list-in-generic-looped-twice-at-two-instances.vl` · a constant index past 0 handed a lambda is [D10793](D10793.md) · was loud emit reject · `vl check` rc 0 · clause 2 · CAPABILITY: a neighbouring spelling runs (the ablation) · found closing [D7846](D7846.md) · filed 2026-10-23 against master `d23840b00`**

Repro:

    function apply2(g) { print(g(1, 2)) }
    function apply3(g) { print(g(10, 20)) }
    function gen<T>(x: T) {
      const gs = [apply2, apply3]
      for f in gs { f((a, b) => a + b) }
    }
    gen("z")
    function v2() {
      apply2((a, b) => a * b)
    }
    v2()

Want:

    3
    30
    2

#### Mechanism

The refused call is `f((a, b) => a + b)` inside `gen`, not a call inside `apply2`. Inside the
generic body the list's type is `((_) => void)[]`, and the element name a closure-list slot is
keyed by drops the hole parameter: it reads `(()=>void)`, the slot a `() => void` function
interns. The loop variable's rung read that slot's key `>v`, which takes no parameters, so a
call passing one was refused. `v2` is scenery: any declared `() => void` function interns `>v`,
and so does a module-level `function tick() { print(9) }`. Without one the slot's key was not
interned and a later rung answered.
