### D13620 — an `if` of hole functions handed beside a caller's un-annotated parameter, to a callee calling it at that parameter, is refused at emit

**loud emit reject · `vl check` rc 0 · clause 2 · CAPABILITY: with `g`'s parameter annotated, `function g(z: i32)`, the same call runs, and so does a literal in its place, `both2(3, …)` · open · `monomorphize: unsupported argument type for `f` in a call to `both2`` · found closing [D13540](D13540.md) · pre-existing: a seed without this change refuses it too · filed 2026-10-25 against master `f5ddf09a0`**

Repro:

    function both2(n, f) {
      print(f("a"))
      return f(n)
    }
    function inner(s) { return s }
    function twice(s) { return s + s }
    let k = false
    function g(z) {
      print(both2(z, if k { twice } else { inner }))
    }
    g(3)
    // vl check: rc 0.  vl run: emitProgram: monomorphize: unsupported argument type for `f` in a call to `both2`

Want:

    a
    3

#### Mechanism

Not ablated to a line. A probe of the split shows the choice planned and applied (one choice
plan, no apply failure), and then `both2`'s `f` is pinned at no slot in the next round: the
callee's parameter `f` is not split. The prediction from the code path is that `f(n)`'s key is
`n`'s type, which is `g`'s parameter hole, so the split finds one key for `f` rather than two.
