### D3029 — `is` against a record shape whose field is an inline string-literal set finds no arm

**closed 2026-10-16 — now prints `b` · was loud emit reject, clause 2 · the tested inline shape's spelling named no registered arm; the `is` lowering and its narrowing now fall back to the arm whose record has the tested record's fields in order (`isVariantSpellingOfShape`), found by ablation closing D5051 · filed 2026-09-28 · pin: `tests/cases/unions/is-declared-name-finds-shape-spelled-arm.vl`**

Repro:

    type A = { x: "a" | "b" } | { y: i32 }
    const u: A = { x: "b" }
    if u is { x: "a" | "b" } { print(u.x) }
    // vl check: rc 0.  vl run: emitProgram: `is` names a declared union member with no interned arm representation (deferred value-union composition)

Want:

    b

#### Mechanism

Localised by the close (see the status line). The checker accepts the test, since the shape is the arm `{ x: "a" | "b" }`. The
emitter looks the tested shape up as a union member and finds no arm row for it. The same test
spelled through an alias (`type L = "a" | "b"`, `is { x: L }`) runs, and so does the other arm's
test (`is { y: i32 }`) with the literal-set arm read in its `else`, so the inline literal set in
the tested shape is what fails to resolve to the arm the declaration registered.

| --- | --- | --- |

| the module binding (`u` a function parameter) | still refused | no |
| the inline set, for an alias `L = "a" \| "b"` in both places | prints `b` | **yes** |
| the arm's field kind, `f32`, `f64`, `i64`, `boolean` or `string` instead | runs | **yes** |
