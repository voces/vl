### D17183 — a literal-union `??` chain whose inner link is a member read off a call reads a local it never declares

**closed 2026-11-24 by IR-N3 · runs, prints `b` then `a` · was check-clean invalid wasm, clause 1 · `coalChainHasCallLhs` reserved the coalesce stash for a chain's middle operand only when it was a call; it now asks the inner link's own `coalLhsStashes`, so a field read off a call or an `if` reserves it too · filed 2026-11-24 against master `1bcc41329` (found and ablated by IR-V9 verifying #9972) · owner IR-N3**

Repro:

    type K = "a" | "b"
    type B = { v: K | null }
    function boxK(x: K | null): B { return { v: x } }
    function mkK(n: i32): K | null { return if n == 1 { "b" } else { null } }
    function lit(n: i32, r: K | null) { print(r ?? boxK(mkK(n)).v ?? "a") }
    lit(1, null)
    lit(0, null)
    // vl check: rc 0.  vl build: the emitted module failed to validate inside `lit`: unknown local 14

Want:

    b
    a

#### Mechanism

`a ?? b ?? d` is lowered re-associated, `a ?? (b ?? d)` (`coalChainMint`). Over a literal union's
`K | null` the chain is no box, so the minted inner link `boxK(mkK(n)).v ?? "a"` carries no type of
its own and reps as its chain's atom. Where that inner link's left operand is a field read off a
call, the inner link writes its left operand once into the coalesce stash (`coalLhsStashes`), but
`coalChainHasCallLhs` reserved that slot for a chain's middle operand only when it was a call, so
the link writes a local no declaration opened and the module does not validate. The same read
bound to a `const` first, or the two-link spelling, reserves it.

| a generic box (`Box<T> = { v: T \| null }`), per IR-V9 | still invalid | no |
| at module scope with a nullable `r`, per IR-V9 | invalid, "unknown local 13" | no |
| an `if` as the middle operand (`r ?? (if n == 1 { mkK(1) } else { null }) ?? "a"`) | invalid | no |
