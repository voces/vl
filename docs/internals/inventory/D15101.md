### D15101 — a lambda seed of a captured written `let` in a generic body instanced at two types needs an id per instance

**runs today and must keep running · split-plan dependent (W family, per-instance id): with the split plan off (`compileSrc` returning after its first compile) it is a loud emit reject, `the reassigned function binding … holds functions called at more than one argument type` · from G2's minimisation of the "reassigned function binding" group · filed 2026-11-03 against master `1484b3d7`**

Repro:

    function other<V>(v: V) { print("O"); print(v) }
    function run<T>(x: T) {
      let k = (y) => { print(y) }
      const flip = () => {
        k = other
      }
      k(x)
    }
    run(1)
    run("s")

Want:

    1
    s

#### Mechanism

The tag decision declines the value written into `k`: the lambda member is declared inside `run<T>`'s body, so each instance of `run` holds its own lambda, and `ftWithinInstancedFn` refuses it as a leaf, since one id cannot name a value per instance. It is one of the shapes the per-instance identity design (with D15102, D15103, D15049 and D15062) is to cover.
