**closed 2026-11-03 · runs, prints `ss` `2` `82` · was a loud emit reject, clause 2 · `ftHolderCoerced` (check_fn_tag.vl) counts a copy `fvaListSetCopy` built as coerced, so the record, list or binding holding it holds no id · the 5 annotated positions of both `fn-set-list-converting-copy` templates run · fixture `tests/cases/closures/fn-set-list-copied-into-holders.vl` · the program that also hands the set to a hole parameter listing it is D15134 · filed 2026-11-03 against master `91585f3a`**

#### Mechanism

The copy is built at every one of these deliveries, but the record literal, list literal or store
around it was typed before the rewrite and still reads as holding the set. `ftHolderCoerced`
followed it to the copy's call, which is no literal, and declined, so the set stayed one closure
called at two types. A recorded copy is a fresh list of adapters and is now counted as coerced.
