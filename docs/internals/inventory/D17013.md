### D17013 — a record of a closed-typed lambda, bound with an annotation and pushed into a list of records of un-annotated functions with different results, is refused at emit

**loud emit reject · `emitProgram: this call runs functions that return different types, and one of them is also held where it cannot be stored as one of the functions this value may hold …` · clause 2 · open · `vl check` rc 0 · the annotated face of `hole-lambda-in-record-of-tagged-set.matrix.vl` at every bound position, and its capture and global-initialiser positions in both faces · found re-grading that matrix after [D17009](D17009.md) · filed 2026-11-19 against master `3398cf5f5`**

Repro:

    function inc0(a) { return a + 1 }
    function half(a) { return a / 2.0 }
    const xs = [{ f: inc0 }, { f: half }]
    const v: { f: (x: i32) => i32 } = { f: (x) => x * 3 }
    xs.push(v)
    print(xs[2].f(3))
    // vl check: rc 0.  vl run: emitProgram: this call runs functions that return different types, and one of them is also held where it cannot be stored as one of the functions this value may hold, so the call has no one signature

Want:

    9

#### Mechanism

Not traced. The binding's annotation closes the lambda at `(i32) => i32`, so it joins the list's set
as a closure of one signature, while the set's other members return `f64`: the tag decision leaves
the set a closure set and the call through it has no one signature. The un-annotated binding runs
since D17009 (the lambda is then a hole lambda the set tags).
