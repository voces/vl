### D2734 — `T` inferred from a nullable map argument against `T | string` answers `is` for the wrong map, or emits an invalid module

**check-clean silently wrong · clause 1 · found by #3202's review (the `b/` grid's `inferred` cells) · identical on master · filed 2026-09-26 against master `74bd044d7`**

Repro:

    function f<T>(u: T | string): boolean { u is Set<i32> }
    const x: {[i32]: boolean} | null = Map()
    print(f(x))
    // PRINTS true

#### Mechanism

With no type argument, `T` is inferred from a `{[i32]: boolean} | null` argument against the
union `T | string`. The monomorphizer's binding walk (`bindGenWalk`) has no arm for a union
expected type, so the instance has no exact binding for `T` and falls back to the rep key,
where a Set and its boolean map share one tag. The explicit spelling
`f<{[i32]: boolean} | null>(x)` is keyed exactly and prints `false` (master printed `true`
for it too). The same family's `string | T` spelling (the grid's `__2__` cells, 14 of them)
emits a module that fails validation.

#### Ablation

| ingredient removed | outcome | needed? |
| --- | --- | --- |
| the inference (`f<{[i32]: boolean} \| null>(x)`) | runs, prints `false` | **yes** |
| the `null` on the argument's type | refuses (D2717) | **yes** |
