### D3642 — no whole-record store in place: a pooled record is reset only field by field (SP-032's remainder after record spread)

**loud check reject · raised at the PARSE stage, so `vl check` closes with `(parse error)` · an open BUILD ITEM, not a defect · sunpa SP-032 · filed 2026-10-04 by lane SD against master `221c7954f` · design context `docs/internals/record-spread-design.md` §5**

Repro:

    type P = { x: f64, y: f64, life: f64, style: i32 }
    const pool: P[] = [{ x: 0.0, y: 0.0, life: 1.0, style: 0 }]
    function spawn(x: f64): P {
      let p = pool[0]
      p = { ...p, x, y: 0.0 }
      p
    }
    print(spawn(2.0).x)
    // master: vl check rc 1, "expected a field name but found `...`" (parse error)

#### Mechanism

This is sunpa's own spelling from SP-032. It fails today because record spread does not parse.
Once spread lands (owner ruling 2026-10-04 (B)) the witness will RUN, but it still will not do what
SP-032 asked for: it allocates a NEW record and rebinds `p`, while `pool[0]` and every other
holder keep the old record (`record-spread-design.md` §5, "Aliasing"). The missing capability is a
store that overwrites EVERY field of an existing record in place, in one statement, without
allocating, so a pool can reset a slot without writing 27 assignments. Its surface (an assignment
form, a std `copyInto(dst, src)` for records of one type, or something else) needs an owner ruling.
When spread lands this row grades MOVED. The PR that lands spread must re-witness the row with the
in-place property, for example a `held` alias that must observe the reset. It must not close the
row.

#### Grading list

- The aliasing witness in `record-spread-design.md` §5 (`held` keeps the stale record), which is
  correct for spread and is exactly the behaviour an in-place store would change.
- sunpa `src/fx.vl` `spawn`: 27 field assignments a reset.
