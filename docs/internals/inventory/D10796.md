### D10796 — a hole-function list element past 0 that calls its parameter with its own parameter is refused an un-annotated lambda

**loud emit reject · `vl check` rc 0 · clause 2 · CAPABILITY: a neighbouring spelling runs (the ablation) · found closing [D10793](D10793.md) · present on master `cf38fa028` · filed 2026-10-23 against master `cf38fa028`**

Repro:

    function apply2<T>(g, x: T) { print(g(x, x)) }
    function apply3<T>(g, x: T) { print(g(x, x)) }
    const gs = [apply2, apply3]
    gs[1]((a, b) => a + b, 7)
    // vl check: rc 0.  vl run: emitProgram: monomorphize: unsupported argument type for `g` in a call to `apply3`

Want:

    14

#### Mechanism

The checker binds the lambda against element 0, as in [D10795](D10795.md). D10793's rung reads
the types that the element's own calls of `g` pass. Here those calls pass `x`, the element's own
parameter, so the flow pins are open (`T`) rather than closed, and the lookup returns nothing. To
resolve them, the call's binding of `x` (here `i32`) has to be substituted into the pins first.
