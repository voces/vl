### D13080 — `?.` on a hole receiver that an instance pins at a union of two records is refused at emit

**closed 2026-10-25 · runs, prints `3` and `-1` · fixed: `drwWalkOptMember` and the `??` fold (`recUnionReadTys`, emit_rewrite.vl) read a hole receiver's pins (`holePinsOfTy`, check_hole_pins.vl), and when every pin is a record or union of records holding the field, rewrite the shared node once, typing the narrowed receiver and the field read as derived holes each instance resolves at its own pin (a pin whose field is a nullable scalar, [D13280](D13280.md)) · pins: `tests/cases/generics/hole-optional-member-read-record-union.vl` · was loud emit reject, clause 2 · CAPABILITY: the annotated twin `function F(u: A | B | null)` prints `3` and `-1` · the residue of [D3215](D3215.md), which admitted `?.` on a hole · found closing [D3215](D3215.md) · filed 2026-10-25 against master `0adbf4b86`**

Repro:

    type A = { k: i32, x: i32 }
    type B = { k: i32, y: string }
    function F(u) { print(u?.k ?? -1) }
    const a: A | B | null = { k: 3, x: 1 }
    const b: A | B | null = null
    F(a)
    F(b)
    // vl check: rc 0.  vl run: emitProgram: `??` over this nullable value is not supported yet

Want:

    3
    -1

#### Mechanism

From the code path. The concrete spelling never reaches the emitter as a `?.`: `drwWalkOptMember`
(`emit_rewrite.vl`) reads the shared node's recorded type, sees a nullable union of records, and
rewrites it into `if u != null { u.k } else { null }`, whose `u.k` is the shared-field dispatch.
In a hole function the shared node's type is the hole, so the rewrite leaves the `?.` alone, and
the emitter's `?.` and `??` arms know a struct row, a variant row and a scalar, not a box of
several records. The rewrite would need the instance's receiver type, or the emitter a
shared-field arm of its own.
