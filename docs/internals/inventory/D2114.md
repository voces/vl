### D2114 — callback specialization rewrites calls to a function-typed parameter inside a for-in loop that shadows the parameter's name

**check-clean invalid wasm · 1 witness, identical on the seed before and after D2110 · filed 2026-09-23 against master `7b16d43ab`, found reviewing #3050**

Repro:

    function a(): void { print("a") }
    function go(f: (i32) => i32): void {
      const fs: (() => void)[] = [a]
      for f in fs { f() }
    }
    function v(x: i32) { return x }
    go(v)

#### Mechanism

The failure is inside `go$cb0`, the callback-specialized instance `emit_mono.vl` builds for
the argument `v`: `type mismatch: expected i32, found structref`. The specialization redirects
calls to the parameter `f` without honouring the loop variable `f` that shadows it, so the loop
body's `f()` is lowered against `(i32) => i32`. Not yet ablated against the non-specialized
spelling (a parameter the specializer declines, e.g. a closure argument that captures).

#### Grading list

The reviewer's `sh3`, `sh3a` and `sh7` probes of #3050 (the same shadow with the signatures
swapped, and with nested loops).
