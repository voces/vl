### D16025 — a union's row identity still rides its label: one union type can hold two rows that differ only in `null` position, and a declared alias is found by its label registration

**runs today and must keep running · carried past step 7 as a floor (coordinator, 2026-11-14) · the
identity half of [D16032](D16032.md), whose readers are typed · filed 2026-11-14 against master `875f5c709`**

Repro:

    type A = { a: i32 }
    type B = { b: i32 }
    function f(x: A | null | B): i32 {
      if x == null { return 0 }
      if x is A { return x.a }
      x.b
    }
    function g(x: A | B | null): i32 {
      if x == null { return 0 }
      if x is B { return x.b }
      1
    }
    const p: A | null | B = { a: 3 }
    const q: A | B | null = { b: 4 }
    print(f(p) + g(q))

Want:

    7

#### Mechanism

No reader looks a union up by its label any more (D16032). The label index (`unRowBySid`) is
still how registration decides that a union already has a row, through three guards:
`unNameAdoptTyKeyRow` (emit_union_tykey), `monoPinMintedUnion` and `monoRegisterPinUnion`
(emit_mono), with `annAdoptRegisteredName` (emit_collect) rewriting an annotation to the
registered spelling. A probe over the 19,744-record population (`tests/cases` and the distilled
corpus, master `875f5c7`) found the label bound where the type key would decide otherwise in
3,242 programs at `unNameAdoptTyKeyRow`, 7 at `monoPinMintedUnion` and 22 rewrites. A sample of
400 of the 3,242:

| why the type key disagrees | programs | decisions |
| --- | --- | --- |
| the name is a declared union alias (`cUserTypes`), which adopt refuses unless it is bound | 399 | 599 |
| the key row exists, but `null` sits in a different position among its members | 24 | 458 |

So two rows can share one member multiset and differ only in where `null` sits, which breaks
step 7's "one row per type". A declared alias reaches its row through its declaration's label
registration, not through its type's key row; #7835 folds an alias to its base type's key, so why
adopt still needs the binding is part of this row.

#### Ablation

The repro is the `null`-position shape. Whether it lands on one row or two is decided by
registration order, so the program runs either way; the defect is the identity, not an output.

#### Grading list

The 24 null-shape programs and the 399 alias programs of the sample, re-graded after the null
position joins the row's typed identity (or the two rows merge) and aliases answer through their
type's key row; then `unRowBySid` and the three guards go, in a sweep-labelled PR.
