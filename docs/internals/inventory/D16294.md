#### Mechanism

[D12234](D12234.md)'s close builds a maker delivered at a second closed function type at that
type's twin (`monoMakerTwin`, emit_mono.vl), and reaches it through the maker's returned BINDING. A
returned literal is the value mono's lambda-literal delivery sees instead, and that path holds a
literal to one signature.

#### Trace (2026-11-15, master `64a0f4dac`)

- The two-type exemption in `monoDeliverCallRets` (D6522, D12234) passes. At the second
  delivery, `monoIsMakerFe`, `elabMakerOpen` and `elabMakerTwinHeld` (both types) all hold.
- The refusal is `monoDeliverLamLit`'s, from the twin `deliver$1`'s own return delivery. Its
  context is the twin, and its node is the root's literal.
- The twin shares the maker's body nodes: `deliver$1` has body 5, return 4 and literal 3, which
  are the root's own. `monoInstanceForReq` mints a header over the same body, so the twin's
  delivery at `(string) => string` reaches the literal the first twin pinned at `(i32) => i32`.
- A literal handed as a call argument takes an instance per type by rewriting the argument slot
  (`monoHoleLamArgAgain`). A twin has no slot of its own to rewrite, since rewriting return 4
  rewrites the root and every twin.
- A returned binding (D12234) runs because its name read is retargeted per frame.
- The fix wants per-instance bodies. In mono that is a change to how instances share bodies, a
  risk to every other path. The IR's instantiate-into-IR (I9) gives each instance its own body by
  construction, so this row is parked there.
