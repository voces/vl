#### Mechanism

The checker typed every `.pop()` `T | null`, whatever guarded it. Now an `if` or `while` whose
whole condition is `k.length > 0` (`!= 0`, `>= 1`, `0 < k.length`, `0 != k.length`, `1 <=
k.length`) opens a fact for the place key `k` (a name or a path like `o.xs`) over its then arm
or body. The first `k.pop()` checked in the same function while the fact is live is typed `T`
and consumes it. The fact ends at: any call or operator that may dispatch to one (which covers
a pop through an alias, a closure, or a callee, and the guard's own pop), an assignment to the
key's root name or to a name a key subscripts with, ANY assignment to a field or element (it may
reach the list through another name: `p.xs = []` with `p` the same record as `o`), a
declaration of its name, a loop (its body runs again), a call with named arguments
(evaluated in parameter order), and the end of the arm; a closure body is another function, so
it neither consumes nor kills. A key through an element (`a[0]`) opens no fact, since the
emitter pops only a local's or a field's list. An element type over a type variable or hole stays nullable. The
emitter reads a pop the checker typed non-null as the element in its own rep, unchecked, and a
`??` over it folds to the pop. `xs[xs.length - 1]` was already `T`.

| ingredient removed | outcome | needed? |
