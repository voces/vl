### D9160 — a choice of two generic functions called inside a generic body whose type parameter shares the callees' name is check-clean invalid wasm

**check-clean invalid wasm · `vl check` rc 0 · `type mismatch` inside `f` · clause 1 · found closing [D9120](D9120.md) · present on master `4121cc9a7` · filed 2026-10-21 against master `4121cc9a7`**

Repro:

    function idg<T>(t: T): T { return t }
    function kg<T>(t: T): T { return t + t }
    const c = [1].length > 0
    function f<T>(v: T): T {
      const h = if c { kg } else { idg }
      print(h("s"))
      return v
    }
    print(f(3))
    // vl check rc 0, vl run: invalid module, the emitted module failed to validate inside `f`

#### Mechanism

Not traced. The choice is called at one type only, so it is not [D9120](D9120.md)'s second
type; what the defect needs is the enclosing generic's type parameter carrying the same name,
`T`, as the callees'. Renaming it fixes the program, which points at the arms' instancing
resolving the callees' `T` against the enclosing frame's binding of `T` (`i32`) rather than the
call's `string`.

#### Ablation

| ingredient removed | outcome | needed? |
| --- | --- | --- |
| the name clash, for `f<S>(v: S): S` | runs, `ss` `3` | **yes** |
| the generic body, for `f(v: i32): i32` | runs, `ss` `3` | **yes** |
| the binding, for `(if c { kg } else { idg })("s")` inline | same invalid wasm | no |

#### Grading list

The inline spelling above; the binding read at both `string` and `T` inside `f<T>`; the same with
a `match` choice.
