### D9160 — a choice of two generic functions called inside a generic body whose type parameter shares the callees' name is check-clean invalid wasm

**closed 2026-10-21 — the filed repro RUNS and prints `ss`, `3` · was check-clean invalid wasm, `vl check` rc 0, `type mismatch` inside `f` · clause 1 · found closing [D9120](D9120.md) · filed 2026-10-21 against master `4121cc9a7` · closed in emit_mono.vl: a value typed at another generic's open signature keeps it in the instance, so the enclosing binding of the shared name does not close it · residue [D9190](D9190.md)**

Repro:

    function idg<T>(t: T): T { return t }
    function kg<T>(t: T): T { return t + t }
    const c = [1].length > 0
    function f<T>(v: T): T {
      const h = if c { kg } else { idg }
      print(h("s"))
      return v
    }
    print(f(3))
    // was: vl check rc 0, vl run: invalid module, the emitted module failed to validate inside `f`

#### Mechanism

The instance `f@i32` binds the name `T` to `i32`, and monomorphization substitutes by name.
The arms' type `(T) => T` belongs to `kg` and `idg`, but three places in `emit_mono.vl`
substituted it with the enclosing binding and got `(i32) => i32`:

- the clone of a generic read by name (`monoCloneGenericCallsRaw`, through `monoLamCallTy`);
- the per-instance retype of the `if` or `match` join (`monoIfChainRebuildPinned`);
- the argument pin handed to a higher-order generic (`monoPinTyParamComposite`). From that pin,
  `monoBindCols` bound the callee's `T` to `i32`.

Each place now leaves a type alone when `tyIsForeignGenericSig` says it is another top-level
generic's open signature. All three are needed. With the join alone, the inline, `match`,
depth-2, higher-order and mixed-name spellings still failed. With the join and the clone, the
higher-order one still failed.

[D9190](D9190.md) replaced the three guards with one rule at the substitution: an instance
binding substitutes only its own template's type variables. Every spelling below still runs.

#### Ablation
