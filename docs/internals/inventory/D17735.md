### D17735 — a function-local `let` list of functions rebound past its earlier values keeps one storage across its regions

**loud emit reject · clause 2 · `vl check` rc 0 · filed 2026-11-27 against master `d29f3434d` by lane START-2, the local half #10627 leaves out**

Repro:

    function id<T>(x: T): T { return x }
    function inc(x: i32) { return x + 1 }
    function runS(a: ((x: string) => string)[]) { print(a[1]("s")) }
    function runI(a: ((x: i32) => i32)[]) { print(a[1](2)) }
    function f() {
      let zs = [id]
      zs.push(inc)
      runI(zs)
      zs = [id, id]
      runS(zs)
    }
    f()
    // vl check: rc 0.  vl run: emit error, "a list holding a generic function is called through its elements at more than one type"

Want:

    3
    s

#### Mechanism

The rebind `zs = [id, id]` cuts every earlier value off from the reads after it (D10202's cut),
so the checker accepts the two deliveries at `(i32) => i32` and `(string) => string`. #10627
holds a module binding of this shape per region (`binding_regions.vl`), deciding it in
`elabRegionsDecide` before the class readers. It leaves a function's local out: holding the
local per region the same way compiles, then traps at run time, `indirect call type mismatch`
inside `runS`. The second region's literal is built with `i32` closures, because the frame's
instances and element types are decided at the joined type before the region decision.
