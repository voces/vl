### D1714 — the nullable-REF `??` arm takes its block type from the operand's own heap type, so a struct default over an `as?`-produced niche has nowhere to land

**closed 2026-09-06 — a joining default takes a boxed arm of its own: the operand is staged in
the `?.` receiver slot, tested for null, and both sides box into the result's row · filed
against master `1f7406139`, mechanism corrected by disassembly the same day · residues D1720
and D1721 · 0 corpus cells**

Repro:

    type A = { r: i32 }
    function mkU(): i32 | string { return 4 }
    function st(): A { return { r: 8 } }
    const u = mkU()
    const w = (u as? string) ?? st()
    if w is A { print(w.r) } else { print(w) }
    // prints 8 since the close; before it, `vl check` rc 0 then exit 70,
    // the emitted module failed to validate: type mismatch: expected (ref $type), found (ref $type)

#### Mechanism

**Three rows, read off the disassembly and the checker.** The operand `u as? string` is
`string | null`, which is the nulstr NICHE — a `(ref null $str)` — and NOT a box. The default
`st()` is a plain `A`, `(ref $A)`. The type the checker records for the `??` is `string | A`, a
union, so its rep is the value box `(ref $uBox)`. Three different heap types, and the emitted
block declared the first of them.

**The failing arm is the nullable-REF one, not the stashed box one.** `emitCoalesceGo` reaches
`emitCoalesceNulRefCtx` through `exprNullableString`, and that core takes the block type from
the operand's own `(ref $heapIx)` because `br_on_non_null` branches with the raw ref it tested.
The struct default was then emitted into a string-typed block.

**The close is the D1699 decision at a third arm**, with a shape `br_on_non_null` cannot
produce. `coalesceNicheJoinsToBox` asks whether the checker's `??` type is a variant-bearing or
value union with two or more non-null members while the operand is a nullable-ref niche; where
it is, the operand is staged once in the `?.` receiver slot (`optRecvSlot`, its reservation
shared, not doubled), `ref.is_null` picks the arm, and both arms `struct.new` the box — the
default through `emitUnionBoxArg`, the operand under its own atom's or variant's tag. A
FITTING default keeps the `br_on_non_null` shape untouched: master's own compiler source emits
byte-identically under the candidate.

**The consumer half is the destination's slot**, and it is why the in-function faces stayed
silent after the lowering was right: `letInitCellKind` and `collectLocals` each read the
OPERAND's rep and declared the niche's own ref, then stored a box into it. Both ladders gained
the same rung, ahead of every rung that reads the operand.

**A struct default whose arm cannot be resolved now refuses LOUDLY** rather than passing raw
into a box blocktype. `unionArmVariantForStructExpr` asks `structIndexOfExpr`, which answers a
VARIANT-table index for a variant-returning call; where a second struct row precedes the arm's
in the struct table the layout compare then reads the wrong row and finds no arm. Declaring
`type W = { f: string | null }` before `type A` is enough to see it, and removing the
declaration is enough to hide it.
