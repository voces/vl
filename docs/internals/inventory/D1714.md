### D1714 — an `as?` operand with a STRUCT default stages the operand's own box where the join's is wanted, the one delivery form D1709's mint does not reach

**check-clean invalid wasm · filed 2026-09-06 against master `1f7406139` · D1709's close moves
the `??`, if-expression and call operand forms and leaves this one · 0 corpus cells**

Repro:

    type A = { r: i32 }
    function mkU(): i32 | string { return 4 }
    function st(): A { return { r: 8 } }
    const u = mkU()
    const w = (u as? string) ?? st()
    if w is A { print(w.r) } else { print(w) }
    // vl check: rc 0.  vl run: exit 70,
    // the emitted module failed to validate:
    // type mismatch: expected (ref $type), found (ref $type)

#### Mechanism

D1709 mints the inferred join's row from the binding initialiser's arena type, and the `??`
lowering's stashed arm then coerces the default into it. An `as?` operand reaches that same
stashed arm, but its own value is already a box — `string | null` here — so the arm stashes one
box and the join wants another, and the two heap types are both elided to `(ref $type)` in the
validator's sentence. The `??` and if-expression operands of the same shape run, and so does an
`as?` operand with a SCALAR default (`(u as? i32) ?? "x"` prints `4`), which is what places this
at the operand's own box rather than at the mint.

#### Ablation

| ingredient removed | outcome | needed? |
| --- | --- | --- |
| the `as?` operand (a call operand instead) | runs, prints `8` | **yes** |
| the struct default (`(u as? string) ?? "x"`) | runs | **yes** |
| the inference (`const w: M = …` with `type M = i32 \| A`) | refuses identically | no |
| the null value (`mkU` returning a string) | refuses identically | no |
