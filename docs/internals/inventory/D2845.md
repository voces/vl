### D2845 — a spread of an `i32[]` into a list literal typed `f64[]` builds no converting element loop

**check-clean invalid wasm · clause 1 · found beside D2838 · the same on master `7323baf55` · filed 2026-09-27 against master `7323baf55`**

Repro:

    const a: i32[] = [3]
    const q = [...a, 2.5]
    print(q[0] / 2.0)
    // vl check: rc 0.  vl run: invalid module in the top-level code

#### Mechanism

A spread copies its operand's elements into the new literal, so no list is shared and no
aliasing rule applies. The literal is typed `f64[]`, but the spread of an `i32[]` operand is
lowered as a copy between two lists of one storage. The `f32[]` operand runs (`[...f32s,
2.5]` prints `0.75` for `1.5`), so the `i32` to `f64` element conversion is the missing arm.
Not yet localised in the emitter.

#### Ablation

| ingredient changed | outcome | needed? |
| --- | --- | --- |
| an `f32[]` operand | runs | **yes** |
| an `i32` element beside it (`[...a, 2]`) | runs | **yes** |
| an annotated destination (`const q: f64[] = [...a]`) | still invalid | no |
| an un-annotated operand (`const a = [3]`) | still invalid | no |

#### Grading list

`const q: f64[] = [...a]`; `xs.push(...a)` on an `f64[]`; a spread argument into an `f64[]`
rest parameter.
