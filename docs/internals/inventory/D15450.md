### D15450 — a choice between a capturing nested function and a plain one, handed to a hole parameter called at two types, needs the split plan

**runs today and must keep running · runs only through the split plan: with it off (`compileSrc` returning after its first compile) a loud emit reject, `monomorphize: unsupported argument type for `f` in a call to `both``, clause 2, open · a member that captures its encloser's binding cannot be a tagged set's id, which carries no environment, so the choice is a closure that one signature cannot serve at both of `both`'s calls: D14841's capturing shape · fixture `tests/cases/closures/choice-of-nested-capturing-function-handed-to-hole-param.vl` · filed 2026-11-05 against master `6474c12f`**

Repro:

    function both(f) {
      print(f("a"))
      print(f(1))
    }
    function nested(c: boolean, n: i32) {
      function inner(s) {
        print(n)
        return s
      }
      function ask(s) { return s }
      both(if c { inner } else { ask })
    }
    nested(true, 9)

Want:

    9
    a
    9
    1

#### Mechanism

`both`'s `f` is called at `string` and at `i32`, so a value handed to it is either a tagged set's
id dispatched per call or one closure per signature (a bundle, D14841). `inner` reads `n`, so its
id would have to carry `nested`'s environment and the tag decision leaves `{inner, ask}` untagged.
The `if` value is then one closure, and with the split plan off mono finds no single signature for
it at the hand. The split plan runs it by giving each of `both`'s calls its own copy.

#### Ablation

| ingredient changed, split plan off | outcome | needed? |
| --- | --- | --- |
| `inner` prints `9`, not the captured `n` | runs | **yes** (the capture) |
| `ask` captures `n` too | refuses the same way | no |
| `both` calls `f` at one type | runs | **yes** (two signatures) |
| `both(inner)`, no choice | refuses: `cannot take the generic function `inner` as a value` | **yes** (another refusal) |
| the choice bound to a `const` first | refuses the same way, and with the plan on too (D15451) | no |

#### Grading list

D15451 (the `const`-bound spelling, which the split plan does not serve either); D14841's bundle
fixtures, since a bundle of `{inner, ask}`'s closures at the two signatures is the close.
