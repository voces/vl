### D3693 — a record-pattern generic instantiated for a record whose pattern field is not its first field, beside a second instance, is invalid wasm

#### Mechanism

Confirmed; the two instances pin `{ x: boolean }` and `{ x: i32 }`, which share a layout, and
three readers took one for the other. (1) `buildStructSupers` (emit_sections.vl) gave `a`'s row
the first one-field prefix of its layout as its wasm supertype, which was the `{ x: i32 }`
literal's row, so `a` could not reach the `{ x: boolean }` instance; it now prefers, of two
prefixes of one length, the one agreeing on `i32` against `boolean` (`rowBoolI32Agree`).
(2) The strict pass of `structIndexOfTypeName` returned the first ANONYMOUS row with the right
field names whatever its code-0 kinds, which D2866 had already stopped for a declared row; a
spelled `{x:boolean}` reached the `{ x: i32 }` literal's row. It now asks every row
`code0SpellingFitsRow`, keeping a misfit only as the fallback. (3) That fallback is what
`anonHandleTyIx` (emit_classify.vl) then handed the monomorphizer as the pin's type, binding `T`
to the other kind: with the first two fixed, the swapped-order spelling (`{ y: 5, x: 7 }` beside
`{ x: false }`) ran and printed `true` for `7`. A spelled shape whose row disagrees is now no
anonymous handle.
