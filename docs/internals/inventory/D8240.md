### D8240 — a list literal around a generic record constructor, inside a generic body pinned at both `i32` and `boolean`, builds the second pin's list at the i32 backing

**closed 2026-10-20 by lane emit-collect · runs, prints `1` then `true` · was loud emit reject · clause 2 · found closing [D2871](D2871.md), whose grading list it is · refused on master `8d04eb8ff` too, as `ref valtype with no interned shape` · filed 2026-10-20 against master `8d04eb8ff` · fixtures `generics/ctor-record-list-pins-sharing-a-rep.vl`, `objects/record-field-holds-pinned-ctor-list-and-typed-map.vl`, matrix `generic-ctor-record-list-two-pins`**

Repro:

    function pc<T>(x: T) { { a: x } }
    const p = [pc(1)]
    const q = [pc(true)]
    print(p[0].a)
    print(q[0].a)
    // vl check: rc 0.  vl run: emitProgram: struct array elements are not supported

Want:

    1
    true

#### Mechanism

The filed guess (that `emitArrUnder` misroutes the second list) was wrong. The `boolean` pin's
record had NO row: D2850's mint (`mintPinnedObjLit`, `compiler/emit_collect.vl`) skipped a
literal whenever `structIndexOfObjCtx` classified it to some row, and `{a: boolean}` classifies
to the `i32` pin's `{a: i32}`, which shares its wasm shape. With no row, `shapeNominalOfTy`
found no nominal element and the list fell to `emitArrI32`. Closed by `pinCtorRowServes`: the
row a literal classifies to serves it only when the literal's type, with each type-parameter
field at its pin, is assignable to that row's type; otherwise the pin mints its own row.
`wasmEmit.vl` is unchanged.

#### Grading list

The generic-body spelling above, and `pc(1)` beside `pc(true)` and `pc("s")` together.
