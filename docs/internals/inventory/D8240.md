### D8240 — a list literal around a generic record constructor, inside a generic body pinned at both `i32` and `boolean`, builds the second pin's list at the i32 backing

**loud emit reject · clause 2 · found closing [D2871](D2871.md), whose grading list it is · refused on master `8d04eb8ff` too, as `ref valtype with no interned shape` · filed 2026-10-20 against master `8d04eb8ff`**

Repro:

    function pc<T>(x: T) { { a: x } }
    const p = [pc(1)]
    const q = [pc(true)]
    print(p[0].a)
    print(q[0].a)
    // vl check: rc 0.  vl run: emitProgram: struct array elements are not supported

Want:

    1
    true

#### Mechanism

Not traced past the refusal site. Each pin's record now has its row (D2850), and `{a: i32}`
and `{a: boolean}` share one wasm shape, but `emitArrUnder` (`wasmEmit.vl`) routes the second
literal to `emitArrI32` rather than the ref-list build. `arrLitIsRef` takes no instance and
reads the literal's own recorded type, so the second record list is not seen as a ref list.

#### Ablation

| ingredient changed | outcome | needed? |
| --- | --- | --- |
| only `pc(1)`, or only `pc(true)` | runs | **yes** (both pins) |
| `pc(1)` beside `pc("s")` | runs, `1`, `s` | **yes** (two pins sharing a rep) |
| non-generic `pi(x: i32)` and `pb(x: boolean)` | runs, `1`, `true` | **yes** (the type parameter) |
| inside a generic `k<T>(t: T) { [pc(t)] }` called `k(1)`, `k(true)` | same refusal | no |

#### Grading list

The generic-body spelling above, and `pc(1)` beside `pc(true)` and `pc("s")` together.
