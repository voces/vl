### D15065 — a function set called at two types through a returned list, beside a hole helper pushing its member onto another list, builds the helper's push at the closure rep

**closed 2026-11-03 · runs, prints `2.25 6`, with the split plan on and off · was check-clean invalid wasm, clause 1 · `ftHoleParamOf` (check_fn_tag.vl) declines a tagged id's hand to an un-annotated parameter the callee writes into a holder's slot (`ftParamStored`), so the set stays a closure there (#5986) · fixtures `tests/cases/closures/hole-helper-pushes-listed-member-onto-other-list.vl` and `…-onto-uncalled-list.vl` · found by G2 closing the hole helper's late demand (#5978) · filed 2026-11-03 against master `77d5ddf6`**

Repro:

    function inc0(a) { return a + 1 }
    function dbl0(a) { return a * 2 }
    function deliver0() { return [inc0] }
    print(deliver0()[0](1.25))
    function addTo(xs, f) { xs.push(f) }
    const fs = [dbl0]
    addTo(fs, inc0)
    print(fs[1](5))
    // vl check: rc 0.  vl run: the emitted module failed to validate inside `addTo`: expected (ref $5), found i32

Want:

    2.25
    6

#### Mechanism

`{inc0}` is tagged at check time, since a list literal read by index holds it, and its hand to
`addTo`'s un-annotated `f` was accepted with no look at the callee (`ftHoleParamOf`). Inside
`addTo`'s instance `xs.push(f)` stored that `i32` id into `fs`'s closure slot, and the late
decision does not untag a set the check tagged. The hand is now declined where the callee writes
the parameter into a holder's slot, as a `push` or `set` argument.
