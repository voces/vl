### D15923 — a call's list of records whose function field holds un-annotated functions returning different types, stored in a record literal's field, has no shape at emit

**closed 2026-11-19 · runs, prints `4` · was loud emit reject, `emitProgram: ref valtype with no interned shape`, clause 2 · fixed in emit_anon_fields.vl `anonRefListElemRowOfTy`: a ref-list field's record element holding a tagged set is keyed by its tag rep (`tagRepTyFn`), the row its literals build at, so the outer literal mints its row · pin `closures/call-result-list-of-tagged-records-in-a-record-field.vl` · neighbours left open: the pass-through return [D17006](D17006.md), the map value [D17007](D17007.md) · found by w320 beside [D15804](D15804.md); filed 2026-11-12 against master `22d35fe47`**

Repro:

    function inc0(a) { return a + 1 }
    function half(a) { return a / 2.0 }
    function mk() { return { a: [{ f: inc0 }, { f: half }] } }
    const w = { f: mk().a }
    print(w.f[0].f(3))

Want:

    4

#### Mechanism

The outer literal's field value `mk().a` is typed at the list of the open record
`{f: (_) => _}`, which names no row: its literals build at the tagged ids row `{f: i32}`. The
ref-list field-code rung asked for that open type's row only, so the field had no code and the
literal no row; the in-place literal reads its leading element's row instead. Before the close: The list reaches the record literal from a call: the same list literal written in
the field runs, as does the call's list bound to a name and read directly. The functions'
differing results are needed, since the one-result twin runs. w320 reports the same message
when the list is returned through a second function or stored as a map value.

#### Ablation

| spelling | outcome |

| the witness | loud emit reject |

| one result type, `half(a) { return a * 2 }` | runs, `4` |
