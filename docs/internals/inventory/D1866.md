### D1866 — a MAP whose value is a union with a map member is check-clean invalid wasm when the map is read back out; the string-keyed spelling is the silent half of `B6a-map-in-union-box`

**check-clean invalid wasm (`the emitted module failed to validate inside the module's top-level code: Invalid input WebAssembly code at offset 2107: type mismatch: expected (ref null $type), found (ref $type)`) · `vl check` rc 0 · filed 2026-09-07 against master `48eeedf57`**

Repro:

    const inner: { [string]: i32 } = Map()
    inner["a"] = 1
    const __m: { [string]: { [string]: i32 } | i32 } = Map()
    __m["k"] = inner
    if __m["k"] != null {
      if __m["k"] is { [string]: i32 } { print(__m["k"].size) } else { print(-1) }
    }
    // vl check: rc 0.  vl run: invalid module, type mismatch: expected (ref null
    // $type), found (ref $type). Should print 1.

#### Mechanism

**This is `B6a-map-in-union-box`** (`open-rulings.md` §D), witnessed at the spelling that
entry believed was safe. A union member lowers into `{tag, value}` with an `anyref` payload,
and the tag records the MEMBER, not the map STRUCT — while a map's struct is per (key rep,
value rep). The unbox at an `is`-narrowed read therefore casts to whichever struct the member
NAME scan claimed, which is right only when the program has exactly ONE map struct.

The witness above has **two**: the outer `{[string]: <union>}` and the inner
`{[string]: i32}`. The cast hits the wrong one, and the module does not validate.

The ruling entry says of the string-keyed spelling that it *"runs today … which is not
evidence the position is sound: it is evidence that one map struct is the common case and the
cast happens to hit it."* **This row is the program that entry predicted.** It was reached
from the other direction — the nine positions the D1865 landing left SILENT in
`recursive-alias-map-into-union.matrix.vl` — and ablated down to six lines with no alias, no
recursion and no generic.

#### Ablation

| ingredient removed | outcome | needed? |
| --- | --- | --- |
| the RECURSIVE alias — `V = f64 \| string \| {[string]: f64}`, no self-reference | **still fails** | **no** |
| the union — a map of a map, read back | runs | **yes** |
| the map MEMBER — store an `f64` in the union instead | runs | **yes** |
| the read-back — store into the map value without reading it out | runs | **yes** |
| the outer MAP — the same union read back from a plain BINDING | runs | **yes** |
| the outer MAP — the same union read back from a LIST element | runs | **yes** |

Two corrections to this row as first filed. **Recursion is not an ingredient**: the
non-recursive spelling fails identically, so the first ablation row above replaces the one
that claimed removing the alias made it run. And *"recovered from a CONTAINER — a map value,
a list element, a struct field"* is too wide: a LIST element runs and a plain binding runs.
The container has to be a **MAP**, which is what puts a second map struct in the program.

#### Grading list

`scripts/capability-probes/matrix/recursive-alias-map-into-union.matrix.vl` is where these
were found — **53 of 62 RUNS, 9 SILENT** on `48eeedf57`, the nine being eight un-annotated

**A fix here is not a fix, it is a ruling.** Closing these means opening the map-in-union arm,
which is option (b) of `B6a-map-in-union-box` and the owner's to take. The cheap half is
option (a′) recorded there: extend the existing loud refusal to the string-keyed spelling, so
the nine cells and this witness become loud instead of silent. No `runs` cell is lost by that
— every one of them is already broken.
