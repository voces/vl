### D1866 — a map-valued union member re-read inside its own narrowing is check-clean invalid wasm; binding the read once makes it run

**check-clean invalid wasm (`the emitted module failed to validate inside the module's top-level code: Invalid input WebAssembly code at offset 2107: type mismatch: expected (ref null $type), found (ref $type)`) · `vl check` rc 0 · filed 2026-09-07 against master `8bdd886af`**

Repro:

    const inner: { [string]: i32 } = Map()
    inner["a"] = 1
    const __m: { [string]: { [string]: i32 } | i32 } = Map()
    __m["k"] = inner
    if __m["k"] != null {
      if __m["k"] is { [string]: i32 } { print(__m["k"].size) } else { print(-1) }
    }
    // vl check: rc 0.  vl run: invalid module, type mismatch: expected (ref null
    // $type), found (ref $type). Should print 1.

The one-line control that RUNS — the same program with the map read bound once:

    const got = __m["k"]
    if got != null {
      if got is { [string]: i32 } { print(got.size) } else { print(-1) }
    }

#### Mechanism

The narrowing is on the EXPRESSION `__m["k"]`, and the arm's body reads `__m["k"]` again.
The second read is a fresh map read that does not carry what the `is` established, so the
value arrives at `.size` as the union box rather than the narrowed map and the module does
not validate. Binding the read to a name once gives the narrowing a place to live, and the
same program runs.

**It is NOT `B6a-map-in-union-box`, though this row said so between #2905 and now.** That
reading was that a map cannot be a union member because the box's tag records the member and
not the map struct. Four spellings refute it — a map IS a usable union member:

| spelling | outcome |
| --- | --- |
| union-member map, from a plain BINDING | runs |
| union-member map, from a LIST element | runs |
| union-member map, from a MAP value, **bound once** | runs |
| union-member map, from a MAP value, **re-read in the narrowing** | **fails** |

A wrong-map-struct cast would not care whether the value was bound first. The i32-keyed
refusal in that ruling keeps its own justification; these nine cells are not its evidence.

#### Ablation

| ingredient removed | outcome | needed? |
| --- | --- | --- |
| the RE-READ — bind `__m["k"]` to a name and narrow that | runs | **yes** |
| the recursive alias — the non-recursive spelling | still fails | no |
| the union — a map of a map, read back | runs | **yes** |
| the map MEMBER — store an `f64` in the union instead | runs | **yes** |
| the outer MAP — the same union from a binding or a list element | runs | **yes** |

**The second axis is ANNOTATION, and it is in the type nowhere.** The matrix's `map_value`
cells differ only in whether the destinations are written:

    const __m: { [string]: V } = Map()   const v: V = __mv     -> RUNS
    const __m = Map()                    const v = __mv        -> SILENT

The types are identical; only inference versus an annotation separates them. So no gate keyed
on the TYPE can tell the failing cells from the running ones — a point worth keeping, because
it is what refuted extending a spelling-shaped refusal to cover them.
