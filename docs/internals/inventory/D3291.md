### D3291 — a join over a literal-union pin, returned from a generic or passed to a generic, reaches its reader as the raw atom id

**closed 2026-09-30 · was check-clean silently wrong, clause 1, on master `b6378e95b` and on `313a071b4`, `f5ecc7995` (`0 1`) · found by the D3281 lane's grid · fixture `tests/cases/generics/join-at-literal-union-pin-to-string.vl`**

Repro:

    type K = "a" | "b"
    function g<T>(a: T, b: T, c: boolean) {
      if c { a ?? "b" } else { b }
    }
    const u: K = "a"
    const w: K = "b"
    print(g(u, w, true))
    print(g(u, w, false))

Want:

    a
    b

#### Mechanism

Two readers of one join, each taking the atom where the pin said otherwise. Returned: the
checker types the join as an inference hole (a `??` result absorbing `b: T`) and the pin as
`string`, but the chain's rebuild re-types a hole join only in a sink or a kept-apart union, so
the instance kept the arms' atom rep and returned the `i32` id; a hole join the pin makes a
`string` or `string | null` is now rebuilt at that type, its atom arms widened
(`monoHoleJoinPinsString`, reading a hole instance's own binding through `monoHoleJoinPinTy`).
Passed to a generic: `holeLitReadIsAtom` answered false for every value join (D1728's string
arm), so the argument pinned `show<U>` at `i32`; a join whose every arm is an atom is now the
atom (`holeJoinArmsAllAtom`).

#### Ablation

| `a ?? "z"` (a non-member default) | prints `0 1` | no |

#### Grading list

The fixture holds the hole spelling of the witness, `show(if c { a } else { b })` and its
`match` twin at `K`, and the `K | null` pin whose null printed `-1`. A hole joined with a
concrete literal the pin does not hold (D3303) and two holes joined apart (D3333) are the
checker's typing of the hole, parked on a ruling.
