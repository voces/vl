### D10310 — a generic returned by an un-annotated function, or read out of a list holding a list binding, handed to a generic's function parameter has no argument type

**loud emit reject · `vl check` rc 0 · `emitProgram: monomorphize: unsupported argument type for `f` in a call to `run`` · clause 2 · CAPABILITY: `const v = id` and `run(v, 2)` print `2`, as do the return annotated `(x: i32) => i32` and a one-level `run(xs[0], 2)` · found closing [D10250](D10250.md), the un-annotated `return_inferred` cell of fn-value-generic-list-literal-arg-two-types-open · present on master `d5ec7f160` · filed 2026-10-22 against master `d5ec7f160`**

Repro:

    function id<T>(x: T): T { x }
    function run<U>(f: (x: U) => U, u: U): U { f(u) }
    function mk() { id }
    const v = mk()
    print(run(v, 2))
    // vl check rc 0.  vl build: monomorphize: unsupported argument type for `f` in a call to `run`

Want:

    2

#### Mechanism

Not traced. Emit finds no pin for the argument of `run`'s function parameter when the generic
reaches it through an un-annotated function's return or through two list reads
(`const xs = [id]`, `const ys = [xs]`, `run(ys[0][0], 2)` refuses the same way, though
`const ys = [[id]]` runs), while a `const` alias or one
list read pins it.

#### Ablation

| ingredient removed | outcome | needed? |
| --- | --- | --- |
| `mk`'s return annotated `(x: i32) => i32` | runs, `2` | **yes** |
| `mk()` replaced by `id` (`const v = id`) | runs, `2` | **yes** |
| `run` replaced by a non-generic `run(f: (x: i32) => i32, u: i32)` | runs, `2` | **yes** |
| `run(v, 2)` replaced by `v(2)` | runs, `2` | **yes** |
| a second call at `string` | the same emit reject | no |

#### Grading list

The `return_inferred` un-annotated cell of fn-value-generic-list-literal-arg-two-types-open,
and `run(ys[0][0], 2)` over `const xs = [id]`, `const ys = [xs]`.
