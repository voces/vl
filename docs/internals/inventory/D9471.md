    function inc0(a) { return a + 1 }

#### Mechanism

`.set` and `.push` judge a value whose type holds holes against the slot by
`bmArgOk`, which defers to a pin constraint (`noteBmCstr`) and accepts. Only a bare function
with holes into a function-typed slot was taken out of that path (`pushHoleFnToConcrete`,
D3867/D3881) and judged by `assignableExpr`, as a binding is. A record literal holding the
function stayed on the deferring path, so nothing compared `inc0`'s i32 result with the
field's f64, and the call read an i32-result function through an f64-result signature.
`pushHoleFnToConcrete` now also answers for a record or list literal holding a function with
holes, and the store is judged as the binding is.

#### Ablation

| ingredient removed | outcome | needed? |
| --- | --- | --- |
| the record (`Map<string, (a: i32) => f64>`, `m.set("a", inc0)`) | loud check reject, `cannot assign (_) => _ to (i32) => f64` | **yes** |
| the container (`const r: R = { f: inc0 }`) | loud check reject, `cannot assign {f: (_) => _} to 'r' of type R` | **yes** |
| the map (`const l: R[] = []`, `l.push({ f: inc0 })`, `print(l[0].f(3))`) | same trap | no |

#### Why the refusal is owed

Every neighbouring spelling already refused on master: the binding, a reassignment, an
argument, a return, an index store into the map or list, a list literal binding and a field
store `r.f = inc0`, each `cannot assign`. The checker owed `.set` and `.push` the same
judgement. A lambda (`{ f: (a) => a + 1 }`) still adapts to the field and prints `4`, and an
un-annotated function of f64 result (`{ f: half }`) prints `1.5`.

#### Grading list

Graded after the close, each `cannot assign`: the pushed list, a record nested one level
(`l.push({ r: { f: inc0 } })` onto `W[]`), a list literal set as a map value
(`m.set("a", [{ f: inc0 }])` into `Map<string, R[]>`) and a record bound first
(`const r0 = { f: inc0 }`, `m.set("a", r0)`). A same-named field record type declared beside
an un-annotated record literal is a different mechanism: [D9530](D9530.md),
[D9531](D9531.md), [D9532](D9532.md).
