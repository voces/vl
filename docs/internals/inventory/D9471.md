### D9471 — an un-annotated function of i32 result, inside a record literal set into a map or pushed onto a list whose field type returns f64, passes check and traps at its call

**loads then traps · `vl check` rc 0 · `wasm trap: indirect call type mismatch` · clause 1 · found closing [D9370](D9370.md) · present on master `4193ec5e4` · filed 2026-10-21 against master `4193ec5e4`**

Repro:

    type R = { f: (a: i32) => f64 }
    function inc0(a) { return a + 1 }
    const m: Map<string, R> = Map()
    m.set("a", { f: inc0 })
    const x = m.get("a")
    if x != null { print(x.f(3)) }
    // vl check rc 0.  vl run: wasm trap: indirect call type mismatch

#### Mechanism

Not traced. `inc0` returns i32 at `(i32)`, which the field type `(a: i32) => f64` does not
accept: the same function bound directly (`const r: R = { f: inc0 }`) or set as a map value
of that function type (`Map<string, (a: i32) => f64>`, `m.set("a", inc0)`) is refused at
check with `cannot assign`. Inside a record literal delivered through `.set` or `.push`, the
check admits it and the call reads an i32-result function through an f64-result signature.

#### Ablation

| ingredient removed | outcome | needed? |
| --- | --- | --- |
| the record (`Map<string, (a: i32) => f64>`, `m.set("a", inc0)`) | loud check reject, `cannot assign (_) => _ to (i32) => f64` | **yes** |
| the container (`const r: R = { f: inc0 }`) | loud check reject, `cannot assign {f: (_) => _} to 'r' of type R` | **yes** |
| the map (`const l: R[] = []`, `l.push({ f: inc0 })`, `print(l[0].f(3))`) | same trap | no |

#### Grading list

The pushed list above, and a second record of an f64 result set beside it
(`m.set("b", { f: half })`, which runs and prints `1.5` before the trap).
