### D9682 — an un-annotated parameter bound at `i64` computes `x + 1.5` at `f64`, where `x: i64` refuses the mix

**check-clean silently wrong · clause 1 · the direct spelling `function f(x: i64) { x + 1.5 }` refuses with `operator '+' mixes i64 and f64` · found closing [D9631](D9631.md) · present on master `abe12f20f` · filed 2026-10-22 against master `abe12f20f`**

Repro:

    function f(x) { x + 1.5 }
    print(f(5000000000))
    // PRINTS 5000000001.5

Want:

    operator '+' mixes i64 and f64

#### Mechanism

Not traced to a decision. The body is checked once with `x` a hole, where a float literal
beside it is accepted, and at an `i64` pin the arithmetic computes at `f64` (since
[D9631](D9631.md), `binArithPinTy` types it `f64` explicitly, as the emitter already did).
The direct spelling refuses the mix, since a fractional literal cannot adapt to `i64`. The
pin does not re-ask the direct spelling's question, so the two spellings disagree; which one
is right is the numeric-join ruling's to say, and the row grades the direct one.

#### Ablation

| ingredient changed | outcome | needed? |
| --- | --- | --- |
| the argument `2` (an `i32` pin) | runs, prints `3.5`, as `x: i32` does | **yes** |
| the annotation `x: i64` | check refuses | **yes** |
| the literal `1` | runs, prints `5000000001`, as `x: i64` does | **yes** |

#### Grading list

A lambda `(x) => x + 1.5`, a `<T>(x: T)` body at `i64`, `-`, `*` and `/`, and an `i64`
pin through a list literal (`[x, x + 1.5]`).
