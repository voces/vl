### D17320 — `{}` completing a union arm writes its omitted sentinel-null field as the bottom ref, because the check-minted `null` names no null of its own

**check-clean invalid wasm · filed 2026-11-24 against master `d6838055` by lane N10**

Repro:

    type Other = { b: i32 }
    type O = { q: boolean | null }
    const c: Other | O = {}
    print(c is O)
    // vl check: rc 0.  vl run: invalid module, type mismatch: expected i32, found nullref

#### Mechanism

An arm's omitted field holds the `null` the literal's check minted (`omittedFieldNullNode`),
which `emitVariantStruct` writes through `emitVariantFieldValue`. For a `nulbool` field (and the
i32 atom slot of a literal union with `null`), `variantFieldArmOf` answers `plain`, so the minted
node is written by `emitNullLitNode` → `emitNullAt` → `nullOwnAt`. The minted node has no type
and no contextual type, so `nullOwnAt` answers `NULL_OWN_NONE` and legacy writes `ref.null none`
into the field's i32 sentinel slot. A written `null` is typed, so it names `NULL_OWN_BOOL`.
The reference kinds (string, record, list, closure) take the bottom ref, which is valid there.

#### Ablation

| ingredient removed | outcome | needed? |
| --- | --- | --- |
| the omission: `{ q: null }` | runs, prints `true` | **yes** |
| the union: `const c: O = {}` (a plain struct row) | runs | **yes** |
| the sentinel kind: `q: string \| null`, `i32 \| null`, `f64 \| null`, `Other \| null`, `i32[] \| null`, a nullable closure | runs | **yes** |
| `q: "a" \| "b" \| null` instead of `boolean \| null` | still invalid | no |
| another field given: `{ q?, z: i32 }` built as `{ z: 1 }` | still invalid | no |
| the delivery: a return `function mk(): Other \| O { return {} }` | still invalid | no |
| the other arm: `O \| string` | still invalid | no |

#### Grading list

`tests/cases/objects/empty-object-all-nullable-runs.vl` must keep running: its arms omit only
reference-kind fields. A close re-grades each sentinel kind (`boolean | null`, a literal union
with `null`) at a const, a reassignment, a return, an argument and a list element. The IR
builder refuses these arms today (`object field coercion`), so a close also covers them in the IR.
