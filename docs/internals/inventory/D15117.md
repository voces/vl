#### Mechanism

Both calls go through one set whose only member is `id0`; without the write it is tagged. With it,
`ftScan` refused the store's target: `ftCtxOk`'s store arm took a left side carrying the set only
as an `Index` whose holder's `ftHoldKind` is 1 or 3, or as an `Ident`, and `r.f` is a `Member`. The
field's type in the record does carry the set. The record kind 2 of `ftHoldKind` says only that a
record holds the set somewhere, so the slot predicate reads the named field instead, at the
record's adopted rep, else its own type, as `ftRecHolds` reads it.
