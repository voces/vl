#### Mechanism

[D1846](D1846.md) joins the arms for a bare NAME, whose narrowing is a scope shadow: the
retirement is written in place at the name's own depth, so the join has one slot to install
into and `lookupDepth` finds it. A path's narrowing is an `npKeys` OVERLAY entry, and
`popScope` unwinds every entry the arm's scope pushed — so by the time the join runs there is
nothing left to install into, and `applyArmJoins` declines a key `isPathKey` answers true for
rather than installing something the overlay would not hold.

The ledger already carries the path rows ([D1847](D1847.md) pushes one per path write, so a
post-guard residual over a path is dropped too); it is the FOLD that stops. So the gap is one
side of one function, not a missing channel.

#### Grading list

The four ablation rows, `tests/cases/unions/narrow-arm-join.vl` (the bare-name join, which must
stay green) and `tests/cases/unions/narrow-path-write-flips-variant.vl` (the same-level path

A close needs the overlay's own fork/join: `checkIfStmtNode` would have to snapshot the
`npKeys`/`npTys`/`npInvBy` frame at the `if`'s entry, let each arm run against its own copy, and
push one merged entry after — which is a bigger change than the scope shadow's, because a path
fact can also be retired mid-arm by a CALL (`noteCallInvalidations`) and a merged entry must not
resurrect what a call in either arm invalidated. **Grade the emitted bytes**: the emitter's push
is keyed by the same path string, so a checker that joins where the emitter does not is
check-clean invalid wasm.
