### D16073 — sixteen emit-time tests for an unnamed function never see one: the emitter has named every lambda `__lambda_N` before they run

**closed 2026-11-14 — every site graded: one mattered (`vrFnValue`, D16075, fixed), the other fifteen are inert or redundant and now say what they mean · was a pin for grading · 16 sites in 14 functions · filed 2026-11-14 against master `a4cc60c9`**

Repro:

    const outer = () => {
      const l = (x) => x
      return l
    }
    const v: (x: i32) => i32 = outer()
    print(v(41) + 1)

Want:

    42

#### Mechanism

`liftFnsInExpr` (emit_collect) writes `__lambda_N` into an unnamed lambda's `fnName` during
`collectFns`, the first emit pass. The elaboration runs before it, but its helpers are also
asked from the passes after it. A test of `fnName == ""` or `fnName != ""` that runs after the
rename reads every lambda as a named function.

Measured by a scratch build in which each of the 50 emit-side tests (emit_*, wasmEmit,
value_reach) traps when it reads a name starting with `__lambda_`. The build was swept over the
population until no new site trapped. 18 sites trapped. Two of them already test the
`__lambda_` prefix and are correct: `monoWrittenLetGenSnap` and `fvaAdapterCallee`. The other
16 are the row:

- emit_classify `capScanFunc` (×2) and `fieldClosureFeOfRecvRaw`;
- emit_elab `elabLamPerEncl`, `elabLateName`, `elabNestedCopyOnChain`, `elabRetCalls`,
  `elabSetCallRows` and `elabTopFn`;
- emit_mono `monoFlowTyParamGen`, `monoPinMapSlot` and `monoPruneTemplates`;
- emit_rewrite `drwRecvIsTyParam` and `registerRetJoinUnions`;
- value_reach `vrFnValue` (×2).

The trap shows that a renamed lambda reaches the test. It does not show that the test's
outcome is wrong: some sites only want a printable name, and a renamed lambda serves them. The
32 sites that never trapped run before the rename or see no lambda in the population. Two of
them are emit_elab's `fnName == ""` exclusions at `elabClosedDestTy` and `elabSolvedHoleCallAt`.

#### Grading list

- Each of the 16 sites: whether its test means "is a lambda", and if so, a program that takes
  the wrong branch because of the rename, or a ruling that the branch is equivalent.
- `vrFnValue`'s lambda branch, a suspect for D16072's pin-path gap. Making it see a renamed
  lambda moved none of D16072's six cells.

#### Grades

Each remaining site's test was restored to its intent, `fnNameIsLambda` (ast), which also matches
the renamed spelling, in one scratch compiler. That build moved none of the 24,325 sweep programs,
left master's compiler source byte-identical, and agreed byte for byte on a probe aimed at each
site's lambda branch (a lambda shadowing a user `__lambda_N`, a hole lambda over a closure field, a
lambda's list-union and function-arm return joins, a held-map maker, a lambda receiver in a generic,
nested lambdas in a generic instanced twice).
