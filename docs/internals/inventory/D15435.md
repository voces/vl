### D15435 — a lambda seeded through a `const` into a written `let` a nested function writes is declined as a leaf, so the binding needs the split plan

**closed 2026-11-04, runs with the split plan on and off · was split-plan dependent (W-lam): with the split plan off (`compileSrc` returning after its first compile) a loud emit reject, `the reassigned function binding `d1` holds functions called at more than one argument type` · `ftWrittenAt` (check_fn_tag.vl) takes a `const`'s lambda as written at its binding only where a read of the `const` seeds a `let` another function writes (`ftConstSeedsCell`, the capture cell's peer); a `const` alias of a named function is no lambda and never reaches it · fixture `tests/cases/closures/cell-lambda-members-tagged-plan-off.vl` · from `cell-peer-called-at-two-types` (split-plan census, W-lam), D15433's other half · filed 2026-11-04 against master `dffeb177`**

Repro:

    function mk(x: string, n: i32) {
      const g = (y) => y
      const h = (y) => y + y
      let d1 = g
      function w1() {
        d1 = d1
      }
      let d3 = h
      d3 = d1
      print(d1(x))
      print(d3(n))
    }
    mk("a", 4)

Want:

    a
    4

#### Mechanism

The tag decision declines `{g, h}` at the lambda `g` (`ftNodeOk`'s `FuncDecl` arm): it is reached through another name, no declared member is beside it, and `ftWrittenAt` takes only a `let`'s initialiser. Without `w1` the set is tagged and the program runs, so the cell is what makes the lambda's own node carry the joined set. Taking a `const`'s initialiser in `ftWrittenAt` runs this witness but is far too wide: over 5,730 `@run` files it changed the bytes of about 50 and turned `binding-copied-from-uncalled-alias` and `binding-copied-from-uncalled-alias-called-after` into emit refusals. A close has to say what the cell adds, not widen the leaf rule.

#### Ablation

| --- | --- | --- |
| no `w1` | runs | **yes** (the cell) |
| `let d1 = (y) => y` for the `const` seeds | runs (D15433) | **yes** |
| named un-annotated functions for `g`, `h` | runs | **yes** (the lambdas) |
