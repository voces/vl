### D2974 — a `string | i32` join delivered where `(string | i64)[]` is wanted builds a list the reader casts wrongly

**loads then traps · clause 1 · open · the #3247 review · filed 2026-09-28 against master `fe1fa1bec`**

Repro:

    function take(xs: (string | i64)[]) { print(xs[0]); print(xs.length) }
    function go(a: string, c: boolean) { const r = if c { a } else { 7 }; take([r, r]) }
    go("b", true)
    go("b", false)
    // vl check: rc 0.  vl run: prints `b` `2`, then traps with `wasm trap: cast failure`

Want:

    b
    2
    7
    2

#### Mechanism

Not localised past the ablation. The join `r` is `string | i32`, and the checker accepts `[r, r]`
where `(string | i64)[]` is wanted, since `i32` widens to `i64`. The trap is a cast inside
`take` when it reads the element the `i32` arm built, so the list's boxes are not the ones the
parameter's union reads, and no widening from `i32` to `i64` happens at the call.
With `a: K` for a literal union `K`, master printed `0 2 7 2` (the atom id). D2952's fix (#3247)
boxes that join as its text, so the `K` spelling now reaches this trap too.

#### Ablation

| ingredient removed | outcome | needed? |
| --- | --- | --- |
| the `i32` arm reaching the list (`go("b", true)` alone) | runs, prints `b` `2` | **yes** |
| the `i64` in the parameter (`(string \| i32)[]`) | runs, prints `b` `2` `7` `2` | **yes** |

#### Grading list

The same program with `a: K`, `type K = "a" | "b"`, which prints `0 2 7 2` on master and traps
after #3247. The argument, binding and return positions of a `(string | i64)[]` destination.
