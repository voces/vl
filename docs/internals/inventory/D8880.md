### D8880 — a lambda or nested function whose result is a bare `null` has no rep, so binding the value of a tail `null` write in one is refused

**loud emit reject · clause 2 · present on master `fe6067cde`, not a regression of [D2497](D2497.md)'s close · filed 2026-10-21 against master `fe6067cde`**

Repro:

    type O = { v: string | null }
    const o: O = { v: "a" }
    const c = () => {
      o.v = null
    }
    const r = c()
    print(r == null)
    // vl check: rc 0.  vl run: emit error, "bare null needs a struct-typed context"

#### Mechanism

The checker types the lambda's tail `o.v = null` at its right side, so `c` returns `null`. A
top-level function's tail `null` write now yields a fresh `null` ([D2497](D2497.md)), but a
lambda's or a nested function's result type travels through the function-value ABI, which has
no rep for a bare `null`: a lambda whose last statement is a literal `null` refuses the same
way, and a nested `function c(): null` called through a forwarder `function d() { c() }` refuses
with "a function value's signature is not yet supported". So `assignTargetSpills` declines a
`null` write at such a tail, the lambda stays void, and the caller's binding is refused.

#### Ablation

| ingredient removed | outcome | needed? |
| --- | --- | --- |
| binding the call's result (`c()` as a statement, then `print(o.v == null)`) | runs, prints `true` | **yes** |
| the lambda (`function c() { o.v = null }` at top level) | runs, prints `true` | **yes** |
| the write (`const c = () => { null }`) | same emit error | no |
