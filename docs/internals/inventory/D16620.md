### D16620 — two un-annotated map parameters that store a generic at a string key build an invalid module when either body is checked before its call

**runs today and must keep running · a refutation pin and an L2 acceptance witness: the map exemption in `callDecidesParam` (check_top_level.vl) keeps it running, and L2 S3's solver must keep it running when it retires that exemption · found grading L2 S1 with `scripts/decl-order-ab.vl` · filed 2026-11-15 against master `55151b05` · fixture `tests/cases/maps/hole-param-maps-of-generics-stored-declared-after-their-calls.vl`**

Repro:

    const b = Map()
    b["k"] = { f: id }
    over(b)
    const h = Map()
    h["k"] = id
    bare(h)
    const hr = h["k"]
    if hr != null { print(hr(7)) }
    function id<T>(x: T): T { return x }
    function id2<T>(x: T): T { print("id2"); return x }
    function over(mm) { mm["k"] = { f: id2 } }
    function bare(mm) { mm["k"] = id2 }
    // with S1's exemption deleted outright: vl run: invalid module inside `over`

Want:

    id2
    7

#### Mechanism

A top-level statement checks a later-declared callee first unless one of the callee's
un-annotated parameters is used as a map. With that exemption deleted, both bodies are checked
before their calls and `over` is invalid. With it kept for `mm.set` only, the body that stores by
index is still checked first and the module is still invalid; only both bodies after their calls
run. A map parameter's key and value
come from the calls. `holeDemandOk` refuses to pin a map demand that a body checked earlier left open,
so a body checked first is emitted against its own open map. S3's solver at the call is what closes
that demand.

#### Ablation

Each variant was run with the exemption kept for a `get`, `set`, `has` or `delete` receiver only,
so a body that stores by index is checked before its call:

| ingredient changed | outcome | needed? |
| --- | --- | --- |
| both bodies by `mm.set`, so neither is checked first | runs | **yes** (a body checked first) |
| the declarations first | runs | **yes** (the order) |
| no `bare` or no `h` | runs | **yes** (two maps) |
| `bare` stores `id`, not `id2` | runs | **yes** (two generics) |
| `over` stores `{ f: id }` | runs | **yes** (two generics) |
| no read of `h["k"]` | runs | **yes** (the read) |
