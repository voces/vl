### D1341 — `as?` on a HOLE parameter: the checker records the cast's result as the BARE arm, so the nullable the cast produces has nowhere typed to land

**closed 2026-09-03 by re-recording the cast's result type at the call that PINS the hole ·
was check-clean invalid wasm, clause 1, `type mismatch: expected i32, found (ref $type)` ·
the `as?` suffix only · ZERO corpus cells · filed 2026-09-03 as the residue
[D1251](#d1251)'s close named · the argument-position cell stays open as [D1371](#d1371)**

**THE CLOSE, AND WHY IT DOES NOT COST THE `runs` CELL THE ROW PRICED.** The filed objection
stands: recording `T | null` whenever the source is an unresolved hole would refuse
`function take(a) { const x: i32 = a as? i32 … }` with `take(5)`. What lands instead is the
reconciliation the row asked for rather than a patch to one side — the cast is PARKED on the
hole (`noteCastDemand`) and `castPinAdjudicate` re-asks `numCastCanFail` under the type the
CALL SITE pinned. At `take(5)` the pin is `i32`, the cast cannot fail, and the node keeps `T`;
at `take(u)` the pin is the box, the cast can fail, and the node becomes `T | null` — which is
exactly what the annotated spelling records. One rung, both answers, and the two producers the
row named (the body's solve and the monomorphizer's) now agree because only one of them
decides.

Repro (prints `5`, the same as the annotated `function take(a: i32 | null)` twin;
it was `vl check` rc 0 over an invalid module):

    const u: i32 | null = 5

    function take(a) {
      print(a as? i32)
    }

    take(u)

#### Mechanism

This is NOT D1251's mechanism, and one program separates them. D1251 was the OPERAND's rep:
the gate read the checker's `TyVar` where the monomorphizer had already pinned the parameter to
the box, and asking `exprUnion` instead fixed `as` and `as!` at every delivery. This row is the
CAST NODE's own recorded RESULT type, and no emit-side answer reaches it.

`checkCastNode` never enters its union arm for a hole operand (the operand is a `TyVar`, so
`argT is TyUnion` is false), and falls to the numeric ladder — which `isNumeric` admits on
purpose, so an unresolved hole does not cascade a spurious `not a number`. There the suffix is
honoured only when the cast CAN FAIL, and `numCastCanFail(primNameStr(primNameOf(TyVar)), "i32")`
is `numCastCanFail("", "i32")` = **false**. So `as?` returns `target`, not `mkNullableTy(target)`:
the checker types `a as? i32` as plain `i32`. The second witness is the checker's own words —
`const r = a as? i32` followed by `if r != null` is a loud `cannot compare i32 with null`, while
the annotated twin runs and prints `0`.

The monomorphizer then pins `a` to `i32 | null`, so the cast IS fallible and its value IS the
box — and since D1251 the union arm emits one, into a context the checker typed `i32`.

**AND THE OBVIOUS CHECKER FIX COSTS A `runs` CELL, which is why it is filed rather than taken.**
Recording `T | null` whenever the source is an unresolved hole is strictly more correct and makes
`r != null` legal — but `function take(a) { const x: i32 = a as? i32 … }` with `take(5)` runs
today and becomes a check reject. The honest root is that the checker solves an un-annotated
parameter from its BODY (`unannotParamTy`, "the SINGLE source of truth") while the monomorphizer
solves it from the ARGUMENT; a fix has to reconcile those two, not patch one side.

#### Ablation

| ingredient removed | outcome | needed? |
| --- | --- | --- |
| the hole (`function take(a: i32 \| null)`) | runs, prints 5 | **yes** |
| the `?` suffix (`as`, `as!`) | runs, prints 5 (D1251) | **yes** |
| the union (`take(5)` into `function take(a)`) | runs, prints 5 | **yes** |
| the delivery (`const r = a as? i32`, `return a as? i32`) | still fails | no |
| the arm kind (`string \| i32` instead of `i32 \| null`) | still fails | no |

#### Grading list

The three deliveries above (statement / binding / return), which run; the `string | i32`
operand; `const r = a as? i32` + `r != null`, whose `cannot compare i32 with null` this close
does NOT lift — the comparison is checked inside the body, before any call pins the hole, and
that is the same one-body-many-pins limit [D1371](#d1371) records; `function take(a) { const r
= a as? i32; print(r) }` with `take(5)`, which runs today and must keep running — it is the
cell this close was shaped to preserve; and D1251's own `as` / `as!` cells at every delivery.
