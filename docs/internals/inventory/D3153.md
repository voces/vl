### D3153 — a closure capturing an un-annotated copy of a value narrowed to `K | Circle` out of a box is refused at emit

**loud emit reject · open · clause 2 · found by the #3281 review (`g/g013`, `g/g138` and the rest of the `KS` family: 18 cells) · the same on master `fc4b2159f` · filed 2026-09-29 against master `fc4b2159f`**

Repro:

    type K = "a" | "b"
    type Circle = { r: i32 }
    function sh(x: K | Circle): string {
      if x is Circle { return "c\{x.r}" }
      return x
    }
    function t(e: K | Circle | i32) {
      if !(e is i32) {
        const c = e
        const f = () => sh(c)
        print(f())
      }
    }
    t("a")
    t({ r: 6 })
    // vl check: rc 0.  vl run: emitProgram: only i32 locals are supported

Want:

    a
    c6

#### Mechanism

Not localised past the ablation. Narrowing the three-member box to two members keeps the box,
and the un-annotated copy binds it in the frame, but the closure's env field is typed by a
ladder that has no kind for a sub-union of a literal union and a record, so `fbValtype`
refuses it. The annotated copy and the direct capture both run.

#### Ablation

| ingredient changed | outcome | needed? |
| --- | --- | --- |
| `print(sh(c))` in `t`, no closure | runs | **yes** (the capture) |
| `const c: K \| Circle = e` | runs | **yes** (the un-annotated copy) |
| `() => sh(e)`, no copy | runs | **yes** (the copy) |
| `e: K \| Circle`, no box | runs | **yes** (the narrowing out of a box) |
| `string` in place of `K` | the same refusal | no |
| a walk variable over `(K \| Circle \| i32)[]`, in a function or at module scope | the same refusal | no |

The #3281 review grid's `KS` cells, the `string` twin, and both walk spellings.
