### D3195 — a bound record literal delivered by `m.set` into a map of a wider declared record is stored at its own row

**closed · the D2933 use walk reads `m.set(k, v)`'s value argument at the map's value type (`rsCallParamTy`), as D2990 taught it the index store · fixture `tests/cases/structs/record-literal-widened-map-set-delivery.vl` · matrix position `map_set` · was check-clean invalid wasm · clause 1 · pre-existing, the same on master `36d233f66` · found by the #3286 round-2 review (`rv3286r2-13226/p2/k1.vl`; also `rv3286-2159/g2` cells `k0543`, `k0553`) · filed 2026-09-29 against master `36d233f66`**

Repro:

    type R = { v: f64, w: i32 }
    const l = { v: 1, w: 3 }
    const m: {[string]: R} = Map()
    m.set("a", l)
    const q = m.get("a")
    if q != null { print(q.v) }
    // vl check: rc 0.  vl build: invalid module, expected (ref null $type), found (ref $type) at the m.set

Want:

    1

#### Mechanism

[D2990](D2990.md) taught the D2933 use walk to follow an index store (`m["a"] = l`) into the
map's declared value record, so the literal is built at `R`. The walk reads a call argument's
destination from `rsCallParamTy`, which knew `.push` and a callee's own `TyFunc`, and a map's
`.set` is neither, so `l` was built at its own `{ v: i32, w: i32 }` record and stored where
`R`'s is expected. `rsCallParamTy` now answers the map's value type for `.set`'s value argument.
The read-back is not needed.

| `R`'s `v: i32` (no widening) | prints `1` | **yes** (a widened field) |
