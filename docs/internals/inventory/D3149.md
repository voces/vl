### D3149 — a `.map` callback's declared `T | X` at a `boolean | null` pin has no box row: invalid wasm returned as a list, refused when read

**check-clean invalid wasm · clause 1 · the `boolean | null` pin cells of the #3280 review's `g1` grid (`rv3280-17445/g1/c035.vl` and siblings invalid, `c009.vl` and siblings loud) · a sibling of D3140 · the same on master `07d414042` · filed 2026-09-29 against master `07d414042`**

Repro:

    function g<T>(x: T): (T | f64)[] { return [x].map((e): T | f64 => e) }
    const a: boolean | null = null
    const r = g(a)
    print(r[0])
    // vl check: rc 0.  vl run: invalid module inside `g`, expected (ref $type)

Want:

    null

#### Mechanism

Not localised past the ablation. `boolean | null` is a niche rep elsewhere, as `string | null`
is (D3140), and the callback's substituted return keeps it as a member of a box. The same pin
handed back as a list of `T | f64` is invalid wasm in `g`, even with no type parameter at all.
Read in place it prints, and `T | boolean` read in place, by index or `.length`, is refused with
`.filter result is a ref list but ref list type not collected`. At `i32 | null` every face runs.

#### Ablation

| ingredient changed | outcome | needed? |
| --- | --- | --- |
| the pin `i32 \| null` | prints `null` | **yes** (the boolean niche) |
| the pin value `true` | invalid wasm | no |
| `g(x: boolean \| null)` with the return spelled out, no type parameter | invalid wasm | no |
| `print([x].map(…)[0])` inside `g`, no list returned | prints `null` | **yes** (the list delivered) |
| `(e): T \| boolean`, `print(m.length)` | loud emit reject, ref list type not collected | no (the loud face) |
| the same at `i32 \| null` with `T \| i32` | prints `1` | **yes** |
