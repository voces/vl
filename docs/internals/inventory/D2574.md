### D2574 — `x.pop()` over a generic `T[]` returned un-annotated declares an `i32` result

**check-clean invalid wasm · clause 1 · pre-existing on master `dcc88a350` · found by #3174's review · filed 2026-09-26**

Repro:

    function f<T>(x: T[]) { return x.pop() }
    const r = f([1.5, 2.5])
    print(r == null)
    // vl check: rc 0.  vl run: invalid module inside `f`, "type mismatch: expected i32, found f64"

#### Mechanism

Not located. The instance's inferred result is `T | null`, which at `f64` is the value-union
box. The function is declared with the `i32` default while its body yields the raw `f64`
element. It fails at every instance tried: at `string` it is "expected i32, found (ref null
$type)", and at `i32` the caller fails validation ("expected struct type at index 0"). The
expression-body spelling (`{ x.pop() }`) fails identically, before and after #3174.

#### Ablation

| ingredient removed | outcome | needed? |
| --- | --- | --- |
| the `f64` instance (`f(["a"])`, `f([1, 2])`) | still invalid wasm | no |
| the `return` (expression body) | still invalid wasm | no |

#### Grading list

* `f([1.5, 2.5])`, `f([1, 2])` and `f(["a"])`, each read with `== null`, in both spellings.
