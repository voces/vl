### D3738 — each object literal scans every struct row field by field, so compile time is quadratic in records

**runs today and must keep running · a cost row: quadratic in CPU, flat in allocation since D3737 · found by lane GH · filed 2026-10-06 against master `7529a4ea6`**

#### Mechanism

`objLitNamesTwoRows` and `structIndexOfObjCtxGo` (emit_classify.vl) each walk every struct row
up to `sScanLim()` for every object literal. For a row with the literal's field count, they look
up each field with `sFieldIndex`. `repRowOfTyStruct` (emit_rep.vl), reached from the same
`structIndexOfObjCtxGo`, compares rows linearly through `repCanonId`. Those three functions are
about 75% of a guest time profile of 2,000 functions that each build one nested inline record.
Fuel grows 12x from 500 to 2,000 such functions, so the work is quadratic in rows times
literals. An index from a field name, or from a field count, to its rows would make each
literal's question cost only its candidates.
