### D2212 — `??` over a nullable literal union narrowed by an `is` else-branch emits invalid wasm

**closed by [D3198](D3198.md): `??` over the `K | null` niche to a non-member default is a string join that widens the present atom and takes the default on `-1` · was check-clean invalid wasm · found closing D2205 · filed 2026-09-23 against master `327b15510`, closed 2026-09-29 against master `94670f728`**

Repro:

    function f(m: "x" | "y" | null) {
      if m is "y" {
        print("then")
      } else {
        print(m ?? "none")
      }
    }
    f("x")
    f(null)

Want:

    x
    none

#### Mechanism

The operand is an atom with a `-1` null niche. In the else-branch the checker types `m` as
`"x" | null`, and `??` lowers it as a nullable ref while the value on the stack is still the
i32 atom. Without the `is`, the same `??` is a loud emit refusal (`` `??` over this nullable
value is not supported yet ``), so the narrowing is what routes it into the ref lowering. Not
caused by D2205's close: the subset spelling above fails the same way on master.

#### Ablation

| ingredient removed | outcome | needed? |
| --- | --- | --- |
| the `is` test (a bare `m ?? "none"`) | loud emit reject | **yes** |
| `??` (read with `if m != null { … }` instead) | runs | **yes** |
| the inline type spelled as `type M = "x" \| "y"`, `m: M \| null` | invalid wasm | no |
| the `??` bound first (`const s = m ?? "none"`) | invalid wasm | no |
| the overlapping test `m is "y" \| "z"` instead of `"y"` | invalid wasm | no |
