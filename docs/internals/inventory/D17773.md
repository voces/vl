#### Mechanism

`mk()` and `mkt()` return records of one field-name set, which share one struct row, so field `m`
has one layout. `tm`'s set is tagged (two capture-free lambdas) and `hm`'s was not, so the field's
map was a closure map at one record and an id map at the other, and `{ m: tm }` asked a converting
copy of an aliased map. The two sets never met at a member, so the family plan (D17739) planned
them apart; the field is now an edge of the family, and both maps hold ids.
