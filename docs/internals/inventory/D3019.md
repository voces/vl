### D3019 — a callee's write to its OWN binding of a name ends the caller's narrowing of a different binding of that name

**closed · was loud check reject (clause 2): `'g' is no longer narrowed to G: the call earlier in this statement may reassign it` on a program no call can change · plumb PL-063 · the writer analysis resolves each assignment to the declaration it names, and a `const` is never reassigned by a call · fixtures `tests/cases/soundness/call-keeps-narrowing-callee-local.vl` (runs) and `tests/cases/soundness/call-keeps-narrowing-callee-local-refused.vl` (the writers that must still end it) · the shadowing face in the CALLER is [D3020](D3020.md) · filed and closed 2026-09-28 against master `ad64c62c1`**

Repro:

    type G = { name: string, ty: i32 }
    type X = { n: i32 }
    function open(): X | null { { n: 1 } }
    function find(x: X, k: i32): G | null { if k > x.n { { name: "g", ty: k } } else { null } }
    function hex(v: i32) {
      let g = v
      g += 1
      "\{g}"
    }
    const x = open()
    if x != null {
      const g = find(x, 2)
      if g == null {
        print("none")
      } else {
        print("\{g.name} \{hex(g.ty)} \{g.name}")
      }
    }
    // vl check: rc 0.  vl run: prints g 3 g (before the close: the two reads after the call refused)

Want:

    g 3 g

#### Mechanism

D2390's `callMayWrite` asks the writer analysis (`crwVisit`, `crInfoOf`) whether a call can reach
a function that assigns the narrowed NAME. The walk recorded every `x = …` under `x` for every
enclosing nested function, whatever `x` resolved to, so `hex`'s own `let g` made `hex` a writer
of every `g`. Module-top bindings escaped it by another route; a binding in a module-level block
(the witness) or in a function body did not. The walk now keeps the declarations in scope
(`crsDeclare`/`crsDepthOf`: `let`/`const` from after the initializer to the end of the enclosing
node, parameters for the body), and a write that resolves to a declaration inside a nested
function is recorded under `name@` and only for the functions nested in the declarer. A query
about a binding of the root's own level or the module (`crNameAtRootLevel`) reads `name` alone;
one about a nested function's binding reads both. The use kinds behind `crNameAssigned` (kind 3)
and the `null`-store walk behind D2529 (`crNulledWalk`) resolve the same way. Separately, a
`const` is never reassigned, so `callMayWrite` and `crMayBeWritten` answer false for one.

#### Grading list

Kept running: a callee's parameter, a callee's closure writing the callee's local, a module-level
lambda's local, a module binding read directly and through a closure, a function's local, a
nested function's local. Still refused: a closure in the callee writing the narrowed binding, a
write after the callee's block-local of that name has gone out of scope, a loop variable of that
name (a declaration the walk does not track counts as the outer binding), a closure writing a
nested function's own local.
