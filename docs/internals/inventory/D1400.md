### D1400 — the cast-pin re-record reaches ONE node, so a value that was COPIED before the pin keeps the stale answer: a hole callee, an inferred binding, an annotated binding and an annotated return are all check-clean invalid wasm

**check-clean invalid wasm · clause 1 · `type mismatch: expected i32, found (ref $type)` ·
4 of the 16 cells of [D1371](#d1371)'s two-face grid · ZERO corpus cells · filed 2026-09-03
as the residue D1371's close named, measured on this worktree's seed**

Repro (`vl check` rc 0; the same program with `function id(x: i32 | null)` prints `5`, and so
does the annotated `function take(a: i32 | null)` face of this one):

    function id(x) { return x }
    const u: i32 | null = 5
    function take(a) {
      print(id(a as? i32))
    }
    take(u)

#### Mechanism

`castPinNullResult` writes ONE thing: `nodeTyIx[castIx]`, the cast node's own recorded type,
at the call that pins the hole. Every OTHER node that took a copy of that type while the body
was being checked keeps the pre-pin answer, and there is no reverse index from a node to its
parents to correct them. D1371 closed the two consumers whose correction is reachable — the
argument compare (re-asked from the parked row) and the `Paren` wrapper (peeled at the reader).
These four are the copies with no such route:

| cell | what copied the stale type | what the annotated face does |
| --- | --- | --- |
| a HOLE callee (`function id(x)`) | `id`'s own parameter, pinned from the pre-pin argument | runs, prints `5` |
| an inferred binding then `??` (`const b = a as? i32` · `b ?? 0`) | `b`'s symbol type | — |
| an annotated binding (`const x: i32 = a as? i32`) | the LetDecl's annotation compare | `cannot assign i32 \| null to 'x' of type i32` |
| an annotated return (`function take(a): i32 { return a as? i32 }`) | the return compare | `return type mismatch: expected i32, got i32 \| null` |

The first two are LEGAL and must reach `runs`; the last two are ill-typed under
`docs/error-handling-design.md` §Trio ("`as?` yields `T | null` as an expression") and owe the
twin's exact diagnostic, the way D1371's argument cell now does. Two different destinations,
one mechanism — which is why they are one row.

**THE FIX ORDER IS D1371's, ONE LAYER OUT.** The argument cell was closable because the
argument loop can record its destination on the parked row before the pin arrives, and
`argMismatchErr` is a single home for the wording. `letAssignMsg` and the return-mismatch
message are the equivalent homes for the two annotated cells, so those two are the same shape
with two more hooks. The HOLE CALLEE is not: `id`'s parameter is pinned from the argument's
pre-pin type, so correcting it means re-pinning a second hole from a type that only exists
after the first pin — an ordering the one-body-many-pins design does not currently express.
The honest repair for that one is the pinned body re-check D1341 named
(`monoRecheckBegin` with diagnostics and node writes enabled), not another destination hook.
