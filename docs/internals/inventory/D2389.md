### D2389 — `parentLetOf`'s single-entry plan cache goes stale when a rewrite adds a binding to the same cached block

**closed · filed 2026-09-25 against master `a8e28a4be`**

Repro:

    type Node = { v: i32, left: Node | null }
    function insert(n: Node, v: i32) {
      if n.left == null { n.left = { v: v, left: null } } else { insert(n.left, v) }
    }
    function run(): i32 {
      const root: Node = { v: 5, left: null }
      insert(root, 3)
      insert(root, 1)
      print(1)
      0
    }
    const done = run()
    // vl check: rc 0.  vl run (pre-fix): invalid wasm inside `insert`

#### Mechanism

`parentLetOf` (`compiler/emit_base.vl`) keys its single-entry plan cache (`plCacheBlock`)
only by `blockIx` and is never invalidated across passes. On master, only a top-level
statement's start-block scan evicted it, by accident, so a program with no top-level
statements reads a stale plan after a rewrite (`insert`'s tail-if spill, D2170) adds a
statement to the cached block. Fixed by an explicit `plCacheBust()` (`emit_base.vl`)
called at every pass boundary in `runEmitPass`'s loop (`emit_sections.vl`), so the cache
no longer depends on an unrelated top-level scan to stay current.

#### Ablation

| ingredient removed | outcome | needed? |
| --- | --- | --- |
| the second `insert` call (one call only) | still invalid wasm | no |
| a top-level statement before `const done = run()` | runs | **yes** |
| calling `insert` from inside a function at all (module-scope calls instead) | runs | **yes** |
