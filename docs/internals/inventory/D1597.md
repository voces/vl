### D1597 — a module GLOBAL and a same-named binding in a top-level BLOCK are one slot, and only in a program with no imports

**check-clean silently wrong · filed 2026-09-04 against master `e05bcfda` · found by the day-one
sampler's new `modules_split` axis, which reported 25 DISAGREE pairs over 1,640 and every one of
them is this · D1595 filed the invalid-wasm face of this as residue needing its own row**

Repro:

    if true {
      const n = 3
    }

    const n = 9
    // PRINTS 3
    print(n)

#### Mechanism

Every module's top-level statements are lowered into ONE start function, so a `const`/`let`
written inside a top-level `if`/`while`/bare block is a start-function LOCAL. Wasm locals are
FUNCTION-scoped; VL's module top level is LEXICALLY scoped. The read above sits outside the
block, so it denotes the module global — and `identBoundInFrame`'s local rung answers "the
frame binds `n`" for the whole start function, so the global read is claimed by the block's
slot. D1593 fixed the mirror claim (a name scan handing a sibling block's binding to a loop
body); this is a global read losing to a block local.

Disassembly of the two-line spelling (`print(n)` inside the block too):

    (local.set $1 (i32.const 9))          ;; the global's initialiser
    (call $fimport$0 (local.get $0))      ;; print(n) reads the BLOCK's slot

It is not the start-local PROMOTION of a top-level binding (G2c): at a `string` global the
cell is a real `(global $global$1 (mut (ref $2)))`, the read is still `local.get $0`, and the
classifier agrees with the wrong resolution — it picks `__print_i32__` over the string print.

**AND THE PROGRAM MUST HAVE NO IMPORTS.** Any second module — a local one, a
declarations-only one, or an unused `import { trim } from "std:str"` — makes every spelling
below run correctly, because the module merge mangles TOP-LEVEL names per module (`n` →
`n$m1`) and leaves block-local ones alone. That is why every cross-module fixture in the tree
missed the family, and why the single-file sampler could not compose it either: its `scope`
axis picks ONE scope for the whole program.

#### Ablation

| ingredient removed | outcome | needed? |
| --- | --- | --- |
| the name collision (block binds `m`) | runs | **yes** |
| the outer binding being a module GLOBAL (two sibling blocks instead) | runs | **yes** |
| module scope (the whole shape inside a function) | runs | **yes** |
| the inner binding being in a BLOCK (a `for` LOOP VARIABLE instead) | runs | **yes** |
| single-module (any `import` added, even unused) | runs | **yes** |
| the block READING its own binding | prints 3, same mechanism | no |
| source order (global first, block second) | prints 0 — the global's own read | no |
| `const` → `let` on either side | prints 3; `n = n + 1` then prints 4 | no |
| an unrelated global before / between / after | prints 3 | no |
| `if` block → bare block → `while` block | prints 3 | no |
| the global's type: `i32` / `f64` / `boolean` / `string` | check-clean SILENTLY WRONG | no |
| the global's type: struct, block binding also a struct | check-clean invalid wasm, `uninitialized local: 0` | no |
| the global's type: struct, block binding `i32` or `string` | loud `emitProgram: field access receiver is not a struct` | no |
| the global read from inside a FUNCTION instead | runs | — |

The last four rows are one mechanism at four reps, not four families: the same ablation
holds for each, and only the rep of the two colliding bindings decides which channel it
comes out of.
