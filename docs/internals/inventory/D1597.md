### D1597 — a module GLOBAL and a same-named binding in a top-level BLOCK are one slot, and only in a program with no imports

**closed · filed 2026-09-04 against master `e05bcfda`, fixed the same day · found by the
day-one sampler's new `modules_split` axis, which reported 25 DISAGREE pairs over 1,640 and
every one of them is this · the fix also closed D1304, the same defect at function scope, and
D1595's own residue witness**

Repro:

    if true {
      const n = 3
    }

    const n = 9
    // PRINTS 9
    print(n)

#### Mechanism

Every module's top-level statements are lowered into ONE start function, so a `const`/`let`
written inside a top-level `if`/`while`/bare block is a start-function LOCAL. Wasm locals are
FUNCTION-scoped; VL's module top level is LEXICALLY scoped. The read above sits outside the
block, so it denotes the module global — and every NAME scan that resolves it answered with
the block's slot instead, because a flat scan over `localNames` cannot tell a dead binding
from a live one. Not a fourth by-name scan: ONE rule, `blockBindingHidden`, read by the three
rungs that were already asking the question.

* **`localBlockLet`** — a new column parallel to `localNames`, set in `addLocalName` from the
  collect walk's own scope DEPTH (frame 1 is the frame's own statement list, deeper is a
  block). The loop-variable flag's twin, one storage class over.
* **`flatScanSkips`** — the flat fallback in `declaredSlotLive` (the LOWERING) and in
  `declaredSlotOf` (the REP) passes a block-scoped slot over wherever the walk's own scope
  stack has already had its say. Live block bindings resolve through `scopeSlotOf`, so a flat
  hit on one is a binding whose `}` has passed.
* **`emitStartFnCode` pushes ONE scope frame** for the top-level statement list, exactly as
  `collectStartLocals` already did for the same walk. A function body gets its frame from
  `emitStmts` on its `Block`; the top level has no `Block` node, so without this the start
  function's lowering was indistinguishable from a scope-less detection pass and the rung
  above could not fire at module scope at all.
* **`frameLetOfLive`** — the ARENA twin of the same rule, since `parentLetOf` answers for the
  whole body, nested blocks included. `identBoundInFrame`'s arena rung and `boundBoolByName`
  both read it; the live lexical binding outranks the name scan (D1593's rule, stated for a
  function frame).
* **`dupScanRun` runs ONE more detection sweep** with `blockLetHidden` armed whenever the
  frame binds a name in a block that a module global also binds. The detectors run
  scope-less, so without it they reserved the frames the block's rep needs and none of the
  global's — `unknown local N` at `vl check` rc 0. D1595's `dupSlotBias` sweep ORs over the
  frame's same-named SLOTS; this is the second HOME, which no slot bias can reach.

The fix is NOT the module merge's name mangling. The cross-module control still runs and
still mangles; the single-file spelling now resolves correctly on its own.
