### D17204 — a value `if` joining a not-yet-written inferred-null binding with a record, at an annotated union destination, boxes the binding's null under its record arm

**closed 2026-11-24 · runs, prints `true` `false` · was check-clean silently wrong (clause 1), printed `false false` · the read is typed `null`, and `holeBoxPlanOf` now boxes a name read typed `null` as the union's null, as it boxes a `null` literal, where it had boxed the read as itself under the tag of the record a later write fills its binding with · fixture `tests/cases/types/null-hole-fill-after-join-runs.vl` (`intoUnion`) · a sibling of [D17203](D17203.md), found by IR-N4 ablating it · owner IR-N4 · filed 2026-11-24 against master `6aabbd9ac`, the same before #9936 (`4e84cecc`)**

Repro:

    type In = { v: i32 }
    type Out = { w: string, k: i32 }
    const rec: In = { v: 9 }
    function run(f: boolean) {
      let m = null
      const j: In | Out | null = if f { m } else { rec }
      m = { w: "z", k: 4 }
      return j == null
    }
    print(run(true))
    print(run(false))
    // vl run: true, false

Want:

    true
    false

#### Mechanism

The read of `m` before the write is typed `null`, but its storage is `Out | null` once the later
write fills the hole. Boxing the `m` arm into `In | Out | null`, `holeBoxPlanOf` took its record
rung (`recArmPlainOf`), which reads the storage's row. It wrote tag 0 (`Out`) with a null payload
where the union's null tag belongs, so `j == null` was false. With `m` annotated `Out | null`,
the box tests the value (`ref.is_null`) and runs.
