### D7847 — a `const` joining two hole functions by `if`, handed a function of a concrete type, is refused

**closed · runs, prints `3` and `30` · was loud emit reject, clause 2, `vl check` rc 0, `emitProgram: a function-value call has no interned signature` · found closing [D7183](D7183.md) · filed 2026-10-20 against master `5d224f614` · closed by [D9381](D9381.md)'s spelling of a function-value pin as the closed parameter type it is taken at (`monoSlotPinName`, emit_mono.vl), so the join's arms are delivered at `(g: (a: i32, b: i32) => i32) => void` rather than at a signature no type parses from · fixture `closures/if-join-hole-fns-concrete-arg.vl`**

Repro:

    function add(a: i32, b: i32) { return a + b }
    function apply2(g) { print(g(1, 2)) }
    function apply3(g) { print(g(10, 20)) }
    function main(c: boolean) {
      const f = if c { apply2 } else { apply3 }
      f(add)
    }
    main(true)
    main(false)
    // vl check: rc 0.  vl run: emitProgram: a function-value call has no interned signature

Want:

    3
    30

#### Mechanism

The join's slot is pinned at the call by a function-value pin (`=>k`), which names only a wasm
signature. Spelled into the function type the arms are delivered at, it parsed as no type, so the
arms kept their hole parameter type at the call. D9381 spells such a pin as the closed parameter
type the flow table took it at. With that one hunk reverted, the row refuses as filed.
