    function inc0(a) { return a + 1 }
    function early(a) {
      const k: ((x: i32) => i32)[] = a
      return k[0](4)
    }
    print(early([inc0]))
    // vl check rc 0.  vl run: emit error: emitProgram: cannot take the generic function `inc0`
    //   as a value ... No call site pins `inc0`

Want:

    5

#### Mechanism

Traced. The checker decides `a` from the annotated binding, so `early`'s parameter is not a
hole at mono: `monoPinHoleParam` takes `recordedParamPinName` (`((i32)=>i32)[]`) and returns
before any of the open-function pins (`monoOpenFnListPin` and its siblings) run. Those pins
were also the only place the argument's own open functions were delivered, and an annotated
parameter's argument is delivered by `monoWalkIdentCall`, which reads only a written
annotation. So the literal reached emit with `inc0` still generic. The flow table already
carried the annotation's pin to the literal's element slot (the literal flows into `a`, `a`
into `k`); nothing asked it. The literal is now coerced there (`monoCoerceFnValueName`, which
reads each element's slot pin) whenever the recorded pin decides the parameter.
