### D9650 — a list whose elements are a call returning a generic and the generic itself, called through each element at its own type, refuses

**loud emit reject · `vl check` rc 0 · `a list holding a generic function is called through its elements at more than one type` · clause 2 · found closing [D9592](D9592.md) · present on master `92d03ef36` · filed 2026-10-22 against master `92d03ef36`**

Repro:

    function id<T>(x: T): T { x }
    function mk() {
      print("mk")
      return id
    }
    const xs = [mk(), id]
    print(xs[0](2))
    print(xs[1]("abc"))
    xs.push(id)
    print(xs[2](true))
    print(xs.length)
    // vl check rc 0.  vl run: emit error: emitProgram: a list holding a generic function is called through its elements at more than one type, so its elements have no one instance — annotate the list's element type

Want:

    mk
    2
    abc
    true
    3

#### Mechanism

Not traced. From the ablation only: the same list with the call bound to a `const` first
(`const v = mk()`, `[v, id]`) runs, so the per-element path that gives each element its own
instance resolves an element through a `const` chain and not an element that is itself a
call. [D9592](D9592.md)'s close covers a one-element list of the call; with a second element
the list takes the per-element path, which still refuses.
