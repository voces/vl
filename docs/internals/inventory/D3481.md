#### Mechanism

A prediction, not yet ablated past the counts below. Every distinct string literal within the
pool's cap is its own module global (`gStrPoolTexts`, compiler/emit_sections.vl), read by
`global.get`. `vl build` only validates; `vl run` has Cranelift compile the module, and the
cost of a function that reads tens of thousands of distinct globals is what grows: 3,000 / 6,000
/ 12,000 distinct literals run in 2.6 / 5.0 / 13.7 s and 0.4 / 0.7 / 1.36 GB against a 1.7 s
build, and at 75,000 Cranelift's per-function `MemFlags` table overflows (it interns one entry
per distinct set of memory flags, and each pooled global's access carries its own). A close keeps the
pool to a bounded number of globals (one array of string refs indexed by literal id) or splits
the readers across functions.

#### Ablation

| ingredient changed | outcome | needed? |
| --- | --- | --- |

| 75,000 `t = t + 2` instead | 4.3 s | **yes**, string literals |
