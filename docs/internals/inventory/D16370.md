### D16370 — `is C` over an `A | null` value tests only the null, so a record without `C`'s fields passes

**check-clean silently wrong · 3 cells of the `d3204` grid (`distilled/named/d3204_r3_gd_c01222_wr_isC_v_{gen,hole,lam}`), whose expectation records the wrong answer · found by the independent oracle (`scripts/oracle/`) · filed 2026-11-14 against master `de4cfa15f`**

Repro:

    type A = { v: i32 }
    type C = { v: i32, s: string }
    const a: A | null = { v: 3 }
    if a is C { print("then") } else { print("else") }
    // PRINTS then

Want:

    else

#### Mechanism

T3.4 makes `is` a value test, and `{ v: 3 }` has no field `s`, so it does not fit `C` under
either reading of OPEN-QUESTIONS Q2. The test is answered `true` whenever the value is not
null: the checker accepts `is C` against `A | null` (C is a narrower record than A), and the
emitted test checks the null arm alone. The narrowed read that follows is a clause-1 hole: with
`print(a.s.length)` in the `then` arm, `vl check` passes and the emitter refuses
(`'.length' on a receiver the emitter cannot classify`).

| `null` replaced by another arm (`a: A \| i32`) | loud emit reject | no, a sibling |
