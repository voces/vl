### D15493 — two different generics held in record fields of one un-annotated map, each called at two types, reach no instance

**loud emit reject · `vl check` rc 0 · `a generic function taken as a value reaches no call that fixes its type` · clause 2 · every un-annotated position of matrix `fn-value-two-generics-in-map-of-records-open` (0 of 23 that check) · a map whose value is a record holding a function set has no holder kind in the tag rule (`ftHoldKind`), so the set stays untagged and mono's pin can name only one generic per field · found designing the map-of-records holder kind (architecture-target-2026-10.md §3.4, bucket 1, G2's record residual) · filed 2026-11-06 against master `6f8803e7`**

#### Mechanism

The map's value is a record `{f: Fn{id, k2}}`. A list of such records is a holder the tag rule
knows (`ftHoldKind` 6), and a map of the set's ids is one (kind 3), but a map whose value is a
record holding the set is neither, so no node of the map is a place an id may stand and the set
is refused. Mono then pins each field at one generic's instance, which one map of two generics
cannot give.

| the same two records in a list (`[{ f: id }, { f: k2 }]`) | runs |
