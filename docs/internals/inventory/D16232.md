### D16232 — a function field typed as a union of a function and a record takes a function of a narrower result unconverted, and `is` on its function arm is false

**closed 2026-11-14 · now a loud check reject, `a {f: () => boolean} cannot be used as {f: (() => boolean | i32) | {w: i32}} here: a call through that type would reach a function it holds…`, by design, as its function-typed field twin · was check-clean silently wrong: on master `613c659f1` the witness printed `false` (sweep stdout `2ed27c14`), where the arm's `is` holds · clause 1 · found closing [D16296](D16296.md) · filed 2026-11-14 against master `613c659f1` · closed by `fvaFnArmsDiffer` (check_ty_relate.vl): a function inside a container that lands in a union is checked against that union's function arms · fixture `closures/error-fn-value-in-record-delivered-to-union-arm.vl`**

Repro:

    function h() { return { f: () => true } }
    const w: { f: (() => boolean | i32) | { w: i32 } } = h()
    print(w.f is () => boolean | i32)
    // vl check: the container refusal.  Was, on master 613c659f1: vl check rc 0, vl run prints false

#### Mechanism

`fvaNestedFnDiffers` (check_ty_relate.vl) compared a function held in a container with its
destination only when the destination was a function type, and answered no for a union. A
function landing in a union's function arm that needs a conversion was stored at its own
signature, so the arm's `is` test was false. The function-typed field twin
(`const w: { f: () => boolean | i32 } = h()`) was already refused.

#### Ablation

| --- | --- |
| the witness | was `false`, now the container refusal |

| the union arm `() => boolean` (no conversion) | runs, `true`, before and after |
| the record inside an outer union, `{…} \| i64` | was `false`, now the container refusal |
