#### Mechanism

`.push`, `.pop` and `.clear` resolve their receiver through `listOpRecvLocal`. A bare local is
used in place; every other receiver (a field, an index, a call, a global) is evaluated once by
`stageListRecv` into the op frame's `recvRef` scratch local, which is typed `(ref $wrap)`. A
nullable list field is stored `(ref null $wrap)` and a narrowed read of it stays that rep, so
the `local.set recvRef` fails validation. `stageListRecv` already recovered a narrowed GLOBAL
and a narrowed CAPTURE ident; the close adds the same `ref.as_non_null` for any non-ident
receiver `nulRecvNeedsRecover` claims — the predicate `.push(a, b)`, indexed stores, `for`-in
and `.slice` already ask. Disassembly: the field is `(field (mut (ref null $5)))` and the
staged slot `(local $3 (ref $5))`; the close emits `local.set $3 (ref.as_non_null (struct.get
$0 0 …))`. Which list methods fail was decided by that one function: `.map`, `.slice`,
`.length`, indexed reads and stores, `for`-in, and a multi-argument `.push` each lower through
their own receiver path and already recovered.
