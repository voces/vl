### D3161 — a closure returning an un-annotated copy of a value narrowed to a nullable string sub-union out of a box is invalid wasm

**check-clean invalid wasm · open · clause 1 · found by the #3281 round-2 review (`rv3281r2-5785/a/a17.vl`) · the same on master `b1794003a` · filed 2026-09-29 against master `b1794003a`**

Repro:

    type K = "a" | "b"
    function t(e: K | string | null | i32) {
      if !(e is i32) {
        const c = e
        const f = () => c
        const r = f()
        if r == null { print("N") } else { print(r) }
      }
    }
    t("a")
    t("zz")
    t("b")
    t(null)
    // vl check: rc 0.  vl run: invalid module inside `t`: type mismatch: expected (ref $type),
    // found (ref null $type)

Want:

    a
    zz
    b
    N

#### Mechanism

Not localised past the ablation. The validator reports a nullable ref where a non-null one is
expected inside `t`, so the frame's copy and the closure's env field or result disagree about
nullability. Which side is wrong has not been traced.

#### Ablation

| ingredient changed | outcome | needed? |
| --- | --- | --- |
| `const r = c`, no closure | runs | **yes** (the closure) |
| `const c: K \| string \| null = e` | runs | **yes** (the un-annotated copy) |
| `() => e`, no copy | runs | **yes** (the copy) |
| no `K`: `string \| null \| i32` narrowed the same way | the same invalid module | no |
