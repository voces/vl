### D2286 — an un-annotated lambda was typed by the last statement of an `if` arm even when that `if` was not the lambda's tail

**closed · was check-clean invalid wasm · found by the PL-033 position grid · filed 2026-09-23 against master `ba5378dd5`**

Repro:

    function f(g: (i32) => i32): i32 { g(1) }
    function h(): i32 {
      f((k) => {
        let t = "a"
        if k > 5 { t = "b" } else { t = "c" }
        t.length - 1
      })
    }
    print(h())
    // vl check: rc 0.  vl run: 0

#### Mechanism

`criWalkBlock` (`compiler/emit_classify.vl`) classifies an anonymous lambda's if-arm tails as
its return values, so a value-`if` union return types from its arms. It did so for the last
statement of EVERY block it walked: the arms of an `if` statement in the middle of the body, and
loop bodies. An arm ending `t = "b"` is a tail value (an assignment yields its right side), so
the lambda's inferred result became `string` while its real tail was `i32`, and the body's
`(result (ref $string))` failed validation. The walk now carries whether the block is in tail
position; only a tail `if`'s arms are return values, and a loop body never is.

#### Ablation

| ingredient removed | outcome | needed? |
| --- | --- | --- |
| a return annotation on the lambda, `(k): i32 =>` | runs | **yes** |
| a named function in place of the lambda | runs | **yes** |
| a string-typed assignment in the arm (an `i32` one) | runs | **yes** |
| the capture (the assigned local is the lambda's own) | still invalid | no |
| the inline delivery (the lambda bound to a `const`) | still invalid | no |
