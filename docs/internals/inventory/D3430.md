### D3430 — a record a function with no declared result builds is invalid wasm into a wider record when an annotation spells a record of its own fields inline

**closed by design · now a loud check reject · was check-clean invalid wasm, identical on master `d0789e90a` · a record spelled inline in an annotation is a declared row for `recBuiltAtDeclared`, as a `type`'s is · fixture `tests/cases/soundness/error-record-fresh-call-at-inline-annotated-row.vl` · found by lane RC2 (D2917 once its list adopts `I[]`) · filed and closed 2026-09-30**

Repro:

    const i: { f: i32 } = { f: 4 }
    type I = { f: i32 | null }
    function mk() { { f: 7 } }
    const b: I = mk()
    print(b.f ?? 0)
    print(i.f)
    // vl check: rc 0.  vl run: invalid module, "expected (ref null $type), found (ref $type)"

#### Mechanism

`mk`'s literal is built at the row of a record of its own field storage when one is declared
(D3338), and the emitter counts a record an annotation spells inline (`const i: { f: i32 }`, a
parameter's `r: { f: i32 }`) as declared. The checker's `recBuiltAtDeclared` looked only at
`type` declarations, so it let the call through as fresh and the `{ f: i32 }` record reached
`I`'s slot. It now also reads the records this pass's annotations spell inline
(`recAnnObjs`, filled where a binding's or parameter's annotation resolves).

#### Ablation

| ingredient removed | outcome | needed? |
| --- | --- | --- |
| `i`'s annotation (`const i = { f: 4 }`) | runs, prints `7` `4` | **yes** |
| a parameter annotation `r: { f: i32 }` in its place | same invalid wasm on master | no |
| `I`'s field made `i64 \| null` | same invalid wasm on master | no |
