### D17758 — a `const` bound to a popped element of a list of un-annotated lambdas in a generic's body has no narrowed read

**closed 2026-11-28 by COV-UNION · runs, its witness prints its expected value · was a loud emit reject, `cannot yet lower this statement (narrowed read)` · the shared arm of `monoPinListElems`, where a generic's instances share the body's nodes, types the `pop`/`get` aliases too (`monoRetypeElemTakeAliases`), as the instance's own arm does · pinned by `tests/cases/closures/hole-fn-list-taken-element-alias-in-generic.vl` · an element whose type is the instance's own type parameter is D17789**

Repro:

    function run<T>(x: T) {
      const f = (a) => a + 1
      const m = [f]
      const g = m.pop()
      if g != null { print(g(3)) }
      print(x)
    }
    run(1)
    run("s")
    // vl check: rc 0.  vl run: emit error (narrowed read) at 5:28

Want:

    4
    1
    4
    s

#### Mechanism

The generic's instances share the body's nodes, so `monoPinListElems` takes its shared arm,
which types the list's element reads per instance (`monoRetypeSlotReads`) and leaves the
`const` bound to `m.pop()` (D17757's fix) at the checker's open nullable type. Its narrowed
read then has no representation.

#### Ablation

| ingredient removed | outcome | needed? |
| --- | --- | --- |
| the type parameter (a plain function body) | runs | **yes** |
| `m.pop()` replaced by `m[0]` | runs | **yes** |
