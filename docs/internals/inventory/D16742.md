### D16742 — a list literal of lists of lists of un-annotated functions with different results has no interned shape at emit

**closed 2026-11-16 — the witness runs and prints `4` then `1.5` · was: loud emit reject · clause 1 (check accepts what emit refuses) and clause 2 · found closing [D16731](D16731.md) · filed 2026-11-16 against master `71ff99b49`**

Repro:

    function inc0(a) { return a + 1 }
    function half(a) { return a / 2.0 }
    const xs = [[[inc0]], [[half]]]
    print(xs[0][0][0](3))
    print(xs[1][0][0](3))
    // vl check: rc 0.  vl run: emit error, "emitProgram: ref valtype with no interned shape"

Want:

    4
    1.5

#### Mechanism

The tag plan's list-literal join (`ftLitJoin`, `compiler/check_fn_tag.vl`) accepted an element
literal holding a smaller set only one level down (`ftInnerLeaves`): `[[inc0]]` inside a list of
lists of lists is a list of lists, so the plan refused, the set stayed untagged, and the list was
held as closures over hole functions, which key no row. `ftInnerLeaves` now descends a list of
lists, each element a smaller-set literal one level down or a literal already holding the set.

The same close ran the hole-instance spellings, which needed the loop element's row of a tagged
list read through `refListSlotOfExpr` (`forInVarStructIdx`) and the element-alias dispatch of
[D16748](D16748.md).

#### Grading list

- Four and five levels of lists: run.
- Walked by nested `for` loops, returned from a function, handed to an un-annotated parameter:
  run.
- [D14782](D14782.md): unchanged (`nested arrays are not supported`), another mechanism.
- Still refused: [D16804](D16804.md) (a returned literal beside a wider set),
  [D16805](D16805.md) (`push`), [D16806](D16806.md) (a record field).
