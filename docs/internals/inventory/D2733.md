### D2733 — `is` over a nullable map answers false when the pattern spells the map's value union in another order

**closed 2026-09-26 — the filed repro RUNS and prints `true` · was check-clean silently wrong (`false`) · clause 1 · found by #3202's review (n3) · closed in the same PR: the niche test compares map types up to union member order and repetition · filed 2026-09-26 against master `74bd044d7` · fixture `tests/cases/generics/pin-exact-key-union-box-is.vl`**

Repro:

    const x: {[string]: string | i32} = Map()
    const u: {[string]: string | i32} | null = x
    print(u is {[string]: i32 | string})
    // PRINTS true

#### Mechanism

A map beside `null` is a niche, so `u is M` is answered by comparing `M` with the map the niche
holds (`mapNicheLacks`). That comparison was `tyEq`, which follows the render and so the order of
a union's members: `string | i32` and `i32 | string` are one type and compared unequal.
`tySameSet` compares members as a set at every level of a map, list or union, and the generic
paths (`mapTwinExact`) read the same comparator. A box test has the same shape since #3198 gave
same-struct maps a tag per member type, keyed by that order-sensitive equality: a pattern with no
exactly-equal member now tests the member it equals up to order (`isPatUnionArmTy`), so
`v: {[string]: string | i32} | string` answers `is {[string]: i32 | string}` true again. Only
the comparison changed; a union's box tags keep their positions.
