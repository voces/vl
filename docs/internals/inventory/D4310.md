### D4310 — a binding of a generic function passed to a generic higher-order parameter is not instanced at the callee's pin

**closed · runs, prints `3` · was loud emit reject, `monomorphize: unsupported argument type for `g` in a call to `app`` · hand probe, no corpus cell · filed 2026-10-13 against `c539edba5` · closed by the D8981 change: the monomorphizer follows a `const` or once-bound `let` to the function it holds and binds the parameter from the value arguments (`monoArgIsOpenFnValue`, `monoOpenFnArgDecl`, emit_mono.vl) · the `const f = idg` spelling runs too · the written spelling (`f = kg` before the call) still refuses and is [D9001](D9001.md)**

Repro:

    function idg<T>(t: T): T { return t }
    function app<T>(g: (x: T) => T, v: T): T { return g(v) }
    let f = idg
    print(app(f, 3))
    // vl check: rc 0.  vl run: emitProgram: monomorphize: unsupported argument type for `g` in a call to `app`

#### Mechanism

The argument `f` reaches `app`'s parameter `g`, whose type is open until `app` is instanced
at `T = i32`. Nothing instances `idg` at that pin before the call is lowered, so the
monomorphizer has no concrete function type for the argument and refuses. It is the
"argument to a generic callee" row of `fn-value-flow-design.md` §(e) at a function-typed
parameter.

#### Ablation

| ingredient removed | outcome | needed? |
| --- | --- | --- |
| a write `f = kg` added | still refuses | no |
| `app` made non-generic (`g: (x: i32) => i32`) | runs, prints `3` | **yes** |
| `idg` made non-generic (`t: i32`) | runs, prints `3` | **yes** |

#### Grading list

- The written spelling: `let f = idg` then `f = kg` before the call.
- `const f = idg` in place of `let`, and `app(idg, 3)` with no binding.
