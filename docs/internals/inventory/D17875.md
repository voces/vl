### D17875 — a list of a two-member tagged set's names beside `null` has no element rep

**closed 2026-11-28 · runs, prints `11` `null` `20` · was `emitProgram: the compiler cannot yet lower this statement (convert null -> closure)` · a list element's join of a member and `null` is a nullable, which `elabFnJoinTy` (check_elab_cap.vl) returned unchanged, so the second member's set never joined the first's; it now joins the functions under the `| null`, and `monoPinListElems` (emit_mono.vl) leaves a literal whose element slot is a tagged set or its nullable typed at the set · pin `closures/list-of-two-tagged-members-beside-null` · the binding of an `if` join of the same is [D17876](D17876.md) · filed 2026-11-28 against master `e5f5a2e39` by COV-UNION (found closing D17865, coordinator ruling)**

Repro:

    function inc(a) { return a + 1 }
    function dbl(a) { return a * 2 }
    const xs = [inc, null, dbl]
    for x in xs { if x != null { print(x(10)) } else { print("null") } }
    // vl run: prints 11, null, 20

Want:

    11
    null
    20

#### Mechanism

Not traced. With one member (`[inc, null]`, D17865) the set is tagged and the list is the nullable
id's list. With two members the same list's `null` meets a closure element rep, so the two-member
set is not held as ids here. Other spellings refuse at other sites: the element read past a null
test, `const f = xs[0]` (`global initializer coercion`); a join `[if c { inc } else { null }, dbl]`
walked by a `for` (`narrowed read`).
