### D4700 — a record field written with a generic in one function and a second record's field written from another emit an i32 where the field's closure ref is wanted

**closed 2026-10-14 — the witness prints `A 3 A 4 2 A x` · the record-field pin reads the flow table's per-field signature (`fnFlowDeclPathPinSigs`) and the mono write index's field writes, replacing the mono-side record walk (`monoPinGenericRecord`) · fixture `tests/cases/closures/record-field-written-in-two-scopes.vl` · was check-clean invalid wasm · clause 1 · filed 2026-10-14 against master `3c4ad2c5d`**

Repro:

    function gA<U>(u: U) {
      print("A")
      print(u)
    }
    function gC<W>(w: W) {
      print("C")
      print(w)
    }
    function main() {
      const y = { h: gC, n: 2 }
      if y.n > 1 { y.h = gA }
      y.h(3)
      const z = y
      z.h(4)
      print(y.n)
    }
    main()
    const t = { h: gC }
    function set() { t.h = gA }
    set()
    t.h("x")

Want:

    A
    3
    A
    4
    2
    A
    x

#### Mechanism

The mono-side record walk (`monoPinGenericRecord`) pinned a written field from the field calls it
found on the binding's own name, so the alias call `z.h(4)` was not among them; with the second
record's write present the validator rejected `main` at `y.h = gA` (an `i32` where a ref was
expected), and without it the same program was a loud emit reject. Which step of the retired walk
crossed the two records was not ablated further. The flow table holds one signature per field
slot, through aliases and across functions, and the pin now reads it.
