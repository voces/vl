#### Mechanism

From the ablation only. D5360 delivers the returned generic at the one pin past `mk`'s return;
two results called at two types give that return two pins, and the delivery takes none. The
alias spelling `const g = k; return g` refuses the same way.

Re-graded 2026-10-17 by lane L1, closing D5530: unchanged, and the mechanism is measured. `mk`
declares no type parameter and takes no argument, so the flow table walks it once, in frame 0,
and its return slot is one class shared by both calls: `a` and `b` each pin it, and
`monoCoerceRetAtPin` declines a return with two pins. D5530's per-call key in `ffDirect` splits
the walk of a callee that is HANDED an open generic; here nothing is handed in, so no key can
split it. Closing it needs `mk` itself instanced per result pin, the D3975 ruling's shape: a
`fn_split` plan that clones a concrete function per pin past its return and renames each call
(`fsAsk` asks only of a reassigned `let` today), or a per-call-type return record. The two
`fw(k)` results of D5530 run because each call there already has a context of its own.
