### D9562 — `??` with an `f64` default over the call of an un-annotated parameter bound at a function returning an `i32` literal union is refused at emit

**loud emit reject · clause 2 · CAPABILITY: an annotated `f: () => N` runs, and `a ?? 2.5` over an `N | null` value directly runs · found closing [D9521](D9521.md) · present on master `95725e040` · filed 2026-10-22 against master `95725e040`**

Repro:

    type N = 1 | 2
    const a: N = 2
    function take(f) {
      print(f() ?? 2.5)
    }
    take(() => a)
    // vl check: rc 0.  vl run: emitProgram: `??` over this nullable value is not supported yet — narrow it first, e.g. `if v != null { … }`

Want:

    2

#### Mechanism

Partly traced. The `??` joins `N` with `f64`, so its pin is not `N`'s scalar base and the
instance's dead-default fold (`coalRetypedDead`, emit_classify.vl) declines. Folding here also
needs the operand converted to the join's type, which the fold does not do.

| --- | --- | --- |

| the call (`a ?? 2.5` over `N \| null`) | runs | **yes** |
| the `f64` default (`?? 0`) | runs since [D9521](D9521.md) | **yes** |
