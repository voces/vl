### D2564 — a nullable-record function is emitted at the wrong heap once an `A | B` union of two other records is spelled

**check-clean invalid wasm · clause 1 · found by the review of #3173 (item 1), the same on master `dcc88a350` · filed 2026-09-26 against master `dcc88a350`**

Repro:

    type A = { r: i32 }
    type B = { q: string }
    type C = { c: i32, z: f64 }
    function mkB(s: string): B | null { if s == "" { return null } return { q: s } }
    function mkC(n: i32): C | null { if n == 0 { return null } return { c: n, z: 1.5 } }
    function stB(): B { return { q: "d" } }
    function go() {
      const x: A | B = stB()
      print(x is B)
    }
    go()
    // vl check: rc 0.  vl run: invalid module, inside `mkC`:
    // "type mismatch: expected (ref null $type), found (ref null $type)"

#### Mechanism

A prediction until a close confirms it. `mkC` never touches `A` or `B`, yet its body fails
validation once the program spells `A | B`, and only while a second nullable-record function
(`mkB`) exists. The likely cause is that registering the union's arms renumbers the record heap
types, and the return type or the `ref.null` of `mkC` is read from a table taken before the
renumbering. It is the same one-slot-off shape lane U saw in [D2373](D2373.md)'s first attempt,
but here it needs no synthesized annotation.

#### Ablation

| ingredient changed | outcome | needed? |
| --- | --- | --- |
| `mkB` deleted | runs, `true` | **yes** |
| the annotation removed (`const x = stB()`) | runs, `true` | **yes** |
| `mkC` returns a non-null `C` | runs, `true` | **yes** |
| `C` with one field (`{ c: i32 }`) | still invalid | no |
| `mkC` called (`print(mkC(2) == null)`) | still invalid | no |
| the annotation `A \| B \| null` | still invalid | no |

#### Grading list

Each ablation row, and the same program with `B | A | null` as a parameter annotation. And the
review of #3173's `A | i32` finding: `const x: A | i32 = mkA(a) ?? 7` beside an unused
`mkB(): B | null` is invalid inside `mkB` on master, and D2373's close lets an inline join
spell such a union where the program writes none, so it reaches this row more often. That is
a recorded price of the close, not a regression of it.
