### D2564 — a nullable-record function is emitted at the wrong heap once an `A | B` union of two other records is spelled

**closed 2026-09-26 — the filed repro RUNS and prints `true` · was check-clean invalid wasm, clause 1 · found by the review of #3173 (item 1) · filed 2026-09-26 against master `dcc88a350`**

Repro:

    type A = { r: i32 }
    type B = { q: string }
    type C = { c: i32, z: f64 }
    function mkB(s: string): B | null { if s == "" { return null } return { q: s } }
    function mkC(n: i32): C | null { if n == 0 { return null } return { c: n, z: 1.5 } }
    function stB(): B { return { q: "d" } }
    function go() {
      const x: A | B = stB()
      print(x is B)
    }
    go()
    // vl check: rc 0.  vl run: invalid module, inside `mkC`:
    // "type mismatch: expected (ref null $type), found (ref null $type)"

#### Mechanism

The row predicted a heap renumbering; the cause was two emitter seeds. `mkB`'s `B` is an arm
of the spelled `A | B`, so its return is the `nulvariant` niche, and `emitReturnValue` seeds
`pendingNulRefHeap` with `B`'s heap for a bare `return null`. A `return { … }` never consumes
that one-shot seed, and the function's exit reset cleared every seed but that one, so it
survived into `mkC` and typed `mkC`'s `return null` as `ref.null $B`. The exit now clears it.
A second shape of the same leak needed no second function: a `const c: C | null = null` inside
`mkB` took `B`'s heap from `emitNullBySeed`'s last-resort arm (the enclosing function's own
`nulvariant` return), which sat ahead of the binding's own `pendingStructIdx` seed; the seed
now answers first. Clearing the leak exposed one consumer of it: an un-annotated function whose
inferred return is a `nulvariant` (`tests/cases/types/inferred-nullable-variant-return.vl`) had
no null seed of its own and typed its `return null` from the previous function's leftover; it
now seeds from the same `fRetStructIdx` column its functype reads.
