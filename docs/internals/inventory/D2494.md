### D2494 — a generic over an index signature, `rd<V>(m: {[string]: V})`, passes check and refuses in monomorphize

**closed · runs, prints `4` at `{[string]: i32}`; at `{[string]: string}` it prints `q` · was loud emit reject, `vl check` rc 0, `emitProgram: monomorphize: unsupported argument type …`, clause 2 · found by #3158's review; the design doc's F7 · identical on master · filed 2026-09-25 against master `0a0d24ac9` · closed by binding the type parameter from the argument's arena type against the parameter's, walking the two together, rather than matching the argument's spelling (`monoBindArenaWalk`, `monoPinTyParamComposite`, emit_mono.vl) · fixture `generics/generic-arena-bind-map-and-alias.vl` · closed with [D9820](D9820.md)**

Repro:

    function rd<V>(m: {[string]: V}, k: string): V | null { m[k] }
    const m: {[string]: i32} = Map()
    m["a"] = 4
    print(rd(m, "a") ?? 0)
    // vl check: rc 0.  vl build: monomorphize: unsupported argument type for `m` in a call to `rd`

Want:

    4

#### Mechanism

Not ablated. The monomorphizer's argument binding has no arm for a map type whose value is
the type parameter, so the pin never binds `V`. This is `collections-representation-design.md`
§10 F7, a prerequisite of that doc's step 4.
