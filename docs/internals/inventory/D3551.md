#### Mechanism

Not yet ablated past the variant level, so this row names costs, not passes. The lambda cost
is the lambda's, not a method's: the built-in `map`/`filter` with lambdas land on the same
+256%, and with named functions on +6.2%. That says a lambda anywhere switches on work that
scales with the whole unit (closure collection or naming over every function is the first
suspect). The import cost does not depend on what is imported or called, which points at
the multi-module merge itself rather than at monomorphization. plumb's real units already
import modules, so they have already paid the second cost; the plumb-shape units hold no
lambda and no import, so the standing gate is blind to both.
