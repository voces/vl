### D2516 — `for v in outer.values()` over a map-valued map has no loop-variable kind, so a check-clean walk refuses in emit

**loud emit reject · clause 2 · pre-existing on master `d29a9d220`, at string and i64 keys ·
found by #3164's review · filed 2026-09-25 against master `aed171ac5`**

Repro:

    const outer: {[string]: {[string]: i32}} = Map()
    const inner: {[string]: i32} = Map()
    inner["x"] = 1
    outer["a"] = inner
    for v in outer.values() { print(v.length) }
    // vl check: rc 0.  vl build: emitProgram: unsupported for-in iterable

#### Mechanism

The refusal is `emitForIn`'s `emitFailAt("emitProgram: unsupported for-in iterable")`, reached
when `forInElemKind` returns no kind for the loop variable. A `.values()` iterable is answered
through `mapValElemKind`, which has no nested-map arm; that is the predicted cause, shared with
[D2515](D2515.md), and not yet confirmed by a probe.

#### Ablation

| ingredient removed | outcome | needed? |
| --- | --- | --- |
| the value `{[string]: i32}` replaced by `string[]` | prints `1` | **yes** — a map value |
| `outer.values()` replaced by `for k in outer` reading `outer[k] ?? Map()` | prints `1` | **yes** — the values walk |
| the keys `string` replaced by `i64` (both levels) | still refuses | no |
