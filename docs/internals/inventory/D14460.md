#### Mechanism

`skQsMoved` (`compiler/driver.vl`) re-answers every banked write question whose declaration's
module the partial check typed again, and declines `interface` when the answer differs from
the banked one. The answers come from `fnWriteShapes` / `fnWriteEffects`
(`compiler/check_write_effects.vl`), which memoise per function in `weShapeSums` / `weSums`.
A summary asked for while the walk was still typing bodies was memoised then, and the
post-check ask read that memo instead of the typed program. The whole check and the partial
check do not ask at the same points of the walk, so the two memos differed: in diderven's
`quaddefs.vl` witness, quadrig's `leg` shape question was banked `-;=atHi…;[]#a<f64>;[]#a<i32>`
and answered `?` (opaque) in the served check, on an edit that moved nothing. The memos are now dropped when
`checkProgramResumed` finishes, so every post-check ask is answered from the typed program.
