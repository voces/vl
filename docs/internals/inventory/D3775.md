### D3775 — a hole callee's write into a list binding is never checked against the element the binding's own later write pins

**check-clean invalid wasm · open · found while closing D3746 · filed 2026-10-06 against master `a21053689`**

Repro:

    function take(a) {
      a.push(1.5)
      print(a[3])
    }
    const h = __array_new_default__(3)
    take(h)
    h.push(2)
    print(h.length)
    // vl check: rc 0.  vl run: invalid module inside `take`, `expected i32, found f64`

#### Mechanism

At `take(h)` the binding's row is still open, so the callee's deferred `.push(1.5)` is
re-recorded with a hole on the destination side (`validateBmCstrs`) and the call does not pin
it (D2218: a binding keeps its own later writes). The caller's `h.push(2)` then pins `i32`,
and nothing re-asks the callee's `f64` write against it: a re-recorded constraint is owned by
the caller and is re-validated only when that caller is itself instantiated, which a
top-level frame or a non-generic function never is. The instance of `take` is built over the
`i32` list and pushes an `f64`. D3746's close records the same write (`calleeWriteRow`) to pin
a row nothing else pins; the missing half is a check of each recorded write against the row's
final element, with literal adaptation (`take` pushing `1` into a list a later `2.5` pins must
keep running, `ua-hole-pin-binding-open`).

#### Ablation

| ingredient changed | outcome | needed? |
| --- | --- | --- |

| the later write is `h.push(2.5)` | runs | **yes** |
| a second callee pushes `"s"` instead of the caller's write | invalid wasm inside the second callee | no |
| `[]` instead of the intrinsic | the same invalid wasm | no |
