### D3775 — a hole callee's write into a list binding is never checked against the element the binding's own later write pins

**closed 2026-10-06 — the witness prints `1.5` then `5` · was check-clean invalid wasm, clause 1 · found while closing D3746 · filed 2026-10-06 against master `a21053689` · closed by lane S4 on #3404's head `8b253f36b` · fixtures `tests/cases/inference/hole-callee-write-then-caller-write.vl`, `tests/cases/inference/error-hole-callee-write-conflicts.vl`**

Repro:

    function take(a) {
      a.push(1.5)
      print(a[3])
    }
    const h = __array_new_default__(3)
    take(h)
    h.push(2)
    print(h.length)
    // vl check: rc 0.  vl run: invalid module inside `take`, `expected i32, found f64`

Want:

    1.5
    5

#### Mechanism

At `take(h)` the binding's row is still open, so the callee's deferred `.push(1.5)` is
re-recorded with a hole on the destination side (`validateBmCstrs`) and the call does not pin
it (D2218: a binding keeps its own later writes). The caller's `h.push(2)` then pins `i32`,
and nothing re-asks the callee's `f64` write against it: a re-recorded constraint is owned by
the caller and is re-validated only when that caller is itself instantiated, which a
top-level frame or a non-generic function never is. The instance of `take` is built over the
`i32` list and pushes an `f64`. D3746's close records the same write (`calleeWriteRow`) to pin
a row nothing else pins; the missing half is a check of each recorded write against the row's
final element, with literal adaptation (`take` pushing `1` into a list a later `2.5` pins must
keep running, `ua-hole-pin-binding-open`).

#### The close

The direct spelling `const h = []; h.push(1.5); h.push(2)` RUNS: the first write pins `f64` and
the later literal `2` adapts to it (the numeric-join ruling: literals adapt). The callee's write
is the first write in program order, so the close gives the callee spelling the same answer
rather than a check error. Two halves, both in typecheck.vl:

* `calleeWritePrePin`, at a caller's `.push` and index store into a still-open row: when an
  earlier hole callee's recorded write cannot be held at the caller's element, the row first
  takes the callee's element, and the caller's write is then checked against it like any later
  write. A literal `1` from the callee beside a later `2.5` CAN be held at `f64`, so the later
  write still decides there (D2218's `ua-hole-pin-binding-open` cells keep running).
* `checkCalleeWrites`, once every pin is in: every recorded callee write is checked against the
  element its row finally took, wherever that came from (a second callee's write, a typed
  parameter the list is passed to). A write that element cannot hold is refused at the call:
  `the callee's body writes string into the list passed here, whose element is f64`.
