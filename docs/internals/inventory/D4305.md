### D4305 — a capture cell written with a generic by a closure the instances share is refused when the written generic already has an instance at another type

**loud emit reject · clause 2 · found closing D3953 (lane SC, fn-value-flow §(f) step 3; `sc3/q/m_aC`, `oc2`, `oc4`) · filed 2026-10-13 against master `3f7d6e27f` with #3622 applied**

Repro:

    function inner<U>(u: U) { print("I"); print(u) }
    function other<V>(v: V) { print("O"); print(v) }
    function c<T>(x: T) {
      let h = inner
      const w = () => { h = other }
      w()
      h(x)
    }
    other(1)
    c(2.5)
    c("s")
    // vl check: rc 0.  vl run: emitProgram: the captured binding `h` is written with a function inside a closure that every instance of the enclosing generic function shares

Want:

    O
    1
    O
    2.5
    O
    s

#### Mechanism

Not located. Without the earlier `other(1)` the two instances of `c` each get their own copy of
the write `h[0] = other` and the program runs; with it, both instances' cell coercions
(`monoCoerceLetValues`) reach the template's write node, so `monoCellSigRecord` is asked for the
`f64` and the `string` signature on one node and `monoCellWriterSigFail` refuses.
