### D16105 — a wider record written into a name under a short-circuit operand, used as a value, has no value lowering

**closed 2026-11-14, runs and prints `true` · was loud emit reject, clause 2, and invalid wasm until [D16104](D16104.md)'s close · closed by delivering the value at the write itself: a name whose record the right side's wider record extends by its row's `sub` chain stores that very object, so the name's re-read, cast back to the wider row, is the value (`asgNameWiderRow`, emit_classify.vl, read by the `=` value arm in wasmEmit.vl and by `structIndexOfExpr`) · graded by `scripts/capability-probes/matrix/wider-record-name-write-value.matrix.vl`, 56 of 56, its ten short-circuit and field-read cells moving from emit refusal to RUNS · fixture `tests/cases/soundness/wider-record-write-value-under-short-circuit.vl` · filed 2026-11-14 against master `a1e5fe53d`**

Repro:

    type A = { x: i32 }
    type B = { x: i32, y: i32 }
    function yOf(q: B): i32 { return q.y }
    let k = 0
    function nb(): B { k = k + 1; return { x: k, y: k * 10 } }
    let a: A = { x: 0 }
    const t = k < 5 && yOf(a = nb()) > 0
    print(t)

Want:

    true

#### Mechanism

The value of `a = nb()` is `nb()`'s record at `B`, while `a` stores `A`'s. D2398 delivers such a
value by moving the write ahead of its statement, but a write in the right operand of `&&`,
`||` or `??` runs only when the left side says so, so the walk stops there and nothing moves.
The name's re-read is not the value at `B`, so the write is refused. Delivering it needs the value
kept in a local of `B`'s rep at the write itself.
