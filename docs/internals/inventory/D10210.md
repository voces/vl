### D10210 — a `string`-result lambda handed through a hole parameter into a generic's `() => T | string` parameter is read as a list

**check-clean invalid wasm · `vl check` rc 0 · `type mismatch: expected (ref $6), found (ref $1)`, an `i32` list against a `string`, inside `len` · clause 1 · the `string`-result face of [D10160](D10160.md) · present on master `d3102bf26` · found closing [D10161](D10161.md) · filed 2026-10-22 against master `d3102bf26`**

Repro:

    function len<T>(f: () => T | string) {
      const t = f()
      if t is string { 0 } else { 1 }
    }
    function take(a) { print(len(a)) }
    take(() => "s")
    // vl check: rc 0.  vl run: the emitted module failed to validate inside `len`: type mismatch: expected (ref $6), found (ref $1); $6 is `i32 array (list and map storage)`, array (mut i32); $1 is `string`

Want:

    0

#### Mechanism

Not traced. D10161's close binds `T` to the unbound default at the call's check, when the
argument's own result is the union's fixed member. Through the hole parameter `a` the call
inside `take` sees a hole, not the lambda, so nothing binds `T` and no adapter boxes the
result. The instance built at `take`'s pin then reads the lambda's `string` as the default's
list rep, as D10161 did before its close.
