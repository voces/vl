### D16110 — a call through a re-pointed `let` of hole lambdas re-asks every lambda written to it, not the one its most recent write stored

**loud check reject · `argument 1: operator '+' is not defined for string and i32 (the body of `k` applies '+' to this argument)` · clause 2 · the flow-sensitive-read ruling permits it: `k("s")` reads the second lambda · the hole-lambda spelling of [D15956](D15956.md)'s grading list · filed 2026-11-14 against master `43943a5bf`**

Repro:

    function main() {
      let k = (x) => { print(x + 1) }
      k(1)
      k = (y) => { print(y) }
      k("s")
    }
    main()
    // vl check: argument 1: operator '+' is not defined for string and i32 (the body of `k` applies '+' to this argument)

Want:

    2
    s

#### Mechanism

D15956's close narrows a read only when every function written to the binding is a declared
generic, because the read is renamed to the function it holds and a lambda has no name. Here
both writes are lambdas, so the read keeps the whole set. The call then re-asks the first
lambda's body at `string` (D3968's `fsbRecheckCalls`).
