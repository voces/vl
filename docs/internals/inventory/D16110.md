### D16110 — a generic passed as a value and instantiated at a scalar is refused at the function argument, not at the scalar

**closed 2026-11-14 by lane J · now a loud check reject at the offending argument, `1` (`3:21`), where it was anchored at `same` · the refusal is owed (DECISIONS A15); its anchor was the defect · found moving the generic `===` refusal to the call site · filed 2026-11-14 against master `688f693a0`**

Repro:

    function same<T>(a: T, b: T) { return a === b }
    function viaHole(f, a, b) { return f(a, b) }
    print(viaHole(same, 1, 2))
    // vl check: check error at `1` (3:21), "argument 2: `===` compares identity, and `i32` has none — use `==` (`same` is passed as a value and instantiated at `i32`, where its body applies `===`)"
    // Was: anchored at `same`, the first argument.

#### Mechanism

A direct call grades the `===` constraint in `validateBinCstrs` with the call's arguments to hand,
and anchors on the argument typed with the value that has no identity (`identityArgOf`). A generic
handed to a function parameter is instantiated where it is passed, so the node the grading sees is
the `same` identifier, not a call. The scalars `1` and `2` are arguments of the enclosing
`viaHole(...)` call, and no parent table reaches it from there. The refusal is the ruled one, and
the sentence names the type and the route. What is owed is the anchor: DECISIONS A15 puts it "on
the offending argument", which here is `1`.

#### Fix

`validateBinCstrs` (`compiler/check_demands.vl`) asks the write-scan parent table
(`cwIxParent`) for the call that passes the generic as one of its own arguments, and raises at
that call's first argument typed with the value that has no identity. With no such call (a
binding's initializer) the refusal stays at the function, naming type and route.

#### Ablation

| ingredient changed | outcome | needed? |
| --- | --- | --- |
| `same(1, 2)` directly | refused at `1` | **yes**: the route through a parameter |
| `viaHole` annotated `<T>` | the same anchor | no |
