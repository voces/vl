### D2160 — an ANNOTATED record delivered where its field is a wider UNION is check-clean invalid wasm, and a list around it is scenery

**closed by design · now a loud check reject · was check-clean invalid wasm · the owner's record-covariance ruling refuses it: an annotated record is not fresh, and a union field is stored as a box · closed 2026-09-30**

Repro:

    function f(p: { x: i32 | string }) { print(p.x) }
    const q: { x: i32 } = { x: 1 }
    f(q)
    // vl check: rc 0.  vl run: invalid module — type mismatch: expected (ref $type), found (ref $type)

#### Mechanism

The checker admits `{ x: i32 }` where `{ x: i32 | string }` is declared (depth subtyping on a
field), and the delivery hands the narrow struct reference over unconverted: the source's field
is a plain `i32` slot and the destination's a union box, so the two structs are unrelated wasm
types. The object-shape floor (`objShapeAdapterless`) refuses the same field pair when it is a
WIDTH pair of numbers (`objFieldWidthPair`) and does not reach a union field. Found while
inventorying implicit container widenings for the 2026-09-23 ruling; the ablation says the
container is not an ingredient, so this is a record row, not a container one.

#### Grading list

The nine-position `rec_fld` rows of the grid (read-only, write through the wide handle, write
through the original). D2036 (`{ x: i32 }` into `{ x: f64 }`) is the sibling whose close is
predicted to decide this one too, and D2060 (#3049, a covariantly delivered record is read-only
in its widened fields) settles the WRITTEN spellings here but not the read-only one, which fails
at validation before any write runs.

#### Close (2026-09-30)

Closed by the owner's record-covariance ruling (DECISIONS.md "Record covariance: only a fresh value widens"): an annotated record is not fresh, and a union field is stored as a box. The refusal names both fixes, building the source at the wider record or copying it with an object literal, so no program the design permits is refused.
