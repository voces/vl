### D7140 — a hole-function list's `for` loop variable called with a generic function is refused, though the element call beside it takes the same generic

**loud emit reject · `vl check` rc 0 · clause 2 · CAPABILITY: the same list called through `fs[0](add)` alone runs `3 4 3 4` ([D7101](D7101.md)), and so does a `for` whose loop variable is unread · found closing [D7101](D7101.md) · the same on master `8e787a973` · filed 2026-10-19 against master `8e787a973`**

Repro:

    function add(a, b) { return a + b }
    print(add(1, 2))
    print(add(1.5, 2.5))
    function apply2(g) {
      print(g(1, 2))
      print(g(1.5, 2.5))
    }
    const fs = [apply2]
    fs[0](add)
    for f in fs { f(add) }
    // vl check: rc 0.  vl run: emitProgram: cannot take the generic function `add` as a value — a function value carries ONE signature, and parameters `a`, `b` are un-annotated

Want:

    3
    4
    3
    4
    3
    4

#### Mechanism

Not located. The value-flow question follows the loop variable to its call `f(add)` and
answers the same call type the element call does, so the refusal is the delivery of `add` at
the loop variable's call, which still hands the hole generic as one signature.
