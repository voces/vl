### D2918 — a lambda capturing a local bound to a hole list literal's element stores it in an `i32` env field

**closed 2026-09-28 — the filed repro prints `2.5` · was check-clean invalid wasm, clause 1, the same on master `e91e04a8f` · closed by typing a captured local's env field from the hole instance's binding, at `f64`, `i64` and `string` pins · the box pins (`i32 | null`, `i32 | string`) are [D2929](D2929.md), an `f32` pin is [D2932](D2932.md) · filed 2026-09-27 against master `0284dc2a8`**

Repro:

    function h(x) {
      const l0 = [x]
      const y = l0[0]
      const k = () => y
      print(k())
    }
    h(2.5)
    // vl check: rc 0.  vl run: invalid module inside `h`, expected i32, found f64

Want:

    2.5

#### Mechanism

A hole instance shares the generic body's nodes, whose recorded type is the hole's type variable, so a classifier reading that type sees the template's `i32` rep. An explicit `<T>` instance re-types those nodes at the pin (`monoPinRetype`) and a hole instance did not. `monomorphize` now banks each hole instance's binding (`monoHoleSubRow`), and `holeOperandTyOf` reads a shared node at it without banking a pin. `letInitCellKind`'s last rung asks it for an initializer no other rung claimed, so the env field takes an `f64`, `i64`, `string` or `string | null` pin's rep. A box pin needs a slot beside its kind, and is [D2929](D2929.md). At `f32` the field is right but the print sink is not, [D2932](D2932.md); at `string | null` the capture traps, [D2926](D2926.md).
