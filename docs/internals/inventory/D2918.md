### D2918 — a lambda capturing a local bound to a hole list literal's element stores it in an `i32` env field

**check-clean invalid wasm · clause 1 · open · 6 cells of the lane TR grid (`lit__cap__*` at `f64`, `string`, `i32 | null`, `i32 | string`) · the same on master `0284dc2a8` · filed 2026-09-27 against master `0284dc2a8`**

Repro:

    function h(x) {
      const l0 = [x]
      const y = l0[0]
      const k = () => y
      print(k())
    }
    h(2.5)
    // vl check: rc 0.  vl run: invalid module inside `h`, expected i32, found f64

Want:

    2.5

#### Mechanism

Not localised past the ablation. `y` is typed at the hole's variable (the index read off the
shared template literal), and the capture's env field is typed from that, as the `i32` default,
while `h` stores the instance's `f64` into it. The binding itself lowers at the pin (reading `y`
without the lambda runs), so only the capture reads the unsubstituted type.

#### Ablation

| ingredient changed | outcome | needed? |
| --- | --- | --- |
| `print(y)` without the lambda | runs, `2.5` | **yes** |
| `const k = () => l0[0]` (the list captured) | runs | **yes** |
| `const y: f64 = l0[0]` | runs | **yes** |
| `h<T>(x: T)` | runs | **yes** (the hole) |
| a `string` pin | still invalid | no |

#### Grading list

The lane TR grid's `lit__cap__f64`, `lit__cap__str`, `lit__cap__ni32N`, `lit__cap__ni32V`,
`lit__cap__uI`, `lit__cap__uS`. A `string | null` pin runs since [D2899](D2899.md) re-made that
literal at its instance type; doing the same for every element is the obvious rung, untried.
