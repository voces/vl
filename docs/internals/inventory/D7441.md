### D7441 — a closure capturing a tag read off an enclosing function's local cannot see the local, and reads the atom env field as a string

**closed 2026-10-19 by lane L6 · runs, prints `b` · was runs but wrong value · clause 1 · the capture classifiers ask the parent binding from the capturing frame, as `captureValKind` sizes the env field · pin: `tests/cases/closures/captured-local-record-union-tag.vl` · present on master `1c86d0f42` · filed 2026-10-19 against master `1c86d0f42`**

Repro:

    type N = { tag: "a" | "c", v: i32 } | { tag: "b", w: i32 }
    function mk(): N { { tag: "b", w: 2 } }
    function inner() {
      const s = mk()
      const t = s.tag
      const k = () => { print(t) }
      k()
    }
    inner()
    // vl check: rc 0.  vl run on master: prints 2, not `b`

#### Mechanism

`captureValKind` types the env field for `t` off its initializer from the capturing frame
(`capInitAsk`), so `s.tag` is classified against `inner`'s local `s` and the field is the
i32 atom. The read inside the closure asks `capturedIsLitAtom`, which classifies the same
initializer without that flag. While the closure is emitted, `inner`'s local `s` has no
loaded slot, so `exprUnionIdent` answers false, the tag read is not an atom, and `print`
prints the i32 as a number. `capturedIsNulLitUnion`, the `?.` niche dual, has the same gap:
`t?.tag` captured and coalesced inside the closure is a loud emit reject. The close sets
`capInitAsk` in both, so the field and its read are classified by one ladder.
