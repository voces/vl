### D2988 — a `boolean` record handed to an un-annotated parameter beside a declared record of a NUMERIC literal set reads as that set's member

**check-clean silently wrong · clause 1 · found by lane RW's record-literal grid · filed 2026-09-28 against master `4dc94bd23`**

Repro:

    type D = { v: 1 | 2 }
    function rd(o) { print(o.v) }
    const q = { v: true }
    rd(q)
    // PRINTS 1

Want:

    true

#### Mechanism

Not localised past the ablation. D2979's close compares a record literal's field types with a
declared record's by layout kind, and gives a numeric literal set (`1 | 2`) no kind: it is an
`i32` at run time, so treating it as `i32` would be right, but doing that moved the annotated
face below from a loud refusal to invalid wasm inside `rd`'s instance, so the close left it out.
`q` itself reads `true`; the instance `rd` takes for it reads the field through the numeric set.

#### Ablation

| ingredient removed | outcome | needed? |
| --- | --- | --- |
| `type D` | runs, prints `true` | **yes** |
| `i32` for `1 \| 2` (`type D = { v: i32 }`) | runs, prints `true` | **yes** |
| the generic reader (`print(q.v)`) | runs, prints `true` | **yes** |

#### Grading list

The annotated face `const q: { v: boolean } = { v: true }` then `rd(q)`, which refuses
`ref valtype with no interned shape` on master and must not become invalid wasm; the same with
`function mk(): { v: boolean } { { v: true } }` read through `mk().v`.
