### D15170 — a generic parameter annotated with a type parameter beside a literal member, `T | "a"`, has no union row at its instance: check-clean, refused at emit on the `is` test or the `print`

**closed · now runs, prints `t` · was a loud emit reject on a `vl check`-clean program, clause 2 · an instance's parameter whose pin is a value union with a literal member (`T | "a" | "b"` at `T := i32`) registers that union under its pin spelling and is annotated by it, as an instance return's is (D1042) (`monoRegisterPinUnion` where the clone builds its parameters, emit_mono.vl) · matrix `generic-param-literal-member-is` · fixture `unions/generic-param-literal-member-is-runs.vl` · the parameter twin of D1042 · found writing D15109 slice 2's rest-pin witness · filed 2026-11-03 against master `ea07679b5`, closed 2026-11-03**

Repro:

    function f<T>(p: T | "a" | "b") {
      if p is "a" { print("is a") } else { print("t") }
    }
    f<i32>(7)

Want:

    t

#### Mechanism

The instance's parameter type is the union instantiation mints by substituting `T` (`i32 | "a" | "b"`), and nothing registers that union's members, so the literal `is` finds no recorded members. A literal member spelled through a multi-member alias (`T | AB`) is registered and runs; a one-member alias is its literal (D15082) and refuses like the inline spelling. When another generic's `T | AB` at the same binding registers an arm for the literal, the `is` test passes and the refusal moves to the arm lookup or the `print` of the union.
