#### Mechanism

`rlElemNicheNullable`, which decides whether a ref-list element slot is a nullable niche, listed
the element codes 1, 3 to 10 and left out 11, the packed byte list, so `(u8[] | null)[]` interned
a non-null slot and the push stored a nullable value into it. It now asks `rlElemListRep`, the
decoder of D2295's `_`-less `rlElemCodeOfListRep`, so no list code can be missing from it.
The filing's analysis follows. The same program over an `f32[] | null` element prints `1.5`, as do the `i64`,
`f64` and `string` leaves (the `nullable-list-join-null-*` matrices run every container
position), so the gap is the `u8` leaf's nullable niche as a REF-LIST element: the push stores a
nullable wrapper where the list's element type is the non-null one, which reads as the element
slot being built from `u8[]` rather than `u8[] | null`.
