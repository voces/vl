### D12070 — an `is` test the emitter folds to a constant drops a call receiver's side effects

**closed 2026-10-24 with [D12060](D12060.md) · the witness prints `E`, `true`, `G`, `true`, `H`, `true` · a static `is` answer still evaluates and drops a receiver that is not a re-readable place · was check-clean silently wrong (printed `true true true`, no call ran) · clause 1 · found grading D12060's `K | string` `is string` cells · fixture `tests/cases/literal-unions/is-litunion-string-call-receiver-evaluated-once.vl` · filed 2026-10-24 against master `271b5c61e`**

Repro:

    function f(): string {
      print("E")
      "x"
    }
    print(f() is string)
    function g(): i32 {
      print("G")
      1
    }
    print(g() is i32)
    type K = "a" | "b"
    function h(): K | string {
      print("H")
      "zz"
    }
    print(h() is string)

Want:

    E
    true
    G
    true
    H
    true

#### Mechanism

`emitIsTest` asks `monoStaticIsResult` whether the answer is known from the types alone and,
when it is, emits the constant without emitting the receiver. That is right for a place and
wrong for a call, whose effects are part of the program. The fold site now emits a receiver
that is not a re-readable place and drops its value before the constant.

#### Ablation

| ingredient changed | outcome | needed? |
| --- | --- | --- |
| `const v = f()`, then `v is string` | prints `E true` | **yes** (a call receiver) |
| `f()` returns `string \| i32` | prints `E true` | **yes** (a statically known answer) |
