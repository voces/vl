### D17381 — a `.get(i) ?? d` nested in another's staged operands overwrites the outer's receiver stash

**closed 2026-11-24 · runs, prints `6` · was check-clean silently wrong · clause 1 · `vl check` rc 0 · fixed in wasmEmit.vl: `listGetStageMark` raises a staging depth for a call that stages an operand, and a nested staging `.get` stashes into its own lazy slots keyed by that depth (`listGetIdxSlotNow`, `listGetRecvSlotNow`), depth 1 keeping the eager slots; a stash read checks the depth's owner and fails loudly if a nested call overwrote it · pin: `tests/cases/lists/list-get-nested-stash-i32.vl` and its f64, string and record siblings · found by verifier V2 on lane IR-D1's PR2 (#9898) · filed 2026-11-24 against master `4a0d6ba55`, pre-existing**

Repro:

    const b: i32[] = [5, 6, 7]
    const c: i32[] = [2, 1]
    print(L(b).get(L(c).get(1) ?? 0) ?? -1)
    // PRINTS 6 (was 1)

Want:

    6

#### Mechanism

A fused `xs.get(i) ?? d` (`emitListGetOr`) stages a receiver or index that is not a re-readable
place into one per-function stash local (`listGetRecvSlot`, `listGetIdxSlot`), teed on its first
read and read again for the element. A nested staging `.get` inside the outer's operands tees its
own receiver into the same local; `listGetStageRestore` puts the outer's markers back but not the
local's value, so the outer's element read reads the inner list.

#### Ablation

| ingredient removed | outcome | needed? |
| --- | --- | --- |
| the outer receiver a call (`b.get(…)`) | runs | **yes** |
| the inner receiver a call (`c.get(1) ?? 0`) | runs | **yes** |
| the inner `?? 0` (the inner a plain `.get`) | refused at check (`i32 \| null` index) | yes |
| a third level | traps, out of bounds | no |
