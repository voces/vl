### D16937 — a record literal holding a lambda, written into a list of records of un-annotated functions with different results, is refused at emit

**loud emit reject · clause 2 (`vl check` rc 0) · found by lane AE grading D16858's neighbours · filed 2026-11-17 against master `a68eff941`**

Repro:

    function inc0(a) { return a + 1 }
    function half(a) { return a / 2.0 }
    const xs = [{ f: inc0 }, { f: half }]
    xs.push({ f: (x) => x * 3 })
    print(xs[2].f(3))
    // vl check: rc 0.  vl run: emit error, `emitProgram: a lambda field value resolved to a non-closure field slot`

Want:

    9

#### Mechanism

The list's set of named functions has two results, so the tag decision builds its records with an
id in `f`. A lambda literal written in place into such a record has no id, and the record literal's
emit finds the slot a non-closure one. A lambda bound to a name first is a member the decision tags,
and runs.
