### D4421 — a generic function passed to a hole the body calls at two types has no one instance

**closed 2026-10-17 by lane L1 with [D5611](D5611.md) · runs, prints `x 3` · was loud emit reject · clause 2 · the split plan gives the hole one parameter per argument-type key (D5611's option A) · pins: `functions/generic-fn-value-hole-called-at-two-types.vl` · filed 2026-10-13 against master `777a705a0`**

Repro:

    function same<T>(k: T): T { k }
    function take(a) {
      print(a("x"))
      print(a(3))
    }
    take(same)
    // vl check: rc 0.  vl run: emitProgram: a function-value call has no interned
    // signature — the callee has no function type to key a signature from

Want:

    x
    3

#### Mechanism

`instGenFnHolePins` (`compiler/typecheck.vl`, D4420) instances the generic only when every
call of the hole agrees; here the two calls bind `T` to `string` and to `i32`, so the hole keeps
the open signature and the emitter has no signature to key. Running needs either one instance
per call (the hole is used polymorphically, which no annotation on `a` can spell) or a
checker refusal naming that; which is a language question, not settled here.
