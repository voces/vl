### D4261 — a write through a record that a union local also holds, to a field whose type is a union, emits invalid wasm

**check-clean invalid wasm · clause 1 · the same on master `f6ee50929` with arms of different field names · found by the D4056 position generator (`over_mut_to_int`) · filed 2026-10-12 against master `f6ee50929`**

Repro:

    type A = { n: i32 | string, k: i32 }
    type B = { n: string }
    function f() {
      const s: string = "q"
      const a: A = { n: s, k: 0 }
      let w: A | B = a
      if w is A { a.n = 4 }
      if w is A { print("A") } else { print("B") }
    }
    f()
    // vl check: rc 0.  vl run: invalid module, "type mismatch: expected (ref $2), found i32; $2 is `union box`"

Want:

    A

#### Mechanism

`a.n = 4` stores into a field laid out as a union box, and the validator finds a bare value
where the box belongs. Delivering `a` into the union local `w` is what the defect needs: with
`let w: A | B = a` and the tests removed, the same store boxes its value and runs. A string
stored instead fails the same way, so it is the store's rep after the delivery, not the
literal's type.
