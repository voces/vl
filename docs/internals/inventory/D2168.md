### D2168 — assigning to a captured literal-union `let` inside a closure builds an invalid module

**check-clean invalid wasm · clause 1 · the same on master and on the D2150 branch · found by the #3056 second review · filed 2026-09-23 against master `f81d01486`**

Repro:

    type K = "zz" | "ww"
    function main() {
      let k: K = "zz"
      const set = () => { k = "ww" }
      set()
      print(k)
    }
    main()

#### Mechanism

Not yet ablated. The validator refuses `set`: `type mismatch: expected i32, found (ref $type)`.
`k` reps as the interned atom, and a captured `let` that a closure writes lives in a shared
cell, so the store into that cell lowers the member literal as a string where the cell holds
the atom id. Reading the capture (no write) runs.

#### Grading list

The same write with a `const W = "ww"` on the right (which reads as a literal-typed value and,
under the D2150 branch, is a loud emit reject naming the target instead); a captured `let k: K`
written from a nested named function; and a captured `let s: string` written the same way,
which runs.
