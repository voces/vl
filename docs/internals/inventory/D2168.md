### D2168 — assigning to a captured literal-union `let` inside a closure builds an invalid module

**closed — the boxed cell a captured `let` becomes carries the list type of its declared type, so a member written through `k[0]` lowers as the atom, and an assignment's value is an atom exactly when its target is, with the target's members to widen it by · was check-clean invalid wasm (clause 1) · the same on master and on the D2150 branch · found by the #3056 second review · filed 2026-09-23 against master `f81d01486` · closed 2026-09-23 against master `a453c09c5` with [D2170](D2170.md); a captured `let` initialised to `null` is not boxed at all, [D2172](D2172.md) · `tests/cases/closures/captured-litunion-assign.vl`**

Repro (runs, prints `ww`):

    type K = "zz" | "ww"
    function main() {
      let k: K = "zz"
      const set = () => { k = "ww" }
      set()
      print(k)
    }
    main()

#### Mechanism

Two defects. `captureBoxRewrite` turns `let k: K = "zz"` into a one-element list and every use of `k`
into `k[0]`, but the `k` it minted carried no checked type, and the element ladder the store reads
(`arrElemLitUnionTy`) resolves a closure's capture through the type of that node, not through the
maker's declaration: the store lowered `"ww"` as a string into the atom cell. The rewrite now records
the cell's list type on the `k` it mints (the read `k[0]` stays untyped, which is how
`assignTargetReReads` recognises a captured cell). Then the closure's value: `set` yields the
assignment, which is lowered as a re-read of the atom cell, while `exprIsLitAtom` had no assignment
arm, so the `string` result took the raw id. The assignment arm, and `litAtomMemberTy` reading the
members off the target rather than the right-hand side's one literal, let `emitReturnValue` and a
caller's `print` widen it; a named function writing a module global takes its members from its
returned expression when its checked result is the wider `string`.

#### Ablation

| ingredient removed | outcome | needed? |
| --- | --- | --- |
| the write inside the closure (a read only) | runs | **yes** |
| the literal-union annotation (`let k: string`) | runs | **yes** |
| the closure, with `k` a module global | runs | **yes** |
| the closure's value, `set` declared `(): void` | invalid wasm (the store alone) | no |
| a lambda, with a nested `function set()` instead | invalid wasm | no |
| the named alias, with the inline `"zz" \| "ww"` | invalid wasm | no |

#### Grading list

All in the fixture: the value printed and bound as `string`, a nested named function, a `const`
member and a `K` parameter on the right (both previously a loud refusal), the inline member set,
a second closure reading the cell, a compare after the write, a module block, a generic frame at two
types, and a module global written by a function whose value is printed.
