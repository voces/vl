### D5380 — a generic instance pinned at a struct-field read carries a union spelling with no row or pool set

**runs today and must keep running · the member-set pool has no set for the pin, so `sharedUnionFieldPlan` reads the receiver's atoms only by splitting the spelling text · found by lane L6 measuring the `sharedUnionFieldPlan` pool-miss arm (46 of 15,565 fixture and corpus files reach it: 45 with a one-atom narrowed set, where the plan declines either way, and this one with two atoms) · filed 2026-10-17 against master `15bd386db`**

Repro:

    type A = { kind: "a", v: f64 }
    type B = { kind: "b", v: f64, n: i32 }
    type S = A | B
    function mk(b: boolean): S {
      if b { return { kind: "b", v: 1.5, n: 4 } }
      { kind: "a", v: 2.5 }
    }
    const box = { it: mk(true), jt: mk(false) }
    function show(p) {
      print(p.kind)
      print(p.v)
      if p is B { print(p.n) }
    }
    show(box.it)
    show(box.jt)

Want:

    b
    1.5
    4
    a
    2.5

#### Mechanism

The un-annotated `p` is pinned from the checker's type of the projection `box.it`, and that
pin is spelled as the structural render `{kind:string,v:f64}|{kind:string,v:f64,n:i32}`, not
as `S`. No union row is bound to that spelling and `msSetOfUnion` returns -1, so in
`sharedUnionFieldPlan` (`emit_classify.vl`) `msMemberAtomsOfSet` misses and
`unionSetAtomsOf` splits the text. That split is load-bearing: a compiler that declines on
the miss refuses `p.kind` with `field access receiver is not a struct`. Close at the pin
producer, by minting the row keyed by member atoms or by pinning at the declared name, and
then retire the miss arm.

#### Ablation

| ingredient removed | outcome | needed? |
| --- | --- | --- |
| the projection (`show(mk(true))`) | pin is `S`, pool hit | **yes** |
| annotating `p: S` | pin is `S`, pool hit | **yes** |
| the record carrier (a list element `xs[0]`) | pool hit | **yes** |
| annotating the carrier (`const box: { it: S }`) | still misses | no |
