### D2832 — a generic if-join of two DIFFERENT list types takes one arm's list rep for the join, so the other arm is delivered into the wrong list

**closed 2026-09-27 · now a loud check reject at the call, in the concrete spelling's words (`field 'length' is not on every member of string[] | f64[]`) · was check-clean invalid wasm, clause 1, on master `9f11c9c9f` · found by the #3215 round-2 review (`rv3215g/p3/a4.vl`, `b6.vl`, `c1.vl`) · filed 2026-09-27 · fixtures `tests/cases/generics/if-join-two-list-types-union.vl`, `error-if-join-two-list-types.vl`, `error-if-join-two-list-types-at-pin.vl`**

Repro:

    function no(): boolean { false }
    function f<T>(xs: T[], ys: string[]) { const r = if no() { ys } else { xs }; print(r.length) }
    f([1.5], ["a", "b"])
    // vl check: rc 0.  vl run: invalid module inside `f` — expected (ref $type), found (ref $type)

#### Mechanism

At the pin `T = f64` the arms are `string[]` and `f64[]`, two list types, while the generic body
was checked with the join collapsed to one list, so `r.length` passed and the emitter built one
arm's rep. The close keeps master's collapse for the body and records every if or `match` join
the return-set rule (#3211) would keep apart. Each call re-joins it at its bindings; where the
join stays a union of lists, the callee's body is re-checked at the pinned parameter types
(`tpIfRecheck`), so a one-list read is refused at the call in the concrete spelling's sentence,
and a returned value is held to the call's type. A join is built as the union box only where it
is bound to a `const`/`let` (the instance annotates the binding with the pinned union,
`monoApartJoinAnn`), assigned, passed, returned or discarded; anywhere else it is refused at the
call (D2833). A re-check that finds a node the instance would build at the template's one-list
type is refused too. A generic caller parks the join and re-asks it at its own pin. The binding
of a join whose concrete list absorbed the parameter's (`if c { ys } else { xs }`) takes the
parameter's list, so its reads name the parameter, unless the concrete list holds numbers or
booleans.
