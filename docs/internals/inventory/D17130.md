### D17130 — a `null`-typed binding joined with a record by a value `if` leaves the join's type `_ | null` open, so its non-null arm reads as null

**closed 2026-11-24: `joinTysAcc` joins an open inferred-null hole beside a concrete `T` to `T | null`, the hole left unfilled (`openNullHoleJoin`); no consumer reads the record arm as null now, two refuse loudly ([D17200](D17200.md), [D17201](D17201.md)) · was check-clean silently wrong · clause 1 · found by IR-N4 locating D17124 · filed 2026-11-24 against master `84768d9e`**

Repro:

    type In = { v: i32 }
    const n = null
    const rec: In = { v: 9 }
    function c(f: boolean) { return (if f { n } else { rec }) == null }
    print(c(false))
    // PRINTS true

Want:

    false

#### Mechanism

A binding whose initializer is a bare `null` has the null-hole type `_ | null`. Joining it with a
record arm leaves the hole open: the `if`'s type is `_ | null`, not `In | null`, so its rep is
`nulnone` (the `null` unit). Every consumer that reads the join's own type treats the record arm's
value as null. D17124 is this join's invalid-wasm face, at an annotated `T | null` destination with
the binding in the then arm; the emitter's fix there takes the record arm's row, and leaves this
root open.

#### Ablation

| consumer of `if f { n } else { rec }`, run with `f = false` | outcome |
| --- | --- |
| `== null` | wrong, `true` (want `false`) |
| the binding on the else side, `== null` | wrong, `true` |
| `(…) ?? { v: 5 }` then `.v` | wrong, `5` (want `9`) |
| `(…)?.v ?? -1` | wrong, `-1` (want `9`) |
| `print(…)` | wrong, prints nothing for the record |
| an un-annotated `const a = …`, then `a == null` | wrong, `true` |
| a call argument at an `A \| B \| null` parameter, `{ a: 1 }` arm | wrong, `== null` is `true` |
| an annotated `const a: In \| null = …` (with D17124's fix) | right |
| the arm `null` literal in place of `n` | right |
| `const n: In \| null = null`, the binding typed | right |
