### D3327 — a generic that returns an inner `let x = w` while an outer `let x` holds another type is refused at emit

**loud emit reject · clause 2 · found by #3307's review, present on master before it · the same on master `b6378e95b` · filed 2026-09-30 against master `b6378e95b`**

Repro:

    function g<T>(w: T) {
      let x = 7
      if true {
        let x = w
        return x
      }
      w
    }
    const r1 = g({ a: 1, b: "r" })
    print(r1.b)
    // vl check: rc 0.  vl run: emitProgram: field access receiver is not a struct

Want:

    r

#### Mechanism

Not traced. The returned `x` appears to read as the outer `let x = 7`, an `i32`, so `r1.b` finds a
scalar where the pin says a record. The non-generic spelling runs, and so does a generic whose
argument is an `i32`, where both bindings share a type.

#### Ablation

| ingredient changed | outcome | needed? |
| --- | --- | --- |
| `g` not generic, `w: { a: i32, b: string }` | runs, `r` | **yes** |
| the outer `let x = 7` removed | runs, `r` | **yes** |
| the inner `let x` renamed `y` | runs, `r` | **yes** (the same name) |
| `return w` instead of `return x` | runs, `r` | **yes** (the returned binding is the inner `x`) |
| the outer `let x` a record of `w`'s own type | runs, `r` | **yes** (a different type) |
| the outer `let x` a `string` or a list | still refuses | no |
| the parameter a bare hole, `g(w)` | still refuses | no |
| `let x: T = w` annotated | still refuses | no |
| a `g(3)` or `g("s")` argument | runs | **yes** (a record argument) |
| a `g([1, 2])` argument | invalid wasm at the top level (`expected (ref null $type)`) | no |
| the `return x` removed, the block only prints `x.b` | runs | **yes** |
