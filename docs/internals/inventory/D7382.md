### D7382 — a generic function delivered into two bindings of one annotated function type compares unequal

**runs but wrong value · `vl check` rc 0 · clause 1 · under the [D7180](D7180.md) ruling a function value's identity is its declaration and captures, so `p == q` is `true` · the non-generic `two(x: i32)` prints `true`, and so does `q` initialised from `p` · found probing [D7180](D7180.md)'s ruling · present on master `622d88f2c` · filed 2026-10-19 against master `622d88f2c`**

Repro:

    function two<T>(x: T): i32 { return 1 }
    const p: (x: i32) => i32 = two
    const q: (x: i32) => i32 = two
    print(p == q)
    // vl run: prints false

Want:

    true

#### Mechanism

Each annotated binding delivers `two` through a forwarder of its own (`p@2`, `q@3`, each a
`return_call $two`), and a closure's identity token is its wasm function index, so the two
forwarders differ. The fix keys the forwarder by the declaration and the binding's function
type, or compares by the declaration the forwarder wraps.
