### D2781 — `is` against a record whose field union is spelled in another member order is refused at emit

**closed 2026-11-04 by lane column-G1 · runs, prints `true` · was loud emit reject, clause 2, the pattern named no union variant · found by #3208's review (item 4) · filed 2026-09-27 against master `f6db92e0d`**

Repro:

    const r: {a: string | i32} = {a: 1}
    const w: {a: string | i32} | string = r
    print(w is {a: i32 | string})
    // vl run: true. Was: emitProgram: `is` names a type that is not a union variant

#### Fix

The checker owns which receiver member a pattern names. `checkIsExprNode`
(`compiler/check_operators.vl`) banks at the `is` node, where the receiver is a union and the
pattern is one of its members spelled another way (each assignable to the other, no member
equal to it), that member's own arena index (`isRecvMemberOf`). Every emit reader of the test
then finds the member exactly. `isPatUnionArmTy`'s map arm stays: it also treats a `Set<K>` and
its boolean map as one member (D2673), which mutual assignability does not, and
`pin-exact-key-nested-set-map.vl` reads `false` without it.
`tests/cases/unions/is-record-field-union-other-member-order.vl`, the two
`is-record-field-union-other-member-order` matrix templates and the named set
`d2781-is-member-order` hold the shapes.

#### Mechanism

The checker accepts the pattern, since a record's field union is one type in any member order.
The emitter looks the pattern up as a variant by its spelling, finds `{a:i32|string}` among no
registered rows (the union registered `{a:string|i32}`), and refuses. The generic spelling at a
`T | null` niche runs since #3208 (D2753), where the exact pin answers; a box has to find the
variant row. A close resolves the pattern to the row whose type is `tySameSet` with it, as
`isPatUnionArmTy` does for maps.
