### D2444 — an unused `boolean | null` record field breaks another function through an inferred boolean-or-record return

**closed 2026-10-03 by D3593 — the witness prints `true` · was check-clean invalid wasm, clause 1 · found in review of #3148, the same on master `a20d69104` · filed 2026-09-25 against master `a20d69104`**

Repro:

    type A = { r: i32 }
    function mkA(): A | null { return { r: 1 } }
    type R = { f: boolean | null }
    function rr(c: boolean) { if c { return true } return { r: 7 } }
    print(rr(false) is A)
    // vl check: rc 0.  vl run: invalid module, inside `mkA`:
    // "type mismatch: expected (ref null $type), found (ref $type)".  Expected: true

Want:

    true

#### Mechanism

D3593's: `rr`'s inferred return is recorded as `boolean|A`, the anonymous `{ r: 7 }` named by
the declared `A`, so the emitter made `A` an arm while the checker's arena kept it a plain
record, and `mkA`'s `A | null` result and its `return { r: 1 }` were classified by the two
different registries. Closed by registering the declared twin in the arena; the emitter half
of D3593's change alone leaves it invalid.
