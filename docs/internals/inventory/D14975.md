### D14975 — a hole callee's push through the result of calling its parameter does not pin the argument function's open list

**closed · runs, prints `s` · was loud emit reject, `vl check` rc 0, clause 2 · closed by giving a hole argument's open list the callee's write at the program's end, as a pending binding's list takes it at scope close (`pinCalleeWrittenLists`) · filed 2026-11-02 against master `a6a876cff`**

Repro:

    function take(a) {
      const m = a(2)
      m.push("s")
      print(m[0])
    }
    take((x: i32) => [])
    // vl check: rc 0.  vl run: emitProgram: monomorphize: unsupported argument type for `a` in a call to `take`

Want:

    s

#### Mechanism

The push is a deferred element constraint on `m`, the derived hole for the result of calling
`a`. At the call it is replayed against the lambda's open list, but a list reached through a
value's type is pinned only when written at the call itself; otherwise it is queued as a
callee write for a pending binding, and an argument is no binding. The map twin is pinned
by `holeKidMapDemands`.

#### Ablation

| ingredient removed | outcome | needed? |
| --- | --- | --- |

| the inline lambda (`const g = (x: i32) => []`, `take(g)`) | still refuses | no |
| the list (`Map()`, `m["k"] = "s"`) | runs | **yes** |
