### D15750 — a record stored into a union keeps its identity, because a union arm's record type is laid out as the variant row

**runs today and must keep running · a refutation pin for laying an arm's record type out as a plain struct and boxing it at the union store · found by lane w321 · filed 2026-11-11 against master `1d517770`**

Repro:

    type Ca = { r: i32 }
    type Sq = { s: i32 }
    type Sh = Ca | Sq
    const a: Ca = { r: 1 }
    const s: Sh = a
    a.r = 5
    if s is Ca { print(s.r) }
    const xs: Sh[] = [a]
    a.r = 6
    const e = xs[0]
    if e is Ca { print(e.r) }
    // vl run: prints 5 then 6

Want:

    5
    6

#### Mechanism

`repOfTy`'s `TyObj` arm answers `variant` when `repTyIsVariant(ty)` holds. That is the case
when the checker's union-member set holds the type (`tyIxIsVariantMember`) or the variant table
holds its shape. So `Ca` is laid out as `Sh`'s variant row wherever it is stored. Storing `a`
into `s: Sh` or into a `Sh[]` element copies nothing: the union holds the same reference, and a
later write through `a` is seen through `s` and `e`. If `Ca` repped as a plain struct and the
union store boxed it by copy, both reads would print `1`.

#### Ablation

The first print, by ingredient:

| ingredient removed | first print | needed? |
| --- | --- | --- |
| the write `a.r = 5` after the store | `1`, under either layout | **yes** |
| the union store (`const s: Ca = a`) | `5`, under either layout | **yes** |
