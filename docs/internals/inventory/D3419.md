### D3419 — a `??` over a list cell a write narrowed to non-null, read inside a closure, builds invalid wasm

**closed 2026-09-30 — the witness prints `7` · was check-clean invalid wasm, clause 1, pre-existing on master `c00198389` · found by lane NW's `nw/g2` grid · filed 2026-09-30 against master `5e277ab52`, closed against master `47aa2950b` · fixture `tests/cases/closures/closure-reads-cell-at-checker-narrowing.vl` · [D3438](D3438.md) closed by the same change**

Repro:

    const g: (i32 | null)[] = [null]
    g[0] = 7
    const h = () => g[0] ?? 0
    print(h())
    // vl check: rc 0.  vl run: the emitted module failed to validate

Want:

    7

#### Mechanism

The emitter carries a narrowing of a place under a capture into the closure's body whole
(`capNarrowReplays`), so the closure reads `g[0]` unboxed as `i32`, while the checker types the
read at the cell's declaration, `i32 | null`, and the `??` lowering reads it as nullable. A fold
that trusts the replayed narrowing is wrong: a write after the closure is made (`g[0] = null`,
or one inside another closure) ends it, and the fold then traps with a cast failure, where a
bare name reads the capture at its declaration and prints the default. The fix is the name's
discipline for a cell: a closure inherits no cell narrowing a later write may end. The same
replay is why D3240's pin-landed read stops at names and fields.

#### Ablation

| ingredient changed | outcome | needed? |
| --- | --- | --- |
| `print(g[0] ?? 0)` outside the closure | prints `7` | **yes** |
| `const h = () => g[0]` | prints `7` | **yes** (the `??` or a null test) |
| a field `q.s` in place of the cell | prints `7` | **yes** (a list cell) |
| a bare name `let s` in place of the cell | prints `7` | **yes** |
| `g[0] = null` after the closure, `string` cell | traps | no (the same replay) |

#### Close

The emitter now replays into a nested body exactly the path narrowings the checker kept there.
Where the checker drops a captured path narrowing (`crPathCaptureLost`: a narrowing a write made,
or any narrowing under a function that escapes), `crNoteLostRead` banks the key in the body's
`capWidenOf` set, and `capNarrowRecord` records no replay for a banked key. So a closure reads a
cell a write narrowed at its declared type, as the checker typed it, and a later `a[0] = null`
reads as the default. This is the name's discipline applied to cells: the checker's answer,
not the emitter's stack, decides what the nested body inherits.

The same replay made three more shapes invalid wasm or a trap on master, all now right: a guard
narrowing of a cell under a closure that escapes (returned, or stored in a `let`) and then read
after `xs[0] = null` (`() => xs[0] ?? 0` prints `0`, the `string` cell prints the default), and
D3438's `q.s == null` inside a closure over a written field (prints `false`).
