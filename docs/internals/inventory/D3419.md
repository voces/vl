### D3419 — a `??` over a list cell a write narrowed to non-null, read inside a closure, builds invalid wasm

**closed 2026-09-30 · was check-clean invalid wasm, clause 1, on master `5e277ab52` · found by lane NW's `nw/g2` grid, where the type-parameter spelling reached it once D3240's instance kept its write's narrowing · filed and closed 2026-09-30 · fixture `tests/cases/lists/closure-coalesce-narrowed-cell.vl`**

Repro:

    const g: (i32 | null)[] = [null]
    g[0] = 7
    const h = () => g[0] ?? 0
    print(h())
    // vl check: rc 0.  vl run: the emitted module failed to validate

Want:

    7

#### Mechanism

The emitter carries a narrowing of a place under a capture into the closure's body whole
(`capNarrowReplays`), so the closure reads `g[0]` unboxed as `i32`; the `??` lowering asked that
narrowing only of a bare name, and lowered the cell as a nullable read of the `i32` it had just
produced. A list cell the emitter's narrowing holds non-null now reads as the operand, as a name
does.

| a field `q.s` in place of the cell | prints `7` | **yes** (a list cell) |
