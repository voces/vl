### D16791 — a maker's hole lambda delivered at a closed function type inside a generic or hole-parameter function keeps the lambda's own result and traps

**closed · runs, prints `0.5` · was loads then traps · `vl check` rc 0 (one unused-parameter warning), `wasm trap: indirect call type mismatch` · clause 1 · the in-instance face of [D16753](D16753.md) beside [D16780](D16780.md) · found auditing the instanced-body maker-call guard · filed 2026-11-16 against master `a9ae9324a` · fixed by lane INIT on lane SOUND's trace: the instanced-body guard retires, since a maker call's result is one per node and every instance builds the same twin; the call search reads a call typed in an instance that runs the one it is under, or the base a wide twin is built from (`elabKeyRunsDlv`, `ekTwinBase`), so the twin's lambda takes its parameter from the delivery · fixture `closures/maker-lambda-delivered-inside-instanced-body.vl`**

Repro:

    function deliver() { return (a) => a + 1 }
    function wrap<T>(x: T) {
      const w: (a: i32) => f64 = deliver()
      return w(3) / 8.0
    }
    print(wrap("s"))
    // vl check: rc 0.  vl run: wasm trap, indirect call type mismatch

Want:

    0.5

#### Mechanism

The checker notes the maker call `deliver()` at `(a: i32) => f64` (`elabMakerCallSig`), but inside
an instanced body `monoWalkIdentCall` skips the maker twin (`shared`, the instanced-body guard), so
the call keeps the root `deliver`, whose lambda returns `i32`. Turning the guard off alone does not
run it: the twin then takes the template's slot (`first`) and the call still names the root, as in
[D16780](D16780.md)'s trace. The guard covers no other program: with it off, 4,251 distilled cells
and closure and generic cases build byte-identical.

#### Ablation

| ingredient changed | outcome | needed? |
| --- | --- | --- |
| `wrap(x: string)`, annotated, not instanced | runs, `0.5` | **yes**: an instanced body |
| `wrap(x)`, a hole parameter | the same trap | no: generic or hole |
| a second instance, `wrap(1)` beside `wrap("s")` | the same trap | no |
| the delivery at module scope | runs, `0.5` | **yes** |
| delivered at `(a: i32) => i32` | runs, `4` | **yes**: a result the lambda does not give |
