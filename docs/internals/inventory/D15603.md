### D15603 — a capturing nested function of a CLOSED encloser, handed to two parameters of one type parameter each called at its own type, gets no joined bundle

**loud emit reject · clause 2, `vl check` rc 0, then `emitProgram: monomorphize: a generic function handed to two parameters of type `F` in a call to `mid` is called at two types, and `F` takes one` · D15598's and D15599's neighbour · filed 2026-11-09 against master `ee306138`**

Repro:

    function mid<F>(a: F, b: F) {
      print(a("x"))
      print(b(2))
    }
    function outer(u: i32) {
      function same(k) {
        print(u)
        k
      }
      mid(same, same)
    }
    outer(7)

Want:

    7
    x
    7
    2

#### Mechanism

`elabBundleForwardsJoin` (emit_elab.vl) walks only the bodies of elaboration instances
(`ekDecl`). A closed `outer` is none, so the call `mid(same, same)` in it never reaches
`elabBundleSiblingsUnite`, and the two parameters' single signatures are never joined. The same
program with `outer<U>(u: U)` runs (D15598). Not yet traced past the walk.

#### Ablation

| ingredient changed | outcome | needed? |
| --- | --- | --- |
| `outer<U>(u: U)`, a generic encloser (D15598) | runs | **yes** |
| `a` called at both types, `print(a(2))` added | runs | **yes**, `a` alone is a bundle |
| `same` captures nothing | runs | **yes** |
| `function same<T>(k: T): T` | the same refusal | no |
