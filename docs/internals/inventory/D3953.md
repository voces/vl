### D3953 — a capture cell in a generic body written with a generic function by a closure the instances share is refused

**closed 2026-10-13 by lane SC · runs · was loud emit reject · pins: `tests/cases/closures/capture-cell-written-with-generic-by-shared-closure.vl` · found in review of #3498 (`rv3498/v09`, `v05`–`v07`, `v10`, `v12`, `u02`, `u13`, `u17`) · filed 2026-10-10 against master `429e7b093`**

Repro:

    function inner<U>(u: U) { print("I"); print(u) }
    function other<V>(v: V) { print("O"); print(v) }
    function a<T>(x: T) {
      let k = inner
      const toO = () => { k = other }
      toO()
      k(x)
    }
    a(1)
    a(true)
    // vl check: rc 0.  vl run: emitProgram: the captured binding `k` is written with a function inside a closure that every instance of the enclosing generic function shares

Want:

    O
    1
    O
    true

#### Mechanism

A capture cell's element store `k[0] = other` recorded its delivery but never instanced the
written generic, and a call through the cell, whose rewritten callee `k[0]` has no recorded type,
took no type at all; each instance of the enclosing generic needs `other` at the cell's type as
that instance spells it. Closed by lane SC (fn-value-flow §(f) step 3): `monoWalk`'s Index arm
coerces the stored value at the element's type, and `monoCellCall` reads the cell's type at the
instance's bindings (`monoCellFnTyNameAt`). The Index-arm coercion is the one this row needs:
removing it alone restores the refusal. A written generic already instanced at another type is
still refused (D4305).
