### D3953 — a capture cell in a generic body written with a generic function by a closure the instances share is refused

**loud emit reject · clause 2 · found in review of #3498 (`rv3498/v09`, `v05`–`v07`, `v10`, `v12`, `u02`, `u13`, `u17`) · filed 2026-10-10 against master `429e7b093`**

Repro:

    function inner<U>(u: U) { print("I"); print(u) }
    function other<V>(v: V) { print("O"); print(v) }
    function a<T>(x: T) {
      let k = inner
      const toO = () => { k = other }
      toO()
      k(x)
    }
    a(1)
    a(true)
    // vl check: rc 0.  vl run: emitProgram: the captured binding `k` is written with a generic function inside a closure that every instance of the enclosing generic function shares

Want:

    O
    1
    O
    true

#### Mechanism

The writer `toO` names no `T`, so it is lifted once and that one body serves the `i32` and
`boolean` instances of `a` (the two share a representation); its write `k[0] = other` can hold
one instance of `other`, and each instance's cell wants its own. D3939 refuses the program when
one write node is asked for two function types (`monoCellSigRecord`, `monoCellWriterSigFail`) rather
than writing one instance into every cell, which printed `O true O true`. Running it needs the
writer instanced per enclosing instance.
