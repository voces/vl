### D12330 — a list of a generic whose element is written a lambda, called through the element at two types, refuses at emit

**closed 2026-11-02 · runs, prints `t` then `1` · was loud emit reject, `emitProgram: a list holding a generic function is called through its elements at more than one type, so its elements have no one instance`, `vl check` rc 0 · clause 2 · found closing D12238's residue · filed 2026-10-24 against master `84941745b` · closed by W-lam slice 1: a lambda member beside a declared one is the set's leaf in the check's own decision, so `{pick, lambda}` is tagged and each call's arm is instanced by the elaboration at its arguments (`ftDeclaredBeside`, check_fn_tag.vl)**

Repro:

    function pick<A, B>(a: A, b: B): A { a }
    const fs = [pick]
    fs[0] = (x, y: string) => x
    print(fs[0]("t", "u"))
    print(fs[0](1, "s"))

Want:

    t
    1

#### Mechanism

The lambda `(x, y: string) => x` keeps a hole for `x`, so each call through the element needs its
own instance of the written lambda, as it does for the generic. The `let` spelling gets one
instance per call type; the list floor in the monomorphizer wants one instance for every element
of a list and refuses when the element calls disagree. The program is well-typed: each call fits
the lambda at its own type, and the checker passes it correctly.
