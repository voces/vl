### D3059 — a written record list passed to a `readonly Shape[]` parameter, or stored into a `readonly Shape[]` module binding, is refused at emit

**loud emit reject · clause 2 · the record twin of [D3042](D3042.md) · found by the #3266 review · the same on master `b09566e16` · filed 2026-09-28 against master `b09566e16`**

Repro:

    type Circle = { r: i32 }
    type Sq = { s: i32 }
    type Shape = Circle | Sq
    function rd(r: readonly Shape[]): i32 { return r.length }
    const l: Circle[] = [{ r: 1 }]
    function grow() { l.push({ r: 2 }) }
    grow()
    print(rd(l))
    // vl check: rc 0.  vl build: emitProgram: covariant list delivery: a Circle[] cannot be
    // delivered into a Shape[] here.

Want:

    2

#### Mechanism

`emitRefListWidenSite` declines the copy because `covarValueWriteState` sees `l` written. Since
[D3041](D3041.md) a declined delivery into a `readonly` destination is built as a view, but only
where the checker recorded it (`noteRefListView`), and that note skips a root `covarRootFreshLocal`
calls fresh: a `const` bound to a list literal. That is the root the copy serves when nothing
writes it, not one that no view can serve. [D3042](D3042.md) is the scalar twin, closed by making
the scalar site build a view for any named root the analysis sees written. The module-binding
store `function st(x: Circle[]) { keep = x }` into `let keep: readonly Shape[]`, then
`l.push(...)` after `st(l)`, is refused the same way.

#### Ablation

| ingredient changed | outcome | needed? |
| --- | --- | --- |
| no write to `l` | runs, prints `1` (the copy is licensed) | **yes** |
| the store into a `readonly Shape[]` module binding instead of an argument | same refusal | no (position) |
| `l` delivered through a callee's `return xs` | runs, the view | **yes** (a fresh literal root) |

#### Grading list

D3041's write-after-view grid with a fresh `const` root at every read, and the store position.
