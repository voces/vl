### D15801 — a call through a function field of a list's records whose functions return different types is refused at check where the read is not a plain one of one literal's list: written to a map or a binding, handed to a callback or a parameter, or nested in a record

**loud check reject · `cannot write 'half' to 'm[][].f': called at (i32) it returns f64, where 'inc0', also written to it, returns i32 — every function a call through 'm[][].f' may run must return one type` · clause 2, the judgment [D15791](D15791.md) lifted for a list's own initialiser · open · found closing D15791 (its position matrix, `record-list-fn-field-two-results.matrix.vl`) · filed 2026-11-12 against master `0921d19fd`**

Repro:

    function inc0(a) { return a + 1 }
    function half(a) { return a / 2.0 }
    const m = Map()
    m["k"] = [{ f: inc0 }, { f: half }]
    const v = m["k"]
    if v != null { print(v[1].f(3)) }

Want:

    1.5

#### Mechanism

`holeSlotJudge` lifts its one-result judgment for a place through an element when the list
holds only its initialiser's functions (D14435's `nW == 0`, or a widening lift). A map entry
written with the list, or a `let` the list is written to after its initialiser, counts the write.
The judge then asks every function stored there for one result, and refuses. For the reassigned
`let`, the refusal is a different one: a delivery at `(i32) => i32` whose conversion is refused.
