### D15801 — a call through a function field of a list's records whose functions return different types is refused at check where the read is not a plain one of one literal's list: written to a map, handed to a callback or a parameter, a record nested in its element, or a list a record holds walked by a loop

**loud check reject · `cannot write 'half' to 'm[][].f': called at (i32) it returns f64, where 'inc0', also written to it, returns i32 — every function a call through 'm[][].f' may run must return one type` · clause 2, the judgment [D15791](D15791.md) lifted for a list's own initialiser · open · found closing D15791 (its position matrix, `record-list-fn-field-two-results.matrix.vl`) · filed 2026-11-12 against master `0921d19fd`**

Repro:

    function inc0(a) { return a + 1 }
    function half(a) { return a / 2.0 }
    const m = Map()
    m["k"] = [{ f: inc0 }, { f: half }]
    const v = m["k"]
    if v != null { print(v[1].f(3)) }

Want:

    1.5

#### Mechanism

`holeSlotJudge` lifts its one-result judgment for a place through an element when the list
holds only its initialiser's functions (D14435's `nW == 0`, or a widening lift). A map entry
written with the list counts the write, and the judge then asks every function stored there for
one result, and refuses. A field through an element of a written binding is lifted as its
initialiser's is, since the call dispatches on the set every write joins; a map value is not, and
with the judgment lifted its emitter has no shape for the set (`ref valtype with no interned
shape`).

#### The map-value family

The witness's family. Lifting the judgment is not enough: the emitter cannot yet build the set
through a map value. Measured on scratch compilers whose `holeSlotJudge` passes `holesApart` for
every slot read (`build/` untouched), against master `9b77c2907`:

* The tag decision does tag the set. A trap in `ftCommit` fires for the witness, and for neither
  `print(1)` nor a one-result list of records.
* The emit gaps, in the order they surface:
  1. `fnTagPlaceRep` (check_elab_cap.vl) reads an index step on a map rep as a list element
     (`tyArrayElemIx`, -1), so `const v = m["k"]` gets no stamp. Nor does a step through a
     narrowed `| null`.
  2. `ftHoldKind` (check_fn_tag.vl) answers 0 for a `TyNullable`, so a binding of a map read,
     `{ f }[] | null`, is not a planned holder. A trap in `fnTagHeldNote` for `v` never fires.
  3. `collectAHeldRep` (emit_collect.vl) interns a held map's value row and mv slot for a record
     value only, not a list of records.
* With all three patched, two failures remain. The witness, global or function-local, is a loud
  emit reject, `ref valtype with no interned shape` (`fbValtypeNullable` from
  `emitGlobalSection` for the global). The `m.set("k", [ … ])` spelling is
  `unsupported map value type` at the map's construction.
* A map holding the records directly, `m["a"] = { f: inc0 }`, builds an invalid module under the
  same lift: [D15806](D15806.md), a refutation pin.

The patches were probes, uncommitted and unmeasured. Gap 1: the walk back out of
`fnTagPlaceRep` peels a `TyNullable` before each step and reads an index step on a `TyMap` as
its value, `| null` on the read's last step. Gap 2: `ftHoldKind` answers a `TyNullable` its
inner kind when that is 4 or 6. Gap 3: `collectAHeldRep` peels the held rep's `| null` before
its list rungs, and for a map whose value is a list of records calls `internShapeDeepOfTy`,
`forceListLeafRepsOfTy` and `mvShapeOfMapHeldTy` on the value, as it does for a record value.
