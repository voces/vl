#### Mechanism

Not traced. From the ablation only: `c` called at one type and also listed takes two lanes in
the split (`fsLetSplitKeys`, fn_split.vl, D9594), one per call key and one for the listed
value. With `c` called at two types the program runs, so the lane the listed read takes seems
to be the one no call reaches when the direct calls share one key.
