### D3179 — a record argument a declared record claims by its field names cannot bind a record-pattern generic's type parameter

**closed 2026-10-05 by lane C2 with [D3674](D3674.md) — the witness prints `m` · was a loud emit reject, clause 2 · 28 cells of lane RF2's pattern grid (`rf2-g2`, every `T := string` cell with `type D` declared) · filed 2026-09-29 against master `995bbc74e` · fixture `tests/cases/generics/record-pattern-arg-claimed-by-declared-name.vl`**

Repro:

    type D = { m: string, n: i32 }
    function g<T>(b: { m: T, n: i32 }, d: T): T { if b.n > 100 { d } else { b.m } }
    print(g({ m: "m", n: 0 }, "d"))
    // vl check: rc 0.  vl build: monomorphize: unsupported argument type for `b` in a call to `g`

Want:

    m

#### Mechanism

The literal `{ m: "m", n: 0 }` has exactly `D`'s field types, so its pin is the declared name
`D`, and `monoBindFromAnn` has no fields to match the pattern `{ m: T, n: i32 }` against a bare
name: `T` stays unbound and the substituted pin is empty. An `#anonN` pin avoids this by
matching the pattern against the argument's spelled shape (`monoAnnPinName(tyToEmitName(…))`),
which a declared-name pin never reaches. Spelling `D` by its fields before the bind
(`tyToStructStr`) moves the refusal one layer on, to `only i32, i64, f64, f32, boolean, struct,
union, array, or string parameters are supported`, so the substituted shape also needs to name
`D`'s row; lane RF2 stopped there after one round.
