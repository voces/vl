### D15827 — a field read off a record literal's binding built wider, handed on at the read's own type, hands on the wider record

**closed 2026-11-12 · now a loud check reject by the shared-record contract, as D15825's call spelling is · was check-clean invalid wasm, clause 1 · the literal spelling of [D15825](D15825.md): the binding's held record is the one the record solve builds it at in this pass (`recBuildPassAt`, read by `storeBindingHeldAt`), so `storeReadsOwnResolve` judges the read · fixture `tests/cases/soundness/field-read-off-wider-built-literal-binding.vl` · found grading D15825 · the same on master `96df041b7`**

Repro:

    type J = { f: i32 | null }
    type K = { j: J }
    const y = { j: { f: 4 } }
    const ks: K[] = [y]
    const w: { f: i32 } = y.j
    print(w.f)
    // vl check: rc 1 — this field read holds a J, as the record it is read from is built wider
    //   than its own type, and it is handed on here as {f: i32} … a record is shared, not copied
    // (was: vl run invalid module — expected (ref null `{f:i32}`), found (ref `J`))

The refusal above is the contract's. Handed to `function own(q: { f: i32 }) { q.f }`, `own(y.j)`
prints `4`.

#### Mechanism

`y` holds a literal, so the record solve builds it at `K`, where it is delivered (`recBuildPush`),
and it keeps its own type. Because `y` is a `const` of a literal, `y.j.f` is narrowed to `i32`, so
`y.j` reads as `{f: i32}` and is accepted where that is declared, while it holds a `J`. D15825's
judgement reads a binding's held record from the store column, which records calls; a literal's
build was not there until the solve's pass end, so the read went unjudged.

#### Ablation

| `J = { f: i64 }` | refused by the pin, `cannot assign J to 'w'` | **yes** (the null's narrowing) |
