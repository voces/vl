### D16571 — a list literal holding a record of a generic function name, spread into a push in a generic body, is built at one instance only

**closed 2026-11-16 · runs, prints `3` `ab` · was check-clean invalid wasm, `type mismatch: expected (ref $type), found i32` · clause 1 · found beside [D16235](D16235.md) · filed 2026-11-15 against master `4b8e8d264` · fixed by `checkListPushArgs` typing the shared spread literal only in the generic body's own check (an instance's re-check had left the last instance's `{f: (string) => string}[]` on it), and by `monoNotePushDeliveries` delivering a spread literal's elements at the list's element per instance · residue [D16695](D16695.md) (the spread binding), [D16696](D16696.md), [D16697](D16697.md) · fixture `generics/generic-body-spread-push-record-of-generic-fn-two-instances.vl`, matrix `generic-body-spread-push-record-of-generic-fn-per-instance.matrix.vl`**

Repro:

    function id<T>(x: T): T { return x }
    function run<T>(x: T) {
      const rs: {f: (x: T) => T}[] = []
      rs.push(...[{ f: id }])
      return rs
    }
    print(run(3)[0].f(3))
    print(run("ab")[0].f("ab"))
    // was: vl check rc 0, vl run invalid module, type mismatch: expected (ref $type), found i32

Want:

    3
    ab

#### Mechanism

The spread branch of `checkListPushArgs` (check_member_call.vl) stamps the spread literal with the
list's type so its function elements are delivered at the destination. That write also ran in each
instance's re-check, at the instance's concrete element, so the literal the instances share ended
typed at the last instance's `{f: (string) => string}[]` and the monomorphizer built `id` there for
every instance. Separately, `monoNotePushDeliveries` (emit_mono.vl) delivered only a literal pushed
directly, so a spread literal's elements (the bare name of [D16572](D16572.md), an un-annotated
list) reached no per-instance delivery.
