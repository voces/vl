### D2924 — a re-seated record list stored in an un-annotated object literal's field keeps the literal's own row in the field

**now a loud emit reject · clause 2, still open · was check-clean invalid wasm, the same on master `8615a730d` · a field initializer is checked against the field the object literal's own row stores it in (`rsFieldInitSafe`), so a literal whose row holds the destination's list or record still runs · fixtures `tests/cases/soundness/error-reseated-record-list-in-object-field.vl`, `tests/cases/soundness/reseated-record-list-joins-and-returns-run.vl` · found closing D2914 · filed 2026-09-27 against master `a41bd80e8`**

Repro:

    const i: { f: i32 } = { f: 4 }
    type I = { f: i64 | null }
    const il = [{ f: 7 }]
    const ic: I[] = il
    const hh = { xs: il }
    print(hh.xs[0].f)
    // vl check: rc 0.  vl run: invalid module in the top-level code

Want:

    7

#### Mechanism

D2881 builds `il` at `I`'s row, but the object literal `{ xs: il }` picks its record row by
field names from the checker's `{ xs: {f: i32}[] }`, whose field holds the `{ f: i32 }` list.
When another declared record of field `xs: I[]` exists, the literal picks that row and runs,
which is why D2914's refusal does not refuse this form: it cannot tell the two apart without
the row the literal resolves to.

#### Ablation

| ingredient removed | outcome | needed? |
| --- | --- | --- |
| the adopting binding (`const ic: I[] = il`) | runs, prints `7` | **yes** |
| a declared `type H = { xs: I[] }` added | runs, prints `7` | **yes** (its absence) |

#### Grading list

The element face `{ r: il[0] }`, which D2914's refusal already refuses loudly.

A DECLARED record of an anonymous record field is the same gap: `type H = { r: { f: i32 } }`
with `const h: H = { r: il[0] }` is invalid wasm on master `a41bd80e8` and is not refused.

#### Close

The use walk now reads the row the object literal is built at, and the field it stores the list
or element in. It refuses the field only when that field holds another record. With `type H =
{ xs: I[] }` declared, or `type H2 = { r: I }` for the element, the literal still runs. The
declared `const h: H = { r: il[0] }` with `H = { r: { f: i32 } }` is refused too. No row holds
`{ xs: I[] }` unless one is declared, so the repro stays open under clause 2.

#### Record covariance (2026-09-30)

The destination stores a numeric field at another width or kind, so under the record-covariance ruling the literal-holding binding or function is not adopted and the program keeps its master behaviour until the owner rules on [D3339](D3339.md) (DECISIONS.md "Record covariance: only a fresh value widens").
