### D15740 — a hole lambda's bundle held in a module-scope `const` and returned from another function is refused at emit

**closed 2026-11-11, runs and prints `5` `2.5` · was loud emit reject, clause 2, `a function returning a parameter called at two signatures is called where its result is not used at one of them` · found grading w315's emit-reject grouping (cell `bundle_copy_closure_returned`) · closed in the elaboration: a module-scope `const` holder may be returned from any function (`elabHolderCanHoldReturned`), and a returned holder's initialiser call is kept whole like a returned call (`elabRetKeptCall`, in `elabPlainCallsNote` and `elabRetRecordKeepsNote`, emit_elab.vl) · fixture `tests/cases/closures/hole-lambda-bundle-in-module-const-returned.vl` · still refused: the cell's lambda `g` and its returned `const` copy of the holder, filed as [D15744](D15744.md)**

Repro:

    function lap(f) {
      f(2.5)
      f(3)
      return f
    }
    const c = lap((a) => a + 1)
    function g() { return c }
    const w = g()
    print(w(4))
    print(w(1.5))

Want:

    5
    2.5

#### Mechanism

`lap` returns its parameter called at two signatures, so its call's value is a bundle record that
a holder must keep whole (`elabResKeeps`). A holder returned from a function is kept only where
every return of it sits in the function declaring it (`elabHolderCanHoldReturned`), and the keep
is noted only for a returned call, not a returned holder's initialiser
(`elabPlainCallsNote`, `elabRetRecordKeepsNote`). `c` is declared at module scope and
returned from `g`.

| --- | --- | --- |

| `g()` used once, `print(g()(4))` | runs, `5` | **yes** |
