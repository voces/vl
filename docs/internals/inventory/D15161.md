#### Mechanism

Re-ablated 2026-11-16 at master `078e4116`, for the L2 S3 plan
(`refactor-notes/2026-11-16-l2-s3-plan.md`). The refusal is the read-only map parameter floor
alone. It does not need function values: a map of `i32` read the same way refuses the same way.
It fires only when `run` is declared before the call; declared after, the witness prints `1.5`.
That order dependence is [D16714](D16714.md). Annotating only the parameter passes check and then
fails at emit, which is [D16715](D16715.md). The `holeSlotJudge` path this row first named is no
longer the one that refuses.

Two further gaps stand behind this one, and D15167's close leaves both. A hole parameter that only
reads its map refuses every map argument when it is declared before the call, the deliberate floor
in the floor's case (now `tests/cases/maps/infer-param-map-read-only.vl`) (ROADMAP E5). Declared after the call,
the witness passed check and refused at emit, which was [D15174](D15174.md), now closed: that
spelling prints `1.5`, and the E5 floor is the one blocker left.

The read-only face over other value types: the un-annotated `argument` cell of `ms-map-of-maps.matrix.vl`
(a nested map read and written through a narrowed read) meets the same floor, as does any body that only
reads its map parameter by index or `.has` (`function t(a) { print(a["z"] ?? 0) }` over a `{[string]: i32}`).
