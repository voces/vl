### D2344 — a generic call's named arguments pin the instance by SOURCE position, so an out-of-order call binds a type parameter from the wrong argument

**closed 2026-09-25 — the witness runs and prints `1` · was check-clean invalid wasm (`type mismatch: expected (ref $type), found i32`), clause 1 · reported by the #3118 review, filed 2026-09-25 against master `a277bf7b0` · fixture `tests/cases/generics/named-args-out-of-declared-order.vl`**

Repro:

    function gen<T>(a: () => i32, b: T): i32 {
      return a()
    }
    print(gen(b: 7, a: () => 1))
    // vl check: rc 0.
    // vl run (as filed): Error: invalid module … type mismatch: expected (ref $type), found i32.
    // Now prints 1.

#### Mechanism

A named call keeps its arguments in source order until the emitter reorders them, and the
monomorphizer paired `callArgs[i]` with `fnParams[i]` in three places: `monoInstantiate`'s pin
loop, `monoSpecializeConcrete`'s callback baking, and `monoWalk`'s generic-function-value
coercion loop. `gen(b: 7, a: …)` therefore bound `T` from the closure and pinned `a` from `7`,
building a `(i32, T=closure)`-shaped instance the reordered call could not feed. All three now
read `monoArgsInParamOrder`, which binds by name through `orderArgsByParamNames` (the checker's
and the emitter's one binder) and keeps source order where the call is positional or does not
bind every slot. The checker was already right; evaluation order is unchanged (parameter order).

Grid (`_scratch`, 43 programs), named order against declared order, with the type parameter bound
by the reordered argument, by an argument in place, by a `T[]` parameter, twice, and unbound by
any argument before the one that pins it; a UFCS receiver; a default filling a gap; a generic
function value into a concrete HOF; a nested generic call; a struct `T`: **17 of 30 reordered
calls failed before** (13 invalid module, 1 wasm trap `indirect call type mismatch`, 3 loud
`monomorphize:` emit rejects), **30 of 30 run after** with the proving value. Declared-order and
positional controls ran before and after.

#### Ablation

| ingredient changed | outcome (as filed) | needed? |
| --- | --- | --- |
| arguments in declared order, or positional | runs | the reorder: **yes** |
| `gen` not generic | runs | the pin: **yes** |
| `a: i32` (both arguments `i32`) | runs, and so hides it | differing wasm types: **yes** |
| `a: f64` | runs, `T` is pinned `f64` and `7` re-encodes | the same wrong pin, masked |

| inside a function body | same invalid module | no |
| `hof(f: idf, s: "z")`, concrete `hof`, generic `idf` | wasm trap, `indirect call type mismatch` | the coercion loop's twin |
