### D3993 — a generic called with a record from a closure, whose body does a compound assignment, traps the compiler

**closed 2026-10-11 by lane CK · runs · was compiler trap · found closing D3992 · filed 2026-10-11 against master `e5128703a` · pins: `tests/cases/objects/width-record-into-declared-param-runs.vl`**

Repro:

    type A = { k: i32, x: f64, y: f64 }
    function mv<W>(p: W) { p.x += 1.0 }
    function main() {
      const a: A = { k: 1, x: 2.0, y: 3.0 }
      const f = () => { mv(a) }
      f()
      print(a.x)
    }
    main()
    // vl run: the compiler itself trapped (out of bounds array access in `monoExprMake`)

Want:

    3

#### Mechanism

`monoPinBodyLambdas` rebuilds an instance body's expressions from their kids. A compound
assignment offers its value kid only while its right side is still `target op value`; a rewrite
over the gradual `p.x` had replaced it, so the kid list held one entry and `monoExprMake` read
`kids[1]`. Such a node is now kept as it is.
