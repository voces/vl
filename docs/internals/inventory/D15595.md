### D15595 — [CLOSED 2026-11-09] a capturing nested generic of a generic encloser, handed to a type-parameter parameter that calls it at two types, gets no pin

**closed 2026-11-09, runs and prints `7`, `x`, `7`, `2` · was loud emit reject, clause 2, `vl check` rc 0, then `emitProgram: a generic function taken as a value reaches no call that fixes its type` · filed 2026-11-09 against master `9145924e` · `elabBundleSigNote` noted a call's signatures for a bundle only where the nested member's enclosers are closed (`elabNestedInClosed`), so a generic `outer`'s `same` got no bundle and mono pinned the argument from the open `(T) => T`. Repro:

    function mid<F>(a: F) {
      print(a("x"))
      print(a(2))
    }
    function outer<U>(u: U) {
      function same<T>(k: T): T {
        print(u)
        k
      }
      mid(same)
    }
    outer(7)

Want:

    7
    x
    7
    2

#### Mechanism

There is no forwarder here. With one call, `a("x")`, the
elaboration keys `mid` at `(string) => string`, because that call fixes the type. With two calls,
no one function type is fixed. The open key `mid<(T) => T>` already records both calls
(`same<string>` and `same<i32>`, both handed back to `outer`'s instance, D15105). Then mono pins
`mid(same)`'s argument in `outer`'s instance from the checker's open `(T) => T`. That is
`monoArgTyNameCascade`, and it refuses there. Under the ruling, the parameter should be bound per
call as `Fn#same`.
