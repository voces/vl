### D15905 — a call through a bundle parameter named like a top-level function calls the function

**closed 2026-11-12, runs and prints `5` `2.5` · was check-clean invalid wasm, clause 1, `vl check` rc 0, then `the emitted module failed to validate inside `lap`: … type mismatch: expected i32, found f64`; with the function taking no parameter, a loud `emitProgram: a call passes more arguments than the function it calls takes` · found working [D15904](D15904.md): any `lap(…)` bundle made inside a function named `f` · filed 2026-11-12 against master `96590b46` · closed in emit: a call whose callee reads a bundle parameter is a call through it even where the name also resolves to a function (`emitCallCoreUserFn`, wasmEmit.vl), as a closure binding of the name already was · fixture `tests/cases/closures/hole-lambda-bundle-handed-on-copied-and-dropped.vl`**

Repro:

    function lap(f) {
      f(2.5)
      f(3)
      return f
    }
    function take(b) {
      print(b(4))
      print(b(1.5))
    }
    function f(n: i32) {
      take(lap((a) => a + 1))
    }
    f(1)

Want:

    5
    2.5

#### Mechanism

`lap`'s parameter `f` holds a bundle (a record of two closures), not a closure, so the emit
test that lets a live closure binding outrank a same-named function did not fire, and `f(2.5)`
in `lap` was emitted as a direct call to the top-level `f`.

#### Ablation

| spelling | outcome on master |
| --- | --- |
| the function named `main` or `g` | runs |
| `lap`'s parameter renamed `h` | runs |
| `ap(f)` calling `f` at one signature, beside a function `f` | runs |
| `function f(n: i32)` making the bundle | invalid wasm |
| `function f()` making the bundle | refuses (more arguments) |
