### D1461 — a literal-union alias beside its own BASE refused, because the unification only knew the atom direction

**closed · 1 witness plus a 50-cell position matrix · filed 2026-09-03 against master `44394ae5`**

Repro:

    type K1 = "circle" | "round"
    type A = { kind: K1, r: f64 }
    type B = { kind: string, r: f64 }
    function f(n: i32): A | B {
      if n == 0 { return { kind: "circle", r: 1.0 } }
      const v: B = { kind: "zz", r: 2.0 }
      return v
    }
    const a = f(0)
    if a is A { print(a.kind) } else { print("notA") }
    // vl check: rc 0.  vl run: emitProgram: union `A|B` discriminates `A` from `B`
    // on a literal field whose two arms rep differently

#### Mechanism

The owner's 2026-09-02 amendment rules a set beside its own base a legal discriminated pair.
D1050 built the ATOM direction of the unification, which this pair cannot use — the base arm
holds an arbitrary string with no interned id — so it kept the loud refusal, and DECISIONS
recorded the string direction as needing "the mirror of every atom consumer (construct intern,
`is` compare, read classifier, widen) written from scratch". **Three of the four were already
built and the fourth is not needed.** A declared INLINE set beside the same base is two code-3
rows, already discriminable as laid out, and already runs — so demoting the ALIAS arm's row to
code 3 lands it exactly where a declared inline row sits, and `emitDiscrimFieldEq`'s code-3 arm
(string equality), the code-3 construct arm (a string constant) and the code-3 read (a `(ref
$string)`) serve it unchanged. The WIDEN is not the missing mirror either: the field's read is
already a string, and it is the ATOM-typed destinations that need a conversion —
`strReppedLitUnionAt` -> `emitStrToAtom`, one hook in `emitExpr` under `pendingLitUnion`, built
for the flattened/inline litunion family and blind to how the value got its string rep.

`K1` keeps the atom everywhere else in the module; only the field moves. The disassembly shows
both: one shared `(struct (field (mut (ref $str))) (field (mut f64)))`, and `takesK(k: K1): K1`
still `(func (param i32) (result i32))` with a real narrow tower at the call.
