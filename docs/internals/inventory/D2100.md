### D2100 — a record delivered into a wider-field record is passed unconverted when the source's rep is pinned, so a read-only delivery is an invalid module

**check-clean invalid wasm · clause 1 · 64 cells of D2060's 840-cell grid, every one read-only · filed 2026-09-22 against master `4b7460028`, residue of [D2060](D2060.md)**

Repro:

    function f(p: { x: i32 | string }) {
      if p.x is i32 { print(p.x) }
    }
    const q: { x: i32 } = { x: 1 }
    f(q)
    print(q.x + 1)
    // vl check: rc 0.  vl run: invalid module — type mismatch: expected (ref $type), found (ref $type)

#### Mechanism

Not yet ablated past the table below. With the source un-annotated (`const q = { x: 1 }`) the
emitter adopts the destination's rep for `q`, and the delivery aliases one struct — that is the
face D2060 closed for writes and which still runs for reads. Annotating `q` pins its own
`{ i32 }` struct, and the call site passes that reference into a parameter typed as the
`{ box }` struct with no conversion. The same holds at a binding, an assignment, a struct field,
a capture and a lambda argument, and at a `return` whose declared type is the wider record
whatever the source's annotation. [D2036](D2036.md) (`i32` into `f64`) is the numeric twin.
Whether the close is a converting copy (legal exactly where D2060's rule already proves
nothing writes) or rep adoption at the pinned face is the fixer's question.

#### Ablation

| ingredient removed | outcome | needed? |
| --- | --- | --- |
| the annotation on `q` | runs (`1`, `2`) | **yes** |
| the widened field (`p: { x: i32 }`) | runs | **yes** |
| the call, as `const p: { x: i32 \| string } = q` | still an invalid module | no |
| the annotation, at a `return` (`function w(a: { x: i32 }): { x: i32 \| string } { return a }`) | still an invalid module | no |

#### Grading list

D2060's grid cells with `read` behaviour and the `ann` face at `arg`, `argfn`, `ufcs`,
`lambda`, `bind`, `bindfn`, `assign`, `field`, `capture`, and every `ret` cell; D2036's
witness; a list FIELD widened by element (`{ xs: [1] }` delivered as `{ xs: (i32 | string)[] }`,
an invalid module read or written — a narrower `push(4)` is admitted by D2060 and lands here);
and the un-annotated face in company — `const a = { x: 1 }` read through
`{ x: i32 | string }` beside `const n = { x: 5 }` read through `{ x: i32 | null }` is an invalid
module at the second call, because the two sources share one `{x: i32}` row and the adoption
serves one destination rep.
