### D17043 — `vl check` reports a binding unused when its only read is a call through a field holding a named function

**open · runs today and must keep running · vl check warns Unused variable on a binding read only through a field call · filed 2026-11-21 by lane IR-N5 against master `568e22a36`**

Repro:

    function twice(a: i32) { return a * 2 }
    function bound() {
      const r = { f: twice }
      return r.f(3)
    }
    print(bound())
    // vl check: rc 0, with "[WARNING]: Unused variable `r`" at `const r`.  vl run: prints 6.

Want:

    6

#### Mechanism

Not traced. The read `r.f(3)` is a call whose callee is a field holding a declaration's
closure value. The unused-variable count does not take the member call's receiver as a read of
`r`. The same binding read through `const h = r.f` counts.

#### Ablation

| ingredient changed | outcome | needed? |
| --- | --- | --- |
| `twice` un-annotated (`function twice(a)`) | still warns | no |
| the field holds a lambda `(a: i32) => a * 2` | no warning | **yes** (a named function) |
| the record annotated `const r: R`, lambda field | no warning | — |
| the field read into a local, `const h = r.f; return h(3)` | no warning | **yes** (the call through the field) |

#### Grading list

- The un-annotated spelling `function twice(a)` (the d15206 corpus cells' shape).
- A top-level binding, `const a = { f: inc0, n: 1 }; print(a.f(3))`.
