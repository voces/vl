### D6201 — one binding of `fw(lam)`, a hole lambda through a hole parameter, called at two types has no slot per type

**closed 2026-10-17 by lane L1 · runs, prints `3 w` · was loud emit reject · clause 2 · a slot for a binding of `fw(lam)` holds a fresh copy of the un-annotated `const` lambda when that lambda reads only its own and module-scope bindings · pins: `tests/cases/functions/hole-lambda-const-through-identity-at-two-types.vl` (three types with f64, a lambda reading a module constant, annotated destinations, inside a function) · the two-binding spelling is filed as [D6241](D6241.md) · found closing [D6020](D6020.md) · filed 2026-10-17 against master `c6cd62ec1`**

Repro:

    function fw(f) { return f }
    const lam = (x) => x
    const q = fw(lam)
    print(q(3))
    print(q("w"))
    // vl check: rc 0.  vl run: emitProgram: monomorphize: unsupported argument type for `f` in a call to `fw`

Want:

    3
    w

#### Mechanism

From the ablation only. D6020's close gives a binding of `fw(id)` a slot per type when `id`
is a hole FUNCTION; the split plan asks the binding when the hole function is refused as a
value. A hole lambda is refused earlier, at `fw`'s argument, by the monomorphizer, so the
plan is never asked; two bindings, one per type, are refused the same way.
