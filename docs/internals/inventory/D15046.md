### D15046 — a `const` alias of an un-annotated function forwarded through a list call, beside an unused hole parameter handed that function, is invalid wasm

**check-clean invalid wasm · clause 1 · found minimising the split-plan census group F-let (`closures/forwarded-hole-fn-to-list-element-value-param.vl`); independent of the split plan, invalid with it on · filed 2026-11-02 against master `0a0b6b529`, pre-existing**

Repro:

    function mul(a, b) { return a * b }
    function same(g, s) { print(g(s, s)) }
    function swap(k, h) {
      const hh = mul
      for f in [same] { f(hh, k) }
    }
    swap(1.5, mul)
    // vl check: rc 0.  vl run: the emitted module failed to validate inside `swap`:
    //   type mismatch: expected (ref $type), found i32

Want:

    2.25

#### Mechanism

Not located. The unused parameter `h` is handed `mul`, so `mul`'s set has a hand into `swap`, and
`hh` hands the same function to `same` through a list call. The two read `mul` at two reps: an
`i32` (a set id) where the list call's argument is built, a closure ref where `same`'s parameter
expects it.

| `same(hh, k)`, no list call | runs, `2.25` | **yes** (the list call) |

| `_h` | still invalid wasm | no |
