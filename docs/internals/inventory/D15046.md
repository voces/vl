### D15046 — a `const` alias of an un-annotated function forwarded through a list call, beside an unused hole parameter handed that function, is invalid wasm

**closed 2026-11-02 · runs, prints `2.25` · was check-clean invalid wasm, clause 1 · `ftSetOnlyArgOf` (check_fn_tag.vl) takes a binding's initialiser as its reads' value, so the alias no longer makes the handed set more than an argument and the list call's set is tagged · fixture `tests/cases/closures/alias-of-fn-forwarded-through-list-beside-unused-hole-param.vl` · found minimising the split-plan census group F-let (`closures/forwarded-hole-fn-to-list-element-value-param.vl`); independent of the split plan, invalid with it on · filed 2026-11-02 against master `0a0b6b529`, pre-existing**

Repro:

    function mul(a, b) { return a * b }
    function same(g, s) { print(g(s, s)) }
    function swap(k, h) {
      const hh = mul
      for f in [same] { f(hh, k) }
    }
    swap(1.5, mul)
    // vl check: rc 0.  vl run: the emitted module failed to validate inside `swap`:
    //   type mismatch: expected (ref $type), found i32

Want:

    2.25

#### Mechanism

The list `[same]` holds the ids of `{same}`, inside an un-annotated function, and its call hands
on a function value. `ftScan` keeps such a holder only when the handed value's set is never read
but as a call argument (`ftSetOnlyArgOf`). `const hh = mul` is a read of `{mul}` that is not an
argument, so `{same}` was declined and built as a closure, while the unused `h`, bound to `{mul}`
by the call, still had `mul` built as its id: the list call handed an `i32` where the closure's
parameter expected a ref. A binding's initialiser is now taken as its reads' value, each of which
carries the set and is asked in its own turn.

#### Ablation

| ingredient changed | outcome | needed? |
| --- | --- | --- |

| `same(hh, k)`, no list call | runs, `2.25` | **yes** (the list call) |
| `let hh = mul` | still invalid wasm | no |
| `_h` | still invalid wasm | no |
