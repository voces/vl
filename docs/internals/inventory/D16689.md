**open · check-clean silently wrong · clause 1 under DECISIONS "An annotation fixes an empty list's element type" · prints `true` · the residue of D16342's close · filed 2026-11-16 against master `88d01b96b`**

Repro:

    function listParam<V>(v: V[]) { return v is f64[] }
    const e: i32[] = []
    print(listParam(e))

Want:

    false

#### Mechanism

D16342's close settles a list test from its pins (`settleListIsPins`, check_operators.vl) only when
the operand is a bare hole or type parameter. Every other spelling still answers by emptiness
(`emitListEmptyFitIs`, D4910): an operand typed `V[]`, `V[][]` or a record field `r.v`, and a
`T[]` local. Widening the pin route to them was measured on this close: the flip is right, but
an arm the test guards that holds a function literal then fails at emit (`ref valtype with no
interned shape`), because the lifted function is typed at the narrowed element no instance builds.
The same guard keeps a bare-parameter test whose arm holds a function literal on emptiness. A test
that a fixed meeting list also reaches (`t(e)` beside `t([2.5])`) keeps emptiness too, since one
node answer cannot serve both instances.
