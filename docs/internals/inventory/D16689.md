### D16689 — an empty list whose element an annotation fixed still passes `is f64[]` through a union parameter, or where the same function also receives an open list

**closed 2026-11-16 by lane AE — the witness prints `false` · a nullable or union operand's pin is read by its one list member (`tySoleListMember`), so the union face answers as a bare `V[]` does; a function also handed an open list at the tested parameter, beside a fixed list that may be empty, is refused at the fixed call (the DECISIONS interim, lifted by L2 S3) · fixture `tests/cases/soundness/is-list-test-union-operand-and-open-call.vl` · was check-clean silently wrong, clause 1 under DECISIONS "An annotation fixes an empty list's element type" · prints `true` · the residue of D16342's close, narrowed twice on 2026-11-16 · filed 2026-11-16 against master `88d01b96b`**

Repro:

    function opt<V>(v: V[] | null) { return v is f64[] }
    const e: i32[] = []
    print(opt(e))

Want:

    false

#### Mechanism

A list test is settled from its pins (`settleListIsPins`, check_operators.vl) for an operand that is
a bare hole or type parameter, or a parameter, field or annotated `let` of a list of one. Every pin
fixed and disjoint makes it `never` with dead, unlifted arms; fixed pins that also meet it answer
per instance (`listIsFixedOnly`, read by the emitter through `elabIsTyIn`). A union operand
(`V[] | null`, `V[] | string`) had pins that were not bare lists, so it kept the emptiness answer
(`emitListEmptyFitIs`, D4910); its pin is now read by its one list member, and one with several
list members keeps its own answer. A test whose function also receives an open list kept the
emptiness answer at every call; one instance cannot answer both before inferred interfaces record
each call's binding, so the fixed call is refused when its list may be empty. The open list now has
to sit at the tested parameter (`listTestOwnerOpenArg`), so an open list at another parameter no
longer turns off the element answer.
