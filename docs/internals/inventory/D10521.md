### D10521 — a generic body's binding of an inferred `T[] | i32[]` result substitutes to `f64[]` on the typed path, losing the `i32[]` arm

**runs today and must keep running · prints `2`, `3` · at `T := f64` the spelled let annotation `monoSubstLetType` builds is `f64[]|i32[]`, and the typed substitution `monoSubstInst` gives `f64[]` · latent: the instance takes the spelling's union and drops the typed row (`subAtoms.length >= 2`), so nothing reads the narrower type yet · it becomes clause 1 the day C1 step 1 mints let types from the typed column · found by the C1 step-1 probe ([render-parse residue](../render-parse-residue-2026-10.md) §C1) · filed 2026-10-22 against master `ba14205a8`**

#### Mechanism

The spelling has both arms. The typed substitution starts from the let annotation's arena type
(`nodeTyIxOf` of the hole annotation), which holds only `T[]`. A generic body's `T | X` is
gradual (the owner's ruling), so the join probably folds the `i32[]` arm into `T[]` before
emit sees it. Substituting that row gives `f64[]`.

#### Ablation

| ingredient removed | outcome | needed? |
| --- | --- | --- |
| `w`'s inferred result (annotate `: T[] \| i32[]`) | typed and spelled agree | **yes** |
| a non-`i32` pin (`len(2, …)`) | agree, both arms are `i32[]` | **yes** |
| the binding (`print(w(t, b).length)`) | still disagrees, at the call's own hole | no |
