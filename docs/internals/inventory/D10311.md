### D10311 — a generic held in an un-annotated `Map()`, read and handed to a generic's function parameter at two types, has no argument type

**loud emit reject · `vl check` rc 0 · `emitProgram: monomorphize: unsupported argument type for `f` in a call to `run`` · clause 2 · CAPABILITY: the read called directly, `mv(2)` and `mv("ab")`, prints `2`, `ab`, and one call `run(mv, 2)` prints `2` · found closing [D10251](D10251.md), the un-annotated `map_value` and `map_set` cells of fn-value-generic-list-element-literal-arg-open and fn-value-generic-list-literal-arg-two-types-open · present on master `d5ec7f160` · filed 2026-10-22 against master `d5ec7f160`**

Repro:

    function id<T>(x: T): T { x }

    const m = Map()

Want:

#### Mechanism

Not traced. The map's value is planned from its reads ([D9310](D9310.md)), and a read handed to a
generic's function parameter at two types fixes no one instance. With the map holding `[id]`
and `run(mv[0], …)` at two types the refusal is `unsupported map value type` instead, at the
map; whether that is the same mechanism is not ablated.

#### Ablation

| ingredient removed | outcome | needed? |

| the second call `run(mv, "ab")` | runs, `2` | **yes** |
| `run` replaced by direct calls `mv(2)`, `mv("ab")` | runs, `2`, `ab` | **yes** |
| the map: `const v = id`, `run(v, 2)`, `run(v, "ab")` | runs | **yes** |
