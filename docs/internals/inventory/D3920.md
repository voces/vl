### D3920 — an inline record spelling takes a union-box row with the same field name declared before it, and a callback over it builds invalid wasm

**closed 2026-10-09 by lane SC, with D3898 · runs · was check-clean invalid wasm · found in review of #3485 (`rv3485-box`: b1–b8) · filed 2026-10-09 against master `09d7de908` · pins: `tests/cases/generics/inline-record-spelling-beside-earlier-union-box-row.vl`, `tests/cases/generics/un-annotated-inline-record-callback-beside-union-box-alias.vl`**

Repro:

    type A = { x: i32 }
    function ap<T, U>(xs: T[], f: (t: T) => U): U[] {
      const r: U[] = []
      for x in xs { r.push(f(x)) }
      r
    }
    const q: { v: i32 | string } = { v: 1 }
    const o: { v: A } = { v: { x: 2 } }
    print(ap([o], (e) => e.v.x)[0])
    // vl check: rc 0.  vl run: the emitted module failed to validate inside `ap`

Want:

    2

#### Mechanism

D3898's spelling resolution, at a union-box field. A field coded as the union box (16) accepts a
record arm, so `{v:{x:i32}}` matched `{ v: i32 | string }`'s row on the strict pass, ahead of
`{ v: A }`'s own row, whenever the box row was declared first. D3898's first fix accepted the box
on the strict pass too, which `structIndexOfTypeName` warns against. Closed: an inline record
accepts a box field only on the lenient pass, which runs only for a spelling no struct row placed.
