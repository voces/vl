### D16394 — `==` over records whose field is a string literal union on one side and `string` on the other passes check and is refused at emit

**loud emit reject · clause 1 (`vl check` rc 0) · bucket (e) · found beside D16393, probing `check_ty_relate.vl:771` · probe `scripts/capability-probes/eq-record-litunion-field-vs-string-field.vl` · filed 2026-11-15 against master `5683d3b2c`**

Repro:

    const a: {f: "a" | "b"} = {f: "a"}
    const b: {f: string} = {f: "a"}
    print(a == b)
    // vl check: rc 0.  vl run: emit error, `emitProgram: struct equality is not supported yet`

Want:

    true

#### Mechanism

The field is stored as an atom on one side and a string on the other, as in D16393's lists. The
checker's pair test (`check_ty_relate.vl`) refuses the list spelling, but not a record whose field
differs that way, so the record reaches the emitter's struct-equality lowering, which has no core
for the mixed field and refuses.

#### Ablation

| spelling | outcome |
| --- | --- |
| the witness | check-clean, loud emit reject |
| `{f: "a" | "b" | null}` against `{f: string | null}` | check-clean, loud emit reject |
| `{f: ("a" | "b")[]}` against `{f: string[]}` | check-clean, loud emit reject |
| `{f: "a" | "b"}` against `{f: "a" | "b"}` | runs, prints `true` |
| `{f: 1 | 2}` against `{f: i32}` | runs, prints `true` |
