### D16421 — an un-annotated binding of a hole parameter's call, whose result reads a nested list element the body pinned, takes the default element

**closed 2026-11-15 — the witness runs and prints `0.5` · was: check-clean invalid wasm · `type mismatch: expected i32, found f64` · clause 1 · found grading D16365's close (`hole-param-record-empty-list-field.matrix.vl`, un-annotated face) · filed 2026-11-15 against master `a058e28f`**

Repro:

    function f(a) { a.push([]); a[0].push(0.5); return a[0][0] }
    const v = f([])
    print(v)
    // vl check: rc 0.  vl run: invalid module in the top-level code

Want:

    0.5

#### Mechanism

At the call, the body's deferred pushes pin the open lists written at the call
(`pinBmCstrElems`), and a value pins only those. The first push put the body's own `[]` into the
argument's element, and `a[0].push(0.5)` then wrote to that inner list, which was not among
them. So its element stayed open, and the binding read the default `i32`; `const w: string =
f([])` checked clean. An open list a deferred push writes into a list written at the call, bare
or in a record field, is now written at the call too (`pinRowsAddOpenLists`). Fixture:
`tests/cases/closures/hole-param-nested-list-pinned-in-body-bound-at-call.vl`.
