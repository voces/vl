### D15551 — a generic function's returned record holding a called set beside a list of its type parameter has no row

**closed · runs, prints `2` · was loud emit reject, `emitProgram: object literal but no struct type declared`, clause 2 · fixed 2026-11-08: a shared list field of values takes its field's type in the instance's frame (`monoRecordObjLitAt`) · the non-generic twin `mk(x: i32)` runs, `2` · found closing [D15549](D15549.md) · filed 2026-11-08 against master `c296e59f`**

Repro:

    function inc0(a) { return a + 1 }
    function mk<T>(x: T) { return [{ fs: [inc0], x: x, y: [x] }] }
    print(mk(5)[0].fs[0](1))

Want:

    2

#### Mechanism

The copy's row is minted from its literal in the instance's frame (`mintGradualObjLitRows`), and
its fields are the template's shared `FieldInit` children. `monoRecordObjLitAt` recorded a shared
read (`x`) in the frame, but a shared list literal (`[x]`) only when it held functions, so the
`y` field read `T[]` there, had no field code, and no row was minted at all. The list of values
now takes the field's type in the frame. The record is outside the open test of the list's own
column, since the first frame to record a node also writes that column and the second instance
would then skip it.
