### D15551 — a generic instance's `??` over a union left typed a number default as the left's union, where its direct spelling joins it apart

**closed · 1 delivery of the box shadow (`generics/param-union-bound-from-one-union-argument`) · filed 2026-11-08 against master `e97619e8`**

Repro:

    function D<A, B>(d: i32, v: A | B | null) { print(v ?? d) }
    const m: f64 | string | null = null
    D(7, m)

Want:

    7

#### Mechanism

`coalJoinApart` joins a number default apart from the left operand (`f64 | string` and `i32`
make `f64 | string | i32`), as the `if` the operator spells does. In a function that declares
type parameters it kept the widening for a union left operand, and a recheck reads the instance
through the same test. The template's left is `A | B`, which `coalParamDefault` joins apart. The
instance's left is the closed `f64 | string`, so it fell through to `assignableExpr(d, i32,
f64 | string)`: an `i32` widens into the `f64` member. The `??` typed `f64 | string`, and every
box record under it (`d`, `v`, the `print` argument) named that union, so the instance boxed `7`
as an f64. The direct spelling joins apart and boxes it as an i32. The emitter read the site's
union, so the program printed `7` either way; a delivery reading the record built the wrong box.
Closed by joining apart in every recheck: an instance is its direct spelling.

#### Ablation

| ingredient removed | outcome | needed? |
| --- | --- | --- |
| the type parameters (`v: f64 \| string \| null`) | record and site agree, `f64 \| string \| i32` | **yes** |
| the `f64` member (`m: boolean \| string \| null`) | no number member to widen into; record and site agree | **yes** |
| the declared `d: i32` (a literal `v ?? 7`) | the literal adapts; record and site agree, `f64 \| string` | **yes** |
