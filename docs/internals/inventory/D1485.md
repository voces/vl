### D1485 — a STRING literal union is refused in a template hole while a NUMERIC literal union is accepted, and `+` accepts both

**loud check reject · clause 2 · ``an interpolation hole is `string` or i32 | i64 | boolean | f64 — this one is "locked" | "open"`` · filed 2026-09-03 against master `cdfdc14e`**

Repro (two lines; rejected at 2:10):

    const st: "locked" | "open" = "locked"
    print(`\{st}`)

#### Mechanism

The hole's admission test is an EXACT type test standing where an assignability test belongs.
Three neighbouring spellings of the same value all run — `"s=" + st`, `const s: string = st`
then `` `\{s}` ``, and a bare `print(st)` — which proves the value IS assignable to `string`
and that the renderer can already print it. And the SAME hole admits a NUMERIC literal union
(`const n: 1 | 2 = 1`, `` `n=\{n}` `` prints `n=1`), so the rule the message states is not the
rule the checker applies.

**THE WORDING IS WHY THIS IS EASY TO MIS-FILE AS DESIGN.** It reads as a contract, names an
allowed set, and concedes no capability gap. The repo's own heuristic settles it the other
way: a NEIGHBOURING spelling running means capability, not design — and here four of them run,
including the numeric half of the very set the sentence enumerates.

#### Ablation

| ingredient removed | outcome | needed? |
| --- | --- | --- |
| the STRING literal arms (`const n: 1 \| 2 = 1`) | runs, prints `n=1` | **yes** — the numeric union is admitted |
| the template hole (`"s=" + st`) | runs | **yes** |
| the template hole (`print(st)`) | runs | **yes** |
| the literal union at the hole (`const s: string = st` first) | runs | the rescue |
| the two arms (a ONE-member `const s: "a" = "a"`) | rejects, `this one is "a"` | no — arity is not the axis |
| the inline spelling (a named `type State = "locked" \| "open"`) | rejects, `this one is State` | no |

#### Grading list

The four RUNS rows must keep running. The close must be graded at a one-member string
literal union and at a named `type` alias as well as the inline spelling, since all three
share the site. And it must NOT admit something the renderer cannot spell: the numeric
union's acceptance is the proof that the render exists for the literal-union rep, so the
close is "widen the admission test to assignability", not "widen the message".
