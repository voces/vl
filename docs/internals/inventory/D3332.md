### D3332 — `v is K` in a generic pinned at `string | null` compares a null receiver's string and traps

**closed 2026-09-30 · was check-clean, then a trap after load (`null reference`), clause 1, on master `b6378e95b` · found by the lane JW grid (`s-k__match__null__arg__is`, both the `<T>` and the direct spelling of the caller) · fixture `tests/cases/generics/is-literal-union-at-nullable-string-pin.vl`**

Repro:

    type K = "a" | "b"
    function show<U>(v: U) {
      print(v is K)
    }
    const a: string | null = "a"
    const z: string | null = null
    show(a)
    show(z)

Want:

    true
    false

#### Mechanism

`is K` over a string receiver is a membership test, one string compare per member
(`emitLitMemberEq`), guarded against a null receiver only when `litMemberRecvIsNulString`
holds, and that asks the checker's type of the read (`nodeTyIsNullable`) as the narrowing
signal. Inside an instance the read is typed at `U`, which is not nullable, so the guard
dropped and the compare dereferenced the null. A read typed at a type parameter now takes the
guarded compare whenever its storage is the `string | null` niche.
