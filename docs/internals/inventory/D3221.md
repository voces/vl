### D3221 — a hole callee pinned to a function with a default parameter, called without it, is invalid wasm

**closed by design 2026-10-17 by lane L3 with [D5750](D5750.md) · now a loud check reject, "wrong number of arguments: expected 2, got 1 (the body of `H` at the call's argument types)" · was check-clean invalid wasm · clause 1 · a call through a function value has exact arity and a default does not widen it: `const g = f; g(4)` and `h: (x: i32, y: i32) => i32` both refuse with the same sentence, so the hole now refuses too · pins: `tests/cases/functions/error-fn-value-to-hole-param-wrong-arity.vl` · found by the #3287 split-head review (`rv3287s-4099`, `p3/a4`) · filed 2026-09-29 against master `94670f728`**

Repro:

    function f(x: i32, y: i32 = 2): i32 {
      return x + y
    }
    function H(h) {
      return h(4)
    }
    print(H(f))
    // vl check: rc 0.  vl run: invalid module inside `H`: type mismatch: expected i32, found
    // structref

Want:

    check reject, as the direct call through a function value gives: `wrong number of arguments: expected 2, got 1`

#### Mechanism

Not localised. The instance calls the pinned function with the arguments written, and nothing
fills the default the direct call fills.
