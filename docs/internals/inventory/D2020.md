### D2020 — a module-level `let x: T` with no initializer is check-clean and then refused by the emitter, which has no cell shape for a global without an initializer

**loud emit reject · `vl check` rc 0, then `emitProgram: module global has no initializer`, clause 2 · filed 2026-09-22 against master `af07f4ae0`, found building `extern let` (PL-003(b)), which is the one uninitialized module global the emitter now serves**

Repro:

    let x: i64
    x = 5
    print(x)
    // vl check: rc 0.  vl run: emit error, module global has no initializer

#### Mechanism

The checker accepts an uninitialized module `let` (definite assignment tracks it through the
top-level statements), but `emitGlobalSection` emits a cell only from an initializer: a constexpr
one becomes the cell's init, a non-constexpr one a zero cell plus a start-function store. With no
initializer neither arm applies and the section refuses. `extern let` is exempt because its cell is
an import. The likely close is the non-constexpr arm's zero cell with no start-function store;
what is still open is what a FUNCTION that reads the binding before the top level assigns it
should see, since definite assignment does not follow calls — a scalar would read zero and a ref
type would need a nullable cell and a trap.

#### Ablation

| ingredient removed | outcome | needed? |
| --- | --- | --- |
| module scope → the same three lines in a function body | runs, prints `5` | **yes** |
| no initializer → `let x: i64 = 0` | runs, prints `5` | **yes** |
| `i64` → `string` | same refusal | no |
