### D2111 — a valued function value called for effect through an index, paren or call-result callee is refused, though its signature is resolved

**closed 2026-09-22 — the witness prints `1` then `2` · was a loud emit reject (`vl check` rc 0, then `a function-value call statement yields a value the tail-value ladder did not claim`), clause 2 · filed 2026-09-22 against master `7b16d43ab`, found beside D2110 · fixture `tests/cases/closures/function-list-call-statement.vl`**

Repro:

    function a(x: i32) {
      print(x)
      return x
    }
    const fs: ((i32) => i32)[] = [a, a]
    fs[0](1)
    const k = 1
    fs[k](2)

#### Mechanism

D1623 gave `emitCallStmt` a floor for the callee shapes that are neither a name nor a member,
and it lowered only a `>v` key; any other key refused, because a value reaching the floor was
read as a tail the tail ladder had declined (D1626's unresolved key). That conflated two
cases. `stmtIsTailValue` claims every tail whose `cloCallSigKey` resolves to a valued key, so a
RESOLVED valued key at the floor is a genuine statement — a discarded result — and is now
`call_ref` + `drop`, the same thing the `Ident` and `Member` arms do. An UNRESOLVED key still
refuses: D1626's cells keep their loud floor.
