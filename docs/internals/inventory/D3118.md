### D3118 — a value narrowed to `K | null` out of a wider box is delivered to a `K | null` destination as the box

**closed · a `K | null` destination converts the box to the atom niche (`emitNarrowedNicheRead`), and an un-annotated binding of such a read takes the niche cell · fixture `tests/cases/literal-unions/narrowed-nullable-literal-delivery.vl` · was check-clean invalid wasm · clause 1 · found while grading [D3107](D3107.md)'s literal-union twin · the same on master `f14a8cca2` · filed 2026-09-28 against master `f14a8cca2`, closed 2026-09-28 against master `f14a8cca2`**

Repro:

    type K = "a" | "b"
    function show(w: K | null): string {
      if w == null { return "N" }
      return w
    }
    function t(e: K | null | i32) {
      if !(e is i32) { print(show(e)) }
    }
    t("b")
    t(null)
    // vl check: rc 0.  vl run: invalid module inside `t`: type mismatch: expected i32, found
    // (ref $type)

Want:

    b
    N

#### Mechanism

`e` is the `{tag, payload}` box, and `!(e is i32)` narrows it to `K | null` at the type level
only; a `K | null` destination is the `i32` atom niche (`-1` for null), so the box reached an
`i32` slot. The atom conversion `emitStrToAtom` covered a narrowing to `K` alone.
`narrowedNulLitBoxKey` (`emit_classify.vl`) recognises a read narrowed to exactly `K | null`
out of such a box, and under `pendingNulLitUnion` `emitExpr` converts it with
`emitNarrowedNicheRead`'s new `NICHE_NUL_LIT` arm: the null tag gives `-1`, otherwise the
payload string is matched against `K`'s members. `letNulLitUnion` claims an un-annotated
binding of such a read, so its cell is the niche and its store converts.
