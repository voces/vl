### D14439 — a two-member set handed to a hole parameter called at two tuples builds invalid wasm

**check-clean invalid wasm · `expected i32, found (ref $type)` inside `lapBack` · clause 1 · open · the one-member spelling `lapBack(wrap, pair, 4)` runs · deleted by the mint's emitter reader (D14430), which instances each call of the set at its own tuple · filed 2026-10-28 against master `4638042eb`**

Repro:

    function wrap(a) { return [a] }
    function wrap2(a) { return [a, a, a] }
    function pair(a) { return [a, a] }
    function lapBack(g, h, x) {
      print(h(g(x)).length)
      print(g(h(x)).length)
      return 0
    }
    const c = true
    lapBack(if c { wrap } else { wrap2 }, pair, 4)
    // Want: 2, 1

#### Mechanism

`g` is called at `i32` and at `i32[]` in one instance of `lapBack`, and `h` is called on
`g`'s result. With one member, the split plan gives `g` one copy per instance (D6210). With two,
the set is handed on as itself and the instance has one body, so one of the two calls is
emitted at the other's tuple.

Measured 2026-10-29 by probe. The split plan hands the one-member `h` two closure parameters
(`h` at `i32` and at `i32[]`) and the two-member `g` one, typed `i32 => i32[]`, which `g(h(x))`
then calls with an `i32[]`. The set is never tagged because `fnTagDecide`'s mint path sees an
incomplete instance:

- Mint facts are noted only by `holeCallNodeTy`, which `genFnHoleCallOwn` runs on each hole
  call's ARGUMENT node. So `g(x)` (an argument of `h`) and `h(x)` (an argument of `g`) get facts,
  and the outer calls `h(g(x))` and `g(h(x))` never do. `ftMintComplete` then refuses `g`'s set.
- Noting the outer call's fact in `genFnHoleCallOwn` (where its closed instance is already
  computed) gives all four calls facts. `ftTry` then stops at `ftPlainArgs`, which refuses an arm
  whose argument is a call (`g(h(x))`).
- Admitting a call argument there tags the set. The build then refuses with `ref valtype with no
  interned shape` at the call site. Across 17,265 files the producer alone moved 16 files, 6 of
  them from runs to not-runs. Five of those are a one-member set the split plan copied, now
  tagged and refused by the monomorphizer (`is called at two instances of the function handed to
  it`), and one traps the compiler. Limited to sets of two or more, it moves 4 files, one of them
  from runs to invalid wasm (`generics/hole-fn-choice-nested-positions.vl`, inside `both`).

The runs-to-invalid file reduces, by deleting cases while the failure holds, to `both(f)`
handed two different sets (`if c { inner } else { ask }` and `if tick() { inner } else { twice }`)
beside the impure-choice spellings (`compound`, `both2`). With complete facts one set is tagged,
so its parameter is an `i32` id, while the other stays a closure, and both share one emitted body
of `both`: `expected (ref null $3), found i32`.

Reduced further by line deletion, the regression is one set handed to a function that calls it
once and to another that calls it at two tuples:

    function both(f) { return f(1) }
    function inner(s) { return s }
    function ask(s) { return s }
    function nestedArg(c) { print(both(if c { inner } else { ask })) }
    nestedArg(true)
    function both2(k: i32, f) {
      print(f("a"))
      return f(k)
    }
    print(both2(3, if true { inner } else { ask }))

The producer notes facts for `both2`'s two calls (it runs where the split plan counts a
parameter's instances) and none for `both`'s single call, so `ftMintComplete`, which checks only
instances that hold facts, lets `both2`'s facts tag the set while `both`'s body is still built
for a closure. Two different sets each tagged at their own function run (`a 1 aa 2`); the gap is
an instance whose calls the producer never visits.

So the producer has to visit every call through a set-bound hole parameter in every instance,
then the arm builder's argument rule and the emitter's per-tuple reader land with it.
