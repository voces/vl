### D14439 — a two-member set handed to a hole parameter called at two tuples builds invalid wasm

**check-clean invalid wasm · `expected i32, found (ref $type)` inside `lapBack` · clause 1 · open · the one-member spelling `lapBack(wrap, pair, 4)` runs · deleted by the mint's emitter reader (D14430), which instances each call of the set at its own tuple · filed 2026-10-28 against master `4638042eb`**

Repro:

    function wrap(a) { return [a] }
    function wrap2(a) { return [a, a, a] }
    function pair(a) { return [a, a] }
    function lapBack(g, h, x) {
      print(h(g(x)).length)
      print(g(h(x)).length)
      return 0
    }
    const c = true
    lapBack(if c { wrap } else { wrap2 }, pair, 4)
    // Want: 2, 1

#### Mechanism

`g` is called at `i32` and at `i32[]` in one instance of `lapBack`, and `h` is called on
`g`'s result. With one member, the split plan gives `g` one copy per instance (D6210). With two,
the set is handed on as itself and the instance has one body, so one of the two calls is
emitted at the other's tuple.

Measured 2026-10-29 by probe. The split plan hands the one-member `h` two closure parameters
(`h` at `i32` and at `i32[]`) and the two-member `g` one, typed `i32 => i32[]`, which `g(h(x))`
then calls with an `i32[]`. The set is never tagged because `fnTagDecide`'s mint path sees an
incomplete instance:

- Mint facts are noted only by `holeCallNodeTy`, which `genFnHoleCallOwn` runs on each hole
  call's ARGUMENT node. So `g(x)` (an argument of `h`) and `h(x)` (an argument of `g`) get facts,
  and the outer calls `h(g(x))` and `g(h(x))` never do. `ftMintComplete` then refuses `g`'s set.
- Noting the outer call's fact in `genFnHoleCallOwn` (where its closed instance is already
  computed) gives all four calls facts. `ftTry` then stops at `ftPlainArgs`, which refuses an arm
  whose argument is a call (`g(h(x))`).
- Admitting a call argument there tags the set. The build then refuses with `ref valtype with no
  interned shape` at the call site. Across 17,265 files the producer alone moved 16 files, 6 of
  them from runs to not-runs. Five of those are a one-member set the split plan copied, now
  tagged and refused by the monomorphizer (`is called at two instances of the function handed to
  it`), and one traps the compiler. Limited to sets of two or more, it moves 4 files, one of them
  from runs to invalid wasm (`generics/hole-fn-choice-nested-positions.vl`, inside `both`).

The runs-to-invalid file reduces, by deleting cases while the failure holds, to `both(f)`
handed two different sets (`if c { inner } else { ask }` and `if tick() { inner } else { twice }`)
beside the impure-choice spellings (`compound`, `both2`). With complete facts one set is tagged,
so its parameter is an `i32` id, while the other stays a closure, and both share one emitted body
of `both`: `expected (ref null $3), found i32`.

Reduced further by line deletion, the regression is one set handed to a function that calls it
once and to another that calls it at two tuples:

    function both(f) { return f(1) }
    function inner(s) { return s }
    function ask(s) { return s }
    function nestedArg(c) { print(both(if c { inner } else { ask })) }
    nestedArg(true)
    function both2(k: i32, f) {
      print(f("a"))
      return f(k)
    }
    print(both2(3, if true { inner } else { ask }))

The producer notes facts for `both2`'s two calls (it runs where the split plan counts a
parameter's instances) and none for `both`'s single call, so `ftMintComplete`, which checks only
instances that hold facts, lets `both2`'s facts tag the set while `both`'s body is still built
for a closure. Two different sets each tagged at their own function run (`a 1 aa 2`); the gap is
an instance whose calls the producer never visits.

Running `genFnHoleCallInsts` in `judgeFnArgHoleCalls`' choice-argument branch as well makes the
producer visit `both`'s call, bound to the same set (`fnTagSetOfTy` answers it there). The module
is still invalid at the same place: `both`'s body is emitted for a closure while its caller hands
it the tagged id, so a function calling its set once is not instanced at the set.

Three further measurements on the reduced witness, each reverted:

- The producer's call to `mintCallNote` has to bind the called parameter to the set: the
  `vTys` it is handed have that hole pinned to an instance function type by
  `instGenFnHolePins`, so `fnTagSetOfTy` answers -1 and no fact is noted. With a copy binding
  `vTys[k]` to `vt`, `both`'s call is noted.
- `emitTagSetAt` reads the set off `nodeTyAt(f, fnIx)` and else `fnTagCallSetOf`, neither of
  which a call inside `both` carries. A fallback to the one set every mint fact for the call names
  makes `both` dispatch on the id.
- The dispatch then calls `inner` and `ask` at `string`, the instance their set's leaves were
  typed at, not at `i32`; typing the arm's callee from the fact's parameter types and results
  does not change the instance chosen, because the emitted `both` is the template body.

So three pieces land together: the producer visiting every call through a set-bound hole
parameter in every instance, the arm builder admitting a call argument (`ftPlainArgs`), and the
emitter instancing each body that receives a tagged set at that set, a single call included.

#### The emitter piece, measured 2026-10-29

Built on the three pieces above, five more changes make the reduced witness run (`1`, `a`, `3`):

- the producer runs in `genFnHoleCallOwn` for a set of two or more members only, with the
  called parameter bound to the set; one-member sets moved 12 files from runs to not-runs;
- each dispatch arm calls its member at the call's own tuple (`mkFuncTy(wp, rs[k])`, `wp` a new
  per-fact column of parameter types), not at the member's leaf type, so `inner` is called at
  `i32` inside `both`, not at the `string` instance `both2`'s leaves were typed at;
- `monoTagSetAt` (emit_mono.vl) falls back to the one set every fact for the call names, so mono
  instances the arms of a call inside a set-keyed instance (mono already keys such an instance
  apart by `#set<id>`, `monoSetPinDiscrim`);
- `emitTagSetAt` (wasmEmit.vl) reads the callee's set from the instance's elaboration
  (`elabNodeTyAt`), so one instance dispatches on the id while another, holding an untagged set,
  calls the closure;
- a set with a leaf inside a generic or hole function's body and a fact noted against it stays
  untagged, since its tag is per instance, which a call fact cannot name yet.

Over 17,267 files that left three moved: `generics/hole-fn-choice-nested-positions.vl` and
`generics/hole-fn-choice-beside-open-param.vl` from runs to not-runs, and
`closures/error-hole-fn-written-element-handed-to-param.vl` from a check refusal to invalid wasm
(a split result through `apply`). The nested-positions file reduces to two sets handed to one
`both(f)` that calls `f` at two tuples: the split plan (D6210) gives `both` one closure parameter
per tuple, so the tagged set's instance takes two parameters whose renamed reads carry neither
the instance's set nor its facts, and the call site passes ids into the split's closure slots.
The next piece is the split plan standing down for a parameter a tagged set reaches.
