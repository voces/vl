### D6532 — a hole function passed to a hole parameter bound to another hole function is refused as a call to an unknown function

**closed 2026-10-18 by lane L1 · runs, prints `2` · was a loud emit reject · clause 2 · the open function value a hole's call hands on now takes the instance the receiving hole function's body calls it at, in the checker (so the hole call's result is closed) and in the flow pin (so the value is built at that parameter type) · pin: `tests/cases/generics/hole-fn-arg-through-hole-callee.vl`, `tests/cases/generics/error-hole-fn-arg-through-hole-callee-result.vl` · found closing [D6481](D6481.md) · filed 2026-10-18 against master `698648f78`**

Repro:

    function id(a) { return a }
    function lap(g) { return g(1) + 1 }
    function use(k) { return k(id) }
    print(use(lap))
    // vl check: rc 0.  vl run: emitProgram: call to unknown function (at 2:10)

Want:

    2

#### Mechanism

`use(lap)` binds `k` at `lap`'s hole signature, and `k(id)` hands `id`'s own hole signature to
`lap`'s `g`. Both sides were open, so in the checker `genFnHoleCallBind` returned "open" and the
`HD_RET` row fell back to `use`'s open `fnRet`; in the emitter `monoHoleGenFnFlowTy` bound `k`
with `g` still a type variable, and the pin ladder fell to the `i32` default with no function
for `g`. The checker now asks `lap`'s body what it calls `g` at (`holeFnArgInst`, through
`genFnHoleInstance`), and the emitter reads the same calls from the flow table
(`monoHoleGenBindFnArgs`) and delivers `id` at that type.

The emit half alone was a loud→silent conversion: `const s: boolean = use(lap)` passed check
with the open result and printed `true`. The checker half is what refuses it.
