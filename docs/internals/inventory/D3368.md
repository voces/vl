### D3368 — an element read of a join of two un-annotated list parameters refuses at the call where the `<T>` and direct spellings run

**loud check reject · clause 2 · the hole spelling printed a wrong value, built an invalid module or refused at emit on master `6e6a5301b` · found by lane UG (71 `arrj` cells of the tp-join grid whose `<T>` twin runs) · filed 2026-09-30**

Repro:

    function g(a0, a1, k: i32) {
      const r = if k == 0 { a0 } else { a1 }
      const e = r[0]
      print(e)
    }
    const x0: boolean = true
    const x1: i32 = 4
    g([x0], [x1], 0)
    g([x0], [x1], 1)
    // vl check: `cannot index non-array boolean[] | i32[] (the body of `g` at the call's argument types)`

Want:

    true
    4

#### Mechanism

The body reads `r[0]` over `?a0 | ?a1`, a gradual union, so the read is deferred to each call
(`tpGradualRecv`), and the call re-asks it of `boolean[] | i32[]` through `indexFloorMsg`, which
knows no union of lists. The direct spelling indexes that union, and the `<T>` spelling rewrites
the read as a narrowing chain over `T0[] | T1[]` (D2760), which the hole spelling does not have.
Lane UG tried `indexFloorMsg` accepting a union of lists: the program then reached the emitter
and refused there (`index receiver is not an array or string`), so the change was not kept.
