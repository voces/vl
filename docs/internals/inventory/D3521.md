### D3521 — a nested lambda's join of two parameters at an `i32` and an `f64` pin returns the `f64` from an `i32` result

**closed 2026-10-03 — the witness prints `2.5` · was check-clean invalid wasm, clause 1 · found by the #3342 review · filed against master `b2238d2c6`, closed against master `331f5e998` by lane LJ with [D3520](D3520.md) · fixture `tests/cases/generics/lambda-join-type-params-keeps-null.vl`**

Repro:

    function F<A, B>(k: i32, a: A, b: B) {
      const g = () => {
        const h = () => { if k == 0 { a } else { b } }
        h()
      }
      g()
    }
    print(F(1, 3, 2.5))
    // vl check: rc 0.  vl run: invalid module inside `__lambda_2`, "type mismatch: expected i32, found f64"

Want:

    2.5

#### Mechanism

[D3520](D3520.md)'s: `g`'s call of `h` collapsed `h`'s deferred join `A | B` to `A`, so `g`
(`__lambda_2`) was built with an `i32` result while `h` returned the `f64`. Kept apart, `h`'s
join is `i32 | f64` at this pin, a union of runtime numbers per the numeric-join ruling, and
`g` returns that box. A separate face fixed with it: an `i32 | f64` value compared `== null`
was refused at check (`operator '==' is not defined`), filed and closed as [D3527](D3527.md). The holes spelling `F(k: i32, a, b)` is the same. Also
graded here, though their mechanism is not established: a `Box<i32> | i32` binding
reassigned to a record, or a record stored as that map value (the review's `u6__let` and
`u6__map`). Those are invalid wasm because the union's rep is taken as a scalar: `let u:
Box<i32> | i32 = 1; u = { v: 7 }` fails with "expected i32, found (ref $type)". The same
program with a plain record `B` runs. They are a different mechanism, filed as
[D3526](D3526.md).
