### D3521 — a nested lambda's join of two parameters at an `i32` and an `f64` pin returns the `f64` from an `i32` result

**check-clean invalid wasm · open · clause 1 · the same on master `b2238d2c6` · found by the #3342 review · filed 2026-10-03 against master `b2238d2c6`**

Repro:

    function F<A, B>(k: i32, a: A, b: B) {
      const g = () => {
        const h = () => { if k == 0 { a } else { b } }
        h()
      }
      g()
    }
    print(F(1, 3, 2.5))
    // vl check: rc 0.  vl run: invalid module inside `__lambda_2`, "type mismatch: expected i32, found f64"

Want:

    2.5

#### Mechanism

Not confirmed. The inner lambda `h` joins `A` and `B`, which pin to `i32` and `f64`, so its
result should widen to `f64`. `__lambda_2` is emitted with an `i32` result instead, and the
`f64` arm is returned unconverted. The holes spelling `F(k: i32, a, b)` is the same. Also
graded here, though their mechanism is not established: a `Box<i32> | i32` binding
reassigned to a record, or a record stored as that map value (the review's `u6__let` and
`u6__map`). Those are invalid wasm because the union's rep is taken as a scalar: `let u:
Box<i32> | i32 = 1; u = { v: 7 }` fails with "expected i32, found (ref $type)". The same
program with a plain record `B` runs. These two cells need their own row once an ablation
separates them.
