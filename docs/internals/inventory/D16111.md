### D16111 — a generic with a fixed parameter named at a closed function type whose parameter is narrower is refused, though the same function delivered through a written `let` runs

**loud check reject · `argument 1: expected (i32, boolean) => void, got (i32 | string, B) => void` · clause 2 · the delivery needs `B` bound and an adapter at the fixed parameter, which the `let` path builds · filed 2026-11-14 against master `43943a5bf`**

Repro:

    function w<B>(a: i32 | string, b: B) {
      print(a)
      print(b)
    }
    function run(f: (a: i32, b: boolean) => void) { f(9, false) }
    run(w)
    // vl check: argument 1: expected (i32, boolean) => void, got (i32 | string, B) => void

Want:

    9
    false

#### Mechanism

A generic named at a closed function type is instantiated by binding its type parameters
against the destination's parameters. A parameter the generic fixes (`i32 | string`) and the
destination narrows (`i32`) is not adapted on that path, and `assignable` refuses the open
`B` against `boolean`. Through `let k = s; k = w; run(k)` the write is adapted at the call's
types (`fsbAdaptWrites`), so it runs. D15956's close keeps a binding with such a member on that
path (`fnParamsAllTyParams`, check_narrow_flow) for this reason.
