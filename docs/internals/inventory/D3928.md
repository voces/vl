### D3928 — a capturing hole lambda inside a generic, called at one type and then delivered as a value at another, builds invalid wasm

**check-clean invalid wasm · found in review of #3490 (`rv3490/v3c_hole_lambda_no_alias`; `v3b` one instance is the control) · filed 2026-10-09 against master `255fc7a6c`**

Repro:

    function call(f: (n: i32) => void) { f(1) }
    function outer<T>(x: T) {
      const h = (u) => { print(x); print(u) }
      h("s")

    }

    outer("s")
    // vl check: rc 0.  vl run: the emitted module failed to validate inside `outer$1`

#### Mechanism

Not located. The lambda twin of D3905: a hole lambda capturing the enclosing generic's `x`, called
at `string` and then handed to a `(n: i32) => void` parameter. The frame keying of a capturing
nested generic's value (D3902) covers a named nested function, not a hole lambda.
