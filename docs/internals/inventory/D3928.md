### D3928 — a capturing hole lambda inside a generic, called at one type and then delivered as a value at another, builds invalid wasm

**closed 2026-10-10 by lane SC · runs · was check-clean invalid wasm · found in review of #3490 (`rv3490/v3c_hole_lambda_no_alias`; `v3b` one instance is the control) · filed 2026-10-09 against master `255fc7a6c` · pins: `tests/cases/generics/capturing-hole-lambda-called-then-delivered-as-value.vl`**

Repro:

    function call(f: (n: i32) => void) { f(1) }
    function outer<T>(x: T) {
      const h = (u) => { print(x); print(u) }
      h("s")
      call(h)
    }
    outer(7)
    outer("s")
    // vl check: rc 0.  vl run: the emitted module failed to validate inside `outer$1`

Want:

    7
    s
    7
    1
    s
    s
    s
    1

#### Mechanism

The value `h` in `call(h)` was one node across both instances of `outer`. The first instance's
coercion renamed it in place to that frame's lambda instance at `i32`, and the second instance
then read the first frame's lambda, whose env holds `x` at the first type. A call through a hole
lambda's binding was already copied per instance (D2854); a read of it as a value was not.
Closed: a value naming a hole lambda's binding is copied per instance, as a callee is. An alias
of it delivered into a list or record literal after a call at another type still traps (D3934).
