### D15313 — a `??` default held in a binding, for a read of a container built wider, is refused inside a list or record literal

**open · loud check reject · `a ?? whose default is a binding, built at J for a read of a container built wider, is not yet supported inside a list or record literal` · clause 2, capability: the literal raises goal-scoreboard's conceded-capability count by one until this row closes · probe `capability-probes/coalesce-held-default-in-literal.vl` · built invalid until D15312 · the written default runs · found closing D15312 · filed 2026-11-04 against master `f53e406f5`**

Repro:

    type J = { f: i32 | null }
    function mk() { { f: 4 } }
    const m = Map()
    m.set("a", mk())
    const wm: {[string]: J} = Map()
    wm.set("a", mk())
    const dl = { f: 1 }
    const xs = [m.get("a") ?? dl]
    print(xs[0].f ?? 0)

Want:

    4

#### Mechanism

A `??` default held in a binding is built at the read's record by adopting the binding there
(D15217, D15240), while the literal slot holding the join is built by the store column
(`storeSlotHeldAt`, D15312); the two builds do not meet, and emit refused the list element ("a value
that fits `J` may be stored as another arm") and built the record field invalid. `storeSlotHeldAt`
refuses the slot at check instead. A nested record's `??` is D15310's emit refusal.

| the join bound first (`const b = m.get("a") ?? dl; [b]`) | still refused | no |
