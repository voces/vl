### D3640 — a UFCS call naming a block-local `self`-function is typed against the module's function once a merge renames it

**loud check reject · open, needs a language ruling: is a block-local `self`-function a UFCS target? · filed 2026-10-04 by lane LF against master `221c7954f`, while grading D3608**

Repro:

    import { hypotF64 } from "std:math"
    function dbl(self: i32): i32 { self * 2 }
    function f() { function dbl(self: i32): string { "loc" }; const s: string = 3.dbl(); print(s) }
    f()
    print(hypotF64(3.0, 4.0))
    // vl check: cannot assign i32 to 's' of type string at 3:77. Without the import the program prints loc.

#### Mechanism

In a single module the checker resolves `3.dbl()` through its scope, so the block-local `dbl`
types it (`string`) from its declaration to its block's end, and the module's `dbl` types it
elsewhere; since D3608's close the emitter calls the same function. The merge renames the
module's `dbl` to `dbl$m0` and banks that name on the call site (`modSelfFnTarget`,
`compiler/driver.vl`), so the merged checker types the call against the module's function and
refuses the program. Banking the plain name where a block-local function shadows it does not
help: the checker then refuses `member access '.dbl' on non-object i32`, which is also what a
single module says when no MODULE function of the name exists, however a block-local one is
declared. So the checker's UFCS gate asks whether a module-level `self`-function of the name
exists and then types the call through the scope: the two halves disagree.

#### Ablation

| spelling | single module | merged |
| --- | --- | --- |
| module `dbl` and a block-local `dbl`, call inside the block | runs, the block-local one | refused, typed as the module's |
| the call above or after the block | runs, the module's | runs, the module's |
| no module `dbl`, only the block-local one | refused, `non-object i32` | refused, `non-object i32` |

#### Grading list

The ruling: (a) UFCS reaches whatever `self`-function the name denotes at the call, a
block-local one included, as a direct call does; or (b) UFCS reaches only module-level
`self`-functions, so a block-local one never answers a member call. **Recommendation (b)**, as
the smaller surface: a `self`-function is a module's method-like API, and (b) is what a single
module already does when no module function of the name exists. Under (b) the checker types
the call above against the module's function in a single module too, and the emitter's
`lfFnAt` must not answer a minted UFCS callee. Under (a) the merge banks the plain name where
a block-local function shadows the module's, and the checker's gate asks the scope. Grade both
compiles, with and without a module function of the name.
