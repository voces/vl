### D4061 — a positional argument after a named one, or before a named one that names its own parameter, binds to a later parameter instead of being refused

**closed 2026-10-11 by lane NA — now a loud check reject (`` `h` is parameter 2 but is written in position 1, which is `w`'s; name the arguments after it, or move it ``) · was check-clean silently wrong value · the program is ill-typed under the Q8 ruling · found writing `docs/spec/expressions.md` (lane SPEC) · filed 2026-10-11 against master `98a4ed71b` · pins: `tests/cases/functions/error-named-arg-out-of-position.vl`, `tests/cases/functions/named-args-positional-after.vl`, `tests/cases/modules/err-named-arg-position-import/`, `tests/cases/modules/named-arg-position-overload/`, `tests/vl_check_fix_test.ts`**

Repro:

    function box(w: i32, h: i32): i32 { w * 10 + h }
    print(box(h: 3, 2))
    // vl check: rc 1 — `h` is parameter 2 but is written in position 1, which is `w`'s; name the arguments after it, or move it
    // was: vl check rc 0, PRINTS 23

Want:

    a check error at the `2`: a positional argument follows `h:`, which is not in its own
    position (parameter 1 is `w`)

#### Mechanism

The call binder (`compiler/ast.vl`, "First place named arguments by parameter name") places
every named argument first, then fills the parameters still unbound with the positional
arguments in declaration order, wherever those stand in the call. So a positional argument
does not land at its written index. The Q8 ruling (DECISIONS.md §"A positional argument
lands at its written index") requires that it does, and refuses every call where it could
not.

#### Ablation

| call | today | under the ruling |
| --- | --- | --- |
| `box(w: 3, 2)` | 32 | 32 |
| `box(h: 3, 2)` | 23 | refused: `h` is not in its own position |
| `box(3, w: 2)` | 23 | refused: `w` is given twice |
| `box(3, h: 2)` | 32 | 32 |

#### Grading list

Each ablation row grades as the ruling column. A method call `x.f(…)` counts the receiver
as position 0. The 14 diderven calls of the shape `gear("Copper Sword", SN_ANVIL, base: 100,
[...])` (`src/craft/recipes.vl`) name their own position and must keep compiling.

#### Close

`orderNamedCallArgs` (`compiler/typecheck.vl`) now refuses both faults before it binds; the
binder is unchanged, since every call the rule accepts already bound correctly. A positional
argument after a misplaced name is refused at that argument (code
`named-arg-out-of-position`), and `check --fix` names it and each later positional argument
for the parameter it bound before the ruling, which keeps the program's meaning. A name given
twice (`` `w` is already given by the positional argument in position 1; give it once ``) has
no mechanical fix. Positions and parameters are counted from 1 within the parentheses, so a
method call's receiver is position 0 and `self` parameter 0. The 14 diderven `gear(…, base: …,
[...])` calls name their own position and check clean, unchanged.
