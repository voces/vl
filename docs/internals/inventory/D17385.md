### D17385 — a returned record literal whose nested field literal sits at another rep of its row is not built in the IR

**runs today and must keep running · the IR names it `return coercion nested twin`, legacy writes it · found by lane IR-D1's return-coercion matrix · filed 2026-11-24 against master `864119c9f`**

Repro:

    type J = { f: i32 }
    type K = { j: J | null }
    type W = { k: K }
    function mk() {
      return { k: { j: { f: 4 } } }
    }
    const y = mk()
    print(y.k.j.f)
    const w: W = mk()
    print(w.k.j?.f ?? 0)

Want:

    4
    4

#### Mechanism

The outer literal is built at the result's rep at its layout row (the return-coercion rule), but
its field `k`'s literal is built at its own row's recorded rep, not the field's (`K`'s twin with
`j` nullable). Delivering it into the field would take a record retag the verifier refuses
(rule 2), so the builder misses by name and legacy writes the function. The fix is the same
row-equals-destination rule at a field delivery (`objLit`), not only at the return.

#### Ablation

| ingredient removed | outcome | needed? |
| --- | --- | --- |

| the inference (`function mk(): W`) | built in the IR, matched | **yes** |
