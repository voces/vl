### D9071 — a declared generic as a `.map` callback inside a generic instance over `T[]` takes no instance

**closed · runs, prints `9` · was check-clean invalid wasm, `type mismatch: expected structref, found i32` · clause 1 · found closing [D9004](D9004.md) · present on master `26a6dc669` · filed 2026-10-21 against master `26a6dc669` · closed with D9004 by `monoCoerceListCbArg` (emit_mono.vl) reading the receiver at the instance's binding · fixture `closures/generic-fn-as-list-callback-result.vl`**

Repro:

    function wrap<T>(t: T): T[] { return [t, t] }
    function keep<T>(t: T): boolean { return true }
    function idg<T>(t: T): T { return t }
    function hw<T>(xs: T[]): T[][] { return xs.filter(keep).map(idg).map(wrap) }
    print(hw([8])[0][1] + 1)
    // master: vl check rc 0, vl run: invalid module inside `hw`, type mismatch: expected structref, found i32

#### Mechanism

The instances of a generic share their body's nodes, so the receiver of `.map` inside `hw`
records `T[]`. `monoCoerceListCbArg` read that recorded type, found an open element and
took no instance of the callback; the emitter then built the mapped list from the generic
template's signature. It now reads the receiver at the instance's binding
(`monoExactPinTyOf`), so each instance takes the callback at its own element.
