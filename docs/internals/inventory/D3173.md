### D3173 — a function value with a `boolean | null` result or parameter cannot be passed to an un-annotated parameter

**closed · runs, prints `false` · was loud emit reject, `vl check` rc 0, clause 2 · found by lane WV's D3167 grid (`fnval`, every `nulB` cell of the `hole` callee, 68 of 810) · filed 2026-09-29 against master `a0b9acaf8` · closed by `boolean | null` keying its i32 token `i` in the function-value argument's pin (`sigRepTokOfTy`, emit_sig_tokens.vl) · fixture `closures/fn-value-nullable-map-null-bool-sig.vl` · with [D9824](D9824.md) closed**

Repro:

    function H(h) {
      return h()
    }
    print(H((): boolean | null => false))
    // vl check: rc 0.  vl build: emitProgram: monomorphize: unsupported argument type for `h`
    // in a call to `H`

Want:

    false

#### Mechanism

Not localised past the ablation. A function-value argument pins its hole parameter by its
`$fnsig` key (`sigKeyOfTy`), and `boolean | null` has no token in that vocabulary, so the pin is
empty and the monomorphiser refuses. `i32 | null` and `string | null` have tokens and run. A
generic parameter typed `() => Y` binds `Y` instead and runs.

#### Ablation

| ingredient changed | outcome | needed? |
| --- | --- | --- |
| `(): i32 \| null => 3` | runs | **yes** (the `boolean \| null` niche) |
| `(): string \| null => "s"` | runs | **yes** |
| `function H<Y>(h: () => Y): Y` | runs | **yes** (the hole) |
| `(x: boolean \| null) => x == true`, the parameter | the same refusal | no |
| `const q = …`, then `H(q)` | the same refusal | no |
