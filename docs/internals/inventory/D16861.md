### D16861 — the IR returned a block body's last statement as its value, where the body runs past it to `null`

**runs today and must keep running · the IR shadow under a claim only (`CLAIMED` is empty) · filed 2026-11-16 against `ir-i8b2-sink` `8eadc0054`**

Repro:

    function put(x: i32) { return x * 2 }
    function f(b: i32) {
      if b >= 0 { return 0 }
      put(9)
    }
    print(f(-1) ?? 5)

Want:

    5

#### Mechanism

A block body returns a value only through `return` (`block_body.vl`): `f` runs past `put(9)`,
drops its value and returns `null`, so its result is `i32 | null`. The IR builder's `tailReturn`
treated every non-void body's last statement as its value and delivered it into the result's rep.
Once I8b admitted the boxed nullable rep, that built `RToBox(put(9))` where legacy writes
`drop(call put)` and then the null box, so a claim printed 18. It surfaced on the self-compile as
`emitListIdxBackRef` boxing tag 224 against legacy's null-unit 230. It was briefly fenced by a
`box of a call` miss, which a non-call tail slips past. The builder now asks `isBlockBody` and names
`block body falls off`.

#### Ablation

Run under mode 3 with a claim-all throwaway compiler that has the defect.

| spelling of `f`'s last statement | legacy | claim with the defect | needed? |
| --- | --- | --- | --- |
| `put(9)` | 5 | 18 | — |
| `b + 100` (not a call) | 5 | 99 | no: any tail expression |
| `return put(9)` | 18 | 18 | **yes**: falling off the body |
| the early `return 0` removed | `f` has no value; the builder's void path | — | **yes**: a valued result |
