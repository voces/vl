### D8203 — a record literal through a generic identity into a union member is re-built from the literal's own row when that row has an instance of its own

**check-clean invalid wasm · `vl check` rc 0 · clause 1 · open · present on master `be738c9f0` · either delivery alone prints its field after [D8021](D8021.md) · found by the D8021 fix · filed 2026-10-20 against master `be738c9f0`**

Repro:

    type J = { r: i32 | null }
    function idn<T>(v: T): T { v }
    const w = idn({ r: 5 })
    print(w.r)
    const u: J | string = idn({ r: 4 })
    if u is J { print(u.r ?? 0) }
    // vl check: rc 0.  vl run: invalid module, "expected (ref null $6), found (ref $3)": `{r:i32}` expected, `J` found

Want:

    5
    4

#### Mechanism

Since D8021 the second call takes its own instance `idn<J>` and returns a `J`. The union
delivery still resolves the call's record row from its checked type `{r: i32}`, by name first
(`structIndexOfExpr`'s `nodeTyCanonObjName` rung, emit_classify.vl). Here the first call gave
`{r: i32}` a row, so the delivery reads the `J` it is handed as a `{r: i32}`, converts it to `J`
field by field, and boxes that. Without the first call `{r: i32}` has no row, and the delivery
boxes the call result directly. With the two calls in the other order the emitter refuses with
`ref valtype with no interned shape`.

#### Ablation

| change | outcome | needed? |
| --- | --- | --- |
| delete the first call | prints `4` | **yes**, the own-row instance |
| `const w = idn({ q: 5 })` | prints `5`, `4` | **yes**, the same field set |
| `const u: J = idn({ r: 4 })` | prints `5`, `4` | **yes**, the union destination |
| `const u: J | string = { r: 4 }` | prints `5`, `4` | **yes**, the type parameter |

#### Grading list

The two calls in the other order, which must run rather than refuse at emit, and the
`generic-identity-literal-into-record-union` matrix with a prelude `const w = idn({ r: 5 })`.
