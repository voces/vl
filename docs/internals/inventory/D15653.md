### D15653 — an `if` join of a record literal and a maker's call an annotated binding builds wider is check-clean invalid wasm

**open · check-clean invalid wasm · clause 1 · `the emitted module failed to validate inside the module's top-level code: … type mismatch: expected (ref $1), found (ref $0); $1 is \`#anon1\`, struct {mut i32}; $0 is \`J\`, struct {mut (ref $3)}` · found closing D15380 · filed 2026-11-10 against master `171a2d4f`**

Repro:

    type J = { f: i32 | null }
    function mk2() { { f: 1 } }
    const dA: J = mk2()
    print(dA.f ?? 0)
    const k = 1
    const b = if k > 0 { { f: 4 } } else { mk2() }
    print(b.f)

Want:

    a check reject at `mk2()`, as `m.get("z") ?? mk2()` is refused

#### Mechanism

Not ablated past the table. `mk2` is kept at `J` by the annotated binding, so its calls are built
there. A `??` default is checked assignable to the left operand's type, which pends it
(`recPend`, check_assignable.vl), and `recKeptConflicts` refuses it at its own type. An `if` or
`match` join unifies its arms with no pending pair, so the call arm is never asked: the join is
typed `{f: i32}` and the arm hands over a `J`.

| both arms the maker's call | runs |
