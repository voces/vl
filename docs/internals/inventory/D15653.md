### D15653 — an `if` join of a record literal and a maker's call an annotated binding builds wider is check-clean invalid wasm

**closed 2026-11-11, runs and prints `1` then `4` · was a loud check reject, owed · closed by the fresh-call copy (`recFreshCallCopy`, `recHeldFreshCopy`, check_fit_rules.vl): a maker called more than once keeps its own record, and a delivery whose destination stores a field differently copies the call there, so no other delivery reads it at another row · graded by `scripts/capability-probes/matrix/kept-maker-delivery.matrix.vl` · found closing D15380 · filed 2026-11-10 against master `171a2d4f` · fixtures `tests/cases/soundness/if-join-of-literal-and-kept-maker-call-runs.vl`, `tests/cases/soundness/if-join-of-kept-maker-calls-runs.vl`**

Repro:

    type J = { f: i32 | null }
    function mk2() { { f: 1 } }
    const dA: J = mk2()
    print(dA.f ?? 0)
    const k = 1
    const b = if k > 0 { { f: 4 } } else { mk2() }
    print(b.f)

Want:

    1
    4

#### Mechanism

Not ablated past the table. `mk2` is kept at `J` by the annotated binding, so its calls are built
there. A `??` default is checked assignable to the left operand's type, which pends it
(`recPend`, check_assignable.vl), and `recKeptConflicts` refuses it at its own type. An `if` or
`match` join unifies its arms with no pending pair, so the call arm is never asked: the join is
typed `{f: i32}` and the arm hands over a `J`.
