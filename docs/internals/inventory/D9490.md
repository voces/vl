### D9490 — a lambda whose body is a member literal is not taken as returning the numeric literal union its destination declares

**loud check reject · clause 2 · CAPABILITY: `const a: N = 2` runs, an annotated lambda `(): N => 2` runs, and the string twin `const h: () => K = () => "y"` runs · found closing [D9382](D9382.md) · present on master `56e51b394` · filed 2026-10-21 against master `56e51b394`**

Repro:

    type N = 1 | 2
    const h: () => N = () => 2
    print(h())
    // vl check: cannot assign () => i32 to 'h' of type () => N

Want:

    2

#### Mechanism

Not traced. The lambda's contextual return adoption (`finishInferredReturn`'s `cbExpectedRetFor` arms,
check_inferred_return.vl) widens a narrower numeric and re-encodes an f32 literal, but has no
arm that takes a numeric literal union whose members every returned literal is; the lambda
infers `() => i32`, which does not fit `() => N`. Adopting it needs every value return
checked against the members, not only the tail.

#### Ablation

| ingredient removed | outcome | needed? |
| --- | --- | --- |
| the lambda (a `function h(): N { 2 }` delivered) | runs | **yes** |
| the numeric union (`type K = "x" \| "y"`, `() => "y"`) | runs | **yes** |
| the expression body (`() => { return 2 }`) | same refusal | no |
| the binding (`call(() => 2)` into a `() => N` parameter) | same refusal | no |
