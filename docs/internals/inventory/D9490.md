Repro:

    type N = 1 | 2

    print(h())
    // vl check: cannot assign () => i32 to 'h' of type () => N

Want:

#### Mechanism

The lambda's contextual return adoption (`finishInferredReturn`, check_inferred_return.vl)
widened a narrower numeric and re-encoded an f32 literal, but had no arm for a numeric literal
union. The lambda inferred `() => i32`, which does not fit `() => N`. The new arm walks every
valued return and the tail (`a20RetWalk`) and adopts `N` only when each is assignable to it, so
`return 3` beside a tail `2` still refuses.

The one matrix cell left, `return_inferred` annotated, is a lambda returned from an
un-annotated function: it has no expected type where it is checked, and its string twin
refuses the same way.
