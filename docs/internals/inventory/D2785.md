#### Mechanism

Local slots came off one cursor in the order the collect pass allocated them, and that pass
reached an if-expression only as a function's binding initializer or `return` operand. A global's
initializer and a top-level expression statement run in the start function, whose collect walk
visited neither, so their arms had no slots at all. The close allocates such an arm's locals by
NODE (`declSlotByNode`, `collectExprArms`) wherever the collect walk meets the expression — every
statement's expressions, loop bounds, conditions, and each global's initializer — and the cursor
steps over those positions (`localByNode`), so no slot the cursor hands out moves. A program with
no such arm skips the walk (`scanExprArmLocals`).

| `i32` → `f64`, `f32`, `i64` or `string` arm values | still refused | no |
