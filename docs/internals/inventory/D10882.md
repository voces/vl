### D10882 — a field read through a generic alias's inline nested record, inside a generic body, has no struct receiver

**closed 2026-10-23 — the filed repro RUNS and prints `3` · was a loud emit reject, `emitProgram: field access receiver is not a struct` · clause 2 · found by lane C3 writing the type-parameter fields of `shapeFieldsRideTyParam` · filed 2026-10-23 against master `ec57e9a8e` · fixture `tests/cases/generics/alias-inline-nested-record-read.vl`**

Repro:

    type B<U> = { s: { g: U } }
    function f<T>(v: B<T>): T { v.s.g }
    print(f({ s: { g: 3 } }))
    // vl check: rc 0.  vl run: emitProgram: field access receiver is not a struct

Want:

    3

#### Mechanism

`paramStructIndexRaw` resolves a parameter's struct row from a declared name or an inline
shape. The instance's annotation `B<i32>` is neither, so `v` had no struct row and `v.s` no
receiver. A leg for a non-variant annotation whose rep type is a record (`TyObj`) now answers
`retStructRowIndex(p.parType)`, the row the annotation's type keys to. A list of the alias,
`B<T>[]`, is still refused (D10930).

#### Ablation
