### D4134 — `u as? B` on a union holding an alias of an `A` object yields a `B`-typed reference that a later write through the `A` alias falsifies

**check-clean silently wrong · found grading the #3568 position matrix · filed 2026-10-11 against master `efd3c3f15`**

Repro:

    type A = { x: i32 }
    type B = { x: 1 | 2 }
    function f(base: A) {
      const a: A | B = base
      const b = a as? B
      if b != null {
        base.x = 7
        const y: 1 | 2 = b.x
        print(y)
      }
    }
    f({ x: 1 })
    // PRINTS 7

#### Mechanism

`as? B` tests whether the value fits `B` (structurally, as `is` does) and yields it at type
`B | null`. The result is a second reference to the object `base` holds, typed `B`; the null
test narrows it to `B`, and a write through `base` ends nothing because `b` was never a
narrowing of `base`. `b.x` reads as `1 | 2` while it holds `7`.

#### Ablation

| ingredient changed | outcome on master | needed? |
| --- | --- | --- |
| the write removed | prints 1 | **yes** |
| `base as? B` directly on the `A` | check reject (`as` supports numeric conversions only) | **yes** (a union operand) |
| `if a is B` and a read of `a.x` | check reject (the narrowing ends on the write) | control |

#### Grading list

The same with `b` passed to a `B` parameter, and with the write inside a closure or a callee.
