Repro:

    type P = { a: i32, b: i32 }
    type Rows<T> = { base: i32, count: i32 }
    function g<T>(_r: Rows<T>, x: T): T { x }
    const st: Rows<P> = { base: 1000, count: 4 }
    print(g(st, 5))
    // vl check: print expects one scalar … got P; argument 2: expected P, got i32 (was rc 0, then invalid wasm at vl run)

#### Mechanism

`Rows<T>` does not use `T`, so the checker resolves `Rows<P>` to the same record as any other
`Rows<_>`, and nothing at the call binds `T` from the first argument, so the call checks with
`T` taken from `x`, an `i32`. The monomorphizer reads the written spelling `Rows<P>` and binds `T` to `P`, so the
instance takes a `P` where the caller passes an `i32`. The two passes disagree about one binding.

| ingredient changed | outcome | needed? |
| --- | --- | --- |

| `flat type P` | the same invalid wasm | no |
| result bound first (`const y = g(st, 5)`) | the same invalid wasm | no |

#### Grading list

The close must agree in both passes: either `T` binds to `P` at the check and `5` is refused,
or the phantom binding is dropped and the program prints `5`. The flat generic rows of
`tests/cases/memory/flat-generic-rows-*.vl` rely on a phantom `T` binding at the monomorphizer
and must keep their outcomes.
