### D3901 — a callback over an inline `{ v: Box<A> }` beside a `Box<A[]>` callback refuses: nested struct fields are not supported

**closed 2026-10-09 by lane SC · runs · was loud emit reject · found in review of #3473 · filed 2026-10-09 against master `9170959d8` · pins: `tests/cases/generics/generic-record-application-field-beside-row-sharing-field-name.vl`, `tests/cases/generics/type-arg-inline-object-field-collision.vl`**

Repro:

    type A = { x: i32 }
    function h<T>(x: T) { x.x }
    type Box<T> = { v: T }
    const ba: Box<A[]> = { v: [{ x: 1 }] }
    print([ba].map((e) => h(e.v[0]))[0])
    const o: { v: Box<A> } = { v: { v: { x: 6 } } }
    print([o].map((e) => h(e.v.v))[0])
    // vl check: rc 0.  vl build: emitProgram: nested struct fields are not supported

Want:

    1
    6

#### Mechanism

D3898's, one spelling over. The record `{ v: Box<A> }` is resolved to a row by its field names
(`structIndexOfTypeName`), and a field type spelled as a generic record alias's application
(`Box<A>`) classified to no field code, which the lenient arm accepted against any row field: the
`{ v: A[] }` row of `Box<A[]>` claimed it, and the literal's nested record had no struct field to
go into. The refusal named the symptom, not a design rule. Closed: an application of a generic
record alias, like an inline record, is compatible only with a struct field, and with a union
box only on the lenient pass.

#### Ablation

| ingredient removed | outcome | needed? |
| --- | --- | --- |
| the `Box<A[]>` row (or any other row with a field `v` not a struct) | runs | **yes** |
| the field a declared record (`{ v: A }`) | runs, since D3898 | **yes** |
