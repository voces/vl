### D16039 — `===` over a union with both record and function arms is refused, though every arm has an identity

**closed 2026-11-14 — `===` over a union of record and function arms compares each arm its own way · was loud check reject, `` `===` over a union of records and functions is not supported yet `` · clause 2 · found building the identity flag (D15975) · filed 2026-11-14 against master `384137871`**

Repro:

    type P = { x: i32 }
    function inc(i: i32) { return i + 1 }
    const p: P = { x: 1 }
    const u: P | ((i: i32) => i32) = p
    const v: P | ((i: i32) => i32) = inc
    print(u === u)
    print(u === v)

Want:

    true
    false

#### Mechanism

`tyHasIdentity` (compiler/check_identity.vl) accepts a union whose non-null arms are all records
or all functions, and refuses a mix. Under DECISIONS A15 every arm of the mix has an identity:
a record by `ref.eq` on the box's payload, a function by "same table index AND the same
captured-environment object". No single lowering serves both. The `ref.eq` arm would compare two
closure structs, which A15 says are not what is compared, and the `==` union core compares a
record arm structurally. The fix stages each operand's payload as an `eqref` (`emitIdentityMixed`):
two closures compare by declaration and environment, and anything else by `ref.eq`, which already
holds a record apart from a function and either apart from `null`, so no tag test is needed.
`tyHasIdentity` accepts the mix.
