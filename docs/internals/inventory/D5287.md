### D5287 — a list-literal arm of a `match` or `if` join is not adapted to the declared return

**closed · was loud check reject · clause 2 · eardstap EV-003 (first half) · filed 2026-10-17 against master `3f6a785db`**

Repro:

    type K = "a" | "b"
    function id<T>(xs: T[]): T[] { xs }
    function f(n: i32): K[] {
      match n { 0 => ["a"], _ => id(["a", "b"]) }
    }
    print(f(1).length)
    // vl check: expected K[], got string[] (with D5283 landed: K[] is not string[]: this join would hold both)

Want:

    2

#### Mechanism

A scalar literal arm adapts to the declared return through the join's arm fit
(`joinArmFits`/`litTyOfExpr`), which does not see a list literal, and the implicit tail banks
no expected type on the join node, so `["a"]` types as `string[]` and the join refuses. Teaching
the checker alone is not enough: the emitter would have to build the literal arm at the atom
list rep too. A trial that taught only the checker made the argument spelling check-clean invalid
wasm, so it was reverted. The error is printed once, not twice as the issue reported.

#### Ablation

| a scalar `K` return with `"a"` and `"b"` arms | runs | **yes** (the list) |
