### D8160 — an un-annotated function widening `i32` to `f64` is accepted at a function type returning `i32`, and traps at the indirect call

**now a loud check reject · filed 2026-10-20 against master `da93ef793` · clause 1, present on master · made loud by `genericFnAssignable` comparing the result the body gives at the target's parameters · fixture `closures/error-hole-fn-widening-bound-at-i32-result.vl`**

Repro:

    function half(a) { return a / 2.0 }
    const f: (i32) => i32 = half
    print(f(3))
    // master: vl check rc 0, vl run: wasm trap: indirect call type mismatch.  now: cannot assign (_) => _ to 'f' of type (i32) => i32

#### Mechanism

`genericFnAssignable` instantiated the source's declared result at the target's parameters.
That result is `T`, because the checker types `a / 2.0` as the hole `T`, so `(i32) => i32`
was accepted while the delivered function returns `f64`. It now takes the result from the
body at those parameters (`genFnHoleBodyRet`, as D8100 does) and compares that.

#### Ablation

| ingredient removed | outcome | needed? |
| --- | --- | --- |
| `a: i32` on `half` | check refuses | **yes** |
| the binding for an argument to `w(h: (i32) => i32)` | still traps on master | no |
| `function half` for `const g = (a) => a / 2.0` | still traps on master | no |
| `(i32) => i32` for `(i32) => f64` | runs, `1.5` | **yes** |

#### Grading list

`const g = (a) => a / 2.0; const f: (i32) => i32 = g` and `w(half)` with
`w(h: (i32) => i32)` refuse the same way. `id` at `(i32) => i32` and `(string) => string`, and
`inc` (`a + 1`) at `(f64) => f64`, still run.
