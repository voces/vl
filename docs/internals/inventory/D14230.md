### D14230 — `repSlotOfKind` answers no map shape for a map whose value is a declared record name, so the `Map()` constructor keeps a type twin of its own

**runs today and must keep running · 13 FILES of 6,701 `tests/cases` files · filed 2026-10-26 against master `8d0974164`**

Repro:

    type O = { v: i32 }
    type J = { f: O | null }
    const s = { f: { v: 4 } }
    const m = Map<string, J>()
    m.set("a", s)
    const x = m.get("a") ?? { f: { v: 9 } }
    print(x.f?.v ?? 70)
    // vl run: prints 4; `repSlotOfKind("map", {[string]: J})` answers -3, the constructor slot 0

Want:

    4

#### Mechanism

`emitMapNew` builds at `mapCtorShapeOf` (emit_shape_rows.vl). That function reads the stamp
through `mapFindShapeOfTy`, which shares `mapShapeOfValKeyed` with `mapFindShapeOfNodeTy`, so
the name-keyed mv-slot rule (`declRecNameAbove`) lives in one function. `repSlotOfKind` and
`repOfTy` (emit_rep_slot.vl) look the map up by key kind and value type alone, and they lack
that rule. A probe compared the two answers for every `Map()` and `Set()` constructor, with the
Set sentinels folded into their map ones. They disagreed in 13 files:

- 8 where the value is a declared record or union name, and `repSlotOfKind` answers -3
  (unsupported) or another slot, while the constructor answers a slot.
- 2 where a `Set()` with a hole element takes its key from its delivery (D14228).
- 1 where the binding's values are built at another record's storage
  (`recBuildElemTyOfInit`).
- 1 literal-union key in a hole-parameter instance (D14229).
- 1 `{[_]: _}` map with an unconstrained value.

The row closes when `repSlotOfKind` carries the name-keyed rule and `mapFindShapeOfTy` is
deleted.
