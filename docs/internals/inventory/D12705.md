### D12705 — a `for` variable over hole functions called at a second function type inside a closure is refused

**loud emit reject · `vl check` rc 0 · clause 2 · CAPABILITY: the same two calls directly in the loop run ([D10791](D10791.md)) · found closing [D10791](D10791.md) · filed 2026-10-25 against master `a448ccb42`**

Repro:

    import { toString } from "std:fmt"
    function cat(a, b) { return a + b.toString() }
    function snd(a, b) { return b }
    function apply2(g) { print(g("x", 2)) }
    function apply3(g) { print(g("y", 20)) }
    const fs = [apply2, apply3]
    for f in fs {
      const k = () => { f(snd) }
      f(cat)
      k()
    }
    // vl check: rc 0.  vl run: emitProgram: a function this call reaches through a list or join is already taken at another function type by an earlier call through it

Want:

    x2
    2
    y20
    20

#### Mechanism

D10791's close rewrites a call of the loop variable to read a copy at the loop's index only
when no function lies between the call and the loop (`fsFnBetween`, fn_split.vl), because the
closure would capture the index rather than the element. A capture of the index serves this
program equally, and is not built.
