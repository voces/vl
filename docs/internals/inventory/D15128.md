### D15128 — a by-rep identity's result handed to a hole parameter is instanced at its own row when the identity is also called at its own storage

**closed · now runs, prints `5`, `4`, `4` · was check-clean invalid wasm, clause 1 · found grading [D15125](D15125.md) · filed 2026-11-03 against master `ac86253af` · closed with [D15172](D15172.md): the call's rep row reads the settled build table, which holds `xs`'s build, so `rd`'s instance is keyed at `J` like `back`'s route · named set `d15128-by-rep-result-at-hole-beside-own-rep-call`**

Repro:

    type J = { f: i32 | null }
    function mk() { { f: 4 } }
    function back(r) { return r }
    const wideJ: J = mk()
    const xs = [mk()]
    const plain = { f: 5 }
    print(back(plain).f)
    function rd(v) { print(v.f) }
    rd(back(xs[0]))
    print(wideJ.f ?? 0)
    // vl check: rc 0.  vl run: invalid module, expected (ref $1) `{f:i32}`, found (ref $0) `J`

Want:

    5
    4
    4

#### Mechanism

`back` has two instances: one at `{f: i32}` for `plain`, and the by-rep one at `J` for `xs[0]`.
Mono routes `back(xs[0])` to the `J` instance, reading `xs[0]`'s build (`monoArgBuildTy`), but
`rd` was instanced at `{f: i32}` only: its call's rep row, which says where the argument is
stored, was empty. With only the by-rep call of `back`, `rd` was keyed at `J` another way and ran.

The fact that closes it is a per-instance parameter rep, distinct from the instance's type key.
Its producer is the call's bind row (`cbaRow`, check_bind_adopt.vl), its carrier the rep row
(`callBindRepTysAt`), and its reader mono's pin for the parameter (`callArgRepTy`), which builds
`rd` stored at `J` with its body still typed at `{f: i32}`. The bug was the bind row reading the
pass's build table, which `recBuildNote` had already emptied, so the row was empty; it now reads
the settled table (`recBuildTable`).
