### D15128 — a by-rep identity's result handed to a hole parameter is instanced at its own row when the identity is also called at its own storage

**open · check-clean invalid wasm · clause 1 · found grading [D15125](D15125.md) · filed 2026-11-03 against master `ac86253af`**

Repro:

    type J = { f: i32 | null }
    function mk() { { f: 4 } }
    function back(r) { return r }
    const wideJ: J = mk()
    const xs = [mk()]
    const plain = { f: 5 }
    print(back(plain).f)
    function rd(v) { print(v.f) }
    rd(back(xs[0]))
    print(wideJ.f ?? 0)
    // vl check: rc 0.  vl run: invalid module, expected (ref $1) `{f:i32}`, found (ref $0) `J`

Want:

    5
    4
    4

#### Mechanism

`back` has two instances: one at `{f: i32}` for `plain`, and the by-rep one at `J` for `xs[0]`.
Mono routes `back(xs[0])` to the `J` instance, reading `xs[0]`'s build (`monoArgBuildTy`). `rd`'s
parameter is typed from the elaborated type of that call, which follows `back`'s base instance,
so `rd` is instanced at `{f: i32}` only. Two producers decide the call's delivered record, and
stamping the call node `J` on the checker's side moves neither. With only the by-rep call of
`back`, both agree on `J`, and the program runs.

#### Ablation

| ingredient removed | outcome | needed? |
| --- | --- | --- |
| `print(back(plain).f)` | runs | **yes** |
| `back` (`rd(xs[0])`) | runs | **yes** |
| `rd`'s early `return` (D15125's matrix cell had one) | still invalid wasm | no |
