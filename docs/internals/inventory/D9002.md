### D9002 — an un-annotated function handed to a generic whose result wraps the arrow result is accepted at a destination of the wrong element type

**closed · now a loud check reject, `cannot assign f64[] to 'ys' of type i32[]` · was check-clean invalid wasm · clause 1 · found closing [D9000](D9000.md) · present on master `f0249c64f` · filed 2026-10-21 against master `f0249c64f` · closed with D9000 by `holeFnRetSubst` (check_relate_core.vl) closing `U[]` at the body's `f64` · fixture `closures/error-hole-fn-to-generic-fn-param-wrapped-result-mistyped.vl`**

Repro:

    function half(a) { return a / 2.0 }
    function m<T, U>(xs: T[], k: (a: T) => U): U[] { return xs.map(k) }
    const ys: i32[] = m([3], half)
    print(ys[0])
    // master: vl check rc 0, vl run: invalid module, type mismatch: expected (ref null $8), found (ref $5)

#### Mechanism

The call's result stayed `_[]`, which the checker accepted at `i32[]`; the monomorphizer then
pinned `U` from the destination as `i32` while the handed body returns `f64`, and the list the
instance builds is not the list the binding wants. Closing the result at the body's type
makes the destination's element type the thing compared.
