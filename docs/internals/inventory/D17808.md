### D17808 — two `const`s bound to calls of one lifted lambda at different widths in one frame are refused, and so is a `let` bound to one

**runs, prints `3` `4` — CLOSED 2026-11-28 by COV-CLOS-3: mono redirects the second call to a clone of the lambda built at the call's width (`__lambda_1$1`, i32), and `cloCallSigKey` now keys a call so redirected by that clone's own lifted function; each `const` reads its own call's key through the one reader (`letOpenCallWidth`), resolving the binding in the instance frame (`identLetOfRead`) at its slot, its reads, its print arm and the IR's storage (`openLocalInitTy`); pinned by `tests/cases/closures/consts-of-one-lifted-lambda-at-two-widths.vl` · the `let` face is [D17824](D17824.md) · was loud emit reject · `cannot yet lower this statement (local rep unsup)` · clause 2 · `vl check` rc 0 · filed 2026-11-28 against master `1619d5a9` by COV-CLOS-3**

Repro:

    function add(a, b) { return a + b }
    function app(g, s) { return g(s, s) }
    function p5(h) {
      const run = (x) => app(h, x)
      const v = run(1.5)
      print(v)
      const u = run(2)
      print(u)
    }
    p5(add)
    // vl check: rc 0.  vl run: emit error at 5:9, "local rep unsup"

Want:

    3
    4

#### Mechanism

The frame holds two widths. Mono splits the lambda per call: `run(1.5)` stays on the f64 slot and
`run(2)` is redirected to a clone, `__lambda_1$1`, built at i32. Two things failed. The
redirected call had no `cloCallSigKey`: its callee is a lambda FuncDecl, which no branch keyed.
And the print arm and the copy chain resolved `u` with `identDeclOf`, which gives the template's
binding, whose call goes to the f64 lambda. So print chose f64 while the IR stored i32.
