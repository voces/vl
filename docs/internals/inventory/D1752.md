#### Mechanism

A literal union reps as an interned i32 atom. `collectLocals` claimed such a local through
`letIsLitUnion` (the annotation is a registered ALIAS) or `letInitIsLitAtom` (UN-annotated, or
a module GLOBAL). An inline annotation inside a frame is none of those, so the binding fell
past `letIsString` — whose `exprString` declines the atom-repped element read — to
`checkLocalI32`, which refuses a non-`i32` annotation.

The ladder's four answers, printed from an instrumented build rather than read off the code:

| spelling | `letIsLitUnion` | `letInitIsLitAtom` | `letIsString` | cell |
| --- | --- | --- | --- | --- |
| alias annotation | **Y** | n | n | atom |
| no annotation | n | **Y** | n | atom |
| inline annotation, call init | n | n | **Y** | string |
| inline annotation, list read | n | n | n | none — refused |

**[D1196](D1196.md) built the one-line classifier fix and REFUSED it**, because re-slotting
made the program check-clean invalid wasm — loud to silent, the one trade this repo refuses —
and recorded that closing it means teaching the STORE about the slot. That price reproduces
exactly on today's tree: the classifier change alone moves these four cells emit → SILENT.

The store is `emitLetDeclStmt`'s widen arm, gated on the annotation's RENDERED name being
`string`. An inline literal union renders as `string`, so the arm widened the atom to its
member string and wrote a `(ref)` into the now-`i32` slot: `expected i32, found (ref $type)`.
The arm now also asks `localSlotIsLitAtom(slot)` — the flag `collectLocals` actually wrote,
read back rather than re-derived, so the store and the slot it writes into cannot answer
differently. D1196's own hazard is unchanged: an annotation that softens to `string` over a
non-atom initializer produces no atom, `exprIsLitAtom` declines it, and the loud refusal
stands for that shape.
