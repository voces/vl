### D14743 — a literal-union field is stored as a string when its record shares a union with a string-field arm

**runs today and must keep running · step 5 `ctxTy` field decline · filed 2026-11-01 against master `5b24d58b`**

Repro:

    type K1 = "circle" | "round"
    type A = { kind: K1, r: i32 }
    type B = { kind: string, r: i32 | string }
    function f(): A | B {
      const a: A = { kind: "circle", r: 1 }
      a
    }
    print(f().kind)

Want:

    circle

#### Mechanism

`A`'s `kind` is typed `K1`, whose `repOfTy` is the i32 atom, and on its own `A` stores it so.
Once `A` is an arm of `A | B` beside `B`'s `kind: string`, the shared field layout (D4056)
stores `A.kind` as a string, so the layout of `A` depends on which union names it. A reader
asking `repOfTy` of the field's contextual type gets the atom. `ctxFieldStorageAgrees`
declines every record field until this agrees. One row per canonical type is step 7's.

#### Ablation

| ingredient removed | outcome | needed? |
| --- | --- | --- |
| `B` and the union (`const a: A` alone) | `kind` stored as the atom | **yes** |
