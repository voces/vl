### D3166 — a hole instance's field function value passed on to another un-annotated function is refused as an unsupported argument type

**loud emit reject · clause 2 · all 48 `hole__*__pass__*` cells of lane HF's 714-cell grid, every field result type and instance count · the same on master `934f169f4` · filed 2026-09-29 against master `934f169f4`**

Repro:

    function H(h) {
      return h()
    }
    function F(z) {
      const g = z.f
      print(H(g))
    }
    const r0 = { f: () => 7 }
    F(r0)
    // vl check: rc 0.  vl build: emitProgram: monomorphize: unsupported argument type for `h` in a call to `H`

Want:

    7

#### Mechanism

Not localised past the ablation. `H`'s hole parameter is pinned per call from the argument's
type, and the argument here is itself typed at a hole of `F`'s instance (`g`, or `z.f`), which
the pin reader does not resolve through the enclosing instance's binding the way D3117's value
call does. With `F` generic (`F<Z>(z: Z)`) the argument has a type at the pin and the call
runs, which is where D3167 lives.

#### Ablation

| ingredient changed | outcome | needed? |
| --- | --- | --- |
| `print(H(z.f))`, no binding | same refusal | no |
| `function H(h: () => i32)` | prints `7` | **yes** (the hole callee) |
| `function F<Z>(z: Z)` | prints `7` | **yes** (the hole caller) |
