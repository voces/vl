### D2299 — a `.filter` callback over a `u8[]` types its parameter `u8`, a storage type, so comparing it refuses

**loud check reject · `cannot compare u8 with i32`, clause 2 · the design makes a `u8` element read an `i32` value at every seam, and the callback parameter is such a read · found while grading D2295 · filed 2026-09-24 against master `a295cf301`**

Repro:

    const b: u8[] = [250, 7]
    const kept = b.filter((x) => x == 7)
    print(kept.length)
    // vl check: rc 1, cannot compare u8 with i32.

#### Mechanism

Not located. The checker binds the callback parameter to the element type `u8` rather than to
the `i32` value a `u8` element reads as, so every operator on it refuses: `x > 10` reads
`comparison expects numeric operands, got u8 and i32`, and an annotated `(x: i32) => …` reads
`filter callback: parameter expects i32, got u8`. With the parameter unused, `(x) => true`
passes the checker and the emitter refuses `only i32, i64, f64, f32, boolean, struct, union,
array, or string parameters are supported`, so the emit side has no `u8` parameter either.

#### Ablation

| ingredient changed | outcome | needed? |
| --- | --- | --- |
| `b: i32[]` | runs | **yes** |
| `(x: i32) => x == 7` | loud check reject, `parameter expects i32, got u8` | no |
| `(x) => true` | loud emit reject, `only i32, … parameters are supported` | a neighbour |
| `.map((x) => x + 10)` | loud check reject, `operator '+' is not defined for u8 and i32` | no |

#### Grading list

`.map`, `.filter`, `.some` and `.find` over a `u8[]` with an un-annotated and an `i32`-annotated
parameter, each printing a value that proves the byte was read (`250`, not `-6`).
