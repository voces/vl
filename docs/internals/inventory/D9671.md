### D9671 — an inline list handed to a parameter bound to an annotated local traps when another annotation pins the function at another type

**closed 2026-10-22 by lane-D9610 · runs, prints `5` `2.5` · was check-clean wasm trap, `indirect call type mismatch`, `vl check` rc 0 · clause 1 · closed with [D9610](D9610.md): the literal is delivered at its own slot's pin, not the one instance another annotation pinned (`monoPinHoleParam`, emit_mono.vl) · fixture `closures/hole-fn-inline-list-to-param-bound-beside-other-pin.vl` · found closing [D9610](D9610.md) · filed 2026-10-22 against master `9e81d3ee3`**

Repro:

    function inc0(a) { return a + 1 }
    function early(a) {
      const k: ((x: i32) => i32)[] = a
      return k[0](4)
    }
    const e: ((x: f64) => f64)[] = [inc0]
    print(early([inc0]))
    print(e[0](1.5))
    // vl check rc 0.  vl run: wasm trap: indirect call type mismatch, in `early`

Want:

    5
    2.5

#### Mechanism

Traced, the same as [D9610](D9610.md). The literal handed to `early` was never delivered, and
the function-value floor let `inc0` through at the one signature the program pins it at, the
`f64` instance `e`'s annotation asked for; `early` then called it as an `i32` function. With the
literal delivered at its own slot's pin, `[inc0]` takes the `i32` instance.

| `e` at `((x: i32) => i32)[]` | runs, the one pin agrees | **yes** |
