### D3791 — a recursive record and its one-step unfolding get different canonical ids, so an inline annotation of it never shares the declared row's heap type

#### Mechanism

`{key: i32, kids: St[]}` is `St` unfolded once, so the checker accepts the call both ways. The
emitter mints a row for the inline spelling, and `buildStructTwins` merges two rows only when
`slotCanonId` agrees. The canonical walk (`repIdOf`, mode `canon`) encodes a cycle as a de
Bruijn back-reference, so `St` reads `obj{key, kids: list(back 2)}` while the unfolding reads
`obj{key, kids: list(obj{key, kids: list(back 2)})}`: two ids for one structure. The keys
differ, the rows never twin, and the call hands `(ref $St)` to a `(ref $St')` parameter. A fix
belongs in the canonical walk (minimise a recursive key, or compare rows coinductively when keys
differ) and is rep-layer work, gated by `scripts/rep-fuzz-check.sh`.
