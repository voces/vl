### D2900 — a parameter-less lambda returning a hole prints a `boolean` pin as `1`

**closed 2026-09-27 — the filed repro prints `true` · was check-clean silently wrong, clause 1, the same on master `0284dc2a8` · closed by copying the call through a lambda whose type names a hole of the instance, typed at the instance's holes · found working [D2884](D2884.md) (the `thunk` and `nest` cells of this lane's grid) · filed 2026-09-27 against master `089c6ff56`**

Repro:

    function mk(x) {
      const c = () => x
      print(c())
    }
    mk(true)
    // vl check: rc 0.  vl run: prints `1`

Want:

    true

#### Mechanism

[D2884](D2884.md)'s twin for a lambda with no parameter: such a lambda has no hole of its own,
so `monoLamBoundNames` did not list its binding and its calls were not copied per instance; the
call stayed typed at the hole's variable and `print` read the `i32` rep. A binding whose lambda
type names a type variable, inside an instance with holes, is now listed, so its call is copied
and typed through `monoLamCallTy`. Removing that one edit brings `1` back; the D2878 edit alone
does not fix it.
