### D17050 — [CLOSED 2026-11-22] a numeric union with an `f32` member added to a float literal unboxes a member whose value box is not registered

**closed 2026-11-22 · runs, prints `2.5` · fixed in emit_collect.vl / emit_union_atoms.vl: `collectU` marks the value boxes of an arithmetic operator's minted numeric-union result (`markNumUnionResultAtoms`), so the `f32 | f64` result of `f32 | i32 + 2.0` has its `f64` box; the same missing box made the dispatch's `struct.new` of that member's value an unregistered index · pins `numerics/f32-int-union-plus-float-literal-boxes-its-result.vl` · was loud emit reject · filed 2026-11-22 against master `bd5715588`**

Repro:

    function halfOrInt(h: boolean): f32 | i32 { if h { return 0.5 } return 4 }
    function asF64(x: f64) { print(x) }
    asF64(halfOrInt(true) + 2.0)
    // vl check: rc 0.  vl build: emitProgram: narrowed union atom has no value box (3:28)

Want:

    2.5

#### Mechanism

The `+` over a numeric union and a float literal takes legacy's `numUnion` route. Its member
dispatch unboxes a member through `emitUnionUnboxTail`, which finds no value box registered for
that member's atom kind (`vbHeapIdxOfKind` is -1) and refuses. It is the `f64` one: the result of `f32 | i32 + 2.0` is `f32 | f64`, since the `f32` pair keeps
`f32` beside a float literal and the `i32` pair computes at `f64`. That minted union is no
registered row, so its `f64` value box was never marked used.
The ablation points at the `f32` member beside a float literal: an `f64 | i32` union, an integer
literal, or an `f64` variable in the literal's place all run. The control
`const d: f64 = halfOrInt(true) ?? 2.5; asF64(d + 2.0)` runs and prints 2.5.

#### Ablation

| ingredient removed | outcome | needed? |
| --- | --- | --- |
| the `f32` member (`f64 \| i32`) | runs, prints 2.5 | **yes** |
| the float literal (`+ 2`) | runs, prints 2.5 | **yes** |
| the literal, as an `f64` variable (`+ w`) | runs, prints 2.5 | **yes** |
| the `f64` parameter (`print(halfOrInt(true) + 2.0)`) | still refuses | no |
| the parameter, as a `const y: f64 =` declaration | still refuses | no |
| the call operand, as a `const` binding read | still refuses | no |
