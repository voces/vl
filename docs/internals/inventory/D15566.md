### D15566 — a hole function parameter handed on inside a list literal to a callee that calls the element at two types is taken as a value with no signature

**loud emit reject · `vl check` rc 0 · `emitProgram: cannot take the generic function `id` as a value — a function value carries ONE signature, and parameter `v` is un-annotated (it would default to i32)` · clause 2 · CAPABILITY: the list built from `id` at the call site prints `5` and `s`, and `g` handed on bare (`call1(g, 5)`, `call1(g, "s")`) prints both · found closing [D15565](D15565.md), which was its check reject until then · filed 2026-11-08 against master `9bbf9564`**

Repro:

    function id(v) { return v }
    function call0(fs, x) { print(fs[0](x)) }
    function run(g) {
      call0([g], 5)
      call0([g], "s")
    }
    run(id)

Want:

    5
    s

#### Mechanism

Not traced. The checker accepts the program once D15565's root key is gone. The emitter then
needs `id` as one value held in the list `[g]`, called at `i32` and at `string`. That is a list
element read at two instances, which a single `Fn#d` value does not serve: it needs one copy of
`run`'s list per instance, or a set.

#### Ablation

| ingredient removed | outcome | needed? |
| --- | --- | --- |
| the second type (`call0([g], 6)`) | runs, `5` `6` | **yes** |
| the list (`call1(g, 5)`, `call1(g, "s")`) | runs, `5` `s` | **yes** |
| `run`'s hole (`call0([id], 5)`, `call0([id], "s")` at top level) | runs, `5` `s` | **yes** |
