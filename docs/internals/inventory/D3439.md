### D3439 — a type parameter's field written in an `is` test's else arm inside a loop is refused at emit

**closed 2026-09-30 · was loud emit reject, clause 2, pre-existing on master `c00198389` · the #3321 review's `h/t4` (and `h/t3`, two writes in the arm, which now runs too) · closed by #3321's round 2: a clone of the write answers the checker's narrowing banks, so the instance re-narrows the field to the member the write lands on · filed and closed 2026-09-30 · fixture `tests/cases/generics/hole-field-write-in-loop-lands-at-pin.vl`**

Repro:

    type A = { v: i32 }
    type B = { s: string }
    function g<Z>(z: Z) {
      let i = 0
      while i < 2 {
        if z.h is A { print(z.h.v) } else { z.h = { v: 5 + i } ; print(z.h.v) }
        i = i + 1
      }
    }
    const x: { h: A | B } = { h: { s: "bee" } }
    g(x)
    // vl run: emitProgram: unknown variant field in narrowed field access

Want:

    5
    5

#### Mechanism

The write is re-made per instance by the monomorphizer, and the clone answered none of the
write's narrowing banks, so the instance's emitter kept the else arm's remainder `B` over the
written `A` and found no `.v` in that variant. `carryAsgBanks` carries them, so the instance
re-narrows the field to the written member, as the template's check does.
