### D4557 — `vl check` costs time quadratic in the length of an `else if` chain whose arms return, and of an `if`-expression chain

**runs today and must keep running · a compile-time cost, not a miscompile: every length checks, runs and prints the right values · regression since D1990's close · filed 2026-10-14 against master `eb2603843`**

Repro (runs, prints `1`):

    function f(x: i32): i32 {
      if x == 0 { return 1 } @@repeat(5000, "else if x == 1 { return 4 } ")@@else { return -1 }
    }
    print(f(0))
    // vl check: rc 0, ~2.7 s CPU; D1990's table read 0.13 s at this length.

#### Mechanism

Not yet located. The parser is linear (`vl fmt` renders a 10,000-link chain in 0.15 s), and a
dense `match` of the same length still checks in linear time, so the cost is in a checker pass
(and the emitter's, for the expression chain) that revisits the rest of the chain at every
link. The ablation points at what each link carries out of its arm: a `return`, or a value.
D1990 measured every shape here as linear on 2026-09-22.

`vl check` CPU seconds on master `eb2603843`, box at load ~60:

| shape | 1,250 | 2,500 | 5,000 | 10,000 |
| --- | ---: | ---: | ---: | ---: |
| `else if` chain, `return` in each arm (the witness) | 0.34 | 0.84 | 3.44 | 15.01 |
| `if`-expression chain in a `const` initialiser | 0.87 | 2.25 | 7.92 | — |
| dense integer `match` (one `br_table`) | — | 0.08 | 0.19 | 0.20 |

#### Ablation

At 2,500 / 5,000 links, `vl check` CPU seconds:

| ingredient changed | outcome | needed? |
| --- | --- | --- |
| none (the witness) | 0.80 / 2.67 | — |
| each arm `print`s instead of returning | 0.31 / 0.53 | **yes** (the `return`) |
| empty arms | 0.27 / 0.43 | **yes** |
| the chain at top level, arms `print` | 0.29 / 0.45 | **yes** |
| every condition one `boolean` parameter, not `x == i` | 0.78 / 2.39 | no |
