### D4557 — `vl check` costs time quadratic in the length of an `else if` chain whose arms return, and of an `if`-expression chain

**closed · runs, and `vl check` is now linear in the chain's length: the witness checks in 0.4 s at 10,000 links · was a compile-time cost quadratic in the length, every length checking, running and printing the right values · regression since D1990's close · filed 2026-10-14 against master `eb2603843`**

Repro (runs, prints `1`):

    function f(x: i32): i32 {
      if x == 0 { return 1 } @@repeat(5000, "else if x == 1 { return 4 } ")@@else { return -1 }
    }
    print(f(0))
    // vl check: rc 0, ~0.2 s CPU (was ~2.7 s); D1990's table read 0.13 s at this length.

#### Mechanism

Two checker walks, each asked once per link about the whole chain below it, located with a
`--names` seed under `$VL_PROFILE_GUEST`:

* `listJoinWidenCheck` (compiler/typecheck.vl), 83% of the witness's samples at 4,000 links.
  Every link of a chain whose value is joined (a function's tail, a `const` initialiser) is a
  join site of `rcwPendJoins`, and each handed its `else` link to `valueTailLeaves`, which walks
  to the chain's end. Closed by remembering the joined type each spine node was walked against
  (`ljwWalked`): a leaf under a node already walked against the same type was reported or fits.
* `valueIsLitOnly`, from `checkIfTail`'s `armLit(ev, n.ifElse)`, 69% of the `if`-expression
  chain's samples. Each tail asks whether every value below its `else` is a literal. Closed by a
  memo (`vloMemo`) live only while one chain's tails run bottom-up, so each link reads the link
  below it.

Neither change alters what is reported or in what order: the same four list-join refusals and
the same literal-join values were A/B'd against master, and the gate held.
