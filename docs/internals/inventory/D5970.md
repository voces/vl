### D5970 — a function returning a generic, called inside a generic or hole-parameter function, delivers no signature to the call

**loud emit reject · `vl check` rc 0 · clause 2 · found closing [D5660](D5660.md) · filed 2026-10-17 against master `7497c0982`**

Repro:

    function k<T>(x: T): T { return x }
    function mk() { return k }
    function g(u) {
      const a = mk()
      print(a(1))
      print(u)
    }
    g(1)
    // vl check: rc 0.  vl run: emitProgram: a function-value call has no interned signature — parameter 1 of type `` has no representation in the function-value ABI

Want:

    1
    1

#### Mechanism

From the ablation and one reading of the code. The pin past `mk`'s return is found (`i32`),
and D5360 retypes the calls of `mk` at that pin, but `monoRetypePinCalls` skips a call inside
a generic instance, so the instance's copy of `a(1)` keeps no signature. With two results at
two types (`const b = mk()`, `b("s")`), a generic `g<U>` refuses at `return k` instead.

#### Grading list

- `function g<U>(u: U)` with `const a = mk()` and `const b = mk()` called at `1` and `"s"`,
  `g` called at `1` and `true`
- the same with a block-local `function mk() { return k }` inside `g`, generic or hole
