#### Fix

`variantStructHeapTwinAt`, the arm's twin question `collectS` asks mid-loop, answers from the
record-row class (`recordRowClassOf`, D15152): the arm's row and the struct row twin when their
record types have one class. The class is read from the checked types alone, so the question no
longer compares the two rows' map fields by mv slot one phase before `collectA` interns them,
and the field-code walk it replaced is deleted. The arm twins are identical over every
`tests/cases` file and the distilled corpus.

#### Mechanism

`collectS` codes `Q.o` through the arm's twin check, which compares the map field of the arm's
own row with the map field of its twin row by mv slot. The two rows spell the same field two
ways. The arm's row records the map's value as `R`; the twin row is minted by
`internArmShapeRow` from `tyToEmitName`'s render of the whole arm, because `armMintRenderOf`
names a field by its record only when every field is a declared record, and that render
spells the value by its shape, `{n:i32,g:{[string]:{r:i32}}}`. The slot interned for one
spelling is not the slot the other looks up.

**Two producers of one fact.** The fix is one spelling of the field, shared by both rows, not a
translation from one spelling to the other at the comparison. Interning the twin row's own map
slots from its current metadata mints a third slot and breaks the twin for every arm with a map
field (`a union arm's row is not on the arm's heap`), which was measured and reverted.

**Spelling the twin nominally is order-dependent, measured 2026-11-03.** Naming every declared
record in the mint's spelling (`tyToNominalName`) runs the record declared BEFORE the holder and
refuses the one declared AFTER it, the mirror of today, where after runs and before refuses:
`collectS` registers declarations in source order and asks the twin question mid-loop, so a name
resolves only if its record came earlier. Guarding the name on the record already owning its row
disables it entirely, because the mint runs in `collectNestedFieldShapes`, before any declared
record has a row. The rows can agree in both orders only if the records exist before the
question is asked.

**The fix is a pass order, not a spelling, and it is held.** Registering every declared record's
row before any field of a struct that names an arm is coded lets the mint spell names, guarded on
the row existing, in both orders. That is the same move as making "these records share a row" a
fact produced before `elabRun` and read by `collectS` and the elaboration key, which another lane
is scoping, so it waits for that scope rather than reordering `collectS` twice.
