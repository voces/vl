### D15098 — a struct holding a union arm whose map value is a declared record keys the arm's two rows' map slots by two spellings

**loud emit reject · clause 2 · filed 2026-11-03 against master `cbb7e2b90` by lane column-G1, found closing [D15097](D15097.md)**

Repro:

    type R = { r: i32 }
    type Q = { o: A }
    type A = { n: i32, g: Map<string, R> }
    type P = { m: i32 }
    type U = A | P
    const g: Map<string, R> = Map()
    g.set("x", { r: 7 })
    const q: Q = { o: { n: 1, g: g } }
    print(q.o.g.get("x")?.r ?? 0)
    // vl check: rc 0.  vl run: emitProgram: map value type has no interned slot

Want:

    7

#### Mechanism

`collectS` codes `Q.o` through the arm's twin check, which compares the map field of the arm's
own row with the map field of its twin row by mv slot. The two rows spell the same field two
ways. The arm's row records the map's value as `R`; the twin row is minted by
`internArmShapeRow` from `tyToEmitName`'s render of the whole arm, because `armMintRenderOf`
names a field by its record only when every field is a declared record, and that render
spells the value by its shape, `{n:i32,g:{[string]:{r:i32}}}`. The slot interned for one
spelling is not the slot the other looks up.

**Two producers of one fact.** The fix is one spelling of the field, shared by both rows, not a
translation from one spelling to the other at the comparison. Interning the twin row's own map
slots from its current metadata mints a third slot and breaks the twin for every arm with a map
field (`a union arm's row is not on the arm's heap`), which was measured and reverted.
