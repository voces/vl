### D10192 — a `let` bound to a call returning one of two generics, written with another such call and called at two types, refuses

**loud emit reject · `vl check` rc 0 · `a generic function taken as a value reaches no call that fixes its type` · clause 2 · CAPABILITY: the write spelled `k = id` prints `21`, `a`, `same`, `22`, `same`, `b` · found closing [D10021](D10021.md) · present on master `9ca7e7751` · filed 2026-10-22 against master `9ca7e7751`**

Repro:

    function id<T>(x: T): T { x }
    function same<T>(x: T): T {
      print("same")
      x
    }
    function pick(n: i32) {
      if n > 1 { return id }
      return same
    }
    let k = pick(5)
    print(k(21))
    print(k("a"))
    k = pick(0)
    print(k(22))
    print(k("b"))
    // vl check rc 0.  vl run: emit error: emitProgram: a generic function taken as a value reaches no call that fixes its type — annotate the destination's function type

Want:

    21
    a
    same
    22
    same
    b

#### Mechanism

The close of [D10021](D10021.md) runs the binding's choosing call once, as the index of the
generic it returns, and gives each call type a slot that selects by that index. A write takes
a slot write per type only from a name, a lambda or a peer binding (`fsValuePeer`,
fn_split.vl), and a second choosing call is none of these, so the whole let plan declines.
Left open by the lane that closed [D10202](D10202.md) and [D10204](D10204.md): the split
plan (`fsPlanMember`), which the checker changes there do not reach.
