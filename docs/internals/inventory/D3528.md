### D3528 — an annotated `A | B | null` binding read through `??` at a pin binding both parameters alike is built at the box's rep

**closed 2026-10-03 by lane KJ — the witness prints `true` · was check-clean invalid wasm, clause 1 · found by lane LJ's grid (its `annif` and `annlam` shapes, 36 cells) · filed 2026-10-03 against master `331f5e998` · fixture `tests/cases/generics/annotated-join-coalesce-at-pin.vl`**

Repro:

    function F<A, B>(k: i32, a: A, b: B) {
      const v: A | B | null = if k == 0 { a } else if k == 1 { b } else { null }
      print((v ?? 9) is i32)
    }
    F(2, 3, 3)
    // vl check: rc 0.  vl run: invalid module inside `F`, "expected (ref null $type), found i32"

Want:

    true

#### Mechanism

The annotation is a union of the parameters that the checker did not build as a kept-apart
join, so the `??` result is a deferred join `A | B`. At `(i32, i32)` the binding is `i32 | null`
and the `??` unboxes to `i32`, but `exprUnion`, the if-join's union name and `exprString` read
the result at the template's union, as the box. They now read a join over the instance's type
parameters at the pin (`pinSubJoinTyOf`), and a scalar join takes the pinned number's width as
its blocktype (`ifExprValtype`), a literal default adapting; except in an instance whose body holds a function: a
lambda's join is still collapsed at its call there ([D3520](D3520.md)), and reading it at the
pin turned invalid wasm into wrong values in #3344.

#### Ablation

| ingredient changed | outcome | needed? |
