#### Mechanism

sunpa's sim runs in the browser and on a Deno server and needs the same bits on both, so a
host `Math.sin` (V8's fdlibm port, wasmtime's libm) is not an answer: they disagree in the
last bits. The close adds `sinF64`/`cosF64`/`sinF32`/`cosF32` to `std:math` as pure VL over
IEEE-754 `+ - * /` and integer ops: Cody–Waite reduction by π/2 in three parts below
2^20·π/2, an integer Payne–Hanek reduction against a 1,280-bit table of 2/π above it, and
minimax kernels on [−π/4, π/4]. The f32 pair evaluates in f64 and rounds once. Accuracy,
the cross-host comparison and the speed figures are in `docs/internals/std-notes.md`
§`std:math`.

The close exposed a second, unrelated defect. `symOccAt` (`compiler/check_query.vl`), the
cursor lookup under go-to-definition, hover type, doc and effects, scanned the identifier
occurrences of EVERY module in the merged graph. So an imported module's identifier at the
cursor's line and column, with a narrower span, won the lookup. Definition then returned the
other file's range as if it were in the open file, and effects went blank. It surfaced
because a draft of the rewritten `std/math.vl` header put an `ax` binding under
`vl_effects_summary_test.ts`'s `clamp01` cursor. The fix keeps only module-0 (entry)
occurrences. `tests/vl_query_entry_only_test.ts` pins it with a two-file graph; on the master
seed, definition returned `{line 0, col 20..21}` (util.vl's parameter `a`), not `farAway`.

#### Grading list

`tests/cases/math/sin-cos*.vl` pin exact results, so the corpus oracle (V8) and the native
host (wasmtime) both grade the bits. The 2.88M-point accuracy and determinism grid is
described in std-notes; re-run it after any coefficient or reduction change. For the query
fix, the ci.yml editor suites and `vl_effects_summary_test.ts`. Not graded: the member-access
lookup (`symMemIxAt`) matches on line and column without a module test either, and no
witness for it has been written yet.
