#### Fix

Two halves of one fact. The tagging decision (`ftHoldKind`, `compiler/check_fn_tag.vl`) takes a
list of lists of records holding a set as a holder of it, at any depth, so the set is tagged and
its functions are ids; `ftHoldCtxOk` admits such an inner list beside another literal of the set.
Once the set is tagged, `ftTry` stamps each holding list literal and un-annotated `let` with its
rep, its type with every list of the set's ids an `i32` list (`fnTagHeldRepOf`,
`compiler/check_elab_cap.vl`); a holder coerced to closures, or annotated, is not stamped. The
emitter's nested-list readers (`arrLitNestedElemName`/`Kind`, the hint arm, the outer row, the
build and `exprRepTy`) read the stamp. `tests/cases/closures/fn-tagged-ids-in-records-in-nested-lists.vl`
and the named set `d15220-records-in-nested-lists` hold the shapes. It also closed
[D15195](D15195.md). An uncalled function in such a list still refuses ([D15159](D15159.md)).

#### Mechanism

Not traced. No function returns the value, so it is not [D15203](D15203.md)'s result; the refusal is the same bounds guard, with no row for the record element two lists deep.
