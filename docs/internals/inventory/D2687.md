### D2687 — each call of an inferred-return function rebuilds the calling function's whole let plan

**closed 2026-09-26 — runs today and must keep running · the defect was its cost: in a caller of `n` statements each calling a different function whose list return is inferred, the build was quadratic in `n` (5.90G fuel at n=800 against 3.13G annotated); the let-plan cache now keeps the caller's plan parked while a callee's is asked about, and the same program costs 3.41G, linear · filed 2026-09-26 against master `f8709e41c`**

Repro:

    function f0(n: i32) {
      const out: i32[] = [n, n + 1]
      out
    }
    function f1(n: i32) {
      const out: i32[] = [n]
      out
    }
    function main() {
      let total = 0
      total = total + f0(1).length
      total = total + f1(2).length
      print(total)
    }
    main()
    // prints 3; every `fK(…).length` rebuilds `main`'s plan after asking about `fK`'s body

#### Mechanism

The emitter's per-function let plan (`plBuildLetMap`, compiler/emit_base.vl) is a
single-entry cache keyed on the body block (`plCacheBlock`). Emitting a call to a function
whose return is inferred asks about the CALLEE's return binding —
`unionNameOfIdentAt`/`parentLetOfAt` from `exprIsI64`, `exprIsF64`, `exprString`,
`listOpRepOf`, and `identIsBoundClosure`/`parentLetOfSid` from `emitArrLen` — which builds the
callee's plan and evicts the caller's; the caller's next question rebuilds it, an
O(caller) walk per call. The guest profile of the n=400 program puts `plScanStmt` at 16.6%
self, all of it under `plBuildLetMap < parentLetOfAt`/`parentLetOfSid` from those askers.
Not the same mechanism as [D2685](D2685.md). Closed by keeping built plans: `plEnsure`
(compiler/emit_base.vl) makes a block's plan current by loading it back from a small
most-recently-used set (`plSaved*`, three parked plans besides the current one) or by building
it into the least recently used set's tables. A plan's tables are array references, so parking
or loading one moves 21 references; each build takes a fresh generation from `plGenTop`, so a
recycled table's older stamps never read as present, and `plCacheBust` drops the parked plans
with the current one, so no plan outlives a pass (D2389). Output is byte-identical: master's
source and the annotation-stripped source both reproduce master's seed, and 158 of 200 random
`tests/cases` programs build byte-identical (the other 42 are refused by both compilers).
