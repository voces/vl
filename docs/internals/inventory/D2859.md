### D2859 — an annotated `T[] | i32[]` return built from `[t]` answers `is T[]` false at every pin

**closed 2026-09-27 by [D2818](D2818.md)'s close · was check-clean silently wrong, clause 1, on master `1df19732b` · found by the #3222 review · filed 2026-09-27 against master `721781075` · fixture `tests/cases/generics/annotated-type-param-list-union-return-keeps-both-arms.vl`**

Repro:

    function w<T>(t: T): T[] | i32[] { [t] }
    const a = w(true)
    if a is boolean[] { print("B") } else { print("N") }
    // vl check: rc 0.  vl run: prints `B`.  Was: prints `N`

Want:

    B

#### Mechanism

[D2818](D2818.md)'s: the template's written `T[] | i32[]` resolved to `T[]`, so there was no
`boolean[]` arm to box the value under. Before that close, not localised past the ablation. The call's value is a `[true]` list, and the box's tag is not
the `boolean[]` arm's. This is not the boolean/i32 shared storage: at `T := string` the same
program prints `N` for `is string[]` too, and `w(3) is i32[]` answers `I`. So the tag the
instance boxes `[t]` under is the `i32[]` arm's, or some other code, whatever the pin.

#### Ablation

| ingredient removed | outcome | needed? |
| --- | --- | --- |
| the boolean pin (`w("s") is string[]`) | prints `N` | no |
| the `T[]` arm's value (`w(3) is i32[]`) | prints `I` | **yes** |

#### Grading list

`w("s") is string[]`; a two-return spelling (`if c { return [t] }` then `[1]`), which the checker
currently refuses at the call (`return type mismatch: expected boolean[], got i32[]`).
