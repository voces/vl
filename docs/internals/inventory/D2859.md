### D2859 — an annotated `T[] | i32[]` return built from `[t]` answers `is T[]` false at every pin

**check-clean silently wrong · clause 1 · found by the #3222 review · the same on master `721781075` · filed 2026-09-27 against master `721781075`**

Repro:

    function w<T>(t: T): T[] | i32[] { [t] }
    const a = w(true)
    if a is boolean[] { print("B") } else { print("N") }
    // PRINTS N

Want:

    B

#### Mechanism

Not localised past the ablation. The call's value is a `[true]` list, and the box's tag is not
the `boolean[]` arm's. This is not the boolean/i32 shared storage: at `T := string` the same
program prints `N` for `is string[]` too, and `w(3) is i32[]` answers `I`. So the tag the
instance boxes `[t]` under is the `i32[]` arm's, or some other code, whatever the pin.

Re-graded 2026-09-27 (#3227 review): keeping the written union's arms apart in the annotation
dedupe closes this row, but it makes the checker refuse `.length`, indexing and `for`-`in` over
`T[] | i32[]` at every non-`i32` pin (`wrap("ada").length` printed `1` on master), because the
checker has no member access shared by a union of lists. The close depends on that list-union
shared-member capability; the dedupe change is withdrawn until it lands.
