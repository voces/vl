### D2092 — a string literal is emitted inline at about three code bytes per character, so a long one builds a function body past wasmtime's 7,654,321-byte limit

**check-clean invalid wasm · `vl check` rc 0, then the engine refuses the module (exit 70, the invalid-module banner) · clause 1 · filed 2026-09-22 against master `48a295c72` · split out of [D1976](D1976.md), whose Mechanism already named this ceiling as "not this row"**

Repro (a 2.85M-character literal in the ENTRY file, written as `@@repeat` so the row can hold it):

    function f0(): string { "@@repeat(2850000, "a")@@" }
    print(f0().length)
    // vl check: rc 0.  vl run: the 8.56 MB module fails to validate inside `f0`,
    // "function body size count exceeds limit of 7654321", in about 0.6 s

#### Mechanism

`emitStr` (`wasmEmit.vl`) pools a literal within the `array.new_fixed` cap into a global. A
literal past the cap is built inline instead: one `i32.const` per UTF-8 byte, flushed into the
backing in chunks, about three code bytes per character. A literal
past about 2.55M characters therefore makes one function body larger than wasmtime's fixed
limit of 7,654,321 bytes, and the engine refuses the module at load. The emitter checks no
limit, so `vl check` and emit both succeed and the failure is the engine's. The entry file is
2.85 MB, so `vl build`/`vl run` compile it under the copying collector. Under the null collector
(`VL_COMPILE_GC=null`, or the same literal in an imported module) the compiler traps first,
in the function's own `i32[]` buffer, and that trap is [D1976](D1976.md).

Below the limit a long literal still costs a lot to load: a 1.6M-character function (a 4.8 MB
module) takes Cranelift 102 s and 12.9 GB of RSS, and two of them take 127 s and 25 GB.

#### Ablation

| ingredient removed | outcome | needed? |
| --- | --- | --- |
| the literal's length (1.6M characters) | runs, after the Cranelift cost above | **yes** |
| the copying collector (`VL_COMPILE_GC=null`) | compiler trap, [D1976](D1976.md) | **yes** |
| the emit (`vl check`) | rc 0 | **yes** |

#### Grading list

- A fix that stores literal bytes in a data segment (or a passive segment read by
  `array.new_data`) removes the size-per-character problem and the Cranelift cost with it;
  re-grade both D1976 witnesses under both collectors after it.
- A fix that only REFUSES an over-long function in the emitter turns this row into a loud emit
  reject, a clause-2 violation: the program is legal.
