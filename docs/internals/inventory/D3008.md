### D3008 — a `let` re-seated at a wider declared record is reassigned another own-type literal binding, which is built at its own record

**check-clean invalid wasm · identical on master `b34730ad9` and on #3253 · found by the #3253 review grid · filed 2026-09-28**

Repro:

    type D = { v: f64 }
    const x: i32 = 3
    const c: {[string]: D} = Map()
    let o = { v: x }
    c["k"] = o
    const p = { v: 4 }
    o = p
    print(o.v)
    // vl check: rc 0.  vl run: invalid module — type mismatch

Want:

    4

#### Mechanism

The map store re-seats `o`'s literal at `D`, so the `let o` slot holds `D`'s record. `p` is a second un-annotated literal whose only use is `o = p`, and nothing re-seats it at `o`'s row, so `local.set` gets `{v: i32}` where `D` is expected. The walk does not follow an assignment into a binding that was itself re-seated.
