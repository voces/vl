### D10794 — a join over a hole function's `.map` result of nullable strings reads its elements as non-null strings

**loads then traps, `vl check` rc 0, `wasm trap: null reference` · clause 1 · 2 cells of `d3125-lift-price` (`d3125_hole_J1_B_P4_3`, `d3125_hole_J1_H_P4_3`) · residue of [D6360](D6360.md), whose close moved them here · filed 2026-10-23 against master `f9c494261` plus the D6360 change**

Repro:

    function t(x) {
      const c = 1 > 0
      const m = [x].map((e) => {
        if e != null { return e }
        return null
      })
      const n = if c { m } else { m }
      for y in n { print(y) }
    }
    const a: string | null = null
    t(a)
    // vl check: rc 0.  vl run: wasm trap, null reference

Want:

    null

#### Mechanism

The callback's clone returns `string | null` (D6360), so `m` is a list of nullable strings
and iterating `m` itself prints `null`. The `if` join's binding `n` reads its elements as
`string`: the `for` loop casts each one non-null before printing it. The template type of
`n` is `(_ | null)[]` over the lambda's own parameter hole, as it is for the declared-`T`
spelling that runs. Where the hole instance's join decides its element kind is not yet
located.
