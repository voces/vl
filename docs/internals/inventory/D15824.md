### D15824 — a binding of a field read off a record built wider takes the row of the read's own type when another literal minted one

**closed 2026-11-12 — runs, prints `4` · was check-clean invalid wasm, clause 1 · the read's held record is the field's record with its null removed, since a read typed as a record is not null (`storeHeldAt`) · found grading D15822 · the same on master `4e65bd710`**

Repro:

    type J = { f: i32 | null }
    type K = { j: J | null }
    function mk() { { j: { f: 4 } } }
    const _k: K = mk()
    const y = mk()
    function mj() { { f: 6 } }
    const w = y.j
    print(w.f ?? 0)
    // vl run: rc 0 — 4
    // (was: invalid module — expected (ref null `#anon2`), found (ref `J`))

Want:

    4

#### Mechanism

`y` is built at `K`, so `y.j` holds a `J`. The binding `w` is held where its initialiser is
(`storeLetsResolve`), and for a field read that is the field's type in the record the receiver is
held at: `J | null`. Only a record is recorded, so the nullable left `w` at its own type
`{f: i32}`. With no row of that shape, the emitter fell back to the read's rep and the program ran.
`mj`'s literal minted one (`#anon2`), so `w`'s slot took it and the `J` reference did not fit.
