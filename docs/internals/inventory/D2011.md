Repro:

    for name in ["red"] {
      const g = name
      const f = () => g
      print(f())
    }

#### Mechanism

Not traced. A prediction for the fix: `captureValKind` types the capture `g` through
`letInitCellKind(g, frame)`, and at module scope the frame is -1, where the initialiser's
`Ident` read of the loop variable `name` has no local to classify. D2010 fixed the direct
capture of the loop variable (`captureLoopVarIterOf`); the binding one step removed from it goes
through the let ladder instead, which has no module-scope loop-variable rung.
