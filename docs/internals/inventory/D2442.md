### D2442 — a module-scope value-union global answers `is` wrongly after a failed `is` of its other member

**closed 2026-09-25 — the witness prints `true` · was check-clean silently wrong, clause 1 · found
in review of #3148, the same on master `a20d69104` · filed 2026-09-25 against master `a20d69104`,
closed against master `be97589c0` by the change that closes [D2447](D2447.md), whose mechanism it
is · fixture `tests/cases/unions/is-retest-narrowed-union-place.vl`**

Repro:

    function mk(): i32 | string { return 5 }
    const x = mk()
    if x is string { print(1) } else { print(x is i32) }
    // vl check: rc 0.  vl run: prints true

#### Mechanism

In the `else` of a failed `is string`, the global `x` is narrowed to `i32` and its read is
unboxed, so the `x is i32` test misses every tag rung of `emitIs` and reached
`monoStaticIsResult`, whose narrowing-blind pin name (`i32|string`) folded it to 0. D2447 has
the rung and the fix. The function-scope spelling and the un-narrowed test both answer `true`,
so the ingredient is a narrowed module GLOBAL of a value union. `boolean | i32` and
`boolean | string` fail the same way; record unions do not.

#### Ablation

| ingredient changed | outcome | needed? |
| --- | --- | --- |
| the same program inside a function | prints `true` | **yes** |
| no preceding `is string` (`print(x is i32)`) | prints `true` | **yes** |
| `boolean \| i32`, testing `is boolean` then `is i32` | prints `false` | no |
