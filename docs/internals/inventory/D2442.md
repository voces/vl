### D2442 — a module-scope value-union global answers `is` wrongly after a failed `is` of its other member

**check-clean silently wrong · clause 1 · found in review of #3148, the same on master `a20d69104` · filed 2026-09-25 against master `a20d69104`**

Repro:

    function mk(): i32 | string { return 5 }
    const x = mk()
    if x is string { print(1) } else { print(x is i32) }
    // vl check: rc 0.  vl run: prints `false`.  Expected: true
    // PRINTS false

#### Mechanism

Not yet located. In the `else` of a failed `is string`, the global `x` is narrowed to `i32`,
and the `x is i32` test there reads the narrowed global at a rep whose tag check fails. The
function-scope spelling and the un-narrowed test both answer `true`, so the ingredient is a
narrowed module GLOBAL of a value union. `boolean | i32` and `boolean | string` fail the same
way; record unions do not.

#### Ablation

| ingredient changed | outcome | needed? |
| --- | --- | --- |
| the same program inside a function | prints `true` | **yes** |
| no preceding `is string` (`print(x is i32)`) | prints `true` | **yes** |
| `boolean \| i32`, testing `is boolean` then `is i32` | prints `false` | no |
