### D15458 — two arguments sharing a function type parameter, one a generic and one a hole or closed function, the generic's parameter called at two types, run only through the split plan

**runs today and must keep running · runs with the split plan on and off since 2026-11-05: the joined-set rule takes a hole function as a set member beside a generic, and a parameter the joined type parameter annotates runs every member of the union (`fnTagJoinsWith`, check_elab_cap.vl; `elabParamArgTargets`, emit_elab.vl); a closed function or closure beside the generic still runs only through the plan, D15464 · was plan-dependent: with the plan off (`compileSrc` returning after its first compile) a loud emit reject, `emitProgram: cannot take the generic function `same` as a value — a function value carries ONE signature` · a hidden split-plan dependent, still one at `d7080b05` after D15409's joined-set rule (#6388), which serves two generic arguments · split-plan group F (owner: lane split-dep-F) · found closing D15453, from its `go<F>(a: F, b: F)` spelling · filed 2026-11-05 against master `d7080b05`**

#### Mechanism

Two gaps, both in the joined-set rule (D15409). `fnTagJoinsWith` admitted only declared generics
as members of the union, so `dbl` declined it and `same` was taken as a value of one signature.
With hole functions admitted, the order `go(dbl, same)` still refused: the instance runs each
call through `a` on the members of `a`'s own argument (`elabParamArgTargets`), so `same` was
never instanced at `i32` and the call's fact was incomplete (`ftMintComplete`). A parameter the
joined type parameter annotates now runs every member of the union. Before this: `a` and `b` share `F`. Where both arguments are generics, #6388 binds `F` to their
joined set and the program runs without the plan (the second ablation row). Here the second
argument is a hole function, or a closed one, and the unsplit compile takes `same` as a value of
one signature.
