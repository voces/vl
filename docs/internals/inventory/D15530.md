### D15530 — a type parameter only a `null` reaches, held inside a list or record `| null` parameter, has no `never` instance

**closed 2026-11-06 — the filed repro prints `true` · was a loud emit reject, clause 2, the composite face of [D3178](D3178.md) · closed per the coordinator's ruling: a `never` list element or record field reps as the D4551 default `i32` (`repNeverCanon`), since no value reaches it, and D3178's rule binds `never` for any `X | null` parameter naming the type parameter · `rep-fuzz-check` exact · fixture `tests/cases/generics/null-only-type-param-binds-never.vl` · filed 2026-11-06 against master `22ca42d59`, closed against master `a398ab268`**

Repro:

    function F<Z>(z: Z[] | null) {
      if z != null { print(z[0].f()) }
    }
    F([{ f: () => true }])
    F(null)
    // vl check: rc 0.  vl build: emitProgram: callee is not a function name

Want:

    true

#### Mechanism

[D3178](D3178.md)'s ruling binds a type parameter whose only argument is a `null` to `never`,
but only where the parameter is a bare `Z | null`. Here `Z` sits inside the list, so `F(null)`
still takes the D4551 default `F<i32>`, whose guarded `z[0].f()` calls a member of an `i32`.
Binding `never` here gave the parameter the type `never[] | null`, which had no value
type: the valtype ladder refused it (`a parameter type the valtype ladder has no rung for`), and
`Z[] | null` read only through `.length` stopped running. The close gives `never` that
representation: the rep derivations read it as the default `i32` inside a list or record, and mono
spells the default where an instance's annotation names the bound parameter, since `never`
resolves as a name in a result position alone.
