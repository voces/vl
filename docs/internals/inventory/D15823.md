### D15823 — a fresh record binding that drops a field is not lifted when it is held in another literal or a list element

**loud check reject · clause 2 · filed 2026-11-11 with D15093's close**

Repro:

    type A = { k: i32, legs: i64 }
    type H = { a: A }
    let n = 0
    function f(): boolean { n = n + 1
      return true }
    const sv = { k: 1, legs: 4, purr: f() }
    const h: H = { a: sv }
    print(h.a.legs + 1)
    print(n)
    // vl check: rc 1 — an object value of shape {k: i32, legs: i32, purr: boolean} flowing into A
    //   (reached through {a: {…}} into H) drops the field `purr`: … not yet supported by codegen

Want:

    5
    1

#### Mechanism

The drop adoption (`recDropAdopt`, D15093) settles a delivery whose source is the binding itself.
Here the source is the outer literal `{ a: sv }`, so the seam's refusal fires before the binding is
reached. The list spelling (`const xs: A[] = [sv]`) is refused the same way; DECISIONS s12 also
keeps a list element out of the arm lift. The nested-literal spelling of D3566
(`const sv = { pet: { …, purr } }` returned as `Box`) is the same family, a level down.
