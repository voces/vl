### D16869 — an un-annotated map's record value read both into a union of records and at its own record type builds a module that fails to validate

**check-clean invalid wasm · `vl check` rc 0, `vl run` invalid module, `expected (ref $union box), found (ref null #anon)` · clause 1 · the same mix is refused at check for a `const` of the literal and for a list ("holds only a literal, so it is built as …") · found closing D16866 · filed 2026-11-16 against master `4bc9c9ee0`**

Repro:

    type Node = { v: i32, next: Node | null } | { e: i32 }
    function sumNode(n: Node | null): i32 {
      if n == null { return 0 }
      if n is { e: i32 } { return n.e * 100 }
      return n.v + sumNode(n.next)
    }
    function plain(r: { v: i32, next: { e: i32 } } | null) { return 1 }
    const m = Map()
    m["k"] = { v: 3, next: { e: 1 } }
    print(sumNode(m["k"]))
    print(plain(m["k"]))
    // vl check: rc 0.  vl run: invalid module

The design wants a check refusal here, as `const b = { v: 3, next: { e: 1 } }; sumNode(b); plain(b)` gets:
`argument 1: expected {v: i32, next: {e: i32}}, got {v: i32, next: Node | null} (`b` holds only a literal, so it is built as …)`.

#### Mechanism

The map's value is built at `Node`'s arm since D16866. The read at the map's own record type is
an own-storage delivery, but a map read is not among `recOwnSrc`. So neither
`recAdConflict` nor `recApartRefuse` sees it. The `const` and list spellings are
refused through that path.
