The design wants a check refusal here; `const b = { v: 3, next: { e: 1 } }; sumNode(b); plain(b)`
is refused at the `plain` read ("`b` holds only a literal, so it is built as …").

#### Mechanism

The `plain` read refuses the map's adoption at the arm, so the re-check undoes it and the map
keeps its own record. `recElemWalk` still exempted a read of a `Map()` as built where it flows,
so the read delivered to the union was not refused. A map whose adoption was undone is now
judged by its type, as an annotated one is.
