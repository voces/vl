### D3981 — a literal-union mismatch names no member when the value is an if/else tail or a prefix minus, and an `f64` literal equal to a member reads as a non-member

**loud check reject · diderven DV-602 follow-up, from the review of #3518 (head 8dfdc3ae4db9) · filed 2026-10-11 against master `1df3c8f91`**

Repro:

    type L = 1 | 2 | 3
    function pick(x: boolean): L {
      if x { 1 } else { 5 }
    }
    const b: L = -2
    const c: L = 2.0
    print(pick(true))
    print(b)
    print(c)
    // vl check: three errors. #3518's "is not one of L" note fires on none of the first two,
    // and on the third says `2.0` is not one of `1 | 2 | 3`.

#### Mechanism

#3518's note reads the literal from the delivered expression only when that expression IS a
literal node. An if/else tail is an `IfExpr` whose arms are the literals, and `-2` is a
unary node over `2`, so neither is seen. `2.0` is seen, but the member comparison is textual
across numeric kinds: the right sentence is that an `f64` cannot be delivered to an integer
literal union, not that 2 is absent.

#### Grading list

`const d: L = 2` (an annotated, member literal) must stay accepted with no note.
