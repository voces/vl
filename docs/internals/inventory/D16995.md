### D16995 — a read-only empty map or set looped into a typed `let` loses its loop variables

**closed 2026-11-18 — the witness prints `0` · was a check reject (`undeclared identifier 'k'`) of a program that ran before #9062, clause 1 regression · #9062 let a read-only container skip its declaration default when a loop read it into a typed `let`, but pinned only a list at loop entry (`forInPinFromTypedRead`), so a map's or set's loop variables bound to no type · the skip now applies to a list only (`listReadTyped`, `check_statements.vl`); a map or set keeps its default, as before #9062, until [D16994](D16994.md) gives it the list's treatment · fixture `tests/cases/inference/read-only-empty-map-set-loop-into-typed-let.vl` · filed 2026-11-18 against master `8c3f2b9d8` by lane F1**

Repro:

    const m = Map()
    for k, v in m { const a: i32 = k; const b: i32 = v; print(a + b) }
    print(m.length)

Want:

    0

#### Mechanism

`cwBindingReadTyped` answers for any `let`, and #9062's step-aside in `checkLetDecl` read it for
every read-only container. The loop-entry pin that replaces the default calls
`pinOpenRowFromDest`, which pins a `TyArray` only, so a `TyMap` or set row stayed an open hole and
`for k, v in m` declared neither variable.

#### Ablation

| ingredient changed | outcome | needed? |
| --- | --- | --- |
| a list in place of the map | runs | **yes** |
| the `let` unannotated | runs (no typed read, the default applies) | **yes** |
| a `Set()` looped `for x in s { const a: i32 = x }` | same refusal | no (both faces) |
