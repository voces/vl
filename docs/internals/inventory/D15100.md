### D15100 — a list-value function called through two sets by two of its instances keeps both sets closures, so a hole function called at two types beside it builds only through the split plan

    function mul(a, b) { return a * b }

#### Mechanism

`same`'s call `g(s, s)` goes through `{add}` in the instance `inner`'s list call makes and through
`{mul}` in `swap`'s. `same` is a value of a list, so the elaboration's rule for one call through
two sets in two instances (`elabMintFactsIn`, `elabMintValueFns`) marks both sets partial: a
closure of `same` names one instance, whose `g` cannot hold two sets. `{add}` therefore stays a
closure, and `twoCalls`, calling it at two types, has no instance to call. The rule could relax
only where every holder of `same` dispatches, which needs the holders' sets and the arm sets
decided together.

#### Close

The rule now marks a member partial only when an untagged set some call goes through holds it
(`elabFnSetMembersUntagged`). A call through a tagged set dispatches at that call, so each
instance of the member takes its own arm and its `g` holds that instance's set. A closure call,
such as `for f in [apply2] { f(h) }` over an untagged one-member set, still names one instance,
so its member keeps the rule.
