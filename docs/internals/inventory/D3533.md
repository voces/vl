### D3533 — a `reduce` callback joining two type parameters, tested with `is`, builds invalid wasm

**check-clean invalid wasm · clause 1 · open · the same on master `f6e17953b` · found by the #3344 review (`rv3344-aZMQ/p/t4.vl`) · filed 2026-10-03 against master `f6e17953b`**

Repro:

    import { reduce } from "std:array"
    function F<A, B>(k: i32, a: A, b: B) {
      const xs = [0, 1, 2]
      const n = reduce(xs, (acc: i32, i: i32) => { const v = if i == k { a } else { b }; if v is i32 { acc + 1 } else { acc } }, 0)
      print(n)
    }
    F(0, 3, "t")
    F(1, "t", 3)
    // vl check: rc 0.  vl run: invalid module inside `__lambda_1`, "type mismatch: expected i32, found (ref $type)"

Want:

    1
    2

#### Mechanism

Not localised. The callback's `v` joins `A` and `B` inside a lambda passed to a generic `std`
function, so the join is neither the enclosing body's kept-apart one nor a box the callback
clone registers; `v is i32` reads it as the scalar while the arm delivers the box.
