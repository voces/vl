### D4380 — dogfood: `std:process` runs one child at a time with no timeout, so the optimizer parity harness is bash

**runs today and must keep running · the witness runs; the gap is what it cannot express · filed 2026-10-13 against master `d4a5496ed`**

Repro (runs, prints `0`):

    import { ProcessOutput, runProgram } from "std:process"

    const r = runProgram("true", [])
    if r is ProcessOutput { print(r.code) } else { print(r.msg) }
    // One child, started and waited for in one call. There is no way to start a second
    // before the first exits, to bound how long it may run, or to give it one variable
    // of its own environment.

#### Mechanism

`scripts/opt-parity.sh` builds every program of tests/cases and the distilled corpus twice
with `-O` and compares the two sides. It needs three things a VL script cannot do today: run
several builds at once (`xargs -P`), kill one that hangs (`timeout`, so a non-converging build
is UNCOMPARED instead of a stalled harness), and set a side's selector variable and the `wasm-opt`
shim's log path for one child only. `runProgram` is synchronous (`__proc_run__` waits for the
child) and inherits the caller's environment, so a VL port would run every build serially
with no bound on any of them. Routing each child through `env` and `timeout` as the command
covers the last two; running children concurrently is the gap.

#### Grading list

The harness is the consumer: the row closes when `scripts/opt-parity.sh` can be rewritten in
VL with its parallelism and its timeout, and the optimizer port's later rungs
(docs/internals/optimizer-in-vl.md) reuse that VL harness.
