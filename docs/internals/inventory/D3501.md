### D3501 — a join of a declared type parameter, a parameter hole and a `null` loses the null when the caller re-folds it

**closed 2026-10-03 — the witness prints `1`, `s`, `null` · was loads then traps, clause 1 · the same on master `04ec2ef6f` and at #3337's first round · found by #3337's review · filed and closed against master `04ec2ef6f` · fixture `tests/cases/generics/hole-param-join-keeps-null-arm.vl`**

Repro:

    function F<A>(k: i32, a: A, b) { if k == 0 { a } else if k == 1 { b } else { null } }
    print(F(0, 1, "s"))
    print(F(1, 1, "s"))
    print(F(2, 1, "s"))
    // vl check: rc 0.  prints `1`, `s`, then `wasm trap: cast failure` at the third call

Want:

    1
    s
    null

#### Mechanism

The return holds a hole, so it is a deferred join each call site re-folds against its own
bindings (`refoldJoinUnion`). The re-fold joins the bound members with `joinRetTys` under a
lambda depth, where no parameter is kept apart, so the null collapsed into the members beside it
and the caller typed the call without it while the instance returned the null tagged in its box.
Filed as a declared parameter absorbing the hole; the fix that closed it is D3497's second half,
which keeps the null of a join `paramNullJoin` made through the re-fold (`paramNullJoins`).
