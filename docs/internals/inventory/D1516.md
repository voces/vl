#### Mechanism

An un-annotated parameter is an open HOLE, so `monoWalk` pins the instance from the ARGUMENT.
Every channel `monoArgTyName` had for a union asks a BINDING — a parameter annotation, an
annotated or inferred local, a global's init, a callee's return spelling. A PROJECTION is none
of those: the `Index` arm resolved an element only when the array's own NAME already resolved
through one of those arms, and the `Member` arm read a nested-STRUCT field (code 15) alone, so
a union-valued field or a map read reached nothing. The ladder then hit `if exprUnion(ix, fnIx)
{ return "" }` — a deliberate LOUD floor, correct in preferring a refusal to the `"i32"`
catch-all, but a floor asked one question too early.

The `exprStruct` floor two lines down already asks that question ("the checker's recorded
SHAPE, routed through the one pin membership list, AT THE FLOOR so it can re-pin nothing the
ladder resolved"); the union floor did not. `monoUnionPinName` is that consult, with one extra
rung the struct side does not need: `tyToEmitName` renders a declared alias as its MEMBER SET
while `monoAnnPinName`'s union rung (`isUName`) reads `unNames`, the ALIAS column, so the two
spellings never met and a `type Val = …`-typed read still had no pin. `unRowOfCanon` keys the
registry on the canonical id instead — the same hand-over `anonUnionFieldName` makes on the
field side — and the name handed back is the registry's own.
