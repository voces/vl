### D16900 — a lambda's scalar result returned through a generic's `() => T | string | null` is tail-called unboxed, and the module fails to validate

**check-clean invalid wasm · clause 1 · `vl check` rc 0 · `vl run`: `the emitted module failed to validate inside \`get\`: … type mismatch` · found grading [D14082](D14082.md) · pre-existing on master `d7a6bf679` · filed 2026-11-16 by lane AE4**

Repro:

    function get<T>(f: () => T | string | null): T | string | null { return f() }
    const r = get(() => 5)
    print(1)

Want:

    1

#### Mechanism

The instance `get<i32>` lowers `return f()` as `return_call $__lambda_0`, a direct tail call to
the lambda, whose result is a bare `i32`, while `get`'s result is the `i32 | string | null` box.
Without the `null` member the same call boxes and runs. Not traced further.

#### Ablation

| ingredient changed | outcome | needed? |
| --- | --- | --- |
| `() => T \| string`, no `null` | runs | **yes** |
| `get(f: () => i32 \| string \| null)`, not generic | runs | **yes** |
| the result read back (`r is string`, `r == null`, `r + 1`) | still invalid | no |

- With a record result (`() => ({a: 2})`), the refusal is [D16901](D16901.md)'s.
