**runs today and must keep running · the witness runs under `vl run`; the defect is `vl fmt --check` on it, which the grader does not drive · found closing D2182 · filed 2026-09-23 against master `0c117d0c3`**

Repro (runs, prints `10000`):

    function f(a: i32): i32 {

      @@repeat(10000, "{ const m = acc + 1; acc = m; ")@@ @@repeat(10000, "} ")@@

    //   no capacity for allocation of 2147483688 bytes". A file that is merely unformatted
    //   also exits 1, with "<file>: not formatted".

#### Mechanism

The formatter's output is quadratic in nesting depth (each level indents once more), about
300 MB of text at 10,000 levels, and `joinOut` gathers it as a code-point list, so the list
asks the GC heap for 2 GiB and the allocation fails. The host reports that failure as an
ordinary error, which exits 1. A compiler trap exits 70 with a banner. So a caller branching on
`--check`'s exit code, including `tests/vl_deep_else_chain_test.ts`, reads an out-of-memory
formatter as "not formatted". The fix is the exit code: a failure inside the seed during `fmt`
should be 70, like any other compiler failure. A smaller output buffer (bytes rather than code
points) would move the depth at which it happens, not the ambiguity.

#### Grading list

`vl fmt --check` on this witness: want exit 70 (or 0/1 with a rendering), never 1 with an
`Error:` report. `tests/vl_deep_nesting_test.ts` reads stderr to tell the two apart today.
