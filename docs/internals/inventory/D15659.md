### D15659 — a value join of list or record literals, one holding a generic named function and one an annotated function, inside a generic function, builds no instance of the generic

**closed 2026-11-11, runs and prints `2` · was loads then traps, clause 1, `vl check` rc 0, then `wasm trap: indirect call type mismatch` · found closing the row PR #7136 files for the hole-callee spelling · filed 2026-11-11 against master `98b73ba7` · closed in mono: `monoElabDeliver` (emit_mono.vl) now delivers a function name inside a generic instance's literal arm at the join's closed type, as it already did outside one; only the literal's retype stays the template's · the record, direct-call, nested-list and hole-callee spellings, and two instances joining at `(i32) => i32` and `(string) => string`, run too · fixture `tests/cases/functions/list-or-record-join-of-generic-and-annotated-member-in-generic-fn.vl`**

Repro:

    function id1(a) { return a }
    function id3(a: i32) { return a }
    function pickB(c) {
      const k = if c { [id1] } else { [id3] }
      print(k[0](2))
    }
    pickB(true)

Want:

    2

#### Mechanism

The checker joins `((_) => _)[]` and `((i32) => i32)[]` to the closed `((i32) => i32)[]`. The
`[id1]` arm keeps its open type and no tag set is formed, so the arm's `id1` is delivered at the
join's type by mono (`monoCoerceIfArms`, `monoElabDeliver`). `c` is a hole, so `pickB` is generic
and the `if` is walked in its instance. There `monoElabDeliver` refused every function-valued
part, so `id1` got no instance and was emitted with no parameters or result. Its closure thunk is
typed `(structref)`, and the call at `(structref, i32) => i32` traps.
