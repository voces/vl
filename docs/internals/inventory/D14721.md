### D14721 — a list literal pushed onto a generic's list of lists keeps the element rep of the generic's first instance

**check-clean invalid wasm · clause 1 · found closing D14735 · filed 2026-10-31 against master `b264c8ef2`**

Repro:

    function w<T>(v: T[][], x: T) {
      v.push([x])
    }
    const a: string[][] = []
    const b: f64[][] = []
    w(a, "s")
    w(b, 2.5)
    print(a.length + b.length)
    // vl check: rc 0.  vl run: invalid module inside `w`: type mismatch: expected i32, found (ref $type)

Want:

    2

#### Mechanism

Not yet located. The inline `[x]` handed to `push` is built at the element rep of the
instance that is emitted first. The order of the calls decides the outcome: `f64` first,
then `string`, runs.

#### Ablation

| ingredient changed | outcome | needed? |
| --- | --- | --- |
| calls reversed (`f64` instance first) | runs | **yes** (the order) |
| `i32` then `f64` | still invalid | no (a ref first element is not needed) |
| `string` then `string` | runs | **yes** (two reps) |
| `const y = [x]; v.push(y)` | runs | **yes** (the literal inline in `push`) |
| `v[0] = [x]` instead of `push` | runs | **yes** (`push`) |
| `T[]` and `v.push(x)` | runs | **yes** (the nested list) |

#### Grading list

The witness at `i32` then `f64`, and the same calls made with empty `[]` arguments,
`w([], "s")` then `w([], 2.5)`, which reach it since D14735.
