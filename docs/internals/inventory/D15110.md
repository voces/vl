### D15110 — a `let` in a generic body seeded with a generic and written with a hole lambda, returned from two instances, calls the second instance's lambda at the first's type

**check-clean silently wrong · clause 1 · with the split plan on and off · found writing slice 4b's escape control (per-instance-identity-2026-11.md, M3) · filed 2026-11-03 against master `4a114e6cd`, pre-existing**

Repro:

    function inner<U>(u: U) { print("I"); print(u) }
    function a<T>(x: T) {
      let k = inner
      k = (u) => { print(u) }
      return k
    }
    a(1)(2)
    a(true)(false)
    // vl check: rc 0.  vl run: prints `2` then `0`

Want:

    2
    false

#### Mechanism

Not yet located. Measured: each instance alone runs correctly, so the defect needs two instances of
`a` whose returned value is the lambda written to `k`. That value leaves its instance, which the
per-instance identity design keeps a closure (M3, "an id that leaves the instance"). The second
instance's closure prints through the first instance's `print` arm: in the swapped order the output
is `false`, `true`. With `a(1)("x")` first, the second call traps.

#### Ablation

| ingredient changed | outcome | needed? |
| --- | --- | --- |
| only `a(true)(false)` | runs, `false` | **yes** (two instances) |
| `a<T>(x: T)` → `a()`, called `a()(2)`, `a()(false)` | runs, `2 false` | **yes** (the generic body) |
| `let k = inner` dropped (`let k = (u) => …` written twice) | loud emit reject | **yes** (the generic seed) |
| a call `k(x)` added in the body | still wrong | no |
| the order of the two rows swapped | prints `false true` | no |

#### Grading list

The swapped order, and `a(1)("x")` followed by `a(true)(false)`, which traps today.
