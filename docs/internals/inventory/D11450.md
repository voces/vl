### D11450 — a generic alias whose field is a list of an inline record, handed as a literal to a generic, has no ref-list slot

**closed · runs, prints `1` · was loud emit reject, `emitProgram: ref-list field element type is not interned`, `vl check` rc 0, clause 2 · CAPABILITY: the parameter concrete, `function f(v: B<i32>)`, prints `1` · found by the D10930 lane probing its neighbours · present on master `4e10a2462` · filed 2026-10-23 against master `4e10a2462` · closed with [D11451](D11451.md), one mechanism: the arena walk skips a generic alias's array field whose annotation mentions the alias's parameter, so the original's spelling mints no ref-list slot (`gaeParamFieldNodeIs`, emit_collect.vl) · fixture `generics/alias-inline-record-list-field.vl`**

Repro:

    type B<U> = { s: { g: U }[] }
    function f<T>(v: B<T>): i32 { v.s.length }
    print(f({ s: [{ g: 3 }] }))
    // vl check: rc 0.  vl run: emitProgram: ref-list field element type is not interned

#### Mechanism

The arena walk (`collectATypeRef`) also visits the alias declaration's own field annotation
`{ g: U }[]`. Its ref-array rung minted a ref-list slot for the element `{g:U}`. Every later
element whose rep key matched that slot was then deduplicated onto it: the literal's `#anon0`
and the application's `{g:i32}`. The slot is stored under the name `{g:U}`, so the
by-name lookup for the literal's row field (`sFieldRefSlot` → `rlSlotByNameTy("#anon0", -1)`)
found nothing. The first `collectA` gave `#anon0` its own slot. The re-runs after
`monomorphize` deduplicated it onto `{g:U}` (traced with a probe on the field-table intern).

The fix records each generic-alias field whose declared annotation mentions a parameter
(`gaeDeclFieldTyName` already asks `gaeAnnHasParam`). The walk now skips those nodes when they
are arrays, as it already skipped `T[]` and `(T | null)[]`. Each application still interns its
own element through `gaeEnsure` and the field-table phase.
