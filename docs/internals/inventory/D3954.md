### D3954 — a capture cell in a generic body is refused for a shared writer that the program never runs

**closed 2026-10-13 by lane SC · runs · was loud emit reject · pins: `tests/cases/closures/capture-cell-written-with-generic-by-shared-closure.vl` · found in review of #3498 (`rv3498/w12`) · filed 2026-10-10 against master `429e7b093`**

Repro:

    function inner<U>(u: U) { print("I"); print(u) }
    function other<V>(v: V) { print("O"); print(v) }
    function a<T>(x: T, w: boolean) {

      k(x)
    }

#### Mechanism

A capture cell's element store `k[0] = other` recorded its delivery but never instanced the
written generic, and a call through the cell, whose rewritten callee `k[0]` has no recorded type,
took no type at all; each instance of the enclosing generic needs `other` at the cell's type as
that instance spells it. Closed by lane SC (fn-value-flow §(f) step 3): `monoWalk`'s Index arm
coerces the stored value at the element's type, and `monoCellCall` reads the cell's type at the
instance's bindings (`monoCellFnTyNameAt`). The Index-arm coercion is the one this row needs:
removing it alone restores the refusal.
