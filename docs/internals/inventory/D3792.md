#### Mechanism

`monoArgTyName` reaches its ref-array floor for a call or projection argument and pins
`tyToEmitName` of the recorded type. That render is structural and lossy: it spells `Hit` as
`{tick:i32,kind:string}`, and a recursive `Node` as `{key:i32,kids:Node[]}`. The instance then
mints rows for a union of two string-kinded records (or for the unfolding, D3791) that no twin
test can equate with the declared `Hit`/`Miss` variants or `Node`. The recorded element is the
declared record itself (`structNameOfTy` names it by arena identity), so the pin is now that
name, `St[]`, which is what an annotated binding of the same list already pins.
`monoDeclRecListPinName` replaces only the floor's own render, only for a writable list.
