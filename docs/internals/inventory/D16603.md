### D16603 — an empty list bound to a `const` in a function body and handed to an un-annotated callback is checked, in a second instance, at the first instance's type

**closed 2026-11-18 by lane F2 · runs, prints `9` · was a loud check reject, clause 2 · closed by re-asking a hole function's demands, at its second and later calls, with each open empty list its body allocates and hands only to calls of its own parameters replaced by a fresh open list (`instFreshOf`, `check_assignable.vl`; read by `substTyDeep`) · pin: `tests/cases/closures/empty-list-per-instance-of-hole-template.vl` · graded by `empty-list-per-instance-of-hole-template.matrix.vl` · filed 2026-11-15 against master `f56fe94c9` by lane T**

Repro:

    function ef(a: i32, b: f64[]) { return a + b.length }
    function es(a: i32, b: string[]) { return a * 2 + b.length }
    function empty(h) {
      const xs = []

    }
    print(empty(ef) + empty(es))

Want:

    9

#### Mechanism

The binding's open element was pinned in place by the first call's re-asked demand
(`substTyDeep` keeps a concrete type's arena identity), so the second call read the first
instance's element. A list the template allocates is a fresh value per call; the second and later
calls now read a fresh open copy. The emitter already builds each instance's list at its callee's
type (`$mk` / `$mk$1` allocate the f64 and string backings).
