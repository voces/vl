### D15264 — a function's nested record result delivered beside an own-type binding to a record that stores a nested number wider passes check

**open · now a loud check reject · `{j: {f: i32}} is not K: they store field `j` differently (`{f: i32}` into `J`), and the record is also kept at its own type; converting it into K is not yet supported: the converting copy does not reach a nested or nullable field` · clause 2, capability · was check-clean invalid wasm, clause 1, until D15247's refusal: a width `recCopyConverts` does not serve refuses as the copy's gap, so it lifts to `runs` when the copy recurses · fixture `soundness/error-call-shared-with-own-binding-nested-wider-int.vl` · named set `d15247-number-behind-null` · found planning the destringify lane's nested-write row · filed 2026-11-04 against master `62165625b`**

Repro:

    type J = { f: i64 }
    type K = { j: J }
    function mk() { { j: { f: 4 } } }
    const _k: K = mk()
    const y = mk()
    print(y.j.f)

#### Mechanism

`mk`'s result is delivered to `K`, whose nested field `j.f` is stored as `i64`, and is also kept
at its own `{j: {f: i32}}` by `y`. One body builds one record, and no copy converts a nested
field (`recCopyConverts` reads one level), so the delivery passes check and `_k` is handed a
record of `mk`'s own row. The flat twin is copied at the delivery and runs.

| --- | --- | --- |

| `const y = mk()` (`_k` the only call) | runs | **yes** |
