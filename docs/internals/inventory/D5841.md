### D5841 — a `let` hole lambda with an un-annotated function parameter, reassigned anywhere, is refused at emit

**loud emit reject · `vl check` rc 0 · clause 2 · found closing [D5791](D5791.md) · filed 2026-10-17 against master `519a09fef`**

Repro:

    function neg(a) { return 0 - a }
    let lap = (g, x) => g(x)
    lap = (g, x) => g(x) + 1
    print(lap(neg, 4))
    // vl check: rc 0.  vl run: emitProgram: call to unknown function

Want:

    -3

#### Mechanism

From the ablation only. [D5791](D5791.md)'s close instances a call through a `let` hole
lambda only when nothing writes the binding. A written binding holds two lambdas whose `g` is
a hole, and neither lambda gets an instance at the call's function type, so the call through
`g` names no function. With a concrete `neg` the binding is refused as holding functions
called at more than one argument type, though every call passes the same types.
