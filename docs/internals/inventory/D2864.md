### D2864 — a closure in a hole-parameter function reads the parameter's boolean field as `1`

**check-clean silently wrong · clause 1 · identical on master `1df19732b` · found by the #3227 review · filed 2026-09-27**

Repro:

    function R(o) {
      const c = () => o.f
      print(c())
    }
    R({ f: true })
    // PRINTS 1

Want:

    true

#### Mechanism

Not localised past the ablation. The instance's own read of `o.f` formats by the literal's own
type ([D2762](D2762.md)'s close), but the closure is lifted once and its result kind comes from
the shared body, where `o` is the template's hole, so the `boolean` prints through the `i32`
import.

#### Ablation

| ingredient removed | outcome | needed? |
| --- | --- | --- |
| the closure (`print(o.f)`) | runs, prints `true` | **yes** |
| the boolean field (`R({ f: 3 })`) | runs, prints `3` | **yes** |

#### Grading list

`R({ f: true }); R({ f: 3 })`, which prints `1` then `3` and wants `true` then `3`.
