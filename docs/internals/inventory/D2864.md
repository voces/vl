### D2864 — a closure in a hole-parameter function reads the parameter's boolean field as `1`

**closed 2026-09-27 · was check-clean silently wrong, clause 1, on master `1df19732b` · found by the #3227 review · filed 2026-09-27 · fixture `tests/cases/closures/hole-closure-reads-param-field-per-pin.vl` · residue [D2878](D2878.md), [D2879](D2879.md)**

Repro:

    function R(o) {
      const c = () => o.f
      print(c())
    }
    R({ f: true })
    // vl check: rc 0.  vl run: prints `true`.  Was: prints `1`

Want:

    true

#### Mechanism

The closure is lifted once, so its result kind comes from the shared body, where `o` is the
template's hole, and the `boolean` printed through the `i32` import. A call of a `const` bound
in the instance to an un-annotated one-expression lambda whose value is a field of one of the
instance's own parameters (`localCloPinFieldTail`) is now classified by reading that field at
the instance, for `boolean` (`exprIsBool`) and `boolean | null` (`exprNulBool`). Such a call
delivered into a list element or into an argument other than `print`'s, where the field is a
`boolean | null` or `K | null` niche or a union box, is refused (`cloTailRefusal`): the shared
lifted body cannot carry it per pin ([D2879](D2879.md)). A literal-set result keeps master's
refusal, since reading it lets a sibling `string | null` pin reach [D2878](D2878.md)'s trap.

#### Ablation

| ingredient removed | outcome | needed? |
| --- | --- | --- |
| the closure (`print(o.f)`) | runs, prints `true` | **yes** |
| the boolean field (`R({ f: 3 })`) | runs, prints `3` | **yes** |
