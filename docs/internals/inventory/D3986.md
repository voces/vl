### D3986 — a hole lambda written to a `let` of a generic through a binding of it is not re-checked at the call

**check-clean silently wrong · clause 1 · found closing D3968 (`h4`) · filed 2026-10-10 against master `56f77d80f`**

Repro:

    function inner<U>(u: U) { print("I"); print(u) }
    function main() {
      let k = inner
      const f = (x) => { print(x + 1) }
      k = f
      k(true)
    }
    main()
    // vl check: rc 0.
    // PRINTS 2

#### Mechanism

Not located. D3968 re-asks, at each call through such a binding, the body constraints of a lambda
written to it in place. A lambda written through a binding (`const f = …; k = f`) shares its
holes with every other use of `f`, so re-asking the enclosing body's constraints over them at the
call's types refused valid programs (`gen4/r053`); that spelling is left unchecked.

| `f(true)`, called through `f` | loud check reject | **yes** |
