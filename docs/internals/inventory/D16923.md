### D16923 — a maker's lambda delivered at two results over one parameter list and at a third parameter list is refused at emit

**loud emit reject · clause 2 · `vl check` rc 0 · the twin build's residue: the maker's twins at one parameter list key the lambda by result (D16770's per-result path), and the per-signature instance cannot serve the third twin beside them, so every twin keeps the per-result path, which holds one literal to one signature · found by lane SLOT grading the twin build of [D16851](D16851.md) · filed 2026-11-17 against master `e45d81194`**

Repro:

    function deliver() { return (a) => a + 1 }
    const v: (a: i32) => i32 = deliver()
    const w: (a: i32) => f64 = deliver()
    const z: (a: f64) => f64 = deliver()
    print(v(3))
    print(w(3) / 8.0)
    print(z(0.5))
    // vl check: rc 0.  vl run: emit error, `this lambda is handed on at two different function types, and one lambda literal has one signature`

Want:

    4
    0.5
    1.5

#### Mechanism

`elabTwinLamSig` (`emit_elab.vl`) declines every twin of a maker where two of its twins share a
parameter list and differ in result. An instance keyed by parameters cannot tell those two apart,
and serving the third twin with an instance pinned the template slot those two rely on, which
trapped at run time. The declined twins take D16770's per-result clone, which pins the literal at
one parameter list, so the third is refused.
