### D16755 — a relay of a generic maker, delivered at two function types, builds one closure for both

**loads then traps · `vl check` rc 0, `wasm trap: indirect call type mismatch` · clause 1 · found closing [D16710](D16710.md) · filed 2026-11-16 against master `6356d3e7d`**

Repro:

    function k<T>(x: T): T { return x }
    function mk() { return k }
    const o = mk()
    const of: f64 = o(2.5)
    function deliver() { return mk() }
    const v: (x: i32) => i32 = deliver()
    const w: (x: string) => string = deliver()
    print(v(41))
    print(w("s"))
    // vl check: rc 0.  vl run: wasm trap, indirect call type mismatch

Want:

    41
    s

#### Mechanism

`fvaRelayRows` hands a relay's maker call the one closed result every call of the relay is
delivered at. Two results leave it none, so `mk` stays withdrawn from twinning and every call
shares the root's `f64` instance. Building the relay per result, as a maker is, would build the
inner call per twin; the inner call is one node for both, which is why the relay is not twinned.

| the `f64` use through `o` | runs | **yes** |
