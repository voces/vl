#### Fix

A node minted after parsing takes the parser's final cursor as its token, so a refusal anchored
at one resolved to the last token of the last module. The instance's `FuncDecl` is now anchored
at its template's name (`monoMakeInstanceFunc`), and `emitErrTokIx`
(`compiler/driver.vl`) falls back to the statement or function cursor at the failure when the
anchored node still holds that final token. Every shape below then named `take` on lib.vl's
line 3: one file, a function after it, a wrapper call, imported at the module's top level, and a
generic `use<T>` instance imported through an exported function. Since [D15157](D15157.md) each
names the refused read on line 6.

#### Mechanism

The refusal is [D15010](D15010.md)'s, raised while the instance of `use` at the list of `id` is
lowered. That body is lowered out of line, after the statement that called it, so the cursor
`emitFail` anchors at still names whatever was lowered last. With the witness in one file it
lands past the last line; with an exported function after it, on that function's body (`one`,
line 9); across an import, on the entry file. A refusal raised in a function body of the
imported module is anchored correctly ([D15144](D15144.md) names `lib.vl:7:29`), so the
out-of-line instance is the ingredient. [D15153](D15153.md)'s refusal, the first witness, was
anchored the same three ways before it closed. Not traced further.
