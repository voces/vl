### D15155 — a refusal raised while a hole parameter's instance is emitted is anchored at another statement, or in another module

**loud emit reject · the diagnostic's position names the wrong line, or the importing file · filed 2026-11-03 against master `a29da2f2d` by lane column-G1, found looking for a positioned witness for [D1519](D1519.md)**

Repro:

    // file: lib.vl
    type R = { r: i32 }
    type A = { g: Map<string, R> }
    function take(a) {
      const v = a.g.get("x")
      print(v?.r ?? 0)
    }
    const g: Map<string, R> = Map()
    g.set("x", { r: 7 })
    const x: A = { g: g }
    take(x)
    export function one(): i32 { 1 }
    // file: main.vl
    import { one } from "./lib"
    print(one())
    // vl check --codegen: rc 1, `at main.vl:2:13`. The refused call is on lib.vl's line 4.

#### Mechanism

The refusal is [D15153](D15153.md)'s, raised while the instance of `take` at `A` is lowered.
That body is lowered out of line, after the statement that called it, so the cursor
`emitFail` anchors at still names whatever was lowered last. With the witness in one file it
lands on the last function's body (`one`, line 11); with the call wrapped in a function, on
the top-level call of that function; across an import, on the entry file. A refusal raised in a
function body of the imported module is anchored correctly ([D15144](D15144.md) names
`lib.vl:7:29`), so the out-of-line instance is the ingredient. Not traced further.
