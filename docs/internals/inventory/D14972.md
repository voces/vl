### D14972 — a lambda returning a fresh `Map()`, handed back by an un-annotated function and bound at an annotated function type, is called through a signature its closure does not have

**closed · runs, prints `0` · was trap after load, clause 1 · closed by pinning a function value's open result into the function type it is delivered to (`constrainEmpty`) · filed 2026-11-02 against master `097423370`**

Repro:

    function deliver() {
      return (x: i32) => Map()
    }
    const v: (x: i32) => {[string]: string} = deliver()
    print(v(2).length)
    // vl check: rc 0.  vl run: wasm trap, indirect call type mismatch

Want:

    0

#### Mechanism

The lambda has no contextual result where it is written, so its `Map()` stays open and its
closure thunk is typed at the defaulted map. The binding's annotation reaches the lambda only
through `deliver`'s inferred return, after that signature is fixed, and no adapter is placed
between the two; the call at the annotated `$fnsig` then misses the table entry.

#### Ablation

| ingredient removed | outcome | needed? |
| --- | --- | --- |
| the lambda's result left open (`(x: i32): {[string]: string} => Map()`) | runs, `0` | **yes** |
| `deliver`'s return left un-annotated (`: (x: i32) => {[string]: string}`) | runs, `0` | **yes** |
| the binding's annotation (`const v = deliver()`, map bound at the call) | runs, `0` | **yes** |
| the fresh `Map()` (returns a bound map instead) | runs, `0` | **yes** |
