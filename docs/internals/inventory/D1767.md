### D1767 — an else-LESS `if` printed directly asks for a value BOX its `T | null` join does not have, so it refuses with a union's sentence at a niche's rep

**closed 2026-09-06 — the join reps as the value-union BOX, so [D1745](D1745.md)'s mint extends to the `TyNullable` an else-less `if` records, gated on the INNER rep · filed against master `1a5955551`, closed against `cb23d669f` · clause 2 · 0 corpus cells**

Repro:

    print(if true { 1 })
    // vl check: rc 0.  vl run: exit 1,
    // emitProgram: union atom has no value box

The same `if` with an else arm — `print(if true { 1 } else { 2 })` — runs and prints `1`, and
so does binding it first (`const b = if true { 1 }` then `print(b ?? 0)`).

#### Mechanism

**The filed mechanism was predicted, not probed, and the probe refutes its central claim.** The
row said the join is a NICHE that `printUnionPlan` declines. It is not, and the plan does not
decline. Instrumented at the print ladder:

    else-less i32     (loud) nulStr=0 nulBool=0 unionPlan=1 exprUnion=1
    declared i32|null (runs) nulStr=0 nulBool=0 unionPlan=1 exprUnion=1
    bound else-less   (runs) nulStr=0 nulBool=0 unionPlan=1 exprUnion=1

The plan claims all three, including both that run. And a declared `i32 | null` disassembles to
the value-union BOX, not a niche:

    (type $1 (struct (field i32) (field anyref)))     ;; the {tag, payload} box
    (type $3 (func (result (ref $1))))                ;; mk(): i32 | null

Measured across the scalars, the split is exact: `i32`, `i64`, `f64` and `f32` all return
`(ref $uBox)` with the box present; `string` returns `(ref null $str)` and `boolean` an `i32`
— the two niches. So the else-less join needs [D1745](D1745.md)'s mint, and its arm declined
only because it tested `TyUnion` and a `T | null` is a `TyNullable`. The close is that arm
extended, gated on the INNER rep so the two niches still decline — the same derivation a
declared `X | null` uses, not a name list.

**The mint's radius is wider than the family, and that is structural.** The arena records the
same `T | null` for an else-less if-EXPRESSION and an if-STATEMENT over the same scalar, so the
mark cannot tell them apart: a program whose only `if` is a statement grows **1,833 → 1,843
bytes**, and **114 of 2,536 `tests/cases` modules** grow 4–10 bytes each. Narrowing the gate to
the inner rep did not reduce that radius — the recorded type is identical — and no other signal
is available where the mark has to run (`collectA`, before `mAssignTypeIndices`). Nothing
breaks: 0 `runs → not-runs`, 0 SILENT, every `tests/cases` oracle green.
