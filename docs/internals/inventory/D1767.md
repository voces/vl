### D1767 — an else-LESS `if` printed directly asks for a value BOX its `T | null` join does not have, so it refuses with a union's sentence at a niche's rep

**loud emit reject · `vl check` rc 0, `vl run` exit 1, `emitProgram: union atom has no value box` · clause 2 · filed 2026-09-06 against master `1a5955551` · the half of [D1745](D1745.md) its close deliberately does not reach · 0 corpus cells**

Repro:

    print(if true { 1 })
    // vl check: rc 0.  vl run: exit 1,
    // emitProgram: union atom has no value box

The same `if` with an else arm — `print(if true { 1 } else { 2 })` — runs and prints `1`, and
so does binding it first (`const b = if true { 1 }` then `print(b ?? 0)`).

#### Mechanism

Predicted from the ablation, not probed. An else-less `if` joins its THEN arm with `null`, so
the recorded type is `i32 | null` — the NICHE, `(ref null $H)` over the heap the non-null kind
is `(ref $H)` over, and not the value-union box. [D1745](D1745.md)'s close opens the union type
block for an unregistered `TyUnion` join and by construction declines this one, because a
`T | null` is not a `TyUnion`; the refusal that remains is the `print` route asking
`vbHeapIdxOfKind` for a box the niche never needed.

So the sentence and the rep disagree: the message names a union atom, and the value is a niche.
Either the `print` route learns the niche — the way the binding route already has, since
binding the same `if` runs — or the join is minted as a box, which would be an allocation
cliff the niche exists to avoid.
