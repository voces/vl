### D1789 — a nested function that calls a SIBLING nested function is refused, because the sibling's capture is resolved against the caller's frame instead of the frame that declares it

**loud emit reject — `emitProgram: captured variable not found in enclosing frame` · clause 2
· filed 2026-09-06 against master `be5a79fd2`, measured while grading
[D1780](D1780.md)'s matrix; no generic and no monomorphization is involved**

Repro:

    function o(n: i32) {
      function k(x: i32) { return n }
      function m(y: i32) { return k(y) }
      return m(1)
    }
    print(o(2))
    // vl check: rc 0, "Checked 1 file, no errors."
    // vl run:   emitProgram: captured variable not found in enclosing frame

#### Mechanism

`k` captures `o`'s parameter `n`. `m` calls `k`, so the call synthesizes `k`'s closure inside
`m`'s frame and reads `n` from there — but `m` does not capture `n`, only `k` does, so the
lookup runs off the end of `m`'s capture list and refuses. The capture that has to be
materialised belongs to the DECLARING frame (`o`), which both siblings can reach; nothing
threads it that far. `k`'s own frame is right, which is why calling `k` directly from `o`
works at every pin.

Independent of everything else on the nested-capture matrix: it refuses with `o`'s parameter
annotated, with one pin, and with no type parameter anywhere, so the monomorphizer never runs.
Respelling both siblings as lambdas runs, so the frame the lambda path builds is the one the
`function` declaration owes.

#### Ablation

| ingredient removed | outcome | needed? |
| --- | --- | --- |
| the sibling hop (`o` calls `k` directly) | runs, prints `2` | **yes** |
| the CAPTURE (`k` returns `x`, not `n`) | runs, prints `1` | **yes** |
| the annotation on `o`'s parameter | refuses, identical | no — both faces |
| both siblings respelled as lambdas | runs, prints `2` | **yes** — the declaration spelling |

  spellings disagree, so the lifting the lambda path performs is the one `function` owes.
