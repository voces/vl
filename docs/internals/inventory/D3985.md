### D3985 — a UFCS std call on a `T[]` parameter inside a generic function is refused at emit

**loud emit reject · `vl check` rc 0 · clause 2 · found during the review of #3528 · filed 2026-10-11 against master `1df3c8f91`**

Repro:

    import { reverse } from "std:array"
    function flip<T>(xs: T[]): T[] {
      xs.reverse()
      xs
    }
    print(flip([1, 2, 3])[0])
    // vl check: rc 0. vl run: emitProgram: callee is not a function name

#### Mechanism

The same program runs when `flip` takes `i32[]`, and when the call is spelled
`reverse(xs)`. So the generic body's member call is resolved to the std function by the
checker but reaches emit still in its member form, at the pin where the receiver is `T[]`.

#### Ablation

| ingredient removed | outcome | needed? |
| --- | --- | --- |
| the type parameter (`xs: i32[]`) | runs, prints 3 | **yes** |
| the member spelling (`reverse(xs)`) | runs, prints 3 | **yes** |

#### Grading list

`xs.removeAt(0)` and `xs.swapRemove(0)` from #3528, and any other generic std:array export
called as a method in a generic body.
