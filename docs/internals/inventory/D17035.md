### D17035 — a generic's tagged union whose `T` sits only in the arm not built passes the checker, and emit's union-arm row check refuses it once the body reads the union

**loud emit reject · clause 1, `vl check` accepts the program · `emitProgram: a union arm's fields are not its row's` (`mAssignUnionHeaps`, `emit_collect.vl`) · found by lane F2 beside [D17033](D17033.md), which is another mechanism (that fix leaves this outcome unchanged) · filed 2026-11-20 against master `48a54c094`**

Repro:

    function mk<T>(_x: T) {
      const y: { k: "g", v: i32 } | { k: "h", w: T } = { k: "g", v: 1 }
      print(y.k)
      return 0
    }
    mk(3)
    mk("s")
    // vl check: rc 0.  vl run: emit error, emitProgram: a union arm's fields are not its row's

Want:

    g
    g

#### Mechanism

`mAssignUnionHeaps` gives each union variant its struct row (`variantRowOrMint`). It then refuses
the variant when `variantRowFieldsMatch` finds the row's fields are not the arm's. The arm holding
`T` is the one built per instance. Which arm's fields disagree with which row, and whether the
instance's arm or the generic's open one is collected, is not yet located.

#### Grading list

The alias spelling `type U<T> = { k: "g", v: i32 } | { k: "h", w: T }`; a read of the built arm's
field under narrowing (`if y.k == "g" { return y.v }`) with an annotated `i32` return; the arm
holding `T` built instead, once D17032 checks.
