### D3689 — `d is 1` with `d: f64` compares an `f64` operand against an `i32` constant

**closed 2026-11-16 · runs, prints `true` · was loud emit reject, `an integer literal is test over a float has no settled answer`, refused pending a ruling · ruled (coordinator): `is` is a type test first. An integer literal pattern on a subject with an integer arm (an integer width or an integer literal member) tests that arm, so `i32 | f64` and `1 | 2 | f64` holding `2.0` are not `2` ([D2221](D2221.md) stands). A subject with a float member and no integer arm (`f64`, `f32`, `f64 | string`, `f64 | null`) compares by value, the literal converted to the float, so `1.0 is 1` and `-0.0 is 0` are true and an inexact literal matches its rounding; the subject keeps its float type after the test · fixed in wasmEmit.vl, check_operators.vl, check_narrow_flow.vl and tyquery.vl (`tyFloatIntLitTest`): such a receiver compares each integer literal at its own float width (`emitNumLitEq`, the numeric-literal-union rung, a box's float arm), the checker no longer calls the test never-matching nor folds it, and the tested branch keeps the float members ([D16703](D16703.md)) · pin: `tests/cases/narrowing/float-is-integer-literal-by-value.vl` · the boxed and `f32` spellings are [D16704](D16704.md) · filed 2026-10-05**

Repro:

    const d: f64 = 1.0
    print(d is 1)
    // was: vl check rc 0, vl run emit error, the answer waited on a ruling

Want:

#### Mechanism

Not traced. The `is` lowering over a scalar receiver and an integer literal emits the literal
at `i32` and compares it against the `f64` operand. The union spelling `d is C` with
`type C = 1 | 2` runs and prints `false`, so the two spellings also disagree about the answer;
under the numeric-join ruling a literal adapts to its use, which reads `1.0 is 1` as `true`.
Settle the answer (a ruling if `false` is meant) before fixing the lowering.
