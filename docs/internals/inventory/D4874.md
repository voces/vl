### D4874 — an un-annotated spread of two nested list literals of different rows builds the narrower inner list at its own row

**closed 2026-10-15 — now runs, printing `4` · was check-clean invalid wasm, clause 1 · the spread result is built at the joined element's row, and a fresh inner literal is built there as without the spread · found closing D4871, as the un-annotated face of its spread template · filed 2026-10-15 against master `3affca3dd` · pins: `tests/cases/arrays/spread-fresh-nested-literal-runs.vl`, `scripts/capability-probes/matrix/nested-list-widen-fresh-spread.matrix.vl`**

Repro:

    const v = [...[[1, 2]], ...[[3.5]]]
    print(v[0][1] / 4.0 + v[1][0])
    // vl check: rc 0.  Was: vl run: invalid module, type mismatch: expected (ref null $type), found (ref $type)

Want:

    4

#### Mechanism

The checker joined the two literals to `f64[][]`, but the spread copied each group at the row
its own literal was built at, so the first group's inner list stayed an `i32[]` in an `f64[]`
slot. `spreadFreshDestRow` (wasmEmit.vl) now builds the result at the joined row when every
source of another row is a list literal, and the checker types those literals from it.
