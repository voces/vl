### D15811 — `is K[][]` over a `V[][] | null` receiver in a generic instance answers true for a non-empty list whose elements cannot be `K`

**closed 2026-11-12, prints `0` · was check-clean silently wrong value, clause 1 · the nullable face of [D15763](D15763.md) · found by D15763's matrix · filed 2026-11-12 against master `47ce8f86` · closed with D15763 by `emitListEmptyFitArms` (wasmEmit.vl) testing the arm's emptiness at the depth its elements part, under the non-null test · fixture `tests/cases/generics/is-nested-list-over-union-arm-tests-emptiness-at-depth.vl`**

Repro:

    function probe<V>(v: V[][] | null) {
      if v is f64[][] { return 1 }
      0
    }
    const n: i32[][] = [[1]]
    print(probe<i32>(n))

Want:

    0

#### Mechanism

`emitListEmptyFitArms` admitted only an arm whose elements and `K`'s part at the first list
level. An `i32[][]` arm against `f64[][]` parts at the second, so it was counted as one that
meets `K`, and the test fell back to the static fold. Over a nullable receiver, that fold
answers the non-null test, true for any list. Over a box, it answered false (D15763).

#### Ablation

| ingredient removed | outcome | needed? |
| --- | --- | --- |
| the nesting: `V[] \| null`, an `i32[]` | prints `0` | **yes** |
| the `null` arm: bare `V[][]` | prints `0` | **yes** |
| the contents: `[]` or `[[]]` | prints `1`, which is right | **yes** |
| a third level: `V[][][] \| null`, `[[[1]]]` | prints `1` (wrong) | no |
