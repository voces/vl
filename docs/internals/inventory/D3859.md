### D3859 — the `f64` spelling of D3865: a module-scope hole lambda written into a function-scope `let` alias is emitted at its `i32` default, and the call through the alias traps

**closed (2026-10-08, lane SC) · was loads then traps · named in D3865's grading list as its `f64` neighbour, found in review of #3449 (`rv3449b-probes`) · filed 2026-10-08 against master `de3f15048` · pins: `tests/cases/closures/fn-scope-alias-of-module-lambda.vl`**

Repro:

    const c = (y) => y + 1.5
    const e = (y) => y + 2.5
    function mk(x: f64) {
      let d = c
      d = e
      print(d(x))
    }
    mk(1.0)
    // vl check: rc 0.  vl run: wasm trap inside `mk`, exit 70

Want:

    3.5

#### Mechanism

D3865's. An `f64` parameter at the hole's `i32` default still validates, because the `+` lowers
on the operand's own type, so the module loads. The `call_ref` through `d` then reaches `e` at
a different function type and traps. It is closed with D3865: the write in `mk` is now resolved
in `mk`, so `e` takes `c`'s `f64` signature from the alias.
