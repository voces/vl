### D15145 — a returned bundle parameter held in a generic caller's instance has no member fact there

**closed 2026-11-03 — the repro now RUNS. Was: loud emit reject · clause 2 · `a function returning a parameter called at two signatures is called where its result is not used at one of them` · filed 2026-11-03 against master `e2207958`**

Repro:

    function lap(f) {
      print(f(2.5))
      print(f(3))
      return f
    }
    function mid<T>(x: T, k: i32) {
      const r = lap((a) => a + k)
      print(r(4))
      print(x)
    }
    mid("s", 2)

Want:

    4.5
    5
    6
    s

#### Mechanism

The elaboration noted the member a call's value is used as only for calls outside every
instance, so the clone of the call in `mid`'s instance had no fact and the pick refused. Each of
slice A's facts (`elabCallResultMember`, `elabCallResultTy`, `elabHolderMemberTy`) is now keyed by
the calling instance, as B1's holder facts already were, and emit resolves the instance only for
a call or binding that has one.
