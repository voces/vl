### D10211 — a `null`-result lambda for a generic's `() => T | null` parameter binds nothing and has no argument type

**loud emit reject · `vl check` rc 0 · `emitProgram: monomorphize: unsupported argument type for `f` in a call to `len`` · clause 2 · CAPABILITY: the same call with `(): i32 \| null => null` runs · present on master `d3102bf26` · found closing [D10161](D10161.md) · filed 2026-10-22 against master `d3102bf26`**

Repro:

    function len<T>(f: () => T | null) {
      const t = f()
      if t == null { 0 } else { 1 }
    }
    print(len(() => null))
    // vl check: rc 0.  vl run: emitProgram: monomorphize: unsupported argument type for `f` in a call to `len`

Want:

    0

#### Mechanism

Not traced. The lambda's result is `null`, the union's fixed member, so nothing binds `T`.
D10161's close binds the default for a `string` (or other non-null) fixed member; extending it
to `null` binds `T` at the check but the monomorphizer still finds no argument type for the
`null`-result function, so the binding is not where this refusal is decided.
