### D15122 — a written `let` every write of which reads a function parameter leans on the split plan

**runs today and must keep running · the written half of D15120 · filed 2026-11-03 against master `c37f2f0d8`**

Repro:

    function id<T>(x: T): T { x }
    function dup<T>(x: T): T {
      print("dup")
      x
    }
    function one<F>(a: F, c: boolean) {
      let b = a
      if c { b = a }
      print(a("x"))
      print(b(3) + 1)
    }
    one(id, true)
    one(dup, false)

Want:

    x
    4
    dup
    x
    dup
    4

#### Mechanism

With the split plan off this refuses at emit (`a function-value call has no interned signature`).
D15120's close lets a `let` nothing assigns keep its initialiser's type; this one is assigned, though
every write reads the same parameter, so `elabFnLetTy` still widens it to the written binding's set
and the late tag plan finds no leaf for it. Closing it needs the copy record to say "every write
reads the same source", which it does not record today. `let b = a1; if c { b = a }`, two
parameters sharing `F`, is the same question one step further.
