### D15122 — a written `let` every write of which reads a function parameter leans on the split plan

**closed 2026-11-03 · runs, prints `x 4 dup x dup 4`, without the split plan too · was a split-plan dependency · the written half of D15120 · filed 2026-11-03 against master `c37f2f0d8` · two sources sharing a type parameter are [D15123](D15123.md)**

Repro:

    function id<T>(x: T): T { x }
    function dup<T>(x: T): T {
      print("dup")
      x
    }
    function one<F>(a: F, c: boolean) {
      let b = a
      if c { b = a }
      print(a("x"))
      print(b(3) + 1)
    }
    one(id, true)
    one(dup, false)

Want:

    x
    4
    dup
    x
    dup
    4

#### Mechanism

With the split plan off this refused at emit (`a function-value call has no interned signature`).
D15120's close let a `let` nothing assigns keep its initialiser's type; this one is assigned, with
every write reading the same parameter, so `elabFnLetTy` still widened it to the written binding's
set and the late tag plan found no leaf for it. The copy record now notes the declaration every `=`
into a binding reads, and `pcLetHoldsInit` (unassigned, or every write the initialiser's own source)
is what `elabFnLetTy` asks.
