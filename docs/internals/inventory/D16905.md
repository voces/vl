### D16905 — a lambda returning a list literal, at a list result whose element union holds a function arm, is refused at check

**closed 2026-11-17 — the witness runs and prints `1` · was: loud check reject · `a function of type () => boolean[] cannot be used as () => ((() => i32) | boolean)[] here` · clause 2 · found by the rep fuzzer's declared leg, seed 67883267 cases 109 and 110 · filed 2026-11-16 against master `d7a6bf679`**

Repro:

    const v: () => ((() => i32) | boolean)[] = () => [false]
    print(v().length)

Want:

    1

#### Mechanism

Not traced. The lambda's result is inferred from its list literal alone, `boolean[]`, rather
than taken from the contextual result, and a list never widens, so the function conversion is
refused. A record or list arm in the element union takes the contextual result and runs.

#### Fix

`inferRetAdoptUnionElemList` (`compiler/check_inferred_return.vl`) had a rung per element-union
shape whose rep the annotated form lowers (value, variant-box, map, ref-arm, nested, boxed-field,
nullable-closure), and none for a union holding a function arm. A rung now adopts the contextual
list, at any nesting, when the body's literal is assignable to it.
