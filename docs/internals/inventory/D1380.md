### D1380 — a declared union PLUS a nullable module GLOBAL poisons variant state that survives `modReset`: the next program on the same compiler instance loses a union-variant field

**runs today and must keep running — the filed witness is the POISONER, and that is the row's point · the DEFECT is a PAIR, which a single-program grader cannot express · clause 1 · on the same compiler instance the victim then gets `emitProgram: object literal is missing a union-variant field` (rc 3), where a fresh instance gives rc 0 · gated by `tests/vl_shared_instance_test.ts`, the only instrument that can fail on it · filed 2026-09-03 from a peer session's ci-native claim, reproduced and minimised here**

Repro — the POISONER compiles clean and prints nothing; the VICTIM compiles clean alone and fails immediately after it on the same instance:

    // poisoner.vl — rc 0 alone
    type Circle = { kind: "circle", r: f64 }
    type Rect   = { kind: "rect", w: f64 }
    type Shape  = Circle | Rect
    const gn: Circle | null = null

    // then, on the SAME WebAssembly.Instance, after modReset() + srcReset():
    //   tests/cases/unions/paren-narrowed-receiver-read.vl
    //   -> rc 3, emitProgram: object literal is missing a union-variant field
    //   (rc 0 on a fresh instance)

* **BOTH INGREDIENTS ARE REQUIRED, AND THE ABLATION IS FOUR-WAY.** The three `type`
  declarations alone do not poison. The union declaration plus a `Circle | null` RETURN
  function does not poison. A `Circle | null` global WITHOUT the union declaration does not
  poison. Only a declared union **and** a nullable module GLOBAL together do it — the
  function-return spelling of the same nullable is clean, which is what makes this a global
  registration defect rather than a nullable one.

* **THE FUNCTION BODIES ARE EMPTY, SO NOTHING NEED EXECUTE.** Delta-debugged from a 60-line
  case by greedy line removal down to twelve lines, and every surviving `function` had an
  empty body; hand-narrowing then removed those too. Declaring the shapes is sufficient. The
  leak is in registration, not in the emission of any statement.

* **IT IS ORDER-DEPENDENT AND STICKY.** Reversed, the pair is clean at both spellings. Driven
  a second time, the victim keeps failing — so the corrupted table persists across
  `modReset()` and `srcReset()` rather than being consumed once.

* **THE STANDING GATES ARE BLIND TO IT AND THE HARNESS ALREADY SUSPECTED WHY.** Both files
  pass alone and in corpus order, so `deno task test` and the corpus oracle never see it.
  `tests/cases_wasm_test.ts` builds ONE `WebAssembly.Instance` for the whole file and resets
  per case; its own driver comment already warns *"the instance is shared across cases, so
  don't trust `diagCount` on a success: a stale emit failure could still be sitting in its
  store"*. That comment names the hazard class and this row is an instance of it that the
  reset does not cover.

* **THE PROBE IS TWENTY LINES AND BELONGS IN THE TREE.** One instance, N programs, two arms —
  each file on its own fresh instance, then all of them through one shared instance in
  argument order. Any pair where ALONE and SHARED disagree is a leak. That instrument found
  this in one run and is the only kind that can: a CLI-only check gives every program a fresh
  instance and is vacuous for this whole class.

#### Why the status line says `runs`

**THE GRADER RUNS ONE PROGRAM, AND THIS DEFECT NEEDS TWO.** `check-filed-witnesses.py`
executes a row's first repro block as a single program on a fresh compiler; this row's
poisoner compiles clean by construction, so `runs` is the correct and only gradeable
outcome. Filing it as `silent_invalid_wasm` would make the row read as MOVED forever
against an instrument that cannot see the pair.

So the row is a PIN in the D171/D172/D173 sense, pointing the other way: the poisoner
must keep RUNNING, and the pair is gated by `tests/vl_shared_instance_test.ts`, which is
the only instrument that can fail on it. **Read this row's status as `the witness still
compiles alone`, never as `the defect is gone`** — those are different sentences and only
the test can say the second one.
