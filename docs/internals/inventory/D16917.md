### D16917 — a lambda returning a list of lambdas, at a generic's `() => ((() => T) | boolean)[]`, has no function-value signature for the instance

**closed 2026-11-17 — the witness runs and prints `1` · was: a loud emit reject · clause 2 · `vl check` rc 0 · `emitProgram: a function value's signature is not yet supported — its result type has no representation in the function-value ABI` · was check-clean invalid wasm (clause 1) on master `b2b754548`, `the emitted module failed to validate inside \`gen\``, until [D16905](D16905.md) closed · found grading D16905 · filed 2026-11-17 by lane AE4**

Repro:

    function gen<T>(f: () => ((() => T) | boolean)[]) { return f().length }
    print(gen(() => [() => 1]))

Want:

    1

#### Mechanism

Two lambdas outside the generic are typed at its open parameter. The outer lambda adopts the
contextual result `((() => T) | boolean)[]` ([D16905](D16905.md)'s rung), and its element
`() => 1` is checked against the arm `() => T` and typed `() => T`. With `T` on both sides the call
binds nothing (`bindGenUnionArm` declines an argument member holding a type variable), so no
instance retypes either lambda and emit has no signature for a type holding `T`. Before D16905 the
outer lambda kept `(() => i32)[]`, which the generic binding accepted for the wider list the
non-generic spelling refuses, and the module failed to validate. Handed to lane L2 (instance and
hole territory): a lambda outside a generic carrying its type variable.

[D16918](D16918.md)'s close binds `T` from a lambda's list result and types a fresh list literal
result at the bound type; here it binds nothing, because the inner element lambda is already
`() => T` when the outer result is joined. What remains is that inner lambda's open type.

Tried and reverted, each graded on this witness, `h1` (`T | i32` result read back) and `h2` (`T`
also bound by a `t: T` argument):

- D10133's retype-at-bound-type block (`check_calls.vl`) entered for any lambda argument whose own
  type holds a type variable: no change, `T` is never bound, so the bound type stays open.
- The D16905 rung closing the expected list first, binding `T` from the literal through
  `bindGenInnerUnionArms` and adopting `substTyDeep` of it: no change, the element is already
  `() => T`. Declining the open type altogether restores the invalid wasm.

#### Fix

[D16905](D16905.md)'s rung no longer adopts an expected list that still holds a call's type
parameter (`compiler/check_inferred_return.vl`): the outer lambda keeps `() => (() => i32)[]`, the
call binds `T := i32` through the function arm ([D16918](D16918.md)'s `bindGenInnerUnionArms`), and
`fvaAdapt` builds the fresh literal at the bound list ([D16924](D16924.md)'s re-type). The open
adoption is what kept both lambdas at `T`.
