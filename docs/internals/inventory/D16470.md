### D16470 — `==` in a generic body over a field, call or element read of two records stored apart passes check and is refused at emit

**loud emit reject · clause 1 (`vl check` rc 0) · bucket (e) · probe `scripts/capability-probes/eq-record-generic-field-operands.vl` · found closing D16397 · filed 2026-11-15 against master `0a3dabd9b`**

Repro:

    function eq<T, U>(a: {v: T}, b: {v: U}): boolean { return a.v == b.v }
    print(eq({v: {f: 1}}, {v: {f: 1.0}}))
    // vl check: rc 0.  vl run: emit error, `emitProgram: struct equality is not supported yet`

Want:

    true

#### Mechanism

D16397's instance arm (`monoPinBin`, `emit_mono.vl`) compares two records stored apart field by
field only when each operand is a name. It reads each operand once per field. A call operand
would run once per field. A field read, such as `a.v`, gets no instance type through
`elabNodeTy` at that arm, as observed on the witness. So such an `==` still reaches
the emitter's one-row struct compare.

#### Ablation

| spelling | outcome |
| --- | --- |
| the witness (field reads) | check-clean, loud emit reject |
| `id(a) == b` (a call operand) | check-clean, loud emit reject |
| `a[0] == b[0]` over `T[]` and `U[]` | check-clean, loud emit reject |
| `a == b` over `T` and `U` (names) | runs, prints `true` (D16397) |
| `const p = a` then `p == b` | runs, prints `true` (D16397) |

#### Grading list

- Nullable records through each operand form.
