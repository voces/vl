### D16470 — `==` in a generic body over a call operand of two records stored apart passes check and is refused at emit

**open · loud emit reject · clause 2 (`vl check` rc 0) · narrowed 2026-11-16 by lane AE: a field or element read of a parameter compares field by field at the instance (`monoPinnedReadTy`, `recEqPureRead`), matrix `eq-generic-read-operands-stored-apart.matrix.vl` 72 of 72 graded run, its nullable face was clause 1 (D16810) · bucket (e) · probe `scripts/capability-probes/eq-record-generic-field-operands.vl` · found closing D16397 · filed 2026-11-15 against master `0a3dabd9b`**

Repro:

    function id<T>(x: T): T { return x }
    function eq<T, U>(a: T, b: U): boolean { return id(a) == b }
    print(eq({f: 1}, {f: 1.0}))
    // vl check: rc 0.  vl run: emit error, `emitProgram: struct equality is not supported yet`

Want:

    true

#### Mechanism

D16397's instance arm (`monoPinBin`, `emit_mono.vl`) compares two records stored apart field by
field, reading each operand once per field. A name, a field read or an element read at a name or
literal index has no effect, so re-reading it is sound, and such reads are now typed through the
pin (`monoPinnedReadTy`). A call operand would run once per field; it needs binding to a fresh
local first, so such an `==` still reaches the emitter's one-row struct compare.

#### Ablation

| spelling | outcome |
| --- | --- |
| `a.v == b.v` (field reads) | runs, prints `true` |
| the witness (`id(a) == b`, a call operand) | check-clean, loud emit reject |
| `a[0] == b[0]` over `T[]` and `U[]` | runs, prints `true` |
| `a == b` over `T` and `U` (names) | runs, prints `true` (D16397) |
| `const p = a` then `p == b` | runs, prints `true` (D16397) |
