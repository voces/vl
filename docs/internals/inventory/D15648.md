### D15648 — a hole handed two named functions, called directly and handed on in a record beside a record of one of them, cannot instance them

**loud emit reject · clause 2 · `a generic function taken as a value reaches no call that fixes its type — annotate the destination's function type` · found closing D15640 · filed 2026-11-10 against master `62b80f09`**

Repro:

    function dbl(v) { return v + v }
    function inc(v) { return v + 1 }
    function call0(r, x) { print(r.f(x)) }
    function both(g) {
      print(g(1))

#### Mechanism

D15640's close keeps `{ f: dbl }` a set id only when every call of `both` hands `g` the one
function the record names (`hfbHandsNamed`, check_calls.vl). Here `g` is `{dbl}` at one call and
`{inc}` at the other, so the record is built at a closure and `call0`'s `f64` instance calls a
closure; `dbl`, handed to `both`, finds no call fixing it at `f64`. Dropping the gate makes the
two sets meet in `call0` at one type, which the late tag decision does not route: 177 of 1,620
combination programs lost `runs`, 24 built invalid wasm.
