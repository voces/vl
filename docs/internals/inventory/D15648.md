### D15648 — a function handed to a callee that calls it at two types and adds the results leaves the caller's result untyped in a `const`

**check-clean invalid wasm · clause 1 · `the emitted module failed to validate inside the module's top-level code: … type mismatch: expected i32, found f64` · found closing D15645 · filed 2026-11-10 against master `0898379e`**

Repro:

    function dbl(v) { return v + v }
    function c2(r, x) { return r(x) + r(1) }
    function both2(g) { return c2(g, 2.5) }
    const b = both2(dbl)
    print(b)

Want:

    7

#### Mechanism

`vl check` accepts `const b: string = both2(dbl)`, so the checker leaves the call's result
open: `g` is called at `f64` and at `i32`, so no single instance binds it, and the result is a
binary-operator hole over two hole calls that no binding resolves. The emitter builds `f64`.
Unmeasured past that.

#### Ablation

| spelling | outcome | needed? |
| --- | --- | --- |
| `print(both2(dbl))` (no `const`) | runs, `7` | **yes** |
| `const b: f64 = both2(dbl)` | runs, `7` | **yes** |
| `c2(dbl, 2.5)` at module scope (no `both2`) | runs, `7` | **yes** |
| `g(2.5) + g(1)` in `both2` (no `c2`) | runs, `7` | **yes** |
| `r(x) + r(2)` with `c2(g, 1)` (one type) | runs, `6` | **yes** |
| `c2([g], 2.5)` reading `r[0](x) + r[0](1)` | still invalid wasm | no |
