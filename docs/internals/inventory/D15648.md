### D15648 — a function handed to a callee that calls it at two types and adds the results leaves the caller's result untyped in a `const`

**closed 2026-11-10, runs and prints `7` · was check-clean invalid wasm, clause 1, `the emitted module failed to validate inside the module's top-level code: … type mismatch: expected i32, found f64` · found closing D15645 · filed 2026-11-10 against master `0898379e` · closed in the checker: a direct call of an un-annotated function handed a generic function's open signature, bare or as a list's element, reads the callee's body with that parameter bound to the signature, so each hole call there takes its own instance (`holeGenArgRetAt` from `holeDirectCallRetAt`, check_relate_core.vl); `const b: string = both2(dbl)` is now refused as `f64` · fixtures `functions/hole-fn-handed-on-called-at-two-types-result.vl`, `functions/error-hole-fn-handed-on-called-at-two-types-result.vl` · the list spelling is [D15650](D15650.md), closed with it**

Repro:

    function dbl(v) { return v + v }
    function c2(r, x) { return r(x) + r(1) }
    function both2(g) { return c2(g, 2.5) }
    const b = both2(dbl)
    print(b)

Want:

    7

#### Mechanism

Before the close, `vl check` accepted `const b: string = both2(dbl)`: the checker left the
call's result open: `g` is called at `f64` and at `i32`, so no single instance binds it, and the result is a
binary-operator hole over two hole calls that no binding resolves. The emitter builds `f64`.
`holeDirectCallRetAt` refused the bare argument, whose type is `dbl`'s open signature.
