### D1481 — a `map`/`filter` result whose element is a STRUCT reaches no `std:array` generic: the monomorphizer cannot pin `self`

**loud emit reject · `vl check` rc 0 (it emits only a `redundant type annotation` HINT) · clause 2 · annotating the destination is the rescue · filed 2026-09-03 against master `cdfdc14e`**

Repro (`vl check` rc 0, then `emitProgram: monomorphize: unsupported argument type for `self` in a call to `sorted`` with NO line:col):

    import { sorted } from "std:array"
    type Person = { name: string, age: i32 }
    const people: Person[] = [{ name: "Ana", age: 31 }]
    const adults = people.filter((p: Person) => p.age >= 30)
    const byAge = adults.sorted((a: Person, b: Person) => a.age < b.age)
    print(byAge[0].name)

#### Mechanism

Three ingredients, and the axis is the PRODUCER of the list, not its type: the element is a
struct (`i32[]` and `string[]` both run), the list value comes from a builtin `map`/`filter`
(a declared list runs, and a `std:array` `sorted` result feeding `mapIndexed` runs), and it
is delivered to a generic `std:array` export's `self`. The refusal fires at
`compiler/emit_mono.vl`'s `unsupported argument type for` family, so what the monomorphizer
cannot recover is a TYPE NAME for the un-annotated `map`/`filter` result — annotating the
binding hands it one.

**NOT A RE-FILE OF [D703](#d703)**, which closed the same message over a module-scope
struct-element list. That spelling runs today; the live coordinate is the `map`/`filter`
PRODUCER, which D703's fixture (`std/array-struct-element-module-scope.vl`) does not cover.

**AND THE CHECKER'S OWN HINT POINTS THE WRONG WAY.** On the working file the only diagnostic
is `[HINT]: redundant type annotation: 'people' is inferred as '{name: string, age: i32}[]'`.
Taking that hint does not make the program run — it turns the emit reject into a CHECK
reject. The hint is about the TYPE and this defect is about the REP.

#### Ablation

| ingredient removed | outcome | needed? |
| --- | --- | --- |
| the `map`/`filter` (sort the declared `people` directly) | runs | **yes** |
| the struct element (`i32[]`, then `string[]`) | runs | **yes** |
| the generic callee (a plain read of the filtered list) | runs | **yes** |
| ADDED: annotate the destination (`const adults: Person[] = …`) | runs | the rescue |
| ADDED: route through `function f(xs: Person[])` and sort inside | runs | the second rescue |
| `.map((p: Person) => p)` instead of `.filter` | refuses | no |
| the `type` declaration (spell the shape inline everywhere) | refuses | no |
| the UFCS spelling (free call `sorted(adults, …)`) | refuses | no |
| `sorted` (`reverse`, then `includes`) | refuses, same message, its own callee name | no |
| the intermediate binding (chained `people.filter(…).sorted(…)`) | refuses | no |

#### Grading list

The two rescues must keep running. The three callee names (`sorted`, `reverse`, `includes`)
must all move, since they are one refusal site. `i32[]` and `string[]` elements must keep
running. And the close must be graded at the UN-ANNOTATED spelling, which is the whole
witness — a fixture that annotates `adults` cannot see this defect.
