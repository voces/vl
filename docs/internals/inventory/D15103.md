### D15103 — a written `let` of generics handed to a generic's closed parameter at two types inside a generic body needs an id per instance

**runs today and must keep running · split-plan dependent (W family, per-instance id): with the split plan off (`compileSrc` returning after its first compile) it is a loud emit reject, `the reassigned function binding … holds functions called at more than one argument type` · from G2's minimisation of the "reassigned function binding" group · filed 2026-11-03 against master `1484b3d7`**

Repro:

    function fst<T>(xs: T[]): T { return xs[0] }
    function lst<T>(xs: T[]): T { return xs[xs.length - 1] }
    function app<T>(g: (x: T[]) => T, v: T[]): T { return g(v) }
    function both<U>(u: U[]): U {
      let f = fst
      if u.length > 1 { f = lst }
      print(app(f, [7, 8]))
      app(f, u)
    }
    print(both(["x", "y"]))

Want:

    8
    y

#### Mechanism

The hand `app(f, …)` of the written `let` to `app`'s closed parameter `g: (x: T[]) => T` is declined by `ftCtxOk`: inside `both<U>` the delivery is at `T = i32` in one call and `T = U` in the other, so the binding's set is delivered at a type per instance of `both`. The per-instance identity design (with D15101, D15102) is to cover it.

#### Grading list

Measured 2026-11-05 at master `3be3d0d1`, split plan off, with `fst`, `lst` and `app` as in the
repro and `both`'s body varied. These run: one delivery at `U` (`app(f, u)` alone), also with
`both` instanced at two types; two deliveries at closed types (`app(f, [7, 8])` beside
`app(f, [1.5])`), each through its own adapter. These refuse: a closed delivery beside a `U` one,
in the written-`let` spelling (this row) and in the `const` choice spelling
(`const f = if u.length > 1 { lst } else { fst }`, `a binding of an if choosing generic functions is
delivered at two function types`). The tag decision declines `{fst, lst}` at the `U` delivery
(`ftCtxOk`: `ftParamOfSet`, `ftListCallHoleArg`, `ftSlotWriteArg` and `ftLateArgOfSet` all fail),
so the binding stays a closure, and the `U` delivery is no adapter: the adapter record is per node
(`fnTagEtaWant`), while `U` is closed only per instance of `both`. The close is an adapter built per
instance at that node, which is per-instance closure keying (per-instance-identity-2026-11.md,
slice 4b-iii); parked for that work.
