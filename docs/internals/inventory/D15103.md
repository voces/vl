### D15103 — a written `let` of generics handed to a generic's closed parameter at two types inside a generic body needs an id per instance

**runs today and must keep running · split-plan dependent (W family, per-instance id): with the split plan off (`compileSrc` returning after its first compile) it is a loud emit reject, `the reassigned function binding … holds functions called at more than one argument type` · from G2's minimisation of the "reassigned function binding" group · filed 2026-11-03 against master `1484b3d7`**

Repro:

    function fst<T>(xs: T[]): T { return xs[0] }
    function lst<T>(xs: T[]): T { return xs[xs.length - 1] }
    function app<T>(g: (x: T[]) => T, v: T[]): T { return g(v) }
    function both<U>(u: U[]): U {
      let f = fst
      if u.length > 1 { f = lst }
      print(app(f, [7, 8]))
      app(f, u)
    }
    print(both(["x", "y"]))

Want:

    8
    y

#### Mechanism

The hand `app(f, …)` of the written `let` to `app`'s closed parameter `g: (x: T[]) => T` is declined by `ftCtxOk`: inside `both<U>` the delivery is at `T = i32` in one call and `T = U` in the other, so the binding's set is delivered at a type per instance of `both`. The per-instance identity design (with D15101, D15102) is to cover it.
