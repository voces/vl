### D3659 — a fallible bare `as` over a hole, called through a re-pointed `let` binding, is not re-asked by the checker

**now a loud check reject, the direct spelling's `` `as u8` propagates null `` — fixed 2026-10-05 · was a loud emit reject, clause 2 (the checker owes the refusal the direct spelling gets) · found by lane WV's alias grid for #3379 · master printed the unconverted `2`, silently wrong · filed 2026-10-05 · fixture `tests/cases/numerics/error-as-cast-hole-repointed-let-propagates.vl`**

Repro:

    function k(x) { x as u8 }
    let j = k
    j = k
    print(j(2.5))
    // vl run: emit error, bare null needs a struct-typed context

#### Mechanism

A parked cast is re-asked at the call that pins its hole once the checker can name the callee's
parameter (`holeCastParamName`): a declared function, a `const`-bound lambda, or a chain of
bindings each bound exactly once (`holeCastCalleeDeclOf`, over `cwBoundInitOf`). A binding
written after its declaration names no single callee, so the cast is not re-asked and the
emitter, which reads the hole pin, owes the null the function cannot return. The direct
spelling `k(2.5)` is the check error `` `as u8` propagates null ``.

Fixed by `holeCastWrittenDeclOf`: where the binding is written more than once, the callee is the
one `FuncDecl` that EVERY write of it reaches (its initialiser and each whole `j = e`, through
aliases), so a binding re-pointed at the same function re-asks the cast. Writes that reach two
different functions still name no single callee and stay a loud emit reject: [D3691](D3691.md).
