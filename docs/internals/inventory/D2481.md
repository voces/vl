### D2481 — a UFCS call sharing a block with a later same-named closure reads that closure's not-yet-initialized wasm local

**check-clean invalid wasm · clause 1 · found in review of #3148 against master `0a0d24ac9`, filed 2026-09-25**

Repro:

    function name(self: i32): i32 { self }
    function main() {
      print(5.name())
      const name = (self: i32): i32 => self + 100
    }
    main()
    // vl check: rc 0.  vl run: invalid module, inside `main`:
    // "Invalid input WebAssembly code ...: uninitialized local: 1"

#### Mechanism

Not ablated to a rung. `5.name()` textually precedes the later `const name = ...` in the same
block with nothing between them, so the checker resolves it to the module function `name` — the
local is not in scope yet at that program point, and `vl check` agrees. The emitter appears to
allocate `name`'s wasm local for the whole block once it sees the later declaration anywhere in
it, and the UFCS call's lowering reads that local's slot before its `local.set` runs, which wasm
itself refuses as an uninitialized local. Wrapping the call in its own nested block — so it is
no longer a direct sibling statement of the later `const` — avoids the shared-slot allocation
and the program runs.

#### Ablation

| ingredient removed | outcome | needed? |
| --- | --- | --- |
| a nested block around the call (`{ print(5.name()) }`) | runs, prints `5` | **yes** |
| the UFCS call (`name(5)` direct instead of `5.name()`) | runs, prints `5` | **yes** |
| the later `const name = ...` declaration | runs, prints `5` | **yes** |

#### Grading list

A same-block UFCS/direct-call pair for every scalar type the D2068/D2316 family already covers
for lambdas (i32 self, string self), to confirm the missing rung is shared.
