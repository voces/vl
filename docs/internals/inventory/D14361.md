### D14361 — a function reading a no-initializer `let`, called inside the statement that assigns it after the write, traps

**closed 2026-11-02 by lane column-G1 · runs, prints `1` and `1` · was loads then traps, clause 2 · the read guard of a module `let` with no initializer compared the progress cell against the statement after which D14360 finds it assigned on every path, which a call following the write inside that statement had not passed; such a binding holds its value from its first write, since no initializer runs later to overwrite it, so its guard now tests a per-binding bit every write sets (`gInitBitIdx`, one `i32` global trailing the progress cell) · a call before the write still fails with the same message · a binding only a function assigns keeps D14360's answer and still traps (`globals/read-unassigned-at-top-level-traps.vl`) · fixture `tests/cases/globals/read-after-assign-inside-statement.vl` (`i32`, `string`, a `match`) · the price of [D14360](D14360.md)'s statement-granular position · filed 2026-10-26 against master `3f27774a4`**

Repro:

    let n: i32
    function rd() { return n }
    function show() { print(rd()) }
    if true {
      n = 1
      show()
    } else {
      n = 2
    }
    show()

Want:

    1
    1

#### Mechanism

D14360 gives a no-initializer binding the position of the first top-level statement after
which the checker finds it assigned on every path, and the start function advances the
progress cell after that whole statement. A function called inside the statement is reachable
at that position, so its read is guarded, and when the call follows the write on its own path
the guard still sees the cell short of the binding and calls `__init_fail__`
("`n` read before its initializer ran (line 1), via rd"). The program is well-defined: the
binding is assigned on the path that calls `show`.
