### D2862 — a record with a closure field bound by `let` in a hole-parameter maker reads the closure's result in the first pin's format

**check-clean silently wrong · clause 1 · identical on master `1df19732b` · the `let` residue of [D2853](D2853.md)'s close, found by its `gen_clo` grid · filed 2026-09-27**

Repro:

    function mk(x) {
      let r = { f: x, g: () => x }
      return r
    }
    const a = mk(true)
    print(mk(7).g())
    // PRINTS true
    // vl check: rc 0.  vl run: prints `true`, want `7`

Want:

    7

#### Mechanism

[D2853](D2853.md)'s: the closure's lambda is shared by both instances and its banked return kind
is the first pin's. `makerRetObjLitOf` follows a returned `const` to its object literal so the
field closure is read per instance; a `let` may be reassigned, so it is not followed, and the
read falls to the shared `fRetBool`. Following a `let` needs the binding proven never reassigned.

#### Ablation

| ingredient removed | outcome | needed? |
| --- | --- | --- |
| `let` for `const` | runs, prints `true` then `7` | **yes** |
| the second pin (`mk(true)` only) | runs | **yes** |

The `gen_clo` grid's 12 `let_*` cells (`let_call0_call2`, `let_field0_bound2`, ...).
