### D1545 — an UN-ANNOTATED parameter handed a litunion array element prints the interned ATOM ID: four lines, and only the position matrix could see it

**check-clean silently wrong · `vl check` rc 0, `vl run` prints `0` where `green` is expected · clause 1 · found 2026-09-03 by the `argument` un-annotated cell of `scripts/capability-probes/matrix/inline-litunion-from-list-element.matrix.vl`, the template written to grade [D1541](D1541.md)'s close — a 30-cell hand grid over the same seam had missed it**

Repro:

    const srcArr: ("red" | "green")[] = ["green", "red"]
    function take(a) {
      print(a)
    }
    take(srcArr[0])
    // PRINTS 0
    // want: green

#### Mechanism

The same seam [D1541](D1541.md) names, at the PARAMETER instead of the module global. A
litunion ARRAY is always the interned-i32 atom list, so `srcArr[0]` delivers an i32 id; the
callee's slot takes it (the printed `0` is `__print_i32__` of the id, not a wrong string), but
the READ side asks `exprIsLitAtom` → `bindingIsLitAtom`, whose `Param` arm is
`tyLitUnionAliasIx(nodeTyIxOf(bn.parType)) >= 0` — and a HOLE parameter has no `parType`, so
it answers false and `print` never widens the atom to its member string.

Not yet fixed: D1541's remedy was keyed on `globalLetOf`, which has nothing to say about a
parameter, and the hole param's slot rule has to be established before the read side is
taught to widen — the same order [D1196](D1196.md)'s decline records for the local.

**And the softening is a GAP, not the design** — measured 2026-09-06 by running six spellings,
of which only this row's fails. A LOCAL binding off the same array, a hole parameter fed a bare
member, an ANNOTATED litunion parameter, an ANNOTATED `string` parameter and the named-ALIAS
spelling all print `green`; the INLINE set through a hole parameter prints `0`. The alias
survives to the pin and the inline set does not, and an atom handed to a declared `string`
parameter already widens correctly — so nothing about the design makes a litunion parameter its
base type. DECISIONS.md (2026-09-03) states the mechanism as a RENDERING choice: canon softens a
literal union to the spelling `string` **while its rep is an interned i32 atom**. The rep is the
atom; only the spelling moves. This row is a reader gap to fix, not a contract to write at the
checker. The `==` face of the same parameter is worse than this one and is [D1717](D1717.md):
check-clean invalid wasm rather than a wrong value.

#### Why the hand grid missed it and the matrix did not

D1541's close was graded on a 30-cell hand grid covering the module global, the `let`, the
struct field, the list element, the return, the second hop, the nested element, both
operators and both scopes. **Every one of those bindings was annotated or inferred at a
DESTINATION; none of them was a hole PARAMETER**, which is a delivery position rather than a
destination shape, and a hand grid is written from the shapes its author is thinking about.
`matrix.py` expands one template over all twenty-six positions in both faces, so it asked the
question nobody would have. It is the third instance of that pattern in this inventory and
the cheapest: the template took four minutes and found a clause-1 cell.
