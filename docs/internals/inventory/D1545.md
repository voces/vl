**closed 2026-09-06 — the monomorphization pin had no rung for an INLINE literal union, so it

· found 2026-09-03 by the `argument` un-annotated cell of
`scripts/capability-probes/matrix/inline-litunion-from-list-element.matrix.vl`, the template
written to grade [D1541](D1541.md)'s close — a 30-cell hand grid over the same seam had missed

Repro:

    const srcArr: ("red" | "green")[] = ["green", "red"]
    function take(a) {
      print(a)
    }
    take(srcArr[0])
    // vl check: rc 0.  vl run: rc 0, prints green

Was: `0`, the interned atom id.

#### Mechanism

A litunion ARRAY is always the interned-i32 atom list, so `srcArr[0]` delivers an atom id. What
decides the callee's rep is the MONOMORPHIZATION PIN: `monoArgTyName` has a rung for a declared
alias (`litUnionAliasNameOfTy` → `K`) and had none for an inline member set, so the argument
fell past every rung to the ladder's own `"i32"` catch-all — the answer that function's header
calls "the defect, not the missing arm". An `i32` pin leaves a hole parameter with no annotation
at all, so `paramTypeNode` reads -1, `exprIsLitAtom`'s identifier arm has no channel, and the
atom is consumed raw: `print` prints the id, `==` and `is` emit the string compare core against
an i32 ([D1717](D1717.md)).

The fix is one rung beside the alias one: an inline set has no alias and reps as the softened
`string`, which is the answer the OTHER pin home — `unionParamPinName` in `emit_rewrite.vl` —
already gives to the same question in its own words. The two producers now agree, and the
emitted module is byte-identical to the annotated inline spelling's.

**The pin's ARENA TYPE was never the problem, and the earlier reading of it was a render.** The
checker binds the hole to the literal union in BOTH spellings — probed at the argument, at
`bindGenWalk`'s bind and at `notePinnedHole`, all three read a `TyUnion` of `TyLit` with
`isLU=1` (arena 55 inline, 43 alias). The only field that differs is `tyLitUnionAliasIx`: 43 for
the alias, -1 for the inline set. The earlier `pin=[string]` was `tyToEmitName`, which softens
the ALIAS to `string` too — a render, not a type, so it could not be the discriminator.

**And the softening is a GAP, not the design** — measured 2026-09-06 by running six spellings,
of which only this row's failed. DECISIONS.md (2026-09-03) states the mechanism as a RENDERING
choice: canon softens a literal union to the spelling `string` while its rep is an interned i32
atom. That soften is exactly what the new rung applies; what was missing was applying it at all.

#### Why the hand grid missed it and the matrix did not

D1541's close was graded on a 30-cell hand grid covering the module global, the `let`, the
struct field, the list element, the return, the second hop, the nested element, both
operators and both scopes. **Every one of those bindings was annotated or inferred at a
DESTINATION; none of them was a hole PARAMETER**, which is a delivery position rather than a
destination shape, and a hand grid is written from the shapes its author is thinking about.
`matrix.py` expands one template over all twenty-six positions in both faces, so it asked the
question nobody would have. It is the third instance of that pattern in this inventory and
the cheapest: the template took four minutes and found a clause-1 cell.
