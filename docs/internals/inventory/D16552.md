### D16552 — a read of a re-pointed generic `let` handed to an un-annotated parameter keeps every function written to it

**loud check reject · `operator '+' is not defined for boolean and i32` · clause 2 · open · bucket (c), L2 inferred interfaces: the un-annotated parameter is the ingredient (by ablation, 2026-11-15) · the open-destination face of [D16182](D16182.md): an un-annotated parameter, or an un-annotated `Map()` receiver's `.set` · an L2 acceptance row (`l2-inferred-interfaces-design.md` §A.5 selects it by its bucket) · filed 2026-11-15 against master `d534d4226`**

Repro:

    function inner<U>(u: U) { print(u) }
    function plus<V>(v: V) { print(v + 1) }
    function applyH(f) { f(true) }
    function main() {
      let k = plus
      k = inner
      applyH(k)
    }
    main()
    // vl check: operator '+' is not defined for boolean and i32

Want:

    true

#### Mechanism

An un-annotated parameter called at several types is served by the binding's whole set, one
slot per type (D5611), which a read renamed to one generic cannot be: the generic then carries
one signature (`generic-fn-value-hole-written-binding-at-two-types.vl`). So D16182's close
keeps such a read at the whole set, and the hole parameter's call at `boolean` asks `plus` too.
Closing it needs the set narrowed to the writes reaching the read while keeping its per-type
slots. The cell is the un-annotated `argument` face of `fn-let-read-after-repoint-generic.matrix.vl`.
