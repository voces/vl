### D1480 — a closure in a TOP-LEVEL `for … in` body that captures the loop variable gets the loop's i32 CURSOR in the capture slot, not the element

**check-clean invalid wasm · `vl check` rc 0, then the engine refuses the module · clause 1 · the same loop inside ANY function runs · filed 2026-09-03 against master `cdfdc14e`**

Repro (four lines; `vl check` rc 0, then `Invalid input WebAssembly code … type mismatch: expected (ref $type), found i32`):

    for name in ["red"] {
      const f = () => name
      print(f())
    }

#### Mechanism

Not yet located in the compiler; what the ablation fixes is the coordinate, and the WASM
error's DIRECTION is the sharpest evidence about the slot. A `string` element reports
`expected (ref $type), found i32` and a STRUCT element reports the mirror image,
`expected i32, found (ref $type)` — one capture slot receiving the other of
{loop cursor, loop element}. The top-level `for … in` lowering is the only ingredient that
distinguishes it from the identical loop inside a function, which runs.

The family also surfaces LOUDLY at three neighbouring reads, each on a `vl check` rc 0
program and so each a clause-2 violation of its own: `() => name.length` gives
`emitProgram: '.length' on a receiver the emitter cannot classify as a list, string, map or
set`; `for p in [{n:1}] { () => p.n }` gives `emitProgram: field access receiver is not a
struct`; and a `(string | null)[]` element read with `??` gives ``emitProgram: '??' over this
nullable value is not supported yet — narrow it first``. Same three ingredients, three
messages — which is why the message must not be what groups this.

#### Ablation

| ingredient removed | outcome | needed? |
| --- | --- | --- |
| the closure (`for name in ["red"] { print(name) }`) | runs | **yes** |
| the capture of the loop variable (capture an OUTER binding) | runs | **yes** |
| the ref element (`for n in [1] { () => n }`) | runs | **yes** |
| the top level (the same loop inside `function go()`) | runs | **yes** — the rescue |
| the `f()` CALL (closure created, never invoked) | invalid wasm | no |
| copying first (`const g = name` then `() => g`) | invalid wasm | no — copying is not a rescue |
| the annotation (`const f: () => string = () => name`) | invalid wasm | no — annotating is not a rescue |
| the literal receiver (iterate a `string[]` variable) | invalid wasm | no |
| the array (`for k in m.keys()` over a map) | invalid wasm | no — map-key iteration too |
| a body-local NOT derived from the loop var (`const g = "blue"`) | runs | the derivation is the ingredient, not the locality |
