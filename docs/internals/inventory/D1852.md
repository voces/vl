### D1852 — an inferred list literal is never `u8[]`, so a spread mixed with a plain element has no element type; the annotation is the rule, not a workaround

**loud emit reject · filed 2026-09-07 against master `5ab3bb8d8`, ruled DESIGN against `8f6ee1aee`**

Repro:

    const bs: u8[] = [1, 2, 3]
    const c = [...bs, 9]
    print(c.length)
    // vl check: rc 0.  vl build: emitProgram: '.length' on a receiver the emitter cannot classify as a list, string, map or set

#### Mechanism

`u8` is only ever an ELEMENT type, never a value type: `arrElemValueTy` maps it to `i32`, so
every element read widens, and a `u8` reaching a join describes no value. Measured on
`8f6ee1aee`, one spelling per row:

| program | infers |
| --- | --- |
| `bs[0]` | `i32` |
| `[bs[0]]` | `i32[]` |
| `[bs[0], 9]` | `i32[]` |
| `[...bs]` | `u8[]` |
| `[...bs, 9]` | `(u8 \| i32)[]` — no backing |
| `const c: u8[] = [...bs, 9]` | runs, `4` / `9` |
| `const c: u8[] = [...bs, x]`, `x` an i32 binding | runs, `9` |
| `const c: u8[] = [...bs, 300]` | `the literal 300 does not fit a `u8` element (0..255)` |

So a list literal infers `i32[]` for small integers and a `u8[]` comes from an annotation or
from COPYING one — `[...bs]` is the single inferred exception, because it is a copy and carries
the source's own type. The mix is neither: it has a packed list in it and a plain element that
inference types `i32`, and nothing joins those.

**The obvious control does not test this.** `[bs[0], 9]` is `i32[]` and contains no `u8` at
all, since the READ already widened — it shows the read widens, not that a literal holding a
packed list does. The closer control is the annotated spread literal, and it adopts.

#### Ablation

| ingredient removed | outcome | needed? |
| --- | --- | --- |
| the plain element (`[...bs]`) | runs | **yes** |
| the spread (`[bs[0], 9]`) | runs — the read widened | **yes** |
| the missing annotation (`const c: u8[] = …`) | runs | **yes** |
| the `u8` element (an `i32[]` source) | runs | **yes** |

#### Grading list

Ruled DESIGN rather than fixed. Two alternatives were built or priced and both are worse:
widening the spread to `i32[]` also widens the pure copy `[...bs]`, silently quadrupling a
byte list and opening a window where `spreadDestKind` and the checker disagree; refusing the
mix at the literal was implemented and turned all four ANNOTATED spellings from running into
check rejects, because the literal is `(u8 | i32)[]` in both faces and only the annotated one
has a destination to adopt into. `tests/cases/lists/u8-spread-annotated-mix.vl` pins the four
that run and `error-u8-spread-inferred-mix.vl` pins the loud refusal; a future close must keep
all five.
