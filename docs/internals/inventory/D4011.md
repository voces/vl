### D4011 — a block `let` that shadows a parameter of the same name is looked up as the parameter, so a generic written into it reuses another instance

**check-clean silently wrong · clause 1 · found in review of #3517 (`rv3517/p01_param_shadow_by_let`, `p01g`, `p03`) · filed 2026-10-11 against master `20fa382fe` with #3517 applied**

Repro:

    function inner<U>(u: U) { print("I"); print(u) }
    function other<V>(v: V) { print("O"); print(v) }
    function h(f: i32) {
      inner(3)
      if true {
        let f = other
        f = inner
        f(true)
      }
      print(f)
    }
    h(9)
    // vl check: rc 0.  vl run: prints I 3 I 1 9

Want:

    I
    3
    I
    true
    9

#### Mechanism

`monoLetFrameOf` walks the enclosing functions outward and returns "none" as soon as
`monoFnBindsParam(fx, name)` matches, before it asks `identLetOfAt` for a block `let` of that name
in the same function. The block's `let f` is therefore never resolved as a binding, so D3979's
written-`let` instancing does not see it and `f(true)` reuses the `i32` instance `inner(3)` made.
The parameter test has to come after the block-`let` lookup at the read's position.
