### D16449 — a spread of a fresh list `const` of nullable records beside a wider record part builds an invalid module

**closed 2026-11-15 — the witness runs and prints `1.25` · was: check-clean invalid wasm, clause 1, every cell of `spread-nullable-record-list-wider.matrix.vl` (46 of 46 SILENT), then a loud check reject · found by lane J's discovery grids · filed 2026-11-15 against master `59155c7df` · closed in the list stamp: the spread `const` adopts the nullable element whole (`recAdPushListDecl`, check_rec_rows.vl), so its own reads are built there too · the call's face is D16613 · fixture `tests/cases/soundness/record-list-nullable-const-spread-beside-wider-part-runs.vl`**

Repro:

    const s = [{ x: 1 }, null]
    const v = [...s, { x: 2.5 }]
    print((v[0] ?? { x: 0.0 }).x + 0.25)
    // (was: vl check rc 0, vl run: invalid module)

Want:

    1.25

#### Mechanism

D16440's no-build arm (`recListSpreadsApartRefuse`, check_bind_adopt.vl) answered only for a bare
record element (`tyAt(le) is TyObj`); with `{x: f64} | null` it neither built the `const` there
nor refused, so the list was stamped nowhere: an invalid module in every position.

The close builds the `const` there as D16440 does, and adopts the binding at the element's list
type whole, `({x: f64} | null)[]`, through the adoption pass (`recAdPushListDecl`), so `s`'s own
reads (`s[0]`, `s[0] ?? d`, a binding of `s[0]`) are typed at the built record. The bare-record
spelling took the same adoption and with it `s.pop() ?? { x: 0.0 }`, which was a `cast failure`
trap on master, now runs.
