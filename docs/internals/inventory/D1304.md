### D1304 — a block-local that is NOT LIVE at the reference still shadows the module global: `localIndexOf`'s flat fallback cannot tell a dead binding from a live one

**check-clean silently wrong · `vl check` rc 0, prints `0` where the module global says `3` · PRE-EXISTS D705's fix at the SAME rep on both sides (measured on master `e6823dc8`), which is why it is a separate row: D705 was the classifier reading the module table, this is the RESOLVER reading a binding that is out of scope · found 2026-09-03 while grading D705's sibling matrix**

Repro:

    const sh: i32 = 3
    function leg() {
      print(sh)
      if 1 > 0 {
        const sh = 7
      }
    }
    leg()
    // PRINTS 0
    // vl check rc 0 (one unused-variable warning). The print should read the
    // GLOBAL (3) — the inner `const sh` is not in scope there. It reads the
    // inner slot instead, still zero.

#### Mechanism

`localIndexOf` (emit_classify) resolves scope-stack → param → `declaredIndexOf`, and that
last rung is `declaredSlotLive`'s FLAT scan of `localNames`. `localNames` holds every
declared local of the function regardless of block, so a name declared in a block that has
not been entered (or has already closed) still matches. Its own header says the flat scan
"cannot tell a dead binding from a live one … it serves the scope-less detection passes".
At EMIT time the scope stack IS maintained, so the flat rung should not be consulted there
at all; at CLASSIFY time there is no scope stack and the flat rung is the only signal.
The fix is a scope-liveness signal both passes can read, not a change to either rung alone.
