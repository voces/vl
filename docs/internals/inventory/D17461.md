### D17461 — `vl check` traps joining a function's returns when one wraps a narrowed map read and the result is bound

**closed 2026-11-24 by S2 · runs, prints `7` · was a compiler trap in `vl check`, clause 1 · a null hole's inner (`mkNullableTy(-1)`, the never-filled `null` field of `mk2()`'s literal) reached `tyParamBesideConcrete` as its parameter side, and `tyAt(-1)` trapped; the reader now answers `false` for an index outside the arena, as its sibling `holeParamBesideConcrete` does · owner S2 · filed 2026-11-24 against master `ec08ae2c3` by lane IR-P1 (found writing a position template for D17168's shape)**

Repro:

    function mk2() { return { f: null, g: 7 } }
    const __m = Map()
    __m["k"] = mk2()
    function pick() {
      const mv = __m["k"]
      if mv != null { return { a: mv } }
      return { a: mk2() }
    }
    const rr = pick()
    print(rr.a.g)
    // vl check: the compiler itself trapped, "an index outside the bounds of an array". vl run: the same.

Want:

    7

#### Mechanism

The trap is in `pick`'s inferred-return join. A named seed of master puts it at `tyAt`
(check_types.vl:194), reached from `tyParamBesideConcrete` (tyquery.vl:1991) →
`nullParamBesideConcrete` (check_type_shape.vl:386) → `tyParamsPart` (check_type_shape.vl:397) →
`joinTysAcc` (check_relate_core.vl:1998) → `joinRetTys` (check_relate_core.vl:2641) → `inferRetJoin`
(check_fit_rules.vl:8989) → `noteInferredRet` → `checkRetStmtNode`. One return wraps a map read
narrowed past `null`; the other wraps `mk2()`'s literal record. `J` is not needed (see the ablation).
Which index `tyAt` is handed past the arena is the fix's to establish.

#### Close

The stale index is `-1`, the inner of a null hole: an L1 build whose `nullParamBesideConcrete`
returned early on `tp.nInner < 0` printed `7`. That hole is a legal state (D1576), so the defect is
the reader's contract, not the caller's argument; `tyParamBesideConcrete` (tyquery.vl) now bounds
its parameter index, beside the same guard in `holeParamBesideConcrete`. Its other two callers
(check_type_shape.vl, check_tp_join.vl) pass a type index that can be the same hole.

The join's type is the one the arms give, not a hole: on head `rr.a.g` checks as `i32`, `rr.a.f`
as `null` and `rr` as `{a: {f: null, g: i32}}`, as `pick().a` and `mk2()` check on base (both arms
hold `mk2()`'s record). With a filled arm (`return { a: { f: 3, g: 8 } }` beside `{ a: mv }`),
`rr.a.f` checks as `i32 | null`; base traps on it, and head builds the invalid module of
[D17463](D17463.md), whose join that is.
