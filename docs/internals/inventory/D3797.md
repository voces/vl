### D3797 — `a[1] ?? 0` over an `f32` element in an un-annotated function pins its result to `f32 | i32`, and refuses

**closed · runs, prints `1.5` · was loud emit reject, clause 2 · found grading D3744 (lane S5) · filed 2026-10-07 against master `a37097b64` · closed by lowering a dead `??` whose pin differs from the operand's type as an `if` recorded at the pin (`coalRetypedDeadJoinIf`, wasmEmit.vl), which boxes the `f32` into the `f32 | i32` pin · fixture `generics/coalesce-dead-default-retyped-pin.vl` · closed with [D9561](D9561.md); the nullable-element face is [D9701](D9701.md)**

Repro:

    function take(a) {
      print(a[1] ?? 0)
    }
    const x: f32 = 1.5
    const k: f32[] = [x, x]
    take(k)
    // vl check: rc 0.  vl run: emitProgram: `??` over this nullable value is not supported yet

Want:

    1.5

#### Mechanism

The `??` node's pin is `f32 | i32`. The `0` default kept `i32` instead of adapting to the `f32`
operand, so the result is a two-member numeric union. The dead-default fold needs the pin to equal
the operand's type, so it declines, and no arm builds a box result from an unboxed `f32`. Outside
a generic body the same spelling prints `1.5`, so only the hole body's join keeps the literal at
`i32`. The `i32[]`, `i64[]` and `f64[]` faces fold and run.

#### Grading list

#### Close

The dead-default fold declined because the `f32` operand is not the `f32 | i32` pin.
`coalRetypedDeadJoinIf` lowers the dead `??` as an `if` recorded at the pin, whose join boxes
the `f32`. The bound spelling over `f32[]` runs too; over `(f32 | null)[]` the `??` is live and
still refuses, filed as [D9701](D9701.md).
