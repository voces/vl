### D6112 — a `const` hole lambda passed by name to a hole parameter the callee never reads has no monomorphization pin

**closed 2026-10-17 by lane L3 · runs, prints `4` · was a loud emit reject · clause 2 · a hole lambda handed BY NAME to a hole parameter the callee never reads takes D5934's unobservable `i32` default at that call (`noteHoleArgNamed`, `pinHoleLambdaVals`, `check_calls.vl`), and the mono pin reads the binding (`monoOpenFnFlowPin`) · pin: `tests/cases/functions/hole-lambda-const-by-name-to-unread-hole-param.vl` · split from [D6110](D6110.md) · filed 2026-10-17 against master `1cadabfaa`**

Repro:

    function apply(h, x: i32, g) { return h(x) }
    function inc(n: i32): i32 { return n + 1 }
    const f = (n) => 0 - n
    print(apply(inc, 3, f))
    // vl check: rc 0.  vl run: emitProgram: monomorphize: unsupported argument type for `g` in a call to `apply`

Want:

    4

#### Mechanism

From the ablation only. [D6110](D6110.md)'s spelling, where the callee calls `g`, takes the
open-function pin of [D6001](D6001.md). A parameter nothing in the body reads gives that pin no
call, so the `const` lambda reaches the call with an open type and no instance.
