### D4931 — a generic forwarding its `V[] | i32[]` parameter to another generic's `W[] | i32[]` binds no `W`

**closed · was a loud emit reject (`emitProgram: monomorphize: unsupported argument type for `a` in a call to `len``), the same on master `bb21e081b` · fixture `tests/cases/generics/typaram-list-union-param-forwards-to-generic.vl` · filed 2026-10-15**

Repro:

    function len<W>(a: W[] | i32[]) { a.length }
    function fwd2<V>(a: V[] | i32[]) { print(len(a)) }
    fwd2(["z"])
    // vl check: rc 0.  vl run: emitProgram: monomorphize: unsupported argument type for `a` in a call to `len`

Want:

    1

#### Mechanism

Inside `fwd2`'s instance the parameter's pinned annotation is `string[] | i32[]`, a union no
row held: the pin substitutes `V` after `collectU` registered the program's unions, and
`monoAnnPinName` answers only a spelling some row already claims, so `monoArgTyName` had no
name to bind `W` from. Closed in `emit_mono.vl`'s `monoInstUnionAnnPin`, which registers a
pinned union annotation the way a pinned return is registered (`monoRegisterPinUnion`), on
both the parameter and the annotated-local arms of `monoArgTyName`.
