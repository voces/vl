### D15140 — a bundle parameter handed whole to a callee that reads its parameter other than by calling it has no record to take

**now a loud emit reject · 2 hand-written witnesses · filed 2026-11-03 against master `dc1bb1f1` (check-clean invalid wasm there)**

Repro:

    function keep(g) { const q = g; print(q(7)) }
    function lap(f) {
      print(f(2.5))
      print(f(3))
      keep(f)
    }
    function go(k: i32) { lap((a) => a + k) }
    go(1)
    // vl check: rc 0.  vl run: emitProgram: a bundle of closures is handed to a parameter that takes one closure

#### Mechanism

`lap`'s parameter is called at two signatures, so it holds a record of one closure per
signature. `keep` copies its parameter into a binding, so `monoBundlePin` declines to pin it at
the record and builds it to take one closure, while the call site still hands the record. Before
the emit-side refusal in `emitDirectCallArgsUnder` this was check-clean invalid wasm. To make it
run, `keep` has to take the record and choose the member its own calls need.

#### Ablation

| ingredient removed | outcome | needed? |
| --- | --- | --- |
| `keep` copies `g` (it calls `g` directly) | runs | **yes** |
| `lap`'s second signature | runs | **yes** |
| the capture of `k` (a top-level `lap((a) => a + 1)`) | check reject, `a` not inferred | **yes** |
| the hand to `keep` (`lap` copies `f` itself) | runs | **yes** |

#### Grading list

`keep(g) { const xs = [g]; print(xs[0](1.5)) }` handed from a function that also calls its
parameter from a capturing closure: the same refusal at the hand.
