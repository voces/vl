### D12820 — a `.map` over a nullable union-arm record has no element row for its result

**closed 2026-10-25 — the witness prints `null` · was a loud emit reject, clause 2: `mfResultKindOf` and `mfResultSlotOf` now ask the call's type for a nullable-record result, a union arm included, and `collectMapFilterUse` interns that row whatever the callback classifies as; `?.` on a lone union arm takes D5300's desugar, and an inferred return names the `| null` row · fixture `tests/cases/lists/map-nullable-union-arm-result.vl`, matrix `map-nullable-union-arm-result` 47 of 48 runs (the red cell is [D3215](D3215.md)) · found closing [D10890](D10890.md) · filed 2026-10-25 against master `a0d8dfeb8`**

Repro:

    type C = { r: i32 }
    type S = { s: i32 }
    type U = C | S
    const c: C | null = null
    const m: (C | null)[] = [c].map((e) => e)
    for y in m { print(y?.r) }
    // vl check: rc 0.  vl run: emitProgram: unsupported .map/.filter element type

Want:

    null

#### Mechanism

The `.map` result's element is `C | null` where `C` is an arm of the declared union `U`, and
the map lowering finds no ref-list row for that element, so it refuses at the call. With `C`
an arm of no union the same program runs, through the row D10890 interns for a nullable-record
result.

#### Grading list

The un-annotated binding, and the `.filter` spelling, which refuses at the `?.` instead.
