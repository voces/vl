### D16819 — a maker returning its lambda through a local `const`, its two call bindings both called at two pins, is refused at emit

**open · loud emit reject · clause 2 (`vl check` rc 0) · the two-binding residue of [D16818](D16818.md) and [D16815](D16815.md) · cell `lambda_bound_first` of `maker-generic-at-two-results.matrix.vl` · filed 2026-11-16 against master `fae99e93f`**

Repro:

    function adder(n) {
      const f = (a) => a + n
      return f
    }
    const v = adder(2)
    print(v(3))
    const x = adder(1.5)
    print(x(2.0))
    // vl check: rc 0.  vl run: emit error, `a function-value call has no interned signature — parameter 1 of type `_` has no representation in the function-value ABI`

Want:

    5
    3.5

#### Mechanism

Not traced past this: both instances' lambdas are lifted at one signature, `(f64) => f64`, so the
`i32` call through `v` finds no closure built for it. Returned directly, each maker call's binding
holds its own instance (`eplHolderCallMember`, D16815); bound to the local `const f`, the slot of `f`
read in each maker instance finds no instance of its lambda (`eplRebuildLeaf`), and a lookup under
the instance being read turned a running neighbour invalid.

#### Ablation

| ingredient changed | outcome | needed? |
| --- | --- | --- |
| the lambda returned directly | runs, `5` `3.5` | **yes**: the local binding |
| one call (`f64` only) | runs, `3.5` | **yes**: two called pins |
| the `i32` binding made but not called | runs, `3.5` | **yes**: both called |
| generic `adder<T>(n: T)` | the same message | no |
