### D3952 — a closure calling a capture cell at `T` is refused when the string instance of the enclosing generic is compiled first

**closed 2026-10-26 · runs, prints `I` `s` `I` `1` · fixed when `monoArgTyName` began reading an argument's pin from its closed type before its binding and rep rungs; the mechanism is not traced past that · was a loud emit reject, clause 2 · found in review of #3498 · filed 2026-10-10 against master `429e7b093` · pin: `tests/cases/generics/closure-calls-capture-cell-string-instance-first.vl`**

Repro:

    function inner<U>(u: U) { print("I"); print(u) }
    function other<V>(v: V) { print("O"); print(v) }
    function run<T>(x: T) {
      let k = inner
      const rd = (t: T) => { k(t) }
      const flip = () => { k = other }
      rd(x)
    }
    run("s")
    run(1)
    // vl check: rc 0 (a warning).  vl run: emitProgram: the reassigned function binding `k` holds functions called at more than one argument type

Want:

    I
    s
    I
    1

#### Mechanism

Not located. The call `k(t)` in the lifted closure `rd` is recorded as a call signature on the
binding `k`, and the two instances of `run` record theirs on one binding rather than each on its
own, so the binding-signature check sees `string` and `i32` on one cell. Which order trips it
depends on which instance owns the shared node.
