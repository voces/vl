### D2302 — a call argument routed to the union-arm builder had its fields dropped and the arm's filled with `null`, including one that cannot hold `null`

**closed · now a loud emit reject (`object literal is missing a union-variant field`) · was check-clean invalid wasm · filed 2026-09-24 against master `c2f040366`**

Repro:

    type Cat = { c: i32 }
    type Dog = { d: i32 }
    type U = Cat | Dog
    type P = { p: i32 }
    function take(p: P): Cat { { c: p.p } }
    const x: Cat = take({ p: 9 })
    print(x.c)
    // vl check: rc 0.  vl build: emitProgram: object literal is missing a union-variant field

#### Mechanism

A binding whose type is a union arm (`Cat`, annotated or inferred) routes the first object
literal its initialiser emits to `emitVariantStruct` (`compiler/wasmEmit.vl`) — here the call
ARGUMENT `{ p: 9 }`, which is a `P`. Before #3077 (26f068db8, D2223) the builder refused it
because `c` was missing, which is the `arm-annotation-consumed-by-call-argument` probe's
clause-2 gap. #3077 let a union-arm literal omit a field and filled it with `null` without
asking whether the field admits `null`, so `{ p: 9 }` became a `Cat` whose `c: i32` held a
`ref.null`: invalid wasm. With `c: i32 | null` the fill is type-correct and the module is still
invalid, because the argument is a `Cat` where `take` wants a `P`. The builder now fills only a
field the arm's record type says admits `null` (`variantFieldMayOmit`), and refuses a literal
that writes a field the arm does not declare (`object literal writes a field its union variant
does not declare`), which the checker already forbids for any literal it routes there itself.

#### Ablation

| ingredient removed | outcome | needed? |
| --- | --- | --- |
| the `: Cat` annotation on `x` (inferred `Cat`) | still invalid wasm on master | no |
| the argument bound to `const q: P` first | runs | **yes** |
| `c: i32 \| null` in `Cat` | still invalid wasm on master; now refuses with the second literal | no |
