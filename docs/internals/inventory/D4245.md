### D4245 — a lambda with an un-annotated parameter written into a list element holding a generic runs at the default `i32`, whatever the element's calls pass

**closed 2026-10-12 by lane SC · runs · was check-clean silently wrong · clause 1 · found in review of #3578, ablating D4241; the list spelling is [D4015](D4015.md)'s `L09` (`rv3517`), which that row's close left printing `L 1` · filed 2026-10-12 against master `f6ee50929` · pins: `tests/cases/closures/list-element-written-with-lambda-called-at-boolean.vl`, `tests/cases/closures/record-field-written-with-lambda-called-at-boolean.vl`**

Repro:

    function gC<W>(w: W) { print("C"); print(w) }
    const y = [gC]
    y[0] = (w) => { print("L"); print(w) }
    y[0](true)
    // vl check: rc 0.  vl run: prints L 1

Want:

    L
    true

#### Mechanism

The list pin gives the list its element calls' function type and coerces every element write at
it, but the coercion reads a name: a lambda literal with a hole parameter was never pinned, so
its first instance took `i32` and printed `true` as `1`. The pin now instances such a literal at
the element type, as a capture cell's write does. The record field pin ([D4241](D4241.md)) had the
same write path; on master the record's field is refused (D4123) before it is reached.

#### Ablation

| spelling | outcome | needed? |
| --- | --- | --- |
| the witness | prints `L 1` | — |
| `(w: boolean) => …` | runs | **yes** (hole parameter) |
| `const lam = (w) => …` then `y[0] = lam` | runs | **yes** (a literal) |
| `y[0](2)` | runs, `L 2` | **yes** (a type other than `i32`) |
| `const y = { h: gC }`, `y.h = (w) => …` | runs (master: loud emit reject, D4123) | no |
