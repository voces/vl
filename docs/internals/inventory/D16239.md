### D16239 — a `for` over `.values()` of an un-annotated map of hole functions does not pin the functions it calls

**loud emit reject · `a function-value call has no interned signature — parameter 1 of type _ has no representation in the function-value ABI` · clause 2 · open · `vl check` rc 0 · found ablating [D16237](D16237.md) · filed 2026-11-15 against master `55151b054`**

Repro:

    function inc(n) { return n + 1 }
    const m = Map()
    m["a"] = inc
    for g in m.values() { print(g(3)) }
    // vl check: rc 0.  vl run: emit error at the call, parameter 1 of type `_`

Want:

    4

#### Mechanism

A call through a loop variable reaches the slot it reads through `cwSlotPath`, which has no step for
a `.values()` iterable. So the call pins nothing in the map's value slot, and `inc` keeps its open
parameter. A key-value walk (`for k, g in m`) reaches the slot and runs. Adding the step on the
check side pins the slot for records of functions. For bare functions it moves the refusal to
`internal: a function slot pinned at one signature has no one closed type the elaboration delivers
it at` (`monoStoredSlotFnTy`). So the elaboration's delivery side needs the same step, and both
halves belong in one change.
