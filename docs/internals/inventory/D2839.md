### D2839 — an if-expression with a string then arm and a record or scalar else arm is classified a string, so an un-annotated parameter it reaches pins `string` while the argument is the union box

**closed 2026-09-27 · was check-clean invalid wasm, clause 1, on master `7323baf55` · found by the #3219 review (`rv3219-q7`) · filed 2026-09-27 · fixture `tests/cases/unions/if-join-string-then-arm-argument.vl`, matrices `if-join-string-record-value`, `if-join-string-scalar-value`**

Repro:

    type Q = { b: string }
    function pick(): boolean { true }
    function take(x) { if x is string { print(x) } else { print(x.b) } }
    take(if pick() { "s" } else { { b: "x" } })
    // vl check: rc 0.  vl run: invalid module in the top-level code — expected (ref $type), found (ref $type)

#### Mechanism

The if-expression's join is the value union `string | {b: string}`, and it is emitted as the
union box. The parameter's pin comes from `monoArgTyName`, which asks `exprString` before its
union floor. `exprString`'s `IfStmt` arm falls back to reading the then arm when the join's type
is not a string, so it answered true for a join the checker kept as a union. The instance took
`string` as its parameter and received the box. Fixed in `exprString`: a join recorded as a
value union box is not a string, whatever its then arm is. An un-annotated binding of the same
`if` resolved through the same arm and is fixed with it.
