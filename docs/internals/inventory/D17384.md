### D17384 — a bound list of records holding a list of un-annotated functions has no struct row declared

**loud emit reject · clause 2 · `vl check` rc 0 · traced 2026-11-25 by SOUND and parked (coordinator: fix if small, else park with the trace) · found by lane IR-D1 ablating `d15293_bound_returned`'s `return coercion` · filed 2026-11-24 against master `864119c9f`, pre-existing**

Repro:

    function inc0(a) { return a + 1 }
    function mk(x: i32) {
      const rs = [{ fs: [inc0], x: x }]
      print(rs[0].x)
    }
    mk(5)
    // vl check: rc 0.  vl run: emit error: emitProgram: object literal but no struct type declared

Want:

    5

#### Mechanism

Traced 2026-11-25 by SOUND, not fixed. `emitObj` (wasmEmit.vl) refuses because `sDeclared` is false:
no struct row is declared in the module at all. So the row-collection pass never mints the
literal's record. Its type holds `fs: ((_) => _)[]`, the hole function's signature, which stays
open because nothing calls it.

The narrowing ablation below sets the scope. The row is missing only for a record literal written
inside a list literal in a function body, whose field is a list of never-called hole functions.
Each of these mints it:
- the same at module scope
- the record bound first (`const r = {…}; [r]`)
- one call through the field (`rs[0].fs[0](4)`), which closes the signature
- a single function field (`{ f: inc0, x }`)

The likely seat is the list literal's element-shape minting (`collectAArrayLit` and
`arrLitShapeElemName` / `ensureRefElemTys`, emit_collect.vl), which keys the element by a type
whose function leaf is still open. The single-field spelling survives through the uncalled
value-slot path. A fix needs the element-row minting to treat an uncalled hole function in a
list field as that path does. It lives in the shared record layout plan, so it outlives I8; it is
not small.

| --- | --- |

| `print(rs.length)` only, or `fs: [inc0, inc0]` | refused |
| an earlier `inc0(1)` at module scope | refused |
| the same at module scope | runs, `5` |

Traced further 2026-11-26 by COV-START, and parked (coordinator ruling: the fix needs reach analysis,
not a proxy). `anonMintRowFor` codes `fs: [inc0]` as -1: `anonRefListElemKeyOfTy` gives no key
because the list type still holds the open signature. An annotated `inc1(a: i32)` in the same place
codes 5 with key `((i32)=>i32)`. Standalone, legacy stores `[inc0]` as a closure list at the uncalled
default `(i32) => i32` (`elabHoleFnClosed`, D9100), but that row is minted lazily at emit, after the
record's row is decided.

A fix that codes the field as that closed list, and interns its row, runs the repro and every
spelling above. Applied whenever no function set records a call, it breaks three programs whose
functions ARE reached:
- `generics/hole-fn-list-below-generic-arg-top.vl`, reached through a generic;
- `closures/error-set-in-record-handed-to-hole-param-two-orders.vl`, which owes its contract refusal;
- `closures/hole-fn-inline-and-annotated-list-one-param-reached.vl`, reached as
  `viaField({ xs: [inc0] })` through an un-annotated parameter's call.

`fnSetCalledWithAny` does not see that last call, and neither the literal's nor the list's
elaboration instance types separate it from this row. The honest fix makes the reach analysis see a
call through an un-annotated parameter, so the default applies exactly when nothing reaches the
functions. The working patch, with a call-argument scan as its guard, was not landed.
