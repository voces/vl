### D9093 — an element of a list of un-annotated functions, called inside a `.map` callback over the list, has no function to call

**closed · runs, prints `4` · was loud emit reject, `emitProgram: call to unknown function`, `vl check` rc 0 · clause 2 · found closing [D9060](D9060.md) · filed 2026-10-21 against master `361494943` · closed by giving the flow an edge from a `.map` / `.filter` lambda's first parameter to the list's element slot (`ffIsElemCallback`, fn_flow_shadow.vl), and instancing the hole callback at the pinned element type (`monoListCbLamAt`, `monoPinnedListAnnTy`, emit_mono.vl) · fixtures `closures/hole-fn-list-written-then-called.vl`, `closures/generic-fn-list-written-then-called.vl`, `closures/error-fn-list-param-write-other-result.vl`, matrix `hole-fn-list-called-in-callback` · [D9171](D9171.md), [D9172](D9172.md) and [D9173](D9173.md) filed for the callback returning the element, the disagreeing stores and the matrix residue**

Repro:

    function inc0(a) { return a + 1 }
    const xs = [inc0]
    print(xs.map((f) => f(3))[0])
    // vl check rc 0.  vl run: prints 4

#### Mechanism

The flow table had no edge from the callback's parameter `f` to the list's element slot, so
the call `f(3)` recorded no pin on the element and the list literal stayed un-instanced.
With the edge, the list is typed `((a: i32) => i32)[]`, but the hole callback kept the
instance it took against the receiver's earlier hole type, so it is now re-instanced at the
pinned element, read from the binding's annotation because the receiver's node type is
stale at that point.

#### Ablation

| ingredient removed | outcome | needed? |
| --- | --- | --- |
| the `.map` (`print(xs[0](3))`) | runs, `4` | **yes** |
| a write to the element (`xs[0] = dbl` before the call, with `dbl(a) { return a * 2 }`) | same refusal | no |

#### Grading list

`.filter((f) => f(3) > 4)` over `[inc0, dbl]` prints `1`; `xs[0] = dbl` then `.map` prints
`6`; a capture inside the callback, `f(k) + f(1)`, prints `13`. With `xs[0] = half` written
first the program must not run: a store the element's type cannot hold makes the pin decline
or is refused at the write, rather than trapping. The checker-owned refusal for it is D9172.
