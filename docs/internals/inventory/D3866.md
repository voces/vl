### D3866 — the value of a function-scope assignment `d = both`, where `both` takes a WIDER parameter than `d`'s function type, keeps `both`'s own signature, and calling it traps

**loads then traps · check-clean, `indirect call type mismatch` at the call · found by the rv3458 review of #3457/#3458 (pa/c5.vl) · filed 2026-10-08 against master `fd225840b`**

Repro:

    type A = { k: "a", v: i32 }
    type B = { k: "b", w: string }
    const both = (p: A | B): i32 => { if p.k == "a" { p.v } else { 7 } }
    let d: (p: A) => i32 = (p: A): i32 => 0
    const g = () => { d = both }
    const r = g()
    print(r({ k: "b", w: "z" }))
    // vl check: rc 0 (one unused-parameter warning).  vl run: rc 1, `wasm trap: indirect call type mismatch`

Want:

    7

#### Mechanism

The checker accepts `d = both` when `both` is a named `const` whose parameter is wider than
`d`'s (`A | B` against `A`), and refuses the same assignment when the right-hand side is a
lambda literal (`a function of type (A | B) => i32 cannot be used as (A) => i32 here`). Calling
through `d` afterwards works: `d({ k: "a", v: 3 })` prints `3`. What traps is the VALUE of the
assignment expression itself, delivered out of `g` and called as `r(...)`: with an `A` argument
as well as a `B` one. Returning `d` from the same body (`{ d = both; d }`) runs, and so does
`const r = d` after a module-scope `d = both`. So the assignment expression's value is
read at a different closure signature than the one the call through `r` is emitted at; which
side holds which signature was not printed, only that the two disagree.

#### Grading list

The `i32 | string` spelling is refused at the checker while the record-union one is accepted:
the two disagree about whether a wider parameter may be assigned into a narrower function
type, which is a design question the close has to settle before it picks a side (accept and
convert at the assignment's value, or refuse as the literal and the typed `r` already do).
The reviewer also reported a trap with a plain module-level `let` and no capture cell; that
did not reproduce on `fd225840b` in the shape `d = both; print(d(...))` (runs, `3`), so it is
not claimed here. Programs that run today and must keep running: `{ d = both; d }`,
`g()` as a statement then `d(...)`, `const r = d`, and passing `both` as an argument to a
function whose parameter is `(p: A) => i32`.
