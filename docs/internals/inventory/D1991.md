### D1991 — `match` re-evaluates a non-variable scrutinee once per tested arm

**check-clean silently wrong · clause 1, wrong value · pre-existing on master · filed 2026-09-22 against master `4d64edc` (#3017 review)**

Repro:

    let n = 5
    function next() {
      n = n + 1
      n
    }
    const r = match next() { 5 => "five", 6 => "six", 7 => "seven", _ => "other" }
    print("\{r} \{n}")
    // expected `six 6`
    // PRINTS other 8

#### Mechanism

`desugarMatchAt` builds each arm's test as `scrut == pat` over the SAME scrutinee node, so the
chain it produces emits the scrutinee expression again at every tested arm (n−1 times for n arms).
A side-effecting scrutinee then advances between tests: `next()` yields 6 at the first test, 7 at
the second and 8 at the third, so no arm matches. `match-design.md` §"Scrutinee evaluated once"
records the promise and that it was not built.

#### Ablation

| ingredient removed | outcome | needed? |
| --- | --- | --- |
| the call as scrutinee (`const k = next(); match k`) | prints `six 6` | **yes** |
| the side effect in `next` | prints the right arm | **yes** |

#### Grading list

The fix is to bind a non-`Ident` scrutinee to a synthesized temp once, ahead of the chain. That
also makes such a match eligible for the `br_table` lowering, which declines a non-`Ident`
scrutinee today only because of this row; re-grade `computed_scrutinee` in
`tests/vl_match_br_table_test.ts`, whose expected count is 0 only while this row is open. Also
re-grade a union `match` over a call, and a scrutinee that is a field read through a call.
