### D17160 — a local bound to a null module global, in a function declared before the global, is declared at i32 and written a null ref

**check-clean invalid wasm · `vl check` rc 0; `vl run` an invalid module inside the function ("type mismatch: expected i32, found nullref"), claimed and claimless alike · clause 1 · filed 2026-11-24 against master `fe728a2f7` (found by V3, a sibling of [D17125](D17125.md))**

Repro:

    function show() {
      const v = g
      print(v == null)
    }
    const g = null
    show()
    // vl check: rc 0.  vl run: invalid module inside `show`: type mismatch: expected i32, found nullref

Want:

    true

#### Mechanism

The checker types `show`'s body before it reaches `const g`, so the read of `g` keeps an open type
(D17125's root). The local `v` bound to that read takes its cell kind from the open type, the `i32`
default, while the global's value is the null ref, so `local.set` writes a null ref into an `i32`
local and the module fails validation. Read directly (`g == null`) no local is declared and it runs;
declared after `g`, the read is typed and it runs. It is not D17125's arm: that is the null test's
own arm choice on a held read; here the null test is fine and the local's cell kind is wrong.

#### Ablation

| ingredient removed | outcome | needed? |
| --- | --- | --- |
| the declaration order (`const g` before `show`) | runs, `true` | **yes** |
| the local (`if g == null { print(true) }`) | runs, `true` | **yes** |
| the literal (`const g = mk()`, `function mk() { return null }`) | still invalid | no |
| `null` for an `i32` or `string` arm, an annotated `mk(): null`, a call from an earlier initializer | still invalid (V3's sweep) | no |
