### D17160 — a local bound to a null module global, in a function declared before the global, is declared at i32 and written a null ref

**closed · a module `const` initialised to `null` binds the A-infer-null hole at the hoist (`progHoistValues`) and at the initializer pre-pass (`globalInitPrePass`), so a function body checked before the declaration reads `_ | null`, not the placeholder, and its local is a nullable ref · fixtures `tests/cases/globals/null-const-*.vl` (functions declared before and after it, a `null`-returning call annotated and not, `??` to a string and an `i32`, a record field, an earlier initializer, effects run once in order) and `error-null-const-initializer-fails-to-check.vl` · was, as shipped on `fe728a2f7`, check-clean invalid wasm in the claimed face ("type mismatch: expected i32, found nullref") while claimless legacy ran it (`true`); the filed status said both faces, which held on `506e46c2a` only · filed 2026-11-24 against master `fe728a2f7` (found by V3, a sibling of [D17125](D17125.md)), closed 2026-11-24 · [D17125](D17125.md) does not move: the same emit refusal on both seeds**

Repro:

    function show() {
      const v = g
      print(v == null)
    }
    const g = null
    show()
    // was: vl check rc 0; vl run (claimed) invalid module inside `show`: type mismatch: expected i32, found nullref

Want:

    true

#### Mechanism

The checker types `show`'s body before it reaches `const g`, so the read of `g` keeps an open type
(D17125's root). The local `v` bound to that read takes its cell kind from the open type, the `i32`
default, while the global's value is the null ref, so `local.set` writes a null ref into an `i32`
local and the module fails validation. Read directly (`g == null`) no local is declared and it runs;
declared after `g`, the read is typed and it runs. It is not D17125's arm: that is the null test's
own arm choice on a held read; here the null test is fine and the local's cell kind is wrong.
