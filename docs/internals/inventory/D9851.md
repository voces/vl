### D9851 — a written `let` holding a generic with a function parameter, called once with a lambda, compares its pin by spelling and refuses

**closed · runs, prints `3` · was loud emit reject, `vl check` rc 0, `emitProgram: the reassigned function binding `v` holds functions called at more than one argument type — …`, clause 2 · found closing [D9820](D9820.md) · filed 2026-10-22 against master `f6475d442` · closed by comparing a function-value pin (`=>k`) at the closed parameter types it was taken at, not at its spelling (`monoLetPinTake`, emit_mono.vl) · fixture `closures/fn-value-generic-nullable-fn-param.vl`**

#### Mechanism

A written `let` takes one instance. `monoLetPinTake` compares the binding's pin with the
signature of the instance its call takes. The lambda argument's pin is spelled as a
function-value signature key (`=>i>i`), while the instance spells the parameter as a function
type. The two never matched, so the comparison returned REFUSE for a binding called at only one
argument type. The close spells the pin through the binding's own parameter types
(`monoSlotPinAnn`) and compares that spelling.
