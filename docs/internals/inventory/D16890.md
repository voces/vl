### D16890 — a lambda whose result is an anonymous record, handed to a generic's bare type parameter, is refused at monomorphization

**closed 2026-11-17 — the witness runs and prints `5` · was: loud emit reject · `emitProgram: monomorphize: unsupported argument type for `x` in a call to `id`` · clause 2 · `vl check` rc 0 · found probing producers of a closure with a union result · probe `scripts/capability-probes/generic-identity-of-record-result-lambda.vl` · filed 2026-11-16 against master `c4052ed4e`**

Repro:

    function id<T>(x: T): T { return x }
    const f = id(() => ({ a: 5 }))
    print(f().a)

Want:

    5

#### Mechanism

`monoElabPin` (`compiler/emit_mono.vl`) names the pin of an argument the elaboration closes `T`
at. For an argument whose own type is already closed it asked only `monoClosedTyName`, which spells
no function type whose result is an anonymous record, and gave up on any type that may hold a
function. A named function or a declared record result has a spelling, so it ran.

#### Fix

A closed function type with no spelled name is pinned by its signature key (`=>` + `sigKeyOfTy`),
the pin an open lambda delivered at the same type already takes.

#### Ablation

| spelling | outcome | needed? |
| --- | --- | --- |
| the witness | emit reject | — |
| `(x: i32) => ({ a: x + 5 })`, a parameter added | the same emit reject | no |
| the lambda bound first, `id(k)` | the same emit reject | no (a lambda, not a literal position) |
| a named `function mk(x: i32) { return { a: x } }` handed instead | runs | **yes** (a lambda) |
| the lambda's result annotated `: P`, `type P = {a: i32}` | runs | **yes** (an anonymous record) |
| the result a list `[x]` or a string | runs | **yes** (a record) |
