### D14438 — a list of un-annotated functions mapped through an inline annotated callback has no interned signature

**closed 2026-10-27 by tagging the set where the read-once adapter returns it, letting `.map` call any plain function-valued callback, and trying every escaping set of declared functions · was loud emit reject, clause 2 · the const-bound spelling with a two-member list was check-clean and trapped on an indirect call · filed 2026-10-27 against master `fdd3bcb28` · pins: `tests/cases/closures/hole-fn-list-inline-annotated-callback.vl`, `tests/cases/closures/hole-fn-list-callback-positions-two-members.vl`**

Repro (runs, prints `7`):

    function inc2(a) { return a + 2 }
    const v2 = [inc2]
    print(v2.map((r: (a: i32) => i32) => r(5))[0])

#### Mechanism

A lambda passed to `.map` is not stable, so the delivery adapter reads it once:
`(($fv) => ($fp0) => $fv($fp0))(lambda)`. The inner adapter is the outer one's returned tail,
not an argument of a call, so the set scan refused it and `{inc2}` stayed untagged. Emit then
met `$fp0` at `inc2`'s hole type as a callee. With the set tagged, the `.map` lowering still
accepted only a lambda, a name or an `if` of those as its callback. The same delivery through
a `const`, a returned function or a record field, with two members, was never tried as a set:
only one-member sets were tried from their escapes, so the list was built of uninstanced
closures and the call through them trapped.
