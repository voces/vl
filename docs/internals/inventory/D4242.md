### D4242 — a record field holding a generic function, called through the field at two argument types, has no one instance to hold

**loud emit reject · `vl check` rc 0 · clause 2 · OPEN · was the D4123 refusal on master until lane SC pinned a record field at its calls ([D4241](D4241.md)); running it needs the instance record of `fn-value-flow-design.md` §(g) · found in review of #3578 · filed 2026-10-12 against master `f6ee50929` · pin: `tests/cases/closures/error-record-field-of-generic-called-at-two-types.vl`**

Repro:

    function gC<W>(w: W) { print("C"); print(w) }
    const y = { h: gC }
    y.h(2)
    y.h(true)
    // vl check: rc 0.  vl run: a record field holding a generic function is called at more than one argument type

Want:

    C
    2
    C
    true

#### Mechanism

The field holds one function value, and a call through it is a `call_ref` at the field's one
function type. [D4241](D4241.md) gives the field the type its calls take and instances the value
at it, so calls at two types want two instances in one slot. It is the record twin of a list of a
generic called through its elements at two types, and of [D4240](D4240.md)'s written `let`: the
program is type-valid, and running it needs the value to carry which generic it is, so each call
can take its own instance.
