### D4242 — a record field holding a generic function, called through the field at two argument types, has no one instance to hold

**closed 2026-10-13 by lane SC · runs · was a loud emit reject · clause 2 · each call through a field whose one unwritten source is a generic takes its own instance (`fn-value-flow-design.md` §(e), §(f) step 4) · found in review of #3578 · filed 2026-10-12 against master `f6ee50929` · pins: `tests/cases/closures/record-field-of-generic-called-at-two-types.vl`, `tests/cases/closures/container-of-generic-instanced-per-call.vl`**

Repro:

    function gC<W>(w: W) { print("C"); print(w) }
    const y = { h: gC }
    y.h(2)
    y.h(true)
    // vl check: rc 0.  vl run: prints C 2 C true

Want:

    C
    2
    C
    true

#### Mechanism

The field holds one function value, and a call through it is a `call_ref` at the field's one
function type. [D4241](D4241.md) gives the field the type its calls take and instances the value
at it, so calls at two types want two instances in one slot. It is the record twin of a list of a
generic called through its elements at two types, and of [D4240](D4240.md)'s written `let`: the
program is type-valid, and running it needs the value to carry which generic it is, so each call
can take its own instance.

#### Grading list

The `field` and `fieldw` rows of `sc_t04_fnvalue_link_chain.py` whose two calls take different
types.

#### Fix

Lane SC, `fn-value-flow-design.md` §(f) step 4 (first part). `fnFlowDeclKidSrc` reads the
field's derived slot in the flow table; when every walk of the record holds the same one
generic there and nothing writes it, `monoPinGenericRecord` points each call through the field
at its own instance as a direct call, instead of refusing the second signature. Two sources, or
a written field, keep the refusal. The list twin (`monoPinGenericList`) takes the same rule.
