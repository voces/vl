### D5290 — a demand parked on one generic's `T` is re-asked when another generic's `T` takes a pin

**closed 2026-10-17 by lane L1 · runs, prints `1 6 str` · was loud check reject · clause 2 · a parked argument demand is re-asked only by a pin of the variable its own binder owns (`argPinRecheck`), and a value carrying another generic's own signature is not parked at all (`tyIsForeignGenericSig`) · pins: `tests/cases/closures/generic-fn-value-demand-other-generic-same-tyvar-name.vl`, `scripts/capability-probes/matrix/generic-fn-value-shared-tyvar-name.matrix.vl` · found closing D5062 · filed 2026-10-17 against master `d1b078d59`**

Repro:

    function k<T>(x: T): T { return x }
    function apply(f: (x: i32) => i32) { print(f(6)) }
    function main() { const h = k; print(h(1)); apply(h); print(k("str")) }
    main()
    // vl check: argument 1: expected (i32) => i32, got (string) => string

Want:

    1
    6
    str

#### Mechanism

`apply(h)` delivers `k`'s open `(T) => T` at `(i32) => i32`, and the checker parks that demand
until `T` takes a pin (D1821). The call `k("str")` pins a fresh copy of `T` at `string`, and
`argPinRecheck` re-asked every parked demand whose type mentioned a variable NAMED `T`, so the
demand was re-asked with `T := string`. The variable a pin binds is identified by its binder
(`tyVarOwner`), and the re-ask now matches on name and owner. A value whose type is another
generic's own signature, however it reached the argument (an alias, an inferred return), is
bound by this delivery and not parked, as a direct `apply(k)` already was.

The program first filed here returns `k` bare from two un-annotated functions. It now passes the
checker and is refused at emit, by a mechanism that needs neither the second function nor
`apply`: [D5360](D5360.md).
