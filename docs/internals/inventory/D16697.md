### D16697 — a generic function name spread into a generic body's push onto a closed function element is refused at the second call

**loud check reject · `push: cannot add (string) => string to ((i32) => i32)[] (the body of `run` at the call's argument types)` · clause 2 · open · the direct push `rs.push(id)` runs, as does one instance · the spread face of [D16235](D16235.md)'s check-side mechanism · found grading [D16571](D16571.md) · filed 2026-11-16 against master `6356d3e7d`**

Repro:

    function id<T>(x: T): T { return x }
    function run<T>(_x: T) {
      const rs: ((x: i32) => i32)[] = []
      rs.push(...[id])
      return rs
    }
    print(run(3)[0](3))
    print(run("ab")[0](4))
    // vl check: push: cannot add (string) => string to ((i32) => i32)[] (the body of `run` at the call's argument types)

Want:

    3
    4

#### Mechanism

Not traced. The element is closed, so `id` is instanced at `(i32) => i32` whatever `T` is, yet the
call-site re-check of the body's push demand at `T = string` types the spread's element at the
call's `T`. D16235 stopped `fvaAdapt` rewriting the shared body during that re-check; the spread
arm's `spreadElemTy` is read there instead.
