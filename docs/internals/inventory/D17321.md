### D17321 — a binding of one type parameter seeded from a generic function of another is built as an i32 once that generic has an instance, so the module does not validate

**open · now a loud emit reject · clause 2 · `the compiler cannot yet lower this statement (narrowed read)` · an I8 holdout (`scripts/ir-i8-census/holdouts.tsv`)**

Before I8: check-clean invalid wasm · clause 1 · filed 2026-11-24 against master `13753236` by lane N10 · the D17117 shape with the seeded generic called elsewhere

Repro:

    function same<T>(k: T): T { return k }
    function twice<T>(k: T): T { return k }

      let b: F = a1
      print(a("x"))

#### Mechanism

D17117's program refuses at the value write of `twice` (`fnValueArmOf` answers `unfixed`), because
no call reaches `twice`: mono attributes `b(3)` to `F`'s function, the binding's annotation, not to
`a1`'s, the value it is seeded with. Once another call gives `twice` an instance, that refusal no
longer fires, and `mid`'s instance stores `b` as an `i32` while `a1` delivers the closure struct.

#### Attempts (COV-CALL, 2026-11-28, time-boxed)

On master `35c521c3` the reject is `narrowed read` at `b` in `print(b(3))`; the late decision
tags `{same}` (`tag G {same}`, as for the running `mid(same, same)`), and `b`'s instance type is
`F`'s, carrying `{same}`, while its initialiser delivers `twice`. The two sets share no member,
so the shared-member family (`fnTagFamilyOf`, D17739) never joins them. Two ways to make `b` hold
both were measured and dropped:

| change | outcome |
| --- | --- |
| an annotated `let` in an instance re-check whose initialiser carries another set is declared at the join (`elabFnJoinTy`) | loud check reject, T9.3: the join is not generic, `F` is |
| widening `F`'s set in place | not built: in the instance `F` is the type of the value `same`, which every read of `same` shares |

What the close needs is D17117's open question ruled: whether `F`'s pin may name one function while
a binding of `F` holds a value of another type parameter. With that ruled, `b` takes a set of
its own type (the write's), and a later write of a third parameter joins it.
