### D2031 — an instance of a generic `new` type is not branded, so it accepts a structural value and cannot carry a getter

**loud check reject · design gap found building getters v1 (#3031) · filed 2026-09-22 against master `ad8712231`**

Repro:

    type Box<T> = new { v: T, n: i32 }
    get val(self: Box<i32>): i32 { self.v + 1 }
    const a: Box<i32> = { v: 41, n: 0 }
    print(a.val)
    // vl check: the getter `val` on Box<i32> needs a nominal receiver, and an instance of a
    // generic `new` type such as `Box<i32>` is not branded yet (D2031)

#### Mechanism

`nwBrand` mints a brand row (`nwTyIxs`) for a non-generic `new` declaration only. An
application `Box<i32>` resolves through the generic-alias path (`genAppNameOfTy`) to the plain
struct shape, so `nomNameOfTy` answers "" for it. The same gap makes the instance structural at
every other position: `function f(b: Box<i32>)` accepts `{ v: 1, n: 2 }` and prints `1`. Getters
key on the brand, so they refuse the receiver loudly rather than attach to a structural shape
(property-access-design.md §C).

#### Grading list

A getter on `Box<i32>` read from `Box<i32>` and refused from `Box<string>`; the structural value
passed as `Box<i32>` (must then be refused); a non-generic brand over the same struct, unchanged.
