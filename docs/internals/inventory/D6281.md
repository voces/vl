### D6281 — generics handed to hole parameters by named arguments out of parameter order are check-clean invalid wasm

**closed 2026-10-18 · runs, prints `3` and `ab` · was check-clean invalid wasm · clause 1 · fixed on master `586fb1cf6` by a change landed after filing (#4065 or #4068), not by the split: the out-of-order named call still declines the split and the merge queue graded the witness running on the merged tree · found closing [D6260](D6260.md) · filed 2026-10-18 against master `469a21175`**

Repro:

    function add(a, b) { return a + b }
    function cat(a, b) { return a + b }
    function apply2(g, h) {
      print(g(1, 2))
      print(h("a", "b"))
    }
    apply2(h: cat, g: add)
    // vl check: rc 0.  vl run: invalid module, the emitted module failed to validate inside `apply2`: type mismatch: expected (ref $type), found i32

Want:

    3
    ab

#### Mechanism

From the ablation only. The program's own arguments are reordered into parameter order by the
emitter, but the outcome turns on generic function values reaching hole parameters out of that
order. In parameter order, or with every parameter annotated, or with plain values in place of
the generics, it runs. No split is involved: each hole is called at one type.
