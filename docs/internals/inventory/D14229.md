### D14229 — in a hole-parameter function, a `Map()` keyed by the parameter is built string-keyed, the key its base body's receivers read

**closed 2026-11-01 — the witness prints `1` · was a refutation pin, runs today and must keep running · fixture `tests/cases/maps/litunion-atom-map-key.vl` · filed 2026-10-26 against master `8d0974164`**

Repro:

    type K = "red" | "green"
    const src: K[] = ["green"]
    function setsIt(a) {
      const m = Map()
      m.set(a, 1)
      print(m["green"] ?? 0)
    }
    setsIt(src[0])
    // vl run: prints 1; the instance's map type is keyed `K`, its receivers read a string key

Want:

    1

#### Mechanism

The instance `setsIt<K>` types `m` as `{[K]: i32}`. A literal-union key is an atom, so that
type's own key kind is `i32`. The receivers (`m.set`, `m["green"]`) are emitted from the base
body, where the key is a type variable, and they read the string key kind. `mapCtorKeyKind`
(emit_shape_rows.vl) settles the disagreement by building the map with the base body's string
key whenever the base key is a type variable and the instance key is a literal union. The
intended fix is for every receiver to move to the instance type together, so that the
constructor and its receivers agree without this rule. The row closes when `mapCtorKeyKind`
loses that branch and this program still prints `1`.

Closed: an index store pins the instance's map key from the key's type in the running instance
(`elabLiveTyOf`), as `.set` does from its argument, so `m[a] = v` and `m.set(a, v)` agree on
`{[K]: …}`. `mapCtorKeyKind` lost the branch, and the index gate asks the instance's key type
beside the base body's, so the constructor and every receiver build the atom key.
