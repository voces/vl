### D4166 — an interpolated `??` over a type parameter pinned at a string-literal union prints a number

**closed 2026-11-01 · runs, prints the Want · was check-clean silently wrong · clause 1 · a `??` the pin folds to its operand keeps the interpolation-hole mark (`monoPinBinOps`) · pin: `tests/cases/generics/type-param-coalesce-folded-interpolation-hole.vl` · pre-existing, the same on master `5e770df5b` · found by the D3423 position matrix (`rv_{KN,IN}_param_*_interp_*`, 16 cells) · filed 2026-10-11 against master `5e770df5b`**

Repro:

    type K = "a" | "b"
    function g<T>(x: T) {
      print("v=\{x ?? "c"}")
    }
    const k: K = "a"
    g(k)

Want:

    v=a

#### Mechanism

At a pin that proves the operand non-null, `monoPinBin` folds `x ?? d` to `x` (D512, and D9915's
element and field read). The fold returned the operand without the interpolation-hole mark the
`??` node carried, so `tplStrHoleOf` declined the render call and the numeric `toString` rendered
the value. A literal-union pin printed its atom's i32 (`v=3`). A `string` pin, the same program
at `g("zz")`, trapped with a cast failure inside `std:fmt`. `monoPinBinOps` now keeps the mark on
whatever node the fold returns.

#### Ablation

| ingredient changed | outcome | needed? |
| --- | --- | --- |
| `const r = x ?? "c"; print("v=\{r}")` | runs | **yes** (the `??` inside the hole) |
| `print("v=" + (x ?? "c"))` | runs | **yes** (interpolation) |
| `print("v=\{x}")` (no `??`) | runs | **yes** (a `??`) |
| `function g(x: K \| null)` (no type parameter) | runs | **yes** (a type-parameter operand) |
