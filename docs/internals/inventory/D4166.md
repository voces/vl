### D4166 — an interpolated `??` over a type parameter pinned at a string-literal union prints a number

**check-clean silently wrong · pre-existing, the same on master `5e770df5b` · found by the D3423 position matrix (`rv_{KN,IN}_param_*_interp_*`, 16 cells) · filed 2026-10-11 against master `5e770df5b`**

Repro:

    type K = "a" | "b"
    function g<T>(x: T) {
      print("v=\{x ?? "c"}")
    }
    const k: K = "a"
    g(k)

Want:

    v=a

#### Mechanism

Not traced. The interpolation hole prints an integer (`v=4` here, `v=3` with default `"b"`) where
the member's text belongs, so the hole is formatted from the atom's i32 rep rather than widened to
`string`. The same `??` bound first, concatenated with `+`, or written at a direct `K | null`
parameter prints `v=a`.

#### Ablation

| --- | --- | --- |

| `print("v=" + (x ?? "c"))` | runs | **yes** (interpolation) |
| `print("v=\{x}")` (no `??`) | runs | **yes** (a `??`) |
| `function g(x: K \| null)` (no type parameter) | runs | **yes** (a type-parameter operand) |
