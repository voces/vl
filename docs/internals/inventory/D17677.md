#### Mechanism

Not the maker's result row. The plainest spelling is `const v = { r: inc0, s: dbl }; const xs = [v]`
with `s` never called: `v` holds `r` as its set's id and `s` as an open closure, while the
record-list pin (`monoHeldRecordListAt`) typed the list at the elaboration's slot fact, every field
a closure. A binding read or call element is not re-typed by that pin, so it reached the list at
another record. `xs = [v]` shares `v`'s record, so a converting copy would break aliasing; the
list takes its elements' layout instead.
