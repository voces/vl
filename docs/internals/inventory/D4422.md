### D4422 — a generic function reaching an un-annotated parameter through an alias is never instanced

**loud emit reject · clause 2 · filed 2026-10-13 against master `777a705a0`**

Repro:

    function same<T>(k: T): T { k }
    function take(a) {
      print(a("x"))
    }
    const s = same
    take(s)
    // vl check: rc 0.  vl run: emitProgram: monomorphize: unsupported argument type for `a`
    // in a call to `take`

#### Mechanism

D4420 instances the generic at the pin only when the argument names the generic's declaration
directly (`argIsOwnGenericFnValue`, `compiler/typecheck.vl`); an alias `s`, or the parameter
of another hole forwarding it (`function mid(a) { take(a) }` then `mid(same)`), keeps the open
signature, and the monomorphizer has no concrete pin for `a`. `take(same)` runs.

#### Grading list

The forwarding spelling above, and a lambda callee `const t = (a) => print(a("x"))` then
`t(same)`, which refuses with D4420's old message and is not yet ablated.
