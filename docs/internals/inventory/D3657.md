### D3657 — a literal tail of a nested join whose own type is another member of the outer union keeps that type, so the inline and hoisted spellings disagree

**closed 2026-11-02 by lane column-G1 under the owner's ruling · runs, prints `true`, `3.5` · was check-clean silently wrong, clause 1 · ruling (A), 2026-11-02: a nested join means exactly what its hoisted twin means, so the inner join's type wins, and inlining or hoisting a sub-expression never changes a program's behaviour · `ifJoinAdaptsScalar` now adapts an inner join typed one wider number whatever its literal tails' own types, so a literal tail is built at that number; `retIfIsOneNumber` takes any literal tail; `emitExprAsF32` builds a float literal at single precision · `tests/cases/numerics/f32-f64-join-widens.vl`'s `outer` line moves from `0.30000000000000004` to the hoisted twin's `0.30000001192092896` · DECISIONS.md "A nested join means what its hoisted twin means" · fixture `tests/cases/numerics/nested-join-means-its-hoisted-twin.vl` (`if` and `else if`, `i64`, a return, an argument) · found by the #3379 review (`rv79`) · filed 2026-10-05**

Ruled by the owner 2026-11-02: see the status line and DECISIONS.md.

Repro:

    function run(q: i32 | null, r: f64 | null) {
      const x = if q != null { q } else { if r != null { r } else { 7 } }
      print(x is f64)
      print(x / 2)
    }
    run(null, null)
    // master printed false, 3

Want:

    true
    3.5

#### Mechanism

The inner `if` types `f64` (the `7` adapts to `r`), and the hoisted twin
`const y = if r != null { r } else { 7 }` delivers it as `f64`. Inline, the union chain boxes the
literal at its own type, `i32`, because `i32` is a member of the outer `i32 | f64`: the rule
DECISIONS.md states for a chain ("a literal inside a union chain boxes at its own type when that
type is a member"). #3379 left that rule in place for a literal whose type differs from the inner
join's (`ifJoinAdaptsScalar` declines), since `tests/cases/numerics/f32-f64-join-widens.vl` pins
it for an `f32` inner join with an `f64` literal. Which of the two is right for a NESTED join is
the question: the Want above is the hoisted twin's answer, and it contradicts that fixture's
`0.30000000000000004` line. Ruled 2026-11-02 (see the status line).
