### D14650 — two split hole parameters forwarded through a wrapper build invalid wasm

**closed · built check-clean invalid wasm (`expected i32, found (ref $type)` inside `lapBack`) until the outer call's check followed each hole parameter `fwd` hands on by name into the callee, bound at `fwd`'s binding, and asked the split plan (D6210) for both parameters when the callee calls it at two instances (`holeFwdSplitAsk`, up to four hand-offs deep) · filed 2026-10-31 against master `c8d61f5c`, closed 2026-10-31**

Repro:

    function wrap(a) { return [a] }
    function pair(a) { return [a, a] }
    function lapBack(g, h, x) {
      print(h(g(x)).length)
      print(g(h(x)).length)
      return 0
    }
    function fwd(g, h, x) { return lapBack(g, h, x) }
    fwd(wrap, pair, 4)

Want:

    2
    1

#### Mechanism

`lapBack` calls each of `g` and `h` at two tuples, so the split plan (D6210) gives each
parameter one copy per tuple. Called directly, the caller hands each copy the named function.
Through `fwd`, the copies are fed by `fwd`'s own `g` and `h` parameters, which the plan does not
split in turn, and one of the closure slots receives a value built at the other tuple.
