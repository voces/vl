### D15306 — a record literal written into a binding widened by its function fields' writes is built at its own row, so the binding's set stays a closure

**closed · runs, prints `2` then `2.5` · was a loud emit reject (`emitProgram: cannot take the generic function id1 as a value`), clause 2 · found grading D15301 · filed 2026-11-04 against master `e5a65514` · fixed by building the written literal at the binding's record: the assignment-stamp producer `recLitPlaceBuiltTy` (check_fit_rules.vl) answers a binding the field widener widened with the binding's own record (`recAsgFnWidenedTy`), and the pass end (`recLitFnFieldsAt`, check_bind_adopt.vl) stamps the literal there and re-types its function fields to the binding's, and fn-tag joins those fields into the set only for such a binding. The field and element slot is [D15307](D15307.md); a `const` record written in is [D15308](D15308.md)**

Repro:

    function id1(a) { return a }
    function id2(a) { return a }
    let r = { f: id1 }
    r = { f: id2 }
    print(r.f(2))
    print(r.f(2.5))

Want:

    2
    2.5

#### Mechanism

The elaboration widens `r`'s field to `{id1, id2}` (the field widener reads the record written
whole through `cwSlotWrittenValues`). What fails is the written literal's row: `{ f: id2 }` is built at its own
record, not at `r`'s, so `id2` is no leaf of `r`'s set and the set stays a closure.

Tried and reverted while grading D15301: a fn-tag scan rule joining a record written whole into a
holder (`ftJoinAt` over its fields) and re-typing the literal to the destination, with a rep
stamp at commit. The set was tagged and the program was **check-clean invalid wasm**: the
initialiser was built as one tag struct and the written literal as another, so fn-tag cannot
make this build decision. The record solve's assignment stamp (`recHeldAsgStamp`, #6223;
`storeAsgLitsBuild`, D15239) builds a literal at the row of a binding built wider; this row is
that stamp not covering a binding widened by function sets.

Also tried while grading D15301 and dropped: the field widener noting, beside the widened set,
each written record's function set (`cwSlotWrittenValues`). It moved D15271's refutation pin from
`runs` to an emit reject, so the slot's set must not be decided with a written record's that way.

#### Ablation

| ingredient removed | outcome | needed? |
| --- | --- | --- |
| the second call type (`r.f(2)` only) | runs | **yes** |
| `id2` (`r = { f: id1 }`) | runs | **yes** |
| a whole-record write (`r.f = id2`) | runs (D15119) | **yes** |
| `let r` reassigned → `xs.push({ f: id2 })` onto `[{ f: id1 }]` at two types | still refuses | no |

The matrix rows this row once listed (`struct_field_assign`, `array_element_assign`,
`array_push`, `map_set`, `map_value`) are a slot, not a binding, and moved to D15307. With the
join ungated, a field or element write was **check-clean invalid wasm**; gated to a widened
binding, both stay the loud refusal. Fixture:
`tests/cases/closures/record-literal-written-into-fn-widened-binding-runs.vl` (four bindings,
a nested record and a write under an `if`; each binding's literals disassemble to one
`struct.new` type).

A literal of the initialiser's own function written back (`e = { f: id2 }; e = { f: id1 }`) has
a type that spells as the binding's widened one, since a set's type spells as a closure's; the
pass end stamps every literal the place answers rather than those whose type differs, or that one
keeps a closure field and the module is invalid. Fixture:
`tests/cases/closures/record-literal-of-own-function-written-back-into-fn-widened-binding-runs.vl`.
