### D15010 — [CLOSED 2026-11-06] a list literal of a hole parameter handed on whole is one closure list, so its element called at two types has no one instance

**closed · runs, prints `1` then `5` · was loud emit reject · filed 2026-11-02 against master `e10fcca1`, after the split requests went (#5870) · closed by the `monoFlow*` chain gate (B1), which renames each call through `xs[0]` to `id`**

Repro:

    function id<T>(x: T): T { x }
    function use(ys) { print(ys.length) }
    function take(a) {
      const xs = [a]
      use(xs)
      print(xs[0]("abc").length + xs[0](2))
    }
    take(id)

Want:

    1
    5

#### Mechanism

`elabListParamSource` takes `xs` as the parameter only when every read of it is an element called
in place; `use(xs)` is not, so no per-instance set is minted for the calls through `xs[0]`, and the
list is built as closures of one signature. Before #5870 the checker asked the split plan for `a`
and mono refused with `` `a` is called at two instances of the function handed to it ``; the split
never made this program run either.
