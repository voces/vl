### D5061 — a record field holding an alias of a generic is called through the field with no signature

**closed 2026-10-16 · runs today and must keep running · was loud emit reject (`a function-value call has no interned signature`) · closed by L1 (`monoFlowLeafGen` follows a chain of un-annotated `const` aliases to the generic, and `monoRetypeFieldReads` types the field's reads at the slot's pin) · fixtures `tests/cases/closures/record-field-alias-of-generic-called-through-field.vl`, `record-field-alias-of-generic-in-generic-frame.vl` · found grading D4891's record-field position · filed 2026-10-16 against master `c604c1179`**

Repro:

    function k<T>(x: T): T { return x }
    function main() {
      const g = k
      const r = { q: g }
      print(r.q(1))
    }
    main()
    // vl check: rc 0.  vl run: emit error, a function-value call has no interned signature

Want:

    1

#### Mechanism

The flow table pins `r`'s `f.q` slot at `(i32)`, and `g` itself is instanced at `i32`. The field
read `r.q` keeps the checker's open `(T) => T`, so the call has no `$fnsig` key. With the
generic named directly (`{ q: k }`), §(f)'s slot-read rewrite turns `r.q(1)` into `k(1)`; it
takes only a slot whose sources name the generic, so an alias of it is left as an open read.
The list twin (`const fs = [g]`) runs, because the list pin pass gives the binding an
annotation; the record pass types only the field's value node.

#### Grading list

- a second read position: `const h = r.q; print(h(1))`

#### Close

§(f)'s slot-read rewrite turns `r.q(1)` into a direct call of the generic only when the slot's
source names the generic, and `monoFlowLeafGen` stopped at the alias `g`. It now follows a chain
of un-annotated `const` aliases to the generic, so `{ q: g }` and `{ q: h }` with `h = g` rewrite as
`{ q: k }` does. A written `let` is not an alias of one function, so for it the record pin pass
now also types each read `r.q` of the binding at the slot's pinned function type, where the
checker left it open. It declines in a generic function's frame, because the instances share
the read node. The positions graded, on master `502f8daa8` and after:
