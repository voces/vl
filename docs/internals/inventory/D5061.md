### D5061 — a record field holding an alias of a generic is called through the field with no signature

**loud emit reject · `vl check` rc 0 · clause 2 · found grading D4891's record-field position · filed 2026-10-16 against master `c604c1179`**

Repro:

    function k<T>(x: T): T { return x }
    function main() {
      const g = k
      const r = { q: g }
      print(r.q(1))
    }
    main()
    // vl check: rc 0.  vl run: emit error, a function-value call has no interned signature

Want:

    1

#### Mechanism

The flow table pins `r`'s `f.q` slot at `(i32)`, and `g` itself is instanced at `i32`. The field
read `r.q` keeps the checker's open `(T) => T`, so the call has no `$fnsig` key. With the
generic named directly (`{ q: k }`), §(f)'s slot-read rewrite turns `r.q(1)` into `k(1)`; it
takes only a slot whose sources name the generic, so an alias of it is left as an open read.
The list twin (`const fs = [g]`) runs, because the list pin pass gives the binding an
annotation; the record pass types only the field's value node.

#### Ablation

| ingredient changed | outcome | needed? |
| --- | --- | --- |
| the field holds `k` itself | runs, `1` | **yes** |
| `r` annotated `{ q: (x: i32) => i32 }` | runs, `1` | **yes** |
| `g` a written `let` (`let g = k; g = k`) | still refuses | no |
| `g` a `let` never written | still refuses | no |
| the same program in a list, `[g]` and `fs[0](1)` | runs, `1` | **yes** |
