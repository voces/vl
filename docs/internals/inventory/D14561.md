#### Mechanism

`vl check` over a directory runs its roots on a worker pool (`check_root_workers`,
scripts/vl-host/src/main.rs), and `check_pool_allowed` keeps the pool on under `$VL_FUEL`
on purpose, adding each retired worker's fuel to the run's total (`CHECK_POOL_FUEL`). Each
worker serves a root from the module checks it already holds (`wiStat`, compiler/driver.vl),
and which roots a worker holds depends on which ones the schedule gave it first. Three
default runs with `VL_CHECK_STATS=1` served 203, 202 and 204 roots. The second run declined
one root for `demand` and re-checked its 84 modules. The diagnostics were byte-identical
across all four runs, `VL_JOBS=1` included. So the result does not depend on the schedule.
The cost does, and the worker count is also capped by `memory_headroom()` when `$VL_JOBS`
is unset.
