### D16857 — a `?.` read of a record field on an un-annotated parameter, bound to a name, builds an invalid module

**closed 2026-11-16 — the witness runs and prints `6` · was: check-clean invalid wasm · clause 1 (check-clean, invalid wasm) · found closing [D16338](D16338.md) · filed 2026-11-16 against master `a8512d420`**

Repro:

    function rec(a) { const r = a?.p; print(r.q) }
    rec({ p: { q: 6 } })
    // vl check: rc 0.  vl run: invalid module, "expected (ref $0), found (ref null $0); $0 is `{q:i32}`"

Want:

    6

#### Mechanism

`emitOptMemberValueGo` (`compiler/wasmEmit.vl`) lowers a `?.` read of a ref leaf (a record, a list,
a map, a function value) as `if <chain is null> { ref.null } else { field }`, a `(ref null $S)`.
An instance whose hole is handed a present record types the read without `null`, and its binding's
cell is a `(ref $S)`, so the store did not validate. The four ref arms now recover the ref
(`ref.as_non_null`) wherever the read's type here excludes `null`: the receiver is present, so the
null arm is dead. Scalar and string leaves were unaffected.
