### D15011 — a list literal of a hole parameter the body writes afterwards, its element called at two types, has no interned signature

**closed · runs, prints `ab`, `7` · was loud emit reject, `a function-value call has no interned signature` · closed in check_elab_cap.vl: a written un-annotated parameter binds at its hand's set joined with every function its body writes to it (`fnTagParamWritesJoin`, read by `fnTagListJoinSet`), and the late tag decision takes the hands and the writes as that set's leaves · a written parameter called directly, and a written `let` copy of it, still refuse (see the refactor note) · fixture `closures/list-of-hole-param-written-after-listing.vl` · filed 2026-11-02 against master `e10fcca1`**

Repro:

    function id<T>(x: T): T { x }
    function dbl<T>(x: T): T { x + x }
    function take(a) {
      const xs = [a]
      a = dbl
      print(xs[0]("ab"))
      print(xs[0](7))
    }
    take(id)
    // vl check: rc 0.  vl run: ab, 7

#### Mechanism

A written parameter is not a `const` source, so `elabListParamSource` declines `xs` and the calls
through `xs[0]` mint no per-instance set; the element is held as a closure that no call at `i32`
interns. Before #5870 the checker asked the split plan for `a` and mono refused with
`` `a` is called at two instances of the function handed to it ``.
