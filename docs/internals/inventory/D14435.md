### D14435 — a bound list of un-annotated functions whose results differ is refused at check, though each call fixes its own member's tuple

**closed 2026-10-29 · runs, prints `abcabc` then `3` · was refused at check (`cannot store 'lenOf' in an element of 'fs'`) while the inline spelling `for g in [twice, lenOf]` ran ([D13783](D13783.md)) · fixed: `holeSlotJudge` (check_relate_core.vl) no longer compares the results of the un-annotated functions an element holds when the binding's initialiser is all it holds, since a call through the element fixes its own member's tuple; an annotated member is still judged against each call, and an element written after its initialiser, a list a call returns and a record field in a list are still judged ([D14645](D14645.md)) · pins: `tests/cases/closures/for-over-bound-fn-list-results-differ.vl` · filed 2026-10-27 against master `953bf0435`**

Repro:

    function twice(s) { return s + s }
    function lenOf(s) { return s.length }
    const fs = [twice, lenOf]
    for g in fs {
      print(g("abc"))
    }
    // abcabc, 3

#### Mechanism

`holeSlotJudge` judges the members a binding's elements hold against each other and refuses
when their results differ. Under D3975 (A) a call through the set fixes each member's tuple
at that call, so the members need no common result type; the inline literal, which the judge
never reaches, already runs that way.

The fix also runs three spellings D9092 and D9172 had closed as refusals; their fixtures are now
`closures/hole-fn-list-literal-looped-over.vl`, `closures/hole-fn-list-literal-results-differ.vl`
and `closures/hole-fn-list-literal-results-differ-called-in-callback.vl`.
