### D2573 — a generic returning its in-place lambda's result at `T = string | null` declares an `i32` result

**check-clean invalid wasm · clause 1 · pre-existing on master `dcc88a350` · found by #3174's review · filed 2026-09-26**

Repro:

    function k<T>(v: T) { return ((p: T) => p)(v) }
    print(k<string | null>("w") == null)
    // vl check: rc 0.  vl run: invalid module inside `k`, "type mismatch: expected i32, found
    // (ref null $type)"

#### Mechanism

Not located. The instance's inferred return is left at the `i32` default while the lambda's
clone at the pin returns the `string | null` niche. Annotating the return `: T` runs and prints
`false`. D2567's fix does not reach it: the result is a niche, not the value-union box.

#### Ablation

| ingredient removed | outcome | needed? |
| --- | --- | --- |
| the inferred return (`k<T>(v: T): T`) | runs, prints `false` | **yes** |
| the in-place call (`const f = (p: T) => p; return f(v)`) | still invalid wasm | no |
| the explicit type argument (`const s: string \| null = "w"; k(s)`) | still invalid wasm | no |

#### Grading list

* All three spellings in the ablation, and `k<i32 | null>(null)`.
