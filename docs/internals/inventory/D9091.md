### D9091 — an un-annotated function of another result written through an alias of a list of functions is called at the first function's signature

**closed 2026-10-29 · runs, prints `1.5`: the source list's set joins the function written through the alias ([D14647](D14647.md), D3975 A) · was a loud check reject from 2026-10-21, `cannot write 'half' to an element of 'xs'`, and before that loads then traps (`indirect call type mismatch`), `vl check` rc 0 · clause 1 · found closing [D9060](D9060.md) · present on master `361494943` · filed 2026-10-21 against master `361494943` · closed by `cwSlotWrittenValues` (check_write_scan.vl) starting from the binding an alias was bound to and collecting writes through every alias and parameter it was handed to · fixtures `closures/hole-fn-written-through-alias.vl`, `closures/hole-fn-written-over-slot-results-agree.vl`**

Repro:

    function inc0(a) { return a + 1 }
    function half(a) { return a / 2.0 }
    const xs = [inc0]
    const ys = xs
    ys[0] = half
    print(xs[0](3))
    // vl check rc 0.  vl run: wasm trap: indirect call type mismatch

#### Mechanism

`cwSlotWrittenValues` collects the writes whose target roots at the called list's own
binding. `ys` is another binding holding the same list, so the write through it is not
collected and the D9060 judge sees only `inc0`.

| the alias (`xs[0] = half`) | check refuses (D9060) | **yes** |
| the second result (`half` replaced by `function dbl(a) { return a * 2 }`) | runs, `6` | **yes** |
