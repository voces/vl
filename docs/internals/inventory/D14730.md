### D14730 — a call handed through a hole identity keeps its record at its own row while another call of the same function delivers it as a declared record

**closed · now runs, prints `3` · was check-clean invalid wasm, clause 1 · the hole face of [D14530](D14530.md) · filed and closed 2026-10-31 against master `8af49501`: `recReadInPlace` and `recLandingIn` (check_fit_rules.vl) follow an argument a non-generic function hands back from an un-annotated parameter (`recHoleIdentityArg`), as they follow a generic identity, and `recRebuiltLeafRow` (check_bind_adopt.vl) reads through it, so a nested `id2(id(mkcall()))` is pinned at the build · the annotated destination `const z: Circle = id(mkcall())` in the grading list is [D14736](D14736.md), invalid on master without `sink` too · fixture `generics/call-through-hole-identity-built-at-delivery.vl`**

Repro:

    type Circle = { r: i32 | null }
    function sink(_x: Circle) { }
    function id(x) { return x }
    function mkcall() { { r: null } }
    sink(mkcall())
    const y = id(mkcall())
    print(y.r ?? 3)

Want:

    3

#### Mechanism

`sink(mkcall())` asks for `mkcall`'s record at `Circle`. The record solve counts the call handed to
`id` as stored at its own row, because `recReadInPlace` follows an argument out of a call only
through a generic identity that alone pins it (`recSolePinArg`), and a hole identity names no type
parameter. The two builds disagree, so `mkcall` is built at its own row and `sink` receives it as
`Circle`. Invalid on line 5.

#### Ablation

Measured with the D14530 close, which the generic spelling in the first row needs.

| change | outcome | needed? |
| --- | --- | --- |
| `function id<T>(x: T): T { x }` | prints `3` | **yes**, the hole |
| delete `sink(mkcall())` | prints `3` | **yes**, the other delivery |
| `const y = mkcall()` | prints `3` | **yes**, the identity |

#### Grading list

`id(id(mkcall()))`, `id(mkcall()).r` read in place, and `const z: Circle = id(mkcall())`, each beside the
same `sink` call.
