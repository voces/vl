### D14730 — a tagged set handed to a hole parameter at one tuple and called directly at another builds its arms at the direct call's tuple

**loud emit reject · `emitProgram: ref valtype with no interned shape` · clause 2 · open · each call alone runs, and so does the pair at one tuple · deleted by the mint's emitter reader (D14430), which instances each call of the set at its own tuple · filed 2026-10-31 against master `ef36ed6c`**

Repro:

    function wrap(a) { return [a] }
    function wrap2(a) { return [a, a, a] }
    const c = true
    const s = if c { wrap } else { wrap2 }
    function one(g, x) { return g(x) }
    print(one(s, [1]).length)
    print(s(1).length)

Want:

    1
    1

#### Mechanism

The direct call `s(1)` and the call `g(x)` inside `one` both go through `s`'s set, so
`fnTagDecide` tags it, and each member is named at the type its leaves were typed at, `i32`.
`one`'s instance calls the set at `i32[]`: its mint fact records that tuple, but the dispatch
arms are built per call node and typed at the leaves, and the emitted `one` is its template
body, so `wrap` is called at its `i32` instance with an `i32[]`. Typing the arm callees from
the fact's own parameter types and results (measured 2026-10-31) does not change the instance
mono builds; the emitter has to read the set and the tuple from the instance's elaboration, as
"The emitter piece" in D14439 lays out (`emitTagSetAt`, `monoTagSetAt`).

The call inside `one` holds no mint fact: facts are noted only for a hole call in an argument
position, and `g(x)` is a result. Noting it in `genFnHoleCallOwn` for sets of two or more
members (measured 2026-10-31) makes the bound spelling in the grading list run, and turns
D14439's reduced `both`/`both2` spelling from runs into invalid wasm inside `both`, the
regression D14439's 2026-10-29 experiment met: `both`'s body is built for a closure while its
caller hands it the id.
