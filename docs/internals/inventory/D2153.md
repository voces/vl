### D2153 — a union minted with exactly a registered literal union's members is a second index the rep layer reads as a string

**closed 2026-09-23 — the witness prints `circle` then `eq` · was check-clean invalid wasm at the written-alias spelling, clause 1 · filed 2026-09-23 against master `b5debe165`, exposed to inline sets by D2150 · fixture `tests/cases/unions/inferred-tag-return.vl`**

Repro:

    type Z = "circle" | "rect"
    type C = { kind: "circle", r: f64 }
    type R = { kind: "rect", w: f64 }
    type S = C | R
    function describe(s: S) { return s.kind }
    print(describe({ kind: "circle", r: 1.0 }))
    if describe({ kind: "rect", w: 1.0 }) == "rect" { print("eq") }

#### Mechanism

Two readers of one return disagreed. The checker's inferred return of `describe` is the alias `Z`
(its member set), so `emitReturnValue` narrows the string field read to the atom; the signature
was set from the returned expression's rep (`criClassify`'s `exprString`), a string. The result
valtype said `(ref $string)` and the body left an `i32`. `criClassify` no longer lets the string
fact override a return the checker inferred as an atom-repped union (`fnInferredRetLitAtom`), and
`mkUnionTy` hands back the registered index when the member set is exactly an alias's, so a join or
a narrowing that lands on the set cannot mint a twin the index-keyed rep tests read as a string.
