### D17083 — a returned record literal whose sibling records hold hole functions on different heaps (a closure and a function tag) has no IR type

**runs today and must keep running · an IR coverage defect · filed 2026-11-23 against master `b03c57be9` by lane IR-N8 (probe lines from IR-D1)**

Repro:

    function inc0(a) { return a + 1 }
    function dbl(a) { return a * 2 }
    function mk() { return { r: { f: inc0 }, s: { f: dbl } } }
    print(mk().s.f(3))
    // VL_IR_SHADOW=1 vl build: `mk` is `uncovered return coercion`

Want:

    6

#### Mechanism

Legacy writes the literal straight at the result's row: `struct.new $2 (struct.new $7 (closure)) (struct.new $4 (i32.const 13))`,
where `$2 = { ref null $7, ref null $4 }`, `$7` holds the closure struct and `$4` a function tag. The
two inner `{ f: … }` records sit on different heaps under one open type, `{f: (_) => _}`. The IR's
return (`stmtNode`'s `ReturnStmt` arm in `ir_build.vl`) builds the value at
`{r: {f: (i32) => i32}, s: {f: (i32) => i32}}` and finds no retag to the result's
`{r: {f: (_) => _}, s: {f: (_) => _}}`: `cloHoleRetag` needs one noted heap for both sides (the
value's is -1), building the outer literal at the result row leaves the inner literals with no
single temp type naming both heaps (`open temp type`), and where one heap holds, the verifier's
retag rule refuses a record whose fields do not lower alike (rule 2; `hole-fn-param-into-returned-record.vl`).

#### Ablation

| --- | --- | --- |

| the literal a module global, not returned | covered and matched | **yes**, a return |
