### D4197 — an `||` chain that tests one binding twice reads the earlier test as retired by the right-hand side

**closed 2026-10-12 by lane CK · runs · was loud check reject · found building D4059 (the compiler's own `wasmEmit.vl` hit it once `==` narrowed) · filed 2026-10-12 against master `0bf4c3bb6` · pins: `tests/cases/literal-unions/or-chain-names-one-binding-twice.vl`**

Repro:

    type K = "a" | "b" | "c" | "d"
    function pick(n: i32): K | null {
      if n == 0 { return null }
      "c"
    }
    function take(k: "c" | "d"): i32 { 7 }
    function f(n: i32, ak: i32): i32 {
      const k = pick(n)
      if k is "a" { return 0 }
      if k == null || k is "b" || ak < 0 { return 1 }
      take(k)
    }
    print(f(1, 2))
    // vl run: prints 7

Want:

    7

#### Mechanism

`crNoteRhsRetired` (`compiler/typecheck.vl`) decides which facts of an `||` chain's left side
the right side may have reassigned by comparing each fact's type with what scope holds for the
name. A name tested twice carries two facts and scope holds only the last, so the earlier fact
always mismatched and was reported retired: "'k' is no longer narrowed to "c" | "d": the
operator '<' … may reassign it". A name faced twice is now judged by its last fact only.

#### Grading list

The `is` and `==` spellings both; a chain that tests the name once must still report a real
retire by a call on the right.
