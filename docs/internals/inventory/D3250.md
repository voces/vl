### D3250 — a hole receiver's record field passed to a function that writes `null` into it, then called, traps

**closed 2026-09-30 · now a loud check reject, as the direct spelling · was loads then traps, clause 1, the same on master `d48a56b17` · found by the #3289 final review (`rv3289f-32528/src/a/*_nestedPath_*`) · filed 2026-09-29 against master `d48a56b17`, closed against master `5e277ab52` · fixture `tests/cases/generics/error-hole-record-delivery-writes-widened-field.vl`**

Repro:

    type R = { v: i32, f: (() => i32) | null }
    const NF: (() => i32) | null = null
    function clr(q: R) {
      q.f = NF
    }
    function F(w) {
      clr(w.r)
      print(w.r.f())
    }
    F({ r: { v: 1, f: () => 5 } })
    // vl check: rc 0.  vl run: wasm trap, null reference

#### Mechanism

The pin types `w.r` as `{ v: i32, f: () => i32 }`, whose `f` cannot be null, and passing it to
`clr(q: R)` widens it to `R` while `clr` writes `null` into `f`. The annotated spelling refuses the
delivery by the record covariance rule; the body's delivery seam saw a hole, which shares nothing
it can name. A delivery whose source is typed at a hole or a type parameter is now recorded
against the function that owns it (`rcwPinNote`) and re-asked at each pin with the source
substituted (`validateRcwPins`): the record storage floor, then the widened-field write, both in
the direct spelling's words.
