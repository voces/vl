### D3250 — a hole receiver's record field passed to a function that writes `null` into it, then called, traps

**loads then traps · clause 1 · open · pre-existing, the same on master `d48a56b17` · found by the #3289 final review (`rv3289f-32528/src/a/*_nestedPath_*`) · filed 2026-09-29 against master `d48a56b17`**

Repro:

    type R = { v: i32, f: (() => i32) | null }
    const NF: (() => i32) | null = null
    function clr(q: R) {
      q.f = NF
    }
    function F(w) {
      clr(w.r)
      print(w.r.f())
    }
    F({ r: { v: 1, f: () => 5 } })
    // vl check: rc 0.  vl run: wasm trap, null reference

#### Mechanism

The pin types `w.r` as `{ v: i32, f: () => i32 }`, whose `f` cannot be null, and passing it to
`clr(q: R)` widens it to `R` while `clr` writes `null` into `f`. The annotated spelling
`F(w: { r: { v: i32, f: () => i32 } })` refuses the delivery by the record covariance rule (`a
{v: i32, f: () => i32} cannot be delivered as R here: the assignment on line 4 writes a
widened field`); the hole's argument check does not ask it, so the call reads a non-null field
that holds `null`.
