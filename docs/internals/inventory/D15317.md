### D15317 — a function built at a read's record by one `??` default's delivery and adopted there by another's is two decisions about one build

**open · check-clean invalid wasm · `type mismatch: expected (ref null $1), found (ref $5)`, at the top-level `??` · clause 1 · each default alone runs · found closing D15311 · filed 2026-11-04 against master `5f65fde96`**

Repro:

    type J = { f: i32 | null }
    function mk() { { f: 4 } }
    const m = Map()
    m.set("a", mk())
    const wm: {[string]: J} = Map()
    wm.set("a", mk())
    function mk2() { { f: 1 } }
    function mk4() { mk2() }
    const dA = mk2()
    const bA = m.get("a") ?? dA
    const b = m.get("z") ?? mk4()
    print(bA.f ?? 0)
    print(b.f ?? 0)

Want:

    4
    1

#### Mechanism

Not yet ablated past the grid below. `mk2` is decided twice: the held one-level default `dA` is
adopted at the read's record J with `mk2`'s build (D15240), while the inline `?? mk4()` delivers
`mk4` at J and hands its build on to `mk2` (D8143). The two decisions about one function's build do not
meet, and the join's operands arrive at two rows. The same shape as
the assignment stamp's two producers that #6255 collapsed into one (D15282): whoever picks this up
should start there, with one decision about `mk2`'s build that both defaults read.

#### Ablation

| ingredient removed | outcome | needed? |
| --- | --- | --- |

| the inline default held instead (`const d = mk4(); … ?? d`) | still invalid | no |
| `mk4` (`?? mk2()` inline) | check refuses: "this value is built as J where line 8 delivers it, and it is handed on here at its own type" | **yes** |
