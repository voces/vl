### D3495 — a return set holding a literal arm still widens its runtime numbers instead of joining them apart

**check-clean silently wrong · held back to master's widening by the numeric-join lane's gate (`njRetSetHeld`) · filed 2026-10-03 against master `a8c4dce6d` with the numeric-join lane applied**

Repro:

    function f(k: i32, a: i32, b: f64) {
      if k == 0 { return a }
      if k == 1 { return b }
      return 3
    }
    print(f(0, 7, 2.5) / 2)
    // PRINTS 3.5

Want:

    3

#### Mechanism

A literal in a return set adapts to the runtime arms beside it, and the runtime arms join apart.
At a generic pin those two rules met in `if k == 1 { b } else { 5 }` at `(i64, i64)`, which the
lane emitted as invalid wasm in 27 cells (and as an emit refusal in the tail form), and a
recursive wrapper at `(f64, f32)` trapped in `toString`. The gate holds back any function whose
returned values include a literal leaf, or a call of a held-back function, to master's widening
(`njRetSetHeld` in `compiler/typecheck.vl`; the pin's re-join reads the same predicate). A call
of such a function whose own return is a join, and a `const` bound only from that call, is held
too (`njExprHeld`): master
typed some of them with the wrong member set (`f32 | i32` for an `i64` arm), and the
ruling's operators would trap over them where master refused the operator. A value `if` in the
same body still joins apart.

#### Ablation

| --- | --- | --- |
| `return 3` removed | prints `3` | **yes** (the literal arm) |
| `return 3` in a nested value `if`, not returned | prints `3` | **yes** (the return set) |
