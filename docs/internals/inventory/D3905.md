### D3905 — an alias of a capturing nested generic first called at one type, then delivered at another, builds invalid wasm

**closed 2026-10-09 by lane SC, with D3902 · runs · was check-clean invalid wasm · found in review of #3479 (`rv3479-witnesses/e1_firstcall_other_type.vl`) · filed 2026-10-09 against master `ce183bab5` · pins: `tests/cases/generics/alias-of-capturing-nested-generic-delivered-as-value.vl`**

Repro:

    function call(f: (n: i32) => void) { f(1) }
    function outer<T>(x: T) {
      function inner<U>(u: U) { print(x); print(u) }
      const k = inner
      k("first")
      call(k)
    }
    outer(7)
    outer("s")
    // vl check: rc 0.  vl run: invalid module inside `outer$1`

Want:

    7
    first
    7
    1
    s
    first
    s
    1

#### Mechanism

The call `k("first")` renames the alias's initializer to `inner`'s instance at `string` for this
frame (D3887), so the value `call(k)` then resolved to that instance, which is no generic: it was
never coerced to `(n: i32) => void`. Closed with D3902: a value read through an alias that a call
renamed to one instance of a generic delivers the generic, instanced at the value's own type and
keyed by the frame.

#### Ablation

| ingredient removed | outcome | needed? |
| --- | --- | --- |
| `call(inner)` in place of `call(k)` | runs, since D3887 | **yes** |
