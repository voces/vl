### D1600 — a bare `return` did not settle the return type, so a valued TAIL made the function non-void and the guard `return` had nowhere to lower

**closed 2026-09-04 · was a loud emit reject at the function name (`vl check` rc 0), clause 2 · the rule is now the CHECKER's: a bare `return` anywhere in a body pins the return type to void and the tail is lowered in statement position · 84 emit rejects of a 273-cell grid go to 0, `runs` 91 → 168 · reported by the `glean` consumer as VL-046 · [D1032](D1032.md) is the same defect at the tail-`if` shape, [D1592](D1592.md) is what made a tail `.push` reach it**

Repro (prints nothing, exit 0):

    const seen = []
    const count = []
    function note(name: i32) {
      for i in 0 to seen.length - 1 {
        if seen[i] == name {
          count[i] += 1
          return
        }
      }
      seen.push(name)
      count.push(1)
    }
    note(7)

#### Mechanism

**Two consumers of one question, and only one of them was asking it.** The emitter lowers a
bare `return` to `0x0f` when `fRetVoid` says the function is void and refuses otherwise
(`compiler/wasmEmit.vl`). `fRetVoid` for an un-annotated function is `computeVoidFns`'
monotone fixpoint, whose conjunction includes `!blockTailMemberValue(fn.fnBody)` — a tail
member call the checker typed non-void keeps the function non-void, or the functype and the
caller disagree. `note`'s tail is a direct `count.push(1)`, `.push` is typed `i32`, so the
conjunction fails, `fRetVoid` stays 0 and the guard `return` four lines up is refused at the
FUNCTION NAME.

**[D1032](D1032.md)'s veto never reached this shape, and `blockHasBareReturn` had no caller
at all.** That row closed the same refusal by letting a bare `return` beat the NULLABLE
inference; the rule then generalised to `tailIfNullableIsReal`, which asks only whether a
tail `if`'s arms end in values, and `blockHasBareReturn` was left in `emit_query.vl` with
zero callers — dead code carrying the right predicate. It is only consulted through
`inferRetBearsNull`, so a tail that is a member CALL, a scalar, a name, a struct literal, a
list, a string or a value-`if` never met it: eleven of the twelve tail shapes in the grid
refused at every one of the seven `return` positions.

**The close moves the verdict to the checker and gives the emitter the same predicate.**
`blockHasBareReturn` moves to `typecheck.vl`; `checkFuncDeclNode` flips `inferring` to false
when the body holds one, which takes the `!inferring` ladder's `TY_VOID` default — the same
one-line flip the void-context lambda adoption already used, and it buys the whole rule from
machinery that exists: the function's `TyFunc` result is void so every caller is checked
against void, a valued `return` beside the bare one mismatches AT the return, and a
value-bearing tail is exempt from the trailing-expression check and discarded. `computeVoidFns`
asks the same exported predicate, so the functype and the type a caller was checked against
cannot disagree, and the answer survives monomorphization because it is derived from the
clone's own body rather than banked by node index.

Three diagnostics follow. A bare `return` under a declared non-void return names both
route-arounds (`return needs a value of type i32 — return a value, or annotate this function
`: void``), a valued `return` beside a bare one says where the void came from (`a bare
`return` in this body makes the function void; drop it, or return no value here`), and the
redundant-annotation hint no longer fires on an annotated body holding a bare `return` — the
un-annotated spelling of it is void, so the annotation is load-bearing.

Disassembly, the same tally with and without the guard `return`:

    without it   (type $4 (func (param i32) (result i32)))
                 (return (struct.get $3 1 (local.get $6)))   ;; the push's new length
                 (drop (call $0 (i32.const 7)))              ;; at the call site
    with it      (type $4 (func (param i32)))
                 (call $0 (i32.const 7))

The witness's module is byte-identical to the `: void`-annotated twin's on master, so the
un-annotated spelling now lowers exactly as the annotated one does.
