### D17061 — a generic instance's record parameter takes its rep from another heap than legacy declares, so the IR leaves the start's argument coercion unclaimed

**runs today and must keep running · 3 corpus cells left unclaimed by the IR · found by lane IR-M1 · filed 2026-11-23 against master `75db3649b`**

Repro:

    type Circle = { r: i32 | null }
    type K = { r: null }
    function sink(_x: Circle) {}
    function mkcall() { return { r: null } }
    const c = mkcall()
    sink(c)
    const k: K = { r: null }
    function ignore<T>(a: T, _b: { f: T }): T { return a }
    print(ignore(c, { f: k }).r ?? 6)

Want:

    6

#### Mechanism

The instance `ignore<T>` binds `T` from both arguments, and its parameter rep lands on the
record heap of `{ r: i32 | null }` (heap 1) while legacy emit declares the parameter
(`paramStructHeap`) at heap 0, the heap the argument `c` was built on. Legacy delivers the
argument with no conversion and the program runs; the IR builder's `directCallAt` finds the
argument rep and the parameter rep on two heaps with no retag admission that legacy agrees
with, so the start function misses with `argument coercion` (`kind=struct ph=0 hv=0 hp=1`)
and stays on legacy. The row pins the run, not the miss: a claim must keep printing `6`.
