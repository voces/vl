### D17827 — an annotated `.map` over an identity `.map` of a set's records is refused at emit

**open · loud emit reject · clause 2 · `vl check` rc 0, `emitProgram: the compiler cannot yet lower this top-level code (map plan)` · filed 2026-11-28 against master `3b5582185` (lane START-2)**

Repro:

    function id(a) { return a }
    function deliver() { return [{ f: id }] }
    const v: { f: (a: f64) => f64 }[] = deliver().map((r) => r).map((q): { f: (a: f64) => f64 } => ({ f: q.f }))
    print(v[0].f(2.5))
    // vl check: rc 0.  vl build: loud emit reject (map plan)

Want:

    2.5

#### Mechanism

The inner identity map's consumer is the outer map's receiver, which closes nothing, so D17793's
rule leaves its callback's result open; the set is held as closures at the outer lambda, untagged,
and the inner callback's open result has no instance at the element.

| this repro | loud emit reject |
| the outer map alone (`deliver().map((q): … => ({ f: q.f }))`) | runs (`2.5`) |
| the inner map alone, consumed at its own type | runs |
