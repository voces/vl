### D17827 — an annotated `.map` over an identity `.map` of a set's records is refused at emit

**closed 2026-11-28 by lane START-2 — the witness prints `2.5` · mono types an open identity `.map` at its receiver and hands the next lambda that list's records · fixture `tests/cases/functions/map-identity-consumed-by-hole-callback-param.vl` · was loud emit reject (map plan), filed against master `3b5582185`**

Repro:

    function id(a) { return a }
    function deliver() { return [{ f: id }] }
    const v: { f: (a: f64) => f64 }[] = deliver().map((r) => r).map((q): { f: (a: f64) => f64 } => ({ f: q.f }))
    print(v[0].f(2.5))
    // vl check: rc 0.  vl build: loud emit reject (map plan)

Want:

    2.5

#### Mechanism

The inner identity map's consumer is the outer map's callback parameter `q`. Annotated, it closes
the inner element, and `fvaMapRecvTyped` types the inner callback there (D17793's rule): the
identity map is the record-sharing refusal, and a map building fresh records runs, directly or
through a binding. Un-annotated, as in this repro, the identity map's result stays open in the
checker, so mono gave the outer lambda no instance and emit found no row for its receiver. Mono now
types an open identity map's result at its receiver, reads a receiver it closed that way, and hands
a lambda over an identity map (directly or through a `const`) the records of the list it maps.

#### Ablation

| spelling | outcome |
| --- | --- |
| this repro (`q` un-annotated) | runs (`2.5`) |
| `(q: { f: (a: f64) => f64 }) => ({ f: q.f })` over the identity map | loud check reject (record sharing) |
| the same over `(r) => ({ f: r.f })`, directly, through a binding, or as `.filter` | runs |
| the outer map alone | runs (`2.5`) |
