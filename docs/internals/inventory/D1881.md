#### Mechanism

**Bounded by [D1825](D1825.md)'s grid rather than instrumented on its own**, and the bound is
what makes it a separate row. That close gives a `.pop()` over a value-union ref list the box as
its cell and reaches twelve cells at both faces and both depths — every one of which reads the
receiver as a NARROWED union arm. It does not reach a plain `Json[]` binding at MODULE scope.

The tell is in the message, before and after that close:

    before   type mismatch: expected i32, found (ref null $type)
    after    type mismatch: expected i32, found (ref $type)

The `null` is gone, so `emitPopGo`'s new miss arm DID fire — the value is now the non-null box.
`expected i32` did not move, so the LET ladder's arm did not: `letPopUnionBoxElem` asks
`popRefRecvSlot`, which asks `exprRefArray` of the receiver, and that answers no here. The cell
stays the `i32` fall-through and a `(ref $uBox)` is stored into it.

**Module scope is the ingredient, not the call-returned receiver**, and the ablation is what
settles that: the identical three lines inside a `function go()` body RUN and print `1`. So the
rung to build is the start function's own receiver resolution; the rep question is settled and
the arm is already written. **Probe the decline before believing that** — this family has
refuted two filed attributions already ([D1822](D1822.md)'s and [D1823](D1823.md)'s).
