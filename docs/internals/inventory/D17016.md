#### Mechanism

The pin re-check declines `keys`/`values` over a union of maps (`lmPinRead`, `check_access.vl`),
so the pin's member floor refuses. Admitting them at the pin is not enough on its own: the
instance reads the call node (`nodeTyAt(call, fnIx)`) at the template's own list type, here
`string[]`, not the pin's union of lists. So the arm dispatcher (`emitArmSite`) has no element
union box to deliver into, and `vl check` passes while the emit refuses. `.get` avoided this
because the pin spells it as an index and records the walk's type on the minted node
(`monoPinMemberCall`). `keys`/`values` have no such spelling, and the call keeps the template's
type.

#### Grading list

- `union-of-maps-for-in-open` / `union-of-maps-for-in`: `argument` and `early_return_guard`
  un-annotated (`.values().length`).
- `union-of-maps-generic-methods`: the same two cells (`.values()`).
- `.values()` over maps whose values differ joins to one list, which no arm's list is. That half
  also needs a per-arm delivery into the joined list, or a union-of-lists result.
