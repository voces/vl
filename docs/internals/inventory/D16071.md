### D16071 — an emit sentence that names its function by `fnName` prints `__lambda_N` for a lambda, the name the emitter synthesizes

**runs today and must keep running · internal-only: no user-reachable sentence shows the name today · a pin for D16070's fix · filed 2026-11-13 against master `1323b99e`**

Repro:

    const id = (a) => a
    print(id(2))
    print(id("x"))

Want:

    2
    x

#### Mechanism

`emit_collect` renames every unnamed lambda to `__lambda_N` (`n.fnName = "__lambda_" + …`)
before monomorphizing, so emit-side code that reads `fn.fnName` never sees `""`. It sees a name
the program does not contain. emit_mono has 13 sentences that interpolate `fn.fnName`. Most are
`emitProgram: internal:` invariants. Three are user-facing refusals:

- `returns one function value and its calls deliver it at two function types`;
- `instantiates itself at a new type on every call`;
- `a generic function handed to two parameters … in a call to`.

None reaches a lambda today. The first is skipped for a lambda callee (D16070), and the other
two need a generic or self-instantiating function. The emitter already keeps the binding's name
for a lambda, as `fnDispNames`, for backtraces. A sentence should name a lambda that way, as the
checker does since D1904 (`fnWhoOf`).

#### Grading list

- D16070's fix: its refusal must name the lambda by its binding (`outer`), not `__lambda_N`.
- The three user-facing emit_mono sentences above, once any of them reaches a lambda.
