### D16840 — a maker call's value is refused where it reaches an uncalled hole parameter, a generic parameter, or a hole parameter from inside a generic function

**open · loud emit reject · clause 2 (`vl check` rc 0) · the positions of [D16816](D16816.md) that the bound spelling (`const w = adder(2)`, then `w` handed on) is refused at as well · cells `uncalled_hole_param`, `generic_param_called` and `in_generic` of `maker-call-handed-to-hole-param.matrix.vl` · filed 2026-11-16 against master `551ddc056`**

Repro:

    function adder(n) { return (a) => a + n }
    function take(a, x: i32) { print(x) }
    take(adder(2), 7)
    // vl check: rc 0.  vl run: emit error, `monomorphize: unsupported argument type for `a` in a call to `take``

Want:

    7

#### Mechanism

Not traced. The maker's call result is open where nothing calls it (its lambda's parameter has no
delivery), where a generic parameter takes it (the instance is keyed on the argument's type, not
on a hole the delivery closes), and inside a generic function's instance (`elabSlotFacts` closes
holders outside instanced functions only). Each position refuses the same way when the call is
bound to a `const` first.
