### D16725 — an empty container nested in a list literal handed to a type parameter is built at its open type, so the parameter has no pin

**closed 2026-11-16 by [D16879](D16879.md)'s close — the witness runs and prints `1` · was: loud emit reject · clause 2 · `one([Set()])`: `emitProgram: a list literal of maps whose value type is still open names no list row`; `one([[]])`: `emitProgram: nested arrays are not supported`; `take([[]]).length`: `emitProgram: '.length' on a receiver the emitter cannot classify as a list, string, map or set` · the residue of D15040 and D16207 · filed 2026-11-16 against master `2a0b71c1a` with their fix applied**

Repro:

    function one<B>(b: B) { return [b].length }

#### Mechanism

`elabHoleContainerClosed` closes the parameter's binding through the list, so the instance is
`one<Set<string>[]>`, but the inner literal `Set()` (or `[]`) is a node of its own whose recorded
type stays open: the outer list literal has no row for an open element. The bound and
top-level forms close (D15040, D16207); the inner literal is not reached.

The inner literal is a list literal holding an empty container read in place, so D16879's close
notes it on the default-only pending list and the program's end takes the read-only default for it.
