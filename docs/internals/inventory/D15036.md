### D15036 — a function list's element called at two types, beside a second list holding the same function and another, is lowered at one instance

**closed · runs, prints `4` then `2.25` · was check-clean invalid wasm · clause 1 · fixture `tests/cases/closures/function-list-element-at-two-types-beside-wider-list.vl` · found by the split-plan census of L-map · filed 2026-11-02 against master `7e3fea10`**

Repro:

    function inc0(a) { return a + 1 }
    function dbl0(a) { return a * 2 }
    function deliver0() { return [inc0] }
    function deliver1() { return [inc0, dbl0] }
    function take0(a) { print(a[0](3)) }
    take0(deliver0())
    print(deliver0()[0](1.25))
    // vl check: rc 0.  vl run: the emitted module failed to validate in the top-level code: expected i32, found f64

Want:

    4
    2.25

#### Mechanism

`{inc0}` is called at `i32` and `f64`, which one closure cannot serve, so it needs the tag. The
tag decision declined it (`ftScan`, check_fn_tag.vl): the `inc0` leaf in `deliver1`'s list is a
member leaf of another set's join, `{inc0, dbl0}`, and a join and its leaves share one rep, so
`{inc0}` was taggable only if that set already was. Nothing calls through `{inc0, dbl0}`, so it
was never tried, `{inc0}` stayed a closure, and its `f64` call was lowered through the closure's
`i32` signature with no refusal. Closed by deciding a wider join's set with `s` (`ftSubNeed`):
both are tagged or neither. The pushed spelling, whose wider plan still declines, is D15060.
