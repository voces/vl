### D15036 — a function list's element called at two types, beside a second list holding the same function and another, is lowered at one instance

**check-clean invalid wasm · clause 1 · found by the split-plan census of L-map · filed 2026-11-02 against master `7e3fea10`**

Repro:

    function inc0(a) { return a + 1 }
    function dbl0(a) { return a * 2 }
    function deliver0() { return [inc0] }
    function deliver1() { return [inc0, dbl0] }
    function take0(a) { print(a[0](3)) }
    take0(deliver0())
    print(deliver0()[0](1.25))
    // vl check: rc 0.  vl run: the emitted module failed to validate in the top-level code: expected i32, found f64

Want:

    4
    2.25

#### Mechanism

Not located. The element of `deliver0()`'s list is called at `i32` inside `take0` and at `f64`
at the top level, and the module calls `inc0`'s `i32` instance at the `f64` site. It needs
`inc0` to sit in a two-member set (`deliver1`, which nothing calls): the L-set and L-map census
traced a call reached through two sets to `elabMintFactAt` marking both sets partial for the
whole program, which leaves `inc0`'s set untagged; this row is that state without the refusal.
