### D16968 — an empty `Map()` bound to a `const` in a hole function's body is typed once, so a second instance at another value type is refused

**closed 2026-11-19 by lane F1 · runs, prints `9` · was a loud check reject, clause 2 · the `const`-bound spelling of the empty-`Map()` family: an empty `Map()` or `Set()` a hole template allocates is fresh per instance through the mechanism that makes `[]` so, the checker re-asking a later call's demands with a fresh open map (`instAllocsOf` / `instFreshTy`, `check_assignable.vl`) and the emitter building it at the instance's own reading ahead of the shared stamp (`litRepTyAt`, `emit_elab.vl`); a function value's map parameter mints its value slot before its `$fnsig` key reads it (`forceParamMapSlots`, `emit_collect.vl`) · the `Set()` spelling is [D17005](D17005.md) · fixture `tests/cases/closures/empty-map-and-set-per-instance-of-hole-template.vl` · found ablating that family · filed 2026-11-18 against master `fe903786` by lane F2**

Repro:

    function ef(a: i32, b: Map<string, f64>) { return a + b.length }
    function es(a: i32, b: Map<string, string>) { return a * 2 + b.length }
    function empty(h) {
      const m = Map()
      return h(3, m)
    }
    print(empty(ef) + empty(es))
    // vl check: argument 2: expected {[string]: string}, got {[string]: f64} (the call of `h` in `empty`, at 5:15)

Want:

    9

#### Mechanism

A hole function's body is re-checked per instance at the call's argument types, and a bare `[]`
argument's open element is a hole each instance pins afresh. The empty map here is held by a binding
whose type row the instances share, so the first instance's pin stands for the second.

#### Ablation

| change | outcome | needed? |
| --- | --- | --- |
| the repro | refused | — |
| `h(3, [])` with list parameters, no binding | prints `9` | the holder: **yes** |
| `h(3, Map())`, no binding | refused (D16602) | the binding: no |
| one call of `empty` | runs | the second instance: **yes** |
