### D16968 — an empty `Map()` bound to a `const` in a hole function's body is typed once, so a second instance at another value type is refused

**loud check reject · clause 2 · open · the `const`-bound `Map()` spelling of the empty-container family D16602 (a `Map()` argument), D16603 (a `const`-bound `[]`), D16423 (a nested `[]`) and D5472 (a record literal's `[]` field) · found ablating that family · filed 2026-11-18 against master `fe903786` by lane F2**

Repro:

    function ef(a: i32, b: Map<string, f64>) { return a + b.length }
    function es(a: i32, b: Map<string, string>) { return a * 2 + b.length }
    function empty(h) {
      const m = Map()
      return h(3, m)
    }
    print(empty(ef) + empty(es))
    // vl check: argument 2: expected {[string]: string}, got {[string]: f64} (the call of `h` in `empty`, at 5:15)

Want:

    9

#### Mechanism

A hole function's body is re-checked per instance at the call's argument types, and a bare `[]`
argument's open element is a hole each instance pins afresh. The empty map here is held by a binding
whose type row the instances share, so the first instance's pin stands for the second.

#### Ablation

| change | outcome | needed? |
| --- | --- | --- |
| the repro | refused | — |
| `h(3, [])` with list parameters, no binding | prints `9` | the holder: **yes** |
| `h(3, Map())`, no binding | refused (D16602) | the binding: no |
| one call of `empty` | runs | the second instance: **yes** |
