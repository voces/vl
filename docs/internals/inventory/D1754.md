#### Mechanism

An un-annotated parameter is a hole the call pins from the argument, and the pin reads the
argument's DECLARED type, not the type the narrowing gives it. A narrowed arm's declaration is
the union, so the clone's parameter has no struct or variant row and `a.r` inside it has no
receiver. Annotating the caller's own binding rescues it, which is the tell: the pin can carry
a concrete arm, it just does not take one from a narrowing.

D1741 gave the un-annotated BINDING the arm's cell, and this cell did not move with it: after
that close, `const q = p` gives `q` a variant cell holding the bare arm and `take(q)` still
refuses. So the pin is not reading the cell either.

Bounded from the other side: a plain struct value, a non-narrowed arm bound with an annotation,
and a program with no union in it all pass an un-annotated parameter and run, so the parameter
being a hole is not itself the ingredient.
