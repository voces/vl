Repro:

    function mk(b: boolean) {

#### Mechanism

An un-annotated parameter is a hole the call pins from the argument, and the pin becomes the
instance's parameter annotation. `monoArgPinName` already has a narrowing rung —
`monoNarrowedPinName` — whose job is exactly this. It declined, and an instrumented build says
why:

    PROBE narrowpin wide=[A|i32] n=[{r:i32}] arms=<A><i32> narrows=n annPin=[{r:i32}]

The rung asks whether the narrowed type's name is one of the union's arms. `tyToEmitName`
spells a narrowed object STRUCTURALLY (`{r:i32}`) while the union carries its arms' DECLARED
names (`A`, `i32`), so the membership test missed **on the spelling and not on the type** — and
`annPin` shows the second guard would have passed. The pin therefore named the whole union, the
instance's parameter was the box, and `a.r` inside it had no struct receiver.

The rung now asks the nominal spelling too, through `nominalStructNameOfTy` — "the equality the
emitter's variant tables are built under", which is the same footing the union's arms are
rendered on. Both guards still stand: a narrowed name that is not an arm, or one
`monoAnnPinName` does not claim, still declines and the ladder's own answer stands.

This is the nominal-versus-structural family: two readers of one type answering on different
footings, where the one that renders structurally cannot match a table keyed nominally.
