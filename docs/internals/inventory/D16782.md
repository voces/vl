### D16782 — a generic's `V[]` result over an open `[]` binding is refused at emit

**closed 2026-11-16 by lane AE — the witness prints `0` · a held call's `V[]` result is the held list's own row (`heldListRetTy`), so the two settle at one element, and a read-only binding of it is not defaulted early (`defaultReadOnlyContainer` skips a held row) · fixture `tests/cases/soundness/open-list-binding-generic-list-result.vl` · was a loud emit reject, clause 2, `emitProgram: '.length' on a receiver the emitter cannot classify as a list, string, map or set` · found grading D16759's neighbours · filed 2026-11-16 against master `e33ab71cc`**

Repro:

    function g<V>(v: V[]): V[] { return v }
    const e = []
    const h = g(e)
    print(h.length)
    // vl run: prints 0 (was an emit error at `h.length`)

Want:

    0

#### Mechanism

The call leaves `V` unbound, since its only argument is an open list, so its result type was `V[]`
with the callee's own `V`, and `h` was typed with it. The result is now the held list's row, which
`settleHeldPins` binds `V` from. A `const h` only ever read would default that row when bound
(`defaultReadOnlyContainer`), settling `e` before a later write; a held row is skipped there.
