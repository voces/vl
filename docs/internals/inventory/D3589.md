### D3589 — a named generic helper returning a join of its two type parameters is read by its caller at the numerically widened type

**closed 2026-10-04 — the witness prints `true`, `false` · was check-clean silently wrong, clause 1 · found by lane KJ's grid (its `helper` shape, 22 wrong cells) · filed 2026-10-03 against master `7073d9d03`, closed by lane HL against `c473889d1` · fixture `tests/cases/numerics/helper-join-read-by-generic-caller.vl`**

Repro:

    function G<A, B>(k: i32, a: A, b: B) { if k == 0 { a } else { b } }
    function F<A, B>(k: i32, a: A, b: B) {
      const v = G(k, a, b)
      print(v is f64)
    }
    F(0, 2.5, 3)
    F(1, 2.5, 3)
    // vl run: true, then true

Want:

    true
    false

#### Mechanism

Two losses, both at the call `G(k, a, b)` inside a generic or hole caller. `njGateScan` recorded
every name a generic or hole body mentions, so `G` was `njFnReached` and its return joined by
widening; and `checkCallOnFuncTy` collapsed the call's deferred join `A | B` (the caller's own
parameters) to one arm, noting it as an escaped join that `validateEscJoins` refused at each pin
once the join stayed apart. A generic or hole body now gates the names it mentions only when its
own function is gated (a fixpoint in `njGateScan`), and a deferred join whose members are the
caller's own parameters, from a callee whose arms joined apart or whose return is annotated, is kept
as a kept-apart union (`keptParamUnion`) that each pin of the caller re-joins without widening.

#### Ablation

| ingredient changed | outcome before | needed? |
| --- | --- | --- |
| the join written directly in `F` | right | **yes**: the helper |
| `F` concrete, `G` called with `f64`, `i32` | right | **yes**: a generic or hole caller |
| `G` annotated `: A \| B` | refused, "an inferred union return through an un-annotated parameter" | no: the same collapse |
| `G` with `return` statements | the same wrong value | no |
