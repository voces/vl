### D15883 — a maker that binds a list of records holding functions of different results and returns it in a record passes the checker, and a call read through the returned record is refused at emit

**closed 2026-11-12, now a loud check reject, `cannot store 'half' in 'xs[].f'`, the sentence the bare `return xs` gets · was a loud emit reject, `emitProgram: object literal field count does not match struct`, clause 1 · closed by `holeSlotRetJudge` (`check_relate_core.vl`) judging a returned record literal at its field's value and the rest of the path (`holeSlotRetRecField`), through the predicate that refuses `return xs` · lifting both to runs is w308's lift family (DECISIONS: a set of functions in one slot need not return one type, D15791, D15225) · found by w314 in D15922's ablation · filed 2026-11-12 against master `d303c9bc`**

Repro:

    function inc0(a) { return a + 1 }
    function half(a) { return a * 0.5 }
    function mk() {
      const xs = [{ f: inc0 }, { f: half }]
      return { a: xs }
    }
    print(mk().a[1].f(3))

#### Mechanism

Traced. A call read through the maker's result, `mk().a[1].f`, is judged by
`holeSlotCallJudgeAt` at the path `a / [] / f`. It asks `holeSlotRetJudge`, which hands each
returned value to `holeSlotArgJudge`. A returned `xs` reaches that function's binding arm and is
refused there. A returned `{ a: xs }` matched no arm, so the judge fell back to reading the
values apart, as for a returned literal (D14648), and accepted them. Emit then had no row for the
record. `holeSlotRetJudge` now hands `holeSlotArgJudge` a returned record literal's field value
at the rest of the path (`holeSlotRetRecField`), so `xs` reaches the same binding arm. Only
returns take it: an argument record is read at each call's own instance. An inline list in the record still reads apart and
runs.

Per the orchestrator's ruling this is containment: the record path agrees with the direct one.
Running both is w308's lift.
