### D15883 — a maker that binds a list of records holding functions of different results and returns it in a record passes the checker, and a call read through the returned record is refused at emit

**loud emit reject · clause 1 · `emitProgram: object literal field count does not match struct` · open · found by w314 in D15922's ablation · filed 2026-11-12 against master `d303c9bc`**

Repro:

    function inc0(a) { return a + 1 }
    function half(a) { return a * 0.5 }
    function mk() {
      const xs = [{ f: inc0 }, { f: half }]
      return { a: xs }
    }
    print(mk().a[1].f(3))

#### Mechanism

Not traced. When `mk` returns `xs` itself, the checker refuses the list: `cannot store 'half' in
'xs[].f': called at (i32) it returns f64, where 'inc0', also stored in it, returns i32`. Through
the returned record, the call is not attributed to `xs[].f`, so the checker accepts it, and emit
finds no struct row for the record `{ a: xs }`. The right answer waits on a ruling: refuse it, as
the bare return is refused, or run it. With the list written inline in the record, the
program runs and prints `1.5`.

#### Ablation

| spelling | outcome |
| --- | --- |
| the witness | loud emit reject |
| `return xs`, called as `mk()[1].f(3)` | type error, the sentence above |
| the list inline, `return { a: [{ f: inc0 }, { f: half }] }` | runs, `1.5` |
| `{ f: half }` pushed rather than in the literal | loud emit reject, the same message |
| the record bound, `const m = mk(); m.a[1].f(3)` | loud emit reject, `ref valtype with no interned shape` |
| no call through `f`, `print(mk().a.length)` | runs, `2` |
| `inc0(a: i32): i32` and `half(a: i32): f64` annotated | type error, `called value is not a function` |
