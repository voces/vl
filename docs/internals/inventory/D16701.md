### D16701 — a list `is` test over a `V[]` operand, every call handing an annotated empty list, still answers by emptiness

**check-clean silently wrong · prints `1` · clause 1 under owner ruling (a) · open · `vl check` rc 0 · the operand face [D16342](D16342.md)'s close left: a test over the type parameter itself (`v: V`) answers by the annotation · found closing D16342 · filed 2026-11-16 against master `c65ab77eb`**

Repro:

    function listParam<V>(v: V[]) {
      if v is f64[] { return 1 }
      return 0
    }
    const e: i32[] = []
    print(listParam(e))
    // vl check: rc 0.  vl run: prints 1

Want:

    0

#### Mechanism

D16342's pin record (`noteIsCstr` into `BND_IS`, settled by `settleListIsPins`) is made for a test
whose operand type is the hole or type parameter itself. A `V[]`, `V[][]` or record-field
(`r: { v: V[] }`) operand is not recorded, so the instance answers by emptiness (D4910). Widening the
record to every operand type that holds a type parameter moved about 20 D4910-era corpus fixtures,
one of them to an emit refusal (`generics/is-list-arm-anon-record.vl`, `ref valtype with no interned
shape`): the defaulted `[]` and the annotated list bind rows the pin cannot tell apart (D16342's
mechanism), so each fixture needs adjudicating under the ruling.
