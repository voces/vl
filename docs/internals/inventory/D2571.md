### D2571 — a lambda whose parameter is a nullable function type has no function-value signature

**closed · runs, prints `false` · was loud emit reject, clause 2 · pre-existing on master `dcc88a350` · filed 2026-09-26 from #3171's review sibling `rv3171r2/min/p5.vl` · closed with [D9772](D9772.md) by keying a nullable function parameter with the `nulclosure` token (`cloParamTok`, emit_fn_ret_kinds.vl; `annParamKindTy`, emit_sig_tokens.vl) · fixture `closures/fn-value-nullable-fn-param.vl`, which also calls it with `null` and in place**

Repro:

    function inc(n: i32): i32 { return n + 1 }
    const f = (p: ((i32) => i32) | null) => p
    print(f(inc) == null)
    // vl check: rc 0.  vl run: emitProgram: a function value's signature is not yet
    // supported — parameter `p` of type `((i32)=>i32)|null` has no representation in the
    // function-value ABI; annotate and call it as a named function instead

#### Mechanism

The closure `$fnsig` vocabulary (`annParamKind`) has no token for a nullable closure
parameter, so the lambda, which is a function value, cannot be keyed. The named-function
spelling (`function f(p: ((i32) => i32) | null) { return p }`) runs and prints `false`, because
a direct call needs no `$fnsig`.

#### Ablation

| ingredient removed | outcome | needed? |
| --- | --- | --- |
| the function value (a named `function f`) | runs, prints `false` | **yes** |
| the `null` arm (`p: (i32) => i32`, then `f(inc)(1)`) | runs, prints `2` | **yes** |
