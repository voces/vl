### D15234 — a list literal of two maps whose function values are different sets is refused at emit

**closed · runs, prints `1.5` · was a loud emit reject (`emitProgram: ref valtype with no interned shape`), clause 2 · found closing [D15187](D15187.md) · named cell `d15187_two_sets` · fixed by deciding the two sets together: fn-tag's `ftLitJoin` takes a list of maps of set `s` holding a map of a smaller set within `s` by planning that set beside `s` (`ftSubNeed`), and `ftHoldCtxOk` takes that map as an element of a list of maps of the wider set it is decided with (`ftMapListOfWider`). The smaller set's map first in the list is [D15352](D15352.md)**

Repro:

    function inc0(a) { return a + 1 }
    function half(a) { return a / 2.0 }
    const fnMap = Map()
    fnMap.set("a", inc0)
    fnMap.set("b", half)
    const m2 = Map()
    m2.set("a", half)
    const xs = [fnMap, m2]
    const g = xs[1].get("a")
    if g != null { print(g(3)) }
    // Want: 1.5

#### Mechanism

`fnMap` holds the set `{inc0, half}` and `m2` the set `{half}`. D15187 tags a list of maps
of a set only where every map delivered into it holds exactly that set, so this list leaves
`fnMap`'s set untagged and the program keeps its loud refusal; admitting it as tagged mixes a
map of ids with a map of closures in one list, which is check-clean invalid wasm. Running it
needs the two sets decided together with one id numbering, as a list widened from a list of a
smaller set already is (`fnWidenedListSourceSets`).
