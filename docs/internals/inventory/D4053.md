### D4053 — a value delivered across a newtype brand is refused as a "lossy" conversion, though nothing is lost

**loud check reject · the refusal is correct and its reason is wrong · found writing `docs/spec/types.md` (lane SPEC) · filed 2026-10-11 against master `1df3c8f91`**

Repro:

    type Meters = new f64
    const raw = 3.0
    const m: Meters = raw
    // vl check: rc 1, "f64 doesn't fit in Meters — the conversion is lossy and must be
    // made explicit with `as` (write `x as Meters`)"

#### Mechanism

DECISIONS.md §"A nominal type is `type N = new B`, and it is ERASED" requires `as` to move
a variable into or out of a brand, because the brand is the point. The refusal is right,
but it is raised through the lossy-numeric-conversion sentence, so it tells the author
that `f64` into `Meters` loses information. The fix it names, `x as Meters`, also uses the
placeholder `x` rather than the operand's own name. The sentence should say that a value
crosses a brand only through `as`, and name the operand.

#### Ablation

| spelling | message |
| --- | --- |
| `f64` binding into `Meters` | "f64 doesn't fit in Meters — the conversion is lossy …" |
| `Meters` binding into `f64` | "Meters doesn't fit in f64 — the conversion is lossy …" |
| `const n = 5` into `type Id = new i32` | "i32 doesn't fit in Id — the conversion is lossy …" |
| `3.0` (a literal) into `Meters` | accepted: a literal is brand-polymorphic |
| `Meters + Feet` | "operator '+' mixes Meters and Feet" (correct) |

#### Grading list

All three directions in the ablation. The real lossy refusals (`i64` into `f64`, an
integer into `f32`) must keep their sentence.
