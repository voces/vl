### D14941 — a maker's results at a string-literal union and at `string` share one instance of the generic it returns, whose rep is the union's atom

**closed 2026-11-02 · runs, prints `x q` · was a check-clean wasm trap at run (`indirect call type mismatch`) · clause 1 · introduced by #5815 (the maker twin at a closed destination), correct at its parent `80aa5201` · a pin of a string-literal union keys an instance apart from its base `string` (`monoLitUnionPinDiscrim`) · pin: `tests/cases/closures/maker-results-at-literal-union-and-string.vl` · found re-ablating M-maker for the split-plan census · filed 2026-11-02 against master `a48eddb4`**

Repro:

    type K = "x" | "y"
    function same<T>(k: T): T { k }
    function d9() { return same }
    const v: (k: K) => K = d9()
    const w: (k: string) => string = d9()
    print(v("x"))
    print(w("q"))

Want:

    x
    q

#### Mechanism

Each destination gets its own twin of `d9`, and each twin builds `same` at its result. Mono keys
an instance by its pins' spellings, and a string-literal union's spelling is softened to its base,
so `same` at `T = K` and at `T = string` both keyed `0#string`. The second twin's delivery hit the
first's instance, which takes `K` as an interned `i32` atom, so `w("q")` called it with a string.
The direct deliveries (`const v: (k: K) => K = same`) escape it through the per-call split key.
