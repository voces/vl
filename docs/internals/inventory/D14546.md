### D14546 — a method call's checker and emitter resolve its callee through two different scopes

**closed 2026-10-27 · runs, prints `25` then `a!` · fixed: the binder records the decl `foo` names at the call site, and the checker and the emitter both read that one record (`memberDeclOf`, `memberMethodOf`) · pins: `tests/cases/ufcs-decl/aa-toplevel-other-type-local-lambda.vl` and its `-annotated` twin · was check-clean invalid wasm, clause 1 · filed 2026-10-27 against master `dd78224c3`**

Repro:

    type P = { x: i32 }
    function foo(self: string) { self + "!" }
    function main() {
      const foo = (self: P) => self.x + 24
      const p: P = { x: 1 }
      print(p.foo())
    }
    main()
    print("a".foo())

Want:

    25
    a!

#### Mechanism

`p.foo()` has two resolvers. The checker types the call through the lexical spelling (`lookup`
in `ufcsCalleeOf`), which finds the local lambda, but gates dispatch on `declFirstParamIsSelf`,
which reads the module function table by name and finds the top-level `foo`. The emitter's
rewrite asks the module table too (`drwSelfFnOf`), so it calls the `string` function with a
`P` receiver and the module fails to validate inside `main`. Ruling (a) on Q1: one resolver,
the declaration the binder records for the spelling at the call site.

#### Ablation

| ingredient removed | outcome | needed? |
| --- | --- | --- |
| the top-level `foo` | `no field 'foo' on P` | **yes** |
| the local `foo` | `no method 'foo' for P`, the free function takes `self: string` | **yes** |
| the top-level `foo`'s `self` renamed `q` | refused, `foo` is not a method | **yes** |
| `print("a".foo())` | still invalid wasm | no |

#### Grading list

The Q1 probe set: a local self lambda shadowing a top-level self function of the same receiver
type (`S`), an imported self function shadowed by a local (`AC`, `AD`), and a nested self
function shadowing a top-level one of another receiver type (`AF`).
