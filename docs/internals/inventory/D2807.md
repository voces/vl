### D2807 — `print` of a type parameter pinned to a nullable literal union has no member texts

**loud emit reject · clause 2 · 2 cells of D2802's grid (`lsn_pv_gen`, `lsnN_pv_gen`) · pre-existing on master `2bbc5c412` · filed 2026-09-27 against master `2bbc5c412`**

Repro:

    type LS = "a" | "b"
    function k<T>(v: T) {
      print(v)
    }
    const x: LS | null = "b"
    k(x)
    // vl check: rc 0.  vl run: emitProgram: print of a literal-union atom whose type carries no member texts

#### Mechanism

Not ablated to a rung; read off the code, not measured. `print`'s literal-union arm claims the operand (`exprIsLitAtom`) and asks
for the nullable niche's member texts (`nodeNulLitUnionMemberTexts`) and then the plain ones
(`litAtomWidenTexts`); at a `LS | null` pin neither reads the pin, since the instance's node
records the generic's `T`, so both come back empty and the arm refuses. The direct parameter
`v: LS | null` and the non-null pin `LS` both print.
