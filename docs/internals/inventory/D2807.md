### D2807 — `print` of a type parameter pinned to a nullable literal union has no member texts

**closed 2026-09-28 — the filed repro prints `b` · was loud emit reject, clause 2, 2 cells of D2802's grid (`lsn_pv_gen`, `lsnN_pv_gen`), pre-existing on master `2bbc5c412` · closed with [D2978](D2978.md): `print`'s niche arm takes its texts from `nulLitAtomTexts`, which reads a parameter's texts off the instance's annotation node, the node `exprNulLitUnion` claims it by · the one-union spellings (`"a" | "b" | null`, or an alias of it) are [D2998](D2998.md) · filed 2026-09-27 against master `2bbc5c412`**

Repro:

    type LS = "a" | "b"
    function k<T>(v: T) {
      print(v)
    }
    const x: LS | null = "b"
    k(x)
    // vl check: rc 0.  vl run: emitProgram: print of a literal-union atom whose type carries no member texts

Want:

    b

#### Mechanism

`print`'s literal-union arm claimed the operand (`exprIsLitAtom`, through `exprNulLitUnion`'s
parameter arm, which reads the instance's pinned annotation node) and then asked for the niche's
member texts off the operand node itself (`nodeNulLitUnionMemberTexts`). An instance's leaf node
records the generic's `T`, so both text readers came back empty and the arm refused. The claim
and the texts now read the same node.
