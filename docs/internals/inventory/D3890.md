### D3890 — a nested generic called through a `const` alias at a type its body refuses runs

**closed 2026-10-08 by lane SC, with D3853 · now a loud check reject · was check-clean silently wrong · found in review of #3468 · filed 2026-10-08 against master `a1c9be3c4` · pins: `tests/cases/generics/error-nested-generic-alias-called-at-wrong-type.vl`**

Repro:

    function a<T>(x: T) {
      function b<U>(y: U) {
        const n: i32 = y
        print(n + 1)
      }
      const f = b
      f(true)
      print(x)
    }
    a(1)
    // vl check: rc 0.  vl run: prints 2, 1

Want:

    vl check: cannot assign boolean to 'n' of type i32

#### Mechanism

`lookupFnAliasNode` resolves `f` to `b`'s declaration, so the call is a declared callee, and
`cstrOwnedBy` then skips every constraint not owned by `b`. A nested generic owns none, because
its constraints belong to the enclosing `a`. So `b`'s demand was never checked at `f(true)`.
Closed by treating a call whose parameters are a nested generic's rows as a call to that
generic, whatever names it.
