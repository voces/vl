### D9741 — a lambda returning `Map()` handed to a function-typed parameter whose result is a map has no map value slot

**loud emit reject · `vl check` rc 0 · clause 2 · CAPABILITY: the lambda with its result annotated, `(x: i32): {[string]: i32} => Map()`, runs, a named function returning `Map()` runs, and a lambda returning an annotated local map runs · found closing [D9581](D9581.md) · present on master `4fce2a127` · filed 2026-10-22 against master `4fce2a127`**

Repro:

    function g(f: (x: i32) => {[string]: i32}): i32 { const m = f(1)
      m["a"] = 4
      m.length }
    print(g((x: i32) => Map()))

#### Mechanism

Not traced. The lambda's `Map()` is an un-annotated map whose value type nothing in its own
body fixes, and the expected return `{[string]: i32}` is not adopted as the lambda's result the
way an expected list return is, so the map literal reaches the emitter with no value slot.

#### Ablation

| ingredient removed | outcome | needed? |
| --- | --- | --- |
| the lambda's un-annotated result (`(x: i32): {[string]: i32} => Map()`) | runs, `1` | **yes** |
| the lambda (`function h(x: i32): {[string]: i32} { return Map() }`) | runs | **yes** |
| the `Map()` literal as the result (a block binding `const m: {[string]: i32} = Map()`) | runs | **yes** |
| the body's use of the map (`g` returns `1`) | still refuses | no |
