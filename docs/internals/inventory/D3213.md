### D3213 — `==` between a join of a type parameter with a literal and the parameter compares the wrong arm at a record or list pin

**closed 2026-09-29 · was check-clean invalid wasm, clause 1, on master `94670f728` · found by the GU lane's body-operation grid (`eqa_rec`, `eqa_li`) and the CK lane's grid (`tp_rec_litrev_eq`) · fixture `tests/cases/generics/gradual-type-parameter-union.vl`**

Repro:

    type R = { f: i32 }
    function g<T>(a: T, c: boolean) {
      const r = if c { a } else { 5 }
      print(r == a)
    }
    const u: R = { f: 1 }
    g(u, true)
    g(u, false)
    // master: invalid module inside `g`

Want:

    true
    false

#### Mechanism

The union compare picks the arm to test by the other operand's type, and the instance's read of
`a` keeps the template's `T`, which the compare took for the `i32` arm. An `==` or `!=` with an
operand typed at a join of a type parameter now re-types its name operands at the pin.

#### Ablation

| ingredient changed | outcome on master | needed? |
| --- | --- | --- |
| an `i32` pin | prints `true false` | **yes** (a reference pin) |
| `function g(a: R, …)`, the direct spelling | prints `true false` | **yes** (the type parameter) |
