### D3126 — `y == null` inside a lambda of a `<T>` or hole instance at a non-null pin is refused at emit

**loud emit reject · clause 2 · open · 52 cells of the #3276 review's `g3` grid · the same on master `cc890c9f4` · filed 2026-09-28 against master `cc890c9f4`**

Repro:

    function f<T>(x: T) {
      print([x].filter((y) => y == null).length)
    }
    f(3)
    // vl check: rc 0.  vl build: emitProgram: bare null needs a struct-typed context

Want:

    0

#### Mechanism

Not localised past the ablation. At an `i32` pin the lambda's `y` is a plain `i32`, and the
comparison with `null` is lowered as though `null` needed a reference type to compare against.
The same test in the instance's own body, `print(x == null)`, folds to `false` and runs; inside
a lambda it reaches the struct-context `null` lowering instead.

#### Ablation

| ingredient changed | outcome | needed? |
| --- | --- | --- |
| `const a: i32 \| null = 3` then `f(a)` | prints `0` | **yes** (a non-null pin) |
| `print(x == null)` in the body | prints `false` | **yes** (the lambda) |
| `const k = (y: T) => y == null`, no `.filter` | loud emit reject | no (any lambda) |
| `function f(x)`, a hole | loud emit reject | no (a hole does the same) |
| `const xs: i32[] = [3]` at top level | prints `0` | **yes** (the instance) |
