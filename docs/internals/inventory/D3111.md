### D3111 — a closure over a parameter narrowed by a literal complement (`a is "err"`, else arm) is invalid wasm

**closed 2026-10-20 by lane L1 · the witness prints `10` · was check-clean invalid wasm · clause 1 · open on master `cd64d5faa` · closed by [D8181](D8181.md)'s inline-literal pin · fixture `tests/cases/generics/literal-complement-capture-at-hole-param.vl` · found by the #3274 review (`rv3274-5974/p/nb/i2.vl`) · filed 2026-09-28 against master `d408f2da4`**

Repro:

    function orErr(bad: boolean): i32 | "err" {
      if bad { return "err" }
      return 5
    }
    function takeErr(a) {
      if a is "err" { print(0) } else {
        const k = () => a * 2
        print(k())
      }
    }
    takeErr(orErr(false))
    // vl check: rc 0.  vl run: invalid module inside the lambda, type mismatch

Want:

    10

#### Mechanism

Not localised past the ablation. The else arm narrows `a` to `i32` by the literal complement
([D1243](D1243.md)/[D1412](D1412.md)'s `HD_GNOT` remainder); the closure's capture of `a` is
typed from the box and read as the narrowed `i32`, or the reverse.

Closed by [D8181](D8181.md)'s pin in `monoMakeInstanceParams` (emit_mono.vl): the hole's
instance parameter keeps `i32 | "err"` rather than softening the literal to `string`, so the
complement narrows to `i32` in the capture as well. Disabling that pin alone brings the invalid
wasm back.
