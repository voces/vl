### D3351 — a fresh function result in an `if` arm joined into a wider record is invalid wasm when a record of its own fields is declared

**check-clean invalid wasm · clause 1 · open · identical on master `2b30e3674` · found by the #3312 review grid (`freshfn`/`freshfnloc` × `ifjoin`, 16 cells) · filed 2026-09-30 against master `2b30e3674`**

Repro:

    type I = { f: i32 }
    type J = { f: i32 | null }
    function mk() { { f: 4 } }
    const c = true
    const x: J = if c { mk() } else { { f: 9 } }
    print(x.f ?? 70)
    // vl check: rc 0.  vl run: invalid module, "expected (ref null $type), found (ref $type)"

Want:

    4

#### Mechanism

The join face of D3338's mechanism: `mk`'s literal is built at the declared `I` row, and the `if`
delivers it to `J`. The direct delivery `const x: J = mk()` is refused by `recBuiltAtDeclared`;
the join operand is walked by the storage rule, which judges a call of a function returning only
literals as fresh, and the `match` and inferred-return joins of the same call run on master, so
refusing every join would lose them.

#### Ablation

| ingredient removed | outcome | needed? |
| --- | --- | --- |
| `type I = { f: i32 }` | runs, prints `4` | **yes** |
| the join (`const x: J = mk()`) | refused by the checker | **yes** |
