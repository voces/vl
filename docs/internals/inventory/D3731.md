### D3731 — a captured parameter, loop variable or module-scope block `let` that a lifted function assigns keeps its heap cell

**runs today and must keep running · open · a cost row, no wrong value: the witness prints its Want, and the cell is the cost · residue of [D3664](D3664.md): only a function frame's own `let` is considered · filed by lane L2 against master `687b42dbe`**

Repro:

    function f(p: i32): i32 {
      const inc = () => { p += 1 }
      inc()
      inc()
      p
    }
    print(f(5))
    // `inc` is lifted, and `p` is still copied into a `struct.new` cell (`p$cb`) per call

Want:

    7

#### Mechanism

`cboxScalarLets` keeps only `CBOX_LET` bindings. A parameter or loop variable is boxed through a
seeded `name$cb` cell, and a module-scope block `let` lives in the start function, which is no
`fnStmts` frame and never hosts a lifted function (`cloLiftDecide` refuses a parent of -1).

#### Grading list

`for i in 0 until 3 { const bump = () => { i += 10 }; bump(); s += i }` (prints 10 for `s`), and
a module-scope `{ let k = 0; const bump = (d: i32) => { k += d }; bump(4); bump(5); print(k) }`.
