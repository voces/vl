### D17029 — a field store through a field narrowed to one record member unboxes a receiver that is already the member's record

**closed 2026-11-20 by lane IR6 · now runs, `5` · was check-clean invalid wasm · `emitFieldStoreNarrowed` unboxes the receiver only where its read is not already the member's record (`boxedArmOfMember`), as the field-read tails do · pins: `tests/cases/narrowing/narrowed-field-store-through-a-member-record.vl` · found grading IR-REV's store positions for D17028 · present on every seed back to the earliest kept · filed 2026-11-20 against master `c34a60bfd`**

Repro:

    type A = { v: i32 }
    type B = { s: string, w: i32 }
    type W = { h: A | B }
    function f(q: W) {
      if q.h is B { q.h.w = 5 }
      if q.h is B { print(q.h.w) }
    }
    f({ h: { s: "b", w: 1 } })
    // vl check: rc 0.  vl run (before): the emitted module failed to validate inside `f`:
    // type mismatch: expected (ref null union box), found (ref B)

Want:

    5

#### Mechanism

`q.h.w = 5` under `q.h is B` takes `fieldStoreArmOf`'s `narrowVariant` arm: the receiver `q.h`,
then the box's payload cast to `B`, then the write. But `q.h` is a read of `B` at its own type out
of the union box it is held in (`boxedArmOfMember`), so the receiver's own field tail has already
cast it, and the store unboxed a record. A variant global receiver ran only while
`boxedArmOfMember` did not name its reads (D17028).
