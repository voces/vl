### D1997 — an `extern function` with no return type was a void import the call lowering did not know was void, and `: void` itself was refused by the scalar whitelist

**closed 2026-09-22 — now a loud check reject (owner ruling 2026-09-22: an extern states its result, `: void` included) · was check-clean invalid wasm, clause 1, and `: void` a loud check reject, clause 2 · reported by plumb (PL-013, `~/plumb/docs/vl-issues.md`) · filed against master `914d64d65` · fixtures `tests/cases/extern/void-result.vl`, `tests/cases/extern/error-no-return-type.vl`, `tests/cases/extern/error-void-value.vl`, `tests/cases/extern/error-void-param.vl`, `tests/vl_extern_test.ts`**

Repro:

    extern function g(a: i32)
    g(1)
    // was: vl check rc 0, vl build: `type mismatch: expected a type but nothing on stack`
    // now: vl check rc 1, extern `g` has no return type — … write `: void` for an extern
    //      that returns nothing

#### Mechanism

Two halves. The checker and the import writer both read a missing return annotation as a void
import (`TY_VOID`, an empty result list), but the statement lowering asked only the fs slot table
and `fRetVoid` whether a call leaves a value, so it wrote a `drop` after a call that left nothing
— invalid wasm at top level, and a function whose tail was the call inferred a result it never
pushed. The spelling that says what the author meant, `: void`, never reached either: the return
annotation went through `externScalarTy`, the parameter whitelist, whose refusal talks about
bytes and `Buf`. The fix refuses the missing annotation in the checker, admits `void` in the
return position only, and gives the emitter one predicate, `calleeIsVoidExtern`, that the
statement lowering and the tail-value classifier both ask. A third gap sat under the lambda
position: an extern called inside a closure, or inside any function of a module that uses a
function value, was captured like a variable, so `emitCall`'s extern arm (gated on the name not
being bound) never fired and the call was `call to unknown function` at every return type.
Externs now take the capture exemption the intrinsics have, and that exemption now sees a
module-scope `for` variable of the same name (D2010). The checker also refuses the two value
positions the void-`function` rules had missed: a `==`/`!=` operand and a generic argument.
