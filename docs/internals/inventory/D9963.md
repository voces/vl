#### Mechanism

The literal is adopted node-side into the declared row `Node`, whose `next` field is a
nested-struct slot (`FC_STRUCT`). The map's value slot is minted from the literal's own
spelling `{v:i32,next:null}`, which names no row, so `mvValRowOfShape` looks for the declared
row it was adopted into; `adoptedFieldCompat` refused a `null` field into a nested-struct
slot, so no row matched and no mv slot was interned. A nested literal failed the same test one
level down, because `nestedStructNamesCompat` compares the field's canonical ids and the
literal's spelling has none.
