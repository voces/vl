### D3168 — a hole instance's member call over a record passed from a local calls the first instance's field function

**closed · the receiver of a member call typed at a hole reads the instance's own binding of it (`holeOperandTyOf`, ahead of `valueReadPinTy`) when choosing the closure, as D3110 made the binding its own record · fixture `tests/cases/generics/record-instance-field-function-through-capture.vl` · was loads then traps (a scalar pair) and check-clean invalid wasm (a mix holding `i32 | null` or `string`) · clause 1 · the 9 master-failing `hole__*__local__member__n{2,3}` cells of lane HF's 714-cell grid · the same on master `934f169f4` · filed 2026-09-29 against master `934f169f4`, closed 2026-09-29 against master `934f169f4`**

Repro:

    function F(z) {
      print(z.f())
    }
    function main() {
      const r0 = { f: () => 7 }
      F(r0)
      const r1 = { f: () => 2.5 }
      F(r1)
    }
    main()
    // on master 934f169f4: prints 7, then wasm trap: indirect call type mismatch

Want:

    7
    2.5

#### Mechanism

The closure a member call dispatches to is found syntactically first: a hole parameter's
receiver follows each call of the instance to its argument, resolved in module scope. A module
binding is found that way and a local is not, so the lookup fell to the row's first literal.
D3110's correction by the instance's own record then asked `valueReadPinTy`, which reads the
parameter's pinned annotation, the shared row. The instance's hole binding carries its own
record since D3110, and is now read first.
