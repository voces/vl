### D2519 — an i32-keyed `Set` or map as an arm of a union `self` refuses at emit, so its `self`-function cannot be declared for a set of integers

**closed 2026-09-26 — the filed repro RUNS and prints `true`, `99` · was loud emit reject, clause 2 · the ruling `open-rulings.md` §B6a-map-in-union-box (owner, Q5 (a)) lifted the refusal, and the integer-keyed mono maps took box tags of their own · filed 2026-09-25 against master `54fcaf5d8` from the #3161 review**

Repro:

    function add(self: Set<i32> | string, x: i32) { print(99) }
    const s = Set<i32>()
    s.add(1)
    print(s.has(1))
    "z".add(3)
    // vl check: rc 0.  vl run: emitProgram: an i32-keyed Map/Set is supported as … — not inside '{[i32]:boolean}|string'

#### Mechanism

Not a member-call defect: the `self` parameter's annotation is a union with an i32-keyed map
member, and `i32MapSpellingLowerable` (`emit_collect.vl`) refuses that position everywhere — a
union box records the member's tag, not which map struct the payload holds, and the i32-keyed
map is a different struct from the string-keyed one. Any binding, parameter or return of type
`Set<i32> | string` refuses the same way. `Set<string> | string` runs. Closed by a tag per key
rep: a map arm's tag was already its value slot's, and a slot carries its key, so only the
mono (i32-cell value) maps shared one tag; the i32- and i64-keyed mono maps now tag at codes 15
and 16 above the value-atom band, and the narrowed unbox casts to its key's struct.
