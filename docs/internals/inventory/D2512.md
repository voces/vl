### D2512 — a widening assignment whose right side is a call, delivered as an `i32` store's value, stores the widened `f64`

**closed 2026-09-25 — the filed repro RUNS and prints `7` / `7` · was check-clean invalid wasm, clause 1 · pre-existing, identical on master `54fcaf5d8` · found by #3165's review grid · filed 2026-09-25 against master `54fcaf5d8`**

Repro:

    let wf: f64 = 0.0
    function g(): i32 {
      return 7
    }
    const mp: {[string]: i32} = Map()
    mp["w"] = (wf = g())
    print(mp["w"] ?? 0)
    print(wf)
    // vl check: rc 0.  vl run: invalid module, type mismatch: expected i32, found f64

#### Mechanism

`assignValueSpill` declines to move a value-position write when an operand evaluated before it
is a name and its right side may write — a call — so the write stayed and lowered as
store-then-re-read, which pushes the cell's widened rep. The re-read is now taken back to the
right side's rep by the exact inverse of the widening (`asgReadUnwidenOp`: `i32.trunc_f64_s`,
`f32.demote_f64`, `i32.wrap_i64`, and `ref.as_non_null` for a ref written into its own nullable
niche), and `asgReadNode` names the right side as the value's rep. Closes [D2412](D2412.md) and
[D1303](D1303.md) with it.

#### Ablation

| ingredient removed | outcome | needed? |
| --- | --- | --- |
| the right side a literal (`wf = 7`) | prints `7` / `7` | **yes** — a call |
| `wi: i32` as the target (no widening) | prints `7` | **yes** — a widening write |
| the value bound (`const r: i32 = (wf = g())`) | prints `7` / `7` | **yes** — an element/map store |
| the value printed (`print(wf = g())`) | prints `7` / `7` | **yes** — as above |
| a list element store (`xs[0] = (wf = g())`) | still invalid | no |
| the program inside a function | still invalid | no |

#### Grading list

* The list-element spelling, `xs[0] = (wf = g())`.
* The function-scope spelling.
