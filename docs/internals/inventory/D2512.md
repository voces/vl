### D2512 — a widening assignment whose right side is a call, delivered as an `i32` store's value, stores the widened `f64`

**check-clean invalid wasm · clause 1 · pre-existing, identical on master `54fcaf5d8` · found by #3165's review grid · filed 2026-09-25 against master `54fcaf5d8`**

Repro:

    let wf: f64 = 0.0
    function g(): i32 {
      return 7
    }
    const mp: {[string]: i32} = Map()
    mp["w"] = (wf = g())
    print(mp["w"] ?? 0)
    print(wf)
    // vl check: rc 0.  vl run: invalid module, type mismatch: expected i32, found f64

#### Mechanism

Not traced. An assignment's value is its right side at the right side's type (`i32` here),
and the store into `mp["w"]` receives the target's widened `f64` instead. The value-write
spill of D2398 (`assignValueSpill`) moves such a write ahead of its statement as
`const v = e; wf = v`, and a literal right side takes a separate copy path (`asvLitCopy`),
which is the spelling that runs; a call right side goes through `spillLocal`. Which of the
spill's local, or a map/element store that never reached the spill, delivers the `f64` is
the question to trace — a prediction, not a finding.

#### Ablation

| ingredient removed | outcome | needed? |
| --- | --- | --- |
| the right side a literal (`wf = 7`) | prints `7` / `7` | **yes** — a call |
| `wi: i32` as the target (no widening) | prints `7` | **yes** — a widening write |
| the value bound (`const r: i32 = (wf = g())`) | prints `7` / `7` | **yes** — an element/map store |
| the value printed (`print(wf = g())`) | prints `7` / `7` | **yes** — as above |
| a list element store (`xs[0] = (wf = g())`) | still invalid | no |
| the program inside a function | still invalid | no |

#### Grading list

* The list-element spelling, `xs[0] = (wf = g())`.
* The function-scope spelling.
