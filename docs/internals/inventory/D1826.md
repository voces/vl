#### Mechanism

D1671 stages a `?.` chain's base in `optRecvSlot` when it is not a re-readable place, and
every arm reads the stash instead of re-emitting the receiver. The staging MARK is set per
lowering entry (`optRecvStageMark`), and the fused `?? d` form of a chain whose own receiver is
another `?.` link re-enters the chain lowering for the inner link, which re-marks and so
re-emits the base. The one-link `?? d` form (`mkC()?.y ?? 0`) and the two-link `== null` form
(`mkD()?.inner?.y == null`) are both cells of `tests/cases/expressions/optchain-call-receiver-once.vl`
and both print 1; it is the two-link `??` that is uncovered.

Not D1815's: the guarded-dot spelling `mkCount()?.y.z ?? 0` normalises to exactly the node
shape above and prints the same 2 on both compilers.
