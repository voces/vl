### D6701 — a record literal holding a generic, written as the argument to a narrower declared record parameter that reads the function under `is`, is refused at emit

**closed 2026-10-18 by lane L1 · runs, prints `9`, `in` then `10` · was loud emit reject · `vl check` rc 0 · clause 2 · a record literal holding a generic, the argument to a declared parameter of a call statement whose callee is a name and whose earlier arguments are constants or names, is declared as a `const` just before the statement, so the narrowed read pins it as the `const` spelling does; `look2(1, { f: k4, g: 10 })` runs too · pins: `tests/cases/objects/record-literal-arg-generic-field-read-under-is.vl` · found closing [D6471](D6471.md) · filed 2026-10-18 against master `ca2adfdc7`**

Repro:

    type G = { g: i32 }
    type H = { f: (x: string) => string, g: i32 }
    function k4<T>(x: T): T { return x }
    function look(o: G) {
      if o is H { print(o.f("in")) }
      print(o.g)
    }
    look({ g: 9 })
    look({ f: k4, g: 10 })
    // vl check: rc 0.  vl run: emitProgram: a generic function taken as a value reaches no call that fixes its type — annotate the destination's function type

Want:

    9
    in
    10

#### Mechanism

Not located. Bound first to `const r4` the record's generic field is pinned by the narrowed read
`o.f("in")`; written in the argument position the literal reaches no such pin.
