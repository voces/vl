### D3833 — a lambda reachable only through a `let` alias is typed with no call site of its own, so its parameter stays `i32`

**check-clean invalid wasm · found in review of lane SC · filed 2026-10-08 against master `5a281ef27`**

Repro:

    function mk(x: string) {
      const c = (y) => y + "C"
      const e = (y) => y + "E"
      let d = c
      if x == "b" { d = e }
      d(x)
    }
    print(mk("a"))
    print(mk("b"))
    // vl check: rc 0.  vl run: exit 70, invalid module inside `mk`:
    //   type mismatch: expected i32, found (ref $type)

Want:

    aC
    bE

#### Mechanism

The call `d(x)` goes through a `let` binding, and `c` and `e` have no direct call sites. The pin that would give their `y` parameter the argument's type (D3820's callback pin) does not follow a mutable alias, so they are emitted with the default `i32` parameter and the indirect call passes a string reference to it. A direct call of `c` anywhere in the function repairs it; so does a `const` alias, which the alias tracking does follow.

#### Ablation

| ingredient removed | outcome | needed? |
| --- | --- | --- |
| the reassignment `d = e` (only `let d = c; d(x)`) | still invalid, inside `mk` | no |
| `let` becomes `const` (`const d = c; d(x)`) | prints `aC` | **yes** |
| a direct call `c(x)` beside `d(x)` | prints `aCaC` | **yes** |
| the hole (`(y: string) => ...` on both lambdas) | prints `aC`, `bE` | **yes** |
| the alias, both lambdas called directly | prints `aCaE` | **yes** |
| `if x == "b" { d = e }` replaced by `const d = if x == "b" { e } else { c }` | loud emit reject: a function-value call has no interned signature | a neighbour, not this row |

#### Grading list

* The `const d = if … { e } else { c }` spelling above: a loud emit reject on the same program.
* `let d = c` captured by a lambda (`const f = () => d(x)`) and by a nested `function`.
* D3832 (a never-called lambda): the same defaulted parameter reached without an alias.
