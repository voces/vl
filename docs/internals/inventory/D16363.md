#### Mechanism

`f` is called at two types, so it holds a tagged function set, an `i32` id, and so does its copy
`v`, which the decision stamps as a holder of the set. The monomorphizer delivers a write into an
un-annotated binding at the signature the flow table pins it at (D3957): `v` is called at `i32`,
so `v = f` materialised `id`'s `i32` instance and re-pointed the read of `f` to it, a closure
stored into the id's slot. A write into a map element took the same path through
`monoDeliverAtPinTys`. Such a write now stores the id: the binding's type, or the container's
element or value type, carries the tagged set. The family is the
written-binding face of the function-holding slot facts (D16301's population, bucket (a) of the
clause-2 map), here with the declarations first.
