### D2992 — an `f32` record literal is built at a declared record whose field is a NUMERIC literal set

**check-clean invalid wasm · identical on master `4dc94bd23` and on #3250 · found by the #3250 review grid · filed 2026-09-28**

Repro:

    type NS = 1 | 2 | 3
    type DA = { v: NS }
    const a: DA = { v: 2 }
    const xc: f32 = 1.5
    const c = { v: xc }
    print(c.v)
    // vl check: rc 0.  vl run: invalid module — type mismatch

Want:

    1.5

#### Mechanism

`c` is checked as `{v: f32}`. The record-literal row scan still lets `DA` capture it, because
`declRowFieldKindFits` (#3250) gives a numeric literal set kind 0, so it cannot tell `NS` apart
from `f32`. A numeric set is an `i32` at run time. Giving it that kind was tried in #3250 and
moved [D2988](D2988.md)'s annotated face from a loud refusal to invalid wasm, so the two rows
close together.

#### Grading list

#3250's two emit → invalid cells: the NS own-read, where the literal is read at its own type
beside a declared `{ v: NS }` record. Also [D2988](D2988.md), the `boolean` face read through a
generic parameter.
