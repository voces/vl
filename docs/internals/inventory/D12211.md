### D12211 — an exported generic function read as a value and never called passes the checker's export rule

**loud emit reject · `vl check` rc 0 · `emitProgram: exported function `id` is generic over `T` and nothing in the program calls it` · clause 2 · DESIGN: the checker refuses the same export with no read (D3817), so it owes this one · found surveying emit refusals for L3 family (d) · filed 2026-10-24 against master `b8e223f93`**

Repro:

    export function id<T>(x: T): T { x }
    const g = id
    print(1)

#### Mechanism

`expUncalledExports` (check_pins.vl) treats an export as called when any statement outside
its body names it (`expNameReaders`). A value read that is never called counts as a reader, so
the checker passes the export; the monomorphizer then finds no instance for the host's entry
and refuses at emit_mono.vl's exported-generic floor. Telling a value read that reaches a call
from one that does not is the monomorphizer's question today, which is why the checker cannot
just narrow its reader test.

#### Ablation

| ingredient removed | outcome | needed? |
| --- | --- | --- |
| the read (`const g = id`) | check reject, D3817 | **yes** |
| `export` | runs (an internal generic with no instance is stubbed) | **yes** |
| a call through the read (`print(g(1))`) | runs | **yes** |
| the read at top level (`function u() { const g = id }`, `[id]`) | still refuses at emit | no |
