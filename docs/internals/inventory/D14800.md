### D14800 — an inferred return of a join of literal-bound consts is typed by their literal set but stored as a string

**runs today and must keep running · refutation pin: switching `emitExpr`'s string-to-atom hook to the closed contextual type lowers the join's const reads as atoms into the string-returning body (invalid wasm) · the return-position twin of [D14757](D14757.md) · filed 2026-11-01 against master `4eb649fb`**

Repro:

    const Z = "zz"
    const W = "ww"
    const f = (n: i32) => if n > 0 { Z } else { W }
    print(f(1))
    function g(n: i32) { if n > 0 { Z } else { null } }
    print(g(0) ?? "none")

Want:

    zz
    none

#### Mechanism

The join's value leaves record the join's type as their contextual type: `"zz" | "ww"`, or
`"zz" | null` (D7446's one-literal niche). Both rep as the i32 atom. The function's inferred
return is stored as a string (a nullable string for the second), so the arms lower as strings
only because the delivery flag is off. By D14757's ruling the storage is the wrong side: the
inferred return is to be stored as the set's atom.

#### Ablation

| ingredient removed | outcome | needed? |
| --- | --- | --- |
| the const reads (`if n > 0 { "zz" } else { null }`) | the leaves' record widens, agreeing with the storage | **yes** |
| the inferred return (`(n: i32): string \| null => …`) | the return is stored as its annotation, agreeing | **yes** |
| the return position (`const v = if … { Z } else { null }`) | runs under the switch since D14757's fix | **yes** |
