### D15090 — two boxed numbers of different width compare their tags, so equal values print `false`

**closed · prints `true` · was check-clean silently wrong, clause 1 · ruling 2026-11-03: numeric `==` across widths is a value compare everywhere, through nullable and union boxes, and `null == null` is true · a union `==` compares two number arms of different width by value at the wider (box against box, staged or re-read, and box against a plain number), and `(i32 \| null) == f64` is admitted at check and at a pin · matrices `nullable-number-cross-width-eq`, `nullable-number-against-wider-number-eq` · pre-existing on master `f7f508c49` · found grading D15055's semantics · filed and closed 2026-11-03 against master `f7f508c49`**

Repro:

    const x: i32 | null = 1
    const y: f64 | null = 1.0
    print(x == y)
    // was: PRINTS false

Want:

    true

#### Mechanism

A union `==` (`emitUnionBoxEqStaged`) compares the two boxes' tags first and answers `false` when
they differ. An `i32` and an `f64` member are different arms with different tags, so `1` and
`1.0` are never equal there, while the plain spelling `i32 == f64` widens and compares the
values. The checker admits only lossless pairs (`i32`/`i64`, `i32`/`f64`, `f32`/`f64`), so those
are the pairs whose tags have to meet. Separately, `(i32 | null) == f64` is refused at check
("cannot compare"), while `(i64 | null) == i32` is admitted.

The nullable and union spellings in the ablation, both operand orders, `!=`, and a `null` on
one side and on both.
