### D5002 — a generic call's `V[]` result delivered straight into a concrete list parameter is invalid wasm

**closed 2026-11-02 · now a loud check reject, the direct spelling's own (`i32[] is not f64[]: a container never widens implicitly`) · was check-clean invalid wasm, clause 1 · fixture `tests/cases/generics/error-type-parameter-list-into-concrete-list.vl` · the non-fresh face of [D4983](D4983.md) · filed 2026-10-15 against master `2f625f31e`**

Repro:

    function sumF(xs: f64[]) { print(xs.length) }
    function idL<W>(xs: W[]): W[] { xs }
    function t<V>(q: V[]) {
      sumF(idL(q))
    }
    t([1])

#### Mechanism

A `V[]` delivered to `f64[]` is converted element by element at the `V = i32` instance only
when the widen site can see what else holds the source: a rooted list or, since D4983, a
`.map` / `.filter` / `.slice` result. A call result has no root, so the site declines and the
instance passes `i32[]` where `f64[]` is taken. Whether a copy is right here (the callee may
return a list the caller still holds) or a refusal is not settled, so this row has no `Want:`.

Closed as the refusal the direct spelling gives (`sumF(q)` with `q: i32[]` is refused). A source
typed at a hole is recorded for its pins (`rcwPinNote`), which re-ask it the delivery seam's
shape and container rule once the pin makes it concrete (`validateRcwPins`); only a bare type
variable or a record holding one was recorded, so a `V[]` was never re-asked. A list or map
holding a type parameter is now recorded too where its destination names none, unless a list
method built it (D4983's fresh result, which converts).

#### Ablation
