### D5002 — a generic call's `V[]` result delivered straight into a concrete list parameter is invalid wasm

**check-clean invalid wasm · clause 1 · the non-fresh face of [D4983](D4983.md) · filed 2026-10-15 against master `2f625f31e`**

Repro:

    function sumF(xs: f64[]) { print(xs.length) }
    function idL<W>(xs: W[]): W[] { xs }
    function t<V>(q: V[]) {
      sumF(idL(q))
    }
    t([1])
    // vl check: rc 0.  vl run: invalid module, type mismatch inside `t`

#### Mechanism

A `V[]` delivered to `f64[]` is converted element by element at the `V = i32` instance only
when the widen site can see what else holds the source: a rooted list or, since D4983, a
`.map` / `.filter` / `.slice` result. A call result has no root, so the site declines and the
instance passes `i32[]` where `f64[]` is taken. Whether a copy is right here (the callee may
return a list the caller still holds) or a refusal is not settled, so this row has no `Want:`.

#### Ablation

| change | outcome | needed? |
| --- | --- | --- |
| `const w = idL(q)` then `sumF(w)` | prints `1` | **yes** |
| `const w: V[] = idL(q)` then `sumF(w)` | prints `1` | **yes** |
| `sumF(idL<V>(q))` | invalid wasm | no |
| `t([1.5])` for `t([1])` | prints `1` | **yes** |
