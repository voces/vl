### D3560 — growing linear memory detaches a JS host's views, and `vl build` had no way to start the memory larger than one page

**closed 2026-10-03 — `vl build --initial-memory=<size>` / `--max-memory=<size>` (owner ruling E + D) · the witness shows the default one-page memory growing on a 4 MiB `Buffer`, which is what detaches a host's views; built with `--initial-memory=8MiB` it starts at 128 pages and does not grow · reported by sunpa (SP-011) · filed against master `fae55dec2` · fixture `tests/vl_initial_memory_test.ts`**

Repro:

    import { Buffer, storeI32, loadI32 } from "std:buffer"
    const before = __memory_size__()
    const b = Buffer(4 * 1024 * 1024)
    storeI32(b, 4 * 1024 * 1024 - 4, 42)
    print(loadI32(b, 4 * 1024 * 1024 - 4))
    print(before)
    print(__memory_size__())

Want:

    42
    1
    65

#### Mechanism

Every memory VL declared had min 1 page and no max (or the `--shared-memory` max), so the first
`Buffer()` past 64 KiB ran `memory.grow`, and growing an unshared memory detaches the
`ArrayBuffer` every JS typed-array view was built over. sunpa kept views of its draw list across
calls, and a culling pass that allocated detached them. The close adds the two limits fields
the declaration lacked: `setMemoryPages(initial, max)` (`compiler/emit_sections.vl`) sets the
min and an optional max that `emitMemoryLimits` writes, imported or defined alike, and the host
parses the sizes (`parse_memory_size`, `memory_sizes_error` in `scripts/vl-host/src/main.rs`).
`std:buffer` is unchanged: it grows only when an allocation passes `memory.size`. Interaction
with `--shared-memory` and the size rules: DECISIONS.md §"A memory's size is a build flag".

#### Grading list

The witness under `vl run --initial-memory=8MiB` prints `42`, `128`, `128`. The fixture builds
the declaration in every face (defined, `--import-memory`, `--shared-memory`, `-O`), runs the
SP-011 frame under V8 with and without the flag (the default memory's view detaches, the 8 MiB
one's does not), and refuses each invalid size and combination with exit 2 on `vl build` and
`vl run`.
