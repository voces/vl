### D3358 — a lambda joining two type parameters returns the first one's rep, so its caller reads the second arm as the first

**check-clean silently wrong · clause 1 · open · the same on master `78abe1318` · found by the #3310 round-2 re-review (`rv3310r2-Q7ZK/x/L1.vl`, `L2.vl`, and 30 split `isall` cells) · filed 2026-09-30**

Repro:

    type K = "a" | "b"
    function g<T0, T1>(a0: T0, a1: T1, k: i32) {
      const f = (j: i32) => if j == 0 { a0 } else { a1 }
      const e = f(k)
      print(e is null)
      print(e)
    }
    const x0: K | null = null
    const x1: boolean = true
    g(x0, x1, 0)
    g(x0, x1, 1)
    const y0: K | null = "a"
    g(y0, x1, 0)
    // today it prints true null false b false a

Want:

    true
    null
    false
    true
    false
    a

#### Mechanism

The lambda's join of `T0` and `T1` collapses to `T0`, a lambda's deferred return re-joins that
way at the call, and the lifted instance returns the `K | null` atom it was typed as. So `true`
is read as the atom `1` (`b`). Lane JW's kept-apart join of bare parameters (D3268) typed the
lambda's join `T0 | T1`, but no lifted lambda builds such a join: the reviewer's single-`is`
programs that ran on master became invalid wasm. So the kept-apart join, the null-arm join
(`tpOpenJoin`) and the non-member `is` answers are **gated off** inside a lambda body, for a
lambda's re-joined deferred return, and for a read bound to a call or an element read. That
restores master's behaviour, and master's defect.
