### D8145 — a list element narrowed to a record with a nullable field, and re-read through the index, is invalid wasm

**closed · the repro runs and prints `5` · was check-clean invalid wasm · `vl check` rc 0 · clause 1 · present on master `f90d0709e` and `8d9a182a7` · found as the one cell of [D8021](D8021.md)'s matrix the emit_mono rung leaves (`array_element_place`, annotated) · fixture `tests/cases/soundness/narrowed-element-nullable-field-reads-unbox.vl` · filed 2026-10-20 against master `f90d0709e`**

Repro:

    type J = { r: i32 | null }
    const q: J = { r: 5 }
    const xs: (J | string)[] = [q]
    if xs[0] is J { print(xs[0].r ?? 0) }

Want:

    5

#### Mechanism

Two reads of one field off a narrowed index place, each missing a step. The `??` arm over a
value-box field (`emitCoalesceUnionField`) asked `structIndexOfExpr` first, and an index place
narrowed to `J` answers with `J`'s struct row whenever the program also holds a bare `J`
(`q`), so the element's box was read as the bare ref without the `struct.get 1; ref.cast`
that unwraps the arm. It now asks the narrowed-arm question first, the pairing `emitMem` makes
(`coalNarrowedBoxArm`). The second read, `xs[0].r` under its own `!= null`, went through
`emitNarrowedMem`, which unboxed the field only by its member-path key, and an index-rooted
path has none (D451), so the box reached an `i32` consumer; it now unboxes through
`emitUnionFieldNarrowUnbox`, whose checker-typed arm the bare-arm read already uses.
