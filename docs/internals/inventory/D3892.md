### D3892 — a hole lambda delivered twice at one function type, after a delivery at another, reaches the first type's instance from the second delivery

**closed 2026-10-09 by lane SC · runs · was loads then traps · found closing D3881 · filed 2026-10-09 against master `c6ac0a1d2` · pins: `tests/cases/closures/hole-lambda-delivered-twice-at-one-type.vl`**

Repro:

    const tw = (y) => y + y
    const fs: ((y: string) => string)[] = []
    fs.push(tw)
    print(fs[0]("a"))
    const gs: ((y: i32) => i32)[] = []
    gs.push(tw)
    const hs: ((y: i32) => i32)[] = []
    hs.push(tw)
    print(gs[0](5))
    print(hs[0](6))
    // vl check: rc 0.  vl run: prints aa, then a wasm trap

Want:

    aa
    10
    12

#### Mechanism

A delivery at a signature the lambda's slot does not hold mints an instance and renames the
delivered name to it (D3867). The test for "this signature needs an instance" asked whether any
instance held it. After the first `i32` delivery one did, so the second delivery left its name
reaching the slot at `string`. It now asks whether the slot itself holds the signature, so every
later delivery finds and is renamed to the existing instance.

| the `string` delivery first | runs, `10`, `12` | **yes** |
