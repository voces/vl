### D15183 — a list argument held at its own type beside a fresh call D14817 copies is handed to an instance the call's wide build moved

**check-clean invalid wasm · clause 1 · gap 1 of [D14818](D14818.md)'s copy, reachable through [D14817](D14817.md)'s · found planning D14818 · filed 2026-11-03 against master `566f95ec`**

Repro:

    type Circle = { r: i32 | null }
    type K = { r: null }
    function sink(_x: Circle) { }
    function mkcall() { { r: null } }
    sink(mkcall())
    const k: K = { r: null }
    const ks: K[] = [k]
    function f<T>(a: T, b: T, c: T[]): i32 { c.length }
    print(f(mkcall(), k, ks))
    // vl check: rc 0.  vl run: the emitted module failed to validate: expected `Circle[]`, found `K[]`

Want:

    1

#### Mechanism

The held `k` pins `f` at `K`, so [D14817](D14817.md) builds `mkcall()` at `Circle` and copies it into
`K` where it is delivered. The call site's list parameter `c: T[]` is then served at the call's wide
rep: `recSitesLandAt` ends with `recRepArgsNote`, which notes every argument `recRepArgOf` serves at
`Circle`, and `recListArgTakesRep` admits the list. The instance is minted with `c` a `Circle[]`
while `ks` is a `K[]`. A copied call lands at its own type, so its siblings should not take the wide
rep.

| `k` in place of `mkcall()` | prints `1` | **yes**, the copied call |
| `[k]`, a literal, in place of `ks` | invalid wasm | no |
