### D15314 — a `??` default already typed at the read's record joins with the read's own type as a union, whose nested field read is refused at emit

**open · loud emit reject · `emitProgram: \`??\` over this nullable value is not supported yet — narrow it first` · clause 2 · the `if` spelling of the same join is refused at check · found closing D15310 · filed 2026-11-04 against master `e5a65514b`**

Repro:

    type H = { f: i32 | null }
    type J = { h: H }
    function mk() { { h: { f: 4 } } }
    const m = Map()
    m.set("a", mk())
    const wm: {[string]: J} = Map()
    wm.set("a", mk())
    const d: J = { h: { f: 1 } }
    const b = m.get("z") ?? d
    print(b.h.f ?? 0)

Want:

    1

#### Mechanism

The read `m.get("z")` is typed at its own record `{h: {f: i32}} | null` and stored at J. A default
typed J (annotated, or a `let` the record solve adopts at J) joins with it as the union
`{h: {f: i32}} | J`. A flat record survives that union, because emit reads a field both arms
share; at depth two the receiver `b.h` has no struct row. This is a question about the join's
type, not about adoption: D15310 closed the un-annotated `const` by building it at J while it
keeps its own type, which leaves its join one record.

#### Ablation

| ingredient removed | outcome | needed? |
| --- | --- | --- |

| the annotation (`const d = { h: { f: 1 } }`) | runs (D15310) | **yes** |
| the annotation, `let d = …` instead | still refused | no |
| the read missing (`m.get("a")`) | still refused | no |
| the join written as `if r != null { r } else { d }` | check refuses: `{h: {f: i32}} is not J … a record is shared, not copied` | no |
| `b` annotated `J` | check refuses, as the `if` does | no |

#### Grading list

The `let` spelling, the `if` spelling (whether the check refusal is the design's or the join's),
and the matrix `coalesce-built-read-held-nested-default` with the default annotated.
