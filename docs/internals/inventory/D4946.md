### D4946 — under `s is S[]` a `map` callback's parameter and a `for` variable over `s` read at the declared element

**closed · was loud check reject (clause 2) · related to D4928 (a narrowed list delivered as `K[]`) · filed 2026-10-15 against master `23dcd80be`**

Repro:

    type S = "a" | "b"
    const s = ["a", "b"]
    let keep: S[] = []
    if (s is S[]) {
      keep = s.map((x) => x)
      for x in s {
        const y: S = x
        print(y)
      }
    }
    s[0] = "zz"
    print(keep[0])
    // vl check (before): cannot assign string[] to S[];
    // cannot assign string to 'y' of type S

Want:

    a
    b
    a

#### Mechanism

The element narrowing `s is S[]` banks covered `s[i]` reads only; a callback parameter and a
`for` variable are fresh bindings typed by the declared element, so the copy D4928's message
named for a string union typed `string[]`, and the message fell back to an unspelled "a `map`
over `s`". The close hands the narrowed element to a `map`/`filter` callback literal's
parameter and to a `for` variable, when the callback or loop body may write no element of `s`
out of the leaf and calls nothing that may, and the callback runs in place (`cbElemNarrowFor`,
`checkForInNode`). Calls on a callback's own list-typed parameter resolve before the body is
checked, so a nested `r.map((x) => x)` copy does not read as an opaque writer. The message
now names `s.map((x) => x)` at every depth, and every named copy runs.

#### Grading list

The position matrix (binding, assignment, argument, return, `for`) for `string[]`, `i32[]`,
`string[][]` and `i32[][]`, annotated and inferred: each refused delivery's named copy runs.
A callback or `for` body writing `s[1] = "zz"`, calling a function that does, or pushing to `s`
keeps the declared element (`list-element-narrowing-callback-write-refused.vl`); a callback
literal in a closure that may run after the guard is not narrowed.
