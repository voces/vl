### D4132 — `is` on a value typed at a type parameter answers by the pinned record's declared type, not by whether the value fits

**closed 2026-10-24 by the D4088 close · the witness prints `fits` twice · the generic arm's read `a.x`, with a write through an aliasing `base: A` before it, prints the written `9` at both faces · was check-clean silently wrong · found in the #3568 review (rv3568 `u/generic_is.vl`) · filed 2026-10-11 against master `efd3c3f15`**

Repro:

    type A = { x: i32 }
    type B = { x: 1 | 2 }
    function f<T>(a: T) {
      if a is B { print("fits") } else { print("no") }
    }
    function h(a: A) {
      if a is B { print("fits") } else { print("no") }
    }
    const o: A = { x: 1 }
    f(o)
    h(o)
    // today: no, then fits

Want:

    fits
    fits

#### Mechanism

`is` is structural (D3885): at a concrete `A` the test asks whether the value's fields fit
`B`, and `{ x: 1 }` does, so `h` prints `fits`. In the generic body the test is decided at the
instance pinned to `A` by comparing the pinned type with `B`, which are different records, so
it answers `false` without looking at the value. The same instance pinned to `B` answers
`fits`.

#### Ablation

| ingredient changed | outcome on master | needed? |
| --- | --- | --- |
| `f(p)` with `p: B` | prints fits | **yes** (a pin that is not `B`) |
| `f({ x: 1 })`, a fresh literal | prints no | no |
| `f(5)` or `f("s")` | prints no (correct) | control |
| the direct `h(a: A)` | prints fits | control |

#### Grading list

A narrowed read inside the generic arm (`f<T>(a: T, base: A) { if a is B { … a.x } }`, rv3568
`u/genparam.vl`, which prints nothing today) once the test answers `fits`: it then needs the
same end-on-aliased-write rule as the concrete face, so grade a write through `base` too.
