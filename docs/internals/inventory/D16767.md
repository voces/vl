### D16767 — a record holding a `filter` result of a built list, returned from an un-annotated function and bound at an annotated record, builds a module that fails to validate

**check-clean invalid wasm · clause 1 · `type mismatch` at the binding · the `return_inferred` cell (annotated face) of `same-elems-result-in-literal.matrix.vl` · the same on master · found by lane WIDTH closing D16765 · filed 2026-11-16 against master `6822b8e75`**

Repro:

    type J = { f: i32 | null }
    function mk2() { return { f: null } }
    const dA: J = mk2()
    const src = [mk2()]
    function d() { return { g: src.filter((y) => y.f == null) } }
    const v: { g: { f: null }[] } = d()
    print(v.g[0].f)
    // vl check: rc 0.  vl run: invalid module, type mismatch

Want:

    null

#### Mechanism

The kept maker's build stores `src`'s elements at `J`, and the returned literal's field holds the
`filter` result at `J[]`, while `v`'s annotation lays its field out at `{ f: null }[]`. With `src`
itself in the field (`{ g: src }`) the build sees `src` delivered into `v`'s storage and keeps it
at `{ f: null }` throughout, which runs; a `filter` result's delivery is not counted as a delivery
of its receiver, so the two layouts meet at the binding unconverted and unrefused.

| the annotation on `v` | runs | **yes** |
| the function (the literal bound directly) | check reject, the built-container refusal | **yes** |
