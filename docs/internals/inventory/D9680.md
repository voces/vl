### D9680 — a list literal of a declared type parameter's value and its arithmetic with a wider literal has no list type at emit

**loud emit reject · clause 2 · `vl check` rc 0 · CAPABILITY: the un-annotated `function g(x)` prints `3.5` since [D9631](D9631.md), and `g(2.0)` prints `3.5` · found closing [D9631](D9631.md) · present on master `abe12f20f` · filed 2026-10-22 against master `abe12f20f`**

Repro:

    function g<T>(x: T) {
      const xs = [x, x + 1.5]
      print(xs[1])
    }
    g(2)
    // vl run: emitProgram: index access but list type not collected

Want:

    3.5

#### Mechanism

Not traced. In a `<T>` body `x + 1.5` is typed `T` itself, not a derived hole (a
`const z: boolean = x + 1.5` probe is accepted), so the list is `T[]` and the join has
nothing to keep apart. At the `i32` pin the list is `i32[]` while its second element
computes at `f64`. The un-annotated spelling mints an arithmetic hole that pins at `f64`.

#### Ablation

| ingredient changed | outcome | needed? |
| --- | --- | --- |
| the literal `1` (`[x, x + 1]`) | runs, prints `3` | **yes** |
| the call `g(2.0)` | runs, prints `3.5` | **yes** |
| the list returned (`return [x, x + 1.5]`, `print(g(2)[1])`) | same refusal | no |
| the bare `[x + 1.5]` | runs, prints `3.5` | **yes** |

#### Grading list

The binding and the returned spellings, an `i64` literal, and the un-annotated `g(x)`,
which must keep printing `3.5`.
