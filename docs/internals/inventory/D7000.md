### D7000 — an `if` expression of a hole function handed to a parameter nothing reads, where another use calls the function through a binding, is refused at emit

**closed 2026-10-19 by lane L1 · runs, prints `1` and `z!` · was loud emit reject · `vl check` rc 0 · clause 2 · CAPABILITY: the same program handing `exclaim` by name runs, printing `1` and `z!` · an uncalled-parameter argument whose every value reaches nothing keeps the closure of the instance another use builds, through an `if` as through a name · pins: `tests/cases/closures/hole-fn-if-to-unread-param-called-elsewhere.vl` · found closing [D6992](D6992.md) · present on master `bfb571e3b` · filed 2026-10-19 against master `bfb571e3b`**

Repro:

    function exclaim(s) { return s + "!" }
    function unread(p) { print(1) }
    const f = exclaim
    unread(if true { exclaim } else { exclaim })
    print(f("z"))
    // vl check: rc 0.  vl run: emitProgram: monomorphize: unsupported argument type for `p` in a call to `unread`

Want:

    1
    z!

#### Mechanism

Measured with a probe build. Handed `exclaim` by name, the parameter takes the closed function
type the checker binds at the call (`(string) => string`, from the call through `f`). Handed the
`if`, the checker's binding for the parameter stays open, so that rung closes nothing. The
unread-parameter stub rung then declines, because another use instances the function, and no
later rung types an `if`.
