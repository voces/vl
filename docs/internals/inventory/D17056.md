### D17056 — a global read from a map of hole functions, in a module with a reassigned list of them, is read non-null under its own `!= null` test and traps when the key is missing

**closed 2026-11-22 by lane IR-C1 (#9641) · now runs, `none` · was loads then traps · `monoPinKeepsNull`: a pinned list type keeps each binding's own null · pin: `tests/cases/soundness/pinned-list-binding-keeps-its-null.vl` · found by lane IR-M1 on the coordinator's missing-key test of IR-N9's `mv4` cell · filed 2026-11-22 against master `025ee3dda`**

Repro:

    function inc0(a) { return a + 1 }
    function dbl(a) { return a * 2 }
    let b2 = [inc0, dbl]
    b2 = [dbl]
    const m4 = Map()
    m4["k"] = [inc0, dbl]
    const mv4 = m4["absent"]
    if mv4 != null {
      const v4 = mv4
      print(v4.map((f) => f(3))[1])
    } else { print("none") }
    // vl check: no errors. vl run: wasm trap: null reference.

Want:

    none

#### Mechanism

`mv4`'s binding is typed (its scope type) as the non-null list `((i32) => i32)[]`, though its
initializer is a map read, `((i32) => i32)[] | null`, and its cell kind (`globalCellKind`) follows
as the non-null `reflist`. The initializer stores the missing key's `null` as it stands into the
`(ref null …)` global, and the `!= null` test that guards a narrowed read is written as
`ref.is_null(ref.as_non_null(global.get mv4))`, which traps before it can answer. In the same
module without the reassigned `let`, the binding is typed nullable and the program prints `none`.
