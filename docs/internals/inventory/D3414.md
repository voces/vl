### D3414 — a binding of `m.get(k)` on a hole's map field refuses at emit, reading the method call as a call of a value

**closed 2026-11-03 by lane column-G1 with [D15153](D15153.md) · runs, prints `true` · was loud emit reject, clause 2 · found by the #3318 review (`rows/g.vl`, un-annotated) · the same on master `8df60e472` · filed 2026-09-30 against master `8df60e472`**

Repro:

    type R = { m: {[i32]: string} }
    function mk(): R {
      const m: {[i32]: string} = Map()
      m[3] = "hi"
      { m: m }
    }
    function use(p) {
      const x = p.m.get(9)
      print(x == null)
    }
    use(mk())
    // vl run: emitProgram: callee is not a function name

Want:

    true

#### Fix

The same mechanism as [D15153](D15153.md), filed later: `monoPinMemberCall` rewrote `m.get(k)` into
the read `m[k]` only for a receiver that is a pinned parameter, so `p.m.get(9)` in a hole's
instance stayed a call. A receiver the instance's elaboration types as a map now reads the same
way; the un-annotated and `<T>` spellings both print `true`.

#### Mechanism

Not traced. Unbound, the method spelling runs through a hole (`print(p.m.get(3) ?? "d")` prints
`hi`, and `print(p.m.has(3))` prints `true`). Bound, the binding's cell kind is classified from
the initializer, whose recorded type at the hole is not a map read, so the `Call` falls to the
function-value call lowering, which finds no function behind `p.m.get`.

#### Ablation

| ingredient changed | outcome | needed? |
| --- | --- | --- |
| `function use(p: R)` | prints `true` | **yes** (the hole) |
| `function use<T>(p: T)` | the same refusal | no |
| `print(p.m.get(9) ?? "d")`, no binding | prints `d` | **yes** (the binding) |
| `const x = p.m[9]`, the index spelling | prints `true` | **yes** (`.get`) |
