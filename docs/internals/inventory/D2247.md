### D2247 — `m[k] ?? null` over a map whose value type excludes null is lowered as the non-null value

**closed 2026-09-23 — the witness prints `true` · was a loud emit reject (`struct equality is not supported yet`) for the un-annotated binding and the compare, and a null-reference trap after load at a return, argument, field or if-arm delivery of a miss · reported by consumer plumb (PL-023: `m[k] ?? null` on a record-valued map) · filed against master `91d4210a0` · fixture `tests/cases/maps/coalesce-nullable-default.vl`**

Repro:

    type V = { x: i32, y: i32 }
    const m: {[string]: V} = Map()
    const w = m["z"] ?? null
    print(w == null)
    // vl check: rc 0.
    // vl run (as filed): emit error, struct equality is not supported yet. Now prints true.

#### Mechanism

The fused get-with-default (`emitMapGetOr`) and its classifier (`coalesceStaysNullable`) held
that a `??` read stays nullable only when the map's VALUE type is nullable
(`mvSlotNullable`). A miss is the read's null whatever the value type admits, so over
`{[K]: V}` a nullable default was classified as the non-null `V` — the binding took a struct
cell and `== null` became struct equality — and the lowering recovered the result with
`ref.as_non_null`, which trapped on a miss at every other delivery. Three changes: the rewrite
pass folds `x ?? null` to `x` for every `x` (a null left selects a null default); a nullable
default leaves the map `??` nullable regardless of the slot; and the fused read seeds the
default's `ref.null` and skips the recovery whenever the default is nullable.
