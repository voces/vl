### D10031 — a generic's function parameter returning `T[] | i32` has no list receiver once `is i32` narrows its result

**loud emit reject · `vl check` rc 0 · `emitProgram: '.length' on a receiver the emitter cannot classify as a list, string, map or set` (an index read refuses as `index receiver is not an array or string`; a list of functions delivered as a literal lambda refuses earlier, `monomorphize: unsupported argument type`) · clause 2 · CAPABILITY: the same function without the type parameter, `f: () => i32[] | i32`, runs, and a `T[] | i32` parameter that is not a function's result runs · found closing [D9970](D9970.md), whose generic twin it is · present on master `2c4263380` · filed 2026-10-22 against master `2c4263380`**

Repro:

    function len<T>(f: () => T[] | i32) {
      const t = f()
      if t is i32 { t } else { t.length }
    }
    const g: () => i32[] | i32 = () => [1, 2]
    print(len(g))
    // vl check: rc 0.  vl run: emitProgram: '.length' on a receiver the emitter cannot classify as a list, string, map or set

Want:

    2

#### Mechanism

Not traced. At the `i32` pin the call `f()` yields the value union `i32[] | i32`, and the
complement of `is i32` is its list arm, but the emitter's receiver classifier finds no list
for that narrowed read in the instance. A parameter of type `T[] | i32` read the same way is
classified, so the miss is on the union that arrives as a function value's result, in a body
over the type parameter.
