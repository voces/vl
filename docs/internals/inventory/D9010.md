### D9010 — a re-pointed `let` of un-annotated functions stored in an un-annotated record field is refused at the call for want of a function-value signature

**closed · was an emit refusal, `vl check` rc 0, `a function-value call has no interned signature`, clause 2 · found closing [D9007](D9007.md) · present on master `464f33df4` · filed 2026-10-21 against master `464f33df4`**

Repro:

    function inc0(a) { return a + 1 }
    function dbl(a) { return a * 2 }
    let f = inc0
    f = dbl
    const b = { g: f }
    print(b.g(3))
    // runs, prints 6.  On master 464f33df4: vl check rc 0, then emit error: a function-value call has no interned signature

#### Mechanism

A record field's pin (`monoPinRecordField`, `emit_mono.vl`) took its function type from
the one instance the field's value names. A re-pointed `let` names none, so the field kept
the hole signature and the call through it had no parameter type. The field now takes the
result the binding's functions agree on at the pin's parameters (`monoValueAtAnnTy`), as a
list element already did. The matrix's `global_assign` cell was a second mechanism: a
write `b = a` whose right side is an alias of the re-pointed `let` instanced none of its
functions. `monoCoerceAliasOfWrittenLet` follows the never-written alias chain to the
`let` and coerces its values at the write's pin.
