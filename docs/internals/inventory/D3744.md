### D3744 — `??` directly over an index read of an un-annotated parameter pinned to `(i32 | null)[]` is refused at emit

**loud emit reject · clause 2 · pre-existing, the same on master `42c4d4c10` · found by lane UA grading D2218's element kinds · filed 2026-10-06 against master `42c4d4c10`**

Repro:

    function take(a) {
      print(a[1] ?? 0)
    }
    const l: (i32 | null)[] = [null, 4]
    take(l)
    // vl check: rc 0.  vl run: emitProgram: `??` over this nullable value is not supported
    // yet — narrow it first, e.g. `if v != null { … }`

#### Mechanism

Not traced to the line. The `??`'s left operand is an index read whose receiver is a hole
parameter, and the emitter's nullable-scalar `??` lowering does not recognise the `i32` niche
through the instance's pin, while it does once the read is bound to a local first. The
`string | null` element (a ref niche) runs at the same spelling, so the scalar niche is the
ingredient.

#### Ablation

| ingredient changed | outcome | needed? |
| --- | --- | --- |
| `a: (i32 \| null)[]` annotated | runs, prints `4` | **yes** — the hole parameter |
| the read bound first (`const e = a[1]; print(e ?? 0)`) | runs, prints `4` | **yes** — the fused read |
| element `string \| null`, default `"-"` | runs | **yes** — the scalar niche |
| the list an empty `[]` the body pushes `null` then `4` into (D2218's close) | refuses the same | no |
| a direct `const v = []` with the same pushes | runs, prints `4` | **yes** |
| element `f64 \| null`, default `0.5` | refuses the same | no |
| a declared generic `take<T>(a: T[])` | runs, prints `4` | **yes** — the un-annotated hole |

#### Grading list

* The `i64 | null` and `f32 | null` elements at the same spelling.
