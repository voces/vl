### D2450 — a closure reading a narrowed index cell of a value union is invalid wasm

**check-clean invalid wasm · clause 1 · filed 2026-09-25 against master `20651a88b`, found
grading #3150's generated grid · open**

Repro:

    function f(xs: (i32 | null)[]): i32 {
      if xs[0] != null {
        const c = (): i32 => xs[0] + 1
        return c()
      }
      0
    }
    print(f([4]))
    // vl check: rc 0.  vl run: invalid module inside `c`: expected i32, found (ref $type)

#### Mechanism

Not yet ablated to the rung. The checker reads `xs[0]` inside `c` at the narrowing live where
`c` is written; the emitter does not replay a literal-subscript cell key into the lifted body
(adding `xs[0]` to `capNarrowRecord`'s recorded keys alone does not change the module), so the
body reads the element box. A field path (`o.v`) in the same position runs.

#### Ablation

| ingredient removed | outcome | needed? |
| --- | --- | --- |
| the closure | runs | **yes** |
| the box (`(string \| null)[]`, `xs[0].length`) | runs | **yes** |
| the element type (`(f64 \| boolean)[]` with `is f64`) | invalid the same | no |
| the index for a field (`o.v`) | runs | **yes** |

#### Grading list

A lambda handed to `map` reading the cell. #3150 exposes more of it: a call to the closure no
longer ends the cell's narrowing when the closure's body writes nothing, so grid cells
`cell_010`, `cell_013` and `cell_036`, refused on master at that call, now reach this defect.
