Repro:

    function f(xs: (i32 | null)[]): i32 {
      if xs[0] != null {
        const c = (): i32 => xs[0] + 1
        return c()
      }
      0
    }
    print(f([4]))
    // vl check: rc 0.  vl run: prints 5

#### Mechanism

The checker reads `xs[0]` inside `c` at the narrowing live where `c` is written. The emitter's
replay (`capNarrowRecord` banks, `capNarrowSeed` replays) recorded only keys equal to a captured
name, plus the one special case of a shared cell's `c[0]`, so the key `xs[0]` was never banked
and never replayed, and the lifted body read the element box. Both halves had to move, which is
why adding `xs[0]` to the recorded keys alone changed nothing.

The fix banks every key whose root (`xs` of `xs[0]`, `o` of `o.v`) the nested body reads, and
replays a path key under a capture whole: the capture holds the same list or struct reference
the declaration site reads through. The shared-cell special case is now one instance of that rule.
