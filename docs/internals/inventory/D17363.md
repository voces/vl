### D17363 — a `let` copy of a copy of a record of un-annotated-function records, reassigned and then assigned back into its source, builds an invalid module

**check-clean invalid wasm · clause 1 · found by V9 verifying D17131 (#9927), owned by lane IR-M1 · filed 2026-11-24 against master `4e84ceccd`**

Repro:

    function inc0(a) { return a + 1 }
    function dbl(a) { return a * 2 }
    function mk(k: i32) {
      const v = { r: { f: inc0 }, s: { f: dbl } }
      let a = v
      let b = a
      if k > 0 { b = { r: { f: dbl }, s: { f: dbl } } }
      a = b
      return a
    }
    print(mk(0).r.f(3))
    print(mk(1).r.f(3))
    // vl check: rc 0.  vl run: invalid module in `mk`

Want:

    4
    6

#### Mechanism

D17131's close follows copies by their initialisers (`fnLetCopiesOf`: an un-annotated `let` whose
initialiser reads the binding). Here the copy `b` is also assigned back into its source (`a = b`),
an assignment edge that no initialiser names, so `b`'s writes reach `a` without widening `a`'s slots.
It is not D17360's or D17361's mechanism: those copies are refused at their initialiser (a field read,
a call); this one's initialisers are plain reads, and the missing edge is the assignment.
