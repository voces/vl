### D16014 — a ref-list row whose element holds a hole function is keyed by its name, because the hole is stored as tagged ids and no closed type spells that rep

**runs today and must keep running · carried past step 7 as a floor (coordinator, 2026-11-13) · 7 programs of the sweep population · filed 2026-11-13 against master `f11a3e113`**

Repro:

    function id1(a) { return a }
    const xs = [[{ f: id1 }]]
    print(xs[0][0].f(2))
    print(xs[0][0].f(2.5))

Want:

    2
    2.5

#### Mechanism

`rlInternNameTyK` keys a ref-list row by `repElemIdOfNameTy(name, ty)`. With no type (`ty` -1) it
resolves the row's name (`repElemTyOfName`), and it records the row's type from the name too
(`fieldElemTyIxOfName`, reaching `declTyIxOfName`). Every caller that holds the element's type
passes it through `rlKeyTyOf`, which declines a type holding a type variable. An un-annotated
function is a hole, `(_) => _`, and a record holding one is stored with the function as a tagged
id: the witness's inner row is named `{f:i32}` while its type is `{f: (_) => _}`. That name is the
spelling of the tagged rep, and no closed type of the element spells it, so the row is keyed and
typed by its name.

#### Ablation

| spelling | outcome |
| --- | --- |
| the witness | `collectAArrayLit`'s kind-9 inner row `{f:i32}` reaches the parse; runs `2`, `2.5` |
| `id1` annotated `(a: i32): i32` (one call kept) | the element type is closed; the parse is not reached |
| `type R5 = { f: (n: i32) => i32 }` beside `function mk() { const xs = [{ f: inc }]; return { a: xs } }`, `inc` un-annotated | the `#anon` row is declined its recorded type (`anonRowTyOfName`: a declaration names its layout) and reaches the parse; runs |
| the same without `type R5` | the `#anon` row is keyed by its recorded type; the parse is not reached; runs |
