### D3016 — a hole value at a `string | null` pin joined through an `if` or `match` value traps on `null`

**closed 2026-09-28 — the witness prints `null` · was loads then traps · clause 1 · `exprNullableString` and `ifLinkYieldsNull` read a hole instance's join at its pin (`holeOperandTyOf`), so the join keeps the niche bound, printed directly, returned or matched · 56 trapping cells of the 2,880-cell grid run, 0 lost · fixture `tests/cases/generics/hole-join-at-nullable-string-pin.vl` · filed 2026-09-28 against master `59cf3b639`**

Repro:

    function f(x) {
      const y = if x == x { x } else { x }
      print(y)
    }
    const v: string | null = null
    f(v)
    // vl check: rc 0.  vl run: wasm trap: null reference

Want:

    null

#### Mechanism

A hole instance shares its template's nodes, so the join's recorded type is the hole's variable,
and both questions that keep a `string | null` niche read the recorded type only:
`exprNullableString` (what a binding and `print` classify the join as) and `ifLinkYieldsNull`
(whether the `if` gets a nullable blocktype). Both answered no, the arms were cast non-null, and
a `null` trapped. Both now also read the join at the instance's pin (`holeOperandTyOf`). `match`
lowers through the same `if` chain.

#### Ablation

| ingredient changed | outcome | needed? |
| --- | --- | --- |
| `const y = x` | prints `null` | **yes** (the join) |
| `function f<T>(x: T)` | prints `null` | **yes** (the hole) |
| `"s"` in place of `null` | prints `s` | **yes** |
| `print(if … )` with no local | traps | no |
| an `i32 \| null` pin | prints `null` | **yes** (the string niche) |
| `match 1 { 1 => x, _ => x }` | traps | no (the same defect) |
