### D17074 — a binding of a record union narrows to the wider arm while its literal is built at the arm with a nullable literal set

**closed 2026-11-23 by lane S1 · now runs, `C` `true` · was check-clean silently wrong · `is` answers from the value where an arm's field shares values with the tested arm's (D4056 is structural): `tyTestMemberFit` answers partly for such a record, and the emitter writes the field test it needs · pin: `tests/cases/unions/is-overlapping-record-arm-after-narrowing.vl` · filed 2026-11-23 against master `e6cb8541` (IR-N5)**

Repro:

    type C = { v: "a" | "b" | null }
    type D = { v: string }
    function g(u: C | D) { if u is C { return "C" } return "D" }
    let w: C | D = { v: "b" }
    print(g(w))
    print(w is C)
    // vl check: rc 0, warns "`is` check type 'C' can never match a value of type D"
    // vl run: prints C, then false

Want:

    C
    true

#### Mechanism

The literal `{ v: "b" }` is built at `C`, the arm its field value fits by value (D4056), so the
value carries `C`'s tag and `g` tests it as `C`. The checker narrows the binding `w` to `D`
instead, then folds `w is C` to `false` with a warning. The static narrowing and the runtime tag
disagree. By D4056 `is` is structural, so neither arm is the one to pick: `{ v: "b" }` fits both,
and `w is C` must test the value. The fault was `tyTestMemberFit(D, C)` answering none because
`C` is not assignable to `D`, though `D` values whose field is `"a"` or `"b"` fit `C`
(`recArmFitKind` 2). Answering partly sends the test to the emitter, which then needed the field
test for a literal-set field against a wider one and for a numeric literal member of a boxed field.

#### Ablation

| ingredient removed | outcome | needed? |
| --- | --- | --- |
| the reassignment (literal in the initializer) | still `C` / `false` | no |
| a module global (a local binding instead) | still `C` / `false` | no |
| a literal only `D` can take (`{ v: "zz" }`) | `D` / `false`, correct | **yes** |
| `| null` in `C`'s literal set | `C` / `true`, correct | **yes** |
