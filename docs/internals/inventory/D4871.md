### D4871 — a fresh nested list literal under a spread is not built at an annotated destination's element type

**loud check reject · clause 2 · found grading D4861's `nested-list-widen-fresh` matrix, where every annotated cell refuses and the un-annotated twin runs · filed 2026-10-15 against master `0a7e96cce`**

Repro:

    const v: f64[][] = [...[[1, 2]]]
    print(v[0][1] / 4.0)
    // vl check: rc 1, i32[] is not f64[] (reached through i32[][] into f64[][]): a container never widens implicitly

Want:

    0.5

#### Mechanism

Not yet ablated past the table. The spread operand is a list literal, so nothing exists to be
copied, but it is typed `i32[][]` on its own instead of from the destination, and the delivery
rule then refuses the inner level. One level down it runs (`const v: f64[] = [...[1, 2]]`), and
without the annotation (`[...nf, ...[[1, 2]]]` beside an `f64[][]`) the same literal is built at
`f64[]` and runs. With a second spread of an `f64[][]` binding the message reads `reached
through f64[][] into f64[][]`, naming no type that differs.

#### Ablation

| ingredient removed | outcome | needed? |
| --- | --- | --- |
| the nesting (`const v: f64[] = [...[1, 2]]`) | runs | **yes** |
| the annotation (beside an `f64[][]` spread) | runs | **yes** |
| the spread (`const v: f64[][] = [[1, 2]]`) | runs | **yes** |
