### D9651 — a generic stored by `.set` through an un-annotated map parameter, then overwritten at module level with a fixed-type function, reaches no call that fixes its type

**loud emit reject · `vl check` rc 0 · `a generic function taken as a value reaches no call that fixes its type` · clause 2 · found closing [D9591](D9591.md) · present on master `92d03ef36` · filed 2026-10-22 against master `92d03ef36`**

    function id<T>(x: T): T { x }

#### Mechanism

Not traced. From the ablation only: with both stores at module level the map's value slot is
typed at `inc`'s type and `id` is instanced there. Through `fill`, [D9591](D9591.md)'s close
flows `id` into the map's slot, but the slot's pin from `inc` does not reach the read of `id`
inside `fill`'s body, so that read is neither instanced at the pin nor noted inert.

#### Grading list

The indexed spelling (`mm["k"] = id` and `m["k"] = inc`), and the same lines in `main()`.
The overwrite with a second generic (`function dbl<T>(x: T): T { x + x }`, `m.set("k", dbl)`,
then `r(2)` and `r("s")`) refuses as `callee is not a function name` on master `92d03ef36` and
after the [D9591](D9591.md) close alike; with both `.set`s at module level it refuses as
`unsupported map value type`.
