### D9853 — a written `let` holding a generic, called twice at one type with two different lambdas, takes one instance per lambda and refuses

**loud emit reject · `vl check` rc 0 · `emitProgram: the reassigned function binding `v` is called at more than one argument type — …` · clause 2 · found closing [D9851](D9851.md) · present on master `f6475d442` with the `holds functions called` wording · filed 2026-10-22 against master `f6475d442`**

Repro:

    function g<T>(f: (x: T) => T, x: T): T { f(x) }
    function __la() {
      let v = g
      v = g
      print(v((x: i32) => x + 1, 2) * 10 + v((x: i32) => x, 5))
    }
    __la()
    // vl check rc 0.  vl run: emit error: emitProgram: the reassigned function binding `v` is called at more than one argument type — one binding holds one closure signature, and the values written to it want two. Annotate the parameters, or bind a separate value per type

#### Mechanism

Not traced to the line. Both calls pass `(i32) => i32`, so they share one argument type. The
refusal is the written-binding guard in `monoMakeInstanceLater` (emit_mono.vl, the arm that
builds `what` and `wants`). That guard fires when a call through a written binding makes a
second instance. One `const f1` passed to both calls runs, so the second instance comes from
the second, different lambda. A lambda argument specialises `g` per callback, and the binding
can hold only one. Whether the fix belongs at that per-callback instance or in fn_split's
instance record (`fsAsk`) is not measured.
