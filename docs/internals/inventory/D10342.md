#### Mechanism

A read past the literal's elements is rewritten only through
`monoFlowKeptIndexElem` (emit_mono.vl), which requires the call to be one
`monoFlowCallStmtOf` places; `monoFlowRunsFirstIn` let only a name or literal run before the
call and refused a `.length` parent, so the element kept the list's one slot at two types.
The bound spelling (`const s = ws[1]("abc")`, then `s.length * 100 + ws[1](7)`) failed at the
second read for the same reason: its left operand `s.length` was not a name or literal.
