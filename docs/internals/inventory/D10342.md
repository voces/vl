### D10342 — a call through a pushed element of a list of a generic refuses unless it is a statement's own call

**loud emit reject · `vl check` rc 0 · `'.length' on a receiver the emitter cannot classify as a list, string, map or set` · clause 2 · CAPABILITY: the two calls as `print` arguments of their own print `abc`, `7`; the element read at index `0` prints `307` · found closing [D10300](D10300.md) · present on master `e811cd6da` · filed 2026-10-22 against master `e811cd6da`**

Repro:

    function id<T>(x: T): T { x }
    const ws = [id]
    ws.push(id)
    print(ws[1]("abc").length * 100 + ws[1](7))
    // vl check rc 0.  vl run: emit error: emitProgram: '.length' on a receiver the emitter cannot classify as a list, string, map or set

Want:

    307

#### Mechanism

Not traced. A read past the literal's elements is rewritten only through
`monoFlowKeptIndexElem` (emit_mono.vl), which requires the call to be one
`monoFlowCallStmtOf` places; this spelling's calls are operands, so the element keeps the
list's one slot at two types. Bound instead (`const s = ws[1]("abc")`) the refusal is the
call-site one, `a function value's signature is not known at this call`, which a binding
init's call should not meet, so the placement is not the whole story.
