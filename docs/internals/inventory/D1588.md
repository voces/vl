### D1588 — a constant range whose direction contradicts its step runs zero times in silence; the checker never folded the descriptor it already requires to be constant

**fixed — now a loud check reject at the `to` token, on the coded `range-never-runs`
channel · was `runs`: zero iterations, no diagnostic, exit 0 · a deliberate
`runs → not-runs`, confined to a range whose bounds AND step are all compile-time integer
literals · distilled corpus 0 classes moved, 0 `runs → not-runs`, 0 `→ silent` · reported
by glean as VL-038 · filed 2026-09-04 against master `2e5cfb21`**

Reported by the language's first external consumer: `~/glean/docs/vl-issues.md` §VL-038,

    let down = 0
    for i in 3 to 0 { down += 1 }
    let up = 0
    for i in 0 to 3 { up += 1 }
    print(`\{down} \{up}`)

    // NOW: 2:11: this range never runs: `3 to 0` counts up (step 1) from a start above
    //      its end — write `3 to 0 step -1` to count down, or swap the bounds

#### Mechanism

**THE DESCRIPTOR WAS ALREADY REQUIRED TO BE CONSTANT, AND NOBODY LOOKED AT IT.** A range
`for` lowers to one `(from, inclusive-to, const-step)` descriptor (DECISIONS B6b), and the
emitter FOLDS the step at emit time — `emitProgram: for-range step must be a constant
integer` refuses anything but a `NumLit` or a unary minus over one, and it then picks
`i32.le_s` or `i32.ge_s` from the step's sign. So the direction of every range in the
language is decided at compile time. The checker asked only one question of that fold: `if
stepNode is NumLit { if stepNode.numText == "0" }`. The bounds were never read at all, so
`3 to 0` emitted a loop whose FIRST continue-test (`3 <= 0`) is false, exited immediately,
and said nothing — a correct lowering of a descriptor nothing had graded.

The fix reads the same three nodes the emitter does. `constIntExprIs` / `constIntExprVal`
fold an integer literal, a unary `+`/`-` over one, or either in parens (a `const` binding
is NOT folded — see the grid); `checkRangeNeverRuns` refuses `from > to` with a positive or
defaulted step, `from < to` with a negative one, and any step of 0. The anchor is the soft
`to` keyword, recovered from the end bound's own start token the way `exportPrefix`
recovers the dropped `export` — and VERIFIED at the token, so a stream the arena disagrees
with falls back to the bound's anchor rather than pointing at something unidentified.

**THE RUNTIME IS UNTOUCHED, DELIBERATELY.** A non-constant wrong-order range still runs
zero times and still says nothing. `for i in lo to hi` with `hi < lo` is how a
possibly-empty span is spelled, and both alternatives — a trap, or a refusal that cannot
be stated because the bounds are unknown — break that idiom. Only what is knowable is
refused. DECISIONS.md §"A CONSTANT range that cannot run is refused" carries the ruling,
including why this is an ERROR and not the warning the retired TS core raised.

#### Ablation

| ingredient removed | outcome | needed? |
| --- | --- | --- |
| the `from > to` order (`0 to 3`) | runs, 4 iterations | **yes** |
| the bounds being LITERALS (`let lo = 3; let hi = 0`) | runs 0 times, silent — unchanged | **yes** |
| the bounds being literals, spelled `const` instead of `let` | runs 0 times, silent — unchanged | **yes** |
| the defaulted step (`3 to 0 step 1` written out) | refused, same sentence | no |
| the negative sign (`-1 to -5` vs `1 to 5`) | refused either way when out of order | no |
| the parens (`(3) to (0)`) | refused, same sentence | no |
| module scope (the same loop inside a function) | refused, same sentence | no |
| a non-zero step (`0 to 3 step 0`) | refused — the zero-step arm, its own sentence | no |

**The `const` row is the deliberate gap, not an oversight.** The checker keeps no
constant-VALUE scope — `constScopes` records which names are `const`, not what they hold —
so `const hi = 0` is an `Ident` to this fold and its range still runs zero times silently.
Building a folder for one rule would give the checker a notion of "constant" wider than the
emitter's, with nothing else reading it; DECISIONS records that as a later, separate call.

**Both faces, and only one exists.** The grammar allows no annotation on a range's loop
variable (`parseFor` reads an `IDENT` and then the soft `in`), so there is no annotated
spelling of this loop to grade. The annotated/un-annotated split that D1588's siblings turn
on does not arise here; the two spellings that DO exist — a defaulted step and a written
one — are both in the grid above and both refuse.
