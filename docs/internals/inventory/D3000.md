### D3000 — a declared record delivered as a declared record whose field is wider builds invalid wasm

**closed by design · now a loud check reject · was check-clean invalid wasm · the owner's record-covariance ruling refuses it: an annotated record is not fresh, and `i32` against `i64` is stored apart · closed 2026-09-30**

Repro:

    type RS = { f: i32 }
    type RD = { f: i64 }
    const rs: RS = { f: 7 }
    const rd: RD = rs
    print(rd.f + 1)
    // vl check: rc 0.  vl run: invalid module, type mismatch

#### Mechanism

Not localised. The checker accepts `RS` where `RD` is wanted, since `i32` widens to `i64`, and the
emitter passes the `RS` struct where an `RD` struct is typed: two heap types, so the module fails
validation. A record is shared, not rebuilt, so the design question is D2100's (a record's field
cannot change type in place): whether the delivery owes a refusal, as a list field's does, or a
converting copy.

#### Ablation

| ingredient changed | outcome | needed? |
| --- | --- | --- |
| `RD = { f: i32 }` | runs, prints `8` | **yes** |
| a literal `const rd: RD = { f: x }` over `x: i32` | runs, prints `8` | **yes** |
| an argument `g(rs)` into `d: RD` | invalid wasm | no |
| `{ f: string \| i32 }` into `{ f: string \| i64 }` | invalid wasm | no |

#### Grading list

The `{ f: string | i32 }` into `{ f: string | i64 }` twin (the #3252 review's `a1.vl`), the
argument, return and field positions, and a readonly consumer of the field.

#### Close (2026-09-30)

Closed by the owner's record-covariance ruling (DECISIONS.md "Record covariance: only a fresh value widens"): an annotated record is not fresh, and `i32` against `i64` is stored apart. The refusal names both fixes, building the source at the wider record or copying it with an object literal, so no program the design permits is refused.
