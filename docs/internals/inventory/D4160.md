### D4160 — an inferred return of a single-literal nullable `"a" | null` is floored by the checker, though a two-member `"a" | "b" | null` and the annotated return run

**loud check reject · clause 2 · pre-existing, the same on master `a3ffa5ad2` · found by the D3423 position matrix (`pm_LN_*_retU_hole_*`, 18 cells) · filed 2026-10-11 against master `a3ffa5ad2`**

Repro:

    function f(b: boolean) {
      let s: "a" | null = null
      if b { s = "a" }
      return s
    }
    print(f(false) ?? "n")
    // vl check: 'f' infers the nullable return type "a" | null — type-valid, but an inferred
    // return of this shape is not yet supported by codegen; annotate the return type

Want:

    n

#### Mechanism

The nullable arm of the inferred-return floor in `typecheck.vl` admits a `K | null` whose inner is
a literal UNION; a single string literal `"a"` is a `TyLit`, not a union, so the floor fires. The
same family as [D2568](D2568.md) (a numeric literal union), at the one-member string spelling.

#### Ablation

| ingredient changed | outcome | needed? |
| --- | --- | --- |
| `let s: "a" \| "b" \| null` | runs, prints `n` | **yes** (one literal) |
| `function f(b: boolean): "a" \| null` | runs, prints `n` | **yes** (an inferred return) |
