### D3875 — un-annotated callbacks over `Box<A[]>` and over an inline `{ v: A }` in one program refuse to build, though each alone runs

**closed 2026-10-09 by lane SC · runs · was a loud emit reject · found extending D3834's fixture under the structural ruling · filed 2026-10-08 against #3464's head `441218435` with #3455's rework · pins: `tests/cases/generics/callback-pin-inline-record-beside-generic-list.vl`**

Repro:

    type A = { x: i32 }
    function h<T>(x: T) { x.x }
    type Box<T> = { v: T }
    const ba: Box<A[]> = { v: [{ x: 1 }] }
    print([ba].map((e) => h(e.v[0]))[0])
    const o: { v: A } = { v: { x: 1 } }
    print([o].map((e) => h(e.v))[0])
    // vl check: rc 0.  vl build: emitProgram: field access receiver is not a struct

Want:

    1
    1

#### Mechanism

A built-in callback over an inline record is pinned at its render (`{v:{x:i32}}`), but the inline
record's struct row is interned under the spelling that keeps its fields' declared names
(`{v:A}`). Alone, the callback's `e.v` reaches `h` at a pin the cascade still lowers. With the
`Box<A[]>` callback in the program, `e.v` read through the render matches no row, and `h` is
instanced at `i32`. Closed by `monoLamPinName` spelling an inline record the way its row is
interned, when that row exists.
