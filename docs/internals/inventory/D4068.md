### D4068 — `vl check --severity info` fails a file whose summary says "no errors" and names no failing severity

**open · wrong summary (no outcome word fits: `vl check` rc 0 and the program runs, so it grades as runs today and must keep running) · found writing `docs/spec/diagnostics.md` (lane SPEC) · filed 2026-10-11 against master `98a4ed71b`**

Repro:

    let x = 3
    print(x)
    // vl check --severity info: rc 1, one [INFO] prefer-const, summary
    //   "Checked 1 file, no errors." with no "(failing at severity info)".
    // vl check --severity warning on a file with one warning prints
    //   "Found 0 errors, 1 warning. (failing at severity warning)".

Want:

    3

#### Mechanism

`--severity <s>` sets both the display floor and the exit gate, and the gate is honoured
at every level. The summary line in `compiler/cli.vl` counts only errors and warnings, and
adds the "(failing at severity …)" note only when one of those two counts is non-zero. At
`info` or `hint` the file fails on a finding the summary does not count, so the summary
reads as a pass while the exit code is 1. The witness program itself runs; the filed
defect is the CLI's summary under the flag, which the witness grader cannot pass.

#### Ablation

| variant | rc | summary |
| --- | --- | --- |
| `--severity info` | 1 | Checked 1 file, no errors. |
| `--severity hint` | 1 | Checked 1 file, no errors. |
| no flag | 0 | Checked 1 file, no errors. |
| `--severity warning` | 0 | Checked 1 file, no errors. (the info is not shown) |

#### Grading list

At `info` and `hint`, the summary counts the findings at or above the gate and carries the
same "(failing at severity …)" note as the warning gate. `docs/spec/diagnostics.md` §D4.
