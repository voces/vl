### D16217 — a compound write used as a value, whose place's index or receiver has an effect, runs that effect twice

**open · loud emit reject · `emitProgram: a compound write (`++p`, `p++`, `p op= v`) used as a value reads and writes a place whose receiver or index has an effect, which would run twice; write it as its own statement` · clause 2 · was check-clean wrong evaluation on master for `++p` and `p op= v` · found by lane I closing D4055 · filed 2026-11-14 against master `685b59c13`**

Repro:

    let calls = 0
    function k(): i32 {
      calls = calls + 1
      0
    }
    const xs = [1, 2]
    print(++xs[k()])
    print(calls)
    // was, vl run: 2 then 2. Now: the emit reject above.

Want:

    2
    1

#### Mechanism

A compound write reads and writes its place through one target node. As a statement,
`spillCompoundPlace` (`emit_rewrite.vl`) spills a receiver or index that is not re-readable
ahead of it, so it runs once. As a value nothing spills it, and the place ran twice: a silently
wrong count. `drwCompoundValueRunsTwice` now refuses that case. Spilling it in place needs an
expression-level temporary that keeps the sibling operands' order.

#### Ablation

| spelling | before | after |
| --- | --- | --- |
| the witness, `++xs[k()]` as a value | check-clean wrong evaluation (`calls` 2) | loud emit reject |
| `(xs[k()] += 1)` as a value | check-clean wrong evaluation | loud emit reject |
| `print(xs[k()]++)` | parse error | loud emit reject |
| `xs[k()]++` or `++xs[k()]` as a statement | runs, `calls` 1 | runs, `calls` 1 |
| `print(xs[0]++)`, a re-readable place | parse error | runs |
