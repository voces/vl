### D1632 — an ANNOTATED rebind of a narrowed struct-valued map read, then captured, is check-clean invalid wasm

**check-clean invalid wasm · 3 cells of the `d1476` matrix's `map_value` position · filed 2026-09-05 against master `47b3a6ac`**

#### Mechanism

A struct-valued map read is `V | null`, and the narrowing proves it non-null for the branch.
Re-binding it there with an ANNOTATION types the new cell from the annotation — the bare
`(ref $S)` — while the value arriving is still the map read's `(ref null $S)`, and the capture
of that cell then declares one and stores the other.

**The annotation is what breaks it, which is the exact mirror of D1476**, where an
un-annotated capture is the broken one and annotating is the whole fix. The pair is worth
keeping together: they are the same seam read from opposite ends, and a fix for either that
assumes "the annotation is always the safe spelling" would break the other.

Found by `scripts/capability-probes/matrix/inferred-projection-capture.matrix.vl`'s
`map_value` position while closing D1476. It is SILENT in BOTH of that matrix's columns, at
the same byte offset, so it is nobody's regression.

#### Ablation

Every row is `vl check` rc 0, and every row behaves identically on master and on D1476's
candidate — this row is untouched by that fix.

| spelling | outcome |
| --- | --- |

| the same inside a function rather than at module scope | **invalid wasm** |
| the rebind UN-annotated (`const v = mv`) | runs, 3 |

Needed: the map read AND the narrowing AND the ANNOTATED rebind AND the capture. Not needed:
the projection that produced the stored value, or the scope — a literal value and a function
body both refuse.
