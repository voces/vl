### D1632 — an ANNOTATED rebind of a narrowed struct-valued map read, then captured, is check-clean invalid wasm

**closed · filed 2026-09-05 against master `47b3a6ac` · closed against `e2781fa0`**

`captureValKind`'s annotated arm now matches the LOCAL's own cell rather than re-deriving
from the annotation. The module-scope spellings run and the `map_value` matrix position is
un-skipped; the FRAME-scoped spelling is filed as D1633.

Repro:

    const m: { [string]: { name: string, n: i32 } } = Map()
    m["k"] = { name: "ada", n: 3 }
    const mv = m["k"]
    if mv != null {
      const v: { name: string, n: i32 } = mv
      const g = () => v
      print(g().n)
    }
    // vl check: rc 0.  vl run: the emitted module failed to validate inside the module start

#### Mechanism

A struct-valued map read is `V | null`, and the narrowing proves it non-null for the branch.
Re-binding it there with an ANNOTATION types the ENV FIELD from the annotation — the bare
`(ref $S)` — while the local it captures keeps the map read's `(ref null $S)`, so the capture
declares one and stores the other.

MEASURED, and the first two probes were both wrong about where. The binding's own recover site
(`nulNicheRecoverOwed` at `emitLetDeclStmt`) never fires for this shape, and instrumenting the
binding shows why:

    D1632LET name=v slotKind=nulstruct annotated=T recoverOwed=F   (the witness)
    D1632LET name=v slotKind=nulstruct annotated=F recoverOwed=F   (the un-annotated control)

**The LOCAL is `nulstruct` in BOTH** — the annotation does not make the cell non-null, and the
recover is rightly not owed because the destination IS the niche. So the disagreement is one
hop later: `captureValKind`'s annotated arm returns `vtKindOfType(bn.letType)` — `struct` —
while the local it reads is `nulstruct`. The env field is the only place the two meet.

**And the ARENA is the wrong oracle here, which is this row's own lesson turned on me.** A
candidate that asked `nodeTyIsNullable(bn.letInit)` instead put the witness straight back to
invalid wasm: the checker records the NARROWED type, so the arena says non-null exactly where
the rep is not. Narrowing is type-level and the cell is not — the same sentence the mechanism
opens with, and the reason the fix compares against `letInitCellKind` rather than the arena.

**The annotation is what breaks it, which is the exact mirror of D1476**, where an
un-annotated capture is the broken one and annotating is the whole fix. The pair is worth
keeping together: they are the same seam read from opposite ends, and a fix for either that
assumes "the annotation is always the safe spelling" would break the other.

Found by `scripts/capability-probes/matrix/inferred-projection-capture.matrix.vl`'s
`map_value` position while closing D1476. It is SILENT in BOTH of that matrix's columns, at
the same byte offset, so it is nobody's regression.
