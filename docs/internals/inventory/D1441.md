### D1441 — the redundant-RETURN-annotation span scanned forward for a depth-0 colon, and a type-parameter BOUND's colon is one: `--fix` wrote `function describe<T {`

**closed 2026-09-03 by finding the colon BACKWARD from the body `{` instead · was a `--fix`
rewrite that does not parse (the program before and after the hint both run; the compiler's own
autofix wrote the broken source) · 7 edits over 6 corpus files, all in `constraints/` and
`generics/` · found by the D1091 corpus sweep, which graded them `runs -> not-runs` with a
PARSE error**

Repro — the program `--fix` now writes when it takes the hint on `describe`'s `: string`
(before the fix it wrote `function describe<T { "<" + x.toString() + ">" }`, which is not a
program):

    type Circle = { r: f64 }
    type Showable = { toString(): string }
    function toString(self: Circle) {
      if self.r > 0.0 { return "C" }
      "c"
    }
    function describe<T: Showable>(x: T) { "<" + x.toString() + ">" }
    print(describe({ r: 1.0 }))

#### Mechanism

`recordRedundantRet` found the return annotation's colon by scanning FORWARD from the function
name for the first `COLON` at bracket depth 0. `<` and `>` are not brackets and cannot be
counted as any — `=>` lexes as `EQUAL` + `GT`, so a `<`/`>` depth counter unbalances on every
function-typed return — so the bound's colon in `<T: Showable>` is at depth 0 and won. The
span then ran from THAT colon to the body `{`, deleting `: Showable>(x: T): string`.

The guard that was supposed to keep generics out (`return 0` when any parameter is
un-annotated) does not fire here: `x: T` is annotated. Scanning BACKWARD from the body brace
needs no such guard — the return's colon is the first depth-0 one going that way, and a colon
inside the return type (`: {a: i32}`, `: (i32) => i32`) is at depth >= 1 in either direction.

The annotation is NOT load-bearing at these sites: with the span correct, all six files run.
