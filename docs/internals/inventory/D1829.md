Repro:

    const xs: (i32 | null)[] = [7, null]

    //   expected (ref $type), found (ref null $type). Now prints 7.

#### Mechanism

Three arms could have claimed it and the wrong one did. The fused scalar-list `.get ?? d` arm
declines — a probe on the failing witness reads `f64arr=0 arr=0 refarr=1`, since a
nullable-element list is a REF list of boxes. The element arm D1828 built declines too, but
only because its bound is a syntactic one: a `.get` is a `Call`, not an `Index`. What claims
it is the call-stash arm (`lhs is Call`), which exists for a call RETURNING a value union and
lowers through `emitUnionCoerce` — over an element read that leaves `(ref null $box)`, its
block type wants the non-null ref and the module fails to validate.

The element arm now sits AHEAD of the call-stash arm and its bound reads "an index read OR a
list `.get` call", so the `.get` spelling of an element read is claimed by the arm that asks
about the element's rep. D1411's bound is unchanged and load-bearing: a struct FIELD is
neither, so its witness keeps the loud refusal it was filed with.

The `.get` half needs one thing the subscript does not. It is the CHECKED read, so an
out-of-range index yields NO box — a second null channel. The present-test short-circuits on
`ref.is_null` before reading the tag, and only for this spelling; the subscript traps out of
range and keeps its one-test shape, byte for byte.
