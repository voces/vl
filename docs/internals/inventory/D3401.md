### D3401 — a record a function with no declared result builds, whose union field the destination stores as another union, is delivered with no conversion

**closed · now runs, prints `3` · was check-clean invalid wasm, clause 1 · found grading D3011's function face · filed 2026-09-30 against master `8df60e472` · closed 2026-11-01 against master `7feb67ca`: the record solve built `mk`'s literal at `D`, and the emitter's result pin named the checked type, so the body built one row and the signature declared its same-layout twin; a function whose returned literals the solve built at one other record now keeps its inferred result, which names that row (`fnRetBuiltRecord`, emit_rewrite.vl) · fixture `soundness/record-call-built-at-destination-union-field-runs.vl` · the merging face is [D14891](D14891.md)**

Repro:

    type D = { v: f64 | string }
    const x: i32 | string = 3
    function mk() { return { v: x } }
    const o = mk()
    const d: D = o
    print(d.v)

Want:

    3

#### Mechanism

Measured at the close: the solve builds the literal at `D` with the field converted, but
`synthNulListRetAnns` pins any record result with a union field (`tyIsJoinedRecord`) to the
checked type, whose row stores alike under another name. The prediction below was the filing's.

A prediction. #3312 never adopts a function's result, so the record `mk` builds keeps its own
row (`{v: i32 | string}`) and the delivery at `D` keeps master's behaviour, which for a union
field stored as another union box is no conversion at all: the `{v: i32 | string}` reference
is handed to a `D` slot. `recFloatBuiltElsewhere` refuses the bare-float field form of the same
delivery, and `recNumChanges` answers `false` for a union field, so nothing refuses this one.
The declared-result twin (`function mk(): S`) is refused as an existing record, which is the
direct spelling's answer this row owes too, or a converting build at the destination.
