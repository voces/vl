### D9662 — a local bound to a nested list of un-annotated functions, returned from a function with an un-annotated parameter, traps the compiler

**compiler trap · `vl check` rc 0 · `out of bounds array access` in `mAssignRefListPairs` (emit_collect.vl), from `mAssignTypeIndices` · clause 1 · found closing [D9553](D9553.md) · present on master `abe12f20f` · filed 2026-10-22 against master `abe12f20f`**

Repro:

    function inc(a) { return a + 1 }
    function deliver(n) {
      const u = [[inc]]
      return u
    }
    const v = deliver(1)
    print(v[0][0](3))
    // vl check rc 0.  vl run: the compiler itself trapped, out of bounds array access

Want:

    4

#### Mechanism

Not traced. A seed built with `--names` puts the trap in `mAssignRefListPairs` (emit_collect.vl),
called from `mAssignTypeIndices` and `emitModule`. That loop indexes the per-slot ref-list tables
(`rlTwin`, `rlBackIdx`, `rlElemKindTbl`) for every slot below `rlElemName.length`, so here one of
them is shorter than the slot list. Which table it is, and which slot outran it, is not traced.

#### Ablation

| ingredient removed | outcome | needed? |
| --- | --- | --- |
| the parameter (`deliver()`) | runs, `4` | **yes** |
| the un-annotated parameter of `inc` (`inc(a: i32)`) | runs, `4` | **yes** |
| the local (`return [[inc]]`) | runs, `4` | **yes** |
| the binding (`print(deliver(1)[0][0](3))`) | same trap | no |
| the inline inner literal, bound first (`const w = [inc]`, `const u = [w]`) | same trap | no |
