### D16993 — a read-only empty list read into a typed destination takes the unbound default at its declaration, before the read

**closed 2026-11-18 — the witness prints `0` · was a loud check reject (`cannot assign i32 to 's' of type string`), clause 2 · census rows 7 and 9 of the no-default ruling (DECISIONS.md §"No default type") · the declaration-time default (`defaultReadOnlyContainer`) steps aside when a read of the binding's elements, or a loop over it, is delivered to a typed destination (`cwBindingReadTyped`, `check_write_scan.vl`): an element read pins the list there (`pinOpenReadFromDest`), and a loop pins it at entry from the annotated `let` its variable is read into (`forInPinFromTypedRead`, `pinOpenRowFromDest`) · fixture `tests/cases/inference/read-only-empty-list-fixed-by-a-typed-read.vl`, with `error-read-only-empty-list-read-two-ways.vl` · filed 2026-11-18 against master `e7861b6fd` by lane F1**

#### Mechanism

A binding nothing but reads ever uses (`cwBindingOnlyRead`) took the unbound default `i32` at its
declaration, so each later read is checked at it; a read into a `string` was then refused. Under
the ruling the typed read is the use that fixes the element.
