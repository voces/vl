### D14883 — one lambda handed through an identity to two hole functions, one calling it through an alias at two types and one handing the alias on, has no single rep

**loud emit reject · `vl check` rc 0 · clause 2 · `emitProgram: monomorphize: unsupported argument type for f in a call to fw` · pre-existing, the same on master `443394d44` · found by the rung B slice 3 controls · filed 2026-11-01 against master `443394d44`**

Repro:

    function fw(f) { return f }
    const lam = (x) => x
    function g(h) { return 0 }
    function keep(a) {
      const v = a
      print(g(v))
      print(v(4))
    }
    function take(a) {
      const v = a
      print(v(3))
      print(v("w"))
    }
    take(fw(lam))
    keep(fw(lam))

Want:

    3
    w
    0
    4

#### Mechanism

`take` only calls its parameter, through a `const` alias, at `i32` and `string`, so it needs
`lam`'s two instances by id. `keep` hands its alias on to `g`, which needs a closure. One set has
one rep, so the two calls of `fw(lam)` cannot both be served, and mono's flow pin has no single
type to give `fw`.

#### Ablation

| ingredient changed | outcome | needed? |
| --- | --- | --- |
| drop `print(v("w"))` | runs | **yes** (two types through the alias) |
| `take` and `keep` call `a` directly, no alias | runs | **yes** (the alias) |
| drop `keep` and its call | runs since the hand-on-through-alias change; refused on master | **yes** (the hand-on beside it) |
