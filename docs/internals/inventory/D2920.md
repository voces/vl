### D2920 — a list literal of a hole-typed record at a record pin refuses as a struct array

**closed 2026-10-25 by PR #4757 · runs, prints `3` · built, not refused: the array-literal classifiers read the instance's banked type of the literal where it is a ref list the template's is not (`arrLitFrameRefTy`, emit_classify.vl), the same rung that closed [D10891](D10891.md); the `ret`, `cap`, push, `==`, the #3285 `b8` and the #3306 `u(q)` cells all run · pins: `tests/cases/generics/hole-list-literal-of-anonymous-record-pin.vl` · was loud emit reject, `struct array elements are not supported` (`ref valtype with no interned shape` at the `cap` face) · clause 2 · 11 `rec` cells of the lane TR grid (`lit__*__rec`, `direct__elem__rec`, `direct__push__rec`) · the same on master `7ac32ffce` · filed 2026-09-27 against master `0284dc2a8`**

Repro:

    function h(x) {
      const xs = [x]
      print(xs[0].a)
    }
    const v: { a: i32, b: string } = { a: 3, b: "r" }
    h(v)
    // vl check: rc 0.  vl run: emitProgram: struct array elements are not supported

Want:

    3

#### Mechanism

Localised by the close: the instance banks the literal as a list of the record, which the
classifiers now read (D10891). Before it, the classifiers read only the template's type, whose
element is the hole's variable, so the list had no row for the record the pin names. [D2899](D2899.md) and
[D2898](D2898.md) close the nullable, union and list elements by annotating the local at the
instance's list (`monoHoleListLitAnn`) and, for a nullable, re-making the literal at that type.
Taking a record element through the same rung ran the element, bind, push, `==` and generic
cells, but moved `lit__ret__rec` and `lit__cap__rec` from this refusal to check-clean invalid
wasm, so it was pulled.

#### Ablation

| ingredient changed | outcome | needed? |

| `h<T>(x: T)` returning `xs` | runs, `3` | **yes** (the hole) |
| a declared `type R` for the pin | still refuses | no |
