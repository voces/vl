#### Mechanism

The write `r.f = dbl` lands in the map's value record through a narrowed binding of a map read,
at the place `m` / `[]` / `f`. A call reaches a slot through `cwSlotPath`, which treats a `for`
loop's element variable as an element of what the loop walks. `cwForInBinderOf` named only a
loop's first variable, which for a map is the key. So `e` in `for k, e in m` was a root of its own,
and `e.f(3)` pinned nothing at the map's value slot. A key read (`m[k]`) goes through `Index` and
did reach it. The second variable of a map walk is now its value. A list walk's second variable
is its index and stays a root.
