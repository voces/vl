### D10402 — a generic read out of an un-annotated `Map()` and handed to a generic whose result is member-read checks a later direct call of the generic at that member read

**loud check reject · `member access '.length' on non-object i32 (the body of `id` at the call's argument types)` · clause 2 · CAPABILITY: `run(id, "ab").length` handed `id` directly prints `2` beside `id(2)`, and the map read handed on without the `.length` prints `ab`, `2` · found closing [D10383](D10383.md), writing its fixture · present on master `949a71aa4` · filed 2026-10-22 against master `949a71aa4`**

Repro:

    function id<T>(x: T): T { x }
    function run<U>(f: (x: U) => U, u: U): U { f(u) }
    const m = Map()
    m["k"] = id
    const mv = m["k"]
    if mv != null { print(run(mv, "ab").length) }
    print(id(2))
    // vl check: member access '.length' on non-object i32 (the body of `id` at the call's argument types)

Want:

    2
    2

#### Mechanism

Not traced. The refusal is the checker's, so no emit change reaches it: the direct call
`id(2)` is checked with the `.length` read that follows the handed map read, as though the
map's value slot and `id`'s own body were one function checked at the call's types.

#### Ablation

| ingredient removed | outcome | needed? |
| --- | --- | --- |
| the map: `run(id, "ab").length` | runs, `2`, `2` | **yes** |
| the `.length`: `print(run(mv, "ab"))` | runs, `ab`, `2` | **yes** |
| `id(2)` | runs, `2` | **yes** |
| `id(2)` as `const g = id`, `g(2)` | same refusal, naming `g` | no |
