### D14519 — a call stored into a record literal's field keeps its record at its own row while another call of the same function delivers it as a declared record

**open · check-clean invalid wasm, clause 1 · filed 2026-10-27 against master `76227d1d5`, present there and after D14518**

Repro:

    type J = { f: i32 | null }
    function mk() { { f: 4 } }
    const wideJ: J = mk()
    const w = { a: mk() }
    print(w.a.f + 1)
    print(wideJ.f ?? 0)

Want:

    5
    4

#### Mechanism

`const wideJ: J = mk()` builds `mk`'s record at `J`. [D14518](D14518.md) and [D14509](D14509.md)
serve a second call stored into an un-annotated list or `Map()`: the container is built where its
stored values are (`recStoresAgree`). A record literal's field is not such a container
(`recStoreDeclOf` answers -1), so `{ a: mk() }` keeps `mk`'s own row in field `a` and `wideJ`
receives the record as `J`. Both seeds fail validation on line 3.

#### Grading list

The generic spelling is the same shape, with a list handed through a type parameter:
`sink(mkcall())` beside `const y = reverse([mkcall()])[0]` (`reverse` from `std:array`, `T`
bound by the argument), where `mkcall` returns `{ r: null }` and `sink` takes
`Circle = { r: i32 | null }`. It is invalid on the `sink` line on both seeds.
