### D4020 — a wider record forwarded through two generic levels into a later-declared record parameter is invalid wasm when each caller is declared above its callee

**closed 2026-10-11 by lane CK · now a loud check reject · was check-clean invalid wasm · clause 1 · found by the #3516 review (wgen-rev3) · filed 2026-10-11 against master `4d0501a9e` · pins: `tests/cases/objects/error-width-record-through-generic-chain-reverse.vl`**

Repro:

    type Pos = { x: f64, y: f64 }
    type A = { k: i32, y: f64, x: f64 }
    function f3<W>(p: W) { f2(p) }
    function f2<W>(p: W) { f1(p) }
    function f1(p: Pos) { p.x = p.x + 1.0 }
    const a: A = { k: 7, y: 3.0, x: 0.0 }
    f3(a)
    print(a.x)
    // vl check: rc 0.  vl run: invalid module inside `f2`

#### Mechanism

A delivery typed at a hole into a record slot (`p` into `f1`'s `Pos`) is parked as a pin of
the function whose body holds it, and each call re-asks it at its bindings
(`validateRcwPins`), moving one still open out to the caller. The constraint probe that walks
callee bodies before a caller recorded every other deferred constraint but not these pins, so
`f3`'s call of `f2` — checked before `f2`'s body — found none to move, and `f3(a)` re-asked
nothing. The probe now records the pin and moves it outward like the other constraints. The
program is refused exactly as its callee-first spelling is.

#### Ablation

| ingredient removed | outcome | needed? |
| --- | --- | --- |
| `f3` (one generic level) | refused | **yes** |
| declaration order (`f1`, `f2`, `f3`) | refused | **yes** |
| `a` built at `Pos` | runs | **yes** |
| a `string` argument in place of `a` | refused (argument constraints were probed) | **yes** |
