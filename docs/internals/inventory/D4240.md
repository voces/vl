### D4240 — a written `let` of generics whose value is copied into another binding or a list, with each called at its own type, has no one instance to hold

**loud emit reject · `vl check` rc 0 · clause 2 · OPEN · was a silently wrong value, invalid wasm or a trap on master until lane SC's refusal; running it needs the instance record of `fn-value-flow-design.md` §(g) · found in review of #3570 (`rv3570` t04, n15, t01) · filed 2026-10-12 against master `f6ee50929`**

Repro:

    function gA<U>(u: U) { print("A"); print(u) }
    function gB<V>(v: V) { print("B"); print(v) }
    let f = gA
    let g = gB
    f = gB
    g = f
    f(2)
    g(true)
    // vl check: rc 0.  master: prints B true B true.  now: the reassigned function binding `f` holds functions called at more than one argument type

Want:

    B
    2
    B
    true

#### Mechanism

Under the generic-let ruling (C) `f` and `g` both keep their seeds' generic types, and after
`g = f` both hold `gB`. A written `let` of generics is lowered by instancing every value written
to it at the one signature its calls give it, recorded per binding (`monoCellSigRecord`). The
copy `g = f` coerced `f`'s values at `g`'s type without recording that signature, so whichever
coercion ran last renamed the shared values and both bindings called one instance. `f` is now
given each signature a copy of it wants, and two of them refuse. The same holds for a list
literal holding `f` (`[f]`, D3978) and a record field written with it. Making the program run
needs the value to carry which generic it is, so a copy can convert at a type of its own: the
instance record that `fn-value-flow-design.md` §(g) leaves to a rep decision.
