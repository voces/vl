### D16711 — an un-annotated lambda returned by a function and bound at a function type returning `f64` keeps its `i32` result and traps at the call

**loads then traps · `vl check` rc 0, `wasm trap: indirect call type mismatch` · clause 1 · the `return_inferred`/annotated cell of `hole-fn-lambda-relaying-i32-at-f64-fn-type.matrix.vl` ([D9020](D9020.md)'s template) · filed 2026-11-16 against master `c040079c`**

Repro:

    function deliver() { return (a) => a + 1 }
    const v: (a: i32) => f64 = deliver()
    print(v(3) / 8.0)
    // vl check: rc 0.  vl run: wasm trap, indirect call type mismatch

Want:

    0.5

#### Mechanism

Not located yet. D9020 closed the direct delivery
(`const f: (a: i32) => f64 = (a) => inc0(a)` runs). Through an inferred return, the lambda is
built at its own `(i32) => i32` signature, and the binding's `f64` result is not applied: no
widening wrapper is built and the closure is not re-instanced. The call then goes through the
`f64` signature.
