### D2405 — after a call ends a path narrowing, the re-test its own message asks for is refused too

**loud check reject · clause 2 · filed 2026-09-25 against master `2304ece42`, found surveying the
forms of [D2390](D2390.md) · open**

Repro:

    type O = { v: string | null }
    function clr(o: O) { o.v = null }
    function g(o: O) {
      if o.v != null {
        clr(o)
        if o.v != null { print(o.v.length) } else { print("gone") }
      }
    }
    g({ v: "abc" })
    // vl check: rc 1, "'o.v' was narrowed by a guard, but the call to 'clr' on line 5 can write
    // it — re-test 'o.v' after the call", reported at the re-test itself

#### Mechanism

A path narrowing a call retired answers every later read of the place with
`pathInvalidatedErr`, the re-test's own operand included (`checkMemberNode`, `checkIndexNode`).
The retirement is only a refusal, never a return to the declared type, because the emitter's
path entry is not retired at the call, so a read at the declared type would lower as the
narrowed member. A bare name ended by D2390's rule reads at its declared type instead, the
emitter retiring it after the call's statement, and its re-test runs.

#### Ablation

| ingredient removed | outcome | needed? |
| --- | --- | --- |
| the path (a local `v` a closure nulls, `clr()` then the same re-test) | runs, prints `gone` | **yes** |

#### Grading list

The `is` spelling (`if v.value is f64 { mutate(v); if v.value is f64 { … } }`) and the index
cell (`xs[0]`) spelling; a read of the place at its declared type after the call
(`print(o.v ?? "none")`), which the same answer refuses.
