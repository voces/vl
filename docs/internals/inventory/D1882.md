### D1882 — a nullable value union renders FLAT, so the mono pin ladder had no name for a checked read's own type and the arena's row was never asked

**closed 2026-09-07 — the witness prints `2` · was a loud emit reject, `monomorphize:
unsupported argument type` · clause 2 · 2 of the 64 cells of the `pop-union-box-element`
matrix (`argument` and `early_return_guard`, un-annotated) · filed 2026-09-07 against
master `8bdd886af` grading [D1881](D1881.md)'s close; resolved against `12bfe370a` ·
fixtures `tests/cases/unions/pop-union-box-generic-pin.vl` and its `-annotated` twin**

Repro:

    type V = i32 | string
    function vs(): V[] { [1, 2] }

    function take(a) {
      if a is i32 { print(a) } else { print(0) }
    }

    const src = vs()
    take(src.get(1))
    // vl check: `Checked 1 file, no errors.` rc 0
    // vl run: emitProgram: monomorphize: unsupported argument type for `a` in a call to `take`

#### Mechanism

**Measured at the union floor of `monoArgTyName`, one probe, and the arena had the answer the
whole time.** The floor's readings for `src.get(1)`:

    ty=65  tyToEmitName=[i32|string|null]  monoAnnPinName=[]  isUName=0
           nullablePartOf=[]  unRowOfCanon=-1
           ARENA=TyNullable inner=48 innerName=[i32|string] innerUnRow=0 innerUnName=[V]

Three name channels and all three decline: the render is FLAT, so `isUName` does not claim it;
`nullablePartOf` splits exactly two parts and cannot peel a `null` off three; and the registry
keys the union, not its nullable, so `unRowOfCanon` misses. The ARENA holds both halves — a
`TyNullable` over the row `V` is registered under. `monoUnionPinName` now asks it.

**The pin has to be the FLAT render, and `<alias>|null` is the wrong answer that looks right.**
Pinning `V|null` was built first and gives the instance the correct CELL — `(param $0 (ref $0))`,
the box — and then no unbox, because `unionNameOfIdentSid` answers on the flattened member set
alone. The two readings side by side, at the narrowed ident read:

    pinned `V|null`      identRead a vAtom=[i32] vSet=[]                capBox=0 chainTy=0
    annotated control    identRead a vAtom=[i32] vSet=[i32|string|null] capBox=0 chainTy=0

so `print(a)` under `a is i32` passed the raw box to `__print_i32__` — a clause-2 refusal traded
for a clause-1 miscompile. `tyToEmitName(ty)` is what canon writes for an annotated `V | null`,
and pinning that makes the instance the program the annotated spelling already lowers.

#### Ablation

| ingredient removed | outcome | needed? |
| --- | --- | --- |
| the un-annotated parameter — annotate it `V`-or-null | ran before, runs now | **yes** |
| the checked read — pass a bare `V` value instead | ran before, runs now | **yes** |
| the union element — `i32[]` in place of `V[]` | ran before, runs now | **yes** |
| an annotated `V`-or-null parameter ELSEWHERE in the module | ran before, runs now | **yes** |
| `.get(1)` for `.pop()` | refused before, runs now | no |

The fourth row is the one that nearly cost a green fixture: **one annotated `V | null`
parameter anywhere in the module registers the flat spelling and rescues every un-annotated
call in the same file, on the pre-fix compiler too.** The first draft of the fixture carried
the annotated face beside the un-annotated one and passed on master. The two faces are
separate modules for that reason.
