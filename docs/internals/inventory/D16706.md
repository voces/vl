### D16706 — an existing record whose list field holds records wider than the destination's element is refused as container widening

**loud check reject · clause 2 · `a container never widens implicitly` · residue of the D3431 close (owner ruling (b), nested width) · found by lane WIDTH · filed 2026-11-16 against master `79afdca8a` · bucket (b), L3 width subtyping**

Repro:

    function mk(): { pets: { legs: i32, purr: boolean }[] } { return { pets: [{ legs: 4, purr: true }] } }
    const sv = mk()
    const u: { pets: { legs: i32 }[] } = sv
    print(u.pets[0].legs)
    // vl check: rc 1, the container-widening refusal at `sv`

Want:

    4

#### Mechanism

Taking `sv` at its own type would keep its list at its own element, one storage with one layout,
as D3431 does for a nested record; `recNestedWidthPair` admits only record fields, so the list
pair goes to the container rule. Whether ruling (b)'s "at any depth" reaches a list's element is
for the owner (the container rule's `readonly` view is D4050's).
