### D14654 — a hole lambda aliased into an annotated list or record slot is judged at a later call's types

**closed · was a loud check reject, clause 2 · the statement-swapped spelling ran · filed 2026-10-31 against master `968e7336`**

Repro:

    const h = (u) => { print(u) }
    const fs: ((n: i32) => void)[] = [h]
    h("s")
    fs[0](3)

Want:

    s
    3

#### Mechanism

`const fs: ((n: i32) => void)[] = [h]` records the pair `((?#L.0) => void)[]` / `((i32) => void)[]`
for the pin (`noteLetCstr`), since its only open part is `h`'s own parameter. The delivery types the
copy of `h` that `fs` holds at `i32`. The later `h("s")` pins `?#L.0 = string` and
`validateLetCstrs` re-asked the pair there, refusing a copy that call never builds. With
`h("s")` first the pair did not exist yet, so the program ran. A pair whose open holes are all a
lambda's own parameters, bound by its closed destination, is no longer re-asked
(`lambdaCopyOnly`).

#### Ablation

| ingredient removed | outcome | needed? |
| --- | --- | --- |
| `h("s")` moved above `fs` | runs | **yes** (order) |
| the list (`const k: (n: i32) => void = h`) | runs | **yes** |
| the list, for a record field (`const r: R = { f: h }`) | still refused | no |
| a `function h(u)` instead of the lambda | runs | **yes** |
| the generic encloser, the `k = h` alias | still refused | no |
