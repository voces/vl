### D16949 — [CLOSED 2026-11-17] a field read across record arms whose shared field is a record in one arm has no struct receiver

**closed 2026-11-17 · was loud emit reject, `emitProgram: field access receiver is not a struct` · clause 2 · found grading [D16948](D16948.md) · filed 2026-11-17 against master `b028ce4d9` · fixed by admitting a record-stored arm into the shared read's boxing plan when the read's type has its arm (`sharedFieldArmsBoxable`) · fixture `tests/cases/records/shared-field-read-record-arm.vl` · matrix `shared-field-read-record-arm` · a list-stored arm is [D16951](D16951.md)**

Repro:

    function pick(b: boolean): {f: i32} | {f: {a: boolean}} {
      if b { return { f: 5 } }
      return { f: { a: true } }
    }
    const z = pick(true)
    const r = z.f
    if r is i32 { print(r) } else { print(r.a) }
    // vl check: rc 0.  vl run: emit error, the refusal above

Want:

    5

#### Mechanism

The checker types `z.f` as `i32 | {a: boolean}`, the shared field read across both arms. The arms
store `f` at different codes (an `i32`, a record), so `sharedUnionFieldPlan` needs a boxing plan,
and `sharedFieldArmsBoxable` admitted only atom-stored arms: the plan declined and the read fell to
the plain struct read, whose receiver is a union. The record arm boxes under its arm of the read's
union, which `emitSharedFieldArm` already did for a plan of records alone.
