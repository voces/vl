### D3423 — a type-parameter write into a nullable literal-union place keeps the template's non-null read at a nullable pin

**check-clean silently wrong · clause 1 · open · pre-existing, the same on master `5e277ab52` · the literal-union residue of item 2 of [D3198](D3198.md), which D3240 fixed for every other place · 20 cells of lane NW's `nw/g2` grid · filed 2026-09-30 against master `5e277ab52`**

Repro:

    type K = "a" | "b"
    function g<T>(x: T) {
      let s: K | null = null
      s = x
      print(s ?? "n")
    }
    const v: K | null = null
    g(v)

Want:

    n

#### Mechanism

D3240's `HD_TVW` read declines a declaration that holds a literal (`tvPlaceWrite`), so this place
keeps master's non-null narrowing and the shared body folds its null tests. Taking the literal
union into `HD_TVW` was measured: the re-typed `??` and a closure's capture lost the member
texts the niche prints through (`print of a literal-union atom whose type carries no member
texts`, `literal-union string widening with no members`) at pins that run on master.

#### Ablation

| ingredient changed | outcome | needed? |
| --- | --- | --- |
| `let s: string \| null` | prints `n` | **yes** (a literal union) |
| `const v: K = "b"` | prints `b` | **yes** (a nullable pin) |
| a field `q.s` or a cell `a[0]` of `K \| null` | prints `b` or `false` for a `null` | no |
