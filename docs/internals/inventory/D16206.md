### D16206 — an un-annotated parameter handed with a wider number to a generic's two `T` uses builds an invalid module

**closed 2026-11-14 — the witness runs and prints `0.25` · was: check-clean invalid wasm · clause 1 · `the emitted module failed to validate inside mix: type mismatch: expected f64, found i32` · the same call with the parameter typed `U` refuses (D15041), and typed `i32` runs · found grading D15041's neighbours · filed 2026-11-14 against master `c522f8dd`**

Repro:

    function mix<T>(a: T, b: T): T[] { [a, b] }
    function w2(u, v: f64) { return mix(u, v)[0] / 4.0 }
    const one: i32 = 1
    print(w2(one, 0.5))
    // vl check: rc 0.  vl run: invalid module, inside `mix`

Want:

    0.25

#### Mechanism

The template binds `T` at `f64`, since the hole `u` adapts to `v`. The caller then closes `u` at
`i32`, and mono pinned `mix`'s parameter from `u`'s own instance type, building
`mix(i32, i32): f64[]`. `elabArgDeliveredTy` reported a record built or widened at its parameter,
and a literal built at it, but not a number the parameter's type widens losslessly. It now
reports that wider parameter type, so the instance is `mix<f64>` and `u` is widened at the call.
