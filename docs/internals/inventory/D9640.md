### D9640 — a record of an un-annotated function bound to a `const` and then listed leaves the function unpinned when the element is handed to an un-annotated parameter

**closed · runs, prints `4` · was loud emit reject, `vl check` rc 0, `emitProgram: cannot take the generic function `inc0` as a value`, clause 2 · found closing [D9570](D9570.md) · filed 2026-10-22 against master `9e81d3ee3` · closed by following the element read `xs[0]` to the `const` record bindings and literals the unwritten list holds, each read only there, and pinning each open function field at the field call's arguments in the callee (`monoOpenFnRecSrcPin`, emit_mono.vl) · fixture `closures/hole-fn-record-bound-listed-handed-to-param.vl` · with [D9641](D9641.md), [D9644](D9644.md), [D9645](D9645.md) and [D9646](D9646.md) closed; the grading list's binding both listed and handed directly is filed open as [D9731](D9731.md)**

Repro:

    function inc0(a) { return a + 1 }
    function take2(a) {
      print(a.f(3))
    }
    const e = { f: inc0 }
    const xs = [e]
    take2(xs[0])
    // vl check rc 0.  vl run: emit error: emitProgram: cannot take the generic function `inc0` as a value

#### Mechanism

The literal written inside the list (`[{ f: inc0 }]`) runs since [D9570](D9570.md); bound
first, the list's element is the binding `e`, which the pin of a list of record literals
(`monoOpenFnRecListPin`) does not follow, so `inc0` is taken as a value that no call pins.

#### Grading list

The binding handed directly (`take2(e)`) while it is also listed, which refuses the same way.
