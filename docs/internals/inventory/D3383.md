### D3383 — a lambda capturing a `const` of a module-scope `if` value block calls an unknown function

**closed 2026-10-25 · runs, prints `5` · fixed with [D13081](D13081.md): the module frame's block-local table now records a value `if` arm's `const`, so the lambda's capture of `fv` is typed as the function value it is · pins: `tests/cases/closures/capture-module-value-block-local.vl` · was loud emit reject, clause 2 · found building the [D3073](D3073.md) adapter · the same on master `3291e99e1` · filed 2026-09-30 against master `3291e99e1`**

Repro:

    function mk(): () => i32 { return () => 5 }
    const v: () => i32 = if true { const fv = mk(); () => fv() } else { mk() }
    print(v())
    // vl check: rc 0.  vl run: emitProgram: call to unknown function

Want:

    5

#### Mechanism

[D13081](D13081.md)'s. The module frame's block-local table skipped a top-level binding's
initializer, so the arm's `const fv` was no module-frame binding, and the lambda's capture of it
took the `i32` default rather than a function value: the call through it named no function.
