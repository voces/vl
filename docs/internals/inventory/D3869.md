### D3869 — a value narrowed by `is` to one of two same-shaped records pins a generic at whichever record the shape names

**closed (2026-10-08, lane SC) · was check-clean silently wrong value · found in review of #3455/#3456 (`rv3455b` s15, v15a, v15b) · filed 2026-10-08 against master `36aa1ab1e` · pins: `tests/cases/modules/narrowed-same-shape-record-pin/`**

Repro:

    // file: r1.vl
    export type A = { x: i32 }
    export function d(self: A): string { "RA" }
    // file: r2.vl
    export type B = { x: i32 }
    export function d(self: B): string { "RB" }
    // file: main.vl
    import { A, d } from "./r1"
    import { B, d } from "./r2"
    function h<T>(x: T): string { x.d() }
    const a: A = { x: 1 }
    const b: B = { x: 2 }
    function pick(i: i32): A | B { if i == 0 { a } else { b } }
    const u = pick(1)
    if u is B { print(h(u)) }
    const v = pick(0)
    if v is A { print(h(v)) }
    // vl check: rc 0.  vl run: prints RB, RB

Want:

    RB
    RA

#### Mechanism

`h` is pinned at the name `monoNarrowedPinName` gives the narrowed argument. Its render
(`{x:i32}`) is no arm of `A | B`, so it fell to `nominalStructNameOfTy`, which looks the render
up and names one of the two records for both. Whichever instance was minted first then answered
the other branch too. The arena's own record (`structNameOfTy`) is now asked first; it is the
type the checker narrowed to. Run-time `is` between same-shaped records is a separate question,
D3870.

#### Ablation

| ingredient removed | outcome | needed? |
| --- | --- | --- |
| the second record (`B` and `u`) | `RA` | **yes** |
| the narrowing (`h(a)`, `h(b)` directly) | `RA`, `RB` | **yes** |
| the order (`v` before `u`) | `RA`, `RA` | no |
