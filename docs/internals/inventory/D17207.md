### D17207 — a loop's write that the back edge never carries still retires an inferred-null binding's `null` narrowing, so a join over the read is refused

**closed 2026-11-25 · runs, prints `n` `v` · was a loud check reject (clause 2), a named price of #9975 (D17206), and check-clean invalid wasm before it · for a binding typed `null`, `crLoopLeavingWrite` (check_narrow_flow.vl) walks a loop body's blocks in order: it stops after a statement that always exits (`stmtAlwaysExits`), and skips a statement a later `break` or `return` in its block follows with no `continue` between, so a write the back edge never carries leaves the read at the loop's top `null`; inside a nested loop it counts every write, as before · fixtures `tests/cases/types/null-hole-loop-write-not-carried.vl`, `tests/cases/types/null-hole-loop-conditional-break-refused.vl` · found by V4 verifying #9975 (LAF2) · owner IR-N4 · filed 2026-11-24 against #9975's head `915156c9e`**

Repro:

    type In = { v: i32 }
    const rec: In = { v: 9 }
    function run(f: boolean) {
      let m = null
      let out = ""
      while true {
        const j = if f { m } else { rec }
        out = out + (if j == null { "n" } else { "v" })
        m = { w: "z", k: 4 }
        break
      }
      return out
    }
    print(run(true))
    print(run(false))
    // vl run: n, v

Want:

    n
    v

#### Mechanism

`crLoopLeavingWrite` (check_narrow_flow.vl) ends the `null` narrowing of `m` at the loop's top for
any write in the loop body that leaves it; since D17206 that includes an object literal written to
the inferred-null binding. It does not ask whether the write reaches the back edge: here a `break`
follows it unconditionally, so every read at the loop's top is truly `null`. With the narrowing
ended the read is the open hole, and the un-annotated join over it is re-asked at the fill
([D17203](D17203.md)) and refused. Before #9975 the read stayed `null` and emit built invalid wasm.
