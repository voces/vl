### D1744 — a deep-`is` site ANYWHERE in the module flattens the union alias, so a plain `is J` over `J | i32` elsewhere is refused as "not a variant" — the refused function type-checks alone and only fails in company

**closed 2026-09-06 — the deep-`is` second pass re-checked a tree whose annotations
`canonEmitTypeNames` had already rewritten into the emitter's vocabulary; the author's
spellings now go back first (`canonRestoreSpellings` in `jwSecondPass`) · clause 2**

Repro:

    type K = "aa" | "bb"
    type J = null | boolean | f64 | string | J[] | { [string]: J }
    type Cfg = { port: f64 }

    function f(d: K | i32) {
      if d is K { print(1) }
    }
    function g(e: J) {
      if e is Cfg { print(2) }
    }
    f("aa")
    g(null)
    // prints 1 — before the fix, `emitProgram: `is` names a declared union member with
    // no interned arm representation`; delete `g` and the same `f` ran

#### Mechanism

`checkProgram` ends in `canonEmitTypeNames`, which rewrites every `TypeRef` annotation in
place into the EMITTER's name — for a union alias member, its flattened member set
(`unionAliasMembers`). `jwSecondPass` then re-checks the whole program so the generated
walkers get typed, and it did so on the rewritten tree, without the `canonRestoreSpellings`
the parse bank already uses for the same reason. An instrumented compiler logs the producer
directly: the `is` gate sees `objTy` twice with `spell=[J | i32] asg=1`, then
`CANON-TY node=4 [J|i32] -> [boolean|f64|string|J[]|{[string]:J}|null|i32]`, then twice more
with `spell=[boolean | f64 | string | J[] | {[string]: J} | i32 | null] asg=0 genStart=85` —
the pass-2 firings, which is what makes the effect whole-program rather than sequential.
The re-spelled union is a different type to the checker (its `null` is the niche's, so `J`
is no longer assignable to the inner) and a different arm set to the emitter (`K` indexes no
variant). The restore puts the parser's spellings back before the re-check; pass 2's own
sweep re-derives the emit names on the arena the emitter actually sees.

#### Ablation

| ingredient removed | outcome | needed? |
| --- | --- | --- |
| `g` deleted entirely | runs / checks clean | **yes** |
| `g`'s target changed to a real member (`e is string`) | runs | **yes — it must be a struct shape** |
| `g`'s body replaced by a `Cfg` value that is never `is`-tested | runs | no — declaring `Cfg` is not the ingredient |
| `g` moved ABOVE `f` | fails identically | no — order-independent |
| `std:json` instead of the local alias | fails identically | no — std is scenery |
| `K` (a literal-union alias) in place of `J` at the `is` | emit reject, and the fix RECOVERS the run | no — the alias kind picks which consumer breaks |

The alias kind is what decides which side reports it, and only the literal-union face was a
running program: `is K` over `K | i32` moves `not-runs → runs`, while `is J` over `J | i32`
moves from a checker refusal naming a union nobody wrote to the emitter refusal it always
owed. `is <value-union alias>` does not lower with or without `g` (D1774).

#### Grading list

* `f` alone, which must keep behaving as it does in company — the control, and the
  thing this row is about.
* D1035's own witness, which must keep printing `3`, and D1190 / D1198, the other two
  deep-`is` rows, whose refusals must not widen.
* D1774, the emit-side gap this uncovered: `is <union alias>` over a union carrying that
  alias has no interned arm representation, with no deep-`is` site anywhere.
* The `as` half of the same design item: `d as Cfg` over a `Json` is a separate loud refusal
  (`` `as Cfg` names a type that is not a member of Json ``) and is NOT closed by this row.
