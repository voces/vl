### D6764 — a hole function read out of a list and handed a generic it calls at two types is refused at emit

**loud emit reject · `vl check` rc 0 · clause 2 · CAPABILITY: the same function called by name, or through a `const` alias, runs · found closing [D6741](D6741.md) · filed 2026-10-18 against master `bd096729d`**

Repro:

    function add(a, b) { return a + b }
    function apply2(g) {
      print(g(1, 2))
      print(g(1.5, 2.5))
    }
    const fs = [apply2]
    fs[0](add)
    // vl check: rc 0.  vl run: emitProgram: cannot take the generic function `add` as a value — a function value carries ONE signature

Want:

    3
    4

#### Mechanism

From the ablation only. The split follows a hole function's calls by name and through a
`const` alias, not through a list element, so `g` keeps one parameter and `add` is asked for
at one signature. With a declared generic the same refusal prints an empty parameter list,
"parameters  are un-annotated".
