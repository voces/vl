**closed 2026-10-18 by lane L1 · runs, prints `3` then `4` · was loud emit reject · `vl check` rc 0 · clause 2 · CAPABILITY · the split followed a hole function's calls by name and through a `const` alias, not through a one-element list literal; it now follows a call on an element of a list that holds one hole function · a declared generic called at `i32` and `string` runs too; the alias of an element is [D6790](D6790.md), a record field [D6791](D6791.md) and a two-element list [D6792](D6792.md) · pins: `tests/cases/functions/hole-fn-from-list-handed-generic-at-two-types.vl` · found closing [D6741](D6741.md) · filed 2026-10-18 against master `bd096729d`**

Repro:

    function add(a, b) { return a + b }
    function apply2(g) {
      print(g(1, 2))
      print(g(1.5, 2.5))
    }
    const fs = [apply2]
    fs[0](add)
    // vl check: rc 0.  vl run: emitProgram: cannot take the generic function `add` as a value — a function value carries ONE signature

Want:

    3
    4

#### Mechanism

From the ablation only. The split follows a hole function's calls by name and through a
`const` alias, not through a list element, so `g` keeps one parameter and `add` is asked for
at one signature. With a declared generic the same refusal prints an empty parameter list,
"parameters  are un-annotated".
