### D5403 — a generic passed to an un-annotated lambda parameter is called with no interned signature

**closed 2026-10-17 by lane L1 · runs, prints `x` · was loud emit reject · clause 2 · with no checker binding at the lambda's call, the hole takes the one pin the flow table carries past it (`monoHoleGenFnTy`, `fnFlowDeclPinTys`, D5612's close) · pins: `tests/cases/closures/generic-hole-fn-value-pinned-past-hole.vl` · split from [D4422](D4422.md)'s grading list, found closing [D5361](D5361.md) · filed 2026-10-17 against master `9c7d1b92d`**

Repro:

    function same<T>(k: T): T { k }
    const t = (a) => print(a("x"))
    t(same)
    // vl check: rc 0.  vl run: emitProgram: a function-value call has no interned signature — the callee has no function type to key a signature from

    x

#### Mechanism

From the ablation only. The hole instancing of D4420/D5361 runs at a call to a declared
function; a call through the lambda binding `t` does not reach it, so `a` keeps the generic's
open signature and `a("x")` has no signature key.

Re-graded 2026-10-17 by lane L1, closing D5402: unchanged. D5402's forward reaches the hole
through the declared callee `instGenFnHolePins` reads, and a `const`-bound lambda is not one: it
is not in `fnAliasScopes`, which decides the constraint owner of a call at four checker sites, so
registering it there would move every lambda call, not only this one.

The close (D5612's): the lambda's constraint owner was not needed. The monomorphizer already
instances the lambda per call; what it lacked was a pin for `a`, and the flow table carries the
one `a("x")` takes downstream of `same`. A numeric call, two lambdas at two types and a
function-local lambda run too.
