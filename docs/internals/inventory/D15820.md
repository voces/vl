### D15820 — a record literal written into a field of a receiver built wider than its own type is built at its own record

**closed 2026-11-11 — runs, prints `5` · was check-clean invalid wasm, clause 1 · `storeWritesResolve` already reads the field's storage in the record the receiver is stored as; it now adopts a record literal written there, or the literal a written un-annotated binding holds, at that stored record, so it is built at `J` as a literal nested in `mk`'s build is · fixture `tests/cases/soundness/field-write-literal-into-wider-built-receiver-runs.vl`**

Repro:

    type J = { f: i32 | null }
    type K = { j: J | null }
    function mk() { { j: { f: 4 } } }
    const _k: K = mk()
    const y = mk()
    y.j = { f: 5 }
    print(y.j.f)

Want:

    5

#### Mechanism

`mk` is built at `K` because `_k` delivers it there and every field of `mk`'s own type reads back
from `K`'s storage (D15214). `y` is therefore stored at `K`, whose field `j` holds a `J`. The
written literal `{ f: 5 }` was built at its own type's row, `{ f: i32 }`, and stored into the
`(ref null $J)` field, so the module failed to validate. Found as the distilled cell
`d15214_nested_write_nullable`.

#### Ablation

| ingredient removed | outcome | needed? |
| --- | --- | --- |
| `const _k: K = mk()` | runs, prints `5` | **yes** |
| `| null` on `K`'s field `j` | runs, prints `5` | **yes** |
| the write `y.j = { f: 5 }` | runs, prints `4` (D15214) | **yes** |

#### Grading list

- The same write two levels deep (`y.j = { h: { g: 9 } }`, then `y.j.h = { g: 10 }`): runs.
- The value held in an un-annotated binding first (`const v = { f: 5 }; y.j = v`): runs.
- The value a call returns, or a held binding also handed at its own type: D15821.
