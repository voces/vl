### D3466 — a parenthesized optional call as a closure's expression body, over a narrowed capture, builds invalid wasm

**check-clean invalid wasm · clause 1 · open · pre-existing, the same on master `47aa2950b` · found by lane NW2's `nw2g` grid (`map_name_none_cloA_nn_dir`, `map_name_none_cloB_nn_dir`) · filed 2026-09-30 against master `47aa2950b`**

Repro:

    let a: string | null = null
    a = "abc"
    const f = () => (a?.includes("b"))
    print(f())
    // vl check: rc 0.  vl run: the emitted module failed to validate, "expected i32 but nothing on stack"

Want:

    true

#### Mechanism

Not localised past the ablation. The parentheses are the ingredient: the same closure without
them runs, and so does the parenthesized call outside a closure. The validator says the call's
value is missing where the closure returns it, which reads as the closure's result or its body's
value being decided off the `Paren` node rather than the call inside it, once a narrowing makes
the receiver's `?.` a plain call. The `<T>` spelling of the grid cells is a loud emit reject
instead (`if-expression requires an else arm`).

#### Ablation

| ingredient changed | outcome | needed? |
| --- | --- | --- |
| no parentheses, `() => a?.includes("b")` | prints `true` | **yes** |
| no closure, `print((a?.includes("b")))` | prints `true` | **yes** |
| no narrowing, `const a: string \| null = "abc"` | prints `true` | **yes** |
| a guard narrowing, `if x != null { … }` over a parameter | the same invalid wasm | no |
| `?? false` after the call, inside the parentheses | the same invalid wasm | no |
| a block body, `() => { (a?.includes("b") ?? false) }` | the same invalid wasm | no |
| a map receiver, `(a?.has("k") ?? false)` | the same invalid wasm | no |
| `(a?.length ?? 0)`, a member in place of the call | check refuses, `member access '?.length' on non-object string` | n/a |

#### Grading list

`nw2g`'s `map_name_none_cloA_*` and `map_name_none_cloB_*` cells in all three spellings.
