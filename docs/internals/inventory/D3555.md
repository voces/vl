#### Mechanism

`parsePostfix` had no arm for `BANG`, so the postfix chain ended at `s`, the statement loop
read `!` as a prefix `!`, and its operand parse failed on whatever followed. The new arm takes a
`BANG` only when the next token can neither begin an operand nor be `is` (newline, `)`, `,`,
`.`, `;`, `}`, `]`, `?.`, `??`, end of input, `=` and the compound assignments, and the binary
operators that cannot begin an operand), so a prefix `!` statement, `!=` (one token) and
`x !is T` never reach it. Every file the arm could fire on was already a parse error: `vl fmt`
over all 14,769 tracked `.vl` files gives byte-identical output and exit codes against master,
except six unparseable matrix templates and this row's own fixture whose FIRST diagnostic is now this one.

#### Grading list

`s!.n`, `f(s!, 1)`, `s! ?? 0`, `(s!)`, `y! + 1`, `y! = 2` each report one error at the `!`; `!(x)`, `a != b`,
`x !is T` unchanged. `xs![0]` still parses as `xs` then `![0]`, as on master, since `[` can
begin an operand, and `x! is O` reads as `x !is O` (D3585).
