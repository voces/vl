### D3827 — a capturing nested `<U>` generic called from a function nested inside one enclosing instance shares the template frame's instance

**closed 2026-10-08 by lane SC · runs · was a loud emit reject, and before that check-clean invalid wasm · found closing D3826 · filed 2026-10-08 against master `cab1ee907` · pins: `tests/cases/generics/nested-generic-capture-sibling-caller.vl`, `tests/cases/generics/nested-generic-capture-callers-that-run.vl`**

Repro:

    function outer<T>(x: T) {
      function inner<U>(u: U) { print(x) }
      function other() { inner(true) }
      other()
    }
    outer(7)
    outer("s")
    // vl check: rc 0.  vl run: invalid module inside `other`, `expected i32, found (ref $type)`

Want:

    7
    s

#### Mechanism

D3826's close keys a capturing nested generic's instance on the enclosing instance only when
the call is made from that instance's own body. From `other` (or a lambda) the caller does not
hold `x`: it does not capture it, since `inner` is a lifted function name rather than a free
variable, so the env the call builds has no source for `x` at `outer$1`'s type. Keying the
instance on the frame alone turned this from invalid wasm into the loud
`captured variable not found in enclosing frame`.

Closed by giving such a call the instance's frame and fixing the capture walk. The sibling's
copy of the call is renamed to the frame-keyed instance (`inner$2`), and `capSiblingFrees` asked
the block-local scopes about that minted name. It has no lexical row, so the answer was "no
function" and the sibling captured nothing. The walk now keeps the frame chain's answer for a
later instance's minted name. `monoNestedCallFrame` takes the enclosing instance's frame for a
caller nested at any depth in it, a lambda or a block-local function included.
