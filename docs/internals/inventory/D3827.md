### D3827 — a capturing nested `<U>` generic called from a function nested inside one enclosing instance shares the template frame's instance

**check-clean invalid wasm · found closing D3826 · filed 2026-10-08 against master `cab1ee907`**

Repro:

    function outer<T>(x: T) {
      function inner<U>(u: U) { print(x) }
      function other() { inner(true) }
      other()
    }
    outer(7)
    outer("s")
    // vl check: rc 0.  vl run: invalid module inside `other`, `expected i32, found (ref $type)`

Want:

    7
    s

#### Mechanism

D3826's close keys a capturing nested generic's instance on the enclosing instance only when
the call is made from that instance's own body. From `other` (or a lambda) the caller does not
hold `x`: it does not capture it, since `inner` is a lifted function name rather than a free
variable, so the env the call builds has no source for `x` at `outer$1`'s type. Keying the
instance on the frame alone turned this from invalid wasm into the loud
`captured variable not found in enclosing frame`, which is why the close declines it.

#### Ablation

| ingredient removed | outcome | needed? |
| --- | --- | --- |
| the second `outer` instance | runs | **yes** |
| the intermediate function (`inner(true)` in `outer`) | runs since D3826 | **yes** |
| a lambda in its place (`const f = () => inner(1)`) | still invalid | no |
