### D3827 — a capturing nested `<U>` generic called from a function nested inside one enclosing instance shares the template frame's instance

**now a loud emit reject (2026-10-08, lane SC) · was check-clean invalid wasm · found closing D3826 · filed 2026-10-08 against master `cab1ee907` · pins: `tests/cases/generics/error-nested-generic-capture-sibling-caller.vl`, `tests/cases/generics/nested-generic-capture-callers-that-run.vl`**

Repro:

    function outer<T>(x: T) {
      function inner<U>(u: U) { print(x) }
      function other() { inner(true) }
      other()
    }
    outer(7)
    outer("s")
    // vl check: rc 0.  vl run: invalid module inside `other`, `expected i32, found (ref $type)`

Want:

    7
    s

#### Mechanism

D3826's close keys a capturing nested generic's instance on the enclosing instance only when
the call is made from that instance's own body. From `other` (or a lambda) the caller does not
hold `x`: it does not capture it, since `inner` is a lifted function name rather than a free
variable, so the env the call builds has no source for `x` at `outer$1`'s type. Keying the
instance on the frame alone turned this from invalid wasm into the loud
`captured variable not found in enclosing frame`. The sibling's own copy of the call is renamed
to the frame-keyed instance and then answers to the template's name again by the time its
captures are taken, so its env never gains the parameter.

`monoNestedCallFrame` now refuses such a call, from a function nested at any depth in a second
instance of the enclosing function, naming the cause, instead of letting it reach the first
instance's copy. A caller nested in an instance of the nested generic itself (its own
recursive lambda) takes that instance's frame and runs. A program needing the call is still
owed a lowering: clause 2.

#### Ablation

| ingredient removed | outcome | needed? |
| --- | --- | --- |
| the second `outer` instance | runs | **yes** |
| the intermediate function (`inner(true)` in `outer`) | runs since D3826 | **yes** |
| a lambda in its place (`const f = () => inner(1)`) | still invalid | no |
