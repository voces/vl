### D16973 — a list mapped to a union arm or `null` traps at an optional read of its null element

**closed 2026-11-19 by lane F1 · runs, prints `53` · was a loud emit reject (`field access but no struct type declared`), clause 2, after a null-reference trap (clause 1) fixed in emit_classify.vl: `fnRetRepTy` no longer takes a returned `null`, stamped with the record it is the null of, as that record's rep (fixture `tests/cases/records/map-callback-record-or-null-reads-nullable-elements.vl`) · the remaining refusal: an element read the checker typed past `null` (`v[0]?.s`) named its own non-null type as its storage, so a list whose `S | null` elements are stored as a nullable variant (`S` declared only as an arm of `U`) found no nullable-variant row and fell to the plain struct read. The element read's storage is now the list's `T \| null` element where the read is its `T` (`idxNulElemStoreTy`, `readStoreTyAt`) · fixture `tests/cases/records/map-callback-union-arm-or-null-optional-element-read.vl` · found by the capability-matrix rot sweep (`map-nullable-union-arm-result.matrix.vl`, `two_instances` un-annotated) · filed 2026-11-18 against master `1d067b11e` by lane F1**

Repro:

    type C = { r: i32 }
    type S = { s: i32 }
    type U = C | S
    const us: U[] = [{ s: 3 }, { r: 4 }]
    const v = us.map((e) => if e is S { e } else { null })
    print((v[0]?.s ?? 0) + (v[1]?.s ?? 50))

Want:

    53

#### Mechanism

The trap: `exprRepTy` builds a `.map` result's rep from its callback's returned values
(`fnRetRepTy`), and the `null` arm is stamped with the record it is the null of, so both values
read as that record and the list was built at the bare record's row, whose elements are not
nullable. Every element read asserted non-null. With that fixed, the list is read at the arm's
nullable row, and the field read reaches the one `emitMemStructRead` floors for a union arm:
`[pick(us[0]), pick(us[1])]`, a named `pick` returning the same `S | null`, is refused the same way
on master.
