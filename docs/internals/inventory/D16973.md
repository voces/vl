### D16973 — a list mapped to a union arm or `null` traps at an optional read of its null element

**loud emit reject · clause 2 · was a null-reference trap (clause 1), fixed in emit_classify.vl: `fnRetRepTy` no longer takes a returned `null`, stamped with the record it is the null of, as that record's rep, so a `.map` over a callback returning a record or `null` builds and reads a list of nullable elements (fixture `tests/cases/records/map-callback-record-or-null-reads-nullable-elements.vl`) · what remains is the gap a list literal of the same results shows on master: a field read of a list of a union arm or `null` is refused, `field access but no struct type declared` · found by the capability-matrix rot sweep (`map-nullable-union-arm-result.matrix.vl`, `two_instances` un-annotated) · filed 2026-11-18 against master `1d067b11e` by lane F1**

Repro:

    type C = { r: i32 }
    type S = { s: i32 }
    type U = C | S
    const us: U[] = [{ s: 3 }, { r: 4 }]
    const v = us.map((e) => if e is S { e } else { null })
    print((v[0]?.s ?? 0) + (v[1]?.s ?? 50))

Want:

#### Mechanism

The trap: `exprRepTy` builds a `.map` result's rep from its callback's returned values
(`fnRetRepTy`), and the `null` arm is stamped with the record it is the null of, so both values
read as that record and the list was built at the bare record's row, whose elements are not
nullable. Every element read asserted non-null. With that fixed, the list is read at the arm's
nullable row, and the field read reaches the one `emitMemStructRead` floors for a union arm:
`[pick(us[0]), pick(us[1])]`, a named `pick` returning the same `S | null`, is refused the same way
on master.
