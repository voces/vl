### D4930 — a generic's `T[] | i32[]` result at a record pin renders structurally, so its list has no element slot

**closed · was a loud emit reject (`emitProgram: `.length` receiver's ref-list element does not resolve`), the same on master `bb21e081b` · fixture `tests/cases/generics/typaram-list-union-return-keeps-both-arms.vl` · filed 2026-10-15**

Repro:

    type P = { x: i32 }
    function wrap<T>(t: T): T[] | i32[] { [t] }
    const q = wrap({ x: 4 })
    print(q.length)

#### Mechanism

The call's result renders structurally, `{x:i32}[]|i32[]`, while the instance registers its
union at the nominal `P[]|i32[]`, and a declared struct's ref-list element key is nominal, so
the structural element found no slot (or, once D2859's dedupe kept the arms apart, a different
tag: `{ f: wrap({ x: 4 }) }` refused, and a field `for`-`in` trapped). Closed in
`emit_collect.vl`'s `shareObjLitFieldUnionRows`, which aliases a structural union spelling to
its canon-equal registered row (`unNameShareCanonRow`), and in `emit_classify.vl`'s
`rlSlotOfKey`, which gives a same-shape record the slot of its declared type.
