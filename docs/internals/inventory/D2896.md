### D2896 — a hole function's nested lambda aliased (`d = c`) and called at another type builds invalid wasm

**check-clean invalid wasm · clause 1 · found by #3231's review (`a7.vl`) · the same on master `8e10ef58b` · filed 2026-09-27 against master `8e10ef58b`**

Repro:

    function mk(x) {
      const c = (y) => y
      const d = c
      print(d(1.5))
      print(c(x))
    }
    mk("s")
    mk(true)
    // vl check: rc 0.  vl run: invalid module inside `mk`

Want:

    1.5
    s
    1.5
    true

#### Mechanism

Not localised. The checker lets the un-annotated lambda serve `f64` through its alias and the
parameter's type through its name, and one lifted body lowers both. Any per-instance pin read
off the calls by name (the approach pulled from [D2854](D2854.md)) cannot see the alias's call.

#### Ablation

| ingredient changed | outcome | needed? |
| --- | --- | --- |
| no alias (`c(1.5)` directly) | still invalid | no |
| one pin (`mk("s")` only) | still invalid | no |

#### Grading list

The lambda returned from `mk` and called outside it (`a1.vl` of the review).
