### D15723 — a fresh call's record holding a list of lists of numbers, delivered at a record storing them wider, is refused as a copy the converter does not reach

**loud check reject · clause 2 · open · `{xs: i32[][]} is not K: they store field `xs` differently (`i32[][]` into `i64[][]`), and the record is also kept at its own type; converting it into K is not yet supported: the converting copy does not reach a nested or nullable field` · found closing D15722 · the same on master `f621e87c3`**

Repro:

    type K = { xs: i64[][] }
    function mk() { { xs: [[4]] } }
    const _k: K = mk()
    const y = mk()
    print(y.xs[0][0])
    print(_k.xs[0][0])

Want:

    4
    4

#### Mechanism

The record copy's rule (`recCopyBoxesAt`) admits a list field of numbers it widens, or of records,
one level of list only. A list whose element is itself a list is neither, so the copy is not
recorded and the kept-maker refusal names the converter. The refusal names a mechanism: the same
record with `xs: i64[]` is copied and runs.
