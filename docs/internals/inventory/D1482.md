### D1482 — `.map` / `.filter` cannot produce a list whose element is a CLOSURE, though `push` builds the same list

**closed · runs, prints `1` · was loud emit reject, `emitProgram: unsupported .map/.filter element type`, later `emitProgram: callee is not a function name`, `vl check` rc 0 · clause 2 · filed 2026-09-03 against master `cdfdc14e` · closed with [D9231](D9231.md): the row a `.map` interns for a function-valued result is named as a closure list (`refElemArrName`, emit_shape_rows.vl); the second face prints `2`, and `.filter` over the result, the annotated destination and the in-function spelling run · fixture `closures/map-builds-closure-list.vl`**

Repro (two lines; `vl check` rc 0, then the emitter refused at 1:6):

    const fs = [1].map((n) => () => n)
    print(fs[0]())

#### Mechanism

The refusal names the RESULT element's type, and only that: the source element is irrelevant
(`i32` and `string` behave identically) and the enclosing scope is irrelevant (the same
expression inside a function refuses too). `(() => T)[]` is a perfectly buildable type —
the identical list built with `push` in a loop RUNS — so nothing about the rep is missing;
only `.map`/`.filter`'s own element classifier declines it. The message concedes a capability
gap (`unsupported … type`) on a program the checker accepts, so it is a clause-2 violation by
construction.

#### Ablation

| ingredient removed | outcome | needed? |
| --- | --- | --- |
| the closure RESULT element (`[1].map((n) => n + 1)`) | runs | **yes** |
| `.map`/`.filter` (build the same list with `push`) | runs | **yes** — the rescue |
| the top level (the same expression inside `function go()`) | refuses | no |
| the annotation (`const fs: (() => i32)[] = …`) | refuses | no — annotating is not a rescue |
| the `i32` source element (`string` instead) | refuses | no |
| the `.map` (a bare curried lambda `(a: i32) => (b: i32) => a * b`) | runs | no |

#### Grading list

The `push`-built `(() => T)[]` must keep running, as must a plain curried lambda. The close
must be graded at `.filter` as well as `.map` — one classifier, two callers — and at both an
annotated and an un-annotated destination, since the annotation is not a rescue here and a
fixture that annotates would still see the defect but would not prove the un-annotated
spelling.
