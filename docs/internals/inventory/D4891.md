### D4891 — an un-annotated list of a written `let` of a generic stores the instance another binding's call picked

**loud emit reject · `vl check` rc 0 · clause 2 · OPEN · `a function-value call has no interned signature` since the L9 `fnNestUsed` gate; was clause 1 before it · found while closing D3975 · filed 2026-10-15 against master `5be21bb0a`**

Repro:

    function k<T>(x: T): T { return x }
    function main() {
      let f = k
      f = k
      print(f("s"))
      let g = k
      g = k
      const fs = [g]
      print(fs[0](1))
    }
    main()
    // vl check: rc 0.  vl run: emit error, a function-value call has no interned signature

Want:

    s
    1

#### Mechanism

`g` is written and then delivered into an un-annotated list, so the list's element type is
inferred from `g` and no destination fixes the instance `g` holds. Both written bindings of
`k` share the generic's instances, and `g` is stored at `f`'s `string` instance while
`fs[0](1)` calls it at `i32`. Not reached by D3975's split: `g` is called at one type only.

`fs[0](1)` is keyed `>v`, the key of a nullary void function. It was invalid wasm while
`main`'s own `() => void` signature was interned and the call found it. Since the L9
`fnNestUsed` gate, a program with no nested frame interns only the signatures of functions used
as values, so `>v` is missing and the call refuses. The mis-keyed call is the defect in both
outcomes.

#### Ablation

| ingredient changed | outcome | needed? |
| --- | --- | --- |
| the list annotated `((x: i32) => i32)[]` | runs, `s 1` | **yes** |
| no `f` (only `g` and the list) | runs, `1` | **yes** |
