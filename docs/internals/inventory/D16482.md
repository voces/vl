### D16482 — an annotated empty container of vectors escapes the checker's container refusal

**check-clean invalid wasm · clause 1: `const xs: F32x4[] = []` passes `vl check` and fails to validate (`expected i32, found (ref $type)`); the map twin is a loud emit reject · found by D16480's position sweep · filed 2026-11-15 against master `940c5e5f4`**

Repro:

    import { F32x4 } from "std:simd"
    const xs: F32x4[] = []
    print(0)

Want:

    a check refusal of `F32x4[]` (D1981), or `0` once a `v128` array lowers

#### Mechanism

`tyNestsV128` answers true for both containers, so `v128NestCheck` would refuse them, but
nothing reaches it: no expression is typed with the container (the literal is empty, or a
`Map()`), and the `const` annotation's resolution does not run the refusal hook. With an element
in the literal (`[splatF32(1.0)]`) the checker refuses, as D1981 says. Not yet ablated past that.

#### Ablation

| ingredient removed | outcome | needed? |
| --- | --- | --- |
| the vector element (`F32x4[]` to `f32[]`) | runs | **yes** |
| the emptiness (`[splatF32(1.0)]`) | loud check reject (D1981) | **yes** |
| the array (`{[string]: F32x4} = Map()`) | loud emit reject (`unsupported map value type`) | no |
