### D2604 — after an early-return null guard, a write of `null` to the binding is refused as if the narrowing were its declared type

**loud check reject · clause 2 (pending an owner ruling, below) · the same on master `483ff4607` ·
filed 2026-09-26 against master `483ff4607`, found by the re-review of #3178**

Repro:

    type A = { r: i32 }
    function mkA(n: i32): A | null {
      if n == 0 { return null }
      { r: n }
    }
    function go() {
      let y: A | null = mkA(6)
      if y == null { return }
      y = null
      print(y == null)
    }
    go()
    // vl check refuses `y = null`: cannot assign null to A (and then `y == null`: cannot
    // compare A with null).  Expected: `true`

#### Mechanism

A prediction. The post-guard narrowing is a shadowing `declare` of the name at `A` in the rest
of the block (`NAR_KIND_POSTGUARD`), and the assignment is checked against what `lookup` returns
there, which is the narrowed type rather than the declaration. Inside `if y != null { y = null }`
the same write is checked against the declaration (the guard kind's banked declared type) and
retires the narrowing, so the two narrowing kinds disagree about what a write may store.

**Pending owner question:** may a block under a narrowing write another member of the declared
type? Recommendation (the coordinator's, 2026-09-26): yes, and the write re-narrows the binding
to what it stored, exactly as it does under an `if` guard (D1736), so `y = null` is accepted and
`y == null` then reads `true`.

#### Ablation

| ingredient changed | outcome | needed? |
| --- | --- | --- |
| the write inside `if y != null { … }` instead of after an early return | accepted | **yes** (the post-guard kind) |
| the write stores `{ r: 1 }` rather than `null` | accepted (the later `y == null` is refused as a comparison of `A` with null) | **yes** (a value outside the narrowing is what refuses) |
| the write stores `mkA(1)`, an `A \| null` | refused the same way | no |

#### Grading list

The same write after a `while` guard's `break`, after an `is` guard's early return over a value
union (`x: i32 | string`, `if x is string { return }`, `x = "s"`), and at a field path.
