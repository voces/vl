### D2604 — after an early-return null guard, a write of `null` to the binding is refused as if the narrowing were its declared type

**closed 2026-09-26 — the filed repro runs and prints `true` · was a loud check reject, clause 2 ·
filed 2026-09-26 against master `483ff4607`, found by the re-review of #3178 · closed under the
owner ruling of 2026-09-26 (DECISIONS.md, the D2390 section) · fixtures
`tests/cases/soundness/postguard-write-renarrows.vl`,
`tests/cases/soundness/narrowed-write-any-declared-member.vl`**

Repro:

    type A = { r: i32 }
    function mkA(n: i32): A | null {
      if n == 0 { return null }
      { r: n }
    }
    function go() {
      let y: A | null = mkA(6)
      if y == null { return }
      y = null
      print(y == null)
    }
    go()
    // now prints `true`

#### Mechanism

A write under a narrowing was checked against `writeStorageTy`, which read the declared type only
for an `if`-guard's bank row (`NAR_KIND_GUARD`) and for an assignment's. The post-guard row
(`NAR_KIND_POSTGUARD`) fell through to the narrowed flow type, so `y = null` was checked against
`A`. The same answer came back for a guard row whenever any function body had been checked
since the narrowing began (the `narFnEpoch` test), so `if x is string { xs.map(...); x = 5 }`
was refused the same way. The close answers every guard kind from the widest layer of the
name's narrowing chain in the function (`narWriteStorage`), drops the epoch test in favour of
the per-call check D2402 already made of a closure called by its handle, and re-narrows the
name to what the write stored (`writeNarrowAfter`). A null test of a name or place a write
under a guard stored into is legal for the rest of that scope (`narWrittenName`,
`narWrittenPath`), as it is after an assignment's narrowing.

#### Ablation

| ingredient changed | outcome on master | needed? |
| --- | --- | --- |
| the write inside `if y != null { … }` instead of after an early return | accepted | **yes** (the post-guard kind) |
| the write stores `{ r: 1 }` rather than `null` | accepted, then `y == null` refused | no (the null test is the same gap) |
| the write stores `mkA(1)`, an `A \| null` | refused the same way | no |
| an `if` guard with a lambda checked between it and the write | refused the same way | no (the epoch test, same refusal) |

#### Grading list

The same write after a `while` guard's `break`, after an `is` guard's early return over a value
union, and at a field path, all in `postguard-write-renarrows.vl` and the narrowed-write grid
(`scripts/capability-probes/narrowed-write-grid.py`).
