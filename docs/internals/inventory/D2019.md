### D2019 — an assignment through a computed index, a nested receiver, or into a field of another type is check-clean and fails validation when its value is used

**closed 2026-09-25 — the witness prints `5`, and so do the three grading spellings · was check-clean invalid wasm, clause 1 · the residue of [D2013](D2013.md) · filed 2026-09-22 against master `6ba849906`, closed with [D2496](D2496.md), whose tail field/element write is a value through `spillTail` · fixture `tests/cases/conditionals/tail-if-assignment-value.vl`**

Repro:

    function f(a: i32[], i: i32) { a[i] = 5 }
    print(f([0, 0], 1))
    // vl check: rc 0.  vl run: rc 70, the emitted module fails to validate (type mismatch)

#### Mechanism

An assignment is an expression yielding its right-hand side (DECISIONS.md), and the checker types
`f` as `(i32[], i32) => i32`. The emitter lowers an assignment's value by storing and then
re-reading its target (`assignTargetReReads`), which is sound only where the re-read is pure and
reads back the assigned type: a name, a captured cell, or a literal-index / field write on a named
non-map place. Everywhere else the tail is lowered as a statement, so the function's functype has
no result while the caller consumes one. A general lowering evaluates the right-hand side once
into a local, stores the local, and pushes it; that needs every store path (list, map, bytes,
struct field, nested receiver) to take a pre-evaluated value.
