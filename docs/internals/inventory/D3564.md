### D3564 — `x as f64 < y` read the `<` as the cast target's type-argument list

**closed 2026-10-03 · was parse error: `expected > but found …` · sunpa SP-018 · filed 2026-10-03 against master `315552b88`**

Repro:

    const h = 10
    let y = 3
    while y as f64 < h as f64 * 0.35 { y = y + 1 }
    print(y)

Want:

    4

#### Mechanism

`parseAsType` parses the cast target with `parseTypeAtom`, whose identifier arm takes a
following `<` as a generic application. A primitive takes no type arguments, so after one the
`<` can only be a comparison. The atom now declines the `<` inside a cast target when the head
is a primitive or a type this module declares without parameters (`asTargetTakesTypeArgs`), and
the expression parser reads it as `<`. A generic target keeps the argument list; when that list
fails to parse, the error adds `if < compares the cast, parenthesize it: (x as T) < y`.

The change can alter an AST only where the token run `as[?!%]? IDENT <` occurs. Across all
14,750 `.vl` files in the repo it occurs nowhere, outside comments, before this row's own
fixtures, so no previously parsing file changes.

#### Ablation

| target | master | after |
| --- | --- | --- |
| `f64` / `i64` / `i32` primitive, `as`, `as?`, `as!`, `as%` | parse error | comparison |
| `type Meters = f64` declared in the module | parse error | comparison |
| an indexed receiver inside `!( … )`, `&&`/`||`, `if`, a call argument, a list element (`!(fill[p] as f64 < fk)`) | parse error | comparison |
| `type Num<T> = T` declared in the module | parse error | parse error naming the parentheses |
| a name the module does not declare | type arguments | unchanged |
| `<=`, `<<` after the cast | comparison / shift | unchanged |
