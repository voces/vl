### D4607 — every first instance of a generic scans the whole arena for writes to its callee's name, so a program with N generic pins compiles in time quadratic in N

**runs today and must keep running · a compile-time cost, not a miscompile: the pair compiles, runs and prints the right value at every size · regression since #3449 (D3857) · filed 2026-10-14 against master `56e06d91c`**

#### Mechanism

`monoMakeInstanceGo` (`compiler/emit_mono.vl`) computes `const written =
monoNameWrittenAt(cal3.identName, calleeIx)` for every first instance. #3449 hoisted it out of
the `cal3.identName != fn.fnName &&` short-circuit it used to sit behind, so it now runs for a
direct call by the generic's own name too, where `written` is never read. `monoNameWrittenAt`
walks `monoProgStmts` (`monoTopFrameOf`) and, for a read that resolves to no `let`, tail-calls
`monoDeclIsAssigned`, a scan of all of `P.nodes` comparing every assignment target's name;
#3622 added a declaration identity per name hit. Guest profile of the 800-pin many arm, master's
seed with `--names`, wasmtime 47: `monoDeclIsAssigned` 55.2% inclusive, `monoTopFrameOf`
11.4%, `__str_eq__` 45.8% self beneath them. Predicted fix, not yet measured: test
`cal3.identName != fn.fnName` before computing `written`, or answer it from a per-name write
index built once per arena generation.
