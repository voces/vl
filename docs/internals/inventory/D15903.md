### D15903 — a hole lambda's bundle stored in a record field, list element or map value, read and handed to a parameter called at two signatures, is refused by mono

**closed 2026-11-12, runs and prints `5` `2.5` · was loud emit reject · clause 2 · `emitProgram: monomorphize: unsupported argument type for \`b\` in a call to \`take\`` · found closing [D15744](D15744.md) · filed 2026-11-12 against master `bd8092cc` · closed in the elaboration: an un-annotated field's or element's read handed as an argument its callee instance takes whole leaves the slot holding the record (`elabSlotRecordNote`, `elabHandCanTakeRecord`, emit_elab.vl) · fixture `tests/cases/closures/hole-lambda-bundle-handed-on-copied-and-dropped.vl` · still refused: the slot read through a `const` holder and handed, a map value handed, and a field both handed and called through, filed as [D15907](D15907.md)**

Repro:

    function lap(f) {
      f(2.5)
      f(3)
      return f
    }
    function take(b) {
      print(b(4))
      print(b(1.5))
    }
    const o = { f: lap((a) => a + 1) }
    take(o.f)

Want:

    5
    2.5

#### Mechanism

An un-annotated container stores the bundle as one closure; the record of members is not
carried into the slot, so the slot's read handed to `take` is a single function value that
mono cannot type at both of `take`'s signatures. Annotated at one member's type, each of these
positions runs.

#### Ablation

| spelling | outcome |
| --- | --- |
| `const o = { f: lap(…) }`, `take(o.f)` | refuses |
| `const xs = [lap(…)]`, `take(xs[0])` | refuses |
| `m["k"] = lap(…)`, `take(m["k"] ?? …)` | refuses |
| the slot annotated `(f64) => f64`, read called at `f64` | runs |
| the bundle from a named or lambda returner | refuses the same |
