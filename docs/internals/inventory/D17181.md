### D17181 — a hole's map read keyed by a call, as a `??` chain's re-associated inner link, reads its hit at the raw value, not the chain's box

**check-clean silently wrong · clause 1 · prints `1` for `true`; a string map's spelling fails to validate · filed 2026-11-24 against master `b8dcfc1ba` (found by IR-N3's `coalesce-chain-untyped-inner-link` template) · owner FREE**

Repro:

    function k(x: i32): i32 { return x }

Want:

    true

#### Mechanism

`a ?? b ?? d` re-associates to `a ?? (b ?? d)`. Over a hole's map reads of mixed kinds (a boolean
map and an i32 map) the chain joins one union box, and the inner link `b ?? d` carries no type of
its own. Where that inner link's map read is keyed by a call and hits, its value reaches the
chain's consumer as the raw map value instead of the boolean member of the chain's box: `print`
shows `1`, a compare against `true` is `false`, and over a string map the module fails to
validate (`expected (ref null $2), found i32`).

#### Ablation

| the hit in the first link instead (`a[k(8)] ?? a[9] ?? b[3]`) | prints `true` | **yes** |
| the parameters annotated (`a: {[i32]: boolean}, b: {[i32]: i32}`) | prints `true` | **yes** |

| the default a literal (`?? 5`) | prints `1` | no |
| the boolean map for a string map (`s[8] = "s"`) | invalid wasm: `expected (ref null $2), found i32` | no |
