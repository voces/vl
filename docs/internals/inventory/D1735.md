### D1735 — a narrowed receiver that names NO variant answered -1 for its field's code, so a struct-valued map cell's `string` field printed through the i32 printer

**closed 2026-09-06 · filed as "an object-shaped map value has no narrowed place read", which
the disassembly refutes: the read was correct and the CLASSIFIER was not · 0 corpus cells**

Repro:

    type Hit = { msg: string }
    type Miss = { why: string }
    type R = Hit | Miss
    function mkA(): Hit { return { msg: "a" } }
    const m: { [string]: Hit } = Map()
    m["k"] = mkA()
    if m["k"] != null { print(m["k"].msg) } else { print("null") }
    // prints a

#### Mechanism

D1734 gated object-shaped map values out because lifting the gate produced invalid wasm.
Lifting it again and reading the module says why, and it is not the delivery: the emitted
`ref.as_non_null · struct.get $Hit 0` is the right read of the right row, and the next
instruction is `call __print_i32__` on a string ref.

`memberFieldCode` — and its twin `memFieldTypeCode`, fixed arm for arm — answered `-1` for
ANY narrowed receiver whose narrow named no variant, a bare early return that skipped the
struct rungs below it. Only a narrowing that names a VARIANT re-homes the field onto the
variant tables; one that does not leaves the receiver at its own shape, so both fall through
now. `exprString` also gained the string-VALUED map rung its Index arm lacked beside the
string-list and union-box ones, gated on `indexPlaceNonNull`.
