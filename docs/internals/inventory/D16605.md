### D16605 — a radix literal inexact at a float is adopted and rounded as a list element or a `??` default, where a binding or argument refuses it

**check-clean silently wrong · clause 1 (`vl check` rc 0) · ruling 4.1 (a radix literal in a float context is the value its digits spell, refused where the float cannot hold it exactly) and 4.3 (a literal that does not fit the typed value keeps its default and the join widens) · found by lane T's literal-adoption position matrix · filed 2026-11-15 against master `c8f0324da`**

Repro:

    const n: f32 | null = null
    print(n ?? 0x1000001)
    // PRINTS 16777216

Want:

    16777217

The element face, `const xs: f32[] = [0x1000001]`, prints `16777216` too; its want is a check
reject, `constant 16777217 is not exact at f32 — write it as a float literal to round it`, as a
binding and an `f32` argument give.

#### Mechanism

Not localised past the ablation. A binding and an argument check a radix literal's exactness at
the float destination and refuse an inexact one. At a list element, and as the default of a `??`
beside a typed float, the literal adopts the float without that check and the value is rounded.
