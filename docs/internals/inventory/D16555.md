### D16555 — `sel(gid)` returned through an inferred return or held as a list element, then called at `f64`, runs the `i32` instance and traps

**loads then traps · clause 1 · open · `vl check` rc 0 · `wasm trap: indirect call type mismatch` · the run-time face of [D16411](D16411.md) and [D16531](D16531.md): the same unbound `A`, but the later call has an interned `$fnsig`, so emit has nothing to compare · the annotated `return_inferred` and un-annotated `array_element` cells of `generic-fn-at-generic-fn-param-bound-by-destination.matrix.vl` · filed 2026-11-15 against master `59155c7df`**

Repro:

    function gid<A>(x: A): A { x }
    function sel<A>(f: (x: A) => A): (x: A) => A { f }

#### Mechanism

`sel(gid)` sits where nothing binds `A`: the return of a function with an inferred return type,
or an element of an un-annotated list literal. The `gid` instance defaults to `i32`. The later
call is keyed `d>d` from its own operand and that key is interned, so the call compiles and the
engine's signature check traps. [D16410](D16410.md)'s destination binding does not reach through
the inferred return. From the ablation.
