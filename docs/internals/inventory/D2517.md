### D2517 — a generic instance re-picks field-then-`self`-function for `x.name(…)` and never asks whether the pinned receiver has a built-in method of that name

**closed 2026-09-25 — the witness prints `1` · was check-clean silently wrong (and, with `self: string`, check-clean invalid wasm), clause 1 · filed 2026-09-25 against master `54fcaf5d8` from the #3161 review ([D2476](D2476.md)'s second decider) · fixtures `tests/cases/generics/member-call-builtin-wins-in-generic.vl`, `tests/cases/generics/member-call-builtin-per-instance.vl`, `tests/cases/modules/member-call-imported-self-fn-per-instance/entry.vl`, `tests/cases/generics/error-member-call-pin-misfit.vl`**

Repro:

    function push(self: i32[] | string, x: i32) { print(99) }
    function f<T>(x: T) { x.push(1) }
    const xs: i32[] = []
    f(xs)
    print(xs.length)
    // vl check: rc 0.  vl run, filed: prints 99 then 0; now 1

#### Mechanism

Three deciders answered `recv.name(…)` and only the checker's concrete arm used the language's
order (built-in method, then field, then `self`-function). Inside a generic body the receiver is
a type parameter, so `drwWalk` (`emit_rewrite.vl`) rewrote the call to the function unless a
call site's argument had a FIELD of that name, and `monoPinBinOps` (`emit_mono.vl`, the D1063
arm) re-picked per instance asking field-then-function — neither asked about built-ins nor read
the checker's banked rung, and the checker's pin (`validateUfcsCstrs`) validated only the
function's `self` fit. The close is one resolution, `memberRungOnTy` (`typecheck.vl`, also what
D2475's declaration refusal reads), asked of each instance's own receiver type: `drwWalk` leaves
a call on a type-parameter parameter to the instance (`MC_RUNG_PER_INSTANCE`), `monoPinBinOps`
keeps the built-in or field call (a map's `get` as the read `m[k]`, D1522) or takes the function
with its defaults filled, and the pin checks that a built-in or field that takes the call fits
how the body used it — its arity, argument types, named arguments, and (for a built-in) its
value — naming what does not fit. The pin's receiver type is the argument's own (a `Set`'s pin
name spells its map rep, which has no `add`).
