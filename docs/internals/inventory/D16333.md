### D16333 — a record of a generic function handed to an un-annotated parameter and called through `?.` builds an invalid module

**closed 2026-11-15 — the witness runs and prints `2` · was: check-clean invalid wasm · clause 1 · bucket (f) · the un-annotated `argument` and `early_return_guard` cells of `fn-value-generic-optional-read.matrix.vl` and of its `-open` twin, SILENT on master · found grading D16310's close · filed 2026-11-14 against master `495c1ff80`**

Repro:

    function id<T>(x: T): T { return x }
    function take(a) { print(a?.f(2) ?? 0) }
    take({ f: id })
    // vl check: 0 errors.  vl run: invalid module inside `take`

Want:

    2

#### Mechanism

The optional call is wrapped in its guard, `if a != null { a.f(2) } else { null }`
(`drwOptGuard`, emit_rewrite.vl). The only call passes a record, so `take`'s instance pins `a`
non-null, its guard test folds to `true`, and the result is an `i32`. The guard's `null` arm still
emitted `ref.null` into that `i32` result.

**Closed.** `emitIfExpr` (wasmEmit.vl) emits only the call for such a guard (`optGuardCallOf`).
That applies when the guard's `else` is the lone `null` and its test is `true`, or `r != null`
over a receiver typed with no `null`. A `null` or nullable argument at the same hole parameter is
refused at check today: [D16338](D16338.md) and [D16339](D16339.md). Fixture
`closures/generic-in-record-optional-call-through-hole-param-runs.vl`.
