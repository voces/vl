### D1311 — the compare-frame pre-pass walks only the TOP-LEVEL struct row, so a NESTED struct's list field gets a core with no frame — silent at `string[]`, loud at the rest

**check-clean invalid wasm: `unknown local 12: local index out of bounds` · clause 1 · PRE-EXISTING: identical message and identical byte offset on `seed-latest` (2026-09-03) · ZERO corpus cells · found 2026-09-03 while grading [D1291](#d1291)'s close one construct deeper**

Repro (`vl check` rc 0; the module fails to instantiate):

    type Deep = { s: string[] }
    type Outer = { d: Deep }
    const a: Outer = { d: { s: ["a"] } }
    const b: Outer = { d: { s: ["a"] } }
    const c: Outer = { d: { s: ["b"] } }
    print(a == b)
    print(a == c)
    // vl check rc 0; vl run -> unknown local 12: local index out of bounds

#### Mechanism

`leqNoteBin` reserves one compare frame per LIST-repped field of the row `binEqStructRow`
resolves — the row of the OPERANDS. A code-15 field recurses at emit time
(`emitStructEqFieldAt` calls `emitStructEqRec` one level down) but the pre-pass never follows
it, so the nested row's own list fields are cores emitted against a frame nobody reserved.
`shapeHasCloField` is the same walk done correctly, with a `seen` list bounding the recursion;
this one has no recursion at all.

The SEVERITY splits by which frame the rep rides, which is why the family cannot be counted
from its message: a `string[]` field reaches `emitListEqSCore`, whose slots are lazily
numbered and run off the end (SILENT); a ref list or a distinct-backing scalar list reaches
`emitListEqGCore`, which checks its frame and refuses loudly; an `i32[]` field RUNS, because
its frame is `fnUsesListEqI`'s and something else in the walk already set it.

#### Ablation

| ingredient removed | outcome | needed? |
| --- | --- | --- |
| the nesting (`{ s: string[] }` compared directly) | runs | **yes** |
| the list field (nested `{ p: i32 }`) | runs | **yes** |
| one nesting level → two | still silent | no |
| `string[]` → `f64[]` / `Inner[]` / `Inner[] \| null` | loud `list compare frame was not reserved for this rep` | no — same mechanism, other severity |
| `string[]` → `i32[]` / `i32[] \| null` | runs | — the frame those ride is reserved elsewhere |
| the `\| null` on any of them | no change either way | no |

Measured as a 15-rep nested sweep on 2026-09-03: 8 run, 5 refuse loudly, 2 are silent
(`string[]`, `string[] | null`), and the split is exactly the frame each rep rides.
[D1291](#d1291)'s close moved the nested `Inner[] | null` cell from
`unsupported struct field type in equality` onto this row's loud message — loud to loud, and
onto the message its NON-null twin already carried, which is the honest column.
