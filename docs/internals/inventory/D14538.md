### D14538 — every arm test and payload read of a `match` is a read node of its own, so a per-node fact about one arm is not overwritten by the next

**runs today and must keep running · a Step 6 pin: the desugar shares no scrutinee read across arms · filed 2026-10-27 against master `579e6a494`**

Repro:

    type Attack = { target: string }
    type Wait = { turns: i32 }

#### Mechanism

The parser threads ONE scrutinee node into every type pattern (`x is T`) and every payload
read (`const x = <scrut>.x`), and `hmsBindMatch` redirected all of them to ONE `$scrut` read
when the scrutinee is computed. Any fact the checker records per node (the read's type, the
type it was narrowed from) then holds only the last arm's answer. The hoist pass now gives each
pattern and each payload read its own copy of the place read (`hmsPointArms`), so a computed
scrutinee is still evaluated once, into the one `$scrut` binding, and read through distinct
nodes.
