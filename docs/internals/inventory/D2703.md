### D2703 — a local alias of a function, shadowing a top-level function of the same name, gets the shadowed function's list storage

**check-clean invalid wasm · `type mismatch` inside `f`, the same on master `1a3088c65` and after D2696 · filed 2026-09-26 from the #3196 re-review (its a8)**

Repro:

    type Circle = { r: i32 }
    type Sq = { s: i32 }
    type Shape = Circle | Sq
    function sum(xs: Shape[]): i32 {
      let t = 0
      for e in xs { if e is Circle { t = t + e.r } else { t = t + e.s * 10 } }
      t
    }
    function k(xs: Circle[]): i32 { xs.length }
    function f() {
      const k = sum
      const out = [{ r: 4 }]
      print(k(out))
    }
    f()
    // vl check: rc 0.  vl run: invalid module inside `f`; should print 4

#### Mechanism

Not yet located. After [D2696](D2696.md) the destination scan resolves `k` to the local alias
and asks `sum`'s parameter, so the scan answers a union box. Something else still reads the
top-level `function k(xs: Circle[])` for the same call, so the two disagree about the list's
storage. The prediction to check: a second reader (the call's argument coercion or the
literal's own element inference) looks the callee up by name with no scope test.
