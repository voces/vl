### D2703 — a local alias of a function, shadowing a top-level function of the same name, gets the shadowed function's list storage

**closed 2026-09-26 with [D2704](D2704.md) — the repro RUNS and prints `4` · was check-clean invalid wasm, `type mismatch` inside `f`, the same on master `1a3088c65` and after D2696 · filed 2026-09-26 from the #3196 re-review (its a8)**

Repro:

    type Circle = { r: i32 }
    type Sq = { s: i32 }
    type Shape = Circle | Sq
    function sum(xs: Shape[]): i32 {
      let t = 0
      for e in xs { if e is Circle { t = t + e.r } else { t = t + e.s * 10 } }
      t
    }
    function k(xs: Circle[]): i32 { xs.length }
    function f() {
      const k = sum
      const out = [{ r: 4 }]
      print(k(out))
    }
    f()
    // vl check: rc 0.  vl run: invalid module inside `f`; should print 4

#### Mechanism

After [D2696](D2696.md) the destination scan resolves `k` to the local alias and asks `sum`'s
parameter, so the scan answers a union box. The second reader the prediction named was the
destination PIN: `dstPinCallArgs` looked the callee up with `fnIndexOf`, found the top-level
`function k(xs: Circle[])`, and pinned `out` to `Circle[]` before the scan was asked. Closed by
D2704's scope test on that lookup (`nameFreeToModule`).
