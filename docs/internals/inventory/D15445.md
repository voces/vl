### D15445 — a hole parameter stored in a record literal and called through the field at one type and directly at another has no interned signature

**loud emit reject · clause 2, `vl check` rc 0 · open · the record-holder capability D15404's split-plan dependent waits on (M-record, architecture-target-2026-10.md §3.2) · with the split plan on and off · found parking D15404 · filed 2026-11-05 against master `f4cc009c`**

Repro:

    function same<T>(k: T): T { k }
    function mid2(a) {
      const r = { f: a }
      print(r.f("v"))
      print(a(3))
    }
    mid2(same)

#### Mechanism

The record literal `{ f: a }` holds `a`'s set at a field the check types once, at the closed
function type its one field call binds (`(string) => string`). The direct call `a(3)` binds
`(i32) => i32`, and nothing delivers a function value at that type into the instance, so the
call has no interned signature. A `const` alias of `a` (no record) runs, because the elaboration
reads an alias's calls as the parameter's own (`elabCallOnlyAlias`); no fact does that for a
field of a record literal.

#### Ablation

| ingredient removed | outcome | needed? |
| --- | --- | --- |
| the record (`const r = a`, `r("v")`) | runs, `v 3` | **yes** |
| the direct call (`r.f("v")`, `r.f(3)`) | still refuses, `object literal but no struct type declared` | no — the field read at two types alone refuses |
| the second type (`r.f(4)`, `a(3)`) | runs, `4 3` | **yes** |
| the hole (`<G>(a: G)`) | still refuses, `parameter a of mid2 is called at two function types that no parameter per type separates` | no |
| `const` (`let r = { f: a }`) | still refuses | no |
| the function (module `const r = { f: same }`, `r.f("v")`, `r.f(3)`) | runs, `v 3` | **yes** |
