### D15445 — a hole parameter stored in a record literal and called through the field at one type and directly at another has no interned signature

**loud emit reject · clause 2, `vl check` rc 0 · open · the record-holder capability D15404's split-plan dependent waits on (M-record, architecture-target-2026-10.md §3.2) · with the split plan on and off · found parking D15404 · filed 2026-11-05 against master `f4cc009c`**

Repro:

    function same<T>(k: T): T { k }
    function mid2(a) {
      const r = { f: a }
      print(r.f("v"))
      print(a(3))
    }
    mid2(same)

#### Mechanism

Two halves, measured 2026-11-05.

**The tag decision.** The late decision declines `{same}` at `mintSetPartial`, because the read
`f: a` is a field value and the per-read rule (`elabMintHandedIn`) marks a parameter read that
is not a call as partial. A record twin of `elabListParamSource` takes it: a `const` record
literal whose fields all read the parameter, every read of it being `r.f(...)`, is a call of
that parameter. With that fact the decision tags `{same}`. The list spelling (`const r = [a];
r[0]("v"); a(3)`) runs on master through exactly that rule.

**The record's row.** The fact cannot land alone. No row exists for a record literal holding a
tagged set's id inside a hole or generic instance. With the set tagged, the witness refuses
`object literal but no struct type declared` (`emitObj`, no row minted). The one-type spelling
(`const r = { f: a }; r.f("v")`), which runs on master as a closure, becomes check-clean
invalid wasm (`expected (ref $3), found i32`): the row is still the closure's while the value
is the id. Minting from the literal in `mintPinnedObjLit`, as `mintGradualObjLitRows` does for
a tagged set, is not reached for this literal. So the row comes first: a per-instance record row
whose field carries a set's id, then the elaboration fact.
