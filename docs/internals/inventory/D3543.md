### D3543 — a box delivered into a union declared by ALIAS keeps its narrower member's tag, so `is` answers false and a read traps

**loads then traps · clause 1 · open · found by the #3345 review's `wd` grid (17 source/destination pairs x 6 positions) · the same on master `f6e17953b` · filed 2026-10-03 against master `f6e17953b` by lane LC**

Repro:

    type D = i64 | string
    const s: i32 | string = 7
    const d: D = s
    print(d is i64)
    print(d)
    // vl run: prints `false`, then traps (cast failure)

Want:

    true
    7

#### Mechanism

Not confirmed. A box whose `i32` member is delivered into a union holding `i64` but no `i32`
owes a retag of that member (`recordWidenRetagTails` → `widenMemberPairs`). With the
destination spelled inline (`const d: i64 | string = s`) the retag is recorded and the program
prints `true` and `7`; spelled through the alias `D` it is not, so the box keeps the `i32` tag
the destination has no arm for. The likely cause is the destination's leaves being read off the
alias without resolving it (`unionLeafIsWide` / `unionLeavesInto` over the alias type), but no
ablation below the spelling has been run.

#### Ablation

| ingredient changed | outcome | needed? |
| --- | --- | --- |
| `const d: i64 \| string = s` (inline destination) | runs, `true` / `7` | **yes** (the alias) |
