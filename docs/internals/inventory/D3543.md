### D3543 — a box delivered into a union declared by ALIAS keeps its narrower member's tag, so `is` answers false and a read traps

**closed 2026-10-04 — the witness prints `true` and `7` · was loads then traps, clause 1 · found by the #3345 review's `wd` grid · filed 2026-10-03 against master `f6e17953b` by lane LC · fixture `tests/cases/unions/alias-union-widen-retag.vl`**

Repro:

    type D = i64 | string

#### Mechanism

Confirmed below the spelling. The retag hook is gated on `tyWideUnionMinted`, a flag
`mkUnionTy` raises when it mints a union with an `i64` or `f64` member. A declared union's
placeholder is minted EMPTY in pass 0a and filled in place in pass 0b (`fillTypeDeclAt`), so the
flag never saw an alias's members: with no inline wide union anywhere in the program the gate read
false and `recordWidenRetagTails` was never asked. Minting any inline `i64 | string` first made the
alias spelling run. The fill now raises the gates its members earn (`noteUnionMembers`, shared
with `mkUnionTy`), which also raises `numUnionMinted` for a numeric alias: [D3653](D3653.md).
