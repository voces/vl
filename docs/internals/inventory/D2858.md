### D2858 — a generic `(T | null)[]` beside `i32[]` collapses to the nullable list at the pin

**check-clean silently wrong · clause 1 · found grading the #3222 delivery grid (`*_generic_nul_*` cells) · the same on master `721781075` · filed 2026-09-27 against master `721781075`**

Repro:

    function h<T>(c: boolean, t: T) {
      if c { return [null, t] }
      [7, 8, 9]
    }
    const v = h(false, true)
    if v is (boolean | null)[] { print(v[1]) } else { print(v[1]) }
    // PRINTS null

#### Mechanism

The return set joins `(T | null)[]` and `i32[]`, and at `T := boolean` the call is typed as the
one list `(boolean | null)[]`: `if v is i32[]` is refused as `can never match`, and the `[7, 8, 9]`
arm's `8` is read as the niche's null sentinel `2`. [D2800](D2800.md)'s rule keeps `T[]` apart
from `i32[]` at the pin; the nullable element `T | null` is the same question one layer down,
and the pin rule does not reach it. The concrete spelling (`t: boolean`) is the union and runs,
since #3222 gave `(boolean | null)[]` its own tag (code 18).

#### Ablation

| ingredient removed | outcome | needed? |
| --- | --- | --- |
| the type parameter (`t: boolean`) | runs, prints `8` | **yes** |
| the boolean pin (`T := string`) | invalid wasm in the top-level code | no — a second face |
| the nullable element (`[t]`) | runs, the union ([D2800](D2800.md)) | **yes** |
