### D3343 — the literal-binding solve read a store target's provisional answer as a bound on what was stored into it, so the type depended on declaration order

**closed · fixture `tests/cases/numerics/literal-binding-declaration-order.vl` · was a loud check reject (`cannot assign i64 to i32` at the store, plus `` `r10` takes its type from its uses, and they conflict ``) · plumb PL-079 (27 of 348 generated units with their `: i64` literal lets stripped, chunk_7 first) · regression from D3246 · filed and fixed 2026-09-30 against master `2b30e3674`**

Repro:

    function w() { 5000000000 }
    function f() {
      let r9 = 0
      let r10 = 0
      r10 = w()
      r9 = r10 * 2
      print(r9)
    }
    f()
    // was: vl check refused `r10 = w()`; with the two `let` lines swapped it printed 10000000000

Want:

    10000000000

#### Mechanism

A store `r9 = r10 * 2` into a literal `let` records an edge: `r10` bounds `r9` from below, and
`r9` bounds `r10` from above. `lbiSettleEdges` solved the candidates in declaration order,
starting from nothing. `r9`, declared first, had only the literal `2` and an edge whose source
was not yet solved, so it took its default `i32`; `r10` then met its `i64` store and an upper
bound of `i32` from `r9`, found no type, and was never updated, so `r9` never saw `i64` either.
The float kind failed the same way through the default: a binding whose rows are only literals
(or a store joined with its `f64` default) offered `f64` downstream before an `f32` destination
could reach it. The solve now settles in two phases, both seeded in row order rather than
declaration order: stores first, each binding offering the narrowest type its rows need
(`lbiChoose`'s `least`), then with each target bounding what was stored into it.

A second, order-independent limit sat beside it: a store of an integer intrinsic over a literal
`let` (`v2 = divU(v1, 1)`) was a typed leaf of its first-pass type, not an edge, so a chain of
three or more needed one re-check per link and ran out of `LBI_MAX_PASSES`. Its operands are
now edges (`lbiIntrCands`), as an operator's are.

#### Ablation

On master, per the grid below (`n` literal `let`s in a chain, every declaration order):

| ingredient changed | outcome before the fix | needed? |
| --- | --- | --- |
| declare `r10` before `r9` | runs | **yes** (declaration order) |
| `r9 = r10 + r10` (no literal in the stored tree) | runs in every order | **yes** (a literal row decides the target early) |
| `r9 = r10` or `r9 = (r10)` | runs in every order | **yes** |
| `g64(r9)` instead of `print(r9)` | runs in every order | **yes** (a typed destination decides the target) |

| `v1 = divU(v0, 1)` links, n ≥ 3 | refused in every order | separate limit (pass budget), fixed here too |
