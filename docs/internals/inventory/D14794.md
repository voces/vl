### D14794 — an intersection of records folds to a one-member union around the merged record, not to the record itself

**runs today and must keep running · the fold's shape is internal: `repOfTy` already answers the struct for the one-member union, and the `$fnsig` tokeniser reads its slot from the member (`repSigSlotTyOf`) · found by the result-kind shadow (`fn_ret_shadow.vl`) on `mkBoth`/`mkAB` · filed 2026-11-01 against master `c9ddb982a`**

Repro:

    type AB = { a: i32 } & { b: i32 }
    function mkAB(): AB { return { a: 1, b: 2 } }
    function sumAB(v: AB): i32 { return v.a + v.b }
    print(sumAB(mkAB()))

Want:

    3

#### Mechanism

The checker folds `{ a: i32 } & { b: i32 }` to a `TyUnion` whose one member is the merged record
`{ a: i32, b: i32 }`, not to the record. Every reader that keys on the record's own type then has
to see through the wrapper: `repOfTy` does (it answers `struct`), and the `$fnsig` tokeniser did
not, so `mkAB`'s result had no token until it read the slot from the member. The cleaner close is
the fold producing the record directly, which retires the see-through.
