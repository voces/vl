### D4961 — a push through an `is K[]` arm is refused when the receiver is also read whole outside the arm

**loud emit reject · clause 2 · the residue of [D4934](D4934.md): the arm's `K[]` replaces the receiver only where every other use is a `.length`, another `is K[]` or a read typed `K[]` · filed 2026-10-15 against branch `d4934-empty-arm-push` over master `e2efbc0af`**

Repro:

    function g<V>(v: V[]) {
      if v is f64[] { v.push(1.5) }
      print(v.length)
      const w = v
      print(w.length)
    }
    const e: i32[] = []
    g(e)
    // vl check: rc 0.  vl run: emitProgram: this `is` arm pushes onto an empty list built with another element type, which cannot hold the pushed value

#### Mechanism

`listFitGrowScan` (wasmEmit.vl) gives a pushed-through arm a `fitGrow*` local only when
`listFitGrowUsesOk` admits every other use of the receiver. `const w = v` reads the receiver
whole at `V[]`, which is the caller's `i32[]` and cannot be the `f64[]` the push filled, so the
arm keeps `LIST_FIT_PUSH_MSG`. A close needs a read at `V[]` to see the `K[]`, which the
instance's `V[]` rep cannot hold.

#### Grading list

The same program without `const w = v` prints `1` (pinned by
`tests/cases/generics/is-list-arm-push-through.vl`).
