### D4961 — a push through an `is K[]` arm is refused when the receiver is also read whole outside the arm

**loud emit reject · needs a ruling · clause 2 · the residue of [D4934](D4934.md): the arm's `K[]` replaces the receiver only where every other use is a `.length`, another `is K[]` or a read typed `K[]` · filed 2026-10-15 against branch `d4934-empty-arm-push` over master `e2efbc0af` · bucket (d), L1 typed IR, secondary (e) (the 2026-11-14 clause-2 map) · witness re-spelled 2026-11-16 at a list nothing fixed: under DECISIONS "An annotation fixes an empty list's element type" the annotated spelling answers by its element**

Repro:

    function g<V>(v: V[]) {
      if v is f64[] { v.push(1.5) }
      print(v.length)
      const w = v
      print(w.length)
    }
    g([])
    // vl check: rc 0.  vl run: emitProgram: this `is` arm pushes onto an empty list built with another element type, which cannot hold the pushed value

#### Mechanism

`listFitGrowScan` (wasmEmit.vl) gives a pushed-through arm a `fitGrow*` local only when
`listFitGrowUsesOk` admits every other use of the receiver. `const w = v` reads the receiver
whole at `V[]`, which is the caller's `i32[]` and cannot be the `f64[]` the push filled, so the
arm keeps `LIST_FIT_PUSH_MSG`. A close needs a read at `V[]` to see the `K[]`, which the
instance's `V[]` rep cannot hold.

**Needs a ruling** (2026-11-17). DECISIONS.md owner ruling (a), "An annotation fixes an empty list's
element type wherever the value goes", does not decide it: it keeps a type an annotation or a write
fixed, and lets a list nothing fixed fit every `is T[]`. It does not say whether a push THROUGH an
`is K[]` arm fixes an unfixed list at `K` for the receiver's other reads. If it does, `g<V>`'s
instance must hold the list at `f64[]` wherever `v` is read whole (`const w = v`), which its `V[]`
rep (`i32[]`, the unbound default) cannot. If it does not, the push itself is the program's error.
The neighbour without `const w = v` runs and prints `1`
(`tests/cases/generics/is-list-arm-push-through.vl`).
