### D3902 — an alias of a capturing nested generic passed as a value, in an enclosing generic instantiated twice, builds invalid wasm

**closed 2026-10-09 by lane SC · runs · was check-clean invalid wasm · found closing D3887 · filed 2026-10-09 against master `9170959d8` · pins: `tests/cases/generics/alias-of-capturing-nested-generic-delivered-as-value.vl`**

Repro:

    function call(f: (n: i32) => void) { f(1) }
    function outer<T>(x: T) {
      function inner<U>(u: U) { print(x); print(u) }
      const k = inner
      call(k)
    }
    outer(7)
    outer("s")
    // vl check: rc 0.  vl run: invalid module

Want:

    7
    1
    s
    1

#### Mechanism

A function value delivered at a concrete function type is instanced through `monoInstanceFor`,
which keyed a capturing nested generic like a module function: every instance of `outer` shared
the first one's `inner` instance, whose env holds `x` at the first type. A call keys it by its
frame (D3827); the value path did not. Two further gaps on the same path: a chain of aliases
(`const j = k`) was not followed at all, so its value trapped even at one instance, and the
alias `Ident` was one node across instances.

Closed: the value coercion sets the frame slot as a call does, follows a never-written alias
chain (`monoGenFnAliasChainFe`), reads an alias a call renamed to one instance as the generic
(D3905), and an alias read as a value is copied per instance like a callee (D3907). A call
through an annotated binding of the alias is not covered (D3926).

Where two instances share a rep (`i32` and `boolean`) the same sharing was a silent wrong value,
not invalid wasm: `outer(7)` then `outer(true)` printed the `i32` frame's `7`, then `1`, for the
boolean frame's `true` (the #3490 review's `u1_bool_noshadow`, 48 such cells in its generator).
