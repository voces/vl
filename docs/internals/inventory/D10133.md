### D10133 — an un-annotated lambda whose result is narrower than a generic function parameter's union result is not adapted to the box

**check-clean invalid wasm · `vl check` rc 0 · `type mismatch: expected (ref $7), found i32`, a union box, inside `len` · clause 1 · CAPABILITY: annotating the lambda's result as the union runs, and so does the same call without the type parameter · found closing [D10031](D10031.md) · present on master `3931f9468` · filed 2026-10-22 against master `3931f9468`**

Repro:

    function len<T>(f: () => T | string) {
      const t = f()
      if t is string { 0 } else { 1 }
    }
    print(len(() => 4))
    // vl check: rc 0.  vl run: the emitted module failed to validate inside `len`: type mismatch: expected (ref $7), found i32; $7 is `union box`, struct {i32, anyref}

Want:

    1

#### Mechanism

Not traced. The checker accepts `() => i32` for `() => T | string` with `T` bound to `i32`, and
the instance reads `f()` as the union box `i32 | string`. The lambda is emitted at its own
narrower result `i32` and no adapter wraps it into the box at the argument, so the instance
reads an `i32` where it expects a box. The non-generic `f: () => i32 | string` adapts the same
lambda, so the miss is the generic instance's argument. D10031's close deliberately binds
nothing at such an argument: there `T` stays unbound for `() => T[] | i32` at `() => [1, 2]`,
which refuses loudly (`'.length' on a receiver the emitter cannot classify`) rather than
reaching this.

#### Ablation

| ingredient changed | outcome | needed? |
| --- | --- | --- |
| the lambda's result annotated, `(): i32 \| string => 4` | runs, `1` | **yes** |
| the type parameter, `f: () => i32 \| string` | runs, `1` | **yes** |
| the type argument explicit, `len<i32>(() => 4)` | loud check reject, `an inferred union return through an un-annotated parameter is not yet supported by codegen` | no |
| the list form `f: () => T[] \| i32, x: T` with `len(() => [1, 2], 0)` | the same invalid wasm, `found (ref $8)` a list | no |
| the list form without `x: T`, `len(() => [1, 2])` | loud emit reject, `'.length' on a receiver the emitter cannot classify` | no |

#### Grading list

Both list-form spellings in the ablation, and the explicit `len<i32>` spelling, whose check
reject concedes the program is type-valid; [D9970](D9970.md)'s generic twin
`take<T>(v: () => T[] | i32)` at `() => [() => "z"]`, which refuses as
`narrowed union atom has no value box`.
