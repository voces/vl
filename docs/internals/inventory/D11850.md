### D11850 — a user string-literal type spelled `#lu<N>` is rendered as the N-th inline literal union

**closed 2026-10-24 — the witness is now a loud check reject that names its type as written, `of type "#lu0"` · was a loud check reject with the wrong type in its message · filed 2026-10-24 against master `4341ada61` · fixed by skipping every closed quoted segment in the two message rewrites (`tyname.closedQuoteEnd`, read by `demangleSpelling` and `inlineLitUnionUnhide`) · pinned by `tests/cases/literal-unions/literal-type-spelled-like-internal-name.vl` and the check-skip case `a literal type spelled like a hidden union alias`**

Repro:

    function pick(u: "x" | "y"): i32 { 1 }
    print(pick("x"))
    const l0: "#lu0" = "c"
    // vl check: rc 1, `cannot assign string to 'l0' of type ""x" | "y""`; want `of type "#lu0"`

#### Mechanism

`inlineLitUnionUnhide` (`compiler/check_types.vl`, reached from `demangleMsg`) replaced
every `#lu<digits>` in a finished message with the members of the inline union that key
names in `cUserTypes`, including text that came from a user's string literal, and
`tyname.demangleSpelling` cut every `$m<digits>` / `$b<digits>` the same way
(`"a$m1"` read `"a"`). In a message, a double-quoted segment holds user text (a literal
type's member, an import specifier, a char literal's suggested string) and never an
internal name, so both rewrites now copy a closed quoted segment as written; an unclosed
quote is a stray character and is scanned as before. The incremental check agrees again:
`skBankNow` refuses to bank a message holding `#` or `$` after rendering, and the literal now
keeps its `#`, so the served check re-checks main and says what the whole check says.

#### Ablation

| a second literal `"#lu1"` with no union 1 | that row reads `"#lu1"` | no (only an existing key) |
