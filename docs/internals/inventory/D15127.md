### D15127 — a function result or a record literal's field holding a built container's read is emitted at a narrow row interned elsewhere

**closed · now runs, prints `4` then `4` · was check-clean invalid wasm, clause 1 · the residue of [D15126](D15126.md) · filed 2026-11-03 against master `7ea18bb0e` · closed by the PR that filed it: the checker's store-rep column holds every un-annotated binding whose initializer a build decides (`storeHeldAt`, check_store_rep.vl), and stamps an inferred function's returned reads with their build (`storeRetsResolve`), which the result row already reads · fixture `soundness/built-container-read-returned-or-fielded-beside-narrow-row-runs.vl` · named set `d15127-held-result-beside-narrow-row`**

Repro:

    type J = { f: i32 | null }
    function mk() { { f: 4 } }
    const wideJ: J = mk()
    const xs = [mk()]
    const plain = { f: 5 }
    function first() { return xs[0] }
    const v = first()
    print(v.f)
    print(wideJ.f ?? 0)
    // vl check: rc 0.  vl run: invalid module

Want:

    4
    4

#### Mechanism

`first`'s result row comes from its returned values' rep stamps (`criRowByStamp`). `xs[0]` was
stamped at its own type `{f: i32}`, so the result was emitted at the narrow row `plain` interns
while the read delivers `J`. A record literal's field, `const w = { f: xs[0] }; const v = w.f`,
fell the same way: no producer held `v` at the field of `w`'s build.
