### D15288 — a record literal spread into a list built at a wider record, beside another list literal of its own record type, is check-clean invalid wasm

**closed 2026-11-04 · runs, prints `7` then `1` · was check-clean invalid wasm, `vl check` rc 0 · clause 1 · found writing [D15285](D15285.md)'s fixture · filed 2026-11-04 against master `930a8aae` · closed by the literal's reader taking its record solve's closed stamp ahead of the parameter its call closes (`litRepTyAt`), and by a pin-time fit of a forwarder's literal writing no template stamp (`argCstrFitsAt`), so one instance's pin no longer decides the shared literal's stamp · fixture `tests/cases/soundness/record-literal-spread-into-built-list-beside-own-list-runs.vl`**

Repro:

    type J = { f: i32 | null }
    function mk() { { f: 4 } }
    const wideJ: J = mk()
    const xs = [mk()]
    xs.push(...[{ f: 7 }])
    const os = [{ f: 1 }]
    print(xs[1].f ?? 0)
    print(os[0].f)

Want:

    7
    1

#### Mechanism

The spread literal's reader asked the parameter its call closes before the literal's own closed
stamp, so the push's `{f: i32}[]` parameter, settled by the other literal's row, won over the `J[]`
the record solve built it at. Taking the stamp first exposed a second writer: a hole forwarder's
pin re-asked the literal's fit at one instance's type and stamped the template node every instance
shares.

Original note: The spread literal `[{ f: 7 }]` is `{f: i32}[]` built at `J[]`
(D15235). With another `{f: i32}[]` literal anywhere in the module, the module fails to validate
(`expected (ref null $type), found (ref $type)`), so something the spread lowering reads is keyed by
the literal's own list type, which the other literal's row then decides.
