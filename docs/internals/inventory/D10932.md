### D10932 — an un-annotated parameter's `(string | null)[]` field read at a `null` element asserted the element non-null

**closed 2026-10-23 — the filed repro RUNS and prints `nil` · was a trap after load, `wasm trap: null reference` · clause 1 · found by lane D10880 grading the argument position of `generic-record-nullable-tyaram-list-field-literal.matrix.vl` · filed 2026-10-23 against master `8be0b10be` · fixture `tests/cases/inference/hole-param-nullable-string-list-field-read.vl`**

Repro:

    function take(a) {
      print(a.g[1] ?? "nil")
    }
    const r: { g: (string | null)[] } = { g: ["s", null] }
    take(r)
    // vl check: rc 0.  vl run: wasm trap: null reference

Want:

    nil

#### Mechanism

`exprNulStrArray` asked `nodeArrayElemIsNulStr` of the read's receiver, which reads the type
recorded at the node. Inside a hole parameter's body that is the hole, so the element was
classified as a plain string and the read emitted `ref.as_non_null`. The check now asks
`arrElemIsNulStrAt(exprIx, fnIx)`, which reads the element type at the instance.
