[D2585](D2585.md) · owner ruling D2390 (a) extended to places · filed 2026-09-26 against master

Repro:

    type H = { f: i32 | string | null }
    function go() {
      const p: H = { f: 4 }
      const q = p
      if p.f != null {
        q.f = null
        print(p.f == null)
      }
    }
    go()
    // vl check: rc 1, "cannot compare i32 | string with null" at `p.f == null`

#### Mechanism

`retireNarrowingsForWrite` ended only the narrowings keyed on the write's own place (`q.f`) and
the paths under it. `p.f` names the same field of the same object once `q = p`, but its key
shares no prefix with `q.f`, so the checker still read `p.f` at the narrowed `i32 | string`
after the write, and a null compare against a non-nullable type is refused. The close matches
the write's SHAPE (`.f`, `[0]`, `["k"]`, `[]` for a variable subscript) against every step of
every live key, the rule a call's write summary already used (`shapesHitKey`). A field step
matches only when the two receivers' types may be one object; a store the narrowed type admits into
the key's last step keeps the narrowing. A `const` bound to a new object whose name its root uses
only as a receiver (`x.f`, `x[i]`, never a value, a method receiver or a getter's) is the only
holder of that object, resolved as the binding in scope at the write: a write through it reaches
no other key, and a write through anything else never reaches its first step. A retirement settles like a call's (`crPathCallRetire`):
the key is banked for the emitter after the statement, and a read inside that statement, in a
loop that read the path earlier, or in a nested function that may run later is refused.
