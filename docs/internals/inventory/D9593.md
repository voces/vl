Repro:

    function id<T>(x: T): T { x }
    function mk() {
      print("mk")
      return id
    }
    const v = mk()
    const w = v
    if w(2) == 2 {
      print(w("abc"))
    }
    // vl check rc 0.  vl run: emit error: emitProgram: a generic function taken as a value reaches no call that fixes its type

Want:

    mk
    abc

#### Mechanism

A `const` bound to a call that always returns one generic (`fsConstRet`, fn_split.vl) and
called at two types is served by the source slot-split planner: `fsPlan` asks the binding,
and each per-type slot reads the generic afresh while the original binding still runs the
call once. The ask was made only for the binding whose initializer is the call. An alias
`const w = v` is a different binding, so nothing asked it, and `fsSlotSrc` had no source for
a read of it that was not the call itself. The close asks each un-annotated `const` alias
down the chain (`fsAskConstAliases`) and resolves a slot's source through the chain to the
call's generic (`fsConstAliasRet`), so `w`'s slots read `id` and `mk` still runs once, at
`v`.
