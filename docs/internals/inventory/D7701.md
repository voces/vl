### D7701 — one generic delivered at two function types, widened into one union-of-function-types binding, compares unequal

**closed 2026-10-20 by lane L1 · runs, prints `true` · was check-clean silently wrong, wrong value · a function-value arm of a union `==` admits the other operand in any function-value arm of the union, then compares the two closures by `decl` and env (`emitUnionUnionEq` and `emitUnionBoxEqStaged`, wasmEmit.vl) · pin: `tests/cases/closures/function-values-in-two-union-arms-equality.vl` · `vl check` rc 0 · clause 1 · under the [D7180](D7180.md) ruling a function value's identity is its declaration, so `u == v` is `true` across the arms of a union (option (a)), while the direct `p == q` stays a check error (`cannot compare (i32) => i32 with (string) => i32`) · the same two deliveries compare equal unwidened since [D7481](D7481.md), and so do two deliveries at ONE type widened into the union · found closing [D7481](D7481.md) · present on master `18100a6d2` · filed 2026-10-20 against master `18100a6d2`**

Repro:

    function two<T>(x: T): i32 { return 1 }
    const p: (x: i32) => i32 = two
    const q: (x: string) => i32 = two
    let u: ((x: i32) => i32) | ((x: string) => i32) = p
    let v: ((x: i32) => i32) | ((x: string) => i32) = q
    print(u == v)
    // PRINTS false

Want:

    true

#### Mechanism

Union `==` compares the two boxes' arm tags before it compares payloads, and `p` and `q` sit
in different arms, so the comparison is `false` before either closure's `decl` field is read.
Both closures carry the same `decl` since [D7481](D7481.md). The fix, if the ruling keeps
`true`, compares function-arm payloads by `decl` and env across arms; it lives in the union
equality core.
