#### Mechanism

`s`'s literal-let pin is a hole, `r.y` with `r` narrowed by `!= null` (an `HD_GNOT` over the walk's
`HD_ITER2`). The solve writes a hole pin as an annotation only when each derivation of its recipe can
be spelled again in the re-check's new arena (`lbiHoleKindSpelled`), and `HD_GNOT` could not, because it
names the type it subtracts. So `lbiApplyHolePin` wrote nothing, yet `pinApply("literal")` reported
progress whenever a pin was pending. Each round re-checked into the same pending pin, so the phase could
not converge at any budget (a probe at 12 rounds logged `HD_GNOT` declined every round); the budget
only chose when `pinUnsettled` gave up.

Two changes close it. The recipe records whether a step is a hole less `null`, and the re-mint passes
that arena's `null`, so the `!= null` narrow is spelled. And a literal round that writes no annotation
is no progress: a pin no round can write is refused at once by the same sentence, not after the
budget's re-checks. An `is T` narrow over another type still names an arena type, and keeps that
refusal (`function t(r) { let s = 0; if !(r is string) { s = s + r } }`, the same on master). Named set
`d16566-null-narrowed-literal-pin`.
