### D3886 — a block-local function reading a captured `let` of its enclosing generic's parameter type, which the enclosing body writes after the function's declaration, reads it at the rep and prints `1` for a `boolean`

**check-clean silently wrong · found by the rv3466 review of #3465/#3466 · related to D3831 and D3829 (they covered only the never-written form) · filed 2026-10-08 against master `a1c9be3c4`**

Repro:

    function outer<T>(x: T) {
      let m = x
      function inner() { print(m) }
      inner()
      m = x
    }
    outer(true)
    // vl check: rc 0.  vl run: rc 0
    // PRINTS 1

Want:

    true

#### Mechanism

A captured binding the enclosing body writes is held in a cell, and the cell is typed from the
capture's rep rather than from the enclosing instance's binding of `T`. `boolean` and a literal
union of integers share `i32` with the rest of the family, so the read prints the integer. The
never-written capture takes the path D3831 and D3829 closed (the nested instance binds the
enclosing parameters), which is why `const m`, and a `let` that is never reassigned, print
`true`. The inner function need not be generic, and a lambda in place of the nested function
reads the same wrong value (`const g = () => print(m)`). Only a write in the enclosing body
AFTER the capturing function's declaration matters, whether or not it is also before the call.
The sentence is a reading of the ablation; the cell's type is not printed here.

#### Ablation

Every row is the witness with one ingredient changed; "outcome" is `vl run`.

| ingredient changed | outcome | needed? |
| --- | --- | --- |
| `const m = x` | prints `true` (right) | **yes** |
| `let m = x` and no `m = x` at all | prints `true` (right) | **yes** |
| the write moved BEFORE `inner`'s declaration | prints `true` (right) | **yes** |
| the write moved between the declaration and the call (`m = x; inner()`) | prints `1` (wrong) | no |
| the write moved INTO `inner` (`function inner() { m = x }`, then `print(m)` in `outer`) | prints `true` (right) | **yes** |
| `inner` made generic (`function inner<U>(u: U) { print(m) }`, `inner(0)`) | prints `1` (wrong) | no |
| a lambda in place of `inner` (`const g = () => print(m); g()`) | prints `1` (wrong) | no |
| `print(m)` after the write in `outer` itself, beside the nested read | prints `1` then `true` | n/a |
| `print(m)` in `outer` only, no nested function | prints `true` (right) | **yes** |
| `T` bound to `string`, `f64`, `i32` (`outer("s")`, `outer(1.5)`, `outer(7)`) | prints `s`, `1.5`, `7` (right) | **yes** |
| `T` bound to `i32` then `boolean` in one program | prints `7` then `1` | n/a |
| `outer(false)` | prints `0` (wrong) | n/a |
| `T` bound to a string-literal union (`outer(e)` with `e: "a" \| "b"`) | prints `a` (right) | n/a |
| a non-generic outer (`function outer(x: boolean)`) | prints `true` (right) | **yes** |

#### Grading list

Programs that run correctly today and must keep running: the unwritten forms (D3831's pins), the
write before the declaration, the write inside the nested function, the non-`boolean` bindings,
and the non-generic outer. Grade the close at an integer-literal-union `T`, which shares the
rep with `boolean`, at a lambda and at a nested function, and at a nested generic called from
the enclosing body. `keep/c06.vl` (a nested generic that reads a written `let` and is called
from a sibling function) is NOT a witness on master: it is refused loudly, `a nested generic
that captures its enclosing function's variables, called from a function nested in a second
instance of that enclosing function, has no instance to call`, so it becomes this row's cell
only if that refusal is lifted.
