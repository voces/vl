### D3394 — a `??` chain whose first link is a nullable loop value finds no rep for the chain

**closed 2026-10-17 as `runs` · was loud emit reject · the outer `??` now classifies the inner one's arm tail with the loop's arm binding in scope (`stmtArmScopeOpen`, `emit_collect.vl`), as D5333 · fixture `tests/cases/unions/coalesce-arm-local-nullable-tail.vl` · still refused on master `3d78a8854` · the #3315 review's `r3`, `r1`, `r4` (`rv3315-25182/p/`) · filed 2026-09-30 against master `4ff12b994` with #3315 applied**

Repro:

    type R = { x: i32 }
    function t(n: i32) {
      const w: R = { x: 102 }
      const o: R | null = null
      const v = (for x in [1, 2, 3] { if x == n { break { x: 100 } } }) ?? o ?? w
      print(v.x)
    }
    t(0)
    t(2)
    // vl check: rc 0.  vl run: emitProgram: `??` over this nullable value is not supported yet

Want:

    102
    100

#### Mechanism

[D3370](D3370.md)'s one level up. `??` groups to the left, so the chain is `((loop) ?? o) ?? w`.
D3370's close moves the inner `??` onto the loop's arm binding, `if true { …; $lv ?? o } else
{ __trap__() }`, which is still nullable, and the outer `??` then classifies that if-expression
through an arm tail naming a binding no scope holds yet, as the inner one did before the close.
The right-grouped spelling, `(loop) ?? (o ?? w)`, runs.

#### Ablation

| ingredient changed | outcome | needed? |
| --- | --- | --- |
| `(loop) ?? (o ?? w)` | runs | **yes** (the loop value under a nullable link) |
| `(loop) ?? (loop) ?? { x: 102 }` (`r1`) | same refusal | no |
| `o ?? (loop) ?? w` (`r4`), the loop the middle link | same refusal | no |
| `o ?? o2 ?? w`, no loop | runs | **yes** |
