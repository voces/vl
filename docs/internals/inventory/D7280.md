    function add(a, b) { return a + b }
    function apply2(g: (a: i32, b: i32) => i32) {
      print(g(1, 2))
    }
    const fs = [apply2]

    // vl check: rc 0.  vl run: emitProgram: cannot take the generic function `add` as a value — a function value carries ONE signature, and parameters `a`, `b` are un-annotated

Want:

#### Mechanism

A call through a function value hands each generic function argument to the callee's
parameter type only where the callee has an annotation to read it from
(`monoCoerceAtValueParams`, through `monoCalleeAnnNode`), and it ran only for a callee named
by an identifier. A list element, a loop variable and an un-annotated alias have no
annotation, so `add` reached the value floor with no instance. The callee's recorded type is
concrete here (`(g: (a: i32, b: i32) => i32) => void`), so it now gives the parameter type
when there is no annotation, and the call path for every callee shape asks it.
