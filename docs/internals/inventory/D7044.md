### D7044 — a generic returning `(T | string)[]` built from a literal at a literal-union pin is invalid wasm inside the instance

**check-clean invalid wasm · clause 1 · open · found by lane L6 step 3's ablation of [D4041](D4041.md) · the same on master `6ca1ebc5c` · filed 2026-10-19 against master `6ca1ebc5c`**

Repro:

    type K = "a" | "b"
    function l<T>(x: T, o: string): (T | string)[] { return [x, o] }
    const a: K = "a"
    const w: (string | K)[] = l(a, "z")
    print(w[0])
    // vl check: rc 0.  vl run: invalid module inside `l`: type mismatch

Want:

    a

#### Mechanism

Not localised. The instance at `T = K` builds the array literal `[x, o]` of the template's
`(T | string)[]`, where `x` is the `K` atom and `o` a string. The validator fails inside `l`. That
says the element store and the list's rep disagree within the instance. [D2968](D2968.md) is the
spread spelling of the same return type. Its validator names a `std:str` instance instead, so
whether the two share a mechanism is not ablated.
