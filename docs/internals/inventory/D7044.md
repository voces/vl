### D7044 — a generic returning `(T | string)[]` built from a literal at a literal-union pin is invalid wasm inside the instance

**closed 2026-10-19 by lane L6 · runs, prints `a` · was check-clean invalid wasm · clause 1 · a union naming a type parameter that collapses to one member at the pin (`T | string` at `T := K`) is spelled as that member, and a grouped list element (`(T | string)[]`, `(T)[]`) is canon'd, at every parameter, local and return pin, as the direct annotation is · pins: `tests/cases/generics/collapsed-union-list-at-the-pin.vl` · found by lane L6 step 3's ablation of [D4041](D4041.md) · the same on master `6ca1ebc5c` · filed 2026-10-19 against master `6ca1ebc5c`**

Repro:

    type K = "a" | "b"
    function l<T>(x: T, o: string): (T | string)[] { return [x, o] }
    const a: K = "a"
    const w: (string | K)[] = l(a, "z")
    print(w[0])
    // vl check: rc 0.  vl run: invalid module inside `l`: type mismatch

Want:

    a

#### Mechanism

`monoSubstAnn` substitutes `K` into the annotation text, giving `(K | string)[]`, and
`monoPinUnionName` canon'd only a top-level union, while `monoPinMintedUnion` returned the raw
name for a type with no ref arm. The array literal reads its rep from that name: the element
`K | string` counted two atoms and took a union-box list row. The signature reads the type,
which is `string[]` once the atom drops under the string (the litunion atom ruling), so the
literal built a box list where a string list was declared. A probe on the literal's rep read
`name=(K|string)[] kind=strlist slot=1` in the instance and `name=string[] slot=0` at the direct
spelling. The scalar `const r: T | string` and the `T := string` spelling (`(string)[]`, a loud
`only i32[] arrays` refusal) were the same name left uncanonicalized.
[D2968](D2968.md), the spread spelling, still fails, inside `ws` now and no longer in `std:str`.
