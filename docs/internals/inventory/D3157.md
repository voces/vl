### D3157 — `?? null` over a hole's niche-valued map read prints the niche's raw i32

**check-clean silently wrong · clause 1 · open · found by the #3282 review (`p5/s2`, `p5/s3`) · the same on master `b1794003a` · filed 2026-09-29 against master `b1794003a`**

Repro:

    type AB = "a" | "b"
    type R = { m: {[i32]: AB | null} }
    function mk(): R {
      const m: {[i32]: AB | null} = Map()
      m[3] = "b"
      m[4] = null
      { m: m }
    }
    function use(p) {
      print(p.m[3] ?? null)
    }
    use(mk())
    // PRINTS 0

Want:

    b

#### Mechanism

Not localised past the ablation. The fused `??` over the niche-valued map reads the raw i32 at
the pin: an atom id, or the `-1` / `2` null sentinel. A `null` default keeps the result
`K | null`, and `print` of the instance's result reads it as a plain `i32`, so the atom is not
decoded and the sentinel is not read as `null`. A missing key prints `null`, so the rep of the
fused read and the rep the consumer reads disagree only where the map holds a value.

#### Ablation

| ingredient changed | outcome | needed? |
| --- | --- | --- |
| `function use(p: R)` | prints `b` | **yes** (the hole) |
| `p.m[4] ?? null`, a stored `null` | prints `-1` | no |
| `p.m[9] ?? null`, a missing key | prints `null` | **yes** (a stored value) |
| `?? "a"`, a member default | prints `b` | **yes** (the `null` default) |
| a `{[i32]: boolean \| null}` map, `?? null` on a stored `false` | prints `0` | no |
