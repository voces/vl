#### Mechanism

`monomorphize` (`emit_mono.vl`) returns at once for a program with no `<T>` generic and no
concrete higher-order function (`monoHasConcreteHOFParam`), which is how the compiler's own
source skips the pass. A concrete higher-order function is one with a function-typed parameter
and an annotated result (`feHasClosureParam`). The compiler has 12 functions with a
function-typed parameter, every one an un-annotated hook setter (`rlLateRowsOn(f: …)` and its
siblings in `emit_state.vl`), so none qualifies. One annotated function with such a parameter
runs the whole pass over 17,519 functions: the guest profile's `emitProgram` share goes from
9,968 to 12,880 samples while the check side does not move (13,293 against 12,758). Inside the
pass, `monoDeclIsAssigned` scans the whole arena once per call through a function-valued name
(482 self samples, all from `monoWalkIdentCall`), so its cost grows with the program times the
number of such calls. The output is unchanged in size (6,400,684 against 6,401,039 bytes, a
different source).

#### Grading list

Narrowed 2026-11-15 by indexing the arena's plain `=` once (`monoDeclIsAssigned`) and walking,
in a program with no generic, only the bodies holding a call of a concrete higher-order function
(`monomorphize`). On master's tree with one annotated higher-order function added, L2 fuel goes
from 97.62G to 91.81G against 89.58G without it, output byte-identical; the median of 10 CPU
goes from 39.00 s to 38.88 s against 37.02 s, so the instructions removed were cheap ones and the
trigger's time is still to find. A 1,500-function program with one such function goes from
1.80G to 1.74G, most of its remaining 0.69G in `elabSetCallRows`, the function set of the
callback parameter, not the walk.
