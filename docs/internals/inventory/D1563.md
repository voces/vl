### D1563 — three global boundaries ARM `pendingVariantIdx` and none of them clears it, so a nullable union-ARM global retypes the next nullable-struct global's `null`

**closed 2026-09-03 — the witness runs and prints `7` then `0` · was check-clean invalid wasm (`vl check` rc 0, `vl check --codegen` and `vl build` both `type mismatch: expected (ref null $type), found (ref null $type)` in `function[7]`, the start function) · clause 1 · fixed by clearing the variant seed at the two global-init loops (`emitStartFnCode`, `emitGlobalSection`) and at `emitAssign`'s `global.set` arm, the three boundaries that set it · reported by the glean session, VL-029, `~/glean/docs/vl-issues.md`, probe `~/glean/vl-probes/VL-029-two-nullable-globals.vl` · **also closes [D1380](D1380.md)**, whose poisoner is the same seed surviving `modReset()`**

Repro (prints `7` then `0`):

    type E = { msg: string }
    type T = { n: i32, m: i32 }
    type C = { a: i32, b: i32 }
    function mk(x: i32): T | E {
      if x < 0 { return { msg: "no" } }
      return { n: x, m: x }
    }
    let t: T | null = null
    let c: C | null = null
    export function go(x: i32): i32 {
      const r = mk(x)
      if r is E { return 0 }
      t = r
      r.n
    }
    export function getC(): i32 { if c != null { c.a } else { 0 } }
    print(go(7))
    print(getC())

#### Mechanism

`t: T | null` is the `nulvariant` niche, because `T` is an ARM of the union `mk` returns.
`emitStartFnCode`'s per-global block seeds `pendingVariantIdx` with that arm index so the
cell's own `= null` can lower as `ref.null $T` — and the reset block at the foot of the loop
clears eleven seeds, `pendingStructIdx` among them, but not that one.
`emitNullLitNode` reads `pendingVariantIdx` BEFORE `pendingStructIdx` and deliberately does
NOT consume it (a `| null` arriving as a tail expression rather than a `return null`
statement needs it to persist). So the arm stayed armed across the loop iteration and `c`'s
own `= null` — a `nulstruct` cell, which seeds only `pendingStructIdx` — took the variant
arm instead.

The two elided heap types, from `wasm-tools print` on the written module. `T` and `C` are
`(struct (mut i32) (mut i32))` twice over: structurally identical, distinct types, because a
defined type's identity is its canonical rec group PLUS its index in it. The globals section
is correct and the START FUNCTION is not:

    (type (;0;) (struct (field (mut i32)) (field (mut i32))))   ;; C = { a, b }
    (type (;1;) (struct (field (mut i32)) (field (mut i32))))   ;; T = { n, m }
    (global (;1;) (mut (ref null 1)) ref.null 1)                ;; t — correct
    (global (;2;) (mut (ref null 0)) ref.null 0)                ;; c — correct
    (func (;7;) (type 10)                                       ;; the start function
      ref.null 1
      global.set 1                                              ;; t = null   ok
      ref.null 1                                                ;; <-- T's heap type
      global.set 2)                                             ;; c = null   INVALID

`expected (ref null $type)` is `(ref null 0)` = `C`; `found (ref null $type)` is
`(ref null 1)` = `T`. Both names elide, so the message is a tautology and the ablation is the
finding.

The same seed is armed and never cleared at TWO more boundaries, and the fix is at all three:
`emitGlobalSection`'s const-cell loop (today its literal consumes the seed, so it is symmetry
rather than a live witness) and `emitAssign`'s `global.set` arm, which IS live — `t = r` over
an arm cell leaves the seed armed for the rest of the function body, so a later `c = null`
into a different nullable struct is the same invalid module with the declaration order
already swapped. The `let` and return boundaries clear struct AND variant and always have.

The minimal witness is five declarations and a `print`, with no call site at all:

    type E = { msg: string }
    type T = { n: i32, m: i32 }
    type C = { a: i32, b: i32 }
    function mk(x: i32): T | E {
      if x < 0 { return { msg: "no" } }
      return { n: x, m: x }

    let c: C | null = null
    print(1)

**Two corrections to the consumer's table**, both from re-running it verbatim on the seed
this row was fixed against. `mk` returning `T | null` does NOT reproduce — with no union
declared, `T` is not an arm, `t`'s cell is `nulstruct`, and nothing seeds the variant; the
union ARM is the ingredient, not the nullability. And "the call's result never reaching the
global" runs only because that edit also removes what makes `T` an arm: `mk` alone, with
`go` deleted entirely, still fails.
