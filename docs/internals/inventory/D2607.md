### D2607 — an empty `[]` argument for a generic's `T[]` binds `T` to `i32` before the argument that names it

**closed 2026-09-26 — the filed repro RUNS and prints `3` · was check-clean invalid wasm,

Repro:

    type B = { v: i32 }
    function f<T>(xs: T[], d: T) { for e in xs { return e }; return d }
    print(f([], { v: 3 }).v)
    // vl check: rc 0.  vl run: invalid module, in the top-level code:
    // "type mismatch: expected i32, found (ref $type)"

#### Mechanism

`monoInstantiate` binds each type parameter at its first use, from that argument's pin. An
empty list literal has no element to name, and its recorded type names none either, so the pin
ladder answered its `i32[]` default and `T := i32`; the later `d: T` then took that binding and
the instance was `f(xs: i32[], d: i32)` while the call passed a record. The close binds, before
that loop, each parameter whose first use is an empty literal from its first later use that
names an element (`monoPreBindPastEmptyLit`).
