### D2951 — at a pin that cannot be null, a `??` over a type parameter keeps its dead default in the re-check's type

**closed 2026-09-28 · was a loud emit reject, clause 2, on master `e9fdc10d9` (and silently wrong at the `boolean` pin's list and generic-pass positions) · found by the CK lane's generic-join grid (`coal` join) · fixture `tests/cases/generics/coalesce-dead-default-at-pin.vl`**

Repro:

    function g<T>(a: T, c: boolean) {
      const r = a ?? 5
      r
    }
    function k(c: boolean) {
      print(g("x", c))
    }

    // vl check: rc 0.  vl run: emitProgram: narrowed union atom has no value box

    x

#### Mechanism

Inside the body, `a ?? 5` over `a: T` is a deferred `HD_COAL` result hole, and a pin
substitutes it through `substHoleTyReal`. That arm joined the pin's non-null part with the
default (`string` with `i32`, so `string | i32`) whether or not the pin could be null. The
concrete `??` over a non-nullable operand types the default as dead and answers the operand's
own type (`checkBinExprNodeReal`). So the call's type named an `i32` member that no value
carries, and the emitter had no box for it. Closed by answering the pin itself when the pin is
a primitive (`string`, `boolean`, a number) and the hole's base is a declared type parameter.
A union, record or list pin keeps the join. At a non-nullable union pin (`i32 | boolean`, `K`,
`string | i32`) the instance still lowers a bound `??` at the joined box, and answering the pin
lost 42 of 224 union-pin cells that run on master. A record pin lost `v: P | i32 = f()` through a
closure (`ref valtype with no interned shape`). A pin nullable only through an aliased member
(`type I = i32 | null; I | boolean`) is a union and is excluded too. An inference hole keeps the join
its instance lowers today. With the rule applied to holes as well, four `boolean`-pin cells
printed `1`/`0` for `true`/`false`, so the un-annotated spelling is left open (grading list).
