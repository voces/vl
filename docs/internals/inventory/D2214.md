### D2214 — a `.filter` or `.map` result delivered straight into a `readonly Shape[]` builds an invalid module, though the same result bound to a const first runs

**check-clean invalid wasm · clause 1 · `.filter` and `.map` over a record list, binding and argument · filed 2026-09-23 against master `327b15510`**

Repro:

    type Circle = { r: i32 }
    type Sq = { s: i32 }
    type Shape = Circle | Sq
    const a: Circle[] = [{ r: 1 }, { r: 5 }]
    const w: readonly Shape[] = a.filter((c) => c.r > 2)
    const s = w[0]
    if s is Circle { print(s.r) }
    // vl check: rc 0.  vl run: invalid module — type mismatch: expected (ref null $type), found (ref $type)

#### Mechanism

Not yet ablated past the rows below. A `readonly Shape[]` destination over a `Circle[]` source
takes the D791 element-converting copy at the delivery site, keyed on the source value's
emitted ref-list row (`exprEmittedRefListSlot`). A `.filter`/`.map` call result delivered with no
name of its own reaches the site with no row the copy recognises, so the `Circle[]` wrapper is
handed to the `Shape[]` slot unconverted. Bound to a `const` first, the binding's row answers and
the copy runs. It predates the readonly-only rule ([D2161](D2161.md)), but that rule's messages
now steer a refused mutable `Shape[]` toward exactly this `readonly` spelling.

#### Ablation

| spelling | outcome | needed? |
| --- | --- | --- |
| the witness (`.filter` at a binding) | invalid module | — |
| `a.map((c): Circle => c)` at a binding | invalid module | method: no |
| either, as an argument to `(xs: readonly Shape[])` | invalid module | position: no |
| the result bound to `const t` first, then delivered | runs | the unnamed result: **yes** |
| `mapIndexed(a, …)` from `std:array` | runs | the builtin method: **yes** |

#### Grading list

The witness and each ablation row, and `a.slice(0)` at the same positions.
