### D16777 — a maker's hole lambda stored into a map and read back through `.values()` keeps its own result at a function type returning `f64`

**loads then traps · `vl check` rc 0, `wasm trap: indirect call type mismatch` · clause 1 · found by the maker/map/relay hunt · filed 2026-11-16 against master `6fb5ac348`**

Repro:

    function deliver() { return (a) => a + 1 }
    const m: { [string]: (a: i32) => f64 } = Map()
    m["k"] = deliver()
    const vs = m.values()
    print(vs[0](3) / 8.0)
    // vl check: rc 0.  vl run: wasm trap, indirect call type mismatch

Want:

    0.5

#### Mechanism

The lambda's result is decided by the calls the lambda reaches ([D16711](D16711.md), `elabLamDeliveredRet` in emit_elab.vl), found by the call search `elabSlotClimb` / `elabReadOn`. From the store it reaches the map's value slot (`v`); a `.values()` call over the map hands those values out as a list's elements, a step the search's path walk does not take (`elabElemMethod` covers list methods only).

#### Ablation

| --- | --- | --- |

| `m["k"]` read directly | runs, `0.5` (with [D16752](D16752.md)'s close) | **yes**: `.values()` |

#### Grading list

`for f in m.values() { print(f(3) / 8.0) }`.
