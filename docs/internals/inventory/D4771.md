### D4771 — `is K[]` over an `i32` list answers true whatever its elements are, though `is` tests value fit

**check-clean silently wrong value · clause 1 · found closing D4320, whose witness now takes the `is K[]` branch for `[5, 6]` · the same answer is given on master for a plain `i32[]` binding · related to D3885 (`is` is structural) · filed 2026-10-14 against master `bd9e38039`**

Repro:

    type K = 0 | 1
    const b: i32[] = [5, 6]
    if b is K[] { print(1) } else { print(0) }
    // vl check: rc 0.  vl run: prints 1

Want:

    0

#### Mechanism

`K[]` and `i32[]` ride one list rep, so a list-to-list `is` is decided from the rep and folds to
true; no element is tested against `K`. The owner's D3885 ruling makes `is` a value-fit test
for record arms, and this row asks whether that reaches list elements: either the test walks
the elements, or the checker says the test is decided by type and the D3885 hint names it.
