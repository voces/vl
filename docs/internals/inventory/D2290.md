### D2290 — the map probe's wrap-trap (D2280) was a bare `unreachable`, with no reason a caller could read

**closed 2026-09-23 — the witness prints `done`; the broken invariant it guards is unreachable under
correct operation, so this row's own witness never trips the trap. Verified separately by
temporarily breaking `__map_resize__`'s growth gate: the seed then prints `map probe found no
free slot (internal invariant)` before the trap, exactly as `__trap__("reason")` streams its
own message · reported in review of #3101 · filed against master `b088e0749`**

Repro:

    const m: {[i32]: i32} = Map()
    for k in 0 until 200 {
      m[k] = k
      if k >= 4 { m.delete(k - 4) }
    }
    print("done")
    // prints done

#### Mechanism

`emitMapProbeBackEdge`'s wrap-trap (D2280) was a bare `fbUnreachable()` — a real user hitting it
would see a generic wasm trap with no indication of what broke. It now streams a reason through
`emitMapProbeTrapReason`, the same `__print_char__`/`__print_str_flush__` pair `__trap__("reason")`
and the `as!` cast trap use, gated on `gImports >= 4` (the module already reserving the print
family) rather than forcing the reservation itself: the self-hosted compiler is the heaviest user
of `Map` in the tree, and every consumer instantiates it with an EMPTY linker (`cli-design.md`,
"defaultScope, std, and sync") — forcing the reservation on any `Map` use would make the compiler's
own seed uninstantiable. A program with no other reason to print still falls back to a bare
`unreachable`, never a call to the wrong function index.

#### Ablation

| ingredient removed | outcome | needed? |
| --- | --- | --- |
| a `print`/`__log__`/`__trap__` call elsewhere in the module | reason not streamed, bare `unreachable` on the (unreachable) trap | **yes**, this is the fallback, not a defect |
| the self-hosted compiler's own `Map` use | irrelevant to this row; the compiler prints nothing itself, so it always takes the fallback | n/a |
