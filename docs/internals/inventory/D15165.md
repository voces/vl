### D15165 — a function written through a const alias of a record's list field passes check and builds invalid wasm

**closed · runs, prints `1.5` · was check-clean invalid wasm, `type mismatch: expected i32, found (ref $2)` in the module's top-level code · clause 1 · found closing [D15138](D15138.md): reading through the alias, `ys[0](3)`, runs · filed 2026-11-03 against master `d467911e` · closed 2026-11-03: a field's write summary follows a binding bound once to a read of the field (`cwSlotProjAliasWrites`, check_write_scan.vl), under the rule a list's alias already follows (`cwSlotAliasPathOf`, shared with `cwSlotAliasOf`), so the decision tags the field's set with the alias's write in it. A nested field's alias is [D15191](D15191.md); reading through the alias first, which printed a wrong value, is [D15192](D15192.md)**

Repro:

    function inc0(a) { return a + 1 }
    function half(a) { return a / 2.0 }
    const r = { xs: [inc0] }
    const ys = r.xs
    ys[0] = half
    print(r.xs[0](3))
    // Want: 1.5

#### Mechanism

The write `ys[0] = half` goes through a `const` alias of `r.xs`, and the read goes through the field. The element the field read calls holds an `i32` while the write stores a closure. The same program reading `ys[0](3)` runs, and so does the list spelling `const ys = xs` ([D14647](D14647.md)). Unchanged by D15138, which widens the field only over writes through `r`.
