#### Mechanism

The elaboration re-checks `f`'s instance (`elabSettle` → `elabOneAt` → `monoRecheckBegin`), and
the store `t = a` reaches `checkAssignStore` → `nhFillLinked` (check_relate_core.vl), which fills
the null hole of `let t = null` in place through `tyMutBump`. Traced with a trap in `tyMutBump`
under emit. The hole is the instance's own, minted fresh by the re-check's `letDeclInferredBound`,
but the bump named no row, so `tyMutBump` could not see that and moved the emit epoch, and
`emitProgram`'s seal check refused the build. A mono re-check never writes a template's row in
place (coordinator ruling); this one did not, it only failed to say so.
