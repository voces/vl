### D15448 — a lambda written to a `let` seeded with a function that returns nothing traps when called

**closed 2026-11-05, runs, prints `L` then `5`, with the split plan on and off · was loads then traps, clause 1 · closed with [D15449](D15449.md): the binding's set is tagged, so the call dispatches to the lambda at its own signature instead of calling a closure built at the binding's · found closing D15015 under the owner ruling 2026-11-05, B2 · filed 2026-11-05 against master `d7080b052`**

Repro:

    function inner(u) { print("I"); print(u) }
    const h = (x) => { print("L"); print(x); x }
    let q = inner
    q = h
    q(5)

Want:

    L
    5

#### Mechanism

Under ruling B2 a `let` seeded with a function that returns nothing takes a function returning a
value, and calls through it drop the result. A named function written to it is instanced at the
binding's void signature through its void twin (`monoNoteVoidTwin`), but a `const` lambda read by
name is not, so its closure keeps its `i32` result and the call through the slot mismatches.
