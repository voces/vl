### D14539 — the aliasing check knows a `match` scrutinee by its node in the lowered chain, not by the place it reads

**runs today and must keep running · open: a second notion of "this read is the scrutinee" · 3 fixtures · filed 2026-10-27 against master `579e6a494`**

Repro:

    type Circle = { r: i32 }
    function mkA(): {[i32]: Circle} {
      const m: {[i32]: Circle} = Map()
      m[1] = { r: 5 }
      m
    }
    function uA(): {[i32]: Circle} | {[i32]: Circle | null} { mkA() }

#### Mechanism

The write scan's occurrence index (`cwIxBuild`, `check_write_scan.vl`) is built over the
lowered if-chain and climbs each read of a handle from its node to its consumer. When D14538
gave every arm test its own read node, the `match`'s own scrutinee node was left in no lowered
statement, and the index read that orphaned `v` as a consumer it cannot follow, refusing the
delivery `f(uA())` with "a handle to it reaches v … which this check cannot follow". So the
check decides "this read is the scrutinee" by node identity, a second notion beside the
checker's place key (`npKeys`). D14538 keeps the program running by giving the FIRST type
pattern the scrutinee node itself (`hmsPointArms`), which is the asymmetry this row exists to
remove.

#### Ablation

| --- | --- | --- |

| the widening to `{[i32]: Circle}` alone (`f(mkA())`) | loud check reject | no |
