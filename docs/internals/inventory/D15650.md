### D15650 — a function handed in a list literal to a callee that calls the element at two types and adds the results leaves the caller's result untyped in a `const`

**closed 2026-11-10, runs and prints `7` · was check-clean invalid wasm, clause 1, `the emitted module failed to validate inside the module's top-level code: … type mismatch: expected i32, found f64` · found closing D15648 · filed 2026-11-10 against master `aa36acae` · closed with D15648: `holeDirectCallRetAt` admits a list whose element is a generic function's open signature, and the callee's `r[0](x)` reads take each call's instance (`holeOpenFnRetAt`) · fixtures `functions/hole-fn-handed-on-called-at-two-types-result.vl`, `functions/error-hole-fn-handed-on-called-at-two-types-result.vl`**

Repro:

    function dbl(v) { return v + v }
    function c2(r, x) { return r[0](x) + r[0](1) }
    function both2(g) { return c2([g], 2.5) }
    const b = both2(dbl)
    print(b)

Want:

    7

#### Mechanism

D15648's, through a list: `g` is called at `f64` and `i32`, so no single instance binds it, and
the result over two hole calls stayed open; `holeDirectCallRetAt` refused the argument, whose
type is a list of `dbl`'s open signature. D15645's literal forward needs one instance and does
not reach it.

#### Ablation

| spelling | outcome | needed? |
| --- | --- | --- |
| `print(both2(dbl))` (no `const`) | runs, `7` | **yes** |
| `const b: f64 = both2(dbl)` | runs, `7` | **yes** |
| `c2([dbl], 2.5)` at module scope | runs, `7` | **yes** |
| `r[0](x) + r[0](2.5)` with `c2([g], 1.5)` (one type) | runs, `8` | **yes** |
| `const r = [g]; return c2(r, 2.5)` | invalid wasm before the close, `7` after | no |

  before and after; it is [D15649](D15649.md)'s family.
