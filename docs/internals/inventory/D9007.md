### D9007 — a re-pointed `let` of un-annotated functions with different results, handed to an un-annotated parameter and called there, traps

**closed · now a loud check reject, `cannot write 'half' to 'f': called at (i32) it returns f64, where 'inc0', also written to it, returns i32` · was loads then traps (`indirect call type mismatch`), `vl check` rc 0 · clause 1 · found closing [D9003](D9003.md) · present on master `145cabbc6` · filed 2026-10-21 against master `145cabbc6` · closed by `holeLetReadsOf` (check_relate_core.vl), reached from a call through a hole parameter (check_calls.vl) · fixtures `closures/error-written-let-of-hole-fns-results-differ-through-hole-param.vl`, `closures/written-let-of-hole-fns-results-agree-delivered.vl` · residue [D9009](D9009.md)**

Repro:

    function inc0(a) { return a + 1 }
    function half(a) { return a / 2.0 }
    function w(h) { return h(3) }
    let f = inc0
    f = half
    print(w(f))
    // master: vl check rc 0, vl run: wasm trap: indirect call type mismatch.  now: cannot write 'half' to 'f': called at (i32) it returns f64, where 'inc0', also written to it, returns i32

#### Mechanism

D9003's refusal read the binding at the parameter types it is called at, and only where the
call names the binding: a direct call, a function-typed destination, a generic's arrow
parameter, `.map`. Here the call is `h(3)` inside `w`, through a hole-typed parameter, so the
call site that fixes `(i32)` is in another body and `f` was never read at it. The annotated
destination (`w(h: (a: i32) => i32)`) was already refused by D9003's check.

Decision: the delivery does not make the program legal. A call through `h` runs whatever
`f` holds, so the contract D9003 states (every function a call through the binding may run
returns one type) is broken the same way, and the refusal is the same one, at the write.
The call through the hole parameter now asks `holeLetReadsOf` which bindings its callee may
be read from: a parameter is followed to each call's argument (`cwParamArgs`), and each
argument is judged on its own, never as one set, since each call instances its own copy. So
`w(inc0)` and `w(half)` as two calls still run. The same walk follows a parameter handed on
(`v(h) { return w(h) }`) and a recursive call handing the parameter back to itself.
