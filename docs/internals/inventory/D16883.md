### D16883 — a list literal argument whose elements hold lists of un-annotated functions pinned at different reps is refused at emit

**open, blocked on S3.4d's per-member dispatch (re-run 2026-11-17 on master: the witness and the flat dynamic-index read still refuse) · rides [D16747](D16747.md)'s clause 2 (per-member dispatch, S3.4d) · loud emit reject · clause 2 (`vl check` rc 0) · the residue of [D16859](D16859.md) and [D16876](D16876.md), whose pin takes a list only where every element pins alike · refused before them too · filed 2026-11-16 against master `5ed2c389e`**

Repro:

    function inc0(a) { return a + 1 }
    function half(a) { return a / 2.0 }
    function id(x) { return x }
    const r = id([[inc0], [half]])
    print(r[0][0](3))
    print(r[1][0](3))
    // vl check: rc 0.  vl run: emit error, `monomorphize: unsupported argument type for `x` in a call to `id``

Want:

    4
    1.5

#### Mechanism

Each inner list pins at its own rep: `[inc0]` at a list of `(i32) => i32`, `[half]` at a list of
`(i32) => f64`. A list of them has no one element type, so the pin is declined rather than built at
the first element's, which a first draft did and which then trapped. The element type the list
needs is the join of the elements' function types, a closure set of both signatures.

#### Why it rides D16747

Sized 2026-11-16. A mixed list (`[inc0, half]`) handed to a generic pins, through the kept rung, at an
erased closure-list rep (`(() => void)[]`), one wasm shape for every signature; a one-member list
(`[inc0]`) pins at its own signature through `eplValueTy`, which is why the elements disagree. Even
the erased mixed list runs only where the value-flow rewrite turns a call into a direct one:
flat `id([inc0, half])` read at a dynamic index (`r[i](3)` in a loop) meets D16747's refusal on
master. Building each element at the erased rep would run static-index reads only; running this row
in general needs each member dispatched at its own signature, which is D16747's clause 2.

#### Ablation
