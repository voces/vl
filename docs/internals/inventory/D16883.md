### D16883 — a list literal argument whose elements hold lists of un-annotated functions pinned at different reps is refused at emit

**loud emit reject · clause 2 (`vl check` rc 0) · the residue of [D16859](D16859.md) and [D16876](D16876.md), whose pin takes a list only where every element pins alike · refused before them too · filed 2026-11-16 against master `5ed2c389e`**

Repro:

    function inc0(a) { return a + 1 }
    function half(a) { return a / 2.0 }
    function id(x) { return x }
    const r = id([[inc0], [half]])
    print(r[0][0](3))
    print(r[1][0](3))
    // vl check: rc 0.  vl run: emit error, `monomorphize: unsupported argument type for `x` in a call to `id``

Want:

    4
    1.5

#### Mechanism

Each inner list pins at its own rep: `[inc0]` at a list of `(i32) => i32`, `[half]` at a list of
`(i32) => f64`. A list of them has no one element type, so the pin is declined rather than built at
the first element's, which a first draft did and which then trapped. The element type the list
needs is the join of the elements' function types, a closure set of both signatures.

#### Ablation

| ingredient changed | outcome | needed? |
| --- | --- | --- |
| one result type (`[[inc0], [inc1]]`) | runs | **yes**: two result types |
| elements alike (`[[inc0, half]]`) | runs | **yes**: elements that differ |
| records holding the lists (`[{ l: [inc0, half] }, { l: [half, inc0] }]`) | the same message | no |
| a narrower element first or last (`[[half], [inc0, half]]`) | the same message | no |
| no generic | runs | **yes**: the generic parameter |
