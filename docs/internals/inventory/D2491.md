### D2491 — `m.get(k) == null` over a numeric-literal-union-valued map is check-clean invalid wasm

**closed 2026-10-23 — the filed repro RUNS and prints `true` · was check-clean invalid wasm, `expected (ref null $6), found i32`, and a loud `only i32 locals are supported` inside a function · found by #3158's review (`rv3158-p/pre1.vl`) · filed 2026-09-25 against master `0a0d24ac9` · the same defect as D11241 and closed by its fix: the box test a binding's collect pass asks of a map read resolves `m.get(k)` as well as `m[k]` · fixture `tests/cases/literal-unions/bound-map-get-of-num-litunion-eq-null.vl`**

Repro:

    type N = 0 | 5 | 7
    const m: {[string]: N} = Map()
    const b = m.get("a")
    print(b == null)
    // vl check: rc 0.  vl run: type mismatch: expected (ref null $type), found i32

Want:

    true

#### Mechanism

Not ablated. A numeric literal union reps as its base `i32`, with no spare value, so a read
of it is `N | null` in the value box (`mapReadScalarBoxKind`'s numeric-litunion rung). The
un-annotated binding `b` and the `== null` over it disagree about that rep: one side pushes the
raw `i32` where the other expects the nullable ref. This is a prediction to grade when the row
is picked up.

#### Grading list

* The `m["a"]` spelling, and the annotated binding `const b: N | null = m.get("a")`.
