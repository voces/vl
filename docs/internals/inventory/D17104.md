### D17104 — a `const`-bound choice of un-annotated functions whose results differ, delivered to a closed function type that admits both and called through nowhere else, is refused at check

**runs, prints `s` — CLOSED 2026-11-28 by COV-CLOS-3 with [D17805](D17805.md): a stable name of a choice delivered where the result is a wider union is called through an adapter at the destination, so the check no longer refuses the choice's two results; `useK(g)` runs too; pinned by `tests/cases/closures/hole-fn-choice-of-two-results-at-wider-result.vl` · was loud check reject · clause 2 · found by the D17097 position sweep · beside [D17098](D17098.md) and [D17099](D17099.md) · owner S2 · filed 2026-11-24 against master `dbeb64c7`**

Repro:

    function inc(a) { return a + 1 }
    function str(_a) { return "s" }
    function run(c: boolean) {
      const g = if c { str } else { inc }
      const k: (a: i32) => i32 | string = g
      print(k(4))
    }
    run(true)
    // vl check: cannot choose 'inc' here: called at (i32) it returns i32, where 'str', also chosen here, returns string — every function a call through the choice may run must return one type

Want:

    s

#### Mechanism

With no call through an open parameter, the set is untagged, so `g` is a closure needing one
result. The delivery's result `i32 | string` admits both members, but the binding is checked
first, so the destination never reaches the choice. Unlocated beyond that.
