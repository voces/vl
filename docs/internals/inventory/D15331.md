### D15331 — a value `if` of records holding an annotated function in one arm and an un-annotated one in the other, handed to an un-annotated parameter, is refused at emit

**closed · runs, prints `3` · was loud emit reject, `emitProgram: cannot take the generic function id1 as a value — a function value carries ONE signature` · closed in check_relate_core.vl: the checker joined the arms at the open arm's type (`{f: (_) => _}`), so the elaboration answered the parameter nothing; `holeFnBesideClosedJoin` now joins a record or list holding a function at its closed sibling's type, as it did a bare function, and `monoCoerceIfArms` (emit_mono.vl) builds the open literal arm at that join, choosing no type · a closed arm that reads a binding (`if c { o } else { { f: id1 } }`) was a check reject at the same join and runs too · fixture `closures/if-arm-closed-record-beside-hole-fn-record.vl` · found grading D15301 M2 · filed 2026-11-04 against master `6f1693f5`**

Repro:

    function id1(a) { return a }
    function inc(x: i32): i32 { return x + 1 }
    const c = 1 > 0
    function g(r) { return r.f(2) }
    print(g(if c { { f: inc } } else { { f: id1 } }))

    3

#### Mechanism

The arms' join kept the open arm's type, `{f: (_) => _}`: `holeFnBesideClosedJoin` took the
closed side only for two bare function types. So `elabCallHoleParamTy` answered no closed type
for `r` and no pin delivered `id1` at `(i32) => i32`; it reached codegen with no instance. Bound to a `const` or listed, the same `if` refused at the same site.
