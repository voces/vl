### D12214 — two generics whose results disagree, written to one `let` and called through a generic parameter, trap instead of refusing at check

**trap after load · `vl check` rc 0 · `wasm trap: indirect call type mismatch` in `app` · clause 1 · DESIGN: the hole-function spelling is refused at check (`every function a call through 'f' may run must return one type`) · found surveying emit refusals for L3 family (d) · filed 2026-10-24 against master `b8e223f93`**

Repro:

    function idg<T>(t: T) { return t }
    function one<T>(t: T) { return 1 }
    function app<T, R>(g: (x: T) => R, v: T): R { return g(v) }
    let f = idg
    f = one
    print(app(f, "s"))

#### Mechanism

At `string`, `idg` returns `string` and `one` returns `i32`, so no single signature serves a
call through `f`. `holeLetWritesDisagree` refuses exactly this for un-annotated (hole)
functions written to a `let`, but does not judge type-parameterised generics, so the checker
passes it and the emitter's own disagreement check (emit_mono.vl, the hole-binding refusal)
does not see it either.

#### Ablation

| ingredient removed | outcome | needed? |
| --- | --- | --- |
| the write `f = one` | runs, `s` | **yes** |
| `app` (`print(f("s"))`) | still traps | no |
| the type parameters (`function id0(a)`, `function one0(a)`) | check reject | **yes** |
| the results' annotations (`: T`, `: i32`) | still traps | no |

#### Grading list

The same hole-function writes inside a generic body (`function run<T>(x: T) { let f = id0;
if … { f = one0 }; print(ap(f, x)) }`, `run("s")`), which traps in `ap` because the checker
skips the judge while `T` is open.
