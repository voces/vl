### D15927 — a function-local binding of a member of a returned list's split set, called, builds an invalid module: the binding holds the set's id, its initialiser the member's closure

**closed 2026-11-12 · runs, prints `4` then `4` · was check-clean invalid wasm, `type mismatch: expected i32, found (ref $2)` inside `go`, clause 1 · found closing [D15926](D15926.md), whose floor does not reach it (the set is tagged here) · filed 2026-11-12 against master `6976e1afd` · fixed by the alias store (`emitLetDeclStmt`, wasmEmit.vl) holding a tagged member's id, not its closure**

Repro:

    function inc0(a) { return a + 1 }
    function half(a) { return a / 2.0 }
    function pick(b: boolean) { if b { return [{ f: inc0 }] } return [{ f: half }] }
    print(pick(true)[0].f(3))
    function go() {
      const g = inc0
      print(g(3))
    }
    go()

Want:

    4
    4

#### Mechanism

The tag decision tags `{inc0, half}`: the call `g(3)` through a function-local `const` of a member is a
direct call (`ftMemberDirectCall`, check_fn_tag.vl), so it reads no id. The binding `g` is then a
holder whose rep is the set's `i32` id. Its initialiser is recorded as an id leaf, but the emitter's
store of a `const` alias used only as a direct callee (`emitLetDeclStmt`, wasmEmit.vl) wrote the
member's closure into that `i32` local. The store now takes the leaf's id where the initialiser
has one; the call stays a direct `call $inc0`.
