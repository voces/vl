### D16441 — a call's fresh record as a part of a list literal beside a held part at a wider record is refused

**closed 2026-11-15 — the witness runs and prints `1` · was: loud emit reject · clause 2 · `emitProgram: this branch hands over a record whose field types differ from the record the branches join to` · found with [D16440](D16440.md) · filed 2026-11-15 against master `6adb40099` · closed in the list stamp: with no part built elsewhere, a call part is copied into the list's element (`recListCallCopy`) and a binding of one has its call copied as it is bound (`recHeldCallPartCopy`), as they are beside a part built elsewhere (D15652, D15655) · fixture `tests/cases/soundness/record-list-call-part-beside-wider-part-runs.vl` · its spread face is [D16444](D16444.md)**

Repro:

    function mk() { return { x: 1 } }
    const a = { x: 2.5 }
    const l = [a, mk()]
    print(l[1].x)
    // was: vl check rc 0, vl run: emit error, this branch hands over a record whose field types differ

Want:

    1

#### Mechanism

A call's result is fresh, so it is copied where it lands (D14817, D15652), but `recListCallCopy`
ran only when a part built elsewhere sets the list's build (`bt`). Here `a` is held at its own storage, so no build is set, no copy is recorded, and the
emitter meets the `{x: i32}` record at the `{x: f64}` join. The spread face,
`[a, ...mk()]` with `mk` returning `[{ x: 1 }]`, was check-clean invalid wasm and is refused at
check since D16440 (`recListSpreadsApartRefuse`); a list copy recorded on that call
(`listCopyTyIx`) is not applied under a spread, so it stays refused, [D16444](D16444.md).
