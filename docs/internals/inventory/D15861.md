### D15861 — a bundle holder handed to a parameter annotated at one member's type is refused at emit

**closed 2026-11-12, runs and prints `5` `4` · was loud emit reject, clause 2, `a function returning a parameter called at two signatures is called where its result is not used at one of them` · found closing [D15749](D15749.md) · filed 2026-11-12 against master `84e28554d` · closed in `elabHandMemberOf` (emit_elab.vl), which takes the member at a plain callee's annotated closed parameter type where the callee has no instance, and in the direct-call argument path (wasmEmit.vl), which asks the elaboration for that member where mono noted none · fixture `tests/cases/closures/bundle-holder-handed-to-annotated-plain-param-runs.vl`**

Repro:

    function lap(f) {
      f(2.5)
      f(3)
      return f
    }
    function u(f: (f64) => f64) { print(f(4)) }
    function main() {
      const k = lap((a) => a + 1)
      u(k)
      print(k(3))
    }
    main()

Want:

    5
    4

#### Mechanism

Unmeasured. A hand of a holder is admitted only to a parameter its callee's instance binds to
the record or to one member (`elabHandTakesRecord`, `elabHandMemberOf`); an annotated
parameter of a plain function is neither, so the hand is a read the holder cannot account for.
