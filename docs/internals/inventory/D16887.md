### D16887 — `__array_new__`'s fill keeps its own type where a literal of the same value takes the destination's element type

**loud check reject · `null[] is not (string | null)[]` · clause 2 · open · reachable only by calling the intrinsic directly: `std:array`'s `filled(2, null)` and `filled(2, 0)` take the destination through their type parameter and run · found closing [D3549](D3549.md) · filed 2026-11-16 against master `bc6546163`**

Repro:

    const xs: (string | null)[] = __array_new__(2, null)
    print(xs.length)
    // vl check: rc 1, null[] is not (string | null)[]

Want:

    2

#### Mechanism

Not traced. `__array_new__`'s checker rule (check_calls.vl) types the list as the fill's own type
(`null[]`, `i32[]`), and the container rule then refuses the widening, where the literal
`[null, null]` is built at the destination's element type. A generic wrapper (`filled<T>`) binds
`T` from the destination (D3539) and so never reaches the gap.
