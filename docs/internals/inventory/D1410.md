### D1410 — a checked list read re-emits its INDEX, so `xs.get(i + 1)` is `emitProgram: .get index must be a literal or a name`

**loud emit reject · check rc 0 · clause 2 · both `.get` faces, fused and unfused · filed
2026-09-03 while closing [D1281](#d1281), and PRE-EXISTING: the fused `xs.get(i + 1) ?? 0`
carries the identical gate on the pre-change seed**

Repro (refuses; `const j = i + 1  print(xs.get(j))` prints `8`):

    const xs: i32[] = [7, 8]
    const i = 0
    print(xs.get(i + 1))

#### Mechanism

The bounds compare and the element read each need the index, and neither `emitListGetOr`
(the fused `xs.get(i) ?? d`) nor `pushTakeCond`/`pushTakeElem` (the unfused read, D1281)
has anywhere to stash it — so both emit the index EXPRESSION twice and gate on it being
re-readable: a `NumLit`, an `Ident`, or a negated `NumLit` (`takeIdxIsPure`). Anything
else is refused by a sentence that describes the emitter's re-read, not the language: an
`i32` index is an `i32` index, and the checker accepts every spelling of one.

The fix is a scratch stash, not a ladder rung. `.push` already reserves a four-slot frame
per receiver rep (`pushKindBitsOf` / `callPopBits`), and its `+1` `pushNewCap` slot is an
i32 — an index stash wants that shape, reserved for a `.get` whose index is impure, then
`local.tee`'d before the compare and `local.get`'d for the read. The receiver went the
same way already: `listOpRecvLocal` stages a global / struct-field / narrowed-union
receiver into `recvRef` rather than refusing it.

#### Ablation

| ingredient removed | outcome | needed? |
| --- | --- | --- |
| the arithmetic (`xs.get(i)`) | runs, prints 7 | **yes** |
| the `.get` (`xs[i + 1]`) | runs, prints 8 | **yes** |
| the un-fused face (`xs.get(i + 1) ?? 0`) | still refuses | no |
| the rep (`u8[]`, `f64[]`, `string[]`, a struct list) | still refuses | no |
| the scope (inside a function) | still refuses | no |
| a CALL index (`xs.get(f())`) instead | still refuses | no |

#### Grading list

The fused `xs.get(i) ?? d` face, which shares the gate and must move with it; `xs.get(-1)`,
which the negated-literal arm admits today and must keep answering `null`; and D1281's own
rep grid, since a stash changes where every rep's index comes from.
