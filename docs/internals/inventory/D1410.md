### D1410 — a checked list read re-emits its INDEX, so `xs.get(i + 1)` is `emitProgram: .get index must be a literal or a name`

**closed 2026-09-06 by D1677's `.get` operand stash — the witness prints `8` · was a loud
emit reject at check rc 0, clause 2, both `.get` faces · filed 2026-09-03 while closing
[D1281](#d1281)**

Repro (prints `8`):

    const xs: i32[] = [7, 8]
    const i = 0
    print(xs.get(i + 1))

#### Mechanism

The bounds compare and the element read each need the index, and neither `emitListGetOr`
(the fused `xs.get(i) ?? d`) nor `pushTakeCond`/`pushTakeElem` (the unfused read, D1281)
has anywhere to stash it — so both emit the index EXPRESSION twice and gate on it being
re-readable: a `NumLit`, an `Ident`, or a negated `NumLit` (`takeIdxIsPure`). Anything
else is refused by a sentence that describes the emitter's re-read, not the language: an
`i32` index is an `i32` index, and the checker accepts every spelling of one.

The fix is a scratch stash, not a ladder rung, and that is what D1677 built: a frame slot
reserved for a `.get` whose index is not a place, `local.tee`'d before the compare and
`local.get`'d for the read. The receiver went the same way — `listOpRecvLocal` already
staged a global / struct-field / narrowed-union receiver into `recvRef`, so a `Call` one is
one more arm on that path.

#### Ablation

| ingredient removed | before | after |
| --- | --- | --- |
| the arithmetic (`xs.get(i)`) | runs, prints 7 | runs, unchanged |
| the `.get` (`xs[i + 1]`) | runs, prints 8 | runs, unchanged |
| the un-fused face (`xs.get(i + 1) ?? 0`) | refused | **runs** |
| the rep (`f64[]`, a struct list) | refused | **runs** |
| the scope (inside a function) | refused | **runs** |
| a CALL index (`xs.get(f())`) instead | refused | **runs** |

#### Grading list

All three moved together: the fused `xs.get(i) ?? d` face runs, `xs.get(-1)` still takes the
absent arm (`?? -99` prints `-99`), and the reps D1281 grids run — an `f64[]` index
expression prints `2.5`. A `string[]` `.get ?? d` still refuses at `.get but list type not
collected`, which is a different gap and refuses identically on the pre-change seed.
