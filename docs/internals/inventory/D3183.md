### D3183 — a recursive function passing a literal-union function value on through its own un-annotated parameter is refused

**loud check reject · clause 2 · the message concedes the program is type-valid · found by the #3284 review (`rv3284-24850`) · the same on master `a0b9acaf8` · filed 2026-09-29 against master `995bbc74e`**

Repro:

    type K = "a" | "b"
    function R(g, n: i32) {
      if n <= 0 { return g() }
      return R(g, n - 1)
    }
    print(R((): K => "b", 2))
    // vl check: the returns of `R` join to K for this argument — type-valid, but an inferred
    // union return through an un-annotated parameter is not yet supported by codegen; annotate
    // the return type

Want:

    b

#### Mechanism

Not localised past the ablation. `R`'s return is inferred through its hole parameter `g`, and
the recursive call's result joins with `g()`'s at the argument's type `K`. The checker refuses
that join for a union result through an un-annotated parameter. An `i32` result, no recursion,
or a generic parameter all run.

#### Ablation

| ingredient changed | outcome | needed? |
| --- | --- | --- |
| `() => 7`, an `i32` result | runs | **yes** (the literal union) |
| `return g()` only, no recursion | runs | **yes** (the recursive join) |
| `function R<Y>(g: () => Y, n: i32): Y` | runs | **yes** (the hole) |

#### Grading list

The witness and its generic twin, which runs.
