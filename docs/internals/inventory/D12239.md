#### Mechanism

The hole-slot judge (check_relate_core.vl) finds the writes to a place by following the place's
own spellings and its aliases. A write through a record field holding the list (`m.xs[0]`),
through a list holding the list (`gs[0][0]`), or into the result of a call (`const fs = mk()`,
with `function mk() { [pick] }`) is a write to the same storage under a path the judge does not
trace back from the call, so no misfit is reported; a call through the written path itself
(`m.xs[0](1, 2)`) is judged and refused. The emitter then calls the written function through the
generic's instance signature, and the indirect call traps. The same holds for a fixed function
`function k(a: i32, b: string): i32` written by those paths.
