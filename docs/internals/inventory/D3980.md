### D3980 — a namespace or default import parsed and bound nothing, so the first use read as an undeclared name

**closed 2026-10-11 — now a loud check reject, raised at the parse stage (`vl check` closes with `(parse error)`) at the import's `*` or default name · was a misleading `undeclared identifier 'S'` at the first `S.A`, and check-clean when the alias was never used · diderven DV-001 · filed against master `56f77d80f` · fixtures `tests/cases/modules/err-namespace-import/`, `err-default-import/`, `err-default-plus-named-import/`**

Repro:

    // file: lib.vl
    export const A: i32 = 1
    // file: entry.vl
    import * as S from "./lib"
    print(S.A)
    // WAS: undeclared identifier 'S' at 2:7.
    // NOW: namespace imports (`import * as …`) are not supported — import the names
    // you use: `import { A } from "./lib"` and drop the `S.` prefix

#### Mechanism

`parseImport` consumed every token between `import` and the path string, and recorded
only the names inside `{ … }`. A `*`, an `as` alias, or a bare name before the braces were
skipped with no diagnostic. The driver's `modScan` records the same names, so nothing was
bound. The refusal is now raised in `parseImport` once the specifier is a well-formed
string. The suggested list is the set of names the file spells as `S.<name>` with no `.`
before the `S`.

#### Ablation

| ingredient removed | outcome | needed? |
| --- | --- | --- |
| the `S.A` use (`import * as S from "./lib"` alone) | was check-clean; now refused | no |
| the `*` (`import S from "./lib"`) | same silence, default-import form; now refused | no |
| the braces' absence (`import S, { B } from "./lib"`) | `B` bound and `S` dropped; now refused | no |

#### Grading list

The char-quoted `import fs from 'std:fs'` (`tests/cases/parser/error-char-quoted-import-specifier.vl`)
keeps its own two errors alone: the new refusal waits for a well-formed specifier.
