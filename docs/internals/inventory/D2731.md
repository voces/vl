### D2731 — an un-annotated `if` joining two record literals that differ in one field's type is invalid wasm

**closed 2026-09-27 — the repro RUNS and prints `2` · was check-clean invalid wasm, the `i32 \| string` field, a map field, and a union-of-maps field (D2730's un-annotated face) · identical on master · filed 2026-09-26 against master `90b63b840`**

Repro:

    function g(sel: i32) {
      const sx = if sel == 0 { { f: 1 } } else { { f: "s" } }
      const v = sx.f
      if v is string { print(v) } else { print(v + 1) }
    }
    g(0)

#### Mechanism

The checker typed the join `{f: i32} | {f: string}`, a union of two records with one field-name
set and no discriminant, which is the union D1023 refuses where it is declared: no rep tells its
arms apart, so each literal built its own row and the binding held one of them. Closed in two
halves. The checker's join (`joinVariantTys`) now joins such a pair as one record of per-field
joins, `{f: i32 | string}`, the type the annotated spelling names; a pair with a literal
discriminant, or identical fields, is unchanged. The emitter builds each literal leaf of a join
at the joined row: an un-annotated binding of such a join takes the joined type as its
annotation (`synthJoinedRecordAnn`), an un-annotated return takes it as its return type, and a
join with no destination interns the joined row and builds its arms there (`ifExprRefSlot`).
A branch that hands over a record VALUE of a narrower row is D2100's converting copy and refuses
loudly (D2765); an un-annotated record variable adopts the joined rep and runs.
