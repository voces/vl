#### Mechanism

After D7940, `vl check src` on a copy of diderven at two jobs still declines 14 roots on
`ambient`. The trace names the key that met. Ablated 2026-10-20 against master `aec7a5332`:

- 9 roots meet `tools/greykey.vl` on `fields:r,g,b`, and 1 meets `tools/contacts.vl` on
  `fields:x,y`. This is the literal half: the served closure writes an object literal whose
  field set is exactly the outside declaration's (`xLit`). The guard is load-bearing. With the
  guard masked, the check-within harness reads an outside `type II = { f: i32 }` and a served
  `idn({ f: 4 })` as UNSOUND, through D7941. Eight other literal deliveries are sound with the
  guard masked: an assignment of an `f64` or a `string` field, an inferred return, a `let`
  reassignment, a list push, a clean root, a private hint, and a union `is`. Limiting the half to
  closures that declare a generic function would serve none of the 10, because every tool's
  closure holds `std:array`. Limiting it to literals that reach a generic call needs flow, since
  `idn(mk())` refuses too. D7941 closed the literal-argument case on 2026-10-20; `idn(mk())`
  still refuses when a module of the graph declares `Col` and runs when none does, so the half
  stays until [D8020](D8020.md) closes.
- 4 roots meet on `rows`: `ui/lookjson.vl`, `mobs/ai.vl` and `sim/balance/policy.vl` meet an
  outside declaration, and `char/mana.vl` meets `std:test`. Each root holds redundant-annotation
  hints, and every one renders `boolean`. The guard reads every row as able to render any type
  name. A narrower rule would have to read which names a row renders. The witness for that is
  not yet written.
- The `rng.vl` getter (`recv:range`) no longer declines.
