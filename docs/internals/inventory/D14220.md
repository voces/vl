### D14220 — an inferred list of two anonymous records with different fields has no list build, and its elements land in a list typed for another rep

**check-clean invalid wasm · open · filed 2026-10-26 against master `c13c39b33`**

Repro:

    print([{ a: 1 }, { b: 2 }].length)
    // vl check: rc 0.  vl run: the emitted module failed to validate:
    // type mismatch: expected (ref null $type), found (ref $type)

#### Mechanism

The literal's checker type is `({a: i32} | {b: i32})[]`, a union of two anonymous records, and
`listBuildOfTy` returns null for it (no element rep), so `emitArr` builds the literal through
the caller's fallback pair rather than at its own type, and the stored elements do not match
the array type that pair declares. Annotating the destination with the same union gives the
literal a type `listBuildOfTy` serves, and it prints `2`. Step 5b slice 6 measured it with the
fallback probe (`tb == null`) and attributes the close to slice 7, which makes `listBuildOfTy`
read `repOfTy`/`repSlotOfKind` for a closed list type.
