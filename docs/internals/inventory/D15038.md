### D15038 — a module choice of two hole functions, one of which never reads its parameter, called with a named function, leans on the split plan

**closed 2026-11-05, runs and prints `30 0.75` with the split plan on and off · was a refutation pin for deleting the split plan: with `compileSrc` returning after its first compile the witness refused at emit, `cannot take the generic function `add` as a value` · closed by letting the late argument rule (`ftLateArgOfSet`, check_fn_tag.vl) accept a member that never reads the parameter (`ftParamUnread`), as `ftLateParamTakes` already did · fixture `closures/choice-with-unread-member-handed-hole-fn-called-at-two-types.vl` · filed 2026-11-02 against master `7e3fea10`**

Repro:

    function add(a, b) { return a + b }
    function apply3(g) {
      print(g(10, 20))
      print(g(0.5, 0.25))
    }
    function apply2(g) {}
    const f = if true { apply3 } else { apply2 }
    f(add)

Want:

    30
    0.75

#### Mechanism

With the plan off, the tag decision's late argument rule (`ftLateArgOfSet`, check_fn_tag.vl)
needs every member of the callee's set to take the argument (`mintParamTakes`), and `apply2`
never reads `g`, so `add` is handed over as a closure of a hole function and refused. Inferred
fix: accept an unread parameter there as `ftLateParamOk` does (`ftParamUnread`).
