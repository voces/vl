### D16814 — a higher-order function handed an un-annotated function at one call and a closed lambda at another checks the un-annotated function's body at the lambda's parameter type

**loud check reject · `vl check` rc 1, `operator '+' is not defined for string and i32` at `hinc`'s body · clause 2 · either call alone is accepted · found by the hof oracle fuzz (`ho_s10_0028`, seed 10) after the D16813 fix · filed 2026-11-16 against master `fae99e93f`**

Repro:

    function app<A, B>(f: (x: A) => B, x: A): B { return f(x) }
    function hinc(x) { return x + 1 }
    print(app(hinc, 2))
    print(app((s: string) => s, "e"))
    // vl check: rc 1, operator '+' is not defined for string and i32 (hinc's body)

Want:

    3
    e

#### Mechanism

Not located yet. Each call binds `app`'s `A` on its own: `i32` at `app(hinc, 2)` and `string` at
`app((s: string) => s, "e")`. `hinc`'s hole parameter is bound through `f: (x: A) => B`. The second
call's `A = string` reaches `hinc`'s body, although `hinc` is not an argument of that call. The
binding seems to be keyed on `app`'s parameter, not on the call that handed `hinc` over.
