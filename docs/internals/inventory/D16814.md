### D16814 — a higher-order function handed an un-annotated function at one call and a closed lambda at another checks the un-annotated function's body at the lambda's parameter type

**closed 2026-11-16 · runs, prints `3` `e` · was loud check reject, `vl check` rc 1, `operator '+' is not defined for string and i32` at `hinc`'s body · clause 2 · fixed in emit_elab.vl: `elabParamArgTargets` takes a lambda or a declared function written as the argument as the function the parameter holds, so an instance no longer falls back to every function any call handed the parameter · the `if`-of-functions spelling is [D16831](D16831.md) · pin: `tests/cases/functions/hof-param-handed-hole-fn-and-closed-fn-at-two-calls.vl` · found by the hof oracle fuzz (`ho_s10_0028`, seed 10) after the D16813 fix · filed 2026-11-16 against master `fae99e93f`**

Repro:

    function app<A, B>(f: (x: A) => B, x: A): B { return f(x) }
    function hinc(x) { return x + 1 }
    print(app(hinc, 2))
    print(app((s: string) => s, "e"))
    // vl check: rc 1, operator '+' is not defined for string and i32 (hinc's body)

Want:

    3
    e

#### Mechanism

The refusal comes from elaboration, not from the checker's call rows. `vl check`'s elaboration
(`emit_elab.vl`, the instance re-check through `monoRecheckBegin`) builds an instance of `hinc`
keyed `?hinc.0 = string`. That instance's body check fails, and `elabErrorNote` reports the
failure as the program's error. The `operator` row, the `BND_LET`/`BND_BIN` demands and
`judgeFnArgHoleCalls` were each ruled out with a trace.

Each call binds `app`'s `A` on its own. A different generic of the same shape at the second call
runs. The read is `elabSetCallRows`: `app`'s `string` instance dispatches `f(x)` through its open
parameter. `elabParamArgTargets` answered `[-1]` for a lambda argument, because `elabCalleeTargets`
names none. So the call fell back to every function any call handed `f`, `hinc` included.
