### D2187 — a generic whose tail `if` joins two locals of its type parameter declares an `i32` result at a nullable-struct pin

**closed 2026-09-26 — the filed repro RUNS and prints `-1` · was check-clean invalid wasm · clause 1 · closed by D2573's rung: the instance's result is the template's checked return read at the pin · filed 2026-09-23 against master `fa5db1bac` · fixture `tests/cases/generics/instance-expressions-typed-at-pin.vl`**

Repro:

    type P = { x: i32 }
    function id<T>(c: boolean, x: T, y: T) {
      const a = x
      const b = y
      if c { a } else { b }
    }
    const n: P | null = null
    const p: P = { x: 5 }
    print(id(true, n, p)?.x ?? -1)
    // vl check: rc 0.  vl run: rc 70, `id` fails validation: expected i32, found (ref null $type)

#### Mechanism

Not ablated. [D2186](D2186.md)'s mechanism at a `P | null` pin: the instance's returned locals
are unclassified during return inference, and the function type names `T`, so the result stays
`i32`. Kept apart from D2186 because the nullable-struct result has its own valtype arm
(`nulstruct`) that a fix must reach.

#### Grading list

The non-null struct pin `id(true, p, p).x`; the value bound before the read.
