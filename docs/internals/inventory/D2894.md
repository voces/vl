### D2894 — a lambda in a generic body returning `[t]` beside `[1]` is invalid wasm at a non-`i32` pin

**closed 2026-10-04 — the witness prints `ok` · was check-clean invalid wasm, clause 1 · found grading D2843's closure face · filed against master `d39c809c1`, closed against master `0c087fb3c` by lane LR with [D3520](D3520.md) · fixture `tests/cases/generics/lambda-list-join-type-param-pin.vl`**

Repro:

    function k<T>(t: T) {
      const g = (c: boolean) => {
        if c { return [t] }
        [1]
      }
      print("ok")
    }
    k("s")
    // vl check: rc 0.  vl run: invalid module — expected (ref $type), found (ref $type)

Want:

    ok

#### Mechanism

Not localised past the ablation. The lambda's return set is `T[] | i32[]`, kept apart as a named
generic's is (#3211), but the lambda is lifted with its captures rather than per pin of `k`, and
its body is invalid at `T := string` whether or not it is ever called. The list-union read
rewrite declines a receiver that is a function-value call for this reason, so D2843's
`g(true).length` and `g(true)[0]` stay loud check rejects.

Closed by D3520's fix: a lambda's clone takes the join its checked signature keeps apart as
its return (`monoCloneLambdaSubst`), where it used to take its last expression's own type
(`[1]`, an `i32[]`), so the `[t]` arm returned a `string[]` into an `i32[]` result.
