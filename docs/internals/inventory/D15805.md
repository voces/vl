### D15805 — a call through a function field of a record nested in a list's element, the functions returning different types, is refused at check; lifted, it builds an invalid module

**loud check reject · `cannot store 'half' in 'pick()[].r.f': called at (i32) it returns f64, where 'inc0', also stored in it, returns i32 — every function a call through 'pick()[].r.f' may run must return one type` · clause 2 · open · the check refusal guards a clause-1 hazard: lifting it builds an invalid module · found closing D15801's two-returned-literals family · filed 2026-11-12 against master `b0219f456`**

Repro:

    function inc0(a) { return a + 1 }
    function half(a) { return a / 2.0 }
    function pick(b: boolean) {
      if b { return [{ r: { f: inc0 } }] }
      return [{ r: { f: half } }]
    }
    print(pick(true)[0].r.f(3))
    print(pick(false)[0].r.f(3))

Want:

    4
    1.5

#### Mechanism

The one-result judge lifts a record nested in a BOUND list's element: the tag decision builds the
element's records, and the records nested in their fields, at the list's rep
(`fnTagHeldRecLit`, check_elab_cap.vl). It also finds a split set in a nested record field
(`fnTagHasSplitField`). A RETURNED list stays refused, for two gaps measured on scratch builds:

1. The return join (`elabFnArmJoinAt`) descends a returned list's record into its list fields and
   its apart function fields only, so a record field's own function field gets no apart note.
   Descending it as a returned list's record moves the failure on.
2. With that, the module still fails to validate inside `pick`. Each return builds the list at
   one row (`$12`, records `$10`), and the function's result rep is another (`$9`, records
   `$11`) of the same shape.
