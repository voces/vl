### D15805 — a call through a function field of a record nested in a list's element, the functions returning different types, is refused at check; lifted, it builds an invalid module

**loud check reject · `cannot store 'half' in 'pick()[].r.f': called at (i32) it returns f64, where 'inc0', also stored in it, returns i32 — every function a call through 'pick()[].r.f' may run must return one type` · clause 2 · open · the check refusal guards a clause-1 hazard: lifting it builds an invalid module · found closing D15801's two-returned-literals family · filed 2026-11-12 against master `b0219f456`**

Repro:

    function inc0(a) { return a + 1 }
    function half(a) { return a / 2.0 }
    function pick(b: boolean) {
      if b { return [{ r: { f: inc0 } }] }
      return [{ r: { f: half } }]
    }
    print(pick(true)[0].r.f(3))
    print(pick(false)[0].r.f(3))

Want:

    4
    1.5

#### Mechanism

The one-result judge's field lift admits a place whose element is followed by one field only
(`holeSlotOneElemField`, which requires `[]` as the second-to-last step). Allowing `[].r.f` made the
program pass check, and the emitted module failed to validate, so this refusal stands between the
program and a clause-1 defect. That was measured on the D15801 two-returned-literals branch with
the lift widened to any path ending in a field. The tag decision joins a list literal's
records' own fields (`ftRecWriteJoins` at depth 0) and builds them at the list's rep; the nested
record `r` is a second literal level whose row is not re-typed to the rep.
