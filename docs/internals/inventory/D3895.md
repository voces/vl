### D3895 — a nested generic named like a top-level function, or like its enclosing function, is checked against that function's demands at its own call

**closed 2026-10-09 by lane SC, with D3853 · runs · was a loud check reject, a valid program refused (clause 2) · found in review of #3468 (`rv3468c-witnesses/c01.vl`, `c02.vl`) · filed 2026-10-09 against master `c6ac0a1d2` · pins: `tests/cases/generics/nested-generic-named-like-top-level-function.vl`, `tests/cases/generics/nested-generic-named-like-enclosing-function.vl`**

Repro:

    function b<U>(y: U) { const n: i32 = y; print(n + 1) }
    function a<T>(x: T) {
      function b<U>(y: U) { print(y) }
      b(true)
      print(x)
    }
    a(1)
    b(5)
    // vl check: cannot assign boolean to 'n' of type i32

Want:

    true
    1
    6

#### Mechanism

The call arm names its callee's declaration by `fnDeclIx[name]`, the top-level table, so the
nested `b(true)` was validated as a call to the top-level `b`, against that `b`'s demand. Closed
by D3853's resolution of a call by scope: the nested `b` is the declaration `b(true)` names. A
row its own declaration does not mark is never bound at that call.
