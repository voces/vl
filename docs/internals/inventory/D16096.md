### D16096 — a re-pointed `let` of lambdas whose results differ is refused when a call through it precedes the write, or when it is returned or handed on

**loud check reject · clause 2 · `cannot assign (i32) => f64 to (i32) => i32 (the body of \`f\` at the call's argument types)` · the residue of [D16090](D16090.md) · filed 2026-11-14 against master `0ae8ca001`**

Repro:

    let f = (a) => a + 1
    print(f(1))
    f = (a) => a / 2.0
    print(f(3))
    // vl check: rc 1, the refusal above

Want:

    2
    1.5

#### Mechanism

A lambda written to a widened `let` leaves a destination row, its type against the binding's,
which a call through the binding no longer asks (D16090). A call typed before the lambda is
checked cannot read that lambda's result (`setMemberUnchecked`) and types the call by its own
callee, so the row is kept for it and the later call refuses. Returned from a function
(`sel(true)(3)`) or handed to a named callee (`ap(f, 3)`), the row is asked at that call too;
with declared functions both run (D16009, D16064).

#### Ablation

| change | outcome |
| --- | --- |
| witness | check reject |

| `sel(c)` returns the binding, `sel(true)(3)` | check reject |
| `ap(f, 3)` with `function ap(g, x) { return g(x) }` | check reject |
