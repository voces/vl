### D17021 — an instance's impossible `is` over a niche-held `T | null` writes `false` without evaluating its operand

**check-clean silently wrong · filed 2026-11-19 against master `5c0fd9a6f`, found by IR-REV**

Repro:

    let calls = 0
    function mk<T>(x: T): T | null {
      calls = calls + 1
      return x
    }
    function g<T>(x: T): boolean { return mk(x) is i32 }
    print(g("y"))
    print(calls)
    // vl check: rc 0.  vl run: prints false, then 0 — `mk` never ran.
    // PRINTS false
    // PRINTS 0

Want:

    false
    1

#### Mechanism

At `T = string` the operand `mk(x)` is a `string | null` held in the null niche, not a box, so
`isArmOf` answers the `nulTest` rung, and `nulNicheIsTestImpossible` finds `i32` can never match.
That arm wrote `i32.const 0` and returned, never writing the operand: the call and its effect are
lost. The `static` rung's decided answer goes through `isConstAfterRecv`, which evaluates and
drops a receiver that is not a re-readable place first (D12070); the `nulTest` arm did not.

#### Ablation

| ingredient removed | outcome | needed? |
| --- | --- | --- |
| `\| null` on `mk`'s result (`T`) | runs, prints `false 1` | **yes** |
| the generic (`mk(s: string): string \| null`, `g(x: string)`) | `vl check` refuses: `is` can never match | **yes** (an instance's decision) |
| the call (a parameter as the operand) | nothing to observe | **yes** |
| statement position (`if mk(x) is i32 { … }`) | still drops the call | no |
