### D7480 — a nested function that captures, read twice in one frame, compares unequal to itself

**closed 2026-10-20 by lane L1 · runs, prints `true` · was check-clean silently wrong, wrong value · each frame keeps one env local per capturing function it declares by statement, filled at the first read and reset at the declaration statement (`envCacheOpen`, emit_sections.vl), so reads in one execution of the declaration share an env and compare equal while a later execution, or another call, is a new value · a lambda is excluded, since each evaluation of its expression is a new value · pin: `tests/cases/closures/capturing-nested-function-read-twice-equality.vl` · a read from another nested function or from the function's own body is [D7700](D7700.md) · `vl check` rc 0 · clause 1 · under the [D7180](D7180.md) ruling a function value's identity is its declaration and captures, and both reads capture the same frame's `n`, so `a == b` is `true` · found closing [D7382](D7382.md) · present on master `1c86d0f42` · filed 2026-10-19 against master `1c86d0f42`**

Repro:

    function outer(n: i32) {
      function inner(x: i32): i32 { return x + n }

      const b = inner
      print(a == b)
    }
    outer(3)
    // PRINTS false

Want:

    true

#### Mechanism

Each read of a capturing nested function built a fresh closure with a fresh environment
(`emitClosureValueOf`, wasmEmit.vl), and a closure comparison compares the environment by
reference, so two reads of one declaration in one frame differed. The close builds the env
once per execution of the declaration and keeps it in a frame local.
