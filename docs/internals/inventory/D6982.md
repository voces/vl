### D6982 — an uncalled hole function's name as the last statement of an else-less `if` that ends a function is refused at emit

**closed 2026-10-19 by lane L1 · runs, prints `1` · was loud emit reject · `vl check` rc 0 · clause 2 · CAPABILITY: the same program with `exclaim(s: string)` runs, and the `if` followed by any statement runs ([D6960](D6960.md)) · the inertness walk follows a function's tail `if` into the last statement of each branch, so an unread result's arm values are inert · pins: `tests/cases/closures/uncalled-hole-fn-if-arm-value.vl` · found closing [D6960](D6960.md) · present on master `641dc8172` · filed 2026-10-19 against master `641dc8172`**

#### Mechanism

The else-less `if` is `f`'s tail, so its value is `f`'s result, and the name was a value use.
The unread-result walk (`monoInertRetHits`) saw only names and literals at the tail, not an
`if`'s branches. It now walks them through `monoIfArmValuesOf`, the same rule that closed
[D6981](D6981.md).
