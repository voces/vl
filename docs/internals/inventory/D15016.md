### D15016 — a generic function handed to `(x: T) => R` binds `R` to the function's own type parameter, so a later call's binding judges an earlier call's `print`

**closed 2026-11-02 · runs, prints `3` then `4` · was loud check reject, `` `app` prints its type parameter here: print expects one scalar or string value (…), got i32[] ``, at the second call · clause 2 · the two calls in the other order run · found building W-hand slice 2 · filed 2026-11-02 against master `bb40408f` · closed by binding `R` from the function's result at the call's bound parameter types (`bindSetArgResult`, check_calls.vl) · fixture `closures/written-let-of-generics-handed-at-open-result.vl`**

Repro:

    function idg<T>(t: T): T { t }
    function len<T>(xs: T[]): i32 { xs.length }
    function app<T, R>(g: (x: T) => R, v: T): R { return g(v) }
    print(app(idg, 3))
    print(app(len, [1, 2, 3, 4]))

Want:

    3
    4

#### Mechanism

`bindGenWalk` binds `app`'s `R` from the argument's function type, and a generic named as a
value carries its own signature, so `app(idg, 3)` bound `R` to `idg`'s `T`. The deferred
`print` constraint on that call's result was recorded on `T`, and `app(len, [1, 2, 3, 4])`,
binding `T` to `i32[]`, judged it there. The same leak kept a written `let` of generics handed
to `app` from closing its destination, so no escape was noted and the split plan was its only
route (W-hand slice 2). `R` is now bound, before the walk, to what the function returns at the
parameter types the call has bound: a named generic's own result, or the join of a set's
members' results.

| --- | --- | --- |

| `R` (`app<T>(g: (x: T) => T, v: T): T`, with `len` dropped) | runs | **yes** |
