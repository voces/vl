### D1683 — the covariant-write closure resolves a callee by name to a declared function, so handing the value to a function VALUE ends it and the read-only copy is declined

**loud emit reject · filed 2026-09-06 against master `294417dc2` · D1658/D1659's residue · 0 corpus cells**

Repro:

    type Circle = { r: i32 }
    type Sq = { s: i32 }
    type Shape = Circle | Sq
    function __other() {
      const w: Shape[] = []
      w.push({ s: 3 })
      print(w.length)
    }
    function f() {
      const a: Circle[] = [{ r: 7 }]
      const b: Shape[] = a
      const take = (ys: Shape[]) => { print(ys.length) }
      take(b)
    }
    f()
    // vl check: rc 0.  vl run: emit error, covariant list delivery.

#### Mechanism

`take` only reads, so nothing writes either list and the element-converting copy is
unobservable. The argument edge asks `cwParamName(callee, position)`, which resolves through
`cwIxFnDecl` — the first NAMED `FuncDecl` for the interned name. A lambda is a `FuncDecl` with
an empty name and is never filed there, so a call through a function-valued binding resolves to
nothing, `cwGrowCall` answers `2`, and the licence falls back on the rep-scoped scan, which
`__other`'s unrelated write has already disqualified. Writing the identical body as
`function take(ys: Shape[])` makes the program run. The same resolver is what the container
alias edge asks (D1658), so `p(nn)` over a lambda `p` loses the container's second name for
one reason rather than two.

Closing it is resolving a callee that is a binding whose initialiser is a lambda: the arena
carries that `FuncDecl`, only the name-keyed index does not, so the edge needs the binding's
own initialiser rather than a second table.

#### Ablation

#### Grading list

Three cells: the lambda parameter annotated and un-annotated, and a container handed to a
lambda (`const p = (g: Shape[][]) => …; p(nn)`). The control that must keep running is the
same program with `function take(ys: Shape[])`. A close must leave D1658's nine writing
witnesses refusing — a lambda that WRITES its parameter is the same program one keyword over,
and the closure following it there is what turns the decline into the `Writable` refusal.
