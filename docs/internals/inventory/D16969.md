### D16969 — a union of a nested list and its literal twin has no list-annotation rung, so its declaration is refused at emit

**loud emit reject · clause 2 · found closing [D16966](D16966.md) · filed 2026-11-18 against master `1d067b11e` by lane F1**

Repro:

    type K = 1 | 2
    const q: i32[][] | K[][] = [[1]]
    print(q[0][0])
    // vl run: emitProgram: only i32[] arrays and struct/union element arrays are supported

#### Mechanism

`collectATypeRef`'s rungs claim a single-depth twin (`i32[] | K[]`, one list, D4743) and each member
of a nested one, but not a union of nested twins. The annotation falls through to `checkArrTy`,
which accepts only `i32[]`. Each member alone runs, as does a non-twin nested union, so the
declaration needs the rung the single-depth twin has: the union is stored as its one nested list.

#### Ablation

| ingredient changed | outcome | needed? |
| --- | --- | --- |
| `K[][]` alone | runs, prints `1` | **yes** (the union) |
| `i32[][] \| string[][]`, not twins | runs | **yes** (twins) |
| `(i32[] \| K[])[]`, the twin one level in | runs | **yes** (the twin at depth 2) |
| `q` a parameter, handed an `i32[][]` | the same reject | no |
| `q` initialised from a `K[][]` binding | the same reject | no |
