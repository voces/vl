### D15093 — a record binding whose literal both widens a field and drops one is refused at a narrower record

**open · loud check reject · clause 2 (`type-valid … but not yet supported by codegen`) · awaiting an owner ruling on the lowering's aliasing (coordinator, 2026-11-03) · the `shallow` spelling of `scripts/capability-probes/union-arm-from-wider-record.vl` · filed 2026-11-03 against master `464e83ad7`**

Repro:

    type A = { k: i32, legs: i64 }
    function g(): A {
      const sv = { k: 1, legs: 4, purr: true }
      return sv
    }
    print(g().legs + 1)
    // vl check: rc 1, "an object value of shape {k: i32, legs: i32, purr: boolean} flowing into A
    // drops the field `purr`: type-valid (structural width subtyping) but not yet supported by
    // codegen"

Want:

    5

#### Mechanism

The binding's literal is built at its own shape, `{k: i32, legs: i32, purr: boolean}`. Delivered
into `A` it must both widen `legs` to `i64` and drop `purr`. A drop alone is a WasmGC subtype
edge (#5956), and a widening alone is the binding's adoption at `A` (D3339), but neither serves
both: the storage differs at `legs`, so no edge exists, and adopting `sv` at `A` would lose
`purr` for a later `sv.purr` read. A converting copy at the delivery serves both, but breaks
aliasing (a write through `sv` after the delivery would not show through the result). Which
one VL owes is the ruling this row waits on.

#### Ablation

| variant | outcome |
| --- | --- |
| this witness | refused |
| `purr` removed (a widening alone) | runs, prints `5` |
| `legs: i32` in `A` (a drop alone) | runs, prints `5` |
| the destination a union `A \| B` | refused the same way |
