### D8020 — an unused record type of a literal's exact field set still stops a literal-building call widening when it passes through a type parameter

**loud check reject · clause 2 · open · the same program prints `15` once the unused `type Col` is deleted · the literal-argument face is [D7941](D7941.md) · owner lane S5 · filed 2026-10-20 against master `981320f30`**

Repro:

    type Col = { r: i32, g: i32, b: i32 }
    type J = { r: i32 | null, g: i32, b: i32 }
    function idn<T>(v: T): T { v }
    function mk() { { r: 15, g: 1, b: 2 } }
    const m: J = idn(mk())
    print(m.r ?? 0)
    // vl check: {r: i32, g: i32, b: i32} is not J: they store field `r` differently ... only a fresh record widens

Want:

    15

#### Mechanism

`mk`'s literal is built at `Col`'s row because `Col` spells its field set, so the call is
refused as an existing record (`recBuiltAtDeclared`). Re-seating `mk`'s literal at `J`
(`recFnBuiltAtDst`) is not enough: measured with that adoption added, the program becomes
check-clean invalid wasm when a second call `idn({ ... })` is delivered into a `Col`, because
the instance `idn` is taken at `mk`'s checked result and both calls share `idn<Col>`. Setting
the call's `nodeRepTyIx` to `J` does not move the instance either. The fix needs the instance
keyed by the delivery, which is emitter-side. This row is what keeps the literal half of
[D7800](D7800.md)'s `ambient` guard load-bearing.

#### Ablation

| change | outcome | needed? |
| --- | --- | --- |
| delete `type Col` | prints `15` | **yes** |
| deliver directly, `const m: J = mk()` | prints `15` | **yes**, the type parameter |
| `function mk(): J` | prints `15` | **yes**, the inferred result |
| `mk` called a second time into an un-annotated binding, `Col` deleted | prints `15` | no |

#### Grading list

before the delivery (that order is the one that shares the instance). Then D7800's ambient trace
with the literal half of the guard masked, under `tests/vl_check_within_test.ts`.
