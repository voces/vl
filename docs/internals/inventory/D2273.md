### D2273 — an un-annotated literal of `f32[]` literals builds its outer list at the wrong element row

**check-clean invalid wasm · clause 1 · found in review of #3094 (reviewer probe b1a) · filed against master `6bfe5e770`**

Repro:

    const gi = [[(1.1 as f32)], [(2.2 as f32)]]
    print(gi[1][0] / 3.0)
    // vl check: rc 0.
    // vl run: invalid module in the top-level code — expected (ref null $type), found (ref $type).

#### Mechanism

Not located. The inner literals build f32 lists, and the outer ref list's element row is not
the f32-list wrapper, so the store of an inner list into the outer backing fails validation.
The f64 twin runs and the annotated `f32[][]` runs, so the missing piece is inference of the
nested f32 element. Likely candidate: the ref-list element-code table `rlElemKindTbl` (kind
10 = f32 list) is not reached from an inferred nested literal. That is a guess and has not
been ablated.

#### Ablation

| ingredient changed | outcome | needed? |
| --- | --- | --- |

| `[[1.5], [2.5]]` (f64 elements) | runs | **yes** (the kind) |
| one inner list instead of two | still invalid | no |
