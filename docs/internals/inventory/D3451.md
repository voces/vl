### D3451 — a list literal and `??` still widen two runtime numbers of different types instead of joining them apart

**runs today and must keep running · pending an owner ruling on whether the numeric-join ruling of 2026-09-30 covers list literals and `??` · filed 2026-09-30 against master `028dedb33`**

Repro:

    function f(x: f64, y: i32) {
      const xs = [x, y]
      print(xs[1] is f64)
      const n: i32 | null = y
      const d = n ?? x
      print(d is f64)
    }
    f(2.5, 7)
    // vl run: true, true — both widen `y` to `f64`

#### Mechanism

The ruling's lane joins apart the arms of a value `if` or `match` and an inferred return set
(`joinArmLit`, `inferRetJoin`); a list literal's element join (`checkArrayLitNode`) and the `??`
result (`assignableExpr(default, inner)` then `joinTys`) still take `joinTys`' widening. A
measurement before the lane: 11 named distilled cells (`d591_*`) and one `tests/cases` file
(`unions/coalesce-result-rep.vl`) would change if they joined apart; plumb has none.

**Question for the owner.** Should `[x, y]` over an `f64` and an `i32` be `(i32 | f64)[]`, and
`n ?? x` be `i32 | f64`? Recommendation: yes for `??` (it is an `if` on `n != null` by another
spelling, and the two spellings should agree), and keep the list widening only if its storage
cost (a box per element) is judged worse than the inconsistency.
