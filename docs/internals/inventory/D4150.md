**Re-graded 2026-10-11 on a seed built from master `8a7854504`: this is now a loud check refusal (moved by `faabd3e87`, #3563), still open.** The un-annotated face refuses with `string[] is not J[]: a container never widens implicitly`. The annotated neighbour runs: `type J = null | string | J[]` then `const a: J[] = ["a"]; print(a.length)` prints `1`, and so does `const xs: J[] = ["a"]; const k: J[] = xs`. The literal-binding inference ruling says a `let` is retyped by its deliveries, so the un-annotated spelling should adapt to its destination: this refusal is a clause-2 capability gap, not a design refusal. The filed Want below stands.

#### Mechanism

The binding `xs` is a literal list that adapts to the first destination it is delivered to. A
destination whose element is a union with a list arm of its own recursive alias is not
a position the delivery knows how to widen, so `xs` keeps its `string[]` rep and the module is
invalid at the store. #3563 turns this into a loud container-widening refusal (fixture
`tests/cases/unions/error-recursive-alias-list-into-list.vl`); once it lands, that fixture
should point here, and the row should be re-graded as clause 2 only if the refusal is not the one the
non-recursive spelling already gives.
