### D3674 — a named record type passed to a generic parameter spelled `{ x: T }` has no monomorphization, so a check-clean call refuses at emit

**closed 2026-10-05 — the witness prints `2` · was a loud emit reject, clause 2 · filed 2026-10-05 by lane LW against master `18ce103be` (found in review of #3383) · fixture `tests/cases/generics/declared-record-arg-to-record-pattern.vl`**

Repro:

    type V = { x: f64 }
    function setX<T>(r: { x: T }, v: T) { r.x = v }
    const a: V = { x: 1.0 }
    setX(a, 2.0)
    print(a.x)
    // vl check: rc 0.  vl run: emitProgram: monomorphize: unsupported argument type for `r` in a call to `setX`

Want:

    2

#### Mechanism

`monoBindFromAnn` (emit_base.vl) binds an object-shape pattern (`{ x: T }`) field by field
against the argument's pin NAME, and only when that name is itself a shape spelling. An anonymous
record argument is re-spelled as its shape before the bind (`monoInstantiateCall`'s `#anon` arm);
a declared record's pin is its name `V`, so the bind found no fields, `T` stayed unbound, the
substituted pin was "", and the call refused. Fixed by `monoArgBindSpelling` (emit_mono.vl): where
the pattern rides an object shape and the pin is a declared name, bind against the argument's own
arena type spelled by its fields, which also covers the pattern under `[]` and inside another
shape. The arena type and not the name's declaration, because a field-set scan can pin an
argument to a record it is not ([D3146](D3146.md), [D3179](D3179.md), closed with this). A pattern
spelled as a generic alias application (`B<T>` with `type B<T> = { x: T }`) is a separate
mechanism and refuses for an anonymous argument too: [D3688](D3688.md).

Price: a declared record whose pattern field is not its first (`type W2 = { y: i32, x: boolean }`)
passed beside a second instance (`getX({ x: 1 })`) moved from this row's emit reject to invalid
wasm, the defect the un-annotated spelling already had on master: [D3693](D3693.md), one cell of
the `rv85` `ga` grid.
