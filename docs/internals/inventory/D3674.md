### D3674 — a named record type passed to a generic parameter spelled `{ x: T }` has no monomorphization, so a check-clean call refuses at emit

**loud emit reject · filed 2026-10-05 by lane LW against master `18ce103be` (found in review of #3383) · clause 2: `vl check` is clean**

Repro:

    type V = { x: f64 }
    function setX<T>(r: { x: T }, v: T) { r.x = v }
    const a: V = { x: 1.0 }
    setX(a, 2.0)
    print(a.x)
    // vl check: rc 0.  vl run: emitProgram: monomorphize: unsupported argument type for `r` in a call to `setX`

Want:

    2

#### Mechanism

Not yet located. The ablation puts it in how the monomorphizer binds `T` from an argument whose
type is a NAMED record (`V`) against a parameter written as an inline record with a type-parameter
field. An un-annotated argument of the same shape, an anonymous record, binds and runs. So does
a non-generic parameter `{ x: f64 }`. The refusal is `monomorphize: unsupported argument type`,
reached after the checker has accepted the call.
