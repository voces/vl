### D15472 — a record literal of named functions in a function with a hole parameter, its field written with another, holds the first's set

**closed 2026-11-05, runs and prints `3 x` · was check-clean invalid wasm (`type mismatch: expected i32, found (ref $5)` inside `go`), clause 1 · the `let` site widens a record literal's function fields with what is written into them (`letLitListsWidenAt`, `elabFnFieldTy`) only outside a generic, and a function with a hole parameter is one, so `r.f` kept `same`'s set; once `a(...)` tags that set, `r.f = dbl` stores a closure where the tagged field holds an id · closed by widening inside a generic too when every field of the literal names a declared function, whose type no instance changes (`recLitNamesFns`, check_statements.vl) · fixtures `closures/record-of-named-fn-in-generic-field-written-*.vl` · found working D15455 · filed 2026-11-05 against master `f0caaf049`**

Repro:

    function go(a) {
      const r = { f: same }
      r.f = dbl
      print(r.f(3))
      print(a("x"))
    }
    function same<T>(k: T): T { k }
    function dbl(x) { x }
    go(same)

#### Mechanism

The literal's field is typed `same`'s function type, which carries `same`'s set. Outside a
generic the `let` re-types it to a set holding every function written to the field; inside one
the re-typing is skipped, because a literal holding a value the instance types cannot record a
per-instance type on one node. A call of the parameter `a` that `same` is handed tags `same`'s
set, and the field, still of that set, is then read as an id while `r.f = dbl` stores a closure.
