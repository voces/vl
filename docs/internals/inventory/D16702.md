### D16702 — a list literal of records spread inside a list literal of a record union builds a module that fails to validate

**closed 2026-11-16 · runs, prints `1` · was check-clean invalid wasm, `vl check` rc 0, `vl run` invalid module, `type mismatch: expected (ref null $type), found (ref $type)` · clause 1 · fixed in wasmEmit.vl: `spreadFreshDestRow` takes a union build's row as the destination's, as a ref build's is, so the outer literal is built at the union's row with its literal sources; before it was built at the record row of its first spread literal · pin: `tests/cases/lists/spread-record-literal-into-record-union-list.vl` · found closing [D16701](D16701.md) · filed 2026-11-16 against master `7de7196e2`**

#### Mechanism

The linked record literal is built at the union's row (D16701), so it needs no boxing and the
outer literal takes `emitArrSpread`'s general path. There `spreadFreshDestRow` took the threaded
row only from a ref build, not from a union build, so the outer literal was built at its first
spread's record row and handed a list of records to a union-list binding. Taking a union
build's row as well builds it at the union's. The same change on a tree without D16701 lost
elements of a scalar-union spread, because a scalar literal source was not yet built at the
union's row; with D16701 it is.
