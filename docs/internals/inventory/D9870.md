### D9870 — a `??` over an un-annotated parameter bound to a never-null `i64`, then an operator over the binding, emits an `i64` where the body expects the join's box

**check-clean invalid wasm · clause 1 · the same at top level prints `5` with a never-used-default warning · found closing [D9802](D9802.md) · present on master `ba2918226` · filed 2026-10-22 against master `ba2918226`**

Repro:

    function take(a) {
      const r2 = a ?? 0.5
      print(r2 + 1)
    }
    const z: i64 = 4
    take(z)
    // vl check: rc 0.  vl run: the emitted module failed to validate inside `take`: expected (ref null $2), found i64; $2 is `union box`

Want:

    5

#### Mechanism

Not traced. At an `i64` pin the `??` cannot take its default, so `r2` is `i64`, but the
operator over `r2` reads it as the `i64 | f64` join's box, and the body stores the bare `i64`
where the box is expected. A prior call at `i64 | null` moves the failure into `take$1`, the
copy at the never-null pin.

#### Ablation

| ingredient changed | outcome | needed? |
| --- | --- | --- |
| `print(r2)` for `print(r2 + 1)` | runs, prints `4` | **yes**, the operator |
| `print((a ?? 0.5) + 1)`, no binding | runs, prints `5` | **yes**, the binding |
| the pin `i32` or `f64` | runs, prints `5` / `3.5` | **yes**, `i64` |

#### Grading list

The operators `- * <`, a lambda body, a `<T>(a: T)` body at `i64`, and the pin at `i64 | null`
beside a never-null `i64` call.
