### D15628 — a top-level call of an un-annotated function returning a field its parameter's record union stores at different value atoms is typed at the hole

**closed 2026-11-10, runs and prints `4` · was check-clean invalid wasm · clause 1 · `vl check` rc 0, then `the emitted module failed to validate inside the module's top-level code` · at module scope `nodeTyAt` read a call's checked type, the open hole, where inside a function it reads the elaboration's; a module-scope call the checker typed at an open type now reads the result of the instance it calls (`elabNodeTyAt`, emit_capture_frames.vl) · fixture `unions/shared-mixed-field-read-through-hole-param.vl` · found closing [D15605](D15605.md) · filed 2026-11-10 against master `cc8c522e`**

Repro:

    type K = { h: i32 }
    type J = { h: string, z: i32 }
    const k: K = { h: 4 }
    const u: K | J = k
    function ret(a) { return a.h }
    const r = ret(u)
    print(r)
    // vl check: rc 0.  vl run: the emitted module failed to validate inside the module's top-level code

Want:

    4

#### Mechanism

The instance `ret` pinned at `K | J` returns the `i32 | string` box, but the checker's type for
the top-level call node `ret(u)` is still the hole `_`, raw and at frame -1 (`nodeTyAt` read the
column there), so the caller held the result in an `i32` cell and `print` took `__print_i32__`.
Inside a function the same call reads the instance's result (`scopeTyAt`). Fixed: at module scope
a call whose checked type is open reads the elaboration's result for it, as a frame does. Before D15605 closed, the read
inside `ret` refused first; an annotated destination (`const r: i32 | string = ret(u)`) was
already invalid wasm.
