### D4876 — an un-annotated list of list literals keys its element from the first inner literal's leaf, not the joined one

**closed 2026-10-15 — now runs, printing `4` · was check-clean invalid wasm, clause 1 · the element's leaf is read over every inner literal, as a flat literal's is over its elements · found closing D4874, ablating its spread · filed 2026-10-15 against master `3affca3dd` · pins: `tests/cases/arrays/nested-literal-leaf-join-runs.vl`, `scripts/capability-probes/matrix/nested-list-literal-leaf-join.matrix.vl`**

Repro:

    const v = [[1, 2], [3.5]]
    print(v[0][1] / 4.0 + v[1][0])
    // vl check: rc 0.  Was: vl run: invalid module, type mismatch: expected (ref null $type), found (ref $type)

Want:

    4

#### Mechanism

The checker joins the element to `f64[]`, but `arrLitElemName` and `arrLitElemKind` keyed a
list of list literals by the leaf of its first non-empty inner literal only, so the outer list
was built at the `i32[]` row and the `[3.5]` element did not fit it. `arrLitNestedNumKind`
(emit_classify.vl) reads the leaf over every inner literal, order-blind like `arrLitNumKind`.

#### Ablation

| ingredient removed | outcome | needed? |
| --- | --- | --- |
| the wider leaf first (`[[3.5], [1, 2]]`) | runs | **yes** |
| the annotation added (`const v: f64[][] = ...`) | runs | **yes** |
| a function body instead of top level | the same invalid module | no |
