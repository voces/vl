### D15267 — a binding of a call built wider, handed to a parameter that is written through, leaves the parameter built at the wider record

**closed · runs, prints `5` · was check-clean invalid wasm, clause 1 · found closing [D15246](D15246.md) · invalid wasm on master too · filed 2026-11-04 against master `d8ba9c452` · closed 2026-11-04: `recSitesLandAt`'s own rep-argument pass (`recRepArgsNote`) gave the parameter the build's rep through the site that had just taken its own copy; it skips those sites, and the own-storage refusal in `recKeptConflicts` reads the same copy (`recOwnHoldsCopy`) · fixture `soundness/record-written-through-parameter-of-own-binding-of-wider-build-runs.vl`**


Repro:

    type J = { f: i32 | null }
    type K = { j: J }
    function mk() { { j: { f: 4 } } }
    const _k: K = mk()
    const y = mk()
    function w(p: { j: { f: i32 } }) { p.j = { f: 5 } }
    w(y)
    print(y.j.f)

Want:

    5

#### Mechanism

D15246's copy reaches `y`: its call is copied back to its own record, since `w` writes through the
parameter `y` is handed to. But `w`'s parameter is still built at `K`, so `w` stores the own-row
literal into a `K` record and `w(y)` hands it an own-row one. Some producer of a parameter's build
does not read the copy (`paramRepOf` and the argument reps the solve records, `recArgRepOf`, are
the likely ones; not yet measured). `callBuiltTy` reads it.
