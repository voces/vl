### D9020 — an un-annotated lambda calling an un-annotated function, delivered at a function type returning `f64`, loads and traps at the call

**loads then traps · `vl check` rc 0 · `wasm trap: indirect call type mismatch` · clause 1 · found closing [D9011](D9011.md) · present on `31c154cea` · filed 2026-10-21 against `31c154cea`**

Repro:

    function inc0(a) { return a + 1 }
    const f: (a: i32) => f64 = (a) => inc0(a)
    print(f(3))
    // vl check rc 0.  vl run: wasm trap: indirect call type mismatch

#### Mechanism

Not traced. The lambda is judged at the target type, so its `i32` result should convert to
`f64` inside its own body, as it does for `(a) => a + 1` and for `(a) => g(a)` with an
annotated `g`. With both the lambda's parameter and `inc0`'s parameter un-annotated, the
function value stored at `f` does not have the `(i32) => f64` signature the call expects.

#### Ablation

| ingredient removed | outcome | needed? |
| --- | --- | --- |
| the hole on the lambda's `a` (`(a: i32) => inc0(a)`) | runs, `4` | **yes** |
| the hole on `inc0`'s `a` (`inc0(a: i32)`) | runs, `4` | **yes** |
| `f64` for `i32` in the target's result | runs, `4` | **yes** |
| the expression body for a block (`{ const r = inc0(a); return r }`) | still traps | no |
| the lambda for a direct function `h(a: i32): f64 { return inc0(a) }` | runs, `4` | **yes** |

#### Grading list

The lambda handed to a `(a: i32) => f64` parameter, returned from a function declared to
return that type, and held in a `((a: i32) => f64)[]` must each print `4`.
