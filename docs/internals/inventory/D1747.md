### D1747 — a `new string` brand meeting a HOLE parameter is refused in the body as `_ and S`, on `==`, `<` and `+` alike, while the annotated spelling runs all three

**loud check reject · `vl check` rc 1, `cannot compare _ and S` · clause 2: the identical body with the parameter annotated `a: S` prints `y` · filed 2026-09-06 against `#2749`'s tree · found by the operator table [D1732](D1732.md)'s close called for · 0 corpus cells**

Repro:

    type S = new string
    const sv: S = "green"
    function take(a) {
      if a == sv { print("y") } else { print("n") }
    }
    take(sv)
    // vl check: rc 1,
    // cannot compare _ and S

Annotate `a: S` and it prints `y`. The `<` spelling says `operator '<' mixes _ and S`, and `+`
says `argument 1: operator '+' is not defined` — three operators, one shape.

#### Mechanism

Predicted, not probed. The `_` in the message is an unresolved hole RENDERING, so the refusal
comes from the body's own comparison check and not from the pin's floor: `binOpDefinedFor`
defers whenever an operand still has a hole (`tyHasHole` → true), and the message it produces
carries the pin's `argument 1:` prefix, which two of these three do not. A literal union in the
same position defers cleanly and is checked at the pin; a nominal brand is refused where it
stands.

**That is what separates this from [D1732](D1732.md).** That row was the pin mirror's gate being
narrower than `checkBinary`'s, and its close copied the gate verbatim — deliberately NOT copying
`checkBinary`'s newtype branch, which is this row.

#### Ablation

Every row measured 2026-09-06 on `#2749`'s tree.

| ingredient removed | outcome | needed? |
| --- | --- | --- |
| the un-annotated parameter (`a: S`) | runs `y` | **yes** |
| the brand (`type S = string`, or a plain `string` parameter) | runs | **yes** |
| the operator (`+` or `<` instead of `==`) | still refuses, own message | no |
| the literal-union comparison in the same position | runs `y` | no — it is the brand |

#### Grading list

* The four ablation rows above, and all three operators: a close must re-grade `==`, `<` and
  `+`, since each refuses in different words from a different site.
* The operator table this came from — `==`, `<`, `%`, `*` and `&` over a literal union all AGREE
  between the hole and the annotated spelling and must keep doing so; the brand was the only
  divergence the table found.
* [D1732](D1732.md), whose close is the reason the `+` cell of this row is not already fixed:
  the mirror copies `checkBinary`'s string-concat gate and not its newtype branch.
