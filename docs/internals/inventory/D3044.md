### D3044 — a loop variable forwarded through a second generic prints its atom id in the innermost interpolation

**closed 2026-09-28 — the filed repro prints `[a]` `[b]` · was check-clean silently wrong, clause 1, the same on master `6c2dafc0b` · closed by resolving a generic call's pin inside an instance that is not exact: `monoExactPinTyOf` now falls back to the calling instance's own parameter binding (`monoPinSubRow`, recorded per instance from its pinned parameters) or its hole binding, so `outer`'s `mid(l)` pins `mid` at `AB[]` rather than at `outer`'s `T[]`; the first instance a forwarder built was the one a later direct `mid(v)` shared, so both printed atom ids · [D3045](D3045.md) closes with it · fixture `tests/cases/generics/loop-var-forwarded-through-generic.vl` · filed 2026-09-28 against master `3a71bb1f9`**

Repro:

    type AB = "a" | "b"
    function inner<U>(x: U) { print("[\{x}]") }
    function mid<T>(l: T[]) { for e in l { inner(e) } }
    function outer<T>(l: T[]) { mid(l) }
    const v: AB[] = ["a", "b"]
    outer(v)
    // vl check: rc 0.  vl run: prints `[0]` then `[1]`

Want:

    [a]
    [b]

#### Mechanism

`monoInstantiate` banks each argument's type beside its pin (`pinTys`), and an instance's
parameter annotation is minted from it. Inside `outer`'s instance the argument `l` records `T[]`
(`outer`'s own type parameter): the body is shared with the template. `monoExactPinTyOf` only
substituted that through an EXACT instance's binding (`monoExactSubRow`), which `outer` is not,
so `mid`'s parameter was pinned at the name `AB[]` with the type `T[]`. Every reader that
resolves the loop variable at the pin (`iterElemPinTy`, through `monoParamPinTy`) then found a
type variable and fell to the `i32` default. The fix records every instance's
parameter-to-pin binding and substitutes the argument's type through it (and through a hole
instance's binding) when no exact row answers.

| `print(e)` in `mid`, no `inner` | prints `0` `1` | no |
| `outer(l: AB[])`, not generic | prints `[a]` `[b]` | **yes** (the forwarder's recorded type parameter) |
