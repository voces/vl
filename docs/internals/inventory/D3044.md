### D3044 — a loop variable forwarded through a second generic prints its atom id in the innermost interpolation

**check-clean silently wrong · clause 1 · the #3261 review's `Pr10` template, 12 cells at the literal-union, nullable literal-union and boolean pins · identical on master `59cf3b639` · filed 2026-09-28 against master `3a71bb1f9`**

Repro:

    type AB = "a" | "b"
    function inner<U>(x: U) { print("[\{x}]") }
    function mid<T>(l: T[]) { for e in l { inner(e) } }
    function outer<T>(l: T[]) { mid(l) }
    const v: AB[] = ["a", "b"]
    outer(v)
    // vl check: rc 0.  vl run: prints `[0]` then `[1]`

Want:

    [a]
    [b]

#### Mechanism

Not localised past the ablation. [D3015](D3015.md)'s close reads a loop variable at its list's
element at the instance's pin. When `mid` is reached only through `outer`, its list is the
forwarded `T[]`, and the pin of `mid`'s instance does not name the literal union there, so
`inner` is cloned at the `i32` atom with no member texts. At `boolean` it prints `[1]` for
`true`, at `AB | null` `[-1]` for `null`.

#### Ablation

| ingredient changed | outcome | needed? |
| --- | --- | --- |
| `mid(v)` called directly, no `outer` | prints `[a]` `[b]` | **yes** (the forwarding) |
| `inner(l[0])`, no loop | prints `[a]` | **yes** (the loop variable) |
| `print(x)` in `inner` | prints `0` `1` | no |
| `function inner(x)`, a hole | prints `[0]` `[1]` | no |
| a second `outer` instance at `i32[]` | prints `[0]` `[1]` `[1]` | no |
