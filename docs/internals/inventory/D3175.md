### D3175 — a hole's field function from an inline record literal is called with no function type again when the body also reads another field of the literal

**closed · the twin-row rung reads the hole parameter's row by field name, admits any field the row holds as a bare `_` and a record field that differs only in function fields in turn, so the record binds its own type · fixture `tests/cases/generics/hole-bound-record-field-function-beside-other-reads.vl` · was check-clean silently wrong · clause 1 · the continuation of D3142, found by the #3283 review (`rv3283-3186/w/w3.vl`, `w6.vl`) · the same on master `934f169f4` · filed 2026-09-29 against master `934f169f4`, closed 2026-09-29 against master `995bbc74e`**

Repro:

    function F(z) {
      print(z.v)
      const g = z.f
      print(g())
    }
    F({ v: 3, f: () => true })
    // prints 3, then 1

Want:

    3
    true

#### Mechanism

A hole parameter registers its anonymous row with `_` at EVERY field the body reads, in the
order the body reads them (`{v: _, f: _}`, `{h: _, f: _}`, `{inner: _}`), not only at the
function field. `monoObjDiffersInFnFieldsOnly` (the twin-row rung in `monoMakeInstance`) then
declined three ways: it compared fields by POSITION, so a body reading `z.h()` before `z.f`
failed on the order; it required every differing field to be a function in the argument, so
`v: i32` against `v: _` failed; and `inner: {f: () => boolean}` against `inner: _` or against a
module binding's concrete `inner: {f: () => i32}` failed as a non-function. Declined, the
instance bound the row, and `g`/`z.inner.f` had no function type at the pin. The rung now
matches fields by name, admits a bare hole on the row's side at any field (counting it as a
difference only where the argument's field reaches a function), and recurses into a record
field. The multi-instance nested face (`M(r0)` then `M(r1)` over `{inner: {f: …}}` module
bindings, 288 cells of the RF2 grid) was the same decline and closes with it.
