#### Mechanism

`parentLetOfAt` answers a name bound once in the body with that binding, whatever the read's
position; only a name bound twice is placed (`plBestDupAt`). So the dead-scoped `const s` is
what #3292's `retLocalCellKind` fix found for a read of the PARAMETER `s`, and the return was
typed `i64`. The same fast path fed `unionNameOfIdentAt`, `identLetOfAt`, the closure-sig and
copy-source readers. `parentLetReadAt` now checks that a sole binding's block holds the read,
returns -1 for a read no body `let` covers, and answers `PL_READ_UNPLACED` when a binding lies
past the block (a pass's splice). `parentLetOfAt` itself is unchanged: the capture channel
(`frameLetAt`) still asks it for a lambda's declaration site (D2325).
