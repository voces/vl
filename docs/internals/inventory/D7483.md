### D7483 — a hole-function list called at a computed index with a generic, after other evaluation in the same statement, is refused

**closed 2026-10-20 by lane L1 · runs, prints `side 3 4 8` · was loud emit reject · `vl check` rc 0 · clause 2 · CAPABILITY: the same call as a `let` value runs ([D7385](D7385.md)) · closed with [D7183](D7183.md): the computed-index read is an `Index` callee of the D7183 retype (`monoCalleeElems` → `monoOpenCallAtElems`, emit_mono.vl), which types the call in place, so no copy of the read runs ahead of `side()` · pin: `tests/cases/closures/hole-fn-list-computed-index-after-evaluation.vl` · found closing [D7385](D7385.md) · present on master `1c86d0f42` · filed 2026-10-19 against master `1c86d0f42`**

Repro:

    function add(a, b) { return a + b }
    function apply2(g) {
      print(g(1, 2))
      print(g(1.5, 2.5))
      return 7
    }
    function side(): i32 { print("side"); return 1 }
    const fs = [apply2]
    const i = fs.length - 1
    print(side() + fs[i](add))
    // vl check: rc 0.  vl run: emitProgram: a generic function is passed to a function value whose parameter type names a type parameter this closure does not bind

Want:

    side
    3
    4
    8

#### Mechanism

[D7385](D7385.md)'s close runs a copy of the computed-index read as the statement before the
call's, which is sound only while nothing evaluated before the call can observe the index's
evaluation or its bounds trap moving earlier. `side()` runs first here, and a short-circuit
operator may not run the call at all, so the copy is declined and the floor refuses.
