### D15803 — a `?.` call whose receiver is a call, written inside an assignment's operand, is refused at emit, where the same expression bound or printed runs

**loud emit reject · `emitProgram: an optional call needs a receiver the guard can read twice — bind it to a name first` · clause 2 · open · found grading D15801's `?.` matrix (`opt-call-record-fn-field-two-results.matrix.vl`) · filed 2026-11-12 against master `bd129b4d4`**

Repro:

    function half(a: i32): f64 { return a / 2.0 }
    const rs = [{ f: half }]
    let acc = 0.0
    acc = acc + (rs.get(0)?.f(3) ?? 0.0)
    print(acc)

Want:

    1.5

#### Mechanism

The `?.` call's guard reads its receiver twice, once to test it and once to call through it, so a
computed receiver must first be bound to a name (D5300). In every spelling the ablation lists as
running, that binding is made. Inside the operand of an assignment it is not, and the guard's
emitter refuses. Not yet localised to the binder: the next step is the rewrite that binds a
computed `?.` receiver (D5300) and the positions it walks.

#### Ablation

| spelling | outcome |
| --- | --- |
| the witness | loud emit reject |
| printed, `print(rs.get(0)?.f(3) ?? 0.0)` | runs, `1.5` |
| in an expression, `print(1.0 + (rs.get(0)?.f(3) ?? 0.0))` | runs, `2.5` |
| bound first, `const x = rs.get(0)?.f(3) ?? 0.0; acc = acc + x` | runs |
| a field read, not a call, `acc = acc + (rs.get(0)?.n ?? 0.0)` | runs |
