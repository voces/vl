### D1662 — a closure read out of a map records `TyFunc | null`, which the sig ladder's arena rung did not peel

**closed · filed 2026-09-05 against master `d040e263` · closed in the same PR**

`calleeCloSigKeySid`'s arena rung peels a `TyNullable` to its inner `TyFunc`, and the same
ladder reaches the module frame. Found by the `map_value` position of D1634's own template,
which had skipped itself for this since the template was written.

Repro:

    const m: { [string]: (i32) => void } = Map()
    m["k"] = (n: i32) => { print(n) }
    const mv = m["k"]
    if mv != null {
      mv(8)
    }
    // vl check: rc 0.  vl run: the emitted module failed to validate inside the module's
    // top-level code: type mismatch: expected a type but nothing on stack

#### Mechanism

The same resolver D1634 names, at a different producer. The binding's initializer is a map
read, so the checker records `((i32) => void) | null`; the arena rung tested `is TyFunc` and
a `TyNullable` is not one, so the key came back "" and the void call's statement form emitted
a `drop` over an empty stack. The narrowed read is non-null, and both spellings call at the
inner signature, so the inner's key is the right one.

A REBIND of that read (`const g: (i32) => void = mv` then `g(8)`) needed the second half: `g`
is a module-scope BLOCK binding, so the ladder's `let` rungs — the frame's body and the
globals registry — are both silent, exactly as D1636's receiver was.
