### D14758 — a hole parameter's set-rep instance dispatches on an id when an unused join puts its function beside a closure-typed one

**check-clean invalid wasm · clause 1 · `vl check` rc 0, then `failed to validate inside apply3$1: type mismatch: expected i32, found (ref $1)` · found grading the γ lane's lambda-member admission against the dispatch arms of #5487, whose lambda spelling `apply3((x) => x * 2)` fails the same way · filed 2026-11-01 against master `16e81d5ce`**

Repro:

    function apply2(g: (a: i32) => i32) { print(g(2)) }
    function apply3(g) { print(g(20)) }
    function pick(b: boolean) {
      const f = if b { apply3 } else { apply2 }
    }
    function dbl(x) { return x * 2 }
    apply3(dbl)
    // vl check: rc 0.  vl run: failed to validate inside `apply3$1`: expected i32, found (ref $1)

Want:

    40

#### Mechanism

Not traced past the ablation. The join in `pick` makes `{apply3, apply2}` a set whose rep is
`apply2`'s closure-typed signature, so `apply3` also gets an instance at that rep (`apply3$1`,
its `g` a closure). The call `g(20)` is tagged as a dispatch over `{dbl}` on the call node, and
the rep instance emits that dispatch too, reading its closure `g` as an i32 id.
