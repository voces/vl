### D15338 — a list literal of a record of an un-annotated function, read at two constant indices at two types beside another such list, is refused at emit

**open · loud emit reject · `emitProgram: cannot take the generic function \`id1\` as a value — a function value carries ONE signature, and parameter \`a\` is un-annotated (it would default to i32). Call sites pin \`id1\` at (i32), (f64)` · clause 2 · re-graded 2026-11-10 on master `e7ebdb52`: the refusal moved from the function-value call to the generic value floor (`genericFnValueRejectMsg`, emit_mono.vl), and it names a mechanism, not a contract: `xs[0]` at both types, the list without `ys`, and `const g = id1` called at both types all run · was `a function value is called at two signatures, and the closure it holds was built for one`, and before that a miscompile (clause 1) on every seed back to D15068's · found grading D15336 · filed 2026-11-04**

Repro:

    function id1(a) { return a }
    const xs = [{ f: id1 }]
    print(xs[0].f(2))
    print(xs[1].f(2.5))
    const ys = [{ f: id1 }]
    print(ys[0].f(2.5))

The module must validate: the run then prints `2` and traps on `xs[1]`, out of bounds.

#### Mechanism

`xs[1]` is past the literal's length, so mono cannot read the element it names
(`monoFlowElemAt`), and the list's field stays one closure. Fn-tag would tag `{id1}` and dispatch
each call by signature, as it does without the second list; with it the plan refuses (a direct
call `id1(2.5)` beside the list refuses the same way, at `ftCtxOk`). The closure is built at
`f64`, and `xs[0].f(2)` called it with a converted argument and read its `f64` result as `i32`.

The function-value call (`emitCallRefAt`, wasmEmit.vl) now refuses a wider result read as `i32`,
and a string or heap argument into an `i32` parameter, beside the wider-number argument it
already refused. A direct call of a member counts as a call of the set before the elaboration too
(`ftMemberDirectCall`, no longer late only), so the `id1(2.5)` spelling runs to its out-of-bounds trap. Fixtures:
`tests/cases/soundness/fn-value-closure-built-wider-than-an-i32-call-reject.vl` and
`fn-value-closure-built-at-i32-read-past-its-length.vl`.
