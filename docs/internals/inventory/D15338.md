### D15338 — a list literal of a record of an un-annotated function, read at two constant indices at two types beside another such list, is check-clean invalid wasm

**open · check-clean invalid wasm · `type mismatch: expected i32, found f64` · clause 1 · the same reads at index 0 run · found grading D15336 · present on every seed back to D15068's · filed 2026-11-04 against master `019d4cdd`**

Repro:

    function id1(a) { return a }
    const xs = [{ f: id1 }]
    print(xs[0].f(2))
    print(xs[1].f(2.5))
    const ys = [{ f: id1 }]
    print(ys[0].f(2.5))

The module must validate: the run then prints `2` and traps on `xs[1]`, out of bounds.

#### Mechanism

Not yet located. The two element reads of `xs` at different constant indices are typed apart
(`xs[0].f` at `i32`, `xs[1].f` at `f64`), and a second list holding the same function read at
`f64` is needed, so the per-literal pin of `id1` in one list is read at the other's type.

#### Ablation

| --- | --- | --- |

| `ys` | traps at run time only (validates) | **yes** |
| `ys[0]` → `ys[1]` or `ys[2]` | still invalid | no |
