### D17260 — a module `const` holding an atom global's assignment, read from a function: the claimed `start` is invalid wasm

**check-clean invalid wasm · clause 1 · claimed start invalid, fallback runs: under `VL_IR_STRICT=1` the build stops with the module invalid (exit 70); the normal build ships legacy bytes with a stderr note · claimless runs (claimless compiler sha256 `5dc8e893…` built in a clean tree at master `838bb284e`) · owner N11 · found by IR-N7's `assignment-value-of-atom-cell` Q58 template (`closure_capture_unann`) · filed 2026-11-24 against master `838bb284e`**

Repro:

    type K = "zz" | "ww"
    let k: K = "zz"
    const c = (k = "ww")
    const f = () => { print(c) }
    f()
    // VL_IR_STRICT=1 vl run: the emitted module failed to validate inside the module's top-level
    // code: unknown local 4: local index out of bounds

Want:

    ww

#### Mechanism

The module's `start` reads the assignment as the value of a `const` the closure reads, and the
IR's build of that `start` is claimed although its bytes differ from legacy's (`VL_IR_SHADOW=5`:
start covered, `mismatch start bytes: prefix or locals at 0x30 vs 0x34`): it names a local the
start never declares.

#### Ablation

| ingredient | outcome |
| --- | --- |
| `const c: K = (k = "ww")`, annotated | runs |
| a `string` or an `i32` global | runs |
| `const c = k`, a plain read | runs |
| `print(c)` at module scope, no function reads `c` | runs |
| `function f() { print(c) }` instead of the lambda | invalid, the same |
| `let k: K \| null` | runs on master (uncovered); IR-N7 keeps it uncovered |
