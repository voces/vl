### D2713 — a map of a numeric literal value delivered as the map of that literal or null builds invalid wasm

**check-clean invalid wasm · clause 1 · found in the #3198 review · identical on master
`fdd0050af` · filed 2026-09-26 by the NR lane**

Repro:

    const m: {[string]: 1} = Map()
    m["k"] = 1
    const w: {[string]: 1 | null} = m
    print(w.length)
    // vl check: rc 0.  vl run: invalid module, "type mismatch: expected (ref null $type), found (ref $type)"

#### Mechanism

Not yet measured. A literal value is one i32 cell, so the source is the mono map; the checker
treats `1 | null` as the same storage and shares the map, while the emitter builds the
destination at another map struct. The prediction is that `1 | null` interns its own value
slot (a nullable literal union) where `boolean | null` rides the mono map.

#### Ablation

| ingredient removed | outcome | needed? |
| --- | --- | --- |
| the literal (`i32` and `i32 \| null`) | refused at check, `never widens implicitly` | **yes** |

#### Grading list

The same delivery at a parameter and a return. The string-literal sibling,
`{[string]: "a"}` into `{[string]: "a" | "b"}`, is also check-clean invalid wasm at every key
rep and at a binding, parameter and return (identical on master): the checker classes both
values as the same storage while the emitter stores a lone string literal as a string and the
union as an atom id. Refusing it as stored differently would be a true reason; running it
needs the emitter to store the lone literal as the atom.
