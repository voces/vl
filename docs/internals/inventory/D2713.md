**closed · now a loud check reject, a design refusal (`a container never widens implicitly`), as the `i32` spelling's · was check-clean invalid wasm, clause 1 · found in the #3198 review · filed 2026-09-26 by the NR lane · closed 2026-11-01 against master `9c392feb`: an integer literal value, or a union of them, had no storage class, so the map pair was judged by nothing; it is now stored as `i32` (`escIntLitStored`, check_ty_rep.vl) and refused beside a value that adds `null`, as `{[string]: i32}` into `{[string]: i32 | null}` is · fixture `soundness/error-map-of-int-literal-delivered-nullable.vl`**

#### Mechanism

Measured at the close: `elemStoreClassOf` answered no class for a lone integer literal, so
`containerElemClassDiffers` declined and the map was shared with one the emitter stores
differently. The prediction below was the filing's.

Not yet measured. A literal value is one i32 cell, so the source is the mono map; the checker
treats `1 | null` as the same storage and shares the map, while the emitter builds the
destination at another map struct. The prediction is that `1 | null` interns its own value
slot (a nullable literal union) where `boolean | null` rides the mono map.
