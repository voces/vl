### D2823 — `==` between two union values refused when either is not a binding, though the staged box compare evaluates each operand once

**closed 2026-09-27 — the witness prints `true` · was a loud emit reject after `vl check` rc 0, `emitProgram: union \`==\` over a non-binding union value is not supported yet`, clause 2 · 10 cells of the #3210 review's `rv3r2w/g2` eq family · filed 2026-09-27 against master `cf6d7f102` · fixture `tests/cases/unions/union-eq-non-binding-both-operands.vl`**

Repro:

    function p(): boolean { true }
    print((if p() { 1 } else { "s" }) == (if p() { 1 } else { "t" }))
    // vl check: rc 0.  vl run: emit error — union `==` over a non-binding union value

#### Mechanism

`emitUnionUnionEq`'s value-union lowering re-reads both operands once per shared arm, so it
refuses any operand `unionEqOperandOk` does not call re-readable (a call, an if-expression). The
struct-union path beside it already evaluates each operand once and compares the two parked
boxes (`emitUnionBoxEqStaged`), and that core serves scalar arms too. The close routes a
non-re-readable pair there, over the left union's arms: box tags are per atom, so a right-hand
arm the left lacks fails the tag test and a shared tag names one payload rep on both sides.

#### Ablation

| ingredient changed | outcome | needed? |
| --- | --- | --- |
| both operands bound first (`const l = …; const r = …; l == r`) | runs | **yes** |
| one operand bound, the other a call | still refused | no |
| scalar arms → struct arms of one declared union | already ran (D973) | — |

#### Grading list

Calls and if-expressions on either side, unions differing in members (`i32 | string` against
`i32 | string | boolean`), float arms, struct unions, `!=`, and an evaluate-once counter (both
calls run exactly once).
