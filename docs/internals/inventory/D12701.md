### D12701 — a list of hole functions handed a frame's forwarded hole function and a value has no interned signature

**loud emit reject · `vl check` rc 0 · clause 2 · CAPABILITY: the same loop handed the named `add` runs ([D10700](D10700.md)) · found closing [D10700](D10700.md) · filed 2026-10-25 against master `a448ccb42`**

Repro:

    function add(a, b) { return a + b }
    function apply2(g, s) {
      print(g(1, 2))
      print(g(s, s))
    }
    function apply3(g, s) {
      print(g(10, 20))
      print(g(s, 0.25))
    }
    function inner(k, h) {
      for f in [apply2, apply3] { f(h, k) }
    }
    inner(0.5, add)
    // vl check: rc 0.  vl run: emitProgram: a function-value call has no interned signature — parameter 1 of type `` has no representation in the function-value ABI

Want:

    3
    1
    30
    0.75

#### Mechanism

The split gives `h` and each element's `g` one slot per call key, and the instance of `add` that
fills each of `h`'s slots is chosen at the OUTER call `inner(0.5, add)` from the pins of the
element calls the slot reaches. Two keys here name an element's own value parameter
(`g(s, s)`, `g(s, 0.25)`), and nothing at the outer call binds `s` to the type `k` takes there,
so those pins stay open and the call is refused at `add`. Reading them under the elements' value
binding at the INNER call instead (`monoElemPinTysUnder` in `monoElemParamTys`, emit_mono.vl)
types the element call at `f64` while the outer call still fills the slot with `add`'s `i32`
instance: `wasm trap: indirect call type mismatch` in `apply3`. So the binding has to reach
the outer call's choice of instance, not the inner call's typing. Keys that are closed
(`g(0.5, 0.25)`) run since a forwarded parameter binds the elements' value parameters at the
instance.
