### D6001 — an un-annotated lambda passed to an un-annotated parameter and returned has no monomorphization pin

**closed 2026-10-17 by lane L1 · runs, prints `3` · was loud emit reject · clause 2 · an argument whose type is an open function type and that names no function takes the one closed pin the fn-flow table gives it past the call (`monoOpenFnFlowPin`), as a hole function's argument already did · pins: `tests/cases/closures/hole-fn-or-lambda-through-hole-handed-on.vl` · one binding of `fw(lam)` called at `3` and `"w"` is filed as [D6020](D6020.md) · found closing [D5972](D5972.md) · the same on master `200c89ff8` · filed 2026-10-17 against master `200c89ff8`**

Repro:

    function fw(f) { return f }
    const lam = (x) => x
    const q = fw(lam)
    print(q(3))
    // vl check: rc 0.  vl run: emitProgram: monomorphize: unsupported argument type for `f` in a call to `fw`

Want:

    3

#### Mechanism

From the ablation only. A top-level function `id` passed to `fw` the same way runs, so the
pin for `fw`'s parameter is found for a function declaration and not for a lambda whose
parameter is a hole.
