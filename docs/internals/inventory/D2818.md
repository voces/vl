### D2818 — a generic's annotated `T[][] | i32[][]` return collapses at the pin, so the parameter's arm is lost

**closed 2026-09-27 · was check-clean silently wrong, clause 1, on master `1df19732b` · found by the #3214 review (h5 `f3`) · filed 2026-09-27 against master `cf6d7f102` · fixture `tests/cases/generics/annotated-type-param-list-union-return-keeps-both-arms.vl` · closes [D2859](D2859.md) too**

Repro:

    function k<T>(c: boolean, t: T): T[][] | i32[][] {
      if c { return [[t]] }
      [[1]]
    }
    const z = k(true, 2.5)
    if z is f64[][] { print(z[0][0]) } else { print("not f64[][]") }
    // vl check: rc 0.  vl run: prints `2.5`.  Was: prints `not f64[][]`

Want:

    2.5

#### Mechanism

The collapse was at the declaration, not the pin: the template's written return
`T[][] | i32[][]` resolved to `T[][]`. The annotation routes dedupe a union's members by
`sameVariantTy`, and inside a generic body `i32[][]` and `T[][]` are assignable both ways, so
the concrete arm was dropped as a duplicate. `tyParamsPart` keeps a type parameter's list apart
from a concrete one only under `tpApartConcrete`, which #3211 set for a return set's join
alone. The annotation dedupe (`annUnionPushDistinctMember`, and `annUnionInnerTy`'s own pass)
now sets it too: a written union names its arms. At a pin that makes the two arms one list
(`T := i32`) the substituted `T[][]` is a fresh arena index, so `substTyDeep`'s union rebuild
now dedupes two equal list members (`substListTwin`) as well as two equal indices.

#### Ablation

| ingredient removed | outcome | needed? |
| --- | --- | --- |
| the type parameter (`t: f64`, `: f64[][] \| i32[][]`) | runs, prints `2.5` | **yes** |
| the annotation (inferred return) | runs, prints `2.5` | **yes** |
| one level of nesting (`: T[] \| i32[]`, `[t]`) | still prints `not f64[]` | no |
