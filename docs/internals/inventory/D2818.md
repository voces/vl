### D2818 — a generic's annotated `T[][] | i32[][]` return collapses at the pin, so the parameter's arm is lost

**check-clean silently wrong · clause 1 · found by the #3214 review (h5 `f3`) · the same on master `cf6d7f102` and on `95ad622d8` · filed 2026-09-27 against master `cf6d7f102`**

Repro:

    function k<T>(c: boolean, t: T): T[][] | i32[][] {
      if c { return [[t]] }
      [[1]]
    }
    const z = k(true, 2.5)
    if z is f64[][] { print(z[0][0]) } else { print("not f64[][]") }
    // PRINTS not f64[][]

Want:

    2.5

#### Mechanism

An annotated union of a type parameter's list and a concrete list keeps master's collapse
(#3211 scoped the apart join to an inferred return set), so at `T := f64` the declared
`f64[][] | i32[][]` is not the union the direct spelling declares, and the `[[t]]` return is
not boxed under the `f64[][]` arm the `is` test reads. At `T := string` the same collapse
refuses the call as `return type mismatch: expected string[][], got i32[][]`, a clause-2
refusal of a program whose direct spelling runs. Not yet localised further.

Re-graded 2026-09-27 (#3227 review): keeping the written union's arms apart in the annotation
dedupe closes this row, but it makes the checker refuse `.length`, indexing and `for`-`in` over
`T[] | i32[]` at every non-`i32` pin (`wrap("ada").length` printed `1` on master), because the
checker has no member access shared by a union of lists. The close depends on that list-union
shared-member capability; the dedupe change is withdrawn until it lands.

Re-graded 2026-09-27 on top of that capability (#3229, then the D2876 lane): the dedupe
re-applied closes this row and D2859, runs 11 wrong values and 18 check rejects of the 60-cell
`wrap` grid and 16 wrong values and 12 invalid modules of the 900-cell delivery grid, and costs
4 cells that ran at a record pin in an anonymous object's field (`{ f: wrap({ x: 4 }) }`), one
of them a cast trap under `for`-`in`. Those are D2891, which an inferred return set already
hits; the dedupe waits on it.
