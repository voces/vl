### D2818 — a generic's annotated `T[][] | i32[][]` return collapses at the pin, so the parameter's arm is lost

**check-clean silently wrong · clause 1 · found by the #3214 review (h5 `f3`) · the same on master `cf6d7f102` and on `95ad622d8` · filed 2026-09-27 against master `cf6d7f102`**

Repro:

    function k<T>(c: boolean, t: T): T[][] | i32[][] {
      if c { return [[t]] }
      [[1]]
    }
    const z = k(true, 2.5)
    if z is f64[][] { print(z[0][0]) } else { print("not f64[][]") }
    // PRINTS not f64[][]

Want:

    2.5

#### Mechanism

An annotated union of a type parameter's list and a concrete list keeps master's collapse
(#3211 scoped the apart join to an inferred return set), so at `T := f64` the declared
`f64[][] | i32[][]` is not the union the direct spelling declares, and the `[[t]]` return is
not boxed under the `f64[][]` arm the `is` test reads. At `T := string` the same collapse
refuses the call as `return type mismatch: expected string[][], got i32[][]`, a clause-2
refusal of a program whose direct spelling runs. Not yet localised further.

#### Ablation

| ingredient removed | outcome | needed? |
| --- | --- | --- |
| the type parameter (`t: f64`, `: f64[][] \| i32[][]`) | runs, prints `2.5` | **yes** |
| the annotation (inferred return) | runs, prints `2.5` | **yes** |
| one level of nesting (`: T[] \| i32[]`, `[t]`) | still prints `not f64[]` | no |

#### Grading list

`k(true, "s")` with `is string[][]` (a check reject today, wants `s`); `k(false, 2.5)`, which
must keep printing `not f64[][]`.
