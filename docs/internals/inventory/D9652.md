#### Mechanism

`monoFlowReads` rewrites each read of a list literal's element to the generic that element
names, then notes the generic names the planned literals still hold as inert. Planning
`ys[1]`, `monoFlowUsePlan` saw `v`, which then named no generic, because `monoFlowLeafGen`
does not look through the read `xs[0]`. It left `ys[1]` unrewritten. The same round rewrote
`xs[0]` to `id`, so `monoFlowNoteInert` noted `v` inert as a planned literal's value. `v`
then took the `string` instance that `c`'s lane gave the list, and `ys[1](2)` called it
through a slot at `i32`. The same list as `[id, v]` was a loud
`a function-value call has no interned signature`, from the same cause.
