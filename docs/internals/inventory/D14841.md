### D14841 — a capturing lambda, or a lambda handed on, called at two signatures leans on the split plan for a closure per signature

**runs today and must keep running · runs only because the split plan copies the hole parameter per tuple; with the split plan and the D6210 rung off it refuses at emit (`unsupported argument type for `f` in a call to `lap4``) · closes when the elaboration mints one instance of the lambda body per call signature, each built with its environment at the lambda's creation site (architecture-target-2026-10.md, increment 3) · filed 2026-11-01 against master `0caff2602`**

Repro:

    function lap4(f) {
      print(f(3))
      print(f(2.5))
    }
    function mk4(k: i32) { lap4((a) => a + k) }
    mk4(1)

Want:

    4
    3.5

#### Mechanism

A lambda that captures, or one handed on before it is called, cannot be a set's id (`ftLambdaIdOk`): an id call goes to the declaration with no environment. Called at two signatures, it needs one closure per signature, and today only the split plan gives it that, by copying the parameter per call tuple.

| the second call type (`f(3)` twice) | runs | **yes** |

#### The bundle, 2026-11-02

`monoPinHoleParam` now hands such a lambda as a bundle (closure-at-delivery step b): one
anonymous record, field `c<k>` the closure built at the `k`th signature the elaboration notes
for the parameter (`elabCallBundleSigs`), each read from the built-closure row. A call through
the parameter reads its own field (`compiler/emit_bundle.vl`). With the split plan and the D6210
rung off, the witness and two of the four grading files run:

| file | split off, before | split off, after |
| --- | --- | --- |
| the witness | emit refusal | runs |
| `closures/hole-lambda-member-tagged.vl` | emit refusal | runs |
| `functions/hole-lambda-literal-at-two-instances.vl` | emit refusal | runs |
| `functions/hole-param-given-two-lambdas-calling-generic-at-two-types.vl` | emit refusal | emit refusal |
| `closures/lambda-through-hole-param-called-with-generic-at-two-types.vl` | emit refusal | emit refusal |

The last two are another shape: the parameter called at two signatures is the lambda's own,
and what it is handed is a declared generic (`id`), through a call by value. The elaboration
notes signatures only for a parameter bound to lambdas, so neither is a bundle yet.

Not bundled, and so still on the split plan: a parameter read other than as a callee (handed on,
stored or captured), a lambda reached through a binding rather than written at the call, and a
parameter handed several different lambdas, which the elaboration binds to no set.

#### A lambda written in an instanced body, 2026-11-02

Each instance of the encloser hands its own closures, built where the lambda is cloned for that
instance. The elaboration keeps one callee instance per encloser instance (their lambda sets
differ), and mono builds one, since both bundles are the same record. `elabDemandFrom` therefore
answers a bundle pin with the call's own instance (`elabPinsHoldBundle`, `elabBundlePinTaken`),
so the shared callee reads an instance whose calls through the parameter are typed. Without it,
`capT<T>(k: T) { lap((a) => { print(k); return a }) }` at `7` and `"g"` was invalid wasm with a
late demand for `lap`. It runs now, with no late demand.
