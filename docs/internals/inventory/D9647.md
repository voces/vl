### D9647 — a list literal of a record of an un-annotated function handed to an un-annotated parameter that passes the element on leaves the function unpinned

**closed · runs, prints `4` · was loud emit reject, `vl check` rc 0, `emitProgram: cannot take the generic function `inc0` as a value`, clause 2 · found closing [D9570](D9570.md) · the un-annotated `argument` cell of matrix `hole-fn-record-list-element` · filed 2026-10-22 against master `9e81d3ee3` · closed by the flow table registering the relayed parameter's field call (`ffBoundObjHasField`, fn_flow_shadow.vl) and the source retype following a list literal argument's element slot to the record literals it holds (`monoOpenFnRecSrcPin`, emit_mono.vl) · fixture `closures/hole-fn-record-list-literal-relayed-to-field-call.vl` · with [D9642](D9642.md) closed; two list literals sharing one field name are [D9951](D9951.md), since closed**

Repro:

    function inc0(a) { return a + 1 }
    function take(a) { print(a.f(3)) }
    function use(v) { take(v[0]) }
    use([{ f: inc0 }])
    // vl check rc 0.  vl run: emit error: emitProgram: cannot take the generic function `inc0` as a value

#### Mechanism

`use` is pinned at `{f: (_) => _}[]`, so the instance of `take` it calls is handed an open
field and nothing pins `inc0`. The pins that instance a record's function at the field call
(`monoOpenFnRecListPin`, `monoOpenFnRecSrcPin`, emit_mono.vl) read the literal at the call that
holds it, and here `v[0]` reads a parameter of a generic instance, which both decline.

| the hole in `inc0` (`inc0(a: i32): i32`) | runs, `4` | **yes** |
