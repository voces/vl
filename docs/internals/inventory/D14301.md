### D14301 — the generic-application span test reads `Tag | Box<i32>` as one application because it ends in `>`

**closed · runs, prints `1` · was a loud emit reject, `unknown struct field in field access` · test `tests/cases/generics/union-member-generic-application-inline-reversed-order.vl` · filed 2026-10-26 against master `2f9786dae`**

Repro:

    type Box<T> = { v: T }
    type Tag = { t: i32 }
    const x: Tag | Box<i32> = { t: 1 }
    if x is Tag { print(x.t) } else { print(x.v) }
    // vl check: rc 0.  vl run: emit error, unknown struct field in field access

Want:

    1

#### Mechanism

`annGenAppSpanEnds` accepted any name that ends in `>` and has a `<` at a positive index.
`canonEmitNameTs` asks it before its union arm, so `Tag|Box<i32>` was canonicalised as one
generic application with the head `Tag|Box`. Its members were never canonicalised, and the
same union written `Box<i32> | Tag` was. The test now also requires the text before the first
`<` to be one, possibly mangled, name.

#### Ablation

| ingredient removed | outcome | needed? |
| --- | --- | --- |
| the member order (`Box<i32> \| Tag`) | runs | **yes** |
| the `else` read of `x.v` | prints nothing, the D14303 outcome | no |
| `const` replaced by `let` and a reassignment | invalid wasm | no |

#### Grading list

The span test has sixteen other callers. A function type returning an application,
`(x: i32) => Box<i32>`, also ends in `>`; the test now answers false for it.
