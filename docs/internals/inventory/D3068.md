### D3068 — a list callback that changes its source's length reads a stale element, traps, or walks the new length, by receiver and by op

**check-clean silently wrong · clause 1 · open, needs a ruling · found grading D3060 (the push and pop cells of its grid) · the same on master `6c2dafc0b` · filed 2026-09-28 against master `6c2dafc0b`**

Repro:

    const h: i32[] = [1, 2, 3]
    let first = true
    let out = ""
    for e in h.filter((e) => {
      if first {
        first = false
        h.pop()
      }
      return e > 0
    }) { out = out + "\{e}," }
    print(out)
    // PRINTS 1,2,3,

#### Mechanism

The core `.map`/`.filter` read the length once, at entry, and then read the backing directly,
so after a `pop` in the callback they read the popped element out of the backing's spare slot.
Over a `readonly` view (D3028) the same read goes through the view's bound-checked getter and
traps (`out of bounds array access`). `std:array`'s `reduce` and `mapIndexed` re-read
`self.length` every step instead, so a `push` in the callback extends the walk (`reduce` over
`[1, 2, 3]` pushing `7` once sums `13`; `.map` stops at 3 elements), and a callback that pushes
every time never ends. D3060 settled the element-value half like JavaScript: the value a
callback sees is read once. The length half is a ruling: JavaScript fixes the length at entry
and skips an index at or past the current length (`filter` gives `1,2,`, `reduce` `3`), and
leaves a hole in `map`'s result, which VL has no rep for.

**Recommendation:** every callback op, core and `std:array`, fixes the length at entry; an index
at or past the current length is skipped by `filter` and `reduce`, and ends `map` and
`mapIndexed` with the index-out-of-range trap an `xs[i]` read would raise, on plain lists and
views alike. Costs one length read per step in the core loops.

#### Ablation

| ingredient changed | outcome | needed? |
| --- | --- | --- |
| `h[0] = 9` in place of `h.pop()` | prints `1,2,3,` (right, D3060) | **yes** (a length change) |
| `.map((e) => e)` | prints `1,2,3,` | no |
