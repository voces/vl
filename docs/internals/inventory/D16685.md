### D16685 — `u as i32 | null` parses as `(u as i32) | null`, and the refusal names the operator, not the `as?` the author meant

**closed 2026-11-16 · now a loud check reject whose refusal adds `` — `as` takes a bare type, so `| null` here is a bitwise or; write `x as? i32` for an `i32 | null` `` (`castOrNullNote`, check_operators.vl) · first-error quality · lane AE conversion audit · filed 2026-11-16 against master `6356d3e7d` · fixture `numerics/error-as-cast-or-null.vl`**

Repro:

    function f(u: f64): i32 | null {
      return u as i32 | null
    }
    print(f(3.5))
    // was: operator '|' is not defined for i32 and null

#### Mechanism

`as` takes a bare type name, so `| null` becomes a bitwise-or operand. The author meant a cast
to the nullable type, which is `as?`. When the right operand of `|` is the `null` literal and the
left is an `as` cast, the operator refusal could name `u as? i32`.
