### D16864 — a generic a maker returns, stored by an index write into a map and called there at another type, must keep its own instance at each call site

**runs today and must keep running · refutation pin (slot store, D16768) · the `map_value/unann` and `map_set/unann` cells of `generic-relay-two-results` · filed 2026-11-16 against master `b867e6aed`**

Repro:

    function __k<T>(x: T): T { return x }
    function __mk() { return __k }
    function __dlv() { return __mk() }
    const __w: (x: string) => string = __dlv()
    print(__w("s"))
    const __m = Map()
    __m["k"] = __dlv()
    const __mv = __m["k"]
    if __mv != null { const v = __mv; print(v(41)) }
    // vl run: s, then 41. Trapped (indirect call type mismatch) between #8731 and its fix-forward.

Want:

    s
    41

#### Mechanism

The delivery walk never followed a value forward through an index write (`m[k] = v`, `xs[i] = v`)
or a `set` into a list or map element: from `__k`'s read it saw only `__w`'s `(string) => string`, and mono's
per-call-site maker clones built the map site's own instance another way. The place classes follow
the write (correct reachability), so `__mk`'s return read was delivered at `(string)` and `(i32)`,
and mono built one wrong instance for both: a trap. The fix-forward leaves an index write's or a `set`'s
edge out of a call search read from a value (`eplSlotCallRecs`, `EPL.idxWrites`), as the walk
did; a search read from the element itself still takes it.

The real fix is mono's (lane AE, per-binding instancing #8705): a maker-returned generic read
delivered at two types takes an instance per call site, never one; the classes may then follow the
write. Probed for a spelling that traps on the pre-flip seed (`69032f02`): a relay with no maker
(`__dlv` returns `__k`) runs there and runs here; a list-element write is refused at emit on every
seed; none traps.

#### Per call site (lane WIDTH)

A relay call with no closed context whose result an index write, `set` or `push` stores into a
container element now takes the one closed signature that element's reads are called at
(`fvaWrittenElemSig`, `check_assignable.vl`): through un-annotated `const` bindings and null tests,
two signatures or an escaping read leaving it unclosed. The relay is then twinned per call site as
for two bindings (`fvaRelayTwinRows`), and the emitter reads the twin back (`elabRelayResultAt`).
The place classes now follow such a write; the index-write omit stays only for a write whose
value is not twinned, since a map element called at two signatures has no one twin and traps
without it ([D16868](D16868.md)). A `push` of the relay call, an emit refusal before, runs.

#### Grading list

`relay-generic-written-into-element.matrix.vl` (map index write, `set`, list index write, `push`,
two signatures, called twice); the index-write omit in `eplSlotCallRecs` goes entirely once a map
element called at two signatures takes an instance per read.
