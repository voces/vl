### D6460 — a captured un-annotated binding of a mixed-width literal-union list has its softened, deduped type, and that type has no ref-list row

**loud emit reject · 4 cells of the `annotated-mixed-width-litunion-list` matrix (`block_if_capture`, `block_while_capture`, `block_bare_capture`, `fn_body_capture`, un-annotated face) · filed 2026-10-18 against master `4d1802f96`**

Repro:

    const src: (9000000000 | 1 | 9000000001)[] = [9000000000, 1, 9000000001]
    function frame() {

#### Mechanism

`c`'s inferred annotation is the softened render `(i64|i32)[]`, whose element type is the
two-member `i64|i32` with no literal members. The ref-list row for the list is keyed by the
source's own element type, `9000000000|1|9000000001` (member sequence `i64|i32|i64`), so
`captureValStructIdx` reads `annValtypeSlotOf` of the softened annotation, `rlSlotOfTy` finds
no row, and the env field's valtype has slot -1. Minting a row for `i64|i32` is not the fix:
box tags are positional, and a two-member set does not carry the source's three-member
sequence. The binding needs the source's element type, not the softened one. Before L6's keyed
mint, this cell refused earlier, at `index access but array type not collected`.
