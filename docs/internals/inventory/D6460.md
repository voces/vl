### D6460 — a captured un-annotated copy of a mixed-width literal-union list has a synthesized annotation whose ref-list row its recorded type does not find

#### Mechanism

`synthCaptureCopyAnn` gives `c` a synthesized annotation spelled by the render `(i64|i32)[]`
and recording the source's own type, `(9000000000 | 1 | 9000000001)[]`. A probe of
`captureValStructIdx` showed one ref-list row in the program, `i64|i32`, whose recorded
element type is the two-member `i64 | i32`: the list is stored at its render's row. The
recorded type's element key (`repElemId` of the literal union) is not that row's key, so
`annRefArrSlot` found no row by type. The intern pass banks a user-written annotation's row by
spelling (`annRlSlotAt`), but that pass ran before this synthesis. The env field's valtype
therefore had slot -1. The filed sentence that the row is keyed by the source's own element
type was wrong; the probe refuted it. Before L6's keyed mint, this cell refused earlier, at
`index access but array type not collected`.

#### Fix

`synthCaptureCopyAnn` banks the row of the element's member bases (`synthAnnBankRlSlot`,
`emit_collect.vl`), only where the recorded type finds no row. It reads the type, not the
render: `intLitUnionBasesOf` gives `[i64, i32]`, and `rlSlotOfUnionMembers` finds the row keyed
by that member sequence. The env field takes the row the source list was built at, so no new row
is minted and no member set changes. The pin covers the four matrix capture positions, a local source, a closure
returning the copy, one passing it to an annotated parameter and a copy of the copy.
