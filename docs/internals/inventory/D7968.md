### D7968 — a hole's map read is typed at the map's value, so a `??` over it drops the `null` and the boolean

**closed 2026-10-20 by lane L6b · runs, prints `2.5` then `null` · was check-clean silently wrong, printed `2.5` then `0` · clause 1 · the checker's hole substitution read a map pin's element as the bare value, where the direct read is the value or `null`; `substHoleTyReal` now answers the read through `mapPinReadTy`, and a `??` typed at that join pins its call argument at the union · pin: `tests/cases/literal-unions/coalesce-hole-join-arg.vl` · filed 2026-10-20 against master `aec7a5332`**

Repro:

    type R = { a: {[i32]: f64} }
    function show(x) { print(x) }
    function mk(): R {
      const a: {[i32]: f64} = Map()
      a[3] = 2.5
      { a: a }
    }
    function use(p) {
      show(p.a[3] ?? p.a[4])
      show(p.a[9] ?? p.a[4])
    }
    use(mk())
    // vl check: rc 0.  vl run: prints 2.5 then 0

Want:

    2.5
    null

#### Mechanism

In the hole instance a read `p.a[k]` off a map pin was substituted as the map's value type,
`f64`, while the same read at the direct spelling is `f64 | null`. The `??` of two such reads
therefore typed as `f64`, and the miss's `null` was delivered as the scalar's zero. The same
substitution typed a boolean map's `p.a[k] ?? 3` as `i32`, so its hit printed `1`.

#### Ablation

| ingredient changed (on master `aec7a5332`) | outcome | needed? |
| --- | --- | --- |
| `use(p: R)` | runs, prints `2.5` then `null` | **yes**, the hole |
| `print(...)` in place of `show(...)` | runs, prints `2.5` then `0` | no, any consumer |
| a `boolean` map, `show(p.a[3] ?? 3)` | runs, prints `1`, want `true` | no, any value type |
| default `1.5` in place of the second read | runs, prints `2.5` | **yes**, a nullable default |

#### Grading list

The annotated twin, the `print` consumer, the boolean map at a call argument, and the
three-link chain `p.a[9] ?? p.a[8] ?? p.b[3]` over an `f64 | null` and an `f64` map, at a hit
and at a miss.
