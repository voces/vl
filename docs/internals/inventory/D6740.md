### D6740 — a binding annotated with one type parameter and seeded from a parameter of another, beside a `const` of a third, prints a wrong value

**closed 2026-10-18 by lane L1 · runs, prints `x`, `3` then `true` · was check-clean silently wrong · `vl check` rc 0 · clause 1 · closed with [D6703](D6703.md) by the same split: `b` and `c` each take the instance of the parameter they are seeded from · pins: `tests/cases/generics/typaram-binding-seeded-from-another-typaram.vl` · found closing [D6703](D6703.md) · filed 2026-10-18 against master `73713bacf`**

Repro:

    function same<T>(k: T): T { k }
    function mid<F, G, H, G1>(a: F, a1: G1, a2: H) {
      let b: G1 = a1
      const c: G = a2
      print(a("x"))
      print(b(3))
      print(c(true))
    }
    mid(same, same, same)
    // vl check: rc 0.  vl run: prints x, 3 then 1

Want:

    x
    3
    true

#### Mechanism

The `const c: G = a2` binding is annotated with `G`, which no parameter takes, and seeded from
`a2: H`; the emitter built `c` at `G`'s instance, the one `same` takes at `i32`, so
`c(true)` printed the `boolean` as `1`.
