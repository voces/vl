### D2264 — an un-annotated binding of an `if` whose then arm is narrowed by its own condition takes the box cell

**check-clean invalid wasm · `vl check` rc 0, then the emitted module fails validation inside
the enclosing function, clause 1 · found by the #3088 round-2 review; the same on master
`bb0252d99` before #3088 · filed 2026-09-23 against master `bb0252d99`**

Repro:

    function f(c: boolean, n: i32 | null, m: i32 | null) {
      const w = if n != null { n } else { 0 }
      print(w + 1)
    }
    f(true, 3, null)
    f(false, null, null)
    f(true, null, 9)
    // vl check: rc 0.  vl run: invalid module,
    // "type mismatch: expected (ref $type), found i32"

#### Mechanism

The join is `i32` and the `if` lowers as `i32`, but the un-annotated local is declared as the
union box: the binding's cell is classified off the then arm, `n`, read at its declared
`i32 | null` rather than under the `n != null` narrowing the arm is evaluated in. The same
then-arm reading is what #3088's first cut tripped over in `emitIfExpr`; #3088 moved the
lowering onto the join's own recorded type, and this is the binding-cell half of the same
question. A prediction until a close confirms which classifier declares the cell.
