### D16473 — `as f64` over a join of integer literals reads a radix arm as its 32-bit pattern, not the value its digits spell

**check-clean silently wrong · clause 1 (`vl check` rc 0) · found by fuzz-nightly run 43686086648 (oracle leg, `ar_s41_0106`, where an `as! i32` that must trap returns `-1`) · filed 2026-11-15 against master `6015bf3ed`**

Repro:

    let c = false
    print((if c { 2147483647 } else { 0xFFFFFFFF }) as f64)
    // PRINTS -1

Want:

    4294967295

#### Mechanism

Ruling 4.1 makes `as f64` a float context, where a radix literal is the value its digits spell.
Ruling 4.3 has one join rule for every join form, so a join whose arms are all literals is a
literal join and takes its context. The float context of `as f64` therefore reaches the join's
literal arms, and `0xFFFFFFFF` there is 4294967295. The compiler types the join at `i32` first,
reads the radix arm as the pattern `-1`, and converts that. In the fuzz cell this turns
`… as f64 as! i32`, which must trap on 4294967295, into `-1`.
