#### Mechanism

`take3` has two instances, binding `a` to a list of `{inc0}` and a list of `{dbl0}`. The call
`f(3)` in its body is one node reached through both sets, from a lambda (or, in the index
spelling, from a holder read `a[0]`), so `elabMintFactAt` marks both sets partial. The late pass
then refuses the hand of `[inc0]` to `take3` (`ftHoldCtxOk`), `{inc0}` stays a closure, and the
one list `deliver0()` returns is read at `f64` and at `i32`: no one closure serves both, and the
`f64` arm instance does not exist.

The partial mark is load-bearing. The elaboration mints a key per set
(`?take3.0=((_) => _)[]#6` and `…#13`), but mono demands `take3` once, at `#6`, and serves
`take3([dbl0])` from that instance too: both lists are `i32[]` of ids, so with both sets tagged
id 0 of `{dbl0}` dispatches to `inc0`'s arm. A close must make mono's call keying take the
set-keyed instance for an argument that is a list literal of a tagged set, before the partial
rule is narrowed to holders and lambdas shared across instances.

**Control any fix must pass:** with the partial mark lifted alone (branch `lane/g2-lmap`, not
merged), the witness prints `2.25 4 4 4` — silently wrong, where it must print `2.25 4 4 6`.
