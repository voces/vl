### D17801 — the shared-leaf rule is off when a call of the function initialises an annotated binding, so one value keeps two layouts

**closed 2026-11-28 by lane START-2 — the witness prints `2` · the rung is deleted: the whole-list delivery is copied through `.map` (D17776), so the shared-leaf rule holds for every call · fixture `tests/cases/functions/list-of-records-set-field-through-map.vl` · was: runs today and must keep running · a rung, not a defect: `recRetSharedLeaf` refuses a function one of whose calls initialises an annotated binding · filed 2026-11-28 against master `77e1160ea` (lane START-2)**

Repro:

    function id(a) { return a }
    function deliver() { return [{ f: id }] }
    const v: { f: (a: f64) => f64 }[] = deliver()
    const u = deliver()
    print(u[0].f(2))
    // vl run: 2 (must keep running)

Want:

    2

#### Mechanism

[D17764](D17764.md)'s join rule makes the one literal a function returns from two or more call
sites hold its set's ids. A call delivered whole into a binding annotated at closures would then
need the list copy that converts each element, and the `.map` copy that converts a list of
records is not built yet ([D17775](D17775.md)), so the rule is off for such a function and its
list keeps the closures the annotation builds. Removed by the PR that lifts the `.map` holder
rule (`ftHoldCtxOk`), fixes the callback's element rep ([D17794](D17794.md)) and copies the list
through `.map`.
