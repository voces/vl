### D6742 — one hole parameter handed two generics by name and a second handed one, at calls inside another function's body, is refused at emit

**loud emit reject · `vl check` rc 0 · clause 2 · CAPABILITY: the same calls at module scope run · found closing [D6705](D6705.md) · filed 2026-10-18 against master `73713bacf`**

Repro:

    function id(a) { return a }
    function dbl(a) { return a + a }
    function app(g, h) { print(g(1) + 1); return h(2) }
    function use(n) { print(n); print(app(id, id)); return app(dbl, id) }
    print(use(1))
    // vl check: rc 0.  vl run: emitProgram: cannot take the generic function `id` as a value

Want:

    1
    2
    2
    3
    2

#### Mechanism

From the ablation only. The by-name plan gives `g`'s second name a copy of `app`, parsed from
the source without the renames the first plan made, so `h`, which a second parameter's plan
reads only in `app` itself, is left a hole in the copy; [D6705](D6705.md) declines the second
parameter of a copied function for that reason.

#### Ablation

| spelling | outcome | needed? |
| --- | --- | --- |
| the witness | loud emit reject | — |
| `app(g)` with no `h`, `app(id)` and `app(dbl)` in `use` | runs, `1 2 2 3 2` | **yes** |
| both calls at module scope, no `use` | runs, `2 2 3 2` | **yes** |
| `app(id, dbl)` for `app(dbl, id)`, the two names on `h` | loud emit reject, the same | no |
