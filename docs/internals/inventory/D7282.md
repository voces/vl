### D7282 — a `let` bound to one hole lambda and written with another inside a generic called at two types is refused, called directly or through a record field

**closed 2026-10-19 by lane L1 · runs, prints `S 3 S s` · was loud emit reject · `vl check` rc 0 · clause 2 · CAPABILITY: the same body in a non-generic function runs · the lambdas' hole parameters are pinned per instance by the call type each instance's value reaches, the close of [D7281](D7281.md) · pin: `tests/cases/closures/two-lambda-written-let-in-two-instances.vl` · found closing [D7201](D7201.md) · present on master `966471462` · filed 2026-10-19 against master `966471462`**

Repro:

    function g<T>(x: T) {
      let k = (n) => { print("R"); print(n) }
      k = (n) => { print("S"); print(n) }
      k(x)
    }
    g(3)
    g("s")
    // vl check: rc 0.  vl run: emitProgram: the reassigned function binding `k` is called at more than one argument type — one binding holds one closure signature, and the values written to it want two

Want:

    S
    3
    S
    s

#### Mechanism

The same as [D7281](D7281.md). With both lifts left at the hole's default, the binding's one
signature met two argument types, one per instance, and `monoBindingSigConflict`'s floor
refused. Each instance now lifts its own copy at its own type, so each binding holds one
signature. The record-field spelling refused with `no interned signature` on master and runs
for the same reason.
