### D2888 — a record list literal returned into `R[] | Q[]` is tagged as the wider record's list, dropping the narrower one's field

**closed 2026-10-26 — the repro RUNS and prints `8` · was check-clean silently wrong, clause 1, the literal now typed as the arm it matches exactly rather than the first that accepts it**

Repro:

    type Circle = { r: i32 }
    type Square = { r: i32, s: i32 }
    function mc(b: boolean): Circle[] | Square[] {
      if b { return [{ r: 1 }] }
      return [{ r: 7, s: 8 }]
    }
    const c = mc(false)
    if c is Square[] { print(c[0].s) } else { print(c[0].r) }
    // PRINTS 7

Want:

    8

#### Mechanism

Not localised past the ablation. `[{ r: 7, s: 8 }]` is assignable to both members, since a
`Square` width-subtypes into `Circle`, and the return boxes it under the first member that accepts
it, `Circle[]`, rather than the member it matches exactly. The `is Square[]` test then answers
false and the literal's `s` is gone.

#### Ablation

| ingredient removed | outcome | needed? |
| --- | --- | --- |
| the literal (`const s: Square[] = [{ r: 7, s: 8 }]`, return `s`) | runs, prints `8` | **yes** |

#### Grading list

The members in the other order (`Square[] | Circle[]`), and the literal as an argument to a
`Circle[] | Square[]` parameter.
