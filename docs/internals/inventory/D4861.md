### D4861 — a spread of an `i32[][]` into an `f64[][]` literal emits a nested list at the wrong row

**check-clean invalid wasm · clause 1 · found beside D4858, whose `+` spelling of the same pair stays a loud emit reject · filed 2026-10-15 against master `0e1ea34b1`**

Repro:

    const a = [[1, 2]]
    const b = [[1.5]]
    const xs = [...b, ...a]
    print(xs[1][1] / 4.0)
    // vl check: rc 0.  vl run: invalid module, expected (ref null $7), found (ref $5); $7 is `f64[][]`, $5 is `i32[][]`

Want:

    0.5

#### Mechanism

The checker types the literal `f64[][]`, joining an `i32[][]` source by element-wise numeric
widening, but the spread copies the `i32[][]` source's backing as it is, with no per-element
converting copy for an inner list. `b + a` reaches the same pair and is refused loudly by the
concat's own floor, since D4858 widens only one level.

#### Ablation

| ingredient removed | outcome | needed? |
| --- | --- | --- |
| the nesting (`[...[1.5], ...[2]]`) | runs | **yes** |
| the spread (`b + a`) | loud emit reject | no |
| a delivery instead (`const ys: f64[][] = a`) | check reject, a container never widens | no |
