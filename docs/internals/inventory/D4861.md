### D4861 — a spread of an `i32[][]` into an `f64[][]` literal emits a nested list at the wrong row

**closed 2026-10-15 — now a loud check reject at the copied source (`i32[] is not f64[]: this join would hold both, and a container never widens implicitly`) · was check-clean invalid wasm, clause 1 · the list literal is a join, and an existing inner list into a wider element is the container widening the design refuses (DECISIONS.md §"No implicit container widening"), so the refusal is the one the `if` join already owed · found beside D4858, whose `+` spelling of the same pair was a loud emit reject and is now the same check reject · filed 2026-10-15 against master `0e1ea34b1` · pins: `tests/cases/arrays/error-list-literal-join-widening.vl`, `list-literal-join-widening-runs.vl`, `scripts/capability-probes/matrix/nested-list-widen-runtime.matrix.vl` and `nested-list-widen-fresh.matrix.vl`**

Repro:

    const a = [[1, 2]]
    const b = [[1.5]]
    const xs = [...b, ...a]
    print(xs[1][1] / 4.0)
    // vl check: rc 1 at `a`, i32[] is not f64[]: this join would hold both. Was: rc 0, then invalid module

Want:

    a check reject naming the copy

#### Mechanism

The checker typed the literal `f64[][]`, joining an `i32[][]` source by element-wise numeric
widening, but the spread copied the `i32[][]` source's backing as it was, with no per-element
converting copy for an inner list. `b + a` reached the same pair and was refused loudly by the
concat's own floor, since D4858 widens only one level.

Building that copy is not the fix: it would make `xs[1]` a new list where the program reads
`a[0]`, so a write through either would not reach the other, which is the aliasing change
the container rule (and the record covariance ruling's rejection of copy-on-delivery) refuses.
The `if` join of the same two lists was already refused by `listJoinWidenCheck`; a list
literal's element joins now go through it too, and a spread or `+` operand, whose own level
the copy converts (D965, D4858), is checked one level down by `ljwCopiedLevelCheck`.

#### Ablation

| ingredient removed | outcome | needed? |
| --- | --- | --- |

| the spread (`b + a`) | loud emit reject | no |
| a delivery instead (`const ys: f64[][] = a`) | check reject, a container never widens | no |
