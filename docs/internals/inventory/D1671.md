### D1671 — a `?.` whose leaf field is a nullable STRUCT evaluates its receiver twice, so a side-effecting receiver runs twice

**check-clean silently wrong · filed 2026-09-05 against master `dcea29414` · found while
closing D1667 · clause 1: `vl check` returns 0, the module validates, and the program's
observable behaviour is wrong**

Repro:

    type I = { z: i32 }
    type B = { y: I | null }
    let n = 0
    function mk(): B | null {
      n = n + 1
      { y: { z: 3 } }
    }
    function once(): i32 {
      if mk()?.y == null { return 0 }
      n
    }
    print(once())
    // PRINTS 2
    // vl check: rc 0.  vl run: prints 2; `mk` is called once in the source and twice in the module.

#### Mechanism

`emitOptChainIsNull` emits the receiver for the `ref.is_null` test, and its `else` arm asks
`emitOptChainValue`, which emits the receiver AGAIN to read the field off it. For a scalar
leaf the else arm is the constant `0`, so the second emission never happens and the defect
is invisible; a code-15 leaf (the field is itself a nullable struct) is the arm that reads
the receiver a second time. Neither function stages the receiver, and neither asks whether
re-emitting it is safe — `optRecvReReadable` guards only `emitOptMemberValue`, the
standalone-value path (D1670).

#### Ablation

| ingredient removed | outcome | needed? |
| --- | --- | --- |
| the nullable-struct leaf (`type B = { y: i32 }`) | prints `1` | **yes** |
| the side effect in `mk` | runs, indistinguishable | **yes** |
| the call receiver (`const t = mk()` then `t?.y == null`) | prints `1` | **yes** |
| the call through a VALUE (`const g = mk`) | prints `2` either way | no |

#### Grading list

D1670 is the loud half of the same re-read and a staging local closes both, so grade
`print(mk()?.y ?? 0)` with any fix here. A fix must also keep the scalar-leaf spelling
(`type B = { y: i32 }`) emitting its receiver ONCE, which it already does.
