### D3492 — `vl fmt` moves a comment that sits between an object key and its value out of the literal

**closed 2026-10-03 — `vl fmt` keeps the comment after `seq:` and the program prints `5` · was a comment RELOCATION by `vl fmt` on a `vl check`-clean program · the same on master `937445a42` · found by lane FR5 · filed 2026-10-03 against master `937445a42`, closed by lane OQ against master `878f6ebe8` · fixture `tests/cases/objects/comment-between-key-and-value.vl`**

Repro (runs, prints `5`; `vl fmt` must print it with the comment kept in place):

    const seq = 5
    const o = { seq: // c
      seq }
    print(o.seq)
    // vl check: rc 0.  vl run: 5.  vl fmt: `const o = { seq: seq }`, then `// c` and a blank line after the statement.

Want:

    5

#### Mechanism

`objectLiteral` in `compiler/format.vl` reprinted every field as `key: value` from the nodes, and
the only comment anchor it had was D1777's, for a comment in the GAPS between fields
(`commentInListGaps`). A comment between a key and its own value is in no gap and inside no
value, so no printer took it, and the statement printer flushed it after the declaration. Fixed
by `commentInFieldKeyGaps`: a pending comment between a field's key and its value takes the same
verbatim anchor (`sliceFallback`) D1777 uses, so the literal keeps its source text. The same
relocation after a binary operator and inside a parenthesis is [D3514](D3514.md).
