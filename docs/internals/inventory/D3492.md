### D3492 — `vl fmt` moves a comment that sits between an object key and its value out of the literal

**runs today and must keep running · open · the program runs and prints `5`; `vl fmt` is the defect (a comment RELOCATION on a `vl check`-clean program) · the same on master `937445a42` · found by lane FR5 · filed 2026-10-03 against master `937445a42`**

Repro (runs, prints `5`; `vl fmt` must print it with the comment kept in place):

    const seq = 5
    const o = { seq: // c
      seq }
    print(o.seq)
    // vl check: rc 0.  vl run: 5.  vl fmt: `const o = { seq: seq }`, then `// c` and a blank line after the statement.

Want:

    5

#### Mechanism

Unconfirmed in `compiler/format.vl`. D3274 made a value starting on the line after its `:` legal,
and D1777 anchored an interior comment between the ELEMENTS of an object literal, but nothing
anchors one between a key and its own value, so the comment falls out of the literal and is
emitted after the enclosing statement. The formatter's standing rule is never to relocate a comment.

idempotent (formatting the output changes nothing); D1777's and D3274's own witnesses must keep
