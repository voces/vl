### D15459 — a named function handed to a hole parameter and called there with a hole function passes `vl check` with an error in its body, and dies at emit

**loud emit reject · `vl check` rc 0 on an ill-typed program, with the split plan on and off; `vl run`: `emitProgram: callee is not a function name` · the checker owes the diagnosis (`'toString' is not imported`), which the direct call `lap(id)` gets · the named-function spelling of D14943 · found grading D14943 · filed 2026-11-05 against master `37b562fe`**

Repro:

    function id(a) { return a }
    function lap(g) { const x = g(1); return x.toString() }
    function use(k) { return k(id) }
    print(use(lap))
    // vl check: rc 0.  vl run: emitProgram: callee is not a function name

#### Mechanism

Not yet probed. `lap`'s body is checked for `use`'s call `k(id)` with `g` holding `id`, a hole
function. Where `id` is closed (`id(a: i32)`) or `lap` is called directly, `x` types `i32` and the
UFCS `toString` is refused. Through the hole parameter and with a hole `id`, `g(1)`'s result
apparently stays open in that instance, so nothing refuses the call, and the emitter meets it.
