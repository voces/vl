#### Mechanism

`lap`'s check-time instance is demanded from `use`'s call `k(id)` at `id`'s set, where `g(1)`'s
result stays open and nothing refuses `x.toString()`. Mono demands `lap` at `(i32) => i32` later,
and that instance's re-check does raise the error (`elabErrorNote`). `checkSrc` (driver.vl) then
compiled the program and muted instance diagnostics whenever the first pass asked a split and no
split-applied pass ran (`fsFirstAsked`), which is the split plan's kept-program filter. Without it
the diagnostic stands, with the plan on and off.
