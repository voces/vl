### D1978 — one emitter buffer is still one packed array, so a single function body past 2^25 bytes (32 MiB) traps the compiler

**compiler trap (`allocation size too large`, exit 70) · residue of D1976 · filed 2026-09-22 against master `48a295c72` plus D1976's fix · a body this size is past wasmtime's own per-body limit four times over, so what is wrong is WHO refuses it**

Repro (three 4M-character literals concatenated in one function, a ~36 MB body, in an imported
module so the entry stays small and the compile keeps the null collector):

    // file: m.vl
    export function s(): string { "@@repeat(4000000, "a")@@" + "@@repeat(4000000, "b")@@" + "@@repeat(4000000, "c")@@" }
    // file: main.vl
    import { s } from "./m"
    print(s().length)
    // vl check: rc 0.  vl build / vl run: the compiler traps, exit 70

#### Mechanism

D1976 made every emitter buffer a packed `u8[]` and the MODULE a rope of chunks, so the module
has no single-object ceiling. Each chunk is still one buffer, though — a section payload, or one
code entry, rendered by the streaming writer into one `u8[]` — and under the null collector one
object is at most 64 MiB, so `.push`'s growth to 2^26 bytes traps once a single buffer passes
2^25. Named backtrace: `wU8@emit_bytes.vl` ← `fbI32Const` ← `emitStr` ← `emitStrValue` ←
`emitStrCatN`. The engine would refuse this body anyway (wasmtime's limit is 7,654,321 bytes,
[D2092](D2092.md)); the defect is that the compiler traps instead of emitting the module the engine
refuses. A non-code section past 32 MiB (about 340 exports of 100,000-character names) reaches
the same cap.

#### Ablation

| ingredient removed | outcome | needed? |
| --- | --- | --- |
| the third literal (an ~24 MB body) | builds; wasmtime refuses it at its body limit | **yes** |
| the import (one file, the function inline) | same trap | no |
