### D1978 — one emitter buffer is still one packed array, so a single function body past 2^25 bytes (32 MiB) traps the compiler

**closed 2026-09-30 — a literal no longer costs its function body a byte per character, so the witness's body is a few hundred bytes and it prints `12000000` (lane CT) · was compiler trap (`allocation size too large`, exit 70) · residue of D1976 · filed 2026-09-22 against master `48a295c72` plus D1976's fix**

Repro (three 4M-character literals concatenated in one function, a ~36 MB body, in an imported
module so the entry stays small and the compile keeps the null collector):

    // file: m.vl
    export function s(): string { "@@repeat(4000000, "a")@@" + "@@repeat(4000000, "b")@@" + "@@repeat(4000000, "c")@@" }
    // file: main.vl
    import { s } from "./m"
    print(s().length)
    // vl check: rc 0.  vl build / vl run: the compiler traps, exit 70

Want:

    12000000

#### Mechanism

D1976 made every emitter buffer a packed `u8[]` and the MODULE a rope of chunks. Each chunk is
still one buffer, and under the null collector one object is at most 64 MiB, so a single buffer
past 2^25 bytes traps. The witness reached it through its literals: `emitStr` built a literal
past the pool's cap with one `i32.const` per byte (`wU8` ← `fbI32Const` ← `emitStr` ←
`emitStrValue` ← `emitStrCatN`), so three 4M-character literals made a ~36 MB body.

A string literal past the pool's `array.new_fixed` cap (10,000 UTF-8 bytes) is now stored once
as a passive DATA SEGMENT and built at each evaluation by `array.new_data` (`emitStr`,
`wasmEmit.vl`; `strLitCollect`, `emitDataCountSection` and `emitDataSection`,
`emit_sections.vl`): the function body carries five instructions whatever the literal's length,
where it carried one `i32.const` per byte. The lexeme is decoded by `litUtf8` (`emit_base.vl`),
which is `cpsToUtf8(decodeStr(strToCps(lex)))` run over pieces of about 2^20 code points, cut
only where no escape can be open, into a packed `u8[]`, so no `i32[]` holds the whole literal.
A module with no such literal emits neither section and is byte-identical to before.

| ---: | ---: | ---: | ---: |
| 20,000 | 78,711,215 | 54,375,185 | 52 MB |
| 1,000,000 | invalid module (the body is past 7,654,321 bytes) | 2,490,499,078 | 231 MB |
| 4,000,000 | trap | 7,652,862,014 | 588 MB |
| 10,000,000 | trap | 19,320,496,574 | 1,510 MB |

#### Grading list

- The buffer cap itself stands, and no program reached it here without a literal. Ordinary code
  makes less body than source (`acc = acc + 1` is 13 source bytes and about 7 body bytes), so a
  body past 32 MiB needs more than 32 MB of source in one function: past the null collector's own source ceiling in an imported module (about
  15.6 MB, DECISIONS.md), and in an entry file that large the copying collector compiles it,
  which built a 34 MB export section (340 exports of 100,000-character names) without a trap;
  the engine then refuses a name that long. Such a body is past every engine's 7,654,321-byte
  limit in any case.
