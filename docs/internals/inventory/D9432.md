#### Mechanism

The call `v((n) => n * 2, 21)` goes through a slot the checker left untyped. Its lambda's type
is `(_) => _`, so the flow pin it records is open, and `monoDeclPathPins` reports no closed
pin. `monoCoerceRetAtPin`, which instances a generic past an un-annotated function's return,
read only closed pins: with none it took the floor. A generic handed over directly
(`take(app)`) already reached `monoHoleGenFnFlowTy`. That function binds the generic's type
parameters from the one call's closed arguments (`21` gives `T = i32`), then binds the
un-annotated lambda at what the rest bind.

The fix: when the returned generic's slot has no closed pin and at most one return,
`monoCoerceRetAtPin` asks `monoHoleGenFnFlowTy` for the instance type. `monoFnPinAt` then
delivers the generic at that type, gives the lambda the parameter type, and retypes the
pinning call.
