### D9432 — a returned generic over a function-typed parameter, handed to an un-annotated parameter and called with an un-annotated lambda, refuses

**loud emit reject · clause 2 · `vl check` rc 0 · CAPABILITY: the generic handed over directly runs · found closing [D9381](D9381.md) · present on master `3a918d6cc` · filed 2026-10-21 against master `3a918d6cc`**

Repro:

    function app<T>(f: (x: T) => T, x: T): T { f(x) }
    function deliver() { return app }
    function take(a) {
      const v = a
      print(v((n) => n * 2, 21))
    }
    take(deliver())
    // vl run: emitProgram: a generic function taken as a value reaches no call that fixes its type — annotate the destination's function type

Want:

    42

#### Mechanism

Not traced. The call in `take` pins `app` with the lambda's parameter still open, so the flow
pin past `deliver`'s return has no closed type for the function-typed parameter, and the
instance declines to the value floor. The lambda annotated as `(n: i32) => n * 2` runs, and so
does `take(app)`.
