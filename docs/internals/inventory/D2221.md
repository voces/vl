### D2221 — an `is` test set containing a float literal answers false for every value

**closed — by owner ruling (2026-09-23), as DESIGN: a float literal is not a type, so the witness is now a loud check reject naming `f64`/`f32` or the integer meant; integer literal types stay distinct from floats · was check-clean silently wrong, `1 | 2.0 | 3` tested with `is 2.0 | 3` printed `false` for `3` and `2.0` · found reviewing D2205's close · filed 2026-09-23 against master `0d5421468` · closed 2026-09-23 · `tests/cases/literal-unions/float-literal-type-refused.vl`, `float-literal-type-suggested-fix-runs.vl`, `is-int-literal-set-dispatch.vl`**

Repro (refused at the annotation and at the `is` test; before the ruling it printed `false false false`):

    function f(n: 1 | 2.0 | 3) { n is 2.0 | 3 }
    print("\{f(3)} \{f(2.0)} \{f(1)}")
    // error: a float literal cannot be a type: … in place of the float literal `2.0`

#### Mechanism

The same union tested with `is 3` alone answers `true` for `3`, so the failure is the float
literal in the TEST set: its membership compare does not match either member, including the
integer one beside it. D2205's disjoint-set refusal reaches it from the other side: over
`n: 1 | 2`, `n is 2.0 | 3` is refused with the suggestion `declare them in its type: 1 | 2 |
2.0 | 3`, and following it gives this program. Whether `2` and `2.0` should be one literal (and
the suggestion normalise them) is part of the fix.

#### Ablation

| ingredient removed | outcome | needed? |
| --- | --- | --- |
| the float literal in the test set (`n is 3`) | runs, `true` for `3` | **yes** |
| the float literal in the operand (`n: 1 \| 2 \| 3`, `is 2.0 \| 3`) | runs after D2205 (tests the overlap `3`); refused before | **yes** |
| an integer member beside it in the operand (`n: 1 \| 2 \| 2.0 \| 3`) | wrong value | no |

#### Grading list

- D2205's refusal suggestion for `n: 1 | 2; n is 2.0 | 3`.

#### Close

Owner ruling (DECISIONS.md, "A float literal is not a type"): float literal types are removed,
following PEP 586 — float equality is not set membership. Both annotation routes refuse a float
lexeme with one sentence, and the grading-list question (whether `2` and `2.0` are one literal)
is answered by the rule: `2.0` names no type, and the refusal suggests `2`. The integer side
needed no change: over `1 | 2 | 3`, `is 2 | 3` answers `true true false`, and over `1 | 2 | f64`,
`is 2` holds for `2` and not for `2.0`.
