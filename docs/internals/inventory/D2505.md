#### Mechanism

`typecheck.mapKeyRepTy` is the one home of which hash a key takes, and it had two answers,
`string` and `i32`. The i64 key is now a third, `MAP_KEY_I64`, threaded as a key KIND where the
emitter used to thread an `i32`-keyed boolean: the mono sentinels gain `-6` (map) and `-7` (Set)
beside `-4`/`-5`, an mv slot's key column holds the kind, and the struct's `keys` field is the i64
list. The index is the i32-keyed pair layout with a tag in place of the key: the tag is the top 32
bits of `key * 2^64/phi` (`fbMapTagOfI64`), placed by the same Fibonacci step as an i32 key, so
the pair resize and the compaction are shared; `__map_probe_i64__` confirms a tag match against
the keys backing. Two keys that differ only in their high 32 bits always get different tags. No
new `VKind`; a program with no i64-keyed map builds byte-identically (all 3,674 pre-existing
fixtures). A literal union over `i64` now hashes as an i64 key, so the fixture that pinned its
refusal is retired.
