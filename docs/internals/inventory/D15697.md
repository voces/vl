### D15697 — a `.map` over a list built at a kept maker's record types its callback's parameter at the list's checked element

**closed 2026-11-11, runs and prints `1` then `1` · was a loud check reject (made loud 2026-11-11 by `recBuiltCallbackRefuse`), before that a loud emit reject, `emitProgram: ref valtype with no interned shape`; the field-read leg `r.ys.map(…)` also runs · closed by the fresh-call copy (`recFreshCallCopy`, `recHeldFreshCopy`, check_fit_rules.vl): a maker called more than once keeps its own record, and a delivery whose destination stores a field differently copies the call there, so no other delivery reads it at another row · graded by `scripts/capability-probes/matrix/kept-maker-delivery.matrix.vl` · found closing D15694 · filed 2026-11-11 against master `e0d19181`**

Repro:

    type J = { f: i32 | null }
    function mk2() { { f: 1 } }
    const dA: J = mk2()
    print(dA.f ?? 0)
    const xs = [mk2()]
    const ns = xs.map((y) => y.f ?? 0)
    print(ns[0])

Want:

    1
    1

#### Mechanism

Not ablated. `xs` is built at `J[]`, and the lambda's parameter `y` is typed at the list's checked
element `{f: i32}`. No instance of a lambda is taken at a build, so before the refusal the
callback's signature named a record with no row. `recBuiltCallbackRefuse` now refuses the receiver
the way `recBuiltReadRefuse` refuses the list handed to a generic.
