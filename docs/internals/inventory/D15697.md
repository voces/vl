**now a loud check reject · clause 2 · `this container's {f: i32} elements are stored at J, the row its stores build; handing it on as {f: i32}[] is type-valid but not supported yet` · was loud emit reject, check-clean, an internal message, clause 1, `emitProgram: ref valtype with no interned shape` · found closing D15694 · filed 2026-11-11 against master `ada32709` · made loud 2026-11-11 against master `8c3feff9`: a `map` or `filter` whose receiver reads a list binding built at another record is refused at check (`recBuiltCallbackRefuse`, check_fit_rules.vl), as a generic handed that list already was · still open: the callback is not instanced at the build; through a record field (`r.ys.map(…)`) it is still the emit error**

    type J = { f: i32 | null }

#### Mechanism

Not ablated. `xs` is built at `J[]`, and the lambda's parameter `y` is typed at the list's checked
element `{f: i32}`. No instance of a lambda is taken at a build, so before the refusal the
callback's signature named a record with no row. `recBuiltCallbackRefuse` now refuses the receiver
the way `recBuiltReadRefuse` refuses the list handed to a generic.
