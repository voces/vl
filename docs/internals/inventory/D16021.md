### D16021 — an `#anonN` pin forwarded from another instance's parameter holds only the placeholder type, so its row is read off the label

**closed 2026-11-13 — no `#anonN` pin is read by its label; the forwarded pin is typed at its literal and the typed ladder finds its row · was runs today and must keep running, 1 program of the sweep population · filed 2026-11-13 against master `537a04cc`**

Repro:

    type G = { g: i32 }
    function k<T>(x: T): T { return x }
    function show(o: G) { print(o.g) }
    function fwd(o: G) { show(o) }
    const r = { f: k, g: 7 }
    print(r.f(1))
    fwd(r)
    // vl run: 1 7, armed and unarmed.

Want:

    1
    7

#### Mechanism

`fwd`'s instance pins `o` at the literal's handle `#anonN` through `synthTypeRefFb`, which keeps
the literal's type, so `retStructRowIndex` finds the anonymous row by type identity (D16020).
`show(o)` inside that instance pins at `o`'s recorded type, which is the `{}` placeholder a
handle pin records, through `synthTypeRefTy`. That pin holds no literal type, and the typed
ladder answers the empty record's row. Only `structIndexByName` on the label finds the literal's
row. The close carries the literal type through the forwarded pin, so the label read can go.

- `recordClonedNodeTyFb` types an `#anonN` pin at its literal's record unless a hole in that
  type's rep would read as an unbound parameter. The forwarded pin therefore inherits the
  literal's type, not `{}`.
- `anonPinLitCarry` keeps the literal type on a pin that `monoInstantiate` re-synthesizes at
  the instance's substituted type.

`retStructRowIndex` reads the anonymous row at the literal type, then the typed ladder. Over
the population that chain agrees with the deleted label read in all 245 programs that reached
it (2,177 decisions), plus this witness. 10 builds change bytes only, all in the
generic-function-field family: the placeholder `(struct)` type is no longer emitted. Their
output is unchanged, armed and unarmed.
