### D15149 — a second list holding the same returned record of members has no slot fact, so it refuses at emit

**open · loud emit reject · clause 2 (`emitProgram: a function returning a parameter called at two signatures is called where its result is not used at one of them`) · owned by lane bundle · residue of B2b · filed 2026-11-04 against master `19b36c636`**

Repro:

    function lap(f) {
      const _a = f(2.5)
      const _b = f(3)
      return f
    }
    const xs = [lap((a) => a + 1)]
    print("\{xs[0](4)} \{xs[0](1.5)}")
    const zs = [lap((a) => a + 1)]
    print("\{zs[0](4)} \{zs[0](1.5)}")

Want:

    5 2.5
    5 2.5

#### Mechanism

B2b's slot fact (`elabSlotRecordNote`, `elabSlotListOfRec`) holds a returned record whole in the
elements of one list per record. Served for a second list of the same record, the second list's
literal and binding were built at the closure list rather than at the record list mono typed
them at: the walk rebuilds that binding's initialiser, and its cell keeps the checker's list type.
The module then failed to validate, so the fact declines a second list and its call keeps the
refusal it had before B2b.

#### Ablation

| spelling | outcome |
| --- | --- |
| `zs` removed | runs, prints `5 2.5` |
| `zs` holding a record of other signatures (`f(true)`, `f(3)`) | refuses at emit, `a call through a held record matches none of its signatures` |
| `xs` a record field (`{ f: lap(...) }`) and `zs` the list | runs |
| `xs` and `zs` in two functions | the same refusal |
