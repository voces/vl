**closed 2026-11-04 by this PR (lane bundle) — the repro now RUNS and prints the Want below: a list binding's ref-list row is read from its slot fact (`letRefListSlot`), and the decline of a second list per record is deleted. Repro:

#### Mechanism

Measured while building B2c, by decoding the invalid module. The second list's literal was built
at the record list, but its module global was declared at the closure list, and the store into it
was the failing instruction. That declaration is the binding's ref-list row (`letRefListSlot`),
read off its synthesized annotation, and for the second binding of a record it did not name the
record's row. Reading the row from the slot fact instead fixes every spelling below. A map value
slot has no ref-list row, which is why two maps never failed while a list after a map did.
