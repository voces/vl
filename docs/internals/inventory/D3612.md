### D3612 — a list literal over a generic helper's nullable join of two type parameters, in a generic caller, drops the second arm

**closed · runs, prints `u` · was check-clean silently wrong, clause 1 · closed by keeping a call's deferred join of the caller's own type parameters beside a null as a union each pin re-joins (`joinOverOwnParams`, `keptParamUnion`), rather than collapsing it onto one arm · fixture `generics/list-of-a-call-join-of-own-params-beside-null.vl` · found by lane HL's grid (its `list` reader, 6 wrong cells) · filed 2026-10-04 against master `c473889d1`**

Repro:

    function G<A, B>(k: i32, a: A, b: B) {
      if k == 0 { a } else if k == 1 { b } else { null }
    }
    function F<A, B>(k: i32, a: A, b: B) {
      const v = G(k, a, b)
      const ys = [v]
      print(ys[0])
    }
    F(1, 3, "u")
    // PRINTS null

Want:

    u

#### Mechanism

The call's return in `F`'s template is `G`'s deferred join `A | B | null` at the caller's own
parameters. `collapseDeferredJoin` re-joined it through `joinTys`, where two holes are assignable
both ways, so it typed `A | null`. `print(v)` reads the call again at the pin and prints `u`, but
the list literal took its element type from the template, so `[v]` was `(i32 | null)[]` at the
pin and the string arm read as a miss. `keptParamUnion` already kept such a join apart when the
callee declared its return; it now also does when the join holds a null, which the callee boxes
at every pin. Without the null a pin may join two numbers as one (`f64` for `f64 | i32`), and
only the collapse reads that, so that shape still collapses.

#### Ablation

| ingredient changed | outcome | needed? |
| --- | --- | --- |
| `F` concrete (`a: i32, b: string`) | prints `u` | **yes**: a generic caller |
| no `null` arm | prints `u` | **yes** |
| `G` annotated `: A \| B \| null` | prints `u` | **yes**: the inferred return |
| `print(v)` instead of the list | prints `u` | **yes**: the list literal |
