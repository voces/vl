#### Mechanism

Not traced. `?.f(2)` is rewritten to a guarded `m["k"].f(2)` whose receiver keeps the
nullable type, and the flow table pins no method call on a nullable receiver (`ffCall`,
fn_flow_shadow.vl). The D4579 close types the map's value from those pins, so it declines
whenever such a call exists (`monoMapValueUnpinnedCall`, emit_mono.vl): a pin taken from
the other calls alone would give the field one instance while this call wants another,
which built invalid wasm before the decline was added.
