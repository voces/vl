### D1647 — an EMPTY `match` arm body is printed by `vl fmt` as three lines with a blank inside, where every other empty block in the language stays on one

**closed 2026-09-05 — the witness runs and each empty arm prints on one line · was a `vl fmt` expansion on a `vl check`-clean program · fixed by giving `blockExpr` the `{}` spelling every other empty block in the language keeps**

Repro (runs, prints `1`):

    type A = { a: i32 }
    type B = { b: i32 }
    type C = { c: i32 }
    type N = A | B | C

    function pick(n: N, cond: boolean): i32 {
      if cond {}
      while cond {}
      match n {
        A => { return n.a }
        B => {}
        C => {}
      }
      0
    }
    print(pick({ a: 1 }, false))
    // vl check: rc 0.  vl run: 1.
    // vl fmt -w: `if cond {}` and `while cond {}` keep their line; each empty ARM becomes
    //            `B => {`, a BLANK line, `}`.

#### Mechanism

The witness RUNS, and the status line says so, for [D1646](D1646.md)'s reason: the defect is
in a tool the witness grader does not drive.

`compiler/format.vl` prints an empty block on one line everywhere it can decide the block is
empty — a function body, an `if`, an `else`, a `while`, a `for` — and a `match` arm's body
does not reach that decision, so it takes the general block path: open brace, the (empty) body
on its own line, close brace. The blank line inside is what a zero-statement body prints as.

The cost is three lines where one would do, and it lands on exactly the arm a reader most wants
compact: an empty arm is the house spelling for "this kind is a deliberate leaf"
(`emit_rep.vl`'s `repElemKeyGo` carries three), and it is what a `_` arm becomes. The pilot
recorded in `docs/internals/kind-ladder-lint.md` paid it 31 times over one file, ~93 of the
+247 lines it added.

#### Ablation

Every row is `vl check` rc 0, and `vl fmt -w` is idempotent on its own output in all of them.

| empty block | before | after |
| --- | --- | --- |
| `match n { A => {} … }` | **three lines, with a blank inside** | one line |
| `match n { _ => {} }` (the wildcard arm) | **three lines** | one line |
| `function emptyFn() {}` (control) | one line | one line |
| `if cond {}` (control) | one line | one line |
| `if cond {} else {}` (control) | one line | one line |
| `while cond {}` (control) | one line | one line |
| `for v in xs {}` (control) | one line | one line |
| `A => { return n.a }` — a one-line NON-empty arm body | three lines | **three lines**, deliberately |

Needed: the empty block being a `match` ARM body. Not needed: the pattern kind, the arm's
position, or whether the arm is the `_` wildcard.

#### Grading list

* The five one-line rows above, which must stay one line.
* [D1646](D1646.md) — the other `match`-printer defect; a rewrite of the arm printer should
  re-grade both.
* An arm whose body is a one-line NON-empty block (`A => { return n.a }`) expands to three
  lines too; that is the same printer's ordinary block rule and is deliberately NOT part of
  this row, so a fix must not quietly collapse it.
