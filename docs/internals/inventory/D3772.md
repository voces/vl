### D3772 — a `match` whose scrutinee has the error type is refused again as "must be a union or an integer, got <error>"

**closed, now a loud check reject with the root cause alone (lane DX) · filed 2026-10-06 against master `e2443d6b2`**

Repro:

    function side(x: f64) {
      const s = nope(x)
      return match s { "a" => 1, "b" => 2 }
    }
    print(side(1.0))
    // master: undeclared identifier 'nope', then match scrutinee must be a union or an
    // integer, got <error>

#### Mechanism

`checkMatch` reaches `matchScrutRejectMsg` for any scrutinee that is not an integer, a literal
union or a union with two or more members, and the error type is none of those. Its diagnostic
is already raised where the error type was made, so the refusal now skips a `TyErr` scrutinee.
The arms were never checked on the refusal path, so nothing else changes.

| --- | --- | --- |

| `x * 1.5` (an `f64`, a real misuse) | refused | refused |
