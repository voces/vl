### D2217 — an un-annotated generic `if` returning a scalar list builds its blocktype as `i32` at a scalar pin

**closed 2026-09-27 — the repro RUNS and prints `2` · was check-clean invalid wasm inside `pick`, `expected i32, found (ref $type)`, the same on master `f6db92e0d` · found by the review of #3069 · filed 2026-09-23 against master `327b15510`**

Repro:

    function pick<T>(c: boolean, x: T) { if c { [x, x] } else { [x] } }
    print(pick(true, 3).length)

#### Mechanism

`monoInstantiate` pins an un-annotated instance's return through a ladder of shape rungs (a
closure call, `.map`/`.filter`, an index, a hole-built local, `monoInferRetExprTy`) and falls to
the `i32` result seed when no rung names the return. A tail `if` or `match` joining list
literals is named by none of them at a scalar pin, and at `T = string` only when the arms are
the literals themselves: the #3181 review's `w1` (`const x = [a]; const y = [b]; if k { x }
else { y }`) failed at `T = string` too. The last rung already read the template's checked
signature at the pin, for a nullable result only. Closed by taking that checked result when it
is a list, or a union of lists, and no rung above named one.

#### Ablation

| ingredient removed | outcome | needed? |
| --- | --- | --- |
| the join (`[x]` as the only tail) | runs | **yes** |
| the return annotation `: T[]` | the annotated spelling runs | **yes** |
| the scalar pin (`T = string`) | runs, when the arms are the literals | no — through locals it failed too |
| the generic (`c: boolean, x: i32`) | runs | **yes** |
| two `return`s instead of a tail `if` | runs | **yes** |
