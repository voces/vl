**closed 2026-11-01 — the witness prints `false` · was loud emit reject · clause 2 · `vl check` rc 0 · fixture `tests/cases/generics/nullable-fold-twin-lists-at-every-delivery.vl` · filed 2026-11-01 against master `d75b1a99c`, found while lifting a nullable annotation member (column-G1 lane)**

Repro:

    type Rec = { x: i32 }

    const r2: Rec2[] | null = [{ x: 8 }]

#### Mechanism

The substitution's null fold kept two lists of same-shape records apart (`substListTwinNominal`),
so at `A = Rec2[] | null`, `B = Rec[] | null` the instance's `A | B | null` folded to the
nullable union `Rec2[] | Rec[] | null`, which no reader builds. The annotation route spells the
same set `Rec2[] | null`, since `Rec2[]` and `Rec[]` are one type. Confirmed and closed: the fold
now merges two lists by `tyEq`, as the union arm's own dedupe (`substListTwin`) already did, so
the instance and the annotation agree on `Rec2[] | null`. The `(A | null) | B` spelling, which
kept the nesting and boxed, folds the same way.
