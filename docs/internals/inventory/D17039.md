### D17039 — `.map` over a `null[]` list passes its i32-stored element to a callback whose parameter is `nullref`

**check-clean invalid wasm · `vl check` rc 0, the module fails to validate (`expected nullref, found i32`) · found by lane IR-N1 writing a shadow row for the `map-declared-callback` claim fallback · filed 2026-11-21 against master `f63eb9975`**

Repro:

    const xs: null[] = [null]
    print(xs.map((e): i32 => 1)[0])
    // vl check: rc 0.  vl run: invalid module, type mismatch: expected nullref, found i32

Want:

    1

#### Mechanism

A `null[]` list is stored as a scalar i32 list (`array.new_fixed` of `(i32.const 2)`), but the
callback lifted for `.map` takes its element at the `null` type's own rep, `nullref`
(`(param structref nullref)`). The map loop reads the i32 element and passes it to that parameter
unconverted. The element reaching the callback through a hole parameter bound at `null`
(`function h(x) { [x].map(…) }`, `h(null)`) is the same list.
