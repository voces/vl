### D13201 — a forwarded hole function its callee calls at operands its body cannot type is check-clean invalid wasm

**check-clean invalid wasm · `vl check` rc 0 · clause 1 · the direct spelling `apply3(add, 0.5)` is a loud check reject (`operator '+' is not defined for f64 and string`) · found closing [D12701](D12701.md) · present before lane L1's D12701 PR (seed at `e07ab908c`) and after it · filed 2026-10-25 against master `db5624b1c`**

Repro:

    function add(a, b) { return a + b }
    function apply3(g, s) {
      print(g(10, 20))
      print(g(s, "x"))
    }
    function inner(k, h) {
      apply3(h, k)
    }
    inner(0.5, add)
    // vl check: rc 0.  vl run: the emitted module failed to validate inside `add`: type mismatch: expected (ref $2), found f64; $2 is `string`

Want: a check reject at `inner(0.5, add)`, as the direct spelling refuses:

    error: operator '+' is not defined for f64 and string

#### Mechanism

Not measured. The demand `g(s, "x")` moves out to `inner`'s hole `h` and binds `add`'s slot to
`(f64, string) => _` at the outer call, but nothing judges `add`'s body at that instance
there, as the direct call's operator check does.
