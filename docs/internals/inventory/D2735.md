### D2735 — a lambda inside a generic that calls another generic at `<T>` has no parameter type for the capture

**loud emit reject · clause 2 · found by #3202's review (a/l1b) · identical on master · filed 2026-09-26 against master `74bd044d7`**

Repro:

    function b<T>(u: T | null): boolean { u == null }
    function a<T>(u: T | null): boolean {
      const k = () => b<T>(u)
      k()
    }
    const m: {[i32]: boolean} = Map()
    print(a<{[i32]: boolean}>(m))
    // vl check: rc 0.  vl run: emitProgram: only i32, i64, f64, f32, boolean, struct, union, array, or string parameters are supported

#### Mechanism

The lambda is lifted per instance of `a`, and its call to `b<T>` is instantiated while the lifted
body still reads `u` at the template's `T | null`. The callee's pin is then not a concrete type,
and emitting it refuses on the parameter kind. The same call made directly in `a`'s body, or a
lambda that tests `u` without calling a generic, runs.

#### Ablation

| ingredient removed | outcome | needed? |
| --- | --- | --- |
| the lambda (`b<T>(u)` in `a`'s body) | runs, prints `false` | **yes** |
| the generic call (`() => u == null`) | runs, prints `false` | **yes** |
| the map (`a<i32>(3)`) | still refuses (`unsupported argument type`) | no |
