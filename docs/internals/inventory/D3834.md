### D3834 — a generic called from a lambda argument over a nested list or generic record pins `T` to the wrong shape when the callback's own parameter is un-annotated

**loud emit reject · 3 shapes found in review of lane SC · filed 2026-10-08 against master `5a281ef27`**

Repro:

    type A = {x:i32}
    type B = {x:i32}
    function h<T>(x: T) { x.x }
    const a: A = { x: 4 }
    print([[a]].map((xs) => h(xs[0]))[0])
    // vl check: rc 0.  vl run: rc 1, emit error `emitProgram: field access receiver is not a struct`

Want:

    4

#### Mechanism

The callback's `xs` is un-annotated and its type comes from the receiver `A[][]`, so `h(xs[0])` sees `xs[0]` before the element's type is fixed and instantiates `h` at a pin that is not the record. #3431 pins a lambda argument to the receiver's element type for a flat `.map`, and declines these nested and generic-record shapes. Annotating the callback's parameter, or passing the element at the top level, runs.

#### Ablation

| ingredient removed | outcome | needed? |
| --- | --- | --- |
| the second record `B` of the same shape (`type B` deleted) | still loud emit reject | no |
| the nesting (`[a].map((xs) => h(xs))`) | loud emit reject, same message | no |
| the lambda (`print(h([a][0]))`) | prints `4` | **yes** |
| the callback's annotation (`(xs: A[]) =>`) | prints `4` | **yes** |
| the generic (`h(x: A)`) | prints `4` | **yes** |
