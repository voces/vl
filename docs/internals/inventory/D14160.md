### D14160 — an object literal argument that sets a field its parameter's named record type does not declare skips the excess-field check and drops the field

**closed · now runs, prints `true`, as the bound spelling `const r = { f: 3, g: 10 }; look(r)` does · was check-clean silently wrong (printed `false`) · closed 2026-10-31 against master `cb178881` with [D14426](D14426.md): the generic bind row is no longer rewritten at the adopted record, so the literal keeps the field · the excess-field refusal the fresh record width ruling gives every other position is still not given at this one; the program is no longer wrong, so that refusal is a check gap, not this row · found ablating the G12 field-set-scan cells · filed 2026-10-26 against master `bbdd4e720`**

Repro:

    type G = { g: i32 }
    type H = { f: i32, g: i32 }
    function look(o: G) { print(o is H) }
    look({ f: 3, g: 10 })
    // PRINTS true (printed false before 2026-10-31)

#### Mechanism

A literal is built at the shape it flows into, so a field that shape does not declare is
refused at check time with `this object literal sets `f`, which G does not declare`. That
refusal fires at a binding, a return, an assignment, a `push`, a list element, a nested
field, and an argument whose parameter type is written inline. At an argument whose
parameter type is a named alias it does not fire. The literal is then built at `G`, `f` is
dropped after its initializer runs, and `o is H` reads `false`. The same literal bound first
(`const r = { f: 3, g: 10 }; look(r)`) is a record of its own type and reads `true`, so the
two spellings disagree.

#### Ablation

| ingredient removed or changed | outcome | needed? |
| --- | --- | --- |
| the argument position (`const o: G = { f: …, g: 10 }`) | loud check reject, `sets `f`, which G does not declare` | **yes** |
| the named parameter type (`look(o: { g: i32 })`) | loud check reject, same sentence | **yes** |
| the literal (`const r = { f: 3, g: 10 }; look(r)`) | runs, prints `true` | **yes** |
| the `is` test (`print(o.g)`, `f: side()`) | runs, prints `side` then `10`: the dropped field's initializer is evaluated | no |
| `f` an `i32` (a string, a named function or a lambda instead) | same, prints `false` | no |
| a return, assignment, `push`, list element or nested field at `G` | loud check reject, same sentence | — |

#### Grading list

The function-field spelling, which prints nothing where the bound face prints `in`:

    type G = { g: i32 }
    type H = { f: (x: string) => string, g: i32 }
    function k4(x: string): string { return x }
    function look(o: G) { if o is H { print(o.f("in")) } }
    look({ f: k4, g: 10 })
