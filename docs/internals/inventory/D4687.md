### D4687 — a generic called with a `null`-typed variable pins its type parameter at `i32`, not `null`

**closed — the monomorphizer's argument pin (`monoArgPinName`, `emit_mono.vl`) names `null` for any argument whose checked type is the `null` unit type, and `null[]` for a list of it, so the instance takes D4550's `nulnone` cell (was check-clean invalid wasm) · graded by `tests/cases/types/null-unit-heap-positions.vl` (`at0`, `put`, `id`) · filed 2026-10-14 against `bfe4fb5c0` (D4550's branch)**

Repro:

    function id<T>(x: T): T { return x }
    function k(v: null): null { return id(v) }
    print(k(null) ?? 1)
    // vl check: rc 0.  vl run: the emitted module failed to validate inside `k`: current function requires result type [nullref] but callee returns [i32]

Want:

    1

#### Mechanism

D4550 pinned a generic at `null` only from a literal `null` argument. An argument that is a
`null`-typed binding or parameter fell through the pin ladder to the i32 default, so the
instance returned `i32` into a caller whose own result is `nullref`.
