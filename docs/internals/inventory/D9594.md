### D9594 — a `const` bound to a call returning a generic, both listed and called directly at two types, reaches no call that fixes its type

**loud emit reject · `vl check` rc 0 · `a generic function taken as a value reaches no call that fixes its type` · clause 2 · found closing [D9481](D9481.md) · present on master `49a7d0b10` · filed 2026-10-22 against master `49a7d0b10`**

Repro:

    function id<T>(x: T): T { x }
    function mk() {
      print("mk")
      return id
    }
    const v = mk()
    const xs = [v]
    print(xs[0](2))
    print(xs[0]("abc"))
    print(v(5))
    print(v(true))
    // vl check rc 0.  vl run: emit error: emitProgram: a generic function taken as a value reaches no call that fixes its type

Want:

    mk
    2
    abc
    5
    true

#### Mechanism

The callee's `return` operands are noted inert only when every link of the `const` chain from
the list element to the call is read once (`monoFlowNoteInertRets`, emit_mono.vl, D9481),
since a second read could call the result at a type the stub does not serve. Here `v` is read
twice, so `id`'s `return` is not inert and `monoStubValueOk` refuses it as a returned generic
that wants a copy per signature.

#### Ablation

| ingredient removed | outcome | needed? |
| --- | --- | --- |
| the direct calls `v(5)`, `v(true)` | runs | **yes** |
| the list (`v` called directly only) | runs | **yes** |
