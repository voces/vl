### D9594 — a `const` bound to a call returning a generic, both listed and called directly at two types, reaches no call that fixes its type

**closed · runs, prints `mk` `2` `abc` `5` `true` · was loud emit reject, `vl check` rc 0, `a generic function taken as a value reaches no call that fixes its type`, clause 2 · found closing [D9481](D9481.md) · filed 2026-10-22 against master `49a7d0b10` · closed by splitting a call-bound `const` of a generic that is called at one type and also delivered as a value, the delivered read taking a slot of its own that reads the generic afresh, while the binding that runs the call keeps a slot a call fixes (`fsLetSplitKeys`, `fsMemHoldsGeneric`, `fsCallLaneFirst`, fn_split.vl) · fixture `closures/call-bound-generic-listed-and-called-directly.vl`, matrix `fn-value-generic-call-bound-listed-open` (0 → 43 of 46, shared with [D9593](D9593.md)) · with [D9593](D9593.md) closed, [D9652](D9652.md) filed open**

Repro:

    function id<T>(x: T): T { x }
    function mk() {
      print("mk")
      return id
    }
    const v = mk()
    const xs = [v]
    print(xs[0](2))
    print(xs[0]("abc"))
    print(v(5))
    print(v(true))
    // vl check rc 0.  vl run: emit error: emitProgram: a generic function taken as a value reaches no call that fixes its type

Want:

    mk
    2
    abc
    5
    true

#### Mechanism

The callee's `return` operands are noted inert only when every link of the `const` chain from
the list element to the call is read once (`monoFlowNoteInertRets`, emit_mono.vl, D9481),
since a second read could call the result at a type the stub does not serve. Here `v` is read
twice, so `id`'s `return` is not inert and `monoStubValueOk` refuses it as a returned generic
that wants a copy per signature.

The slot-split planner (fn_split.vl) could serve it but did not ask: it asked a call-bound
`const` only when its reads carried two call keys (`fsLetCallKeys(d) > 1`), and `v` has one
(its direct calls) plus a value read (`[v]`, key `u:`), and `fsLaneSet` declined any `u:`
delivery into an open destination. The close asks on one call key plus a value read
(`fsLetSplitKeys`), lets a `u:` read take its own slot when the member is a `const` whose call
always returns one generic name (`fsMemHoldsGeneric`; that slot reads the name afresh, so the
list's element stays the open generic the D9481 path serves), and puts a call-fixed key first
so the original binding, which runs the call once, keeps a slot a call types
(`fsCallLaneFirst`).
