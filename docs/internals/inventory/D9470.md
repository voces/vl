### D9470 — a record of an un-annotated function bound to a `const` before it is written into a map is not judged with the map's other records at check

**loud emit reject · `vl check` rc 0 · `unsupported map value type` · clause 2 · found closing [D9370](D9370.md) · present on master `4193ec5e4` · filed 2026-10-21 against master `4193ec5e4`**

Repro:

    function inc0(a) { return a + 1 }
    function half(a) { return a / 2.0 }
    const m = Map()
    m.set("a", { f: inc0 })
    const r0 = { f: half }
    m.set("b", r0)
    const r = m.get("b")
    if r != null { print(r.f(3)) }
    // vl check rc 0.  vl run: emit error: emitProgram: unsupported map value type (no rep for a union-member struct, ...)

#### Mechanism

Partly traced. `cwSlotDescend` follows a written value into list and record literals only,
so the `set` of the binding `r0` makes `cwSlotWrittenValues` answer -1 and
`holeSlotJudge` declines; the disagreement reaches the emitter. The inline spelling
`m.set("b", { f: half })` is refused at check ([D9370](D9370.md)).

#### Ablation

| ingredient removed | outcome | needed? |
| --- | --- | --- |
| the `inc0` write | runs, `1.5` | **yes** |
| the binding (`m.set("b", { f: half })`) | loud check reject ([D9370](D9370.md)) | **yes** |

#### Grading list

The same binding pushed onto a list (`l.push(r0)`, `l[1].f(3)`), and a binding written
through after it is stored (`r0.f = half`).
