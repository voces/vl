### D9470 — a record of an un-annotated function bound to a `const` before it is written into a map is not judged with the map's other records at check

**closed 2026-10-22 by lane-D9470 · now a loud check reject, DESIGN, `cannot write 'half' to 'm[].f': … every function a call through 'm[].f' may run must return one type` · was loud emit reject, `unsupported map value type`, `vl check` rc 0 · clause 2 · closed by following a value written at a place into the binding it names, every value that binding holds at the rest of the path (`cwSlotDescendBinding`, check_write_scan.vl) · fixtures `closures/error-hole-fn-records-bound-before-set-into-map.vl`, `closures/error-hole-fn-records-bound-before-push.vl`, control `closures/hole-fn-records-bound-before-push-of-one-result.vl` · residue [D9533](D9533.md), [D9534](D9534.md) · found closing [D9370](D9370.md) · present on master `4193ec5e4` and `1cf53e320` · filed 2026-10-21 against master `4193ec5e4`**

Repro:

    function inc0(a) { return a + 1 }
    function half(a) { return a / 2.0 }
    const m = Map()
    m.set("a", { f: inc0 })
    const r0 = { f: half }
    m.set("b", r0)
    const r = m.get("b")
    if r != null { print(r.f(3)) }
    // vl check rc 0.  vl run: emit error: emitProgram: unsupported map value type (no rep for a union-member struct, ...)

#### Mechanism

`cwSlotDescend` followed a written value into list and record literals only, so the `set`
of the binding `r0` made `cwSlotWrittenValues` answer -1 and `holeSlotJudge` declined; the
disagreement reached the emitter. An identifier reached before the path ends now descends
into the binding it names through `cwSlotWrittenValues` at the rest of the path, which
also collects a later write through it (`r0.f = half`) and an alias of it. A chain of
bindings deeper than 16 declines as before.

#### Ablation

| ingredient removed | outcome | needed? |
| --- | --- | --- |
| the `inc0` write | runs, `1.5` | **yes** |
| the binding (`m.set("b", { f: half })`) | loud check reject ([D9370](D9370.md)) | **yes** |

#### Why the refusal is owed

The rule is [D9370](D9370.md)'s: a call through the field of a record read from the map
may run any function stored in that field, so every such function must return one type.
Binding the record first changes nothing about what is stored.

#### Grading list

Graded after the close, each the same refusal: the binding pushed onto a list
(`l.push(r0)`, `l[1].f(3)`, which on master trapped), the binding written through after it
is stored (`r0.f = half`), an alias (`const r1 = r0`, `m.set("b", r1)`), an index store
(`m["b"] = r0`, `l[0] = r0`), a list literal holding the binding
(`[{ f: inc0 }, r0]`) and the binding nested in a pushed record (`l.push({ g: r0 })`, which
on master trapped). Records of one result run (`{ f: dbl }` pushed after `{ f: inc0 }`,
`6`). A record bound first and set alone into an un-annotated `Map()` still refuses at emit
when every function returns one type, as on master: [D9533](D9533.md); a list literal
mixing an inline record and a bound one: [D9534](D9534.md).
