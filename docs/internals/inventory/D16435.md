### D16435 — a list literal of a held record and a fresh one, at an annotated record list with a literal-union field, joins its elements before the annotation can adopt the fresh one

**loud check reject · filed 2026-11-15 by lane H against master `50e2c3f4` · found by the stage 4 layout probes (`type K = "a" | "b"` as a record field)**

Repro:

    type K = "a" | "b"
    type RA = { k: K }
    const ra: RA = { k: "a" }
    const ys: RA[] = [ra, { k: "b" }]
    print(ys.length)
    // vl check: RA is not {k: string}: they store field `k` differently (`K` into `string`), and a record is shared, not copied, so only a fresh record widens

Want:

    2

#### Mechanism

The elements of the list literal are joined with each other before the destination `RA[]`
reaches the fresh element. The literal `{ k: "b" }` therefore takes its widened anonymous type
`{k: string}`, and the held `ra: RA` is then asked to fit that join, which the shared-record rule
refuses. When every element is fresh, each literal is adopted at `RA` and the program runs. So
does a `push` of the same literal onto an `RA[]`.

#### Ablation

| change | outcome | needed? |
| --- | --- | --- |
| the field is `"a" \| "b"` inline instead of the alias `K` | still refuses | no |
| the elements in the other order (`[{ k: "b" }, ra]`) | still refuses | no |
| the list passed to an `RA[]` parameter instead of bound | still refuses | no |
| the field is `i32` or `i32 \| null` | runs | **yes** (a literal-union field) |
| every element fresh (`[{ k: "a" }, { k: "b" }]`) | runs | **yes** (a held record beside a fresh one) |
| `ys.push({ k: "b" })` onto `const ys: RA[] = [ra]` | runs | **yes** (a list literal) |

#### Grading list

- The argument position: `function f(xs: RA[]): i32 { xs.length }` called as `f([ra, { k: "b" }])`.
- The reversed order, `[{ k: "b" }, ra]`.
- A map-literal spelling of the same join, if one exists, and a record field holding the list.
