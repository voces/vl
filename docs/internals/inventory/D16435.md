### D16435 — a fresh record literal joined beside a held record with a literal-union field takes its widened type, and the held record is refused

#### Mechanism

Ablation widened the family past the list literal: an `if` and a `match` joining `ra` with a
fresh `{ k: "b" }` refused the same way, with or without an `RA` destination. A fresh record
literal's string field widens to `string` before the join, so the join is `{k: string}`, and the
held record is then refused. The `if` banked that join as its value type
(`ifTailBankValTy`) even where `litJoinOf` found the destination. The close adapts the fresh
literal to its held sibling, as a numeric literal adapts (owner ruling 4.3).

The original reading: the elements of the list literal are joined with each other before the destination `RA[]`
reaches the fresh element. The literal `{ k: "b" }` therefore takes its widened anonymous type
`{k: string}`, and the held `ra: RA` is then asked to fit that join, which the shared-record rule
refuses. When every element is fresh, each literal is adopted at `RA` and the program runs. So
does a `push` of the same literal onto an `RA[]`.

#### Ablation (before the close)

| change | outcome | needed? |
| --- | --- | --- |
| the field is `"a" \| "b"` inline instead of the alias `K` | still refuses | no |
| the elements in the other order (`[{ k: "b" }, ra]`) | still refuses | no |
| the list passed to an `RA[]` parameter instead of bound | still refuses | no |
| the field is `i32` or `i32 \| null` | runs | **yes** (a literal-union field) |
| every element fresh (`[{ k: "a" }, { k: "b" }]`) | runs | **yes** (a held record beside a fresh one) |
| `ys.push({ k: "b" })` onto `const ys: RA[] = [ra]` | runs | **yes** (a list literal) |
| `const y = if c { ra } else { { k: "a" } }`, with or without `: RA` | still refuses | no (any join form) |
| `match s { 1 => ra, _ => { k: "b" } }` | still refuses | no (any join form) |
| `[ra, { k: "c" }]`, a literal outside `K` | still refuses | refused by design after the close |

- A map-literal spelling of the same join, if one exists, and a record field holding the list.
