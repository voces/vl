### D14620 — the emitter still finds a self-function by name, through `drwSelfFnOf` for a member call with no recorded declaration and through `fnDeclNamed` in `emit_mono`

**runs today and must keep running · a named floor, no wrong value · filed 2026-10-28 against master `5a6cf70a4`**

Repro:

    type V = { x: i32 }
    function "+"(self: V, other: V): i32 { self.x + other.x }
    function "[]"(self: V, i: i32): i32 { self.x * i }
    function "[]="(self: V, i: i32, v: i32) { print(self.x + i + v) }
    const p: V = { x: 2 }
    const q: V = { x: 3 }
    print(p + q)
    print(p[4])
    p[1] = 10

Want:

    5
    8
    13

#### Mechanism

Filed when the checker banked a resolved operator function as a NAME, so the dispatch rewrite
minted every operator callee through `fnDeclNamed`, a name-to-`FuncDecl` index over `fnStmts`
(`fdnDecl`). The checker now records the declaration itself (`opSiteBank` writes `opSiteDecl`,
read by `opDeclAtNode`), and a UFCS callee is minted only from the declaration the checker
records for every call it types as UFCS (`memberDeclOf`); a call without one gets a named
emit failure. Two name-keyed readers remain, both deciding dispatch for a member call with no recorded
declaration (`drwSelfDeclAt` answering -2): `drwDispatches`' `drwSelfFnOf` path in
`emit_rewrite.vl`, which also decides `MC_RUNG_PER_INSTANCE`, and `emit_mono.vl`'s per-instance
lowering, which reads the same path and `monoFnDeclNamed`. The deletion target is `fdnDecl` and
`drwSelfFnOf` once both read a declaration.
