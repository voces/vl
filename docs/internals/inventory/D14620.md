### D14620 — the emitter finds an operator's function by name, because the checker banks the resolved operator function as a string

**runs today and must keep running · a named floor, no wrong value · filed 2026-10-28 against master `5a6cf70a4`**

Repro:

    type V = { x: i32 }
    function "+"(self: V, other: V): i32 { self.x + other.x }
    function "[]"(self: V, i: i32): i32 { self.x * i }
    function "[]="(self: V, i: i32, v: i32) { print(self.x + i + v) }
    const p: V = { x: 2 }
    const q: V = { x: 3 }
    print(p + q)
    print(p[4])
    p[1] = 10

Want:

    5
    8
    13

#### Mechanism

The checker resolves a user-defined operator at its site and banks the function's NAME
(`opIdxBank`/`opBinBank` in `check_call_resolve.vl`, read back by `opIdxFnAtNode` and
`opBinFnAtNode`). The emitter's dispatch rewrite (`drwFnRef` in `emit_rewrite.vl`) therefore
has only a name to mint the callee from, and finds the declaration through `fnDeclNamed`, a
name-to-`FuncDecl` index over `fnStmts` (`fdnDecl`). The other `drwFnRef` callers, the
self-reference callee and the extern wrapper, are synthesised callees. Each is counted
here unless it can carry a declaration at synthesis time. The deletion target is one checker
column holding the resolved operator `FuncDecl` at the operator node, with one writer, which the
three operator sites read. Once those move, `monoFnDeclNamed` in `emit_mono.vl` is the last
reader of `fnDeclNamed`.
