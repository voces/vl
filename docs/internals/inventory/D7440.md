### D7440 — a bare-literal field read handed to a generic pins the atom's raw width, not `string`

**closed 2026-10-19 by lane L6 · runs, prints `a` · was runs but wrong value · clause 1 · a lone string literal with no alias pins the `string` instance and widens at the call (`monoArgLitUnionPin`) · pin: `tests/cases/generics/one-literal-field-through-generic.vl` · present on master `1c86d0f42` · filed 2026-10-19 against master `1c86d0f42`**

Repro:

    type A = { kind: "a", x: i32 }
    type B = { kind: "b" | "c", x: i32 }
    type U = A | B
    function id<T>(x: T): T { return x }
    const a: A = { kind: "a", x: 1 }
    print(id(a.kind))
    // vl check: rc 0.  vl run on master: prints 0, the interned atom, not `a`

#### Mechanism

A field typed by one bare string literal reps as the interned atom wherever its record shares
a literal-set field with a sibling arm (here `B`'s `"b" | "c"`), and everywhere since
[D7220](D7220.md)'s close. `monoArgLitUnionPin` pins a literal-union argument by its alias
name, else by its inline spelling, and a lone `TyLit` has neither: it is not a `TyUnion`, so
the pin fell through to the argument's raw rep, and `id` was instantiated over the atom's
i32 while printing it as a scalar. The close pins a lone literal at `string`, and the call
widens the atom to its text through the named-union conversion.
