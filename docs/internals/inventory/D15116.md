### D15116 — a map written one un-annotated function through an index store, called at two types, has no value slot

**open · loud emit reject · `emitProgram: unsupported map value type (... any other value type here interned no mv slot)` · clause 2 · the same store spelled `m.set(k, f)` runs · found choosing G2's next item from D14401's message · filed 2026-11-04 against master `e394c738d`**

Repro:

    function inc(a) { return a + 1 }
    const mp = Map()
    mp["k"] = inc
    const g = mp["k"]
    if g != null {
      print(g(2))
      print(g(2.5))
    }

Want:

    3
    3.5

#### Mechanism

Both calls go through one set whose only member is `inc`, and the fn-tag pass declines to tag it,
so the map's value is a closure that has no one signature. `ftScan` refuses the store
`mp["k"] = inc`: `ftCtxOk`'s store arm asks the left side's own type (`_ | null`) whether it holds
the set, while the map's type, `{[string]: (_) => _}`, does hold it (`ftHoldKind` 3). The
`m.set(k, f)` spelling is judged by `ftSlotWriteArg`, which asks the holder's `ftHoldKind`, so the
two spellings of one slot write disagree. Two members run, because the read type of their join is
the set itself.

#### Ablation

| --- | --- | --- |

| the map (`{ f: inc }` read as `r.f`) | runs | **yes** |
| the map (`xs.push(inc)` read as `xs[0]`) | runs | **yes** |
| the one member (`mp["j"] = dbl` beside it) | runs (D14432) | **yes** |
| the second call type (`g(2)` only) | runs | **yes** |
| the `if g != null` read (`mp["k"] ?? inc`) | still refuses | no |

#### Grading list

* The same store into a list (`xs[0] = inc` over a list holding the set).
* A list of maps of the set written through an index (D15187's kind).
