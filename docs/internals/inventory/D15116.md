#### Mechanism

so the map's value is a closure that has no one signature. `ftScan` refuses the store
`mp["k"] = inc`: `ftCtxOk`'s store arm asks the left side's own type (`_ | null`) whether it holds
the set, while the map's type, `{[string]: (_) => _}`, does hold it (`ftHoldKind` 3). The
`m.set(k, f)` spelling is judged by `ftSlotWriteArg`, which asks the holder's `ftHoldKind`, so the
two spellings of one slot write disagree. Two members run, because the read type of their join is
the set itself.
