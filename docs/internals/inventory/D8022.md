### D8022 — a generic identity given an explicit anonymous record type argument, delivered into a wider record, is invalid wasm

**check-clean invalid wasm · `vl check` rc 0 · clause 1 · open · present on master `981320f30` · the same call with a declared record type argument is refused · found grading [D7941](D7941.md) · owner lane S5 · filed 2026-10-20 against master `981320f30`**

Repro:

    type J = { r: i32 | null }
    function idn<T>(v: T): T { v }
    const u: J = idn<{ r: i32 }>({ r: 4 })
    print(u.r ?? 0)
    // vl check: rc 0.  vl run: invalid module, "expected (ref null $type), found (ref $type)": `J` expected, `{r:i32}` found

Want:

    4

#### Mechanism

The written type argument pins `T` at `{r: i32}`, so the result is an existing record of that
type, and the record storage rule should refuse it as it refuses `idn<Col>(...)` with
`type Col = { r: i32 }` declared. The anonymous spelling is let through as though the literal
were delivered fresh, and nothing re-seats it, since the instance is fixed by the type
argument. Whether the call refuses or runs is a ruling question; today it does neither.

#### Ablation

| change | outcome | needed? |
| --- | --- | --- |
| `idn<J>(...)` | prints `4` | **yes** |
| `J`'s field `r: i32` | prints `4` | **yes**, the field stored differently |
| `type Col = { r: i32 }` and `idn<Col>(...)` | refuses, an existing record | **yes**, the anonymous spelling |

#### Grading list

The same with a `{ r, g, b }` field set, and through a binding, `const s = idn<{ r: i32 }>(...)`.
