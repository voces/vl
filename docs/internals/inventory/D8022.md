### D8022 — a generic identity given an explicit anonymous record type argument, delivered into a wider record, is invalid wasm

**closed 2026-10-20 by lane records · now a loud check reject (`{r: i32} is not J: they store field r differently`) · was check-clean invalid wasm · clause 1 · a call that writes its type arguments is the origin of its result, so the record is refused as an existing `{r: i32}` exactly as `idn<Col>(...)` is, at every delivery position of the `generic-identity-written-type-arg-into-wider-record` matrix (36 cells invalid wasm on master, 0 now) · fixture `tests/cases/soundness/error-record-built-at-its-own-row-positions.vl` · filed 2026-10-20 against master `981320f30`**

Repro:

    type J = { r: i32 | null }
    function idn<T>(v: T): T { v }
    const u: J = idn<{ r: i32 }>({ r: 4 })
    print(u.r ?? 0)
    // vl check: {r: i32} is not J: they store field `r` differently ... only a fresh record widens

#### Mechanism

The written type argument pins `T` at `{r: i32}`, so the result is an existing record of that
type. `recOriginExpr` (`check_rec_fresh.vl`) used to look through the call to the literal
argument and report the delivery as fresh; it now stops at a call with written type arguments,
so the record storage rule sees the call and refuses it, the same verdict as the declared
`idn<Col>(...)` spelling.

#### Ablation

| change | outcome | needed? |
| --- | --- | --- |
| `idn<J>(...)` | prints `4` | **yes** |
| `J`'s field `r: i32` | prints `4` | **yes**, the field stored differently |
| `type Col = { r: i32 }` and `idn<Col>(...)` | refuses, an existing record | no, same verdict |

#### Grading list

The same through a binding, `const s = idn<{ r: i32 }>({ r: 4 })` then `const u: J = s`, which
the fixture pins; and the matrix `generic-identity-written-type-arg-into-wider-record`.
