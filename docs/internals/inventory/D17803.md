### D17803 — mono builds a binding of one type parameter seeded from another's parameter at that parameter's annotation, a rung standing in for the binding's writes' join

**runs today and must keep running · rung REMOVED 2026-11-28 by COV-CLOS-3: `monoSubstLetType` builds an annotated binding of one type parameter initialised at another at its initialiser's type, through the same substitution its annotation takes (`monoSubstOpenTyRef`), which is the type the check binds it at (`checkLetDeclNodeIn`); the parameter-seeded special case is gone, and the witness prints the same · was a rung, not a defect: `monoSubstLetType` (emit_mono.vl) builds `let b: F = a1`, `a1: G`, at `G`'s annotation because mono has no join of the binding's writes · added by D17321's close (#10708) · filed 2026-11-28 against master `f5f6070c` by COV-CALL**

#### Mechanism

The ruling (DECISIONS.md, "A type parameter's pin is not a binding's set") types the binding at
what it is written. The check does that for the initialiser; mono reads the initialiser's
parameter's annotation instead, which holds while the later writes' parameters are pinned the same
way (closure-first). Without the rung this program is refused at emit, `call of a non-declaration`.

#### Removal

Express the binding's type in mono as its writes' join (initialiser and every whole write), read
through the one reader the check uses, and delete the rung; this witness must keep printing the
same.

Removed 2026-11-28. The replacement reads the binding's initialiser, which is what the check binds
it to, not a join of every write: the check joins no writes either, and the later write of
`a2` (`H`) is pinned closure-first at the same signature, as before. A program whose later write
needs a type the initialiser's does not admit is not covered by this, nor was it by the rung.
