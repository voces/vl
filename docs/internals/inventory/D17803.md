### D17803 — mono builds a binding of one type parameter seeded from another's parameter at that parameter's annotation, a rung standing in for the binding's writes' join

**runs today and must keep running · a rung, not a defect: `monoSubstLetType` (emit_mono.vl) builds `let b: F = a1`, `a1: G`, at `G`'s annotation because mono has no join of the binding's writes · added by D17321's close (#10708) · filed 2026-11-28 against master `f5f6070c` by COV-CALL**

Repro:

    function same<T>(k: T): T { return k }
    function twice<T>(k: T): T { return k }
    function third<T>(k: T): T { return k }
    function mid<F, G, H>(a: F, a1: G, a2: H) {
      let b: F = a1
      print(b(3))
      if "ab".length > 1 { b = a2 }
      print(a("x"))
      print(b(5))
    }
    mid(same, twice, third)

Want:

    3
    x
    5

#### Mechanism

The ruling (DECISIONS.md, "A type parameter's pin is not a binding's set") types the binding at
what it is written. The check does that for the initialiser; mono reads the initialiser's
parameter's annotation instead, which holds while the later writes' parameters are pinned the same
way (closure-first). Without the rung this program is refused at emit, `call of a non-declaration`.

#### Removal

Express the binding's type in mono as its writes' join (initialiser and every whole write), read
through the one reader the check uses, and delete the rung; this witness must keep printing the
same.
