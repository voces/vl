#### Mechanism

A top-level statement checks the later-declared functions it reaches first, except one whose
facts come from the statement. An un-annotated parameter is one of those: the statement's own
call solves it (`eagerCheckable` in `compiler/check_top_level.vl`). So `both2` and `c2`
are checked in source order, after `const b = both2(dbl)` has been typed from their pending
results. Inside an early `main()` the statement is a function body, its callees are checked
first by their pending results, and it runs. An inferred interface per function (L2) would give
`both2` and `c2` a signature before any call, and the order would not matter.
