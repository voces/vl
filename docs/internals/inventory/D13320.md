### D13320 — a forwarded hole function called over a `const`-bound list whose elements call it at two keys has no interned signature

**closed 2026-10-25 by lane L1 · runs, prints `1 2.5` · a `for` over an un-annotated `const` bound to a list literal moves the other elements' hole demands out to the caller's holes as the same list in the header does (`forIterListLit`, `forElemArgCstrs`, check_calls.vl), so the forwarded hole binds at both keys · pin: `tests/cases/closures/forwarded-hole-fn-const-list-two-keys.vl` (the witness, a top-level `const` list, a result delivered to a binding, three elements at three keys from two frames) · was loud emit reject · `vl check` rc 0 · clause 2 · CAPABILITY: the same list written inline in the `for` header runs · found by lane L1 closing [D13200](D13200.md) · present on master and after lane L1's D13200 PR · filed 2026-10-25 against master `ea2c435a3`**

Repro:

    function add(a, b) { return a + b }
    function apply2(g, s) {
      print(g(s, s))
    }
    function apply4(g, s) {
      print(g(s, 2))
    }
    function innerThree(k, h) {
      const gs = [apply2, apply4]
      for f in gs { f(h, k) }
    }
    innerThree(0.5, add)
    // vl check: rc 0.  vl run: emitProgram: a function-value call has no interned signature — parameter 1 of type `` has no representation in the function-value ABI

Want:

    1
    2.5

#### Mechanism

The split round plans the same slots for both spellings; the asymmetry is in the checker.
A call through a `for` variable is typed at one element's signature, and `forElemArgCstrs`
(check_calls.vl) moves every OTHER element's demands on its hole parameters out to the
caller's holes (D12701) — but only when the loop's iterable was itself a list literal. Bound
to a `const`, `apply4`'s demand on `g` never reached `h`, so after the split `innerThree`'s
second slot stayed unbound (type ``) at `innerThree(0.5, add)`. Hand-splitting the program
reproduced it: an element that only reads the second slot failed, one that read both ran.
The fix resolves the iterable through `ctnLitInitOf` to the `const`'s literal initializer.
A `let`-bound list is still refused (D13521).
