### D15160 — an open map or list written two generic functions of different result types is refused at check

**closed · runs, prints `1.5` · was loud check reject, `set: expected (i32) => i32, got (i32) => f64` (a list `push` said `push: cannot add (i32) => f64 to ((i32) => i32)[]`) · clause 2 · found closing [D15137](D15137.md) · filed 2026-11-03 against master `b813a46b` · closed 2026-11-03: `elabSlotJoinTy` joins a container slot's writes when either set holds a generic too, and the deferred `set`/`push` argument check passes a function the joined slot's set holds (`elabSlotSetHolds`), since the join admitted it; a generic whose body fails at the call's arguments is still refused there**

Repro:

    function id<T>(x: T): T { return x }
    function half<T>(x: T): f64 { return x / 2.0 }
    const m = Map()
    m.set("a", id)
    m.set("b", half)
    const g = m.get("b")
    if g != null { print(g(3)) }
    // Want: 1.5

#### Mechanism

`elabSlotJoinTy` (check_elab_cap.vl) joins a container slot write with the binding's other writes only when neither set holds a generic (`fnSetHasGeneric`), so the first write pins the slot at the generic's instance and the second write is judged against it.
