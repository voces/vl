### D4770 — `.length`, `a[i]` and `for` over a union of lists that all spell one list are refused when a member's element is a literal union

**loud check reject · `i32[] | K[]` (a numeric literal union `K`) read without an `is` · clause 2 · found closing D4745, whose grading list named the `.length` refusal · filed 2026-10-14 against master `9ce99156e`**

Repro:

    type K = 0 | 1
    const a: i32[] | K[] = [1, 0, 1]
    print(a.length)
    // vl check: rc 1, field 'length' is not on every member of i32[] | K[] — narrow with `is` first (i32[] is a list, not a record)

Want:

    3

#### Mechanism

`checkMemberNode`'s union arm types `.length` over a union of lists through the D2874
rewrite (`luLengthAt`), and `luMembers` declines any member whose element holds a literal
type (D2886), so the read falls to the generic "not on every member" refusal. `checkIndexNode`
and the `for` arm decline the same way. Since D4743/D4745 such a union reps as the one list
its members render at every position, so the rewrite is not needed here: the read is that
list's own `.length`, and the element is the members' join.

#### Grading list

The `a[2]` and `for` spellings above. `K[] | string[]` keeps its refusal by
`tests/cases/unions/error-list-union-declined-shapes.vl` (D2886), and only a union whose
members render ONE list is in scope here.
