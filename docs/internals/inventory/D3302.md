#### Mechanism

`x` lives in a capture cell, so every read is `x[0]` and its narrowing is keyed on the cell. In
the else arm the emitter pushes the `x == null` complement on `x[0]` (a plain `i32`), while the
checker's type for the inner read, which `captureBoxRewrite` carries in `cboxReadTy`, is still
`i32 | null`: the then arm's call retired the name in place, and the else arm's guard layer sits
over that retirement. The inner `x == null` is then neither a dead test (the checker's type admits
null) nor a live one (the emitter reads an `i32`), and the compare has no null to lower. The
review's other 38 cells of this message were a dead test over a narrowed cell read, which #3304
lowers now (`cellReadProvesNonNull`).
