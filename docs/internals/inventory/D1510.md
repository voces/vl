### D1510 — a struct literal evaluated its initialisers in LAYOUT order, so a literal written in any other order ran them permuted

**closed — `emitObj` / `emitVariantStruct` evaluated each initialiser at the moment they pushed
it, and `struct.new` takes its operands sorted by field NAME (D622) · was `check-clean wrong
evaluation`, clause 1 · reported by the glean session as VL-018 (`~/glean/docs/vl-issues.md`),
where it silently permuted a nine-byte record read · filed and closed 2026-09-03 against master
`bd500845`**

Repro (runs, prints `1` then `2` then `3`):

    let n = 0
    function next() { n += 1; n }
    const s = { b: next(), a: next(), c: next() }
    print(s.b)
    print(s.a)
    print(s.c)
    // PRINTS 2 1 3 before the fix — each field got its ALPHABETICAL neighbour's value

#### Mechanism

A struct row's fields are laid out in the CANONICAL order — ascending by field name
(`fieldNameOrder`, D622) — and `struct.new` takes its operands in that order. `emitObj` walked
the LAYOUT indices and called `emitExpr` on each field's initialiser at the moment it pushed it,
so the initialisers ran in layout order, not source order. `emitVariantStruct` did the same for
a union arm. Nothing in the type system can see it: every field gets a value of the right type,
so `vl check` is clean, the module validates, and only a side effect reveals the permutation.

The fix evaluates out-of-order initialisers into scratch locals in SOURCE order and pushes the
locals in layout order. `objLitNeedsOrderStash` is the gate and it has TWO conditions, the
second of which is what keeps the tree byte-identical: the layout order must actually reorder
something, AND some initialiser must be observable (`exprEffectFree` — a whitelist over the leaf
and operator kinds, fail-CLOSED on everything else). A permutation of reads alone changes
nothing, so a literal whose initialisers are all effect-free keeps the push-in-place lowering.
The slots ride the LAZY list frame under codes `100 + <field code>`, minted FRESH per field
(`liBack` 1's rule: a nested literal is emitted DURING one of the outer literal's initialisers,
while the outer's earlier stashes are live). The slot's valtype comes from `pushFieldStorage` —
the same table the type section writes the field itself from, moved into the byte layer so both
writers read one table.
