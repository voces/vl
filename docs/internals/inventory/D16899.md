### D16899 — a lambda in a list handed to a generic's `(() => T | U)[]` keeps its own result rep, so the call through the list traps

**closed 2026-11-16 — the witness runs and prints `7` · was: loads then traps · clause 1 · `vl check` rc 0 · `vl run`: `wasm trap: indirect call type mismatch` in `many` · found building [D14082](D14082.md)'s position matrix · filed 2026-11-16 against master `c4052ed4e` by lane AE4**

Repro:

    function many<T>(fs: (() => T | string)[]) {
      fs[0]()
      return 7
    }
    print(many([() => 5]))

Want:

    7

#### Mechanism

In the instance `many<i32>`, the call through `fs[0]` is a `call_indirect` at the signature of
`() => i32 | string`, whose result is the union box. The closure the list holds points at the
lambda's own entry, whose result is a bare `i32`, and no adapter boxes it. A single
`f: () => T | string` parameter is delivered through an adapter and runs; the list element is not.

| the list bound first, `const fs = [() => 5]` | still traps | no |

#### Fix

`bindGenInnerUnionArms` (`compiler/check_relate_core.vl`) now reads a function type held inside a
list, nullable, field or map value at its result union, as `bindGenFnRetUnionArm` does at the top
level, so the argument is delivered at the bound type (`check_calls.vl`, D10133's delivery,
widened from a function type to any type that may hold one) and each list element is adapted.
