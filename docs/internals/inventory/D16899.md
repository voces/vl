### D16899 — a lambda in a list handed to a generic's `(() => T | U)[]` keeps its own result rep, so the call through the list traps

**loads then traps · clause 1 · `vl check` rc 0 · `vl run`: `wasm trap: indirect call type mismatch` in `many` · found building [D14082](D14082.md)'s position matrix · filed 2026-11-16 against master `c4052ed4e` by lane AE4**

Repro:

    function many<T>(fs: (() => T | string)[]) {
      fs[0]()
      return 7
    }
    print(many([() => 5]))
    // vl check: rc 0.  vl run: wasm trap: indirect call type mismatch

Want:

    7

#### Mechanism

In the instance `many<i32>`, the call through `fs[0]` is a `call_indirect` at the signature of
`() => i32 | string`, whose result is the union box. The closure the list holds points at the
lambda's own entry, whose result is a bare `i32`, and no adapter boxes it. A single
`f: () => T | string` parameter is delivered through an adapter and runs; the list element is not.
