### D17423 — a `null`-typed compare with an assignment of `null` on one side, against anything but a bare `null`, emits an invalid module

**check-clean invalid wasm · clause 1 · `vl check` rc 0, `vl run`: `the emitted module failed to validate inside \`g\`: type mismatch: expected i32, found nullref` · legacy's bytes, as the IR declines (`operand at null`) · filed 2026-11-24 by lane S1 against master `cea354ff6`, found writing the `null test of null` matrix**

Repro:

    function n(): null { return null }
    function g() {
      let s: string | null = "a"
      print((s = null) == n())
    }
    g()
    // vl check: 0 errors.  vl run: invalid module, `type mismatch: expected i32, found nullref`

Want:

    true

#### Mechanism

Legacy's `null`-typed pair compare (`emitNulNoneEq`) runs each side for its effect through
`emitNulNoneForEffect`, and an assignment of `null` on one side leaves a value of the wrong type
where the compare's `i32` answer is expected. Not yet read past the symptom.
