### D2162 — the converting copy is licensed at a RETURN although the argument it came from is written afterwards, so the copy silently stops sharing

**check-clean silently wrong · clause 1 · 5 pairs of the no-implicit-container-widening grid, one position · filed 2026-09-23 against master `b52b14e83`**

Repro:

    function view(xs: i32[]): f64[] { return xs }
    const a: i32[] = [1, 2]
    const b = view(a)
    a[0] = 7
    print(b[0])
    // PRINTS 1
    // vl check: rc 0.  vl run: prints 1; with `view` returning `i32[]` the same program prints 7

#### Mechanism

A covariant list delivery whose element storage changes lowers as an element-converting copy
(D791/D965), licensed only where nothing writes either handle (`covarValueWriteState` == 0).
At a `return xs` the licence is asked of the root `xs` in the callee's frame, and the alias
closure does not follow the parameter back to the caller's argument `a`, so the later `a[0] = 7`
is not seen and the copy is taken. The program then observes the divergence the licence exists
to rule out. Every other position of the grid refuses the same written program at check. The
2026-09-23 ruling (no implicit container widening) is the design reason this is wrong rather
than merely surprising.
