### D8720 — an inferred return, or a `match` value arm, joins a dead tail after an always-exiting statement into its type

**loud check reject · clause 2 · the dead tail never yields a value, and the declared-return and value-`if` paths already leave it out (D1974) · found closing [D1974](D1974.md) · filed 2026-10-20 against master `05e6ced30`**

Repro:

    function f(k: i32) {
      return "a"
      5
    }
    const s: string = f(1)
    print(s)
    // vl check: rc 1, `cannot assign string | i32 to 's' of type string`

#### Mechanism

Not located yet; a prediction. The checker's `tailIsReturn` rule in `check_fn_decl.vl` stops a
dead tail being taken as the implicit return under a DECLARED return type. Return-type
inference still collects that tail as a return witness, so `f` infers `string | i32`. A `match`
value arm whose block returns and then ends in a value does the same, while the value-`if` twin
leaves the dead value out.

#### Ablation

| change from the witness | outcome | needed? |
| --- | --- | --- |
| dead tail `"z"` (same type as the return) | runs | **yes** (the tail's type must differ) |
| `: string` on `f` | runs | **yes** (inference must decide the type) |
| `const s = f(1)`, no annotation on `s` | runs, `s` is `string \| i32` | **yes** (a destination must see the type) |

#### Grading list

The `match` value arm, which is refused while the value-`if` twin runs:

    function f(k: i32): string {
      const s: string = match k {
        1 => {
          return "a"
          5
        }
        _ => "b"
      }
      s
    }
    print(f(1))
    print(f(2))

The un-annotated closure, refused with `expected () => string, got () => string | i32`:

    import { toString } from "std:fmt"
    function mk(n: i32): () => string {
      () => {
        return "c" + n.toString()
        5
      }
    }
    print(mk(3)())
