### D8720 — an inferred return, or a `match` value arm, joins a dead tail after an always-exiting statement into its type

**closed 2026-10-20 · runs, prints `a` · was loud check reject · clause 2 · a block's last statement is dead when ANY statement before it always exits (`blockTailIsDead`, `ast.vl`); `checkBlockNode` and `fnDeclCheckBody` then type no value from it and record the block, and the first emit pass `deadTailDrop` (`emit_rewrite.vl`) drops those statements so every emit tail reader agrees · pin: `tests/cases/inference/dead-tail-not-inferred.vl` · matrices `dead-tail-inferred-return`, `dead-tail-inferred-generic`, `dead-tail-match-arm`, `dead-tail-closure-inferred` · found closing [D1974](D1974.md) · filed 2026-10-20 against master `05e6ced30`**

Repro:

    function f(k: i32) {
      return "a"
      5
    }
    const s: string = f(1)
    print(s)

#### Mechanism

The declared-return path already refused to take a tail after an always-exiting statement as the
implicit return (`tailIsReturn`). Three other positions read a block's tail without asking:

* return-type inference, through `fnTailInferWitness`;
* a `match` arm, a labelled block, or an `else if` branch, through `checkBlockNode`'s
  `blockTailTy`;
* an un-annotated closure, which is a function declaration that infers its return.

Each therefore joined the dead tail into its type, so `f` inferred `string | i32`. Both checker
sites now ask `blockTailIsDead` once the earlier statements are checked, because a `never`
call is marked only by its own check.

The checker alone was not enough. The emitter infers return kinds again from the function's
tail (`computeRetInference`, `fnRetExprOf`). With only the checker fixed, `if k > 0 { return 4 }
return 3 "x"` was check-clean invalid wasm. The checker therefore records each dead-tail block,
and `deadTailDrop` runs before any collection and pops the dead statements from the arena.
A dead function declaration is popped too: a block-local function is visible only after its
declaration, so nothing live can name it.

The rule also reaches one shape that was check-clean invalid wasm on base, not only refused: a
`match` that is the inferred return's tail, whose arm returns and then ends in a value of
another type (`function f<T>(x: T, k: i32) { match k { 1 => { return "a" x } _ => "b" } }`).

Not changed: an inferred function whose every path exits still infers `void`, because
`noteInferredRet` skips `never`. A dead tail after `__trap__()` no longer gives it a value type,
so `function f(k: i32) { __trap__() "x" }` infers `void` exactly as `function g(k: i32) {
__trap__() }` does. On base, `f` inferred `string` from the dead `"x"`.

#### Ablation

| change from the witness | outcome on base | needed? |
| --- | --- | --- |
| dead tail `"z"` (same type as the return) | runs | **yes** (the tail's type must differ) |
| `: string` on `f` | runs | **yes** (inference must decide the type) |
| `const s = f(1)`, no annotation on `s` | runs, `s` is `string \| i32` | **yes** (a destination must see the type) |

#### Grading list

Every one of these now runs.

The `match` value arm, which was refused while the value-`if` twin ran:

    function f(k: i32): string {
      const s: string = match k {
        1 => {
          return "a"
          5
        }
        _ => "b"
      }
      s
    }
    print(f(1))
    print(f(2))

The un-annotated closure, which was refused with `expected () => string, got () => string | i32`:

    import { toString } from "std:fmt"
    function mk(n: i32): () => string {
      () => {
        return "c" + n.toString()
        5
      }
    }
    print(mk(3)())
