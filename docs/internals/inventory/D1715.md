### D1715 — a `K` holder and a `K | null` holder sharing a field name take one anonymous row, so the niche field loses the member set the atom slot needs

**closed 2026-09-06 — an ATOM is not a box, and the box arm's lenient default said it was ·
filed against master `4ea675797` + D1710 · residue of D1710 · residue D1717 · 0 corpus cells**

Repro:

    type K = "a" | "b"
    function plain(): K { return "a" }
    function nul1(): K | null { return "b" }
    function firstHolder() {
      const first = { xs: plain() }
      print(first.xs)
    }
    const v = { xs: nul1() }
    const l = v.xs
    if l != null { print(l) } else { print("none") }
    // vl check: rc 0.  vl run: rc 0, prints b

Was: `emitProgram: literal-union string widening with no members`. Deleting `firstHolder` — a
function nothing calls, sharing nothing with the value but the field NAME — printed `b` at both
seeds, which is what named the ingredient.

#### Mechanism

Probed, not read off the code path. An `emitFail` in `anonValueFitsField` on every pair
involving code 30, with the failing witness as the control, printed one line:

    PROBE fit30 vc=30 sc=16 anonRow=1 vNm=[K] fNm=[K]

**The row it collided with is a code-16 union BOX, not the code-0 atom the row was filed
against.** `anonFieldCode` claims a litunion-typed value as a box before its atom arms are
reached, so the uncalled holder minted a box row; `anonValueFitsField`'s `sc == 16` branch then
refutes only a code-15 struct and a code-16 box whose member sets differ, and **returns `true`
for everything else** — a leniency its own comment says the DECLARED side needs. So the code-30
atom fitted a `(ref)` slot, and the widening that followed had no members to spell it with.

The arm added says the thing the codes already imply: codes 0 and 30 are the interned i32 (30
spending `-1` on the niche's null), a box slot is a `(ref)`, and an anon row cannot hold one in
the other. The declared side keeps its leniency.
