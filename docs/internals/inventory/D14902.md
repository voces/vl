### D14902 — a function's recorded record result reads the checker's type, not the record the checker's build solve stores its value at

**runs today and must keep running · the result-kind shadow grades `g` and `h` `kind agree` (before the hand-back read, `row: stamped >s1;, lowered >s0;`) · open pin: 1 of its 7 functions remains · found tracing D14900's remaining record functions · filed 2026-11-01 against master `9d1d7374a`**

Repro:

    type A = { d: i32 | null }
    type II = { d: i32 }
    function g(v) {
      const w = v
      return w
    }
    function h<T>(v: T): T { return v }
    const c: A = g({ d: 5 })
    print(c.d ?? 0)
    const e: A = h({ d: 6 })
    print(e.d ?? 0)

Want:

    5
    6

#### Mechanism

The checker types the literal `{ d: 5 }` at its own record (`II`, slot 1), and its record solve
builds it at the landing record `A` (slot 0): `recHoleIdentityAt` for the hole identity,
`recPassThroughArg` for the generic one (D8800, D7941). The emitter stores the value at that
build. The instance's recorded result (`fnRecordedRetTy`: `elabResultOf`, the calls' stamps) and
every value stamp in its body still name slot 1, so the row the lowering keys the result on
(slot 0) is read from neither. No elaboration change can move it: the elaboration agrees with the
checker, and a wide twin (`elabWidenedRet`) is not minted for these keys.

The same split, a value typed at one record and stored at the build of another, accounts for 7 of
the 11 "calls disagree or name another row" functions in D14900. Those are `g` and `h` here,
`relay` and `idn` in `generics/hole-instance-typed-at-binding-stored-at-build.vl` (D14426),
`idn` and `idn$1` in `soundness/record-literal-through-identity-ignores-unused-record.vl`, and
`g` in `soundness/returned-binding-built-wider-handed-to-hole-param-runs.vl` (D14741). The close
is for the recorded result to read the build ledger (`recBuildTable`, `recKeptFnDstOf`, the
pass-through adoptions) where it builds the value elsewhere.

The recorded result now reads a call whose callee hands an argument straight back
(`recPassThroughArg`, `recHoleIdentityArg`) at the row that argument is built at: the literal's
adopted stamp, a binding's `recBuildTable` entry, or a nested hand-back's own answer
(`frsCallBuiltAt`). That closes 5 of the 7.

The sixth, `g` in the D14741 file, takes `r2()`, an un-annotated function whose every value is a
call's (`const k = id(mk())`, rebound once). Its callers stamp it at the narrow record while the
call it returns is built at the wider one, so its recorded result, and a call of it, now read the
stamp of its returned calls (`frsValuesBuiltRow`) before the callers' stamps, where each is a call
of a plain function, directly or through identities. An annotated result converts at the return,
and a chain that ends in a literal is built at its instance's row, so neither is read through:
reading `idn({ r: 4 })` that way lowered D8341's `deliver` to invalid wasm.

Open: `idn$1` in the `ignores-unused` file. Its minimal witness keeps the unused record:

    type Col = { r: i32, g: i32, b: i32 }
    type J = { r: i32 | null, g: i32, b: i32 }
    function idn<T>(v: T): T { v }
    const b: J = idn(idn({ r: 5, g: 1, b: 2 }))

The shadow grades the outer `idn` `kind agree` at the literal's own row and the inner `idn$1`
`row: stamped >s0;, lowered >s1;`: the lowering builds the inner instance at `J`, a row neither
the literal's stamp nor the build ledger records. Settling it needs mono's binding for the
nested instance traced, which no checker ledger read can supply.
