### D15957 — a re-pointed generic `let` delivered at a closed function type is typed at its seed's open signature

**loud check reject · `cannot assign ((V) => void)[] to 'fs' of type ((boolean) => void)[]` · clause 2 · the flow-sensitive-read ruling permits it: `[k]` after `k = inner` reads `inner` · the function-valued face of that item, beside [D15956](D15956.md) · filed 2026-11-12 against master `682105de7`**

Repro:

    function inner<U>(u: U) { print(u) }
    function plus<V>(v: V) { print(v + 1) }
    function main() {
      let k = plus
      k = inner
      const fs: ((b: boolean) => void)[] = [k]
      fs[0](true)
    }
    main()
    // vl check: cannot assign ((V) => void)[] to 'fs' of type ((boolean) => void)[]

Want:

    true

#### Mechanism

`k` reads its storage, a clone of the seed `plus`'s signature `(V) => void` carrying the set
of both writes (`elabFnLetTy`). The list literal is typed at it, and `V` is never bound. With
the seed `inner` and no write, the same delivery runs. Under the ruling, the read after the
write is `inner`'s, which the destination's `boolean` closes.

#### Ablation

| ingredient changed | outcome | needed? |
| --- | --- | --- |
| no write (`let k = inner`) | runs, `true` | **yes** |
| `k` delivered bare, `const f: (b: boolean) => void = k` | refused, `cannot assign (V) => void to 'f'` | no, a second spelling |

#### Grading list

The record-field and parameter delivery spellings that D3968's
`error-let-of-generic-written-delivered-*` fixtures pin from the other side.
