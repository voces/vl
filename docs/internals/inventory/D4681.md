### D4681 — a call ending the last `if` arm of a void function is never a tail call

**closed 2026-10-14 · runs — the witness prints `1000000` · the statement ending a void body is marked (`voidTailAt`), an `if` there passes the mark to each arm's last statement, and each arm ends through `emitVoidTailCall` · fixture `tests/cases/functions/tail-call-depth-void-arm-value.vl` · was trap after load (call stack exhausted) · filed 2026-10-14 against master `ed7d31d07` with #3748 applied**

Repro:

    let c = 0
    function down(n: i32): void {
      if n > 0 {
        c = c + 1
        down(n - 1)
      }
    }
    down(1000000)
    print(c)
    // vl check: rc 0.  was, vl run: wasm trap, call stack exhausted in `down`

Want:

    1000000

#### Mechanism

D4655 rewrites a call that is the last instruction of a void body. A call ending an `if` arm
is followed by that `if`'s `else` or `end`, so the check that the call is still the last thing
written never held. The rewrite now also runs at the end of each arm of an `if` that is itself
in tail position, before the `else` or `end` is written; `return_call` leaves the frame, so the
`end` after it is unreachable. The mark passes only through `if` arms, so a call ending a loop
body keeps its `call`.
