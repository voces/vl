### D16142 — a generic call whose result type comes from a call result's un-annotated function passes check at any type, and prints a wrong value

**closed 2026-11-14 — the filed repro is now a loud check reject, the refusal the design owes: `cannot assign i32 to 'q' of type boolean` · was silent wrong output (`vl check` rc 0; its output was `true` where the value is the `i32` `4`) · clause 1 · fixed with [D16099](D16099.md): `R` now closes from the call result's function at the bound parameter types (`holeFnArgDecls`), so the result is `i32` · found closing D16099 · filed 2026-11-14 against master `7cdda1fef` · fixtures `generics/error-call-result-hole-fn-generic-result-misused-closed-param.vl`, `generics/error-call-result-hole-fn-generic-result-misused.vl`**

Repro:

    function inc(a) { return a + 1 }
    function pick1(_c: boolean) { return inc }
    function apr<R>(g: (x: i32) => R): R { return g(3) }
    const q: boolean = apr(pick1(true))
    print(q)
    // vl check: rc 1, the refusal above

#### Mechanism

The argument is a call result whose type is `inc`'s open signature. Binding `g: (x: i32) => R`
against it left `R` an inference hole, so the call's result was open and any destination
accepted it. Where the monomorphizer could build the call (`apr`, whose parameter type is
closed), the `i32` result `4` was stored as a boolean and printed `true`. With `app<T, R>` it
was refused at emit instead (D16099).

#### Ablation

| change | outcome (before the fix) |
| --- | --- |
| witness | runs, prints `true` (wrong) |
| `const q = apr(pick1(true))` | runs, prints `4` |
| `app<T, R>(g: (x: T) => R, v: T)` instead | emit reject (D16099) |
| un-annotated `ap(g, x)` | check reject, `cannot assign i32 to 'q'` |
