#### Mechanism

The checker records the set. In the first check pass `elabFnLetTy` widens `k`'s read type, joining
its initialiser's set `{inner}` and the writes' set `{inner, λ}` (`fnLetSetOf`). `fnTagEtaAgain`
then vetoes the widening (`fnLetVeto`), because a set holding a generic function and a hole lambda
cannot be tagged. That is by design, and from the second pass on `k`'s read type carries `{inner}`
alone. What survives the veto is the set itself, through `elabFnLetMembers`.

S2c read the vetoed read type, found nothing, and walked `a`'s returns and writes itself. Now
`elabReturnedLam` reads what the checker says `a` may return: `recFnValueLeaves(a)`, then
`elabFnLetMembers` of a returned `let`. No walk is left in elaboration.
