Repro:

    function inner<U>(u: U) { print("I"); print(u) }
    function a<T>(x: T) {
      let k = inner
      k = (u) => { print(u) }
      return k
    }
    a(1)(2)
    a(true)(false)
    // prints 2, false

#### Mechanism

`elabFnValNote` and `fnLetReadTy` give a set only to a value the checker reads at an open type. For
`k` in `a`'s body, none of `a`'s return type, the call `a(1)`'s type, the returned `k`'s type or
`fnLetReadTyOf(k)` carries `{inner, λ}`. So S2c's `elabReturnCredits` finds the returned lambda
itself. `elabReturnedLam` visits `a`'s `return` statements, and `elabValueLamIn` reads the
returned `let`'s writes through `cwBindingWrittenValues`. That is a second producer of "which
functions this value may be", beside the checker's fnTag sets.

#### Close

Make the checker record the set of a `let` that is written a lambda inside an open body. Then
read the return value's set in `elabReturnedLam` and delete the walk. The witness must keep
printing `2`, `false`. So must the named set `d15110-returned-lambda`.
