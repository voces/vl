### D3921 — an un-annotated record two levels deep beside a declared one whose inner field is a string refuses to build

**loud emit reject · found in review of #3485 (`rv3485-rv3`: g_map_str; g_map_1lvl, g_map_nc and g_map_recws are the controls) · filed 2026-10-09 against master `09d7de908`**

Repro:

    function h<T>(x: T) { x.x }
    const q: { v: { w: string } } = { v: { w: "s" } }
    print(q.v.w)
    const o = { v: { w: { x: 2 } } }
    print([o].map((e) => h(e.v.w))[0])
    // vl check: rc 0.  vl build: emitProgram: field access receiver is not a struct

Want:

    s
    2

#### Mechanism

Not located. It is the two-level twin of D3898: the un-annotated record's spelling
`{v:{w:{x:i32}}}` resolves to `q`'s row. The suspected cause is that `nestedStructNamesCompat`
accepts when the un-annotated inner spelling has no canonical key, so `{w:{x:i32}}` passes
against `q`'s `{w:string}`.
