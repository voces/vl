### D1701 — the `??` arm for a CALL operand picks its block type from the operand's residual atom, the mistake the IDENT arm beside it no longer makes

**closed 2026-09-06 — the stashed arm takes the same three decisions off the recorded result
type the re-evaluating one does · filed against master `1efd26c50` · D1699's mechanism at the
second operand form · 0 corpus cells**

Repro:

    function mkN(): i32 | null { return null }
    const v = mkN() ?? "x"
    print(v)
    // prints x since the close; before it, `vl check` rc 0 then exit 70,
    // the emitted module failed to validate: type mismatch: expected i32, found (ref $type)

#### Mechanism

`emitCoalesceGo` has two arms for a value-union operand, because a CALL cannot be re-read: the
ident arm re-evaluates the operand in the non-null branch, the call arm stashes the box once
and tests the tag off that single evaluation. D1699 taught the IDENT arm to take its result rep
from the type the checker recorded for the `??` node — a box when the default joins, the wider
scalar when it widens — and the call arm still reads `unionResidualSoloKindOfSet` off the
operand. Binding the call to a name first is the whole difference:
`const a = mkN()` then `a ?? "x"` prints `x`.

#### Ablation

| ingredient removed | outcome | needed? |
| --- | --- | --- |
| the call operand (`const a = mkN()`, then `a ?? "x"`) | runs, prints `x` | **yes** |
| the joining default (`mkN() ?? 7`, which fits) | runs, prints `7` | **yes** |
| the string default, for the widening one (`mkN() ?? 1.5`) | refuses identically | no — any non-fitting default |
| the null value (`return 4`, so the default is dead) | refuses identically | no |

#### Grading list

The four ablation rows and the ident control that must keep running. The two other operand
forms the same arm serves are worth re-grading with it, since the gate widened to cover them
together: an `as?` yielding a box, and an if-expression operand — both name a place that cannot
be re-read, and both reach this arm rather than the ident one. Both were graded with the close
and both run: `(u as? i32) ?? "x"` prints `4`, and
`(if 1 == 1 { mkN() } else { mkP() }) ?? "x"` prints `x`.

The close moves no code: the stashed arm already had the shape, and it now reads the same three
answers off the recorded result type that the re-evaluating arm reads — the union NAME for
whether the result is a box, the coerce target for the default, and the atom kind for the block
type, with `coalWidenUnboxed` carrying the unboxed stash up to a widened result. The two arms
are one lowering over one rep, so a decision taken in one and not the other is the defect.
