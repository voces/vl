### D2065 — a constant-range loop variable is typed `i32`, so the getter amendment's own four-lane example cannot index a lane

**closed 2026-11-14 · runs, prints `10` · the loop-variable half of the owner's ruling (2026-09-22, D-Q2) is built: `rangeVarFits` (`compiler/check_range_var.vl`) delivers a constant-range loop variable, never written in its body, where `i32` does not fit and every value of its interval is an integer literal the destination admits; matrix `range-var-into-literal-union`, fixtures `tests/cases/simd/lane-index-constant-range-loop.vl` and `error-lane-index-range-loop-not-constant.vl`; the getter half, a bounded loop inside a getter, is [D16065](D16065.md) · was loud check reject · a design gap in a ruled-but-unbuilt amendment (#3039), not a regression · the ruling: a constant-range loop variable gets an internal interval type `[lo, hi)`, assignable where every value fits · filed 2026-09-22 against master `31ea77721`, found independently by three lenses of the getters/effects persona review (Swift `p1`, game-perf `p3`, minimalist `p11`/`p13`)**

Repro:

    import { f32x4 } from "std:simd"
    const v = f32x4(1.0, 2.0, 3.0, 4.0)
    let s: f32 = 0.0
    for i in 0 until 4 { s = s + v.lane(i) }
    print(s)
    // was: vl check: argument 1: expected Lane4, got i32

Want:

    10

#### Mechanism

`lane` takes `Lane4 = 0 | 1 | 2 | 3`, and the underlying intrinsic needs a literal index. A
`for i in 0 until 4` loop types `i` as `i32`, so it cannot be passed. The #3039 amendment to
property-access-design.md §D3a-contract gives "a four-lane reduction written as
`for i in 0 until 4`" as its tier-2 example, and that example does not type-check in a getter or
outside one. Two fixes were proposed: type a constant range's variable as the literal union of
the values it visits (so `lane(i)` checks and folds after unrolling), or drop the example.

Built as a delivery rule, not a type kind. The variable stays `i32` everywhere, its rep included, and `assignableExpr` asks `rangeVarFits` only after `assignable` has refused. So every program that checked before checks and compiles to the same bytes. Where it now fits, the interval is `[lo, hi)`: `to` adds one, and a negative step swaps the ends. An empty or wrapped interval fits nothing. Ends and step are literals or `const`s initialised by one, up to four hops. An un-annotated `const j = i` carries the interval, transitively, as a `const` keeps its initialiser's type. A `let j = i` and a `const j: i32 = i` are `i32`.

#### Grading list

The same loop inside a getter once the amendment is built; `for i in 0 to 3`; a range bound by a
