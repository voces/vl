**loud emit reject (`emitProgram: .keys() scratch frame not reserved`, and `.values()` for its twin) · `vl check` rc 0 · 2 of the 11 uses on [D1866](D1866.md)'s grading list · filed 2026-09-07 against master `cf96ae508`**

#### Mechanism

`.keys()` and `.values()` build a fresh list in a 6-slot scratch frame, and `emitMapKeys`
refuses outright when `fnUsesMapKeys` is false. The flag is set by `mfScan`
(`emit_collect.vl`), which asks `exprMap(callee.memObj, fnIx)` — and `mfScan` is a walk of its
own that never pushes an `is` narrowing, so under it the receiver is still the union box and
`exprMap` answers false. `collectLocalsIf` DOES push narrowings, which is why the sibling
questions that walk asks (a local's own rep) are answered under the narrowing and this one is
not: it is one reservation walk short, not a missing capability.

#### Ablation

| ingredient removed | outcome | needed? |
| --- | --- | --- |
| the `is` narrowing — a plainly-typed `{ [string]: i32 }` receiver | runs | **yes** |
| the union — `const v: { [string]: i32 } = mkInner()` | runs | **yes** |
| the INDEX-PATH spelling — the bare name above is already the minimal form | refuses at both | no |
| `.keys()` for `.values()` | refuses with `.values()`'s own message | no |

The third row is what separates this from D1866: that row's mechanism is the re-read of an
index path, and this one refuses at the bound-name spelling too, so it is not the re-read.
