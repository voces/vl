### D7101 — a hole-function list iterated by `for`, or bound with `let`, beside a call through its slot handed a generic at two types, is refused at emit

**loud emit reject · `vl check` rc 0 · clause 2 · CAPABILITY: the same list read for its `.length`, or through a `const` alias, runs `3 4 3 4` ([D6880](D6880.md)) · found closing [D6880](D6880.md) · the same on master `6ca1ebc5c` · filed 2026-10-19 against master `6ca1ebc5c`**

Repro:

    function add(a, b) { return a + b }
    print(add(1, 2))
    print(add(1.5, 2.5))
    function apply2(g) {
      print(g(1, 2))
      print(g(1.5, 2.5))
    }
    const fs = [apply2]
    fs[0](add)
    for f in fs { print(1) }
    // vl check: rc 0.  vl run: emitProgram: cannot take the generic function `add` as a value — a function value carries ONE signature

Want:

    3
    4
    3
    4
    1

#### Mechanism

From the ablation only. The split rewrites a list element per call type only while every read
of the list is one the value-flow question follows exactly; a `for` binding, or a `let` that
may be reassigned, is a read it loses, so the element keeps one function type.
