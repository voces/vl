### D1817 — a DECLARED-but-never-called sibling frame whose nested function captures makes the same-named nested function of the frame that IS called compile at the wrong pin

**check-clean invalid wasm — `the emitted module failed to validate inside \`c$1\`: type
mismatch: expected i32, found f64` · clause 1 · filed 2026-09-06 against master `c30049d6c`,
found writing [D1795](D1795.md)'s fixture — the three-frame version broke while each frame
alone ran**

Repro:

    function o(n) {
      function k(x: i32) { return n }
      function use(p) { return p(1) }
      return use(k)
    }
    function c(n) {
      function k(x: i32) { return x }
      function use(p) { return p(1) }
      return use(k)
    }
    print(c(2))
    print(c(2.5))
    // vl check: rc 0, "Checked 1 file, no errors."
    // vl run:   the emitted module failed to validate inside `c$1`:
    //           type mismatch: expected i32, found f64

#### Mechanism

**Not instrumented.** `o` is never called, so nothing it declares should reach `c`'s
instances; what the two frames share is the nested NAMES `k` and `use`. Every name-keyed
resolver in this family walks `fnParent` from the reader's own frame, and the three that
[D1781](D1781.md), [D1782](D1782.md) and [D1795](D1795.md) each fixed took a flat
first-occurrence-wins map before that — so a fourth reader still keying on the bare name is
where to look, not the pin itself. Probe the decline before changing anything: three
attributions in this family have already died to one.

The row is master's rather than any close's — the witness behaves identically on a seed built
from `origin/master` and on [D1795](D1795.md)'s candidate, byte for byte in the message and
the offset.

| the sibling being CALLED as well | never called in the witness | no |
