#### Mechanism

**THE OFFSET IS THE ONLY HANDLE, AND NOTHING HELD THE OTHER END.** `cli.vl` said so in its
own comment — "POSITIONLESS: the offset the validator names is a wasm offset, and no map
from it back to a VL span exists". The emitter is the one pass that knows both ends, so
`emitCodeSection` now banks, per user function body, its arena `FuncDecl`, its `fnStmts`
position and the `[start, end)` byte range the body occupies. The range is payload-relative
while the code payload is being built and rebased onto the module the moment `wSection`
places it (`wLen() - codePayload.length`), which is the coordinate the validator reports.

Six exports read it back (`emitFnSpanAt` / `Line` / `Col` / `Module` / `NameLen` /
`NameAt`, driver.vl). The lookup is a SCAN, deliberately: it runs at most once per compile
and only on a failure path where the module is already known not to load, so the happy
path pays nothing at all.

**THE ANCHOR IS THE PRE-MONOMORPHIZATION ORIGINAL, AND THAT IS THE WHOLE DEFECT'S SECOND
HALF.** `fnStmts[fe]` at emit time is frequently NOT the parsed declaration — an instance,
a lifted lambda copy and a pruned stub are all minted after parsing, and `addNode` anchors
a node at `P.pos - 1`, which is then the EOF token. The first working version of this row
printed the LAST LINE OF THE FILE for every such function, a position that reads as real.
`monoOrigNode` holds the slot's pristine declaration; the `declNameTok` STAMP is the test,
because only a parsed declaration carries one — so a synthesized body is positionless
rather than confidently wrong.

**EXIT 70, NOT 1.** `vl check` returned 0 to reach the emitter, so an invalid module is the
compiler's fault by construction. 70 is EX_SOFTWARE, the code a compiler TRAP already uses
(#2483), and it is what lets a build script or an editor tell a vl BUG from a bad program
without parsing stderr.

**TWO RENDERERS, ONE LOOKUP.** `vl check --codegen` renders inside the CLI pump, which
`vl build` / `vl run` never enter, so the host has its own `EmitSpans` reader and its own
`engine_fail_offset` beside the compiler's `engineFailOffset` — wasmtime spells the offset
two ways (`(at offset 0x11b)` from `Module::validate`, `at offset 188` from `Module::new`).
Each parser's header names the other. The host reaches the guest at all because
`compile_vl_located` hands the live compiler instance BACK to the caller instead of
dropping it with the store; nothing is read out of it unless the module already failed.
