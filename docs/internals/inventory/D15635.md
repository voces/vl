### D15635 — a generic call whose value `if` holds a literal arm takes its body's result while its instance returns the substituted join's box

**closed 2026-11-10 · runs, prints `6` · was check-clean invalid wasm · clause 1 · found by the step 7 shadow of `exprUnionCall` (`refactor-notes/2026-11-10-step7-generic-call-kept-join.md`) · filed 2026-11-10 against master `3de5b959` · closed by `directGenericNumRet` (check_relate_core.vl) declining a substituted result that is a union, so the call is recorded at the join its instance returns · fixture `tests/cases/generics/kept-join-call-result-in-arithmetic.vl`**

Repro:

    function lit<A, B>(k: i32, a: A, b: B) {
      if k == 0 { return a }
      if k == 1 { b } else { 5 }
    }
    const z: i64 = 9
    print(lit(2, z, z) + 1)
    // vl check: rc 0.  vl run: rc 70, invalid module, `type mismatch: expected i32, found (ref $type)`

Want:

    6

#### Mechanism

The template's result is the return-set join `A | B | i32`, kept apart, and at `(i64, i64)` it
substitutes to `i64 | i32`. The elaboration builds the instance at that substitution
(`elabRetOf`), so the instance returns the box. The call site took `directHoleBodyRet` instead. It
re-checks the body at the call's types, where the literal adopts `i64`, and `directGenericNumRet`
let that `i64` replace the substituted result because both hold numbers. The call was recorded
`i64` around a call that returns the box. The fix makes `directGenericNumRet` decline when the
substituted result is a union. The rule stays for its own case: arithmetic over a type parameter,
`x / 2.0` at `i32`.

#### Ablation

| ingredient changed | outcome | needed? |
| --- | --- | --- |
| `print(lit(2, z, z))`, the box printed | runs, `5` | **yes** (a consumer that reads a number) |
| `const q: i64 = lit(2, z, z)` | the same invalid wasm | no |
| `if k == 1 { return b }` then `5` | runs, `6` | **yes** (the value `if`) |
| no `return a` (the `if` alone) | runs, `6` | **yes** |
| `function lit<A>(k: i32, a: A, b: A)` | the same invalid wasm | no |
| `b: i64` declared | runs, `6` | **yes** (both arms from type parameters) |
| `const z: f64 = 9.5` | the same invalid wasm | no |
| `lit(2, 7, 8)` at `i32` | runs, `6` | **yes** (a wider binding) |

#### Grading list

Non-generic `lit2(k: i32, a: i64, b: i64)` with the same body still types `i64`, which is the
non-generic join, not the instance's. `numeric-join-held-back-through-a-wrapper.vl` keeps its output.
