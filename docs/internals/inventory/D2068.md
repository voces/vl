### D2068 — a binding scoped to an inner block of a closure (or of its maker) is treated as bound for the whole frame, because every capture question is asked by NAME within a frame

**closed 2026-09-22 — the witness prints `inner` then `6` · was a loud emit reject (`emitProgram: identifier is not a parameter, local, or global`, `vl check` rc 0, clause 2), and at a shadow of a different type check-clean invalid wasm or a wrong value (clause 1) · filed 2026-09-22 against master `9ec3b19be`, found reviewing #3042 (D2090) · fixture `tests/cases/closures/capture-block-scoped-shadow.vl`**

Repro:

    function outer() {
      let y = 5
      const g = () => {
        { const y = "in" + "ner"; print(y) }
        print(y + 1)
      }

#### Mechanism

Four readers disagreed with the checker's block scoping. `capScan` grew its bound set
monotonically, so an inner-block `y` hid the outer `y` from the capture list for the rest of
the lambda (the reject above). Where the outer `y` was read BEFORE the block it was captured,
and then the emitter's capture-first read (`emitCapturedRead` runs before the scope stack) and
every name-keyed capture classifier answered the block-local `y` with the env field: a wrong
value at a shadow of the same type, invalid wasm at a different one (`if y > 0 { const y = 2.5;
print(y) }` → `expected f64, found i32`). In the MAKER, `parentLetOf` is first-wins over the
whole frame, so a block-local `y` before the captured `let y`, a closure inside a shadowing
block, or a block-local shadowing a module global typed (or located) the env field from the
wrong binding. And `captureBoxRewrite` vetoed boxing whenever any nested function declared the
name, so a closure assigning the outer `y` after a shadow was refused. The fix scopes
`capScan` and the boxing scan by block, and adds `shadowRespell` (`emit_rewrite.vl`), the
first emit pass. It respells a binding only where a capture question would be ambiguous: one
a function nested in its own frame reads, while another binding of the name is visible or
earlier in the frame, gets a unique `name$sN`; one that shadows an enclosing frame's binding
or a module name gets one spelling shared by the frame. A name some call spells as a method
(`v.name()`) is never respelled, since the checker may resolve that call to the local and a
member name is not an identifier the pass follows. `capScan` also gained the `Spread` arm it
lacked (`[...xs]` inside a closure never captured `xs`), and a module-scope block's
captured-and-assigned `let` is now boxed like a function's.
