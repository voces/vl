### D3917 — a function whose tail calls a record field's void function, with no caller reading its result, builds invalid wasm

**closed 2026-10-09 by lane SC · runs · was check-clean invalid wasm · found in review of #3484 (`rv3484/x`: lib7 + x12_lib_min, lib8 + x13_lib_inline) · filed 2026-10-09 against master `09d7de908` · pins: `tests/cases/closures/void-field-function-called-at-tail-of-exported-function.vl`**

Repro:

    function q<U>(y: U) { print(y) }
    export function useLib(k: i32) {
      const r: { f: (v: i32) => void } = { f: q }
      r.f(k)
    }
    useLib(1)
    // vl check: rc 0.  vl run: the emitted module failed to validate inside `useLib`: expected i32 but nothing on stack

Want:

    1

#### Mechanism

Neither the generic nor the import is an ingredient: the same program with a concrete lambda in
the field fails, and so does an un-exported function that nothing calls. The function had no
return annotation, so `computeVoidFns` asked whether its tail is a value. `stmtIsTailValue`'s
D980 arm claimed every call of a record field's function as a value, void or not, and the
function was typed `-> i32` with nothing on the stack. A function some caller calls for effect
escaped through `fnPosResultUnconsumed`; an exported or uncalled one does not.

Closed: the D980 arm declines when the checker typed the call `void`. A field whose function
returns a value is still the result (D980's own case).
