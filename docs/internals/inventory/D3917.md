### D3917 — a generic function stored as a record field inside an exported non-generic function builds invalid wasm

**check-clean invalid wasm · found in review of #3484 (`rv3484/x`: lib7 + x12_lib_min, lib8 + x13_lib_inline) · filed 2026-10-09 against master `09d7de908`**

Repro:

    function q<U>(y: U) { print(y) }
    export function useLib(k: i32) {
      const r: { f: (v: i32) => void } = { f: q }
      r.f(k)
    }
    useLib(1)
    // vl check: rc 0.  vl run: the emitted module failed to validate inside `useLib`: expected i32 but nothing on stack

Want:

    1

#### Mechanism

Not located. The review found it through an imported module, but the ingredient is `export`: the
same function in one module runs without it. A binding (`const h: (v: i32) => void = q`) or a list
element in the same exported function runs, so the gap is the record-field delivery. A generic
record alias (`R<i32>`, lib7 with x12) builds the same invalid module.

#### Ablation

| ingredient changed | outcome on master | needed? |
| --- | --- | --- |
| `export` removed | runs | **yes** |
| a binding instead of the field | runs | **yes** |
| a list element instead of the field | runs | **yes** |
| imported from another module (lib8 + x13) | invalid wasm, the same | no |
