### D13462 — an `if` of hole functions handed to a parameter called at two types, inside a call that is not its own statement, is refused at emit

**closed 2026-10-25 · runs, prints `a` and `1` · fixed: the plan runs the choice before the statement holding the call wherever each enclosing expression runs the call once after only pure reads, or literals and function names for a choice that calls (`fsChoiceStmtOf`, `fsRunsChildFirst`, fn_split.vl), and binds a binding read ahead of a calling choice first (`fsAheadHoists` in `fsChoiceArgStmt`) · pins: `tests/cases/generics/hole-fn-choice-nested-positions.vl` · was loud emit reject, clause 2 · `monomorphize: unsupported argument type for `f` in a call to `both`` · found closing [D13360](D13360.md) · filed 2026-10-25 against master `ad209bcf6`**

Repro:

    function both(f) {
      print(f("a"))
      return f(1)
    }
    function inner(s) { return s }
    function ask(s) { return s }
    function g(c: boolean) {
      print(both(if c { inner } else { ask }))
    }
    g(true)
    // vl check: rc 0.  vl run: emitProgram: monomorphize: unsupported argument type for `f` in a call to `both`

Want:

    a
    1

#### Mechanism

From the code path, not ablated to a line. D13360's plan runs the choice once before the
statement holding the call (`fsChoiceArgStmt`, fn_split.vl), and admits a statement only when
it is the call itself, a `let` whose initialiser is the call, or a `return` of the call. A call
nested in another expression, here `print`'s argument, has no such statement, so the plan
declines and the call reaches the monomorphizer with one function value for two slots.
