### D17092 — a `null` handed to a `Z | null` parameter binds `Z` at `never`, and the instance's annotated `Z | null` result is emitted at `i32`

Repro:

      if z != null { return z }
      return null
    }

    // vl check: rc 0.  vl run: invalid module inside `h`, type mismatch: expected i32, found nullref

Want:

    true

#### Mechanism

A `null` handed to `Z | null` binds `Z` at `never`, so the instance reads its parameter and its
annotated result as `never | null`. The rep tree gave a nullable of `never` no discipline
(`nulDisciplineOfTy`), so the result's annotation had no rep and `vtKindOfType` fell back to
`i32`, while the parameter, `return null` and every caller held the `nullref` the call's recorded
`null` result names. `rtOfNullable` now reads `never | null` as the `null` leaf, as it reads an
unfilled hole. The same instance's `z is null` fell past the null-instance arm, which asked for
the `null` type only, to the `noUnion` emit refusal; that arm takes `never | null` too.

#### Grading list

- The un-narrowed `return z`, a result bound to a `const`, and a second instance at `i32` beside
  the `null` one: all invalid wasm before, all run.
- `if z is null { return null }`: a loud emit reject before (`is` test but no union type
  declared), runs.
- `const n = null; h(n)` and an un-annotated result already ran (D3305's `null` pin) and still do.
- A non-generic `never | null` parameter stays refused at check: `never` is legal only as a result.
