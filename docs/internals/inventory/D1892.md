### D1892 — `[]` and `[]=` on an un-annotated parameter pass `vl check` and refuse in the EMITTER, naming an array the program does not contain

**loud emit reject · 8 of 123 `op_index` pairs, every one at the `argument` position · filed 2026-09-07 against master `f3cac5fe5`**

Repro:

    type Box = new { x: i32 }
    function "[]"(self: Box, i: i32): i32 { return self.x + i }
    function mkval(): Box {
      const r: Box = { x: 3 }
      return r
    }
    function take(p) { print(p[4]) }
    take(mkval())
    // vl check: rc 0.
    // vl run: 8:14: emitProgram: index access but array type not collected

#### Mechanism

A bracket on an un-annotated parameter is accepted by the checker, which has no arm that
refuses it, and reaches the emitter's index lowering. That lowering asks the collected LIST
types for the receiver's element type; the receiver is a struct with an index operator and no
list type was collected for it, so the read finds nothing and refuses. `vl check` returning 0
is what makes this a clause-2 violation by construction: the program is either legal and must
compile, or illegal and the checker owed the diagnosis.

The refusal's own sentence is wrong twice over — it names an ARRAY for a program containing
none, and the operator declaration two lines above is exactly the thing it should have found.

**The message is not stable, which is why it must not define the family.** The same program
with an unrelated `const bag = [1]` elsewhere in the module refuses with
`emitProgram: indexed-assignment target is not an array` instead; the setter spelling refuses
with `emitProgram: indexed assignment but list type not collected`. Three sentences, one
mechanism — the ablation below is what separates it from [D1891](D1891.md), which refuses at
CHECK.

#### Ablation

| ingredient removed | outcome | needed? |
| --- | --- | --- |
| the parameter is un-annotated (`take(p: Box)`) | runs, prints `7` | **yes** |
| the operator (`idxBox(p, 4)`, same body) | runs, prints `7` | **yes** |
| the bracket is a READ (`p[4] = 5`, the setter) | refuses, different sentence | no |
| the parameter is generic (`take<T>(p: T)`) | refuses identically | no |
| the `new` brand on `Box` | still refuses | no |
| an unrelated `const bag = [1]` in the module | refuses, third sentence | no |

#### Grading list

Both brackets, both faces: `print(p[4])` and `p[4] = 5`, each with the parameter annotated
(runs today, must keep running) and un-annotated. The three sentences above must collapse to
one outcome, not to one sentence — a close that only narrows the message leaves the program
refusing. [D1891](D1891.md) is the check-side twin and moves neither of these cells.
