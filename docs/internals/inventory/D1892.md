### D1892 — `[]` and `[]=` on an un-annotated parameter pass `vl check` and refuse in the EMITTER, naming an array the program does not contain

**closed 2026-09-08 — the witness prints `7` · was a loud emit reject, 8 of 123 `op_index` pairs, every one at the `argument` position · clause 2 · filed 2026-09-07 against master `f3cac5fe5` · 36 of 36 hole cells (GET/SET x 9 positions x 2 forms) move EMIT to `runs`, 0 lost · the half-declared read/write is [D1932](D1932.md) · fixture `tests/cases/operators/index-overload-through-hole-parameter.vl`**

Repro:

    type Box = new { x: i32 }
    function "[]"(self: Box, i: i32): i32 { return self.x + i }
    function mkval(): Box {
      const r: Box = { x: 3 }
      return r
    }
    function take(p) { print(p[4]) }
    take(mkval())
    // vl check: rc 0.
    // vl run: 8:14: emitProgram: index access but array type not collected

#### Mechanism

Measured at the emit site, printing what the emitter receives for the hole witness:

    emitProgram: index access but array type not collected PROBE recvTy=[] opIdxFnAtNode=[]

Two empties tell the whole story. `recvTy=[]` — the receiver `p`'s solved type renders no
list name, because it is a nominal object, not a list. `opIdxFnAtNode=[]` — nothing was
banked at the site. The checker's dispatch rewrite (`dispatchRewrite`, `emit_rewrite.vl`)
turns `p[4]` into a call to the resolved `"[]"` function only when the checker BANKED it
(`opIdxBank`), and the un-annotated parameter's receiver was still a hole when its body was
checked, so `opIdxFnFor` had no receiver type and banked nothing. The pin (`validateMemCstrs`)
then re-validated the constraint against the solved `Box` — that is why `vl check` passes —
but validated without banking. So the emitter meets a raw `Index` over a receiver with no
list rep and falls through to `emitFail`.

The annotated twin banks during the body check and runs, which is exactly the shape a fixture
that annotates cannot see. Closed by banking the resolved operator at the pin, on the site the
constraint already carries: the GET constraint's index node, and a new SET constraint keyed to
the assignment node (the write is a separate lowering and needs the setter).

**The message is not the family.** The same program with an unrelated `const bag = [1]`
refuses with `emitProgram: indexed-assignment target is not an array`; the setter with
`emitProgram: indexed assignment but list type not collected`. Three sentences, one
mechanism — three delivery positions of the one gap, all closed together. It refuses at EMIT,
where [D1891](D1891.md)'s hole-operand sibling refuses at CHECK.
