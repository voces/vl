### D10023 — two un-annotated maps each filled with one generic through its own parameter and read at different types refuse at check

**loud check reject · `set: expected (f64) => f64, got (i32) => i32 (the body of … at the call's argument types)` · clause 2 · CAPABILITY: without `m.set("k", inc)` the program prints `1.5`, `2` · found closing [D9651](D9651.md) · present on master `00cbfe00b` · filed 2026-10-22 against master `00cbfe00b`**

Repro:

    function id<T>(x: T): T { x }
    function inc(x: i32): i32 { x + 1 }
    function fill(mm) { mm.set("k", id) }
    function fillAt(mm) { mm.set("a", id) }
    const m = Map()
    fill(m)
    m.set("k", inc)
    const m4 = Map()
    fillAt(m4)
    const r4 = m4.get("a")
    if r4 != null { print(r4(1.5)) }
    const r = m.get("k")
    if r != null { print(r(2)) }
    // vl run: type error: set: expected (f64) => f64, got (i32) => i32 (the body of `r4` at the call's argument types)

Want:

    1.5
    3

#### Mechanism

Not traced. The refusal is the checker's: once a write of `inc` fixes `m`'s value type, the
generic `id` stored through `fill` and through `fillAt` is typed as one, so the `f64` read of
`m4` and the `i32` value of `m` disagree, though the two maps and the two fill functions share
nothing but `id`. The same refusal follows with `fill` used for both maps.

#### Ablation

| ingredient removed | outcome | needed? |
| --- | --- | --- |
| `m.set("k", inc)` | runs, `1.5`, `2` | **yes** |
| the second map (`m4`, `fillAt`) | runs, `3`, since [D9651](D9651.md) | **yes** |
