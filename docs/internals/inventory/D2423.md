### D2423 — an un-annotated record literal takes a declared row with the same field names when its field is a record, a record list or a different list

**closed 2026-09-25 — the witness runs and prints `1.5` then `2` · was check-clean invalid wasm, clause 1 · the family of [D2208](D2208.md) and [D2215](D2215.md) (a declared shape captures an anonymous literal) · found grading D2382, filed 2026-09-25 against master `a277bf7b0` · fixture `tests/cases/objects/declared-row-field-layout-no-capture.vl`**

#### Mechanism

`structIndexOfObjCtxGo` matches an object literal to a row by field names, then refutes per
field. Against an anonymous row every code mismatch refutes (`anonValueFitsField`), but against
a DECLARED row a differing code was lenient, on the ground that a declared field's code can
differ through adoption — refuted only between a string list and a named-heap slot (D1704). So
`{ k: xs }` with `xs: f64[]` took the `{ k: i32[] }` annotation's row and stored an `f64` list into
an `i32`-list slot. `declRowFieldFits` now also refutes a differing code between a named-heap slot (a record, a
record list, their `| null`) and a self-contained one, and between a record and a record list. It
also refutes a code mismatch between two scalar or string lists, except where an array literal
widens into the row (integer elements into an `f64`, `i64`, `f32` or `u8` list, float into `f32`).
The caller asks it on every code mismatch against a row the literal's own destination does not
name. The scalar and scalar-against-list captures are [D2435](D2435.md) and [D2436](D2436.md).

The widening exception is load-bearing, and the review of #3147 measured it. A first cut refused
every scalar-list mismatch, so a literal built at a destination the checker had never stamped lost
its row. That broke a local reassignment inside a function (`let v: R = …; v = { k: [1, 2] }`)
and an inferred return delivered to `R`, both of which run on master. The reassignment's
destination is now stamped (`recordListFieldWidenAdopt`, with `structIndexOfObjCtxGo` building a
stamped literal at its row). The inferred return has no destination at the literal and keeps the
old leniency, with its decoy failure filed as [D2437](D2437.md).

Grid of a literal field against a declared or annotated field of the same name, 13 cells: an
`f64[]` against `i32[]` and back, in and out of a function; a literal `[1.5]` against `i32[]` and
`[7]` against `f64[]`; `["s"]` against `i32[]`; a record list against `i32[]` both ways and
against `f64[]`; a record against `i32`, `string` and a record list. **0 of 13 ran before** (7
invalid wasm, 6 loud emit rejects: `field access receiver is not a struct`, `nested struct fields
are not supported`), **12 of 13 after**. The one left, the integer literal `[7]` against a
declared `f64[]`, is the widening exception above and [D2437](D2437.md)'s un-annotated face. The destination-adoption controls (`R = { k: f64[] }`
fed `[2]`, `{ k: P[] }` fed `[]`, `{ k: f64 }` fed `2`, a literal returned as `R`) ran before and
after.
