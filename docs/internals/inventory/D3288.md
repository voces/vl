### D3288 — a non-null write to a name a closure writes narrows it in the checker, but the emitter reads its cell as the box

**closed 2026-09-29 (`asgStripTyOf` banks the checker's null strip at the assignment, and `pushPostGuardNarrow` pushes it onto the cell's read key when `captureBoxRewrite` made the target a cell; `cboxRenameJoins` does the same for an `if` join) · was check-clean invalid wasm, clause 1 · filed against master `296e1141d` · fixture `tests/cases/closures/capture-cell-write-narrows.vl`**

#### Mechanism

A name some closure writes is rewritten to a shared cell, so `x = 0` becomes `x[0] = 0` and
every read `x[0]`. The emitter's straight-line null strip lives in the bare-name arm of
`pushPostGuardNarrow`, which the rewritten target no longer reaches, and the index arm pushed
only a retirement's re-narrow; the checker still typed the reads after the write at `i32`, so
they lowered the box as a scalar. The index arm now pushes the checker's banked strip onto the
cell key when the target is a cell `captureBoxRewrite` made, and join rows naming a boxed binding
are renamed to the cell key the same way.
