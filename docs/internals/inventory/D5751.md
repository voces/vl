### D5751 — an un-annotated generic handed to a const lambda's un-annotated parameter is not instanced at the call the lambda makes

**loud emit reject · `vl check` rc 0 · clause 2 · found closing [D5612](D5612.md) · filed 2026-10-17 against master `5aa033e26`**

Repro:

    function neg(a) { return 0 - a }
    const lap = (g, x) => g(x)
    print(lap(neg, 4))
    // vl check: rc 0.  vl run: emitProgram: cannot take the generic function `neg` as a value — a function value carries ONE signature, and parameter `a` is un-annotated (it would default to i32). No call site pins `neg`, so there is no inferred signature to adopt — annotate the parameter, or call `neg` directly by name

Want:

    -4

#### Mechanism

From the ablation only. [D5612](D5612.md)'s close instances a generic at the one pin past a call
to a hole FUNCTION. A const lambda's parameter is not a function hole: `lap` is one closure
value, not instanced per call, so `monoHoleGenFnPin` never runs for `lap(neg, 4)` and nothing
else pins `neg`.
