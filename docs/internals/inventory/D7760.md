### D7760 — a forward tail call to a function with a bare `return` reads the pending hoist, and a binding of the caller's result is check-clean invalid wasm

**closed 2026-10-20 · now a loud check reject (`cannot bind the void result of 'x'`) · was check-clean invalid wasm · clause 1 · the hoist leaves a bare-`return` un-annotated function pending (`-2`) while its body re-declares it `: void` as a fresh `TyFunc`, so a caller checked first never sees the void · pins: `tests/cases/inference/bare-return-callee-read-before-recheck.vl`, `tests/cases/inference/bare-return-callee-operand.vl` · present on master `b56512057`**

Repro:

    function a(n: i32) {
      const x = b(n)
      print(x)
    }
    function b(n: i32) {
      g(n)
    }
    function g(n: i32) {
      if n > 5 { return }
      print(n)
    }
    a(1)
    // vl check: rc 0.  vl run: invalid module ... type mismatch: expected i32 but nothing on stack (rc 70)

Want:

    [ERROR]: cannot bind the void result of 'x' — a void function returns no value

#### Mechanism

`progHoistRetTy` hoisted an un-annotated function as the pending `-2` unless no caller reads
its result. `fnDeclRetMode` then checks a body holding a bare `return` as `: void`, and that
branch declares a NEW `TyFunc` instead of patching the hoisted one. Demand inference
(`checkCallOnFuncTy`) checks `g` and re-reads the hoisted type: still `-2`, so `TY_ERR`. On
master `inferReturnsPrePass` infers `b` from that `TY_ERR`, and pass 2 checks `a` before it
re-checks `b`, so `a` binds an error type without a diagnostic. With the pre-pass off the same
read surfaces as `cannot infer a return type` on the caller: diderven `src/game.vl`'s
`playerHits`, `sprite`, `drawShots` and `drawLineup` are each that shape. The hoist now types a
bare-`return` body `void` up front, the type its body is checked as.

Master outcome, then the outcome with the fix. Every ingredient is needed:

| no `a`, a global `const x = b(1)` | refuses | refuses |

"refuses" is `cannot bind the void result of 'x'`. As an operand (`b(n) + 1` in `a`) master
reported only `cannot infer a return type for 'a'`. It now also names
`operator '+' is not defined for void and i32`, as the `g`-first spelling always did.
