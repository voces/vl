### D2522 — the value binding of a `for k, v in m` walk over a ref-list-valued map carries no ref-list row

**closed 2026-09-25 — the filed repro RUNS and prints `4` · was a loud emit reject, clause 2 · pre-existing on master `ca544493e` · found by [D2511](D2511.md)'s grading grid · filed 2026-09-25 against master `ca544493e`**

Repro:

    type P = { x: i32 }
    const m: {[string]: P[]} = Map()
    m["a"] = [{ x: 4 }]
    for k, v in m { print(v[0].x) }
    // vl check: rc 0.  vl build: emitProgram: a ref list's element row does not resolve

#### Mechanism

`forInPairStructIdx`, the companion slot the second name is bound with, answered only a struct
value, so a `reflist` value was bound with slot -1 and every read of it found no row. It now
answers the inner ref-list slot (`mvValInnerRlSlot`) for a ref-list value and the inner map
shape for a nested-map value ([D2515](D2515.md)), the slots `.values()` already bound.

#### Ablation

| ingredient removed | outcome on `ca544493e` | needed? |
| --- | --- | --- |
| `for v in m.values()` instead of the pair walk | prints `4` | **yes** — the pair walk |
| `{[string]: string[]}` (a scalar-backed list value) | prints | **yes** — a ref-list value |
| `{[string]: i32[][]}` | still refuses | no |
| `{[string]: P[] \| null}`, narrowed | still refuses | no |
| `{[string]: P[][]}`, read `v[0][0].x` | loud `field access receiver is not a struct` | no — another face |
