### D17620 — a function parameter called at two signatures, returned from a closure and handed on, meets a call key the tag decision's arrow facts lack

**loud check reject · clause 2 · `internal: an instance call through a function set the check decided from the arrow facts meets a key those facts lacked` · found by COV-CALL's Q58 sweep of captured bundle parameters · owner COV-CALL · parked until after I8 (coordinator, 2026-11-25) · filed 2026-11-25 against master `4fbb6097`**

Repro:

    function take(b) { print(b(7)) }
    function ret(f) {
      print(f(2.5))
      const h = () => f
      take(h())
    }
    ret((a) => a + 1)
    // vl check: rc 1 (the emit refusal, reported by check).  vl run: emit error

Want:

    3.5
    8

#### Mechanism

`emit_sections.vl` refuses an instance call whose function set the check decided from the arrow
facts when it meets a key those facts did not record. `f` is called at `(f64)` in `ret` and at
`(i32)` in `take`, so it is a bundle of two instances. Handed straight to `take`, it runs. Read back
out of a closure's result (`h()`), the value reaching `take`'s `b(7)` carries no key the arrow facts
banked for that set.

Traced 2026-11-25 by SOUND. The refusal fires in `ftFactsCoverInstances` (check_fn_tag.vl): the
instance call `b(7)` goes through the lambda's set, and no arrow fact stands for that call and set,
because `arrowParamDeclOf` (check_arrow_facts.vl) follows `const` copies to a parameter but not a
call `h()` of a closure that returns it. The split is upstream, in `ret`'s call row: the direct and
captured spellings record `f` as `(_) => _` carrying the set, while `take(h())` records it as
`(f64) => f64`, closed at its first call and carrying none, the same type id `take(h())`'s row
records, so `h()` reads `f`'s hole as first bound rather than the hole. The bundle signature walk
(`bundleMemberFits` over `cwOccWalk`), the arrow facts and the instance keys (`ikIdTy`, `idSetOf`)
each stop at `h()`; a close changes all three and the hole binding of `h()`'s result.

Warning: teaching `arrowParamDeclOf` alone to read through `h()` makes `vl check` pass and `vl run`
build invalid wasm inside `take` (a `(ref struct)` parameter where the set's i32 tag arrives), a
clause-1 regression from today's loud reject.

#### Ablation

| spelling | outcome |
| --- | --- |
| `take(h())`, `h = () => f` | refused |
| `const g = h(); take(g)` | refused |
| `take(f)` | runs, `3.5` then `8` |
| `f` handed through a closure's capture (`const k = () => take(f); k()`) | runs |
