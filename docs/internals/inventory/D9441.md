#### Mechanism

A list literal holding `id` runs because `monoFlowReads` rewrites each call through an
element to the generic's name and marks the stored values inert. A pushed value was not one
of the literal's values: the use plan refused the `.push` use, and `monoPinListElems`, seeing
two pins on the element, either left the element open (no interned shape) or refused with the
list message. With `[id]` and a push, the checker wraps the pushed generic in a closed
adapter function, which is a value of its own, not a slot read.
