### D2401 — a module global narrowed inside a function survives a call to a top-level function that writes it

**loads then traps · clause 1 · filed 2026-09-25 against master `2304ece42`, found surveying the
forms of [D2390](D2390.md) · open**

Repro:

    let g: boolean | f64 = 1.5
    function setG() { g = true }
    function f(): f64 {
      if g is f64 {
        setG()
        return g as f64
      }
      0.0
    }
    print(f())
    // vl check: rc 0.  vl run: wasm trap: cast failure

#### Mechanism

D2390's rule reads the closures of the ROOT the narrowing sits in: the enclosing top-level
function, or the whole module for top-level code. `setG` is another top-level function, outside
`f`'s root, so no writer of `g` is seen and the call keeps the narrowing. The path channel has a
free-variable write summary for exactly this (`fnWriteFreePaths`), but it records path keys only
and skips a bare name. The fix is that summary answering for a bare global, asked by
`callMayWrite`'s bare-name leg for a call to a known declaration.

#### Ablation

| ingredient removed | outcome | needed? |
| --- | --- | --- |
| the call `setG()` | runs, prints `1.5` | **yes** |
| the member written (`g = 2.5`) | runs, prints `2.5` | **yes** |
| the enclosing function (the guard at top level) | loud check reject | **yes** — the module root sees `setG` |
| the top-level writer (a local `const setG = () => …`) | loud check reject | **yes** — D2390 |

#### Grading list

A global written by a top-level function two calls down (`f` calls `h` calls `setG`); a global
written through an imported function in another module; a module-level `const k = () => { v =
true }` writer called from inside a top-level `f` that narrows the global `v` (the writer is in
the module's root, the narrowing in `f`'s, so neither sees the other — review of #3145).
