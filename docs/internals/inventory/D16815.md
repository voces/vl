#### Mechanism

The call `v(3)` is keyed by the slot fact of `v`'s binding (`elabSlotTyAt` → `eplHolderTy`). Both
bindings hold the one lambda node the maker returns, and the class leaf asked the lambda's instance
at the call's parameters through `eplFrameMember`, which accepts an instance under any parent whose
parameters match: for `x`'s binding it took the one under `v`'s maker instance, so the slot read
`(i32) => f64`, a key no lifted function interns. The lookup now takes the instance under the
binding's own maker call (`eplHolderCallMember`).
