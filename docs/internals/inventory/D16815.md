### D16815 — a maker's two call bindings at two pins, the wider pin called first or the lambda bound to a local before it is returned, give the later call's closure an open parameter

#### Mechanism

Traced for the witness. The call `v(3)` is keyed by the slot fact of `v`'s binding
(`elabSlotTyAt` → `eplHolderTy`), which reads `(i32) => f64`: the `i32` parameter `v(3)` passes
and the `f64` result of `x`'s instance. Both bindings hold the one lambda node the maker returns,
so they share one function-value class, which closes at one signature drawn from both calls;
`(i32) => f64` is interned by no lifted function, and the call is refused. Each maker call builds
a fresh closure at its own pins, so each call's binding wants a class of its own. The order
matters because the class takes the first call's result.
