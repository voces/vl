### D3278 — a function type's parameter list could not break across lines, named or not

**closed — runs, prints `1` · was a loud check reject raised at the PARSE stage, `(parse error)`, `expected an identifier but found end of line` · found by the #3300 review, where named signatures made long lists common · fixture `tests/cases/functions/fn-type-multiline-params.vl`**

Repro:

    type GuestCall = (
      fn: i32,
      rcx: i64,
    ) => i32
    function h(a: i32, b: i64) { a }
    const g: GuestCall = h
    print(g(1, 2 as i64))

Want:

    1

#### Mechanism

`parseTypeAtom`'s parenthesized arm read its comma list with no newline skip, while
`parseParamList` skips a newline after `(`, after each `,` and before `)`. The arm now skips at
the same three places. It was the same with unnamed parameters, `(\n  i32,\n  i64,\n) => i32`,
and in a parameter annotation, `cb: (i32,\n  i64) => i32`.
