### D4995 — a `for` over an instance's `is Q[]` arm list that a push grew types its variable at the receiver's record

**closed 2026-10-15 — now prints `hi` then `1` · was loud emit reject, clause 2 · the iterating face of [D4962](D4962.md) with [D4934](D4934.md)'s push · pins: `tests/cases/generics/is-list-arm-push-for.vl` · filed 2026-10-15 against master `9ce1d13a2`**

Repro:

    type P = { x: i32 }
    type Q = { y: string }
    function g<V>(a: V[]) {
      const q: V[] = []
      if q is Q[] {
        q.push({ y: "hi" })
        for e in q { print(e.y) }
      }
      print(a.length)
    }
    const ps: P[] = [{ x: 1 }]
    g(ps)
    // emitProgram: unknown struct field in field access

Want:

    hi
    1

#### Mechanism

Not ablated. The arm's empty `Q[]` is not iterated when nothing grows it, but a pushing arm's
list does iterate, and `emitForInStmt` types the loop variable from the instance's own element,
`P`, so `e.y` names no field of it. The scalar spelling (`is string[]` over an `i32[]`) runs.

#### Close

`refListElemNameOfExpr` answers the arm's read from `listFitArmTyOf` ([D4993](D4993.md)), so
`emitForInStmt` types the loop variable at the arm's `Q`, and a primitive arm (`is f64[]`
over a `P[]`, pushed and iterated) binds at `f64`.
