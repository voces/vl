### D6250 — a hole parameter called on another hole parameter's result, and at a second instance, is emitted at one

**closed 2026-10-18 by lane L3 · runs, prints `2 2` · was check-clean invalid wasm · clause 1 · the checker types a hole call whose argument is another hole call's result at the instance that call produced (`holeCallNodeTy`), so the second parameter is listed at both instances and split · pins: `tests/cases/functions/hole-fn-result-into-other-hole-two-instances.vl` (swapped order, `const`, `let`, annotated, three deep, summed, indexed, three hole parameters, two-argument holes, `string` and `boolean` arguments) · found closing [D6210](D6210.md) · filed 2026-10-18 against master `4090ad9df`**

Repro:

    function wrap(a) { return [a] }
    function pair(a) { return [a, a] }
    function lap(g, h, x) {
      print(h(g(x)).length)
      print(h(x).length)
      return 0
    }
    lap(wrap, pair, 4)
    // vl check: rc 0.  vl run: the emitted module failed to validate inside `lap`

Want:

    2
    2

#### Mechanism

From the ablation only. `pair` is needed at `i32[]` for `h(g(x))` and at `i32` for `h(x)`.
The checker lists the instances a hole's calls ask for, and marks the parameter for a split when
there are two. An argument that is ANOTHER hole parameter's result has no type there yet, so
`h` is listed at one instance and never marked. [D6210](D6210.md) is the same with one
parameter, whose own result the list does resolve.
