### D6332 — a string handed to an un-annotated parameter the body pushes onto passes check

**loud emit reject · `vl check` rc 0 · clause 2 · found closing [D6301](D6301.md) · filed 2026-10-18 against master `5e3ba8429` on lane L3's `l3-d6250` base `f30a3c7ce`**

Repro:

    function pu(a) {
      a.push(1)
      return 0
    }
    print(pu("s"))
    // vl check: rc 0.  vl run: emitProgram: .push receiver is not a list

#### Mechanism

From the ablation only. A pushed hole is an array demand, and the call refuses an argument
that cannot meet it (`pu(5)`: `expected an array, got i32`). A string can be indexed, so it
passes that test, but it cannot be pushed onto. The checker owes the refusal the annotated
spelling gets; a fix should not make the program run.

#### Ablation

| spelling | outcome | needed? |
| --- | --- | --- |
| the witness | loud emit reject | — |
| `function pu(a: string)` | loud check reject, `no method '.push' on string` | **yes** |
| `pu(5)` | loud check reject, `argument 1: expected an array, got i32` | **yes** |
| `const s = "s"`, `pu(s)` | loud emit reject, the same | no |

#### Grading list

The `const s` spelling, and `tests/cases/functions/hole-fn-to-unread-param-default.vl`, whose
pushing body is tried at `i32[]` before `string` because of this row.
