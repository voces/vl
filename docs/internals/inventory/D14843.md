### D14843 — a hole parameter read through a binding by a function nested in its owner, handed through a set at two instances, refuses at emit

**loud emit reject · clause 2 · `vl check` rc 0, then `emitProgram: call to unknown function` with the split plan on and off · present on master `3e36a3c26` before #5733, and kept so by #5733, whose alias forward declines a read in a nested function (D14842's rule) · closes when a function nested in a generic instance is instanced per encloser, or its creation sites key (node, instance) (`docs/internals/closure-at-delivery-2026-11.md`) · pin: `tests/cases/closures/error-forwarded-hole-param-alias-read-in-nested-fn.vl` · filed 2026-11-01 against master `3e36a3c26`**

Repro:

    function add(a, b) { return a + b }
    function mul(a, b) { return a * b }
    function apply2(g) {
      print(g(1, 2))
      print(g(1.5, 2.5))
    }
    function run(h) {
      let hh = h
      function inner() {
        for f in [apply2] { f(hh) }
      }
      inner()
    }
    run(add)
    run(mul)
    // vl check: rc 0.  vl run: emit error, call to unknown function

Want:

    3
    4
    2
    3.75

#### Mechanism

`inner` has one body for both of `run`'s instances, so neither the parameter `h` nor its copy `hh` can be handed on as one instance's set id there (D14842). The elaboration marks `{add}` and `{mul}` partial, and the list call has no closure signature to fall back to, since `apply2` calls `g` at two types.

#### Ablation

| ingredient removed | outcome | needed? |
| --- | --- | --- |
| the nested function (the list call in `run`'s body) | still refuses (two instances through `hh`) | no, the alias alone refuses too |
| the alias (`f(h)` in `inner`) | runs, `3 4 2 3.75` (D14842's pin) | **yes** |
| the second instance (`run(mul)`) | still refuses | no |
