### D14843 — a hole parameter read through a binding by a function nested in its owner, handed through a set at two instances, refuses at emit

**closed · runs, prints `3`, `4`, `2`, `3.75` · was loud emit reject, clause 2, `a generic function taken as a value reaches no call that fixes its type` · closed in emit_elab.vl: a nested function reading a copy of its encloser's parameter is built per encloser instance as one reading the parameter is (`elabReadsParamOf`), and the copy's read there forwards the set as at that instance (`elabAliasSetFwd`) · a copy also called in the nested function, and one read two functions deep, still refuse · fixture `closures/forwarded-hole-param-alias-read-in-nested-fn.vl` (was this row's refusal pin) · filed 2026-11-01 against master `3e36a3c26`**

Repro:

    function add(a, b) { return a + b }
    function mul(a, b) { return a * b }
    function apply2(g) {
      print(g(1, 2))
      print(g(1.5, 2.5))
    }
    function run(h) {
      let hh = h
      function inner() {
        for f in [apply2] { f(hh) }
      }
      inner()
    }
    run(add)
    run(mul)
    // vl check: rc 0.  vl run: 3, 4, 2, 3.75

Want:

    3
    4
    2
    3.75

#### Mechanism

`inner` has one body for both of `run`'s instances, so neither the parameter `h` nor its copy `hh` can be handed on as one instance's set id there (D14842). The elaboration marks `{add}` and `{mul}` partial, and the list call has no closure signature to fall back to, since `apply2` calls `g` at two types.
