### D14514 — a function's list of literals delivered at two readonly lists that store a field differently is refused, and the hints named copies that do not run

**closed · now a loud check reject, kept as filed, `{r: null}[] is not readonly Circle[]: a container never widens implicitly` at each call · DESIGN: a readonly list is covariant only over elements that need no conversion, and a record is shared, so a record element that stores a field differently does not widen into `readonly` either (a declared `Small[]` into `readonly Circle[]` refuses the same way) · filed 2026-10-27 as clause 2 against master `4e04cd6de`, re-graded the same day · closed by fixing the hints: the mutable spelling no longer offers `readonly Circle[]` (`readonlyFixOf` declines an element that stores a field differently), and both spellings name the field copy `.map((x): Circle => { r: x.r })`, built from the destination element's field list (`listCopyMapText`/`recCopyLitText`, check_diag_text.vl) where they named `.map((x): Circle => x)`, which refuses · fixtures `arrays/error-record-list-widen-field-copy-hint.vl`, `arrays/error-declared-record-list-widen-field-copy-hint.vl`, `arrays/record-list-field-copy-widen.vl`**

Repro:

    type Circle = { r: i32 | null }
    type Tag = { r: string | null }
    function sink(x: readonly Circle[]) { print(x.length) }
    function sink2(x: readonly Tag[]) { print(x[0].r == null) }
    function mkcall() {
      const cc = [{ r: null }]
      return cc
    }
    sink(mkcall())
    sink2(mkcall())
    print(1)

#### Mechanism

D14510's close refuses, in the list-result arm of a call delivery, a function whose calls land
its one list on two storages (`recSitesLandApart`, `recRefuseAtOwnRow`, check_fit_rules.vl).
The row was filed as a capability gap on the reading that a `readonly` destination widens any
list. It widens only a list whose elements are stored the same way: a view shares its records,
and a `Circle` read through the view would have to see an `i32 | null` field the source stores
as a placeholder. Serving it needs a copy, which is what the hint now names.

#### Grading list

The binding spelling shares the refusal: `const a = mkcall()`, `sink(a)`, `const b = mkcall()`,
`sink2(b)` refuses at both bindings with D8301's sentence. With one delivery only (`sink(a)` and
no `sink2`) it runs and prints `1`. The copy the hint names, `sink(mkcall().map((x): Circle => {
r: x.r }))` with its `Tag` twin, prints `1`, `true`, `1`.
