### D15605 — a field read off a union of records whose members store it at different value atoms, through an un-annotated parameter, has no value box

**closed 2026-11-10, runs and prints `4` · was loud emit reject · `vl check` rc 0 · `field access receiver is not a struct` · clause 2 · D15571's mixed-field neighbour · the field join each instance closes the read to now registers its box (`registerSharedReadUnion`, emit_obj_lit_fits.vl, over `elabNodeInstTys`), and the shared read names that box at the instance's type (`armFieldUnionName`, emit_classify.vl) · fixture `unions/shared-mixed-field-read-through-hole-param.vl` · the top-level call of a function returning the read, filed and closed as [D15628](D15628.md) · filed 2026-11-09 against master `de73ab0c`**

Repro:

    type K = { h: i32 }
    type J = { h: string, z: i32 }
    const k: K = { h: 4 }
    const u: K | J = k
    function take(a) { print(a.h) }
    take(u)
    // vl check: rc 0.  vl run: emitProgram: field access receiver is not a struct

Want:

    4

#### Mechanism

The shared-field plan boxes the read as the field union `i32 | string`, and
`sharedFieldPlanDispatchable` declined because the `i32` value box was never minted
(`vbHeapIdxOfKind(0)` is -1). The union is the read's type only in the instance pinned at
`K | J`; the template node holds the parameter's hole, so `registerSharedReadUnion`, which reads
the template's type, never registered it, and `armFieldUnionName` named no box for the read
because its gate asked the template's type too. Annotated `a: K | J`, the template node carries
the union. Fixed by registering the union at each instance's type and gating the name on the
instance's type.
