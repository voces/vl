### D16049 — a shared field read is refused when the records store the field as nullable refs of different types

**closed 2026-11-14 — each member boxes its nullable list ref under the list's tag, or as the null box, into the read's box · was loud emit reject, `emitProgram: field access receiver is not a struct` · clause 2 · found grading D15882's neighbours (lane F) · filed 2026-11-14 against master `2509180f3`**

Repro:

    type A = { v: i32[] | null }
    type B = { v: string[] | null }
    const b: B = { v: null }
    const u: A | B = b
    print(u.v == null)

Want:

    true

#### Mechanism

Not traced. The read is typed `i32[] | string[] | null`, a union box over two list arms. Each
record stores its field as its own nullable list ref, so the shared-field dispatch would have to
box each member's ref under its arm's tag; no plan does, and the read falls to the plain struct
read.

#### Closed by

`sharedFieldArmsBoxable` admits a member storing a nullable list ref (`sharedFieldArmNulListKind`,
the list's box tag), and `emitSharedFieldNulListBox` boxes it: a null ref as the null-tagged box,
any other ref under its list's tag. Graded by `matrix/shared-nullable-field-list-*.matrix.vl`. The
nullable-record sibling is D16130.
