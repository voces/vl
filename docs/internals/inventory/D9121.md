### D9121 — a `const` bound to an `if` choosing two generic functions, delivered to a generic parameter or `.map` at two types, refuses

**loud emit reject · `vl check` rc 0 · clause 2 · CAPABILITY: the alias `const h = kg` delivered at the same two types runs, and so does the binding delivered at one type ([D9080](D9080.md)) · found closing [D9080](D9080.md) · present on master `7736fb65b` · filed 2026-10-21 against master `7736fb65b`**

Repro:

    function idg<T>(t: T): T { return t }
    function kg<T>(t: T): T { return t + t }
    function app<T>(g: (x: T) => T, v: T): T { return g(v) }
    const c = [1].length > 0
    const h = if c { kg } else { idg }
    print(app(h, 3))
    print(app(h, "x"))
    // vl run: emitProgram: a binding of an `if` choosing generic functions is delivered at two function types — annotate the binding

#### Mechanism

The binding holds one closure value, built where the first delivery pins its arms
(`monoCoerceChoiceBinding`, emit_mono.vl); a delivery at another function type is refused
rather than emitted against that value. Running it needs the binding to hold one value per
delivered type, or the choice to be re-made at each read, as an alias of one generic is. On
master both deliveries refused with ``monomorphize: unsupported argument type for `g` in a call to `app` ``.
