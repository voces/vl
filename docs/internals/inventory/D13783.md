### D13783 — a `for` over a list literal of un-annotated functions whose results differ is refused at emit, not at check

**loud emit reject · `'.length' on a receiver the emitter cannot classify as a list, string, map or set` · `vl check` rc 0 · clause 2 · open · with the list bound first, `const fs = [twice, lenOf]` and `for g in fs`, the checker refuses (`cannot store 'lenOf' in an element of 'fs'`), so the checker owes this spelling the same refusal · found closing [D13740](D13740.md) · present on master `46e8112f6` · filed 2026-10-25 against master `46e8112f6`**

Repro:

    function twice(s) { return s + s }
    function lenOf(s) { return s.length }
    for g in [twice, lenOf] {
      print(g("abc"))
    }
    // vl check: rc 0.  vl run: '.length' on a receiver the emitter cannot classify as a list, string, map or set

#### Mechanism

Not ablated to a line. The slot judge (`holeSlotJudge`, check_relate_core.vl) finds a `for`
element's functions through the binding the loop iterates, and a list literal has none, so the
elements are never judged against each other.
