### D13783 — a `for` over a list literal of un-annotated functions whose results differ is refused at emit, not at check

**closed 2026-10-27 · runs, prints `abcabc` then `3` · was loud emit reject, clause 2, `'.length' on a receiver the emitter cannot classify as a list, string, map or set` · fixed by ef-1a: the inline literal holds the set `{twice, lenOf}` tagged, so `g("abc")` calls each element's own member at its own tuple (D3975 (A)); the bound spelling's check refusal is the gap, filed as [D14435](D14435.md) · pinned by `tests/cases/closures/for-over-inline-fn-list-results-differ.vl` · found closing [D13740](D13740.md) · filed 2026-10-25 against master `46e8112f6`**

Repro:

    function twice(s) { return s + s }
    function lenOf(s) { return s.length }
    for g in [twice, lenOf] {
      print(g("abc"))
    }
    // vl run: abcabc, 3

#### Mechanism

Not ablated to a line. The slot judge (`holeSlotJudge`, check_relate_core.vl) finds a `for`
element's functions through the binding the loop iterates, and a list literal has none, so the
elements are never judged against each other.
