### D5050 — a complement `else` read of an inferred record-or-scalar list union gets the box when a `for` walks the same binding

**closed 2026-10-16 — now prints `s` twice · was check-clean invalid wasm, clause 1 · with the `for`, the declared set is spelled by shape (`{x:i32}[] | string[]`), so subtracting the spelling `P[]` cleared no member and the `else` kept the whole box; the complement now subtracts the tested TYPE when its spelling names no member (`msSubTy`) · found closing D2891 (its field position) · filed 2026-10-16 against master `03c935872` · pin: `tests/cases/unions/inferred-record-list-union-complement-read.vl`**

Repro:

    type P = { x: i32 }
    function ws(t: P, b: boolean) {
      if b { return [t] }
      ["s"]
    }
    const so = ws({ x: 15 }, false)
    if so is P[] { print(so[0].x) } else { print(so[0]) }
    for v in so {
      if v is P { print(v.x) } else { print(v) }
    }
    // vl check: rc 0.  vl run: invalid module — expected (ref null $type) `string list`, found (ref $type) `union box`

Want:

    s
    s

#### Mechanism

Localised by the close (see the status line). The `else` arm reads `so` as the `string[]` the complement of
`P[]` leaves, but the read is handed the union box itself. Either the complement read or the
`for` alone runs, so the `for` changes what the narrowed read is handed. The same program read
through a record field (`const so = { f: ws(…) }`, `so.f`) fails the same way.

#### Ablation

| ingredient removed | outcome | needed? |
| --- | --- | --- |
| the `for` over `so` | runs | **yes** |
| the `else` of the `for` body (`if v is P { print(v.x) }` alone) | runs | **yes** |
| the complement (`if so is string[] { print(so[0]) }` instead) | runs | **yes** |
| the inference (`: P[] \| string[]` written on `ws`) | runs | **yes** |
| the string arm (`[2]`, so `P[] \| i32[]`) | still invalid wasm | no |

#### Grading list

The field position (`const so = { f: ws({ x: 15 }, false), k: "k" }` read as `so.f`), and the
`i32[]` arm's twin.
