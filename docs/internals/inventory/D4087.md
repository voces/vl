### D4087 — a `match` arm naming a record type does not test value fit, as `is` does

**loud check reject · clause 2 · found reviewing the D4058 close (#3549) · filed 2026-10-11 against master `5a9535c91`**

Repro:

    type A = { x: i32 }
    type B = { x: 1 | 2 }
    type C = { z: string }
    function g(r: A | C): string {
      match r {
        B => "B"
        C => "C"
        _ => "A-other"
      }
    }
    print(g({ x: 1 }))
    print(g({ x: 7 }))
    print(g({ z: "q" }))
    // vl check: rc 1, "match pattern `B` is not a member of A | C"

Want:

    B
    A-other
    C

#### Mechanism

D3885 (A) makes `is` a value-fit test, and `if r is B` over `r: A | C` is accepted by the
checker (it then fails at emit, D4089). A `match` arm naming a type still asks whether the
type is a MEMBER of the scrutinee's union, so a contained record is refused, and a containing
record (`A` over `B | C`) is refused and leaves the match non-exhaustive. The match arm and
`is` should answer the same question.

#### Ablation

| variant | outcome |
| --- | --- |
| scrutinee `A \| C`, arm `B` (the repro) | check reject |
| scrutinee `B \| C`, arm `A` | check reject, plus non-exhaustive (missing `B`) |
| scrutinee `A` alone, arm `B` | check reject, "match scrutinee must be a union or an integer" |
| scrutinee `A \| C`, arms `A`, `C` | runs |

#### Grading list

Each ablation row, and exhaustiveness: an arm naming a containing record covers every member
it contains.
