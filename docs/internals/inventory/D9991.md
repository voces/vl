### D9991 — a Set as a generic record's type argument builds its literal as a second record, because the canon rep key told a Set from its boolean map

**closed · runs, prints `false` · was check-clean invalid wasm, clause 1 · closed by keying a Set as its `{[K]: boolean}` map under the CANON rep key (`repKeyGo`, `repIdGo`, emit_rep.vl), so the record row typed from the instantiation's name is the row the literal's adopted type finds; the elem and mv keys still tell the two apart · fixture `sets/set-as-generic-record-argument.vl` · found closing [D9920](D9920.md), where `Box<Set<i32>>` went from the spelling gate's refusal to the same invalid wasm · present on master `0f0face1e` · filed 2026-10-22 against master `0f0face1e`**

Repro:

    type Box<T> = { v: T | null }
    function f<T>(b: Box<T>) { print(b.v == null) }
    const s: Set<string> = Set()
    const bs: Box<Set<string>> = { v: s }
    f(bs)
    // vl check: rc 0.  vl run (master): the emitted module failed to validate inside the module's top-level code

Want:

    false

#### Mechanism

The canon name rewrite erases a Set's flavour (`Set<string>` is spelled `{[string]: boolean}`),
so `Box<Set<string>>`'s struct row is typed as a box of a plain map. The literal's adopted type
keeps the Set flag, and `repRowOfTyStruct` compared canon keys that put a Set and its map twin
under different tags, so it missed the row and built the literal as a fresh anonymous record
whose field is not nullable. The store then validated against neither.

Outcomes on master `0f0face1e`; every row runs after the close.

| the string key, for `i32` (after D9920's close) | the same invalid wasm | no |
