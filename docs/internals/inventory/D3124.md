### D3124 — a second `<Z>` instance at a nullable record pin calls the first instance's field function

**check-clean silently wrong · clause 1 · open · the `nullable__gen__*__b_i` and `listel__gen__*__b_i` cells of the #3276 review's D3110 grid · the same on master `cc890c9f4` · filed 2026-09-28 against master `cc890c9f4`**

Repro:

    function F<Z>(z: Z | null) { if z != null { print(z.f()) } }
    const r0 = { f: () => true }
    const q0: { f: () => boolean } | null = r0
    F(q0)
    const r1 = { f: () => 7 }
    const q1: { f: () => i32 } | null = r1
    F(q1)
    // vl check: rc 0.  vl run: prints true, then true

Want:

    true
    7

#### Mechanism

Not localised past the ablation. The two records share one anonymous row, and the second
instance's field call dispatches to the closure the first literal of that row holds. D3110's
fix resolves the closure by the receiver's own function type, but here the receiver is the
narrowed `z` of a `Z | null` pin, whose type is not read through that path.

#### Ablation

| the hole `function F(z)` | prints `true`, `true` | no |
| one instance only | prints `true` | **yes** (the second instance) |
