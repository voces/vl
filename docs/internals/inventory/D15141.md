### D15141 — a bundle parameter handed to a call through a `let` copy of a function, or from inside a closure, gets no record without the split plan

**closed 2026-11-03 — the repro runs without the split plan too. Was: runs today and must keep running, leaning on the split plan, which builds `lap` once per signature · filed 2026-11-03 against master `38b42426`**

Repro:

    function keep(g) { print(g(7)) }
    function lap(f) {
      print(f(2.5))
      const kk = keep
      kk(f)
    }
    function go(k: i32) { lap((a) => a + k) }
    go(1)

Want:

    3.5
    8

#### Mechanism

`lap` calls `f` at two signatures, so without the split plan `f` must hold a record. The
record was declined for the whole of `lap` when `monoParamReadOtherThanCalled` found a read of
`f` other than a call through it or a hand to a named function in `lap`'s own body: a call
through `kk`, a `const` copy of `keep`, was such a read, and so was `keep(f)` inside a closure.
Now both are hands. The elaboration records the key of the parameter each hand reads, walking
`ekParent` to the instance that declares a captured one (`elabCallHandOwner`), and mono pins
the callee at the record pinned for that key (`monoBundleKeyTys`). A call through the copy
hands the record, or the member at a one-closure parameter's type (`bundleSlotTakesRecord`).

#### Ablation

| ingredient removed (plan off) | outcome | needed? |
| --- | --- | --- |
| `lap`'s call at `2.5` (one signature) | runs | **yes** |
| the call through `kk` (`keep(f)` directly) | runs | **yes** |
| `keep` hands `g` on (it only calls it) | still refuses | no |
| the capture of `k` (a top-level `lap((a) => a + 1)`) | check reject, `a` not inferred | **yes** |

#### Grading list

The same hand from inside a closure, which refuses with the plan off for the same reason:
`function lap(f) { print(f(2.5)); const h = () => keep(f); h() }`, printing `3.5` then `8`.
Without the hand (`const h = () => print(f(7))`) it runs.
