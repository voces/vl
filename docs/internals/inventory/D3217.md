### D3217 — a guarded call of an `f64` function through a hole at a null pin is check-clean invalid wasm

**closed · the numeric classifiers read a hole instance's value call through a field at its pin, as `exprString` does since D3203, and an `i64`/`f32` result is keyed like the others · fixture `tests/cases/generics/hole-guarded-numeric-call-with-no-closure-of-its-signature.vl` · was check-clean invalid wasm · clause 1 · pre-existing, the same on master `94670f728` · found by the #3289 review (`rv3289-q8x4/p/pre1.vl`) · filed and closed 2026-09-29 against master `94670f728`**

Repro:

    type H = { g: () => f64 }
    type R = { v: i32, f: H | null }
    function F(z) {
      const g = z.f
      if g != null { print(g.g()) } else { print("none") }
    }
    const r: R = { v: 1, f: null }
    F(r)

Want:

    none

#### Mechanism

The call `g.g()` is keyed at `() => f64` from the pin (D3117's keying of a hole callee), but
`exprIsF64` read the result off a field callee only through `fieldClosureFeOfRecv`, which finds
no closure literal in the field, so `print` took the i32 sink over an f64. It is
D3203's mechanism in the f64 classifier. `exprIsF64`, `exprIsI64` and `exprIsF32` now ask the
instance's pin for a field callee (and the last two for a name callee), and `cloCallSigKey`
keys an `i64` or `f32` result as well. The review's B2 is the same arm: a guarded
`z.f()` over `(() => f64) | null` at a null pin was a loud emit reject on master and became
invalid wasm under D3197's narrowing.

#### Ablation

| ingredient changed | outcome on master | needed? |
| --- | --- | --- |
| a `() => f64` closure elsewhere in the program | the same invalid wasm | no |
| `() => i32` | prints `none` | **yes** (a non-i32 result) |
| `if z.f != null { print(z.f.g()) }`, no binding | a loud emit reject (no signature) | **yes** (a binding) |
