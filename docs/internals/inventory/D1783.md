#### Mechanism

`fieldCodeOfSpelling` splits a literal-union field two ways, and says so in its own comment:
*an inline member set is the string slot* (code 3, recording its member set, since code 3 is
layout-shared with a plain string field) *and a registered alias is the atom* (code 0,
recording its union name). The ANONYMOUS mint — `anonFieldCode` with its companion
`anonFieldElemName` — had only the alias half, added by [D1757](D1757.md). An inline member
set therefore fell past it to the spellability gate `anonTySpellable`, whose partition is
`TyPrim`/`TyObj`/`TyFunc`/`TyArray` and which declines a `TyUnion`, so `anonFieldCode`
returned -1 and the literal was refused a row at all.

Losing the row, not the field, is why the refusal wore three different sentences: at module
scope the missing row surfaces as `ref valtype with no interned shape`, inside a frame as
`object literal but no struct type declared`, and in map-value position as
`unsupported map value type`. One mechanism, three messages — the ablation is what groups them.

The close is the missing half, arm for arm: a code-3 rung in `anonFieldCode` under
`tyIsLitUnion` (below D1757's `tyIsLitUnionAlias` rung, which is strictly narrower, so the two
stay disjoint) and a code-3 arm in `anonFieldElemName` recording the rendered member set,
self-gating on `nameIsInlineLitUnion` so a plain string field still answers "".

#### Ablation

**The filed ablation was wrong on one row and is corrected here**: the LIST ELEMENT source is
NOT needed. Three sources refuse — an element, a binding fed by one, and a call — and only a
bare member literal runs, because its type is a `TyLit` and never a union at all.

| ingredient removed | outcome | needed? |
| --- | --- | --- |
| the INLINE spelling (a `type Color` alias at both ends) | ran `green` | **yes** |
| the ANONYMOUS holder (`const w: { f: "red" \| "green" } = …`, or a declared `type Box`) | ran `green` | **yes** |
| the literal union (`srcArr: string[]`, or an `i32[]`) | ran `green` | **yes** |
| the list-element source, for a BINDING of the same type | same refusal | no |
| the list-element source, for a CALL returning the union | same refusal | no |
| the list-element source, for a bare member literal (`{ f: "green" }`) | ran `green` | **yes, in this one form** |
| the binding hop (`print(w.f)` directly) | same refusal | no |
| module scope (the same literal inside a function body) | `object literal but no struct type declared` | no — same mechanism |
| a second field beside it (`{ f: srcArr[0], n: 1 }`) | same refusal | no |
