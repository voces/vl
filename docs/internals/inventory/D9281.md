#### Why a check refusal

The program never says what the element returns. `a[0](4)` names the parameter type, not the
result, and nothing else is in the list. `function g(a) { return a[0](4) }` then
`const r: string = g([])` passed `vl check` because the result was a hole. The language's
answer for an element type no use names is `const e = []`'s refusal, and this is that refusal
reached through a parameter. It names a contract (annotate the list), not a mechanism. The
neighbouring spellings run:
`const e: ((x: i32) => i32)[] = []` then `early(e)` prints `0`, and so does
`early(a: ((x: i32) => i32)[])` with `early([])`. An empty list whose element the body only
indexes for arithmetic (`a[0] + 1`) or only measures (`a.length`) still runs, since those uses
name or need no element type. The refusal also covers the element called inside a `.map`
callback and a list relayed through a second un-annotated parameter.

#### Mechanism

Not traced at filing. The literal `[]` holds no function, so nothing pins the element the body calls,
and the instance of `early` is built at an element with no function type.
