#### Mechanism

A bare `m[k]` is `V | null` by construction, so both map positions add an outer `!= null` to
unwrap the read before the template's own proof runs. `map_value_place` already made that
guard conditional, and its docstring states why: a template whose TEST is itself a null test
needs no second one, because with the cell narrowed the inner test is `i32 != null`, which the
checker refuses — "and the position would score its own shape rather than the compiler's".
`map_value` never got that rule, so it did exactly that, in two ways.

Eleven cells are the case the sibling's docstring names. The generated program was

    const __mv = __m["k"]
    if __mv != null {
      const v = __mv          // narrowed: i32
      if v != null { … }      // check refuses: cannot compare i32 with null
    }

The twelfth is the one the docstring does not name, and is worse: when the template's VALUE is
`null`, the outer guard can never be entered at all, so the MISS branch is unreachable while
the template's WANT is exactly that branch. That cell grades `WRONG (no output)` on every
seed, so no `--before`/`--after` run can clear it — a permanent false positive in the
instrument that decides whether a discovery sweep has found anything.

The witness above is what the fixed position generates for that template. The row is a
REFUTATION PIN: it must keep running, so a change that reintroduces the unconditional guard
flips it.
