### D3896 — a nested generic returned through an enclosing `(T) => void` annotation is called at the enclosing pin's type without its demand being checked

**check-clean silently wrong · found in review of #3468 (`rv3468d-witnesses/a_ret_bad.vl`) · filed 2026-10-09 against master `995c7d82e`**

Repro:

    function a<T>(x: T): (T) => void {
      function b<U>(y: U) { const n: i32 = y; print(n + 1) }
      return b
    }
    a(true)(true)
    // vl check: rc 0.  vl run: prints 2

Want:

    vl check: cannot assign boolean to 'n' of type i32

#### Mechanism

Not located. `b` escapes as a value through the return, whose annotation binds `U` to `a`'s `T`.
No call of `b` binds it, so its demand is checked neither at a call nor at `a(true)`, the same
gap a call through a lambda parameter's hole leaves, here at a return. The same on master and after
D3853.
