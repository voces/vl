### D15296 — a list of records holding a list of an un-annotated function, built inside a generic function, is refused at emit when a call reaches that function through the list

**loud emit reject · `emitProgram: ref valtype with no interned shape` · clause 2 · open · the same body with the stored function never called runs since [D15293](D15293.md) · found closing [D15293](D15293.md) · filed 2026-11-04 against master `b19b5895`**

Repro:

    function inc0(a) { return a + 1 }
    function mk<T>(x: T) { return [{ fs: [inc0], x: x }] }
    const r = mk(5)
    print(r[0].fs[0](4))

Want:

    5

#### Mechanism

A call through a function value makes the stored set TAGGED, and a tagged set's value is its member's id: `emitExpr` emits `inc0` as `fnTagLeafId` whatever type mono records on it, and the call dispatches on that id, as the non-generic twin's `fs` (an `i32` id list) shows. So the closed type the elaboration stamps ([D15293](D15293.md), `elabHeldListFacts`) has to keep the tagged set's own type, not a plain `(i32) => i32`, which lays the row out as a closure list the id elements cannot fill (invalid wasm; the producer declines the called set for that reason). With the tagged type kept, three readers have to follow the stamp and each was measured to need it: the stored list and record literals (stamped too, and built at their stamp by `monoHeldValueAt`), a field the template shares with every instance copy (`x: x` reads the template's own parameter node, so the anonymous row takes that field's code from the record's recorded type), and the instance's list result, whose ref-list slot is interned only for an element type with no type variable (`fnRetRefListDemand` and its join) while a tagged leaf keeps its members' holes. Making that last gate tag-aware is not enough on its own: the witness still refuses with the same message, so at least one further emitter gate reads a tagged record as open, of 107 that test `tyHasTyVar`. The three readers are on branch `claude/d15296-held-stamp-reader`. The emit side's test for "closed but for a tagged set's own holes" belongs in one reader of the elaboration's `elabTyClosed`, not a local copy, and `fnRetRefListDemand` and `fnRetRefListRowJoin` take only that swap for their `!tyHasTyVar` test.
