### D15296 — a list of records holding a list of an un-annotated function, built inside a generic function, is refused at emit when a call reaches that function through the list

**closed · runs, prints `5` · was loud emit reject, `emitProgram: ref valtype with no interned shape`, clause 2 · found closing [D15293](D15293.md) · filed 2026-11-04 against master `b19b5895` · fixed 2026-11-08: the elaboration's closed held type keeps each function leaf's set from the identity type (`elabHeldKeepSets`, in `elabHeldValTy` and `elabHeldListFacts`), so the record's `fs` row is the tagged set's id list the values are built at, and mono's generic-instance `holdsLit` guard in `monoRetFnListTy` is deleted**

Repro:

    function inc0(a) { return a + 1 }
    function mk<T>(x: T) { return [{ fs: [inc0], x: x }] }
    const r = mk(5)
    print(r[0].fs[0](4))

Want:

    5

#### Mechanism

A call through a function value makes the stored set TAGGED, and a tagged set's value is its member's id: `emitExpr` emits `inc0` as `fnTagLeafId`, a list of ids. The identity type of the literal (`{fs: ((_) => _)[], x: T}[]`) carries that set on its `fs` leaf. `elabHeldValTy` closed it to `{fs: ((i32) => i32)[], x: i32}[]` and dropped the set, so the record row coded `fs` as a closure ref-list keyed `((i32)=>i32)`, which resolved to the outer list's slot (`$0 = {fs: ref $4, x: i32}`, `$4` a list of `$0`): invalid wasm with mono's guard removed, and no row at all with it. The closed type now takes each unset function leaf's set from the identity type. `elabHeldListFacts` no longer skips a called set, so a literal bound to a `const` and returned is stamped the same way.
