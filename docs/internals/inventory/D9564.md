### D9564 — `??` with a default of another type over the call of an un-annotated parameter whose instance cannot be null is refused at emit

**loud emit reject · clause 2 · CAPABILITY: an annotated `f: () => i32` runs, and `x ?? "q"` over an un-annotated parameter bound at `i32` runs · found closing [D9522](D9522.md) · present on master `95725e040` · filed 2026-10-22 against master `95725e040`**

Repro:

    function take(f) {
      print(f() ?? "q")
    }
    take(() => 3)
    // vl check: rc 0.  vl run: emitProgram: `??` over this nullable value is not supported yet — narrow it first, e.g. `if v != null { … }`

Want:

    3

#### Mechanism

Partly traced. The instance's dead-default fold (`coalRetypedDead`, emit_classify.vl) takes an
operand at the `??`'s own pin or at a numeric literal type repped as it. Here the operand is
`i32` and the `??` joins it with the `string` default, so the fold declines; folding needs the
`i32` delivered into the join's union box. The `string` instance with an `i32` default
(`take(() => "y")` beside `take(() => 3)`, `?? 0`) refuses the same way.

| --- | --- | --- |
