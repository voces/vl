### D9564 — `??` with a default of another type over the call of an un-annotated parameter whose instance cannot be null is refused at emit

**closed · runs, prints `3` · was loud emit reject, `vl check` rc 0, clause 2 · CAPABILITY: an annotated `f: () => i32` runs, and `x ?? "q"` over an un-annotated parameter bound at `i32` runs · found closing [D9522](D9522.md) · filed 2026-10-22 against master `95725e040` · closed by lowering a dead `??` whose pin differs from the operand's type as an `if` recorded at the pin (`coalRetypedDeadJoinIf`, wasmEmit.vl), which delivers the `i32` into the `i32 | string` box · fixture `literal-unions/coalesce-hole-call-litunion-join.vl` · closed with [D9561](D9561.md)**

Repro:

    function take(f) {
      print(f() ?? "q")
    }
    take(() => 3)
    // vl check: rc 0.  vl run: emitProgram: `??` over this nullable value is not supported yet — narrow it first, e.g. `if v != null { … }`

Want:

    3

#### Mechanism

The instance's dead-default fold (`coalRetypedDead`, emit_classify.vl) takes an operand at the
`??`'s own pin or at a numeric literal type repped as it. Here the operand is `i32` and the
`??` joins it with the `string` default, so the fold declined. The same root as
[D9562](D9562.md): `coalRetypedDeadJoinIf` builds `if true { l } else { d }` at the pin, and
the `if`-join lowering boxes the `i32` into the join's union. The `string` instance with an
`i32` default (`take(() => "y")` beside `take(() => 3)`, `?? 0`) runs too.
