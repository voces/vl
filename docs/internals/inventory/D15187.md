#### Mechanism

Not the record twin's mechanism ([D15186](D15186.md)). The function set was not tagged: `ftHoldKind` (check_fn_tag.vl) named no kind for a list whose element is a map of the set, so the list was no holder, the scan failed, and the set stayed closures; a closure map of a hole function type has no row. Even `const xs = [fnMap]; print(xs.length)` is refused, with no read. The same map read through a plain local alias runs, and so does the list element read when the function is annotated.
