#### Mechanism

Probed 2026-11-12 with `wasm-dis -n`. The pushed literal `[m2, fnMap]` was built as an array of
`struct {structref, i32, i32}`, which is a function-value row, while the holder's element is a list
of maps. The literal keeps its open type `{[string]: (_) => _}[]`, so `arrLitRowSlotIn` finds no
row, and `arrRefSlotOf` fell back to slot 0, whatever list row was interned first. A list of maps
whose value type is still open now refuses there instead (`emitProgram: a list literal of maps
whose value type is still open names no list row`). The fix is to give the pushed literal the
holder's element type, or to mint its list-of-map row. The original note follows.

Not yet traced at the time of filing. The pushed argument is a list literal whose elements are maps of un-annotated
functions. D15942's change, which delivers a pushed value at the holder's element type, covers a
join's branches, not a literal's elements. Under that change the one-map spelling below moves from
invalid wasm to a loud `monoPinMapValues` refusal, but this two-map witness stays invalid wasm:

    function half(a) { return a / 2.0 }
    const m2 = Map()
    m2.set("a", half)
    const xs: (({ [string]: (a: f64) => f64 })[])[] = []
    xs.push([m2])
    const v = xs[0]
    const h = v[0].get("a")
    if h != null { print(h(6)) }

#### Close

Mono pins `m2` and `fnMap` and retypes their reads, but the literal `[m2, fnMap]` kept the
checker's open type, so `arrLitRowSlotIn` found no row. After a pinned map's reads are retyped,
`monoCloseMapListLits` types each open list literal whose elements all carry one closed map type
at the list of that map, and an enclosing literal of such literals in turn.
`map-of-hole-fns-pushed-onto-map-list.matrix.vl` grades it: `array_push` in both faces and
`map_set` annotated run.
