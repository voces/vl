### D17661 — a named `never` callback baked into its callee's specialization loses its never mark, so a value position below the call has nothing on the stack

**closed 2026-11-26 by `cov-call-cbnever` · check-clean invalid wasm · filed 2026-11-26 against master `bc5a7f45d` (COV-IS's trace, handed to COV-CALL)**

Repro:

    type B = (s: string) => never
    function bail(s: string): never { print(s); __trap__() }
    function r(b: B, c: boolean): i32 { if c { return 3 }; return b("x") }
    print(r(bail, true))
    // vl check: rc 0.  vl run: invalid module, `r$cb0`: callee returns [] where [i32] is required

Want:

    3

#### Mechanism

`monoBakeCallback` (`emit_mono.vl`) rewrites a call through a callback parameter into a
direct call of the function the call site passes, re-minting the call node with
`monoRemintCallTpl`. The copy carried the template's type but not its `callNever` mark, which
the checker sets only on the template. `callEndsNever` therefore read the copy as returning,
and both emitters wrote no `unreachable` after it. A lambda callback is not specialized, and
neither is a direct call, so both ran. A re-mint that answers the template's type
(`monoRemintCallTpl`) now carries the checker's per-call marks in one place, `callMarksCarry`
(`ast.vl`): the never mark and the rest-packed mark (`callRestPacked`). A generic instance's
copy does not carry them. Its type is its own, and a template call typed `never` at one instance
returns at another (`generics/null-only-type-param-binds-never.vl` traps when it carries them). The re-mint already carried the call's type
(`nodeTyCarry`), its UFCS site (`ufcsSiteCarry`), its template note and its source note.
`valDiscardAt` marks an `if` or a block, not a call. Explicit type arguments are carried by
`monoExprMake`, the one remake that keeps them.
