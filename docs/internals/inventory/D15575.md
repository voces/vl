### D15575 — a type-parameter parameter handed a generic and passed on to a generic's function parameter at two types is refused at emit

**closed · runs, prints `4` · was a loud emit reject, clause 2, `vl check` rc 0, then `emitProgram: monomorphize: parameter `a` of `take` is called at two function types that no parameter per type separates` · closed in step 2: a parameter its own type parameter alone annotates is handed a generic called at two signatures as a bundle, as a hole is, and inside the instance it reads as an open function value · the annotated twin of [D10382](D10382.md), which runs · found closing D10382 · filed 2026-11-08 against master `4a1d010d`**

Repro:

    function id<T>(x: T): T { x }
    function run<U>(f: (x: U) => U, u: U): U { f(u) }
    function take<A>(a: A) {
      print(run(a, 2) + run(a, "ab").length)
    }
    take(id)
    // vl run: 4

Want:

    4

#### Mechanism

The elaboration answers `take(id)`'s parameter with two signatures (`elabCallBundleSigs`). The
un-annotated spelling reaches `monoPinHoleParam`, whose first rung (`monoBundlePin`) hands `id`
as a bundle of its two instances. The annotated spelling took `monoPinAnnotatedParam`'s
`ann == tp` arm, which had no bundle rung, so `monoHoleGenFnPin` found the flow slot holding two
pins and refused. With the rung, the outer call pins, and inside the instance `run(a, ...)` read
`a` through `monoArgIsOpenFnValue`, which declined any annotated parameter. It now accepts one
whose checked type is a type variable, and reads the instance's set as it does for a hole.
