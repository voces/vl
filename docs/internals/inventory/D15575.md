### D15575 — a type-parameter parameter handed a generic and passed on to a generic's function parameter at two types is refused at emit

**closed · runs, prints `4` · was a loud emit reject, clause 2, `vl check` rc 0, then `emitProgram: monomorphize: parameter `a` of `take` is called at two function types that no parameter per type separates` · closed in step 2: a parameter its own type parameter alone annotates is handed a generic called at two signatures as a bundle, as a hole is, and inside the instance it reads as an open function value · the annotated twin of [D10382](D10382.md), which runs · found closing D10382 · filed 2026-11-08 against master `4a1d010d`**

Repro:

    function id<T>(x: T): T { x }
    function run<U>(f: (x: U) => U, u: U): U { f(u) }
    function take<A>(a: A) {
      print(run(a, 2) + run(a, "ab").length)
    }
    take(id)
    // vl run: 4

Want:

    4

#### Mechanism

The elaboration binds both spellings' instance of `take` at the untagged set `Fn#id`: `A` here,
the hole there. The un-annotated one pins through `monoPinHoleParam`, and inside the instance
mono binds `run`'s `U` from the value arguments (`monoArgIsOpenFnValue`). The annotated one goes
through `monoPinAnnotatedParam`'s `ann == tp` arm. That arm pins a tagged set at the set, and
otherwise asks `elabCallParamTyOwn` and `elabCallParamTy`. Both read -1, because the set's
signature `(T) => T` is open. `monoHoleGenFnPin` then finds the two calls through `a` and refuses
(`monoHoleGenManyPins`). `monoArgIsOpenFnValue` also refuses any annotated parameter
(`dn.parType >= 0`). The un-annotated spelling's first rung is `monoBundlePin`, which hands `id` as a bundle of the
two signatures the elaboration answers (`elabCallBundleSigs`). The fix gives the `ann == tp` arm
that rung, and lets `monoArgIsOpenFnValue` accept a parameter whose checked type is a type variable.
