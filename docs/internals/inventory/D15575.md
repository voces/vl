### D15575 — a type-parameter parameter handed a generic and passed on to a generic's function parameter at two types is refused at emit

**loud emit reject · clause 2 · `vl check` rc 0, then `emitProgram: monomorphize: parameter `a` of `take` is called at two function types that no parameter per type separates` · the annotated twin of [D10382](D10382.md), which runs · found closing D10382 · filed 2026-11-08 against master `4a1d010d`**

Repro:

    function id<T>(x: T): T { x }
    function run<U>(f: (x: U) => U, u: U): U { f(u) }
    function take<A>(a: A) {
      print(run(a, 2) + run(a, "ab").length)
    }
    take(id)
    // vl check: rc 0.  vl run: emitProgram: monomorphize: parameter `a` of `take` is called at two function types that no parameter per type separates

Want:

    4

#### Mechanism

The elaboration binds both spellings' instance of `take` at the untagged set `Fn#id`: `A` here,
the hole there. The un-annotated one pins through `monoPinHoleParam`, and inside the instance
mono binds `run`'s `U` from the value arguments (`monoArgIsOpenFnValue`). The annotated one goes
through `monoPinAnnotatedParam`'s `ann == tp` arm. That arm pins a tagged set at the set, and
otherwise asks `elabCallParamTyOwn` and `elabCallParamTy`. Both read -1, because the set's
signature `(T) => T` is open. `monoHoleGenFnPin` then finds the two calls through `a` and refuses
(`monoHoleGenManyPins`). `monoArgIsOpenFnValue` also refuses any annotated parameter
(`dn.parType >= 0`). Both arms would need to treat a parameter that its own bare type parameter
annotates, bound to an untagged set of generics, as they treat the hole. That is mono's pin code.
