### D3251 — a call before a null test in the same condition ends a narrowing the test has not made yet

**loud check reject · clause 2 · open · pre-existing, the same on master `d48a56b17`, at the annotated and the hole spelling · found by the #3289 final review (`rv3289f-32528/src/a/*_condClrFirst_*`) · filed 2026-09-29 against master `d48a56b17`**

Repro:

    type R = { v: i32, f: (() => i32) | null }
    const NF: (() => i32) | null = null
    function clrB(q: R): boolean {
      q.f = NF
      return true
    }
    function F(z: R) {
      if clrB(z) && z.f != null { print(z.f()) } else { print("none") }
    }
    F({ v: 1, f: () => 5 })
    // vl check: called value is not a function ((() => i32) | null) — 'z.f' is no longer narrowed to () => i32: the call to 'clrB' on line 8 may reassign it

#### Mechanism

Not localised. `clrB(z)` runs before `z.f != null` is tested, so the narrowing the test makes
holds in the then-arm. The call is charged against it anyway: the condition's calls are
counted as though they followed the narrowing (D2390's rule applied out of order), and the
program, which prints `none`, is refused.
