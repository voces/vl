### D3164 — a `for-in` directly over a `"[]"` operator's literal-union list prints the atom ids

**check-clean silently wrong · open · clause 1 · found by lane NC re-grading the #3281 round-3 review (`rv3281r3-10862/x/y01.vl`) · the same on master `b1794003a` · filed 2026-09-29 against master `b1794003a`**

Repro:

    type K = "a" | "b"
    type Bag = { ks: K[] }
    function "[]"(self: Bag, i: i32): K[] { return self.ks }
    function h(bag: Bag) {
      for e in bag[0] {
        print(e)
      }
    }
    h({ ks: ["b"] })
    // PRINTS 0
    // vl check: rc 0.  vl run: prints the member's atom id; over `["b", "a"]` it prints 0 and 1

Want:

    b

#### Mechanism

Not localised past the ablation. A user `"[]"` is rewritten into a call to the operator, whose
node is appended past the arena, and the loop variable is not flagged as a literal-union atom.
`print` therefore widens it as a plain `i32`. The same list bound to a name first, or produced
by a named call, is flagged and prints its members.

The capture face is `rv3281r3-10862/x/y01.vl`. A closure over a copy of the loop variable
(`const c = e; const f = () => c; print(f())`) builds invalid wasm inside `f` (`expected
(ref $type), found i32`): the closure reads the capture as a string while the env field holds
the atom.

#### Ablation

| ingredient changed | outcome | needed? |
| --- | --- | --- |
| `const xs = bag[0]` then `for e in xs` | prints `b`, `a` | **yes** (the operator result as the iterable) |
| `get(bag, 0)`, a named function | prints `b`, `a` | **yes** (the `"[]"` rewrite) |
| `string[]` in place of `K[]` | prints `b`, `a` | **yes** (the literal union) |
| `print(bag[0][0])`, no loop | prints `b` | **yes** (the loop variable) |
| a closure over a copy of `e` (`x/y01`) | invalid module inside `f` | no (the capture face) |
