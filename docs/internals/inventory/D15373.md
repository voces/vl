### D15373 — a fresh literal a generic builds wider and hands back, handed on at its own type, is refused or not by whether the write scan's index is built

Repro:

    type V = { y: i32, x: i32 | string }
    function k(v: V) { v.y }
    function back<T>(v: T): T {
      k(v)
      v
    }
    function f(q: { y: i32, x: i32 }) { q.x }
    print(back({ y: 2, x: 9 }).y)
    print(f(back({ y: 2, x: 9 })))

Want:

    2
    9

#### Mechanism

`recArgTakesRep` (check_fit_rules.vl) decides whether an argument's parameter takes the argument's
rep. It read the write scan's node index (`cwIxUpKind`, `cwIxUp`, `cwIxUpAux`) without building
it, so on an unbuilt index it answered "no" and `f`'s parameter was judged not to take `V`'s rep.
Nothing in this program built the index before that question.

Named by bisection: each of the 74 functions that read those columns was given a build on entry,
switchable by range. With none switched on, the program refuses; with all, it prints `2` then `9`.
`recArgTakesRep` alone is enough.

The answer it then gives is sound. Both literals are built at `V`, `f` is compiled at `V`'s rep
(it reads `x` through the box), and other callers of `f` are built there too.
