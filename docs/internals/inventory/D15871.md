### D15871 — a `let` list binding reassigned another list literal is refused when delivered as a list of a wider record

**loud check reject · clause 2 · open · split from D3340, whose stored-into faces run · the same on master `8f3814d17` · filed 2026-11-12 against master `8f3814d17`**

Repro:

    type D = { v: i64 }
    let q = [{ v: 1 }]
    q = [{ v: 3 }]
    const ds: D[] = q
    print(ds[0].v)
    // vl check: rc 1 — {v: i32}[] is not D[]: a container never widens implicitly, and only a
    //   readonly list is covariant

Want:

    3

#### Mechanism

D3340's close lets an un-annotated list literal binding adopt the list it is delivered to
(`recAdForce` ahead of the container floors). A `let` reassigned another list literal holds only
literals too, but the adoption does not follow a reassigned list binding, so the delivery is
judged at its own type.
