### D17034 — inside a generic, `is` narrowing to the arm of a recursive union that refers back to the union does not narrow, so the arm's field is refused

**loud check reject · clause 2, CAPABILITY, the program is type-valid · `` field 'kids' is not on every member of {leaf: T} | {kids: (…)[]} — narrow with `is` first `` · reported by lane F1 through the coordinator, triaged by lane F2 against [D17032](D17032.md) (a different mechanism) · filed 2026-11-20 against master `de317fa31`**

Repro:

    type Tr<T> = { leaf: T } | { kids: Tr<T>[] }
    function count<T>(t: Tr<T>): i32 {
      if t is { kids: Tr<T>[] } {
        return t.kids.length
      }
      return 1
    }
    const t: Tr<i32> = { kids: [{ leaf: 1 }, { leaf: 2 }] }
    print(count(t))
    // vl check: rc 1, field 'kids' is not on every member of {leaf: T} | {kids: ...}

Want:

    2

#### Mechanism

Inside the generic body the `is` pattern `{ kids: Tr<T>[] }` does not select the union's own
`{ kids: Tr<T>[] }` arm: the arm's recursive reference to `Tr<T>` is not identified with the
pattern's, so the narrowing yields nothing and the field read is checked against both members.
Narrowing to the arm free of the self-reference works, and so does the whole program once `T` is
concrete. Where the open recursive arm and the pattern stop comparing equal is not yet located.
