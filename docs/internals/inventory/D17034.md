### D17034 — inside a generic, `is` narrowing to the arm of a recursive union that refers back to the union does not narrow, so the arm's field is refused

**closed 2026-11-20 by lane F2 · runs, prints `2` · was loud check reject, clause 2, CAPABILITY, the program is type-valid · `` field 'kids' is not on every member of {leaf: T} | {kids: (…)[]} — narrow with `is` first `` · `recIsFitsAcrossTags` (`check_fit_rules.vl`) now finds the tested arm by `recArmOfChk` · pin: `tests/cases/generics/recursive-union-is-narrows-self-arm.vl` · reported by lane F1 through the coordinator, triaged by lane F2 against [D17032](D17032.md) (a different mechanism) · filed 2026-11-20 against master `de317fa31`**

Repro:

    type Tr<T> = { leaf: T } | { kids: Tr<T>[] }
    function count<T>(t: Tr<T>): i32 {
      if t is { kids: Tr<T>[] } {
        return t.kids.length
      }
      return 1
    }
    const t: Tr<i32> = { kids: [{ leaf: 1 }, { leaf: 2 }] }
    print(count(t))
    // vl check: rc 1, field 'kids' is not on every member of {leaf: T} | {kids: ...}

Want:

    2

#### Mechanism

`is` narrows only when no other arm of the union "fits across tags" (`recIsFitsAcrossTags`, the
D4056 rule: an arm under its own tag whose values also pass the test keeps the wide type). The
tested arm was skipped by `m != chk && !tySame(m, chk)`. Inside the generic, the union's own
`{ kids: Tr<T>[] }` arm, its self-reference unrolled, and the pattern's `{ kids: Tr<T>[] }` intern
apart and are not `tySame`, so the arm under test counted as another arm that fits it, and the
narrowing was dropped. With `T` concrete the two intern alike. `recArmOfChk` now takes the one arm
assignable both ways with the pattern as the tested arm when none is `tySame` to it; two such arms
stay two, as D4056 needs.
