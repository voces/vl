### D15958 — a held list literal of an arm-shaped anonymous record, returned, has no struct row for its element's field read

**closed 2026-11-12 — runs (prints `7`); `rlElemVariantRow` finds the arm of a record of its shape that has no struct row of its own · was: loud emit reject · filed 2026-11-12 against master `f7b6b8d9`**

Repro:

    type Circle = { r: i32 }
    type Sq = { s: i32 }
    type Shape = Circle | Sq

    function g() {
      const o = [{ r: 7 }]
      return o
    }
    print(g()[0].r)
    // vl check: rc 0.  vl run: prints 7 (was: emit error, field access but no struct type declared)

Want:

    7

#### Mechanism

**Fixed:** `tyIsVariantMember` tests the checker's member set by type index, and the literal's
`{ r: 7 }` is not `Circle`'s index, so `rlElemVariantRow` answered -1 for the returned list's
element and no row served the read. A record of an arm's shape with no struct row of its own now
asks the variant table by type (`exactArmRowOfTy`). The original diagnosis follows.


The anonymous `{ r: 7 }` has the arm `Circle`'s shape, and the only rows of that shape are
variant rows. The program declares no record outside a union, so `collectS` mints no struct
row and `sDeclared` stays false. `emitMemStructRead` floors on `sDeclared` before it asks for
the receiver's row. With the floor removed, `structIndexOfExpr` finds no row for the call
result's element either ("field access receiver is not a struct"). So the gap is the read of
an element whose row is only a variant row, not just the guard. A declared same-shape record
(D36's `Dot`) supplies the struct row the read takes. That is why `typeDeclMintsRow` keeps a
twin declaration's own row until this row closes (`2026-11-12-step7-variant-name-reads-cut-2.md`).
