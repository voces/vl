### D4638 — a map annotated with an anonymous union arm as its value type builds an i32 map where the record map is declared

**closed 2026-10-14 — the witness prints `0` · the map-value slot's find hint answers an anonymous arm by its spelling (`mvArmHintOfTyName`), as the mint records it, so every find after the mint reuses the slot instead of minting an untyped twin · fixture `tests/cases/unions/anon-arm-map-value.vl` · template `if-expr-anon-arm-literals.matrix.vl` (`map_value`, `map_set`, `map_value_place`, both faces) loud → runs · was check-clean invalid wasm · clause 1 · the annotated face of [D4636](D4636.md) · filed 2026-10-14 against master `536c4c79e`**

Repro:

    type U = { q: i32 } | { r: i32 }
    const m: Map<string, { q: i32 }> = Map()
    print(m.length)
    // vl check: rc 0.  vl run: type mismatch: expected i32, found (ref $3); $3 is `i32 array (list and map storage)`

    0

#### Mechanism

The map-value slot is keyed by its value's spelling plus an arm hint. The mint takes the hint
from `mvArmHintOfTy` and, when that is -1, from the spelling (`mvArmSigOfName`). The finds
(`mapAnnShape`, `mvShapeOfValNameArmTyGo`, `mvSlotOfMapValNameOrMonoKTy`) took it from the
type alone. An inline `{ q: i32 }` annotation's type reaches no arm row, so each find asked
with -1, declined the minted slot, and minted a late twin whose map type was never filled in.
The global was typed against that twin and `Map()` built the wrong struct. With a store, the
local and parameter spellings refused instead (locals desync, `map values must be i32 /
boolean`). All four sites now read one helper, `mvArmHintOfTyName`, that applies the mint's
fallback.
