### D15444 — the late decision marks partial only the set the last instance's call went through, so which of two sets stays taggable follows the order of the calls

**runs today and must keep running · with the two alias calls in the other order the same program is D15443, check-clean invalid wasm · `elabMintFacts`'s partial pass (emit_elab.vl) reads `elabMintSets[c]`, the set the call `c` went through in the last instance minted, which `elabMintFactAt` overwrites per instance · found closing D15442, at the coordinator's ask · filed 2026-11-05 against master `0507b893`**

Repro:

    function add(a, b) { return a + b }
    function mul(a, b) { return a * b }
    function apply2(g) { print(g(1, 2)) }
    function m() {
      const k = apply2
      k(mul)
      k(add)
    }
    m()
    function viaFor(h) {
      for f in [apply2] { f(h) }
    }
    viaFor(add)

Want:

    2
    3
    3

#### Mechanism

`apply2`'s call `g(1, 2)` goes through `{add}` in one instance and `{mul}` in another. The
partial pass asks whether every instance of `apply2` binds the call's set, and marks partial the
one set `elabMintSets[c]` holds, which is the last instance's. The other set stays taggable, so
whichever function the first alias call hands is the one tagged. Here that is `{mul}`, which
`viaFor` never hands, and the program runs; with `k(add)` first `{add}` is tagged and
`viaFor(add)` hands its id into the `{apply2}` closure (D15443). A decision that is a function of
the program's facts marks every set a call goes through in some instance, or none.
