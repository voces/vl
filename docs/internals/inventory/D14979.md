### D14979 — a generic function handed to a type parameter is accepted where the body delivers it to a non-function type

**closed 2026-11-03 · now a loud check reject at the call, `cannot assign (T) => T to 'zz' of type boolean (the body of `one` at the call's argument types)` · was check rc 0 then a loud emit reject, the checker owing the refusal · `fnShapeClash` (check_assignable.vl) judges a let or return constraint whose source still holds the argument's own open parameters when it puts a function where the destination holds no function at any instance · fixtures `tests/cases/generics/error-generic-fn-handed-to-param-*.vl` and the controls in `generics/generic-fn-handed-to-param-delivered-where-a-function-fits.vl` · filed 2026-11-03 against master `1484b3d72`**

Repro:

    function id<T>(x: T): T { x }
    function one<F>(a: F) {
      const zz: boolean = a
      print(zz)
    }
    one(id)
    // vl check, before: rc 0, then vl run: emitProgram: a generic function taken as a value reaches no call that fixes its type

#### Mechanism

The body of `one` is re-checked at each call's argument types. With `F` bound to a closed type the
re-check refuses the delivery to `boolean` (`cannot assign (i32) => i32 to 'zz' of type boolean (the
body of `one` at the call's argument types)`). With `F` bound to a generic function the re-check
reports nothing, so `vl check` passes a program no instance can type, and the emitter is the first
stage to refuse it.

#### Ablation

| `function id(x: i32): i32` (not generic) | loud check reject at the call | **yes** |
| `function one<F>(a: F): boolean { a }`, a return | check rc 0, loud emit reject | no, any non-function destination |
