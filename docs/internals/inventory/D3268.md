### D3268 — a join of two bare type parameters answers `is i32` true for its boolean arm

**closed 2026-09-30 · was check-clean silently wrong, clause 1, on master `b6378e95b` (`true true`) · found by the #3297 round-1 review (`g3` grid, `bool_i32__jab__isi`, `in_str__jab__lst`) · fixture `tests/cases/generics/join-two-bare-type-params-is.vl`**

Repro:

    function g<T, U>(a: T, b: U, k: i32) {
      const r = if k == 0 { a } else { b }
      print(r is i32)
    }
    const x: boolean = true
    const y: i32 = 3
    g(x, y, 0)
    g(x, y, 1)

Want:

    false
    true

#### Mechanism

`tyParamsPart` kept two differently named bare parameters collapsed at depth 0, a carve-out
D2760 left because a union there then met a bind position with no box. The join was typed `T`,
and at `boolean`, `i32` both arms stored into the one `i32` cell, so no tag told the boolean
apart. Bare parameters now part like parameters under a list or nullable: the join is `T | U`,
the pin re-joins it (`i32` beside `f64` still widens to `f64`, D2716), and the bind positions
that had no box register one (`monoTpJoinBindAnn`, `monoPinUnionBoxed`).
