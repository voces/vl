### D17401 — a `??` chain of two `boolean | null` operands with a default of another type yields the boolean as an `i32`

**closed 2026-11-24 by IR-N3 · runs, prints `true` · was check-clean silently wrong, clause 1 · `coalChainMint` types both re-associated links at the chain's union wherever `emitCoalesce` boxes the chain (`exprUnion`), as it already did for struct-bearing and number-apart chains · found ablating the `map read default rep` corpus cells (lane IR-C1) · filed 2026-11-24 against master `f7e47d34a`, the same under the IR and the claimless compiler**

Repro:

    function f(): boolean | null { return null }
    function g(): boolean | null { return true }
    print(f() ?? g() ?? 2)
    // vl check: rc 0.  vl run: PRINTS 1

Want:

    true

#### Mechanism

`a ?? b ?? d` is lowered re-associated, `a ?? (b ?? d)` (`coalChainMint`). The minted inner link
was typed at the chain's union only for a struct-bearing or number-apart chain, else only where `d`
already had the chain's type. Under a `boolean | i32` chain the inner link `g() ?? 2` stayed
untyped, its arms delivered the boolean raw, and the outer link boxed that at the `i32` arm (or at
a string default's heap, which does not validate). Bound to a `const` first, the inner join is
typed and boxes right.
