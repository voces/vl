### D3841 — a for-in over a generic call's list result inside an enclosing `<T>` binds the loop variable at the `i32` rep, so a `boolean` prints `1` and a literal union prints its atom index

**closed 2026-10-08 by lane SC · was check-clean silently wrong · found in review of lane SC (round 3, `e6_wrap_ctrl`) · filed 2026-10-08 against master `04be94d88` · pins: `tests/cases/generics/for-in-generic-call-result-at-pin.vl`**

Repro:

    function wrap<U>(u: U): U[] { [u] }
    function outer<T>(x: T) {
      const ws = wrap(x)
      for e in ws { print(e) }
      print(ws[0])
      for e in wrap(x) { print(e) }
    }
    outer(true)
    // vl check: rc 0.  vl run: rc 0
    // PRINTS 1
    // PRINTS true
    // PRINTS 1

Want:

    true
    true
    true

#### Mechanism

`iterElemPinTy` answers a for-in loop variable's element type at an instance. It had no arm for
a list a generic call returns, in two spellings. A binding of one (`ws`) is recorded at `T[]`
and was never substituted through the instance's binding. The call itself, copied per instance
by `monoCloneGenericCalls`, has no recorded type at all. The variable fell back to the `i32`
rep a `boolean` or a literal union shares. The close adds a fallback for each: a list recorded
at a type parameter is substituted (`pinSubOperandTyOf`), and a copied call reads the return its
instance declares (`instCallRetListTy`).

#### Ablation

| ingredient removed | outcome | needed? |
| --- | --- | --- |
| the for-in (`print(ws[0])`) | prints `true` | **yes** |
| `outer`'s `<T>` (`function outer(x: boolean)`) | prints `true` | **yes** |
| `wrap`'s `<U>` (`function wrap(u)`, a hole) | still prints `1` | no |
| `boolean` for a literal union `"a" \| "b"` | prints `0` for `b` | no |
| `boolean` for `f64` / `string` / `i32` / a record | right | the rep is not shared |
