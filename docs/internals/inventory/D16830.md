### D16830 — a `?.` call on a binding of a record of un-annotated functions, beside a declared record of the same field, has no value at emit

**closed 2026-11-16 — the witness runs and prints `6` · was: loud emit reject · clause 1 (check accepts what emit refuses) and clause 2 · found closing [D16809](D16809.md) · filed 2026-11-16 against master `eb9685821`**

Repro:

    type G = { f0: (a: i32) => i32 }
    function dbl(a) { return a * 2 }
    function inc1(a) { return a + 1 }
    const m = Map()
    m.set("a", { r: { f0: inc1 } })
    m.set("b", { r: { f0: dbl } })
    const t = m.get("b")?.r
    print(t?.f0(3) ?? 0)
    // vl check: rc 0.  vl run: emit error, "emitProgram: union if-expression arm ends in a void call, which yields no value"

Want:

    6

#### Mechanism

Beside a declared record of the field's name, the tag decision leaves the set untagged: the
members are built as closures at the call's signature. The guarded call's callee, a field read
through a hole, is typed `(_) => _`, as is the row's stored field, so `cloCallSigKey`
(`compiler/emit_classify.vl`) found no `$fnsig` key. `stmtIsTailValue` then read the call as
void, and the `?.` guard's value arm was refused. The key now falls back to the call's own
argument types and result type, taken only where that signature is interned.

#### Findings (lane WIDTH, 2026-11-16, master `06f1673d5`)

Which declared record breaks it, beside the map of nested `{ f0 }` records:

| other record in the module | outcome |

| `type G = { g0: (a: i32) => i32 }` | runs, prints `6` |

So another record of exactly the field names `{ f0 }` with a function in it, whatever its
signature. A list `.get(0)` of the records in place of the map runs. At the refusal, the guarded
arm's call (`?.` desugar, `drwWalkMemberCall`) is typed `i32` and noted at a set, but its minted
callee `t.f0` (`optCallCalleeOf`) has no node type. `structFieldNameUsed` gates only the `"[]"`
index rewrite, so it is not the trigger. The call is noted at the map value's set, but that set is
not tagged and has no arms (`fnTagCallArms` empty, `fnTagSetIsTagged` false), so `stmtIsTailValue`
finds neither a tagged dispatch nor a closure field and reads the arm as a void call. With `G`
absent the same set is tagged. With `G` present the plan (`ftPlan`) declines it in `ftScan`, at the
second `m.set`: the entry literal's nested field holds `dbl`, which is neither typed at the set
nor one of its members (`ftRecWriteJoins` → `ftJoinAt` → `ftValuesOk`), so the set holds only
`inc1`. That is D16829's gap: a later `m.set`'s nested record does not join its functions into the
map's value (`elabFnRecJoin`). Making that join recurse moves this witness to another emit
refusal (`ref valtype with no interned shape`) and breaks the program without `G`. The row closed
apart from D16829 all the same, at emit: the untagged members are closures at the call's
signature (Mechanism).
