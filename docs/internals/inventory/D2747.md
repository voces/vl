### D2747 — a generic call pins its type parameter at a list literal's checked element while the literal is built for a union destination

**closed 2026-09-26 — the repro RUNS and prints `1` then `3` · was check-clean invalid wasm · the #3204 review's `b19`, `b20`, `b27`, `b28` and the lane's capture, alias and `T[]`-returning variants · filed 2026-09-26 against master `92bed043d`**

Repro:

    type Circle = { r: i32 }
    type Sq = { s: i32 }
    type Shape = Circle | Sq
    function sum(xs: Shape[]): i32 { xs.length * 3 }
    function len<T>(xs: T[]): i32 { xs.length }
    function f() {
      const out = [{ r: 3 }]
      print(len(out))
      print(sum(out))
    }
    f()

#### Mechanism

`out` is checked as `{r: i32}[]`, and the destination scan (`letRefListDestSlot`) builds it as
a `Shape` box list because `sum` declares `Shape[]`. The monomorphizer pinned `len`'s `T` from
the binding's initializer instead, so the instance took a `Circle` list parameter and was handed
the box list. The destination pin that rewrites the annotation (`dstPinAnnIn`) does not fire
here: it pins an object literal to a union ARM, not a list to the union. Closed by pinning an
un-annotated list binding at the list its destination builds (`monoDestListPinName`), for a
local, a global, and a binding a closure captures.
