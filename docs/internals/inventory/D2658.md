### D2658 — a generic whose parameter is a map over a type parameter cannot be pinned at all

**loud emit reject · clause 2 · found by #3189's review (P4) · identical on master · filed 2026-09-26 against master `979323f83`**

Repro:

    function g<V>(m: {[string]: V}): i32 {
      m.length
    }
    const mb: {[string]: boolean} = Map()
    print(g(mb))
    // vl check: rc 0.  vl run: emitProgram: monomorphize: unsupported argument type for `m` in a call to `g`

#### Mechanism

The monomorphizer names each pinned argument by its type, and its argument-pin ladder has no
rung for a map whose VALUE is the type parameter, so it floors with `unsupported argument type`
before the instance is cloned. The review found it on `{[i32]: V} | {[i64]: i32} | null`; the
union, the key rep and the value the parameter binds are all scenery.

#### Ablation

| ingredient removed | outcome | needed? |
| --- | --- | --- |
| the boolean value (pinned at `i32` or `string`) | the same refusal | no |
| the string key (`{[i32]: V}`, and the review's union around it) | the same refusal | no |
| the type parameter in the map (`m: {[string]: boolean}`) | runs | **yes** |
