### D12219 — a reassigned binding of two generics, called twice with different lambdas at one type, is refused as two signatures

**closed 2026-11-05, runs and prints `3 5`, with the split plan on and off · was loud emit reject, `vl check` rc 0, `emitProgram: the reassigned function binding `v` is called at more than one argument type` · clause 2 · found surveying emit refusals for L3 family (d) · filed 2026-10-24 against master `b8e223f93` · closed by not baking a lambda argument into a call made through a binding something writes (`monoInstantiateCallIn`, emit_mono.vl): each baked lambda keyed an instance of its own, while the binding holds one · fixture `closures/written-let-of-two-generics-called-with-two-lambdas.vl`, the former `-reject` fixture**

Repro:

    function g<T>(f: (x: T) => T, x: T): T { f(x) }
    function h<T>(f: (x: T) => T, x: T): T { f(x) }
    function la(n: i32) {
      let v = g
      if n > 0 { v = h }
      print(v((x: i32) => x + 1, 2))
      print(v((x: i32) => x, 5))
    }
    la(1)

Want:

    3
    5

#### Mechanism

Both calls are at `((i32) => i32, i32)`; only the lambda values differ, yet the reassigned-binding
rule in emit_mono.vl counts two signatures. Two literals of one text still refuse and one
`const` lambda passed twice runs, so the rule distinguishes the lambda VALUES rather than the
types they lower to. The values are what callback specialization keys on: a non-capturing lambda
argument is baked into the callee's instance by name, so each literal makes an instance of `g`
and the second is a binding called at a second instance.
