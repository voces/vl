### D12219 — a reassigned binding of two generics, called twice with different lambdas at one type, is refused as two signatures

**loud emit reject · `vl check` rc 0 · `emitProgram: the reassigned function binding `v` is called at more than one argument type` · clause 2 · CAPABILITY: annotating the binding, or one shared lambda, runs · found surveying emit refusals for L3 family (d) · filed 2026-10-24 against master `b8e223f93`**

Repro:

    function g<T>(f: (x: T) => T, x: T): T { f(x) }
    function h<T>(f: (x: T) => T, x: T): T { f(x) }
    function la(n: i32) {
      let v = g
      if n > 0 { v = h }
      print(v((x: i32) => x + 1, 2))
      print(v((x: i32) => x, 5))
    }
    la(1)

Want:

    3
    5

#### Mechanism

Both calls are at `((i32) => i32, i32)`; only the lambda values differ, yet the reassigned-binding
rule in emit_mono.vl counts two signatures. Two literals of one text still refuse and one
`const` lambda passed twice runs, so the rule distinguishes the lambda VALUES rather than the
types they lower to. Not traced further. D9853 is closed and
`closures/written-let-of-two-generics-called-with-two-lambdas-reject.vl` pins this refusal.
