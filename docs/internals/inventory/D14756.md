### D14756 — an overloaded method call in a generic body skips the record-delivery check its instance's pick owes

**closed 2026-11-01 · now a loud check reject, refused as a lone candidate's generic call is, "{z: boolean, x: i32} is not W: they store field `x` differently": `ovPinCheck` delivers the receiver to the pick's `self` through `ufcsRecvPinSeam` · was check-clean invalid wasm, clause 1, on master `b3f08b57` · fixtures `tests/cases/modules/err-overload-generic-pick-delivery`, `tests/cases/modules/overload-generic-two-picks-run` · filed 2026-11-01 against master `1d98f35a`**

Repro:

    // file: a.vl
    export type W = { z: boolean, x: i32 | string }
    export function poke(self: W): i32 {
      self.x = "s"
      0
    }
    // file: b.vl
    export type V = { y: i32, x: i32 | string }
    export function poke(self: V): i32 { 1 }
    // file: entry.vl
    import { W, poke } from "./a"
    import { V, poke } from "./b"
    function g<T>(v: T): i32 { v.poke() }
    const j = { z: true, x: 3 }
    print(g(j))
    print(j.x + 1)
    // was: vl check rc 0, then the emitted module failed to validate inside `g` ($3 is `W`, $6 is `#anon2`)

#### Mechanism

An overloaded call in a generic body is picked per instance (`ovPinCheck`), and the pick only
re-checks the receiver and arguments for assignability. The record-delivery rule that the direct
spelling and a single candidate both apply never runs for the instance's pick: a single `poke`
refuses the same body at `v.poke()` ("writes a widened field"). So the `{z, x: i32}` record reaches
`W`'s storage unconverted.

#### Ablation

| ingredient removed | outcome | needed? |
| --- | --- | --- |
| `./b`'s `poke` (one candidate, no overload) | loud check reject: writes a widened field | **yes** |
| the generic `g` (call `j.poke()` directly) | loud check reject: writes a widened field | **yes** |
| the write in `./a`'s `poke` | still check-clean invalid wasm | no |

#### Grading list

The position matrix, overloaded `./a`/`./b` as above, before → after:

| cell | before | after |
| --- | --- | --- |
| direct, pick writes (`j.poke()`) | refused: writes a widened field | same |
| direct, pick reads (`i.poke()`) | runs `1` | same |
| generic, pick writes (`g(j)`) | check-clean invalid wasm | refused: stores `x` differently |
| generic, pick reads (`g(i)`) | check-clean invalid wasm | refused: stores `x` differently |
| generic, two instances, two picks (`g(i) + g(j)`) | check-clean invalid wasm | refused |
| generic, two instances, each stored as its pick (`v: V`, `w: W`) | runs | runs `1`, `0` |
| one candidate, generic, reads | refused: stores `x` differently | same |
| one candidate, generic, writes | refused: writes, and stores differently | same |

A generic call of a fresh literal is refused where the direct call runs, with or without an
overload: the direct call builds the literal at `V`, the generic one hands `T` on unbuilt.
