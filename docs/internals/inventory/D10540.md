### D10540 — a generic instance bound to a boolean map by an explicit type argument answers `is Set<i32>` on a generic call's result with the box tag the two share

**closed 2026-10-23 · runs, prints `false` · was check-clean silently wrong, printed `true` · clause 1 · the value is a `{[i32]: boolean}`, so `is Set<i32>` should print `false` · the inferred spelling `g(uq)` prints `false` · fixture `tests/cases/generics/is-set-twin-at-bound-type-argument.vl` · found while fixing the C1 typed column ([render-parse residue](../render-parse-residue-2026-10.md) §C1): binding `T` in `letBT` for the inferred call sent it here too · filed 2026-10-22 against master `823e61a63`**

Repro:

    function id<X>(x: X): X { x }
    function g<T>(u: T | string): boolean { id(u) is Set<i32> }
    const q: {[i32]: boolean} = Map()
    const uq: {[i32]: boolean} | string = q
    print(g<{[i32]: boolean}>(uq))
    // PRINTS false

#### Mechanism

A Set and a boolean map share one box tag, so `is` tells them apart only by a static answer
from the instance's exact types (D2753). That answer read only `exactOperandTyOf`, which knows a
bare type-parameter operand. Once the column binds `T`, the clone's body is retyped at the bound
argument, so `id(u)`'s operand names no type parameter and the answer was absent: `is` tested the
shared tag.

#### Fix

`isOperandExactTyOf` (`emit_value_sites.vl`) falls back, inside a pinned instance, to the
operand's recorded type when it names no type parameter, and both twin tests read it. That
recorded type comes from the instance's typed column, and a pin spelling renders a Set as its
boolean map — also inside a generic record's field (D9991). So `monoMakeInstanceLetTyCol` takes
the true `pinTys` row where it differs from the parsed pin only by Set flavour (`tySameSpelled`
but not `tySameSet`); without it `Box<Set<i32>>` through a generic reads `false`.

The two fixtures that pinned the shared tag were re-graded: `bm.v is Set<i32>` over a
`{[i32]: boolean}` is `false`, as `is` is structural ([D2722](D2722.md),
`sets/set-as-generic-record-argument.vl`, `maps/i32-keyed-function-type-parameter.vl`).

#### Ablation

| ingredient removed | outcome | needed? |
| --- | --- | --- |
| the explicit type argument (`g(uq)`) | prints `false` | **yes** |
| the generic call (`u is Set<i32>`) | prints `false` | **yes** |
| the `string` arm (`g<T>(u: T)` at `{[i32]: boolean} \| string`) | still prints `true` | no |

`h<Set<i32>>(up)` with `id(u) is {[i32]: boolean}` over a `Set<i32> | string` printed `true`
the same way; it prints `false` now.
