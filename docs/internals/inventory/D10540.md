### D10540 — a generic instance bound to a boolean map by an explicit type argument answers `is Set<i32>` on a generic call's result with the box tag the two share

**check-clean silently wrong, prints `true`, clause 1 · the value is a `{[i32]: boolean}`, so `is Set<i32>` should print `false` · the inferred spelling `g(uq)` prints `false` · found while fixing the C1 typed column ([render-parse residue](../render-parse-residue-2026-10.md) §C1): binding `T` in `letBT` for the inferred call sent it here too, so `monoBindCols` leaves a binding that holds a Set or a boolean map unbound · filed 2026-10-22 against master `823e61a63`**

Repro:

    function id<X>(x: X): X { x }
    function g<T>(u: T | string): boolean { id(u) is Set<i32> }
    const q: {[i32]: boolean} = Map()
    const uq: {[i32]: boolean} | string = q
    print(g<{[i32]: boolean}>(uq))
    // PRINTS true

#### Mechanism

A Set and a boolean map share one box tag, so `is` tells them apart only by a static answer
from the instance's exact types (D2753). When the instance's binding column names `T`, the
body walks that read it (`bodyBN` into `monoCloneBody` and `monoPinBodyLambdas`; withholding the
binding from those two alone restores `false`) leave the `is` over `id(u)`'s result with no
static answer, and it tests the shared tag. With `T` unbound in the column, as for the inferred
call on master, the static answer is `false`.

#### Ablation

| ingredient removed | outcome | needed? |
| --- | --- | --- |
| the explicit type argument (`g(uq)`) | prints `false` | **yes** |
| the generic call (`u is Set<i32>`) | prints `false` | **yes** |
| the `string` arm (`g<T>(u: T)` at `{[i32]: boolean} \| string`) | still prints `true` | no |

`h<Set<i32>>(up)` with `id(u) is {[i32]: boolean}` over a `Set<i32> | string` prints `true`
the same way.
