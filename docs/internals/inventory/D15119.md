### D15119 — a record field holding one un-annotated function, written another, and called at two types, reads only the write's set

**open · loud emit reject · `emitProgram: cannot take the generic function id1 as a value — a function value carries ONE signature` · clause 2 · no write joins a function field's set, as `elabFnLetTy` joins a written `let`'s and `elabFnFieldListTy` a written list field's · found ablating D15117's two-member half · filed 2026-11-04 against master `fc6645cfd`**

Repro:

    function id0(a) { return a }
    function id1(a) { return a }
    const r = { f: id1 }
    r.f = id0
    const g = r.f
    print(g(2))
    print(g(2.5))

Want:

    2
    2.5

#### Mechanism

The elaboration widens a function value's set where something writes another function into its
storage: `elabFnLetTy` for a written `let`, `elabSlotJoinTy` for a list or map slot, and
`elabFnFieldListTy` for a list field of a record (D15166). A record field that holds a function
itself has no such join, so the read `r.f` carries one member's set and the literal's own `id1` is
in no set the calls dispatch over. The fn-tag pass then cannot tag it (`ftJoinAt` refuses the
store), and the value reaches mono as a function of one signature.
