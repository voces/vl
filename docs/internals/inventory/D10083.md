### D10083 — a list of a generic pushed a fixed-type function through a parameter is typed by an unrelated call of the generic

**closed · runs, prints `3`, `s` · was loud check reject, `push: cannot add (i32) => i32 to ((string) => string)[] (the body of `id` at the call's argument types)`, clause 2 · CAPABILITY: the last call spelled `id(7)` prints `3`, `7` · found closing [D10020](D10020.md) · present on master `e0eecffc4` · filed 2026-10-22 against master `e0eecffc4` · closed with [D10080](D10080.md): a written container reached through a parameter of a top-level function is skipped at a call that cannot reach any argument bound to it, when the function reads the parameter only by writes, element calls and length reads, and every read of the function is a direct call passing a `let`/`const` binding at that position (`ctnParamArgDecls`, check_decl_scan.vl) · fixture `closures/generic-list-written-through-parameter-beside-other-type.vl`**

Repro:

    function id<T>(x: T): T { x }
    function inc(x: i32): i32 { x + 1 }
    const ys = [id]
    function fill(a) { a.push(inc) }
    fill(ys)
    print(ys[1](2))
    print(id("s"))
    // vl run: 3, s

Want:

    3
    s

#### Mechanism

[D10020](D10020.md)'s, through a parameter: the push row is re-validated at `id("s")`, which
binds `id`'s `T` by name. The close of D10020 skips the row only when the receiver is a
`let`/`const` binding whose reads it can enumerate; here the receiver is `fill`'s parameter
`a`, whose values are the arguments at every call of `fill`, and nothing walks them.

| `fill` inlined as `ys.push(inc)` | runs, `3`, `s` since [D10020](D10020.md) | **yes** |
