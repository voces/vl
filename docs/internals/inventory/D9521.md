### D9521 — `??` over the call of an un-annotated parameter bound at a function returning a numeric literal union is refused at emit

**loud emit reject · clause 2 · CAPABILITY: the same `??` over an `i32`-returning lambda runs, an annotated `f: () => N` parameter runs, and `a ?? 0` over the `N` value directly runs · found closing [D9491](D9491.md) · present on master `0be192a3f` · filed 2026-10-22 against master `0be192a3f`**

Repro:

    type N = 1 | 2
    const a: N = 2
    const h = () => a
    function take(f) {
      print((f() ?? 0) + 40)
    }
    take(h)
    // vl check: rc 0.  vl run: emitProgram: `??` over this nullable value is not supported yet — narrow it first, e.g. `if v != null { … }`

Want:

    42

#### Mechanism

Not traced. The un-annotated parameter's instance at `() => N` reaches the emitter's `??` with
an operand it does not take for the non-nullable `i32` it reps as; the `i32` instance
(`take(() => 2)`) takes the plain-value path. [D9522](D9522.md) is the string spelling and
fails differently (invalid wasm), so the two may or may not share a cause.

#### Ablation

| ingredient removed | outcome | needed? |
| --- | --- | --- |
| the numeric union (`take(() => 2)`) | runs | **yes** |
| the un-annotated parameter (`f: () => N`) | runs | **yes** |
| the call (`take(x)` with `x ?? 0`, `x` bound at `N`) | runs | **yes** |
| the `const h` (`take(() => a)` inline) | same refusal | no |
