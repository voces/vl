### D4553 — a variadic `.push` onto a nullable or literal-union list is refused

**closed 2026-10-14 · runs — the witness prints `3` · `emitPushMany` builds its argument run under the element seeds the one-argument push gives its value (`pushRunBuildCtx`), and a string-list literal under a threaded `null` seed builds the string list whatever its first element · fixture `tests/cases/arrays/push-many-nullable-and-literal-union.vl` · was loud emit reject · clause 2 · 5 hand probes · filed 2026-10-13 against master `eb2603843`**

Repro:

    type K = "a" | "b"

#### Mechanism

`emitPush` lowers a one-argument push element by element, and routes several arguments or a
spread to `emitPushMany`, which builds the arguments as one list literal and appends it with
`array.copy`. That literal is built without the element seeds a literal-union atom, a
`boolean | null` sentinel or a nullable string slot need, so `emitPushMany` refused those
receivers outright.

The fix removes the refusal and builds the run under `pushRunBuildCtx`: the receiver's list
build plus the same seeds, read by the same predicates, that the one-argument push gives its
value (`litUnion` for `K[]`, `nulBool` and the nul-bool build for `(boolean | null)[]`,
`litUnion` + `nulLitUnion` and the atom-niche build for `(K | null)[]`, `nulString` for
`(string | null)[]`). `emitArr` then delivers each element exactly as it does a declaration's
literal. One more seam: the synthesized literal records no type, so a `(string | null)[]` run
whose first element is `null` fell to the i32 build; a non-empty literal under
`LBK_STR_LIST` with `pendingNulString` now builds the string list.
