### D15645 — the result of a function that hands a hole function, in a list or record literal, to a callee calling it at `f64` is left untyped by the checker

**check-clean invalid wasm · clause 1 · `the emitted module failed to validate inside the module's top-level code: … type mismatch: expected i32, found f64` · found writing D15640's matrix · filed 2026-11-10 against master `1fc9a771`**

Repro:

    function dbl(v) { return v + v }
    function c1(r, x) { return r[0](x) }
    function both1(g) { return c1([g], 2.5) }
    const b = both1(dbl)
    print(b + 1)

Want:

    6

#### Mechanism

`vl check` accepts `const b: string = both1(dbl)` too (it refuses `c1([dbl], 2.5)` there as
`f64`), so the checker gives `both1(dbl)` an open type, and the emitter, which builds `f64`,
has no conversion to the type the reader assumed. Where it opens is unmeasured.

#### Ablation

| spelling | outcome | needed? |
| --- | --- | --- |
| `print(b)` for `print(b + 1)` | runs, `5` | **yes** |
| `const b: f64 = both1(dbl)` | runs, `6` | **yes** |
| `c1(g, 2.5)` calling `r(x)` (no literal) | runs, `6` | **yes** |
| `c1({ f: g }, 2.5)` calling `r.f(x)` (record for list) | still invalid wasm | no |
