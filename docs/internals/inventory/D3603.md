### D3603 — in a merged compile, a call above a block's `const` of the same name was undeclared (sunpa SP-029)

**closed 2026-10-03 — the witness runs and prints `7` then `5` · was a loud check reject (`undeclared identifier 'over'`) of a program that runs as a single module · fixed in the module merge's rename**

Repro (runs; the `std:math` import is what makes it a merged compile):

    import { hypotF64 } from "std:math"
    function over(x: i32) { x + 1 }
    function f(k: i32) {
      let a = 0
      for i in 0 until k {
        a += over(i)
      }
      const h = () => over(a)
      const over = 3
      print(h() + over)
      over + hypotF64(3.0, 4.0) as! i32 - 3
    }
    print(f(2))
    // vl check (before): undeclared identifier 'over' at 6:10 and 8:19.

Want:

    7
    5

#### Mechanism

The merge renames each module's top-level names (`over` becomes `over$m0`) and leaves a name
alone where a local shadows it. `modRwBlock` (`compiler/driver.vl`) collected every `let`/`const`
of a block before rewriting any of it, so a block-local `const over` kept the name `over` for
the whole block, including the reads above it. The checker resolves those reads to the module's
function, which by then was named `over$m0`, so `over` was undeclared there. A `let`/`const` now
starts shadowing at its own declaration, after its initializer is rewritten. A block-local
`function` still shadows the whole block, because it is hoisted.

#### Ablation

| ingredient | outcome |
| --- | --- |
| no import (single-module compile) | runs before and after |
| the import | refused before, runs after |
| the read inside a loop, an `if`, or a lambda above the `const` | refused before, runs after |
| the read below the `const` | the `const`; calling it is D3599's error |

#### Grading list

`tests/cases/scope/module-function-read-above-local-shadow.vl`. Not fixed here: a lambda created
above a later local named like a NUMERIC BUILTIN, which calls the builtin
(`const f = () => floor(x); const floor = 0.25`), is check-clean and the emitter refuses it with
`call to unknown function`. The capture scan (`capRecord`, `compiler/emit_classify.vl`) treats
the later local as captured, because its frame lookup ignores where the local is declared.
