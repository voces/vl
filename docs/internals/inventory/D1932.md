### D1932 — a HALF-declared index operator refuses at EMIT through a hole, where an annotated receiver refuses at CHECK: `indexFloorMsg` answers "" for a set-only receiver it should reject

**now a loud check reject (closed 2026-09-08 by [D1892](D1892.md)'s pin banking, naming the missing half) · was a loud emit reject, `vl check` rc 0, clause 2 · found by D1892's control grid · fixture `tests/cases/operators/index-overload-half-declared-through-hole.vl`**

Repro:

    type Box = new { x: i32 }
    function "[]="(self: Box, i: i32, k: i32) { print(self.x + i + k) }
    function mkval(): Box {
      const r: Box = { x: 3 }
      return r
    }
    function take(p) { print(p[4]) }
    take(mkval())
    // vl check (before): rc 0.  vl run: emitProgram: index access but array type not collected
    // vl check (after): operator "[]=" for Box needs a matching "[]" operator —
    //                   an index that cannot be READ cannot be written either

#### Mechanism

`indexFloorMsg` — the pin's index-read floor — returns "" (no error) when the receiver has
EITHER a `"[]"` or a `"[]="` operator. That is right for a read of a receiver with a getter,
and wrong for a read of a receiver with only a setter: a SET-only type has no readable index,
and the inline arm says so at an annotated receiver (`an index that cannot be READ cannot be
written either`). The hole path had no such arm, so the read passed `vl check` and fell to the
emitter, which met a raw `Index` over a receiver with no list rep — the same emit reject
[D1892](D1892.md) closes, reached by a different check-side hole.

The write mirror is the same shape: a GET-only receiver written through a hole
(`p[4] = 5`) passed check and emit-refused, where an annotated one is a loud check reject.
Both are closed at the pin: the GET-constraint arm now names the missing `"[]"` when only a
setter resolves, and the SET-constraint arm names the missing `"[]="` when only a getter does.

#### Ablation

| ingredient removed | outcome | needed? |
| --- | --- | --- |
| the operator is set-ONLY (declare `"[]"` too) | runs, prints `7` | **yes** |
| the parameter is un-annotated (`take(p: Box)`) | refused before, at CHECK | **yes** |
| it is a READ (make it `p[4] = 5`, GET-only) | the write mirror, same close | no |
| the `new` brand on `Box` | still refuses | no |

#### Grading list

The full-operator witness (`"[]"` and `"[]="` both declared, un-annotated) must RUN —
[D1892](D1892.md)'s fixture. The annotated set-only read and get-only write already refused at
CHECK and must keep their exact sentences (`needs a matching "[]"` / `no "[]=" operator`). A
scalar receiver with no operator at all stays a `cannot index non-array` refusal — the missing
half is only named when the other half is present.
