### D3739 — a top-level fresh `const` after a function re-walks the whole program for its sole-reference check

**closed 2026-10-06 by lane CT · runs, as it always did · was a cost row: 850 MB, a quarter of the compiler's self-compile allocation · found by lane GH · filed 2026-10-06 against master `7529a4ea6` · pin: the `allocation: top-level fresh consts between functions` axis in `tests/vl_scaling_shape_test.ts`**

Repro:

    function f(n: i32): i32 {
      const p = { v: n }
      p.v + 1
    }
    const a = { v: f(1) }
    function g(n: i32): i32 {
      const q = { v: n }
      q.v + 2
    }
    const b = { v: g(1) }
    print(a.v + b.v)
    // vl check: rc 0.  vl run: prints 5. `a` and `b` each walked the whole program.

Want:

    5

#### Mechanism

`crNoteSoleRef` (typecheck.vl, D2584) asks `crValUseWalk` for the names a root uses as
something other than a receiver. It cached one root, `crValUseRoot`. A fresh `const` inside a
function asks about that function's root, and a fresh `const` at the top level asks about
`crProgRoot`, the whole program, so a program that alternates between the two re-walked the
whole program on every return to the top level: 49 walks of a 754,703-node arena on the
compiler's self-compile, 33 on sunpa's `game.vl`.

The walk is not a function of the syntax tree alone, though the memo census called it that:
a `x.p` site counts `x` only when the checker has banked a getter there (`getSiteFnOf`), and a
`x[i]` site only when it dispatches to an operator (`opSiteDecls`). Both tables fill in place as
checking proceeds, so a cache of the walk's answer would be stale. The close splits the walk.
The part that reads only the tree is cached per root (`crValUseEnter`), together with the list
of the `x.p` and `x[i]` sites whose receiver the two tables decide. Each entry to a root reads
those sites against the tables as they stand, which is when the old walk read them. A root is
walked again when the arena epoch moved since its walk. The program's root instead adds the
subtrees of the slots that the logged in-place edits rewrote (`arenaNoteEdit`, ast.vl), when
every epoch bump since its walk was a logged edit. Those edits fold literals, lower `match`
chains and splice blocks; none adds a name, and a name one removes stays counted, which can only
make a binding look shared.

A dual-run compiler that also ran the old walk at every entry and trapped on any differing
answer built the compiler, sunpa's `game.vl` and all 4,532 `tests/cases` programs without
trapping. Its control, the same compiler with the getter and operator sites ignored, trapped
on 22 of those programs.

Self-compile (L2, null collector): fuel 69.71G to 60.31G, allocation 3.18 GB to 2.34 GB.
sunpa's `game.vl`: fuel 81.93G to 79.78G, allocation 2.36 GB to 2.24 GB. Output byte-identical.

#### Ablation

| ingredient changed | outcome | needed? |
| --- | --- | --- |
| the fresh `const` inside each function | one whole-program walk | **yes**: the alternation is the cost |
| the top-level `const`s | no whole-program walk | **yes** |
| a top-level `if true { const a = … }` block instead of a global | the same walk (no function base, so the program's root) | no: the axis uses it, since a global's own destination pins are a separate cost |
