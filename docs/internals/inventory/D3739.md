### D3739 — a top-level fresh `const` after a function re-walks the whole program for its sole-reference check

**runs today and must keep running · a cost row: 850 MB, a quarter of the compiler's self-compile allocation · found by lane GH · filed 2026-10-06 against master `7529a4ea6`**

Repro:

    function f(n: i32): i32 {
      const p = { v: n }
      p.v + 1
    }
    const a = { v: f(1) }
    function g(n: i32): i32 {
      const q = { v: n }
      q.v + 2
    }
    const b = { v: g(1) }
    print(a.v + b.v)
    // vl check: rc 0.  vl run: prints 5. `a` and `b` each walk the whole program.

Want:

    5

#### Mechanism

`crNoteSoleRef` (typecheck.vl, D2584) asks `crValUseWalk` for the names a root uses as
something other than a receiver. It caches one root, `crValUseRoot`. A fresh `const` inside a
function asks about that function's root, and a fresh `const` at the top level asks about
`crProgRoot`, the whole program. A program that alternates between the two re-walks the whole
program on every return to the top level. The compiler's self-compile does 49 such walks over a
754,703-node arena, 34.3M node visits, about 850 MB allocated (mostly `nodeChildren` arrays).
sunpa's `game.vl` does 33 walks, 8.5M visits. That is 25% of the self-compile's allocation.

The walk is not a function of the syntax tree alone, though the memo census says it is.
`getSiteFnOf` and `opSiteDecls` read getter and operator-site tables that the checker fills as
it reaches each function. A cache of the whole-program walk therefore needs a key over those
tables, not just the root.
