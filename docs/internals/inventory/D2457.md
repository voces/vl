### D2457 — a nested generic passing its own `T` through an un-annotated lambda to an inner generic has no monomorphization pin

**closed 2026-09-25 — the filed repro RUNS and prints `7` · was a loud emit reject · clause 2 · found reviewing #3152, filed 2026-09-25 against master `20651a88b` · closed by D2551/D2552 (the lambda's inferred parameter and the argument's function type pinned per instance); `outer("s")` prints `s` · fixture `tests/cases/std/generic-closure-forward.vl` covers the forwarding hop**

Repro:

    function outer<T>(x: T) {
      function ap<U>(f: (U) => U, y: U) { return f(y) }
      return ap((v) => v, x)
    }
    print(outer(7))
    // vl check: rc 0.
    // vl run: emit error, emitProgram: monomorphize: unsupported argument type for `f` in a
    // call to `ap`.

#### Mechanism

Not yet located. The inner call binds `U` to the OUTER type variable `T`, so the lambda is
seeded `(T) => T` with the argument order fixed (D2426); the inner instance is minted per
outer instance, and at that point the lambda's recorded type still names `T`, so
`monoArgFnTypeName` answers "" as it did for D2426 before its close.
