### D13360 — an `if` choosing generic functions, handed to a hole parameter its callee calls at two types, is refused at emit

**closed 2026-10-25 · runs, prints `a` and `1` · fixed: a choice of generics no one pin closes asks the split plan for a parameter per type (`monoHoleGenFnPin`, emit_mono.vl), and the plan runs the choice once before its statement into an arm index that selects each slot's argument (`fsChoiceArgStmt`, `fsPlanChoiceArg`, `fsApplyChoiceRets`, fn_split.vl) · pins: `tests/cases/generics/hole-fn-choice-arg-two-keys.vl` · was loud emit reject, clause 2 · `monomorphize: unsupported argument type for `f` in a call to `both`` · pre-existing on master `247fb2679` · found closing [D13282](D13282.md) · filed 2026-10-25 against master `d63e667e7`**

Repro:

    function both(f) {
      print(f("a"))
      print(f(1))
    }
    function inner(s) { return s }
    function ask(s) { return s }
    function g(c: boolean) {
      both(if c { inner } else { ask })
    }
    g(true)
    // vl check: rc 0.  vl run: emitProgram: monomorphize: unsupported argument type for `f` in a call to `both`

Want:

    a
    1

#### Mechanism

From the code path, not ablated to a line. A single generic handed to a hole called at two
types is split, one parameter per type (D6210, D6280). An `if` naming generics takes one closed
type, from the checker's binding or from the one flow pin of an arm's read
(`monoChoiceArmFlowTy`, emit_mono.vl); two pins give none, and the split plan has no arm for
a choice, so the argument classifier refuses.
