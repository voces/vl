### D1521 — a function whose INFERRED return is a union gets no result box when a return arm's type derives from an un-annotated parameter's hole

**check-clean invalid wasm · clause 1 · reported by the `~/glean` WC3 replay player as **VL-005**, VL's first external consumer, at their pin `2fb8b271` · filed against master `bd500845` · ZERO corpus cells**

Repro:

    type Err = { msg: string }
    function decl(n: i32): i32 | Err {
      if n > 0 { return { msg: "d" } }
      n
    }
    function tryParse2(x) {
      const y = x * 2
      if y > 10 { return { msg: "too big" } }
      y
    }
    const r3 = tryParse2(9)
    if r3 is Err { print(r3.msg) } else { print(r3) }
    const rd = decl(0)
    if rd is Err { print(rd.msg) } else { print(rd) }
    // vl check: rc 0.  vl run: Invalid input WebAssembly code at offset 372:
    //   type mismatch: expected (ref $type), found i32
    // Should print "too big" then 0.

#### Mechanism

`tryParse2`'s emitted functype result is `(ref $Err)` — the STRUCT's own ref type, not the
`{tag, payload}` union box `decl` gets — so the `Err` arm's `struct.new` matches and the
scalar arm's `local.get` (an i32) does not. The union is never formed at the rep level.

Two gates decline in series, both on the same ingredient. `a20RetSetDisagrees` skips a
return whose type carries a type VARIABLE, so with `y` derived from the hole `x` it sees
only ONE concrete arm, `retIsConcreteUnion` stays false, the un-annotated parameter makes
the A20 recorder call the function generic, and no inferred-return row is banked. One pass
later `monoRetJoinDisagrees` declines to mint the instance's return annotation for the same
reason its own header gives, leaving the instance "to the return-inference path that already
handles a union result" — which, with no A20 row, does not.

`decl` is SCENERY that selects the FACE, not part of the mechanism: it is the only thing in
the module that declares `i32 | Err`, and without it the same program is a clause-2 loud
`emitProgram: \`is\` test but no union type declared` instead. Both faces are identical at
the consumer's pin `2fb8b271` and at master `bd500845` — the defect did not move; the
minimal program they filed dropped the declaration and so shows the other face.

#### Grading list

Both faces, and the second call shape: a module with the union declared elsewhere, and one
without. Re-grade [D1520](D1520.md) (their VL-004) — same un-annotated parameter, different
mechanism — and the two-instantiation spelling (`tryParse2(1)` beside `tryParse2(1.5)`),
which is why a name-keyed A20 row cannot be the whole answer.
