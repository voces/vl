### D1521 — a function whose INFERRED return is a union gets no result box when a return arm's type derives from an un-annotated parameter's hole

**closed 2026-09-03 (`monoInferRetSetUnionName` mints the joined return set at the pin) · was check-clean invalid wasm, clause 1 · reported by the `~/glean` WC3 replay player as **VL-005**, VL's first external consumer, at their pin `2fb8b271` · filed against master `bd500845` · ZERO corpus cells**

Repro (prints `too big` then `0`; was invalid wasm):

    type Err = { msg: string }
    function decl(n: i32): i32 | Err {
      if n > 0 { return { msg: "d" } }
      n
    }
    function tryParse2(x) {
      const y = x * 2
      if y > 10 { return { msg: "too big" } }
      y
    }
    const r3 = tryParse2(9)
    if r3 is Err { print(r3.msg) } else { print(r3) }
    const rd = decl(0)
    if rd is Err { print(rd.msg) } else { print(rd) }
    // was: Invalid input WebAssembly code at offset 372:
    //   type mismatch: expected (ref $type), found i32

#### Mechanism

`tryParse2`'s emitted functype result was `(ref $Err)` — the STRUCT's own ref type, not the
`{tag, payload}` box `decl` gets — so the `Err` arm's `struct.new` matched and the scalar
arm's `local.get` did not. The union was never formed at the rep level.

Two gates declined in series on the same ingredient. `a20RetSetDisagrees` skips a return
whose type carries a type VARIABLE, so with `y` derived from the hole `x` it saw only ONE
concrete arm, `retIsConcreteUnion` stayed false, the un-annotated parameter made the A20
recorder call the declaration generic, and no inferred-return row was banked. One pass later
`monoRetJoinDisagrees` declined to mint the instance's return for the same reason, leaving it
to "the return-inference path that already handles a union result" — which, with no A20 row,
does not.

The fix is at the PIN, and it has to be: the parameters are bound there, so one function is
`Err | i32` at one call and `Err | f64` at the next (the fixture calls `twoWays` both ways in
one program). A name-keyed A20 row could hold only one of them, which is exactly what D970's
skip was protecting. `monoInferRetSetUnionName` re-checks EVERY valued return under the pin,
joins them, renders through the three A20 renderers so `registerInlineUnion` claims the name,
and `monoRegisterPinUnion` registers it — `collectU` ran before this pass and nothing re-runs
it. A still-holey arm declines the whole set, so the deferred-join family is untouched.

#### The clause the consumer reported, and the clause on master

Their minimal program dropped the only declaration of `i32 | Err` in the module, and that
declaration is what selects the FACE. Graded on a seed self-compiled from their own pin
`2fb8b271` (fixpoint-proven) and on master `bd500845`, the two agree exactly — the defect
did not move between the commits:

| program | at `2fb8b271` | at `bd500845` |
| --- | --- | --- |
| their filed minimal (no `i32 \| Err` declared) | `emitProgram: `is` test but no union type declared` | same |
| the same body with the union declared | `offset 372: expected (ref $type), found i32` | same (offset 372) |

So the message they filed belongs to a LARGER program of theirs (their `t6.vl`, whose
`function[6]` and offset 393 say so) and the minimal one they reduced it to shows the other
face. Both are this row, and both run now.
