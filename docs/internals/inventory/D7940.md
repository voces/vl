#### Mechanism

D7801 banked a target from a check with errors only when G held them all. A target whose G held
none still declined `dirty`, and on diderven with one injected error that was 17 roots, 198
module checks. Such a target is now banked clean, with only the diagnostics placed in G, unless
an error outside G could have changed G's check. Five channels can, and each is guarded:

- an adoption the check undid (`pinAdoptUndid`, check_pins.vl);
- a width rewrite it declined or undid (`wsRefusalUndid`, check_width.vl);
- a refusal it dropped as a repeat of an earlier one, keyed by message or type
  (`diagKeyDrops`); the outside error may be the first report;
- a deep `is` site in G (`wiDeepIsIn`): the second pass runs only on a check with no errors,
  so G's own clean check runs it and the importer's did not;
- the redundant-annotation hints, which a check with errors drops; `pinHintReport` now
  withholds them instead (`redunWithhold`), and a clean target banked from such a check
  reports the withheld rows (`wiBankedHeld`, `wiHeldSwap`).

The repeat-refusal and deep-`is` halves have mask witnesses (`8192`). The adoption and width
halves are defensive: no graph found prints a different answer once they are dropped.

The unknown type name in a signature that D7801 cited as an error no module places is placed:
it declines because the name is a miss the CLI's sibling scan may answer (`mimpMissed`), and
that guard declines every target of the check.
