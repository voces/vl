### D14531 — a call in a list literal read without a binding keeps its record at its own row while another call of the same function delivers it as a declared record

**closed · now runs, prints `3` · was check-clean invalid wasm, clause 1 · filed 2026-10-27 against master `7480d5bae` · closed 2026-10-31 against master `ef8c85e1`: `recReadInPlace` (check_fit_rules.vl) follows an element of a list literal that is only indexed to where the index read is, so `mkcall` is built at `Circle` and the list holds it there · the same list handed to a generic (`first([mkcall()])`, `reverse([mkcall()])[0]`) is [D14731](D14731.md) · fixture `lists/call-in-list-literal-read-in-place-built-at-delivery.vl`**

Repro:

    type Circle = { r: i32 | null }
    function sink(_x: Circle) { }
    function mkcall() {
      const cc = { r: null }
      return cc
    }
    sink(mkcall())
    const y = [mkcall()][0]
    print(y.r ?? 3)

Want:

    3

#### Mechanism

`sink(mkcall())` builds `mkcall`'s record at `Circle`. [D14519](D14519.md)'s container rule names
a list literal only as a binding's initializer (`recLitDeclOf`), so `[mkcall()]` read in place is no
container and keeps `mkcall`'s own row while `sink` receives the record as `Circle`. Both seeds fail
validation on line 7.
