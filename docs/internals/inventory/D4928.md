### D4928 — a list narrowed by `is K[]` is delivered as `K[]` and later written through its wider type

**check-clean silently wrong value · clause 1 · related to D4771 (`is` over a list tests every element) and D4926 (the narrowing outliving a write) · filed 2026-10-15 against master `23dcd80be`**

Repro:

    type K = 0 | 1
    const b: i32[] = [0, 1]
    let k: K[] = []
    if (b is K[]) { k = b }
    b[0] = 5
    const e: K = k[0]
    print(e)
    // vl check: rc 0.  vl run: prints 5, a value outside K
    // PRINTS 5

#### Mechanism

Inside the guard `b` reads as `K[]`, and the assignment delivers that same list object into a
binding whose declared type is `K[]`. The binding outlives the guard, so a store through `b`'s
declared `i32[]` after the `if` changes what `k` holds without any narrowing for D4926's
retirement to end. A narrowed list is only safe to read at the narrowed element type, never
to deliver at it.

#### Ablation

| ingredient changed | outcome | needed? |
| --- | --- | --- |
| `b[0] = 5` removed | prints 0, right | **yes** (a later write through the wider type) |
| `k = b.map((x) => x as K)` style copy | a separate list, right | **yes** (the same list object) |

#### Grading list

The other delivery positions: an argument to a `K[]` parameter, a return from a `K[]`
function, a record field of type `K[]`, and a capture.
