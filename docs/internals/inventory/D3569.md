### D3569 — an un-annotated kept-apart join of two numbers and `null`, joined again with itself, folds the numbers and reads the `i32` member as `null`

**closed 2026-10-03 — the witness prints `3` · was check-clean silently wrong, clause 1 · found by lane KJ's no-lambda port of the #3344 review's `c1.vl` · filed and closed against master `3b9319528` · fixture `tests/cases/generics/kept-apart-join-rejoined-keeps-numbers.vl`**

Repro:

    function F<A, B>(k: i32, a: A, b: B) {
      const w = if k == 0 { a } else if k == 1 { b } else { null }
      const v = if k >= 0 { w } else { w }
      print(v)
    }
    F(0, 3, 4.5)

Want:

    3

#### Mechanism

The checker joins two runtime arms of a type parameter apart and marks that join so an
instance re-joins its members apart too (`markTpJoinApart`). `joinArmLit` returned early when
both arms had one type, and `joinArmTys(w, w)` mints a fresh kept-apart join without the mark.
At `(i32, f64)` the substitution then joined `i32` and `f64` to `f64`, so `v` took an
`f64 | null` slot while `w` held the three-tag box, and the `i32` tag fell to the `null` arm of
every reader. A join of a marked join with itself now carries the mark. The annotated face, whose
join the checker never kept apart, traps on its `null` instead: [D3594](D3594.md).
