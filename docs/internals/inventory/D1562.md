#### Mechanism

`buildFnMap`'s name ladder classifies an un-annotated return from the NAME the checker
recorded. It had a `nulstruct` arm (`inferNulStructRow`, D887) and no nullable-VARIANT twin,
and the struct twin cannot answer for one: `collectS` gives a union ARM no struct row, so
`structIndexOfTypeName("Hit")` is -1 and the whole ladder fell through to its `"i32"` default.
`inferNulVariantRow` is that twin, one index space over — `variantIndexOf` on the same
`nullablePartOf` cut, which is where the ANNOTATED spelling's `nulVariantIndexOf` ends too, so
the two faces name one row.

**THE ARM ALONE DOES NOT HOLD, BECAUSE `retKindPri` HAD NO TIER FOR THE KIND.** With
`"nulvariant"` seeded, `criClassify` then reaches `exprNullableStruct`, whose per-node fallback
`nodeTyIsNullableStruct` reads the checker's type and cannot tell a union ARM from a standalone
struct — it answers TRUE. Absent from the priority ladder the kind ranks 0, so that tier-5
`criSetRetKind(i, "nulstruct")` won, and its payload came from `fnRetStructIndexSid`, which is
kind-gated and has no row for a variant: the pair reaching `fbValtype` was (`"nulvariant"`'s
heap, -1). The fix is the tier, not a fourth `!=` guard on that arm — `nulvariant` shares
`nulstruct`'s tier exactly as `variant` shares `struct`'s, and for the identical stated reason:
a return is a nullable plain struct or a nullable union arm, never both, so neither fact may
overwrite the other and `criSetRetKind`'s strict `>` is that refusal.

**FOUR SITES, EACH LOAD-BEARING BY MEASUREMENT.** The name ladder and the tier get the KIND
right; the two companion-slot readers get the SLOT. `emitOneFuncType`'s inferred arm (the
signature half) and `cloRetValSlot` (the call-result half, which `nulVariantIdxOfExpr`'s Call
arm declares an inferred binding's cell from) each already carried a `variant` line and no
nullable one. Ablated one at a time against the position matrix: neither alone (45), the
signature alone (46), both (47) — one cell each, and the witness needs the call-result half.

A FIFTH SITE WAS PREDICTED AND IS NOT NEEDED. The return-site value seed (`wasmEmit`'s
`pendingVariantIdx` / `pendingNulRefHeap`, D887's arm one kind over) already fires off
`retNulVariantFlag`'s neighbouring inferred path: a bare `return null` beside a nulvariant call
lowers correctly with the four sites above and nothing else — graded, it prints `7` then `-1`.
