### D2421 — a `let x = null` hole that only a closure fills is boxed as a list of `null`

**loud emit reject · clause 2 · filed 2026-09-25 against master `a277bf7b0`, the residue of
[D2392](D2392.md)'s close**

Repro:

    function f(): i32 {
      let x = null
      const k = () => { x = 5 }
      k()
      if x != null { return x + 1 }
      0
    }
    print(f())
    // vl check: rc 0.  vl run: emit error: bare null needs a struct-typed context

#### Mechanism

`captureBoxRewrite` types an un-annotated cell as a list of its initializer's recorded type,
and a hole's initializer is the bare `null`, whose type is the unfilled hole rather than the
`i32 | null` the closure's write fills it to. The cell literal `[null]` then has no element
rep to build the `null` at. The annotated face takes its cell type from the annotation.

#### Ablation

On master `a277bf7b0`, and the same with D2392's close applied.

| --- | --- | --- |
| inference (`let x: i32 \| null = null`) | runs, `6` | **yes** |
| the closure's write (`x = 5` in `f`, the closure only reads) | runs, `6` | **yes** |
| the `i32` fill (`x = "w"`, a `string \| null` niche) | still refuses | no |
