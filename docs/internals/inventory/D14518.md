### D14518 — a call stored into an un-annotated `Map()` through a binding is built at its own row while the binding's other delivery builds it wider

**open · check-clean invalid wasm, clause 1 · filed 2026-10-27 against master `eef670449`, present there and after D14517**

Repro:

    type J = { f: i32 | null }
    function mk() { { f: 4 } }
    const wideJ: J = mk()
    const m = Map()
    const a = mk()
    m.set("a", a)
    const x = m.get("a")
    if x != null { print(x.f + 1) }
    print(wideJ.f ?? 0)

Want:

    5
    4

#### Mechanism

`const wideJ: J = mk()` builds `mk`'s record at `J`. The other call, `const a = mk()`, is queued
for no delivery and is not read for a field (`recReadInPlace`), so `recSitesLandAt` declines and
`mk` builds at its own row; `wideJ` then receives it as `J` and the module fails to validate.
[D14517](D14517.md) serves a call stored directly into the map, not one held by a binding first.
