### D14518 — a call stored into an un-annotated `Map()` through a binding is built at its own row while the binding's other delivery builds it wider

**closed · now runs, prints `5` / `4` · was check-clean invalid wasm, clause 1 · filed 2026-10-27 against master `eef670449`, closed 2026-10-27 against `76227d1d5` · closed by `recHeldStored` (check_fit_rules.vl) serving a call whose binding is only stored or read for a field, and `recKeptStoreDecls` handing the container it is stored into to `recStoresAgree`: a binding holding a call counts as the build it holds · fixtures `maps/unannotated-map-binding-value-built-at-wider-record.vl`, `lists/unannotated-list-binding-element-built-at-wider-record.vl`**

Repro:

    type J = { f: i32 | null }
    function mk() { { f: 4 } }
    const wideJ: J = mk()
    const m = Map()
    const a = mk()
    m.set("a", a)
    const x = m.get("a")
    if x != null { print(x.f + 1) }
    print(wideJ.f ?? 0)

Want:

    5
    4

#### Mechanism

`const wideJ: J = mk()` builds `mk`'s record at `J`. The other call, `const a = mk()`, is queued
for no delivery and is not read for a field (`recReadInPlace`), so `recSitesLandAt` declines and
`mk` builds at its own row; `wideJ` then receives it as `J` and the module fails to validate.
[D14517](D14517.md) serves a call stored directly into the map, not one held by a binding first.

#### Close

The list element of [D14515](D14515.md) kind 2 is the same mechanism: a value stored into an
un-annotated container (a `Map()` store, a list-literal element, or an index store into a list
literal binding), directly or through a `const` that holds it, counts as that container's build.
One rule serves both: `recStoreDeclOf` names the container and `recStoresAgree` builds its values
where every stored value is built, refusing each store at its own row where they land apart.
