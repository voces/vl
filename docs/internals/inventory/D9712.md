### D9712 — `.map` over a nested list of an un-annotated function, calling the inner element, is refused as a call with no callee

**closed · runs, prints `6` · was loud emit reject, `vl check` rc 0, `a call statement's callee is neither a name, a member, nor a function value`, clause 2 · CAPABILITY: `for r in v { print(r[0](5)) }` runs · found closing [D9662](D9662.md) · filed 2026-10-22 against master `e8163edd5` · closed by instancing the callback at the receiver's row type when the receiver is a closed list of function lists (`monoBuiltinCbRecv`, `monoCbFnListRowSpell`, `monoPinLamFromCheckedTy`, emit_mono.vl) · fixture `closures/hole-fn-nested-list-map-row-call.vl` · with [D9710](D9710.md) closed**

Repro:

    function inc(a) { return a + 1 }
    const v = [[inc]]
    print(v.map((r) => r[0](5))[0])
    // vl check rc 0.  vl run: emit error: emitProgram: a call statement's callee is neither a name, a member, nor a function value

Want:

    6

#### Mechanism

The callback's parameter `r` is un-annotated, so its instance was taken from the checker's type
for the lambda, whose parameter is the inner list with its element still open at a function. The
call `r[0](5)` then had no function-value type to call through. The callback is now instanced at
the receiver's row spelling, `((a: i32) => i32)[]`, once mono has closed the receiver.

#### Ablation

| ingredient removed | outcome | needed? |
| --- | --- | --- |
| the un-annotated parameter of `inc` (`inc(a: i32): i32`) | runs, `6` | **yes** |
| the `.map` (`const r = v[0]`, `print(r[0](5))`) | runs, `6` | **yes** |
| the `.map`, for a loop (`for r in v { print(r[0](5)) }`) | runs, `6` | **yes** |
