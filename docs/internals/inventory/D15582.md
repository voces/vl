### D15582 — a hole lambda a closed function pushes onto a list, capturing its parameter, is never built when the list is called with a closed function

**loud emit reject · `vl check` rc 0, then `emitProgram: call to unknown function` · clause 2 · CAPABILITY: the same program runs with `snd` un-annotated, with `apply2`'s parameter annotated, or with the lambda capturing a module `const` · found closing [D15580](D15580.md) · filed 2026-11-09 against #6940's head `88dfe69e`**

Repro:

    function snd(a: string, b: i32) { return b }
    function apply2(g) { print(g("x", 2)) }
    const fs = [apply2]
    function add(k: i32) {
      fs.push((g) => { print(g("z", k)) })
    }
    add(9)
    for f in fs { f(snd) }
    // vl check: rc 0.  vl run: emitProgram: call to unknown function

#### Mechanism

Mono builds a hole lambda in a list at the call through the list only when the call hands a
generic function or a hole lambda (`monoElemArgNamesFn`, emit_mono.vl). A closed `snd` is
neither, so `monoOpenCallAtElems` declines, and the push's value read names the lambda's
template, which no build made. The elaboration has the instance (D15580); mono does not build it.
