### D14724 — a top-level member read of one generic's result is re-checked as another generic's body constraint, where a phantom alias binds the type parameter at `i32`

**loud check reject · clause 2 · the program is type-valid · found writing the D12601 fixture · filed 2026-10-31 against master `24bf6782f`**

Repro:

    type P = { a: i32, b: i32 }
    type Rows<T> = { base: i32, count: i32 }
    function pick<T>(_r: Rows<T>, x: T): T { x }
    function mk<T>(base: i32): Rows<T> { return { base: base, count: 1 } }
    const su = mk<P>(8)
    const q = pick(su, { a: 3, b: 4 })
    print(q.a + q.b)
    function wrap<T>(_r: Rows<T>): i32 { return 1 }
    const st2: Rows<i32> = { base: 1000, count: 4 }
    print(wrap(st2))
    // vl check: member access '.a' on non-object i32 (the body of `wrap` at the call's argument types)

Want:

    7
    1

#### Mechanism

Not yet located. The `.a` / `.b` reads are top-level reads of `q`, `pick`'s result at `P`. They
are re-checked as `wrap`'s body's deferred constraints at `wrap(st2)`'s binding `T = i32`, though
`wrap`'s body reads nothing: a constraint attributed to the wrong owner. Each half of the program
checks clean alone.
