### D2456 — a literal-union value pinned into a generic's hole and read inside a closure has no string widening

**loud emit reject · clause 2 · found reviewing #3152, filed 2026-09-25 against master `20651a88b`**

Repro:

    const su: "a" | "b" = "b"
    function show<T>(a: T) { const c = () => "v=\{a}"
      return c() }
    print(show(su))
    // vl check: rc 0.
    // vl run: emit error, emitProgram: literal-union string widening with no members.

#### Mechanism

Not yet located. `T` pins to the named literal union, whose rep is an interned i32 atom, and
the closure captures `a`. Widening the atom to its member string inside the lifted closure
finds no member list, apparently because the capture carries the atom rep without the union
it came from. On master the template spelling refused at check (the `toString` demand, D2241),
so #3152 moved it from a check refusal to this emit refusal. The `+` spelling is this row on
master too.

#### Ablation

| ingredient changed | outcome | needed? |
| --- | --- | --- |
| `"v=" + a` instead of the template | same refusal, on master too | no |
| no closure, `return "v=\{a}"` | runs, `v=b` | the closure: **yes** |
| `a: "a" \| "b"` annotated, not generic | runs, `v=b` | the pin: **yes** |
| the closure returns `a` itself | runs, prints `b` | the widening: **yes** |
| method spelling `su.show()` over `show<T>(self: T): string` with the closure | master printed `v=0` (silently wrong); now this refusal | no |

#### Grading list

The `+` spelling and the method spelling in the ablation.
