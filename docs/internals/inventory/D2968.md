### D2968 — a spread in a generic returning `(T | string)[]` builds invalid wasm at a literal-union pin

**closed 2026-11-02 by lane column-G1 · runs, prints `3`, `y`, `2` · was check-clean invalid wasm, clause 1 · D2868's spread of literal-union atoms into a `string[]` asks each source's element for its member texts (`spreadSrcAtomTexts`), and read it off the template's type, where a generic body's source is `T[]`, so at the `K` pin the literal was built as an atom list and the `"s"` part stored into it; the element is now read at the instance (`nodeTyAt`), so the spread widens each atom to its string as the direct spelling does · the `i32` pin's loud emit refusal (a spread whose elements must each be boxed) is unchanged · fixture `tests/cases/literal-unions/spread-atoms-into-generic-string-union-list.vl` (appended and prepended spreads, a second `string[]` pin, a loop over the result) · found by the #3246 review · filed 2026-09-28 against master `fe1fa1bec`**

#### Mechanism

Not localised. The instance at `T = K` joins a literal-union atom list with a `string` inside a
generic body, where the literal's recorded type is the template's `(T | string)[]`, so neither
D2868's string-list spread (which reads a concrete `string[]` element) nor the boxing spread
(which needs a union-box row) claims it. The validator names a `std:str` instance, which says
the wrong list type leaked into a shared instance rather than staying in `ws`.
