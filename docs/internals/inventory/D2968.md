### D2968 — a spread in a generic returning `(T | string)[]` builds invalid wasm at a literal-union pin

**closed 2026-11-02 · runs, prints `3` `y` `2` · was check-clean invalid wasm, clause 1 · fixture `tests/cases/generics/spread-scalar-list-into-union-at-pin.vl` · found by the #3246 review, the same on master `fe1fa1bec` · filed 2026-09-28 against master `fe1fa1bec`**

Repro:

    function ws<T>(xs: T[]): (T | string)[] { return [...xs, "s"] }
    type K = "x" | "y"
    const pb: K[] = ["y", "x"]
    const g_K = ws(pb)
    print(g_K.length)
    const g_K0 = g_K[0]
    if g_K0 is K { const e = g_K0
     print("\{e}") }
    g_K.push(g_K[0])
    print(pb.length)
    // vl check: rc 0.  vl run: invalid module inside `split$m2` (std:str)

Want:

    3
    y
    2

#### Mechanism

Not localised. The instance at `T = K` joins a literal-union atom list with a `string` inside a
generic body, where the literal's recorded type is the template's `(T | string)[]`, so neither
D2868's string-list spread (which reads a concrete `string[]` element) nor the boxing spread
(which needs a union-box row) claims it. The validator names a `std:str` instance, which says
the wrong list type leaked into a shared instance rather than staying in `ws`.

#### Close

The spread literal's classifiers read the template's types, so at the pin the literal was still
`(T | string)[]` with a `T[]` source. They are `spreadLitElemIsString`, `spreadLitScalarElem`,
`spreadLitElemRow`, `spreadBoxingSource`, `spreadSrcAtomTexts` and `spreadSrcBoxAtom`. The
direct spelling of each pin ran. They now read the instance's types (`nodeTyAt`). At `T := K`
the literal is the instance's `string[]`, and each atom widens to its string (D2868). At
`T := i32`, `f64` or `i64` each element is boxed into `T | string`. Those spellings were loud
emit rejects, and they run too. A `K` or `boolean` pin into `(T | i32)[]` or `(T | null)[]` is
still refused, because the direct spelling refuses it too.
