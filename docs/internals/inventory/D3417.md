### D3417 — an array literal costs about 30,000 compiler fuel and 1.3 KB of never-freed heap per element, so a 2.7-million-element literal cannot be built

**closed · runs, prints `2700001` · was check-clean invalid wasm (the emitted module is refused by the engine: `function body size count exceeds limit of 7654321`) · a cost row at plumb scale · found by the #3317 review planning · filed 2026-09-30 against master `5e277ab52` · fixtures `tests/cases/arrays/long-literal-u8-data-segment.vl`, `tests/cases/arrays/long-literal-widths-exact.vl` · closed 2026-09-30, the residues are D3464 and D3465**

Repro:

    const xs: i32[] = [@@repeat(2700000, "300,")@@300]
    print(xs.length)
    // vl check: rc 0.  vl run: "failed to parse WebAssembly module: function body
    // size count exceeds limit of 7654321" (vl build: the same, exit 70)

Want:

    2700001

#### Mechanism

Two halves, both closed. The SIZE half: a scalar literal past the 10,000-operand `array.new_fixed`
cap lowered as straight-line code, a few instructions per element in one function body, so the
body reached wasmtime's 7,654,321-byte limit between 2.5 and 2.7 million elements. The `vl run`
half: `vl build` only validates the module, while `vl run` has Cranelift compile it, and Cranelift
over that body is super-linear (100,000 elements 6.6 s, 1,000,000 106.7 s and 9.8 GB, the compile
of the emitted module, not the guest). A literal past the cap whose every element is a number or
boolean literal is now one passive data segment read by `array.new_data` (`arrLitDataBuild`,
compiler/wasmEmit.vl), each element emitted through the literal's own element lowering and its one
constant instruction decoded into the segment, so the values are the ones the old lowering built;
the function body is a few bytes whatever the length. A literal with any computed element keeps the
chunked build. The same path gives a `u8[]` literal past the cap a lowering where it had a refusal.
The compile cost was a third, smaller half: `arrLitIsF64` and `arrLitIsI64` each re-scanned every
element with both width classifiers, each asked of every literal twice, and every classifier answer
built a rep descriptor for a primitive; one shared scan (`arrLitNumKind`) and a primitive's code read
off its name (`tyKindCodeOfPrim`) take 29% off. What remains is D3464.

#### Ablation

One `i32` literal of `i % 1000` constants per row, `VL_FUEL=1`, `VL_NO_CACHE=1`, the build under
`VL_COMPILE_GC=null` as filed, master `47aa2950b` against this close. Fuel is a count and exact;
wall times are at box load 7 to 40 and indicative only.

| ingredient changed | outcome | needed? |
| --- | --- | --- |
| one element computed (`[m, 300, …]`) | keeps the chunked build, still invalid wasm at 2.7 million (D3465) | **yes**, every element a literal |
| element kind `i64`, `f64`, `f32`, `u8`, `boolean` | each builds one data segment, values byte-exact | no |
| the literal at 10,000 elements or fewer | unchanged, one `array.new_fixed` | **yes**, past the operand cap |
