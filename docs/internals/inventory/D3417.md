### D3417 — an array literal costs about 30,000 compiler fuel and 1.3 KB of never-freed heap per element, so a 2.7-million-element literal cannot be built

**check-clean invalid wasm (the emitted module is refused by the engine: `function body size count exceeds limit of 7654321`) · a cost row at plumb scale · the compiler's own cost is linear, flat per element from 100,000 up · the grader has no cost outcome word, so the size cliff is the graded half · found by the #3317 review planning · filed 2026-09-30 against master `5e277ab52`**

Repro:

    const xs: i32[] = [@@repeat(2700000, "300,")@@300]
    print(xs.length)
    // vl check: rc 0.  vl run: "failed to parse WebAssembly module: function body
    // size count exceeds limit of 7654321" (vl build: the same, exit 70)

#### Mechanism

A prediction. The literal lowers to one straight-line function body with a few instructions per
element, so the body reaches wasmtime's 7,654,321 limit between 2.5 and 2.7 million elements;
the emitter has no chunked or data-segment path for a constant list. Underneath, the compiler's
own cost is the other half: the null collector never frees, so peak RSS follows the element count
(below) and a literal a few times larger exhausts the heap before the limit is reached.

#### Ablation

One `i32` literal per row, `VL_FUEL=1`, `VL_COMPILE_GC=null`, `timeout 300` on the `vl build`
itself, a seed refreshed from master `5e277ab52`; re-run on `12406d5af` the fuel reads 389,516,585 / 3,225,655,581 / 29,820,178,192 at 10,000 / 100,000 / 1,000,000, within 0.03% of the table, so it is not seed drift. The literal is `i % 1000` constants, one per element; a different element mix will read differently.

`vl run` of the same literal is dearer than `vl build`, and super-linear: 100,000 elements 5.3 s and
1.1 GB, 1,000,000 elements 106.7 s and 9.8 GB (the witness at `1,` per element fits under the
limit at 2.7 million and ran past 120 s, which is why the witness uses `300,`).

#### Grading list

A close owes the ladder above at 1,000,000 with a per-element fuel that falls, and a 2.7-million
element literal that builds. The interaction with the body-size limit (a chunked or
data-segment lowering) is a design question, not just a cost one, and stays with the row. The
`f64` and `string` literals were not measured.
