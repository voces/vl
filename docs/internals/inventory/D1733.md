### D1733 — an if-EXPRESSION joining a STRING arm with a NUMERIC arm has no join rep, and `print` of it directly is check-clean invalid wasm

**check-clean invalid wasm · `vl check` rc 0, `vl run` exit 70 · clause 1 · filed 2026-09-06 against master `25a59b496`, re-measured at `15baeb884` · the residue [D1728](D1728.md)'s 96-cell arm-pair grid leaves, minimised past every ingredient that grid varied · 0 corpus cells**

Repro:

    const c = true
    print(if c { "green" } else { 7 })
    // vl check: rc 0.  vl run: invalid module

Bind it first — `const b = if c { "green" } else { 7 }` then `print(b)` — and the same join
runs, printing `green`. So the join HAS a rep; `print`'s direct route is the half that has no
arm for it.

#### Mechanism

Measured 2026-09-06, and the disassembly names the rung. The checker types the join correctly —
`nodeTyIxOf` is a real `TyUnion` whose `tyToEmitName` is `string|i32`. What over-claims is the
CONSUMER: `exprString`'s `IfStmt` arm falls back to `exprString(<then arm>)` alone, so the join
is claimed a string because its first arm is one, and `ifExprRefKind`'s `exprString(tv)` rung
reads the same single arm. `print` then takes `emitPrintStrExpr` and the blocktype is the string
ref, so the emitted module is literally

    (if (result (ref $2))
     (local.get $0)
     (then (global.get $global$0))
     (else (i32.const 7)))

— the `7` staged into a string block. It is [D1728](D1728.md)'s defect in the other direction,
at the same two sites: there the then arm was an atom and under-claimed, here it is a string and
over-claims.

**There is no small fix, and that is the finding.** The join has no single scalar or ref rep, so
the value must be BOXED (or the consumer sunk into the arms). The box route is four pieces and
three of them were built and measured to work: (1) `unionNameOfExpr`'s `IfStmt` arm derives
`string|i32` from the two arms — `tyToEmitName` of each arm's own recorded type; (2) `exprUnion`
needs an `IfStmt` arm so `printUnionRecvIsBox` admits it; (3) `printUnionPlanCode`'s member-set
fall-back drops an already-inline set, where `emitUnionCoerce` guards the same case. With those
three the plan fires (`nm=[string|i32] exprUnion=1 plan=1 kinds=2`) and `emitPrintValueUnion`'s
own if-expression arm coerces through `emitUnionIfValue` — **the emit side is already built**.
(4) is the blocker: the union ROW for `string|i32` was never registered, because registration is
declaration-driven, so the box tag has no recorded members and
`emitProgram: union box atom test on a union with no recorded members: string|i32` fires — an
invariant whose own comment calls it structurally impossible. Registration is a three-site,
multi-column protocol in the collect pass (`unNamesPush`/`unMemberSetPush` and the member
columns), which is the lane this row needs.

**No literal union, no hole parameter, no annotation and no declared union is required** — that
is what separates this from [D1728](D1728.md), which needed all of the parameter, the alias and
the atom arm. The atom-armed cells below are the same join with the string arm narrowed to a
litunion, and they are a WRONG VALUE rather than invalid wasm, so this row does not claim them
as one mechanism until someone ablates them.

**A MISSING REGISTRY ROW IS NOT THE BLOCKER, measured rather than argued.** #2749's decline
placed it there — registration being declaration-driven, so `string | i32` is never minted.
Declaring the row does not move the witness: with `type U = string | i32` in the same program,
`print(if c { "green" } else { 7 })` is check-clean invalid wasm at the same validator sentence
(measured 2026-09-06 against master `114b3f835`). And an INFERRED all-atom join needs no mint
in the first place — `const w = mkS() ?? mkI()` over `string | i32 | null` runs un-annotated.
The gap is `print`'s classification of a DIRECT if-expression argument, which is what this
row's own ablation already says; a mint would not reach it.
