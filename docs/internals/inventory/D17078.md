### D17078 — a null test does not narrow an `if` join of hole-typed parameters, so the instance reads the join at `T | null`

**closed 2026-11-23: `nonNullNarrowTy` narrows a union with a hole member member by member, each hole to its deferred non-null face · was loud check reject · clause 2 · filed 2026-11-23 against master `1d35bb971`**

Repro:

    function g(a0, a1, k: i32) {
      const v = if k == 0 { a0 } else if k == 1 { a1 } else { [7] }
      if v == null { print("none") } else { print(v[0]) }
    }
    const x0: i32[] | null = null
    const x1: i32[] = [1, 2]
    g(x0, x1, 0)
    // vl run: cannot index non-array i32[] | null (the body of `g`, used at 3:47)

Want:

    none

#### Mechanism

The template types `v` as the union `_ | _ | i32[]`. Every null-test fact collector asks
`nonNullNarrowTy` for the place's non-null face. It peeled a `TyNullable` and deferred a bare
hole (`HD_GNOT`), but handed back a union holding holes unchanged, so the branch recorded no
narrowing. Each instance re-adjudicates the body's deferred index constraint against the
substituted template type, `i32[] | null`. The fix narrows such a union member by member: a hole
member to its `HD_GNOT` face, a `null` member dropped, the rest kept.
