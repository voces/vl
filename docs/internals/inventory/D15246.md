### D15246 — a record literal written into a nested field of an own-type binding whose record is built wider is built at the binding's own row

**closed · runs, prints `5` · was check-clean invalid wasm, `type mismatch: expected (ref null $type), found (ref $type)`, clause 1 · found grading D15214 · filed 2026-11-04 against master `39579d12f` · closed 2026-11-04: the record solve copies a call back to its own record, at the read-back site that let the binding share the call's wider build, when a record is written through that binding (`recSiteWrittenThrough`), and the store pass, `callBuiltTy`, struct collection and emit read that copy; a scalar field write still shares, and a site no copy serves shares as before · fixture `soundness/record-written-into-own-binding-of-wider-build-runs.vl` · the six non-binding positions are [D15266](D15266.md), the write through a parameter [D15267](D15267.md)**

Repro:

    type J = { f: i32 | null }
    type K = { j: J }
    function mk() { { j: { f: 4 } } }
    const _k: K = mk()
    const y = mk()
    y.j = { f: 5 }
    print(y.j.f)

Want:

    5

#### Mechanism

`mk` is built at `K` for both calls (`recNullWidenedAt` reads `y`'s own row back from `K`'s
storage), so `y` holds a `K` record. The literal written to `y.j` is typed at `y`'s own field
type `{f: i32}` and built there, then stored into a field of `J`'s storage. Not yet ablated past
the grid below.

#### A fix that copies the binding, parked

The plan: a binding that is written through, or that hands a record it holds to an own-row place,
takes its own copy of the call's result at its call, and does not share the build. The
whole-binding arm (D15239) reads that fact. A work-in-progress branch (`claude/perframe-69`) gets as
far as this, and is parked at its time box:

- The copy is lowered once the checker records the call's build row on the copy note
  (`recCopyFromOf`) and emit reads the destination row by shape (`structRowOfAnnTy`). The global
  initialiser then emits `struct.new` of the own row from the build, with the nullable field
  unwrapped.
- The decision cannot be made in `storeLetsResolve`. A written binding is not held there
  (`storeHeldAt` answers -1), and its wider typing comes from the kept-function stamp
  (`litKeptStamp` reading `recKeptFnDstOf`). A parameter the binding is passed to is built at the
  wider record by the solve before `storeLetsResolve` runs, so copying the binding afterwards
  leaves that parameter at `K` (`rd(y)` then fails).
- So the copy has to be decided inside the record solve, at the read-back site of
  `recSitesLandAt` that lets `y` share. There the parameter deliveries and the kept-function build
  can read it. Grade it on this matrix plus D14818's four fixtures and `rd(y)`, which must keep
  running.

#### The solve-side copy, second attempt

Branch `claude/perframe-71` (`4a4bf60f0`, not for merging) decides the copy inside the record solve:
`recSitesLandAt`'s read-back arm copies a call back to its own record when the binding it
initialises is written through, and `storeLetsResolve`, `callBuiltTy` and emit read that decision.
`collectAnonShapes` interns the copy's destination row. The witness, `y.j = n` and the alias write
then run, and the position matrix falls from 17 to 6 SILENT; the six left are
[D15266](D15266.md), and the write through a parameter is [D15267](D15267.md). That first cut broke
`soundness/nullable-nested-record-built-wider-beside-own-binding-runs.vl` (D15214's fixture): it
counted a scalar field write (`y.j.f = 7`) as written through, and a site whose copy cannot narrow
(`j: J | null`) then refused the wider build for every call. The landed rule counts only a
record-valued write and lets such a site share; that fixture, D14818's four and `rd(y)` are its guards.
