### D3273 — a labelled block whose braces read like an object made the enclosing brace an object even with statements after it

**closed 2026-09-29 (`labelledBraceIsBlock` in `compiler/parser.vl` also reads what follows the inner `}`: a `;`, or a line break then a token that begins a statement and cannot continue the field's value, makes the enclosing brace a block); since the 2026-09-30 label ruling the label is `@C`, which no brace test reads as a field, and `labelledBraceIsBlock` is gone (D3374) · was a parse error of a legal program, clause 2, left by D3265 · found by the #3299 review grid · filed against master `296e1141d` · fixtures `tests/cases/loops/labelled-block-object-looking-then-stmt.vl`, `tests/vl_label_block_object_test.ts`**

Repro:

    let n = 0
    function h() {
    @C {}
    n = 5
    }
    h()
    print(n)
    // was (spelled `C: {}`): parse error, expected `}` but found `n`
    // now: prints 5

Want:

    5

#### Mechanism

A brace in a body that admits an object literal asks `looksLikeObject`, which for `{ C: { … } }`
asks `labelBraceOpensStmt` about the inner brace alone. An inner `{}` or `{ n }` looks like an
object value (empty, or shorthand), so the outer brace became an object and the statement after
the inner `}` was a parse error. Read as an object, the inner brace is a field's value, which is followed by `,` or `}` or
continued on the next line by a `.`, `?.`, binary operator (`-` included), `is` or `as T`, as
the expression parser continues it inside brackets. So a `;` after the inner `}`, or a line
break followed by a token that begins a statement and continues nothing, decides a block. The
recursive step of `labelBraceOpensStmt` asks the same, so `B1: { C: { n }\n n = 5 }` resolves at
every depth. A next-line `-1` continues the value, so `C: {}\n-1` stays an object, as on master.
