### D3273 — a labelled block whose braces read like an object made the enclosing brace an object even with statements after it

**closed 2026-09-29 (`labelledBraceIsBlock` in `compiler/parser.vl` also reads what follows the inner `}`: a line break then anything but `,` or `}` is a statement, so the enclosing brace is a block) · was a parse error of a legal program, clause 2, left by D3265 · found by the #3299 review grid · filed against master `296e1141d` · fixtures `tests/cases/loops/labelled-block-object-looking-then-stmt.vl`, `tests/vl_label_block_object_test.ts`**

Repro:

    let n = 0
    function h() {
    C: {}
    n = 5
    }
    h()
    print(n)
    // was: parse error, expected `}` but found `n`
    // now: prints 5

Want:

    5

#### Mechanism

A brace in a body that admits an object literal asks `looksLikeObject`, which for `{ C: { … } }`
asks `labelBraceOpensStmt` about the inner brace alone. An inner `{}` or `{ n }` looks like an
object value (empty, or shorthand), so the outer brace became an object and the statement after
the inner `}` was a parse error. An object field's value can only be followed by `,` or `}`
(fields never separate by a line break), so a line break or `;` after the inner `}` followed by
any other token decides a block. The recursive step of `labelBraceOpensStmt` asks the same, so
`B1: { C: { n }\n n = 5 }` resolves at every depth.
