#### Mechanism

Two mechanisms. The row claim: `structIndexOfObjCtx` (literal), `structRowOfObjFieldSetK`
(arena type) and `shapeRowScanK` (spelling) matched a declared row by field names and field
codes, and every closure shares one code, so `{ v: i32, f: () => i32 }` became `R`, although
the checker refuses that assignment (record function fields are invariant). Each scan now asks
`fnFieldTyFits` of a declared row. The call: `fieldClosureFeOfRecv` types a field call by a
closure found among the row's literals, the first one (`named`'s), and checked it against the
receiver's type only inside a generic instance; it now asks the checker's receiver type outside
one and the instance's pin binding (`pinSubOperandTyOf`) for a receiver no other channel binds,
which is the generic face. The param and return spellings (`ref valtype with no interned shape`)
were the claim too, and now run.
