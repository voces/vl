### D10243 — a `string`-result lambda through a hole parameter into `() => T | string` beside `x: T` refuses as an un-annotated union return

**loud check reject · `the returns of `f` join to f64 | string for this argument — type-valid, but an inferred union return through an un-annotated parameter is not yet supported by codegen; annotate the return type` · clause 2 · CAPABILITY: the refusal concedes the program is type-valid · present on master `57b3adb1e` · found closing [D10210](D10210.md) · filed 2026-10-22 against master `57b3adb1e`**

Repro:

    function len<T>(f: () => T | string, x: T) {
      const t = f()

    }
    function take(a) { print(len(a, 1.5)) }

#### Mechanism

Not traced. `x: T` binds `T` to `f64`, so the hole parameter `a` is asked as
`() => f64 | string`, and the lambda's `string` result reaches it as an inferred union return
through an un-annotated parameter. On master the same program also prints a second
diagnostic, `argument of type () => string flows into `len` expecting () => f64 | string`;
since [D10210](D10210.md) only the first remains.
