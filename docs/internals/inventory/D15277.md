### D15277 — a function returning one of two record literals, its function field written another function in a binding, is refused at emit

**closed · runs, prints `2`, `2.5` · was loud emit reject `emitProgram: cannot take the generic function id1 as a value — a function value carries ONE signature` · clause 2 · either literal returned alone runs · found grading D15273 · filed 2026-11-04 against `lane/g2-d15273` with D15273 · closed by the returned join holding each return's set, as a value `if`'s does (D15300)**

Repro:

    function id0(a) { return a }
    function id1(a) { return a }
    function mk() {
      if 1 > 0 { return { f: id1 } }
      return { f: id1 }
    }
    const r = mk()
    r.f = id0
    print(r.f(2))
    print(r.f(2.5))

Want:

    2
    2.5

#### Mechanism

The returned join (`joinRetTys`) unioned the returns' function sets through records (D15209) but
did not note each return's set beside the join's, so the join's set had no leaves; it now does,
as a value `if`'s arm join does (`elabFnArmJoinNote`, D15300). The returned literal is built at
the joined result (`adoptRetLits`), so its field and its `return` are read as holders of a set
decided with the return's own (`ftTyHoldsDecided` in `ftRecHolds` and `ftHoldCtxOk`'s `RetStmt`
arm).

#### Ablation

| ingredient removed | outcome | needed? |
| --- | --- | --- |
| the write (`r.f = id0`) | runs | **yes** |
| the second `return` (one literal, D15270) | runs | **yes** |
| the direct call (`const g = r.f; g(2)`) | still refuses | no |
| a parameter deciding the branch (`mk(b)`) | still refuses | no |
