### D3540 — `filled` with an explicit literal-union type argument picks the ref-list fill arm and refuses

**closed 2026-11-07 by lane rowintern · runs, prints `7` · was loud emit reject, `__array_new__ fill type not yet supported natively`, `vl check` rc 0 · clause 2 · closed by `arrNewDestKind` (emit_ref_list_kinds.vl) naming a numeric literal union element's base list, as `listBuildOfTy` builds it · fixture `generics/filled-at-numeric-literal-union-type-argument.vl` · found again as the fourth loss of c98, the call-key binding without its literal carve-out (D15537) · filed 2026-10-03 against master `f6e17953b` · closing this lets `monoPinnedTyOf`'s literal-union-list arm go: mono pins `filled(2, 7)` into a `(1 | 2 | 7)[]` destination at `i32[]`, and the elaboration's `(1 | 2 | 7)[]` reaches this refusal**

Repro:

    import { filled } from "std:array"
    const v = filled<1 | 2 | 7>(3, 7)
    print(v[0])
    // vl check: rc 0.  vl run: "emitProgram: __array_new__ fill type not yet supported natively"

Want:

    7

#### Mechanism

The instance is built from the written type argument's spelling, and `__array_new__` inside
it took its kind from `arrNewDestKind`, which named the ref list for a `(1 | 2 | 7)[]` destination,
and so classifies the literal-union element as a reference fill (`arrNewIntrKind` kind 3) whose
ref-list slot does not resolve, so `wasmEmit` refuses. The same call with the type argument
INFERRED from the destination (`const v: (1 | 2 | 7)[] = filled(3, 7)`, D3539) pins the
instance from the argument instead and runs, printing `7`; so does a user `mk<1 | 2 | 7>(7)`
that builds its list with a literal rather than `__array_new__`.

#### Ablation

| ingredient removed | outcome | needed? |
| --- | --- | --- |
| the written type argument (destination-inferred instead) | runs | **yes** |
| `__array_new__` (a user generic building `[x, x]`) | runs | **yes** |
| the alias (`type K = 1 \| 2 \| 7`, `filled<K>`) | same refusal | no |

#### Closed

`arrNewDestKind` now names a numeric literal union element's base list (`f64list`, `i64list` or
the i32 `list`). With the fix: the witness prints `7`, the alias spelling `filled<N>` prints `7`, and
a generic calling `__array_new__` directly (`mk<1 | 2>(2, 2)`) prints `2`, all three refused on
master. An annotated destination, a nullable union (`filled<1 | 2 | 7 | null>`) and a string
literal union (`filled<"a" | "b">`) run before and after. The call-key
binding without its literal carve-out (D15537) reaches this refusal at `T := 1 | 2 | 7`.
