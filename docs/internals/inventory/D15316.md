### D15316 — a `??` default the record solve pins at a built read's record joins as a union, which a list or record literal slot built at that record cannot hold

**open · loud check reject · `a ?? whose default is a let or a call's result held in a const, built at J for a read of a container built wider, is not yet supported inside a list or record literal` · clause 2, capability: the literal raises goal-scoreboard's conceded-capability count by one until this row closes · probe `capability-probes/coalesce-pinned-default-in-literal.vl` · without the refusal the list element is an emit refusal and the record field invalid wasm · found closing D15313 · filed 2026-11-04 against master `23c9f7db8`**

Repro:

    function mk() { { f: 4 } }

Want:

#### Mechanism

A `const` of a call and a `let` are adopted at the read's record J: the call's function is built
there and its other calls share that build (D15240), and a `let`'s later writes must land there
too. The adopted binding is typed J, so `m.get("a") ?? dl` joins as `{f: i32} | J` (D15314), and the
literal slot the store column builds at J (`storeSlotHeldAt`, D15312) has no conversion from that
union. Without the refusal, emit refused the list element ("a value that fits `J` may be stored as
another arm") and built the record field invalid. A `const` of a literal is built at J while it
keeps its own type, so its join is one record and it runs (D15313).

#### Ablation

| ingredient removed | outcome | needed? |
| --- | --- | --- |
| the call (`const dl = { f: 1 }`) | runs (D15313) | **yes** |
| the literal slot (`const b = m.get("a") ?? dl`) | runs (D15240) | **yes** |
| a `let` instead (`let dl = …; dl = …`) | still refused | no |
| a record literal `{ g: … }` instead of the list | still refused | no |
| the join bound first (`const b = m.get("a") ?? dl; [b]`) | still refused | no |
