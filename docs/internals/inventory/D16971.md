### D16971 — [CLOSED 2026-11-18] a list literal declared at `i64[] | K[]` traps at its first `is K[]` test

**closed 2026-11-18 · runs, prints `0` · was trap after load (and a silently wrong `.length` of `0`) · clause 1 · fixed in wasmEmit.vl: `coerceListAtomOf` boxes a list literal under the kind of the union arm it is built at (`nodeRepTyIxOf`, `recordRepTyAdopt`'s `listLitUnionArm`), where its own ladder kept the `i32` list tag because `K[]` counts as an `i32` list · fixture `tests/cases/narrowing/list-literal-at-wider-list-and-literal-twin-boxes-at-its-arm.vl` · found beside [D16970](D16970.md) · filed 2026-11-18 against master `1d067b11e` by lane F1**

Repro:

    type K = 1 | 2
    const q: i64[] | K[] = [1]
    if q is K[] { print(1) } else { print(0) }

Want:

    0

#### Mechanism

The literal is built at the first list arm it fits, `i64[]`, as the rep sidecar records it
(`listLitUnionArm`), but `coerceListAtomOf` chose the box tag from the union's atoms: an
integer list widens to `i64[]` only where the union has no `i32` list arm, and `K[]` is one. So
the box held an `i64` list under the `i32` list's tag, and every read cast it as the wrong list:
`.length` read the fallback's empty list (`0`), `is i64[]` was false, and `is K[]` trapped
casting it. The literal now boxes under the kind of the arm it is built at. `is K[]` reads `0`,
since an `i64[]` arm is tested by its tag ([D16970](D16970.md)'s ruling).
