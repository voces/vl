### D16752 — a hole lambda returned by an inferred-return function and stored into a map at a function type returning `f64` keeps its `i32` result

**closed 2026-11-16 · runs, prints `0.5` · was loads then traps, `vl check` rc 0, `wasm trap: indirect call type mismatch` · clause 1 · fixed in `elabReadOn` (emit_elab.vl): the call search follows a value written into a named binding's element or map value (`m[k] = v`), and a value set into a named map (`m.set(k, v)`, written type or not), to that slot's reads, as it already followed a push · the `map_value` and `map_set` annotated cells of `hole-fn-lambda-relayed-by-inferred-return-at-f64.matrix.vl` run · pin: `tests/cases/functions/maker-lambda-set-into-map-at-f64-result.vl` · [D16711](D16711.md)'s fix reads the result from the calls the lambda reaches · filed 2026-11-16 against master `6356d3e7d`**

Repro:

    function deliver() { return (a) => a + 1 }
    const m: { [string]: (a: i32) => f64 } = Map()
    m["k"] = deliver()
    const mv = m["k"]
    if mv != null { print(mv(3) / 8.0) }
    // vl check: rc 0.  vl run: wasm trap, indirect call type mismatch

Want:

    0.5

#### Mechanism

The lambda is instanced at `a: i32` with the body's `i32` result. `elabLamDeliveredRet` finds
no call the lambda reaches (the climb stops at the map store), and the delivery walk
`elabSlotDeliveries` names no closed type for it either, so the instance keeps `i32` while the
call through `mv` uses `(structref, i32) -> f64`.

#### Ablation

| --- | --- | --- |
| the inferred return (store the lambda literal) | runs, `0.5` | **yes** |
| the hole on `a` (`(a: i32) => a + 1` in `deliver`) | runs, `0.5` | **yes** |
| the `f64` result (map of `(a: i32) => i32`) | runs, `4` | **yes** |
| the call through the map's value (store only) | runs | **yes** |
| `m["k"] = …` for `m.set("k", …)` | still traps | no |
