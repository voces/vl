### D15694 — a `for` over a list read off a record field types its loop variable at the list's checked element, not where the list is built

**closed 2026-11-11, runs and prints `1` then `1` · was loud emit reject, check-clean, an internal message, clause 1, `emitProgram: field access receiver is not a struct` · found closing D15690 · filed 2026-11-11 against master `ada32709` · closed emit-side: a field read of a record built at another record is built as that record's field (`exprStoredRepTy`'s member arm, emit_classify.vl), so `listRowOfExpr` finds the list's row and `forInVarStructIdx` types the loop variable there · the repro, a bound `const zs = r.ys`, a list binding in the field, a nested `r.a.ys`, inside a function, a second field read in the body, a field write through the loop variable, and an empty-body loop run · fixture `tests/cases/soundness/for-over-field-list-built-at-kept-maker-runs.vl` · filed: a `.map` over such a list ([D15697](D15697.md), with or without the record, on master too)**

Repro:

    type J = { f: i32 | null }
    function mk2() { { f: 1 } }
    const dA: J = mk2()
    print(dA.f ?? 0)
    const r = { ys: [mk2()] }
    for y in r.ys { print(y.f ?? 0) }

Want:

    1
    1

#### Mechanism

Not ablated. The field `ys` holds a list built at `J[]`, while the loop variable `y` is typed at the
field's checked element `{f: i32}`, so the read `y.f` asks for a struct the element is not.
