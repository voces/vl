#### Mechanism

A hole parameter called at two types is split into one parameter per call type (D5611).
`fsHoleKeys` (fn_split.vl) accepted a read only as a call, a forward to another hole, or a
copy into a binding read at one key; a list element was none of these, so `hsBad` was set and
`monoPinHoleParam` (emit_mono.vl) refused. The list stays as written, holding the parameter's
first slot; each call through it names its own key's slot instead. The plan declines, and the
refusal stands, when the listed binding is written, when the list is a `let`, is read other than as a call at a literal index in
range (`.length`, a variable index, handed on, pushed to, returned), or is not an un-annotated
`const`.
