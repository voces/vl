Repro:

    const l = (q: i32 | null, s: f64) => { if q != null { q } else { s } }
    const r = l(4, 1.5)
    print(r is i32)
    // vl check: `is` check type 'i32' can never match a value of type f64 (before the close)

Want:

    true

#### Mechanism

Not traced. Under the numeric-join ruling, runtime values of two number types join as a union,
and `function l(q: i32 | null, s: f64) { … }` is typed `i32 | f64` and prints `true`. The lambda
spelling's join is typed `f64`, so the `i32` arm is converted away and `is i32` is refused.
The emitter reads the same join's type, which is why [D3656](D3656.md)'s return-path fix was
refused three times: where the checker types a join inconsistently, the emitter cannot tell where to box its value.
