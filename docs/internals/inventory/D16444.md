#### Mechanism

The call's list is fresh, so its records can be copied into the list's element, as
`recFreshCallCopy` copies a list call where it lands (`listCopyTyIx`). With that copy recorded on
the spread's call, the call is emitted and copied element by element (`emitListCopyTail`), but
the spread lowering (`emitArrSpread`) chose its row and each group's temporary from the source's
own row (`refListSlotOfExpr`), the `{x: i32}` list, so the copied `{x: f64}` list was stored into
a local of the wrong type: an invalid module. It now reads a source at the row its delivery copies
it into (`spreadSrcRow`). Disassembly: the call's list stays at its own row, a loop of
`f64.convert_i32_s` fills the copy, and every group temporary is the `{x: f64}` list's row.
