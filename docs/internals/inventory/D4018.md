### D4018 — `as?` and `as!` to the function arm of a union are refused at emit

**loud emit reject · clause 2: `vl check` is clean · found in review of #3531 (the `is`/`as` positions, concrete control) · filed 2026-10-11 against master `5d4cd14dc`**

Repro:

    function id(x: i32): i32 { return x }
    function main(w: boolean) {
      let v: ((x: i32) => i32) | string = "z"
      if w { v = id }
      const g = v as? (x: i32) => i32
      if g != null { print(g(3)) }
    }
    main(true)
    // vl check: rc 0.  vl run: emit error, `as? (i32)=>i32` is supported for a value-atom arm, a struct-variant arm and a sub-union

Want:

    3

The write is conditional since 2026-11-12: a straight-line `v = id` narrows `v` to the function
member (DECISIONS.md, "A read of a `let` takes its most recent write's type"), and the `as?` of
it is then refused as a cast that does nothing.

#### Mechanism

Not located. The `as?` lowering names three arm shapes, and a function arm is none of them.
`as!` to the same arm fails differently, with `call to unknown function`. Narrowing with
`is` reaches the arm: `if v is string { … } else { v(3) }` runs with a concrete `id`. No
generic function is involved, so this is a gap in the union arms, not in function-value flow.

#### Ablation

| ingredient changed | outcome on master | needed? |
| --- | --- | --- |
| `v as! (x: i32) => i32` | loud emit reject, call to unknown function | no (`as?`) |
| the other arm `i32` | loud emit reject, same message | no (`string`) |
| `is` narrowing instead of `as?` | runs | **yes** |
