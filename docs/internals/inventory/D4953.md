### D4953 — `is L` over a nullable union answers false for an empty list of another arm

**closed 2026-10-15 — now prints `fits` · was check-clean silently wrong, clause 1 · `emitListIsAcrossReps` answers a nullable operand, false on null · pin: `tests/cases/unions/empty-list-is-nullable-operand.vl` · found closing D4949 · filed 2026-10-15 against branch `d4949-empty-list-push` over master `bb21e081b` · re-graded 2026-11-15 by the owner's refinement of D16047: an empty list whose annotation fixes its element type is tested by its arm, so `is` of another list arm is false and its branch does not run**

Repro:

    const e: f64[] = []
    let v: f64[] | string[] | null = e
    if v is string[] {
      print("fits")
    } else {
      print("no")
    }
    // vl check: rc 0.  vl run (before): prints no

Want:

    no

#### Mechanism

An empty list fits every list type (D4771), and `emitListIsAcrossReps` answers that for a box
union whose list arm is in another rep (D4915). It declines a nullable operand
(`nodeTyIsNullable`), so `is string[]` falls back to the tag compare, which sees the `f64[]` arm.

#### Ablation

| ingredient changed | outcome | needed? |
| --- | --- | --- |
| `let v: f64[] \| string[] = e` (no `null` arm) | prints `fits` | **yes** |
| `const e: f64[] = [1.5]` | prints `no` (correct) | **yes** (empty) |

the then-branch (the store-back D4949 added has to reach this path too).
