### D3167 — a function value an instance passes on to an un-annotated function shares that function's instance with another signature of the same wasm type, so `true` prints as `1`

**check-clean silently wrong · clause 1 · the 3 `gen__i__*__pass__n3` cells of lane HF's 714-cell grid (the record and its field are scenery) · the same on master `934f169f4` · filed 2026-09-29 against master `934f169f4`**

Repro:

    function H(h) {
      return h()
    }
    function F<Z>(g: Z) {
      print(H(g))
    }
    F(() => 7)
    F(() => true)
    // prints 7, then 1

Want:

    7
    true

#### Mechanism

Not localised past the ablation. Both instances of `F` call one instance of `H`: the
disassembly holds `$H` alone, called from `$F` and `$F$1`, each printing through
`__print_i32__`. `() => i32` and `() => boolean` share a wasm signature, and the argument pin
that picks `H`'s instance does not tell them apart when the argument is an instance's own
parameter, so the second call's result is printed at the first's type. Called from the top
level, `H(() => true)` gets its own instance and prints `true`. D3176 may be the same
mechanism reached without the intermediate generic; grade both rows on either close.

#### Ablation

| ingredient changed | outcome | needed? |
| --- | --- | --- |
| `print(H(() => 7))`, `print(H(() => true))`, no `F` | prints `7`, `true` | **yes** (the instance's parameter) |
| `F(() => 2.5)` first | prints `2.5`, `true` | **yes** (a shared wasm signature) |
| `F(() => true)` first, then `F(() => 7)` | prints `true`, `true` | no (the other order, same defect) |
| `function F(g)`, a hole | prints `7`, `1` | no |
| a record field, `const g = z.f` | prints `7`, `1` | no |
