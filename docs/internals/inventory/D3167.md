### D3167 — a function value an instance passes on to an un-annotated function shares that function's instance with another signature of the same wasm type, so `true` prints as `1`

**closed · a function-value pin is keyed by the value's checked type as well as its `$fnsig` key · fixture `tests/cases/generics/function-value-pin-checked-type.vl` · was check-clean silently wrong · clause 1 · the 3 `gen__i__*__pass__n3` cells of lane HF's 714-cell grid (the record and its field are scenery) · the same on master `934f169f4` · filed 2026-09-29 against master `934f169f4`, closed 2026-09-29 against master `a0b9acaf8`**

Repro:

    function H(h) {
      return h()
    }
    function F<Z>(g: Z) {
      print(H(g))
    }
    F(() => 7)
    F(() => true)
    // prints 7, then 1

Want:

    7
    true

#### Mechanism

A function-value argument pins its parameter by `"=>"` plus the value's `$fnsig` key, and the
key is a wasm-level spelling: `() => i32`, `() => boolean`, `(): K` and `(): K | null` all key
`>i`. Two calls whose values differ only there shared one instance, which read every result at
the first call's type. A lambda literal passed directly already got its own instance; an
instance's parameter and a plain binding (`const q = () => true; H(q)`) did not.
`monoMakeInstance` now extends a function-value pin's key with the value's checked type
(`monoSigPinDiscrim`), the rule `monoAnonPinDiscrim` already applies to anonymous record pins.

#### Ablation

| ingredient changed | outcome | needed? |
| --- | --- | --- |
| `print(H(() => 7))`, `print(H(() => true))`, no `F` | prints `7`, `true` | **yes** (the instance's parameter) |
| `F(() => 2.5)` first | prints `2.5`, `true` | **yes** (a shared wasm signature) |
| `F(() => true)` first, then `F(() => 7)` | prints `true`, `true` | no (the other order, same defect) |
| `function F(g)`, a hole | prints `7`, `1` | no |
| a record field, `const g = z.f` | prints `7`, `1` | no |
