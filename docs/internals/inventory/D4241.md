### D4241 — a record field holding a generic function, called through the field, runs whichever instance another call already made

**closed 2026-10-12 by lane SC · runs · was check-clean silently wrong · clause 1 · found grading the `sc_t04_fnvalue_link_chain.py` matrix for D4240 · filed 2026-10-12 against master `f6ee50929` · pins: `tests/cases/closures/record-field-of-generic-called-after-another-instance.vl`, `tests/cases/closures/record-field-written-with-generic-called-through-field.vl`, `tests/cases/closures/record-field-of-generic-called-at-two-types.vl`, `tests/cases/closures/record-field-of-generic-in-generic-body.vl`**

Repro:

    function gC<W>(w: W) { print("C"); print(w) }
    const y = { h: gC }
    gC(2)
    y.h(true)
    // vl check: rc 0.  vl run: prints C 2 C 1

Want:

    C
    2
    C
    true

#### Mechanism

The first instance of a generic keeps the bare name and slot, so a value naming the generic that
no pin renamed is a closure over that instance. A record literal's field was never pinned: the
call `y.h(true)` went through the closure `gC` at `i32`, and printed `true` as `1`; a `string`
argument built invalid wasm. Without another instance the value was the pruned stub and was
refused ([D4123](D4123.md)). An un-annotated `const` record whose every read is a field call, a
field write, or a read of a field holding no generic now gives each field holding a generic the
type its calls take, as D3977 does for a list's elements, and instances the field's value and
every write to the field at it. Calls at two types are refused.
