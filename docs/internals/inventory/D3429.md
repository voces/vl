### D3429 — a 64-bit integer literal beside a type parameter pinned at `f32` is rounded silently at the instance

**closed · now a loud check reject, refused by the checker as the direct spelling is, "argument 1: operator '+' mixes f32 and i64 (the body of `g` applies '+' to this argument)" · was check-clean silently wrong, printing `2147483648`, clause 1 · found by the #3323 review · filed 2026-09-30 against master `afb0ecc08` · closed with [D9802](D9802.md): the pin asks the direct spelling's pair rule with the operator's node, so the literal is judged by the value it holds, as at the direct spelling (`binCstrPairRefusal`, check_relate_core.vl) · the exact `x + 16777216` at `f32` still runs**

Repro:

    function g<T>(x: T): T { x + 2147483649 }
    const z: f32 = 0
    print(g(z))
    // PRINTS 2147483648

#### Mechanism

The body is checked once with `T` open, so `x + 2147483649` records only the operator's deferred
constraint, which the pin accepts for `f32 + i64` although the direct spelling refuses it. The
`f32` instance then adds the literal at single precision, where 2147483649 is not exact, and
prints 2147483648. The width constraint D3426 added (`OP_LITFIT`) refuses only an `i32` pin.
The fix is to record the literal's value rather than its width and have the pin ask whether the
pinned type holds it, as the delivery check does (`cexFitsAt`).

#### Ablation

| spelling | outcome |
| --- | --- |
| `T` pinned `f32`, `x + 2147483649` | `2147483648` |
| `T` pinned `f32`, `x + 16777216` | `16777216`, exact |
| `T` pinned `i32`, `x + 2147483649` | refused at the pin (D3426) |
| direct `(x: f32) + 2147483649` | refused, `operator '+' mixes f32 and i64` |
