### D2499 — an else-less tail `if` that assigns a closure to a name traps on `unreachable`

**closed 2026-10-13 by [D4349](D4349.md) · runs, prints `2` · was check-clean invalid wasm · clause 1 · filed 2026-09-25 against master `dec16071c` as a load then an `unreachable` trap, found by the review of #3162 ([D2495](D2495.md)/[D2496](D2496.md)) · pins: `tests/cases/closures/nullable-closure-return-fallthrough.vl`**

Repro:

    let g: (i32) => i32 = (n) => 0
    function f(flag: boolean) {
      if flag { g = (n) => n + 1 }
    }
    const a = f(true)
    const b = f(false)
    print(g(1))

#### Mechanism

The write re-reads its name, so the checker and the emitter agree that the arm yields the
closure, and the inferred return is `((i32) => i32) | null`. Nothing lowers that return's
fall-through `null`: `fnRetNullBearing` answers for a nullable closure only through an annotation
(`nulCloFlag`), and no pass pins an inferred one, so the function end is `unreachable` padding.
[D2495](D2495.md) closed the same gap for nullable lists; a pin, or a `ref.null $cloStruct` for
the inferred row, is the analogue.

#### Grading list

The review grid's `clo__n_glob`, `clo__n_fld`, `clo__n_lit` and `clo__n_val` cells, in statement
and `() => void` callback use.

#### Close

[D4349](D4349.md) pins an inferred nullable-closure return to its own spelling, and
`fnRetNullBearing` now answers for `nulCloFlag`, so the fall-through emits the `ref.null
$cloStruct` that `emitNullForRet` already had. The annotated spelling trapped the same way
before, so "answers through an annotation" in the mechanism above was not true.
