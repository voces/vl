### D7444 — a hole's `??` chain over an atom-valued map with no literal default prints the miss sentinel

**check-clean silently wrong · clause 1 · open · the direct spelling `use(p: R)` runs and prints `null` since [D7448](D7448.md), so the owed result is `null` · `function use<T>(p: T)` prints the same `-1` · split out of [D3424](D3424.md) when its repro closed · present on master `1c86d0f42` · filed 2026-10-20 against master `1c86d0f42`**

Repro:

    type AB = "a" | "b"
    type R = { m: {[i32]: AB} }
    function mk(): R {
      const m: {[i32]: AB} = Map()
      m[3] = "b"
      { m: m }
    }
    function use(p) {
      print(p.m[9] ?? p.m[8] ?? p.m[7])
    }
    use(mk())
    // PRINTS -1

#### Mechanism

The checker's refusal needs the receiver's map type, which a hole or `<T>` receiver does
not give it at check time, so nothing refuses at the pin. The chain groups left, and the
inner `p.m[9] ?? p.m[8]` is classified non-null by `coalesceDefaultNullable`, which lacks the
hole map-read rung `coalMapDefaultMayBeNull` has, so the outer `??` reads the `-1` miss
sentinel as a member. Adding that rung is not the whole close: it prints `b` for the repro,
and a two-link chain bound to a local then refuses at print for a set with no member texts.
