### D7444 — a hole's `??` chain over an atom-valued map with no literal default prints the miss sentinel

**closed 2026-10-20 by lane L6 · runs, prints `null`; `<T>` prints `null` · was check-clean silently wrong (printed `-1`) · clause 1 · `coalesceDefaultNullable` gained the hole map-read rung (a hole's read off a map its instance pins is `V | null`), and is now the one nullability decision `coalMapDefaultMayBeNull` duplicated; the print classifier reads a chain's member texts link by link (`coalMapReadChainTexts`), so bound two- and three-link chains print too · pin: `tests/cases/literal-unions/hole-map-read-coalesce-chain-nullable-atom.vl` · split out of [D3424](D3424.md) when its repro closed · present on master `1c86d0f42` · filed 2026-10-20 against master `1c86d0f42`**

Repro:

    type AB = "a" | "b"
    type R = { m: {[i32]: AB} }
    function mk(): R {
      const m: {[i32]: AB} = Map()
      m[3] = "b"
      { m: m }
    }
    function use(p) {
      print(p.m[9] ?? p.m[8] ?? p.m[7])
    }
    use(mk())
    // PRINTS -1

#### Mechanism

The checker's refusal needs the receiver's map type, which a hole or `<T>` receiver does
not give it at check time, so nothing refuses at the pin. The chain groups left, and the
inner `p.m[9] ?? p.m[8]` is classified non-null by `coalesceDefaultNullable`, which lacks the
hole map-read rung `coalMapDefaultMayBeNull` has, so the outer `??` reads the `-1` miss
sentinel as a member. Adding that rung alone printed `b` for the repro, because print's member
texts were read only off a single fused map read; reading them link by link down the chain
(`coalMapReadChainTexts`) is the other half, and covers a chain bound to a local.
