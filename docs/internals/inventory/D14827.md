### D14827 — a record or list narrowed by `is` is refused as a delivery even where no later write can reach its source

**loud check reject · open, low priority: the owner's option (c), the refinement of the narrowed-delivery rulings for lists (D4928) and records (D4084) · the witness is D14752's original spelling, a correct program, and should run once this lands · filed 2026-11-01 against master `bab63f39`**

Repro:

    type K = "circle" | "round"
    type A = { kind: K, r: i32 }
    type B = { kind: string, r: i32 }
    function useA(a: A) { print("useA " + a.kind) }
    function f(n: i32): A | B {
      if n == 0 {
        const a: A = { kind: "circle", r: 1 }
        return a
      }
      if n == 1 { return { kind: "zz", r: 2 } }
      const b: B = { kind: "round", r: 3 }
      b
    }
    let i = 0
    while i < 3 {
      const x = f(i)
      if x is A {
        useA(x)
        const y: A = x
        print(y.kind)
      } else {
        print("B " + x.kind)
      }
      i = i + 1
    }
    // vl check: rc 1, "'x' is narrowed by `is` only for reading its fields; … cannot be delivered as A"

#### Mechanism

A value narrowed by `is` fits the narrowed type only by its current contents, so delivering it as
that type is refused (D4928 for lists, D4084 for records): a later write through its wider type
would break the delivered value. Here no write can reach `x` or the record it holds, since `b` is
dead after `f` returns and `x` is a `const`, so the delivery is sound and the copy the error names
is not needed. The refinement accepts a narrowed delivery when no write that can reach the source
follows it, for lists and records alike.
