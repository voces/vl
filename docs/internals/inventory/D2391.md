### D2391 — a module-scope closure that stores an `f64[]` into a module `f64[] | string` global is invalid wasm

**check-clean invalid wasm · clause 1 · filed 2026-09-25 against master `3ab3c402f`, found
grading [D2387](D2387.md)/[D2388](D2388.md)**

Repro:

    let v: f64[] | string = "a"
    const k = () => { v = [1.5, 2.5] }
    print("ok")
    // vl check: rc 0.  vl run: invalid module inside `k`: type mismatch: expected (ref $type), found (ref $type)

#### Mechanism

The store is in the lambda's body, where the global's union member for the f64 list is not
resolved the way the module frame resolves it: the same assignment written at module scope,
or in a top-level `function k()`, runs. Not the D2387 mechanism, which is a function frame's
boxed cell; a module binding is a global and is never boxed. Not yet localised further.

#### Ablation

| ingredient removed | outcome | needed? |
| --- | --- | --- |
| the lambda (`v = [1.5, 2.5]` at module scope) | runs | **yes** |
| the lambda, for a top-level `function k() { v = [1.5, 2.5] }` | runs | **yes** |
| the list literal (`v = xs` with `const xs: f64[]`) | still invalid wasm | no |
| the call `k()` | still invalid wasm | no |
| the f64 element (`string[] \| i32`, or `i32[] \| string`) | runs | **yes** |
| the module frame (the same inside a function) | runs | **yes** |
