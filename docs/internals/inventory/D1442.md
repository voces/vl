### D1442 — `redundant type annotation` compared the annotation against a type the annotation itself produced: `seedExpected` runs BEFORE the initializer is checked

**closed 2026-09-03 by gating the finding on `cbSeedUsed`, a counter of contextual seeds a
lambda actually CONSUMED · the witness runs and must keep running, and the HINT it used to
carry must stay gone · 138 of the 269 sites `--fix` refused to apply were this · the compiler's
own comment claimed the compared type was "the initializer's CONTEXT-FREE type", which it has
never been**

Repro (runs, prints `7`; the point is the `[HINT]: redundant type annotation` it no longer
carries — `vl check --severity hint` must print nothing):

    const v: () => (i64 | boolean)[] = () => ([7])
    const t0 = v()
    const e = t0[0]
    if e is i64 { print(e) } else { print("OTHER") }

#### Mechanism

`checkLetDecl` calls `seedExpected(n.letInit, annot)` — bidirectional inference — and only
THEN `checkNode(n.letInit)`. So for any initializer the seed reaches, `initTy` was computed
WITH the annotation in hand, and `recordRedundantAnnot`'s `tyEq(initTy, annot)` is circular:
the two agree because the annotation made them agree. Un-annotated, `() => ([7])` self-infers
`() => i32[]` and the `is i64` test is a loud check reject; `const f: (i32) => i32 = (x) =>
x + 1` does not type at all.

The gate is a COUNTER, not a syntactic test, because a seed that reaches a lambda is not
necessarily load-bearing. `cbSeedUsed` increments in exactly the two places a seed changes
what a lambda infers: an un-annotated parameter typed from `cbExpect`, and the contextual
RETURN ADOPTION block (`inferred != preAdopt` — snapshot/compare over all twenty arms, so a
twenty-first does not have to remember). `checkLetDecl` reads the delta across its own
initializer. A plain `const xs: i32[] = [1, 2]` seeds nothing and keeps its hint.

Measured over `tests/cases`: the finding goes 3,668 -> 3,455 sites, the ones `--fix` must
refuse 269 -> 131, and 58 sites that were safe are lost with them — an annotation whose seed
was consumed but whose un-annotated spelling had another mechanism (`noteValBindLambda` makes
an un-annotated binding's lambda params holes). The checker cannot tell those apart without a
second, un-seeded inference pass.
