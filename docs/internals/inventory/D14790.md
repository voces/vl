### D14790 — `std:buffer`'s `bufferRelease` called through a `(mark: i32) => void` value traps, because a build-time fold left its emitted result an `i32`

**closed 2026-11-01 by `computeVoidFns` taking a recorded `void` result as void (`fnRecordedRetTy`) · the witness prints `1024`, `1` · was trap after load, `indirect call type mismatch`, clause 1, on master `c4604eb7` · fixture `tests/cases/std/buffer-release-as-void-fn-value.vl` · filed 2026-11-01 against master `c4604eb7` · found by the emitted-function result shadow (`fn_ret_shadow.vl`)**

Repro:

    import { bufferMark, bufferRelease } from "std:buffer"
    function run(g: (mark: i32) => void, m: i32) { g(m) }
    const m = bufferMark()
    print(m)
    run(bufferRelease, m)
    print(1)
    // was: 1024, then wasm trap: indirect call type mismatch

Want:

    1024
    1

#### Mechanism

`bufferRelease` ends in a write (`bumpOff = mark - heap`) after an `if __memory_shared__() { … }`
arm holding its bare `return`s. The checker types both arms, and a bare `return` pins the function
void (D1600). `foldMemShared` drops the arm in a default build before `computeVoidFns` runs, so the
emitter saw no bare `return`, took the spilled tail write for a value and gave the function an
`i32` result. A direct call drops that result and runs; a call through a value of the checked type
`(i32) => void` is a `call_ref` at the other signature.
