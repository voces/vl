### D15039 — a binding of a hole function returned through a hole identity, called only through that binding, is stored as a closure and read as the set's id

**closed · runs, prints `3` · was check-clean invalid wasm · clause 1 · found closing the split plan's group N · filed 2026-11-02 against master `7e3fea10` · fixture `tests/cases/closures/hole-fn-through-identity-bound-and-called-once.vl`**

Repro:

    function fw(f) { return f }
    function add(a, b) { return a + b }
    const p = fw(add)
    print(p(1, 2))

Want:

    3

#### Mechanism

The call through `p` needs `add`'s own instance, so `add`'s set is tagged and `fw` returns the
member's id; the call site reads `p` as that id. The binding's cell was built from the type
`letBindTy` answers, the declared type the call pinned closed, `(i32, i32) => i32`, which carries
no set, so the cell was a closure. Closed in `letHeldTyOf`: a binding whose own type's set is
tagged is held at that type, so its cell is the id too.
