### D14085 — an un-annotated two-arm `match` over `i32[]` and a literal-union list answers every `is` over it true

**check-clean silently wrong · clause 1 · `vl check` rc 0 · the `i32[]` arm takes the `is K[]` branch · pre-existing on master `2f8428da3` · found grading [D14083](D14083.md) · filed 2026-10-26 against master `30a8cca38`**

Repro:

    type K = "a" | "b"
    function h(a0: i32[], a1: K[], k: i32) {
      const r = match k {
        0 => a0
        _ => a1
      }
      if r is K[] { print(r.length) } else { print("i") }
    }
    h([1, 2], ["a"], 0)
    h([1, 2], ["a"], 1)
    // vl run: prints 2, then 1

Want:

    i
    1

#### Mechanism

Not traced. The checker types `r` as `i32[] | K[]` in both the `match` and the `if` spelling,
so the two differ only in lowering. In the `match` spelling neither `is` can tell the arms
apart: `is K[]` holds for the `i32[]` arm and `is i32[]` holds for the `K[]` arm, so the
first test written wins. The element values do not decide it (`[5, 7]` and `[0, 1]` take the
same wrong branch), so this is not an atom-code collision. The `is` lowering over list unions
belongs to the step 6 lane.
