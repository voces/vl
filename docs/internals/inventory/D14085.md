### D14085 — an un-annotated two-arm `match` over `i32[]` and a literal-union list answers every `is` over it true

Repro:

    type K = "a" | "b"
    function h(a0: i32[], a1: K[], k: i32) {
      const r = match k {
        0 => a0
        _ => a1
      }
      if r is K[] { print(r.length) } else { print("i") }
    }
    h([1, 2], ["a"], 0)
    h([1, 2], ["a"], 1)

Want:

    i
    1

The same mechanism, unbound, in both spellings (printed `true` `true` before the fix):

    type K = "a" | "b"
    function h(a0: i32[], a1: K[], k: i32) {
      print((if k == 0 { a0 } else { a1 }) is K[])
    }
    h([1, 2], ["a"], 0)
    h([1, 2], ["a"], 1)

It must print `false` then `true`.

#### Mechanism

The `is` lowering is shared by both spellings. They differed in the union row. `K[]` and
`i32[]` share one storage, so only the registered row for `i32[] | K[]` gives the two arms
distinct box tags. With no row, both arms boxed under the storage's tag, and `is K[]` tested
that tag, which every value carried.

The only producer of that row for an un-annotated join was a binding pin. The checker queued a
binding when its initializer was an `IfStmt` or a `??`, and the emitter pinned and registered
it. At check time a `match` is not yet desugared to an `if`, so it was never queued. An
unbound join was never queued at all in either spelling, because the join producer
(`noteInferJoin`) did not admit list unions.
