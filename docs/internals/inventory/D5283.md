### D5283 — a list literal of members passed to a generic infers `string[]` against a literal-union destination

**closed · was loud check reject · clause 2 · eardstap EV-003 (second half) · filed 2026-10-17 against master `3f6a785db`**

Repro:

    type K = "a" | "b"
    function id<T>(xs: T[]): T[] { xs }
    const r: K[] = id(["a", "b"])
    print(r[1])

Want:

    b

#### Mechanism

The type parameter's binding from the destination (`dstTyParamAdapts`) let a scalar string
literal adopt a literal-union `T`, but `argIsStrLit` did not look inside a list literal, so
`["a", "b"]` bound `T` to `string` first. The literal check now recurses through list literals,
and a literal-union destination binds `T` to the member type the literal leaves fit
(`litLeafFitting`, `check_relate_core.vl`). A non-member literal still binds `string`.
