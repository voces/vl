#### Mechanism

The checker types the `??` as `T[]`, so the call is `string[]` at `T := string`, and the
instance declares a `string[]` result while the fallback `[1]` is built as an `i32` list. The
same function with `xs: string[] | null` spelled out types the `??` as `string[] | i32[]` and
runs, as does the return-set join of `[t]` beside `[1]` (D2783): the `??` result type does not
go through the join that keeps a type parameter's list apart from a concrete one: the `??` arm
answers the left's non-null type whenever the default is assignable to it, and `T[]` accepts
`i32[]` through `T`.

The emitter now refuses the `??` where the instance's operand list and the default's list have
different storage (a string or record list beside a number list, or an `f64` default beside an
integer list), which is the loud refusal this program had before `2bbc5c412`. Pins where the
storage agrees, and a numeric default at an `f64` pin, keep running. Typing the `??` apart
(`T[] | i32[]`) is the clause-1 close, and #3214 tried it for five review rounds: it needs every
body read of such a join to be re-asked at the pin, which is [D2843](D2843.md).
