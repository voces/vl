### D2799 — `xs ?? [1]` over a `T[] | null` parameter is typed `T[]`, so a string pin builds the `i32` list into a `string[]` result

**check-clean invalid wasm · clause 1 · found grading D2783's positions · a loud emit reject on master `b586b6063`, invalid wasm since `2bbc5c412` · filed 2026-09-27 against master `2bbc5c412`**

Repro:

    function h<T>(xs: T[] | null) {
      xs ?? [1]
    }
    const q = h(["a"])
    if q is string[] { print(q[0]) } else { print(-1) }
    // vl check: rc 0.  vl run: invalid module inside `h`

#### Mechanism

The checker types the `??` as `T[]`, so the call is `string[]` at `T := string`, and the
instance declares a `string[]` result while the fallback `[1]` is built as an `i32` list. The
same function with `xs: string[] | null` spelled out types the `??` as `string[] | i32[]` and
runs, as does the return-set join of `[t]` beside `[1]` (D2783): the `??` result type does not
go through the join that keeps a type parameter's list apart from a concrete one. Not yet
localised further.
