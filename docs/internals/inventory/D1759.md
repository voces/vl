### D1759 — ANNOTATING a captured struct binding at a MODULE-LEVEL block is what breaks it: the un-annotated spelling of the same seven lines runs

**closed 2026-09-06 — `captureValKind`'s annotated arm asks the field slot's own question
when the frame-taking rung cannot: a nested-struct field read's cell is the niche whether or
not the binding is annotated · was check-clean invalid wasm, clause 1 · filed 2026-09-06
against master `dcbf7521c`, closed against `65a34adcc` · closes [D1771](D1771.md) with it ·
0 corpus cells**

Repro:

    type Rec = { name: string, n: i32 }
    function mkval(): Rec { return { name: "ada", n: 3 } }
    if true {
      const box = { it: mkval() }
      const held: Rec = box.it
      const get = () => held
      print(get().n)
    }
    // vl check: rc 0.  vl run: exit 70,
    // the emitted module failed to validate:
    // type mismatch: expected (ref $type), found (ref $type)

Delete the `: Rec` and the same program prints `3`. `@hint` does not call the annotation
redundant, and the checker agrees about the TYPE in both spellings — it is the REP the two
disagree about.

#### Mechanism

MEASURED with an `emitFail` probe in `captureValKind`'s annotated arm, printing that arm's
own inputs at four faces. The broken and the working spelling differ in ONE field:

    modblk_ann   annK=struct niche=nulstruct initK=struct    nested=F isStruct=T frameOk=F
    fnbody_ann   annK=struct niche=nulstruct initK=nulstruct nested=F isStruct=T frameOk=T
    modblk_idx   annK=struct niche=nulstruct initK=struct    nested=F isStruct=T frameOk=F

`parentBindingFrameArenaOf` answers **-1** for a binding in a module-level BLOCK — no frame's
`fnBody`, not a global, the hole [D1636](D1636.md) named one function over. With `fnIx = -1`
every frame-taking rung of `letInitCellKind` is silent, `letIsNulRef` among them, so D1632's
reconciliation (`initK == nicheK` → take the niche) never fires and the arm returns the
annotation's own non-null `struct`. The disassembly agrees: the working face declares env
`(struct (field (ref null $0)))` with `(func (param structref) (result (ref null $0)))`, the
broken one `(struct (field (ref $0)))` — a non-null field over a value the field's slot hands
over nullable, which is the `expected (ref $type), found (ref null $type)` the engine reports.

**And the rung that DOES know is annotation-gated**, which is why the un-annotated twin runs
at every frame: `letInitIsNestedStructField` opens with `if d.letType >= 0 { return false }`,
so D1476's own "a nested-struct field read reads back `(ref null $S)`" answer is unavailable
to exactly the spelling that needs reconciling. The close splits that test in two — the rung
keeps its gate, and `captureValKind`'s annotated arm asks the ungated one, which is
FRAME-BLIND because the field's storage decides it and the scope does not.

**Not the widening D1636 measured and refused.** Making `parentBindingFrameArenaOf` answer for
module-frame blocks is the unrestricted rung that cost 18 corpus classes (66 cells)
`runs -> check-clean invalid wasm`; nothing here touches it, and `letInitCellKind` is
unchanged, so the un-annotated ladder reads exactly as before.
