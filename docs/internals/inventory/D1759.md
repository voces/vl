### D1759 — ANNOTATING a captured struct binding at a MODULE-LEVEL block is what breaks it: the un-annotated spelling of the same seven lines runs

**check-clean invalid wasm · clause 1 · filed 2026-09-06 against master `dcbf7521c`, re-graded as filed on `b35b2a093` · found by `scripts/day-one/sample.py`'s annotation ablation over seeds 3001–3005 · the reverse polarity of [D1476](D1476.md) and [D1636](D1636.md) · 0 corpus cells**

Repro:

    type Rec = { name: string, n: i32 }
    function mkval(): Rec { return { name: "ada", n: 3 } }
    if true {
      const box = { it: mkval() }
      const held: Rec = box.it
      const get = () => held
      print(get().n)
    }
    // vl check: rc 0.  vl run: exit 70,
    // the emitted module failed to validate:
    // type mismatch: expected (ref $type), found (ref $type)

Delete the `: Rec` and the same program prints `3`. `@hint` does not call the annotation
redundant, and the checker agrees about the TYPE in both spellings — it is the REP the two
disagree about.

#### Mechanism

Predicted, not probed. [D1636](D1636.md) gave `structIndexOfExpr`'s Ident arm a MODULE-frame
`let` rung **ANNOTATED only**, and [D1632](D1632.md) made `captureValKind`'s annotated arm
match the LOCAL's own cell rather than re-derive from the annotation. At a module-level block
the two answers are not the same: the un-annotated binding takes its cell from the field
projection and the capture follows it, while the annotated one re-derives a row from `Rec`
and the closure's field is declared at a heap type the projection does not produce. Only the
module frame has the split — the identical block inside a function body runs at both
spellings — which is the frame D1244's own rung was cut for.

**The annotation is the ingredient, so no fixture that annotates can see this and no fixture
that omits annotations can either.** It needs a pair, which is why the sampler's annotation
ablation found it and the eleven position matrices did not: every one of them holds the
annotation fixed.

`const` against `let`.
