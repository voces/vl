### D15366 — two returns of records whose list field holds functions of different results build an invalid module

**check-clean invalid wasm · `vl check` rc 0, `type mismatch: expected (ref $type), found (ref $type)` inside the function · clause 1 · open, target `1.5` · found closing [D15227](D15227.md), whose join note leaves a list a record holds out · filed 2026-11-04 against master `177b27d96`**

Repro:

    function inc0(a) { return a + 1 }
    function half(a) { return a / 2.0 }
    function pick(b: boolean) {
      if b { return { fs: [inc0] } }
      return { fs: [half] }
    }
    print(pick(false).fs[0](3))

Want:

    1.5

#### Mechanism

Not ablated past the table. The checker types the call `f64`. The two returned records are
built at two rows, each with a list of its own one-member set, and the function's result row is a
third. [D15227](D15227.md) ties the members' sets to the join's for a list returned bare. Doing the
same for a list a record holds turns [D15303](D15303.md)'s emit refusal into an invalid module,
because each arm's record is still built at its own row. So the record rows have to agree first.
