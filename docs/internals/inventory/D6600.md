### D6600 — a `print` of a hole call given an un-annotated lambda is judged by a later direct call of the generic it was bound to

**closed 2026-10-18 by lane L1 · runs, prints `3` then `4` · was a loud check reject · clause 2 · the hole call's result now takes the instance its lambda binds, so no `print` demand naming the generic's own `U` is left at module scope · pin: `tests/cases/generics/hole-call-generic-lambda-arg.vl` · found closing [D6543](D6543.md) · filed 2026-10-18 against master `12a607621`**

Repro:

    function app<T, U>(f: (T) => U, v: T): U { f(v) }
    function via(a) {
      print(a((n) => n + 1, 2))
    }
    via(app)
    const r = app((n) => [n, n], 4)
    print(r[0])
    // vl check: `app` prints its type parameter here: print expects one scalar or string value ..., got i32[]

#### Mechanism

`holeCallRetAt` could not bind `app`'s variables at the hole call, because the lambda
argument's type was open, so the `HD_RET` row fell back to `app`'s own `fnRet`, `U`.
`validatePrintCstrs` re-recorded `via`'s `print` at that still-open type with no owner. An
unowned demand is judged by every instance (`cstrOwnedBy`), so the direct call's `U = i32[]`
refused it. [D6543](D6543.md)'s binding of the lambda closes the hole call's result, so the
demand is judged at `i32` and is never re-recorded.
