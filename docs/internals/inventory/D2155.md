### D2155 — two arms of two unions whose literal-union fields share a layout fold onto one heap type

**closed 2026-09-23 — the witness prints `0` · was check-clean invalid wasm at the written-alias spelling, clause 1 · filed 2026-09-23 against master `b5debe165`, exposed to inline sets by D2150 · fixture `tests/cases/unions/arm-with-inline-literal-union-field.vl`**

Repro:

    type K = "a" | "b"
    type Named = { r: i32, k: K }
    type NOther = { o: string }
    type NShape = Named | NOther
    type K3 = "a" | "b" | "c"
    type Tri = { r: i32, k: K3 }
    type TOther = { o: string }
    type TShape = Tri | TOther
    type TW2 = { g: Tri }
    const t: Tri = { r: 0, k: "a" }
    const tp: TW2 = { g: t }
    print(tp.g.r)

#### Mechanism

`buildVariantTwins`' D1023 arm folds two arms that share a field-name signature and are
discriminable by a literal field onto one heap type, because `assignTags` gave them one tag. Tags
are per union; the fold was not, so `Tri` took `Named`'s heap while `TW2.g` stores through the
arm-shape row `Tri`'s own layout interned, and the stored value's heap type was the other one.
The fold now requires the two arms to belong to one union. `objVariantName` also asks the arm the
checker proved a literal is before its first-match scan.
