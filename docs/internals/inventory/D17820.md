### D17820 — one hole parameter handed two storages of a function at different reps reads both at one, and the call traps

**loads then traps · `wasm trap: indirect call type mismatch` · clause 1 (`vl check` rc 0) · open · one storage handed to the same parameter runs once D17817's close lands (#10744) · filed 2026-11-28 against master `186ae23a9` · owner COV-CLOS-3 (re-routed 2026-11-28, coordinator ruling: the per-width lift of [D17808](D17808.md)) · traced by I8-PREP**

Repro:

    function dbl(a: f64): f64 { return a * 2.0 }
    const g = (a) => a + 1
    const xs = [g, dbl]
    function walk(ys) { const v = ys[0]; print(v(3)) }
    walk(xs)
    const one = [g]
    walk(one)
    // vl check: rc 0.  vl run: wasm trap: indirect call type mismatch (in `walk`)

Want:

    4
    4

#### Mechanism

`xs` stores its members at `dbl`'s `(f64) => f64`; `one` stores `g` alone at another closure
signature. `walk` has one instance for both arguments, so its read of `ys[0]` and the call through
it take one storage's rep, and the other's closure is called at a type it was not built at. The
close keys the hole parameter's instance by its argument's storage rep, as the monomorphizer keys
an instance by type (coordinator ruling 2026-11-28): no converting copy at the call, which would
break aliasing, and no unifying of the two storages, each decided at its declaration. The trace
below moves the open half to the per-width lift.

#### Trace (I8-PREP, 2026-11-28, on #10765's seed)

The instance key is not the gap. `xs = [g, dbl]` is typed `((f64) => f64)[]` and `one = [g]` is
`((i32) => i32)[]`, because the hole lambda `g` defaults to `i32` alone, so the type key already
gives `walk` two instances: `$walk` calls its element at `(f64) => f64`, `$walk$1` at `(i32) =>
i32`. The trap is `xs`'s build. `const g = (a) => a + 1` is lifted once, at `i32` (`$g@2 (param
i32)`), and both literals store that one closure (`$global$4`, table index 7), so the `f64` slot of
`xs` holds `g`'s `i32` closure and `$walk`'s `f64` call through `xs[0]` traps. With `walk(xs)`
alone, `g` is lifted at `f64` and the program runs. The close is a `const` hole lambda stored into
storages of two widths built at each storage's slot signature, each decided at its declaration:
the per-width lift of D17808, not an instance key.
