### D16064 — a call through a `let` re-pointed between functions whose results differ is refused, where a list element holding the same two dispatches

**loud check reject · clause 2, CAPABILITY: `cannot write 'str' to 'f': called at (i32) it returns string, where 'inc', also written to it, returns i32 — every function a call through 'f' may run must return one type` · a list element holding the same two dispatches (see the ablation) · the open half of [D13966](D13966.md), whose clause-1 trap ended on 2026-10-26 · filed 2026-11-14 against master `7b679c9f1`**

Repro:

    function inc(a) { return a + 1 }
    function str(a) { return "s" }
    function run(c: boolean) {
      let f = inc
      if c { f = str }
      print(f(3))
    }
    run(true)
    // vl check: rc 1, the refusal above

Want:

    s

#### Mechanism

`holeLetJudge` (`compiler/check_relate_core.vl`) collects every function a `let` may hold
(`elabFnLetMembers`) and refuses through `holeLetDisagreeMsg` when their results at the call's
widened parameters differ. A list element (D15791) and a call result (D13965) keep the member set
and the call dispatches on the member it holds. A `let` has no such lowering, so the judge's
refusal stands in for one.
