### D1602 — a call through a closure binding was resolved by the callee's NAME, so a module function of that name won

**closed · filed 2026-09-04 against master `73376e63` · found while grading D1600 (#2541)**

Repro:

    function g() { 6 }
    function tak(g: (i32) => void) { g(8) }
    tak((n) => { print(n) })
    // before: vl check rc 0; vl run -> invalid module,
    //   "failed to validate inside `tak`: type mismatch: expected structref, found i32"
    // after:  8

#### Mechanism

The checker resolves a callee lexically, so `g(8)` above denotes the parameter and `vl check`
returns 0. Four emitter passes resolved the same callee by NAME first — `fnIndexOfInScopeChain`
and `fnIndexOf` walk DECLARATIONS, and a param or a local is in neither — so each of them
answered with the module function:

* **`emitCall`** lowered a direct `call` on `g`. Disassembled, `tak`'s body is
  `(return_call $0 (i32.const 8))` — one argument into a function whose only parameter is the
  closure ABI's `structref` env, hence the validator's sentence.
* **`emitCallStmt`**'s drop decision read the module function's `fRetVoid` row for a call
  through the binding, so a `>v` closure call had a `drop` written after it.
* **`stmtIsTailValue`** typed the frame's result from the module function's voidness. This one
  survives past the first fix: with the call lowered correctly, `tak` still promised `i32` over
  a body that leaves nothing.
* **`blockHasCallRef`** decided the frame needs no `callRefSlot`, so the `call_ref` spilled its
  fat pointer into a local the vector never declared (`unknown local 3`).

`drwFillDefaults` is a fifth, and its face is a WRONG ANSWER rather than a refusal: it
normalizes a direct call to the declaration's full arity, so with `function g(a: i32, b: i32 =
5)` beside it the shadowed `g(8)` became `g(8, 5)` and printed 13.

The fix is one predicate, `identIsBoundClosure`, read by all five: a narrowed closure arm, a
closure-typed param, a nullable one, or a local whose slot is a closure cell. It is the rungs
of `exprIsClosure`'s `Ident` arm that read a BINDING, split out so a call site can ask them
without the module-function rung above them answering first, and `exprIsClosure` now reads it
too rather than keeping a second copy. `declaredSlotLive` resolves the local, so a loop
variable's slot and a closed block binding are passed over — the rule D1597 built.

Two passes run before `buildLocals` fills that registry and need their own answer. The rewrite
pass keeps a block-scoped stack of open closure `let` names (`drwCloNames`), which is what lets
a shadowed call and a call to the module function outside the shadow's block both be right in
one frame. `stmtIsTailValue` reaches an arena rung inside the predicate, gated on the name
being a module function at all, which resolves the frame's own top-level bindings through
`exprIsClosureNoLocal` — one hop, so an alias (`const v = a`) counts.

Disassembly of the witness, before and after:

    (func $1 (param $0 structref) (param $1 (ref $1)) (result i32)   ;; before
      (drop (ref.null none))
      (return_call $0 (i32.const 8)))

    (func $1 (param $0 structref) (param $1 (ref $1))                ;; after
      (local.set $2 (local.get $1))
      (call_indirect (type $4)
        (struct.get $1 0 (local.get $2))
        (i32.const 8)
        (struct.get $1 1 (local.get $2))))

A closure the shadowing frame CAPTURES rather than binds — `function tak(g: (i32) => void) {
const run = () => { g(8) }  run() }` beside a module `function g`. Renaming `g` gives
`emitProgram: call to unknown function`: a captured closure has no call lowering at all.
Teaching `exprIsClosure` the capture storage class was measured and REFUSED here — it makes
that loud refusal check-clean invalid wasm, a clause-2 refusal traded for a clause-1
miscompile.

A `for` variable over a list of closures (`for g in fs { g(1) }`), and a closure read out of a
`Map()` then bound and called: both are check-clean invalid wasm with the collision removed.
