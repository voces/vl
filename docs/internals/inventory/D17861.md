### D17861 — a `let` written from two generic function parameters and called at two types gives neither parameter a slot per call type

**loud emit reject · `monomorphize: parameter `a` of `mid` is called at two function types that no parameter per type separates` · clause 2 · `vl check` rc 0 · filed 2026-11-28 against master `8470351db` by COV-CLOS-3 (found ablating D17323/D17324)**

Repro:

    function same<T>(k: T): T { return k }
    function other<T>(k: T): T { return k }
    function mid<F, G>(a: F, a1: G) {
      let b = a
      b = a1
      print(b(3))
      print(b("y"))
    }
    mid(same, other)
    // vl check: rc 0.  vl run: emit error at 9:16, "parameter `a` of `mid` is called at two function types that no parameter per type separates"

Want:

    3
    y

#### Mechanism

Not traced. The binding holds one of two values, so each call through it must run whichever it
holds at that call's own types: an instance per value and call signature. Mono's per-type split
gives one parameter a slot per call type only when the binding has one source.
