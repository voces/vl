### D16152 — two recursive record aliases spelled with `| null` that name each other build an invalid module

**closed 2026-11-14 · runs, prints `6` · a recursive annotation's canonical rewrite banks the spelling's own type rather than a parse of its render, so one record has one type and one struct row · was check-clean invalid wasm, clause 1 · found closing [D16069](D16069.md) · filed 2026-11-14 against master `5e7c7527f`**

Repro:

    type A = { v: i32, b: B } | null
    type B = { w: i32, a: A } | null
    let x: A = { v: 1, b: { w: 2, a: { v: 3, b: null } } }
    let s = 0
    while x != null {
      s = s + x.v
      const y = x.b
      if y == null { break }
      s = s + y.w
      x = y.a
    }
    print(s)
    // prints 6 since the close; before it, vl run: the emitted module failed to validate

Want:

    6

#### Mechanism

The second struct was not a second mint of one type but a second TYPE. Canon rewrote the binding's
annotation to the record's render, and `canonBankTyOf` banked `nameToTy` of that render. A
recursive render closes its cycle on a name (`{w:i32,a:{v:i32,b:{w:i32,a:A}|null}|null}`, the inner
`A` from `nulFoldAliasNameOf`), so the parse built a fresh copy of `B`'s record, and the emitter's
annotation walk minted that copy a row beside the type-keyed one the literals were built at.

#### Grading list

The generic spelling `type A<T> = { v: T, b: B<T> } | null` beside `B<T>`.

#### Close

`canonBankTyOf` (`check_program.vl`) banks the spelling's own resolved type when it is recursive
(`tyReachesSelf`), so no render of it is parsed back; a non-recursive annotation keeps the parse.
`nulFoldTieRecord` ties transitively, through the records its tied fields reach, so a generic
mutual pair (`GA<T>`, `GB<T>`), whose partner is tied before this wrapper has a member, and a pair
declared record-first (`W`, `K`) both end on the nullables. The witness builds two struct types,
one per record (three before, one a copy). Fixture `tests/cases/soundness/recursive-nullable-alias-mutual.vl`.
