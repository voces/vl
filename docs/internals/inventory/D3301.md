### D3301 — a record's nullable field read passed straight to an un-annotated parameter traps on `null`, even when the callee tests it

**closed 2026-09-29 (`monoArgTyName`'s struct-field rung in `compiler/emit_mono.vl` declines a field whose recorded type is a nullable record, so the nullable floor pins the instance at `O | null`) · was loads then traps, clause 1 · pre-existing on master `e70102886` · found by the NF2 lane's pass-through grid while closing the #3305 row (`pp/guard_fld_N_ann`) · filed 2026-09-29 against master `e70102886` · fixture `tests/cases/inference/hole-param-nullable-record-field-arg.vl`**

Repro:

    type O = { n: i32 }
    type R = { v: O | null }
    function u(q) {
      if q != null { return q.n }
      return 0
    }
    const r: R = { v: null }
    print(u(r.v))
    // was: vl check rc 0, then a wasm trap (null reference)
    // now: prints 0

Want:

    0

#### Mechanism

An un-annotated or generic parameter is instantiated at a pin `monoArgTyName` names from the
argument. Its `Member` rung resolves the receiver's struct and, for a field stored as code 15
(`FC_STRUCT`), returns the field's struct name. A nullable record field is also code 15 with
the same companion name, so `r.v` pinned `u` at `O`: the instance's parameter was
`(ref $0)`, the call site cast the field with `ref.as_non_null` and trapped before `u` ran, and
`u`'s `q != null` test folded to true. The rung now declines when the argument's recorded type
is a nullable record (`nodeTyIsNullableStruct`), and the ladder's nullable-struct floor pins
`O | null`, the spelling an annotated `q: O | null` already lowers. The instance's parameter is
`(ref null $0)`, the field is passed without a cast, and `u`'s test decides.
