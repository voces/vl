### D3301 — a record's nullable field read passed straight to an un-annotated parameter traps on `null`, even when the callee tests it

**loads then traps · clause 1 · pre-existing, the same on master `e70102886` · found by the NF2 lane's pass-through grid while closing D3300 (`pp/guard_fld_N_ann`) · filed 2026-09-29 against master `e70102886`**

Repro:

    type O = { n: i32 }
    type R = { v: O | null }
    function u(q) {
      if q != null { return q.n }
      return 0
    }
    const r: R = { v: null }
    print(u(r.v))
    // vl check: rc 0.  vl run: wasm trap, null reference

Want:

    0

#### Mechanism

Not yet located; it is on the emit side, since the checker's types are the direct spelling's.
Binding the same value first (`const x = r.v` then `u(x)`) prints `0`, and so does annotating
`q: O | null`, so the trap sits where a field read of a nullable record is delivered as the
argument of an inferred parameter: the read is lowered as if the field were non-null.

#### Ablation

| ingredient changed | outcome on master | needed? |
| --- | --- | --- |
| `const x = r.v` and `u(x)` | prints `0` | **yes** (a field read as the argument) |
| `function u(q: O \| null)` | prints `0` | **yes** (an inferred parameter) |
| `function u(q) { return 7 }` | traps | no (the callee's test) |
| inside `function t(z: R) { print(u(z.v)) }` | traps | no |
