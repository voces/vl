### D3301 — a record's nullable field read passed straight to an un-annotated parameter traps on `null`, even when the callee tests it

**closed 2026-09-29 (`monoArgTyName`'s struct-field rung in `compiler/emit_mono.vl` pins a nullable record field at the field's own `O|null`, reading the nullability from the struct row's declared field type, and resolves a narrowed nullable receiver through its base) · was loads then traps, clause 1 · pre-existing on master `e70102886` · found by the NF2 lane's pass-through grid while closing D3300 (`pp/guard_fld_N_ann`) · filed 2026-09-29 against master `e70102886` · fixture `tests/cases/inference/hole-param-nullable-record-field-arg.vl`**

Repro:

    type O = { n: i32 }
    type R = { v: O | null }
    function u(q) {
      if q != null { return q.n }
      return 0
    }
    const r: R = { v: null }
    print(u(r.v))
    // was: vl check rc 0, then a wasm trap (null reference)
    // now: prints 0

Want:

    0

#### Mechanism

An un-annotated or generic parameter is instantiated at a pin `monoArgTyName` names from the
argument. Its `Member` rung resolves the receiver's struct and, for a field stored as code 15
(`FC_STRUCT`), returns the field's struct name. A nullable record field is also code 15 with
the same companion name, so `r.v` pinned `u` at `O`: the instance's parameter was
`(ref $0)`, the call site cast the field with `ref.as_non_null` and trapped before `u` ran, and
`u`'s `q != null` test folded to true. The rung now pins such a field at `O|null`, through `monoAnnPinName`, the spelling an annotated
`q: O | null` already lowers. The nullability comes from the node's recorded type or, where
that is a clone's gradual `q.next`, from the struct row's declared field type
(`monoFieldDeclNullable`). A receiver pinned `O|null` (a parameter narrowed by its own test)
resolves through its base record, which is what lets a recursive `depth(q.next)` pin at all.
The instance's parameter is `(ref null $0)`, the field is passed without a cast, and `u`'s
test decides. A first candidate declined the rung and let the nullable floor spell the pin
from the node's type; that spelling is wrong for a self-referencing record (`O = { kids: O[] }`,
mutual `O`/`Q`, a linked list) and lost `runs` there, which is why the rung keeps the name.
