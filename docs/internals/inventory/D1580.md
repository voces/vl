### D1580 — the return-tail flag followed the tail expression's SUBTREE, so an if-expression written as an object-literal field value had its arms unioned into the function's inferred return

**closed (fixed) — `retTailPos` is now cleared by `checkNode` for every node that is not on the return SPINE (block, if-expression, `return`, paren), so only the function's own tail value contributes return candidates · was a loud CHECK reject at the CALLER, clause 2, at the INFERRED face only · position matrix 24 -> 30 of 30, 6 cells fixed, `runs -> not-runs` 0 · ZERO corpus cells · reported by the glean session, VL-034, `~/glean/docs/vl-issues.md`, probe `~/glean/vl-probes/VL-034-if-field-return.vl` · filed 2026-09-04 against master `9ba97704`**

Repro (runs, prints `1`):

    function a(x: boolean) { { i: if x { 1 } else { 0 } } }
    print(a(true).i)

#### Mechanism

`retTailPos` marks "the value of the node being checked IS this function's return", and
it exists so a tail `if`'s base-case branch seeds the inferred return BEFORE a recursive
sibling branch is checked (`fib`). `checkFuncDeclNode` sets it on the body's LAST
statement and `checkBlockNode` re-sets it on a block's last statement; `checkIfStmtNode`
reads it as `ifTail` and, when true, calls `noteInferredRet` for EACH arm.

Nothing cleared it on the way DOWN into a subexpression. So for the tail statement
`{ i: if x { 1 } else { 0 } }` the flag was still set when the walk reached the `if`
nested in the object literal's field initialiser, and both arms were noted as return
candidates — joined with the object literal's own type into `i32 | {i: i32}`. The
function itself checked clean; the error landed on the CALLER, describing a union the
author never wrote (`field 'i' is not on every member of i32 | {i: i32}`), and only once
the return type was USED — so the definition could sit unexported and uncalled and look
fine. The reporter met eleven at once and worked around them with a `const`, which is a
change nothing in the diff explains.

The fix inverts the default at the one dispatcher every node passes through: `checkNode`
saves the flag, clears it unless the node is on the return SPINE (`tailSpineNode`: `Block`,
`IfStmt`, `RetStmt`, `Paren` — the four whose OWN value is the return), and restores it on
exit. Restoring is what today's three consumers already did by hand, so the wrapper is a
no-op for them.

**ONE FACE, NOT TWO.** The annotated spelling was already clean at every position: the
annotation pins the destination, so the object literal's field type never mixes with the
return's. That is why a fixture that annotates could not have seen this.

#### Ablation

| ingredient removed | outcome | needed? |
| --- | --- | --- |
| the object literal (`if` is the bare tail) | runs — infers `i32` | **yes**, a CONTAINER is required |
| the container is a LIST instead (`[if x {1} else {0}]`) | refuses the same way (`i32 \| i32[]`) | no — object and list literals are the same mechanism |
| the container is a call argument or a binop operand | runs | those positions did not leak |
| the `else` (`{ i: if x { 1 } }`) | runs | **yes** — an else-less `if` is D1086's shape and takes another path |
| the tail is `return { … }` instead of a bare expression | refuses the same way | no — `RetStmt` is on the spine, so its argument inherits the flag |
| the value is bound to a `const` first | runs | **yes** — the binding is the reporter's workaround |
| the return type is ANNOTATED | runs | **yes** — the defect is inference-only |
| the caller never reads the field | checks clean | **yes** for the diagnostic, no for the wrong return type |
