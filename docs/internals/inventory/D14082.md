### D14082 — a record returned by an un-annotated lambda bound to a generic's `() => T | string` has no union box

**closed 2026-11-16 — the witness runs and prints `7` · was: loud emit reject · clause 2 · `vl check` rc 0 · `emitProgram: a record value delivered into a union box this program never registered has no tag` · found closing [D14080](D14080.md) · present on master `2f8428da3` · filed 2026-10-26 against master `2f8428da3` · bucket (e), rep-as-ADT or hash-consed types, secondary (c) (the 2026-11-14 clause-2 map)**

Repro:

    type P = {a: i32}
    const p: P = {a: 1}
    function len<T>(f: () => T | string) {
      return 7
    }
    print(len(() => p))

Want:

    7

#### Mechanism

Not traced. `T` binds to `P` from the lambda's inferred result, but the lambda's body delivers
`p` into the `P | string` box. No `P | string` union is registered by that route. Annotating the
lambda's result or the type argument registers it.
An acceptance row of bucket (e) Rep-as-ADT / hash-consed types
(`docs/internals/refactor-notes/2026-11-14-clause2-architecture-map.md`); capability probe
`lambda-record-result-at-generic-union-return.vl`. On master `a12b561d` the refusal reads
`emitProgram: ref valtype with no interned shape`, at `const p` (D15158's position).

#### Fix

The elaboration types each instance's signature (`len<P>`'s `f: () => P | string`), and
`elabInstUnionArmTys` already primes `P` as a variant from those types, but the union registry
walked only the annotations a declaration spells (`() => T | string`), so `P | string` had no row
and `P` no variant row. `collectInlineUnions` (`compiler/emit_collect.vl`) now walks every closed
instance signature (`elabInstSigTys`, `compiler/emit_elab.vl`) as it walks an annotation.
