### D3861 — a call through a top-level alias of a hole lambda is refused inside a function that rebinds the lambda's name

**closed (2026-10-08, lane SC) · was loud emit reject · found grading D3843's probes · filed 2026-10-08 against master `67ff2a485` · pins: `tests/cases/closures/alias-call-in-function-rebinding-lambda-name.vl`**

Repro:

    const c = (y) => y + "C"
    const d = c
    function k(c: string) { d(c) }
    print(k("z"))
    // vl check: rc 0.  vl build: emitProgram: a function-value call has no interned
    // signature — parameter 1 of type `` has no representation in the function-value ABI

Want:

    zC

#### Mechanism

Three resolvers read the alias from the calling function rather than from the module that
declares it. The monomorphizer's chain walk (`monoLetFrameOf`) took a module-scope binding found
from inside `k` to live in `k`'s frame, so `d`'s initializer `c` was looked up in `k`, where it
is the parameter. A `const`-only chain is otherwise re-spelled to the lambda's own name, which
the rebinding forbids, and the chain walk without a `let` on it declined. And the emitter keyed
the call from the copy's initializer read in `k`. Now a module-scope binding resolves at module
scope in all three, a `const` chain whose re-spelling is shadowed pins the lambda through the
chain and keeps the `call_ref` (`monoNameShadowedAt`), and so does any chain whose instance name
is rebound at the call. A local `const c = 1` beside the call (not a parameter) is still the
loud refusal (D3880).

#### Ablation

| ingredient removed | outcome | needed? |
| --- | --- | --- |
| the rebinding (`function k(s: string) { d(s) }`) | runs, `zC` | **yes** |
| the argument being the rebinding (`function k(c: string, s: string) { d(s) }`) | refused | no |
| `const` for the alias (`let d = c`) | refused | no |
