### D3861 — a call through a top-level alias of a hole lambda is refused inside a function that rebinds the lambda's name

**loud emit reject · found grading D3843's probes · filed 2026-10-08 against master `67ff2a485`**

Repro:

    const c = (y) => y + "C"
    const d = c
    function k(c: string) { d(c) }
    print(k("z"))
    // vl check: rc 0.  vl build: emitProgram: a function-value call has no interned
    // signature — parameter 1 of type `` has no representation in the function-value ABI

Want:

    zC

#### Mechanism

Not ablated to a site. The call `d(c)` needs no read of the parameter: `d(s)` in a function
whose other parameter, or local `const`, is named `c` is refused the same way, and the same
call in a function that binds no `c` runs. Resolving `d`'s initializer `c` from the calling
function, where `c` is the function's own binding, instead of from `d`'s frame is the likely
ingredient. Moving `monoLetFrameOf`'s answer for a global to the module frame alone does not
close it.

#### Ablation

| ingredient removed | outcome | needed? |
| --- | --- | --- |
| the rebinding (`function k(s: string) { d(s) }`) | runs, `zC` | **yes** |
| the argument being the rebinding (`function k(c: string, s: string) { d(s) }`) | refused | no |
| `const` for the alias (`let d = c`) | refused | no |
