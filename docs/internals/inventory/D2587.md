### D2587 — a closure that captures an un-annotated alias of a reference-element list cannot classify the alias as a list

**loud emit reject · clause 2 · the `closure` writer column of the laneN3 place grid (32 cells,
`(A | null)[]`, `(A | B | null)[]`, `(i32 | string | null)[]` and siblings) · the same on master
`216770428` · filed 2026-09-26 against master `216770428`**

Repro:

    type A = { r: i32 }
    function go() {
      const p: A[] = [{ r: 1 }]
      const q = p
      const k = () => { print(q.length) }
      k()
    }
    go()
    // vl check: rc 0.  vl run: emit error, "'.length' on a receiver the emitter cannot
    // classify as a list, string, map or set"

#### Mechanism

A prediction. Inside the lifted closure `q` is a captured slot whose kind is read off the
capture's recorded type, and an alias bound from another binding (`const q = p`) records no list
row for a reference-element list, so every list classifier declines it. The `i32[]` and
`string[]` spellings run, so the gap is the ref-list row lookup, not the capture: annotating the
alias `const q: A[] = p`, or reading `p` itself in the closure, runs. An index write
(`q[0] = null`) in the closure refuses the same way, as `indexed-assignment target is not an
array` / `list type not collected`.

#### Grading list

The index write `q[0] = null` in the closure, over `(A | null)[]` and `(i32 | string | null)[]`
(the grid's `idx_*_closure_*` cells). A map alias captured the same way already runs, which
says the gap is the list row.
