### D1976 — the emitter keeps each output buffer as an `i32[]` with one slot per byte, so a module past 2^23 bytes (8 MiB) traps the compiler

**closed 2026-09-22 by the compiler's collector policy, NOT by a fix — the witness is a 3.2 MB source, so `vl build`/`vl run` now compile it under the copying collector, which has no 64 MiB object cap, and it prints `3200000` · was compiler trap (`allocation size too large`, exit 70) · the mechanism stands: under `VL_COMPILE_GC=null` the same witness still traps, exit 70, and the buffers still spend 4 bytes per module byte · filed 2026-09-22 against `490229809` (#3013) · found in review of D1975 · the output-side twin of D1975's intake ceiling**

Repro (3.2M code points of source, written as `@@repeat` so the row can hold it):

    function f0(): string { "@@repeat(1600000, "a")@@" }
    function f1(): string { "@@repeat(1600000, "b")@@" }
    print(f0().length + f1().length)
    // vl check: rc 0.  vl build / vl run: prints 3200000 (copying collector, source >= 1.5 MiB)
    // VL_COMPILE_GC=null vl run: the compiler traps, exit 70; one function alone builds a 4.8 MB module

#### Mechanism

The emitter writes bytes with `wU8` (`emit_bytes.vl`), which pushes `b & 0xff` onto the current
buffer. Every buffer is an `i32[]`: the module's own `W.bytes` (`emit_state.vl`,
`{ bytes: i32[] }`) and each function body's buffer before `wBytes` appends it. The compile
store runs under the null collector, where one object is at most 64 MiB, so `.push`'s growth
to 2^24 slots traps as soon as a buffer passes 2^23 bytes. Named backtrace for the repro:
`wU8@emit_bytes.vl:261` ← `wBytes@emit_bytes.vl:305` ← `emitFuncCode@emit_sections.vl:801`,
appending the second function to `W.bytes`. A single function past 8 MiB traps in its own
buffer first (`wSLEB` ← `fbI32Const` ← `emitStr`). A string literal emits about three module
bytes per character, so the trap needs about 2.8M characters of literal. plumb's shape (D1975)
emits about 0.3 bytes per source byte and reaches the 4 GiB heap ceiling first.

A separate ceiling, not this row: wasmtime refuses any function body over 7,654,321 bytes
(`function body size count exceeds limit of 7654321`). A single 2.75M-character literal builds
an 8.26 MB module that the engine then rejects, exit 70 with the invalid-module banner.

#### Ablation

| ingredient removed | outcome | needed? |
| --- | --- | --- |
| `f1` (one 1.6M-character function, 4.8 MB module) | runs | **yes** |
| the split into two functions (one 2.85M-character literal) | same trap, in the function's own buffer | no |
| the collector (`vl check`, a collecting collector, no emit) | rc 0 | **yes** |

#### Grading list

- The fix must hold at the next buffer too: a module and a function body each past 8 MiB,
  and the function past 7,654,321 bytes must then fail at the engine's limit, not in the compiler.
- A byte buffer (`u8[]`, a quarter of the memory) moves the ceiling to 2^25 bytes (32 MiB);
  chunking `W.bytes` the way D1975 chunked the intake removes it.
