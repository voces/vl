### D1976 — the emitter keeps each output buffer as an `i32[]` with one slot per byte, so a module past 2^23 bytes (8 MiB) traps the compiler

**fixed 2026-09-22 — the witness now builds an 8.56 MB module that wasmtime refuses at its per-body limit, which is check-clean invalid wasm and the next ceiling's own row ([D2092](D2092.md)) · was compiler trap (`allocation size too large`, exit 70) · filed 2026-09-22 against `490229809` (#3013) · re-witnessed 2026-09-22 as a two-file program so the ENTRY FILE stays under 1.5 MiB and `vl build`/`vl run` keep the null collector (an entry file of 1.5 MiB or more compiles under the copying collector, which has no 64 MiB object cap and does not reach this trap) · found in review of D1975 · the output-side twin of D1975's intake ceiling · fix: packed `u8[]` buffers, one per code entry, joined into a chunk rope (`emit_state.ByteRope`); pin `tests/vl_large_output_test.ts` · residue D1977, D1978**

Repro (a 2.85M-character literal, an 8.55 MB body, in an IMPORTED module, written as `@@repeat` so the row can hold it):

    // file: m.vl
    export function f0(): string { "@@repeat(2850000, "a")@@" }
    // file: main.vl
    import { f0 } from "./m"
    print(f0().length)
    // vl check: rc 0.  before the fix: the compiler traps, exit 70, in the body's own buffer
    // (entry file 45 bytes: null collector). after: `vl build` writes the module and wasmtime
    // refuses it, "function body size count exceeds limit of 7654321", exit 70 with the
    // invalid-module banner

#### Mechanism

The emitter wrote bytes with `wU8` (`emit_bytes.vl`), which pushed `b & 0xff` onto the current
buffer, and every buffer was an `i32[]`: the module's own `W.bytes`, each section payload, the
code payload and each function body. The compile store for an entry file under 1.5 MiB runs
under the null collector, where one object is at most 64 MiB, so `.push`'s growth to 2^24 slots
trapped as soon as any one buffer passed 2^23 bytes: the code payload for a module of several
ordinary functions (`wU8` ← `wBytes` ← `emitFuncCode`), a single body past 8 MiB in its own
buffer (`wSLEB` ← `fbI32Const` ← `emitStr`), the export payload for 86 exports of 99,000-character
names (`wU8` ← `wName` ← `emitExportSection`). Every byte buffer is now a packed `u8[]` (a quarter
of the memory, so a buffer's own ceiling is 2^25 bytes), each code entry renders into a buffer of
its own, and the module is a `ByteRope` — an ordered list of chunks, one per section header,
section payload and code entry, joined without a copy. The host reads it out unchanged through
`rbyteLen`/`rbyteAt`/`rbyteStore`, which walk the chunks.

Output is byte-identical: the compiler's own self-compile is a fixpoint across the change, and
all 3,321 `tests/cases` programs build to identical bytes (and identical failures) with and
without `--names`. Self-compile peak RSS 1,211 MB → 1,135 MB; CPU unchanged within noise.

#### Ablation

| ingredient removed | outcome | needed? |
| --- | --- | --- |
| the literal's length (1.6M characters, a 4.8 MB module) | builds and runs | **yes** |
| the null collector (`VL_COMPILE_GC=copying`) | no trap; the module is refused at the engine's function-body limit, [D2092](D2092.md) | **yes** |
| the module split (the literal in the entry file, which is then 1.5 MiB or more and gets the copying collector) | as the row above, [D2092](D2092.md) | **yes**, under the default collector choice |
| the emit (`vl check`, no emit) | rc 0 | **yes** |

#### Grading list

- Two functions of 1.6M characters each (a 9.6 MB module) build, and V8 runs the module and
  prints `3200000` (`tests/vl_large_output_test.ts`). Do not `vl run` it: wasmtime's compile of
  a literal-heavy module this size takes minutes and ~25 GB.
- Twenty such functions of 1.2M characters (a 72 MB module, past the old ceiling eight times)
  build in 3.3 s at 2.9 GB peak RSS, and V8 validates the result.
- The next ceilings: one BUFFER past 2^25 bytes (a single body or a single non-code section
  past 32 MiB) still traps, D1978; one string LITERAL past 2^23 code points traps in the string
  pool first, D1977; a body past 7,654,321 bytes is the engine's refusal, [D2092](D2092.md).
