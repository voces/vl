### D15464 — a generic sharing a function type parameter with a closed function or a closure, called at two types, runs only through the split plan

**closed 2026-11-06 · now a loud check reject at the argument `con`, `` `con` is passed as `F`, but `go` calls `F` with `string` (line 3); `con` takes `i32` `` · was runs only through the split plan · DESIGN (owner ruling 2026-11-06, Q6 (A): an unbounded `<F>` takes what the body demands of it, and an argument failing a demand is refused at the call, naming it, as constraints-design.md §7.7 refuses `dbl<T>`'s) · `go(same, same)`, an un-annotated `con` (D15458), a `(x: string | i32)` `con` and `a` called at one type all run, with the split plan on and off · the residue of D15458 · filed 2026-11-05 against master `0a92a593`**

Repro:

    function go<F>(a: F, b: F) {
      print(a(3))
      print(a("x"))
    }
    function same<T>(k: T): T { k }
    function con(x: i32) { x }
    go(same, con)

Want:

    the refusal above, at `con`

#### Mechanism

`a` and `b` share `F`. The joined-set rule (D15409, D15458) binds `F` to the union of the
arguments' sets where each argument is a generic or a hole function, so each holds an id in the
union. `con` is a closed function and has no id in any set, so the rule declines, as it must, and
the unsplit compile takes `same` as a value of one signature. The plan splits `a` per type.
