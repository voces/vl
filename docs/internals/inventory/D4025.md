### D4025 — a function returning a generic call on a bare `null` is invalid wasm

**closed by D4550 — `id<null>` returns the `nulnone` cell `d`'s signature already declared · was check-clean invalid wasm · clause 1 · found grading D4024's position matrix (`dst-generic-id-null`, `return_inferred`) · filed 2026-10-11 against master `3667afbf9`**

Repro:

    function id<T>(x: T): T { x }
    function d() {
      return id(null)
    }
    const v = d()
    print(v == null)
    // vl check: rc 0.  vl run: invalid module inside `d`: current function requires result type [nullref]

Want:

    true

#### Mechanism

No destination reaches the call, so `T` binds to `null` and `d`'s inferred return is the null
type, which the function's signature lowers as `nullref` while the `id<null>` instance returns
another reference type. The annotated spelling `const v: Item | null = d()` fails the same way:
the binding's annotation does not reach through `d`'s inferred return.
