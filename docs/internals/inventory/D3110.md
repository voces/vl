### D3110 — a lambda calling a record field's function through a parameter traps with `indirect call type mismatch` when two record layouts share the function

**loads then traps · clause 1 · open · found by the #3274 review (`rv3274-5974/p/nb/c1.vl`, `c3.vl`) · the same on master `d408f2da4` · filed 2026-09-28 against master `d408f2da4`**

Repro:

    const s = { f: () => "ok" }
    const b = { f: () => 7 }
    function hole(z) {
      const k = () => z.f()
      print(k())
    }
    hole(s)
    hole(b)
    // vl check: rc 0.  vl run: prints `ok`, then wasm trap: indirect call type mismatch

Want:

    ok
    7

#### Mechanism

Not localised past the ablation. The direct call `z.f()` resolves the field's closure per
instance ([D987](D987.md)'s argument resolution); inside the lambda the receiver is a capture, and
the second instance calls through the first layout's signature.

#### Ablation

| ingredient changed | outcome | needed? |
| --- | --- | --- |
| `print(z.f())`, no lambda | prints `ok` `7` | **yes** (the lambda) |
| `hole(b)` removed | prints `ok` | **yes** (the second layout) |
| `function hole<Z>(z: Z)` | traps the same | no |
