### D3884 — indexing one generic's `T` refuses a non-array argument to every other generic whose parameter is also called `T`

**closed 2026-10-08 by lane SC · runs · was a loud check reject, a valid program refused (clause 2) · found closing D3853 · filed 2026-10-08 against master `a1c9be3c4` · pins: `tests/cases/generics/index-demand-per-generic.vl`**

Repro:

    function first<T>(y: T) { print(y[0]) }
    function show<T>(x: T) { print(x) }
    first([1])
    show(2)
    // vl check: argument 1: expected an array, got i32

Want:

    1
    2

#### Mechanism

`holeArrayDemand` records that a type variable is indexed in a body, under the variable's bare
name. The pin then asks whether its parameter's name was ever indexed anywhere, so `first`'s
`y[0]` made `T` demand an array at `show(2)`. The demand is now keyed by the row's declaring
function (`arrayDemandKey`), the key a declared parameter's row carries. A hole, or a row with no
owner, keeps the bare name, and a pin still honours a bare-name record. A value of an enclosing
type parameter passed to an indexed parameter carries the demand to that parameter's own pin.
