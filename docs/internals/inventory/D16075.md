### D16075 — a lambda's result is taken to reach no call once the emitter renames it, so a generic function it returns is stubbed and the call traps

**closed · clause 1 by #7945 (the refusal), clause 2 here: the written function type's result is the returned generic's delivery · found by lane I grading D16073's `vrFnValue` · filed 2026-11-14 against master `2e964197`**

Repro:

    function inc(x) { x + 1 }
    const m: () => (x: i32) => i32 = () => inc
    print(m()(5))

Want:

    6

#### Mechanism

`vrFnValue` (value_reach) sends a lambda to "lost", meaning its result may reach any call, and
sends a named function to the calls that read it by name. It recognised a lambda by
`fnName == ""`. The monomorphizer asks after `collectFns` has renamed every lambda `__lambda_N`
(D16073), so the lambda took the named arm. Nothing reads `__lambda_N` by name, so the result
"reached no call", `inc` was judged inert, and the prune stubbed it as `() -> void`. The
disassembly shows `inc` as `(func $3 (param structref))` called through `call_indirect` at
`(structref i32) -> i32`. Now both of `vrFnValue`'s lambda tests use `fnNameIsLambda` (ast),
which also matches the renamed spelling, so `inc` stays reached and the emitter's value floor
refuses it. A lambda maker reached the same trap through a parameter
(`function run(f: () => (x: i32) => i32) { print(f()(5)) }; run(() => inc)`), a binding of
`f()`, and a block body `() => { return inc }`.

#### Grading list

- Clause 2 is closed in the elaboration. When `elabReadOn` follows a returned value to its
  lambda, it also adds the closed result of the function type written where that lambda is
  bound (a typed `let`) or handed (a typed parameter), through `elabLamWrittenRetAdd`. The
  returned read then has one flow pin and is instanced there. Mono discovers nothing.
- `tests/cases/closures/generic-fn-returned-by-lambda-at-annotated-type.vl` (renamed from its
  `error-` spelling) runs the binding, block-body, parameter and binding-of-call spellings at
  `i32` and at `f64`.
- Still open, as D16077: a hole parameter (`function run(f)`) whose result is called. The
  argument lambda's type stays open there, so `run`'s instance has no closure type for `f`.
