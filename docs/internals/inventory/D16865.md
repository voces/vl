### D16865 — a maker's generic stored into an un-annotated map, after another call of the maker is delivered at a closed type, traps at the call through the map value

**closed · now runs, prints `s` `41`: a read of the maker's result leaves out the calls an index write or `set` stores it into a map element reaches ([D16864](D16864.md)) · was loads then traps (`indirect call type mismatch`), `vl check` rc 0 · clause 1 · the `map_set` and `map_value` un-annotated cells of `generic-relay-two-results.matrix.vl` ([D16755](D16755.md)'s template) · found grading D16412 · filed 2026-11-16 against master `9648a5f2a` · closed by `eplSlotCallRecs` (emit_elab.vl) · named cell `slotmv_maker_generic_map_get`**

Repro:

    function k<T>(x: T): T { return x }
    function mk() { return k }
    const w: (x: string) => string = mk()
    print(w("s"))
    const m = Map()
    m.set("k", mk())
    const mv = m.get("k")
    if mv != null { print(mv(41)) }

Want:

    s
    41

#### Mechanism

The first `mk()` is delivered at `(string) => string`. The second is stored into
an un-annotated map and called at `i32` through the value read back, but that value calls the
`string` instance. D16755 twins a relay per closed result at bindings, which a map value is not. The slot store's classes followed the `set` into the map and delivered the generic's read at both types; mono built one instance. The read now omits the write's calls, as for D16864.
