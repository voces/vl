### D1661 — the module scope's two declaration registries were each checked against themselves and never against each other

**now a loud check reject · 20 cells, ten module-scope positions of `call-through-binding-shadowing-fn-name` in both faces · filed 2026-09-05 against master `d040e263` · closed against `d040e263`**

Pass 1.5 cross-checks `fnDeclIx` when it hoists a top-level value binding, so a top-level
`function` and a top-level `let`/`const` of one name are the `redeclared` B16 already names.
The four nested-shadowing controls are unchanged.

Repro:

    function v(): i32 { 6 }
    const v: (i32) => void = (n: i32) => { print(n) }
    v(8)
    // vl check: redeclared v

#### Mechanism

The checker keeps two module-scope declaration registries — `fnDeclIx` for top-level
functions, `moduleGlobals` for top-level value bindings — and hoists them in two passes. Pass
1 refuses a second `function` of a name it already holds; pass 1.5 refuses a second
`let`/`const`. **Neither reads the other registry**, so the cross-kind pair alone was admitted
at `vl check` rc 0. The emitter's call arm then resolved `v` by name to the module function
and emitted a direct `call`:

    0x0dc   ref.null -21     ;; the env of `function v(): i32`
    0x0de   i32.const 8      ;; the argument the closure wanted
    0x0e0   call 4           ;; (structref) -> i32, ONE parameter
    ;; type mismatch: expected structref, found i32

**This is a refusal the DESIGN owed, and the grading is CLAUDE.md's own test.** The
neighbouring spellings at the same scope are already refused with the same word (two
top-level `function v` and two top-level `const v` each read `redeclared v`), a module MERGE
refuses the pair at parse (`Duplicate binding "v"`), and the refusal names a CONTRACT rather
than a mechanism — B16, "one binding per name per scope; nested shadowing is allowed". The
spellings that run are all nested: a function body and a module-scope BLOCK are scopes of
their own, and both keep running.

**The family is wider than the closure call the template is built on.** `let v = 1` beside
`function v(): i32` is the same check-clean invalid wasm with no closure and no call in it,
so the ingredient is the collision, not the callee shape.

Needed: the module scope AND the collision. Not needed: the closure, the call, the
annotation, the declaration order, or the function's generic-ness.
