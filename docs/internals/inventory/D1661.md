#### Mechanism

Not ablated to a mechanism. What the ablation establishes is that the SHADOW is the whole
ingredient and the result kind is not: deleting the module `function v` runs, renaming the
binding runs, and an i32-returning closure under the shadowed name fails exactly as the void
one does. So the call is being resolved by NAME to the module function — D1602's shape, which
that row closed for a function-scoped binding and left standing at module scope.

**The template's own skip reasons for these ten positions were false and are what hid the
family.** They read `a second module-scope v is redeclared v, not a shadow`; the checker
admits the program at rc 0 and the module is what fails, so the cells graded the capability
after all. Running the sentence is what corrected it (CLAUDE.md, "before believing a
refusal's scope, run the plainest program the sentence forbids").
