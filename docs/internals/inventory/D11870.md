### D11870 — an unresolved import whose path holds `$m<digits>` names a module key with the suffix cut

**closed 2026-10-24 — the witness is now a loud check reject (parse error) that names the module key as written, `(no module "n$m1.vl")` · was a loud check reject (parse error) with the wrong module key in its message · filed 2026-10-24 against master `0ed167e92` · fixed by double-quoting the module key in the five import diagnostics that carry it (unresolvable ×2, cycle, chain depth, duplicate binding), so `demangleSpelling` skips it as user text · pinned by `tests/cases/modules/err-unresolvable-mangle-shaped-path/`**

Repro:

    import { q } from "./n$m1"
    print(q)
    // vl check: rc 1, `Cannot resolve import "./n$m1" (no module `n.vl`)`; want `n$m1.vl`

#### Mechanism

The import diagnostics in `driver.vl` print the module key in backticks, and every
reader of a diagnostic passes it through `demangleMsg`, whose `demangleSpelling` cuts
`$m<digits>` anywhere outside a double-quoted segment (D11850). A module key is user text
and is never mangled, but in backticks it looks like an internal name. The specifier in
the same message is double-quoted and is kept.

#### Ablation

| ingredient removed | outcome | needed? |
| --- | --- | --- |
| the digit after `$m` (`./n$x1`) | message reads `n$x1.vl` | **yes** |
| `demangleMsg` on the read | message reads `n$m1.vl` | **yes** |

#### Fix

The key is double-quoted, like every other user-text segment in a diagnostic. Making
`demangleSpelling` skip backtick segments instead would be wrong: backticks also wrap
internal names that must be demangled — `tyToStr` output (`check_num_lits.vl`,
`check_calls.vl`'s bound refusals) and narrowing place keys (`check_getter_effects.vl`).
Graded one program per message, each with `$m1` in the path: unresolvable relative import,
cycle back-edge, chain past depth 256, duplicate binding in a module named `m$m1.vl` — all
four printed the key cut before and as written after. `#lu0` in a path was already kept
before the fix (no inline-union alias is registered when the module pass reports), and the
not-exported refusal names only the double-quoted specifier, so neither moved.
