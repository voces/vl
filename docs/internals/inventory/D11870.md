### D11870 — an unresolved import whose path holds `$m<digits>` names a module key with the suffix cut

**loud check reject (parse error) with the wrong module key in its message · filed 2026-10-24 against master `0ed167e92`**

Repro:

    import { q } from "./n$m1"
    print(q)
    // vl check: rc 1, `Cannot resolve import "./n$m1" (no module `n.vl`)`; want `n$m1.vl`

#### Mechanism

The import diagnostics in `driver.vl` print the module key in backticks, and every
reader of a diagnostic passes it through `demangleMsg`, whose `demangleSpelling` cuts
`$m<digits>` anywhere outside a double-quoted segment (D11850). A module key is user text
and is never mangled, but in backticks it looks like an internal name. The specifier in
the same message is double-quoted and is kept.

#### Ablation

| ingredient removed | outcome | needed? |
| --- | --- | --- |
| the digit after `$m` (`./n$x1`) | message reads `n$x1.vl` | **yes** |
| `demangleMsg` on the read | message reads `n$m1.vl` | **yes** |
