### D16279 — a `for` over a parameter bound to a list of records of un-annotated functions whose results differ, built by a call, called each element's field through its first member's signature

**closed · runs, prints `5.5` · was a wasm trap (indirect call type mismatch) on a check-clean program · clause 1 · found grading [D16278](D16278.md)'s parameter form after #8225, which let a `for` over a hole parameter check · filed 2026-11-15 against master `6015bf3ed` · closed 2026-11-15 by lane N: the instance's fact follows a `for` element to the list it walks (`elabForInIterOf`), the decision roots its call there (`ftForInIterOf` in `ftSlotRoot` and `ftChainFields`), and a list a call returns takes the rep of the literal it returns, its stamp or the rep that literal is built at (`fnTagRetPlaceRep`, `fnTagLitRep`), which mono pins the parameter at · fixture `closures/fn-field-list-from-call-dispatches-through-param.vl` · matrix `fn-field-list-from-call-through-param.matrix.vl`**

Repro:

    function inc0(a) { return a + 1 }
    function half(a) { return a / 2.0 }
    function mk() { return { a: [{ f: inc0 }, { f: half }] } }
    function takeF(v) { let acc = 0.0; for e in v { acc = acc + e.f(3) }; print(acc) }
    const L = mk().a
    takeF(L)

Want:

    5.5

#### Mechanism

The check leaves a list bound once to a call's result to the per-member dispatch, as it does a
literal list. The elaboration's fact for a call through an element's field (D16160) followed an
index off the parameter but not a `for` element, so the decision never tried the set, the list
was built of closures, and the instance called `half`'s `(i32) => f64` thunk through
`(i32) => i32`. The index spelling was refused at emit instead: the list a call returns had no
stamped rep, so mono found no pin for the parameter.

#### Ablation

| `inc0` and `half` annotated | runs | the un-annotated members: **yes** |
| the loop at module scope | runs | the parameter: **yes** |

#### Grading list

`fn-field-list-from-call-through-param.matrix.vl`: the bound, `let`, in-function and literal
spellings by index and by `for`, and the un-annotated built-in positions that bind the list
first. The list handed straight to the parameter (`takeF(mk().a)`) and a field of a bound
record (`take(r.a)`) are still refused at check; they are [D16278](D16278.md)'s.
