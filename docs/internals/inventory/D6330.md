### D6330 — a `const` lambda calling its hole parameter at two instances, ill-typed at one, passes check and is refused at emit

**loud emit reject · `vl check` rc 0 · clause 2 · found closing [D6300](D6300.md) · filed 2026-10-18 against master `5e3ba8429` on lane L3's `l3-d6250` base `f30a3c7ce`**

Repro:

    function id(a) { return a }
    const lap = (g) => "" + g(1) + g("s")
    print(lap(id))
    // vl check: rc 0.  vl run: emitProgram: cannot take the generic function `id` as a value — a function value carries ONE signature, and parameter `a` is un-annotated (it would default to i32)

#### Mechanism

From the ablation only. [D6300](D6300.md) judges each operator over a hole call's result at
each instance when the callee is a declared function. A `const` lambda callee's parameter is a
lambda hole, and the instance machinery that check uses reads only a declared function's
parameters, so `"" + 1` at the `i32` instance is never judged. The checker owes the refusal; a
fix should not make the program run.

#### Grading list

The declared-function spelling, which must keep refusing, and the `g(1) + g("s").length`
sibling, which must keep running.
