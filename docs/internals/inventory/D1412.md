### D1412 — the `is` complement over a hole parameter reaches every arm EXCEPT a literal one: the pin softens `"err"` away before the emitter's complement can see it

**loud check reject · clause 2 · the `i32 | null` and `i32 | string` spellings of the same
program RUN since [D1243](#d1243), and the annotated `a: i32 | "err"` twin prints `10` ·
filed 2026-09-03 while closing D1243**

Repro (`vl check` rc 1; the same body under `function take(a: i32 | "err")` prints `10`, and
so does the identical program with `null` or `string` in place of the literal arm):

    function orErr(bad: boolean): i32 | "err" {
      if bad { return "err" }
      return 5
    }

    function take(a) {
      if a is "err" { print(0) } else { print(a * 2) }
    }

    take(orErr(false))

#### Mechanism

[D1243](#d1243) built the deferred remainder (`HD_GNOT`): a hole has no member list to
subtract from, so the `else` arm's type is a derived hole the CALL's pin resolves. The
checker half works at every arm — with the gate lifted, `vl check` returns 0 for this program
and types `a` in the else arm as `i32`.

**The EMITTER is what confines it.** `litElseNarrow` (`emit_classify.vl`) is the only
complement that can see a literal member, and it reads the receiver ident's own recorded
type. For a hole parameter that type is the pin's SOFTENED spelling: measured, a 2-member
union whose members yield ZERO literal lexes — `i32 | string`, not `i32 | "err"`. So `"err"`
matches no member, nothing is pushed, and the else arm reads the raw `(ref $uBox)` where the
i32 arm is expected. With the gate lifted the four literal cells are **check-clean invalid
wasm** (`type mismatch: expected i32, found (ref $type)`), which is why D1243 ships gated:
that is the "narrow the checker first" trade CLAUDE.md names, paid in full.

The parameter ANNOTATION is not the missing spelling either — the synthesized annotation
route was built and measured, and it answers the same softened union. The exact type survives
in the CHECKER (`take(orErr(false))` reports `expected boolean, got i32 | "err"` for an
un-annotated `const z: boolean = a`), so the fix is to carry the un-softened member set to
the emitter's complement, not to find it somewhere it already is.
