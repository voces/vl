**closed 2026-09-03 by banking the CALL'S PIN and reading the literal complement from it ·
was loud check reject, clause 2 — only the LITERAL arm was lost, the `i32 | null` and
`i32 | string` spellings having run since [D1243](#d1243) · ZERO corpus cells · fixture
`inference/hole-param-is-complement.vl` · `matrix/orerr-generic-pin` 47 -> 49 of 52,
0 silent, 0 runs lost; its nullable twin unmoved at 52 of 52 · filed and closed 2026-09-03**

Repro (prints `10`; before the fix `vl check` rc 1, while the same body under
`function take(a: i32 | "err")` printed `10` and so did the identical program with `null` or
`string` in place of the literal arm):

    function orErr(bad: boolean): i32 | "err" {
      if bad { return "err" }
      return 5
    }

    function take(a) {
      if a is "err" { print(0) } else { print(a * 2) }
    }

    take(orErr(false))

#### Mechanism

[D1243](#d1243) built the deferred remainder (`HD_GNOT`): a hole has no member list to
subtract from, so the `else` arm's type is a derived hole the CALL's pin resolves. The
checker half works at every arm — with the gate lifted, `vl check` returns 0 for this program
and types `a` in the else arm as `i32`.

**The EMITTER is what confined it, and the filed sentence was one layer off.**
`litElseNarrow` (`emit_classify.vl`) is the only complement that can see a literal member,
and it reads the receiver ident's own recorded type. The row filed that type as "the pin's
SOFTENED spelling, a 2-member union whose members yield ZERO literal lexes"; re-measured
with an accumulating emit-time log, **it is not a union at all — it is the HOLE**
(`tyToStr` renders `_`, the `TyVar` is `?take.0`), so `litElseNarrow` never reached its own
member walk. The softening IS real, one holder further out: `unionNameOfIdent` and the
union REGISTRY row both answer `i32|string`, with `unTyIx` and `unMemTys` recording
`i32::i32, string::string` — no literal anywhere. Both facts had to be true for the cell to
fail, and only the second one was filed.

Three places the arena still carried `i32 | "err"`, none of which the emitter could reach:
the `orErr` declaration, the ARGUMENT at the call, and — measured — the ELSE-arm read's own
recorded type, which is the derived hole `?gnot.64.?take.0` whose `alt` names the tested
literal's arena row.

**The fix is the CALL'S PIN, banked.** `substHoleTy` is the one seam where a hole meets the
type a call bound it to (`bindOf`); `notePinnedHole` records that type under the hole's name
there, first pin winning and a DISAGREEING second pin poisoning the row to `-2` — one wasm
body serves every call, so a rep read off one pin would be a miscompile at the other.
`pinnedHoleTyOf` is the emitter's reader, and `litElseNarrow` resolves through it before its
member walk. A non-hole answers -1, so the annotated spelling's route is untouched, and the
hole face then takes the identical path: the soundness surface is the one that already
ships.

**THE NAIVE LIFT'S PRICE, RE-MEASURED, IS TWO MATRIX CELLS AND ONE PROGRAM — not four
cells.** A seed carrying ONLY the `isLitBearing` removal from `holeElseRemainderOk` grades
`orerr-generic-pin` at **47 of 52 with 2 SILENT** — `argument`/un-annotated and
`early_return_guard`/un-annotated, `type mismatch: expected i32, found (ref $type)` — and
turns this row's own witness (which is also D1243's witness and
`scripts/capability-probes/is-complement-hole-param.vl`, one program filed three times)
check-clean invalid wasm. The nullable matrix does not move: it has no literal arm.
Disassembled, the silent arm is `(i32.mul (local.get $0) (i32.const 2))` over the
`(ref $uBox)` parameter, where the working `i32 | string` twin reads
`(struct.get $1 0 (ref.cast (ref $1) (struct.get $0 1 (local.get $0))))`. With the pin
banked the literal face emits that same unbox and every one of those cells runs.

#### The soundness control, and why it is the cell to keep

A pin of `i32 | string` tested against `is "err"` must NOT reduce: the else arm can still
hold another string. It does not — `subtractTy` declines and the remainder keeps the whole
pin, so `else { print(a * 2) }` refuses there exactly as it did before, and
`litElseNarrow`'s own "exactly one member is the tested literal" walk finds `hit == 0` over
`[i32, string]`. The fixture carries that cell (`takeWide`) beside the closing one.
