### D9130 — an un-annotated `const` alias of a re-pointed `let` of functions, handed to a generic higher-order parameter, is refused

**loud emit reject · `vl check` rc 0 · clause 2 · CAPABILITY: the `let` itself handed at the same call runs ([D9001](D9001.md)), and so does the alias handed to `.map` · found closing [D9006](D9006.md) · present on master `c4d5c70cc` · filed 2026-10-21 against master `c4d5c70cc`**

Repro:

    function fst<T>(xs: T[]): T { return xs[0] }
    function lst<T>(xs: T[]): T { return xs[xs.length - 1] }
    function app<T>(g: (x: T[]) => T, v: T[]): T { return g(v) }
    let f = fst
    if [1].length > 0 { f = lst }
    const g = f
    print(app(g, [1, 2, 3]))
    // vl run: emitProgram: monomorphize: unsupported argument type for `g` in a call to `app`

#### Mechanism

Not traced. A `.map` callback follows the alias to the written `let`
(`monoCoerceAliasOfWrittenLet`, emit_mono.vl); the hand to a generic's arrow parameter
coerces a written `let` only when the argument names it directly (`monoHandWrittenLet`).
