### D17118 — `print` of an assignment of `null` to a `K | null` binding takes the `i32` arm, since `printArmOf` asks only `exprIsNulNone`

**fixed 2026-11-24 · closed, runs `null` · was: check-clean invalid wasm · clause 1 · reserved by IR-N7, filed 2026-11-24 against master `1784a86d` by IR-N9 · fixed by `printArmOf` (wasmEmit.vl): its first test is `boxOperandIsNulNone`, whose `asgYieldsNullLit` half names an assignment of `null` · fixtures `null/print-an-assignment-of-null-{string,i32,boolean,list}-or-null.vl`**

Repro:

    function nnull() {
      let m: string | null = "ss"
      print(m = null)
    }
    nnull()
    // vl check: no errors.  vl run: invalid module, type mismatch: expected i32, found nullref

Want:

    null

#### Mechanism

The value of `m = null`, typed `null` by the checker, is the `null` unit, not a re-read of the
cell. `exprIsNulNone` answers only from a cell, so `printArmOf` fell through its ladder to the
`"i32"` default and called `__print_i32__` on the `ref.null` the assignment yields. The same root
as D17090 at the union-box delivery sites, which `boxOperandIsNulNone` already closed there.

#### Ablation

| spelling | outcome before | in the family? |
| --- | --- | --- |
| `print(m = null)`, `m: string \| null` | invalid module | **yes** |
| the same over `i32 \| null`, `boolean \| null`, `i32[] \| null` | invalid module | **yes** |
| `const r = m = null` then `print(r)` | prints `null` | no |
| `print(m = "y")` | prints `y` | no |
| `let n = null` (inferred) then `print(n = null)` | invalid module | no: D17120 |

#### Grading list

- `print((m = null))`, parenthesised: want `null`.
