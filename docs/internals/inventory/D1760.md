### D1760 — a list literal built from a hole parameter pinned at the softened `string` reserves no string list, so [D1756](D1756.md)'s close routes one more program into [D1740](D1740.md)'s floor

**closed 2026-09-06 — five routes, and only the one that carries the REP rather than the type closes it · filed against `709e3e9fb`, closed against `#2768`'s tree · was the PRICE [D1756](D1756.md)'s close paid, and the only cell it lost · 0 corpus cells**

Repro:

    function mkval(): "red" | "green" { return "red" }
    const srcArr = [mkval()]
    function take(p) {
      const xs = [p]
      print(xs[0])
    }
    take(srcArr[0])
    // vl check: rc 0.  vl run: rc 0, prints red

Was: `emitProgram: string array literal but string list type not collected`. It also ran BEFORE
[D1756](D1756.md)'s close, but for the wrong reason — the parameter was pinned at the atom's raw
width, which is the defect that close fixes; the value survived only because nothing read it as
a member.

#### Mechanism

Measured. [D1756](D1756.md) pins an inline literal-union element at the softened `string`, so
`[p]` inside the callee is a STRING list — and the collect scan classifies a list literal with
no frame, so a parameter element reserves nothing and the emit floor refuses a rep it can name.
It is [D1740](D1740.md)'s mechanism exactly, reached by one more program.

**Five routes were built. The four that only reserve the string list were refused**, each on
its own measurement, and the fifth is the close:

| route | result |
| --- | --- |
| 1. name a literal-union element's rep by alias-ness at the collector | this cell and [D1740](D1740.md)'s go **SILENT invalid wasm** |
| 2. match the element NAME against every parameter annotation in the program | same, plus an `arena-scan-outside-pass` regression |
| 3. route 2 with the element-pin reader gated on ALIAS-ness | fixes both, and **breaks `joined-element-adopts-the-annotated-list.vl`** — a declared inline-litunion array genuinely holds atoms |
| 4. the same gate narrowed to a list LITERAL, still asking the pinned TYPE | breaks that fixture anyway, and both cells go silent |
| **5. carry the REP into all three sites, asked in the enclosing frame** | **both cells run, every control holds** |

**What routes 1-4 share is that all four ask a TYPE.** A literal union's type does not carry its
rep, so the reader deciding whether `xs[0]` is an atom could not tell a declared litunion array
(atoms) from a list literal built from a `string`-pinned parameter (strings) — both reach it as
"an array whose element pins to a literal union". Reserving the string list without moving that
reader is why every one of them traded the floor for invalid wasm, and the floor was correct to
stand there.

#### Close

The rep IS what the elements lower as, and `arrLitIsStr` answers it — but only with a frame,
which none of the three sites had. Route 5 gives each one:

* The collector's list reservation moves off the whole-arena scan (no enclosing function, so it
  passed `-1`) and into `collectArrNewFrames`' per-body walk, which exists for this exact shape
  at the array intrinsics ([D1669](D1669.md)). Monotone, so a spare reservation is inert.
* `exprIsLitAtom`'s `Index` arm declines before its type rungs when the receiver is a local
  bound to an un-annotated list literal whose elements lower as strings, resolved through
  `localDeclIx`. An annotated binding is not that question — its annotation fixed the rep.
* `arrElemLitUnionTyAt`'s element-pin rung answers atom for a list literal only when its first
  element lowers as one.

Route 3's control passes because the gate is now the element's rep and not the pin's alias-ness:
a declared `("red" | "green")[]` holds atom elements, `arrLitIsStr` says so, and nothing declines.
