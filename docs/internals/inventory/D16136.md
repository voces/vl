### D16136 — a value `if` of list literals of records of un-annotated functions, bound to a `const` and returned, is refused at emit, where the same join returned directly runs

**loud emit reject · `emitProgram: cannot take the generic function` … `as a value — a function value carries ONE signature`, naming `inc0` · clause 2 · open · found by lane I closing [D15925](D15925.md) · filed 2026-11-14 against master `5762698f9`**

Repro:

    function inc0(a) { return a + 1 }
    function dbl(a) { return a * 2 }
    function two() { [1, 2].length }
    function pick(b: boolean) {
      const r = if b { [{ f: inc0 }] } else { [{ f: dbl }] }
      return r
    }
    print(pick(two() > 5)[0].f(3))

Want:

    6

#### Mechanism

Two layers stand in the way.

The first is mono's delivery. A returned read of the binding goes to `monoIfBoundRetAtPin`
(`emit_mono.vl`), which finds no first-arm generic in list arms and leaves the value to the
refusal. Re-entering `monoCoerceRetAtPin` on the binding's initializer, in the binding's frame,
reaches [D15925](D15925.md)'s join-of-lists arm and clears that refusal. Mono discovers nothing
there, since the instances stay the elaboration's.

The second is storage, and it is the open half. With the delivery fixed, `retStorageMismatch`
(`wasmEmit.vl`) refuses with "a returned container of functions is built at another storage than
this function's result". A returned `if` is stored at the local its join builds
(`refListSlotOfUntyped` → `ifExprRefSlot`), which is the row the function's result takes. A
returned binding is stored at its own cell row (`refListCellSlotOfRead`), which is minted
separately. Recording the tails' type on the read instead moves the function's result to `i32`,
and the module fails validation. The close needs the bound join built at the result's row, or the
result made to take the binding's cell row: a rep/intern decision, not a mono one.
