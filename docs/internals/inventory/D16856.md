### D16856 — a `?.` read of a string field on an un-annotated parameter is printed as a number

**closed 2026-11-16 — the witness runs and prints `s` · was: invalid module · clause 1 (check-clean, invalid wasm) · found closing [D16338](D16338.md) · filed 2026-11-16 against master `a8512d420`**

Repro:

    function take(a) { print(a?.f) }
    take({ f: "s" })
    // vl check: rc 0.  vl run: invalid module, "expected i32, found (ref $1); $1 is `string`"

Want:

    s

#### Mechanism

`exprString` (`compiler/emit_classify.vl`) listed `OptMember` among the kinds that are never a
string by their own form. In a hole instance handed a present record, `a?.f` reads at the field's
type, so the print ladder chose the `i32` printer for a string ref. The arm now asks the node's
rep, as an `as` does; a nullable read keeps its own rep and stays false.

#### Ablation

| spelling | outcome |
| --- | --- |
| the witness | runs, `s` |
| `a.f` for `a?.f` | runs |
| `a?.f ?? "none"` | runs |
| the field `true`, `1.5`, `7`, `3 as i64` | runs (unchanged) |
