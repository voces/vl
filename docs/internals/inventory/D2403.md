### D2403 — a path narrowing read before a writing call inside a loop reads the stale member on the next iteration

**closed 2026-09-25 — now a loud check reject (`'v.value' was narrowed by a guard outside
this loop, and the call to 'mutate' can write it, so the read on line 8 would see the old
narrowing on the next iteration`) · was loads then traps, clause 1 · filed against master
`2304ece42`, closed against master `a277bf7b0` · fixture
`tests/cases/soundness/loop-read-before-path-writing-call-rejected.vl`**

Repro:

    type W = { value: f64 | boolean }
    function mutate(w: W) { w.value = true }
    function f(v: W): f64 {
      let t = 0.0
      if v.value is f64 {
        let i = 0
        while i < 2 {
          t = t + (v.value as f64)
          mutate(v)
          i = i + 1
        }
      }
      t
    }
    print(f({ value: 1.5 }))
    // vl check: rc 0.  vl run: wasm trap: cast failure

#### Mechanism

`mutate(v)` retires the `v.value` narrowing for the statements after it, and the loop body is
checked once, top to bottom, so the read before the call is typed under the narrowing. On the
second iteration that read runs after the call. A WRITE in a loop to a place narrowed outside it
is refused for this reason (`writeBarredErr`), and D2390 ends a bare name's narrowing before a
loop that may call its writer (`crLoopPreRetire`); a call that may write a path gets neither.

#### Ablation

| ingredient removed | outcome | needed? |
| --- | --- | --- |
| the second iteration (`i < 1`) | runs, prints `1.5` | **yes** |
| the read before the call (read moved after it) | runs, prints `2` | **yes** |
| the field (an index cell `xs[0]`, `g(xs)` writing it) | traps the same | no |

#### Grading list

The same with a map value `m["a"]`; with a `for … in` loop; with the path narrowed by the
loop's own condition (which re-tests, and should keep running).

#### Close

Path reads under a narrowing made outside the enclosing loop are logged while the loop is
checked (`crNoteLoopRead`, a `while` condition included); a call in the loop that ends such a
narrowing is refused when the loop read the path before it (`crLoopReadCheck`). An `is` test's
own operand is not a use. This is a refusal where D2390's bare names retire before the loop:
a path's writer is decided per call from the checked types, which a loop body does not have
before it is checked. A re-test inside the loop, the loop's own condition, and a call with no
earlier read all run.
