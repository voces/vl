### D3654 — `as?` to a number over an un-annotated parameter is typed at the bare target before the pin, so every position refuses at emit

**loud emit reject · clause 2 · the `as?` residue of [D3624](D3624.md) · 126 of 126 `as?` cells of D3624's grid, at every hole position · filed 2026-10-04 against master `32b753681`**

Repro:

    const k = (x) => x as? u8
    print(k(300))
    print(k(5))
    // vl run: emit error, `as? i32` over a type parameter needs the instance's exact pin

Want:

    null
    5

#### Mechanism

Over a type parameter the checker types `x as? N` as `N | null` at every pin (D2754), but the
hole case is excluded (`checkCastNode`: `argH.tvName[0] != '?'`), so the cast is typed bare `N`
and only re-typed `N | null` at the pin (`castPinNullResult`), after the body, its bindings and the
inferred return were already typed bare. The emitter's `emitHoleNumAsOpt` reads only the generic
exact pin and refuses. Reading the hole pin there as well (tried on lane WV) makes a cast whose
value only reaches `print` run, and turns one bound to a `const` and returned into check-clean
invalid wasm (`expected i32, found (ref $type)`), so the fix starts on the checker side: type the
hole cast `N | null` up front as the generic one is, then let the emitter read the hole pin. That
changes the type of `x as? i32` over a hole pinned at `i32`, so grade the direct spelling with it.

#### Ablation

| ingredient changed | outcome | needed? |
| --- | --- | --- |
| `function k<T>(x: T) { x as? u8 }` | prints `null`, then the value | **yes** (the hole) |
| `function k(x) { x as? u8 }` | emit reject | no (lambda or declared) |
| `function k(x) { print(x as? u8) }` | emit reject | no (where the value goes) |
