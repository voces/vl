### D4341 — `??` over a nullable function-typed value has no lowering, whatever the right side is

**loud emit reject · 2 witnesses (a lambda and a named-function right side) · filed 2026-10-13 against master `b13a4e324`**

Repro:

    function f(v: ((q: i32) => i32) | null): i32 {
      const g = v ?? ((q: i32) => q + 1)
      return g(2)
    }
    print(f(null))
    print(f((q: i32) => q * 10))
    // vl check: rc 0.  vl run: emit error,
    // emitProgram: `??` over this nullable value is not supported yet — narrow it first, e.g. `if v != null { … }`

#### Mechanism

The checker accepts `??` with a nullable function type on the left, and the emitter refuses it at
the `??` node. The message names a capability (`not supported yet`), so this is a clause-2 gap.

#### Ablation

| ingredient removed | outcome | needed? |
| --- | --- | --- |
| the lambda on the right (a named function `inc` instead) | still refuses, same message | no |
| the `const g =` binding, called inline: `(v ?? ((q: i32) => q + 1))(2)` | refuses with a different message, ``callee is not a function name`` | no (a second refusal) |
| the function type (a nullable `i32`) | not graded here | untested |

#### Grading list

The `if v != null { … } else { … }` spelling the message suggests; the inline-call spelling
above; a nullable function stored in a record field.
