### D4071 — a value-`if` whose arm ends in a statement is check-clean when its binding is unread, then refused at emit

**closed 2026-10-11 — now a loud check reject at the arm (`this arm yields no value, but the `if` is the value of `x`: end the arm with a value, or make the `if` a statement`) · was a loud emit reject · closes D1993 and D1994 as duplicates · found by the October code-quality survey (`docs/internals/code-quality-2026-10.md` L3) · filed 2026-10-11 against the shared `~/vl` seed (compiler source hash `0027a12458222156`) · fixtures `tests/cases/conditionals/error-if-binding-arm-yields-no-value.vl`, `if-binding-no-else-stays-nullable.vl`**

Repro:

    function f(c: boolean) {
      const x = if c { 1 } else { let y = 2 }
    }
    f(true)
    // WAS: vl check rc 0, two unused-variable warnings.  vl run: emit error, `if-expression arm ends in a statement, which yields no value`
    // NOW: this arm yields no value, but the `if` is the value of `x` (at the `let`)

#### Mechanism

The checker types the `if` as `i32 | void` and refuses that type only where the value is used
(`print(x)` gives `print expects a value, got i32 | void`). An unread binding of it passes
check, and the emitter's value-`if` lowering (`wasmEmit.vl`) refuses the arm that yields no
value. The refusal names a rule about the user's program, so it belongs in the checker: a
clause-2 violation by construction.

Closed in the checker: an un-annotated binding whose type mentions `void` without being `void`
is refused at the first arm whose block ends in a statement or a void call, or is empty
(`ifNoValueArmAt`), naming `match` when the value is one. An initializer that is no `if` or
`match` but whose type includes `void` (`const x = p` with `p: i32 | void`, a field read, a call
returning `i32 | void`) is refused at the initializer: `void` is not storable (DECISIONS.md,
"`void` is a real type in the lattice"). A wholly-void binding keeps `cannot bind the void result`. An `if` with
no `else` is unaffected, because its missing arm is an implicit `null`. Family L3 of the October ranking (value-`if` arms, 6 emit
sites).

#### Grading list

The top-level spelling (`const c = true` / `const x = if c { 1 } else { let y = 2 }`), and the
other value-`if` emit sites the close moves into the checker: `match` arms, a `return` of the
`if`, and an argument position. Graded at the close: top level and a `match` arm moved from
the emit reject to the new check reject; a `return` of the `if` into `i32` and an argument into
an `i32` parameter were already check rejects (`got i32 | void`). An argument into an
`i32 | void` parameter still reaches the emit refusal `union if-expression arm ends in a
statement`; that cell is not closed here.

Still open: the ANNOTATED spelling `const x: i32 | void = 1` inside a function passes check and
refuses at emit (`only i32 locals are supported`); that is the written face, D4052.
