### D4071 — a value-`if` whose arm ends in a statement is check-clean when its binding is unread, then refused at emit

**loud emit reject · found by the October code-quality survey (`docs/internals/code-quality-2026-10.md` L3) · filed 2026-10-11 against the shared `~/vl` seed (compiler source hash `0027a12458222156`)**

Repro:

    function f(c: boolean) {
      const x = if c { 1 } else { let y = 2 }
    }
    f(true)
    // vl check: rc 0, two unused-variable warnings.  vl run: emit error, `if-expression arm ends in a statement, which yields no value`

#### Mechanism

The checker types the `if` as `i32 | void` and refuses that type only where the value is used
(`print(x)` gives `print expects a value, got i32 | void`). An unread binding of it passes
check, and the emitter's value-`if` lowering (`wasmEmit.vl`) refuses the arm that yields no
value. The refusal names a rule about the user's program, so it belongs in the checker: a
clause-2 violation by construction. Family L3 of the October ranking (value-`if` arms, 6 emit
sites).

#### Ablation

| ingredient changed | outcome | needed? |
| --- | --- | --- |
| `else { 2 }` (both arms yield a value) | runs | **yes** |
| `x` read by `print(x)` | check reject (`print expects a value, got i32 \| void`) | **yes** (unread) |
| at top level instead of inside a function | same emit refusal | no |

#### Grading list

The top-level spelling (`const c = true` / `const x = if c { 1 } else { let y = 2 }`), and the
other value-`if` emit sites the close moves into the checker: `match` arms, a `return` of the
`if`, and an argument position.
