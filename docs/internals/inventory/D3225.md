### D3225 — a hole callee's scalar argument is never held to the parameter the callee is bound to, so it arrives converted, reinterpreted or invalid

**now a loud check reject · the call of a hole records each argument against the bound function's parameter (`HD_PARAM`), and the pin asks the direct call's question of the argument's origin node, for a pair of different scalar primitives, in the direct call's words · fixtures `tests/cases/generics/hole-callee-scalar-argument-reject.vl`, `tests/cases/generics/hole-callee-scalar-argument-runs.vl` · was check-clean silently wrong (a lossy `i32` into `f32`, a `boolean` into `f64` read as `1`, an `i32` into `boolean` printed `true`) and check-clean invalid wasm (`f64`/`f32` into `i32`/`i64`, `string` into `i32`) · clause 1 · lane BI's scalar delivery grid, 28 of the 40 cells of its `hole` column, each refused by the direct call · found widening D3218 · filed 2026-09-29 against master `94670f728`, fixed 2026-09-29 against master `94670f728`**

Repro:

    function H(h, v) {
      return h(v)
    }
    const s: i32 = 16777217
    print(H((x: f32) => x, s))
    // vl check: argument 1: expected f32, got i32 (the call of `h` at the call's argument types)

#### Mechanism

A call through a hole (`h(v)` with `h` an un-annotated parameter) checked its arguments on
their own and recorded nothing, so the instance never compared `v`'s binding with the
parameter of the function `h` was bound to. The emitter then converted the value (`16777217`
printed `16777216`), passed a `boolean`'s bit as `1`, or built a module that failed to
validate. The call now records each argument against a derived hole for the bound function's
parameter, re-asked at the pin. For two different scalar primitives the pin asks
`assignableExpr` of the argument's origin node (the call-site argument for a parameter hole,
the body's own argument otherwise), so a literal adopts the parameter's width and a
`boolean` value keeps its designed `i32` delivery exactly as the direct call does. A demand the
call leaves open moves out to the caller's hole with its origin node. Records,
lists, unions and type parameters are left to D3171's design.
