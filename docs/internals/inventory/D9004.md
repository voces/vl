### D9004 — a declared generic handed to `.map` leaves the mapped element type open

**closed · runs, prints `3` · was loud emit reject, `emitProgram: index receiver is not an array or string` · `vl check` rc 0 · clause 2 · found closing [D9001](D9001.md) · filed 2026-10-21 against master `f0249c64f` · closed by the checker binding the callback's type parameters from the list's element (`memberCallMapFilterTy`, check_member_call.vl) and the monomorphizer reading a generic instance's receiver at that instance's binding (`monoCoerceListCbArg`, emit_mono.vl) · fixtures `closures/generic-fn-as-list-callback-result.vl`, `closures/error-generic-fn-list-callback-at-wrong-destination.vl`, matrix `fn-value-generic-as-list-callback-result`**

Repro:

    function idg<T>(t: T): T { return t }
    print([3].map(idg)[0])
    // vl run: emitProgram: index receiver is not an array or string

#### Mechanism

Two halves. The checker typed `.map(idg)` as the list of the callback's declared result,
`T[]`: the hole path (D8944) reads an un-annotated function's body at the element, but a
declared generic's result is its type variable and nothing bound it, so the list stayed open
and the emitter could not classify it. The checker now binds the callback's parameter type
against the element (`bindGenWalk`) and substitutes the result, so `[3].map(idg)` is `i32[]`
and `[3].map(wrap)` with `wrap<T>(t: T): T[]` is `i32[][]`. The monomorphizer already took the
callback's instance at the element (`monoCoerceListCbArg`), but read the receiver's recorded
type, which inside a generic instance is `T[]`, so `xs.map(idg)` in `h<T>(xs: T[])` took none;
it now reads the receiver at the instance's binding (`monoExactPinTyOf`).
