### D9004 — a declared generic handed to `.map` leaves the mapped element type open

**loud emit reject · `vl check` rc 0 · clause 2 · CAPABILITY: the annotated destination `const ys: i32[] = [3].map(idg)` runs, and so does a lambda `(t) => t` · found closing [D9001](D9001.md) · present on master `f0249c64f` · filed 2026-10-21 against master `f0249c64f`**

Repro:

    function idg<T>(t: T): T { return t }
    print([3].map(idg)[0])
    // vl run: emitProgram: index receiver is not an array or string

#### Mechanism

Not traced. The `.map` result is read off the callback's result at the element type; an
un-annotated function is read through its body (`holeFnArgDecls`), and a lambda closes the
same way, but a declared generic's result is its type variable, which nothing substitutes at
the element, so the result stays `_[]`.

#### Ablation

| ingredient removed | outcome | needed? |
| --- | --- | --- |
| the annotated destination, added (`const ys: i32[] = ...`) | runs, `3` | **yes** |
| the generic, for a lambda `(t) => t` | runs, `3` | **yes** |
| the name, for `let f = idg` handed instead | same emit refusal | no |
| the `[0]` index (`.length`) | emit refuses, `'.length' on a receiver the emitter cannot classify` | no |
