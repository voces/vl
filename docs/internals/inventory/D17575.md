### D17575 — a generic's type parameter bound to the open variable a phantom alias's instance result carries types the call `_`, and the build is invalid

**closed 2026-11-26 by SOUND · runs, prints `9`, every function claimed (`VL_IR_REQUIRE_CLAIM=1`) · was check-clean invalid wasm, clause 1 (`expected i32, found f64`), and the open `_` was assignable to any type (`const z: string = q` checked clean) · a type variable no enclosing body declares is now no binding, so a later argument's closed type fixes it (`bindGenWalk`'s rebind, which took only an inference hole, D16099); and an un-annotated binding whose initializer still mentions such a variable is refused at check (`cannot infer the type parameter … no argument fixes it`) · found by lane START-2, routed by the coordinator · filed 2026-11-26 against master `903f71519` · pinned by `tests/cases/generics/phantom-param-bound-by-later-argument.vl` and `tests/cases/generics/error-type-parameter-no-argument-fixes.vl`; also closes [D10402](D10402.md)**

Repro:

    type P = { a: i32, b: f64 }
    type Rows<T> = { base: i32, count: i32 }
    function g<T>(_r: Rows<T>, x: T): T { return x }
    function mk<T>(b: i32): Rows<T> { return { base: b, count: 1 } }
    const su = mk<P>(8)
    const q = g(su, { a: 3, b: 4.5 })
    const f = q.b * 2.0
    print(f)
    // vl check: rc 0.  vl run: invalid module, `expected i32, found f64`

Want:

    9

#### Mechanism

`Rows<T>` uses no `T`, so `mk<P>(8)`'s result is the structural `{base: i32, count: i32}`. Its alias
application keeps `mk`'s own `T`, not `P`. Binding `g`'s `T` against it bound that foreign variable.
The later argument `{a: 3, b: 4.5}` could only replace an inference hole (`?…`), so the binding
stood, `q` was typed at the open variable (`_`), and `f` took an `i32` cell for an `f64`.

#### Ablation

| ingredient changed | outcome | needed? |
| --- | --- | --- |
| `su` annotated `Rows<P>` | binds `T=P`, runs | **yes**: the instance result |
| the arguments swapped (`g(x, su)`) | binds from `x`, runs | **yes**: the order |
| `g<T>(x: T)` alone | binds from `x`, runs | **yes**: the phantom parameter |

#### Grading list

- `only<T>(_r: Rows<T>): T[]` called as `only(mk<i32>(8))`: no other argument, so `T` is refused at
  check. The argument does name `i32`, but `mk<i32>(8)`'s result keeps no `i32`. Keeping the alias
  application on an instance's result would let it bind; that is a follow-up, not a soundness gap.
