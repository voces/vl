### D1541 — an INLINE literal union annotated on a MODULE GLOBAL fed by a list element printed the interned ATOM ID; the alias spelling and every other position ran

**closed — now runs · was `check-clean silently wrong` (`vl check` rc 0, `vl run` printed `0` where `green` was expected) and `check-clean invalid wasm` at the `==` / `+` reads · clause 1 · found 2026-09-03 by minimising the day-one sampler's `only i32 locals are supported` cell, which is a DIFFERENT face of the same seam ([D1196](D1196.md), still open)**

Repro:

    const arr: ("red" | "green")[] = ["green"]
    const v: "red" | "green" = arr[0]
    print(v)
    // PRINTS 0
    // want: green

#### Mechanism

A literal-union ARRAY is always the interned-i32 ATOM list (`tyIsLitUnionArray`, which does not
consult the alias seam), while a SCALAR litunion destination's rep follows the SPELLING — an
alias is the atom, an inline member set is the string ref (`tyIsLitUnionAlias`, and
`ctxKeepsLitUnion` softens the inline spelling to `string` at `RC_ROOT`). At MODULE scope the
global cell ladder still slots this binding as the atom, so the STORE writes an i32 id; the READ
side asks `exprIsLitAtom` → `bindingIsLitAtom` → `letInitIsLitAtom`, whose annotated face
declined, so `print` took the plain-i32 arm instead of the atom→string `select` tower.

**Two ends of one decision, disagreeing** — the store said atom, the widen said not-atom. The
disassembly is the whole defect in three lines: the array global is `(array (mut i32))` holding
`(i32.const 0)`, the string constant `"green"` is emitted as `$global$0` and never read, and the
print is `call $__print_i32__ (local.get $0)`. The DIRECT read `print(arr[0])` on the same array
emits the `select` tower and prints `green`, which is what proves the value was recoverable.

`letInitIsLitAtom` now claims the annotated face **for a module GLOBAL only**
(`globalLetOf(d.letName) == letIx`).

#### Ablation

| ingredient removed | outcome | needed? |
| --- | --- | --- |
| the list (`const v: "red" \| "green" = "green"`) | runs `green` | **yes** |
| the annotation on `v` (`const v = arr[0]`) | runs `green` | **yes** |
| the inline spelling — any `type Color = "red" \| "green"` **declared anywhere, even unused** | runs `green` | **yes** |
| an alias over a DIFFERENT set (`"up" \| "down"`) or a SUPERSET (`+ "blue"`) | still wrong | no |
| the string members (`const arr: (7 \| 9)[]`, a NUMERIC litunion) | runs `9` | **yes** |
| module scope (the same program inside a `function`) | `only i32 locals are supported` — [D1196](D1196.md) | **yes** |

The alias row is the sharp one: an alias whose member set is EXACTLY the inline spelling's makes
the inline annotation resolve to the alias's own arena index (`litUnionAliasTyOfMembers`), so
`tyIsLitUnionAlias` becomes true and both ends agree again. That is why the defect needs a
program with no such alias in it — and why every fixture that names its literal union is blind
to it.

#### The reads, and what each did

| read of `v` | before | after |
| --- | --- | --- |
| `print(v)` | prints `0` | `green` |
| `if v == "red" { … }` | check-clean invalid wasm | runs |

| element of an element (`arr: (…)[][]`, `arr[0][0]`) | prints `0` | `green` |
| a `let` re-assigned from the element | prints `0` | `green` |

#### Price

None measured. The four FUNCTION-scope cells (`z0`–`z2`, `z6` of the grid; a module-scope
`for`-in body is one of them, since its binding is a start-fn LOCAL) keep their D1196 refusal
byte for byte — that is what the `globalLetOf` gate buys. The un-gated version of this patch
(claiming the annotated face everywhere) takes those four from loud emit reject to **check-clean
invalid wasm**, which is why the gate is on the global and not on `fnIx < 0`: a module-scope
`for`/`if` body has `fnIx == -1` too.

**AND THE REFUSED PATCH'S RECORDED REASON WAS WRONG, WHICH IS WORTH MORE THAN THE PATCH.**
D1196 says the price is "the `print` widen's str-op frame reservation scan does not see the new
atom slot". Measured on the un-gated candidate: the same function is invalid wasm with **no
widen in it at all** — `print(arr.length)` instead of `print(v)` fails identically, at the same
offset. The bad instruction is the STORE (`local.set` of a softened `(ref $type)` string into
the newly-i32 slot), not the widen's frame. Closing D1196 means making `ctxKeepsLitUnion`
preserve the inline spelling at `RC_ROOT`, or teaching the store to narrow — not teaching the
reservation scan.
