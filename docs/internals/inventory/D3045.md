### D3045 — a loop variable forwarded through a second generic at a `string[]` pin builds invalid wasm

**check-clean invalid wasm · clause 1 · the #3261 review's `Pr10` template at the string pin · identical on master `59cf3b639` · filed 2026-09-28 against master `3a71bb1f9`**

Repro:

    function inner<U>(x: U) { print("[\{x}]") }
    function mid<T>(l: T[]) { for e in l { inner(e) } }
    function outer<T>(l: T[]) { mid(l) }
    const v: string[] = ["p", "q"]
    outer(v)
    // vl check: rc 0.  vl run: invalid module inside `mid$m0`

Want:

    [p]
    [q]

#### Mechanism

Not localised past the ablation. The string twin of [D3044](D3044.md): `mid`'s instance,
reached only through `outer`, has no pin for its loop variable, so `inner` is cloned at `i32`
and handed a string ref.

#### Ablation

| ingredient changed | outcome | needed? |
| --- | --- | --- |
| `mid(v)` called directly, no `outer` | prints `[p]` `[q]` | **yes** (the forwarding) |
| `inner(l[0])`, no loop | prints `[p]` | **yes** (the loop variable) |
| `print(x)` in `inner` | invalid wasm | no |
| `function inner(x)`, a hole | invalid wasm | no |
