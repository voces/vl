### D2452 — an assignment of a string literal to a `string` name, used as a value, is the literal's atom

**check-clean invalid wasm · clause 1 · pre-existing on master `20651a88b` · filed 2026-09-25 against master `20651a88b`, found reviewing #3154**

Repro:

    function main() {
      let a: string = "x"
      const r = (a = "q")
      print(r)
    }
    main()
    // vl check: rc 0.  vl run: invalid module inside `main`: type mismatch: expected i32, found (ref $type)

#### Mechanism

Not ablated. The checker types the assignment at the literal's own type `"q"`, which the emitter
reps as an interned `i32` atom, so `r` takes an `i32` slot; the value is the re-read of the
`string` name, a ref. [D2398](D2398.md)'s move declines a literal type on purpose, since a
literal-union store encodes the atom. A literal value into a non-literal place is the case the
checker's D2394 rule (the value typed at the place's type) would settle.

#### Ablation

| ingredient removed | outcome on `20651a88b` | needed? |
| --- | --- | --- |
| the function (top level) | still invalid wasm | no |
| the value position (`a = "q"; print(a)`) | prints `q` | **yes** |

#### Grading list

`const r = (a = "q")` with `a: string | null`, and `b = (a = "q")` with `b: string`.
