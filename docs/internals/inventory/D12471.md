### D12471 — a lambda handed to one generic binds a same-named type parameter of another, refusing its later call

**closed 2026-10-24 — runs, prints `14` then `abab` · was loud check reject, `` cannot infer a type for parameter `a` ``, clause 2 · a hole lambda's body demands were re-judged against every function's constraints under the callee's own type-parameter bindings, and `T` matches by name, so `gen3`'s rows were re-recorded at `T = i32`; the lambda is now judged under hole bindings only (`holeBindsOnly`, `check_calls.vl`) · lane L3 · pin: `tests/cases/generics/hole-lambda-to-two-generics-one-param-name.vl` · found closing [D10893](D10893.md), whose list spelling reached it · present on master `799a09dea` · filed 2026-10-24 against master `799a09dea`**

Repro:

    function gen3<T>(g, x: T) { print(g(x, x)) }
    function gen4<T>(g, x: T) { print(g(x, x)) }
    gen4((a, b) => a + b, 7)
    gen3((a, b) => a + b, "ab")
    // vl check: cannot infer a type for parameter `a`, at the second lambda

#### Mechanism

`pinHoleLambdaVals` judges a lambda at the instance a callee's body calls it at, through `judgeHoleLambdaAt`, which re-validates every deferred constraint in the program (`CSTR_NODECL`) under the names it is given. Those included the callee's declared type parameters, so `T = i32` from the first call substituted into `gen3`'s rows too, and the moved rows were recorded with no owner, which every later callee counts as its own.

#### Grading list

Ablation: renaming either function's parameter (`<U>`) runs; making the calls from inside two functions runs; the same instance at both calls runs; a named function in place of the first lambda runs. The running neighbours are those spellings.
