### D12301 — an un-annotated lambda that is never called, stored in a list or record, is emitted at `i32` and is check-clean invalid wasm

**now runs, prints `1` · was check-clean invalid wasm (`type mismatch: expected (ref $1), found i32; $1 is `string``) after `vl check` rc 0 · clause 1 · closed 2026-10-24 by lane L3 (d): a lambda with an open parameter that no call goes through, however it is stored, has no instance and is not emitted, as one nothing reads already was; the inline spelling's `cannot infer a type for parameter` refusal is unchanged · moved: the same lambda bound inside a function body, and the record spelling, ran invalid and now run · pins: `tests/cases/closures/uncalled-hole-lambda-stored-runs.vl` · found closing D12237 · filed 2026-10-24 against master `43ea89c8c`**

Repro:

    const c = (y) => y + "C"; const fs = [c]; print(fs.length)

#### Mechanism

No call gives the lambda's parameter a type, and its body (`y + "C"`) needs a `string`. Written
inline in the list literal, the checker refuses the parameter it cannot infer. Bound to a name
first, the checker passes it, and storing the binding in a list or record emits the lambda as a
value at the default `i32`, which its body's string concatenation does not validate against.
The close is the inline spelling's refusal at the named one, or an inference that reads the body.

#### Ablation

| ingredient removed | outcome | needed? |
| --- | --- | --- |
| the list (`const c = …; print(1)`) | runs | **yes** |
| a record in place of the list (`const r = { f: c }`) | invalid wasm inside `c` | no: any container |
| an alias in place of the list (`const g = c`) | runs | **yes**: a container |
| the string body (`y + 1`, or `y`) | runs | **yes** |
| the call-free use (`print(fs[0]("x"))`, or `c("x")` beforehand) | runs, prints `xC` | **yes** |
| the binding (`[(y) => y + "C"]`) | check reject, `cannot infer a type for parameter `y`` | **yes** |
| the hole (`(y: string) => …`) | runs | **yes** |
