### D3721 — a list of a record whose fields have different number types is never flattened

**runs today and must keep running — a cost row: `-O3` keeps one `struct.new` per push · lane S2 of inline-records-design.md (§7) · filed 2026-10-05 against master `0948a28e3`**

Repro:

    type M = { n: i32, w: f64 }
    let s = 0.0
    for f in 0 until 100 {
      const ms: M[] = []
      for i in 0 until 16 { ms.push({ n: i, w: i as f64 * 0.5 }) }
      for m in ms { s = s + m.w + m.n as f64 }
    }
    print(s)
    // vl build -O3 with VL_INLINE_EXPLAIN=1: no array type is a candidate.

Want:

    18000

#### Mechanism

A wasm array has one element type, so the step flattens `T[]` only when every field of `T`
is the same number type (`V3`, `Q`, `{a: i32, b: i32}`). `{n: i32, w: f64}` would need one
array per field (a struct of arrays, which also removes D3720's per-field bounds checks for
a single-field read) or a bit-cast into `i64` slots. Neither is built.

#### Grading list

The witness at `-O3` must reach 0 `struct.new`; a list read only field by field must not get
slower than D3720's measurement.
