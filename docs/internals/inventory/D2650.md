### D2650 — a nullable map read back through a narrowed list-element place is not a map receiver for any map operation

**loud emit reject · clause 2 · the `array_element_place` cells of the D2519 lane's `| null` templates (30 cells, every key rep, Sets included) · identical on master · filed 2026-09-26 against master `19dfb80af`**

Repro:

    const m: {[string]: i32} = Map()
    m.set("a", 1)
    const xs: ({[string]: i32} | null)[] = [m]
    if xs[0] is {[string]: i32} {
      let c = 0
      for k in xs[0] { c = c + 1 }
      print(c)
    }
    // vl check: rc 0.  vl run: emitProgram: unsupported for-in iterable

#### Mechanism

A `| null` map is not boxed: it reps as a nullable map ref (the niche). Under a guard on the
element place `xs[0]`, every map consumer classifies its receiver from the place's DECLARED
element type, which is the nullable map, and none has an arm for it: `for` refuses
`unsupported for-in iterable`, `.length` `'.length' on a receiver the emitter cannot classify`,
`.has`/`.set`/`.delete` `callee is not a function name`, `.get` `index receiver is not an array
or string`. The boxed twin (`({[string]: i32} | i32)[]`) runs every one of them, because its
place recovery goes through `emitPlaceNarrowContainerUnbox`, which has no nullable-map rung.

#### Ablation

| ingredient removed | outcome | needed? |
| --- | --- | --- |
| the `null` partner (`\| i32`, a box) | runs, prints `1` | **yes** |
| the `is` guard (`xs[0] != null`) | the same refusal | no |
| the `for` loop (`print(xs[0].length)`, or `.has`, `.set`, `.get`, `.delete`) | each refuses in its own consumer's words | no — the same place recovery |
| the string key (`{[i32]: i32}`) | the same refusal | no |
