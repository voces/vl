### D1740 — an INLINE literal union through a hole parameter, in a list literal, reserves no string list — and the four routes that only reserve it trade the floor for invalid wasm

**closed 2026-09-06 — the rep is what the elements LOWER as, and both the reservation and the read had asked a type · filed against `#2749`'s tree, closed against `#2768`'s · the one cell [D1725](D1725.md)'s close leaves, and four refused candidates for it are measured here · 0 corpus cells**

Repro:

    const src: ("red" | "green")[] = ["green", "red"]
    function take(a) {
      const xs = [a]
      print(xs[0])
    }
    take(src[0])
    // vl check: rc 0.  vl run: rc 0, prints green

Was: `emitProgram: string array literal but string list type not collected`. Annotating the
parameter `a: "red" | "green"` printed `green` all along, as did adding any other `string[]`
to the module — the reservation is module-wide.

#### Mechanism

Probed. [D1545](D1545.md) pins an INLINE member set at
a hole parameter to the softened `string`, so `[a]` classifies as a string list at emit — while
the CHECKER's recorded element is still the literal union, which is neither a `TyPrim` nor a
hole. [D1725](D1725.md)'s pin-resolving element reader is `TyPrim`-gated and so answers "" for
it, and no string list is reserved.

**Four routes to the reservation alone were measured and REFUSED**; the table is on
[D1760](D1760.md), which is this row's mechanism at a second source spelling. Every one of them
moved this cell from the loud floor to **check-clean invalid wasm**, because the reservation is
only half the disagreement.

#### Close

Both halves ask the same question in a FRAME, where before each asked a type with none.

* The collector reserved list types from a whole-arena scan, which has no enclosing function
  and so passed `-1`: a parameter pinned at the softened `string` named nothing to it and the
  i32 pair covered a string backing. `collectArrNewFrames` already existed for exactly this
  shape at the array intrinsics ([D1669](D1669.md)), so the list-literal question joins that
  per-body walk and asks `arrLitIsStr` with the frame. Monotone — a spare reservation is inert.
* `exprIsLitAtom`'s `Index` arm claimed the atom off the READ's own recorded type, and a literal
  union's type does not carry its rep. It now declines first when the receiver is a local bound
  to an un-annotated list literal whose elements lower as string refs, resolved through
  `localDeclIx`. An annotated binding is not that question; its annotation fixed the rep.
* `arrElemLitUnionTyAt`'s element-pin rung, which [D1725](D1725.md) added, is gated the same
  way: a list literal answers atom only when its first element lowers as one.
