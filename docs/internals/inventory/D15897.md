### D15897 — an un-annotated `const` lambda whose only use is a function slot with a nullable result is check-clean invalid wasm

**closed 2026-11-12 · runs, prints `10` · a call through a binding holding one lambda is keyed by the closure the lambda was built at, not by the slot type the adapter's read carries (`calleeCloSigKeyOfRead`, emit_classify.vl) · fixture `closures/const-hole-lambda-only-at-wider-result-slot.vl`, matrix `const-hole-lambda-at-nullable-result.matrix.vl` 21 → 48 of 48 (27 SILENT cells on master run) · was check-clean invalid wasm, clause 1, `type mismatch: expected i32, found (ref $4)` inside `v`, `vl check` rc 0 on master `d303c9bcd` · found grading D15896's matrix ([D15896](D15896.md)) · filed 2026-11-12 against master `d303c9bcd`**

Repro:

    const dbl = (a) => a * 2
    const v: (a: i32) => i32 | null = dbl
    print(v(5) ?? 0)

Want:

    10

#### Mechanism

The delivery's adapter `($fp0: i32): i32 | null => dbl($fp0)` reads `dbl` at the slot's type,
and the emitter keyed the call by that read's recorded type (the D8880 rung) before the rung that
asks what the binding's lambda was lowered at. The closure is built at `(i32) => i32`, so the
`call_indirect` named a functype the callee does not have. With a direct call `dbl(1)` beside it
the read was typed at the lambda's own signature and the program ran. The `f64` spelling, refused
at emit once the result widening is admitted, is the same key ([D15898](D15898.md)).

#### Ablation

| spelling | outcome on master |

| `print(dbl(1))` before the delivery | runs, `2`, `10` |
| `let dbl` | invalid wasm |
| a parameter `w(f: (a: i32) => i32 | null)` | invalid wasm |
| `i32 | string` for the result | invalid wasm |

#### Grading list

The binding, `let`, parameter and `i32 | string` spellings, all in the fixture.
