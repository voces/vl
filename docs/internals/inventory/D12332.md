### D12332 — an exported generic written through a container another binding shares, which no call reads, still passes the checker and refuses at emit

**now a loud check reject · was a loud emit reject (`emitProgram: exported function `id` is generic over `T` and nothing in the program calls it`) after `vl check` rc 0 · clause 2 · DESIGN: the same write into an unshared literal is refused at check ([D12302](D12302.md)) · closed 2026-10-24 by lane L3 (d): value reach follows a written place to every binding whose literal it may land in — an alias, a field or element holding another binding, and a `let` re-pointed at another binding — and judges the write by the reads of all of them · pins: `tests/cases/functions/error-exported-generic-written-through-shared-field-uncalled.vl`, `error-exported-generic-written-through-alias-uncalled.vl`, `error-exported-generic-written-through-shared-element-uncalled.vl`, `exported-generic-written-through-shared-container-called.vl`; the re-pointed `let` refuses and its `print(o.f(3))` twin runs · found on the way and closed in the same change: a record returned by a function and then written ([D12370](D12370.md)) · found closing D12302 · filed 2026-10-24 against master `84941745b`**

Repro:

    export function id<T>(x: T): T { x }
    const inner = { f: id }
    const r = { a: inner }
    r.a.f = id
    print(1)

#### Mechanism

Value reach follows a write to a place only when every container on the way is a fresh literal
held by the written binding alone. Here `r.a` is `inner`, so the write lands in `inner`'s storage
and the reads of `inner.f` would decide it. Value reach does not follow an alias, keeps the write
as one that may reach a call, and the monomorphizer's floor refuses the export. A `let` re-pointed
at another binding's literal (`let r = { f: id2 }; r = o; r.f = id`) is the same shape: before
D12302's close the checker refused it by following `r.f` as `r`'s own literal, which also refused
the program where `o.f` is called.

#### Ablation

| ingredient removed | outcome | needed? |
| --- | --- | --- |
| the alias (`const r = { a: { f: id } }`) | check reject, D12302 | **yes** |
| a call reading the shared container (`print(inner.f(3))`) | runs, prints `3` | **yes** |
| `export` | loud emit reject, `a generic function taken as a value reaches no call that fixes its type` | no |

#### Grading list

The re-pointed `let` spelling in the mechanism, and the same with `print(o.f(3))`, which must
keep running.
