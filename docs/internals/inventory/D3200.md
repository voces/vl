### D3200 — a bound list of record literals delivered by `m.set` into a map of a wider declared record list is stored at its own row

**closed · runs, prints `3.5` · was check-clean invalid wasm · `ls` adopts `R[]` at the `m.set` · fixture `tests/cases/maps/record-literal-list-set-into-wider-record-list-map.vl` · closed 2026-09-30**

Repro:

    type R = { v: f64, w: i32 }
    const ls = [{ v: 1, w: 3 }]
    const m: {[string]: R[]} = Map()
    m.set("a", ls)
    const q = m.get("a")
    if q != null { print(q[0].v / 2.0 + q[0].w) }
    // vl check: rc 0.  vl run: invalid module, expected (ref null $type), found (ref $type) at the m.set

Want:

    3.5

#### Mechanism

Not localised. The index-store spelling `m["a"] = ls` runs, and D3195 taught the use walk's
`rsCallParamTy` to read `.set`'s value argument at the map's value type, so the list walk
should see `R[]` at the `.set` as it sees it at the store. It does not, so `ls` is still
built as a list of its own `{ v: i32, w: i32 }` row. The list walk's `.set` arm is the first
place to look.

The review's other map-delivery failures are named here, not ablated. None of them is this
mechanism:

- `m.set("a", [l])` and `m["a"] = [l]`, a list literal of a bound record literal (`t/p5.vl`,
  `p5i.vl`): invalid wasm in both spellings.
- `m.set("a", mk())` and `m["a"] = mk()` of a call result (`t/p8.vl`, `p8i.vl`): invalid wasm
  in both spellings. That is [D2996](D2996.md), a record that is not a fresh literal, which
  waits on a ruling.
- `m["a"] = l` into `{[string]: R | S}` where `R = { s: string | null, n: i32 }`, then a read
  of `l.s` (`t/pre1.vl`): invalid wasm at the read. The `.set` spelling of an `R | S` store
  with a widened field (`t/p3.vl`) runs.

#### Ablation

| ingredient changed | outcome | needed? |
| --- | --- | --- |
| `m["a"] = ls` | prints `3.5` | **yes** (the `.set` delivery) |
| `R`'s `v: i32` (no widening) | prints `3.5` | **yes** |

#### Grading list

The witness, `rv3288-k7q2/t/p5.vl`, `p5i.vl`, `p8.vl`, `p8i.vl` and `pre1.vl`.

#### Record covariance (2026-09-30)

The destination stores a numeric field at another width or kind, so under the record-covariance ruling the literal-holding binding or function is not adopted and the program keeps its master behaviour until the owner rules on [D3339](D3339.md) (DECISIONS.md "Record covariance: only a fresh value widens").

#### Close under the D3339 ruling (2026-09-30)

Closed by the owner's ruling D3339 (A): a literal-holding binding adopts a record that stores a number at another width or kind, fully (DECISIONS.md "Record covariance: only a fresh value widens"). `ls` holds only a literal and `m.set` delivers it as `R[]`, so it adopts `R[]` and `ls[0].v / 2` reads `0.5`.
