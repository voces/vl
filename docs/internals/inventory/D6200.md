### D6200 — a generic handed to two parameters of one type parameter called at two types is refused when that type parameter is also read elsewhere

**loud emit reject · `vl check` rc 0 · clause 2 · found closing [D6090](D6090.md) · master `c6cd62ec1` emitted a module that failed to validate · filed 2026-10-17 against master `c6cd62ec1`**

Repro:

    function same<T>(k: T): T { k }
    function take(a) {
      print(a("x"))
    }
    function take2(a) {
      print(a(3))
    }

      take(a)
      take2(a1)
      a
    }
    mid(same, same)
    // vl check: rc 0.  vl run: emitProgram: monomorphize: a generic function handed to two parameters of type `F` in a call to `mid` is called at two types, and `F` takes one

Want:

    x
    3

#### Mechanism

From the ablation and D6090's close. The close gives each parameter of type `F` the instance
its own calls need when `F` is read only as those parameters' type. When `F` is also the
return type or a body annotation, one `F` would have to name two instances, so the bind site
refuses rather than emit `take2` at the string instance as master does.

Lane L1, 2026-10-17, closing D6240: that close drops `F` from the parameters' annotations
only when `F` appears nowhere else in the function, and declines here on purpose. With the
return type `F` left standing, `F` would lose the bindings that fix it. A close needs `F`
split into one type parameter per parameter position, with every other read of `F` resolved
to one of them. The spelling alone cannot say which one the return `a` is, so that answer has
to come from the checker.
