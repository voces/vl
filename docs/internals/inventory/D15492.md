### D15492 — a generic written into an un-annotated map through a helper, beside a map holding another generic, reaches no instance

**closed 2026-11-06 by lane Fn#d (G2) · runs, prints `2`, `s`, `k2` and `3` · was loud emit reject, `indexed-assignment target is not an array`, `vl check` rc 0 · clause 2 · closed by tagging the written generic's set when the helper's store lands in a parameter every call hands a map or list holding that set, or a wider one decided with it (`ftParamHolderHolds`, `ftNamedFnValue`, check_fn_tag.vl) · fixture `closures/generic-written-into-map-through-param-called-at-two-types.vl` · refactor-notes/2026-11-06-emit-mono-queue-shadows.md bucket 1, group G2 · filed 2026-11-06 against master `7d3e4244`**

Repro:

    function id<T>(x: T): T { x }
    function k2<T>(x: T): T {
      print("k2")
      x
    }
    function fill(mm) { mm["k"] = id }
    const a = Map()
    const b = Map()
    b["z"] = k2
    fill(a)
    fill(b)
    const ra = a["k"]
    if ra != null {
      print(ra(2))
      print(ra("s"))
    }
    const rb = b["z"]
    if rb != null { print(rb(3)) }
    // vl check rc 0.  vl run: emit error: indexed-assignment target is not an array

Want:

    2
    s
    k2
    3

#### Mechanism

The callee's write lands in each caller's map with its function set, but the tag rule refused the
store `mm["k"] = id` itself: it writes into a hole parameter's slot, and only a holder known to
hold the set may take an id. Every call of `fill` hands a map holding `{id}` or the wider
`{id, k2}`, so the slot is an id of that set, decided with `{id}`. Without the tag, mono's flow
rewrite and the map pin had to name one generic per map and refused once a map held two.
