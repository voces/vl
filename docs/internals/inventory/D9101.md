### D9101 — an un-annotated `let` holding a `Map()` of un-annotated functions, or a record of one, has no map value type

**loud emit reject · `vl check` rc 0 · `unsupported map value type` · clause 2 · found closing [D9062](D9062.md) · filed 2026-10-21 against master `7736fb65b`**

Repro:

    function inc0(a) { return a + 1 }
    let m = Map()
    m["k"] = inc0
    const x = m["k"]
    if x != null { print(x(3)) }
    // vl check rc 0.  vl run: emit error: emitProgram: unsupported map value type (no rep for a union-member struct, ...)

#### Mechanism

Not traced. The pins that type a container from its calls (`monoPinMapValues`,
`monoPinFieldContainers`, emit_mono.vl) read the binding's writes and calls and act only on
a `const` declaration, where the init is the only value the binding can hold. A `let` can be
reassigned, so nothing pins it and the value keeps the function's hole signature.

#### Ablation

| ingredient removed | outcome | needed? |
| --- | --- | --- |
| `let` (`const m = Map()`) | runs, `4` | **yes** |
| the map (`let r = { m: Map() }`, `r.m["k"] = inc0`, read through `r.m`) | same refusal | no |
