### D15452 — an un-written `let` list literal holding a function parameter called at two types is refused; the `const` spelling runs

**closed 2026-11-05, runs and prints `3 x`, with the split plan on and off · was loud emit reject, `vl check` rc 0, `emitProgram: monomorphize: parameter `g` of `go` is called at two function types that no parameter per type separates`, clause 2, with the split plan on and off (never a split-plan dependent) · found writing the cell-read witnesses after #6383 · filed 2026-11-05 against master `755ba974` · closed by letting the holder rules take a `let` nothing re-points, by the same `cwLetUnwritten` test D15404's copy rule reads (`elabListParamSource`, `elabRecParamSource`, emit_elab.vl) · fixtures `closures/unwritten-let-{list,record}-of-generic-param-called-at-two-types.vl`, `closures/unwritten-let-list-of-hole-param-called-at-two-types.vl`**

Repro:

    function same<T>(k: T): T { k }
    function go<F>(g: F) {
      let r = [g]
      print(r[0](3))
      print(r[0]("x"))
    }
    go(same)

Want:

    3
    x

#### Mechanism

The holder rules that let a list literal of a parameter read the parameter's set per call
(`elabListParamSource`, emit_elab.vl) take only a `const` binding (`ln.letKw != "const"`), so an
un-written `let` holding the same literal is read as one closure at one signature. D15404 extended
the rules to an un-written `let` COPY of a parameter (`cwLetUnwritten`), not to an un-written `let`
HOLDER. Taking the holder through the same test was the whole fix: the list, record and
un-annotated spellings all run with it, and nothing else was in the way.

#### Ablation

| ingredient removed | outcome | needed? |
| --- | --- | --- |
| `let r` → `const r` | runs, `3 x` | **yes** |
| the call at a second type | runs | **yes** |
| index `0` → a `const k = 0`, or `[g, g]` read at `1` | still refuses, same message | no (not the cell spelling) |
| list → record `{ f: g }` read as `r.f` | still refuses, same message | no |
| `<F>(g: F)` → an un-annotated `go(g)` | still refuses, `a function-value call has no interned signature`; its `const` spelling runs | no |
| the binding moved to module scope (`let r = [same]`) | runs | **yes** |
| the list → a `let h = g` alias called at both types | runs | **yes** |

#### Grading list

The un-annotated `go(g)` spelling and the record `{ f: g }` spelling above (both fixtures). A `let`
holder that IS re-pointed (`r = [g]` after its declaration) is not this rule's: it still refuses
loudly, with the same message.
