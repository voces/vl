### D9005 — an `if` expression choosing between two functions, handed to a generic higher-order parameter, is not instanced at the callee's pin

**loud emit reject · `vl check` rc 0 · clause 2 · CAPABILITY: the same choice between annotated `inc0(a: i32)` / `dbl(a: i32)` runs, and so does a re-pointed `let` of the generics ([D9001](D9001.md)) · found closing [D9001](D9001.md) · present on master `f0249c64f` · filed 2026-10-21 against master `f0249c64f`**

Repro:

    function idg<T>(t: T): T { return t }
    function kg<T>(t: T): T { return t + t }
    function app<T>(g: (x: T) => T, v: T): T { return g(v) }
    const c = [1].length > 0
    print(app(if c { idg } else { kg }, 3))
    // vl run: emitProgram: monomorphize: unsupported argument type for `g` in a call to `app`

#### Mechanism

Not traced. The monomorphizer binds a generic's arrow parameter from an argument naming a
declaration or a written `let` of declarations (`monoOpenFnArgDecl`, `monoWrittenGenLetFrame`,
emit_mono.vl); an `if` expression is neither, so no instance is taken at `i32`.
