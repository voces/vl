### D5714 — `match` over a union mixing literal kinds, or a literal beside a non-literal member, is refused

**closed 2026-10-17 by lane L3 · runs, prints `one` · was loud check reject · clause 2 · a union mixing literal kinds, or literals beside type members, is one arm vocabulary: a literal arm is an `==` test covering its member, a type arm an `is` test, and each test reads a fresh scrutinee typed under the earlier arms' else facts (`matchBankValTests`, `check_match.vl`); `pushLitEqFactAt` narrows a literal no other member of a non-nullable union admits · pins: `tests/cases/match/litunion-mixed-type-member-dispatch.vl`, `tests/cases/match/litunion-mixed-type-member-errors.vl`, `scripts/capability-probes/matrix/mixed-litunion-type-member-match.matrix.vl` · residue: [D5890](D5890.md) · filed 2026-10-17 against master `bb4448de7`**

Repro:

    function f(k: "a" | 1): string {
      match k { "a" => "a", 1 => "one" }
    }
    print(f(1))
    // vl check: match over a union mixing literal members with members of another kind is not supported — compare them with `==` in an if-chain, got "a" | 1

Want:

    one

#### Mechanism

`checkMatchExprByScrut` (`check_match.vl`) has one arm vocabulary per scrutinee: an integer,
a literal set of ONE kind (D5594, D5710), or a union of types. A union whose members are
literals of two kinds, or a literal beside a type such as `"a" | i32`, fits none of them, so
`checkMatchUnionScrut` refuses it. Each member has a test that lowers (`k == "a"`, `k == 1`,
`k is i32`); what is missing is one arm checker that covers members by both values and types.
