### D15924 — returns whose list literals hold different sets of un-annotated functions returning different types, of different lengths, are built at different rows

**closed 2026-11-12, runs and prints `5.5` · was a loud emit reject, `emitProgram: the lists this function returns are built at different rows, so its inferred list result has none`, clause 2 · closed by `ftRecListOfWider` (`check_fn_tag.vl`), the record twin of D15234's map rule · found closing [D15805](D15805.md), whose returned-list twin shares it · filed 2026-11-12 against master `22d35fe47`**

Repro:

    function inc0(a) { return a + 1 }
    function half(a) { return a / 2.0 }
    function two() { [1, 2].length }
    function pick(b: boolean) { if b { return [{ f: inc0 }, { f: half }] } return [{ f: half }] }
    const l = pick(two() > 1)
    print(l[0].f(3) + l[1].f(3))

Want:

    5.5

#### Mechanism

Traced. The function's inferred result is a list of records whose field holds the wider set
`{inc0, half}`. The tag plan for the smaller set `{half}` met its record `{ f: half }` as an
element of the second return's list, which is typed at that wider result. The holder test for a
list literal (`ftHoldCtxOk`'s `ArrayLit` arm) accepted a map of a smaller set in a list of maps of
a wider one (`ftMapListOfWider`, D15234), but had no record twin. So `{half}` stayed undecided,
neither list was built at the tagged rep, and `retListLitSetsSplit` found the first list's
elements of two sets.

`ftRecListOfWider` (`check_fn_tag.vl`) is that twin: a record whose field carries `s`, in a list
of records of a wider set `s` is within, holds `s`'s records, and an undecided wider set is
decided with `s`. Both rules share `ftHolderListOfWider`.
