### D17222 — a statement assigning `null` to a captured, never-filled `let x = null` in a function writes an `i32` where the cell holds `nullref`

**fixed 2026-11-24 · closed, runs `null` · was: check-clean invalid wasm · clause 1 · `type mismatch: expected i32, found nullref` inside `f` · claimed and claimless alike · found by IR-N5 ablating D17221 · filed 2026-11-24 against master `1384572c` by IR-N5 · fixed by #9977 (IR-N9): `cboxWalkIdent` (emit_rewrite.vl) types a cell read of a never-filled hole at `null`, the type its `null[]` cell holds · fixture `closures/write-null-to-a-captured-never-filled-null-let.vl`**

Repro:

    function f() {
      let x = null
      const g = () => x
      x = null
      print(g())
    }
    f()
    // vl check: rc 0.  vl run: invalid module.

Want:

    null

#### Mechanism

A captured `let x = null` in a function body is held in its environment cell as `nullref`, and the
statement write of `null` into it is written as an `i32`. The capture's cell kind and the write's
store disagree.
