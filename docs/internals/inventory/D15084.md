### D15084 — a local list typed by a single numeric literal (`1[]`) is refused at emit

**closed 2026-11-03 · runs, prints `1` · a list of a numeric literal type rides its base scalar's list (`repOfArray`), its nullable twin too (`repOfNullableArray`), and a map value of one asks its rep before its spelling · was loud emit reject · clause 2 · pre-existing · filed 2026-11-03 against master `9c5f61d6e`**

Repro:

    function f() {
      const a: 1[] = [1]
      print(a[0])
    }
    f()
    // vl check: rc 0.  vl run: emit error, `only i32 locals are supported`

Want:

    1

#### Mechanism

A function-local binding whose type is a list of the bare numeric literal `1` gets no local
type: `(1 | 2)[]`, `i32[]` and the string-literal twin `"a"[]` all run. At module top level the
same list builds, and the concatenation of two of them refuses instead (`the two operands of this
list + do not resolve to one list rep`). Found because `type J = 1` made transparent (D15082)
routes `tests/cases/literal-unions/litunion-list-concat-backing.vl` through this spelling.

#### Ablation

| spelling | outcome |
| --- | --- |
| `const a: 1[]` local, read (the witness) | emit reject |
| two `1[]` locals concatenated | emit reject (the same message) |
| two `1[]` module bindings concatenated | emit reject, `do not resolve to one list rep` |
| `(1 \| 2)[]` locals concatenated | runs |
| `i32[]` locals concatenated | runs |
| `"a"[]` locals concatenated | runs |
