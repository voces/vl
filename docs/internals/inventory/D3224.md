### D3224 — an uninitialized record `let` in a module-scope if-expression arm leaves the binding it initializes unclassified

**loud emit reject · filed 2026-09-29 against master `94670f728`**

Repro:

    function seven(): i32 { 7 }
    const v = if true {
      let t: { r: i32 }
      t = { r: seven() * 3 }
      t
    } else {
      __trap__()
    }
    print(v.r)
    // vl check: rc 0.  vl run: emitProgram: field access receiver is not a struct

Want:

    21

#### Mechanism

The un-annotated module global `v` takes its cell kind from its initializer, an if-expression
whose value is the arm-local `t`. Asked at module scope, the classifier finds no frame to look
`t` up in (`frameLetOf` answers -1 for the start function), so only a rung that reads `t`'s
own initializer can say it is a record, and an uninitialized `t` has none. `v` becomes an `i32`
cell and the field read is refused. The same program inside a function runs. Loop and
labelled-block values (pending, the follow-up to #3293) lower through such a binding, so a
record loop value at module scope meets this too.

#### Ablation

| ingredient removed | outcome | needed? |
| --- | --- | --- |
| module scope (the same body inside a function) | runs | **yes** |
| the missing initializer (`let t: { r: i32 } = { r: 1 }`) | runs | **yes** |
| no annotation on `v` (add `const v: { r: i32 } = …`) | runs | **yes** |
| the record type (`let t: i32`) | runs | **yes** |
