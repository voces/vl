### D12212 — a lambda with an un-annotated parameter written into a list of a generic function inside a generic body traps at the second instance

**trap after load · `vl check` rc 0 · `wasm trap: indirect call type mismatch` in `w$1` · clause 1 · the annotated lambda is a check reject and the non-generic body runs · found surveying emit refusals for L3 family (d) · filed 2026-10-24 against master `b8e223f93`**

Repro:

    function id<T>(x: T): T { x }
    const fs = [id]
    function w<T>(t: T) {
      fs[0] = (x) => x + x
      print(fs[0](2))
      print(t)
    }
    w(1)
    w("s")
    // PRINTS 4
    // PRINTS 1
    // then traps in w$1

#### Mechanism

Each instance of `w` lowers the written lambda again, and the instance at `T = string` gives
the hole parameter the type the slot's element takes at that instance rather than the `i32`
the call `fs[0](2)` passes; the indirect call then names a signature the stored closure does
not have. The checker judges the write once, in the generic body, where the slot is open. With
the parameter annotated `(x: i32)` the checker refuses the write at `w("s")`
(`cannot assign (i32) => i32 to (string) => string`), so the two faces disagree.

#### Ablation

| ingredient removed | outcome | needed? |
| --- | --- | --- |
| the second instance `w("s")` | runs, `4 1` | **yes** |
| the type parameter on `w` (`t: i32`) | runs | **yes** |
| the generic body (the write at top level) | runs, `4` | **yes** |
| the lambda's missing annotation (`(x: i32)`) | check reject | **yes** |

#### Grading list

The record-field spelling `const r = { f: id }; r.f = (x) => x + x` in `w<T>` (traps in
`__start__`), and the lambda that captures `t` (`fs[0] = (x) => { print(t); x }`, also traps).
