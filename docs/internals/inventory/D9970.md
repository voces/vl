#### Mechanism

A lambda delivered at a wider function type is wrapped by the function-value adapter, whose
inner lambda carries a result annotation built from the type's display name (`fvaAnnot`,
check_annot_resolve.vl). The display name spaces its arrows, `(() => string)[] | i32`, and
after checking `canonEmitTypeNames` (check_program.vl) re-parses every annotation that has no
spelling tree from its text. That re-parse of the spaced form came back as
`() => string[]|i32`, which drops the parens that group the function-element list, so the
lambda's result was a function returning a union and the list literal matched no list arm.
The tight form `(()=>string)[]|i32` survives the rename, and the adapter now spells its
annotation tight, as it already did for pipes and map colons. The arena's own render was
right throughout, so the arm-matching in the union delivery was never at fault. Spellings
annotated by hand never pass through the adapter, which is why they ran.
