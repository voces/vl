### D1596 — the monomorphizer's pin could not see a binding declared in a module-scope BLOCK

**closed · filed 2026-09-04 against master `83db028a` + D1593 (#2521) · consumer report VL-042 (glean, `/home/verit/glean/docs/vl-issues.md`), the earlier spelling D1593 filed as its second residue**

Repro:

    type Box = { base: i32 }

    function ld(self: Box) { self.base }

    function adler32(buf) { buf.ld() }

    if true {
      const out: Box = { base: 1 }
      print(adler32(out))
    }
    // before: vl check rc 0; vl run -> invalid module,
    //   "failed to validate inside `adler32`: type mismatch: expected (ref $type), found i32"
    // after:  1

#### Mechanism

`monoArgTyName` pins an un-annotated parameter from its argument's BINDING, because
mid-monomorphization the rep classifiers are blind (`buildLocals` is post-mono). Its
module-scope rung, `monoGlobalLetOf`, was a flat scan of the top-level statement list — and
module scope has TWO storage classes. A `const` written inside a top-level `if`/`while`/`for`/
bare block is a START-FUNCTION LOCAL, not a wasm global, so it appears in no top-level
`LetDecl` and every channel in the cascade declined. The `"i32"` catch-all then answered, the
instance declared `(type (func (param i32) (result i32)))` over a body whose `return_call`
hands the parameter to `ld`'s `(ref $1)`, and `vl check` had already returned 0.

Disassembly of the witness, before and after:

    (func $1 (type $3) (param $0 i32) (result i32)          ;; before
    (func $1 (type $3) (param $0 (ref $1)) (result i32)     ;; after

Both faces of the parameter were needed to see it. ANNOTATED (`function adler32(buf: Box)`) the
same program runs at every position, because the annotation pins the rep instead of the
argument doing it — the fixture that annotates cannot show this defect.

The fix is the module-frame table `moduleLocalLetOf`, already built for `parentBindingOf`'s
module arm (D1244), consulted after the flat scan misses. It is read through a new
`moduleLocalLetOfUnique`: that table is FIRST-WINS over a walk with no notion of which block a
call site sits in, so answering unconditionally hands one block's `Box` to a sibling block's
i32 call — a measured `runs -> not-runs` (`print(p.base)` in one block, `twice(p)` on an i32 in
the next). Declining on a duplicated name restores exactly the pre-fix answer there; the
lexical resolution that would close it too is the residue below.
