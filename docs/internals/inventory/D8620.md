### D8620 — a record literal handed to an un-annotated parameter is built at a declared record that stores its field differently

**check-clean invalid wasm · clause 1 · open · present on master `02d8f4c21` · the twin matrix `unlanded-call-beside-call-into-wider-record` carries it at `argument` and `early_return_guard`, un-annotated · found closing [D8302](D8302.md) · filed 2026-10-20 against master `02d8f4c21`**

Repro:

    type J = { f: i32 | null }
    function rd(r) { return r.f + 1 }
    print(rd({ f: 4 }))
    // vl check: rc 0.  vl run: the emitted module failed to validate inside `rd`: expected i32, found (ref $type)

Want:

    5

#### Mechanism

The checker types the literal `{f: i32}` and binds `rd`'s hole at it, so `r.f + 1` is `i32`
arithmetic. Emit maps an anonymous record to a declared row by its field names, and `J` is the
only declared record with field `f`, so the literal is built at `J` and `r.f` reads `J`'s boxed
`i32 | null` field where the body adds an `i32`. Declaring `type II = { f: i32 }` gives the
literal its exact row and the program runs. The close is in emit's row choice for an anonymous
record (a row whose field storage differs is not the literal's row), outside the checker.
