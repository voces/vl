### D3370 — `??` directly on a nullable record, list or function loop value finds no rep for its left operand

**loud emit reject · the `*_for_coal` cells of the #3295 review's `tw/` set · filed 2026-09-30 against master `6e6a5301b`**

Repro:

    type P = { x: i32, y: string }
    function h(n: i32) {
      const v = (for x in [1, 2, 3] {
        if x == n { break { x: 100, y: "r0" } }
      }) ?? { x: 102, y: "r2" }
      print(v.x)
    }
    h(0)
    h(2)
    // vl check: rc 0.  vl run: emitProgram: `??` over this nullable value is not supported yet

Want:

    102
    100

#### Mechanism

A loop value lowers to `if true { let $lv: T | null = null; <loop>; $lv } else { __trap__() }`.
The `??` ladder classifies its left operand through the if-expression's first arm, and
`armTailValue` sees the arm's tail `$lv` through to its initializer, the bare `null`, so no
nullable rep (record, list, closure) claims the operand and the ladder falls to its floor. Bound
first (`const o = for …; o ?? d`) the binding's own annotation classifies it, and it runs; the
`if` spelling of the same join runs too. A map loop value takes the D3257 rung and runs.

#### Ablation

| ingredient removed | outcome | needed? |
| --- | --- | --- |
| the loop (`(if n == 2 { … } else { null }) ?? d`) | runs | **yes** |
| directly under `??` (`const o = for …; o ?? d`) | runs | **yes** |
| the record (`break [0, 100]` with `?? [2, 102]`) | same refusal | no |
