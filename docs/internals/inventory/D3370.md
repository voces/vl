### D3370 — `??` directly on a nullable record, list or map loop value found no rep for its left operand

**closed · fixture `tests/cases/loops/loop-value-coalesce.vl` · was a loud emit reject (`` `??` over this nullable value is not supported yet ``) · the `*_for_coal` cells of the #3295 review's `tw/` set · filed 2026-09-30 against master `6e6a5301b`, closed against `4ff12b994`**

Repro:

    type P = { x: i32, y: string }
    function h(n: i32) {
      const v = (for x in [1, 2, 3] {
        if x == n { break { x: 100, y: "r0" } }
      }) ?? { x: 102, y: "r2" }
      print(v.x)
    }
    h(0)
    h(2)
    // was: vl check rc 0, then emitProgram: `??` over this nullable value is not supported yet

Want:

    102
    100

#### Mechanism

A loop value lowers to `if true { let $lv: T | null = null; <loop>; $lv } else { __trap__() }`.
The `??` ladder classifies its left operand through that if-expression's arms, and neither arm
names a rep before the arm lowers: the then arm's tail is its own binding `$lv`, which no scope
binds yet (`armTailValue` reads it through to its `null` initializer), and the else arm is the
`never` trap. So no nullable rep claimed the operand and the ladder fell to its floor. Bound
first (`const o = for …; o ?? d`) the `??` meets `o` after it is bound, and runs. The loop
rewrite now moves a `??` whose left operand is a nullable loop value onto the arm's binding,
`if true { …; $lv ?? d } else { __trap__() }` (`lvCoalesceIntoArm`), so the `??` meets `$lv`
after the arm has bound it, as the bound-first spelling does; the else arm never runs, so the
two are the same program. The function face is [D3373](D3373.md)'s: `??` over a nullable
function value has no lowering in any spelling, loop or not, and still refuses here.

#### Ablation

| ingredient removed | outcome | needed? |
| --- | --- | --- |
| the loop (`(if n == 2 { … } else { null }) ?? d`) | runs | **yes** |
| directly under `??` (`const o = for …; o ?? d`) | runs | **yes** |
| the record (`break [0, 100]` with `?? [0, 102]`, or a map) | same refusal | no |
| a `string` or `i32` loop value | runs | **yes** (a ref rep) |
| `for x in xs`, `for i in 1 to 4`, `while true`, a labelled block | same refusal | no |
