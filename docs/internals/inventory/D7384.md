#### Mechanism

The split gives `apply2` a parameter per instance of `g`, so in the plan's re-check its
signature is `(_, _) => void` and `other`'s is `(_) => void`. `checkEqualityBinNode`'s
mutual-assignability test refused the pair, the re-check failed, and the driver declined the
split, which left the two-instance call to the monomorphizer's floor. Hole binding is not
involved: `assignable` against a type variable binds nothing.
