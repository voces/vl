### D2722 — an i32-keyed map as a type argument of a generic record has no rep

**closed 2026-10-22 · runs, prints `true` `true` · was loud emit reject, clause 2 · closed with [D9920](D9920.md) by deleting the i32-keyed spelling gate, and with [D9991](D9991.md) by keying a Set as its boolean map under the canon rep key, without which the lifted `Box<Set<i32>>` literal is invalid wasm · fixture `maps/i32-keyed-function-type-parameter.vl` · found by #3202's review (a1) · filed 2026-09-26 against master `74bd044d7`**

Repro:

    type Box<T> = { v: T | null }
    function f<T>(b: Box<T>) { print(b.v is Set<i32>) }
    const s: Set<i32> = Set()
    const m: {[i32]: boolean} = Map()
    const bs: Box<Set<i32>> = { v: s }
    const bm: Box<{[i32]: boolean}> = { v: m }
    f(bm)
    f(bs)
    // vl check: rc 0.  vl run: emitProgram: an i32-keyed Map/Set is supported as … — not inside 'Box<{[i32]:boolean}>'

Want:

    true
    true

#### Mechanism

The i32-keyed map rep is wired at a list of positions (binding, parameter, return, `| null`,
union member, array element, map value, struct or variant field) and a generic record's type
argument is not among them, so the emitter refuses at the application `Box<{[i32]:boolean}>`
before any `is` is reached. The same record declared with a concrete field type runs.

#### Ablation

| ingredient removed | outcome | needed? |
| --- | --- | --- |
| the `is` (`print(b.v == null)`) | still refuses | no |
| the generic record (`type Box = { v: {[i32]: boolean} \| null }`) | runs | **yes** |
