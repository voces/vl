### D3365 — an `else if` chain of `K | null` parameters with a string-literal arm refuses at a sink

**loud emit reject · clause 2 · the same at the `<T>` and the direct spelling · the hole spelling built an invalid module on master `6e6a5301b` · found by lane UG (the D3303 generator's `g0150`, `g0256`, `g0429`, and 8 `field` cells of the tp-join grid) · filed 2026-09-30**

Repro:

    type K = "a" | "b" | "c"
    function show<T>(x: T) { print(x) }
    function g(a, b, c: boolean) {
      show(if c { a } else if !c { b } else { "c" })
    }
    const u: K | null = null
    const w: K | null = "b"
    g(u, w, true)
    g(u, w, false)
    // vl check: rc 0.  vl run: emit error, `literal-union string widening with no members`

Want:

    null
    b

#### Mechanism

The join is `string | null` at the pin, and the chain is lowered as the `K | null` niche: the
chain's head is claimed by its first nullable arm (`nulIfArmNullableValueIx`), so the `"c"` arm
and the widening of the atom arms to strings meet an atom join, which has no member texts for
them. Lane UG made a two-arm join typed `string | null` the string niche (`ifIsChainHeadIn`),
which is why the two-arm spellings of this row run; a chain keeps the old answer, because
claiming only the head as the string niche left its inner link an atom, which was invalid wasm.
A value binding (`const r = …; print(r)`) runs, since the binding's annotation decides.
