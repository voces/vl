### D2925 — an `if` join of a re-seated record list with a list of the literal's own annotated record is invalid wasm

**now a loud emit reject · clause 2, still open · was check-clean invalid wasm, the same on master `8615a730d` · an `if` arm that joins the list is checked against its sibling arms, and a list literal arm holding a record built at another row is refused (`rsJoinSiblingBad`, `rsBuiltElemFail`) · fixtures `tests/cases/soundness/error-reseated-record-list-joined-with-built-record.vl`, `tests/cases/soundness/reseated-record-list-joins-and-returns-run.vl` · found closing D2914 (the #3238 review) · filed 2026-09-28 against master `a41bd80e8`**

#### Mechanism

D2881 builds `il` at `I`'s row. The `if` joins it with `[i]`, a list of the annotated
`{ f: i32 }` record, which is built at that record's own row, so the two arms deliver lists of
two heap types into one join. An `if` join of `il` with itself or with a fresh object-literal
list runs, so D2914's refusal allows every `if` arm rather than refuse those.

#### Grading list

#### Close

The walk now climbs from an `if` arm to the whole join. It checks the other arms: a list literal
arm whose already-built record is at another row is refused with D2917's message. A join with
`il` itself or with object literals runs. The join's own uses are then walked like the list's,
which covers the grading list's returned join. `[i]` would need its record converted, so the
row stays open under clause 2.

#### Record covariance (2026-09-30)

The destination stores a numeric field at another width or kind, so under the record-covariance ruling the literal-holding binding or function is not adopted and the program keeps its master behaviour until the owner rules on [D3339](D3339.md) (DECISIONS.md "Record covariance: only a fresh value widens").
