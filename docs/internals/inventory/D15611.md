### D15611 — [CLOSED 2026-11-09] a generic called through a function parameter and through a list of it at two types traps on an indirect call

**closed 2026-11-09, runs and prints `5` then `s` · was loads then traps, clause 1, `vl check` rc 0, prints `5`, then `wasm trap: indirect call type mismatch` · filed 2026-11-09 against master `d4901c70` · closed in mono's flow planner (emit_mono.vl `monoFlowReadSet`): an element read of an un-annotated list parameter handed on uncalled is no longer rewritten to a bare name read of the generic it holds, which carried no instance and resolved to the generic's first one; the read stays a read of the element its caller's literal already instanced · fixture `functions/list-element-handed-to-hole-at-two-types.vl` · the same program under a hole is [D15609](D15609.md)**

Repro:

    function id(v) { return v }
    function call1(f, x) { print(f(x)) }
    function call0(fs, x) { call1(fs[0], x) }
    call1(id, 5)
    call0([id], "s")

Want:

    5
    s

#### Mechanism

`monoFlowReadSet` rewrote the read `fs[0]` in place to the name read `id`. The emitter resolves a
bare name to the generic's first slot, so `call0` handed `call1$string` the `i32` instance's closure
while the literal itself held the `string` one. A name read has no instance to carry.
