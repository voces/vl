### D16362 — a record field of a list of an integer-literal union with a member past `i32` is laid out as an `i32` list

**closed 2026-11-14 — the witness runs and prints `9000000000` `1` · was: check-clean invalid wasm · clause 1 · `failed to parse WebAssembly module` · the same list outside a record runs · found grading `annotated-mixed-width-litunion-list.matrix.vl` and `inferred-mixed-width-litunion-list.matrix.vl` (8 struct-field cells) · filed 2026-11-14 against master `b45a06ef`**

Repro:

    type W = { f: (9000000000 | 1)[] }
    const w: W = { f: [9000000000, 1] }
    print(w.f[0])
    print(w.f[1])
    // vl check: rc 0.  vl run: failed to parse WebAssembly module

Want:

    9000000000
    1

#### Mechanism

A union of integer literals whose members fit `i32` is stored as `i32`, and a list of it as an
`i32` list. `fieldCodeOfTyCovered` applied that rule to any integer-literal union, so a field
`(9000000000 | 1)[]` was laid out as an `i32` list. The value is built as a list of union boxes,
which is how that union is stored everywhere else, so the module's `struct.new` took the wrong
list. The field's rule now asks that every member fit `i32`, as the rest of the rep does.
