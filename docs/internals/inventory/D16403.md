### D16403 — a hole parameter inferred at a record by its body's delivery takes no wider row: the width rewrite respells only a written annotation

**loud check reject · clause 2 · `an object value of shape … flowing into P drops the field …` · the `hole_fwd` cell (annotated face) of `record-param-width-before`/`-between` · found by lane I in L3 A2 · filed 2026-11-15 against master `83a90988d`**

Repro:

    type P = { name: string }
    function show(p: P) { print(p.name) }
    function fwd(t) { show(t) }
    const v: { age: i32, name: string } = { age: 3, name: "a" }
    fwd(v)
    // vl check: rc 1, the field-dropping refusal at `fwd(v)`

Want:

    a

#### Mechanism

`fwd`'s un-annotated parameter takes `P` from its body's delivery into `show`, so `fwd(v)`
delivers the wider row into an inferred `P` parameter. The record-width rewrite
(`wsCandidateAt`) requires the parameter's written annotation to name the record, which a hole
parameter has none of, so the refusal stands. With the value un-annotated the row is built at
`P` and the program runs.
