### D3962 — a `let` seeded with an alias of a generic function and then written builds invalid wasm

**check-clean invalid wasm · clause 1 · found by the D3960 matrix (`alias_match_*`, `alias_generic_*`, 50 cells) · filed 2026-10-10 against master `eb81bdd89`**

Repro:

    function inner<U>(u: U) { print("I"); print(u) }
    function q(n: i32) { print("Q"); print(n) }
    function main() {
      const al = inner
      let k = al
      k = q
      k(1)
    }
    main()
    // vl check: rc 0.  vl run: the emitted module failed to validate inside `main`

Want:

    Q
    1

#### Mechanism

Not located. With the seed named directly (`let k = inner`) the same program runs, so the
written-let rung that instances the seed resolves a generic by name and does not follow a
`const` alias to it; the binding keeps the generic's un-pinned type.

#### Ablation

| ingredient changed | outcome on master | needed? |
| --- | --- | --- |
| `let k = inner`, no alias | runs | **yes** |
| no write | runs | **yes** |
| `k = inner`, the aliased generic written back | runs | **yes** |
| `k = other`, another generic written | invalid wasm | no |
