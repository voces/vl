### D16780 — a generic or hole-parameter function relaying a non-generic maker's hole lambda, delivered at a function type returning `f64`, keeps the lambda's `i32` result

**loads then traps · `vl check` rc 0, `wasm trap: indirect call type mismatch` · clause 1 · a relay face of [D16753](D16753.md) beside [D16755](D16755.md) · routed to lane INIT (relay twins) · found by the maker/map/relay hunt · filed 2026-11-16 against master `6fb5ac348`**

Repro:

    function deliver() { return (a) => a + 1 }
    function wrap<T>(x: T) { return deliver() }
    const w: (a: i32) => f64 = wrap("s")
    print(w(3) / 8.0)
    // vl check: rc 0.  vl run: wasm trap, indirect call type mismatch

Want:

    0.5

#### Mechanism

Not traced. The delivery's result reaches `wrap`'s instance, which relays `deliver()`; `deliver`'s
closure is built at the body's `i32`. The non-generic relay of one delivery runs (the call search
climbs through `relay` to the call `w(3)`); through an instance of a relay with a generic or hole
parameter it does not, even for one delivery.

#### Ablation

| ingredient changed | outcome | needed? |
| --- | --- | --- |
| `wrap(x: string)`, annotated, not generic | runs, `0.5` | **yes**: an instanced relay |
| `wrap(x)`, an un-annotated parameter | the same trap | no: any instanced relay, generic or hole |
| `relay() { return deliver() }`, no parameter, one delivery | runs, `0.5` | **yes**: the generic relay |
| a second delivery `const v: (a: i32) => i32 = wrap(1)` | prints `4`, then the same trap | no |
