### D16829 — a map of records nesting a record whose function field holds un-annotated functions of different results is refused at check

**closed 2026-11-16 — the witness runs and prints `1.5` · was: loud check reject · clause 2 · found closing [D16809](D16809.md) · filed 2026-11-16 against master `eb9685821`**

Repro:

    function inc0(a) { return a + 1 }
    function half(a) { return a / 2.0 }
    const m = Map()
    m.set("a", { r: { f0: inc0 } })
    m.set("b", { r: { f0: half } })
    const t = m.get("b")
    if t != null { print(t.r.f0(3)) }
    // vl check: rc 1, "cannot write 'half' to 'm[].r.f0': called at (i32) it returns f64, where 'inc0', also written to it, returns i32 — every function a call through 'm[].r.f0' may run must return one type"

Want:

    1.5

#### Mechanism

Two halves, as WIDTH's findings below say. **Join:** a later `m.set`'s record joins its function
sets into the map's value one level deep (`elabFnRecJoin`, `compiler/check_elab_cap.vl`), so the
read's set missed `half`. `m.set` now joins through nested records (`elabFnRecJoinDeep`), and
every record literal already written into the map's slots is regrown to the joined record at any
depth (`elabSlotLitsRegrow`), so the first `set`'s leaf is the joined set's id. **Storage:** a
record's tagged function field is rewritten to its `i32` id only inside a list or a map
(`fnTagRepTyOf`), so a literal nesting a record was built at a row keyed by its own set, while the
map stores the value at its deep rep; two maps of the shape with different sets then disagreed on
the row. Each record literal `set` into a held map nesting a record is now stamped, its nested
literals too, at the map's storage rep (`ftStampMapSetLits`, `compiler/check_fn_tag.vl`).

The index-store spelling, `m[k] = { r: { f0: … } }`, keeps the one-level join and stays a check
reject: regrowing there built a second row of the same shape beside a `set` map's.

#### Findings (lane WIDTH, 2026-11-16, master `06f1673d5`)

Two halves, both needed; a judge that accepts the program without the second builds invalid wasm.

- **Join.** A later `m.set`'s record joins its function sets into the map's value
  (`elabFnRecJoin`, `check_elab_cap.vl`, D15806) for the record's own function fields only; it
  does not descend into a nested record, so the read's set misses `half` and the judge refuses.
  Recursing into a nested record field lets the `if t != null` spelling past the check; the `?.`
  spelling stays a check reject.
- **Plan.** With the join recursing, the second `m.set` builds a module that fails to validate:
  its record literal's nested record is not built at the map's record rep. The post-commit stamp
  for a record written into a map of the set's records (`ftMapRecLit`, `check_fn_tag.vl`) stamps
  only the top record, and stamping its nested records too (`fnTagHeldRecLit`) changes nothing:
  the plan does not record this store, so the loop never sees it.
