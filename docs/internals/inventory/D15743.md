### D15743 — a function field written into a generic maker's record is refused at emit, at one call type or two

**closed 2026-11-11, runs and prints `2` `2.5` · was loud emit reject, clause 2, `cannot take the generic function \`id1\` as a value` at one type and `ref valtype with no interned shape` at two · found grading w315's emit-reject grouping (cell `d15270_generic_mk`) · closed in the check: D15270's arm reads a generic maker's returned values when each is a record literal (`holeSlotCallRetRecs`, check_relate_core.vl), whose function fields are the same in every instance, so `letCallFieldsWiden` widens the written field · two instances of the maker, each written, run · fixture `tests/cases/generics/fn-record-from-generic-maker-field-written-two-types.vl` · not reached: the maker returning a `const` that holds the literal, filed as [D15745](D15745.md)**

Repro:

    function id0(a) { return a }
    function id1(a) { return a }
    function mk<T>(x: T) { return { f: id1, x: x } }
    const r = mk(1)
    r.f = id0
    print(r.f(2))
    print(r.f(2.5))

Want:

    2
    2.5

#### Mechanism

D15270's arm seeded a call-bound binding only from a function declaring no type parameter (`holeSlotCallRets`). The same maker without a type parameter (`function mk(x: i32)`) runs, and so does
the generic maker with no write. The write into an instance's record meets a field built as a
closure of `id1`; at two types, the instance's record has no interned row.
