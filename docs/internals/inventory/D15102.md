### D15102 — a written `let` read in a closure inside a generic body instanced at two types, written with a lambda, needs an id per instance

**runs today and must keep running · split-plan dependent (W family, per-instance id): with the split plan off (`compileSrc` returning after its first compile) it is a loud emit reject, `the reassigned function binding … holds functions called at more than one argument type` · from G2's minimisation of the "reassigned function binding" group · filed 2026-11-03 against master `1484b3d7`**

Repro:

    function inner<U>(u: U) { print("I"); print(u) }
    function a<T>(x: T) {
      let k = inner
      const rd = () => {
        k(x)
      }
      k = (u) => { print(u) }
      rd()
    }
    a(1)
    a(true)

Want:

    1
    true

#### Mechanism

The written value `(u) => { print(u) }` is a lambda declared inside `a<T>`'s body, a value per instance of `a`, which `ftWithinInstancedFn` refuses as a leaf of the set `k` holds. The per-instance identity design (with D15101, D15103) is to give each instance's lambda its own id.
