### D15102 — a written `let` read in a closure inside a generic body instanced at two types, written with a lambda, needs an id per instance

**closed 2026-11-03, runs with the split plan on and off · was split-plan dependent (W family, per-instance id): with the split plan off a loud emit reject, `the reassigned function binding … holds functions called at more than one argument type` · closed by per-instance-identity-2026-11.md slice 4b: the tag decision admits a lambda declared in an instanced body as a member when its binding is written only in that body and every read is a call (`ftInstLeafOk`), so each instance makes and dispatches its own ids · fixture `closures/per-instance-lambda-written-in-instance-body-read-in-closure.vl` · from G2's minimisation of the "reassigned function binding" group · filed 2026-11-03 against master `1484b3d7`**

Repro:

    function inner<U>(u: U) { print("I"); print(u) }
    function a<T>(x: T) {
      let k = inner
      const rd = () => {
        k(x)
      }
      k = (u) => { print(u) }
      rd()
    }
    a(1)
    a(true)

Want:

    1
    true

#### Mechanism

The written value `(u) => { print(u) }` is a lambda declared inside `a<T>`'s body, a value per instance of `a`, which `ftWithinInstancedFn` refuses as a leaf of the set `k` holds. The per-instance identity design (with D15101, D15103) is to give each instance's lambda its own id.
