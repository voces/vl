### D15691 — a spread of a fresh literal list beside a kept maker's call in a list literal is refused, though the list could be built at the call's record

**closed 2026-11-11, runs and prints `1` then `5` then `1` · was loud check reject · closed by the fresh-call copy (`recFreshCallCopy`, `recHeldFreshCopy`, check_fit_rules.vl): a maker called more than once keeps its own record, and a delivery whose destination stores a field differently copies the call there, so no other delivery reads it at another row · graded by `scripts/capability-probes/matrix/kept-maker-delivery.matrix.vl` · found closing D15657 · filed 2026-11-11 against master `ada32709`; master trapped the compiler on it**

Repro:

    type J = { f: i32 | null }
    function mk2() { { f: 1 } }
    const dA: J = mk2()
    print(dA.f ?? 0)
    const xs = [{ f: 5 }]
    const ys = [...xs, mk2()]
    print(ys[0].f ?? 0)
    print(ys[1].f ?? 0)

Want:

    1
    5
    1

#### Mechanism

Not ablated. `ys` is a container whose stored value `mk2()` builds it at `J` (`recStoresAgree`).
`xs` is a fresh `const` of a record literal held at its own `{f: i32}`, and nothing adopts it at
`J` from a spread into a list literal (D15287's adoption covers a spread into a push only), so
`recStoreSpreadsApart` refuses the part. On master the spread part reached `recRefuseAtOwnRow`
with no type and trapped the compiler.
