### D17782 — D15777's record `if` handed to a function's `const` lambda is refused at emit when that function takes an un-annotated parameter the lambda reads

**closed 2026-11-28 · runs, prints `4` · fixed in wasmEmit.vl: `printScalarArmOf` reads a call the frame types open at the width its callee is called at (`openCallWidth`: a lifted `const` lambda's slot result, else the closure call's signature result), so the arm `printOp` lowers agrees with the operand `printStmt` builds · pins `closures/closure-call-over-instance-param-printed-at-call-width.vl` · the same mechanism as D17664's float face · the bound form is [D17804](D17804.md) · was loud emit reject · clause 2 · `print operand rep` at `print(take(q))` · `vl check` rc 0 · a neighbour of D15777 · filed 2026-11-28 against master `0d0ff1e2` by COV-CALL**

Repro:

    function inc0(a) { return a + 1 }
    function half(a) { return a / 2.0 }
    function two() { return [1, 2].length }
    function main(k) {
      const take = (r) => r.f(k)
      const q = if two() > 5 { { f: half } } else { { f: inc0 } }
      print(take(q))
    }
    main(3)
    // vl check: rc 0.  vl run: emit error (print operand rep)

Want:

    4

#### Mechanism

`take` is a closure (no lift, no capture-free lambda: `r` is un-annotated), and the call is typed
at a hole of `main`'s instance. `printStmt` builds the operand through `closureCallRhs` at the
call's signature key, whose result is `f64`; the print arm was asked of the call's open frame type
and took the `i32` default, so the two disagreed and the builder refused. Reading the arm at the
callee's called width closes it, and the same reader answers D17664's lifted call.
