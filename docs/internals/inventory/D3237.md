### D3237 — an inferred return that is a tail assignment reads its target cell from the name's first binding in the function, in any scope

**check-clean invalid wasm · clause 1 · the assignment-tail sibling of [D3236](D3236.md), found by its grid · filed 2026-09-29 against master `94670f728`**

Repro:

    function pick(c: boolean, big: i64, small: i32) {
      if c {
        const s = big + 1
        print(s)
      }
      let s = 0
      s = small
    }
    function main(): i32 {
      const r = pick(false, 9, 7)
      r
    }
    print(main())
    // vl check: rc 0.  vl run: invalid module inside `main`, expected i32, found i64

Want:

    7

#### Mechanism

A function whose tail is an assignment takes its result from the target cell
(`fnAssignRetKind`). The five cell readers (`fnAssignCellKind`, `…Slot`, `…MapShape`,
`…TypeName`, `…Elem`) each resolve the target by `parentLetOf(body, name)`. That returns the
name's first `LetDecl` anywhere in the body: here the dead-scoped `i64` one. D3236 fixed the
same lookup in `retLocalCellKind` and `boundBoolByName`, where the read's own node was in
hand. These readers receive only a NAME, from `fnAssignRetTargetName` and from the tail-`if`
arm join (`ifTailAssignName`, `fnAssignCellEq`). The fix is to hand them the target `Ident`'s
node and resolve with `parentLetOfAt`. The arm join has to carry each arm's own target node
too, because an arm's target can be arm-local.
