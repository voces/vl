### D2804 — an un-annotated record literal with a type-parameter field has no row in a generic instance

**loud emit reject · clause 2 · 20 cells of the D2801 grid (the `fld` consumer at a `T` pin) and every pin tried · pre-existing on master `2bbc5c412` · filed 2026-09-27 against master `2bbc5c412`**

Repro:

    function g<T>(v: T) {
      const o = { f: v }
      print(o.f)
    }
    g(3)
    // vl check: rc 0.  vl run: emitProgram: object literal but no struct type declared

#### Mechanism

Not ablated to a rung. The literal's inferred type is `{f: T}` in the generic body, and no
struct row is collected for it at the instance's pin, so the literal refuses where it is built.
The same literal in a non-generic function (`v: i32`) and the annotated binding
(`const o: { f: T } = { f: v }`) both run, as does a declared return `{ f: T }`. At a union pin
(`i32 | string`) the sentence is `object literal matches no union variant` instead.

#### Ablation

| ingredient removed | outcome | needed? |
| --- | --- | --- |
| the generic (`v: i32`) | runs | **yes** |
| the inference (`const o: { f: T }`) | runs | **yes** |
| the binding (`print({ f: v }.f)`) | still refuses (`field access but no struct type declared`) | no |
| the `T` field being read (`{ f: v, n: 1 }`, `print(o.n)`) | still refuses | no |

#### Grading list

The D2801 grid's `fld` cells at the `gen`/`genN` faces, and the pins `i32`, `string | null`,
`i32 | string`, `i32 | null`.
An instance of D2850. #3220 closed this for a moment by giving the binding the substituted
shape as its annotation, then withdrew it with the rest of D2850's per-pin rows. The same
literal refuses outside a binding too: returned (`function f<T>(t: T) { { v: [t] } }`), passed
(`g({ v: t })`), read by `.field` directly, or held as a list element.
