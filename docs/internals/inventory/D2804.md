### D2804 — an un-annotated record literal with a type-parameter field has no row in a generic instance

**closed 2026-09-27 · was a loud emit reject, clause 2, on master `7323baf55` · 20 cells of the D2801 grid (the `fld` consumer at a `T` pin) and every pin tried · filed 2026-09-27 against master `2bbc5c412` · fixture `tests/cases/generics/generic-record-literal-binding.vl` · the literal outside a binding is D2840**

Repro:

    function g<T>(v: T) {
      const o = { f: v }
      print(o.f)
    }
    g(3)
    // vl check: rc 0.  vl run: emitProgram: object literal but no struct type declared

#### Mechanism

Anonymous struct rows are minted by `collectAnonShapes` before monomorphization, from each
literal's recorded shape. The literal records `{f: T}`, which has no field code, so no row is
minted, and the clone shares the template's literal node, so no later pass sees a concrete
shape. Closed by giving the un-annotated binding the shape substituted through the instance's
binding as its annotation (`monoTyParamShapeAnn`), which `collectAnnShapes` interns, as it
already did for the annotated spelling.

The same literal in a non-generic function (`v: i32`) and the annotated binding
(`const o: { f: T } = { f: v }`) both run, as does a declared return `{ f: T }`. At a union pin
(`i32 | string`) the sentence is `object literal matches no union variant` instead.

#### Ablation

| the `T` field being read (`{ f: v, n: 1 }`, `print(o.n)`) | still refuses | no |
