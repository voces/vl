### D17730 — an element read over a union of lists stored alike tests the literal-set arm by its elements, which the shared rep cannot tell apart

**loud emit reject · clause 2 · `the compiler cannot yet lower this statement (is list fit refused)` · found closing [D16981](D16981.md) · filed 2026-11-27 by COV-IS**

Repro:

    type K = 1 | 2
    const c: K[][] | i32[][] = [[1], [2]]
    for e in c { print(e.length) }
    // vl run: emitProgram: the compiler cannot yet lower this statement (is list fit refused)

Want:

    1
    1

#### Mechanism

The list-union rewrite (`check_list_union.vl`) splits an element read over `K[][] | i32[][]`,
a `for` walk's element or an index `c[0]`, into one arm per member behind an `is` test, since the
element it yields is typed per member (`K[]` against `i32[]`). The `is K[][]` test must check that
every element is a `K`, a list fit (`listFitIsPlanOf`). The two members share one rep, an i32 list
of lists, so the builder refuses the fit (`lftOk < 0`). D16981's close merges the arms of a LENGTH
read only (`luAlikePut`); an element read is left split by ruling, so it needs either the element
walk built at the shared rep or a ruling that the element read takes the union of the members'
element types.
