### D1863 — the doc table is filled by the LEX, and the module pipeline serves tokens from a cache instead of lexing

**closed · one `import` silenced every `///` surface; filed 2026-09-08 against master `4b36f61b1`, fixed the same day**

Repro:

    /// A documented function.
    function mine(): i32 { return 7 }
    print(mine())
    // vl run: 7.  The program is not the witness — see below.

#### Mechanism

`docCmt*` (`check_state.vl`) is filled by `vcLoadToks`, which runs only when a module is
LEXED. The module pipeline is built not to lex twice: `modScan` tokenizes each module and
banks the tokens in `modCacheTok*`, and `vcLoadToksMod` then replays that bank and returns
before reaching `vcLoadToks`. So the doc table was empty for every module the cache served
— which, after `modScan`, is all of them.

A second clear compounded it: `vcLoadToks` reset the table whenever `P.toks` was empty, and
the module load loop empties `P.toks` after `modScan` has run, so the rows a lex did collect
were dropped before the loop that needed them. The fix banks the `///` rows beside the
tokens (`modCacheDoc*`, filled at both sites that fill `modCacheTok*`, replayed on a hit,
evicted with the slot) and moves the clear into `modCompile`, where the module tables reset.

#### Ablation

| ingredient removed | outcome | needed? |
| --- | --- | --- |
| the `///` above the declaration | no doc, correctly | n/a — it is the subject |
| the `import` (single-module) | the doc is returned | **yes** |
| a warm module cache (ask before any check) | still no doc | no — `modScan` warms it first |
| a second module that is not the entry | still no doc for the entry's own declaration | no |
