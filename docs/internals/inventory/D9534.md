### D9534 — a list literal holding an inline record and a bound record of un-annotated functions of one result cannot take the inline function as a value

**closed 2026-10-26 with [D13970](D13970.md) · the witness prints `6` · every spelling in the grading list runs (the element store `l[0] = r0`) · fixture `tests/cases/lists/list-literal-elements-delivered-at-built-type.vl` · clause 2 · was loud check reject `a {f: (i32) => i32} cannot be delivered as {f: (_) => _} here`, before that loud emit reject, `emitProgram: cannot take the generic function `inc0` as a value` · found closing [D9470](D9470.md) · present on master `1cf53e320` · filed 2026-10-22 against master `1cf53e320`**

Repro:

    function inc0(a) { return a + 1 }
    function dbl(a) { return a * 2 }
    const r0 = { f: dbl }
    const l = [{ f: inc0 }, r0]
    print(l[1].f(3))
    // vl check rc 1 (was rc 0, then an emit reject). Expected: 6.

#### Mechanism

The call `l[1].f(3)` now closes both records' `f` at `(i32) => i32`: `l` and `r0` are re-checked
as that type. The list literal still joins its elements from the first, `{ f: inc0 }`'s open
`{f: (_) => _}`, and the covariant-delivery check refuses the now-typed `r0` there. That join
is [D13970](D13970.md), which refuses the fully annotated spelling on master too.

#### Ablation

| ingredient removed | outcome | needed? |
| --- | --- | --- |
| the binding (`[{ f: inc0 }, { f: dbl }]`) | runs, `6` | **yes** |
| the inline record (`[r0]`, `l[0].f(3)`) | runs, `6` | **yes** |
