### D17877 — `vl check` is silent on a pure comparison discarded as the last statement of a nested block

**runs today and must keep running · open as a lint gap: `vl check` warns nothing at the discarded comparison · filed 2026-11-28 by COV-CALL against master `caffc73f9`**

Repro:

    function f(x: i32): boolean {
      if x > 1 {
        x < 0
      }
      return false
    }
    print(f(2))
    // vl check: rc 0, no warning.  vl run: prints false

Want:

    false

The program is right to run; what is missing is a warning at `x < 0`, a comparison whose value
nothing reads.

#### Mechanism

`compiler/lint.vl`'s discarded-value rule (the "This expression has no effect" arm and the
"did you mean `return …`?" arm) fires on a non-final expression statement, and on the final
statement of a void function's body. The final statement of a nested block (an `if` arm, here)
is exempt as a possible block value, even when the block is a statement whose value nothing
reads, so a pure comparison there is discarded silently. That is the shape the compiler itself
carried at `compiler/emit_sig_tokens.vl`'s `letAnnIsUninternedShape`: its only true answer was a
bare `repStructRowOfTy(...) < 0`, so the function always answered false and its caller's
refusal could never fire (deleted as dead code with this row).

#### Ablation

| ingredient removed | outcome | needed? |
| --- | --- | --- |
| the `if` (the comparison as a non-final statement of the body) | warns `This expression has no effect` | **yes** |
| the comparison as the body's final statement in a void function | warns `did you mean return …?` | **yes** |
| the comparison (`x + 1` in its place) | still silent | no |

#### Grading list

- A pure arithmetic expression at the same place (`x + 1`) is silent too; the rule should cover
  any discarded value whose evaluation has no effect, the `exprEffectFree` set.
- A block whose value IS read (`const y = if c { x < 0 } else { false }`) must stay silent.
