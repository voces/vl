**closed · now prints `4` then `i` · was check-clean silently wrong, clause 1 · found by the #3317 review (`rv3317-7c184e7a`, P2) · filed 2026-09-30 against master `8df60e472` · closed 2026-11-01 against master `f6db0729`: a field read at the own type narrows a box stored at a wider record back member by member, and gave up on any stored member the own type lacks, `null` among them, so the `f64` was read as it lay; a stored `null` now needs no re-tag (`memReadBoxPlan`, emit_classify.vl) · fixture `soundness/record-built-at-nullable-converting-field-read-at-own-type-runs.vl`**

Repro:

    type D = { v: f64 | string }
    const x: i32 | string = 4
    const o = { v: x }
    const d: { v: f64 | string | null } = o
    print(d.v)
    const t = o.v
    if t is i32 { print("i") } else { print("n") }

Want:

    4
    i

#### Mechanism

Measured at the close: the destination without `| null` already ran, printing `i`, because the
read re-tags the stored `f64` back to `i32`. With `| null` in the stored union, the read plan
declined the whole re-tag. The prediction below was the filing's.

A prediction, D3011's neighbour without the merge. The adoption of `o` is undone by the
`is i32` read, so `o` keeps its own type while built at the destination, which stores the
`i32` as an `f64`, and the own-type read answers from the `f64` box. D3011's refusal
(`recNumMergeField`) fires only where the destination keeps two of the source's numbers as
one, and `i32 | string` has one number, so nothing refuses this. The owed outcome is a read
that recovers the `i32` (a bare `D`-typed delivery does, `{v: i32 | string}` into
`{v: f64 | string}` printing `1` for `3 / 2`), or the D3011 refusal extended to a converted
member.
