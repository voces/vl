### D4927 — `is S[]` over `string[] | S[]` reads the box tag and never tests the elements

**check-clean silently wrong value · clause 1 · related to D4771 (`is` over a list tests every element) and D4906 (the `i32[] | K[]` atom spelling) · filed 2026-10-15 against master `23dcd80be`**

Repro:

    type S = "x" | "y"
    const v: string[] | S[] = ["x", "y"]
    print(v is S[])
    // vl check: rc 0.  vl run: prints false
    // PRINTS false

Want:

    true

#### Mechanism

`emitListFitIs` declines every union receiver (`exprUnion`), so `is S[]` over a union falls
to the box-tag test. The literal is delivered into the `string[]` arm, and the tag answers
which arm holds the value, not whether every element fits `S` as D4771 and D3885 rule. The
fix tests the tag, and on the other list arm walks its elements as `emitListFitIs` does for a
non-union list.

#### Ablation

| ingredient changed | outcome | needed? |
| --- | --- | --- |
| `const v: string[] = ["x", "y"]` | prints true, right | **yes** (a union receiver) |
| `["x", "z"]` | prints false, right | **yes** (elements that fit) |

#### Grading list

The numeric spelling `i32[] | K[]` with `type K = 0 | 1`, and the same test as a function
parameter.
