### D16868 — a generic a maker returns, written into a map element called at two signatures, must keep an instance per read

**runs today and must keep running · refutation pin (the index-write omit in `eplSlotCallRecs`) · the `elem_map_two_signatures` cells of `relay-generic-written-into-element.matrix.vl` · found by lane WIDTH closing D16864 · filed 2026-11-16 against master `ffeb4f4ee`**

Repro:

    function k<T>(x: T): T { return x }
    function mk() { return k }
    const w: (x: string) => string = mk()
    print(w("s"))
    const m = Map()
    m["k"] = mk()
    const a = m["k"]
    if a != null { print(a(41)) }
    const b = m["k"]
    if b != null { print(b(true)) }
    // vl run: s, then 41, then true. Traps (indirect call type mismatch) without the omit.

Want:

    s
    41
    true

#### Mechanism

The map element is called at `(i32)` and at `(boolean)`, so the maker call written into it has no
one signature to be built at (`fvaWrittenElemSig` declines) and is not twinned. The place classes
would then follow the write, delivering `mk`'s returned read at `string`, `i32` and `boolean`, and
mono builds one wrong instance: a trap. The index-write omit (`eplSlotCallRecs`, `EPL.idxWrites`)
leaves the write's calls out of a call search read from a value, so the read is built per call
another way; D16864 narrowed it to writes whose value is not twinned, and this program is why it
stays. It goes once a map element called at two signatures takes an instance per read.
