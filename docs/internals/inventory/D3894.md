### D3894 — a nested generic called through two `const` aliases with a value of the enclosing `T` builds invalid wasm

**closed 2026-10-09 by lane SC · runs · was check-clean invalid wasm · found in review of #3468 (`rv3468c-witnesses/b16.vl`) · filed 2026-10-09 against master `c6ac0a1d2` · pins: `tests/cases/generics/alias-chain-of-generic-function.vl`**

Repro:

    function a<T>(x: T) {
      function b<U>(y: U): U { y }
      const f = b
      const h = f
      print(h(x))
    }
    a("s")
    // vl check: rc 0.  vl run: invalid module

Want:

    s

#### Mechanism

Not located. The monomorphizer, not the checker: the same on master and after D3853, whose
checker change is the only one in its PR. A one-link alias (`const f = b; print(f(x))`) runs.

Closed: a call through an alias resolved the callee from the alias's own initializer, which for
`h` is `f`, no function, so `b` was never instanced for it and the call lowered at the template.
The call arm now follows a chain of un-annotated, never-written aliases to the generic it names
(`monoGenFnAliasChainFe`). In an enclosing generic instantiated twice, D3887's per-instance copy
and frame rename follow the same chain.
