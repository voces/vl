### D7482 — comparing a delivered generic with the generic's name fixes its type parameter, so a later delivery at another type is refused

**loud check reject · clause 2 · CAPABILITY: without the comparison both deliveries run, printing `2` · the comparison binds `two`'s `T` at `i32` for the rest of the module, which no ruling asks for · found closing [D7382](D7382.md) · present on master `1c86d0f42` · filed 2026-10-19 against master `1c86d0f42`**

Repro:

    function two<T>(x: T): i32 { return 1 }
    const p: (x: i32) => i32 = two
    print(p == two)
    const r: (x: string) => i32 = two
    print(r("a"))
    // vl check: cannot assign (T) => i32 to 'r' of type (x: string) => i32

Want:

    true
    1

#### Mechanism

Not located. Something in checking `p == two` leaves `two` typed at `(x: i32) => i32` for the
later delivery. It is not `assignable` against `T` in `checkEqualityBinNode`, which binds
nothing ([D7384](D7384.md)'s mechanism); the operand's own read of `two` is the next suspect.
