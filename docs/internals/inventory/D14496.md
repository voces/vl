      const v = a

#### Mechanism

Delivering `mk()` into `J` builds `mk`'s one literal at `J`'s row, where `f` is a nullable
`i32` box (`struct (field (ref $box))`). The un-annotated parameter takes the row of the
argument its caller passes, so `__take`'s parameter is typed at that boxed row. But the
parameter's checker type is still `{f: i32}`, and the field read is emitted at that type: a
`struct.get` whose `(ref $box)` result goes straight into `i32.add`, with no unboxing. A local
bound to the same call (`const w = mk(); print(w.f + 1)`) reads the same row correctly, so the
miss is in how a parameter's field read picks its storage. The emit site that makes that choice
is not identified yet.
