### D16326 — `x is 1 | "a"` over an `i32 | string` answers `false` for the numeric member

**open · wrong output, prints `false` then `true` then `false` · clause 1 · found closing D4082 · filed 2026-11-15 against master `5683d3b2c`**

Repro:

    function h(x: i32 | string) { x is 1 | "a" }
    print(h(1))
    print(h("a"))
    print(h(2))

Want:

    true
    true
    false

#### Mechanism

Disassembled: the test reads the box's tag once, compares it with the string arm's, and then
compares the payload with `"a"`. Nothing tests the `i32` arm against `1`, so a literal
set over two scalar bases is answered for its string members only. D4086, the same set as a
narrowed record field, waits on this: the record test leaves such a field to the emitter
(`litSetMixesBases`, check_annot_resolve.vl).

#### Ablation

| ingredient removed | outcome | needed? |
| --- | --- | --- |
| the string member (`x is 1 \| 3`) | runs | **yes** |
| the numeric member (`x is "a"`) | runs | **yes** |
| a third member (`x is 1 \| "a" \| "b"`, `x is 1 \| 3 \| "a"`) | wrong output, the same | no |
| the order (`x is "a" \| 1`) | wrong output, the same | no |
