### D3156 — a `??` over a hole's literal-union map read, defaulted by another read of it, prints the atom id

**closed 2026-09-30 · was check-clean silently wrong, clause 1, on master `8df60e472` · found by the #3282 review's `f1` grid (`r7` `hole` cells) · built by lane MH · runs and prints the value, where the direct spelling is a capability refusal · fixture `tests/cases/generics/hole-map-read-atom-value.vl`**

Repro:

    type AB = "a" | "b"
    type R = { m: {[i32]: AB} }
    function mk(): R {
      const m: {[i32]: AB} = Map()
      m[3] = "b"
      { m: m }
    }
    function use(p) {
      print(p.m[9] ?? p.m[3])
    }
    use(mk())
    // PRINTS 0

#### Mechanism

The direct spelling `function use(p: R)` is a check reject: a `??` over a non-nullable atom map
must take a member literal or an atom, and a read `K | null` is neither. At a hole the checker
defers the `??` (`HD_COAL`) and never re-asks that rule at the pin, so the program is
check-clean. The instance reads both operands at the template's type, so the fused read
yields the atom id and `print` reads an `i32`.
The row asked for the checker's refusal at the pin. The close runs the program instead,
printing `b`, which is the value: the direct spelling's refusal is `tErrUnsupported`, a
capability sentence, and the `{[i32]: AB | null}` twin it is a refusal for runs at both
spellings. The `??` default that no atom can hold (`?? 5`) is [D3127](D3127.md).
