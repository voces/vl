### D15956 — a call through a re-pointed generic `let` re-asks every function ever written to it, not the one its most recent write stored

**loud check reject · `argument 1: operator '+' is not defined for boolean and i32 (the body of `k` applies '+' to this argument)` · clause 2 · the flow-sensitive-read ruling permits it (DECISIONS.md, "A read of a `let` takes its most recent write's type"): `k(true)` reads `inner` · the function-valued face of that item · filed 2026-11-12 against master `682105de7`**

Repro:

    function inner<U>(u: U) { print(u) }
    function plus<V>(v: V) { print(v + 1) }
    function main() {
      let k = plus
      k(1)
      k = inner
      k(true)
    }
    main()
    // vl check: argument 1: operator '+' is not defined for boolean and i32 (the body of `k` applies '+' to this argument)

Want:

    2
    true

#### Mechanism

Two mechanisms refuse it, and both have to move.

- **The D3968 re-ask.** `fsbRecheckCalls` re-asks, at every call through a binding marked by
  `fsbMark`, the deferred constraints of every function written to it. The call's own
  constraint owner is the seed, through `identFnAliasOf`. Neither asks which writes reach the
  call.
- **The function set.** The binding's type carries the set of every function written to it
  (`elabFnLetTy`). A call through it makes an elaboration instance of each member at the
  call's argument types, so `plus<boolean>` is checked.

A prototype scoped the first mechanism with hidden write rows, described in the
2026-11-12 refactor note `flow-reads-function-face-measured`. That moved the refusal into `plus`'s body (`operator '+' is not
defined for boolean and i32` at its `v + 1`), which is the second mechanism. A visible row of
the written function's type cost three programs that run today at emit:
`let f = id; f(1); f = (n) => n; f("s")` became "the reassigned function binding `f` is called
at more than one argument type". So the close narrows the read's function set to the writes that
reach it, and the emitter lowers such a read.

#### Ablation

| ingredient changed | outcome | needed? |
| --- | --- | --- |
| the second call at `5` instead of `true` | runs, `2` `5` | **yes** |
| the write `k = inner` removed | refused, correctly (`plus` holds) | **yes** |
| the order swapped (`let k = inner; k(true); k = plus; k(1)`) | refused at `k(true)`, the earlier call | no, a second spelling |

#### Grading list

* The swapped order above, where a later write is re-asked at an earlier call.
* The hole-lambda spelling: `let k = (x) => { print(x + 1) }; k(1); k = (y) => { print(y) }; k("s")`.
* [D15957](D15957.md), the delivery spelling.
