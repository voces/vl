### D4304 — a `match` arm that destructures a field named like a generic function calls the field's value as that function's instance

**check-clean invalid wasm · clause 1 · found by the function-value flow table in shadow mode (fn-value-flow-design.md §(f) step 1) over the review witnesses (`rv3487/round3/s06d`; `s06c`, the same shape without generics, runs) · filed 2026-10-13 against master `aa43e52ef` with #3542 applied**

Repro:

    function a<T>(x: T): (t: T) => boolean { (t: T) => true }
    type FA = { a: (x: f64) => (t: f64) => f64 }
    type FB = { b: i32 }
    function pr<T>(u: FA | FB, y: T) {
      match u {
        FA{a} => print(a(2.5)(2.5))
        FB{b} => print(a(y)(y))
      }
    }
    pr({ a: (x: f64) => (t: f64) => t * 2.0 }, 1)
    pr({ b: 3 }, "s")
    // vl check: rc 0.  vl run: the emitted module failed to validate inside `pr`

#### Mechanism

In the `FA{a}` arm, `a` is the destructured field, but the monomorphizer reads the call
`a(2.5)` by its spelling and instances the module generic `a` at `f64`; the field's closure
and the instance disagree on the result type. The flow table grades the arm's call
`disagree: a call spelled like a local binding | shadowed binding`, and `pr`'s instances
`disagree: instance fits no binding`.
