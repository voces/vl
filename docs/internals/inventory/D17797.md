### D17797 — a maker called at two types beside another maker of the same un-annotated function is refused at emit

**loud emit reject · `a generic function taken as a value reaches no call that fixes its type` · clause 2 · `vl check` rc 0 · filed 2026-11-28 against master `77e1160e` by COV-CLOS-3 (found writing D17129's witness)**

Repro:

    function inc0(a) { return a + 1 }
    function mk(f) { return { f: f } }
    print(mk(inc0).f(3))
    function mk2(f) { return { g: f } }
    print(mk2(inc0).g(3))
    print(mk2(inc0).g(4.5))
    // vl check: rc 0.  vl run: emit error at 5:11, "reaches no call that fixes its type"

Want:

    4
    4
    5.5

#### Mechanism

`inc0` is one singleton set. Without `mk`, the check tags it and `mk2`'s two calls dispatch on the
id. With `mk`, D16738's rung in `ftParamStored` (check_fn_tag.vl) refuses the tag for the whole
set, because `mk` reads its parameter into a record field whose row is built with a closure. Left
a closure, `mk2`'s calls are pinned by `monoHoleGenFnPin` → `elabHoleGenFlowTy`, which reads the
EPL place graph. That union-find has no call/return context, so both `mk2` calls' field `g` fall
into one class called at `i32` and `f64`; it answers -1 and the cascade refuses.

#### Parked (2026-11-28, coordinator ruling)

Ruled close (A): tag the set and deliver the member's closure at the closed field type to `mk`'s
argument (`cloAt` / `fnCloCoerceNote`), with mono following the delivered type. Route (B), call
context in the EPL union-find, was refused.

Tried: the rung becomes that delivery (`ftCloFieldHand`), and `monoPinHoleParam` pins at
`fnCloCoerceTyOf`. Both fire, and `mk` is pinned at `(i32) => i32`. It stops at a delivery to a
hole parameter whose reads are typed by the set: every existing `cloAt` destination is
annotated, so its reads take the annotation. Here the check types three nodes past the
conversion at the set's id: the callee's parameter, the literal's field `f`, and the reads of
the call's result (`mk(inc0).f`, rep `i32`, and the call through it, a set dispatch). The witness
then refuses with "member record with no row", and k8 (`mk` and `mk2` called once each, which runs
on master) goes runs → not-runs. Noting the call result's row lets the read follow the built kid;
`mk`'s instance then builds invalid wasm, since its literal is still stamped at the id record.
Refused as ways out: a retype of those nodes from the outside (a second planner of the set's
reach), and a tag predicate "only when a call is split". The WIP is branch `cov-union-d17797-wip`.

Likely the same mechanism as I8-PREP's instance per argument storage rep ([D17820](D17820.md),
D17816's PR 3a): `mk`'s instance keyed at its argument's converted closure rep would type its
parameter, field and result at that rep from the declaration down. When PR 3a lands, re-run k8
and this witness on it. If it covers them, this closes as a small follow-up; if not, the row says
why.
