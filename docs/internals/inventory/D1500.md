### D1500 — assigning a bare INDEX to a function-local `let` TRAPS THE COMPILER: `len = xs[0]` is check-clean, then the seed dies

**COMPILER TRAP · `vl check` rc 0, then the SEED's own `out of bounds array access` with ~14 anonymous frames · clause 1 · reported 2026-09-03 by the first EXTERNAL vl consumer (the `~/glean` WC3 replay player, VL-016), hit on the first compile of a DEFLATE decoder · confirmed on master `cdfdc14e`, not only their pinned `2fb8b271`**

Repro (`vl check` rc 0; `vl run`, `vl build` and `vl check --codegen` all die inside the compiler):

    function f(xs: i32[]) {
      let len = 0
      len = xs[0]
      len
    }
    print(f([5]))

* **THE INGREDIENT IS A PLAIN `=` WHOSE RHS IS EXACTLY AN INDEX NODE, INTO A FUNCTION-LOCAL
  `let`.** Every neighbour runs, and the reporter's ablation reproduces cell for cell:

  | variant | outcome |
  | --- | --- |
  | `let len = xs[0]` (declaration, not assignment) | runs `5` |
  | `len = xs[0] + 0` (RHS is a BinExpr) | runs `5` |
  | the same two lines at MODULE scope | runs `5` |
  | `const v = xs[0]` then `len = v` | runs `5` |
  | `left -= h.count[i]` (compound assign) | runs |
  | `return len` instead of the bare tail | **traps** |

  So the bare tail is not the ingredient either — the assignment is.

* **IT IS INDISTINGUISHABLE FROM A PROGRAM TRAP, WHICH IS THE SECOND DEFECT.** The message is
  the seed's own `wasm trap: out of bounds array access` with no function names, so a user
  reads it as *their* array index being out of range — the reporter first looked for the bug in
  their own DEFLATE decoder. A compiler crash must not wear a program's error. Filed separately
  by the reporter as VL-013; this row records the interaction because it is what cost them the
  time, not the crash itself.

* **THE FAMILY IS NOW THREE, ALL FOUND ON ONE DAY BY UNRELATED WORK.** [D1440](D1440.md) (an
  unguarded `T.tys[t.nInner]` on a `-1` hole) and [D1462](D1462.md) (`print(xs[0] + 1)` over an
  un-annotated `[]`) are the other two. Three compiler traps surfacing in a day from three
  independent directions is the argument for auditing the unguarded-index family as a family
  rather than patching the three sites.

#### Why no instrument had this

`vl check` returns 0, so the checker's own suites cannot see it. It is not in the distilled
corpus (generated over fixed axes) and had no capability probe (one hand-written program per
already-known gap). It took an external user writing an ordinary decoder. That is the same
population [D1473](D1473.md) came from, measured there at roughly one defect per twenty
ordinary programs.

#### The consumer-facing half

The second defect this row names — *a compiler crash must not wear a program's error* — is
closed in the HOST rather than the compiler: `vl` now prints a banner naming the file and the
seed, and exits **70**, whenever the failing wasm call went into the compiler module. See
`docs/internals/cli-design.md` §"Exit codes, and which module trapped".
