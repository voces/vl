### D1500 — assigning a bare INDEX to a function-local `let` TRAPPED THE COMPILER: `len = xs[0]` is check-clean, then the seed dies

**closed 2026-09-03 — the witness runs · was a compiler trap (`vl check` rc 0, then the seed's own `out of bounds array access` with anonymous frames) · fixed by taking `refListSlotOfExprStrict` in `exprEmittedRefListSlot`'s `Index` arm and bound-guarding `rlElemInnerSlot`'s name fall-through · clause 1 · reported 2026-09-03 by the first EXTERNAL vl consumer (the glean WC3 replay player, VL-016, `~/glean/docs/vl-issues.md`), hit on the first compile of a DEFLATE decoder · confirmed on master `cdfdc14e`, not only their pinned `2fb8b271`**

Repro (before: `vl check` rc 0 and `vl run` / `vl build` / `vl check --codegen` all die inside
the compiler; now: prints `5`):

    function f(xs: i32[]) {
      let len = 0
      len = xs[0]
      len
    }
    print(f([5]))

#### The named backtrace

Localised with `vl build compiler/entry.vl --names`, then that module as the `--compiler`
seed — the reported frames were `2175 ← 3812 ← 3878 ← 3936 ← 4005`:

    0:  0xf048b - vl!rlElemInnerSlot$m15
    1: 0x17ab26 - vl!emitAssign$m19
    2: 0x182f8c - vl!emitFuncBody$m19
    3: 0x189be6 - vl!emitFuncCode$m2
    4: 0x1926e0 - vl!emitCodeSection$m2

    6: 0x18f6b6 - vl!emitProgram$m2

#### Mechanism

`refListSlotOfExpr` CLAMPS a miss to slot `0` — the in-band sentinel its strict twin's own
header calls "exactly wrong for a consumer deciding whether two rows DIFFER, because slot 0
is a real row". `exprEmittedRefListSlot`'s `Index` arm (added by D791) consumed the clamping
reader and handed the 0 straight to `rlElemInnerSlot`, whose arena rung declines for a
bare-scalar array and whose NAME fall-through then read `rlElemName[0]` with no bound. A
module whose only arrays are scalar (`i32[]`, `f64[]`, `boolean[]`, `string[]`) interns no
ref-list row at all, so `rlElemName` is EMPTY and slot 0 is out of bounds.

Only `emitAssign`'s `local.set` arm asks that classifier pair on this path: the `global.set`
arm returns from `if idx < 0` before reaching it, and a DECLARATION never enters `emitAssign`.
That is the whole ablation in one sentence.

Both halves are fixed, because either alone would have hidden the other: the arm now takes
`refListSlotOfExprStrict` (a miss answers -1, which is this function's documented contract),
and the fall-through bound-guards its read the way `refListElemNameOfExpr`'s six sibling
reads already do (D227, D179 — the same hazard, twice previously named in this file).

The last two rows are the decisive controls: the defect is not "an Index RHS", it is a
CLAMPED slot read against an EMPTY table. Add one ref-array anywhere in the module and the
same witness compiles — which is why every fixture in the tree missed it.

#### The position matrix found it at exactly one cell, and that cell did not exist

`scripts/capability-probes/matrix/index-read-into-local-assign.matrix.vl`, graded
`--before` the pre-fix seed and `--after`: **52 of 52 run after, 0 silent, 0 runs → not-runs**,
with `local_assign` the only red cell before — in BOTH faces.

`matrix.py` had no `local_assign` position. `global_assign` covered `emitAssign`'s
`global.set` arm (D965's missed position) and the `local.set` arm — the plainest reassignment
in the language — had no cell, so the other twenty-six graded this value green while the
compiler crashed on it. The position is added, pinned by name in
`tests/vl_capability_matrix_test.ts`, and it immediately found a second, unrelated silent cell
it is the only position that can see: `array-new-default-f64`'s un-annotated face is
check-clean invalid wasm at `local_assign` and RUNS everywhere else. That one is PRE-EXISTING
(identical before and after this fix) and is not closed here.

#### The family is three, and they do NOT share a rung

All three surfaced on 2026-09-03 from unrelated directions, and each is a distinct site:

| row | rung | phase | sentinel |
| --- | --- | --- | --- |
| [D1440](D1440.md) | `nodeTyIsNulBool` → `T.tys[t.nInner]` | emit | `-1` arena hole |
| [D1462](D1462.md) | `checkBinExprNodeReal` → `T.tys[lt]` | **check** | `-1` unresolved element |
| D1500 | `rlElemInnerSlot` → `rlElemName[slot]` | emit | clamped `0` into an EMPTY table |

Verified by re-running both witnesses on this candidate seed: D1440 is the loud
`bare null needs a struct-typed context` it was closed to, and D1462 still traps, unmoved,
inside the CHECKER. **Fixing this rung fixes neither of the others**, and no single guard
covers all three — D1440/D1462 index the arena with a hole id, this one indexes a reflist
column with a clamp. The family-wide guard is the shape, not the site: *a table read whose
index came from a reader with an in-band "no answer" value must be bound-tested or must take
that reader's strict twin.* `emit_classify.vl` already spells the bound-test idiom fourteen
times for `rlElemName` alone; what is missing is anything that makes a new consumer adopt it.

#### The second defect, not closed here

The trap wears the seed's own `wasm trap: out of bounds array access` with no function names,
so a user reads it as THEIR index being out of range — the reporter went looking in their own
DEFLATE decoder and lost a session. A compiler crash must not be able to wear a program's
error. Filed separately by the reporter as VL-013; recorded here because it is what cost them
the time, not the crash itself.

#### Why no instrument had this

`vl check` returns 0, so the checker's own suites cannot see it. It is not in the distilled
corpus (generated over fixed axes), it had no capability probe, and the position matrix had no
cell for its position. It took an external user writing an ordinary decoder. That is the same
population [D1473](D1473.md) came from, measured there at roughly one defect per twenty
ordinary programs.
