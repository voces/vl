### D3926 — a call through an annotated binding of an alias of a capturing nested generic, in a generic instantiated twice, builds invalid wasm

**closed 2026-11-01 — runs, prints `7` `2` `s` `2` · was check-clean invalid wasm (clause 1) · an annotated binding of a generic's value or alias now counts among an instance's generic aliases (`monoInstGenAliasNames`), so each enclosing instance copies the calls through it; the call `h(2)` had been one node every instance shared, and the later instance's rename to its own frame's copy of the nested generic overwrote the first's · fixture `tests/cases/closures/nested-generic-alias-into-annotated-binding-two-instances.vl` (an alias of an alias at three instances, a `let` binding, one also held in a list) · found closing D3902 (`d3902/m`: `alias__bind__*`, `chain__bind__*` at two and three instances) · filed 2026-10-09 against master `255fc7a6c`**

Repro:

    function outer<T>(x: T) {
      function inner<U>(u: U) { print(x); print(u) }
      const k = inner
      const h: (n: i32) => void = k
      h(2)
    }
    outer(7)
    outer("s")
    // vl check: rc 0.  vl run: prints 7 2 s 2 (was: the emitted module failed to validate inside `outer`)

Want:

    7
    2
    s
    2

#### Mechanism

Not located. A call through `h` is not a call through the alias `k` (an annotated binding is not
followed by the alias chain), so D3887's frame rename of the alias does not reach it. Since
D3902, passing `h` on as a value (`call(h)`) runs.

#### Ablation

| ingredient changed | outcome | needed? |
| --- | --- | --- |
| `outer("s")` removed | runs | **yes** |
| `h` passed on (`call(h)`) instead of called, alone | runs, since D3902 | **yes** |
| `h` passed on, beside another function with a nested generic | invalid wasm, the same | no |
| `h` un-annotated (`const h = k`) | runs | **yes** |
