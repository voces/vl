### D3664 — a captured `let` that a lifted local function writes is still a shared heap cell, a list wrapper and its backing per binding

**runs today and must keep running · open · a cost row, no wrong value: the witness prints its Want, and the cell is the cost, which no grader outcome reads · sunpa SP-037 step 2, the half [D3663](D3663.md) left · at `-O3` binaryen inlines `bump` and scalarizes the cell, so the allocation remains at `-O0`/`-O` and wherever the callee is not inlined · filed by lane CL against master `32b753681`**

Repro:

    function count(n: i32): i32 {
      let k = 0
      const bump = (d: i32) => { k += d }
      for i in 0 until n { bump(i) }
      k
    }
    print(count(10))
    // after D3663: `bump` is a direct call taking the cell as a parameter (no environment),
    // but `k` is `struct.new $list (array.new_fixed 1 …)` once per `count` call

Want:

    45

#### Mechanism

`captureBoxRewrite` decides by-reference capture early, from the AST, before anything knows
the closure will be lifted: `k` is assigned by a closure, so every use of it reads and writes
`cell[0]`. Lifting ([D3663](D3663.md)) passes the cell's reference, which is correct and
keeps the allocation. Removing it needs the lift decision BEFORE `captureBoxRewrite` (it is
syntactic, so it can be made there) and a second calling convention for a lifted function
that writes a capture: the value passed in and returned beside the result as wasm
multi-value, written back by each call site — every return path, a void body, and the tail
call (`return_call` cannot carry the extra result) would need it.

#### Grading list

The written-after-creation and written-by-the-closure cells of the lane-CL grid (`letwa`,
`box_writes`, `box_writes_ret`, `cap_list_mutate`): each must still print what master prints,
and a closure that ESCAPES must keep sharing the cell.
