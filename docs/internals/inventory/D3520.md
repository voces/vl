### D3520 — a generic body's lambda joining its two type parameters and `null` loses the null's tag: `?? 9` then `is i32` answers true for a string

**closed 2026-10-04 — the witness prints `false` · was check-clean silently wrong, clause 1 · found by the #3342 review (its findings 1–3, at the declared spelling) · filed against master `b2238d2c6`, closed against master `0c087fb3c` by lane LR · fixtures `tests/cases/generics/lambda-join-type-params-keeps-null.vl`, `tests/cases/generics/lambda-join-call-readers.vl`, `tests/cases/generics/lambda-join-captured-copy.vl`**

Repro:

    function G<A, B>(k: i32, a: A, b: B) {
      const g = () => { if k == 0 { a } else if k == 1 { b } else { null } }
      const v = g()
      print((v ?? 9) is i32)
    }
    G(1, 3, "t")
    // PRINTS true on master

Want:

    false

#### Mechanism

A lambda's inferred return over the enclosing body's type parameters was a deferred hole join
(`A | B | null`), and every call of the lambda collapsed it to its first member
(`collapseDeferredJoin`): `g()` typed `A | null`, so at the pin `(i32, string)` the body read
the lambda's box as `i32 | null` and folded `is i32` to `true`. Closed in the checker: a
lambda's join of two or more of an enclosing body's type parameters is that body's kept-apart
join (`openParamJoinOf`), so the lambda's clone and every caller re-join it at the pin alike.
Parameter holes take the same join only when it carries a `null` ([D3616](D3616.md)), and a
join the lambda only relays from a call (`dJoinRelayed`) is the callee's, which a gated helper
widens. The clone returns that signature (`monoCloneLambdaSubst`), and an `if` whose arms have
no pinned join of their own names its record-armed box at the pin. [D3528](D3528.md)'s
"instance holds a function" gate is lifted with it.
