### D15299 — a `??` default between a map read of a function set and a declared function outside the set keeps the set untagged

**runs today and must keep running · refutation pin · the tag decision refuses a `??` join of a set's id with a closed function outside the set (`ftNodeOk` on the `??`), so the set stays untagged and mono's map-value pin (`monoStoredSlotFnTy`'s `v` path) carries it; a step-4 join question (architecture-target-2026-10.md, step 4) · found sizing step 4 (γ)'s map slice, [D15298](D15298.md) · filed 2026-11-04 against master `5dbc31bf`**

Repro:

    function inc0(a) { return a + 1 }
    function zero(a: i32) { a - a }
    const m = Map()
    m["k"] = inc0
    print((m["k"] ?? zero)(3))

Want:

    4

#### Mechanism

`m["k"]` reads the set `{inc0}` as `(_) => _ | null`, and `?? zero` joins it with `zero`, a declared function whose type is closed and which is no member of the set. The tag decision walks every node carrying the set and refuses this join (`ftNodeOk`, the `??` arm), and since a set's decision covers all its uses, one such default keeps every other spelling of the set on the pin. With the map-value pin refused, the program is an emit refusal.
