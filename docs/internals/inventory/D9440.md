### D9440 — a map of generic functions handed to an un-annotated function that stores another generic into it refuses the store as an indexed assignment to a non-array

**loud emit reject · `vl check` rc 0 · `indexed-assignment target is not an array` · clause 2 · found closing [D9310](D9310.md) · present on master `af839a093` · filed 2026-10-21 against master `af839a093`**

Repro:

    function id<T>(x: T): T { x }
    function id2<T>(x: T): T { print("id2"); x }
    function fill(mm) { mm["k"] = { f: id2 } }
    const m = Map()
    m["k"] = { f: id }
    fill(m)
    const r = m["k"]
    if r != null {
      print(r.f(2))
      print(r.f("s"))
    }
    // vl check rc 0.  vl run: emit error: emitProgram: indexed-assignment target is not an array

Want:

    id2
    2
    id2
    s

#### Mechanism

Not traced. From the ablation only: the refusal is at `fill`'s store, and needs the stored
value to be a generic other than the one the caller stored; storing `id` again runs. The
map escapes to `fill`, so the read devirtualisation that closed D9310 declines it.

#### Ablation

| ingredient removed | outcome | needed? |
| --- | --- | --- |
| the second call's type (`r.f("s")`) | refuses, `a generic function taken as a value reaches no call that fixes its type` | no |
| the record (`mm["k"] = id2`, `r(2)`) | same refusal | no |
| `id2` in `fill` (stores `id`, one call type) | runs, `2` | **yes** |

#### Grading list

The same program with one call type, which refuses with the generic-value message.
