### D7484 — a generic whose function-typed parameters are handed raw generics, binding its type parameter from nothing, meets an internal floor

**closed 2026-10-23 by lane L1 · runs, prints `true false` · built: a type parameter whose every naming parameter is a function slot handed a generic function default-binds under the [D4551](D4551.md) ruling (`monoDefaultTyParamsOnlyGenFns`, emit_mono.vl), declining where the return or a body spelling would answer the default · pins: `tests/cases/generics/open-generics-*fn-typed-params*.vl` · was loud emit reject · `vl check` rc 0 · clause 2 · CAPABILITY: the same call with one argument delivered first as `(x: i32) => i32` runs, printing `true` · found closing [D7382](D7382.md) · filed 2026-10-19 against master `1c86d0f42`**

Repro:

    function two<T>(x: T): i32 { return 1 }
    function three<T>(x: T): i32 { return 3 }
    function same<T>(f: (x: T) => i32, g: (x: T) => i32): boolean { return f == g }
    print(same(two, two))
    print(same(two, three))
    // vl check: rc 0.  vl run: emitProgram: internal: a parameter type the valtype ladder has no rung for — every parameter type the checker accepts has one above

Want:

    true
    false

#### Mechanism

Nothing binds `same`'s `T`: both arguments are generic in their own parameter, so the instance
is asked for at an open `T`. The D4551 default (`monoDefaultUnboundTyParams`) skipped `T` because
a parameter annotation names it. The default now also applies when every parameter naming `T`
is a function slot handed a generic function; each generic is then instanced at the default.
