### D977 — `.pop()` on the SCALAR-LIST family: no arm, and a discarded pop lands as invalid wasm

**closed — `i64[]`, `f64[]`, `f32[]` and `u8[]` now pop through the same shape the i32 default uses · found by std:fmt's exact big-integer arithmetic (serde stage 0), which carried a `bnLen` scan because it could not trim high zero limbs**

`emitPop` handled ref lists, string lists and the i32 default. `exprArray` claims only an
i32-element list, so every wide scalar list fell to `.pop receiver is not a list` — and
because **`emitFail` does not halt**, a DISCARDED `a.pop()` then landed as check-clean INVALID
WASM rather than a refusal. Three lines, no other list in the program.

* **THE ARM NEEDED NOTHING NEW.** `scalarListWrap` / `scalarListBack` give the wrapper and
  backing, and each kind already has its own push scratch base. The i32 arm was the model.

* **THE SPELLING DECIDED WHETHER IT WAS LOUD, which is what made it a clause-1 row and not
  only a clause-2 one.** A discarded `a.pop()` is silent; the same pop through a function
  PARAMETER refused loudly (`emitProgram: .pop receiver is not a list`), and an `f64[]` pop
  refused with a THIRD message. One missing ladder, three outcomes.

* **THE VALUE-USED SPELLING IS A SEPARATE, PRE-EXISTING LIMIT.** `const v = a.pop()` refuses
  for **i32 too** — verified against `git archive origin/master`, unchanged by this fix — so
  it is not scalar-list-specific and does not belong to this row.

    print(a.length)
