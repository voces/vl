### D2562 — a generic's `a ?? b` over `a: T | null` types as the bare `T` at the pin, dropping the default's type and the null

**check-clean invalid wasm · clause 1 · found grading [D2373](D2373.md)'s close · filed 2026-09-26 against master `71571e409`**

Repro:

    type A = { r: i32 }
    type B = { q: string }
    function mkA(): A | null { return null }
    function mkB(): B | null { return { q: "b" } }
    function pick<T>(a: T | null, b: B | null) { return a ?? b }
    const x = pick(mkA(), mkB())
    print(x.r)
    // vl check: rc 0.  vl run: invalid module, inside `pick`:
    // "type mismatch: expected (ref null $type), found (ref null $type)"

#### Mechanism

A prediction until a close confirms it: the checker types the call `pick(mkA(), mkB())` as `A`,
so `x.r` checks clean although the value is a `B` (or null). The `??` over a left operand whose
non-null part is a type parameter defers its result to the pin, and the pin answers with the
parameter's binding alone, never joining the default's type or keeping the default's null. The
body is then emitted as `A`'s niche with `mkB()`'s `(ref null $B)` as its fallthrough.

#### Ablation

| ingredient removed | outcome | needed? |
| --- | --- | --- |
| the type parameter (`a: A \| null`) | runs | **yes** |
| the default's null (`b: B`) | still invalid | no |
| a record default (`b: i32`, `?? 4`) | still invalid, `x.r` still checks | no |
| the inferred return (`: T \| B \| null` written) | still invalid inside `pick` | no |
| a default of the same parameter (`b: T \| null`) | `x == null` refused: `cannot compare A with null` | no |

#### Grading list

Each ablation row above, and the same body with the join bound to a local inside `pick`.
