#### Mechanism

`monoCoerceRetAtPin` delivered a returned generic NAME at the caller's pin, but a returned list
or record literal fell through, so the functions inside it were coerced at the literal's own
slots, which no call pins. A call by index (`v[1](3)`) went through the per-destination return
copy and ran. The `.map` callback is instanced in `monoCoerceListCbArg` and needs a closed
receiver type, which `monoPinnedAnnTyAt` could not read through a call. Module code is walked
before the callee's body, so the returned literal's element type was still open when the
callback asked for it.
