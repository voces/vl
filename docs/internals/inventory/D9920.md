### D9920 — an integer-keyed map spelled as a parameter of a function type refuses at the annotation

**loud emit reject · `vl check` rc 0 · `emitProgram: an i32-keyed Map/Set is supported as … — not inside '({[i32]:i32})=>i32'` · clause 2 · CAPABILITY: the same function taken as a value through an un-annotated `const` runs, and a `{[string]: i32}` parameter runs at every spelling · found closing [D9822](D9822.md) · present on master `a901a928e` · filed 2026-10-22 against master `a901a928e`**

Bind the i32-keyed map on its own and pass it where you need it.

#### Mechanism

The spelling gate (`i32MapPeelWrappers`, `i32MapSpellingUnsupported`, emit_collect.vl) peels a
function type's RESULT, a list layer and a `| null` to reach the map leaf, but never a
function type's PARAMETER, so any annotation that spells an integer-keyed map in a parameter
of a function type is refused before the signature is built. The `$fnsig` key itself has the
token: the same `g` bound to an un-annotated `const` and called with `null` at
`{[i32]: i32} | null` runs.

| the `i32` key, for `i64` | still refuses, naming `i64-keyed` | no |
