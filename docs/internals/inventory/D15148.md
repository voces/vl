### D15148 — a call through a map entry is taken to write the entry, so a narrowed `m["k"]` cannot be called twice

**closed 2026-11-04 by this PR (lane bundle) — the repro now RUNS and prints the Want below: a call through a map slot or list element is charged the functions stored there (`callFnValueDecls`). Was: loud check reject · clause 2 (`'m["k"]' was narrowed by a guard, but the call on line 4 can write it — re-test 'm["k"]' after the call`) · found grading `returned-bundle-record.matrix.vl`'s `map_value_place` cells (both faces, both bundle templates) · filed 2026-11-04 against master `ccfdb7a33` by lane bundle**

Repro:

    const m = Map()
    m["k"] = (a: i32) => a + 1
    if m["k"] != null {
      if m["k"](4) == 5 {
        print(m["k"](4))
      }
    }

Want:

    5

#### Mechanism

The guard narrows the place `m["k"]`. A call made through that place is a call of a function value
the map holds, and the narrowing is dropped across any call that can write the place. The checker
takes this call as one that can, although every function the map is written (here one lambda,
capturing nothing) writes nothing. The function values a slot can hold are known to the write scan
(`cwPathFnTargets`, keyed by root binding and path); this call site did not ask it. A call through
a plain binding already asked the same question of the binding (`callFnValueDecls`, D5017); the
index callee, `m[k](...)` or `xs[i](...)`, now asks it of the binding's element or map slot, and
a set holding any value that is not a known function stays opaque.
