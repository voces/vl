### D2711 — whether a tree of integer literals takes a float destination (`const q: f64 = 7 / 2`), pending the owner's ruling

**runs today and must keep running until ruled — prints `3` · a language-semantics question
beside plumb's PL-047 (D2709) · filed against master `fdd0050af`**

Repro:

    const q: f64 = 7 / 2
    print(q)
    // PRINTS 3
    // vl check: rc 0. The tree is computed as i32 (3) and converted.

#### Mechanism

D2709 lets a tree of integer literals take an `i64` destination's width. The same rule at a
float destination would read `7 / 2` as 3.5 (Swift's reading, `let x: Double = 7 / 2`) where
today it is 3 (Go's, whose untyped constants divide as integers), and so change the value of
programs that run today; `y * (1 / 2)` over an `f64` is 0 today and would be the half. It also
decides clause 2 at `f32`, where `const s: f32 = 7 / 2` is refused today (`i32 doesn't fit in
f32`). The candidate is built and switched off: `litTreeFloatAdopts` in `compiler/typecheck.vl`
answers false; true adopts a float destination when every operator has a float form (`+ - * /
%`, unary `-`) and every literal is exact there. Turning it on also needs `emitNumLitNode` to
emit an f64-typed literal past the i32 range as `f64.const` ahead of its `i64.const` arm
(`100000 * 5000000000` at an `f64`); that arm was left out because it cost every literal.

#### Grading list

`scripts/literal-tree-grid.py --float-adopt` grades the f64 and f32 columns against the candidate
reading; without it, against today's. With the switch on, 1,360 of 1,360 cells matched the
candidate reading on the D2709 branch.
