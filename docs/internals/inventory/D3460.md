### D3460 — a binding of a call's un-annotated fresh record, delivered to a record with a wider numeric field, builds invalid wasm

**closed 2026-10-20 by lane records with [D8140](D8140.md) · runs, prints `3.5` · was check-clean invalid wasm · clause 1 · the adoption follows the un-annotated binding back to the call it holds (`recBindOrigin`) and builds `mk`'s literal at `D`; the `let`, `const b = a`, `a.v = 2`, second-field, argument, return, list-element and map-`set` spellings all run, a second `const c = mk()` refuses (the literal cannot be built at two rows), and the siblings D3350 and D3342 are unchanged · fixture `tests/cases/soundness/record-fresh-call-delivered-through-binding.vl` · filed 2026-10-02 against master `c17016a1e`**

Repro:

    type D = { v: f64 }
    function mk() { return { v: 7 } }
    const a = mk()
    const d: D = a
    print(d.v / 2)
    // vl check: rc 0.  vl run: invalid module, "expected (ref null $type), found (ref $type)"

Want:

    3.5

#### Mechanism

Not localised past the ablation. The checker accepts the delivery (the fresh-record rule lets a
literal-built record widen its `i32` field to `f64`), but the emitter lays `a` out at the row the
literal's own `i32` field gives it, and the delivery into `D` copies the reference. The literal
delivered directly (`const d: D = mk()`) and a literal bound without a call (`const a = { v: 7 }`)
both run, so what is needed is a call result that is bound first and delivered later. Every
delivery position of the binding fails alike; inside a function the validator's sentence loses its
`null` (`expected (ref $type), found (ref $type)`). An annotated `mk(): { v: i32 }` is a check
reject, correctly, since that record is not fresh.

#### Ablation

| ingredient changed | outcome | needed? |
| --- | --- | --- |
| `const d: D = mk()`, no binding | prints `3.5` | **yes** (the binding) |
| `const a = { v: 7 }`, a literal instead of the call | prints `3.5` | **yes** (the call) |
| `type D = { v: i64 }` | prints `3` | **yes** (an `f64` target) |
| `type D = { v: i32 \| null }` | prints `7` | **yes** (a numeric widening) |
| `let a = mk()` | the same invalid wasm | no |
| a following `a.v = 2` | the same invalid wasm | no |
| a following `const b = a` | the same invalid wasm | no |
| a second field in both records | the same invalid wasm | no |
| the delivery as an argument `use(a)`, a return `r(): D { return a }`, a list element `[a]` | the same invalid wasm, `expected (ref $type), found (ref $type)` for the first two | no |
| `print(a.v / 2)` alone, no delivery | prints `3` | **yes** (the delivery) |
