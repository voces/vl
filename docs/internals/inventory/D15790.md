### D15790 — a call through a field of a `.slice` of a list of records whose functions return different types is refused at emit, where the unsliced read is refused at check

**closed 2026-11-11 · runs, `1.5`, since [D15791](D15791.md) closed (2026-11-12) · was a loud check reject from 2026-11-11, the unsliced twin's, `cannot store 'half' in 'mk()[].f': called at (i32) it returns f64, where 'inc0', also stored in it, returns i32 — every function a call through 'mk()[].f' may run must return one type` · was loud emit reject, `emitProgram: the lists this function returns are built at different rows, so its inferred list result has none`, clause 2 · the twin's refusal was ruled not a contract · found in w315's grouping of clause-2 emit rejects (group B: `d15221_slice_half`, `d15221_sliceb_half`, `d15294_two_records_called`) · filed and closed 2026-11-11 against master `82eca538` · fixed by reading a list's `.slice(…)` as its receiver in both slot-path walkers (`cwSliceRecv` in `cwSlotPath` and `holeSlotCallPath`), so the judge D15221 added sees the call through the slice**

Repro:

    function inc0(a) { return a + 1 }
    function half(a) { return a / 2.0 }
    function mk() { return [{ f: inc0 }, { f: half }] }
    print(mk().slice(0, 2)[1].f(3))

Want:

    1.5

#### Mechanism

`holeSlotJudge` decides whether every function stored in a list element's field may run under one
call. It reaches the stored functions by walking the read back to its root (`cwSlotPath` for a
binding, `holeSlotCallPath` for a call), and both walks stopped at a `.slice` call. The read
was not judged, the check passed, and the two records reached the emitter at two different rows.
A slice holds its receiver's own elements, so the walk now steps through it. The judge then
refuses with the sentence its unsliced twin already gives; that refusal is [D15791](D15791.md).
