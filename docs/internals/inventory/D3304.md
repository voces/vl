### D3304 — a parameter whose type is `null` alone has no lowering, so a bare `null` passed to a hole or generic parameter is refused

**loud emit reject · clause 2 · pre-existing on master `e70102886` · found by the D3301 lane grading #3305's re-review witness `q/a12` · filed 2026-09-29 against master `e70102886`**

Repro:

    function u(q) {
      if q != null { return 1 }
      return 0
    }
    print(u(null))
    // vl check: rc 0.  vl run: emitProgram: bare null needs a struct-typed context

Want:

    0

#### Mechanism

Not yet located. A hole or type parameter bound only by a `null` literal takes the type `null`,
and no parameter lowering exists for it: the annotated spelling `function u(q: null)` refuses at
emit with `only i32, i64, f64, f32, boolean, struct, union, array, or string parameters are
supported`. The call site's `null` argument then has no heap type to take. The rep a
`null`-typed parameter should have (`nullref`, the one the `const x = null` global already
takes) is the open question.
