### D14403 — an un-annotated function returning a generic keeps the generic's free `T` in its result, so an annotated destination cannot adopt it

**runs today and must keep running · carried by the emitter's flow pin, not by the checker · filed 2026-10-27 against master `9687dabf4` · the same family as D14400**

Repro:

    type K = "x" | "y"
    function same<T>(k: T): T { k }
    function d1() { return same }
    const v1: (k: K) => string = d1()
    print(v1("x") + "!")
    // vl check: rc 0.  vl run: x!

#### Mechanism

`d1` has no annotation, and its result is inferred as `same`'s own signature with `T` left
free. The annotated destination `v1` meets the call `d1()`, not the name `same`. So the
adoption that builds a generic named at a closed function type never reaches `same`, which
stands inside `d1`'s body. `same` is built at `(K) => string` only because the emitter
reads the flow pin of `d1`'s result in the generic-return path (`monoSlotPinNameTys` beside
`monoRetGenWidePins`). With that read removed the program traps with `indirect call type
mismatch`. D14400 is the same leaked `T`, held by a reassigned `let`.

This row is not built, by ruling. TypeScript infers `d1` as `() => <T>(k: T) => T`, which
returns a generic value rather than binding a type parameter from the result. Binding a
type parameter from the expected type is refused by design (`checkRetTyParamBound`), and
per-destination instantiation of an un-annotated function is not worth a mechanism for two
files. The pin that carries them stays. That pin is the generic-return read
(`monoSlotPinNameTys` in `monoCoerceRetAtPin`). Its neighbour `monoRetGenWidePins` stays as
well, as a correctness floor (`fn-value-instance-set-design.md` §5).

Witnesses, beside the repro:

* `tests/cases/closures/generic-returned-litunion-to-string.vl`
* `tests/cases/closures/generic-returned-two-results-one-param.vl`

#### Ablation

| ingredient removed | outcome | needed? |
| --- | --- | --- |
| the flow-pin read on the generic-return path | traps, `indirect call type mismatch` | **yes** |
| the relaying function (`const v1: (k: K) => string = same`) | runs on the checker stamp | **yes** |
