### D16798 — a maker with an un-annotated parameter, its call held by an un-annotated binding called at an `f64` result, builds an `i32` lambda into an `f64` use

**check-clean invalid wasm · `vl check` rc 0, `type mismatch: expected i32, found f64` · clause 1 · the un-annotated face of `maker-hole-param-at-two-results.matrix.vl`'s `two_instances` position, which [D16778](D16778.md)'s close (the annotated face) does not reach · filed 2026-11-16 against master `eaa93e525`**

Repro:

    function adder(n) { return (a) => a + n }
    const v = adder(2)
    print(v(3) / 8.0)
    // vl check: rc 0.  vl run: invalid module, expected i32, found f64

Want:

    0.625

#### Mechanism

Partly traced. A maker row for an un-annotated binding comes from the signature the binding is
called at (`fvaCallSig`), and `v(3)`'s result is still open when the rows are banked, so no row
names the `f64` result. With `n` annotated or absent, the lambda's result is decided from its
calls (D16711) on the maker's own instance; with a hole parameter the call's instance is the
hole-pinned one, which that path does not reach, so it keeps the body's `i32`.

#### Ablation

| --- | --- | --- |

| `const v: (a: i32) => f64 = adder(2)` | runs | **yes**: the un-annotated binding |
| inside a function, or two calls at `i32` and `f64` | the same invalid module | no |
