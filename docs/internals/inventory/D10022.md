### D10022 — a call returning one of two generics, handed to a split parameter after an argument reading a module `let` it writes, refuses

**loud emit reject · `vl check` rc 0 · `monomorphize: … is called at two instances of the function handed to it` · clause 2 · CAPABILITY: the first argument spelled `2` prints `4`, `zz`, `5`, `z` · found closing [D9596](D9596.md) · present on master `00cbfe00b` (as `monomorphize: unsupported argument type`) · filed 2026-10-22 against master `00cbfe00b`**

Repro:

    function id<T>(x: T): T { x }
    function twice<T>(x: T): T { x + x }
    let m = 2
    function deliver(n: i32) {
      m = m + 1
      if n > 1 { return id }
      return twice
    }
    function take3(k: i32, a) {
      print(a(k))
      print(a("z"))
    }
    take3(m, deliver(1))
    take3(5, deliver(3))
    // vl check rc 0.  vl run: emit error: emitProgram: monomorphize: `a` is called at two instances of the function handed to it in a call to `take3`

Want:

    4
    zz
    5
    z

#### Mechanism

The close of [D9596](D9596.md) binds the choosing call once ahead of the call's statement
(`fsChoiceStmt`, fn_split.vl), which reorders it before the arguments to its left; it accepts
only literals, functions, `const`s and parameters there, which the call cannot write. A
module `let` read ahead of it may be written by the call, so the hand-out declines. It needs
the arguments ahead bound in order too.
