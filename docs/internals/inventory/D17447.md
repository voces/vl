### D17447 — a list literal whose only element is a `null` unit read is not refused and builds invalid wasm

**check-clean invalid wasm · clause 1 · found by the D17445 sweep · owner S2 · filed 2026-11-24 against master `6063a6c1`**

Repro:

    const n = null
    const xs = [n]
    print(xs.length)
    // vl check: rc 0.  vl run: invalid module, expected i32, found nullref

Want:

    the check refusal its neighbours get: a list of only `null` has no element type

#### Mechanism

Not established. The check's `a list of only null` refusal fires for a `null` literal, a
`null`-returning call and a `null`-typed field read, but not for a `null` unit; the list then
takes an `i32` element rep and the `null` is stored into it. A generic body's `[x]` with
`x: T | null`, instantiated at `T = never` by a `null`-only call (D3178), is the same list and
is legal by the generic's own typing, so it must run.

#### Ablation

| spelling | outcome |
| --- | --- |
| `[null]`, `[g()]` with `g` returning `null`, `[o.f]` with `o = { f: null }` | the check refusal |
| `[n, 3]` | runs, `2` |
| `const xs: (i32 \| null)[] = [n]` | runs, `1` |
| `[n]` with nothing reading `xs` | invalid, the same |
| `function f<T>(x: T \| null) { return [x] }` called as `f(null)` | invalid inside `f` |
| the same called as `f<string>(null)` | runs, `1 true` |

#### Grading list

- The generic spelling, which must run: `f(null).length` prints `1`, `f(null)[0] == null` prints `true`.
  Its instance at `T = never` is invalid on master and after [D17445](D17445.md); with D17445 the
  call site no longer refuses first, so `f(null).length` is invalid too.
