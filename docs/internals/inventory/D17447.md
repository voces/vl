### D17447 — a generic's list literal of its `T | null` parameter, instantiated by a `null`-only call, builds invalid wasm

**check-clean invalid wasm · clause 1 · found by the D17445 sweep · owner S2 · filed 2026-11-24 against master `6063a6c1`; re-scoped 2026-11-25 by ADOPT-CHK: the filed unit spelling (`const n = null; [n]`) became the `[null]` check refusal with #10016 (D17304), so the row keeps the generic half**

Repro:

    function f<T>(x: T | null) { return [x] }
    print(f(null).length)
    // vl check: rc 0.  vl run: invalid module inside `f`, expected i32, found nullref

Want:

    1

#### Mechanism

Not established. The check's `a list of only null` refusal now fires for a `null` literal, a
`null`-returning call, a `null`-typed field read and a `null` unit (#10016). A generic body's `[x]` with
`x: T | null`, instantiated at `T = never` by a `null`-only call (D3178), is the same list and
is legal by the generic's own typing, so it must run.

#### Ablation

| spelling | outcome |
| --- | --- |
| `[null]`, `[g()]` with `g` returning `null`, `[o.f]` with `o = { f: null }` | the check refusal |
| `const n = null; const xs = [n]` (the filed spelling) | the check refusal since #10016 (D17304) |
| `[n, 3]` | runs, `2` |
| `const xs: (i32 \| null)[] = [n]` | runs, `1` |
| `[n]` with nothing reading `xs` | the check refusal since #10016 |
| `function f<T>(x: T \| null) { return [x] }` called as `f(null)` | invalid inside `f` |
| the same called as `f<string>(null)` | runs, `1 true` |

#### Grading list

- The generic spelling, which must run: `f(null).length` prints `1`, `f(null)[0] == null` prints `true`.
  Its instance at `T = never` is invalid on master and after [D17445](D17445.md); with D17445 the
  call site no longer refuses first, so `f(null).length` is invalid too.
