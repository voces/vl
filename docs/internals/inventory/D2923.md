### D2923 — a block-local list at the top level named like an adopted global list is built at the global's destination row

**check-clean invalid wasm · clause 1 · the same on master `a41bd80e8` · found closing D2914 · filed 2026-09-27 against master `a41bd80e8`**

Repro:

    const i: { f: i32 } = { f: 4 }
    type I = { f: i64 | null }
    function show(r: { f: i32 }) { print(r.f) }
    const il = [{ f: 7 }]
    const ic: I[] = il
    if true {
      const il = [{ f: 9 }]
      show(il[0])
    }
    print(ic[0].f)
    // vl check: rc 0.  vl run: invalid module in the top-level code

Want:

    9
    7

#### Mechanism

`dsScopeRootOf` finds a scope only for a function's binding or a module global; a `let` in a
block at the top level has neither, so `letRefListDestSlotK` falls back to a name-matched scan
of the whole arena and finds the outer `il`'s destination `const ic: I[] = il`. The inner list
is then re-seated at `I`'s row (D2881) and handed to `show` unconverted. D2914's refusal walks
the same missing scope and cannot speak for it.

#### Ablation

| ingredient removed | outcome | needed? |
| --- | --- | --- |
| the shared name (the inner list named `jl`) | runs, prints `9` `7` | **yes** |
| the block (the inner list inside a function) | runs | **yes** |

#### Grading list

The union-box twin (D381's destination walk over the same fallback), and a top-level `for`
body's binding.

A top-level `for` body is the same gap: `for k in [1] { const il = [{ f: 7 }]; const ic: I[] =
il; show(il[0]) }` is invalid wasm on master `a41bd80e8` and is not refused.
