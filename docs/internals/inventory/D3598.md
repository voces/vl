### D3598 — a record held in a loop-carried `let` keeps a `struct.new` per iteration: two allocations merge into one local at the loop header, which `--heap2local` cannot scalarize

**closed by D3625 — the witness prints `3.000000000000002`, and its `-O3` loop makes no allocation (1,001 before); 10M iterations take 5.2 ms on V8 against 34 ms, the three-locals spelling's speed · `p` is now held as one local per field, a field-only local the multi-value step scalarizes, so `add`'s and `scale`'s twins pass the fields through · no wrong value, a cost row · sunpa SP-027 · filed 2026-10-03 against master `af70a066a`**

Repro:

    type V3 = { x: f64, y: f64, z: f64 }
    function add(a: V3, b: V3): V3 { { x: a.x + b.x, y: a.y + b.y, z: a.z + b.z } }
    function scale(a: V3, k: f64): V3 { { x: a.x * k, y: a.y * k, z: a.z * k } }
    export function bench(n: i32): f64 {
      let p: V3 = { x: 0.0, y: 0.0, z: 0.0 }
      const v: V3 = { x: 0.001, y: 0.002, z: 0.003 }
      for _i in 0 until n { p = add(p, scale(v, 0.5)) }
      p.x + p.y + p.z
    }
    print(bench(1000))
    // vl build -O3: `add` and `scale` are inlined and `scale`'s record folds to constants,
    // but one `struct.new` per iteration stays in the loop, assigned to `p`

Want:

    3.000000000000002

#### Mechanism

The call and return boundary is not what keeps the allocation here. The escape step inlines both
producers, so a multi-value ABI under ruling (B) would remove nothing (refuted by D3625: its step holds a field-only `let` as one local per field, which is the lowering proposed below). The allocation that
survives is the one assigned to `p`. That local receives two allocations, the literal before
the loop and the result inside it, and the read `p.x` in iteration i+1 reads the allocation made
in iteration i. `--heap2local` scalarizes one allocation at a time, and only when that
allocation is the sole value reaching the locals it flows through. A merge at the loop header
fails that test, at any `-O` rung and with any inlining budget. The fix that matches what users
already write by hand (the a2 and a5 rows below, both at scalar speed) is a compiler-side
lowering. A `let` of a small record type that never escapes (only its fields are read, it is
reassigned only as a whole, and any call it is passed to neither writes its fields nor keeps
it) is held as one local per field. Each whole use builds a fresh `struct.new` from those
locals, and that single-site allocation is one `--heap2local` already melts once the callee is
inlined. This is a scalar replacement written in the compiler, which `DECISIONS.md` leans
against. It needs the coordinator's or owner's sign-off before it is built.

`-O3`, 10M iterations, Deno 2.9.6, median of 5 in-process calls at load 70–80 (`nice -n 19`). Results are identical in every row.
