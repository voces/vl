#### Mechanism

A list is `{backing, len, cap}`. `[]` builds a zero-length backing, and every `push` tests
`len == cap`, grows by doubling from a floor of four, stores, and writes `len` back. So a
16-element product made 4 backing arrays, copied 12 elements and did 16 `struct.set`s on
the wrapper. Pre-sizing alone measured only about 7%: the larger cost was that a push in a
loop body (1) counts as a call for `unrollCost`, so a 4-trip loop around it never unrolls, and (2)
blocks the list-header hoist (`hoistSafeExpr`), because any call may reallocate a list, so
every read of the input matrices reloaded its backing and `len` per iteration.

The close: when `const o: T[] = []` (or `let`) is followed, before any other use of `o`, by
pushes that are unconditional statements in constant-trip range loops (literal or module
`const` ends, any literal step, nested), with no `break`, `continue` or `return` in the
region, the binding allocates its backing at the product of the trip counts. Those pushes
are a build region: each stores into a local copy of the backing at a local count while the
count is under the reserve, and otherwise writes the count back to `len` and takes the
ordinary growing append, so a wrong count costs a growth, never a wrong answer. After the
region's last statement the count is written back to `len`. A region push touches only its
own fresh list, which nothing else holds and the region never indexes, so it neither blocks
the header hoist nor counts as a call for unrolling (it weighs 16 extra nodes there).

The rest of the gap is the growing append's presence: its writes to the wrapper rejoin the
loop, so the engine reloads what they might have changed. Deleting it trusts the count, which
this row does not; moving it to an out-of-line helper is worth about 7% and is not built.
`filled` itself benefits from binaryen proving `len` constant over the whole module, which a
program that pushes anywhere else loses (`filled` 115 -> 121 ms with one unrelated push-built
`f64[]` reaching the loop; `push` here 132 ms either way).
