### D1517 — `u as? i32 ?? d` over a value union asked an unregistered union row: the cast's `i32 | null` result is a BOX, and nothing in the program spells it

**closed 2026-09-03 by registering the `as?` node's own recorded result type in `scanPrintUse`,
the sibling of the rung [D1041](D1041.md) already put there for a NUMERIC-operand cast · was
`emitProgram: union box atom test on a union with no recorded members: i32|null` on a `vl
check`-clean program · clause 2 · found by the day-one sampler (#2478), `--seed 1 --count 400`,
pairs at lines 3 and 68 · position matrix 54/54 runs after against 2/54 before, `runs ->
not-runs` 0**

Repro (runs, prints `3`):

    type Val = i32 | string
    function mkval(): Val { return 3 }
    function go() {
      const v = mkval()
      print(v as? i32 ?? -1)
    }
    go()

#### Mechanism

`u as? i32` yields `i32 | null`, and that is a value-union BOX: a scalar has no spare null
niche, which is exactly the split `isValueUnionName` already encodes (`boolean | null` and
`string | null` are niches and need no row). The spelling exists NOWHERE else in the program —
no annotation, no `type` declaration, no inferred binding carries it — so `scanPrintUse` is the
only pass that can mint the row, and D1041 put a rung there for precisely that reason.

That rung is gated on `asExprNumFallible`, which **declines a union operand by construction**;
its own header says the two gates are disjoint by OPERAND. So a union-operand `as?` reached
neither rung, the box heap type was never interned, and `emitUnionCoerce`'s promotion ladder
(`unionStoreAtomKind`, entered at i32 and at f64) asked `unionHasAtomTy` about a row that does
not exist — the "cannot happen" that function's header documents, firing on a legal program.

The `??` is what reaches that ladder: `const r = u as? i32` plus a `!= null` test runs at every
scope, before and after. The registration is the node's own recorded type and
`registerValueUnionName` is self-gating, so the niche spellings stay no-ops.
