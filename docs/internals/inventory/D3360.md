### D3360 — `a is U` over a record `P` refuses as "can never match", though `P` is a member of the union alias `U`

**loud check reject · clause 2 · open · the same on master `78abe1318` · found by the #3310 round-2 re-review (`rv3310r2-Q7ZK/x/a4/u1.vl`) · filed 2026-09-30**

Repro:

    type P = {x: i32}
    type U = P | string
    function h(a: P) { print(a is U) }
    h({x: 1})
    // vl check: `is` check type 'U' can never match a value of type P

Want:

    true

#### Mechanism

Not localised past the ablation. The `is` checker's "can never match" test compares the receiver
with the named type as a whole, not with the alias's member set, so a union that holds the
receiver's type reads as disjoint from it. The design owes `true` here, or at most a redundant
test hint, never a refusal.
