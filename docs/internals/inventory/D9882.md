### D9882 — an un-annotated list literal of two functions whose results differ in rep traps when an element is called

**closed · runs, prints `1.5` · was check-clean trap (`indirect call type mismatch`) on the [D9781](D9781.md) candidate, `called value is not a function` on master `ba2918226` · found closing [D9781](D9781.md) · filed 2026-10-22 against master `ba2918226` · closed by adapting each element of a list literal whose element type holds a function to the joined element type (`fvaAdaptListLit`, check_assignable.vl, run from `checkNodeDone`, check_node_rules.vl) · fixture `closures/fn-value-result-widens-to-nullable.vl`**

Repro:

    function n(x: i32): f64[] { return [1.5, 2.5] }
    function z(x: i32): f64[] | null { return null }
    const xs = [n, z]
    const a = xs[0]
    const r = a(1)
    if r != null { print(r[0]) } else { print(0) }

Want:

    1.5

#### Mechanism

Once `n` is assignable to `z`'s type, the literal's element join collapses to the wider
`(i32) => f64[] | null`, while the slot holding `n` keeps `n`'s own `$fnsig`, so the call through
`a` reached it at the wrong signature. Each element is now wrapped in the adapter `fvaAdapt`
builds at a declared slot; a nested literal (`[[z], [n]]`) adapts one level down.

| ingredient removed | outcome | needed? |
| --- | --- | --- |

| the read through a binding (`xs[0](1)` directly) | loud emit reject, [D9880](D9880.md) | no |

#### Grading list

`[n, z]` and `[z, n]` iterated with `for`; `[[z], [n]]`; an element taken from a record field
(`[rec.f, z]`).
