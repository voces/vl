### D15543 — a binding of a nullable record holding a generic function value gets a non-null struct cell, and its `null` traps

**loads then traps · clause 1 · found by the step-7 `letIsStruct` shadow (65 calls disagree, all this class) · filed 2026-11-07 against master `0e2c0ca5`**

Repro:

    function id<T>(x: T): T { x }
    const a = Map()
    a["k"] = { f: id }
    const ar = a["z"]
    if ar != null { print(ar.f(2)) } else { print("none") }
    // vl check: rc 0.  vl run: wasm trap, null reference.  Want: none

#### Mechanism

The binding's type is `{f: (T) => T} | null`. `TyFunc` carries no quantifier, so the generic
function's own `T` reads as an open type variable, and `bindCellGo`'s `tyHasTyVar` guard
declines the typed claim (`letBindRepClaims` false). The cell then falls to
`letInitCellKind`, whose `letIsStruct` rung answers `struct` from the initializer: a non-null
cell, so the missing key's `null` traps. The typed rep is `nulstruct`, which is right. Lifting
the guard at module scope is not the fix: `repSlotOfKind` then picks the `{f:i32}` row, and
the module is invalid wasm.
