### D3063 — a lambda inside a `<T>` instance calls a generic on a captured literal-union value and prints its atom id

**closed · a lambda's capture of an enclosing frame's parameter pins at the instance's substituted annotation · fixture `tests/cases/generics/lambda-capture-literal-generic-call.vl` · was check-clean silently wrong · clause 1 · found by the #3270 review (`rv3270-q7k2/g` `T6_cap_ab__*`) · the same on master `614fe177c` · filed 2026-09-28 against master `614fe177c`, closed 2026-09-28 against master `f14a8cca2`**

Repro:

    type AB = "a" | "b"
    function g<T>(x: T) { const f = () => h(x); f(); f() }
    function h<U>(u: U) { print(u) }
    const v: AB = "b"
    g(v)
    // vl check: rc 0.  vl run: PRINTS 0 then 0

Want:

    b
    b

#### Mechanism

The call `h(x)` sits in a lambda lifted out of `g`'s instance, where `x` is a capture rather
than a parameter, so `monoArgTyName` found no annotation and `h` was cloned at the bare `i32`
atom with no member texts. `monoCapturedParamPin` (`emit_mono.vl`) walks the lambda's
enclosing frames to the one whose parameter the capture names (stopping at a frame that binds
it as a local) and answers that parameter's substituted annotation, the pin the direct call in
`g`'s body already used.

#### Ablation

| ingredient changed | outcome | needed? |
| --- | --- | --- |
| `h(x)` called directly in `g`, no lambda | prints `b` | **yes** (the lambda) |
| a `string` pin | prints `s` | **yes** (an `i32`-shared pin) |
| `h` declared before `g` | prints `0` `0` | no |
