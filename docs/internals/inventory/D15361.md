### D15361 — the function-tag pass tests each written `let` against a list of every written `let`, quadratic in a module's lets

**closed 2026-11-04 · runs today and must keep running · a cost regression, not a wrong outcome: 6.6 G of [D15360](D15360.md)'s self-compile fuel · introduced by #6018 (`e121ddaaa`), whose fixed-source reading is 66.14 G against 59.53 G at the landing before it · closed by holding the written `let`s in a Map (`ftArmOnlyLamsNote`, check_fn_tag.vl) · filed 2026-11-04 against master `17ccaa12e`**

Repro:

    function f(x: i32 | null) {
      if x != null { print(x + 1) }
    }
    f(2)

Want:

    3

The witness is a stand-in: the subject is the L2 build's guest fuel, `VL_FUEL=1 vl build
compiler/entry.vl --compiler <fixpoint seed>`.

#### Mechanism

`ftArmOnlyLamsNote` walks a module once. It records each `let` declaration in `lets`, and each
declaration some store writes in `written`. `written` was an `i32[]`, so `i32ListHas(written, d)`
scanned it once per store into a `let` and again once per declaration. That is O(lets × written
lets) per module, and the compiler's large modules hold thousands of each.

A guest profile on a `--names` seed shows the jump. `i32ListHas` is not in the top 20 at #211
(`68e9c4a0d`). At #213 (`e121ddaaa`) it is third by self time, at 3.87%, and this function is its
only new caller.

Fuel moved more than time: samples rose 1.3% against fuel's 11%, because the scan is a tight
compare loop.
