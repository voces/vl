### D2323 — a map walk's resync compared 31-bit wrapping sequences, so a live entry 2^30 inserts older than the walk read as later

**closed 2026-09-24 — the witness prints `46 6 1 1`. Found in review of #3113 (the D2315 fix)
before it merged, never on master: that candidate kept each entry's insertion sequence in the
low 31 bits of its live flag and compared them as serial numbers, which holds only while every
live entry is within 2^30 inserts of the walk's saved sequence. Fixed in the same PR by an i64
sequence per entry. Fixture `tests/cases/maps/forin-walk-resync-past-an-old-entry.vl`**

Repro:

    const m: {[i32]: i32} = Map()
    m[-1] = -1
    m[-2] = -2
    let k = 0
    while k < 10000 {
      m[k] = k
      if k >= 4 { m.delete(k - 4) }
      k = k + 1
    }
    let visits = 0
    let added = 0
    let seen1 = 0
    let seen2 = 0
    for x in m {
      visits = visits + 1
      if x == -1 { seen1 = seen1 + 1 }
      if x == -2 { seen2 = seen2 + 1 }
      if x != -1 && x != -2 && added < 40 {
        m.delete(x)
        added = added + 1
        m[-100 - added] = x
      }
    }
    print("\{visits} \{m.length} \{seen1} \{seen2}")
    // prints 46 6 1 1

#### Mechanism

`__map_resync__` scanned the entries from 0 for the first whose `(live[i] | 1) - seq` was
positive as an i32. With the permanent keys `-1` and `-2` inserted at sequence 1 and 2, and the
walk's entry past 2^30 inserts later, that difference wraps positive, so the first permanent key
read as later than the walk and every mid-walk compaction sent the walk back to the start. The
Repro above is the witness's SHAPE at 10,000 churn inserts; the defect needs the count below,
which is too slow for the witness grader, so it is kept here and was run by hand:

    // the Repro with `while k < 1073741888` (2^30 + 64), and the walk printing each value;
    // ~45 s under `vl run`
    // the candidate printed  -1 -2 1073741884 … -101 -102 -1 -2 -103 … | 52 6  (revisits)
    // JS Map and the fix     -1 -2 1073741884 … -101 -102 -103 … -136 | 46 6

The review also found the mirror case, a walk that ends early and skips live entries, and that
the `(live[cur] | 1) != seq` moved-check could miss at a difference of exactly 2^31. The fix keeps
`live` a plain 0/1 flag and stores the sequence as an i64 in a `seqs` field (plus a `next`
counter), which no program lives long enough to wrap, compared with `i64.gt_s`.
