### D3431 — a literal binding delivered to a record whose nested record drops a field is refused at emit when the dropped field is read

**loud emit reject · clause 2 · open · identical on master `d0789e90a` · not a width change: an `i32` field into `i32` fails the same way · found by lane RC2 (the anon-struct fixtures' `reInternWidening` shape) · filed 2026-09-30 against master `d0789e90a`**

Repro:

    const sv = { pet: { legs: 4, purr: true } }
    const u: { pet: { legs: i32 } } = sv
    print(sv.pet.purr)
    // vl check: rc 0.  vl run: emitProgram: unknown struct field in field access

#### Mechanism

The literal is built at the destination's shape, which drops `purr` from the nested record
(the "re-intern that widens a field and drops one" the object-shape floor accepts), while the
checker still types `sv` at its own shape, so the read of `purr` names a field the built record
does not have. The annotated twin, `const sv: { pet: { legs: i32 } } = { pet: { legs: 4,
purr: true } }`, is refused by the checker (the literal sets a field the destination does not
declare). The D3339 width adoption declines such a destination (`recNamesDeepEq`), so it keeps
this behaviour rather than refusing a program that ran.

#### Ablation

| ingredient removed | outcome | needed? |
| --- | --- | --- |
| the read of `sv.pet.purr` (`print(u.pet.legs)`) | runs, prints `4` | **yes** |
| the delivery `const u` | runs, prints `true` | **yes** |
| `legs` widened to `i64` | same refusal | no |

#### Grading list

`{ legs: i32 | null }` as the destination field, the same refusal. Whether a fresh literal may
drop a nested field at all is the object-shape floor's question: refusing at the checker would
refuse `anon-struct-declared-nested-row-not-captured.vl`'s `reInternWidening`, which runs.
