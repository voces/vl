### D17125 — a null test of a module `const` of a map read, in a function declared before it, takes no null-test arm and refuses at emit

**closed 2026-11-26 by SOUND · runs, prints `true`, on master `33bbecca` and after · was a loud emit reject, clause 2 · found closed by the witness sweep of D16819's proof; the change that closed it was not bisected (coordinator ruling) · pinned by `tests/cases/maps/null-test-of-map-read-const-before-decl.vl`**

Repro:

    const m = Map()
    m["a"] = { v: 1 }
    function has(): boolean { return x != null }
    const x = m["a"]
    print(has())
    // vl check: rc 0.  vl run: "emitProgram: struct equality is not supported yet" at `x != null`

Want:

    true

#### Mechanism

The checker types `has`'s body before it reaches `const x`, so the read of `x` keeps an open
`_ | null`. Its rep is then no nullable ref (`nodeRepIsNullRef` is false), so `nulTestArmOf` falls to
`instMap`, `nulTestClaims` declines, and `!=` goes to the generic compare, which refuses a record and
has no core for a closure. Declared after `x`, the same function takes the `nullRef` arm and runs; an
annotated map types the read and keeps legacy's read-before-init trap. A holder of a record of
members takes the `nullRef` arm by its holder fact instead (D17111's rung), so only plain values reach
this.

#### Ablation

| ingredient removed | outcome | needed? |
| --- | --- | --- |
| the function's position (`has` declared after `const x`) | runs, `true` | **yes** |
| the un-annotated map (`const m: {[string]: R} = Map()`) | runs; read before its initializer, traps as any global | **yes** |
| the call order (`print(has())` before `const x`, `has` after it) | runs or traps as filed by the position | no |
| the record value for a closure (`m["a"] = (a: i32): i32 => a + 1`) | still refuses ("no compare core") | no |

#### Grading list

- Both values (a record, a closure), each with `has` called before and after `x`'s initializer.
- A FREE follow-up: take the `nullRef` arm for a read whose binding's own type, once checked, is a
  nullable ref, whatever the read's earlier open type.
