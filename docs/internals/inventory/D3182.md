### D3182 — a hole parameter whose body null-tests a function field calls a second record's non-nullable field function at the first record's nullable type, or refuses it

**check-clean silently wrong · clause 1 · the second face is a loud emit reject (clause 2) · pre-existing, the same on master `995bbc74e` and `a6cb22568` · found by the #3285 review (`rv3285-2112/p/x2.vl`) · filed 2026-09-29 against master `a6cb22568`**

Repro:

    function F(z) {
      print(z.v)
      const g = z.f
      if g != null { print(g()) }
    }
    const a: { v: i32, f: (() => i32) | null } = { v: 1, f: () => 2 }
    F(a)
    F({ v: 5, f: () => true })
    // prints 1, 2, 5, then 1

Want:

    1
    2
    5
    true

#### Mechanism

Not localised past the ablation. The second call's literal has a plain `() => boolean` for `f`,
and the body null-tests `g`. Where the literal's data fields match `a`'s (`v: 5`), the call runs
but prints `true` as `1`, read at the `i32` result of `a`'s `(() => i32) | null`. Where they
differ (`v: "s"`, the second face), the `g != null` test is lowered against the `null` literal
with no struct-typed context and refuses. The first instance, whose `f` is nullable, runs
alone.

Second face (`rv3285-2112/p/x2.vl`), a loud emit reject:

    function F(z) {
      print(z.v)
      const g = z.f
      if g != null { print(g()) }
    }
    const a: { v: i32, f: (() => i32) | null } = { v: 1, f: () => 2 }
    F(a)
    F({ v: "s", f: () => true })
    // vl check: rc 0.  vl build: emitProgram: bare null needs a struct-typed context

#### Ablation

| ingredient changed (from the repro) | outcome | needed? |
| --- | --- | --- |

| second face with the first call removed | same refusal | no (for the second face) |
| second face with `a`'s `f: () => i32` (not nullable) | same refusal | no (for the second face) |
