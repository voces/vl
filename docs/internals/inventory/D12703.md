### D12703 — a `for` loop with a named index over hole functions, its variable called at two function types, is refused

**loud emit reject · `vl check` rc 0 · clause 2 · CAPABILITY: the same loop without the index runs ([D10791](D10791.md)) · found closing [D10791](D10791.md) · filed 2026-10-25 against master `a448ccb42`**

Repro:

    import { toString } from "std:fmt"
    function cat(a, b) { return a + b.toString() }
    function snd(a, b) { return b }
    function apply2(g) { print(g("x", 2)) }
    function apply3(g) { print(g("y", 20)) }
    const fs = [apply2, apply3]
    for f, i in fs {
      f(cat)
      f(snd)
    }
    // vl check: rc 0.  vl run: emitProgram: a function this call reaches through a list or join is already taken at another function type by an earlier call through it

Want:

    x2
    2
    y20
    20

#### Mechanism

D10791's close points a call at another type at the type's copy read at the loop's index, and
names that index itself only when the loop names none (`fsLoopLanes`, fn_split.vl). A loop that
names `i` declines, because the body may declare another `i` between the loop and the call.
