### D15742 — a function field written into a two-level maker's record and called at two types is refused at emit

**closed 2026-11-11, runs and prints `2` `2.5` · was loud emit reject, clause 2, `cannot take the generic function \`id1\` as a value — a function value carries ONE signature` · found grading w315's emit-reject grouping (cell `d15270_two_level`) · closed in the check: a binding a call initialises reads the records that call returns through the calls it returns (`holeSlotCallRetsDeep`, check_relate_core.vl, in `checkLetDeclNodeIn`'s D15270 arm, check_statements.vl), so `letCallFieldsWiden` widens its function field to the written set as it does one maker deep · three maker levels run too · fixture `tests/cases/closures/fn-record-from-two-level-maker-field-written-two-types.vl`**

Repro:

    function id0(a) { return a }
    function id1(a) { return a }
    function mk() { return { f: id1 } }
    function mk2() { return mk() }
    const r = mk2()
    r.f = id0
    print(r.f(2))
    print(r.f(2.5))

Want:

    2
    2.5

#### Mechanism

The D15270 arm seeded the binding with the one call's returned values (`holeSlotCallRets`). With one maker level (`const r = mk()`) it runs; the maker's record holds the
field's set. Through `mk2`, which returns `mk()`, the write `r.f = id0` meets a record built
as a closure of `id1` at one signature.
