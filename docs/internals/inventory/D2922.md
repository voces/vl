### D2922 — an element of a re-seated record list returned by an inferred-return function is handed on at the literal's own record

**closed by design · now a loud check reject · was a loud emit reject (`rsRetCallUse`), before that check-clean invalid wasm · `il` adopts `I[]`, so `g()` returns an `I` and `show(g())` is refused as its annotated twin's is · fixture `tests/cases/soundness/error-reseated-record-list-element-returned.vl` · closed 2026-09-30**

Repro:

    const i: { f: i32 } = { f: 4 }
    type I = { f: i64 | null }
    function show(r: { f: i32 }) { print(r.f) }
    const il = [{ f: 7 }]
    const ic: I[] = il
    function g() { return il[0] }
    show(g())
    print(ic[0].f)
    // vl check: rc 0.  vl run: invalid module in the top-level code

Want:

    7
    7

#### Mechanism

D2881 builds `il` at `I`'s row. `g`'s return is inferred from `il[0]`, so it returns the `I`
record, while the checker types the call `{ f: i32 }`, and the call result is passed to `show`'s
`{ f: i32 }` parameter unconverted. D2914's refusal follows the list and its element through
bindings, loops and direct deliveries in the list's own scope, but not through a function's
inferred return into that function's callers, so this one stays silent.

#### Ablation

| ingredient removed | outcome | needed? |
| --- | --- | --- |
| the adopting binding (`const ic: I[] = il`) | runs, prints `7` | **yes** |
| the hand-on (`print(g().f)` instead of `show(g())`) | runs, prints `7` `7` | **yes** |

#### Grading list

The same with `const q = g()` then `show(q)`.

An element chosen by an `if` join and handed on is the same shape one hop shorter, and invalid
the same way on master `a41bd80e8`: `const e = if true { il[0] } else { il[0] }` then `show(e)`.

#### Close

The walk now treats an un-annotated function that returns the element, other than the one
binding the list, as a further name: each call of it is a use of the element. So `show(g())`,
`const q = g()` then `show(q)`, and an `if` join of elements handed on are refused, and
`print(g().f)` still runs. The storage is `I` and the use needs `{ f: i32 }`, so the row stays
open under clause 2 with D2914.

#### Record covariance (2026-09-30)

The destination stores a numeric field at another width or kind, so under the record-covariance ruling the literal-holding binding or function is not adopted and the program keeps its master behaviour until the owner rules on [D3339](D3339.md) (DECISIONS.md "Record covariance: only a fresh value widens").

#### Close under the D3339 ruling (2026-09-30)

Closed by the owner's ruling D3339 (A): a literal-holding binding adopts a record that stores a number at another width or kind, fully (DECISIONS.md "Record covariance: only a fresh value widens"). `il` adopts `I[]`, so `g`'s inferred return is `I` and handing it to a `{ f: i32 }` parameter is the annotated twin's refusal, with a note naming the adoption. `print(g().f)` runs and prints `7`.
