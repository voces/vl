### D2922 — an element of a re-seated record list returned by an inferred-return function is handed on at the literal's own record

**check-clean invalid wasm · clause 1 · the same on master `a41bd80e8` · found closing D2914 · filed 2026-09-27 against master `a41bd80e8`**

Repro:

    const i: { f: i32 } = { f: 4 }
    type I = { f: i64 | null }
    function show(r: { f: i32 }) { print(r.f) }
    const il = [{ f: 7 }]
    const ic: I[] = il
    function g() { return il[0] }
    show(g())
    print(ic[0].f)
    // vl check: rc 0.  vl run: invalid module in the top-level code

Want:

    7
    7

#### Mechanism

D2881 builds `il` at `I`'s row. `g`'s return is inferred from `il[0]`, so it returns the `I`
record, while the checker types the call `{ f: i32 }`, and the call result is passed to `show`'s
`{ f: i32 }` parameter unconverted. D2914's refusal follows the list and its element through
bindings, loops and direct deliveries in the list's own scope, but not through a function's
inferred return into that function's callers, so this one stays silent.

#### Ablation

| ingredient removed | outcome | needed? |
| --- | --- | --- |
| the adopting binding (`const ic: I[] = il`) | runs, prints `7` | **yes** |
| the hand-on (`print(g().f)` instead of `show(g())`) | runs, prints `7` `7` | **yes** |

#### Grading list

The same with `const q = g()` then `show(q)`, and with `g` returning the list (`il`) and a
caller indexing it.
