### D3308 — a computed-index or aliased write later in a loop body does not end an earlier read's path narrowing on the next iteration

**now a loud check reject, the refusal the design owes, 2026-09-29 (`loopWriteMayReach` in `compiler/typecheck.vl`: a loop's write to a prefix of the key, to a cell of its receiver at a computed index, or to a same-named last step through another receiver retires the path before the loop) · was check-clean, trapping at run time on master, clause 1 · filed against master `e70102886` · fixture `tests/cases/unions/error-flow-join-kill-any-path.vl`, hazards `loop_computed_index*`, `loop_alias_field` in `scripts/flow-narrowing/join-hazards.py`**

Repro:

    function nn(v: i32): i32 | null {
      if v < 0 { return null }
      return v
    }
    function f(k: i32): i32 {
      const a: (i32 | null)[] = [nn(k)]
      let s = 0
      let i = 0
      a[0] = 7
      while i < 3 {
        s = s + a[0]
        a[i % 1] = null
        i = i + 1
      }
      return s
    }
    print(f(-1))
    // was: vl check rc 0, then a value was not an instance of the type it was narrowed to
    // now: operator '+' is not defined for i32 | null and i32 at `s + a[0]`

#### Mechanism

Before a loop, `crLoopPathPreRetire` ends each live path narrowing some write in the body may
leave, since the reads before that write run again. `crLoopLeavingPathWrite` matched a write
only by its exact key, so `a[i % 1] = null` (no key) and `q.v = null` through an alias of `a`
passed unseen, and the second iteration read `a[0]` as the narrowed `i32`. A write that may reach
the key, and whose value may leave the narrowing, now counts; an unknown value counts as leaving.
A write through another receiver reads that place's declared storage type: the first cut read
the narrowed storage type, found none on the other receiver, and so ended the narrowing for any
value, which refused `bs[0].v = 4` in a loop over `a.v` even for the reads below the loop that
master ran (#3304 round 4 review, fixture `flow-join-write-after-retire.vl`).
