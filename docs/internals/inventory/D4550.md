#### Mechanism

DECISIONS.md A-infer-null makes `null` a type of its own (an unconstrained `let x = null`
resolves to it), so the checker accepts it wherever a type is written. The emitter already had
a rep for a value statically known to be `null` — `nulnone`, the GC bottom `nullref` — but
reached it only from inference: an annotated parameter, binding, return or global classified
from its annotation, which named no `T` to choose a rep from, and a generic called with a bare
`null` was not pinned at all. `checkParams` refused the parameter by name; the other positions
reached older floors (`bare null needs a struct-typed context`).

The close routes every annotation spelling `null` (`annRepKindOf`, `letIsNulNone`,
`retAnnKindChain`, the argument and return seeds) and a `null` pin (`monoArgPinName`) to
`nulnone`, and resolves `a ?? d` in a body pinned at `null` to `d`'s type, as the concrete `??`
already does — the value classifiers (`exprUnion`, `exprIsF64`/`I64`/`F32`) answer about the
default for the same reason `exprString` did.
