### D4550 — the `null` unit type alone has no value rep in any position

**loud emit reject · 1 probe (`scripts/capability-probes/null-unit-type-parameter.vl`) · filed 2026-10-13 against master `eb2603843`**

Repro:

    function f(x: null) { print(x == null) }
    f(null)
    // vl check: rc 0.  vl run: emitProgram: a parameter of type `null` is type-valid but has no lowering yet

#### Mechanism

DECISIONS.md A-infer-null makes `null` a type of its own (an unconstrained `let x = null`
resolves to it), so the checker accepts it wherever a type is written. Every value rep the
emitter builds is chosen from a non-null type: `T | null` rides a niche or a nullable ref of
`T`'s rep, and with no `T` there is nothing to choose. `checkParams` refuses the parameter by
name; the other positions reach older floors with the same cause.

#### Ablation

| spelling | outcome |
| --- | --- |
| `function f(x: null)` / `(x: null) => 1` / `type N = null` param | emit refuse (`checkParams`) |
| `const x: null = null` · `function f(): null` · `null \| null` param | `bare null needs a struct-typed context` |
| a struct field `a: null` | `struct field type \`null\` has no struct-field rep` |
| `x: i32 \| null` | runs |

#### Grading list

Close every position in the ablation together (parameter, binding, return, field) — a rep for
one position alone turns the others' loud refusals into silent invalid wasm. Grade with a
`capability-matrix.vl` template whose value type is `null`.
