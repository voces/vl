### D1674 — an anonymous literal is keyed against a DECLARED inline-shape row without its element, so an annotated holder and an inferred one still share one row

**loud emit reject · filed 2026-09-06 against master `bce33eae0` · D1689's residue: the same

Repro:

#### Mechanism

`structIndexOfObjCtxGo` scans EVERY struct row for a field-name and field-code match, declared
rows included. D1689 gave the match an element test, but only against an `#anon` row —
`anonValueFitsField`'s composite arms have always been anon-only, because a declared field's
code can differ from the value's through adoption and boxing. So the annotation on `one`'s
holder mints a declared `{xs:A[]}` row that `two`'s inferred literal still lands on, and the
element column is read off the wrong holder exactly as before.

The element comparison the declared side needs is the one `structRowOfObjFieldSet` already
runs on the type side (`fieldElemDeclConflict`): nominal, refutation-only, and a preference
rather than a veto. Dropping the `anonRow` guard and comparing the two names textually is not
it — measured 2026-09-06 on D1689's ref-list arm with the guard removed, that moves 19 of
3,046 `tests/cases` modules, four of them from building to a compiler trap (exit 70), because
a declared row spells its element while a minted one names a row, and the two spellings need
not agree.
