### D3061 — a list literal of a hole instance's local refuses at a scalar pin when the instance is reached through another function's call

**closed 2026-09-28 — the filed repro prints `p` · was a loud emit reject, clause 2, the same on master `6c2dafc0b` · found by lane GF's forwarding grid (`alias` and `local` cells at the `string` and `f64` pins, hole spelling, depth 2 to 4) · closed by reserving the scalar list pair from the element's hole pin in the per-frame collection walk (`collectHoleElemListPair`): the rungs there name a local's rep from the locals table, which does not exist when collection runs · fixture `tests/cases/generics/hole-local-list-through-forwarder.vl` · filed 2026-09-28 against master `6c2dafc0b`**

Repro:

    function f2(x) {
      const y = x
      const s = [y, y]
      print(s[1])
    }
    function f1(x) { f2(x) }
    const v: string = "p"
    f1(v)
    // vl check: rc 0.  vl run: emit error, string array literal but string list type not collected

Want:

    p

#### Mechanism

`collectArrNewFrames` decides, per instance, which scalar list a literal builds, through
`arrLitIsStr`/`arrLitIsF64`, whose identifier rung for a local asks the locals table
(`declaredString`). Collection runs before any function's locals are declared, so a literal whose
first element is a local of a hole-typed value reserves no string list, and `emitArrLit`, which
asks the same question once the table exists, refuses the list it cannot build. Reached directly,
another collection site reserves the pair; reached through a forwarder, nothing does.

#### Ablation

| ingredient changed | outcome | needed? |
| --- | --- | --- |
| `f2(v)` called directly, no `f1` | prints `p` | **yes** (the forwarding) |
| `const s = [x, x]`, no local | prints `p` | **yes** (the local) |
| `const y = g(x)` for a hole identity `g` | refuses the same | no |
| `function f1<T>(x: T)`, an explicit forwarder | refuses the same | no |
| an `i32` or a literal-union pin | prints `4` / `b` | **yes** (a non-`i32` scalar list) |
| an `f64` pin | `f64 array literal but f64 list type not collected` | no |
