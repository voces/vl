### D2557 — a value-position widening write to a binding a closure shares is refused as "only an identifier assignment"

**closed 2026-09-25 for a scalar cell — the filed repro RUNS and prints `10` / `7` · a nullable cell (`f32 | null`, `i32 | null`) is still refused, grading list · was a loud emit reject, clause 2 · pre-existing, identical on master `039fd6832` · found by #3169's review · filed 2026-09-25**

Repro:

    function main() {
      let a: f64 = 0.0
      function k(): i32 { 3 }
      function h(p: i32, q: i32) { p + q }
      const cl = () => { print(h(k(), a = 7)) }
      cl()
      print(a)
    }
    main()
    // vl run (master): emit error, emitProgram: only an identifier assignment is a value expression

#### Mechanism

A binding a closure writes is a shared cell, so the closure's `a = 7` is rewritten to the cell's
slot `a[0] = 7`. A value-position write that stays in place lowers as store-then-re-read, and
`assignTargetReReads` admitted an element target only when its read type equals the value's, so a
widening write fell through to the refusal. A cell slot is its binding: it now re-reads whenever
`asgReadUnwidenOp` can take the cell's rep back to the right side's, as [D2530](D2530.md) does
for the binding itself. Sibling of D2441.

#### Ablation

| ingredient removed | outcome | needed? |
| --- | --- | --- |
| `a: i32` (no widening) | ran on master | **yes** — a widening write |
| the call before it (`h(3, a = 7)`) | ran on master | **yes** |
| the write outside the closure | ran on master | **yes** — a shared cell |
| `a: f32 \| null` or `i32 \| null` | still refused | open: the cell's re-read is not narrowed to its member |

#### Grading list

* `let a: f32 | null = null` and `let a: i32 | null = null` in the same shape: still a loud emit reject.
