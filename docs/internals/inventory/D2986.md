### D2986 — a record literal whose field is only `null` gets no struct row, annotated or not

**loud emit reject · clause 2 · found by lane RW's record-literal grid · filed 2026-09-28 against master `4dc94bd23`**

Repro:

    const r = { f: null }
    print(r.f)
    // vl check: rc 0.  vl run: emitProgram: ref valtype with no interned shape

#### Mechanism

Not localised past the ablation. `{ f: null }` is checked as `{f: null}`. No row is minted for
it; the likely rung, not yet confirmed by a probe, is the anonymous-row mint, which codes each
field from its value and declines a field with no code, which a bare `null` may be. The annotation `{ f: null }`
interns nothing either. Beside an annotated `{ f: i32 | null }` record, the literal builds at
that row and prints `null`. Beside annotated records of other field types, the refusal becomes
`bare null needs a struct-typed context` (30 cells of the grid's `trio_*_un` family, all loud
on master too).

#### Ablation

| ingredient removed | outcome | needed? |
| --- | --- | --- |
| the read (`print(1)`) | same refusal | no |
| the missing annotation (`const r: { f: null } = { f: null }`) | same refusal | no |
| a second field (`{ f: null, g: 1 }`, reading `r.g`) | same refusal | no |
| module scope (the binding inside a function) | refuses: `object literal but no struct type declared` | no |
| no `{ f: i32 \| null }` record in the module | adding one: runs, prints `null` | **yes** |

#### Grading list

`const r0: { f: i32 } = { f: 3 }` then `const r1 = { f: null }` and both reads, which refuses
`bare null needs a struct-typed context`; the same beside `{ f: boolean }`, `{ f: i64 }`,
`{ f: f32 }` and `{ f: string }`.
