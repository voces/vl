### D3095 — a generic callback taker given an un-annotated named function has no pin for the function argument

**loud emit reject · clause 2 · found by the #3271 review · the same on master `505bb44e0` · filed 2026-09-28 against master `505bb44e0`**

Repro:

    function app<T>(x: T, f: (T) => boolean): boolean { return f(x) }
    function g(w) { return w is i64 }
    const z: (string | i64)[] = [5, "t"]
    for e in z { print(app(e, g)) }
    // vl check: rc 0.  vl run: emitProgram: monomorphize: unsupported argument type for `f`
    // in a call to `app`

Want:

    true
    false

#### Mechanism

Not investigated past the ablation. `monoArgFnTypeName` names a function argument by its
signature, and a named function whose parameter is an inference hole has no signature until
an instance is pinned, so the arrow parameter `f: (T) => boolean` gets no pin.

| ingredient changed | outcome | needed? |
| --- | --- | --- |
| a lambda `(w) => w is i64` in place of `g` | runs ([D3072](D3072.md)) | **yes** (a named function) |
| `g`'s parameter annotated `w: string \| i64` | runs, prints `true`, `false` | **yes** (the hole) |
