### D3197 — a hole or generic body calls a record's nullable function field at a pin that admits `null`, which the direct spelling refuses

**loads then traps · clause 1 · open, needs a ruling (the refusal costs `runs`) · pre-existing, the same on master `2771214c7` · found by the RF4 lane while grading D3192 · filed 2026-09-29 against master `2771214c7`**

Repro:

    type R = { v: i32, f: (() => boolean) | null }
    function F(z) { print(z.f()) }
    const r: R = { v: 7, f: null }
    F(r)
    // vl check: rc 0.  vl run: wasm trap, null reference

#### Mechanism

The direct spelling, `function F(z: R) { print(z.f()) }`, refuses `called value is not a
function ((() => boolean) | null)`. A call through a hole (`checkCallNode`'s `TyVar` arm) mints
an `HD_RET` hole and records no constraint, so the re-check at the call's argument types never
asks whether the pin is callable, where a member read of a `string | null` pin is refused
(`memCstrTy`). A candidate records the call as a `memCstrTy` row (prop `()`, refusing in the
direct spelling's words) and turns this witness loud. On the RF4 grid (nine result types x
nullable x hole/generic x literal/bound/two instances x declared/anonymous record, 270 cells)
it moves 72 cells to that refusal, and **40 of them ran** before: a bound `R` whose `f` holds a
function, called through the hole. Each is ill-typed at its direct spelling, and a sibling
holding `null` traps, but the lane's bar is 0 runs lost, so it is not shipped. Question: should
a pin's re-check refuse a call through a `| null` function, as it refuses a member read of a
`| null` pin? Recommendation: yes, it is the direct spelling's rule, and the 40 cells are
unsound runs.
