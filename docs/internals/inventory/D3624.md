### D3624 — a fallible numeric cast over an un-annotated lambda parameter lowers with no range test

**fixed 2026-10-04 — the filed repro loads then traps, `as! u8 at 1:24: not exact`, the ruled outcome the generic spelling has · was check-clean silently wrong, printing 300 · clause 1 · found 2026-10-04 by the review of D3622 · filed 2026-10-04 against master `7eeb9e8c3` · fixtures `tests/cases/numerics/as-trap-hole-lambda.vl`, `as-trap-hole-receiver.vl`, `error-as-cast-hole-lambda-propagates.vl`**

Repro:

    const k = (x) => x as! u8
    print(k(300))
    // vl run: traps, as! u8 at 1:24: not exact

#### Mechanism

Two halves, one per mode. The emitter's hole-cast lowering (`asExprHolePinSrc`) read the
operand's pin only through `exactOperandTyOf`, the GENERIC instance's substitution; an
un-annotated parameter is pinned through the hole table instead, so the read answered -1 and the
cast fell to the plain conversion. It now reads `instanceOperandTyOf`, which asks the exact pin,
the hole pin and the lifted pin in turn, so `as!` takes the range test at every hole pin. The
checker's half: a parked cast is re-asked at the call that pins the hole (`holeCastPinCheck`),
but only a call to a declared function named the parameter, so a lambda bound to a `const` and a
method receiver never re-asked it and a bare `as` printed the unconverted value. The lambda's
parameter list is now read through `cwCalleeDeclOf`, and the receiver pins `self` as an argument
does. `as?` over a hole stays a loud emit reject at every position: [D3654](D3654.md).
