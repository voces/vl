### D1244 — a closure capturing a ref local declared in a MODULE-SCOPE block is `emitProgram: field access receiver is not a struct`; the identical block inside a function runs

**closed — `parentBindingOf` resolves the MODULE frame's block-locals (`moduleLocalLetOf`), so a capture of one is typed off its own binding instead of `captureValKind`'s i32 default · was a loud emit reject at check rc 0, clause 2, with three cells check-clean invalid wasm beside it · ZERO corpus cells · found 2026-09-02 by the position-matrix harness (#2415), closed 2026-09-03**

Repro (runs, prints `7`; before the close it refused, while the identical block wrapped in
`function go() { … }` already ran):

    type P = { x: i32 }

    if true {
      const p: P = { x: 7 }
      const f = () => p.x
      print(f())
    }

**THE RUNG AND THE FIX.** `parentBindingFrameOf` walks `fnParent`, and a lambda written at
module scope (or in a top-level block) has `fnParent == -1` — the module's top level is not
a lifted frame. So `parentBindingOf` returned -1, `captureValKind` fell to its `"i32"`
default, and `captureValStructIdx` to -1: the env FIELD was typed i32 whatever the capture
held. `moduleLocalLetOf` (`emit_base.vl`, built by the same walk as `moduleBindsLoopVar`)
answers the module frame's BLOCK-locals — deliberately not its top-level `LetDecl`s, which
are globals and are never captures — and `parentBindingOf` consults it where the frame walk
runs off the chain. `parentBindingFrameArenaOf` already returns -1 for the module frame,
which IS the `fnIx` the start function classifies under, so the un-annotated arm's
`letInitCellKind` resolves in the right scope with no second conversion.

**GRADED, 152 cells over {8 reps} × {`if`, `while`, `for`, bare, nested} × {annotated,
inferred} × {captured, plain read}, plus the field WRITE, a closure-in-closure, a closure
ESCAPING the block to a module global, and four controls. Before: 84 RUNS · 45 SILENT · 23
loud emit reject. After: 152 RUNS, every one printing the right value, 0 runs lost.** All
three of this row's named silent cells are in it. The three `matrix/module-block-capture-*`
templates each moved 32/38 → **38 of 38 graded · 0 silent · 0 other**.

**AND THE LOUD MESSAGE WAS ONE OF TWO LAYERS.** With the capture typed, the matrix cells
(which BIND the capture to a local inside the closure and call the closure as a STATEMENT)
turned SILENT rather than running: a closure BOUND in a module-scope block resolved no
`$fnsig` either, so a void one was `drop`ped at its call. That is [D1350](#d1350), it
reproduces with no capture at all, and it is fixed in the same change.

The pre-close observations, kept because they are what the close had to re-grade:

* **IT IS NOT "A BLOCK" — IT IS A BLOCK WHOSE ENCLOSING SCOPE IS THE MODULE.** The same `if`
  body one level inside a function RUNS, and so does an `if` inside a `while` inside a
  function. At module scope every block kind refuses: `if`, `else`, `while`, `for`, and a
  bare `{ … }`. Two module-scope blocks nested inside each other refuse too. The reported
  headline ("the block scope is the ingredient") is half of it; the other half is that a
  function body already fixes it.

* **THE CAPTURE IS LOAD-BEARING AND SO IS THE LOCAL'S SCOPE.** Reading `p.x` in the block
  with no closure runs. Passing `p` to the closure as a PARAMETER runs. A closure declared in
  the block capturing a MODULE-scope `p` runs. Only capturing a local *declared in that
  block* refuses.

* **AND IT IS EVERY REF REP, WITH TWO OF THEM SILENT.** A captured `i32` runs. A captured
  struct is this row's loud refusal on a field READ, and `emitProgram: field-assignment
  receiver is not a struct` on a field WRITE. A captured `i32[]`, a captured `string`, and a
  struct merely PASSED THROUGH the closure to a function are all **check-clean invalid
  wasm** — and all three RUN when the same block is inside a function. Those are the cells
  this row's close has to re-grade; they are named here rather than filed as a message group.
