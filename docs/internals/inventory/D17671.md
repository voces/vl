### D17671 — D17666's list of hole-function records, built by a maker, still writes the maker's record at a row its list does not lay elements out at

**check-clean invalid wasm · 2 spellings, D17666's grading list · filed 2026-11-26 against `cov-call-listplace` (lane COV-CALL), split from D17666 when its literal spelling closed**

Repro:

    function inc0(a) { return a + 1 }
    function dbl(a) { return a * 2 }
    function mk() { return { r: { f: inc0 }, s: { f: dbl } } }
    const xs = [mk()]
    print(xs[0].r.f(6))
    // vl check: rc 0.  vl run: invalid module inside `mk`, type mismatch: expected (ref $type), found (ref $type)

Want:

    7

#### Mechanism

D17666's literal spelling closed when a list place and its element reads took the ref-list slot's
row (`rowRep`). A maker's record is built and returned at the maker's own result row, which is
not the row the list lays elements out at. The IR declines the return with `convert record ->
record`, because no retag joins the two rows. This is the records part of the "place reads at
storage" series: the value built for the list takes the list's row.
