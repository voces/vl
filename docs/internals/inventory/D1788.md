### D1788 — a STRUCT at the template's pin leaves the instance reading the TEMPLATE's return kind, because most of the return-kind reader family takes a bare sid with no frame

**closed 2026-09-06 — D1781 converted two readers of a family of twelve, and the other ten answer the same question at the same index space · filed against master `be5a79fd2`, closed against `053e9e853` + `#2796` · 3 cells of the 264-cell nested-capture matrix, and 46 more the grid had not named · 0 corpus cells**

Repro:

    function o(n) {
      function k(x: i32) { return n }
      return k(1)
    }
    print(o({ a: 9 }).a)
    print(o(2))
    // vl check: rc 0.  vl run: rc 0, prints 9 / 2

#### Mechanism

The mirror of [D1781](D1781.md) one index space over. That row converted the scalar and
list readers to `fnIndexOfInScopeSid`; the STRUCT readers (`fnRetStructSid`,
`fnRetStructIndexSid` and their nullable and variant siblings) take a bare sid with no frame
argument, so the instance keeps reading the template's `"struct"` kind and its struct-table
row. It shows only when the struct is the TEMPLATE's pin: with the struct at the instance's
pin the instance is the one that needs the ref kind, and its own return expression supplies
it. Annotating the outer return (`o<T>(n: T): T`) fixes it, because the annotation names the
substituted type instead of the inferred one.

One of the three cells is a price [#2796](https://github.com/voces/vl/pull/2796) paid rather
than found: the un-annotated nested parameter spelling (`function k(x) { … }`) was an emit
refusal behind B15's generic-value floor and became check-clean invalid wasm once the floor no
longer fired on a direct call. It RUNS at this close, so the price is repaid.

#### Close

The row named the struct readers; the family is TWELVE, and D1781 had converted two.
`fRetKind` is one column read by one reader per return kind, and every one of them asked
`fnIndexOfSid` — the flat lookup that always answers the template. Each now takes the calling
frame and resolves through `fnIndexOfInScopeSid`, which is what D1781 did for `list` and the
scalar and what the other ten needed for the same reason:

    nulstruct  nulstr  str  strlist  map  union  reflist  variant
    refListName  nulRefListName  struct  structIndex

Each had exactly ONE call site, all of one shape, and all inside a classifier that already
carried `fnIx`. The struct pair is the row's own witness; the string-backed ones are why the
grid held 46 silent cells rather than 3.
