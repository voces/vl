### D8220 — a wrapper returning a direct call of a function widening `i32` to `f64` is accepted at an `i32` binding

**check-clean invalid wasm · filed 2026-10-20 against master `be738c9f0` · clause 1, present on master**

Repro:

    function half(a) { return a / 2.0 }
    function w(x) { return half(x) }
    const r: i32 = w(3)
    print(r)
    // vl check: rc 0.  vl run: the emitted module failed to validate: type mismatch: expected i32, found f64

#### Mechanism

D8161 takes a direct call's result from the callee's body at the bound arguments
(`holeLamRetAt`). `w`'s body re-derived at `i32` reaches `half(x)`, a direct call inside a
body, and `holeCallNodeTy` (`check_relate_core.vl`) answers it with the call's recorded type
`T` rather than re-deriving `half` at `x`'s bound `i32`. The close is there, outside lane
L1b's file boundary.

#### Ablation

| ingredient removed | outcome | needed? |
| --- | --- | --- |

| the `: i32` on `r` | runs, `1.5` | **yes** |
| `a: i32` on `half` | check refuses | **yes** |

#### Grading list

`function w(x) { return half(x) + 0.0 }` and a `const` lambda wrapper `(x) => half(x)`.
