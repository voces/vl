### D2724 — a shift count that is a `const` name, not a literal, is taken modulo the width with no refusal

**check-clean silently wrong · clause 1 · found in the #3201 review (h01) · identical on master
`74bd044d7` · filed 2026-09-26 by lane PL47**

Repro:

    const K = 40
    const a: i64 = 1 << K
    print(a)
    // PRINTS 256

#### Mechanism

Not yet measured. D2710 refuses a literal count at or above the operand's width, and D2709 lets a
tree of literals take an `i64` destination; both read the literal's digits, and a `const` name is
neither. So `1 << K` is an `i32` shift (the left operand's own type) whose count wraps modulo 32,
and the result is widened. The checker keeps no constant-value scope (D1588 declined one for the
range fold), so the fix needs either that scope or a ruling that a `const` count is a computed one.

#### Ablation

| ingredient changed | outcome | needed? |
| --- | --- | --- |
| `K` → the literal `40` | `1099511627776` (D2709) | **yes** (a name, not a literal) |
| `1` → `(1 as i64)` | `1099511627776` | **yes** (an i32 left operand) |

#### Grading list

`const K = 40` then `print(1 << K)`, which must refuse as `print(1 << 40)` does, or be ruled a
computed count.
