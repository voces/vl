### D3408 — an arm tail `z ?? nf()` over a never-filled `null` binding, joined into a record-filled binding, builds invalid wasm

**closed · now runs, prints `a`, `nf`, `7` · was check-clean invalid wasm, clause 1 · the #3315 review's `x.vl` (there `z ?? z ?? nf()`) · filed 2026-09-30 against master `8df60e472` · closed 2026-11-01 against master `4f10ded8`: the `??`'s block was typed non-null because its default, a call whose type is `null` itself, did not count as nullable; it now does (`coalesceDefaultNullable`, emit_classify.vl) · fixture `soundness/coalesce-null-binding-with-null-call-default-filled-later-runs.vl`**

Repro:

    function nf() {
      print("nf")
      null
    }
    function t(n: i32) {
      const z = null
      let w = if n == 1 { print("a") z ?? nf() } else { print("b") null }
      w = { x: 7 }
      print((w ?? { x: 9 }).x)
    }
    t(1)
    // vl check: rc 0.  vl run: invalid module inside `t`: type mismatch: expected (ref $type), found nullref (exit 70)

Want:

    a
    nf
    7

#### Mechanism

Measured at the close: `z ?? nf()` lowers as a `br_on_non_null` block whose result is non-null
unless the default is nullable, and `nf()`'s type `null` was not counted, so the default's
`ref.null` met a `(ref $S)` block. The note below was the filing's.

Not traced. `z` is a `null` binding nothing fills, so every link of the chain is `null`-typed
and the join is the `null` type, which a `nf() ?? nf()` tail lowers correctly since D3355's
close. With `z` read on the left the module fails to validate, on master and after the close, as it
does for `z ?? z ?? nf()`; the same tail with an `i32` fill runs.

#### Ablation

| --- | --- | --- |
| `nf() ?? nf()` for the tail | runs | **yes** (the `null` binding `z` in the chain) |
| `w = 7` for the fill | runs | **yes** (a record fill) |
| `z ?? z ?? nf()` | same invalid wasm | no |
