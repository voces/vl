### D15495 — a type parameter seeded from a `let` annotation is unbound at a call inside a generic's cloned body

**closed 2026-11-07 by lane Fn#d · runs, prints `x 3 true 1 x 3 true s` · was loud emit reject, `emitProgram: call to unknown function`, `vl check` rc 0 · clause 2 · closed by keying the seeded binding at the cloned call's template (`monoCallTplOf`, `monoBindSeededTyParams`) · fixture `generics/typaram-binding-seeded-in-cloned-call.vl` · filed 2026-11-07 against master `1ae7fe7f`**

Repro:

    function same<T>(k: T): T { k }
    function mid3<F, G, H, G1>(a: F, a1: G1, a2: H) {
      let b: G1 = a1
      const c: G = a2
      print(a("x"))
      print(b(3))
      print(c(true))
    }
    function outer<X>(x: X) {
      mid3(same, same, same)
      print(x)
    }
    outer(1)
    outer("s")

Want:

    x
    3
    true
    1
    x
    3
    true
    s

#### Mechanism

`mid3`'s `G` appears in no parameter; it is seeded from the parameter `a2` its `let` annotation is
initialised from (`elabTyParamSeedParam`). `monoBindSeededTyParams` asked the elaboration for that
binding with the raw call node (`elabCallSeedBind(decl, callIx, tp)`). Inside `outer`'s instance
the call is a clone, which the elaboration never keyed (`elabCallKeys` holds the template call
only), so the binding was missing and the emit refused `call to unknown function`. The sibling
`monoBindTyParamElab` already maps a clone to its template with `monoCallTplOf`; the seeded bind now
does the same.
