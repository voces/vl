#### Mechanism

D9001's close coerces the values written to the binding to one instance, the first pin it
is handed at (`monoHandWrittenLet`, emit_mono.vl), and refuses a second, different pin with
the written-let refusal (`monoBindSigFail`). Direct calls at two types run because the
binding then keeps one slot per call type; a hand to a generic does not take that path.
Before D9001 every hand was refused (`unsupported argument type for `g``).

The close reuses the split that direct calls already take. On the refusal the driver asks
fn_split to plan the binding, and a read handed to a generic or un-annotated parameter is now
keyed by that parameter and its call's argument types. Each pin gets its own `let`, written at
every write, and each one reaches D9001's single-pin path. The key is used only when the
ordinary keys give no split, or give one slot to hands at different pins, so every plan that
split before splits the same way.
