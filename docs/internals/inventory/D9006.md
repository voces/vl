### D9006 — a re-pointed `let` of generics handed to a generic higher-order parameter at two different pins is refused

**loud emit reject · `vl check` rc 0 · clause 2 · CAPABILITY: the same binding called directly at both types runs, and so does a `const` of one generic handed at both pins · found closing [D9001](D9001.md) · present on master `f0249c64f` · filed 2026-10-21 against master `f0249c64f`**

Repro:

    function fst<T>(xs: T[]): T { return xs[0] }
    function lst<T>(xs: T[]): T { return xs[xs.length - 1] }
    function app<T>(g: (x: T[]) => T, v: T[]): T { return g(v) }
    let f = fst
    if [1].length > 0 { f = lst }
    print(app(f, [1, 2, 3]))
    print(app(f, ["a", "b"]))
    // vl run: emitProgram: the reassigned function binding `f` holds functions called at more than one argument type — one binding holds one closure signature, and the values written to it want two. Annotate the parameters, or bind a separate value per type

#### Mechanism

D9001's close coerces the values written to the binding to one instance, the first pin it
is handed at (`monoHandWrittenLet`, emit_mono.vl), and refuses a second, different pin with
the written-let refusal (`monoBindSigFail`). Direct calls at two types run because the
binding then keeps one slot per call type; a hand to a generic does not take that path.
Before D9001 every hand was refused (`unsupported argument type for `g``).

#### Ablation

| ingredient removed | outcome | needed? |
| --- | --- | --- |
| the second pin (`app(f, [4, 5])`) | runs, `3` `5` | **yes** |
| the write `f = lst`, for `const f = fst` | runs, `1` `a` | **yes** |
| the hand, for direct calls `f([1, 2, 3])`, `f(["a", "b"])` | runs, `3` `b` | **yes** |
