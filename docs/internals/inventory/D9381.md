### D9381 — a generic over a record parameter returned from an un-annotated function and bound at a function type refuses

**closed · runs, prints `y!` · was loud emit reject, clause 2, `vl check` rc 0, `emitProgram: a generic function taken as a value reaches no call that fixes its type` · found closing [D9282](D9282.md) · filed 2026-10-21 against master `a28f82fcb` · closed by reading a named or inline record pin by its shape when binding the type parameters (`monoPinShapeName`, `monoPinShapeSpell`, `monoPinDeclSpell`, emit_mono.vl; a field's spacing trimmed in `monoBindFromAnn`, emit_base.vl) and by spelling a function-value pin as the closed parameter type it was taken at (`monoSlotPinName`, `monoPinFnParamTys`, emit_mono.vl), while a written `let` of hole lambdas keeps the signature its closures take (`monoSlotSigName`) · fixtures `closures/generic-returned-record-param.vl` and `closures/generic-returned-fn-param.vl`, matrices `fn-value-generic-returned-record-param` (0 → 46 of 48) and `fn-value-generic-returned-fn-param` (0 → 45 of 48)**

Repro:

    type K = "x" | "y"
    type R = { k: K }
    function pick<T>(r: { k: T }): T { r.k }
    function deliver() {
      return pick
    }
    const v: (r: R) => K = deliver()
    print(v({ k: "y" }) + "!")
    // vl run: emitProgram: a generic function taken as a value reaches no call that fixes its type — annotate the destination's function type

Want:

    y!

#### Mechanism

Past `deliver`'s return, the flow table gives `pick` a pin spelling for each parameter.
`monoInstanceFor` binds type parameters by decomposing that spelling against the declared
pattern, and three spellings bound nothing:

* A declared record is pinned by its name `R`, so `{ k: T }` against `R` binds no `T`, the
  substitution comes back empty, and the instance declines to the value floor.
* An inline record is pinned as `{k: i32}`. The field split kept the space after the colon, so
  `T` bound to ` i32`, the instance spelled a parameter type no shape is interned under, and the
  build refused with `ref valtype with no interned shape`. That second message is the
  un-annotated face of this row: the un-annotated binding pinned `pick` at the call's inline
  record.
* A function-typed parameter is pinned as a wasm signature (`=>k`), which no pattern can read a
  type out of.

The fix:

* A record declaration's name is spelled by its declared fields (`monoPinDeclSpell`).
* An inline record pin is respelled field by field, and that spelling is also the instance's
  parameter type.
* A function-value pin is spelled as the closed parameter type the flow table took it at.
