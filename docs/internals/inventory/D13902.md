### D13902 — a `Map()` binding that keeps its own record type is delivered as a wider map as invalid wasm when a declared type shares its layout

**check-clean invalid wasm · filed 2026-10-25 against master `74362376a`**

Repro:

    type Circle = { r: i32 | null }
    type P = { r: i32 }
    const q: P = { r: 1 }
    print(q.r)
    function sink(x: {[string]: Circle}) {
      const v = x["k0"]
      if v != null { print(v.r ?? 0) }
    }
    const b = Map()
    b["k0"] = { r: 7 }
    sink(b)
    const w = b["k0"]
    if w != null { print(w.r + 1) }
    // expected: 1, 7, 8

#### Mechanism

`b` is delivered as `{[string]: Circle}`, and `w.r + 1` needs its own `{r: i32}`, so the
record adoption is undone and `b` keeps `{[string]: {r: i32}}`. The checker accepts the
delivery because each value is a fresh literal, and the emitter hands the map over as is:
its values are stored at `P`'s row, which `sink` reads as `Circle`'s. Without the declared
`P` the same program runs.

#### Ablation

| ingredient removed | outcome | needed? |
| --- | --- | --- |
| `type P`, `q` and `print(q.r)` | runs | **yes** |
| the `w` lines (the binding adopts `{[string]: Circle}`) | runs | **yes** |
| the `v.r` read in `sink` (prints `x.length`) | invalid wasm | no |

#### Grading list

Either the checker refuses the delivery of a map whose records keep a narrower storage (a map
is shared, not copied), or the emitter builds the map's values at the delivered row. The
first loses programs that run today when no declared type shares the layout (the second
ablation row without `P`).
