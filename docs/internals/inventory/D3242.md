### D3242 — an uninitialized record `let` assigned in both arms of an `if` is check-clean invalid wasm

**closed 2026-10-26 (`localUnset` in `compiler/emit_state.vl`, set by `markLocalDecl`; `fbEmitLocalsVec` declares the cell through `fbValtypeNullable` and `fbLocalGet`/`fbLocalTee` assert non-null) · was check-clean invalid wasm · clause 1 · filed 2026-09-29 against master `fc1e91d24` · fixtures `tests/cases/functions/uninit-ref-let-branch-writes.vl`, `tests/cases/functions/uninit-ref-let-branch-writes-initialised.vl`**

Repro:

    type Circle = { r: i32 }
    function g(n: i32) {
      let c: Circle
      if n > 2 { c = { r: n } } else { c = { r: 0 } }
      c.r
    }
    print(g(4))
    // vl check: rc 0.  vl run: invalid module, uninitialized local

Want:

    4

#### Mechanism

`fbEmitLocalsVec` declared every local at `fbValtype` of its kind, and for every ref kind that
is a non-null `(ref $t)`. Wasm counts a non-null local as set only inside the block that set
it, so a `let` with no initializer written in both arms of an `if` (or every arm of a `match`)
and read after the join is invalid, though the checker has proved the write precedes the read.
Only the function-typed spelling ran, through a closure-only rung in `letIsNulClosure`
(D3256) that gave such a `let` the nullable closure kind. The cell is now declared at
`fbValtypeNullable`, the producer a non-constant global cell already uses, and each read of it
is `local.get` + `ref.as_non_null`; the slot keeps its kind, so every other rep question is
answered as before. The module-scope spelling is D14281.
