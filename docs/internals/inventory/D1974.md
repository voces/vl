### D1974 — a dead value after an always-exiting statement, under a declared return type, is emitted as the function's result and fails validation

**check-clean invalid wasm, clause 1 · pre-existing on base `a8a104432`, not a regression of D1970 · found by the D1970 review · filed 2026-09-22 against master `a8a104432`**

Repro:

    function f(k: i32): string {
      {
        return "a"
      }
      5
    }
    print(f(1))
    // vl check: rc 0 (plus an unreachable-code warning).  vl run: rc 70, the emitted module
    // fails to validate inside `f`: `type mismatch: expected (ref $type), found i32`

#### Mechanism

Not ablated yet; this is a prediction. The checker does not treat an unreachable tail as the
implicit return (`tailIsReturn` is false after a statement for which `stmtAlwaysExits` holds),
so the `i32` is never checked against `string`. The emitter still seems to lower the tail as the
function's result. The fix makes both sides agree on a dead tail: the emitter drops it or pads
with `unreachable`, or the checker types it.

#### Grading list

The `match` spelling, `function f(k: i32): string { match k { 1 => { return "a" } _ => { return
"b" } }; 5 }` with `print(f(1))`: rc 70 with the same message on base and on D1970's head. Also
the plain `return "a"` then `5` spelling, and the inferred-return twin.
