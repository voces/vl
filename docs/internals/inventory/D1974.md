### D1974 — a dead value after an always-exiting statement, under a declared return type, is emitted as the function's result and fails validation

**closed 2026-10-20 · runs, prints `a` · was check-clean invalid wasm · clause 1 · the emitter now lowers a block's last statement as `unreachable` when the statement before it always exits (`blockTailIsDead`/`emitDeadTail`, `wasmEmit.vl`), which is the checker's own `tailIsReturn` rule, at both tail sites (`emitFuncBody`, `emitStmtsTail`) · pin: `tests/cases/functions/dead-tail-after-exit.vl` · matrices `dead-tail-after-exit`, `dead-tail-after-exit-generic`, `dead-tail-after-exit-lambda` · pre-existing on base `a8a104432`, not a regression of D1970 · found by the D1970 review · filed 2026-09-22 against master `a8a104432`**

Repro:

    function f(k: i32): string {
      {
        return "a"
      }
      5
    }
    print(f(1))

#### Mechanism

The checker does not take a tail that follows an always-exiting statement as the implicit
return (`tailIsReturn` is false when `stmtAlwaysExits` holds for the statement before it), so
the `i32` was never checked against `string`. The emitter still lowered that tail as the
function's result, and the module failed validation inside `f`. The emitter now asks the same
question (`stmtAlwaysExits` on the second-last statement) and lowers the dead tail as
`unreachable`, advancing the local-slot cursor past any locals the tail owns. A dead nested
`function` declaration still takes the statement path.

Ablation, on base `05e6ced30`:

| change from the witness | outcome |
| --- | --- |
| none | check-clean invalid wasm |
| no block around the `return` | check-clean invalid wasm (the block is scenery) |
| no return annotation (inferred) | runs |
| tail matches the declared type (`"z"`) | runs |
| `: i32` with a `"z"` tail | check-clean invalid wasm |
| `match` whose arms all return, as the predecessor | check-clean invalid wasm |
| a predecessor that does not exit (`print(3)`) | loud check reject (the tail is typed) |

Positions that failed on base and run after the fix: function body, `if`-arm block tail,
lambda body, nested function, generic function, a `never` call or an `if`/`else` whose arms
both return as the predecessor, a value-`if` statement tail, a member-call tail, an else-less
nullable tail, list and record returns, an assignment tail. Two dead tails were clause-2 emit
refusals on base and now run: a dead `null` (`bare null needs a struct-typed context`) and a
dead nested function declaration (`a lambda-lifted local function was taken as a value`).
