### D2035 — the editor's `Import \`area\`` quick-fix inserts the plain name even when the file binds its own `area`, producing a duplicate binding

**parse error (a loud check reject at the merge) · the program below is what the quick-fix leaves behind · filed 2026-09-22 against master `605feab9b`, found closing D1984**

Repro:

    // file: base.vl
    export type Box = { v: i32 }
    export function box(v: i32): Box { return { v: v } }
    // file: lib.vl
    import { Box } from "./base"
    export function area(self: Box): i32 { return self.v * self.v }
    export function helper(): i32 { return 0 }
    // file: main.vl
    import { box } from "./base"
    import { helper, area } from "./lib"
    function area(self: string): i32 { return self.length }
    print(box(2).area())
    // vl check: Duplicate binding "area": module `main.vl` both imports and declares it (parse error)

#### Mechanism

Without the `area` import (and with the local `area` kept), `box(2).area()` raises D1230 (`ufcs-not-imported`, `data.modules = ["./lib"]`).
Since D1984 the sentence proposes `area as areaBox`, because the file already binds `area`, but
`lsp/src/codeActions.ts`'s `ufcsImportFixes` still builds `Import \`area\` from "./lib"` from the
member name alone and applies it verbatim, which yields the program above. The fix is for the
payload to carry the alias the sentence proposes and for the quick-fix to insert `area as
areaBox` and rewrite the call's member to `.areaBox`.

#### Grading list

`tests/lsp_ufcs_import_test.ts` and `tests/playground_import_actions_test.ts` gain a row for a
file binding its own `area`; the no-collision rows keep their plain import.
