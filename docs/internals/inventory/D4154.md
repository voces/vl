### D4154 — a generic type alias over a non-record body (`type X<T> = T[]`) is refused as an unknown type

**loud check reject · clause 2 · the record-bodied generic alias runs · filed 2026-10-11 against master `66f24dbe6`**

Repro:

    type X<T> = T[]
    const a: X<i32> = [1]
    print(a.length)
    // vl check: unknown type 'T' within 'T[]' in union 'X<T>'; unknown type 'X<i32>'

Want:

    1

#### Mechanism

The spec rule T9.4 (`docs/spec/types.md`) says a type alias may take type parameters and gives only a
record-bodied example. It is silent on other bodies, so the spec allows the form and nothing
forbids it. The checker resolves the body's `T` outside the alias's parameter scope when the body is a
list (the message calls it a union), while `type X<T> = { v: T }` resolves and runs.

#### Ablation

| ingredient changed | outcome | needed? |
| --- | --- | --- |
| body `{ v: T }`, value `{ v: 1 }` | runs, prints `1` | **yes** (a non-record body) |

#### Grading list

Grade a union body (`T | null`), a function-type body and a map body beside the list.
