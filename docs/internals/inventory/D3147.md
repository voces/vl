### D3147 — a doubly nested capture of a hole-bound field function from an inline record literal calls it through the wrong signature

**closed · D3142's close: the instance binds the literal's own field function type, which `holeOrCapturedTyOf` reads through both capture frames · fixture `tests/cases/generics/hole-bound-inline-record-field-function.vl` · was loads then traps · clause 1 · found by the #3280 review (`rv3280-17445`) · the same on master `07d414042` · filed 2026-09-29 against master `07d414042`, closed 2026-09-29 against master `934f169f4`**

Repro:

    function F(z) {
      const g = z.f
      const k = () => {
        const m = () => g()
        return m()
      }
      print(k())
    }
    F({ f: () => "x" })
    // vl check: rc 0.  vl run: wasm trap, indirect call type mismatch

Want:

    x

#### Mechanism

Not localised past the ablation. It needs D3142's ingredient, a record literal written at the
call, whose hole binding is `{f: _}`, so there is no function type for the bound `g`. With one
level of capture the call is refused at emit, loudly. Two levels reach a keyed call, which
dispatches through a signature the closure does not have and traps. A named record argument
runs, since D3117.

#### Ablation

| ingredient changed | outcome | needed? |
| --- | --- | --- |
| `const r = { f: () => "x" }` then `F(r)` | prints `x` | **yes** (the literal argument) |
| one level, `const k = () => g()`, named record | prints `x` | no |
| `function F<Z>(z: Z)`, named record | prints `x` | **yes** (the hole) |
