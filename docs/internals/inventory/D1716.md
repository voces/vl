### D1716 — a litunion atom reached through a struct FIELD of an un-annotated parameter printed the interned id, because the element reader asked the bare recorded type and not the banked pin

**closed 2026-09-06 — the ref-array element reader resolves its container's recorded hole
through the pin, three lines · filed against master `4ea675797` + D1710 · D1545's family at a
different reader, and D1545 itself stays open · 0 corpus cells**

Repro:

    type K = "a" | "b"
    function plain(): K[] { return ["b"] }
    function take(a) {
      const v = a
      print(v.xs[0])
    }
    take({ xs: plain() })
    // vl check: rc 0.  vl run: rc 0, prints b

Was: `0`, the interned atom id. Annotating the parameter printed `b` at every seed.

#### Mechanism

Probed, not read off the code path. An `emitFail` in `exprIsLitAtom`'s `Index` arm, on this
already-wrong program, printed every type the arm can see:

    PROBE index-arm arrTy=[] elemLU=-1 selfTy=[] pureLU=0 pinArr=[K[]] pinSelf=[K]

**Nothing is recorded on any node reached through a hole parameter — and the PIN has the whole
answer.** D1693 banks a recorded hole's concrete type under its own name; `nodeTyPinIxOf`
returns it and falls back to the bare recorded type wherever no pin exists, so asking it is a
strict widening. `arrElemLitUnionTyAt`'s first rung asked `nodeArrayElemTyIx` and stopped, so
the member set was never found and `print` emitted the raw i32.

**Three rungs looked necessary and one was**, measured by lifting each alone: adding the pin to
`exprIsLitAtom` and to `litAtomMemberTyAt` as well left this witness printing `0`, and the
element reader alone fixes it. The other two buy exactly one further cell — `argument` /
un-annotated on `anon-nullable-litunion-field.matrix.vl`, where the outcome is a LOUD refusal
either way — and are left out as D1545-adjacent scope rather than shipped unmeasured.
