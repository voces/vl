### D15083 — a list built from a binding typed by a single string literal stores the binding's string where the list holds atoms

**closed 2026-11-03 · runs, prints `x` · the checker records which list literal each element goes into (`markElemValue`), and the element takes that list's atom where the list's element reps as one · was check-clean invalid wasm · clause 1 · pre-existing · filed 2026-11-03 against master `9c5f61d6e`**

Repro:

    let j: "x" = "x"
    let js = [j]
    print(js[0])
    // vl check: rc 0.  vl run: invalid module, `type mismatch: expected i32, found (ref $0); $0 is `string``

Want:

    x

#### Mechanism

The un-annotated list literal `[j]` over a binding whose type is the bare literal `"x"` is built
as a list of literal atoms (i32), while the binding's read pushes its string reference. The two
`const` spelling runs, so the decision depends on the binding or the list being a `let`.
Found because `type J = "x"` made transparent (D15082) routes `tests/cases/literal-unions/const-literal-keeps-declared-member.vl`
through this spelling.

#### Ablation

| spelling | outcome |
| --- | --- |
| `let j: "x"`, `let js = [j]` (the witness) | invalid wasm |
| `let j: "x"`, `const js = [j]` | invalid wasm |
| `const j: "x"`, `let js = [j]` | invalid wasm |
| `const j: "x"`, `const js = [j]` | runs |
| `const js: "x"[] = [j]` (annotated list) | runs |
| `j: "x" \| "y"` (two-member literal union) | runs |
| `print(j)` (no list) | runs |
