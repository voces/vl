### D12800 — a hole lambda pushed onto a list of hole functions is called as an unknown function

**loud emit reject · `vl check` rc 0 · clause 2 · CAPABILITY: the same program with `snd` annotated runs · found closing [D12700](D12700.md) · filed 2026-10-25 against master `a0d8dfeb8`**

Repro:

    function snd(a, b) { return b }
    function apply2(g) { print(g("x", 2)) }
    const fs = [apply2]
    fs.push((g) => { print(g("z", 5)) })
    for f in fs { f(snd) }
    // vl check: rc 0.  vl run: emitProgram: call to unknown function

Want:

    2
    5

#### Mechanism

Not yet ablated past the table below. The pushed lambda's parameter `g` is a hole function
that nothing at the push binds, and the lambda's body call `g("z", 5)` is lowered as a direct
call to a function that has no instance. The same lambda as a list literal element is refused
by `vl check` (`cannot infer a type for parameter g`), so either the checker owes the pushed
spelling that refusal, or the push owes the lambda an instance at the list's call type.
