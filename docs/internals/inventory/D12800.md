### D12800 — a hole lambda pushed onto a list of hole functions is called as an unknown function

**closed 2026-10-25 by lane L1 · runs, prints `2 5` · a lambda pushed or index-written into an un-annotated `const` list literal is one of its elements, pinned at the list's call type (`monoAllFnValues`, `monoLamLitTake` in `monoOpenCallAtElems`, emit_mono.vl), and a push of a lambda is mirrored on each per-type copy (`fsListPushRead`, fn_split.vl) · pin: `tests/cases/closures/hole-lambda-pushed-onto-hole-fn-list-called-at-two-fn-types.vl` · the literal-element face stays a check reject by design (below) · a pushed lambda capturing a hole parameter is [D12880](D12880.md) · was loud emit reject · `vl check` rc 0 · clause 2 · CAPABILITY: the same program with `snd` annotated runs · found closing [D12700](D12700.md) · filed 2026-10-25 against master `a0d8dfeb8`**

Repro:

    function snd(a, b) { return b }
    function apply2(g) { print(g("x", 2)) }
    const fs = [apply2]
    fs.push((g) => { print(g("z", 5)) })
    for f in fs { f(snd) }
    // vl check: rc 0.  vl run: emitProgram: call to unknown function

Want:

    2
    5

#### Mechanism

The pushed lambda was left out of the list's elements (only identifiers counted), so the call
through the list never instanced it and its body call `g("z", 5)` named no function.

The two faces are graded separately, each against its concrete twin. The PUSH is CAPABILITY:
`fs.push((y) => y * 2)` onto `[(x: i32) => x + 1]` runs, since a push delivers the lambda at the
list's element type (E14.1), and refusing it in the checker would lose the annotated-`snd`
spelling that already ran. The LITERAL element is DESIGN: `[(x: i32) => x + 1, (y) => y * 2]`
refuses with `cannot infer a type for parameter y`, because a list literal's element type is
the join of its elements (E15.2) and a sibling does not deliver one. Making the two agree in
outcome needs sibling contextual typing in list literals, a language decision.

#### Ablation

| spelling | outcome | needed? |

#### Grading list

The pushed lambda called at two function types; `fs[1] = (g) => …` in place of the push; the
literal-element spelling, which must keep refusing exactly as its concrete twin does.
