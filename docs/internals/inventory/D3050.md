### D3050 — a double negation of a 32-bit hex literal under `as i64` negates its i32 bit pattern

**closed 2026-09-28 — the filed repro prints `4294967295` twice · was check-clean silently wrong, the same on master `3a71bb1f9` and `0b618d160`, for `const` and `let` alike · closed with [D3043](D3043.md): `as i64` adopts a negation chain as it adopts any literal tree, so the literal is read at 64 bits under every negation, as it already was under one · fixture `tests/cases/expressions/negation-chain-at-i64.vl` · found by the #3262 review · filed 2026-09-28 against master `3a71bb1f9`**

Repro:

    const K = (-(-0xffffffff)) as i64
    let L = (-(-0xffffffff)) as i64
    print(K)
    print(L)

Want:

    4294967295
    4294967295

#### Mechanism

`0xffffffff` is typed i64 (`0xffffffff as i64` and `(-0xffffffff) as i64` print its full value,
`4294967295` and `-4294967295`). Under the outer `-`, the operand is classified i32, so the literal
is emitted as the i32 bit pattern `-1`. Negating it twice gives `-1`, which the cast then
sign-extends. With a single negation the literal is read at full magnitude. #3262's const fold
refuses this shape (a negated literal whose width is not the fold's), so the const keeps
master's value until this row is closed.

#### Grading list

`(-(-0xffffffff)) as% i32`, and `-(-0xffffffff)` at an i64 destination.
