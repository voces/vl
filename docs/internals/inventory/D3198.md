### D3198 — a function whose result is a nullable literal union is miscompiled at nearly every call

**closed · an inline `"a" | "b" | null` names the same hidden literal-union alias as `K | null`, the instance reads the call's result through a `| null` pin again, and `??` to a non-member and the widening to `string | null` gained a `-1` arm · fixtures `tests/cases/literal-unions/nullable-literal-union-function-result.vl`, `tests/cases/generics/instance-call-of-nullable-literal-union-function.vl`, `tests/cases/literal-unions/nulLitUnion-niche-into-nullable-string.vl`, `tests/cases/maps/nulLitUnion-coalesce-non-member-default.vl` · was loads then traps · clause 1 · pre-existing · found by the #3288 review · filed 2026-09-29 against master `2771214c7`, closed against master `94670f728`**

Repro:

    const g: () => "a" | "b" | null = () => "a"
    print(g())
    // vl check: rc 0.  vl run: wasm trap, indirect call type mismatch

Want:

    a

#### Mechanism

Three causes, one per face. (1) The annotation route built the inner union of `"a" | "b" |
null` with a bare `mkUnionTy` whenever `null` was a member, so it was never registered as a
hidden literal-union alias. The contextual lambda then recorded no inferred-return row
(`nulLitUnionRetName` names only an alias), `synthRetAnnots` left it unpinned, and the body
returned a string ref under a call site keyed at the `i32` atom. `annUnionInnerTy` now takes the
literal-union flatten for a string-literal member list with or without `null`. (2) With the rep
agreed, #3288's two declines (`tyFnRetIsLitUnion` skipping a nullable result, `callPinFnTy`
refusing a `| null` pin whose function returns one) became the cause of the instance's wrong
reads and are removed. (3) `??` to a non-member default and the widening of the niche to
`string | null` refused on every spelling, aliased ones included, because the widening tower had
no arm for `-1`. `emitNulAtomToStr` and `emitCoalesceNulAtomStr` map `-1` to `null` or the
default and a member id through the tower; `litAtomWidenTexts` also reads a generic instance's
pin, which a narrowed call result there needs.

Round 2 wired the module scope. A `K | null` global's initialiser widens
(`globalInitIsLitAtom`), and an un-annotated global that holds the niche copies as the atom
rather than widening into an atom cell. An inferred return of the niche refuses rather than
widening into a non-null result. The flatten applies only to a member list of string literals;
a union naming an alias beside `null` (`K | "c" | null`, `K | L | null`) stays the box it was.
