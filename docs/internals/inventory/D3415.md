### D3415 — a `??` whose right operand is a type parameter is not re-checked at the pin at a push, an if-expression arm, a `+`, a spread or an un-annotated record field, and the value is wrong

**check-clean silently wrong · clause 1 · open · the destinations [D3252](D3252.md)'s close did not cover (its own residue note) · found by the #3317 review (`rv3317-7c184e7a`, grid `gE`) · the same on master `5e277ab52` · filed 2026-09-30 against master `5e277ab52`**

Repro:

    function gp<T>(x: T) {
      const o: f64 | null = null
      const a: f64[] = []
      a.push(o ?? x)
      print(a[0])
    }
    gp(3 > 2)
    // PRINTS 1

Want:

    check reject: a `boolean` is not a number

#### Mechanism

A prediction. [D3252](D3252.md) records a `??` over a hole default as a derived hole at the
deferred constraint of a binding, assignment, return, argument and literal element, and the
pin answers it as the concrete `??` type. The destinations below are consulted by no such
constraint, so the body's vacuous fit stands: `boolean`'s i32 `1` is delivered into an `f64`
slot and read as `1.0` (prints `1`, or `1.5` through a `+`). The direct spelling refuses each
of them, except the un-annotated field, which types the field as the join and prints `true`.
