### D16687 — a literal `step 0` is reported twice by `vl check`, once by the `for-step-zero` lint and once by the checker, with one message at one caret

**loud check reject · first-error quality · found re-running `docs/guide/soundness.md` · filed 2026-11-16 against master `d30dbc538`**

Repro:

    for i in 0 to 4 step 0 { print(i) }
    // vl check: [ERROR]: a range with `step 0` never advances   (at 1:22)
    //           [ERROR]: a range with `step 0` never advances   (at 1:22)
    //           Found 2 errors.

#### Mechanism

`reportDegenerateStep` (lint.vl) emits `for-step-zero` at error severity for a literal `step 0`,
and `checkRangeNeverRuns` (check_node_rules.vl) raises the same sentence at the same node under
`range-never-runs`; the lint's comment says the shared wording is deliberate, so neither drifts.
The CLI prints the lint stream and the checker stream side by side and dedups neither against the
other, so the one mistake counts as two errors. Either the CLI drops a lint diagnostic the checker
repeats at the same span, or the lint arm goes now that the checker's fold covers every literal
step it sees.
