#### Mechanism

**Found by pairing, so the control is attached**: the sampler generated this program's `==`
and `is` twins from the same plan, and both RUN. The refusal is therefore about the SPELLING
of the test, not about the hole — the checker resolves the same parameter's type for `is` and
for `==` and declines only for `match`.

The `got _` is the hole rendering. The generic spelling refuses too, with `got T` — **two
messages, one mechanism**, which is why this row is grouped by its ablation and not by either
sentence.

The close checks such a `match` over the union its arms name, as the parameter annotated with
that union is, and each arm narrows to its own pattern. Unless a `_` takes the rest, the call
that pins the parameter is asked that annotation's argument question, so an uncovered pin is
refused there ("argument 1: expected "red" | "green", got string"), as the annotation refuses it.

scrutinee the message names as accepted runs — so the message's own vocabulary is accurate
about integers and the gap is the whole union half of it.
