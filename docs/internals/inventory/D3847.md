### D3847 — a top-level `let` alias of a hole lambda, called and then reassigned, is refused at emit for want of a function-value signature

**closed (2026-10-08, lane SC) · was a loud emit reject · found in review of #3441 (`l9`) · filed 2026-10-08 against master `52c8e492d` · pins: `tests/cases/closures/module-let-alias-of-hole-lambda.vl`**

Repro:

    const c = (y) => y + "C"
    const e = (y) => y + "E"
    let d = c
    print(d("a"))
    d = e
    print(d("b"))
    // vl check: rc 0.  vl run: emit error `a function-value call has no interned signature — parameter 1 of type `` has no representation in the function-value ABI`

Want:

    aC
    bE

#### Mechanism

Two module-scope gaps. `monoLetFrameOf` walked function frames only, so the alias resolver
could not find a global `let` read at module scope. And `fieldValueFeOfIn` resolved an
initializer name only to a named function, while a module-scope `const c = (y) => …` is a
binding, so the call through `d` had no lambda to key its `$fnsig` from. Both now resolve
module-scope bindings. A function's own bindings keep their scope-chain answer, because the
written-chain checks that guard a reassigned alias live in the alias resolver (D3849). A chain
of two aliases at module scope is still refused (D3854).
