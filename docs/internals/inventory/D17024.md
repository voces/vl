### D17024 — `__trap__` streams its message as a string, so a literal-union atom message is check-clean invalid wasm

**check-clean invalid wasm · 0 corpus cells (no grid crosses `__trap__` with a literal union) · filed 2026-11-19 against master `8b89f4bc3`**

Repro:

    type Why = "empty" | "full"
    function fail(w: Why) { __trap__(w) }
    fail("full")
    // vl check: rc 0.  vl run: the emitted module failed to validate inside `fail`:
    // unknown local 1: local index out of bounds

#### Mechanism

`emitCallCoreTrap` (wasmEmit.vl) writes its message through `emitPrintStrExpr`, which is
`emitExpr` followed by `printStrTail`, the string stream. A literal-union atom's value is its
interned i32 id, not a string ref, so the stream reads a string scratch frame the function never
reserved (`fnUses.strOp` is not set for an atom operand) over an i32. `print` routes the same
atom through `printArmOf`'s `atom` arm (`printAtomTail`) and runs; the trap arm has no such
route.

#### Ablation

| ingredient removed | outcome | needed? |
| --- | --- | --- |
| the atom type (a `string` parameter) | runs, prints the message and traps | **yes** |
| the parameter (a local of the atom type) | still invalid wasm | no |
| the trap (`print(w)` instead) | runs | **yes** |
| the atom read as a `string` local first | runs | **yes** |

#### Grading list

- `__trap__` of a `K | null` atom, and of a `string | null`, both message positions `print` routes
  through its own arms.
- The IR's `trapStmt` builds only a message at `printArmOf`'s `str` arm (#9171), so it never
  takes this shape; the fix belongs to `emitCallCoreTrap` routing its message as `print` does.
