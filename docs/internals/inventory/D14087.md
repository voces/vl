### D14087 — a labelled block joining an `i32` and an `f64` through `break` promotes the join to `f64`, where `if` and `match` give `i32 | f64`

**check-clean silently wrong · open · clause 1 · the repro prints `true` `true` · `vl check` rc 0 · against the numeric-join ruling of 2026-09-30, under which runtime values of two number types join as a union and `is` tells them apart · pre-existing on master `baa5cd694` and `b02fce014` · found filing [D14086](D14086.md) · filed 2026-10-26 against master `b02fce014`**

Repro:

    function h(a0: i32[], a1: f64[], k: i32) {
      const r = @out {
        if k == 0 { break @out a0 }
        a1
      }
      print(r is f64[])
    }
    h([1, 2], [1.5], 0)
    h([1, 2], [1.5], 1)

Want:

    false
    true

#### Mechanism

The checker types the block's join `f64[]`, not `i32[] | f64[]`, and delivers the `i32[]`
arm converted. An assignment of `r` to a `string` reads `cannot assign f64[]`. Under `if k == 0
{ a0 } else { a1 }`, the same assignment names `i32[] | f64[]`. With `if r is f64[] { print(r[0]
/ 2.0) }`, the `i32[]` arm prints `0.5`, so the elements were converted, not reinterpreted.
