#### Mechanism

The emitter's keyer is a pair, and only one half recurses. `indexPathKeyOf` now keys an index
below an index (D1722), but its Member leg asks `memberPathKeyOf`, which answers "" for a path
whose root is an index — by design and with its reason written down: a dozen member-shaped
readers depend on that answer, and D451 split the two keyers to get it.

So `ws[0].xs` keys "" and `ws[0].xs[0]` with it, while the checker's single recursive
`placeKeyOf` keys both. The remaining disagreement between the two keyers is exactly this
link, which makes it a bounded row rather than the general one D1722 closed.

#### Grading list

The three ablation rows that run. A close owes the same write-side half D1722 did: a write to
`ws[0].xs` under a live `ws[0].xs[0]` narrowing must retire it, and the keyer-only arm of that
change traps rather than refusing — so grade the write witness, not only the read.
Widening `memberPathKeyOf` is what D451 deliberately did not do; a close should either say why
that is now safe or key the link somewhere else.
