#### Mechanism

The emitter's keyer is a pair, and only one half recurses. `indexPathKeyOf` now keys an index
below an index (D1722), but its Member leg asks `memberPathKeyOf`, which answers "" for a path
whose root is an index — by design and with its reason written down: a dozen member-shaped
readers depend on that answer, and D451 split the two keyers to get it.

So `ws[0].xs` keys "" and `ws[0].xs[0]` with it, while the checker's single recursive
`placeKeyOf` keys both. The remaining disagreement between the two keyers is exactly this
link, which makes it a bounded row rather than the general one D1722 closed.

#### Close

The row's own instruction — "a close should either say why [widening `memberPathKeyOf`] is now
safe or key the link somewhere else" — is answered by keying it somewhere else.
`memberPathKeyOf` and a new `memberKeyThroughIndex` are now two spellings of ONE ladder
(`memberPathKeyAt`), whose `thruIndex` parameter is the whole difference: without it an index
receiver stays un-narrowable, which is the answer D451 split these keyers to guarantee and a
dozen member-shaped readers depend on. Only `indexPathKeyOf`'s own receiver leg and the write
retirement ask the widened spelling, and both already key index places.

Folding the pair into one ladder is also why the seed SHRANK: two ladders became one, and the
`kind-ladder` ratchet is unchanged rather than one higher.

#### The write half is DEFENSIVE, and that is measured

D1722's close needed a write-side half, and this row's grading list asked for the same. It was
built — both write sites take the widened keyer — and a keyer-only variant was built beside it
and graded on the same 17-cell grid: **the two are cell-for-cell identical**. Every write
witness attempted is refused by the CHECKER first, which retires the narrowing by prefix on both
sides:

| write witness | outcome at both variants |
| --- | --- |
| write the cell (`ws[0].xs[0] = 7`) | `cannot assign i32 to A` — the checker refuses |
| write the list, then read `.r` | `field 'r' is not on every member of M` — retired by prefix |
| the same over an `A \| null` niche | `print` refuses the re-typed `A \| null` |
| the same over an `(i32 \| null)` niche | a separate `??` capability gap refuses first |

So the write half is **kept without a witness**, because an asymmetric keyer is exactly what
D1722 named as the trap: the read side can now establish a key the write side would not retire.
A close that shipped only the keyer would be correct today and silently wrong the first time a
checker-side retirement is narrowed.
