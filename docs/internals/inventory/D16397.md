### D16397 — `==` in a generic body instantiated at two records of one field set stored apart passes check and is refused at emit

**loud emit reject · clause 1 (`vl check` rc 0) · bucket (e) · probe `scripts/capability-probes/eq-record-generic-instances-stored-apart.vl` · found grading D16394's close · filed 2026-11-15 against master `55e900553`**

Repro:

    function eq<T, U>(a: T, b: U): boolean { a == b }
    const x: {f: i32} = {f: 1}
    const y: {f: f64} = {f: 1.0}
    print(eq(x, y))
    // vl check: rc 0.  vl run: emit error, `emitProgram: struct equality is not supported yet`

Want:

    true

#### Mechanism

D16394 rewrites a record `==` over fields stored apart into one `==` per field pair, in the
checker, where the operands' records are known. A generic body is checked once, over its type
parameters, so the rewrite does not fire there (`recEqFieldsAt` leaves an operand with a type
variable alone). The instance reaches the emitter's struct-equality lowering with two rows, which
it refuses. The instance is known only after the checker, so the close needs the same field-wise
compare at the instance.

#### Ablation

| spelling | outcome |
| --- | --- |
| the witness | check-clean, loud emit reject |
| `eq<T>(a: {f: T}, b: {f: f64})` called as `eq({f: 1}, {f: 1.0})` | check-clean, loud emit reject |
| `eq<T>(a: {f: T}, b: {f: T})` called as `eq({f: 1}, {f: 1})` | runs, prints `true` |
| `x == y` outside a generic body | runs, prints `true` (D16394) |
