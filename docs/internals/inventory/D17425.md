### D17425 — a hole function that writes a field of its parameter and returns it, delivered wider, emits an invalid module

**closed 2026-11-25 by SOUND · runs, prints `7` · was check-clean invalid wasm, clause 1 · the D17047 close admits a field write as it admits a read: a write is a use as a field's receiver, and the literal is built at the destination's record before it · pinned by `tests/cases/records/hole-identity-field-uses-delivered-wider.vl` · filed 2026-11-24 by IR-S1 against master `c59738bbd`**

Repro:

    type A = { d: i32 | null }
    function g(v) {
      v.d = 7
      return v
    }
    const c: A = g({ d: 5 })
    print(c.d ?? -1)
    // vl check: 0 errors.  vl run: invalid module, inside `g`

Want:

    7

#### Mechanism

The same split as D17047: the result is delivered at `A`, and the parameter stays at the
literal's own row. The hand-back adoption (`recHoleIdentityArg`, `check_fit_rules.vl`) declines a
body that writes the parameter, and D17047's fix still declines it. A write is not a read, and
building the literal at `A` under a write is its own question.

#### Grading list

The write through a rebound name (`let w = v; w.d = 7; return w`).
