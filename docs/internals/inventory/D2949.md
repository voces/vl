### D2949 — the pin's `==` mirror softens one side only, so `K | i32 == K` is refused at a literal-union pin

**closed 2026-09-29 · was a loud check reject, clause 2, on master `94670f728` · closed with D2906: the pin's mirror tests the written pair too, and the `K | i32` local it then reached is built at the pin · found by the CK lane's generic-join grid (`lit` pin, `eq` position) · filed 2026-09-28 against master `e9fdc10d9` · fixture `tests/cases/generics/gradual-type-parameter-union.vl`**

Repro:

    type K = "a" | "b"
    function g<T>(a: T, c: boolean) {
      const r: T | i32 = if c { a } else { 5 }
      print(r == a)
    }
    const k: K = "a"
    g(k, true)
    g(k, false)
    // vl check: argument 1: operator '==' is not defined for K | i32 and K

Want:

    true
    false

#### Mechanism

`binOpDefinedFor` (the pin's mirror of `checkBinary`) softens both operands with `softenLitTy`
before its mutual-assignability test. `softenLitTy(K)` is `string`, while `softenLitTy(K | i32)`
is unchanged, because the union holds a member that is no literal. Neither `string` nor
`K | i32` is assignable to the other, so the pin refuses. The direct spelling
(`checkBinary`) tests the written pair, `K` into `K | i32`, which holds, and the concrete
twin runs. Also testing the written pair in the mirror clears the check. The witness then
reaches the emitter and stops at `emitProgram: only i32 locals are supported`, so the check
fix alone moves this row from one refusal to another. It is left open for the lane that
builds the `K | i32` local at a pin.

#### Grading list

The un-annotated join, `const r = if c { a } else { 5 }` in the same body, and the CK grid's
`tp_lit_lit_eq` and `tp_lit_listlit_eq` cells. Neither refuses today, because the template
types that join as `T`. Both refuse the same way once the join is typed `T | i32` (D2906).
