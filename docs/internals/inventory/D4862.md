### D4862 — a kept-apart join of a type parameter's list and a concrete list collapses at a nullable-element pin

**closed 2026-10-15 — runs (`1`, `2`): a pin re-joins the body's return VALUES, not its join's members, and keeps apart every list value stored as built (only a list literal adapts to the join), in the checker's `substTyDeep` and the emitter's `monoInferRetSetUnionName`/`monoInferRetSetListTy` alike, so the all-open rule of D3367 is now one case of it · was check-clean invalid wasm · clause 1 · found by L2 §13.30, the sibling of D3367 its fix leaves alone · filed 2026-10-15 against master `e2d96e401` · fixtures `tests/cases/generics/type-param-list-join-concrete-list-apart.vl`, `tests/cases/generics/type-param-list-return-join-apart.vl` · left open: the un-annotated face D4882, the bound-`if` faces D4883 and D4884**

Repro:

    function w<T>(t: T, b: boolean, q: i32[]) {
      if b { return [t] }
      q
    }
    function g<T>(t: T, b: boolean) {
      const q: i32[] = [5, 6]
      const v = w(t, b, q)
      print(v.length)
    }
    const x: i32 | null = null
    g(x, true)
    g(x, false)
    // vl check: rc 0.  vl run: invalid module inside `w`

#### Mechanism

The body's join `T[] | i32[]` is kept apart (D2760) and re-joined at the pin. At `T := i32 |
null` the re-join collapses onto `(i32 | null)[]`, which `q`'s `i32[]` is stored differently
from, so `w` returns `q` where its result type wants the other list. The direct spelling refuses
the same join. The re-join keeps the two apart only when every member is open in a type
parameter (D3367), because a concrete member can be a literal the join adapts.
