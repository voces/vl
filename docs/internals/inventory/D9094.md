### D9094 — a `let` list of un-annotated functions written with another function that agrees is refused at emit

**loud emit reject · `vl check` rc 0 · `emitProgram: cannot take the generic function inc0 as a value` · clause 2 · found closing [D9060](D9060.md) · present on master `361494943` · filed 2026-10-21 against master `361494943`**

Repro:

    function inc0(a) { return a + 1 }
    function dbl(a) { return a * 2 }
    let xs = [inc0]
    xs[0] = dbl
    print(xs[0](3))
    // vl check rc 0.  vl run: emit error: emitProgram: cannot take the generic function `inc0`
    // as a value

#### Mechanism

Not traced. The `const` spelling runs, so the emitter's typing of a list literal of hole
functions from its writes does not cover a `let` binding, and the literal's element is
left un-instanced.

#### Ablation

| ingredient removed | outcome | needed? |
| --- | --- | --- |
| `let` (`const xs = [inc0]`) | runs, `6` | **yes** |
| the write (`let xs = [inc0]`, `xs[0](3)`) | runs, `4` | **yes** |

#### Grading list

The write made inside a function through a parameter, `function put(ys) { ys[0] = dbl }`
then `put(xs)` with `const xs = [inc0]`, which emit refuses with `cannot take the generic
function `dbl` as a value`. With `half` in place of `dbl` that spelling is also refused at
emit, where D9060 would have it refused at check.
