### D15205 — a record literal holding one un-annotated function, used without being bound and called through that field, builds an invalid module

**closed · runs, prints `4` · was an invalid module after a clean `vl check` (`type mismatch: expected (ref $0), found i32`), clause 1 · found tracing [D15203](D15203.md)'s remainder · present on master `f6b19ca4` · filed 2026-11-03 against master `6e694945` · fixed by asking the tag decision's record-field holder rule the type the literal's row is built at: `ftRecHolds` (check_fn_tag.vl) reads `nodeRepTyIxOf`, the adopted rep, where `ftHolds` read the literal's own type, whose field carried the set the rep's did not. The inline two-field spelling is [D15206](D15206.md). The named set `d15205-unbound-record-fn` holds the positions**

Repro:

    function inc0(a) { return a + 1 }
    print({ f: inc0 }.f(3))

Want:

    4

#### Mechanism

The literal's own type and the record it was adopted at (`recordRepTyAdopt`) are different records. The tag decision asked whether the literal holds the set of its own type, whose field carried it, and tagged the set; the row is built at the adopted rep, whose field carried no set, so `fieldCodeOfTy` coded it a closure. The constructor stored the id into a closure field. A bound literal left the set untagged, so both read closure.
