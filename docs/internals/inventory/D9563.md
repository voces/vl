### D9563 — an `i32` default for a nullable all-`i64` literal union joins at `i32`, so `+` on the result is refused

**loud check reject · clause 2 · CAPABILITY: the same `(a ?? 0) + 1` over `i64 | null` runs, binding `a ?? 0` to an `i64` first runs, and a default spelled `5000000000` runs · found closing [D9521](D9521.md) · present on master `95725e040` · filed 2026-10-22 against master `95725e040`**

Repro:

    type L = 5000000000 | 6000000000
    const a: L | null = 6000000000
    print((a ?? 0) + 1)
    // vl check: operator '+' is not defined for 5000000000 | 6000000000 | i32 and i32

Want:

    6000000001

#### Mechanism

Not traced. The `??` joins `L` with the literal `0` at `L | i32` instead of adopting the
literal into `L`'s base `i64`, as the numeric join ruling does for `i64 | null` (`literals
adapt`). The operator check then has no `+` for a union whose members soften to two widths.
The same refusal reaches an un-annotated parameter's call: `take(() => a)` with
`(f() ?? 0) + 1`.

| the `i32` default (`?? 5000000000`) | runs | **yes** |
| `null` (`a: L`) | runs | **yes** |
