### D2503 — the value binding of a `for k, v in m` walk over a union-box-valued map reads as the scalar, not the box

**check-clean invalid wasm · clause 1 · pre-existing on master `d29a9d220`, at every key rep ·
found by [D2505](D2505.md)'s operation grid · filed 2026-09-25 against master `d29a9d220`**

Repro:

    const m: {[string]: i32 | null} = Map()
    m["a"] = 3
    for k, v in m { print(v) }
    // vl check: rc 0.  vl run: invalid module, type mismatch: expected i32, found (ref $type)

#### Mechanism

`forInPairElemKind` binds the second name at kind `union` (the vals element is `$uBox`), and
the loop's own read stores the box into it. A read of `v` in the body then lowers as the plain
scalar: the disassembly shows `call $__print_i32__ (local.get $v)` over the `(ref $uBox)` local.
The same value walked as `for w in m.values()` prints `3`, so the classifier that turns a loop
variable into its box rep knows the `.values()` walk and not the pair walk's second name. Not
traced further than that.

#### Ablation

| ingredient removed | outcome | needed? |
| --- | --- | --- |
| `for k, v in m` replaced by `for w in m.values()` | prints `3` | **yes** |
| the value `i32 \| null` replaced by `string \| null` or `boolean \| null` | runs | **yes** — a union BOX value |
| `i32 \| null` replaced by `f64 \| null`, `i64 \| null` or `i32 \| string` | still invalid | no |
| the key `string` replaced by `i32` or `i64` | still invalid | no |
| the walk inside a function | still invalid | no |
| `print(v)` replaced by `if v != null { print(v) }` | still invalid | no |
| `print(v)` replaced by `print(v ?? 0)` | loud emit reject, `?? over this nullable value is not supported yet` | no |
| `print(v)` replaced by `const x = v` | runs | **yes** — a read that lowers the value |

#### Grading list

* The same program at `{[i64]: i32 | null}` and `{[i32]: i32 | null}`.
* `print(v ?? 0)` in the same walk, the loud face of the same binding.
