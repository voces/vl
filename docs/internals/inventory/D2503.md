### D2503 — the value binding of a `for k, v in m` walk over a union-box-valued map reads as the scalar, not the box

**closed 2026-09-25 — the filed repro RUNS and prints `3` · was check-clean invalid wasm, clause 1, at every key rep · found by [D2505](D2505.md)'s operation grid · filed 2026-09-25 against master `d29a9d220`**

Repro:

    const m: {[string]: i32 | null} = Map()
    m["a"] = 3
    for k, v in m { print(v) }
    // vl check: rc 0.  vl run: invalid module, type mismatch: expected i32, found (ref $type)

#### Mechanism

`forInPairElemKind` binds the second name at kind `union` (the vals element is `$uBox`), and
the loop's own read stores the box into it. What a read of `v` then lowers as comes from the
union member set, and a loop variable has no declaration to name one: `forInLoopVarUnionName`
answers it from the ITERABLE (`localLoopIter`), which the one-name `.values()` walk records and
the pair walk's second name did not. With no member set the read lowered as the bare scalar
(`call $__print_i32__ (local.get $v)` over the `(ref $uBox)` local), and `v ?? 0` refused. The
fix records the walked map on the second name's slot (`localPairIter`, `markPairVarIter`) and
answers its union from the map's vals slot — the list `m.values()` walks.

| `print(v)` replaced by `const x = v` | runs | **yes** — a read that lowers the value |
