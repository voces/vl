### D3269 — a union DECLARED with `type` whose member is a function type loses the function arm's rep: the call through the arm is invalid wasm and `is` answers wrong

**closed 2026-10-13 · runs today and must keep running · was check-clean invalid wasm · clause 1 · found 2026-09-29 by the PL-060 (function-type parameter names) position grid · the same on master `569caa36c` · filed 2026-09-29 against master `569caa36c`**

Repro:

    type U = ((i32) => i32) | string
    function dbl(x: i32) { x * 2 }
    function run(v: U): i32 {
      if v is string { return 0 }
      v(4)
    }
    print(run(dbl))
    print(run("s"))

Want:

    8
    0

#### Mechanism

`collectU` (`compiler/emit_collect.vl`) recorded a declared union's member set by joining its
members with `|`, and a function-type member is stored without its grouping parens. So `U`'s
set read `(i32)=>i32|string`, which splits as ONE atom: an arrow returning `i32|string`. Every
reader of the set then misread the arms. `unionBoxLacksTag` folded `is` to false, the narrowed
call read an `i32` atom, and a scalar delivery found no value box. The inline name is
`((i32)=>i32)|string`. Closed by keeping the parens in the join. The position matrix
`scripts/capability-probes/matrix/alias-fn-arm-union-is.matrix.vl` graded `WRONG` at 58 of
64 cells before and `RUNS` at the same 58 after. The other 6 refuse in the inline spelling too
([D4347](D4347.md)). Every row of the grading list below prints its wanted output.
