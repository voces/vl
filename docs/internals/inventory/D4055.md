### D4055 — postfix `++` and `--` on a field or an element are a parse error, while the prefix forms run

**open · loud check reject, raised at the parse stage (`vl check` closes with `(parse error)`) · clause 2 (the parser's own comment calls the form "isn't supported") · found writing `docs/spec/expressions.md` (lane SPEC) · filed 2026-10-11 against master `98a4ed71b`**

Repro:

    type C = { n: i32 }
    const c: C = { n: 1 }
    c.n++
    const xs = [1, 2]
    xs[0]++
    print(c.n)
    print(xs[0])
    // vl check: rc 1, "postfix `++` target must be an identifier", twice

Want:

    2
    2

#### Mechanism

The parser desugars a postfix `++`/`--` only when its operand is an `Ident`
(`compiler/parser.vl`, the `PLUSPLUS`/`MINUSMINUS` arm after a postfix chain). Any other
operand is reported with "postfix `++` target must be an identifier", and the operator is
consumed. Prefix `++c.n` and `++xs[0]` run, as do `c.n += 1` and `xs[0] += 1`. Each of
those evaluates its place once, by the compound-assignment rule. No ruling restricts
postfix increment to a bare name. The guide's operator section lists `x++` among the
postfix operators without such a limit.

#### Ablation

| variant | outcome |
| --- | --- |
| `c.n++` | parse error |
| `xs[0]++` | parse error |
| `++c.n` | runs, prints `2` |
| `++xs[0]` | runs, prints `2` |
| `let i = 1; i++` | runs |

#### Grading list

Grade both statement and expression positions, for example `const old = xs[0]++`. Use a
side-effecting index, such as `xs[next()]++`, to show that the place is evaluated once.
