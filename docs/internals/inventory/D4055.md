### D4055 — postfix `++` and `--` on a field or an element are a parse error, while the prefix forms run

**closed 2026-11-14 · runs, prints `2` `2` · was a loud check reject raised at the parse stage, `postfix `++` target must be an identifier` · closed by desugaring a field or element target as prefix `++` does, under the postfix wrapper (`parsePostfix`, `parser.vl`) · found writing `docs/spec/expressions.md` · filed 2026-10-11**

Repro:

    type C = { n: i32 }
    const c: C = { n: 1 }
    c.n++
    const xs = [1, 2]
    xs[0]++
    print(c.n)
    print(xs[0])
    // vl check: rc 1, "postfix `++` target must be an identifier", twice

Want:

    2
    2

#### Mechanism

The parser desugared a postfix `++`/`--` only over an `Ident`. A field or element target is now
the prefix form's compound write (`mkPreIncr`, its place one node) under the postfix `Unary`
that yields the old value. The statement-position spill (`spillCompoundPlace`, `emit_rewrite.vl`)
sees through that wrapper, so an effectful index runs once. As a value, a place whose receiver
or index has an effect is refused loudly ([D16217](D16217.md)), and the old value is recovered at
the place's own width ([D16216](D16216.md)). Any other operand keeps a parse error, now naming a
name, a field or an element.
