### D1739 — concatenating two literal unions is refused as `not defined for string and string`, because the string-concat gate needs ONE operand to be the `string` prim and neither is

**loud check reject · `vl check` rc 1, `operator '+' is not defined for string and string` · clause 2: the message names two `string` operands and declines to concatenate them · filed 2026-09-06 against master `15baeb884` · the residue [D1732](D1732.md)'s close leaves, since that close made the pin mirror `checkBinary` exactly and so inherited its gap · 0 corpus cells**

Repro:

    type K = "red" | "green"
    const src: K[] = ["green", "red"]
    function take(a: K, b: K) { print(a + b) }
    take(src[0], src[1])
    // vl check: rc 1,
    // operator '+' is not defined for string and string

Make either operand a real `string` and it runs: `b: string` prints `greenred`, and so does
assigning `b` to a `string` local first.

#### Mechanism

`checkBinary`'s `+` arm gates string concat on `isStringTy(lt) || isStringTy(rt)` — at least
one operand being the `string` PRIM — and only then tests mutual assignability. Two literal
unions are `TyUnion`s of `TyLit`s, so neither satisfies the gate; the arm is skipped entirely,
the arithmetic tail softens both to `string`, and the numeric test fails. The message renders
the SOFTENED pair, which is why it reads as a contradiction: the softening that makes the
message say `string and string` happens one line after the gate that could have used it.

**The numeric twin is the control.** `type N = 1 | 2` with `a + b` prints `3`, because the
arithmetic tail *does* consult `softenLitTy`. Only the string gate reads the unsoftened pair.

#### Grading list

* The nine ablation rows above. Four are needed and five are not, so the family is exactly
  "neither operand is the `string` prim, both are assignable to it".
* **The one-line close is measured, and its price is zero.** Softening the gate —
  `isStringTy(softenLitTy(lt)) || isStringTy(softenLitTy(rt))` — turns five of the refusing
  rows into `runs` (`K + K`, module scope, two inline sets, two bare literal types, two
  different aliases) and moves no other cell in the table, including both controls. It was
  measured and NOT taken here because it widens the accepted LANGUAGE rather than repairing a
  mirror, which is a different decision from [D1732](D1732.md)'s and wants its own lane.
* The pin mirror must move WITH it: `binOpDefinedFor`'s `+` arm now copies `checkBinary`'s gate
  verbatim, so softening one home without the other re-opens the divergence D1732 closed. The
  hole-parameter spelling (`function take(a, b) { print(a + b) }`) is the witness for that half.
