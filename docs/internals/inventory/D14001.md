### D14001 — an `if` of `{f: 1}` and `{f: t}` in a generic body builds the literal record at the pin's field type

**check-clean invalid wasm · clause 1 · open · found grading [D14000](D14000.md)'s arm-order grid · filed 2026-10-26 against master `01cfbcdeb`, pre-existing (invalid in both arm orders before and after D14000)**

Repro:

    function g<T>(t: T, b: boolean): i32 {
      const v = if b { {f: 1} } else { {f: t} }
      0
    }
    print(g("s", true))
    // vl check: rc 0.  vl run: the emitted module failed to validate inside `g`

Want:

    0

#### Mechanism

Two halves, ablated by probe on `2f8428da3`.

**Check.** The if-join records its kept-apart join for every pin to re-check (`noteTpJoinRow`,
D2832), but only when that join is a union. The record arms merge fieldwise, to `{f: i32 | T}`,
so no row was written; and the pin filters (`tpIfPinCheck`, `tpIfCmpNode`) asked for a union of
LISTS, while the pinned record join is `{f: i32 | string}`. Both filters now ask whether the
pinned join reaches a union of any kind, so the annotated `{f: T}` cells and the runtime-arm
cells at `T := string` are refused (at the call, and at the `r` arm respectively).

**Emit, still open.** The un-annotated witness re-checks clean at the pin — `{f: i32 | string}`
is a legal type for `v` — and the literal arm is still built at its template type `{f: T}`
substituted, `{f: string}`, holding an `i32`. At `T := f64` no union arises at all: the pinned
join is `{f: f64}`, and the `1` in the literal arm is built as an `i32` field there.
`{f: 1.0}` beside `{f: t}` runs at `f64`, and so does the non-generic `{f: 1}` / `{f: t: f64}`.
