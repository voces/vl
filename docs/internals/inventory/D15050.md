### D15050 — an un-annotated `??` of a nullable map and a wider map that stores alike builds invalid wasm

**closed · runs: the `??` reads at the result map's shape, as a value `if` join does · pins `tests/cases/maps/coalesce-nullable-map-into-wider-map.vl` · was check-clean invalid wasm, clause 1 · the `coalesce` cells of D2701's grid, which no `is` is needed for · found closing D2701 · filed 2026-11-02 against master `f4445ecd5`**

Repro:

    const a: {[string]: string} = Map()
    const n: {[string]: string} | null = a
    const w: {[string]: string | null} = Map()
    const r = n ?? w
    print(r.length)

Want:

    0

#### Mechanism

The join of `{[string]: string}` and `{[string]: string | null}` is the wider map (D2666), which
D2666 allows only for two maps that store alike, so both operands build one struct. The `??` block
was that struct, but `mapShapeOfExpr` answered the `??` its left operand's shape only when the
result type was the left's own map type. Here it fell through to the mono `{[string]: i32}` shape,
so the binding's cell and a `.length` read named that struct. A `??` over a nullable map whose
result and right operand are maps now answers the result type's shape (`coalesceMapJoinShape`,
`emit_classify.vl`), as a value `if` reads its join's.

#### Ablation

| ingredient removed | outcome | needed? |
| --- | --- | --- |
| `r` annotated `{[string]: string \| null}` | runs, prints `0` | **yes** |
| `w` typed `{[string]: string}` (one map type) | runs | **yes** |
| `w` typed `{[string]: i32}` (stores apart, so a union) | runs | **yes** |
| a value `if` in place of `??` | runs | **yes** |
