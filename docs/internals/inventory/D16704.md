### D16704 — a boxed float receiver, or an `f32` one, tested against an integer literal answers `false` for an equal value

**closed 2026-11-16 · runs, prints `true` · was check-clean wrong value, prints `false` · clause 1 · fixed in wasmEmit.vl and check_narrow_flow.vl: a box whose only number arm is a float tests the literal at that arm (`unionNumIsF64Only`, `unionNumIsF32Only`), a box with an integer and an `f64` arm tests both, and an `f32` receiver compares at `f32` with the checker's never-matching warning gone · pin: `tests/cases/narrowing/float-is-integer-literal-by-value.vl` · found closing [D3689](D3689.md) under its ruling · filed 2026-11-16 against master `2a0b71c1a`**

Repro:

    const v: f64 | string = 2.0
    print(v is 2)
    // was: vl check rc 0, vl run prints false

Want:

    true

#### Mechanism

`emitUnionLitIs` picked an integer literal's `i32` arm, so the tag test failed for a box holding
the value in its `f64` arm. An `f32` receiver was answered by the checker's never-matching fold
(a warning, `is check type '2' can never match a value of type f32`) and the emitter had no
`f32` compare. Under the ruling both compare by value.
