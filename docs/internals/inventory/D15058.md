### D15058 — `==` between a read of an un-annotated `Map()` of struct-union values and the union is refused at emit

**open · loud emit reject · clause 2 (check-clean, so the emitter owes it) · found by the `arm-nullable-string-list-field-eq` matrix's un-annotated map cells (D15054's close) · pre-existing, the same on master `49e25778e` · re-graded on master `0ab8a73b0` after #6004: still refuses · the map read's union is spelled structurally (`{k:i32}|{s:string}`) with no member set, so `emitUnionUnionEq`'s struct-union path (`lname == rname`) never meets `U`'s row; handed to the step-5 coercion lane as an acceptance cell for D15082 (coordinator, 2026-11-03) · probe `scripts/capability-probes/union-eq-unannotated-map-struct-union.vl` · filed 2026-11-03 against master `49e25778e`**

Repro:

    type U = { k: i32 } | { s: string }
    const q: U = { s: "a" }
    const m = Map()
    m["k"] = q
    const v = m["k"]
    if v != null { print(v == q) }
    // vl check: rc 0.  vl build: emitProgram: `==` over a struct union is not supported yet

Want:

    true

#### Mechanism

The map is un-annotated, so its value type comes from the store. The `==` lowering of a struct
union finds no row for the read's union and refuses with the codegen-gap sentence. The same
program with `const m: {[string]: U} = Map()` runs.

#### Ablation

| variant | outcome |
| --- | --- |
| this witness | loud emit reject |
| `const m: {[string]: U} = Map()` | runs, prints `true` |
| `const w: U = v` then `w == q` | runs, prints `true` |
| `m["k"] == q` read in place, guarded | loud emit reject |
| no null guard, `v == q` | loud emit reject |
