### D9173 — a list of un-annotated functions nested in another list, called inside a `.map` callback, has no function to call

**closed · runs, prints `6` · was loud emit reject, `emitProgram: call to unknown function`, `vl check` rc 0 · clause 2 · found closing [D9093](D9093.md) · filed 2026-10-21 against master `c2df9510f` · closed by pinning a list of function-list literals from the calls on its elements' elements (`monoPinNestedListElems`), and reading a callback receiver's pinned type through an alias, an element, a field or a map value (`monoPinnedAnnTyAt`, emit_mono.vl) · fixture `closures/hole-fn-list-reached-through-alias-called-in-callback.vl`, matrix `hole-fn-list-called-in-callback` · [D9230](D9230.md) filed for the receiver that is an un-annotated parameter**

    function inc0(a) { return a + 1 }
    function dbl(a) { return a * 2 }

#### Mechanism

D9093's close typed a list from a callback's calls only when the receiver was a binding whose
annotation a pin wrote. Two gaps, by grid origin rather than by message:

* A receiver that reaches a pinned list through another binding, a record field, a map value
  or a capture read no annotation; the receiver's type is now followed through those.
* A list nested in another list had no pin at all (direct calls `ws[0][1](3)` gave `nested
  arrays are not supported`); the outer literal is now typed `(fn)[][]` from the calls on
  `ws[i][j]` when every inner literal agrees.
