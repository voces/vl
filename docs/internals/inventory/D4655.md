### D4655 — a void function whose body ends in a call is never a tail call

**closed 2026-10-14 · runs — the witness prints `1000000` · when a void body falls off its end right after a direct call to a void user function, that call is rewritten to `return_call` (`emitFuncCode` → `emitVoidTailCall`) · fixture `tests/cases/functions/tail-call-depth-void-union-indirect.vl` · was trap after load (call stack exhausted) · filed 2026-10-14 against master `43c852e79`**

Repro:

    let total = 0
    function down(n: i32): void {
      if n == 0 { return }
      total = total + 1
      down(n - 1)
    }
    down(1000000)
    print(total)
    // vl check: rc 0.  was, vl run: wasm trap, call stack exhausted in `down`

Want:

    1000000

#### Mechanism

Only a `return` ever reached the tail-call rewrite, so a void body whose last statement is a
call fell off its end with the caller's frame still stacked. Nothing after the call can
observe that frame, so the call is in tail position: a `return_call` changes only stack depth
and the frames a backtrace shows. `emitFuncCode` now runs `emitVoidTailCall` after the body,
under the same conditions as D4654. A call followed by any other instruction, including an
enclosing block's `end`, stays a `call`.
