### D17817 — a `const` bound to an element of a function list inside the hole parameter it was handed to calls the element at the wrong signature

**loads then traps · `wasm trap: indirect call type mismatch` · clause 1 (`vl check` rc 0, the module builds and traps) · open · the inline call `ys[0](3)` prints `4` · filed 2026-11-28 against master `f011dc749` · owner COV-IS**

Repro:

    function dbl(a: f64): f64 { return a * 2.0 }
    const g = (a) => a + 1
    const xs = [g, dbl]
    function walk(ys) { const v = ys[0]; print(v(3)) }
    walk(xs)
    // vl check: rc 0.  vl run: wasm trap: indirect call type mismatch (in `walk`)

Want:

    4

#### Mechanism

Not traced. `g` is called only through `v` inside `walk`'s instance, at `(i32)`; the list stores
its members at one closure signature, and the `const`'s call goes through a `call_indirect` at
another, so the element's function is called at a type it was not built at. A call of `g` at both
signatures at module scope, or the read inline, gives the members one rep and the program runs.

#### Ablation

| ingredient removed | outcome | needed? |
| --- | --- | --- |
| the `const`: `print(ys[0](3))` | runs, `4` | **yes** |
| the call's `i32`: `v(3.0)` | runs, `4` | **yes** |
| the parameter: `const v = xs[0]` at module scope | runs, `4` | **yes** |
| `g`'s calls at both signatures at module scope first | runs, `4` | **yes** (`g` instanced only in `walk`) |
| the element read: `ys[1]` (`dbl`) | runs, `6` | **yes** (the lambda member) |
| a tagging walk `for v in xs { print(v(3)) }` at module scope | the same trap | no |
