### D17817 — a `const` bound to an element of a function list inside the hole parameter it was handed to calls the element at the wrong signature

**runs, prints `4` — CLOSED 2026-11-28: a binding initialised or written with an element or field read is a stored value, which its calls read at the slot's stored signature and which instances nothing at its delivery (emit_elab `elabStoredRead` in `elabAnnotatedDeliveryRows`; coordinator ruling: the one reader of a stored slot); pinned by `tests/cases/closures/stored-function-read-through-a-const-in-a-hole-parameter*.vl` and its neighbours. One hole parameter handed two storages of the member at different reps still traps, filed separately. Was: loads then traps · `wasm trap: indirect call type mismatch` · clause 1 (`vl check` rc 0, the module builds and traps) · open · the inline call `ys[0](3)` prints `4` · filed 2026-11-28 against master `f011dc749` · owner COV-IS**

Repro:

    function dbl(a: f64): f64 { return a * 2.0 }
    const g = (a) => a + 1
    const xs = [g, dbl]
    function walk(ys) { const v = ys[0]; print(v(3)) }
    walk(xs)
    // vl check: rc 0.  vl run: wasm trap: indirect call type mismatch (in `walk`)

Want:

    4

#### Mechanism

`elabAnnotatedDeliveryRows` took the un-annotated `const v = ys[0]` as a delivery of a function
value: every call through `v` passes `(i32)`, so it instanced each function the initialiser may
hold there (`g` at `(i32)`). But `ys[0]` reads a list that stores its members at `(f64) => f64`,
`dbl`'s; with two instances of `g` the list's slot took a degenerate closure, and the call's
`call_indirect` at `(f64) -> f64` trapped. A read of a stored slot is read at the slot's rep and
instances nothing at the delivery.
