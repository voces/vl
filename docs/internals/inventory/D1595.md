### D1595 — scratch-frame detection guessed which of two same-named slots a read denotes

**closed · filed 2026-09-04 against `257b696f` (D1593's landing, on master `83db028a`) · consumer report VL-042 (glean, `/home/verit/glean/docs/vl-issues.md`)**

Repro:

    for n in 0 to 1 { print(n) }
    if true {
      const n = "hi"
      print(n)
    }
    // before: vl check rc 0; vl run -> invalid module,
    //   "unknown local 3: local index out of bounds"
    // after:  0 1 hi

#### Mechanism

A frame's scratch frames (the string-op quad, the map/push/`__array_new__`/coalesce/HOF
frames) are sized by a DETECTION sweep that runs before the body is lowered, and that sweep
runs with the scope stack EMPTY — `collectStartLocals` and `buildLocals` both pop their last
frame before returning. So every type-directed detector resolves an identifier through
`declaredSlotOf`'s flat fallback, which hands back the FIRST `localNames` slot of that name.

With two slots of one name that is a guess. Here `localNames` is `["n", "n#b", "n"]` — the
loop variable, its bound, and the block's `const n` — and the guess is the i32 loop var, so
`print(n)` is not a string print, `fnUsesStrOp` stays false and `fbBeginFunc` reserves no
string frame. The EMIT pass then resolves the same read through the LIVE scope stack, gets the
block's string slot, and writes `local.set` against the frame that was never declared. `vl
check` returns 0 and the engine refuses the module. The start function's locals vector is 3
locals before the fix and 14 after (the 11-slot string frame), which is exactly what the old
compiler already emitted for the same program with `const pad = "x" + "y"` beside it.

The fix keeps ONE resolution rather than adding a second scan: the detection asks its question
once per CANDIDATE slot. `dupScanRun` sets `dupSlotBias` to select the k-th same-named match
and re-runs the sweep while `declaredSlotOf` reports an unvisited later match of a different
rep; the `fnUses*` flags only ever go true and every frame list dedupes, so the passes OR.
A frame that binds no name twice takes the flat scan's early return and emits the bytes it
always did — the compiler's own seed grew 1,065 bytes, its added source. Over-reserving is the
safe direction: an unused frame is spare locals, an unreserved one is invalid wasm.

#### Ablation

Held fixed: a module-scope `for n` loop and a top-level block binding `n`. Graded on the
pre-fix compiler.

| ingredient removed | outcome | needed? |
| --- | --- | --- |
| the name collision (loop var `n` → `q`) | runs | **yes** |
| the name collision (block `const n` → `m`) | runs | **yes** |
| the scratch-needing op (`print(n)` → `print(1)`) | runs | **yes** |
| the block (`const n` at top level, a global) | runs | **yes** |
| the source ORDER (block first, then the loop) | runs | **yes** |
| the loop variable (two SIBLING blocks bind `n`) | invalid wasm, same message | no |
| the for-RANGE loop (`for n in [1, 2]`) | invalid wasm, same message | no |
| module scope (the whole collision inside a function) | invalid wasm, same message | no |
| the direct string (`const n = mk()`, `print(n.msg)`) | invalid wasm, same message | no |
| a union anywhere (D1593's ingredient) | invalid wasm, same message | no |
| the string frame → an i32 `.push` frame | runs | no |
| the string frame → an `__array_new__` frame | runs | no |
| the string frame → a map frame (`Map()` in the block) | runs | no |
| the string op made syntactic (`print(n + "b")`) | runs | no |
| the string frame → a REF-list `.push` frame | **loud emit reject**, other clause | no |
| CONTROL: `const pad = "x" + "y"` added at top level | runs | — |

The four `runs` rows above are what makes this the TYPE-DIRECTED detectors' defect and not
every detector's: an i32 `.push`, `__array_new__`, a `Map()` call and a `+` with a literal
operand are all claimed from the SYNTAX, so no slot is resolved and no guess is made. The
REF-list push is the same mechanism in the OTHER clause — its receiver's ELEMENT type must be
resolved, so the shadowed name reaches it, and `const p: E[] = []  p.push(mk())` inside the
block refuses `emitProgram: a ref-element list op needs its receiver's element type known
before the body is lowered`. One fix moves both. The order row is the shape of the bug stated
as a symptom: first-match means the collision is invisible whenever the frame-needing binding
happens to come first.
