### D16794 — a parenthesised `??` over a hole map parameter's `get`, read as an `f64`, builds an invalid module

**check-clean invalid wasm · clause 1 · `vl check` rc 0 · found grading the S3.4a floor-removal experiment ([D16714](D16714.md)) · filed 2026-11-16 against master `d59e4401` · the same read through [D16795](D16795.md) traps the compiler and through [D16797](D16797.md) refuses at emit**

Repro:

    const m: {[string]: f64} = Map()
    m.set("a", 1.5)
    t(m)
    function t(q) { print((q.get("a") ?? 0.0)) }
    // vl check: rc 0.  vl run: invalid module inside `t`, "type mismatch: expected i32, found f64"

Want:

    1.5

#### Mechanism

Not located yet. The parentheses are the ingredient: the same `??` unparenthesised, or bound first
(`const v = (q.get("a") ?? 0.0)`), runs. The parenthesised node seems to keep a type from before
the argument pinned the parameter's value, and the emitter reads it as `i32`. Declared before the
call, the read-only map floor refuses the program today, so only this order reaches it. With the
floor lifted, both orders build the invalid module.
