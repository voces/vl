### D2981 — D2966's store note suggested an annotation a later read of the binding refuses

**loud check reject, by design, and the diagnostic no longer suggests the refused annotation · fixed with D2977 · found by the #3249 review grid · filed and fixed 2026-09-28 against master `264fd86f1`**

Repro:

    function ti(a: i32): i32 { a }
    const B = 1.5
    let w = 0
    w = B
    print(ti(w))
    // master: cannot assign f64 to i32 — `w` on line 3 has no annotation, so its literal
    //         defaulted to `i32`; annotate it: `let w: f64 = …`   (and `ti(w)` then refuses)
    // now:    cannot assign f64 to i32

#### Mechanism

D2966 withheld a store note only when another STORE to the binding refused the suggested type;
it never looked at the binding's reads. A whole scalar store's note now goes through the same
read check as D2977's read notes (`numLitReadsRefuted` / `numLitUseAccepts`): every read of the
binding in its declaring top-level statement must take the suggested type, and `ti(w)` does not.

#### Ablation

| ingredient removed | outcome | needed? |
| --- | --- | --- |
| the `i32` read (`print(w)`) | note, `let w: f64 = …`, which then runs | **yes** |
| the non-literal store (`w = 2`) | checks | **yes** |
