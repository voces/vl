### D16698 — a spread binding of a generic function name in a generic body traps at a field receiver and in a spread initialiser

**loads then traps · `wasm trap: indirect call type mismatch` · clause 1 · open · `vl check` rc 0 · the positions [D16695](D16695.md)'s close did not reach; the push onto a named list runs · found grading D16695's position matrix · filed 2026-11-16 against master `05297d752`**

Repro:

    function id<T>(x: T): T { return x }
    function run<T>(_x: T) {
      const o: {rs: ((x: T) => T)[]} = { rs: [] }

#### Mechanism

Not traced to a fix. At the field receiver no delivery reaches `src`'s element (temporary probe:
`elabSlotDeliveries` empty, `pins=0`, the uncalled arm), since the delivery walk's spread arm finds
the receiver's binding through `elabPushedOnto`, which takes a name only. In the spread initialiser
`const rs: ((x: T) => T)[] = [...src]`, `src` is pinned per instance (`i32`, `string`), and the second
instance still traps: the copy into `rs` is the shared part.
