### D15806 — a map of records whose function field holds un-annotated functions returning different types builds an invalid module once the one-result judgment is lifted for it

**loud check reject today, and must not become an invalid module · a refutation pin: reachable only under a refused change, lifting `holeSlotJudge`'s one-result judgment for a map value (the [D15801](D15801.md) map-value family) · under that lift `vl run` reports `invalid module`, `type mismatch: expected (ref null $type), found (ref $type)` in the module's top-level code · found grading D15801's map-value family · filed 2026-11-12 against master `0671904bf`**

Repro:

    function inc0(a) { return a + 1 }
    function half(a) { return a / 2.0 }
    const m = Map()
    m["a"] = { f: inc0 }
    m["b"] = { f: half }
    const r = m["b"]
    if r != null { print(r.f(3)) }

#### Mechanism

Today the judge refuses it at check, `cannot write 'half' to 'm[].f'` ([D9370](D9370.md)'s
ruling, since overruled for a list by [D15791](D15791.md)). A scratch compiler whose
`holeSlotJudge` passes `holesApart` for every slot read lets it through, and the tag decision
tags the set. The module it emits stores a non-null record reference where the map's value
slot holds a nullable one, and the validator rejects it. A lift of the map-value family must
make this program run, or keep refusing it, before it ships.

#### Ablation

| spelling, under the lift | outcome |
| --- | --- |
| the witness | invalid module |
| a list of the records as the map's value, `m["k"] = [{ f: inc0 }, { f: half }]` | loud emit reject, `ref valtype with no interned shape` |
| the same, through `m.set` | loud emit reject, `unsupported map value type` |
| one result type, `dbl` for `half` | runs, on master too |
