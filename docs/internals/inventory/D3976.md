### D3976 — a written `let` alias of a capture cell's read, reassigned with a generic and returned, builds invalid wasm

**closed 2026-10-11 by lane CK · runs · was check-clean invalid wasm · clause 1 · closed by #3508 (a call or delivery through a written `let` instances each generic written to it) · found in review of #3501 (`rv3501/r05`); re-witnessed under ruling C (#3500) · filed 2026-10-10 against master `56f77d80f`**

Repro:

    function inner<U>(u: U) { print("I"); print(u) }
    function other<V>(v: V) { print("O"); print(v) }
    function mk(): (b: boolean) => void {
      let k = inner
      const flip = () => { k = other }
      flip()
      let r = k
      r = inner
      return r
    }
    mk()(true)
    // vl check: rc 0.  vl run: the emitted module failed to validate inside `mk`

Want:

    I
    true

#### Mechanism

Not located. `r` is a `let` initialized with the cell's read and then written (`r = inner`), so the
alias rule of D3948, which follows only aliases never written after their initializer, does not
apply, and the cell's element keeps the generic seed's un-pinned type while `r` is built at the
return type. The filed witness wrote the concrete `q` into `r`, which ruling C (#3500) now refuses
at check time; this is the generic-write spelling the ruling allows.
