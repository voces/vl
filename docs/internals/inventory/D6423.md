### D6423 — a binding annotated with a type parameter, written with one generic and called at another type than the parameter it was written from, is check-clean invalid wasm

**closed 2026-10-18 by lane L1 · now a loud emit reject, "parameter `a` of `mid` is called at two function types that no parameter per type separates" · was check-clean invalid wasm · clause 1 · a hole-generic parameter whose flow slot holds two pins, none of which closes, no longer takes its argument's recorded type, which names one of them; the refusal is recorded without halting, so the compile still asks every split it reaches · open as [D6470](D6470.md) (clause 2: one value called at two types wants a per-call-type record) · pins: `tests/cases/functions/error-generic-fn-value-param-copied-into-written-binding.vl`, `tests/cases/functions/error-generic-fn-value-param-copied-into-unannotated-binding.vl` (un-annotated, in a branch, from a function) · found closing [D6372](D6372.md) · filed 2026-10-18 against master `066d19373`**

Repro:

    function same<T>(k: T): T { k }
    function take(a) { print(a("x")) }
    function take2(a) { print(a(3)) }
    function mid<F>(a: F, a1: F) {
      let b: F = a1
      b = a
      take(a)
      take2(b)
    }
    mid(same, same)
    // vl check: rc 0.  vl run: the emitted module failed to validate inside `take`: type mismatch: expected i32, found (ref $type)

Want:

    x
    3

#### Mechanism

From the ablation only. `a` and `b` hold one generic, called at `string` through `a` and at
`i32` through `b`; `F` takes one function type, and the written binding makes the two reads one
value, so `take` and `take2` are built at one instance and one of them reads the wrong type.
