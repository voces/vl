### D3529 — a module-level `i64[]` initialised from a one-element list of a two-width literal union is built as a list of boxes

**check-clean invalid wasm · clause 1 · open · found by lane LC's literal-union grid (4 of 5,632 cells, `w2_*_i64_elem`) · the same on master `f6e17953b` · filed 2026-10-03 against master `f6e17953b`**

Repro:

    type D = 9000000000 | 1
    function mk(): D { 1 }
    const xs: i64[] = [mk()]
    print(xs[0])
    // vl check: rc 0.  vl run: invalid module, "expected (ref null $type), found (ref $type)"

Want:

    1

#### Mechanism

Not confirmed. The disassembly declares the global `xs` as a list of union boxes (an array of
`(ref null $box)`), while the read and the print take it as `i64[]`. `D[]` is assignable to
`i64[]` at the type level (every literal fits `i64`), so the list literal is never converted
element by element, and the module global's cell appears to take its rep from the literal
rather than the annotation. The `f64[]` spelling, which only the element-wise conversion
admits (D3523), builds correctly.
