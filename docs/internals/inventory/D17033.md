### D17033 — a generic returning its union at the arm free of the type parameter passes the checker, then trips emit's guard on a type written after an emit memo read it

**closed 2026-11-20 by lane F1 · now runs, `1` · was a loud emit reject, clause 1, `vl check` accepts the program · `internal: an emit-phase write changed a type an emit memo may hold` (`emit_sections.vl`) · a generic union alias applied while emit monomorphizes (`synthTypeRefTy` → `applyGenAliasTys`) is filled in its own fresh scope, but `fillUnionDeclMembers` bumped the epochs naming no row, so the emit epoch moved; it now names the placeholder row unless its members reach it, as the record fill does · pin: `tests/cases/generics/union-alias-instance-applied-at-emit.vl`, which also holds STORE's record-arm spelling (`W<T> = { n: i32, v: T } | { s: string }`, the same write) · found by lane F2 ablating [D17032](D17032.md) · filed 2026-11-20 against master `de317fa31`**

Repro:

    type U<T> = { k: "g", n: i32 } | { k: "h", v: T }
    function mk<T>(x: T): U<T> {
      return { k: "g", n: 9 }
    }
    const a = mk(3)
    if a.k == "g" { print(1) }
    // vl check: rc 0.  vl run: emit error, internal: an emit-phase write changed a type an emit memo may hold

Want:

    1

#### Mechanism

Mono's `synthTypeRefTy` applies `U<T>` at a new argument during emit. `applyGenAliasTys` mints
the instance's placeholder inside `tyFreshBegin`, and its union arm fills it through
`fillUnionDeclMembers`, whose `tyMutBump(-1, -1)` named no row, so the write counted as one an emit
memo could hold and `emitProgram`'s window check failed. The record arm already bumps naming its
fresh row.
