### D1777 — an OBJECT literal and a CALL argument list eject an interior comment the same way a list literal did, and the same anchor closes both

**runs today and must keep running · a `vl fmt` comment RELOCATION on a `vl check`-clean program · the sibling [D1776](D1776.md) closed for `ArrayLit` alone**

Repro (runs, prints `6`):

    const o = {
      a: 1,
      // the b field
      b: 2,
    }
    function g(x: i32, y: i32): i32 { x + y }
    const s = g(
      1,
      // the second argument
      2,
    )
    print(o.a + o.b + s)
    // vl check: rc 0.  vl run: 6.
    // vl fmt: `const o = { a: 1, b: 2 }` then a BLANK line then `// the b field`; and
    //         `const s = g(1, 2)` then a BLANK line then `// the second argument`.

#### Mechanism

The same one [D1776](D1776.md) names, at two more callers. `objectLiteral` and the call
printer render their items through `expr` and hand them to `wrapList`; neither reads the
comment table, so a comment inside the braces or the parens is still pending when the
construct is finished and the next `emitLeadingComments` emits it after the whole statement.

D1776 fixed `arrayLiteral` by testing `commentInCharSpan` over the node's own span and
falling through to `sliceFallback`, which reproduces the construct from source and calls
`markVerbatim` so the comment is not re-emitted. Nothing about that anchor is list-specific —
it is what `ifExpr` does — so the fix here is the same two lines at each of the two printers.
It was left out of D1776 deliberately: that PR's rule is a LIST layout rule, and widening a
comment anchor to two more constructs re-flows a different population, which wants its own
tree sweep and its own byte-identity reading.

#### Ablation

Every row is `vl check` rc 0 and prints the same value before and after.

| construct | comment inside it | `vl fmt` |
| --- | --- | --- |
| `[1, 2, /* … */ 3]` — a list literal | yes | pinned (D1776) |
| `{ a: 1, // … \n b: 2 }` — an object literal | yes | **ejected** |
| `g(1, // … \n 2)` — a call argument list | yes | **ejected** |
| `import { a, // … \n b } from "…"` — an import name list | yes | rebuilt on one line, comment ejected |
| the same object with the comment AFTER the `}` | no | stays put |

Needed: a comment whose start offset lies inside the construct's own span, at a printer that
has no comment-aware path. Not needed: the field or argument count, the position, or whether
the construct fits one line.

#### Grading list

* [D1776](D1776.md)'s own witness and the four list-layout fixtures, which must keep their
  current output — the anchor must not widen to a list that has no comment.
* The import-name row above: `importDecl` already rebuilds a braced name list on one line and
  says so in its comment, so a fix there is a decision, not a bug fix.
* `vl fmt` idempotence and tree-wide `--check` cleanliness, which a verbatim slice can only
  keep if the slice is its own fixed point at the indentation the construct is re-emitted at.
