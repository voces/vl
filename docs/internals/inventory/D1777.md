### D1777 — an OBJECT literal and a CALL argument list eject an interior comment the same way a list literal did, and the same anchor closes both

**closed 2026-09-06 — the witness runs and `vl fmt` reproduces it byte for byte · was a `vl fmt` comment RELOCATION on a `vl check`-clean program · fixed by giving `objectLiteral` and `callTail` the verbatim anchor [D1776](D1776.md) gave `arrayLiteral`, over the GAPS between items rather than the whole span**

Repro (runs, prints `6`):

    const o = {
      a: 1,
      // the b field
      b: 2,
    }
    function g(x: i32, y: i32): i32 { x + y }
    const s = g(
      1,
      // the second argument
      2,
    )
    print(o.a + o.b + s)
    // vl check: rc 0.  vl run: 6.
    // vl fmt: `const o = { a: 1, b: 2 }` then a BLANK line then `// the b field`; and
    //         `const s = g(1, 2)` then a BLANK line then `// the second argument`.

#### Mechanism

The same one [D1776](D1776.md) names, at two more callers. `objectLiteral` and the call
printer render their items through `expr` and hand them to `wrapList`; neither reads the
comment table, so a comment inside the braces or the parens is still pending when the
construct is finished and the next `emitLeadingComments` emits it after the whole statement.

D1776 fixed `arrayLiteral` by falling through to `sliceFallback`, which reproduces the
construct from source and calls `markVerbatim` so the comment is not re-emitted. Nothing about
that anchor is list-specific — it is what `ifExpr` does — so the close is the same test at each
of the two printers. Two things it could not simply copy:

* **The span it tests is the GAPS between the items, not the whole node.** An item that
  renders itself already hosts its own comments — a block-bodied lambda flushes them through
  `blockExpr` — so the whole-span test froze a construct that had no defect. That is
  [D1787](D1787.md), filed and fixed with this, and `arrayLiteral` moves to the same predicate.
* **A call's anchor is the ARGUMENT LIST, not the call.** The callee is already rendered into
  `head`, and the node's span reaches back over a whole receiver chain, so `callTail` slices
  `[callArgOpenAt(node, ix), nodeEndOf(ix))` and leaves the chain layout alone.

#### Ablation

Every row is `vl check` rc 0 and prints the same value before and after.

| construct | before | after |
| --- | --- | --- |
| a list literal, comment between two elements | pinned (D1776) | pinned |
| an OBJECT literal, comment on its own line between two fields | **ejected** | pinned |
| an object literal, comment TRAILING a field | **ejected** | pinned |
| a CALL argument list, comment on its own line between two arguments | **ejected** | pinned |
| a call argument list, comment TRAILING an argument | **ejected** | pinned |
| `import { a, b } from "…"` with a comment inside the braces | rebuilt on one line | unchanged |
| the same object with the comment AFTER the `}` | stays put | stays put |

Needed: a comment whose start offset lies in the construct's own PUNCTUATION, at a printer
with no comment-aware path. Not needed: the field or argument count, the position within the
list, or whether the construct fits one line.

#### Grading list

* [D1776](D1776.md)'s own witness and the five list-layout fixtures, which must keep their
  current output — the anchor must not widen to a list that has no comment.
* [D1787](D1787.md)'s witness, the negative control: a comment INSIDE an item must leave the
  construct free to reformat, in all three brackets.
* The import-name row above: `fmtImport` already rebuilds a braced name list on one line and
  says so in its comment, so a change there is a decision, not a bug fix.
* `vl fmt` idempotence and tree-wide `--check` cleanliness, which a verbatim slice can only
  keep if the slice is its own fixed point at the indentation the construct is re-emitted at.
