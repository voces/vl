### D3860 — a capturing hole lambda literal, written from a nested lambda into a function-scope alias of a module-scope hole lambda, traps

**closed (2026-10-08, lane SC) · was loads then traps · found grading D3843's mutate-then-read matrix · filed 2026-10-08 against master `67ff2a485` · pins: `tests/cases/closures/cell-written-hole-lambda-tail.vl`**

Repro:

    const c = (y) => y + "C"
    function m(x: string) {
      let d = c
      const g = (s: string) => { d = (y) => y + s }
      g("!")
      print(d(x))
    }
    m("a")
    // vl check: rc 0.  vl run: wasm trap inside `g`, exit 70

Want:

    a!

#### Mechanism

`g`'s body is the assignment, so `g` returns the value written, and its tail is lowered as a
store and then a re-read of the capture cell. `assignTargetReReads` allowed that re-read only
when the cell's type and the value's type are the same, and the written literal is typed at its
holes while the cell holds the instance D3857 gives it. So the tail was no value, `g` still had
a closure result, and its body ended in `unreachable`. Every function value is one closure rep,
so a function-typed cell's re-read now counts as the value written. With `let d = (y) => …` in
place of the module-scope `c`, the same write is still the loud `ref valtype with no interned
shape` refusal.

#### Ablation

| ingredient removed | outcome | needed? |
| --- | --- | --- |
| the module-scope lambda (`let d = (y) => y + "C"`) | loud emit refusal | **yes** |
| the written literal's hole (`(y: string) => y + s`) | runs, `a!` | **yes** |
| the write (`print(d(x))` alone) | runs, `aC` | **yes** |
| the capture's name differing from the lambda's (`(c: string) => { d = (y) => y + c }`) | traps the same | no |
