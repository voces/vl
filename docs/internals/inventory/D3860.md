### D3860 — a capturing hole lambda literal, written from a nested lambda into a function-scope alias of a module-scope hole lambda, traps

**loads then traps · found grading D3843's mutate-then-read matrix · filed 2026-10-08 against master `67ff2a485`**

Repro:

    const c = (y) => y + "C"
    function m(x: string) {
      let d = c
      const g = (s: string) => { d = (y) => y + s }
      g("!")
      print(d(x))
    }
    m("a")
    // vl check: rc 0.  vl run: wasm trap inside `g`, exit 70

Want:

    a!

#### Mechanism

Not ablated to a site. The trap is inside `g`, where the written literal is built, so the
literal's closure and the alias's function type disagree. Without the module-scope lambda
(`let d = (y) => y + "C"`) the same write is the loud `ref valtype with no interned shape`
refusal, so the alias is what turns that capability gap into a trap. D3865's fix (#3452) does
not move it.

#### Ablation

| ingredient removed | outcome | needed? |
| --- | --- | --- |
| the module-scope lambda (`let d = (y) => y + "C"`) | loud emit refusal | **yes** |
| the written literal's hole (`(y: string) => y + s`) | runs, `a!` | **yes** |
| the write (`print(d(x))` alone) | runs, `aC` | **yes** |
| the capture's name differing from the lambda's (`(c: string) => { d = (y) => y + c }`) | traps the same | no |
