### D3078 — a function body reading an un-annotated module global declared after it checks against the global's placeholder

**check-clean invalid wasm · clause 1 · open · found grading [D3062](D3062.md)'s close · the same on master `bae51e6b7` · filed 2026-09-28 against master `bae51e6b7`**

Repro:

    function f2(x: string) { print(x + k) }
    const k = 2 + 3
    f2("s")
    // vl check: rc 0.  vl run: invalid module inside `f2`

#### Mechanism

Pass 1.5 hoists an un-annotated top-level binding whose initializer is not a scalar literal as `TY_ERR` until pass 2
reaches it, so a function body checked before that point reads the global as an error type and
every diagnostic over it is suppressed; `string + i32` is admitted and lowered. With the global
declared first the program is refused (`operator '+' is not defined for string and i32`). A
generic body is the same, and its deferred constraints are never recorded either.

#### Ablation

| ingredient changed | outcome | needed? |
| --- | --- | --- |
| `const k` declared before `f2` | check reject | **yes** (the order) |
| `const k: i32 = 2 + 3`, annotated | check reject | **yes** (no annotation) |
| `const k = 5`, a scalar literal | check reject | **yes** (not a scalar literal) |
| `const k = [1, 2]` read as `k[0]` | invalid wasm | no |
| `function f2<T>(x: T)` called with `"s"` | invalid wasm | no |

#### Grading list

The generic spelling, caller-first and callee-first: a `print(x + k[0])`, `x == k[0]`,
`let y = x; y = k[0]` or `return k[0] + x` body at a `string` pin, with `k` declared after both
functions, is invalid wasm in both orders (the D3062 lane's `tdzgen.py`, its `glast` cells).
