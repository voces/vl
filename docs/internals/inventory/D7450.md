### D7450 — an un-annotated `if` joining a narrowed `K | null` atom and a `string | null` builds invalid wasm

**closed 2026-10-20 by lane L6 · runs, prints `b` · was check-clean invalid wasm · clause 1 · the join's nullable-string classifier asked whether the `if` heads its chain only inside a function body, so at module scope it answered false and the then arm's atom kept its `i32` rep; `ifIsChainHeadIn` now walks the module when the frame is -1, and `ifJoinIsNulString` takes a chain of any length · pin: `tests/cases/literal-unions/nullable-atom-joins-nullable-string-module-scope.vl` · found closing [D7448](D7448.md) · present on master `573358403` · filed 2026-10-20 against master `573358403`**

Repro:

    type K = "a" | "b"
    const k: K | null = "b"
    const n: string | null = null
    const r = if k != null { k } else { n }
    print(r ?? "rnull")
    // vl check: rc 0.  vl run: invalid module, expected i32, found (ref null $0); $0 is `string`

Want:

    b

#### Mechanism

The join of `K` and `string | null` is `string | null`. `exprNulLitUnion` decodes a then
arm's atom only for an `if` that heads its chain, and `ifIsChainHeadIn` answered false for
any frame that was not a function body, so at module scope the `if` took the atom's `i32` rep
while its else arm stayed the nullable string ref.
