### D15560 — a returned binding of a call's record, beside a record of another function set, compiles to invalid wasm

**open · check-clean invalid wasm · clause 1 · the same pair with a record literal for the binding runs since [D15559](D15559.md) · found closing D15559 · filed 2026-11-08 against master `2a59f035`**

Repro:

    function inc0(a) { return a + 1 }
    function dbl(a) { return a * 2 }
    function mk() { return { fs: [dbl] } }
    function pick(b) {
      const c = mk()
      const a = { fs: [inc0] }
      if b { return a }
      return c
    }
    print(pick(false).fs[0](3))
    print(pick(true).fs[0](3))

Want:

    6
    4

#### Mechanism

`c` holds `mk`'s result, whose row is `mk`'s own: its set is `{dbl}`, and `mk` has other callers, so it cannot take `pick`'s joined set. The return of `c` needs a record copy at `pick`'s result row, or a ruling that the two rows, which differ only by a set whose ids are decided together, are one row.

Measured 2026-11-08 on the D15563 fixpoint: `mk`'s literal mints `#anon0`, `pick`'s `a` mints `#anon1`, and `pick`'s result is `#anon1`. Both rows store `fs` as the same `i32` list, their row keys (`repRowKey`) are both `{fs:=>[],}` and `structFieldCodesEq` holds, yet `repStructSlotsTwin` is 0, so the type section emits two struct types. Their row ids (`repRowId`) differ because each row's type holds its set's function type with its own holes, `(_) => _` at two arena indices, and the row id keys a list field's element by its canonical id, which keys a hole by its index. A tagged set's id is an `i32` whatever its signature, so a row keyed by rep would key a tagged function position as that id, and the two rows would be one. Where to do that, without letting a declared `{fs: i32[]}` record alias these rows through `structIndexOfTy`'s canonical alias or `pin_spell`'s row lookup, neither of which checks layout, is the open decision.
