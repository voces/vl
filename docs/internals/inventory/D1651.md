### D1651 — `vl fmt` sorts the names inside an `import { … }`, and ten checked-in fixtures were never formatted: no gate reaches `tests/`

**closed 2026-09-05 — the witness runs and is now `vl fmt`-clean · was a `vl fmt --check` failure on ten checked-in files, invisible to every gate · the PRINTER is correct and the files were stale; fixed by formatting them · found beside D1646, when the whole-tree `vl fmt` sweep left one file drifting for a reason that had nothing to do with that fix**

Repro (runs, prints `1`; before: `vl fmt --check` rc 1, now rc 0):

    // file: lib.vl
    export type Tag = "a" | "b"
    export function rank(t: Tag): i32 { return 1 }
    export function note(t: Tag): i32 { return 0 }
    // file: entry.vl
    import { Tag, rank, note } from "./lib"
    const t: Tag = "a"
    print(rank(t) + note(t))

#### Mechanism

`fmtImport` reconstructs a braced import from the token stream and calls `fmtSortNames` on the
items before `wrapList` reflows them. The sort is deliberate, and the printer says why: a
`{ … }` list is a SET, order carries no meaning, so sorting it makes the wrapped one-per-line
block read alphabetically and a duplicate or stale import easy to spot. The key is
case-sensitive code-point order over the item's FULL text, so `Tag` sorts before `note` and an
`a as b` item sorts by `a` (`export { cube as cubed, square }`).

Two things it does NOT do, both measured rather than read: it does not re-order import
STATEMENTS — `emitImports` walks the token stream in source order, so `./lib2` written first
stays first — and a comment written INSIDE the braces takes the verbatim path, which keeps the
author's order untouched.

So the printer is right and the checked-in files are stale. The reason nobody noticed is the
gate's reach: `lint-self.sh`'s fmt half runs `find compiler std scripts`, and `tests/` is not
passed in at all. It is not a tolerant check — it is an absent one.

The ten are the safe slice and the only one closed here: for each, the diff is a single line and
the NAME SET is unchanged — only the order inside the braces moves — so no fixture can be
testing anything the reformat disturbs. The other 852 have real layout drift and stay as they
are.

#### Ablation

| case | `vl fmt` |
| --- | --- |
| `import { c, a, b }` | **sorted** to `{ a, b, c }` |
| `export { square, cube as cubed }` (re-export) | **sorted** to `{ cube as cubed, square }`, by the source name |
| `import { a, b, c }` already sorted (control) | unchanged |
| two import STATEMENTS, paths out of order (control) | unchanged — statement order is source order |
| a comment inside the braces (control) | unchanged — the verbatim path keeps the author's order |

Needed: a braced name list whose items are not already in code-point order, and no comment
inside the braces. Not needed: the module path, `import` versus a re-export, or the arity.
