### D17066 — a union compare against a `K | null` atom operand that is no place has no lowering

**closed 2026-11-23 by lane IR-S1 · now runs, `false` `true` `false` · was loud emit reject · the operand is read once as its id into its own slot (`unionEqOperandSlot`), tested against `-1` for the null leg and decoded from the slot (`atomStrTail`), in source order beside a staged box · pin: `tests/cases/unions/union-eq-nullable-atom-call-operand.vl` · filed 2026-11-23 against master `d6341e57`**

Repro:

    type K = "a" | "b"
    type U = i32 | K
    let gk: K | null = null
    function ck(): K | null { return gk }
    function g(u: U) { return u == ck() }
    print(g("a"))
    gk = "a"
    print(g("a"))
    gk = "b"
    print(g("a"))
    // vl check: rc 0.  vl run (was): emit error, a union `==` against a `K | null` atom operand that is no place is not supported yet

    false
    true
    false

#### Mechanism

`emitUnionConcreteEq` (`compiler/wasmEmit.vl`) decodes a `K | null` atom operand twice: once
for its null leg and once for the atom compare. A place is re-read; a call cannot be, and no
slot holds the decoded operand, so the arm refuses instead of running the call twice. A string
operand that is no place already reads once into `unionEqOperandSlot`; the atom operand needs
the same staging into a slot of its own rep.
