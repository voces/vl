### D4886 — in a generic body, the complement of `is i32[]` over an inferred `T[] | i32[]` kept the whole union, so it reached no `T[]` or `T` destination

**closed · was a loud check reject at the return and binding positions (`return type mismatch: expected string[], got string[] | i32[]`) and a loud emit reject at a generic `T[]` argument (`argument 1: string[] | i32[] is two list types, not one list`), identical on master `b8dc4604d` · fixture `tests/cases/generics/generic-complement-list-delivery-positions.vl` · filed 2026-10-15**

Repro:

    function w<T>(t: T, b: boolean) {
      if b { return [t, t] }
      [1, 2, 3]
    }
    function ret<T>(t: T, b: boolean): T[] {
      const v = w(t, b)
      if v is i32[] { return [t] } else { return v }
    }
    print(ret("a", true)[1])
    print(ret(2.5, true)[0])

Want:

    a
    2.5

#### Mechanism

The else of `is i32[]` was `subtractTy(T[] | i32[], i32[])`. The gradual test that removes a
member counts `T[]` as the same variant as `i32[]`, so both left, the remainder was empty, and
the else recorded no narrowing. At each pin the body is re-checked with `v` still the whole
union. The else now subtracts with a type parameter's list kept apart from a concrete list
(`elseRemainderTy`), as a return set already does, so it is `T[]`; the else of `is T[]` keeps
the old remainder. Two emitter readers then had to take the record: the two-list argument
refusal skips a read the checker narrowed to one list, and the argument pin substitutes the
instance's bindings into a recorded `T[]`.
