### D3854 — a chain of two `let`/`const` aliases of a hole lambda at module scope is refused at emit for want of a function-value signature

**loud emit reject · 174 of 600 generated programs moved to module scope (`gen.py`, lifted out of `mk`) · found closing D3847 · filed 2026-10-08 against master `5b2ec9f85`**

Repro:

    const c = (y) => y + "C"
    const e = (y) => y + "E"
    let d = c
    const d2 = d
    print(d2("a"))
    d = e
    print(d("b"))
    print(d2("c"))
    // vl check: rc 0.  vl run: emit error `a function-value call has no interned signature`

Want:

    aC
    bE
    cC

#### Mechanism

Not yet located. The same lines inside a function run. At module scope, a single alias
(`let d = c`) now keys its call through `fieldValueFeOfIn` (D3847). That resolution stops at one
hop on purpose: following a chain there would also rename the call to the initializer's lambda,
which is wrong once a link is written. The signature key needs its own chain walk, the one
`calleeCloSigKeyAt`'s copy rung (`identCopySourceNodeAt`) makes inside a function.
