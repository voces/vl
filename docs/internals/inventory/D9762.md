### D9762 — an element of a returned list of an un-annotated function, read straight off the call and handed to an un-annotated parameter, is refused as an argument type

**closed 2026-10-26 by the elaboration worklist, increment 1 (#4819) · runs, prints `4` · was: loud emit reject · `vl check` rc 0 · `monomorphize: unsupported argument type for `f` in a call to `use`` · clause 2 · found closing [D9710](D9710.md) · present on master `e8163edd5` · filed 2026-10-22 against master `60aaa08c0`**

Repro:

    function inc(a) { return a + 1 }
    function use(f) { return f(3) }
    function deliver() {
      const u = [inc]
      return u
    }
    print(use(deliver()[0]))
    // vl check rc 0.  vl run: emit error: emitProgram: monomorphize: unsupported argument type for `f` in a call to `use`

Want:

    4

#### Mechanism

Not traced. The call bound first (`const v = deliver()`, `use(v[0])`) runs, because the argument
pin reads a binding of the call's returned slot. An index read straight off the call has no
binding to read, and the pin falls through. The local is not needed: `return [inc]` refuses the
same way, and so does the nested twin (`[[inc]]`, `deliver()[0][0]`).

| the un-annotated parameter of `use` | runs, `4` | **yes** |
