### D9912 — a lambda over a hole's `??` binding at a never-null pin computes at the pin where its result is the join's

**closed · runs, prints `6` · was check-clean invalid wasm, clause 1 · `vl check` rc 0 · the binding read without the operator, `() => r2`, prints `4` · found closing [D9870](D9870.md) · present on master `8700f0727` · filed 2026-10-22 against master `8700f0727` · closed with [D9914](D9914.md): at a never-null number pin the `??` is typed as the pin, so the lambda's result is the scalar its body computes (`coalDeadAtPin`, check_hole_pins.vl) · the grading list's 24 cells run, and `() => r2 / 8` prints `0`, `0`, `0.5` at `i32`, `i64`, `f64`**

Repro:

    function take(a) {
      const r2 = a ?? 0.5
      const f = () => r2 + 2
      print(f())
    }
    const z: i64 = 4
    take(z)
    // vl run: the emitted module failed to validate inside `__lambda_1`: type mismatch: expected (ref $7), found i64; $7 is `union box`

Want:

    6

#### Mechanism

The lifted lambda's result was the join the checker typed (`i64 | f64` at an `i64` pin, `f64` at
an `i32` one), but its body read the captured binding at the pin's scalar and computed the
operator at that width. The join was the defect: the default is dead at a never-null pin, and
the pin's own type is what the body computes.

#### Grading list

The `i32`, `i64` and `f64` pins, the operators `- * <`, and the lambda returned from `take`.
