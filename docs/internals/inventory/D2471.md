### D2471 — a built-in method that replaces or removes a cell is effect-free in a callee's write summary

**closed 2026-09-25 — now a loud check reject (`'m["a"]' is no longer narrowed to i32: the call to
'put' on line 5 may reassign it`) · was loads then traps, clause 1 · filed and closed against
master `2bf40476c`, from the collections design review's finding F4 · fixture
`tests/cases/soundness/builtin-mutator-in-callee-ends-cell-narrowing-reject.vl`**

Repro:

    const m: {[string]: i32 | string} = Map()
    m["a"] = 1
    function put(k: string) { m.set(k, "x") }
    if m["a"] is i32 {
      put("a")
      print(m["a"] + 1)
    }
    // vl check: rc 0.  vl run: wasm trap: cast failure

#### Mechanism

A path narrowing ends at a call whose callee may write it. For a top-level function the only leg
is its free-variable summary (`fnWriteFreePaths`), which records assignments and composes
declared callees; a built-in method is an intrinsic there, and "an intrinsic contributes none"
(`callFreeEffects`). So `m.set(k, …)`, `m.delete(k)`, `xs.pop()` and `xs.clear()` inside the
callee wrote nothing as far as the caller's `m["a"]` or `xs[0]` narrowing could tell. #3150 had
made `set` a writer only at a direct call on the narrowed receiver itself.

#### Ablation

| ingredient removed | outcome | needed? |
| --- | --- | --- |
| the call `put("a")` | runs, prints `2` | **yes** |
| the function (`m.set("a", "x")` inline) | loud check reject | **yes** — the direct-call leg sees it |
| `set` for `push` (`xs.push("s")` on a list narrowed at `xs[0]`) | runs, prints `2` | **yes** — an append replaces no cell |

#### Grading list

The same with `m.delete(k)` on a `{[string]: i32}` map narrowed `!= null`, which printed the wrong
value `1`; `xs.pop(); xs.push("s")` and `xs.clear(); xs.push("s")` on a list narrowed at `xs[0]`,
which trapped; a nested function of a function calling `p.set(k, "x")`; and the review of
#3159's `a17`, the `delete` writer handed on through `call(f) { f("a") }`, which printed `1`. All
refuse at the read after the call.

#### Close

Every built-in method now has one effect column, `builtinMethodEffect`: `NONE` reads or builds,
`APPENDS` (`push`, `add`) adds a cell and leaves every held one untouched, and `CELLS` (a list's
`pop` and `clear`, a map's `set` and `delete`) may replace or remove one. The direct-call rule
(`cellRemovingMethod`), the getter effects (`esMethodMutates`) and the write shapes
(`builtinMethodShape`, D2461) all read it, and it applies only when the receiver's type has that
built-in (`builtinMethodOn`): a record's own `clear` is its declaration, and a std function such as
`reverse` is summarised from its body like any other. A callee's summary carries its built-in
writes as cell shapes tagged with the container's element type: `[k]` for a store under a literal
key, `-[k]` for a map cell removed, `[]` / `-[]` for any. A store under another literal key, a
store of exactly the narrowed type, and a write into a container whose element type cannot be the
narrowed one's keep the narrowing.
