### D3342 — a function declared to return a wider record, its result set into a map of that record, is invalid wasm when a record of the literal's own fields is declared

**check-clean invalid wasm · clause 1 · open · identical on master `2b30e3674` · found by the #3312 review (`m03`, whose un-annotated spelling runs) · filed 2026-09-30 against master `2b30e3674`**

Repro:

    type O = { v: i32 }
    type I = { f: O }
    type J = { f: O | null }
    function mk(): J { { f: { v: 4 } } }
    const m = Map<string, J>()
    m.set("a", mk())
    const x = m.get("a") ?? { f: { v: 9 } }
    print(x.f?.v ?? 70)
    // vl check: rc 0.  vl run: invalid module, "expected (ref null $type), found (ref $type)"

Want:

    4

#### Mechanism

The annotated face of the fresh-function delivery. With `type I` declared, the literal in `mk`'s
body is built at `I`'s row though `mk` declares `J`, and the map's `set` stores it into a `J`
slot. It is why the first #3312 candidate, which adopted a function's result as the type it
was delivered to, turned the un-annotated spelling (which runs) into invalid wasm; functions are
no longer adopted.

#### Ablation

| ingredient removed | outcome | needed? |
| --- | --- | --- |
| `type I = { f: O }` | runs, prints `4` | **yes** |
| the call (`m.set("a", { f: { v: 4 } })`) | runs, prints `4` | **yes** |
| the annotation `: J` on `mk` | runs, prints `4` | **yes** |
