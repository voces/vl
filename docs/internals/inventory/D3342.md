### D3342 — a function declared to return a wider record, its result set into a map of that record, is invalid wasm when a record of the literal's own fields is declared

**closed · runs, prints `4` · was check-clean invalid wasm · clause 1 · closed 2026-10-24 by lane L6 blocker 1: `structIndexOfTypeNameTy` asks the map value's type `J` for its own row before the spelling `{f:{v:i32}|null}`, whose field-set scan found the declared `I` · the un-annotated spelling (`function mk()`) was invalid wasm on master `845bd1bdf` too and runs with it · fixtures `tests/cases/maps/wider-record-fn-result-set-with-own-record-declared.vl`, `tests/cases/maps/unannotated-fn-result-set-into-wider-record-map-with-own-record-declared.vl` · found by the #3312 review (`m03`) · filed 2026-09-30 against master `2b30e3674`**

Repro:

    type O = { v: i32 }
    type I = { f: O }
    type J = { f: O | null }
    function mk(): J { { f: { v: 4 } } }
    const m = Map<string, J>()
    m.set("a", mk())
    const x = m.get("a") ?? { f: { v: 9 } }
    print(x.f?.v ?? 70)
    // vl check: rc 0.  vl run: invalid module, "expected (ref null $type), found (ref $type)"

Want:

    4

#### Mechanism

The annotated face of the fresh-function delivery. With `type I` declared, the literal in `mk`'s
body is built at `I`'s row though `mk` declares `J`, and the map's `set` stores it into a `J`
slot. It is why the first #3312 candidate, which adopted a function's result as the type it
was delivered to, turned the un-annotated spelling (which runs) into invalid wasm; functions are
no longer adopted.

#### Ablation

| ingredient removed | outcome | needed? |
| --- | --- | --- |

| the call (`m.set("a", { f: { v: 4 } })`) | runs, prints `4` | **yes** |
| the annotation `: J` on `mk` | runs, prints `4` | **yes** |
