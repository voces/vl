#### Mechanism

A profile of the N = 4,800 build on a `--names` seed puts 12.6% of the samples, all of
them self time, in `variantRowOfTy` (compiler/emit_mv_slots.vl), a linear scan of `uVarTyIx`
for the row whose arm type is `ty`. Its callers in that profile are `objVariantNameCtx`
(compiler/emit_classify.vl, about 54% of its samples) and `collectAnonShapes`
(compiler/emit_collect.vl, about 46%). No other frame is above 5.5% self. An index from arm type to its first row, kept like `unRowOfCanon`'s (emit_rep.vl),
is the expected fix.

#### Fix

`variantRowOfTy` answers from a map of arm type to its first `uVarTyIx` row, so the first
match a scan would return is still the answer. Rows are only appended between resets, so the
map extends over new rows in place; `collectU` emptying the table bumps `uVarTyIxResets`, and
that or a new pass generation rebuilds it. Guest fuel (`VL_FUEL=1 vl build`), D11270's
generator at one filler statement per use:
