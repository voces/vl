### D17002 — inside `is K[]` over a numeric list arm stored apart from `K[]`, a write or a `for` loop at `K` is refused

**loud check reject · clause 2 · the write and loop half of the 2026-11-18 ruling (DECISIONS, "`is K[]` tests a list's contents"): inside the arm the value is a `K[]`, and a `K` write converts back · D17001 closed the element read (`q[i]` at `K`); a write through the index still meets the union-of-lists write refusal, and a loop variable still binds at the arms' join · filed 2026-11-19 against master `de44e8985` by lane F1**

Repro:

    type K = 1 | 2
    const a: u8[] = [1, 2]
    const q: u8[] | K[] = a
    if q is K[] { q[0] = 2; print(q[0]) }
    // vl check: cannot write through an index of u8[] | K[]: the value would have to fit every member's element — narrow with `is` first

Want:

    2

#### Mechanism

`checkIndex` refuses a write through an index of a union of lists before any narrowing is
consulted, and `for x in q` over a union receiver binds `x` at the arms' element join (`i32`),
not at the arm's `K`. Each needs a per-arm lowering: a store that converts a `K` back to the
arm's element rep, and a loop that reads each arm's element at `K`'s rep, as
`emitListUnionArmIndex` does for a read.

#### Ablation

| ingredient changed | outcome | needed? |
| --- | --- | --- |
| `for x in q { const k: K = x }` in place of the write | refused (`cannot assign i32 to 'k' of type K`) | no (both faces) |
| `q[0]` read only | runs (D17001) | **yes** (a write or a loop) |

#### Grading list

- The write and the loop above, at a `u8[]`, `i64[]` and `f64[]` arm.
