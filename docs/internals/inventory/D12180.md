### D12180 — a generic handing a record whose type parameter no field names on to another generic has no argument type

**closed 2026-10-31 — the filed repro RUNS and prints `8` · a composite parameter riding type parameters pins at the type the elaboration gives it at the call (`monoElabCompositeTy`, emit_mono.vl) before `monoPinTyParamComposite` · fixture `tests/cases/generics/composite-param-pins-at-elaboration-type.vl` · was: loud emit reject · `vl check` rc 0 · `emitProgram: monomorphize: unsupported argument type for `r` in a call to `inner`` · clause 2 · CAPABILITY: the direct call and the forwarder's explicit `inner<U>(r)` both run · found surveying emit refusals for L3 · filed 2026-10-24 against master `ed5d4f7f7`**

Repro:

    type Rows<T> = { base: i32, count: i32 }
    function inner<T>(r: Rows<T>) { return r.base }
    function outer<U>(r: Rows<U>) { return inner(r) * 2 }
    const st: Rows<string> = { base: 4, count: 1 }
    print(outer(st))

Want:

    8

#### Mechanism

`Rows<T>` names `T` in no field, so the argument `r: Rows<U>` carries nothing the call in
`outer`'s instance can bind `inner`'s `T` from. The checker binds it from the declared type
argument; the monomorphizer's argument-type ladder reads the instance's structural type of
`r` and finds no `T` to pin, so the call to `inner` has no argument type. A flat `T.size`
read through the same hand-on (`flat-records-design.md` §11.3) refuses the same way.
