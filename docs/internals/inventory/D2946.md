### D2946 — an element read off a generic list parameter pinned by an inferred `[null, true]` prints the niche's `i32`

**check-clean silently wrong · clause 1 · open · the un-annotated spelling of [D2943](D2943.md)'s witness · the same on master `8615a730d` · filed 2026-09-28 against master `8615a730d`**

Repro:

    function h(x) {
      print(x[0])
      print(x[1])
    }
    const v = [null, true]
    h(v)
    // vl check: rc 0.  vl run: prints `2` then `1`

Want:

    null
    true

#### Mechanism

Not localised. The checker hints that an annotation `(boolean | null)[]` on `v` is redundant, and
with it the program runs since [D2943](D2943.md). Without it the instance's pin is the inferred
list type, whose element the `boolean | null` niche test (`tyIsNulPrim`) does not recognise, so
`print` takes the `i32` import. The explicit `h<T>(x: T[])` prints `2` the same way, so the gap is
in the inferred pin, not the hole read.

#### Ablation

| ingredient changed | outcome | needed? |
| --- | --- | --- |
| `const v: (boolean \| null)[] = [null, true]` | runs, `null`, `true` | **yes** (the inferred list) |
| `print(v[0])` at module scope | runs, `null` | **yes** (the generic parameter) |
| `h<T>(x: T[])` | prints `2` | no |
| `h([null, true])` | prints `2` | no |
| `[true, null]` | prints `1` | no |
