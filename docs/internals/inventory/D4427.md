### D4427 — dogfood: `runProgram` captures a child's output, so a long `vl build` driven from a VL script shows nothing until it ends

**runs today and must keep running · the witness runs; the gap is what it cannot express · filed 2026-10-13 against master `777a705a0`**

Repro (runs, prints `3`):

    import { ProcessOutput, runProgram } from "std:process"

    const r = runProgram("echo", ["hi"])
    if r is ProcessOutput { print(r.stdout.length) } else { print(r.msg) }
    // The child's stdout is returned as bytes after it exits; there is no way to let the
    // child write to this program's own stdout and stderr as it goes.

#### Mechanism

`memo-generation-probe.vl --run` builds the whole compiler with one memo disabled, which
takes a minute or more. The Python passed the terminal through, so the build's progress
(and a hang) was visible as it happened. The port prints the captured stdout and stderr
after the child exits, so a non-converging probe build looks like a silent script. The one
mitigation, a `timeout` the caller wraps around the script, kills the script and leaves the
`vl build` orphaned (CLAUDE.md, "timeout kills the shell, not the build").

#### Grading list

The row closes when `std:process` can run a child with inherited stdio (and, with D4380, a
bound on its run time), and `--run` uses it. The ordering of the lines the script prints
around the build output then matches the Python's again, which it already does for a build
that writes only to stdout.
