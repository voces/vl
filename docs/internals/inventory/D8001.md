### D8001 — a call of a call or a field whose function type returns one string literal lowers its result as `i32`

**closed 2026-10-20 by lane L6 · a call whose callee is a call result or a field, and whose result type is a lone string literal, now classifies as a string when the function type returns the string ref; the repro prints `a`, pinned by `tests/cases/literal-unions/lone-literal-result-of-call-of-call.vl` and `scripts/capability-probes/matrix/lone-literal-result-of-generic-fn-value.matrix.vl` · was check-clean invalid wasm · clause 1 · found closing [D7880](D7880.md) · filed 2026-10-20 against master `981320f30`**

Repro:

    function g(): "a" { return "a" }
    function wrap(): () => "a" { return g }
    print(wrap()())
    // vl check: rc 0.  vl run: invalid module, type mismatch: expected i32, found (ref $0) (`string`)

Want:

    a

#### Mechanism

A function type's bare one-literal result (`() => "a"`) is a string ref, which the
callee returns. When the callee is itself a call result (`wrap()()`) or a record field
(`r.f()`), the consumer of the call reads the result as `i32`, the rep of a one-literal SET.
Through a local (`const w = wrap()`, then `w()`) the call runs. `exprString`'s call arm
asked the closure signature's return kind only for a node whose type is `string`, and its
field-closure arm only for `TK_STR`; a bare `TyLit` is neither, so both now also accept one
(`tyIsBareStrLit`).

#### Ablation

| ingredient changed | outcome | needed? |
| --- | --- | --- |
| `() => string` in place of `() => "a"` | runs | **yes** |
| `const w = wrap()`, then `print(w())` | runs | **yes**, the callee not a local |
| `const s = wrap()()`, then `print(s)` | invalid at the binding | no, any consumer |
| `const r: R = { f: g }` with `type R = { f: () => "a" }`, then `print(r.f())` | invalid the same way | no, a second callee shape |

The `r.f()` spelling, and the closure-literal callees in
