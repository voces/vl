### D3416 — a function value of single-literal result type, delivered at a function type whose result is the literal union, is refused as having "no spelling to convert through" unless it is a declared name or a `const`

**loud check reject · clause 2 · open · the adapter of [D3073](D3073.md) needs a stable name to read at call time and has no spelling for the literal type of a value it cannot name · found by the #3314 review (`rv3314-7732`, `h2`, `k1`-`k4`) · it trapped on master before #3314 · the same on master `5e277ab52` · filed 2026-09-30 against master `5e277ab52`**

Repro:

    type K = "on" | "off"
    function F(): "on" { return "on" }
    function use(g: () => K): K { return g() }
    const o = { f: F }
    print(use(o.f))
    // vl check: rejects: a function of type `() => "on"` cannot be used as `() => K` here:
    // calling it through that type needs its arguments or result converted, and a parameter
    // or result type has no spelling to convert through

Want:

    on

#### Mechanism

A prediction. `fvaRefuse` (`compiler/typecheck.vl`) says "no spelling" when it gets no reason
string, and the adapter is built only over a stable name (`fvaStableName`: a declared function or
a `const`). A function value read from a field, a `let`, or a parameter is not stable, and its
single-literal result type has no rep of its own to convert from, so the refusal fires. The same
function delivered by its declared name, or through a `const` alias, runs, so the program is
legal and the refusal names a mechanism, not a contract.

#### Ablation

Observed on master `5e277ab52`.

| variant | outcome | needed? |
| --- | --- | --- |
| `use(F)`, the declared name | runs, prints `on` | **yes** (a value that is not a stable name) |
| `const fv = F; use(fv)` | runs | same |
| `let fv = F; use(fv)` | loud check reject, the same message | no, a second position |
| `function via(h: () => "on"): K { return use(h) }` | loud check reject | no, a third position |
| an annotated record field `type R = { f: () => "on" }` | loud check reject | no |
| `F(): K`, a union result | runs | **yes** (the single literal) |
| `K = 1 \| 2` and `F(): 1` | loud check reject | no, the `i32` literal face |
| `F` delivered in a list, a field of `H = { g: () => K }`, a binding, a return, or a generic `use<T>` | runs | the delivery is the field read |

#### Grading list

The four rows that refuse, and the `i32`-literal face. A `() => "on"` lambda is typed
`() => string` by inference and is refused at `() => "on"` with a plain mismatch, which is a
separate and unfiled question of the literal's inference.
