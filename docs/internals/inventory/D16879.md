### D16879 — an empty list literal inside a list literal used in expression position is refused at emit

**open · loud emit reject · `a list literal's element type gives its list no element rep` · clause 2 · the `for` spelling is [D16273](D16273.md) · found closing D16273 · filed 2026-11-16 against master `2a0b71c1a`**

Repro:

    print([[]].length)
    // vl check: rc 0.  vl run: emit error: a list literal's element type gives its list no element rep

Want:

    1

#### Mechanism

The inner literal's element is a hole nothing writes. A binding of the literal is noted pending
and scope close defaults the hole (`flushUninferred`); D16273 notes a literal a `for` iterates the
same way. A literal in expression position is neither, so the hole reaches emit open. The open
question is when to settle it: at the end of its statement nothing later can write it, but a write
can arrive later in the same expression (`[[]][0].push(1)`), so the default must wait at least for
the expression, and the write decides first.

#### Ablation

| ingredient changed | outcome | needed? |
| --- | --- | --- |
| a binding (`const ys = [[]]`, then `ys.length`) | runs, prints `1` | **yes** |
| the inner list bound (`const x = [[]][0]`, then `x.length`) | runs, prints `0` | **yes** |
| a write in the same expression (`[[]][0].push(1)`) | runs | **yes** |
| `[[]][0].length` or `const n = [[]].length` in place of the `print` | still refused | no |
