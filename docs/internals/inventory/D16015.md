### D16015 — a field or element write used as an operand, a call argument or a module-level initializer has no value lowering

**closed · runs, prints `9` `8` · was loud emit reject, clause 2 · fixed 2026-11-14: an element or field write used as a value yields the cell its store parks · the residue is [D16016](D16016.md) (a value typed apart from its target), [D16017](D16017.md) (a map entry) and [D16018](D16018.md) (a byte-list element) · residue of [D2171](D2171.md) · filed 2026-11-13 against master `b2ff138e0`**

Repro:

    function f(xs: i32[], i: i32) { return (xs[i] = 8) + 1 }
    const xs = [1, 2, 3]
    print(f(xs, 2))
    print(xs[2])

Want:

    9
    8

#### Mechanism

An assignment yields its right-hand side, which `emitBinExprNode`'s `=` arm delivers by
storing and then re-reading the target (`assignTargetReReads`). The re-read is refused for an
element with a non-literal index (re-evaluating the index could repeat its effects) and for a
right side whose type differs from the target's. D2170 and D2171 spill the write into
`const`s before a block's tail, a `return` or a function-level `let`, where nothing else is
evaluated. An operand or a call argument has siblings evaluated around it, so hoisting the
spill would reorder their effects. A module-level initializer is outside the function bodies
the spill walks.

#### Ablation

| position | outcome |
| --- | --- |
| operand, `(xs[i] = 8) + 1` (the witness) | loud emit reject |
| call argument in a function, `print(xs[i] = 8)` | loud emit reject |
| call argument at top level, `print(xs[i] = 8)` with `let i` | loud emit reject |
| module-level `const y = xs[i] = 8` | loud emit reject |
| a literal index, `print(xs[2] = 8)` | runs, `8` `8` |
| `return xs[i] = 8` or a function-level `const y = xs[i] = 8` | runs (D2171) |

#### Grading list

The position matrix `scripts/capability-probes/matrix/element-write-value.matrix.vl`
(`vl run scripts/capability-matrix.vl -- <it>`), to 50 of 50 graded cells or a named reason for
each left. At D2171's close it runs 12 of 50 and 0 are silent. The module-scope positions
(`binding`, `global_init`, `global_assign`, `block_*`, `local_assign`, `closure_capture`) take
the same hoist at statement level. The operand positions (`argument`, `array_element`,
`array_push`, `map_value`, `map_set`, `struct_field_init`) need an expression-level lowering
that keeps sibling order. Add a sibling with an effect before and after the write,
`f(next(), xs[i] = 8, next())`, which must observe source order.

#### Closed (2026-11-14)

An element store already parks its value in a scratch local of the element's rep before its
`array.set`, so the stored cell is that local. `emitBinExprNode`'s `=` arm now has a rung after
the re-read: for a list element or a field whose type is the assignment's, it emits the store,
then reads the parked local (`asgYieldsParkedCell`). A field store tees its value into such a
local only when that rung asks (`asgParkField`, the scalar and string kinds). Nothing is hoisted,
so siblings keep source order: `f(next(), xs[i] = next() + 4, next())` prints `163`. Both
matrices run every graded cell: `element-write-value` 50 of 50 and `field-write-value` 48 of 48,
0 silent.
