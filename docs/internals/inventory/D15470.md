### D15470 — a closed function of another parameter type, written to a `let` a hole parameter seeds, passes `vl check` and is refused only when built

**compiler trap, as the witness checker grades it · `vl check` rc 0; `vl run` and `vl build` then refuse with a type error, `cannot assign (string) => string to (i32) => i32 (the body of `go` at the call's argument types)`, which only the split plan's re-check finds; with the plan off a loud emit reject, `monomorphize: parameter `b` of `go` is called at two function types that no parameter per type separates` · clause 2, the program is ill-typed and `vl check` owes the diagnosis · found measuring D15456 · filed 2026-11-05 against master `3ed87a1a5`**

Repro:

    function same(x) { return x }
    function dbl(x: string): string { return x + x }
    function go(a, b) {
      let hh = a
      hh = b
      print(hh(3))
      print(a("x"))
    }
    go(same, dbl)

#### Mechanism

`hh` may hold `dbl`, which takes a `string`, and `hh(3)` calls it with an `i32`, so the program is
ill-typed. The first check types the call through the hole parameter's binding at the call's own
arguments and never meets `dbl`'s written parameter type, since `dbl` reaches `hh` only through
`b` in the instance `go(same, dbl)`, so `vl check` passes. The split plan's re-check of the
instance finds the mismatch; without the plan, mono finds `b` called at two function types.

The direct spelling `let hh = same; hh = dbl; print(hh(3))` at module scope, which the checker
refuses today, is the refusal this one owes.
