### D14727 — a nested list of one hole function called at two types has no element type the elaboration closes; mono's stub rung is its only answer

**runs today and must keep running · step 2 residue: `monoPinHoleParam`'s `monoInertParamStubPin` rung serves only this shape and goes when it closes · found closing rung C · filed 2026-11-01 against master `0b0456f91`**

Repro:

    function inc(a) { return a + 1 }
    function take(v) {
      print(v[0][0](3))
      print(v[1][0](2.5))
    }
    take([[inc], [inc]])

Want:

    4
    3.5

#### Mechanism

`inc` is called through the parameter at `i32` and at `f64`, so the list's element holds a
function with no one signature, and the elaboration leaves `take`'s key open (`elabCallParamTy`
is -1). The stub rung pins the parameter at `(() => void)[][]` and keeps the closures, and the
two calls each run their own instance. A flat list of the same function called at two types
does not need the rung: it takes a per-type route the nested level does not reach.

| the witness, a nested list called at `3` and `2.5` | check-clean invalid wasm (`expected (ref null $type), found (ref $type)`) | runs, `4 3.5` |
