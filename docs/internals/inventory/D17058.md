### D17058 — a call of an element of `??` over a global read from a map of hole functions, in a module with a reassigned list of them, is refused as a function-value call with no interned signature

**closed 2026-11-23 by lane IR-N6 (#PRNUM) · now runs, `4` · was a loud emit reject · `monoInitHeldTy`: a `??` over a read of a binding mono closed holds that binding's type, so its list's element calls key the closed signature · pin: `tests/cases/closures/coalesce-global-copy-of-map-read-called-by-index.vl` · found by lane IR-M1 on the coordinator's missing-key test of IR-N9's `mv4` cell · filed 2026-11-22 against master `87a19deaa`**

Repro:

    function inc0(a) { return a + 1 }
    function dbl(a) { return a * 2 }
    let b2 = [inc0, dbl]
    b2 = [dbl]
    const m4 = Map()
    m4["k"] = [inc0, dbl]
    const mv4 = m4["absent"]
    const got = mv4 ?? [inc0]
    print(got[0](3))
    // vl check: no errors. vl build: "a function-value call has no interned signature —
    // parameter 1 of type `_` has no representation" at `got[0](3)`.

Want:

    4

#### Mechanism

`got`'s element is a closure whose parameter is still the open `_` of the hole functions: the
`??` over `mv4`, which this module types as the non-null list (D17056), never pins the element
to the `(i32) => i32` the call supplies, so the call through it has no signature to intern. The
same `??` read straight off the map (no `mv4` binding) pins it and prints `4`. The refusal names
a mechanism, not a contract.

#### Ablation

| ingredient | outcome | needed? |
| --- | --- | --- |
| `mv4` bound (`const got = m4["absent"] ?? [inc0]` instead) | prints `4` | **yes** |
| `b2` reassigned (`b2 = [dbl]` removed) | invalid wasm, D17055 | **yes** |
| the functions un-annotated (`a: i32` on both) | prints `4` | **yes** |
| the key missing (`m4["k"]` instead) | still refused | no |
| the default naming one function (`?? [inc0, dbl]` instead) | still refused | no |
