#### Mechanism

D1626's second floor, split off from it because the mechanism is a REP question and not a
sig-key one. A closure delivered as an un-annotated parameter arrives with a `PIN_SIGKEY`
payload the monomorphizer wrote on the parameter, which is what D1626's capture rung reads —
but the ref-list element kind and the inferred struct-field kind are classified from the
INITIALIZER expression, and `[a]` / `{ f: a }` route through `letInitCellKind`, whose closure
rungs answer off `exprIsClosure` and `nodeTyIsFunc`. The checker leaves the parameter's node
the inference hole `_`, so neither answers and the container's element/field is typed i32.

The refusal wears four sentences, one per read shape, and none of them names the container:
the tail read says `a call statement's callee is neither a name, a member, nor a function
value`, the expression read `callee is not a function name`, the rebound read `call to
unknown function`, and the struct-field spelling `object literal but no struct type declared`.
Grouping by the message would make four families out of one.
