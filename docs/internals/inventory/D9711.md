### D9711 — a bound nested list of an un-annotated function, called through its element at two types, is refused

**loud emit reject · `vl check` rc 0 · `nested arrays are not supported` · clause 2 · found closing [D9662](D9662.md) · present on master `e8163edd5` · filed 2026-10-22 against master `e8163edd5`**

Repro:

    function inc(a) { return a + 1 }
    const u = [[inc]]
    print(u[0][0](3))
    print(u[0][0](2.5))
    // vl check rc 0.  vl run: emit error: emitProgram: nested arrays are not supported

Want:

    4
    3.5

#### Mechanism

Not traced. Each element read takes its own pin, so the binding's inner element is pinned at two
function types and `monoPinNestedListElems` (emit_mono.vl) declines on more than one pin. The flat
list (`const u = [inc]`) asks for a copy of the function per pin and runs; the nested walk has no
such arm.

#### Ablation

| ingredient removed | outcome | needed? |
| --- | --- | --- |
| the second call (`u[0][0](2.5)`) | runs, `4` | **yes** |
| the nesting (`const u = [inc]`, `u[0](3)`, `u[0](2.5)`) | runs, `4` `3.5` | **yes** |

#### Grading list

The same list returned from a function, as a local:

    function inc(a) { return a + 1 }
    function deliver(_n) {
      const u = [[inc]]
      return u
    }
    const w = deliver("s")
    print(w[0][0](3))
    print(w[0][0](2.5))

That refuses with `ref valtype with no interned shape`. It does the same without the parameter,
and when the local is the flat `[inc]` wrapped at the return (`return [u]`). The flat local
returned whole (`const u = [inc]`, `return u`) refuses with `a function value's signature is not
known at this call`. The inline spelling `return [[inc]]` runs at both types.
