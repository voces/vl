### D9711 — a bound nested list of an un-annotated function, called through its element at two types, is refused

**closed · runs, prints `4` `3.5` · was loud emit reject, `vl check` rc 0, `nested arrays are not supported`, clause 2 · CAPABILITY: the flat list `const u = [inc]` runs at both types · found closing [D9662](D9662.md) · filed 2026-10-22 against master `e8163edd5` · closed by giving the inner elements the slot's uncalled stub when its pins disagree, so each read names its own instance (`monoUncalledNestedListElems`, emit_mono.vl) · fixture `closures/hole-fn-nested-list-read-two-types.vl`, matrix `hole-fn-nested-list-read-open` (1 → 21 of 64, its 2 SILENT cells now running) · with [D9710](D9710.md) closed**

Repro:

    function inc(a) { return a + 1 }
    const u = [[inc]]
    print(u[0][0](3))
    print(u[0][0](2.5))
    // vl check rc 0.  vl run: emit error: emitProgram: nested arrays are not supported

Want:

    4
    3.5

#### Mechanism

Each element read takes its own pin, so the inner slot was pinned at two function types and
`monoPinNestedListElems` declined on more than one pin. The flat list already falls back to an
uncalled stub there and lets each read call its own instance. The nested walk now does the same
when the slot is uncalled, or when its pins disagree outside a generic instance and the held
values are inert.

| the nesting (`const u = [inc]`, `u[0](3)`, `u[0](2.5)`) | runs, `4` `3.5` | **yes** |
