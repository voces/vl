### D2768 — a non-generic function whose returns join two list types of different storage is built inconsistently, even when the result is discarded

**check-clean invalid wasm · the #3207 round-2 review · filed 2026-09-27 against master `f6db92e0d`**

Repro:

    function h(c: boolean, t: string) {
      if c { return [t] }
      [1]
    }
    h(true, "s")
    print("ok")
    // vl check: rc 0.  vl run: invalid module inside `h`

#### Mechanism

The checker types `h` as returning `string[] | i32[]`, and it records that union as the inferred
return (the A20 `retIsConcreteUnion` route), so the result is a union box. The `return [t]` and
tail `[1]` arms are built as bare lists and never wrapped into that box, so `h`'s body does not
validate. The generic spelling at `T := string` goes through the pin instead and builds the box
([D2766](D2766.md)).

#### Ablation

| ingredient removed | outcome | needed? |
| --- | --- | --- |
| the second list type (`[t]` both ways) | runs | **yes** |
| the use of the result (discarded) | invalid wasm | no |
| `t: string` → `t: boolean` (one storage) | runs; `is` answers wrong ([D2769](D2769.md)) | **yes** |
| a type parameter `h<T>(c, t: T)` | runs | **yes** |
