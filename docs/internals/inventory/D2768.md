### D2768 — a non-generic function whose returns join two list types of different storage is built inconsistently, even when the result is discarded

**closed 2026-09-27 — the filed repro RUNS and prints `ok` · was check-clean invalid wasm · the return is pinned to the checked list union, as the annotated spelling is (`synthListUnionRet`), and a record-list arm's union is registered there · the #3207 round-2 review · filed 2026-09-27 against master `f6db92e0d` · fixture `tests/cases/functions/return-join-two-list-types.vl`**

Repro:

    function h(c: boolean, t: string) {
      if c { return [t] }
      [1]
    }
    h(true, "s")
    print("ok")
    // vl check: rc 0.  vl run: invalid module inside `h`

#### Mechanism

The checker types `h` as returning `string[] | i32[]`, and it records that union as the inferred
return (the A20 `retIsConcreteUnion` route), so the result is a union box. The `return [t]` and
tail `[1]` arms are built as bare lists and never wrapped into that box, so `h`'s body does not
validate. The generic spelling at `T := string` goes through the pin instead and builds the box
([D2766](D2766.md)).

The close pins an un-annotated named function whose checked return is a union of lists (or that
union with `null`) to that union by its emit name, with a record list spelled by its row, and
registers the union after `collectU` when an arm needs a row. The checker's floor no longer
refuses a union of lists un-annotated, so `Circle[] | i32[]` now runs too. The `is` complement
of a union whose record list is spelled by shape matches a tested `Circle[]` by row
(`setAtomSpelling`).
