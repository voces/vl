### D14541 — a `for … in` variable does not hide an enclosing binding's path narrowing of the same name

**closed 2026-10-27 · now a loud check reject, `operator '+' is not defined for i32 | string and i32` · was check-clean, trapped with `cast failure` (clause 1) · fixed: a path narrowing answers only while its key's root still resolves to the declaration it was pushed under (`npRoot`, `npSlotOf`, check_narrow_paths.vl) · pins: the witness below · filed 2026-10-27 against master `ef0b62b07`**

Repro:

    type Box = { v: i32 | string }
    function f(o: Box): i32 {
      if o.v is i32 {
        const ys: Box[] = [{ v: "x" }]
        for o in ys {
          return o.v + 1
        }
        return o.v
      }
      0
    }
    print(f({ v: 1 }))

Want:

    operator '+' is not defined for i32 | string and i32

#### Mechanism

A path narrowing (`o.v → i32`) is keyed on the spelling `"o.v"`, and an inner declaration of
`o` hid it only by pushing an invalidated copy (`narShadowPaths`). Only `let` and parameters
called it. A `for … in` variable of the same name left the outer narrowing answering, so
`o.v` in the loop read `i32`. `vl check` accepted the program, and on master it trapped at
run time with `cast failure` (clause 1).

#### Ablation

| ingredient removed | outcome | needed? |
| --- | --- | --- |
| the outer `if o.v is i32` | check reject (no narrowing to leak) | yes |
| the loop variable named `o` (named `p`) | check reject at `p.v + 1` | yes |
| `for … in` replaced by `const o: Box = ys[0]` | check reject (a `let` hid it) | yes |
