### D5791 — an un-annotated generic handed to a `let` lambda's un-annotated parameter is not instanced at the call the lambda makes

**loud emit reject · `vl check` rc 0 · clause 2 · found closing [D5751](D5751.md) · filed 2026-10-17 against master `519a09fef`**

Repro:

    function neg(a) { return 0 - a }
    let lap = (g, x) => g(x)
    print(lap(neg, 4))
    // vl check: rc 0.  vl run: emitProgram: cannot take the generic function `neg` as a value — a function value carries ONE signature

Want:

    -4

#### Mechanism

From the ablation only. [D5751](D5751.md)'s close walks a call through an un-annotated `const`
hole lambda in the instance context mono builds for that call. A `let` binding is not taken
there, because it can be written, so the call is walked once in the lambda's declaring context
and the pin of `g(x)` stays open. Closing it needs the same walk for a `let` the program never
writes, or for each value a written one can hold.
