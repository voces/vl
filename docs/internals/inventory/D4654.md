### D4654 — `return f()` in a void function is never a tail call

**closed 2026-10-14 · runs — the witness prints `1000000` · the bare `return` the checker leaves behind becomes `return_call` when the call before it is a direct call to a void user function (`emitVoidTailCall`) · fixture `tests/cases/functions/tail-call-depth-void-union-indirect.vl` · was trap after load (call stack exhausted) · filed 2026-10-14 against master `43c852e79`**

Repro:

    let total = 0
    function down(n: i32): void {
      if n == 0 { return }
      total = total + 1
      return down(n - 1)
    }
    down(1000000)
    print(total)
    // vl check: rc 0.  was, vl run: wasm trap, call stack exhausted in `down`

Want:

    1000000

#### Mechanism

The checker's `voidRetRewrite` splits `return e` in a void function into the statement `e`
and a bare `return`, so the emitter never sees a valued return there. The bare-return arm of
`emitStmt` wrote a plain `return`, and the tail-call rewrite (`emitTailCallRet`) declined every
void caller, so the self call stacked one frame per level. The rewrite now also runs at that
bare `return`, through `emitVoidTailCall`: the tail-call cursor must still be the last thing
written, the call must be direct, and the callee must be void with no lifted write-back, since
`return` tolerates a leftover result and `return_call` does not.
