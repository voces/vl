### D16998 — a bound record of a function, pushed into a list of records of un-annotated functions with different results, is refused at emit

**loud emit reject · `emitProgram: this call runs functions that return different types, and one of them is also held where it cannot be stored as one of the functions this value may hold …` · `vl check` rc 0 · clause 2 · found by lane F2's `hole-lambda-in-record-of-tagged-set` matrix (every built-in position that binds the record before the push) · filed 2026-11-19 against master `938930861`**

Repro:

    function inc0(a) { return a + 1 }
    function half(a) { return a / 2.0 }
    const xs = [{ f: inc0 }, { f: half }]
    const v = { f: (x) => x * 3 }
    xs.push(v)
    print(xs[2].f(3))
    // vl check: rc 0.  vl run: emit error, "this call runs functions that return different types, and
    // one of them is also held where it cannot be stored as one of the functions this value may hold"

Want:

    9

#### Mechanism

The lambda spelling's cause is upstream of the push: a record-field lambda is not a value-bound
hole lambda ([D17009](D17009.md)), so its parameter is pinned only by the push's replay, at the
list's closed binding.

The list's set is tagged, so its records hold an id in `f`. With a lambda in it, the record
own-storage solve builds the `const`'s literal at the closed type the push delivers it to
(`recStoreMismatchMsg`: "`v` holds only a literal, so it is built as the `{f: (i32) => i32}` it
is delivered to"), so the record solve never widens it, the tag decision's push rule (`ftSlotOp`)
refuses `xs` as a holder, and the call through the element has no one signature (the D15926 judge
in `emitCallRefAt`). A named member in the bound record runs since 2026-11-19: the push rule reads
a pushed `const` as its widened literal (`ftPushedRecLit`). The record literal written in the push
itself runs ([D16937](D16937.md)). The remaining ingredient, the lambda's literal built at its delivery
rather than widened, is lane STORE's record-row producer stage (with [D15923](D15923.md)).
