#### Mechanism

Quadratic in the lambda count, because every instance rebuilds the whole program. Each
un-annotated `(g) => g(out)` is generic in `g`, so each call instantiates it, and
`monoMakeInstance` (`compiler/emit_mono.vl`) calls `monoRebuild` after registering the instance
and again after walking its body. `collectA` and `buildFnMap` resume from where the last rebuild
stopped, but `computeVoidFns` and `computeRetInference` re-run over every function, so each of
the 2N instances costs O(program): 88% of a 100-pair build is `monomorphize`, all of it under
`monoRebuild`, and under the null collector every rebuild's garbage stays, which is the
4.1 GB. `VL_COMPILE_GC=copying` compiles 300 pairs (1.7 GB peak RSS, 70 G fuel): the trap is the
collector's, the cost is the rebuild's.

Inside a rebuild, `computeRetInference` and `computeVoidFns` asked `capturedKindOf` of `main`
for most of its identifiers, and each ask recomputed `main`'s capture set, with a
`nestedFnDeclaredIn` scan of `main`'s 2N children per reference to a module function. Lane CT
armed the capture memo for those two passes inside `monoRebuild`, as the pass table already
arms it for `computeRetInference`, after reporting an edit so no answer survives from the
previous rebuild. That cut fuel by 27–40% and changed no output (every `tests/cases` program
and corpus cell builds byte-identical); it does not change the order:

| pairs | fuel before | fuel after | peak RSS after |
| ---: | ---: | ---: | ---: |
| 10 | 109,882,757 | 101,519,039 | 56 MB |
| 30 | 825,771,915 | 713,518,787 | 109 MB |
| 100 | 10,288,768,063 | 7,446,692,259 | 683 MB |
| 200 | 50,694,366,152 | 30,263,048,196 | 2,540 MB |
| 300 | trap | trap | — |

**Plan (not built).** `monoRebuild` must cost the new instance, not the program. Two ways,
cheapest first: (1) batch — defer the rebuild while the instance's body contains no generic
call and no call whose return inference could read the new instance, and run one rebuild per
batch; (2) make `computeVoidFns`/`computeRetInference` resumable like `collectA`, re-seeding the
fixpoint with the new instance and the callers whose tail or return reaches it (the reverse
call edges `buildFnMap` already walks). Either needs the instance's callers to see its return
kind before their own emission, which is what the per-instance rebuild guarantees today. A host
fallback — retry a compile that exhausts the null collector's heap under the copying collector —
would move the 300-pair program from a trap to a 21 s compile and is independent of both.

| ingredient removed | outcome | needed? |
| --- | --- | --- |
