### D16604 — a `??` default that is a shift constant past 32 bits is pinned to an `i32` left operand instead of widening the join

**closed 2026-11-15 · runs, prints `1099511627776` · was a loud check reject, clause 2, `constant 1099511627776 overflows i32` · bucket (f) · closed by letting a `??` default that is an integer constant its left side's number type cannot hold skip the fits-the-left test, so the join widens as the `if` does (`checkCoalesceBinNode`, check_operators.vl); the folded shift had been refused there in its own words by the destination seam (`cexDeliver`) · fixture `tests/cases/numerics/coalesce-default-constant-wider-than-left.vl` · ruling 4.3 (one join rule for every join form) and Q8 (a shift count of 32 to 63 makes an untyped literal operand `i64`) permit it · found by lane T's literal-adoption position matrix · filed 2026-11-15 against master `c8f0324da`**

Repro:

    const n: i32 | null = null
    print(n ?? (1 << 40))
    // vl check: constant 1099511627776 overflows i32

Want:

    1099511627776

#### Mechanism

Not localised past the ablation. The default of a `??` over an `i32 | null` operand is checked at
the operand's `i32` when it is a shift constant, so the widening its count earns (Q8) is refused
there. A decimal constant of the same value keeps its default and widens the join, as 4.3 says,
and so does the `if` join of the same two values.
