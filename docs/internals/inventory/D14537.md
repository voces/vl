### D14537 — a discriminant narrowing of a receiver whose arm shares its structure with another union's arm reads the checker's arm, not a name derived from the structure

**closed · a Step 6 pin: the narrowed read's variant row comes from the checker's read type and storage type, never `narrowVariantFor` · filed 2026-10-27 against master `1810bc326`**

Repro:

    type C = { kind: "circle", r: f64 }
    type R = { kind: "rect", w: f64 }
    type S = C | R
    function area(s: S) {
      if s.kind == "circle" { return s.r }
      return 0.0
    }
    type KC = "circle"
    type KR = "rect"
    type Ca = { kind: KC, r: f64 }
    type Ra = { kind: KR, w: f64 }
    function areaA(s: Ca | Ra) {
      if s.kind == "circle" { return s.r }
      return 0.0
    }
    print(area({ kind: "circle", r: 3.0 }))
    print(areaA({ kind: "circle", r: 9.0 }))

Want:

    3
    9

#### Mechanism

`C` and `Ca` are one arena type once `KC` folds, so a nominal name derived from the
structure is ambiguous across the two unions. The emit narrowing stack resolved the narrowed
receiver's variant by that name, declined on the ambiguity, and the member read fell to a
shared-field plan that refused `r` (`field access but no struct type declared`). The read now
takes its variant row from the checker's read type (`narrowedReadRow`), gated on the
checker's recorded storage type (`nodeNarFrom`) being a union box, so no name is consulted.
