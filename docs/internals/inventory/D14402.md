### D14402 — an un-annotated destination of a hole function takes its function type only from the emitter's call flow

**runs today and must keep running · carried by the emitter's flow pin, not by the checker · filed 2026-10-27 against master `9687dabf4`**

Repro:

    function inc7(u) { return u + 1 }
    function inc8(u) { return u + 1 }
    const us = [[inc7]]
    us.push([inc8])
    print(us[1][0](3))
    // vl check: rc 0.  vl run: 4

#### Mechanism

`us` has no annotation, so no declared function type reaches `inc8` and the checker's
adoption (`recordRepTyAdopt`) has nothing to stamp. `inc8` is built at `(i32) => i32` only
because the emitter's 0-CFA flow table records the signature of the one call through the
slot, `us[1][0](3)`, and `monoDeliverLitAt` reads it through `monoSlotPinNameTys`. With that
read removed the program is an emit reject: `cannot take the generic function inc8 as a
value ... No call site pins inc8`. This class holds most of the pin sites left after
the S2 adoption slice. Its destinations are a hole `let`, an inferred record field, an
un-annotated list of hole functions, and an un-annotated function's inferred result.
Closing it means the checker infers a hole's function type from its uses. That needs a
design note before code.

`tests/cases/functions/error-generic-fn-value-alias-stored-in-list.vl` is the same class.
`const ks = [k]` stores an alias of a hole function in an un-annotated list. Under Decision
5 (`architecture-target-2026-10.md`) the program should run, but no declared type reaches
`k`, so it keeps its `@emit-error`.

#### Ablation

| ingredient removed | outcome | needed? |
| --- | --- | --- |
| the flow-pin read in `monoDeliverLitAt` | emit reject, `No call site pins inc8` | **yes** |
| the annotation's absence (`const us: ((u: i32) => i32)[][] = [[inc7]]`) | runs on the checker stamp | **yes** |
