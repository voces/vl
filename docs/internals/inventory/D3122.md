#### Mechanism

D1230's registry (`ufcsImpAdd`, filled by `modCollectSelfFns`) holds only modules the
host loaded, so a program that imports nothing from `std:str` got the plain `no method
'.trimEnd' on string` and the same program with any `std:fmt` import got the suggestion.
And the list arm of `checkCallNode` raised its own `no method … on array` with no D1230 or
D1570 fall-through, so a list receiver never got either sentence. The close adds
`compiler/std_receivers.vl`, generated by `deno task gen-std` from std's exports whose
receiver annotation a program can hold without the module (builtin leaves, the function's
type parameters, `[]`, `readonly`, `|`), read by `stdRecvSpecsInto` for modules the
registry has no row for, and matched on the annotation's spelling (`stdRecvFits`). The list
arm now shares the string arm's raise (`ufcsMissRaise`), which puts D1230 on the property
token, where `ufcsMissingImportAt` reads the quick-fix's member name; it was on the whole
call, so the string quick-fix found no name. `ufcsWouldDispatch` now mirrors `ufcsCallTy`'s
refusal to bind a type parameter to `u8` — a `self` whose substituted type still holds a hole
after the receiver binds, so `describe<T>(self: T)` takes a `u8[]` and `count<T>(self: T[])`
does not.

A name the caller's module already binds would collide with the proposed import (review of
#3277). `ufcsSiteKind` resolves that binding (its `self`-function, else its own declaration):
a plain function (D1570 kind 1) answers with D1570 ahead of every candidate module, a
`self`-function that declines (kinds 2, 3) answers ahead of std's catalog while a loaded
module keeps D1984's aliased import, and any other binding — a `const`, a local — makes
`ufcsImportAliasAt` propose an alias (`ufcsFreeAliasAt` now decides it).
