### D17093 — `print` of a bare `null` literal takes the i32 arm, since `exprIsNulNone` answers only from a cell

**fixed 2026-11-24 · closed, runs `null` · was: check-clean invalid wasm · clause 1 · filed 2026-11-24 against master `0fccbcba` · fixed by `printArmOf` (wasmEmit.vl): a bare `null` literal operand takes the `nulNone` arm · fixture `null/print-a-bare-null-literal.vl`**

Repro:

    print(null)
    // vl check: no errors.  vl run: invalid module, type mismatch: expected i32, found nullref

Want:

    null

#### Mechanism

`printArmOf` asks `exprIsNulNone` first, and for a `NullLit` that falls to its last line,
`identCellVKind(...) == "nulnone"`; a literal names no cell, so the answer is false. No other
classifier claims a `null` literal, and the ladder ends in its default `"i32"`, which calls
`__print_i32__` on the `ref.null` the literal builds. Every other spelling of a `null` value
reaches a cell, a join rep or a call result that names the unit and prints `null`.

#### Ablation

| spelling | outcome | in the family? |
| --- | --- | --- |
| `print(null)` | invalid module | **yes** |
| `print((null))` | invalid module | **yes** |
| `function show() { print(null) }` | invalid module | **yes** |
| an `else { print(null) }` arm beside `print(x)`, `x: i32 \| null` or `R \| null` | invalid module | **yes** |
| `let n = null` then `print(n)` | prints `null` | no |
| `const x: i32 \| null = null` then `print(x)` | prints `null` | no |
| `print(if true { null } else { null })` | prints `null` | no |
| `function z() { return null }` then `print(z())` | prints `null` | no |

#### Grading list

The three in-family spellings above besides the witness (parenthesised, in a function body, in an
`else` arm over `i32 | null` and over a record `R | null`), and `print` of a bare `null` in a string
interpolation hole and as one argument of a multi-value print, if the design admits it there.
