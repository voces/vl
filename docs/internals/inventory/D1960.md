**closed 2026-09-22 — the witness prints `1`, `-1`, `no` · was loud emit reject `emitProgram: unsupported for-in iterable`, `vl check` rc 0, clause 2, positioned at the enclosing function's NAME · reported by plumb (PL-005) · filed against master `a8a104432` · fixture `tests/cases/unions/arm-struct-ref-list-field.vl` · sibling trap [D1961](D1961.md)**

Repro:

    export type P = { xs: S[] }

#### Mechanism

Once `P` is an arm of a union of two structs, its layout lives in the VARIANT tables (`uField*`)
and it has no struct row, so `structIndexOfExpr(self)` is -1 for a param typed `P`.
`refListElemNameOfExpr`'s `Member` arm asked only the narrowed-variant rung and that struct
rung, so an un-narrowed arm receiver answered `""`, while `memFieldTypeCode` — which carries
the `exprVariantIndex` and `nulvariant` rungs — still called the field a ref list. The name
miss made `forInElemKind` null. The fix gives the name ladder `memFieldTypeCode`'s receiver
rungs arm for arm (variant, nullable variant, struct, shared-union field), and the refusal
is now positioned at the iterable rather than at the ambient function span.
