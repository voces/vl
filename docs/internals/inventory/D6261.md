### D6261 — a hole function called through a `const` alias, with a generic called at two types, is not split

**loud emit reject · `vl check` rc 0 · clause 2 · found closing [D6204](D6204.md) · the same on master `4090ad9df` · filed 2026-10-17 against master `4090ad9df`**

Repro:

    function add(a, b) { return a + b }
    function apply2(g) {
      print(g(1, 2))
      print(g(1.5, 2.5))
    }
    const h = apply2
    h(add)
    // vl check: rc 0.  vl run: emitProgram: cannot take the generic function `add` as a value — a function value carries ONE signature, and parameters `a`, `b` are un-annotated (they would default to i32). Call sites pin `add` at (i32, i32), (f64, f64) — annotate the parameters with the signature this value needs, or call `add` directly by name

Want:

    3
    4

#### Mechanism

From the ablation only. The split plan takes a hole parameter only when every read of its
function is a call (`fsHoleParamOk` in `compiler/fn_split.vl`). `const h = apply2` reads it
as a value, so `g` keeps one type, and the generic reaches the emitter's floor. Exported or
not, the outcome is the same.
