### D14162 — a named alias intersecting a recursive record type with another record has no struct row of its own, so a field or nullable of it refuses

**closed 2026-11-10 · runs, prints `3` · was loud emit reject, `emitProgram: field access receiver is not a struct`, clause 2 · the record field and nullable positions store a one-member intersection alias at its record's row · fixture `tests/cases/objects/intersection-alias-field-and-nullable-positions.vl` · found ablating the G12 field-set-scan cells · filed 2026-10-26 against master `bbdd4e720`**

Repro:

    type Node = { v: i32, next: Node | null }
    type M = Node & { v: i32 }
    type H = { m: M }
    const h: H = { m: { v: 3, next: null } }
    print(h.m.v)

Want:

    3

#### Mechanism

The canonicaliser folds `type AB = {a: i32} & {b: i32}` to the shape `{a:i32,b:i32}`. It leaves
`Node & { v: i32 }` spelled as an intersection, because `Node` refers to itself. So `collectS`
interns no row under the name `M`. The checker still types `M` as a one-member union over
`Node`'s record. Since 2026-11-10 the readers asked by type fold that union to its record
(`repStructRowOfTy`, `structRowOfRecordTy`, `recordStructRow`), and every position they serve
runs on `Node`'s row. A record field typed `M` and a nullable `M | null` are lowered by name, and
`M` names no row.

runs since 2026-11-10:

The record field refused for the non-recursive aliases too, from a declaration alone, with
`struct field type … has no struct-field rep`. The four readers each asked for a `TyObj` where the
checker records the alias's one-member union. `nameFieldCodeTy`, `nulBaseStructRow` and
`retNulRefFlag` now peel that union, as the nullable rung of `nameFieldCodeTy` already did.
`sFieldTgtStructIdx` stores a field of a recursive alias, whose declaration interns no row of
its own, at its record's row.

`a == b` over two `M` values traps the compiler, as it does over plain `Node` (D15636).

has to re-grade the others.
