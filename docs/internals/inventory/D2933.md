### D2933 — an un-annotated record literal that matches a declared record exactly is delivered unconverted into a nullable-field record of the same names

**check-clean invalid wasm · clause 1 · the same on master `e91e04a8f` and on `a41bd80e8` · no list adoption involved · found in the #3238 review · filed 2026-09-28 against master `e91e04a8f`**

Repro:

    type J = { f: i32 | null }
    type I = { f: i32 }
    const il = [{ f: 7 }]
    function show(r: J) { print(1) }
    show(il[0])
    // vl check: rc 0.  vl run: invalid module in the top-level code

Want:

    1

#### Mechanism

Not localised past the ablation. The literal `{ f: 7 }` builds at `I`'s row, since `I` declares
exactly its field types, and the element is passed to `show`'s `J` parameter with no
conversion. `J`'s `i32 | null` field is stored differently. Without `I`, the literal adopts
`J`'s row from its delivery, as D2060 describes, and runs. A declared type that matches exactly
pins the row the same way an annotation does in [D2100](D2100.md).

#### Ablation

| ingredient removed | outcome | needed? |
| --- | --- | --- |
| `type I = { f: i32 }` | runs, prints `1` | **yes** |
| the list (`const r = { f: 7 }` then `show(r)`) | still invalid | no |
| the delivery, as `const j: J = il[0]` | still invalid | no |
| an annotated `const i: J = { f: 4 }` added | still invalid | no |

#### Grading list

The same with a record-valued field and a spread, and no delivery at all:
`type A = { v: i32 }`, `type J = { f: A | null }`, `type I = { f: A }`,
`const il = [{ f: { v: 7 } }]`, `const cp = [...il]`, `print(cp.length)` is invalid wasm, and
runs without `type I`. The #3238 review's `showJ` and `tkJ` forms beside an annotated
`const i: J` are invalid the same way.
