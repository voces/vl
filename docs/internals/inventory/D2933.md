### D2933 — an un-annotated record literal that matches a declared record exactly is delivered unconverted into a nullable-field record of the same names

**now a loud emit reject · clause 2, still open · was check-clean invalid wasm, the same on master `8615a730d` · the binding face now RUNS: an un-annotated literal is built at the record its binding is handed to (`objLitBindDestRow`); the list face runs where a list of that record exists and is refused where none does (`rsElemListDestSlot`) · fixtures `tests/cases/soundness/record-literal-builds-at-declared-destination.vl`, `tests/cases/soundness/error-record-literal-at-two-record-destinations.vl`, `tests/cases/soundness/error-record-list-element-to-another-record.vl` · found in the #3238 review · filed 2026-09-28 against master `e91e04a8f`**

Repro:

    type J = { f: i32 | null }
    type I = { f: i32 }
    const il = [{ f: 7 }]
    function show(r: J) { print(1) }
    show(il[0])
    // vl check: rc 0.  vl run: invalid module in the top-level code

Want:

    1

#### Mechanism

`structIndexOfObjCtx` picks a literal's row by field names, and with two rows of the same names
it takes the one the literal's own type names, `I`. No delivery converts a record, so handing that
struct to `J` is invalid. Without `I` the name scan finds only `J`, which is why the ablation runs.

The binding face is closed at the literal. `objLitBindDestRow` walks the binding's uses with
#3238's use index. If a use hands it to a declared record of the literal's field names that is
stored differently, and every other use reads that row, the literal is built there. A binding
that one use needs at each row is refused. The list face asks the same question of an element
use (`rsElemListDestSlot`). It re-seats the list when a list of the destination's record is
interned, and it is refused otherwise, since no heap type for that list exists by the time the
use index can be built. That refusal is this repro, and the reason the row stays open under
clause 2.
