### D1483 — a `?.` whose receiver is a CALL or an INDEX has no lowering, while the identical value bound to a name first runs

**loud emit reject · `vl check` rc 0 · clause 2 · ``emitProgram: `?.` needs a re-readable receiver (a name, or a field chain of names)`` · filed 2026-09-03 against master `cdfdc14e`**

Repro (four lines; `vl check` rc 0, then the emitter refuses at 3:18):

    type Contact = { phone: string }
    function find(): Contact | null { return null }
    const p = find()?.phone
    print(p ?? "-")

#### Mechanism

The refusal's own sentence is accurate about the constraint and silent about the reason: `?.`
lowers as a null TEST followed by a read, and the receiver is emitted TWICE, so a receiver
with an effect cannot be re-emitted. That is a lowering restriction, not a design rule — the
sibling shared-field dispatch in `emitMem` solved exactly this by handing out a stash slot
(`sharedFieldRecvSlot`) and evaluating a non-`Ident` receiver ONCE into it. `?.` never got
that slot, so a `Call` and an `Index` receiver both floor while a name, a paren-wrapped name
and a field chain of names all run.

**THE i32 FIELD REACHES A SECOND LITERAL, so this gap has at least two sites.** With the
field typed `i32`, `find()?.n ?? -1` refuses at ``emitProgram: `??` over this nullable value
is not supported yet — narrow it first`` instead — the same non-name receiver, a different
message, and the NAME-receiver spelling of that one runs too.

#### Ablation

| ingredient removed | outcome | needed? |
| --- | --- | --- |
| the CALL receiver (`const c = find()` then `c?.phone`) | runs | **yes** — the rescue |
| the CALL receiver, replaced by an INDEX (`xs[0]?.phone`) | refuses, same message | the ingredient is "not a name", not "a call" |
| the CALL receiver, replaced by a paren'd name (`(c)?.phone`) | runs | no |
| the CALL receiver, replaced by a field chain (`o.inner?.phone`) | runs | the message's own promise holds |
| the `??` (bare binding of the `?.`) | refuses, same message | no — `??` is scenery |
| the annotation (`const p: string \| null = …`) | refuses, same message | no — annotating is not a rescue |
| the null return (the function returns a real value) | refuses, same message | no — the runtime value is irrelevant |
| the `string` field (an `i32` field, call receiver) | refuses, DIFFERENT message (the `??` literal) | no — a second site |
| the `string` field (an `i32` field, NAME receiver) | runs | — |

#### Grading list

The four RUNS rows must keep running. The close must move BOTH literals — the `?.` one and
the `??`-over-a-nullable one — since one receiver restriction reaches them both, and a fix
that only teaches `?.` a stash slot leaves the `i32` spelling refusing. Grade at a `Call`
receiver AND an `Index` receiver; reading the call sites is what missed the second one in
