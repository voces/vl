### D3843 — a never-read top-level hole lambda whose name a nested function's parameter reuses is still lowered at its `i32` default

**closed (2026-10-08, lane SC) · was check-clean invalid wasm · found closing D3832 · filed 2026-10-08 against master `52c8e492d` · pins: `tests/cases/closures/unread-hole-lambda-name-shadowed.vl`, `tests/cases/closures/hole-lambda-read-beside-shadowed-name.vl`**

Repro:

    const c = (y) => y + "C"
    function k(c: string) { c }
    print(k("z"))
    // vl check: rc 0.  vl run: invalid module inside `c`, `expected (ref $2), found i32`

Want:

    z

#### Mechanism

D3832's close stubs a hole lambda when no name in its enclosing frame reads its `const`. The
search is by name, not by binding, so `k`'s parameter `c` counts as a read and the lambda is
lowered at its parameter's `i32` default, as before that close. The frame walk now carries the
names each nearer scope rebinds (a function's name and parameters, a loop's variables, a
block's declarations from the statement on), and a read of a frame-level name that one of them
shadows is not counted. The same holds for a parameter, a block `const`, a loop variable, a
lambda parameter, a nested function, and a function-scope lambda.

#### Ablation

| ingredient removed | outcome | needed? |
| --- | --- | --- |
| the shadowing name (`function k(s: string) { s }`) | prints `z` | **yes** |
| the top level (the lambda inside a function, `k` beside it) | prints `z` | **yes** |
