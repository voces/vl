### D3673 — no diagnostic for a discarded operator statement over scalar names, so a line led by `-` that silently drops half an expression says nothing (sunpa SP-040)

**closed 2026-10-05 — the witness runs and `vl check` now warns on its second line · was check-clean with no diagnostic on master · by widening `unused-pure-expression` to operator trees over plain scalars, with a line-break message for a statement led by `-` · the parser is unchanged: whether a leading `-` continues the line above is a pending owner decision · sunpa SP-040, the camera's aim · filed and closed by lane LW against master `d2b09774b` · fixtures `tests/cases/lint/unused-pure-expression-scalar-operands.vl`, `tests/cases/lint/unused-pure-expression-no-warn.vl` · since D3698 (owner ruling 2026-10-05) the spaced witness below continues the line and prints -0.5 with no finding; the line-break message now covers the tight `-b` spelling only**

Repro:

    function f(a: f64, b: f64): f64 {
      const w = a * 3.0
        - b * 3.5
      w
    }
    print("\{f(1.0, 1.0)}")   // prints 3, want -0.5; the second line is a separate, discarded statement

#### Mechanism

A leading `+` continues the expression above, a leading `-` does not: `- b * 3.5` parses as
a statement of its own, unary minus over `b` times `3.5`, and its value is dropped. The only
rule that looks at discarded statements, `unused-pure-expression`, admitted an operator tree
only when every leaf was a literal, because an identifier operand could carry an object type
that dispatches the operator to a user overload. `b` is an `f64`, so nothing fired. The rule
now also admits leaves that are names or field reads of an unbranded number, boolean or
string: no overload can take those. A field read counts only when its receiver chain is names,
parentheses and field reads that are not getters, so `mk().x` and `xs[i].x` stay quiet, and an
integer `/` or `%` by a read (which traps on zero) counts only over literals. Under `vl check` and the corpus the checker banks each such read's type (by token
offset, the `byte-as-code-point` channel); the editor, which lints before it checks, sees
parameters and `let`s annotated as a scalar and `let`s initialised from literals. A
non-final operator statement whose first token is a `-` on its own line gets a sentence of
its own whatever its operands are, since the claim is only that the value is discarded:
sunpa's line called `smooth01`, which the general sentence never fires on.

#### Ablation

| ingredient removed | outcome | needed? |
| --- | --- | --- |
| the line break before `-` (one line) | `w` is -0.5, nothing to report | **yes** |
| the `w` after it (the `-` line is the block's value) | returns -3.5, the second line alone; nothing is discarded | **yes** |
| `b`'s annotation (un-annotated `b`) | still fires: the line-break message reads no types | no |
| `b * 3.5` replaced by `smooth01(b) * 3.5` (sunpa's shape) | still fires, line-break message | no |
| leading `+` instead of `-` | continues the expression, `w` is 6.5 | **yes** |
