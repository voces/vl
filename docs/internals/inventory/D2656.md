### D2656 — a `for k, v` over a map whose value is a literal union binds an interned index, not the member's string

**check-clean silently wrong · clause 1 · found by #3189's review (P2) · identical on master at every key rep · filed 2026-09-26 against master `979323f83`**

Repro:

    type L = "p" | "q"
    const m: {[string]: L} = Map()
    m.set("a", "q")
    for k, v in m { print(v) }
    // PRINTS 0

#### Mechanism

A literal-union map value rides the mono i32 `vals` list as its interned atom, and the
`for k, v` loop variable is bound from that cell with the value kind of an `i32`, so the print
lowers the atom's index rather than rendering the member's text. `m.get(k)` and
`for v in m.values()` render the member (they print `q`); the two-name `for` form is the one
consumer that does not.

#### Ablation

| ingredient removed | outcome | needed? |
| --- | --- | --- |
| the literal union (`{[string]: string}`) | prints `q` | **yes** |
| the two-name loop (`for v in m.values()`) | prints `q` | **yes** |
| the string key (`{[i32]: L}`) | prints an index | no |
| a union around the map (`{[i32]: L} \| string`, narrowed) | prints an index | no |
