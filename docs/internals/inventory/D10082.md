### D10082 — a `slice` of a list holding a generic leaves the source with no instance when the source is called at two types

**loud emit reject · `vl check` rc 0 · `a generic function taken as a value reaches no call that fixes its type` · clause 2 · CAPABILITY: the copy spelled `[...xs]` prints `2`, `s` · found closing [D10020](D10020.md) · present on master `e0eecffc4` · filed 2026-10-22 against master `e0eecffc4`**

Repro:

    function id<T>(x: T): T { x }
    const xs = [id]
    const ys = xs.slice(0)
    print(xs[0](2))
    print(xs[0]("s"))
    // vl check rc 0.  vl run: emit error: emitProgram: a generic function taken as a value reaches no call that fixes its type — annotate the destination's function type

Want:

    2
    s

#### Mechanism

Not traced. `slice` hands the list to a built-in whose result shares the source's element, and
the emitter's per-call-type plan for `xs` declines on that read, so `id`'s element instance is
never chosen. The spread copy took the same plan since [D9595](D9595.md); `slice` has no such
arm. With `ys` written with `inc` (`ys.push(inc)` or `ys[0] = inc`) and called, the refusal is
`a list holding a generic function is called through its elements at more than one type`.

#### Ablation

| ingredient removed | outcome | needed? |
| --- | --- | --- |
| `[...xs]` instead of `xs.slice(0)` | runs, `2`, `s` | **yes** |
| `xs[0]("s")` (one call type) | runs | **yes** |
| the slice (`ys` not declared) | runs | **yes** |

#### Grading list

- `ys.push(inc)` then `print(ys[1](2))`, beside the two calls of `xs[0]`.
