### D3898 — an un-annotated callback to a user generic over an inline record whose field names a declared record, beside a `Box<A[]>` callback, refuses to build

**loud emit reject · the user-generic sibling of D3875, found closing it · filed 2026-10-09 against master `e0d15f2e6`**

Repro:

    type A = { x: i32 }
    function h<T>(x: T) { x.x }
    type Box<T> = { v: T }
    function ap<T, U>(xs: T[], f: (t: T) => U): U[] {
      const r: U[] = []
      for x in xs { r.push(f(x)) }
      r
    }
    const ba: Box<A[]> = { v: [{ x: 1 }] }
    print(ap([ba], (e) => h(e.v[0]))[0])
    const o: { v: A } = { v: { x: 2 } }
    print(ap([o], (e) => h(e.v))[0])
    // vl check: rc 0.  vl build: emitProgram: field access receiver is not a struct

Want:

    1
    2

#### Mechanism

D3875's fix is for a callback passed to a built-in `.map` / `.filter`, which takes the pin
`monoLamPinName` spells. A callback handed to a user generic keeps that generic's instance key, the
render (`{v:{x:i32}}`), per D3834's review. The inline record's row is interned under `{v:A}`, and
in a program that also pins `h` through `Box<A[]>` the render reaches no row. Not fixed with D3875,
whose change is to the built-in path's spelling only.
