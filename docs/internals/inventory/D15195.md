### D15195 — a list literal of two records, one whose list field was written a function, passes check and builds invalid wasm

**check-clean invalid wasm · `type mismatch` in the module's top-level code · clause 1 · open, target `1.5` then `4` · was loud emit reject, `emitProgram: ref valtype with no interned shape`, on master `d467911e`, before [D15138](D15138.md) widened the written record's field · found ranking the D15193 family · filed 2026-11-03 against master `2bb36ff5`**

Repro:

    function inc0(a) { return a + 1 }
    function half(a) { return a / 2.0 }
    const r = { xs: [inc0] }
    r.xs[0] = half
    const q = { xs: [inc0] }
    const rs = [r, q]
    print(rs[0].xs[0](3))
    print(rs[1].xs[0](3))
    // Want:
    //   1.5
    //   4

#### Mechanism

Since D15138, `r`'s field `xs` is widened to the set `{inc0, half}` while `q`'s keeps `{inc0}`, so the list literal `[r, q]` holds two record types whose `xs` fields carry different sets, and the element is built at one of them. The same holds when the written function has the same result type (`r.xs[0] = dbl`). A list of two lists of different sets, `[a, b]`, is refused at emit (`ref valtype with no interned shape`) as this program was before D15138.
