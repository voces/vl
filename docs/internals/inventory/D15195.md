### D15195 — a list literal of two records, one whose list field was written a function, passes check and builds invalid wasm

**loud emit reject · `emitProgram: ref valtype with no interned shape` · clause 2 · open, target `1.5` then `4` · was an invalid module after a clean `vl check` from [D15138](D15138.md) (#6081) to 2026-11-03, and a loud emit reject before it on master `d467911e` · found ranking the D15193 family · filed 2026-11-03 against master `2bb36ff5` · no longer built since 2026-11-03: a record listed beside other bindings widens its field over their writes too (`fnFieldListedWith`, check_elab_cap.vl), so the literal no longer holds one record at the widened type and one at the literal's, and the emitter refuses it as it refuses two lists of different sets. Running it waits on the shape [D15194](D15194.md) names**

Repro:

    function inc0(a) { return a + 1 }
    function half(a) { return a / 2.0 }
    const r = { xs: [inc0] }
    r.xs[0] = half
    const q = { xs: [inc0] }
    const rs = [r, q]
    print(rs[0].xs[0](3))
    print(rs[1].xs[0](3))
    // Want:
    //   1.5
    //   4

#### Mechanism

Since D15138, `r`'s field `xs` is widened to the set `{inc0, half}` while `q`'s keeps `{inc0}`, so the list literal `[r, q]` holds two record types whose `xs` fields carry different sets, and the element is built at one of them. The same holds when the written function has the same result type (`r.xs[0] = dbl`). A list of two lists of different sets, `[a, b]`, is refused at emit (`ref valtype with no interned shape`), as this program was before D15138 and is again now. A list of one written record, `[r]`, and of a record and its alias, `[r, q]` with `q = r`, run.
