#### Mechanism

The inverse of [D1476](D1476.md)'s own field split, on the arm that row did not touch. A
nested-struct field read reads back `(ref null $S)` — the lowering folds `inner: S` and
`inner: S | null` onto one code-15 hop — so `letInitCellKind` gives the binding `"nulstruct"`,
which is what D1476 built. `captureValKind`'s ANNOTATED arm does not consult that ladder: it
returns `vtKindOfType(bn.letType)`, and the annotation says `Rec`, so the env field is declared
at the non-null `(ref $S)` while the value arrives nullable.

The arm already carries the machinery for exactly this disagreement — D1632's rung compares the
annotation kind's nullable NICHE against `letInitCellKind`'s answer and prefers the niche — so
the question a close owes is why that rung declines here, not whether the reconciliation
belongs.

**The un-annotated spelling of the same program RUNS**, which is the tell: this is the one
face of the projection family where annotating is what breaks it, and every instrument in the
family annotates.
