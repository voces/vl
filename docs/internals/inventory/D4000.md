### D4000 — a bounds guard that the enclosing loop's range already decides is still tested on every iteration: VL and binaryen keep no loop-range facts, and V8's wasm tier does not fold them

**runs today and must keep running · open · a cost row, no wrong value · a ROADMAP-level feature (loop-range facts that fold guards after inlining) · diderven DV-1000 (`view.vl` drawWallCorner, `drawDress`, `jitterAt`) · lane PF · filed 2026-10-11 against master `50ab2d601`**

Repro:

    import { filled } from "std:array"
    const wall = filled(136 * 136, 0)
    function rockAt(x: i32, y: i32) {
      if x < 0 || y < 0 || x >= 136 || y >= 136 { return 1 }
      wall[y * 136 + x]
    }
    function corners(): i32 {
      let s = 0
      for y in 0 until 136 { for x in 0 until 136 {
        s += rockAt(x - 1, y - 1) | (rockAt(x, y - 1) << 1) | (rockAt(x, y) << 2) | (rockAt(x - 1, y) << 3)
      } }
      s
    }
    print(corners())

Want:

    1631

#### Mechanism

The scan spends its time on guards, not on the access path. Each cell runs four inlined
`rockAt`s: 16 range compares and four list bounds tests. Inside `for x in 0 until 136` only
about five of those compares can be true (`x - 1 < 0`, `y - 1 < 0`); the rest are false for
every `x` and `y` the loop produces. V8's JavaScript tier range-types the induction variables
and folds them, which is why the hand-written JS runs at 32–63 µs a call. Neither VL's emitter,
binaryen, nor V8's wasm tier keeps those facts. VL runs at 122–234 µs at default and 201–318 µs
at `-O3`. That is node 24, at load 30–90 on 24 cores, as the minimum of 40–50 interleaved
rounds, repeated three times. The access path is not the cost. The same program with the array
in a local and every guard inlined by hand measures the same as `rockAt` (131–194 µs). Dropping
only the guards the loop decides gives JS speed (42–76 µs). Removing the mutable nullable
global, the `ref.as_non_null`, the closure-ABI `structref` parameter and the list bounds test
together moves it 10–20%, inside the noise one at a time.
