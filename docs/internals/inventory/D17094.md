#### Mechanism

Legacy refuses this program at `m["a"] = lap(...)` (7:26): "emitProgram: a function returning a
parameter called at two signatures is called where its result is not used at one of them". The
map's record note (`elabSlotRecordNote`) declined because `m` is read from a function, so the map is
declared at the closure struct while `lap(...)` returns the bundle record. A function body the IR
claims is written by the IR and skips that refusal: the claimed start stores the bundle record
(`{c0:(f64)=>f64,c1:(i32)=>i32}`) into the closure-typed slot, and the module fails validation. The
shadow (modes 1/2/6) reads every function matched, since it compares the IR's bytes to legacy's per
function and never sees legacy's refusal; only `ir-identity --claimless` shows it (exit 70 vs 1).
The claim skipping a legacy refusal is IR-P1's, routed by the coordinator.
