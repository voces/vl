### D5972 — an annotated local function binding gives its type to a module binding of the same name called through a hole

**closed 2026-10-17 by lane L1 · runs, prints `3` then `w` · was loud check reject · clause 2 · a deferred row's reach test (`wrUnreachedBy`) matched a call through a binding by NAME, and now matches the call's own declaration; a row no top-level function owns (an annotation in a lambda's body at module scope) reaches a call elsewhere only when that body is checked inside a generic; and a top-level function named as an annotated value records no row, since the delivery has already checked its body · pins: `tests/cases/closures/annotated-local-binding-type-stays-with-its-binding.vl`, `tests/cases/closures/error-annotated-local-binding-called-off-its-type.vl` · found closing [D5660](D5660.md) · filed 2026-10-17 against master `7497c0982`**

Repro:

    function fw(f) { return f }
    function id(x) { return x }
    function g() {
      const h: (x: i32) => i32 = id
      print(h(3))
    }
    g()
    const h = fw(id)
    print(h("w"))
    // vl check: rc 1, cannot assign (string) => string to 'h' of type (i32) => i32 (the body of `h` at the call's argument types)

Want:

    3
    w

#### Mechanism

The two `h` bindings are in different scopes, and the refusal names the local's annotation
at the module binding's call. The annotation records a deferred row against `id`'s body, and
`wrUnreachedBy` (`check_decl_scan.vl`) let every call whose callee had the row's binding NAME
re-ask it, so `h("w")` through the module binding was checked at `(x: i32) => i32`.
