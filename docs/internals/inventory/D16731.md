#### Mechanism

The tag decision for a set held in a record field is asked by several walks, in the checker and
the emitter, each with its own depth budget: `ftHoldKind` and its siblings (`FT_HOLD_DEPTH`,
eight), the join walks (`elabFnJoinDeepAt`, `elabFnArmJoinAt`, six), the held-rep walks
(`fnTagRecLitsOnly`, `fnTagHeldRecLit`, eight; `fnTagRepTyIn`, sixteen), `fnTagHoldsTy` (four to
sixteen by caller), and the walks that build a literal at its place (`recordRepTyAdopt`,
`recLitFnFieldsAt`, six). At seven records `ftHoldKind` ran out first: the field was left a
closure, and emit reached `inc0` as a generic value. Lifting one budget moves the cut to the next,
and lifting some but not the held-rep walks builds an invalid module, because the walks must
agree. None takes a budget now: a type walk carries the types it has met (a recursive type stops
there), and a literal walk is bounded by the literal.

Lifting them exposed an exponential read. `readRepOf` skipped its memo for a read whose type
names a type variable, and a field read asks its receiver twice, so sixteen levels took 13.6 s.
Such a read is now remembered within one outermost query, where the instance cannot change
(0.04 s at sixteen, 0.14 s at twenty-five).
