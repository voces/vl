### D3038 — a record literal with a type-parameter field passed to another generic has no row when that call is monomorphized

**closed 2026-10-26 — now prints `s` · was loud emit reject, clause 2 · the mint interns a row at each closed record type the elaboration gives the literal per instance, so the bound-first face reaches `h` at that row · found grading [D3032](D3032.md) · filed 2026-09-28 against master `3a71bb1f9` · pin: `tests/cases/generics/record-binding-per-instance-into-generic.vl`**

Repro:

    function g<T>(x: T): T {
      const o = { k: x, n: 1 }
      h(o)
    }
    function h(o) {
      o.k
    }
    print(g("s"))
    // vl check: rc 0.  vl run: emitProgram: monomorphize: unsupported argument type for `o` in a call to `h`

Want:

    s

#### Mechanism

D3032 mints each instance's row of a record literal in the pass after monomorphization, and
monomorphization pins `h` at the argument's row while it instantiates `g`: at that moment the
literal `{ k: x, n: 1 }` has no row of its own, so the pin refuses. Before D3032 a declared
record of the same field names could lend its row, which ran only where the pin shared its
slot (an `i32` or a `boolean`). The close is to mint the instance's literal rows as the
instance is registered, before its body's calls are pinned.

#### Ablation

| ingredient changed | outcome | needed? |
| --- | --- | --- |
| `h` a generic (`h<U>(o: { k: U, n: i32 }): U`) | loud emit reject | no |
| the literal handed straight to `h` (`h({ k: x, n: 1 })`) | prints s | **yes** |
| the call (`const o = …` then `o.k`) | prints s | **yes** |
| an `i32` pin with a declared `{ k: i32, n: i32 }` | prints 1 | **yes** |
