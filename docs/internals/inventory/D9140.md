### D9140 — a list literal of two records whose field holds an un-annotated function leaves the functions un-instanced

**closed · runs, prints `4` `6` · was loud emit reject, `emitProgram: cannot take the generic function inc0 as a value`, `vl check` rc 0 · clause 2 · found closing [D9090](D9090.md) and [D9092](D9092.md) · filed 2026-10-21 against master `e6219eb35` · closed by typing a list literal of record literals from the pins on its element's function field, through the stored-record walk the map path already used (`monoPinListRecords`, `monoPinStoredRecords`, emit_mono.vl) · fixtures `closures/hole-fn-list-written-then-called.vl`, `closures/generic-fn-list-written-then-called.vl` · [D9172](D9172.md) filed for the disagreeing records read through `.map`**

Repro:

    function inc0(a) { return a + 1 }
    function dbl(a) { return a * 2 }
    const rs = [{ f: inc0 }, { f: dbl }]
    for r in rs { print(r.f(3)) }
    // vl check rc 0.  vl run: prints 4, then 6

#### Mechanism

A list of record literals had no pin path: the flow table records the calls through
`rs[].f`, and the map path typed its stored record literals from them
(`monoPinMapSlot`), but a list literal's records were never visited, so their function
fields stayed generic. The record walk is now shared by both containers.

| the second record (`[{ f: inc0 }]`, `rs[0].f(3)`) | runs, `4` | **yes** |
| the un-annotated parameters | runs, `4` `6` | **yes** |
