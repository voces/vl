### D9140 — a list literal of two records whose field holds an un-annotated function leaves the functions un-instanced

**loud emit reject · `vl check` rc 0 · `emitProgram: cannot take the generic function inc0 as a value` · clause 2 · found closing [D9090](D9090.md) and [D9092](D9092.md) · present on master `e6219eb35` · filed 2026-10-21 against master `e6219eb35`**

Repro:

    function inc0(a) { return a + 1 }
    function dbl(a) { return a * 2 }
    const rs = [{ f: inc0 }, { f: dbl }]
    for r in rs { print(r.f(3)) }
    // vl check rc 0.  vl run: emit error: emitProgram: cannot take the generic function `inc0`
    // as a value

#### Mechanism

Not traced. A list literal of un-annotated functions takes its element type from the calls
through it, and a record literal of them runs, but a list of records holding them does not.
With annotated parameters the same program prints `4` and `6`.

#### Ablation

| ingredient removed | outcome | needed? |
| --- | --- | --- |
| the `for` loop (`print(rs[1].f(3))`) | still refuses | no |
| the second record (`[{ f: inc0 }]`, `rs[0].f(3)`) | runs, `4` | **yes** |
| the un-annotated parameters | runs, `4` `6` | **yes** |

#### Grading list

The same records with functions of different results (`{ f: half }` for `{ f: dbl }`) are
refused at check since D9092's close (`cannot store 'half' in 'rs[].f'`) and must stay
refused once this row runs. Re-grade `rs[i].f(3)` at a computed index too.
