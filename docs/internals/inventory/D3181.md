### D3181 — a nested record literal whose data field's type differs from a declared record's traps on its field function through a hole

**closed · a literal whose data field widens into a declared record's but whose function field has another signature keeps its own row (`declRowFieldKindFits` asks `fnFieldTyFits`) · fixture `tests/cases/structs/nested-record-literal-beside-declared-record-with-another-field-function.vl` · was loads then traps · clause 1 · found by the #3285 review (`rv3285-2112/p/v1.vl`) · the same on master `995bbc74e` and `a6cb22568` · filed 2026-09-29 against master `a6cb22568`, closed 2026-09-29 against master `36d233f66`**

Repro:

    type I = { v: f64, f: () => boolean }
    type R = { inner: I }
    function F(z) {
      print(z.inner.f())
    }
    F({ inner: { v: 3, f: () => 2.5 } })
    // vl check: rc 0.  vl run: wasm trap: indirect call type mismatch, on master

Want:

    2.5

#### Mechanism

The row claim, D3180's first mechanism. `structIndexOfObjCtx` built the inner literal as
`I` (its `v: 3` widens to `f64`, which `declRowFieldKindFits` allows) and never compared the
function field, so the outer literal became `R`, the hole instance bound `z` to `R`, and the
call used `I`'s `() => boolean` signature against a closure built at `() => f64`.
`declRowFieldKindFits` now also refuses a function field of another signature, reading the
field value's own type where the literal's recorded type is the hole.

#### Ablation

| ingredient changed | outcome | needed? |
| --- | --- | --- |
| `type R` removed (only `I` declared) | prints `2.5` | **yes** |
| `type I` and `type R` removed | prints `2.5` | **yes** |
| `v: 3.5` (the literal's `v` is `f64`, as `I`'s) | prints `2.5` | **yes** (the differing data field) |
| `I`'s `v: i32` (as the literal's) | prints `2.5` | **yes** |

#### Grading list

The witness, the generic `F<Z>(z: Z)` spelling, and the module-bound argument
(`const r = { inner: … }; F(r)`).
