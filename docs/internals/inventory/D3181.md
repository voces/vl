### D3181 — a nested record literal whose data field's type differs from a declared record's traps on its field function through a hole

**loads then traps · clause 1 · pre-existing, the same on master `995bbc74e` and `a6cb22568` · found by the #3285 review (`rv3285-2112/p/v1.vl`) · filed 2026-09-29 against master `a6cb22568`**

Repro:

    type I = { v: f64, f: () => boolean }
    type R = { inner: I }
    function F(z) {
      print(z.inner.f())
    }
    F({ inner: { v: 3, f: () => 2.5 } })
    // vl check: rc 0.  vl run: wasm trap: indirect call type mismatch

Want:

    2.5

#### Mechanism

Not localised past the ablation. The inner literal `{ v: 3, f: () => 2.5 }` has `v: i32`, and
the declared `I` shares its field names with `v: f64`. Something in the member call's
dispatch resolves the inner record through `I` and calls `f` at `I`'s `() => boolean`
signature, while the closure was built at `() => f64`. #3285's twin rungs admit a declared
record only where it differs from the argument in function fields alone, so a differing data
field leaves this path untouched.

#### Ablation

| ingredient changed | outcome | needed? |
| --- | --- | --- |
| `type R` removed (only `I` declared) | prints `2.5` | **yes** |
| `type I` and `type R` removed | prints `2.5` | **yes** |
| `v: 3.5` (the literal's `v` is `f64`, as `I`'s) | prints `2.5` | **yes** (the differing data field) |
| `I`'s `v: i32` (as the literal's) | prints `2.5` | **yes** |

#### Grading list

The witness, the generic `F<Z>(z: Z)` spelling, and the module-bound argument
(`const r = { inner: … }; F(r)`).
