### D9072 — an `if` expression choosing between two functions as a `.map` callback has no result kind

**closed · runs, prints `4` · was loud emit reject, `emitProgram: unsupported .map/.filter element type` · `vl check` rc 0 · clause 2 · found closing [D9004](D9004.md) · filed 2026-10-21 against master `26a6dc669` · closed by classifying and building an `if` whose arms are plain function values as a closure value of the `if`'s own type (`fnChoiceArmsPlain`, `mfCallbackCloKey`, emit_classify.vl; `emitMfCallbackValue`, wasmEmit.vl) and instancing a generic arm at the receiver's element (`monoCoerceListCbArg`, emit_mono.vl) · fixtures `closures/fn-choice-as-callback.vl`, `closures/fn-choice-unannotated-as-callback.vl`, matrix `fn-choice-as-list-callback-result`**

Repro:

    function inc(a: i32): i32 { return a + 1 }
    function dbl(a: i32): i32 { return a + a }
    const c = [1].length > 0
    print([3].map(if c { inc } else { dbl })[0])
    // vl run: emitProgram: unsupported .map/.filter element type

#### Mechanism

`mfResultKindOf` (emit_classify.vl) read the result kind from the callback's lifted function
(`mfCallbackFe`) or a closure value's signature key (`mfCallbackCloKey`), and
`emitMfCallbackValue` built a callback only from a name, a lambda or a binding; an inline
`if` was none of them, while the same `if` bound to a `const` was a binding and ran. The
classifier now keys an `if` whose arms are each a function name, a lambda, a field of a name
or another such `if` by the `if`'s own type, and the emitter builds it with `emitExpr` as the
binding's initializer is built. For generic arms the monomorphizer's `.map` / `.filter`
coercion now accepts the `if`, instances each arm at the element and records the instanced
type on the `if`.

#### Ablation

| ingredient removed | outcome | needed? |
| --- | --- | --- |

| the inline `if`, for `const f = if c { inc } else { dbl }` handed as `.map(f)` | runs, `4` | **yes** |
| an annotated destination, `const ys: i32[] = ...` | same emit refusal | no |
