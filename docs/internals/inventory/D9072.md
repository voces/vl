### D9072 — an `if` expression choosing between two functions as a `.map` callback has no result kind

**loud emit reject · `vl check` rc 0 · clause 2 · CAPABILITY: each function handed alone runs, and so does the same choice bound first, `const f = if c { inc } else { dbl }`, and handed by name · found closing [D9004](D9004.md) · present on master `26a6dc669` · filed 2026-10-21 against master `26a6dc669`**

Repro:

    function inc(a: i32): i32 { return a + 1 }
    function dbl(a: i32): i32 { return a + a }
    const c = [1].length > 0
    print([3].map(if c { inc } else { dbl })[0])
    // vl run: emitProgram: unsupported .map/.filter element type

#### Mechanism

Not traced. `mfResultKindOf` (emit_classify.vl) reads the result kind from the callback's
lifted function (`mfCallbackFe`) or a closure value's signature key (`mfCallbackCloKey`); an
`if` expression is neither, so no kind is found. The annotated functions show it is not a
generics question; with declared generics (`idg` / `kg`) the same refusal follows, and it is
the `.map` face of [D9005](D9005.md).
