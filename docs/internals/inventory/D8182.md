### D8182 — `v is i32` is true when an un-annotated or generic parameter is bound at `null`

**closed 2026-10-20 by lane L6 · an `is` whose re-readable operand the instance reads at `null` answers whether the tested type admits `null`, ahead of the name cascade; the repro prints `1`, pinned by `tests/cases/unions/is-on-null-bound-param.vl` · was check-clean silently wrong · clause 1 · found closing [D8122](D8122.md) · filed 2026-10-20 against master `da93ef793`**

Repro:

    function t(v) {
      if v is i32 { print(0) } else { print(1) }
    }
    t(null)
    // vl check: rc 0.  vl run: prints 0

Want:

    1

#### Mechanism

`monoStaticIsResult` folds an `is` inside an instance by the operand's argument type name.
`monoArgTyName` names a `null`-bound operand `i32`, the type it shares a pin with, so
`is i32` folded to true and `is null` to false. The instance's own read type,
`instanceReadTyOf`, is `null` there. `nullInstanceIsResult` (wasmEmit.vl) now answers from
it whether the tested type admits `null`, before `emitIsTest` reaches the fold.

A `null` delivered through a binding (`const n = null; t(n)`) or a nested generic call is
still pinned wrong at the call site and builds invalid wasm: [D8280](D8280.md).

#### Ablation

| ingredient changed | outcome | needed? |
| --- | --- | --- |
| `v is f64` or `v is boolean` | prints `1` | **yes**, `i32` |
| `const n: i32 \| null = null; t(n)` | prints `1` | **yes**, bare `null` |
| `function t<T>(v: T)` | prints `0` | no |
| `v: null` annotated | check reject, `is` can never match | **yes**, the instance |
| a second call `t(4)` | prints `0` twice | no |
| `v is 0` | invalid wasm | no, the same fold |

#### Grading list

The generic spelling `function t<T>(v: T)`.
