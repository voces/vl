#### Mechanism

Probed 2026-11-12 at `monoPinMapValues`: `fnMap` has `et` = `nt` = `{[string]: (f64) => f64}`; `m2` has
`et` = `{[string]: (f64) => f64}` (its slot fact, `elabSlotClose` → `elabHeldFnTy`, finds `half`'s one
instance) and `nt` = `{[string]: (i32) => i32}` (`monoStoredSlotFnTy` → `monoUncalledSlotFnTy` →
`elabUncalledSlotTy`, the D9100 default). The original note follows. `half` is in two maps. The annotation pins `fnMap`'s functions at `(f64) => f64`.
`m2`, never read, leaves `half` at its own type, and the slot fact of the two maps' shared value
storage disagrees with the pinned closures. The refusal names the mechanism (`monoPinMapValues`),
not a contract: the program's two maps are legal, and reading `m2` makes it run.
