### D1887 — a two-parameter generic whose BOTH holes bind a map is check-clean invalid wasm; one hole, or a second hole at any other rep, runs

**closed 2026-11-02 · runs, prints `1` · was check-clean invalid wasm, clause 1 · fixture `tests/cases/generics/empty-map-to-bare-type-parameter.vl` · the second hole is not needed: one empty `Map()` handed to a bare parameter is enough · filed 2026-09-07 against master `6f76e471a` by the day-one sampler's new multi-parameter pin**

Repro:

    type Rec = { name: string, n: i32 }

    function mkval(): {[string]: Rec} {
      const m: {[string]: Rec} = Map()
      m["k"] = { name: "ada", n: 3 }
      return m
    }

    function pass2<A, B>(a: A, b: B): A { return a }

    function srcOf(): {[string]: Rec} { return pass2(mkval(), Map()) }

    print(srcOf().length)
    // vl check: `Found 0 errors, 1 warning.` rc 0
    // vl run: the emitted module failed to validate inside `srcOf`:
    //         type mismatch: expected i32, found (ref $type)
    // Should print 1; `pass<T>` with one parameter does, and so does any second argument
    // that is not a map.

#### Mechanism

**The ingredient is the two holes agreeing, not disagreeing** — which is the opposite of what
the axis was built to look for. The sampler's second-hole table draws seven differing reps and
one `same` control; over 519 `generic2` pairs the differing reps produced **0** disagreements
between them and `same` produced **18**, five of them SILENT.

Both holes must be a MAP. A list, a struct and a scalar at both holes all run, so it is not
"one instance, two holes at one rep" in general; and the map's VALUE type is not the ingredient
either — `{[string]: i32}` at both holes is invalid wasm too.

#### Close

Re-ablated 2026-11-02: the ingredient is an empty `Map()` handed to a parameter that nothing else
types. `function one<B>(b: B)` called as `one(Map())` alone was invalid wasm, and `pass2(5, Map())`
was too. The second map at `A` was scenery, and it was the map at `B` that mattered. The
argument's type is `{[_]: _}`, and the pin cascade read that as its `i32` floor, while the call
site built the empty map at the default map. The elaboration now binds the type parameter at
that map, a hole key as `string` and a hole value as `i32` (`elabHoleMapClosed`, applied in
`elabSetArgBind`), so the instance is minted inside `elabRun`; mono's pin reads the same rule
and demands nothing late. An empty `Set()` in the same position is
[D15040](D15040.md).

#### Ablation

| ingredient removed | outcome | needed? |
| --- | --- | --- |
| the SAME rep — a second hole at `1` / `"s"` / `[1]` / `{ q: 1 }` | prints `1` | **yes** |
| the second PARAMETER — `pass<T>(x: T): T` | prints `1` | **yes** |
| the pin entirely | prints `1` | **yes** |
| the MAP — a list, a struct or an i32 at both holes | prints its value | **yes** |
| the map's VALUE type — `{[string]: i32}` at both holes | still invalid wasm | no |
