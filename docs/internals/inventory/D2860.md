### D2860 — a mismatch on a defaulted numeric literal never named the declaration whose annotation fixes it

**loud check reject, by design, and the diagnostic now names the declaration · plumb PL-052 · filed and fixed 2026-09-27 against master `721781075` · typing unchanged: a bare literal still defaults to `f64`/`i32`, and the corpus A/B built every master-building program to byte-identical wasm**

Repro:

    function mul32(a: f32, b: f32): f32 { a * b }
    const TABLE = [1.0, 0.0, 0.0, 1.0]
    function f(): f32 { mul32(TABLE[0], TABLE[1]) }
    print(f())
    // master: argument 1: expected f32, got f64   (at the call; nothing names line 2)
    // now:    argument 1: expected f32, got f64 — `TABLE` on line 2 has no annotation, so its
    //         literal defaulted to `f64[]`; annotate it: `const TABLE: f32[] = …`

#### Mechanism

The literal's type is decided at `TABLE`'s declaration and the refusal is raised at the use,
so the message named only the use. The checker now marks every un-annotated `let`/`const`
whose initializer is a numeric literal, a negated one, or a non-empty list of them
(`markNumLitBinding`, depth-tagged like the D1609 rows so shadowing holds). `tErrPush` asks
whether the refused value reads such a binding directly or through one index and whether the
message names both the literal's default type and a numeric type the literal also fits
(`f32` for a float; `i64`/`f32`/`f64` for an integer; the list spelling for a list read
whole). The note rides the MESSAGE, the channel D1590 and D2390 already use, so the CLI and
the LSP show it alike; a declaration in another module is named `line N of <file>`. It is
appended at the end of the check. It is dropped, for a `let` or a `const`, when the program
can store a non-literal through the binding: a whole-name assignment, an element assignment
(`TABLE[1] = poke()`), a storing method call (`TABLE.push(poke())`), or an un-annotated alias
(`const B = TABLE`) — the suggested annotation would refuse that store. One name walk covers
every queued note and runs only when one is queued, so an error-free program pays one type
compare per declaration. An exported declaration keeps `export` in the suggestion. A scalar
integer passed as `i64` needs no note: `i32` widens to `i64` implicitly and it runs.

#### Ablation

| ingredient removed | outcome | needed? |
| --- | --- | --- |
| the un-annotated declaration (`const TABLE: f64[]`) | the bare mismatch, no note | **yes** |
| the literal initializer (`const V = T[0]`) | the bare mismatch, no note | **yes** |
| a non-literal write to a `let` (`w = src()`) | the bare mismatch, no note | **yes** |
| a non-literal element write or push, `const` or `let` | the bare mismatch, no note | **yes** |
| the index (a scalar `const X = 1.5` passed as `f32`) | note, `const X: f32 = …` | no |
| a type the literal fits (`2.5` passed as `i32`) | the bare mismatch, no note | **yes** |
