### D14140 — a record argument is handed unconverted to a generic parameter whose field is `T | string`, when `T` is inferred from that argument

**check-clean invalid wasm · clause 1 · `vl check` rc 0 · `type mismatch: expected (ref $0), found (ref $3); $0 is {v:i32|string} …; $3 is #anon0, struct {mut i32}` · found grading the residue of [D14081](D14081.md) · present on master `baa5cd694` · filed 2026-10-26 against master `baa5cd694`**

Repro:

    function len<T>(r: {v: T | string}) {
      7
    }
    const r = {v: 5}
    print(len(r))
    // vl check: rc 0.  vl run: invalid module, expected {v:i32|string}, found #anon0 {mut i32}

Want:

    7

#### Mechanism

Not traced. `T` is inferred as `i32` from `r`'s field, so `len`'s instance takes
`{v: i32 | string}`, whose field is a union box, while `r` is the struct `{v: i32}`. The call
passes `r`'s reference with no field-widening copy. The same call with the type argument written,
`len<i32>(r)`, runs, and so does a field of `T | null`, so the copy exists and this delivery does
not reach it. Record adoption is not involved: a binding annotated with a declared record, and a
function result, fail the same way.
