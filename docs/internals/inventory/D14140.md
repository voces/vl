### D14140 — a record argument is handed unconverted to a generic parameter whose field is `T | string`, when `T` is inferred from that argument

**closed 2026-11-02 · runs, prints `7` · was check-clean invalid wasm, clause 1 · a refusal the record-covariance ruling (D2996) owed at the direct spelling and lost at the pin · probes `scripts/capability-probes/matrix/record-scalar-field-into-generic-union-field.matrix.vl` and its direct twin · found grading the residue of [D14081](D14081.md) · filed 2026-10-26 against master `baa5cd694`**


Repro:

    function len<T>(r: {v: T | string}) {
      7
    }
    const r = {v: 5}
    print(len(r))

Want:

    7

#### Mechanism

The record-covariance ruling (DECISIONS.md, D2996) lets a record widen to one that stores a field
differently only when it is fresh: a literal is built at the destination, and a binding holding
only a literal adopts it. Every other record is refused. The record solve queues each delivery
(`recPend`) and judges it once the pass is over, but a generic call's argument was queued at the
parameter's own type, `{v: T | string}`, which names the callee's `T` and is open where the call
is (`recAdOpen`), so it was never judged: `len<i32>(r)` adopted and ran, and `len(r)` built
neither. A generic call now also queues each argument at its parameter with this call's binding
substituted (`recPendBoundArgs`), so `r` adopts `{v: i32 | string}` and runs, and an existing
record (an annotated `R`, a call result) is refused with the direct spelling's message.
