### D2524 — an un-annotated list parameter pinned only by `push(null)` checks against a `(string | null)[]` argument and then has no rep for the `null`

**closed 2026-09-26 — the filed repro RUNS and prints `1` · was a loud emit reject, clause 2 ·
pre-existing on master `ca544493e` · found by [D2506](D2506.md)'s ruling question · fixture
`tests/cases/inference/container-null-hole-filled.vl`**

Repro:

    function use(v) {
      v.push(null)
      print(v.length)
    }
    const xs: (string | null)[] = []
    use(xs)
    // vl check: rc 0.  vl build: emitProgram: bare null needs a struct-typed context

#### Mechanism

The checker was right: the parameter's element is a derived hole, so the pin checks the push at
the argument's `string | null`. The emitter was not. `emitPush` seeds a bare `null` for a
`(string | null)[]` receiver from the receiver node's recorded type, and an instance shares its
body's nodes with the generic, whose receiver records only the hole, so no seed was set and the
`null` refused. `arrElemIsNulStrAt` asks the banked pin and then the instance's own parameter
annotation, the same fallback `arrElemLitUnionTy` takes for a literal-union element. An `i32 |
null` or record `| null` element never hit this, since its push seeds from the ref-list row.

#### Ablation

| ingredient removed | outcome | needed? |
| --- | --- | --- |
| `v` annotated `(string \| null)[]` | prints `1` | **yes** — the inferred parameter |
| the element `string \| null` replaced by `i32 \| null` | prints `1` | **yes** — the string niche |

#### Grading list

* `i32 | null` and a struct `| null` element: both run. `boolean | null` took the same missing
  seed through `nodeArrayElemIsNulBool` and runs by the twin `arrElemIsNulBoolAt`.
* An OPEN list argument (`const c = []`, `use(c)`, then `c.push(4)`): the call leaves `c`'s
  element an open `_ | null`, and the call is refused (`the element type of `c` is still open
  here`, D2506), where master accepted it and refused at emit.
