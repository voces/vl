### D3071 — an un-annotated value-bound lambda testing `is` on a union element called in a `for` walk is invalid wasm

**check-clean invalid wasm · clause 1 · 91 cells of the #3266 review's `g39b` grid (`foreachclo`) · a record union is a loud emit reject instead · the same on master `b09566e16` · filed 2026-09-28 against master `b09566e16`**

Repro:

    const z: (i64 | string)[] = [5, "t"]
    let c = 0
    const f = (w) => w is i64
    for e in z { if f(e) { c = c + 1 } }
    print(c)
    // vl check: rc 0.  vl run: invalid module in the top-level code: type mismatch: expected
    // i32, found (ref $type)

Want:

    1

#### Mechanism

Not investigated past the ablation. `const f = (w) => …` is a value-bound lambda whose parameter
is an inference hole, monomorphised per call shape. Called with a union box from the walk, the
call passes the box where the instance takes an `i32`, so the hole seems to be pinned to a
scalar rather than to the element union. Over `(Sq | Circle)[]` the same program is refused at
emit (``emitProgram: `is` receiver is not a union value``), which points at the same pin: the
instance's `w` is not the union.
