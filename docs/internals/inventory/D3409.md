### D3409 — a parenthesised expression after a statement on the same line parses as a call of that statement's value

**loud check reject · the #3315 review · possibly the intended grammar (a call's `(` may follow its callee on the same line) · filed 2026-09-30 against master `8df60e472`**

Repro:

    function nf() {
      print("nf")
      null
    }
    function t() {
      const w = if 1 > 0 { print("a") (nf() ?? nf()) } else { null }
      print(w == null)
    }
    t()
    // vl check: called value is not a function (void)

#### Mechanism

Not traced. Statements in a block need no separator, and a `(` after an expression on the same
line continues it as a call, so `print("a") (nf() ?? nf())` reads as `print("a")(…)`, a call of
`print`'s `void` result. Written without the parentheses, `print("a") nf() ?? nf()`, the arm
runs and prints `a nf nf true`. Whether a same-line `(` should instead start a new statement is
a grammar ruling, not a defect to fix here: the language's other call-continuation rules decide
it, and the refusal is loud either way.
