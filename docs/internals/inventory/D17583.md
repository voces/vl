### D17583 — a `??` over a read of an un-annotated map of a two-signature bundle is refused at emit: the join finds no map value rep

**loud emit reject · `unsupported map value type (no rep for a union-member struct …)` · clause 2 · open · `vl check` rc 0 · found by COV-CLOS's Q58 sweep of the map-of-bundles rep · filed 2026-11-25 against master `e84016b73`**

Repro:

    function lap(f) {
      const _a = f(2.5)
      const _b = f(3)
      return f
    }
    const m = Map()
    m["a"] = lap((a) => a + 1)
    const d = lap((a) => a)
    const h = m["a"] ?? d
    print(h(1.5))
    // vl check: rc 0.  vl run: emit error, "emitProgram: unsupported map value type (no rep for a
    // union-member struct or a nullable list over an unnamed element ...)"

Want:

    2.5

#### Mechanism

`m`'s value type is the open hole function, while its mv slot stores `lap`'s two-signature bundle record (D17094). Legacy's index read, `get` and `.has` reach the slot and run. This position asks for the map value's rep off the open type and finds none, so it refuses with the generic map-value sentence. The same refusal happens on the IR side, so it is not the IR's. Not ablated into the emitter further.
