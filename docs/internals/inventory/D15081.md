### D15081 — one member set reaches two union rows, an alias row and a structural row, and readers pick different ones

**runs today and must keep running · step 7 row keying · filed 2026-11-03 against master `c327c862`**

Repro:

    type A = { r: i32 }
    type B = { r: f64 }
    function toBinding(a: A | null) {
      const g: A | B = a ?? { r: 1.5 }
      print(g.r)
    }
    toBinding({ r: 7 })
    toBinding(null)
    const p: { r: i32 } | { r: f64 } = { r: 2.5 }
    print(p.r)

Want:

    7
    1.5
    2.5

#### Mechanism

The union registry keys a row per spelling, so `A | B` and `{r: i32} | {r: f64}` are two rows
holding one member set. The `??` node's checked type reaches the structural row through its type
key (`unRowOfRecordTy`), while the variant rung of `coalesceResultUnionName`
(`nodeVariantUnionName`) reaches the alias row. The program runs because both rows carry
matching arms; the step 7 keying item is to make one member set one row, so a reader's answer
does not depend on which rung it asks. Closing it renumbers tags, so it is graded by output and
`@log`, not bytes, and this witness must keep printing as it does.
