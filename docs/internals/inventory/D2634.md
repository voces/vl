### D2634 — a generic body's `T | null` or `T | i32` bound to a vector has no lowering

**loud check reject · clause 2 (capability) · the generic face of D2633 · filed 2026-09-26 against master `50c627ce4`**

Repro:

    function wrapN<T>(x: T): T | null {
      const w: T | null = x
      w
    }
    const a = wrapN(__splat_i32x4__(4))
    print(a == null)
    // vl check: v128 | null boxes `wrapN`'s type parameter bound to a 128-bit vector, which a
    //   generic body has no lowering for yet

#### Mechanism

D2633 lowers `v128 | null` and `v128 | i32` at their direct spelling. A generic body's
`T | null` reaches the emitter as the instance's substituted spelling. Once the checker admits
it, the instance's union cell is typed as an i32 arm and the module fails validation
(`expected i32, found v128`). `validateNestCstrs` therefore still refuses, at the call, any pin
that binds a type parameter to a vector inside a nullable or union (`tyBoxesV128`). The bare
pin, `id<T>(x: T): T` at a vector, now runs: the monomorphizer names the pin `v128`. Before,
it fell to the `i32` default and was check-clean invalid wasm.

#### Ablation

| ingredient removed | outcome | needed? |
| --- | --- | --- |
| the `| null` (a bare `T` binding) | runs | **yes** |
| the type parameter (`x: v128`, `v128 \| null`) | runs | **yes** |

#### Grading list

`const u: T | i32 = x` at `T = F32x4`; `T | null` as a return, a field and a list element in a
generic body.
