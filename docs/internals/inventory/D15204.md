### D15204 — a list of un-annotated functions three list literals deep, read inline or through a binding of one element, builds an invalid module

**closed · runs, prints `4` · was an invalid module after a clean `vl check` (`type mismatch: expected (ref null $type), found (ref $type)`), clause 1 · bound whole, the same literal was half of [D15203](D15203.md)'s emit reject · found re-scoping D15203 · present on master `2cde0cf6` · filed 2026-11-03 against master `2cde0cf6` · fixed by naming a list literal's element at any depth when it is a list of a tagged set's ids: `arrLitNestedElemName` (emit_shape_rows.vl) spells it with `fnTagListRepName` (`i32[]`, `i32[][]`, …) and `arrLitNestedElemKind` answers the i32 list only for a list of the ids themselves, a ref list for a list of such lists. The outer literal had shared its middle list's row. The named set `d15204-tagged-id-list-depth` holds the positions**

Repro:

    function inc0(a) { return a + 1 }
    print([[[inc0]]][0][0][0](3))

Want:

    4

#### Mechanism

A list of a tagged function set's ids is stored as the i32 list, a list of those as a ref list of i32 lists. The literal's element row was special-cased one level deep only, so a list of id-lists got no element name and the i32-list kind, and its row was the middle list's.
