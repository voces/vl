### D16414 — a float constant tree read at `f32` anywhere but an annotated binding folds as a double and rounds again

**check-clean silently wrong · clause 1 · open · a `const` with no annotation, read at `f32`, folds in doubles and rounds again; every other `f32` use folds in `f32` arithmetic since the fold keeps the tree's `f32` value beside its literal (`cexF32LexOf`, check_num_lit_state.vl; `numLitLexAt`, wasmEmit.vl) · fixture `tests/cases/numerics/const-float-fold-f32-use.vl` · found folding Q9 part 1 · filed 2026-11-15 against master `b8bb77669`**

Repro:

    function f(x: f32) { print(x) }
    f((1.5 % 0.1) / (2.5 % 0.1))
    const H = (1.5 % 0.1) / (2.5 % 0.1)
    const h: f32 = H
    print(h)
    // vl check: rc 0.  vl run: prints `1.0000001192092896`, `1`.

Want:

    1.0000001192092896
    1.0000001192092896

#### Mechanism

The fold rewrites a tree into its value's literal the first time the checker reaches the tree's
root, before its destination is known, so it computes in doubles. It now also computes the tree
in `f32` arithmetic and keeps that value beside the literal, and the emitter lowers a literal used
at `f32` from it, so an argument, return, field, element, write, operator peer and `f32 | null`
binding all print the `f32` result; `as f32` converts a tree its operand types at `f64`, as at run
time. A `const` with no annotation is folded at its own declaration, and each read is a fresh
literal of the double value, so a read at `f32` rounds the double again. It has no one use type
when it is read at both widths, which is the open half and needs the owner's reading.

`f32` IEEE result; a shared `const` read at `f32` and `f64` needs the owner's reading.
