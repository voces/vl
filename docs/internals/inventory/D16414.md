### D16414 — a float constant tree read at `f32` anywhere but an annotated binding folds as a double and rounds again

**check-clean silently wrong · clause 1 · open · E9.1's IEEE-at-the-use-type fold reaches `f32` only at a binding annotated `f32`; every other `f32` use rounds the double result once more · found folding Q9 part 1 · filed 2026-11-15 against master `b8bb77669`**

Repro:

    function f(x: f32) { print(x) }
    f((1.5 % 0.1) / (2.5 % 0.1))
    const H = (1.5 % 0.1) / (2.5 % 0.1)
    const h: f32 = H
    print(h)
    // vl check: rc 0.  vl run: prints `1`, `1`.

Want:

    1.0000001192092896
    1.0000001192092896

#### Mechanism

The fold rewrites a tree into its value's literal the first time the checker reaches the tree's
root, before its destination is known, so it computes in doubles; the literal then rounds to
`f32` at the use. Only a binding annotated `f32` folds its initializer root in `f32` first
(`cexTryFoldF32`). A shared `const` read at both widths has no one use type, which is the
open half. From the ablation.

#### Grading list

The tree at an `f32` argument, return, field, list element and `f32` peer must print the
`f32` IEEE result; a shared `const` read at `f32` and `f64` needs the owner's reading.
