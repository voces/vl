#### Mechanism

Two write-side channels feed a narrowing and only one of them has a path arm. The one
[D1847](D1847.md) built runs inside `retireNarrowingsForWrite` and fires when the write
FALSIFIES a live narrowing — it retires the old fact and installs the written member. The one
this row names is the assignment narrowing, `checkNodeReal`'s `=` arm: a straight-line
`x = <non-null>` over a null-bearing binding banks the declaration under `NAR_KIND_ASG` and
`declare(nonNullTy(asgCur))`s the name for the rest of the block, with the emitter's complement
push (`pushNarrowComplement(name, set, "null")`) as its twin. Both of those are keyed on a bare
NAME: `asgTgt is Ident` gates the checker's, and `tgt is Ident` the emitter's.

A path reaches neither, so nothing happens at all — which is why the guard makes no difference:
`if o.v == null`, `if o.v is null` and no guard whatsoever all refuse the same way, and the
whole family is the missing arm rather than a narrowing that fails to survive.

**The refusal is CONSISTENT and that is exactly what makes it a ruling.** The bare-name spelling
of the same shape already refuses on master —
`let x: i32 | null = null; x = 5; const y = x; if y != null` is
`cannot compare i32 with null` — because `isAsgNarrowedName` exempts only the narrowed NAME
itself, not a binding read out of it. Closing this row makes the path meet that rule and turns
three working programs into refusals. Extending the exemption to the path's own `== null` is
part of the build (an `npFromAsg` column, so a GUARD-narrowed path keeps master's refusal); it
does not reach a binding one hop away, and neither does master's for a name.
