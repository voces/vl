### D3280 — a join of several type parameters holding a literal union, a string and a null has no box at the instance

**closed 2026-09-30 · was a loud emit reject (the #3297 park, clause 2) on master `b6378e95b`, and check-clean invalid wasm (`unknown local`) or a wrong value for its `null`-arm and no-arm slices and its direct non-generic spelling · found by the #3297 round-2 review (`gA3` grid, 38 cells; `m1.vl`, `q1.vl`) · fixture `tests/cases/generics/join-type-params-literal-union-string-null.vl`**

Repro:

    type K = "a" | "b"
    function g<T, U>(a: T, b: U, k: i32) {
      const r = if k == 0 { a } else if k == 1 { b } else { "s" }
      return r
    }
    const x: i32 | null = null
    const y: K = "a"
    print(g(x, y, 0))
    print(g(x, y, 1))
    print(g(x, y, 2))

Want:

    null
    a
    s

#### Mechanism

The literal union's arm widens to its member string through the string-op scratch frame, and
the scan that reserves that frame (`exprHasStrOp`'s value-`if` arm) asked only for a join typed
`string` or a registered box: a join typed `string | null` reserved nothing, and the widening
read a local no function declared, in the direct spelling as in an instance. The scan now asks
`nodeTyIsNulString` as well. In the generic spelling the pin's left-fold re-join also kept the
literal members beside `string` (`rejoinDropSubsumed` drops them) and the nullable union had no
registered box (D3267, D3284), so the park `monoMultiParamLitNullJoin` is deleted.
