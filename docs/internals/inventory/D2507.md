### D2507 — a value whose type is a recursive-alias map, passed to a generic parameter, is check-clean invalid wasm at the call site

**closed 2026-09-26 by the NR lane with [D2698](D2698.md) — the filed repro RUNS and prints `1` · was check-clean invalid wasm · 8 cells of `recursive-alias-map-into-union.matrix.vl` (every un-annotated face that reaches a hole) · filed 2026-09-25 against master `d29a9d220`**

Repro:

    type V = f64 | string | { [string]: V }
    type VMap = { [string]: V }
    function t<T>(a: T) { print(1) }
    const m: VMap = Map()
    t(m)
    // vl check: rc 0.  vl run: invalid module, type mismatch: expected (ref $type), found (ref $type)

#### Mechanism

`V` is a union, so a `{ [string]: V }` value is the shared union box and the map is a kind-2
(union-valued) map. The instance pinned for `T = VMap` and the caller's value interned two
kind-2 value slots whose canonical value ids differed, so two map structs; D2698 makes every
pair of union-valued slots of one key rep one struct, which closed this with no change of its
own. The body of the generic is scenery (it need not read `a` at all), so the
defect is at the call's argument delivery: the instance pinned for `T = VMap` and the value
the caller holds disagree about which struct the map is. D1865 closed the same alias spelling
delivered into the union `V`; the generic pin is a second delivery that was not graded then.
