#### Mechanism

The record-row class is `repKeyOf(ty, "row")`, the key behind `repRowId`, which `buildStructTwins`
keys heap twins on through `slotCanonId`. It first keyed 31 pairs apart that share a row. The row
mode now spells a record's fields in layout order (`fieldNameOrder`), a nullable record field as
its record (both store a `ref null` to one row), and a union's members in one order, which closes
26 of them at no byte cost (0 movers over `tests/**` and the distilled corpus).

The class also folds in the union literal re-lay (D1050, D14752): where an arm of a union meets a
sibling of the same field names whose field is another literal set, both store the atom, and where
either is the plain `string`, both store the string. Over declared unions that closed the one re-lay
pair (`one-literal-field-through-generic.vl`).

The 4 that remained were the same re-lay over an INLINE union. `A = {kind: K, r}` and
`B = {kind: string, r}` meet only in a function's `A | B`, and the re-lay stores the field at the
string for the whole layout family, a standalone `A` included. The class now takes the re-lay's
memberships from every union with two or more record members in the checked arena, collected once
per compile on first use, so an inline union counts as a declared one does. Deduping literal
members in the key is not the fix: the key spells every string literal `string`, so `"a" | "b"`
and `"z"` differ only by member count, and deduping merged 15 pairs that build at two rows, which
was measured and reverted.
