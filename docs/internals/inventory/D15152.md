### D15152 — the record-row class keys three record pairs apart that build at one heap row

**runs today and must keep running · structural: `recordRowClassOf` (the emitter's `repRowKey`) is finer than the heap partition in three named cases, so a reader that KEYS on the class mints a separate entry where one row serves both · measured 2026-11-03 over 5,332 compiling `tests/cases` files, 7,575 pairs of declared records with a heap: 0 pairs of equal class on two heaps, 31 pairs of one heap at two classes · filed against master `e2207958d` by lane column-G1**

    type PA = { a: i32, b: string }
    type PB = { b: string, a: i32 }
    const pa: PA = { a: 1, b: "x" }
    const pb: PB = { b: "y", a: 2 }

#### Mechanism

The record-row class is `repKeyOf(ty, "row")`, the key behind `repRowId`, which `buildStructTwins`
keys heap twins on through `slotCanonId`. Two rows also share a heap when one record type resolves
to another's row, which the key does not see. The three cases, by count of the 31 pairs:

| case | example | why one row |
| --- | --- | --- |
| field order | `{a: i32, b: string}` vs `{b: string, a: i32}` | layout is in `fieldNameOrder`, the key in declaration order |
| a nullable record field vs a non-null one | `{f: {v: i32}?}` vs `{f: {v: i32}}` | both store `ref null` to one row |
| a repeated literal member | `{kind: "a"}` spelled `(string)` vs `(string\|string)` | the member set is not deduped in the key |

A merge is never wrong: equal keys never name two heaps. A split is a cost only to a reader that
keys instances on the class, which the per-frame elaboration key will (D15107's A2b).

**And the key's SIZE grows with record sharing.** `repKeyOf` spells a referenced record inline at
each place it is reached, so a diamond of records (`D_n` holding `D_{n-1}` twice) has a key that
doubles per level, capped at 262,144 characters. Warming every declared record's class before the
elaboration failed `tests/vl_scaling_shape_test.ts` on all five diamond-depth axes (fuel ratio 4.4 to
7.1 against bars of 2.5 to 4.45), so the class is computed only when a reader asks. A reader that
asks per record on a hot path needs a fixed-size identity first: `repRowId`'s hash-consed id within
one compile, or a memoised structural hash.

#### Grading list

`tests/vl_row_classes_test.ts` pins the field-order pair as keying apart today, so normalising the
key (sorting fields, folding the nullable field, deduping literal members inside the row mode) must
update that case on purpose; that change is priced by its own byte diff before A2b reads the class.
