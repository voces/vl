### D15212 — a bundle record handed as an argument has no member fact at the call

**closed 2026-11-04 by #6156 (lane bundle-value) — the repro now RUNS and prints the Want below: the argument takes the member the parameter's annotation names (`elabArgParamMember`). Was: loud emit reject · clause 2 · `emitProgram: a function returning a parameter called at two signatures is called where its result is not used at one of them` · found planning [D15146](D15146.md) (lane destringify) · filed 2026-11-03 against master `f49fe0052`**

Repro:

    function lap(f) {
      f(2.5)
      f(3)
      return f
    }
    function use(g: (x: f64) => f64) { g(4) }
    print(use(lap((a) => a + 1)))

Want:

    5

#### Mechanism

`lap(...)`'s value is `lap`'s parameter's record ([D15144](D15144.md)). Handed to `use`'s parameter,
it is neither a call through the value nor a holder, so `emitBundleResultPick` (wasmEmit.vl)
has no member fact for it and refuses. The parameter is called at one signature, so the member
that position takes is decided by its type.

#### Ablation

| ingredient removed | outcome | needed? |
| --- | --- | --- |
| the second call of `f` in `lap` | runs, prints `5` | **yes** |
| `use`'s parameter annotation (`function use(g)`) | still refuses | no |
| `lap(...)` held first (`const v = lap(...)`, `use(v)`) | still refuses | no |
| `lap(...)` returned through `mk(k: i32)`, `use(mk(1))` | still refuses | no |
