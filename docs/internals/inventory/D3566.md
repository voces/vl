### D3566 — a record binding built for a union-typed field, with a field the arm drops, returns into the declared record as invalid wasm

**loud check reject · clause 2 · open · was check-clean invalid wasm (clause 1) until 2026-11-01, when the record solve's build of `sv` at `Box` began refusing the nested literal with the capability refusal its one-level neighbour already gave ("drops the field `purr` … not yet supported by codegen") · the close is the arm copy, collector work: build a record literal at the one union arm it fits, dropping a field as D1696 does for a plain record · probe `scripts/capability-probes/union-arm-from-wider-record.vl` · pre-existing, the same on master `f6e17953b` · found in the #3348 review · filed 2026-10-03 against master `fae55dec2`**

Repro:

    type A = { k: i32, legs: i64 }
    type B = { s: string }

    type Box = { pet: Pet }

    //   type-valid (structural width subtyping) but not yet supported by codegen

#### Mechanism

The un-annotated binding `sv` is built at a shape whose `pet` is the union `Pet`, so its inner
literal takes arm `A`'s layout, which has no `purr` (the D1696 floor: the extra field is
dropped and its initialiser runs for its effect). Delivered into `Box` on return, the value's
`pet` is not the reference the declared field holds. The defect needs the dropped field and the
union together: without either, the program runs. The capture-depth sibling with a plain record
(`type Shallow = { pet: Plain }`) runs and prints `1` (fixture
`tests/cases/eval-order/struct-literal-dropped-field-return.vl`).

Traced 2026-11-01. The literal is built at `Box` by two routes, and neither built the nested
literal at an arm. The pinned re-check exempted a pinned binding's dropped field for a union
arm as it does for a record (D3339), so it accepted. Without that exemption its refusal undoes
the adoption, and the next check builds `sv` at `Box` unadopted (`recBuildPush`), where
`recordRepTyAdopt` finds no arm whose field names correspond and leaves the literal raw. The
emitter then boxes the raw 3-field struct into the union slot. Both routes now refuse, the
second loudly (`recBuildArmDropRefuse`). Making the stamp choose the one arm the literal fits
instead mints a 3-field row typed `A` that `variantRowOrMint` refuses ("a union arm's row is
not on the arm's heap"), which is why the close is collector work.

#### Ablation

| ingredient changed | outcome | needed? |
| --- | --- | --- |
| no `purr: f()` field | runs, prints `0` | **yes** |
| `type Pet = A` (no union) | runs, prints `1` | **yes** |
| `return { pet: { k: 1, legs: 4 } }` directly | runs, prints `0` | **yes** (the binding) |
| `legs: i32` instead of `i64` | the same (invalid wasm before 2026-11-01, loud check reject now) | no |
| `const sv: Box = { pet: { k: 1, legs: 4 } }` | runs, prints `0` | the annotation removes it |
| `function mk(): Pet { const sv = { k: 1, legs: 4, purr: f() }; return sv }` | loud check reject, the same capability message | the neighbour this row now matches |
| `return { pet: { … purr: f() } }` directly, or `const sv: Box = …` | loud check reject, "this object literal sets `purr`, which A does not declare" | a fresh literal at its destination (design) |
