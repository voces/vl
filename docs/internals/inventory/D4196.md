### D4196 — a method call never reaches a `self`-function declared inside a function body

**closed 2026-10-27 · runs, prints `5` · ruling (a) for Q1: the binder records the decl a method call's spelling names by lexical scope, so a body-local `self`-function is a candidate from its declaration onward · pin: `tests/cases/ufcs-decl/d4196-body-local-self-fn.vl` · was loud check reject, clause 2 · filed 2026-10-12 against master `ba694ca47`, found reviewing #3575 (D4066)**

Repro:

    type Foo = { v: i32 }
    function main(): i32 {
      function bump(self: Foo): i32 { self.v + 1 }
      const f: Foo = { v: 4 }
      f.bump()
    }
    print(main())
    // vl check: `no field 'bump' on Foo`

Want:

    5

#### Mechanism

expressions.md §E11.4 resolves `x.f(a)` against "the names in scope in the calling module",
and statements.md §S9.1 puts a block-local `function` in scope from its declaration to the
end of the block. The method-call resolution finds only top-level and imported `self`
functions, so a block-local one is never a candidate and the call falls through to the
field lookup's "no field" refusal. The plain call `bump(f)` in the same position runs and
prints `5`, so the function is declared and typed. Only the method spelling cannot reach it.

#### Ablation

| change to the repro | outcome | needed? |
| --- | --- | --- |
| `bump` moved to the top level | runs, `5` | **yes** |
| `f.bump()` written as `bump(f)` | runs, `5` | **yes** |
| receiver `i32` instead of a record (`n.twice()`) | refuses, `member access '.twice' on non-object i32` | no |
| `bump` declared inside a nested `if` block | refuses, same sentence | no |
| `bump` a block-local `const` lambda | refuses, same sentence | no |

#### Grading list

- The `i32` receiver: `function twice(self: i32): i32 { self * 2 }` declared in a body, then
  `n.twice()`. It refuses with a different sentence.
- Visible from the declaration on (S9.1): a `f.bump()` written ABOVE the local declaration must
  stay refused, or reach a top-level `bump` of the same name if one exists.
- Receiver overloading (O1): a local `bump(self: Foo)` beside an imported `bump(self: string)`.
  `x.bump()` picks by receiver, and the local one has to be among the candidates.
- A `const bump = (self: Foo): i32 => …` refuses at the top level too. Whether E11.4's "a
  function" covers a lambda-valued `const` is a separate question, and this row does not
  decide it.
