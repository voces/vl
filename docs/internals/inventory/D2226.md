### D2226 — an un-annotated empty-`[]`-or-`null` join passed straight into a call refuses with a message that names a scope it doesn't have

**loud emit reject 2026-09-23 — `emitProgram: bare null needs a struct-typed context` at the call argument · clause 2 · found during PR #3069's review, predicted in [D2209](D2209.md)'s grading list ("a ref-element `[]` beside `null`, un-annotated, which moved from silent to `bare null needs a struct-typed context`") · filed against master `07d5e3b66`**

Repro:

    type P = { x: i32 }
    function take(a) {
      if a != null { print(a.length) } else { print(0) }
    }
    take(if 1 == 1 { [] } else { null })

#### Mechanism

The `if`/`null` join is delivered as a call argument with no annotation anywhere to pin
its element, so the checker never resolves the bare `null` arm to a box context and the
emitter's `bare null needs a struct-typed context` fallback fires
(`wasmEmit.vl:22451`). The message overclaims its scope: `type P` above is declared but
never referenced by the witness, and removing it changes nothing; the identical message
and site fire for a `string[] | null` value delivered the same way (this is the
`empty-list-join-null-sibling` matrix's `argument`, `array_element`,
`array_element_place` and `early_return_guard` cells, un-annotated, all four alike, none
of them struct-typed). Per CLAUDE.md's "a message is not a scope" — run before trusting
the wording — this row files the refusal as a capability gap independent of element type,
not as a struct-specific one.
