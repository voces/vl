### D17823 — a `const` holding a hole function a generic identity hands back, called directly and also delivered to a closed function type, is refused as a value

**open · loud emit reject · clause 2 · `emitProgram: cannot take the generic function inc as a value` · found closing D17815 · filed 2026-11-28 against master `ccc3531ee` by CENSUS**

Repro:

    function inc(a) { return a + 1 }
    function id<T>(t: T): T { return t }
    const g = id(inc)
    print(g(4))
    const k: (a: i32) => i32 = g
    print(k(4))
    // vl run: emitProgram: cannot take the generic function `inc` as a value

Want:

    5
    5

#### Mechanism

Not traced. Delivered alone, or called alone (once or twice), `g` runs. With both, the value
`id(inc)` hands back has a call through it (`g(4)`) and a closed delivery, and emit refuses
`inc` as a value. No widening is involved: the destination's type is `inc`'s own.

#### Ablation

| ingredient removed | outcome | needed? |
| --- | --- | --- |
| `id` (`const g = inc`) | runs | **yes** |
| the direct call `g(4)` | runs | **yes** |
| the annotation on `k` (`const k = g`) | runs | **yes** |
| `inc`'s hole (`inc(a: i32)`) | runs | **yes** |
| the let destination (a parameter `k: (a: i32) => i32` of a called function) | still refuses | no |
