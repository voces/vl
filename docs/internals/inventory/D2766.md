### D2766 — a generic function whose returns join two list types at a pin is typed as one list at the call

**now a loud emit reject — was check-clean invalid wasm on master `876559d2f` · the #3207 review · filed 2026-09-26 against master `876559d2f`**

Repro:

    function h<T>(c: boolean, t: T) {
      if c { return [t] }
      [1]
    }
    const q = h(true, "s")
    print(q.length)

#### Mechanism

The checker types `h`'s result as `T[]` and the call as `string[]`, but at the pin `T := string`
the returns join to `string[] | i32[]`. The same function with `t: string` spelled out is typed
`string[] | i32[]`, and the checker refuses `q.length` there (`field 'length' is not on every
member`). The pin built the instance's return as a union box while the call site read it as a
string list. It is refused at the pin now (D2745): `h` returns `string[] | i32[]` at this call,
two list types, not one list. The design question stays open: the checker, not the pin, owes
this refusal, and it owes it only at a use that needs one list. `if q is string[] { … }`
runs on master and is refused too now.

#### Ablation

| ingredient removed | outcome | needed? |
| --- | --- | --- |
| the type parameter (`t: string`) | loud check reject at `q.length` | **yes** |
| the disagreeing return (`[t]` both ways) | runs | **yes** |
| `q.length` replaced by `if q is string[] { print(q[0]) }` | runs on master; now the same loud reject | no |
| `T := boolean` (one list rep for both members) | runs on master, and reads `[1]` as `true` | no |
