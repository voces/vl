### D2766 — a generic function whose returns join two list types at a pin is typed as one list at the call

**now a loud emit reject — was check-clean invalid wasm on master `876559d2f` · the #3207 review · filed 2026-09-26 against master `876559d2f`**

Repro:

    function h<T>(c: boolean, t: T) {
      if c { return [t] }
      [1]
    }
    const q = h(true, "s")
    print(q.length)

#### Mechanism

The checker types `h`'s result as `T[]` and the call as `string[]`, but at the pin `T := string`
the returns join to `string[] | i32[]`, which is how the same function with `t: string` spelled
out is typed. #3207 builds the instance's result as that union and refuses, at the USE, exactly
what the checker refuses of the non-generic spelling: `.length` and an index on the call or on
an un-annotated binding of it (`field 'length' is not on every member of …`), and passing it to
a generic `T[]` parameter ([D2772](D2772.md)). A discard, an `is` test, a union annotation and a
union parameter build and give the right values. Two list types stored alike (`T := boolean`
beside `i32[]`) are built as the one list the checker types the call as, where `is` cannot
tell them apart ([D2769](D2769.md)). The design question stays open: the checker, which types
the call as `string[]`, owes this refusal, not the emitter.
