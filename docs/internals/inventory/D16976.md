#### Mechanism

The checker can give each call of a hole function a fresh copy of a container its body allocates
(D16603 does, for an empty list handed straight to the template's own parameter). The emitter's
elaboration does not follow: it types the allocation from the template node, so the instance built
for the second call allocates the first instance's rep. Measured with the checker freshening every
template allocation:
- a `Map()` fails emit with `no $fnsig for its table thunk`, or builds an invalid module inside
  `mk$1`;
- a list nested in a record literal gives 30 invalid modules and 2 emit errors over the
  235-cell grid;
- a list relayed to a second hole, `pass(h, a)`, gives 1 invalid module.

D16603's scope predicate (`instAllocsOf`, `check_assignable.vl`) excludes exactly these. A close
makes the elaboration build each instance's allocation at that instance's type, and is graded on
deleting those exclusions.
