### D3913 — a generic function passed to a generic callback parameter bound to the enclosing generic's T is refused at emit

**closed 2026-10-09 by lane SC · runs · was loud emit reject · found by D3909's position matrix (`arg__*`, `list_arg__*`) · filed 2026-10-09 against master `097937914` · pins: `tests/cases/generics/generic-function-to-generic-callback-parameter.vl`**

Repro:

    function run<V>(g: (v: V) => void, v: V) { g(v) }
    function b<U>(y: U) { print(y) }
    function a<T>(x: T) {
      run(b, x)
    }
    a("s")
    // vl check: rc 0.  vl build: monomorphize: unsupported argument type for `g` in a call to `run`

Want:

    s

#### Mechanism

The callee's arrow parameter (`g: (v: V) => void`) bound `V` from the argument's own function
type, and a generic function has none to give. The value arguments had already pre-bound `V`
(D58's pre-binding, `monoCallGenFnToTyParamArrow`). Closed: a generic function value takes the
parameter's annotation substituted at those bindings. A list of functions riding the type
parameters (`gs: ((v: V) => void)[]`) handed a literal of generics now triggers the pre-binding
too, and the literal is coerced element-wise at the substituted list type.
