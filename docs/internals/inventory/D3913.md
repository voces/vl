### D3913 — a generic function passed to a generic callback parameter bound to the enclosing generic's T is refused at emit

**loud emit reject · found by D3909's position matrix (`arg__*`, `list_arg__*`) · filed 2026-10-09 against master `097937914`**

Repro:

    function run<V>(g: (v: V) => void, v: V) { g(v) }
    function b<U>(y: U) { print(y) }
    function a<T>(x: T) {
      run(b, x)
    }
    a("s")
    // vl check: rc 0.  vl build: monomorphize: unsupported argument type for `g` in a call to `run`

Want:

    s

#### Mechanism

Not located. The callee's parameter `(v: V) => void` binds `V` to the caller's `T`, and the
argument is a generic function value. With a concrete caller or a concrete parameter it runs.
A list of them (`runAll<V>(gs: ((v: V) => void)[], v: V)`, `runAll([b, c], x)`) is refused the
same way for `gs`.

#### Ablation

| ingredient removed | outcome | needed? |
| --- | --- | --- |
| the generic caller (`a(x: string)`) | runs | **yes** |
| the generic parameter (`run(g: (v: string) => void, …)`) | runs | **yes** |
