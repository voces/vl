### D2175 — a captured `K | null` literal-union `let` that a closure writes has no cell to store into

**loud emit reject · clause 2 · filed 2026-09-23 against master `fa5db1bac`, found reviewing the [D2168](D2168.md) close (#3058); the same on master and on the close**

Repro:

    type K = "zz" | "ww"
    function show(k: K | null) {
      if k != null { print(k) } else { print("none") }
    }
    function main() {
      let k: K | null = "zz"
      const set = () => {
        k = "ww"
      }
      const clr = () => {
        k = null
      }
      set()
      show(k)
      clr()
      show(k)
    }
    main()
    // vl check: rc 0.  vl run: emitProgram: indexed assignment but list type not collected

#### Mechanism

Not ablated. The `let` is boxed, since its initializer is a string literal, into a
one-element list whose element is the nullable atom niche `K | null`. No list type is collected
for that element, so the store through `k[0]` refuses. D2168's close gives the cell its
declared list type but only the non-null atom list has a rep; [D2172](D2172.md) is the
neighbour where a `null` initializer leaves the binding unboxed.

#### Grading list

The same with `let k: K | null = null` (D2172's spelling); a read-only capture of the nullable cell.
