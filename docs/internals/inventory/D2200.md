### D2200 — a closure whose block ends in an element write with a computed index, returned from an un-annotated function, is called through an `i32`-result signature it was not emitted with

**loads then traps · `vl check` rc 0, then `wasm trap: indirect call type mismatch` at the call · the same on master `66e74235a` and with PL-021's compound forms · found by the #3061 review (`m4.vl`) · filed 2026-09-23 against master `66e74235a`**

Repro:

    const xs = [1, 2, 3]
    const k = 2
    function mkc() {
      return () => { xs[k] = 100 }
    }
    const c = mkc()
    c()
    print(xs[2])
    // vl check: rc 0.  vl run: wasm trap: indirect call type mismatch

#### Mechanism

The disassembly shows two signatures for one closure. The lambda is emitted as
`(func (param structref))`, with no result. The call through `c` is a `call_indirect (type (func
(param structref) (result i32)))`. So the closure's type that the caller reads from `mkc`'s
inferred return treats the tail write's value (an assignment yields its right-hand side) as the
lambda's result, while the lambda body is lowered as a statement. Which of the two is wrong, and
whether D2170's value-position tail spill is the producer of the `i32`, is a prediction to grade,
not a finding.

#### Ablation

| ingredient removed | outcome | needed? |
| --- | --- | --- |
| a literal index, `xs[2] = 100` | runs, prints `100` | **yes** |
| a statement after the write, so it is not the tail | runs | **yes** |
| an annotated return, `function mkc(): () => void` | runs | **yes** |
| the return, the closure bound to a `const` first and that returned | still traps | no |
| a field write, `b.v = 100`, in place of the element | runs | **yes** |
| a compound write `xs[at(2)] += 100`, or a call index | still traps | no |
| the closure defined and called at top level, not returned | runs | **yes** |

#### Grading list

The #3061 review's `m4.vl` (both a returned block closure and a top-level expression closure over
`xs[at(0)] += 1`), the `+=` and `^=` spellings, and the annotated `(): () => void` control, which
must keep running.
