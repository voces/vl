#### Mechanism

The emitter instances a generic or hole function value that reaches a call through a slot, a
written `let` or a parameter, and writes the instance's parameter types onto the copy as a
synthesized annotation. Where no checker instance covers that copy, `nodeTyAt(param, fnIx)`
answers the template's open type (`V`, `_`, `(T) => T`), while the annotation names the closed
type the copy was built at (`i32`, `string`). Every parameter-type read goes through
`paramTyAt`, which returned the instance answer when it was closed and otherwise the minted
annotation. That fallback arm was deleted with no outcome change over tests/cases or the regress
corpus, so every parameter-type read is now `nodeTyAt`, open answer included.

#### Ablation

A probe at `paramValtypeFloor` asked, for every copy parameter whose instance answer is open,
the worklist key of its instance and the elaboration's type for the template parameter there.
Over the 47 open rows of tests/cases, two families separate by where the elaboration stops:

| family | key | elaboration of the template param | minted annotation | rows |
| --- | --- | --- | --- | --- |
| 1, no elaboration row | `-2`, or an instance that never recorded the param | none | closed (`i32`, `string`, `(string, i32) => i32`) or `() => _` | 13 |
| 2, elaboration row left open | an instance | open (`(_) => _`, `(T) => T`, `((_) => _)[]`, `{f: (T) => T, g: i32}`) | same set type, a stub `(() => void)[]`, or closed (`(string) => string`, `(i32) => i32`) | 24 |

Family 1 is this row: the value-pinned instance has no elaboration at all. Family 2 is a
separate family: the instance exists and records the parameter, but leaves an inference hole
open (instanceTyOf closes type parameters, not holes). The `(() => void)[]` pins are family 2,
the stubbed open element signature, and so are the fn-set parameters, whose set type is open in
both. c2's first slice closes family 1; family 2 closes with the per-instance mint (D14430).
