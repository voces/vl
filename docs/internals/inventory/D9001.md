### D9001 — a `let` re-pointed between two functions with open parameters, handed to a generic higher-order parameter, is not instanced at the callee's pin

**loud emit reject · `vl check` rc 0 · clause 2 · CAPABILITY: the same binding annotated `let f: (x: i32) => i32 = idg` runs, and so does the binding never re-pointed ([D4310](D4310.md)) · found closing [D4310](D4310.md) · present on master `da95613f6` · filed 2026-10-21 against master `da95613f6`**

Repro:

    function idg<T>(t: T): T { return t }
    function kg<T>(t: T): T { return t }
    function app<T>(g: (x: T) => T, v: T): T { return g(v) }
    let f = idg
    f = kg
    print(app(f, 3))
    // vl run: emitProgram: monomorphize: unsupported argument type for `g` in a call to `app`

#### Mechanism

Not traced. The monomorphizer binds a generic's arrow parameter from a function value only
when the argument names one declaration: a declared function, or a `const` or once-bound
`let` holding one (`monoOpenFnArgDecl`, `compiler/emit_mono.vl`). A `let` written twice holds
either, so no declaration answers and the parameter type stays open.
