Repro:

    function idg<T>(t: T): T { return t }
    function kg<T>(t: T): T { return t }
    function app<T>(g: (x: T) => T, v: T): T { return g(v) }
    let f = idg
    f = kg
    print(app(f, 3))
    // vl run: emitProgram: monomorphize: unsupported argument type for `g` in a call to `app`

#### Mechanism

The monomorphizer bound a generic's arrow parameter from a function value only when the
argument named one declaration: a declared function, or a `const` or once-bound `let` holding
one (`monoOpenFnArgDecl`, `compiler/emit_mono.vl`). A `let` written twice holds either, so no
declaration answered and the parameter type stayed open. For the un-annotated spelling the
checker had the same gap one step earlier: the argument was not ordered after `x`, so `T`
bound to `_`, and a mistyped destination (`const y: string = ap(f, 5)`) was check-clean.

The close treats the binding as the set of functions written to it (`cwFnValueTargets`). The
checker reads each body at the bound parameters and takes the result only when all agree. The
monomorphizer instances every written generic at the callee's pin, once per binding, and
refuses loudly when the bodies give different results or a second call wants another pin
([D9003](D9003.md), [D9006](D9006.md)).
