### D16531 — `sel(gid)` with no destination, delivered to a hole parameter or an open `Map` value and called wider than `i32`, builds an `i32` closure called at `f64`

**check-clean invalid wasm · clause 1 · open · `vl check` rc 0 · `the emitted module failed to validate inside `__take`: type mismatch` · the silent face of [D16411](D16411.md) (the same program with no delivery is a loud emit reject) · the un-annotated `argument`, `map_set` and `map_value` cells of `generic-fn-at-generic-fn-param-bound-by-destination.matrix.vl` · filed 2026-11-15 against master `ab210efa2`**

Repro:

    function gid<A>(x: A): A { x }
    function sel<A>(f: (x: A) => A): (x: A) => A { f }
    function __take(a) { print(a(1.5)) }
    __take(sel(gid))
    // vl check: rc 0.  vl run: invalid module, type mismatch inside `__take`

Want:

    1.5

#### Mechanism

Nothing at `sel(gid)` binds `A`: the hole parameter and the open `Map` value give no
destination type, so the instance defaults to `i32`. Only the later call `a(1.5)` says `f64`.
Called directly or through a local, the mismatch is caught at emit and refused (D16411). Through a
hole parameter or an open `Map` value it is not caught, and the module does not validate. From
the ablation.
