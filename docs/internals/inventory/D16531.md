### D16531 — `sel(gid)` with no destination, delivered to a hole parameter or an open `Map` value and called wider than `i32`, builds an `i32` closure called at `f64`

**closed 2026-11-15 by lane R1 · now a loud check reject, `argument 1: expected i32, got f64` at `a(1.5)` since [D16562](D16562.md) bound the unbound `A` at the call (the emit fallback refusal stays for a key with no interned type) · was check-clean invalid wasm, clause 1, `type mismatch` inside `__take` · the call's `$fnsig` key (`d>d`) has no interned type, so it took the all-`i32` arity type with its arguments pushed wide; that fallback now refuses a key that coerces any argument wider than `i32` (`emitCallRefAt`, wasmEmit.vl) · the matrix's un-annotated `argument`, `map_value` and `map_set` cells go SILENT → loud, 0 `runs → not-runs` · the running form is D16411's, open · the two cells of the same matrix that trap at run time are [D16562](D16562.md) · filed 2026-11-15 against master `ab210efa2`**

Repro:

    function gid<A>(x: A): A { return x }
    function sel<A>(f: (x: A) => A): (x: A) => A { return f }
    function __take(a) { print(a(1.5)) }
    __take(sel(gid))
    // vl check: loud check reject (D16562); was invalid module

Want:

    1.5

#### Mechanism

Nothing at `sel(gid)` binds `A`: the hole parameter and the open `Map` value give no
destination type, so the instance defaults to `i32`. Only the later call `a(1.5)` says `f64`.
Called directly or through a local, the mismatch is caught at emit and refused (D16411). Through a
hole parameter or an open `Map` value it is not caught, and the module does not validate. From
the ablation.
