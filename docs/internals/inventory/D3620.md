#### Mechanism

`u8` is a storage type, never a value type (DECISIONS.md, "`x as u8` is the i64 → i32
narrowing"), so `std:array.filled<T>(n, v: T)` cannot produce a `u8[]`: binding `T = u8`
would make `v` a `u8` value parameter. The only public spelling left was a `push(0)` loop (user code can name the intrinsic, which is not API), which
grows the list `n` times. The fix is not a generic rule but a std export: `zeroBytes(n)` is
one `__array_new_default__` over a `u8[]` destination, the intrinsic `std:buffer.loadBytes`
already allocates through, so it lowers to a single `array.new_default` of the packed byte
array. A negative `n` traps naming `zeroBytes`, as `filled` does; an `n` the heap cannot
hold traps in the engine's allocation (`GC heap out of memory`). `const bs: u8[] =
filled(4, 0)` still refuses, by the ruling: no generic rule changed.

Measured at `n = 4,000,000` (the count sunpa pushes today), guest fuel by bisection under
`wasmtime -W fuel` and wall as the minimum of five runs, both including a ~6 ms startup:

| spelling | build | fuel | wall |
| --- | --- | --- | --- |
| `zeroBytes(4000000)` | default | 4,000,114 | 10.4 ms |
| `push(0)` loop | default | 140,583,498 | 19.3 ms |
| `zeroBytes(4000000)` | `-O` | 4,000,041 | 9.1 ms |
| `push(0)` loop | `-O` | 124,583,449 | 16.4 ms |

wasmtime charges `array.new_default` one unit per element, so `zeroBytes`' fuel is the
allocation's own zeroing (`zeroBytes(4)` burns 118); the push loop costs 31x to 35x that.
