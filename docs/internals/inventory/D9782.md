### D9782 — a lambda returning `Map()` handed to an un-annotated parameter has no map value type

**loud emit reject · `vl check` rc 0 · clause 2 · CAPABILITY: the lambda with its result annotated runs, and the same lambda at an annotated parameter runs ([D9741](D9741.md)) · found closing [D9741](D9741.md) · present on master `60aaa08c0` and `260b24edd` · filed 2026-10-22 against master `60aaa08c0`**

Repro:

    function take(v) {
      const m = v(1)
      m["a"] = "q"
      print(m["a"] ?? "")
    }
    take((x: i32) => Map())
    // vl run: emitProgram: monomorphize: unsupported argument type for `v` in a call to `take`

Want:

    q

#### Mechanism

Traced, not fixed. The lambda's result is a map with key and value holes, and nothing at the
call supplies them: the parameter has no type, and the only thing that fixes the value type is
the write `m["a"] = "q"` inside the callee, after the call. At the pin the inline argument's
node type and the call's binding for `v` are the same unfilled `(i32) => {[_]: _}`, so every
rung of `monoPinHoleParam` (emit_mono.vl) answers `""`: `monoHoleLamArgPin` wants hole
PARAMETERS, and `monoOpenFnFlowPin` reads only a let-bound or call argument. The spellings that
run — the lambda bound to a `const` first, or a declared `function mk(x: i32) { Map() }` —
run through the function-split plan's re-compile (`fsAsk` on an identifier argument), which a
literal lambda never reaches. A close is the checker filling the pinned function type's result
holes from the callee body's demands, or the split plan covering a literal lambda.

The same refusal, `unsupported map value type`, is reached without an un-annotated parameter:
a lambda returned from a function with no return annotation and bound at an annotated type
(`return_inferred` annotated in the matrices) refuses, while annotating the lambda's result or
the function's return runs:

    function d() {
      return (x: i32) => Map()
    }
    const v: (x: i32) => {[string]: string} = d()
    const m = v(1)
    m["a"] = "q"
    print(m["a"] ?? "none")
    // vl run: emitProgram: unsupported map value type (no rep for a union-member struct, …)

The same lambda returning `[]` at `(x: i32) => i32[]` runs there.

#### Ablation

| ingredient removed | outcome | needed? |
| --- | --- | --- |
| the lambda's un-annotated result (`(x: i32): {[string]: string} => Map()`) | runs, `q` | **yes** |
| the un-annotated parameter (`v: (x: i32) => {[string]: string}`) | runs, `q` | **yes** |

#### Grading list

`argument`, `global_assign` and `two_instances` in the matrix `fn-value-lambda-result-map`;
`argument` and `global_assign` un-annotated and `return_inferred` annotated in
`fn-value-lambda-result-empty-collection` and `fn-value-lambda-result-map-nullable`; an empty
list `[]` result at an un-annotated parameter.
