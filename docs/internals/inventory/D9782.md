### D9782 — a lambda returning `Map()` handed to an un-annotated parameter has no map value type

**loud emit reject · `vl check` rc 0 · clause 2 · CAPABILITY: the lambda with its result annotated runs, and the same lambda at an annotated parameter runs ([D9741](D9741.md)) · found closing [D9741](D9741.md) · present on master `60aaa08c0` and `260b24edd` · filed 2026-10-22 against master `60aaa08c0`**

Repro:

    function take(v) {
      const m = v(1)
      m["a"] = "q"
      print(m["a"] ?? "")
    }
    take((x: i32) => Map())
    // vl run: emitProgram: monomorphize: unsupported argument type for `v` in a call to `take`

Want:

    q

#### Mechanism

Not traced. The lambda's result is a map with key and value holes, and nothing at the call
supplies them: the parameter has no type, and the only thing that fixes the value type is the
write `m["a"] = "q"` inside the callee, after the call. The monomorphizer's argument ladder has
no signature key for a function whose result holds a hole. The matrix
`fn-value-lambda-result-map` reaches the same family at `global_assign` and `two_instances`.

#### Ablation

| ingredient removed | outcome | needed? |
| --- | --- | --- |
| the lambda's un-annotated result (`(x: i32): {[string]: string} => Map()`) | runs, `q` | **yes** |
| the un-annotated parameter (`v: (x: i32) => {[string]: string}`) | runs, `q` | **yes** |

#### Grading list

`argument`, `global_assign` and `two_instances` in the matrix `fn-value-lambda-result-map`;
an empty list `[]` result at an un-annotated parameter.
