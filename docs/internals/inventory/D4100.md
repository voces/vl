### D4100 — `vl build` reads its flags by membership test, so an unknown flag is ignored and the build exits 0

**open · wrong exit code (no outcome word fits: the witness program runs, so it grades as runs today and must keep running) · CLI · found reviewing `docs/spec/diagnostics.md` (lane SPEC) · filed 2026-10-11 against master `98a4ed71b`**

Repro:

    print(1)
    // vl build main.vl --bogus -o out.wasm: rc 0, "wrote out.wasm (145 bytes)".
    // vl check main.vl --bogus and vl run main.vl --bogus: rc 2, "unknown flag `--bogus`".

Want:

    1

#### Mechanism

`vl run` parses its arguments strictly: its loop in `scripts/vl-host/src/main.rs` ends in
`other => arg_error("unknown flag …")`, which replaced an `_ => {}` that discarded
flag-shaped tokens. `vl build` has no such loop. It asks `args.iter().any(|a| a == "--names")`
and the like for each flag it knows, so a token it does not know is never examined. A
misspelt flag (`--name`, `-o3`) is silently dropped and the build succeeds without the
behaviour the user asked for. A command with no input file at all is still refused (rc 2, "missing the
<file.vl> input").

#### Ablation

| variant | rc |
| --- | --- |
| `vl build main.vl --bogus` | 0 |
| `vl build main.vl --name` (misspelt `--names`) | 0 |
| `vl build` with no file | 2 |
| `vl check main.vl --bogus` | 2 |
| `vl run main.vl --bogus` | 2 |

#### Grading list

`vl build` with an unknown flag exits 2 and names the flag, as `vl check` and `vl run` do,
and every documented `vl build` flag (`vl help build`) still builds. `docs/spec/diagnostics.md`
