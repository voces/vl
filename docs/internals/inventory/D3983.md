### D3983 — a function-body `let` and a nested function of the same name raise no "redeclared", and a module const beside a function cascades

**loud check reject · from the review of #3524 · filed 2026-10-11 against master `1df3c8f91`**

Repro:

    function inner(): i32 {
      let k = 1
      function k(): i32 { 2 }
      k
    }
    print(inner())
    // vl check: "expected i32, got () => i32" and nothing names the duplicate binding.

#### Mechanism

#3524 makes a module-scope `let` beside a function of the same name one "redeclared" error.
Inside a function body, the nested function and the `let` are bound by a different path,
which neither reports the clash nor stops the later use resolving to the function. At module
scope a `const` beside a function still gives "redeclared" plus a "shadows the function"
error at every later use (`function f(): i32 { 1 }` then `const f = 2` then `print(f)`
`print(f())`). The duplicate-binding ruling for a parameter and a same-level nested function
says this should be one error.

#### Grading list

The module-scope `const`/`function` spelling in the mechanism must be one error too.
