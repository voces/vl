### D15619 — a hole function called directly and listed to a callee that hands the element to a second callee has no value signature

**loud emit reject · clause 2 · `vl check` rc 0 · found by lane fn-value rows 28 probing D15611 · filed 2026-11-09 against master `5ee48c6d`**

Repro:

    function id(v) { return v }
    function call1(f, x) { print(f(x)) }
    function call0(fs, x) { call1(fs[0], x) }
    print(id(5))
    call0([id], "s")
    // vl check: rc 0.  vl run: emitProgram: cannot take the generic function `id` as a value — a function value carries ONE signature, and parameter `v` is un-annotated

#### Mechanism

`id` is an un-annotated (hole) function, and the program uses it at two types: directly at
`i32`, and as a value at `string` through the list `[id]`. The list reaches `call1` only
through `call0`'s element read `fs[0]`, and the emitter takes `id` as a value at one
signature. With nothing at that position to name the `string` instance, it refuses. The
ablation shows each ingredient alone is fine: called directly at two types, or called
through the element without the second hop, `id` runs.

#### Ablation

| ingredient changed | outcome | needed? |
| --- | --- | --- |
| `print(id(5))` removed (one type only) | runs, prints `s` | **yes** |
| `call0([id], "s")` replaced by `call1(id, "s")` | runs, prints `5` then `s` | **yes** |
| `call0` calls `fs[0](x)` itself instead of handing it to `call1` | runs, prints `5` then `s` | **yes** |
