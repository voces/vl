### D17767 — a generic function's captured hole lambda and a module bundle result in one program refuse `capture binding`

**closed 2026-11-28 by lane COV-START · runs, prints `2` · was a loud emit reject (`capture binding`), each half running alone · "held as the uniform closure" is answered per place (`placeHeldOpen`, `compiler/ir_build.vl`), not by the build-wide `elabMakesHeldClosureRecords` gate, which is deleted · fixture `tests/cases/closures/bundle-beside-unrelated-open-closure.vl` · filed 2026-11-27 against master `fddec816e`**

Repro:

    function nest<T>(x: T) {
      let k = (u) => { print(u + u) }
      const rd = () => { k(x) }
      rd()
    }
    nest(1)
    function lap(f) {
      f(2.5)
      f(3)
      return f
    }
    const c = lap((a) => a + 1)
    // was: emit error at 3:25, the compiler cannot yet lower this statement (capture binding)

Want:

    2

#### Mechanism

`closureHeld` answered "an open function type is held at the uniform closure" with
`c && !elabMakesHeldClosureRecords()`, a build-wide flag that is on once any binding is held
as a record of closures (`lap`'s bundle). With it on, `k`, typed `(_) => void` and no
holder, had no capture rep (`capRepAtTy` -1), so `rd`'s read missed `capture binding`. Not
the lift (coordinator ruling, 2026-11-28: one value, one layout, decided at its place). Now
every held-open answer is asked of its place (`placeHeldOpen`): a place the elaboration
holds as a record (`placeHoldsRecord`: a holder binding, a bundle parameter, a call kept
whole, a function returning a record) holds no closure; any other holds the uniform closure.
