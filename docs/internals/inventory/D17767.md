### D17767 — a generic function's captured hole lambda and a module bundle result in one program refuse `capture binding`

**loud emit reject · each half runs alone · filed 2026-11-27 against master `fddec816e`**

Repro:

    function nest<T>(x: T) {
      let k = (u) => { print(u + u) }
      const rd = () => { k(x) }
      rd()
    }
    nest(1)
    function lap(f) {
      f(2.5)
      f(3)
      return f
    }
    const c = lap((a) => a + 1)
    // vl run: emit error at 3:25, the compiler cannot yet lower this statement (capture binding)

#### Mechanism

`rd`'s read of `k`, a hole lambda captured from a generic instance, misses `capture binding` only
when the program also holds a bundle result: a parameter called at two types and returned
(`lap`). Each half runs alone. That points to the lambda-lift decision table and the capture
reader disagreeing once a bundle is noted. The disagreement is untraced, and it is lifting
PR 2b's to close (coordinator ruling, 2026-11-27).

#### Ablation

| ingredient removed | outcome | needed? |
| --- | --- | --- |

| `k`'s hole (`(u: T)`) | runs | **yes** |
| `rd` (call `k(x)` directly) | runs | **yes** |
| `rd`'s capture of `x` (`k(1)`) | still refuses | no |
| `lap`'s second call (`f(3)`) | runs | **yes** |
| `lap`'s `return f` | runs | **yes** |
| the use of `c` | still refuses | no |
| `lap`, replaced by a module hole lambda called at two types | runs | **yes** |
