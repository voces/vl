### D3851 — a hole lambda stored into a `let` that a nested function writes, with no call through it, is stored at an `i32` cell element

**check-clean invalid wasm · found closing D3850 (24 of the rv3443 generator's last 30 silent of 600) · filed 2026-10-08 against master `e64f78985`**

Repro:

    function mk(x: string) {
      const c = (y) => y + "C"
      let d1 = c
      function w3(): i32 { d1 = c; 0 }
      print(x)
    }
    mk("a")
    // vl check: rc 0.  vl run: invalid module inside `mk`, `expected i32, found (ref $4)`

    a

#### Mechanism

Not yet located. `d1` is written in a nested function, so the rewrite boxes it into a capture
cell `[c]`. Nothing calls through `d1`, so `c` has no call to pin it, and the cell's element
type is the hole's `i32` default while the closure stored there is a reference. Calling
`d1(x)` once, or annotating `c`'s parameter, runs. On master the called spelling is a loud
refusal and now runs.
