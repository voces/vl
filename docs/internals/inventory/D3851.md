### D3851 — a hole lambda stored into a `let` that a nested function writes, with no call through it, is stored at an `i32` cell element

      let d1 = c
      function w3(): i32 { d1 = c; 0 }

    }

#### Mechanism

`d1` is written in a nested function, so the rewrite boxes it into a capture cell `[c]`. The cell
takes `c`'s checked type, whose parameter is a hole. A hole-typed function lowers at the `i32`
default, so the cell's element is `i32` while the value stored there is a closure reference.

Some lambdas ARE instantiated, by a call or by the signature of a lambda written into the same
cell. For those, `monoRetypeLamCells` (`compiler/emit_mono.vl`) now records the instance's
function type on the cell, its element and its reads, and a cell seeded from another cell's read
takes that cell's type. Peer pins also run in rounds, so a chain of peers settles whatever its
slot order. `monoNameUnread` now treats a binding read only along a cycle back to itself
(`d = d`) as unread, and its path no longer keeps a binding reached twice. Those programs run.

In this witness nothing calls `c` and no peer pins it, so there is no signature to give the
cell. It is now refused: `emitProgram: a lambda with an un-annotated parameter is stored in a
list, or in a variable a nested function writes, and no call fixes its parameter types`. That
is clause 2 residue: a cell nothing reads could hold any representation, so it is still owed a
lowering.
