### D9820 — a direct call of a generic passing a function into a nullable function parameter over its type parameter is refused

**loud emit reject · `vl check` rc 0 · `emitProgram: monomorphize: unsupported argument type for `f` in a call to `g`` · clause 2 · found closing [D9772](D9772.md) · present on master `260b24edd` · filed 2026-10-22 against master `260b24edd`**

Repro:

    function g<T>(f: ((x: T) => T) | null, x: T): T {
      if f != null { return f(x) }
      x
    }
    print(g((x: i32) => x + 1, 2))
    // vl check rc 0.  vl run: emit error: emitProgram: monomorphize: unsupported argument type for `f` in a call to `g`

#### Mechanism

Not traced. The refusal is the monomorphizer's argument classifier (emit_mono.vl), which finds
no instance type for a lambda or a named function delivered into `((x: T) => T) | null`. A
binding already typed `((x: i32) => i32) | null` is accepted, so the classifier reads the
argument's declared type and has no arm for a function value meeting the nullable function
parameter.

#### Ablation

| ingredient removed | outcome | needed? |
| --- | --- | --- |
| the function argument, `g(null, 5)` | runs, `5` | **yes** |
| the lambda, for `const h: ((x: i32) => i32) \| null = (x: i32) => x + 1` and `g(h, 2)` | runs, `3` | **yes** |
| the lambda, for a named `function inc(x: i32): i32` and `g(inc, 2)` | same refusal | no |
| the `\| null`, `f: (x: T) => T` | runs, `3` | **yes** |

The lambda and named-function arguments above; the un-annotated face of the

where `const v = g` called as `v(lambda, 2)` refuses with this sentence at 17 and 18 positions.
