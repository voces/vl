### D14433 — a map of a set of un-annotated functions handed to a generic helper refuses its argument

**loud emit reject · `vl check` rc 0 · clause 2 · CAPABILITY: the same read without the helper runs · waits on the per-instance mint ([D14430](D14430.md)): `V` binds to the set, and the helper's instance has no set of its own to mint · found building the container write-join · filed 2026-10-27 against master `efb1a8105` · pinned by `tests/cases/maps/error-fn-set-map-through-generic-helper.vl`**

Repro:

    function inc(x) { return x + 1 }
    function dbl(x) { return x + x }
    function pick<V>(m: {[string]: V}, k: string): V | null { return m.get(k) }
    const m = Map()
    m["a"] = inc
    m["b"] = dbl
    const h = pick(m, "a") ?? dbl
    print(h(2))
    print(h(2.5))
    // vl check rc 0, vl run: emitProgram: monomorphize: unsupported argument type for `m` in a call to `pick`

Want:

    3
    3.5

#### Mechanism

The map's writes join to the set {inc, dbl}, tagged at the top level. The call `pick(m, "a")`
binds `V` to the set, and monomorphization has no instance for a type parameter bound to a
set: the instance would need the set's tag rep, decided inside its own check. The gap is that
instance, not a refusal of the program; the per-instance mint decides the set per instance.
