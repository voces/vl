### D12462 — a record field read at its own type after the record was stored at a wider record two of its members widen into

**closed 2026-11-12 · now a loud check reject by the shared-record contract (owner ruling, DECISIONS "Record covariance", the merged-numbers limit on adoption) · was a loud emit reject, `vl check`-clean, clause 2 · D3011's delivery refusal (`recAdMergeRefuse`) now also fires where two own numbers both widen into one destination class, not only where one widens into a class the other is (`recNumMerges`, check_ty_relate.vl) · pin `tests/cases/objects/error-record-literal-widened-box-ambiguous-read.vl` · site `wasmEmit.vl`, reached from a `vl check`-clean program by lane L3's census (`docs/internals/l3-reachable-refusals-2026-10.md`) · filed 2026-10-24 against master `b861c1d9f`**

Repro:

    type D = { v: f64 | string }
    const x: i32 | f32 | string = 1.5
    const o = { v: x }
    const c: {[string]: D} = Map()
    c["k"] = o
    const t = o.v
    if t is f32 { print(t * 2) }
    // vl check: rc 1 — `o` is built as D where line 5 delivers it, which stores field `v`
    //   (`i32 | f32 | string`) as `f64 | string`, keeping two of its numbers as one, so it cannot
    //   also keep its own type
    // (was: vl check rc 0, vl run emit error — this field is stored at a wider record whose member
    //   two of its own members widen to)

#### Mechanism

`i32` and `f32` are both stored as the wider record's `f64`, so a read of `o.v` at its own type `i32 | f32 | string` cannot tell which one the box held (D3006).

#### Grading list

| delivery of `o` at `D` (map value, list element, annotated binding, argument) | outcome |
| --- | --- |
| read of `o.v` at its own type, bound or direct, or through `const p = o` | refused at the delivery (D3011) |
| `print(o.v)`, or no read: the adoption retypes `o` as `D` | runs |
| `o` handed whole to a parameter of its own type | the adoption's type error, as on master |
| one numeric own member (`i32 \| string`), `const o: D`, or a second literal | runs |
