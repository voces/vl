#### Mechanism

**The filer asked that a fixer who finds two rungs SPLIT the row, and the probe says there is
one.** `captureValKind`'s un-annotated arm, instrumented, over the four reps and both
projections:

    nulscalar   index  function      KIND=i32   arena=TyNullable<TyPrim:i32> letIsUnion=F letIsMap=F slot=-1  ARENAREP=union
    structunion index  function      KIND=i32   arena=TyUnion                letIsUnion=F letIsMap=F slot=-1  ARENAREP=union
    valunion    index  function      KIND=i32   arena=TyUnion                letIsUnion=F letIsMap=F slot=-1  ARENAREP=union

    map         field  module_block  KIND=i32   arena=TyMap                  letIsUnion=F letIsMap=T→F slot=-1 ARENAREP=<uncovered>

The FIELD face in a function body and the same face in a module block are **the same program
shape with the same recorded type**, and `letIsUnion` / `letIsMap` answer `T` in one and `F` in
the other. So the two escape routes are one syntactic ladder's SCOPE REACH, not a second
mechanism: the `letIs*` predicates resolve the projection's owner through the frame's binding
tables, which a module-level block does not offer. The index face has no owner to resolve at
any scope, so it refuses everywhere but plain module. **One rung answers both**, and the
`ARENAREP` column is why: it already equals the kind the running face produces.

The rung is not four hand-written arms. `vtKindOfType`'s FIRST leg is `annRepKindOf`, the rep
descriptor of the annotation node — so asking it of the INITIALIZER node is the same
derivation, and the two faces of one binding cannot answer differently by construction. It is
gated to a projection, since every other initializer shape commits a rep the ladder above
already reads. `TyMap` is the one arm the descriptor leaves uncovered, so the map keeps its own
kind arm and its own companion (`mapFindShapeOfNodeTy`, a find and never a mint).

**A speculative companion was written and reverted.** `letMapShapeOf` gained a projection
fall-back for the map INDEX face; the grid was byte-for-byte the same with and without it, so
the arm fired for no cell and came out. That face's remaining rung was the closure's `$fnsig`
RESULT slot, a different reader from this row's pair — D1750, which #2770 then closed.
