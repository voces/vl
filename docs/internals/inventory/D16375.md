### D16375 — a constant tree under `>>>` whose left side is negative is computed at i32 at run time, so a sub-tree that wraps to zero divides by zero

**loads then traps · `wasm trap: integer divide by zero` · 1 of 2,000 programs of the oracle's arithmetic fuzz · found by the independent oracle (`scripts/oracle/fuzz.sh`) · filed 2026-11-15 against master `6c486842e`**

Repro:

    print((-7 % (65536 * 65536)) >>> 1)
    // vl check: rc 0.  vl run: wasm trap: integer divide by zero

Want:

    2147483644

#### Mechanism

E9.1 makes the whole tree a constant computed exactly: `-7 % 4294967296` is `-7`, and `-7 >>> 1` at
the default i32 is `2147483644`. A non-negative left side folds this way and prints. A negative one
is not folded: the tree is emitted as i32 arithmetic, `65536 * 65536` wraps to `0`, and the `%`
traps. The trap is not a value E9.1 or E2.3 gives this program.

#### Ablation

| ingredient removed | outcome | needed? |
| --- | --- | --- |
| the negative left (`(7 % (65536 * 65536)) >>> 1`) | prints `3` | **yes** |
| `>>>` (`>> 1` instead) | prints `-4` | **yes** |
| the `%` (`(-7 - (65536 * 65536)) >>> 1`) | prints `2147483644`, no trap | **yes** |
| the shift (`(-7) % (65536 * 65536)`) | prints `-7` | **yes** |
| `print` (`const v: i32 = …`) | still traps | no |

#### Grading list

`/` in place of `%`, and a `>>>` tree at an i64 destination.
