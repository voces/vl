Repro:

    type P = { k: "a", n: f64 } | { k: "b", n: i32 }
    function mk(b: boolean): P {
      if b { return { k: "b", n: 9 } }
      { k: "a", n: 1.5 }
    }
    const p = mk(true)
    if p.k == "a" { print(p.n) } else { print(p.n + 1) }

Want:

    10

#### Mechanism

`tySame` (`check_types.vl`) treats a `TyLit` like a `TyVar` or a `TyErr`, as the same only as
its own arena index. A literal type is not nominal, though, and `mkLitTy` does not intern, so
every spelling of `"b"` is a fresh index. `tyEq` compares a literal by kind and text, and
`tyquery.vl` already bridges the gap for one caller with its own `litTySame` (D5289). So a
narrowed `{k: "b", n: i32}` read matches no arm by `tySame`, and the else arm above casts to
the wrong arm and traps. A probe in which `tySameAt` compares `TyLit` by kind and text prints
`10` here and closes both spellings in the grading list.

The relation that should survive is `tyEq`'s for a literal: kind and text. Comparing that way
in `tySameAt`, or interning `mkLitTy` so that index identity is literal identity, makes
`tyquery`'s `litTySame` redundant. Interning touches the interner and needs `rep-fuzz-check.sh`.

`tySame`'s other disagreement with the shape lookup is intended: it keeps a `Set<T>` apart from
the map `{[T]: boolean}`, as `tyEq` does. The gap there is the arm's stored type, which canon's
`builtinCollNorm` spells as the boolean map, and `tySameSpelled`'s Set clause bridges it.

#### Fix

`mkLitTy` interns, so every spelling of `"b"` is one index and `tySame`'s index rung already
answers. Interning alone was unsound: `wideLitTyIxs` flagged the literal a `const` inferred by
its arena index, relying on each being minted fresh, so an interned `const c = "a"` made the
declared member `"a"` of every union widen to `string` (the compiler's own `TokKind` reads
stopped checking). The widening fact is therefore part of the literal's identity: `TyLit`
carries `litWide`, the interner keys on it, and a caller that equates a widening literal with
its declared twin compares `litRegularTy` indices. `const-literal-keeps-declared-member.vl`
pins the three programs the bare intern broke.

Interning exposed a second producer for numeric tags. Canon spells an int-literal field as its
base, so twin arms `{k: 1, n: i32}` and `{k: 2, n: i32}` share the spelling `{k:i32,n:i32}`, and
the emitter typed a declared union's variants and their fields by re-parsing that spelling.
Three sites did: `collectDeclaredUnion` (each variant's `uVarTyIx`), `collectVariantFields`
(the literal field that marks the discriminant), and `recordUnMemTys` (the member type an
`is` complement narrows to). Each now takes the arm's arena type from the union's own row:
`collectDeclaredUnion` reads the row's member columns, `collectVariantFields` receives the
type, and `recordUnMemTys` keeps the arena type for a record member. `emitUnionBox` takes the
row from `objVariantRowCtx` rather than a name lookup, since twin arms share a name.

Re-graded on the fix: the annotated spelling prints `10`, `print(p.n)` prints `9`, and the
numeric-tag spelling prints `10`. The five `numeric-tag-*` and `string-tag-*` fixtures pin
the tag read as `==`, `!=`, `match`, an `if` chain, both `is` branches, a call argument
and the un-narrowed read. The same-width and mixed-width numeric unions are both covered.
On master `4f2f1ff86` the mixed one trapped (cast failure) under `==`, an `if` chain, an early
return and a narrowed call argument, and its `is` then-branch printed `2` for the `k: 2` arm.
