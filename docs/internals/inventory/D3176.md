### D3176 — a hole callee parameter whose argument is a module-scope function value is called at the first instance's `i32` result, so `true` prints as `1`

**closed · by D3167's fix: a function-value pin is keyed by the value's checked type, so each binding's signature gets its own instance · fixture `tests/cases/generics/function-value-pin-checked-type.vl` · was check-clean silently wrong · clause 1 · found by the #3283 review (`rv3283-3186/w/p1.vl`, `p5.vl`) · the same on master `934f169f4` · filed 2026-09-29 against master `934f169f4`, closed 2026-09-29 against master `995bbc74e`**

Repro:

    function F(g) {
      print(g())
    }
    const c0 = () => 7
    F(c0)
    const c1 = () => true
    F(c1)
    // prints 7, then 1

Want:

    7
    true

#### Mechanism

`() => i32` and `() => boolean` share a wasm signature, so both bindings pinned `F` by one
`$fnsig` key and shared one instance, which printed the second call's result at the first's
`i32`. Inline lambda arguments were told apart, bindings were not. D3167's mechanism: the pin's
instance key now carries the value's checked type (`monoSigPinDiscrim`).

#### Ablation

| ingredient changed | outcome | needed? |
| --- | --- | --- |
| `F(() => 7)`, `F(() => true)` inline | prints `7`, `true` | **yes** (the binding argument) |
| `c1` a `(): "a" \| "b" => "a"` | prints `7`, `0` | no (the literal-union face) |
