### D2026 — a function TYPE cannot spell a `never` result, so a never-returning callback cannot be annotated

**loud check reject, clause 2 · residue of D1972 · filed 2026-09-22 against master `af07f4ae0`**

Repro:

    function g(onErr: (string) => never, c: boolean): i32 {
      if c { return 1 }
      onErr("no")
    }
    print(1)
    // vl check: rc 1, `never` has no values, so it is legal only as a function's declared return type

#### Mechanism

D1972 made `never` resolvable only through `resolveRetAnnotAt`, the declared return of a
`function` or lambda. A function type's result goes through the general annotation resolver,
which refuses the name. A lambda declared `(s: string): never => …` already has the type and a
call through its binding already ends a path; what is missing is the spelling, and with it an
indirect `call_ref` to a result-less never closure followed by `unreachable`.

#### Grading list

A callback parameter, a struct field of function type, and an un-annotated binding of a
never lambda called in a guard arm.
