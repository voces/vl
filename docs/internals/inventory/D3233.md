### D3233 — writing a hole field in an `is` test's else arm and then reading the tested member traps in the `<Z>` spelling

**loads then traps · clause 1 · open · pre-existing, the same on master `94670f728` · found by the #3289 round-2 review (`ga` cells `wr_*`) · filed 2026-09-29 against master `94670f728`**

Repro:

    type A = { v: i32 }
    type B = { s: string }
    function F<Z>(z: Z) {
      if z.h is A { print(z.h.v) } else { z.h = { v: 9 }
        print(z.h.s) }
    }
    const x: { h: A | B } = { h: { s: "bee" } }
    F(x)
    // vl run: wasm trap in `F`

#### Mechanism

The annotated spelling refuses `no field 's' on A`: the write re-narrows `z.h` to the written
record. The `<Z>` body keeps the else arm's remainder after the write, so the read is checked
against `B` and emitted as a `B` field read of an `A`. The hole spelling is a loud emit reject
(`unknown variant field in narrowed field access`).

#### Ablation

| ingredient changed | outcome on master | needed? |
| --- | --- | --- |
| `function F(z: { h: A \| B })` | check refuses | **yes** |
| `function F(z)` | emit refuses | **yes** (`<Z>`) |
| the write removed | prints `bee` | **yes** |
