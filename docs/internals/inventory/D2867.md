### D2867 — a function returning a call through a function-typed parameter types its map result as the `i32`-valued map

**closed as `runs` · the repro prints `hi` · `mapRetExprShape` sent every call's callee to `fnRetMapShapeAt`, which answers the mono map for a name that is no declared function; a call through a parameter or local now takes the recorded rung, as `mapShapeOfExpr` already did · was check-clean invalid wasm · clause 1 · from the IW2 lane brief · the same on master `1df19732b` · filed 2026-09-27 against master `1df19732b` · fixture `tests/cases/closures/closure-returned-map-through-function-param.vl`**

Repro:

    const v: {[string]: string} = Map()
    v["k"] = "hi"
    function hof(f: () => {[string]: string}) { return f() }

#### Mechanism

`hof`'s result valtype is minted from `inferredRetMapSlot`, which reads the return expression's
map shape. For a call it asked `fnRetMapShapeAt(sid)`, which resolves `sid` to a declared
function and answers -1, the `{[string]: i32}` mono map, when there is none. `f` is a parameter,
so the result was declared as the `i32`-valued map while the value was the `string`-valued one.
None of D10, D1015 or D1091 is this defect.
