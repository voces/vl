### D2027 — an `extern function` cannot declare a `never` result, so a host `exit` does not end a path

**fixed 2026-10-26 — `vl check` rc 0, and `vl build` writes a valid module whose `exit` import is result-less with `unreachable` after each call · graded here as check-clean invalid wasm: `vl run` cannot load the witness, since the native host implements only `nowMillis`, and the grader files that load error under this outcome · `tests/vl_extern_test.ts` links `exit` to another unit and runs it to the trap · was loud check reject, clause 2 · residue of D1972 · filed 2026-09-22 against master `af07f4ae0` · fixture `tests/cases/extern/never-result.vl`**

Repro:

    extern function exit(code: i32): never
    function f(x: i32 | null): i32 {
      if x == null { exit(2) }
      x + 1
    }
    print(f(1))
    // vl check: rc 1, extern `exit` returns `never`, which cannot cross a host boundary

#### Mechanism

The extern result whitelist (D1997) admits the scalars and `void`; `never` falls to its
"cannot cross a host boundary" refusal. A `never` extern would lower as a result-less import,
exactly as `: void` does since D1997, with each call followed by `unreachable` as a `: never`
function's is. It is the natural spelling of a `std:process` exit.

#### Grading list

The import's type must be result-less; a guard arm calling it narrows; a call to it as an
if-expression arm types as the other arm. Beside it, from the same review: a `never` operand is
refused by arithmetic (`1 + fail()`) but accepted by string `+` (`"s" + fail()` runs), although
`never` is assignable to everything.
