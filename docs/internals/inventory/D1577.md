### D1577 — an if-EXPRESSION arm is a DELIVERY, and the one delivery that never recovered the nullable ref a struct field is STORED in

**closed (fixed) — `emitRefIfArm` now makes the `ref.as_non_null` every other delivery boundary makes (`nulNicheRecoverOwed`, D1115), gated on the blocktype the caller actually wrote · was check-clean INVALID WASM (clause 1) at BOTH the annotated and the un-annotated spelling · position matrix 0 -> 54 of 54, ref-kind grid 15 -> 17 of 20 with SILENT 3 -> 1 · ZERO corpus cells · reported by the glean session, VL-035, `~/glean/docs/vl-issues.md`, probes in `~/glean/vl-probes/` · filed 2026-09-04 against master `b6eb19b9`**

Repro (runs, prints `7`):

    type V = { i: i32 }
    type S = { ret: V, flag: boolean }
    export function pick(s: S) {
      const out = if s.flag { s.ret } else { s.ret }
      out.i
    }
    print(pick({ ret: { i: 7 }, flag: true }))

#### Mechanism

**A NESTED-STRUCT FIELD IS STORED NULLABLE THOUGH ITS TYPE IS NOT.** `ret: V` interns as
`(field (mut (ref null $V)))` — a struct must be defaultable — so `struct.get` hands back
`(ref null $V)` while the checker's type for the read is the non-null `V`. The compiler
already knows this: `exprNullableStruct`'s `Member` arm answers TRUE for a code-15 field
read for exactly this reason, and `nulNicheRecoverOwed` (D1115) is the one question every
DELIVERY into a `(ref $H)` destination asks before storing such a value.

The return, argument and binding boundaries ask it. The if-expression ARM did not. So a
non-null join wrote `(if (result (ref $V)))` — correctly, the checker's join is `V` — and
both arms pushed `(ref null $V)` under it. `vl check` rc 0; the engine refuses the module.

Disassembly, before and after, the two lines that disagree:

    (local $1 (ref $1))                     ;; the binding's slot: NON-NULL
    (local.set $1
     (if (result (ref $1))                  ;; the join: NON-NULL
      (struct.get $2 0 (local.get $0))
      (then (struct.get $2 1 (local.get $0)))   ;; before: (ref null $1)  ← mismatch
      (then (ref.as_non_null                    ;; after
              (struct.get $2 1 (local.get $0))))

The fix threads the blocktype the caller wrote (`nulJoin`) into `emitRefIfArm` rather than
re-deriving it, so the declaration and the arm's recover cannot disagree about the result's
nullness — and nothing is owed under a NULLABLE blocktype, which is what keeps D1560's
`T | null` arms lowering unchanged. It is the KIND's own niche that is asked for
(`vkNulNicheOf`), not a struct special case, so a `variant`-typed field arm is served by
the same line.

**BOTH FACES ARE ONE CELL.** Annotating the binding `: V` draws `@hint redundant type
annotation` and emits byte-identical bytes: the annotation agrees about the TYPE, and the
disagreement was about the REP. That is why this row has no annotated control.
