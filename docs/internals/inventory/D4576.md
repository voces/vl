### D4576 — a record of a generic returned by an un-annotated function is refused as a shared record when bound at its concrete field type

**closed 2026-10-14 by lane SC · runs · was loud check reject · the record-covariance check reads a direct call whose every returned value is fresh as fresh (`rcwCallSlotFresh`), and the returned literal is then delivered at the annotation as D4575's list is, through a nullable record slot too (`fn-value-flow-design.md` §(f) step 4) · pins: `tests/cases/closures/generic-record-returned-to-annotated.vl` · found by `fn-value-generic-optional-read.matrix.vl` (`return_inferred`, annotated face) · filed 2026-10-14 against `bd616c03b`**

Repro:

    function id<T>(x: T): T { x }
    function d() { return { f: id } }
    const v: { f: (x: i32) => i32 } = d()
    print(v.f(2))
    // vl check: a {f: (T) => T} cannot be delivered as {f: (i32) => i32} here: it reaches the call to `v.f` on line 4, a function value this check cannot see the body of. A record is shared, not copied

Want:

    2

#### Mechanism

The record-covariance check treats `{f: (T) => T}` into `{f: (i32) => i32}` as a widening of a
shared record. Here the field is a generic function being INSTANCED at the field's type, not a
narrower value seen through a wider one, and the record `d` returns is a fresh literal no other
binding holds. The direct spelling `const v: { f: (x: i32) => i32 } = { f: id }` is accepted.
