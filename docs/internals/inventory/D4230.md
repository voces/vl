### D4230 — a binding named like an ambient function is told apart by renaming it, not by marking the reference

**runs today and must keep running · design follow-up of D4066 (review of #3575) · filed 2026-10-12 against master `8a7854504`**

Repro (runs, prints `32` then `103`):

    function show(print: i32, n: i32) { print * 10 + n }
    function viaFn() {
      function print(x: i32) { x + 100 }
      print(3)
    }
    print(show(n: 2, print: 3))
    print(viaFn())

#### Mechanism

D4066 makes a declaration named `print`/`fromCodePoint`/`fromCodePoints`/`Map`/`Set` shadow
the ambient function by renaming the binding to `name$m<k>` in the module merge, so the 78
sites that recognise an ambient function by spelling (45 in `typecheck.vl`, 33 across
`wasmEmit.vl`/`emit_*.vl`) stop matching. The cost is that the renamed spelling is not the
source name, and every place that reads a binding's NAME as data — a named-argument label, a
record field looked up by a binding's name, a diagnostic, a hover, a trap frame — must
demangle it. D4066 covers the readers known today; a new reader that forgets is a wrong
answer, not a refusal.

#### Grading list

The cleaner shape keeps the source name and marks a reference that resolves to a user
binding, routing the ambient-spelling sites through one predicate (`refIsUserBinding(node)`).
Many of those sites take a bare name string, and the emitter reads mono-cloned bodies, so the
predicate needs the mark carried through cloning. Re-grade D4066's 253-cell matrix
(`~/.claude/vl-tools/generators/d4066_ambient_shadow_matrix.py`) and its six fixtures.
