### D4914 — `is K[][]` over `i32[][] | K[][]` with a string literal union `K` cannot tell atom ids from integers

**check-clean silently wrong value · clause 1 · found closing D4906 · the same answer on master before D4906's close · filed 2026-10-15 against master `23dcd80be`**

Repro:

    type K = "x" | "y"
    function f(a: i32[][] | K[][]) {
      if a is K[][] { print("K") } else { print("i32") }
    }
    f([[7]])
    // vl check: rc 0.  vl run: prints K

Want:

    i32

#### Mechanism

D4906's one-layer twin. Its close gives a `K[]` arm beside an `i32[]` arm its own box tag,
but at two layers both arms are lists of lists, which share one ref-list slot as D4896's
boolean-leaf lists did, so the outer union again has no tag to read.

#### Ablation

| ingredient changed | outcome | needed? |
| --- | --- | --- |
| one layer, `i32[] \| K[]` and `f([7])` | prints `i32`, which is right (D4906) | **yes** (two layers) |
| `type K = 0 \| 1` | prints `i32` (D4771's element test) | **yes** (a string literal union) |

#### Grading list

The other direction (`f([["y"]])` tested `is i32[][]`), and `(K | null)[][]` as the second arm.
