### D2752 — a union member that is a map of Sets fails `is` against its own type

**closed 2026-09-26 — the filed repro RUNS and prints `true` · was check-clean silently wrong (`false`) · clause 1 · found by #3202's review (`w3e`, and the shallow `wd2`–`wd8`) · closed by matching a pattern to the union member it names once a nested Set is spelled as its boolean map (`tySameSpelled`, `isPatUnionArmTy`) · filed 2026-09-26 against master `876559d2f` · fixture `tests/cases/generics/pin-exact-key-nested-set-map.vl`**

Repro:

    const s: {[string]: Set<string>} = Map()
    const w: {[string]: Set<string>} | string = s
    print(w is {[string]: Set<string>})
    // PRINTS true

#### Mechanism

A union's members are registered under their spelling, and a spelling renders a nested `Set<K>`
as `{[K]: boolean}`. The pattern `{[string]: Set<string>}` therefore matched no member by `tyEq`,
by `tySameSet`, or by `mapTwinSame`'s Set rule, which looks only at the top level. Its own value
slot (keyed `Set<string>`) was never interned, so `mapArmTagOfTy` gave it no tag and the test
folded to `false`. `isPatUnionArmTy` now takes the member that is the pattern once every nested
Set reads as its boolean map (`tySameSpelled`), and the test reads that member's tag. An exact
generic instance still tells the two apart, because `exactUnionLacksMap` compares against the
pattern as written, not the member it was matched to.
