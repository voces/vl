#### Mechanism

The refusal is raised when the union type is formed, before any `is` is written. Its sentence
says no literal-typed field tells the arms apart. Here `k` is literal-typed in both arms, and
`"x"` and `1` are disjoint, so a discriminant field is exactly what the author wrote.
D3885 (owner ruling A, 2026-10-10) kept the behaviour of the string-against-integer-literal
refusal, so this row is about its wording. Whether the refusal is owed at all is owner
question Q4 in `docs/spec/OPEN-QUESTIONS.md`. A close either lets the program run or refuses
it with a sentence that names what is actually wrong.

#### Ruling

Q4 ruled 2026-10-12 as (c): the union is legal and `is` tests the value (DECISIONS.md §"Record arms that share a field name form a legal union"). The build: the arms are tagged by their field types (a literal set read as its base), and
`is X` over a box `i32.or`s the tag test with one term per other arm whose values may fit `X`,
testing the fields only some values fit. Every grading-list program runs: the D3885 pin prints
the arm its value fits, and `{ v: i32 } | { v: boolean }` answers by the field's value.

#### Open question for the owner (review of #3579, §3)

An inline record literal whose field value fits several arms is built as one of them, and `is`
answers for the arm that was built. Which arm that is depends on how the union is spelled:

    type A = { v: f64 }
    type B = { v: i32 }
    function f(u: A | B) { … }   // prints which of `is A`, `is B` hold
    function g(u: B | A) { f(u) }
    f({ v: 3 })   // A notB
    g({ v: 3 })   // notA B

`A | B` and `B | A` are one type, yet the same literal answers differently. Separately,
`{ v: i64 } | { v: 1 | 2 }` builds `{ v: 1 }` as the `i64` arm in either order, so `is` of the
arm whose literal set names exactly `1` is false.

Question: which arm does such a literal build? Recommendation: the most specific arm it fits,
whatever the spelling order. A literal set naming the value comes first, then the literal's
default type (`i32` for an integer literal, `f64` for a decimal one), then wider widths. Under
that rule `{ v: 3 }` builds `B` and `{ v: 1 }` builds the literal-set arm in both orders. This
row does not decide it, and the build is unchanged.
