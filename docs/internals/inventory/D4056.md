### D4056 — a union of two records whose shared field is a string literal in one and an integer literal in the other is refused as having no literal-typed field

**loud check reject · the message is false: both arms' field is literal-typed, and the literal sets are disjoint · found reviewing `docs/guide/unions.md` (lane SPEC) · filed 2026-10-11 against master `98a4ed71b`**

Repro:

    type A = { k: "x" }
    type B = { k: 1 }
    function f(v: A | B): i32 { 3 }
    print(f({ k: 1 }))
    // vl check: rc 1, "arms `A` and `B` share a field-name set and no literal-typed field
    // distinguishes them — add a discriminant field"

#### Mechanism

The refusal is raised when the union type is formed, before any `is` is written. Its sentence
says no literal-typed field tells the arms apart. Here `k` is literal-typed in both arms, and
`"x"` and `1` are disjoint, so a discriminant field is exactly what the author wrote.
D3885 (owner ruling A, 2026-10-10) kept the behaviour of the string-against-integer-literal
refusal, so this row is about its wording. Whether the refusal is owed at all is owner
question Q4 in `docs/spec/OPEN-QUESTIONS.md`. A close either lets the program run or refuses
it with a sentence that names what is actually wrong.

#### Ablation

| variant | outcome |
| --- | --- |
| this witness | refused, message above |

| `A = { k: 0 }`, `B = { k: 1 }` (two integer literals) | runs |
