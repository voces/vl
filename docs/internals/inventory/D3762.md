### D3762 — an un-annotated list literal of a nominal record with a nullable-record field refuses as a struct array

**closed · was loud emit reject · clause 2 · 8 `list_elem` cells of lane GN's D3760 grid (`B | null` field) · fixture `tests/cases/lists/nominal-record-nullable-record-field-list-literal.vl` · filed 2026-10-06 against master `b05991d98` · closed by lane S5**

Repro:

    type B = { v: i32 }
    type H = new { f: B | null }
    const p: H = { f: { v: 4 } }
    const xs = [p]
    print(xs.length)
    // vl check: rc 0.  vl run: emit error, "emitProgram: struct array elements are not supported"

Want:

    1

#### Mechanism

A `new` record is a second arena index over its body (`nwBrand`, typecheck.vl), and no struct row
records it: `sTyIx` holds the body's index, so `structIndexOfTy` answered -1 for the brand.
`p`'s recorded type is the brand, so `arrLitNominalElemName` resolved no row and `arrLitIsRef`
declined. A brand over a record with only plain fields is rescued by the field-set scan, which
declines a nullable-record field, so only that shape fell through. Closed in `structIndexOfTy`:
a miss retries at `nomErasedTyIx`, the index the brand erases to at run time.

`scripts/capability-probes/matrix/nominal-record-nullable-record-field.matrix.vl` grades the value
at every position: 48 of 48 run after, and the base seed refused only `array_element`
un-annotated. The first notes, kept for the record: The literal reaches `emitArrayLit`'s `i32`-list fallback (wasmEmit.vl) with a
struct element, so the list's rep was not resolved to a ref list of `H`. The annotated spelling
(`const xs: H[] = [p]`) and a `push` onto an annotated empty list both run, so the missing input is
the inferred element type's rep. A nominal record with no nullable-record field also runs. This is
not [D2920](D2920.md), which needs a generic hole.

The two faces disagree, and the hint points the wrong way: on the annotated spelling, which runs,
`vl check` hints `redundant type annotation: \`xs\` is inferred as \`H[]\``. That annotation is
the one that makes it run. Removing it as the hint asks turns a running program into this refusal.
