### D3762 — an un-annotated list literal of a nominal record with a nullable-record field refuses as a struct array

**loud emit reject · clause 2 · open · 8 `list_elem` cells of lane GN's D3760 grid (`B | null` field) · filed 2026-10-06 against master `b05991d98`**

Repro:

    type B = { v: i32 }
    type H = new { f: B | null }
    const p: H = { f: { v: 4 } }
    const xs = [p]
    print(xs.length)
    // vl check: rc 0.  vl run: emit error, "emitProgram: struct array elements are not supported"

Want:

    1

#### Mechanism

Not yet located. The literal reaches `emitArrayLit`'s `i32`-list fallback (wasmEmit.vl) with a
struct element, so the list's rep was not resolved to a ref list of `H`. The annotated spelling
(`const xs: H[] = [p]`) and a `push` onto an annotated empty list both run, so the missing input is
the inferred element type's rep. A nominal record with no nullable-record field also runs. This is
not [D2920](D2920.md), which needs a generic hole.

The two faces disagree, and the hint points the wrong way: on the annotated spelling, which runs,
`vl check` hints `redundant type annotation: \`xs\` is inferred as \`H[]\``. That annotation is
the one that makes it run. Removing it as the hint asks turns a running program into this refusal.
