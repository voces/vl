### D16121 — a function read back through a map of maps is called at a signature no stored value was instanced at, when that call is the only one

**closed 2026-11-14 — the witness runs and prints `2.5` · was: loud emit reject · `` emitProgram: a function-value call has no interned signature — no function value of type `(f64) => f64` reaches this call to intern its signature `` · clause 2 · the same program runs once the function is called through its own map first, or held in a list or record instead · filed 2026-11-14 against master `1b5ee549`**

Repro:

    function half(a) { return a / 2.0 }
    const m4 = Map()
    m4.set("a", half)
    const mm = Map()
    mm.set("k", m4)
    const f = mm.get("k")
    if f != null {
      const g = f.get("a")
      if g != null { print(g(5.0)) }
    }

Want:

    2.5

#### Mechanism

`m4`'s slot finds no pin (`monoStoredSlotFnTy`, `elabSlotUncalled`), because the only call reaches
`half` through `mm`'s value. The elaboration does not alias `mm`'s value slot to `m4`'s slot the
way it aliases a list element or a record field to it. `m4` closes at the uncalled default, and
the read-back call names a signature no stored value was instanced at. A `for` loop over `mm`
reaches a related refusal: the loop variable's own value reads keep their open type, because a
loop variable is no binding `monoReadLetFrame` resolves.

#### Ablation

| ingredient changed | outcome | needed? |
| --- | --- | --- |
| a call through `m4` first (`m4.get("a")` called at `3.0`) | runs, `1.5` `2.5` | **yes** |
| `[m4]` or `{ m: m4 }` in place of `mm` | runs | **yes** (a map holder) |
| the read through `mm` without the call (`f.length`) | runs | **yes** (the call) |
| `for k, inner in mm` in place of the `get` | the parameter-type refusal, `_` | no |
