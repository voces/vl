#### Mechanism

The direct call through a binding of an `if` (`monoCallIfBound`, emit_mono.vl) instanced the
arms at the first call's type, so the binding held one closure value and the second call was
emitted against it. Every call and delivery through such a binding now records its function
type on the binding (`monoChoiceBindNote`); a second type is refused loudly and asked of the
split (`fsAsk`), which plans one `const` copy of the choice per type, re-parsed from the
binding's tokens and placed after it, and re-points each read at its type's copy. A copy is
made only when the condition (or `match` scrutinee) is a pure read and every arm is a name or a
nested pure choice, so the copies evaluate to the same function; otherwise the refusal stays
([D9161](D9161.md)). A binding whose arms a first use already instanced is still followed as a
choice (`monoChoiceBindIx` in `monoIfBindingWalk`), so a later call at a second type reaches the
same refusal.
