### D9120 — a `const` bound to an `if` choosing two generic functions, called directly at two types, is check-clean invalid wasm

**check-clean invalid wasm · `vl check` rc 0 · `type mismatch: expected (ref $type), found i32` · clause 1 · found closing [D9080](D9080.md) · present on master `7736fb65b` · filed 2026-10-21 against master `7736fb65b`**

Repro:

    function idg<T>(t: T): T { return t }
    function kg<T>(t: T): T { return t + t }
    const c = [1].length > 0
    const h = if c { kg } else { idg }
    print(h(3))
    print(h("x"))
    // vl check rc 0, vl run: invalid module, type mismatch: expected (ref $type), found i32

#### Mechanism

Not traced. The checker types `h` as the generic signature both arms share and accepts both
calls; the direct call through a binding of an `if` (`monoCallIfBound`, emit_mono.vl) instances
the arms at one call's type, so the binding holds one closure value and the other call is
emitted against it. The alias `const h = kg` called at the same two types runs, `6` then `xx`.

#### Ablation

| ingredient removed | outcome | needed? |
| --- | --- | --- |
| the second call, `h("x")` | runs, `6` | **yes** |
| the `if`, for `const h = kg` | runs, `6` `xx` | **yes** |
| the direct calls, for `app(h, 3)` / `app(h, "x")` through a generic parameter | loud emit reject, [D9121](D9121.md) | no |
