#### Mechanism

Type-bound resolution (#3005) asked the receiver type's home module only when `ufcsCallTy`'s
`lookup(name)` missed, so any same-named binding in the caller's scope blocked it. Fixed by
`ufcsScopeStepsAside` under the owner's ruling (option (a), 2026-09-22): the scope's
`self`-function steps aside only when the receiver is a newtype and its `self` is ANNOTATED with
a concrete type that does not name that newtype. Structural receivers, un-annotated `self` and
generic `self: T` keep the call as before. The test reads declared names only: an earlier cut
that asked whether `self` ACCEPTED the receiver let a library field addition or a body edit
re-route a compiling call (review of #3030). type-bound-ufcs-design.md §F and DECISIONS.md
§"UFCS is never implicit" carry the rule. D1230's sentence now proposes an aliased import
(`dot as dotF32x4`, or the next free suffix) whenever the caller binds the name.
