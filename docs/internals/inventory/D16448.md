### D16448 — an inferred return joining an empty list literal with `null` builds an invalid module

**closed 2026-11-15 — the witness runs and prints `0` · was: check-clean invalid wasm · clause 1 · `type mismatch: expected i32, found (ref $type)` inside the function · found grading D16342's arm (`empty-list-join-null-sibling`, un-annotated `return_inferred`, SILENT on master) · filed 2026-11-15 against master `32f872af5` · closed: an un-annotated function's inferred return defaults the open containers no read reached and no write fixed before A20 records it, as a `let` binding's are (`defaultInferredRet`, check_narrow_flow.vl, called in `checkProgramNode`'s A20 loop) · fixture `tests/cases/functions/infer-return-empty-list-or-null.vl`**

Repro:

    function truthy() { return 1 == 1 }
    function deliver() { return if truthy() { [] } else { null } }
    const v = deliver()
    if v != null { print(v.length) } else { print("null") }
    // was: vl check rc 0, vl run: invalid module inside `deliver`

Want:

    0

#### Mechanism

The return is inferred `_[] | null`, its element open: no write fixes it. A `let` holding such a
join is defaulted at the program's end (`settleOpenUnionRows`, `defaultUnfixed`), but a
function's return was not: A20 recorded `_[] | null`, no recorder names an open nullable list,
and the function was emitted with an `i32` result over a body returning the list struct. The
return now takes the unbound default where no read reached it and no write fixed it
(`defaultOpenHoles`, the rule the `let` path uses); the defaultable-hole test's path walk
(`recOpenHolePath`) does not see through `| null`, so the return asks only the two facts.
