### D17675 — a record field written in an `is` branch, then tested for the member the write left: the claimed function is invalid wasm

**closed 2026-11-26 by COV-IS, cov-is-52 · runs, prints `1`, graded under `VL_IR_STRICT=1` · was check-clean invalid wasm under `VL_IR_STRICT=1` (the claim of `f`; a run without strict IR fell back to legacy and printed `1`), clause 1 · the lowering writes a field read at its storage (`gfStored`) without the union unbox its narrowing would take · pins: `tests/cases/soundness/field-rewritten-is-at-storage-positions.vl` · found by COV-IS while widening `is stored member receiver` · filed 2026-11-26 against master `acd462ed4`**

Repro:

    type O = { v: i32 | string }
    function f(o: O) {
      o.v = "s"
      if o.v is string { o.v = 9 }
      if o.v is i32 { print(1) }
    }
    f({ v: 1 })
    // was, under VL_IR_STRICT=1: the emitted module failed to validate inside `f`: type mismatch:
    // expected (ref null $5), found i32

Want:

    1

#### Mechanism

The last `is` is decided at its storage, so its receiver `o.v` is read there: the builder holds that
read at the field's box (`storedMemberBoxTest`), but the lowering's field tail under the storage
mark still unboxed it, because `memReadCheckerAtomKind` reads the checker's type of the member, which
the branch write narrowed to `i32`. Legacy's storage-mode `is` reads the raw slot. The field
analogue of D17663 (a map cell).

| --- | --- | --- |

| the whole write `o.v = "s"` | still invalid | no |
| the final `is` test | valid | **yes** |
