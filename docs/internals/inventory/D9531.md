### D9531 — a record literal of an un-annotated function pushed onto an un-annotated list traps at its call when a declared record type of the same field name is used elsewhere

**loads then traps · `vl check` rc 0 · `wasm trap: indirect call type mismatch` · clause 1 · found closing [D9471](D9471.md) · present on master `1cf53e320` · filed 2026-10-22 against master `1cf53e320`**

Repro:

    type R = { f: (a: i32) => f64 }
    function inc0(a) { return a + 1 }
    const r: R = { f: (a: i32): f64 => 1.0 }
    const p = []
    p.push({ f: inc0 })
    print(p[0].f(3))
    // vl check rc 0.  vl run: wasm trap: indirect call type mismatch

#### Mechanism

Not traced. The list `p` and the record pushed onto it never meet `R`, yet the call reads
`inc0` (i32 result) through an f64-result signature, as if the element were laid out at
`R`'s row. With `R` declared but no value of it built, the program runs.

#### Ablation

| ingredient removed | outcome | needed? |
| --- | --- | --- |
| the binding `r` (`R` still declared) | runs, `4` | **yes** |
| the hole in `inc0` (`inc0(a: i32): i32`) | runs, `4` | **yes** |
| the push, as a list literal (`const p = [{ f: inc0 }]`) | runs, `4` | **yes** |
| the literal, bound first (`const q = { f: inc0 }`, `p.push(q)`) | same trap | no |

#### Grading list

`m.set("a", { f: half })` into a `Map<string, R>` in place of the binding `r` (same trap),
and the sibling rows [D9530](D9530.md) and [D9532](D9532.md).
