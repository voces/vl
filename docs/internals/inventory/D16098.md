### D16098 — a re-pointed `let` of un-annotated functions whose results differ, handed to a generic `(x: T) => R` parameter, is refused at check

**loud check reject · clause 2 · `cannot write 'str' to 'f': called at (i32) it returns string, where 'inc', also written to it, returns i32 — every function a call through 'f' may run must return one type` · the `let` twin of [D16093](D16093.md) · filed 2026-11-14 against master `e5bfe3d6c`**

Repro:

    function inc(a) { return a + 1 }
    function str(_a) { return "s" }
    function app<T, R>(g: (x: T) => R, v: T): R { return g(v) }
    function run(c: boolean) {
      let f = inc
      if c { f = str }
      print(app(f, 3))
    }
    run(true)
    // vl check: rc 1, the refusal above

Want:

    s

#### Mechanism

A widened `let` handed to an open parameter is left to the tag decision (D16009). A generic
parameter `g: (x: T) => R` is not open in that sense, so `holeLetJudge` judges the binding's
writes at the call's types and refuses. A list element or a record field handed to the same
parameter dispatches (D16093, D16097), and a choice does (D16094).
