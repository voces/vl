### D3873 — the VALUE of a function assignment `(d = inc)`, bound to a `const` or `let` or called in place, is refused at emit: "call to unknown function", or "callee is not a function name" when called directly

**loud emit reject · clause 2: `vl check` rc 0, a legal program · found by the rv3461 review of #3454–#3461 (d/d05, d06, e5, e6, e8; e1 the direct call) · filed 2026-10-08 against master `862c99b79`**

Repro:

    const inc = (x: i32): i32 => x + 1
    let d: (x: i32) => i32 = (x: i32): i32 => 0
    const r = (d = inc)
    print(r(4))
    // vl check: rc 0 (one unused-parameter warning).
    // vl run: rc 1, `emitProgram: call to unknown function` at the `r(4)` call

Want:

    5

#### Mechanism

An assignment is an expression whose value is the assigned function, and `d = inc` stores into `d`
correctly: `d = inc` as a statement then `d(4)` prints `5`. The refusal is on delivering that value
onward and calling it. Bound to a binding, the call `r(4)` names a binding with no function behind
it, so the emitter says "call to unknown function"; called in place, `(d = inc)(4)`, the callee is
not a name at all, and the emitter says "callee is not a function name". Both look like the same
missing case, a call whose callee is an assignment expression, at one delivery or the other, but
only the refusal sentences were compared. Delivering the same value through a lambda (`const g = ()
=> (d = inc)`, then `const r = g()`) runs.
