### D9230 — a list of un-annotated functions handed to an un-annotated parameter and called inside its `.map` callback runs a function taken at another type

**closed · runs, prints `6` · was loads then traps, `wasm trap: indirect call type mismatch` in `__lambda_1`, `vl check` rc 0 · clause 1 · found closing [D9173](D9173.md) · filed 2026-10-21 against master `12b0bac7e` · closed by sending a `.map` / `.filter` lambda over an un-annotated parameter through the flow's list-method edge, so the callback's call pins the list handed to the parameter (`ffCall` / `ffIsElemCallback`, fn_flow_shadow.vl) · fixture `closures/hole-fn-list-to-hole-param-called-in-callback.vl`, matrix `hole-fn-list-called-in-callback` (`argument` and `early_return_guard`, un-annotated) · [D9280](D9280.md), [D9281](D9281.md) and [D9282](D9282.md) filed beside it**

Repro:

    function inc0(a) { return a + 1 }
    function dbl(a) { return a * 2 }
    function take(a) { print(a.map((f) => f(3))[1]) }
    const g = [inc0, dbl]
    take(g)
    // vl check rc 0.  vl run: prints 6

#### Mechanism

The flow table (fn_flow_shadow.vl) routes a method call to `ffMethod` only when the checker
typed its receiver as a list or a map. An un-annotated parameter is a type variable, so
`a.map(lambda)` fell to `ffOpaque`: the lambda escaped as an argument of `.map`, its
parameter `f` never joined the element slot of `a`, and the call `f(3)` pinned nothing on
the list handed to `take`. `g` was then taken as a list nothing calls and its functions were
instanced at the uncalled type `() => void`, while the instance of `take` called them at
`(i32) => i32`: an indirect call type mismatch. Handed inline, `take([inc0, dbl])`, the same
missing pin left the literal's element open and `.map`'s result had no list type
(`index receiver is not an array or string`). One mechanism, both spellings.

The fix sends a `.map` / `.filter` call whose receiver is a type variable and whose argument
is a lambda to `ffMethod`, and `ffIsElemCallback` accepts that receiver, so the lambda's first
parameter joins the receiver's element slot as it does for a typed list (D9093).
