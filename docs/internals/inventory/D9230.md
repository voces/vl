### D9230 — a list of un-annotated functions handed to an un-annotated parameter and called inside its `.map` callback runs a function taken at another type

**loads then traps · clause 1 · `vl check` rc 0 · `wasm trap: indirect call type mismatch` in `__lambda_1` · the same on master `12b0bac7e` · found closing [D9173](D9173.md) · filed 2026-10-21 against master `12b0bac7e`**

Repro:

    function inc0(a) { return a + 1 }
    function dbl(a) { return a * 2 }
    function take(a) { print(a.map((f) => f(3))[1]) }
    const g = [inc0, dbl]
    take(g)
    // vl check rc 0.  vl run: wasm trap: indirect call type mismatch

#### Mechanism

Not traced. The likely shape: the flow's callback edge (`ffIsElemCallback`,
fn_flow_shadow.vl) needs the receiver typed as a list of functions, and a hole parameter is
not, so the call `f(3)` pins nothing on `g`; `g` is then taken as an un-called list and its
functions are instanced at a value type the callback's call does not match.

#### Ablation

| ingredient removed | outcome | needed? |
| --- | --- | --- |
| the parameter (`g.map((f) => f(3))[1]` at top level) | runs, `6` | **yes** |
| the `.map` (`a[1](3)` in `take`) | runs, `6` | **yes** |
| a direct call `print(g[0](1))` added at top level | runs, `2` `6` | no, masks it |
| annotations on `inc0` / `dbl` | runs, `6` | **yes** |

#### Grading list

The literal handed inline, `take([inc0, dbl])`, is a loud emit reject
(`index receiver is not an array or string`), as are the `argument` and
`early_return_guard` cells of matrix `hole-fn-list-called-in-callback`'s un-annotated face.
`for f in a` over the hole parameter is refused at check (`for-in expects an array`).
