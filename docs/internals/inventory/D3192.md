### D3192 — a generic or hole instance calling a record's nullable `() => boolean` field prints its result as an i32

**check-clean silently wrong · clause 1 · pre-existing, the same on master `36d233f66` · found by the #3286 review (`rv3286-2159/g/c0123_bool_same_bool_n_i32_hole.vl`, `c0124_…_generic.vl`) · filed 2026-09-29 against master `36d233f66`**

Repro:

    type R = { v: i32, f: (() => boolean) | null }
    function F(z) { print(z.f()) }
    F({ v: 7, f: () => true })
    // PRINTS 1

Want:

    true

#### Mechanism

Not localised past the ablation. The closure's signature matches the field's, so no row claim
is involved (the #3286 row checks accept it): inside the instance the pin binds `z` to a
record whose `f` is `(() => boolean) | null`, and the call's result is classified as `i32`,
which suggests the result classifiers read through a nullable function type no further than
its `null` arm. D3193 is the literal-union result's twin, but needs no nullable, so it is filed
apart until one fix is shown to close both.

#### Ablation

| ingredient changed | outcome | needed? |
| --- | --- | --- |
| `type R` removed | prints `true` | **yes** (a row whose field is the nullable function) |
| `R`'s `f: () => boolean` (not nullable) | prints `true` | **yes** |
| `print(x.f())` on a module binding, no function | prints `true` | **yes** (an instance) |
| `function F<Z>(z: Z)` in place of the hole | prints `1` | no |
| `const r: { v: i32, f: (() => boolean) \| null } = …; F(r)`, no declared `R` | prints `1` | no |
| `function F(z: R)`, the body null-testing `z.f` before calling it | prints `true` | **yes** |
