### D6481 — a `let` lambda handed to an un-annotated parameter that calls it with a generic function is refused at emit

**closed 2026-10-18 by lane L1 · runs, prints `2` then `s` · was loud emit reject · `vl check` rc 0 · clause 2 · a hole parameter of a module function read only as a callee and handed the same module function or `const` lambda by name at every call is planned as that function: the call through the parameter becomes a call by name and the parameter is dropped from the function and from each call, so the generic it hands on is instanced at each type the lambda calls it at; a hole parameter given two different functions is [D6706](D6706.md) · pins: `tests/cases/closures/lambda-through-hole-param-called-with-generic-at-two-types.vl`, `tests/cases/functions/hole-param-always-one-fn-default-param.vl` · found closing [D6421](D6421.md) · filed 2026-10-18 against master `b21da3d5d`**

Repro:

    function id(a) { return a }
    const lap = (g) => { print(g(1) + 1); return g("s") }
    function use(k) { return k(id) }
    print(use(lap))
    // vl check: rc 0.  vl run: emitProgram: monomorphize: unsupported argument type for `k` in a call to `use`

#### Mechanism

From the ablation only. `use`'s parameter `k` is an inference hole bound to a lambda value
whose own parameter is a hole, and the monomorphizer has no argument type to instance `use`
at.
