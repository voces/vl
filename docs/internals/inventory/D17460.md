### D17460 — the IR misses a string literal's `.length`

**closed 2026-11-24 by lane IR-P1 · runs, prints `2`, the IR claiming it · was an IR coverage defect: `buildMember` (ir_build_ref.vl) now takes a string literal's `.length` over its `OStr` operand, as `RListLen` and `irLOpnd` already could · filed 2026-11-24 against master `cea354ff6` by lane IR-P1 (census class `start: string length receiver`; found as the next miss past `method isCharBoundary` in two tests/cases programs)**

Repro:

    print("ab".length)
    // VL_IR_SHADOW=1 vl build: `start uncovered string length receiver`

Want:

    2

#### Mechanism

`buildMember` (`ir_build_ref.vl`) takes a string's `.length` only when its receiver builds to an
`OVar` (`string length receiver`). A string literal builds to another operand, so the read misses
and legacy builds the function. Every other receiver measured builds a variable and is covered.

#### Ablation

| ingredient changed | outcome | needed? |
| --- | --- | --- |
| the literal bound first (`const s = "ab"; print(s.length)`) | covered | **yes**, a literal receiver |
| a user call's result (`f().length`) | covered | **yes** |
| a builtin call's result (`fromCodePoint(233).length`) | covered | **yes** |
| `s.slice(0, 2).length`, `("a" + "b").length` | covered | **yes** |
| the empty or a non-ASCII literal (`"".length`, `"é".length`) | still `string length receiver` | no |
| the read inside a function (`function k() { print("é".length) }`) | still, as `uncovered string length receiver` | no |
| the result bound (`const n = "ab".length`) | still | no |
