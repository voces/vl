### D10381 — a generic passed back through two un-annotated functions' returns, handed to a generic's function parameter at two types, interns no signature

**loud emit reject · `vl check` rc 0 · `emitProgram: a function-value call has no interned signature — no function value of type `(i32)=>i32` reaches this call to intern its signature` · clause 2 · CAPABILITY: `deliver` returning `id` itself prints `4`, and one call `run(v, 2)` prints `2` · found closing [D10310](D10310.md), the un-annotated `return_inferred` cell of fn-value-generic-unannotated-return-handed-open · present on master `34af3ccc6`, where it refuses as `monomorphize: unsupported argument type for `f` in a call to `run`` · filed 2026-10-22 against master `34af3ccc6`**

Repro:

    function id<T>(x: T): T { x }
    function run<U>(f: (x: U) => U, u: U): U { f(u) }
    function mk() { id }
    function deliver() { return mk() }
    const v = deliver()
    print(run(v, 2) + run(v, "ab").length)
    // vl check rc 0.  vl build: a function-value call has no interned signature

Want:

    4

#### Mechanism

Not traced. A guess, not ablated: `monoFlowCallLeaf` names the generic through `deliver`'s
return of `mk()`, so the reads of `v` are rewritten to `id`, but what is noted inert is
`deliver`'s return operand, the call `mk()`, not `mk`'s own `id`, and one instance of the call
`f(u)` is left with no value of its type.
