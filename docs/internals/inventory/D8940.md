### D8940 — an un-annotated function whose returns join an `f64` with its `i32` argument is typed at the argument's `i32` at the call

**closed 2026-10-21 by lane L1 · now a loud check reject (`f64 | i32 doesn't fit in i32`) · was check-clean invalid wasm · clause 1, present on master `30ff8d9b5` · fixtures `tests/cases/soundness/error-hole-fn-joined-widening-at-i32.vl` and `tests/cases/functions/hole-fn-joined-widening-runs.vl` · filed 2026-10-21 against master `30ff8d9b5`**

Repro:

    function half(a) {
      if a > 1 { return a / 2.0 }
      return a
    }
    const r: i32 = half(3)
    print(r)
    // vl check: f64 | i32 doesn't fit in i32 — the conversion is lossy and must be made explicit with `as`

#### Mechanism

D8161 takes a direct call's result from the callee's body at the bound arguments
(`holeRetTyOf`, `check_relate_core.vl`), but answered -1 as soon as two returns
disagreed, so the call fell back to the signature's hole `T` pinned at `i32`, and the
`f64` arm was delivered into an `i32` local. A `return if … else …` was never split
into its arms either. Closed there: `bodyRetTyAt` collects every return leaf, the
`if`/`match`/block arms of each return argument included, and `holeRetJoin` joins
disagreeing numeric leaves by the numeric-join ruling, a literal arm adapting, so
`half(3)` is `f64 | i32`, its leaves joined in source order as the direct spelling joins them. The same join decides the `f64` destination, which now runs.

#### Grading list

The return order swapped, `return if a > 1 { a / 2.0 } else { a }`, a `const` lambda,
a literal arm `return 2` beside `a * 1.5`, an `i32` argument, and `(i32) => i32`,
which printed `1.5` on master. All of these are refused after the change; the
un-annotated, `f64`-binding and `f64`-argument spellings run.
