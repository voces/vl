### D15430 — a record holding a generic, returned by a function and handed to a hole parameter that calls the field, holds closures rather than the set's id

**closed 2026-11-04, runs with the split plan on and off · was loud emit reject (`a function-value call has no interned signature`), clause 2 · `ftHoldCtxOk` (check_fn_tag.vl) takes a call of a named function handed to a hole parameter as it takes a binding read, so the set is tagged and the field holds its id · fixture `tests/cases/closures/record-generic-field-returned-handed-to-hole-param.vl` · found minimising `maker-result-in-module-record-field-returned-or-listed` (split-plan census, group M) · filed 2026-11-04 against master `a090a48b`**

Repro:

    function k<T>(x: T): T { return x }
    const r3 = { f: k, g: 7 }
    function get3() { return r3 }
    function show(o) { print(o.f(true)); print(o.g) }
    print(r3.f(1))
    print(r3.f("z"))
    show(get3())
    // vl check: rc 0.  vl run, before: emitProgram: a function-value call has no interned signature

Want:

    1
    z
    true
    7

#### Mechanism

The tag decision declined the set `{k}` at the holder's hand `show(get3())`: `ftHoldCtxOk`'s call arm took a holder handed to a hole parameter only when the argument was a binding read (`show(r3)` runs). A call of a named function hands its result, whose type is the holder's, so the hole parameter binds to it as it does to a binding. Declined, `k` stayed a closure called at two types: with the split plan on, the plan's copies served `r3.f(1)` and `r3.f("z")` but not a third type inside `show`; with the plan off, the closure had no signature at all.
