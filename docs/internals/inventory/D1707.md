Was: `emitProgram: nested-struct field element type is not interned`. Three neighbouring

#### Mechanism

Probed, not read off the code path, with the failing witness as the control:
`PROBE arm-field-no-twin nm={xs:C} ftxt=C vi=0 twin=-1 sNames=0`. D761 gives an arm-typed field
the struct row the arm SHARES, and `internInlineShapeTy` applies that rung — but
`armFieldStructRow` resolves through `variantStructHeapTwinAt`, which reads the struct table,
and the probe says that table is EMPTY.

**The mint was not missing, it was one statement late.** `collectNestedFieldShapes` ran
`internShapeDeepTy` — which is where the nested shape is classified — and only then
`internArmFieldShape`, whose own descent (D1672) already reaches an inline shape's fields. So
the arm's twin row was minted immediately after the reader that needed it. Swapping the two
gives the nested shape the same table the declaration's own fields already had.
