### D2064 — the getter intrinsic allow-list omits every scalar math and bit intrinsic, and the refusal calls them "not pure intrinsics"

**closed · the filed repro RUNS and prints `5` · was `loud check reject` · clause 2 (a type-valid getter the contract's own text allows) · filed 2026-09-22 against master `31ea77721`, found independently by four lenses of the getters/effects persona review (Swift, game-perf, compiler-engineer, beginner)**

Repro:

    type Pt = new { x: f64, y: f64 }
    get len(self: Pt): f64 { sqrt(self.x * self.x + self.y * self.y) }
    const p: Pt = { x: 3.0, y: 4.0 }
    print(p.len)
    // was, at filing — vl check: the getter `len` on Pt calls `sqrt`, which is neither a
    // pure intrinsic nor a getter — …

#### Mechanism

`getterIntrinsics` in `compiler/typecheck.vl` is a hand-written list of load and `f32x4` names.
It contains `__sqrt_f32x4__` and `__abs_f32x4__` but not the scalar `sqrt`, `abs`, `floor`,
`ceil`, `trunc`, `nearest`, `min`, `max`, `copysign`, `clz`, `ctz`, `popcnt`, `rotl` or `rotr`,
each of which lowers to one wasm instruction. The checker already has the predicate that names
them, `isNumIntrinsicName` (float and int intrinsic arity tables), so the fix is to consult it
rather than keep a second list. The message is false as well as unhelpful: `sqrt` IS a pure
intrinsic by any reading of the word.

#### Grading list

`popcnt(self as! i32)` on a `new i32`; `min`/`max` over two fields; `f32fromBits`-style bitcasts;
the doc's canonical `len` above. The i32/f64 mismatch the beginner lens reported beside `abs` is
NOT part of this row: prelude `abs` is f64-typed outside a getter too (`const k: i32 = abs(-5)`
is refused), so that second error is correct.

#### Close

`getterIntrinsicName` replaces the hand list: a callee is admitted when the emitter's own
classifiers name it — `isNumIntrinsicName` (the float and integer opcode tables and the four
bitcasts), `__load_i32__` / `nameIsMemLoadIntrinsic`, `nameIsSimdIntrinsic` less any member whose
declared result is `void` (so `__store_v128__`, and any later SIMD store, stays out), the two
heap-window reads and `__trap__`. Every store width, `__memory_grow__` / `__memory_size__` /
`__memory_copy__` / `__memory_fill__`, `__log__`, `__array_new__` and the host floor are in none
of those sets. A program function spelled like an intrinsic is now refused as "calls the function
`sqrt`", and the call rule names the admitted class — "a getter may call only other getters and
the single-instruction numeric, load and SIMD intrinsics" — instead of the word "pure". Float `%` keeps the
classification it had (an operator, allowed); its `__f64_rem__` loop is the separate row filed
beside this one.

Newly admitted, 44 name×width pairs, each disassembled (`wasm-dis`) to its single instruction
inside the getter and run: f64 and f32 `sqrt abs floor ceil trunc nearest min max copysign`;
i32 and i64 `clz ctz popcnt rotl rotr divU remU ltU leU gtU geU`; `f32bits f64bits f32fromBits
f64fromBits`. Fixtures: `tests/cases/getters/getter-scalar-intrinsics.vl` (all 44 plus the repro,
a brand read through `as!` and an un-annotated local), `getter-intrinsic-rejects.vl` (the
exclusions, one per family), `getter-intrinsic-traps.vl` (`divU` by zero traps in a getter), and
`tests/cases/modules/getter-intrinsic-module/` (a library getter calling `sqrt`/`min` beside an
entry `function min`).
