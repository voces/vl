### D3945 — a parameter and a function declared directly in the same body with the same name were both accepted

**closed 2026-10-10 by lane SC · now a loud check reject, by the owner's ruling · found in review of #3481 (`rv3481b/ord/o1f`, `x1`, `x1b`, `x1c`) · filed 2026-10-10 against master `00bf1871f` · pins: `tests/cases/functions/error-param-and-nested-function-same-name.vl`, `tests/cases/functions/param-shadowed-by-function-in-inner-scope.vl`**

Repro:

    function b(f: i32) {
      function f() { print("inner f") }
      f()
    }
    b(1)
    // vl check: rc 0 before the ruling (a direct call reached the nested function, an alias the parameter)

Want:

    redeclared f

#### Mechanism

The owner's ruling (2026-10-10): a parameter and a function declared directly in that function's
body bind one name twice in one scope, exactly as a `const f` redeclaring the parameter does, so
the checker refuses it with a duplicate-binding error naming both (`checkParamNestedFnClash`).
Before the ruling the two were accepted and resolved inconsistently: a direct call `f()` reached
the nested function while `const h = f` read the parameter. A function declared in a deeper
scope (an inner block, an inner function or a lambda body) may still shadow the parameter.
