### D3441 — a literal-holding binding delivered through an `if` arm, a `match` arm or `??` is not adopted, so it reads at its own width where the annotated twin reads at the record's

**closed · runs, prints `3.5` · was check-clean silently wrong, printing `3` · the adoption looks through a join's tails and both `??` operands · fixtures `tests/cases/soundness/record-literal-binding-adopts-through-join.vl`, `tests/cases/soundness/error-record-literal-join-at-two-record-destinations.vl` · found by the #3322 review (`rv3322-6397`) · filed 2026-09-30 against master `afb0ecc08`, closed 2026-09-30 by lane RC3**

Repro:

    type D = { v: f64 }
    const q = { v: 7 }
    const d: D = if true { q } else { { v: 2 } }
    print(q.v / 2)
    // PRINTS 3

Want:

    3.5

#### Mechanism

Owner ruling D3339 (A) makes a literal-holding binding delivered as a record that stores a field
at another width or kind adopt that record fully, so `const d: D = q` makes every read of `q`
an `f64` read and prints `3.5`, as `const q: D = { v: 7 }` does. The adoption is noted by
`recAdoptNote` (`compiler/typecheck.vl`), which peels only parentheses (`cwPeelValue`) before
it asks whether the source is a binding, an element of one, a call, or a literal. An `if` or
`match` arm and a `??` operand are delivered as join operands: the storage rule walks through
them and judges `q` fresh, so the delivery is accepted, but nothing notes `q` for adoption. The
value is built for `D` (`print(d.v / 2)` prints `3.5`), while `q`'s own reads stay `i32`
(`print(q.v / 2)` prints `3`). A write through `d` is refused by D2060's reads-only rule, where
the direct delivery adopts and admits it.

**Close (lane RC3).** `recAdoptNote` now walks a value `if`, `match` or block to its tails and a
`??` to both operands and adopts each literal binding it reaches; the list-widening walk
(`listWidenJoin`) judges each tail by its own origin, so a list-of-records field through a join is
fresh too. Two bindings joined together each adopt; one binding joined into one record and
delivered at another storage gets the two-demands refusal. Every spelling in the table below
now prints its twin's value (`q ?? q`, both arms, the assignment and argument faces, `i64`
prints `2147483648`, a write through `d` runs); the `f32` face is still refused, as its twin
is (the `else` literal joins as `{v: f32 | i32}`). A 312-cell grid over seventeen positions and
six field pairs agrees with the twin everywhere.

#### Ablation

All on master `afb0ecc08`; "twin" is the same program with `const q: D = { v: 7 }`.

| spelling | outcome | needed? |
| --- | --- | --- |
| the `if` removed (`const d: D = q`) | adopts, prints `3.5` like the twin | **yes** |
| `(q)` in place of the `if` | adopts, prints `3.5` | **yes**: parentheses are peeled, a join is not |
| a `match` arm (`match k { 1 => q, _ => ({ v: 2 }) }`) | prints `3`; twin `3.5` | no: same family |
| a `??` operand (`q ?? { v: 1.5 }`, or `q ?? q`) | prints `3`; twin `3.5` | no: same family |
| `q` in both arms (`if true { q } else { q }`) | prints `3` | no |
| `let d: D` then `d = if … { q } …` | prints `3` | no: assignment face |
| the `if` as an argument (`take(if … { q } …)`) | prints `7` then `3` | no: argument face |
| the `if` as a function's declared result | prints `3.5` twice | **yes**: the result position adopts |
| field `i64`, `q = { v: 2147483647 }`, `print(q.v + 1)` | prints `-2147483648`; twin `2147483648` | no: every width change |
| a write through `d` (`d.v = 0.5`) | loud check reject, "writes a widened field"; the direct delivery adopts and runs | no |
| field `f32` | loud check reject, "cannot assign {v: i32} to 'd'"; that is D3443's face | no |

The generic identity face (`const d: D = idd(q)`) is the same missing adoption, but at `f64`
it builds invalid wasm, so it is filed as D3442. At `i64` it runs and reads wrong like this
row: `q.v + 1` prints `-2147483648`, `d.v + 1` prints `2147483648`.
