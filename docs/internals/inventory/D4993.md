### D4993 — a `.map` callback over an `is K[]` arm's empty receiver of another element type is typed at the receiver's element

**check-clean invalid wasm · clause 1 · the callback face of [D4911](D4911.md) and [D4962](D4962.md) · pre-existing on master `358350b10`, identical output · a record pair (`is Q[]` over an empty `P[]`, `a.map((e) => e.y)`) is a loud emit reject instead (`unknown struct field in field access` on master, `.map/.filter scratch frame not reserved` after D4962) · filed 2026-10-15 against master `358350b10`**

Repro:

    type P = { x: i32 }
    function h<V>(a: V[]) {
      if a is f64[] {
        const ys = a.map((e) => e + 1.5)
        print(ys.length + 10)
      }
    }
    const pe: P[] = []
    h(pe)
    // vl run: the emitted module failed to validate inside `__lambda_1`: type mismatch:
    // expected f64, found (ref $type)

Want:

    10

#### Mechanism

Not ablated. The arm reads `a` as an empty `f64[]` (D4911), but the lifted callback's
parameter `e` is typed from the instance's own element, `P`, while its body is checked at
`f64`, so the lambda adds `1.5` to a struct ref. The list never iterates, so any callback the
arm hands it is dead code that still has to validate.
