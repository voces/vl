### D15030 — a void generic written to a `let` initialized with a generic returning a value traps when called through it

**closed · now a loud check reject, `cannot write 'inner' to 'k': called at (i32) it returns void, where 'retV', also written to it, returns i32` · DESIGN (owner ruling 2026-11-05, B2: a `let` seeded with a function that returns a value refuses a write of one that returns nothing; one seeded with a function that returns nothing takes a value-returning write, whose result its calls drop, and reading that result is refused) · was loads then traps · found grading D14785's close · filed 2026-11-02 against master `b4ffadefd`**

Repro:

    function inner<U>(u: U) { print("I"); print(u) }
    function retV<V>(v: V): V { print("R"); print(v); v }
    function main() {
      let k = retV
      k = inner
      k(3)
    }
    main()

Want:

    I
    3

#### Mechanism

Not probed. It is D3969 with the order of the two values reversed. Here the binding's type is the
initializer's `(V) => V`, and the void generic written to it is accepted. The call is lowered at a
signature returning `i32`, and `inner`'s instance returns nothing.

#### Ruling

Refused by design, owner ruling 2026-11-05, B2: a `let` seeded with a function that returns a value refuses a write of one that returns nothing; one seeded with a function that returns nothing takes a value-returning write, whose result its calls drop, and reading that result is refused. `holeLamRetAt` answers `HOLE_RET_VOID` for a function whose signature returns nothing, and `holeLetJudge` (check_relate_core.vl) refuses a write of one to a binding its initializer seeds with a function returning a value; the void-seeded order is one named condition (`voidSeedTakesValues`).
