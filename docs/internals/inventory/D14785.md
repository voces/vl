### D14785 — D3969's binding delivered to an annotated void function type is check-clean invalid wasm

**closed · now a loud check reject, `cannot write 'retV' to 'k': called at (i32) it returns i32, where 'inner', also written to it, returns void` · DESIGN (owner ruling 2026-11-05 (Q5, W-split): a `let` holding a function that returns nothing cannot be written with one that returns a value, or the other way round, in either order) · was check-clean invalid wasm, clause 1, then ran until the ruling · found closing D3969 · filed 2026-11-01 against master `3e63502cb`**

Repro:

    function inner<U>(u: U) { print("I"); print(u) }
    function retV<V>(v: V): V { print("R"); print(v); v }
    function main() {
      let k = inner
      k = retV
      const g: (n: i32) => void = k
      g(3)
    }
    main()

#### Mechanism

Two, by delivery. Read only at the delivery, `k` is a tagged set, and the checker's adapter calls
through it at `void | i32`, the join of `inner`'s and `retV`'s results. `emitFnTagDispatch` boxed
each member's result into that union, and `inner`'s call leaves nothing to box. Delivered into a
record field or a list element, `k` is a closure, and only the binding's own call noted `retV` for a
void twin (`monoNoteVoidTwin`), so the slot held `retV`'s `(i32) => i32` instance and the call
trapped. A twin minted at the slot's types also read its parameter as `i32`, since its synthesized
annotation has no type: at `f64` it converted an `f64` and failed to validate.

Closed by three changes. A call through a set whose type has a `void` member is a statement, and
each member's result is dropped. A write whose own closed stamp returns nothing notes the value for
a twin, as the binding's own call does. A pin read off an un-annotated parameter does not count:
its `void` result is a spelling, not a promise. And the twin's parameter reads take the instance's parameter type.

#### Ruling

Refused by design, owner ruling 2026-11-05 (Q5, W-split): a `let` holding a function that returns nothing cannot be written with one that returns a value, or the other way round, in either order. The annotated spelling already refused a void function written to a `let` whose type returns a value; `holeLetJudge` (check_relate_core.vl) now judges a member whose signature returns nothing as `void` against every member that returns a value, in both orders, so the hole and generic spellings agree with it (D15015).
