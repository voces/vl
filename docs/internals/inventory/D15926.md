### D15926 — a call through a function field of a returned list's records, of different results, builds an invalid module when a `const` binding elsewhere holds one of the functions and calls it

**loud emit reject · `emitProgram: this call runs functions that return different types, and one of them is also held where it cannot be stored as one of the functions this value may hold, so the call has no one signature` · clause 2 · open, target `4` `4` · built an invalid module until the emit floor of 2026-11-12 (`type mismatch: expected f64, found i32` in the top-level code, `vl check` clean, clause 1) · found closing [D15805](D15805.md), whose returned-list lift reaches it too · filed 2026-11-12 against master `22d35fe47`**

Repro:

    function inc0(a) { return a + 1 }
    function half(a) { return a / 2.0 }
    function pick(b: boolean) { if b { return [{ f: inc0 }] } return [{ f: half }] }
    print(pick(true)[0].f(3))
    const g = inc0
    print(g(3))

Want:

    4
    4

#### Mechanism

The one-result judge lifts the call through `pick()[].f` on the understanding that the tag
decision will tag the set `{inc0, half}`. Here it declines: a trap in `ftScan` fires at the
holder-context check (`ftHoldCtxOk`, check_fn_tag.vl, its `LetDecl` arm), for this program and
not for the control without the binding. The set stays a closure set, and the call lowered as a
`call_indirect` at `inc0`'s `i32` signature where its type is the join, `f64`. A probe in the
decision's refusal loop shows the early decision leaves the split call untagged with no owed
refusal in every invalid spelling, and in none that runs. The emitter now refuses such a call
where it is lowered (`emitCallRef`, wasmEmit.vl). The run-fix is the tag accepting the holder:
the declines seen are `ftHoldCtxOk`'s `LetDecl` arm (a called bound list) and `ftCtxOk`
(`const g = inc0`).
