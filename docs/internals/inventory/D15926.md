### D15926 — a call through a function field of a returned list's records, of different results, builds an invalid module when a `const` binding elsewhere holds one of the functions and calls it

**check-clean invalid wasm · `type mismatch: expected f64, found i32` in the module's top-level code, `vl check` reports 0 errors · clause 1 · open · on master · found closing [D15805](D15805.md), whose returned-list lift reaches it too · filed 2026-11-12 against master `22d35fe47`, re-run on `d303c9bcd`**

Repro:

    function inc0(a) { return a + 1 }
    function half(a) { return a / 2.0 }
    function pick(b: boolean) { if b { return [{ f: inc0 }] } return [{ f: half }] }
    print(pick(true)[0].f(3))
    const g = inc0
    print(g(3))

Want:

    4
    4

#### Mechanism

The one-result judge lifts the call through `pick()[].f` on the understanding that the tag
decision will tag the set `{inc0, half}`. Here it declines: a trap in `ftScan` fires at the
holder-context check (`ftHoldCtxOk`, check_fn_tag.vl, its `LetDecl` arm), for this program and
not for the control without the binding. The set stays a closure set, and the call lowers as a
`call_indirect` at `inc0`'s `i32` signature where its type is the join, `f64`.

#### Ablation

| spelling | outcome |
| --- | --- |
| the witness | invalid module |
| no second holder | runs, `4` |
| a bound list called, `const bs = [{ f: inc0 }]; bs[0].f(3)` | invalid module |
| that list, of `half`, or of both functions | invalid module |
| that list read for its `.length` only | runs |
| a bound record, `const o = { f: inc0 }; o.f(3)` | runs |
| a direct call, `inc0(3)` | runs |
| the binding holds a third function, `dbl` | runs |
| a record returned, not a list, `return { f: inc0 } … pick(true).f(3)` beside `bs` | invalid module |
