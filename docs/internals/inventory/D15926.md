### D15926 — a call through a function field of a returned list's records, of different results, builds an invalid module when a `const` binding elsewhere holds one of the functions and calls it

**closed 2026-11-12 · runs, prints `4` then `4` · was a loud emit reject from 2026-11-12 (D15926's floor), and before that check-clean invalid wasm, `type mismatch: expected f64, found i32` in the top-level code, clause 1 · found closing [D15805](D15805.md) · filed 2026-11-12 against master `22d35fe47` · fixed by a module `const` of a member counting as a direct call (`ftLocalAliasedFn`, check_fn_tag.vl), so the set is tagged, and by the module alias store holding the member's id (`emit_sections.vl`) · the bound-list holder stays refused: [D15928](D15928.md)**

Repro:

    function inc0(a) { return a + 1 }
    function half(a) { return a / 2.0 }
    function pick(b: boolean) { if b { return [{ f: inc0 }] } return [{ f: half }] }
    print(pick(true)[0].f(3))
    const g = inc0
    print(g(3))

Want:

    4
    4

#### Mechanism

The one-result judge lifts the call through `pick()[].f` on the understanding that the tag
decision will tag the set `{inc0, half}`. A module `const` of a member was not a direct call to
the decision (`ftLocalAliasedFn` resolved only a function-local one), so `g(3)`, noted through no
set, declined it at `ftCtxOk`, and the call lowered at `inc0`'s `i32` signature. A module `const`
of a member is now a direct call, so the set is tagged; the copy's slot is then the set's id,
which the module alias store (`emit_sections.vl`, as `emitLetDeclStmt` for a local one,
[D15927](D15927.md)) fills with the member's id, not its closure. The call stays direct.
