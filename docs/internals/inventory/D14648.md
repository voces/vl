### D14648 — a function list written through a parameter, re-pointed, returned by a call or held in a record field, or a map of functions written by index, is refused at check when the results differ

**loud check reject · `cannot write 'half' to an element of 'xs'` · clause 2 · open · the direct, pushed and aliased writes run ([D14645](D14645.md), [D14646](D14646.md), [D14647](D14647.md)), so the refusal is the gap under D3975 (A), not a design rule · found closing D14647 · filed 2026-10-29 against master `f56bdc49`**

Repro:

    function inc0(a) { return a + 1 }
    function half(a) { return a / 2.0 }
    function put(ys) { ys[0] = half }
    const xs = [inc0]
    put(xs)
    print(xs[0](3))
    // Want: 1.5

#### Mechanism

`elabFnListLetTy` (check_elab_cap.vl) widens only an un-annotated list binding initialised by a
list literal, over the writes through it and its aliases, and `holeSlotJudge` lifts its
comparison only for a binding so widened. Still refused at check, each measured 2026-10-29:

- a write through a parameter, `put(xs)` with `ys[0] = half` (the repro);
- a re-pointed `let`, `xs = [half]`;
- a list a call returns, `const xs = mk()` then `xs[0] = half`, or `mk()` returning `[inc0, half]`;
- a record's list field, `r.xs[0] = half`;
- a map written by index, `m["b"] = half`.

With the comparison lifted for every written element, the parameter write and the re-point
refused at emit, the record field built `ref valtype with no interned shape`, and the map index
write refused (`scalar map read has no value-box type`).

Lifting the comparison for a `Map()` whose `set` writes `elabSlotJoinTy` already joins makes
`m.set("a", inc0); m.set("b", half)` print `1.5` through `m.get("b")`, but `m.get("zz")` then
reads as present: the tagged map's `get` boxes the probe's entry with tag `0` whether or not the
key was found. The map spelling waits on that read, not only on the judge.
