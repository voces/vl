### D14648 — a function list written through a parameter, returned by a call or held in a record field, or a map of functions written by index, is refused when the results differ

**closed · runs, prints `1.5` · was loud emit reject, `the function written to this element returns another type than the element's` since the list veto went (#5898), and a loud check reject before that · clause 2 · the direct, pushed and aliased writes run ([D14645](D14645.md), [D14646](D14646.md), [D14647](D14647.md)) · found closing D14647 · filed 2026-10-29 against master `f56bdc49` · closed 2026-11-03: the write summary follows a list handed to a parameter into the callee's writes (`cwSlotParamWrites`), and the decision reads each recorded write as its member's leaf (`fnTagWriteLeavesOf`) where every call of the writer hands it a list widened to the set. The record field is [D15138](D15138.md), the map is [D15137](D15137.md), and an uncalled function handing the writer a list is [D15136](D15136.md)**

Repro:

    function inc0(a) { return a + 1 }
    function half(a) { return a / 2.0 }
    function put(ys) { ys[0] = half }
    const xs = [inc0]
    put(xs)
    print(xs[0](3))
    // Want: 1.5

#### Mechanism

Since #5898 a widened list keeps its widened set when the decision leaves it untagged (unless
that set holds a capturing lambda), so the check no longer re-types the list at its literal's set. The element handed to an un-annotated
parameter (`apply(xs[0], 3)`) runs, printing `1.5` (`closures/hole-fn-written-element-handed-to-param.vl`),
and the parameter write below passes check and is refused at emit instead.

`elabFnListLetTy` (check_elab_cap.vl) widens only an un-annotated list binding initialised by a
list literal, over the writes through it and its aliases, and `holeSlotJudge` lifts its
comparison only for a binding so widened. Still refused at check, each measured 2026-10-29:

- a write through a parameter, `put(xs)` with `ys[0] = half` (the repro);
  this refusal is the check's (`holeSlotJudge`), raised before any instance is elaborated, so
  a mint fact for a call through `ys[i]` (`elabMintFactAt`) cannot close it (measured
  2026-11-01 with callee-chain facts built: the program is still refused at check);
- a list a call returns, then written, `const xs = mk()` then `xs[0] = half`;
- a record's list field, `r.xs[0] = half`;
- a map written by index, `m["b"] = half`.

A re-pointed `let`, `xs = [half]`, runs since 2026-10-29: `cwLetRepointFnTargets` joins the
re-pointing literal's functions and the literal is built at the widened list. With the
comparison lifted for every written element, the parameter write refused at emit, the record field built `ref valtype with no interned shape`, and the map index
write refused (`scalar map read has no value-box type`).

Lifting the comparison for a `Map()` whose writes `elabSlotJoinTy` already joins (marking the
binding widened there, as `elabFnListLetTy` does) makes `m.set("a", inc0); m.set("b", half)`
print `1.5` through `m.get("b")`, and on master `c331ea8` a missing key reads `null` through
`get`, `has` and `for k, v in m`. The index read is what stays missing: `m["b"]` of the tagged
map routes to the scalar box (`emitMapGetScalarBox`, `scalar map read has no value-box type`),
and excluding a tagged value there gives `union atom has no value box`. So the map spelling
waits on an index read lowered as `get` is, and the lift has to wait with it, since it is
decided at the write, before any read is checked.

A call returning a list literal of such functions, `mk()` returning `[inc0, half]`, runs since
2026-10-29: the returned literal is read at each call's own tuple, as its inline spelling is
(`holeSlotRetApart`).

#### Close (2026-11-03)

Three links, each measured on the repro. The widened list's write summary did not see `ys[0] = half`
inside `put`; `cwSlotWritesInto` now follows each occurrence of the binding handed as an argument
to the parameter it binds (`cwSlotParamWrites`), so `xs`'s set is `{inc0, half}` as for the direct
write. The decision refused `put(xs)` as a holder context; a binding handed to a hole parameter
binds it to the binding's own type, so it is accepted (`ftHoldCtxOk`). And `half` had no leaf the
set typed, since its only occurrence is typed by `put`'s hole; the decision now takes the recorded
write as the leaf, typed as the list's element, without re-typing the callee's node. A second
caller handing `put` a list of closures is refused at emit as before, not built invalid.
