### D14648 — a function list written through a parameter, returned by a call or held in a record field, or a map of functions written by index, is refused at check when the results differ

**loud check reject · `cannot write 'half' to an element of 'xs'` · clause 2 · open · the direct, pushed and aliased writes run ([D14645](D14645.md), [D14646](D14646.md), [D14647](D14647.md)), so the refusal is the gap under D3975 (A), not a design rule · found closing D14647 · filed 2026-10-29 against master `f56bdc49`**

Repro:

    function inc0(a) { return a + 1 }
    function half(a) { return a / 2.0 }
    function put(ys) { ys[0] = half }
    const xs = [inc0]
    put(xs)
    print(xs[0](3))
    // Want: 1.5

#### Mechanism

`elabFnListLetTy` (check_elab_cap.vl) widens only an un-annotated list binding initialised by a
list literal, over the writes through it and its aliases, and `holeSlotJudge` lifts its
comparison only for a binding so widened. Still refused at check, each measured 2026-10-29:

- a write through a parameter, `put(xs)` with `ys[0] = half` (the repro);
  this refusal is the check's (`holeSlotJudge`), raised before any instance is elaborated, so
  a mint fact for a call through `ys[i]` (`elabMintFactAt`) cannot close it (measured
  2026-11-01 with callee-chain facts built: the program is still refused at check);
- a list a call returns, then written, `const xs = mk()` then `xs[0] = half`;
- a record's list field, `r.xs[0] = half`;
- a map written by index, `m["b"] = half`.

A re-pointed `let`, `xs = [half]`, runs since 2026-10-29: `cwLetRepointFnTargets` joins the
re-pointing literal's functions and the literal is built at the widened list. With the
comparison lifted for every written element, the parameter write refused at emit, the record field built `ref valtype with no interned shape`, and the map index
write refused (`scalar map read has no value-box type`).

Lifting the comparison for a `Map()` whose writes `elabSlotJoinTy` already joins (marking the
binding widened there, as `elabFnListLetTy` does) makes `m.set("a", inc0); m.set("b", half)`
print `1.5` through `m.get("b")`, and on master `c331ea8` a missing key reads `null` through
`get`, `has` and `for k, v in m`. The index read is what stays missing: `m["b"]` of the tagged
map routes to the scalar box (`emitMapGetScalarBox`, `scalar map read has no value-box type`),
and excluding a tagged value there gives `union atom has no value box`. So the map spelling
waits on an index read lowered as `get` is, and the lift has to wait with it, since it is
decided at the write, before any read is checked.

A call returning a list literal of such functions, `mk()` returning `[inc0, half]`, runs since
2026-10-29: the returned literal is read at each call's own tuple, as its inline spelling is
(`holeSlotRetApart`).
