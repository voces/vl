### D2479 — a UFCS call's callee-signature lookup shares one minted binding across sibling blocks' same-named closures of differing signature

**check-clean invalid wasm · clause 1 · found in review of #3148 against master `0a0d24ac9`, filed 2026-09-25**

Repro:

    function w(self: i32): i32 { self }
    function main() {
      {
        const w = (self: i32): i32 => self + 1
        print(5.w())
      }
      {
        const w = (self: string): string => self + "!"
        print("hi".w())
      }
    }
    main()
    // vl check: rc 0.  vl run: invalid module, inside `main`:
    // "type mismatch: expected (ref $type), found (ref $type)"

#### Mechanism

Not ablated to a rung. `5.w()`'s UFCS rewrite resolves the callee's signature through the same
family of binding rungs `calleeCloSigKeyAt` chases (D2316/D2325/D2326's `parentLetOfAt` and
siblings). Each block mints its own local `w` at a fresh position, but the SECOND call's lookup
answers with the FIRST block's closure — the `self: i32` signature is used to build the
`self: string` call's `call_ref`, and the two closures' distinct `$fnsig` types collide. A
module-level function named `w` is what makes `.w()` type-check as UFCS at all (D2068's `is not
a method` rung); it is scenery, not the ingredient.

#### Ablation

| ingredient removed | outcome | needed? |
| --- | --- | --- |
| the module-level function `w` | type error, `member access '.w' on non-object i32` | **yes** |
| the second sibling block (only the string closure and its call remain) | runs, prints `hi!` | **yes** |
| both blocks' closures typed `self: i32` (no differing signature) | runs, prints `6` then `7` | **yes** |
