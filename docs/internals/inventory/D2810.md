### D2810 — a value call whose function type has no `$fnsig` falls back to the all-i32 arity functype and calls a non-i32 argument at an i32 parameter

**closed 2026-09-27 — the filed repro is now a loud emit reject naming parameter 2, of type `{[string]:i32}|null`, where master built check-clean invalid wasm · closed by refusing the arity fallback when an untokened position has no derived i32 rep · filed 2026-09-27 against master `2bbc5c412` · the loud residue is the nullable-map token D2718 asks for**

Repro:

    function run(fn: (i32, {[string]: i32} | null) => i32, m: {[string]: i32}): i32 { fn(2, m) }
    print(1)
    // master: vl check rc 0; vl run: the emitted module failed to validate inside `run$m0`: type mismatch: expected i32, found (ref $type)

#### Mechanism

When `cloCallSigKey` finds no interned `$fnsig` for a value call, the emitter used to take
`fnSigIdxForArity`, the all-i32 functype of the call's arity, whenever one existed. The
arguments had already been pushed at their real valtypes, so any parameter that is not an
i32 (a nullable map here; a `v128` before D2811) made `call_indirect` invalid. The fallback
is now taken only when every untokened position is known to ride an i32 (`boolean | null`,
a derived `i32` rep); otherwise the call refuses and `cloCallSigRejectWhat` names the first
position with no token, replacing the old `function-value call arity has no interned
signature`.
