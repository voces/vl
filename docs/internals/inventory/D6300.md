### D6300 — a hole call's result added to a string, ill-typed at one of its instances, passes check and is refused at emit

**loud emit reject · `vl check` rc 0 · clause 2 · found closing [D6212](D6212.md) · the same on master `2ffbe1ed5` · filed 2026-10-18 against master `586fb1cf6`**

Repro:

    function id(a) { return a }
    function lap(g) {
      print("" + g(1))
      return g("s")
    }
    print(lap(id))
    // vl check: rc 0.  vl run: emitProgram: monomorphize: `g` is called at two instances of the function handed to it in a call to `lap`

Want:

    vl check: rc 1, operator '+' is not defined for string and i32

#### Mechanism

From the ablation only. At the `i32` instance, `"" + g(1)` is `"" + 1`, which the design refuses.
With `g` called at one type the checker judges the operator at that instance and refuses. With
two instances the operand stays a hole when the operator is judged, so the program passes check
and the split plan then has no instance to emit it at. The checker owes the refusal here, and a
fix should not make the program run.
