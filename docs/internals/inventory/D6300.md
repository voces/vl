### D6300 — a hole call's result added to a string, ill-typed at one of its instances, passes check and is refused at emit

**now a loud check reject, `operator '+' is not defined for string and i32 (in `lap`, at one of the instances it calls a function argument at)`, the direct spelling's sentence — fixed 2026-10-18 by lane L3: a hole called at two instances has each binary operator over its calls' results judged at each instance (`judgeHoleCallOps`), handed a declared function or a `const` lambda · was loud emit reject, clause 2 · pins: `tests/cases/functions/error-hole-call-binop-at-one-instance.vl` (the witness, a `const` lambda `id`, the `const a = g(1)` spelling) and `functions/hole-call-binop-two-instances.vl` (the `g(1) + 1` and `g("x") + g("y")` siblings run) · the `const lap = (g) => …` callee is filed as [D6330](D6330.md) · found closing [D6212](D6212.md) · filed 2026-10-18 against master `586fb1cf6`**

Repro:

    function id(a) { return a }
    function lap(g) {
      print("" + g(1))
      return g("s")
    }
    print(lap(id))
    // vl check: rc 1, operator '+' is not defined for string and i32 (in `lap`, at one of the instances it calls a function argument at)
    // was: vl check rc 0.  vl run: emitProgram: monomorphize: `g` is called at two instances of the function handed to it in a call to `lap`

Want:

    vl check: rc 1, operator '+' is not defined for string and i32

#### Mechanism

From the ablation only. At the `i32` instance, `"" + g(1)` is `"" + 1`, which the design refuses.
With `g` called at one type the checker judges the operator at that instance and refuses. With
two instances the operand stays a hole when the operator is judged, so the program passes check
and the split plan then has no instance to emit it at. The checker owes the refusal here, and a
fix should not make the program run.
