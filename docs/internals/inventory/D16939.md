### D16939 — record arms that share a box tag and differ only in a nested literal set are told apart by tag alone, so `is` answers the wrong arm

**closed 2026-11-17 · runs, prints `C` `A` · was check-clean silently wrong · clause 1 · two producers, both fixed: (1) a binding of one arm was boxed under the first row of its shape, so `C` values took `A`'s tag (`variantRowOfRead`, `compiler/emit_classify.vl`, now takes the arm whose member is the read's type first, `exactArmRowOfTy`); (2) the shared-row fit of `is` compared only top-level fields, and now ANDs on the literal sets of each nested record field that another member stored at the row declares differently (`emitSharedNestedFits`, `emitRecordLitMembership` in wasmEmit.vl, over `armRowSharedMembers`) · `samename-record-arms-nested-literal.matrix.vl` 34 WRONG cells now run, 66 of 66 · pin: `tests/cases/unions/record-arms-nested-literal-same-storage.vl` · found grading D4267's fix · filed 2026-11-17 against master `c97ab1fea`**

Repro:

    type A = { v: { x: 1 | 2 } }
    type C = { v: { x: 3 | 4 } }
    function f(u: A | C) {
      if u is A { print("A") } else { print("C") }
    }
    const c1: C = { v: { x: 3 } }
    f(c1)
    const a1: A = { v: { x: 1 } }
    f(a1)
    // vl check: no errors.  vl run: PRINTS A A

Want:

    C
    A

#### Mechanism

`A` and `C` store alike (`{ v: { x: i32 } }`), so they share one box tag. `u is A` is that tag,
then the membership half for fields the tag cannot settle (`emitVariantDiscrimTest`,
`variantDiscrimFieldNeeded` in `compiler/emit_map_twins.vl`). That half reads only TOP-LEVEL
literal-set fields (`variantFieldLitLexes`), so a literal set one record deeper is never compared,
and every `C` value tests as `A`. Under it, a `C` binding is boxed under `A`'s row, the first of
its shape (`variantRowOfRead` took `repVariantShapeRowOf` alone), so `u is C` misses it too.

#### Ablation

| change from the repro | outcome | needed? |
| --- | --- | --- |
