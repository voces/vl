### D16939 — record arms that share a box tag and differ only in a nested literal set are told apart by tag alone, so `is` answers the wrong arm

**check-clean silently wrong · clause 1 · found grading D4267's fix · filed 2026-11-17 against master `c97ab1fea`**

Repro:

    type A = { v: { x: 1 | 2 } }
    type C = { v: { x: 3 | 4 } }
    function f(u: A | C) {
      if u is A { print("A") } else { print("C") }
    }
    const c1: C = { v: { x: 3 } }
    f(c1)
    const a1: A = { v: { x: 1 } }
    f(a1)
    // vl check: no errors.  vl run: PRINTS A A

Want:

    C
    A

#### Mechanism

`A` and `C` store alike (`{ v: { x: i32 } }`), so they share one box tag. `u is A` is that tag,
then the membership half for fields the tag cannot settle (`emitVariantDiscrimTest`,
`variantDiscrimFieldNeeded` in `compiler/emit_map_twins.vl`). That half reads only TOP-LEVEL
literal-set fields (`variantFieldLitLexes`), so a literal set one record deeper is never compared,
and every `C` value tests as `A`.

#### Ablation

| change from the repro | outcome | needed? |
| --- | --- | --- |
| top level, `{ v: 1 \| 2 }` against `{ v: 3 \| 4 }` | right, prints `C` | **yes** (nested) |
| string literals, `{ v: { x: "a" } }` against `{ v: { x: "b" } }` | wrong, `A` | no |
| two records deep (`{ v: { w: { x: 1 } } }`) | wrong, `A` | no |
| beside a plain field (`k: i32` in both) | wrong, `A` | no |
| `C` has an extra field `z` (storage differs) | right, `C` | **yes** (a shared tag) |
| the nested record nullable in both arms | loud emit reject | — |
