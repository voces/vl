### D17842 — the redundant-annotation hint answers by `tyEq`, which tells two function types apart by their result rows' identity

**runs today and must keep running · refactor-blocking: under S2a's interning `vl check` adds a `redundant type annotation` hint on `v` that master does not give; master's annotation and inference mint different rows · filed 2026-11-28 against master `9ee417b8d` · owner COV-IS**

Repro:

    const src: i64[] = [6000000000, 42]
    const v: () => i64[] = () => (src)
    print(v()[1])

Want:

    42

#### Mechanism

The hint (`check_redundant_annot.vl`) fires when `tyEq(initTy, annot)` holds and no exemption
applies. On master the annotated `() => i64[]` and the inferred one render alike but `tyEq` holds them
apart, since their result lists are different rows; interning makes those one row and the hint fires.
Either `tyEq` reads a child's row identity where it means structure, or master's silence is the
accident and the new hint is right; the row's prep PR settles which, reading the annotation node
against the inferred type by the rule the hint states.
