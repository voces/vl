### D4067 — a binding annotated `: null` has no rep, while the un-annotated `const n = null` that the redundant-type hint calls the same has one

**open · loud emit reject (`vl check` rc 0; the build fails with `emitProgram: bare null needs a struct-typed context`) · clause 2 · found writing `docs/spec/diagnostics.md` (lane SPEC) · filed 2026-10-11 against master `98a4ed71b`**

Repro:

    const n: null = null
    print(1)
    // vl check: rc 0, a hint "redundant type annotation: `n` is inferred as `null`".
    // vl run: rc 1, emit error "emitProgram: bare null needs a struct-typed context"

Want:

    1

#### Mechanism

The checker accepts `null` as an annotation and agrees with the initializer, so the
redundant-type hint fires: the TYPES of the two spellings are equal. Their reps are not.
The un-annotated binding runs, as [D1576](D1576.md)'s unfilled `let x = null` does. The
annotated one reaches an emitter path that lowers a bare `null` only into a struct-typed
slot, so the refusal names the context rather than the type. Which emitter function makes
the split is not yet located. The hint advises a rewrite that changes whether the program
builds (here in the safe direction) and does not say so.

#### Ablation

| variant | outcome |
| --- | --- |
| the witness | emit refuses: bare null needs a struct-typed context |
| `print(n)` instead of `print(1)` | the same refusal |
| `let` instead of `const` | the same refusal |
| inside a function body | emit refuses: only i32 locals are supported |
| no annotation (`const n = null`) | runs |

#### Grading list

The un-annotated spelling must keep running. After the fix, the annotated `print(n)` must
print `null`, as the un-annotated one does today. `docs/spec/types.md` §T1.1 lists `null`
among the type names.
