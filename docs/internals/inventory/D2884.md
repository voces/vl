### D2884 — a nested lambda's call inside a hole-parameter function prints a `boolean` pin as `1`

**check-clean silently wrong · clause 1 · found working D2854 · the same on master `8e10ef58b` · filed 2026-09-27 against master `8e10ef58b`**

Repro:

    function mk(x) {
      const c = (y) => y
      print(c(x))
    }
    mk(true)
    mk(7)
    // vl check: rc 0.  vl run: prints `1` then `7`

Want:

    true
    7

#### Mechanism

Not localised. The call `c(x)` is typed at the lambda's own variable, which no instance binding
substitutes, so `print` reads the rep (`i32`) and not the type. `exprIsBool` answers through
`fnIndexOf` for a callee bound to a lambda, which the shared lambda's `fRetBool` serves only
when an earlier binding of the call (`const a = c(x)`) classified it. A per-instance clone of
the lambda ([D2854](D2854.md)) would not help: a clone is reached only through its value.
