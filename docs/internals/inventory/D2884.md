### D2884 — a nested lambda's call inside a hole-parameter function prints a `boolean` pin as `1`

**closed 2026-09-27 — the filed repro prints `true` then `7` · closed by typing each instance's own copy of the call at the instance's binding and holes ([D2854](D2854.md)) · found working D2854 · the same on master `8e10ef58b` · filed 2026-09-27 against master `8e10ef58b`**

Repro:

    function mk(x) {
      const c = (y) => y
      print(c(x))
    }
    mk(true)
    mk(7)
    // master: vl check rc 0.  vl run: prints `1` then `7`

Want:

    true
    7

#### Mechanism

The call `c(x)` is typed at the lambda's own variable, bound to the hole's, which no instance
binding substituted, so `print` read the rep (`i32`) and not the type. The instance's copy of
the call ([D2854](D2854.md)) is now recorded at the call's type substituted through the
instance's binding and then its holes (`monoLamCallTy`), which reads `boolean` here.
