### D2572 — a generic that binds a slice or filter of `[x, null]` and returns the binding builds the wrong list rep

**closed 2026-09-26 — the filed repro RUNS and prints `1` · was check-clean invalid wasm · clause 1 · pre-existing on master `dcc88a350` · found by #3174's review · filed 2026-09-26 · fixture `tests/cases/generics/nullable-literal-slice-bound-and-returned.vl`**

Repro:

    function g<T>(x: T) {
      const q = [null, x].slice(1)
      return q
    }
    const r = g("s")
    print(r.length)
    // vl check: rc 0.  vl run: invalid module inside `g`, "expected struct type at index 0,
    // found (array (mut i32))" (master: the engine fails to parse the module at all)

#### Mechanism

The generic is not an ingredient: `function g<T>(x: T, y: string)` binding a concrete
`const q: (string | null)[] = [null, y]` and returning it was invalid wasm the same way. An
instance whose un-annotated result is `return <local>` types that local by re-checking the body
at the pin (`monoInferListElem`), and annotated both the instance's return and the local with
the checker's RENDER of the list type, `(string | null)[]`. The annotation tables key a union on
the parser's spelling, `string|null`, so the spaced one read as a union-box list: the literal
built its `null` as a box no union row had collected. The rung now spells the list the way an
annotation would (`monoListSpelling`): a record element by its row's name (`(P|null)[]`), any
other element with the union unspaced.
