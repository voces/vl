### D16841 — a `?.` read over a value only ever `null`, bound to a name or through an annotated nullable, is refused at emit

**closed 2026-11-16 — the witness runs and prints `true` · was: loud emit reject · `` `?.` receiver is not a struct chain `` · clause 2 · `vl check` rc 0 · found closing [D16828](D16828.md) · filed 2026-11-16 against master `7eb37eae4`**

Repro:

    const a = null
    const v = a?.f
    print(v == null)
    // vl check: rc 0.  vl run: emit error, "emitProgram: `?.` receiver is not a struct chain"

Want:

    true

#### Mechanism

`const a = null` types `a` as a nullable of nothing (`nInner < 0`), not as `null`, so
`checkOptMemberRead` (`compiler/check_access.vl`) left the null-only ruling's branch unreached and
returned the error type with no diagnostic: the read was check-clean and error-typed, and its
binding's cell was an `i32`. That receiver now takes the ruling's branch, so the read is typed
`null` with the always-null hint. A `?.` call over it reads `null` too (`checkCallNodeGo`,
arguments still checked). `drwOptGuard` folds such a call off a name or field chain to `null`, or
to nothing as a statement; its guarded `null` stamp trapped the compiler on a minted node.
`emitOptMemberValueGo` answers a read off the `null` unit as its destination's `null`, and a
guard's dead arm calling through a receiver an instance types `null` is unreachable.
