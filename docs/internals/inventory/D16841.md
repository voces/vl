### D16841 — a `?.` read over a value only ever `null`, bound to a name or through an annotated nullable, is refused at emit

**loud emit reject · `` `?.` receiver is not a struct chain `` · clause 2 · `vl check` rc 0 · found closing [D16828](D16828.md) · filed 2026-11-16 against master `7eb37eae4`**

Repro:

    const a = null
    const v = a?.f
    print(v == null)
    // vl check: rc 0.  vl run: emit error, "emitProgram: `?.` receiver is not a struct chain"

Want:

    true

#### Mechanism

Not yet located. Under `??` the read folds to its fallback ([D16828](D16828.md)). Folding the bare
read to a `null` literal in the rewrite built an invalid module (`expected i32, found nullref`):
the binding's cell is classified off the read before the fold, so the null literal lands in an
`i32` cell.

#### Grading list

- An annotated `const n: { f: (x: i32) => i32 } | null = null`, `n?.f(2) ?? 0`: `union if-expression
  arm ends in a void call`; its read is not recorded as null-only.
- A `?.` call statement, `d?.h(t(5))`: `callee is not a function name`.
