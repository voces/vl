### D4290 — the field-closure receiver walk recurses without bound through a function whose argument is its own result

**closed 2026-10-13 · runs · was compiler trap · found porting `scripts/check-filed-witnesses.py` · filed 2026-10-13 against master `641b6f84d` · pins: `tests/cases/closures/member-call-tail-fed-its-own-result.vl`, `tests/cases/closures/member-call-tail-fed-its-own-result-no-function-value.vl`, `tests/cases/std/array-sorted-beside-member-call-tail-fed-its-own-result.vl`**

Repro:

    function a(s: string): string { s.slice(0, s.length) }
    const f = (x: i32) => x + 1
    print(f(1))
    print(a(a("xy")))
    // vl check: rc 0.  vl run: 2, then xy (trapped the compiler, call stack exhausted, before the fix)

#### Mechanism

Once any function value exists in the module, the emitter asks whether a member call's
receiver is a field closure. `fieldClosureFeOfRecvRaw` follows a parameter receiver to the
call site's argument (`fieldClosureFeOfRecv(arg, prop, -1)`, compiler/emit_classify.vl),
an argument that is a call to `fieldClosureFeOfInit`, then `fnRetExprOf` to the callee's
tail, which is the same member call on the same parameter. Nothing marks the walk as
visited, so `a(a(..))` loops until the stack runs out. `std:array`'s `sort` with a
comparator lambda was the ingredient in the ported script.

#### Ablation

| ingredient removed | outcome | needed? |
| --- | --- | --- |
| the lambda `f` (no function value in the module) | runs | **yes** |
| the member call in `a`'s tail (`{ s }`) | runs | **yes** |
| the self-call argument (`a(b("xy"))`, `b` returning `s`) | runs | **yes** |
| a literal argument (`a("xy")`) | runs | **yes** |
| the nesting (`const t = a("xy")` then `a(t)`) | still traps | no |

#### Grading list

The binding spelling above (`const t = a("xy")`, `print(a(t))`), and a mutual pair `a(b(..))`
with `b`'s tail `a(s)`; `scripts/check-filed-witnesses.vl` can go back to `std:array`'s
`sort` once this closes.

#### Fix

The cycle, read off a `--names` seed: `fieldClosureFeOfRecv(s)` → the hole-param arm →
argument `a("xy")` → `fieldClosureFeOfInit` → `fnRetExprOf(a)` → `stmtIsTailValue` (its D980
closure-field-call arm) → `fieldClosureFeOfRecv(s)`. `fieldClosureFeOfRecv` now keeps a stack
of the (receiver, function) pairs it is resolving and answers -1 for one already on it, so the
inner frame declines and the outer one finishes its own walk. Graded: the witness, the binding
spelling, return, record-field and list-element deliveries, an un-annotated `a`, the mutual
pair (ran before and after), a real field closure through a literal and through a maker (still
resolved), the no-function-value control (ran before and after), and `std:array`'s `sorted`
with a comparator, which trapped on master and now runs, including in #3602's script with its
hand merge sort replaced.
