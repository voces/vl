### D4290 — the field-closure receiver walk recurses without bound through a function whose argument is its own result

**compiler trap · filed 2026-10-13 against master `641b6f84d` · found porting `scripts/check-filed-witnesses.py`**

Repro:

    function a(s: string): string { s.slice(0, s.length) }
    const f = (x: i32) => x + 1
    print(f(1))
    print(a(a("xy")))
    // vl check: rc 0.  vl run: the compiler itself trapped (call stack exhausted)

#### Mechanism

Once any function value exists in the module, the emitter asks whether a member call's
receiver is a field closure. `fieldClosureFeOfRecvRaw` follows a parameter receiver to the
call site's argument (`fieldClosureFeOfRecv(arg, prop, -1)`, compiler/emit_classify.vl),
an argument that is a call to `fieldClosureFeOfInit`, then `fnRetExprOf` to the callee's
tail, which is the same member call on the same parameter. Nothing marks the walk as
visited, so `a(a(..))` loops until the stack runs out. `std:array`'s `sort` with a
comparator lambda was the ingredient in the ported script.

#### Ablation

| ingredient removed | outcome | needed? |
| --- | --- | --- |
| the lambda `f` (no function value in the module) | runs | **yes** |
| the member call in `a`'s tail (`{ s }`) | runs | **yes** |
| the self-call argument (`a(b("xy"))`, `b` returning `s`) | runs | **yes** |
| a literal argument (`a("xy")`) | runs | **yes** |
| the nesting (`const t = a("xy")` then `a(t)`) | still traps | no |

#### Grading list

The binding spelling above (`const t = a("xy")`, `print(a(t))`), and a mutual pair `a(b(..))`
with `b`'s tail `a(s)`; `scripts/check-filed-witnesses.vl` can go back to `std:array`'s
`sort` once this closes.
