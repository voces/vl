### D3388 — a generic that stores its parameter into a record field of another field storage builds invalid wasm where the direct spelling is refused

**closed 2026-09-30 · now a loud check reject at the pin · was check-clean invalid wasm, clause 1 · closed by lane NW with [D3250](D3250.md): a delivery is decided once per source type (`rcwPend` keyed on it), so the pin's `{h: I}` return into `H` is asked beside the template's and refused for the write `q.h.f = null`; the sentence is the widened-field one rather than the direct spelling's storage one · fixture `tests/cases/generics/error-type-param-record-store-widened-write.vl` · `q11` of the #3312 review's second round (`rv3312r2-q8m4/q/`) · filed 2026-09-30 against master `4ff12b994`**

Repro:

    type I = { f: i32 }
    type J = { f: i32 | null }
    type H = { h: J }
    const s: I = { f: 4 }
    function st<T>(v: T): H { { h: v } }
    const q = st(s)

    print(s.f + 1)
    // vl check: rc 0.  vl run: invalid module inside `st`: type mismatch: expected (ref null $type), found (ref $type) (exit 70)

#### Mechanism

Not traced. The direct spelling, `function st(v: I): H { { h: v } }`, is a check reject under
the record-covariance ruling (only a fresh record widens to a record that stores a field
differently: `I is not J … they store field f differently`). Through a type parameter the body
checks against the open `T`, and the pin at `T = I` does not re-ask the delivery of a non-fresh
`I` into the `J` field, so the instance lowers an `I` ref into the `J` slot. The expected
outcome is the direct spelling's check reject at the call, not a run.
