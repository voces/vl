### D16843 — the place classes draw no call-result edge from a closure a callee's instance makes, so a call through that closure's result reaches nothing

**loud emit reject · design row (slot store, D16768) · 1 fixture · filed 2026-11-16 against master `30a6da134`**

Repro:

    function same<T>(k: T): T { return k }
    function wrap<G>(g: G) { return () => g }
    function mid<F>(a: F) {
      const w = wrap(a)
      print(w()(3))
      print(a("x"))
    }
    mid(same)
    // vl run: emit error. master (the delivery walk): "monomorphize: parameter `a` of `mid` is
    // called at two function types that no parameter per type separates". With mono reading the
    // place classes: "a generic function taken as a value reaches no call that fixes its type".

#### Mechanism

`eplCallResultFlow` draws a call through a function value from each member's result place,
keyed `eplKeyOfFn(member)` under the call's instance. The member here is the lambda `() => g`,
made in `wrap`'s instance, a child of `mid`'s instance where `w()` runs; `eplKeyOfFn` looks only
among the calling instance's ancestors, finds none and draws nothing. So `w()(3)` is not a call
through `a`, and mono sees `a` called at one type. The refusal moves, it does not lift; the
fixture is `tests/cases/functions/error-generic-handed-to-bare-param-comes-back-in-returned-closure.vl`.

A first fix (the member flows from each instance of its frame the calling instance reaches) made
the compile of this program hang, and was reverted.
