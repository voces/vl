### D16843 — a generic handed to a bare parameter, called at a second type through a closure a callee's instance returns, is refused by mono's per-type split

**closed · clause 2 · the set the generic belongs to stays tagged through a callee that hands it back in a closure or a record field, so each call dispatches to its own instance · filed 2026-11-16 against master `30a6da134`, closed 2026-11-17**

Repro:

    function same<T>(k: T): T { return k }
    function wrap<G>(g: G) { return () => g }
    function mid<F>(a: F) {
      const w = wrap(a)
      print(w()(3))
      print(a("x"))
    }
    mid(same)

Want:

    3
    x

#### Mechanism

The per-type split of a handed generic is the tagged set: `mid` takes the set's member id and each
call through it dispatches to the member's instance at that call's types. A set holding a member
with type parameters is decided only after the elaboration, and was left a closure when the
parameter was read anywhere but as a callee or a hand-on: a read inside a nested function marked the
set partial (`elabMintHandedNested`), and a call whose callee was a call or a field had no complete
fact (`ftMintComplete`). One closure cannot serve two types, so mono refused. The fix treats a call
of a closure that only returns the parameter, and a record field a callee hands it back in, as reads
of the parameter where they stand (`handBackCallParam`, `handBackFieldParam`,
`compiler/check_hand_back.vl`), in both deciders.
