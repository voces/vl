### D4938 — `is K[]` over `K[] | J[]` with two string literal unions cannot tell one union's atoms from the other's

**closed 2026-10-15 — now prints `d` · was check-clean silently wrong value, clause 1 · both arms are atom lists under one box tag, so `is` now tests each atom against `K`'s literals, at every list depth · found by D2886's mechanism note · filed 2026-10-15 against master `c2dbf639e` · pin: `tests/cases/unions/two-atom-list-arms-is.vl`**

Repro:

    type K = "a" | "b"
    type J = "c" | "d"
    function mk(b: boolean): K[] | J[] {
      if b { return ["a"] }
      ["d"]
    }
    const w = mk(false)
    if w is K[] { print(w[0]) } else { print(w[0]) }
    // vl check: rc 0.  vl run: prints a

Want:

    d

#### Mechanism

An atom list holds interned atom ids whatever union they came from, so `K[]` and `J[]` box
under one tag and `is K[]` read only the tag: every `J[]` answered true, and the then-branch
printed the atom through `K`'s spelling. A tag cannot part them, since a `string[]` widened into
either is the same list; testing each atom against `K`'s literals does, as D4779 does for a
`string[]` arm.

#### Ablation

| ingredient changed | outcome | needed? |
| --- | --- | --- |
| `i32[] \| K[]` | prints the right arm (D4906) | **yes** (two atom lists) |
| `K[][] \| J[][]` with a `J[][]` argument | prints `K`, want `J` | no (any depth) |

#### Grading list

A parameter delivery `f(jl)` with `jl: J[]`, the two-layer `K[][] | J[][]`, and `is J[]` over
a `K[]` value.
