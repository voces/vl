### D8342 — `??` over a field of a hole parameter narrowed to a record that stores it nullable, where the stored row stores it flat, is refused at emit

**loud emit reject · `vl check` rc 0 · clause 2 · open · present on master `38ea07302` · the `argument` and `early_return_guard` un-annotated cells of `fresh-call-into-record-union-beside-declared-row` · filed 2026-10-20 against master `38ea07302`**

Repro:

    type Col = { r: i32, g: i32 }
    type J = { r: i32 | null, g: i32 }
    function mk() { { r: 15, g: 1 } }
    function take(a) {
      const v = a
      if v is J { print(v.r ?? 0) } else { print(0) }
    }
    take(mk())
    // vl check: rc 0.  vl run: emit error, "`??` over this nullable value is not supported yet"

Want:

    15

#### Mechanism

The instance's `v` is stored at the literal's row, which stores `r` as a flat `i32`. Inside the
`is J` branch the checker types `v.r` at `J`'s `i32 | null`, so the `??` reaches the emitter's
nullable arms, none of which matches a flat field, and the fall-through refuses
(`emitCoalesceNullableRefs`'s last `emitFail`, wasmEmit.vl). The annotated spelling `function take(a: Col)`
prints `15`: there the checker narrows to the meet, `Col`, and the `??` folds away. Before
[D8300](D8300.md) closed, the `early_return_guard` cell folded the test to false and printed `0`.

#### Ablation

| change | outcome | needed? |
| --- | --- | --- |

| `print(v.r)` in place of `v.r ?? 0` | prints `15` | **yes**, the `??` |
| `type J = { r: i32, g: i32 }` | prints `15` | **yes**, the wider field |
