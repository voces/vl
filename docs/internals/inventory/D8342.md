### D8342 — `??` over a field of a hole parameter narrowed to a record that stores it nullable, where the stored row stores it flat, is refused at emit

**closed · was loud emit reject, `vl check` rc 0, clause 2 · `emitCoalesceGo` (wasmEmit.vl) emits the field alone when the receiver's stored row holds it at the `??`'s own non-null scalar (`coalFieldStoredFlat`) · pinned by `tests/cases/generics/coalesce-flat-field-of-narrowed-hole.vl` and its `-annotated` twin, by the `argument` and `early_return_guard` un-annotated cells of `fresh-call-into-record-union-beside-declared-row`, and by all 64 cells of `coalesce-flat-field-through-generic` · filed 2026-10-20 against master `38ea07302`**

Repro:

    type Col = { r: i32, g: i32 }
    type J = { r: i32 | null, g: i32 }
    function mk() { { r: 15, g: 1 } }
    function take(a) {
      const v = a
      if v is J { print(v.r ?? 0) } else { print(0) }
    }
    take(mk())
    // vl check: rc 0.  vl run: prints 15 (was: emit error, "`??` over this nullable value is not supported yet")

Want:

    15

#### Mechanism

With `Col` declared, `mk()`'s literal is stored at `Col`'s row, which stores `r` as a flat `i32`.
Inside the `is J` branch the checker types `v.r` at `J`'s `i32 | null`, so the `??` reached the
emitter's nullable arms, none of which matches a flat field, and the fall-through refused
(`emitCoalesceNullableRefs`'s last `emitFail`). A field stored flat cannot be null whatever row
a narrowing typed the read at, so the close emits the field and drops the dead default. It does
this only when the stored field code, the `??`'s type and the default's type are one non-null
scalar (`i32`, `i64`, `f32`, `f64` or `string`). The annotated spelling `function take(a: Col)`
printed `15` before the close as well: there the checker narrows to the meet, `Col`, and the
`??` folds away.
