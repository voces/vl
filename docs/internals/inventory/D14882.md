### D14882 — an import's name list takes names with no comma between them

**check-clean silently wrong · the parser accepts `import { a b } from "./m"` and imports both names, where a list literal `[1 2]` is a parse error · pre-existing, the same on master `638ea22fe` · found in review of #5593, where two compiler imports had lost a comma · filed 2026-11-01 against master `638ea22fe`**

Repro:

    // file: m.vl
    export function a() { return 1 }
    export function b() { return 2 }
    // file: main.vl
    import { a b } from "./m"
    print(a() + b())
    // PRINTS 3

#### Mechanism

`parseImport` scans the statement token by token to the path string. Inside the braces every
`IDENT` becomes a name and every other token is skipped, so a comma is never required between two
names. The fix is to require one, so the list reads as the language's other comma lists do.

#### Ablation

| ingredient changed | outcome | needed? |
| --- | --- | --- |
| `import { a, b }` | prints `3` | **yes** (the missing comma) |
| `const xs = [1 2]` | a parse error: a comma is expected | no (the list literal requires it) |
