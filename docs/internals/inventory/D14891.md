Repro:

    type D = { v: f64 | string }
    const x: i32 | f64 | string = 3
    function mk() { return { v: x } }
    const o = mk()
    const d: D = o
    print(d.v)
    // vl check: rc 0.  vl run: invalid module inside `mk`

Want:

    3

#### Mechanism

The record solve builds `mk`'s literal at `D`, but no conversion re-boxes the field: `D` keeps
`i32` and `f64` as one `f64`, and the stored box keeps `x`'s own tag. The binding face,
`const o = { v: x }` delivered at `D` and read at its own type, is refused at the delivery
(D3011). The function face reaches no refusal. With
the result pinned at `D` (D3401's close, where no number merges) the program would trap on the
read's cast, so the close declines it and the signature still names the checked type.
