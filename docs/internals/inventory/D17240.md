### D17240 — a generic body's index over a lowered member call is re-made untyped by the pin pass, so legacy reads it at `i32`

**closed · was check-clean invalid wasm, 1 witness plus 2 spellings, at `f64` and `i64` elements · filed 2026-11-24 against master `18fcee51c` · closed by the pin pass typing every node it re-makes**

Repro:

    function rev<T>(self: T[]): T[] { return self }
    function e<T>(xs: T[]): T { return xs.rev()[0] }
    print(e([1.5, 2.5]))
    // was: vl check rc 0, vl run invalid module, inside `e`: type mismatch: expected i32, found f64

Want:

    1.5

#### Mechanism

`monoPinBinOps` (`emit_mono.vl`), the per-instance pin pass over a generic body, lowers the member
call `xs.rev()` to a direct call. That changes the kid of the `Index` around it, so the pass re-makes
the `Index` with a bare `mkIndex` and records no type. Its other rebuild arms (`Unary`, `Paren`,
`Member`, `OptMember`, `IsExpr`, `AsExpr`, `Spread`) do the same. `monoCloneGenericCalls`, by
contrast, carries a re-made node's template type. Legacy reads the untyped index at `i32`. That is
right for an `i32`, string, boolean or record element, but not for `f64` or `i64`. The IR misses
the same node as `rep ?`.

#### Ablation

| ingredient removed | outcome | needed? |
| --- | --- | --- |

| `f64` elements made `i32`, string, boolean or record | runs | **yes** |
| `[0]` spelled `(xs.rev())[0]` or `xs.rev()[i]` | still invalid | no |
