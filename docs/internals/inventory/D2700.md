### D2700 — an inferred return that joins a map and its nullable-ref twin declares one twin's struct and returns the other's

**check-clean invalid wasm · clause 1 · the `fnret` cells of the #3194 review's join grid for the
`str_strnul`, `circ_circnul` and `arr_arrnul` pairs · identical on master · filed 2026-09-26
against master `1a3088c65`**

Repro:

    function mk(): {[string]: string} {
      const m: {[string]: string} = Map()
      m["a"] = "x"
      return m
    }
    function mkw(): {[string]: string | null} {
      const m: {[string]: string | null} = Map()
      return m
    }
    function pick(c: boolean) {
      if c { mk() } else { mkw() }
    }
    print(pick(true).length)
    // vl check: rc 0.  vl run: invalid module in `pick`, "current function requires result type [(ref (id 6))] but callee returns [(ref (id 7))]"

#### Mechanism

Not yet measured. The two maps store alike, so the checker joins them to the wider map (D2666),
and a binding or a parameter typed at either takes the other's value. The inferred return is
the one place the emitted module keeps two struct types for the pair: `pick`'s result names one
and `mk`'s the other. The prediction is that the inferred return's valtype is read from the
wider map's own value slot rather than its canonical twin (`mvCanonRepOf`).
