Repro (`vl check` rc 0; `vl run` fails to compile the module in function `get`):

    const held: (i32) => i32 = (x: i32) => x + 1
    const get = () => held
    const v: (i32) => i32 = get()
    print(v(4))
    // vl check: rc 0.  vl run: WebAssembly translation error, function[5]::get
    //   type mismatch: expected i32, found (ref $type)

#### Mechanism

The capture of a MODULE-scope binding whose value is a CLOSURE is typed at the capturing
lambda's frame as an i32 — the same `captureValKind` default D1244 fixed for a module-scope
BLOCK local — so `get`'s body loads the fat pointer where an i32 is declared and the module
fails validation. D1244's close taught `parentBindingOf` the module frame's *block* locals;
a plain module-scope `const` holding a closure is the rung beside it, and this witness has no
block at all.

**The two faces land in different clauses, which is why the pair found it.** With `v`
annotated the module is emitted and is INVALID (clause 1). Drop the annotation on `v` — or on
`held` — and the same program becomes a loud emit reject instead (clause 2). Neither spelling
runs, and only the annotated one is silent.

#### The close

`exprIsClosureNoLocal`'s `Ident` arm walks `fnParent`, which is **−1 for a top-level lambda**,
so a module-scope `const get = () => held` fell through to the module-wide FUNCTION lookup —
and a lifted lambda is not named `held`. [D1542](D1542.md) gave that arm two rungs,
block-local before global, which is [D1244](D1244.md)'s rule one construct over.

**Nobody worked this row.** The standing witness gate reported it `silent_invalid_wasm → runs`
on a branch whose commits never name it, which is the whole argument for filing a defect as a
row with a runnable witness rather than as a note: a fix from another direction is graded
against it automatically, and the close costs one re-run.
