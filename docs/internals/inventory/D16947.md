### D16947 — a list-of-union field in a record a pin mints has no row its elements agree with

**loud emit reject · clause 2 · found grading [D2681](D2681.md) · filed 2026-11-17 against master `57e8ea94a`**

Repro:

    type IM = {[i32]: i32}
    function h<V>(x: IM) {
      const b: { v: (V | IM)[] } = { v: [x] }
      return b.v.length
    }
    const m: IM = Map()
    print(h<string>(m))
    // vl check: rc 0.  vl run: emitProgram: '.length' on a receiver the emitter cannot classify as a list, string, map or set

#### Mechanism

The record `{ v: (string | IM)[] }` exists only at the instance. D2681's fix gives a pinned record
a row of its own, but not one holding a list of such a union: that row's field would be a list of
union boxes while the literal `[x]` builds its elements bare, and the program would build invalid
wasm. Such a record keeps the literal's own row, which types the field as the literal's list, so
any read of the field through the annotation is refused.

#### Ablation

| ingredient removed | outcome | needed? |
| --- | --- | --- |
| the pin (the direct `{ v: (string \| IM)[] }`) | runs | **yes** |
| the record (a bare `(V \| IM)[]` let) | runs | **yes** |
| the map member (`(V \| i32)[]`) | prints `1` | **yes** |
| the read of `b.v` | prints `0` | **yes** |
| one level of nesting (`{ o: { v: (V \| IM)[] } }`, unread) | `nested-struct field element type is not interned` | no |
