### D14509 — a call stored into an un-annotated list keeps its record at its own row while another call of the same function delivers it as a declared record

**closed · now runs, prints `1` · was check-clean invalid wasm, clause 1 · filed 2026-10-27 against master `60e7acac2`, closed 2026-10-27 against `76227d1d5` · closed beside [D14518](D14518.md): the list literal is a container built where its stored values are (`recStoresAgree`), so `[mkcall()]` is served from the `Circle` build and the list's row is that build's (`arrLitRepElemRow`); the record-field and generic neighbours below stay open as [D14519](D14519.md) · fixture `lists/unannotated-list-call-element-built-at-wider-record.vl`**

Repro:

    type Circle = { r: i32 | null }
    function sink(_x: Circle) { }
    function mkcall() {
      const cc = { r: null }
      return cc
    }
    sink(mkcall())
    const xs = [mkcall()]
    print(xs.length)

Want:

    1

#### Mechanism

`sink(mkcall())` asks to build `mkcall`'s record at `Circle`. `recSitesLandAt` serves a second
call that is queued for no delivery only when that call is read for a field (`recReadInPlace`).
`[mkcall()]` stores the value, so nothing is adopted, the record keeps its own row, and the
`sink` delivery emits it where a `Circle` is expected. Both storages want the same `Circle`: the
list's element type is derived from the call, so it would follow the result if the result
settled first. `reverse([mkcall()])[0]` is the same shape, since `T` is bound by the argument.

#### Grading list

Corpus cell `b000498`, which is invalid with `objVariantNameCtx`'s scan ablated. `const xs:
Circle[] = [mkcall()]` is the annotated face of the same program. A field store is the same
defect: `const wideJ: J = mk()` beside `const w = { a: mk() }`, where `mk` returns `{ f: 4 }`
and `J = { f: i32 | null }`, is invalid wasm on the `const wideJ` line.

The build at `Circle` is the kept-function outcome (`recAdPushDecl`'s `FuncDecl` arm,
check_rec_rows.vl). The function's result stays typed at its own row at every call, and only
its body is built at `Circle`. So a stored call's container keeps the own row, and serving it
from the `Circle` build needs the result's type to change too. Dropping `recReadInPlace` alone
runs this repro, but it turns 13 cells of the `unlanded-call-beside-call-into-wider-record`
matrix silent, as D8302 recorded.
