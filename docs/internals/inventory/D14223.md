### D14223 — a function returning a list literal of two record shapes is delivered as a record list without adoption or refusal

**closed 2026-10-26 · runs, prints `true` · fixed by `recReturnedOrigins` (check_fit_rules.vl): when every value a single-site list function returns is a list literal its destination can store, each is built at the destination and the result is kept as that list (`recKeptFnPush`, read by `criKeptRetTy` in emit_closure_sites.vl); a mix of literals and bindings adopts neither · was check-clean invalid wasm · clause 1 · pin: `tests/cases/soundness/list-fresh-call-bare-literal-into-record-list.vl` · filed 2026-10-26 against master `32d371fef`**

Repro:

    type Cir2 = { c2: i32 }
    type Sq2 = { s2: i32 }
    type Shape2 = Cir2 | Sq2
    type Circle = { r: Shape2 }
    function mk() { [{ r: { c2: 1 } }, { r: { s2: 5 } }] }
    const g: Circle[] = mk()
    print(g[1].r is Sq2)
    // vl check: rc 0.  vl run: invalid module, expected `Circle[]`, found the union-box list

#### Mechanism

The checker accepts `({r: Cir2} | {r: Sq2})[]` into `Circle[]` at a call result, but adoption
only reaches a literal binding (D14224) and a function result of ONE record shape. The two-shape
result is built as a union-box list and delivered with no conversion. Its annotated twin
(`function mk(): (A | B)[]`) is refused by design (only a readonly list is covariant), so the
checker owes the same refusal here, or the result adopts as the one-shape result does.
