#### Mechanism

Three limits on one path, each answering the unsafe way when it ran out:

- `objShapeAdapterless` (`check_fit_rules.vl`) returns "no adapter" for a pair whose destination
  reaches an inference hole, asked as `tyReachesHole(dst, 8)`. That answers `true`, "reaches a
  hole", when its budget runs out, and a record seven levels deep spends the budget of 8 on its
  leaf. So the pair returned before the nested-width decision, and the module was built with the
  source's own record rows where the destination's are read.
- `objSrcReachesHoleFor`, the source half of the same guard, walked the record pairs eight
  levels and then fell back to `tyReachesHole(ft, 7)`.
- `recWidthFit` (`check_obj_shape.vl`), behind `recNestedWidthPair`, answered 0, "does not fit",
  after eight levels. That stopped depths eight and deeper once the first guard was fixed.

The close gives the guard `tyHoldsHole` (`tyquery.vl`), the same walk with a path of the unions
and records entered instead of a budget, and walks `objSrcReachesHoleFor` and `recWidthFit` on a
path of the source records. A cycle back to a record still on the path keeps the answer the
exhausted budget gave. Raising every `recordRepTyAdopt` budget to 64 did not move the witness, and
neither did lane AE4's D16731/D16732 branch.
