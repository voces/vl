### D2267 — a top-level `s ?? a` over a nullable string and a nullable record answers `is A` true for every value

**check-clean silently wrong · clause 1, wrong value · found by the #3088 round-2 review; the
same `is A` answers on master `bb0252d99` before #3088 · filed 2026-09-23 against master
`bb0252d99`**

Repro:

    type A = { r: i32 }
    function mkA(): A | null { return null }
    function mkS(): string | null { return null }
    function mkSq(): string | null { return "q" }
    const w = mkS() ?? mkA()
    const w2 = mkSq() ?? mkA()
    print("\{w is A} \{w2 is A}")
    // expected `false false` (`w` is null, `w2` is "q")
    // PRINTS true true

#### Mechanism

The same program inside a function answers `false` for both, so the defect is the module
global's storage class: the top-level binding of the `string | A | null` join reads `is A`
through a rung that does not test the box's tag. Before #3088 the null `w` also answered
`w == null` false; #3088's null-keeping box fixed that half and left `is A` as it was. A
prediction until a close names the rung.

#### Ablation

| ingredient removed | outcome | needed? |
| --- | --- | --- |
| module scope (the same bindings inside a function) | prints `false false` | **yes** |
| the null (`w2`, a present string) | still `true` | no |
