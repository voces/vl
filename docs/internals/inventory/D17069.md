### D17069 — a record whose row type is open only in a tagged function set was built off its row in the IR

**runs today and must keep running · 8 tests/cases programs in IR shadow `object field coercion` (corrected 2026-11-23 against master `9c7453e`; filed 2026-11-23 against `53f48d7`)**

Repro:

    function id1(a) { return a }
    function id2(a) { return a }
    let r = { f: id1 }
    r = { f: id2 }
    print(r.f(2))
    print(r.f(2.5))

Want:

    2
    2.5

#### Mechanism

Legacy stores a function field as an `i32` id exactly when the field's elaborated type is a tagged
set (`fnTagTyIsTagged`), a checker fact final before emit, so the storage is a function of the
row's recorded type. The literal's row records `{ f: <tagged set of id1, id2> }`, open because the
members are generic, and `objLit` refused to build at an open row type; it built at the literal's
own `{ f: typeof id1 }`, whose closure kid disagrees with the row's `i32`. `rowTyBuildsAt` builds at
the row when each open field is a tagged set the row stores as `i32`, or a nested record whose own
row does. As filed, this row named two other things: the generic `x: T` instance split (rows of a
generic record per instance, which the IR already matches) and the canonical key folding a tagged
and an untagged record type, which are two types.
