### D16112 — a read of a re-pointed generic `let` handed to a call keeps every function written to it, not the one its most recent write stored

**loud check reject · `argument 1: expected (boolean) => void, got (V) => void` · clause 2 · the flow-sensitive-read ruling permits it: `apply(k)` after `k = inner` hands `inner` · the call-argument face of [D15956](D15956.md) · filed 2026-11-14 against master `43943a5bf`**

Repro:

    function inner<U>(u: U) { print(u) }
    function plus<V>(v: V) { print(v + 1) }
    function apply(f: (b: boolean) => void) { f(true) }
    function main() {
      let k = plus
      k = inner
      apply(k)
    }
    main()
    // vl check: argument 1: expected (boolean) => void, got (V) => void

Want:

    true

#### Mechanism

D15956's close narrows a read only in a binding none of whose reads is a call argument
(`cwLetWritesStraight`, check_write_scan). A read handed to a generic parameter called at two
types, renamed to the generic, reached mono's one-closure refusal where the whole set does not
(`generic-fn-value-hole-written-binding-at-two-types.vl`). So a binding with such a read keeps
its whole set, and here `plus` is asked at `boolean`. `apply(inner)` runs.
