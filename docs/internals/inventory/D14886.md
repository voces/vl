### D14886 — a returned list of a function, read through `.map` inside a hole parameter's body, runs only through the split plan

**runs today and must keep running · refutation pin for retiring the split plan (inc3) · step 7's G2f · filed 2026-11-01 against master `5aacb348`**

Repro:

    function inc0(a) { return a + 1 }
    function deliver0() { return [inc0] }
    function take0(a) { print(a.map((f) => f(3))[0]) }
    take0(deliver0())
    print(deliver0().map((f) => f(1.25))[0])

Want:

    4
    2.25

#### Mechanism

Today the split plan builds a copy of `deliver0` per pin (`monoAskSplitRetCopies`, D9553). With the
plan off (`compileSrc` returning after its first compile), the program is refused at emit:
`cannot take the generic function inc0 as a value`.

The forward answer is D14823's: tag `{inc0}` so the list holds its id. The check's tag decision
refuses the set at the holder rule on `take0(deliver0())`, as it did for D14823. Only the decision
after the elaboration accepts that holder (`ftInnerLit`, #5700), and that decision runs only when
the elaboration recorded a per-instance call through a set (`elabMintFacts() > 0`). Here the call
through the set is `f(3)`, through a `.map` callback's parameter rather than `take0`'s own, so no
fact is minted and the late decision never runs. The fix mints that fact: a call through a builtin
callback's parameter whose receiver is the instance's set-holding parameter (`elabMintFactAt`,
`elabCalleeParam`), with `ftMintComplete` accepting it.

#### Ablation

| ingredient changed, split plan off | outcome | needed? |
| --- | --- | --- |
| `a[0](3)` for the `.map` in `take0` (D14823's shape) | runs | **yes** (the callback) |
| the split plan on | runs | **yes** (the plan) |

#### Built

The elaboration mints the fact for a call through a `.map` lambda's element parameter when the
receiver is a parameter of the instance holding a set (`elabMintCallbacksAt`), and that receiver
read no longer marks the set partial, provided the lambda reads its element only as a callee
that takes a fact. With the split plan off, the witness runs and prints `4` and `2.25`. So do
two members (`[inc0, dbl0]`), a capture of the element in a nested lambda, and two `.map`
calls at `i32` and `f64` in one body. Three spellings stay loud refusals with the plan off and
run with it: `a.map((f) => f)`, which hands the elements on; `a.filter(...)`, whose result
holds them; and a named callback, `a.map(cb)`. Fixture:
`tests/cases/closures/hole-fn-list-returned-mapped-in-hole-param.vl`.
