### D17012 — a generic helper returning an element of a list of un-annotated functions with different results is refused at check as a choice

**loud check reject · `cannot choose 'half' here: called at (i32) it returns f64, where 'inc0', also chosen here, returns i32 — every function a call through the choice may run must return one type` · clause 2 · open · the same element read without the helper runs · found tracing [D14433](D14433.md) · filed 2026-11-19 against master `0d005e72c`**

Repro:

    function inc0(x) { return x + 1 }
    function half(x) { return x / 2.0 }
    function pick<V>(xs: V[], i: i32): V { return xs[i] }
    const xs = [inc0, half]
    const h = pick(xs, 1)
    print(h(3))
    // vl check: cannot choose 'half' here: called at (i32) it returns f64, where 'inc0', also chosen here, returns i32 — every function a call through the choice may run must return one type

Want:

    1.5

#### Mechanism

Not traced. The refusal states a rule the read without the helper does not obey: `xs[1](3)` over
the same set runs, the set tagged so each member keeps its result type. Through the generic
helper the call is judged as a choice of functions that must share one result type.

#### Ablation

| spelling | outcome |
| --- | --- |
| the witness | check refuses |
| without the helper, `const h = xs[1]` | runs, `1.5` |
| called directly, `pick(xs, 1)(3)` | same refusal |
| one result type, `half(x) { return x / 2 }` | runs, `1` |
