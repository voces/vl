### D17037 — an order-stashed variant literal inside a list-literal argument is claimed without legacy's two stash locals

**runs today and must keep running · filed 2026-11-20 against master `6851d881` · armed shadow: `fail a claimable function did not match: bytes: prefix or locals`**

Repro:

    type V = { ov: i32 }
    type I = { oiRep: i32, oiBits: i64 }
    type S = { osAt: i32, osRep: i32 }
    type O = V | I | S
    function rep(): i32 { return 7 }
    function eff(xs: O[], k: i32): i32 { return xs.length + k }
    function f(a: O, n: i32): i32 {
      return eff([a, { ov: n }, { oiRep: rep(), oiBits: -1 }], 0)
    }
    print(f({ ov: 1 }, 2))
    // vl run: prints 3 claimed or not. $VL_IR_SHADOW=1: `f` covers and verifies, and does not
    // match: its locals vector is one i32 and one i64 shorter than legacy's.

Want:

    3

#### Mechanism

Legacy writes the variant literal `{ oiRep: rep(), oiBits: -1 }` at the list element through its
order stash and declares one scratch local per stashed field (an i32 and an i64). The IR builds
the same literal without those slots, so its claimed bytes declare two locals fewer. The output is
correct, and only byte identity with legacy is lost. The same shape is the self-compile's
`node-in array: differ` row in `irMapCompactFnCode` (`ir_helper.vl`,
`[seqs, i, { oiRep: I64(), oiBits: -1 }]`), and it keeps that function's `expression if ref
variant` from being admitted: admitting it covers the function with a locals mismatch.
