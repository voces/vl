### D12702 — a hole function looping over hole functions with a generic argument is refused when it is called at two value types

**loud emit reject · `vl check` rc 0 · clause 2 · CAPABILITY: one call `inner(0.5)` runs ([D10700](D10700.md)) · found closing [D10700](D10700.md) · filed 2026-10-25 against master `a448ccb42`**

Repro:

    function add(a, b) { return a + b }
    function apply2(g, s) {
      print(g(1, 2))
      print(g(s, s))
    }
    function apply3(g, s) {
      print(g(10, 20))
      print(g(s, 0.25))
    }
    function inner(k) {
      for f in [apply2, apply3] { f(add, k) }
    }
    inner(0.5)
    inner(3)
    // vl check: rc 0.  vl run: emitProgram: a generic function is passed to a function value whose parameter type names a type parameter this closure does not bind

Want:

    3
    1
    30
    0.75
    3
    6
    30
    3.25

#### Mechanism

Not traced. Each `inner` instance types its loop's elements at its own `k`, and the second
instance's elements take `add` at `(i32, f64)` where the first took `(f64, f64)`; the refusal is
the generic-function floor, reached after the element typing declines.
