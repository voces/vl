### D1470 — `__array_new_default__`'s element kind was hardcoded to the i32 list while the checker had already pinned it from the destination

**closed 2026-09-03 by reading the pinned element off the CALL node (`arrNewDefaultKind`), and
by giving the checker the two answers the call site could not have: an element with no zero is
refused, and an element nothing pins defaults to `i32` · was check-clean invalid wasm at every
non-`i32` element annotation, and `cannot infer a type for 'zs'` at the un-annotated spelling ·
clause 1 and clause 2 in one row · filed 2026-09-03 against master `f0c824a7`**

Repro (before the fix: `vl check` rc 0, then `Invalid input WebAssembly code … type mismatch:
expected (ref null $type), found (ref $type)`; now: prints `1.75`):

    const zs: f64[] = __array_new_default__(6)
    zs[0] = 1.5
    print(zs[0] + 0.25)

#### Mechanism

`arrNewIntrKind` answered `0` — the i32 list — for every `__array_new_default__` call, on the
stated ground that "its element kind is not derivable from the argument list; the host covers it
generically". True of the argument list, false of the CALL. The checker returns `mkArrayTy(-1)`
for the intrinsic and the destination then pins that hole IN PLACE (`constrainEmptyD`), exactly
as it pins an empty `[]` — so `nodeTyIxOf(callIx)` is already `f64[]` at the node the emitter is
lowering, and `emptyArrHoleKind` reads the identical type for the literal.

The two halves of the module therefore disagreed about the rep. The disassembly of the witness
is the whole defect in six lines: the global is declared `(ref null $f64ListWrapper)` and the
READ emits `array.get $f64arr` into `__print_f64__`, while the WRITE emits
`struct.new $i32ListWrapper (array.new_default $i32arr …)`.

`array.new_default` writes each slot's ZERO, so the honest domain is the elements that HAVE
one. `f64`/`i64` already had emit arms (kinds 1 and 4); `u8` and `f32` are two new kinds wired
in the collector and the lowering. Everything else — `string`, a struct, a closure, a map, a
nested list, a union, anything nullable — would get a WasmGC null or a niche sentinel that is
not a member of its own type, and is now a plain `tErr` naming that and pointing at
`__array_new__(n, fill)`. Both late answers are keyed by the CALL, in one pass at the end of
`checkProgram`, so they cover every delivery position rather than one gate per position.

**THE DEFAULT NEEDED A LINK BEFORE IT WAS SAFE, and the position matrix is what said so.**
`constrainEmptyD` writes `s.aElem = d.aElem` when the source is open — and when the
DESTINATION is open too that writes the `-1` back and loses the fact that the two rows must
agree. Nothing read that fact while an unpinned hole was an error; the moment it acquired a
default, `let a = __array_new_default__(3)` / `let b = …` / `b = a` / `b[0] = 1.25` defaulted
`a` to i32 while the store pinned `b` to f64 — a loud `cannot infer a type for 'a'` turned into
check-clean invalid wasm at `global_assign`, un-annotated. The pair is now recorded and read
once, at flush, before the default: 37 of 38 cells, no new silence.

#### Ablation
