### D14643 — a local map's cell took its type's rep slot where a module global's takes the shape its readers deliver

**closed 2026-10-29 · runs, prints the two lines below · was refused at build (`map values must be i32 / boolean`) inside a function while the same program ran at module scope · fixed: `letCellSlot` answers a `map` cell's shape from `letMapShapeOf`, the producer the module global's cell reads, before the binding's rep slot · pins: `tests/cases/maps/local-map-value-built-at-wider-record.vl` · filed 2026-10-29 against master `4b53baaec`**

Repro:

    type J = { f: i32 | null }
    function mk() { { f: 4 } }
    function main() {
      const wideJ: J = mk()
      const m = Map()
      const a = mk()
      m.set("a", a)
      const x = m.get("a")
      if x != null { print(x.f + 1) }
      print(wideJ.f ?? 0)
    }
    main()

Want:

    5
    4

#### Mechanism

The map's values are built at the wider record `J` because a binding of `mk()` is annotated
`J` (D14518), so the shape its stores and reads deliver is `J`'s map. The binding's type rep
claims the cell and its rep slot (`repMapSlotOfTy`) names no map for that shape, so the local's
cell had no value struct and the emitter refused. A module global's cell already read the shape
(`letMapShapeOf`). Found by comparing the global and local cell-slot producers over 17,265 files.

#### Ablation

| ingredient removed | outcome | needed? |
| --- | --- | --- |
| `const wideJ: J = mk()` | runs | **yes** |
| the enclosing function (module scope) | runs | **yes** |
