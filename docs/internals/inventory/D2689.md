### D2689 — a prefix `++`/`--` on a literal desugars to an assignment the checker never sees as one

**closed 2026-10-24 — now a loud check reject, `the operand of prefix `--` must be a variable, a field or an element` · was loud emit reject (`emitProgram: only an identifier assignment is a value expression`) on a `vl check`-clean program, clause 2 · DESIGN: the checker refuses an assignment whose target is not a name, a field or an element (`asgTargetIsPlace`, `check_operators.vl`); `--x`, `++xs[0]` and `--p.x` run · lane L3 · pin: `tests/cases/operators/error-assignment-target-not-a-place.vl` · found by the module-const fold's random A/B · filed 2026-09-26**

Repro:

    print(--5)
    // vl check: the operand of prefix `--` must be a variable, a field or an element

#### Mechanism

`parseUnary` desugars a prefix `++x` / `--x` to `x = x ± 1` whatever `x` is, where the postfix
form in `parsePostfix` refuses a non-identifier target with `postfix `--` target must be an
identifier`. So `--5` reaches the checker as `5 = 5 - 1`, which it does not refuse as an
assignment to a non-place, and the emitter's value-position assignment arm is the first to
notice the target is not an identifier.

#### Ablation

| ingredient removed | outcome | needed? |
| --- | --- | --- |
| the literal target (`let x = 5` then `--x`) | runs | **yes** |
| the value position (`--5` as a statement) | to grade | — |
| a `const` target instead (`--K`) | check reject `cannot reassign` | the literal is the hole |

#### Grading list

`++5`, `--(5)`, `--f()`, `--xs[0]` and `--p.x` as values and as statements: the postfix form's
diagnostic is the likely model, but whether a field or element target is a place is a ruling,
not something this row decides.
