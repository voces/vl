### D9171 — a `.map` callback that returns the element of a list of un-annotated functions leaves the functions un-instanced

**closed · runs, prints `8` · was loud emit reject, `emitProgram: cannot take the generic function inc0 as a value`, `vl check` rc 0 · clause 2 · found closing [D9093](D9093.md) · filed 2026-10-21 against master `c2df9510f` · closed by joining a `.map` lambda's result to the `.map` result's element in the flow (`ffMethod`, fn_flow_shadow.vl), recording the call's type as a list of the lambda's result (`monoCoerceListCbArg`, emit_mono.vl), and lowering a `.map` whose result element is a function (`mfListResultElemTy`, emit_classify.vl) · fixture `closures/fn-list-mapped-to-functions.vl` · [D9231](D9231.md) filed for a `.map` that builds new closures**

Repro:

    function inc0(a) { return a + 1 }
    const xs = [inc0]
    const gs = xs.map((f) => f)
    print(gs[0](7))
    // vl check rc 0.  vl run: prints 8

#### Mechanism

D9093's flow edge joins the callback's parameter to the receiver's element, but the
callback's RESULT was not joined to the `.map` result's element, so the call `gs[0](7)` pinned
nothing on `xs`. With the edge the list is pinned, and the `.map` call itself is recorded as
a list of the function type so its result can be indexed and called.
