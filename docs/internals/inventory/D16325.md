### D16325 — a record `is` narrowing a non-literal field, over a generic or un-annotated operand, is refused at emit

**closed 2026-11-16 — the witness runs and prints `true` · was: loud emit reject · ``emitProgram: `is` over a record tests a field that is not a literal set narrowed from the declared field, which has no lowering yet`` · clause 2 · bucket (c), L2 inferred interfaces: the operand's type is a hole or a type parameter, and annotating it runs · the annotated spelling runs since D4082's close · found closing D4082 · filed 2026-11-15 against master `5683d3b2c`**

Repro:

    type A = { x: i32 | string }
    type B = { x: i32 }
    function g<T>(a: T) { return a is B }
    const a: A = { x: 1 }
    print(g(a))

Want:

    true

#### Mechanism

The checker mints a record's per-field content check only over a concrete operand type
(`recFieldFitBuild` refuses a type with a type variable), so the instance's test reaches the
emitter's own record lowering, `emitRecordFitIs`, which covered literal-set fields only. An
un-annotated parameter (a hole) is the same shape. `recFitNarrowedFields` now lists every
narrowed field, and `emitRecordFitIs` tests a field narrowed to a type by its union box's arm
tags (`null`'s among them, and a variant arm that needs no discriminant), answering a null box
apart. A field whose storage is not a union box, or whose arm needs a discriminant, is still
refused, under its own sentence.

#### Ablation

On master `5683d3b2c` plus D4082's fix.
