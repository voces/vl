**closed — `collectInlineUnionsIn`'s statement ladder gains the `Block` arm the four block-BEARING statements already had, so a bare block's declarations register like any other scope's · was check-clean silently wrong (`vl check` rc 0, the module ran and printed the MISS branch) · 3 of 24 cells of the block x arm-type grid, and the two red cells of `matrix/map-arm-narrowed-read-methods.matrix.vl` · filed and closed 2026-09-07 against master `e61682fa5`**

#### Mechanism

`collectInlineUnionsIn` (`emit_collect.vl`) is the walk that registers every inline union
spelling before the emitter runs, and its statement ladder names `FuncDecl`, `LetDecl`,
`TypeDecl`, `IfStmt`, `WhileStmt`, `ForRange` and `ForIn` — the four block-BEARING statements
each hand their body to `collectInlineUnionsBlock`. A bare `{ … }` is a `Block` statement in
its own right, and the ladder walked straight past it, so its declarations were never visited.

Measured with the probe's own control firing, not read off the code path: an `emitFail` in the
`LetDecl` arm, gated on the annotation rendering with a `|`, prints
`PROBE collectInlineUnionsIn LetDecl reached: [{[string]:i32}|i32]` for the module-scope
spelling AND for the `if true { … }` one (the ladder has that arm), and did not fire at all for
the bare block at module scope or inside a function — those two compiled and printed `-1`.

The MAP arm is the only one that goes wrong, because it is the only one whose `is` test needs
the `uVariants` row: a `string` or `i32[]` arm resolves by its own rep. So the registry hole was
total and the visible damage was one arm type.

**It was the BARE BLOCK, not module scope.** [D1244](D1244.md), [D1751](D1751.md),
[D1861](D1861.md) and [D1862](D1862.md) are the module-block family — env rows and cells keyed
without the block frame — and this row is not one of them: the bare block inside a `function`
was wrong too. What they share is the shape [D1370](D1370.md) names, a ladder over a closed kind
set with a missing arm and a bare fall-through.
