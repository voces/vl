### D16616 — a maker's list of nullable records delivered at a wider nullable-record list builds an invalid module when the maker is called again

**closed 2026-11-15 — the witness runs and prints `1.25` · was: check-clean invalid wasm · clause 1 · found by lane J closing D16613 · filed 2026-11-15 against master `9a7f37ef3` · closed with D16613: a nullable-record pair is copied element by element, each null kept (`recListElemRecCopies`, check_fit_rules.vl; `emitRecListCopyTop`, wasmEmit.vl) · fixture `tests/cases/soundness/record-list-nullable-call-spread-beside-wider-part-runs.vl`**

Repro:

    function mk() { return [{ x: 1 }, null] }
    const v: ({ x: f64 } | null)[] = mk()
    print((v[0] ?? { x: 0.0 }).x + 0.25)
    mk()
    // was: vl check rc 0, vl run: invalid module, expected (ref $2), found (ref $5)

Want:

    1.25

#### Mechanism

A maker called more than once keeps its own record, so a delivery at a record storing a field
apart is a copy of its fresh result (`recFreshCallCopy`). The copy's element rule
(`recListElemRecCopies`) asked for a bare record destination, so a nullable-record list took no
copy and was delivered at its own storage: an invalid module. The rule now reads a nullable pair
by its records, and the list copy tests each element for null.
