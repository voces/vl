### D1624 — `vl fmt` produces invalid output for a function whose implicit tail is a bare lambda

**runs today and must keep running · filed 2026-09-05 against master `ef92ad0c`**

Repro:

    function mk() {
      (n: i32) => n + 4
    }
    print(mk()(40))
    // vl check: rc 0.  vl run: 44.

#### Mechanism

The witness above RUNS, and the status line says so, because the defect is in a tool
`check-filed-witnesses.py` does not drive: `vl fmt --check` on the same file prints
`formatter produced invalid output — file left unchanged, please report`. Filing it at any
`emit_reject`-shaped status would make the grader report a MOVED row on a program that behaves
exactly as filed, so the pin is the runnable half and this paragraph is the rest.

`vl fmt` re-parses its own output and compares. For this shape the round trip does not survive:
the printed form of a statement-position lambda with no `return` in front of it does not read
back as the same tree. Giving the tail a `return`, or binding it to a local and returning the
name, both format clean, so the ingredient is the bare lambda literal standing as the
implicit-return statement.

The refusal is a self-check, so it is loud and lossless — the file is left unchanged rather
than corrupted, which is the right failure. It does surface as a `vl fmt --check` line in
`lint-self.sh` for any file carrying the shape, so a fixture wanting this spelling cannot be
committed until it closes.

#### Ablation

Every row is `vl check` rc 0 and prints 44.

| spelling | `vl fmt --check` |
| --- | --- |
| `function mk() { (n: i32) => n + 4 }` | **invalid output** |
| `function mk() { return (n: i32) => n + 4 }` | clean |
| `function mk() { const f = (n: i32) => n + 4; f }` | clean |
| `function deliver() { mk() }` — an implicit-tail CALL | clean |

Needed: the implicit tail being a LAMBDA LITERAL. Not needed: the call around it, the arity,
the parameter type, or anything about the enclosing module.
