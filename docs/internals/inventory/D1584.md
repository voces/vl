### D1584 — an unpinned empty collection is a LOUD CHECK error at a binding and a positionless EMIT refusal in an object-literal field: the ladder has a rung the field position never got

**loud emit reject · found while grading [D1582](D1582.md)'s inferred face · reported by the glean session, VL-033's second half, `~/glean/docs/vl-issues.md` · filed 2026-09-04 against master `9ba97704`**

Repro:

    const s = { names: [], index: Map() }
    print(1)
    // vl check: rc 0, "Checked 1 file, no errors."
    // vl run:   emitProgram: ref valtype with no interned shape   (no file, no line, no column)

#### Mechanism

VL's rule for an empty collection literal is that something must PIN its element or value
type — an annotation, or a use. At a BINDING the checker enforces exactly that, with a
position and a remedy: `const xs = []` and `const m = Map()` both answer
`cannot infer a type for 'xs' — add a type annotation`. In an object-literal FIELD nothing
asks the question, so an unpinned `[]` or `Map()` passes `vl check` and reaches the
emitter, where the missing rep surfaces as `emitProgram: ref valtype with no interned
shape` — a sentence that names neither the field nor the file, and that reads as an
internal invariant rather than as the program's own missing annotation.

By CLAUDE.md's own reading this is a clause-2 violation whichever way it is resolved:
either the program is legal and should compile, or it is illegal and the CHECKER owed the
diagnosis. The binding rung says which — the program is illegal under VL's existing rule,
so the fix is the missing rung, not a new capability. The reason it is filed rather than
fixed is that the test has to run AFTER the whole program is checked: a field pinned by a
LATER use (`s.names.push("a")`) must not be refused, and that pin arrives during checking.

This is NOT [D1582](D1582.md)'s mechanism. The message named `Map` in the report, but the
ablation shows a `Map` is not an ingredient at all.

#### Ablation

| ingredient removed | outcome | needed? |
| --- | --- | --- |
| the `Map()` field (`{ names: [], n: 1 }`) | still refuses, same message | no — the map is scenery |
| the `[]` field (`{ index: Map() }`) | still refuses, same message | no — either empty collection alone does it |
| the object literal (`const xs = []`, `const m = Map()`) | LOUD CHECK reject with a position and a remedy | **yes** — the field position is the whole defect |
| a USE that pins the field (`s.names.push("a")`, `s.index.set("k", 1)`) | runs | **yes** — the pin is what is missing, not the field |
| an annotation on the binding | runs | **yes** — same |
| the object literal is a function's inferred RETURN (`function mk() { { index: Map(), n: 1 } }`) | refuses the same way when unpinned, runs when used | no — the return position inherits it |

#### Grading list

* The witness above, plus the six ablation rows — the two that must stay LOUD CHECK
  rejects (bare `const xs = []` / `const m = Map()`) are the shape any fix has to reuse.
* The reporter's larger form, `{ names: [], index: Map() }` used as a name interner, and
  the minimal `{ index: Map(), n: 1 }` + `.set` + read, which RUNS today and must keep
  running.
