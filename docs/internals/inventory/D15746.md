### D15746 — a `const` copy of a copy of a hole lambda's bundle, handed to a parameter called at two types, is refused by mono

**closed 2026-11-12, runs and prints `5` `2.5` · was loud emit reject, clause 2, `monomorphize: unsupported argument type for \`b\` in a call to \`take\`` · found closing [D15741](D15741.md) · closed in the elaboration: a `const` copy of a copy may hold a record (`elabResMayHoldAt`, emit_elab.vl), and a holder's copies are walked through copies of copies (`elabCopiesDeep`), each counting its own copies among its reads · fixture `tests/cases/closures/hole-lambda-bundle-copy-of-copy-handed.vl`**

Repro:

    function lap(f) {
      f(2.5)
      f(3)
      return f
    }
    function take(b) {
      print(b(4))
      print(b(1.5))
    }
    const c = lap((a) => a + 1)
    const v = c
    const u = v
    take(u)

Want:

    5
    2.5

#### Mechanism

A copy may hold a record only when its source is a parameter or a call-initialised holder
(`elabResMayHold`), so a copy of a copy was no copy at all, and the holder's copy that it read
had an unaccounted read, which refused the whole group.

#### Ablation

| spelling | outcome | needed? |
| --- | --- | --- |
| `take(v)` | runs (D15741) | **yes** |
| `const u = v` called directly at both signatures | refused on master, runs | no |
| three copies deep, `take(t)` | refused on master, runs | no |
| the chain inside a function, or its last copy inside a lambda | refused on master, runs | no |
