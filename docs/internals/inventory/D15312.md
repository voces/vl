### D15312 — a `??` default for a read built wider, placed in a list or record literal, is built at the literal's own row

**open · check-clean invalid wasm · `type mismatch: expected (ref null $type), found (ref $type)` · clause 1 · the `array_element` and `struct_field_init` cells of `coalesce-built-read-held-call-default` · found grading D15240 · filed 2026-11-04 against master `ddb0573bc`**

Repro:

    type J = { f: i32 | null }
    function mk() { { f: 4 } }
    const m = Map()
    m.set("a", mk())
    const wm: {[string]: J} = Map()
    wm.set("a", mk())
    const xs = [m.get("a") ?? { f: 1 }]
    print(xs[0].f ?? 0)

Want:

    4

#### Mechanism

The store column builds a `??` join at the read's record where it initialises a binding
(`storeHeldAt`), but a list or record literal holding the join is typed at the default's own row
and its element is stored there. A literal default, a held one and a call behave the same. Through a
binding (`const b = m.get("a") ?? d; const xs = [b]`) it is an emit refusal instead.

#### Ablation

| ingredient removed | outcome | needed? |
| --- | --- | --- |
| the list (`const b = m.get("a") ?? { f: 1 }`) | runs (D15217) | **yes** |
| the `??` (`[r]` for a narrowed read `r`) | runs | **yes** |
| a record literal `{ g: … }` instead of the list | still invalid wasm | no |
