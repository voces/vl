### D17072 — the IR builds a shared read of a tag both union arms spell as one literal at `string` where legacy reads its atom

**runs today and must keep running · an IR coverage defect · filed 2026-11-23 against master `d699cfc48` by lane IR-N8**

Repro:

    type KC = "circle"
    type Cs = { kind: KC, r: f64 }
    type Rs = { kind: KC, w: f64 }
    function tagS(s: Cs | Rs) { print(s.kind) }
    tagS({ kind: "circle", r: 1.0 })
    tagS({ kind: "circle", w: 2.0 })
    // VL_IR_SHADOW=1 vl build: `tagS` is `uncovered print operand rep`

Want:

    circle
    circle

#### Mechanism

Over the un-narrowed `Cs | Rs` box, legacy's `exprIsLitAtom` claims the field read as an atom
through `sharedUnionFieldPlan`, so `print` takes its `atom` arm. The IR's shared-read arm in
`ir_build_ref.vl` builds `RSharedRead` only at the node type's rep, and the type `"circle"` reps as
`string`. The fix is `exprRepOf` agreeing with legacy's atom claim on this read, a rep-layer change.
