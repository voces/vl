### D17740 — a module `let` of a tagged set of generic functions, rewritten and read in a function, calls its first member

**check-clean silently wrong · clause 1 · open · `vl check` rc 0 · prints `3` where `1` is right · found grading the shared-member family rule ([D17739](D17739.md)), where `closures/global-let-of-generic-reassigned-called-from-a-function.vl` printed `3 3` · filed 2026-11-27 against master `2cd65b2e3` by I8-PREP**

Repro:

    function addT<T>(a: T, b: T) { return a + b }
    function first<T>(a: T, b: T) { return a }
    const _fs = [addT, first]
    function useK() { print(k(1, 2)) }
    let k = addT
    k = first
    useK()
    // vl check: rc 0.  vl run: prints 3

Want:

    1

#### Mechanism

Not traced past this: the list literal `[addT, first]` tags the set `{addT, first}` as ids, so
`k` holds an id; the call through `k` in `useK` dispatches `addT` after the write `k = first`.
Without the list the set stays a closure and the program prints `1`.

#### Ablation

| ingredient removed | outcome | needed? |
| --- | --- | --- |
| the list `const _fs = [addT, first]` | prints `1` | **yes** (the tagged set) |
| `useK`, `k(1, 2)` read at module scope | prints `1` | **yes** (the read in a function) |
| `addT`, `first` declared `(a: i32, b: i32): i32` | prints `1` | **yes** (the generic members) |
| a call `useK()` before the write | still prints `3` after it | no |
