### D3080 — a generic passed as a function value to a typed parameter is never held to its deferred constraints

**check-clean invalid wasm · clause 1 · open · found by the review of [D3062](D3062.md)'s close · the same on master `e1e40ac99` · filed 2026-09-28 against master `e1e40ac99`**

Repro:

    type R = { a: i32 }
    function show<T>(x: T) { print(x) }
    function hof(f: (R) => void) { f({ a: 1 }) }
    hof(show)
    // vl check: rc 0.  vl run: invalid module inside `show`

#### Mechanism

A generic's deferred constraints are adjudicated only at a call that names it. Delivered as a
value to a `(R) => void` destination, `show` is instantiated at `T = R`, but no call site binds
`T`, so the `print` constraint its body recorded is never validated and the instance prints a
record. Called directly, `show({ a: 1 })` is refused, and the non-generic `function show(x: R)`
is refused at its own `print`.

#### Ablation

| ingredient changed | outcome | needed? |
| --- | --- | --- |
| `show({ a: 1 })` called directly | check reject | **yes** (a function value) |
| `function show(x: R)`, not generic | check reject | **yes** (the type parameter) |
| `show` declared after `hof(show)` | invalid wasm | no |
| a record-field destination `{ f: (R) => void }` | invalid wasm | no |

#### Grading list

The review's `m/` probes: a field of a record type, a lambda forwarding to the generic, and a
module-imported generic, each at both declaration orders.
