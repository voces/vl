### D2506 — an un-annotated map parameter pinned only by a `null` write infers the value type `null`

**loud check reject · pre-existing on master `d29a9d220`, at every key rep · found by the
`argument` un-annotated cell of `i64-keyed-map-in-container-nullable.matrix.vl` ([D2505](D2505.md))
· filed 2026-09-25 against master `d29a9d220`**

Repro:

    function use(v) {
      v.set("b", null)
      print(v.has("b"))
    }
    const m: {[string]: string | null} = Map()
    use(m)
    // vl check: argument 1: expected {[string]: null}, got {[string]: string | null}

#### Mechanism

The body's only write to the parameter's value hole is a bare `null`, and the pin takes it as
the whole value type, so the parameter becomes `{[string]: null}` and the call site's map, whose
value type is `string | null`, is refused by map invariance. The annotated twin
(`function use(v: {[string]: string | null})`) runs. Whether a `null`-only pin should leave the
value hole open to the call site's type, as other null holes do, is a question about the
inference rule; this row records the witness and makes no ruling.

**Ruling asked (2026-09-25, lane V): what does a map value hole whose only write is `null`
infer?** The same rule already disagrees with itself: a LIST parameter pinned by `v.push(null)`
passes `vl check` against a `(string | null)[]` argument ([D2524](D2524.md)), and a local
`const m = Map(); m["a"] = null; m["b"] = "s"` refuses `cannot assign string to null | null`.
Recommendation: a `null`-only write pins the hole to `T | null` with `T` still open — A-infer-null's
rule for `let x = null` — so the call site (or a later write) fills `T`, and a hole no write
fills stays the `null` type. The alternative, refusing the un-annotated parameter with a
request for its annotation, keeps the checker simpler and costs every such caller an annotation.

#### Ablation

| ingredient removed | outcome | needed? |
| --- | --- | --- |
| `v`'s annotation added | prints `true` | **yes** — the inferred face |
| `v.set("b", null)` replaced by `v.set("b", "x")` | refuses `expected {[string]: string}` | no — invariance, a non-null pin |
| the key `string` replaced by `i32` or `i64` | still refuses | no |
