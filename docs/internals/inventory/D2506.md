Repro:

    function use(v) {
      v.set("b", null)
      print(v.has("b"))
    }
    const m: {[string]: string | null} = Map()
    use(m)
    // vl check: argument 1: expected {[string]: null}, got {[string]: string | null}

#### Mechanism

A write of a bare `null` into an open container slot (`.push`, `.set`, `m[k] = v`, `xs[i] = v`)
pinned the element or value to the `null` type, so every later write of a `T` was refused
(`push: cannot add i32 to null[]`, `set: expected null, got string`, `cannot assign i32 to
null | null`) and a hole parameter's map demand refused its caller's `T | null` by invariance.
Ruling (a): the null write pins `T | null` with `T` open, A-infer-null's rule for `let x = null`.
The checker now mints an open `_ | null` at that pin (`cnhPinTy`) and records it; a later write
fills `T` in place from its non-null part (`cnhFill`, at all four write spellings), and so does
a nullable destination the container is delivered to (`constrainEmptyD`: an argument, a return
annotation, an annotated binding). A hole parameter's map demand takes each call site's own
nullable value type (`holeMapNullValAt`), an open map or list argument takes an open hole of its
own (`holeMapArgNullPin`, `cnhPinBmElem`), and a hole nothing fills is refused at the end of
the check with one sentence, `the element type of `xs` is only ever null — annotate it` (the
value type, for a map). On the emit side, an empty `[]` whose element is a nullable ref interns
that row in `collectA`, and its synthesized annotation takes the nominal spelling of a nullable
record (`arrLitNulRefElemName`) ahead of the structural one, so every reader names one row;
a hole parameter's instance pins that same nominal row (`nulRecListNominalName`).

An open hole written into another open hole (`xs.push(x)` with `let x = null`, `x = xs[0]`,
`xs.push(ys[0])`, `m.set(k, xs[0])`) LINKS the two (`nhLink`), and a fill of either fills both
(`nhFillLinked`), so a later write that disagrees is refused at the type the first fill chose.
Filled separately, the two took different types and the list stored one hole's box as the
other's element: check-clean invalid wasm, found in review of #3188 before it merged.

The order matters and is not reversed: a write of `T` FIRST pins `T`, and a later `null` is
refused (`push: cannot add null to i32[]`), exactly as `let x = 3` then `x = null` is. That is
the ruling's scope as written; widening a pinned `T` to `T | null` in place would re-type every
read already checked at `T`.

#### Ablation
