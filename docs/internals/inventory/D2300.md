### D2300 — a generic `[x]` with no return annotation builds its list at the wrong rep for every non-`i32` `T`

**closed 2026-09-24 — the witness prints `3` · was a loud emit reject (`struct array elements are not
supported`), and check-clean invalid wasm at `T = f64[]` · found in review of the list-rep campaign · filed
2026-09-24 against master `a295cf301` · fixture `tests/cases/generics/generic-list-literal-inferred-return.vl`**

Repro:

    type Circle = { r: i32 }
    function wrap<T>(x: T) { return [x] }
    const c: Circle = { r: 3 }
    print(wrap(c)[0].r)
    // vl check: rc 0.
    // vl run: emit error, `emitProgram: struct array elements are not supported` at `wrap(c)[0]`.

#### Close

The instance's return was never inferred. `emit_mono`'s return ladder ends in
`monoInferRetExprTy`, which re-checks the return expression at the pin but answered only for a
primitive or a record, so `[x]` fell to the functype's `i32` default at every pin: an `i32` list
where the body built a `Circle` or `f64[]` one. It now answers a list too, spelled by
`tyToEmitName`, and a list whose leaf is a record is minted by the record's row name, as the
record arm already was, so `(wrap(c1[0]) + c1).length` resolves its element. Each instance
carries its own return, which also closes the in-company shape: the three `f64`/`string`/`i32`
calls and the `idg` trio run in one module.

#### Mechanism

Not located. Every spelling below runs once the return is annotated `: T[]`, so the missing
ingredient is the inferred return: the monomorphized body's `[x]` and the caller's read of the
result do not agree on the list rep a non-`i32` `T` produces. The reviewer's original,
`(wrap(c1[0]) + c1)` over `c1: Circle[]`, refuses at the read of the concatenation for the same
reason; the concat is scenery. A second shape needs several instances in one module: `T` at
`f64`, `string` and `i32` together refuses with `f64 array literal but f64 list type not
collected` at the `i32` call, while each instance alone runs, so a per-instance answer leaks
across instantiations. Unchanged by D2295's code-table work.

#### Ablation

| ingredient changed | outcome | needed? |
| --- | --- | --- |
| `function wrap<T>(x: T): T[]` (return annotated) | runs, `3` | **yes** |
| a non-generic `function wrap(x: Circle)` | runs | **yes** |
| `(wrap(c1[0]) + c1).length` over `c1: Circle[]` | same emit reject | no |

| any one of those three alone | runs | **yes** (the company) |

#### Grading list

The three neighbour spellings above, each with and without `: T[]`; the same `function idg<A>(x:
A) { return [x] }` at `i32`, `Circle[]` and `f64[]` in one module (a loud emit reject, `nested
arrays are not supported`, today); and `regress.py`'s shared oracle, since the in-company shape
is invisible to a one-program CLI check.
