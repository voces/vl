### D17120 — an assignment of `null` to an inferred `let n = null` binding, read as a value by `print` or `==`, is not taken as the `null` unit

**fixed 2026-11-24 · closed, runs `null` · was: check-clean invalid wasm · clause 1 · filed 2026-11-24 against master `9ac05ddb` by IR-N9 · fixed by `asgYieldsNullLit` (emit_classify.vl) taking the never-filled hole `TyNullable(-1)` as `null`, and `nulTestArmOf` (emit_plan_null.vl) taking such an assignment's null test as `nullty` · fixture `null/print-an-assignment-of-null-to-an-unfilled-let-null.vl`**

Repro:

    function main() {
      let n = null
      print(n = null)
    }
    main()
    // vl check: no errors.  vl run: invalid module, type mismatch: expected i32, found nullref

Want:

    null

#### Mechanism

`printArmOf` asks `boxOperandIsNulNone`, whose assignment half (`asgYieldsNullLit`) answers only
when the checker typed the assignment `null`. With the binding's type inferred from `let n = null`
rather than written, that half answers false and the ladder falls to its `"i32"` default, which
calls `__print_i32__` on the `ref.null` the assignment yields; `==` against `null` fails the same
way. The checker types the assignment `_ | null`, the never-filled hole `TyNullable(-1)` (a
hover reads `_ | null` at the declaration), which is not `null` until scope close decides it.

#### Ablation

| ingredient changed | outcome | needed? |
| --- | --- | --- |
| `let n: null = null` (annotated) | prints `null` | **yes** |
| `print((n = null) == null)` instead | invalid module | no |
| `const z: null = (n = null)` then `print(z)` | prints `null` | **yes** (a read as a value) |
| `let m: string \| null` (D17118's spelling) | prints `null` after D17118 | **yes** |
