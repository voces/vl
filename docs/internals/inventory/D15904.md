### D15904 — a hole lambda's bundle held in a `let` and read through another `let`, handed to a parameter called at two signatures, is refused by mono

**closed 2026-11-12, runs and prints `5` `2.5` · was loud emit reject · clause 2 · `emitProgram: monomorphize: unsupported argument type for \`b\` in a call to \`take\`` · found closing [D15744](D15744.md) · filed 2026-11-12 against master `bd8092cc` · closed in the elaboration: a never-assigned `let` copy holds its source's record as a `const` copy does (`elabResMayHoldAt`), and a `let` holder written from another holder may be handed on and copied (`elabHolderLinkedHolds`, emit_elab.vl) · fixture `tests/cases/closures/hole-lambda-bundle-handed-on-copied-and-dropped.vl`**

Repro:

    function lap(f) {
      f(2.5)
      f(3)
      return f
    }
    function take(b) {
      print(b(4))
      print(b(1.5))
    }
    let p = lap((a) => a + 1)
    let q = p
    take(q)

Want:

    5
    2.5

#### Mechanism

A `let` holder of the bundle copied into, or written into, another `let` is not followed as a
holder: the elaboration follows a `const` copy of a holder (D15741, D15746), and a `let` written
by fresh `lap(…)` calls runs, but `q` read from `p` is one closure to mono.

#### Ablation

| spelling | outcome |
| --- | --- |
| `let q = lap(…)`, `q = lap(…)`, `take(q)` | runs |
| `let q = p`, `take(q)` | refuses (mono) |
| `let q = lap(…)`, `q = p`, `take(q)` | refuses (mono) |
| `p`, `q` initialised by a returner `g()` | refuses (function value at two signatures) |
