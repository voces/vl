### D15061 — two lists of records whose field holds the same generic, called at two types, are lowered at one rep

**closed · runs, prints `w`, `5`, `1` then `w` · was check-clean invalid wasm · clause 1 · with the split plan on and off alike · found closing the split plan's group M-record (A) · filed 2026-11-02 against master `0a0b6b52` · fixture `tests/cases/objects/record-generic-field-called-beside-list-of-record.vl`**

Repro:

    function k<T>(x: T): T { return x }
    const r = { f: k, g: 7 }
    const xs = [r]
    print(xs[0].f("w"))
    print(xs[0].f(5))
    const r2 = { f: k, g: 8 }
    const ys = [r2]
    print(r2.f(1))
    print(r2.f("w"))
    // vl check: rc 0.  vl run: the emitted module failed to validate in the top-level code: expected (ref $type), found i32

Want:

    w
    5
    1
    w

#### Mechanism

`k` called at `string` and `i32` through a record field needs its set tagged, and a record
holding the set is a holder of it (`ftHoldKind` kind 2). A list of such records was no holder
kind at all, so a list literal of the record declined the set in `ftHoldCtxOk`'s `ArrayLit` arm.
With one list the split plan or the closure path covered it; with two, part of the program
was lowered as the tagged id and part as the closure. Closed by holder kind 6, a list of kind-2
records, read where kind 2 is (`ftHoldKind`, check_fn_tag.vl); a slot write onto it still declines.
