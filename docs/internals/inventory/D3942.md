### D3942 — a reassigned let of generic functions passed to a generic callback parameter is refused

**loud emit reject · clause 2 · found in review of #3493 (`rv3493/i1`, `i3`) · filed 2026-10-10 against master `00bf1871f`**

Repro:

    function inner<U>(u: U) { print("I"); print(u) }
    function other<V>(v: V) { print("O"); print(v) }
    function callT<T>(f: (t: T) => void, t: T) { f(t) }
    function g<T>(x: T) {
      let k = inner
      callT(k, x)
      k = other
      callT(k, x)
    }
    g(1)
    g("s")
    // vl build: emitProgram: monomorphize: unsupported argument type for `f` in a call to `callT`

Want:

    I
    1
    O
    1
    I
    s
    O
    s

#### Mechanism

Not located. `callT(f: (t: T) => void, t: T)` binds `T` from the arrow argument's function
type (D3913 takes a generic function's from the other arguments); a reassigned `let` of
generics is neither, so `f` is refused. A direct generic argument (i5) runs.
