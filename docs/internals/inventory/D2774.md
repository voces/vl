#### Mechanism

D2775 types an `if`/`match` join of an f32 value and a float literal `f32`, as `raw + 0.1` is.
The same rule at an inferred return (`return x` beside `return 0.1`, or a tail `if`/`match`)
and at a list literal (`[x, 0.1]`) makes both `f32`, and consistency asks for it. But unlike the
`if` join, which was a type error or invalid wasm wherever it was consumed, both of these RUN
today with the literal read as f64 wherever an f64 is accepted, so adopting changes their
values (0.30000000000000004 becomes 0.30000001192092896). The candidate is built and switched
off: `f32JoinRetypesRunning` in `compiler/typecheck.vl` answers false; true joins an inferred
return's witnesses (`inferRetF32Join`), a list's elements (`f32LitJoinOf`, with the emitter's
`arrLitIsF32` reading the checker's `f32[]`) and a return-tail `if`/`match`. Recommendation:
turn it on. It is the reading an operator already gives, and the programs it changes join an
f32 value with a literal and then widen the result.
