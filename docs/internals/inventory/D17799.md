### D17799 — a tag dispatch over a set of lambdas whose callee its place stores as a closure has no closure signature

**closed 2026-11-28 by COV-UNION · runs, its witness prints its expected value · was a loud emit reject, `cannot yet lower this statement (tag dispatch closure key)` · a dispatch's function-local callee held as the nullable id's box and read on the `unbox` arm is read as stored, then non-null, and an element callee planned at a closure is read at the member id (`irIndexHook` at `i32`), both in `tagCallee` (ir_build.vl) · pinned by `tests/cases/closures/tagged-set-local-popped-and-in-place.vl`**

Repro:

    function main() {
      const f = (a) => a + 1
      const d = (a) => a * 2
      const two = [f, d]
      const s = two.pop()
      if s != null { print(s(3)) }
      const m = [f]
      print(m[0](3))
    }
    main()
    // vl check: rc 0.  vl run: emit error (tag dispatch closure key) at 6:28

Want:

    6
    4

#### Mechanism

The list holds the set's member ids (an `i32` list); the popped local is the union box of the id.
The call planned its callee at a closure, so the box's payload was read as one: keying that call at
its own closure signature built it and trapped at run time (`wasm trap: cast failure`, the id's
box cast to a closure). The build was right and the read wrong: the dispatch now reads the callee
as the binding, or the list's element, holds it, and dispatches on the id.
