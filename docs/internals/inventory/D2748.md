### D2748 — a list literal handed to an un-annotated parameter used as the callee finds no destination

**closed 2026-09-26 — the repro RUNS and prints `3` · was check-clean invalid wasm · the #3204 review's `b29` and the lane's nested-function, later-parameter and lambda-argument variants · filed 2026-09-26 against master `92bed043d`**

Repro:

    type Circle = { r: i32 }
    type Sq = { s: i32 }
    type Shape = Circle | Sq
    function sum(xs: Shape[]): i32 { xs.length * 3 }
    function f() {
      const out = [{ r: 3 }]
      const ap = (g) => g(out)
      print(ap(sum))
    }
    f()

#### Mechanism

D2704 made the destination scan ask the callee's checked function type, and its row says that
covers an un-annotated lambda parameter. It does not: the checker leaves such a parameter an
open hole (`ap` checks as `(_) => _`), so no `TyFunc` answers, and the name path found a `Param`
with no annotation. `out` was built as a `Circle` list, and the specialized `ap` passed it to
`sum`. Closed by reading the function each call of the lambda's `const` (or nested function)
hands that parameter (`dsLamParamCalleeSlot`).

#### Ablation

| ingredient removed | outcome | needed? |
| --- | --- | --- |
| the annotation `(g: (Shape[]) => i32)` | the annotated spelling runs on master | **yes** |
| the `Shape[]` parameter of `sum` | runs | **yes** |
| the enclosing function (module scope) | runs on master | **yes** |
| `const ap` replaced by `function ap(g)` nested | invalid wasm | no |
| a lambda argument `ap((xs: Shape[]) => xs.length)` | invalid wasm | no |
