### D4121 — a generic function passed through a generic identity call reaches its call un-instanced

**loud emit reject · clause 2: `vl check` is clean · found by lane SC with [D4120](D4120.md)'s ablation · filed 2026-10-11 against master `8411b89d5`**

Repro:

    function id<T>(x: T) { x }
    function sel<F>(f: F) { f }
    const k = sel(id)
    print(k(3))
    // vl check: rc 0.  vl run: emitProgram: a function-value call has no interned signature — parameter 1 of type `` has no representation in the function-value ABI

#### Mechanism

`sel` returns its argument at the type parameter `F`, which binds to `id`'s still-generic type,
so the call `k(3)` sees a callee whose parameter is a type-parameter hole and nothing instances
`id` at `i32`. From the ablation; the rung's input has not been printed. With a destination
annotation the same program builds and traps instead: [D4122](D4122.md).

#### Ablation

| spelling | outcome | needed? |
| --- | --- | --- |

| `function sel(f: (x: i32) => i32)`, not generic | runs, `3` | **yes** |
| `function id(x: i32)`, not generic | runs, `3` | **yes** |
| inside a function body | loud emit reject | no |
| `const k: (x: i32) => i32 = sel(id)` | loads then traps ([D4122](D4122.md)) | changes the clause |
