### D8143 — a function returning a fresh call, beside a declared record of the call's fields, is invalid wasm delivered into a wider record

**closed 2026-10-20 by lane records · runs, prints `15` · was check-clean invalid wasm on master `f90d0709e` · clause 1 · the adoption hands the destination on through a leaf that calls another inferred function (`recFnBuiltAtDst`), up to the depth `recBuildsLit` follows · fixture `tests/cases/soundness/record-fresh-call-delivered-through-binding.vl` · filed 2026-10-20 against master `f90d0709e`**

Repro:

    type Col = { r: i32, g: i32 }
    type J = { r: i32 | null, g: i32 }
    function mk() { { r: 15, g: 1 } }
    function d() { return mk() }
    const m: J = d()
    print(m.r ?? 0)
    // vl check: rc 0.  vl run on master: invalid module, "type mismatch: expected (ref null $type)"

Want:

    15

#### Mechanism

`recFnBuiltAtDst` re-seated only the literal leaves of the function delivered, and `d`'s
leaf is a call, so nothing re-seated `mk`'s literal while the delivery was accepted as fresh.
A call leaf to another inferred function now passes the destination on to it. When `d` is
also called somewhere that keeps `mk`'s own row, the leaf cannot be re-seated for both, and
the delivery is refused with [D8020](D8020.md)'s message instead.
