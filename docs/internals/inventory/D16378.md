### D16378 — a shift of a constant by a constant count at or above the width passes the checker, which E6.2 says refuses it

Repro:

    print(4294967296 >> 65535)
    // vl check: shift count 65535 is out of range for an i64 operand (0 to 63) — `>>` would take
    // it modulo 64
    // (filed: rc 0, PRINTS 0)

#### Mechanism

E6.2 says a constant shift count must be less than the operand's width. With a typed operand the
checker refuses (`x >> 64`, `x: i64`: "shift count 64 is out of range for an i64 operand"). When
the operand is a constant too, the tree is folded exactly under E9.1 and never meets the width
check. The fold has no width, so it shifts the exact value. The two rules disagree for a constant
operand. The fix is the refusal E6.2 states, unless the owner rules that E9.1's fold
takes precedence. That is why this row carries no `Want`.

#### Ablation

| ingredient removed | outcome | needed? |
| --- | --- | --- |
| the constant operand (`const x: i64 = 4294967296; x >> 64`) | loud check reject, E6.2's sentence | **yes** |
| the out-of-range count (`4294967296 >> 63`) | prints `0`, legal | **yes** |
| `>>` (`1 << 32`) | prints `4294967296`, the exact fold | no |
| a small operand with a huge count (`1 << 65535`) | refused, "constant overflows the 512-bit exact integer range", not E6.2 | no |

#### Grading list

`>>>` and `<<` at counts 32 and 64 over i32-sized and i64-sized constants, and a literal `const`
count (`const k = 64`).
