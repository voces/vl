### D1724 — a literal-union value is refused as a MAP KEY at every spelling, while the identical value typed `string` is accepted

**loud emit reject · filed 2026-09-06 against master `194d1f8d2` · found by the spelling x use
grid built for D1545/D1717, as the one column that fails independently of the parameter ·
clause 2: `vl check` returns 0 and every member of the union is a string · 0 corpus cells**

Repro:

    type K = "red" | "green"
    function take(a: K) {
      const m = Map()
      m["green"] = 1
      print(m[a] ?? 0)
    }
    take("green")
    // vl check: rc 0.  vl run: emit error,
    // emitProgram: map key is not a string

Annotate the same parameter `a: string` and the identical program prints `1`.

#### Mechanism

Predicted, not probed. A literal union's members are strings and its REP is the interned i32
atom; the map-key gate asks for the string rep and the atom is not one. Every other consumer in
the grid either widens the atom to its member text or compares atoms directly — the key gate is
the one that does neither, so it refuses rather than widening. The fix is the widening the
`print` path already performs (`litAtomWidenTexts`), applied at the key boundary; probe the
gate against this failing witness before writing it.

**This is NOT the softening family.** D1545 and D1717 are about an INLINE set losing its atom
rep through a hole parameter, and they are fixed by the alias spelling and by an annotation.
This row is refused at ALL FOUR spellings the grid covers, which is what separates it.
