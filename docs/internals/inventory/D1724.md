### D1724 — an ATOM-repped literal-union value is refused as a MAP KEY, while the identical value typed `string` is accepted

**closed 2026-09-06 — the key boundary widens the atom to its member text, the widen `print` already performs · filed against master `194d1f8d2`, closed against `#2749`'s tree · scope NARROWED 2026-09-06 from "at every spelling": the inline member set runs at both seeds, one ablation row was wrong · 0 corpus cells**
Repro:

    type K = "red" | "green"
    function take(a: K) {
      const m = Map()
      m["green"] = 1
      print(m[a] ?? 0)
    }
    take("green")
    // vl check: rc 0.  vl run: rc 0, prints 1

Was: `emitProgram: map key is not a string`, while `a: string` printed `1` all along.

#### Mechanism

Probed against the failing witness, where the row filed it as predicted. `emitMapRecvKey` is the
ONE gate every map-key consumer reaches, and its key test is `exprString(keyIx, fnIx)`. An
atom-repped literal union answers false there — correctly, its rep is the interned id — so the
gate refused a value whose MEMBERS are strings. The close asks the sibling question the same
ladder already answers (`exprIsLitAtom`) and emits `emitAtomToStr` for the key instead of
`emitExpr`: the widen `print` performs, through the one home both consumers share.

**One gate, six consumers.** Because every map-key path routes through `emitMapRecvKey`, the
index read, `.get`, `.has`, `.delete` and — at the hole-parameter face — the index WRITE and
`.set` all move together. A 28-cell grid (key spelling x consumer) moves **ten** cells from
`emit: map key is not a string` to RUNS and loses none.

**What is left is a different refusal with a different channel.** `A K-keyed Map isn't
supported` is a CHECK reject naming the map's declared KEY TYPE, not the value's rep, and it
stands at the annotated write side and at `Set.add`. It is [D1748](D1748.md).
