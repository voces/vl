### D2199 — an `if` value joining two differently-typed literal values into a declared literal-union binding is refused by the emitter

**loud emit reject · `emitProgram: literal-union atom narrowing needs a re-readable receiver` · `vl check` rc 0 · runs (prints `x`) on the seed built before #3056 · found writing the D2198 fixtures · filed 2026-09-23 against master `66e74235a`**

Repro:

    const A: "x" | "y" = "x"
    const B: "y" = "y"
    function join(c: boolean) {
      const M: "x" | "y" | "z" = if c { A } else { B }
      print(M)
    }
    join(true)

#### Mechanism

Not yet diagnosed. The refusal is the emitter's atom-narrowing floor in `wasmEmit.vl`, reached for
the `if` value's join (`"x" | "y"` from its two arm types) delivered into a declared set that is
wider than the join; every variant where the two arms carry the same type, or the value is written
by statements instead, runs.

#### Ablation

| ingredient removed | outcome | needed? |
| --- | --- | --- |
| `B` typed `"x" \| "y"` like `A` (and `M` too) | runs | **yes** |
| `A` unannotated, so both arms are `const` literals | runs | **yes** |
| `B` unannotated (a `const` literal `"y"`) | refuses | no |
| `M` declared `"x" \| "y"` instead of the wider set | refuses | no |
| the function, with `M` a module const | refuses | no |
| the `if` value, written as `if c { M = A } else { M = B }` on a `let` | runs | **yes** |

#### Grading list

The same join as a function argument and as a return into a declared literal-union result; the
`const M: "x" | "y" | "z" = ...` spelling D2198's refusal suggests for a join of `const`s, whose own
witness (both arms unannotated) runs today.
