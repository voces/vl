### D13461 — a labelled block handing out an `if` of hole functions, bound and passed to a parameter called at two types, is refused at emit

**closed 2026-10-25 · runs, prints `a` and `1` · fixed: the split reads a labelled block whose body only breaks out with a value as that value (`labelBlockValue`, ast.vl; `fsParenPeel`, fn_split.vl), so the bound choice takes D13360's plan · pins: `tests/cases/generics/hole-fn-choice-nested-positions.vl` · was loud emit reject, clause 2 · `monomorphize: unsupported argument type for `f` in a call to `both`` · found closing [D13360](D13360.md) · filed 2026-10-25 against master `ad209bcf6`**

Repro:

    function both(f) {
      print(f("a"))
      print(f(1))
    }
    function inner(s) { return s }
    function ask(s) { return s }
    function g(c: boolean) {
      const h = @B {
        break @B if c { inner } else { ask }
      }
      both(h)
    }
    g(false)
    // vl check: rc 0.  vl run: emitProgram: monomorphize: unsupported argument type for `f` in a call to `both`

Want:

    a
    1

#### Mechanism

From the code path, not ablated to a line. D13360's plan selects a slot's argument by an arm
index only when the choice is the call's argument (`fsChoiceArgStmt`, fn_split.vl). Here the
argument is an identifier bound to a labelled block, so the plan sees a `const` carrying one
function value and has no arm to hand each per-type slot.
