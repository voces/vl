### D15137 — a map written two functions of different result types by `set` is refused at check

**closed · runs, prints `1.5` · was loud check reject, `cannot write 'half' to an element of 'm': called at (i32) it returns f64, where 'inc0', also written to it, returns i32` · clause 2 · split from [D14648](D14648.md) (step 2, the map) · filed 2026-11-03 against master `097fd927` · closed 2026-11-03: `elabSlotJoinTy` records each container binding whose slot writes it joins (`elabFnSlotWidened`), and `holeSlotJudge` lifts its comparison for such a binding as for a widened list. The index read is [D15139](D15139.md); generics are [D15160](D15160.md); a parameter, a return and a captured local alias are [D15161](D15161.md), [D15162](D15162.md) and [D15163](D15163.md)**

Repro:

    function inc0(a) { return a + 1 }
    function half(a) { return a / 2.0 }
    const m = Map()
    m.set("a", inc0)
    m.set("b", half)
    const g = m.get("b")
    if g != null { print(g(3)) }
    // Want: 1.5

#### Mechanism

The list spelling runs because `elabFnListLetTy` widens the list binding over its writes and
`holeSlotJudge` lifts its comparison for a binding so widened. A `Map()` has no such widening.
D14648's row measured the lift for a map: `set` and `get` then run, and the index read `m["b"]`
routes to the scalar box (`scalar map read has no value-box type`). So the index read is its own
step after this one.
