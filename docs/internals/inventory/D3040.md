### D3040 — an `i32[]` the program writes is refused as a `readonly i64[]`, though a view of it is now built and its union twin is accepted

**loud check reject · clause 2 pending a ruling · found closing [D3028](D3028.md) · the same on master `3a71bb1f9` · filed 2026-09-28 against master `3a71bb1f9`**

Repro:

    const l: i32[] = [1, 2]
    const r: readonly i64[] = l
    l.push(3)
    print(r.length)
    // vl check: i32[] is not readonly i64[] here: this list is written (line 3), and a written
    // container never widens implicitly.

Want:

    3

#### Mechanism

The checker refuses D965's scalar pair wherever `covarValueWriteState` is not 0, because the
copy it served was a snapshot. Since D3028 the emitter builds a view that reads through its
source for any delivery it is handed, so this refusal names a mechanism that no longer exists.
The union twin, `(string | i32)[]` written and delivered as `readonly (string | i64)[]`, is
accepted and shared ([D3026](D3026.md)). The message reads as a rule ("a written container never
widens implicitly"), so lifting it is a language question: does a `readonly` view of a wider
element observe writes to its source, as the union view already does? Recommendation: yes, and
lift the refusal for a `readonly` destination only; the mutable one stays refused by DECISIONS.md
A9. Not lifted here, because every read position of a view must be served first.

#### Ablation

| `(string \| i32)[]` into `readonly (string \| i64)[]` | runs, sees the push | the scalar pair only |

#### Grading list

The scalar grid's `check` cells (2,226 of 3,780: every write the analysis sees) must run and
print the written value once lifted, at every reader. The same refusal
("nothing shows this list is never written") also fires at the return of
`function back(x: i32[]): readonly i64[] { return x }` once its result, as a view, is later:

* returned inside a union, `readonly i64[] | P`, from a second function;
* an element of a list literal, `const arr: (readonly i64[])[] = [r, r]`;
* spread into a list, `const s: i64[] = [0, ...r, 9]`;
* spread into a rest argument, `tot(...r)` with `function tot(...xs: i64[])`.

Each must run and read the source's later writes once lifted (the #3264 review's `f1a`, `f1c`,
`h_spreadmix`, `h_rest` probes).
