Repro (runs, prints `11` then `12`):

#### Mechanism

`fbIfForSharedField` is keyed on the field CODE alone, and a code-15 (nested-struct) result
needs the field's own TARGET ROW to spell `(ref $S)` — so `optChainFieldCodeOk` declined the
code and the site refused. The site holds that row (`nsi` / `nfi` → `sFieldTgtStructIdx`), so
it emits the `if` itself.

THE NULLABLE TRAP THE ROW FILED IS REAL AND THE ANSWER IS NOT TO DISTINGUISH THE TWO
DECLARATIONS. A code-15 slot is `(ref null $S)` storage whether the field is declared `S` or
`S | null` — [D1180](D1180.md)'s ruling, in the equality recursion — so the lowering tests
receiver-null OR field-null, short-circuited through an i32 `if` so `struct.get` never runs on
a null receiver. On a declared `S` the second arm is constant-false and the answer is
unchanged; on `S | null` it is exactly what `o?.f ?? d` means. The receiver is a re-readable
place (`optRecvReReadable` gates the whole arm), so the three reads are effect-free and the
default is emitted ONCE. A nullable DEFAULT keeps the block result nullable and skips the
`ref.as_non_null`, the same either/or the boxed-union `??` arms make.
