### D16672 — a radix `^` whose 32-bit result is zero reads as its exact value, `(-1) ^ 0xFFFFFFFF` printing `-4294967296`

**closed 2026-11-16 · runs, prints `0` twice · was check-clean silently wrong, `-4294967296` twice · clause 1 · ruling A (a radix literal is a bit pattern at its use's width, under every operator) · found by the independent oracle's arithmetic generator (lane T's cells `ar_s13_0110`, `ar_s13_0136`) · filed 2026-11-15 against master `f195dacbc` · fixed by `cexBitwise` (const_exact.vl) leaving a pattern result past 32 bits to its use's width, as `cexPatResult` already does for `+`, `-` and `*`; the `i64` destination keeps `-4294967296` · fixture `bitwise/radix-bitwise-past-32-bits-at-use-width.vl`**

Repro:

    print((-1) ^ 0xFFFFFFFF)
    print(0xFFFFFFFF ^ (-1))
    // was: vl check rc 0, prints -4294967296 twice

Want:

    0
    0

#### Mechanism

`cexBitwise` (const_exact.vl) computes `^` exactly over the infinite two's-complement forms
(`-1 ^ 4294967295 = -4294967296`) and kept the result as a pattern, with no width test. The ring
operations refuse a pattern result past 32 bits (`cexPatResult`), since it is a different bit
pattern at each width; the bitwise ones did not. A result whose low 32 bits are not zero was
read at 32 bits anyway; one whose low 32 bits are zero kept its exact value. The exact value is outside `i32`, so the tree is typed `i64`
and widens its typed peers: `v2 * ((-1) ^ 0xFFFFFFFF)` with `v2: i32 = 7` prints
`-30064771072`, not `0`.

#### Ablation

| spelling | master | want |
| --- | --- | --- |
| `(-1) ^ 0xFFFFFFFF`, either operand order | `-4294967296` | `0` |
| `(-1) ^ (0xFFFFFFFF + 0)` | `-4294967296` | `0` |
| `const x: i32 = (-1) ^ 0xFFFFFFFF` | refused | `0` |
| `v2 * ((-1) ^ 0xFFFFFFFF)`, `v2: i32 = 7` | `-30064771072` | `0` |

| `(-2) ^ 0xFFFFFFFF`, `(-1) ^ 0xFFFF0000`, `(-1) ^ 0x7FFFFFFF` | pattern | same |
| `0 ^ 0xFFFFFFFF`, `1 ^ 0xFFFFFFFF` | pattern | same |
| `(-1) & 0xFFFFFFFF`, `(-1) \| 0xFFFFFFFF`, `(-1) + 0xFFFFFFFF` | pattern | same |

#### Grading list

- Every ablation row whose master and want differ.
- The same tree under `i64`: `const x: i64 = (-1) ^ 0xFFFFFFFF` is `-4294967296` there, which is
  right at 64 bits and must stay.
