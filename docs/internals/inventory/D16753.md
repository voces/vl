### D16753 — one maker returning a hole lambda, delivered at two function types whose results differ, builds one closure for both

**closed 2026-11-16 · runs, prints `4` `0.5` · was loads then traps, `vl check` rc 0, `wasm trap: indirect call type mismatch` at the second call · clause 1 · fixed by `elabTwinLamRet` (emit_elab.vl): the maker's wide twin already existed per delivered result, and a lambda it returns whole now returns that twin's result instead of the body's · the two-argument spelling runs too; the relay spelling (`relay()` returning `deliver()` at two types) is a loud emit reject, not silent · pin: `tests/cases/functions/maker-lambda-twin-per-delivered-result.vl` · found closing [D16711](D16711.md) · filed 2026-11-16 against master `6356d3e7d`**

Repro:

    function deliver() { return (a) => a + 1 }
    const v: (a: i32) => i32 = deliver()
    const w: (a: i32) => f64 = deliver()
    print(v(3))
    print(w(3) / 8.0)
    // vl check: rc 0.  vl run: prints 4, then wasm trap, indirect call type mismatch

Want:

    4
    0.5

#### Mechanism

The lambda's calls take two results, `i32` and `f64`, so `elabLamDeliveredRet` answers none and
one instance returning the body's `i32` serves both deliveries. The `f64` call traps. A closure
per delivered result is what the maker twin builds for two closed results; here the twin is not
built per result for both reads, so the bundle the design calls for (one built closure per
creation site, instance and closed signature, `closure-at-delivery-2026-11.md`) is missing.
