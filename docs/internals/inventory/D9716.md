### D9716 — a `let` bound to a nested list of un-annotated functions, returned and handed to an un-annotated parameter, is refused as an argument type

**loud emit reject · `vl check` rc 0 · `monomorphize: unsupported argument type for `a` in a call to `take`` · clause 2 · found closing [D9662](D9662.md) · present on master `e8163edd5`, there as `a parameter type the valtype ladder has no rung for` · filed 2026-10-22 against master `e8163edd5`**

Repro:

    function inc(a) { return a + 1 }
    function dbl(a) { return a * 2 }
    function deliver(_n) {
      let u = [[inc], [dbl]]
      return u
    }
    function take(a) { print(a[1][0](3)) }
    take(deliver(1))
    // vl check rc 0.  vl run: emit error: emitProgram: monomorphize: unsupported argument type for `a` in a call to `take`

Want:

    6

#### Mechanism

Not traced. With `const`, [D9662](D9662.md)'s close gives the instance of `deliver` its own copy
of the binding (`monoLetOwnCopy`, emit_mono.vl), which its walk annotates. It does that for a
`let` only when the binding is the returned one a binding of the call asks for, which the
argument position does not. Allowing every `let` there leaves this refusal as it is.

#### Ablation

| ingredient removed | outcome | needed? |
| --- | --- | --- |
| the `let`, for `const` | runs, `6` | **yes** |
| the argument position (`const v = deliver(1)`, `v[1][0](3)`) | runs, `6` | **yes** |
| the local (`return [[inc], [dbl]]`) | runs, `6` | **yes** |
