### D9561 — `??` over the call of an un-annotated parameter bound at a function returning a mixed-width numeric literal union is refused at emit

**loud emit reject · clause 2 · CAPABILITY: an annotated `f: () => W` runs, and `a ?? 0` over a `W | null` value directly runs · found closing [D9521](D9521.md) · present on master `95725e040` · filed 2026-10-22 against master `95725e040`**

Repro:

    type W = 1 | 2 | 5000000000
    const a: W = 2
    function take(f) {
      print(f() ?? 0)
    }
    take(() => a)
    // vl check: rc 0.  vl run: emitProgram: `??` over this nullable value is not supported yet — narrow it first, e.g. `if v != null { … }`

Want:

    2

#### Mechanism

Partly traced. The instance's dead-default fold (`coalRetypedDead`, emit_classify.vl) takes an
operand whose numeric literal type reps as the `??`'s scalar pin. `W` reps as a value box, not
a scalar, so the fold declines and the nullable-value arm refuses. The fold would deliver the
box into the `??`'s pin, which needs the pin's type for a box operand.
