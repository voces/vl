### D9063 — an un-annotated function in an un-annotated `Map()` read only by a `for k, v in` loop, or never called, has no map value type

**loud emit reject · `vl check` rc 0 · `unsupported map value type` · clause 2 · found closing [D4579](D4579.md) and [D9040](D9040.md) · present on master `16cf779bd` · filed 2026-10-21 against master `16cf779bd`**

Repro:

    function inc0(a) { return a + 1 }
    const m = Map()
    m["k"] = inc0
    for k, g in m { print(g(3)) }
    // vl check rc 0.  vl run: emit error: emitProgram: unsupported map value type (no rep for a union-member struct, ...)

#### Mechanism

Not traced. The D9040 close types the map's value from the parameter types its calls
pin on the value slot (`v`). A two-variable loop's value binding flows from the map's
element slot (`e`, `ffFlow` over `ForIn`, fn_flow_shadow.vl), so `g(3)` pins no call on
`v`. With no pin there is no type to give, which is also why a map whose value is never
called still refuses.

#### Ablation

| ingredient removed | outcome | needed? |
| --- | --- | --- |
| the un-annotated map (`const m: {[string]: (a: i32) => i32} = Map()`) | runs, `4` | **yes** |
| the map (`const xs = [inc0]`, `for g in xs { print(g(3)) }`) | runs, `4` | **yes** |
| the call (`for k in m { print(k) }`) | same refusal | no |
