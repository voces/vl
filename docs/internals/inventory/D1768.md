### D1768 — a CAPTURED literal-union list element spelled INLINE leaks the interned atom id, and the same capture inside any block is check-clean invalid wasm instead

**check-clean silently wrong · `vl check` rc 0, `vl run` prints `0` where `green` is expected · clause 1 · filed 2026-09-06 against master `0a6a31c0b` · found by `inline-litunion-from-list-element.matrix.vl`'s four capture cells, silent at both seeds of #2775 · [D1541](D1541.md)'s class at the capture · 0 corpus cells**

Repro:

    const srcArr: ("red" | "green")[] = ["green", "red"]
    const v: "red" | "green" = srcArr[0]
    const g = () => v
    print(g())
    // PRINTS 0
    // want: green

Spell the union as an alias — `type Color = "red" | "green"`, `srcArr: Color[]`,
`const v: Color = …` — and the same four lines print `green`. So does deleting the capture
(`print(v)`), and so does a CALL source instead of the list element.

#### Mechanism

Predicted from the ablation, not probed. [D1541](D1541.md) records the seam: a litunion ARRAY
is always the interned-i32 ATOM list, while a scalar litunion destination's rep follows the
SPELLING — an alias is the atom, an inline member set is the string ref — so the two ends
disagree exactly when the spelling is inline. Its close reached the direct read; the CAPTURE is
a third end, and the env field is typed by a classifier that reads the same spelling.

**One shape, two outcome classes, decided by where the capture sits.** At plain module scope
and at every un-annotated spelling the env field takes the atom and the read prints the id — a
wrong value. Inside a block or a function body with the annotation present the env field takes
the string ref over an atom slot and the module fails to validate. The wrong value is the
worse half and is what this row's status names.

#### Ablation

| ingredient removed | outcome | needed? |
| --- | --- | --- |
| the INLINE spelling (an alias `type Color` at both ends) | runs `green` | **yes** |
| the capture (`print(v)` directly) | runs `green` | **yes** |
| the LIST ELEMENT source (a call returning the union) | runs `green` | **yes** |
| the literal union (a struct element and a struct annotation) | runs `3` | **yes** |
| the annotation, at plain module scope | prints `0` | no — same class |
| the annotation, inside a module block or a function body | prints `0` | no — same class |
| the plain module scope, with the annotation (an `if true` block) | **check-clean invalid wasm** | no — the other class |
| the same, in a bare block, a module `while`, a function body, or a function's `if` block | **check-clean invalid wasm** | no |
| the first element swapped for the second (`srcArr[1]`) | **check-clean invalid wasm** | no |

Needed: the inline spelling AND the capture AND the list-element source. Not needed: the
annotation or the scope — those pick which of the two classes you get, not whether it fires.
