Repro:

    const srcArr: ("red" | "green")[] = ["green", "red"]
    const v: "red" | "green" = srcArr[0]
    const g = () => v
    print(g())
    // vl check: rc 0.  vl run: prints green.

Spell the union as an alias — `type Color = "red" | "green"`, `srcArr: Color[]`,
`const v: Color = …` — and the same four lines printed `green` before the close too. So did
deleting the capture (`print(v)`), and so did a CALL source instead of the list element.

#### Mechanism

[D1541](D1541.md) records the seam: a litunion ARRAY is always the interned-i32 ATOM list,
while a scalar litunion destination's rep follows the SPELLING — an alias is the atom, an
inline member set is the string ref — so the two ends disagree exactly when the spelling is
inline. Its close reached the direct read; the CAPTURE is a third end, with a cell site and a
reader site that had to move together.

**One shape, two outcome classes, decided by where the capture sat.** At plain module scope
and at every un-annotated spelling the env field took the atom and the read printed the id — a
wrong value. Inside a block or a function body with the annotation present the env field took
the string ref over an atom slot and the module failed to validate.

**The CELL — `captureValKind`'s annotated arm.** Three name-gated `emitFail` probes, each read
against the ALIAS control that runs. (A probe that is not name-gated reports only the FIRST
failure in the program, which is `srcArr`, and that artefact hid the `v` row on the first two
readings.) The arm fires for the block and function-body faces and stays silent for the
module-scope ones, so a captured GLOBAL does not reach it:

| face | `annK` | `initK` | `initIsLitAtom` | `letIsLitUnion` |
| --- | --- | --- | --- | --- |
| inline, module block | **`str`** | **`i32`** | **T** | F |
| alias, module block | `i32` | `i32` | T | **T** |
| inline, CALL source | `str` | `str` | **F** | F |
| struct element | `struct` | `struct` | F | F |

The annotation renders `str` for the inline spelling ([D1541](D1541.md)'s soften) while the
init cell is the atom the litunion array hands over. `letInitIsLitAtom` separates the two
litunion faces from both controls, and it answers at `frameOk=F`, so it is frame-blind. The
arm now asks it after [D1632](D1632.md)'s niche test and returns `"i32"`.

**The GLOBAL's cell is NOT the module-scope site.** `globalCellKindGo` was probed on the same
table and the emitted module settles it: both spellings declare `v` as `(mut i32)`, the atom.
The direct read (`print(v)`) and the direct compare both printed correctly at module scope;
only the CAPTURED read was wrong, so the capture is the ingredient at every scope.

**The READER — `exprIsLitAtom`'s Call arm.** The read is `print(g())`, a CALL, so the Ident
arm never applies. The arm that answered was `nodeTyIsLitUnionAlias(unwrapParen(exprIx))`,
whose own comment says a named call to an inline-litunion-returning function reps as a string
ref and is correctly excluded — true, and it stays true. What was missing is the CLOSURE call,
whose result rep is what the lifted body yields rather than what a spelling renders. The new
rung resolves the callee `Ident` to its lifted frame with `identClosureFeSid` — the same
resolver `cloLamParamUnionName` uses, and the one that reaches all three scopes including
the module frame — and reads `fRetLitAtom`, the banked flag the named-callee rung below it
already reads. A named function is a `FuncDecl` and not a lambda binding, so that resolver
answers -1 for it and the exclusion is untouched.

Needed: the inline spelling AND the capture AND the list-element source. Not needed: the
annotation, the scope or the reader — those pick which of the two classes you get, not whether
it fires.

**The cell rung alone is a class REGRESSION** — measured on this branch before the reader
landed, on the 32-cell grid below: `runs -> not-runs` 0 and no new SILENT, but WRONG **4 to
10** as the six invalid-wasm print cells became printed atom ids. Six silent cells for six
wrong values is the trade the standing rule forbids, which is why both halves land together.
