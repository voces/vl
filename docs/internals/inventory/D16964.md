### D16964 — a record literal with a field holding a built read, stored into a nullable record field whose initialiser is a join, builds invalid wasm

**closed 2026-11-18 by lane F2 · runs, prints `4` · was check-clean invalid wasm, clause 1 · closed by building a record literal stored into a field of a binding the record solve builds elsewhere at that field's record, read through `| null` (`recBuildRowOf`, `emit_classify.vl`); the checker already recorded the binding's build · pin: `tests/cases/records/built-record-stored-into-nullable-field.vl` · graded by `built-record-read-nullfield-*.matrix.vl` · filed 2026-11-18 against master `0ca511a3e` by lane F2**

Repro:

    type J = { f: i32 | null }
    const m = Map()
    m.set("a", { f: 4 })
    const wm: {[string]: J} = m
    const d = { f: 1 }
    const w3 = { k: if d.f == 99 { null } else { { x: { f: 7 } } } }
    w3.k = { x: m.get("a") ?? d }
    print(w3.k?.x.f ?? 0)
    // vl check: rc 0.  vl run: invalid module at the store, type mismatch: expected `#anon1` {mut i32}, found `J`

Want:

    4

#### Mechanism

The stored literal holds a record built at `J` (a read of `m`, which `wm` builds at `J`), so the
binding's field must be built with that field's build. The check recorded it (`w3` built at
`{k: {x: J} | null}`), but the emitter's row for a stored literal (`recBuildRowOf`) read a recorded
build only for a list element, `m[k] = …`, `m.set(k, …)` and a binding's initialiser, never for a
field store `rec.f = …`. With a non-null field the literal's own row happened to serve; through
`| null` it did not, so the store wrote a `J` record into a field laid out at its own record.
