### D15233 — a binding reassigned from a map whose function values have hole types is refused at emit

**closed · runs, prints `1.5` · was a loud emit reject (filed as `emitProgram: ref valtype with no interned shape`; by 2026-11-04 it read `emitProgram: unsupported map value type`), clause 2 · found grading [D15186](D15186.md) · fixed in fn-tag: a map binding reassigned a map of the set it is planned with takes that map as it is, since two maps of one key whose values carry the set share one storage, a map of its ids (`ftDstTakes`, check_fn_tag.vl). An iteration of such a map is [D15353](D15353.md), a reassignment under an `if` [D15354](D15354.md), and a binding whose own write is outside the source's set [D15355](D15355.md)**

Repro:

    function inc0(a) { return a + 1 }
    function half(a) { return a / 2.0 }
    const fnMap = Map()
    fnMap.set("a", inc0)
    fnMap.set("b", half)
    let m2 = Map()
    m2.set("a", inc0)
    m2 = fnMap
    const g = m2.get("b")
    if g != null { print(g(3)) }
    // Want: 1.5

#### Mechanism

`m2` is its own `Map()` written `inc0` and then reassigned the two-function map. Both bindings
are maps of the set `{inc0, half}`, but at two type nodes, and fn-tag's store check took a holder
only into a destination of its own exact type (`ftDstTakes`), so the set stayed untagged and the
map value had no rep. A probe at the store read `dst {[string]: (_) => _} set 1, x set 1`.
