### D16835 — a list of lists of records whose nested record holds un-annotated functions of different result types is refused at check, where one list of them runs

**loud check reject · clause 2 · `listlist_d02` to `listlist_d10` of the type hash-cons 6b breadth-and-depth grid · residue of D16824 · found by lane WIDTH closing D16824 · filed 2026-11-16 against master `a78100c9b`**

Repro:

    function inc0(a) { return a + 1 }
    function half(a) { return a / 2.0 }
    const xs = [[{ a: { f: inc0 } }], [{ a: { f: half } }]]
    print(xs[1][0].a.f(3))
    // vl check: cannot store 'half' in 'xs[][].a.f': called at (i32) it returns f64, where 'inc0', also stored in it, returns i32 — every function a call through 'xs[][].a.f' may run must return one type

Want:

    1.5

#### Mechanism

`holeSlotFieldLift` lifts a field read through a record nested in a list's element only after
exactly one element step (`holeSlotElemNestedField`); D16824 lifted a list of lists' element's own
field and left this one refused. Lifting it was tried while closing D16824 and refused: with both
records in one inner list the module failed to validate (SILENT), and with one per inner list the
emitter refused (`a list-of-lists element has no inner list shape: {a:{f:i32}}[]`). The outer
list's element is stamped at the tagged record (`{a:{f:i32}}`), and no inner list slot is interned
at it, so the lowering has to come first.
