### D8981 — a `const` naming an un-annotated function or lambda, handed to `.map`, is refused at emit

**closed · runs, prints `4` · was loud emit reject, `vl check` rc 0 · clause 2 · found closing [D8944](D8944.md) · filed 2026-10-21 against master `efbbf5f06` · closed by following a `const` or once-bound `let` to the function it holds (`cwFnValueDeclOf`, check_write_scan.vl; `holeFnArgDecl`, check_relate_core.vl), ordering such an argument after the values that bind its parameter (`cwHeldFnOf`, check_generic_args.vl), and binding a generic's arrow result from one in the monomorphizer (`monoArgIsOpenFnValue`, `monoOpenFnArgDecl`, emit_mono.vl) · fixtures `closures/hole-fn-alias-as-callback-result.vl`, `closures/error-hole-fn-alias-generic-result-mistyped.vl`, matrices `hole-fn-alias-as-list-callback-result`, `hole-fn-alias-to-generic-fn-param-result` · [D9000](D9000.md) filed for a result wrapping `U`**

Repro:

    const inc = (a) => a + 1
    print([3].map(inc)[0])
    // vl run: emitProgram: index receiver is not an array or string

#### Mechanism

Not traced. D8944's close reads the callback's result only when the argument names an
un-annotated function declaration; a `const` binding is not one, so `.map`'s result stays
`_[]` and no instance of the value is taken at the element.
