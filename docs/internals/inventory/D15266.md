#### Mechanism

D15246's copy is decided at a call site that initialises a binding: the record solve copies the
call's result back to its own record when that binding is written through. A call handed to a list
element, an argument, a map value or set, an inferred return or a struct field initialiser is not a
binding's initialiser, so it shares `mk`'s build at `K`, and the binding the value is later read
into is written at its own row. The position matrix
`own-binding-of-wider-build-written.matrix.vl` grades these six positions SILENT: `argument`,
`array_element`, `map_value`, `map_set`, `return_inferred`, `struct_field_init`.

#### Returns, closed; arguments, measured

A call returned by a function is now asked through the function's call sites
(`recValueWrittenThrough`, which also answers the let-initialiser case), with the same copy back as
D15246, and `callBuiltTy` reads the copy at any call; the matrix's `return_inferred` cell runs, and
so does a recursive return (fixture `soundness/record-written-into-binding-of-returned-wider-build-runs.vl`).
The `argument` cell (`__take(mk())` into a hole parameter) now runs too. Its site lands at the
build through the hole parameter's queued delivery, and that arm now commits the same copy back.
The copy commit stamps the call's rep at its own record. `nodeRepStamped` lets the readers that
took `rep == own` to mean "never adopted" see the stamp: `recArgBuiltTyIn` for the call-binding
row, and `recRebuiltLeafRow`'s call arm for the elaboration key's delivered-row entry. Those
readers then stop falling back to `mk`'s build at `K`, and the instance is keyed at the record it
is handed (fixture `soundness/record-written-through-hole-parameter-of-wider-build-runs.vl`).
Four stamp guards used `rep == own` to mean "not stamped yet": `recArmLitsAdopt`,
`ralListAdopt`, `recListLitBuild` and `recObjLitBuild`. They now ask `nodeRepStamped`, so the column
has one meaning. The readers that still compare a rep with its own type ask whether the node is
built wider, a question whose answer is the same stamped or not.
#### Container slots, closed

A value stored in a list element, a record field, a map index or a `.set`/`.push` argument is asked
of the slot's reads (`recSlotWrittenThrough`). The binding's occurrence index gives the reads, and
the write scan's slot model (`cwSlotPath`, `cwSlotWrittenValues`) decides which of them see the
stored value. A read written through takes the copy back. Its readers see the stamp:
`recKeptValueDst` keeps the call nowhere else, and `recLitPartBuiltTy` does not count it as a
wider-built element. `array_element`, `struct_field_init`, `map_value` and `map_set` run (fixture
`soundness/record-written-through-container-slot-of-wider-build-runs.vl`).
