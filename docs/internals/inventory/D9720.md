### D9720 — a pushed list of a generic whose pushed element is bound to a `const`, called through the `const` and another element at two types, refuses

**closed 2026-10-27 by the D14438 slice ([D14438](D14438.md)): each call through the pushed list or its `const` read calls the member at its own arguments · was loud emit reject, clause 2 · found closing [D9650](D9650.md) · filed 2026-10-22 against master `4fce2a127` · pins: `tests/cases/closures/generic-list-pushed-element-bound-called-at-two-types.vl`**

Repro (runs, prints `q` `2`):

    function id<T>(x: T): T { x }
    const xs = [id, id]
    xs.push(id)
    const f = xs[2]
    print(f("q"))
    print(xs[1](2))

Want:

    q
    2

#### Mechanism

Not traced. From the ablation only: the `.push` and the `const` read are both needed, and
either alone runs. So the inert path for a pushed list (D9441, `monoValsInert`, emit_mono.vl)
seems to reach a list only when each read of it is a direct call. The `const` read is planned
by another path.
