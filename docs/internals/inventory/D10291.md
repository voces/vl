### D10291 — a generic's direct null test of a map read at a scalar pin has no unboxed form

**closed · runs, prints `true` · was loud emit reject, clause 2 · found closing [D10280](D10280.md) · present on master `d5ec7f160` · filed 2026-10-22 against master `d5ec7f160` · closed by testing the probe's miss as the null where the instance pins the map's value to a scalar (`emitInstMapReadIsNull`, wasmEmit.vl, the map-read arm of `emitNulIsNullTest`) · fixture `maps/generic-map-read-null-test-scalar-pin.vl`**

Repro:

    function g<V>(m: Map<string, V>, k: string) {
      print(m.get(k) != null)
    }
    const mm: Map<string, i32> = Map()
    mm.set("k", 5)
    g(mm, "k")
    // vl check: rc 0.  vl build: bare null needs a struct-typed context

Want:

    true

#### Mechanism

At `V = i32` the instance reads `m.get(k)` as a plain `i32` that is `0` on a miss, so it has
no null to compare. `emitNulIsNullTest`'s map-read arm asked `mapReadScalarBoxKindTy`, which
reads only an `Index` and not the pin, and the comparison fell to the bare-`null` path. The
same holds for `m[k] == null` and for `m.get(k) ?? d` / `return m[k] ?? d` with an `f64` default.

#### Ablation

| ingredient changed | outcome | needed? |
| --- | --- | --- |
| `m: Map<string, i32>`, no type parameter | prints `true` | **yes** |
| `m[k] == null` for the `.get` | refuses the same | no |
| `m.get(k) ?? d` with `d: f64` | refuses the same | no |
