### D17171 — a hole function's nested field read with `?.` inline off a maker call emits no module

**closed 2026-11-25 by lane COV-START · runs, prints `4` · was a loud emit reject (`object literal field count does not match struct`), clause 2 · an instance's record literal minted before the literals it holds, so its nested field had no row yet; `mintPinnedObjLitsIn` now mints children first · fixture `tests/cases/records/hole-maker-nested-literal-optional-read.vl` · loud emit reject · check-clean, claimed and claimless alike · clause 2 · filed 2026-11-24 against master `3ede426f5` by lane IR-N2 (found while probing D17163's optional spellings)**

Repro:

    function inc0(a) { return a + 1 }
    function mk(f) { return { r: { f: f } } }
    print(mk(inc0).r?.f(3))
    // vl check: rc 0.  vl run: "emitProgram: object literal field count does not match struct" (rc 1), claimed and claimless alike

Want:

    4

#### Mechanism

Traced 2026-11-25 by COV-START: in the maker's instance, `mintPinnedObjLitsIn` minted the outer
literal before walking its children. The outer's field `r` was coded before the inner literal had a
row (`anonMintRowFor` field code -1), so the outer minted no row and the literal resolved to another
row. It now mints a literal after the literals it holds.
