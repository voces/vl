### D2987 — an un-annotated record literal built at a WIDER declared record of its field names is read at its own narrower type

**check-clean invalid wasm · open · 10 cells of lane RW's record-literal grid · filed 2026-09-28 against master `4dc94bd23`**

Repro:

    type D = { v: i64 }
    function t(a: i32): i32 { a }
    const q = { v: 3 }
    print(t(q.v))
    // vl check: rc 0.  vl run: invalid module — type mismatch

Want:

    3

#### Mechanism

The widening face of [D2979](D2979.md). `q` is checked as `{v: i32}`. The record-literal row scan
still builds it at `D`, because the checker lets `{v: i32}` into `{v: i64}` (and into `{v: f64}`,
`{v: i32 | null}`, `{v: f64 | null}`), so a binding handed on to such a record through a
position the D2933 use walk does not follow (`c["k"] = q` into a `{[string]: D}` map, say) runs
only because the literal was built there. A read at the literal's own type then gets the row's
wider field: `i64` into an `i32` parameter, or `i32 | null` returned as `i32`. The `f64` row
converts at the read; `i64` and the two nullable rows do not. A close either builds the literal
at its own row and re-seats it at every delivery (the D2933 walk, widened to the map store), or
converts at the read.

#### Ablation

| ingredient removed | outcome | needed? |
| --- | --- | --- |
| the `i32` read (`print(q.v)`) | runs, prints 3 | **yes** |
| `i64` for `f64` (`type D = { v: f64 }`) | runs, prints 3 | **yes** |
| the missing annotation (`const q: { v: i32 } = { v: 3 }`) | runs, prints 3 | **yes** |

#### Grading list

The grid's other nine cells: `D = { v: i64 }` with the read inside a declared-`i32` function
return (`function h(): i32 { q.v }`), and `{ v: i32 | null }`, `{ v: f64 | null }` at that return
(the last with `{ v: 1.5 }` and `f64`), each with and without a constructed `D`. The map-store
spelling that must keep running: `const c: {[string]: { r: i64 }} = Map()` then `c["k"] = q`.
