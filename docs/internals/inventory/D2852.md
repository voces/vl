### D2852 — a closure returning an un-annotated parameter pinned to a literal set cannot print its result

**closed 2026-09-27 — the filed repro prints `y` · was loud emit reject, clause 2, the same on master `a41bd80e8` · closed by [D2900](D2900.md)'s edit: the call through the capturing lambda is copied per instance and typed at the instance's holes, so it reads the literal set · fixture `tests/cases/generics/hole-capture-lambda-at-pin.vl` · found by the #3220 round-2 `g2841` grid (`hb_captured_*`) · filed 2026-09-27**

Repro:

    type K = "x" | "y"
    const k: K = "y"
    function mk(x) {
      const g = () => x
      print(g())
    }
    mk(k)
    // vl check: rc 0.  vl run: emitProgram: print of a literal-union atom whose type carries no member texts

#### Mechanism

Not ablated to a rung. The instance pins `x` to the atom `K`, and the closure's result is the
atom, but the closure body is shared with the template, so the call's recorded type is the
hole. The print floor then finds an atom with no member set to render. Reading the same
value through a record field (`const o = { f: x }; () => o.f`) refuses the same way.
