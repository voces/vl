### D2749 — the second specialization of a lambda whose un-annotated parameter is the callee types a captured list as `i32` in its environment

**closed 2026-09-27 — the repro RUNS and prints `3` then `6` · was check-clean invalid wasm, the same on master `781f68091` · found grading D2748 · filed 2026-09-26 against master `92bed043d`**

Repro:

    function s1(xs: i32[]): i32 { xs.length * 3 }
    function s2(xs: i32[]): i32 { xs.length * 6 }
    function f() {
      const out = [7]
      const ap = (g) => g(out)
      print(ap(s1))
      print(ap(s2))
    }
    f()
    // vl check: rc 0.  vl run: invalid module inside `f`, expected i32, found (ref $type)

#### Mechanism

`ap` is specialized once per callback it is handed (`ap(s1)` and `ap(s2)` each get a clone
that calls its callback directly). The first clone's closure environment carries `out` as the
list it is; the second clone's environment struct is built with an `i32` field, so the list
is stored into an `i32` slot. Seen in the disassembly as two env structs for one capture,
`(struct (field (ref $list)))` and `(struct (field i32))`. Localised: `monoInstantiate` keeps
the template's slot, and its frame, for the first instance only, and pushed every later one with
`fnParent` -1. `captureValKind` types an env field by resolving the capture in the instance's
parent frame, so from module scope `out` resolved to nothing and the field fell to `i32`. Closed
by pushing a later instance under the template's own parent frame (still -1 for a top-level one).
