### D3103 — an `if`-join of a type parameter with a concrete value collapses to the parameter, so delivering it where the parameter is wanted is not refused

**check-clean invalid wasm · clause 1 · open · found grading [D3079](D3079.md)'s close · filed 2026-09-28 against master `d408f2da4`**

Repro:

    function f2<T>(x: T, c: boolean): T {
      return if c { x } else { 7 }
    }
    print(f2("s", false))
    // vl check: rc 0.  vl run: invalid module inside `f2`

#### Mechanism

Inside a generic body `joinTys(T, i32)` collapses to `T`, since a type parameter is assignable
either way there, so the `if` is typed `T` and its delivery to the `T` return records no constraint
a pin can refuse. At `T = string` the instance returns `7` as a `string`. The direct twin
`function f2(x: string, c: boolean): string` is refused (`return type mismatch: expected string, got
string | i32`). A list literal had the same collapse and now keeps the union ([D3079](D3079.md));
the `if`-join keeps it on purpose for the reads inside the body and re-joins only a binding of it at
the pin (D2893), which this delivery never reaches.

#### Ablation

| ingredient changed | outcome | needed? |
| --- | --- | --- |
| `function f2(x: string, …): string`, the direct spelling | check reject | **yes** (the type parameter) |
| `f2(3, false)`, an `i32` pin | prints `7` | **yes** (the pin differs from the arm) |
| no return annotation | prints `7` | **yes** (a destination typed `T`) |
| `const v = if c { x } else { 7 }` then `return v` | invalid wasm | no |
| `const v = …; const w: T = v; print(w)` | invalid wasm | no |

#### Grading list

The return, the `: T` binding and the relayed binding above, at `string`, record and list pins;
the `i32` pin and an un-annotated binding printed directly must keep running.
