### D6205 — a maker result called at a generic body's own type parameter is refused when the body is instanced at two types

**loud emit reject · `vl check` rc 0 · clause 2 · found closing [D6003](D6003.md) · the same on master `c6cd62ec1` · filed 2026-10-17 against master `c6cd62ec1`**

Repro:

    function k<T>(x: T): T { return x }
    function mk() { return k }
    function g<U>(u: U) {
      const a = mk()
      print(a(u))
    }
    g(1)
    g("z")
    // vl check: rc 0.  vl run: emitProgram: a generic function taken as a value reaches no call that fixes its type — annotate the destination's function type

Want:

    1
    z

#### Mechanism

From the ablation and D6003's close. The close records the call `a(u)` at the closed types
every flow walk agrees on. With two instances of `g` the walks disagree, so no type is
recorded, and `mk`'s `return k` has one signature for both instances.

Lane L1, 2026-10-17, measured by hand split. Copying `g` per instance (`g`, `g1`) is not
enough: it still refuses at `mk`'s `return k`, because one `mk` serves both copies. Copying
`mk` as well (`mk`, `mk1`, each called by one copy) runs, printing `1 z`. So a close copies
the body per instance and copies, per copy, every maker it calls. The plan reads only the
original parse, and a `reparseFuncDeclAt` copy is minted at apply, so the inner maker call has
to be retargeted inside a copy that the plan never saw.
