### D15712 — a maker's call handed through a generic identity to two records that store a field differently is refused, though the direct calls are copied where they land

**loud check reject · clause 2 · `{r: i32, g: i32} is not J: they store field \`r\` differently (\`i32\` into \`i32 | null\`), and a record is shared, not copied, so only a fresh record widens` · found closing D15691 by the fresh-call copy · filed 2026-11-11 against master `161d481c`**

Repro:

    type J = { r: i32 | null, g: i32 }
    type K = { r: i32 | null, g: i32 | null }
    function idn<T>(v: T): T { v }
    function mkB() { { r: 16, g: 1 } }
    const c: J = idn(mkB())
    const d: K = idn(mkB())
    print(c.r ?? 0)
    print(d.g ?? 0)

Want:

    16
    1

#### Mechanism

Not ablated. A direct call `mkB()` delivered at `J` or `K` is copied there (`recFreshCallCopy`),
but the delivered value here is the identity's call, whose function returns its parameter rather
than a fresh literal, so the copy is not offered and `recSitesLandApart` refuses each landing. The
identity's result is as fresh as its argument (`recSolePinArg`), so the copy could be recorded on
the identity's call.
