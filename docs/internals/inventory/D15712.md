### D15712 — a maker's call handed through a generic identity to two records that store a field differently is refused, though the direct calls are copied where they land

**closed 2026-11-11, runs and prints `16` then `1` · was a loud check reject, clause 2, `{r: i32, g: i32} is not J: they store field \`r\` differently` · closed by copying the identity's result (`recAdoptNote`, check_fit_rules.vl): a generic identity handed a maker's call directly hands back that fresh value, so the delivery copies the identity's call where it lands, as `recFreshCallCopy` does a direct call · graded by the `identity_at_kept_row` cell of the three `kept-maker-delivery*.matrix.vl` templates, emitting an invalid module before at the union and width rows · found closing D15691 · filed 2026-11-11 against master `161d481c`**

Repro:

    type J = { r: i32 | null, g: i32 }
    type K = { r: i32 | null, g: i32 | null }
    function idn<T>(v: T): T { v }
    function mkB() { { r: 16, g: 1 } }
    const c: J = idn(mkB())
    const d: K = idn(mkB())
    print(c.r ?? 0)
    print(d.g ?? 0)

Want:

    16
    1

#### Mechanism

Not ablated. A direct call `mkB()` delivered at `J` or `K` is copied there (`recFreshCallCopy`),
but the delivered value here is the identity's call, whose function returns its parameter rather
than a fresh literal, so the copy is not offered and `recSitesLandApart` refuses each landing. The
identity's result is as fresh as its argument (`recSolePinArg`), so the copy could be recorded on
the identity's call.
