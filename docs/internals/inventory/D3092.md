### D3092 — a union-returning `.map`'s result element is read as the first union the module registers, not the union its call holds

**closed · `mfResultSlotOf` and `collectMapFilterUse` name the result's ref-list row by the union the call's element holds at the instance's pin (`mapUnionResultRow`), interned per instance, where they named `unNames[0]` · fixture `tests/cases/generics/map-union-result-reads-its-pin.vl` · was loads then traps · clause 1 · found by the #3274 review (`rv3274-5974/p/n3.vl`, 7 cells at `i32 | null`, `f64 | null` and `i32 | string`) · the `<T>` spelling traps the same on master `d408f2da4`, the hole spelling was invalid wasm there and traps once #3274 builds its literal at the pin · filed 2026-09-28 against master `d408f2da4`, closed 2026-09-28 against master `f14a8cca2`**

Repro:

    type AB = "a" | "b"
    function f<T>(x: T) {
      print([x].map((e) => e)[0])
    }
    const v0: i32 | null = 4
    f(v0)
    // vl check: rc 0.  vl run: wasm trap: cast failure (before the close)

Want:

    4

#### Mechanism

Every value union shares one box, so a union-returning `.map` builds its result as a list of
boxes whatever union it holds. The row that list is read at was chosen as `unNames[0]`, the
first union the module registers: the result's element then carried that union's name, and
`print`, a narrowing or a `for` over it dispatched on that union's arms. With `type AB` first,
the `i32 | null` element was printed as `AB`'s string arm, a `cast failure`. With no literal union
but a second instance at another pin, the second instance's element was read at the first's
union and printed a wrong value (`null` for `1.5`), silently. The row is now the union the call's
element holds at the pin of the instance it is emitted in (`iterElemPinTy`, which also learned
the return of an inline `.map` callback), and `collectMapFilterUse` interns that row for every
instance holding a call whose recorded element names a type variable. The `for y in [x].map(…)`
face at a `boolean | null` `<T>` pin, which printed `1` for `true`, is the same pin read and closed
with it.
