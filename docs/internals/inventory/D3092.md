### D3092 — a `.map` over a one-element list of a boxed or nullable value traps with `cast failure` when the module declares a string-literal union

**loads then traps · clause 1 · open · found by the #3274 review (`rv3274-5974/p/n3.vl`, 7 cells at `i32 | null`, `f64 | null` and `i32 | string`) · the `<T>` spelling traps the same on master `d408f2da4`, the hole spelling was invalid wasm there and traps once #3274 builds its literal at the pin · filed 2026-09-28 against master `d408f2da4`**

Repro:

    type AB = "a" | "b"
    function f<T>(x: T) {
      print([x].map((e) => e)[0])
    }
    const v0: i32 | null = 4
    f(v0)
    // vl check: rc 0.  vl run: wasm trap: cast failure

Want:

    4

#### Mechanism

Not localised past the ablation. The alias is never used, so its effect has to come through a
module-wide table: the string-literal union's registration changes which box the `.map` result's
element is cast to. The hole spelling `function f(x)` is the same trap with #3274, which builds
the literal at the pin where master built invalid wasm.
