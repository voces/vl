### D3338 — a record literal handed through a generic identity call into a wider declared record is invalid wasm when a record of the literal's own field types is declared

**closed 2026-10-20 · runs, prints `4` · was check-clean invalid wasm, identical on master `2b30e3674`, then a loud check reject from 2026-09-30 · since [D7941](D7941.md) a literal argument that alone pins the call's instance is built at the destination, so a declared record of its fields no longer decides the verdict; a literal built inside a function and handed through is still built at that declared record and refused (`recBuiltAtDeclared`, [D8020](D8020.md)); the method-argument and `if`-join faces stay open as D3349-D3351 · fixtures `tests/cases/soundness/error-record-not-fresh-through-coalesce-call-or-escape.vl` and `tests/cases/soundness/record-literal-through-identity-ignores-unused-record.vl`**

Repro:

    type I = { f: i32 }
    type J = { f: i32 | null }
    function id<T>(v: T): T { v }
    const x: J = id({ f: 4 })
    print(x.f ?? 0)
    // vl check: rc 0.  vl run: invalid module, "expected (ref null $type), found (ref $type)"

Want:

    4

#### Mechanism

The literal is fresh, so the record storage rule lets it through (DECISIONS.md "Record covariance:
only a fresh value widens"), but the call pins `T` at the literal's own record, and with
`type I` declared the literal is built at `I`'s row; the call's result reaches `J`'s slot as an
`I`. The call is an ordinary generic instance, so neither the literal's re-seat nor the binding
adoption reaches it. Pinning `T` from the destination when the argument is fresh would build it
at `J`.

#### Ablation

| ingredient removed | outcome | needed? |
| --- | --- | --- |
| `type I = { f: i32 }` | runs, prints `4` | **yes** |
| the generic call (`const x: J = { f: 4 }`) | runs, prints `4` | **yes** |
| the field pair made `f: i32` both sides | runs | **yes** |

#### Grading list

The same through a literal-holding binding, `const s = { f: 4 }` then `id(s)`, and the other seven
field pairs of the grid (`i64`, `f64`, `O | null`, `i32 | string`, a nested record, `string | null`,
a string literal union into `string`, a record into a union of records).

#### Close (2026-09-30)

Closed by the owner's record-covariance ruling (DECISIONS.md "Record covariance: only a fresh value widens"). The literal is built where it is written, at the declared record of its fields, so it is an existing record by the time the call delivers it.

#### Close (2026-10-20)

Under the structural-records ruling a declared record of the literal's fields is the same type
as the literal's, so its presence cannot decide the verdict. [D7941](D7941.md) builds a literal
argument that alone pins the instance at the destination, and the witness prints `4`.
