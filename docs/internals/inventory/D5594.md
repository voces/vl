### D5594 — `match` over a single-literal type is refused as a union with literal members, while a two-literal union runs

**closed 2026-10-17 — the witness prints `b` · was a loud check reject, clause 2 · lane L3 (legality decided in one place): `matchLitSetTys` (`check_match.vl`) now names the member set of a lone literal, a one-kind literal union and either of them with `null`, and `checkMatchExprByScrut` dispatches on that set, so a lone `"b"` takes the member-string arms and integer sets take D5710's · fixture `tests/cases/match/lit-set-singleton-dispatch.vl` · found while minimising eardstap EV-009 · filed 2026-10-17 against master `44ed9635a`**

Repro:

    function f(k: "b"): string {
      match k { "b" => "b" }
    }
    print(f("b"))
    // vl check: match over a union with literal members is not supported — compare them with `==` in an if-chain, got "b"

Want:

    b

#### Mechanism

`matchScrutRejectMsg` (`check_leaf_steps.vl`) fires because a lone literal type is not a
union, so the scrutinee has no member set, and `unionHasLitMember` then names it a union. A
narrowing that leaves one literal (`if i.kind != "b" { return }` then `match i.kind`) reaches
the same refusal. A one-literal type is a one-member set, and the match over it is complete.
