### D3720 — a list filled once and read every pass is flattened, and each of its reads is slower than the boxed list's

#### Mechanism

The cost rule is static: it refuses a list whose read sites outnumber its store sites by more
than six whole elements per store, and it cannot know that the one store runs 1,024 times
while the read loop runs two million. A flat element read is one bounds-checked `array.get`
per field, plus a select that keeps `i * n` from wrapping (13–16% of the read), where a boxed
one is one `array.get` and unchecked `struct.get`s. Measured on the S2 bench (§7):
iterate-only over 1,024 elements, V8 22.1 ms boxed against 36.2 ms flat, wasmtime 39.0
against 67.4. The loss is an in-cache one: `bench/arrays/struct-aos` (10^6 elements, 500
read-only rounds) is faster flat, V8 0.93 → 0.62 s and wasmtime 1.51 → 1.26 s, because the
boxed list chases a pointer per element. Two ways out: a dynamic profile, or proving an index below the list's own
length so the select can go, which measured closes about a third of the gap on V8.
