### D2712 — a literal tree in a generic body is computed at 32 bits in the instance whose `T` is pinned `i64`

**closed 2026-09-30 — the owner's exact-constant ruling (A): `3 << 31` is a constant, exact before any instance reads it, so `g<i64>(0)` prints `6442450944` and `1 << 40` prints `1099511627776` · the `g<i32>` instance, which printed the 32-bit reading `-2147483648`, is now refused at the pin (`i32 cannot hold the 64-bit constant it meets`, a deferred `OP_LITFIT` constraint beside a type-parameter operand), as is the bare-literal spelling `x + 6442450944`, which built invalid wasm at `g<i32>` (D3426) · fixtures `tests/cases/generics/literal-tree-at-i64-instance.vl`, `tests/cases/generics/error-wide-constant-at-i32-pin.vl` · was check-clean silently wrong · clause 1 · found in the #3201 review (h10) · filed 2026-09-26 by lane PL47**

Repro:

    function g<T>(x: T): T { x + (3 << 31) }
    print(g<i64>(0))
    // PRINTS -2147483648

Want:

    6442450944

#### Mechanism

Not yet measured. D2709's operand adoption types a literal tree `i64` beside an `i64` operand,
but in a generic body the operand is `T`, so the check of the body sees no `i64` peer and the tree
keeps its `i32` reading; the `g<i64>` instance adds a sign-extended `-2147483648` (the i64
answer is `6442450944`). The body's nodes are shared by every instance (`g<i32>` beside `g<i64>`
must keep the i32 reading), so the adoption cannot be stamped on the node itself: the fix is a
per-instance width, the same question D2617 left open for `id(0xfffffffe)` at a hole.

#### Ablation

| ingredient changed | outcome | needed? |
| --- | --- | --- |
| `T` → `i64` in the signature | `6442450944` (D2709) | **yes** (a type parameter) |
| `3 << 31` → `1 << 40` | refused: `shift count 40 is out of range for an i32 operand` | no (D2710 sees the 32-bit reading; master printed 257) |
| also call `g<i32>(0)` | both print `-2147483648` | no |

#### Grading list

The `1 << 40` spelling above, which must then print `1099511627776` at `g<i64>` and still refuse
at `g<i32>`; the `g<i32>` instance must keep printing `-2147483648`.
