### D2318 — the lexer allocated a fresh string for every token, so a unit's half-million `(`, newlines and register names each held a 32-byte slice header for the whole compile

**closed 2026-09-24 — with D2317, plumb's `chunk_662` live set at its last collection 143 → 118 MiB (`$VL_GC_STATS=1`), output byte-identical · a memory cost, not a miscompile: the witness runs · filed 2026-09-24 against master `7e80d135c`**

Repro:

    function f(rax: i32, rcx: i32): i32 { (rax + rcx) * (rax - rcx) }
    print(f(5, 3))
    // runs, prints `16`. Every `(`, `)`, `rax`, `rcx` and newline in the file used to be its
    // own `gSrc.slice` header, retained by `P.toks` and the AST until the compile ends.

#### Mechanism

`mkTok` built each token's `text` with `gSrc.slice(start, gPos)`, one 32-byte GC header per
token. `P.toks` holds every token for the whole compile, so the headers are live at the emit
peak. In generated code nearly all lexemes are short and repeat: `chunk_662` has ~490K tokens,
93% of them four bytes or fewer, over 316 distinct spellings.

#### Fix

`lexText` interns every lexeme of one to four bytes in a per-`tokenize` open-addressing table
keyed by its packed bytes (length checked on a hit), so each short spelling is one string per
lex. The table is reset per source and sized to it (256 / 1,024 / 4,096 slots), so an editor's
instance never keeps an old file's bytes alive through it. The identifier path slices once
instead of twice. Longer lexemes are sliced as before.

#### Grading list

The three plumb units and a 332-file `tests/cases` + `std` sample byte-identical against
master's seed; the self-compile fixpoint.
