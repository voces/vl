#### Mechanism

D10795's rung, `monoOtherPinFns` (emit_mono.vl), leaves out the pins every function but the
named element takes in the parameter's fn-flow class, so it answers only when the element's body
does nothing with the parameter but call it. `apply3` hands `g` to `h`, whose call is the one
that pins it, and leaving `h`'s pins in while leaving the list sibling's out needs to know which
functions the parameter's value reaches by a call rather than by the list's merge. The rung
declines, and the class's two parameter lists disagree.
