### D17754 — an un-annotated local read from a record field of type `null` breaks the IR verifier's null-unit read rule

**closed 2026-11-27 by COV-UNION · runs, its witness prints its expected value · was a loud emit reject (internal compiler error, verifier rule 2) · a module binding's `null`-typed initializer that is a null-unit place read builds its null carrying that read (`nulNonePayload`, ir_build.vl), as the rule requires · pinned by `tests/cases/records/unit-field-read-into-module-binding.vl` · `fn-value-enclosing-param-into-generic-nullable` matrix 34 → 45 of 48 runs**

Repro:

    const w = { f: null }
    const v = w.f
    print(v == null)
    // vl check: rc 0.  vl run: internal compiler error (verifier rule 2)

Want:

    true

#### Mechanism

A module binding's `null`-typed initializer is run for its effects and then written as the
bottom null with no read (`nulNonePayload`). Where the initializer is itself a null-unit place
read (`w.f`), the verifier's rule 2 requires the null to carry that read, as a local's read
(`nulUnitPlaceRead`) does; the null carried none. A function body's local took that path already.
It is a different mechanism from D17752's: both are module bindings only.
