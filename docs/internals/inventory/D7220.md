### D7220 — a one-literal record field and the same field at a one-literal alias are one type, but rep apart: a `string` and an atom

**closed 2026-10-19 by lane L6 · runs, prints `circle` · was check-clean invalid wasm · clause 1 · a one-member string literal set reps as its literal at a record field: a string field code, and the canon field soften keys it as its literal, so both spellings share one struct row; the `utkStructText` guard stays, since the union box site still resolves a member by name ([D7340](D7340.md) is the list position) · pin: `tests/cases/structs/one-literal-alias-field-one-record.vl` · filed 2026-10-19 against master `ff910c059`**

Repro:

    type KC = "circle"
    type C = { kind: "circle", r: f64 }
    type Ca = { kind: KC, r: f64 }
    const a: C = { kind: "circle", r: 1.0 }
    const b: Ca = a
    print(b.kind)
    // vl check: rc 0 (it hints that `b` is inferred as `C`).  vl run: invalid module,
    // expected (ref null $1), found (ref $0); $1 is `Ca`, struct {mut i32, mut f64};
    // $0 is `C`, struct {mut (ref $5), mut f64}

#### Mechanism

The checker reads `KC` as the literal `"circle"`, so `C` and `Ca` are one record type
(D3870) and the delivery needs no copy. The emitter gives them two struct rows: a field
spelled with a named literal union reps as an interned `i32` atom, and a field spelled
with one inline literal reps as a `string`. The delivery then hands one struct to a slot
typed by the other. The same split is why lane L6's type-keyed union lookup has to check
`utkStructText` before `Ca | Ra` may share `C | R`'s row, and why `mintInlineUnion` cannot
key by type yet. Fix direction: decide a record field's rep from its canonical type, so
that one record type has one struct row. Either a one-literal alias field reps as a
`string`, or a one-literal inline field reps as an atom. The atom read paths
(`unions/discriminated-union-tag-read.vl`) grade whichever is chosen.

#### The close

The first direction was taken: a one-member string literal set reps as its literal at a
record field. `fieldCodeOfTy` and `fieldCodeOfSpelling` give it the string code, and
`repCanonFieldTy` keys it as its literal on both canon walks, so `C` and `Ca` share one
struct row. Two-member aliases keep the atom. The soften is field-only: at the union's own
canon arm it failed five oracle cases, so a `KC` value outside a record field keeps its rep.

The `utkStructText` guard stays. With it removed, `tagA(s: Ca | Ra)` was handed a `struct.new`
of `C | R`'s member struct while it takes the `Ca | Ra` row's, and the oracle trapped
(`illegal cast`): the union box site resolves a member by NAME against the adopted row, so
a row shared by type still needs the names to agree. `mintInlineUnion` stays name-keyed for
the same reason. Both move with step 5's slice 4, the type threaded to the box site.
