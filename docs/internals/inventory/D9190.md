### D9190 — a generic function held in a list element, a record field or a call result, called inside a generic body whose type parameter shares the callee's name, is check-clean invalid wasm

**closed 2026-10-21 — the filed repro RUNS and prints `ss`, `3` · was check-clean invalid wasm, `vl check` rc 0, `type mismatch` inside `f` · clause 1 · found closing [D9160](D9160.md) · filed 2026-10-21 against master `8747b6432` · closed at the root in check_relate_core.vl/check_subst.vl/emit_mono.vl: an instance binding substitutes only its own template's type variables, which replaces D9160's three point guards · found [D9220](D9220.md)**

Repro:

    function idg<T>(t: T): T { return t }
    function kg<T>(t: T): T { return t + t }
    const c = [1].length > 0
    function f<T>(v: T): T {
      const fs = [if c { kg } else { idg }]
      print(fs[0]("s"))
      return v
    }
    print(f(3))
    // was: vl check rc 0, vl run: invalid module, the emitted module failed to validate inside `f`

#### Mechanism

It is [D9160](D9160.md)'s ingredient at three more delivery positions. Bindings are
parallel name/type arrays, so substituting the instance `f@i32` (`T := i32`) into the
recorded type `(T) => T` of `kg` closed `kg`'s own `T` too. D9160 guarded three readers of
that substitution, and a list element, a record field and a call result are typed by others.

The fix is at the substitution. `substTyDeepOf` (check_relate_core.vl) substitutes with a
self owner set, and `substSkipsForeignSig` (check_subst.vl) leaves alone a function type
whose type variables all belong to another top-level generic, through the TyVar owner table
the checker already keeps. Every instance binding in the pin walk, the clone and the
`monoExactSub*` / `monoPinSub*` rows (now carrying their template owner) goes through it.
A call's own binding of the callee's parameters does not, so a call still closes its
callee's `T`. D9160's three guards are removed.

Alpha-renaming each generic's type parameters was the other choice. It would change every
recorded type and the spelling a diagnostic renders from it. The owner table already exists,
so skipping a foreign signature at the substitution changes no type and no message: `vl
check` over `tests/cases` is byte-identical before and after.

Removing the coincidence exposed [D9220](D9220.md): a read of such a choice was shared by
two instances. It is fixed in the same change.

#### Grading list

- The same list called at the body's own parameter, `print(fs[0](v))`. It loads, then traps with
  `indirect call type mismatch`.
- The choice held in a record field, `const r = { h: if c { kg } else { idg } }; print(r.h("s"))`,
  for both an `if` and a `match`.
- The callee returned by a function and called in the body:
  `function pick() { return kg }` then `print(pick()("s"))`. This fails even with no choice.
- Arms whose type parameters have different names (`idg<U>`, `kg<T>`) in a list element.

All of these run, in `tests/cases/generics/fn-held-in-generic-same-typaram.vl` and the matrix
`fn-value-held-in-generic-same-typaram` (48 of 48 cells, 0 on master).
