### D3081 — a nested generic that reuses its enclosing generic's type-parameter name reports its own demand against the outer binding

**closed 2026-10-08 by lane SC, with D3853, the same mechanism · runs · was a loud check reject, clause 2 · found by the review of [D3062](D3062.md)'s close · filed 2026-09-28 against master `e1e40ac99` · pins: `tests/cases/generics/nested-generic-redeclaring-type-parameter.vl`**

Repro:

    function takesI32(n: i32) { print(n) }
    function outer<T>(x: T) {
      function inner<T>(y: T) { takesI32(y) }
      inner(5)
      print(x)
    }
    outer("s")
    // vl check: argument of type string flows into `takesI32` expecting i32

Want:

    5
    s

#### Mechanism

A nested function's constraints are owned by the enclosing top-level declaration, and the
call site matches a constraint's `TyVar` by NAME, so `inner`'s `T` is substituted with the
`string` `outer("s")` binds to `outer`'s `T`. The program is well-typed: `inner` is called at
`i32`, and renaming its parameter makes it run.

#### Ablation

| ingredient changed | outcome | needed? |
| --- | --- | --- |
| `function inner<U>(y: U)` | prints `5` `s` | **yes** (the shared name) |
| `print(y)` in place of `takesI32(y)` | prints `5` `s` | **yes** (a deferred demand in `inner`) |
