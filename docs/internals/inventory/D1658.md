### D1658 — a covariant list written through a container the closure cannot name refuses at the emitter, where the design owes the checker's own `Writable` sentence

**now a loud check reject 2026-09-06 · was loud emit reject · filed 2026-09-05 against master `d2d7518b6` · D1656's residue · 0 corpus cells**

Repro:

    type Circle = { r: i32 }
    type Sq = { s: i32 }
    type Shape = Circle | Sq
    type Box = { xs: Shape[] }
    function f() {
      const a: Circle[] = [{ r: 7 }]
      const b: Shape[] = a
      const sf: Box = { xs: b }
      const sf2 = sf
      sf2.xs.push({ s: 3 })
      print(a.length)
    }
    f()
    // vl check: rc 1, `a Circle[] cannot be assigned to Shape[] here: the list is WRITTEN THROUGH`.

#### Mechanism

The write in this program DOES reach the covariant value, so the answer the design owes is the
`Writable` refusal D793 already writes — the one `sf.xs.push({ s: 3 })` gets, at the
assignment, from `vl check`. The alias closure could not see it because `cwEscapedFields`
filed the escaped list under the container's own name, and `cwBoundOnceSealed` refused to claim
a container reached under a second name, an unconsumed call result (`take(hand(b))`), or a
container handed to a function (`poke(nn)`). The state was `2`, so the checker's arm — which
fires on `1` — never ran, and D1656's emit refusal was what the program got instead.

Closed by growing the closure past the seal, in two edges that share one resolver. A container
is now an alias set of its own: `cwContainerAliases` walks the container's occurrences and
joins the name of a passthrough binding (`const sf2 = sf`), the plain-name target of a store,
and the PARAMETER a call argument delivers it to; every escape is filed under every name in
that set, so a read through any of them matches as a handle and a write through one is the
definite `1`. And a call result handed straight on as an ARGUMENT reaches that call's
parameter, which `cwGrow` binds and `cwReturnConsumed` counts as consumed — the same
`cwArgParamName` on both sides, so the closure and the claim cannot disagree. The half of the
same decline where nothing writes the value, and the program should run, is D1659.
