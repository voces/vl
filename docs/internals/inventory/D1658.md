### D1658 — a covariant list written through a container the closure cannot name refuses at the emitter, where the design owes the checker's own `Writable` sentence

**loud emit reject · filed 2026-09-05 against master `d2d7518b6` · D1656's residue · 0 corpus cells**

Repro:

    type Circle = { r: i32 }
    type Sq = { s: i32 }
    type Shape = Circle | Sq
    type Box = { xs: Shape[] }
    function f() {
      const a: Circle[] = [{ r: 7 }]
      const b: Shape[] = a
      const sf: Box = { xs: b }
      const sf2 = sf
      sf2.xs.push({ s: 3 })
      print(a.length)
    }
    f()
    // vl check: rc 0.  vl run: emit error, covariant list delivery.

#### Mechanism

The write in this program DOES reach the covariant value, so the answer the design owes is the
`Writable` refusal D793 already writes — the one `sf.xs.push({ s: 3 })` gets, at the
assignment, from `vl check`. The alias closure cannot see it because `cwEscapedFields` files
the escaped list under the container's own name, and `cwBoundOnceSealed` refuses to claim a
container reached under a second name, an unconsumed call result (`take(hand(b))`), or a
container handed to a function (`poke(nn)`). The state is `2`, so the checker's arm — which
fires on `1` — never runs, and D1656's emit refusal is what the program gets instead: correct,
loud, at the right node, and a clause-2 refusal by construction, since `check` returned 0.

Closing this is growing the closure past the seal: a second name for a sealed container is
still one container, and a call result delivered to a parameter is a handle the callee's own
body can be scanned for. Each shape ends with the write reaching the alias set, which turns
the emit refusal into the check refusal the author can act on. The half of the same decline
where nothing writes the value, and the program should RUN, is D1659.
