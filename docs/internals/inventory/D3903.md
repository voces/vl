### D3903 — a call through a `const` alias of a capturing nested generic from a lambda builds invalid wasm

**closed 2026-10-09 by lane SC · runs · was check-clean invalid wasm · found closing D3887 · filed 2026-10-09 against master `9170959d8` · pins: `tests/cases/generics/alias-of-capturing-nested-generic-called-from-nested.vl`**

Repro:

    function outer<T>(x: T) {
      function inner<U>(u: U) { print(x); print(u) }
      const k = inner
      const g = () => k(3)
      g()
    }
    outer(7)
    // vl check: rc 0.  vl run: invalid module inside `__lambda_1`, `expected structref, found i32`

Want:

    7
    3

#### Mechanism

Not located. One instance of `outer` is enough, so this is not D3887's cross-instance mix-up:
the call from the lambda reaches `inner` without its env. D3894's two-link alias gives the
same message.

Closed: the call is in a frame that does not declare the alias, which the alias-of-a-function
rungs ask only in the frame that declares it. D3894's chain walk (`monoGenFnAliasChainFe`) now
answers a one-link chain too, read from any frame, so the call reaches `inner` and its frame's
instance. The same holds for a call from a sibling function (review of #3479, `b1_sib_only`).
