### D8380 — an inferred-return function handing back a generic identity's record literal, delivered into a record union and also read at the literal's own type, returns the bare row into the union

**check-clean invalid wasm · `vl check` rc 0 · clause 1 · open · present on master `cd64d5faa` · found closing [D8341](D8341.md) · filed 2026-10-20 against master `cd64d5faa`**

Repro:

    type J = { r: i32 | null }
    function idn<T>(v: T): T { v }
    function deliver() {
      return idn({ r: 4 })
    }
    const v: J | string = deliver()
    const q = deliver()
    print(q.r)
    if v is J { print(v.r ?? 0) } else { print(0) }
    // vl check: rc 0.  vl run: invalid module, "expected (ref null $5), found (ref $6)": the union box expected, the `{r: i32}` row found

Want:

    4
    4

#### Mechanism

`deliver` is built once, at `{r: i32}`, since its second call site reads it at the literal's
own type, and the union delivery at the first site stores that bare `{r: i32}` ref with no
box and no conversion to `J`. The checker accepts the first site as a fresh record delivered
to the wider `J` (spelling `deliver(): { r: i32 }` refuses there, "only a fresh record
widens"), but with two sites at two types nothing builds the record at `J` for the first.
With the literal returned directly (no `idn`) the same two sites run, printing `4` twice:
`deliver` is then built at `J` and the second site reads `J`. The pin that decides it is the
checker's or mono's adoption of the fresh return, outside the emit-collect lane; a relative of
[D8301](D8301.md), a literal-building function delivered into two records of different storage.

#### Ablation

| change | outcome | needed? |
| --- | --- | --- |
| delete `const q = deliver()` and its print | prints `4` (the D8341 fixture) | **yes**, the second site at the literal's type |

| `print(deliver().r)` in place of the `q` binding | the same invalid module | no |
