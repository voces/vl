### D15902 — a hole lambda's bundle handed to an un-annotated parameter that hands it on to a parameter called at two signatures is refused at emit

**closed 2026-11-12, runs and prints `5` `2.5` · was loud emit reject · clause 2 · `emitProgram: a function value is called at two signatures, and the closure it holds was built for one` · found closing [D15744](D15744.md) · filed 2026-11-12 against master `bd8092cc` · closed in the elaboration: a parameter taking a record whole hands it on whole to a parameter its callee instance calls at the record's signatures, to a fixpoint along chains (`elabParamHandsNote`, over hands of parameters, `elabParamHands`); the bundle join follows a `const` copy of a parameter to it (`elabParamCopyRoot`); and the parameter and copy notes run again after a plain call's record (emit_elab.vl) · fixture `tests/cases/closures/hole-lambda-bundle-handed-on-copied-and-dropped.vl` · still refused: a hand from inside a lambda in the function, filed as [D15909](D15909.md)**

Repro:

    function lap(f) {
      f(2.5)
      f(3)
      return f
    }
    function take(b) {
      print(b(4))
      print(b(1.5))
    }
    function fw(a) { take(a) }
    fw(lap((a) => a + 1))

Want:

    5
    2.5

#### Mechanism

The bundle (the record of `lap`'s two instances of the lambda) is delivered whole to a parameter
called at both signatures (`take(lap(…))` runs), but a parameter that only hands it on is not
followed: `fw`'s `a` is one closure, and `take`'s two calls through it reach a closure built
at one signature.

#### Ablation

| spelling | outcome |
| --- | --- |
| `take(lap(…))` | runs |
| `fw(lap(…))`, `fw` calls `a` at one or two signatures itself | runs |
| `fw(lap(…))`, `fw` hands `a` to `take` | refuses (function value at two signatures) |
| `fw` hands `const v = a` to `take` | refuses (mono) |
| the bundle from a named or lambda returner, or a module `const` holder | refuses the same |
