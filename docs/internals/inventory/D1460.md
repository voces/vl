### D1460 — a mixed-spelling discriminant refused when one arm's set held ONE member, because `tyIsLitUnion` declines a bare `TyLit`

**closed · 1 witness plus a 50-cell position matrix · filed 2026-09-03 against master `44394ae5`**

Repro:

    type K1 = "circle" | "round"
    type A = { kind: K1, r: f64 }
    type B = { kind: "a", r: f64 }
    function f(n: i32): A | B {
      if n == 0 { return { kind: "circle", r: 1.0 } }
      const v: B = { kind: "a", r: 2.0 }
      return v
    }
    const a = f(0)
    if a is A { print(a.kind) } else { print("notA") }
    // vl check: rc 0.  vl run: emitProgram: union `A|B` discriminates `A` from `B`
    // on a literal field whose two arms rep differently

#### Mechanism

D1050 lays a mixed-spelling literal discriminant out under the interned-ATOM rep, gated by
`litFieldRowIsAtomisable` — code 0 or 3, plus `tyIsLitUnion` on the field's own arena type.
`tyIsLitUnion` requires a `TyUnion`, so it answers NO for a bare `"a"`, and the pair fell to
`assignTags`' capability refusal. The bound was recorded in DECISIONS as "a 2+-member set",
but the member count was never the rep's question: `type KC = "a"` — a ONE-member alias — is
a one-member `TyUnion`, codes 0, and emits `(struct (field (mut i32)) …)` with the interned
id today. The gap was the SPELLING, not the size. `tyIsLitUnionOrLit` is the predicate that
already asked the right question (it exists for `emitStrToAtom`'s one-member narrowing), and
the promotion needed three things to follow it: the read classifiers
(`variantFieldIsLitUnion` / `sFieldIsLitUnion`) to accept the bare `TyLit` sidecar,
`promoteLitFieldToAtom` to have a NAME for a set `litUnionInlineNameOfTy` declines below two
members, and the widen ladder to find the member texts — `nodeLitUnionMemberTexts` declines a
bare `TyLit` on purpose, so `emitAtomToStr` and `print`'s atom arm now share
`litAtomWidenTexts`, whose third rung reads the node's own type kind-blind.

#### Ablation

| ingredient removed | outcome | needed? |
| --- | --- | --- |
| the alias `K1` on arm A (both arms inline) | runs on master | **yes** |
| `B`'s bare literal widened to `"a" \| "b"` | runs on master | **yes** |
| `B`'s bare literal named by an alias `type KC = "a"` | runs on master | **yes** |
| the `const v: B` annotation (bare `return { … }`) | still refuses on master | no |
| `f64` field `r` | still refuses on master | no |
