**closed · now runs, prints `4` then `4` · was a loud check reject, clause 2 (the refusal said `type-valid but not supported yet`) · the residue of [D14819](D14819.md) · filed 2026-11-03 against master `7f8f65fc8` · closed by the PR that filed D15128: the node a function's result row is read from is named by one check-side walk (`retValueRootCall`, check_store_rep.vl) and stamped by the store column (`storeRetsResolve`), so `recFnResultLeaf` is deleted · fixture `soundness/built-container-read-by-rep-result-returned-by-another-function-runs.vl` · a by-rep result handed to a hole parameter beside an own-storage call of the identity is [D15128](D15128.md)**

Repro:

    type J = { f: i32 | null }
    function mk() { { f: 4 } }
    function back(r) { return r }
    const wideJ: J = mk()
    const xs = [mk()]
    function g() { return back(xs[0]) }
    print(g().f)
    print(wideJ.f ?? 0)
    // vl check: this {f: i32} is stored at J, ... type-valid but not supported yet

#### Mechanism

`back(xs[0])` reads where `xs[0]` does (`recIdentityReadsBuilt`, check_fit_rules.vl), but a
value another function returns was refused (`recFnResultLeaf`). Accepting it was check-clean
invalid wasm once `back` also had an own-storage instance (`back(plain)` beside it): `g`'s result
was emitted at the base instance's `{f: i32}`, while the call returns the by-rep instance's `J`.
The result row now comes from the checker's stamp on the returned value's root call.
