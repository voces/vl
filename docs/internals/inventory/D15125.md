### D15125 — a by-rep identity's result returned by another inferred function refuses

**open · loud check reject · clause 2 (the refusal says `type-valid but not supported yet`) · the residue of [D14819](D14819.md) · filed 2026-11-03 against master `7f8f65fc8`**

Repro:

    type J = { f: i32 | null }
    function mk() { { f: 4 } }
    function back(r) { return r }
    const wideJ: J = mk()
    const xs = [mk()]
    function g() { return back(xs[0]) }
    print(g().f)
    print(wideJ.f ?? 0)
    // vl check: this {f: i32} is stored at J, ... type-valid but not supported yet

Want:

    4
    4

#### Mechanism

`back(xs[0])` reads where `xs[0]` does (`recIdentityReadsBuilt`, check_fit_rules.vl), except as
a value another function returns (`recFnResultLeaf`). There the identity's argument is refused
as D14819's were. Accepting it is check-clean invalid wasm once `back` also has an own-storage
instance (`back(plain)` beside it): `g`'s result is emitted at the base instance's `{f: i32}` while
the call returns the by-rep instance's `J`.

#### Ablation

| ingredient removed | outcome | needed? |
| --- | --- | --- |
| `back` (`return xs[0]`) | runs | **yes** |
| `const wideJ: J = mk()` | runs | **yes** |
| `back(xs[0])` held first (`const c = xs[0]; return back(c)`) | still refuses | no |
