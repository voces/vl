Repro:

    function id<T>(x: T): T { x }
    const m = Map()
    m["k"] = { f: id }

Want:

    2

#### Mechanism

The map's value type is taken from the parameter types its calls pin on the stored slot
(`monoStoredSlotFnTy`, emit_mono.vl), and one slot holds one closed type: with two pins it
read -1. A list literal holding the same record runs because `monoFlowReads` rewrites each
call through an element to the name of the generic it holds and marks the stored values
inert; an un-annotated `Map()` was never one of its containers. A per-type copy of the map
(the `fn_split` lanes) was not taken, since the writes follow the binding and would each need
copying per call type, and the `r != null` narrowing does not carry to a copied binding.
