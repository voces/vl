### D3274 — an object field whose value starts on the line after its `:` was a parse error

**closed 2026-09-29 (`parseObjLit` in `compiler/parser.vl` skips line breaks after a field's `:`, as `parseOneArg` does after a named argument's) · was a parse error of a legal program, clause 2 · found by the #3299 review grid · filed against master `296e1141d` · fixture `tests/vl_label_block_object_test.ts` (`vl fmt` joins the lines, so the shape lives in a source string)**

Repro:

    const b = 3
    const v = { a:
      { c: { b } } }
    print(v.a.c.b)
    // was: parse error, expected an expression but found NEWLINE
    // now: prints 3

Want:

    3

#### Mechanism

`parseObjLit` skipped line breaks around fields and separators but not between a key's `:` and
its value, so the value's parse met the NEWLINE. A field needs its value, so the break ends
nothing and skipping it is unambiguous. `looksLikeObject` already called `{ a:\n …` an object
(a labelled block needs its `{` on the label's line), so no body changes reading.
A label whose loop or block starts on the next line (`a:\n  while …`, `a:\n  { n = 5 }`) is not a
field value; it gets one diagnostic naming `a: while …`, where master gave three.

#### Ablation

| ingredient changed | outcome | needed? |
| --- | --- | --- |
| the value on the `:` line | ran | **yes** |
| a scalar value `b` instead of `{ c: { b } }` | parse error | same family |
| a blank line between `:` and the value | parse error | same family |
| a function body's tail object instead of a `const` | parse error | same family |

#### Grading list

Object shapes `{ a:\n { c: { b } } }`, `{ a: { c:\n { b } } }`, `{ a:\n b }` and
`{ a:\n\n { c:\n { b } } }` at the grid's 12 non-`match` positions: 48 cells, parse error → run
with the right value. `{ a:\n {}, x: b }` now parses and then grades exactly as its one-line
spelling does (the checker's `{}` refusal, except at the argument position, which runs).
`vl fmt` joins the value onto its key's line.
