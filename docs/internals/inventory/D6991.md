### D6991 — an uncalled hole function bound through an `if` expression and called through the binding is refused at emit

**closed 2026-10-19 by lane L1 · runs, prints `a!` · was loud emit reject · `vl check` rc 0 · clause 2 · CAPABILITY: the same program with `exclaim(s: string)` runs, and `const x = exclaim` called as `x("a")` runs · a call through an un-annotated, never-written binding of an `if` naming generic functions in every arm, through a chain of copies of one, or of the `if` itself, instances each arm at the type the call takes the first one at, and retypes the `if` to it · pins: `tests/cases/closures/hole-fn-if-bound-called-through.vl`, `tests/cases/closures/hole-fn-if-bound-called-compared.vl` · found closing [D6981](D6981.md) · present on master `4ad81c0e0` · filed 2026-10-19 against master `4ad81c0e0`**

Repro:

    function exclaim(s) { return s + "!" }
    const x = if true { exclaim } else { exclaim }
    print(x("a"))
    // vl check: rc 0.  vl run: emitProgram: cannot take the generic function `exclaim` as a value — a function value carries ONE signature

Want:

    a!

#### Mechanism

A call through a binding of a hole function instanced the function at the call's argument types
only when the binding's initialiser named it directly. An `if` expression of the name was not
followed, so the hole function stayed a value with no signature. `monoCallIfBound` now follows
the binding (through un-annotated `const` copies) to an `if` initialiser, and `monoCallIfValue`
takes an `if` called directly. Each instances the first arm at the call, coerces every arm to
that signature (`monoCoerceFnValueName`), and records the closed type on the `if` and the read
(`monoRetypeIfInit`), where the emitter looks for the call's signature. A written `let` seeded
by an `if` takes the same route through `monoCallWrittenLet`.
