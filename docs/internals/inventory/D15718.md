### D15718 — a literal binding built wider, stored into an un-annotated map beside a literal, is stored at the map's own row

**closed 2026-11-11 · now a loud check reject, `set: expected {f: i32}, got J (`o` holds only a literal, so it is built as the `J` it is delivered to; …)` · DESIGN (orchestrator ruling 2026-11-11: an un-annotated container is pinned by its first store, and `o` is the `J` it is built as, so a later store of it into the `{f: i32}` slot is the type mismatch `const o: J` gets there; building the map at `J` whatever the order would make the un-annotated spelling more permissive than the annotated one) · the refusal (`recBuiltStoresRefuse`, check_program.vl; `recStoreMismatchMsg`, check_fit_rules.vl) says the container's mismatch, as the index write and push did and do · was check-clean invalid wasm, clause 1 · graded by `scripts/capability-probes/matrix/literal-binding-built-wider-store.matrix.vl`, the after-literal map set, index write and push owed in both faces · present on master `ebbc4bc2` · found rewriting the box-dst shadow's `storelit` witness for #7200 · filed 2026-11-11 against master `ebbc4bc2`**

Repro:

    type J = { f: i32 | null }
    const o = { f: 4 }
    const wideJ: J[] = [o]
    const m = Map()
    m.set("b", { f: 5 })
    m.set("a", o)
    const x = m.get("b")
    if x != null { print(x.f + 1) }
    print(wideJ[0].f ?? 0)

Want:

    6
    4

#### Mechanism

Not ablated past the table. `o` is a literal binding built at `J`, since a `J[]` takes it. The map
holds `{ f: 5 }` at its own `{f: i32}` row and is handed `o`, which is a `J`: one map, two storages.
A later `.set` at the slot's type was no own-storage delivery, and the list literal's build is
recorded after the kept judgement, so nothing judged the store. `recBuiltStoresRefuse` runs once
the list literals are built and refuses it, in the words the container's store gives a `J`.
