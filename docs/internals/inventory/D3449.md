### D3449 — an operator over a union of numeric types is refused, so a join of two runtime numbers cannot be computed with

**closed · runs, prints `3`, `true`, `1.25`, `false` · was a loud check reject · owner ruling on numeric joins, 2026-09-30: arithmetic on a numeric union dispatches per member · fixture `tests/cases/numerics/numeric-union-dispatch.vl` · closed 2026-09-30**

Repro:

    function f(c: boolean, x: f64, y: i32) {
      const r: i32 | f64 = if c { x } else { y }
      print(r / 2)
      print((r / 2) is i32)
    }
    f(false, 2.5, 7)
    f(true, 2.5, 7)
    // vl check: operator '/' is not defined for i32 | f64 and i32

Want:

    3
    true
    1.25
    false

#### Mechanism

The checker's arithmetic tail took a union operand as not numeric and refused it; the emitter had
no lowering for an operator over a box. Now `numUnionBinTy` types each member pair by the scalar
rule (`numPairOpTy`: a literal adapts, `i32` widens into `i64` or `f64`, `f32` into `f64`) and
answers the union of the pair results, or boolean for a comparison, refusing a pair the scalar rule
refuses (`i64` beside `f64`). The emitter (`emitNumUnionBin`) evaluates each operand once into a
lazy-frame stash keyed by nesting depth, dispatches on the box tag, runs the pair at its own type
and re-boxes the result. Unary minus, `+=` (its desugared `=`), an infallible `as`, a generic pin
(`monoNumUnionOpPin` re-types the operator at the pinned operand types) and a hole take the same
path.
