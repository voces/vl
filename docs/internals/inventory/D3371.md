### D3371 — a function-typed `let` a closure assigns after capturing it has no shared cell without an initializer

**loud emit reject · pre-existing, found by the #3295 review · filed 2026-09-30 against master `6e6a5301b`**

Repro:

    function h(n: i32): i32 {
      let q: (i32) => i32
      q = (x: i32) => x + n
      const w = () => {
        q = (x: i32) => x * 100
        0
      }
      w()
      q(n)
    }
    print(h(3))
    // vl check: rc 0.  vl run: `q` is assigned after a closure captures it, so the closure shares it, and a shared binding of its type needs an initializer: give `q` one

Want:

    300

#### Mechanism

A closure that assigns a captured binding boxes it into a one-element cell, built from the
binding's initializer (`cboxBoxLet`), and a binding with none gets a zero value only for the
scalar types `cboxZeroInit` knows. A function type has no zero, so the capture refuses. Since
D3256 the binding itself is a nullable closure cell, so the box could start at `null` the same
way; a closure that only reads the binding already runs.

#### Ablation

| ingredient removed | outcome | needed? |
| --- | --- | --- |
| the closure's assignment (it only calls `q`) | runs | **yes** |
| the missing initializer (`let q: (i32) => i32 = (x: i32) => x`) | runs | **yes** |
