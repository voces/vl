### D16044 — an `i8` field of a `flat` record accepts a literal above 127 and reads it back unnarrowed

**closed 2026-11-13 · now a loud check reject, `` the literal 200 does not fit an `i8` field (-128..127) `` · was check-clean silently wrong · the field is range-checked as `u8` (0..255), so `200` passes · filed 2026-11-13 against master `57cda2b6`**

Repro:

    flat type P = { a: i8, c: i32 }
    const p: P = { a: 200, c: 7 }
    print(p.a)
    // PRINTS 200

#### Mechanism

A `flat` field's sub-word width has no type of its own: every width resolves to `u8` (D15978).
The literal check therefore asks whether `200` fits a `u8`, which it does. The owner ruling (a)
(DECISIONS, "A sub-word field of a `flat` record has storage semantics") refuses a visibly
out-of-range literal at the field's own width, so `200` in an `i8` field is a check error owed by
the design. The value is then stored in an `i32` slot and read back as `200`.

#### Ablation

| ingredient changed | outcome | needed? |
| --- | --- | --- |
| `a: i8` with `100` | runs, `100` | **yes** (above 127) |
| `a: u8` with `200` | runs, `200`, correct | **yes** (the signed width) |
| `a: i8` with `300` | refused, `does not fit a \`u8\` element` | **yes** (inside 0..255) |
| `a: i16` with `40000` | refused as `u8`; an `i16` literal `200` runs | — |

#### Grading list

Closes with D15978's build. The literal must become a check refusal naming `i8` and its range
(the `literal_out_of_range` cell of `scripts/capability-probes/matrix/flat-sub-word-i8.matrix.vl`,
an owed refusal). A computed `200` in the same field must read back `-56`.
