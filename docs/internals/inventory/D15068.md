### D15068 — a one-element list literal of a hole function, iterated inside a hole function and handed that function's own parameter, is invalid wasm

**check-clean invalid wasm · clause 1 · open · with the split plan on and off · removing the `ftFwdFn && ftInOpenFn` veto in `ftScan` (check_fn_tag.vl) builds it, and refuses the running fixture `closures/forwarded-hole-fn-to-list-element-value-param.vl` and D15100 at emit, so that alone is not the close · found grading D15062 item 2's hazard spellings · filed 2026-11-03 against master `1484b3d7`**

Repro:

    function add(a, b) { return a + b }
    function apply2(g) {
      print(g(1, 2))
    }
    function viaFor(h) {
      for f in [apply2] { f(h) }
    }
    viaFor(add)
    // vl check: rc 0.  vl run, before: the emitted module failed to validate inside `viaFor`: type mismatch: expected (ref $type), found i32

Want:

    3

#### Mechanism

`ftScan` declines the set of `[apply2]` when the literal sits in an open function (`viaFor`) that
hands a function on (`f(h)`), before asking `ftHoldCtxOk` whether the literal is a holder there.
The declined set leaves `apply2` untagged while the call through `f` is emitted as a dispatch, so
`h` reaches `apply2`'s parameter as an `i32` id where a closure is expected. Removing the veto
builds the witness, but the same veto keeps a forwarded list call's sets closures where a member
calls its parameter at two signatures, so a close has to keep that case declined.
