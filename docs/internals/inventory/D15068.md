#### Mechanism

`ftScan` declines the set of `[apply2]` when the literal sits in an open function (`viaFor`) that
hands a function on (`f(h)`), before asking `ftHoldCtxOk` whether the literal is a holder there.
The declined set leaves `apply2` untagged while the call through `f` is emitted as a dispatch, so
`h` reaches `apply2`'s parameter as an `i32` id where a closure is expected. Removing the veto
builds the witness, but the same veto keeps a forwarded list call's sets closures where a member
calls its parameter at two signatures, so a close has to keep that case declined.
