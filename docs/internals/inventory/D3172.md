### D3172 — `??` over a value narrowed to `K | null` out of a wider box is refused

**loud emit reject · clause 2 · found by lane WV's D3161 grid (`narcopy`, the `K | null | i32` `coal` cells, 8 of 232, every copy spelling) · the same on master `a0b9acaf8` · filed 2026-09-29 against master `a0b9acaf8`**

Repro:

    type K = "a" | "b"
    function t(e: K | null | i32) {
      if !(e is i32) {
        print(e ?? "b")
      }
    }
    t("a")
    t(null)
    // vl check: rc 0.  vl build: emitProgram: `??` over this nullable value is not supported
    // yet — narrow it first, e.g. `if v != null { … }`

Want:

    a
    b

#### Mechanism

Not localised past the ablation. The narrowed read of `e` is typed `K | null` while its value is
still the box, and `??`'s lowering has an arm for the `K | null` atom niche and for a box
holding a nullable scalar, but not for a box narrowed to the literal-union niche. Annotating a
copy (`const c: K | null = e`) converts at the binding, and then `??` runs.

#### Ablation

| ingredient changed | outcome | needed? |
| --- | --- | --- |
| `e: K \| null`, no box | runs | **yes** (the box) |
| `string \| null \| i32` narrowed the same way | runs | **yes** (the literal union) |
| `if e != null { … } else { … }` | runs | **yes** (the `??`) |
| `const c: K \| null = e`, then `c ?? "b"` | runs | **yes** (the direct read) |
| a module-scope walk over `(K \| null \| i32)[]` | the same refusal | no |
| `const c = e`, then `const f = () => c ?? "N"` (the #3284 review) | the same refusal | no |

#### Grading list
