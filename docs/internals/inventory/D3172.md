### D3172 — `??` over a value narrowed to `K | null` out of a wider box is refused

**loud emit reject · clause 2 · found by lane WV's D3161 grid (`narcopy`, the `K | null | i32` `coal` cells, 8 of 232, every copy spelling) · the same on master `a0b9acaf8` · filed 2026-09-29 against master `a0b9acaf8` · bucket (d), L1 typed IR, secondary (e) (the 2026-11-14 clause-2 map)**

Repro:

    type K = "a" | "b"

      }

#### Mechanism

Not localised past the ablation. The narrowed read of `e` is typed `K | null` while its value is
still the box, and `??`'s lowering has an arm for the `K | null` atom niche and for a box
holding a nullable scalar, but not for a box narrowed to the literal-union niche. Annotating a
copy (`const c: K | null = e`) converts at the binding, and then `??` runs.

Not an emit fix (2026-11-17): lowering the `??` as the null test it spells (`coalNullTestIf`) builds
invalid wasm, because the synthesized present-arm read is the raw box. The checker never typed that
read, and `coalNarrowedReRead` leaves an `Ident` unnarrowed. A close types the re-read at check (a
rewrite before check, or a narrowed twin the checker records). The closure face of the grading list
(`const c = e; const f = () => c ?? "N"`) now runs.

| a module-scope walk over `(K \| null \| i32)[]` | the same refusal | no |
| `const c = e`, then `const f = () => c ?? "N"` (the #3284 review) | the same refusal | no |
