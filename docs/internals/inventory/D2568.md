### D2568 — an inferred `K | null` return over a NUMERIC literal union is floored by the checker, though its annotated twin runs

**loud check reject · clause 2 · pre-existing on master `dcc88a350` · filed 2026-09-26, found by D2567's `lambda-inplace-nullable-litunion` position matrix (`return_inferred`, both faces)**

Repro:

    type LN = 1 | 2
    function pLN(): LN | null { return 2 }
    function f() { return pLN() }
    print(f() ?? 0)
    // vl check: 'f' infers the nullable return type LN | null — type-valid, but an inferred
    // return of this shape is not yet supported by codegen; annotate the return type

#### Mechanism

The nullable arm of the inferred-return floor in `typecheck.vl` admits a `K | null` whose inner
has a literal-union alias name (`litUnionAliasNameOfTy`), and its comment says the `K | null`
niche lowers un-annotated. A numeric literal union (`1 | 2`) is not admitted by that test, so
the floor fires; the string twin (`type LN = "a" | "b"`) runs. Not located further: whether the
emitter's inferred-return cascade then serves a numeric `K | null` is the open half.

#### Ablation

| ingredient removed | outcome | needed? |
| --- | --- | --- |
| the inferred return (`f(): LN \| null`) | runs, prints `2` | **yes** |
| the numeric literals (`type LN = "a" \| "b"`) | runs, prints `b` | **yes** |
| a lambda (none in the repro) | still refuses | no |
