### D16822 — a nullable literal-union atom compared with a string widens to a nullable ref and reaches the non-null string compare

**check-clean invalid wasm · found by lane IR-C while writing compiler code · filed 2026-11-16 against master `69032f02`**

Repro:

    type P = "i32" | "str"
    function pick(n: i32): P | null {
      if n == 0 { return null }
      return "str"
    }
    function bad(n: i32, w: string): boolean { return pick(n) != w }
    print(bad(0, "str"))
    print(bad(2, "str"))
    // vl check: rc 0.  vl run: invalid module, `bad` fails to validate:
    // type mismatch: expected (ref $0), found (ref null $0)

#### Mechanism

The compare routes to `emitStrEq`. A `P | null` value is an atom niche: an i32, with -1 for null.
`emitStrValue` widens it to its member string through `emitAtomToStr`, which writes `ref.null` for
the -1 niche, so the operand is a `(ref null $string)`. `emitEqRecoverNarrowed` does not recover
it, because the operand is not a narrowed read. The non-null core `__str_eq__` then receives a
nullable ref. The nullable-niche guard (`emitNulNicheEq`, `binEqNulNiche`), which `string | null`
takes, does not claim an atom niche beside a string.

The expected output is `true`, then `false`: `null != "str"` holds, and `"str" != "str"` does not.

#### Ablation

| ingredient removed | outcome | needed? |
| --- | --- | --- |
| the `null` member (`P` instead of `P \| null`) | runs, prints `true` / `false` | **yes** |
| the literal union (`string \| null` instead of `P \| null`) | runs | **yes** |
| `!=` replaced by `==` | still invalid wasm | no |
| the call read bound to a local first (`const p = pick(n)`) | still invalid wasm | no |
| a `const` string compared instead of the parameter `w` | runs | **yes** |

#### Grading list

- `==` over the same operands.
- The operands swapped (`w != pick(n)`).
- A nullable literal-union record field compared with a string.
