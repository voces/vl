### D4062 — `b is A` is refused as "can never match" when `b`'s declared record type is contained in `A`, though every such value fits `A`

**closed 2026-10-11 · runs today and must keep running · was loud check reject · clause 2 · found by the review of #3544 (lane SPEC) · filed 2026-10-11 against master `98a4ed71b`**

Repro:

    type A = { x: i32 }
    type B = { x: 1 | 2 }
    function g(b: B): boolean { b is A }
    print(g({ x: 1 }))
    // vl check: rc 0.  vl run: rc 0, prints true
    // (was vl check rc 1, "`is` check type 'A' can never match a value of type B")

Want:

    true

#### Mechanism

By the owner's ruling on D3885 (A, 2026-10-10), `is` tests whether the value fits the type.
Every value of `B` has an `x` of `1` or `2`, which fits `A`'s `i32`, so `b is A` always
holds. The checker's test for an impossible `is` treats two different record types as
disjoint when neither is a member of the other, and refuses with a sentence that is the
opposite of the truth. It is the mirror of D4058, where the contained direction folds to
`true` without reading the value. An always-true test is at most worth a hint; the
same-type test `b is B` runs with none.

Closed by `recFitMeetTy` in the checker, beside the literal-set meets: over `B` or `B | null`
the test is banked as `is B`, and over a union it is banked as the one member that can fit
`A`, when every other member is a non-record or a record missing a field `A` requires. The
then-arm narrows to that member.

#### Ablation

| variant | outcome |
| --- | --- |
| `b: B`, `b is A`, `B = { x: 1 \| 2 }` | refused, "can never match" (wrong) |
| `A = { k: string }`, `B = { k: "p" }` | refused, "can never match" (wrong) |
| `b: B \| null`, `b is A` | refused, "is not a variant of B \| null" (wrong) |
| `b: B \| C`, `C = { z: string }`, `b is A` | refused, "is not a variant of B \| C" (wrong) |
| twin shapes, `A = C = { x: i32 }`, `b: C`, `b is A` | runs, `true` |
| same type, `b: B`, `b is B` | runs, `true` |
| scalar, `n: 1 \| 2`, `n is i32` | runs, `true` |

`B = { x: i32, y: i32 }` against `A = { x: i32 }` is refused the same way; whether a wider
record fits a narrower one is not settled by D3885, so that variant is not graded here.

#### Grading list

Each refused row should run and print `true`, alongside D4058's rows: the two rows close
together, since both are the record arm of the value-fit rule.
