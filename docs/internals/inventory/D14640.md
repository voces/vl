### D14640 — an instance's elaboration types a join over a literal type argument at the literal, where mono widens the argument

**runs today and must keep running · a named floor, no wrong value: `emitNullLitNode` keeps the destination's seed where the instance's own `null` stamp names another null · filed 2026-10-28 against master `add376795`**

Repro:

    type K = "a" | "b"
    function n<T, U>(a: T, b: U, k: i32) {
      const r = if k == 0 { a } else if k == 1 { b } else { null }
      return r
    }
    const y: K = "a"
    print(n("x", y, 0))
    print(n("x", y, 2))

Want:

    x
    null

#### Mechanism

The call binds `T` from the literal argument `"x"`. The monomorphiser widens it, so the instance
takes `T = string` and stores `r` as a `string | null` ref. The instance's elaboration checks
the join at the literal, so it types it `"x" | "a" | "b" | null`, a literal union, and stamps the
`null` arm with that union's sentinel `-1`. Lowered from that stamp, the arm is an i32 where the
block wants a ref, which fails validation. `emitNullLitNode` therefore keeps the destination's
seed wherever an instance stamp and the seed name different nulls. Deletion target: the
elaboration widens a literal type argument as mono does, after which this program's two
answers agree and the seed comparison goes.
