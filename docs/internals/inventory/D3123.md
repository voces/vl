#### Mechanism

An anonymous object literal gets its struct row from `anonMintRowFor`, which codes each field
through `anonFieldCode`. A map was coded only by the syntax rung's `Call` arm. A map fed by a
binding, an annotated parameter or a member read fell through to the recorded-type rungs, where
`anonTySpellable` declines a `TyMap`. The field coded -1, the literal minted no row, and the
function's inferred return type then had no shape at `fbValtype`. The fix is a recorded-type
rung for a plain map, behind the same lowerability gate the call arm uses. The field's
companion (`anonFieldElemName`, which gives the mv-slot key) rendered the map's value with
`tyToEmitName`. At the root that widens a literal union to `string`, so a `{[K]: "a" | "b"}`
field keyed a string-valued slot while the map itself is the i32-atom map. That was check-clean
invalid wasm on master through the call arm as well, and the nullable map arm (code 29) had the
same fault. Both codes now read the key through `anonMapValName`, which asks
`litUnionAliasNameOfTy` first, and that gives the key `mapValNameOf` cuts from the declared spelling.

A row for the literal has two consumers the rung had to be taught about. A generic call whose
parameter is a record pattern (`g<T>(b: { m: T })`) pinned the argument at its `#anonN` row
name, which has no fields to bind `T` from, so the monomorphiser refused. That refusal was
already on master for every inline record argument (`g({ m: 5 })`); master's binding-fed map
field escaped it only by having no row. The composite arm now pins such an argument at the
checker's spelled shape, unless a literal anywhere in the type or its fields would be softened
by the render (`monoAnonArgSoftens`). Where a declared record sharing the field names would
claim that spelling by the lenient field-set scan, the parameter is pinned at the argument's
own `#anonN` row instead (`monoSpelledShapeStaysAnon`, fixture
`tests/cases/generics/anon-record-arg-shares-declared-field-names.vl`). A map field holding a literal, in a literal that a
generic call receives directly or through the `const` it reads, stays uncoded
(`anonGenArgLit`), because the softened pin would build the instance at a different row. Such
a literal takes master's path, which already ran it. And `anonMapFieldDestAdmits`
peels `| null` off the destination field, so a map delivered into an `M | null` field keeps its
code. An un-annotated parameter as the field value is a separate defect, [D3132](D3132.md). The same pin closes [D2851](D2851.md).

#### Price

One cell moves loud to check-clean invalid wasm: `anon-litunion-map-field-call`'s
`argument`/un-annotated face. The refusal it had was this row's; lifting it reaches a
separate defect in the hole instance, which is already check-clean invalid wasm on master
with a declared record and no binding-fed field:

    type AB = "a" | "b"
    function mkL(k: i32, x: AB): {[i32]: AB} {
      const m: {[i32]: AB} = Map()
      m[k] = x
      m
    }
    type R = { direct: {[i32]: AB} }
    function wrapL(k: i32, x: AB): R {
      const m = mkL(k, x)
      { direct: m }
    }
    function __take(a) {
      const v = a
      print(v.direct[3] ?? "a")
    }
    __take(wrapL(3, "b"))

The instance reads `v.direct[3] ?? "a"` at the template's types. An i32 index on a hole is an
element derivation (`HD_ELEMV`), which `substHoleTyReal` and `holePinReadOf` resolve for a
list or string pin and not for a map. The `??` result hole (`HD_COAL`) carries the default as
the widened `string`, so it joins to `string` at a literal-union pin. The map-value read is
the i32 atom and every consumer expects a string ref. Resolving the two derivations at the
pin is not enough on its own, and with the map default keyed at the pin `print` then prints
the atom id, a wrong value. The consumers of the `??` result read the template type, so
this is its own lane: [D3127](D3127.md).
