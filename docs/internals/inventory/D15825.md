### D15825 — a field read off a record built wider, delivered at the read's own type, hands on the wider record

**closed 2026-11-12 · now a loud check reject by the shared-record contract, as a binding held at another record is when annotated (`{j: {f: i32}} is not K`) · was check-clean invalid wasm, clause 1 · the read holds the field's stored record (`storeHeldAt`), and each delivery of it at its own type is judged there (`storeReadsOwnResolve`): an annotated parameter takes that record (`recHeldArgTakesRep`), a binding of the read is judged as a binding read is, and any other delivery is refused · fixtures `tests/cases/soundness/field-read-off-wider-built-record-handed-at-own-type-runs.vl`, `…-annotated-refused.vl` · found grading D15822 · the same on master `4e65bd710`**

Repro:

    type J = { f: i32 | null }
    type K = { j: J }
    function mk() { { j: { f: 4 } } }
    const _k: K = mk()
    const y = mk()
    const w: { f: i32 } = y.j
    print(w.f)
    // vl check: rc 1 — this field read holds a J, as the record it is read from is built wider
    //   than its own type, and it is handed on here as {f: i32} … a record is shared, not copied
    // (was: vl run invalid module — expected (ref null `{f:i32}`), found (ref `J`))

The refusal above is the contract's. Handed to `function own(q: { f: i32 }) { q.f }`, `own(y.j)`
prints `4`.

#### Mechanism

`y` is built at `K`, so `y.j` holds a `J`, which stores `f` as `i32 | null`. Delivered where the
read's own type `{f: i32}` is declared, the reference is handed on as it is built, and no copy or
refusal is recorded for it: the delivery seam judges the read by its own type, which equals the
destination. A binding read held at another record is judged by its held record
(`storeHeldArgsAt`); a field read is not.
