### D1371 — a hole's cast is re-typed at the CALL SITE, so the ARGUMENT position inside the same body was already checked against the old answer

**check-clean invalid wasm · clause 1 · `type mismatch: expected i32, found (ref $type)` ·
the `as?` suffix in ARGUMENT position only — statement, binding and return all run since
[D1341](#d1341) · ZERO corpus cells · filed 2026-09-03 as the one cell of D1342's 24-cell
two-face grid where the two faces still disagree, measured on this worktree's seed**

Repro (`vl check` rc 0; the annotated `function take(a: i32 | null)` twin is the loud
`argument 1: expected i32, got i32 | null`):

    function id(x: i32): i32 { return x }
    const u: i32 | null = 5
    function take(a) {
      print(id(a as? i32))
    }
    take(u)

#### Mechanism

D1341's close parks the cast on the hole and re-records its result type as `T | null` from
`castPinAdjudicate`, at the call that PINS the hole. That is the first moment the operand's
type exists — and it is strictly after `take`'s own body was checked, so every consumer INSIDE
the body adjudicated the cast at the pre-pin type `i32`. In argument position that consumer is
`assignableExpr(args[i], at, expected)` against `id`'s `i32` parameter, which passed against
`i32` and is never re-asked. `print` is not affected because its own classifier reads the node
type at EMIT time, after the re-record.

The disassembly is the box going straight into `$id`: the `as?` union arm builds
`(if (result (ref $1)) (i32.eq (struct.get $1 0 …) (i32.const 0)) …)` and that value is the
argument of `(call $id)`, whose parameter is `i32`.

The general shape is the checker's ONE-BODY-MANY-PINS limit: a hole parameter's body is
type-checked once, and a per-call answer recorded afterwards can only reach consumers that
read node types later than it is written. The two standing repairs both exist already —
`noteArgCstr`'s deferred re-validation at the pin, and `monoRecheckBegin`'s pinned body
re-check — and either would cover this; neither is wired to the cast rung.
