### D4013 — a generic-seeded `let` written with an `if` expression of generics is not instanced at the call through it

**closed 2026-10-13 by lane SC · runs · was check-clean silently wrong · pins: `tests/cases/closures/written-let-if-expression-of-generics.vl` · found in review of #3517 (`rv3517/d10_ifexpr_write`) · filed 2026-10-11 against master `20fa382fe` with #3517 applied**

Repro:

    function inner<U>(u: U) { print("I"); print(u) }
    function other<V>(v: V) { print("O"); print(v) }
    function main() {
      inner(3)
      const c = true
      let f = other
      f = if c { inner } else { other }
      f(true)
    }
    main()
    // vl check: rc 0.  vl run: prints I 3 I 1

Want:

    I
    3
    I
    true

#### Mechanism

D3979 instanced a call through a written `let` only when every value written into it NAMES a
declared generic, and an `if` expression is not a name. Closed by lane SC (fn-value-flow §(f)
step 3): `monoWrittenGenLetFrame` asks `monoValueNamesGenerics`, which reads an `if` expression
whose every arm names a declared generic as naming generics; removing it alone restores
`I 3 I 1`.

#### Ablation

| ingredient changed | outcome | needed? |
| --- | --- | --- |
| `f = inner` written directly (D3979) | runs | **yes** |
| `inner(3)` removed | trap, indirect call type mismatch | no |
| the `if` as the initialiser, `let f = if c { inner } else { other }` | loud emit reject, no interned signature | changes the clause |
