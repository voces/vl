### D4013 — a generic-seeded `let` written with an `if` expression of generics is not instanced at the call through it

**check-clean silently wrong · clause 1 · found in review of #3517 (`rv3517/d10_ifexpr_write`) · filed 2026-10-11 against master `20fa382fe` with #3517 applied**

Repro:

    function inner<U>(u: U) { print("I"); print(u) }
    function other<V>(v: V) { print("O"); print(v) }
    function main() {
      inner(3)
      const c = true
      let f = other
      f = if c { inner } else { other }
      f(true)
    }
    main()
    // vl check: rc 0.  vl run: prints I 3 I 1

Want:

    I
    3
    I
    true

#### Mechanism

D3979 instances a call through a written `let` only when every value written into it NAMES a
declared generic. An `if` expression whose arms name generics is not a name, so the binding
keeps master's path: the call pins nothing and resolves to the `i32` instance `inner(3)` made.
Following the arms of an `if` (and `match`) value is the widening this row wants.

#### Ablation

| ingredient changed | outcome | needed? |
| --- | --- | --- |
| `f = inner` written directly (D3979) | runs | **yes** |
| `inner(3)` removed | trap, indirect call type mismatch | no |
| the `if` as the initialiser, `let f = if c { inner } else { other }` | loud emit reject, no interned signature | changes the clause |
