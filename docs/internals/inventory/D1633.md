### D1633 — D1632's frame-scoped half: a capture classifier asked about a frame's own `let` had no resolver for one

**closed · filed 2026-09-05 against master `e2781fa0` · closed against `abecf8da`**

`exprMap`, `mapShapeOfExpr`, `exprNullableStruct` and `structIndexOfExpr` gained the
function-frame twin of the module-frame `let` resolver they already carried. Both faces of
the witness run, and so do the six other frame-scoped spellings the ablation found.

Repro:

    function go() {
      const m: { [string]: { name: string, n: i32 } } = Map()
      m["k"] = { name: "ada", n: 3 }
      const mv = m["k"]
      if mv != null {
        const v: { name: string, n: i32 } = mv
        const g = () => v
        print(g().n)
      }
    }
    go()
    // vl check: rc 0.  vl run: the emitted module failed to validate inside `go`:
    // type mismatch: expected (ref $type), found (ref null $type)

#### Mechanism

Not the phase this row was filed on, and the probe is what said so. Instrumenting
`captureValKind`'s annotated arm at both scopes reads:

    D1633CAP3 initK=struct    mLet=T mCell=map letIsMap(m)=T mShape=T exprMapIdent=F   (frame)
    D1633CAP3 initK=nulstruct mLet=F mCell=<null> letIsMap(m)=F mShape=F exprMapIdent=F (module)

**The map's shape IS resolvable from the arena at that moment** — `letIsMap` and
`letMapShapeOf` both answer for the frame's `let` — so "the input is not yet available" was
wrong. What declines is `exprMap` of the receiver IDENT: its arm reads the emit-time
declared-locals table, the param arena, the capture set and the globals registry, and a
frame's own `let` is in none of them. The table speaks only while that frame's own body is
emitted; the env struct is typed in the TYPE SECTION, before any frame declares its locals,
so every cross-frame question declined. Module scope escaped because a module binding is a
global, and the globals registry is durable.

So the module frame had an arena binding resolver (`globalLetOfIn`) and the function frame
had none. `frameLetOf` is that twin, and four Ident arms take it last, after every resolver
that can speak sooner.

#### Ablation

Every row is `vl check` rc 0. **The table this row was filed with was wrong in two rows** —
it was written from the module-scope analogy rather than run, and the un-annotated and
no-rebind spellings do not run inside a frame either.

| spelling | before | after |
| --- | --- | --- |
| the witness (annotated rebind, captured, in a function) | **invalid wasm** | **runs 3** |
| the rebind UN-annotated, in a function | **invalid wasm** | **runs 3** |
| the narrowed value captured directly, in a function | **invalid wasm** (`expected i32`) | **runs 3** |
| the map a PARAMETER rather than a frame local | **invalid wasm** | **runs 3** |
| one frame inside another | **invalid wasm** | **runs 3** |
| the same program at MODULE scope | runs 3 | runs 3 |
| the capture hop removed | runs 3 | runs 3 |
| no map — an annotated struct bound and captured, in a function | runs 3 | runs 3 |
| a LIST-valued map read, same shape | runs 3 | runs 3 |
| a STRING-valued map read, same shape | runs `ada` | runs `ada` |

Needed: the frame AND the map read AND the narrowing AND the capture. Not needed: the
annotation, the rebind, or where the map itself came from. The value's kind IS an
ingredient — a list- and a string-valued map both ran, so only the struct rep reached the
missing resolver.
