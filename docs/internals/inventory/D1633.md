### D1633 — D1632's frame-scoped half: inside a function the map-read arm cannot resolve the map's shape at capture time

**check-clean invalid wasm · 1 cell, D1632's function-scope spelling · filed 2026-09-05 against master `e2781fa0`**

Repro:

    function go() {
      const m: { [string]: { name: string, n: i32 } } = Map()
      m["k"] = { name: "ada", n: 3 }
      const mv = m["k"]
      if mv != null {
        const v: { name: string, n: i32 } = mv
        const g = () => v
        print(g().n)
      }
    }
    go()
    // vl check: rc 0.  vl run: the emitted module failed to validate inside `go`:
    // type mismatch: expected (ref $type), found (ref null $type)

#### Mechanism

The identical program at MODULE scope runs since D1632. That fix makes `captureValKind`'s
annotated arm defer to the binding's own cell when the initialiser classifies as the nullable
NICHE of the annotated kind — it asks `letInitCellKind(b, parentBindingFrameArenaOf(...))`.
At module scope that ladder's map-read arm resolves the map's value shape and reports
`nulstruct`, so the env field matches the local. Inside a frame it does not resolve at this
phase, reports no niche, and the annotated `struct` stands over a `(ref null $S)` value.

So the residue is not a different rung — it is the SAME rung asked in a frame where its input
is not yet available, which is why this is filed rather than folded into D1632's mechanism.

**The arena cannot substitute here**, and that was measured on D1632: asking
`nodeTyIsNullable` of the initialiser puts even the module-scope witness back to invalid wasm,
because the checker records the NARROWED type. Narrowing is type-level and the cell is not, so
the oracle has to be the rep ladder, and the rep ladder is the thing that is frame-blind.
