### D1640 — the `fromCodePoints` arm emits its argument TWICE, so only an identifier is accepted

**loud emit reject · 4 refused argument spellings · filed 2026-09-05 against master `df312ed6b` · found by glean, VL's first external consumer**

Repro:

    print(fromCodePoints([72, 105]))
    // vl check: rc 0.
    // vl run: emitProgram: fromCodePoints argument must be a named i32[] binding

#### Mechanism

`wasmEmit.vl`'s `fromCodePoints` arm lowers to `__utf8_enc__(xs.backing, 0, xs.len)`,
and it builds that call by emitting the ARGUMENT EXPRESSION twice — once under
`struct.get 0` for the backing and once under `struct.get 1` for the length. An `Ident`
is safe to emit twice; an arbitrary expression is not, because the second emission would
re-run its side effects. So the arm tests `fcpNode is Ident` (after unwrapping one
`Paren`) and `emitFail`s on everything else.

The message names the shape it wants rather than the reason, which reads as a rule about
i32 arrays. It is a rule about SYNTAX: the refusal has nothing to do with the argument's
type, and a spill to a temporary local would lift it for every spelling at once.

The refusal's SCOPE was measured rather than believed — one program per spelling:

| argument spelling | outcome |
| --- | --- |
| `fromCodePoints([72, 105])` — a literal | refused |
| `fromCodePoints(o.xs)` — a field | refused |
| `fromCodePoints(mk())` — a call result | refused |
| `fromCodePoints(cps.slice(0, 2))` — a slice | refused |
| `fromCodePoints(cps)` — a name | runs, prints `Hi` |
| `fromCodePoints((cps))` — a parenthesised name | runs, prints `Hi` |

So the sentence is accurate about what it admits and misleading about why: it is not the
element type or the binding that matters, it is that the node is an `Ident`.

#### Ablation

| ingredient removed | outcome | needed? |
| --- | --- | --- |
| the literal argument, bound to `const cps = [72, 105]` first | runs, prints `Hi` | **yes** |
| the annotation, `const cps: i32[] = [72, 105]` | runs, prints `Hi` | no |
| `print` around the call | still refuses | no |

Both faces of the binding — annotated and un-annotated — run, so this is not the
missing-annotation family: the ingredient is the argument's NODE KIND alone.

#### Grading list

`fromCodePoint(72)` — the SINGULAR builtin — already accepts a literal and runs, because
its arm emits the argument once into an `array.new_fixed`. Any fix here must leave that
arm alone and must keep the two builtins sharing `__utf8_enc__`, so a width-and-shift
ladder cannot drift between them. Re-grade all six spellings in the scope table above,
not just the literal, and the four `std/` builders that drain an `i32[]` accumulator
through `fromCodePoints` (`str.vl`, `fmt.vl`, `utf8.vl`, `base64.vl`) — they pass a name
today and must keep running unchanged.
