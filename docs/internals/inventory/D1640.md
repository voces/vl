### D1640 — the `fromCodePoints` arm emits its argument TWICE, so only an identifier is accepted

**closed — the argument is spilled into one scratch local and read from there, so every
spelling lowers and the argument is evaluated exactly once · was a loud emit reject at 4
argument spellings · position matrix 58 of 58 cells `emit refuses` → `RUNS`, 0 silent, 0
`runs → not-runs` · emitted wasm byte-identical over all 3,002 corpus modules · found by
glean, VL's first external consumer · landed in #2665 · filed 2026-09-05 against master
`df312ed6b`**

Repro:

    print(fromCodePoints([72, 105]))
    // vl check: rc 0.
    // BEFORE: emitProgram: fromCodePoints argument must be a named i32[] binding
    // NOW: prints `Hi`.

#### Mechanism

`wasmEmit.vl`'s `fromCodePoints` arm lowers to `__utf8_enc__(xs.backing, 0, xs.len)`,
and it built that call by emitting the ARGUMENT EXPRESSION twice — once under
`struct.get 0` for the backing and once under `struct.get 1` for the length. An `Ident`
is safe to emit twice; an arbitrary expression is not, because the second emission would
re-run its side effects. So the arm tested `fcpNode is Ident` (after unwrapping one
`Paren`) and `emitFail`ed on everything else.

The message named the shape it wanted rather than the reason, which read as a rule about
i32 arrays. It was a rule about SYNTAX: the refusal had nothing to do with the argument's
type, and a spill to a temporary local lifts it for every spelling at once.

That spill is what landed. A one-slot `(ref null $lTypeIdx)` frame — `fcpSpillSlot`,
reserved after every other eager frame — takes the argument once via `local.tee`, and both
`struct.get`s read it back. The frame is module-wide off `moduleHasFcpSpill`, the
`moduleHasNumCast` twin, so a module that hands the builtin only bare names reserves
nothing and its bytes do not move; the bare-name path still emits twice, which is why the
compiler's own self-compile is byte-identical. `callSpillsFcpArg` is the single home of
"does this call need the slot", asked by both the reservation and the lowering.

The refusal's SCOPE was measured rather than believed — one program per spelling:

| argument spelling | before | after |
| --- | --- | --- |
| `fromCodePoints([72, 105])` — a literal | refused | runs, prints `Hi` |
| `fromCodePoints(o.xs)` — a field | refused | runs, prints `Hi` |
| `fromCodePoints(mk())` — a call result | refused | runs, prints `Hi` |
| `fromCodePoints(cps.slice(0, 2))` — a slice | refused | runs, prints `Hi` |
| `fromCodePoints(cps)` — a name | runs, prints `Hi` | unchanged |
| `fromCodePoints((cps))` — a parenthesised name | runs, prints `Hi` | unchanged |

So the sentence was accurate about what it admitted and misleading about why: it was not
the element type or the binding that mattered, it was that the node was an `Ident`.

#### Ablation

| ingredient removed | outcome | needed? |
| --- | --- | --- |
| the literal argument, bound to `const cps = [72, 105]` first | runs, prints `Hi` | **yes** |
| the annotation, `const cps: i32[] = [72, 105]` | runs, prints `Hi` | no |
| `print` around the call | still refuses | no |

Both faces of the binding — annotated and un-annotated — ran, so this was not the
missing-annotation family: the ingredient was the argument's NODE KIND alone.

#### Grading list

`fromCodePoint(72)` — the SINGULAR builtin — already accepted a literal and ran, because
its arm emits the argument once into an `array.new_fixed`. The fix leaves that arm alone
and the two builtins still share `__utf8_enc__`, so a width-and-shift ladder cannot drift
between them. All six spellings in the scope table above are re-graded, not just the
literal, and the four `std/` builders that drain an `i32[]` accumulator through
`fromCodePoints` (`str.vl`, `fmt.vl`, `utf8.vl`, `base64.vl`) pass a name and are
byte-identical.

`u8[]` is refused by the CHECKER (`fromCodePoints expects an i32[], got u8[]`), which is
what keeps the arm's `lTypeIdx` assumption true for every argument that reaches it — the
lowering is unchanged in that respect, and the row makes no claim about widening it.
