### D4057 — a range with a literal `step 0` is reported twice, once by the checker and once by the lint

**open · loud check reject · the refusal is right, the duplicate is the defect · found writing `docs/spec/statements.md` (lane SPEC) · filed 2026-10-11 against master `98a4ed71b`**

Repro:

    for i in 0 until 3 step 0 { print(i) }
    // vl check: rc 1, "a range with `step 0` never advances", twice, at the same caret

Want:

    one error, "a range with `step 0` never advances", at the `0`

#### Mechanism

Two passes raise the same sentence at the same node. The checker's `checkRangeNeverRuns`
(`compiler/typecheck.vl`) refuses any constant step of 0 through `tErrCodedData`, with
`CODE_RANGE_NEVER_RUNS`. The lint's `reportDegenerateStep` (`compiler/lint.vl`, rule
`for-step-zero`, tier `error`) refuses a literal `0` step through `lintEmit`. The lint's own
comment says it shares the checker's wording so the two "cannot drift". Since D1588
widened the checker's fold, the lint's case is a strict subset of the checker's, and
nothing drops one copy. The other lint rule that shadows a checker case, `/ 0`, is a
warning that the checker does not raise, so it does not double.

#### Ablation

| variant | outcome |
| --- | --- |
| `0 until 3 step 0` at the top level | two errors |
| `n to 0 step 0`, `n` a constant | two errors |
| `0 to k step 0`, `k` a parameter | two errors |
| the same loop in a function body | two errors |
| `3 to 0` with no step (the direction arm) | one error |

#### Grading list

Each variant in the ablation table should print exactly one error. A computed step that
folds to 0 (`const z = 1 - 1; … step z`) is the checker's alone and must still be refused.
