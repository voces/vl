### D17070 — a record whose bare-literal field came from a binding fails IR verifier rule 3 when delivered to a literal-field record parameter

**runs today and must keep running · IR shadow `fail rule 3` on 3 spellings, identical on master `d699cfc` and with rowFieldStorage · filed 2026-11-23**

Repro:

    function show(r: { f: "a", g: i32 }) { print(r.f) }
    function h(x: "a") {
      show({ f: x, g: 1 })
    }
    h("a")
    // vl run: a.  VL_IR_SHADOW=1 vl check --codegen: "fail rule 3 in h at -1: v1's rep is not its type's", and show is "uncovered member record"

Want:

    a

#### Mechanism

Legacy runs the program. The IR builds the argument and the verifier rejects it: the value's rep
is not the rep of the type it is delivered at (rule 3). The value is a record whose field typed by
one string literal was built from a binding of that type, which legacy's anonymous row stores as
the string (`rowFieldStorage` answers 0). The parameter's record type asks its own row. Not yet
ablated past the table below; the callee's `member record` miss is a separate row-read gap that
also shows when the literal is spelled directly.
