### D17070 — a record whose bare-literal field came from a binding fails IR verifier rule 3 when delivered to a literal-field record parameter

**closed · IR shadow `fail rule 3` on 4 spellings, closed 2026-11-23 against master `ff34a69` (filed against `d699cfc`)**

Repro:

    function show(r: { f: "a", g: i32 }) { print(r.f) }
    function h(x: "a") {
      show({ f: x, g: 1 })
    }
    h("a")
    // vl run: a.  VL_IR_SHADOW=1 vl check --codegen: "fail rule 3 in h at -1: v1's rep is not its type's", and show is "uncovered member record"

Want:

    a

#### Mechanism

Legacy runs the program. The argument literal is built at the parameter's row, which keeps `f` as
the atom, so `x` (a string holding `"a"`) is delivered as its member's id: `atom_sole`, legacy's
`strToAtomSoleTail`. That temp is typed at `x`'s own type, the lone literal `"a"`, whose rep is
the string a binding holds; verifier rule 3 refused an atom at it. A record field keeps a lone
string literal as its atom (`rtOfObjAs`, `repFieldLitAsSet`), so rule 3 now admits an atom typed at
one (`loneLitAtom`, over `repTyIsLoneStrLit`). `h` is covered and matched in every spelling below.
The callee's `uncovered member record` is a separate row-read gap and stays.

#### Ablation

| spelling | legacy | IR shadow |
| --- | --- | --- |
| as filed | runs, prints `a` | `fail rule 3` in `h`, `uncovered member record` |
