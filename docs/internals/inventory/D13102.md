### D13102 — a hole function forwarded to list elements that call it at their own value parameter gets no instance

**closed 2026-10-25 by lane L1 · runs, prints `1` · built, not refused: an element call's argument that is a parameter forwarding a function takes the one instance its frame's instance was handed, when every call of the element's parameter closes at that instance's parameter types under the element's value binding (`monoElemFwdFnFits` in `monoElemParamTys`, emit_mono.vl) · pin: `tests/cases/closures/forwarded-hole-fn-to-list-element-value-param.vl` · was loud emit reject · `vl check` rc 0 · clause 2 · the part of [D12701](D12701.md) where each element's calls agree on one key · present on master `1b0f55762` · filed 2026-10-25 against master `1b0f55762`**

#### Mechanism

The element `apply2`'s parameter `g` is typed at the inner call from the argument `h`. Its pins
(`g(s, s)`) name `apply2`'s own value parameter, so they stay open where the outer call
`inner(0.5, add)` chooses `add`'s instance, and the element's parameter had no type. The fix
types `g` as the instance `h` holds in `inner`'s frame. It does so only when every call of `g`
in the element's body, with `s` substituted by its binding at this call, closes at exactly that
instance's parameter types. Without that check, the unguarded version gave D12701's witness
`indirect call type mismatch`.
