### D2414 — a closure returning a nullable record list has no function-value signature

**loud emit reject · clause 2 · pre-existing on master `a277bf7b0` · filed 2026-09-25 against
`a277bf7b0`, found grading [D2399](D2399.md)**

Repro:

    type R = { n: i32 }
    function f(): i32 {
      const v: R[] | null = [{ n: 1 }]
      const q = (): R[] | null => { v }
      const got = q()
      if got != null { return got.length }
      0
    }
    print(f())
    // vl check: rc 0.  vl run: emitProgram: a function value's signature is not yet supported — its result type has no representation in the function-value ABI

#### Mechanism

A function value's `$fnsig` is keyed by one token per parameter and one for the result
(`cloSigKeyExt`, `repSigTokOfKind` in `emit_rep.vl`). A nullable ref list (`nulreflist`) has
no token, so the signature does not intern and `emitClosureValueCore` refuses. The non-null
`R[]` result carries the slot-bearing `r` token; the nullable one needs the same slot. Before
[D2399](D2399.md)'s close the un-annotated spelling was not pinned at all and reached
`bare null needs a struct-typed context`, or, as the tail write `v = v`, check-clean invalid
wasm; the close pins it, so every spelling now names this refusal.
