### D2850 — a function whose result is a record naming its hole or type parameter has no row of its own at a pin, so it takes a sibling row of another kind or none

**closed 2026-09-27 · was check-clean silently wrong, clause 1, on master `7323baf55` (a loud emit reject alone, invalid wasm with a declared literal-set row) · found by the #3220 round-2 review (`r2/t10.vl`, `r2/t7.vl`) · filed 2026-09-27 · fixtures `tests/cases/structs/record-constructor-pins.vl`, `tests/cases/generics/record-constructor-widened-i64.vl`, `record-constructor-widened-f64.vl`**

Repro:

    const a = { f: true }
    function mk(x) { return { f: x } }
    print(mk(7).f)
    // PRINTS true
    // vl check: rc 0.  vl run: prints `true`, want `7`

#### Mechanism

`mk`'s literal records `{f: ?mk.0}`, whose field has no kind, so no anonymous row is minted for
it and every instance shares the template's literal. Alone, the result has no row at all
(`ref valtype with no interned shape`). Beside another `f` row the literal joins that row
leniently, and the read formats by it, so `mk(7).f` printed `true` and `mk("a").f` beside a
declared `{ f: Kab }` was invalid wasm. D2841's first round made this reachable from a new
spelling (`p({ f: true })` then `mk(7)`), which is how the review found it. Fixed at the pin:
an instance whose checked result is a plain record naming the hole takes that record,
substituted through the pin, as its return annotation, so each instance interns its own row.
Those pin rows are interned after every other annotation: a pin whose record no row holds
exactly, but exactly one other row holds by a numeric widening (an `i32` field under an `i64`
or `f64` one), takes that row and widens at construction, as master's shared literal did
(`const w: { v: i64 } = mk(5)`).

#### Ablation

| ingredient removed | outcome | needed? |
| --- | --- | --- |
| the other `f` row (`mk` alone) | loud emit reject | no, a second face |
| the hole (`x: i32`) | runs | **yes** |
| the return position (`const o = { f: x }; o`) | same wrong value | no |
| the type parameter for the hole (`mk<T>(x: T)`) | same wrong value | no |

#### Grading list

`g2841`'s `ctor_*` cells: a literal handed to an un-annotated `p` first, then `mk` at
`boolean`, `i32`, a literal set, `string` and `f64`, for the hole, the generic, and the generic
tail spelling. All of them run beside the two crowds as well.
