### D2850 — a record built by a generic/hole constructor has no row of its own

**loud emit reject · clause 2 · a design row · identical on master `38e64e7ca` · filed 2026-09-27 from the #3220 review rounds 2–5**

Repro:

    function mk(x) { return { v: x } }
    print(mk(7).v)
    // vl check: rc 0.  vl run: emitProgram: ref valtype with no interned shape

#### Mechanism

Anonymous struct rows are minted before monomorphization, from each literal's recorded shape.
A constructor's literal records `{v: ?mk.0}` (or `{v: T}`), which has no field code, so it
gets no row, and every instance shares that one literal node. Alone the result has no row.
Beside another row with the same field names the shared literal joins it, so one instance's
record is built and read in another's format.

#3220 rounds 2–5 tried giving each pin its own row, by synthesizing the substituted record
as the instance's return or binding annotation and picking a row for it at intern time. It
leaked a new family each round, and was withdrawn:

1. **List element**: `[mk(5)]` beside `{ f: true }` keyed the list on a sibling row.
2. **Function-field exclusion**: `{ f: x, g: () => x }` bound to a local went silent.
3. **Closure in the constructor**: `const c = (y) => y; return { f: c(x) }`, which also
   exposed D2854.
4. **Widened row into a union**: `const u: A | B = mk(5)` with `A = { v: i64 }` was invalid
   wasm. The intern-time pick of a wider row cannot follow the value through the box.

A correct fix mints a row per pin and delivers it with a converting copy at every destination:
binding, argument, return, element, push, field, map value and union box. It must not pick a
row at intern time.
