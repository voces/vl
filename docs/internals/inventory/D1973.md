### D1973 — a guard arm ending in `while true { … }` with no `break` never falls through, but does not narrow the code after it

**loud check reject, clause 2 · residue of D1970 · filed 2026-09-22 against master `a8a104432`**

Repro:

    type IoError = { msg: string }
    function f(x: i64 | IoError): i64 | null {
      if x is IoError {
        while true {
          return null
        }
      }
      x
    }
    print(f(3 as i64))
    // vl check: rc 1, `expected i64 | null, got i64 | IoError` at the trailing `x`

#### Mechanism

`stmtAlwaysExits` treats every loop as falling through, because a `break` in its body leaves
only the loop. A `while true` whose body has no `break` binding to it cannot complete normally,
and the function-totality check (`nodeIsTotalAt`) already counts `while true` as total. Admitting
it here needs the break-binding scan (`blockHasContinueFor`'s shape, for `break`), labelled
breaks included, so that `while true { break }` stays a fall-through.

#### Grading list

`while true { break }` and a labelled `break outer` from a nested loop as negatives; both
return spellings.
