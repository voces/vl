### D15433 — lambda members of a written `let` that a nested function writes are tagged, and mono still refuses the binding for two signatures

**runs today and must keep running · split-plan dependent (W-lam, a capture cell): with the split plan off (`compileSrc` returning after its first compile) it is a loud emit reject, `the reassigned function binding `d1` holds functions called at more than one argument type` · from `cell-peer-called-at-two-types` (D3857's pin; split-plan census at `9a45989d`, W-lam) · filed 2026-11-04 against master `a090a48b`**

Repro:

    function mk(x: string, n: i32) {
      let d1 = (y) => y
      function w1() {
        d1 = d1
      }
      let d3 = (y) => y + y
      d3 = d1
      print(d1(x))
      print(d3(n))
    }
    mk("a", 4)

Want:

    a
    4

#### Mechanism

The tag decision tags the set `{d1's lambda, d3's lambda}` here; the refusal is mono's (`monoBindSigFail`, emit_mono.vl), which still counts the bound lambda's call signatures per binding once `w1` captures `d1` as a cell. Without `w1` the program runs with the plan off. With the lambdas seeded through `const g = (y) => y` (the census file's spelling) the decision declines first, at the lambda (`ftNodeOk`: not written at the binding, no declared member beside it), and only with the cell: the same seeding without `w1` is tagged and runs. Step 4 (γ)'s let-write join slice, one closure per call type (D3975's ruling).
