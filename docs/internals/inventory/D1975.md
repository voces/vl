### D1975 — the seed collected a staged source into ONE `i32[]` of code points, so a source past 2^23 code points trapped the compiler before lexing

**closed 2026-09-22 — was a compiler trap (`allocation size too large`, exit 70, 0.1 s) on any source past 8,388,608 code points · reported by plumb (PL-002) · fix in `compiler/strutil.vl` (`CpAcc`), wired into `driver.srcLoad`/`modSrcLoad`/`modKeyLoad` and `cli.cliResultLoad`; pin `tests/vl_large_source_test.ts`**

Repro (the defect is the source's LENGTH, and the pad cannot be written inline — the pin builds it):

    print("héllo ☃ " + "1")
    // padded by a leading 9,000,000-character `//` comment: rc 70 before the fix, prints `héllo ☃ 1` after

#### Mechanism

The compile store runs under the null collector, whose largest single object is 64 MiB (the
object size lives in 26 bits of the GC header). The host stages a source as UTF-32 code points
through `srcLoad` (a module through `modSrcLoad`), and the seed pushed every one into a single
`i32[]`. `.push` doubles, so the backing reached 2^24 slots, 64 MiB plus a header, once the
source passed 2^23 code points, and the allocation trapped in `srcLoad` before a token existed.
plumb's 11.6 MB `s1000.vl` hit it; its 2.3 MB `s200.vl` did not. `CpAcc` flushes the stream to a
string every 1M code points (a 4 MiB backing) and joins the chunks pairwise once, when the source
is first read; the joined string replaces the chunks, so `vcSource`'s repeat calls no longer
re-encode the whole source each time.

#### Grading list

- plumb's `vl-probes/synth/s1000.vl` (`gen.vl <out> 1000 20 10`, 11.6 MB): builds, ~24 s, 3.2 GB peak RSS.
- The next ceiling for the same shape: the null collector's GC heap is 32-bit, so a compile can
  allocate 4 GiB in total, garbage included. `F=1340` (15.6 MB) builds at 4.15 GB peak RSS;
  `F=1375` (16.0 MB) traps `allocation size too large` in `repMk` during the emitter's scan
  passes. Under the copying collector the same shape builds to 29 MB (`F=2500`) and runs out
  of heap in the parser at 46 MB (`F=4000`).
- The self-compile output is unchanged in behaviour: `native-fixpoint.sh` and the corpus.
