#### Mechanism

The closure `flip` writes `inner2` into the captured cell `k`. Both nested generics capture
`x`, whose type differs between `outer`'s two instances, and the validator fails inside the
closure with an `i32` where the `string` instance wants a `string`: the write appears to be
lowered against the first instance's capture. Traced at the close: the write lowers through a
synthesized `const __cbv0 = inner2` in the closure's body, which `monoCloneBodyRaw` shares between
both instances' clones because nothing in it names a type parameter; `monoRenameGenAliasInit`
renames its initializer in place for the second instance (`inner2$1`), so the first instance's
closure built the string instance's `inner2` too.
