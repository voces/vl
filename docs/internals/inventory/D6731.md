### D6731 — a list literal holding a spread copy of an un-annotated nested-record list is invalid wasm when two declared records share its layout up to a nullable field

**closed 2026-10-18 by lane L6 · runs, prints `82` · was check-clean invalid wasm · `vl check` rc 0 · clause 1 · an index into a list of lists reads the outer row's own inner row rather than the row its structural element name keys, which can be a same-layout record declared earlier; the no-spread `[src]`, a lambda result, a `let` reassigned, `xs[0][1]`, an inferred call result and a mixed `[src, [...src]]` run too, and the generic `first(xs)` is [D6772](D6772.md) · pins: `tests/cases/lists/nested-record-list-beside-same-layout-declared-records.vl` · found grading the L6 type-threading change · filed 2026-10-18 against master `73713bacf`**

Repro:

    type Ax = { v: i32 }
    type Jx = { f: Ax | null }
    type Ix = { f: Ax }
    const src = [{ f: { v: 7 } }, { f: { v: 8 } }]
    const xs = [[...src]]
    const v = xs[0]
    print(v[1].f.v * 10 + v.length)
    // vl check: rc 0.  vl run: invalid module, expected (ref null $6), found (ref $4)

Want:

    82

#### Mechanism

From the ablation only. The inner spread copy keeps the source's row ([D2938](D2938.md)), but
the outer list literal's element type is resolved against a declared record of the same
layout, and `Jx` (whose `f` is nullable) is the one it picks.
