### D14227 — `repOfTy` has no element kind for a ref-list element pinned from a type parameter

**runs today and must keep running · 23 FILES of 6,701 `tests/cases` files, a lower bound · filed 2026-10-26 against master `641c18ca1`**

Repro:

    import { filled } from "std:array"
    type Item = { n: i32 }
    const u: i32 | string = 3
    print(u)
    const a = filled<Item | null>(2, null)
    print(a.length)
    // vl run: prints 3 then 2; the element kind comes from `rlElemKindTbl`, not from the type

Want:

    3
    2

#### Mechanism

`rlElemKindTbl` answers a ref list's element kind by slot. The type-driven reader (`repOfTy` /
`repSigKindOfTy`) has no kind when it is asked about an element pinned through a type
parameter. An emitter probe counted 20 files where it had no kind, 2 where it had no element
type, and 1 where it disagreed (`tests/cases/unions/degenerate-union-alias-is-its-arm.vl`). The
count is a lower bound: in a file where an earlier probe fired, emission stopped before this
probe could run. The table cannot be deleted until this reader covers these files.

Measured again on 2026-10-30, at the intern point (`rlInternNameTy`): the kind each caller passes
against the rep of the slot's recorded element type (`rlElemTyIx`). 60 files disagree on their
first slot: 52 record a type-variable element (`T`, `T | null`, `T | string`), the template's
type rather than the instance's, which is this row; 6 record a literal-union element (`N`, `AB`,
`CaseMap`) the type reads as `i32`; 2 more disagree on `AB` as a union. The type-variable slots
were a generic TEMPLATE's own (an `__array_new__` fill and a `T[]` annotation in its body), which
no emitted code reads, since each instance interns its own row; collection no longer interns
them, and the count falls to 13 files: 8 literal-union elements, 4 nullable-scalar inner lists
(`(i32 | null)[]`) and 1 slot with no recorded type. A `map` callback returning a literal union interned the union's first row beside the result's own, and now interns only the result's: 10 files, 5 literal-union elements. Readers with a list expression of their own do not wait on that: they read
the element's rep from the list's type at the instance, and 16 have moved so far
(`forInElemKind`, union/row/map/closure tests in `emit_classify`, the index store and `.push` in
`wasmEmit`), each probed against the table with no disagreement over 17,267 files. `emitArrRef`
cannot: its slot is the literal's destination row, which disagreed with the literal's own type in
507 files.
