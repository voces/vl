### D17003 — inside `is S[]` over a `string[]` arm with `S` a string literal set, an element read at `S` is refused

**loud check reject · clause 2 · the string face of the 2026-11-18 ruling's in-arm view (DECISIONS, "`is K[]` tests a list's contents") · D17001 gave the numeric arms the read at `K`; a string literal set is stored as atoms, which a `string[]` arm's element needs converting to (the atom table's string-to-atom lookup) · filed 2026-11-19 against master `de44e8985` by lane F1**

Repro:

    type S = "a" | "b"
    const a: string[] = ["a", "b"]
    const q: string[] | S[] = a
    if q is S[] { const s: S = q[1]; print(s) }
    // vl check: cannot assign string to 's' of type S

Want:

    b

#### Mechanism

`pushArmElemReadFact` (`check_narrow_flow.vl`) narrows an arm's element reads for a numeric
literal set only. For a string set the per-arm read (`emitListUnionArmIndex`) would deliver a
`string[]` arm's string ref where the read is an atom, which no arm converts to: without the
restriction the module fails to validate.
