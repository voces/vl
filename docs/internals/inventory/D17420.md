### D17420 — a record compare whose literal operand holds a `null` field fails the IR's stack-order check (`non-stack temp: out of order`), so legacy alone lowers it

**runs today and must keep running · IR-uncovered: the IR shadow reports `mismatch unlowered: non-stack temp: out of order` and legacy lowers the function · IR class, FREE · filed 2026-11-24 by lane S1 against master `838bb284`, unmasked from `tests/cases/lint/deep-record-compare.vl::@start` by the `nullable record eq bare side` close**

Repro:

    type T = { id: i32, tags: string[] | null }
    function f(t: T): boolean { return t == { id: 2, tags: null } }
    print(f({ id: 1, tags: null }))
    // vl run: false.  VL_IR_SHADOW=6 vl build: `mismatch unlowered: non-stack temp: out of order`

Want:

    false

#### Mechanism

The record compare's literal operand is a record literal holding a `null` literal at a nullable
reference field. The operand's temps reach `irLSettle`/the root staging in another order than they
were defined, so the lowering misses and the function falls back to legacy. Two variables, or a
literal whose field is not `null`, lower and match.
