#### Mechanism

The parameter solve reads the call site's argument, an empty `[]` whose element is still
open there. So `take` is instantiated over the i32 list, and then its own `.push("x")` pins
the element to `string`. Ablation: `take(["a"])` runs, and so does `a: string[]` with
`take([])`. Both ingredients are needed: the empty literal, and the element pinned only
inside the callee.

The close, in two layers. The CHECKER re-checks the body at the call's argument types
from the constraints the body deferred, and a `.push(v)` whose receiver was the parameter
deferred `v` against the parameter's element; at a pin to an open `[]` that element was still
open, so the constraint was vacuous and nothing was pinned (`take([])` then accepted
`a.push("p"); a.push(3)` alike). `pinBmCstrElems` now runs ahead of every validation at the
three pin sites (direct call, UFCS, function value) and pins the argument's row in place with
what the body's first push gives it, the direct spelling's own rule (`cnhPinTy`); later pushes
validate against it. The EMITTER's pin ladder (`monoArgTyName`) read an empty literal off its
elements, so it fell to `exprArray`'s `i32[]`; an empty literal now pins at its recorded row,
by its render, else by the record row its field set matches, else the loud floor.

Ablation, on master `42c4d4c10` (all now run, with the printed value checked): the element
`string`, `f64`, `i64`, `boolean` (was `1` for `true`, silently wrong), an anonymous record, a
declared record built through `const v = a`, a nested list, a union, a map, a function value,
`null` then `string`; the call through UFCS (`[].take()`) and through a function-value
binding (`const g = take; g([])`); the push value a second hole parameter (`take([], "s")`).
`take([1])` with `a.push("p")` stays a loud check reject, and so does a body pushing two
element types into one `take([])`, at the second push.
