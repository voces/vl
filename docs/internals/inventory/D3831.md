### D3831 — a block-local `<U>` generic reading a captured list of its enclosing generic's parameter reads the list at the wrong element rep

**check-clean silently wrong · found in review of lane SC · filed 2026-10-08 against master `5a281ef27`**

Repro:

    function outer<T>(x: T) {
      const ys = [x, x]
      function inner<U>(u: U) { print(ys[1]) }
      inner(1)
    }
    outer(true)
    // vl check: rc 0.  vl run: rc 0
    // PRINTS 1

Want:

    true

#### Mechanism

`inner` declares its own `<U>`, so it is instantiated by `monoInstantiate` at the call site and keeps the template's frame rather than `outer$1`'s (the nested-generic frame-sharing mechanism of lane SC's filed row for a nested `<U>` capturing an enclosing parameter). The captured `ys` is read at the template's element rep for `T`, an `i32`-represented slot, and the `boolean` held there comes back as `1`. Where that row builds the env at the wrong rep and the validator refuses, a one-instance program reads the wrong slot type without a type error, so it validates and prints the wrong value.

#### Ablation

| ingredient removed | outcome | needed? |
| --- | --- | --- |
| `inner`'s own `<U>` (`function inner(u: i32)`) | prints `true` | **yes** |
| the capture of `ys` (`print(x)` instead of `print(ys[1])`) | prints `true` | **yes** |
| `outer`'s `<T>` (`function outer(x)`, a hole) | still prints `1` | no |
| the pin of `U` (`inner("k")`) | still prints `1` | no |
| a second `outer` instance (`outer("s")` added) | check-clean invalid wasm inside `outer$1` (that row) | the neighbouring row |

#### Grading list

* `print(ys[1])` at an `f64`, `string` and record `T`: each should print the value.
* A closure over `ys` inside `inner` (`const g = () => print(ys[1])`).
* The lane SC rows for a nested `<U>` capturing an enclosing parameter close with this one; re-grade them together.
