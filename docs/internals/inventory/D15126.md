    function mk() { { f: 4 } }
    const wideJ: J = mk()
    const xs = [mk()]
    const plain = { f: 5 }

Want:

#### Mechanism

`keep` is built as a list of `J`, its element being a read of `xs`, whose records are built at
`J`. `z`'s held row was decided by `letElemReadHeldTy` (emit_classify.vl), which asked only the
checker's store builds (`recBuildElemTyOf`), in the emitter. `keep`'s `J` is its literal's rep stamp, not a store,
so the answer was -1 and `z` took its type's own row. That row exists only when some other value
interns it: an unrelated record literal of the same shape, or a parameter annotated with it. With
no such row `z` fell on `J` and ran, which is why the corpus graded every such cell `runs`.
