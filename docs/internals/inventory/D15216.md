### D15216 — a fresh call kept at its own row, returned through an inferred function into a record storing its number field wider, is not copied there

**closed 2026-11-04 · now runs, prints `12000000000` · was check-clean invalid wasm · clause 1 · the `return_inferred`/annotated cell of `fresh-call-record-into-wider-number-fields.matrix.vl`, found grading the destringify lane's nested-field fix against its matrices · filed 2026-11-04 against master `214d93f91` · closed by the record solve handing a wider destination on through a call leaf only where that leaf's function can itself be built there (`recFnBuildsAt`, check_fit_rules.vl, in `recFnBuiltAtDst`); else the delivery takes the converting copy, as the direct spelling does · fixture `soundness/fresh-call-returned-through-function-into-wider-number-record-runs.vl` · a function delivered both directly and through another is [D15244](D15244.md)**

Repro:

    type R = { n: i64, s: string }
    function mk() { { n: 3, s: "a" } }
    const own = mk()
    const ownN: i32 = own.n + 1
    function f() { return mk() }
    const v: R = f()
    print(v.n * 4000000000)

Want:

    12000000000

#### Mechanism

`own` reads `mk()` at its own row (`n: i32`), so `mk` is built there and each delivery into `R`
(`n: i64`) copies, converting the field. Delivered directly (`const v: R = mk()`) the copy is made.
Through `f`, an inferred function returning the call, `v`'s delivery reaches `mk()` one call deep and
no copy is made, so an `i32`-row record is handed to `R`'s storage.
