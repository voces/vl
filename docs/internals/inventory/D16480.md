#### Mechanism

A bare `F32x4` field is refused by the checker (D1981) and has no struct-field code in the
emitter (`nameFieldCodeTy` answers -1), so `F32x4 | null` is the only record spelling. It is the
general union box `(struct i32 (ref null (struct v128)))`: a write mints the tag box and the
`v128` box, and a read loads three times and tests the tag. Binaryen cannot remove either
allocation, since both escape into the heap. A `v128` local is a value type, so nothing is
boxed and nothing needs scalarising.

#### Ablation

At -O3, with `struct.new` counted inside the loop:

| spelling | allocations per iteration | needed? |
| --- | --- | --- |
| the witness (`F32x4 \| null` field, write) | 2 (at -O as well) | — |
| the same field, read only | 0 | **yes** (the write) |
| an `F32x4` local | 0 | **yes** (the field) |
| a bare `F32x4` field | refused at check (D1981) | — |
| lanes in a `Buf` field | 0 | **yes** (the box) |
| a `{x, y, z: f32}` record field, reassigned whole | 1 | no: the record face, roadmap AE-004 |
| the same record as a loop-carried local | 1 | no: heap2local does not split a loop phi |
