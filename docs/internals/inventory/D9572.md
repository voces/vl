### D9572 — an un-annotated parameter handed a record of an un-annotated function and a record of an annotated lambda leaves the function unpinned

**closed · runs, prints `4` `1.5` · was loud emit reject, `vl check` rc 0, `emitProgram: cannot take the generic function `inc0` as a value`, clause 2 · CAPABILITY: either call alone runs · found closing [D9530](D9530.md) · filed 2026-10-22 against master `49a7d0b10` · closed by pinning an open function named at a record literal's field at the argument types every `<param>.<field>(...)` call in the callee's body agrees on (`monoFieldCallPinnedFnTy`, `monoOpenFnRecListPin`, emit_mono.vl) · fixture `closures/hole-fn-record-beside-lambda-record.vl`, matrix `hole-fn-record-beside-lambda-record` (27 → 28 of 46, the rest bound first, [D9645](D9645.md)) · with [D9570](D9570.md) closed, [D9645](D9645.md) and [D9646](D9646.md) filed open**

Repro:

    type R = { f: (a: i32) => f64 }
    function inc0(a) { return a + 1 }
    function take(a) {
      print(a.f(3))
    }
    take({ f: inc0 })
    take({ f: (x: i32): f64 => 1.5 })
    // vl check rc 0.  vl run: emit error: emitProgram: cannot take the generic function `inc0` as a value

#### Mechanism

With one call, every literal reaching `take` names `inc0`, and the call `a.f(3)` is rewritten to
`inc0(3)` before mono, which pins it. With a second call at another record type the literals
disagree, the rewrite declines, and `take`'s instance at `{f: (_) => _}` names no signature for
`inc0`. The flow table holds no pin at slot `f.f` either: the receiver `a` is a hole, so
`a.f(3)` is an opaque member call (`ffCall`, fn_flow_shadow.vl). The close reads the field's
call arguments off the callee's body instead, takes `inc0` at them when every call agrees and
each argument is closed, and delivers it there; calls at two argument types still refuse.
