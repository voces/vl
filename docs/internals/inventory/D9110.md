### D9110 — a function-typed parameter named like a module function refuses as a `.map` callback

**loud emit reject · `vl check` rc 0 · clause 2 · CAPABILITY: the same program with the parameter renamed runs, and so does the direct call `k(3)` of the shadowing parameter · found closing [D9073](D9073.md) · present on master `713f2c17d` · filed 2026-10-21 against master `713f2c17d`**

Repro:

    function k(x: i32): i32 { return x + 1 }
    function h(k: (x: i32) => i32): i32 { return [3].map(k)[0] }
    print(h((x: i32): i32 => x * 10))
    // vl check rc 0, vl run: emitProgram: unsupported .map/.filter element type

#### Mechanism

Not traced. The checker resolves the callback `k` by scope to the parameter; the emitter's
`.map` lowering appears to resolve the name to the module function `k` instead, so its element
and result types disagree with the parameter's.
