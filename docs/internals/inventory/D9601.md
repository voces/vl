### D9601 — a returned list of un-annotated functions from two calls at two parameter types, read by `.map` at two types, has no list type

**loud emit reject · `vl check` rc 0 · `index access but list type not collected` · clause 2 · found closing [D9550](D9550.md) · present on master `8789642ad` · filed 2026-10-22 against master `8789642ad`**

Repro:

    function inc(a) { return a + 1 }
    function dbl(a) { return a * 2 }
    function deliver(n) { return [inc, dbl] }
    const v = deliver(1)
    print(v.map((f) => f(3))[1])
    const w = deliver("s")
    print(w.map((f) => f(1.5))[0])
    // vl check rc 0.  vl run: emit error: emitProgram: index access but list type not collected

Want:

    6
    2.5

#### Mechanism

Partly traced. `deliver` takes two instances, one per parameter type, and each instance's
returned slot `e` takes one pin. A probe on the second callback's receiver read it at
`(i32) => i32`, the first instance's element, although its own instance's slot holds the `f64`
pin: the read of the template frame's slot (`monoDeclPathKeys` through `monoFrameInstTmpl`)
finds the pin the first instance banked and answers for both.

#### Ablation

| ingredient removed | outcome | needed? |
| --- | --- | --- |
| the second parameter type (`deliver(2)`) | runs, `6` `2.5` | **yes** |
| the second `.map` (`print(w[0](1.5))`) | runs, `6` `2.5` | **yes** |
| the first `.map` (`print(v[1](3))`) | same refusal | no |
| both bindings, inline (`deliver(1).map(...)`, `deliver("s").map(...)`) | same refusal | no |

#### Grading list

The inline spelling in either order refuses the same way; with `.length` after the second
`.map` it refuses with `a list of this element kind is read where no such list was built`.
