### D3857 — a hole lambda reached through a capture cell at one argument type and through a binding the cell's read is written into at another traps on an indirect call type mismatch

**now a loud emit reject (2026-10-08, lane SC) · was loads then traps · `rv3448b-probes/h/f1_two_types.vl` and `f2_peer_string_seed_i32.vl`, found in review of #3448 · filed 2026-10-08 against master `09e133eb4` · pins: `tests/cases/closures/error-cell-peer-called-at-two-types.vl`, `tests/cases/closures/hole-lambda-binding-one-signature.vl`**

Repro:

    function mk(x: string, n: i32) {
      const g = (y) => y
      const h = (y) => y + y
      let d1 = g
      function w1(): i32 { d1 = d1; 0 }
      let d3 = h
      d3 = d1
      print(d1(x))
      print(d3(n))
    }
    mk("a", 4)
    // vl check: rc 0.  vl run: prints `a`, then exit 70: wasm trap: indirect call type mismatch

#### Mechanism

One closure binding holds one signature, and every lambda written into it is lowered at that
signature. `d1(x)` pins `g` at `string` through `d1`'s capture cell. `d3 = d1` stores that very
`string` instance in `d3`, which `d3(n)` calls at `i32`. The let-alias spelling refuses this
(`is called at more than one argument type`), but the check sits where a call mints a second
instance through a binding's own name, which a cell read and a peer never reach.

`monoBindingSigConflict` (`compiler/emit_mono.vl`) now gives each binding a call goes through
one signature after the pass settles. That signature is what the calls through the binding
were lowered at (`monoNoteBindCall`, recorded along its initializer chain); two of them is a
refusal. The binding's fixed values must share it. Those are a value read through another
binding (taken at that binding's signature), and a lambda read through anything but its own
name. A lambda written by its own name, through bindings never written live after their
initializer, or as the literal itself, is instantiated at the binding's signature and renamed
there. The initializer read by name is renamed the same way. This turns traps into runs,
including a lambda no call pinned. A binding holding only one lambda runs at each call's own
instance as before.

Writes in functions nothing names, writes whose value no later statement reads, annotated
bindings, and lists the program indexes constrain nothing. This check replaces D3858's
registry-hit refusal, which refused a binding whose calls all agreed when the lambda's
instance at that signature was not its first (`gen4.py` module-scope r462).

#### Ablation
