### D3602 — arithmetic on a type parameter bound to a literal union leaves the union, so `mul<5 | 6>(5)` holds 5000000

**closed 2026-10-22 by lane-D9560 · now a loud check reject, `return type mismatch: expected 5 | 6, got i32 (the return of \`mul\` at the call's argument types)`, as the direct spelling is · was check-clean silently wrong, printed `5000000` · clause 1 · closed by the second option below: arithmetic over a type parameter or hole is a derived hole (`HD_BINOP`) that the pin types at the operand's softened base (`binArithPinTy`, check_union_mint.vl), so the product is an `i32` and fails the `: T` return; the inferred `inc(c)` spelling refuses the same way, and `mul<i32>(5)` still prints `5000000` · fixture `literal-unions/error-generic-litunion-arith-annotated-return.vl` · found closing [D9560](D9560.md) by its preflight · found by the #3357 review (D3539's binder reached it from a destination, now declined) · filed 2026-10-03 against master `af70a066a`**

Repro:

    function mul<T>(x: T): T { x * 1000000 }
    const c = mul<5 | 6>(5)
    print(c)
    // vl check: return type mismatch: expected 5 | 6, got i32 (the return of `mul` at the call's argument types)

#### Mechanism

The body checks `x * 1000000` with `x: T` as an open type parameter, and the result is typed
`T`, so returning it passes. At the pin `T = 5 | 6` the operator is not re-asked against the
literal union: the product is an `i32` that the instance returns as a `5 | 6`, which no
member holds. The direct spelling (`const x: 5 | 6 = 5; const y: 5 | 6 = x * 1000000`) is a
check error. A fix re-asks a body operator whose result flows to `T` at the pin and refuses
when the instance's `T` is a literal union the result may leave, or types such an operator's
result as the union's base, which then fails the return. No `Want:` block: whether the
right answer is that refusal or something else waits on that choice. Still open at its own
witness: D4024 binds a literal-union `T` from a call's destination only when the callee's body
makes no new value of `T` (no arithmetic, negation, concatenation or `as` on it, transitively
through the generics it calls), so `const c: 5 | 6 = mul(5)` refuses, but a written type
argument reaches the pin unasked.

#### Ablation

| ingredient removed | outcome | needed? |
| --- | --- | --- |
| the literal-union binding (`mul<i32>(5)`) | prints `5000000`, a real `i32` | **yes** |
| the arithmetic (`id<5 \| 6>(5)`) | prints `5` | **yes** |
| the written type argument (`const c: 5 \| 6 = 5; inc(c)` with `x + 1`) | same escape | no |
