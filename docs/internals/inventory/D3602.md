### D3602 — arithmetic on a type parameter bound to a literal union leaves the union, so `mul<5 | 6>(5)` holds 5000000

**check-clean silently wrong · clause 1 · found by the #3357 review (D3539's binder reached it from a destination, now declined) · filed 2026-10-03 against master `af70a066a`**

Repro:

    function mul<T>(x: T): T { x * 1000000 }
    const c = mul<5 | 6>(5)
    print(c)
    // PRINTS 5000000

#### Mechanism

The body checks `x * 1000000` with `x: T` as an open type parameter, and the result is typed
`T`, so returning it passes. At the pin `T = 5 | 6` the operator is not re-asked against the
literal union: the product is an `i32` that the instance returns as a `5 | 6`, which no
member holds. The direct spelling (`const x: 5 | 6 = 5; const y: 5 | 6 = x * 1000000`) is a
check error. A fix re-asks a body operator whose result flows to `T` at the pin and refuses
when the instance's `T` is a literal union the result may leave, or types such an operator's
result as the union's base, which then fails the return. No `Want:` block: whether the
right answer is that refusal or something else waits on that choice.

#### Ablation

| ingredient removed | outcome | needed? |
| --- | --- | --- |
| the literal-union binding (`mul<i32>(5)`) | prints `5000000`, a real `i32` | **yes** |
| the arithmetic (`id<5 \| 6>(5)`) | prints `5` | **yes** |
| the written type argument (`const c: 5 \| 6 = 5; inc(c)` with `x + 1`) | same escape | no |
