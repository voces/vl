### D2977 — a defaulted literal binding passed FIRST, or read inside an operator, record or list value, lost D2860's note

**loud check reject, by design, and the diagnostic now names the declaration · plumb PL-056 (its diagnostic half; the typing half is an owner ruling) · filed and fixed 2026-09-28 against master `3352eff5c` · typing unchanged: `vl check` exit code and error count identical on all tests/cases, distilled-corpus and std programs**

Repro:

    function mul(a: f32, b: f32): f32 { a * b }
    const x = 0.0
    function f(y: f32): f32 { mul(x, y) }
    print(f(2.0 as f32))
    // master: argument 1: expected f32, got f64   (at `x`; nothing names line 2)
    // now:    argument 1: expected f32, got f64 — `x` on line 2 has no annotation, so its
    //         literal defaulted to `f64`; annotate it: `const x: f32 = …`

#### Mechanism

Three gaps, one family. (1) D2860 queued the note, then dropped it: `numLitNamesStoredNonLit`
drops a read note when the program can store a non-literal through the binding, and it read
every call `g(name, v)` with a non-literal `v` as a UFCS list store (`push(xs, v)`), so passing
the binding FIRST, beside any non-literal argument, withdrew the note. A scalar is passed by
value; the call arms now count only for a list-literal binding. (2) The read test
(`numLitReadIdent`) saw the binding only as the whole refused value or through one index, so
`h * y`, `-h * y`, `{ v: fv }` and `[e, y]` had no note. The destination sites that know their
type (an argument, an explicit or tail return, an annotated `let`/`const`) now raise through
`tErrWant`, and `numLitLeafFor` walks the value against that type through record and list
literals, arithmetic and negation to the literal binding the destination refuses; an arithmetic
walk requires every other leaf to already have the type or be a literal that fits
(`numLitArithFits`), so the suggestion makes the whole value fit. An `operator … mixes` refusal
has no destination and takes the other operand's type. (3) No note is kept when another read of
the binding, in the top-level statement that declares it (anywhere, for a module-level one),
would refuse the suggested type (`numLitUseAccepts`: a parameter of another type, an index, an
`i32` comparison or operand, any position it cannot follow), nor when two notes on one
declaration suggest different annotations. This also withdraws a wrong note master gave: `const
b = 3` read by an `f32` and an `i32` parameter was told `const b: f32`, which refuses the second.

#### Ablation

| ingredient removed | outcome | needed? |
| --- | --- | --- |
| the non-literal second argument (`mul(x, 1.0)`) | note on master | **yes** (gap 1) |
| the binding first (`mul(y, x)`) | note on master | **yes** (gap 1) |
| a scalar binding (`const x = [0.0]`, `mul(x[0], y)`) | note on master | **yes** (gap 1) |
| the operator (`return x` for `return x * y`) | note on master | **yes** (gap 2) |
| the record / list literal (`const z: f32 = x`) | note on master | **yes** (gap 2) |
| the annotation-less declaration (`const x: f64 = 0.0`) | the bare mismatch, no note | **yes** |

#### Grading list

A 240-cell grid (15 positions — first and second argument, return, tail and returned
arithmetic, both operand orders, negation, binding, record field in a binding / argument /
return, list element in a binding / argument / return — × a float literal at `f32` and an
integer literal at `i64`/`f32`/`f64` × `const`/`let` × module / function scope): 120 cells
check (an `i32` read widens to `i64` and `f64`), and all 120 refused cells carry the note —
24 did on master. Every suggestion was applied and the program then checks and prints the
right value (120 of 120). Seventeen controls pin the withheld and the kept notes: another read
at `i32`, as an index, in an `i32` comparison, in another function reading the module binding;
a non-literal store; a same-named binding in another function (kept). Fixtures:
`tests/cases/numerics/literal-default-names-declaration-read.vl`, and the absent notes in
`tests/lsp_wasm_checker_test.ts`.
