### D3514 — `vl fmt` moves a comment after a binary operator, or inside a parenthesis, out of the expression

**closed 2026-10-03 — `vl fmt` keeps each comment where the source had it and the program prints `3` · was a comment RELOCATION by `vl fmt` on a `vl check`-clean program · pre-existing, the same on master `878f6ebe8` · found by lane OQ while grading [D3492](D3492.md) · filed and closed against master `878f6ebe8` · fixture `tests/cases/operators/comment-after-operator.vl`**

Repro (runs, prints `3`; `vl fmt` must print it with the comment kept in place):

    const b = 1 + // c
      2
    print(b)
    // vl check: rc 0.  vl run: 3.  vl fmt: `const b = 1 + 2`, then `// c` and a blank line after the statement.

Want:

    3

#### Mechanism

`binaryChain` in `compiler/format.vl` flattens an operator chain into operand texts and
rejoins them with the operators; `parenExpr` prints `(` inner `)`. Neither has a place for a
comment between an operand and the next one, or between a parenthesis and the expression it
holds, so the comment stayed pending and the statement printer flushed it after the
declaration — the [D3492](D3492.md) shape one construct over. Fixed by the same verbatim anchor:
`commentInOperatorGaps` walks the chain's operator gaps and `parenExpr` tests its two bracket
gaps, and either keeps the expression's source text (`sliceFallback`).
