### D17088 — an unannotated binding whose initialiser is an assignment of `null` drops the assignment's store

**closed 2026-11-24 by lane S1 · now runs, `true` · was check-clean silently wrong, clause 1 · `emitNulNoneLeafPayload` writes an assignment's store before the bottom null, and runs any other leaf for its effect · pin: `tests/cases/soundness/null-binding-initialiser-runs.vl` · found by lane S1 while covering `assignment value nullLit` · filed 2026-11-24 against master `49a2a3c20`**

Repro:

    function f() {
      let s: string | null = "a"
      const x = (s = null)
      print(s == null)
    }
    f()
    // vl check: 0 errors.  vl run (was): prints `false`

Want:

    true

#### Mechanism

The binding's type is the `null` unit, and legacy writes its initialiser as the bottom null
alone: `local.set $x (ref.null none)`. The assignment's store to `s` is never emitted, so `s`
keeps `"a"`. The IR writes the same bytes: its `assignment value nullLit` arm stores first, but
the binding never asks for the value as an assignment. The writer was `emitNulNoneLeafPayload`
(`wasmEmit.vl`): it ran a call and a `??`, and wrote every other leaf as the bottom null alone.
