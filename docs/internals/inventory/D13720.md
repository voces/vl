### D13720 — a lambda that hands on a captured hole function is refused when its enclosing function is called with two generics

**loud emit reject · `vl check` rc 0 · clause 2 · CAPABILITY: the same call made directly in the enclosing function runs, so does the lambda calling the captured function itself, and so does either call alone · found by lane L1 closing [D13660](D13660.md) · present on master `3e3b18500` and after lane L1's D13660 PR · filed 2026-10-25 against master `36bb58995`**

Repro:

    function add(a, b) { return a + b }
    function mul(a, b) { return a * b }
    function apply2(g, s) { print(g(s, s)) }
    function outer(h) {
      const run = (x) => { apply2(h, x) }
      run(1.5)
    }
    outer(add)
    outer(mul)
    // vl check: rc 0.  vl run: emitProgram: cannot take the generic function `mul` as a value

Want:

    3
    2.25

#### Mechanism

Not measured past the ablation. The second call's argument `mul` is refused as a function
value that no call site pins. So the pin that the lambda's call `apply2(h, x)` gives `h`
reaches `add`, the first instance of `outer`, but does not reach `mul`. Suspected: the
lambda's call is attributed to `outer`'s template rather than to each of its instances.
