### D16881 — a call through a set of functions with different results, left closures and handed to an un-annotated parameter, is refused at build after `vl check` passed it

**open, blocked on S3.4d (STORE's at-call solve: mono, after check, is what fixes the per-instance callee signature) · loud emit reject · breaks the check contract: `vl check` rc 0, then the build refuses (`closureCallSetSplits`, wasmEmit.vl's `emitCallRefAt`) · the refusal [D16747](D16747.md) and [D16878](D16878.md) close a trap to; it belongs at check, as [D16851](D16851.md)'s does · filed 2026-11-16 against master `2a0b71c1a`**

Repro:

    function inc0(a) { return a + 1 }
    function half(a) { return a / 2.0 }
    function id2(x) { return x }
    function app(o) { return o.l[0](3) }
    const ll = id2([half, inc0])
    print(app({ l: [inc0, half] }))
    print(app({ l: [half, inc0] }))
    // vl check: rc 0.  vl run: emit error, `this call runs a function value that may hold any of a set of functions returning different types, held where the instance keeps them at one signature; dispatching such a call per function is not built yet`

#### Mechanism

`closureCallSetSplits` reads the tag decision (whether the set is tagged) and the sets handed to
the instance's parameters, both settled by the time emit runs, and refuses at the call. `vl check`
never asks it, so a program check accepts is refused at build. Mono also instances the callee
before the refusal fires: the fixture `tests/cases/closures/error-set-in-record-handed-to-hole-param-two-orders.vl`
records one late demand (`app`), the price of refusing at emit.

#### Why it is blocked

Measured 2026-11-16 with a check-time pass after `elabPrepare` settles the tag decision, asking
`closureCallSetSplits` at each call through a value of every instance key the program needs:

- `vl check` does elaborate (`checkSrcOnce` ends in `elabPrepare`, which runs `elabRun` and
  `fnTagRedecide` until the tag decision settles), so the set's tag state is known at check.
- The callee's signature is not: in D16878's witness the instance `app` elaborates `o.l[0]` to
  `(_) => _`. Emit's guard reads `(i32) => i32`, which mono's own instance typing closes after check.
- A check-time approximation (refuse where the handed set's members return different types at
  the call's argument types) also refuses D16878's same-order spelling, which runs today because
  mono's value-flow rewrite (`monoFlowReadSet`) turns its call into a direct one: runs -> not-runs.

So the refusal moves to check once the closed per-instance callee signature is decided there, or
the value-flow resolution moves into the elaboration. The instance-key design is in
[the STORE note](../refactor-notes/2026-11-16-store-n1-instance-keyed.md).

check closes this row; making these programs run (each member dispatched at its own signature) is
