### D16881 — a call through a set of functions with different results, left closures and handed to an un-annotated parameter, is refused at build after `vl check` passed it

**open · loud emit reject · breaks the check contract: `vl check` rc 0, then the build refuses (`closureCallSetSplits`, wasmEmit.vl's `emitCallRefAt`) · the refusal [D16747](D16747.md) and [D16878](D16878.md) close a trap to; it belongs at check, as [D16851](D16851.md)'s does · filed 2026-11-16 against master `2a0b71c1a`**

Repro:

    function inc0(a) { return a + 1 }
    function half(a) { return a / 2.0 }
    function id2(x) { return x }
    function app(o) { return o.l[0](3) }
    const ll = id2([half, inc0])
    print(app({ l: [inc0, half] }))
    print(app({ l: [half, inc0] }))
    // vl check: rc 0.  vl run: emit error, `this call runs a function value that may hold any of a set of functions returning different types, held where the instance keeps them at one signature; dispatching such a call per function is not built yet`

#### Mechanism

`closureCallSetSplits` reads the tag decision (whether the set is tagged) and the sets handed to
the instance's parameters, both settled by the time emit runs, and refuses at the call. `vl check`
never asks it, so a program check accepts is refused at build. Mono also instances the callee
before the refusal fires: the fixture `tests/cases/closures/error-set-in-record-handed-to-hole-param-two-orders.vl`
records one late demand (`app`), the price of refusing at emit.

D16747's clause 2.
