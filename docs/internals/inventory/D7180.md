#### Mechanism

Probed 2026-10-19 against master `966471462`. The list and the loop are scenery. The
ingredient is comparing a hole function that its calls split into two instances: `apply2(add);
print(apply2 == apply2)` with no list is refused too (`g` is called at two instances of the
function handed to it). A comparison reads the function's identity, and the split leaves two
functions where the program wrote one. Treating the comparison as a read that calls nothing in
the value-flow question was tried. It also builds seven `@emit-error` fixtures that
compare an uncalled hole function (`closures/error-uncalled-hole-fn-*-compared.vl` and
neighbours). Each of those would then compare a value at a defaulted signature, and a default
must never be observable ([D4551](D4551.md)). So the close needs a ruling on what a split
function's identity is, not a wider reach.
