### D2555 — a kept assignment narrowing of a scalar box reads at the box inside a function body

**closed 2026-09-25 for module bindings — the filed repro RUNS and prints `1` · the by-reference local face stays check-clean invalid wasm (grading list) · was check-clean invalid wasm, clause 1 · pre-existing, identical on master `680b67486` · filed 2026-09-25 while revising D2529**

Repro:

    let g: i32 | null = null
    g = 0
    function f(): i32 { return g + 1 }
    print(f())
    // vl check: rc 0.  vl run (master): invalid module, expected i32, found (ref $type)

#### Mechanism

The checker keeps an assignment's narrowing in a body nothing can reach after a `null` write
(D2529), and the emitter replays a declaration-site narrowing into a body from
`capNarrowRecord`. `capNarrowBuild` never recorded one for a module binding: it scanned the start
function's statements without the post-statement narrowing step a block gets, skipped global
initialisers, and recorded a top-level function's frame before any module statement, so the
body read the global's box where the checker had typed its member. It now walks start
statements and global initialisers in list order with `preStmtNarrow`/`cnPostGuard` between
them, and records each top-level function, and each instance a generic one was monomorphised into, at
its own position (`topFnNodes`/`topFnOrd`), the instance under its template's widening bank. A
reference nullable read off the box ran before only because `array.len` and `struct.get`
accept a null ref.

#### Ablation

| ingredient removed | outcome | needed? |
| --- | --- | --- |
| `g: string \| null` with `g.length` | ran on master | **yes** — a scalar box |
| the function a module lambda, or a `map` callback | same, now runs | no |
| the function generic (`function h<T>(x: T)`) | same, now runs | no |
| a later `g = null` | the checker widens (D2529) | **yes** |
| a local captured by reference (`v = 1; const h = () => v + 0; v = 2`) | still invalid wasm | open: the cell's read replays no narrowing |

#### Grading list

* The by-reference local face: `function main() { let v: i32 | null = null; v = 1; const h = () => v + 0; v = 2; print(h() + 1) }` — check-clean invalid wasm, identical on master.
* A module lambda `const h = () => g + 0` and `[1, 2].map((x: i32) => x + g)`.
* A local's sync callback before a later null write, `v = 1; [1, 2].map((x: i32) => x + v); v = null`:
  still check-clean invalid wasm, the same cell read.
