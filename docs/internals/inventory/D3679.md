### D3679 — a record whose literal is a constant expression (a module-level record built at instantiation) never has its record fields inlined

**closed 2026-11-16 · runs, prints `999000` · a cost row: one `struct.new` per store survived at `-O3`; fixed by lane AE4 (Aeomach AE-004, the record face), as the inline-record step takes a global initializer's `struct.new` operand apart, so the witness goes from 1 `struct.new` in function bodies to 0 at `-O3`, and AE-004's own witness from 2 in `step` to 0 · lane IR1 · filed 2026-10-05 against master `18ce103be` · note: [2026-11-16-ae4-record-field-inplace](../refactor-notes/2026-11-16-ae4-record-field-inplace.md)**

Repro:

    type V3 = { x: f64, y: f64, z: f64 }
    type Foot = { off: V3, lift: f64 }
    const foot: Foot = { off: { x: 1.0, y: 2.0, z: 3.0 }, lift: 0.5 }
    function mk(k: f64): V3 { return ({ x: k, y: k * 2.0, z: k * 3.0 }) }
    let s = 0.0
    for i in 0 until 1000 {
      foot.off = mk(i as f64)
      s = s + foot.off.y
    }
    print(s)

Want:

    999000

#### Mechanism

The emitter builds a module-level record literal as the global's constant initializer,
`struct.new $Foot (struct.new $V3 …) …`. The inline-record step rewrites function bodies
only, so it refused any parent type a constant expression makes. The fix is the same deletion
it does in a body, in the global section: a `struct.new $V3` operand's fields are already in
place. A table or element initializer stays opaque. sunpa's `$29` field 1 is this row.

#### Grading list

The witness at `-O` and `-O3`, by output and by `struct.new` count in function bodies; a
constant parent whose record operand is a `global.get` (not deletable in a constant
expression) must stay refused (`tests/vl_opt_inline_const_test.ts`).
