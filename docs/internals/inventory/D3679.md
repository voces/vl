### D3679 — a record whose literal is a constant expression (a module-level record built at instantiation) never has its record fields inlined

**runs today and must keep running — a cost row: one `struct.new` per store survives at `-O3` · lane IR1 · filed 2026-10-05 against master `18ce103be`**

Repro:

    type V3 = { x: f64, y: f64, z: f64 }
    type Foot = { off: V3, lift: f64 }
    const foot: Foot = { off: { x: 1.0, y: 2.0, z: 3.0 }, lift: 0.5 }
    function mk(k: f64): V3 { ({ x: k, y: k * 2.0, z: k * 3.0 }) }
    let s = 0.0
    for i in 0 until 1000 {
      foot.off = mk(i as f64)
      s = s + foot.off.y
    }
    print(s)
    // vl build -O3 with VL_INLINE_EXPLAIN=1: "not inlined: type 1 is made in a constant
    // expression (a global's initializer)"; one struct.new per iteration.

Want:

    999000

#### Mechanism

The emitter builds a module-level record literal as the global's constant initializer,
`struct.new $Foot (struct.new $V3 …) …`. The inline-record step rewrites function bodies
only, so it refuses any parent type a constant expression makes. The rewrite is the same
deletion it does in a body — a `struct.new $V3` operand's fields are already in place — in the
global and element sections. sunpa's `$29` field 1 is this row.

#### Grading list

The witness at `-O` and `-O3`, by output and by `struct.new` count in function bodies; a
constant parent whose record operand is a `global.get` (not deletable in a constant
expression) must stay refused.
