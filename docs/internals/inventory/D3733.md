### D3733 — an `i64` local assigned a value `if` of hex literals as an annotated function's tail is check-clean invalid wasm

**closed 2026-10-06 — the witness prints `4294967294` · was check-clean invalid wasm, clause 1 · found by lane L2 while grading [D3664](D3664.md) against master `687b42dbe` · closed by lane S4 against master `a37097b64` · fixture `tests/cases/literals/hex-width-through-assignment-value.vl`**

Repro:

    function v(c: boolean): i64 {
      let x: i64 = 0
      x = if c { 0xfffffffe } else { 1 }
    }
    print(v(true))
    // vl check: rc 0.  vl run: invalid module, type mismatch: expected i64, found i32

Want:

    4294967294

#### Mechanism

An assignment is typed by its right side, and a hex literal is a bit pattern of the width it is
used at. The store re-types a value `if`, `match` or block of radix tails to the target's width
([D2617](D2617.md), `radixLitAdoptTails`), so the cell holds the 64-bit value, while the checker
keeps the assignment's value at the literal's 32-bit reading, `i32`. The emitter re-reads the
cell and unwidens it to `i32` (`asgReadUnwidenOp`), but the `emitExprAs*` widenings classified the
value by the right side's re-typed width (`widenClassifyExpr`), took it as already `i64` and
extended nothing: invalid wasm at an `i64` result, the 32-bit pattern sign-extended elsewhere.

The close is emit-side and leaves the checker's type alone: `asgRadixWidePrim` (emit_classify.vl)
names the width such an assignment's right side was built at, and `emitExprAsI64`/`F64`/`F32`
read the stored cell where the delivery's width is that one, and otherwise take the 32-bit
pattern and convert it as an `i32`. Every `i32` use keeps master's value. A chained `a = b = …`
hands on the inner assignment's width. Neither a closure nor a capture is an ingredient: the
closure-local spelling was invalid wasm too, and [D3734](D3734.md) is this row through a cell.

A first close (lane S4, round 1) re-typed the assignment itself to the wide type, and lost runs:
every `i32` use of the value (`t(x = 0xff)` with `t(n: i32)`, `const k: i32 = (z = 0xff)`, `y & 1`,
`[y]` into `i32[]`) became a check error. The per-use read is the rule the literal already obeys.
