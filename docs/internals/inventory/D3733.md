### D3733 — an `i64` local assigned a value `if` of hex literals as an annotated function's tail is check-clean invalid wasm

**closed 2026-10-06 — the witness prints `4294967294` · was check-clean invalid wasm, clause 1 · found by lane L2 while grading [D3664](D3664.md) against master `687b42dbe` · closed by lane S4 against master `a37097b64` · fixture `tests/cases/literals/hex-width-through-assignment-value.vl`**

Repro:

    function v(c: boolean): i64 {
      let x: i64 = 0
      x = if c { 0xfffffffe } else { 1 }
    }
    print(v(true))
    // vl check: rc 0.  vl run: invalid module, type mismatch: expected i64, found i32

Want:

    4294967294

#### Mechanism

The delivery into the target re-types a value `if`, `match` or block of radix tails to the
target's width ([D2617](D2617.md), `radixLitAdoptTails`), so the store builds the join at 64 bits.
The checker had already read the right side's type as the 32-bit `i32` join and kept it as the
assignment's value type, recording an `i64` store beside it. An assignment yields its right side,
so the emitter re-read the cell and unwidened it to `i32` (`asgReadUnwidenOp`, `i32.wrap_i64`),
and the tail-return coercion, which reads the re-typed join as already `i64`, extended nothing.
The close (`asgRadixPinnedTy`, typecheck.vl) takes the right side's re-typed width as the
assignment's type once the delivery has pinned it, at an `i64`, `f64` or `f32` target or its
nullable, so the value is the stored pattern. Neither a closure nor a capture is an ingredient:
the closure-local spelling was invalid wasm too, and [D3734](D3734.md) is this row with a cell.
