### D7452 — `??` straight over a closure parameter's call returning a nullable literal union is refused at emit

**closed 2026-10-20 by lane L6 · runs, prints `a` · was loud emit reject (`` `??` over this nullable value is not supported yet ``) · clause 2 · `monoBakeCallback` specialises a call passed a closure literal, and the `??` and parens it rebuilt carried no type, so the niche classifier saw an untyped left operand; the rebuilt nodes now carry the template's type (`nodeTyCarry`) · pin: `tests/cases/literal-unions/coalesce-baked-callback-nullable-atom.vl` · found closing [D3207](D3207.md) · present on master `573358403` · filed 2026-10-20 against master `573358403`**

Repro:

    function run(f: () => "a" | "b" | null): string { return f() ?? "n" }
    print(run(() => "a"))
    // vl check: rc 0.  vl run: emitProgram: `??` over this nullable value is not supported yet

Want:

    a

#### Mechanism

`monoBakeCallback` specialises `run` for the closure literal and rebuilds its body, rewriting
`f()` into a direct call. The `??` and parens it rebuilt carried no recorded type, so
`coalesceDefaultNullable` and the atom-niche `??` saw an untyped node and fell to the refusal.
A bound `const v = f()` or a non-literal argument does not reach the rebuilt node.
