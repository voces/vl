### D6703 — a binding annotated with one type parameter and seeded from a parameter of another is accepted by the checker and builds invalid wasm

**closed 2026-10-18 by lane L1 · runs, prints `x` then `3` · was check-clean invalid wasm · `vl check` rc 0 · clause 1 · the split that gives a parameter's type parameter a fresh name per instance ([D6372](D6372.md)) now renames with it a binding annotated with another type parameter of the same function and seeded from that parameter, so `b` takes `a1`'s instance; the emitter asks for it when the two type parameters bind different function instances; three type parameters, a `const` binding and a `boolean` call run too, and [D6740](D6740.md) closed with it · pins: `tests/cases/generics/typaram-binding-seeded-from-another-typaram.vl` · found closing [D6523](D6523.md) · filed 2026-10-18 against master `ca2adfdc7`**

Repro:

    function same<T>(k: T): T { k }
    function mid<F, G>(a: F, a1: G) {
      let b: F = a1
      print(a("x"))
      print(b(3))
    }
    mid(same, same)
    // vl check: rc 0.  vl run: the emitted module failed to validate inside `mid`: type mismatch: expected (ref $type), found i32

Want:

    x
    3

#### Mechanism

Two distinct type parameters are not assignable to each other in a generic body, but `mid` is
checked at its call, where `F` and `G` both bind the generic `same`, so the binding is well typed
there; the emitter built `F` and `G` at different instances of `same` and gave `b` the wrong one.

Re-graded 2026-10-18 by lane L1: the close is the split's, not a refusal, since the call the
checker grades is well typed.
