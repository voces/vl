### D3743 — an empty `[]` binding that no use ever pins is refused, while the same `[]` handed to an un-annotated parameter defaults to `i32` and runs

**loud check reject · graded DESIGN, the refusal D1470 owes: no use fixes the element · the `two_instances` un-annotated cell of `empty-list-union-arm` and the `lk-empty-*` family · lane UA · filed 2026-10-06 against master `42c4d4c10`**

Repro:

    function __two() {
      const v = []
      print(v.length + 70)
    }
    __two()
    // vl check: cannot infer a type for 'v' — an empty array literal has no element type
    // until it is used; use it where its type is known, or annotate the binding

#### Mechanism

`checkArrayLitNode` types `[]` as a list with an open element, `flushUninferred` finds the
binding's row still open when its scope closes, and only an `__array_new_default__` row may
take the `i32` default (`arrDefRowIsCall`, D1470: `array.new_default` promised each slot a
zero, a bare `[]` promised nothing). Nothing in the witness reads or writes an element, so
nothing could pin it, and the refusal is the one the design documents. The template's other
instance (`const r2 = v; r2.push("x")`) is pinned and runs; only the instance with no
element use is refused.

The one inconsistency is at the ARGUMENT position: `function take(a) { print(a.length) }`
then `take([])` runs and prints `0`, because an argument is not a pending binding and the
emitter takes the `i32[]` default. That default is harmless (no element is ever observed), so
it is not a soundness defect, but it is the same program the binding spelling refuses.

Question for the owner, only if the asymmetry matters (recommendation: (a), no change):

* (a) keep both as they are: a binding with no element use is refused, an argument is not.
  `const v = []; print(v.length)` refuses; `take([])` with a length-only body runs.
* (b) refuse the argument too, in the binding's words: `take([])` with a length-only body
  becomes `cannot infer a type for this argument`. Consistent, but moves a program that runs
  today to a refusal.
* (c) let a binding no use observes default to `i32`, as `__array_new_default__` does:
  `const v = []; print(v.length)` prints `0`. Relaxes D1470 for the case where the element
  can never be seen.

#### Ablation

| ingredient changed | outcome | needed? |
| --- | --- | --- |
| `v.push("x")` added | runs | **yes** — no element use |
| `const v: string[] = []` | runs | **yes** |
| `v` passed to an un-annotated parameter instead (`take([])`, length-only body) | runs, prints `0` | — the asymmetry above |
| moved to module scope | refuses the same | no |

#### Grading list

* Must stay a loud check reject unless the owner picks (c).
* `take([])` with a length-only body must keep running unless the owner picks (b).
