### D2621 — a declared `__…__` intrinsic named as a value (not called) is check-clean and has no emit lowering

**closed 2026-11-08 (`intrinsicValuesWrap`, `compiler/check_intrinsic_values.vl`) · the filed repro RUNS and prints `0` · was loud emit reject · a value read of an intrinsic is rewritten before checking into a lambda that calls it; `sqrt` and the other bare numeric intrinsics take `f64` (integer ones `i32`) there · a lane-immediate SIMD intrinsic as a value now refuses at check, since its lane cannot be a runtime operand · the checker-special `__str_from_bytes__`, `__trap__`, `__array_new__` and `__array_copy__` are values too, and `__array_new_default__` refuses as a value by design (§The checker-special intrinsics) · fixture `tests/cases/intrinsics/intrinsic-as-value.vl` · filed 2026-09-26 against master `06930fb68` (found reviewing PL-043)**

Repro:

    const f = __load_i32__
    print(f(0))
    // vl check: rc 0.  vl run: emitProgram: identifier is not a parameter, local, or global

Want:

    0

#### Mechanism

The dunder intrinsics are `declare`d into the checker's global scope with a function type
(`__load_i32__`, every `simdTableBuild` row, every atomic, the saturating truncations), so an
identifier naming one outside callee position types as an ordinary function value. The
emitter lowers them only as a callee (`emitCall`'s by-name arms); as a value there is no
function index, closure or wrapper to read, so a binding reports `identifier is not a
parameter, local, or global` and a `.map` callback `.map/.filter callback signature is not
interned`. The bare numeric intrinsics (`sqrt`) are not declared and refuse at check instead.

#### Ablation

| spelling | outcome |
| --- | --- |
| `const f = __load_i32__` | check rc 0, emit refuses (as filed) |
| `const f = __add_f32x4__` (SIMD row) | check rc 0, same emit refusal |
| `const f = __atomic_load_i32__` (atomic row) | check rc 0, same emit refusal |
| `[1.5].map(__trunc_sat_f64_s_i32__)` | check rc 0, `callback signature is not interned` |
| wrapped: `const f = (a: i32) => __load_i32__(a)` | runs, prints 0 |
| `const f = sqrt` (bare numeric intrinsic) | check refuses: undeclared identifier |

The ingredient is a declared intrinsic in a non-callee position; the family is every
declared dunder, not one table. Wrapping it in a lambda always runs, so the capability
exists and only the value position lacks a lowering (clause 2). Open question for a ruling:
synthesise a wrapper function per intrinsic used as a value, or refuse the value position
at check as `sqrt` already is. Recommendation: synthesise the wrapper, since a lambda of the
same signature already compiles.

#### Grading list

- `const f = __add_f32x4__` then `f(a, b)`, and the atomic and trunc_sat spellings above.
- `[1.5].map(__trunc_sat_f64_s_i32__)` must print `1`.
- A value reference inside a function body and in a struct field of function type.

#### The checker-special intrinsics

Five intrinsics are typed by an arm of the call checker rather than declared, so a read of one
outside callee position said `undeclared identifier`, which is false of every one of them.
Graded with `const f = NAME` and a call that prints the result:

| intrinsic | value |
| --- | --- |
| `__str_from_bytes__` | `(u8[], i32, i32) => string`, runs |
| `__trap__` | `(string) => never`, or `() => never` where the destination takes no argument; runs and traps |
| `__array_new__` | generic in `T`, which the fill binds; `an(3, 7)` and `an(2, "q")` both run |
| `__array_copy__` | generic in `T`, which the two lists bind; runs |
| `__array_new_default__` | refused at the read: `cannot be named as a value: its element type comes only from the destination of each call` |

The last is a DESIGN refusal. The element type of `__array_new_default__(n)` is bound only by
where the result lands, and a function value has no parameter to bind it from. That is the rule
the language already applies to the user-written twin: `function mk<T>(n: i32): T[]` named as a
value is refused with `cannot infer type parameter `T`` at a bare binding, and again with
`(n: i32) => i32[]` as its destination.

The `const f = NAME` grid over 317 names (every `__…__` literal in `compiler/*.vl` plus the 20
bare numeric intrinsics) runs 247 on master `9686b2a1`, 258 with the host-floor rows above, and
262 with these four. The 55 left are 14 lane rows, `__array_new_default__`, four names refused in
