### D14801 — a value typed by a written union of two type parameters is returned through a concrete annotated return without the instance checking it

**check-clean silently wrong · clause 1 · open · found checking the template typing of D3618's `v ?? 9` · filed 2026-11-01 against master `d4033156`**

Repro:

    function F<A, B>(v: A | B): boolean {
      v
    }
    print(F(5))
    // vl check: rc 0.  vl run: prints `true`

Want:

    a check reject at the call: the instance returns an `i32` where `boolean` is declared

#### Mechanism

Inside a generic body a type variable is assignable to anything, so the template accepts `v` as a
`boolean` result. The instance's re-check refuses the same delivery into an annotated binding
(`const r: boolean = v` is `cannot assign i32 to 'r' of type boolean`), and refuses the one-parameter
spelling's return (`return type mismatch: expected boolean, got i32`), but a value typed by a WRITTEN
union of two parameters reaches the annotated return unchecked. The emitter then stores the
instance's value at the declared result's rep.

#### Ablation

| ingredient changed | outcome on master | needed? |
| --- | --- | --- |
| `F<A>(v: A): boolean` | check reject at the instance | **yes** (two parameters) |
| `const r: boolean = v` before returning `r` | check reject at the instance | **yes** (the return position) |
| `F(5, "s")` over `F<A, B>(v: A \| B, w: B)` | check-clean invalid wasm | no, a second face |
| `F<A, B>(v: A \| B): i32` called with `"s"` | check-clean invalid wasm | no, a second face |
| `F<A, B>(v: A \| B \| null): boolean { v ?? 9 }` with a `boolean \| null` null | prints `true` | no, D3618's `??` reaches it too |
