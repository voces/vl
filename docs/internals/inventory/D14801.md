### D14801 — a value typed by a written union of two type parameters is returned through a concrete annotated return without the instance checking it

**closed · now a loud check reject, `return type mismatch: expected boolean, got i32 (the return of `F` at the call's argument types)` · was check-clean silently wrong, clause 1 · closed by re-checking a deferred return's bound union members when the call leaves another member's parameter open (`boundUnionMembers`, `validateRetCstrs`, check_assignable.vl) · the face whose call binds no parameter at all moved to [D14802](D14802.md) · found checking the template typing of D3618's `v ?? 9` · filed 2026-11-01 against master `d4033156`**

Repro:

    function F<A, B>(v: A | B, w: B): boolean {
      v
    }
    print(F(5, 6))
    // was: vl check rc 0, prints `true`

#### Mechanism

Inside a generic body a type variable is assignable to anything, so the template accepts `v` as a
`boolean` result and defers the question to each call (`noteRetCstr`). `validateRetCstrs` answered
it only once the substituted body type held no hole. `F(5, 6)` binds `B` from `w` and leaves `A`
open, so the body type is `A | i32` and the check was skipped for good. Its bound members are in
the instance's value whatever `A` becomes, so they are now checked against the declared return.
