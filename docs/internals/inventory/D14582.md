#### Mechanism

Not traced past the ablation. D6541 made the value-call union-name reader take the hole's
pinned instance for one hole parameter; with two parameters holding instances of one generic,
the reader still finds no union name for one of them. With `paramCloSigKey` read from the
elaboration instead (D14580's conversion), the same program fails one step later, with
"parameter 1 of type (blank) has no representation in the function-value ABI": the instance of
`viaOrz` has no elaborated type for its parameters, because each holds a generic function
value (`elabParamsClosed` declines, D14580 cause (b)).
