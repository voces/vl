### D17862 — a choice of two annotated-parameter functions whose closed results differ joins as a union of function types, so no call through it checks

**loud check reject · clause 2, under D15791, its fix a covariant function join with T8.3 adapters (coordinator: a design question ruled separately) · `called value is not a function (((i32) => string) | ((i32) => boolean))` · split from D17100 by M1 · filed 2026-11-28 against master `15901f4e3` by lane CENSUS**

Repro:

    function str(_a: i32) { return "s" }
    function bo(_a: i32) { return true }
    function run(c: boolean) {
      const g = if c { str } else { bo }
      print(g(3))
    }
    run(true)
    // vl check: rc 1, "called value is not a function (((i32) => string) | ((i32) => boolean))"

Want:

    s

#### Mechanism

The members' annotated parameters are the only ingredient that separates this from D17100's M1
close. A read of a function with an annotated parameter carries no set (`elabFnSetOf` is empty),
so `fnSetResultJoin` (`check_relate_core.vl`) does not apply, and the `if` joins the two
closures into a union of function types, which the call checker does not call.
