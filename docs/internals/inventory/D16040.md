### D16040 — a list of a generic call's records keys its ref-list row at the call's untagged checker type

**runs today and must keep running · 6 programs of the sweep population · filed 2026-11-13 against master `1a24ba21`**

Repro:

    function inc0(a) { return a + 1 }
    function mk<T>(x: T) { return { fs: [inc0], x: x } }
    const rs = [mk(1)]
    print(rs[0].fs[0](2))

Want:

    3

#### Mechanism

The global list literal `[mk(1)]` mints its ref-list row in `collectAArrayLit`'s record-list arm
(through `nodeMintOnRead` ← `arrLitMintTrees` ← `collectAHeldRep`). It keys the row by
`arrLitMintHintTy`, the call's checker type, `{fs: ((i32) => i32)[], x: i32}`, whose `fs` element
is untagged. The values are built at the instance's record, the held rep (D15350), where `fs`'s
element is tagged with set 0. The two render and compare `tySame` alike, but their row keys
differ (`repRowId` 13 against 9). So no type rung of `rlElemStructRow` finds the row, and it is
found by the element NAME. The fix is the mint's: key the slot by the held rep. Traced by lane D
on master `739db770`.
