### D16040 — a generic body mints its instance's ref-list row at the body's function-value set

**runs today and must keep running · 6 programs of the sweep population · filed 2026-11-13 against master `1a24ba21`**

Repro:

    function inc0(a) { return a + 1 }
    function mk<T>(x: T) { return { fs: [inc0], x: x } }
    const rs = [mk(1)]
    print(rs[0].fs[0](2))

Want:

    3

#### Mechanism

The list of records built from `mk`'s instance gets a ref-list row whose recorded element type
is the generic body's record type. The struct row the values are built at is the instance's. The
two print the same (`{fs: ((i32) => i32)[], x: i32}`) and are `tySame`, but their row keys differ
(`repRowId` 13 against 9): the function-value sets differ. So no type rung of
`rlElemStructRow` finds the row. It is found by the element NAME, through `structIndexByName`,
which crosses the function-set identity the twin ruling keeps apart. The fix is mono's: the
instance's ref-list row records the instance's element type.
