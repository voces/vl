### D17073 — a method-style call to a recursion-group member declared after its caller records the type `<error>` in a check-clean program

**closed 2026-11-23 — the member call queues itself for re-recording at the callee's published return, as the plain call does (`ufcsPendRet`) · 1 witness · filed 2026-11-23 against master `c12265041` by lane IR-C1 · found by the IR's `rep unsup` census: the call's recorded type is `<error>`**

Repro:

    type N = { k: i32 }
    function down(self: N) {
      if self.k <= 0 { return 0 }
      return { k: self.k - 1 }.up()
    }
    function up(self: N) { return self.down() + 1 }
    print({ k: 3 }.up())
    // vl check: rc 0.  vl run: 4.  The call `{ k: self.k - 1 }.up()` in `down` is recorded at `<error>`

Want:

    4

#### Mechanism

The checker infers an un-annotated recursion group from whichever member the program reaches first
(D7761). The method-style call `{ ... }.up()` in `down` names `up` before `up` has a result type,
and the node keeps the `<error>` type it was given then. The program builds and runs only because
legacy writes the call from the callee's signature, not from the node's type. A check-clean program
must not carry an error type to emit. The IR missed it as `rep unsup` until it read the callee's
result rep instead.

#### Ablation

| ingredient changed | recorded type | needed? |
| --- | --- | --- |
| `up` declared before `down` | `i32` | **yes** |
| `up({ k: self.k - 1 })` (the plain call) | `i32` | **yes** (method-style) |
