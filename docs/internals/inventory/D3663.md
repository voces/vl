#### Mechanism

Every function value was a fat pointer `{env, id}` with `env` a struct of the captured values,
and every call of a local binding went through `call_indirect`, whether or not the value ever
left its frame. `cloLiftScan` (the last pass, once the arena is final) decides per lifted slot:
the binding is a `const` initialised with the lambda, or a block-local declaration; every
identifier spelling its name in the declaring frame is the callee of a call (a block-local
function may also call itself); no nested function names it, no member access spells it, and
no other declaration in the frame binds it or binds a capture's name twice, since a call site
reads the captures by name. A lifted function's captures are parameters `1..n`
(`envSlotShift`), its functype is its own rather than the shared `$fnsig`, its capture reads
are `local.get` (`emitCaptureSlotRead`), every call is `emitDirectCall` with the captures
pushed after the env, and its binding stores nothing. Passing the CURRENT value is sound
because a capture that a write could change after the closure is made is already a shared
cell (`captureBoxRewrite`'s `cboxByRef`), and the cell's reference is what is passed.
Declined, so they keep the closure path: an unannotated parameter (per-pin clones), a
generic or monomorphized frame chain, a module-scope frame ([D3666](D3666.md)), and a use
inside another function ([D3665](D3665.md)). Materialising a lifted function as a value is a
loud `emitFail`, not a silent miss.

#### Ablation

| ingredient | lifted | why |
| --- | --- | --- |
| the witness | yes | every use of `f` is a call in `sum` |

| a second `const f` in an inner block | no | the frame binds the name twice |
| `f(x)` inside another lambda | no | a capture of `f` ([D3665](D3665.md)) |

| the loop at module scope | no | [D3666](D3666.md) |
