#### Mechanism

Traced, not fixed (time-boxed 2026-11-28). As in D17778, the write widens `t.f`'s set to
`{inc0, dbl}`, which is tagged; a probe shows both written values and the binding's field type
carry that set (set 2, tagged), and `dbl` is built as its id (source `i32`). The record literal
holds a tagged leaf, so `elabHeldFnLitStamps` skips it (class 3), and its open `g` closure list
keys no row: the literal is built at its own closure row and converted. Stamping it with the
tagged fields kept and the rest closed at the uncalled default (`elabClosedKeepingIds`, tried and
reverted) does not close it either; the next step is to probe which row the stamped type mints.

Probed again 2026-11-28 (after D17781's fix). The IR's miss converts the written value's id
(`i32`) into a closure slot: the binding's row comes from its held type
`{f: (i32) => i32, g: ((i32) => i32)[]}`, where `f` is a plain closed function, the tag dropped.
Two attempts changed nothing, both reverted:
- stamping the class-3 record through the class-2 path, which keeps `f` as the tagged open type;
- letting `letLitHeldTy` take a stamp whose only type variables sit inside tagged functions.

A rung probe of `letHeldTyOf` shows `letLitHeldTy` answers: the init literal's rep is the binding's
own closed type, `f` a plain closure, since the checker's closed record carries no tag. Keeping a
field whose value's type is tagged there (`litKeepTaggedFields`) changed nothing, and was reverted.

A reduced spelling, with no write, already refuses on master:

    let t = { f: inc0, g: [half] }
    print(t.f(3))

It runs as a `const`, with `g: 1`, or with `t.g[0](3)` also called. That `let` refusal is the next
probe; this row's write may only be a second way into it.
