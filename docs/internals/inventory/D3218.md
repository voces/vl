### D3218 — [CLOSED 2026-09-29] a `boolean` binding fits an `i32` parameter, binding or hole, and the program prints its bit

**closed 2026-09-29 by the owner's ruling (C), `open-rulings.md` §`boolean-into-i32`: the A7 coercion is retired, so the filed repro is now a loud check reject naming the conversion (``argument 1: expected i32, got boolean — a `boolean` is not a number; convert it with `b as i32` ``), and `b as i32` / `b as u8` / the wider numeric targets are the explicit spelling · was check-clean silently wrong, the designed A7 coercion (#152) · clause 1 · found by the #3287 split-head review (`rv3287s-4099`, the hole-callee grid) · filed 2026-09-29 against master `94670f728`**

Repro:

    function H(h, v) {
      return h(v)
    }
    const aa: boolean = true
    print(H((x: i32) => x + 1, aa))
    // before the ruling: vl check rc 0, vl run prints 2

Want:

    check reject: argument 1: expected i32, got boolean

#### Mechanism

Not localised. The checker's fit refuses the literal (`((x: i32) => x + 1)(true)` is `argument 1:
expected i32, got boolean`) and accepts a `boolean`-typed binding at the same destination, so the
`i32` rep of `true` is read as the number `1`.
