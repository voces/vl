### D6772 — the result of a declared list-returning generic is read at the row its structural element name keys, not the row its signature declares

**closed 2026-10-18 by lane L6 · runs, prints `82` · was check-clean invalid wasm · `vl check` rc 0 · clause 1 · a call to a named function whose return is a bare list annotation reads its element from the row the signature's result names, the one the instance returns · pins: `tests/cases/lists/nested-record-list-beside-same-layout-declared-records.vl` · found closing [D6731](D6731.md) · filed 2026-10-18 against master `1e7bc12cb`**

Repro:

    type Ax = { v: i32 }
    type Jx = { f: Ax | null }
    type Ix = { f: Ax }
    const src = [{ f: { v: 7 } }, { f: { v: 8 } }]
    const xs = [[...src]]
    function first<T>(g: T[][]): T[] { return g[0] }
    const v = first(xs)
    print(v[1].f.v * 10 + v.length)
    // vl check: rc 0.  vl run: invalid module, expected (ref null $6), found (ref $4); $6 is `Jx[]`

Want:

    82

#### Mechanism

The instance's signature returns the `Ix[]` row, but the binding of `v` took its element name
from the call's recorded result, a structural `{f:{v:i32}}` that keys `Jx`, declared first
with the same layout. The same name-keys-an-earlier-record cause as [D6731](D6731.md), at the
call result rather than at an index.
