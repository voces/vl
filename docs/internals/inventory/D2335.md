### D2335 — a bare `{ … }` lowered to `if (i32.const 1)`, and every one was an `if` binaryen's `code-pushing` re-walked the rest of its block for

**closed 2026-09-24 — plumb's `chunk_568` (2.4 MB, 22,271 bare blocks) runs `wasm-opt -O` in 3.7 s CPU where it took 11.5 (on the same host, rung input only), `chunk_393` 7.4 → 5.5 s, the median `chunk_0` 1.58 → 1.52 s; a build-time cost, not a miscompile: every spelling ran · filed 2026-09-24 against master `84efc195a`**

#### Mechanism

`drwBareBlock` (compiler/emit_rewrite.vl, D1253) rewrites a bare block to `if true { … }` so
the per-function scans need no `Block` arm, and `emitIfLinkStmt` then lowered that `if` like
any other: `i32.const 1`, `if`, the arm, `end`. Binaryen's `code-pushing` treats every `if` as
a push point, and for each one whose block holds a single-assignment local before it,
`optimizeIntoIf` walks every later item of the block to learn which locals the code after the
`if` reads. A translated function is one long block of such blocks, so the pass was
quadratic in them: 568's rung input held 27,425 `if`s, 22,271 of them `i32.const 1`, and
`code-pushing` read 7.4 of its 11.0 s.

#### Fix

`emitIfLinkStmt` lowers an else-less `if` whose condition is the literal `true` (a bare block,
or a written `if true`) as its arm's statements, with no frame, as the A-exhaust arm already
did for a condition the checker proved. Locals, narrowing and `break`/`continue` depths are
unchanged: the arm opened no scope of its own in wasm, and no branch targeted its frame. The
seed grows 25 bytes; the `-O` output of all 47 `bench/` programs and of plumb's
`tools/decode-bench.vl` is byte-identical, and plumb units grow by +0.02% to +0.7%, where
binaryen now duplicates a shared tail into the arms of an `if` it restructures.
`tests/cases/scope/bare-block-lowers-inline.vl` pins the exits.
