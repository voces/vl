### D17668 — a maker's first instance mints its lambda with no frame, so the lambda's capture has no binding and is held at `i32`

**closed 2026-11-26 by COV-CLOS · runs, prints `1.5`, `1`, `3`, `s` · was check-clean invalid wasm · clause 1 · found closing `closure env capture` in `maker-delivered-at-two-function-types.vl` `counted` · filed 2026-11-26 against master `5969aea67`**

Repro:

    let calls = 0
    function counted() {
      calls = calls + 1
      const k = calls * 1.5
      const l = (x) => {
        print(k); return x
      }
      return l
    }
    const f: (x: i32) => i32 = counted()
    const g: (x: string) => string = counted()
    print(f(1))
    print(g("s"))
    // vl check: rc 0.  vl run: the emitted module failed to validate inside `counted`: expected i32, found f64

Want:

    1.5
    1
    3
    s

#### Mechanism

A maker delivered at a function type is instanced. Its first instance takes the template's
own slot (`monoMakeInstanceFirst`), a later one is pushed (`monoMakeInstanceLater`). The lambda
minted while walking each instance's body gets its frame from `monoLamParentOf`, which finds no
slot for the cloned node and answers -1; only the later instance re-pointed its minted lambdas at
itself (D943). So the first instance's lambda had no frame, `parentBindingOf` found no binding for
`k`, and `captureValKind` held the env field at its `i32` default. Closed by re-pointing the first
instance's minted lambdas at its slot as well (`monoReparentMinted`).

#### Ablation

| `counted` not delivered at a function type (no instance) | runs | **yes** |
| `k` a string | still invalid | no |
