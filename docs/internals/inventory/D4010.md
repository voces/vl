### D4010 — a generic written into a list element is instanced at a call the checker should have refused, so an ill-typed program runs

**check-clean silently wrong · clause 1 · the checker owes the refusal · the price of #3517 (D3979), recorded in review (`rv3517/i03`) · filed 2026-10-11 against master `20fa382fe` with #3517 applied · narrowed 2026-10-11: #3508 (D3968) made the five `let` cells of the ablation loud check rejects; the list-element cell remains**

Repro:

    function inner<U>(u: U) { print("I"); print(u) }
    function plus<V>(v: V) { print(v + 1) }
    function main() {
      const fs = [inner]
      fs[0] = plus
      fs[0](true)
    }
    main()
    // PRINTS true

#### Mechanism

`fs[0] = plus; fs[0](true)` is ill-typed (`plus` adds `1` to its argument), and `vl check`
accepts it because the call through the list element is never re-checked against the values
written into it. #3508 re-checks a call through a written `let`; a list element is not covered. `plus` prints `true + 1` as `true`. Before #3517 the call reused another instance and trapped with an indirect-call type
mismatch; #3517 instances every written generic at the call's argument types, so the ill-typed
instance is now built. At `boolean` (and at a type-variable name collision) it runs and prints
garbage; at `string` it fails to validate. The fix is the checker's: re-check each written
generic at each call through the element, as #3508 does for a binding.
