### D4010 — a generic written into a binding is instanced at a call the checker should have refused, so an ill-typed program builds

**check-clean invalid wasm · clause 1 · the checker owes the refusal · the price of #3517 (D3979), recorded in review (`rv3517/i01`, `i02`, `i03`, `d01_tvname_collide_silent`, `c05_min`, `c05_str`) · filed 2026-10-11 against master `20fa382fe` with #3517 applied**

Repro:

    function inner<U>(u: U) { print("I"); print(u) }
    function plus<V>(v: V) { print("P"); print(v + 1) }
    function main() {
      let k = inner
      k = plus
      k("s")
    }
    main()
    // vl check: rc 0.  vl run: invalid module inside `plus` (expected (ref $string), found i32)

#### Mechanism

`k = plus; k("s")` is ill-typed (`plus` adds `1` to its argument), and `vl check` accepts it
because the call through the generic-seeded `let` is never re-checked against the values written
into it. Before #3517 the call reused another instance and trapped with an indirect-call type
mismatch; #3517 instances every written generic at the call's argument types, so the ill-typed
instance is now built. At `boolean` (and at a type-variable name collision) it runs and prints
garbage; at `string` it fails to validate. The fix is the checker's: re-check each written
generic at each call through the binding (#3508's checker half), after which every cell below is a
loud check reject.
