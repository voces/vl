### D14978 — a record literal inside a list literal, re-typed to its destination for a null field, leaves that field's box to the emitter

**runs today and must keep running · 12 hand-written spellings · filed 2026-11-03 against master `f8d3af1f1`**

Repro:

    type Shape = Circle | Sq
    type Sq = { s: i32 }
    type Circle = { r: i32 | null }
    function mk() {
      const lv1 = [{ r: null }]
      return lv1
    }
    const xs: Circle[] = mk()
    print(xs[0].r ?? 5)

Want:

    5

#### Mechanism

`{ r: null }` has a null hole, so `recordNullHoleObjAdopt` re-types the list literal and its
elements to the destination (`Circle[]`, `Circle`). That makes the literal's own type equal its
destination, so `litAtDstStorage` declines and `recordRepTyAdopt` never walks the elements. No
check-side producer then records `i32 | null` as the box destination of the field's `null`.
The program runs only because the emitter derives the box from the variant struct's shape
(`emitVariantFieldValueUnder`, D763's shape intern), and the box-destination shadow reads it
as `no record`.
