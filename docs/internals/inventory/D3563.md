### D3563 — `abs` of an integer widened to f64, where `min` and `max` keep the integer width

**closed 2026-10-03 · was loud check reject: `cannot assign f64 to i32`, and `abs expects f64, got i64` for an i64 · sunpa SP-017 · filed 2026-10-03 against master `315552b88`**

Repro:

    const v: i32 = 200
    let s = 0
    s += abs(v - 7)
    print(s)

Want:

    193

#### Mechanism

`abs` is a float intrinsic in the checker (`floatIntrArity`), typed at `floatIntrWidth`, which
lands every integer operand on f64. `min` and `max` were carved out by `intMinMaxOperands` and
lowered by `emitIntMinMax`; `abs` was not. It now joins that rule: integer operands type the
call at `intIntrWidth` (i32, or i64 when the operand is), and `emitIntAbs` lowers it as
`select(0 - x, x, x < 0)`, so `abs(i32.MIN)` wraps to itself under the overflow-wraps ruling.
A literal argument adapts (`const x: f64 = abs(-3)` is `3`). The type of an existing
`abs(intExpr)` changes from f64 to i32; across the repo, `~/plumb/src`, `~/sunpa/src` and
`~/glean` the only integer-argument calls are sunpa's PNG Paeth predictor
(`src/worldgen/png.vl:28-30`), which compares the three results to each other and means the
same thing at either width. No call in those trees reaches the deferred hole form.

#### Ablation

| operand | master | after |
| --- | --- | --- |
| `i32` | f64 | i32, `abs(-5) / 2` is `2` |
| `i64` | refused | i64 |
| `i32.MIN` | `2147483648` as f64 | `-2147483648` |
| `f64` / `f32` / float literal | f64 / f32 / f64 | unchanged |
| integer literal | f64 | i32, adapts to an f64 destination |
| an un-annotated or generic parameter's hole | f64 at every pin | the pin's width, as `min`/`max` defer (`minMaxHoleOperand`) |
