### D14746 — a literal-union field is stored as a string when its record shares a union with a string-field arm

**runs, prints `circle` — CLOSED 2026-11-01: across two tags a literal-set field beside its `string` base keeps its own layout, and the shared read converts between the atom and the string · was a step 5 `ctxTy` field decline · the same-tag pair is [D14752](D14752.md) · filed 2026-11-01 against master `5b24d58b`**

Repro:

    type K1 = "circle" | "round"
    type A = { kind: K1, r: i32 }
    type B = { kind: string, r: i32 | string }
    function f(): A | B {
      const a: A = { kind: "circle", r: 1 }
      a
    }
    print(f().kind)

Want:

    circle

#### Mechanism

`A`'s `kind` is typed `K1`, whose `repOfTy` is the i32 atom, and on its own `A` stores it so.
Once `A` is an arm of `A | B` beside `B`'s `kind: string`, the shared field layout (D4056)
stores `A.kind` as a string, so the layout of `A` depends on which union names it. A reader
asking `repOfTy` of the field's contextual type gets the atom. `ctxFieldStorageAgrees`
declines every record field until this agrees. One row per canonical type is step 7's.

The demotion was D1050's `reLayLitFieldsByName` (emit_collect.vl), which re-laid an atom set at
the string wherever another arm under a different tag held the field as a plain `string`. Across
tags the two layouts are apart anyway, and the shared read converts between the atom and the
string (`sharedFieldLitSetPlan`, and since D14750 the boxing plan too), so that demotion is
deleted and `A` keeps its one layout. The `B.r: i32 | string` box is an ingredient: it is what
puts `A` and `B` under two tags. With `B.r: i32` the pair shares one tag, and that case is D14752.

#### Ablation

| ingredient removed | outcome | needed? |
| --- | --- | --- |
| `B` and the union (`const a: A` alone) | `kind` stored as the atom | **yes** |
