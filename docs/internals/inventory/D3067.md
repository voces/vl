### D3067 — a hole function's `.filter` or `.map` callback that captures is invalid wasm at a non-`i32` list pin

**check-clean invalid wasm · clause 1 · open · found grading D3060's receivers · the same on master `6c2dafc0b` · filed 2026-09-28 against master `6c2dafc0b`**

Repro:

    function g(h, z) {
      return h.filter((e) => e != z)
    }
    const b: string[] = ["a", "b"]
    print(g(b, "b")[0])
    // vl check: rc 0.  vl run: invalid module inside `g`, expected i32, found (ref $type)

Want:

    a

#### Mechanism

Not localised past the ablation. A capture alone is enough (`const q = z`, never reading the
element), and so is reading the element with no capture ([D3083](D3083.md)); a callback that
does neither runs, and so does the `<T>` spelling. The
monomorphizer pins a `.map`/`.filter` callback lambda per instance when its receiver parameter is
bound to a non-`i32` element (`monoPinMapLambdas`); the capturing lambda appears to keep the
template's `i32` element, which the `string` backing's element read does not fit.

#### Ablation

| ingredient changed | outcome | needed? |
| --- | --- | --- |
| `(e) => true`, no capture, no element read | prints `a` | **yes** |
| `(e) => e != "a"`, no capture | invalid wasm ([D3083](D3083.md)) | no |
| a capture of `h` instead of `z` (`h[0] = z`, `h.length`) | invalid wasm | no |
| `.map` in place of `.filter` | invalid wasm | no |
| an `i32[]` pin | runs | **yes** |
| an `f64[]` pin | invalid wasm | no |
| a record-list pin | loud emit reject, list type not collected | no (a sibling) |
| `function g<T>(h: T[], z: T)` | prints `a` | **yes** (the hole) |
