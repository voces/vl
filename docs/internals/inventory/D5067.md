#### Mechanism

`canonUnionKeyOfName` and `canonUnionKeyOfAnnName` (check_nj_join.vl) memoise the key by its
TEXT (`cukIds`), and build that text first, every call: `canonUnionKeyText` splits the
spelling into atoms, asks `aliasDeclRowSet` and `unionAliasMembers` of each, splits each
expansion again and concatenates. `canonUnionKeyOfAnnName` renders it twice, once to count the
atoms and once inside `canonUnionKeyOfName`. The L6 steps that moved binding annotations and
`monoAnnPinName` onto the key put this on the per-node classifier paths (`letAnnIsUnion`,
`globalStructIndexSid`, `nameKeyRow`). #3885 (`33e7e5b45`) cost +1.72% for 28 source lines
and #3904 (`26b6fad0c`) +1.62% for 57; `canonUnionKeyText` went from 0.08% to 1.22% inclusive
across #3885. On `7ce930c32`, `canonUnionKeyOfAnnName` is 2.68% inclusive.

#### Fix

`canonUnionKeyOfName` memoises the rendered key text and its width by SPELLING (`cukTextMemo`,
`cukAtomsOfName`) and renders only on a miss; `canonUnionKeyOfAnnName` reads the width from
the memo instead of rendering a second time, and mints no id for a spelling it declines. The
memo is dropped when any input the render reads moves (`cukMemoKey`): `tyMutEpoch`,
`cUserTypesVer`, `gRootStmts.length`, and `tyVarRenames`, a new count of `tyVarRenameRow`'s
in-place arena writes, which `tyMutEpoch` does not see. `memoCompileReset` clears the key at
each compile.

The same change makes `modRecomputePending` (driver.vl) incremental. It rebuilt the pending
list from every import row at each module commit, quadratic in modules, and hashed every
module key again each time, which is why the self-compile read more fuel from a longer source
path.
