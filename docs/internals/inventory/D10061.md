### D10061 — a `??` over a nullable `i32` record field or list element with a runtime `f64` default is typed `f64`, where the same `??` over a parameter is `i32 | f64`

**loud check reject · clause 2 · CAPABILITY: `x ?? d` over `x: i32 | null` prints `true` · found closing [D9915](D9915.md) · present on master `e0eecffc4` · filed 2026-10-22 against master `e0eecffc4`**

Repro:

    function field(o: { v: i32 | null }, d: f64) {
      const r = o.v ?? d
      print(r is i32)
    }
    function elem(a: (i32 | null)[], d: f64) {
      const r = a[0] ?? d
      print(r is i32)
    }
    field({ v: 5 }, 1.5)
    elem([5], 1.5)
    // vl check: `is` check type 'i32' can never match a value of type f64

Want:

    true
    true

#### Mechanism

Not traced. Under the numeric-join ruling's `??` extension a runtime `i32` and a runtime `f64`
join as `i32 | f64`, so rewriting `if q != null { q } else { b }` as `q ?? b` keeps `is i32`.
The parameter spelling is typed that way; the field and element spellings are typed `f64`, the
`i32` converted away. [D10060](D10060.md)'s close types the field read at the checker's `f64`,
so a fix here moves that row's fixture as well. [D3710](D3710.md) is the lambda spelling of the
same split.
