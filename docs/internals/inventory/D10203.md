Repro:

    function k<T>(x: f64, y: T): f64 { x }
    function h(x: f64, y: i32): f64 { x + 1.0 }
    const ys = [k]
    ys.push(h)
    function run(a) { print(a[1](3, 2)) }
    run(ys)
    // vl check rc 0.  vl build: a generic function taken as a value reaches no call that fixes its type

The owed outcome is a run printing `4`.

#### Mechanism

The push pins the list's element to `h`'s type at check, and emit does not see the call
through the un-annotated parameter as the call that fixes `k`'s `T`. The ingredient is the
integer literal `3` at the `f64` parameter: written `3.0` the same call runs. So the emit
side's call pin through an un-annotated parameter (`monoDeclPathPins`, `monoUncalledSlotFnTy`,
emit_mono.vl) reads the argument's own type rather than the element type it is delivered at.
Left open by the lane that closed [D10204](D10204.md): an emit mechanism the checker changes
there do not reach.
