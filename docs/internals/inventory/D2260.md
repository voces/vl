### D2260 — an inline `??` or `if` joining a union to a nullable record no union declares has no box for the record's arm

**closed 2026-09-26 — the filed repro RUNS and prints `true` · was loud emit reject, `vl check` rc 0, then
`emitProgram: union atom has no value box`, clause 2 · the residue of the #3088 review's
nullable-ref cells · filed 2026-09-23 against master `7d369c028`**

Repro:

    type Err = { code: i32 }
    type Ok = { v: i32 }
    function f(d: Ok | null) {
      const m: {[string]: i32[] | Err} = Map()
      print((m["z"] ?? d) == null)
    }
    f(null)
    // vl check: rc 0.  vl run: emit error, "emitProgram: union atom has no value box"

#### Mechanism

The join `i32[] | Err | Ok | null` is named by its own recorded type and no declaration, so
`Ok` has no variant tag in it: the record arm reaches the value-atom ladder, which has no box
for a record. Binding the join to a local first registers its union, and then the arm boxes and
its null becomes the union's null. The same #3088 change fixed the rest of the family, where a
nullable record or string delivered into a union that admits `null` was boxed under its arm's
tag over a null payload (a wrong `is`, or a `null reference` trap on a string), and a null
`boolean | null` (its null is the i32 value 2) was boxed as the boolean; that half is
pinned by `tests/cases/unions/nullable-ref-into-union-keeps-null.vl`. Confirmed by the
close: registering the inline join from the checker's recorded type ([D2373](D2373.md)'s
mechanism) is the whole fix, at both the `??` and the `if` spelling.

#### Ablation

| ingredient removed | outcome | needed? |
| --- | --- | --- |
| binding the join to a local first (`const y = m["z"] ?? d`) | runs, prints `true` | **yes** |
| the map (`(if c { a } else { d }) == null`, `a: i32[] \| Err`) | still refuses | no |
| a declaration naming `Ok` as a union arm elsewhere (`y is Ok` on another binding) | runs | **yes** |
