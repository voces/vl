### D2995 — a record literal bound inside a nested block is not re-seated at the wider declared record it is handed to

**closed · runs, prints `1.5` · was check-clean invalid wasm · `q` adopts `D` at any block depth · fixture `tests/cases/soundness/record-literal-in-nested-block-adopts-wider-record.vl` · closed 2026-09-30**

Repro:

    type D = { v: f64 }
    const x: i32 = 3
    function g(d: D) { print(d.v / 2.0) }
    if true {
      const q = { v: x }
      g(q)
    }
    // vl check: rc 0.  vl run: invalid module — type mismatch

Want:

    1.5

#### Mechanism

Not localised past the ablation. The D2933 use walk (`objLitBindDestRow`) re-seats `q` at `D`
when `q` is bound at the top of a function body or the module; bound one block deeper, at the
module or inside a function, the argument is built at `q`'s own `{v: i32}` record. The walk's
scope root (`dsScopeRootOf`) or the local's slot type, decided before the arena is final, is
the likely seam.

#### Ablation

| ingredient removed | outcome | needed? |
| --- | --- | --- |
| the block (`q` bound in the function body itself) | runs, prints 1.5 | **yes** |
| module scope (the block inside a function) | same invalid wasm | no |
| the parameter (a `{[string]: D}` map store instead) | same invalid wasm | no |

#### Record covariance (2026-09-30)

The destination stores a numeric field at another width or kind, so under the record-covariance ruling the literal-holding binding or function is not adopted and the program keeps its master behaviour until the owner rules on [D3339](D3339.md) (DECISIONS.md "Record covariance: only a fresh value widens").

#### Close under the D3339 ruling (2026-09-30)

Closed by the owner's ruling D3339 (A): a literal-holding binding adopts a record that stores a number at another width or kind, fully (DECISIONS.md "Record covariance: only a fresh value widens"). Adoption rewrites `q`'s declaration wherever it is bound, so the block depth the emitter's re-seat walk missed no longer matters: `q` is a `D`.
