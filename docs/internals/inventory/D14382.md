### D14382 — a function returning an alias of its literal binding is built at its own row while its one call is delivered at a wider record

**closed 2026-10-26 · runs, prints `1` `a` · fixed by the fresh-literal producer (`recValueOrigins`, check_rec_fresh.vl): `recFnBuiltAtDst` follows the result through un-annotated bindings and aliases to the literal, and builds that binding at the destination · was check-clean invalid wasm · clause 1 · pin: `tests/cases/soundness/record-fresh-call-returns-alias-of-literal-binding.vl` · found grading the slice 2 follower · introduced by `dbcb67496` (#4902), whose leaf test read only a binding the result names directly · filed 2026-10-26 against master `dbcb67496`**

Repro:

    function rec() { const r = { x: 1, y: "a" }; const s = r; s }
    function take(p: { x: i64, y: string }): void { print(p.x) print(p.y) }
    take(rec())
    // vl check: rc 0.  vl run: invalid module, expected the `{x: i64, y: string}` row

Want:

    1
    a

#### Mechanism

#4902 built a function's literal binding at the record its one call delivers it to
(`recFnBuiltAtDst`), but its leaf test accepted a result leaf only when it named the literal's
binding. `s` names an alias of `r`, so the leaf was refused, the literal stayed at its own
`{x: i32, y: string}` row, and the call was still delivered at `{x: i64, y: string}`. The fix
deletes that leaf test: one producer (`recValueOrigins`) walks result tails through bindings
that hold only their initializer, so `s` reaches `r`'s literal and `r` is built at the
destination.
