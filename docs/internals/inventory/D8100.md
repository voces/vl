### D8100 — a handed un-annotated function whose result widens its `i32` argument to `f64` is keyed `(i32)=>i32` at the hole's call

**closed · filed 2026-10-20 against master `4846b38dc` · clause 2 · closed by the hole instance taking the result its body gives at the bound parameters · fixtures `closures/handed-hole-fn-widening-*.vl`, matrix `handed-hole-fn-widening-result`**

Repro:

    function half(a) { return a / 2.0 }
    function p(h) {
      print(h(3))
    }
    p(half)
    // vl check: rc 0.  vl run: emitProgram: a function-value call has no interned signature — the callee is an un-annotated value this instance binds to `(i32)=>i32`

Want:

    1.5

#### Mechanism

The checker types a hole's arithmetic as the hole (`T / f64` is `T`), so `half` is
`(T) => T`. Binding `h` substituted that signature at the call's `i32` and got
`(i32) => i32`, though the body at `i32` gives `f64`. Three places now re-derive the result
from the body at the bound parameters (`genFnHoleBodyRet`, `check_relate_core.vl`): the
checker's hole binding (`genFnHoleInstance`), the emitter's flow pin for a const-bound lambda
(`monoHoleGenFnFlowTy`), and a binary operator inside the body (`holeArithNodeTy`, which uses
the scalar pair rule). A lambda's `#L` hole name is also found again after emit renames the
lambda `__lambda_<n>` (`holeParamDecl`).
