### D8100 — a handed un-annotated function whose result widens its `i32` argument to `f64` is keyed `(i32)=>i32` at the hole's call

**loud emit reject · filed 2026-10-20 against master `4846b38dc` · clause 2, present on master**

Repro:

    function half(a) { return a / 2.0 }
    function p(h) {
      print(h(3))
    }
    p(half)
    // vl check: rc 0.  vl run: emitProgram: a function-value call has no interned signature — the callee is an un-annotated value this instance binds to `(i32)=>i32`

Want:

    1.5

#### Mechanism

Not traced. The direct call `half(3)` prints `1.5`, and the hole call `h(3.0)` runs, so the
checker types the result right at the argument's own type; the instance the emitter keys for
`h` takes the result to be the argument's `i32`, and no signature of that shape is interned.

#### Ablation

| ingredient removed | outcome | needed? |
| --- | --- | --- |
| `a: i32` on `half` | runs, `1.5` | **yes** |
| `: f64` result on `half` | runs, `1.5` | **yes** |
| the `i32` argument (`h(3.0)`) | runs, `1.5` | **yes** |
| `/ 2.0` for `+ 0.5` | still refuses | no |
| the `print` for `const r: f64 = h(3)` | still refuses | no |
| `function half` for `const half = (a) => a / 2.0` | still refuses | no |

#### Grading list

`half` handed beside a second hole function in the same call (`p(add, half)` with `g(1, 2)`
and `h(3)`), which refuses with the same sentence.
