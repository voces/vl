### D16207 — a generic identity's result over an empty `Map()` keeps an open map type, so a read of it is refused

**closed 2026-11-16 · runs, prints `0` · was a loud emit reject (`emitProgram: '.length' on a receiver the emitter cannot classify as a list, string, map or set`), clause 2 · fixed by reading a top-level generic call whose recorded type is an open container at its instance's closed type (`nodeTyAt`, `elabHoleContainerClosed`) · fixture `tests/cases/generics/empty-map-through-generic-identity-read.vl` · `tests/selfhost_native_diag_pos_test.ts` moves its top-level anchor to D16725's `take([[]]).length` · filed 2026-11-14 against master `c522f8dd`**

Repro:

    function take<B>(b: B): B { return b }
    print(take(Map()).length)
    // vl check: rc 0.  vl run: the refusal above, at `length`

Want:

    0

#### Mechanism

D1887 pins the argument at the closed map the elaboration builds an empty `Map()` at, and the
call's instance returns it, but the call's recorded type is the template's open map. `nodeTyAt`
took the instance's type for a top-level call only where the recorded one held a type variable,
and an open map's hole key is no type variable, so the receiver had no map rep. It now also
takes it where `elabHoleContainerClosed` closes the recorded type.
