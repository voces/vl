### D1966 — a NESTED named function whose inferred return is a union or nullable (a tail `xs.pop()`, `return 1` / `return null`) gets an `i32` wasm result: the checker exports inferred returns for top-level functions and anonymous lambdas only

**closed 2026-09-22 — the witness prints `5` · was check-clean invalid wasm, clause 1 · filed against master `a8a104432`, found grading [D1965](D1965.md) · 386-cell grid: 62 cells to runs, 0 runs lost · review: the name-keyed CALLEE resolution this unmasked is fixed in the same close · fixture `tests/cases/functions/nested-fn-inferred-union-return.vl`**

Repro:

    function main() {
      function m() {
        const out: i32[] = [1, 5]
        out.pop()
      }
      print(m())
    }
    main()
    // was: vl check rc 0, vl run: invalid module — failed to validate inside `main`:
    //   type mismatch: expected (ref null $type), found i32
    // now: prints 5

#### Mechanism

`checkProgram`'s A20 export records each un-annotated function's inferred return for the emitter,
but it walks `topUnannotFns` only; `finishInferredReturn` records an anonymous lambda under its
node key (`#<nodeIx>`) and, for a NAMED function, only patches the scope binding. A nested named
function therefore has no row, `buildFnMap` (`compiler/emit_collect.vl`) finds neither the name
nor the node key, and `computeRetInference`'s expression classifier does not see the value union
`i32 | null` that `.pop()` yields: the function is typed `(result i32)` while its body builds the
union box. The same function at top level, or as `const m = () => ...`, runs.

The close records a nested named function like the other two kinds: `finishInferredReturn` banks
its final `TyFunc` (`noteNestedUnannotFn`), and the A20 export runs the SAME ladder as for a
top-level function (`a20RecordFn`) under the node key `#<nodeIx>`, because the name is neither
unique nor still bound when the export runs. Every emitter read of a declaration's row goes
through `inferRetFnKey(declIx, name)`. Two checker faults of the same root came with it: the
inferred return PATCHED an outer namesake's `TyFunc` (the lookup ran past the nested function's
own, not-yet-declared binding, so `const s: string = m()` after a nested `m` was refused), and an
un-annotated nested function could not call itself (`undeclared identifier`), since only the
annotated spelling bound its signature before the body. It now binds a pending one, as the
top-level hoist does.

Review of the close found the same fault one layer out, in CALLEE resolution. With the row fixed,
two outer functions each declaring a nested `k` whose unions differ in rep printed a wrong value
(`k(false)` in the second frame read the first frame's `f64 | null` rep and printed `null` for
`"one"`), trapped on a cast, or built invalid wasm — base refused the same programs loudly or
built them invalid, and the ANNOTATED twins failed identically there. `fnIndexOfSid` is keyed by
the interned NAME and first-wins, and every emit-time classifier asking which function a call hits
went through it. While a body is lowered it now resolves a nested function's name through that
body's scope chain (`fnIndexOfInScopeSid`), and a sibling frame's nested function never answers
for one of the body's own params or locals (a param `k` beside a sibling's nested `k` built
invalid wasm on base too). The mono pass's argument-pin read (`emit_mono.vl`, a generic call's
argument that is a call of a nested namesake, `id(k())`) resolves its callee the same way.
