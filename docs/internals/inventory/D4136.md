### D4136 — a literal argument with an extra field refuses at emit when its record parameter is also an arm of a tagged union

**loud emit reject · filed 2026-10-11 against master `3096c492f` · found by the #3557 review (`rv3557/r2/q/ret_param_is`)**

Repro:

    type A = { k: "a", v: i32 }
    type U = A | { k: "b", s: string }
    function id(a: A): i32 { return a.v }
    print(id({ k: "a", v: 7, w: 2 }))
    // vl check: rc 0.  vl run: emit error, `object literal writes a field its union variant does not declare`

Want:

    7

#### Mechanism

A literal argument with a field its literal-typed record parameter does not declare is passed
wider (D3992, D4070). When `A` is also an arm of a tagged union declared anywhere in the module,
the emitter builds the literal against `A` as a union variant, finds `w` with no slot there and
refuses, though no value of `U` is ever made. `U` need not be used: declaring it is enough.
Without `w`, without `U`, or with `U = A | null`, the program runs. A program `vl check`
accepts, so a clause-2 violation by construction; the checker or the emitter owes it.

#### Ablation

| ingredient changed | outcome | needed? |
| --- | --- | --- |
| no `w` in the literal | runs, prints 7 | **yes** |
| no `type U` | runs, prints 7 | **yes** |
| `type U = A \| null` | runs, prints 7 | **yes** (a tagged union) |
| `k: string` on `A`, `U`'s other arm tagged by another field | runs, prints 7 | **yes** (the literal-typed field) |
| the argument parenthesised | same emit refusal | no |
| `id` returns `a` as `U`, then `if r is A` | same emit refusal | no |
| the call inside a function | same emit refusal | no |

#### Grading list

The same call with no extra field (must keep printing 7), the program with no `type U` (must
keep running), the parenthesised argument, and the union-parameter argument `g(u: U)` with the
extra-field literal, which #3557 refuses at check.
