### D2762 — two single-field record literals of different field types, handed straight to one un-annotated parameter that reads the field, share one row

**check-clean invalid wasm · the review's `h2` cell and its `f64`, reversed-order and bound-local-return twins · identical on master · filed 2026-09-27 against master `f6db92e0d`, from the #3181 review**

Repro:

    function g(o) { o.v }
    print(g({ v: "s" }))
    print(g({ v: 3 }))
    // vl check: rc 0.  vl run: invalid module in the top-level code — expected (ref $type), found i32

#### Mechanism

Not localised past this: `g` is instantiated twice (`g` and `g$1`), and both instances take the
`{v: string}` row as their parameter and result, while the second call builds `{ v: 3 }` at
that row too — `struct.new $0 (i32.const 3)` into a string field. The `{v: i32}` row is never
interned. The anonymous-row machinery (`anonLeaf…`, the `??`-family folds keyed on a field-name
set) is the suspect: every ingredient that separates a working neighbour from this one is a
reason for the second literal to be resolved by its field NAMES alone.

#### Ablation

| ingredient removed | outcome | needed? |
| --- | --- | --- |
| the field read (`function g(o) { o }`, `.v` at the call) | runs | **yes** |
| a second field (`{ v: "s", w: 1 }` beside `{ v: 3, w: 1 }`) | runs | **yes** — one field only |
| the literal at the argument (`const b = { v: 3 }; g(b)`) | runs | **yes** |
| the call order (`{ v: 3 }` first) | same invalid module | no |
| the `i32` field (`{ v: 2.5 }`) | same invalid module | no |
| the tail read (`const r = o.v; r`) | same invalid module | no |
| the hole (`function g<T>(o: T)`) | runs | **yes** |
| `function g<T>(o: { v: T })` | loud emit reject, `unsupported argument type for \`o\`` | — a clause-2 twin |

#### Grading list

The review's `h1`–`h5`, which must keep running, and the `function g<T>(o: { v: T })` twin.
The same mechanism prints a lone literal's field in the hole's format: `function p(o) {
print(o.f) }` with `p({ f: true })` prints `1` on master `38e64e7ca`. Recording the literal's
own shape as the row type (`anonRowTyIx`) fixes both, but alone it let a hole constructor's
shared literal join that row (`mk(7).f` printing `true`), which is D2850's gap, so it waits
for D2850.
