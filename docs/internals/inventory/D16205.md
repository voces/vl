### D16205 — a number literal beside a narrower typed value binds a type variable at the value's width, so the order of the arguments decides the call

**loud check reject · `argument 2: expected i32, got f64` · clause 2 · against DECISIONS "A type variable's uses join over numeric widening" (D2459): the order of the arguments does not decide the instance · found grading D15041's neighbours · filed 2026-11-14 against master `c522f8dd`**

Repro:

    function pick<T>(a: T, b: T): T { return b }
    const one: i32 = 1
    print(pick(one, 0.5))
    // vl check: rc 1: argument 2: expected i32, got f64

Want:

    0.5

#### Mechanism

Not yet traced. A number literal binds its variable after the values beside it (D3541), so `T`
is bound at `one`'s `i32` before `0.5` is seen. The join over widening that D2459 asks for is not
taken for a literal that does not fit the bound width.

| `function mix<T>(a: T, b: T): T[]` with `mix(one, h)[0]` | runs, `1` | no (any `T` use) |
