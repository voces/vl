### D16205 — a number literal beside a narrower typed value binds a type variable at the value's width, so the order of the arguments decides the call

**closed 2026-11-14 — the witness runs and prints `0.5` · was: loud check reject · `argument 2: expected i32, got f64` · clause 2 · against DECISIONS "A type variable's uses join over numeric widening" (D2459): the order of the arguments does not decide the instance · found grading D15041's neighbours · filed 2026-11-14 against master `c522f8dd`**

Repro:

    function pick<T>(a: T, b: T): T { return b }
    const one: i32 = 1
    print(pick(one, 0.5))
    // vl check: rc 1: argument 2: expected i32, got f64

Want:

    0.5

#### Mechanism

A number literal binds its variable after the values beside it (D3541), so `T` was bound at
`one`'s `i32` before `0.5` was seen, and the literal was barred from asking the widening join a
typed value asks. It now asks that join when the binding beside it is an integer, which cannot
hold it. Beside a float binding, which holds any literal, it still adapts, so `mix(x, 0.1)` with
`x: f32` stays `f32[]`. `pick(one, 5000000000)` widens to `i64` the same way.

#### Ablation

| ingredient changed | outcome | needed? |
| --- | --- | --- |
| `pick(0.5, one)` | runs, `1` | **yes** (the order) |
| `const h: f64 = 0.5; pick(one, h)` | runs, `0.5` | **yes** (a literal) |
| `function mix<T>(a: T, b: T): T[]` with `mix(one, h)[0]` | runs, `1` | no (any `T` use) |
