### D1751 — two sibling module-level blocks reusing one binding name give their captures one env row, so the second block's closure reads the first's field type

**check-clean invalid wasm · clause 1 · filed 2026-09-06 against master `006cacb65` · found while building [D1758](D1758.md)'s fixture · 0 corpus cells**

Repro:

    type MaybeN = i32 | null

#### Mechanism

Not a rep gap: each block's capture is typed correctly in isolation — both blocks run when
their bindings are given distinct names, and both run as separate FUNCTIONS. What fails is the
env row's identity. Two module-level blocks are two frames, but the capture's parent binding is
resolved by NAME, so the second block's `held` finds the first's cell and the second closure's
env field is declared at the first's rep.

Rename either block's `held` and `get` and the program prints `4` then `6`. That is the whole
ablation: the names, not the reps.

**Reached at both seeds and both outcomes, which is why the witness is the MIXED pair.** With
two STRUCT reps the same shape is a loud `emitProgram: unknown struct field in field access`
at both seeds; with a nullable scalar beside a map it is check-clean invalid wasm at both. The
silent spelling is filed because it is the clause-1 one.

#### Ablation

Every row is `vl check` rc 0.

| ingredient removed | outcome |
| --- | --- |
| the second block's names made distinct (`held2`, `get2`) | runs, 4 then 6 |
| the two blocks made two FUNCTIONS instead | runs, 4 then 6 |
| the second block deleted | runs, 4 |
| the two reps made the same (two nullable scalars) | runs |
| the two reps made two STRUCTS | loud emit reject, another message |
| the capture removed from both blocks | runs, 4 then 6 |

Needed: two module-level blocks AND one shared binding name AND a capture in each AND two
different reps. Not needed: which two reps, except that two structs reach a loud refusal and
every other pair tried reaches the silent one.
