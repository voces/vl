#### Mechanism

The module frame is not a lifted frame, so `parentBindingOf`'s `fnParent` walk runs off the
chain and its module arm resolves the capture through `moduleLocalLetOf` — a map the
module-frame walk fills FIRST-WINS, "with no notion of which block a reader sits in", as its
own header already said. Instrumented at that arm, both closures mint one key:

    [name=held fe=3 declNode=47 picked=44 cands=44,63]   <- block 1's closure, correct
    [name=held fe=4 declNode=66 picked=44 cands=44,63]   <- block 2's closure, owes 63

`moduleLocalLetAll` sees both candidates; the resolver takes the first, so block 2's `held`
is typed at block 1's cell.

**There are TWO readers of that fact and fixing one leaves a trap.** With
`parentBindingOf` positioned and the call site not, `wasm-dis` shows the env structs correct
and distinct — `(type $20 (struct (field (ref $2))))` for the union box, `(type $21 (struct
(field (ref $22))))` for the map — while the call is `call_indirect (type $16)`, block 1's
union-result functype. The second reader is `identClosureFeSid`'s module rung, the same
first-wins resolver one layer over, which hands the value call block 1's `$fnsig`. On the
struct pair that variant is a `wasm trap: indirect call type mismatch`, so the halves land
together or a loud refusal becomes a trap.

**The reader's position is an arena node, and the ARENA IS POST-ORDER** — a statement's index
is the maximum in its own subtree, measured by dumping the module-frame walk. So "the last
binding before the reader" is not the rule: a nested block's binding also precedes a reader
that has already left the block. The scope test is two comparisons against the owning block,
`binding < reader <= ownerBlock`, and the owner is what the walk now records beside each
binding. Taking the nearest preceding binding alone moved a nested-shadowing spelling
loud → check-clean invalid wasm, which is what caught it.

`moduleLocalLetOfUnique` — D1596's decline, which is this question asked with no reader —
becomes the unpositioned rung of the new resolver rather than a second copy of the walk.
