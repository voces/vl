### D8684 — a fresh-builder call handed to an un-annotated parameter that reads its field is built at a declared record that boxes the field

**check-clean invalid wasm · clause 1 · open · present on master `a0af58b15` · the `argument` and `early_return_guard` un-annotated cells of `unlanded-call-beside-call-into-wider-record` · found closing [D8620](D8620.md) · filed 2026-10-20 against master `a0af58b15`**

Repro:

    type J = { f: i32 | null }
    function mk() { { f: 4 } }
    function rd(r) { return r.f + 1 }
    print(rd(mk()))
    // vl check: rc 0.  vl run: the emitted module failed to validate inside `rd`: expected i32, found (ref $type)

Want:

    5

#### Mechanism

`mk`'s literal is built at `J`, the declared record with field `f`, and `rd`'s hole is pinned at
the call's row, so `r.f + 1` reads `J`'s boxed field where the body adds an `i32`. D8620's close
moves a literal off a boxing row only when the literal itself, or an un-annotated binding of it,
is the argument; here the argument is a call. Unlike D8620, declaring the exact record
`type II = { f: i32 }` does not rescue it, so the builder's literal takes its row on a different
path from a literal argument's. Not yet traced past that.

#### Ablation

| change | outcome | needed? |
| --- | --- | --- |
| `const k = mk()` and `print(k.f + 1)` (no hole) | prints `5` | **yes**, the hole |
| `rd(r) { return r }`, read `.f ?? 0` outside | prints `4` | **yes**, a field read in the hole |
| declare `type II = { f: i32 }` too | still invalid wasm | no |
| also store `const j: J = mk()` | still invalid wasm | no |
