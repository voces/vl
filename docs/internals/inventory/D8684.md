### D8684 — a fresh-builder call handed to an un-annotated parameter that reads its field is built at a declared record that boxes the field

**closed 2026-10-21 · runs, prints `5` · was check-clean invalid wasm · clause 1 · a call to a non-generic builder with no return annotation, whose body ends in a record literal, counts as handing that literal to the parameter, so D8620's row rule covers it (`litCallTail`, `emit_classify.vl`) · pin: `tests/cases/soundness/fresh-builder-into-hole-beside-boxed-row.vl` · matrix `fresh-builder-into-hole-beside-boxed-row` 4 → 64 of 64 · the `argument` and `early_return_guard` un-annotated cells of `unlanded-call-beside-call-into-wider-record` also store the builder's result at `J`, and are [D8681](D8681.md)'s · present on master `a0af58b15` and `3f8abb772` · found closing [D8620](D8620.md) · filed 2026-10-20 against master `a0af58b15`**

Repro:

    type J = { f: i32 | null }
    function mk() { { f: 4 } }
    function rd(r) { return r.f + 1 }
    print(rd(mk()))
    // vl check: rc 0.  vl run: the emitted module failed to validate inside `rd`: expected i32, found (ref $type)

Want:

    5

#### Mechanism

`mk`'s literal is built at `J`, the declared record with field `f`, and `rd`'s hole is pinned at
the call's row, so `r.f + 1` reads `J`'s boxed field where the body adds an `i32`. D8620's close
moves a literal off a boxing row only when the literal itself, or an un-annotated binding of it,
is the argument; here the argument is a call, so the literal's delivery to `rd` is never
recorded and the row choice keeps `J`.
