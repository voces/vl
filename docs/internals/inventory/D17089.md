### D17089 — a template string reading `.length` of one union-of-lists local twice lowers its stack values out of order in the IR

**fixed 2026-11-24 · closed, matches · was: IR shadow only (legacy bytes ship): `mismatch unlowered: stack value read out of order` · filed 2026-11-24 against master `73c87bff` · fixed by `stageLead` (ir_lower.vl): a root staged below a valued `if` reads above the roots already staged beneath it (`rootsFloor`) · fixture `strings/two-union-list-lengths-at-every-position.vl`**

Repro:

    const e: f64[] = []

      const kx: f64[] | string[] = e
      print("\{kx.length} \{kx.length}")
    }
    main()

Want:

    0 0

#### Mechanism

`kx.length` over a union of list arms is a valued `if` (`armSiteRead`). Before the second one
opens, `stageLead` stages the operands pending below it: the leading literal `v14`, already on
the stack, then the first part's `call f29(v3)`, whose argument `v3` is the first `if`'s value,
sitting above `v14`. Staging ran at the enclosing floor, so `liveTake(v3)` found `v14` lowest and
refused, though `v14` is a root that stays below for the concat and legacy writes this order.
One read, or two summed with `+`, stage no root beneath a read.
