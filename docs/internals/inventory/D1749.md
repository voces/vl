### D1749 — an INFERRED nested list of closures has no element rep, so the inner list read back from the outer one is not a callable

**loud emit reject · 1 cell, `array_element` un-annotated of `container-read-callee.matrix.vl` · filed 2026-09-06 against master `40334c8cf` · D1664's residue · 0 corpus cells**

Repro:

    const xs = [[(n: i32) => n + 1]]
    const v = xs[0]
    const __cp = (m: i32) => v[0](m)
    print(__cp(54))
    // vl check: rc 0.  vl run: emitProgram: callee is not a function name

#### Mechanism

Named by D1664's close, which it survived: the matrix cell that row cited as one of its two
carries no parameter at all, so the pin the close reads does not exist here. The container is
a nested list literal whose LEAF is a closure, and the outer literal's element kind is decided
by `arrLitElemKind`'s nested-array rung, which keys the inner list by its scalar leaf (string
6, f64 7, i64 8, else the i32 wrapper 4) and has no closure leaf. The inner list therefore
interns as the i32-list wrapper, `v` reads back an i32 list, and its element is not a callable.

The bare read `v[0](54)` in place of the lambda reaches a DIFFERENT sentence,
`emitProgram: nested arrays are not supported`, which is the same missing element rep one
message earlier — the read shape picks the sentence, exactly as it did in D1664.
