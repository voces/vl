### D1749 — a nested list of closures is keyed as a CLOSURE list, because the "merely contains a closure" decline has arms for a struct and a map and none for a list

**closed 2026-09-06 — the outer element is a LIST that contains a closure, the third container the rung's own comment names · filed against master `40334c8cf`, closed against `cb23d669f` · D1664's residue · 0 corpus cells**

Repro:

    const xs = [[(n: i32) => n + 1]]
    const v = xs[0]
    const __cp = (m: i32) => v[0](m)
    print(__cp(54))
    // vl check: rc 0.  vl run: rc 0, prints 55

#### Mechanism

**The filed mechanism above was a PREDICTION and the probe refutes it.** It said
`arrLitElemKind`'s nested-array rung "keys the inner list by its scalar leaf … and has no
closure leaf". That rung is never reached. A probe placed at the top of its `e0 is ArrayLit`
arm fired on the nested-i32 control and stayed **silent on this witness** — the instrument
worked and the arm was skipped — so a second probe was placed one rung earlier:

| | nested i32 (`[[1, 2]]`) | this witness (`[[lambda]]`) |
| --- | --- | --- |
| `nodeArrayElemName` of the outer literal | `i32[]` | **`((i32)=>i32)[]`** — the checker records it correctly |
| `arrElemIsClosureTy` of the outer literal | 0 | **1** |

The outer literal is claimed as a CLOSURE list (kind 5) before the nested-array arm is
consulted at all. `arrElemIsClosureTy`'s last rung is `tyMentionsFunc(ety, 0)` — an arrow at
any depth, deliberately wide because the element reps as a ref either way — and its
corrections are explicit declines for the containers that merely CONTAIN a closure: `TyObj`
and `TyMap`. **There is no `TyArray` arm.** A list of closures is the third such container,
and its element reps as the inner list's wrapper, not as a closure cell.

The read shape only picks which sentence fires. On master this one witness wore FOUR:
`callee is not a function name`, `call to unknown function`, `nested arrays are not
supported`, and `a call statement's callee is not a function`.

#### Close

One rung, beside the two declines the comment already named:

    if et is TyArray { return false }

The nested-array rung then runs and already has what it needs — `arrLitIsRef` answers true
for a lambda-leaf inner literal, so the ref path keys it. Nothing was added to the leaf
vocabulary the row predicted was short.
