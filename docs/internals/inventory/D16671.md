### D16671 — a unary `-` over a literal join does not adopt the typed type beside it, as `~` and the bare join do

**check-clean silently wrong · clause 1 · open · `vl check` rc 0 · ruling 4.3 (a literal adopts a typed join or peer, one rule for every join form) · `~(join)`, the bare join and `-0xFFFFFFFF` adopt · the `f32` face is also a loud check reject: `const z: f32 = -(if c { 0.1 } else { 1.5 })` is refused · found by the independent oracle's arithmetic generator (fuzz cells `ar_s67_0013`, `ar_s71_0182`) · filed 2026-11-15 against master `93ad5a25c`**

Repro:

    function id(x: i32): i32 { return x }
    const c = id(1) == 1
    const w: i64 = 5
    print((-(if c { 0xFFFFFFFF } else { 46341 })) + w)
    const a: f32 = 1.5

    // master: vl check rc 0, prints 6 then 0.16666666666666666

Want:

    -4294967290
    0.1666666716337204

#### Mechanism

Not ablated to a compiler function. The join adopts the typed peer, `i64` or `f32`, when it is
the operator's operand, and `~` passes that adoption through. `-` does not: the join under it
keeps its default (`i32`, or `f64`), the negation runs there, and the result widens.
