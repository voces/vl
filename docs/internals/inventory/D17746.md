### D17746 — an empty map an un-annotated function stores into the container it returns takes the i32 key before the caller's read can pin it

**closed 2026-11-27 — an open map held whole as a value counts as a defaultable hole, so one leaving an un-annotated function waits for the program's end and its caller's reads pin it · filed against master `ba6dff69` · 400 F1 cells and 3 F2 representatives that refused "got {[i32]: i32}" run**

Repro:

    function mkcall() { const lv1 = Map(); const cc = Map(); cc["k0"] = lv1; return cc }
    const dd = mkcall()
    const g0 = dd["k0"] ?? Map()
    const g1 = g0["k0"] ?? { r: 1 }
    print(g1.r)
    // prints 1

Want:

    1

#### Mechanism

A capability gap, not an unknown type. The inner `Map()` is never written, and the caller's read
supplies both its types: the key from the read's key (D16726's `pinReadKey`), the value from the
`??` default (D17734). But the map is made inside `mkcall` and leaves it inside `cc`, so its open
key takes the `i32` default before the caller's read is checked. The module-scope spelling
pins and runs once D17734's `??` pin is in (#10641).
