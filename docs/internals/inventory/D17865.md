### D17865 — a member name of a tagged set written straight into a list beside `null` is read as no id

**closed 2026-11-28 · runs, prints `4` · was `emitProgram: the compiler cannot yet lower this statement (read of inc)` · the flow rewrite (`monoFlowReadSet`, emit_mono.vl) overwrote the read `xs[0]` with the member's name, which as a read of the set's `F | null` carries no id; it now leaves a read of the set or of its nullable alone · pin `closures/list-of-tagged-member-name-beside-null` · filed 2026-11-28 against master `c088f52cf` by COV-UNION (D17854's remaining face, coordinator ruling)**

Repro:

    function inc(a) { return a + 1 }
    const xs = [inc, null]
    const f = xs[0]
    if f != null { print(f(3)) }
    // vl run: prints 4

Want:

    4

#### Mechanism

The list is the set's `F | null` and holds the nullable id. The checker types the element name `inc`
at that slot type, `((_) => _) | null`, so `ftIsS` (a value test that reads the node's type) does
not take it as a value of the set, and it is no leaf: its read finds no id. Taking member names by
their declaration in `ftIsS` makes this read an id but moves 82 filed rows from runs to a refusal,
so the leaf must come from the slot, not from `ftIsS`.
