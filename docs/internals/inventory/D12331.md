### D12331 — a lambda written into a list element holding a generic, whose return misfits the generic's, called inside a generic body still passes the checker

**loud emit reject · `vl check` rc 0 · `emitProgram: a function value's signature is not known at this call — the type it was given takes fewer parameters than the call passes` · clause 2 · DESIGN: the same write called at top level is refused at check (`cannot write a lambda to an element of 'fs': a call through it at (string, string) runs it, and it is (string, string) => i32`) · check_relate_core.vl, `holeSlotFixedJudge` / `holeLamMisfitAt` while deferring · found closing D12238 · filed 2026-10-24 against master `84941745b`**

Repro:

    function pick<A, B>(a: A, b: B): A { a }
    const fs = [pick]
    fs[0] = (x: string, y: string) => 5
    function g<T>(v: T): T { fs[0](v, v) }
    print(g("a"))

#### Mechanism

D12238's close records, while the hole-slot judge defers a call inside a generic body, a demand
per PARAMETER that each pin re-checks. The written function's RETURN is not recorded: at the pin
`g<string>` the call `fs[0]("a", "a")` wants `string` back from `pick` and the lambda returns
`i32`, which the top-level judge refuses and the deferred one never sees. A return demand beside
the parameter demands (a new argument-constraint form) is the close.

#### Ablation

| ingredient removed | outcome | needed? |
| --- | --- | --- |
| the generic body (`print(fs[0]("a", "b"))` at top level) | check reject | **yes** |
| the misfit return (`=> x`) | runs, prints `a` | **yes** |
| the annotation on `x` (`(x, y: string) => 5`) | loud emit reject, same | no |

#### Grading list

The record-field spelling (`const r = { f: pick }; r.f = …`); the fixed-function spelling (a
declared `function k(x: string, y: string): i32 { 5 }` written to the element), which refuses
at emit with the same message today.
