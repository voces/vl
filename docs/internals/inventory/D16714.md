### D16714 — the read-only map parameter floor fires only when the function is declared before the call: declared after, the same program runs

**loud check reject · `argument 1: parameter is used as a map but nothing in the body pins its key or value — add a type annotation` · clause 2 and a declaration-order dependence (D16301's class) · found re-ablating [D15161](D15161.md) for the L2 S3 plan · filed 2026-11-16 against master `078e4116`**

Repro:

    function run(m) {
      const g = m.get("b")
      if g != null { print(g) }
    }
    const m = Map()
    m.set("a", 1)
    m.set("b", 2)
    run(m)
    // vl check: the refusal above at the call.  With `run` moved below the call: runs, prints 2

Want:

    2

#### Mechanism

The floor (`tests/cases/maps/error-infer-param-map-not-pinned.vl`, the workboard's E5 escalation)
refuses a hole parameter whose map demand the body left open. That demand is open only when the
body is checked before the call. Checked after it, the call's argument has already pinned the
hole, and the program builds and prints the right value. `decl-order-ab.vl` cannot see this,
because it reads only `@run` cases, and the floor's own case is an error case.

#### Ablation

| ingredient removed | outcome | needed? |
| --- | --- | --- |
| the declaration order (`run` below the call) | runs, prints `2` | **yes** |
| the hole (`m: {[string]: i32}`) | runs, prints `2` | **yes** |
| the function values of D15161 (scalar values here) | still refuses | no |
