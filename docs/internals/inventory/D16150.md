### D16150 — an `is` test against a record arm that mentions the type parameter, in a generic body, names no variant

#### Mechanism

Two defects, one per face.

**The checker face.** Every annotation a generic resolves mints its own `TyVar` row for `T`, and
`tySame` compares type variables by index, so the `is` spelling's `{ kids: T[] }` was never the
same type as the parameter's arm and `recIsFitsAcrossTags` kept the operand unnarrowed. The
signature's and the body's rows now record the declaration they are a parameter of
(`tyVarDeclOwner`), and `tySameDecl`, which `recIsFitsAcrossTags` asks, treats two rows of one
declaration's parameter as one type. `tySame` itself is unchanged: equating them there moves a
nested generic's redeclared `T` (`error-nested-redeclared-param-called-with-outer-value-operator.vl`).

**The emit face.** A union of records over `T` at a union-of-records argument bound nothing:
`bindGenWalk` had no union arm on the call path, so `T` defaulted to `i32` and the instance's
`is { kids: i32 }` was no variant of the `string` union. `bindGenRecordArms` pairs each parameter
arm with the argument arm of the same field names, in either order, and binds field by field. The
same gap left a call result typed with `T` open (`back(c)` returning `{leaf: T} | {kids: T}`).
