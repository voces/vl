### D2464 — a nested function whose only use of a narrowed place is re-testing it is refused at a later writing call

**loud check reject · clause 2 · filed 2026-09-25 against master `2bf40476c`, found by the review
of #3157 · open**

Repro:

    const xs: (i32 | string)[] = [1]
    function w() { xs[0] = "s" }
    if xs[0] is i32 {
      const c = (): boolean => xs[0] is i32
      w()
      print(c())
    }
    // vl check: 'xs[0]' is read at its narrowed type by the function on line 4, which may run after the call to 'w' writes it — re-test 'xs[0]' inside that function

#### Mechanism

Not yet ablated to the rung. D2402's close refuses a writing call once a nested function has
read a narrowed path, because that read would use the narrowed type. An `is` test is not such a
read. It is the re-test the sentence asks for, and since D2447's close `emitIs` tests the place's
storage rather than trusting the narrowing. The reader census (`crCaptureCallCheck`) counts an
operand of `is` as a narrowed read. The program is sound and should print `false`.

#### Ablation

| ingredient removed | outcome | needed? |
| --- | --- | --- |
| the call `w()` | runs, prints `true` | **yes** |
| the test (`c` reads `xs[0] + 1`) | the same refusal, which is correct there | **yes** |
| the place (a field `o.v`) | the same refusal | no |

#### Grading list

The field spelling (`o.v`, written by `w`); a module global `g`, whose writer-call rule is D2390's.
