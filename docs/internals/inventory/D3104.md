### D3104 — a top-level binding of a generic function value is re-asked at every later generic call whose type parameter shares its name

**closed 2026-09-28 — the filed repro prints `s` then `3` · was a loud check reject of a well-typed program, clause 2 · found closing [D3080](D3080.md) · closed by recording no destination constraint outside every generic when neither side holds an inference hole: the only type parameters there are a generic function value's own, which its delivery binds and now adjudicates · fixture `tests/cases/generics/generic-fn-value-binding-not-reasked.vl` · filed and closed 2026-09-28 against master `d408f2da4`**

Repro:

    type R = { a: i32 }
    function show<T>(x: T) { print(3) }
    const g: (R) => void = show
    function asInt<T>(x: T) {
      print(x)
    }
    asInt("s")
    g({ a: 2 })
    // vl check: cannot assign (string) => void to 'g' of type (R) => void (the body of `asInt` at the call's argument types)

Want:

    s
    3

#### Mechanism

`const g: (R) => void = show` records a destination constraint with `show`'s own `(T) => void` as
its source and no owning declaration. A row with no owner is re-asked at every generic call, and
`substTyDeep` matches a type parameter by name, so `asInt("s")` substitutes `T := string` into
`show`'s signature and refuses a binding it never touched. The same holds for a record field
`{ f: show }` and a list element `[show]`. [D2756](D2756.md) is the same mechanism met by a
second call of the SAME generic at another pin.

#### Ablation

| ingredient changed | outcome | needed? |
| --- | --- | --- |
| `asInt` renames its parameter `U` | runs | **yes** (the shared name) |
| `const g = show`, no written type | runs | **yes** (the typed destination) |
| the binding inside a function | runs | **yes** (no owning declaration) |

#### Grading list

The binding, record-field and list-element deliveries at the top level, with a later generic call
at `string` and at `i32`.
