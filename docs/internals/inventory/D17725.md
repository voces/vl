### D17725 — a map read of a tagged set's id, returned in a list a `for` walks and calls, is recorded non-null though its key may be missing

**closed 2026-11-27 · runs, prints `none` · was loud emit reject, clause 2, `narrowed read` · closed in two halves: I8-PREP's #10561 kept the map read's `| null` through the mono pin, and COV-CLOS's `fnSetTyKeep` (emit_elab.vl, from `tyKeepNullOf`) keeps the read's function set on the type the pin closes, so the list, the loop variable and the call share the set's one rep · fixture `closures/for-in-over-returned-map-reads-of-a-tagged-set.vl` · filed 2026-11-27 against master `ff95d049f` (lane COV-CLOS)**

Repro:

    function inc(a) { return a + 1 }
    const m = Map()
    m["k"] = inc
    function ret() { return [m["zz"]] }
    for f in ret() { if f != null { print(f(3)) } else { print("none") } }
    // vl check: rc 0.  vl run: was an emit error at the loop's narrowed read (narrowed read)

Want:

    none

#### Mechanism

The monomorphizer closed the map read `m["zz"]` at the list's pinned slot type and dropped two
facts the open read carried. `monoStoredSlotFnTy` (through `monoRecordOpen`) and `monoRetFnListTy`
dropped its `| null` (fixed by #10561: `tyKeepNullOf` keeps it). They also dropped its function SET:
the closed `(i32) => i32` carried none, so `ret`'s list was a list of closures while the walk's
read and call, typed at the set, asked for its member id. The variable and its read disagreed on
the set's rep, and the IR converted at the list (`RTagClo`) and refused at the read. A pin now
keeps the set too (`fnSetTyKeep`, called by `tyKeepNullOf`), so the list, the loop variable and the
dispatch all hold the set's one rep, the id, and no conversion is built.
