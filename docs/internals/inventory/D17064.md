### D17064 — an arithmetic or comparison operator whose left operand is `never` is typed at i32, so a float right operand reaches an integer op

**check-clean invalid wasm · 1 witness · filed 2026-11-23 against master `f3f248cd4` by lane IR-C1**

Repro:

    function fail(): never { __trap__() }
    function w(c: boolean, x: f64) {
      if c { return x }
      return fail() * x
    }
    print(w(true, 2.5))
    // vl check: rc 0.  vl run: failed to validate inside `w`: type mismatch: expected i32, found f64

#### Mechanism

The operator over a `never` operand is itself `never` (D14420), and legacy picks its numeric op
from the left operand's type. `never` falls to the default i32, so it writes
`call fail; unreachable; local.get x; i32.mul; f64.convert_i32_s; return`. The f64 `x` is an
operand of `i32.mul`, and the result is widened to the function's f64. Past the `unreachable` the
stack is polymorphic, so only the right operand's type is checked, and it does not match.

#### Ablation

| ingredient changed | outcome | needed? |
| --- | --- | --- |
| `x * fail()` (the `never` operand on the right) | runs, 2.5 | **yes** |
| `x: i32` | runs, 4 | **yes** (a float right operand) |
| `x: i64` | runs, 5 | **yes** |
| `x: f32` | invalid wasm | no |
| `fail() - x`, `fail() < x` | invalid wasm | no (any arithmetic or comparison op) |
| `fail() * 2.0` (a literal) | invalid wasm | no |

#### Grading list

- `return fail() * 2.0` in a function whose other path returns `2.5` (the literal spelling).
- `x * fail()` and `fail() + 1` must keep running.
