### D1560 — an if-EXPRESSION whose ARMS are themselves `T | null` classified as nothing, because the family asked its NON-NULL predicate of the arm

**closed (fixed) — the `exprNullable*` family, `ifExprRefKind` and `ifExprRefSlot` gained an if-EXPRESSION rung gated on the checker's own join, so the INFERRED binding gets the rep the annotation gives it · was a loud emit reject at check rc 0 (clause 2) at the un-annotated spelling and check-clean INVALID WASM (clause 1) at the annotated container spellings · rep grid 23 -> 56 of 56, position matrices 33 -> 50 and 4 -> 47 of 54 · ZERO corpus cells · reported by the glean session, VL-025, `~/glean/docs/vl-issues.md`, probe `~/glean/vl-probes/VL-025-if-expr-nullable-calls.vl` · filed 2026-09-03 against master `194c8ff4`**

Repro (runs, prints `ok` then `b`):

    type E = { msg: string }
    function a(ok: boolean): E | null {
      if ok { return null }
      return { msg: "a" }
    }
    function b(ok: boolean): E | null {
      if ok { return null }
      return { msg: "b" }
    }
    function pick(flag: boolean, ok: boolean) {
      const e = if flag { a(ok) } else { b(ok) }
      if e != null { return e.msg }
      "ok"
    }
    print(pick(true, true))
    print(pick(false, false))

#### Mechanism

**BOTH FACES CARRY THE IDENTICAL ARENA ROW.** The checker types this join `TyNullable(TyObj E)`
— `joinTys` sees two mutually assignable arms and hands back the first — and annotating the
binding `E | null` draws `@hint redundant type annotation`, which is the checker agreeing about
the TYPE. Only the annotated face reached `letIsNulRef`; the inferred one took the `"i32"` slot
default from `collectLocals`' last rung while the `if` pushed `(ref null $E)`.

The reason is one line in each `exprNullable*` member. `nulArmIfThenValueIx` answers an
if-expression only when the OTHER arm is a bare `null` — the D1086 shape — and each member then
asks its **NON-NULL** predicate of the surviving arm (`exprArray`, `structIndexOfExpr`,
`exprMap`, …). A `T | null`-returning CALL answers no to every one of those, so the family
declined, no rung claimed the node, and the slot fell through. The fix is the parallel rung:
`nulIfArmNullableValueIx` returns the arm that carries the rep and each member asks **its own
nullable predicate** of it, so the recursion ends at the arm's own producer.

**THE GATE IS THE TYPE PRODUCER, NOT A NAME LOOKUP.** `nodeTyIsNullableOneRep` (typecheck.vl)
is `TyNullable` over one inner — `joinTys` folds two nullable arms of DIFFERENT shapes into
`TyNullable(TyUnion(Hit, Miss))`, whose rep is the box and not either arm's niche, so a rung
reading one arm's rep would name a heap type the other member cannot hold. A literal union is a
`TyUnion` by shape and one rep by niche (the interned i32 atom), so it is admitted explicitly —
the same exclusion `??`'s rewrite states from the other side.

**TWO SENTENCES, TWO ARMS OF ONE MECHANISM.**

| face | what it said | what fired |
| --- | --- | --- |
| plain struct, INFERRED only | `emitProgram: bare null needs a struct-typed context` | no kind was chosen at all — the slot is `"i32"`, so `e != null` reaches `emitNullLitNode` with every boundary seed at its default |
| the arm's struct is a UNION MEMBER, BOTH faces | `emitProgram: ref valtype with no interned shape` | a kind WAS chosen — `ifExprRefKind`'s `nodeTyIsNullableStruct` fallback said `"struct"` — and `Hit` lives in `uVarHeap`, so `ifExprRefSlot` answered -1 and `fbValtype`'s bounds guard fired before any `null` was written |

The second is what the reporter's MPQ reader hit, and it needed no extra scenery: declaring
`type R = Hit | Miss` and never using it is the whole difference. `exprNullableVariant` had no
if-expression rung at all — not even D1086's — which is why that face refused at the annotated
spelling too.

**AND THE ANNOTATED CONTAINER FACES WERE CLAUSE 1, NOT CLAUSE 2.** `ifExprRefKind` asks the
then arm's non-null predicates, so `const e: i32[] | null = if c { la() } else { lb() }` matched
none, fell to the SCALAR path, and emitted `(if (result i32))` over two `(ref null $wrapper)`
arms — `vl check` rc 0, engine refuses. Measured at `i32[]`, `string[]`, `f64[]`, `i64[]`,
`E[]` and `{[string]: i32}`: **11 silent cells, all at the spelling an annotation was supposed
to pin.**

Four sites carry the fix, and each is the "read kind and slot off ONE arm" rule: the family's
rungs (the binding's rep), `ifExprRefKind` (the join's kind), `ifRepArmValueIx` feeding
`ifExprRefSlot` (its companion slot, with a `variant` arm the struct fallback used to swallow),
and `emitRefIfArm` / `emitIfExprAs` lowering a bare-`null` ARM as the join's own null
(`fbRefNullOfKind`, or the niche sentinel) rather than through `emitNullLitNode`'s boundary
seeds — which a binding's initializer position never sets, so the explicit `else { null }`
spelling refused where its else-less twin ran.

#### Ablation

| ingredient removed | outcome | needed? |
| --- | --- | --- |
| the annotation is ADDED to the binding | runs (plain struct) / still refuses (union member) | **yes** for the plain face, no for the variant face |
| one arm replaced by a literal `null` (a NON-nullable then arm) | runs | **yes** — that is D1086's shape, already served |
| one arm replaced by a literal `null`, then arm still a `T \| null` CALL | still refuses | no — the same missing rung |
| both arms replaced by ONE call (`const e = a(ok)`) | runs | **yes** — the if-expression is the ingredient |
| the binding is never read (no `e != null`) | check-clean INVALID WASM (`expected i32, found (ref null $type)`) | no — the read only changes which sentence fires |
| `type R = Hit \| Miss` deleted from the module | refuses with the OTHER sentence | **yes** for which sentence, not for whether it refuses |
| the two arms return DIFFERENT structs (`Hit \| null` / `Miss \| null`) | stays a LOUD refusal on both seeds | the negative control: `TyNullable(TyUnion)` must NOT take an arm's rep |
