### D4034 — a receiver-overload set whose candidates return their own type parameter is refused at a type-parameter receiver, blaming the receiver

**loud check reject · clause 2 · the refusal names the wrong cause · found in the #3538 review (lane DV, D4030) · filed 2026-10-11 against master `98a4ed71b`**

Repro:

    // file: s.vl
    export function tag<T>(self: string, v: T): T { print("S"); v }
    // file: a.vl
    export function tag<T>(self: i32[], v: T): T { print("L"); v }
    // file: entry.vl
    import { tag } from "./s"
    import { tag } from "./a"
    function d<R, T>(r: R, v: T): T { r.tag(v) }
    print(d("a", 1))
    // vl check: `.tag(…)` cannot choose between `tag` from "./s" (a `string` first) and
    // `tag` from "./a" (a list first) for a receiver each call supplies, because a
    // candidate's return type depends on its receiver — annotate the receiver

Want:

    S
    1

#### Mechanism

`ovHoleCallTy` (`compiler/typecheck.vl`) types a call through an overload set at a receiver
each instance supplies by the one return type every candidate shares, and refuses any
candidate whose return type has a type variable with the sentence "depends on its
receiver". Here both candidates return `T`, which is bound by `v`, not by the receiver, so
the sentence is false, and the two candidates agree on the return type once `T` is bound at
the call. When both candidates return `i32` the same program runs and picks per instance.

#### Ablation

| ingredient removed | outcome | needed? |
| --- | --- | --- |
| the candidates' type parameter (both `(self, v: i32): i32`) | runs, prints S 1 L 2 | **yes** |

#### Grading list

The four-instance spelling (`d("a", 1)`, `d([1], "x")`, `d("b", 2.5)`, `d([2], true)`,
want `S 1 L x S 2.5 L true`), and a set whose candidates return different instantiations
of their own `T`, which should still refuse, with a sentence that names that cause.
