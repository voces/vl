#### Mechanism

At the nullable argument type, `a?.f` is typed `((i32) => i32) | null`, and the call pin
`OP_CALL_PIN` refused it, though `?.` owes the call only on the present receiver. At the pin,
`callFloorMsg` judged the read's type, `null` included, so a present record argument and the
`<T>` spelling were refused too (traced for L2 S3.4c). Judging the call at the read's non-null
face alone passed check but built an invalid module, so the fix is in three places:

- **Checker.** A `?.` call through a hole notes its own pin, `OP_CALL_OPT_PIN`
  (`compiler/check_leaf_steps.vl`). `memCstrMsg` judges that pin on the callee's non-null face,
  and a pin of `null` reads `null`.
- **Rewrite.** At a hole instance, `drwOptGuard` types the guard `if` at the call's result
  `| null`. Without that, the null arm built an invalid module (`expected i32, found nullref`).
- **Emit.** `cloCallSigKey` keys a field callee that the guard left untyped by the field of its
  receiver's non-null type. Without that, an instance that never builds a closure of the field's
  type read the call as void (`union if-expression arm ends in a void call`). The annotated
  parameter `a: { f: (x: i32) => i32 } | null` failed the same way when no `inc` was declared.
