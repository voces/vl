#### Mechanism

At the nullable argument type, `a?.f` is typed `((i32) => i32) | null` and the call through it is
refused, where `?.` owes the call only on the non-null receiver. The annotated parameter
`a: { f: (x: i32) => i32 } | null` runs.

Traced for L2 S3.4c (2026-11-16). The call through the hole records the plain call pin
(`OP_CALL_PIN`), and at the pin `callFloorMsg` judges the `?.` read's type, `null` included. Even a
non-null record argument is refused, and the `<T>` spelling is too. Judging an optional-chain call
at the read's non-null face instead (`memCstrMsg`) passes check, but the instance then builds an
invalid module (`type mismatch: expected i32, found nullref`), so that change alone is a clause-1
regression and was not kept. The emitter's instance lowering of an optional call is the missing
half. The direct spelling with a `const` bound to `null` is [D16828](D16828.md)'s.
