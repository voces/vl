### D3271 — a `match` arm could not name a constant, so every arm spelled its value and a comment

**closed 2026-09-29 (`resolveMatchConstPats` in `compiler/typecheck.vl` rewrites a bare-name arm that names no type into a read of the `const` it resolves to; owner ruling (A) on plumb PL-062) · was a loud check reject, clause 2 · filed against master `569caa36c` · fixtures `tests/cases/match/const-arm-dispatch.vl`, `tests/cases/match/const-arm-errors.vl`, `tests/cases/match/const-arm-litunion-errors.vl`, `tests/cases/match/const-arm-precedence.vl`, `tests/cases/modules/match-const-imported/`, `tests/cases/modules/match-const-type-shadow/`, `tests/vl_match_br_table_test.ts` (`const_arms`)**

Repro:

    const LF_CLASS = 0x1504
    function kind(k: i32) {
      match k {
        LF_CLASS => "class"
        _ => "other"
      }
    }
    print(kind(0x1504))
    // was: invalid match pattern — a pattern over i32 is an integer literal or the `_` wildcard
    // now: prints class

Want:

    class

#### Mechanism

The parser mints every bare name in pattern position as a type pattern (`IsExpr`), and each
value vocabulary (integer, literal union, a hole the arms decide) refused one outright. Now,
before the vocabulary is chosen, the name is looked up as a value: a `const` whose initializer
is a number, `-` over one, or a string is rewritten in place into an `Ident` read of it, so the
desugared test is the hand-written `scrut == K`, and the literal is kept beside the node for the
duplicate check, literal-union membership and the `br_table` key. Over an integer or literal
union such a constant wins over a same-named type (no type but `null` is a pattern there); over
a union of types, and at a hole, the type wins. Anything else — a variable, a function, a
computed `const`, an unknown name — is a hard error at the pattern. The module merge renames a
pattern as a type and, where a local value shadows the name, banks the value spelling beside it
(`modRwMatchPat`), so a shadowing local reads as itself in a merged program and a shadowed
imported type still reads as the type.
