**now a loud check reject, the refusal the design owes, 2026-09-29 (`retireAliasedNarrowings` in `compiler/typecheck.vl` resolves neither sole-reference exemption through a name an inner declaration hides, and `narShadowPaths` shadows an already retired entry too) · was check-clean, trapping at run time on master, clause 1 · sibling of D3020 · filed against master `e70102886` · fixture `tests/cases/unions/error-flow-join-kill-any-path.vl`, hazards `hidden_outer_alias*` in `scripts/flow-narrowing/join-hazards.py`**

    type Box = { v: i32 | null }

#### Mechanism

An alias write retires every path narrowing whose object it may reach, except where a key's root
is a binding no other place refers to (`crSoleRefBinding`). That exemption resolves the root by
NAME at the write, where `a` is the inner `const a` bound to a fresh object, so the outer `a.v`
narrowing looked unreachable. An entry an inner declaration hides now takes neither exemption.
