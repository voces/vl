### D2036 — a struct with an `i32` field passed where a struct with an `f64` field of the same name is declared is check-clean invalid wasm

**closed by design · now a loud check reject · was check-clean invalid wasm · the owner's record-covariance ruling refuses it: an annotated record is not fresh, and its field is stored as `i32` against the destination's `f64` · closed 2026-09-30**

Repro:

    type V = { x: i32 }
    type W = { x: f64 }
    function f(w: W): i32 { return 1 }
    const v: V = { x: 5 }
    print(f(v))
    // vl check: rc 0.  vl run: invalid module — type mismatch: expected (ref $type), found (ref $type)

#### Mechanism

Not yet ablated. The checker admits `V` where `W` is declared (the `i32` field widening to
`f64`), and the call site passes the `V` struct reference unconverted into a parameter typed as
`W`'s struct. Either the argument boundary needs the field-converting copy, or the checker owes a
refusal; the direct call and the UFCS spelling `v.f()` with `f(self: W)` fail identically.

#### Grading list

The UFCS spelling; the same pair at a binding (`const w: W = v`), a return, and a struct field.

#### Close (2026-09-30)

Closed by the owner's record-covariance ruling (DECISIONS.md "Record covariance: only a fresh value widens"): an annotated record is not fresh, and its field is stored as `i32` against the destination's `f64`. The refusal names both fixes, building the source at the wider record or copying it with an object literal, so no program the design permits is refused.
