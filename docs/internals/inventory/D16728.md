### D16728 — a `string | null` field shared by a record union's arms, read after a member null test, is delivered nullable into a non-null string slot

**closed 2026-11-17 · runs, printing `hi` · was check-clean invalid wasm · graded by `shared-nullable-string-field-narrowed.matrix.vl`, 46 of 64 cells silent before, 64 of 64 run after · found by hand while sizing rep ADT stage 5 · filed 2026-11-17 against master `a68eff941`**

Repro:

    type A = { v: string | null }
    type B = { v: string | null, w: i32 }
    function f(x: A | B) {
      if x.v != null { print(x.v) }
    }
    f({ v: "hi" })
    f({ v: null, w: 3 })
    // master a68eff941: vl check rc 0, vl run invalid module "expected (ref $1), found (ref null $1)" inside `f`

Want:

    hi

#### Mechanism

The read `x.v` off the un-narrowed union goes through the shared-field plan (`sharedUnionFieldPlan`,
code `FC_NUL_STR`). Its tag dispatch is an `if (result (ref null string))`, and the consumer of
the narrowed read stores that result straight into a `(ref string)` local with no
`ref.as_non_null`. A read off a single record type recovers the non-null string. A shared read of
a nullable list, boolean or record recovers too, because `readOwesNonNullRecover` serves those
kinds and leaves `string | null` to its own rule, which the shared dispatch does not reach.

#### Grading list

- The four delivery spellings and the early-return guard in the ablation.
- The same read through a three-arm union, and through a union with a `null` member.

#### The close

`readOwesNonNullRecover` treats a narrowed `string | null` cell like every other nullable ref:
the read recovers once, after it is emitted, whichever lowering produced it. The string-only
recoveries at field, local, capture and global reads go, and the IR's global read asks the same
rule.
