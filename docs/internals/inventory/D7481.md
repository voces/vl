### D7481 — a generic delivered into a function type compares unequal to the generic's own name read at another instance

**closed 2026-10-20 by lane L1 · runs, prints `1 s true` · was check-clean silently wrong, wrong value · a closure carries a third field, `decl`, the slot of the function standing for its source declaration (`cloDeclOf`, wasmEmit.vl: through void twins and adapters to the generic origin), and `==` compares `decl` and env; `id` stays the dispatch slot · pin: `tests/cases/closures/generic-delivered-at-two-signatures-equality.vl` · two deliveries widened into one union-of-function-types binding at different arms are [D7701](D7701.md) · `vl check` rc 0 · clause 1 · under the [D7180](D7180.md) ruling a function value's identity is its declaration, never the instance it was split into, so `f == id` is `true` · found closing [D7382](D7382.md) · present on master `1c86d0f42` · filed 2026-10-19 against master `1c86d0f42`**

Repro:

    function id(x) { return x }
    print(id(1))
    print(id("s"))
    const f: (x: string) => string = id
    print(f == id)
    // vl run: prints 1, s, then false

Want:

    1
    s
    true

#### Mechanism

A closure's identity token was the function index of the adapter or instance it calls, and
[D7382](D7382.md)'s close canonicalised it per declaration AND signature, so two values of
one declaration at two signatures carried two tokens. The close separates identity from
dispatch: the `decl` field names the generic origin, the `id` field still names the callee.
