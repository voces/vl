#### Mechanism

The checker leaves the call's result an unconstrained hole: in `p4`, `const v = run(1.5)` accepts
`const w: string = v`. A destination that pins it (`const v: f64 = run(1.5)`) runs and prints `3`;
an unpinned one (`print(run(1.5))`) is written at the i32 a hole defaults to while the value is
`f64`. The lambda's result is `app(h, x)`'s, a generic call over the captured hole function `h`;
the same lambda calling `h(x, x)` itself is typed and runs. Not fixed by D17641's built-rep keying
(#10333): the argument is a scalar, not a storage row.
