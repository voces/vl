### D3264 — a returned join of a type parameter with a literal, bound outside the generic and put in an object literal, mints no row

**closed 2026-09-29 at depth 1 only (a literal `{ v: w }` whose own field holds the join) · the remainder, a literal nested deeper, a generic returning `{ v: r }` or `[r]` whose element is re-delivered, and two record pins at one shape, stays a loud emit reject and is [D3282](D3282.md) · was a loud emit reject, clause 2, in #3297 round 2 (invalid wasm on master `569caa36c` at a record binding; the `"a" | "b"` cell ran there) · a concrete record literal with a field at a union now mints its row after monomorphization, when every box exists · found by the #3297 review (`g2` grid, `rec__jrev__field` and `k__jrev__field` cells) · filed 2026-09-29 · fixture `tests/cases/generics/gradual-type-parameter-union.vl`**

Repro:

    type R = { f: i32 }
    function g<T>(a: T, c: boolean) {
      const r = if c { 5 } else { a }
      return r
    }
    const u: R = { f: 1 }
    const w = g(u, true)
    const b = { v: w }
    if b.v is i32 { print("L") } else { print("P") }
    // vl check: rc 0.  vl run: emitProgram: object literal matches no union variant

Want:

    L

#### Mechanism

`w` is typed `R | i32`, the join D2906 keeps apart. The anonymous-row pass runs before the
monomorphizer, and its field code for a union needs a box it can name; a box a pin registers, or
one the program spells under a member order the pass does not match, is not there to name, so
the literal minted no row and the emitter fell to the variant path (`object literal matches no
union variant`). When some generic instance returns a union holding a type parameter, the
post-monomorphization shape pass (`collectAnnShapes`) now interns the row of every concrete record
literal with a union-typed field, leaving a literal whose spelling already resolves to a row to
that row (the declared-row contract of D1694). A program with no such instance pays no walk.
