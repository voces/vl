### D17112 — a structural `==` of two records of a declared type that is also a union arm traps the compiler at a nullable scalar field

**closed 2026-11-24 by S2 · runs, prints `false true false false true 7` · was compiler trap, out of bounds in `sFieldElemTyIxAt` from `emitStructEqFieldAt` · the union-box field arm read the field's box type off the struct table with a variant eq row (`row < 0`); it now reads it through `eqRowFieldElemTyIx`, from whichever table owns the row · found by the D17103 position sweep · beside [D17103](D17103.md) · filed 2026-11-24 against master `ec119adc`**

Repro:

    type J = { f: i32 | null, g: i32 }
    function su(j: J | string): i32 { return if j is string { 0 } else { j.g } }
    const a: J = { f: null, g: 7 }
    const b: J = { f: 3, g: 7 }
    const c: J = { f: 3, g: 7 }
    const d: J = { f: 4, g: 7 }
    const e: J = { f: null, g: 8 }
    print(a == b)
    print(b == c)
    print(b == d)
    print(a == e)
    print(a != b)
    print(su(a))

Want:

    false
    true
    false
    false
    true
    7

#### Mechanism

`J` is an arm of `J | string`, so its values are compared through their variant's eq row, which
is negative (`eqRowOfVariant`). Field `f: i32 | null` is a union box, and the box arm of
`emitStructEqFieldAt` asked `sFieldElemTyIxAt(si, fi)`, indexing `sFieldStart` with the negative
row. The ref-list arm beside it already guarded `si >= 0`.
