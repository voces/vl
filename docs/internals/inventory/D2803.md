### D2803 — a type parameter bound only through a union parameter is never pinned, so the body's deferred checks never run

**now a loud check reject — the refusal the explicit `k<R>(x)` already gives · was check-clean invalid wasm · clause 1 · the four `gN/sR_*_inf` cells and `gPr/{ias0,sR0}_gnar` of #3208's review · closed by binding the union's one open member to the argument's members no concrete member admits (`bindGenUnionArm`) for the call's deferred checks and its return · filed 2026-09-27 against master `2bbc5c412` · fixtures `tests/cases/generics/error-union-param-pin-at-body.vl`, `tests/cases/generics/pin-union-param-binds-open-member.vl`**

Repro:

    type R = {a: i32}
    function k<T>(v: T | string) {
      if v is string { print(v) } else { print(v) }
    }
    const x: string | R = "q"
    k(x)
    // vl check: rc 0.  vl run: invalid module inside `k` — expected i32, found (ref $type)

#### Mechanism

The checker's call-site binding (`bindGenWalk`) has no arm for a union parameter, so a call
whose only use of `T` is `v: T | string` bound nothing. Every deferred check of the body — the
print, destination, argument and return constraints — is gated on the call's bindings, so none
ran, and the return kept its hole. The monomorphizer binds `T` to the argument's members no
concrete member names (D2734's `monoBindUnionRest`/`exactBindWalk`), so the instance printed a
record through `__print_i32__`. The checker now makes the same binding into a separate list
read only by the deferred checks and the return substitution: bound through the ordinary walk
first, a use such as `w: T` still wins, and the escaped-join refolder keeps the ordinary list.
