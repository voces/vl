**now a loud emit reject · clause 2, still open · was check-clean invalid wasm, the same on master `a41bd80e8` · the use that hands the list or an element on at its own record is refused (`rsNarrowUseRefuse`) · fixtures `tests/cases/soundness/error-reseated-record-list-handed-on-at-own-type.vl`, `tests/cases/soundness/reseated-record-list-converting-uses-run.vl`, `tests/cases/soundness/reseated-record-list-same-layout-runs.vl` · found by the #3235 review · filed 2026-09-27 against master `1f092d569`**

Want:

#### Mechanism

D2881 builds `il` at `I`'s row, which its declared destination names, but the checker still
types `il` and its elements `{ f: i32 }`. Some uses read the storage where it is: a field read,
`.length`, `.push`, a `for` over it, a return or `if` join that keeps the list's type, and a
delivery into a record of `I`'s layout. Every other use hands an `I` record to a place built
for `{ f: i32 }`: a call argument or annotated binding of the list or an element
(`show(il[0])`, `takeN(il)`, `first(il)`), another method call (`il.map`, `il.filter`), a
spread, a list literal around it, an inferred return from the function that binds it, and an
assignment into a `{ f: i32 }` binding. A record is shared, not converted (DECISIONS.md "Record
depth covariance"), so no copy can serve those uses without losing a write through the other
handle. Making them run needs either a per-value rep that follows the storage into every such
use, or a ruling that a re-seated list's own binding takes the destination's type. Until then
the emitter refuses the first such use loudly (`rsNarrowUseRefuse`). It reads a use index built
once per program: each node's parent, and each identifier chained to the next one of the same
name, program-wide and within its function, so a list bound in a function reads only that
function's and its nested functions' identifiers. It follows un-annotated aliases and `for` variables, and treats a function, `for` or
block binding of the same name as a rebinding. It does not fire where the two records share a
layout. It does not follow a value into a caller's hands ([D2922](D2922.md)), has no scope for a
top-level block's binding ([D2923](D2923.md)), leaves a record literal's field alone
([D2924](D2924.md)), and allows an `if` join with a list of another record
([D2925](D2925.md)).

#### Record covariance (2026-09-30)

The destination stores a numeric field at another width or kind, so under the record-covariance ruling the literal-holding binding or function is not adopted and the program keeps its master behaviour until the owner rules on [D3339](D3339.md) (DECISIONS.md "Record covariance: only a fresh value widens").
