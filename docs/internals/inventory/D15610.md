### D15610 — [CLOSED 2026-11-09] two different hole functions joined in a list literal handed to a callee that calls an element at two types are taken as values with no signature

**closed 2026-11-09, runs and prints `7` then `u` · was loud emit reject, clause 2, `vl check` rc 0, then `emitProgram: a generic function taken as a value reaches no call that fixes its type — annotate the destination's function type` · filed 2026-11-09 against master `d4901c70` · closed in the late tag decision (check_fn_tag.vl): the plan of a set a parameter's calls go through notes, for decision with it, each smaller set a caller hands a parameter that is handed on to that one (`ftFwdInSubsets`, over the new reverse forward index `mintParamFwdInsOf`), and a hand of such a set is taken where the parameter forwards to a wider set being decided with it (`ftLateParamOk`); the join dispatches by tag, `runTwo` takes `(i32 i32)` and the module has no `call_indirect` · fixture `functions/hole-params-joined-in-list-literal.vl` · a hole beside a function named directly in the literal (`[g, id]`) still refuses**

Repro:

    function id(v) { return v }
    function dbl(v) { return v + v }
    function call1(fs, x) { print(fs[1](x)) }
    function runTwo(g, h) {
      call1([g, h], 7)
      call1([g, h], "u")
    }
    runTwo(dbl, id)

Want:

    7
    u

#### Mechanism

Each hole forwards to `call1`'s list parameter, whose calls go through the joined set `{dbl, id}`.
That set's plan had no leaf for either member and no smaller set to borrow one from, and `{dbl}`
and `{id}` were never tried, since nothing calls through `g` or `h`.
