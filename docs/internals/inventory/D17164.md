### D17164 — the IR misses a two-signature bundle held in a module record's field and read as a value

**closed 2026-11-24 by lane IR-N2 · runs, `5 2.5`, matched in mode 6 · `exprTyOf` types an open-typed read of a module binding whose cell is a closed record at that cell's type (`globalCellRecordTy`, the module twin of `storedVarOf`), and `builtRecvTy` asks it for a name receiver · fixture `tests/cases/closures/bundle-field-of-a-module-record-read-as-a-value.vl`, shadow row `tests/ir-shadow-rows/bundle-field-of-a-module-record-read-as-a-value.vl` · was an IR coverage defect (runs under legacy) · filed 2026-11-24 against master `aef0be317` by lane IR-N2 (census class `start: field read coercion`, family B, 5 cells) · four of the five cells then stop at pre-existing misses the field read hid: [D17172](D17172.md) (`method f`) and [D17173](D17173.md) (`global read coercion`)**

Repro:

    function lap(f) {
      f(2.5)
      f(3)
      return f
    }
    const w = { f: lap((a) => a + 1) }
    const v = w.f
    print(v(4))
    print(v(1.5))
    // VL_IR_SHADOW=1 vl build: `start uncovered field read coercion` (kid rep closure → record)

Want:

    5
    2.5

#### Mechanism

`buildMember` (`ir_build_ref.vl`) declines a plain struct field read when the field's kid rep is
not the read's rep: here the kid is a closure and the read is the bundle's record (measured with
a probe build naming both reps). Legacy builds the read; which decision gives it the record rep is
the fix's to establish.

#### Ablation

| ingredient changed | outcome | needed? |
| --- | --- | --- |

| `w.f(4)` and `w.f(1.5)` called directly, no copy | covered | **yes**, a value read |
| `take(o.f)`, the read handed to a function | still `field read coercion` | no |
| `v` never called | still `field read coercion` | no |
| the same lines in a function body | covered | **yes**, module scope |
