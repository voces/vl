### D15015 — a `let` of functions written one returning nothing and one returning a value traps when called

**loads then traps · `vl check` rc 0 · `vl run`: `wasm trap: indirect call type mismatch` · clause 1 · the void-result twin of [D9003](D9003.md), found re-minimising the split plan's W-named census group (W-split) · filed 2026-11-02 against master `a29c90e7`**

Repro:

    function inner(u) { print(u) }
    function retV(v) { v }
    let m = retV
    m = inner
    m(7)
    // vl check: rc 0.  vl run: wasm trap: indirect call type mismatch

Want:

    7

#### Mechanism

D9003's `holeLetWritesDisagree` compares the results of the functions written to one `let` at
the types it is called at, and refuses a write whose result differs. A function whose body
returns nothing is not compared against one that returns a value, so the write is accepted
and the call through the binding is lowered at the seed's signature while the slot holds the
written function. The generic spelling traps the same way when the seed returns a value; seeded
with the function that returns nothing, it runs.

#### Ablation

| ingredient removed | outcome | needed? |
| --- | --- | --- |
| the write `m = inner` | runs, prints nothing | **yes** |
| the order (`let m = inner; m = retV`) | same trap | no |
| the holes (`inner<U>(u: U)`, `retV<V>(v: V): V`) | same trap | no |
| the holes and the order (`let m = inner; m = retV`, generic) | runs, prints nothing | **yes** |
| the call at a second type (`m("t")` after `m(7)`) | same trap | no |

#### Grading list

Whether a statement-position call through a written set whose members disagree on void
against a value is refused at the write or dispatches is a ruling question (W-split); either
close must make the generic spelling and this one agree.
