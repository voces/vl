### D5611 — a generic handed to an un-annotated parameter that is called at two signatures has no single instance

**loud emit reject · `vl check` rc 0 · clause 2 · found closing [D5402](D5402.md) · filed 2026-10-17 against master `7fe51e77c`, re-graded on the merged pin driver against master `5aa033e26`**

Repro:

    function same<T>(k: T): T { k }
    function take(a) {
      print(a("x"))
    }
    function take2(a) {
      print(a(3))
    }
    function mid(a) {
      take(a)
      take2(a)
    }
    mid(same)
    // vl check: rc 0.  vl run: emitProgram: a function-value call has no interned signature — the callee has no function type to key a signature from

Want:

    x
    3

#### Mechanism

From the ablation only. A function value carries one signature, and `mid`'s hole is reached by
pins at two: `(string) => string` and `(i32) => i32`. The pin driver `monoHoleGenFnPin` takes
the flow table's pin only when the argument's read has exactly one closed pin (D5612's close).
With two it declines, and the forwarded value stays open. Closing this needs either the hole
instanced once per pin (one `mid` per signature) or the program refused at `vl check`. That is a
rank-2 question, not a gap in the driver.

Re-graded after [D5751](D5751.md)'s close, unchanged. That close gives a const hole lambda one
flow walk per call, which a hole function like `mid` already had. It does not reach this row:
the one `mid(same)` call still reaches two closed pins.
