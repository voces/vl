**closed 2026-10-25 by lane L1 · runs, prints `1` · built, not refused: the substituted parameter annotation was spelled `i32|null[][]`, a union whose last member is a list, because `monoSubstAnn`'s `[]`-run arm (emit_base.vl) re-attached the run to a union leaf bare; the first `[]` now goes through `arrElemSuffixed`, which groups it, so the instance's `T[][]` is `(i32|null)[][]` · closed with [D13061](D13061.md), the same misspelling at a declared result · pins: `tests/cases/generics/declared-nested-list-result-at-union-pin.vl` · was a loud emit reject, clause 2, `` `.length` receiver's ref-list element does not resolve `` · found closing [D3154](D3154.md), whose grid's `arg` body hands a nested literal to such a parameter · the same on master `0adbf4b86` · filed 2026-10-25 against master `0adbf4b86`**

Repro:

    function n<T>(l: T[][]): i32 { return l.length }
    const v: i32 | null = 4

#### Mechanism

Measured with a probe on the refusal: inside the instance, `l` records `T[][]`, and
`instanceTyOf` returns -1 for it because the instance has no pin-binding row
(`monoPinSubRow` holds no entry for it). The program has interned a row for `(i32 | null)[]`.
The parameter just never reaches it. The binder (`monoBindCols` and `bindGenWalk`,
emit_mono.vl) was not the step: the instance's parameter annotation is synthesized from
`monoSubstAnn("T[][]")`, which spelled it `i32|null[][]`, a union whose last member is a list,
and grouping that spelling ([D13061](D13061.md)'s close, emit_base.vl) is the only change that
made this witness run.
