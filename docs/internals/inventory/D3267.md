### D3267 — a join of a literal-union parameter, a boolean parameter and a `null` arm prints the wrong arm

**check-clean silently wrong · clause 1 · open · the same on master `569caa36c` · found by the #3297 round-2 review (`q4.vl`) · filed 2026-09-29**

Repro:

    type K = "a" | "b"
    function g<T, U>(a: T, b: U, k: i32) {
      const r = if k == 0 { a } else if k == 1 { b } else { null }
      return r
    }
    const x: K = "a"
    const y: boolean = true
    print(g(x, y, 0))
    print(g(x, y, 1))
    print(g(x, y, 2))
    // today it prints a b b

Want:

    a
    true
    null

#### Mechanism

Not localised past the ablation. At `T := K`, `U := boolean` the join `K | boolean | null` is
lowered as the atom niche of `K`, so the boolean arm reads as the atom `1` (`b`) and the null
arm as a stale atom. The direct spelling is refused at emit (`literal-union string widening
with no members`), so no running twin exists either.

#### Ablation

| --- | --- | --- |
| `function g(a: K, b: boolean, …)`, the direct spelling | emit reject | the right answer waits on the emitter |
| the `null` arm replaced by `a` | prints `a b a` (the boolean arm still wrong) | no (the `null` arm) |
