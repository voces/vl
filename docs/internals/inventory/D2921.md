### D2921 — a `boolean | null` read inside a hole function off a list or a lambda prints its sentinel

**check-clean silently wrong · clause 1 · open · found by the #3237 review grids (`litIdx`, `litMap`, `litFilter`, `recFn`, `lamRetList` at `boolean | null`) · the same on master `a41bd80e8` · filed 2026-09-27 against master `a41bd80e8`**

Repro:

    function F(x) {
      const xs = [x]
      print(xs[0])
    }
    const n: boolean | null = null
    F(n)
    // vl check: rc 0.  vl run: prints `true`

Want:

    null

#### Mechanism

Not localised. `boolean | null` is an `i32` niche (0, 1, and 2 for null). The read off the
hole list literal is typed at the hole's variable, so `print` takes the plain boolean or `i32`
path and prints the sentinel as `true`, `1` or `2`. `print(x)` directly prints `null`.

#### Ablation

| ingredient changed | outcome | needed? |
| --- | --- | --- |
| `print(x)` without the list | runs, `null` | **yes** |
| the value `true` | runs, `true` | **yes** (a null, or `false` through `.map`) |
| `[x].map((e) => e)` with `false` | prints `0` | no |
