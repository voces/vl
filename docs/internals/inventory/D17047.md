### D17047 — a hole parameter whose field is read is declared at the literal's own row while its result, delivered wider, is declared at the destination's row, and the parameter is returned unconverted

**check-clean invalid wasm · `vl build`: the emitted module failed to validate inside `g` · filed 2026-11-22 against master `682638c55`**

Repro:

    type A = { d: i32 | null }
    function g(v) {
      print(v.d)
      return v
    }
    const c: A = g({ d: 5 })
    print(c.d ?? -1)
    // vl check: rc 0.  vl build: the emitted module failed to validate inside `g`: type
    // mismatch: expected (ref $0), found (ref $1); $0 is `A`, $1 is `#anon1` struct {mut i32}

Want:

    5
    5

#### Mechanism

`g` is a hole function, and its instance is declared by delivery. The result goes to
`c: A`, so legacy declares the result at A's row (`(result (ref $0))`). The parameter's field
read `v.d` keeps the parameter at the literal's own row (`(param $0 (ref $1))`, `{d: i32}`).
`return v` then hands the `$1` parameter to the `$0` result with no conversion. Without the
field read, legacy declares the parameter, its local and the result all at A, and the program
runs.

#### Ablation

| ingredient removed | outcome | needed? |
| --- | --- | --- |
| the field read `v.d` (body is `return v`) | runs, prints 5 | **yes** |
| the `: A` on `c` | runs, prints 5 5 | **yes** |
| returning `v` (body returns `1`, `c: i32`) | runs, prints 5 1 | **yes** |
| the parameter's hole (`v: A`) | runs, prints 5 5 | **yes** |
| `print` around the read (`const x = v.d`) | still fails to validate | no |

#### Grading list

The no-field-read control (`function g(v) { return v }`) runs today and must keep running; it is
the D15180 instance-signature witness the IR builds at A's row.
