### D3072 — a generic callback taker given a union element and an un-annotated `is` lambda has no interned signature

**loud emit reject · clause 2 · found by the #3266 review · an annotated lambda fails validation instead · the same on master `b09566e16` · filed 2026-09-28 against master `b09566e16`**

Repro:

    function app<T>(x: T, f: (T) => boolean): boolean { return f(x) }
    const z: (string | i64 | boolean)[] = [5, "t", true]
    let c = 0
    for e in z {
      if !(e is boolean) {
        if app(e, (w) => w is i64) { c = c + 1 }
      }
    }
    print(c)
    // vl check: rc 0.  vl build: emitProgram: a function-value call has no interned signature
    // — no function value of type `(i32)=>boolean` reaches this call to intern its signature

Want:

    1

#### Mechanism

Not investigated past the ablation. The instance of `app` is keyed with `T` as `i32`, not the
element union, so its `f(x)` asks for a `(i32)=>boolean` signature the lambda never interns.
Annotating the lambda `(w: string | i64)` moves it from the refusal to invalid wasm (`expected
i32, found (ref $type)` at the call), so the argument side is pinned to the box while the
instance takes an `i32`: the same wrong pin as [D3071](D3071.md), at a generic's hole.

#### Ablation

| ingredient changed | outcome | needed? |
| --- | --- | --- |
| no narrowing (`e` still `string \| i64 \| boolean`) | same refusal | no |
| annotate the lambda `(w: string \| i64)` | check-clean invalid wasm | no (a worse face) |

#### Grading list

Both faces of the lambda, the narrowed and un-narrowed element, and a record-union element.
