### D13963 — a `let` holding a generic call's kept-apart list join, reassigned to the parameter's list, stores the wrong list rep at an `i32` pin

**check-clean invalid wasm · open · clause 1 · found beside the Step 6 container-family PR, a sibling of D4862 · filed 2026-10-26 against master `e769fa165`**

Repro:

    function w3<T>(t: T, k: i32, q: (i32 | null)[]) {
      if k == 0 { return [1, 2] }
      if k == 1 { return q }
      [t]
    }
    function g3<T>(t: T, k: i32, q: (i32 | null)[]) {
      let v = w3(t, k, q)
      if k == 2 { v = [t, t, t, t] }
      print(v.length)
    }
    const q3: (i32 | null)[] = [5, null, 6]
    g3(3, 1, q3)
    g3(3, 2, q3)
    // vl check: rc 0.  vl run: invalid module inside `g3` (expected the `i32` list, found `(i32|null)[]`)

Want:

    3
    4

#### Mechanism

Not yet ablated past the table below. At `T := i32` the call `w3(t, k, q)` returns one rep,
`(i32 | null)[]`, but `v`'s cell is a union box of that list and the `i32` list `[t, t, t, t]`
builds, so the assignment and the stored value disagree about which list the cell holds. The
read `v.length` is typed by the checker as `(i32 | null)[]`, and since the Step 6 container
family it unboxes at that type. That unbox is right only while every value reaching the cell
is that one rep.

#### Ablation

| ingredient changed | outcome | needed? |
| --- | --- | --- |

| the `[1, 2]` literal arm removed from `w3` | the same invalid wasm | no |
| the reassignment removed (`const v`) | runs (the D4862 fixture's `g3`) | **yes** |

#### Grading list

Re-grade the container unbox verdict (`identReadContainerAt`) on this witness the day the cell
can hold the other list rep: a read that unboxes to `(i32 | null)[]` with an `i32` list in the
box is a silent wrong value, not a validation failure. Also
`tests/cases/generics/type-param-list-join-concrete-list-apart.vl` and
`tests/cases/unions/narrowed-container-read-unboxes-at-checker-type.vl`, and D13964.
