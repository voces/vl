### D3427 — a radix shift count with its top bit set reads as a negative `i32` and escapes D2710's refusal

**closed 2026-09-30 — now a loud check reject (`shift count 0x80000000 is out of range for an i32 operand (0 to 31)`), a radix count graded at its full value · fixture `tests/cases/bitwise/error-shift-count-constant.vl` · was check-clean silently wrong · clause 1 · found by the exact-constant grid's shift-count column · filed 2026-09-30 against master `5e277ab52`**

Repro:

    function f(x: i32): i32 { x << 0x80000000 }
    print(f(1))
    // PRINTS 1

#### Mechanism

`checkShiftCounts` refused a count when `parseI32(lex) >= w`. A radix lexeme of 32 bits is a bit
pattern, so `parseI32("0x80000000")` is `-2147483648`, below every width, and the count went to wasm,
which takes it modulo 32 (0). The count is now compared at its full value: a radix count wider than
six bits is out of range for every width.

#### Ablation

| spelling | master | now |
| --- | --- | --- |
| `x << 0x80000000` | `1` | refused |
| `x << 0xFFFF00FF` | runs, count modulo 32 | refused |
| `x << 0x1F` | `-2147483648` | same |
