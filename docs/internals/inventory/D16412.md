### D16412 — an un-annotated function handed to a generic's function-typed parameter that no other argument binds is refused at monomorphization

**loud emit reject · clause 2 · open · `vl check` rc 0 · `emitProgram: monomorphize: unsupported argument type for `f` in a call to `sel`` · found by the independent oracle's higher-order generator (`scripts/oracle/gen_hof.ts`, cases 8, 12 and 13) · filed 2026-11-15 against master `33ef972d7`**

Repro:

    function hinc(x) { x + 1 }
    function sel<A>(f: (x: A) => A): (x: A) => A { f }
    print(sel(hinc)(1))
    // vl check: rc 0.  vl run: emit error, monomorphize: unsupported argument type for `f` in a call to `sel`

Want:

    2

#### Mechanism

`hinc` has a hole parameter, so its type at `sel`'s `(x: A) => A` is open in `A` and
nothing else at the call binds `A`; mono has no argument type to key `sel`'s instance on.
Unlike [D16411](D16411.md) the refusal comes at `i32` too. From the ablation. [D14888](D14888.md)
is the same message through a hole identity inside a generic.
