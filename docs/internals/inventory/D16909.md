### D16909 — a lambda whose record result has a list-or-boolean field beside a nullable map field written `null` has no type for the union field at emit

**closed 2026-11-17 by lane SLOT — the witness prints `false` · a record literal's field whose code becomes a union only at its storage type (a list value typed at its own arm, filling a list-or-boolean field) is boxed at that storage type: its union type and box name are read after `anonFieldCodeOfStore` (`emit_collect.vl`), where before they were read off the value's own type, which names no union box · fixture `tests/cases/records/lambda-record-list-arm-of-union-beside-null-map-field.vl` (the fuzz case's three-field `makeIt()` spelling, the `\| null` variant, narrowing reads) · was loud emit reject `emitProgram: a record literal's union field has no type` · clause 2 · `vl check` rc 0 · found by the rep fuzzer's multiobs leg, seed 81922145 cases 399 and 400 · filed 2026-11-16 against master `6cd505a50`**

#### Mechanism

The record mint (`emit_collect.vl`) read a union field's box type and name off the value's own
type before `anonFieldCodeOfStore` re-derived the field's code from its storage type. Here the
value `[1.5]` is typed `f32[]`, an arm, and only the store makes the field a union, so the box had
no type. The other spellings in the ablation type the value at the union itself.
