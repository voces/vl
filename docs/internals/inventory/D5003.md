### D5003 — an un-annotated binding of a type-parameter list in its `is K[]` arm binds the arm's list, and a push through it is lost

**closed · now a loud check reject · was check-clean silently wrong, clause 1 · owner ruling (c) (D4928) applied at the instance: a list that passes `is K[]` only by an empty list's value fit is never delivered as `K[]` where it can be written or kept, and its read-only uses stay legal (`narConvListDeliveryErr`, check_narrow_flow.vl, read by `assignableExprIn` and an un-annotated binding; the instance's arm is live, `isListFitsWhenEmpty`, check_operators.vl) · pins `soundness/list-value-fit-instance-delivery-reject.vl` and `soundness/list-value-fit-instance-read-only.vl` · DECISIONS §"A value-fit list is not delivered at an instance" · filed 2026-10-15 against master `2f625f31e`**

Repro:

    function t<V>(a: V[]) {
      if a is f64[] {
        const z = a
        z.push(1.5)
      }
      print(a.length)
    }
    const e: i32[] = []
    t(e)
    // PRINTS 0

Want:

    a check error at `const z = a` at the `V = i32` instance, naming the copy: the binding would keep a fresh `f64[]` the caller's list does not see

#### Mechanism

`const z = a` takes the narrowed read's type, so `z` is bound as `f64[]`, which the
list-narrowing ruling says a narrowed list is never delivered as; at the `V = i32` instance
the empty list fits the test (D4771) and `z` is the arm's own empty `f64[]`, not the caller's
list. An `a.push(1.5)` in the arm reaches the receiver (D4934) and prints `1`. The instance
refuses the binding, as ruling (c) refuses any delivery of a narrowed list.

#### Ablation

| change | outcome | needed? |
| --- | --- | --- |
| `a.push(1.5)` for the binding and its push | prints `1` | **yes** |
| `const f: f64[] = []` and `t(f)` | prints `1` | **yes** |
