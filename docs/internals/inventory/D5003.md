### D5003 — an un-annotated binding of a type-parameter list in its `is K[]` arm binds the arm's list, and a push through it is lost

**check-clean silently wrong · clause 1 · the binding face of [D4963](D4963.md) · related to [D4934](D4934.md) (a push in the arm reaches the receiver) and [D4981](D4981.md) (the bare-`V` face) · filed 2026-10-15 against master `2f625f31e`**

Repro:

    function t<V>(a: V[]) {
      if a is f64[] {
        const z = a
        z.push(1.5)
      }
      print(a.length)
    }
    const e: i32[] = []
    t(e)
    // PRINTS 0

#### Mechanism

`const z = a` takes the narrowed read's type, so `z` is bound as `f64[]`, which the
list-narrowing ruling says a narrowed list is never delivered as; at the `V = i32` instance
the empty list fits the test (D4771) and `z` is the arm's own empty `f64[]`, not the caller's
list. An `a.push(1.5)` in the arm reaches the receiver (D4934) and prints `1`. Whether `z`
should bind `V[]` (refusing the push) or alias the receiver is not settled, so this row has
no `Want:`.

#### Ablation

| change | outcome | needed? |
| --- | --- | --- |
| `a.push(1.5)` for the binding and its push | prints `1` | **yes** |
| `const f: f64[] = []` and `t(f)` | prints `1` | **yes** |
