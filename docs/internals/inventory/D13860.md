### D13860 — a hole function parameter handed on to a generic at two types is refused at emit

**loud emit reject · `vl check` rc 0 · `emitProgram: cannot take the generic function `add` as a value — a function value carries ONE signature` · clause 2 · CAPABILITY: the enclosing function calling the parameter itself at both types runs, and so does handing `add` itself to the callee at both types · found by lane L1 closing [D13720](D13720.md) · present on master `0efe9c8bf` · filed 2026-10-25 against master `0efe9c8bf`**

Repro:

    function add(a, b) { return a + b }
    function apply2(g, s) { print(g(s, s)) }
    function outer(h) {
      apply2(h, 1.5)
      apply2(h, 4)
    }
    outer(add)
    // vl check: rc 0.  vl run: emitProgram: cannot take the generic function `add` as a value

Want:

    3
    8

#### Mechanism

Not traced past the ablation. `outer`'s two calls ask `h` for two signatures,
`(f64, f64) => f64` and `(i32, i32) => i32`. The argument `add` is pinned at the first, or at
neither, but never split into one copy of `outer` per signature. A direct `add` handed to
`apply2` at both types does get two pins. [D12231](D12231.md) is the same refusal reached
through a list element rather than a parameter. The lambda spelling, `const run = (x) => {
apply2(h, x) }` called as `run(1.5)` and `run(4)`, refuses the same way.

#### Ablation

| spelling | outcome | needed? |
| --- | --- | --- |
| the witness | loud emit reject | — |
| `apply2(h, 1.5)` alone | runs, prints `3` | **yes**: the second type |

| `apply2(add, 1.5)` and `apply2(add, 4)` at module scope | runs, prints `3` and `8` | **yes**: the parameter |

| the lambda `(x) => { apply2(h, x) }` called at `1.5` and `4` | loud emit reject, same sentence | no |
