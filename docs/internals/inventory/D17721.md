### D17721 — two calls of a hole-parameter maker, at two function types, join through one record shape, so one function is checked at the other's argument

**loud check reject · `vl check` rc 2 · `operator '+' is not defined for string and i32` · clause 2, a false rejection · filed 2026-11-27 against master `d91286336` by I8-PREP, from COV-UNION's report (two makers returning `{ r: { f } }`)**

Repro:

    function inc0(a) { return a + 1 }
    function mk2(f) { return { f: f } }
    print(mk2(inc0).f(3))
    function ex(s: string): string { return s + "!" }
    print(mk2(ex).f("hi"))
    // vl check: rc 2, operator '+' is not defined for string and i32 (at `a + 1` in inc0)

Want:

    4
    hi!

#### Mechanism

Each call of the un-annotated maker `mk2` returns a record whose field holds the function it was
handed. The two records share one shape, so the field's function set joins `inc0` and `ex`, and
the call `.f("hi")` checks `inc0`'s hole parameter at `string`. Two distinct makers that return the
same shape (COV-UNION's spelling, `mk2(f)` and `mk3<F>(f: F)` each returning `{ r: { f: f } }`)
join the same way, which makes the rejection depend on an unrelated declaration.
