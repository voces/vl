### D17721 — a call to an un-annotated nested generic whose inferred result mixes the encloser's type parameter with its own is typed at the wrong list, so the module fails to validate

**check-clean invalid wasm · 1 spelling and its relatives · filed 2026-11-27 against master `3b82965f0` by I8-PREP, found reducing D15014's neighbour (`tests/cases/closures/hole-lambda-builds-list-of-encloser-and-own-param.vl`)**

Repro:

    function valued<T>(x: T) {
      function wrap<U>(u: U) { return [x, u] }
      print(wrap("a").length)
    }
    valued(1)
    // vl check: rc 0.  vl run: invalid module inside `valued`: expected `string list`, found `(i32|string)[]`

Want:

    2

#### Mechanism

`wrap`'s instance builds `[x, u]` at `(i32|string)[]`, its bindings `T=i32, U=string` being
right. The call site in `valued` takes the call's value as `string list`: the inferred result
`(T | U)[]` is substituted at the call's own binding of `U` without the encloser instance's `T`.
The instance's body and its caller disagree on the list's row.
