### D10790 — a list mixing a function with an annotated function parameter and a hole function has no instance of the annotated one at a call through it

**loud emit reject · `vl check` rc 0 · clause 2 · CAPABILITY: a neighbouring spelling runs (the ablation) · found closing [D10701](D10701.md) · present on master `d78220c61` · filed 2026-10-23 against master `d78220c61`**

Repro:

    function apply2(g: (a: string, b: i32) => i32) { print(g("x", 2)) }
    function apply3(g) { print(g("y", 20)) }
    function snd(a: string, b: i32) { return b }
    const fs = [apply2, apply3]
    fs[0](snd)
    // vl check: rc 0.  vl run: emitProgram: call to unknown function (at `g(` in apply2)

Want:

    2

#### Mechanism

Untraced. The refusal points into `apply2`'s body at the call of its annotated parameter, so the
element typing that serves a list of hole functions (`monoElemParamTys`, emit_mono.vl) seems to
treat `apply2` as a hole function too and emit it without a callee for `g`.

#### Ablation

| spelling | outcome | needed? |
| --- | --- | --- |
| the witness | loud emit reject | — |
| `apply3` annotated too | runs | **yes**: a hole element beside it |
| `const fs = [apply2]` | runs | **yes**: a hole element beside it |
| `const f = apply2; f(snd)` | runs | **yes**: the list |
| `fs[1](snd)` (the hole element called) | runs | **yes**: the annotated element called |
| `snd` un-annotated, or a lambda `(a, b) => b` | loud emit reject | no |
| `for f in fs { f(snd) }` | loud emit reject | no |

#### Grading list

The `for` spelling above, and the lambda argument.
