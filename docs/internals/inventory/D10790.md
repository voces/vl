### D10790 — a list mixing a function with an annotated function parameter and a hole function has no instance of the annotated one at a call through it

**closed 2026-10-23 by lane L1 · runs, prints `2` · built: a generic function named by a list literal or an `if` value whose type a closed sibling fixed is instanced at that type (`monoCoerceListLitElems` and `monoCoerceIfArms`, emit_mono.vl) · pins: `tests/cases/closures/mixed-annotated-hole-fn-list-*.vl`, `tests/cases/closures/if-joining-annotated-and-hole-fn-called.vl` · residue: an `if` whose then-arm is the hole function is [D10797](D10797.md) · was loud emit reject · `vl check` rc 0 · clause 2 · CAPABILITY: a neighbouring spelling runs (the ablation) · found closing [D10701](D10701.md) · filed 2026-10-23 against master `d78220c61`**

Repro:

    function apply2(g: (a: string, b: i32) => i32) { print(g("x", 2)) }
    function apply3(g) { print(g("y", 20)) }
    function snd(a: string, b: i32) { return b }
    const fs = [apply2, apply3]
    fs[0](snd)
    // vl check: rc 0.  vl run: emitProgram: call to unknown function (at `g(` in apply2)

Want:

    2

#### Mechanism

The refusal is in `apply3`'s body, not `apply2`'s: both bodies open on line 2 at the same
column. The list takes its element type from `apply2`, which is closed, so a call through the
list passes a closed argument and reaches no open-call rung. Nothing instances `apply3`, and it
is emitted as its raw template with `g: _`. A list of hole functions only goes through the
open-call path instead. The fix instances every generic element of a list literal at the
literal's closed element type. The same gap held for an `if` value joining the two functions
with `apply2` first, and the fix instances its generic arm at the `if`'s type.
