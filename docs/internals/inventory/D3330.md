### D3330 — a recursive hole callee over a self-referential record is pinned at the non-null record, so its null base case never runs and the recursion traps

**loads then traps · clause 1 · open · found while filing D3328/D3329 from #3306's review · the same on master `b6378e95b` · filed 2026-09-30 against master `b6378e95b`**

Repro:

    type O = { n: i32, next: O | null }
    function depth(q) {
      if q == null { return 0 }
      return 1 + depth(q.next)
    }
    const o: O = { n: 1, next: { n: 2, next: null } }
    print(depth(o.next))
    // vl check: rc 0.  vl run: wasm trap, null reference (in `depth` at `depth(q.next)`)

Want:

    2

#### Mechanism

Not traced. `o.next` is `O | null` and the call sits at a non-null value, so the instance appears
to be pinned at `O`, where `q == null` is unreachable and `depth(q.next)` hands a possibly-null
field to a non-null parameter; the trap fires when the recursion reaches the last node. The
annotated `depth(q: O | null)` runs and prints `2`. A callee that stops before recursing
(`q.next == null` guard) runs, so it is the null-bearing recursive call that is mishandled.

#### Ablation

| ingredient changed | outcome | needed? |
| --- | --- | --- |
| `depth(q: O \| null)` annotated | runs, `2` | **yes** (a hole parameter) |
| `depth(q): i32` return annotated only | still traps | no |
| called at `depth(o)` instead of `depth(o.next)` | still traps | no |
| the base case `q != null { return 1 + depth(q.next) }` form | still traps | no |
| `q.n + sum(q.next)` in place of `1 + depth(q.next)` | still traps | no |
| no recursion: two hops written out, `q.next == null` tested | runs, `2` | **yes** (the recursive call) |
| `last(q)` recursing only on the non-null branch, no `q == null` | runs, `2` | **yes** (a null-bearing argument) |
| called with a `const e: O \| null = null` | loud emit reject, `unsupported argument type for q` | no |
