### D15569 — a width-generic numeric intrinsic as a value takes its default width, not its destination's

**check reject · filed 2026-11-08 on the D2621 fix branch**

Repro:

    const g: (f32) => f32 = sqrt
    print(g(4.0))
    // vl check: cannot assign (f64) => f64 to 'g' of type (f32) => f32

#### Mechanism

D2621 lifts an intrinsic in value position into a wrapper function built before the checker
runs, so the wrapper's signature cannot read the destination. The numeric intrinsics (`sqrt`,
`abs`, `min`, `clz`, `rotl`, …) are generic over width when called; as a value they take their
family's default, f64 or i32. An f32 or i64 destination is a type mismatch. Wrapping by hand,
`(x: f32) => sqrt(x)`, runs.

#### Grading list

- the repro must print `2`.
- `const h: (i64) => i64 = clz` then `print(h(1 as i64))` must print `63`.
