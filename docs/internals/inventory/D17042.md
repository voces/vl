### D17042 — an order-stashed record literal whose first field is a valued `if`, boxed into a union, leaves the box tag above the `if`'s value

**closed 2026-11-21 by lane IR-N2 · runs today and must keep running, prints `2` · was a claimable function that failed to lower (`unlowered: operand above a valued if's value`), its claim falling back to legacy · the lowering writes the box head ahead of a valued `if` first field (`stashIfBoxHead`) · pin: `tests/ir-shadow-rows/stash-set-record-boxed.vl` · filed 2026-11-21 against master `41144724`**

Repro:

    type A = { a: i32, k: i32 }
    type B = { s: string }
    type U = A | B
    function mk(x: i32, flag: boolean): U {
      return { k: if flag { 2 } else { 3 }, a: x + 1 }
    }
    const u = mk(6, true)
    if u is A { print(u.k) }
    // vl run: prints 2.  VL_IR_SHADOW=1: fail a claimable function did not match

#### Mechanism

The literal is written out of layout order with a valued `if`, so its fields go through the
order stash (`RStashSet`, `mrSet`). Boxed under its own arm, legacy writes the arm's tag first and
then the literal, so the tag sits below the first field's `if`. The builder writes that valued
`if` as a statement ahead of everything the box writes, and the lowering finds the box's tag
operand above the `if`'s value.

| the binding annotated at the record `A` | uncovered, `declaration coercion` | **yes**, the box |
