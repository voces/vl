### D16170 — a shared field read is refused when the records store the field as nullable records of different types

**closed 2026-11-14 — the witness runs and prints `true` · was: loud emit reject · clause 2 · `emitProgram: field access receiver is not a struct` · found closing D16049 (lane F) · filed 2026-11-14 against master `1b5ee5499`**

Repro:

    type X = { a: i32 }
    type Y = { b: string }
    type A = { v: X | null }
    type B = { v: Y | null }
    const b: B = { v: null }
    const u: A | B = b
    print(u.v == null)

Want:

    true

#### Mechanism

Both records store the field at code 15 (a record ref, here nullable), so `sharedUnionFieldPlan`
answers `FC_STRUCT` unmixed. `sharedFieldStructBoxPlan` reads it as the box of the read's union
only when that type is a bare union: `sharedFieldArmStructTag` refuses the read's
`X | Y | null`, and the record arm boxes under its tag with no test for a null ref. With no plan
dispatchable, the read falls to the plain struct read. Underneath, no union row existed for the
read: the collect pass registered a shared read's union only when its type was a bare union
(`nodeTyIsUnionRow`). Closed by registering the union inside the nullable and the nullable itself,
looking a nullable read's arm up in that row (`sharedFieldArmStructTag`), and boxing a nullable
record field under the null tag when its ref is null (`sharedFieldArmNulRecord`), as a
`string | null` field already is.
