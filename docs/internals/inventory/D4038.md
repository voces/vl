### D4038 — a list delivered to a recursive alias with a list arm skips the container-widening refusal

**closed as `now a loud check reject` · the repro refuses with `string[] is not J[] (reached through string[] into J): a container never widens implicitly` · `tyReachesHole` counted a recursive alias's cycle as a hole, so the widening walk declined; a row met again on the path now reaches nothing new · was check-clean silently wrong · clause 1 · diderven DV-1202 · filed 2026-10-11 against master `efd3c3f15`**

Repro:

    type J = null | string | J[]
    const ys: string[] = ["a"]
    const k: J = ys
    print(k is J[])
    // PRINTS false

#### Mechanism

The "no implicit container widening" walk declines on any type that reaches an inference
hole. `tyReachesHole` answered `true` when its depth ran out, and a recursive alias is a
cycle in the arena, so every walk through `J` ran out and `J` read as a hole. The list was
then delivered without its copy: `k is J[]` answers `false`, `const k: J[] = ys` is invalid
wasm, and `std:json`'s `toJson` reports a value that is none of the six JSON types. An
importer's check reached the same store through an alias walk and refused it, blaming
`std:fmt`.

#### Ablation

| ingredient removed | outcome | needed? |
| --- | --- | --- |
| the recursion (`type J = null \| string`, `J \| J[]`) | refuses | **yes** |
| the element difference (`ys: J[]`) | runs, prints true | **yes** |
| the annotation on `ys` | still silent on master | no |
