### D1676 — a standalone `?.` has no rep for an f64 or a nullable-list leaf, and its refusal names a set two of whose members run

**loud emit reject · filed 2026-09-05 against master `a0fa9533c` · found while closing D1670,
whose fix made the call-receiver spelling reach this layer · clause 2: `vl check` returns 0
and the refusal concedes the program is type-valid**

Repro:

    type B = { y: f64 }
    function mk(): B | null { { y: 1.5 } }
    const b = mk()
    const v = b?.y
    print(v == null)
    // vl check: rc 0.  vl run: emit error,
    // emitProgram: a standalone `?.` supports only i32/boolean and string leaf fields
    //   — read it through `?? d` or a `!= null` guard

#### Mechanism

`emitOptMemberValue` builds the `F | null` value of a standalone chain by dispatching on the
result's rep, and it carries arms for the nested-struct niche (code 15), the boxed scalar and
value union (code 16), the `i32 | null` box and the `string | null` niche. A field whose rep
is an f64 (or an i64, an f32) and a field that is itself a nullable list reach neither the
code-15 arm nor the box arms, so the gate above them refuses.

Both faces refuse identically, at every receiver shape — a name, a call, a call through a
function value — so neither inference nor the receiver is an ingredient. `?? d` and a
`!= null` guard both lower these fields, which is what the refusal's own advice says and what
makes this a capability gap rather than a design rule.

**The sentence is wrong about its own set.** It names `i32/boolean and string`, and the
nested-struct leaf (`I | null`) and the value-union leaf (`i32 | string`) run today — the
message predates the arms that serve them. Narrowing the wording is part of the fix, not a
substitute for one.

#### Ablation

One row per leaf type, un-annotated and annotated (`const v: <T> | null = b?.y`):

| leaf field type | un-annotated | annotated |
| --- | --- | --- |
| `i32` | runs | runs |
| `boolean` | runs | runs |
| `string` | runs | runs |
| `f64` | **emit refuses** | **emit refuses** |
| `i32[] \| null` | **emit refuses** | **emit refuses** |
| `I \| null` (nested struct) | runs | runs |
| `i32 \| string` (value union) | runs | runs |

#### Grading list

`?? d` over the same fields runs today (`b?.y ?? 0.0`), so a fix must not move those; and the
refusal's sentence must name only what it still refuses.
