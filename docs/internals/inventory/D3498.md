### D3498 — `print` of a nullable record, list, map or closure narrowed to `null` passes the reference to `__print_i32__`

**closed 2026-10-03 — the witness prints `null` · was check-clean invalid wasm, clause 1 · pre-existing on master · found by #3336's review (the `(Rec, Rec)` pin of its grid, 28 cells) · filed and closed against master `04ec2ef6f` · fixture `tests/cases/unions/print-nullable-ref-narrowed-to-null.vl`**

Repro:

    type Rec = { x: i32 }
    const v: Rec | null = null
    if v is Rec { print(v.x) } else { print(v) }
    // vl check: rc 0.  vl run: invalid module, "expected i32, found (ref null $type)"

Want:

    null

#### Mechanism

The `else` of `v is Rec` narrows `Rec | null` to `null`, which `print` accepts. `Rec | null` is a
nullable reference niche, not a box, and none of `print`'s rungs claims it: the `null`-type rung
(D1576) asks the binding's cell, which is the niche; the narrowed-to-`null` rung (D2801) asks for
a narrowing key, and `is Rec` on a niche pushes none; the niche rungs cover only `string | null`
and `boolean | null`. The argument fell to the scalar tail. A niche whose other arm has no printed
form (a record, a list, a map, a closure) can only print as `null`, so a new rung tests it at run
time (`emitPrintNulRefNiche`): `null` when it is, and a trap when it is not, which a checked
program does not reach. It reads the niche by its rep (`exprNulNicheKind`, `exprNullableMap`), so
it holds whatever narrowed the value there.
