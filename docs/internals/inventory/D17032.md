### D17032 — inside a generic, a record literal built at the union arm that carries the type parameter is not checked against the union, so its literal discriminant widens to `string`

**loud check reject · clause 2, CAPABILITY, the program is type-valid · `return type mismatch: expected {k: "g", v: T} | {k: "h"}, got {k: string, v: T}` · reported by lane STORE (with an `n: i64` field, which is incidental), triaged by lane F2 · filed 2026-11-20 against master `de317fa31`**

Repro:

    type U<T> = { k: "g", v: T } | { k: "h" }
    function mk<T>(x: T): U<T> {
      return { k: "g", v: x }
    }
    const a = mk(3)
    if a.k == "g" { print(1) }
    // vl check: rc 1, return type mismatch: expected {k: "g", v: T} | {k: "h"}, got {k: string, v: T}

Want:

    1

#### Mechanism

The literal's expected type is the generic union `U<T>`, but the arm it is built at holds the open
type parameter, and the literal is typed on its own: `"g"` widens to `string`, and a widened
record matches no arm. Concretely instanced (`U<i32>` in a non-generic function) the literal is
contextually typed at its arm and runs. Where in the checker the expected union is dropped for an
open arm is not yet located.
