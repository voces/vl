### D15082 — a literal field spelled through an alias atom reps at another struct row than the bare literal, though the two are one type

**closed 2026-11-03 · runs, prints `3` then `9` · a one-member literal alias is its literal (`singleAliasMemberTyIx`), so `Ca` and `C` are one type and the union-row adopt guard keys every record atom by type, its literal exception deleted · was a refutation pin (runs today and must keep running) · step 7 struct-row keying · filed 2026-11-03 against master `c327c862`**

Repro:

    type C = { kind: "circle", r: f64 }
    type R = { kind: "rect", w: f64 }
    type S = C | R
    function area(s: S) {
      if s.kind == "circle" { return s.r }
      return 0.0
    }
    type KC = "circle"
    type KR = "rect"
    type Ca = { kind: KC, r: f64 }
    type Ra = { kind: KR, w: f64 }
    function areaA(s: Ca | Ra) {
      if s.kind == "circle" { return s.r }
      return 0.0
    }
    print(area({ kind: "circle", r: 3.0 }))
    print(areaA({ kind: "circle", r: 9.0 }))

Want:

    3
    9

#### Mechanism

`Ca` and `C` are one arena type once `KC` folds, but `collectS` builds them as two struct
rows (the union rows `S` and `Ca | Ra` hold arms at struct rows 0,1 and 2,3). So the union-row
adopt guard keys a record atom by its type only when the record holds no literal
(`utkTyHoldsLit`, D15081), and keeps these two union rows apart by spelling. A union row merged
across them boxes one arm under the other's heap type: built that way, both witnesses below are
invalid modules. The design question this row holds is whether an alias-literal field may rep
apart from the bare literal at all; if not, one member set is one struct row, and the guard's
literal exception goes.
