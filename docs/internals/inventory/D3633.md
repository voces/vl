### D3633 — a module-scope block's local function that captures a string, called from a lambda, refuses its capture

**loud emit reject · clause 2 · open · filed 2026-10-04 by lane LF against master `221c7954f`, from the #3376 review's generator**

Repro:

    const tt = true
    if tt {
      const s = "loc"
      function k() { s + "!" }
      print((() => k())())
    }
    // vl check rc 0; vl run: emitProgram: captured variable not found in enclosing frame at 5:18

Want:

    loc!

#### Mechanism

Not localised past the ablation. The lambda calls `k`, so `capSiblingFrees` folds `k`'s free
names (`s`) into the lambda's captures. `s` is a module-scope block binding, which no frame's
body holds, so the lambda's env cannot find it in its enclosing frame (the start function). An
`i32` capture runs, so the string's rep is in it too. The same on master and after D3608's close.

#### Ablation

| ingredient changed | outcome |
| --- | --- |
| the capture an `i32` (`const c = 40`, `c + 2`) | runs, `42` |
| `k` called directly (`print(k())`) | runs |
| the block inside a function | runs |
| `k` a lambda binding (`const k = () => s + "!"`) | runs |
| the lambda bound first (`const g = () => k()`) | still refuses |
| a bare block `{ … }` instead of `if tt` | still refuses |

#### Grading list

The `i32` capture and the bare-block spelling. A module-scope block's lambda that captures `s`
directly (`print((() => s + "!")())`), to place the fault in the sibling fold or in the capture.
