### D15231 — a nested record result kept at a wider nested record at one delivery and at its own type at another is check-clean invalid wasm

**check-clean invalid wasm · `vl check` rc 0 · clause 1 · open, target `4` · found grading [D15188](D15188.md) · filed 2026-11-04 against master `dc27d0a9` · handed to the destringify lane**

Repro:

    type J = { f: i32 | null }
    type K = { j: J }
    function mk() { { j: { f: 4 } } }
    const k: K = mk()
    const y = mk()
    print(y.j.f)

Want:

    4

#### Mechanism

`mk`'s result is delivered to `K`, whose field `j` stores `f` as `i32 | null`, and is also kept at
its own `{j: {f: i32}}` by `y`. The emitter builds the result one way and hands it to `k`'s
global as the other: `expected (ref null $K), found (ref $#anon)`. The flat twin, one record
level, runs.

#### Ablation

| ingredient removed | outcome | needed? |
| --- | --- | --- |
| the second use `const y = mk()` | runs | **yes** |
| the nesting (`type J` only, `const wideJ: J = mk()` with a flat `mk`) | runs | **yes** |
| the read `print(y.j.f)` (`const xs = [mk()]; print(xs.length)` instead) | still invalid wasm | no |
| `mk`'s declared result `{ j: { f: i32 } }` | loud check reject (design: a declared result is not fresh) | — |
