### D3812 — an un-annotated function whose tail calls a local closure a nested lambda reassigns emits a result with no value

**check-clean invalid wasm · the un-annotated spelling of `closures/capture-mutation-init-kinds.vl`'s `closureLocal`, which D3800's hint asked for · filed 2026-10-07 against master `79190c15d` (lane DH)**

Repro:

    function f(g: (i32) => i32) { g(0) }
    function h() {
      let op = (x: i32) => x + 1
      f((_i) => {
        op = (x: i32) => x + 5
        0
      })
      op(2)
    }
    print(h())
    // vl check: rc 0, `h` inferred as `i32`. vl run: rc 70, invalid module in the top-level
    // code: type mismatch: expected i32 but nothing on stack.

Want:

    7

#### Mechanism

`op` is captured and written by the lambda, so it lives in a cell. The checker infers `h` as `i32`
from the tail call, but the un-annotated function is emitted as returning nothing, and its caller's
`print` finds no value. Annotating `h`, or binding the call first (`const r = op(2)` then `r`),
builds a function that returns `7`.
