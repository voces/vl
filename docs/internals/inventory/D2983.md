### D2983 — a `for`-in loop variable over a hole or `<T>` list at a literal-union pin prints its atom id

**check-clean silently wrong · clause 1 · the LU2 grid's `S_s16` and `E_e5_g` rows, 30 cells · pre-existing on master `4dc94bd23` · filed 2026-09-28 against master `4dc94bd23`**

Repro:

    type AB = "a" | "b"
    function f(x) {
      const l = [x]
      for e in l { print(e) }
    }
    const v: AB = "b"
    f(v)
    // vl check: rc 0.  vl run: prints `0`

Want:

    b

#### Mechanism

Not localised past the ablation. `declareForInLocals` flags a loop variable as the atom from its
iterable's RECORDED element type (`nodeArrayElemIsLitUnion`), and a list built over a hole records
the hole's variable, so the flag is never set and `print` takes the `i32` import. The read
`l[0]` of the same list prints `b`, since [D2942](D2942.md) reads it at the instance's pin.

#### Ablation

The LU2 grid's `S_s16_h`, `S_s16_g` and `E_e5_g` rows (`scratchpad/LU2/gen.py`) at every pin.
