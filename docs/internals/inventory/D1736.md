#### Mechanism

`checkWhileStmtNode` collected the condition's facts like an `if` and then kept only those
whose narrowed type was exactly `nonNullTy(lookup(name))` — a null strip — and the emitter
held `narrowStripNullOnly` across the same push. The restriction was deliberate and its
reason was the WRITE contract, not the loop: a narrowed binding's type was also what it
ACCEPTED, so pinning the body would have refused `x = true`, the flip a loop over a union
terminates by. #2821 built the pin as first ruled and measured that price on working code
(`tests/cases/unions/paren-is-narrow.vl`, a `runs -> not-runs`), which is what sent the
question back.

The owner re-ruled it: **narrowing applies to READS.** A write is checked against the
DECLARED type and re-narrows the binding to the member it wrote, for the reads that follow.
The pin then costs nothing and the filter goes; `narrowStripNullOnly` had no other purpose
and goes with it, leaving `narrowBareIdentOnly` as the loop body's one restriction and the
exact mirror of the checker's `isPathKey` test.
