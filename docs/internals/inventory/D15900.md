#### Mechanism

The argument position runs since `store-b3-held-key`: a literal handed straight to an
un-annotated parameter is decided with the set (`ftHandedRecHolds`), stamped at its own rep, and
the hole is keyed and pinned at the set's id rows. The other positions are not yet traced past
D15338's. The tag plan takes a list literal bound by an annotated binding as
holding closures; one handed elsewhere first is still read as a holder of the set's ids, so
`{id}` stays closures and the calls through `xs` meet one closure at two signatures. A list of
lists of such records, `const zs = [[{ f: id }]]`, is refused the same way: the walk is one list
level deep, since admitting a nested one trapped the compiler in `rlTwinSigOf` (emit_collect.vl).
