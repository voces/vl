#### Mechanism

The tag plan refuses the set in `ftHoldCtxOk` (check_fn_tag.vl): `a`'s list holds the set's ids,
and it is written into `b`, which the record solve built at the closed closure type its one read
at `f64` gives it. A holder has one rep and no converting copy, and a copy is no answer: `b = a`
aliases the list. The literal positions (an argument, a return, a record field, a nested list, a
push, a local reassignment, a map value) run since `ftLitStampedAt` reads the record solve's stamp
on a list literal built at closures. The two left need the per-family rep decision: `a`'s literal,
and the list a called function returns, put at the closure rep from the start because the family
they flow into is built there (coordinator ruling, 2026-11-27).
