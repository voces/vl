### D1645 — two anonymous lambdas at module scope collided as `redeclared ` with a blank name: the hoist filed both under the empty key

**closed 2026-09-05 — the witness runs · was a loud check reject (`[ERROR]: redeclared ` with nothing after it) on a program the design permits · fixed by ruling a nameless `FuncDecl` an EXPRESSION, so the top-level signature hoist skips it and `unused-pure-expression` owns the diagnostic · clause 2 · found beside D1643**

Repro (before: `[ERROR]: redeclared ` and rc 1; now: rc 0 with an `unused-pure-expression`
warning on each discarded lambda, and it prints `7`):

    (x: i32) => x
    (y: i32) => y
    print(7)

#### The rule

**A `FuncDecl` node is a DECLARATION when it has a name and an EXPRESSION when it does not,
and its position does not change that.** A bare lambda statement is the `55` of function
values: it builds a value and discards it.

Read off the two neighbours the question is decided by:

* A NAMED function at the same position binds a name that is reachable from anywhere in the
  module — that is the whole point of hoisting it — and a second one of the same name is
  `redeclared g`, which names something a reader can act on. None of that is true of an
  anonymous lambda: it binds nothing, nothing can call it, and `redeclared ` with a blank
  name names nothing.
* A bare `55` statement checks clean and, when a statement follows it, draws
  `unused-pure-expression`. A lambda literal is pure in exactly the sense that rule means —
  building a closure has no effect, no more than the array literal already on its whitelist.

So the hoist takes only named declarations, `unused-function` (which has no name to report
and no `export` to suggest) declines a nameless one, and `unused-pure-expression` admits it.
The tail exemption comes along for free: a lambda as the final statement is the block's value
and draws nothing, exactly as `55` does.

#### Mechanism

Pass 1 walked every top-level `FuncDecl` and ran `declare(s.fnName, …)`, `fnDeclIx[s.fnName]`
and `declareFnDeclNode(s.fnName, …)` on it. An anonymous lambda's name is `""`, so every one
of them was filed under one key and the second tripped the pass's own redeclaration check —
which then printed `opDeclLabel("")`, the empty string. The same arm banked a pending-return
row under the empty name, which is the read D1643 had to bound-test.

The name-keyed reader is defended at the writer too: `recordInferRet` refuses the empty key,
because a row banked under it would answer for every anonymous lambda at once.

The two named-function controls are the rule's other half and are unmoved: a named
declaration still binds, still warns when unused, and still collides when repeated. The
return annotation moves nothing — the collision is about the NAME, not the signature.
