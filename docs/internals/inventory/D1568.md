### D1568 — the field-WRITE arm never seeded the struct row its construct-side twin does, so `w.f = null` had no rep while `{ f: null }` had one

**closed 2026-09-03 — the witness runs and prints `none` then `7` · was `loud emit reject` (`emitProgram: bare null needs a struct-typed context`, `vl check` rc 0) · clause 2 · fixed by seeding `pendingStructIdx` from `sFieldTgtStructIdx` at `emitAssign`'s code-15 field-write arm, restored in the same reset block as the store's other seeds · left loud by [D1563](D1563.md) (#2497), previously papered over by the leaked seed**

Repro (prints `none` then `7`):

    type C = { a: i32, b: i32 }
    type W = { f: C | null }
    const w: W = { f: { a: 1, b: 2 } }
    w.f = null
    if w.f != null { print(w.f.a) } else { print("none") }
    w.f = { a: 7, b: 8 }
    if w.f != null { print(w.f.a) } else { print("none") }

#### Mechanism

`emitObjField` — the CONSTRUCT half of every struct field code — brackets its value emit with
`const savedPSI = pendingStructIdx` / `if scode == 15 { pendingStructIdx =
sFieldTgtStructIdx(si, fi) }` / restore, so `{ f: null }` over an `f: C | null` field reaches
`emitNullLitNode` with the field's own struct row armed and lowers `ref.null $C`.
`emitAssign`'s field-WRITE arm is the other half of that same code and seeds the map shape
(code 19), the list kind, the niche flags for codes 20/21/30 and the box coercer for code
16 — but never the code-15 struct row. So `w.f = null` arrived with nothing.

**The seed state, printed at `emitNullLitNode` in both faces:** the construct spelling
arrives with `pendingStructIdx = <C's row>`; the store arrives `fnRet=-99 pStruct=-1 pVar=-1
pNulRefHeap=-1` with every niche flag `false` — and `fnRet=-99` is itself the finding, because
the store is at module scope where `fnIx < 0`, so the node's own last-resort arm (the
enclosing function's return annotation) cannot speak either. Both faces of the position refuse
identically, which is what distinguishes this from an annotation-pins-the-rep defect: the
missing seed is the FIELD's, not the binding's.

The `nulvariant` face rides the same fix without an arm of its own. `sFieldTgtStructIdx`'s
arena leg (`sFieldElemTyIxAt` → `structIndexOfTy`) resolves an arm-typed field to the arm's
layout twin ROW, which is the row the construct-side seed already uses — so `w.g = null` over
a `g: Circle | null` field lowers the same heap type the `{ g: null }` spelling does, by
construction rather than by two ladders agreeing.
