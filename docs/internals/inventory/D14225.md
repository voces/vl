### D14225 — a list literal of generic or hole function values has no elaborated type and is built from the destination seed

**runs today and must keep running · 46 FILES of 6,701 `tests/cases` files · filed 2026-10-26 against master `641c18ca1`**

Repro:

    function exclaim(s) { return s + "!" }
    function g(_p) { print(1) }
    g([exclaim])
    g([exclaim, exclaim])
    // vl run: prints 1 twice; the literal's list build comes from the ExpCtx seed alone

Want:

    1
    1

#### Mechanism

`emitArr` builds at `listBuildOfTy(litRepTyAt)`, else at `listBuildOfTy(arrLitDestTy)`, else at
the seed `listKind`/`listSlot` that its destination threaded. When a literal's elements are
generic or hole functions, neither type fact answers. The seed is then the only producer, and
these files are why it cannot be deleted yet. An emitter probe counted 46 files: about 37
closure, generic and function lists, about 6 literal-union lists, and 3 `T[]` in a generic body.
A further 82 untyped literals build correctly on the default seed and are not counted.
