### D6781 — the check skip serves an edit to S whose own narrowing a served module's writer ends, because the S-only check cannot see the writer

**runs today and must keep running · since #10547 a call ends a module binding's narrowing only when a function it may run writes the binding, so `noop()` keeps `g` narrowed under the whole check and the skip alike, and the skip has nothing to serve differently; the skip suite's writer witness is now `lib starts narrowing across a hook a served writer fills` · was a loud check reject, closed by lane S5 declining when a whole-program question S asked has a served statement in its writer closure · clause 1 (skip soundness) · found by lane S5 while ablating the `interface` declines · filed 2026-10-18 against master `1e7bc12cb`**

Repro:

    // file: lib.vl
    export let g: i32 | null = 1
    export function noop(): void { print(1) }
    export function reg(h: () => void): void { h() }

#### Mechanism

A served check merges only S, so `crProgRoot` is S's root, and `crInfoOf` answers "who writes
`g`" from S alone. Main's `w` writes `g` and escapes into `reg`, which makes `noop()` end the
narrowing; the S-only check never saw `w` and kept it. Every whole-program question that walks
the program root has the same blind spot: `crNameAssignedInRoot`, `crNameNulledInProgram`,
`crRootMayKeep`, `crEscapesIn` at the root, and the sole-reference rows.

#### Ablation

| ingredient changed | outcome under the skip | needed? |
| --- | --- | --- |
| `w` writes a local instead of `g` | serves, and the whole check agrees | **yes**, a served writer |
| `reg(w)` removed from main | serves, and the whole check agrees | **yes**, the writer escapes |
| `noop()` removed from `f` | serves, and the whole check agrees | **yes**, a call inside the narrowing |
