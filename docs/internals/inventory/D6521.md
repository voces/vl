### D6521 — a second call of a hole function with the same generic re-checks its body at the first call's argument types

**closed — runs, `x 4 x 4` — fixed 2026-10-18 by lane L3, CAPABILITY: a hole call's derived result carries its call, and a hole bound to the open signature of a declared generic reads that result at the call's own argument types (`holeCallRetAt`, `check_relate_core.vl`), so no residue typed at the first call's instance is left for the second to adjudicate · was loud check reject, clause 2 · pins: `tests/cases/functions/generic-fn-value-hole-second-call-own-types.vl` (the witness, two different generics, three calls, `a(a(3))`, a two-parameter generic, `const`-bound results), `tests/cases/functions/error-hole-call-second-generic-own-types.vl` (a second generic whose own result misfits still refuses) · the `T[]`-parameter control is filed as [D6540](D6540.md) · found closing [D6470](D6470.md) · filed 2026-10-18 against master `d9c8431e5`**

Repro:

    function same<T>(k: T): T { k }
    function viaResult(a) {
      print(a("x"))
      print(a(3) + 1)
    }
    viaResult(same)
    viaResult(same)
    // vl check: rc 1, 7:11 operator '+' is not defined for string and i32 (the call's argument types)

Want:

    x
    4
    x
    4

#### Mechanism

Measured on a probe build. At the first `viaResult(same)` the body's two calls disagree, so
`a` stays bound to the open signature `(T) => T`. The `+` over `a(3)` is replayed with
`a(3)`'s result resolved through that signature to `same`'s own `T`. That still holds a type
variable, so a residue `T + i32` is re-recorded at module scope. The second call then judges
the instance `(string) => string` non-strictly, takes that residue with `T = string`, and
refuses at the argument `same` (7:11). The residue matches `T` by name, which is why two
different generics refuse too.
