#### Mechanism

The instance's join now keeps `string[]`, `boolean[]` and `K[]` as three members, as the
non-generic spelling does. Lane JW's lowering for a join of lists holding a literal-union
element beside another list (emit_mono.vl) refuses it, as it already refused the `string[]`,
`string[]`, `K[]` and two-parameter spellings. Before D14083's fix the `K[]` was folded into
the `string[]` member and handed back empty, so the refusal never fired.

Located 2026-10-31. Removing the refusal (`monoTpJoinBindAnn`, `monoInitListsLitMixed`'s site)
prints a wrong `0` and traps on an index, so the refusal guards a real miscompile. `i32[]` or
`boolean[]` beside `K[]` runs right at the instance either way, so only `string[]` beside a
literal-union list collides. The template's list-union rewrite is built over `T0[] | T2[]`, and
its tests stay structural for type-parameter arms (D4917). The instance's pinned union box does
not keep `string[]` and `K[]` on separate tags, so no test can tell them apart. The fix is the
pinned union (`monoPinUnionNameOfTy`/`monoRegisterPinUnion`) keeping the literal list's own tag,
as the non-generic box does (D4906), with D4917's tag dispatch then widened to those arms.
