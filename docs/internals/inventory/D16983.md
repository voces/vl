### D16983 — an empty list stored as a record field takes the unbound default after a typed read of its element was already checked

**closed 2026-11-18 — the witness prints `0` · was check-clean invalid wasm, clause 1 · census row 10 of the no-default ruling (DECISIONS.md §"No default type") · one producer, `pinOpenReadFromDest` (`check_narrow_flow.vl`): a read of an open list element delivered whole to a closed destination type (an annotated `let`, a typed assignment target) pins the element to that type, so no unbound default settles it and a later use that disagrees is refused at check · fixture `tests/cases/inference/empty-list-element-fixed-by-a-typed-read.vl`, with `error-empty-list-element-fixed-two-ways.vl` and `error-empty-list-element-read-then-pushed-another-type.vl` for the contradictory uses · filed 2026-11-18 against master `ab08356f1` by lane F1**

Repro:

    const r = { xs: [] }
    if r.xs.length > 0 { const s: string = r.xs[0]; print(s) }
    print(r.xs.length)
    // vl check: rc 0.  vl run: invalid module, expected string, found i32

Want:

    0

#### Mechanism

The field's empty literal is an open hole until `objFieldHolesToI32` (`check_narrow_flow.vl`) settles
it at the unbound default `i32`, after the statements are checked. The read `r.xs[0]` into a
`string` was checked against the open hole and is not checked again, so the emitter builds an
`i32[]` and reads a string out of it. Under the ruling the typed read is a use that fixes the
element: `string[]`.

#### Ablation

| ingredient changed | outcome | needed? |
| --- | --- | --- |
| the read typed `i32` | runs, prints `0` | **yes** (a type other than the default) |
| the read untyped, `print(r.xs[0])` | runs | **yes** (the typed destination) |
| a plain binding `const xs = []` in place of the field | refused at check, `cannot assign i32` | **yes** (the field: a binding's default lands before the read) |
| a push of `"a"` before the read | runs, prints `a` | **yes** (no write fixes it) |
