### D14081 — a generic's record literal bound to a `const` is built at its literal row and handed to a generic's `{v: T | null}` parameter unconverted

**closed · runs, prints `7` · was check-clean invalid wasm, `expected (ref $0), found (ref $1); $0 is {v:i32|null} …; $1 is {v:i32}` · closed in check_rec_rows.vl: record adoption decides a generic body's literal at its template types, stored apart at some pin, and pins it as a parsed annotation, so each instance builds `r` at `{v: U | null}` and passes it without a copy · test `tests/cases/generics/record-literal-adopts-generic-template-destination.vl` · filed 2026-10-26 against master `2f8428da3`**

Repro:

    function len<T>(r: {v: T | null}) {
      7
    }
    function outer<U>(x: U) {
      const r = {v: x}
      print(len(r))
    }
    outer(5)
    // vl check: rc 0.  vl run: invalid module inside outer, expected {v:i32|null}, found {v:i32}

Want:

    7

#### Mechanism

Not traced. The `const r` in the instance at `U = i32` is built as the struct `{v: i32}` and
passed where `len`'s instance takes `{v: i32 | null}`, with no conversion. It is a
generic-instance issue, not the per-node choice of anonymous-record storage: the same binding in
a function whose parameter is `x: i32` runs, and so does the same code at top level.

#### Ablation
