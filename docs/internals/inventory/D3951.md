### D3951 — a capture cell seeded with a hole lambda and written with a generic function traps when called

**closed 2026-10-10 by lane SC · runs · was loads then traps · pins: `tests/cases/closures/captured-cell-hole-lambda-seed-written-with-generic.vl` · found in review of #3498 (`rv3498/p17`) · filed 2026-10-10 against master `429e7b093`**

Repro:

    function other<V>(v: V) { print("O"); print(v) }
    function main() {
      let k = (x) => { print("L"); print(x) }
      const flip = () => { k = other }
      k(1)
      flip()
      k(2)
    }
    main()
    // vl check: rc 0.  vl run: wasm trap: indirect call type mismatch

Want:

    L
    1
    O
    2

#### Mechanism

A call through the cell pins its hole-lambda seed (D3845), but the write `k[0] = other` of a
declared generic was never instanced at the binding's signature, so the second call reached
`other`'s stub. A call through a cell seeded with a hole lambda now instances the lambda at the
call (`monoCellSeedLamFe`, which reads the seed itself since the binding's writes make its alias
chain decline) and coerces every value written into the cell at that signature under D3939's
value rule; a second call signature is the binding conflict and refused.
