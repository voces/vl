### D14400 — a reassigned `let` holding a generic read back from a container keeps the generic's free `T`, so a generic call is instantiated at that `T`

**runs today and must keep running · carried by the emitter's flow pin, not by the checker · filed 2026-10-26 against master `e139633e3`**

Repro:

    function id<T>(x: T): T { x }
    function runAll<U>(a: ((x: U) => U)[], u: U): U { a[0](u) }
    const mp = Map()
    mp["k"] = id
    const mpv = mp["k"]
    if mpv != null {
      let p = mpv
      p = mpv
      print(runAll([p], 2) + runAll([p], "ab").length)
    }
    // vl check: rc 0.  vl run: 4

#### Mechanism

Storing `id` into an un-annotated container types its element with `id`'s own signature
and the type parameter left free: the checker's diagnostics show the map as
`{[string]: (T) => T}`. A reassigned `let` that holds a read of that element keeps the open
type, and `runAll`'s `U` is solved to that free `T`. So `[p]` is checked only against
`((T) => T)[]`. No instance check runs at `U = i32` or `U = string`, and `recordRepTyAdopt`
is never reached, so no stamp is written. A probe in its `Ident` arm fires for the `const`
spelling and for `let p = id; p = id`, and stays silent here. The emitter builds the program
from the 0-CFA flow pin (`monoSlotPinNameTys`, read in `monoCoerceLitPart` after the checker
stamp misses). That is the last caller the stamp from #4911 does not cover. Closing this row
means the call is instantiated at the closed type each delivery supplies, so the pin read can
be deleted. The program must keep printing `4` when that happens.

#### Ablation

| ingredient removed | outcome | needed? |
| --- | --- | --- |
| the Map (`const ar = [id]`, `const mpv = ar[0]`) | same: `U` solved to `T`, runs on the pin | no |

| the container (`let p = id; p = id`) | stamped at both instances, runs | **yes** |
| the second instance (`runAll([p], 2)` only) | same: `U` solved to `T`, prints `2` | no |
