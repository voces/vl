### D2769 — an `is` test between two list types of one storage cannot tell them apart

**closed as `runs` · the repro prints `-1` · `boolean[]` takes its own value-atom code 17, `(boolean | null)[]` code 18, and each deeper boolean-leaf list (`boolean[][]`, ...) the code `18 + depth`, on the same i32-list storage, so the union box tags the two arms apart; the codes exist only in a module whose unions hold one (`vbBoolListTop`, which lifts `uAtomBandTop`) · was check-clean silently wrong · clause 1 · the #3207 round-2 review · filed 2026-09-27 against master `f6db92e0d` · fixtures `tests/cases/unions/bool-list-beside-i32-list-tags-apart.vl`, `tests/cases/unions/bool-nested-list-beside-i32-nested-tags-apart.vl`**

Repro:

    function h(c: boolean, t: boolean) {
      if c { return [t] }
      [1]
    }
    const q = h(false, true)
    if q is boolean[] { print(q[0]) } else { print(-1) }
    // PRINTS -1
    // Was: prints true.

Want:

    -1

#### Mechanism

`boolean[]` and `i32[]` are both stored as the i32 list, and the value carries no tag, so
`q is boolean[]` has nothing to test at run time and answers from the static type. `h(false,
true)` returns `[1]`, an `i32[]`, and the test says `boolean[]` and prints `true` where `-1` is
right; `is i32[]` on `h(true, true)` answers true the same way. The generic spelling at
`T := boolean` builds one list for the pair too (D2766) and answers the same.

#### The close (option B of the design, built)

The design investigated against `7323baf55` chose a distinct atom code over a distinct wasm type
(the i32 list type is read at 318 sites; the box already discriminates by tag). As built:

* producers answer 17 for a `boolean` element and 18 for `boolean | null`: `valueAtomKind`,
  `valueRowListKind`, `valueRowNulElemKind`, `nulElemListAtomKind`, `retAtomKindOf`,
  `tyValueAtomKindOf`, `unMemAtomKind`, and the carrier ladder in `emitUnionCoerce`, which reads
  the value at its instance's pin (`exprBoolListCode`: the recorded type, the exact instance's
  type, a local's initializer, a parameter's substituted annotation, a call's instance return);
* consumers read 17 and 18 as the i32 list: `listWrapHeapOfKind` (which refuses the code when no union
  registered it), `leqCoreKindOfAtomKind`, `identListRep`, `indexListRep`, `coalNicheAtomKind`,
  `refAtomElemName`;
* a nested boolean-leaf list shares its reflist slot with the `i32` twin, so its tag is
  `boolListArmTag(depth)` rather than `refArrSlotTag(slot)`, at `isArmTagOfTy` and at every
  ref-array box producer (`refArrBoxTagOf`);
* the band: `vbBoolListTop` is the deepest boolean-leaf arm any union registers
  (`markValueUnionAtoms`, `markRefArrayArms`), the codes `17 ..= 18 + top` exist only then, and
  the map-twin codes start above them (`mTwinCodeBase`); a module with none keeps every tag;
* `as?` / `as!` to a list arm, flat or nested, now lower (the nullable list or ref-list is the
  `T | null` rep), where every list arm refused before.
