### D3117 — a hole's bound field function value is called at the `i32` rep, so a `boolean` result prints as `1`

**closed · the hole-pin read follows a call of a hole to the bound function's result (`holePinReadOf`'s `HD_RET` arm), a value call whose callee is a hole, or a capture of one, is keyed by the function type the instance binds it to, and `exprIsF64`/`exprString` read that pin as `exprIsBool` already did · fixture `tests/cases/generics/hole-bound-field-function-call.vl` · was check-clean silently wrong (`boolean`) and loud emit reject (`f64`, `string`) · clause 1 · the `bound__hole__*__b_i` cells of the #3276 review's D3110 grid, and lane FF's `ff1` `hole__bind*` cells · the same on master `cc890c9f4` · filed 2026-09-28 against master `cc890c9f4`, closed 2026-09-29 against master `07d414042`; the inline-literal-argument face is D3142**

Repro:

    function F(z) {
      const g = z.f
      print(g())
    }
    const r0 = { f: () => true }
    F(r0)
    // PRINTS 1

Want:

    true

#### Mechanism

The hole instance binds `g` from `z.f`, a field-derived hole, and the call `g()` from a
call-derived one (`HD_RET`). The instance's read of a hole (`holePinReadOf`) followed field and
element derivations but not a call's, so the call's result had no type at the pin and printed
as the `i32` it rides in. The callee had the same gap one step earlier: `cloCallSigKey` keyed a
value call only from the callee's checked type, a hole, so an `f64` or `string` result found no
signature. Both now read the instance's binding; a result the classifiers do not read at a pin
(a union or a nullable) stays unkeyed and refused.

#### Ablation

| ingredient changed | outcome | needed? |
| --- | --- | --- |
| `function F<Z>(z: Z)` | prints `true` | **yes** (the hole) |
| `z: { f: () => boolean }` annotated | prints `true` | **yes** (the hole) |
| `print(z.f())`, no binding | prints `true` | **yes** (the bound value) |
| `print((z.f)())` | prints `1` | no (the parenthesised callee is the same read) |
| `const b: boolean = g()` then `print(b)` | prints `true` | **yes** (the inferred result) |
| field `() => 2.5` or `() => "ok"` | loud emit reject, no interned signature | the same gap, loud |
| top level `const g = r0.f` | prints `true` | **yes** (the hole) |

#### Grading list

- the `f64` and `string` field spellings above, which must print `2.5` and `ok`;
- two records `{ f: () => true }` and `{ f: () => 7 }` through the one hole, printing `true` then `7`.
