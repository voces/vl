### D3117 — a hole's bound field function value is called at the `i32` rep, so a `boolean` result prints as `1`

**check-clean silently wrong · clause 1 · open · the `bound__hole__*__b_i` cells of the #3276 review's D3110 grid · the same on master `cc890c9f4` · filed 2026-09-28 against master `cc890c9f4`**

Repro:

    function F(z) {
      const g = z.f
      print(g())
    }
    const r0 = { f: () => true }
    F(r0)
    // PRINTS 1

Want:

    true

#### Mechanism

Not localised past the ablation. The hole instance binds `g` from `z.f` without the field's
function type, so the call's result is formatted as the `i32` it is carried in rather than as
the `boolean` the field returns. An annotated destination (`const b: boolean = g()`) formats
right, and a field function whose result is not carried as `i32` (`f64`, `string`) is refused
at emit with `a function-value call has no interned signature`, the loud face of the same gap.

#### Ablation

| ingredient changed | outcome | needed? |
| --- | --- | --- |
| `function F<Z>(z: Z)` | prints `true` | **yes** (the hole) |
| `z: { f: () => boolean }` annotated | prints `true` | **yes** (the hole) |
| `print(z.f())`, no binding | prints `true` | **yes** (the bound value) |
| `print((z.f)())` | prints `1` | no (the parenthesised callee is the same read) |
| `const b: boolean = g()` then `print(b)` | prints `true` | **yes** (the inferred result) |
| field `() => 2.5` or `() => "ok"` | loud emit reject, no interned signature | the same gap, loud |
| top level `const g = r0.f` | prints `true` | **yes** (the hole) |

#### Grading list

- the `f64` and `string` field spellings above, which must print `2.5` and `ok`;
- two records `{ f: () => true }` and `{ f: () => 7 }` through the one hole, printing `true` then `7`.
