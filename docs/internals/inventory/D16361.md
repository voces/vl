#### Mechanism

A `let` written a generic function, and called through, holds a tagged function set: its value is
the `i32` id of the member it names. In the disassembly, `v` is an `i32` local while `fs` is a
list of closures, and the list literal stores `local.get` of that id where a closure is due. The
tag decision records a coerce to a closure (`fnCloCoerceNote`) for a set delivered alone to a
closed function type, so `[v]` runs. An element of a literal beside another member gets none.

#### Fixed

The decision accepted a list literal as a place an id can stand whatever the literal's element
type. `[v]` joins to `v`'s own set, so the literal holds ids. `[v, inc]` joins to a function type
that carries no set: the emitter builds a list of closures, and the element `v` was stored as its
id. Beside a closed annotation the element now takes the closure of the set's one generic member
at that type, the coerce a lone delivery already took; without one (`run([v, inc], 2)`, D16332) no
id fits there and the set stays untagged, so `v` is a closure, as in `[v]`. All 46 graded cells of
`fn-value-generic-list-literal-arg-at-i32.matrix.vl` run.
