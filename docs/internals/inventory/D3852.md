### D3852 — a hole lambda delivered to an annotated function-typed parameter through a binding, or returned at an annotated function-typed return, is lowered at the hole's `i32` default

**closed (2026-10-08, lane SC) · was check-clean invalid wasm · 34 of 600 fresh programs from the rv3445 generator (`gen2.py`, base 7000) · filed 2026-10-08 against master `5b2ec9f85` · pins: `tests/cases/closures/delivered-const-alias-pins-lambda.vl`**

Repro:

    function callIt(f: (y: string) => string, s: string): string { f(s) }
    function mk(x: string) {
      const e = (y) => y + "E"
      const d1 = e
      print(callIt(d1, x))
      function get1(): (y: string) => string { e }
      print(get1()(x))
    }
    mk("a")
    // vl check: rc 0.  vl run: invalid module inside `e`, `expected (ref $2), found i32`

Want:

    aE
    aE

#### Mechanism

Nothing calls the lambda, so the only thing that can pin it is the contextual type the checker
recorded for it (`monoPinLamFromCheckedTy`). Passed by its own name as the argument, it runs.
Passed through a binding, or returned at an annotated return, it gets no contextual type, and
its body was lowered at the hole's `i32` default. Closed with D3862: a typed delivery of a
name that reaches a hole lambda nothing has pinned instantiates that lambda in place at the
annotation's signature (`monoNoteBindDelivery`).

#### Ablation

| ingredient removed | outcome | needed? |
| --- | --- | --- |
| the binding (`callIt(e, x)`) | runs | **yes** (argument position) |
| `const d1` for `let d1` | still invalid | no |
| the nesting (a top-level `get1` returning a top-level `e`) | runs | **yes** (return position) |
| the call, for the annotated binding `const f: (y: string) => string = e` | runs | that position already works |
