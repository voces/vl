### D15625 — a hole function joined with a function named directly in a list literal handed to a callee that calls an element at two types is taken as a value with no signature

**loud emit reject · clause 2 · `vl check` rc 0, then `emitProgram: a generic function taken as a value reaches no call that fixes its type — annotate the destination's function type` · two holes joined in the literal run since [D15610](D15610.md) · found closing D15610 · filed 2026-11-09 against master `cf536d88`**

Repro:

    function id(v) { return v }
    function dbl(v) { return v + v }
    function call1(fs, x) { print(fs[1](x)) }
    function runOne(g) {
      call1([g, id], 7)
      call1([g, id], "u")
    }
    runOne(dbl)

Want:

    7
    u

#### Mechanism

The join `{dbl, id}` is planned with `g`'s set `{dbl}` (D15610), but `id` has no leaf in any
row: the `id` named in the literal is not scanned as a node of the join. Noting the literal's
member-naming elements as the join's leaves lets the join commit, and the emitter then refuses
`id` in the literal as a closure value (`cannot take the generic function ... as a value`),
so the literal itself must also be built at the join's rep.
