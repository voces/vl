### D2805 — a join left open at module scope is re-folded by a sibling generic's call that names its own `T`

**closed 2026-09-27 — the filed repro RUNS and prints `3` then `true` · was a loud check reject conceding codegen · clause 2 · found writing D2803's fixture · closed by stamping each escaped join with the body it escaped inside and re-folding it only at a call to that body (`validateEscJoins`) · filed 2026-09-27 against master `2bbc5c412` · fixture `tests/cases/generics/pin-union-param-binds-open-member.vl`**

Repro:

    function back<T>(v: T | string): T | string { v }
    function first<T>(w: T): T { w }
    const r = back(3)
    print(r)
    print(first(true))
    // vl check: the returns of `back` join to boolean | string for this argument — type-valid,
    // but an inferred union return through an un-annotated parameter is not yet supported by codegen

#### Mechanism

A call whose return still names an unbound hole records the join as escaped (`noteEscJoin`),
and every later generic call re-folds every recorded join under its own bindings. `substTyDeep`
matches a `TyVar` by name, so `first(true)` bound its own `T` to `boolean` and re-folded
`back`'s module-scope join to `boolean | string`, refusing a call that does not involve
`first` at all. The other deferred tables are stamped with their owning body
(`cstrOwnerTop`/`cstrOwnedBy`); escaped joins were not. They now are, and a module-scope one
(owner `-1`) is never re-folded, since no later call binds the holes it names.

| --- | --- | --- |

The cases suite's escaped-join refusals, which fire inside a generic body and are re-folded at
