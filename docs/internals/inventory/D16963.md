### D16963 — a union of a numeric list and its literal twin binds no type parameter at a generic list parameter

**loud emit reject · clause 1 (`vl check` accepts a destination the value cannot have) · found closing [D16959](D16959.md) · filed 2026-11-18 against master `0b8c7beb2` by lane F1**

Repro:

    function first<T>(xs: T[]): T { return xs[0] }
    type K = 1 | 2
    const q: i32[] | K[] = [1, 2]
    const b: boolean = first(q)
    print(b)
    // vl check: rc 0.  vl run: emitProgram: monomorphize: expected an array argument for `xs` in a call to `first`

#### Mechanism

`i32[] | K[]` over a numeric literal union `K` is one list (`oneListUnionRender`, D4743), so
D16959's refusal leaves it alone: each member stores as `i32[]` and binds `T` alike. The call
still binds no `T`, so its result `T` fits `boolean`, and monomorphization, handed the union, has
no list to bind `xs` at. Binding `T` at the one list the union renders as would serve both.

#### Ablation

| ingredient changed | outcome | needed? |
| --- | --- | --- |
| `q: K[]`, one list type | check refuses `K` into `boolean` | **yes** (the union) |
| `K` spelled inline, `i32[] \| (1 \| 2)[]` | the same | no |
| `print(first(q))`, no destination | check clean, the same emit reject | no (the clause-1 half needs a destination) |
| `n<T>(xs: T[]): i32`, `T` not in the result | check clean, the same emit reject | no |
| `string[] \| K[]` over a string literal union | refused at check (D16959): not one list (D4906) | **yes** (a numeric twin) |
