### D3565 — `std:fmt` had no fixed-precision float renderer, so a port of JS `toFixed` re-derived the exact-tie rule by hand

**closed 2026-10-03 — the witness prints JS's strings · was loud check reject (`toFixed` is not exported by `std:fmt`) · a std capability gap, not a compiler defect · owner ruling 2026-10-03 (A) on `open-rulings.md` §`fmt-fixed-precision` · sunpa SP-015 · fixtures `tests/cases/std/fmt-to-fixed.vl`, `tests/cases/std/fmt-to-fixed-digits-out-of-range-traps.vl` · filed against master `315552b88`**

Repro:

    import { toFixed } from "std:fmt"
    print(toFixed(1.005, 2))
    print(toFixed(2.5, 0))
    print(toFixed(-2.5, 0))
    print(toFixed(0.000001, 7))
    print(toFixed(-0.0001, 2))
    print((1e21).toFixed(2))

Want:

    1.00
    3
    -3
    0.0000010
    -0.00
    1e+21

#### Mechanism

`std:fmt` rendered an `f64` only at full precision (`toString`), so every port that prints a
fixed number of decimals carried its own renderer: `scripts/seed-size.vl`'s integer-tenths
`pctStr`, and sunpa's `fixed` in `src/tools/libm.vl`, which decides the tie with Dekker's
two-product. Rounding the shortest string is wrong for `toFixed` (`1.005` is
1.00499999999999989…, so two places is `"1.00"`), and multiplying by `10^digits` in floating
point is wrong at every product that is not exact. The close is `toFixed(self: f64, digits:
i32): string` in `std:fmt`, which scales the exact significand by `10^digits` as a big natural
and rounds the binary shift half upward — exact integer arithmetic, no float multiply. It
reuses the module's existing big-natural limbs, adding a right shift and a divide by 10^9.

#### Grading list

A sweep of 1,000,000 random doubles × `digits` 0..20 (21,000,000 calls, five value families:
raw bit patterns, exponents 2^-40..2^72, `n / 10^j`, exact binary ties `n / 2^k`, quarters)
agreed with V8's `Number.prototype.toFixed` string for string, 0 mismatches; so did 20,000
doubles × `digits` 0..100 and 50 edge values × 0..100. `scripts/seed-size.vl`'s `pctStr`
now calls it, and `tests/vl_seed_size_test.ts` moved its pinned Python divergence from the
2003-byte case (now agrees) to the 2005-byte exact tie.
