#### Mechanism

Two copy paths took a call's list as fresh by the call alone: the spread copy of D16444
(`recSpreadCallCopy`) and the whole-call copy for a function called more than once
(`recFreshCallCopy`'s list arm). A function returning a list it holds (a module `const`, a
parameter) hands every call the same records, so a converting copy forks them and a later write
through the holder is not seen. Both paths, and D2196's nested copy, now ask one predicate,
`callBuildsFreshList` (check_fit_rules.vl): the callee is declared and every value it returns is a
list literal, a local `const` of one read only by that return, or such a call.

Refusing the copy exposed a second path: with the copy refused, two calls of the holding function
fell to the read adoption (`recAdoptNote` of the returned binding), which retyped the binding for
one call while the other read it at its own storage, an invalid module. Two calls of a held list
are refused beside D8301's split landing.
