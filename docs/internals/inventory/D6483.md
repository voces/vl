### D6483 — a function-typed binding at one type parameter called with a value of another is refused at emit, though the instance is ill-typed

**loud emit reject · `vl check` rc 0 · clause 2 · DESIGN: the checker owes the refusal it gives the direct spelling, `argument 1: expected i32, got string` · found closing [D6426](D6426.md) · filed 2026-10-18 against master `b21da3d5d`**

Repro:

    function h<T>(x: T) { print(x) }
    function f<T, U>(a: T, b: U) { const k: (x: T) => void = h; k(b) }
    f(1, "s")
    // vl check: rc 0.  vl run: emitProgram: the function binding `k` is called in a body instanced at two types, and one binding names one function

#### Mechanism

From the ablation only. A call through a function-typed binding records no argument
constraint for the instance to re-ask, so `k(b)` with `b: U` against `x: T` is accepted in
the body and never judged at `f(1, "s")`. The emit sentence also misdescribes the program:
`f` is instanced at one type.
