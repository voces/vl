### D6483 — a function-typed binding at one type parameter called with a value of another is refused at emit, though the instance is ill-typed

**now a loud check reject, `argument of type string flows into `k` expecting i32 (the call's argument types)` — fixed 2026-10-18 by lane L3: DESIGN, the refusal the non-generic spelling and module-scope `k("s")` already give. A call through a binding or parameter typed with the body's `T`, a lambda declaring `T` in its parameters, or a nested non-generic function over `T` now binds that `T` to itself (`bindCalleeScopeTyParams`, `check_calls.vl`) instead of rebinding it to the argument, so `k(b)` records the pair the instance re-asks; an un-annotated alias of a generic keeps its own type parameters and still runs · was a loud emit reject, clause 2 · pins: `tests/cases/generics/error-fn-typed-binding-type-params-apart.vl`, `tests/cases/generics/fn-typed-binding-type-params-same-type-instances.vl` · an annotated alias of a generic at two instances is filed as [D6501](D6501.md) · found closing [D6426](D6426.md) · filed 2026-10-18 against master `b21da3d5d`**

Repro:

    function h<T>(x: T) { print(x) }
    function f<T, U>(a: T, b: U) { const k: (x: T) => void = h; k(b) }
    f(1, "s")
    // vl check: rc 0.  vl run: emitProgram: the function binding `k` is called in a body instanced at two types, and one binding names one function

#### Mechanism

From the ablation only. A call through a function-typed binding records no argument
constraint for the instance to re-ask, so `k(b)` with `b: U` against `x: T` is accepted in
the body and never judged at `f(1, "s")`. The emit sentence also misdescribes the program:
`f` is instanced at one type.
