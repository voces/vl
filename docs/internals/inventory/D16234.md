### D16234 — a bound list literal of records holding a generic function, written in a generic body, keeps one instance's element at the other

**loads then traps · `vl check` rc 0, `wasm trap: indirect call type mismatch` · clause 1 · open · the `two_instances` cells of `ffc-generic-body-fn-field-list-per-instance.matrix.vl`, both faces · filed 2026-11-15 against master `55151b054`**

Repro:

    function id<T>(x: T): T { return x }
    function run<T>(x: T) {
      const rs = [{ f: id }]
      rs.push({ f: id })
      return rs
    }
    print(run(3)[0].f(3))
    print(run("ab")[0].f("ab"))
    // vl check: rc 0.  vl run: prints 3, then wasm trap, indirect call type mismatch.

Want:

    3
    ab

#### Mechanism

The literal's element at `rs[0]` holds `id` at the first instance's `T` in every instance once the
list is also written. The pushed element (`rs[1]`) is re-instanced per instance and runs. With no
write the literal element runs, so what changes the outcome is the list becoming a written place:
its literal leaf stops being taken at the instance's own `T`. Not root-caused past the ablation.
