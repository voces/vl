### D16234 — a bound list literal of records holding a generic function, written in a generic body, keeps one instance's element at the other

**closed 2026-11-15 · runs, prints `3`, `ab` · was loads then traps, `vl check` rc 0, `wasm trap: indirect call type mismatch`, clause 1 · the `two_instances` cells of `ffc-generic-body-fn-field-list-per-instance.matrix.vl`, both faces · filed 2026-11-15 against master `55151b054` · closed by building a generic instance's own record-list literal at the elaboration's slot fact for the instance when it carries no stamp, and typing the writes its own body makes there (`monoHeldRecordListAt`, emit_mono.vl) · fixture `generics/generic-body-list-of-generic-fn-records-written-per-instance.vl`**

Repro:

    function id<T>(x: T): T { return x }
    function run<T>(x: T) {
      const rs = [{ f: id }]
      rs.push({ f: id })
      return rs
    }
    print(run(3)[0].f(3))
    print(run("ab")[0].f("ab"))
    // vl check: rc 0.  vl run: prints 3, then wasm trap, indirect call type mismatch.

Want:

    3
    ab

#### Mechanism

`monoHeldRecordListAt` types an un-annotated list of records of functions. In a generic instance
it read only the instance's rep stamp on the literal, which the elaboration does not leave on a
bound list, and it gave up on any element write. The literal then fell to the program-level pin,
the first instance's: built at `i32` in both, it trapped where a write kept the string instance's
pushed element apart ([D16236](D16236.md) where nothing did). The elaboration's slot fact for
the binding is per instance (`elabSlotTyAt(at, ["e"], ctx)` is `{f: (string) => string}` there),
so the instance now builds at it, and writes its own body makes are typed with the literal.
