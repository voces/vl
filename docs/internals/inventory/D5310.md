### D5310 — a generic's `T | i32` parameter, bound to a literal-union alias, has no union row

**closed 2026-10-17 — now prints `true` `false` · was loud emit reject, `vl check` rc 0, clause 2 · the instance's parameter annotation is substituted to `K|i32` after `collectU` ran, and `monoPinMintedUnion` registers a pinned union only when it holds a map or record arm, so no row was minted; `monoMakeInstanceParams` now registers one when the substituted type holds a literal-union arm (`monoTyHoldsLitUnionArm`, `emit_mono.vl`), keyed by its member atoms through `recordUnMemTys` · found by lane L6 closing D5260 (its generic spelling) · filed 2026-10-17 against master `2ff492745` · pin: `tests/cases/generics/generic-union-param-litunion-alias-arm.vl`**

Repro:

    type K = "x" | "y"
    function same<T>(p: T | i32, q: T | i32): boolean { p == q }
    const k: K = "x"
    const j: K = "y"
    print(same(k, k))
    print(same(k, j))
    // vl check: rc 0.  vl run: emitProgram: `==` over a struct union is not supported yet

Want:

    true
    false

#### Mechanism

In the instance at `T = K` the parameter's node type renders empty (`tyToEmitName` of its
node type, and of its pin, is `""`), so no union row `K | i32` is minted for it and the
`==` falls to the struct-union refusal. A `K | i32` spelled anywhere else in the program
mints the row, and then the same instance runs. Mono/collect layer, not the `==` lowering.

#### Ablation

| ingredient removed | outcome | needed? |
| --- | --- | --- |
| the generic (`("x" \| "y") \| i32` spelled on a plain function) | runs | **yes** |

| the `==` (`show<K>(3)` boxing into `T \| i32` and reading `is i32`) | still refuses: `union atom has no value box` | no |
| a `const z: K \| i32 = 3` elsewhere in the module | runs | **yes** |

#### Grading list

`show<K>(3)` with `function show<T>(p: T | i32): string { if p is i32 { return "i" } "k" }`
(the boxing face), and the explicit `same<K>(k, 3)`.
