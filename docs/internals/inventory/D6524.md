### D6524 — an un-annotated hole lambda read out of a list has no function-value signature when the read is copied into a binding, or when the lambda was called at another type

**loud emit reject · `vl check` rc 0 · clause 2 · CAPABILITY: the annotated lambda runs · found closing [D6470](D6470.md) · filed 2026-10-18 against master `d9c8431e5`**

Repro:

    const h = (u) => u
    const fs = [h]
    const g = fs[0]
    print(g(3))
    // vl check: rc 0.  vl run: emitProgram: a function-value call has no interned signature — parameter 1 of type `` has no representation in the function-value ABI

Want:

    3

#### Mechanism

From the ablation only. A call straight off the element, `fs[0](3)`, binds the lambda's hole at
`i32`. A copy `g = fs[0]` is not followed back to the lambda, so its parameter type stays empty
and the call has no signature. The same refusal fires on `fs[0](3)` when `h` was first called at
`string`.

#### Ablation

`let fs = [h]` with `print(h("s"))` before `print(fs[0](3))`, the second spelling in the
