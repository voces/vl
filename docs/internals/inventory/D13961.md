### D13961 — a narrowed shared-field read over a record union whose arms store the same value-union box returned the box

**closed · was check-clean invalid wasm · filed 2026-10-26 against master `1501cdf28`, closed by Step 6 slice 2 (narrowed path reads)**

Repro:

    type Ba = { a: i32, v: i32 | string }
    type Bb = { b: i32, v: i32 | string }
    function shared(x: Ba | Bb) {
      if x.v is i32 { print(x.v + 100) } else { print("other") }
    }
    shared({ a: 1, v: 5 })
    shared({ b: 2, v: "t" })
    // vl check: rc 0.  vl run on master: invalid module inside `shared`,
    // type mismatch: expected i32, found (ref $type)

Want:

    105
    other

#### Mechanism

`emitMemSharedRead` unboxed a shared field only when the receiver's arms store it at different
reps (`sharedFieldAnyArmBoxes`), and otherwise returned 0, leaving the read as the raw field.
When every arm stores the same code-16 value-union box, that raw read is the box, and a
narrowed read typed `i32` by the checker delivered a `(ref $type)` where `i32` was owed. The
fix unboxes any `FC_UNION` plan's result at the checker's atom for the read
(`pathReadAtomKind`), as a single record receiver's code-16 field already did.
