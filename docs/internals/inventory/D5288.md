### D5288 — a `match` arm written after the `_` silently tests first

**closed · now a loud check reject · was check-clean silently wrong · found closing D5284 · filed 2026-10-17 against master `3f6a785db`**

Repro:

    type Wide = "a" | "b" | "c"
    function pick(k: Wide): i32 { match k { _ => 2, "c" => 3 } }
    print(pick("c"))
    // master printed 3; the `_` arm, written first, should have taken it

#### Mechanism

The `match` desugar moves the `_` arm to the chain's final `else`, so every arm written after
it was reordered ahead of it and the program printed what the later arm said. The checker
had no rule about the wildcard's position over a literal or a value union, while the integer
arm checker already refused it. Both other arm checkers now refuse an arm after the `_` with
the integer checker's sentence, which is what the written order means.
