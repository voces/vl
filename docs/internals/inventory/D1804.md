### D1804 — the stale-seed recovery removed the live seed before it knew a replacement was obtainable, so a failed fetch left the tree with none

**closed (fixed) — the download goes to a temp destination and every write to the seed path lands by renaming a sibling over it, so the live seed is never absent; the seed found on entry is restored when neither seed compiles the source · was a tooling hazard whose diagnosis pointed at the wrong cause · filed 2026-09-07 against master `384d6d539`**

Repro (the FLOOR — the seed still builds and runs a program, which is what a destroyed seed
takes away; the defect's own witness is the shell transcript below, and the fix's proof is
that this PR's own audit rebuilds a candidate tree with the changed script):

    const a: i32[] = [1, 2, 3]
    print(a[0] + a[2])

#### Mechanism

`selfcompile` failing sets `ok=0`, which enters the stale-CACHED-seed recovery in
`scripts/refresh-compiler.sh`. That block opened with `rm -f "$SEED"` — because
`fetch-seed.sh` no-ops when its destination already exists — and only then tried to download
`seed-latest`. When the download could not happen, the run exited with no seed at all:

    printf 'not a wasm module at all' > /tmp/probe-seed.wasm
    VL_SEED_REPO=voces/no-such-repo SEED=/tmp/probe-seed.wasm OUT=/tmp/probe-out.wasm \
      bash scripts/refresh-compiler.sh
    # rc 1, and /tmp/probe-seed.wasm no longer exists.

The `temp + mv` discipline the script already used for PUBLISHING never covered this: the
loss is in the recovery, not the publish.

**The diagnosis pointed at the wrong thing, which is why it read as a broken merge.** A
self-compile fails for reasons other than staleness, and a compile error in `compiler/*.vl`
is the common one — that was the trigger the day this was found. The message asserted
`seed cannot compile current source (stale seed)` and told the reader to check network
access, while the real cause was a diagnostic printed a few lines above and the seed was
already gone.

#### Ablation

| ingredient removed | outcome | needed? |
| --- | --- | --- |
| the fetch failing — `seed-latest` reachable | recovers; the seed is replaced and the build succeeds | **yes** |
| the self-compile failing — source and seed both good | never enters the block; the seed is untouched | **yes** |
| the seed being present on entry — a fresh checkout | the bootstrap fetch runs earlier and is unaffected | no |

#### Grading list

Four paths, each re-run against the fix:

| path | before | after |
| --- | --- | --- |
| recovery, fetch unreachable | seed **destroyed**, rc 1 | seed **intact**, rc 1, and the message says so |
| recovery, fetch reachable | recovers | recovers, unchanged |
| normal build | works | works, unchanged |
| bootstrap, no seed present | fetches | fetches, unchanged |

The concurrency rule the fix keeps: every write to the seed path is a rename of a SIBLING
temp over it, never a `cp` in place and never a window where the path is absent — another
agent's gate rows read the same `build/` in parallel.
