#### Mechanism

A heap census (drop each whole-program global after the compile, force a collection, read the
live bytes that left) split `chunk_662`'s 118 MiB: `P.nodes` 30, `P.toks` 26, and twenty-one
`i32[]` columns at 2 MiB each (301K nodes, capacity 512K). Eleven of those columns held
fewer than 1% non-default rows on the unit — `isParentTyIx`, `isParentElseTyIx`, `asgNarTyIx`
and the three anon-leaf `??` columns held none — because each was pre-filled to the arena at
the start of its pass, or grown lazily to the highest node written, which in a long program is
near the end. The anon-leaf resolver index (`anonIx*`, another ~8 MiB) stayed built after the
passes that read it.

#### Fix

Columns that are pre-filled but rarely written (`isVarTyIx`, `isParentTyIx`,
`isParentElseTyIx`, `asgNarTyIx`, the anon-leaf `??` columns) grow only to the last row
written, with the old length kept as a separate write bound so a bounded write lands exactly
where it did. Columns with scattered rows (`ifValTyAt`, `ifNoValueAt`, `intMatchHead`,
`annUnionAtoms`, `cwFrameUp`, `armPreludeBlocks`) are `{[i32]: …}` maps; every reader's miss
answers the column's old default. The anon-leaf index is cleared at the end of
`collectAnonShapes`; `anonLeafIxEnsure` rebuilds it for a later reader, and none on the three
units asks. The copying compile's first heap is then 256 MiB, the knee of the unit's CPU/RSS
curve (docs/internals/profiling-the-compiler.md, "Measured 2026-09-24, second pass").
