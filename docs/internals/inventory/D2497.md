### D2497 — the value of a tail write of `null` to a field or element is invalid wasm

**check-clean invalid wasm · clause 1 · filed 2026-09-25 against master `0a0d24ac9`, found
grading [D2496](D2496.md)'s close, which leaves it as it was**

Repro:

    type O = { v: string | null }
    function clr(o: O) { o.v = null }
    const r = clr({ v: "a" })
    print(r == null)
    // vl check: rc 0.  vl run: invalid module, "expected nullref but nothing on stack"

#### Mechanism

The checker types `o.v = null` at its right side, `null`, so `clr` returns `null`, and the caller
binds that. The emitter keeps `clr` void: [D2496](D2496.md)'s `assignTargetSpills` declines a bare
`null` right side, because spilling it would give the value a local with no rep of its own
(without the decline, the six `= null` fixtures listed below failed: five as invalid wasm, one
as an emit refusal). The
name-target spelling `g = null` runs, by re-reading `g`. Either the checker types a `null` write's
value at the place (`string | null`) and the spill re-reads the place, or the emitter yields a
fresh `null` literal as the value.

#### Grading list

`xs[0] = null` over `(string | null)[]` (same outcome); the six fixtures that write `null` to a
field, an element or a captured cell (`structs/null-store-into-nullable-field.vl`,
`soundness/alias-write-*.vl`, `soundness/call-ends-path-narrowing-retest-runs.vl`,
`objects/place-narrowed-nullable-array-element.vl`, `closures/capture-nullable-closure-null-write.vl`).
