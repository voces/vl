### D2599 — a closure capturing an un-annotated copy of a nullable list binding finds no list type for its env field

**closed 2026-09-26 — the filed repro RUNS and prints `7` · was loud emit reject, clause 2 ·
pre-existing on master `483ff4607` · found by the un-annotated `fn_body_capture` cell of the
`null-hole-fill-list-*` matrices ([D2597](D2597.md)) · fixture
`tests/cases/closures/nullable-list-copy-captured.vl`**

Repro:

    function k(): boolean { return true }
    function main() {
      let h: i32[] | null = null
      if k() { h = [7] }
      const c = h
      const f = () => {
        const v = c
        if v != null { print(v[0]) } else { print("none") }
      }
      f()
    }
    main()
    // vl check: rc 0.  vl run: emit error: bare null needs a struct-typed context

#### Mechanism

The env field of a captured un-annotated binding is classified from its initializer in the owning
frame (`captureValKind` → `letInitCellKind`). A copy `const c = h` asks whether the NAME `h` is a
nullable list, and that is answered through the frame's registered locals, which do not exist
while the type section is built; so the field fell to the `i32` default and the closure's
`v != null` had no list heap for its null. At module scope the copied name is a global, which
resolves without locals, and runs. The close synthesizes the copy's annotation from the checker's
recorded type of the read (`synthNulListCopyAnn`, in the same pre-inference pass as
[D2598](D2598.md)), so the capture takes the annotated twin's cell.
