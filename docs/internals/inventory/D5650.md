### D5650 — a forward callee inferred on demand resolves its free names in the caller's scope

**check-clean silently wrong · found closing D5593 · filed 2026-10-17 against master `7fe51e77c`**

Repro:

    const x = 1
    function act() {
      const x = 2.5
      print(x)
      return g()
    }
    function g() { return x }
    print(act())

Want:

    2.5
    1

#### Mechanism

`act` is inferred in the return pre-pass and calls `g` before `g` is inferred, so
`checkCallOnFuncTy` demand-checks `g`'s `FuncDecl` from inside `act`'s body. The body scope
`g` pushes sits on top of `act`'s, and `lookup` reads the innermost binding, so `x` in `g`
resolves to `act`'s local `const x = 2.5` instead of the module constant. `g` is then
inferred as returning `f64` and what it returns is the caller's value. With a `boolean` local
the same spelling is refused (`operator '+' is not defined for boolean and i32` at a use of
`act()`), and with a `string` local `act`'s own return cannot be inferred.

#### Ablation

| ingredient removed | outcome | needed? |
| --- | --- | --- |
| `g` declared before `act` | runs, prints `1` | **yes** |
| the local renamed `y` | runs, prints `1` | **yes** |
| `act`'s return annotated `: f64` | runs, prints `1` | **yes** |

#### Grading list

The `boolean` and `string` spellings above; a forward callee reading a module `let` that the
caller shadows with a parameter; a narrowing of a module global live in the caller at the
forward call, which the callee's body must not see.
