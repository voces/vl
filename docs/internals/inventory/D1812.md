### D1812 — the `as` trio refused a niche-repped `T | null` operand, because it looked for a tag

**now a loud emit reject · filed 2026-09-06 against master `c21f7f4ce`**

Repro:

    type A = { a: i32 }
    function f(): A | null { return { a: 7 } }
    const x: A = f() as! A
    print(x.a)
    // vl check: rc 0.  vl run: emitProgram: `as A` over a `A | null` is lowered for
    // a string, a list and a union variant

#### Mechanism

`emitAsCast`'s union arm is a tag chain: it evaluates the operand into `unionAsSlot`,
compares `struct.get $uBox 0` against the target arm's tags, and unboxes. A niche-repped
`T | null` carries no such struct — `ref.null` IS the absent arm — so the arm asked
`exprUnion` and refused every niche operand with one sentence, for all three modes.

The niche needs no tag machinery at all. `as!` is `ref.as_non_null`: one opcode, no heap
index, no stash, and its trap is the trio's own ruled sad path. `as?` is the identity,
since `T | null` is what the operand already reps as. Both now lower, for the string, list
and union-VARIANT cells.

What is still refused is the CONSUMER side, not the lowering: a standalone struct, a map and
a closure have no rep classifier that reads a cast node, so their un-annotated face was
check-clean invalid wasm at six of twenty-six delivery positions. `nulNicheCastWiredTy` is
the gate that keeps those a loud refusal rather than a miscompile. The propagating bare `as`
is refused too — its sad path returns the enclosing function's null, which needs the operand
staged at its own heap type, and the niche has no typed slot for that.
