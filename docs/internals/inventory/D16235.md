### D16235 — pushing a record holding a generic function onto a `T`-typed list in a generic body is checked at the first instance's `T`

**loud check reject · `push: cannot add {f: (i32) => i32} to {f: (string) => string}[]` · clause 2 · open · the sentence is false: at the string instance the pushed `id` is `(string) => string` · found ablating [D16234](D16234.md) · filed 2026-11-15 against master `55151b054`**

Repro:

    function id<T>(x: T): T { return x }
    function run<T>(x: T) {
      const rs: {f: (x: T) => T}[] = []
      rs.push({ f: id })
      return rs
    }
    print(run(3)[0].f(3))
    print(run("ab")[0].f("ab"))
    // vl check: push: cannot add {f: (i32) => i32} to {f: (string) => string}[]

Want:

    3
    ab

#### Mechanism

The pushed record's field type is fixed by the first instance's re-check and reused by the second,
so the second instance compares an `(i32) => i32` field against its own `(string) => string` list.
An initialiser delivered to the same annotation is typed per instance and runs.
