### D14755 — a record delivered by an overloaded method call is judged by every same-named `self`-function, not the one the call picks

**closed 2026-11-01 by `rcwSelfDeclsOf` reading the checker's pick (the recorded declaration and each instance's pick), which deletes `cwSelfDeclsNamed` · the witness prints `1` · was a loud check reject, clause 2, on master `1d98f35a` · fixture `tests/cases/modules/overload-pick-reads-only-delivery` · filed 2026-11-01 against master `1d98f35a`**

Repro:

    // file: a.vl
    export type W = { z: boolean, x: i32 | string }
    export function poke(self: W): i32 {
      self.x = "s"
      0
    }
    // file: b.vl
    export type V = { y: i32, x: i32 | string }
    export function poke(self: V): i32 { 1 }
    // file: entry.vl
    import { W, poke } from "./a"
    import { V, poke } from "./b"
    const i = { y: 2, x: 9 }
    print(i.poke())
    // was: a {y: i32, x: i32} cannot be delivered as V here: the assignment on line 3 of a.vl writes a widened field

Want:

    1

#### Mechanism

Only `V` accepts `{y, x}`, so the checker picks `./b`'s `poke` (`ovPickFor`) and records it on
the call. The record-write analysis asked `rcwSelfDeclsOf` which `self`-functions the call reaches,
and it answered the recorded one plus every declaration spelled `poke` (`cwSelfDeclsNamed`). `./a`'s
`poke` writes the widened field `x`, so the delivery was refused on a write the call never reaches.
