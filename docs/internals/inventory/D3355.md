### D3355 — a binding whose initializer joins an exiting arm with a bare `null` is typed `_ | null`, and no use pins the hole

**loud emit reject · 143 cells of the #3293 review grid `h5` carry this message (value family `nul`; a message count, 138 more of that family refuse with two other emit messages, unablated) · filed 2026-09-30 against master `455e553ca`**

Repro:

    function h(n: i32): i32 {
      const y = if n == 4 { return -7 } else { null }
      (y) ?? -1
    }
    print(h(4))
    print(h(2))
    // vl check: rc 0.  vl run: emitProgram: only i32 locals are supported

#### Mechanism

Since the loop-values change the `if` join leaves out an arm that always exits (D3222), so the
join is the other arm's bare `null`, which the checker types `_ | null` with an open hole. The
hole of a plain `const y = null` is pinned by its uses (here `?? -1` pins it to `i32`), but the
hole of this join is not, so the binding reaches the emitter at `_ | null`, which no local
represents. On master the same program was a check reject (`void | i32`), so the population is
loud either way; the fix is to pin the join's hole as the literal binding's is.
