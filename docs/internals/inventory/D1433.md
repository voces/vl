### D1433 — a NESTED member read off an open parameter is not re-asked at the call, so a bad argument reaches the emitter at both spellings

**loud emit reject · clause 2 · OPEN · found 2026-09-03 grading [D1431](D1431.md)'s ruling one
level of nesting down · ZERO corpus cells**

Repro:

    function a<T>(x: T): i32 { x.inner.foo }
    print(a({ inner: { bar: 1 } }))
    // vl check: rc 0.  vl run: emitProgram: unknown struct field in field access
    // The un-annotated twin `function a(x) { x.inner.foo }` does exactly this too.

#### Mechanism

The FIRST read records a deferred row keyed on the parameter's own type
(`noteMemCstr(T, "inner")`) and yields a derived hole `?fld.inner.T`. The SECOND read is
taken off that derived hole, so it goes down `checkMemberNode`'s `?`-hole branch and grows
the hole SHAPE — and the shape is only ever consulted at the argument through
`holeDemandOk(params[i].tvName, …)`, which names the PARAMETER, not the derivation. Nothing
re-asks the nested demand under the substituted argument, so `{inner: {bar: 1}}` is accepted
and the emitter is left holding a field access it cannot resolve.

The ruling ([D1431](D1431.md)) is satisfied here — both spellings behave identically, before
and after — and the gap it exposes belongs to the HOLE path, which `<T>` now shares. It is a
clause-2 violation at both: `check` returned 0, and `unknown struct field in field access`
names a mechanism rather than a contract the program broke.

#### Ablation

| ingredient removed | outcome | needed? |
| --- | --- | --- |
| the nesting (`x.foo`, argument `{bar: 1}`) | `argument 1: expected {foo: _}, got {bar: i32}` | **yes** |
| the `<T>` (bare `(x)`) | identical emit refusal, same mechanism | no |
| the bad argument (`{inner: {foo: 1}}`) | prints `1` | **yes** |

#### Grading list

* The hole spelling, which must keep matching whatever this closes to — the two agreeing is
  [D1431](D1431.md)'s property and is not this row's to break.
* `function a<T>(x: T) { x.inner.foo }` beside `function b<T>(x: T) { x.inner.bar }`, which
  prints `1` / `2`: two declarations reading the same nested path share the derived-hole NAME
  `?fld.inner.T` and therefore one demanded shape. Nothing checks that shape at a call today,
  so the sharing is currently invisible — a fix that starts consulting it must scope the key
  first, or it will refuse both of these.
