### D3226 — a float or wide integer literal handed through a hole to an `f32` parameter reaches it at its own width

**closed · runs, prints `1.5` · was check-clean invalid wasm · clause 1 · a number literal handed to a hole whose use demands another numeric width is rebuilt at that width as D5840 rebuilds an aggregate literal (`adoptHoleLitArg`'s number arm, `holeNumLitAdopts`), so `v` is pinned at `f32` and the literal built there · fixture `numerics/number-literal-through-hole-to-f32-parameter.vl` · filed 2026-09-29 against master `94670f728`, closed 2026-11-01**

Repro:

    function H(h, v) {
      return h(v)
    }
    print(H((x: f32) => x, 1.5))

Want:

    1.5

#### Mechanism

Not localised past the ablation. The direct call `((x: f32) => x)(1.5)` adopts the literal at
`f32`; through the hole, `v` is pinned at the literal's own `f64` and nothing converts it
where it meets `h`'s `f32` parameter. The same shape as D3171 (a literal typed by its
context, transitively), at a float width rather than a literal union.

#### Ablation

| ingredient changed | outcome | needed? |
| --- | --- | --- |
| `((x: f32) => x)(1.5)`, no hole | prints `1.5` | **yes** (the hole) |

| `3`, an integer literal | prints `3` | **yes** (the float literal) |
| `(x: f64)` | prints `1.5` | **yes** (the `f32` parameter) |
| `5000000000`, an `i64` literal | the same invalid module (`expected i32, found i64`); the direct call prints `5000000000` | no (any literal the direct call adopts at `f32`) |
