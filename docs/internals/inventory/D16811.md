### D16811 — a list of records of un-annotated functions beside a map of records of a wider set builds an invalid module

**closed 2026-11-16 — the witness runs and prints `1.5` then `6` · was: check-clean invalid wasm · `type mismatch: expected (ref null $type), found (ref $type)` · clause 1 · found closing D16749 · filed 2026-11-16 against master `69032f028`**

Repro:

    function inc0(a) { return a + 1 }
    function half(a) { return a / 2.0 }
    function dbl(a) { return a * 2 }
    const xs = [{ f0: inc0 }, { f0: half }]
    print(xs[1].f0(3))
    const m = Map()
    m.set("a", { f0: inc0 })
    m.set("b", { f0: half })
    m.set("c", { f0: dbl })
    const q = m.get("c")
    if q != null { print(q.f0(3)) }
    // vl check: rc 0.  vl run: invalid module, the top-level code fails to validate

Want:

    1.5
    6

#### Mechanism

The smaller set `{inc0, half}` and the wider `{inc0, half, dbl}` were tagged apart. Planning one
met the other's member names in record literals built at the other's record, and the tag plan
either refused the set (a loud emit reject, [D16749](D16749.md)) or, with the list's records,
tagged both and built a record literal at a row the other set's read does not accept. A field of
a record literal built at a record of another tagged set is that set's leaf now (`ftOtherTail`,
`compiler/check_fn_tag.vl`), and a record of the smaller set written into a map of the wider
set's records decides the two together (`ftRecIntoMap`).
