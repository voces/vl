### D3206 — `??` in an instance whose operand the pin makes a plain `i32` or `string` refuses

**closed · the emitter reads the operand when the instance pins it to `i32` or `string` and the default has that type, as the checker's fold does at a direct spelling · fixture `tests/cases/generics/instance-coalesce-over-non-nullable-pin.vl` · was loud emit reject · clause 2 · pre-existing · found by the #3288 round-2 review (`rv3288r2-q8m3/gF`, `*_anon_*` cells) · filed and closed 2026-09-29 against master `94670f728`**

Repro:

    function F(z) {
      const x = z.f()
      print(x ?? 0)
    }
    F({ v: 1, f: () => 4 })
    // vl check: rc 0.  vl run on master: emit refuses "`??` over this nullable value is not supported yet"

Want:

    4

#### Mechanism

The rewrite folds a `??` whose operand cannot be `null` into its operand, but it runs over the
generic body the instances share, where the operand is typed at a type parameter. An instance
that pins it to a non-nullable type reached `emitCoalesceGo` with no niche to test and fell to the
refusal. The emitter now folds there when the pin is `i32` or `string` and the default is the same
type, and `exprString` answers for the folded node. Other pins keep the refusal: the `??` node's
own classifiers do not read the operand's rep, and folding `boolean` printed `1`, folding under an
`f64` default was invalid wasm, and folding a literal-union pin printed its atom.
