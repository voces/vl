### D3535 — a list literal with a nullable runtime element beside a number of another type still widens instead of joining them apart

**closed 2026-11-02 · runs, prints `false` · the gate in `listJoinApart` (`compiler/check_fit_rules.vl`) that kept a nullable runtime element widened is deleted: `indexOf` and a generic `==` over the apart list, the two readers it guarded, run at every pin of a 150-cell grid before and after · was check-clean silently wrong · clause 1 · grading list: the 1,654-cell grid's list cells gain 12 and lose 0 · pin: `tests/cases/numerics/literal-return-and-nullable-list-element-join-apart.vl` · filed 2026-10-03 against master `f6e17953b` with the NJ2 lane applied**

Repro:

    function f(a: i64 | null, b: i32) {
      const xs = [a, b]
      print(xs[1] is i64)
    }
    f(null, 7)
    // PRINTED true before the close

Want:

    false

#### Mechanism

Joined apart, the list is `(i64 | i32 | null)[]`, and a `std:array` generic over it does not
lower: `indexOf(xs, xs[1])` is check-clean invalid wasm inside `indexOf$m1` (`expected i32,
found (ref $type)`), and a generic `==` over `i32 | f64 | null`
(`function same<T>(a: T, b: T): boolean { a == b }`) traps with a cast failure when one side is
`null`. Both are master's own, reached there through the `if` spelling
(`[if c { a } else { b }]`); the lane's grid found the list spelling newly reaching the first in
2 cells that run on master. `listJoinApart` therefore keeps master's widening for a list with a
nullable runtime element, except in a body checked at each pin (`njFnOpen`), where the template
cannot see the element's nullability and has to join apart as its instance's re-check does.
