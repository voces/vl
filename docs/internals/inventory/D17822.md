### D17822 — a binding's list of a set's records aliased into an annotated list and handed through a call or nested in a list, then called at another signature, is not refused

**open · trap after load · clause 1 · `vl check` rc 0, `wasm trap: indirect call type mismatch` · filed 2026-11-28 against master `d76847374` (lane START-2)**

Repro:

    function id(a) { return a }
    function deliver() { return [{ f: id }] }
    function use(xs) { return xs[0].f(2) }
    const a = deliver()
    const b: { f: (a: f64) => f64 }[] = a
    print(use(a))
    print(b[0].f(2.5))
    // vl check: rc 0.  vl run: prints 2, then traps

#### Mechanism

D17819's refusal reads every call through the aliased field's set whose storage is the binding or
no binding the walk can name. A call inside a generic function's body is typed at the type
parameter, so it carries no set fact at check; a list nested in another list roots at the outer
binding. `capability-matrix.vl` over
`scripts/capability-probes/matrix/aliased-set-record-list-called-at-another-signature.matrix.vl`
names the three un-annotated cells that still trap: `argument`, `return_inferred`, `array_element`.
