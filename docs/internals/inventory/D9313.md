### D9313 — a generic function in a record held as an un-annotated `Map()`'s value, called through `?.` after an earlier same-shaped record literal's call, has no value box

**closed 2026-10-21 by lane-D9311 · runs, prints `1.5` and `2` · was loud emit reject, `union atom has no value box`, `vl check` rc 0 · clause 2 · closed with [D9312](D9312.md) by the same match (`fieldValueTakesFnTy`, emit_classify.vl) · fixture `closures/hole-fn-record-in-map-after-same-shaped-literal.vl` · found closing [D9065](D9065.md) · present on master `cf1b1a8d3` (as `unsupported map value type`) · filed 2026-10-21 against master `cf1b1a8d3`**

Repro:

    function half(a) { return a / 2.0 }
    function id<T>(x: T): T { x }
    const b = { f: half }
    print(b.f(3))
    const j = Map()
    j["k"] = { f: id }
    print(j["k"]?.f(2) ?? 0)
    // vl check rc 0.  vl run: emit error: emitProgram: union atom has no value box

#### Mechanism

Traced: the shared struct row of [D9312](D9312.md). `{ f: half }` and `{ f: id }` have
the same field names, and the `?.` call was classified through the first literal's closure,
because the signature filter compared the field's guessed `(i32)=>i32` type rather than
each function's own result at the call's parameters, so the `?? 0` met an f64 where the
call built an i32.
