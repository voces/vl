### D17665 — a one-element list literal of a record holding two different un-annotated functions lays the field out as a closure where the element writes the set's id

**closed 2026-11-26 by lane COV-START · runs, prints `7` · was check-clean invalid wasm, clause 1 · the IR claims the start body: the element's `r`, typed at a tagged set's id, goes into the row's closure slot as the function's closure (`tagIdIntoClosure`), and the call through the tag set calls that stored closure (`tagDispatchAt`); the nested and maker spellings are D17666**

Repro:

    function inc0(a) { return a + 1 }
    function dbl(a) { return a * 2 }
    const xs = [{ r: inc0, s: dbl }]
    print(xs[0].r(6))
    // vl check: rc 0.  vl run: invalid module, type mismatch: expected (ref $2), found i32; $2 is struct {structref, i32, i32}

Want:

    7

#### Mechanism

Legacy writes the element's `r` field as a tagged set's i32 id. The list's ref-list row lays that
field out as a closure struct (`$2`), so `struct.new` meets an i32 where the row's field wants a
`(ref $2)`. Each field holds a single function whose set no other value widens. With two elements
that cross the functions, each field's set has two members, the row stores ids, and the program
runs. Which side picks the wrong storage (the element's field code or the list row's) is not yet
localised.

#### Close

The IR builds the field and the call at the row's storage. Legacy still writes the mismatched
module, so the program runs once the IR claims its start body (`$VL_IR_REQUIRE_CLAIM=1` exits 0
and prints `7`). The positions file is
`tests/cases/lists/record-of-two-unannotated-functions-in-list-positions.vl`. Its control, the seed
without this close, exits 1 (`object field coercion`). Calling both fields makes legacy store the
ids and run, so each position calls `r` alone.
