### D8340 — a record literal delivered through a generic identity into a union member leaves a later generic call at the same field names without a row

**loud emit reject · `vl check` rc 0 · clause 2 · open · present on master `38ea07302` · the reversed order of [D8203](D8203.md) · filed 2026-10-20 against master `38ea07302`**

Repro:

    type J = { r: i32 | null }
    function idn<T>(v: T): T { v }
    function one<T>(v: T): i32 { 1 }
    const u: J | string = idn({ r: 4 })
    print(one({ r: 5 }))
    // vl check: rc 0.  vl run: emit error, "emitProgram: ref valtype with no interned shape"

Want:

    1

#### Mechanism

The second call's instance takes a parameter of the literal's own type `{r: i32}`, and no
struct row exists for it: the valtype that refuses is kind `struct` at row `-1`. The first
literal is built at `J`'s row because the union delivery pins it there (D8021), and nothing
else in the program mints `{r: i32}`. A row minted by any other route makes it run, so the
gap is in which literals mint a row for a generic instance's parameter, in the collect pass,
outside `emit_classify.vl`.

#### Ablation

| change | outcome | needed? |
| --- | --- | --- |
| `const u: J = idn({ r: 4 })` | prints `1` | **yes**, the union destination |
| `one({ q: 5 })` | prints `1` | **yes**, the same field names |
| `function one(v: { r: i32 }): i32 { 1 }` | prints `1` | **yes**, the type parameter |
| add `const k: { r: i32 } = { r: 6 }` | prints `1` | **yes**, no other row for `{r: i32}` |
| `print(idn({ r: 5 }).r)` as the second call | still refuses | no, any generic callee |
