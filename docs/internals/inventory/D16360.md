### D16360 — the first `.set` or `.push` of a one-literal value into an un-annotated container is not delivered at the slot it pins

**closed 2026-11-14 — the witness runs and prints `a` · was: check-clean invalid wasm · clause 1 · `the emitted module failed to validate: type mismatch: expected i32, found (ref $1); $1 is string` · `m["k"] = a` and an annotated map run · found grading `lone-literal-result-of-generic-fn-value.matrix.vl` (cell `map_set`, un-annotated) · filed 2026-11-14 against master `b45a06ef`**

Repro:

    const a: "a" = "a"
    const m = Map()
    m.set("k", a)
    print(m.get("k") ?? "none")
    // vl check: rc 0.  vl run: invalid module in the top-level code

Want:

    a

#### Mechanism

The first write into an un-annotated `Map()` or `[]` pins the slot to the value's type. A lone
string literal pins as its one-member set, whose rep is an atom (D7449). Every later write is
checked with `assignableExpr`, which records the value's delivery at the slot (`recordCtxTy`), so
the emitter lowers it as the atom. The first `.set` and `.push` recorded no delivery, so the value
was emitted at its own rep, a string, into an atom slot. Both first-pin arms now record it, as
the `m[k] = v` arm already did through its assignment check.
