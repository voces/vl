### D3453 — an operator over an un-annotated parameter bound to a nullable numeric union, past its `null` test, has no result type at the hole instance

**closed · was a loud emit reject with the numeric-join lane applied (master refuses the f64-first spelling at check, and runs the i32-first one by widening) · the pin resolves the read through the parameter's hole, also through an un-annotated local it initialises (`monoAliasedParam`) · fixture `tests/cases/numerics/hole-param-numeric-union-past-null.vl` · filed 2026-09-30 against master `81c11a1be`**

Repro:

    function use(r) {
      if r != null {
        print(r + 1)
      }
    }
    function test(k: i32, a: f64, b: i32) {
      const j = if k == 0 { a } else if k == 1 { b } else { null }
      use(j)
    }
    test(0, 2.5, 7)
    test(1, 2.5, 7)

Want:

    3.5
    8

#### Mechanism

The hole instance of `use` pins `r` at `f64 | i32 | null`, and the read past `r != null` is typed
at a derived hole (the narrowing's remainder), not at `r`'s own hole. `monoNumUnionOpPin`, which
re-types an operator over a numeric union at each instance, reads a name's hole binding directly
and cannot resolve a derived one without re-substituting it, which mints union rows the emitter's
literal-complement narrowing then reads wrongly (it broke `inference/hole-param-is-complement.vl`).
So `r + 1` keeps the template's type, the emitter's dispatch would build an `f64 | i32` box its
`print` reads as an `i32`, and `emitNumUnionBin` refuses that shape by name instead.

#### Close

Arm order mattered on master: the `i32`-first spelling ran there by widening, so with the lane
applied it was a run lost (the #3327 review's `p/h1.vl`), while the `f64`-first spelling was a
master check refusal. `monoNumOperandPinTy` now answers an operand typed at an unresolved hole
from the hole of the parameter it names, following an un-annotated local initialised from
that name (`let a = r`). The binding is read directly, so no row is minted. That parameter's
binding past the `null` test is the union without its `null`.

#### Ablation

| `print(r)` in place of `print(r + 1)` | runs | **yes** (the operator) |
