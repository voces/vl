### D4159 — a generic delivered through a `let` alias is refused once a later written `let` calls it at another type

**closed 2026-10-17 by lane L1 ([D5290](D5290.md)) · runs, prints `true 9` · was loud check reject · an alias carrying a generic's own signature is bound by its delivery and not parked, so the later pin of `gA` through `z` does not re-ask it · pins: `tests/cases/closures/generic-fn-value-demand-other-generic-same-tyvar-name.vl` · found by the D3961 position matrix (54 of 1,944 `gen2` cells) · filed 2026-10-11 against master `3096c492f`**

Repro:

    function gA<U>(u: U) { print(u) }
    function gB<V>(v: V) { print(v) }
    function ci(g: (x: boolean) => void) { g(true) }
    let f = gA
    ci(f)
    let z = gB
    z = gA
    z(9)
    // vl check: argument 1: expected (boolean) => void, got (i32) => void

Want:

    true
    9

#### Mechanism

Not located. The write `z = gA` and the call `z(9)` appear to pin `gA` at `(i32) => void` for
the checker, and the alias `f`, which ruling C keeps generic, then reads the pinned type.
`ci(gA)` with no alias is accepted, and prints `true` then `9` since D3961/D4158 closed.
