### D1677 — `.get` re-reads its index and its receiver, so a call at either is refused, in the plain and the fused `?.`/`??` spelling alike

**closed 2026-09-06 — the witness prints `3` · was a loud emit reject · filed 2026-09-05
against master `a0fa9533c` · found while D1670 retired the same re-readability gate one layer
up · fixture `tests/cases/expressions/listget-call-operands-once.vl` · matrix
`scripts/capability-probes/matrix/listget-call-operands-once.matrix.vl`**

Repro:

    type S = { w: i32 }
    function ix(): i32 { 0 }
    const xs: S[] = [{ w: 3 }]
    print(xs.get(ix())?.w ?? 0)
    // was: vl check rc 0, then emitProgram: .get index must be a literal or a name.
    // Now prints 3.

#### Mechanism

`.get` lowers to a bounds test and an element read, and it emits BOTH the index and the
receiver twice — once for `idx u< len` and once for the `array.get`. Rather than stage
either, three sites gated the index to a literal or a name and two gated the receiver to a
bare `Ident`; the fused `xs.get(i)?.f ?? d` arm carries its own copy of both, so the refusal
is reached with and without the `?.`.

Both are now staged, D1670's mechanism one lowering over. The index takes a new i32 slot and
the receiver a `(ref null struct)` one, both teed in on the FIRST read — the bounds compare,
which every arm emits before the branch that reads them again — so a `.get` whose operands
are places emits the bytes it always did. The RECEIVER needed no new machinery on the
`emitPop` path: `listOpRecvLocal` already stages a global `Ident`, a `Member` and an `Index`
receiver into the push frame's `recvRef` slot through `stageListRecv`, which is `emitExpr` +
`local.set`, so a `Call` receiver is one more arm on a path that already existed.

Both refusal literals are gone from the compiler.

#### Grading list

The `?.`-free spelling was the one to fix first, and it is: `const e = xs.get(ix())` runs.
`.pop()`, `.clear()`, `.push()`, `.length` and `[]` on a call receiver all run too.
