### D15761 — the canonical type key gives one key to two unions of record twins, whose rows record different variants

**closed 2026-11-12 — one set, one row: a declared alias whose record arms are layout twins of an existing set's arms adopts that row (`declArmsMatchRow` assigns each twin an unclaimed arm), so `U` and `V` share a row and the union key licence reads 0 on its control; the repro still prints `7` then `7`. Was: runs today and must keep running · the union key licence's control · filed 2026-11-12 against master `ce340a60`**

Repro:

    type Cat = { m: i32 }
    type Kot = { m: i32 }
    type U = Cat | Kot
    type V = Cat | { m: i32 }
    function pickU(u: U) {
      if u is Cat { u.m } else { -1 }
    }
    function pickV(v: V) {
      if v is Cat { v.m } else { -1 }
    }
    print(pickU({ m: 7 }))
    print(pickV({ m: 7 }))

Want:

    7
    7

#### Mechanism

The canonical type key (`utkTyKeyText`) spells a record by its fields' interned shape, so `Cat`,
`Kot` and `{ m: i32 }` key alike. `U` and `V` are two rows, with variant slices `[Cat, Kot]` and
`[Cat, #anon]`, under one type key. The union key licence (`unKeySweepPair` over `unTyKey`, with
`tests/vl_union_key_licence_test.ts`) counts the pair as `merge-diffset` and `merge-diffvar`. A
typed lookup for either type returns the first row registered. Both programs print their want
today. The record-twin union is the class `tyIsTwinRecordUnion` names, which the canon walk
already keeps apart by type.

#### Ruling

Structural, as `tySame` is (lane orchestrator, 2026-11-12). A union is a set (D1712), brands
are erased, twins share heaps, and `is` between twins is already a value test (D1023). So
twin sets are one set, and one row.
