### D3925 — an un-annotated record parameter whose tail calls a field's void function builds invalid wasm when exported, or when another call reads a valued result

**check-clean invalid wasm · found in review of #3488 (`rv3488`: h05, h08, h12, h13, h16; h07, h09, h10, h11 are the controls) · filed 2026-10-09 against master `255fc7a6c`**

Repro:

    export function click(b) {
      b.onClick()
    }
    click({ onClick: () => print("A") })
    print("end")
    // vl check: rc 0.  vl run: the emitted module failed to validate inside `click`: expected i32 but nothing on stack

Want:

    A
    end

#### Mechanism

Not located. It is D3917's shape at a hole parameter: `click`'s tail `b.onClick()` is claimed as
its result. D3917 declines a call the checker typed `void`, but through a hole receiver the call
is typed by the template's hole, not by the record a caller passes. Asking the field's declared
type off the receiver's row at the tail does not reach it either, so the decision is made where
the receiver has no row yet. The explicit generic spelling (`click<B>(b: B)`) runs.

Two shapes fail: an exported hole function (h05, h08, and h12 with a declared record), and a
non-exported one called both with a void-field record and with a valued one whose result a
caller reads (h13, h16).
