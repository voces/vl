### D1643 — an anonymous lambda as a MODULE-LEVEL statement trapped the compiler: the inferred-return export indexed the arena with the pending-return sentinel

**closed 2026-09-05 — the witness runs · was a compiler trap (`vl check` exit 70, the seed's own `out of bounds array access`, no diagnostic printed) · fixed by bound-testing the two `T.tys[er]` reads in `checkProgram`'s A20 inferred-return export · clause 1 · found by the `*.matrix.vl` templates of #2661's capability-probe harness, three of which are the trapping shape verbatim**

Repro (before: `vl check` exit 70 with the compiler-trap banner; now: checks, builds and
prints `7`):

    (x: i32) => x
    print(7)

#### The named backtrace

`vl build compiler/entry.vl --names`, then that module as the `--compiler` seed. All three
finding templates report the same three frames at the same offsets:

    0:  0xc13ac - vl!checkProgram$m10
    1: 0x1f5ce0 - vl!checkSrc$m6
    2: 0x20e33a - vl!cliCheckCurFile$m7

#### Mechanism

An arrow lambda parses to a nameless `FuncDecl` (`parseArrowLambda`), so one written as a
bare statement at module scope is a top-level function declaration. Pass 1 hoists every
top-level `FuncDecl`'s signature, and an un-annotated return hoists as the **pending
sentinel** `-2` — `declare(s.fnName, mkFuncTy(hpt, -2))` — with the node pushed onto
`topUnannotFns` for the return-inference pre-pass to patch. That patch is keyed by name, and
an anonymous lambda's name is `""`, so its `fnRet` is never patched and the sentinel
survives the whole check.

`checkProgram`'s A20 loop — the one that records each un-annotated top-level function's
inferred concrete return name for the emitter — then walks `topUnannotFns` and reads
`T.tys[er]` where `er` is that `fnRet`, twice, before its own `er >= 0` test at the recording
rung. `T.tys[-2]` is out of bounds and the seed dies. Both reads were already standing
`sentinel-index-unguarded` hits, named by the ratchet's own `--why` as
`compiler/typecheck.vl:checkProgram (x2)`, and it fell by exactly those two.

A **return annotation** resolves the return at the hoist, so `hret >= 0`, the node never joins
`topUnannotFns`, and the annotated spelling has always checked clean. That single-ingredient
split is the whole family — every one of the three finding templates minimises by greedy line
removal to the same **one line**, `(i32) => i32`, which is a lambda whose parameter is named
`i32` and whose body is the identifier `i32`. The `@@…@@` placeholders are scenery: they are
inside `//` comments, and no placeholder token participates.

#### Ablation

Graded `vl check` against the pre-fix seed and the fixed one.

| ingredient | before | after |
| --- | --- | --- |
| the witness: `(x: i32) => x` as a module statement | **COMPILER TRAP** | checks clean (`Unused function ``` warning) |
| the parameter annotation removed (`(x) => x`) | **COMPILER TRAP** | rc 1 — `cannot infer a type for parameter `x`` |
| no parameters at all (`() => 1`) | **COMPILER TRAP** | checks clean |
| a block body (`() => { print(1) }`) | **COMPILER TRAP** | checks clean |
| two parameters (`(a: i32, b: i32) => a + b`) | **COMPILER TRAP** | checks clean |
| a RETURN annotation added (`(x: i32): i32 => x`) | checks clean | checks clean |
| wrapped in parentheses (`((x: i32) => x)`) | checks clean | checks clean |
| immediately called (`((x: i32) => x)(1)`) | checks clean | checks clean |
| bound to a `const` instead | checks clean | checks clean |
| moved inside a function body | checks clean | checks clean |
| moved inside a module-level `if` | checks clean | checks clean |
| moved inside a module-level block | checks clean | checks clean |
| any other bare module statement (`55`) | checks clean | checks clean |
| a named un-annotated top-level function | checks clean | checks clean |

The decisive rows are the return annotation and the position: the defect is not "a lambda",
it is a lambda that reaches the **top-level signature hoist** with no return annotation. A
`(` at module statement position is what puts it there; inside a body, an `if`, a block or a
binding it is an ordinary expression and never enters `topUnannotFns`.
