### D3339 — a literal-holding binding delivered where a numeric field changes width or kind is not adopted, so its whole-value uses keep master's emit refusals

**closed · runs, prints `1.3333333333333333` then `5` · was a loud emit reject · owner ruling (A), 2026-09-30: the binding adopts the record fully, and every read sees it · fixtures `tests/cases/soundness/record-literal-binding-adopts-wider-numeric-record.vl`, `tests/cases/soundness/error-record-literal-binding-adopted-read-at-own-width.vl` · closed 2026-09-30**

Repro:

    type J = { f: f64 }
    const il = [{ f: 4 }]
    const ic: J[] = il
    print(il[0].f / 3)
    const z = il.map((e) => e.f)
    print(z[0] + ic.length)
    // vl check: rc 0.  vl run: emitProgram: this list is built as `J[]` for a declared destination,
    // and is handed on here at its own element type

#### Mechanism

A binding that holds only literals adopts the record it is delivered to (DECISIONS.md "Record
covariance: only a fresh value widens"), but NOT when the destination stores one of its numeric
fields at another width or kind (`i32` into `i64` or `f64`, at any depth): adopting would change
what its reads compute. `il[0].f / 3` would turn from integer into float division, `1` into
`1.3333333333333333`, and `e.f + 1` over `2147483647` from `-2147483648` into `2147483648` (the
#3312 review's `h01`-`h12`, `g03`, `g05`, `f17`). Such a delivery keeps master's behaviour: the
emitter builds the literal at the destination and serves reads at the literal's type, and a
whole-value use at the literal's own type (`il.map`, a call's argument, an object literal field,
an `if` join with an own-type list) is its emit refusal. Where master built invalid wasm the
checker refuses instead: a record a function built into a bare float field, and one binding
handed on at its own type after such a delivery.

**Question for the owner.** May an adopted binding's reads change width? The ruling says the
binding "adopts the destination type", which read literally makes `il[0].f` an `f64` and prints
`1.3333333333333333`, the value of the annotated twin `const il: J[] = [{ f: 4 }]` (the D3246
precedent, "each equal to its annotated twin"). Recommendation: yes, adopt, and record the moved
values as #3296 did; the parked rows then run.
