#### Mechanism

A delivery position threads the shape a literal must build through the emitter's `pending*`
seeds (`pendingListKind`/`pendingListSlot`, `pendingStructIdx`, `pendingMapSlot`). The direct
call resets them per argument and re-seeds them from the callee's parameter; the two value-call
lowerings did not. `emitCallRef` (a `const` lambda, a closure parameter, a closure field, an
indexed closure) seeded only a struct row from the `$fnsig` key, and `emitCapturedCall` (a
capturing nested function) seeded nothing, so a literal argument read the seeds the enclosing
binding, field, element, map value, return, argument or `??` default had set for the CALL's
result. Both now seed every container shape from the parameter (`seedValueArgShape` from the
key's kind and slot, `seedParamArgShape` from the declaration) and leave the seeds neutral
afterwards, as the direct call does. The checker was never involved: the arguments were
already typed by the callee's parameters.

#### Ablation

| ingredient removed | outcome | needed? |
| --- | --- | --- |
| the closure (a top-level, generic or `self` function) | runs | **yes** |
| the record field (an annotated binding `const b: Clip[] = f([0])`) | same invalid module | no |
| the destination's annotation (`const b = f([0])`) | runs | **yes** |
| the list literal argument (`f(0)`, or `const rs = [0]; f(rs)`) | runs | **yes** |
| the `Clip[]` result (an `f64[]` or `i64[]` destination) | invalid module (ref mismatch) | no |
| a nested-list or record argument instead | loud emit reject (`nested arrays are not supported`, `object literal is missing …`) | no |
