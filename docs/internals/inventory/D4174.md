### D4174 — a generic's `match` join of a `K` pin, `null` and a non-member string in an array literal prints the string as a member

**closed · runs, prints `a` `null` `z` · was check-clean invalid wasm, clause 1 · closed by keeping a nullable bare type parameter apart from a concrete arm in `joinTys` (`nullParamBesideBare`), as [D2906](D2906.md)'s rule keeps a bare one, with the null as the wrapper · fixture `generics/match-join-of-nullable-param-keeps-concrete-arm.vl` · found by the D3336 position matrix (`matchnull_generic_{elem,coalkn}_un`) · filed 2026-10-11**

Repro:

    type K = "a" | "b"
    function g<T>(a0: T, k: i32) {
      const xs = [match k {
        0 => a0
        1 => null
        _ => "z"
      }]
      print(xs[0])
    }
    const x0: K = "a"
    g(x0, 0)
    g(x0, 1)
    g(x0, 2)
    // vl check: rc 0.  vl run: prints `a`, `null`, `b`

Want:

    a
    null
    z

#### Mechanism

A `match` joins its arms left to right, so `a0` and `null` join first, to `T | null`.
`tyParamBesideBare` keeps a bare `T` apart from a concrete arm (D2906), but `T | null` is not
bare, so `"z"` fell through to `assignable`. Inside the body a type parameter takes anything, so
the join absorbed `"z"` and typed `T | null`. At `T := K` the list was the `K | null` niche, and
`"z"` was stored at it. The `if` chain nests its join, so `null` met `"z"` first and it ran. Any
concrete third arm was absorbed in the same way: a non-literal `string`, or an `i32`.
