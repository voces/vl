#### Mechanism

Inside a generic body `xs ?? [false]` over `T[] | null` is typed `T[]`, because `[false]` is
assignable to `T[]` through `T` (D2799). At `T := f64` the default is built as an `f64` list, so
the null arm answers `is f64[]` and prints `0` where the direct spelling (`xs: f64[] | null`)
types the join `f64[] | boolean[]` and prints `dflt`. D2799's emit refusal covers the pins where
the two lists have different storage; a boolean list and a number list are both built from
numbers, and refusing them would refuse the value arm, which runs correctly on master. The close
is D2799's: type the `??` apart, which needs [D2843](D2843.md).

The string-pin face (`xs ?? [1]` bound, then returned, at `h(["a"])`) was invalid wasm on master
and is now D2799's loud emit reject.

Re-graded 2026-09-27 on master `1df19732b`: still prints `0`, and the grading list's
`xs ?? [1]` at `h<boolean>(null)` still prints `true`. Neither a correct build nor a refusal
without a lost run is reachable at the emitter: the instance's `??` is typed `f64[]`, so the
default has no second arm to be boxed under, and refusing the pin refuses `h([2.5])`, which
runs. The close is typing the `??` apart, which needs [D2843](D2843.md).
