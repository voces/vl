### D1864 — dogfood: a union narrowed to its MAP arm loses its map rep when a PRIOR narrowing already ran, so `std:json`'s documented `m[k]` / `m.size` cannot be reached

**loud emit reject · filed 2026-09-07 against master `0f9fbbdda`**

Repro:

    import { Json, JsonError, parseJson } from "std:json"

    type JsonMap = { [string]: Json }

    const row = parseJson("{\"a\": 1}")
    if row is JsonError {
      print("err")
    } else {
      if row is JsonMap { print(row.size) } else { print("not an object") }
    }
    // vl check: rc 0.  vl build: emitProgram: field access receiver is not a struct
    // the index spelling `row["a"]` refuses too: emitProgram: map op receiver is not a map

#### Mechanism

`parseJson` answers `Json | JsonError`, and `Json` itself is a six-member union whose object
arm is a map. The FIRST narrowing (`row is JsonError`, taken in the `else`) leaves the binding
typed as `Json`, and the SECOND (`row is JsonMap`) types it as a map for the checker while the
emitter can no longer classify the value as one — `.size` falls off the struct-field classifier
and `[k]` off the map-op classifier, two sentences over one mechanism. Narrowed once it works;
narrowed twice the map arm alone is lost, which is why the ablation and not either message is
what names this row.

The cost is not hypothetical: `std:json`'s own header says objects are VL maps "so `m.has(k)`
sits beside `m[k]`", and the shape every consumer writes — guard the error, then branch on the
value — is exactly the one that refuses. It is the reason `scripts/seed-size.py` cannot be
ported to VL today: reading `{"bytes": N}` out of the parsed baseline is this program.

#### Ablation

| ingredient removed | outcome | needed? |
| --- | --- | --- |
| the outer `is JsonError` guard (`if row is JsonMap { print(row.size) }`) | runs, prints `1` | **yes** |
| the map arm — the same shape over `Json[]` behind the guard | runs, prints `2` | **yes** |
| the map arm — the same shape over `string` behind the guard | runs, prints `hi` | **yes** |
| `.size` for `.has("a")` behind the guard | refuses the same way | no |
| `.size` for `row["a"]` behind the guard | refuses: `map op receiver is not a map` | no |

#### Grading list

The three running controls above are the row's own boundary and must keep running: a fix that
closes this by disturbing the array or string arm behind the same guard has moved the family,
not closed it. `std/json.vl`'s header promises `m.has(k)` beside `m[k]`, so a close owes both
spellings at the twice-narrowed position, not only the one this witness prints.
