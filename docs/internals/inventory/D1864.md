#### Mechanism

**Measured at the classifier, one rung at a time.** `exprMap`'s `Ident` arm asks
`narrowedMapOf` first, and at the twice-narrowed spelling it answers `""` while every other
rung answers no as well — though the checker's own recorded type says map:

    twice   MAPRECV row narrowedMapOf=[] declared=0 param=0 global=0 nodeTyIsMap=1

Inside `narrowedMapOf` the two spellings agree on everything except the last rung:

    once    NARROW row slot=0 v=[{[string]:boolean|f64|string|Json[]|{[string]:Json}|null}]
                       ty=66 unMemIsMap=1 atomKind=-1 bareMap=1
    twice   NARROW row slot=1 v=[JsonMap]
                       ty=66 unMemIsMap=1 atomKind=-1 bareMap=0

The narrow slot banks the ALIAS the program wrote (`JsonMap`) where the first narrowing banked
the RENDERED `{[K]: V}` spelling, and the final rung is `nameIsBareMap(v)` — a name test that
cannot see through an alias. **The arena row is identical at both** (`ty=66`, `unMemIsMap=1`),
and `narrowedMapOf` has already consulted it one guard earlier to reject non-map narrows. So
the answer was in hand and a spelling vetoed it.

The close renders the map name from that row when the name test declines. It is the family's
recurring shape — a name-keyed answer where the arena already knows — and the guard above it is
what makes the render safe: only a narrow `unMemIsMap` has confirmed can reach it.
