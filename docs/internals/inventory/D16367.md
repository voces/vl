### D16367 — a `Map` or `Set` keyed by one string literal is refused as an unsupported key

**closed 2026-11-15 — the witness runs and prints `true` · was: loud check reject · `A "a"-keyed Set isn't supported yet — Map/Set keys must be string, i32 or i64` · clause 2 · `Set<"a" \| "b">` and `Set<7>` run · bucket (f), a local rule · found ablating D16360 · filed 2026-11-15 against master `c8d93774`**

Repro:

    const s: Set<"a"> = Set()
    s.add("a")
    print(s.has("a"))
    // vl check: A "a"-keyed Set isn't supported yet

Want:

    true

#### Mechanism

A literal-union key hashes as the atom `i32` it reps as (`mapKeyRepTy`), but a lone string literal
is a `TyLit`, not a union, so the key gate refused it. Every other container slot stores one as
its one-member set (D7446, D7449). The map key now does too: `mkMapTy` and `tyPinKey`, the key's
one writer, store it as the set, and `mapKeyRepTy` answers that set's hash. An inferred key
(`s.add(a)` with `a: "a"`) is also delivered at the pinned set (`recordCtxTy`), as D16360 delivers
a first value.

#### Ablation

| ingredient changed | outcome | needed? |
| --- | --- | --- |
| `Set<"a" \| "b">` | runs | **yes** (one literal) |
| `Map<"a", i32>` | was the same refusal; runs | no (a map) |
| `const a: "a" = "a"; const s = Set(); s.add(a)` | was a check reject; runs | no (inferred) |
| `m[a] = 5` into an un-annotated `Map()` | runs | no |
| `Set<7>` | runs | **yes** (a string literal) |
