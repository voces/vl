### D14501 — a list of an instance's own lambda has no reflist row at its instance type, so its binding's rep cannot be read from that type

**runs today and must keep running · 5 fixtures (`closures/written-let-in-*-instances`, `generics/fn-held-in-generic-same-typaram`) · filed 2026-10-26 against master `8fb015d29`**

Repro:

    function other<V>(v: V) { print("O"); print(v) }
    function g<T>(x: T) {
      let k = other
      k = (n) => {
        print("L"); print(n)
      }
      const fs = [k]
      fs[0](x)
    }
    g(3)
    g("s")

Want:

    L
    3
    L
    s

#### Mechanism

At the `g<i32>` instance `fs`'s binding type substitutes to `((i32) => void)[]`, and
`repOfNodeAt` answers `reflist` for it, but `repSlotOfKind` finds no reflist row at that type:
the function-list rows of a lambda written in a generic body are minted at the stub's signature
(D4123), not at each instance's. `letBindRepClaims` therefore declines and the binding's cell
still comes from `letLocalSlot`'s list ladder, which reads the row off the initializer. The cell
is the rep of the instance type once each instance mints its own row there.

The iterated, record-field and three-instance spellings, and `fn-held-in-generic-same-typaram`.
