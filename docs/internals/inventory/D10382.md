### D10382 — [CLOSED 2026-11-08] a generic delivered to an un-annotated parameter and handed on to a generic's function parameter at two types is typed at the first

**closed 2026-11-08, runs and prints `4` · was loud check reject, `argument 1: expected (string) => string, got (i32) => i32`, clause 2 · closed by leaving a hole that flows into two different function types unsolved (`holeFlowsToTwoFns`, check_fn_decl.vl), so the call binds it per call as `Fn#id`; mono binds `run`'s `U` from the value arguments for such a parameter as for a named generic (`monoArgIsHeldGeneric`), and hands the bundle's member at the parameter's type · pins: `tests/cases/functions/hole-param-generic-handed-to-generic-at-two-types.vl`, `tests/cases/functions/error-hole-param-concrete-fn-handed-at-two-types.vl` · found closing [D10310](D10310.md) · filed 2026-10-22 against master `34af3ccc6`**

Repro:

    function id<T>(x: T): T { x }
    function run<U>(f: (x: U) => U, u: U): U { f(u) }
    function take(a) {
      print(run(a, 2) + run(a, "ab").length)
    }
    take(id)
    // vl check: rc 0.  vl run: 4

Want:

    4

#### Mechanism

The solve of `take`'s parameters (`solveUnannotParams`) took the first function type the hole
flows into, `(i32) => i32`, and the second use was checked against it. The hole parameter `a` takes the function type of its first use as an argument of
`run`, `(i32) => i32`, and the second use at `string` is then checked against it, where direct
calls of `a` at two types are accepted.

#### Ablation

| ingredient removed | outcome | needed? |
| --- | --- | --- |
| the second call `run(a, "ab")` | runs, `2` | **yes** |
| `run` replaced by direct calls `a(2)`, `a("ab")` | runs, `4` | **yes** |
| the order: the `string` call first | the mirrored check reject, `a` typed `(string) => string` | no |
