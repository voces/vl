**closed 2026-11-16 · runs, prints `4` `6` · fixed by lane AE4: a hole parameter's pin takes the tagged list its argument holds (`nodeTyIxOf`, where the elaboration types no argument), as the elaboration binds the instance and the caller builds the literal · fixture `tests/cases/closures/hole-fn-list-param-subset-set-calls.vl` · was check-clean invalid wasm · clause 1 · found closing [D16744](D16744.md) · filed 2026-11-16 against master `7de99c68a`**

Repro:

    function inc0(a) { return a + 1 }
    function dbl(a) { return a * 2 }
    function run(xs) { print(xs[0](3)) }
    run([inc0, dbl])
    run([dbl])
    // vl check: rc 0.  vl run: invalid module, "inside `run$1` … type mismatch: expected (ref null $9), found (ref $7); $9 is `list of i32-represented elements` … $7 is `((i32)=>i32)[]`"

Want:

    4
    6

#### Mechanism

A smaller set handed beside a larger one is decided with it (`ftSubNeed`) and tagged at the
larger set's member ids. So the caller builds `[dbl]` as an id list, and the elaboration binds the
instance's parameter at the larger set. The instance's signature came from mono's hole pin
(`monoPinHoleParam`, `emit_mono.vl`), which read `elabCallParamBoundTy`: an open function list for
a literal argument the elaboration types no node for. That left a closure-list parameter that
neither the caller nor the body agreed with. The pin now takes the argument's own type where it is
a tagged list, as it already did for a single tagged function.
