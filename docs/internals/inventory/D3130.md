### D3130 — a `{[i32]: boolean}` map field read through an un-annotated parameter's instance prints the raw i32

**check-clean silently wrong · pre-existing on master `a29230611` · found by the #3278 review grid's `mb_*_unann_use` cells · filed 2026-09-28 against master `a29230611`**

Repro:

    type H = { m: {[i32]: boolean} }
    function f(): H {
      const v: {[i32]: boolean} = Map()
      v[0] = true
      { m: v }
    }
    function use(r) {
      const e = r.m
      print(e[0] ?? false)
    }
    use(f())
    // PRINTS 1

Want:

    true

#### Mechanism

Not traced. The instance for `use`'s hole reads the map value as the i32 cell a boolean map
stores, and `print` formats it as a number, so the read or the `??` result keeps an `i32` type
where the pin says `boolean`. It is the same shape as [D3127](D3127.md), where the element read and
the `??` result hole are resolved at the template's types rather than at the pin.
