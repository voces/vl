### D15536 — a returned hole lambda's second delivery compared its function type by index, not as a type

**runs today and must keep running · refutation pin for `monoDeliverCallRets`' second-delivery check · closed 2026-11-07 by reach (the check compares with `tySame`) · filed 2026-11-07 against master `a5ce5b99`**

Repro:

    const h = (u) => { return u }
    print(h("s"))
    function deliver() { return h }
    const v: (n: i32) => i32 = deliver()
    const w: (n: i32) => i32 = deliver()
    print(v(3) + w(4))
    // runs today. With monoRetsReachHoleLam reading the elaboration's static fact, the second
    // delivery refused "`deliver` returns one function value and its calls deliver it at two

Want:

#### Mechanism

`monoDeliverCallRets` records the function type a returned hole lambda is first delivered at, and
refuses a later delivery at another. The record and the later delivery are each built by
`nameToTy` from the annotation's spelling. Two spellings of one type can land at two indices, and
the check compared them with `==`. On master the gate in front of it closes after the first
delivery, because mono's own slot for the returned read is instanced by then, so the second
delivery never reached the comparison. With the gate reading the elaboration's static fact, which
stays open, it did, and refused a program delivering one type twice. Measured on master
`a5ce5b99`: `prev` and `at2` print `(i32) => i32` both, `tySame` true.

#### Ablation

| --- | --- | --- |
| the second delivery (`w`) | runs | **yes** |
| the annotation on `w` (another type) | refuses, correctly | **yes** |
