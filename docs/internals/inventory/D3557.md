### D3557 — an INFERRED list of anonymous records cannot be delivered to a generic `T[]` parameter, while the built-in list methods take the same list

**loud emit reject · clause 2 · `emitProgram: only i32, i64, f64, f32, boolean, struct, union, array, or string parameters are supported` · found by lane BI's std prototypes (`builtin-methods-to-std.md` prerequisite 6) · filed 2026-10-03 against master `fae55dec2`**

Repro (`vl check` rc 0; `vl run` refuses at emit):

    function len<T>(xs: T[]): i32 { xs.length }
    const xs = [{ x: 1 }, { x: 2 }]
    print(len(xs))

Want:

    2

#### Mechanism

The list's element type is an anonymous record that only inference names, and the
monomorphizer binds `T` to it at the call. The instance's parameter then classifies as none of
the reps the parameter ladder accepts, so the emitter refuses the signature. The same list
reaches every BUILT-IN list method (`xs.map`, `xs.filter`, `xs.slice`) because those never
form a generic instance. This blocks moving those methods to `std:array`: `std:array.reverse`
over the same `xs` refuses with the same sentence today.

#### Ablation

| ingredient removed | outcome | needed? |
| --- | --- | --- |
| the inference: `const xs: { x: i32 }[] = …` | runs, prints 2 | **yes** |
| the record: a named `type P = { x: i32 }` with `const xs: P[]` | runs | **yes** |
| the generic: `function len(xs: { x: i32 }[])` | runs, prints 2 | **yes** |
| the list: one inferred record into `function len<T>(x: T)` | runs | **yes** |
| the binding: the literal `len([{ x: 1 }, { x: 2 }])` | refuses, same sentence | no |
| a second field (`{ x: 1, y: "a" }`) | refuses, same sentence | no |
| the callee: `xs.reverse()` from `std:array` | refuses, same sentence | no |
| a free `mapB<T, U>(xs: T[], f: (T) => U)` with an UN-annotated lambda | refuses, same sentence | no |
| the same `mapB` with the lambda annotated `(p: { x: i32 }) => …` | runs | the annotation pins the element |
| the built-ins `xs.map((p) => p.x + 1)`, `xs.filter(…)`, `xs.slice(1)` | run | the built-ins are not generic |

#### Grading list

`xs.reverse()` with `import { reverse } from "std:array"` over the inferred list; the free
`mapB` with an un-annotated lambda; the returning position `function first<T>(xs: T[]): T`;
and the lane-BI prototypes `mapA`/`filterP` over the same list once D1484 lets their
un-annotated callback type.
