#### Mechanism

Two producers each push a value-union row for `J`'s nullable composite, and the second does not
find the first by type, so the table holds two rows for one type (step 7: one row per type).
Both rows carry the same name, so `unRowBySid` reaches only one of them. No module difference
results: the emitted type section is identical to the swapped declaration order's.

#### Close

Blocks step 7's close: one row per type holds even where the module bytes do not differ. Owner: lane G, after its member-set change. The fix shows the duplicate gone under the duplicate-row probe, with a sweep. A newtype's row beside its base's (`NtI32|null` / `i32|null`) is distinct by design and is not this row.

#### Grading list

- `tests/cases/maps/recursive-alias-declared-first.vl` keeps running and printing as filed.

#### Fixed

`registerInlineUnionGo` checks the type key at its top, then walks the union's members. On this
recursive union, that walk reaches the same type at another site, and the inner call mints the
row. The outer call then minted a second row without looking again. It now re-checks the key and
adopts the row before minting. Under the duplicate-row probe (two rows whose types are `tySame` and
`tyEq`), the corpus population goes from 2 programs to 0: this fixture and the D1037 witness.
