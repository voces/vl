### D14040 — a record type's struct-or-variant storage is chosen per node, so `repOfTy` cannot decide it

**runs today and must keep running · refutation pin for step 7 PR 0 · filed 2026-10-26 against master `4d8bf5400`**

Repro:

    type J = { r: i32 }
    type N = { r: i32 | null }
    const a: J | string = { r: 5 }
    function take(b) { return b.r + 1 }
    print(take({ r: 7 }))
    const keepN: N = { r: null }

Want:

    8

#### Mechanism

An anonymous record type that is canon-equal to a union arm (`{ r: i32 }` beside `J | string`)
has no single storage. A hole-pin instance (`take`'s `b`) mints a struct row for it in
emit_mono. An un-annotated literal with no struct row takes the arm's variant row
(`objLitVariantIdxNoStructRow`, `letObjLitVariantIdx`). `tyIxIsVariantMember` holds only for the
arm's own arena index, so `repOfTy` answers `struct` for the twin and the program runs. The type
rule step 7 asked for, "a record that is a union member is `variant`", was tried as
`variant` when the type is canon-equal to an arm and has no struct row. It asks
`repSlotOfTy` before the hole-pin mint has run. `take`'s parameter then reads as `variant`
with no row, and the program fails with `emitProgram: ref valtype with no interned shape`
(about 20 corpus files moved runs → not-runs, among them
`tests/cases/soundness/record-literal-into-hole-beside-union-member-row.vl` and
`tests/cases/soundness/generic-identity-literal-into-union-beside-own-row.vl`). The structural
fix: the hole-pin row mint follows `repOfTy`. Decide struct or variant once per type, before
any row is minted, and have the mint and every literal read that one answer.
