### D15930 — an element read of a fresh list delivered into a record that stores a field wider keeps the list at its own row

**closed · now runs, prints `12` · was check-clean invalid wasm, clause 1 · filed 2026-11-12 against master `0f6984ee` · closed 2026-11-12 against master `1a13277a`: an element read of a list literal, of a generic declared to return `T[]` or a `T` identity handed one, of a binding holding that call, or of an inferred function's list stamps the literal at the destination's list (`recAdoptNote`'s index arm, check_fit_rules.vl); the read lands the list's calls where it lands (`recLandingIn`), the generic's own-type parameter does not decide a relayed landing (`recListRetArgRelayed`), and an inferred function whose value is such a read is built at the destination (`recFnBuiltAtDst`, `recFreshListRead`) · fixture `soundness/fresh-list-element-built-at-wider-record-runs.vl` · template `fresh-list-element-into-nullable-field.matrix.vl` · the same family's generic spelling is [D15893](D15893.md), closed with it**

Repro:

    type Circle = { r: i32 | null }
    const c: Circle = [{ r: null }][0]
    print(c.r ?? 12)

Want:

    12

#### Mechanism

`recElemWalk` (check_program.vl) clears an element of a list literal, or of a call whose result
is inferred, as built where it is delivered, so the checker accepts the `{r: null}` into
`Circle`. The record solve only stamped a literal held in a binding (`const ks = [...]; ks[0]`).
A literal indexed directly, or handed through a generic, stayed at its own `{r: null}` row, and
its element was stored into a `Circle` slot.
