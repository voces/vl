### D2293 — a method shorthand meant for `looksLikeObject`'s ambiguous positions, with its body brace on the next line, reads as two unrelated statements with no diagnostic naming the adjacency rule

**loud check reject, but the wrong one — a generic cascade names neither the missing adjacency
nor the method shorthand at all · found while closing [D2292](D2292.md)'s residual, 2026-09-24**

Repro:

    function mk() {
      greet()
      { "hi" }
    }
    print(mk().greet())
    // vl check: two errors, neither mentioning `greet` as an intended method or the newline —
    // "undeclared identifier 'greet'" at 2:3, then "member access '.greet' on non-object void"
    // at 5:14 (the outer print, once `mk()` is void because its body is a block, not an object).

#### Mechanism

D2292 requires a method shorthand's body brace to sit on the same line as the closing `)` of
its parameter list, so `looksLikeObject` (`compiler/parser.vl`) never mistakes a call-then-
brace-tail pair of statements for a bogus signature. The same rule silently defeats a genuine
attempt: a user who intends `greet() { "hi" }` but breaks the line before the `{` gets the
block reading, `greet()` becomes an ordinary call to an undeclared name, and the diagnostic
cascade that follows never mentions the adjacency requirement.

No fix is attempted here because none is safe at parse time: the ambiguous shape before the
decision — `IDENT(...)` followed by a NEWLINE then a brace-led statement — is EXACTLY the shape
every one of D2292's own fixtures relies on being read as two ordinary statements
(`print("mk")` then `{ x: n }`). A lookahead cannot tell "the user meant a signature and typo'd
the line break" from "the user wrote a call and a following object/block on purpose" without a
signal neither `looksLikeObject` nor its caller currently has (identifier naming conventions,
declared-type context, or similar heuristics all risk misfiring on legitimate two-statement
code, which is the common case this rule exists to keep working).

#### Ablation

| ingredient | outcome |
| --- | --- |
| body brace on the next line, first statement `greet()` | two unrelated errors, no adjacency diagnostic |
| body brace on the same line (`greet() { "hi" }`) | runs — resolves as a method (D2292) |
| a real two-statement call-then-brace body (`print("mk")` / `{ x: n }`) | runs — correctly read as a block (D2292) |

#### Grading list

A future fix must not regress D2292's own fixtures — any diagnostic added here fires only when
it cannot also be a legitimate call followed by its own object/block statement, which the
ablation above shows is not decidable from the shape alone. `tests/cases/parser/call-first-
stmt-then-brace-tail.vl` and `tests/vl_fmt_test.ts`'s dedicated same-line-shorthand test are
both on the grading list for any change here.
