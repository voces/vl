### D2487 — a map-typed generic parameter has no monomorphization pin for any concrete key or value type

**closed · runs, prints `1` at `{[i32]: string}`; the `{[string]: T}`/`.has(k)` twin prints `true` `false` · was loud emit reject, `vl check` rc 0, `emitProgram: monomorphize: unsupported argument type …`, clause 2 · clause 2 · found by the collections critics against master `0a0d24ac9`, filed 2026-09-25 · closed by binding the type parameter from the argument's arena type against the parameter's, walking the two together, rather than matching the argument's spelling (`monoBindArenaWalk`, `monoPinTyParamComposite`, emit_mono.vl) · fixture `generics/generic-arena-bind-map-and-alias.vl` · closed with [D9820](D9820.md)**

Repro:

    function tot<T>(m: {[i32]: T}): i32 { m.length }
    const m: {[i32]: string} = Map()
    m[1] = "a"
    print(tot(m))
    // vl check: rc 0.  vl run:
    // emitProgram: monomorphize: unsupported argument type for `m` in a call to `tot`

Want:

    1

#### Mechanism

Not ablated to a rung. `tot`'s parameter `m` is a map type whose VALUE is the type parameter,
`{[i32]: T}`. Calling it with a concrete `{[i32]: string}` map refuses at monomorphization — the
same message as D2486's `T | string`. The same shape with a `{[string]: T}` key type and a
`.has(k)` body instead of `.length` refuses identically, over both a `{[string]: i32}` and a
`{[string]: string}` map. A non-generic version of the same function (a concrete
`m: {[i32]: string}` parameter, no `<T>`) runs, so a map parameter with `T` in the value
position is what the monomorphizer's argument-typing rung cannot classify — a sibling of
D2486's union case, not the map body's own `.length`/`.has` lowering, both of which work fine on
a non-generic map.
