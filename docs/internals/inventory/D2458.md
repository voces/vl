### D2458 — an un-annotated declared function passed as a value to a generic HOF has no monomorphization pin

**closed 2026-10-09 by lane SC, with D3913 · runs · was loud emit reject · clause 2 · found reviewing #3152, filed 2026-09-25 against master `20651a88b` · pins: `tests/cases/generics/named-hole-function-to-generic-callback-parameter.vl`**

Repro:

    function show(a) { return a + 1 }
    function run<T>(cb: (T) => i32, v: T) { return cb(v) }
    print(run(show, 3))
    // vl check: rc 0.
    // vl run: emit error, emitProgram: monomorphize: unsupported argument type for `cb` in a
    // call to `run`.

#### Mechanism

D3913's. A declared function with a hole parameter is generic to the monomorphizer, and
`monoArgFnTypeName` answers "" for it, so `cb: (T) => i32` had nothing to bind `T` from. The value
argument `3` had already pre-bound `T`. Closed with D3913: a generic function value takes the arrow
parameter's annotation substituted at those bindings, and the witness prints `4`.

#### Ablation

| ingredient changed | outcome | needed? |
| --- | --- | --- |
| `function show(a: i32)` | runs, prints 4 | the un-annotated parameter: **yes** |
| `show<U>(a: U)` | runs, prints 4 | **yes** |
| a lambda `(a) => a + 1` | runs, prints 4 (since D2426) | the declared function: **yes** |
