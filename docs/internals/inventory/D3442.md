### D3442 — a record with an integer field delivered through a generic identity call to a record that stores it as `f64` builds invalid wasm

**closed · runs, prints `3.5` twice · was check-clean invalid wasm · a generic identity hands its argument's adoption through; a literal argument into a flat float field is a loud check reject · fixtures `tests/cases/soundness/record-literal-binding-adopts-through-generic-identity.vl`, `tests/cases/soundness/error-record-literal-through-generic-identity-into-float.vl` · found by the #3322 review (`rv3322-6397`) · filed 2026-09-30 against master `afb0ecc08`, closed 2026-09-30 by lane RC3**

Repro:

    type D = { v: f64 }
    const q = { v: 7 }
    print(q.v / 2)
    function idd<T>(x: T): T { x }
    const d: D = idd(q)
    print(q.v / 2)
    // vl check: rc 0.  vl run: invalid module in the top-level code,
    // "type mismatch: expected (ref null $type), found (ref $type)"

Want:

    3.5
    3.5

#### Mechanism

The storage rule follows a generic identity call (a bare `T` result from one `T` parameter) to
its argument and judges `q` fresh, so the checker accepts the delivery. Adoption does not
follow it: `recAdoptNote`'s call arm (`compiler/typecheck.vl`) looks through a pass-through
argument only to refuse a literal built at a declared row (`recBuiltAtDeclared`), never to note
the binding, so `q` keeps its `{v: i32}` storage and `idd` is instantiated at it. The emitter
then hands that `{v: i32}` struct to a `D` slot with no conversion, the same missing
integer-to-float conversion `recFloatBuiltElsewhere` refuses for a function's result. That
last step is read off the ablation, not confirmed by a scratch fix. `i64` and `i32 | null`
fields run, so the gap is specific to crossing from an integer to a float.

**Close (lane RC3).** The adoption note follows a generic identity (nested identities and a
join inside one included) to a literal binding and adopts it, so `idd` is instantiated at `D`
as for the twin; the list-widening walk follows it too. `take(idd(q))`, `first(q, 1)` and the
`i64` face run at the twin's values. `idd({ v: 7 })` has no binding to adopt and the identity's
instance holds the integer, so into a flat float field it is now a loud check reject, not
invalid wasm (`i64`, `i32 | null` and a nested record already ran); a fresh call handed through
an identity is judged as at a direct delivery.

#### Grading list

- The `idd({ v: 7 })` spelling, which has no binding to adopt: the fix has to build or convert
  the literal, not only adopt a binding.
- The argument face `take(idd(q))`.
- D3441, whose generic-identity face at `i64` reads the binding at its own width.
- The `f32` face, which is D3443's refusal and should move with it.
