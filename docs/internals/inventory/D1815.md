Repro:

#### Mechanism

The parser built `Member(OptMember(o, "y"), "z")`, so the `.z` read the chain's own type —
`Leaf | null` — and the plain member arm refused it. One `?.` guards everything to its right
in every language that has the operator, so the chain's tail belongs INSIDE the guard, not
after it.

`parsePostfix` now carries a `guarded` flag: once a chain has taken a `?.`, every later `.`
in it becomes a guarded link too (`OptMember` with `omDot` recording that the source spelled a
plain dot). The emitter needs no new arm — the normalised shape is the one `x?.y?.z` already
ran. What `omDot` buys is PRECISION at the checker: a guarded link reads through the link
below's guarded type, so `o?.y.z` over a `y` that is itself `Leaf | null` still refuses with
the same sentence and the same fix (`o?.y?.z`), rather than silently folding a second null.

`drwWalk` folds a guard whose receiver cannot be null back to the plain read, for the reason
`x ?? d` over a non-nullable left operand folds: the null arm is unreachable and the
standalone `?.` lowering has no rep to build for a result the guard never widened. That fold
also closes `a?.y?.z` over a non-nullable `a`, which was a loud emit reject.
