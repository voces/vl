### D3398 — a hole called at two map types shares one binding of its map read, typed at neither pin, so a miss reads the raw zero

**closed 2026-10-27 · runs, prints `null` twice (a hit prints `7` then `1.5`) · was a loud emit reject, clause 2 · filed 2026-09-30 against master `8df60e472` · fixed by the D14432 slice: a map read's box takes its atom from the instance's receiver (`mapRecvScalarBoxKindIn`), and an un-annotated binding's box cell names the row of its own type at that instance (`letNulScalarBoxName`) · pins: `tests/cases/maps/two-instance-map-read-binding-miss.vl`**

Repro:

    type A = { m: {[i32]: i32} }
    type B = { m: {[i32]: f64} }
    function mkA(): A {
      const v: {[i32]: i32} = Map()
      v[3] = 7
      { m: v }
    }
    function mkB(): B {
      const v: {[i32]: f64} = Map()
      v[3] = 1.5
      { m: v }
    }
    function use(r) {
      const x = r.m[9]
      print(x)
    }
    use(mkA())
    use(mkB())
    // prints 0 twice

Want:

    null
    null

#### Mechanism

A scalar map read's `V | null` needs the value box, which an un-annotated binding gets from an
annotation `synthNullableAnn` writes onto the `LetDecl`. Both instances share that node, and
the annotation is written from the program's one banked pin (`nodeTyPinIxOf`), which two
disagreeing pins collapse to none. So neither instance gets the box, and each binds the raw
scalar. The read itself is right per instance (`mapRecvTyIn` asks the instance's binding
first), which is why the unbound spelling runs. The fix needs a per-instance cell kind for a
shared binding, the same spine question as [D1816](D1816.md).
