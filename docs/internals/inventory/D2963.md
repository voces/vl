### D2963 — the checker admits an `i32[]` spread into `(f32 | null)[]`, a widening it refuses for the element itself

**check-clean invalid wasm · clause 1 · found grading D2882's element types · filed 2026-09-28 against master `03dcbcfac`**

Repro:

    const a: i32[] = [3, 4]
    const q: (f32 | null)[] = [...a]
    print(q.length)
    // vl check: rc 0.  vl run: invalid module in the top-level code

#### Mechanism

The checker refuses the scalar delivery (`const x: f32 | null = i` with `i: i32` is
`cannot assign i32 to 'x' of type f32 | null`), and `i32` to `f32` is not one of the three
lossless widenings D965 measured. The spread's element check admits it anyway, so the emitter
finds no member the `i32` elements box under or widen to (`spreadSrcBoxAtom`) and falls to the
plain copy, which stores the `i32` backing in a list of union boxes. The owed answer is the
checker's refusal at the spread, as for the scalar.
