### D11800 — `vl fmt` moves a comment written between two links of a broken `.` chain to after the statement, and joins the chain

**closed 2026-10-24 — the witness runs, prints `3`, and `vl fmt` returns it unchanged · was a `vl fmt` relocation on a `vl check`-clean program · filed 2026-10-24 against master `a7f78e005` · fixed by breaking a chain whose links hold a comment between them (`chainCommentedLink`) and hosting the comment in `chainBroken` above the link it preceded, a trailing one at the end of the link line · fixture `tests/cases/parser/leading-dot-comment-between-links.vl` restored; `tests/vl_fmt_test.ts` pins the grading list**

Repro (runs, prints `3`):

    const xs = [1, 2, 3]

#### Mechanism

The witness RUNS, and the status line says so, because the defect is in `vl fmt`, which the
filed-witness grader does not drive (the D1646 shape). `compiler/format.vl`'s fit-or-break
chain layout (`chainLayout`) returns "" when `commentInCharSpan` finds a comment in the chain,
the same guard as the one-line `if` collapse, so `memberAccess` prints `obj + "." + prop` and only a sub-chain below the comment is laid out again.
The plain member printer has no slot for a comment between two postfix links: the comment is flushed after
the enclosing statement, and the links around it are not broken at the comment. A long chain
with a comment between links comes out partly joined (`.map(…)[0].inner?.n`) with the comment
below it. It is meaning-preserving for the program and lossy for the reader, and it is why the
fmt-clean `tests/cases/` corpus cannot hold a comment between two chain links:
`parser/leading-dot-comment-between-links.vl` had been reduced to a one-line chain by the
corpus fmt sweep, and that layout is now pinned in `tests/vl_paren_newline_test.ts` instead.

#### Ablation

| ingredient removed | outcome | needed? |
| --- | --- | --- |
| the comment line between `.map(…)` and `.length` | fmt keeps the chain as written (it fits, so joined, with nothing moved) | **yes** |
| `///` in place of `//` | same relocation | no |
| a chain too wide for one line | comment still moves, and the links after it are joined onto the link above | no |

#### Grading list

A comment before a leading `?.` link (`hit` / `.inner` / `// …` / `?.n`); a comment between
two CALL links of a chain too wide to fit; the `if`-collapse and `match`-arm comment slots
(D1646), which share the "never relocate a comment" rule.
