### D2956 — a `??` over a bounded `T | null` parameter drops its default from the call's type

**closed 2026-10-04 — the witness prints `5` · was check-clean invalid wasm · clause 1 · the #3243 review · filed 2026-09-28 against master `e9fdc10d9`, closed by lane NJ against master `32b753681` · fixture `tests/cases/generics/coalesce-bounded-param-keeps-default.vl`**

Repro:

    type P = { x: i32 }
    function g<T: { x: i32 }>(a: T | null) {
      const r = a ?? 5
      r
    }
    const n: P | null = null
    const v: P | i32 = g(n)
    if v is P { print(v.x) } else { print(v) }
    // vl check: rc 0.  vl run: invalid module inside `g`

Want:

    5

#### Mechanism

[D3580](D3580.md)'s: a `??` over a declared parameter typed as the parameter whenever the default
was assignable to it, which a type parameter always is. It now joins as its `if` spelling does,
so the call is `P | i32`.

#### Ablation

| ingredient removed | outcome | needed? |
| --- | --- | --- |
| the `null` in the parameter (`a: T`, argument `{ x: 3 }`) | invalid wasm in the top-level code, as on master | no |
| the type parameter (`a: P \| null`) | runs, prints `5` | **yes** |

#### Grading list

The bound removed (`<T>`), and a non-null argument (`const n: P | null = { x: 2 }`, want `2`).
The non-null parameter in the table's first row is a separate top-level defect with the same
record pin.
