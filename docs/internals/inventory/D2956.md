### D2956 — a `??` over a bounded `T | null` parameter drops its default from the call's type

**check-clean invalid wasm · clause 1 · open · identical on master `e9fdc10d9` · the #3243 review · filed 2026-09-28 against master `e9fdc10d9`**

Repro:

    type P = { x: i32 }
    function g<T: { x: i32 }>(a: T | null) {
      const r = a ?? 5
      r
    }
    const n: P | null = null
    const v: P | i32 = g(n)
    if v is P { print(v.x) } else { print(v) }
    // vl check: rc 0.  vl run: invalid module inside `g`

Want:

    5

#### Mechanism

Not localised past the ablation. The call `g(n)` is typed `P`: `const z: string = g(n)` reports
`cannot assign P to 'z'`. The concrete `??` over `P | null` with an `i32` default is `P | i32`. The
`5` is dropped from the call's type, and the instance returns a record slot for it.

#### Ablation

| ingredient removed | outcome | needed? |
| --- | --- | --- |
| the `null` in the parameter (`a: T`, argument `{ x: 3 }`) | invalid wasm in the top-level code, as on master | no |
| the type parameter (`a: P \| null`) | runs, prints `5` | **yes** |

#### Grading list

The bound removed (`<T>`), and a non-null argument (`const n: P | null = { x: 2 }`, want `2`).
The non-null parameter in the table's first row is a separate top-level defect with the same
record pin.
