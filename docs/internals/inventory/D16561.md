### D16561 — a radix tail beside a typed `i32` arm of a value join is read at the join's 64-bit destination or peer, where ruling 4.3 makes the join `i32`

**closed · runs, prints `-1` · was check-clean silently wrong · clause 1 · found by the arith fuzz (`ar_s5_0107`), graded by the coordinator under ruling 4.3 (2026-11-15) · filed 2026-11-15 against master `bcc1a353f` · closed 2026-11-15 by lane N: `radixLitAdoptTails` leaves a join with a typed 32-bit tail at 32 bits (`radixJoinTyped32`), so its literals adopt that arm and the `i32` join widens at its use · fixture `literals/radix-tail-beside-typed-arm-adopts-arm.vl`**

Repro:

    let v3: i32 = 255
    const c = v3 >= v3
    const k: i64 = 1
    print((if c { 0xFFFFFFFF } else { v3 }) * k)

Want:

#### Mechanism

D2617 delivers each radix tail of a value join to the join's destination, and a radix operand
takes an `i64` peer's width (`radixLitAdoptPeer64`), so the tail read `0xFFFFFFFF` as 4294967295
even where a typed `i32` arm makes the join `i32` (ruling 4.3: the literal adopts the typed value
first). The same join bound first (`const j = …`) is `i32` and printed `-1`.
