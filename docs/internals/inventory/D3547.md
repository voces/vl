### D3547 — `g() is L` for a numeric literal union over a lambda joining two parameters answers false at a pin of members

**closed 2026-10-03 by lane KJ — the witness prints `true` twice · was check-clean silently wrong, clause 1 · found by the #3344 review (`rv3344-aZMQ/isg`, `il__lamjoin__one-one`) · filed 2026-10-03 against master `f6e17953b` · fixture `tests/cases/generics/lambda-join-is-numeric-literal-union.vl`**

Repro:

    type L = 1 | 2
    function F<A, B>(k: i32, x: A, y: B) {
      const g = () => { if k == 0 { x } else { y } }
      print(g() is L)
    }
    F(0, 1, 1)
    F(1, 1, 1)
    // vl check: rc 0.  vl run: prints false twice

Want:

    true
    true

#### Mechanism

The lambda's call is not a re-readable place, so the membership test over `L` fell through to
the name fold, which answered `false` for an `i32` receiver without reading it: the mechanism
of [D3570](D3570.md), which closes this too. The lambda's collapse at the call
([D3520](D3520.md)) was not an ingredient at this pin.
