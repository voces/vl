#### Mechanism

D2869's boxing spread boxes each source element under its own value atom, so a source whose
element is not a member of the destination's union but widens to one (`i32` to `f64`, `i64`)
needs the scalar converting copy (`emitScalarListWidenTop`) first. Chaining the two was tried
and built invalid wasm (the `f64` list's types are not collected when only the union names
`f64`), so D2869 leaves such a source to the plain copy, which puts the `i32` backing in the box list.

Closed without the chain: the boxing loop converts each element itself (one `f64.convert_i32_s`,
`i64.extend_i32_s` or `f64.promote_f32` between the read and the box), so no `f64` list is ever
built. `spreadSrcBoxAtom` picks the member a source boxes under, its own atom first and then the
lossless widenings in `unionStoreAtomKind`'s order. Both grading-list pairs run, graded with the
`spread-literal-widen-box-nullable-f64*` matrix templates at every position.
