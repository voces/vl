Repro:

    type P = { x: i32 }
    type Q = { y: i32 }
    type UU = P | Q
    const p: P = { x: 1 }
    const xs = [if true { p } else { p }]

    // was: vl check rc 0, then exit 70, expected i32, found (ref $type). Now prints 1.

#### Mechanism

Not `arrLitIsRef`, which claims the literal correctly — `arrLitNominalElemName` answers `P`
and the disassembly shows the ref backing built: `(array.new_fixed $4 1 (if (result i32) …
(global.get $global$0)))`. The i32 is the IF-EXPRESSION's own blocktype.

`ifExprRefKind` classifies a ref join from the deciding arm through a ladder — closure,
string, the five list kinds, map, struct — and carried a `variant` rung only inside its
NULLABLE half. A concrete union arm is neither: with the union declared, `p` classifies as a
variant, so `structIndexOfExpr` answers -1, every rung declines, and `emitIfExpr` falls
through to `emitIfExprAs(ifExprValtype(...))`, whose default is i32. That is why deleting
`type Q` and `type UU` makes the identical literal run — it is what stops `p` being a variant.

`exprVariantIndex` gains the same arm on the destination side, so the un-annotated binding,
return, assignment and capture positions resolve the cell's rep too. It is gated on every arm
denoting the SAME row: arms denoting different rows join to the union BOX, which
`emitUnionCoerce`'s own if-value path builds, and answering a concrete row for those turns
`tests/cases/unions/union-if-value-variant.vl` from `runs` into invalid wasm — measured, and
the gate is what the fixture now pins.
