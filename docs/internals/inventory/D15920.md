### D15920 — a record of un-annotated functions joined by an `if` and bound, handed to an un-annotated parameter the callee binds to a second name and calls through, is refused at emit

**closed · clause 2 · runs since lane I taught the mint facts' parameter walk (`elabParamRowRoot`, `elabElemRead`) to read through an un-annotated alias of the parameter, a `const` or a `let` nothing re-points · found grading [D15807](D15807.md) (the record matrix's `argument` cell, whose callee aliases its parameter) · filed 2026-11-12 against master `0671904bf`**

Repro:

    function inc0(a) { return a + 1 }
    function half(a) { return a / 2.0 }
    function two() { [1, 2].length }
    function __take(a) {
      const v = a
      print(v.f(3) + v.f(4))
    }
    const r = if two() > 5 { { f: half } } else { { f: inc0 } }
    __take(r)

Want:

    9

#### Mechanism

A call an instance makes through a field of a parameter its callers forward a hole into is
noted by `elabMintParamRowFactAt` (`emit_elab.vl`), and that note puts the set in front of the
decision after the elaboration (`mintFwdFieldSetsOf`). Two things stopped at the alias. One was
`elabParamRowRoot`, which followed `const v = a` but restarted its step count there, so it took
`a` for the receiver itself. The other was `elabElemRead`, which took a field read only of a
receiver declared as a `Param`. Through the alias the set was never tried, so the joined record
was built as closures and refused by #7517's floor. Both now read through an un-annotated alias
(`elabConstParamAlias`).
