### D1861 — a map declared in a MODULE-LEVEL BLOCK and captured by a closure: check-clean invalid wasm at a string key, a loud emit reject at an i32 key

**CLOSED 2026-09-07 — the captured-map shape resolver reads the owning frame as an ARENA index, the conversion the env field's own resolver already made, so the two tables answer with one slot; it RUNS at every map value type, both key reps and both faces. Was: check-clean invalid wasm at a string key and a loud emit reject at an i32 one · found by B6a's position matrix (`i32-keyed-map-in-container.matrix.vl`, its six `*_capture` cells, which now read 46 of 46 RUNS)**

The closure's ops resolved the map's SHAPE to the mono struct while the env field carried the
interned one. At a STRING key the engine refused the module — `type mismatch: expected i32,
found f64` inside the closure — a clause-1 violation `vl check` could not see; at an i32 key the
emitter reached `emitProgram: map key is not a string` first, off that same mono answer, so one
defect wore a loud message on one face and none on the other. Neither was about the KEY, and
neither was about the block alone: a map whose value rides the shared mono vals list (`i32`,
`boolean`) was correct by accident.

Repro:

    if true {
      const c: {[string]: f64} = Map()
      c.set("a", 2.5)
      const f = () => {
        c.set("b", 3.5)
        print(c.get("b") ?? 0.0)
      }
      f()
    }
    // vl check: rc 0.  vl run: invalid module — the emitted module failed to validate
    //   inside `f`: type mismatch: expected i32, found f64

#### Mechanism

`mapShapeOfExpr`'s captured-map arm asked `parentBindingFrameOf` for an `fnStmts` POSITION and
indexed `fnStmts[cpar]`, so a MODULE-frame block binding — which has no such position — fell
through to the mono map `-1`, while `captureValStructIdx` had already typed the env field from
the annotation and answered the interned slot. The probe printed the pair: for the same program
in a function body `b=3 kind=map annSlot=0 frame=28`, and in a module-level block `b=4 kind=map
annSlot=0 frame=-1`. The env row was never wrong; the shape rung could not ask. It now reads
`parentBindingFrameArenaOf` — where the module frame IS `-1` — with the annotation rung ahead of
it, which is the order and the pair of rungs the env field's resolver uses.
