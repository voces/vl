### D17581 — a read of an un-annotated map holding a hole function, delivered at an annotated function type, is refused by the mono pin's closed-type lookup

**loud emit reject · clause 1 (check accepts what emit refuses) · open · `vl check` rc 0 · found by COV-CLOS's Q58 sweep of the map-read twin retag · filed 2026-11-25 against master `265592ab2`**

Repro:

    function inc(a) { return a + 1 }
    const m = Map()
    m["k"] = inc
    const g: ((a: i32) => i32) | null = m["k"]
    if g != null { print(g(3)) }
    // vl check: rc 0.  vl run: emit error at 3:7, "emitProgram: internal: a function slot pinned
    // at one signature has no one closed type the elaboration delivers it at"

Want:

    4

#### Mechanism

`m`'s value type comes from the un-annotated `inc` written into it, a hole function pinned at one
signature (`emit_mono.vl`'s pinned-slot lookup). Delivering a read of `m` at an annotated
function type, by a binding or an argument, makes the write's slot ask for the one closed type the
elaboration delivers it at, and it finds none. The same read bound with no annotation runs. Not
ablated into the emitter further.

#### Ablation

| ingredient removed | outcome | needed? |
| --- | --- | --- |
| the annotation on `g` (`const g = m["k"]`) | runs, prints 4 | **yes** |
| the map (`const g: ((a: i32) => i32) \| null = inc`) | runs, prints 4 | **yes** |
| the binding, the read passed to a `((a: i32) => i32) \| null` parameter instead | still refuses | no |
| the `\| null`, the read narrowed first and passed to a `(a: i32) => i32` parameter | still refuses | no |
