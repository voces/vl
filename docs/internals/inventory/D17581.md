### D17581 — a read of an un-annotated map holding a hole function, delivered at an annotated function type, is refused by the mono pin's closed-type lookup

**closed 2026-11-25 · runs, prints `4` · was: loud emit reject, `internal: a function slot pinned at one signature has no one closed type …`, clause 1 (check accepts what emit refuses) · fixed by `monoSlotDeliveryTy` reading a stored slot delivered at `F | null` as `F` (emit_mono.vl) · found by COV-CLOS's Q58 sweep of the map-read twin retag · filed 2026-11-25**

Repro:

    function inc(a) { return a + 1 }
    const m = Map()
    m["k"] = inc
    const g: ((a: i32) => i32) | null = m["k"]
    if g != null { print(g(3)) }
    // vl check: rc 0.  vl run: prints 4 (was: emit error at 3:7, "emitProgram: internal: a
    // function slot pinned at one signature has no one closed type the elaboration delivers it at")

Want:

    4

#### Mechanism

`m`'s value type comes from the un-annotated `inc` written into it, a hole function pinned at one
signature (`emit_mono.vl`'s pinned-slot lookup). Delivering a read of `m` at an annotated
function type, by a binding or an argument, makes the write's slot ask for the one closed type the
elaboration delivers it at. The slot's class signature (`eplSlotSig`) is the read's delivery type
`((a: i32) => i32) | null`, the `| null` being the map miss's, and the lookup demanded a bare function
type. The close reads a stored slot delivered at `F | null` as `F`; the cell and list callers of
`monoSlotDeliveryTy` keep the exact type, since a cell or element typed `F | null` may hold `null`.
