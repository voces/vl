### D14572 — the elaboration answers a generic instance's binding with another instance's type

**runs today and must keep running · refutation pin: the instance copy's minted binding type (`monoTpJoinBindAnn`) is right here and the elaboration is not, so the mint cannot yet be deleted · deletion target with D14430's per-instance mint · filed 2026-10-28 against master `873368d69`**

Repro:

    function len<T>(f: () => T | string) {
      const t = f()
      if t is string { t.length } else { 100 }
    }
    function outer<U>(x: U) { print(len(() => x)) }
    outer("abc")
    outer(2.5)
    outer(7)
    outer("hello")
    function outerAnn<U>(x: U) { print(len((): U | string => x)) }
    outerAnn("abcd")
    outerAnn(1.5)

Want:

    3
    100
    100
    5
    4
    100

#### Mechanism

In `len`'s instance at `T = string`, the instance copy mints `const t`'s type as `string`, and
the elaboration's binding type for the same node reads `i32 | string`, the type of the instance
reached from `outer(7)`. A shadow note comparing the two (`VL_REP_SHADOW=1`) shows it in
`tests/cases/generics/enclosing-param-into-generic-union.vl`. The elaboration keys the binding
by node, not by node and instance. The witness still prints right with the mint deleted,
because no reader of `t` decides on the binding type today, so this row is graded by the shadow
note. The per-instance mint (D14430's slice (c)) is the change that lets the elaboration answer
here.
