### D2250 — an if/else value compared to null inline emits an invalid module

**closed 2026-09-23 — the witness prints `true` · was check-clean invalid wasm: the inline if/else's value took an `i32` blocktype over box arms · filed against master `3330dcaa3` · fixture `tests/cases/conditionals/if-join-nullable-inline-consumers.vl`**

Repro:

    function f(c: boolean, a: i32 | null, b: i32 | null) {
      print((if c { a } else { b }) != null)
    }
    f(true, 1, null)
    // vl check: rc 0.  vl run: invalid module,
    // "type mismatch: expected i32, found (ref $type)"

#### Close

The prediction was wrong about the rung. The compare's operand ladder was right: it asked
`exprUnion` of the if/else, got `true`, and read the box's tag. The disagreeing side was
`emitIfExpr` — a value-position `if` picks its blocktype from `ifExprRefKind`, which has no
union rung, then falls to the numeric `ifExprValtype`, so an `i32 | null` join emitted `if
(result i32)` over two `(ref $uBox)` arms. Only a union DESTINATION (`emitUnionCoerce`'s
`IfStmt` arm) knew to lower the join as the box, which is why binding it to a local first ran.
`emitIfExpr` now routes a join through `emitUnionIfValue` itself when the join's OWN recorded
type names a union (`ifJoinUnionName`), so every consumer — `== null`, `is`, `??`, an argument,
`print` — reads the box. It must not ask the then arm: in `if n != null { n } else { -1 }` the
arm keeps its declared `i32 | null` while the join is `i32`, and the first cut of this fix,
gated on `exprUnion` (which reads the then arm), broke that everyday shape; it is pinned by
`tests/cases/conditionals/if-join-narrowed-arm-stays-scalar.vl`. The same
change retires the `bare null needs a struct-typed context` emit refusal for `if c { a } else
{ null }` and `else if` chains over a nullable scalar, which died on the same scalar blocktype.

#### Mechanism

The failure needs the if/else's value to feed the `!=`/`==` null compare directly: binding
it to a local first (`const v = if c { a } else { b }; v != null`), or returning it from a
function and comparing the call's result outside, both run. The if/else's own value-lowering
(`emitIfExprRef`, `wasmEmit.vl`) picks a nullable ref blocktype for the join and leaves a
`(ref null $ht)` on the stack; the compare's operand ladder (`emitNulIsNullTest`, the
`exprUnion`/`nodeTyIsNulNumLitUnion` rung at `wasmEmit.vl:2276`) expects a specific shape for
a nullable-primitive-union operand and disagrees with what the if/else actually leaves only
when it is inlined rather than staged through a local. Not yet ablated to the exact
disagreeing rung; a prediction, to be graded by the close. The `f64 | null` spelling of `a`/`b`
fails identically, same message.

#### Ablation

| ingredient removed | outcome | needed? |
| --- | --- | --- |
| the if/else (compare a plain parameter instead) | runs | **yes** |
| binding the if/else's value to a local (or returning it from a function) before the compare | runs | **yes** |
| the compare operator (`==` for `!=`, or vice versa) | still invalid wasm | no |
