### D2250 — an if/else value compared to null inline emits an invalid module

**check-clean invalid wasm · `vl check` rc 0, then the emitted module fails validation
inside the enclosing function, clause 1 · no map involved · found while extending the
D2247 value-type grid to a bare `i32 | null` if/else join · filed 2026-09-23 against
master `3330dcaa3`**

Repro:

    function f(c: boolean, a: i32 | null, b: i32 | null) {
      print((if c { a } else { b }) != null)
    }
    f(true, 1, null)
    // vl check: rc 0.  vl run: invalid module,
    // "type mismatch: expected i32, found (ref $type)"

#### Mechanism

The failure needs the if/else's value to feed the `!=`/`==` null compare directly: binding
it to a local first (`const v = if c { a } else { b }; v != null`), or returning it from a
function and comparing the call's result outside, both run. The if/else's own value-lowering
(`emitIfExprRef`, `wasmEmit.vl`) picks a nullable ref blocktype for the join and leaves a
`(ref null $ht)` on the stack; the compare's operand ladder (`emitNulIsNullTest`, the
`exprUnion`/`nodeTyIsNulNumLitUnion` rung at `wasmEmit.vl:2276`) expects a specific shape for
a nullable-primitive-union operand and disagrees with what the if/else actually leaves only
when it is inlined rather than staged through a local. Not yet ablated to the exact
disagreeing rung; a prediction, to be graded by the close. The `f64 | null` spelling of `a`/`b`
fails identically, same message.

#### Ablation

| ingredient removed | outcome | needed? |
| --- | --- | --- |
| the if/else (compare a plain parameter instead) | runs | **yes** |
| binding the if/else's value to a local (or returning it from a function) before the compare | runs | **yes** |
| the compare operator (`==` for `!=`, or vice versa) | still invalid wasm | no |
