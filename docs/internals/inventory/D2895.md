### D2895 — a hole function's nested lambda called at a single `f64 | string` pin builds invalid wasm

**check-clean invalid wasm · clause 1 · found by #3231's review (`b1.vl`) · the same on master `8e10ef58b` · filed 2026-09-27 against master `8e10ef58b`**

Repro:

    function mk(x) {
      const c = (y) => y
      const r = c(x)
      return r
    }
    const u: f64 | string = 2.5
    const w = mk(u)
    if w is f64 { print(w / 2.0) }
    // vl check: rc 0.  vl run: invalid module inside `mk`

Want:

    1.25

#### Mechanism

Not localised. One instance only, so this is not [D2854](D2854.md)'s shared body: the lambda's
parameter is typed at its own variable and lowers at a scalar default, while the value passed
is the `f64 | string` box. A pin at the union would have to carry the box into the lambda.

#### Ablation

| ingredient changed | outcome | needed? |
| --- | --- | --- |
| an `f64` argument | runs | **yes** |
| `return x` without the lambda | runs | **yes** |
