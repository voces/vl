### D2895 — a hole function returning a local that holds its record-union pin builds invalid wasm

**check-clean invalid wasm · clause 1 · found by #3231's review (`b1.vl`) · the same on master `829bd497c` · filed 2026-09-27 against master `8e10ef58b` · #3233 fixed the value-atom half (`f64 | string`, the original repro); this row now carries the record half**

Repro:

    type A = { a: i32 }
    type B = { b: string }
    function mk(x) {
      const c = (y) => y
      const r = c(x)
      return r
    }
    const v: A | B = { b: "hi" }
    const w = mk(v)
    if w is A { print(w.a) } else { print(w.b) }
    // vl check: rc 0.  vl run: invalid module inside `mk`

Want:

    hi

#### Mechanism

Not a lambda defect: `const r = x; return r` at the same pin is invalid too. An un-annotated
return that no rung of `monoMakeInstance`'s return ladder names falls to the functype's `i32`
seed; the ladder's last rung reads the checked return at the instance's binding and holes but
annotated only a join bearing `null` or a list. #3233 adds a union of value atoms there
(`f64 | string`, `i32 | string`, `boolean | i32`), which is what the original repro needed.
Its first version boxed every value union and was pulled in review: at a RECORD-union pin it
re-annotated an identity function's result, which broke complement narrowing of the caller's
un-annotated binding (`if c is A {…} else { print(c.b) }` became `field access receiver is not
a struct`) and renumbered union tags in three fixtures. So a union with a record, map or
reference-list arm is left out (`monoTyHoldsRefArm`), and this repro still fails. A fix here
must keep complement narrowing working on the pinned record union.

#### Ablation

| ingredient changed | outcome | needed? |
| --- | --- | --- |
| an `f64 \| string` pin | runs (since #3233) | **yes** |
| `return x` directly | runs | **yes** |
| `const r = x` in place of the lambda | still invalid | no |
