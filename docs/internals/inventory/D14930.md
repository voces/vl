### D14930 — a re-pointed `let` of a generic listed inside a function called at two instances runs only through `monoPinListElems`

**runs today and must keep running · step 4 (γ) family C of `monoPinListElems`' flat path · with that pin cut to return early the witness is a loud emit reject (`a function value's signature is not known at this call`), so the pin is the only producer of each instance's element signature · capture-cell join territory ([D14425](D14425.md)) · pins: `tests/cases/closures/written-let-in-list-called-in-two-instances.vl`, `written-let-in-two-element-list-called-in-three-instances.vl` · found ablating family W · filed 2026-11-02 against master `ea74167bd`**

Repro:

    function other<V>(v: V) { print(v) }
    function g<T>(x: T) {
      let k = other
      k = (n) => { print(n) }
      const fs = [k]
      fs[0](x)
    }
    g(3)
    g("s")

Want:

    3
    s

#### Mechanism

`k` is a `let` first bound to a generic and re-pointed to a hole lambda, so it is a capture cell
holding one function per instance. The list literal `[k]` reads that cell, and the checker types
the list at `k`'s open signature. Only the flow-table pin `monoPinListElems` reads gives each
instance's list its closed element type. The fix is the per-instance join of a written `let`, not a
closed signature for the list.

| the list (`k(x)` directly) | runs | **yes** |
| the type parameter (`function g(x)`) | emit reject | no |
| the generic initialiser (`let k = (n) => ...` first) | runs | **yes** |
