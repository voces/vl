### D15273 — two bindings of one function's returned record, one written another function, refuse when the unwritten one's field is called

**closed · runs · was loud emit reject `emitProgram: cannot take the generic function id0 as a value — a function value carries ONE signature` · clause 2 · either binding alone runs · the read spelling runs · found grading D15270 · filed 2026-11-04 against `lane/g2-d15270-call` `9c379a287` · closed by the elaboration joining every binding a call of one function initialises**

Repro:

    function id0(a) { return a }
    function id1(a) { return a }
    function mk() { return { f: id1 } }
    const r = mk()
    r.f = id0
    const s = mk()
    print(r.f(2))
    print(r.f(2.5))
    print(s.f(7))

Want:

    2
    2.5
    7

#### Mechanism

`mk` returns one literal, and both `r` and `s` read it. `r`'s field was widened to `{id0, id1}`
and `s`'s was not, so `s.f(7)` adopted the literal at the call's closed row
(`holeFieldCallAdopt`), the smaller set `{id1}` failed its scan, and `r`'s set stayed untagged.
`elabFnFieldTy` now joins, for a binding a call initialises, what every other binding a call of
the same function initialises stores at the field (`fnFieldCalledWith`), so `s` is widened too
and its call dispatches. A second function's literal (D15274), an unbound call (D15275) and two
returned literals (D15277) stay open.

#### Ablation

| ingredient removed | outcome | needed? |
| --- | --- | --- |

| `s.f(7)` read as `const h = s.f; h(7)`, `r.f` likewise | runs | **yes** (the direct call) |
| `r` (only `s`, its field called at two types) | runs | **yes** |
