### D15711 — a list literal's ref-list row kind comes from its element spelling, so keying that row by the build type alone splits kind from key

Repro:

    const ei: i32[] = []

Want:

#### Mechanism

`collectAArrayLit` mints the literal's ref-list row with `rlInternNameTy(arrLitElemName(i, -1),
elemKind, arrLitMintHintTy(i))`. The kind (`arrLitElemKind(i, -1)`) is read off the element
spelling, and the literal's elements are built at that kind. The refused change passed the
literal's build element type (`tyStepElem(arrLitBuildTy(i))`) as the key for every closed element.
Here the key is `i32[] | string[]`, which finds the annotation's union-box row (kind 2), while the
literal builds its element as a raw `i32[]` (kind 4, from the spelling `i32[]`). The empty element's
`is string[]` then reads no box tag, and prints `-1` where D4939's rule prints `0`. The same split
refuses two programs at the type-index pass. In
`closures/written-binding-of-generics-delivered-by-list-of-lists-literal.vl` (`((i32) => i32)[]`)
and `lists/spread-boxes-nested-and-pushed.vl` (`(string | i32)[]`), a kind-9 row records an element
type whose inner slot (`rlInnerSlotOfElem`, by type) was never interned. That gives "a list-of-lists
element has no inner list shape". The reader that must take the type before the key does is the
literal's kind, `arrLitElemKind`, together with the element build that reads it.
`2026-11-11-step7-l2-arrlit-placeholder-rekey.md` keeps that change to closures and lists of `string`
or `u8`.
