#### Mechanism

`collectAArrayLit` mints the literal's ref-list row with `rlInternNameTy(arrLitElemName(i, -1),
elemKind, arrLitMintHintTy(i))`. The row's kind follows its type (`rlElemKindAt` reads
`rlElemTyIx`), but its stored name (`rlElemName`) is the spelling of whichever caller mints it
first. The refused change passed the literal's build element type (`tyStepElem(arrLitBuildTy(i))`)
as the key for every closed element. Here the literal is collected before the annotation and mints
the `i32[] | string[]` row under its placeholder spelling `i32[]`; the annotation then finds that row
by key. `g[0] is string[]` reaches `emitListEmptyFitArms`, which takes the box's arms from
`unionNameOfExpr(g[0])`. That answers the row's stored name, `i32[]`, and not the union, so the test
loses D4771's empty-other-arm clause and keeps only the `string[]` tag test. The empty `i32[]`
element prints `-1` where D4939's rule prints `0`. (Probed: under the refused change `nm` is
`i32[]` at that site.) The two refusals are the same first-minter name read back as the element's
shape. In `closures/written-binding-of-generics-delivered-by-list-of-lists-literal.vl`
(`((i32) => i32)[]`) and `lists/spread-boxes-nested-and-pushed.vl` (`(string | i32)[]`), a kind-9
row is named `i32[]`, and its element type's inner slot (`rlInnerSlotOfElem`, by type) was never
interned. That gives "a list-of-lists element has no inner list shape". The reader that must take the
type before the key widens is the row's stored name read back as the element's union name or shape
(`unionNameOfExpr` over an element read). `2026-11-11-step7-l2-arrlit-placeholder-rekey.md` keeps the
key change to closures and lists of `string` or `u8`.
