**closed 2026-11-02 with [D3611](D3611.md) · runs, prints `1`, `2.5`, `null` · `paramNullJoin` re-marked its result as an ordinary join (or not at all when neither side was marked), and its deferred-join twin (`apartHoleJoins`) was never set, so a caller re-joined `f64 | i32 | null` widened to `f64 | null`; it now keeps the input's mark, marks a join of two or more declared parameters and `null` apart (each parameter is a runtime value), and sets the twin, so the caller reads `f64 | i32 | null` as the owner's ruling for the direct spelling has it ([D3363](D3363.md)); with the caller agreeing, the instance's refusal `monoNulJoinMixesNumbers` had nothing left to guard and is deleted · was loud emit reject · clause 2 · grading list: a 675-cell return-set grid (pins × return statements, tail `if`, `null` first × print, `is A`, `is B`, `== null`, `??`, list, a hole-body `??`, a generic `==`, binding) gains 62 and loses 0, and a 450-cell grid of readers inside the generic body (`== null`, `v == v`, a list, `??`, `is A`, returned) gains 36 and loses 0; 0 emitted-byte movers over `tests/**/*.vl` · pin: `tests/cases/generics/param-join-beside-null-kept-apart-at-number-pins.vl` · found 2026-10-03 · filed against master `e5ff25ff9`**

Repro:

    function two<A, B>(k: i32, a: A, b: B) { if k == 0 { a } else if k == 1 { b } else { null } }
    print(two(0, 1, 2.5))
    print(two(1, 1, 2.5))
    print(two(2, 1, 2.5))
    // vl check: rc 0.  vl run: the emit refusal above (before the close)

Want:

    1
    2.5
    null

#### Mechanism

The generic's own return type absorbs the null (`A | B | null`) and at `(i32, f64)` the two number
arms and the null need a box that the instance does not have, so emit refuses at the mono
instance. The non-generic twin `function two(k: i32, a: i32, b: f64) { … }` runs and prints
`1`, `2.5`, `null`, so the capability exists at the direct spelling and is missing at the pin: the
refusal names a MECHANISM, not a contract. The pins that DO run are those with a string arm, up
to the next row (D3487), which fails at run time instead.

D3487's fix keeps the null in the inferred join, which it already was in the explicit-annotation
spelling that refused the same way, so this refusal is not that row's absorbed null: it is the
floor in `monoIfChainRebuildPinned`, which refuses an `if`-chain join over two different number
pins beside a null because the concrete join of those types is order-dependent (D3363). Measured
with the floor removed, every number pin of D3487's grid printed the right value through `print`
and `== null`; the floor was kept because the numeric-join ruling's change (#3327) owns those
joins and keeps it. The same join written as three `return`s never reaches the floor, and runs.
