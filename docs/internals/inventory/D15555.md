### D15555 — a generic instance over a list of a held generic function cannot resolve its element rep

**loud emit reject · 1 hand witness (`vl_emit_diag_position_test`'s generic instance shape) · filed 2026-11-08 against master `43be4f8c` plus the held-generic call key**

Repro:

    function id<T>(x: T): T { x }
    function use<T>(ys: T[]) { print(ys.length) }
    function take(a) {
      const xs = [a]
      use(xs)
      print(xs[0]("abc").length + xs[0](2))
    }
    take(id)
    // vl check: rc 0.  vl run: emit error at line 2, `.length` receiver's ref-list element does not resolve

#### Mechanism

`take`'s hole `a` is handed the generic `id`, and the list `xs` holds it. The call key now binds
`use`'s `T` to that held generic as it stands (open only beneath a function type), so `use`'s
instance is lowered with an element type that is a generic function, and `ys.length` finds no
ref-list element rep for it. Before the key bound held generics, the same program refused later,
at the generic read in `take` (line 6). A check-clean program, so a clause-2 violation.
