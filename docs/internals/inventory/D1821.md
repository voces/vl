### D1821 — a helper whose parameter is annotated with a CONCRETE function type takes the argument the first instance pinned it with, and the checker's own refusal is lost at the pin

**loads then traps — `wasm trap: indirect call type mismatch` after printing the first pin's
value · clause 1 · filed 2026-09-06 against master `23c39222e`, named without an id by the
argument-hop row [D1795](D1795.md), whose close does not reach this spelling**

Repro:

    function o(n) {
      function k(x: i32) { return n }
      function use(p: (i32) => i32) { return p(1) }
      return use(k)
    }
    print(o(2))
    print(o(2.5))
    // vl check: rc 0, "Found 0 errors, 1 warning."
    // vl run:   prints 2, then
    //           wasm trap: indirect call type mismatch

#### Mechanism

**A prediction, not a measurement — probe the decline before changing anything.** What IS
measured is that the refusal exists at the direct spelling and is lost at the pin. The plainest
non-generic program of the same shape is refused, correctly:

    function kf(x: i32) { return 2.5 }
    function use(p: (i32) => i32) { return p(1) }
    print(use(kf))
    // [ERROR]: argument 1: expected (i32) => i32, got (i32) => f64

At the pin the same disagreement reaches `vl check` rc 0. The f64 instance's `k` is a per-pin
clone returning `f64`, and it is handed to a parameter annotated `(i32) => i32`; one `use` is
emitted at that concrete signature and the instance `call_indirect`s at it.

The predicted rung is `monoLamNodeIsTemplateCore`'s annotation pair, which asks
`monoAnnHasTyParam` of the WRITTEN annotation. A concrete `(i32) => i32` names no type
parameter, `use` captures nothing and its body names none either, so no rung fires and one
lifted `use` serves both instances. That reading predicts the ablation below and nothing more:
whether the fix belongs there or in the checker — which owes the argument diagnosis it already
gives at the direct spelling — is what a probe has to settle, and this row does not.

#### Ablation

| ingredient removed | outcome | needed? |
| --- | --- | --- |
| the SECOND pin (`print(o(2))` alone) | runs, prints `2` | **yes** |
| the CAPTURE (`k` returns `x`, not `n`) | runs, prints `1` `1` | **yes** |
| the annotation's CONCRETENESS (`use(p: (i32) => T)` on the declared face) | runs, prints `2` `2.5` | **yes** |
| the annotation itself (`use(p)`) | traps, identical | no — the un-annotated route reaches the same trap |
| the inference face (`o<T>(n: T): T`, same concrete annotation) | traps, identical | no — both faces |

#### Grading list

* The single-pin twin and the capture-free twin, which RUN today and must keep running.
* `use(p: (i32) => T)` on the declared face, which RUNS today and must keep running — it is the
  spelling that shows the ingredient is the annotation's concreteness, not the face.
* The direct spelling `use(kf)`, whose `argument 1: expected (i32) => i32, got (i32) => f64`
  must keep being refused; a close that admits the pin must not lose it.
* The un-annotated helper (`use(p)`), [D1795](D1795.md), whose row this one was split out of
  and whose fixture must keep running.
