### D16008 — the `else` arm of a record `is` test over an un-annotated parameter reads a scalar remainder at the whole argument type

**loud check reject · clause 2 · found closing [D16004](D16004.md) · present on master `7b0b9d8ac` · filed 2026-11-13 against master `7b0b9d8ac` · neighbour [D3216](D3216.md)**

Repro:

    type A = { v: i32 }
    function F(h) { if h is A { print(h.v) } else { print(h) } }
    const x: A | i32 = 5
    F(x)
    // vl check: `F` prints its type parameter here: print expects one scalar or string value (i32 | i64 | f32 | f64 | boolean | string), got A | i32
    // Should print 5; annotating `h: A | i32` does.

Want:

    5

#### Mechanism

A hole's `else` remainder (`HD_GNOT`) is not minted for a record tested type
(`holeElseRemainderOk`), so the `else` arm reads `h` at the whole pin `A | i32`, and `print`, `+`
and other scalar uses refuse it. D16004 closed the field-read form through the argument's
member-by-member demand check. A scalar use is not a demand on the argument, so that check does
not reach it. Minting the remainder for a record type moves field demands off the argument
check (D16004's refuted first attempt). This row's fix must keep them there. D3216 is the same
shape over a hole's field.

#### Ablation

| ingredient removed | outcome | needed? |
| --- | --- | --- |
| the missing annotation — `h: A \| i32` | prints `5` | **yes** |
| the record test — `if h is string` over `string \| i32` | prints `5` | **yes** |
