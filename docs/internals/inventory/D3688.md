### D3688 — a parameter spelled as a generic record alias application (`B<T>`) binds no type parameter from an argument that is not that application

**loud emit reject · clause 2: `vl check` is clean · found by lane C2 grading [D3674](D3674.md) · filed 2026-10-05 against master `56af0f07e`**

Repro:

    type B<T> = { x: T }
    function getX<T>(r: B<T>): T { r.x }
    print(getX({ x: 7 }))
    // vl check: rc 0.  vl run: emitProgram: monomorphize: unsupported argument type for `r` in a call to `getX`

Want:

    7

#### Mechanism

`monoBindFromAnn`'s generic-application arm pairs the pattern's arguments with the actual's
only when both spell the same head (`B<T>` against `B<i32>`). An anonymous record, a declared
record `V = { x: i32 }`, or an un-annotated `const a = { x: 7 }` has no `B<…>` head, so `T` binds
to nothing and the substituted pin is "". The checker resolves `B<T>` structurally and accepts
all three. A fix expands the pattern to its alias body (`{ x: T }`) when the heads differ, then
binds as [D3674](D3674.md)'s shape arm does; the pin it then needs (the argument's own row or
`B<i32>`) is the open question, since the two are different wasm types.

#### Ablation

| ingredient changed | outcome | needed? |
| --- | --- | --- |
| `const a: B<i32> = { x: 7 }` as the argument | prints `7` | **yes** (no application head on the argument) |
| a declared `V = { x: i32 }` argument | same refusal | no |
| `r: { x: T }` written inline | prints `7` | **yes** (the alias spelling) |
