### D3032 — a record literal whose field is a generic parameter is built as a declared record of the same field names in every instance, whatever `T` is bound to

**check-clean invalid wasm · clause 1 · identical on master `cac5e4ad5` and on #3259 · the generic twin of [D3024](D3024.md), found by the #3259 review · filed 2026-09-28**

Repro:

    type X = { k: i32, n: i32 }
    type U = X | { z: i32 }
    function g<T>(x: T): i32 {
      const o = { k: x, n: 1 }
      0
    }
    print(g(1))
    print(g("s"))
    // vl check: rc 0.  vl run: invalid module, inside `g$1`: type mismatch: expected i32, found (ref $type)

Want:

    0
    0

#### Mechanism

Filed as the generic twin of D3024, but the ablation shows the union is scenery: a declared
record `X` alone captures the literal, so the reader is not the union-arm matcher; the
declared-row match (`structIndexOfObj`) is the likely one, not yet printed. The kind checks read
the field's scalar kind off the literal's CHECKED type, and inside a generic body that type is
the `TyVar` `T`, whose kind is 0, "unknown", which a refutation treats as agreeing. So each
instance builds `{ k: x, n: 1 }` as `X`, and a `string` instance stores a string into its
`i32` slot. The close has to ask the instance's binding of `T`, not the body's type.

| --- | --- | --- |
