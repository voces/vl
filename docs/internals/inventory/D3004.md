### D3004 — an alias of a record literal re-seated at a wider declared record reads the field at the wider type

**closed · was check-clean silently wrong on #3253 (invalid wasm on master `b34730ad9`) · since the D3339 ruling `o` adopts `D`, and so does its alias, so `same.v / 2` prints `1.5`, its annotated twin's value · fixture `tests/cases/objects/record-literal-widened-read-any-handle.vl` · found by the #3253 review grid · filed 2026-09-28**

Repro:

    type D = { v: f64 }
    const x: i32 = 3
    const c: {[string]: D} = Map()
    const o = { v: x }
    c["k"] = o
    const same = o
    print(same.v / 2)
    // PRINTS 1.5

Want:

    1.5

#### Mechanism

One mechanism with [D3003](D3003.md): the narrowing was keyed on the receiver being an object-literal binding. Keyed on the receiver's checked record type, an alias, an alias chain and a nested field all narrow.

As filed: `same` is an un-annotated alias of `o`, which the map store re-seats at `D`. `o.v / 2` narrows to the checked `i32` on #3253 and prints `1`, but `memReadNarrowOp` asks whether the receiver's binding is an object literal, and `same`'s is an identifier, so `same.v` stays `f64` and divides as one.

#### Under the D3339 ruling (2026-09-30)

The owner ruled (D3339 (A)) that a literal-holding binding delivered to a record storing a number at another width or kind takes that record as its type at every read, as its annotated twin does. `o` is a `D`, so its alias `same` is one too and `same.v / 2` prints `1.5`, as `const o: D = { v: x }` does.
