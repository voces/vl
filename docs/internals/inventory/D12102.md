### D12102 — `is` over a list whose element is a scalar alias tests the box against the wrong list type

**check-clean invalid wasm · filed 2026-10-24 against master `492ea9482`**

Repro:

    type C = i32

    const v: C[] | string = [1, 2]
    if v is C[] {
      print(v.length)
    }
    // vl check: rc 0.  vl run: invalid module, a union box where the i32 list was expected

Want:

    2

#### Mechanism

The alias spelling `C[]` and the direct `i32[]` are one type, but the narrowed binding is not
unboxed from the union box at the `is` arm when the arm is spelled through the alias, so the box
reference reaches a slot typed as the list. The direct spelling runs.

#### Ablation

| change | outcome | needed? |
| --- | --- | --- |
| `i32[]` for `C[]` in both places | runs, prints `2` | **yes** (the alias) |
| no `is` test (`print(1)`) | runs | **yes** |
| `type C = boolean`, `[true, false]` | same invalid module | no |
| the test inside a function over a parameter `v: C[] \| string` | same invalid module | no |
| `C \| C[] \| i32` (a scalar alias arm too) | same invalid module | no |

#### Grading list

The parameter delivery (`function g(v: C[] | string): i32 { if v is C[] { return v.length } 0 }`)
and the boolean alias.
