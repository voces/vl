### D16743 — a map written two records whose function field holds un-annotated functions of different results is refused at check

**closed 2026-11-16 — the witness runs and prints `4` then `1.5` · was: loud check reject · clause 2 · found closing [D16731](D16731.md) · filed 2026-11-16 against master `71ff99b49`**

Repro:

    function inc0(a) { return a + 1 }
    function half(a) { return a / 2.0 }
    const m = Map()
    m.set("a", { f0: inc0 })
    m.set("b", { f0: half })
    print(m.get("a")?.f0(3) ?? 0)
    print(m.get("b")?.f0(3) ?? 0)
    // vl check: rc 1, "cannot write 'half' to 'm[].f0': called at (i32) it returns f64, where 'inc0', also written to it, returns i32 — every function a call through 'm[].f0' may run must return one type"

Want:

    4
    1.5

#### Mechanism

The one-result judge (`holeSlotJudge`, `compiler/check_relate_core.vl`) lifts a call through a map
entry's record field when every write is a literal (D15801), but kept judging a read through `?.`
(`holeSlotReadsOpt`), and the tag decision (`ftHoldCtxOk`, `compiler/check_fn_tag.vl`) declined
that read as a guarded call it built no member call for. The emitter builds that call: a `?.`
straight to the entry's own field of the set is lifted on both sides now. A `?.` through a record
nested in the entry stays refused ([D16809](D16809.md)).

#### Grading list

- `m["a"] = { f: inc0 }` written by index, `r?.f0(3)` on a bound `.get`, an absent key, a second
  field of another set, a loop over keys, a field re-pointed through a read of the entry: run.
- The record nested two and three levels in the map's value: still refused,
  [D16809](D16809.md).
- A named record written to an entry: still refused, as [D9370](D9370.md) records.
- [D15161](D15161.md), the map handed to a parameter: still refused.
- Two maps whose sets share a member: refused at emit on master by the bound `.get` spelling
  too, [D16749](D16749.md).
