#### Mechanism

Probed against the D7183 close. The argument `h` is the frame's own hole parameter, not a named
function, so neither the split's ask (`fsAskOpenCallPars` reads a function by name) nor the
element typing (`monoElemParamTys`) finds the function it holds.

Traced at the close: there were three gaps. The split planned `h` at two keys but its rewrite
handed `h` no slots at the list call, because `fsHoleFwd` reads only a declared callee. The
emitter never asked the split for that call. And the applied round typed the elements' parameter
`_`, because `h` is not a function name.
