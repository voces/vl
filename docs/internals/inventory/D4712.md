### D4712 — `.map` over a callback parameter that returns a union has no result list

**loud emit reject · clause 2 · found grading D4684's union delivery · the same on master `209f5d1ca` · filed 2026-10-14 against master `209f5d1ca`**

Repro:

    type Pet = i32 | string
    function mk(n: i32): Pet { return n }
    function go(f: (n: i32) => Pet, xs: i32[]) { const ps = xs.map(f); print(ps.length) }
    go(mk, [3])
    // vl check: rc 0.  vl run: emitProgram: unsupported .map/.filter element type

Want:

    1

#### Mechanism

Not yet ablated past the table. The `.map` lowering finds the result element from the
callback's function entry or lambda; a parameter holding a union-returning closure gives it
neither, and no rung reads the result from the parameter's closure signature, which D4684's
close does for a record result.

#### Ablation

| ingredient changed | outcome | needed? |
| --- | --- | --- |
| the named function as the callback (`xs.map(mk)`) | runs | **yes** |
| a record result (`(n: i32) => B`) | runs | **yes** |
| a union of records (`{ meow: i32 } \| { bark: i32 }`) | the same refusal | no |
| an annotated `: Pet[]` return of the result | the same refusal | no |

#### Grading list

* The record-union spelling, and the result returned rather than read in place.
