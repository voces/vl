### D16281 — a call through a written binding of generic functions, copied from another, is keyed at the other binding's call when the functions are declared last

**check-clean silently wrong · clause 1 · open · a declaration-order dependence (D16301's generic-value keying rung): 21 of its 38 clause-1 movers, none of which records a slot fact in either order · found splitting D16301's named set for slot-store stage 2b · filed 2026-11-15 against master `065a55686`**

Repro:

    let f = gA
    let g = gB
    f = gB
    g = f
    f(2)
    g(true)
    function gA<U>(u: U) {
      print("A")
      print(u)
    }
    function gB<V>(v: V) {
      print("B")
      print(v)
    }
    // vl check: rc 0.  vl run: prints `B`, `2`, `B`, `1`.

Want:

    B
    2
    B
    true

#### Mechanism

Not in the slot store: `f` and `g` hold annotated generics, so the elaboration records no slot
fact for either binding in either order. What moves is the instance set. With the declarations
first, the module holds `gA`, `gB` and `gB$1`, and `g(true)` reaches the `boolean` instance. With
them last, it holds `gA`, `gB`, `gA$1` and `gB$1`, all at `i32`, and `g(true)` reaches a `gB`
keyed at `f(2)`'s `i32` call. So the call through `g` is keyed from the call through `f`, its copy
source, and which instances exist when the top-level calls are elaborated depends on whether the
generic declarations were visited first. The likely owners are the value and call keys
(`elabValueKeys`, `elabCallKeys`) and the set notes of a call through a function value; this has
not yet been narrowed by an instrument.

#### Ablation

| ingredient removed | outcome | needed? |
| --- | --- | --- |
| the order (declarations first) | runs, prints `B`, `2`, `B`, `true` | **yes** |
| the copy `g = f` | runs | **yes** |
| the re-point `f = gB` | runs, prints `A`, `2`, `A`, `true` | **yes** |
| the call `f(2)` | runs, prints `B`, `true` | **yes** (a second call type) |
| both writes, as `let f = gB` and `let g = f` | runs | **yes** (a written binding) |
