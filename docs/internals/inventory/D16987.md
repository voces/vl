**closed 2026-11-18 — the witness prints `1` · was check-clean silently wrong, clause 1 · the `is`-arm summary follows a `const` the arm binds to the receiver, so the push fixes `V` as `f64` and the arm's list is the receiver's (`tpArmWriteTy`, `compiler/check_tp_arm_writes.vl`) · fixture `tests/cases/generics/empty-argument-typed-by-the-is-arm-that-writes-it.vl` · found building the `is`-arm summary for D4961 · filed 2026-11-18 against master `666291883` by lane F1**

#### Mechanism

`g([])` binds `V` to nothing, so the call takes the unbound default `i32` and `v` is an empty
`i32[]`. The `is f64[]` arm answers by emptiness (D4910) and reads a fresh empty `f64[]` in
`v`'s place (D4911). Pushed through `v` itself, that list stays `v`'s place after the arm
(D4934), but through `al` it is a local of the arm, so `v` reads its own empty list. Under
DECISIONS.md §"No default type" the arm's push is a use that fixes `V` as `f64`.

| `g(v: f64[])`, not generic | runs, prints `1` | **yes** (the type parameter) |
