### D16847 — a record `is` over an un-annotated receiver ignores the null an instance hands it

**closed 2026-11-16 — the witness runs and prints `true`, `false`, `false` · was: wasm trap · clause 1 (check-clean, traps at run) · found closing [D16325](D16325.md) · filed 2026-11-16 against master `6cd6d0210`**

Repro:

    type A = { x: i32 }
    type B = { x: 1 | 2 }
    function g(a) { return a is B }
    function pick(n: i32): A | null {
      if n > 0 { return { x: n } }
      return null
    }
    print(g(pick(1)))
    print(g(pick(5)))
    print(g(pick(0)))
    // vl check: rc 0.  vl run: prints true, false, then a wasm trap

Want:

    true
    false
    false

#### Mechanism

`emitRecordFitIs` (`compiler/wasmEmit.vl`) answered null apart only when the receiver's own
node type was nullable. An un-annotated parameter's node type is a hole, so an instance handed
`A | null` read the field of a null record. The test now also reads the instance's type.

#### Ablation

| ingredient removed | outcome | needed? |
| --- | --- | --- |
| the parameter annotated `a: A \| null` | runs | **yes** |
| `pick` returning `A` | runs | **yes** |
