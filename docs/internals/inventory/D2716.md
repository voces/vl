### D2716 — a list whose returns or `if` arms disagree about their element is built at the first literal's list type, not the joined one

**closed 2026-09-26 — the repro RUNS and prints `0.5` · was check-clean invalid wasm · 17 of the 32 cells of the lane's inferred-return grid, the annotated `const y: f64[] = if c { [2] } else { [1.5] }` among them · filed 2026-09-26 against master `90b63b840`**

Repro:

    function f(c: boolean) {
      if c { return [2] }
      return [1.5, 2]
    }
    print(f(true)[0] / 4.0)

#### Mechanism

The checker joins the two returns to `f64[]` (and `[1, "s"]` beside `["s"]` to
`(i32 | string)[]`), but the emitter took a list return's kind from the FIRST return literal
that classified (`criClassify`'s list arms are guarded by "not yet a list"), so the result was
declared `i32[]` and the `[1.5, 2]` return pushed an f64 list into it. The other half was the
build: an un-annotated function seeded only an EMPTY returned `[]` with its inferred kind, so a
`return ["s"]` beside `return [1, "s"]` built a string list into a union-element result. The
same first-arm reading decided an `if` expression's list blocktype, annotated or not. Closed by
banking the joined list type when the returns disagree (`inferJoinListTyOf`) and re-seating the
kind on it (`criJoinedListKind`), seeding every returned or arm array literal at the result's
list kind and row, and letting the join's checked type name a wide scalar list in
`ifExprRefKindOf`.

#### Ablation

| ingredient removed | outcome | needed? |
| --- | --- | --- |
| the second return (one literal only) | runs | **yes** |
| the return annotation (`: f64[]`) | the annotated spelling runs | **yes** |
| the order of the two returns | invalid wasm both ways | no |
| `return` (a tail `if` expression instead) | invalid wasm | no |
| the element width (`[1, "s"]` beside `["s"]`) | invalid wasm | no |
