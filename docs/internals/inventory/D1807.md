### D1807 — a `readonly` marker written in a FUNCTION TYPE is never read: the closure takes a callee's parameter list off a `FuncDecl` only, so a re-pointed binding and a lambda held in a field keep refusing

**loud emit reject · filed 2026-09-06 against master `4805d8fae` · D1687's residue, from the `readonly T[]` view landing · 0 corpus cells**

Repro:

    type Circle = { r: i32 }
    type Sq = { s: i32 }
    type Shape = Circle | Sq
    type Hold = { fn: (readonly Shape[]) => void }
    function __other() {
      const w: Shape[] = []
      w.push({ s: 3 })
      print(w.length)
    }
    function f() {
      const a: Circle[] = [{ r: 7 }]
      const b: Shape[] = a
      const h: Hold = { fn: (ys: readonly Shape[]): void => { print(ys.length) } }
      h.fn(b)
    }
    f()
    // vl check: rc 0.  vl run: emit error, covariant list delivery.

#### Mechanism

`cwCalleeDeclOf` places a callee by finding a `FuncDecl` in the arena — the declared function
a name binds, or the lambda a once-bound `const` was initialised with. A field read (`h.fn`)
and a re-pointed `let` bind neither, so no parameter list answers and the closure returns `2`.
D1687 named that as the row's whole mechanism and the view's ruling made it moot for a
declared parameter — but only for a declared parameter.

The missing input is not the same one D1687 lacked. That row's `fn: (Shape[]) => void` said
what the parameter IS and nothing about whether the body writes it, so reading covariance off
the type would have answered "may write" for every function value. `fn: (readonly Shape[]) =>
void` is different in kind: it says the callee may NOT write, and it says so in the type, which
the arena already carries at the annotation node. The value `fn` holds is still chosen
elsewhere, and it does not matter — every function assignable to that type has a read-only
parameter, because `readonly T[]` never converts to `T[]`.

Closing it is a second resolver beside `cwCalleeDeclOf`: where the callee expression has no
`FuncDecl`, read its recorded `TyFunc` and ask whether parameter `argIx` is a read-only list.
The re-pointed `let take = …; take = …; take(b)` spelling is the same row for the same reason.
