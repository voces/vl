### D1474 — an UNCALLED lambda whose body calls a function-typed parameter is a loud emit reject: nothing interns a `$fnsig` for that arity, and any unrelated call of the same arity makes it run

**closed 2026-09-06 — `collectCloSigs` walks every LIFTED FUNCTION's own arena type, so a
lambda's parameters intern their `$fnsig` the way a declaration's parameter annotation always
did · was a loud emit reject at `vl check` rc 0, clause 2, the LAMBDA spelling only · filed
2026-09-03 against master `cdfdc14e`, closed against `91b299d5d` · 0 corpus cells**

Repro (two lines; ran as an emit reject at 1:38, now prints `7`):

    const apply = (f: (i32) => i32) => f(1)
    print(7)

#### Mechanism

MEASURED by the position matrix below, not read off the call site. `emitCallFnValue` resolves
the call `f(1)` through `cloSigPosOfKey`, falls back to `fnSigIdxForArity(args.length)` and
refuses when that is `-1`; it is `-1` because nothing interned an arity-1 closure functype.
**The missing mint is the ROOT SET, not the call.** `collectCloSigs`'s last pass walks
`cloSigWalkRoots` — the annotations `collectInlineUnions` recorded — and its `FuncDecl` arm
pushes every PARAMETER's and the RESULT's arena type, so a declaration whose parameter is
function-typed interns that parameter's `$fnsig` whether or not anything calls it. A lambda is
an EXPRESSION: its statement is a `LetDecl`, whose arm pushes only the binding's own
annotation, so the lambda's parameters reached no root. That is why annotating the binding
fixed it, and why an unrelated arity-1 call did too — either one mints the key from somewhere
else.

The close gives every LIFTED function its own arena type as a root, after the existing roots
so each key they mint keeps its slot. One loop; the walk is idempotent, so a declaration —
whose parameters are already roots — interns nothing new.

That the fix had to be the root set and not a fallback at the call is what the position matrix
says: **the refusal reached seven positions no `LetDecl` fix could see** — an object field, a
list element, a lambda returned from a function, a lambda nested in another lambda's body, and
both module-level block scopes.
