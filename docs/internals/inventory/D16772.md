### D16772 — a list a kept maker's build stores at a wider record is refused where it is handed to an un-annotated parameter or returned from an un-annotated function

**loud check reject · clause 2 · CAPABILITY: the annotated parameter and the annotated return run · `this container's {f: null} elements are stored at J, the row its stores build; handing it on as {f: null}[] is type-valid but not supported yet` · the `argument` and `return_inferred` cells (un-annotated face) of `same-elems-result-of-built-list`, `map-callback-over-built-list` and `same-elems-result-in-literal`, and their `map_value`/`map_set` cells · residue of D16767 · found by lane WIDTH · filed 2026-11-16 against master `0ab7c1bf7`**

Repro:

    type J = { f: i32 | null }
    function mk2() { return { f: null } }
    const dA: J = mk2()
    const src = [mk2()]
    function show(a) { print(a[0].f) }
    show(src)
    // vl check: rc 1, the built-container refusal at `src`

Want:

    null

#### Mechanism

`dA`'s delivery keeps `mk2` building at `J`, so `src` stores its elements at `J`
(`recBuiltElemOf`). A hole parameter or an un-annotated result is typed at `src`'s own
`{ f: null }[]`, which `recBuiltReadRefuse` (and `recBuiltRetListsRefuse` for a returned list)
refuses because the build is not its own row. The parameter or result would have to be instanced
at the build, as `elabCbAtBuild` does for a callback's hole parameter, or be counted as a
delivery that lands `mk2`'s call off `J` (`recSitesLandOff`), as an annotated one is.

#### Ablation

| ingredient removed | outcome | needed? |
| --- | --- | --- |
| `dA` (no build at `J`) | runs, prints `null` | **yes** |
| the hole (`a: { f: null }[]`) | runs, prints `null` | **yes** |
| the field read (`print(a.length)`) | still refuses | no |
| the parameter (`function all() { return src }`) | still refuses at the return | no |
| the return's hole (`all(): { f: null }[]`) | runs, prints `null` | **yes** |

#### Grading list

The un-annotated `argument`, `return_inferred`, `map_value` and `map_set` cells of the three
templates above; `identity_returned` and `filter_in_record_argument` (both faces), which
hand the list to the same positions.
