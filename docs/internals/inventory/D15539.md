### D15539 — a generic whose type parameter binds to a function through a `(T | null)[]` parameter is instanced late

**runs today and must keep running · late demand: the instance of `first` at a function element is minted after `elabRun` returned · filed 2026-11-07 against master `2c47ae9b2`**

Repro:

    function first<T>(xs: (T | null)[]): T | null { return xs[0] }
    function inc(a: i32): i32 { return a + 1 }
    const f = first([inc, null])
    if f != null { print(f(1)) }

Want:

    2

#### Mechanism

`first` is called with a list of a function and a `null`, so `T` binds to a function. The
elaboration's call key holds `T` at the function's identity form, and the monomorphizer demands
`first` at the concrete signature `(i32) => i32`. Nothing in the elaboration's run minted that
instance, so it is demanded late (`VL_LATE_DEMANDS=1` prints `demand first`). The program runs and
prints `2`. Before #6650 deleted mono's niche guard, it was refused at emit ("a
nullable-(i32)=>i32 list element has no rep"), so the late demand was hidden behind the
refusal.

The parked escaping-list demand (`use` in `closures/listed-hole-fn-escaping-list.vl`, D15010's
shape) is a different mechanism. There one helper instance has to serve holders of different
function sets. Here a plain generic is instanced at a function-typed type argument that the call
key does not name. The holder is Fn#d's value-instance key (#6645): a call whose argument is a
list of a function has to name the concrete instance its type parameter takes.

#### Ablation

| `T` bound to `i32` (`first([1, null])`) | no late demand | **yes** |
