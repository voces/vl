### D1694 — a declared row whose nested-struct field names another row captures the OUTER literal, so a correctly-minted inner box is rebuilt at the declared element's tags

**closed 2026-09-06 — the nested-struct arm joins D1690's destination preference, refuting on
the two element rows' BOX fields alone · filed against master `83a3f2315` + D1663 + D1690 ·
D1674's mechanism at the code-15 arm, with a wrong-value outcome instead of a refusal ·
residue D1696 · 0 corpus cells**

Repro:

    type U1 = i32 | boolean
    type U2 = string | boolean
    type Inner = { xs: U2 }
    type H = { f: Inner }
    function u1(): U1 { return 7 }
    const b = { f: { xs: u1() } }
    print(b.f.xs)
    // vl check: rc 0.  vl run: rc 0, prints 7

Was: `PRINTS true`. `b.f.xs` holds the i32 `7` and printed `true` because the value was built
as `Inner`, whose tag 1 is `boolean`.

#### Mechanism

D1690's close fixed the INNER literal and the probe shows it working — and shows the capture
one level out in the same dump:

    ROW 0 Inner  [xs:16:<U2> ]        render={xs:string|boolean}   -> nameRow0
    ROW 1 H      [f:15:<Inner> ]      render={f:{xs:string|boolean}} -> nameRow1
    ROW 2 #anon2 [xs:16:<i32|boolean> ] render={xs:i32|boolean}    -> nameRow2
    LIT node16 -> row2 lit-fields[xs:16:<i32|boolean> ]
    LIT node18 -> row1 lit-fields[f:15:<#anon2> ]

The inner literal mints `#anon2` correctly. The OUTER literal then lands on `H`, whose `f`
slot is `(ref $Inner)` — the last line says it in one place, the row naming `Inner` and the
literal naming `#anon2` — so the inner value is emitted as `Inner` whatever row it resolved
to. Delete `type H` and the outer literal mints `#anon [f:15:<#anon>]` and the program
prints `7`; D1690's close is what made that half work.

**This is D1674's mechanism, not D1690's.** `anonValueFitsField`'s code-15 element test rides
the `sIsAnonRow` gate exactly as its code-5 sibling does, so a DECLARED row is never refuted on
its element. What differs is the outcome: D1674's filed witness is a loud
`unknown struct field in field access` at the ref-list arm, and this one is a check-clean wrong
VALUE, because two box rows have the same wasm layout and only their tags differ.

**The close is D1690's gate one arm over, plus a comparator narrow enough to survive the
boundary D1674 measured.** The destination gate alone is not sufficient and that was measured
rather than assumed: refuting on the two element rows' full CANONICAL keys moved **4 of 3,051**
`tests/cases` modules, two of them from running to check-clean invalid wasm, and one of the
four is `objects/object-shape-unannotated-literal-rebuilt.vl`, the fixture whose whole purpose
is to pin the accepting side — a literal re-interned at a destination row that WIDENS a field
and DROPS one. So the comparator asks only what a re-intern cannot fix: `elemRowsBoxCompat`
compares the two element rows' union-BOX fields by member sequence and nothing else, because
tags are positional and no re-intern renumbers them. With that narrowing the module diff is
**0 of 3,051**.

**And it does NOT close D1674**, which is the prediction this row carried, refuted: D1674's
own witness still refuses `emitProgram: unknown struct field in field access` at the candidate,
because the arm is scoped to codes 16 and 15 and D1674's is a ref list (code 5). The ref-list
and `| null` arms would need the same treatment and their own boundary measurement.
