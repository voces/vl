### D1694 — a declared row whose nested-struct field names another row captures the OUTER literal, so a correctly-minted inner box is rebuilt at the declared element's tags

**check-clean silently wrong · filed 2026-09-06 against master `83a3f2315` + D1663 + D1690 ·
D1674's mechanism at the code-15 arm, with a wrong-value outcome instead of a refusal ·
0 corpus cells**

Repro:

    type U1 = i32 | boolean
    type U2 = string | boolean
    type Inner = { xs: U2 }
    type H = { f: Inner }
    function u1(): U1 { return 7 }
    const b = { f: { xs: u1() } }
    print(b.f.xs)
    // vl check: rc 0.  vl run: rc 0
    // PRINTS true

`b.f.xs` holds the i32 `7`. It prints `true` because the value is built as `Inner`, whose
tag 1 is `boolean`.

#### Mechanism

D1690's close fixed the INNER literal and the probe shows it working — and shows the capture
one level out in the same dump:

    ROW 0 Inner  [xs:16:<U2> ]        render={xs:string|boolean}   -> nameRow0
    ROW 1 H      [f:15:<Inner> ]      render={f:{xs:string|boolean}} -> nameRow1
    ROW 2 #anon2 [xs:16:<i32|boolean> ] render={xs:i32|boolean}    -> nameRow2
    LIT node16 -> row2 lit-fields[xs:16:<i32|boolean> ]
    LIT node18 -> row1 lit-fields[f:15:<#anon2> ]

The inner literal mints `#anon2` correctly. The OUTER literal then lands on `H`, whose `f`
slot is `(ref $Inner)` — the last line says it in one place, the row naming `Inner` and the
literal naming `#anon2` — so the inner value is emitted as `Inner` whatever row it resolved
to. Delete `type H` and the outer literal mints `#anon [f:15:<#anon>]` and the program
prints `7`; D1690's close is what made that half work.

**This is D1674's mechanism, not D1690's.** `anonValueFitsField`'s code-15 element test rides
the `sIsAnonRow` gate exactly as its code-5 sibling does, so a DECLARED row is never refuted on
its element. What differs is the outcome: D1674's filed witness is a loud
`unknown struct field in field access` at the ref-list arm, and this one is a check-clean wrong
VALUE, because two box rows have the same wasm layout and only their tags differ.

**The prescription is D1690's, applied one arm over.** D1690's close conditions the refutation
on the literal's own destination — `repRowOfTyStruct(nodeRepTyIxOf(objIx))`, asked once per
literal — because a declared field may legitimately be wider than the value. The same gate at
the code-15 arm would let a delivered literal keep its declared row while refusing the capture.
**Written as a prediction, not a claim**: a close of D1674 that refutes on
`fieldCodeRefsElemHeapC` (15, 5, 28) moves this row with it; one that handles the ref-list arm
alone does not. Either way this witness belongs on D1674's grading list, and it is there.
