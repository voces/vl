### D3169 — a closure capturing an un-annotated `kn ?? e`, with `e` a literal-union walk variable, is invalid wasm

**check-clean invalid wasm · open · clause 1 · found by the #3281 round-4 review · the same on master `b1794003a` · filed 2026-09-29 against master `b1794003a`**

Repro:

    type K = "a" | "b"
    function t(ks: K[], kn: K | null) {
      for e in ks {
        const k = kn ?? e
        const f = () => k
        print(f())
      }
    }
    t(["a", "b"], null)
    // vl check: rc 0.  vl run: invalid module: type mismatch: expected (ref $type), found i32

Want:

    a
    b

#### Mechanism

Not localised past the ablation. `k` is the atom that `??` joins from a `K | null` niche and a
walk variable. The closure reads the capture as a string ref while the env field holds the
`i32` atom, so the capture's atom classification of a `??` join does not see the walk
variable. A parameter in place of the walk variable runs.

#### Ablation

| ingredient changed | outcome | needed? |
| --- | --- | --- |
| `e: K` a parameter, not a walk variable | runs | **yes** (the walk variable) |
| `print(k)`, no closure | runs | **yes** (the capture) |
| `const k: K = kn ?? e` | runs | **yes** (the un-annotated binding) |
| `string` in place of `K` | runs | **yes** (the literal union) |
| the loop at module scope | the same invalid module | no |

#### Grading list

The witness and its module-scope twin.
