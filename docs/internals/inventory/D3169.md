### D3169 — a closure capturing an un-annotated `kn ?? e`, with `e` a literal-union walk variable, is invalid wasm

**closed · a walk variable asked outside its frame's emission is an atom when its loop's iterable holds atoms, in both the atom and the niche channel · fixture `tests/cases/closures/capture-walk-variable-coalesce.vl` · was check-clean invalid wasm · clause 1 · found by the #3281 round-4 review · the same on master `b1794003a` · filed 2026-09-29 against master `b1794003a`, closed 2026-09-29 against master `a0b9acaf8`**

Repro:

    type K = "a" | "b"
    function t(ks: K[], kn: K | null) {
      for e in ks {
        const k = kn ?? e
        const f = () => k
        print(f())
      }
    }
    t(["a", "b"], null)
    // vl check: rc 0.  vl run: invalid module: type mismatch: expected (ref $type), found i32

Want:

    a
    b

#### Mechanism

A capture's env field is typed while no local of the walking frame is live. `exprIsLitAtom`
and `exprNulLitUnion` recognised a walk variable only through its slot's `localLitUnion` flag, so
the right operand of `kn ?? e` (or the left of `e ?? d` over a `(K | null)[]`) was not an atom
there, `coalesceLitUnionFits` declined, and the closure read the capture as a string ref while
the frame stored the `i32` atom. Both Ident arms now fall back to the loop enclosing the read
(`readLoopVarIsLitAtom`, over `readLoopNodeOf` and `forInVarIsLitAtom`).

#### Ablation

| ingredient changed | outcome | needed? |
| --- | --- | --- |
| `e: K` a parameter, not a walk variable | runs | **yes** (the walk variable) |
| `print(k)`, no closure | runs | **yes** (the capture) |
| `const k: K = kn ?? e` | runs | **yes** (the un-annotated binding) |
| `string` in place of `K` | runs | **yes** (the literal union) |
| the loop at module scope | the same invalid module | no |

#### Grading list

The witness and its module-scope twin.
