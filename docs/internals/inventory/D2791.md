### D2791 — `as!` to `i32` inside a generic instance truncates a fractional or out-of-range pin instead of trapping

**fixed 2026-09-27 — the filed repro loads then traps, `as! i32 at 1:34: not exact`, the ruled outcome the direct cast has · was a silent wrong value, printing 1 · clause 1 · found by #3208's review · filed 2026-09-27 against master `781f68091` · fixtures `tests/cases/generics/as-trap-type-param-fraction.vl`, `as-trap-type-param-i64-range.vl`, `as-trap-type-param-non-number.vl`, `as-type-param-pin-exact.vl`**

Repro:

    function k<T>(u: T): i32 { u as! i32 }
    print(k<f64>(1.5))
    // vl run: traps, as! i32 at 1:34: not exact

#### Mechanism

Over a type parameter the checker types `u as! i32` without its fallibility (the operand is a
hole), so the instance lowered the plain conversion (`i32.trunc_f64_s`) rather than the exact
test that `x as! i32` over a direct `f64` gets. `i64` wrapped and `boolean` read as its bit.
Closed by reading the instance's exact pin (`asExprHolePinSrc`, over `exactOperandTyOf`): a pin
the cast can fail at takes the exact-or-fail lowering from that source (`emitNumExactCastFrom`),
and a pin at no number is never the target, so `as!` traps and a bare `as` returns the
function's null (`emitHoleNumCastMiss`), the twin of `as?` answering `null` there (D2754). A pin
the cast is exact at keeps the plain conversion.

#### Ablation

| ingredient removed | outcome | needed? |
| --- | --- | --- |
| the generic (`const x: f64 = 1.5; x as! i32`) | traps, as ruled | **yes** |
| the fraction (`k<f64>(2.0)`) | prints `2` | **yes** |

#### Grading list

The four fixtures above; a bare `as` at `f64` (`b(2.5)` prints `null`), `as! i64` at `2.5`
(traps), a string pin (was invalid wasm, now traps), a closure capturing the operand (traps),
and a union pin (`string | i32`, the union arm's own lowering, unchanged).
