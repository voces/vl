### D2791 — `as!` to `i32` inside a generic instance truncates a fractional or out-of-range pin instead of trapping

**check-clean silently wrong · clause 1 · found by #3208's review · identical on master · filed 2026-09-27 against master `781f68091`**

Repro:

    function k<T>(u: T): i32 { u as! i32 }
    print(k<f64>(1.5))
    // PRINTS 1

#### Mechanism

Over a type parameter the checker types `u as! i32` without its fallibility (the operand is a
hole), so the instance lowers the plain conversion (`i32.trunc_f64_s`) rather than the exact
test that `x as! i32` over a direct `f64` gets. `i64` wraps and `boolean` reads as its bit. The
`as?` twin was fixed by D2754 by reading the instance's exact pin; `as!` needs the same.

#### Ablation

| ingredient removed | outcome | needed? |
| --- | --- | --- |
| the generic (`const x: f64 = 1.5; x as! i32`) | traps, as ruled | **yes** |
| the fraction (`k<f64>(2.0)`) | prints `2` | **yes** |
