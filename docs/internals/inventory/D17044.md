### D17044 — a hole lambda handed to a function that calls it once and returns it is a function tag in the callee but held as a closure by the caller

**check-clean invalid wasm · `vl check` clean, `vl run` refuses an invalid module (validation error) · clause 1 · filed 2026-11-21 against master `7781e9bd` by IR-D1, found while measuring the open-parameter class**

Repro:

    function lap(f) {
      f(2.5)
      return f
    }
    const k = lap((a) => a + 1)
    print(k(3.5))
    // vl check: rc 0.  vl run: invalid module, the emitted module failed to validate inside
    // the module's top-level code: type mismatch: expected (ref null $1), found i32

Want:

    4.5

#### Mechanism

`lap` takes its argument as a function tag. The lambda is the only member, so the parameter is
an `i32` id, the call `f(2.5)` is a direct `call $__lambda_0`, and `lap` returns the `i32`. The
module binding `k` that holds `lap`'s result is typed as a closure (`(mut (ref null $3))`, the
closure struct), and `k(3.5)` is a `call_indirect` through that struct. The `global.set` stores
`lap`'s `i32` into it. The callee's tag decision and the caller's closure decision for the same
value disagree. The IR claims `lap` with legacy's own bytes and does not build the start body
(`call of a non-declaration`), so the faulty bytes are legacy's.

#### Ablation

| ingredient removed or changed | outcome | needed? |
| --- | --- | --- |

| `k(3.5)` changed to `k(3)`, a second signature | still invalid wasm | no |
| the module scope, moved into `function main()` | still invalid wasm | no |
| a second call of `f` at another signature inside `lap` (a bundle) | runs (D15902, D15906 family) | **yes**, one signature only |
