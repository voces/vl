### D9301 — an inline list of un-annotated functions in a record stored as a list element or a map value has no element representation

**loud emit reject · `vl check` rc 0 · `emitProgram: object literal but no struct type declared` · clause 2 · found closing [D9254](D9254.md) · present on master `cf1b1a8d3` · filed 2026-10-21 against master `cf1b1a8d3`**

Repro:

    function inc0(u) { return u + 1 }
    const a = [{ xs: [inc0] }]
    const v = a[0]
    print(v.xs[0](3))
    // vl check rc 0.  vl run: emit error: emitProgram: object literal but no struct type declared

Want:

    4

#### Mechanism

D9254 types an inline list literal in an open record field only where the record literal goes
through `monoClosedObjLitTy`, a return or a binding. A record literal stored as a list element
or a map value is typed by `monoPinStoredRecords` (emit_mono.vl). For a field that is not
itself a function, it asks `monoClosedFieldValTy`, which knows record literals and binding
reads but not list literals, so the whole record is left open.

A trial that gave such a field its element slot's pin (`monoStoredSlotFnTy` over path
`…/f.<field>/e`) made the witness check-clean invalid wasm, the [D9300](D9300.md) shape, and
moved the map-value spelling to `callee is not a function name`. It was reverted. D9300 is
likely a prerequisite.

#### Ablation

| ingredient removed | outcome | needed? |
| --- | --- | --- |
| the outer list (`const v = { xs: [inc0] }`) | runs, `4` | **yes** |
| the inline list (`const hl = [inc0]`, `{ xs: hl }`) | invalid wasm, [D9300](D9300.md) | **yes** |

#### Grading list

The un-annotated `array_element`, `array_element_place`, `map_value`, `map_set`,
`map_value_place`, `local_assign` (a `let` reassigned with a fresh record literal), `argument`
and `early_return_guard` rows of matrix `hole-fn-list-in-record-field`. The last two refuse
with `unsupported argument type`, the un-annotated parameter delivery, and may be a separate
mechanism.
