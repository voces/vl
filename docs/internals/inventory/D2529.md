### D2529 — a narrowing an assignment establishes leaks into a function body that runs after a later write

**closed 2026-09-25 — the filed repro is now a loud check reject (`operator '+' is not defined for i32 | null and i32`), and its `?? -1` spelling runs and prints `-1` · was check-clean invalid wasm, clause 1 · found by #3167's review · filed 2026-09-25 against master `680b67486`**

Repro:

    let vv: i32 | null = null
    vv = 1
    function f() { return vv }
    vv = null
    const r = f()
    print(r + 1)
    // vl check: rc 0, `f()` typed `i32`.  vl run: invalid module

#### Mechanism

`vv = 1` narrows `vv` by an assignment-kind layer (`NAR_KIND_ASG`), which, unlike a guard's
layer, does not refuse a later write it does not admit. A function body checked under that layer
read it: a top-level function is its own writer-analysis root, and `crCaptureWiden` returned at
once for a root, while a nested function or lambda called only by its handle kept the layer on
the claim that any direct write under the capture is refused, which holds only for a guard.
`crCaptureLosesNarrowing` (nested) and `crRootLoses` (top-level) now drop a non-guard layer in a
body that reads the name when a write that may store `null` can precede the body: anywhere in the
program for a module `let` (`crNameNulledInProgram`), after or around the capture for a local
captured by reference (`crCaptureByRef`, never finer than the emitter's `cboxByRef`), and, for a
top-level function, also a call or operator/index dispatch ahead of the binding's first
non-null write (`crRootMayKeep`). A scalar-box local loses on any later write, since its shared
cell's read is not yet narrowed (D2555).
A sync callback keeps the layer (D2402). The declared type is bound in a layer a body declaration
may shadow (`crDeclareWidened`). The rule and its price are DECISIONS.md, under D2390.

#### Ablation

| ingredient removed | outcome | needed? |
| --- | --- | --- |
| `function f` → `const f = () => vv`, `() => { return vv }`, a nested `function` | same | no |
| the later `vv = null` | the narrowing is kept, and the body runs (D2555) | **yes** — a write that may store `null` |
| the binding a local of `main` | same | no |
| the narrowing a guard (`if vv != null { … }`) | the write under it is refused | **yes** — an assignment or post-guard layer |
| a later `vv = 2` instead of `null` | kept for a module or reference-stored binding; a scalar-box local still loses | **yes** |
| `i32 \| string` with `g = 5` | runs: assignment narrows only `T \| null` | **yes** |

#### Grading list

* `const f = () => vv` and `(() => vv)()` at module scope; `xs.map((x) => x + vv)`, which keeps it.
* The local face: `v = 1; const h = () => v; v = null; h() ?? -1`, a write in a loop after the
  capture, a writer closure, and a local declared inside the loop, which keeps it.
* A declaration in the body shadowing the narrowed name (`const v = "abc"`).
* `tests/cases/closures/capture-by-reference.vl` (`narrowed()`), which a guard keeps.
