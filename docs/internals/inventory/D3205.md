### D3205 — a function read through a declared row's `H | null` field of a literal whose field is present is called at `i32` in a hole or generic instance

**check-clean silently wrong · clause 1 · open, parked with D3204: reading through a nullable record's non-null face at the pin keyed calls the pin had refused, which then trapped on a `null` record · pre-existing, the same on master `94670f728` · found by the NF lane's grid (`n0153_bool_NR_hole_bound_fn_lit`) · filed 2026-09-29 against master `94670f728`**

Repro:

    type R = { v: i32, h: { f: () => boolean } | null }
    function F(z) {
      const g = z.h.f
      print(g())
    }
    F({ v: 7, h: { f: () => true } })
    // PRINTS 1

Want:

    true

#### Mechanism

The checker pins `z` at the literal, whose `h` is present, so the program is well-typed. The
emitter's instance lays the literal out at the declared row `R` it matches, whose `h` is
`{ f: () => boolean } | null`, and the result of `g()` is read off `?ret.?fld.f.?fld.h.z`:
`holePinReadAt` (and, for `<Z>`, `substHoleTyReal`) looked `f` up on the nullable record, found
no field, and the result fell to `i32`. The parked candidate read a nullable record at its non-null face in both.
The checker cannot be fooled by this: a read through a pin that is really `| null` is refused
by its own `memCstrTy` row (D3204).

#### Parked

The candidate read a nullable record's non-null face in `holePinReadAt` and `substHoleTyReal`. That is sound only where the pin re-asks the member read (D3204); with D3204 parked it turned 48 emit refusals over a `null` record (`NR*_U_*N`, `*_NR_*_null_*`) into traps, so it was parked with it.
