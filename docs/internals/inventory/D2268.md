### D2268 — an import's local binding could take a compiler intrinsic's name and silently replace it

**closed 2026-09-23 — now a loud check reject (`'__trap__' is a compiler intrinsic and cannot be redefined — every call to it lowers to instructions inline, so this definition would never run`, anchored at the alias) · was check-clean silently wrong: `vl check` rc 0 and `__trap__(4)` called `bump`, printing `5` · `const __trap__ = bump` in the same program was already refused (D2263) · owner ruling 2026-09-23 · filed against master `6bfe5e770` · fixtures `tests/cases/modules/err-intrinsic-name-import/`, `tests/cases/modules/err-intrinsic-name-reexport/`, `tests/cases/modules/intrinsic-name-import-control/`**

Repro:

    // file: lib.vl
    export function bump(x: i32) { return x + 1 }
    // file: entry.vl
    import { bump as __trap__ } from "./lib"
    print(__trap__(4))
    // vl check (as filed): rc 0.  vl run (as filed): 5 — the import won every call.

#### Mechanism

D2263's pre-rename screen (`driver.modCheckReservedDecls`) walked a module's top-level
`FuncDecl` and `LetDecl` names only. An import creates no declaration: the merge maps its
local name straight to the target's mangled name (`modBuildRename`), so every call spelled
`__trap__` in the importing module rewrote to `bump$m1` and the intrinsic became unreachable
there. The fix adds `modCheckReservedImports`, which runs the same name-only rule
(`typecheck.checkNotIntrinsicImportLocal`, sharing `intrinsicNameRefusal` with
`checkNotIntrinsicName`) over every row `modScan` recorded for the module — `import { … }` and
re-export `export { … } from` alike — anchored at the alias token, or the name token when there
is no alias.

#### Ablation

| ingredient removed | outcome | needed? |
| --- | --- | --- |
| the alias (`import { __trap__ }` of a dependency's `export function __trap__`) | still ran the dependency's body (its declaration now refused by D2263, the import by this row) | no |
| the importer (`export { bump as __trap__ } from "./lib"` in a module nobody imports `__trap__` from) | re-export binds the local in its own module; refused | no |
| the reserved spelling (`bump as plus`, or the non-reserved helper `bump as __str_concat__`) | runs, `"a" + "b"` unaffected | **yes** |

#### Grading list

`import * as ns from "./lib"` and `import dflt from "./lib"` parse and bind nothing (a later
`ns`/`dflt` is an undeclared identifier), so neither can shadow an intrinsic; the named list
and the re-export list are every way an import binds a name. `tests/cases/modules/intrinsic-name-import-control/`
pins that an ordinary alias and a non-reserved `__…__` helper alias still run.
