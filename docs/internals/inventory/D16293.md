### D16293 — a generic numeric accumulator written `let t = 0` refuses a float argument, and the refusal is about the callee's body

**open · loud check reject · by design: DECISIONS.md "A literal binding takes its type from its uses", "Within kind" (owner rulings B′ + C, provisional) · an owner question, not a capability gap · found by the 2026-11 engineering review (§3.1) · filed 2026-11-14 against master `94f5055d`**

Repro:

    function sum(xs) {
      let t = 0
      let i = 0
      while i < xs.length { t = t + xs[i]; i = i + 1 }
      return t
    }
    print(sum([1.5, 2.5]))
    // vl check rc 1: cannot assign f64 to i32 (the body of `sum` at the call's argument types)

#### Mechanism

A literal `let` is re-typed by its deliveries and stores only within its literal's kind: an
integer literal widens to `i64`, never to a float. Each call instantiates `sum` at its argument
type, so at `f64[]` the store `t = t + xs[i]` is an `f64` into an integer binding and is refused,
and the diagnostic lands at the CALL. The same body at `i32[]` runs.

#### Ablation

| spelling | outcome | needed? |
| --- | --- | --- |
| the witness | check reject | — |
| `sum([1, 2])` only | runs, prints `3` | the float argument: **yes** |
| `let t = 0.0` | runs at `f64[]` (prints `4`) and at `i32[]` (prints `3`) | the integer literal: **yes** |
| `sum([1, 2])` and `sum([1.5, 2.5])` both | check reject at the second | no |

#### Grading list

The owner's answer decides this row: either an integer literal `let` in a generic body may join
to a float at an instance (and the witness prints `4`), or the refusal stands and its sentence
names the binding `t` and the annotation that fixes it, not only the call.
