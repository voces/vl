### D15925 — a function whose tail is a value `if` returning records of un-annotated functions is refused at emit, where the same arms as `return`s run

**closed · clause 2 · the list spelling, as a tail `if` and as `return if`, runs since lane I's join-of-lists delivery in `monoCoerceRetAtPin`; the record spelling since w314's tail-join fix; the join bound to a `const` and returned is [D16136](D16136.md) · found closing [D15805](D15805.md), whose returned-list twin shares it · filed 2026-11-12 against master `22d35fe47`**

Repro:

    function inc0(a) { return a + 1 }
    function dbl(a) { return a * 2 }
    function two() { [1, 2].length }
    function pick(b: boolean) { if b { [{ f: inc0 }] } else { [{ f: dbl }] } }
    print(pick(two() > 5)[0].f(3))

Want:

    6

#### Mechanism

Traced for the record spelling. A call through the result is judged by `holeRecSrcsOf`
(`check_calls.vl`), which follows a call's returned values through `holeSlotCallRets`:

- For `return if …`, the returned value is the `if` itself, which is no literal or slot, so the
  call builds no records and the tag plan holds the arms.
- For a tail `if`, the walk yields the arms' literals. The call adopts them at its record of
  closed function fields (a closure rep), so the plan finds a field that cannot hold an id.

Two changes make the two spellings agree:

- `holeCallTailIsJoin` declines a callee whose body ends in a value `if` or `match`, as the
  returned `if` is declined.
- The tag plan's body-tail holder (`ftHoldCtxOk`) compares the tail's type with the inferred
  result structurally (`tySame`). The tail's type is an equal copy, not the same arena index.

The list spelling, `if b { [{ f: inc0 }] } else { [{ f: dbl }] }`, is a join no tagged result
covers: each arm's list carries its own one-member set, so `elabRetTaggedJoinTy` answers -1 for
every leaf. `monoCoerceRetAtPin` now delivers each list leaf of such a join as the returned
literal it is, which is what the arms written as `return`s already did.
