#### Mechanism

The object literal `{ f: g }` inside a hole-typed body mints an anonymous struct row whose
field's storage type (`sFieldStoreTy`) is the unpinned hole `_`, or a type variable (`F`, `G`)
in the generic cases. `repOfTy` has no rep for that type, so `fieldCodeOfRep` answers -2, while
the anon ladder stored code 0 (`FC_I32`). The row is read during emit by `fieldRowCode`,
`rowKind`, `layoutId` and `storeAlike`, so it is not dead. Over both corpora (tests/cases+std
and distilled): 649 disagreeing reads in 18 files. Stage 3c-ii keeps the stored code for this
class (`fcKeptHoleRow`, `emit_rep.vl`). A scratch compiler that derives the code here instead
fails 9 of these modules with `emitProgram: struct field has no storage kind`, and moves
d681's type section (a dead template struct changes its subtyping group). The close: the row is
minted at the instance's type, or not minted where only a template reads it, and the fallback
is deleted. For the d681 subset (`d681_refused_spelling_pin`,
`tests/cases/functions/structural-generic.vl`), not minting is a named type-section mover:
dead types drop.
