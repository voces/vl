### D3882 — a nested generic printing its own type parameter, called at the enclosing function's `T`, is not checked at the enclosing function's record pin

**check-clean invalid wasm · found closing D3827 (lane SC) · filed 2026-10-08 against master `a1c9be3c4`**

Repro:

    type P = { a: i32 }
    function outer<T>(x: T) {
      function inner<U>(u: U) { print(u) }
      inner(x)
    }
    outer({ a: 1 })
    // vl check: rc 0.  vl run: invalid module inside `inner`, `expected i32, found (ref $0)`

Want: a check error at `outer({ a: 1 })`, like the one a non-generic `outer` gets at `inner(x)`:

    vl check: `inner` prints its type parameter here: print expects one scalar or string value (i32 | i64 | f32 | f64 | boolean | string), got P

#### Mechanism

Not located. The `print` constraint on `inner`'s `U` is recorded and owned by `outer`. Here
`U` is bound to `outer`'s `T` at `inner(x)`, and then to `P` only at `outer`'s pin. The constraint
is not re-checked at that pin. This is likely the same ownership question as D3853, where a
nested generic's constraints are substituted at the enclosing function's pins by name.

#### Ablation

| ingredient removed | outcome | needed? |
| --- | --- | --- |
| `outer`'s type parameter (`x: P`) | check error at `inner(x)` | **yes** |
| the forwarding (`inner({ a: 1 })` in `outer<T>`) | check error | **yes** |
| `inner` (`print(x)` in `outer`) | check error at `outer({ a: 1 })` | **yes** |
| a record pin (`outer(1)`) | runs, `1` | **yes** |
