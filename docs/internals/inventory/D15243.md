### D15243 — a returned record of members handed back through a plain function into an annotated binding is invalid wasm once the check takes the member

**closed 2026-11-04 by #6203 (lane bundle) — the repro now RUNS and prints the Want below: a maker handing back a record of members is withdrawn from maker instancing (`elabMakerBlock` in `elabPlainRetRecord`, emit_elab.vl), and the check's `return_inferred` test is deleted. Was: loud check reject (`… not yet supported at this position`), clause 2; with the check lifted, invalid wasm inside `__deliver`, clause 1 · filed 2026-11-04 against master `80e3a45be`**

Repro:

    function __lap(f) {
      const __a = f(2.5)
      const __b = f(3)
      return f
    }
    function __gen<T>(t: T, k: i32) {
      const r = __lap((a) => a + k)
      const __t = t
      return r
    }
    function __deliver() {
      return __gen("s", 1)
    }
    const v: (x: f64) => f64 = __deliver()
    print("\{v(4)} \{v(1.5)}")

Want:

    5 2.5

#### Mechanism

Measured on 2026-11-04, and not the destination narrowing first filed. `__deliver` takes no
parameter and returns a function value, so it is a maker (`fvaIsMaker`). A maker call whose value
is used at one closed signature banks a maker row (`fvaMakerCallRows`): an annotated destination
does, and so does an un-annotated binding read only by calls at one signature. Mono then builds the
maker's twin (`monoMakerTwin`) with that one member's closure type as its declared result, while
its body returns `__gen`'s record. The elaboration already knew `__deliver` returns the record
(`elabPlainRetRecord`). The fix withdraws such a maker from instancing (`elabMakerBlock`), so it is
built returning the record and each caller takes its member.

#### Ablation

| `const u = __deliver()`, called at both signatures | runs, prints `5 2.5` |
| `__deliver(q: i32)`, any of the above | runs: not a maker row's shape |
| `function __gen() { return __lap((a) => a + 1) }` used once | emit refuses: `a lambda called at two signatures has no closure built for one of them` |
| `__gen`'s type parameter removed | same as with it |

Residue: a maker of a record called inside a generic function's instance still refuses at emit
(`a function returning a parameter called at two signatures is called where its result is not
used at one of them`), on master and with the fix.
