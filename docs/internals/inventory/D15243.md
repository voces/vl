### D15243 — a returned record of members handed back through a plain function into an annotated binding is invalid wasm once the check takes the member

**open · loud check reject today (`… not yet supported at this position`), clause 2; with the check lifted the module fails to validate, clause 1 (`claude/d15146-unconditional-lift-probe`) · owned by lane bundle (its holder reader, the #6143 path) · residue of [D15146](D15146.md) · filed 2026-11-04 against master `80e3a45be`**

Repro:

    function __lap(f) {
      const __a = f(2.5)
      const __b = f(3)
      return f
    }
    function __gen<T>(t: T, k: i32) {
      const r = __lap((a) => a + k)
      const __t = t
      return r
    }
    function __deliver() {
      return __gen("s", 1)
    }
    const v: (x: f64) => f64 = __deliver()
    print("\{v(4)} \{v(1.5)}")

Want:

    5 2.5

#### Mechanism

`__deliver` is a plain function returning `__gen(...)`'s result, a record of one closure per
signature. The check keeps it refused (`letCstrBundleServed` declines a function handing back
another call's result). With the refusal lifted the module fails to validate inside `__deliver`:
the annotated destination narrows `__deliver`'s inferred return to one member, `(x: f64) => f64`,
so emit gives the function the closure type as its wasm result while the call inside it returns
the record. Ruling (coordinator, 2026-11-04): a destination never narrows a callee's inferred
return. Neither the generic nor `__gen`'s type parameter is an ingredient (lane bundle); the plain
template's same cell is the loud `a lambda called at two signatures has no closure built for one
of them`. Bundle's slice makes that checker change and deletes the `return_inferred` test from
the predicate.

#### Ablation

| ingredient removed | outcome | needed? |
| --- | --- | --- |
| `__deliver` (`const v: (x: f64) => f64 = __gen("s", 1)`) | runs, prints `5 2.5` | **yes** |
| `v`'s annotation (`const v = __deliver()`) | runs, prints `5 2.5` | **yes** |
| `__gen`'s type parameter (a plain `__gen(t: string, k: i32)`), with the check lifted | still invalid | no |
