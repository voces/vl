### D16292 — a hole lambda a function returns by name, called inline on the call's result, has no interned signature at emit

**closed 2026-11-15 by lane J · runs, prints `3` · was loud emit reject, clause 2 · `tests/cases/closures/maker-result-called-in-place.vl` · `vl check` rc 0 · the inline face of [D14881](D14881.md), whose close covered the bound spelling only · found ablating [D16291](D16291.md) · filed 2026-11-14 against master `94f5055d`**

Repro:

    const lam = (x) => x
    function mk() { return lam }
    print(mk()(3))
    // vl check rc 0.  vl run: emit error 3:14: emitProgram: a function-value call has no
    // interned signature — parameter 1 of type `_` has no representation

Want:

    3

#### Mechanism

Closed by banking a maker call that is called in place: `fvaMakerCallRows` takes the signature the
outer call passes (`mk()(3)` at `(i32)`) and builds the maker at that result, as it already did for
a `const` holding the call and only called. Each such call is banked at its own signature, so
`mk()(3)` and `mk()("s")` both run. It is limited to makers whose every returned value is a lambda
or a name (`fvaRetsNamed`). A returned labelled block of nested hole functions keeps the path it
takes today: the maker instance does not pin a member that only a later call reaches, which the
`const` spelling already refuses on master.

Before the close:

D14881's close builds the maker at the signature its result is called at when the result is a
`const` that is only called (`const q = mk(); q(3)`). A call whose callee is itself a call
(`mk()(3)`) is not such a binding, so the maker keeps the lambda's open signature and the call
reaches emit with a hole parameter type.
