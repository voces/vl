#### Mechanism

Closed by one rule over a maker call's reach (`fvaMakerCallRows`): the call is built at the one
closed result its reach asks for, whether that is the calls made through it in place (`mk()(3)`),
the calls through a `const` that holds it and is only called, or a closed function type it is
delivered at. Before, only the `const` and the delivered spellings were banked. Each in-place call
is its own reach, so `mk()(3)` and `mk()("s")` both run. A maker counts only when every value it
returns is a lambda or a name (`fvaRetsNamed`). A returned labelled block of nested hole
functions is built through its own deliveries instead, so `const q = pick(2)`, which was refused,
runs too.

Before the close:

D14881's close builds the maker at the signature its result is called at when the result is a
`const` that is only called (`const q = mk(); q(3)`). A call whose callee is itself a call
(`mk()(3)`) is not such a binding, so the maker keeps the lambda's open signature and the call
reaches emit with a hole parameter type.
