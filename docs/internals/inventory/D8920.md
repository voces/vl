### D8920 — a record literal handed on to a second hole that reads its field is built at a declared record that boxes the field

**closed 2026-10-21 · runs, prints `5` · was check-clean invalid wasm · clause 1 · the literal's row choice follows a hole that hands its parameter on, through an un-annotated binding, a further call or an identity, up to four holes deep, and treats a parameter declared as an unbounded type parameter as a hole (`holeBodyReadsField`, `holeFwdReadsField`, `paramTakesArgRow`, `litCallTail`, `emit_classify.vl`) · pin: `tests/cases/soundness/record-literal-through-holes-beside-boxed-row.vl` · matrices `record-literal-through-two-holes-beside-boxed-row` and `record-literal-into-generic-hole-beside-boxed-row` → 66 of 66 · present on master `646307dbe` and `935c60d96` · found closing [D8900](D8900.md) · filed 2026-10-21 against master `935c60d96`**

Repro:

    type J = { f: i32 | null }
    function rd(r) { return r.f + 1 }
    function fwd(a) { return rd(a) }
    const keepJ: J = { f: null }
    print(fwd({ f: 4 }) + (keepJ.f ?? 0))
    // vl check: rc 0.  vl run: the emitted module failed to validate inside `rd`: expected i32, found (ref $type)

Want:

    5

#### Mechanism

[D8620](D8620.md)'s close builds a literal at its own row when the hole it is handed to reads
its field bare (`litHoleReadsField`). It looked only at the first hole's own body. `fwd` reads
nothing off `a`; it hands `a` to `rd`, and both instances are pinned at the literal's row,
which was `J`, so `r.f + 1` reads a box. The same holds when the literal reaches `rd` through
`const v = a` or back out of `id(x) { return x }`, and when the holes are declared `<T>(r: T)`.
