### D16809 — a `?.` call through a record nested in a map's entry is refused

**closed 2026-11-16 — the witness runs and prints `6` · was: loud emit reject · clause 1 (check accepts what emit refuses) and clause 2 · found closing [D16743](D16743.md) · filed 2026-11-16 against master `d14f2c88c`**

Repro:

    function inc0(a) { return a + 1 }
    function dbl(a) { return a * 2 }
    const m = Map()
    m.set("a", { r: { f0: inc0 } })
    m.set("b", { r: { f0: dbl } })
    print(m.get("b")?.r.f0(3) ?? 0)
    // vl check: rc 0.  vl run: emit error, "emitProgram: an optional call needs a receiver the guard can read twice — bind it to a name first"

Want:

    6

#### Mechanism

Not a map or function-set matter: every `x?.r.f(…)`, a `?.` chain more than one field deep ending
in a call, was refused at emit, annotated too (`e: R | null`, `e?.r.f0(3)`). Its receiver `e?.r`
is an `OptMember`, which the lowering cannot read twice, so `drwOptGuard` declined and
`emitCallCore` refused, naming a remedy that did not help. `checkOptCallNode`
(`compiler/check_calls.vl`) now checks such a call as written, so the place's judges still refuse
what they owe, and then checks it again as `{ const $oc = b?.r; $oc?.f(…) }`, built by
`luValueAt` as `recEqTypedChain` builds its operands' bindings: the guard tests a name, and the
binding carries the checker's facts. The receiver is evaluated once.

#### Grading list

- Annotated: `e?.r.f0(3)` on a bound or returned `R | null`, a null receiver, three fields deep,
  a `void` call in statement position, a receiver with an effect (run once), a parameter, a
  nullable inner field read with its own `?.`: run.
- A standalone `m.get("a")?.r.f0(3)` (`a standalone ?. has no rep`): runs.
- Members of different results: still refused at check, [D16829](D16829.md).
- Beside a declared record of the same field name: refused at emit, as the bound spelling is on
  master, [D16830](D16830.md).
