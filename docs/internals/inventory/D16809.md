### D16809 — a `?.` call through a record nested in a map's entry is refused

**loud emit reject · clause 1 (check accepts what emit refuses) and clause 2 · found closing [D16743](D16743.md) · filed 2026-11-16 against master `d14f2c88c`**

Repro:

    function inc0(a) { return a + 1 }
    function dbl(a) { return a * 2 }
    const m = Map()
    m.set("a", { r: { f0: inc0 } })
    m.set("b", { r: { f0: dbl } })
    print(m.get("b")?.r.f0(3) ?? 0)
    // vl check: rc 0.  vl run: emit error, "emitProgram: an optional call needs a receiver the guard can read twice — bind it to a name first"

Want:

    6

#### Mechanism

Not a map or function-set matter: every `x?.r.f(…)`, a `?.` chain more than one field deep ending
in a call, is refused at emit, annotated too (`e: R | null`, `e?.r.f0(3)`). Its receiver `e?.r`
is an `OptMember`, which `exprReReadable` rejects, so `drwOptGuard` (`compiler/emit_rewrite.vl`)
declines and `emitCallCore` refuses. The refusal names a remedy that does not help: binding `e`
leaves the receiver `e?.r`. The fix is to bind the receiver once in a value block at check time,
as `recEqTypedChain` (`compiler/check_operators.vl`) binds an effectful operand, so the temp
carries the checker's facts; a guard over a freshly minted `e.r` read has none. A `?.` straight
to the entry's own function field runs ([D16743](D16743.md)).

With members of different results (`half` for `dbl`) the checker refuses first, `cannot write
'half' to 'm[].r.f0'`, by every read spelling: a bound `.get` checked for `null`, a loop over the
map, `?.`.

#### Grading list

- Members of different results, through `?.`, a bound `.get` and a loop.
- Three levels of records.
