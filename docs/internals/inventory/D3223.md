### D3223 — an uninitialized `let x: T` in a generic function trapped the compiler

**closed 2026-09-29 (`mintPinnedObjLitsIn` in `compiler/emit_collect.vl` reads a `let`'s initializer only when it has one) · was a compiler trap, clause 1 · filed against master `94670f728` · fixtures `tests/cases/generics/uninitialized-let-in-generic.vl`**

Repro:

    function f<T>(a: T): T {
      let x: T
      x = a
      x
    }
    print(f(3))
    // was: the compiler itself trapped (out of bounds array access)
    // now: prints 3

Want:

    3

#### Mechanism

`mintPinnedObjLitsIn` walks each monomorphized instance and, for every `LetDecl`, called
`unwrapParen(n.letInit)` before testing the index; a declaration with no initializer has
`letInit == -1`, so `P.nodes[-1]` trapped. Found because a loop's result binding
(`WhileStmt.whileLv`) is exactly such a declaration inside a generic body.

#### Ablation

| ingredient removed | outcome | needed? |
| --- | --- | --- |
| the type parameter (`a: i32`, `let x: i32`) | runs | **yes** |
| the missing initializer (`let x: T = a`) | runs | **yes** |
