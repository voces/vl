### D3996 — a nullable record spelled by its shape was a union-box list element, which no union mints

**closed 2026-10-11 by lane CK · runs · was check-clean invalid wasm · found closing D3995 (the shared-instance witness of #3512's fixture) · filed 2026-10-11 against master `cfd7de9b5` · pins: `tests/vl_shared_instance_order_test.ts`, `tests/cases/arrays/filled-nullable-shape-element-beside-union.vl`**

Repro:

    import { filled } from "std:array"
    type Item = { n: i32 }
    const u: i32 | string = 3
    print(u)
    const a = filled<Item | null>(2, null)
    print(a.length)
    // vl check: rc 0.  vl run: the emitted module failed to validate inside `filled`

Want:

    3
    2

#### Mechanism

The `filled` instance spells its element by shape, `{n:i32}|null`. A `(P | null)[]` element is
a struct list (the `(ref null $P)` niche) only when `P` is a declared name (`structIndexByName`),
so the shape spelling fell to the union-box kind and the list was built over `$uBoxIdx`. With no
union in the program that index is unassigned and happened to name the record (index 0); beside
a union it names the box, and the list stores a record into it. A shape-spelled `P` that
interned a row now takes the struct kind too (`structIndexOfTypeName`). On a shared compiler
instance the stale `$uBoxIdx` of a previous compile reached it the same way.
