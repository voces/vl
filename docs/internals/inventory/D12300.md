### D12300 — an un-annotated function returning a call through a list element whose lambda returns its parameter is check-clean invalid wasm at a non-`i32` call

**check-clean invalid wasm · `vl check` rc 0 · `current function requires result type [i32] but callee returns [(ref $4)]` · clause 1 · the program is well-typed: the same function with `T` written for its parameter, or with the element bound to a name before the call, runs · emit_mono.vl / the inferred return of a hole function · found closing D12237 · filed 2026-10-24 against master `43ea89c8c`**

Repro:

    function outer(a) { const fs = [() => a]; fs[0]() }; print(outer(1)); print(outer("s"))

#### Mechanism

The function's inferred return is the result of `fs[0]()`, a call through an element of a list of
lambdas that each return the hole parameter `a`. At a `string` instance the call yields a string
reference, while the instance's result is still the default `i32` the return inference gave
the hole. Binding the element first (`const g = fs[0]; g()`) resolves the result, so the gap is
the result type of a call whose callee is an index read, not the list or the closure.

#### Ablation

| ingredient removed | outcome | needed? |
| --- | --- | --- |
| the `outer(1)` call (only `outer("s")`) | invalid wasm inside `outer` | no |
| the `string` call (only `outer(1)`) | runs, prints `1` | **yes**: a non-`i32` instance |
| the list (`const f = () => a; f()`) | runs | **yes** |
| the call through the element (`const g = fs[0]; g()`) | runs | **yes** |
| the hole (`outer<T>(a: T): T`) | runs | **yes** |
| the lambda reading `a` (`() => 1`) | runs | **yes** |

#### Grading list

`outer(1.5)` in place of `outer(1)`; `const f = () => a; const fs = [f]; fs[0]()`;
`const fs = [(x: i32) => a]; fs[0](1)`.
