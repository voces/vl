### D16681 — `x as i32 ?? d` is refused for the bare cast's propagation, and the message does not say the `??` needs `as?` to see the null

**closed 2026-11-16 · now a loud check reject whose refusal ends `; the `??` after it never sees that null — write `(x as? i32) ?? …` to default it there`, with no dead-default finding beside it; where the propagation is legal the finding names `as?` instead of "drop the `??`" (`castCoalNote`, check_demands.vl; `coalBareCastMsg`, check_coal.vl) · first-error quality · lane AE conversion audit · filed 2026-11-16 against master `6356d3e7d` · fixtures `numerics/error-as-cast-before-coalesce.vl`, `numerics/as-cast-before-coalesce-dead-default.vl`**

Repro:

    function f(u: f64): i32 {
      const k = u as i32 ?? 0
      return k
    }
    print(f(1.5))
    // was: `as i32` propagates null, which the enclosing function cannot return (it returns i32) — use `as!` to trap instead, or `as?` to take the null here
    //      warning: this `??` default is never used: `i32` is never null — drop the `??` and its default

#### Mechanism

The author meant the `??` to take the miss. The refusal is right (a bare `as` propagates), but it
names `as?` generically, and the follow-on warning tells the author to delete the default they
wrote. When the refused cast is the left operand of `??`, the refusal could name the one-character
fix, `(u as? i32) ?? 0`, and the dead-default warning could stay silent for that operand.
