### D3511 — `print` of a map read narrowed past `null` counts the members of the value-union ALIAS by its spelling, so the box is printed as an `i32`

**closed 2026-10-03 — the witness prints `5` · was check-clean invalid wasm, clause 1 · found by lane LU's position matrix (`map_value_place`) · the same on master `878f6ebe8` · filed 2026-10-03 against master `878f6ebe8`, closed in the same change · fixture `tests/cases/maps/narrowed-alias-union-value-print.vl`**

Repro:

    type U = i32 | i64
    const m: { [string]: U } = Map()
    m["k"] = 5
    if m["k"] != null { print(m["k"]) }
    // vl check: rc 0.  vl run: invalid module, "type mismatch: expected i32, found (ref $type)"

Want:

    5

#### Mechanism

Confirmed by the close. `m["k"] != null` narrows the read to the value type, which the
narrowing names by its alias, `U`. The print plan's `printNarrowKeepsBox` and
`printNarrowLiveAtoms` (`emit_classify.vl`) counted the members of that NAME with
`unionMemberCount`, a spelling count that reads `U` as one member, so the plan decided the
read was narrowed to a single scalar and fell through to `__print_i32__` with the box on the
stack. Both now resolve the alias through `unionMemberSetOf` / `unionArmsOf` first.
