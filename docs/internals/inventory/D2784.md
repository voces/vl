### D2784 — a generic that returns another generic's two-list result beside its own list is invalid wasm

**closed 2026-09-27 — the filed repro RUNS and prints `2.5` then `ok` · was check-clean invalid wasm · `g`'s pinned `T[] | f64[]` joins with `[t]` as a union the pin re-joins, and the instance builds it · the #3207 round-3 review (`m01`) · filed 2026-09-27 against master `f6db92e0d` · fixture `tests/cases/generics/return-join-nested-generic-two-lists.vl`**

Repro:

    function g<U>(u: U, c: boolean) {
      if c { return [u] }
      [2.5]
    }
    function h<T>(c: boolean, t: T) {
      if c { return g(t, false) }
      [t]
    }
    const q: string[] | f64[] = h(true, "s")
    if q is f64[] { print(q[0]) } else { print(-1) }
    h(false, "s")
    print("ok")
    // vl check: rc 0.  vl run: invalid module inside `h`

#### Mechanism

At `U := string`, `g` returns the two-list union `string[] | f64[]` (D2766). `h`'s return set
joins that union with its own `[t]`, a `string[]`. Neither the pin's list join
(`monoInferRetSetListTy`, which reads each return's recorded type) nor the union join sees a
call returning a union beside a list. So `h`'s instance declares a result one of its returns
does not deliver. Not yet localised further.
