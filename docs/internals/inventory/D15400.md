### D15400 — a function set called at two types through a returned list, whose member a hole helper pushes onto a wider list, is refused at emit with the split plan off

**runs today and must keep running · runs only through the split plan: with it off (`compileSrc` returning after its first compile) a loud emit reject, `a function value is called at two signatures, and the closure it holds was built for one`, clause 2, open · D15062's hole-helper escape, left when its record escape closed · fixture `tests/cases/closures/function-list-element-at-two-types-pushed-through-hole-helper.vl` · filed 2026-11-04 against master `f2599d8e`**

Repro:

    function inc0(a) { return a + 1 }
    function dbl0(a) { return a * 2 }
    function deliver0() { return [inc0] }
    function take0(a) { print(a[0](3)) }
    take0(deliver0())
    print(deliver0()[0](1.25))
    function addTo(xs, f) { xs.push(f) }
    const fs = [dbl0]
    addTo(fs, inc0)
    print(fs[1](5))

Want:

    4
    2.25
    6

#### Mechanism

`{inc0}` has to be tagged for `deliver0()[0]` to be called at `i32` and `f64`. Its hand to
`addTo`'s un-annotated `f` is declined by `ftCtxOk` (`check_fn_tag.vl`): D15065's veto keeps an
id out of a parameter the callee pushes into a holder, and no other reading applies. Inside
`addTo` the push stores into `fs`, whose element set `{dbl0, inc0}` is untagged, so `f` there is a
closure. A close builds `inc0` as that closure at the hand, where the push's destination is a
set no decision tags, as a record literal pushed onto a list of records now is (D15062).
