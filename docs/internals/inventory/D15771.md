### D15771 — a lambda handed to a hole function that calls it directly and hands it on in a `const` record is refused by the checker

**loud check reject · clause 2 · `argument 1: expected i32, got string (the call of a function value at the call's argument types)` · found closing D15639 · filed 2026-11-12 against master `04fad9d17`**

Repro:

    function call0(r, x) { print(r.f(x)) }
    function run(g) {
      print(g(5))
      const r = { f: g }
      call0(r, "s")
    }
    run((v) => v)

Want:

    5
    s

#### Mechanism

D15639's spelling with the named `id` replaced by a lambda. With D15639's close (#7433) the
checker follows the `const` record and the named function runs, but the lambda then stops at
"cannot infer a type for parameter `v`": a lambda argument has no declaration the hole's open
call can re-instance at the second type.

| --- | --- | --- |
| the lambda replaced by `function id(v) { return v }` | runs with #7433, `5` `s` | **yes** |
| the `const` record handed on (only `g(5)`) | runs | **yes** |
