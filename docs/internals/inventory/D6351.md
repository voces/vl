### D6351 — a `let`-held lambda calling its hole parameter at two instances, ill-typed at one, passes check and is refused at emit

**loud emit reject · `vl check` rc 0 · clause 2 · found closing [D6330](D6330.md) · filed 2026-10-18 against master `b48acada7` on lane L3's `l3-d6300` base `25d98fe9c`**

Repro:

    function id(a) { return a }
    let lap = (g) => "" + g(1) + g("s")
    print(lap(id))
    // vl check: rc 0.  vl run: emitProgram: cannot take the generic function `id` as a value — a function value carries ONE signature, and parameter `a` is un-annotated (it would default to i32). No call site pins `id`, so there is no inferred signature to adopt — annotate the parameter, or call `id` directly by name

#### Mechanism

From the ablation only. [D6330](D6330.md) judges each operator at each instance when the
callee is a declared function or a `const` lambda, whose body is known at the call. A `let`
binding can be reassigned, so the call does not resolve to the lambda and `"" + 1` at the
`i32` instance is never judged. The checker owes the refusal; a fix should not make the
program run.
