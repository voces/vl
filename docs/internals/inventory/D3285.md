### D3285 — a place filled on one arm of an `if` and tested non-null on the other is not narrowed after it

**closed 2026-09-29 (flow narrowing slice 1: `applyArmJoins` in `compiler/typecheck.vl` meets the per-path facts of every key an arm writes, each path starting at its condition fact; DECISIONS.md "Flow narrowing: per-path facts meet at joins") · was a loud check reject of a sound program, clause 2 · plumb PL-064 · filed against master `296e1141d` · fixtures `tests/cases/unions/flow-join-fill-on-miss.vl`, `tests/cases/unions/error-flow-join-unfilled-path.vl`, `tests/cases/unions/error-flow-join-call-may-write.vl`**

Repro:

    function nn(v: i32): i32 | null {
      if v < 0 { return null }
      return v
    }
    function f(k: i32) {
      let x = nn(k)
      if x == null { x = 0 }
      return x + 1
    }
    print(f(5))
    print(f(-1))
    // was: operator '+' is not defined for i32 | null and i32
    // now: prints 6 then 1

Want:

    6
    1

#### Mechanism

The arm join (D1846) folded only the rows an arm WROTE, started both arms at the first row's
before-type, and skipped every key the condition tested, so the fall-through path's `x != null`
fact never reached the meet. Three further gaps sat under it: a straight-line null strip banked
its row's end at the declaration (`i32 | null`), a non-null write to an un-narrowed nullable path
banked no row at all, and the install wrote the join in place at the binding's own depth, which
outlived a loop body or an enclosing arm. The join now starts each path at its condition fact
(the entry type where it has none), folds the arm rows in one pass, installs in the block that
holds the `if` (what the emitter's push after the statement lives as long as), and hands its
enclosing join one summary row per key, which keeps the ledger linear under nesting.
