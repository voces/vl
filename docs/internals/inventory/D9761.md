### D9761 — a declared function with an un-annotated parameter, passed to `.map` over a list of an un-annotated function, is refused as an unknown function

**closed · runs, prints `6` · was loud emit reject, `call to unknown function`, `vl check` rc 0 · clause 2 · found closing [D9712](D9712.md) · filed 2026-10-22 against master `60aaa08c0` · closed with [D9766](D9766.md)'s flow link, by instancing a named callback at the annotation the pin gave the list and typing the `.map` the checker left open, and its un-annotated binding's reads, at that callback's result (`monoCoerceListCbArg`, `monoCloseListCbBindReads`, emit_mono.vl) · fixture `closures/hole-fn-list-named-callback.vl` · the result delivered anywhere but a local binding is [D9862](D9862.md)**

Repro:

    function inc(a) { return a + 1 }
    const v = [inc]
    function ap(r) { return r(5) }
    print(v.map(ap)[0])
    // vl check rc 0.  vl run: emit error: emitProgram: call to unknown function

Want:

    6

#### Mechanism

Two steps. [D9766](D9766.md)'s missing flow link left `inc` unpinned. With it in place, the
callback `ap` is generic, and `monoCoerceListCbArg` read the receiver at the checker's open type
`((_) => _)[]`, so no instance of `ap` was asked for and its body called an unknown `r`. It now
reads the receiver at the annotation the pin gave the list, as it already did for a lambda
(D9093), instances `ap` at that element, and records the `.map` result, which the checker left
`_[]`, as the list of that instance's result. The nested twin (`[[inc]]`, `r[0](5)`) closes the
same way.
