### D16231 — a function written into a list through a parameter is stored as a closure when the same member is also written into another list directly

**closed 2026-11-14 · runs, prints `1.5` then `2.5` · was check-clean invalid wasm, `the emitted module failed to validate inside 'put'` · clause 1 · found folding the map write leaves into the place-path walk · filed 2026-11-14 against master `f302cddec` · closed by `ftPlan` (check_fn_tag.vl), which now takes every write `fnTagWriteLeavesOf` records as a leaf, as it already did for maps (D15531), not only for a member with no other leaf · fixture `closures/fn-list-written-through-param-beside-a-direct-write-of-the-member.vl`**

Repro:

    function inc0(a) { return a + 1 }
    function half(a) { return a / 2.0 }
    function put(ys) { ys[0] = half }
    const xs = [inc0]
    put(xs)
    const ws = [inc0]
    ws[0] = half
    print(xs[0](3))
    print(ws[0](5))
    // Was: vl check rc 0.  vl run: the emitted module failed to validate inside `put`

Want:

    1.5
    2.5

#### Mechanism

The direct write `ws[0] = half` gives `half` a leaf in the set the lists share. The decision asked the
write leaves only for a member with none, so `put`'s write stayed a closure stored into a list of
ids. A map's write leaves were always taken; the two producers are now one walk, taken always.

#### Ablation

| ingredient removed | outcome | needed? |
| --- | --- | --- |
| `ws[0] = half` (the direct write) | runs, `1.5` | **yes** |
| `put(xs)` (the write through a parameter) | runs, `2.5` | **yes** |
