### D1306 — a BLOCK-BODIED lambda declared inside a module-scope block is check-clean invalid wasm; the expression-bodied twin runs

**check-clean invalid wasm · `vl check` rc 0, then `Invalid input WebAssembly code at offset 224: type mismatch: expected a type but nothing on stack` · reproduces IDENTICALLY on master `e6823dc8` and after #2447 — it is not that landing's, it is what that landing's position matrix FOUND · the SIBLING of D1244, which is the same module-scope-block-plus-lambda family at a different rung (a captured ref field, `emitProgram: field access receiver is not a struct`) · found 2026-09-03 grading `block_if_capture` in `matrix/global-shadowed-by-local.matrix.vl`**

Repro:

    if true {
      const f = () => {
        const q = 7
        print(q)
      }
      f()

    // vl check rc 0. vl run: Invalid input WebAssembly code at offset 224:
    // type mismatch: expected a type but nothing on stack

#### Mechanism

Not yet named. What is measured: the ingredient is the BLOCK BODY of the lambda, not the
capture and not any global. `() => 7` in the same module-scope `if` runs and prints; giving
the lambda a `{ … }` body with its own `const` makes the module invalid. Wrapping the whole
block in `function g() { … }` runs, so it is the MODULE-scope block specifically — the same
scope D1244's row isolates. The stack-shape message points at the lifted body's result
seam rather than at any type, so the row records the ablation and stops there.

#### Ablation

| ingredient removed | outcome | needed? |
| --- | --- | --- |
| the lambda's block body (`() => 7`) | runs, prints `7` | **yes** |
| the module-scope block (the lambda at top level) | runs | **yes** |
| the block moved inside a function (`function g() { if true { … } }`) | runs | **yes** |
| a captured variable in the lambda | still invalid wasm | no |
| a module global shadowed by the lambda's `const` | still invalid wasm | no |
