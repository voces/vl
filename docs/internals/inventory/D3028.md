### D3028 — D965's scalar converting copy snapshots a list a caller writes after the delivery

**closed · a source other than a `const` bound once to a list literal is delivered as a VIEW: a final subtype of the destination's wrapper that keeps its source (`__sv_mk_*__`), whose element and length reads go through the source (`__sv_get_*__`, `__sv_len_*__`) and whose whole-list reads refresh its snapshot first (`__sv_sync_*__`) · fixtures `tests/cases/arrays/readonly-scalar-view-reads-source.vl`, `readonly-scalar-view-nullable-reads-source.vl` · matrix `readonly-scalar-view-written.matrix.vl` · was check-clean silently wrong · found by the #3260 review (`h/*_scalar.vl`) · filed 2026-09-28 against master `cac5e4ad5`, closed 2026-09-28 against master `3a71bb1f9`**

Repro:

    function back(x: i32[]): readonly i64[] { return x }
    const l: i32[] = [1, 2]
    const r = back(l)
    l.push(3)
    print(r.length)
    // PRINTS 2

Want:

    3

#### Mechanism

D965 copied an `i32[]` delivered as `readonly i64[]` where `covarValueWriteState` answers 0.
That analysis follows the aliases of a local root only. Where the delivered value's root is a
parameter (`x` here), a call result or a two-hop parameter chain, it answers 0 without having
seen the caller's handle, so the copy was a snapshot of a list the caller then grows. The copy
is now kept only for D2999's fresh source (`covarRootFreshLocal`); every other source becomes a
view. The checker marks the pair (`scalarViewPairs`), the module mints the view type and its
helpers only then, so a module with no such delivery is byte-identical. Reads that miss the
helpers keep the view's snapshot, which is what the copy gave. A source the analysis sees
written is still refused: [D3040](D3040.md).

#### Ablation

| ingredient changed | outcome | needed? |
| --- | --- | --- |

| a call result, a field read or a two-hop alias as the root | prints `2` | no |
| a `const` bound to a list literal as the root | copied, never written | the copy stays |
