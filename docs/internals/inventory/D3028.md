### D3028 — D965's scalar converting copy snapshots a list a caller writes after the delivery

**check-clean silently wrong · clause 1 · found by the #3260 review (`h/*_scalar.vl`) · the same on master `cac5e4ad5` · filed 2026-09-28 against master `cac5e4ad5`**

Repro:

    function back(x: i32[]): readonly i64[] { return x }
    const l: i32[] = [1, 2]
    const r = back(l)
    l.push(3)
    print(r.length)
    // PRINTS 2

Want:

    3

#### Mechanism

D965 copies an `i32[]` delivered as `readonly i64[]` where `covarValueWriteState` answers 0.
That analysis follows the aliases of a local root only. Where the delivered value's root is a
parameter (`x` here), a call result, a field read or an index read, it answers 0 without having
seen the caller's handle, so the copy is a snapshot of a list the caller then grows. The fix is
D2999's rule (`covarRootFreshLocal`): copy only a `const` bound once to a list literal, and
refuse or share the rest.

#### Ablation

| ingredient changed | outcome | needed? |
| --- | --- | --- |
| no `l.push(3)` | prints `2`, right | **yes** |
| a call result, a field read or a two-hop alias as the root | prints `2` | no |
