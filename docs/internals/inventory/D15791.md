### D15791 — a call through a function field of a list's records whose functions return different types is refused at check, where a list element written with such functions runs

**loud check reject · `cannot store 'half' in 'rs[].f': called at (i32) it returns f64, where 'inc0', also stored in it, returns i32 — every function a call through 'rs[].f' may run must return one type` · clause 2, ruled not a contract (orchestrator, 2026-11-11): the call's result is well typed, the union of its members' results · open · the same judgment is lifted for a list element ([D14435](D14435.md)), a written element ([D14645](D14645.md), [D14646](D14646.md), [D14647](D14647.md), [D14648](D14648.md)) and a record's list field ([D15138](D15138.md)) · found closing [D15790](D15790.md) · filed 2026-11-11 against master `82eca538`**

Repro:

    function inc0(a) { return a + 1 }
    function half(a) { return a / 2.0 }
    const rs = [{ f: inc0 }, { f: half }]
    print(rs[1].f(3))

Want:

    1.5

#### Mechanism

`holeSlotJudge` (check_relate_core.vl) compares the results of the functions a slot may run, and
refuses when they differ. The chain above lifts that comparison where a call through the element
fixes its own member's tuple (D3975 A, (γ)). It has not been lifted for a function-valued field
of a list's records (`rs[].f`), nor for a list a call returns (`mk()[].f`, through
`holeSlotCallRootJudge`). Both are still judged against one common result.

The judge is only the first refusal. Measured on master `ebe1862f` by lifting it for any path
through an element (the D14435 lift extended to a field of an element):

1. **The bound spellings fail in the main check pass.** These are the witness, a `for` over `rs`,
   and `const g = rs[1].f; g(3)`. Each gives `expected i32, got f64` at `half`, from
   `fnTailGradeAgainstRet` in `half`'s own body. So `half` is checked at a signature whose
   result is already `i32`. A probe there read `inferQuiet` 0 with `curFnDeclIx` at `half`.
2. **The returned spelling fails at emit:** `the lists this function returns are built at
   different rows`.
3. **The call already types the union.** At `check_calls`' set-call branch the callee is
   `(_) => _` with a 2-member set, and `holeSetCallRetOf` answers `f64` (`joinRetTys(i32, f64)`).
   The wrong fact is `half`'s `i32` pin, not the call.
4. **The elaboration's held-list closure is not the producer.** `emit_elab.vl`'s
   `elabHeldAtArgsOr` and `elabHeldFnTy`'s call-tuple branch were made to answer a union-result
   function type instead of declining when the members disagree. That changed nothing.

**The prime suspect is the delivery.** `checkArrayLitNode` (check_container_lits.vl) types each
element alone, joins them, then delivers each element to the joined type
(`recordCtxTy(el, elemTy)`). So `{ f: half }` is delivered at a field type closed at `inc0`'s
signature, and the un-annotated `half` takes it as its contextual signature. The plain list
`[inc0, half]` keeps the element at `(_) => _` there (its type reads `((_) => _)[]`), and runs.
