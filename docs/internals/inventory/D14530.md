### D14530 — a call handed through a generic function keeps its record at its own row while another call of the same function delivers it as a declared record

**closed · now runs, prints `3` · was check-clean invalid wasm, clause 1 · filed 2026-10-27 against master `7480d5bae` · closed 2026-10-31 against master `85cef35f`: `recReadInPlace` (check_fit_rules.vl) follows an argument a generic identity alone pins to where the identity's result is read, so `mkcall` is built at `Circle`; the call's rep row reads that kept build (`recKeptFnDstOf` in `recRebuiltLeafRow`), and mono pins the identity's parameter at the rep (`monoPinAnnotatedParam`) · the list spelling in the grading list is [D14733](D14733.md) and the hole identity is [D14730](D14730.md) · fixture `generics/call-through-identity-built-at-delivery.vl`**

Repro:

    type Circle = { r: i32 | null }
    function sink(_x: Circle) { }
    function id<T>(x: T): T { x }
    function mkcall() {
      const cc = { r: null }
      return cc
    }
    sink(mkcall())
    const y = id(mkcall())
    print(y.r ?? 3)

Want:

    3

#### Mechanism

`sink(mkcall())` builds `mkcall`'s record at `Circle`. `id(mkcall())` pins `T` to `mkcall`'s own
type, so the instance of `id` stores its argument at that row while the value it receives is built
at `Circle`. The instance's TYPE and the REP of the value it holds are two facts, and the checker
carries one; serving this needs the per-instance rep flow, not another container arm. Both seeds
fail validation on line 8.

#### Grading list

`const y = reverse([mkcall()])[0]` (`reverse` from `std:array`) beside the same `sink` call is the
same shape through a list: invalid on line 8 on both seeds.
