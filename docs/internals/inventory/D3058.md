### D3058 — a closure returning a record list as `readonly Shape[]` is invalid wasm inside the lambda

**closed · the delivery site reads a captured list's row off the closure's env field, so the lambda's return reaches the view · fixture `tests/cases/closures/lambda-returns-readonly-record-view.vl` · was check-clean invalid wasm · found by the #3266 review · the same on master `b09566e16` · filed 2026-09-28 against master `b09566e16`, closed 2026-09-28 against master `67ca68cf3`**

Repro:

    type Circle = { r: i32 }
    type Sq = { s: i32 }
    type Shape = Circle | Sq
    function mkf(x: Circle[]): () => readonly Shape[] { return () => x }
    const f = mkf([{ r: 1 }])
    print(f().length)
    // vl check: rc 0.  vl run: invalid module, inside `__lambda_0`: type mismatch:
    // expected (ref $type), found (ref $type)

Want:

    1

#### Mechanism

The lambda's return did reach `emitRefListWidenSite`, with the source row from
`exprEmittedRefListSlot`. That function answers a local, a parameter or a global, and inside the
lifted lambda a capture is none of them, so the source row was -1. The site read a row of -1 as
"not a widenable pair" and emitted nothing, and the raw `Circle[]` wrapper was returned where the
union-box list is declared. A captured global resolved through the global arm, which is why the
module-level spelling ran. The capture now answers the row its env field is typed with
(`capturedRefListSlot`), and the delivery becomes the [D3041](D3041.md) view.

#### Ablation
