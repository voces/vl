### D15460 — a written `let` seeded from a hole parameter the body also calls directly is refused at the direct call

**closed 2026-11-05, runs and prints `2.25 2.5`, with the split plan on and off · was loud emit reject, `vl check` rc 0, `emitProgram: a function-value call has no interned signature`, clause 2, with the split plan on and off · found grading the seeded written-let family (D15409) · filed 2026-11-05 against master `71274700` · closed by deciding the let's wider set with the parameter's set whichever way the parameter takes it: `ftLateParamTakes` (check_fn_tag.vl) asked `ftParamSeedsWider` last, so a parameter that also took its set another way never queued the wider set · fixture `closures/written-let-seeded-by-hole-param-also-called-directly.vl`**

Repro:

    function add(a, b) { return a + b }
    function mul(a, b) { return a * b }
    function swap(h) {
      let hh = h
      hh = mul
      print(hh(1.5, 1.5))
      print(h(0.5, 2.0))
    }
    swap(add)

Want:

    2.25
    2.5

#### Mechanism

`hh` is seeded from `h` and written with `mul`, so the elaboration notes `h` as seeding
`hh`'s wider set (`mintSeedNote`, emit_elab.vl), and the tag decision takes `h`'s set with it
(`ftParamSeedsWider`). Mono pins `h` at the tagged set: the argument `add` is tagged, set 333
in the probe. The call `h(0.5, 2.0)` is then a call through the set, but no member call was built
for it, so `monoTagSetAt` finds no arm (`fnTagArmsAt`) and the call lowers as a closure call at
`h`'s open type. Without the seed note the set is partial, `h` is pinned per type and the call
runs, but taking the note out loses a `runs` cell
(`closures/forwarded-hole-fn-to-list-element-value-param.vl`).

#### The seed rule's tagged path is not served

Measured 2026-11-05. After the decision tags `add`, each elaboration round binds `swap`'s hole to the
tagged set (`elabSetArgBind`), but the hole-pin rows the root check banked before the tag still bind
the same hole to `add`'s function type, and `elabDrainHoleRows` mints a second, closure-typed
instance from them. Skipping those rows leaves only the tagged instance: `h(0.5, 2.0)` then gets its
arms, and the failure moves to `hh(1.5, 1.5)`, whose wider set `{add, mul}` is not typed or
dispatched as tagged there. The cause was the order in `ftLateParamTakes`: `ftParamSeedsWider`,
which queues the wider set to be decided with the parameter's, came after `mintParamTakes`, so a
parameter that took its set as a callee never queued it and `{add, mul}` stayed untagged.
[D15018](D15018.md)'s fixture, the same `swap` without the direct call, ran on the stale closure
instance. With the seed check first the wider set is tagged and both calls dispatch through it;
the stale rows no longer decide any witness here.

#### Ablation

| ingredient changed | outcome | needed? |
| --- | --- | --- |
| the direct call `h(0.5, 2.0)` removed | runs, `2.25` | **yes** |
| `hh` not written again (`let hh = h` only) | runs | **yes** |
| `let hh = mul; hh = h` (written from `h`, not seeded) | runs | **yes** (the seed) |
| `h(1, 2)`, a second type | refuses the same way with the plan off; runs with it on, through the split | no |
