### D5713 — a one-arm `match` whose body is a block has no value

**loud emit reject · `vl check` rc 0 · clause 2 · lane L3 · filed 2026-10-17 against master `bb4448de7`**

Repro:

    function f(n: i32): i32 {
      const s = match n { _ => { 5 } }
      s
    }
    print(f(1))
    // vl build: emitProgram: unsupported expression

Want:

    5

#### Mechanism

D5711 lowers a lone arm with an EXPRESSION body to that expression. A block body stays a bare
`Block`, and VL has no valued bare block (`function f(): i32 { { 5 } }` is refused too), so
the initializer reaches the emitter as an unsupported expression, and as a function tail the
checker says "not all code paths return a value". The same block body in a two-arm match is
an `if` branch and runs.

#### Ablation

| ingredient removed | outcome | needed? |
| --- | --- | --- |
| the body `5` without braces | runs (D5711) | **yes** |
| a second arm `1 => { 4 }` added | runs | **yes** |
| the match used as a statement | runs | **yes** |
| the match as the function's tail | still refused (check: not all code paths return a value) | no |

#### Grading list

The function-tail spelling, a block body with a `const` before its tail, and a struct-union
scrutinee.
