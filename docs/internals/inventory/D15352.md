### D15352 — a list literal of maps whose function values are a set and a smaller set, the smaller set's map first, is refused at emit

**open · loud emit reject · `emitProgram: ref valtype with no interned shape` · clause 2 · the wider set's map first runs since D15234 · found closing D15234 · filed 2026-11-04 against master `9a45989d`**

Repro:

    function inc0(a) { return a + 1 }
    function half(a) { return a / 2.0 }
    const fnMap = Map()
    fnMap.set("a", inc0)
    fnMap.set("b", half)
    const m2 = Map()
    m2.set("a", half)
    const xs = [m2, fnMap]
    const g = xs[0].get("a")
    if g != null { print(g(3)) }

Want:

    1.5

#### Mechanism

The list literal's element type is its FIRST element's: with `m2` first, `xs` is a list of maps
of `{half}`, and the plan for `{half}` refuses `fnMap`, whose value carries the wider set
(`ftLitJoin`'s list-of-maps arm admits only a smaller set). Admitting the wider set there (deciding
it with `{half}`, the mirror of D15234) runs this witness and is WRONG on its neighbours: every
read through `xs` dispatches on the list's element set, so `xs[1].get("a")(3)` calls `half` and
prints `1.5` where `inc0` gives `4` (check-clean silently wrong, measured on lane G2's D15351
branch). The fix is the list literal's type, a join of its elements' map types at the wider set,
not the tag plan.

#### Ablation

| ingredient removed | outcome | needed? |
| --- | --- | --- |
| the order (`[fnMap, m2]`) | runs (D15234) | **yes** |
| `xs[0]` → `xs[1]` read | still refuses | no |

#### Grading list

`xs[1].get("a")(3)` and `for m in xs { m.get("a")(4) }` over `[m2, fnMap]` must print `4` and `2`, `5`.
