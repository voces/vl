### D3822 — a hole receiver typed only by its call site lets a lambda argument's `T` bind at check and arrive at emit with no interned signature

**loud emit reject · filed 2026-10-07 against #3430 (`35ed60c0a`, found in review)**

Repro:

    function each<T>(self: T[], f: (T) => void) { for x in self { f(x) } }
    function cnt3<T>(x: T): i32 {
      let n = 0
      x.each((v) => { n = n + 1 })
      n
    }
    print(cnt3([1, 2, 3, 4]))
    // vl check: rc 0.  vl run: "a function-value call has no interned signature —
    // no function value of type `(i32)=>void` reaches this call to intern its signature"

#### Mechanism

#3430 types a member call's lambda from the receiver-bound `T`. Here the receiver `x` is a
bare `T` (a hole until `cnt3` is instantiated at `i32[]`), so the lambda's parameter type is
fixed per instance, but no function value of `(i32)=>void` is ever interned for the
instance's `f(x)` call. Before #3430 the same program was refused at check ("cannot infer
a type for parameter `v`"), so this moved a check refusal to an emit refusal: no runs lost.
The outcome also depends on the type variable's NAME: rename `each`'s `T` to `U` and both
spellings refuse at emit with "monomorphize: unsupported argument type for `f`", and the
plain call `each(x, …)` refuses at check with "i32[] flows into `each` expecting i32[][]",
which looks like a type-variable capture between `cnt3`'s `T` and `each`'s `T`.

#### Ablation

| ingredient removed | outcome | needed? |
| --- | --- | --- |
| `cnt3`'s receiver annotated `x: i32[]` | runs | **yes** |
| `each`'s `T` renamed to `U` | emit refuses (different message) | partly |
| method spelling → `each(x, (v) => …)` | check refuses (`i32[][]`) | no |

#### Grading list

- the `U`-renamed twin, and the plain-call spelling (expected to run once fixed)
