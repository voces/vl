### D17863 — a tagged choice and a closure at its own signature share one instance of a callee called first with the choice, so the closure is converted to an id

**loud emit reject · clause 2, one value wanted at two reps, the tagged id through `ap` and the closure at an annotated destination · `emitProgram: the compiler cannot yet lower this statement (convert closure -> i32)` · the one grid cell M1 moves from a check reject (the annotated `through_ap` cell of the template for D17100's shape, tagged) · filed 2026-11-28 against master `15901f4e3` by lane CENSUS**

Repro:

    function bo(_a) { return true }
    function str(_a) { return "s" }
    function ap(g, x) { return g(x) }
    function flag(): boolean { return 1 > 0 }
    const g = if flag() { str } else { bo }
    print(ap(g, 3))
    const w: (a: i32) => string | boolean = g
    print(ap(w, 4))
    // vl check: rc 0.  vl build: emitProgram: the compiler cannot yet lower this statement (convert closure -> i32)

Want:

    s
    s

#### Mechanism

Located to the instance, not the lowering. Whenever `ap(g, …)` with the tagged set is called before
`ap(w, …)` with the closure, the build fails at `g`'s binding; with `ap(w, …)` first, it runs. So
`ap`'s instance for the set's id and its instance for the closure at the same signature are one
instance, whose parameter takes the first call's rep; an id converts to a closure, a closure does
not convert to an id. Not reached for an open-result choice (`inc` for `bo`), in either spelling
of the destination's result union; why the closed join's type keys like the closure was not found
inside the 30-minute box.

Direction (coordinator, 2026-11-28): the outcome depends on call order, which breaks order-free
decide-once. The fix keys the callee's instance on the argument's rep as well as its signature,
decided from every call, never from the first.
