### D16484 — `??` over a list cell whose index has a side effect is refused at emit

**closed 2026-11-15 · runs, prints `1` then `1` · was a loud emit reject, clause 2: `vl check` rc 0, then emitProgram: ?? over this nullable value is not supported yet; the re-readable index ran since D16483 · fixed 2026-11-15 by lane L: a `??` over a list cell joins the compound writes' value-position spill (`spillsItsPlace`, emit_rewrite.vl), so the receiver and index run once into locals and the re-readable cell takes D16483's null test; the spill's never-run else arm lowers as dead (D16485) · found closing D16483 · filed 2026-11-15**

Repro:

    import { F32x4, splatF32 } from "std:simd"
    let n = 0
    function idx(): i32 {
      n = n + 1
      return 0
    }
    const xs: (F32x4 | null)[] = []
    xs.push(splatF32(1.0))
    print((xs[idx()] ?? splatF32(0.0)).x)
    print(n)

Want:

    1
    1

#### Mechanism

The null test D16483 lowers to reads the cell twice, so an index that is not re-readable
(`exprReReadable` refuses a call) could not take it. The receiver and index now spill once, as
a compound write's do, and the spilled cell is re-readable.
