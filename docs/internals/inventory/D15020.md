### D15020 — an if of record literals delivered to an annotated record whose field is a numeric union is built at no row that field holds

**closed 2026-11-02 · runs, prints `2.5` `1` · was check-clean invalid wasm, clause 1 · `recordRepTyAdopt` (check_fit_rules.vl) stamps a value `if`, `match` or block whose arms took a record destination with that record, so its block type is the destination's row and not the arms' join · fixture `tests/cases/structs/if-of-record-literals-at-numeric-union-field.vl` · the generic union-of-records cells are [D15042](D15042.md) · found grading D14021's direct spellings · filed 2026-11-02 against master `fe466a46`, pre-existing**

Repro:

    function g(b: boolean) {
      const v: {f: i32 | f64} = if b { {f: 2.5} } else { {f: 1} }
      print(v.f)
    }
    g(true)
    g(false)
    // vl check: rc 0.  vl run: the emitted module failed to validate inside `g`

Want:

    2.5
    1

#### Mechanism

Located 2026-11-02. The checker stamps each arm literal at the destination record, so both arms
are built as `{f: i32 | f64}` with a boxed field, but it never stamps the `if` itself. The emitter
takes the `if`'s block type from its stamp, else its type (`ifTypedStructRow`), and its type is
the join `{f: f64}`, so the block says one row and the arms another. The field's union is all numbers: `{f: i32 | string}` at the same position
runs, and so does `{f: i32 | f64}` holding one literal, or the same `if` as a function's
annotated result. The if-join of the arms is `{f: f64}` by record widening (D2731), so the
destination's numeric-union box and the join's `f64` field disagree at the binding.

#### Close

`recordRepTyAdopt`'s `IfStmt | Block | MatchExpr` arm now stamps the node itself with the
destination when the destination is a record and an arm took the stamp. Every position the
ablation names runs: the arms swapped, module scope, `{f: i32 | i64}`, an `else if` chain, a
`match`, an assignment, an argument, a second field, a named alias. The generic
`{f: i32 | T}` annotation runs at `T := f64` too.
