### D10270 — a generic's `() => x` handed to `() => T | string` at `T = string` instances the callee with `T` unbound

**closed · runs, prints `0` · was check-clean invalid wasm, `type mismatch: expected (ref $6), found (ref $1)` inside `len`, clause 1 · closed in check_emit_queries.vl (`bindGenBareArmAtMember`: a closed argument that is exactly one fixed member of `T | string` binds `T` to it, so the emitter's arena binding agrees with the checker's) · fixture `generics/enclosing-param-into-generic-union.vl` (`outer` at `"abc"`, `2.5`, `7`, `"hello"`, and the annotated `(): U | string => x` face) · found closing [D10241](D10241.md) · filed 2026-10-22 against master `cf2f91c99`**

Repro:

    function len<T>(f: () => T | string) {
      const t = f()
      if t is string { 0 } else { 1 }
    }
    function outer<U>(x: U) {
      print(len(() => x))
    }
    outer("s")
    // vl check: rc 0.  vl run: invalid module inside len

Want:

    0

#### Mechanism

At the pin `U = string` the delivered argument is `() => string`. The checker's spelling
binding took `T := string`, but the emitter's arena binding (`monoBindCols` →
`bindGenUnionShapedArmInto`) bound a union-shaped parameter only from a union argument, so
`T` stayed unbound and the instance read `t: T | string` as the i32-array default rep. The
lambda's adaptation is not the ingredient: the annotated `(): T | string => x` failed the same
way, and so did a `const g = (): U => x` handed in by name.
