### D10270 — a generic's `() => x` handed to `() => T | string` at `T = string` instances the callee with `T` unbound

**check-clean invalid wasm · `vl check` rc 0 · `the emitted module failed to validate inside `len`: ... type mismatch: expected (ref $6), found (ref $1); $6 is `i32 array (list and map storage)`` · clause 1 · present on master `cf2f91c99` · found closing [D10241](D10241.md) · filed 2026-10-22 against master `cf2f91c99`**

Repro:

    function len<T>(f: () => T | string) {
      const t = f()
      if t is string { 0 } else { 1 }
    }
    function outer<U>(x: U) {
      print(len(() => x))
    }
    outer("s")
    // vl check: rc 0.  vl run: invalid module inside len

Want:

    0

#### Mechanism

Not traced. At the pin `U = string` the callee's result `T | string` collapses to `string`,
so nothing binds `len`'s `T` and its instance reads `t` as the i32-array default rep. The
lambda's adaptation is not the ingredient: the annotated `(): T | string => x` fails the same
way, and so does a `const g = (): U => x` handed in by name.

#### Ablation

| ingredient changed | outcome | needed? |
| --- | --- | --- |
| `outer` not generic, `x: string` | runs, `0` | **yes** |
| `len<string>(() => "s")` at top level | runs, `0` | **yes** (the pin) |
| `outer(5)` in place of `outer("s")` | runs, `1` | **yes** (`T = X`) |
| the lambda annotated `(): U \| string => x` | same invalid wasm | no |
