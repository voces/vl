### D16032 — the `unNames` label of a type-reached union is canon of a render, not spelled from the type

**closed 2026-11-14 · runs, prints `2` · the label is spelled from the type: `arenaEmitName` is `tyToNominalName` and `canonUnionMembersWalk` labels each member by its nominal render, with no canon re-parse; `canonEmitNameOfTy` and `canonEmitName` are deleted · 1 of 19,769 programs moves bytes with identical output, 0 `runs → not-runs` · was 301 of 37,371 `arenaEmitName` calls rewritten, 78 distinct · filed 2026-11-13 against master `580eb218`**

Repro:

    type Node = { v: i32, next: Node | null } | { e: i32 }
    function len(n: Node | null): i32 {
      if n == null { return 0 }
      if n is { e: i32 } { return 1 }
      1 + len(n.next)
    }
    const a: Node = { e: 9 }
    const b: Node = { v: 1, next: a }
    print(len(b))

Want:

    2

#### Mechanism

`arenaEmitName` (emit_collect) renders a reached union with `tyToNominalName`. It then hands the
string to `canonEmitNameOfTy`, which re-parses it with the check_program canon parsers. That is
a render followed by a parse. The result is only the union's `unNames` label; registration is
keyed by type (`unRowOfTyKey`, #7809). The same round trip sits inside `canonUnionMembersWalk`
(check_program): `canonEmitNameAt(tyToNominalName(leaf), ctx)` for each member.

A probe drained after `emitProgramRun` over the sweep population (master `580eb218`) found that
canon rewrites the render in 301 of 37,371 calls, 78 distinct. The rewrites are:
- an alias expanded to its members: `Node|null` becomes `{v:i32,next:Node|null}|{e:i32}|null`;
- a non-union alias expanded: `JO` becomes `{[string]:J}`, `Box<i32>` becomes `{v:i32}`;
- literal-union aliases softened or regrouped by position: `K|L|i32` becomes `string|i32`, while
  `i32|K|L|null` becomes `i32|"a" | "b" | "x" | "y"|null`.

No typed render reproduces it. `tyToEmitName` keeps alias names and renders recursive members
empty. `canonUnionKeyTextOfTy` keeps declared names. `canonUnionMemberTysOf` is canon
underneath. A typed canon would be a second spelling-derived speller.

#### Closed

With no reader, fallback or registration deciding by label (the checklists above, and
[D16025](D16025.md)), the label only names a row. The grading list's two sites now spell it from
the type: `arenaEmitName` is `tyToNominalName`, and `canonUnionMembersWalk` labels a member by its
`tyToNominalName`. `canonEmitNameOfTy`, `canonEmitName` and `canonTwinArmsShareRow` are deleted,
and so are their two `render-parse-floors.txt` entries. Canon itself stays: the checker's
annotation pass still uses it.
