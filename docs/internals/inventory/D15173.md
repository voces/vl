#### Mechanism

Mono pins `u`'s hole parameter at `J` for `u(r())` from the checker's rebuilt row (`monoRebuiltLitRetName`, `recRebuiltRetRow`), and at the literal's `{f: i32}` for `u({ f: 1 })`. The elaboration binds the hole `?u.0` at the argument's checked type, `{f: i32}`, at both calls, and mono's demand for the `J` instance is answered by that key. The type-parameter twin of this was closed by the elaboration's call binding taking the rebuilt row (#6105); the same rule applied to a hole binding is a measured dead end. Retyping `?u.0` to the rebuilt row also retypes the parameter for the hole solve and the body walk, and it broke three files: the source of this witness, `soundness/returned-binding-built-wider-handed-to-hole-param-runs.vl`, became invalid wasm in its top-level code (`expected i32, found (ref $type)`); `generics/hole-instance-typed-at-binding-stored-at-build.vl` and `closures/hole-fn-inline-list-record-stored.vl` stopped building (`unsupported argument type for p in a call to take`), and `closures/hole-fn-inline-and-annotated-list-one-param-reached.vl` with them. A close needs the hole's delivered record as a key fact that leaves the hole's type alone. That is necessary and not sufficient: a key-only entry (a `#r.` binding per hole parameter carrying the argument's rebuilt row's `recordRowClassOf`, the hole's type and the body walk unchanged) splits the witness's two `u` instances and prints `4 1 4`, and turns the source file's `print(u(r()) + u({ f: 1 }))` into the same invalid wasm (`expected i32, found (ref $type)`), because the split instance still walks `a.f` at the shared checked type. The close moves the key and the instance's walk type together, after D15172.
