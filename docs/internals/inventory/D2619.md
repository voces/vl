### D2619 — a value `if` whose every tail is a literal f32 holds exactly is refused at an `f32` destination that the bare literal flows into

**closed 2026-09-26 — the witness prints `3` · was loud check reject, clause 2 · found grading
[D2617](D2617.md)'s float destinations · filed against master `e289f84d7` · fixture
`tests/cases/numerics/f32-literal-tails-of-value-if.vl`**

Repro:

    function f(c: boolean) {
      let x: f32 = 0
      x = if c { 3 } else { 4 }
      print(x)
    }
    f(true)
    // vl check on master: cannot assign i32 to f32 — while `x = 3` runs

#### Mechanism

A literal re-encodes exactly at `f32`, so `assignableExpr` grants it an f32 destination
(`isF32AdoptingLitExpr`). A value `if`, `match` or block whose tails are all such literals is
typed by its join (`i32`, or `f64` for `3.5`), and neither type flows into `f32`, so the checker
refused what each tail alone would be granted; only a typed tail return, which delivers each arm
separately, ran. The close grants the join when every tail adopts f32 (`f32LitTailsAdopt`, over
the same tail walk as [D2617](D2617.md)), at an `f32` destination or its nullable and beside an
f32 operand, and re-types its `if` and `match` nodes `f32`. `exprIsF64`'s arm inspection yields
to that type, so a join of float literals is built at f32 rather than f64.
