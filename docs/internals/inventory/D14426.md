### D14426 — a hole instance reached by a kept function's result is typed at the record that result is built as, which the body was never checked against

**closed · now runs, prints `5` · was check-clean invalid wasm, clause 1 · kind 1 of [D14515](D14515.md) · filed 2026-10-27 against master `7ba96d0a4` · closed 2026-10-31 against master `cb178881` by the c-2 ruling: `callBindAdoptReps` (check_bind_adopt.vl) records the adopted record as the call's REP row beside the checker's binding instead of rewriting it, the elaboration keeps the instance at the binding (`elabPinTakes`), mono pins the parameter at the rep (`callArgRepTy`), and a parameter's storage, a `let` copying it and a result returning it read the rep (`paramStructIndex`, `paramHeldTy`, `monoRetRepOf`) · fixture `generics/hole-instance-typed-at-binding-stored-at-build.vl`**

Repro:

    type II = { f: i32 }
    type J = { f: i32 | null }
    function mk() { { f: 4 } }
    const wideJ: J = mk()
    const wideF: i32 = wideJ.f ?? 0
    function __take(a) {
      const v = a
      print(v.f + 1)
    }
    __take(mk())

Want:

    5

#### Mechanism

The `wideJ` delivery keeps `mk`'s result typed `{f: i32}` and builds it as `J`. At module scope,
`const v = mk()` keeps that type, carries `J` as its rep, and its read unboxes the field.

Two ingredients:

- **`callBindAdoptRekey` (check_bind_adopt.vl, D8202) is the producer.** It rewrites the call's
  bind row to the argument's built record. So `J`, a rep row, becomes the binding the `__take`
  instance is TYPED at, and the body is never checked against it. Under `J`, `v.f` reads
  `i32 | null`. `==` is legal on that union and compares tags, so a `v.f == 4` guard still
  runs. `+` is ill-typed.
- **The quiet elaboration re-check swallows the type error.** The instance's re-check at `J`
  raises nothing, and the emitter lowers `+` as a raw `i32.add` on the field's box.

Two things do not fix it:

- Removing the rekey alone moves the failure. The instance is typed `{f: i32}` while its
  parameter stays pinned at `J`, and `const v = a` is stored at `II`.
- Reading the field by the instance's type does nothing, because that type is `J` too.

The fix keeps type and rep as separate facts within an instance:

- the instance stays at the checker's binding;
- the parameter's pin is its rep;
- a `let` or `return` copying it takes that rep, through the same carrier literals use;
- the quiet re-check refuses loudly on any type error.

#### Close

The instance's type and its rep are separate facts, as the c-2 ruling directs. The checker's
bind row keeps the binding (`{f: i32}`). The adopted record (`J`) is a rep row beside it
(`callBindAdoptReps`, which no longer rewrites the type row), and mono pins the copy's
parameter at that rep. The elaboration takes the checker's instance for a pin that is a wider
record over the same fields (`recRepWidens`). So the body is checked at `{f: i32}`, the read
`a.f` is typed `i32` over a `J` box, and it unboxes. A `let` copying the parameter is stored at
the parameter's annotation (`paramHeldTy`), and a result that returns it is the pin
(`monoRetRepOf`). Over the 6,988 `tests/**/*.vl`, the change is byte-identical.
