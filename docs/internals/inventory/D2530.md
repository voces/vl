### D2530 — a value-position `i32` write into an `f32` or a nullable scalar cell re-reads the cell at its own rep

**closed 2026-09-25 — the filed repro RUNS and prints `7` / `4` · was check-clean invalid wasm, clause 1 · found by #3167's review · filed 2026-09-25 against master `680b67486`**

Repro:

    let a: f64 | null = null
    function k(): i32 { 3 }
    function h(p: i32, q: i32) { p + q }
    print(h(k(), a = 4))
    print(a ?? -1.0)
    // vl check: rc 0.  vl run: invalid module, expected i32

#### Mechanism

A value-position write that stays in place (an operand before it is a call) lowers as
store-then-re-read, and [D2512](D2512.md) taught `asgReadUnwidenOp` to take the re-read back to
the right side's rep for `f64`, `i64` and a ref in its own niche. Two widenings had no inverse:
an `i32` literal into `f32` (the checker admits only exactly representable ones, so
`i32.trunc_f32_s` is exact), and an `i32` into `f64 | null`, `f32 | null` or `i64 | null`, whose
cell is the value-union box. The box is now re-read under its inner member's narrowing
(`asgReadNullInnerTy`, pushed by `pushAsgReadNarrow`) and then unwidened like the bare scalar.

#### Ablation

| ingredient removed | outcome | needed? |
| --- | --- | --- |
| the call before it (`h(3, a = 4)`) | runs: the write is hoisted | **yes** |
| `a: f64` (no `null`) | runs since D2512 | **yes** — `f32`, or a nullable cell |
| `a: i64 \| null` | same | no |
| the program inside a function | same | no |
| a binary operand or a list element instead of an argument | same | no |

#### Grading list

* `f32`, `f64 | null`, `f32 | null`, `i64 | null` cells, at argument, operand and element positions.
* Module and function scope.
