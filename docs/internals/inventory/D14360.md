### D14360 — a module `let` with no initializer, read through a function before its first write, reads the cell's zero

**check-clean silently wrong · clause 1 · open · the no-initializer face of [D2652](D2652.md), reachable since [D14281](D14281.md) gave the binding a cell · filed 2026-10-26 against master `bcfaf4328`**

Repro:

    let i: i32
    function readI() { return i }
    print(readI())
    i = 2
    // PRINTS 0

The program should stop with a runtime error naming `i`, as D2652's ruling gives a global read before its
initializer ran.

#### Mechanism

The checker's definite-assignment pass orders a write before every read in top-level code,
but not before a read inside a function body, which may run at any call. D2652's guard
covers that read for a binding with an initializer: the start function advances a progress
cell past the declaration, and a read checks it. A binding with no initializer has no such
point — its first write can be any assignment, at top level or in a function — so the guard
does not apply (`gInitGuard` stays 0) and the read returns the cell's zero default.

#### Ablation

| ingredient removed | outcome | needed? |
| --- | --- | --- |
| the scalar type (`let s: string`) | traps `null reference`, loud, naming no binding | yes, for the silent outcome |
| the read inside a function (`print(i)` at top level) | check reject, used before assigned | **yes** |
| the call before the write (`i = 2` first) | runs, `2` | **yes** |

#### Grading list

The ref-typed spelling above, which should name the binding rather than trap anonymously.
