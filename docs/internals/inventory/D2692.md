### D2692 — an annotated `{[string]: boolean} | {[string]: boolean | null}` passed to a `{[string]: boolean | null}` parameter builds invalid wasm

**check-clean invalid wasm · clause 1 · found in the #3194 review · identical on master
`1be1363d9` · filed 2026-09-26 by the W2 lane**

Repro:

    function take(m: {[string]: boolean | null}) { m.length }
    const a: {[string]: boolean} = Map()
    const u: {[string]: boolean} | {[string]: boolean | null} = a
    print(take(u))
    // vl check: rc 0.  vl run: invalid module in the top-level code, "type mismatch: expected (ref $type)…"

#### Mechanism

Not yet measured. The checker accepts the union as the parameter's type because each member is
assignable to it (the two maps share one storage), but the argument is the union box and the
parameter is the bare map struct; no unbox is emitted at the call. The same program with the
join spelled un-annotated (`if c { a } else { b }`) collapses to the wider map and runs.

#### Ablation

| ingredient removed | outcome | needed? |
| --- | --- | --- |
| the union annotation (`const u = a`) | runs | **yes** |
| the parameter (`u.length` read directly) | refused at check: `.length` is not on every member | no |
