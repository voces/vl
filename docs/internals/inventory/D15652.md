### D15652 — a call's fresh record as a part of a list literal beside a part built at a wider record refuses, though nothing shares it

**open · loud check reject · clause 2 · `this record, returned by a call, is fresh and type-valid here, but not supported yet: it is not built where a list holding elements built as J (line 6) takes it` · found closing D15372 and D15375 · filed 2026-11-10 against master `2e71e5a1`**

Repro:

    type J = { f: i32 | null }
    function mk() { { f: 4 } }
    const wideJ: J = mk()
    const xs = [mk()]
    function os0() { { f: 1 } }
    const ws = [xs[0], os0()]
    print(ws[1].f ?? 0)

Want:

    1

#### Mechanism

Not ablated past the table. The list stamp (`recListLitBuild`) builds a fresh record literal part,
or a part reading a fresh record `const`, at the build the other parts agree on (D15371, D15372),
but a call's result has no literal to stamp, so the part is refused (`recListPartsApartRefuse`).
Delivering the call there (`recAdoptNote`, as `recHeldBindAdopt` does for a held call) runs the
plain `os0()` and `const o = os0()` spellings, but a maker whose call is also held at its own
type elsewhere then traps the compiler in `recStoresAgree` (`tyAt` of a missing type), and a
generic's call is not built by it at all, so that change was not shipped.
