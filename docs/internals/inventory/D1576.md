### D1576 — a NEVER-FILLED `let x = null` is the `null` TYPE, and the type already had a rep: the hole was answered at scope close instead of flowing on as `-1`

**closed 2026-09-04 — the witness runs and prints `0` · was `loud emit reject` (`emitProgram: ?? over this nullable value is not supported yet`, `vl check` rc 0) and, at six delivery positions, `check-clean invalid wasm` · clause 2 and clause 1 · fixed by resolving the unfilled A-infer-null hole to the `null` type at scope flush and giving the binding D1567's `nulnone` cell · left loud by [D1575](D1575.md) (#2506); the `nulnone` answer from [D1567](D1567.md) (#2502)**

Repro (prints `0`):

    function go(c: boolean) {
      const x = null
      const y = (if c { x } else { x }) ?? 0
      print(y)
    }
    go(true)

#### Mechanism

`let x = null` / `const x = null` binds `mkNullableTy(-1)` — the A-infer-null hole, a
`TyNullable` whose inner is not yet a type, filled IN PLACE by the first non-null assignment.
**Nobody ever asked what happens when no assignment arrives.** The `-1` flowed on: D1575
bound-tested 22 readers of it in `typecheck.vl` so the compiler stopped trapping, and the
program then took the loud refusal every delivery of a value with no rep takes.

The answer is that a binding whose only value is `null` **has the `null` type**, which is not
`T | null` for any `T` — and [D1567](D1567.md) already built that type's rep: `nullref`, the
bottom of the GC hierarchy, one value and a subtype of every nullable REF valtype. Two halves:

* **The checker resolves the hole rather than reporting it.** `noteNullHole` records every
  minted hole with the scope depth that owns it; `flushNullHoles`, called from
  `flushUninferred` at the close of the declaring scope — D1470's "every pin gets its chance"
  point — re-reads `nInner` and banks the LetDecl node when it is still `-1`. That is an
  inference that SUCCEEDED with the answer `null`, not the uninferable-`[]` floor beside it,
  so nothing is reported. The A20 recorder makes the same reading for a RETURN of the hole
  (`IR_REC_NULL_ONLY`, banked at `TY_NULL`), which retires the
  `infers the nullable return type _ | null … not yet supported by codegen` refusal.
* **The emitter gives the binding the `nulnone` cell, and a READ of it takes the
  DESTINATION's null rep.** `letIsNulNone` is the gate `collectLocals`, `letInitCellKind`
  (which types a CAPTURED such binding's env field) and `globalCellKindGo` share.
  `emitIdentNode` then routes the read through `emitNullBySeed` — the same table a bare
  `null` LITERAL reads — so every position the literal already reaches is reached here too,
  with `ref.null none` as the last resort where nothing seeded. That is the whole position
  matrix in one arm rather than a conversion per site.

Three consumers needed arms because the value is STATICALLY null and no rep can be read out
of it: `x ?? d` is `d`, `x == null` is `true` (`!=` false), and `print(x)` writes the word.
Each also closes the same shape for a `nulnone`-returning CALL — [D1567](D1567.md)'s named
residue (a) and (b) — because `exprIsNulNone` is one home for both spellings.

**AND TWO MORE `.nInner` READERS TRAPPED THE COMPILER, both OUTSIDE `typecheck.vl`, which is
why D1575's sweep could not see them.** `mapUnionRetName` is reached only through a LAMBDA's
inferred return (`checkFuncDeclNode` under `checkLetDeclNode`), and
`cloCallUnionResultUnrepresentable` (`emit_classify.vl`) only through that lambda's
`call_ref`. `const x = null` + `() => x` therefore still died with the seed's own
`out of bounds array access` on a `vl check`-clean program, at CHECK and then at EMIT — one
witness, two rungs, refusals in layers. Both now bound-test, on D1500's family rule.

#### Ablation

Graded on master `ac666db0`'s own fixpoint seed, one ingredient per row.

| ingredient removed | outcome | needed? |
| --- | --- | --- |
| the if-expression (`x ?? 0` straight) | refuses | no |
| the `??` (`x != null` instead) | refuses (`bare null needs a struct-typed context`) | no |
| the `??` (`print(x)` instead) | **runs, printing `0`** | **yes** — a silent wrong value |
| at MODULE scope rather than in a function | refuses | no |
| delivered to a `C \| null` binding / argument / field / return | **check-clean INVALID WASM** | no |
| delivered to an `i32 \| null` binding | **runs, printing `0` where `?? 9` owes `9`** | no |
| captured by a lambda (`() => x`) | **COMPILER TRAP**, at `mapUnionRetName` | no |
| one arm a real value (`if c { x } else { 1 }`) | refuses, and STILL refuses | **yes** — that join is a real `i32 \| null`, not this |
| the hole FILLED by a write (`if c { x = 1 }`) | runs | **yes** |
| the ANNOTATED spelling (`const x: C \| null = null`) | runs | **yes** — the annotation pins the rep |

The last three rows say what the defect is NOT: not `= null`, not the `??`, and not a
nullable. It is a hole that is NEVER FILLED, whose type is `null`.
