Repro:

    function F<A, B>(k: i32, a: A, b: B) {
      const v: A | B | null = if k == 0 { a } else if k == 1 { b } else { null }
      print(v ?? 9)
    }
    F(0, true, "s")
    F(2, true, "s")
    // vl run: prints true, then wasm trap: cast failure (before the close)

Want:

    true
    9

#### Mechanism

`joinTys` folds a concrete sibling into a WRITTEN union of type parameters, because a type
parameter member accepts anything: `v ?? 9` and its `if` spelling both type as `A | B`, so a pin
reads the `9` as `boolean | string`. The `if` spelling traps too, and at the `(string, boolean)`
pin the witness prints `s`, `true` (silently wrong). A kept-apart join (`tpJoinUnions`) has this
rule already (`gradualUnionJoin`'s concrete-beside arm); a written union has none. Lane NJ's one
round, a `joinTys` arm keeping a written union of open-body parameters apart from a concrete
type it does not hold, closed this witness and moved 2,675 cells of a 16,464-cell pin × shape
grid to right, but lost 384 right cells, nearly all a `??` over a kept-apart join with a
literal or runtime default (`union atom has no value box`, `` `??` over this nullable value is
not supported yet ``) and an `f64-i32` `if` arm beside a literal bound or listed (invalid wasm).
Those readers are this row's work; split out under the one-round rule.

Ablated 2026-11-02, the lost cells were no reader's fault: `const r = if true { v } else { 9 }`
with `v: A | B` at pin `(f64, i32)` builds the `f64 | i32` box from its arm, and the binding's
type, the join re-joined at the pin, widened `A`'s and `B`'s members to `f64` because a
join kept apart only by its literal re-joins every member as literals do. Re-joining the written
union's members apart and folding the literal into them is the close; marking the whole join
apart instead boxes `9` beside `f64 | f64` and loses `(v ?? 9) == 9` and `[v ?? 9]` there.
