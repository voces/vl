### D17815 — a `const` holding a hole function a generic identity hands back, delivered to a wider function type, finds no hole instance, so its adapter is built where emit refuses the function as a value

**open · loud emit reject · clause 2 · `emitProgram: cannot take the generic function inc as a value`, raised in the adapter the wider destination needs · re-graded 2026-11-28 on a fixpoint seed of master `70ca072f2`: filed as `loads then traps` (clause 1, a trap on a seed of `d76847374`), it refuses at emit since a commit in `d76847374..785e1e21` · filed 2026-11-28 by CENSUS**

Repro:

    function inc(a) { return a + 1 }
    function id<T>(t: T): T { return t }
    const g = id(inc)
    const k: (a: i32) => i32 | string = g
    print(k(4))
    // vl run: emitProgram: cannot take the generic function `inc` as a value

Want:

    5

#### Mechanism

Not fixed. The delivery needs an adapter, since the result widens. `fvaAdapt` (check_assignable.vl)
finds no hole instance for `g` (`fvaHoleDeclOf` resolves `const g = inc`, not a `const` bound to
a call), so it notes an escape. The restarted check builds the stable adapter `(fp0) => g(fp0)`
at `g`'s open type, where emit refuses `inc` as a value.

#### Ablation

| ingredient removed | outcome | needed? |
| --- | --- | --- |
| `id` (`const g = inc`) | runs | **yes** |
| the wider result (`(a: i32) => i32`) | runs | **yes** |
| the annotated let (a parameter `k: (a: i32) => i32 \| string` of a called function) | still traps | no |
| a binding of `inc` first (`const h = inc; id(h)`) | still refuses | no |

Calling `g(4)` directly as well refuses with the same sentence, and so it does without any
widening (`const k: (a: i32) => i32 = g`).
