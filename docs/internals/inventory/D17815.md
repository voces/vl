#### Mechanism

`const g = id(inc)` delivered to `(a: i32) => i32 | string` needs an adapter, since the result
widens. `fvaAdapt` (check_assignable.vl) found no hole instance for `g`: `fvaHoleDeclOf` read a
name only through `holeFnArgDecl`, which resolves `const g = inc` but not a `const` bound to a
call. So the delivery was noted as an escape, and the restarted check built the stable adapter
`(fp0) => g(fp0)` at `g`'s open type, where emit refuses `inc` as a value. With the instance
found, the adapter is built in the first pass at `inc`'s `(i32) => i32`. `g`, a value and not a
name of a function, is read once into it like any other value (the non-stable path).

#### Ablation

| ingredient removed | outcome | needed? |
| --- | --- | --- |
| `id` (`const g = inc`) | runs | **yes** |
| the wider result (`(a: i32) => i32`) | runs | **yes** |
| the annotated let (a parameter `k: (a: i32) => i32 \| string` of a called function) | still traps | no |
| a binding of `inc` first (`const h = inc; id(h)`) | still refuses | no |

Calling `g(4)` directly as well refuses with the same sentence, and so it does without any
widening (`const k: (a: i32) => i32 = g`). That spelling is its own row.
