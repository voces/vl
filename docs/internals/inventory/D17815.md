### D17815 — a hole function returned by a generic identity and delivered to a wider function type is called at the hole's own signature

**open · loads then traps · clause 1 · `vl check` rc 0, `wasm trap: indirect call type mismatch` · filed 2026-11-28 against master `785e1e21` by CENSUS**

Repro:

    function inc(a) { return a + 1 }
    function id<T>(t: T): T { return t }
    const g = id(inc)
    const k: (a: i32) => i32 | string = g
    print(k(4))
    // vl check: no errors.  vl run: wasm trap: indirect call type mismatch

Want:

    5

#### Mechanism

Not traced. Delivered directly (`const g = inc`), the value is adapted to the wider
`(a: i32) => i32 | string` and runs. Through `id`, the call through `k` uses the destination's
signature while the table entry keeps `inc`'s `(i32) => i32`, so no adapter is built on that
path. Found grading the function-element pin's witness w6 (`useK(id(h))`).

#### Ablation

| ingredient removed | outcome | needed? |
| --- | --- | --- |
| `id` (`const g = inc`) | runs | **yes** |
| the wider result (`(a: i32) => i32`) | runs | **yes** |
| the annotated let (a parameter `k: (a: i32) => i32 \| string` of a called function) | still traps | no |
| a binding of `inc` first (`const h = inc; id(h)`) | still traps | no |

Calling `g(4)` directly as well (beside the delivery) turns the trap into an emit error,
"cannot take the generic function `inc` as a value".

#### Grading list

- `useK(id(h))` with `const h = inc`, the w6 witness of the function-element pin, run with
  COV-CLOS-3's one-signature rule both on and off.
