### D1515 — an anonymous struct's struct-ref-LIST field had a code only when the list was written as a LITERAL; a call result or a bound list left the owner literal with no row

**closed 2026-09-03 by giving the field coder's ARENA rung the companion column a code-5 field
needs (`anonRefListElemRow`), so the element row is read off the checker's recorded element
type when there is no element NODE to read it off · was `emitProgram: object literal field
count does not match struct` on a `vl check`-clean program · clause 2 · found by the day-one
sampler (#2478), `--seed 1 --count 400`, pair at line 69 · position matrix 39/42 runs, 0
silent, `runs -> not-runs` 0**

Repro (runs, prints `1` then `3`):

    type Rec = { name: string, n: i32 }
    function rows(): Rec[] { return [{ name: "ada", n: 3 }] }
    function go() {
      const box = { it: rows() }
      print(box.it.length)
      print(box.it[0].n)
    }
    go()

#### Mechanism

`collectAnonShapes` mints an `#anon` row only if EVERY field value has a code.
[D1443](D1443.md) gave `anonFieldCodeSyn`'s `ArrayLit` arm a code-5 rung for a list of object
LITERALS — each element carries its own row by the time the field is coded, so the companion
`sFieldElemName` can name it. Every other producer of the same `Rec[]` has no element node to
read: a call result and a bound list both fell to `-1` in the syntax rung, and the ARENA rung
below it codes them 5 correctly and then refused them at `anonCodeIsSelfContained`, whose own
header says code 5 needs a companion this rung could not supply.

So the owner literal got no row at all, `structIndexOfObjCtx` answered -1, and the refusal was
a sentence about the literal's own field count — which is why the message names a shape
mismatch for a program with no mismatch in it. `repRowOfTyStruct` is this compiler's home for
turning a recorded element type into the row the emitter interns through, and supplying it is
what admits code 5 from that rung, exactly the bargain code 16 struck in [D1242](D1242.md) and
code 5 struck for the literal spelling in D1443.
