### D13982 — `x is null[]` parses as `x is null` indexed by `[]`

**closed 2026-10-26 · runs, prints `true` · `parseIsType` took a leading `null` as the one-token type whatever followed it; it now hands `null[]` to `parseTypeName` · fixture `tests/cases/unions/null-list-arm.vl` · was loud check reject, clause 2, `expected boolean, got _[]` (and a parse error inside an `if` condition), while `type N = null[]` with `x is N` and `x is (null[])` both ran · found closing [D13980](D13980.md) · present on master `5807f0fd7` · filed 2026-10-26 against master `5807f0fd7`**

Repro:

    function f(v: null[] | i32[]): boolean { v is null[] }
    const a: null[] = [null]
    print(f(a))
    // vl check: type error, expected boolean, got _[]

Want:

    true

#### Mechanism

`parseIsType` special-cases `null`, the one type that is a single keyword token, and returned
before `parseTypeName` could see the `[` after it. The expression parser then read `[]` as an
index into the boolean `v is null`.

#### Ablation

| ingredient changed | outcome | needed? |
| --- | --- | --- |
| `v is (null[])` | runs | **yes** (the bare `null` token first) |
| `v is N` with `type N = null[]` | runs | **yes** |
| `v is i32[]` | runs | **yes** |
| `v !is null[]` | the same refusal | no |

#### Grading list

`x is null` and `if x is null { … }` keep parsing as the null test; `v !is null[]`.
