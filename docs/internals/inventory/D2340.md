### D2340 — a `let` with no initializer whose type has no zero value cannot be shared with a closure

**loud emit reject · `is assigned after a closure captures it, so the closure shares it` ·
found building D2339 · filed 2026-09-24 against master `90c3ba566`**

Repro:

    type P = { x: i32 }
    function main() {
      let p: P
      const g = () => p.x
      p = { x: 7 }
      print(g())
    }
    main()
    // vl check: rc 0.  vl run: emit error (should print 7)

#### Mechanism

A binding a closure captures and that is assigned afterwards lives in a length-1 cell
(`captureBoxRewrite`, D2339), and the cell is built at the declaration, from the init. A `let`
with no init gets its annotated type's zero value (`cboxZeroInit`: the numeric types,
`boolean`, `string`). A struct, list, map, union or function type has none, so the rewrite
refuses rather than capture the binding by value, which would silently print a stale value.
On master the same program failed validation instead.
Likely lowerings: a `(T | null)` cell whose reads the definite-assignment facts license as
non-null, or building the cell at the first assignment when that dominates the capture. Both
are predictions.

#### Ablation

| ingredient removed | outcome | needed? |
| --- | --- | --- |
| the missing initializer (`let p: P = { x: 0 }`) | runs, prints 7 | **yes** |
| the struct type (`let p: i32`, `p.x` → `p`) | runs | **yes** |
| the write after the capture | runs, by value | **yes** |
