### D3881 — a hole lambda stored into a map of a function type is lowered at its `i32` default, and the call through the read traps

**loads then traps · found in review of #3463 (`rv3464/p63t/a7.vl`) · filed 2026-10-08 against master `a1c9be3c4`**

Repro:

    const tw = (y) => y + y
    const fs: ((y: string) => string)[] = []
    fs.push(tw)
    print(fs[0]("a"))
    const m: {[string]: (y: i32) => i32} = Map()
    m["k"] = tw
    const f = m["k"]
    if f != null { print(f(5)) }
    // vl check: rc 0.  vl run: prints aa, then a wasm trap

Want:

    aa
    10

#### Mechanism

Not located. A list element store (`fs[0] = tw`) and a `push` deliver the lambda at the element
type (D3867); a map store is lowered through the map's own write path, which that delivery does
not see, so the `i32` call through the map reaches `tw` at its `string` instance; with no other
pin the map's own contextual type pins it, and it runs.

#### Ablation

| ingredient removed | outcome | needed? |
| --- | --- | --- |
| the string push (only the map store) | runs, `10` | **yes** |
| the map (a second list and `gs[0] = tw`) | runs, `aa`, `10` | **yes** |
