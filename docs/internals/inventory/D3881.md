### D3881 — a hole lambda stored into a map of a function type is lowered at its `i32` default, and the call through the read traps

**closed 2026-10-09 by lane SC · runs · was loads then traps · found in review of #3463 (`rv3464/p63t/a7.vl`) · filed 2026-10-08 against master `a1c9be3c4` · pins: `tests/cases/closures/hole-lambda-stored-into-typed-map.vl`**

Repro:

    const tw = (y) => y + y
    const fs: ((y: string) => string)[] = []
    fs.push(tw)
    print(fs[0]("a"))
    const m: {[string]: (y: i32) => i32} = Map()
    m["k"] = tw
    const f = m["k"]
    if f != null { print(f(5)) }
    // vl check: rc 0.  vl run: prints aa, then a wasm trap

Want:

    aa
    10

#### Mechanism

A list element store (`fs[0] = tw`) and a `push` deliver the lambda at the element type (D3867).
A map store's left side reads as the map's nullable value type, which is no function type, so the
delivery skipped it, and `m.set` had no delivery at all. The `i32` call through the map reached
`tw` at its `string` instance. With no other pin, the map's own contextual type pinned it, and it
ran. Closed by delivering at the map's value type for `m[k] = v` and for `m.set(k, v)`.

#### Ablation

| --- | --- | --- |
| the string push (only the map store) | runs, `10` | **yes** |
| the map (a second list and `gs[0] = tw`) | runs, `aa`, `10` | **yes** |
