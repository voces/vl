### D3746 — an `__array_new_default__` BINDING handed to a hole callee that writes a non-`i32` element is built as the `i32` list

**closed 2026-10-06 by lane S3 — the filed repro RUNS and prints `1.5` · was check-clean invalid wasm, clause 1 · the binding half #3398's D2218 close leaves, by the review's ruling · filed 2026-10-06 against master `082c36f12` · fixture `tests/cases/inference/hole-callee-write-pins-binding-at-flush.vl`**

Repro:

    function take(a) {
      a.push(1.5)
      print(a[3])
    }
    const h = __array_new_default__(3)
    take(h)
    // vl check: rc 0.  vl run: invalid module inside `take`, `expected i32, found f64`

#### Mechanism

[D2218](D2218.md)'s close pins an open list from the callee's writes only when the list is
WRITTEN AT THE CALL (`take(__array_new_default__(3))` runs). A binding is left open on purpose:
its own later writes may still widen it (`take(h); h.push(2.5)`), and pinning it at the call
lost six programs that run on master (named set `ua-hole-pin-binding-open`). With no later
write, `flushUninferred` gives the intrinsic's row its `i32` default (D1470) while the
instance's body stores `f64`. A bare `const b = []` in the same place is refused instead
(the D1470 binding rule), so only the intrinsic's default is silent.

The fix has to run at the flush, not at the call: a binding the caller never pins should take
the element its callee's writes give it (or be refused naming them) instead of `i32`.

The close: `cnhPinBmElem` still declines to pin a binding at the call, and records the write
(`calleeWriteRow`, `calleeWriteGot`) when the row is open. At scope close the intrinsic's row takes
the first recorded write's element before the `i32` default (`arrDefPinHoleElem`, through a
chain of hole links), a literal union at its base primitive (`type D = 0 | 1 | 2` stores `i32`,
as master's default did), and an empty `[]` binding no write of its own pinned takes it instead of the
"cannot infer a type" refusal (`calleeWritePin` in `flushUninferred`): `const e = []; fill(e)`
now runs. The records follow the checker's speculative rollbacks (`monoRecheckEnd`,
`cstrTablesTruncate`) and a quiet re-check records none. A recorded element with no zero is refused by the existing
`checkArrayNewDefaultElems` (`string`, a record). A binding whose own later write pins a
different element than the callee wrote is still unchecked: [D3775](D3775.md).

#### Ablation

| ingredient changed | outcome | needed? |
| --- | --- | --- |
| the intrinsic written at the call, `take(__array_new_default__(3))` | runs, prints `1.5` | **yes** |
| a later caller write, `h.push(2.5)` after the call | runs, prints `1.5` | **yes** |
| `const h = []` instead | loud check reject (`cannot infer a type for 'h'`); runs after the close | **yes** |
| `take` writes `1` (an `i32`) | runs | **yes** |
| an element store (`a[0] = 1.25`) instead of the push | still invalid wasm | no |
