### D15259 — the elaboration leaves open a captured function's type that mono's substitution closes

**runs today and must keep running · found probing mono-pin survey group A · filed 2026-11-04 against master `55102709c` by lane column-G1**

Repro:

    function a<T>(x: T) {
      let k = (u) => { print(u + u) }
      const rd = () => { k(x) }
      rd()
    }
    a(1)
    a(1.5)
    a("s")
    // vl run: 2, 3, ss

#### Mechanism

In each instance of `a`, `elabWalkTy` reads `k`'s function type as `(_) => void`: the elaboration
leaves the hole that `k(x)` binds open. `monoPinnedTyOf`'s substitution closes it, to `(i32) =>
void` at `a(1)`. Mono's pins read the instance's record where it is closed and fall back to the
substitution where it is not, so this row is that fallback's reason. The elaboration closing
the captured lambda's hole at the instance retires the fallback.
