### D17004 — inside `is K[]` over a record-list arm stored apart from `K[]`, an element read at the record `K` is refused

**loud check reject · clause 2 · the record face of the 2026-11-18 ruling's in-arm view (DECISIONS, "`is K[]` tests a list's contents") · D16989 made `is K[]` answer by a `W[]` arm's records; reading a `W` record as a `K` needs a converting record view (the `rvEmitView` family), and a `K` write through it converts back · filed 2026-11-19 against master `de44e8985` by lane F1**

Repro:

    type W = { x: i32 | null }
    type K = { x: i32 }
    const a: W[] = [{ x: 1 }, { x: 2 }]
    const q: W[] | K[] = a
    if q is K[] { const k: K = q[0]; print(k.x) }
    // vl check: cannot assign {x: i32 | null} to 'k' of type K

Want:

    1

#### Mechanism

`listIsFitsAcrossRecs` keeps the declared union in the then arm and pushes no element-read fact,
because a `W` record is laid out apart from a `K`: its `x` is a box where `K`'s is an `i32`. A
read at `K` needs a view of the `W` record whose fields read at `K`'s, and a write through it to
convert back, which the emitter does not build for an `is` arm.
