### D15283 — a fresh record `let` pushed or assigned into a place built at a wider record is check-clean invalid wasm

**closed 2026-11-04 · runs, prints `6` · was check-clean invalid wasm, `vl check` rc 0 · clause 1 · found closing [D15238](D15238.md) and [D15237](D15237.md), their `let` spelling · filed 2026-11-04 against master `ee0b51d5` · closed by a `let` nothing reassigns holding its literal as a `const` does (`recCoalesceHeldLit` asks `cwLetUnwritten`, building the write scan's index first), so the push and assignment producers of D15237 and D15238 build it · fixtures `tests/cases/soundness/record-let-binding-held-wider-runs.vl` and `-reject.vl` · a reassigned `let` is [D15374](D15374.md)**

Repro:

    type J = { f: i32 | null }
    function mk() { { f: 4 } }
    const wideJ: J = mk()
    const xs = [mk()]
    let r = { f: 6 }
    xs.push(r)
    print(xs[1].f ?? 0)

Want:

    6

#### Mechanism

D15237 and D15238 build a fresh record binding where it is pushed or
assigned into a place built at `J`, but only a `const` (`recCoalesceHeldLit` takes `letKw ==
"const"`). A `let` stays built at its own `{f: i32}` and is handed to a place of `J`'s row.
