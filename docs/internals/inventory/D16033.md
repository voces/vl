### D16033 — `==` between a nullable record and a plain one is refused once any union holding the record is declared

**closed 2026-11-13 · runs, prints `true` · `emitNulStructEq` matches the nullable side's variant row against the bare side's · was loud emit reject · clause 2 · `emitProgram: struct equality over a non-struct operand` · found probing `===` operands for D15975 (lane E) · filed 2026-11-13 against master `0260e578`**

Repro:

    type A = { a: i32 }
    type B = { b: i32 }
    type U = A | B
    const x: A = { a: 1 }
    const n: A | null = x
    print(n == x)

Want:

    true

#### Mechanism

`emitNulStructEq` (compiler/wasmEmit.vl) looked for an eq row through `binEqNulVariantRow`,
which needs both sides nullable over one variant row, then through `structIndexOfExpr` of the
left operand. Declaring a union that holds `A`, even an unused one, makes `A` a variant record
with no struct-table row, so an `A | null` against a bare `A` found neither, and the refusal
fired. It is D57's trigger on the nullable path D57's close did not cover. The close takes the
nullable side's `nulVariantIdxOfExpr` and accepts it when the bare side's `eqConcreteVariantRow`
is the same row. Test cells: `tests/cases/operators/nullable-record-eq-variant-record.vl`.
