### D3548 — `__array_new__` refuses a fill that is a call through a function-typed PARAMETER, while the same value hoisted into a `const` builds

**loud emit reject · clause 2 · `emitProgram: __array_new__ fill names no element rep, and its destination names none either` · found by lane BI's `std:array.map` prototype (`builtin-methods-to-std.md` prerequisite 3) · filed 2026-10-03 against master `fae55dec2`**

Repro (`vl check` rc 0; `vl run` refuses at emit):

    function mk(xs: i32[], f: (i32) => i32): i32[] {
      const out = __array_new__(xs.length, f(xs[0]))
      out
    }
    print(mk([1, 2, 3], (v: i32) => v * 2)[2])

Want:

    2

#### Mechanism

The fill's rep is read off the fill EXPRESSION, and a call through a function-typed parameter
(a closure call) answers no element rep there; the destination's annotation is not consulted
as the fallback the sentence promises. Every other spelling of the same `i32` fill names its
rep, so the refusal is a classifier gap at this one producer, not a missing capability.

#### Ablation

| ingredient removed | outcome | needed? |
| --- | --- | --- |
| the call in the fill: `const v = f(xs[0])`, then `__array_new__(xs.length, v)` | runs, prints 2 | **yes** |
| the PARAMETER: `f` a top-level `const f = (v: i32) => v * 2` | runs, prints 2 | **yes** |
| the closure: a declared `function dbl(v: i32)` called in the fill | runs, prints 2 | **yes** |
| the destination's inference: `const out: i32[] = __array_new__(…)` | refuses, same sentence | no |
| the generics: a `map<T, U>(self: T[], f: (T) => U)` with the same fill | refuses, same sentence | no |

#### Grading list

The annotated-destination spelling `const out: i32[] = __array_new__(xs.length, f(xs[0]))`,
which must run as well; the generic `std:array.map` prototype `mapA` with its fill un-hoisted,
over `i32[]`, `f64[]`, a record list and a string list.
