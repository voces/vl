### D8060 — a fallible `as` over a hole call's result is not judged by the checker and is refused at emit

**loud emit reject · `vl check` rc 0 · clause 2 · the checker owed the refusal: binding the call's result as `const x: f64` first is a loud check reject, `as i32` propagates null, which the enclosing function cannot return · found closing [D7841](D7841.md) · present on master `370ba120c` · filed 2026-10-20 against master `370ba120c`**

Repro:

    function add(a, b) { return a + b }
    function p(g) {
      print(g(1.5, 2.5) as i32)
    }
    p(add)
    // vl check: rc 0.  vl run: emitProgram: bare null needs a struct-typed context

#### Mechanism

Not traced. The checker types the hole call's result loosely, so the `f64 → i32` narrowing
`as`, which may produce null, is not held to the void function it propagates into; the emitter
then has no place for the null. The direct spelling is refused by the checker.

#### Ablation

| spelling | outcome | needed? |
| --- | --- | --- |
| the witness | loud emit reject | — |
| `const x: f64 = g(1.5, 2.5)` then `print(x as i32)` | loud check reject, `as i32` propagates null | **yes**: the hole call's own result |
| `p` handed a lambda `(x: f64): f64 => x`, called `g(1.5)` | loud emit reject, same message | no: the handed function's typing |
| no `as` | runs | **yes** |

#### Grading list

The un-annotated `as?` and `as!` spellings, which should run.
