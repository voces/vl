#### Mechanism

Traced. `noteCastDemand` (check_demands.vl) parks a cast whose operand is a hole parameter so
`holeCastPinCheck` can judge it once the pin is known, but it took only an identifier operand.
A hole call's result is a derived `?ret.<hole>` type variable, so the cast was never parked and
the emitter met a null with nowhere to go. `noteHoleCallCastDemand` parks it under the base
hole, and the pin re-types the call at its own arguments (`holeCallResultAt`) before
`castPinAdjudicate` judges the cast.
