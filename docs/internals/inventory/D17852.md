#### Mechanism

`gaUnionUnwrap` (`check_relate_core.vl`) unwraps a non-record alias's one-member placeholder to
its member `m` and banks the application on `m` (`genAppCarry`) when `m > resIx`, reading index
order as "this fill minted it". A row the fill mints is a type other code can hold too: shared by
structure, every holder answers as the application. Under S2a the close is the application's
identity in the intern key of every row its fill mints (coordinator ruling), so the fill's member
never merges with a row written plainly. A twin row for the member was tried and refused: with
interning off it moves `soundness/recursive-nullable-alias-list.vl` (mono reads the member's
identity). Answering "which application wrote this" at the use site, not from the row, is S2c's,
with records.
