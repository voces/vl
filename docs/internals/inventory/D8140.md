### D8140 — a fresh call held by an un-annotated binding, beside a declared record of its fields, is invalid wasm when the binding is delivered into a wider record

**closed 2026-10-20 by lane records · runs, prints `15` · was check-clean invalid wasm · clause 1 · the adoption follows an un-annotated binding back to the call it holds (`recBindOrigin`, `check_rec_fresh.vl`) and builds the called function's literal at the destination · fixture `tests/cases/soundness/record-fresh-call-delivered-through-binding.vl` · found grading [D8020](D8020.md) · filed 2026-10-20 against master `f90d0709e`**

Repro:

    type Col = { r: i32, g: i32 }
    type J = { r: i32 | null, g: i32 }
    function mk() { { r: 15, g: 1 } }
    const s = mk()
    const m: J = s
    print(m.r ?? 0)
    // vl check: rc 0.  vl run on master: invalid module, "type mismatch: expected (ref null $type)"

Want:

    15

#### Mechanism

`mk`'s literal is built at `Col`'s row because `Col` spells its field set. Delivered directly,
`const m: J = mk()` re-seats the literal at `J` (`recFnBuiltAtDst`). Through `s` the adoption
saw an identifier, not a call, so nothing re-seated it, while the delivery was accepted as
fresh. The adoption now follows the binding to the call, through further un-annotated
bindings too.

#### Ablation

| change | outcome | needed? |
| --- | --- | --- |
| `const m: J = mk()` | prints `15` on master | **yes**, the binding |
| `s` handed to `f(m: J)` | invalid wasm on master, prints `15` now | no |
| `const c: Col = s` before the delivery | refuses: the record is shared at its own type | no, the designed refusal |
