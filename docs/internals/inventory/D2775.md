### D2775 — a join of an `f32` value with a bare float literal typed `f64`, where an operator's literal operand adopts the f32

**closed 2026-09-27 — the repro RUNS and prints `9` · was a loud check reject (`argument 1: expected f32, got f64`) · plumb PL-049 · 68 of the 118 f32 cells of the lane's join-form × position grid moved to runs, 0 runs lost and 0 values changed across its 472 cells · filed 2026-09-27 against master `f6db92e0d`**

Repro:

    function mul32(a: f32, b: f32): f32 { a * b }
    function f(raw: f32): f32 {
      const clamped = if raw > 0.0 { raw } else { 0.0 }
      mul32(clamped, clamped)
    }
    print(f(3.0))

#### Mechanism

`binOpType` lets a literal beside an f32 operand adopt f32 (`raw * 2.0` is f32), and an i64
`if` join already widens its i32 literal arm, but the `if`/`match` join itself went through
`joinTys`, which knows only types: `f32` beside the literal's `f64` is `f64`. Closed by
`joinF32LitTails`: when some tail of a value `if` or `match` is an f32 value and every other
tail adopts f32 as a literal does beside an operator (`isF32AdoptingLitExpr`: a float literal
that does not overflow f32, or an integer literal f32 holds exactly), the join is `f32` and its
`if`/`match` nodes are re-typed f32, so each literal lowers as `f32.const`. An enclosing join
that stays `f64` hands the inner nodes back their f64 type (`f32JoinRevert`), and a join in an
inferred function's return tail is left alone, so no program that runs today reads a literal
at a different precision. The inferred-return and list-literal joins are built and switched
off pending a ruling: [D2774](D2774.md).
