### D14430 — a list of a function set built in the body of a hole instance stays untagged, served by the element pin

**runs today and must keep running · a scope boundary, no wrong value: in a function with an un-annotated parameter the list is built as a closure list and the element pin types its calls; the generic half is lifted (the same body in `run<T>(v: T, n: i32)` is tagged) · deleted when the split plan keys a forwarded hole parameter per tuple for the arms, which takes out `ftInOpenFn` (check_fn_tag.vl) · found landing (γ) slice 1 · filed 2026-10-27 against master `1558e9ab0`**

Repro:

    function inc(a) { return a + 1 }
    function dbl(a) { return a * 2 }
    function run(v, n: i32) {
      const fs = [inc, dbl]
      print(fs[0](n) + fs[1](n))

#### Mechanism

(γ) slice 1 tags a set held in a list literal, so the list is the i32 list of the set's ids and
an element call dispatches on the id. `ftInOpenFn` left every list of a set whose holder sits in
a generic function, or in one with an un-annotated parameter, untagged, and the element pin
(`monoPinListElems`) produced its element signature.

The generic half is lifted: the same body in `run<T>(v: T, n: i32)` is tagged, and each call dispatches at
the instance's own tuple, since the mint records the facts per instance. The half that stays is a
holder in a function with an un-annotated parameter. Lifting it as well turned the forwarded-list
files (`forwarded-hole-to-two-list-params.vl` and its siblings) into invalid wasm, because the
split plan (D6210) copies the hole parameters a call hands on per tuple, and the arms of a set
called in that body do not see the copies. The witness must keep printing its Want.
