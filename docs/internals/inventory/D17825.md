### D17825 — emit readers resolve a binding with `identDeclOf` inside an instance frame, which names the template's binding rather than the instance's

**runs today and must keep running · suspected clause 1, unproven · refactor target · filed 2026-11-28 against branch `cov-clos-d17808` (c6678bcc8) by COV-CLOS-3 (found closing [D17808](D17808.md))**

Repro:

    function add(a, b) { return a + b }
    function app(g, s) { return g(s, s) }
    function p5(h) {
      const run = (x) => app(h, x)

    }
    p5(add)
    // vl run: prints 3 then 4 since D17808. Before, the print arm read `u` through identDeclOf,

#### Mechanism

`identDeclOf(read)` answers the declaration the checker resolved. In an instance frame mono has
cloned the body and redirected calls, so the instance's own binding can differ from the
template's (`identLetOfRead(read, fnIx)` resolves it in the frame). D17808 moved three readers:
`openCallWidth` (wasmEmit), and `openReadTy` and `letOpenCallWidth`'s copy chain (emit_classify).

Raw call counts on c6678bcc8, not audited: `identDeclOf(` emit_classify 40, wasmEmit 22, ir_build
47; `identLetOfRead(` emit_classify 9, wasmEmit 1, ir_build 1. A count is not a bug count. Each
reader class needs a witness, an instance frame where the two answers differ and the outcome
changes, before this is scheduled.

Refactor target: one "resolve a binding in the current frame" reader that every emit reader takes.
