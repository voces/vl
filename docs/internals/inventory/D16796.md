### D16796 — a hole parameter handed a nullable record wider than its `??` default builds an invalid module at a field read

**closed 2026-11-16 by lane L2-S2 · runs, prints `5` · was check-clean invalid wasm, clause 1 · `tests/cases/structs/hole-param-coalesce-wider-record-default.vl` · found grading the S3.4a floor-removal experiment (two map value shapes through one hole) · filed 2026-11-16 against master `d59e4401`**

Repro:

    const r: {x: i32, y: i32} | null = {x: 5, y: 6}
    t(r)
    function t(q) { print((q ?? {x: 0}).x) }
    // vl check: rc 0.  vl run: invalid module inside `t`, "type mismatch: expected (ref $type), found (ref $type)"

Want:

    5

#### Mechanism

The concrete `??` marks an operand that may be a record that already exists (`njFixSet`), so
`joinTys` keeps it as a member of the join. A hole's `??` is answered at the pin by
`coalJoinAtPin`, which did not, so the join narrowed `{x, y}` to the default's `{x}` and the
emitter stored the argument's `{x, y}` ref in a `{x}` slot. The `HD_COAL` hole now carries the two
flags the check computed, and `coalJoinAtPin` sets them before it joins.
