**closed 2026-10-17 — the witness prints `W 6 false` · was loads then traps, `vl check` rc 0, clause 1 · a write whose right-hand side is a written binding records it as a copy, so the source's writes are adapted at the copy's call types · the `written-fn-binding-copy-fixed-union` matrix 0 → 57 of 64 runs · found closing D4892 · filed 2026-10-16 against master `83752e744` · pins: `tests/cases/closures/written-let-of-generics-written-from-another-let.vl`, `scripts/capability-probes/matrix/written-fn-binding-copy-fixed-union.matrix.vl`**

    function w<B>(a: i32 | string, b: B) { print("W"); print(a); print(b) }

      let k = s

#### Mechanism

The same gap as D5160, reached through a write. `k2 = k` is one of `k2`'s owner-row writes, but
its right-hand side is the binding `k`, whose value is `w`'s instance taking a boxed
`i32 | string`. D4892's adapter rewrites `k`'s own write `k = w` at `k`'s call types, and `k`
has no call of its own here. Why `k2`'s own recheck does not adapt `k2 = k` is not yet
ablated. The write's right-hand side is a binding rather than a function, `k2` stores the
unadapted instance, and the indirect call at `(i32, boolean)` traps.

#### Closed by L1 (2026-10-17)

The same close as D5160: the write `k2 = k` is recorded as a copy (`fsbNoteCopy`), and the
call through `k2` re-asks and adapts `k`'s write `k = w` (`fsbOwnerReaches`). The ablation
table is D5160's; removing `fsbNoteCopy` at a write alone brings back this row's trap.
