### D15213 — a holder of a bundle record copied into another binding has no member fact at the call it holds

**closed 2026-11-04 by the D15213 PR (lane bundle-value) — the repro now RUNS and prints the Want below: the copy holds the holder's record, and the two are recorded together or not at all (`elabHolderCopiesHold`). Was: loud emit reject · clause 2 · `emitProgram: a function returning a parameter called at two signatures is called where its result is not used at one of them` · found planning [D15146](D15146.md) (lane destringify) · filed 2026-11-03 against master `f49fe0052`**

Repro:

    function lap(f) {
      f(2.5)
      f(3)
      return f
    }
    const v = lap((a) => a + 1)
    const w = v
    print(w(4))

Want:

    5

#### Mechanism

`v` holds `lap`'s parameter's record ([D15144](D15144.md)), and its only use is to initialise `w`.
At the `lap` call, `emitBundleResultPick` (wasmEmit.vl) has neither a member fact for the call's
value nor a holder keeping the record whole (`elabCallKeepsRecordAt`), and refuses; `v` called
directly is a holder that does.

#### Ablation

| ingredient removed | outcome | needed? |
| --- | --- | --- |
| `w` (`print(v(4))`) | runs, prints `5` | **yes** |
| `w` annotated `(x: f64) => f64` | still refuses | no |
| `w` a `let` assigned `v` (`w = v`) | still refuses | no |
| `lap(...)` returned through `mk(k: i32)` | still refuses | no |
