### D2667 — an arm cell initialized by a list-element read does not agree with an annotated map cell of the same type

**loud emit reject · `emitProgram: bare null needs a struct-typed context` · found in the #3191 review · filed 2026-09-26 against master `525837973`**

Repro:

    type S = { a: i32 }
    function mkR(v: i32): {[string]: S} {
      const m: {[string]: S} = Map()
      m["a"] = { a: v }
      return m
    }
    let gd: {[string]: S} = mkR(0)
    let gc = [mkR(1)][0]
    function fc(c: boolean) {
      if c { gc = mkR(8) } else { gd = mkR(7) }
    }
    const r = fc(false)
    const v = r["a"]
    if v != null { print(v.a) }
    // vl check: rc 0.  vl run: emit error at `v != null`

#### Mechanism

The arm join (`fnAssignCellEq`) compares two cells by struct slot, element and declared
spelling, and since D2662 also by map shape. `gd` is annotated and `gc` is not. The shape that
`letMapShapeOf` derives for `gc`'s list-element initializer, a composition read of a list
literal of maps, differs from the annotation's shape. So the join declines, `fc`'s result
takes the mono map, and the read of `r["a"]` is not a struct. A value `if` in place of the
annotation runs on #3191.

#### Ablation

| ingredient removed | outcome | needed? |
| --- | --- | --- |
| `gd`'s annotation | runs, prints `7` | **yes** |
| the index initializer (`let gc = mkR(1)`) | runs, prints `7` | **yes** |
| `gc` as an arm cell (`gc` read alone) | runs | **yes** |
