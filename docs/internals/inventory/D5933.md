### D5933 — a written `let` hole lambda whose initializer does not call its function parameter and whose write does, called with a generic, is refused at emit

**closed 2026-10-17 by lane L3 · runs, prints `-4` · was a loud emit reject · clause 2 · the checker now takes the generic's instance from the calls the written lambdas make on the binding's hole (`fsbGenFnHolePins`, `check_calls.vl`), which the mono pin reads · pin: `tests/cases/functions/written-let-hole-lambda-generic-typed-by-write.vl` · found closing [D5841](D5841.md) · filed 2026-10-17 against master `3e78365df`**

Repro:

    function neg(a) { return 0 - a }
    let lap = (g, x) => x + 1
    lap = (g, x) => g(x)
    print(lap(neg, 4))
    // vl check: rc 0.  vl run: emitProgram: cannot take the generic function `neg` as a value

Want:

    -4

#### Mechanism

From the ablation only. The generic argument's instance is decided by the calls of `g` in the
binding's instanced initializer; this initializer never calls `g`, so `neg` is delivered as a
value with no instance, though the lambda written later calls it at `i32`.
