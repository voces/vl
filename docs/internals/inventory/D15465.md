### D15465 — a result chosen between two parameters one type parameter annotates, handed two different generics and called at two types, is refused

**open · loud emit reject, `vl check` rc 0, `emitProgram: monomorphize: parameter `a` of `pick` is called at two function types that no parameter per type separates`, clause 2, with the split plan on and off · the residue of D15461, which serves one generic handed to both parameters · filed 2026-11-05 against master `ebf27b75`**

Repro:

    function id<T>(x: T): T { x }
    function dup<T>(x: T): T {
      print("dup")
      x

#### Mechanism

D15461 hands each parameter back, so the result is one argument's value of the set the parameters
share. With one generic handed to both, that set is the generic's own. With two, it is their
union (D15409's joined set), and the bare-result case of `ftOwnTyParamJoins` still requires one
named function. Widening it to two joinable generics, with the joined set read for a result too,
was measured on 2026-11-05 and does not settle: `internal: the tag decision after the elaboration
did not settle`. The result's set and the parameters' set are decided in turn and never agree.
