### D15465 — a result chosen between two parameters one type parameter annotates, handed two different generics and called at two types, is refused

**open · loud emit reject, `vl check` rc 0, `emitProgram: monomorphize: parameter `a` of `pick` is called at two function types that no parameter per type separates`, clause 2, with the split plan on and off · the residue of D15461, which serves one generic handed to both parameters · filed 2026-11-05 against master `ebf27b75`**

Repro:

    function id<T>(x: T): T { x }
    function dup<T>(x: T): T {
      print("dup")
      x
    }

      if k { return a }
      c
    }

Want:

    x

#### Mechanism

D15461 hands each parameter back, so the result is one argument's value of the set the parameters
share. With one generic handed to both, that set is the generic's own. With two, it is their
union (D15409's joined set), and the bare-result case of `ftOwnTyParamJoins` still requires one
named function. Widening it is two problems, measured on 2026-11-05 by widening it to two
joinable generics (`fnTagJoinsWith`) and reading the joined set for a result too:

1. **The decision does not settle** (`internal: the tag decision after the elaboration did not
   settle`). The rounds alternate with period 2: tagged `{}` → `{id}, {dup}, {id, dup}` →
   `{id}` → … Only `{id}` is tried. The union joins it through `ftLateParamOk`, which returns
   `true` for a set an earlier round tagged (`ftWas`) before it pushes the joined set into
   `ftSubNeed`. So every second round tags `{id}` alone. Pushing the join ahead of that early
   return settles both orders.
2. **Once settled, the result is typed at the first argument's set.** `pick(id, dup, false)`
   then prints `3` at one type, where master prints `dup 3`. That makes it a clause-1 wrong
   answer. The check binds `F` from `id`, so `h` holds `{id}`, and a call through a one-member
   set is a direct call to `id`. The call's result, and every binding of it, needs the joined
   set the elaboration binds `F` to. That set does not exist until the elaboration mints it.
   The second problem is the open one; the first fix is only safe beside it.
