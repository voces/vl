### D1420 — a `??` merge moves the callee's return row but not its RELAY's: a function that returns another function's result is left at the pre-merge row

**check-clean invalid wasm · clause 1 · OPEN · `type mismatch: expected i32, found (ref $type)` ·
ZERO corpus cells · identical on the pre-[D1100](#d1100) seed, so it is residue and not a
regression · found 2026-09-03 by ablating D1100's fifth position, which turned out not to be
about the container at all**

Repro (`vl check` rc 0; deleting `mid` and calling `src` directly prints `5` then `7`):

    function src(p: {r: i32}): {r: i32} | null {
      p
    }
    function mid(q: {r: i32}): {r: i32} | null {
      src(q)
    }
    function rd() {
      const v = mid({ r: 5 }) ?? { r: 0 }
      print(v.r)
      const g1 = src({ r: 7 }) ?? { r: "s" }
      print(g1.r)
    }
    rd()

#### Mechanism

`src({r: 7}) ?? {r: "s"}` widens `src`'s `{r: i32}` return row to a merged `{r: i32|string}`,
and `anonLeafMarkRetMoved` redirects every reader of `src`'s return (`fnRetStructIndexSid`,
`retStructIndex`, the two functype arms) onto it. **`mid` returns `src(q)` — so `mid`'s own
return row is `src`'s, moved — and nothing marks `mid`.** Its declared `{r: i32} | null` still
names the narrow row, so `mid({r: 5}) ?? {r: 0}` builds its default there while the call hands
back the merged one.

`anonLeafCalleeRead` already walks a callee's returned LITERALS and marks the functions whose
rows must follow (`anonLeafJoinCallee`'s `fns` list, D871). What it does not walk is a return
whose value is another function's CALL — the relay hop — and the mark is what the four
return-row resolvers key on.

#### Ablation

| ingredient removed | outcome | needed? |
| --- | --- | --- |
| the MERGE (`?? { r: "s" }` on `src`) | runs, prints `5` | **yes** |
| the RELAY (call `src` directly) | runs, prints `5 7` | **yes** |
| the relay's OWN `??` (`print(mid(…) != null)`) | still fails | no |
| the relay returning a LITERAL (`{ r: q.r }`) instead of `src(q)` | runs, prints `5 7` | **yes** |
| the relay spelled as a LAMBDA into a HOF (`apply((q) => src(q))`) | still fails | no |

The last two rows are what put this row here rather than in [D1100](#d1100): the lambda and
the higher-order call are SCENERY — the same failure reproduces with a named relay called
directly, no function value anywhere — while the relay's body calling `src` is load-bearing.
