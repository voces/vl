#### Mechanism

`assignable` admits `{ x: i32 }` where `{ x: i32 | string }` is declared, and the emitter
adopts the destination's rep for the source, so both handles are one struct. A store of a
`string` through the wider handle then sits in the field the caller reads as `i32`. The close
applies the owner's reads-only rule for covariant lists (DECISIONS.md A9) field by field: at
every delivery the checker computes the widened slots (`.x`, `.inner.x`, `.xs[]`, and the slots of
a union member the value may be narrowed to), drops the ones a fresh literal owns, and follows
the destination through the list rule's occurrence index — bindings, parameters, relays,
closures, stores, loop variables, `map`/`filter` callbacks, returns (every call, method-spelled
ones included), function-typed parameters (every argument their callers pass), `??`, `if`
arms; a discarded expression statement ends a path. A JOIN is a delivery too: a list
literal's element, an `if` value's arm, a `??` operand or a `return` of a function whose result
type is inferred, narrower than the joined type, is checked as delivered into it. Every delivery
is decided after all bodies are checked, so the order of declarations does not matter. A write
to a widened slot of a value the source's own slot type does not accept (or a type variable,
unless parametricity proves it is one of the slot's own values) refuses the delivery, naming
the write and the imprecise hop it came through (`p.x = 5` into an `i32` source runs); a handle
reaching a form the index does not model refuses too, since a record has no converting copy to
fall back on (DECISIONS.md "Record depth covariance"). The residue is [D2100](D2100.md), [D2101](D2101.md) and [D2102](D2102.md) (a join of lists whose element changes storage, the container rule's to refuse). A list or map whose element changes storage is the container rule's throughout; one that keeps it (a list of records whose fields widen, [D2161](D2161.md)'s `C[]` into `(C | null)[]`) is shared, and this rule refuses its unsafe writes.
