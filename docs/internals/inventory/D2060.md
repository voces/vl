### D2060 — a MUTABLE record field is accepted covariantly in depth, so a callee writes a wider member into a narrower caller's struct

**loads then traps · clause 1 (soundness) · filed 2026-09-22 against master `31ea77721`, found by the getters/effects persona review (type-theory lens, probes `p2`/`p3`/`p6`/`p7`)**

Repro:

    function f(p: { x: i32 | string }) { p.x = "s" }
    const q = { x: 1 }
    f(q)
    print(q.x + 1)
    // vl check: rc 0.  vl run: wasm trap: cast failure

#### Mechanism

Not yet ablated past the ingredients below. The argument check admits `{ x: i32 }` where
`{ x: i32 | string }` is declared, which is depth subtyping, and it is sound only for a field
nothing writes. The callee then stores a `string` into the caller's `i32` field, and the
caller's own read of `q.x` casts what it finds. This is Java's covariant-array hole for
records. The list twin is already ruled: `readonly T[]` is covariant, `T[]` is invariant
(D1686/D1687), and the covariant-write analysis (D852, D1610) tracks lists only. Records have no
equivalent rule.

#### Ablation

| spelling | outcome |
| --- | --- |
| annotated parameter `p: { x: i32 \| string }` (the witness) | rc 0, then `cast failure` |
| bound `setx<T: { x: i32 \| string }>(t: T)` | rc 0, then `cast failure` |
| field `{ x: i32 \| null }`, written `null` | rc 0, then `cast failure` |
| field `{ sh: Circle \| Sq }` given `{ sh: Circle }`, written `{ s: 5 }` | rc 0, then emit floor `field access receiver is not a struct` (clause 2) |
| un-annotated `function setx(t) { t.x = "s" }` | loud check reject at the pin, correct |

#### Grading list

Every row of the ablation table. The sibling [D2036](D2036.md) (an `i32` field delivered
where an `f64` field is declared) is the width-and-conversion face of the same admission and
should be re-graded by whichever close lands first. A `{ readonly x }` bound (F5 in
property-access-design.md) should not be built until this is closed, since `readonly` gets its
meaning from being the covariant one of the pair.
