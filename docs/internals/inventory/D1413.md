### D1413 — `.pop()` on a LITERAL-UNION list has no `??` lowering: the fused spelling is check-clean invalid wasm, the unfused one refuses in words

**closed 2026-11-01 as `runs` · was check-clean invalid wasm at the fused spelling (clause 1) · the fused `xs.pop() ?? d` arm in `emitCoalesceGo` claimed any list whose element stores as `i32`, so a literal-union list's pop built a string default where the block holds the atom; it now declines when `coalesceNulAtomToStr` says the `??` widens the atom, and the niche lowering (`emitCoalesceNulAtomStr`) converts it · the unfused spelling already ran on master before this close · fixture `tests/cases/literal-unions/pop-coalesce-widens-to-string.vl` · found 2026-09-03 while verifying [D1281](D1281.md)'s close**

Repro (fused — `vl check` rc 0, the engine then refuses the module):

    const xs: ("a" | "b")[] = ["a"]
    print(xs.pop() ?? "empty")

Want:

    a

Unfused (the same program with the pop bound first; it was a loud emit reject when filed and runs on master):

    const xs: ("a" | "b")[] = ["a"]
    const v = xs.pop()
    print(v ?? "empty")

* **THE ELEMENT REP IS THE WHOLE INGREDIENT, AND ITS TWO NEIGHBOURS RUN.** `string[]` at the
  identical fused spelling prints `a`; `i32[]` with `?? -1` prints `1`. Only the literal-union
  element fails. Emptiness is scenery — `[]` and `["a"]` fail identically, so this is not the
  empty-list trap [D1281](D1281.md) closed on its way past, which that row fixed with
  `tyNulLitUnionInner`'s `-1` sentinel.

* **TWO FACES, TWO CLAUSES, ONE MISSING LOWERING.** Fusing `?? d` into the pop is what turns a
  loud refusal into invalid wasm: the fused path emits without asking, the unfused path asks
  and declines. That is the shape this repo has now measured seven times — an annotated or
  fused spelling and its plain twin landing in different clauses — and it means a fix must
  grade BOTH or it converts one into the other rather than closing either.

* **THE UNFUSED MESSAGE CONCEDES THE GAP IN WORDS.** ``not supported yet — narrow it first``
  is one of the phrasings `goal-scoreboard.py` counts as admitting a capability gap, so this
  is a clause-2 violation by the tree's own accounting, with a clause-1 sibling one spelling
  away. Its advice also does not help: the value is a literal-union atom, and narrowing it
  with `if v != null` is a different program from the one the author wrote.

* **NOT COVERED BY THE ROWS FILED BESIDE IT.** [D1410](D1410.md) is a computed INDEX
  (`xs.get(i + 1)`) and this witness has no index; [D1411](D1411.md) is object-literal row
  merging; [D1412](D1412.md) is the `is` complement at a hole. Checked each before filing.
