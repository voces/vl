### D9990 — a lambda whose map parameter is typed only by the function type it is delivered to has no map receiver

**loud emit reject · `vl check` rc 0 · `emitProgram: '.length' on a receiver the emitter cannot classify as a list, string, map or set` (an index read refuses as `index receiver is not an array or string`) · clause 2 · CAPABILITY: the same lambda with its parameter annotated runs, and a record or list parameter typed the same way runs · key-agnostic: `{[string]: i32}`, `{[i32]: i32}` and `{[i64]: i32}` refuse alike · found closing [D9920](D9920.md), which this row's i32-keyed spellings reached once the spelling gate was gone · present on master `0f0face1e` · filed 2026-10-22 against master `0f0face1e`**

Repro:

    const f: (k: {[string]: i32}) => i32 = (k) => k.length
    const m: {[string]: i32} = Map()
    print(f(m))
    // vl check: rc 0.  vl run: emitProgram: '.length' on a receiver the emitter cannot classify as a list, string, map or set

Want:

    0

#### Mechanism

Not yet located. The checker types `k` from the annotation on `f`, and the program is well
typed; the emitter's receiver classifier finds no map for a parameter whose type arrives only
by context, while a parameter annotated with the same map spelling, or a record or list
parameter typed by context, is classified. A `| null` parameter whose body narrows it first
(`if k == null { return 7 }`) runs, so the miss is on the un-narrowed parameter read.
