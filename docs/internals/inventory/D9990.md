**closed · runs, prints `0` · was loud emit reject, `vl check` rc 0, `emitProgram: '.length' on a receiver the emitter cannot classify as a list, string, map or set` (an index read refused as `index receiver is not an array or string`), clause 2 · CAPABILITY: the same lambda with its parameter annotated runs, and a record or list parameter typed the same way runs · key-agnostic: `{[string]: i32}`, `{[i32]: i32}` and `{[i64]: i32}` refused alike · found closing [D9920](D9920.md), which this row's i32-keyed spellings reached once the spelling gate was gone · present on master `0f0face1e` · filed 2026-10-22 against master `0f0face1e` · closed by pinning a context-typed map parameter at its own map spelling (`recordedParamPinName`, emit_rewrite.vl) · fixture `maps/lambda-map-param-typed-by-context.vl`, matrices `fn-value-lambda-map-param-by-context` (0 → 27 of 48) and `fn-value-lambda-map-param-by-context-open` (12 → 38 of 46, its 26 check-clean invalid wasm cells on master now running) · with [D2675](D2675.md) closed, [D10030](D10030.md) filed open**

Repro:

    const f: (k: {[string]: i32}) => i32 = (k) => k.length
    const m: {[string]: i32} = Map()
    print(f(m))
    // vl check: rc 0.  vl run: emitProgram: '.length' on a receiver the emitter cannot classify as a list, string, map or set

Want:

    0

#### Mechanism

The checker types `k` from the annotation on `f`, and the program is well typed. A parameter
whose type arrives only by context is pinned by `recordedParamPinName` (emit_rewrite.vl) from
its recorded type name, and for a map that name gave no map spelling, so the parameter's local
was not a map and every receiver classifier missed it. A parameter annotated with the same
spelling, or a record or list parameter typed by context, pinned correctly. The pin now renders
a map parameter's own type (`tyToEmitName`), and still pins nothing while the map holds an open
type variable. A generic over the map's value type, `sz<V>(k: {[string]: V})` called on the
parameter, was check-clean invalid wasm on master and runs with the same pin.

The nullable spelling `(k: {[i32]: i32} | null) => (k?.get(3) ?? 0) + 1` in the grading list
is a different mechanism, filed as [D10030](D10030.md): it refuses with no lambda at all.

#### Ablation

| ingredient removed | outcome | needed? |
| --- | --- | --- |
| the context (annotate the lambda: `(k: {[string]: i32}) => k.length`) | runs, `0` | **yes** |
| the map (`(k: P) => k.x` over a record, `(k: i32[]) => k.length`) | runs | **yes** |
| the binding (`run((k) => k.length)` into a function-typed parameter) | still refuses | no |
| the parameter name in the type (`({[string]: i32}) => i32`), or an alias `M` | still refuses | no |
| `.length` for `k.get("a")` or `k[3]` | refuses as `index receiver is not an array or string` | no |
| the string key, for `i32` or `i64` | still refuses | no |
