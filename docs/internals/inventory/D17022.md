### D17022 — struct `==` re-reads each operand from its root at every field compare, so a call operand runs once per field

**check-clean silently wrong · filed 2026-11-19 against master `85ce0724c`, found probing IR-REV's leads on #9149**

Repro:

    type P = { a: i32, b: i32, c: i32 }
    let n = 0
    function mk(): P {
      n = n + 1
      return { a: 1, b: 1, c: 1 }
    }
    const q: P = { a: 1, b: 1, c: 1 }
    print(mk() == q)
    print(n)
    // vl check rc 0; vl run prints true, then 3 — `mk` ran once per field.

Want:

    true
    1

#### Mechanism

`emitStructEq` (`compiler/wasmEmit.vl`) lowers to `emitStructEqRec`, which compares field by
field and, for each field, re-emits the operand from its root (`lRoot`/`rRoot`) and walks the
path to the field. That core is re-read based by contract, but its dispatch in `emitBinExpr`
(`binEqVariantRow`/`binEqStructRow`) never stages an operand that is not a re-readable place,
so a call operand runs once per leaf field the and-chain reaches. The nullable twin
`emitNulStructEq` shares the core and adds its two null tests, each one more evaluation. The
union `==` (D2823) and the cross-arm `is` (`ctSlot`) stage such an operand into a local first.

#### Ablation

| spelling | `n` printed | needed? |
| --- | --- | --- |
| the repro (3 fields, all equal) | 3 | — |
| one field | 1 | the field count is the multiplier |
| first field differs | 1 | short-circuit stops the re-reads |
| nested `{ a: {x, y}, b }` | 4 | one per leaf field |
| `const m = mk()` then `m == q` | 1 | **yes**: a call operand |
| both sides `P \| null` calls, both non-null | 7 for two calls | the nullable twin adds its null tests |

#### Grading list

The `!=` spelling; a call on the right; `P | null` on one side and on both; a variant-row
compare (`binEqVariantRow`); a generic body at a record instance (D16470's neighbourhood).
