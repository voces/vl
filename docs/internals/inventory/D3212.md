### D3212 — two returned joins of a type parameter with different literals return only the first join's type

**closed 2026-09-29 · was check-clean invalid wasm, clause 1, on master `94670f728` · found by the GU lane re-grading the rv3236 `k3` grid's `earlyZ` cells · fixture `tests/cases/generics/gradual-type-parameter-union.vl`**

Repro:

    function g<T>(a: T, c: boolean) {
      const z = if c { a } else { "s" }
      if !c { return z }
      const y = if c { a } else { 5 }
      return y
    }
    const u: string | null = "n"
    print(g(u, true))
    print(g(u, false))
    // master: invalid module inside `g`

Want:

    n
    s

#### Mechanism

The return set joins `T | string` with `T | i32`. `joinTys` collapses a pair when one side is
assignable to the other, and a type parameter member is assignable from anything, so the
second join was absorbed into the first and the instance returned a nullable string while
`y` built an `i32`. Two unions holding a declared parameter now join by their members
(`gradualUnionJoin`): one absorbs the other only when it holds every member, else they stay
apart as `T | string | i32`.

#### Ablation

| ingredient changed | outcome on master | needed? |
| --- | --- | --- |
| `return a` in place of the second join | prints `n s` | **yes** (a second join) |
| `function g(a: string | null, …)`, the direct spelling | prints `n s` | **yes** (the type parameter) |
