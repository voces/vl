### D5890 — a literal test before the `null` test does not take the literal out of a nullable mixed union

**closed 2026-10-17 by lane L3 · runs, prints `6` · was loud check reject · clause 2 · `pushLitEqFactAt` narrows a literal no other member admits whether or not `null` sits beside them, and the emitter's `narrowIsElse` rules the literal's scalar out of the box when the literal is the only member lowering to it (`litElseAtom`, `emit_classify.vl`), so the complement of `"a" \| i32 \| null` reads as `i32 \| null` · pins: `tests/cases/match/litunion-nullable-literal-before-null.vl`, `scripts/capability-probes/matrix/nullable-mixed-litunion-type-member-match.matrix.vl` · residue: [D5920](D5920.md) (closed), [D5921](D5921.md), [D5922](D5922.md) · found closing [D5714](D5714.md) · filed 2026-10-17 against master `c73299e5a`**

Repro:

    function f(k: "a" | i32 | null): i32 {
      match k { "a" => 1, null => 2, i32 => k + 5 }
    }
    print(f(1))
    // vl check: operator '+' is not defined for "a" | i32 and i32

Want:

    6

#### Mechanism

`pushLitEqFactAt` (`check_narrow_flow.vl`) narrows the else side of `k == "a"` only when every
member is a literal, or when the literal is a member no other member of a NON-nullable union
admits. Over `"a" | i32 | null` it records nothing, so after `null` is removed the receiver is
still `"a" | i32`. The rule stops at a nullable union because the emitter's `litElseNarrow`
handles only a two-member `TyUnion`, not a `TyNullable`: lifting the checker half alone makes
the hand-written chain below check-clean invalid wasm. The same chain is refused on master.
