#### Mechanism

D17756's close notes a binding delivered whole at a closed type (`ctnDeliveryNote`,
check_assignable.vl) and makes it the binding's slot fact (`elabSlotFacts`), but only for a map
destination: a kind rung. The coordinator's rule is the one F2 uses, a delivered fact taken only
where it is the single destination type across the binding's whole deliveries and typed reads.
Here `r` is delivered at `(b: boolean) => void` and called at `(i32)` through `fs[0]`, which conflict,
so no fact should be taken. The refused change took the fact for any kind wherever
`eplHolderTy(ix, -1)` did not answer another type; it answers -1 both where nothing closes the
binding and where two uses close it differently (two pins in its class), so it cannot tell a
conflict from none, and both cells lost. Removing the rung needs a reader of the class's pins
(none, one, or several), so that several means no fact whatever the holder kind.

Closed by that reader. `eplOneCall` already tells the three apart: -1 for no call, a record for
one signature, -4 for two and -3 for an open argument. `eplDeliveredAgrees` walks the delivered
type down to each function leaf, and takes the fact only where that leaf's class is uncalled or is
called once at the leaf's own parameters. Here `fs[0](3)` calls `r`'s class at `(i32)` against a
`(b: boolean)` delivery, so no fact is taken. A binding whose own type is nullable takes no
delivered fact: it is delivered only through a narrowing, at a type it does not hold whole
(D10402's `const mv = m["k"]`, handed on as `run(mv, …)`, reds without that exclusion).
