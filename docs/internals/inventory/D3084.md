### D3084 — a hole for-in loop variable captured by a closure is invalid wasm at an `i32 | string` pin

**check-clean invalid wasm · clause 1 · open · found by the #3269 review · the same on master `67ca68cf3` · filed 2026-09-28 against master `67ca68cf3`**

Repro:

    function f(x) {
      const l = [x]
      for e in l {
        const k = () => e
        print(k())
      }
    }
    const v: i32 | string = "s"
    f(v)
    // vl check: rc 0.  vl run: invalid module inside `f`, expected i32, found (ref $type)

Want:

    s

#### Mechanism

Not localised past the ablation. The loop variable binds the union box, while the closure's
env field for `e` is typed from the template's hole, the `i32` default. At the nullable pins
the same shape is a loud refusal (`print of a union value whose arms the tag dispatch cannot
classify`), and at `string | null` a trap ([D2926](D2926.md)).

#### Ablation

| ingredient changed | outcome | needed? |
| --- | --- | --- |
| `print(e)`, no closure | prints `s` | **yes** (the capture) |
| `const k = () => x` | runs | **yes** (the loop variable) |
| `function f<T>(x: T)` | runs | **yes** (the hole) |
