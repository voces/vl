### D3374 — `{ a: { b } }` is a labelled block as an if-expression's then arm and an object literal as its else arm

**loud check reject · pre-existing, found by the #3295 review · needs a ruling · filed 2026-09-30 against master `6e6a5301b`**

Repro:

    function h(c: boolean, b: i32) {
      const t = if c { a: { b } } else { 0 }
      const e = if c { 0 } else { a: { b } }
      print(t)
      print(e)
    }
    h(true, 5)
    h(false, 6)
    // vl check: print expects one scalar or string value, got i32 | {a: {b: i32}} (at `print(e)`)

#### Mechanism

The then arm is parsed by `parseBlock`, where `a: {` opens a labelled block whose value is `b`,
so `t` is `i32`. The else arm's braces go through the object-literal look-ahead, which reads the
same text as the object `{ a: { b } }`, so `e` is `i32 | {a: {b: i32}}`. The same spelling means
two things by arm position. Which reading both arms take is a language ruling; the
recommendation is a block, as a `match` arm's braces already are (D3276). Whichever it is, the
parse then has to agree in both positions.

#### Ablation

| ingredient removed | outcome | needed? |
| --- | --- | --- |
| the else-arm position (both arms spelled as the then arm) | `t` checks as `i32` | **yes** |
| the nested braces (`{ a: b }`) | parse error: `a: …` starts no statement | **yes** |
