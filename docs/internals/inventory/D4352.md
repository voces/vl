### D4352 — a member literal passed through a local alias of an un-annotated function parameter is delivered as a string where the instance's signature takes the atom

**closed 2026-10-13 — the witness prints `y` · a value call reads its literal-union parameters off the function type the instance pins a hole- or type-parameter-typed callee to · fixture `tests/cases/closures/alias-of-fn-param-litunion-arg.vl` · was check-clean invalid wasm · clause 1 · found by the `fn-value-litunion-result-as-string` matrix (`argument`, un-annotated face) · filed 2026-10-13 against master `8e5c20356`**

Repro:

    type K = "x" | "y"
    function t(k: K): string { k }
    function take(a) {
      const v = a
      print(v("y"))
    }
    take(t)
    // was: vl check rc 0, then the emitted module failed to validate inside `take`:
    // type mismatch: expected i32, found (ref $type)

Want:

    y

#### Mechanism

`emitCallRefUnder` asks `cloCallParamLitUnion` whether a value call's parameter is a literal
union, and that read only the callee node's recorded type. Inside the un-annotated `take`, `v`
records the hole's type variable, so the answer was "no" and `"y"` was emitted as a string ref
into the `$fnsig` slot the key had already made an i32. The direct `a("y")` already ran; the
alias, and the alias inside a `<F>(a: F)` generic, did not. The fix reads the parameters off
`cloCallParamFnTyOf`: the recorded type when it is a function type, else the hole pin
(`cloCallHoleFnTyOf`), else the instance's type-parameter pin through `const`/`let` aliases
(`valueReadPinTy`).
