### D4352 — a member literal passed through a local alias of an un-annotated function parameter is delivered as a string where the instance's signature takes the atom

**check-clean invalid wasm · clause 1 · pre-existing, the same on the #3653 head `ff59e9fdd` and on the main checkout's seed · found by the `fn-value-litunion-result-as-string` matrix (`argument`, un-annotated face) · filed 2026-10-13 against master `8e5c20356`**

Repro:

    type K = "x" | "y"
    function t(k: K): string { k }
    function take(a) {
      const v = a
      print(v("y"))
    }
    take(t)
    // vl check: rc 0.  vl run: the emitted module failed to validate inside `take`:
    // type mismatch: expected i32, found (ref $type)

Want:

    y

#### Mechanism

The instance of `take` pinned at `(k: K) => string` calls `v` at the atom signature, but the
argument `"y"` is emitted as a string ref: the call through the alias does not hand the
literal the callee's literal-union parameter type, which the same call through `a` itself does.
A `K`-typed argument needs no adoption, so it is unaffected. NEXT: find where a direct call of
a pinned function-valued parameter seeds its literal arguments at the parameter types, and
route a `const` alias of that parameter (the frame copy lane SC's flow table answers) through
the same seed.
