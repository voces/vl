### D16364 — a function declared before a module-level `[]` that later top-level code pins reads the list at no element type

**check-clean invalid wasm · `type mismatch: expected (ref null $5), found (ref $3); $5 is list of i32-represented elements` · clause 1 · with the function declared after the push it runs, and without the alias the compiler traps · found grading `inferred-empty-list-scalar-elem.matrix.vl` (cell `two_instances`, un-annotated) · filed 2026-11-14 against master `b45a06ef`**

Repro:

    function one() {
      const v = xs
      print(v[0] + 1.0)
    }
    const xs = []
    xs.push(1.5)
    one()
    // vl check: rc 0.  vl run: invalid module inside `one`

Want:

    2.5

#### Mechanism

Not yet traced. The body of `one` is checked before the top-level `xs.push(1.5)` pins the list's
element, so its reads of `xs` see the open `[]`. Without the alias, `print(xs[0] + 1.0)`, the
compiler traps at emit: `binNumWidth` asks `numPairOpTy`, and `sameNumeric` reads `tyAt(-1)`, an
operand type nothing recorded. A declaration-order dependence, beside D16301's population.

#### Ablation

| ingredient changed | outcome | needed? |
| --- | --- | --- |
| `one` declared after `xs.push(1.5)` | runs, `2.5` | **yes** (the order) |
| `xs.push(1)`, an `i32` | runs | **yes** (an element the default `i32` is not) |
| `ys.push("s")` beside it | invalid wasm | no |
| `print(xs[0] + 1.0)`, no alias | compiler trap, `out of bounds array access` | no (a worse face) |
| `print(xs[0])` | invalid wasm | no (any read) |
