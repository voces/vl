### D16364 — a function declared before a module-level `[]` that later top-level code pins reads the list at no element type

**closed 2026-11-15 — the witness runs and prints `2.5` · was: check-clean invalid wasm · `type mismatch: expected (ref null $5), found (ref $3); $5 is list of i32-represented elements` · clause 1 · with the function declared after the push it runs; without the alias it trapped the compiler and runs since the hoisted container is kept · found grading `inferred-empty-list-scalar-elem.matrix.vl` (cell `two_instances`, un-annotated) · filed 2026-11-14 against master `b45a06ef`**

Repro:

    function one() {
      const v = xs
      print(v[0] + 1.0)
    }
    const xs = []
    xs.push(1.5)
    one()
    // vl check: rc 0.  vl run: invalid module inside `one`

Want:

    2.5

#### Mechanism

Pass 1.5 declares every module binding first, and a `[]` initializer as an open list. Pass 2
checked `const xs = []` again and minted a second open list, which `xs.push(1.5)` pinned, while a
body declared above read the first. The binding keeps the hoisted container now when both are
still open (`letHoistedOpenCtn`). The alias closes too: `const v = xs` in that body copies a
module binding pass 2 has not declared yet (`globalBeforeDecl`). It neither takes the read-only
default nor waits at the body's scope close, so the top-level push still pins the shared row.
A binding in such a body that takes its type from the element itself is D16368.
