### D4893 — a written `let` copied from another, called at a literal union, runs the instance of a different literal union

**closed 2026-10-17 — now prints `B r B q` · was check-clean silently wrong · a marked binding called at a literal union is banked at its call's signature: the instance record annotates every member of the copy set at that signature, so a copy reaches the instance of its own atom set (`fn_split.vl`) · found while closing D3975 · filed 2026-10-15 against master `5be21bb0a` · pins: `tests/cases/closures/written-let-copied-at-string-called-at-literal-union.vl`, `tests/cases/closures/written-let-copied-called-at-two-literal-unions.vl`, `tests/cases/closures/written-let-copy-called-at-another-literal-union.vl`**

Repro:

    function gA<U>(u: U) {
      print("A")
      print(u)
    }
    function gB<V>(v: V) {
      print("B")
      print(v)
    }
    function gC<W>(w: W) {
      print("C")
      print(w)
    }
    type S = "p" | "q"
    type R = "p" | "r"
    const a: S = "q"
    const b: R = "r"
    let x1 = gA
    x1 = gB
    let y = gC
    y = x1
    gB(b)
    y(a)

Want:

    B
    r
    B
    q

#### Mechanism

`y = x1` copies `x1` into `y`, and `y(a)` calls it at `S`. The two literal unions are atoms of
different sets, and the copy reaches `gB`'s instance at `R` rather than at `S`, so `a`'s atom
prints as `r`. D3975's split declines a copied binding called at a literal union for this
reason (the fixtures `written-let-copied-at-string-called-at-literal-union` and
`written-let-copied-called-at-two-literal-unions` kept their refusal until this closed).
