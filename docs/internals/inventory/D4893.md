### D4893 — a written `let` copied from another, called at a literal union, runs the instance of a different literal union

**closed 2026-10-16 — now prints `B r B q` · was check-clean silently wrong (`B r B r`) · a generic instance spells a literal-union atom by its own declaration's member set, not by the hole's one program-wide pin · pins: `tests/cases/closures/written-let-copied-at-literal-union-beside-direct-call-at-another.vl`, `tests/cases/closures/written-let-copied-at-string-called-at-literal-union.vl`, `tests/cases/closures/written-let-copied-called-at-two-literal-unions.vl` · found while closing D3975 · filed 2026-10-15 against master `5be21bb0a`**

Repro:

    function gA<U>(u: U) {
      print("A")
      print(u)
    }
    function gB<V>(v: V) {
      print("B")
      print(v)
    }
    function gC<W>(w: W) {
      print("C")
      print(w)
    }
    type S = "p" | "q"
    type R = "p" | "r"
    const a: S = "q"
    const b: R = "r"
    let x1 = gA
    x1 = gB
    let y = gC
    y = x1
    gB(b)
    y(a)

Want:

    B
    r
    B
    q

#### Mechanism

`y(a)` reaches `gB`'s instance at `S` correctly; what was wrong is how that instance printed its
atom. An instance's body shares its leaf nodes with the generic, so `print(v)` asked the hole's
banked pin (`nodeTyPinIxOf`) for the member texts, and that pin is one program-wide answer: `R`,
from the direct call `gB(b)`. `litAtomWidenTexts` (`emit_value_sites.vl`) now asks a pinned
instance's own declaration for its member set first, so `gB` at `S` spells `q`. With that, the
split's decline of a copied binding called at a literal union (`fn_split.vl`) is lifted, and the
two former `error-` fixtures run.
