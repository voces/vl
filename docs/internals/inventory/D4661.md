### D4661 — an un-annotated lambda parameter in a generic body is not read as a list at a generic call that also takes a captured `T`

**loud emit reject · `vl check` rc 0 · clause 2 · found closing D4647 · filed 2026-10-14 against master `1c1740512`**

Repro:

    function pick<T>(self: T[], _d: T): T { self[0] }
    function h<T>(xs: T[]): T {
      const k = (ys) => pick(ys, xs[0])
      k(xs)
    }
    print(h([3, 1, 2]))
    // vl check: rc 0. vl run: emitProgram: monomorphize: expected an array argument for
    // `self` in a call to `pick`

Want:

    3

#### Mechanism

Not yet ablated past the table below. The un-annotated face of D4032: `ys` takes its type
from `k(xs)`, and at the inner call the monomorphizer reads `ys` as `i32` with an
unpinned hole, so `self` gets no array type. A second argument whose type rides `T` is
what sends the call down that path; with a one-argument callee the same lambda runs.
