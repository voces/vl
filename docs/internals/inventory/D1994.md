### D1994 — an EMPTY if-expression arm in an un-annotated binding initialiser passes check (`i32 | void`) and refuses at emit

**closed 2026-10-11, a duplicate of D4071 — now a loud check reject at the empty `else { }` (`this arm yields no value, but the `if` is the value of `n`: end the arm with a value, or make the `if` a statement`) · was a loud emit reject · residue of D1992, D1993's second spelling · filed 2026-09-22 against master `af07f4ae0`**

Repro:

    function f(c: boolean) {
      const n = if c { 1 } else { }
      n
    }
    f(true)
    print("done")
    // WAS: vl check rc 0.  vl run: 2:31: emitProgram: if-expression arm is empty, so it yields no value

#### Mechanism

Predicted to be D1993's mechanism — the un-annotated binding slot does not demand a value from
an if-join typed `i32 | void` — and filed apart because an EMPTY block, unlike a void call, has a
competing reading: the else-less `if c { 1 }` resolves its provisional `void` to `i32 | null` at
this very slot, so whether `else { }` should refuse or mean `null` is a ruling, not a fix.
Annotated, it already refuses: `const n: i32 = if c { 1 } else { }` → `cannot assign i32 | void
to 'n' of type i32`.
