### D3718 — a record nested inside an exported value kept its box, because the `-O` boundary rule followed fields (sunpa `V3`)

**closed — the witness prints `2 4`, and its `-O`/`-O3` module stores `P.a` inline; under `--stable-layout` it keeps the box · a cost row, no wrong value · lane LA, owner ruling 2026-10-05 (inline-records-design.md §6 Q2) · filed 2026-10-05 against master `f9fdede1c`**

Repro:

    type V = { x: f64, y: f64 }
    type P = { a: V, n: i32 }

    }

Want:

    2 4

#### Mechanism

The inline-record step (D3678, `scripts/vl-host/src/inline.rs`) refused any record a
boundary-crossing value could reach through fields, list elements and union boxes, so
`W | i32` crossing an export kept `P.a` boxed although JS cannot read a struct's fields.
sunpa's `animationReady` returns a record with a `V3` field, which kept every `V3` field in
the game boxed. Per the owner's ruling, only a type a boundary signature names now keeps
its layout and identity, and a value handed to an `any`/`eq`/`struct` place is still
refused while such a reference crosses. `vl build --stable-layout` restores the rule that
follows fields, for linked units.
