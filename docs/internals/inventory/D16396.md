### D16396 — `==` over two records whose field pairs widen in opposite directions is refused at check, though each pair compares bare

**loud check reject · clause 2 · bucket (e) · probe `scripts/capability-probes/eq-record-fields-widen-opposite-ways.vl` · found grading D16394's close · filed 2026-11-15 against master `33ef972d7`**

Repro:

    const a: {x: i32, y: i64} = {x: 1, y: 2}
    const b: {x: f64, y: i32} = {x: 1.0, y: 2}
    print(a == b)
    // vl check: cannot compare {x: i32, y: i64} with {x: f64, y: i32}

Want:

    true

#### Mechanism

The checker's `==` asks whether one whole record is assignable to the other. Here `x` widens from
left to right and `y` from right to left, so neither record is assignable to the other, though
`1 == 1.0` and `2 == 2` (an `i64` against an `i32`) each compare bare. Under structural `==`
(DECISIONS A15) the pair is comparable field by field; D16394's rewrite would lower it unchanged
once the checker asks the question per field.

#### Ablation

| spelling | outcome |
| --- | --- |
| the witness | loud check reject |
| `b: {x: f64, y: i64}` (one direction) | runs, prints `true` |
| `a.x == b.x && a.y == b.y` | runs, prints `true` |
| `{x: i64}` against `{x: f64}` | loud check reject, as bare `i64 == f64` is |
