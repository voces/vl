### D9596 — a call returning one of two generics, handed to an un-annotated parameter that calls it at two types, refuses

**loud emit reject · `vl check` rc 0 · `monomorphize: unsupported argument type` · clause 2 · found closing [D9540](D9540.md) · present on master `49a7d0b10` · filed 2026-10-22 against master `49a7d0b10`**

Repro:

    function id<T>(x: T): T { x }
    function same<T>(x: T): T {
      print("same")
      x
    }
    function deliver(n: i32) {
      if n > 1 { return id }
      return same
    }
    function take(a) {
      print(a(21))
      print(a("a"))
    }
    take(deliver(3))
    take(deliver(0))
    // vl run: emitProgram: monomorphize: unsupported argument type for `a` in a call to `take`

Want:

    21
    a
    same
    21
    same
    a

#### Mechanism

A hole parameter called at two types is split into one parameter per type (D5611), and a call
argument is handed to it only when every `return` of the callee names one generic
(`constRetFnName`, check_calls.vl; `fsConstRet`, fn_split.vl, D9540), because the split
parameters past the first take that generic by name. With two generics the call's result is
known only at run time, so no split is marked and the argument reaches `monoArgTyFail`.
