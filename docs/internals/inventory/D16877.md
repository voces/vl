### D16877 — a built-in member call on an un-annotated parameter from inside a closure has no per-instance lowering

**closed 2026-11-16 by lane L2 · runs, prints `8` · `tests/cases/generics/member-call-through-param-closure.vl` · was loud emit reject · `emitProgram: callee is not a function name` · `vl check` rc 0 · clause 2 · filed 2026-11-16 against master `b88be2644` (L2, sizing the alias-receiver family)**

Repro:

    const m4 = Map()
    m4.set("a", 7)
    function take(a) {
      const g = () => {
        const h = a.get("a")
        if h != null { print(h + 1) }
      }
      g()
    }
    take(m4)
    // vl check: rc 0.  vl run: the refusal above, at `a.get`

Want:

    8

#### Mechanism

The per-instance pick of a member call on an un-annotated parameter (D2517) is made on the
generic's own body, and it does not walk into a lambda's body. Inside a closure, `a.get` reaches
the emitter as a call whose callee no instance resolved. `.length` (a field read) and `.has`
already run. This is the closure half of [D2520](D2520.md); the alias half closed with the
alias-receiver change. A string built-in such as `.slice` is refused at check inside a closure
and outside it alike, which is [D16882](D16882.md), not this row.

#### Close (2026-11-16, L2 closure receiver)

Three places stopped a closure's member call on a parameter from being picked per instance:
- `monoPinBinOps` treated a lambda as a leaf;
- the rewrite (`drwRecvIsTyParam`) judged the receiver against the lambda being walked, so it
  fixed the call once for every instance;
- the checker (`ufcsSitePinnable`) required the call to sit in the owner's own body.

Now `monoCloneLambdaSubst` runs `monoPinBinOps` over each per-instance lambda clone's body, under
the instance's parameters less the lambda's own. The rewrite judges the receiver against the
function whose parameter it holds (`aliasRootParamOwner`), and the checker accepts the site.
Graded in both orders of instances, since the first version printed `fn` for a string instance
built first.
