### D3222 — an if-expression or `match` arm that always exits joined `void` into the value's type

**closed 2026-09-29 (the `if` and `match` joins skip an arm block that always exits, `checkIfTail` / `matchArmExits` in `compiler/typecheck.vl`; the emitter ends each such arm with a `never` value, `exitArmsEndNever` in `compiler/emit_rewrite.vl`, so every rep's arm lowering meets it) · was a loud check reject of a legal program, clause 2 · filed against master `94670f728` · fixtures `tests/cases/loops/break-value-exiting-arm.vl`**

Repro:

    function r(n: i32): i32 {
      const y = if n == 4 { return 99 } else { n }
      y + 1
    }
    print(r(4))
    print(r(5))
    // was: check reject, operator '+' is not defined for void | i32 and i32
    // now: prints 99 then 6

Want:

    99
    6

#### Mechanism

`checkIfTail` returned `joinTys(thenTy, elseTy)` for an `if` with an `else`, and an arm block
ending in `return`, `break` or `continue` has the tail type `void`, so the join became
`void | i32`; the three `match` joins did the same per arm. The joins now leave such an arm
block out and note it, and the emitter's first pass appends `__trap__()` to each noted arm:
the exit runs as the arm's prelude and the dead `never` value is the tail every rep's arm
lowering already accepts (D1972). `ifThenValueIx` reads the else arm when the then arm's tail
is that `never` value, so a record join classifies by the arm that has a value. An exiting
`else if` link keeps the old join, and stays a check reject.

| --- | --- | --- |
