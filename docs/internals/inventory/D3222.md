### D3222 — an if-expression arm that always exits joined `void` into the `if`'s type

**closed 2026-09-29 (the arm join skips an arm that always exits, `checkIfTail` in `compiler/typecheck.vl`; the emitter lowers such an arm as its statements then `unreachable`, `emitExitingArm` in `compiler/wasmEmit.vl`) · was a loud check reject of a legal program, clause 2 · filed against master `94670f728` · fixtures `tests/cases/loops/break-value-exiting-arm.vl`**

Repro:

    function r(n: i32): i32 {
      const y = if n == 4 { return 99 } else { n }
      y + 1
    }
    print(r(4))
    print(r(5))
    // was: check reject, operator '+' is not defined for void | i32 and i32
    // now: prints 99 then 6

Want:

    99
    6

#### Mechanism

`checkIfTail` returned `joinTys(thenTy, elseTy)` for an `if` with an `else`, and an arm whose
block ends in `return`, `break` or `continue` has the tail type `void`, so the join became
`void | i32`. The same function already skipped an exiting arm when it recorded `ifValTyAt`;
the returned type did not. With the type fixed the emitter met an arm that ends in a
statement and refused it (`ifArmNoValueFail`); an exiting arm now lowers as its statements
followed by `unreachable`, which meets any blocktype.

#### Ablation

| ingredient removed | outcome | needed? |
| --- | --- | --- |
| the `return` (arm is `{ 99 }`) | runs | **yes** |
| `return` replaced by `break` inside a loop | same refusal | no, any exit |
