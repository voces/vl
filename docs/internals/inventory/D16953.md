### D16953 — [CLOSED 2026-11-17] a generic list of a pinned union, stored into a pinned record's field, builds invalid wasm: the list literal finds no rep for its instance type

**closed 2026-11-17 · was check-clean invalid wasm · clause 1 · found ablating [D16947](D16947.md) · filed 2026-11-17 against master `a1902979a` (the same on `586cc6b4c`, before [D2681](D2681.md)) · fixed by rebuilding the rep tree when a union row is registered after a build (`rtSync`) · fixture `tests/cases/generics/pinned-union-list-into-pinned-record.vl` · matrix `pinned-union-list-into-pinned-record`**

Repro:

    type IM = {[i32]: i32}
    function h<V>(x: IM) {
      const xs: (V | IM)[] = [x]
      const b: { v: (V | IM)[] } = { v: xs }
      return 0
    }
    const m: IM = Map()
    print(h<string>(m))
    // vl check: rc 0.  vl run: invalid module, type mismatch inside `h`

Want:

    0

#### Mechanism

The local `xs` is declared at the list of union boxes `(string | IM)[]` is, but its literal was built
as a list of bare maps: `repOfTy` of the literal's instance type answered no rep, so `listBuildOfTy`
declined and the literal fell back to its own shape's build. The type and its element union were the
same as in the runnable program without the record line, and the union had its row. The rep tree's
node for the list was built before the pin registered that row, and `rtSync` rebuilt the tree only on
an arena or user-type write, so the node kept answering none; the record's processing is what asked
for it early. The tree now rebuilds when the union rows have grown since it was built.
