### D16846 — two maker calls at two pins, each handed to a parameter that calls it at a different type, are refused at emit

**closed 2026-11-16 by lane INIT — the witness prints `5` `2.75` · was a loud emit reject, clause 2 (`vl check` rc 0) · each maker call whose binding hands its value on, so that no call banked its result, is built at the closed type its binding's slot holds: the elaboration twins the call's maker instance there and notes it as the call's result (`elabSlotMakerTwins`), and lifts the maker's cover block once each read it named is covered (`elabMakerCoverLift`) · fixture `tests/cases/functions/maker-calls-handed-on-at-two-signatures.vl` · the clause-1 face with annotated destinations is [D16850](D16850.md); a call the check types directly beside one handed on is [D16852](D16852.md) · filed 2026-11-16 against master `6cd6d0210`**

Repro:

    function adder(n) { return (a) => a + n }
    function take(a) { print(a(3)) }
    function half(a) { print(a(0.5)) }
    const x = adder(2)
    take(x)
    const z = adder(2.25)
    half(z)
    // was: vl check rc 0, then vl run: emit error, `a function value is called at two signatures, and the closure it holds was built for one: this call passes a wider number than its `i32` parameter`

Want:

    5
    2.75

#### Mechanism

Not traced. Each binding holds its own maker instance's closure (`adder` at `i32`, at `f64`),
and each is called at one signature, but through `half`'s parameter the closure is read as built
for the `i32` parameter `take` calls the lambda at: the lambda's parameter is fixed across the
maker's instances, not per instance, once the closures reach parameters.
