### D16846 — two maker calls at two pins, each handed to a parameter that calls it at a different type, are refused at emit

**open · loud emit reject · clause 2 (`vl check` rc 0) · the hand-on face of [D16845](D16845.md)'s two-pin spelling, which runs where the bindings are called directly · filed 2026-11-16 against master `6cd6d0210`**

Repro:

    function adder(n) { return (a) => a + n }
    function take(a) { print(a(3)) }
    function half(a) { print(a(0.5)) }
    const x = adder(2)
    take(x)
    const z = adder(2.25)
    half(z)
    // vl check: rc 0.  vl run: emit error, `a function value is called at two signatures, and the closure it holds was built for one: this call passes a wider number than its `i32` parameter`

Want:

    5
    2.75

#### Mechanism

Not traced. Each binding holds its own maker instance's closure (`adder` at `i32`, at `f64`),
and each is called at one signature, but through `half`'s parameter the closure is read as built
for the `i32` parameter `take` calls the lambda at: the lambda's parameter is fixed across the
maker's instances, not per instance, once the closures reach parameters.

#### Ablation

| spelling | outcome | needed? |
| --- | --- | --- |
| `print(x(3))`, `print(z(0.5))` in place of `take`, `half` | runs, `5` `2.75` | **yes**: handed to parameters |
| `half` alone | runs, `2.75` | **yes**: two calls |
| `take` calling `a(3.5)` | runs, `5.5` `2.75` | **yes**: two parameter types |
| a parameterless maker `mk()` | runs, `5` `2.5` | **yes**: the maker's hole |
| `(a: f64) => a + n` in the maker | runs, `5` `2.75` | **yes**: the lambda's hole |
| `take(a: (a: i32) => i32)` | the same message | no |
| `half` first, then `take` | the same message | no |
