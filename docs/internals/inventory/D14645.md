### D14645 — a list of un-annotated functions written after its initialiser is refused at check when the results differ

**closed 2026-10-29 · runs, prints `abab` then `2` · was refused at check (`cannot write 'lenOf' to an element of 'fs'`) while the unwritten spelling ran ([D14435](D14435.md)) · fixed: `elabFnListLetTy` (check_elab_cap.vl) joins the functions an un-annotated list binding's scope pushes into it with its literal's set, the literal adopts the joined list, and `holeSlotJudge` lifts the result comparison for that binding unless the widened set stayed untagged (the recheck's veto); an index write, a write through an alias or parameter, a list a call returns, a record's list field and a map are still judged ([D14646](D14646.md)) · pins: `tests/cases/closures/hole-fn-pushed-results-differ.vl` · filed 2026-10-29 against master `8b9d1e22`**

Repro:

    function twice(s) { return s + s }
    function lenOf(s) { return s.length }
    const fs = [twice]
    fs.push(lenOf)
    for g in fs { print(g("ab")) }
    // abab, 2

#### Mechanism

`holeSlotJudge` (check_relate_core.vl) still judges an element with writes after its
initialiser (`push`, `fs[i] = g`) against one common result, and so it does a list a call
returns (`const fs = mk()`) and a function-valued field of a list's records (`rs[].f`). With the judge skipped, the
set's members are not joined over the write, and the emitter refuses to take `twice` as a
value at the initialiser.
