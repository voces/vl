### D3021 — a record field cannot be named `type`: the keyword is refused in every field position

**closed · was parse error: `expected an identifier but found \`type\`` (declaration, access) and `expected a field name but found \`type\`` (literal) · plumb PL-067 (a) · `type` is a keyword only where a declaration can start, so the parser now reads it as a field name in a record or inline object type, a key-value literal field, `.`/`?.` access and a match payload clause (`atFieldName`) · the shorthand `{ type }` is refused with its own sentence · fixtures `tests/cases/parser/field-named-type.vl`, `tests/cases/parser/field-named-type-shorthand-error.vl` · filed and closed 2026-09-28 against master `ad64c62c1`**

Repro:

    type Global = { name: string, type: i32 }
    const g: Global = { name: "x", type: 3 }
    print(g.type)
    // vl check: rc 0.  vl run: prints 3 (before the close: three parse errors)

Want:

    3

#### Mechanism

`type` lexes as the hard keyword `TYPE`, and each field-name site took only `IDENT`. None of
those sites is ambiguous: a declaration is `type Name …`, so `type` followed by `:` (a field
declaration or a key-value literal field) or preceded by `.`/`?.` cannot start one. The one
place that had to look ahead is a `{` at statement position, which `looksLikeObject` decides:
`{ type: …` is now an object literal there, as `{ name: …` already was. The shorthand `{ type }`
would read a binding named `type`, which cannot be declared, so it is refused rather than read.

#### Grading list

Ran with the field named `type`: a declared record and its literal, an un-annotated literal, an
inline object parameter type, `?.type` on a nullable record, `r.type = …` and `r.type += …`, a
statement-position literal as a function's value, multi-line declaration and literal, a list of
such records in a `for`, a block-scoped `type` declaration beside the field, a match payload
`Sym{type: t}`, and `vl fmt` round-tripping each. Two neighbours refused with `ty` as well, so
they are not this row: a union of two records with the same field names and different field
types (`union cannot be discriminated`) and a generic `Box<T>` literal argument (`monomorphize:
unsupported argument type`).
