### D5171 — a copy of a written `let` of a generic called both at `string` and at a string literal union is refused

**closed 2026-10-17 — the witness prints `B r B q` · was loud emit reject, `vl check` rc 0, clause 2 · the refusal of a copy called at two argument types now asks for the instance record on the copy's declaration, and the split closes the set over the binding it copies · found while re-grading D4244 · filed 2026-10-17 against master `8eed466cb` · pins: `tests/cases/closures/written-let-copy-called-at-string-and-literal-union.vl`, `scripts/capability-probes/matrix/written-fn-binding-copy-two-calls.matrix.vl`**

Repro:

    function gA<U>(u: U) { print("A"); print(u) }
    function gB<V>(v: V) { print("B"); print(v) }
    type S = "p" | "q"
    const a: S = "q"
    let x = gA
    x = gB
    let y = x
    y("r")
    y(a)
    // vl check: rc 0.  vl run: the function binding `y`, a copy of a reassigned binding, is called at more than one argument type

Want:

    B
    r
    B
    q

#### Mechanism

D4244 runs when the `string` call goes through `x` and the union call through the copy `y`,
and `x("r")` with `x(a)` runs with no copy. Here the COPY takes both calls. A binding written
itself is refused through `monoBindSigFail`, which asks `fn_split` for the instance record;
the copy's refusal in `monoMakeInstanceLater` did not ask, so no slots were planned. It asks
now, on the copy's declaration. `fsPlan` already closes the set over copies in both
directions, so the binding it copies is split with it.
