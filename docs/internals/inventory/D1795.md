#### Mechanism

**The filed reading pointed at `monoCloPinNames`, and the probe put it one function away.**
Four accumulating `emitFail` probes on scratch seeds. The lifted-slot dump reads
`FN fe=2 use par=0 sig=c>i ps=[ p:38==>i>i]` beside `FN fe=3 k par=4 sig=i>d` — one `use`,
whose parameter is pinned to the TEMPLATE's `$fnsig`, called from the f64 instance that builds
its closure over `k`'s clone. `use` is instantiated at BOTH pins and the keys are identical:
`INST use key=[2#=>i>i,] pins=[ =>i>i/k1/[i>i]/]` twice, so the second call is a registry hit.

The pin name comes from `monoArgTyName`'s function-value arm, whose `Ident` rung asked
`fnIndexOf` — the FLAT, first-occurrence-wins map. A per-pin clone shares its template's name,
so that answers `i>i` in every instance. It is the rung [D1781](D1781.md) and
[D1782](D1782.md) replaced at their own sites, one delivery further on: the argument's name
resolves through the calling frame (`fnIndexOfInScope`), with the flat map kept as the
fall-back for a module-scope function no chain declares.

**Two readings were tried first and both are refuted by measurement.** `use` is not a template
by `monoLamNodeIsTemplateCore` — it captures nothing and names no type parameter — and a fifth
rung that made it one still minted no clone: `monoBindCols` walks the parameter's ANNOTATION
node, so an inference-face instance binds NOTHING (`UAP b=[]`). Binding the hole from the
parameter's recorded type fixes that (`b=[,?o.0=f64]`) and still does not close the row, because
the helper's own parameter carries a DIFFERENT hole that no instance binding names
(`UAP p=7 rty=65 b=[,?o.0=f64] rs=[]`). The pin, not the clone, is the deciding fact.
