#### Mechanism

`J` and `N` carry the same field names, and every `J` value fits `N`, so `crossTagFitRows`
listed `J`'s row as one `b`'s box might hold under its own tag (D4056). `pushNarrowIs` then
pushed no narrowing, and `b.r` was read as a field of the un-narrowed union, whose checked
type at the read is `N`: no shared-field plan, and the plain struct read's floor. But a `J`
value never sits in `N | string`. They store `r` differently, the checker refuses every
delivery of one but a fresh record, and a fresh record is built at `N`'s row. Spelled
`b.r ?? 0` directly, the refusal was instead
`` `??` over this nullable value is not supported yet ``.
