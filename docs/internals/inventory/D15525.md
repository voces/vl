### D15525 — an alias of a capturing lambda, read inside a closure, is rewritten to a name the closure did not capture

**runs today and must keep running · a REFUTATION PIN for option B′ of the `monoFlow*` rewrite (the elaboration's answer admitted where the walkers decline, refused 2026-11-06) · filed 2026-11-06 against master `6c59497a`**

Repro:

    function mkK(x: string, k: string) {
      const c = (y) => y + k
      const d = c
      const f = () => d(x)
      print(f())
    }
    mkK("t", "!")

Want:

    t!

#### Mechanism

Under B′, `d` (a `const` alias of `c`) is renamed to `c` inside `f`. `f`'s captures were computed for `d`, so the emitter finds no `c` in the enclosing frame and refuses: `captured variable not found in enclosing frame`. The walkers' in-scope test (`monoFlowInScope`) declines this. A local function namesake reached through a labelled block's `break` is the same scope fact; there the rename resolves to the top-level namesake (`functions/nested-hole-fn-namesakes.vl`, invalid wasm).
