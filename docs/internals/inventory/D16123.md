### D16123 — the elaboration banks no destination for a list literal argument, so mono reads the pushed literal's type off its receiver

**runs today and must keep running · step-5 residue: mono types a literal the elaboration should have handed it closed · found closing [D15943](D15943.md) · filed 2026-11-14 against master `171795b68`**

Repro:

    function half(a) { return a / 2.0 }
    const m2 = Map()
    m2.set("a", half)
    const xs: (({ [string]: (a: f64) => f64 })[])[] = []

Want:

#### Mechanism

The pushed literal `[m2]` is delivered at `xs`'s element type, but neither the check
(`nodeCtxTyIxOf`) nor the elaboration (`elabNodeCtxAt`) records that destination on it. The
elaboration computes the holder's element type for a pushed read (`elabReadStampsAt`), but only to
collect function types. So `monoCloseMapListLits` (`emit_mono`) types the open literal from the
receiver's checked type, a pure read. Close this by having the elaboration bank a literal
argument's destination, as the check does for a bare argument. `monoCloseMapListLits` and
`monoCloseListLitAt` are then deleted.
