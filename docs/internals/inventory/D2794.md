### D2794 — [CLOSED 2026-10-25] a record value joined with a wider record where no leaf of the join is audited is handed over unconverted

**closed as `runs` 2026-10-25, when a `??` join is typed once and the emitter's merged rows are gone · was check-clean invalid wasm · the three faces below, identical on master `781f68091` · filed 2026-09-27 from the #3209 review's hunt set, the uncovered remainder of [D2765](D2765.md)**

#### Mechanism

The same converting-copy gap as D2765 and D2100, at three places D2765's audit does not refuse:

* a `??` with a record-value left and a literal right. The `??` family keeps its own merged
  rows (the `anonLeaf…` machinery), and a refusal keyed on the two operand types refused
  dozens of running coalesces, so this face has no refusal until that family says which
  row the literal is built at;
* a join passed straight to an ANNOTATED parameter (`use(if … { a } else { { f: "s" } })`
  with `use(r: { f: i32 | string })`). The `if` is built at its then-arm's row and never sees
  the parameter's;
* a reassignment (`let r = { f: 2.5 }; if … { r = a }` with `a: { f: i32 }`), which is an
  assignment and not a join at all.

#### Ablation

| ingredient removed | outcome | needed? |
| --- | --- | --- |
| the annotation on `a` (an adopting local) | runs | **yes** |
| a `??` chain with a second record value (`a ?? b ?? { f: "s" }`) | a loud emit reject (D2765) | — the chain is audited |
| a record value nested in a literal arm's field (`{ h: a }`) | a loud emit reject (D2765) | — audited |

#### Grading list

The annotated-parameter and reassignment faces above, and D2100's and D2160's witnesses, which
share the converting copy that would close all three.

#### Close

The `??` face runs: the join is typed `{f: i32} | {f: string}` and stored in its box. The
annotated-parameter and reassignment faces are now check rejects under record covariance A
(an existing record is never widened), which the design owes.
