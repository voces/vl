### D17011 — a generic helper reading a map of un-annotated functions with different results is refused at emit with an internal error

**loud emit reject · `emitProgram: internal: a function slot pinned at one signature has no one …` · clause 2 · open · `vl check` rc 0 · the same read without the helper runs · found tracing [D14433](D14433.md) · filed 2026-11-19 against master `0d005e72c`**

Repro:

    function inc0(x) { return x + 1 }
    function half(x) { return x / 2.0 }
    function pick<V>(m: {[string]: V}, k: string): V | null { return m.get(k) }
    const m = Map()
    m["a"] = inc0
    m["b"] = half
    const h = pick(m, "b") ?? inc0
    print(h(3))
    // vl check: rc 0.  vl run: emitProgram: internal: a function slot pinned at one signature has no one closed type the elaboration delivers it at

Want:

    1.5

#### Mechanism

Not traced. The set {inc0, half} returns `i32` and `f64` at one `i32` call, so the read without
the helper stores it tagged. Through the generic helper the map's slot is pinned at one signature
and the elaboration delivers it at no closed type. The message is an internal invariant, not a
capability refusal. A neighbour of D14433, where the same helper over a set whose results follow
its parameter is refused at its argument instead.

#### Ablation

| spelling | outcome |
| --- | --- |
| the witness | internal emit error |
| without the helper, `m.get("b") ?? inc0` | runs, `1.5` |
| no `??`, `const h = pick(m, "b"); if h != null { print(h(3)) }` | same internal error |
| one result type, `half(x) { return x / 2 }` | runs, `1` |
