Repro:

    function inc0(a) { return a + 1 }
    function wa(h: (a: i32) => i32) { return h(3) }
    print(wa(inc0))
    print(inc0(3.5))
    // was: vl check: argument 1: expected (i32) => i32, got (f64) => f64

#### Mechanism

Each use of an un-annotated function takes its own instance, and a delivery is judged at its
target by `genericFnAssignable`. Two deferrals then re-asked that delivery under a pin that a
later direct call gave the function's holes, so whichever use came first decided the answer:

* an argument was parked for a pin ([D1821](D1821.md), `argPinPark`), and `inc0(3.5)` pinned
  `inc0`'s hole to `f64` and re-asked the parked `(i32) => i32` delivery. A declared generic
  (`<T>`) was already exempt (`tyIsForeignGenericSig`, `argIsOwnGenericFnValue`); the open
  signature of an un-annotated top-level function is now exempt too (`tyIsHoleGenericSig`);
* a module-level annotated binding recorded a deferred `let` row (`noteLetCstr`) whenever the
  value carried the function's holes, and the later call re-asked it with `f64` bindings.
  [D5972](D5972.md) skipped the row for a bare function name only; it is now skipped whenever
  every hole in the value rides a top-level function's own signature, so a record field
  (`{ f: inc0 }`), a list element (`[inc0]`) and a call's result are covered.
