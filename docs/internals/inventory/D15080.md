### D15080 — a generic `T` default of `??` over a nullable scalar joins at the scalar's rep, not the instance's union

**closed · now runs, prints `7` · was check-clean silently wrong, clause 1 · filed 2026-11-02 against master `ebd304ac` · closed 2026-11-03 against master `3261f0bb8`: a type-parameter default beside a closed left joins apart (`coalParamDefault`), so the template's `??` is the open `boolean | T` each instance builds · fixture `generics/coalesce-closed-left-type-param-default.vl`**

Repro:

    function pick<T>(x: boolean | null, d: T) { x ?? d }
    print(pick(null, 7))
    // vl check: rc 0.  vl run: printed `true` before the close

Want:

    7

#### Mechanism

A generic body's `x ?? d` over a nullable scalar (`boolean | null`, `i32 | null`,
`string | null`) is lowered at the scalar's own rep, though the instance's result is the union
`boolean | T` at the pin. At `T = i32` the default's `7` is read back as the boolean arm and
prints `true`. At any `T` whose rep differs from the scalar's (a `string`, or a `boolean`
default over `i32 | null`), the same lowering is check-clean invalid wasm (`type mismatch:
expected i32, found (ref $string)`). The non-generic twin, with `d: i32`, prints `7`.
