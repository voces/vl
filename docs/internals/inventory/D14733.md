### D14733 — a call in a list literal handed to a generic over the list keeps its record at its own row while another call of the same function delivers it as a declared record

**closed · now runs, prints `3` · was check-clean invalid wasm, clause 1 · the list face of [D14530](D14530.md), through a generic rather than an index · filed 2026-10-31 against master `ef8c85e1` · closed 2026-11-01 against master `efc86b3b`: a list literal whose elements are all built at one wider record is that record's list (`recListLitBuiltTyOf`, check_bind_adopt.vl), a generic list parameter only indexed or measured for the rep takes it (`recListParamTakesRep`, check_fit_rules.vl), mono pins the `T[]` instance there (`monoPinAnnotatedParam`) and the call's result slot is its rep row's (`callRetRepTy`, `callBuiltTy`) · fixture `soundness/record-call-in-list-handed-to-generic-list-runs.vl` · the result returned, relayed, compared or stored, and the list bound or returned in the callee, are [D14812](D14812.md)**

Repro:

    type Circle = { r: i32 | null }
    function sink(_x: Circle) { }
    function first<T>(xs: T[]): T { xs[0] }
    function mkcall() { { r: null } }
    sink(mkcall())
    const y = first([mkcall()])
    print(y.r ?? 3)

Want:

    3

#### Mechanism

`sink(mkcall())` asks for `mkcall`'s record at `Circle`. The record solve counts the call in the
list literal as stored at its own row: `recReadInPlace` follows an element only out of a literal
that is indexed in place ([D14531](D14531.md)), and a list handed to `first<T>(xs: T[])` is a
generic's argument, which no sole-pin rule names. The two builds disagree, so `mkcall` is built at
its own row and `sink` receives it as `Circle`. Invalid on line 5. `reverse([mkcall()])[0]` from
`std:array` is the same shape.
