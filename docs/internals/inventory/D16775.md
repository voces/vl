### D16775 — a maker's hole lambda pushed or stored into a list or map handed in as a parameter keeps its own result at a function type returning `f64`

**closed 2026-11-16 · runs, prints `0.5` · was loads then traps, `vl check` rc 0, `wasm trap: indirect call type mismatch` · clause 1 · fixed in emit_elab.vl: a holder the call search reaches that is a function's parameter is also each call's argument, whose binding's slot it reads too (`elabHolderReads`) · the map-parameter face runs too · pin: `tests/cases/functions/maker-lambda-held-by-field-param-generic-values.vl` · found by the maker/map/relay hunt · filed 2026-11-16 against master `6fb5ac348`**

Repro:

    function deliver() { return (a) => a + 1 }
    function put(xs: ((a: i32) => f64)[]) { xs.push(deliver()) }
    const xs: ((a: i32) => f64)[] = []
    put(xs)
    print(xs[0](3) / 8.0)
    // vl check: rc 0.  vl run: wasm trap, indirect call type mismatch

Want:

    0.5

#### Mechanism

The lambda's result is decided by the calls the lambda reaches ([D16711](D16711.md), `elabLamDeliveredRet` in emit_elab.vl), found by the call search `elabSlotClimb` / `elabReadOn`. The push hop reads the receiver's element reads in the parameter's own scope; the holder's reads are the caller's, through the argument handed to `put`, which the search does not climb back to.

#### Ablation

| ingredient changed | outcome | needed? |
| --- | --- | --- |
| the push at the top level, onto `xs` itself | runs, `0.5` | **yes**: the parameter |
| `m["k"] = deliver()` into a map parameter | the same trap | no: any store into a parameter's holder |

#### Grading list

`function put(m: { [string]: (a: i32) => f64 }) { m["k"] = deliver() }` called on a top-level map, read with `m["k"]`.
