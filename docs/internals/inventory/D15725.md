### D15725 — a record literal binding delivered at a record whose field is a union of records, then read at its own type through that field, is refused by the emitter

**closed 2026-11-12, runs and prints `7` · was a loud emit reject, clause 2, `vl check` rc 0, `emitProgram: field access receiver is not a struct`, master too · a field read at its own record type out of a union of records the receiver was built into is the member with its field names (`boxedArmOfMember`, emit_classify.vl): its struct row is the member's, its read casts out of the box, and it is no box to a delivery (`exprUnion`) · graded by the three un-annotated `held_*` cells of `scripts/capability-probes/matrix/kept-maker-delivery-record-union-member.matrix.vl` · fixture `tests/cases/structs/held-literal-read-through-record-union-field-runs.vl` · found writing that template · filed 2026-11-12**

Repro:

    type Cir = { f: i32 }
    type Sq = { s: i32 }
    type J = { j: Cir | Sq }
    const o = { j: { f: 7 } }
    const d: J = o
    print(o.j.f)

Want:

    7

#### Mechanism

The literal binding `o` holds only a literal, so it is built at the `J` it is delivered to, and
its `j` is stored as the union box. The read `o.j.f` is typed at `o`'s own type, where `j` is the
record `{ f: i32 }`, so the emitter reads `f` straight off the box and finds no struct row for the
receiver. With `J = { j: { f: i32 } | null }` the same program runs (the read unwraps the niche).
