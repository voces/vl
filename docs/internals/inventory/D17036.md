### D17036 — `r.k ?? d` over a `K | null` field writes its operand twice, so an effectful receiver runs again when the field is present

**check-clean silently wrong · clause 1, `vl check` accepts the program · `f().k ?? "a"` calls `f` twice when `k` holds a member · found by lane F2 checking IR-REV's question on the `litUnion` re-read · filed 2026-11-20 against master `afb9ab3eb`**

Repro:

    type R = { k: "a" | "b" | null }
    let calls = 0
    function f(): R {
      calls = calls + 1
      return { k: "b" }
    }
    const v = f().k ?? "a"
    print(v)
    print(calls)
    // vl check: rc 0.  vl run: prints b, then 2

Want:

    b
    1

#### Mechanism

`emitCoalesceNiche`'s `litUnion` arm stashes only a `Call` or `if` operand (`lhsReEval` false) in
`coalesceCallBoolSlot`; any other operand is written once for the `-1` test and again in the present
arm. A field read whose receiver is a call, or a method call, is not effect-free, so the receiver
runs a second time whenever the field is present.

#### Ablation

| spelling | outcome | needed? |
| --- | --- | --- |
| the witness | prints `b`, `2` | — |
| the field null (`{ k: null }`) | prints `a`, `1` | **yes** (the present arm re-reads) |
| a method receiver, `o.m().k ?? "a"` | prints `b`, `2` | no (any effectful receiver) |
| an element with an effectful index, `xs[g()] ?? "a"` | prints `b`, `1` | **yes** (a field read) |
| the operand a call, `g() ?? "a"` | prints `b`, `1` | **yes** (a call is stashed) |
| a `??` nested in the default, `g(0) ?? (g(1) ?? "a")` | prints `b`, calls counted once each | no |

#### Grading list

The method spelling `o.m().k ?? "a"`; a receiver that is an `if` or a `??`; the other re-reading niche
arms of `emitCoalesceNiche` (the `boolean | null` select, the `string` arm), which re-evaluate the
same way; and the IR's `litUnion` arm, which must stash the receiver rather than match the re-read.
