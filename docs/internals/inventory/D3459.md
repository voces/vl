### D3459 — `?.` over a map read of a record refuses any field that is not `i32` or `boolean`

**closed 2026-11-13 · runs, prints `3.5` · the fused map-read `?.f ?? d` opens its `if` at the field's blocktype (`optLeafKindOf`), as the nullable-record arms do · was loud emit reject · clause 2 · pre-existing, the same on master `028dedb33` · found by the #3325 review (`b/ch14.vl`, a check reject on master and this refusal after lane RC3) · filed 2026-09-30 against master `028dedb33`**

Repro:

    type D = { v: f64 }
    const m: {[string]: D} = Map()
    m["a"] = { v: 7 }
    print((m["a"]?.v ?? 0.0) / 2)
    // vl check: rc 0.  vl run: emitProgram: `?.` over a map read supports only i32/boolean fields

Want:

    3.5

#### Mechanism

`emitCoalesceOptMapField` (compiler/wasmEmit.vl), the fused lowering of `m[k]?.f ?? d`, opened
its `if` at a fixed i32 blocktype and refused any field whose numeric kind was not 0. So an f64,
i64 or f32 field was refused, though the program is type-valid. The same read through a narrowed
local runs, and so does `?.` without `??`. The close takes the blocktype from the field through
`optLeafKindOf` / `fbIfForOptLeaf`, and widens the default through `emitOptLeafDefault`, as the
nullable-record arms beside it do. Kind 0 still opens an i32 `if`. Test cells:
`tests/cases/maps/optional-field-default-wide-scalars.vl`.

#### Ablation

| `const x = m["a"]?.v` (no `??`) | prints `7` | **yes** (the fused `??`) |
| `string`, `i32[]` or record field | runs | no (only a wide scalar was refused) |

#### Grading list

A `string`, `i64`, `f32`, record and list field through the same `?.`, one program each.
