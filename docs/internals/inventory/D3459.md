### D3459 — `?.` over a map read of a record refuses any field that is not `i32` or `boolean`

**loud emit reject · clause 2 · open · pre-existing, the same on master `028dedb33` · found by the #3325 review (`b/ch14.vl`, a check reject on master and this refusal after lane RC3) · filed 2026-09-30 against master `028dedb33`**

Repro:

    type D = { v: f64 }
    const m: {[string]: D} = Map()
    m["a"] = { v: 7 }
    print((m["a"]?.v ?? 0.0) / 2)
    // vl check: rc 0.  vl run: emitProgram: `?.` over a map read supports only i32/boolean fields

Want:

    3.5

#### Mechanism

The emitter lowers `?.` over a map read (`V | null`) by its own arm, and that arm builds the
optional result only for an `i32` or `boolean` field. Every other field kind is refused at
emit, although the program is type-valid and the same read through a narrowed local runs.

#### Ablation

| ingredient changed | outcome | needed? |
| --- | --- | --- |
| `D`'s field `i32`, `print(m["a"]?.v ?? 0)` | prints `7` | **yes** (the field kind) |
| `const r = m["a"]`, `if r != null { print(r.v / 2) }` | prints `3.5` | **yes** (the `?.` on the map read) |

#### Grading list

A `string`, `i64`, `f32`, record and list field through the same `?.`, one program each.
