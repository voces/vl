**closed 2026-10-25 · runs, prints `3`, `null` and `z` · fixed: a member storing the field as `string | null` boxes it under the null or string tag by a null test (`sharedFieldArmNulStr`, emit_obj_lit_fits.vl; `emitSharedFieldArm`, wasmEmit.vl), and a read typed as a nullable over a union registers that union's box (`registerSharedReadUnion`) · pins: `tests/cases/unions/shared-mixed-nullable-field-read.vl` · also closes the same read with `i32` beside `string | null`, and with `i32 | null` beside `f64`, both the same loud emit reject · was loud emit reject, clause 2 · `emitProgram: field access but no struct type declared` · pre-existing on master `247fb2679` · found closing [D13280](D13280.md) · filed 2026-10-25 against master `d63e667e7`**

Repro:

    type A = { k: i32 | null, x: i32 }
    type B = { k: string | null, y: string }
    function F(u: A | B) {
      print(u.k)
    }
    F({ k: 3, x: 1 })
    F({ k: null, y: "s" })
    F({ k: "z", y: "s" })
    // vl check: rc 0.  vl run: emitProgram: field access but no struct type declared

Want:

    3
    null
    z

#### Mechanism

From the code path, not ablated to a line. The read's type is `i32 | string | null`, and the
members store the field as two different reps: `A` as the `i32 | null` value box, `B` as a
nullable string reference. The shared-field plan (`sharedUnionFieldPlan`) has no conversion from
one member's box to the read's wider union, so the read falls through to the single-struct path.
