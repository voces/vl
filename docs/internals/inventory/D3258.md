### D3258 — an if-expression whose then arm is a `never` call classifies by that arm, so a list else is check-clean invalid wasm

**check-clean invalid wasm · 2 cells of the #3293 review grid `g3` · filed 2026-09-29 against master `313a071b4`**

Repro:

    function die(msg: string): never {
      print(msg)
      __trap__()
    }
    function h(n: i32): i32 {
      const y = if n == 99 { die("dead") } else { [n, n] }
      y.length + y[0]
    }
    print(h(4))
    // vl check: rc 0.  vl run: invalid module, type mismatch: expected i32, found (ref $type)

Want:

    6

#### Mechanism

The binding's rep is classified from the if-expression's then-arm value (`ifThenValueIx` in
`compiler/emit_classify.vl`), and a then arm whose tail is a `never` value has none to give, so
the binding is classified `i32` while the else arm delivers a list reference. With the `never`
arm in the else position the classifier reads the list arm and the program runs. A record else
reaches the same misclassification loudly (`field access receiver is not a struct`). The
loop-values follow-up to #3293 reads the else arm when the then arm's tail is `never`, which is
the fix's shape.

#### Ablation

| ingredient removed | outcome | needed? |
| --- | --- | --- |
| `never` arm first (swap the arms) | runs | **yes** |
| the list (else `"ab"`, read `y.length`) | runs | **yes** |
| the call (`__trap__()` directly in the then arm) | same invalid wasm | no |
| the missing annotation (`const y: i32[] = …`) | same invalid wasm | no |
| the list, for a record (`{ r: n }`, read `y.r`) | loud emit reject | no, a louder twin |
