### D15031 — a binding of a void generic written a generic returning a value, called with a record literal, is refused at emit

**closed · now a loud check reject, `cannot write 'retV' to 'k': called at ({a: i32}) it returns {a: i32}, where 'inner', also written to it, returns void` · DESIGN (owner ruling 2026-11-05 (Q5, W-split): a `let` holding a function that returns nothing cannot be written with one that returns a value, or the other way round, in either order) · was loud emit reject, clause 2 · found grading D14785's close · filed 2026-11-02 against master `b4ffadefd`**

Repro:

    function inner<U>(u: U) { print("I") }
    function retV<V>(v: V): V { print("R"); v }
    function main() {
      let k = inner
      k = retV
      k({ a: 1 })
    }
    main()

#### Mechanism

Not probed. The binding is called once, at one argument, yet emit reports two argument types.
Only the inline record literal and the value-returning member are needed, so the literal's shape
and the type the void twin is minted at probably disagree.

#### Grading list

`tests/cases/generics/error-generic-value-return-written-to-void-generic-let-delivered.vl` refuses the same write.

#### Ruling

Refused by design, owner ruling 2026-11-05 (Q5, W-split): a `let` holding a function that returns nothing cannot be written with one that returns a value, or the other way round, in either order. The annotated spelling already refused a void function written to a `let` whose type returns a value; `holeLetJudge` (check_relate_core.vl) now judges a member whose signature returns nothing as `void` against every member that returns a value, in both orders, so the hole and generic spellings agree with it (D15015).
