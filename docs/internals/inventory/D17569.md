### D17569 — a list of un-annotated functions handed through two identity calls is refused by mono: no pin for the inner call's result

**closed 2026-11-28 by lane START-2 — the witness prints `4` · a list of the set's ids handed to a hole parameter is held when every reader reads ids: each read of the parameter in the callee's body and, where the callee hands it back, each reader of the call's value, is a hold `ftHoldCtxOk` accepts (`ftHandOnReadsIds`, check_fn_tag.vl; coordinator ruling) · fixtures `tests/cases/closures/hole-fn-list-through-nested-identity-calls.vl`, `hole-fn-list-of-two-results-through-pass-through-calls.vl` · `const q = id([…]); id(q)` is D17873 · was loud emit reject (`unsupported argument type for x`), filed against master `66d6ea2e`**

Repro:

    function inc0(a) { return a + 1 }
    function half(a) { return a / 2.0 }
    function id(x) { return x }
    const r = id(id([half, inc0]))
    print(r[1](3))
    // vl check: rc 0.  vl run: emit error, monomorphize: unsupported argument type for `x`

Want:

    4

#### Mechanism

Mono pins a list of hole functions handed straight to `id` through the literal itself
(`monoArgPinName`), and a call returning a fresh literal (`id(mkl())`) through the literal that
call returns (`fnTagPlaceRep`, `fnTagRetPlaceRep`). An argument that is a call handing back its own
argument has neither, so `monoArgTyFail` refuses it. Pinning such a call as the argument it hands
back (tried 2026-11-25 by SOUND, not landed) only moves the refusal: `id(id([half, inc0]))` then
meets D17570's `no one signature`, `id(id([inc0, half])).length` meets `cannot take the generic
function inc0 as a value`, and `id(snd(1, …))` meets `the lists this function returns are built at
different rows`. The list must be carried as one rep through each pass-through instance.
