#### Mechanism

Building a closure's env, the maker reads each captured variable from its own frame
(`emitCaptureRead`, and the lifted-write copy-back in `wasmEmit.vl`). The captures come from
`captureNamesOf`, which lists names, not the declarations the closure's reads resolved to. So
the maker's slot is found by name (`captureHomeOf`): the live scope stack (`scopeSlotOf`), then
a parameter of the maker, then a capture a lifted maker assigns. Every other local lookup in
the emitter answers from the read's declaration (`localIndexOf`, `declaredSlotOf`); this is the
one left that a user's binding reaches by its spelling. It is right today because the scope
stack is live while the maker is emitted, so the innermost binding of the name in scope at the
closure is the one the closure's reads denote. The witness pins both directions: `h` must read
the inner `y`, and `j`, built after that block closed, the outer one.
