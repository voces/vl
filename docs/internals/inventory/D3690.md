### D3690 — a function with an un-annotated parameter, bound to a `let` that is later re-pointed, cannot be taken as a value

**loud emit reject · clause 2: `vl check` is clean · found by lane C2 grading [D3659](D3659.md) · filed 2026-10-05 against master `56af0f07e`**

Repro:

    function k(x) { x + 1 }
    let j = k
    j = k
    print(j(7))
    // vl check: rc 0.  vl run: emitProgram: cannot take the generic function `k` as a value

Want:

    8

#### Mechanism

Not traced. A `let` bound once (`let j = k`, no re-point) and a `const` alias both run, and the
refusal's own text says every call site pins `k` at `(i32)`, so one signature exists. The
re-pointing write `j = k` is what takes the value path that refuses a hole function rather than
pinning it from its calls.

#### Ablation

| ingredient changed | outcome | needed? |
| --- | --- | --- |
| no `j = k` | prints `8` | **yes** (the re-point) |
| `function k(x: i32)` | prints `8` | **yes** (the hole) |
