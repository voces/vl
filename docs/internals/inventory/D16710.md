### D16710 — a generic function returned by an un-annotated function, used at one type, then relayed through a second inferred return at another type, calls the first instance

**closed · runs, prints `41` · was loads then traps, `vl check` rc 0, `wasm trap: indirect call type mismatch` · clause 1 · a relay (a maker by signature every returned value of which is another maker's call, `fvaIsRelay`) hands the one closed result all its calls are delivered at to the maker calls it returns, through chains of relays (`fvaRelayRows`, check_assignable.vl), so `mk`'s read in `deliver` takes an instance and `mk` is no longer withdrawn from twinning · fixture `closures/generic-maker-relayed-by-inferred-return.vl`, matrix `generic-two-result-pins-relayed` · still open: a relay delivered at two results ([D16755](D16755.md)), a relay's result held in an un-annotated binding ([D16756](D16756.md)), an unused relay ([D16757](D16757.md)) · the `return_inferred`/annotated cell of `generic-two-result-pins-inferred.matrix.vl` ([D5531](D5531.md)'s template) · filed 2026-11-16 against master `c040079c`**

Repro:

    function k<T>(x: T): T { return x }
    function mk() { return k }
    const o = mk()
    const of: f64 = o(2.5)
    function deliver() { return mk() }
    const v: (x: i32) => i32 = deliver()
    print(v(41))
    // vl check: rc 0 (one unused-variable warning).  vl run: wasm trap, indirect call type mismatch

Want:

    41

#### Mechanism

`mk` is a maker: it returns a generic bare, and each call is built at the closed result its
delivery takes (`fvaMakerCallRows`, `monoMakerTwin`). A maker is twinned only while every read
of it takes such a result (`fvaMakerCoverCheck`). `deliver` returns `mk()`, so it is no maker
under `fvaRetsNamed` (a returned call is not a lambda or a name). The `mk()` inside it is
delivered at `deliver`'s open result, so that read of `mk` takes none, and `mk` was withdrawn
from twinning: every call shared the root, whose generic is the `f64` instance `o` asked for.
The call through `v` then ran the `f64` body at an `i32` signature.
