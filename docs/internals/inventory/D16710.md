### D16710 — a generic function returned by an un-annotated function, used at one type, then relayed through a second inferred return at another type, calls the first instance

**loads then traps · `vl check` rc 0, `wasm trap: indirect call type mismatch` · clause 1 · the `return_inferred`/annotated cell of `generic-two-result-pins-inferred.matrix.vl` ([D5531](D5531.md)'s template) · filed 2026-11-16 against master `c040079c`**

Repro:

    function k<T>(x: T): T { return x }
    function mk() { return k }
    const o = mk()
    const of: f64 = o(2.5)
    function deliver() { return mk() }
    const v: (x: i32) => i32 = deliver()
    print(v(41))
    // vl check: rc 0 (one unused-variable warning).  vl run: wasm trap, indirect call type mismatch

Want:

    41

#### Mechanism

Not located yet. What the ablation shows: the value `deliver()` hands back is the generic's `f64`
instance, the one the earlier call through `o` took. The binding's `(x: i32) => i32` type does not
reach through the second inferred return (`deliver` → `mk`) to select or build the `i32`
instance, and the call through `v` calls the `f64` body at an `i32` signature.
