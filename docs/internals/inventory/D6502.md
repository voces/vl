### D6502 — two un-annotated or bare type-parameter arguments handed to one generic's `T[]` parameters are check-clean invalid wasm at an instance binding them apart

**check-clean invalid wasm · `vl check` rc 0 · clause 1 · DESIGN: the checker owes the refusal it gives `f<A, B>(a: A[], b: B[])`, `argument of type string[] flows into `g` expecting i32[]` · found closing [D6482](D6482.md) · filed 2026-10-18 against master `4d1802f96`**

Repro:

    function g<T>(_x: T[], y: T[]): T[] { return y }
    function f(a, b) { return g(a, b) }
    f([1], ["s"])
    // vl check: rc 0.  vl run: the emitted module failed to validate inside `f`: type mismatch: expected (ref $3), found (ref $5); $3 is `list of i32-represented elements`

#### Mechanism

From the ablation only. [D6482](D6482.md)'s close records the pair an instance re-asks when
both sides are type parameters or parameter holes; at a `T[]` parameter the second argument
meets `T` bound to the first argument's element, a derived hole, so no pair is recorded.
Admitting an element-of hole over a parameter hole in `tyParamsApart` alone does not move
the witness.
