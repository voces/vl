### D4830 — a generic rest parameter's pack recorded no type, so an `i32 | boolean` element was read off the i32 spine

**closed 2026-10-15 by L2 stage 3 (rep-descriptor-campaign §13.24) · runs · was check-clean silently wrong and loud emit reject · clause 1 · pins: `tests/cases/functions/rest-pack-value-union-in-generic.vl` · filed 2026-10-15 against master `cad7f9a6a`**

Repro:

    function each<T>(...xs: T[]) { for x in xs { print(x) } }
    each(3, true)
    function second<T>(...xs: T[]): T { return xs[1] }
    print(second(1, true))
    // before the close: vl check rc 0, vl run: emitProgram: narrowed union atom has no value box
    // with `second` removed, it printed `3` and `1`

#### Mechanism

The checker packs the trailing arguments of a rest call into a list literal it mints during the
check (`restCallPack`). `checkNodeDone` records a type only for a node inside `nodeTyIx`, which
is sized to the arena when the check starts, so the pack's type `(i32 | boolean)[]` was dropped.
With no recorded type the list classifier fell back to the element spine, packed an `i32` list,
and the instance read it as one: `true` printed as `1`, and a `T` return found no box. The pack
now grows `nodeTyIx` before it is checked, so it records its type like any argument.
