### D3510 — a parameter default naming a module `const` that holds `null` passes the global's nullable box ref where the parameter takes a non-null one

**check-clean invalid wasm · clause 1 · open · found by lane LU's literal-union grid (3 of 1,040 cells) · the same on master `878f6ebe8` · filed 2026-10-03 against master `878f6ebe8`**

Repro:

    const bv: i32 | null = null
    function g(d: i32 | null = bv) { print(d) }
    g()
    // vl check: rc 0.  vl run: invalid module, "type mismatch: expected (ref $type), found (ref null $type)"

Want:

    null

#### Mechanism

Not confirmed. The module global for `bv` is a `(ref null $box)`, and a parameter of a value
box takes a `(ref $box)`. Written as an argument, `g(bv)` delivers `ref.as_non_null(global.get
bv)` and runs; substituted as the default, the same global is delivered with no
`ref.as_non_null`. The default node is the declaration's own (`fillArgDefaults` /
`emit_rewrite.vl` pushes `paramDefaultOf`), so whatever decides the recover at an argument is
probably keyed on something the shared declaration node does not carry.

#### Ablation

| ingredient changed | outcome | needed? |
| --- | --- | --- |

| `f64 | null` for `i32 | null` | still invalid | no (the scalar) |
| `9000000000 | 1 | null`, `3 | 1 | null` | still invalid | no (the union) |
