### D9565 — an un-annotated parameter bound at a lambda returning `null` has no monomorphization pin

**loud emit reject · clause 2 · CAPABILITY: an annotated `f: () => string | null` runs, and `take(null)` into an un-annotated value parameter runs · found closing [D9522](D9522.md) · present on master `92d03ef36` · filed 2026-10-22 against master `95725e040`**

Repro:

    function take(f) {
      const r = f()
      print(r)
    }
    take(() => null)
    // vl check: rc 0.  vl run: emitProgram: monomorphize: unsupported argument type for `f` in a call to `take`

Want:

    null

#### Mechanism

Traced, not fixed. The argument's type is `() => null`, and the function-value ABI has no
result token for the `null` unit type: `retTokOfTy` (emit_sig_tokens.vl) takes a `TyPrim`
named `null` to its `""` decline, so the argument has no signature key and the monomorphizer's
argument ladder refuses it (`monoArgTyFail`, emit_mono.vl). The annotated twin
`f: () => null` refuses at emit the same way, as `a function-value call has no interned
signature — its result type `null` has no representation in the function-value ABI`
(`cloCallSigRejectWhat`, emit_closure_sites.vl). The emitter already has a `nulnone` return
kind for a function declared to return `null` ([D4550](D4550.md)); running this needs a
`nulnone` result token in the `$fnsig` key and a function-value type for it, then the pin.
Not part of [D9561](D9561.md)'s `??` root, so it stays open.

Graded again closing [D9741](D9741.md) and [D9742](D9742.md): the matrix
`fn-value-lambda-result-null` (a lambda returning `null` at a function type returning `null`)
is 0 of 48 before and after their adoption rung, every cell refusing at emit with no ABI token,
`bare null needs a struct-typed context`, or this row's monomorphizer refusal. The token lives
in emit_sig_tokens.vl, so the close belongs with that file's owner. A lambda returning `null`
into a nullable-list or nullable-scalar slot runs since that close, where an annotation pins
it; at an un-annotated pin it does not (`two_instances` in the list matrices).
