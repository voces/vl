### D9565 — an un-annotated parameter bound at a lambda returning `null` has no monomorphization pin

**loud emit reject · clause 2 · CAPABILITY: an annotated `f: () => string | null` runs, and `take(null)` into an un-annotated value parameter runs · found closing [D9522](D9522.md) · present on master `95725e040` · filed 2026-10-22 against master `95725e040`**

Repro:

    function take(f) {
      const r = f()
      print(r)
    }
    take(() => null)
    // vl check: rc 0.  vl run: emitProgram: monomorphize: unsupported argument type for `f` in a call to `take`

Want:

    null

#### Mechanism

Not traced. The argument's function type `() => null` has no name in the monomorphizer's
argument ladder. The same refusal holds with a second call `take(() => "y")` beside it, and
with `print(f() ?? "q")` as the body.

| --- | --- | --- |
| the un-annotated parameter (`f: () => string \| null`) | runs | **yes** |
| the lambda (`take(null)` with `x ?? "q"`) | runs | **yes** |
