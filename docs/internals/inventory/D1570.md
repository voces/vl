### D1570 — a UFCS call whose callee is a function in scope reported `no field`, because the member arm never asked which UFCS gate refused

**now a loud check reject (fixed) — the program stays illegal (the `self`-name rule is the design) and the SENTENCE changed: `ufcsNotMethodKind` mirrors `ufcsCallTy`'s gate arm for arm, banks its answer on the callee member node beside D1230's, and `memberFloorErr` raises it under the new `ufcs-not-method` code with the parameter's own position on the `data` channel · four `tests/cases` fixtures pinned the old sentence and every one of them is in the defect's domain · ZERO corpus cells, 0 runs → not-runs · reported by the glean session, VL-021, `~/glean/docs/vl-issues.md` · filed 2026-09-03 against master `4490423c`**

Repro:

    type Cursor = { pos: i32 }
    function skipTags(c: Cursor): i32 { return c.pos + 1 }
    const cur: Cursor = { pos: 3 }
    print(cur.skipTags())
    // BEFORE: no field 'skipTags' on Cursor
    // AFTER:  'skipTags' is not a method — its first parameter is named `c`, not
    //         `self`, and a UFCS call `x.skipTags(…)` dispatches only to a `self`
    //         first parameter; rename it to `self`, or call `skipTags(…)` directly

#### Mechanism

**THE RULE IS NOT THE DEFECT.** `x.f(…)` in VL resolves only to a free function whose FIRST
parameter is named `self` (DECISIONS.md §"UFCS is never implicit"), and that rule stands. What
was wrong is that `checkCallNode` learned the answer and threw it away: `ufcsCallTy` returns
`-1` from four different gates, the caller falls through to `checkMemberNode`, and
`memberFloorMsg`'s `TyObj` arm then says the only thing it can see — the receiver has no such
FIELD. True, permanent, and it sends the reader looking for a field the type will never have.

`ufcsNotMethodKind` is the mirror. It re-asks `ufcsWouldDispatch`'s ladder in its order — the
declaration lookup, the `self`-NAME rule, the arity RANGE, `assignable(recvTy, params[0])` —
and stops exactly where that one stops, because it runs SPECULATIVELY on a call that has
already failed and must not force a pending return, record a deferred constraint or reorder
named arguments the way `ufcsCallTy` does on its way to an answer. A name with no `FuncDecl`
answers 0: a closure-valued binding is a function VALUE, `TyFunc` carries no parameter names,
and every sentence here names one.

**THE BANK IS D1230'S, FOR D1230'S REASON.** Only the CALL knows `argc`; only the member arm
reaches the sentence. `noteUfcsNotMethod` banks the finished message on `n.callFn` and
`memberFloorErr` reads it AFTER `ufcsMissSpecsAt`, so `ufcs-not-imported` keeps winning
wherever a name can be brought into scope by an import — which is the more actionable answer.
The STRING receiver arm answers before the general one and never banks, so it asks and raises
in place, exactly as D1230's string arm does.
