### D15546 — a record holding an un-annotated `Map()`, handed to an un-annotated parameter, has no argument type when only the callee pins the map

**closed 2026-11-08 · runs, prints `1` · was loud emit reject, `monomorphize: unsupported argument type for a` (`monoArgTyFail`, emit_mono.vl), `vl check` rc 0 · clause 2 · closed by pinning the argument's map from the callee's store through the field, as a store into a bare `Map()` argument pins it (`holeKidMapDemands` follows a field read's derived hole, check_demands.vl); the store-free spelling is now a check reject naming the field (`cannot infer a type for 'r.f'`) or the argument written in place · fixtures `maps/record-field-map-pinned-by-callee-store.vl`, `maps/error-record-field-map-never-pinned.vl` · found by the `argument` row of matrix `record-field-map-of-fn-records` closing [D15545](D15545.md) · filed 2026-11-08 against master `be09b8cbc`**

Repro:

    function t(a) {
      a.f["k"] = 41
      print(a.f.length)
    }
    const r = { f: Map() }
    t(r)

Want:

    1

#### Mechanism

The callee's `a.f` is a hole derived from `a` (`HD_FLD`), and its store gives that hole a map
demand. At the call, `holeKidMapDemands` re-asked the demands of `a`'s result and non-null-face
holes against the argument, but not of its field holes, so the record's `Map()` stayed open and
mono had no closed argument type. Field holes are now kids of their base, and a field kid is
asked against the argument's field of that name, which pins the map in place.
