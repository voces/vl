### D15546 — a record holding an un-annotated `Map()`, handed to an un-annotated parameter, has no argument type when only the callee pins the map

**loud emit reject · `vl check` rc 0 · clause 2 · `monomorphize: unsupported argument type for a` (`monoArgTyFail`, emit_mono.vl) · found by the `argument` row of matrix `record-field-map-of-fn-records` closing [D15545](D15545.md) · filed 2026-11-08 against master `be09b8cbc`**

Repro:

    function t(a) {
      a.f["k"] = 41
      print(a.f.length)
    }
    const r = { f: Map() }
    t(r)
    // vl check rc 0.  vl run: emit error: monomorphize: unsupported argument type for `a`

Want:

    1

#### Mechanism

Not traced. The caller's record type keeps its map open, and only the callee's store
closes it, which no argument pin carries back to the call.

#### Ablation

| ingredient removed | outcome | needed? |
| --- | --- | --- |
| the record (`t(Map())`, `a["k"] = 41`) | runs, `1` | **yes** |
| the hole parameter: a caller-side store `r.f["j"] = 1` first | runs, `2` | **yes** |
| the store in the callee (`print(a.f.length)` alone) | still refuses | no |

#### Grading list

The store-free spelling `function t(a) { print(a.f.length) }` with `t({ f: Map() })` refuses
the same way; a bare `const m = Map(); print(m.length)` is a check reject (`cannot infer a
type for 'm'`), so that spelling may be one the checker owes rather than one that should run.
