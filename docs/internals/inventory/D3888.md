### D3888 — a call to a nested generic checks every nested generic's deferred constraints that use the same type-parameter name

**closed 2026-10-08 by lane SC, with D3853 · runs · was a loud check reject, a valid program refused (clause 2) · found closing D3853 (lane SC) · filed 2026-10-08 against master `a1c9be3c4` · pins: `tests/cases/generics/nested-generic-bound-per-declaration.vl`**

Repro:

    function add(x: i32) {
      function b<U>(y: U) { print(y + 1) }
      b(1)
      print(x)
    }
    add(1)
    function len(x: i32) {
      function c<U>(y: U) { print(y.length) }
      c([1, 2])
      print(x)
    }
    len(2)
    // vl check: `c` prints its type parameter here: print expects one scalar or string value (i32 | i64 | f32 | f64 | boolean | string), got i32[]

Want:

    2
    1
    2
    2

#### Mechanism

A nested function has no `fnDeclIx` entry, so a call to one is `CSTR_NODECL`, and `cstrOwnedBy`
treats that as owning every constraint in the program. The constraints are substituted by
type-parameter name, so `c([1, 2])` binds `U` to `i32[]` and re-checks `b`'s `y + 1` and
`print(y + 1)` with it. A fix needs the call to name the nested declaration it reaches.

Closed by D3853's per-declaration rows: a call to `c` binds only `c`'s rows.
