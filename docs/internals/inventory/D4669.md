### D4669 — a hole parameter pinned once to a value and once to `null` has no rep for a null test in the value's instance

**closed 2026-10-14: runs, prints false then true · was a loud emit reject with `vl check` rc 0, clause 2 · fixed on master by a change that landed while this PR was queued · found closing D4637 · filed 2026-10-14 against master `1c1740512`**

Repro:

    function g(v) {
      print(v == null)
    }
    g(4)
    g(null)
    // vl check: rc 0.  vl run: emitProgram: bare null needs a struct-typed context

Want:

    false
    true

#### Mechanism

Not localised past the ablation. Each call pins its own instance of `g`. The `null` instance
gives the test no operand rep to compare against, so the bare `null` reaches the emitter with
no context. A single non-null call folds the test (D2240, D4637).

#### Ablation

| ingredient changed | outcome | needed? |
| --- | --- | --- |
| the `g(null)` call | runs, `false` | **yes** |
| the `g(4)` call (`g(null)` alone) | still refuses | no |
| the argument a record (`g({ q: 4 })`, `g(null)`) | still refuses | no |
| the test of a field (`v.q == null`, `g({ q: 4 })`, `g({ q: null })`) | still refuses | no |
| `v: i32 \| null` annotated | runs | **yes** |

#### Grading list

The field spelling in the ablation. `g({ q: null })` alone refuses with
`monomorphize: unsupported argument type`, which is the same pin seen from the other side.
