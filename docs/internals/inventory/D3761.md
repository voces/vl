### D3761 — a generic's first instance retires `buildFnMap`'s whole banked prefix, so n generics instantiated once each compile quadratically

**closed 2026-10-06 by lane GN · runs, as it always did · was a cost row: guest fuel 0.117G / 0.385G / 1.385G / 5.179G at n = 100 / 200 / 400 / 800, now 0.051G / 0.116G / 0.296G / 0.853G, byte-identical output · found in review of #3399 · filed 2026-10-06 against master `b05991d98` · pin: the `generic first instances` axis in `tests/vl_scaling_shape_test.ts`**

#### Mechanism

`monoRebuild` (emit_mono.vl) runs `buildFnMap` after every minted instance. B8 of
`perf-opportunities-2026-09.md` made that call resume: it re-seeds the classified prefix of
`fnStmts` from a row cache and classifies only the new tail. A first instance does not push a
row. It replaces its template's slot (`fnStmts[origFe] = nfn`) and calls
`buildFnMapNoteFnSlotWrite`, which retires the whole prefix, so the next call re-classified every
function. A profile at n = 400 (`--names` seed, `VL_PROFILE_GUEST`) put `buildFnMap` at **72.2%
inclusive**, under `monoMakeInstanceGo` at 82.8%. The close notes such a write with
`buildFnMapNoteFnStmtWrite(slot, node)`. When the slot is its own row and the new declaration
keeps the row's name, the name, its sid and the nested mark are unchanged. The slot is then marked
dirty, and the resume re-classifies only that row (`buildFnMapClassifyRow`, the loop body
factored out).
Any other write still retires the prefix.
