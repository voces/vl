### D15929 — records of un-annotated functions returning different types, pushed into an un-annotated empty list, trap when the second is called through

**closed 2026-11-12 · runs, prints `1.5` · it trapped at run time, `indirect call type mismatch`, `vl check` clean, clause 1, then was a loud check reject under the judge's containment · found tracing [D15806](D15806.md), whose map spelling shares the cause · filed 2026-11-12 against master `411245305` · fixed by each later store into a filled record element joining its function fields' sets (`elabFnRecJoin`, check_elab_cap.vl, at `.push` and the index write)**

Repro:

    function inc0(a) { return a + 1 }
    function half(a) { return a / 2.0 }
    const l = []
    l.push({ f: inc0 })
    l.push({ f: half })
    print(l[1].f(3))

Want:

    1.5

#### Mechanism

The empty list's element hole is filled by the first push's record, whose function field carries
`inc0`'s set alone; a later push was checked against that fill, not joined into it, so the call
lowered at `inc0`'s signature with no split noted for [D15926](D15926.md)'s floor. Each later store
into a filled record element now unions the stored record's function-field sets into the element's
(`elabFnRecJoin`), at `.push`, at `l[i] = v`, and at a map's `m[k] = v` and `.set`. The judge's
containment (`holeSlotSetHolds`) stays: it refuses a read whose set still misses a written function.
