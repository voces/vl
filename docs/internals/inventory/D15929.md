### D15929 — records of un-annotated functions returning different types, pushed into an un-annotated empty list, trap when the second is called through

**trap after load · `wasm trap: indirect call type mismatch`, `vl check` reports 0 errors · clause 1 · open · on master · found tracing [D15806](D15806.md), whose map spelling shares the cause · filed 2026-11-12 against master `411245305`**

Repro:

    function inc0(a) { return a + 1 }
    function half(a) { return a / 2.0 }
    const l = []
    l.push({ f: inc0 })
    l.push({ f: half })
    print(l[1].f(3))

Want:

    1.5

#### Mechanism

Not traced past the type. The empty list's element hole is filled by the first push's record, whose
function field carries `inc0`'s set alone; the second push is checked against that fill rather than
joined into it. The one-result judge lets the call through, but no call through a split set is
noted, so [D15926](D15926.md)'s floor does not see it, and the call lowers at `inc0`'s signature.
D15806's map spelling, `m[k] = { f: … }` into an un-annotated `Map()`, has the same one-member value
set (a probe in the tag decision's scan found `half` outside it).

#### Ablation

| spelling | outcome |
| --- | --- |
| the witness | runtime trap |
| the first element called, `l[0].f(3)` | runs, `4` |
| the pushes in the other order, the second called | runtime trap |
| a literal initialiser, `[{ f: inc0 }]` then the push | runs, `1.5` |
| one result type, `dbl` for `half` | runs |
| the functions pushed bare, `l.push(inc0); l.push(half); l[1](3)` | runs, `1.5` |
| a `Map()` of the records, `m["b"] = { f: half }` | loud check reject ([D15806](D15806.md)) |
