### D15929 — records of un-annotated functions returning different types, pushed into an un-annotated empty list, trap when the second is called through

**loud check reject · `cannot write 'half' to 'l[].f': called at (i32) it returns f64, where 'inc0', also written to it, returns i32 — every function a call through 'l[].f' may run must return one type` · clause 2 · open, target `1.5` · it trapped at run time, `indirect call type mismatch`, `vl check` clean, clause 1, until the judge's containment of 2026-11-12 · found tracing [D15806](D15806.md), whose map spelling shares the cause · filed 2026-11-12 against master `411245305`**

Repro:

    function inc0(a) { return a + 1 }
    function half(a) { return a / 2.0 }
    const l = []
    l.push({ f: inc0 })
    l.push({ f: half })
    print(l[1].f(3))

Want:

    1.5

#### Mechanism

Not traced past the type. The empty list's element hole is filled by the first push's record, whose
function field carries `inc0`'s set alone; the second push is checked against that fill rather than
joined into it. The one-result judge lets the call through, but no call through a split set is
noted, so [D15926](D15926.md)'s floor does not see it, and the call lowers at `inc0`'s signature.
D15806's map spelling, `m[k] = { f: … }` into an un-annotated `Map()`, has the same one-member value
set (a probe in the tag decision's scan found `half` outside it). The judge now refuses a lifted call
whose read's set misses a written function (`holeSlotSetHolds`, check_relate_core.vl); the run-fix is
the hole fill joining a later store's sets.
