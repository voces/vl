### D13282 — a labelled block written as the argument of a hole parameter, choosing a hole function declared in its loop, is refused at emit

**loud emit reject · `vl check` rc 0 · clause 2 · CAPABILITY: binding the block first, `const h = @B { … }` then `apply(h, "a")`, runs · open · `monomorphize: unsupported argument type for `f` in a call to `apply`` · pre-existing on master `247fb2679` · found closing [D13082](D13082.md), whose argument face this is · filed 2026-10-25 against master `247fb2679`**

Repro:

    function ask(s) { return s + "?" }
    function apply(f, s: string) { return f(s) }
    function g(xs: string[]) {
      print(apply(@B {
        for v in xs {
          function inner(s) { return s + "!" }
          if v == "q" { break @B inner }
        }
        ask
      }, "a"))
    }
    g(["p", "q"])
    g(["z"])
    // vl check: rc 0.  vl run: emitProgram: monomorphize: unsupported argument type for `f` in a call to `apply`

Want:

    a!
    a?

#### Mechanism

From the code path. The loop-value rewrite turns the block into an index carrier and a choice
among the functions (`lvOpenFnChoice`, emit_rewrite.vl), or with a capture a seeded closure
carrier (D13082). A binding of either is delivered to `apply`'s hole parameter through the
written-let flow; the same `if` written in the argument itself reaches the monomorphizer's
argument classifier, which has no arm for it.
