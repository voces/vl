### D17811 — a map of a function set whose calls split, handed to an un-annotated parameter that walks its values, is refused at the map's binding

**loud emit reject · `the compiler cannot yet lower this statement (convert map -> map)` · clause 2 · open · `vl check` rc 0 · the same walk at module scope runs (D17731), as does a list handed to the same parameter · graded with [D17773](D17773.md), the same `convert map -> map` gap · filed 2026-11-28 against master `d76847374` · owner COV-IS**

Repro:

    function dbl(a: f64): f64 { return a * 2.0 }
    const g = (a) => a + 1
    const _a = g(2.5)
    const _b = g(3)
    const m = Map()
    m["a"] = g
    m["b"] = dbl
    function walk(mm) { for v in mm.values() { print(v(3)) } }
    walk(m)
    // vl check: rc 0.  vl run: emit error at `const g` (convert map -> map)

Want:

    4
    6

#### Mechanism

Not traced. The split call `v(3)` tags the set (D17731's rule), so `m` is stored as a map of
ids; the hole parameter `mm`'s instance is not, and the hand of `m` to it is a conversion between
two map reps that no arm builds. A list handed to the same parameter runs, so the map's hand is
what lacks the tagged rep.

#### Ablation

| ingredient removed | outcome | needed? |
| --- | --- | --- |
| the split: `v(3.0)` | runs, `4` `6` | **yes** (the tagged set) |
| `g`, one member `dbl` | runs, `6` | **yes** (the set) |
| the parameter: the walk at module scope | runs, `4` `6` (D17731) | **yes** (the hand) |
| the values walk: `mm.has("a")` | runs, `true` | **yes** (a read of the values) |
| the list `[g, dbl]` handed and walked | runs, `4` `6` | **yes** (the map) |
