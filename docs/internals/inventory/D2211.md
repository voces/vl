### D2211 — an un-annotated alias of a `(string | null)[]` is classified as no list

**closed 2026-09-23 — the witness prints `3` · was `loud emit reject`, `emitProgram: .push receiver is not a list` with `vl check` rc 0 · clause 2 · found by D2209's position grid · filed against master `99d1f4fdd` · fixture `tests/cases/arrays/nullable-string-list-alias.vl`**

Repro:

    function f(): (string | null)[] | null { ["a", null] }
    const mv = f()
    if mv != null {
      const v = mv
      v.push("x")
      print(v.length)
    }
    // before the close: vl check rc 0, then `emitProgram: .push receiver is not a list`

#### Mechanism

A `(string | null)[]` has the string-list rep, but its type kind is not the one
`exprStringArray`'s typed fast path reads. So an `Ident` bound by an un-annotated alias fell
through every storage rung and was classified as no list: `.push` and `.length` refused. The
source could be a narrowed call result, a global, a parameter or a narrowed map read. The
close adds a rung to the `Ident` arm. It takes a binding the checker pinned to an array
(`nodeTyPinIxOf`) whose element is the nullable string (`nodeArrayElemIsNulStr`).

#### Grading list

The narrowed, global, parameter and map-read spellings of the fixture, and push-then-read
(`a true x true 4`). Also the two `map_value` cells of D2209's grid (`(string | null)[]`
element, empty arm first, un-annotated). They ran on the base only because the join was
typed `string[]`, and they print `1` / `z` after the close.
