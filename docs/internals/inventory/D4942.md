#### Mechanism

`monomorphize` (`compiler/emit_mono.vl`) returns early on a program with no generic, so a
generic-free program — the compiler itself among them — never builds `fnFlowTableBuild` or runs
the mono walk. One generic anywhere runs both over the whole program, and four questions in
them were superlinear. `ffMerge` (`compiler/fn_flow_shadow.vl`) kept the left root and copied
the right class's source/binding/result lists into it with a linear `i32ListHas` dedupe, so
many bindings read from one shared slot (`const a = G[0]` in every function) cost cubic time;
it is now union-by-size over per-root membership sets. `ffDirectedPins` ran a BFS per store
site (`xs.push`, `m.set`, `=` into a member or index, via `monoPlacePinName`) and now returns
at once for a class that holds no pin, memoising the per-slot key list otherwise.
`monoFrameHolds(-1, …)` and `monoTopFrameOf` scanned every top-level statement per write, and
`monoTopFnUnnamed` walked every statement per call; each now reads one whole-program table
built once per arena stamp (`monoProgTopOf`, `monoProgNamesIdent`).

#### Grading list

The compiler with one generic helper added (the D3975 builder's `fsExcluded<V>`) must
self-build: after this fix it does under the copying collector (rc 0, 98.7e9 fuel, 1.90 GB
allocated). Under `VL_COMPILE_GC=null`, which `refresh-compiler.sh` and `native-fixpoint.sh`
pin, it still traps `allocation size too large`: master's own generic-free self-build already
allocates 3.56 GB of the 4 GiB heap, and the mono walk's linear cost (+13% fuel) pushes it over.
That is headroom, not this row's superlinearity.

The banked tables are cleared per compile: `monomorphize` empties `monoProgTop` and
`monoProgNames`, and `fnFlowShadowBegin` the flow sets and the pin-key memo.
`tests/vl_instance_state_leak_test.ts` pins it with two same-shape programs that differ only in
their writers' names. Without the clears the second compiles to different bytes.

The pin-key memo is a `string[][]` indexed by slot, not a `{[i32]: string[]}`. That map type
was new to the compiler, and it added three unused scratch locals to 882 of the seed's
functions, `capScan` among them, which does not use it. That larger frame was enough to
overflow V8's stack in `tests/vl_deep_nesting_test.ts` at 600 bare blocks.
