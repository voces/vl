### D16290 — a wider record into a parameter of an INLINE record type is refused unless the dropped fields sort last; a named record type takes it

**closed 2026-11-15 · runs, prints `tom` · was a loud check reject, clause 2 · the record-width rewrite keys an inline record of fields by its spelling, and the slot's bound is re-resolved from that spelling every pass (`wsRecKey`, `rowSlotBind`) · filed 2026-11-14 against master `94f5055d`**

Repro:

    type Cat = { name: string, age: i32 }
    function name(a: { name: string }) { print(a.name) }
    const c: Cat = { name: "tom", age: 3 }
    name(c)

Want:

    tom

#### Mechanism

A wider record into a declared record parameter is lowered by making the parameter generic
([D3992](D3992.md)), but `wsCandidate` (check_demands.vl) only takes a parameter whose annotation
NAMES a record (`wsAnnRecName`), so an inline record type is never rewritten. The argument then
needs its layout to be a wasm subtype of the parameter's, and a record's fields are laid out by
name, so `{age, name}` is not a prefix-extension of `{name}` while `{name, zz}` is.

#### Grading list

The four spellings above at a record-typed parameter, a nullable inline record parameter, and an
exported function (`wsCandidate` also declines an `export`).
