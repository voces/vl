### D5750 — a function handed to an un-annotated parameter is called with more arguments than it takes, and the checker does not refuse it

**loud emit reject · `vl check` rc 0 · clause 2 (the checker owes the diagnosis) · found closing [D5612](D5612.md) · filed 2026-10-17 against master `5aa033e26`**

Repro:

    function idg<T>(v: T): T { v }
    function apply(g, x, y) { return g(x, y) }
    print(apply(idg, 3, 0))
    // vl check: rc 0.  vl run: emitProgram: a function-value call has no interned signature — the callee has no function type to key a signature from

Want:

    a `vl check` error naming the arity: `idg` takes one argument and `apply` calls `g` with two

#### Mechanism

From the ablation only. The program is ill-typed: `g` is called with two arguments and is
handed a one-parameter function. With `g` annotated, the checker refuses it at the argument.
Un-annotated, the hole's type is fixed by the call inside the instance, and the checker never
compares it with the argument's arity. The emitter then refuses with a different sentence for
each kind of argument.

#### Ablation

| spelling | outcome | needed? |
| --- | --- | --- |
| the witness (a declared generic) | emit reject, `no interned signature` | — |
| `function one(v: i32): i32` as the argument | emit reject, `a call passes more arguments than the function it calls takes` | no |
| `function neg(a)` as the argument | emit reject, `cannot take the generic function` | no |
| `g: (a: i32, b: i32) => i32` annotated | `vl check` rc 1, `argument 1: expected (i32, i32) => i32, got (T) => T` | **yes** |
