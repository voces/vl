### D2765 — a record VALUE joined with a differently-typed record of the same field names needs a converting copy the join has nowhere to make

**loud emit reject · clause 2 · the audited non-literal faces of D2731's join: an `if` or `match` tail, a `return` and a return tail, a list literal's element, a record value in a literal leaf's field, a `??` between two record values, and an un-annotated function value returning a join of nested records handed to a call; the unaudited faces are [D2794](D2794.md) · on master a loud emit reject in most faces (`union \`A|B\` cannot be discriminated`) and invalid modules in the rest · filed 2026-09-27 against master `f6db92e0d`**

Repro:

    type A = { f: i32 }
    type B = { f: string }
    function g(sel: i32) {
      const a: A = { f: 1 }
      const b: B = { f: "s" }
      const sx = if sel == 0 { a } else { b }
      const v = sx.f
      if v is string { print(v) } else { print(v + 1) }
    }
    g(0)
    // vl check: rc 0.  vl run: emitProgram: this branch hands over a record whose field types differ from the record the branches join to …

#### Mechanism

Since D2731 the join is the record `{f: i32 | string}`. A literal arm is built at that row; a
record VALUE arm (`a`, pinned to `A`'s row by its annotation or a parameter) holds a bare `i32`
field where the joined row holds a union box, and the two are unrelated wasm structs. A record
is shared, not copied, so this is [D2100](D2100.md)/[D2160](D2160.md)'s converting-copy gap at
the places a join's value is made. One pass (`auditRecordJoinLeaves`, after the struct rows
exist) visits the tails of a value `if` or `match`, the elements of a list literal, every value a
function returns against its declared or pinned return row, and the fields of a literal leaf, and
refuses a leaf that is a record VALUE built at a row whose fields are stored differently
(`recordRepDiffers`, through nested records). A `??` is refused only where both operands are
record values of rows that differ. A lambda argument whose un-annotated result joins records
with a record-valued field is refused at the call, since its parameter reads the result at the
first row of those field names. A literal leaf is built at the join's row and runs; an
un-annotated record variable that adopts the joined rep runs. Not covered, and still invalid
wasm as on master: a `??` whose one operand is a literal, a join passed straight to an
annotated parameter, and a reassignment, all [D2794](D2794.md); the binding position with no
join (`const sx: { f: i32 | string } = a`) is still D2160.
