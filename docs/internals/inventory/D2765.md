### D2765 — a record VALUE joined with a differently-typed record of the same field names needs a converting copy the join has nowhere to make

**loud emit reject · clause 2 · the named-record and parameter faces of D2731's join, annotated or not · was a loud emit reject on master too (`union \`A|B\` cannot be discriminated`) · filed 2026-09-27 against master `f6db92e0d`**

Repro:

    type A = { f: i32 }
    type B = { f: string }
    function g(sel: i32) {
      const a: A = { f: 1 }
      const b: B = { f: "s" }
      const sx = if sel == 0 { a } else { b }
      const v = sx.f
      if v is string { print(v) } else { print(v + 1) }
    }
    g(0)
    // vl check: rc 0.  vl run: emitProgram: this branch hands over a record whose field types differ from the record the branches join to …

#### Mechanism

Since D2731 the join is the record `{f: i32 | string}`. A literal arm is built at that row; a
record VALUE arm (`a`, pinned to `A`'s row by its annotation or a parameter) holds a bare `i32`
field where the joined row holds a union box, and the two are unrelated wasm structs. A record
is shared, not copied, so this is [D2100](D2100.md)/[D2160](D2160.md)'s converting-copy gap at
one more position, the `if` arm. `emitRefIfArm` refuses it loudly (`refIfArmNeedsRecordCopy`)
rather than handing the narrow struct over, which is what the binding position still does
(D2160). An un-annotated record variable (`const a = { f: 1 }`) adopts the joined rep and runs.

#### Ablation

| ingredient removed | outcome | needed? |
| --- | --- | --- |
| the annotation on `a` (`const a = { f: 1 }`) | runs | **yes** |
| the join (`const sx: { f: i32 \| string } = a`) | check-clean invalid wasm — D2160 | no |
| `b`'s annotation, keeping `a: A` | check-clean invalid wasm on master; the same refusal now | no |
| parameters `a: A, b: B` in place of locals | the same refusal | no |

#### Grading list

D2160's and D2100's witnesses — the close is one converting copy for every position.
