### D2525 — a `(T | null)[]` over a type parameter was refused on the generic original's own annotation, before any instance bound `T`

**closed 2026-09-25 — the filed repro RUNS and prints `7` · was a loud emit reject, `emitProgram: a nullable-V list element has no rep; use a non-null element type` · clause 2 · found building `std:idtable` (collections Q4) · filed 2026-09-25 against master `ca544493e` · fixture `tests/cases/generics/nullable-type-param-list.vl`**

Repro:

    function at<V>(xs: (V | null)[], i: i32): V | null {
      if i < 0 || i >= xs.length { return null }
      return xs[i]
    }
    const s: (i32 | null)[] = [null, 7]
    print(at(s, 1) ?? -1)

#### Mechanism

`collectA`'s ref-array rung classifies the annotation `(V | null)[]` of the generic ORIGINAL,
whose element names the type parameter itself. Its kind-2 element is a two-part nullable that is
not a value union, so the rung refused it as a niche with no list rep. The original is never
emitted: each instance re-runs the pass over its substituted spelling. `genTyParamArr` already
skips `T[]` for this reason but declines every ref-array name, so it never saw the nullable
spelling. The fix adds its nullable twin, `genTyParamNulArr`, as a rung ahead of the ref-array
rung. The instances then build wherever `V | null` is a box (`i32`, `i64`, `f64`, `f32`, an integer
literal union) or a nullable reference (a record, a nullable record, a list, a map). Where it is a
NICHE (`string`, `boolean`, a literal union of strings, a function type) the instance's element
reads take the template's rep — a push of `null` trapped at `string` and `boolean` was invalid
wasm — so `monoNicheNulListCheck` refuses those instances with the original sentence, naming the
bound type.

A lambda written directly as a `return` argument (or a block's tail) inside the generic was
lifted ONCE and shared by every instance, so its capture of the `(T | null)[]` read the element
at the template's rep: invalid wasm when `T` is a list, reached through a parameter or through a
generic record `self` (`getter<V>(self: Tbl<V>) => (i) => self.slots[i]`). `monoPinBodyLambdas`
cloned only a binding's or a field's lambda; it now clones an anonymous lambda in any position it
walks, so those instances run.

The refused set, exactly, each loud with `a nullable-<T> list element has no rep`:

* a generic FUNCTION's `(T | null)[]` parameter, local or return, with `T` a `string`, a
  `boolean`, a literal union of strings or a function type (`monoNicheNulListCheck`), or a union
  of records (`Circle | Square`, refused by the ref-array rung: the instance annotation classifies
  by name as a union box, while the concrete `(Sh | null)[]` runs because its node carries an arena
  type). A generic RECORD's `(T | null)[]` field built directly (`Tbl<string>`, `Tbl<boolean>`,
  `Tbl<SL>`, `Tbl<Sh>`) runs; `IdTable<V>` is refused for these because its constructor is a
  generic function.
* inside a generic that declares a lambda, `T` a union, including an integer literal union
  (`monoLamNulUnionListCheck`): the closure's result reaches D2535's unboxing gap; and `T` a generic
  record application that itself holds a `(P | null)[]` field (`IdTable<Tex>`,
  `gaeAppHasNulParamListField`), where the cloned lambda read the element at the wrong heap.
* a generic record alias's `(T | null)[]` field applied at a generic application
  (`Bx<GB<i32>>`, so `IdTable<GB<i32>>` and `IdTable<IdTable<Tex>>`; `gaeNulParamListAtApp`).
  The mechanism: the application's row resolves no ref-list slot of its own for that field
  (`sFieldRefSlot` answers another list's), so a list literal holding `null` builds at a union
  box. This guard is still wider than the failure, since a program that never delivers such a
  literal to the field would run; it goes when the application interns its field's slot.
