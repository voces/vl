#### Mechanism

The multi-value step returns a record as fields only to a call site that reads it field by
field. A site that stores the result keeps the struct, and the producer's twin for that site
(`qnorm.mv` in sunpa: fields in, a struct out) allocates. The store could take the record
apart if the inline-record step held the field (`Joint.rot`) inline. That step refuses because
`last = j.rot` reads the field whole, and a whole read of an inline field re-boxes, where
today it shares the box. In sunpa the stores are `quatOf`'s five keeping call sites
(`twoBone`, `fabrik`, `aimChain`: type 32 field 4, "5 of its 7 read(s) take the whole
record (first in parentRotation)"). `unit`'s keeping sites hand its result to `cylAlong`, which
keeps it in a `Cyl` (type 67, "2 of its 4 read(s) take the whole record (first in holeOf)"),
and to locals that another use keeps (`legsLayer`, `stepSplit`).

sunpa `frame-alloc` under `feet-test` (10,938 frames): `qnorm.mv` 42,090 `struct.new` (3.8 a
frame), `unit.mv_2196` 119,344 (10.9 a frame), the same on master and this lane.

#### Analysis (lane RA, master `e2443d6b2`)

**The witness has no cheaper lowering today.** Inlining `Joint.rot` would delete the stored
quaternion's box at the push and add one at `last = j.rot`, which stores into a module
global and so must be a box: ten stores and ten whole reads a frame trade one allocation for
one. Re-boxing into a local, as the flat step does for lists (`flat.rs`), pays only where the
re-boxed local is itself scalarized; a global, a field and a store are not. A fix would need
the inline step to weigh each whole read by what it feeds (a scalarized local, a field-only
parameter, or a real store), and to compare re-boxed reads against stores, per field. That
is a design question, not a small change.

**sunpa's cost was mostly not this row.** Ablated against sunpa `f81a945`:

* `quatOf`'s five keeping sites (`twoBone`, `fabrik`, `aimChain`) are
  `rotateBy(pose, b, turn, if pb < 0 { sk.rootRotation } else { quatOf(g[pb]) })`: the
  `if`'s value, not a store. D3766 makes such a merge leave fields. `qnorm.mv`: 42,132 →
  25 `struct.new` under `feet-test` (3.85 a frame → 0). The 25 left are `animSkeleton`'s
  real store into `Skeleton.rootRotation`, once per skeleton.
* `unit`'s keeping sites were `stepSplit`'s `if d0.z < d1.z { d1 } else { d0 }` (D3766) and
  `legsLayer`'s `pf`, passed as `unit`'s fallback (D3767). Left: `holeOf` and `wrapFingers`
  (a grip fitted per hand when a character is posed the first time, not per frame), where the
  result is a `Cyl`'s field (`Cyl` holds two `V3` references, which the inline step does not
  take) or a local passed to `cylAlong`, which keeps it. `unit.mv`: 119,344 → 99,739.

What stays of this row in sunpa is `Skeleton.rootRotation` (stored once, read whole five
times a frame, where today it shares one box: inlining it would cost five boxes a frame) and
the `Cyl` fields: both are cases where the box is cheaper than re-boxing.
