### D15940 — a map of an un-annotated function pushed or set into an annotated holder at one signature, while another holder needs another, is refused at emit

**open · loud emit reject · `monoPinMapValues: the map's stored functions close at another type than its slot fact` · clause 2 · the same map in the annotated holder's literal runs, as does the push when the function is needed at one signature · found by lane w321 ablating D15758's grading list · filed 2026-11-12 against master `f050912e4`**

Repro:

    function half(a) { return a / 2.0 }
    const m1 = Map()
    m1.set("a", half)
    const m4 = Map()
    m4.set("a", half)
    const ws: ({ [string]: (a: f64) => f64 })[] = [m1]
    const g = ws[0].get("a")
    const xs: ({ [string]: (a: i32) => f64 })[] = []
    xs.push(m4)
    if g != null { print(g(3) + 1.5) }
    // vl check: rc 0.  vl run: monoPinMapValues refusal

Want:

    3

#### Mechanism

Not yet traced. `half` is needed at `(f64) => f64` through `ws`, and `m4` is delivered at
`(i32) => f64` by the push. The refusal says `m4`'s slot fact and the type its stored functions pin at
disagree, so one of them misses the push's delivery once `half` has a second instance. The refusal
names a mechanism, not a contract.
