### D16740 — a list of two records nested seven deep, one leaf a value and the other `null`, builds an invalid module

**closed 2026-11-16 · runs, prints `a` `none` · fixed by lane AE4: `recordRepTyAdopt` follows a literal at any depth, so the leaf is built at the list element's rep · was check-clean invalid wasm · clause 1 · fixture `tests/cases/soundness/deep-literal-leaf-rep.vl` · found closing [D16731](D16731.md) · filed 2026-11-16 against master `71ff99b49`**

Repro:

    const ys = [{ a: { b: { c: { d: { e: { g: { h: "a" } } } } } } }, { a: { b: { c: { d: { e: { g: { h: null } } } } } } }]
    print(ys[0].a.b.c.d.e.g.h ?? "none")
    print(ys[1].a.b.c.d.e.g.h ?? "none")
    // vl check: rc 0.  vl run on master: invalid module, "type mismatch: expected (ref null $type), found (ref $type)"

Want:

    a
    none

#### Mechanism

`recordRepTyAdopt` (`check_fit_rules.vl`) stamps a literal and its nested fields with the rep
they are built at. Its callers handed it a budget of six or eight levels. Past the budget the
inner literals kept their own record row while the list element's row named the joined
`string | null` field, so the struct built and the struct stored disagreed. The walk follows the
literal's own nodes, so it needs no budget; it now has none.
