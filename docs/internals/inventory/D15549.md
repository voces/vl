### D15549 — a generic instance's returned list of records holding a called set is built at another instance's record row

**closed · runs, prints `2` then `s` · was check-clean invalid wasm, `the emitted module failed to validate inside `mk``, clause 1 · fixed 2026-11-08: a shared field read takes its type in the instance's frame (`monoRecordObjLitAt`), and the row of a literal re-typed in a generic instance mints in that frame (`mintGradualObjLitRows`) · found closing [D15297](D15297.md) · filed 2026-11-08 against master `82072a24`**

Repro:

    function inc0(a) { return a + 1 }
    function mk<T>(x: T) { return [{ fs: [inc0], x: x }] }
    print(mk(5)[0].fs[0](1))
    print(mk("s")[0].x)

Want:

    2
    s

#### Mechanism

Each instance's element literal is its own copy with its own closed type, and each gets its own
row, but the copies share their `FieldInit` children: a generic instance's clone rebuilds only
its statement spine. `monoRecordObjLitAt` wrote each instance's type for the shared read `x` into
the node column, so the last instance's type won, and `anonMintRowFor` (reached from
`mintGradualObjLitRows` with no frame) read every copy's `x` at it. Both rows read `x: string`,
and the f64 instance then converted its `x` from i32. The row key was right; the layout was not.
