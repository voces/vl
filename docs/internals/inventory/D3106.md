### D3106 — a list literal joining a type parameter with a concrete element, passed to a concrete list parameter, is not refused at a pin that makes it a union

**closed 2026-09-30 — now a loud check reject at the pin, `argument of type (string | i32)[] flows into `sum` expecting i32[]` · was check-clean invalid wasm · clause 1 · closed by D3253's composite-argument demand (`ACF_COMP`): a list argument carrying a hole is re-asked by its node at the pin; `f(3)` still prints `10` · found by #3275's review · filed 2026-09-28 against master `d408f2da4`**

Repro:

    function sum(xs: i32[]) { let s = 0; for e in xs { s = s + e }; return s }
    function f<T>(x: T) { print(sum([x, 7])) }
    f("s")
    // vl check: rc 0.  vl run: invalid module inside `f`

#### Mechanism

The body types `[x, 7]` as `T[]`, since joining a type parameter with `i32` collapses to the
parameter ([D3079](D3079.md)), so the argument records no constraint the `string` pin can refuse
and the instance hands a `string` list to `sum`. The direct twin `function f(x: string)` is refused:
`argument 1: expected i32[], got (string | i32)[]`. The owed outcome is that refusal. It shares
D3079's collapse, whose fix waits on the owner's ruling on whether a union holding a type parameter
stays gradual.
