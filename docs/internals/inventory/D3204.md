### D3204 — a hole or generic body reads a member through a record field typed `H | null` at a pin, which the direct spelling refuses

**loads then traps · clause 1 · open, parked with its price named (`d3204-memread-price`) · pre-existing, the same on master `94670f728` · found by the NF lane's grid (the `NR` field spelling) · filed 2026-09-29 against master `94670f728`**

Repro:

    type H = { v: i32 }
    type R = { h: H | null }
    function F(z) { print(z.h.v) }
    const r: R = { h: null }
    F(r)
    // vl check: rc 0.  vl run: wasm trap, null reference

#### Mechanism

The direct spelling, `function F(z: R)`, refuses `member access '.v' on non-object H | null`.
A member read off an inference hole grows the hole's shape (`holeMemberTy`), and a read off an
unbounded `<T>` records a `memCstrTy` row, but a read off a hole's own FIELD (`?fld.h.z`) did
neither check at the pin: the argument check compares the parameter's shape, not a field's, so
`H | null` reached `.v` and trapped on `null`. The parked candidate recorded the row for a read off an `HD_FLD` hole,
and the pin refuses it by `memberFloorMsg`, as a first-level read of a `| null` pin is refused.
A null test on the field narrows it (D3197's `placeFieldTy` arm), so a guarded read still runs. An `is` test's else arm reads the pin's remainder, whose reads are re-asked the same way (D3216).
