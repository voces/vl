### D17071 — the IR reads a `{ f: null }` view's field at `null` where its record's row stores the field as a union box

**closed 2026-11-23 by lane IR-N9 (batch 7): a union-box field read whose tail leaves the box (`unionBoxTailLeavesBox`) is built at the field's storage rep, so `print`'s union arm takes that box; runs today and must keep running · filed 2026-11-23 against master `d699cfc48` by lane IR-N8**

Repro:

    type J = { f: i32 | null }
    function mk2() { return { f: null } }
    const dA: J = mk2()
    const src = [mk2()]
    function show(z: { f: null }) { print(z.f) }
    const s = src.filter((y: { f: null }) => {
      show(y)
      return true
    })
    print(s.length)
    // VL_IR_SHADOW=1 vl build: `show` is `uncovered print operand rep`

Want:

    null
    1

#### Mechanism

`const dA: J = mk2()` gives `mk2()`'s record J's row, whose `f` is stored as a union box. In
`show`, reached through the `filter` callback, legacy's `printArmOf` answers `union` from that
stored box (`exprIsNulNone` is false), while the IR builds `z.f` as `RGetField` at the node's type
`null`: the receiver's record rep has a `null` kid the row does not store. The fix is the read at
the field's storage rep, or the view's record rep following the row; either is a rep-layer change.
