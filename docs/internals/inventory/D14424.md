### D14424 — a call through a choice of hole functions used as a statement leaves the set untagged, so it still needs the call-site pin

**runs today and must keep running · refutation pin for the holes-close pin-caller deletion · found grading holes-close with `monoCallIfBound` and `monoIfBoundRetAtPin` removed · filed 2026-10-27 against master `ad860e97d`**

Repro:

    function apply2(g) { print(g + 2) }
    function apply3(g) { print(g + 3) }
    const c = [1].length == 1
    const f = if c { apply2 } else { apply3 }
    f(1)
    // today: 3.  with both pin callers removed: emit reject at 4:7, cannot take the generic function `apply2` as a value

#### Mechanism

The call `f(1)` stands as a statement and its members return nothing. With the pin callers
removed the set {apply2, apply3} is not tagged, so `f` reaches the emitter as a hole function
taken as a value, which only the 0-CFA pin gives a signature. The same members returning a
value, with the call printed, are tagged and run. Which of the two ingredients `ftScan`
refuses (the statement position or the `void` result) is not yet ablated.
