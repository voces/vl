### D2272 — an un-annotated if-join of `T[]` values in a generic body binds an i32 cell at `T = i32`, `i64` or `f64`

**check-clean invalid wasm · clause 1 · found in review of #3094 (reviewer probes m2, a7, g_*) · filed against master `6bfe5e770`**

Repro:

    function t() { 1 == 1 }
    function ops<T>(xs: T[]): T[] {
      const c = if t() { xs } else { [] }
      c
    }
    print(ops([1, 2]).length)
    // vl check: rc 0.
    // vl run: invalid module inside `ops` — expected i32, found (ref $type).

#### Mechanism

Inside the instance, the join's recorded type is the hole's, and neither `exprArray` (no
arena opener, no `IfStmt` arm) nor `exprF64Array` / `exprI64Array` (whose opener reads
`tyKindOf` and does not resolve the pinned hole) names the list. The local therefore takes the
i32 cell. The f32 and string instances run: `exprListRep` resolves the pin through `repOfTy`,
and `exprStringArray` has an `IfStmt` arm. This is a prediction for the list-rep campaign's
next steps: moving each remaining predicate onto `exprListRep` should close its kind. Grade
this row when that happens rather than assuming it. The price of #3094: a program whose f32
instance used to refuse loudly (`an f32[] return must be annotated`) beside an f64 or i32
instance of the same generic now reaches this row's invalid wasm (reviewer probes a4, a5).
That is loud to silent, with 0 runs lost.

#### Ablation

| ingredient changed | outcome | needed? |
| --- | --- | --- |
| `const c: T[] = …` (annotated) | runs | **yes** |
| `else { xs }` instead of `else { [] }` | still invalid | no |
| monomorphic `xs: i32[]` | runs | **yes** |
| `T = f32` or `T = string` | runs | **yes** (the kind) |
| inferred-return spelling `join<T>(c, xs) { if c { xs } else { [] } }` | still invalid | no |
