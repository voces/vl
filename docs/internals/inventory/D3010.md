### D3010 — a `let` a delivery re-seats at a wider declared record is reassigned a record that is not a fresh literal

**closed by design · now a loud check reject · was a loud emit refusal · the owner's record-covariance ruling refuses it: a `let` assigned an existing record holds more than a literal, so it is not fresh · closed 2026-09-30**

Repro:

    type D = { v: f64 }
    const x = 3
    const c: {[string]: D} = Map()
    let o = { v: x }
    c["k"] = o
    const q: {v: i32} = { v: 5 }
    o = q
    print(o.v)
    // vl check: rc 0.  vl run: emit error — this record is handed on here at its own type

#### Mechanism

The map store re-seats `o`'s literal at `D`, so the `let o` slot holds `D`'s record. `q` is
already built at its own `{v: i32}` record, and a record is shared, not converted, so the
assignment cannot land in that slot. The D2933 walk ignored a store INTO the binding
(`o = q`), so the slot got the wrong struct: invalid wasm. It now asks that the stored
record be a fresh literal, a literal-bound name (which follows the slot, [D3008](D3008.md)),
or already of the slot's row (`rsAssignIntoSafe`), and refuses otherwise with the walk's
existing message. Whether a non-fresh record may be converted at such a delivery is D2996's
open question; this row is the same question at a reassignment.

#### Grading list

The same shape with the stored record a parameter or a call result, and a bare-name store
`slot = o` of a parameter `o` into an annotated `slot: D` (invalid wasm on master and here,
D2996's annotated-position face).

#### Close (2026-09-30)

Closed by the owner's record-covariance ruling (DECISIONS.md "Record covariance: only a fresh value widens"): a `let` assigned an existing record holds more than a literal, so it is not fresh. The refusal names both fixes, building the source at the wider record or copying it with an object literal, so no program the design permits is refused.
