### D3960 — a `let` seeded with a generic function accepted a concrete function and was then called at another type

**closed 2026-10-10 by lane CK · now a loud check reject · was check-clean silently wrong (and `loads then traps` at a reference argument) · clause 1 · found in review of #3498 (`rv3498/z24`, `round4/c02`, `z07`, `z09`, `z10`, `z11`) · filed 2026-10-10 against master `eb81bdd89` · pins: `tests/cases/functions/error-let-of-generic-written-concrete-called-at-other-type.vl`, `tests/cases/functions/error-let-of-generic-written-in-closure-called-at-other-type.vl`, `tests/cases/functions/error-let-of-generic-called-before-concrete-write.vl`, `tests/cases/functions/error-let-of-generic-written-concrete-delivered.vl`, `tests/cases/functions/error-let-of-generic-written-concrete-in-generic-instance.vl`, `tests/cases/functions/error-let-of-generic-two-concrete-writes.vl`, `tests/cases/functions/let-of-generic-written-concrete-runs.vl`**

Repro:

    function inner<U>(u: U) { print("I"); print(u) }
    function q(n: i32) { print("Q"); print(n) }
    function main() {
      let k = inner
      k = q
      k(true)
    }
    main()
    // vl check: rc 0.  vl run: prints `Q` then `1`; with `k("s")` it traps, indirect call type mismatch

#### Mechanism

`let k = inner` binds `k` at `(U) => void`, and a type parameter is gradual, so the write
`k = q` of an `(i32) => void` was accepted and every later call through `k` was checked against
`(U) => void` at whatever type it passed. The binding holds one function at a time (the emitter
already refuses one called at two types), so after the write a call at `boolean` reached `q`.
The checker now groups such a binding with its un-annotated aliases (`fsbMark`): the first
concrete function written to the group fixes its type, a later concrete write must fit it, and
every call through it and delivery of it is graded against that type, including uses checked
before the write was seen (`fsbNoteStore`). An argument typed by an enclosing type parameter is
re-asked at each instance (`noteLetCstr`), so `a<T>`'s body is refused at `a(true)`. This is the
literal-binding ruling's shape for a function value: a `let` is typed by what is stored in it.
