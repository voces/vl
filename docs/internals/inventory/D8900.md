### D8900 — a hole's parameter is pinned at a declared record that boxes its field when the argument is a builder call whose literal has its own row

**check-clean invalid wasm · clause 1 · open · present on master `54684861f` · found closing [D8682](D8682.md) · filed 2026-10-21 against master `54684861f`**

Repro:

    type J = { f: i32 | null }
    function bump(n) { return { f: n + 1 } }
    function take(a) {
      const v = a
      print(v.f + 1)
    }
    take(bump(4))
    // vl check: rc 0.  vl run: the emitted module failed to validate inside `take`: expected i32, found (ref $type)

Want:

    6

#### Mechanism

Mono pins `take`'s hole parameter from its argument. For a call argument it reads the
callee's return row (`monoArgTyNameRep` → `structIndexOfExpr`, `emit_mono.vl`), and at that
point the only row with `bump`'s field names is `J`, so the instance's parameter is `J` and
`v.f + 1` reads a box. The checker binds the hole at `{ f: i32 }`. Neither D8680's row rule nor
D8682's own-row mint reaches it, because the pin is made before the literal's own row exists.
The close is in mono's argument pin.
