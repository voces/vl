### D3927 — two nested generics in different functions that share a type-parameter name share its binding, so a valid program is refused

**loud check reject · clause 2 · found closing D3902 (`d3902/b/b5_two_k`, `b8`–`b11`) · filed 2026-10-09 against master `255fc7a6c`**

Repro:

    function call(f: (n: i32) => void) { f(1) }
    function outer(x: i32) {
      function inner<U>(u: U) { print(x); print(u) }
      const k = inner
      call(k)
    }
    function firstOther(x: i32) {
      function inner<U>(u: U) { print(x); print(u) }
      const k = inner
      k("first")
      call(k)
    }
    outer(7)
    firstOther(7)
    // vl check: argument 1: expected (i32) => void, got (string) => void (at `outer`'s `call(k)`)

Want:

    7
    1
    7
    first
    7
    1

#### Mechanism

Not located. `firstOther`'s call `k("first")` binds its nested generic's `U` to `string`, and
`outer`'s alias of its own nested generic, whose parameter is also spelled `U`, is then checked as
`(string) => void`: the two declarations' type parameters are told apart by name only.

#### Ablation

| ingredient changed | outcome | needed? |
| --- | --- | --- |
| `firstOther`'s parameter renamed `V` | runs | **yes** |
| `k("first")` removed | runs | **yes** |
| `k(9)` (an `i32`) instead | runs | **yes** |
| the nested functions or the aliases renamed | refuses the same | no |
| the enclosing functions generic | refuses the same | no |
