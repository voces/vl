### D4135 — a generic record parameter with a literal-typed field refuses at emit for every instantiation

**loud emit reject · filed 2026-10-11 against master `3096c492f` · found by the #3557 review (`rv3557/r2/c/generic_rec_2_ctl`)**

Repro:

    function h<T>(a: { k: "a", v: T }): T { return a.v }
    print(h({ k: "a", v: 8 }))
    // vl check: rc 0.  vl run: emit error, `a record argument's fields name a row that holds another field kind, and a record is shared rather than converted`

#### Mechanism

The literal argument infers `k: string`, the parameter declares `k: "a"`, and monomorphizing `h`
at `T = i32` builds the instance's record row from the parameter while the argument's row holds
a `string` in that field. The emitter finds two rows that disagree about one field's kind, has
no converting copy for a record argument, and refuses. With `k: string` on the parameter, or no
`k`, the two rows agree and the program runs. A program `vl check` accepts, so a clause-2
violation by construction.

#### Ablation

| ingredient changed | outcome | needed? |
| --- | --- | --- |
| `k: string` on the parameter | runs, prints 8 | **yes** |
| no `k` field at all | runs | **yes** |
| `h` not generic (`v: i32`, returns `i32`) | runs | **yes** |
| `h` returns `1` instead of `a.v` | runs | **yes** |
| `T` written explicitly (`h<i32>(...)`) | same emit refusal | no |
| `k: "a" \| "b"` or `k: 1` on the parameter | same emit refusal | no |
| a second call at `T = string` | same emit refusal | no |
| argument bound first as `const x: { k: "a", v: i32 }` | runs | **yes** (a literal argument) |
| parameter spelled through `type R<T> = { k: "a", v: T }` | emit refusal, `monomorphize: unsupported argument type for \`a\`` | different message |

#### Grading list

The alias spelling `h<T>(a: R<T>)` (a different emit message, likely the same row), the
`string`-instantiated call, and the extra-field spelling `h({ k: "a", v: 8, w: 2 })`, which
refuses at emit with `field access receiver is not a struct`.
