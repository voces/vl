### D3100 — an empty list literal filled by `push` of a type parameter keeps the default `i32` element at an `f64`, `i64`, list or record pin

**closed 2026-09-28 — the filed repro prints `1` · was check-clean invalid wasm, clause 1, and a loud emit reject for a relayed `string` pin · closed by annotating, per instance, an un-annotated binding of an empty literal whose element a `push` pinned to a type parameter with that list at the pin (`monoPushedListAnn`); independent of [D3079](D3079.md), which stays open · every `f64`, `i64`, list, record and relayed pin of lane GV's push shapes runs and prints what its direct twin prints · fixture `tests/cases/generics/empty-list-pushed-type-param-pins.vl` · filed 2026-09-28 against master `e1e40ac99`, closed against master `d408f2da4`**

Repro:

    function f<T>(x: T) {
      const l = []
      l.push(x)
      print(l.length)
    }
    f(1.5)
    // vl check: rc 0.  vl run: invalid module inside `f`

Want:

    1

#### Mechanism

Not localised past the ablation. The direct spelling `function f(x: f64)` runs and prints `1`,
so the empty literal's element is pinned by the push there. Inside the instance every failing
pin reads `expected i32`: the list is built at the default `i32` element and the pushed value
is not one. `boolean` and `string` pins run called directly, so it is not simply every
non-`i32` pin, but a `string` pin relayed through a second generic is refused at emit
(`emitProgram: string array literal but string list type not collected`), clause 2.

| --- | --- | --- |

| `f(3)`, an `i32` pin | prints `1` | **yes** (the pin's type) |

| `f(r)` with `r: R` a record | invalid wasm | no |
| `f("s")` reached through `function mid<T>(x: T) { f(x) }` | loud emit reject | no |

and must keep running.
