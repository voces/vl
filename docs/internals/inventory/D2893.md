### D2893 — in a generic body, a value `if` joining a type parameter with a literal of another type is invalid at a string pin

**check-clean invalid wasm · clause 1 · found by the generic-join grid of the D2876 lane · filed 2026-09-27 against master `d39c809c1`**

Repro:

    function f<T>(t: T, c: boolean) {
      const u = if c { t } else { 5 }
      print(u)
    }
    f("z", false)
    // vl check: rc 0.  vl run: invalid module — expected (ref $type), found i32

Want:

    5

#### Mechanism

Not localised past the ablation. Inside the body the parameter is assignable either way, so the
join is recorded as the parameter's arm (`T`) rather than `T | i32`, and at the `string` pin the
`5` arm is lowered into a string blocktype. At `boolean` the same join prints `1` for `true`
beside a literal arm (`f(true, true)`), and a `"s"` arm beside `t` is invalid at every
non-string pin.

#### Ablation

| ingredient removed | outcome | needed? |
| --- | --- | --- |
| the type parameter (`t: string`) | runs, prints `5` | **yes** |
| the binding (`print(if c { t } else { 5 })`) | invalid wasm | no |
| the value `if` (`if c { return t }` then `5`, a return set) | runs | **yes** |
| an annotation (`const u: T \| i32 = …`) | runs | **yes** |

#### Grading list

The same join at `boolean` (`f(true, true)` must print `true`), `if c { 5 } else { t }`, and
`if c { t } else { "s" }` at `i32`, `f64` and `boolean`.
