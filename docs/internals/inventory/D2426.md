### D2426 — an un-annotated lambda handed to a type-parameter arrow parameter has no monomorphization pin

**loud emit reject · clause 2 · found grading D2344, filed 2026-09-25 against master `a277bf7b0`**

Repro:

    function ap<T>(f: (T) => T, x: T): T { return f(x) }
    print(ap((v) => v + 1, 3))
    // vl check: rc 0.
    // vl run: emit error, emitProgram: monomorphize: unsupported argument type for `f` in a
    // call to `ap`.

#### Mechanism

Not yet located past the refusing rung. `monoInstantiate` pins an arrow parameter riding the
callee's type parameters from `monoArgFnTypeName(args[i])`, the argument's function-type name.
An un-annotated lambda's parameter is a hole the checker solved from the call (`v: i32`, since
`x` binds `T`), but the name the pin reads still carries the hole, so it answers "" and the rung
refuses. The pre-binding pass that binds `T` from the other arguments first runs only for a
generic function VALUE (D58), not for a lambda.
