### D4854 — a captured walk variable over a local box-element list literal is typed from the literal's first element

**closed · the list rep of a node whose element type is a value union the checked-rep column boxes is the ref list (`valueUnionBoxList`), and `forInElemKind` binds a box-element list built at its destination's row as the box · fixture `tests/cases/closures/capture-walk-variable-box-list-literal.vl` · was check-clean invalid wasm · clause 1 · found by L2 §13.29's residue probe · filed and closed 2026-10-15 against master `a33e5643a`**

Repro:

    function u() {
      const vs: (string | i32)[] = [3, "a", "b"]
      for e in vs {
        const f = () => e
        print(f())
      }
    }
    u()
    // vl check: rc 0.  vl run: invalid module inside `u`: type mismatch: expected i32, found
    // (ref $0); $0 is `union box`

Want:

    3
    a
    b

#### Mechanism

A capture's env field is typed outside the frame's emission, so `frameBlindIter` re-asks the
local iterable `vs` through its initializer, and `forInElemKind` classified the literal by
the list-rep ladder. That ladder read the literal's first element: `3` gave the i32 list and
`1.5` the f64 list, so the field was a scalar while the loop variable is the box. A first
element `"a"` gave the string list, which typed the field right only for the string member.
The literal is built at the annotation's row, which its own spelling `(i32 | string)[]` does
not name, so the ref-list slot lookup missed too.
