### D3272 — a constant computed from other constants is refused as a `match` arm though the emitter folds it

**loud check reject · open, clause 2 by the owner's own ruling (a folded constant should be an arm) · filed 2026-09-29 against master `569caa36c`**

Repro:

    const A = 1
    const B = A + 1
    function f(k: i32) {
      match k {
        B => "two"
        _ => "other"
      }
    }
    print(f(2))
    // vl check: a match arm needs a literal or a constant; `B` has no literal value — declare it with a number or string literal, or test it with `==`

Want:

    two

#### Mechanism

The ruling on PL-062 admits a constant computed from other constants when the compiler already
folds it. #3262 folds exactly that, but in the EMITTER (`constFoldOfLet`, `emit_query.vl`), after
the checker has finished; the checker keeps no constant-value scope (D1588), and the arm's value
is needed at check time for the duplicate check, literal-union membership and exhaustiveness.
A const's operands must also resolve where the const is DECLARED, not where the `match` stands,
so a second fold written against the checker's live scope would read a local that shadows the
operand. Recommendation: move the integer constant evaluator to one checker-visible home keyed by
declaration (module consts first), have `constFoldOfLet` read it, and let `matchConstPatWhy` accept
any `const` it answers; `const A2 = A` (an alias) is the one-step case of the same fix.

#### Ablation

| ingredient removed | outcome | needed? |
| --- | --- | --- |
| the operator (`const B = 2`) | runs | **yes** |
| the operand being a constant (`const B = 1 + 1`) | still refused | no |
