### D8944 — an un-annotated function handed to `.map` over a list is refused at emit

**closed · runs, prints `4` · was loud emit reject, `emitProgram: index receiver is not an array or string` · clause 2 · filed 2026-10-21 against master `30ff8d9b5` · closed by the checker typing the callback's result at the list's element (`memberCallMapFilterTy`, check_member_call.vl) and the monomorphizer taking the callback's instance there (`monoCoerceListCbArg`, emit_mono.vl) · fixtures `closures/hole-fn-as-list-callback-result.vl`, `closures/error-hole-fn-list-callback-ill-typed-at-element.vl`, matrix `hole-fn-as-list-callback-result`**

Repro:

    function inc(a) { return a + 1 }
    const r = [3].map(inc)[0]
    print(r)
    // vl run: emitProgram: index receiver is not an array or string

#### Mechanism

Two halves. The checker typed `.map(inc)` as `_[]`, the open result of `inc`'s own
`(_) => _`, so nothing downstream knew the list's element. It now reads the callback's result
at the receiver's element and judges the body there, so an ill-typed body (`"v" + a` at
`i32`) is refused as the direct call `tos(3)` is, rather than reaching emit. The monomorphizer
never took an instance of the callback, so its value had no signature; it now takes the
instance at `(elem) => result` (`boolean` for `.filter`), as a lambda's contextual type does.
