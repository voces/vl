**runs today and must keep running · refutation pin for the literal-atom Ident arms reading the binding storage column · filed 2026-10-27 against master `c073bbc52` plus #5047**

#### Mechanism

`bindCellRep`, the per-declaration storage column, declined every literal-union binding, so
`letLocalSlot` stored one by two rungs of its own and the literal-atom Ident arms
(`exprIsLitAtomIdent`, `exprNulLitUnion`) asked a third ladder. Where the ladders disagreed the
program still ran, because each arm happened to agree with the storage it read. Two
measured shapes:

* (B) storage is the atom, but the `K | null` arm asked only `letNulLitUnion`, which misses an
  un-annotated binding whose initialiser is an atom: `r` above at each instance,
  `literal-unions/length-and-hole-coalesce-default`, and the module-level `t`/`__c` of
  `unions/arm-local-chain-join-nullable-litunion`.
* (C) the synthetic loop-value binding of `loops/loop-value-reps` is stored as the niche atom
  while the arm read it as not nullable.

The fix makes the column the one producer of literal-union storage (the i32 atom, nul 3 for
the `K | null` niche) and has both arms read a `let` by its declaration: the slot the frame
being emitted collected for it, else the column. The shadow comparison of each arm against
the column reads zero disagreements on `let` reads afterwards.

`literal-unions/is-literal-set-overlap-narrows-to-meet` is the one place where storage and
the narrowed type disagree by design. The narrowed read of a `string`-declared `J` has a
literal-union type, but the binding is stored as a string, so the column is the right
criterion and the arm answers "not an atom".

`literal-unions/shadowed-atom-widen-reserves-frame` closes with the same change. Its
first-match slot scan resolved the outer `v` of a shadowed pair, and the read by declaration
picks the inner `v: K`.
