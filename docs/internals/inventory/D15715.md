### D15715 — a maker's call delivered where a field is a wider nullable number has no converting copy and is refused

**closed 2026-11-11, runs and prints `4` then `4` · was a loud check reject, clause 2, `{f: i32} is not K: they store field \`f\` differently (\`i32\` into \`i64 | null\`)` · closed by the copy gate (`recCopyBoxesOnly`, `recNumWidens`, check_fit_rules.vl; `rcWrapKind`, `rcWidenTo`, wasmEmit.vl): a number copied into a nullable of a number it widens to exactly is converted, then boxed under the wider tag · graded by `scripts/capability-probes/matrix/kept-maker-delivery-width.matrix.vl` · a binding of the call read at its own type is [D15716](D15716.md) · found closing D15691 · filed 2026-11-11 against master `161d481c`**

Repro:

    type K = { f: i64 | null }
    function mk() { { f: 4 } }
    const a: K = mk()
    const b = mk()
    print(b.f)
    print(a.f ?? 0)

Want:

    4
    4

#### Mechanism

Not ablated. The fresh-call copy boxes a scalar only into its own nullable (`recCopyBoxesOnly`),
and the width copy (`recCopyConverts`) refuses a nullable field, so neither serves `i32` into
`i64 | null` and `recWidthCopyGapErr` refuses the delivery. A relay of the call (`relay()`, D14516)
refuses the same way.
