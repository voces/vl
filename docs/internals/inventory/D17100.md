### D17100 — a choice of two functions whose closed results differ is a union of function types, and no call through it checks

**runs, prints `s` — CLOSED 2026-11-28 by CENSUS: two functions of known sets whose closed results differ join as one function type at the join of their results, carrying both sets (`fnSetResultJoin`, check_relate_core.vl), so a call through the choice dispatches on the member (DECISIONS, D15791); pinned by `tests/cases/closures/choice-of-closed-differing-results-dispatches.vl`. An untagged choice delivered to a closed function type is D17104 (M2). Was: loud check reject · clause 2 · beside [D17098](D17098.md) and [D16094](D16094.md) · owner S2 · filed 2026-11-24 against master `1603ddda`**

Repro:

    function str(_a) { return "s" }
    function bo(_a) { return true }
    function run(c: boolean) {
      const g = if c { str } else { bo }
      print(g(3))
    }
    run(true)
    // vl check: called value is not a function (((_) => string) | ((_) => boolean))

Want:

    s

#### Mechanism

Where one member's result is open (`inc`, `a + 1`), the choice is a set and a call through it
dispatches (D16094). Where every member's result is already closed and they differ, the `if`
joins the members into a union of function types, which the call checker does not treat as
callable. The refusal names the join's representation, not a contract.

#### Ablation

| ingredient | outcome |
| --- | --- |
| `bo` returning `2.5`, or `str` returning `9` | still refuses |
| members annotated `(_a: i32): string` and `(a: i32): i32`, called through `ap(g, 3)` | still refuses |
| one member returning `_a + 1` (open) | runs |
| both members returning one type | runs |
| a third, open member, `if c { str } else if d { bo } else { inc }` | loud check reject, `cannot choose 'bo' here` |

#### Grading list
