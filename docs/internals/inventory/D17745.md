### D17745 — a concrete function stored into a binding annotated with a type parameter that a call leaves generic is accepted by the checker

**loud emit reject · clause 1, `vl check` accepts a program the design refuses (T9.3) · `emitProgram: the compiler cannot yet lower this statement (rep ?)` · filed 2026-11-27 against master `ff6ec607b` by lane CENSUS · found beside D17321**

Repro:

    function same<T>(k: T): T { return k }
    function inc(k: i32): i32 { return k + 1 }
    function mid<F, G>(a: F, a1: G) {
      print(a("x"))
      print(a(1))
      let b: F = a1
      print(b(2))
    }
    mid(same, inc)
    // vl check: rc 0.  vl run: emit error at 7:13, "the compiler cannot yet lower this statement (rep ?)"

Want:

    vl check: rc 1, a refusal naming T9.3 at `let b: F = a1`

`F` is called at `string` and at `i32`, so the call binds it to `same`'s generic type, and a
concrete `(i32) => i32` may not be stored in a binding of a generic function's type.

#### Mechanism

At `mid(same, inc)` the checker binds `F` to `same`'s type and `G` to `inc`'s. A body call of
`F` at two types keeps `F` generic, but the annotated `let b: F = a1` is graded at the
assignment of `G`'s bound type to `F`'s, which a generic type accepts from its instance at
`i32`. The un-annotated module-scope spelling (`let g = same; g = inc`) is refused by T9.3's own
rule; the type-parameter spelling reaches no such rule, so the program passes check and the
emitter finds no rep for `b`.

#### Ablation

| --- | --- | --- |
