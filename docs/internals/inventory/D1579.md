### D1579 — the CROSS-TABLE layout guard declined every arm carrying a ref the field code does not name, so a union arm with a struct-typed field had no rep as another struct's field

**closed 2026-09-04 — the repro now RUNS. Was: loud emit reject, `emitProgram: a struct field typed as the union ARM \`A\` has no field rep` · reported by the glean session, VL-032, `~/glean/docs/vl-issues.md`**

Repro:

    type Inner = { base: i32, length: i32 }
    type A = { n: i32, inner: Inner }
    type E = { msg: string, line: i32 }
    function make(): A | E { { n: 3, inner: { base: 0, length: 1 } } }
    type S = { a: A, p: i32 }
    function use(s: S) { s.a.n + s.a.inner.length }
    print(use({ a: { n: 3, inner: { base: 0, length: 1 } }, p: 1 }))
    // vl check: rc 0.  Was: loud emit reject at 5:5.  Now prints 4.

#### Mechanism

D1518 gave a union ARM a struct-table row — `collectS` SKIPS a `type X = {…}` that is a union
member, so the arm's own canonical render is MINTED as an anonymous row and
`variantStructHeapTwinAt` merges the two. That comparator's per-field layout guard then
declined outright on any field code whose emitted storage is a ref the CODE does not name
(15 a nested struct, 5 a ref list, 28 its `| null` niche), so an arm carrying one shared a heap
with no struct row at all and a field typed as that arm had no rep.

**Both sibling comparators already descended.** `structFieldCodesEq` does it for the struct⇄struct
seam and `variantFieldLayoutEq` for variant⇄variant; only the CROSS-TABLE one asked the code
alone. The fix gives it the same two rungs its siblings use — `repStructSlotsTwin` over the
code-15 targets, `rlSlotsLayoutTwin` over the 5 / 28 slots — and `sFieldRefSlot` moves from
`wasmEmit.vl` to sit beside `variantFieldRefSlot`, since the guard now asks both about one
field position.

**The two sides spell one field differently, which is why the code alone cannot answer.**
Measured at the refusing site on an instrumented seed, for the repro:

| | row | field 0 code | field 0 elem name | field 1 code |
| --- | --- | --- | --- | --- |
| variant `A` (vi 0) | `repSlotOfTy` −1, `repRowOfTyStruct` **1** | 15 | `Inner` | 0 |
| its minted anon row (si 1) | `{n:i32,inner:{base:i32,length:i32}}` | 15 | `{base:i32,length:i32}` | 0 |

Struct table at that moment: `0:{base:i32,length:i32}` `1:{n:i32,inner:{base:i32,length:i32}}`
`2:Inner` `3:S` (in flight, `sFieldCount` −1). The codes AGREE; row 2 and row 0 are layout
twins; nothing was missing but the descent.

`wasm-dis` on the built module, which is what says the merge cost no heap type:

    (type $0 (struct (field (mut i32)) (field (mut i32))))            ;; Inner AND its anon twin
    (type $1 (struct (field (mut (ref null $0))) (field (mut i32))))  ;; the ARM and its mint
    (type $2 (struct (field (mut (ref null $1))) (field (mut i32))))  ;; S — `a` IS the arm's heap

**The `collectU` face needed the mirror.** `armFieldDeferredRowOk` answers the same question one
phase early, for a field on a declaration that is ITSELF an arm, and its `armPlainLayoutShapeOk`
applied the same 5 / 15 / 28 decline. It now routes those codes — and the `-1` an inline shape
carries before it is interned, which is what `tyToEmitName` writes for a declared target —
through `armRefFieldLeafOk`, the peel `internArmShapeAt` already uses. Without it the repro's
declaration order ran and the swapped one did not, which is D1518's own two-orders-two-sentences
shape one level deeper.
