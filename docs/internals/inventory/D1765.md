### D1765 — the module-global kind ladder asks its niche rungs before its union rung, so a box-joining `??` took the operand's niche cell

**closed 2026-09-06 · was check-clean invalid wasm · filed against master `e9c5665c6` ·
0 corpus cells**

Repro:

    type A = { r: i32 }
    type B = { s: i32 }
    type Sh = A | B
    function lhs(): i32[] | null { return null }
    function dflt(): A | null { return { r: 7 } }
    const v = lhs()
    const w = v ?? dflt()
    if w is A { print(w.r) } else { print(0) }
    // prints 7

#### Mechanism

`globalCellKindGo`'s UN-ANNOTATED ladder runs `letIsNulRefArray` and `letIsNulListInfer` before
its union rung, and both read the `??`'s OPERAND alone — their own comments claim "only
nullability changes", which is false the moment the DEFAULT is of another type. The join
`i32[] | A | null` is the union box, so the global took a `(ref null $wrapper)` cell while the
lowering built the box. Measured 2026-09-06, `globalCellKind` instrumented on a `??` init:

| cell | kind chosen | `joinsBox` | result name |
| --- | --- | --- | --- |
| nullable-collection operand, nullable-variant default | `nullist` | 1 | `i32[]\|A\|null` |
| the same with a NON-null default | `union` | 1 | `i32[]\|A` |

Every input the union rung needs was already resolving — `coalesceNicheJoinsToBox` answered 1
and the name rendered — and a rung above simply answered first. The FUNCTION-frame ladder asks
its union rung earlier and was right all along, which is why only the module spelling failed.
The fix asks the lowering's own question (`coalesceNicheJoinsToBox`) ahead of the niche rungs,
so the cell and the lowering cannot disagree about what the join reps as.

The `exprArray` / `exprRefArray` `??` legs carry the same false claim in their comments and
are INERT for this cell: gating them moves nothing, because the ladder rung is what answers.
