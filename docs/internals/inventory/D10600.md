#### Mechanism

At a list pin the `??` default is not dead (D2951 drops it only at a primitive pin), so the
checker's `coalJoinAtPin` and the emitter's `holeCoalReadAt` both give `a ?? 5` the join
`i32[] | i32`, and the call site reads the box. The instance's re-check and `monoInferListElem`
gave it `i32[]`, so `monoCloneLetDecl` annotated the binding `i32[]` and the instance returned a
bare list. Before #4449 that disagreement refused loudly (`narrowed union atom has no value
box`). #4449's `exprUnionIf` arm made the bound `if` a box, while the binding, the early return
and the result stayed `i32[]`, and the twoNames and earlyR spellings became invalid wasm.

The close annotates an un-annotated binding of such a `??` with the pinned box, ahead of the
returned-local rungs (`monoCoalBoxBindAnn`). It also lets the D2895 result rung box a result
whose annotation names one member of the checked union (`monoRetNamesMemberOf`). A union `==`
against the parameter now classifies the concrete operand at its instance type, not at `T`.
