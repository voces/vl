### D1977 — the string pool decodes each distinct literal into ONE `i32[]` of code points, so a single literal past 2^23 code points traps the compiler

**closed 2026-09-30 — the literal is a data segment decoded piecewise, and the witness prints `8400000` (lane CT) · was compiler trap (`allocation size too large`, exit 70) · residue of D1976 · filed 2026-09-22 against master `48a295c72` plus D1976's fix**

Repro (one 8.4M-character literal, in an imported module so the entry stays small and the
compile keeps the null collector):

    // file: m.vl
    export function s(): string { "@@repeat(8400000, "a")@@" }
    // file: main.vl
    import { s } from "./m"
    print(s().length)
    // vl check: rc 0.  vl build / vl run: the compiler traps, exit 70

Want:

    8400000

#### Mechanism

`collectStrPool` (`emit_sections.vl`) decoded every distinct string literal with `strToCps`
(`emit_base.vl`), which pushed the literal's code points onto one `i32[]`. Under the null
collector one object is at most 64 MiB, so `.push`'s growth to 2^24 slots trapped once a single
literal passed 2^23 code points (`strToCps` ← `collectStrPool` ← `emitModule`).

A string literal past the pool's `array.new_fixed` cap (10,000 UTF-8 bytes) is now stored once
as a passive DATA SEGMENT and built at each evaluation by `array.new_data` (`emitStr`,
`wasmEmit.vl`; `strLitCollect`, `emitDataCountSection` and `emitDataSection`,
`emit_sections.vl`): the function body carries five instructions whatever the literal's length,
where it carried one `i32.const` per byte. The lexeme is decoded by `litUtf8` (`emit_base.vl`),
which is `cpsToUtf8(decodeStr(strToCps(lex)))` run over pieces of about 2^20 code points, cut
only where no escape can be open, into a packed `u8[]`, so no `i32[]` holds the whole literal.
A module with no such literal emits neither section and is byte-identical to before.

| characters | fuel before | fuel after | peak RSS after |
| ---: | ---: | ---: | ---: |
| 20,000 | 27,497,173 | 19,580,917 | 49 MB |
| 1,000,000 | 1,233,966,605 | 828,061,073 | 106 MB |
| 8,400,000 | trap | 5,392,964,355 | 448 MB |
| 20,000,000 | trap | 12,809,024,974 | 978 MB |

Linear: 2.38× the fuel for 2.38× the characters from 8.4M to 20M.

#### Grading list

- The decoded bytes are kept in parts of at most 2^24 bytes (`LIT_PART`), so no one `u8[]`
  holds them all: 40M characters in an imported module builds (25.9 G fuel, 1.9 GB peak RSS)
  and prints `40000000`. The next ceiling is the source text's own, 64 MiB under the same
  collector ([D1975](D1975.md)).
- A line continuation's indentation is left out of the piece it would fill, so a continuation
  followed by millions of spaces decodes in pieces too: `a`, a backslash-newline, 8.4M spaces
  and `b` in an imported module prints `2`.
- `tests/cases/literals/long-literal-chunked.vl` and `tests/cases/strings/literal-chunked-bytes.vl`
  now take the data-segment path.
