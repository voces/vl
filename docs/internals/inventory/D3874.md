### D3874 — a function with a parameter of its own name calls the PARAMETER, and the "always recurses" lint reads that call as a self-call

**lint false positive (no outcome word fits: `vl check` rc 0 and the program runs) · runs today and must keep running · found by the rv3455b review (t/c1a.vl) · filed 2026-10-08 against master `862c99b79`**

Repro:

    function f(n: i32, f: (a: i32) => i32) { f(n) }
    print(f(3, (a: i32) => a + 1))
    // vl check: rc 0, with
    //   [WARNING]: This function always recurses: every path through `f` calls it again, so the call never returns
    //   at 1:10 (the function name)
    // vl run: rc 0, prints 4

Want:

    4

#### Mechanism

The lint decides "every path through `f` calls `f`" by the callee's NAME, and inside the body `f(n)`
is the parameter `f`, which shadows the function. The program is not recursive: it prints `4`.
The grader has no outcome word for a warning on a program that runs, so this row is filed with
the pin vocabulary `runs today and must keep running`: the grader checks only that the witness
still runs and prints `4`. THE DEFECT IS THE WARNING, which the grader cannot see; the close has to
remove the warning on this witness and is checked by `vl check` on it, not by the gate.

#### Ablation

Every row is the witness with one ingredient changed; "outcome" is `vl check`.

| ingredient removed | outcome | needed? |
| --- | --- | --- |
| the name clash (function `g`, parameter `h`) | no warning | **yes** |
| the return annotation (`: i32`) | still warns | no |
| the type of the parameter (`(a: i32) => string`) | still warns | no |
| the type parameter added (`f<T>(t: T, f: (a: T) => T)`) | still warns | no |
| the nesting (`inner<U>` inside `outer`, with a parameter `inner`) | still warns, naming `inner` | no |
| the parameter, replaced by a local `const f` shadowing the function | still warns | no |
| an exit path (`if n > 0 { f(n - 1, k) } else { k(n) }`, parameter `k`) | no warning | n/a |
| the parameter (`function f(n: i32): i32 { f(n) }`, a genuine self-call) | warns, rightly | n/a |

#### Grading list

The genuine self-call (the last row) must keep warning. The local `const f` shadow is a second
delivery of the same name-based read; a close that resolves the callee to its binding fixes both,
one that only looks at the parameter list fixes the first.

A nested function named like its enclosing function is a third delivery: `function a<T>(x: T)
{ function a<T>(y: T) { print(y) }; a(true); … }` warns that `a` always recurses, though the call
reaches the nested `a` (`tests/cases/generics/nested-generic-named-like-enclosing-function.vl`
declares the warning, which a close removes).
