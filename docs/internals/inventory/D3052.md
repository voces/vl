### D3052 — a prefix `--` over a literal passes the checker, which owes its refusal, and the emitter refuses it instead

**loud emit reject · open · the same on master `0b618d160` and on #3265 · found by the #3265 review · filed 2026-09-28 against master `0b618d160`**

Repro:

    const g: i64 = --2147483648
    print(g)
    // vl check: rc 0.  vl build: emitProgram: only an identifier assignment is a value expression

#### Mechanism

`--2147483648` lexes as the prefix decrement over a literal, which desugars to an assignment
whose target is not a name. `vl check` accepts it (only a redundant-annotation hint), and the
emitter's value-assignment arm is the first place that notices the target is a literal. A
decrement needs a variable, so the checker owes the refusal, as it does for `x++` over a
non-variable. `-(-2147483648)` is the spelling of the double negation. This is a clause-2
violation by construction: a loud emit reject after a clean check.

#### Ablation

| spelling | outcome |
| --- | --- |
| `const g = --5`, un-annotated, small literal | same emit reject |
| `let y = 3` then `const g = --y` in a function | runs, `2` |
| `const g = -(-2147483648)` | runs, `-2147483648` (i32, no 64-bit destination) |

#### Grading list

`const g = --5`, and `--` over a parenthesised literal and over a call result.
