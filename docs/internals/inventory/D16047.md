### D16047 — an inferred union return with an unpinned collection hole in a member floors at check

**open · loud check reject · `` 'pick' infers the union return type {[_]: _}[] | {[string]: i32} — type-valid, but an inferred return of this shape is not yet supported by codegen `` · clause 2 · `[Map()]` returned alone runs · filed 2026-11-14 against master `d17f98725`**

Repro:

    function pick(c: boolean) {
      if c { return [Map()] }
      const m: {[string]: i32} = Map()
      return m
    }
    const r = pick(false)
    print(1)

Want:

    1

#### Mechanism

The list literal's element is an empty `Map()` whose key and value nothing pins, so the list
infers as `{[_]: _}[]`, a hole map. Returned alone it runs, built at the default rep its uses
settle. Joined into a union or a nullable return, the recorders `checkInferredReturn` consults
name it by its emitter render (`tyToEmitName`), which has no spelling for a hole, so every
recorder answers "" (a scratch probe: `mapUnionRetName` returns "" for the witness) and the
return floors. Its annotated twin, `: {[string]: i32} | {[string]: i32}[]`, runs. Any unpinned
collection hole in a member does the same: `[]`, `Map()` and `Set()`, at any depth.
