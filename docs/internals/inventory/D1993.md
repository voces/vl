### D1993 — an UN-ANNOTATED `const`/`let` initialiser accepts an if-expression typed `void | T`, so a void-call arm passes check and refuses at emit

**loud emit reject · `vl check` rc 0, clause 2 (the checker owes it) · residue of D1992 · filed 2026-09-22 against master `af07f4ae0`**

Repro:

    function v() { print("side") }
    function f(c: boolean) {
      const n = if c { v() } else { 1 }
      n
    }
    f(true)
    print("done")
    // vl check: rc 0.  vl run: 3:20: emitProgram: if-expression arm ends in a void call, which yields no value

#### Mechanism

The checker types the if-expression `void | i32` and refuses it by the SLOT that demands a value
(`tests/cases/expressions/void-if-arm-join-rejected.vl`): `print(…)`, `return …`, an annotated
`const n: i32 = …` and an assignment `n = …` all report `void | i32`. An un-annotated binding
initialiser demands nothing and adopts the type, so the program reaches the emitter, which has no
value to place for the void arm. The design owes the refusal (no value has a type mentioning
`void`), so this is a checker miss at one slot, not a capability gap.

#### Ablation

| spelling | outcome | slot demands a value? |
| --- | --- | --- |
| `const n = if c { v() } else { 1 }` | emit reject | **no** |
| `const n: i32 = if c { v() } else { 1 }` | check reject `cannot assign void \| i32 to 'n'` | yes |
| `return if c { v() } else { 1 }` | check reject `return expects a value` | yes |
| `n = if c { v() } else { 1 }` | check reject `cannot assign void \| i32 to i32` | yes |
| `const n = if c { 1 } else { }` (empty arm) | emit reject — D1994 | **no** |
