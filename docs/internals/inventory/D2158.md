### D2158 — spreading a literal-union list into a list literal beside a string builds an invalid module

**closed 2026-09-28 — the repro RUNS and prints `bb/bb/zz` then `true` · was check-clean invalid wasm inside `main` · closed by [D2868](D2868.md)'s string-list spread, which widens each atom of a literal-union list source to its member string · fixture `tests/cases/lists/spread-inline-litunion-atoms-beside-string.vl` · found by the #3056 review · filed 2026-09-23 against master `f81d01486`**

Repro:

    import { join } from "std:str"
    const Z = "zz"
    function kk(): "a" | "bb" { "bb" }
    function main() {
      const k = kk()
      const lits = [k, k]
      const sp2 = [...lits, Z]
      print(join(sp2.map((x): string => x), "/"))
      print(lits[0] == "bb")
    }
    main()

#### Mechanism

Not yet ablated. `lits` is the interned-atom list, and the spread literal joins its element with a
`string`, so the new list's element is `string` while the spread copies atom ids into it. The
validator's complaint is a heap-type mismatch inside `main`, which fits a copy that neither
widens each atom to its member string nor builds the atom list. D2868's close confirmed it: the
literal now builds at the string list and each atom group is copied through the widening tower.

#### Grading list

The same spread with a written alias (`type K = "a" | "bb"`), with `Z` removed (a spread of the
atom list alone), and `[...lits]` into an annotated `string[]`.
