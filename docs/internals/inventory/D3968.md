Repro:

    function inner<U>(u: U) { print("I"); print(u) }
    function main() {
      let k = inner
      k = (x) => { print(x + 1) }
      k(true)
    }
    main()
    // vl check: rc 0 before the fix.  vl run: prints `2`

#### Mechanism

A call through a binding re-asks the deferred constraints of the function the binding names, and
a `let` bound to a declared generic names that generic (`lookupFnAliasNode`), so `k(true)`
re-asked only `inner`'s. The lambda written to `k` keeps its body's `x + 1` as a constraint of
the enclosing function, which no call naming `inner` reads. Each function written to a binding
that keeps its generic type is now recorded with the owner of its constraints, and after the walk
every call through the binding re-asks them, its bindings joined by the written function's own
type variables, bound structurally through each parameter (`A[]`, `A | null`, `Box<A>`,
`() => A`) against the call's argument type at its position, and each argument is checked
against the parameter under those bindings (`fsbBindParams`, `fsbArgsFit`); the seed's own
type variables, which may share their names, are not bound (`fsbRecheckOne`). A written generic
function (`k = other`, with `other` doing `v + 1`) is re-asked the same way, and only its own
constraints are (`cstrOwnedStrict`). A call is re-asked at once against the writes already seen,
inside the generic body it stands in, so a pair over that body's type parameter defers to its
instances as a direct call's does; the writes seen later in that body (a loop's back edge) are re-asked when its walk ends, still
inside it, and those at module scope after the walk. A delivery
of the binding to a concrete function type is a call at that type's parameters, including as
an array literal's element or a record literal's field.

#### Ablation

| ingredient changed | outcome before the fix | needed? |
| --- | --- | --- |
| `let k = (y) => { print(y) }`, a hole-lambda seed | loud check reject | **yes** |
| at module scope | loud check reject | **yes** |
| `k(5)` | runs | **yes** |
| the call in a closure declared before the write | prints `2` | no |

#### Design price

Flow-insensitive: every function ever written to the binding is re-asked at every call through
it, so `k(true); k = plus; k(5)` is refused although `plus` never receives `true`. Nothing that
ran on the base is lost; such programs were check-clean and wrong or emit-refused there.
