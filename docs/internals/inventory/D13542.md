#### Mechanism

From the code path. The split runs the choice once before the statement holding its call
(`fsChoiceStmtOf`, fn_split.vl); a `while` runs its condition once per iteration, so a single
run ahead of the loop would choose once for every iteration, and the walk declines
(`fsRunsChildFirst`). The same walk declines a right side of `&&`, `||` or `??` for a choice
that calls, or whose condition reads an element or divides, since running it ahead would run
it where the source may not.
