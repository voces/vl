### D3457 — `?.` of a nullable scalar field through a nullable record, then `??`, builds invalid wasm

**check-clean invalid wasm · clause 1 · open · pre-existing, the same on master `028dedb33` · found by the #3325 review (the one loud → silent cell of lane RC3, whose annotated twin is this) · filed 2026-09-30 against master `028dedb33`**

Repro:

    type R = { v: i32 | null }
    const d: R | null = { v: 7 }
    print(d?.v ?? 0)
    // vl check: rc 0.  vl run: invalid module, "type mismatch: expected i32, found (ref …)"

Want:

    7

#### Mechanism

A `?.` over a nullable record yields the field's value or `null`, and when the field is itself
`i32 | null` the result is a nullable scalar whose rep is a box. The `??` that follows reads
the chain's result as the bare `i32` of a non-nullable field, so the emitted fold hands the box
where an `i32` is expected. Unconfirmed past the validator: the ablation, not a probe, places
the mismatch at the chain's result.

#### Ablation

| `const d: R = { v: 7 }` and `d.v ?? 0` | prints `7` | **yes** |
| `d` from a function with no declared result, `R` also declared `{ v: i32 }` elsewhere | the same invalid wasm (lane RC3's loud → silent cell) | no |
