### D3457 — `?.` of a nullable scalar field through a nullable record, then `??`, builds invalid wasm

**closed 2026-10-03 — the witness prints `7` · was check-clean invalid wasm, clause 1 · pre-existing since at least master `028dedb33` · found by the #3325 review (the one loud → silent cell of lane RC3, whose annotated twin is this) · filed 2026-09-30 against master `028dedb33`, closed by lane OQ against master `878f6ebe8` · fixture `tests/cases/soundness/optional-chain-nullable-field-coalesce.vl`**

Repro:

    type R = { v: i32 | null }
    const d: R | null = { v: 7 }
    print(d?.v ?? 0)
    // vl check: rc 0.  vl run: invalid module, "type mismatch: expected i32, found (ref …)"

Want:

    7

#### Mechanism

`emitCoalesceGo`'s arm for `r?.f ?? d` over a nullable record tested only the RECEIVER for
null, then yielded the field as read. For a value-box field (`i32 | null`, `i64 | null`,
`f64 | null`, `f32 | null`, `i32 | string | null`; storage code 16) it built an
`if (result (ref $box))` with the default boxed — so the `??` handed the box to a consumer
expecting the scalar (the invalid wasm), and a present receiver with a null field yielded the
null box instead of the default. Fixed by `emitOptCoalesceBoxLeaf`: one null test covering
every link and the field's own null tag (`emitOptChainIsNull`), the default at the `??`'s rep,
and the present arm unboxed at the FIELD's scalar kind and then widened to the result's
(`r?.i ?? 2.5` over `i: i32 | null` is `f64`; unboxing at the result's kind trapped on the cast),
or kept as the box of a union result. `r?.f is null` takes the same null test as `== null`.

The lane's matrix (7 field types × nullable or not × 3 receivers × 8 consumers, 336 cells)
found three more mechanisms on the same `?.` leaf, all fixed here:

* `emitOptChainIsNull` treated every leaf but a nested record or a value box as never null, so
  `r?.f == null` answered `false` for a `string | null` or `K | null` field holding `null`
  (check-clean silently wrong). It now tests each field's own encoding of `null`
  (`optChainLeafNulDisc`: a null ref, the boolean `2`, the literal-union `-1`, the box tag).
* A standalone `r?.f` refused (`a standalone ?. has no rep …`) for a `boolean | null` or
  `K | null` field and for a non-null literal-union field `K`. It now yields the i32 niche:
  the sentinel when the chain is null, else the field.
* `exprNulLitUnion` did not know a `?.` with a literal-union leaf is the `K | null` niche, so
  `print(r?.k)` printed the atom id and `r?.k ?? "a"` emitted its default as a string into an
  i32 `if` (invalid wasm). It now answers for such a chain, which routes the `??` to the
  literal-union arm.
