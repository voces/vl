### D15270 — a record a function returns, its function field written another function, called at two types, is refused at emit

**open · loud emit reject · `emitProgram: cannot take the generic function id1 as a value — a function value carries ONE signature` · clause 2 · one member runs · the binding's own literal runs since D15119 · found grading D15119 · filed 2026-11-04 against #6185 with #6186 and D15119**

Repro:

    function id0(a) { return a }
    function id1(a) { return a }
    function mk() { return { f: id1 } }
    const r = mk()
    r.f = id0
    const g = r.f
    print(g(2))
    print(g(2.5))

Want:

    2
    2.5

#### Mechanism

Two halves, measured on a probe of #6190's head. The write scan's half: `cwPathFnTargets` seeds its
walk with the binding's own initialiser, and a call is no literal, so `r` has no path set. Seeded
with the call's returned values (`holeSlotCallRets`, which the hole-slot judge already reads) it
answers both members, and the elaboration widens `r`'s record to their join. The build's half: the
program still refuses, now at `mk`'s literal (`id1`), because that literal is built at `mk`'s own
row while its reader `r` is widened. A returned literal has to be built at the row its call-bound
reader is widened to, the build-at-read rule of D15188 and D15230 in the checker's record solve. The
seed half lands with that build.

#### Ablation

| ingredient removed | outcome | needed? |
| --- | --- | --- |

| the second member (`mk` returns `{ f: id0 }`) | runs | **yes** |
| inside a function | still refuses | no |
| a list field (`{ fs: [id1] }`, `r.fs[0] = id0`) | still refuses, `ref valtype with no interned shape` | no |
| the list field with one member (`{ fs: [id0] }`) | runs | **yes** |
