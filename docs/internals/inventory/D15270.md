### D15270 — a record a function returns, its function field written another function, called at two types, is refused at emit

**open · loud emit reject · `emitProgram: cannot take the generic function id1 as a value — a function value carries ONE signature` · clause 2 · one member runs · the binding's own literal runs since D15119 · found grading D15119 · filed 2026-11-04 against #6185 with #6186 and D15119**

Repro:

    function id0(a) { return a }
    function id1(a) { return a }
    function mk() { return { f: id1 } }
    const r = mk()
    r.f = id0
    const g = r.f
    print(g(2))
    print(g(2.5))

Want:

    2
    2.5

#### Mechanism

Not yet ablated past the grid. `elabFnFieldTy` widens a field of the record literal a `let`
initialises (`letFieldListsWidenAt` walks the binding's own literal). A binding initialised by a
call has no literal of its own, so the write `r.f = id0` joins no set and the read carries `id1`'s
alone. The same program with a list field (`{ fs: [id1] }`, `r.fs[0] = id0`) refuses too, with
`ref valtype with no interned shape`.

#### Ablation

| ingredient removed | outcome | needed? |
| --- | --- | --- |
| the call (`const r = { f: id1 }`) | runs (D15119) | **yes** |
| the second member (`mk` returns `{ f: id0 }`) | runs | **yes** |
| inside a function | still refuses | no |
