### D15270 — a record a function returns, its function field written another function, called at two types, is refused at emit

**closed 2026-11-04 by lane destringify, runs, prints `2`, `2.5` · was a loud emit reject (`emitProgram: cannot take the generic function id1 as a value — a function value carries ONE signature`), clause 2 · the write scan now seeds a call-bound binding's path with the call's returned values, so `letCallFieldsWiden` widens its function and function-list fields; and `fnWidenedSourceSets` hands the tag pass the set of the record the call returns, so `ftPlan` decides it with the widened one: a tagged value is its member's declaration id in every set, so `mk`'s literal needs no build of its own · fixture `closures/fn-record-returned-field-written-another-fn-two-types.vl` · named set `d15270-call-bound-field` · the direct call `r.f(2)` is D15245 · found grading D15119 · filed 2026-11-04 against #6185 with #6186 and D15119**

Repro:

    function id0(a) { return a }
    function id1(a) { return a }
    function mk() { return { f: id1 } }
    const r = mk()
    r.f = id0
    const g = r.f
    print(g(2))
    print(g(2.5))

Want:

    2
    2.5

#### Mechanism

Two halves. The write scan's: `cwPathFnTargets` seeds its walk with the binding's own initialiser,
and a call is no literal, so `r` had no path set; `cwPathFnTargetsFrom` seeds it with the call's
returned values (`holeSlotCallRets`) and the elaboration widens `r`'s record to their join. The
tag pass's: `mk`'s literal leaf `id1` is typed at `mk`'s own set `{id1}`, so `ftPlan` for `r`'s
widened `{id0, id1}` found no leaf for `id1` and left the set a closure. The record solve was not
the missing half: a delivery of the call into the widened row changed nothing, because a tagged
value is the same declaration id in either set and there is nothing to rebuild.
