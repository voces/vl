#### Mechanism

#4001 (`bb4448de7`, D5593/D5650) added `progCheckCalleeFirst` (check_top_level.vl). Before each
function that is not yet checked, it asks `weSummaryUnsettled` (check_write_effects.vl) about
every later-declared function the body names, and checks that callee first when the answer is
true. Each probe computes a write summary. Inside the compiler's large call cycle, that summary
walks every member of the cycle. The cycle closes unsettled because the probed body is not
checked yet, so `weSettleCycle` caches none of its members. A true probe is followed by a body
check, and `weUnresDrop` clears `weUnresSums` at the check's enter and leave. So the next probe
walks the whole cycle again. Counted on master with a counter build: 5,167 probes, 2,295 of
them true. Probes ran 32,964 summary computations against 2,096 outside them, and built 268M
summary characters against 0.6M. 14,495 cycle members were dropped as unsettled, and 2,150
were kept. In a `--names` profile the probe's own leaves are `weSplit` and `weDedupe` (about a
third of its samples), `weSubstArgs` and string hash and compare.

The reorder itself is cheap; the probe is the cost. Checking every later callee first without
the probe changes the check order of every program, so it is a design choice, not a local fix.
Two other routes: drop only the unsettled summaries a check actually changed, or make the
summary set algebra cheaper than split-and-dedupe over strings.

#### Fix

`compiler/check_write_effects.vl`. A summary that closes unsettled records a witness in
`weUnresWit`: the largest untyped read it counted, `2n` for a node and `2n + 1` for an index site
whose receiver has no type. `weUnresDrop` does not clear it. `weSummaryUnsettled` answers true
without a walk while that witness is still untyped (`weWitLive`), since a walk would count it
again. Otherwise it walks in probe mode: the first untyped read ends the walk (`weProbeHit`), and
the walk stores no unsettled summary, because only its yes/no answer is read. Settled summaries
are still cached as before. Shape walks never reach `fnWriteFreePaths` or `fnWriteEffects`, so
the early stop cannot leave a partial entry in those caches.

Checked with a build that ran master's full walk beside the new answer and raised an error on any
disagreement. Over `compiler/entry.vl`, `scripts`, `std` and 5,538 `tests/cases` files there were
0 disagreements. A control build that raised an error on every memo answer fired 681 times. An
A/B of the soundness, scope, inference, functions and closures cases (1,446) against master's
seed changed no output.

What is left: in a `--names` profile, `weSummaryUnsettled` is still about 16% of the samples of
`vl check compiler/entry.vl`. Most of it is the string set operations `weSplit`, `weDedupe` and
`weSubstArgs` in the walks that settle. This is not filed.
