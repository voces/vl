### D15494 — an untagged map whose generic is called at two types is annotated with one signature, a rep spelling the elaboration has no fact for

**runs today and must keep running · refutation pin · filed 2026-11-06 against master `ed698805`**

Repro:

    function id<T>(x: T): T { x }
    function inc(x: i32): i32 { x + 1 }
    function fill(mm) { mm["k"] = id }
    const m = Map()
    fill(m)
    const d = Map()
    d["j"] = inc
    fill(d)
    const r = m["k"]
    if r != null {
      print(r(2))
      print(r("s"))
    }

Want:

    2
    s

#### Mechanism

`fill` is handed a map that holds a non-generic `inc`, so the set `{id}` stays untagged and `m` is
a map of closures (D9480). `monoPinMapValues` annotates `m` as `{[string]: (i32) => i32}`, the
signature of one call. That annotation is not a type: written in source it is a check reject at
`r("s")`. It is a rep spelling, and any closed function type gives the map its closure rep while
the calls reach `id` at both signatures. `elabSlotTyAt` correctly closes no type for `m`, so the
map-values switch (§3.4, slot type) keeps mono's spelling here. Making it decline instead turns
ten `tests/cases` programs and D15298 into emit refusals, one of them a compiler trap.

The missing fact is a holder bundle: "slot `v` of `m` holds a closure called at signatures
S1..Sn" (`elabSlotBundleSigs(holder, path)`), the holder-slot form of a parameter's
`elabCallBundleSigs`. It is queued behind the reach lane's per-call bundle registry.

#### Ablation

| ingredient removed | outcome with the switch declining | needed? |
| --- | --- | --- |
| `d` and `fill(d)` (the set is tagged) | runs, through the tag path | **yes** |
| `r("s")` (one signature) | runs, the slot fact closes | **yes** |
| `fill` (`m["k"] = id` directly, `d` written `id` too) | not measured | — |
