### D2746 — a function relaying the call of one whose returns join two list literals keeps the first literal's list kind

**closed 2026-09-26 — the repro RUNS and prints `s` · was check-clean invalid wasm · 3 relay cells of the #3204 review's `a/` grid, `r/r2_relay.vl`, and the relay positions of the lane's return-form grid · filed 2026-09-26 against master `92bed043d`**

Repro:

    function f(c: boolean) {
      if c { ["s"] } else { [1, "t"] }
    }
    function r(c: boolean) { f(c) }
    print(r(true)[0])

#### Mechanism

`computeRetInference` classifies every un-annotated function to a fixpoint. On its first round
`f`'s list kind is the string list its `["s"]` arm settles, and D2716's re-seat onto the joined
`(i32 | string)[]` row happens only on the next round. `r`, classified after `f` in that first
round, read `f`'s string-list kind through its call, and `criClassify`'s list arms never
revisit a kind once it is a list, so `r` was declared to return a string list over a body
returning `f`'s union-element list. The `return f(c)` spelling fails the same way; the review's
`return`-spelled control that runs is the one where `f` itself uses `return` statements, whose
first round happens to settle differently. Closed by letting a return that relays a call of a
function with a banked join, directly or through up to four more relays, re-seat on that join
(`criRelayJoinListTy`).
