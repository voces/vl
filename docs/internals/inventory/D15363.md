### D15363 — a list literal of functions of different results, handed to an un-annotated parameter that calls an element, is refused at check

**closed · runs, prints `1.5` · was loud check reject, `cannot store 'half' in an element of 'xs': called at (i32) it returns f64, where 'inc0', also stored in it, returns i32` · clause 2 · found re-running [D15161](D15161.md)'s witness: the list twin of its per-argument judge · filed 2026-11-04 against master `73062b831` · closed 2026-11-04: `holeSlotArgJudge` (check_relate_core.vl) lifts a literal handed straight to the parameter, and a binding holding only its literal, as `holeSlotJudge` already lifts a binding read in its own scope · fixture `tests/cases/closures/mixed-result-fn-list-literal-handed-to-hole-param-runs.vl`**

Repro:

    function inc0(a) { return a + 1 }
    function half(a) { return a / 2.0 }
    function run(xs) { print(xs[1](3)) }
    const xs = [inc0, half]
    run(xs)

Want:

    1.5

#### Mechanism

A call through a list element runs the member it reads, so an element holding only its literal's
functions needs no common result (D14435). The literal's own type already joins its elements.
`holeSlotJudge` lifts the comparison for a binding read in its own scope when nothing is written to
it, `nW == 0`.

A read through an un-annotated parameter is judged one call argument at a time, by
`holeSlotArgJudge`, and that path took neither half of the lift:

* a literal argument, `run([inc0, half])`, was judged with no lift;
* a binding argument kept only `holeSlotWidenLift`, so a binding holding only its literal was
  judged as if its elements had been written.

The fix gives both the lift, for an argument handed straight to the parameter (`depth == 0`). Through
a forwarder, `fwd(xs) { run(xs) }`, the instance does not read the argument at the literal's type,
and lifting there built a trapping module. That spelling keeps its loud check reject.
