### D6601 — a list literal of un-annotated lambdas handed to an un-annotated parameter that calls an element builds the instance at a `() => void` element

**closed 2026-10-18 by lane L1 · runs, prints `4` · was check-clean invalid wasm · clause 1 · the element call's result now takes the element function's own instance at the call's arguments in the checker, and the parameter is pinned at the list of that function type in the emitter · pins: `tests/cases/closures/hole-param-list-of-hole-functions.vl`, `tests/cases/closures/error-hole-param-list-of-hole-functions-result.vl` · found closing [D6524](D6524.md) · filed 2026-10-18 against master `8c82621c`**

Repro:

    function run(fs) {
      return fs[0](3)
    }
    const h = (u) => u + 1
    print(run([h]))
    // vl check: rc 0.  vl run: the emitted module failed to validate inside `run`: type mismatch

Want:

    4

#### Mechanism

`run([h])` binds `fs` at `h`'s open signature in a list. In the checker the `HD_RET` row for
`fs[0](3)` found that signature and fell back to its open result, since `holeCallRetAt` reads only
a declared generic's; so the call's result was gradual and `const s: boolean = run([h])` checked.
In the emitter no pin rung read a list of open functions, so `run` was instanced at
`(() => void)[]` and the element call returned nothing. The checker now types the element call as
a direct call of that lambda or hole function (`holeOpenFnRetAt`); the emitter pins the parameter
at a list of the type the flow table agrees its elements are called at (`monoOpenFnListPin`), and
delivers each element at it.

The emit half alone was a clause-1 move in the other direction: the annotated spelling printed
`true`. The checker half is what refuses it.
