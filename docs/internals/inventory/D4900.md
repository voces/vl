### D4900 — a hole function joining `return [t]` with a tail `[1]` is typed as the `i32` list at an `f64` pin

**closed · was a check-clean invalid wasm (`type mismatch: expected (ref $type), found (ref $type)` inside `w`), identical on master `c2dbf639e` · fixture `tests/cases/generics/hole-ret-tail-literal-adapts.vl` · filed 2026-10-15**

Repro:

    function w(t, b: boolean) {
      if b { return [t] }
      [1]
    }
    print(w(2.5, true)[0])
    // vl check: rc 0.  vl run: invalid module inside `w`: type mismatch: expected (ref $type), found (ref $type)

Want:

    2.5

#### Mechanism

The instance is emitted as `(param f64 i32) (result (ref $3))` with `$3` the `i32` list, and
the returned `[t]` is an `f64` list. The D1521 rung in `emit_mono.vl` that re-types an
unannotated list return at the instance passed only the `let`-column binding to
`monoInferRetSetListTy`, which declines a return type holding a hole, so the D592 tail rung's
`i32[]` stood. Closed: the rung joins the holes' binding (`monoHoleBinding`) into the one it
passes, so the return is the list at `t`'s binding and the tail literal adapts to it.
