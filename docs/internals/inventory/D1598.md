Repro:

    // file: cell.vl
    export function hbase(b) { return b.base }

    // file: entry.vl
    import { hbase } from "./cell"

    if true {
      const n = { base: 3 }
      print(n.base)
    }

    if true {
      const n = { base: 4 }

    }
    // before: vl check rc 0; vl run -> emit error,
    //   "emitProgram: field access receiver is not a struct"
    // after:  3, 4

#### Mechanism

`monoArgTyName` pins an un-annotated parameter from its argument's BINDING, and a `const`
written inside a top-level block is a start-function local rather than a global, so the
module-frame table `moduleLocalLetOf` is the rung that answers. That table is FIRST-WINS over
a walk with no notion of which block a call site sits in, so `moduleLocalLetOfUnique` declined
on any name it held more than once (D1596) and the instance took the `"i32"` catch-all over a
`(ref $type)` argument. `mllDup` recorded only that a name was bound twice, not what the two
bindings were.

Declining is right where the candidates DISAGREE — answering there hands one block's ref
binding to a sibling block's i32 call, a measured `runs -> not-runs`, and
`tests/cases/generics/pin-module-block-binding.vl` leg 7 is that control. It was wrong
everywhere else, and the resolution the decline was waiting for was already taken: the CHECKER
resolves an identifier lexically, so the type it recorded for the call site NAMES which
candidate the site denotes. `monoModuleDupPin` reads the candidate set (`moduleLocalLetAll`,
the second-and-later bindings kept beside the first-wins map) and takes the candidate carrying
that type; failing that, a set whose candidates all pin ONE spelling has no disagreement to
decline over. Neither rung is a name scan, and neither answers where the candidates disagree
and the site's type names none of them — leg 7 keeps its i32 instance.

A candidate is matched on BOTH of its spellings, because they are two producers: `const p: Box
= {…}` carries `Box` on the annotation and the inline shape on the initializer, and only one of
those renders as what the site's own recorded type does. With the annotation half missing,
D1596's residue witness still failed while its un-annotated twin ran.

Disassembly of the UFCS witness, before and after:

    (func $1 (type $3) (param $0 i32) (result i32)          ;; before
    (func $1 (type $3) (param $0 (ref $1)) (result i32)     ;; after

The cross-module spelling is the shape glean's VL-042 had, and the boundary is NOT an
ingredient — the same program with `hbase` in the entry refused identically.
