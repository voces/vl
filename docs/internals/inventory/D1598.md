### D1598 — the hole parameter's module-frame pin declines on a duplicated name even when every candidate binding has the SAME type

**loud emit reject at the field-read delivery below; the UFCS delivery of the same call is the
clause-1 face and stands as a capability probe · filed
2026-09-04 against master `e05bcfda` · ALL 80 BOTH-FAIL pairs the day-one sampler's new
`modules_split` axis reported over 1,640 carry it · D1596 filed the disagreeing half of this as
residue needing its own row**

Repro:

    // file: cell.vl
    export function hbase(b) { return b.base }

    // file: entry.vl
    import { hbase } from "./cell"

    if true {
      const n = { base: 3 }
      print(n.base)
    }

    if true {
      const n = { base: 4 }
      print(hbase(n))
    }
    // vl check rc 0; vl run -> emit error,
    //   "emitProgram: field access receiver is not a struct"

#### Mechanism

`monoArgTyName` pins an un-annotated parameter from its argument's BINDING, and a `const`
written inside a top-level block is a start-function local rather than a global, so the
module-frame table `moduleLocalLetOf` is the rung that answers. That table is FIRST-WINS over
a walk with no notion of which block a call site sits in, so `moduleLocalLetOfUnique` declines
on any name it holds more than once (D1596) and the instance takes the `"i32"` catch-all over
a `(ref $type)` argument.

Declining is right where the candidates DISAGREE — answering there hands one block's ref
binding to a sibling block's i32 call, a measured `runs -> not-runs`, and
`tests/cases/generics/pin-module-block-binding.vl` leg 7 is that control. It is wrong where
they AGREE: both bindings here are `{base: i32}`, every candidate pins the same rep, and the
decline costs a working program for a disagreement that does not exist. `mllDup` records only
that a name was bound twice, not what the two bindings were.

The cross-module spelling is the shape glean's VL-042 had, and the boundary is NOT an
ingredient — the same program with `hbase` in the entry refuses identically.
