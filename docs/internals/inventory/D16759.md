### D16759 — an open `[]` binding handed to a generic list parameter, then written at an element other than the unbound default, is refused at the call

**open · now a loud check reject · clause 2 · `this call hands an empty list whose element a later write fixes as f64, after the call's instance is built; annotate the list's element type` · residue of D16758's close · was refused at emit, at the instance's `T[]` parameter · filed 2026-11-16 against master `e33ab71cc`**

Repro:

    function probe<V>(v: V[]) { return v.length }
    const e = []
    print(probe(e))
    e.push(2.5)
    // vl check: rc 1, the refusal above at `probe(e)`

Want:

    0

#### Mechanism

The call leaves `V` unbound, because the row is open when it is checked, and the checker builds
the call's instance at the unbound default. `settleHeldPins` (check_calls.vl) adds the settled
element to the call's bind row, but an instance already built at `i32` is not rebuilt, so a row a
later write fixes at `f64` would reach an `i32` body (invalid wasm). It is refused instead. The fix is
to defer the call's instance until the row settles, or to rebuild it from the late binding.
