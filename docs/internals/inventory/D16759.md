### D16759 — an open `[]` binding handed to a generic list parameter, then written at an element other than the unbound default, is refused at the call

**closed 2026-11-16 by lane AE — the witness prints `0` · a call that bound no type parameter and held one open for a list is banked for the elaboration once its rows settle, at the element the row settled at (`settleHeldPins`, `elabUnboundCallNote`), not at the unbound default when it is checked · fixture `tests/cases/soundness/open-list-binding-to-generic-list-parameter-later-write.vl` · residue D16782 · was a loud check reject, clause 2, `this call hands an empty list whose element a later write fixes as f64, after the call's instance is built; annotate the list's element type` · filed 2026-11-16 against master `e33ab71cc`**

Repro:

    function probe<V>(v: V[]) { return v.length }
    const e = []
    print(probe(e))
    e.push(2.5)
    // vl run: prints 0 (was refused at the call)

Want:

    0

#### Mechanism

The call leaves `V` unbound, because the row is open when it is checked, so `elabUnboundCallNote`
(check_calls.vl) banked its instance at the unbound default then. `settleHeldPins` added the settled
element to the call's bind row later, but the elaboration had already built the body at `i32`, and
a row a later write fixed at `f64` reached that body. Such a call now defers the note to
`settleHeldPins`, which banks it at the settled element. A call that already bound the parameter
from another argument at a different type is a type mismatch, refused at the call.
