### D2270 — `exprF32Array` had no if-join rung and no arena opener, so an un-annotated `if c { f32s } else { [] }` bound an i32 cell

**closed 2026-09-23 — the witness runs and prints `7.5` · was check-clean invalid wasm, clause 1, 17 cells of the list-kind grid's f32 `empty-join` family (plus a loud emit reject at an inferred return and a generic body, clause 2) · fixed by `exprListRep`, one list-rep producer that asks the recorded type first and the syntactic rungs second, with `exprF32Array` its projection · found by `list-kind-grid.py` (`list-kind-audit-2026-09.md` §3) · filed against master `e4f244373` · fixture `tests/cases/lists/if-expr-f32-list-empty-join.vl`**

Repro:

    function t() { 1 == 1 }
    const src: f32[] = [(7.5 as f32)]
    const v = if t() { src } else { [] }
    print(v[0])
    // vl check: rc 0.
    // vl run (as filed): invalid module — expected i32, found (ref $type); `v` declared i32.
    // Now prints 7.5.

#### Mechanism

`letIsF32Array` falls through to `exprF32Array(init)` for an un-annotated binding, and
`exprF32Array` was the one scalar-list predicate with neither an arena opener (`exprF64Array`
opens on `tyIsF64Array(nodeTyPinIxOf(e))`) nor an `IfStmt` arm (`exprStringArray` and
`exprRefArray` ask `ifExprRefKind`). An `if` node therefore answered "not an f32 list", the
binding took the i32 cell, and the join's `(ref $fl32)` value met it. The f64 twin ran only
because of its opener. The fix adds `exprListRep(e, fnIx): VKind | null`: the recorded type's
`repOfTy` answer first (never at an `ArrayLit` or `Index`, whose recorded type is not the rep
they build), except that a recorded `f64[]` yields to an f32 syntactic claim because the checker
types a float literal f64; then the syntactic rungs, with an `IfStmt` arm that reads
`ifExprRefKind`. `exprF32Array(e)` is `exprListRep(e) == "f32list"`. Only f32's leaf rungs live
in the producer so far; the other six predicates move onto it one PR each. A covered recorded
type naming a non-list rep answers null without reaching the syntactic rungs; the review of the
first head found the `IfStmt` rung made nested joins exponential, which is D2271.
