### D3215 — `?.` on an inference hole is refused as a member access on a non-object, where the annotated spelling runs

**loud check reject · clause 2 · open · pre-existing, the same on master `94670f728` · found by the #3289 review (`rv3289-q8x4/p/a01.vl`) · filed 2026-09-29 against master `94670f728`**

Repro:

    type H = { v: i32 }
    type Q = { h: H | null }
    function F(z) { print(z.h?.v ?? -1) }
    const a: Q = { h: null }
    const b: Q = { h: { v: 4 } }
    F(a)
    F(b)
    // vl check: member access '?.v' on non-object _

#### Mechanism

`checkOptMemberNode` types `?.` against the receiver's non-null face and knows a record, a
union and a nullable, but not an inference hole: a `TyVar` receiver falls to the closing
`member access … on non-object` sentence, printed with the hole's `_`. The plain `.` read has a
`TyVar` arm that derives a field hole and re-asks it at the pin, and `?.` has no counterpart,
which would need a derivation for "the field of the non-null face, re-wrapped nullable". The
annotated twin `function F(z: Q)` prints `-1` and `4`.

#### Ablation

| ingredient changed | outcome on master | needed? |
| --- | --- | --- |

| `function F(h) { print(h?.v ?? -1) }` over `H \| null` | the same refusal | no (any hole receiver) |
| `print(z.h?.v)`, no `??` | the same refusal | no |
