### D16393 — `==` over a list of a string literal union and a `string[]` is refused: the two store their elements apart

**loud check reject · clause 2 · bucket (e) · found probing the unprobed `--sites` row `check_ty_relate.vl:771` (mutually assignable types stored differently) · probe `scripts/capability-probes/eq-litunion-list-vs-string-list.vl` · filed 2026-11-15 against master `5683d3b2c`**

Repro:

    const a: ("a" | "b")[] = ["a"]
    const b: string[] = ["a"]
    print(a == b)
    // vl check: `==` over ("a" | "b")[] and string[] has no lowering: the two are mutually assignable but store their elements differently

Want:

    true

#### Mechanism

A string literal union is stored as an interned atom, a `string` as a string, so the two lists take
different equality cores. `emitEqNonNullCore` runs one core chosen from one operand, so the checker
refuses the pair rather than lower one list over the other's storage (D45). Two lists of the same
literal union, and the scalar pair `"a" | "b"` against `string`, compare.

#### Ablation

| spelling | outcome |
| --- | --- |
| the witness | refused |
| `a != b`, `b == a` | refused |
| `("a" | "b" | null)[]` against `(string | null)[]` | refused |
| `("a" | "b")[]` against `("a" | "b" | "c")[]` | runs, prints `true` |
| `"a" | "b"` against `string` (scalars) | runs, prints `true` |
| `(1 | 2)[]` against `i32[]` (an integer literal union) | runs, prints `true` |
