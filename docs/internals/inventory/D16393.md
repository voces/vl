**closed 2026-11-16 by lane AE — the witness prints `true` · a list of string literals beside a list of `string` is read through a copy at the string element (`eqAtomListCopy`, `site.map(($e): string => $e)`), so both compare in the string core; the copy is read once and never written · matrix `eq-litunion-list-vs-string-list.matrix.vl` 74 of 74 graded cells run (was 0) · fixture `tests/cases/types/eq-litunion-list-vs-string-list.vl` · was a loud check reject · clause 2 · bucket (e) · found probing the unprobed `--sites` row `check_ty_relate.vl:771` (mutually assignable types stored differently) · probe `scripts/capability-probes/eq-litunion-list-vs-string-list.vl` · filed 2026-11-15 against master `5683d3b2c`**

Repro:

    const a: ("a" | "b")[] = ["a"]
    const b: string[] = ["a"]
    print(a == b)
    // vl run: prints true (was refused at check, `has no lowering`)

Want:

    true

#### Mechanism

A string literal union is stored as an interned atom, a `string` as a string, so the two lists take
different equality cores. `emitEqNonNullCore` runs one core chosen from one operand, so the checker
refuses the pair rather than lower one list over the other's storage (D45). Two lists of the same
literal union, and the scalar pair `"a" | "b"` against `string`, compare.
