### D3682 — a lambda whose body reads a record field is given the field's nullable result type, so a call through its declared function type traps

**loads then traps — `indirect call type mismatch` in a plain build · found by the #3384 review, pre-existing on master · filed 2026-10-05 against master `56af0f07e`**

Repro:

    type V = { x: f64, y: f64 }
    type P = { a: V, n: i32 }
    const p: P = { a: { x: 1.0, y: 2.0 }, n: 0 }
    function getter(): () => V { () => p.a }
    print(getter()().y)
    // vl check: rc 0.  vl run: wasm trap: indirect call type mismatch

Want:

    2

#### Mechanism

The emitter types a record field as `(ref null $V)`. The lambda `() => p.a` takes its wasm
result type from its body, so its function is `(func (param structref) (result (ref null $V)))`
(`$5` in the witness's module). The call through the declared `() => V` uses
`(call_indirect (type $6))`, whose result is `(ref $V)`. `call_indirect` compares function
types exactly, so the call traps. The lambda's wasm signature should be the one its function
type names, with a `ref.as_non_null` on the body's value, as a declared function's return
already gets.

#### Ablation

| spelling | outcome | needed? |
| --- | --- | --- |
| the witness | trap | |
| `() => p.n` (an `i32` field) | prints `0` | **yes**: a reference-typed field |
| `const g = () => p.a; g().y` at top level | prints `2` | **yes**: a call through the function type |
| `getter` without its `: () => V` annotation | trap | no |
| a plain captured `v: V` instead of `p.a` | prints `2` | **yes**: a field read, not a local |
| `const q = p` inside `getter`, then `() => q.a` | trap | no |
| `const f = getter(); f().y` | trap | no |

#### Grading list

A lambda returning a record read from a list element (`xs[0]`) and from a map (`m.get(k) ?? d`);
a lambda passed as an argument of type `() => V`; the `-O` build.
