### D17809 — a `const` bound to a call the frame types open, through a lifted lambda over a captured hole function, is refused when read at the float the call returns

**loud emit reject · clause 2 · `print operand rep` at `print(v)` · `vl check` rc 0 · the bound face of D17664 and D17782 · filed 2026-11-28 against master `711e77a85` by I8-PREP**

Repro:

    function add(a, b) { return a + b }
    function app(g, s) { return g(s, s) }
    function p5(h) {
      const run = (x) => app(h, x)
      const v = run(1.5)
      print(v)
    }
    p5(add)
    // vl check: rc 0.  vl run: emit error (print operand rep)

Want:

    3

#### Mechanism

The call's frame type is a hole of `p5`'s instance. D17664's and D17782's close reads a printed
call at its callee's called width (`openCallWidth`), but `v` is a read, not a call: the IR holds
`v` at the call's `f64` (`storedVarOf`), and the print arm reads the binding's open type and takes
the `i32` default. Stop point: extending `openCallWidth` to a read of an un-annotated `const`
holding such a call moves the refusal to `locals layout`, because the function's local layout
still types `v`'s slot at `i32`; the local's slot width has to come from the same reader first.
D17782's bound form (`const v = take(q)`, a closure call) refuses earlier, at `local rep unsup`.
