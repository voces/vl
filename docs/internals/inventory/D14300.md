### D14300 — an inline union with a generic-application member is not registered as a variant box, so a reassignment to its other arm builds no box

**closed · runs, prints `3` · was check-clean invalid wasm inside `main` · test `tests/cases/generics/union-member-generic-application-inline-reassign-local.vl` · filed 2026-10-26 against master `2f9786dae`**

Repro:

    type Box<T> = { v: T }
    type Tag = { t: i32 }

    function main() {
      let w: Box<i32> | Tag = { v: 2 }
      w = { t: 3 }
      if w is Tag { print(w.t) } else { print(w.v) }
    }
    main()
    // vl check: rc 0.  vl run: invalid module inside `main`

Want:

    3

#### Mechanism

A declared union's members are canonicalised member by member, and a generic application
there becomes its instantiated shape. An inline annotation is one `TypeRef` whose name is the
pipe-joined set, and canon's union arm left `Box<i32>` as written. Inline union registration
(`registerInlineUnionGo` → `isVariantBoxUnionAtoms` → `isStructAtom`) is name-based: a
declared struct name or a shape span. `Box<i32>` is neither, so the union was not given a
variant box. The binding was stored as one struct, and the write of the `Tag` arm stored a
`Tag` ref into it. Canon now rewrites the generic-application members of an inline union with
two or more non-null members to their shapes (`inlineUnionGenAppShapes`). `Box<i32> | null`
keeps the name its nullable niche resolves through.
