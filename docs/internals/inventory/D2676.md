### D2676 — a type parameter bound only by an explicit type argument left the body's `V | M` unsubstituted by type, so the union was never minted and `is` answered from the bare member

**closed 2026-09-26 by the W2 lane PR — the filed repro RUNS and prints `true` · was check-clean
silently wrong, clause 1 · found grading D2493's close · filed 2026-09-26 against master
`525837973`**

Repro:

    function g<V>(n: {[i32]: i32}) {
      const u: V | {[i32]: i32} = n
      u is {[i32]: i32}
    }
    const mi: {[i32]: i32} = Map()
    print(g<string>(mi))
    // printed false on master; prints true

Want:

    true

#### Mechanism

`monoMakeInstance` built the body's type-binding column (`letBN`/`letBT`) from the parameters
alone, so a type parameter no parameter mentions had a name binding (`tvN`/`tvV`) and no type
binding. `monoSubstLetType` then substituted the annotation's spelling but got no substituted
type, and `monoPinMintedUnion` (D2657), gated on that type holding a map, never registered the
union: `u` became the bare map of its initializer and `is` folded to a constant. The explicit
arguments' arena types now seed that column (`monoExplicitBN`), the minting gate also admits a
record member (whose `as?` result takes its struct row through `asNulStructRow`), and a local
annotated with a substituted union takes the type its registered spelling names, the one an
assignment's `letUnionNameOf` resolves, so `let u: V | M = …; u = …` boxes its writes too.

#### Ablation

| ingredient removed | outcome | needed? |
| --- | --- | --- |
| `V` bound by a parameter too (`g<V>(m: V, n)`, `g("s", mi)`) | prints `true` (D2657's close) | **yes** |
| the map member (a scalar or list member, `V \| i32`, `V \| i32[]`) | prints `true` | **yes** |
| the map member, for a record one (`V \| R`) | `emitProgram: ref valtype with no interned shape` | no — the same mechanism, loud |
| a `Set<i32>` member instead | prints `false` | no |
| the same-rep pair (`V := {[i32]: string}` or `{[i32]: boolean}`) | prints `false` | no |
