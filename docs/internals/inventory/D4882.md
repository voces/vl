### D4882 — an un-annotated parameter's list returned beside another list joins as one list in the template, and the pin builds the wrong one

**closed · was check-clean invalid wasm (a union box where a list is expected, at top level), filed against master `5be21bb0a` · fixture `tests/cases/generics/hole-param-list-join-concrete-list-apart.vl` · found by L2 §13.30, the un-annotated face of D4862 · filed 2026-10-15**

Repro:

    function w(t, b: boolean, q: i32[]) {
      if b { return [t] }
      q
    }
    const q: i32[] = [5, 6]
    const v = w(2.5, false, q)
    print(v.length)
    for e in w(2.5, true, q) { print(e) }

Want:

    2
    2.5

#### Mechanism

The template's return is `_[]`: the hole `t` absorbs `i32[]`, so the return set joins as ONE
list before any pin, and nothing is left for the pin to keep apart. The `<T>` spelling keeps
`T[] | i32[]` apart and re-joins it at the pin (D4862), so it runs. On master the failure sat
inside `w`; D4862's close moved it to the caller, and at `t := i32 | null` it is now a loud
emit reject (`.length` receiver's ref-list element does not resolve) where master built invalid
wasm. Closed by L2 §13.34: a parameter's hole beside a concrete type under a constructor
parts as a declared parameter does (`holeParamBesideConcrete`), so the template keeps `_[] | i32[]`
apart and the pin builds each list. The `[5, 6]` spelling is D4900.
