### D17041 — a record field holding a `let` first bound to a generic keeps the open closure rep, which a read at an instance's closed type does not share

**runs today and must keep running · an I8 precondition (one of the misses I8 needs at zero) · filed 2026-11-21 against master `33aa73a2`**

Repro:

    function other<V>(v: V) { print(v) }
    function inLambda<T>(x: T) {
      let k = other
      k = (n) => { print(n) }
      const o = { f: k }
      const h = o.f
      const q = () => h(x)
      q()
    }
    inLambda(5)
    inLambda("w")
    // vl run: prints 5, then w. $VL_IR_SHADOW=1: the lambda `q` misses as
    // `closure temp at an open type's rep`.

Want:

    5
    w

#### Mechanism

`k` takes `other`'s open function type, `(V) => void`, so the record `o` built from it has a
field kid at the open closure rep (an `RClosure` whose parameter kid is the open one). Inside `q`,
the read of `h` (from `o.f`) is typed at the instance's closed `(i32) => void` or `(string) =>
void`. The rep tree is keyed by type, so that closed type's `RClosure` is a different node from
the field kid's. The builder names it (`irBLetTempTy`) instead of letting the verifier refuse it
under rule 3. The IR fails closed there, keeping legacy's bytes, so output is correct. The same
rows-vs-rep-tree family as D17040.

#### Ablation

| ingredient removed | outcome | needed? |
| --- | --- | --- |
| the second instance (`inLambda("w")`) | covered past the read | **yes** |
| the write `k = (n) => …` | covered past the read | **yes** |
| the lambda `q` (calling `h(x)` directly) | covered past the read | **yes** |
