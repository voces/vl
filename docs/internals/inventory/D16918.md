### D16918 — a lambda's scalar list result at a generic's `() => (T | boolean)[]` has no interned signature for the call through it

**closed 2026-11-17 — the witness runs and prints `1` · was: loud emit reject · clause 2 · `vl check` rc 0 · `emitProgram: a function-value call has no interned signature` · pre-existing on master `b2b754548` · found grading [D16905](D16905.md) · filed 2026-11-17 by lane AE4**

Repro:

    function gen<T>(f: () => (T | boolean)[]) { return f().length }
    print(gen(() => [1]))

Want:

    1

#### Mechanism

`bindGenFnRetUnionArm` bound a function result's union arm only at a union or nullable result, so
`() => (T | boolean)[]` bound nothing from `() => i32[]` and D10133's bound-type delivery never ran;
the instance called `f` at a signature nothing interned. Bound, the delivery wrapped the lambda in
an adapter, which a list result cannot take: a list never widens.

#### Fix

`bindGenFnRetUnionArm` (`compiler/check_relate_core.vl`) binds at the unions a list, record or map
result holds (`bindGenInnerUnionArms`), and D10133's delivery (`compiler/check_calls.vl`) types a
lambda argument whose body tail is a fresh list or record literal assignable to the bound result at
the bound function type (`lamRetLitFits`), where its literal is built, as an annotated one is.
