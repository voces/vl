### D15976 — a record field's un-annotated `[]`-or-`null` join reaches emit with its element hole unfilled, laid out from its field code

**runs today and must keep running · 4 programs of the sweep population · filed 2026-11-12 against master `1c930e7c`**

Repro:

    const w = { f: if 1 == 1 { [] } else { null }, n: 7 }
    print(w.f == null)
    print(w.n)
    // vl check: rc 0.  vl run: prints `false`, `7`

Want:

    false
    7

#### Mechanism

The field's storage type is `T[] | null` whose element `T` is an inference hole no use fills.
The rep descriptor does not cover a list of a hole (`rowStoreRepIn` answers no rep), so the
struct row's layout, and every emit-time reader of the field, take the field code instead.
The readers are `tsStruct`, `emitObj` (`fieldRowKindIn`), `letSpellsNulAtom` and
`exprIsLitAtom` (`fieldRowIsNulAtom`). The program runs, but the field's rep comes from a code,
not a type. The checker leaves the hole open at emit. A local binding of the same join (no
record) is pinned and has a rep, and so does a field whose element a later `push` pins.
Lane H's census of uncovered storage rows
(`2026-11-12-step7-vkind-uncovered-storage-rows.md`) found it.
