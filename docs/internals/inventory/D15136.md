### D15136 — a function list written through a parameter is refused at emit when an uncalled function also hands a list to that parameter

**closed 2026-11-14 · runs, prints `1.5` · was loud emit reject, `the function written to this element returns another type than the element's` · clause 2 · found closing [D14648](D14648.md) · filed 2026-11-03 against master `097fd927` · closed by `fnArgOnlyFrom` (check_elab_cap.vl), where a parameter of a function nothing calls hands no list, and `ucCompute` (check_unconsumed.vl), where such a function keeps its own result but consumes none of its tail callees', so `put` is built with no result · fixtures `closures/fn-list-written-other-result-through-param-beside-uncalled-hand.vl`, `closures/fn-list-read-then-written-other-result-through-param-beside-uncalled-hand.vl` · residue [D16230](D16230.md)**

Repro:

    function inc0(a) { return a + 1 }
    function half(a) { return a / 2.0 }
    function put(ys) { ys[0] = half }
    function hand(zs) { put(zs) }
    const xs = [inc0]
    put(xs)
    print(xs[0](3))

Want:

    1.5

#### Mechanism

D14648 takes the write `ys[0] = half` as `half`'s leaf only when every call of `put` hands it a
list widened to the same set (`fnWriteOnlyInto`, check_elab_cap.vl). `hand` is never called, so
`zs` has no argument, but `hand`'s body is still built at its parameter's default and
instantiates `put` there. Treating the empty argument list as vacuous stores the id into that
instance's list, and the module fails to validate inside `put` (measured 2026-11-03). The leaf
has to be noted per instance of `put`, or the uncalled body has to skip building the call.

Which gate holds it: `monoPinListElems`' own-type gate (refactor-notes/2026-11-07-slot-type-and-instance-binding.md, "Slot
deliveries, switched"). The elaboration delivers `xs` at `half`'s `(i32) => f64`, which `inc0` does
not return, so the list keeps `inc0`'s type and the write is refused. Typing the list at the delivery
instead prints `1.5` here but traps when the list is read before `put`
(`closures/error-fn-list-element-returns-other-than-a-write-through-param.vl`), so a fix needs a
per-element rep (an adapter at `inc0`), not the delivered type.

Late demand: the root call `put(xs)` instances `put` at `xs`'s own type after `elabRun` returns,
on master as here. `hand` is never built. Its second call of `put` makes `fnWriteOnlyInto` decline
`half` as the written leaf, so the elaboration delivers `xs` at `half`'s type. Without `hand`, or
with a write of the same result type, the program builds with no late demand.
`late-demands-baseline.txt` counts it once, through the fixture above. It exists only on this
refusing build and goes with this row's fix.

#### Close (2026-11-14)

Two links, each measured on the repro. `fnArgOnlyFrom` declined the write leaf because `zs` has
no argument; a function nothing calls (and that is not exported) builds no instance of `put`, so
its parameter now hands no list and the leaf is taken. With the leaf taken the module failed to
validate inside `put`: `hand`'s expression body is `put(zs)`, and `ucCompute` counted a
never-called function's tail calls as consumed, so `put` returned its assignment's value, typed
as `half`'s closure while the leaf emits an id. A never-called function now keeps its own result
but consumes none of its tail callees'. The same invalid module with the result really held,
`const g = put(xs)`, is open as [D16230](D16230.md).
