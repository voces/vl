### D15136 — a function list written through a parameter is refused at emit when an uncalled function also hands a list to that parameter

**loud emit reject · `the function written to this element returns another type than the element's` · clause 2 · open, target `1.5` · found closing [D14648](D14648.md) · filed 2026-11-03 against master `097fd927`**

Repro:

    function inc0(a) { return a + 1 }
    function half(a) { return a / 2.0 }
    function put(ys) { ys[0] = half }
    function hand(zs) { put(zs) }
    const xs = [inc0]
    put(xs)
    print(xs[0](3))
    // Want: 1.5

#### Mechanism

D14648 takes the write `ys[0] = half` as `half`'s leaf only when every call of `put` hands it a
list widened to the same set (`fnWriteOnlyInto`, check_elab_cap.vl). `hand` is never called, so
`zs` has no argument, but `hand`'s body is still built at its parameter's default and
instantiates `put` there. Treating the empty argument list as vacuous stores the id into that
instance's list, and the module fails to validate inside `put` (measured 2026-11-03). The leaf
has to be noted per instance of `put`, or the uncalled body has to skip building the call.
