**closed 2026-11-05, runs and prints `6`, with the split plan on and off · was loud emit reject, `vl check` rc 0, `emitProgram: cannot take the generic function `dbl` as a value — a function value carries ONE signature, and parameter `a` is un-annotated`, clause 2, with the split plan on and off · found probing the flow table's join edges (`ffJoin2`'s second operand) after the fn_flow_shadow audit's deletion · filed 2026-11-05 against master `34b01a716` · closed by reading a `??` as both its sides: the elaboration instances what a call through it may hold, the read's functions and the default (`elabCalleeTargets`, check_elab_cap.vl), and mono delivers the default at the join's function type, as an `if` arm is (D10797; `monoWalk`'s `BinExpr` arm, emit_mono.vl), with no late demand · fixture `closures/coalesce-default-hole-function-over-map-read.vl`**

Repro:

    function inc0(a) { return a + 1 }
    function dbl(a) { return a * 2 }
    const m = Map()
    m["k"] = inc0
    print((m["j"] ?? dbl)(3))

Want:

    6

#### Mechanism

As filed: `??` joins the map's value, an un-annotated function the map was written with, and the default
`dbl`, also un-annotated. The call through the join fixes the signature for the map's side, but
the default reaches the emitter as a bare value of a hole function with no signature of its own,
so it is refused as a generic taken as a value. The join's second operand is the `??` default,
and nothing carries the call's pin to it.
