### D5593 — a callee's write summary depends on whether its body was checked before the caller asks

**loud check reject · clause 2, structural · residual of D5592 · filed 2026-10-17 against master `44ed9635a`**

Repro:

    type Box = { kind: "a" | "b" | "c" }
    function "[]="(self: Box, _i: i32, _v: i32) { self.kind = "a" }
    function "[]"(self: Box, i: i32): i32 { if self.kind == "a" { 0 } else { i } }

    function act(i: Intent, xs: i32[]): string {
      if i.kind == "a" { return "a" }
      fill(xs)
      match i.kind { "b" => "b\{xs[0]}", "c" => "c" }
    }
    function fill(xs: i32[]) { xs[0] = 7 }
    print(act({ kind: "b" }, [0]))

Want:

#### Mechanism

`fnWriteShapes` reads `nodeTyOf` over the callee's body, and that table is filled as bodies
are checked: un-annotated ones in the inference pre-pass or on demand at a forward call,
annotated ones in source order in pass 2. When the narrowing diagnostic is decided while the
callee's body is still unchecked, `xs[0] = 7` has no receiver type, D5590's built-in test
cannot apply, and the site is charged with every declared index operator. D5592 stopped that
answer being cached; it is still the answer given at that moment. The structure that removes
the class is one producer of per-function write facts that does not depend on check order:
check a callee's body on demand before summarising it, with an in-progress guard for
recursion, or compute the summaries in a pass after every body is typed.
