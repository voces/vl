### D17760 — a fresh binding adopted at a destination that widens an `i32 | string` field to `f64` would lose the `i32` its own reads narrow to

**runs today and must keep running · a refutation pin: F2's adoption (coordinator ruling A) at a widening leaf printed `n` here, so adoption is limited to leaves that narrow the literal's own type · filed 2026-11-27 against master `1faa021d1` by lane CENSUS**

Repro:

    type D = { v: f64 | string | null }
    const x: i32 | string = 4
    const o = { v: x }
    const d: D = o
    print(d.v ?? "z")
    const t = o.v
    if t is i32 { print(t / 3) } else { print("n") }

Want:

    4
    1

#### Mechanism

The reader is the binding's own field read `o.v`. Under an adoption at `D` it is typed at `D`'s
field, `f64 | string | null`, so the `i32` member the program wrote is read as an `f64` and the
`is i32` arm is never taken. The binding is built at its own type and converted at `d`
(D3403); `destAdopts` (`check_statements.vl`) refuses a leaf that widens, so this stays so.
