### D3087 — an un-annotated lambda returning an `i32[]` capture as `() => readonly i64[]` is refused by the checker as a join

**loud check reject · clause 2 · found grading [D3058](D3058.md) · the same on master `505bb44e0` · filed 2026-09-28 against master `505bb44e0`**

Repro:

    function mkf(x: i32[]): () => readonly i64[] { return () => { return x } }
    const f = mkf([1])
    print(f()[0])
    // vl check: type error, `i32[] is not readonly i64[]: this join would hold both`

Want:

    1

#### Mechanism

Not investigated past the ablation. The checker infers the lambda's return from its body
(`i32[]`) rather than from the `() => readonly i64[]` it is delivered into, then compares the
two lists as a join, where no [D3028](D3028.md) view is offered. The annotated lambda and a
plain function returning the same parameter are both views and run.

#### Ablation

| ingredient changed | outcome | needed? |
| --- | --- | --- |
| the lambda's return annotated `(): readonly i64[] => x` | runs, prints `1` | **yes** |
| a plain `function mk(x: i32[]): readonly i64[] { return x }` | runs | **yes** (the lambda) |
| a `Circle[]` capture returned as `readonly Shape[]` | runs ([D3058](D3058.md)) | **yes** (a scalar pair) |

#### Grading list

The `i32` to `f64` and `f32` to `f64` pairs, a block body, and a lambda bound to a typed `const`.
