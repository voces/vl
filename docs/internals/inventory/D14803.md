### D14803 — an argument only a union of type parameters admits binds none of them, so the call's return check passes `never | never`

**closed 2026-11-14 · now a loud check reject, `return type mismatch: expected boolean, got i32 (the return of \`F\` at the call's argument types)` · was check-clean silently wrong, prints `true` · clause 1 · owner ruled 2026-11-14: bind every candidate parameter (DECISIONS) · split from [D14802](D14802.md) · filed 2026-11-01 against master `d4033156` · fixed by binding every open member of a union to the argument's members no concrete member admits when they do not pair one to one: `bindParamUnionLate` at the call, `bindGenUnionRest` at the instance's pin (check_relate_core.vl) · fixtures `generics/union-of-type-params-binds-every-candidate.vl`, `generics/error-union-of-type-params-binds-every-candidate.vl`**

Repro:

    function F<A, B>(v: A | B): boolean { v }
    print(F(5))
    // master: vl check rc 0, vl run prints `true`.  now: return type mismatch: expected boolean, got i32

Want:

    a check reject at the call

#### Mechanism

`5` is accepted into `A | B` without binding either parameter. D2803's rule, that an argument a
union's concrete member admits whole binds nothing, does not reach this case, because the union has
no concrete member. D14802's close reads both open parameters as `never` in the deferred return,
and `never | never` passes into `boolean`, so the instance returns the `i32` it was handed as a
`boolean`.

The owner's choice, both plausible:

- refuse the argument as ambiguous, since it binds no parameter of a union whose only members are
  type parameters: `5 could bind A or B: give an explicit type argument`;
- bind every candidate parameter to the argument's type, as `F<i32, i32>(5)`, after which the
  return check refuses `i32` into `boolean`.

#### Ablation
