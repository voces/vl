#### Mechanism

`a.in = { v: null }` retires the `a.in.v` overlay through the prefix rule, but only a write to
the key itself pushed a ledger row. The join therefore saw the else path as untouched and
started it at the entry type, `i32`, while the then arm's own write re-narrowed the key. A
write to a prefix now leaves a kill row for every narrowed key below it, and the meet declines
a key any surviving path leaves unknown.
