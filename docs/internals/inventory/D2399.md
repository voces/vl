### D2399 — a closure whose tail writes a named nullable string or f64 list into a captured cell declares an i32 result

**check-clean invalid wasm · clause 1 · pre-existing on master `2304ece42` · filed 2026-09-25
against `2304ece42`, found reviewing the [D2393](D2393.md) close (#3144)**

Repro:

    function f(): string {
      let v: string[] | null = ["a"]
      const q = () => { v = v }
      q()
      "x"
    }
    print(f())
    // vl check: rc 0.  vl run: invalid module inside `q`: type mismatch: expected i32, found (ref null $type)

#### Mechanism

The closure's value is its tail write to the boxed cell, `v[0] = v[0]`. `cboxYieldTail` leaves
the tail alone, since the value's type is the cell's, so the write lowers as store-then-re-read
and the closure's result kind comes from `criClassify` on the right side: a synthetic `v[0]`
read with no recorded type. No classifier names a nullable `string[]` or `f64[]` element from
that node, so the result defaults to `i32` (disassembly: `(func $q … (result i32))`) while the
re-read pushes `(ref null $list)`. An `i32[] | null` cell classifies and runs. On master a later
`if v != null { v.length }` refused first, loudly; the D2393 close lifted that refusal and left
this one visible.

#### Ablation

| ingredient removed | outcome on master `2304ece42` | needed? |
| --- | --- | --- |
| the tail position (`v = v; 0`) | runs | **yes** |
| the element kind (`i32[] \| null`) | runs | **yes** |
| `string[]` for `f64[]` | still invalid wasm | no |
| the self-write (`v = w`, `w: string[] \| null`) | still invalid wasm | no |
| the named right side (a literal, `v = ["b", "c"]`) | runs | **yes** |
| the list (`string \| null`) | runs | **yes** |

#### Grading list

`string[] | null`, `f64[] | null`, `i64[] | null`, `boolean[] | null` and a record list
`| null`, each with the closure's value discarded and used.
