### D10701 — two calls through one list of hole functions, handed functions of different results, are refused

**loud emit reject · `vl check` rc 0 · clause 2 · CAPABILITY: a neighbouring spelling runs (the ablation) · found closing [D7846](D7846.md) · filed 2026-10-23 against master `d23840b00`**

Repro:

    import { toString } from "std:fmt"
    function cat(a, b) { return a + b.toString() }
    function snd(a, b) { return b }
    function apply2(g) { print(g("x", 2)) }
    function apply3(g) { print(g("y", 20)) }
    const fs = [apply2, apply3]
    for f in fs { f(cat) }
    for f in fs { f(snd) }
    // vl check: rc 0.  vl run: emitProgram: a function this call reaches through a list or join is already taken at another function type by an earlier call through it

Want:

    x2
    y20
    2
    20

#### Mechanism

The list holds one value per element, so each element is one instance of `apply2` or `apply3`.
The first loop takes them at `(string, i32) => string`, the second needs them at
`(string, i32) => i32`, and one list value cannot be both. Before D7846's close this was a
trap: master `d23840b00` runs the second loop through the first loop's instances and fails with
`wasm trap: indirect call type mismatch` at `apply2`. The close made it this loud refusal
(`monoElemTakenSig`, emit_mono.vl).

Either the language refuses the second call at `vl check` (the list's element type is fixed by
its first use, as D9092 refuses a binding called at two types), or the list holds an element per
call type. Which is a design question this row does not settle.

#### Ablation

| --- | --- | --- |
