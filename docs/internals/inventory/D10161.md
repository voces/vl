### D10161 — a generic's `() => T | string` parameter given a `string`-result function leaves `T` unbound and emits it as a list

**check-clean invalid wasm · `vl check` rc 0 · `type mismatch: expected (ref $5), found (ref $0)`, an `i32` list against a `string`, inside `len` · clause 1 · present on master `6bb8a329f` · found closing [D10133](D10133.md) · filed 2026-10-22 against master `6bb8a329f`**

Repro:

    function len<T>(f: () => T | string) {
      const t = f()
      if t is string { 0 } else { 1 }
    }
    print(len(() => "s"))
    // vl check: rc 0.  vl run: the emitted module failed to validate inside `len`: type mismatch: expected (ref $5), found (ref $0); $5 is `i32 array (list and map storage)`, array (mut i32); $0 is `string`

Want:

    0

#### Mechanism

Not traced. The argument's result `string` is the union's fixed member, so nothing binds `T`,
and the instance is built with `T` at a default whose rep is an `i32` list; `f()` then reads the
lambda's `string` result as that rep. The checker accepts the call with `T` unbound.
