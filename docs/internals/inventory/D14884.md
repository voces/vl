### D14884 — a hole lambda returned through an identity from an inferred-return function is pinned by mono's rung B, not by the elaboration

**runs today and must keep running · refutation pin for retiring mono's rung B (`monoOpenFnFlowPin`) · filed 2026-11-01 against master `443394d44`**

Repro:

    function fw(f) { return f }
    const lam = (x) => x
    function deliver() { return fw(lam) }
    const v: (x: i32) => i32 = deliver()
    print(v(3))

Want:

    3

#### Mechanism

`deliver`'s return is inferred, so nothing at `fw(lam)`'s own position says which instance of
`lam` it carries. The only fact is the declared type of `v`, one return hop later. The
elaboration flows forward only (Decision 5), so it leaves `fw`'s parameter open, and rung B
pins it by reading that later destination. Before the coercion below, the program was refused
with rung B disabled: `emitProgram: monomorphize: unsupported argument type for f in a call to
fw`.

#### The forward answer

Step 3's singleton function type. `deliver()`'s inferred result is `Fn#lam`, which flows forward
through the return unchanged, and the delivery to `(x: i32) => i32` is a coercion record that
instantiates `lam` at that destination. Rung B can be deleted once the holder positions below are
coerced too.

#### Built: the coercion at the delivery

A one-member set holding a hole lambda, delivered from a call of an inferred-return function
with no open parameter (`fvaInferredRetCall`) to a closed function type, is an escape the late tag
decision tags. The decision records the delivery (`fnCloCoerceTyIx`). Mono builds the lambda's
instance at the destination's parameters (`monoCloCoerceBuild`), and `emitExpr` lowers the record
by building that closure (`emitFnCloCoerced`). With rung B disabled, the witness runs, and so do
`return_inferred` in both `hole-lambda-through-*-fn-result` templates and 41 of 48 cells of
`hole-lambda-through-inferred-return`.

Still pinned by rung B, a holder of the delivered value: `struct_field_init` (annotated),
`struct_field_assign` (both), `array_element` (annotated), `array_element_assign` (both) and
`map_value` (un-annotated). There the literal holding the value is taken as holding the set's ids
(`ftHolds`), where the coercion makes it hold closures. A set of two or more members is not
coerced: its delivery needs a dispatch on the id, not one member's closure.

#### Ablation
