### D9380 — a generic returned from one un-annotated function and bound at two results over the same literal-union parameter traps

**closed · runs, prints `x!y` · was loads then traps, clause 1, `vl check` rc 0, `wasm trap: indirect call type mismatch` · found closing [D9282](D9282.md) · filed 2026-10-21 against master `a28f82fcb` · closed by asking for a copy of the returning function per result when the return annotations pin one parameter list at two results (`monoSlotRetCount`, `monoAskRetCopies`, emit_mono.vl) · fixture `closures/generic-returned-two-results-one-param.vl`, matrix `fn-value-generic-returned-beside-copies` (0 → 48 of 48)**

Repro:

    type K = "x" | "y"
    function same<T>(k: T): T { k }
    function deliver() {
      return same
    }
    const v: (k: K) => string = deliver()
    const w: (k: K) => K = deliver()
    const z = w("y")
    print(v("x") + "!" + v(z))
    // vl check rc 0.  vl run: wasm trap: indirect call type mismatch

Want:

    x!y

#### Mechanism

The flow pins on `deliver`'s result are keyed by parameter list, so `(k: K) => string` and
`(k: K) => K` are one pin with two results. `monoCoerceRetAtPin` saw one pin, took no copies,
and instanced `same` once at `(K) => K`, so the call through `v`, typed `(K) => string`, met
that instance. Two distinct results now ask for a copy of `deliver` per result, as two
parameter lists already did.
