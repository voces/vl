### D3567 — a generic function returning an un-annotated object literal of its type parameter is refused at emit, `ref valtype with no interned shape`

**loud emit reject · clause 2 · open · pre-existing, the same on master `f6e17953b` · found in the #3348 review · filed 2026-10-03 against master `fae55dec2`**

Repro:

    function mk<T>(x: T) { return { a: x, b: x } }
    print(mk(1).a)
    print(mk("s").b)
    // vl check: rc 0.  vl run: emit error, emitProgram: ref valtype with no interned shape

#### Mechanism

The inferred return type of `mk` is a record whose field types are the type parameter `T`.
At each pin the instance's return row is a record over the pinned type, but no shape is
interned for it on this path, so the emitter's value-type lookup has nothing to map the
reference to and refuses. Spelling the return type (`: { a: T }`) interns it and runs. Not
yet traced past the refusal site.

#### Ablation

| ingredient changed | outcome | needed? |
| --- | --- | --- |
| one pin, `mk(1)` only | same emit refusal | no: two pins are not needed |
| one field, `{ a: x }` | same emit refusal | no |
| `{ a: x, b: 1 }` | same emit refusal | no |
| through a binding, `const o = { a: x, b: x }; return o` | same emit refusal | no |
| the return type spelled, `mk<T>(x: T): { a: T }` | runs, prints `1`, `s` | **yes** (the inferred return) |
| not generic, `mk(x: i32)` | runs, prints `1` | **yes** (the type parameter) |
