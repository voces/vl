#### Mechanism

`fnSlotAssignable` refuses a function slot whose two types store differently
(`containerElemClassDiffers`), since a function value is not converted. `elemStoreClassOf`
has no numeric literal-union arm: `1 | 2` is a `TyUnion` of literals, so it answered
`ESC_BOX` against `i32`'s `ESC_I32`, while the emitter reps the union as its base `i32` and
builds one signature for both. A string literal union answered `ESC_ATOM`, which the slot
serves with an adapter (`fnSlotAtomToString`). The slot now compares a numeric literal union
at its base (`numLitUnionBaseTy`); containers keep `elemStoreClassOf`'s answer.
