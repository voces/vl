### D3177 — a generic instance over an inline record literal calls the named record type's field function when that type's instance came first

**closed · a record argument a declared record claims by its field names, differing from it only in function fields, keys its own instance and binds its own type there, spelled by the declared record's row (`monoDeclFnFieldTwin`) · fixture `tests/cases/generics/generic-record-literal-after-declared-record-field-function.vl` · was check-clean silently wrong · clause 1 · found by the #3283 review (`rv3283-3186/w/p3.vl`, `p4.vl`) · the same on master `934f169f4` · filed 2026-09-29 against master `934f169f4`, closed 2026-09-29 against master `995bbc74e`**

Repro:

    type R = { f: () => boolean }
    const named: R = { f: () => true }
    function F<Z>(z: Z) {
      print(z.f())
    }
    F(named)
    F({ f: () => 11 })
    // prints true, then true

Want:

    true
    11

#### Mechanism

The inline literal `{ f: () => 11 }` pins at `R`: a declared record claims a same-shaped
literal by its field names, and the two share one layout since a function field's rep does not
depend on its signature. `monoAnonPinDiscrim` added the argument's own type to the key only for
an `#anonN` pin, so both calls keyed `0#R,` and reached one instance, which called `f` at `R`'s
`() => boolean`. The key now carries the argument's canonical type where a declared-record pin
differs from that record only in function fields, and the instance binds that type in place of
`R`'s (`monoFnFieldTwinRow` keeps the pin spelled `R`), exactly as D3110's twin rung does for an
anonymous row.
