### D3177 — a generic instance over an inline record literal calls the named record type's field function when that type's instance came first

**check-clean silently wrong · clause 1 · found by the #3283 review (`rv3283-3186/w/p3.vl`, `p4.vl`) · the same on master `934f169f4` · filed 2026-09-29 against master `934f169f4`**

Repro:

    type R = { f: () => boolean }
    const named: R = { f: () => true }
    function F<Z>(z: Z) {
      print(z.f())
    }
    F(named)
    F({ f: () => 11 })
    // prints true, then true

Want:

    true
    11

#### Mechanism

Not localised past the ablation. The second call's instance prints the first instance's
field result: a declared record type and a same-shaped inline literal reach one instance (or
one closure choice), and the literal's own `() => i32` is not what the call reads. With an
`f64` field on `R` the second call dispatches through the wrong signature and traps.
