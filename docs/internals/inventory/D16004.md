### D16004 — an `is` test's `else` over an un-annotated parameter keeps the parameter open, so a read there is asked at every pin and of the wrong member

Repro:

    type A = { kind: "a", x: i32 }
    type B = { kind: "b", y: string }
    function mkval(): A | B { return { kind: "b", y: "yy" } }
    function take(p) {
      if p is A { print(p.x) } else { print(p.y) }
    }
    take(mkval())
    // master 81ad3cc09: vl check: argument 1: expected A | {y: _}, got A | B
    // Should print yy; annotating `p: A | B` does, and so does `else if p is B`.

Want:

    yy

#### Mechanism

The `else` arm's `p.y` grows the parameter's demanded shape (`{y: _}`), and the `is` guard adds
`A` as an alternative, so the argument must meet `A | {y: _}`. `holeDemandOk` asked that of the
whole argument: `A | B` is neither `A` nor `{y: _}`, so it was refused, though each member
takes its own path. The close asks each member of a union argument for the shape or an
alternative: `A` takes the guard and `B` meets `{y: _}`. A member neither fits is still refused
at the argument (`A | B | C`: `C` has no `y`). The guard-alternative soundness net
(`soundness/hole-is-guard-alternative-reject.vl`) keeps all three of its refusals. D3234 is the
same defect with a three-member chain.

A first attempt minted the `else` arm's `HD_GNOT` remainder for a record `T`. It ran these
programs, but it moved the arm's field demands off the argument check, and the soundness net lost
its refusal of `foobar({ baz: "baz" })` (elaboration still refused it, later). It is not landed.
