### D16004 — an `is` test's `else` branch over an un-annotated parameter keeps the parameter open, so a read there is asked at every pin and of the wrong member

**loud check reject · clause 2 · found closing [D1885](D1885.md) · present on master `81ad3cc09` · filed 2026-11-13 against master `81ad3cc09`**

Repro:

    type A = { kind: "a", x: i32 }
    type B = { kind: "b", y: string }
    function mkval(): A | B { return { kind: "b", y: "yy" } }
    function take(p) {
      if p is A { print(p.x) } else { print(p.y) }
    }
    take(mkval())
    // vl check: argument 1: expected A | {y: _}, got A | B
    // Should print yy; annotating `p: A | B` does, and so does `else if p is B`.

Want:

    yy

#### Mechanism

The `then` branch narrows the parameter to the tested type. The `else` branch has no type to
subtract from while the parameter is a hole, so `p` stays open there. Its member read `p.y`
then records a demand on the hole itself (`{y: _}`), which the pin `A | B` fails. A scalar
read in the same branch is asked at every pin the same way: with `p + "!"` in the `else` arm,
`take(4); take("s")` is refused because the `i32` pin reaches it ("operator '+' is not defined
for i32 and string"). D1885's close makes each arm of a `match` over an open parameter narrow to
its own pattern, so a `match` no longer meets this. The `if`/`else` spelling still does.

#### Ablation

| ingredient removed | outcome | needed? |
| --- | --- | --- |
| the missing annotation — `p: A \| B` | prints `yy` | **yes** |
| the bare `else` — `else if p is B` | prints `yy` | **yes** |
| the record — `i32 \| string` with `p + "!"` in the `else`, one pin | prints | **yes** |
| the record — the same with two pins, `take(4); take("s")` | refuses at the `+` | no |
