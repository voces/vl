### D2809 — a record `{a: t}` beside `{a: 1}` at a boolean pin reads the `i32` field as a boolean

**check-clean silently wrong · clause 1 · found by the #3211 review · the same on master `2bbc5c412` · filed 2026-09-27 against master `2bbc5c412`**

Repro:

    function h<T>(c: boolean, t: T) {
      if c { return { a: t } }
      { a: 1 }
    }
    print(h<boolean>(false, true).a)
    // PRINTS true

Want:

    1

#### Mechanism

The record join of `{a: T}` and `{a: i32}` at `T := boolean` shares a field storage, so the
instance builds one record and the call types `.a` as the parameter's `boolean`; the `1` built
by the second return is printed as `true`. The record twin of D2800. Not yet localised further.

Re-graded 2026-09-27 against [D2769](D2769.md)'s close: still prints `true`. The list tag does not
reach a record — the pinned join builds one record `{a: boolean}` with no union to tag, so the fix
is the record twin of [D2800](D2800.md)'s: keep `{a: T}` apart from `{a: i32}` at the pin, which
needs a record union whose arms the box can tell apart. The string pin of the same program is
check-clean invalid wasm ([D2855](D2855.md)), which says the join is wrong at every pin whose
storage differs and only silently wrong where it agrees.

Re-graded 2026-09-27 on master `1df19732b` (still prints `true`) and localised: the checker's
return-set join types `{a: t}` beside `{a: 1}` as `{a: T}`, so every pin reads the call as
`{a: T}` substituted. `tyParamsPart`, which keeps `T[]` apart from `i32[]` in a return set, reads
no further through a record, and `joinObjFieldwise` joins the field at depth 0, where a bare `T`
beside `i32` collapses. Reading the record's fields apart (a `TyObj` arm in `tyParamsPart` and a
field join that keeps `T | i32` as a `tpJoinUnions` union) types the pin as `{a: boolean | i32}`,
the direct spelling's type. It is not a close by itself: the instance still builds both returns
at the one unboxed `{a: i32}` row the template's literals share, so the wrong value only moves
to the other branch (`h<boolean>(true, true).a` printed `1`), and making the pin loud refuses
`h<boolean>(true, true).a`, which prints `true` on master. A correct build needs a row per pin for
the shared literals, which is [D2850](D2850.md). The attempt is not in the tree.
