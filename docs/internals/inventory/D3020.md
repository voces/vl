### D3020 — a declaration shadowing a narrowed name hides a call's write to the narrowed binding, and the read after the block traps

**loads then traps · clause 1 · found grading [D3019](D3019.md) · the same on master `ad64c62c1` and after D3019 · filed 2026-09-28**

Repro:

    type G = { name: string }
    function mk(): G | null { { name: "a" } }
    let g: G | null = mk()
    function k() { g = null }
    if g != null {
      if true { const g = 5; k(); print(g) }
      print(g.name)
    }
    // vl check: rc 0.  vl run: prints 5, then wasm trap: null reference

#### Mechanism

At `k()` the outer `g` is live-narrowed and `k` writes it, so D2390 would retire the narrowing.
But the retirement works on the name's innermost binding: `crRetire` walks `crChainWidest`, which
stops at the first scope layer that is not a narrowing, and here that layer is the inner
`const g`. Nothing is retired, nothing is banked for the emitter, and when the inner block ends
the outer `g` reads as `G` again. A fix has to retire the shadowed layers in the checker and bank
the retirement at the statement that holds the shadowing block, where the emitter's by-name
retirement resolves to the outer binding again.

#### Ablation

| ingredient removed | outcome | needed? |
| --- | --- | --- |
| the shadowing declaration (`const q = 5`) | refused at `g.name`, naming the call | **yes** |
| `const` (`let g = 5`) | traps | no |
| the `if true` (a bare block) | traps | no |
| the module (all inside a function, `k` a local closure) | traps | no |
| the call before the declaration (`k(); const g = 5`) | refused | **yes** |
