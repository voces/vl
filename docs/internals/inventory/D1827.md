### D1827 — a MAP read inside an `if` used as an EXPRESSION reserves no map scratch frame, so the body reads locals nothing declared

**closed 2026-09-06 — the witness prints `42` · was check-clean invalid wasm · filed
2026-09-06 while closing D1814, whose optional-call desugar excluded a map receiver because
of this row · fixture `tests/cases/maps/map-read-in-if-expression.vl` · matrix
`scripts/capability-probes/matrix/map-read-in-if-expression.matrix.vl`**

Repro:

    const reg: {[string]: i32} = Map()
    function fill() { reg["k"] = 42 }
    fill()
    function condOnly() {
      const v: i32 | null = if reg["k"] != null { 42 } else { null }
      v ?? 0
    }
    print(condOnly())
    // was: `vl check` rc 0, then the emitted module failed to validate inside
    //   `condOnly`: type mismatch: expected i32, found (ref $type). Now prints 42.

#### Mechanism

`fnUsesMap` decides whether a function reserves the 15-slot map scratch frame, and its walk
`exprHasMapOp` tested every operand kind — `Index`, `BinExpr`, `Call`, `Member`, `OptMember`,
`Unary`, `Paren`, `IsExpr`, `AsExpr`, `ObjLit`, `ArrayLit` — then fell through to a bare
`false`. An `if` used as an EXPRESSION is none of those, so the frame was never reserved and
the body emitted `local.get`/`local.set` against fifteen slots the locals vector never
declared. The engine reports that as `unknown local N` where the index is past the vector and
as `type mismatch: expected i32, found (ref $type)` where it collides with a declared local —
two sentences, one missing frame. A `match` desugars to the same if-chain in the checker, so
its arms were lost the same way.

The arm now delegates to `ifChainHasMapOp`, the walk that already owns an `if` chain, so the
statement and the expression spelling cannot reserve different frames. That walk's own default
hands back to `exprHasMapOp` rather than answering `false`, so no kind falls between the two
halves, and `exprHasMapOp`'s default is named rather than bare.
