### D4059 — `k == "a"` over a literal union narrows neither branch, while `k is "a"` narrows both

**open · loud check reject · unruled: guide and compiler disagree (`docs/spec/OPEN-QUESTIONS.md` Q10) · found writing `docs/spec/narrowing.md` (lane SPEC) · filed 2026-10-11 against master `98a4ed71b`**

Repro:

    type K = "a" | "b" | "c"
    function f(k: K): string {
      if k == "a" { return "A" }
      const j: "b" | "c" = k
      j
    }
    print(f("c"))
    // vl check: rc 1, "cannot assign K to 'j' of type "b" | "c""

Want:

    c

#### Mechanism

The guide (`docs/guide/narrowing.md`, "What narrows") states that `x == L` narrows the
then-branch to `x & L` and the else-branch to `x − L`. That is how a literal `is` behaves:
the same program with `k is "a"` runs and prints `c`. A compare against a literal leaves
`k` at `K` in both branches and after an early return. A literal-union `match` after an
`==` guard is therefore refused as non-exhaustive unless it names the tested member again.
A discriminant compare `c.kind == "m"` does narrow the record. The gap is a bare
literal-union value compared with one of its members.

#### Ablation

| variant | outcome |
| --- | --- |
| `if k == "a" { return … }`, then `const j: "b" \| "c" = k` | refused |
| then-branch `const j: "a" = k` | refused |
| `else { const j: "b" \| "c" = k }` | refused |
| `if k != "a" { const j: "b" \| "c" = k }` | refused |
| integer literal union `1 \| 2 \| 3`, `k == 1` | refused |
| `match k { "b" => …, "c" => … }` after the `==` guard | refused, non-exhaustive, missing "a" |
| `if k is "a" { return … }` | runs, prints `c` |
| discriminant `c.kind == "m"` | runs |
