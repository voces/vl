### D4059 — `k == "a"` over a literal union narrows neither branch, while `k is "a"` narrows both

**closed 2026-10-12 by lane CK · runs · was loud check reject · ruled Q10 (a) · found writing `docs/spec/narrowing.md` (lane SPEC) · filed 2026-10-11 against master `98a4ed71b` · pins: `tests/cases/literal-unions/eq-literal-narrows-as-is.vl`, `tests/cases/literal-unions/eq-literal-narrows-boxed.vl`, `tests/cases/literal-unions/error-eq-narrowed-away-member.vl`, `tests/cases/literal-unions/error-eq-string-does-not-narrow.vl`**

Repro:

    type K = "a" | "b" | "c"
    function f(k: K): string {
      if k == "a" { return "A" }
      const j: "b" | "c" = k
      j
    }
    print(f("c"))
    // vl run: prints c

Want:

    c

#### Mechanism

The guide (`docs/guide/narrowing.md`, "What narrows") states that `x == L` narrows the
then-branch to `x & L` and the else-branch to `x − L`. That is how a literal `is` behaves:
the same program with `k is "a"` runs and prints `c`. A compare against a literal left
`k` at `K` in both branches and after an early return. A literal-union `match` after an
`==` guard was therefore refused as non-exhaustive unless it named the tested member again.
A discriminant compare `c.kind == "m"` did narrow the record. The gap was a bare
literal-union value compared with one of its members.

#### Ablation

| variant | outcome |
| --- | --- |
| `if k == "a" { return … }`, then `const j: "b" \| "c" = k` | refused |
| then-branch `const j: "a" = k` | refused |
| `else { const j: "b" \| "c" = k }` | refused |
| `if k != "a" { const j: "b" \| "c" = k }` | refused |
| integer literal union `1 \| 2 \| 3`, `k == 1` | refused |
| `match k { "b" => …, "c" => … }` after the `==` guard | refused, non-exhaustive, missing "a" |
| `if k is "a" { return … }` | runs, prints `c` |
| discriminant `c.kind == "m"` | runs |

#### Grading list

Every refused row of the ablation table should run. Check the else-branch, the post-guard
fall-through and the `!=` direction, at both a string and an integer literal union.

#### Ruling

Q10 ruled 2026-10-12 as (a): `x == L` narrows as `x is L` does (DECISIONS.md §"`x == L` narrows a literal union as `x is L` does").

#### Close

The checker's then and else collectors push the literal fact beside the discriminant one
(`pushLitEqFact`, `compiler/typecheck.vl`), only for an operand whose members are all literals
and not a widening const. The emitter narrows a boxed receiver through the `is` arms
(`narrowIsThen`/`narrowIsElse`, `compiler/emit_classify.vl`), keyed on the literal the checker
banks at the comparison. A position matrix of 296 cells (string and integer unions; then, else,
exiting guard, `!=`, `&&`, `||`, `!`, inside `match`, in a loop; annotated, inferred and
parameter bindings) grades `==` identical to `is` in every cell. The accepted price is the one
`is` pays: a later compare or `match` arm naming a member narrowed away is refused.
