### D9901 — a loop variable over a list of an un-annotated function, bound to a `const` in the body, beside a read at another type, is refused

**loud emit reject · `vl check` rc 0 · `cannot take the generic function `inc` as a value` · clause 2 · found closing [D9760](D9760.md) · present on master `23ac8244a` · filed 2026-10-22 against master `23ac8244a`**

Repro:

    function inc(a) { return a + 1 }
    const u = [inc]
    for f in u {
      const q = f
      print(q(3))
    }
    print(u[0](2.5))
    // vl check rc 0.  vl run: emit error: emitProgram: cannot take the generic function `inc` as a value

Want:

    4
    3.5

#### Mechanism

Not traced. From the ablation only: the loop runs when its variable is called directly, so the
likely place is the flow-read rewrite's loop plan (`monoFlowLoopUse`, `monoFlowRowLoopUse`,
emit_mono.vl), which would decline an alias of the loop variable and leave the element one pin. The nested twin
(`const u = [[inc]]`, `const q = r`, `q[0](3)`) refuses with `unsupported for-in iterable`.

#### Ablation

| ingredient removed | outcome | needed? |
| --- | --- | --- |
| the alias, for `print(f(3))` | runs, `4` `3.5` | **yes** |
| the read at another type after the loop | runs, `4` | **yes** |
| the flat list, for the nested twin | refuses, `unsupported for-in iterable` | no |

#### Grading list

The nested twin; an alias by `let`.
