### D3163 — a `for-in` over a called lambda literal whose list holds a literal union is refused at emit

**loud emit reject · open · clause 2 · found by the #3281 round-2 review (`rv3281r2-5785/a/a09.vl`) · the same on master `b1794003a` · filed 2026-09-29 against master `b1794003a`**

Repro:

    type K = "a" | "b"
    function g(ks: K[]) {
      for e in (() => ks)() {
        print(e)
      }
    }
    g(["a"])
    // vl check: rc 0.  vl run: emitProgram: unsupported for-in iterable

Want:

    a

#### Mechanism

Not localised past the ablation. `forInElemKind` has no rung for a lambda literal called in
place whose result is a literal-union list. A named call, a bound lambda, and the same shape
over `i32`, `string` or a record list all classify.

#### Ablation

| ingredient changed | outcome | needed? |
| --- | --- | --- |
| `mk(ks)`, a named function returning `K[]` | runs | **yes** (the lambda literal) |
| `const f = () => ks` then `for e in f()` | runs | **yes** (called in place) |
| `i32[]`, `string[]` or `C[]` (a record) | runs | **yes** (the literal union) |
| the loop at module scope | the same refusal | no |

#### Grading list

The witness and its module-scope twin.
