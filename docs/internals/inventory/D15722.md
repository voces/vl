### D15722 — a fresh call's record holding a list of records, delivered at a record whose list element stores a field otherwise, is check-clean invalid wasm

**closed 2026-11-12, runs and prints `4` then `4` · was check-clean invalid wasm, clause 1, the same on master `6cc20ecad` · the record copy admits a list field of records under the same rule (`recCopyBoxesAt`, check_fit_rules.vl) and copies it element by element inside the record copy, each element read off the copy loop's own locals (`emitRecListCopyTop`, wasmEmit.vl) · graded by `scripts/capability-probes/matrix/kept-maker-delivery-record-list.matrix.vl` · fixture `tests/cases/structs/kept-maker-record-list-field-copied-at-wider-row-runs.vl` · found grading D15826's twins**

Repro:

    type J = { f: i32 | null }
    type H = { xs: J[] }
    function mk() { { xs: [{ f: 4 }] } }
    const _k: H = mk()
    const y = mk()
    print(y.xs[0].f)
    print(_k.xs[0].f ?? 0)
    // vl run: was invalid module inside the module's top-level code

Want:

    4
    4

#### Mechanism

Not traced past the gate. The record copy's rule (`recCopyBoxesAt`) admits a list field only of
numbers, so `{xs: {f: i32}[]}` into `H` is neither copied nor refused, and the call reaches emit
built at its own row. The list result itself is copied element by element (D15826); the record copy
would need that loop for a list field, with an element slot of its own beside the record's.
