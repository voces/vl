### D15722 — a fresh call's record holding a list of records, delivered at a record whose list element stores a field otherwise, is check-clean invalid wasm

**check-clean invalid wasm · clause 1 · open · found grading D15826's twins (a list in a record result) · the same on master `6cc20ecad`**

Repro:

    type J = { f: i32 | null }
    type H = { xs: J[] }
    function mk() { { xs: [{ f: 4 }] } }
    const _k: H = mk()
    const y = mk()
    print(y.xs[0].f)
    print(_k.xs[0].f ?? 0)
    // vl run: invalid module inside the module's top-level code

Want:

    4
    4

#### Mechanism

Not traced past the gate. The record copy's rule (`recCopyBoxesAt`) admits a list field only of
numbers, so `{xs: {f: i32}[]}` into `H` is neither copied nor refused, and the call reaches emit
built at its own row. The list result itself is copied element by element (D15826); the record copy
would need that loop for a list field, with an element slot of its own beside the record's.

#### Ablation

| spelling | outcome |
| --- | --- |
| this repro | invalid wasm |
| the list itself the result (`function mk() { [{ f: 4 }] }`, `const _k: J[] = mk()`) | runs (D15826) |
| `xs: i64[]` with `mk() { { xs: [4] } }` | runs (the list copy) |

#### Grading list

The same shape with the record one level down (`{ j: { xs: J[] } }`), and a `J[]` element that is
itself nullable.
