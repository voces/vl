### D6401 — a string map key starting with `@` reads as a parameter call in a write summary, so an unrelated key loses its narrowing

**closed — fixed 2026-10-18 by lane L5: a summary part records whether it is a parameter call, rather than the text spelling one · was loud check reject, `'m["ab"]' is no longer narrowed to i32: the call to 'clr' on line 7 may reassign it`, clause 2 · pin: `tests/cases/maps/subscript-narrow-at-key-write.vl` (the witness) · filed 2026-10-18 against master `4cfd7b6b6`**

Repro:

    function clr(m: {[string]: i32 | null}) {
      m["@x"] = null
    }
    const m: {[string]: i32 | null} = Map()
    m["ab"] = 1
    if m["ab"] != null {
      clr(m)
      print(m["ab"] + 1)
    }
    // vl check: no longer narrowed.  Want: prints 2

Want:

    2

#### Mechanism

A part of a write summary spelled `@<i>` meant "calls parameter i", and the reader decided
that by looking for an `@` in the text. The shape `["@x"]` carries one, so the summary read
as a call of an unknown function and invalidated every narrowing on `m`.
