Repro:

    type D = { v: f64 | string }
    const x: i32 | f64 | string = 3
    const o = { v: x }
    const c: {[string]: D} = Map()
    c["k"] = o

    if t is i32 { print(t / 2) } else { print("lost i32") }
    // PRINTS lost i32

#### Mechanism

The destination `f64 | string` holds `i32` only as `f64`, and it already holds `f64` in its own
right, so the box built at `D` stores the `i32` as an `f64`. Nothing can tell the two apart on
the way back: a read at the own type cannot narrow an `f64` that was always an `f64`. The
checker refuses the `| null` twin (`{v: i32 | f64 | null}` into `{v: f64 | null}`: `cannot
assign`), and accepts this one. Either the checker refuses this delivery as it does the twin
(recommended: one rule for both, since no rep can keep the member), or `is i32` over the value
is answered by the value's integrality, which changes what `is` means.

| --- | --- |
| as filed | `lost i32` |

| `x: i32 \| f32 \| string` into `{ v: f64 \| string }` (two members to one) | loud emit reject since #3255 |
