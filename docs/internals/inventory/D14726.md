#### Mechanism

The type parameter `T` is shadowed by the declared record `T`, and the elaboration agrees:
`elabCallParamTy` reads `{g: ({x: i32} | null)[]}`, with the record. `monoClosedTyPin` of it is
`{g:({x:i32}|null)[]}`, which spells the nested record by its fields. That spelling interns as a
structural row, not the declared `T`, so the instance's parameter and its argument disagree:
check-clean invalid wasm (`call[0] expected type (ref 2), found struct.new of type (ref 1)`).
Measured with the shadowing decline removed; with it in place, the composite path answers.
The top-level record arm of `monoClosedTyName` names a declared record. Its render fallback does
not, for one nested in a field, list or nullable.
