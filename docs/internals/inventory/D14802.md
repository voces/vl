### D14802 — a call whose inference leaves a type parameter unbound types its result as a hole, which any destination accepts

**check-clean silently wrong · clause 1 · open · split from [D14801](D14801.md) · filed 2026-11-01 against master `d4033156`**

Repro:

    function G<A>(v: A | i32): A { v }
    const y: boolean = G(5)
    print(y)
    // vl check: rc 0.  vl run: prints `true`

Want:

    a check reject at the call: `G(5)` gives `A` no binding

#### Mechanism

The argument `5` matches the `i32` member of `A | i32`, so the call binds nothing to `A`, and its
result stays an inference hole. A hole is assignable to every type, so the `boolean` binding is
accepted, and the instance stores the `i32` it returns there. A union of two parameters is the
same question with both left open: `function F<A, B>(v: A | B): boolean { v }` then `F(5)`.

Ruling (2026-11-01, coordinator, conditional on measurement): a call whose inference leaves a type
parameter unbound is refused (`cannot infer A`); an explicit type argument binds it.
