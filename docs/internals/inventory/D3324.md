### D3324 — references to an imported name mix the defining module's ranges into the entry document's list, with no file attached

**runs today and must keep running · the defect is not a CLI outcome: `referencesAt` on `L` in the entry below answers `0:13`, `1:38` and `1:9`, where `1:38` is the read of `L` inside `lib.vl` presented as a range of the entry document · pre-existing: identical on master `e70102886`; on #3296 a read in a parameter default (`x: i64 = L`, lib `1:28`) now joins the list the same way · found in the #3296 round-4 review (`lsp2.ts`) · filed 2026-09-29 against #3296 head `fcb70b50e`**

Repro:

    // file: lib.vl
    export const L = 0xFFFFFFFF
    export function lf(x: i64): i64 { x + L }
    // file: entry.vl
    import { L, lf } from "./lib"
    print(lf(L))

#### Mechanism

A prediction until a close confirms it. The symbol table records occurrences from every module
the check walks, keyed by token, and `referencesAt` returns each occurrence of the resolved
binding as a range without its module; the host then places every range in the requesting
document. A reference in another module needs its file attached (an LSP `Location`), or has to
be filtered to the entry document.

#### Ablation

| ingredient changed | outcome | needed? |
| --- | --- | --- |
| `lf` does not read `L` | no foreign range | **yes** (a use of the name inside the defining module) |
| `L` declared in the entry document | all ranges are the entry's | **yes** (the import) |
