### D6500 — a generic's `T[]` result reached through an un-annotated or bare type-parameter argument is refused at emit when it is read, at one type

**loud emit reject · `vl check` rc 0 · clause 2 · CAPABILITY: the direct `g([1]).length` and an element returned as `T` both run, so the result's list type is a delivery the emitter has not classified · found closing [D6482](D6482.md) · filed 2026-10-18 against master `4d1802f96`**

Repro:

    function g<T>(x: T[]): T[] { return x }
    function f(a) { return g(a) }
    print(f([1]).length)
    // vl check: rc 0.  vl run: emitProgram: '.length' on a receiver the emitter cannot classify as a list, string, map or set

Want:

    1

#### Mechanism

From the ablation only. The call `g(a)` with `a` a hole (or a bare declared `A`) leaves its
result typed `T[]` with `T` unbound in `f`'s body, and the reader at the instance cannot
classify that receiver. The result is never read as a list when it is returned as `T`, so
that spelling runs.
