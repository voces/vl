### D3105 — a written `(T | i32)[]` whose type parameter pins to the concrete member is refused at emit

**loud emit reject · clause 2 · open · found grading a candidate close of [D3079](D3079.md) (lane GV's `joinann` cells) · the same on master `d408f2da4` · filed 2026-09-28 against master `d408f2da4`**

Repro:

    function f<T>(x: T) {
      const l: (T | i32)[] = [x, 7]
      print(l.length)
    }
    f(3)
    // vl check: rc 0.  vl run: emitProgram: only i32[] arrays and struct/union element arrays are supported

Want:

    2

#### Mechanism

Not localised past the ablation. At `T = i32` the written annotation substitutes to the spelling
`(i32 | i32)[]`, whose two members are one type; the direct spelling `const l: (i32 | i32)[]`
runs and prints `2`, so the instance's substituted annotation is read as a union list with no
element rep rather than collapsing to `i32[]` as the direct one does. `f64` beside `f64` runs.

#### Ablation

| ingredient changed | outcome | needed? |
| --- | --- | --- |
| `function f(x: i32)` with `(i32 \| i32)[]`, the direct spelling | prints `2` | **yes** (the type parameter) |
| `f("s")`, a `string` pin beside `i32` | prints `2` | **yes** (the pin is the other member) |
| `(T \| string)[]` with `[x, "a"]` at `f("s")` | emit reject | no |
| `(T \| f64)[]` with `[x, 7.5]` at `f(1.5)` | prints `2` | **yes** (an `i32` or `string` member) |
| an un-annotated `const l = [x, 7]` | prints `2` | **yes** (the written annotation) |
