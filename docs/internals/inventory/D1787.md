### D1787 — the list-literal comment anchor read the WHOLE span, so a comment inside a lambda ELEMENT froze a construct that had no defect

**closed 2026-09-06 — the witness runs and the lambda body is reformatted · was a `vl fmt` layout FREEZE on a `vl check`-clean program · fixed by testing the gaps between the items rather than the node's whole span**

Repro (runs, prints `3` then `2`):

    function apply1(f: (i32) => i32) { f(1) }
    const zs = [
      (v: i32) => {
            // tripling
            const   w=v*3
            w
      },
    ]
    const ws = apply1((v: i32) => {
          // doubling
          const   u=v*2
          u
    })
    print(zs[0](1))
    print(ws)
    // vl check: rc 0.  vl run: 3 then 2.
    // vl fmt: `ws`'s body is reformatted (`const u = v * 2`, at one indent);
    //         `zs`'s is NOT — the list element keeps its six-space indent verbatim.

#### Mechanism

The witness RUNS, and the status line says so, for [D1647](D1647.md)'s reason: the defect is
in a tool the witness grader does not drive.

[D1776](D1776.md) anchored a comment-bearing list literal by testing `commentInCharSpan` over
the node's WHOLE span and falling through to `sliceFallback`. That is one test too coarse. A
comment inside an ITEM is not homeless: a block-bodied lambda renders through `blockExpr`,
which flushes the comments in its own body at its own indent, and the same holds for an `if`
expression, a `match`, and a nested literal once it carries this anchor too. Only the
construct's own PUNCTUATION — before the first item, between two items, after the last — has
no printer to host a comment.

So the whole-span test froze every list holding such an item, which is a formatter declining
to format rather than a comment moving. `commentInListGaps(from, stop, items)` walks the items
in order, asks `commentInCharSpan` of each gap, and answers no for an item with no span; all
three printers ([D1777](D1777.md) adds the other two) take it.

Nothing in the tree carries the shape, which is why the tree sweep could not see it: the
witness came from writing the negative control for D1777's fix before believing it.

Not needed: the item kind beyond that, the list length, or the element type.
