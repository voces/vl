### D3509 — a `K | L | null` parameter passed to a type parameter beside a string builds invalid wasm

**closed 2026-10-03 — the witness prints `false` then `true` · was check-clean invalid wasm · clause 1 · fixture `tests/cases/generics/nullable-fold-nominal-lists-and-literal-box.vl` · found by #3339's review (witness W5) · filed and closed against master `937445a42`**

Repro:

    type K = "a" | "b"
    type L = "c" | "d"
    function F<A, B>(a: A, b: B): A | B { return a }
    function g(kl: K | L | null) {
      const u = F(kl, "q")
      print(u == null)
    }
    g("c")
    g(null)
    // vl check: rc 0.  vl run (master): invalid module

Want:

    false
    true

#### Mechanism

The instance pins `A` at the softened `string | null`, so its parameter and result are the
nullable string, while the caller held the `{tag, anyref}` box and typed the result as the box's
union. Closed with [D3504](D3504.md)'s fold, which folds a `(K | L) | null` binding as the
`string | null` its instance reads, and [D3382](D3382.md)'s argument and return positions, which
convert the box to that niche (`emitBoxToNulStr`).
