#### Mechanism

An assignment to a name lowers as a value by storing and re-reading the name
(`assignTargetReReads` answers true for every `Ident` target), while the checker types the
assignment at its right side: `i32` for `5`. Where the name's storage is wider than that type,
the re-read pushes the storage rep (`f64`, or a nullable ref for `i32[] | null`) into a
position typed at the right side's. [D2285](D2285.md) settled the same disagreement for a
closure's boxed cell by yielding through `const t = e; v = t; t`; the plain name has no such
rewrite. [D2394](D2394.md)'s close covers only the right sides the place's type built (a
container literal, or a union in another member order), where the assignment now yields the
place's type; these right sides are values of their own type the place merely accepts.

The close is D2285's temp applied to plain names, before collection (`assignValueSpill`,
`emit_rewrite.vl`). A value-position write whose name's storage type (`asgStoreTyOf`, which
the checker banks because a narrowed read type hides it) is not the value's type moves ahead
of its statement as `const v = e; a = v`, and the statement reads `v`. It moves only off a
statement's leading evaluation path: every operand evaluated before it is a literal or a name
the write cannot change. A value tail (`function bump() { g = 9 }`, arm by arm under a tail
`if`) becomes `const v = e; a = v; v`. At module scope the moved write keeps its statement's
start-function order (`startOrderKey`). The checker's alias walk now follows an assignment's
value to what consumes it, which is [D2411](D2411.md).
