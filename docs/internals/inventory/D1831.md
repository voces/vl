#### Mechanism

The literal's classifiers do not distinguish the two spellings. A probe in `collectU`'s
array-literal loop prints, for the annotated `(P | null)[]` and the bare `[{n: 42}, null]`:

    PROBE lit ty=({n:i32}|null)[] elem={n:i32}|null isRef=1 nulRef=[] nulNum=[]

Identical, and the annotated one RUNS — so what registers its row is the ANNOTATION, and the
element the literal infers is the ANONYMOUS shape `{n:i32} | null`, which nothing interns.
`arrLitNulRefElemName` — the ref twin the numeric arm's `nulNumScalarUnionName` suggests —
answers `""` for all three spellings, so there is no ready producer to call: a nullable struct
element wants the nullable-ref NICHE and an anonymous struct ROW, not a value box.

Three messages, one mechanism, which is why the message must not name the family: the `!= null`
guard says `struct equality is not supported yet`, an `is P` guard says `` `is` test but no
union type declared ``, a nested literal says `ref valtype with no interned shape`, and the
map-value delivery says `cannot compare {n: i32} with null` — from the CHECKER, not the
emitter.

It is ORDER-dependent in the same way D1830 was spelling-dependent: `[null, {n: 42}]` RUNS,
because `arrLitIsRef` is a first-element probe and answers 0 there. `e.get(0)` runs too.

#### Refused candidate, and its price

Registering the element through the `aeu` arm's own pair — `collectTyMembersReach` then
`registerInlineUnionAt` over `tyToEmitName` of the element type — moves **zero** cells of the
11-cell grid. That route mints a value-union BOX row, and a nullable struct element is a niche;
the candidate adds a registration nothing reads. What remains is minting the anonymous struct
row and its nullable-ref list slot — the `#anon` family — which is larger than the one-line
sibling this row was expected to be.
