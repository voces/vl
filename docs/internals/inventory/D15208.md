### D15208 — an expression-bodied arrow whose result is a record holding a list of un-annotated functions is refused at emit

**closed · runs, prints `4` · was loud emit reject, `emitProgram: ref valtype with no interned shape`, clause 2 · found closing [D15203](D15203.md) · filed 2026-11-03 against master `aaf9ba5c` · the mechanism was any function's TAIL value, not the arrow: fn-tag read a function body's last statement as no holder of the set's ids, where a `return`'s value is one (`ftHoldCtxOk`), so the record's list of the set stayed untagged and its field had no code; fixed by reading a function body's tail as its result (`ftFnBodyTail`); residue [D15290](D15290.md); named set `d15208-tail-holder`**

Repro:

    function inc0(a) { return a + 1 }
    const mk = () => ({ fs: [inc0] })
    print(mk().fs[0](3))

Want:

    4

#### Mechanism

An arrow's expression body is a one-statement `Block`, so its record is the body's tail value. fn-tag (`ftHoldCtxOk`) accepted a holder whose parent is a `return` delivering the inferred result, and a `Block` parent only when the block's own type is the holder's, which a function body never has; the singleton set `{inc0}` stayed untagged, `anonFieldCode` gave the untagged list field -1, and the record minted no row. A named function's tail (`function mk() { { fs: [inc0] } }`) failed the same way.
