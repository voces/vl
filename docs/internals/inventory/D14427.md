### D14427 — a choice of hole functions in a record field called at a closed type is tagged on a stale call note, while the field is built as a closure

**closed 2026-10-27 by making a call through a set a per-check fact, cleared with the type facts in `fnTyFactsReset` · was check-clean invalid wasm, clause 1 · found grading c-3's un-annotated stamp against the annotated face · filed 2026-10-27 against master `41c611055` · pins: `tests/cases/closures/hole-fn-choice-in-record-field-called-closed.vl`, `tests/cases/closures/hole-fn-choice-in-record-field-beside-closed-escape.vl`**

Repro (runs, prints `6`):

    function idg(t) { return t }
    function kg(t) { return t + t }
    const c = [1].length > 0
    const r = { h: if c { kg } else { idg } }
    print(r.h(3))

#### Mechanism

The first check types `r.h(3)` through the set {kg, idg} and notes the call. The record is then
pinned at the call's closed type `{h: (i32) => i32}` and the program is checked again, where
the record literal's field is a delivery into a closed function type and is noted as an
escape. The call notes outlived that restart, so the decision tagged the set on the account of
a call the final check types as a closure call. The field was built as a closure at its slot,
and the call dispatched on a tag read out of the closure: invalid wasm.

A set's rep is one fact, decided from the calls of the check that last typed them. Call notes
are now cleared with the type-indexed facts, so the call is a closure call, the set stays
untagged, and the field and the call agree.
