### D2871 — a list literal around a generic call returning a record, inside a generic body, has no interned shape

**closed by the D2850 constructor mint · clause 2 · found by the #3225 review · the same on master `93b93319e` · filed 2026-09-27 against master `93b93319e`**

Repro:

    function pc<T>(x: T) { { a: x } }
    function k<T>(t: T) {
      const xs = [pc(t)]
      print(xs.length)
      0
    }
    k(1)
    // vl check: rc 0.  vl run: emitProgram: ref valtype with no interned shape

Want:

    1

#### Mechanism

Not localised. The literal's element is the record `{a: T}` pinned per instance; the list of that
record has no ref-list row at the pin, so the local's valtype names no shape. [D2849](D2849.md)
types the re-made literal but a record element needs its row interned at the pin too.

#### Ablation

| ingredient changed | outcome | needed? |
| --- | --- | --- |
| the call bound first (`const r = pc(t); [r]`) | same reject | no |
| a list result (`pc<T>(x: T) { [x] }`) | runs (D2849) | **yes** |

#### Grading list

The same at `string` and `boolean` pins.

#### Close

`pc` is a constructor, so [D2850](D2850.md)'s mint gives `{a: T}` its row at each pin, and the
list of it then has a row. Graded 2026-10-20: the witness prints `1`. `k(1)` beside `k("s")`
prints `1 1 1 s`, and `k(true)` alone prints `1 true`. `k(1)` beside `k(true)` still refuses,
now as `struct array elements are not supported`, filed as [D8240](D8240.md). Pinned in
`objects/record-holding-hole-call-result.vl`.
