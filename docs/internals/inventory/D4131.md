### D4131 — a union held in a record field and narrowed to a record by path keeps the narrowing across a write to the object through another place

**closed 2026-11-01 by lane step7 · now a loud check reject (`'h.v' was narrowed by a guard, but the assignment to 'base.x' on line 7 can write it`): a path narrowed to a record keeps the field entries a name does · was check-clean silently wrong · pin: `tests/cases/soundness/record-path-narrowing-retired-by-alias-write-reject.vl` · found in the #3568 review (rv3568 `u/infield.vl`) · filed 2026-10-11 against master `efd3c3f15`**

Repro:

    type A = { x: i32 }
    type B = { x: 1 | 2 }
    type H = { v: A | B }
    function f(base: A) {
      const h: H = { v: base }
      if h.v is B {
        base.x = 7
        const y: 1 | 2 = h.v.x
        print(y)
      }
    }
    f({ x: 1 })
    // PRINTS 7

#### Mechanism

`h.v is B` pushes a path narrowing for `h.v` at the record `B`. A write ends a path
narrowing only when it may reach the narrowed place itself; `base.x = 7` writes the field
`x` of the object `h.v` holds, a place below the narrowed one, so `h.v` stays narrowed and
`h.v.x` reads as `1 | 2` while it holds `7`. A bare binding narrowed the same way pushes
an entry per wider field (`narFitCompanions`), which the write then ends; a path
narrowing to a record pushes none.

#### Ablation

| ingredient changed | outcome on master | needed? |
| --- | --- | --- |
| the write removed | prints 1 | **yes** |
| the write through a closure `k()` | prints 7 | no (any aliased write) |
| the write spelled `h.v.x = 7` | check reject, `7` is no `1 \| 2` | **yes** (the write goes through another place) |
| the narrowed field a scalar union, write through an alias of `h` | check reject (the path rule ends it) | control |
| the read before the write, `h.v.x` printed after it | prints 1, then 7 | no |

#### Grading list
