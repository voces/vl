### D16060 — a field read through an un-annotated parameter of a record union stays typed at the hole in its instance, so the print plan learns the members from the name rung

**runs today and must keep running · 2 programs of the sweep population · filed 2026-11-12 against master `a16e7550`**

Repro:

    type K = { h: i32 }
    type J = { h: string, z: i32 }
    const k: K = { h: 4 }
    const u: K | J = k
    function ret(a) { return a.h }
    const r = ret(u)
    print(r)
    // vl check: rc 0.  vl run: prints `4`

Want:

    4

#### Mechanism

The print is planned over the box `r` holds, `i32 | string`. Every type source for the read
answers the open hole: `nodeTyAt`, `elabNodeTyAt`, `nodeTyInOf` and `exactOperandTyOf`. The
instance of `ret` at `K | J` never typed `a.h` at the arms' field union. No member set is
keyed by a hole, so `printUnionPlanCode` takes the members from `unionNameOfExpr`, whose rung
read the arms' fields. That name read is the plan's one floor. Lane H's probe found it
reached by this witness and by `tests/cases/unions/shared-mixed-field-read-through-hole-param.vl`,
and by no other program.
