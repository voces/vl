### D7621 — each module's rename map rebuilt its two sid-indexed views as fresh arrays padded to the highest sid in the program

**closed 2026-10-20 by lane perf · runs, prints `hi!` and `3` · no wrong value, a cost row · `modRenameClear` (compiler/driver.vl) keeps `modRenameFirstBySid`/`modRenameLastBySid` across modules and resets only the slots the previous map set, by position · serial diderven `vl check src` `sidArrPut` 0.98% to 0.11% of samples; combined fuel with D7620 and D7622 is on D7620 · filed against master `7498f679e`**

Repro:

    // file: dep.vl
    export function shout(self: string): string { self + "!" }
    export const two = 2
    // file: main.vl
    import { shout, two } from "./dep"
    print("hi".shout())
    print(two + 1)

Want:

    hi!
    3

#### Mechanism

`modBuildRename` ran once per module in `modCollectSelfFns` and again in the rewrite loop, and each
run set both sid views to `[]` before pushing rows. `sidArrPut` pads an array with `-1` up to the sid
it writes, so the first row naming a late-interned symbol padded the array to that sid. Every module
paid O(highest sid) in the merged program, which grows with the graph, so the total was quadratic in
the graph's size. Clearing only the slots the previous map set keeps the views' contents identical
at every read, including after a `sidReset`, since the reset is by slot number rather than by name.
