### D3818 — an overloaded member call on a local that aliases an un-annotated parameter is refused, because only a parameter receiver is re-dispatched per instance

**loud check reject · 1 cell of the `overload-receiver-list` matrix · filed 2026-10-07 against lane OV's branch**

Repro:

    import { lastIndexOf } from "std:array"
    import { lastIndexOf } from "std:str"
    function take(a) {
      const v = a
      print(v.lastIndexOf(2))
    }
    take([1, 2, 3, 2])
    // vl check: `.lastIndexOf(…)` cannot choose … because the receiver is not a parameter of the function the call sits in

Want:

    3

#### Mechanism

A receiver whose type each instance supplies picks its candidate per instance
(`ovHoleCallTy` in the checker, `monoPinBinOps` in the emitter). The emitter re-dispatches a
member call per instance only when its receiver is one of the generic's own parameters
(`ufcsSitePinnable`, `drwRecvIsTyParam`, D2520), so the checker refuses every other hole
receiver rather than let one instance's choice serve all. The same call on `a` itself runs.

#### Ablation

| ingredient removed | outcome | needed? |
| --- | --- | --- |
| the alias (`a.lastIndexOf(2)`) | runs | **yes** |
| the second candidate (one import) | runs | **yes** |
| the annotation's absence (`a: i32[]`) | runs | **yes** |
