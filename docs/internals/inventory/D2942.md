### D2942 — a hole value at a literal-union pin prints its atom `0` through a capture, `id`, `idh` or a lambda chain

**check-clean silently wrong · clause 1 · open · the #3239 review's `cap`, `capx`, `id`, `idh` and `chain` cells at `"a" | "b"` · filed 2026-09-28 against master `cab9694f8`**

Repro:

    function h(x) {
      const l = [x]
      const y = l[0]
      const k = () => y
      print(k())
    }
    const a: "a" | "b" = "b"
    h(a)
    const s: string = "s"
    h(s)
    // vl check: rc 0.  vl run: prints `0` then `s` (invalid wasm on master `cab9694f8`)

Want:

    b
    s

#### Mechanism

Not localised. A literal-union value is an interned `i32` atom. Read back through a capture, a
generic call or a lambda chain, it is typed at the hole's variable, so `print` takes the `i32`
path and prints the atom. Run alone (no second instance) the capture is a loud emit reject
(`print of a literal-union atom whose type carries no member texts`). The `id(l[0])`, `idh(l[0])`
and `chain` spellings print `0` alone too, the same on master.

#### Ablation

| ingredient changed | outcome | needed? |
| --- | --- | --- |
| the `string` instance removed | loud emit reject | no (a different outcome) |
| `print(l[0])` directly, with the `string` instance | prints `0`, `s` (the same on master) | no |
| `print(l[0])` directly, alone | runs, `b` | **yes** (another instance, or a capture) |
