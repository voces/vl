### D3141 — a second instance whose record field function returns `i32 | null`, called through a capture, is typed at the first instance's scalar field

**check-clean invalid wasm · clause 1 · 6 cells of lane FF's `ff1` grid (`*__cap__{b,i,s}_n`), beside 2 loud `*__cap__f_n` and 4 trapping `hole__bind__*n*` cells of the same field pair · the same on master `07d414042` · filed 2026-09-29 against master `07d414042`**

Repro:

    function F<Z>(z: Z) {
      const k = () => z.f()
      print(k())
    }
    const r0 = { f: () => true }
    F(r0)
    const r1 = { f: (): i32 | null => null }
    F(r1)
    // vl check: rc 0.  vl run: invalid module inside `__lambda_4`, expected i32, found (ref $type)

Want:

    true
    null

#### Mechanism

Not localised past the ablation. The two records share one anonymous row, which records the
first literal's `() => boolean`. The second instance's capturing lambda is typed from that
row, so it returns `i32` while the call inside it now produces the `i32 | null` value box.
D3110 binds an instance's own record type for its parameter; the capturing lambda's result is
the position that still reads the row. The hole spelling that binds the field by name calls
the second closure through the first's signature and traps.
