### D16334 — a value an un-annotated map is set to from a call through hole parameters reads back as `null` once bound

**closed 2026-11-14 — the witness runs and prints `11` · was: check-clean silently wrong · clause 1 · the un-annotated `map_value`, `map_set` and `map_value_place` cells of `hole-lambda-arg-through-hole-callee.matrix.vl` (there an invalid module, SILENT on master) · found grading [D16310](D16310.md)'s close · filed 2026-11-14 against master `b09064cee`**

Repro:

    function lap(g) { return g(1) + 1 }
    function use(k) { return k((a) => a * 10) }
    const m = Map()
    m["k"] = use(lap)
    const mv = m["k"]
    print(mv)
    // PRINTS null

Want:

    11

#### Mechanism

Not traced. The value is the result of a call whose callee and argument are both un-annotated
parameters (`use(lap)` calls `lap` through `k`). A result of a plain function set into the same
map reads back right, and so does the map read directly in `print`.

**Closed.** The check types a call through a hole parameter from the function bound to it (`holeCallInstOf`, check_relate_core.vl). Bound to a declared un-annotated function, its own open signature carries no lambda's parameter type, so the result stayed open. The parameter's binding now names that function (`holeDeclOfFnTy`, from the hole its first parameter names), and the call is typed as the direct call is (`holeDeclCallInst`): each lambda argument at the closed types the function's body calls that parameter at, then the body at the closed arguments. Grid `hole-call-through-declared-hole-fn.matrix.vl`.
