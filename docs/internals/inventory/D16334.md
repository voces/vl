### D16334 — a value an un-annotated map is set to from a call through hole parameters reads back as `null` once bound

**check-clean silently wrong · clause 1 · the un-annotated `map_value`, `map_set` and `map_value_place` cells of `hole-lambda-arg-through-hole-callee.matrix.vl` (there an invalid module, SILENT on master) · found grading [D16310](D16310.md)'s close · filed 2026-11-14 against master `b09064cee`**

Repro:

    function lap(g) { return g(1) + 1 }
    function use(k) { return k((a) => a * 10) }
    const m = Map()
    m["k"] = use(lap)
    const mv = m["k"]
    print(mv)
    // PRINTS null

Want:

    11

#### Mechanism

Not traced. The value is the result of a call whose callee and argument are both un-annotated
parameters (`use(lap)` calls `lap` through `k`). A result of a plain function set into the same
map reads back right, and so does the map read directly in `print`.

#### Ablation

| spelling | outcome |
| --- | --- |
| the witness | prints `null` |
| `m.set("k", use(lap)); const mv = m.get("k")` | prints `null` |
| `if mv != null { print(mv) }` | prints nothing |
| `print(m["k"])`, no binding | runs, `11` |
| `m` annotated `{[string]: i32}` | runs, `11` |
| `m["k"] = f()` for a plain `f` returning `14` | runs, `14` |
| `const mv = use(lap)`, no map | runs, `11` |
| the matrix cell, which adds `useC(lap)` | check-clean invalid wasm |
