### D15174 — an un-annotated map of functions handed to a hole parameter that calls a value it reads by `get` has no call to emit

**closed · runs, prints `6` · was loud emit reject, `emitProgram: callee is not a function name` · clause 2 · found closing [D15167](D15167.md), the map half of [D15161](D15161.md) · filed 2026-11-03 against master `93bcb08d7` plus the D15167 PR · closed 2026-11-04: mono pins the hole from the elaboration's binding of it, a map of the set's ids, by its `{[K]: i32}` storage (`elabCallParamBoundTy`, `monoPinHoleParam`), and the `get` read it rewrites to an index carries the pinned read type and registers its box (emit_mono.vl) · fixture `tests/cases/closures/fn-map-get-through-hole-param.vl`**

Repro:

    function half(a) { return a * 2 }
    const m = Map()
    m.set("b", half)
    run(m)
    function run(m) {
      const g = m.get("b")
      if g != null { print(g(3)) }
    }
    // Want: 6

#### Mechanism

Mono's `monoPinHoleParam` re-derived the hole's pin from the argument (`monoArgTaggedSetTy`), which
knew a tagged function and a list of one, not a map of one; the pin fell to `monoArgPinName`'s
`i32` floor and demanded `?run.0=i32`, an instance no call has, while the elaboration held
`?run.0={[string]: (_) => _}`. At `i32` mono's `get` → index rewrite (D1522) did not fire, so the
call fell through to `callee is not a function name`. With the pin read from the elaboration, the
rewritten index was minted after the collect pass that boxes a function map's read (D15139), so it
registered no box (`scalar map read has no value-box type`) until it registered its own.
