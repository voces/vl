### D2661 — a hole parameter's instance pinned by a `let x = null` argument lowers the parameter at the hole's final `T` while the call passes `nullref`

**check-clean invalid wasm · clause 1 · pre-existing on master `979323f83` · found by the #3188
review's `m11` witness · filed 2026-09-26 against master `979323f83`**

Repro:

    function take(v) { const ys = [v]; ys.length }
    function main() {
      let x = null
      print(take(x))
      x = 5
    }
    main()
    // vl check: rc 0.  vl run: the emitted module failed to validate inside `take`

#### Mechanism

Not traced. The call pins `v` to `x`'s open hole. The later `x = 5` fills that hole in place,
so the instance of `take` is built for `i32 | null`, while the body's list literal `[v]` and the
argument at the call disagree about the rep: `take` expects an `i32` and receives a boxed ref.
With two such bindings filled differently (`x = 5`, `y = "s"`), both calls share one instance.
Leaving the hole unfilled also fails, in `main` this time: `expected i32, found nullref`.

#### Ablation

| ingredient removed | outcome | needed? |
| --- | --- | --- |
| `x = 5` removed | still invalid wasm, in `main` (`found nullref`) | no — the open hole alone |
| `const ys = [v]` replaced by `print(v)` | runs (the #3188 review's `show(x)` control prints `null`) | **yes** — the list literal over `v` |

#### Grading list

* The review's two-binding form: `take(x)`, `x = 5`, `let y = null`, `take(y)`, `y = "s"`.
* Whether D2506's call refusal should extend to an argument that is itself an open hole; the
  plain `show(x)` with `print(v)` runs on master, so it cannot be refused wholesale.
