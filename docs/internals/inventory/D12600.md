Repro:

    type P = { a: i32, b: i32 }
    type Rows<T> = { base: i32, count: i32 }
    function g<T>(_r: Rows<T>, x: T): T { x }
    function mk<T>(b: i32): Rows<T> { return { base: b, count: 1 } }
    const su = mk<P>(8)
    const q = g(su, { a: 3, b: 4 })
    print(q.a + q.b)
    // vl check: rc 0.  vl build: unsupported argument type for `_r` in a call to `g`

#### Mechanism

The monomorphizer types a phantom-parameter argument from the binding's written spelling
(`Rows<P>`). An un-annotated binding has none: `mk<P>(8)` and a bare `{ base, count }` record
both resolve to the record every `Rows<_>` shares, so the instance argument has no type to
name and the call is refused. The checker binds `T` from `x` and accepts.

#### Ablation

| ingredient changed | outcome | needed? |

| `const st = { base: 1000, count: 4 }` passed as `g(st, 5)` | the same refusal | no (any un-annotated source) |
| `Rows<T>` uses `T` (`items: T[]`) | runs | **yes** (the phantom parameter) |
