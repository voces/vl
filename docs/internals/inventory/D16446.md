#### Mechanism

Parked on Rep ADT stage 4, rows keyed by `tyRepId` (lane E's design note 2026-11-14-rep-adt-design.md
§5, row 4; lane E lists this row among stage 4's acceptance rows). A maker called more than once
keeps its own record, so the call `s` holds must be copied into the literal's element
(`recSpreadCallCopy`) and the binding must hold the copy's row. The existing binding-row channel
serves that: the call's rep stamp, read by `exprStoredRepTy` ahead of `fnRetRepTy` (measured,
scratch). The un-annotated face then runs (a copy loop of `f64.convert_i32_s` fills `s`), but
with an annotated destination (`const v: { x: f64 }[] = [{ x: 2.5 }, ...s]`) the stamp is the
annotation's `{x: f64}[]`, a type id with no collected row, so `listRowOfExpr` answers -1 and
the binding falls back to `{x: i32}`: 25 SILENT cells of a 46-cell grid. Two list types that
store alike land on one row only once rows are keyed by rep identity, `tyRepId` of the element
(H: final after `canonRepFinal`; the element's id plus the list kind for a `readonly` view),
which replaces the spelling key in `rlSlotOfTy` / `listRowOfExpr` / `recListRowTy`.
