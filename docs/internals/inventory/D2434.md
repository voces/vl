### D2434 — written type arguments annotating an open lambda replaced a field name or a string-literal member that spelled a type parameter

**closed 2026-09-25 — the filed repro RUNS and prints `3` · was a loud check reject of a type-valid program · found by #3155's second review round (`rv3155r2-p/fld.vl`) · filed 2026-09-25 against master `57238edf4`**

Repro:

    function ap<K>(f: ({ K: K }) => i32, x: { K: K }): i32 { f(x) }
    print(ap<string>((o) => o.K.length, { K: "abc" }))
    // was: no field 'K' on {string: string}

#### Mechanism

`annotateTyArgLambdas` (#3155) annotates an un-annotated lambda parameter with the callee's
declared parameter spelling, its type parameters replaced by the written type arguments. The
replacement ran over the rendered TEXT and swapped every whole identifier equal to a type
parameter, so `{ K: K }` at `K = string` became `{string:string}` and `(A | "A")` at `A = i32`
became `(i32|"i32")`. The fix renders the declared spelling TREE instead
(`ast.tsToNameSubst`), replacing only `TS_NAME` leaves and a map spelling's key — the type
positions — so a field name, a method name and a literal member keep their text.

#### Ablation

| ingredient removed | outcome | needed? |
| --- | --- | --- |

| the lambda parameter annotated by hand | ran | **yes** |
| a string-literal member `"A"` beside `A` instead of a field | the same refusal | no — the same mechanism |
