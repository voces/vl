### D15325 — a list holding a holder's record, its element copied and called at one signature beside a place call at the other, refuses at emit

**open · loud emit reject · clause 2 (`emitProgram: a function returning a parameter called at two signatures is called where its result is not used at one of them`) · owned by lane bundle · the list half of [D15324](D15324.md) · filed 2026-11-04 against master `b7e08d5a8`**

Repro:

    function lap(f) {
      const _a = f(2.5)
      const _b = f(3)
      return f
    }
    const u = lap((a) => a + 1)
    const xs = [u]
    const v = xs[0]
    print(v(4))
    print(xs[0](1.5))

Want:

    5
    2.5

#### Mechanism

Not the field half's. A probe that logged every writer of a binding's annotation logged none for
the list. A probe in the slot note showed no slot candidate noted at all (`elabResSlotCalls` is
empty), so the read `u` in `[u]` fails one of the candidate tests (`elabResStoredRead`,
`elabResInLiteral`, `elabSlotHolderOf`) in this spelling, though it passes them when both calls go
through `xs[0]` in one interpolation. Which test fails is not yet measured.

#### Ablation

| spelling | outcome |
| --- | --- |
| both calls in one interpolation, `"\{v(4)} \{xs[0](1.5)}"` | runs |
| the record field instead, `{ f: u }` | runs (D15324) |

#### Grading list

- The function-body spelling, and `const v = xs[0]` called at both signatures.
