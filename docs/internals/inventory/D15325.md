### D15325 — a list holding a holder's record, its element copied and called at one signature beside a place call at the other, refuses at emit

**closed 2026-11-04 by this PR (lane bundle) — the repro now RUNS and prints the Want below: slot candidates are read off the literal or store that writes them, not off the write scan's index. Was: loud emit reject · clause 2 (`emitProgram: a function returning a parameter called at two signatures is called where its result is not used at one of them`) · the list half of [D15324](D15324.md) · filed 2026-11-04 against master `b7e08d5a8`**

Repro:

    function lap(f) {
      const _a = f(2.5)
      const _b = f(3)
      return f
    }
    const u = lap((a) => a + 1)
    const xs = [u]
    const v = xs[0]
    print(v(4))
    print(xs[0](1.5))

Want:

    5
    2.5

#### Mechanism

Not the field half's. A probe that logged every writer of a binding's annotation logged none for
the list. A probe in the slot note showed no slot candidate noted at all (`elabResSlotCalls` is
empty), so the read `u` in `[u]` fails one of the candidate tests (`elabResStoredRead`,
`elabResInLiteral`, `elabSlotHolderOf`) in this spelling, though it passes them when both calls go
through `xs[0]` in one interpolation.

Measured with a marker per candidate test: both literal tests (`elabResStoredRead`,
`elabResInLiteral`) failed because they read the write scan's index (`cwIxUpKind`, `cwIxParent`)
before anything had built it, and an unbuilt index answers "not there". So a candidate was noted
only when an earlier query in the compile happened to build the index, which is why the outcome
flipped with the spelling. A probe that trapped on any read past the index, run over 7,430 corpus
files, found the same reader reading nodes emit had minted after a build in 429 of them.

The candidate scan now reads each slot value off the literal or store that writes it: an array
literal's elements, a record literal's field values, `m[k] = v` and `m.set(k, v)`
(`elabResScanSlots`). It reads no index, so it depends on no other query having built one. The slot
note, which builds the index, re-checks every candidate as before. Building the index before the
scan was measured too and rejected: +21% peak live on the plumb unit.
