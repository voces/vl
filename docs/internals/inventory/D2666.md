### D2666 — a tail `if` whose arms assign an `i32`-keyed and an `i64`-keyed map builds an invalid function

**check-clean invalid wasm · found in the #3191 review · filed 2026-09-26 against master `525837973`**

Repro:

    function m32(): {[i32]: i32} {
      const m: {[i32]: i32} = Map()
      m[3] = 30
      return m
    }
    function m64(): {[i64]: i32} {
      const m: {[i64]: i32} = Map()
      m[3 as i64] = 64
      return m
    }
    let ga = m32()
    let gb = m64()
    function fc(c: boolean) {
      if c { ga = m32() } else { gb = m64() }
    }
    const r = fc(false)
    print(gb[3 as i64] ?? -1)
    print(ga[3] ?? -1)
    // vl check: rc 0.  vl run: invalid module, `fc` fails validation

#### Mechanism

The checker types `fc`'s result as the union of the two map types. The emitter's arm join sees
two `map` cells with different shapes and declines, so the tail `if` has no single cell. The
function's result valtype then comes from the stored inferred kind, which does not describe
the value either arm pushes. The union box that a two-map result needs is never built. The
program behaves identically on master and on #3191.

#### Ablation

| ingredient removed | outcome | needed? |
| --- | --- | --- |
| the `i64` key (both arms `i32`-keyed) | runs | **yes** |
| the `if` (a straight tail `gb = m64()`) | runs | **yes** |
