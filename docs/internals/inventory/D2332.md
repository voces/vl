### D2332 — a list `.slice` stored its receiver and length in the shared map/filter frame before evaluating its bounds, so a slice, `.map` or `.filter` in a bound overwrote them

**closed 2026-09-24 — the witness prints `3` and `30`. Filed against master `816bda01e`, where it loads then traps with `index outside the bounds of an array`; with other lengths it is silently wrong. Found by the D2331 sweep**

Repro:

    const a = [10, 20, 30, 40, 50]
    const b = [1, 2, 3]
    const s = a.slice(b.slice(1, 3)[0])
    print(s.length)
    print(s[0])
    // prints 30

#### Mechanism

`emitArrSlice` evaluated the receiver into `srcL`, derived its length into `auxL`
(`mfScratchBase + 2`), then evaluated `start` and `end` one at a time into `startL`/`endL`.
The three i32 slots are the function's one `.map`/`.filter` frame, and `srcL` is that frame's
source slot for the rep, so a `.slice`, `.map` or `.filter` inside a bound overwrote the length,
the other bound, and — at the same rep — the receiver itself. The receiver and both bounds are now
evaluated onto the stack and stored after the last of them, and only then is the length read and
the bounds clamped. The string slice already staged on the stack and is unaffected.

#### Ablation

| ingredient removed | outcome | needed? |
| --- | --- | --- |
| the list op in the bound (`a.slice(b[1])`, `a.slice(two())`) | runs | **yes** |
| the bound computed into a `const` first | runs | **yes** |
| the same rep (`a.slice(ss.slice(1).length)` over a string list) | still traps | no |
| the end bound (`a.slice(0, b.slice(2)[0])`) | still traps | no |
| a plain receiver (a field, a narrowed nullable list, a generic parameter) | still traps | no |

#### Grading list

`tests/cases/lists/slice-nested-argument.vl`: nested slice, `.map` and `.filter` in either bound,
the i32, string, f64 and struct reps, a field and a nullable receiver, a generic at two
instances, a compound-assignment place and a slice concat.
