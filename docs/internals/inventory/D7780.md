#### Mechanism

D2584 lets a write keep the narrowings of a `const` bound to a fresh object that its root uses only
as a receiver. `crNoteSoleRef` decided that at the declaration. For a top-level `const` the root is
the program. That meant one `crValUseWalk` over the whole merged arena per `checkProgram`, plus the
pass over its index sites (`opSiteDecls`). `vl check <dir>` runs `checkProgram` once per root.

The only reader is `retireAliasedNarrowings`, and it asks only when a write meets a live narrowing.
A top-level record now keeps its declared type and its root, and is graded the first time a write
asks about it. Grading saves and restores the root `crValUseNames` describes, so the records of
function roots are graded exactly as before.

What changes is when a top-level record is graded: on the arena at the first query, not at the
declaration. The program root's walk already grows by replaying logged edits between notes, so this
is the same approximation, read later.
