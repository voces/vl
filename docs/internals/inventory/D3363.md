### D3363 — a concrete join of `i32`, `f64` and `null` types differently depending on which arm comes first

**loud check reject · clause 2 · open · the same on master `455e553ca` · found by the #3310 round-3 re-review (`rv3310r3/m/np_c1`–`np_c4`) · filed 2026-09-30**

Repro:

    function g(a: i32, b: f64, k: i32) {
      const r = if k == 0 { a } else if k == 1 { b } else { null }
      print(r is i32)
      print(r is f64)
      print(r)
    }
    g(3, 1.5, 0)
    // vl check: `is` check type 'i32' is not a variant of f64 | null

#### Mechanism

Not localised past the ablation. With the `i32` arm first the join widens to `f64 | null` and
`is i32` refuses; with the `f64` arm first (`a: f64, b: i32`) the join keeps both numbers and the
same program runs, `g(2.5, 5, 1)` printing `true false 5`. One of the two is wrong; which waits
on a ruling, so this row has no `Want:`. The generic spelling refuses at emit since #3310.

#### Ablation

| ingredient changed | outcome on master | needed? |
| --- | --- | --- |
| arms swapped (`a: f64, b: i32`) | runs, keeps both numbers | **yes** (the order) |
| `a: i32 \| null` (`np_c4`) | the same refusal | no |
| `a: f64, b: i32 \| null` (`np_c3`) | runs, keeps both numbers | no |
