### D3350 — a binding holding a literal with a record field, set into a map of a wider record, is invalid wasm when a record of its own fields is declared

**closed · runs, prints `4` · was check-clean invalid wasm · clause 1 · closed 2026-10-24 by lane L6 blocker 1 with [D3342](D3342.md): the map value's type `J` is asked for its own row before the spelling's field-set scan finds the declared `I` · the annotated spelling (`const s: J`) was invalid wasm on master `845bd1bdf` too and runs with it · fixtures `tests/cases/maps/wider-record-binding-set-with-own-record-declared.vl`, `tests/cases/maps/annotated-wider-record-binding-set-with-own-record-declared.vl` · found by the #3312 review grid (`onull__ubind__mapval`) · filed 2026-09-30 against master `2b30e3674`**

Repro:

    type O = { v: i32 }
    type I = { f: O }
    type J = { f: O | null }
    const s = { f: { v: 4 } }
    const m = Map<string, J>()
    m.set("a", s)
    const x = m.get("a") ?? { f: { v: 9 } }
    print(x.f?.v ?? 70)
    // vl check: rc 0.  vl run: invalid module, "expected (ref null $type), found (ref $type)"

Want:

    4

#### Mechanism

`s` holds only a literal and would adopt `J`, but its delivery is a method argument, which the
record-covariance rule does not adopt from, and the literal is built at the declared `I` row, so
the map stores an `I` into a `J` slot. The binding spelling of D3342 and D3349.
