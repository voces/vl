### D2575 — a function returning a record-producing `.map` is invalid wasm when its result is unused

**now a loud emit reject · clause 2 · was check-clean invalid wasm; return inference now reads the `.map` result as a ref list (`rep-descriptor-campaign.md` §13.15), and the anonymous record has no ref-list row, so the refusal is `ref valtype with no interned shape` · pre-existing on master `dcc88a350` · found by #3174's review · filed 2026-09-26**

Repro:

    function f(xs: i32[]) { return xs.map((e) => { x: e, y: 0 }) }
    f([3, 1, 2])
    print(1)
    // vl check: rc 0.  vl run: emitProgram: ref valtype with no interned shape
    // (was: invalid module inside `f`, "type mismatch: expected (ref $type), found (ref $type)")

#### Mechanism

`computeRetInference` asked `mfResultKindOf` about the callback before return inference had
classified it, got `i32`, and gave `f` a plain list result while its body built a ref list.
The classifier now answers from the checked-rep column, so `f`'s result is a ref list, and
the refusal moved to its element: the record is an anonymous shape, and no ref-list row for
it exists when return inference fills `fRetRArrElem`. The same refusal fires when the result
is used (`const r = f([3, 1]); print(r[1].x)`, which refused with `field access receiver is
not a struct` before), and when the callback returns a named record through a call
(`(e) => mk(e)`, `mk(e: i32): P`).

#### Ablation

| ingredient removed | outcome | needed? |
| --- | --- | --- |
| the unused result (`print(f([3, 1])[1].x)`) | the same refusal | no |
| the `return` (expression body, result unused) | runs, prints 1 | **yes** |
| the anonymous record (a named `P` through `mk(e)`) | the same refusal | no |

#### Grading list

* Both spellings, with the result unused and used, and the named-record spelling.
