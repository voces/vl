### D2575 — a function returning a record-producing `.map` is invalid wasm when its result is unused

**check-clean invalid wasm · clause 1 · pre-existing on master `dcc88a350` · found by #3174's review · filed 2026-09-26**

Repro:

    function f(xs: i32[]) { return xs.map((e) => { x: e, y: 0 }) }
    f([3, 1, 2])
    print(1)
    // vl check: rc 0.  vl run: invalid module inside `f`, "type mismatch: expected (ref $type),
    // found (ref $type)"

#### Mechanism

Not located. The record produced by the callback is an anonymous shape, and the list `f`
declares and the list its body builds are keyed at two different rows. When the result is
used (`const r = f([3, 1]); print(r[1].x)`), the program instead refuses loudly with
`field access receiver is not a struct`. The expression-body spelling (`{ xs.map(…) }`) gives
the same invalid wasm since #3174. On master it failed with `expected i32` instead, because
the result was never classified.

#### Ablation

| ingredient removed | outcome | needed? |
| --- | --- | --- |
| the unused result (`print(f([3, 1])[1].x)`) | loud emit reject | **yes** |
| the `return` (expression body) | still invalid wasm | no |

#### Grading list

* Both spellings, with the result unused and used.
