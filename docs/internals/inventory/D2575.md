### D2575 — a function returning a record-producing `.map` is invalid wasm when its result is unused

**closed · return inference names the `.map` result's ref-list row from the callback's own record (`rep-descriptor-campaign.md` §13.16); fixture `tests/cases/lists/map-record-result-inferred-return.vl` · was a loud emit reject after §13.15, and check-clean invalid wasm before it · pre-existing on master `dcc88a350` · found by #3174's review · filed 2026-09-26**

Repro:

    function f(xs: i32[]) { return xs.map((e) => { x: e, y: 0 }) }
    f([3, 1, 2])
    print(1)
    // vl check: rc 0.  vl run: prints 1
    // (was: emitProgram: ref valtype with no interned shape; before that, an invalid
    // module inside `f`, "type mismatch: expected (ref $type), found (ref $type)")

Want:

    1

#### Mechanism

`computeRetInference` runs before `collectMapFilterUse`, which interns the ref-list row a
`.map` result gets. So when return inference asked for `f`'s element row, the callback had no
recorded result slot, `refListElemNameOfExpr` answered "", and `fRetRArrElem` stayed empty: a
ref-list return with no row, refused at emission. The member arm now falls back to the row
name the callback's own record or variant gives (`mfStructResultRowName`), and `criClassify`
retries a ref-list return still missing its row on a later fixpoint pass.

#### Ablation

| ingredient removed | outcome | needed? |
| --- | --- | --- |
| the unused result (`print(f([3, 1])[1].x)`) | the same refusal | no |

| the anonymous record (a named `P` through `mk(e)`) | the same refusal | no |

#### Grading list

* Both spellings, with the result unused and used, the named-record spelling, the
  expression-bodied function, and a callback returning a union variant: all run, and the
  fixture prints each. A generic `wrap<T>(xs: T[])` returning the same `.map` still refuses,
  on a different literal, and is D4683.
