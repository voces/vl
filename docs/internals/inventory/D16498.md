### D16498 — a radix tree arm under `/`, `%`, `<<` or `>>` is computed at 32 bits in an `i64` join with no destination

**check-clean silently wrong · clause 1 · open · `vl check` rc 0 · ruling A (a radix literal is a bit pattern at its use's width, under every operator) with 4.3 (a literal adopts a typed join) · the same join's `+`, `^` and `&` arms adopt `i64`, and every operator adopts it under an `i64` destination · found by the independent oracle's arithmetic generator (fuzz cell `ar_s39_0017`) · filed 2026-11-15 against master `6f9bafb92`**

Repro:

    let c = true
    print(if c { 0xFFFFFFFF % 7 } else { 3000000000 })
    print(if c { 0xFFFFFFFF << 1 } else { 3000000000 })
    // master: vl check rc 0; prints -1 then -2, the 32-bit readings

Want:

    3
    8589934590

#### Mechanism

Not ablated to a compiler function. The join is `i64`, because its other arm is a decimal outside
`i32`, so its radix arm is read at 64 bits: `0xFFFFFFFF` is `4294967295` there (T2.3). An arm
whose operator commutes with wrapping (`+`, `^`, `&`) gives the same bits either way, and those
arms agree. The width-dependent operators show that the arm was folded at 32 bits before the
join's type reached it.

#### Ablation

| arm, other arm `3000000000` | master | at 64 bits |
| --- | --- | --- |
| `0xFFFFFFFF` | `4294967295` | `4294967295` |
| `0xFFFFFFFF + 0`, `& 0xFFFFFFFF`, `^ 1` | 64-bit | 64-bit |
| `0xFFFFFFFF % 7` | `-1` | `3` |
| `0xFFFFFFFF / 2` | `0` | `2147483647` |
| `(-1) % 0xFFFFFFFF` | `0` | `-1` |
| `0xFFFFFFFF << 1` | `-2` | `8589934590` |
| `0xFFFFFFFF >> 1` | `-1` | `2147483647` |
| `0xFFFFFFFF / 2` under `const x: i64 = if …` | `2147483647` | same: the destination adopts |
| other arm `w` with `w: i64`, arm `(-1) % 0xFFFFFFFF` | `0` | `-1` |

#### Grading list

- Every 32-bit row of the ablation table reads 64 bits.
- The `match` face, `match 1 { 1 => 0xFFFFFFFF % 7; _ => 3000000000 }`, prints `-1` on master,
  and the oracle agrees today. Under 4.3 it is the same join, so the fix changes it, and the
  oracle's `match` must follow.
