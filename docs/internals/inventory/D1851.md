### D1851 — a generic `T[]` parameter pinned from a BOXED-union element list refuses at the monomorphizer, so the union the checker built has no instance

**closed 2026-09-07 — the witness prints `2` · was `loud emit reject`,
`emitProgram: monomorphize: expected an array argument for `xs` in a call to `g`` with
`vl check` rc 0 · clause 2 · filed 2026-09-06 against master `c3961f2e9`; closed against master
`8bdd886af` by [D1836](D1836.md)'s grouping rule, which is the same rendering defect one
element kind over · fixture `tests/cases/generics/nullable-nested-reflist-elem-slot-inferred.vl`**

Repro:

    function g<T>(xs: T[]): i32 { return xs.length }
    const v = [1, "x"]
    print(g(v))
    // vl check: rc 0.  vl build: emitProgram: monomorphize: expected an array argument for `xs` in a call to `g`

#### Mechanism

The checker joins a list literal's elements, so `[1, "x"]` is `(i32 | string)[]` and the value
is legal — `g([1, "x"])` into a CONCRETE `g(xs: (i32 | string)[])` runs, which is what says the
list itself has a rep. What has no instance is the PIN: `monoArgPinName` hands the argument's
rendered name to a `nameIsArray` gate, and a boxed-union element list does not survive it, so
the monomorphizer refuses rather than minting `g` at `T = i32 | string`. Every element pair
whose arms do not share one rep is in the family; `(i32 | boolean)` is not, because both arms
are i32-repped and the union rides the i32 spine.

This is a clause-2 gap: `vl check` returned 0, so either the program is legal and should build,
or the checker owed the diagnosis. It is filed rather than fixed because the rest-parameter
spelling of the same program reached it by a SILENT route — that half is closed, and this row
is what the refusal there points at.

**The rendered name was the whole of it, and [D1836](D1836.md) closed this row without naming
it.** `monoArgPinName` built a list literal's pin by concatenation, `arrLitElemName(ix) + "[]"`,
skipping the array-element grouping rule every other renderer applies — so `(i32 | string)[]`
spelled `i32|string[]`, whose trailing `[]` binds into the `string` arm and which `nameIsArray`
therefore declines. With the grouping in place the pin is `(i32|string)[]` and the instance
mints. The two rows are one defect at two element kinds, which is why neither ablation could
find the other: both name the ELEMENT, and the mechanism is the SUFFIX.

#### Ablation

| ingredient removed | outcome | needed? |
| --- | --- | --- |
| the generic (`g(xs: (i32 \| string)[])`) | runs | **yes** |
| the boxed union (`[1, true]`, both arms i32-repped) | emit reject — the pin refuses this too | no |
| the union entirely (`[1, 2]`) | runs | **yes** |

#### Grading list

`tests/cases/functions/error-rest-element-hole-boxed-union.vl` is the REST spelling of this
program and must keep refusing at the CHECKER while this row is open — it was check-clean
invalid wasm before that refusal, which is the outcome this row must never be graded against.
Its running twin `rest-element-hole-joins.vl` pins the three joins that are NOT this row —

into them. `[1, "x"]` bound to a concrete `(i32 | string)[]` parameter runs today and is the
control that says the list has a rep.

**The REST face is a DIFFERENT mechanism and its refusal stays.** Measured on master with this

| join | rest face, refusal ON | rest face, refusal OFF |
| --- | --- | --- |
