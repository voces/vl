### D9631 — a list literal holding an un-annotated parameter and arithmetic of it with a wider literal has no list type at emit

**loud emit reject · clause 2 · `vl check` rc 0 · CAPABILITY: `function f(x: i32)` prints `3.5` · found closing [D9620](D9620.md) · present on master `54fb716a1` · filed 2026-10-22 against master `54fb716a1`**

Repro:

    function f(x) {
      const xs = [x, x + 1.5]
      print(xs[1])
    }
    f(2)
    // vl run: emitProgram: index access but list type not collected

Want:

    3.5

#### Mechanism

Not traced. `checkArrayLitNode` (check_container_lits.vl) joins the element types once in the
hole-typed body, where `x` and `x + 1.5` are a hole and a derived hole; at the `i32` pin the
elements are `i32` and `f64`, and the list the index reads was not collected at the type the
emitter asks for. Since [D9620](D9620.md), `x + 5000000000` reaches the same refusal: master
refused it at check with D3426's "cannot hold the 64-bit operand it meets".

#### Ablation

| ingredient changed | outcome | needed? |
| --- | --- | --- |
| the literal `1` (no widening) | runs, prints `3` | **yes** |
| the literal `5000000000` | same refusal | no |
| the list returned (`function f(x) { [x, x + 1.5] }`, `print(f(2)[1])`) | same refusal | no |
| the annotation `x: i32` | runs, prints `3.5` | **yes** |

#### Grading list

The binding and the returned spellings, the `f64` and `i64` literals, a `<T>(x: T)`
spelling, and a second call at another type.
