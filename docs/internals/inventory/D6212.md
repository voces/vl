### D6212 — a hole parameter of a lambda, called at two types, is not split the way a declared function's is

**loud emit reject · `vl check` rc 0 · clause 2 · found closing [D6190](D6190.md) · the same on master `3805fcf57` · filed 2026-10-17 against master `3805fcf57`**

Repro:

    function id(a) { return a }
    const lap = (g, x) => {
      print(g(1))
      return g("s")
    }
    print(lap(id, 0))
    // vl check: rc 0.  vl run: emitProgram: cannot take the generic function `id` as a value — a function value carries ONE signature, and parameter `a` is un-annotated (it would default to i32). No call site pins `id`, so there is no inferred signature to adopt

Want:

    1
    s

#### Mechanism

From the ablation only. The split plan of [D5611](D5611.md) gives a hole parameter called at
two argument types one parameter per type, but only for a declared function. The same body as a
`const` or written `let` lambda keeps one parameter, so `id` has two pins and no single
signature.

#### Ablation

| spelling | outcome | needed? |
| --- | --- | --- |

| `const id = (a) => a` | loud emit reject, `unsupported argument type for g in a call to __lambda_1` | no |

#### Grading list

The `let` spelling, the explicit generic and the `const` lambda `id`, each from the table.
