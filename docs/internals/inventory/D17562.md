### D17562 — an assignment of a generic function to a function-typed binding, passed as a generic higher-order call's argument, is refused by mono

**loud emit reject · clause 2 · found by COV-UNION's Q58 sweep · owner SOUND · filed 2026-11-25 against master `66aea212`**

Repro:

    function inner<U>(u: U) { print(u) }
    function run<T>(f: (t: T) => void, x: T) { f(x) }
    function go<T>(x: T) {
      let k: (t: T) => void = inner
      run(k = inner, x)
    }
    go(5)
    go("s")
    // vl check: rc 0.  vl run: emit error, "monomorphize: unsupported argument type for `f` in a
    // call to `run`"

Want:

    5
    s

#### Mechanism

Not established. The same call with the binding read (`run(k, x)`) runs and prints `5` `s`, so
mono reads a binding of the generic function at its annotation but takes no type for the
assignment expression in the argument position.

#### Ablation

| spelling | outcome |
| --- | --- |
| `run(k, x)` | runs, `5` `s` |
| `run(k = inner, x)` | the mono refusal |

#### Grading list

- The assignment at a non-generic destination (`const g: (t: i32) => void = (k = inner)`).
- COV-UNION's cases 2–5 (`k = other` returned, listed, interned, or at a `V` parameter), which
  are emit refusals for the IR to claim; re-grade them if this close moves them.
