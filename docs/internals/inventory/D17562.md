### D17562 — an assignment of a generic function to a function-typed binding, passed as a generic higher-order call's argument, is refused by mono

**closed 2026-11-25 by SOUND · runs, prints `5` `s` · was a loud emit reject, clause 2 · mono named a function-slot argument by its own type, and an assignment `k = inner` is typed by its right side, the generic `inner`, which names no closed signature; its value is the target re-read, so `monoArgFnTypeName` and `monoArgPinTyAt` (emit_mono.vl) now read an assignment to a name as that name (`monoAsgTargetOf`), as `run(k, x)` is read · pinned by `tests/cases/generics/assignment-of-generic-fn-as-generic-hof-argument.vl` · found by COV-UNION's Q58 sweep · filed 2026-11-25 against master `66aea212`**

Repro:

    function inner<U>(u: U) { print(u) }
    function run<T>(f: (t: T) => void, x: T) { f(x) }
    function go<T>(x: T) {
      let k: (t: T) => void = inner
      run(k = inner, x)
    }
    go(5)
    go("s")
    // vl check: rc 0.  vl run: emit error, "monomorphize: unsupported argument type for `f` in a
    // call to `run`"

Want:

    5
    s

#### Mechanism

The same call with the binding read (`run(k, x)`) runs and prints `5` `s`, so
mono reads a binding of the generic function at its annotation but takes no type for the
assignment expression in the argument position.

#### Ablation

| spelling | outcome |
| --- | --- |
| `run(k, x)` | runs, `5` `s` |
| `run(k = inner, x)` | the mono refusal |

#### Grading list

- The assignment at a non-generic destination (`const g: (t: i32) => void = (k = inner)`).
- COV-UNION's cases 2–5 (`k = other` returned, listed, interned, or at a `V` parameter), which
  are emit refusals for the IR to claim; re-grade them if this close moves them.
