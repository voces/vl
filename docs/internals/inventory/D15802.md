### D15802 — a list of records whose function field holds functions returning different types, handed to an un-annotated parameter and called through, traps at run

**closed 2026-11-12 · now a loud check reject, `cannot store 'half' in 'v[].f': called at (i32) it returns f64, where 'inc0', also stored in it, returns i32 — every function a call through 'v[].f' may run must return one type` · was trap after load, `wasm trap: indirect call type mismatch`, `vl check` rc 0, clause 1 · the refusal is clause 2, the call running is [D15801](D15801.md)'s · found closing [D15791](D15791.md) · filed 2026-11-12 against master `30871c538` · fixed by judging a field through an element of a list literal handed to the parameter (`holeSlotArgJudge`), as an element of one is, with no lift: the instance reads the elements at the parameter's one type**

Repro:

    function inc0(a) { return a + 1 }
    function half(a) { return a / 2.0 }
    function take(v) { print(v[1].f(3)) }
    take([{ f: inc0 }, { f: half }])


#### Mechanism

The literal is built at its own type, so each record's `f` holds the member's closure at that
member's own signature. The callee's parameter is instanced at the argument's type, and its call
through `v[1].f` is a `call_indirect` at the joined signature `(i32) => f64`. `inc0`'s closure,
built at `(i32) => i32`, fails the signature check. Neither the record adoption nor the tag
decision reaches the argument position.
