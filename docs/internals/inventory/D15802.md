### D15802 — a list of records whose function field holds functions returning different types, handed to an un-annotated parameter and called through, traps at run

**closed 2026-11-15 · runs, prints `1.5` · was a loud check reject, `cannot store 'half' in 'v[].f': called at (i32) it returns f64, where 'inc0', also stored in it, returns i32`, clause 2 from 2026-11-12, and before that trap after load, clause 1 · found closing [D15791](D15791.md) · filed 2026-11-12 against master `30871c538` · runs since the decision stamps a list handed straight to a parameter with its place's rep and the one-result judge lifts it (with [D16278](D16278.md)) · fixtures `closures/record-list-fn-field-two-results-handed-to-param.vl`, `closures/list-of-records-of-different-results-handed-to-const-lambda.vl`**

Repro:

    function inc0(a) { return a + 1 }
    function half(a) { return a / 2.0 }
    function take(v) { print(v[1].f(3)) }
    take([{ f: inc0 }, { f: half }])

Want:

    1.5


#### Mechanism

The literal is built at its own type, so each record's `f` holds the member's closure at that
member's own signature. The callee's parameter is instanced at the argument's type, and its call
through `v[1].f` is a `call_indirect` at the joined signature `(i32) => f64`. `inc0`'s closure,
built at `(i32) => i32`, fails the signature check. Neither the record adoption nor the tag
decision reaches the argument position.
