### D1998 — a labelled loop as the FIRST statement of a block parsed as an object literal, because `{ IDENT :` was the whole object test

**closed 2026-09-22 (`looksLikeObject` in `compiler/parser.vl` reads `{ name: while …` / `{ name: for …` as a block) · was a parse error on a legal program, clause 2 · reported by plumb (PL-012, `~/plumb/docs/vl-issues.md`) · filed against master `914d64d65` · fixtures `tests/cases/loops/labelled-loop-first-in-block.vl`, `tests/vl_fmt_test.ts` (D1998: a binding, an `else if` arm, an arrow body, an arrow body with an `else if` arm, a lambda call argument)**

Repro:

    function f(c: boolean): i32 {
      let n = 0
      if c {
        n = 1
      } else {
        B: while true {
          n = 2
          break B
        }
      }
      n
    }
    print(f(false))
    // was: parse error, `expected an expression but found WHILE` at 6:8
    // now: prints 2

#### Mechanism

Wherever a `{` could open either a block or an object literal (a function body, an `else` arm, a
lambda body, a bare or nested block at statement position), `looksLikeObject` called it an
object as soon as the first token after `{` was an IDENT followed by `:`. A labelled loop has
exactly that prefix, so `{ B: while …` went to `parseObjLit`, which then wanted an expression
where `while` stood. With any statement before the label the brace had already been decided as a
block, and `parseStmt`'s own labelled-loop dispatch (IDENT, `:`, `while`/`for`, adjacent) took
it. The fix is that same three-token shape inside `looksLikeObject`: `{ IDENT : while` and
`{ IDENT : for` are blocks. `while` and `for` start no expression, so no object literal that
parsed before can reach the new branch; an `if` value (`{ a: if c { 1 } else { 2 } }`) is still
an object. Formatting the fixed form found a second, older defect in `vl fmt`: an `if`
expression whose arm was not one simple expression went through the whitespace-collapsing slice,
joining the arm's statements onto one line (`const t = 4` then `[t][0]` re-parsed as `4[t][0]`),
and an `else if` arm rendered only its first statement (`q = 5` / `q + 1` became `q = 5`,
printing 5 instead of 6). A multi-line `if` expression with any such arm now renders every arm
as a block. That printer (`ifExpr`) is reached from every expression position (a binding, a
`return`, a call argument, a `match` arm) and, since `statementInline` routes an `if` to it
too, from every one-statement body: an arrow body, a lambda passed as an argument or stored in
an object field, and a bare function body. Before that routing an arrow-body `if` still took
the collapsing slice; review found it, and the squashed `q = 5 -q` it produced is
[D2013](D2013.md).

#### Ablation

A 139-cell grid, graded `vl run` before and after under both seeds: 13 block positions
(function body, function body behind a nested block, `if` arm, `else` arm, `else if` arm,
`while` body, `for` body, `match` arm, bare block, nested block, lambda body, `if`-expression
arm, the label after a statement) × a labelled `while` / `for-in` / C-style `for` first, plus 16
expression and statement positions × six brace contents (`a: 1`, `a: 1, b: 2`, `"a": 1`, `a`,
`a, b`, `m() { 5 }`), plus `{ a: if … }` and a label split from its loop by a newline. 22 cells
moved and all 22 are labelled-loop cells: 16 now run with the right value, the six C-style `for`
cells move from one parse error to another (VL has no C-style `for`, unlabelled either), and the
two `if`-expression arms at top level now reach the emitter's existing refusal of a loop inside
a top-level `if`-expression arm, which an unlabelled `while` there reaches too. No object or
shorthand cell changed outcome or message. `vl fmt` over all 3,321 `.vl` files in the tree
produces identical output under both seeds except for this row's own fixture. A second grid of 17
formatter programs — a binding, `return`, call argument, `match` arm, arrow body, arrow body
with an `else if` arm, lambda call argument, object-field lambda, bare function body, a default
parameter value, and a `;`-joined line opening an `if`, `while`, `for` or bare block — formats
idempotently and every program that ran before `vl fmt` runs after it with the same output;
under the old seed 8 of the 15 that run stopped compiling or trapped after `vl fmt`. The default-parameter cell is illegal by design (a default must be a literal) and the
top-level call-argument cell hits the existing top-level `if`-expression refusal; both format
without losing a statement.

#### Grading list

The label after a newline (`B:` then `while` on the next line) is still not a label, at any
position, and the six-content object grid above must keep its outcomes. A `break` naming no
enclosing loop is still accepted by `vl check` and refused only by the emitter.
