### D2384 — a binding of a top-level function's call takes the cell of a closed block's same-named closure

**check-clean invalid wasm · clause 1 · found in review of #3135 (D2289), the same on its base · filed 2026-09-24 against master `02cce0b14`**

Repro:

    function w(): f64 { return 1.5 }
    function blk(c: boolean) {
      if c { const w = () => { return "s" }
        print(w()) }
      const r = w()
      print(r / 2.0)
    }
    blk(true)
    // vl check: rc 0.  vl run: invalid module, inside `blk`:
    // "type mismatch: expected (ref $type), found f64"

#### Mechanism

A prediction until a close confirms it. The disassembly declares `r`'s local as the string ref
`(ref $2)` while the call is the top-level `w`'s `f64`: the cell of `r` is classified off the
block's closure `w`, which is out of scope at `const r = w()`. The reader is one that resolves
the callee by NAME through the function-scoped let table (first-wins, not positioned), unlike the
expression readers #3135 positioned. Annotating `r` does not help, so the cell's classifier is
not the only reader asking. The string return is the ingredient that survives #3135: the
scalar-returning closure's twin is closed by it, so a reader of the string rep is what remains.
