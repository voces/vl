### D2384 — a binding of a top-level function's call takes the cell of a closed block's same-named closure

**closed 2026-09-25 · was check-clean invalid wasm · clause 1 · found in review of #3135 (D2289), the same on its base · filed 2026-09-24 against master `02cce0b14`**

Repro:

    function w(): f64 { return 1.5 }
    function blk(c: boolean) {
      if c { const w = () => { return "s" }
        print(w()) }
      const r = w()
      print(r / 2.0)
    }
    blk(true)
    // vl check: rc 0.  vl run (before the close): invalid module, inside `blk`:
    // "type mismatch: expected (ref $type), found f64".  Now prints `s`, `0.75`.

#### Mechanism

`r`'s cell comes from `letIsString` → `exprString(w())`, whose function-value rung
`calleeReturnsStringAt` asks `calleeCloSigKeyAt` for the callee's `$fnsig`. That ladder's
binding rungs (`identClosureFeAt` and its siblings) read `parentLetOfAt`, whose fast path
hands back a name's SOLE `LetDecl` without testing that it covers the position (the gap D2325
named): the block's closed closure answered `>S` for a call of the module function. The close
asks first, at a real source position, whether the name denotes a named function there
(`fnIndexOfInScopeAt`, #3135's positional shadow test); if it does, only the callee node's
own checker type answers (`calleeNodeSigKey`). A UFCS rewrite mints its callee past the frame's
body, so the rewrite records the call it came from (`noteCallOrigin`) and the question is asked
at that call's position (`n.w()` beside a closed block's `w`); any other node past the body keeps
the old ladder, which `closures/capture-shadow-local-method-name.vl` needs.
