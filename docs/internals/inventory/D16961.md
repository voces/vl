### D16961 — [CLOSED 2026-11-18] a re-pointed `let` of a record literal returned from a function with an inferred result, delivered at a wider record, builds only the initialiser at the destination

**closed 2026-11-18 · was check-clean invalid wasm · clause 1 · fixed in check_fit_rules.vl: `recFnBuiltAtDst` delivers an assigned binding through `recAdPushDecl`, as D16867 does for an alias, where `recBuildPush` built its initialiser alone · fixture `tests/cases/records/inferred-return-repointed-let-adopts.vl` · found grading D16958's (unfiled: D16958) `rec-adopt-chain-whole-k1.matrix.vl` (`return_inferred`, annotated face; SILENT on master and on the D16958 seed alike) · filed 2026-11-18 against master `665aeae36` by lane F2**

Repro:

    type J = { f: i32 | null }
    function g() {
      let r1 = { f: 1 }
      r1 = { f: 9 }
      return r1
    }
    const v: J = g()
    print(v.f ?? 0)
    // vl check: rc 0.  vl run: invalid module inside `g`, type mismatch: expected (ref $0) `J`, found (ref $1) `#anon1` {mut i32}

Want:

    9

#### Mechanism

The function's result adopts `J` (its body returns only a binding holding literals), so `r1`'s
initialiser is built at `J`, but the literal written by `r1 = { f: 9 }` stays at its own
`{f: i32}` and is stored into the `J` local. This is D16867's shape (a re-pointed binding whose
written literal is not delivered as its initialiser is) reached through a returned binding
instead of an alias.
