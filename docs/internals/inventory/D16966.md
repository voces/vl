### D16966 — [CLOSED 2026-11-18] an `as` cast to one member of a twin-list union has no lowering, since the union is stored as its one list with no tag to test

**closed 2026-11-18 · runs, prints `5` · was a loud emit reject · clause 2 · fixed in wasmEmit.vl: `emitAsOneListCast` lowers `as`, `as!` and `as?` over a union stored as its one list by `is`'s own element test (`emitListFitAt`, split from `emitListFitIs`): the whole list always fits, a literal list fits when every element does, and a nullable operand misses on null; the refusal it replaced now names a `| null` niche only for a nullable operand · fixtures `tests/cases/narrowing/as-cast-twin-list-union-tests-elements.vl`, `tests/cases/traps/as-cast-twin-list-union-element-miss-traps.vl` · found closing [D16963](D16963.md) · filed 2026-11-18 against master `906520a5d` by lane F1**

Repro:

    type K = 1 | 2
    const q: i32[] | K[] = [5, 2]
    const r = q as! i32[]
    print(r[0])

Want:

    5

#### Mechanism

`i32[] | K[]` over a numeric literal union `K` is stored as its one list (`oneListUnionRender`,
D4743): no box and no tag, so the cast's member test has nothing to read. The emitter's sentence
then names a `| null` niche the program does not have. An `is i32[]` test on the same value runs
(`if q is i32[] { print(q[0]) }` prints `5`), so the cast could take that test's answer.
