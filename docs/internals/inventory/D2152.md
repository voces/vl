### D2152 — a function-value call specialised to a named callee widens its atom result with no member texts

**closed 2026-09-23 — the witness prints `a` · was a loud emit reject (`literal-union string widening with no members`) at the written-alias spelling, clause 2 · filed 2026-09-23 against master `b5debe165`, exposed to inline sets by D2150 · fixture `tests/cases/literal-unions/fntype-litunion-result-controls.vl`**

Repro:

    type AB = "a" | "b"
    function toAB(x: i32): AB {
      "a"
    }
    function apply(g: (i32) => AB, n: i32): string { return g(n) }
    print(apply(toAB, 1))

#### Mechanism

The call `apply(toAB, 1)` bakes `toAB` into a specialised copy of `apply`, whose `g(n)` becomes a
call node the checker never typed. `exprIsLitAtom` still claims it an atom through the callee's
declared result, but `litAtomWidenTexts` asked only the node's recorded type for the members, so
the string return had none to widen with. `callResultAtomTexts` reads the same two sources the
atom claim does: the callee's function type, then a named callee's declared result.

#### Grading list

The inline spelling `(i32) => ("a" | "b")`, and the un-annotated callee whose result is inferred.
