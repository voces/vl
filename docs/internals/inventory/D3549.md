### D3549 — `__array_copy__` lowers only i32, boolean and f64 lists; a string, record, i64 or f32 list is refused at emit

**loud emit reject · clause 2 · `emitProgram: __array_copy__ supports i32/boolean/f64 lists natively` (string, record) and `emitProgram: __array_copy__ expects list (T[]) operands` (i64, f32) · found by lane BI's `std:array.slice` prototype (`builtin-methods-to-std.md` prerequisite 2) · filed 2026-10-03 against master `fae55dec2`**

Repro (`vl check` rc 0; `vl run` refuses at emit):

    const xs = ["a", "b"]
    const out: string[] = __array_new__(2, "")
    __array_copy__(out, 0, xs, 0, 2)
    print(out[1])

Want:

    b

#### Mechanism

The intrinsic's lowering has arms for the i32 list (which also carries boolean) and the f64
list only. Every other list kind has a backing the emitter already knows how to `array.copy`:
the built-in `xs.slice(…)` (`emitArrSlice`) copies string, ref-slot, i64, f32 and packed-`u8`
backings with the same instruction. The gap is the intrinsic's own dispatch, and it is what
keeps a pure-VL `slice` out of `std:array`.

#### Ablation

| ingredient removed | outcome | needed? |
| --- | --- | --- |
| the string element: `[1, 2]` into an `i32[]` | runs | **yes** |
| the string element: `[true, false]` into a `boolean[]` | runs, prints false | **yes** |
| the string element: a named record `P[]` | refuses, `supports i32/boolean/f64 lists natively` | no |
| the string element: an `i64[]` | refuses, `expects list (T[]) operands` | no |
| the string element: an `f32[]` with `__array_new_default__` | refuses, `expects list (T[]) operands` | no |
| the top level: the same copy inside a generic `copyOf<T>(xs: T[])` over `["a", "b"]` | refuses, same sentence | no |
| the intrinsic: the built-in `xs.slice(0, 2)` on each of these lists | runs | the built-in has the arms |

#### Grading list

One copy per list kind the built-in `slice` reaches: string, nullable string, record,
union-of-records, i64, f32, and the packed `u8[]` — each printing the copied last element.
