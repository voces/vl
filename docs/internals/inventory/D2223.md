### D2223 — an empty object literal `{}` passes `vl check` and has no lowering in any position, so a `{}` meant as an empty block in an `if` arm is refused by the emitter

**now a loud check reject, raised at the PARSE stage so `vl check` closes with `(parse error)` · closed by owner ruling (2026-09-23, revised the same day to option (b)), as DESIGN for the statement and BUILT for the value: a `{}` statement is an empty block and refused (`an empty block does nothing; remove it`); a `{}` value completes an expected record whose fields all admit `null` and runs, and is refused, naming the reason, against a record with a required field or where no record is expected · was loud emit reject, clause 2 · found by the decode-bench perf report (`docs/internals/perf/decode-bench-gap-2026-09.md` §5) · filed 2026-09-23 against master `0d5421468` · closed 2026-09-23 · `tests/cases/objects/empty-object-all-nullable-runs.vl`, `tests/cases/objects/error-empty-object-expression.vl`, `tests/cases/statements/error-empty-nested-block.vl`, `tests/cases/statements/empty-bodies-run.vl`**

Repro:

    type P = { a: i32 }
    const p: P = { a: 1 }
    if p.a > 0 {
      {}
    }
    print(p.a)
    // error: an empty block does nothing; remove it
    // (before the ruling: vl check rc 0, then emitProgram: object literal field count does not match struct)

#### Mechanism

The parser reads `{}` in statement position as an empty OBJECT LITERAL, never as an empty
block (a block with a statement in it, `{ print(x) }`, parses as a block and runs). The checker
types it as the empty record `{}` and accepts it; the emitter has no shape for a zero-field
record, so the literal is refused wherever it lands. The message depends only on what else the
module declares: with a struct declared the literal is matched against it and the field count
disagrees; with none it reads `object literal but no struct type declared`; next to a union
arm it reads `object literal matches no union variant`; bound to a name,
`const o = {}` reads `ref valtype with no interned shape`. The `if`/`else` join in the
report's witness is not an ingredient.

#### Ablation

| spelling | outcome | needed? |
| --- | --- | --- |
| the report's witness (`{}` in both arms of an `if`/`else`, struct declared) | refuses: field count | — |
| `{}` in the `then` arm only | refuses: field count | the join: no |
| no struct declared | refuses: no struct type declared | the struct: no, it only picks the message |
| `{}` as a bare statement in a function body | refuses (the checker warns `no effect`) | the `if`: no |
| `const o = {}` at top level | refuses: no interned shape | statement position: no |
| `{ print(x) }` as a statement | runs | the EMPTY literal: **yes** |

#### Grading list

A close decides one of two things and grades every spelling above either way. If `{}` in
statement position is an empty block (a parser ruling), the first four rows run and
`const o = {}` still needs a lowering or a design refusal from the checker. If `{}` is always
the empty record, the emitter needs a zero-field shape, and all five rows run.

#### Close

The owner's ruling, as revised: a record literal may omit a nullable field, so `{}` is the
literal omitting every field (DECISIONS.md, "`{}` completes an all-nullable record"). The
witness above is the statement reading and stays a check reject, `an empty block does
nothing; remove it`, as do the other statement-position rows of the ablation. The value row
splits three ways: `const c: Cfg = {}` over `type Cfg = { verbose: boolean | null, out: string
| null }` runs (both null), and so does every delivery position graded in
