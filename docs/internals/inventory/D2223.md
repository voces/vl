### D2223 — an empty object literal `{}` passes `vl check` and has no lowering in any position, so a `{}` meant as an empty block in an `if` arm is refused by the emitter

Repro:

    type P = { a: i32 }
    const p: P = { a: 1 }
    if p.a > 0 {
      {}
    }
    print(p.a)
    // error: an empty block does nothing; remove it
    // (before the ruling: vl check rc 0, then emitProgram: object literal field count does not match struct)

#### Mechanism

The parser reads `{}` in statement position as an empty OBJECT LITERAL, never as an empty
block (a block with a statement in it, `{ print(x) }`, parses as a block and runs). The checker
types it as the empty record `{}` and accepts it; the emitter has no shape for a zero-field
record, so the literal is refused wherever it lands. The message depends only on what else the
module declares: with a struct declared the literal is matched against it and the field count
disagrees; with none it reads `object literal but no struct type declared`; next to a union
arm it reads `object literal matches no union variant`; bound to a name,
`const o = {}` reads `ref valtype with no interned shape`. The `if`/`else` join in the
report's witness is not an ingredient.

#### Grading list

A close decides one of two things and grades every spelling above either way. If `{}` in
statement position is an empty block (a parser ruling), the first four rows run and
`const o = {}` still needs a lowering or a design refusal from the checker. If `{}` is always
the empty record, the emitter needs a zero-field shape, and all five rows run.

#### Close

The owner ruled neither reading in: an empty nested block does nothing, and an empty object
holds nothing `null` does not (DECISIONS.md, "A bare `{}` is refused"). Every row of the
ablation is now one check reject: the four statement-position spellings read `an empty block
does nothing; remove it`, and `const o = {}` reads `an empty object has no fields to hold;
write its fields, or use `null` for no value`. `{ print(x) }` as a statement still runs.
