### D4350 — a string literal passed to `Set<K>.add` is not adapted to the literal-union element, so the call refuses

**loud check reject · clause 2 · pre-existing, the same on master `d92163e47` · found probing the `one-literal-union-rep` ruling · filed 2026-10-13 against master `d92163e47`**

Repro:

    type K = "a" | "b"
    const s: Set<K> = Set()
    s.add("a")
    print(s.has("a"))
    // vl check: add: expected K, got string
    // want: true

#### Mechanism

The `add` argument is typed before the receiver's element type is offered as its context, so the
literal `"a"` widens to `string` and then fails the `K` parameter. A bound `const k: K = "a"`
passed to `s.add(k)` runs, so the set itself and its atom rep are fine: only the literal's
adaptation at this call is missing.

#### Ablation

| ingredient removed | outcome | needed? |
| --- | --- | --- |
| the alias (inline `Set<"a" \| "b">`) | still refuses | no |
| the literal argument (`s.add(k)` over `const k: K`) | runs | **yes** |

#### Grading list

The inline spelling `Set<"a" | "b">`, `s.has("a")` and `s.delete("a")` as the first literal
delivery, and a `Map<K, i32>` key written by literal.
