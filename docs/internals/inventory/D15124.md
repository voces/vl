### D15124 — a read out of a built container reaching an annotated destination through one hop is not checked as a read

**closed · now runs, prints `4` then `4` · was check-clean invalid wasm, clause 1 · found planning [D14819](D14819.md) · filed 2026-11-03 against master `d467911e6` · closed by the PR that filed it: `recBuiltReadTyIn` follows a held binding's initialiser and an inferred function's value leaves, and `recOwnPend` queues a delivered literal's elements and fields · fixtures `soundness/built-container-read-held-by-binding-handed-to-annotated-callee-runs.vl`, `soundness/built-container-read-reaching-annotated-destination-through-a-literal-or-result-runs.vl`**

Repro:

    type J = { f: i32 | null }
    function mk() { { f: 4 } }
    const wideJ: J = mk()
    const xs = [mk()]
    function take(v: { f: i32 }): i32 { v.f }
    const b = xs[0]
    print(take(b))
    print(wideJ.f ?? 0)

Want:

    4
    4

#### Mechanism

`xs`'s elements are built at `J`. A delivery of a read of them at its own type is queued
(`recOwnPend`) and judged by `recBuiltReadRefuse`, which asks `recBuiltReadTy` for the build.
That answered only a direct index, `.get`, field or `??` read, and a binding only from the build
table, so a delivery through one hop was never judged and was emitted at `{f: i32}`:

* a `const` or unassigned `let` holding the read, handed to an annotated parameter (the Repro);
* an inferred function returning the read;
* a list or record literal holding the read, delivered whole to an annotated destination.

The first now instances the callee at the build and runs. The other two take the capability
refusal the annotated binding of the read already gave; serving them is [D15093](D15093.md)'s
question. An inferred function's result handed to an annotated parameter refuses too: the
result is kept at the parameter's type, so an instance at the build cannot read it.
