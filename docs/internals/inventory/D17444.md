### D17444 — `.get` on a union of maps handed through a call is refused

**loud emit reject · clause 2 · found by the D17443 sweep, the same on master and on the D17443 fix · owner S2 · filed 2026-11-24 against master `ca404e1f`**

Repro:

    type MI = { [string]: i32 }
    type MS = { [string]: string }
    function mk(k: i32): MI | MS | i32 {
      if k == 0 { return 0 }
      const m: MI = Map()
      m["a"] = 5
      return m
    }
    function id<T>(x: T): T { return x }
    function g(a) {
      if a is i32 { return }
      print(id(a).get("a") ?? "none")
    }
    g(mk(1))
    // vl check: rc 0.  vl build: emitProgram: callee is not a function name

Want:

    5

#### Mechanism

Unlocated past the dispatch. The `.get` site reaches `emitCall`'s per-arm dispatch and
`armSiteReads` admits its call receiver (D17443), but inside the arm the `.get` call itself is
written through a path that knows a map `.get` only on a name receiver, and falls to the floor.

#### Ablation

| ingredient | outcome |
| --- | --- |
| `a.get("a")`, a name receiver | runs, `5` |
| `id(a)["a"]`, the index spelling | runs, `5` |
| `id(a).has("a")`, `id(a).length` | runs |

#### Grading list

- `.get` on a union-of-maps call receiver, generic and not, inside `??` and bound by a `const`.
