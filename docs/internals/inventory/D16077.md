### D16077 — a generic function returned by a maker that a hole parameter calls has no instance: the call through the parameter names an unknown function

**loud emit reject · clause 2 · found by lane I grading D16073's `vrFnValue` · filed 2026-11-14 against master `8f6978b8`**

Repro:

    function inc(x) { x + 1 }
    function run(f) { print(f()(5)) }
    run(() => inc)
    // vl check: rc 0.  vl run: emitProgram: call to unknown function (2:10)

Want:

    6

#### Mechanism

`run`'s hole parameter `f` is called, and what it returns is called with an `i32`, so that call
pins `inc` at `(x: i32) => i32`. No pass delivers that pin back through `f`'s result to the
generic that the argument lambda returns, so no instance of `inc` is built and the emitter
finds no function to call. The named-maker spelling fails at the same call with a different
sentence ("no interned signature"), so the lambda renaming of D16073 is not the cause.

#### Ablation

| ingredient removed | outcome | needed? |
| --- | --- | --- |
| `inc`'s un-annotated parameter (`x: i32`) | runs, 6 | **yes** |
| the hole parameter (`f` called directly: `const m = () => inc; m()(5)`) | runs, 6 | **yes** |
| the generic (`run(() => (x: i32) => x + 1)`) | runs, 6 | **yes** |
| the lambda maker (`function mk() { inc }; run(mk)`) | still refuses, "no interned signature" | no |
| the chained call (`const g = f(); print(g(5))`) | still refuses, "call to unknown function" | no |
| the hole (`f: () => (x: i32) => i32`) | refuses: "cannot take the generic function `inc` as a value" (D16075's sentence) | no |
