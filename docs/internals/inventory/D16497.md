### D16497 — a float literal join nested in a `min`/`max` argument or a constant tree does not adopt a typed `f32` beside it, as an integer one adopts `i64`

**check-clean silently wrong · clause 1 · open · `vl check` rc 0 · ruling 4.3 (one rule for every join form) · the same join directly beside an `f32`, as a list element, or as an argument adopts `f32`, and the integer faces adopt `i64` · found by the independent oracle's arithmetic generator (fuzz cells `ar_s36_0009`, `ar_s42_0113`) · filed 2026-11-15 against master `6f9bafb92`**

Repro:

    let c = false
    const a: f32 = -0.25
    print(min(a, (if c { 0.1 } else { 0.5 })) - 0.01)
    const b: f32 = 1.0
    print(b + (16777217.0 * (if c { 2.0 } else { 1.0 })))
    // master: vl check rc 0; prints -0.26 then 16777218, both computed at f64

Want:

    -0.25999999046325684
    16777216

#### Mechanism

Not ablated to a compiler function. Under 4.3 a literal join adopts a typed join or peer, and
Q9 folds a float constant at the type it is used at. The checker types the join `f64` when it
is a `min`/`max` argument or a leaf of a constant tree, so the `f32` beside it widens to
`f64` instead. The integer faces adopt: `min(a, join)` with `a: i64` is `i64`, and an `i64`
peer of a join tree reads a radix arm zero-extended.
