### D11160 — a closure over a `let` bound from a narrowed member field returns the box its reassignment narrowed away

**check-clean invalid wasm · hand witness, found grading D7's narrowed-null fixture · filed 2026-10-23 against master `5ba694235`**

Repro:

    function t(w: { f: i32 | null | string }) {
      if !(w.f is string) {
        let c = w.f
        c = 9
        const f = () => c
        print(f() + 1)
      }
    }
    t({ f: 3 })
    // vl check: rc 0.  vl run: the emitted module failed to validate inside `t`:
    // type mismatch: expected i32, found (ref $type)

Want:

    10

#### Mechanism

The checker types `c` after `c = 9` as `i32`, so `f` returns `i32` and `f() + 1` is
arithmetic. The emitter stores `c` in a capture cell whose rep it takes from the member path's
narrowing, which is the `i32 | null` value box, and `f` returns that box unconverted. The same
program with a PARAMETER in place of the member (`v: i32 | null | string`, `let c = v`) runs, so
the ingredient is the binding being seeded from a member-path narrowing. That the cell's rep
comes from the member path is a reading of the ablation below, not yet traced in the emitter.
A second face, `print(f())`, is a loud emit reject instead (`print of a union value whose arms
the tag dispatch cannot classify`). Its function's position is reported as the error span.
