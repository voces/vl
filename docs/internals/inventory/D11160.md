### D11160 — a `let` bound from a narrowed field or element read holds the box under the place's whole union, so a later null-subtracting re-narrow leaves two members

**closed · check-clean invalid wasm · hand witness, found grading D7's narrowed-null fixture · filed 2026-10-23 against master `5ba694235`**

Repro:

    function t(w: { f: i32 | null | string }) {
      if !(w.f is string) {
        let c = w.f
        c = 9
        const f = () => c
        print(f() + 1)
      }
    }
    t({ f: 3 })
    // master: vl check rc 0.  vl run: the emitted module failed to validate inside `t`:
    // type mismatch: expected i32, found (ref $type)

Want:

    10

#### Mechanism

The checker types `c` as the narrowed `i32 | null`, and after `c = 9` as `i32`. The emitter
names a `let`'s union by `letUnionNameOf`, whose D5921 rule binds a read narrowed to a smaller
box at that box, but only for a bare NAME read. A member or index read fell through to the
place's declared union, `i32 | null | string`. The write `c = 9` banks no member type here, so
`pgAssignIdentNarrow` re-narrows by subtracting `null` from the binding's union: `i32 | string`
under the whole union, still a box, where the checker has `i32`. Every read of `c` after the
write then lowers at the box. The fix lets `narrowedBoxRenderOf` and its collect-side twin
`initIsNarrowedBoxRead` take a member or index read too, when `placeReadIsNarrowed` finds the
read typed at fewer members than the place's own declaration. Comparing with the binding's
union alone would also catch D3403's record built at a wider row, whose read is no narrowing
and whose box then traps at the narrower name. The parameter form ran because its init is a
name.
