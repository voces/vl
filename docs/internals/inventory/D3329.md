### D3329 — a recursive record that is also an arm of a declared union `type U = O | P` has no field rep for its own `O | null` field

**loud emit reject · clause 2 · found by #3306's review · the same on master `b6378e95b` · filed 2026-09-30 against master `b6378e95b`**

Repro:

    type O = { n: i32, next: O | null }
    type P = { m: i32 }
    type U = O | P
    const o: O = { n: 1, next: null }
    print(o.n)
    // vl check: rc 0.  vl run: emitProgram: a struct field typed as the union ARM `O` has no field rep — give the field the UNION's own type, or declare the arm as a plain struct

Want:

    1

#### Mechanism

Not traced. `O`'s own `next: O | null` field names `O` as a union ARM once `U = O | P` makes `O`
one, and the struct's field row cannot be minted for an arm that is itself under construction.
The review filed it through a hole callee (`depth(o.next)` over the same types); the callee is
not needed, nor is any value of `U`: declaring `type U` and using `O` alone refuses. The same
refusal literal is [D2174](D2174.md)'s, reached there by a tail `if` joining a struct write with a
scalar one; here nothing is joined.

#### Grading list

The direct spellings `o.next?.n ?? 0`, `u is O` then `u.next`, and a `U`-typed field holding an
`O`. [D2174](D2174.md) is the tail-`if` route to the same refusal; a close at the field row should
be graded against both.
