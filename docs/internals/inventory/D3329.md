### D3329 — a recursive record that is also an arm of a declared union `type U = O | P` has no field rep for its own `O | null` field

**closed 2026-11-03 by lane column-G1 · runs, prints `1` · was a loud emit reject, clause 2, filed 2026-09-30 against master `b6378e95b` · `collectVariantFields` codes an arm's fields during `collectU`, before any declared record has a struct row, and coded a field naming the arm itself `-1`; a field naming a declared record now codes `15` and waits for the row, as a nested inline-shape field already did · fixture `tests/cases/unions/self-recursive-arm-field.vl` (built, read through the union, narrowed, walked, mutually recursive with a sibling arm, held by a `U`-typed field, and [D2174](D2174.md)'s join) · a plain struct holding the recursive arm still refuses, [D15095](D15095.md) · found by #3306's review**

Repro:

    type O = { n: i32, next: O | null }
    type P = { m: i32 }
    type U = O | P
    const o: O = { n: 1, next: null }
    print(o.n)

Want:

    1

#### Mechanism

Not traced. `O`'s own `next: O | null` field names `O` as a union ARM once `U = O | P` makes `O`
one, and the struct's field row cannot be minted for an arm that is itself under construction.
The review filed it through a hole callee (`depth(o.next)` over the same types); the callee is
not needed, nor is any value of `U`: declaring `type U` and using `O` alone refuses. The same
refusal literal is [D2174](D2174.md)'s, reached there by a tail `if` joining a struct write with a
scalar one; here nothing is joined.
