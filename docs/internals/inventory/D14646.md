### D14646 — a function list written by index, through an alias or a parameter, or a map of functions, is refused at check when the results differ

**loud check reject · `cannot write 'lenOf' to an element of 'fs'` · clause 2 · open · the pushed spelling runs ([D14645](D14645.md)), so the refusal is the gap under D3975 (A), not a design rule · found closing D14645 · filed 2026-10-29 against master `5ea95968`**

Repro:

    function twice(s) { return s + s }
    function lenOf(s) { return s.length }
    const fs = [twice, twice]
    fs[1] = lenOf
    for g in fs { print(g("ab")) }
    // Want: abab, 2

#### Mechanism

`elabFnListLetTy` (check_elab_cap.vl) widens a list binding's set only over the values its own
scope pushes, and `holeSlotJudge` lifts its comparison only for a binding so widened. Measured
with the comparison lifted for every written element: an index write builds `cannot take the
generic function 'twice' as a value`, a write through an alias traps (`indirect call type
mismatch`), a parameter's write and a re-pointed `let` refuse at emit, a record's list field
builds `ref valtype with no interned shape`, and a map read through `m["b"] = half` refuses
(`scalar map read has no value-box type`). `m.set` alone ran. Each spelling needs its writes
joined into the set and the set tagged before the judge can lift for it.
