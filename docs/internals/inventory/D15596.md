**closed 2026-11-09, runs and prints `7`, `x`, `7`, `2`, `true`, `x`, `true`, `2` · was loud emit reject, clause 2, `vl check` rc 0, then `emitProgram: a generic function taken as a value reaches no call that fixes its type` · filed 2026-11-09 against master `714c5595` · bundled like D15595's member, the hole built and trapped because the bundle keeps the read `same` generic, so `outer`'s body never names a per-signature instance and `monoPruneTemplates` stubbed it as a dead nested function (`monoNestedFnDead`). #### Mechanism

D15595 hands a generic nested `same<T>` as a bundle, one closure per signature built in each
`outer` instance (`elabNestedGeneric`). A hole `same(k)` was not admitted there. Unbundled, mono
pinned `mid(same)`'s argument from the open type and refused. Admitted, it built and trapped with
`indirect call type mismatch` once `outer` had two instances of different types: mono built
`same` at both signatures under both instances (the built-closure row held all four), but
`monoPruneTemplates` replaced the first instance's `(i32) => i32` slot with a no-parameter stub.
`monoNestedFnDead` reads a nested slot as dead when its parent's body does not name it, and the
bundle keeps the read `same` (`monoNoRename`), so no body names the instance.
