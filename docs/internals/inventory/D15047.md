**runs today and must keep running · split-plan dependent: with the split plan off (`compileSrc` returning after its first compile) it is a loud emit reject, `the reassigned function binding 'fc' holds functions called at more than one argument type` · without the split plan since 2026-11-03 (#5994): the set's check-time tag decision refused the call's allocating list-literal argument, so `{fst, lst}` stayed untagged and the binding held two pins; a literal is now plain where every member takes that argument at one rep, its parameter shaped only by type variables or the argument's closed type (`ftLitArgsAgree`, check_fn_tag.vl) · pin `tests/cases/closures/written-let-of-generics-called-with-list-literals-at-two-types.vl` · found ablating the split-plan census's "reassigned function binding" group, in `closures/written-let-of-generics-handed-at-two-pins.vl` · filed 2026-11-03 against master `11693b2ef`**

Repro:

    function fst<T>(xs: T[]): T { return xs[0] }
    function lst<T>(xs: T[]): T { return xs[xs.length - 1] }
    let fc = fst
    if [1].length > 0 { fc = lst }
    print(fc([1, 2]))
    print(fc(["a", "b"]))

Want:

    2
    b

#### Mechanism

It is the call's list LITERAL argument, not the members' list parameter. The scalar spelling runs
because the check-time tag decision tags `{fst, lst}`: `fc` holds the set's id and each call
dispatches through arms. Here `ftPlan` refused the set at `ftPlainArgsIn`, which takes an
allocating literal argument as plain only for a late singleton set, since the one node is emitted
in every member's arm. With the set untagged, the binding met both call types at one signature.
Closed by `ftLitArgsAgree`: the literal is plain where every member takes that argument at one
rep, its parameter shaped only by type variables or the argument's closed type.
