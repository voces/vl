#### Mechanism

`mfResultKindOf` named a result list for struct, variant, union, string and scalar callback
returns; a callback returning a list had no arm, and the nested spelling
`a.map((r) => r.map((x) => x as f64))` over `a: i32[][]` refused instead with
`unsupported .map/.filter element type`. `mfListResultElemTy` (emit_classify.vl) now reads the
call's own element type when it is a list (and, for a named callback, its return is a plain
list), so the result kind is `ref` at that element's row, the collect pass interns the row,
and an inferred function return names the same element.
