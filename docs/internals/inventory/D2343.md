### D2343 — a closure passed as a named argument was ordered by source position, so a write in an earlier-spelled argument left it with a copy

**closed 2026-09-24 — the witness prints `5`. Was check-clean silently wrong on D2339's branch
(it printed `1`); found by the review of D2339's PR before it merged. Fixture
`tests/cases/closures/capture-by-reference.vl` (`namedArgs`)**

Repro:

    function call2(a: () => i32, b: i32) { a() }
    function g() {
      let x = 1
      const r = call2(b: x = 5, a: () => x)
      print(r)
    }
    g()
    // prints 5

#### Mechanism

Named arguments are evaluated in parameter order, so the closure for `a` is created before
`x = 5` runs. `cboxScan` (`compiler/emit_rewrite.vl`) walked `callArgs` in source order, saw the
assignment first, and decided `x` was never written after a capture, so it copied `x`. A call
with any named argument now dates every closure in its argument list to the call's start
(`cboxArgFloor`). Every assignment in the list therefore counts as after the capture, whatever
order the arguments are spelled in.
