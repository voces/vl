### D2664 — a read of a module global above a same-named local `let` in the same function reads the local's zero instead

**closed 2026-09-26 — the witness prints `9` · fixture `tests/cases/scope/local-after-global-read.vl` · was check-clean silently wrong · found in the #3190 review · filed 2026-09-26 against master `979323f83`**

Repro:

    function seven(): i32 { 7 }
    const n = seven()
    function f(): i32 {
      const a = n
      let n = 2
      return a + n
    }
    print(f())
    // PRINTS 2

#### Close

No ruling was needed, because the tree already has one: a local's scope starts at its
declaration. #1858 pinned `const v = v + 1` reading the parameter, and D2289 pinned
`print(w("g"))` above `const w = 6` calling the top-level function. Both run today, and a TDZ
error would refuse both fixtures. The emitter now matches the checker instead. A function's
own `let` of a name a module global also binds is marked block-scoped (`markLetOverGlobal`),
so the flat local scan skips it until `scopeBind` puts it on the stack. `frameLetOfLive`
declines it for the frame being emitted until then. A read above the `let`, and the `let`'s
own initializer, reach the global. Graded: `i32`, `f64`, string, list, struct, nullable-string
and union locals over `i32`, struct, list and string globals; a write and a `+=` to a `let`
global above the local; a `while` loop; a generic function; a lambda; two frames.

#### Mechanism

The checker walks the body in order, so at `const a = n` the local `n` is not declared yet and
the name resolves to the module global (`7`), and `vl check` returns 0. The emitter collects
every local of the function before lowering it (`buildLocals`), so the same `n` resolves to the
local's slot, which still holds its zero default: `a` is `0` and the program prints `2` rather
than `9`. The two phases disagree about which binding the name means. With a local of a
DIFFERENT type (`let n = "x"`) the same read is check-clean invalid wasm (`uninitialized
local`). The fix is a ruling on the language's side: either the read is a check error (the
local's scope is the whole block, as in JS's TDZ) or it reads the global and the emitter must
resolve by position. Recommendation: a check error, "`n` is used before its declaration",
which matches how the module level already treats an early read.

#### Ablation

| ingredient removed | outcome | needed? |
| --- | --- | --- |
| the module global `n` | loud check reject: undeclared identifier `n` | **yes** |

| the local's type (`let n = "x"`, `return a`) | check-clean invalid wasm | no — changes the symptom |
