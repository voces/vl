### D2196 — a readonly list that needs a converting copy has no lowering under `| null` or nested in another list, so the checker refuses it

**loud check reject · clause 2 (a capability the readonly spelling promises) · 2 positions, numeric and record-into-union pairs · filed 2026-09-23 against master `0c117d0c3`**

Repro:

    type Circle = { r: i32 }
    type Sq = { s: i32 }
    type Shape = Circle | Sq
    const circles: Circle[] = [{ r: 7 }]
    const v: readonly Shape[] | null = circles
    if v != null { print(v.length) }
    // vl check rc 1: … a copy into a list that may be null is not built yet (D2196).
    // Before this row: vl check rc 0, then an invalid module.

#### Mechanism

Under the readonly-only list rule ([D2161](D2161.md)) a `readonly` destination whose element is
stored differently from the source's (`i32[]` into `readonly f64[]`, `Circle[]` into `readonly
Shape[]`) is served by the D965/D791 element-converting copy. The emitter wires that copy at
each delivery site keyed by the destination cell's kind, and a NULLABLE list cell
(`nulreflist`, a nullable scalar list) and a list ELEMENT of an outer list have no copy site: the
narrow list reference was handed to the wide slot unconverted, which the engine refused. The
checker now refuses both (`listWidenArray`'s `underNul` arm, `objShapeAdapterless`'s nested arm)
rather than admit an invalid module, and the message offers only the `.map` copy, which builds.
A readonly list that SHARES its storage (`C[]` into `readonly (C | null)[] | null`) needs no copy
and runs.
