### D16211 — a list callback over a kept maker's built list is refused where its parameter is annotated at the element type, or where a `map` result holds the record

**open · loud check reject, clause 2 · `this container's {f: null} elements are stored at J, the row its stores build; handing it on as {f: null}[] is type-valid but not supported yet` · the floor D16134 left · found by lane I closing D16134 · filed 2026-11-14 against master `a5624eb2d`**

Repro:

    type J = { f: i32 | null }
    function mk2() { { f: null } }
    const dA: J = mk2()

Want:

#### Mechanism

The elaboration keys a callback's parameter by the list's build (`elabCbAtBuild`), not its
result. A `map` result holding the record would need the result list's storage too, a second
late fact. A parameter annotated `{ f: null }` has no hole and no `#r.0` entry the key could
carry. Both stay refused by `recBuiltCallbackRefuse` (`recCbTakesBuild`).
