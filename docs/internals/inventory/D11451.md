### D11451 — a generic alias whose field is a list of a second generic alias, delivered as a literal, has no list rep

**closed · runs, prints `3` · was loud emit reject, `emitProgram: only i32[] arrays and struct/union element arrays are supported`, `vl check` rc 0, clause 2 · CAPABILITY: the outer alias inlined, `v: { s: I<i32>[] }`, prints `3` · found by the D10930 lane probing its neighbours · present on master `4e10a2462` · filed 2026-10-23 against master `4e10a2462` · closed with [D11450](D11450.md), one mechanism: the arena walk skips a generic alias's array field whose annotation mentions the alias's parameter (`gaeParamFieldNodeIs`, emit_collect.vl) · fixture `generics/alias-generic-alias-list-field.vl`**

Repro:

    type I<U> = { g: U }
    type B<U> = { s: I<U>[] }
    function f(v: B<i32>): i32 { v.s[0].g }
    print(f({ s: [{ g: 3 }] }))
    // vl check: rc 0.  vl run: emitProgram: only i32[] arrays and struct/union element arrays are supported

#### Mechanism

The refusal came from the alias DECLARATION, not from the call or the literal. The arena walk
(`collectATypeRef`) visits `B`'s own field annotation `I<U>[]`. No ref-array rung claims it,
because `I<U>` names no row. The generic-original rungs did not claim it either. `genTyParamArr`
reads only a bare parameter leaf. `annArrOverTyParam` asks the node's recorded type, and for an
alias field the checker records none (`-1`) when the alias is unused, or the type of the
application it checked last (`I<i32>[]`). So the annotation fell through to `checkArrName`,
which refuses every non-`i32` element. A program that only declares `B` refuses the same way.

The fix: the field's declared annotation mentions `U` (`gaeAnnHasParam`, already asked by
`gaeDeclFieldTyName`). That node is now recorded and skipped as a generic original. Each
application's `I<i32>[]` is interned through `gaeEnsure`, as before.

#### Ablation

On the pre-fix seed, with the tested programs. The filed row said binding the argument first
under `B<i32>` runs; that was not reproduced on master `f67058834`, where it refuses too.
