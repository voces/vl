### D2620 — a function's `for` variable spelled like an extern shadows the extern for the whole function, not only inside its loop

**closed 2026-09-26 — the witness prints `106` · was loud emit reject after `vl check` rc 0,
clause 2 · found in review of [D2618](D2618.md) (#3182) · pre-existing on master `06930fb68` ·
fixture `tests/cases/extern/function-loop-var-named-like-extern.vl`**

Repro:

    extern function nowMillis(): i64
    function f(): i32 {
      let s = 0
      for nowMillis in [1, 2, 3] { s = s + nowMillis }
      const v = nowMillis
      if v() > (0 as i64) { s = s + 100 }
      s
    }
    print(f())
    // vl check: rc 0.  On master: emit error — identifier is not a parameter, local, or global

#### Mechanism

The emitter asked whether a frame binds a name through a whole-frame lookup (`frameBindingNode`),
which answers yes for a loop variable anywhere in the function. So a read of the extern after
the loop, or a call to it from a closure written outside the loop, was taken for the loop
variable, which is out of scope there, and refused. [D2010](D2010.md) made the module frame's
loop variables positional; the close does the same for a function frame. The respell walk tracks
the loops of the frame it walks, and an outer frame's loop variable binds only when the reading
frame sits inside that loop (`outerFrameBinds`, shared by the respell and by the callee arm of
capture analysis).

the loop variable (`130` = 10 + 20 + 100). The module-frame fixture
