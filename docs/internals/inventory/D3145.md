### D3145 — forwarding a record-pattern parameter to a second record-pattern generic is refused when a declared record shares the field names

**closed 2026-10-09 by lane SC, with D3898 · runs · was loud emit reject · clause 2 · found by the #3278 round-3 review · filed 2026-09-29 against master `fc4b2159f` · pins: `tests/cases/generics/record-pattern-forwarded-beside-declared-record.vl`**

Repro:

    import { toString } from "std:fmt"
    type D = { m: string, n: i32 }
    const dd: D = { m: "dm", n: 8 }
    function g<T>(b: { m: T, n: i32 }): T { b.m }
    function k<T>(b: { m: T, n: i32 }): T { g(b) }
    const e = k({ m: { x: 1, y: 2 }, n: 2 })
    print(toString(e.y))
    // vl check: rc 0.  vl run: emit error, monomorphize: unsupported argument type for `b` in a call to `g`

Want:

    2

#### Mechanism

D3898's. The argument's spelling `{m:{x:i32,y:i32},n:i32}` resolved by field names to `D`'s row
(`{ m: string, n: i32 }`): the nested inline record `{x:i32,y:i32}` classified to no field code,
and that arm accepted `D`'s string field. Closed with D3898. An inline record is now compatible
only with a struct field or a union box.
