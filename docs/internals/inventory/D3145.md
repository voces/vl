### D3145 — forwarding a record-pattern parameter to a second record-pattern generic is refused when a declared record shares the field names

**loud emit reject · clause 2 · found by the #3278 round-3 review · filed 2026-09-29 against master `fc4b2159f`**

Repro:

    import { toString } from "std:fmt"
    type D = { m: string, n: i32 }
    const dd: D = { m: "dm", n: 8 }
    function g<T>(b: { m: T, n: i32 }): T { b.m }
    function k<T>(b: { m: T, n: i32 }): T { g(b) }
    const e = k({ m: { x: 1, y: 2 }, n: 2 })

#### Mechanism

Not traced. Master refuses the outer call to `k`. With #3278 the outer call pins `k`'s
parameter at the argument's own `#anonN` row, because `D` would claim its spelling. Inside
the instance `b` is that row, and forwarding it to `g` finds no spelled shape to bind `T`
from, so the inner call refuses.
