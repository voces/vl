### D15434 — `const`-seeded lambda members of a captured written `let` inside a generic body are check-clean invalid wasm

**closed 2026-11-04, runs with the split plan on · was check-clean invalid wasm, clause 1 · `ftLeafBinding` and `ftInstLeafOk` (check_fn_tag.vl, per-instance identity slice 4b-i) take a `const` lambda seeding a captured `let` as the `let` spelling (`ftSeedsCellAt`), so the split plan's copy holds it as it holds D15436's; with the plan off it is a loud emit reject, D15436's, which closes with slice 4b-ii · fixture `tests/cases/closures/cell-lambda-members-const-seed-generic.vl` · found probing D15433's close · filed 2026-11-04 against master `dffeb177`**

Repro:

    function mk<T>(x: T, n: i32) {
      const g = (y) => y
      const h = (y) => y + y
      let d1 = g
      function w1() { d1 = d1 }
      let d3 = h
      d3 = d1
      print(d1(x))
      print(d3(n))
    }
    mk("a", 4)
    // vl check: rc 0.  vl run: the emitted module failed to validate inside `mk`: type mismatch: expected i32, found (ref $type)

Want:

    a
    4

#### Mechanism

With the split plan off the tag decision declines `{g, h}` at `ftInstLeafOk` (check_fn_tag.vl), per-instance identity slice 4b-i's rule for a lambda declared in an instanced body: it admits one whose binding is a `let`, read only by calls and written only in that body. Here the seed is a `const` read into `d1`, and `w1` writes `d1` from a nested function, which is slice 4b-ii (per-instance-identity-2026-11.md), D15101's capture-cell shape. With the plan on, its copy of `d1` builds invalid wasm. The non-generic spelling runs (D15433, D15435), and so does this one without `w1` (no capture cell) or with the lambdas written at their `let`s; the generic body, the `const` seeds and the cell are each needed. The split plan's copy of `d1` reads an id where the instance holds a closure, or the reverse: one of the per-instance identity shapes (per-instance-identity-2026-11.md, M3).
