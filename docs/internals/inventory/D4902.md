### D4902 — a string-literal-union list literal delivered into `f64[] | K[]` is built as the numeric arm

**check-clean invalid wasm · clause 1 · pre-existing on master; the annotation names both arms · found closing [D4896](D4896.md) · filed 2026-10-15 against master `abb7359ea`**

Repro:

    type K = "x" | "y"
    const a: f64[] | K[] = ["x"]
    print(1)
    // vl check: rc 0.  vl run: constant expression required: non-constant operator: visit_f64_convert_i32_s

Want:

    1

#### Mechanism

Not yet located. A string literal union is an atom held as an `i32` code, and the module-scope
initialiser converts that code with `f64.convert_i32_s`, so the literal `["x"]` is lowered as
the `f64[]` arm instead of the `K[]` arm it was typed as. Inside a function the same
delivery fails validation as `expected i32, found (ref $type)` (exit 70).

#### Ablation

| ingredient removed | outcome | needed? |
| --- | --- | --- |
| the `f64[]` arm (`string[]` in its place) | runs | **yes** |
| `f64[]` replaced by `i64[]` | same, `visit_i64_extend_i32_s` | no |
| the alias (`("x" \| "y")[]` inline) | same refusal | no |
| module scope (the binding inside a function) | invalid wasm, `expected i32, found (ref $type)` | no |

#### Grading list

The `is K[]` test on the same binding (`if a is K[] { print(a[0]) }`), and the in-function
spelling.
