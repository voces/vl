### D15727 — a fresh call's record copied where it lands is not copied when its own type is also an arm of a row union, so the module is invalid

**closed 2026-11-12, runs and prints `2` `1` `2` · was check-clean invalid wasm, clause 1, the same on master · `copyArmRowOf` (wasmEmit.vl) falls back to the variant's own row (`variantRowOf`) for an arm with no annotated row · fixture `tests/cases/structs/copied-call-record-also-row-union-arm-runs.vl` · found when the record-into-union-member copy (D15726) reached `tests/cases/soundness/inferred-result-delivered-wider-runs.vl` · filed 2026-11-12**

Repro:

    type W = { f: i64 }
    function mk() { { f: 1 } }
    function rows() {
      const t = [{ f: 1 }, { g: "x" }]
      t
    }
    const a: W = mk()
    const b = mk()
    print(a.f + 1)
    print(b.f)
    print(rows().length)

Want:

    2
    1
    2

#### Mechanism

`recCopyRowAt` (wasmEmit.vl) finds the copied call's source row by expression, and, for a record
that is also a union's arm, by its type through `copyArmRowOf`. Here `{ f: i32 }` is an arm of
`rows`'s row union `{ f: i32 } | { g: string }`, which has no annotated row for it, so both
lookups answer -1, no copy is emitted, and the call's own record lands where `W` is wanted.
