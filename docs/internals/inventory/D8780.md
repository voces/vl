#### Mechanism

`modIdKeyOf` (driver.vl) hashes a module's path from its staged project root (D5760), and a
module with no root keeps its absolute path. Since #4200 the canonical type order (`typeSeeds`
in emit_sections.vl, keys in emit_type_order.vl) seeds a list wrapper's key with its element's
merged name, `P$m<id>`, so the absolute path reached the type section and every index into it.
The id itself stays a hash of the module's own key, which whole-root serving relies on being
the same in every graph, so the fix is on the reading side: `modIdAssign` also records, per
module, an order spelling — the suffix for a module keyed relative to a root or `std:`, and
`$p` plus its path from the entry's directory for one keyed absolutely — and `typeSeeds` reads
names through it. Distinct modules keep distinct spellings, so the order stays total. A build
in which every module has a root reads exactly the bytes it read before.
