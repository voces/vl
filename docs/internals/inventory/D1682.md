### D1682 — a covariant list delivered into a container that is never bound to a name of its own has no container identity, so the read-only copy is declined

**loud emit reject · filed 2026-09-06 against master `294417dc2` · D1658/D1659's residue · 0 corpus cells**

Repro:

    type Circle = { r: i32 }
    type Sq = { s: i32 }
    type Shape = Circle | Sq
    type Box = { xs: Shape[] }
    function __other() {
      const w: Shape[] = []
      w.push({ s: 3 })
      print(w.length)
    }
    function mk(b: Shape[]): Box { { xs: b } }
    function f() {
      const a: Circle[] = [{ r: 7 }]
      const b: Shape[] = a
      const sf = mk(b)
      print(sf.xs.length)
    }
    f()
    // vl check: rc 0.  vl run: emit error, covariant list delivery.

#### Mechanism

Nothing writes either list, so the element-converting copy is unobservable and this program is
legal. The covariant-write closure names a container by the BINDING its literal initialises:
`cwEscapeByLit` files the escape only where the literal's consumer is a `LetDecl`, because that
is the name every read back out of the container is keyed on. A literal that is returned, or
nested inside another literal, initialises no binding, so no owner is filed, `cwLitClaimed`
declines, and the state is `2` — which the rep-scoped scan then cannot override, because
`__other` writes an unrelated `Shape[]`. Binding the same literal to a name and returning that
name runs, which is the whole difference.

Closing it is a fifth container identity: a literal consumed by a return is reached through the
CALL RESULT the closure already roots at (D1628's fourth edge), and a literal nested in another
literal is reached through the outer container's own key.
