### D1682 — a covariant list delivered into a container that is never bound to a name of its own has no container identity, so the read-only copy is declined

**closed 2026-09-06 · was a loud emit reject · filed 2026-09-06 against master `294417dc2` · D1658/D1659's residue · 0 corpus cells**

Repro:

    type Circle = { r: i32 }
    type Sq = { s: i32 }
    type Shape = Circle | Sq
    type Box = { xs: Shape[] }
    function __other() {
      const w: Shape[] = []
      w.push({ s: 3 })
      print(w.length)
    }
    function mk(b: Shape[]): Box { { xs: b } }
    function f() {
      const a: Circle[] = [{ r: 7 }]
      const b: Shape[] = a
      const sf = mk(b)
      print(sf.xs.length)
    }
    f()
    // vl check: rc 0.  vl run: prints 1.

#### Mechanism

Nothing writes either list, so the element-converting copy is unobservable and this program is
legal. The covariant-write closure named a container by the BINDING its literal initialises:
`cwEscapeByLit` filed the escape only where the literal's consumer is a `LetDecl`, because
that is the name every read back out of the container is keyed on. A literal that is returned,
or nested inside another literal, initialises no binding, so no owner was filed, `cwLitClaimed`
declined, and the state was `2` — which the rep-scoped scan cannot override, because `__other`
writes an unrelated `Shape[]`.

`cwLitOwners` resolves the containers instead, and both remaining consumers have one: a
returned literal is reached through the CALL RESULT the closure already roots at, so the
containers are the destinations `cwRetDestNames` collects from every call; a literal nested in
another is reached through the enclosing container's own key, with the field prepended to the
path. The escape key is a container name plus a dotted PATH (`cwProjPath`), and the claim, the
filing and `cwIsEscapedHandle` all build it by one join rule. An intermediate on that path
given a name of its own is a handle no key spells, so `cwContainerSealed` declines on it
(D1686).
