### D3930 — a reassigned binding of generic functions handed to a function-typed parameter traps

**closed 2026-10-09 by lane SC · runs · was loads then traps · found in review of #3490 (`rv3490/q5_reassign_toplevel`, `q4`) · filed 2026-10-09 against master `255fc7a6c` · pins: `tests/cases/generics/binding-of-generic-function-delivered-as-value.vl`**

Repro:

    function call(f: (n: i32) => void) { f(1) }
    function inner<U>(u: U) { print(u) }
    function other<V>(v: V) { print("O"); print(v) }
    function main() {
      let k = inner
      k = other
      call(k)
    }
    main()
    // vl check: rc 0.  vl run: wasm trap: indirect call type mismatch

Want:

    O
    1

#### Mechanism

A reassigned `let` holding generic functions, delivered at a function type, was read through
the generic its initializer named, or not instanced at all, so `call` received a function at
another signature. Closed: a read of an un-annotated, reassigned `let` delivered at a concrete
function type keeps the binding's value, and every declared generic function its initializer or
a write in its frame names is instanced at that type (`monoCoerceWrittenLet`). A write after the
delivery is read only by later deliveries; a hole lambda in the binding keeps its own signature
rules (D3857).
