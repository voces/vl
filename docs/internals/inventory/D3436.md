### D3436 — a hole's value written into a nullable place is refused a member read at the template, where the `<T>` spelling defers it to the pin

**closed 2026-11-16 by lane L2, (c) PR 2 · runs, prints `3` · `tests/cases/generics/hole-param-written-into-nullable-place.vl` · was loud check reject · clause 2 · open · pre-existing, the same on master `b2a85883d` · 16 cells of lane NW's `nw/g1` grid (`*_{len,arg}_s_hole`) · filed 2026-09-30 against master `b2a85883d` · bucket (c), L2 inferred interfaces (the 2026-11-14 clause-2 map)**

Repro:

    function g(x) {
      let s: string | null = null

#### Mechanism

Not localised past the ablation. An un-annotated parameter is gradual like a declared type
parameter (#3313), and the `<T>` spelling reads `s` after the write at the member its pin lands
on (D3240), so `.length` is asked at the `string` pin and runs. The hole's write is not taken
that way: `s` reads at its declaration in the template, and the read is refused there for every
pin. The direct spelling `x: string` runs.

Probed for L2 S3.4c (2026-11-16): the `<T>` spelling reaches the name write's narrowing
(`check_operators.vl`, the `rhsNonNull` arm) with the right side typed `T`, and `tvPlaceWrite`
answers yes, so `s` reads at the pin. The hole spelling never reaches that arm with a type variable
on the right, so extending `tvPlaceWrite` to parameter holes (`tyIsParamHole`) changed neither this
row nor [D3299](D3299.md). The template types the hole's read on the right of a write as something
other than its hole, and that is where a fix starts. A second probe measured it: at the template
the write's right side is typed `string | null`, the place's own type, since writing the hole into
the declared place pins it there, so `rhsNonNull` is false and nothing narrows. Narrowing from the
parameter's own hole (its `Param` declaration's type) through `tvPlaceWrite` did not move the
witness either; the declaration no longer reads as the hole by then.


#### Close (2026-11-16, L2 (c), coordinator ruling: a parameter written into a `T | null` place stays pin-generic)

The parameter-solve flow answered the hole with the place's own type, `T | null`, so the write's
right side was concrete and nothing narrowed. `noteHoleFlow` (`check_leaf_steps.vl`) now leaves a
bare parameter hole open when it is the value of an assignment into a place that admits `null`
and holds no type variable or literal, and `tvPlaceWrite` admits the hole (PR 1), so the place
reads at the pin's member (`HD_TVW`). A literal-holding place keeps the flow answer, which lets a
literal argument adapt (`"a"` into `Ab | null`; `<T>` refuses that one). Graded on
`hole-written-into-nullable-place-*.matrix.vl`: 28 cells move to runs, 0 runs → not-runs.
