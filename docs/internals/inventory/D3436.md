### D3436 — a hole's value written into a nullable place is refused a member read at the template, where the `<T>` spelling defers it to the pin

**loud check reject · clause 2 · open · pre-existing, the same on master `b2a85883d` · 16 cells of lane NW's `nw/g1` grid (`*_{len,arg}_s_hole`) · filed 2026-09-30 against master `b2a85883d`**

Repro:

    function g(x) {
      let s: string | null = null
      s = x
      print(s.length)
    }
    g("abc")
    // vl check: rc 1, "member access '.length' on non-object string | null"

#### Mechanism

Not localised past the ablation. An un-annotated parameter is gradual like a declared type
parameter (#3313), and the `<T>` spelling reads `s` after the write at the member its pin lands
on (D3240), so `.length` is asked at the `string` pin and runs. The hole's write is not taken
that way: `s` reads at its declaration in the template, and the read is refused there for every
pin. The direct spelling `x: string` runs.

| `print(s ?? "n")` | prints `abc` | **yes** (a read needing non-null) |
