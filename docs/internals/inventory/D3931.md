### D3931 — a local lambda delivered to a function type with a wider result inside a generic is refused as an undeclared name

**loud check reject · clause 2 · found in review of #3489 (`rv3489/p35_*`, `p37_*`, `p38`; `p36` concrete is the control) · filed 2026-10-09 against master `255fc7a6c`**

Repro:

    type Circle = { r: i32 }
    type Sq = { s: i32 }
    type Shape = Circle | Sq
    function area(s: Shape) {
      if s is Circle { return s.r }
      0
    }
    function a<T>(x: T) {
      const b = (t: T): Circle => {
        print("first")
        return { r: 1 }
      }
      const h: (t: T) => Shape = b
      print(area(h(x)))
    }
    a(2.5)
    // vl check: a function of type `(f64) => Circle` cannot be used as `(f64) => Shape` here: … refused (undeclared identifier 'b')

Want:

    first
    1

#### Mechanism

Not located. The function-value adapter for a different-rep result (`Circle` into `Shape`) is
built when the delivery is re-checked at the instance's types, outside the function's scope, and
its body names the local `b`, which is not declared there. D3918 banks the declaration a name
resolves to; the adapter's own body still resolves `b` in the wrong scope. With a module generic
in the slot the emitter refuses instead (`no interned signature`, p35_fn, p37_*).
