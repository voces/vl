### D6540 — a declared generic whose parameter is `T[]`, handed to a hole and called with a non-list, passes check

**loud emit reject · clause 2, DESIGN: the checker owes the refusal its concrete spelling gives · found closing [D6521](D6521.md) · filed 2026-10-18 against master `698648f78`**

Repro:

    function first<T>(k: T[]): T { k[0] }
    function viaResult(a) {
      print(a("x"))
    }
    viaResult(first)
    // vl check: rc 0.  vl run: emitProgram: a function-value call has no interned signature — the callee has no function type to key a signature from

#### Mechanism

From the ablation only. The call `a("x")` binds `first`'s `T[]` against `string` and finds
no binding, but nothing refuses that; the instance stays open, and the emitter has no
signature to take `first` at. With `firstI(k: i32[])` or `(k: i32[]) => k[0]` the same call
is refused at check with `argument 1: expected i32[], got string (the call of `a` at the
call's argument types)`. So the checker refuses a list parameter that cannot take the
argument when the type is concrete, but not when it is generic.

#### Ablation

#### Grading list

The concrete spellings above must keep refusing. A list argument must keep running:
`viaResult(first)` with `print(a([1]))` and `print(a(["s"]))`.
