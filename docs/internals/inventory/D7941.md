### D7941 — an unused record type of a literal's exact field set stops that literal widening when it passes through a type parameter

**closed 2026-10-20 by lane S5 · runs, prints `4` · a literal argument that alone pins a generic call's instance (`recSolePinArg`) is built at the record it is delivered to, so a declared record of its fields no longer decides the verdict, at every delivery position and across modules · the literal-building call face stays open as [D8020](D8020.md) · fixture `tests/cases/soundness/record-literal-through-identity-ignores-unused-record.vl` · filed against master `aec7a5332`**

Repro:

    type Col = { r: i32, g: i32, b: i32 }
    type J = { r: i32 | null, g: i32, b: i32 }
    function idn<T>(v: T): T { v }
    const xj: J = idn({ r: 4, g: 1, b: 2 })
    print(xj.r ?? 0)
    // vl check: {r: i32, g: i32, b: i32} is not J: they store field `r` differently ... only a fresh record widens

Want:

    4

#### Mechanism

The literal's record is adopted as the declared `Col`, because `Col` spells its exact field
set. Passed through `T`, the binding then receives a `Col` rather than a fresh record, so the
widening into `J`'s `i32 | null` field is refused. Without `Col`, the literal stays anonymous
and widens. Nothing in the program names `Col`, so a type declaration that is never used
changes whether a program is accepted. Module banking's `ambient` guard (D7800) depends on this
case: one module's private record type changes another module's check when the graph holds both.

#### Ablation

| change | outcome | needed? |
| --- | --- | --- |
| delete `type Col` | prints `4` | **yes** |
| `Col.r` is `f64` | prints `4` | **yes**, the exact field set and types |
| `Col` has an extra field | prints `4` | **yes** |
| `Col`'s fields reordered | refuses | no |
| `type Col = new { ... }` | refuses, same message | no |
| deliver the literal directly, `const xj: J = { ... }` | prints `4` | **yes**, the type parameter |
| `idn(mk())` with `mk` returning the literal | refuses | no, the literal need not be the argument |
| `idn<Col>(...)` | refuses | no |
| `Col` private to another module of the graph | refuses in the importer's check | no |

Removing `Col` makes no difference to any of these, which all print `4` either way: an `if` or
`match` join, `??`, a list literal, an inferred return, a nested field, a lambda, a map value, a
union arm, an untyped-parameter `function idh(v)`, std `last`, a generic method, a generic
record type `Bx<T>`, a `readonly J[]` and a `J | null` binding.

#### Grading list

The un-annotated spelling `const xj = idn({ r: 4, g: 1, b: 2 })` delivered later into a `J`
parameter. Then rerun D7800's ambient trace: once this closes, the literal half of that guard
has no case left to defend.

#### Close (2026-10-20)

`recAdoptNote` re-seats the literal at the destination when the call writes no type argument
and exactly one parameter mentions `T` (`recSolePinArg`); a call pinned anywhere else keeps the
refusal, because its instance can be shared with another call. A binding holding such a call
adopts as a binding holding the literal does (`recPassLitDeclOf`), which grades the un-annotated
spelling above. Over a 90-program grid against master, every change is a refusal or invalid
wasm becoming a run, plus two invalid-wasm programs (`i32` into `f64` through a binding) now
refused as their direct spelling is. The `idn(mk())` row of the ablation still refuses, so
D7800's literal half stays: [D8020](D8020.md). Also found grading: [D8021](D8021.md),
[D8022](D8022.md).
