### D4012 — a list of generics bound by `let`, or written through an element inside a closure, is not followed by the list pin, so its element call reuses another instance

**loud emit reject · `vl check` rc 0 · clause 2 · OPEN · `a generic function taken as a value reaches no call that fixes its type` since [D4123](D4123.md)'s refusal (#3569); was clause 1 before it**

Repro:

    function inner<U>(u: U) { print("I"); print(u) }
    function other<V>(v: V) { print("O"); print(v) }
    function main() {
      inner(3)
      let fs = [other]
      fs[0] = inner
      fs[0](true)
    }
    main()
    // vl check: rc 0.  vl run: prints I 3 I 1

Want:

    I
    3
    I
    true

#### Mechanism

Not located past the gate. The D3977 list pin and D3979's element-write coercion follow a
`const` list whose element writes sit in the same function body. A `let`-bound list is not
followed at all, the element write is scenery (`let fs = [other]; inner(3); fs[0](true)` traps
with no write), and a `const` list written from inside a closure is not followed either. Either
way the element call pins nothing and reuses whichever instance already exists, or with none
refuses loudly.

#### Ablation

| ingredient changed | outcome | needed? |
| --- | --- | --- |
| `const fs` (D3979) | runs | **yes** (`let`) |
| no write, `let fs = [other]; fs[0](true)` after `inner(3)` | trap, indirect call type mismatch | no |
| no prior instance (`inner(3)` removed) | loud emit reject, no interned signature | changes the clause |
| `const fs`, the write `fs[0] = inner` inside a closure `w` that is called (`L03`) | prints `I 3 I 1` | the closure is the ingredient |
| `L03` without `inner(3)` | loud emit reject | changes the clause |
| `L03`'s shape on a `let f`, not a list | runs | **yes** (the list) |
