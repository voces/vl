### D3260 — an un-annotated nested record literal takes a declared row whose nested field has the same name but a scalar type

**loud emit reject · filed 2026-09-29 against master `73bbd20bb` · the family of [D2423](D2423.md) (a declared shape captures an anonymous literal) · found writing #3293's `labelled-block-vs-object.vl`**

Repro:

    type P = { a: { b: i32 } }
    const q = { a: { b: { c: 4 } } }
    print(q.a.b.c)
    // vl check: rc 0.  vl run: emitProgram: nested struct fields are not supported

Want:

    4

#### Mechanism

The outer literal matches the declared `P` by field names, and the per-field refutation that
D2423 added does not reach a record literal against a declared nested row whose own field is a
scalar: the inner `{ b: { c: 4 } }` is taken for `P.a`'s `{ b: i32 }` row, and a record stored
into its `i32` slot is refused. The declaration is never used; its field names are enough.

#### Ablation

| ingredient changed | outcome | needed? |
| --- | --- | --- |
| no `type P` line | runs | **yes** |
| `P = { a: { d: i32 } }` (different inner name) | runs | **yes** |
| one level shallower (`P = { b: i32 }`, `{ b: { c: 4 } }`) | runs | **yes** |
| `q` annotated with its own type | runs | the un-annotated literal: **yes** |
| the literal as a function's tail, not a global | same refusal | no |
