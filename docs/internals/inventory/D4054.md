### D4054 — an existing wider record bound, returned or assigned at a narrower record type is refused as a codegen gap

**open · loud check reject · clause 2 (the refusal says `type-valid … but not yet supported by codegen`) · found re-grading `docs/spec/types.md` §T4.6 after D3631 closed (lane SPEC) · filed 2026-10-11 against master `98a4ed71b`**

Repro:

    type Animal = { b: string }
    type Cat = { b: string, a: i32 }
    const c: Cat = { b: "tom", a: 1 }
    const an: Animal = c
    print(an.b)
    // vl check: rc 1, "an object value of shape Cat flowing into Animal drops the field `a`:
    // type-valid (structural width subtyping) but not yet supported by codegen"

Want:

    tom

#### Mechanism

D3992 closed width subtyping into a declared record PARAMETER by making that parameter
generic, so an existing `Cat` is passed to `function nm(x: Animal)` as it is. A binding, a
return and an assignment have no such route, and D3992's own ablation table records the
binding as "loud check reject (kept)". These positions still accept the value only when
every dropped field's name sorts after every kept one. Here `a` sorts before `b`, so the
value is refused.

#### Ablation

| variant | outcome |
| --- | --- |
| this witness | refused with the codegen-gap sentence |
| fields `a` kept, `z` dropped (the dropped name sorts last) | runs, prints `tom` |
| `function nm(x: Animal): string { x.b }` with `nm(c)` | runs, prints `tom` (D3992) |
| `function f(c: Cat): Animal { c }`, the return position | refused, same sentence |
| `let an: Animal = { b: "x" }` then `an = c` | refused, same sentence |

#### Grading list

The three positions in the ablation table: binding, return and assignment. Also re-grade
D4050, a list of the wider record into a `readonly` list of the narrower one, which reaches
the same refusal through a container.
