### D10191 — a `slice` copy of a list holding a generic, written by index with a fixed-type function, has no one instance

**loud emit reject · `vl check` rc 0 · `a list holding a generic function is called through its elements at more than one type, so its elements have no one instance` · clause 2 · CAPABILITY: the copy spelled `[...xs]` prints `2`, `s`, `6` · found closing [D10082](D10082.md) · present on master `9ca7e7751` · filed 2026-10-22 against master `9ca7e7751`**

Repro:

    function id<T>(x: T): T { x }
    function inc(x: i32): i32 { x + 1 }
    const xs = [id]
    const ys = xs.slice(0)
    ys[0] = inc
    print(xs[0](2))
    print(xs[0]("s"))
    print(ys[0](5))
    // vl check rc 0.  vl run: emit error: emitProgram: a list holding a generic function is called through its elements at more than one type, so its elements have no one instance — annotate the list's element type

Want:

    2
    s
    6

#### Mechanism

Not traced. The refusal points at the source literal `[id]`. Since the close of
[D10082](D10082.md), the same program with `ys.push(inc)` and `ys[1](2)` runs, so the index
write through the copy is the ingredient that differs. The spread copy runs with the same index
write, so the copy's missing expansion in the flow pass (`mfrSliced`, emit_mono.vl) is the
likely seat, as for [D10190](D10190.md). Left open by the lane that closed
[D10202](D10202.md) and [D10204](D10204.md): an emit mechanism the checker changes there do
not reach.
