### D1813 — a type parameter only the RETURN type names refused at the monomorphizer, not at the checker

**now a loud check reject · filed 2026-09-06 against master `78e690ee9`**

Repro:

    function mk<T>(): T[] { return [] }
    mk()
    // vl check: rc 0.  vl run: emitProgram: monomorphize: a return type
    // parameter of `mk` is not bound by any parameter

#### Mechanism

`bindGenWalk` binds a generic call's type parameters from the ARGUMENTS, and VL has no
explicit type-argument spelling, so a parameter that appears only in the return type is
bound by nothing at any call. The checker typed `mk()` as `T[]` and let it flow into any
annotated destination; `monoSubstAnn` then found no binding and refused at emit — a
clause-2 violation by construction, since `check` returned 0 to reach it.

The destination annotation is not a pin: `const xs: i32[] = mk()` is checked against the
call's type, never fed into inference, and it refused identically. `checkRetTyParamBound`
now asks the declaration's written SPELLINGS — does the return annotation mention the
name, and does no parameter annotation — from both the direct and the UFCS call paths.
The spelling is what decides, not the arena row: a phantom `Bare<A>` parameter binds `A`
that its structural row (`{base: i32}`) has dropped.

#### Ablation

| ingredient removed | outcome | needed? |
| --- | --- | --- |
| the call (declaration alone) | runs | **yes** |
| `T` in the return, kept in a parameter (`box<T>(seed: T): T[]`) | runs | **yes** |
| the destination annotation (`const xs: i32[] =`) | still refuses | no |
| the array (`function mk<T>(): T`) | still refuses | no |
| the direct spelling, taken as UFCS (`b.firstOf()`) | still refuses | no |

`phant<A>(self: Bare<A>, i: i32): A` runs and must keep running; an arena-shaped version
