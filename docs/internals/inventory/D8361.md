### D8361 — a `null`-typed read handed through a generic identity into a nullable-record map value is built at the map's record

**check-clean invalid wasm · clause 1 · open · present on master `f28d2ba58` (there the instance is `i32`) · found closing [D8280](D8280.md) · filed 2026-10-20 against master `f28d2ba58`**

Repro:

    type C = { a: i32, b: i32 }
    function id<T>(x: T): T { x }
    const nn = null
    const m: { [string]: C | null } = Map()
    m.set("k", id(nn))
    print(m.get("k") == null)
    // vl check: rc 0.  vl run: invalid module in the top-level code, expected nullref, found (ref null $C)

Want:

    true

#### Mechanism

The instance `id` is pinned at `null`, so its parameter is a `nullref`. The read `nn` inside the
argument is emitted as `ref.null $C`. `emitMapSetValExpr` (wasmEmit.vl) seeds
`nulRefHeap` with the map's value heap for a bare `null` value. The seed is still set when the
call's own argument is emitted, so a `null` read deep inside the call takes the map's heap
instead of the instance's parameter heap. The pin is right; the value context leaks across a
call boundary. The close is in wasmEmit.vl, outside lane L1.
