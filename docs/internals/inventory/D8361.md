### D8361 — a `null`-typed read handed through a generic identity into a nullable-record map value is built at the map's record

**closed · was check-clean invalid wasm, clause 1 · `emitDirectCallArgsUnder` (wasmEmit.vl) clears the destination's `nulRefHeap` seed before it emits a call's arguments · pinned by `tests/cases/maps/null-read-through-identity-into-nullable-record-value.vl` and its `-annotated` twin, and by the `map_set` / `map_value_place` annotated cells of `null-hole-through-generic-identity` · found closing [D8280](D8280.md) · filed 2026-10-20 against master `f28d2ba58`**

Repro:

    type C = { a: i32, b: i32 }
    function id<T>(x: T): T { x }
    const nn = null
    const m: { [string]: C | null } = Map()
    m.set("k", id(nn))
    print(m.get("k") == null)
    // vl check: rc 0.  vl run: prints true (was: invalid module, expected nullref, found (ref null $C))

Want:

    true

#### Mechanism

The instance `id` is pinned at `null`, so its parameter is a `nullref`. `emitMapSetValExpr`
(wasmEmit.vl) seeds `nulRefHeap` with the map's value heap for a bare `null` value, and
`emitDirectCallArgsUnder`'s argument context cleared the other destination seeds but not that
one, so the `null`-typed read `nn` inside the argument took the map's heap and was emitted as
`ref.null $C`. The pin was right; the value context leaked across the call boundary. The close
clears `nulRefHeap` in the argument base, so a parameter's own seeds are the only ones an
argument sees.
