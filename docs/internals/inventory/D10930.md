### D10930 — a list of a generic alias whose record holds an inline nested record, handed to a generic, has no list rep

**closed 2026-10-23 — the filed repro RUNS and prints `1` · was a loud emit reject, `emitProgram: only i32[] arrays and struct/union element arrays are supported` · clause 2 · found by lane D10880 ablating D10882 · filed 2026-10-23 against master `8be0b10be`, re-confirmed live at `4e10a2462` · fixture `tests/cases/generics/alias-inline-nested-record-list.vl`**

Repro:

    type B<U> = { s: { g: U } }
    function f<T>(v: B<T>[]): i32 { v.length }
    print(f([{ s: { g: 3 } }]))
    // vl check: rc 0.  vl run: emitProgram: only i32[] arrays and struct/union element arrays are supported

Want:

    1

#### Mechanism

The instance's annotation `B<i32>[]` is interned by the second `collectGenAliasShapes`, after
`monomorphize`. `gaeInternAppFieldShapes` interns the substituted field shape `{g:i32}`, but
by then `collectAnonShapes` has already interned the argument literal's `{ g: 3 }` as an
`#anonN` row, so the field shape dedups onto that row. `gaeEnsure` then looked the field up
by its applied spelling (`structIndexByName("{g:i32}")`), found nothing, declined the whole
application, and the list rung in `collectA#2` had no `B<i32>` row and refused. A source
annotation `B<i32>[]` ran because the first `collectGenAliasShapes` runs before
`collectAnonShapes`, so the shape interned under its own spelling.

`gaeEnsure` now asks the interner's nested-field arm (`nestedFieldShapeRow`, shared with
`internInlineShapeTyGo`) for the row and keys the field by that row's own name.
