### D2635 — `return <expr>` whose value is void is refused inside a void function

**loud check reject · clause 2 · plumb PL-045 (reported by plumb) · filed 2026-09-26 against master `50c627ce4`**

Repro:

    function g(x: i32) { print(x) }
    function f(op: i32) {
      if op == 0 { return g(1) }
      g(2)
    }
    f(0)
    f(1)
    // vl check: return expects a value, got void

#### Mechanism

`checkRetStmtNode` sends every `return <expr>` through `voidValueSlotErr`, on both the inferred
(`-2`) path and the declared `: void` path, so a void call returned from a function that itself
returns nothing is refused as a missing value. The refusal is owed only when the function
returns a value; in a void function `return g(1)` means "call, then return".

#### Ablation

| ingredient changed | outcome | needed? |
| --- | --- | --- |
| `return g(1)` → `g(1); return` | runs | **yes** |
| `f` annotated `: void` | still refuses | no |
| `f` returns `i32` elsewhere (`return 5`) | refuses, and must keep refusing | the void function |
