### D2635 — `return <expr>` whose value is void is refused inside a void function

**closed 2026-09-26 — the witness prints `1` then `2` · was loud check reject, clause 2 · plumb PL-045 (reported by plumb) · filed 2026-09-26 against master `50c627ce4` · fixtures `tests/cases/functions/return-void-call-in-void-function.vl`, `error-return-void-call-in-valued-function.vl`, `error-return-void-call-in-annotated-function.vl`**

Repro:

    function g(x: i32) { print(x) }
    function f(op: i32) {
      if op == 0 { return g(1) }
      g(2)
    }
    f(0)
    f(1)
    // On master: vl check: return expects a value, got void

#### Mechanism

`checkRetStmtNode` sent every `return <expr>` through `voidValueSlotErr`, on both the inferred
(`-2`) path and the declared `: void` path, so a void call returned from a function that itself
returns nothing was refused as a missing value. The refusal is owed only when the function
returns a value. The close accepts a wholly void `return e` as a void return: on the declared
path at once, on the inferred path once the function's return is final (refused, naming the type,
if it infers a value). A void that is only a recursive cycle's provisional answer is not taken
for one. Once every body is checked, `voidRetRewrite` splits each accepted site into the
statement `e` and a bare `return` in its block, which the emitter already lowers, and whose bare
`return` its void classification (`computeVoidFns`) already reads.

#### Ablation

#### Grading list

The run fixture grades each position in its own function, printing which arm ran: an early
return, the tail, a declared `: void`, both arms of a nested `if`, `while` and `for`-in bodies,
beside a bare `return`, every return void, `print`, a void function value, an inferred closure, an
annotated `: void` closure, a lambda argument to a void parameter, a nested closure, recursion
under `: void`, a generic, a `match` arm and a parenthesised call. Un-annotated recursion
(`function f(n) { if n > 0 { return f(n - 1) } print(n) }`) still asks for an annotation, as
it did before, because the recursive call's type is not known while the return is inferred.
Mutual recursion through a value return (`a` → `b` → `a`) still infers `i32`.
