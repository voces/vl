### D2720 — a `T | string` parameter pinned at a boolean map answers `is Set<i32>` true, since the box tag is shared with the Set

**closed 2026-09-26 — the filed repro RUNS and prints `false` then `true` · was check-clean silently wrong (`true true`) · clause 1 · found by #3202's review (a3, a3b) · closed in the same PR as D2684: an exact instance answers a box test from the member set it binds · filed 2026-09-26 against master `74bd044d7` · fixture `tests/cases/generics/pin-exact-key-union-box-is.vl`**

Repro:

    function f<T>(u: T | string) { print(u is Set<i32>) }
    const s: Set<i32> = Set()
    const m: {[i32]: boolean} = Map()
    f<{[i32]: boolean}>(m)
    f<Set<i32>>(s)
    // PRINTS false
    // PRINTS true

#### Mechanism

A union box holds a Set under the tag of its boolean map, because the emitter spells the set as
that map (D2673). The instance pinned at `{[i32]: boolean}` therefore tags the map with the tag
`is Set<i32>` tests for, and answers true. Inside an exact instance (D2684) the operand's type is
known with `T` substituted, so `exactUnionLacksMap` answers the test false when no member of that
type is the pattern's map exactly. The tag test still decides the case where the member is there.
