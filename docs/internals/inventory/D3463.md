### D3463 — a `u8[]` literal past the operand cap with a computed element is refused, where every other scalar list builds chunked

**loud emit reject (`emitProgram: u8 array literal is too long for one array.new_fixed`) · a clause-2 capability refusal · found by lane AL while closing D3417 · filed 2026-09-30 against master `d8b998a5e`**

Repro:

    let m = 3
    m = m + 1
    const u: u8[] = [m, @@repeat(10000, "1, ")@@1]
    print(u.length)
    // vl check: rc 0.  vl run: emit error, "u8 array literal is too long for one array.new_fixed"

Want:

    10002

#### Mechanism

The `u8[]` literal arm in `emitArr` (compiler/wasmEmit.vl) has no chunked build: past the
10,000-operand `array.new_fixed` cap it refuses. D3417 gave it the data-segment build, which needs
every element to be a literal, so an all-literal `u8[]` literal of any length now builds and one
computed element brings the refusal back. The `i32`, `i64`, `f32` and `f64` arms chunk through a
lazily-minted backing local (`arrLitChunkStart`); the packed `i8` backing has no lazy-local kind
there (`liKinds` in compiler/emit_bytes.vl), which is the work a close owes.

#### Ablation

| ingredient changed | outcome | needed? |
| --- | --- | --- |
| every element a literal | runs (D3417's data segment) | **yes**, a computed element |
| 10,000 elements or fewer | runs, one `array.new_fixed` | **yes**, past the cap |
| `i32[]` instead of `u8[]` | runs, chunked | **yes**, the packed element |

#### Grading list

The same literal in a function body, and as a field value.
