### D5340 — a function returning the nullable atom `K | null` traps when its body falls off its end

**closed · clause 1 · eardstap EV-007, the same defect as D2041 · filed 2026-10-17 against master `cd07cb6a8`**

Repro:

    type R = "a" | "b" | "c"
    function f(c: boolean, r: R): R | null {
      if c { r }
    }
    print(f(true, "b") ?? "none")
    print(f(false, "b") ?? "none")
    // vl check: rc 0.  vl run, before the fix: wasm `unreachable` trap in `f`

Want:

    b
    none

#### Mechanism

The fall-through path of a nullable return is lowered by `emitNullForRet`, gated on
`fnRetNullBearing`. Neither knew the nullable atom rep (the i32 atom with the `-1` sentinel),
so the function end was padded with `unreachable` and the else-less tail `if` was lowered as a
statement that drops its value. Every shape that falls through traps: an else-less tail `if`
(a value or an assignment, whose value is the assigned atom), an `if` or loop that returns
early, and an `else if` chain with no final `else`. eardstap's spelling reached it through an
exported un-annotated function, whose return is inferred from the body as `R | null`; the module
split and the null-narrowed record field are scenery. The fix names the rep in both functions
(`fnRetIsNulAtom`).
