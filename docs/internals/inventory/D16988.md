### D16988 — the redundant-annotation hint names a function's return annotation that breaks an inference cycle through a global, so following it is a check error

**runs today and must keep running · message quality · the hint is wrong where it fires, not the program · found by lane IR2 writing `tests/cases/start-order/read-own-global-before-init.vl` · filed 2026-11-18 against master `666291883`**

Repro:

    function f(): i32 { return x.n * 2 }
    const x = { n: 3, g: f }
    print(x.g())
    // vl run: prints 6. The type-informed hint stream (the corpus oracle's lint tier) says
    // "redundant type annotation: `f` is inferred as `i32`"; without `: i32`, `vl check`
    // fails "cannot infer a return type for 'f' — annotate a return type".

Want:

    6

#### Mechanism

The hint compares the annotation with the type the body infers once the checker already holds
`x`'s type, which it could only build because the annotation gave `f` a type first. The cycle
`f` → `x` → `f` is broken by the annotation itself, so a comparison made after the cycle is
solved finds them equal. The same check that refuses the un-annotated spelling (no return type
inferable inside the cycle) is not asked before naming the annotation redundant. D3800 closed the
initializer half of this class (an annotation whose removal changes what an initializer infers);
a return annotation through a global's initializer is outside it.

#### Ablation

| ingredient | outcome | needed? |
| --- | --- | --- |
| `f`'s only return reads `x` | with a second `return 1` arm, removal still checks and the hint is right | **yes** |
| `x`'s initializer reaches `f` (here as a field value) | without it there is no cycle and the hint is right | **yes** |
| the call happens during the initializer (`const x = f()`) | same hint; the program then traps on the read-before-init guard | no |
| `x` annotated | both annotations hinted, `x`'s correctly | no |
