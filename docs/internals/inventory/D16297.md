### D16297 — writing a narrowed path's other member while a nested function re-tests it is refused as `cannot assign string to i32`

**closed 2026-11-15 · runs, prints `false` · was a loud check reject, clause 2, `cannot assign string to i32` · closed by holding a write to a narrowed path to the narrowing only when a nested function checked since read the path under it (`npCapBy`, `writeStorageTy`), not whenever one was checked · fixture `tests/cases/soundness/path-write-under-retesting-closure-runs.vl` · filed 2026-11-14 against master `4b94dbf0b`, the path twin of [D2463](D2463.md), found closing [D2464](D2464.md)**

#### Mechanism

Localised at the close: `writeStorageTy` answered the narrowing, not the storage, for a path
whose narrowing predates the latest nested function check (`narFnEpoch`), whether or not that
function read the path. `xs[0]` stores `i32 | string`, so the write is legal: without the nested
function the same write runs. The checker keeps the narrowing live for `c` and checks the write
against it, as it did for a bare name before D2463's close. `c` only re-tests the place, which
reads its storage (D2464's close), so nothing reads the old narrowing.

#### Grading list

The field spelling `o.v` and a function-local list. With `c` reading `xs[0] + 1` instead, a
refusal is owed, but its sentence should name `c` as D2402's per-call rule does.
