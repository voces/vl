### D16297 — writing a narrowed path's other member while a nested function re-tests it is refused as `cannot assign string to i32`

**loud check reject · clause 2 · filed 2026-11-14 against master `4b94dbf0b`, the path twin of
[D2463](D2463.md), found closing [D2464](D2464.md) · open**

Repro:

    const xs: (i32 | string)[] = [1]
    if xs[0] is i32 {
      const c = (): boolean => xs[0] is i32
      xs[0] = "s"
      print(c())
    }
    // vl check: rc 1, "cannot assign string to i32", at the written value

Want:

    false

#### Mechanism

Not yet localised. `xs[0]` stores `i32 | string`, so the write is legal: without the nested
function the same write runs. The checker keeps the narrowing live for `c` and checks the write
against it, as it did for a bare name before D2463's close. `c` only re-tests the place, which
reads its storage (D2464's close), so nothing reads the old narrowing.

#### Ablation

| ingredient removed | outcome | needed? |
| --- | --- | --- |
| the nested function `c` | runs; `xs[0] is string` after the write prints `true` | **yes** |
| the write | runs, prints `true` | **yes** |
| the storage (a field `o.v`, or a local list in a function) | the same refusal | no |

#### Grading list

The field spelling `o.v` and a function-local list. With `c` reading `xs[0] + 1` instead, a
refusal is owed, but its sentence should name `c` as D2402's per-call rule does.
