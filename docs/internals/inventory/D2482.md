### D2482 — an unrelated declared row's nullable-`i32` field is what a same-named boolean literal field reads back as

**check-clean silently wrong · clause 1 · found in review of #3147 against master `0a0d24ac9`, filed 2026-09-25**

Repro:

    type Q = { k: i32 | null }
    const r = { k: true }
    print(r.k)
    // PRINTS null
    // vl check: rc 0.  Want `true`: r's own field is a boolean, Q is unrelated.

#### Mechanism

Not ablated to a rung. `r`'s literal has no annotation, and a declared type `Q` elsewhere in the
module has a field also named `k` — a nullable union, `i32 | null`. `r`'s own field is a
`boolean`, an unrelated shape, but something matches `r` to `Q`'s row by field NAME alone and
builds `r.k` at `Q`'s nullable-union rep; reading it back sees the union box's null tag rather
than the boolean's own bit, so `print` renders `null`. D2435 already closed the plain-scalar
case of a declared row absorbing a differently-coded literal (`i32` field vs `boolean` literal,
both code 0); this is the same family one layer up, where the declared field's code is a
NULLABLE UNION rather than a bare scalar, and D2435's fix does not reach it.

#### Ablation

| ingredient removed | outcome | needed? |
| --- | --- | --- |
| the declared type `Q` | runs, prints `true` | **yes** |
| `Q`'s field made non-nullable (`k: i32`) | runs, prints `true` (D2435's fix covers this) | **yes** |

#### Grading list

D2483 (the same shape over `f64 \| null`, which refuses instead of misreading); the annotated
spelling `const r: { k: boolean } = { k: true }`, which must keep printing `true`.
