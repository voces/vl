### D1750 — a lambda returning a captured MAP resolves no `$fnsig` result slot when the capture's binding is an INDEX projection, so the value call has no interned signature

**runs today (closed by #2770's lambda root set) · filed as a loud emit reject against `65a34adcc`, re-graded `runs` on `1a5955551` · 5 cells (`map_index` un-annotated at `function` / `fn_block` / `fn_while` / `module_block` / `module_while`) of [D1758](D1758.md)'s grid · 0 corpus cells**

Repro:

    type Rec = { n: i32 }
    function mkval(): { [string]: Rec } {
      const m: { [string]: Rec } = Map()
      m["k"] = { n: 4 }
      return m
    }
    function go() {
      const xs = [mkval()]
      const held = xs[0]
      const get = () => held
      print((get()["k"] ?? { n: 0 }).n)
    }
    go()
    // vl check: rc 0.  vl run: rc 0, prints 4

#### Mechanism

**The filed mechanism was wrong and three probes replaced it.** It said `mapShapeOfExpr` has
arms for a call, an ident and a field read and none for an index read. It has one —
`compositionMapReadSlot`'s list-of-maps rung, gated on `exprRefArray` plus a kind-3 element —
and routing the capture's companion through it was built, graded, and reverted: the 144-cell
grid was identical with and without the arm.

What the probes actually found, each fired on the loud cell with the running field face as the
silent control:

    D1750PROBE cloRetKeySuffix  slot=0 fRetKind=map capShape=0 tok=[m0;]      ← the INTERN side
    D1750PROBE ckey=[>m1;] pos=-1 arenaKey=[>m1;] arenaPos=-1                  ← the CALL side
    D1750PROBE mvTable= [Rec] [{n:i32}]  find=0  valName=[{n:i32}]  byName=1

**One map value type is interned at TWO mv slots under two spellings** — slot 0 as the declared
alias `Rec`, from `mkval`'s annotation, and slot 1 as its structural render `{n:i32}`, from the
ref-list element. `collectCloSigs` minted `>m0;` through the arena-hinted resolver while the
call site derived `>m1;` on BOTH its routes, the name one and the arena-key override, and
`>m1;` was interned by nothing. The existing divergence override fires only when one of the two
keys IS interned, so it could not bridge them. The field face never split because
`sFieldMapShape` reads the field's recorded companion, minted from the declared spelling, so
both sides land on slot 0.

**#2770 closed the SYMPTOM, not the split.** Making every lifted function's own type a `$fnsig`
root interns the key the call site derives, so the two spellings now both name an interned
signature and the call resolves. The two slots are still two slots: the interning is unified
nowhere, and a program that needs them to BE one — two readers keying one map value type
through different spellings at a site with no root to fall back on — would split again. That is
a **latent hazard with no witness**: it is recorded here because the probe measured it, not
because a program reaches it, and it should not be scheduled until one does.
