### D2451 — an assignment skipped by a short circuit or an optional call still reads back as a written value

**check-clean silently wrong · clause 1 · pre-existing on master `20651a88b` · filed 2026-09-25 against master `20651a88b`, found reviewing #3154 · the `if`-condition spellings (`&&`, `||`, over `i32 | null` and `string | null`) run correctly since D3285's join (2026-09-29), which folds a condition's write as one that may not have run; the witness is now the `??` spelling, which has no `if`**

Repro:

    function nn(v: i32): i32 | null {
      if v < 0 { return null }
      return v
    }
    function main() {
      let c: i32 | null = null
      const _k = nn(3) ?? (c = 5)
      print(c ?? -1)
    }
    main()
    // PRINTS null
    // vl check: rc 0.  Want `-1`: the right of `??` never ran, so `c` is still null.

Want:

    -1

#### Mechanism

Not ablated. After the `if`, `a ?? -1` prints `null`, so the read of `a` is neither the stored
`null` taken through `??` nor `5`. The assignment sits where it may not run (the right of `&&`,
or the argument of `xs?.push(a = 5)` on a null `xs`), and something after it treats `a` as
written: a post-write narrowing, or the box's tag read at the non-null member. The same program
without the short circuit prints `5`.

#### Ablation

| ingredient removed | outcome on `20651a88b` | needed? |
| --- | --- | --- |
| the short circuit (`if (a = 5) > 0`) | prints `5` | **yes** |
| `&&` for `?.` (`xs?.push(a = 5)`, `xs` null) | still prints `null` | no |
| `??` for `&&` inside an `if` condition | prints `-1` since D3285 | the `if` spellings run |

#### Grading list

`||` with a true left side; `??` with a non-null left side; the three with `a: string | null`.
