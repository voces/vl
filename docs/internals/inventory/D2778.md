### D2778 — `T | null` pinned at a record answers `is` against an anonymous record of the same field names by the null test

**closed 2026-09-27 — the filed repro RUNS and prints `false` · was check-clean silently wrong (`true`) · clause 1 · found by #3208's review (item 1) · closed in #3208 with D2753: the niche test asks the exact instance whether it holds only a twin of the pattern · filed 2026-09-27 against master `f6db92e0d` · fixture `tests/cases/generics/pin-exact-key-niche-record-twin.vl`**

Repro:

    function f<T>(u: T | null): boolean { u is {a: string} }
    print(f<{a: i32}>({a: 1}))
    // PRINTS false

#### Mechanism

A record beside `null` is a niche, so `u is P` was the null test whenever `P` shared the held
record's variant row, and anonymous records share a row by field names alone. D2753's twin rule
covered a union box; the niche test (`nulNicheIsTestImpossible`) now asks it too, so a held
`{a: i32}` answers `false` for `{a: string}` and `true` for itself.
