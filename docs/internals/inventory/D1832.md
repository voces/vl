### D1832 — a list literal of only `null` infers `null[]`, and every read of one refuses at the literal

**closed 2026-10-12 — now a loud check reject, by the owner's ruling (option a, open-rulings.md
§D1832): a null-only list literal no typed destination receives is refused by `vl check` with a
sentence naming the annotation · was loud emit reject, clause 2 · filed 2026-09-06 against
master `b7a666856` · found while grading [D1830](D1830.md)'s null-first and null-only cells**

**THE CLOSE.** `checkArrayLitNode` records a literal whose joined element type is the `null`
type; `assignableExpr`, the seam every typed delivery flows through, marks it taken when its
own destination (walked beside the value through list elements, record fields and value tails)
names an element type and holds no type variable; `flushNullOnlyLits` refuses the rest at
program end: "a list of only `null` has no element type; annotate it, e.g. `const e: (i32 |
null)[] = [null]`". Inferring the element from the first non-null use (option c) is the later
target, on ROADMAP.md. Residue at typed destinations the emitter does not seed:
[D4190](D4190.md) (a value `match`/`if` tail) and [D4191](D4191.md) (a generic record field).

Repro:

    const e = [null]
    print(e.length)
    // vl check: rc 0.  vl run: emitProgram: bare null needs a struct-typed context
    // Should print 1.
    // Since the ruling: vl check refuses it, `a list of only `null` has no element type`.

#### Mechanism

Not yet ablated to a rung. The literal's inferred type is pinned: forcing it into a diagnostic
(`const bad: i32 = e`) reads `cannot assign null[] to 'bad' of type i32`, so the element is the
bare `null` type and not a nullable of anything. There is no non-null member, so no value box
is owed and D1830's registration correctly declines — the refusal is the element rep itself
having no cell to live in, and it fires at the LITERAL, before any read.

Not D1830's, and the boundary is sharp: `[null, 42]` runs since D1830, so it is the ABSENCE of
a non-null member and not the position of the `null`. Whether `null[]` should be a legal
inferred type at all, or should be an open element hole a later `.push` pins (A-infer-null's
rule for a scalar binding), is an owner question this row does not answer.
