### D9100 — an un-annotated function in an un-annotated `Map()` that no read calls has no map value type

**loud emit reject · `vl check` rc 0 · `unsupported map value type` · clause 2 · found closing [D9063](D9063.md) · filed 2026-10-21 against master `7736fb65b`**

Repro:

    function inc0(a) { return a + 1 }
    const m = Map()
    m["k"] = inc0
    for k in m { print(k) }
    // vl check rc 0.  vl run: emit error: emitProgram: unsupported map value type (no rep for a union-member struct, ...)

#### Mechanism

Not traced. The map's value type comes from the parameter types its calls pin on the value
slot (`monoPinMapValues`, `monoStoredSlotFnTy`, emit_mono.vl). With no call there is no
pin, so the value keeps the function's hole signature, which the map value layer has no
slot for. An uncalled hole function on its own is served by a stub (D6830); a map holding
one is not. The list spelling held in a record field fails at the field instead.

#### Ablation

| ingredient removed | outcome | needed? |
| --- | --- | --- |
| the annotation's absence (`const m: {[string]: (a: i32) => i32} = Map()`) | runs, prints `k` | **yes** |
| the uncalled value (`for k, g in m { print(g(3)) }`) | runs, `4` | **yes** |
| the map (`const xs = [inc0]`, `const r = { xs: xs }`, `print(r.xs.length)`) | `ref valtype with no interned shape` | no |

#### Grading list

`const r = { m: m }` then `print(r.m.length)`, and the list spelling in the ablation.
