    // vl check: rc 0.  vl run: prints 3 then 3.5.

#### Mechanism

Two mechanisms wearing one validator sentence, and only the first is this row's.

**This row: the clone was never minted.** `monoPinBodyLambdas` and `monoLamNodeIsTemplate`
both returned early on `typarams.length == 0` — `fn.fnTyParams`, the column of DECLARED `<T>`
names. An inference-hole generic pins its parameter without declaring one, so the nested-clone
walk never ran and one lifted `k` served both instances. Probed, not read: an instance of
`function o(n)` reports `fnTyParams=0` and one of `function o<T>(n: T)` reports `fnTyParams=1`,
which is why the explicit face failed identically and looked like a refutation. Removing both
guards lets the existing D943 capture rung fire; disassembly of the witness goes from
`$o, $k, $o$1` (no clone) to `$o, $k, $k_7, $o$1`.

**The second is [D1781](D1781.md)**, which the first exposes: the instance's `return k(1)`
resolved `k` through the flat `fnIndexOfSid` and adopted the TEMPLATE's return kind.
