### D3049 — `-(-2147483648)` at an i64 destination is computed as i32 and sign-extended

**closed 2026-09-28 — the filed repro prints `2147483648` · was check-clean silently wrong, the same on master `3a71bb1f9` and `0b618d160` · closed with [D3043](D3043.md): the i64 destination adopts the whole negation chain, so the double negation is computed at 64 bits · fixture `tests/cases/expressions/negation-chain-at-i64.vl` · found by the #3262 review · filed 2026-09-28 against master `3a71bb1f9`**

Repro:

    const C0: i64 = (-(-2147483648))
    print(C0)
    // PRINTS -2147483648

Want:

    2147483648

#### Mechanism

This is [D3043](D3043.md)'s disagreement with no i64 instruction to reject it. The emitter's
`exprIsI64` reads `-2147483648` as an i32 at `I32_MIN` and propagates that through the outer `-`.
So the double negation computes `0 - I32_MIN`, which wraps back to `I32_MIN`, and the
`i64.extend_i32_s` at the i64 cell sign-extends it. The checker's i64 type says the value is
`2147483648`. `function g(): i64 { -(-2147483648) }` prints the same wrong value.

#### Grading list

`function g(): i64 { -(-2147483648) }`, and [D3043](D3043.md)'s witness.
