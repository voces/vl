### D15975 — the owner-ruled reference-identity operator `===` is unbuilt, and the parser's refusal contradicts the ruling

**loud emit reject · clause 2 · open · filed 2026-11-12 against master `2bb5d2f2a`; the refusal moved from the parser to the emitter on 2026-11-14**

Repro:

    type A = { x: i32 }
    const a: A = { x: 1 }
    const c: A = { x: 1 }
    print(a === c)
    // vl run: emit error, "emitProgram: reference identity (`===` / `!==`) is not lowered yet"

#### Mechanism

`strictEqTail` (compiler/parser.vl) treats a third `=` after `==` as a JavaScript reflex,
consumes it and reports that VL has no `===`. The owner ruled on 2026-09-01
(`docs/identity-design.md` §0, DECISIONS A15) that `===`/`!==` is reference identity over
reference reps, a check error on scalars and `string`. No lowering exists, so the operator is
refused at parse and the message names a rule the design reversed.

Since 2026-11-14 the parser spells `===`/`!==` as equality-precedence operators and the checker
applies the ruling's operand rule (`compiler/check_identity.vl`): an operand with no identity is
refused with the `==` spelling, and operands no value can share are refused as `==` refuses them.
An accepted compare passes `vl check` and is refused at emit, one counted `emitFailAt` site with
a live-sites row and the probe `identity-eq-record.vl`, until the emitter lowers it.

#### Ablation

| ingredient changed | outcome | needed? |
| --- | --- | --- |
| `a == c` | runs, prints `true` (structural) | **yes** |
| operands `1 === 1` | the ruled check error, "`===` compares identity, and `i32` has none" | no |

#### Grading list

The identity design's §0 acceptance list (ROADMAP A15), and the `==`-on-views ruling
(open-rulings `width-view-equality`), whose identity counterpart is `===`.
