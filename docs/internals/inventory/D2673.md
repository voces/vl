### D2673 — a `Set<K>` and a map of its representation cannot share a union: the emitter spells the set as the boolean map

**loud check reject · clause 2 · the `Set<K>` half of D2493, which D2493's fix left refused · filed 2026-09-26 against master `525837973`**

Repro:

    function f(x: Set<string> | {[string]: boolean} | null) { print(x == null) }
    f(null)
    // vl check: rc 1 — a union cannot hold both Set<string> and {[string]: boolean} yet

#### Mechanism

D2493 closed by giving each map TYPE that shares a map struct with another union arm its own box
tag, registered from the union's arm types. A set never reaches that registry as a set: the
emitter renders `Set<K>` as `{[K]: boolean}` (`tyToEmitName`), so the union's member-set key is
`{[string]:boolean}|{[string]:boolean}` and the set arm is the boolean map by the time a tag is
chosen. With `setMapUnionClashMsg` lifted and nothing else changed, the repro's declared-alias
twin printed `set` for the map, and a string-keyed set in the union was invalid wasm. The close
is a union spelling that keeps the set a set, then the D2493 registry already tells the two apart
(it compares arena types, and `tyEq` separates `mSet`).
