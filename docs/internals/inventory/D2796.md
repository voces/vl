### D2796 — a boolean list delivered into a union beside a float or `i64` list is widened into the number list

**closed 2026-09-27 — the filed repro RUNS and prints `true` · was check-clean silently wrong, printing `-1` · clause 1 · found grading D2783's three-list joins · filed 2026-09-27 against master `b586b6063` · fixture `tests/cases/unions/bool-list-arm-beside-number-list.vl`**

Repro:

    function h(c: i32, t: boolean): boolean[] | f64[] {
      if c == 0 { return [t] }
      [2.5]
    }
    const q = h(0, true)
    if q is boolean[] { print(q[0]) } else { print(-1) }
    // PRINTS true

Want:

    true

#### Mechanism

The union-box delivery classifies a boolean list as the i32 list, and a union with no `i32[]`
arm promotes that list to its `i64[]`, `f64[]` or `f32[]` arm, the widening an integer literal
list is owed. A boolean is no number, so `[true]` was built as `[1.0]` under the float-list tag
and `is boolean[]` answered false. A module-scope binding of the same union was a parse failure
of the module (`i64.extend_i32_s` in a global initialiser). Closed by keeping a boolean list at
the union's `boolean[]` arm (`exprIsBoolList`) before the promotion.

#### Ablation

| ingredient removed | outcome | needed? |
| --- | --- | --- |
| the float arm (`boolean[] \| string[]`) | prints `true` | **yes** |
| the boolean element (`i32[] \| string[] \| f64[]` at `[4]`) | prints `4` | **yes** |
| the return (`const q: boolean[] \| f64[] = [true]`) | the module fails to parse | no |

#### Grading list

`boolean[] | f64[]`, `boolean[] | string[] | f64[]`, `boolean[] | string[] | i64[]` and a
module-scope binding, each tested with `is boolean[]`; an integer literal list into
`boolean[] | f64[]` still widens to the float arm.
