### D2314 — an i32-keyed Set's `for`-in walk bound its membership booleans instead of its elements

**closed 2026-09-24 — the witness prints `0`, `3` and `6`. Found by the D2313 variant matrix; filed
against master `403fcd5e8`, where it prints `1` three times**

Repro:

    const s: {[i32]: boolean} = Set()
    for i in 0 until 3 { s.add(i * 3) }
    for x in s.values() { print(x) }
    // prints 0, 3, 6

#### Mechanism

`mapIsSetExpr` asked `mapShapeOfExpr(...) == -2`, the string-keyed set sentinel, and never the
i32-keyed one (-5). So for an i32-keyed Set `forInMapWalksVals` answered true and the walk read
the `vals` list (the stored `true`s) instead of the keys list, and `forInPairIsMapVal` bound
`for x, i in s`'s second name to the membership boolean rather than a dense index. The loop
variable's KIND was already right (`forInElemKind` has its own `-5` arm), so nothing refused.
`mapIsSetExpr` now answers both sentinels.

#### Ablation

| ingredient removed | outcome | needed? |
| --- | --- | --- |
| the i32 key (`{[string]: boolean}` Set) | runs | **yes** |
| `.values()` (`for x in s`) | runs, walks the keys | **yes** |
| `.values()` bound first (`const xs = s.values()`) | runs, a copied list | **yes** |
