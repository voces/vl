### D9760 — a `for` loop over a bound nested list of an un-annotated function, beside a read at another type, is refused as an iterable

**closed · runs, prints `4` `3.5` · was loud emit reject, `vl check` rc 0, `unsupported for-in iterable`, clause 2 · CAPABILITY: the flat list in the same loop ran · found closing [D9711](D9711.md) · filed 2026-10-22 against master `60aaa08c0` · closed by planning a `for … in` over a list whose literals hold only list literals as a read of each row's element slot, so each row read in the body calls its own instance (`monoFlowRowLoopUse`, emit_mono.vl) · fixture `closures/hole-fn-list-unbound-and-returned.vl` · with [D9763](D9763.md), [D9861](D9861.md) and [D9863](D9863.md) closed, [D9900](D9900.md) and [D9901](D9901.md) filed open; rows holding two different functions are [D9500](D9500.md)'s**

Repro:

    function inc(a) { return a + 1 }
    const u = [[inc]]
    for r in u { print(r[0](3)) }
    print(u[0][0](2.5))
    // vl check rc 0.  vl run: emit error: emitProgram: unsupported for-in iterable

Want:

    4
    3.5

#### Mechanism

The flow-read rewrite (`monoFlowReadsRound`, emit_mono.vl) plans each read of a list of
un-annotated functions so that it calls its own instance, and [D9711](D9711.md)'s close leaves the
list's element as the uncalled stub. It had no plan for a `for … in` whose rows are themselves
lists, so the row `r` found no element type. The flat twin (`for f in u`) already had a plan and ran.

#### Grading list

The same loop over a nested list handed to an un-annotated parameter; a dynamic index read
`u[i][0]` at two types, which refuses with `nested arrays are not supported`.

Graded at the close: a nested inner loop (`for f in r`) runs; the dynamic index is [D9900](D9900.md);
an alias of the row in the body is [D9901](D9901.md)'s nested twin; the list handed to an
un-annotated parameter is a check reject (`for-in expects an array, a map or a string, got _`) for
`[[3]]` as well, so it is not this family.
