### D9760 — a `for` loop over a bound nested list of an un-annotated function, beside a read at another type, is refused as an iterable

**loud emit reject · `vl check` rc 0 · `unsupported for-in iterable` · clause 2 · found closing [D9711](D9711.md) · present on master `e8163edd5` · filed 2026-10-22 against master `60aaa08c0`**

Repro:

    function inc(a) { return a + 1 }
    const u = [[inc]]
    for r in u { print(r[0](3)) }
    print(u[0][0](2.5))
    // vl check rc 0.  vl run: emit error: emitProgram: unsupported for-in iterable

Want:

    4
    3.5

#### Mechanism

Not traced. [D9711](D9711.md)'s close types the inner element with the uncalled stub when its pins
disagree, and each element read calls its own instance. The loop variable `r` is a row of that
list, and the loop asks the iterable for one element type at the row, which the list does not give
it. The flat twin (`const u = [inc]`, `for f in u { print(f(3)) }`, `u[0](2.5)`) runs.

#### Ablation

| ingredient removed | outcome | needed? |
| --- | --- | --- |
| the other type (`print(u[0][0](2))`) | runs, `4` `3` | **yes** |
| the read after the loop | runs, `4` | **yes** |
| the nesting (flat list, `f(3)` in the loop) | runs, `4` `3.5` | **yes** |

#### Grading list

The same loop over a nested list handed to an un-annotated parameter; a dynamic index read
`u[i][0]` at two types, which refuses with `nested arrays are not supported`.
