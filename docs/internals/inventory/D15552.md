### D15552 — a list of one generic function's returned record holding a set, the set called at a literal, has no interned rep shape

**closed · runs, prints `3` · was loud emit reject, `emitProgram: ref valtype with no interned shape`, clause 2 · fixed 2026-11-08: `collectA` interns a held list of flat records' element row and ref-list slot, as it does a held map's value row · `mk(x: i32)` runs, `3` · found closing [D15549](D15549.md) and [D15548](D15548.md) · filed 2026-11-08 against master `c296e59f`**

Repro:

    function inc0(a) { return a + 1 }
    function mk<T>(x: T) { return { fs: [inc0], x: x } }
    const rs = [mk(1)]
    print(rs[0].fs[0](2))

Want:

    3

#### Mechanism

Calling the set at a literal tags it, and the binding then holds the rep `{fs: i32[], x: i32}[]`
(D15350). Readers of `rs` ask for that rep's ref-list slot (`letRefListSlot`, `arrLitRowTyIn`), and
`collectA` interned the held rep's row for a map but not for a list, so the global's valtype had
slot -1. The list twin interns the element row and the slot (`forceListLeafRepsOfTy`). It is gated
to a flat element: on a nested one (`{o: {fs: ...}}`, `fs: [[inc0]]`) the forced row competes with
the one the instance builds, and `d15296_deep_record` / `d15296_nested_list` became invalid wasm.
The deferred mint the earlier note proposed (`mintPinnedObjLit`) is not needed. The readers
resolve through the held rep's row, so no row is keyed by the checker's holed type.
