### D3114 — a hole's `string | null` value stored into a string list by index assignment or as a nested literal's element recovers non-null

**closed · the checker re-derives the assignment narrowing each time it checks the write, so a hole body checked again at a `string | null` pin no longer keeps the non-null `string` its template check banked; and a string-list literal whose element is a nullable string holds nulls however its own element was recorded · fixture `tests/cases/generics/hole-nullable-string-cell-write.vl` · was loads then traps · clause 1 · the residue of [D3089](D3089.md)'s close: 24 `B_assign`/`B_nested`/`B_nested2`/`B_2d`/`B_2dfor` `snn` cells of the #3274 review's `gen`, `gen2` and `gen3` grids · filed 2026-09-28 against master `f14a8cca2`, closed 2026-09-29 against master `b1794003a`**

Repro:

    function f(x) {
      const l: (string | null)[] = [null]
      l[0] = x
      print(l[0])
    }
    const v0: string | null = null
    f(v0)
    // vl check: rc 0.  vl run: wasm trap: null reference

Want:

    null

#### Mechanism

Two mechanisms, one per spelling. The index assignment: the checker banks the type a written
place reads at afterwards (`asgNarTyIxOf`), and the template check of the hole body wrote a
hole-typed value, which it reads as non-null, so it banked `string` for `l[0]`. The body is
checked again at the pin, where the value is `string | null` and nothing is banked, but the
stale `string` stayed, and the emitter pushed a non-null narrowing for the cell: the read after
the write recovered non-null and trapped. The nested literal: the inner `[x]` records the
template's element, so its string-list build seeded no nullable-string context and stored the
parameter through `ref.as_non_null`. The READ was never the fault in either spelling.

#### Ablation

| ingredient changed | outcome | needed? |
| --- | --- | --- |
| `l.push(x)` then `print(l[1])` | prints `null` | **yes** (the index assignment) |
| `const l = [x]; l[0] = x`, un-annotated | traps, on master and after the close | **yes** (the annotation is needed for the close; the un-annotated spelling is [D3202](D3202.md)) |
| `const l = [[x]]; print(l[0][0])` | traps | no (a nested literal's element is the same store) |
| `const v0: string \| null = "s"` | prints `s` | **yes** (the `null`) |
| an `i32 \| null` pin, `[[x]]` | prints the value | **yes** (the string niche) |
| `function f<T>(x: T)`, `l[0] = x` | prints `null` | **yes** (the hole) |
