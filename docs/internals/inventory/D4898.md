### D4898 — a record holding the complement of `is i32[]` over `v: T[] | i32[]` cannot be read at an `f64` instance

**closed · was a loud emit reject (`emitProgram: index receiver is not an array or string`), identical on master `c2dbf639e` · fixture `tests/cases/generics/complement-list-record-scalar-and-hole.vl` · filed 2026-10-15**

Repro:

    function h<T>(v: T[] | i32[]) {
      if v is i32[] { print(0) } else {
        const r = { xs: v }
        print(r.xs[0])
      }
    }
    h([2.5])
    // vl check: rc 0.  vl run: emitProgram: index receiver is not an array or string

Want:

    2.5

#### Mechanism

At the `f64` instance `r.xs` still types as `T[]` (the pin does not reach the field read),
so `exprListRepOf` falls to the syntactic `memberListRep`, whose `memberFieldListRep` knew
the `i32`, ref, `string` and `f32` list field codes but not `FC_F64_LIST`/`FC_I64_LIST`.
Closed in `emit_classify.vl`: both codes map to `f64list`/`i64list`, and the member-field
gate admits them, so index, `.length` and `for` read the field at its scalar list.
