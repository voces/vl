### D15001 — a `const` whose kept-whole radix tree traps at `i32` traps at load, though every read computes it at `i64`

**closed 2026-11-02 by lane column-G1 · runs, prints `-2147483648` · was loads then traps (`integer overflow`), clause 1 · since D14990 every read of a kept-tree `const` is a copy of its tree, so the declaration's own `i32` value is read by nothing, yet the start function still computed it; the checker now records any read that reaches the binding instead of a copy (`lbiKeptPlain`), and the emitter skips the declaration of a kept-tree `const` no such read reached (`lbiKeptDeclUnread`, at a local and at a module global), as it skips a lambda-lifted `const` · an `i32` read still traps, at the read, as the direct spelling does · fixture `tests/cases/numerics/const-kept-tree-declaration-unread.vl` (module and function scope, a read above the declaration, `%`, an unread `const`) · 4 cells of the D14990 constant grid · found closing [D14990](D14990.md) · filed 2026-11-02 against master `a48eddb4d`**

Repro:

    const P = 0x80000000 / -1
    const w: i64 = P
    print(w)
    // vl check: rc 0.  vl run: wasm trap: integer overflow

Want:

    -2147483648

#### Mechanism

Since D14990 each read of `P` is a copy of its tree and computes at the read's width, so `w`
is `-2147483648`. The declaration itself is still emitted as a module global, computed once at
`i32`, where `0x80000000 / -1` is `INT_MIN / -1` and `i32.div_s` traps. Written at the read,
`const w: i64 = 0x80000000 / -1` prints `-2147483648`.

#### Ablation

| ingredient changed | outcome | needed? |
| --- | --- | --- |
| the tree written at the read, `const w: i64 = 0x80000000 / -1` | prints `-2147483648` | **yes** (the `const` in between) |
| `print(0x80000000 / -1)`, an `i32` read | the same trap | no (the `i32` answer traps, as it should) |
| `0x80000000 / 2` | prints `1073741824` | **yes** (a tree that traps at `i32`) |

#### Grading list

The `0xFFFFFFFF` divisor twin and the `0x7FFFFFFF + 1` dividend, and `%` by `-1`.
