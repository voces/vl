### D16844 — a copy of a closure-written type-parameter binding stored into a record costs hundreds of billions of guest fuel to compile

**closed 2026-11-16 · runs, and the repro builds at 19.7M guest fuel (was 175.6G); the whole fixture at 26.1M (was 420G, 130 s) · cost cliff (compile, not output) · fixed by applying the slot walks' cycle rule (`elabSeenDeep`: a node reached again at a path that only lengthens one it was reached at delivers nothing new) at every path length, not only from 8 steps · byte-identical over 8,408 corpus modules · residue: the cost still grows with the record's fields, D16724 · filed 2026-11-16 against master `30a6da134`**

Repro:

    function viaCopy<H>(a: H, c: H) {
      let b = a
      const w = () => {
        return b = c
      }
      w()
      const v = b
      const r = { f: v, g: a }
      print(r.f)
      print(r.g)
    }
    viaCopy(3, 4)
    viaCopy(1.5, 2.5)
    // VL_FUEL=1 vl build: 175,623,219,065 guest fuel, 51 s, on master's fixpoint seed.

Want:

    4
    3
    2.5
    1.5

#### Mechanism

The elaboration slot query (`elabSlotDeliveriesAt` → `elabSlotReadDeliveries` ↔
`elabSlotClimb`, compiler/emit_elab.vl), asked by `monoDeclPathKeys` for the instance. The
capture rewrite's write cell hands the binding's slot back with an `e` step added, so the walk
comes round to the same binding at `/e/`, `/e/e/`, … Below 8 steps the walks keyed `seen` by
(node, path length), so each lengthening was a new state; only from 8 steps did `elabSeenDeep`'s
cycle rule apply. Each state launched nested queries with a fresh `seen`, so the repro reached 47
distinct (binding, path) states millions of times and made 2.9M queries over 373 distinct keys.
Applying the rule at every length cuts the pumping at its first turn. `elabSeenDeep`'s entries
now sit in their own band (`ELAB_SEEN_BAND`), so a short key never reads as a node index or
path id beside it.
