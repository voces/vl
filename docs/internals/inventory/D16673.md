### D16673 — a constant integer division by zero is accepted, and traps at run time, when the tree holds a radix literal

**closed 2026-11-15 · now a loud check reject, `division by zero in a constant expression`, the refusal D2.3 owes · was loads then traps where D2.3 refuses, clause 1, `vl check` rc 0 · closed by testing an integer zero divisor before the radix-pattern bail in `cexDiv` and `cexRem` (const_exact.vl) · fixture `tests/cases/numerics/error-const-zero-divisor-radix.vl` · D2.3 and DECISIONS ("Division or remainder by an integer zero has no value and is a check error") make no exception for a radix literal · the decimal spelling `7 % 0` is refused with `division by zero in a constant expression` · found by the independent oracle's arithmetic generator (fuzz cells `ar_s37_0026`, `ar_s82_0153`); first seen grading E6.2 and D2.3 in #8441 · filed 2026-11-15 against master `f195dacbc`**

Repro:

    print(0xFF % 0)
    // master: vl check rc 0; vl run traps: integer divide by zero

Want:

    error: division by zero in a constant expression

#### Mechanism

`cexDiv` and `cexRem` (const_exact.vl) returned not-a-constant on any operand carrying a radix
pattern (`cxPat`, ruling A: its value depends on the use's width) before they tested the divisor
for zero. The tree was left to run-time code, and the division trapped. An integer zero is zero at
every width, so the zero test now runs first and the pattern bail only after it. A non-zero radix
divisor or dividend is still settled at the use's width, a run-time zero still traps, and a float
`/ 0.0` is still IEEE.

#### Ablation

| spelling | master | want |
| --- | --- | --- |
| `7 % 0`, `7 % (~(-1))` | refused | same |
| `0xFF % 0`, `0xFF / (1 - 1)`, `(0xFF + 0) / 0` | rc 0, traps | refused |
| `7 / (0xFF & 0)`, `7 / (0x100 - 0x100)` (radix divisor) | rc 0, traps | refused |
| `0xFF % (~(-1))` | rc 0, traps | refused |

#### Grading list

- Every rc-0 row of the ablation table is refused with the decimal spelling's words: done, the
  fixture holds four of them, and `0xFF / (1 - 1)` and `0xFF % (~(-1))` are refused too.
- Unchanged controls: `0xFF / 3` prints `85`; `let z = 0; 0xFF / z` traps at run time; a float
  `/ 0.0` prints `Infinity`.
