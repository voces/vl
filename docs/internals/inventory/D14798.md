### D14798 — a closure whose only value is a `null` it writes into a captured nullable cell returns that cell's null, not the `null` unit's

**closed 2026-11-01 by `emitRetNulNoneValue` lowering a `null` literal or `null`-yielding write as `ref.null none` in a function whose result holds only `null` · the witness prints `other` · was a trap (`unreachable`), check-clean, on master `11b437ffa` · fixture `tests/cases/closures/null-result-closure-writes-cell.vl` · found by step 4's flip re-grading `capture-nullable-closure-null-write.vl` · filed 2026-11-01 against master `11b437ffa`**

Repro:

    function strNull() {
      let v: string | null = "s"
      const k = (): null => {
        v = null
      }
      k()
      if v is string { v } else { "other" }
    }
    print(strNull())

Want:

    other

#### Mechanism

The closure's result is the `null` unit type, which lowers as `nullref`. Its tail write yields
the right side's `null`, which the checker typed at the place's type, so the lowering built the
place's null (`ref.null $string`), a value `nullref` cannot hold. The result's null is the bottom
`ref.null none`, whatever place the write targets.
