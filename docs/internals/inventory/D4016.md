### D4016 — a binding of the same name written in another scope makes the instance guard refuse a call through a binding that is never written

**closed 2026-10-13 by lane SC (fn-value-flow §(f) step 2, identity not name) · runs, prints `I`, `true`, `O`, `1` · write detection is keyed on the binding a write resolves to (`monoDeclIsAssigned`), so a write to another scope's binding of the name no longer counts · was loud emit reject · pin: `tests/cases/closures/same-name-written-elsewhere-guard.vl` · clause 2 · found in review of #3517 (`rv3517/b03b_sibling_fns_same_name`, `b01`, `b03`, `b05`) · filed 2026-10-11 against master `20fa382fe` with #3517 applied**

Repro:

    function inner<U>(u: U) { print("I"); print(u) }
    function other<V>(v: V) { print("O"); print(v) }
    function a() {
      let f = other
      f = inner
      f(true)
    }
    function b() {
      let f = other
      f(1)
    }
    a()
    b()
    // vl check: rc 0.  vl run: emit error, the reassigned function binding `f` is called at more than one argument type

Want:

    I
    true
    O
    1

#### Mechanism

The refusal is the D3858 instance guard in `monoMakeInstanceGo`, which refuses a second instance
called through a binding it believes is written. `b`'s `f` is never written, but `a`'s `f` of the
same name is. #3517 moved several sites to binding-keyed write detection (`monoLetWrittenAt`);
the review attributes the remainder to the sites still keyed by name (`monoNameIsAssigned`, and
the name-keyed fallback in `monoNameWrittenAt` when a read's frame does not resolve). Which
of those fires here is not yet probed.
