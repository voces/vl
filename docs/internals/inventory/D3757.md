### D3757 — an un-annotated map-read `const` captured by a lambda and narrowed inside it emits invalid wasm

**check-clean invalid wasm · open · found by review of lane SP · filed 2026-10-06 against master `b05991d98`**

Repro:

    const m: Map<i32, i32> = Map()
    m[3] = 7
    function cl(x: i32): i32 {
      const g = m.get(x)
      const f = () => if g == null { -5 } else { g }
      f()
    }
    print(cl(3))
    // vl check: rc 0.  vl run: the emitted module failed to validate inside `cl`: type
    // mismatch: current function requires result type [i32] but callee returns
    // [(ref (id 0))]  (exit 70)

Want:

    7

#### Mechanism

Not yet located. The lambda's own result is `(ref $box)` where `cl` expects `i32`: the narrowed
read of the captured `g` inside the lambda yields the box rather than its unboxed arm, or the
lambda's signature is minted from the un-narrowed type. The binding's annotation decides it,
so the rep of an inferred `m.get(x)` binding and the capture's rep disagree. Lane SP's
`nulScalarSplit` declines a captured binding and does not change this program.
