### D3757 — an un-annotated map-read `const` captured by a lambda and narrowed inside it emits invalid wasm

**closed 2026-10-06 by lane S3 — the filed repro RUNS and prints `7` · was check-clean invalid wasm, clause 1 · found by review of lane SP · filed 2026-10-06 against master `b05991d98` · fixture `tests/cases/closures/captured-map-read-narrowed-in-lambda.vl`**

Repro:

    const m: Map<i32, i32> = Map()
    m[3] = 7
    function cl(x: i32): i32 {
      const g = m.get(x)
      const f = () => if g == null { -5 } else { g }
      f()
    }
    print(cl(3))
    // vl check: rc 0.  vl run: the emitted module failed to validate inside `cl`: type
    // mismatch: current function requires result type [i32] but callee returns
    // [(ref (id 0))]  (exit 70)

Want:

    7

#### Mechanism

The emitter's return classifier (`criClassify`) types an un-annotated lambda's result from its
returned expressions, under the narrowing `criWalkStmt` replays. A captured value-union box
narrows inside the lambda only when `capturedUnionName` names its member set, which it reads off
the parent binding through `letUnionNameOf`. That reader names a scalar-valued map read
(`m.get(k)`, `m[k]`, whose `V | null` is the box) nowhere: its map arm answers only a
union-valued map. So `g == null` pushed no narrowing, the else arm's bare `g` classified as the
box, and the lambda's wasm result became `(ref $box)` while its body, which narrows through
another channel, returned the unboxed `i32`. Not `nulScalarSplit` (#3400), which declines a
captured binding and predates nothing here. The close: `capturedUnionName` falls back to the
init's checker type (`nodeUnionName`) when it is a value union, which is exactly the box the env
field holds (`capturedKindOf == "union"` gates the function).
