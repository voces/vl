### D16238 — a hole lambda pushed onto a list a hole parameter holds gets no parameter type from the list's calls

**loud check reject · `cannot infer a type for parameter n` · clause 2 · open · the `argument` cell, un-annotated face, of `ffc-hole-record-fn-field-list-pushed.matrix.vl` · filed 2026-11-15 against master `55151b054`**

Repro:

    function inc(n) { return n + 1 }
    function take(a) {
      a.push((n) => n * 2)
      let c = 0
      for g in a { c = c + g(1) }
      print(c)
    }
    take([inc])
    // vl check: cannot infer a type for parameter `n`

Want:

    4

#### Mechanism

The lambda's parameter would take its type from the calls through the list it is pushed onto,
`g(1)`. That list is a hole parameter, so its element type is open when the push is checked,
and the lambda is checked as if it reached no call. The same push onto a local list, or onto an
annotated parameter, takes `i32` from the walk.
