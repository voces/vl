### D6400 — a string map key holding a comma splits a write summary's part, so a narrowing of that key survives the write

**now a loud check reject, `'m["a,b"]' is no longer narrowed to i32: the call to 'clr' on line 7 may reassign it` — fixed 2026-10-18 by lane L5: write summaries are a set of interned parts rather than one comma-joined string · was check-clean invalid wasm, `vl run`: wasm trap: cast failure, clause 1 · pin: `tests/cases/maps/error-subscript-narrow-comma-key-write.vl` (the witness, a free-variable write and an alias write) · filed 2026-10-18 against master `4cfd7b6b6`**

Repro:

    function clr(m: {[string]: i32 | null}) {
      m["a,b"] = null
    }
    const m: {[string]: i32 | null} = Map()
    m["a,b"] = 1
    if m["a,b"] != null {
      clr(m)
      print(m["a,b"] + 1)
    }
    // vl check: rc 0.  vl run: wasm trap: cast failure

#### Mechanism

The callee's write summary was a comma-joined string of shapes, so the shape `["a,b"]` split
into `["a` and `b"]` and neither matched the caller's narrowed key. The same split hid an
alias write (`const q = m; q["a,b"] = null`) from `retireAliasedNarrowings`, which skipped
any target shape that did not come back whole.
