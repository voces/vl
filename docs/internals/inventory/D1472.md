### D1472 — inside a GENERIC body `__array_new_default__` reads an un-substituted `T[]`, so every instance but the i32 one builds the wrong backing

**check-clean invalid wasm · PRE-EXISTING and unmoved by D1470 (graded verbatim on both seeds)
· filed 2026-09-03 against master `24f119e4` · the residue ROADMAP B12's `map`-in-std item
names, now with a mechanism instead of "the element kind is not derivable"**

Repro (`vl check` rc 0; `vl run`: `Invalid input WebAssembly code … type mismatch: expected
(ref $type), found (ref $type)`. `mk(3, 1)` on the same source prints `0`):

    function mk<T>(n: i32, seed: T): T[] {
      const xs: T[] = __array_new_default__(n)
      return xs
    }
    const a = mk(3, 1.5)
    print(a[0])

#### Mechanism

`arrNewDefaultKind` reads the element the checker pinned onto the CALL node, which is the whole
of D1470 — and a monomorphized instance body is EMITTER-SYNTHESIZED, so its nodes read
`nodeTyIxOf == -1` (`exprF64Array`'s own header states this) and the un-cloned definition node
still carries the un-substituted `T[]`. Neither answers `f64`, so the kind falls to `0` and the
i32 backing is built under a destination the rest of the instance reads as the f64 list.

**`__array_new__` in the identical shape RUNS**, and that contrast IS the mechanism: it reads
its FILL argument, whose type is concrete in every instance, so it never needed the destination.
The i32 instantiation runs for the same reason a broken clock is right — `0` is what the
fall-through builds.

#### Ablation

| ingredient removed | outcome | needed? |
| --- | --- | --- |
| the generic (`function mk(n: i32): f64[]`) | runs, prints `0` | **yes** |
| the non-i32 instance (`mk(3, 1)`) | runs, prints `0` | **yes** |
| `__array_new_default__` (`__array_new__(n, seed)`) | runs, prints `1.5` | **yes** |
| the `T[]` annotation on `xs` (return it directly) | still invalid wasm | no |
| `f64` for `string` (`mk(3, "x")`) | still invalid wasm | no — it is every non-i32 instance |

#### Grading list

* `mk(3, 1)` — the i32 instance must keep RUNNING; it is the one the fall-through happens to get
  right, so a fix that re-derives the kind must not lose it.
* `__array_new__` in the same generic shape at `f64`, `string` and a struct fill — the sibling
  that already works, and the thing a fix must not disturb.
* `scripts/mono-tyaram-grid.sh`, since the answer has to come from the instance rather than the
  definition.
