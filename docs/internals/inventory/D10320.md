### D10320 — a list of a two-parameter generic called with a runtime `i32` at its `f64` parameter through an un-annotated parameter, beside one handed to an annotated parameter, traps

**closed · runs, prints `4`, `8` · was trap after load, `vl check` rc 0, `wasm trap: indirect call type mismatch` in `run2`, clause 1 · found closing [D10203](D10203.md) · present on master `d5ec7f160` · filed 2026-10-22 against master `d5ec7f160` · closed with [D10203](D10203.md): a call through an un-annotated parameter pins the list slot at each parameter the element type closes, so `run2`'s call delivers `n` at `f64` like the list's own instance (`monoPinsAtElemParams`, emit_mono.vl) · fixture `closures/generic-two-param-list-called-through-unannotated-parameter.vl`**

Repro:

    function k<T>(x: f64, y: T): f64 { x }
    function h(x: f64, y: i32): f64 { x + 1.0 }
    const ys = [k]
    ys.push(h)
    function run(a: ((x: f64, y: i32) => f64)[]) {
      const z = 3
      print(a[1](z, 2))
    }
    run(ys)
    function g(n: i32) {
      const ws = [k]
      ws.push(h)
      function run2(a) { print(a[1](n, 2)) }
      run2(ws)
    }
    g(7)
    // vl check rc 0.  vl run: prints 4, then wasm trap: indirect call type mismatch in `run2`

Want:

    4
    8

#### Mechanism

The call `a[1](n, 2)` through the un-annotated `a` pins `ws`'s slot at the argument's own
types, `(i32, i32)`, while the element type is `(f64, i32) => f64`. Next to `ys`'s annotated
delivery, `run2` was built calling the slot at `(i32, i32)` and handed `h`'s `(f64, i32)`
function, a mismatched indirect call. The direct spelling `h(n, 2)` widens `n` and prints `8`.
