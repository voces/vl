### D16181 — a generic with a fixed parameter named at a closed function type whose parameter is narrower is refused, though the same function delivered through a written `let` runs

**loud check reject · `argument 1: expected (i32, boolean) => void, got (i32 | string, B) => void` · clause 2 · the delivery needs `B` bound and an adapter at the fixed parameter, which the `let` path builds · filed 2026-11-14 against master `43943a5bf` · bucket (g), not a clause-2 fix until ruled: a parameter widened to a union is admitted only where the destination's parameter is a record, and DECISIONS rules only the result direction (re-ablated 2026-11-15)**

Repro:

    function w<B>(a: i32 | string, b: B) {
      print(a)
      print(b)
    }
    function run(f: (a: i32, b: boolean) => void) { f(9, false) }
    run(w)
    // vl check: argument 1: expected (i32, boolean) => void, got (i32 | string, B) => void

Want:

    9
    false

#### Mechanism

A generic named at a closed function type is instantiated by binding its type parameters
against the destination's parameters. A parameter the generic fixes (`i32 | string`) and the
destination narrows (`i32`) is not adapted on that path, and `assignable` refuses the open
`B` against `boolean`. Through `let k = s; k = w; run(k)` the write is adapted at the call's
types (`fsbAdaptWrites`), so it runs. D15956's close keeps a binding with such a member on that
path (`fnParamsAllTyParams`, check_narrow_flow) for this reason.

#### Ablation

| ingredient changed | outcome | needed? |
| --- | --- | --- |
| `a: B2` with a second type parameter | runs | **yes** |
| delivered through a written `let` | runs | **yes** |

Re-ablated 2026-11-15: the generic is not the ingredient, and the written `let` no longer runs.

| spelling | outcome |
| --- | --- |
| `function w(a: i32 \| string)` passed as `(a: i32) => void` | check reject |
| `string \| i32` as `string`, `string \| null` as `string`, `boolean \| string` as `boolean` | check reject |
| a lambda `(a: i32 \| string) => …` written at the `(a: i32) => void` slot | check reject |
| `R \| i32` as `R`, a record destination | runs |
| `let k = s; k = w; run(k)`, the row's `let` ablation | loud emit reject (`a generic function taken as a value reaches no call that fixes its type`) |

So the refusal is the parameter rule `fnSlotAssignable` applies (`check_relate_core.vl`): an
adapter widens a parameter into a union only for a record destination ("a union parameter read
as a record one", DECISIONS, "A function value at another function type is adapted where it is
delivered"). The result direction is ruled admitted (D15896, D9781), but the parameter direction
is ruled only for numbers ("a parameter widened the same way stays refused"). Whether a
parameter widened into a value union, or into `T | null`, is adapted is the owner's question.
