### D2617 — a hex literal delivered as a tail of a value `if`, `match` or block is read at 32 bits, whatever the destination's width

**closed 2026-09-26 — the witness prints `4294967294` then `4294967295` · was check-clean
silently wrong, clause 1 · Reported by plumb (PL-041) · filed against master `e289f84d7` ·
fixture `tests/cases/literals/hex-width-through-value-if.vl`**

Repro:

    let rax: i64 = 0
    function f(level: i64) {
      rax = if level != 0 { 0xfffffffe } else { 0xffffffff }
    }
    f(1)
    print(rax)
    f(0)
    print(rax)
    // PRINTS 4294967294
    // vl check: rc 0.  On master it printed -2 then -1.

#### Mechanism

A hex literal is a bit pattern of its destination's width, and `radixLitAdoptDst` pins it at the
`assignableExpr` seam, where every position delivers its value. It peeled only parentheses, so a
literal that was a TAIL of a value `if`, `match` or block kept the 32-bit reading its eight
digits imply, the join typed `i32`, and the emitter sign-extended it into the i64 slot. A typed
tail return worked only because that position delivers each arm separately. The close walks the
tails (`valueTailSplit`, the walk the tail-return check already uses), pins each radix tail, and
re-types every `if` and `match` on the way down to `i64` so the emitter builds the join at that
width. An object or array literal's fields and elements take the same walk, because a widening
record or list is `assignable` and short-circuits the field-wise recursion. At an `f64`
destination the join is re-typed `f64`, so a radix tail reads as the value a bare one does
there. A `match` desugared before the delivery leaves its later links untyped; they take the
head's type.

#### Ablation

On master `e289f84d7`.

| ingredient changed | outcome | needed? |
| --- | --- | --- |
| the `if` → a bare `0xfffffffe` | `4294967294` | **yes** (a tail, not the value itself) |
| `0xfffffffe` → decimal `4294967294` | `4294967294` | **yes** (a radix literal with bit 31 set) |
| the assignment → `let x: i64 = if …` | still `-2` | no (plumb's "a fresh `let` works" was the bare-literal spelling) |
| global → local, field, list cell, map cell, `+=`, argument, `return if …`, struct/array literal part, closure write | still `-2` | no |
| `if` → a two- or three-arm `match`, an `else if` chain, an arm with a statement prelude | still `-2` | no |
| a typed tail return `function g(c: boolean): i64 { if c { 0xfffffffe } else { 1 } }` | `4294967294` | the one position that already delivered per arm |
| the destination → `f64` | `-2` where a bare literal gives `4294967294` | no |

#### Grading list

Every row of the ablation table beyond the first two now prints the 64-bit value (the fixture
carries one line per position and shape). An `i32` destination keeps the 32-bit pattern (`-2`),
and a pattern too wide for an `i32` destination now reports at the literal
(`0x1_0000_0000 does not fit a 32-bit destination`) instead of `cannot assign i64 to i32`. A
generic hole bound by the argument (`const x: i64 = id(if c { 0xfffffffe } else { 1 })`) still
reads `-2`, the same as `id(0xfffffffe)`: the literal's destination is `T`, bound to `i32`.
