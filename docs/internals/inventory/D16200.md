### D16200 — a `for` loop variable over a map of maps reads its inner map's un-annotated functions at an open parameter type

**closed 2026-11-14 — the witness runs and prints `2.5` · was: loud emit reject · `` emitProgram: a function-value call has no interned signature — parameter 1 of type `_` has no representation in the function-value ABI `` · clause 2 · the same read through `mm.get("k")` runs (D16121's witness) · split from D16121's grading list · filed 2026-11-14 against master `6d7f0957`**

Repro:

    function half(a) { return a / 2.0 }
    const m4 = Map()
    m4.set("a", half)
    const mm = Map()
    mm.set("k", m4)
    for k, inner in mm {
      const g = inner.get("a")
      if g != null { print(g(5.0)) }
    }
    // vl check: rc 0.  vl run: the refusal above, at the `for`

Want:

    2.5

#### Mechanism

A loop variable is no binding `monoReadLetFrame` resolves. `monoRetypeMapReads` typed the loop
variable's own reads at the inner map's type, but not the reads of that map's values through it,
which a `const` bound to `mm.get("k")` gets by recursion. So `inner.get("a")` kept its open type.
Closed by recursing for the loop variable too (`monoRetypeMapReads` naming it by its loop, and `monoReadIsBinding` matching a
loop variable by its declaration).
