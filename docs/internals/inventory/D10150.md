### D10150 — a written list of a generic handed to a generic function and called at that function's type parameter passes check and traps

**trap after load · `vl check` rc 0 · `wasm trap: indirect call type mismatch` · clause 1 · DESIGN: `run<U>` called with `U = string` calls `inc` at `string`, which the annotated twin `run(a: ((x: string) => string)[])` refuses · found closing [D10120](D10120.md) · present on master `17b0be5a8` · filed 2026-10-22 against master `17b0be5a8`**

Repro:

    function id<T>(x: T): T { x }
    function inc(x: i32): i32 { x + 1 }
    const ys = [id]
    ys.push(inc)
    function run<U>(a: ((x: U) => U)[], u: U): U { a[1](u) }
    print(run(ys, "s"))
    // vl check rc 0.  vl run: wasm trap: indirect call type mismatch, in `run`

The owed outcome is a check refusal.

#### Mechanism

[D10080](D10080.md)'s delivery judge reads the push row at the type the delivery fixes, and
this delivery fixes none it can read: the argument binds `U` to `T`, `id`'s own type
variable, so the delivered element type still carries a type variable and the judge skips
it. The slot judge of [D10120](D10120.md) runs only for an un-annotated parameter.

#### Ablation

| ingredient removed | outcome | needed? |
| --- | --- | --- |
| `ys.push(id)` instead of `ys.push(inc)` | runs, `s` | **yes** |
| `run(ys, 2)` instead of `run(ys, "s")` | runs, `3` | **yes** |
| `run` not generic, `a: ((x: string) => string)[]` | check refuses ([D10080](D10080.md)) | **yes** |
