### D3005 — an `f32` field re-seated at a wider declared `f64` record is read back at its own `f32` type unconverted

**check-clean invalid wasm · identical on master `b34730ad9` and on #3253 · found by the #3253 review grid · filed 2026-09-28**

Repro:

    type D = { v: f64 }
    const x: f32 = 1.5
    const c: {[string]: D} = Map()
    const o = { v: x }
    c["k"] = o
    const z: f32 = o.v
    print(z)
    // vl check: rc 0.  vl run: invalid module — type mismatch

Want:

    1.5

#### Mechanism

The map store builds `o` at `D`, so `o.v` loads an `f64` where the checker's `f32` is expected. #3253's `memReadNarrowOp` narrows only to `i32` (`i32.wrap_i64`, `i32.trunc_f64_s`); an `f32` read needs `f32.demote_f64`, which is exact for a value that came from an `f32`.
