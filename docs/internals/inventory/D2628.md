### D2628 — a boolean binding is accepted where an `i32` is expected, and passes as `0`/`1`

**check-clean silently wrong · clause 1 · open · filed 2026-09-26 against master `06930fb68`,
found by the review of #3184 (the same on both seeds)**

Repro:

    function usei32(v: i32) { print(v) }
    const b = true
    usei32(b)
    // PRINTS 1
    // vl check: rc 0.  A boolean is not an `i32`; the literal spelling `usei32(true)` is refused.

#### Mechanism

A prediction. The literal `true` is refused as `expected i32, got boolean`, but a binding
initialised from it is accepted, so the binding's type is not the `boolean` primitive the literal
check compares against (a literal-typed or inferred boolean that `assignable` lets through to
`i32`), and the emitter passes the `i32` rep of the boolean. The narrowed-write grid of #3184 found
it through `x: i32 | boolean`, `if x is i32 { x = true; usei32(x) }`, which prints `1` the same
way: the write re-narrows to the member the value lands on, and a boolean lands on `i32`.

#### Ablation

| ingredient changed | outcome | needed? |
| --- | --- | --- |
| `usei32(true)`, the literal | loud check reject | **yes** (a binding) |
| `x: i32 \| boolean` narrowed `is i32`, then `x = true` | prints `1` the same way | no |
| `x: i32 \| boolean`, `x = true`, no narrowing | loud check reject (the union) | no |
