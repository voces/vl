### D2227 — a `null`-then-list `if` join into an annotated nullable-list local builds invalid wasm, with no empty literal anywhere

**check-clean invalid wasm 2026-09-23 — `type mismatch: expected i32, found (ref null $type)` in the module's top-level code · clause 1 · found during PR #3069's review, predicted in [D2209](D2209.md)'s grading list ("a `null` then arm over a non-empty list arm into an annotated `string[] | null`") · filed against master `07d5e3b66`**

Repro:

    function t() { 1 == 1 }
    const x: string[] | null = if t() { null } else { ["a"] }
    if x != null { print(x.length) } else { print(0) }
    // vl check: rc 0 (one hint: the annotation on `x` is redundant).
    // vl run: Error: invalid module — "the emitted module failed to validate inside the
    // module's top-level code: type mismatch: expected i32, found (ref null $type)"

#### Mechanism

Neither arm is an empty `[]` literal, so D2209's fix — which pins an empty arm's element
from its non-empty sibling — has nothing to pin here. The `if`'s blocktype is still read
off the THEN arm alone, and when the THEN arm is a bare `null` that reads as `i32` (the
scalar-niche default), while the ELSE arm yields a list ref — the two arms disagree at
the `if`'s own join point. Swapping the arms (list arm first, `null` second) runs
correctly, so the defect is ORDER-dependent, not join-membership-dependent. Removing the
annotation on `x` still fails, but through a different, already-filed mechanism
([D2226](D2226.md)'s un-annotated-argument refusal), so this row keeps the annotated
spelling as its own witness.
