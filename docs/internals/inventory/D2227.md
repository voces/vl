#### Mechanism

Neither arm is an empty `[]` literal, so D2209's fix — which pins an empty arm's element
from its non-empty sibling — has nothing to pin here. The `if`'s blocktype is still read
off the THEN arm alone, and when the THEN arm is a bare `null` that reads as `i32` (the
scalar-niche default), while the ELSE arm yields a list ref — the two arms disagree at
the `if`'s own join point. Swapping the arms (list arm first, `null` second) runs
correctly, so the defect is ORDER-dependent, not join-membership-dependent. Removing the
annotation on `x` still fails, but through a different, already-filed mechanism
([D2226](D2226.md)'s un-annotated-argument refusal), so this row keeps the annotated
spelling as its own witness.

#### Fix

The join's rep is read off its first arm that is not a bare `null` (`ifThenValueIx`, following an
`else if` chain), so every classifier that asked the then arm now asks that arm; the nullable
twin (`nulArmIfThenValueIx`) finds the `null` in any arm of a chain. A ref-typed chain's
blocktype is nullable from the first link that can yield `null` inward (`ifLinkYieldsNull`), an
i32-niche join seeds a `null` then arm the way it already seeded a `null` else arm
(`emitNicheArmValueAs`), and a join whose every arm is a bare `null` runs its conditions as a
void `if` chain and yields the one `null` its destination seeds (`emitAllNullIf`), with the
un-annotated binding's cell classified `nulnone` (`exprIsNulNone`). Every site that consumes a
`null`-typed value without keeping it (`??`, a folded `== null`, `print`, a union box payload)
runs such an `if` for its effects (`emitIfForEffect`), so its conditions and arm calls still run
once; an arm whose value is itself an all-`null` `if` counts as a `null` arm (`exprIsNullLike`).
Fixture `tests/cases/conditionals/if-join-all-null-effects.vl`.
