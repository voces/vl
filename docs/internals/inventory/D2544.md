### D2544 — an un-annotated function's implicit return is a tail write to a map entry or array index; the return-kind ladder only names a plain-identifier assignment target

**check-clean invalid wasm · clause 1 · found by review, the map-write twin of #3167's assignment-cell family (D2515/D2516) which this shape was not part of · filed 2026-09-25 against master `a09d1f6bc`**

Repro:

    function mkM(): {[i32]: i32} {
      const mm: {[i32]: i32} = Map()
      mm
    }
    let k = 1
    const m: {[i32]: {[i32]: i32}} = Map()
    function f() {
      m[k] = mkM()
    }
    export function main() {
      const r = f()
    }
    main()
    // vl check: rc 0.  vl run: invalid module inside `main`, type mismatch: expected
    // (ref $type) but nothing on stack

#### Mechanism

`f` has no return annotation, so its result is inferred from its tail statement — here the
assignment `m[k] = mkM()`. The checker's own inference (any assignment's type is its RHS's
type) correctly types `f` as returning `{[i32]: i32}`. But the emitter's matching rung,
`fnAssignRetTargetName` (`emit_classify.vl`), only recognizes the assignment target when it is a
plain `Ident` (`t is Ident { return t.identName }` — the doc comment says so: "`fe`'s body's
last statement is `<name> = <rhs>`"); a map-entry or array-index target is not an `Ident`, so it
falls through to `""`, and `fnAssignRetKind`/`fnAssignRetSlot` answer `null`/`-1`. The function's
wasm signature still carries the checker's ref-typed answer, but the body compiles the tail
assignment as a plain statement and pushes nothing for it — hence "expected (ref $type) but
nothing on stack" at the caller that binds the result.

#### Ablation

| ingredient removed | outcome | needed? |
| --- | --- | --- |
| binding the call's result (`f()` as a bare statement, not `const r = f()`) | runs | **yes** |
| the return annotation (`function f(): {[i32]: i32} { m[k] = mkM() }`) | runs | **yes** |
| the computed key (`m[1] = mkM()` instead of `m[k]`) | same invalid module | no |
| a map-entry target replaced by an array-index target (`arr[k] = mkM()` on `{[i32]: i32}[]`) | same invalid module | no — generalizes to any non-identifier assignment target |

#### Grading list

Any assignable target the parser does not represent as a bare `Ident` — a field write
(`obj.field = e`) as the sole tail statement of an un-annotated function is the untested
sibling shape; `fnAssignRetTargetName`'s `Ident`-only match is the same hole for it.
