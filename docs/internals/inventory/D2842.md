### D2842 — a list literal of only `null` under a one-literal nullable element annotation refuses

**loud emit reject · clause 2 · identical on master `7323baf55` · found by the #3220 review · filed 2026-09-27**

Repro:

    const xs: ("x" | null)[] = [null]
    print(xs.length)
    // vl check: rc 0.  vl run: emitProgram: bare null needs a struct-typed context

#### Mechanism

Not ablated to a rung. The element is `"x" | null`, which D2827 made the `string | null`
niche. A `null` element takes its rep from the element context, and the context this literal
hands down does not name the nullable string. `(string | null)[] = [null]` and
`("x" | "y" | null)[] = [null]` both run, and so does `("x" | null)[] = ["x", null]`.

#### Ablation

| ingredient removed | outcome | needed? |
| --- | --- | --- |
| the one-literal element (`string \| null`) | runs | **yes** |
| the one-literal element (`"x" \| "y" \| null`) | runs | **yes** |
| every element being `null` (`["x", null]`) | runs | **yes** |
