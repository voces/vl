### D16606 — a `??` over an `f32 | null` whose integer default the `f32` cannot hold builds an invalid module when delivered straight into `f64`

**check-clean invalid wasm · clause 1 (`vl check` rc 0) · `the emitted module failed to validate inside the module's top-level code` · ruling 4.3 (the default keeps its type and the join is `f32 | i32`, which converts to `f64`) · found by lane T writing the D16605 capability template · filed 2026-11-15 against master `059a5a687`**

Repro:

    function noneF(): f32 | null { return null }
    const v: f64 = noneF() ?? 16777217
    print(v)
    // vl check: rc 0.  vl run: invalid module, inside the module's top-level code

Want:

    16777217

#### Mechanism

Not localised past the ablation. The `??` joins its `f32` side with an integer default the
`f32` cannot hold to `f32 | i32` (4.3). That join delivered straight into an `f64` destination
builds a value the destination's slot does not accept. Bound first to a name and then
delivered, or annotated `f32 | i32`, it runs; so does the `if` join of the same two values.
