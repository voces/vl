### D2625 — a string accumulated into a field, or by prepending, copies the whole string on every append

**runs today and must keep running · the witness runs under `vl run`; the defect is its cost (quadratic: 154,914 appends take 10.9 s where the local-variable spelling takes 0.05 s), which the grader does not measure · found answering plumb's segmented-`elem` comment in `tools/translate-all.vl` · filed 2026-09-26 against master `e289f84d7`**

Repro:

    import { toString } from "std:fmt"
    type B = { s: string }
    function build(nt: i32): string {
      const o: B = { s: "" }
      for k in 0 until nt { o.s = o.s + " $t" + toString(k) }
      o.s
    }
    print(build(154914).length)
    // prints 1283116, in 10.9 s; `let el = ""` + `el = el + …` builds the same string in 0.05 s

#### Mechanism

The in-place append that #2920 built (`strAccScan`, ROADMAP row 26) recognises one shape only: a
plain variable, local or module global, assigned `x = x + …`. Any other accumulator falls back to
a fresh concatenation that copies the whole left operand on every step. Two such shapes are
measured here: a record field (`o.s = o.s + …`) and a prepend (`el = … + el`), each about 10 s for
154,914 appends against 0.05 s for the recognised spelling. A list cell or map value accumulator
is expected to behave like the field (not measured).

#### Ablation

| ingredient removed | outcome | needed? |
| --- | --- | --- |
| the field (a plain `let el` accumulator) | 0.05 s, linear | **yes** |
| the append order (`el = … + el`, prepend) | 9.4 s, quadratic | no — a second shape of the same gap |
| `toString(k)` (constant appended text) | not measured | — |

#### Grading list

The prepend spelling (`let el = ""`, `el = " $t" + toString(k) + el`); a list-cell and a
map-value accumulator; plumb's `tools/translate-all.vl` `elem` segmenting, which predates the
in-place append and could now be one line built whole (reported to plumb 2026-09-26).
