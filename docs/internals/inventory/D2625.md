### D2625 — a string accumulated into a field, or by prepending, copies the whole string on every append

**closed 2026-09-26 — the witness prints `1283116` in 0.044 s against 12.3 s on master · runs today and must keep running · the defect was its cost, which the grader does not measure; `tests/vl_scaling_shape_test.ts` "place string append loop" is the gate (18.2 on master, bar 2.5) · filed 2026-09-26 against master `e289f84d7`**

#### Mechanism

The in-place append from #2920 (`strAccScan`) recognised one shape: a plain variable, local
or module global, assigned `x = x + …` and proven by a static aliasing argument. Any other
accumulator copied its whole prefix per append. Closed by the SITE-CACHED append
(`strSiteArm` / `emitStrSiteCat`, compiler/wasmEmit.vl): every `p = p + parts` or
`p = parts + p` inside a loop, whatever place `p` is (field, nested field, list cell, map value
spelled `(m[k] ?? "") + …`, global, parameter, prepended local), owns two function locals —
`SB`, the buffer that site allocated last, and `SE`, its frontier. The value is extended in
place only when it is a view into `SB` whose edge is `SE`; anything else, an alias included,
copies into a fresh buffer with slack. Soundness is that runtime test, so it needs no
aliasing proof (DECISIONS.md "String building is a lowering"). Two shapes stay quadratic and
are filed: an append site outside any loop, reached from a caller's loop ([D2669](D2669.md)),
and one site cycling over several strings ([D2670](D2670.md)).
