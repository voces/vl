### D2814 — a generic returning its own list before another generic's two-list result types the call as neither

**check-clean invalid wasm · clause 1 · found by the #3211 review · invalid wasm on master `2bbc5c412` too (inside `h` there, at the `.length` read on #3211) · filed 2026-09-27 against master `2bbc5c412`**

Repro:

    function g<U>(u: U, c: boolean) {
      if c { return [u] }
      [2.5]
    }
    function h<T>(c: boolean, t: T) {
      if !c { return [t] }
      g(t, false)
    }
    print(h(true, 3).length)
    // vl check: rc 0.  vl run: invalid module

#### Mechanism

At `T := i32` the returns are `i32[]` and `g`'s pinned result, which joins to `f64[]` (D2716),
so `h`'s instance returns an `f64[]` or an `i32[] | f64[]` while the call is read as another
list. With the return order swapped (D2784's shape: `g(t, false)` first, then `[t]`) the same
program runs and prints `1`: the return-set join reads the call's deferred result and the list
in one order only. Not yet localised further.

#### Ablation

| ingredient removed | outcome | needed? |
| --- | --- | --- |
| the return order (`g(t, false)` first) | runs, prints `1` | **yes** |
| the nested generic (`[2.5]` in `h` directly) | runs | **yes** |
