### D2814 — a generic returning its own list before another generic's two-list result types the call as neither

**closed 2026-09-27 — the filed repro RUNS and prints `1` · was check-clean invalid wasm · clause 1 · found by the #3211 review · invalid wasm on master `2bbc5c412` too (inside `h` there, at the `.length` read on #3211) · closed by keeping a union's apart arm in either join order (`tyParamArmAbsorbs`) · filed 2026-09-27 against master `2bbc5c412` · fixture `tests/cases/generics/return-join-own-list-before-generic-two-lists.vl`**

Repro:

    function g<U>(u: U, c: boolean) {
      if c { return [u] }
      [2.5]
    }
    function h<T>(c: boolean, t: T) {
      if !c { return [t] }
      g(t, false)
    }
    print(h(true, 3).length)
    // vl check: rc 0.  vl run: invalid module

#### Mechanism

At `T := i32` the returns are `i32[]` and `g`'s pinned result, which joins to `f64[]` (D2716),
so `h`'s instance returns an `f64[]` or an `i32[] | f64[]` while the call is read as another
list. With the return order swapped (D2784's shape: `g(t, false)` first, then `[t]`) the same
program runs and prints `1`: the return-set join reads the call's deferred result and the list
in one order only: `tyParamArmAbsorbs(u, o)` asked only whether a UNION `u` held an arm `o`
would absorb, so with `[t]` first the join of `T[]` and `T[] | f64[]` passed neither test and fell
to `assignable`, which absorbs `f64[]` through `T`. The test now runs when either side is the
union.

#### Ablation

| --- | --- | --- |
| the return order (`g(t, false)` first) | runs, prints `1` | **yes** |
| the nested generic (`[2.5]` in `h` directly) | runs | **yes** |
