### D17302 — an assignment of `null` into a never-filled `let x = null`, compared with a non-literal nullable, takes no null-test route

**fixed 2026-11-24 · closed, runs `true` · was: check-clean invalid wasm · clause 1 · found by IR-V5 grading #9908 against #9901, filed 2026-11-24 against master `3da65c5f` by IR-N9 · fixed by `nulNameSide` (emit_plan_null.vl) taking an assignment `asgYieldsNulHole` names (#9945) · fixture `null/compare-an-assignment-of-null-to-a-nullable.vl`**

#### Mechanism

`binNulNameTestOf` (#9901) routes a `null`-typed name against a nullable to that operand's null
test, the name run for effect. Its name side asked `isNullTy` and `exprIsNulNone`, and an
assignment into the never-filled hole is neither: the checker types it `_ | null`, and an
assignment names no cell. The compare fell to a route that read the assignment's `ref.null` as an
`i32`. `(n = null) == null` takes the null-test arm (D17120) and `n == z` the name route, so each
half ran alone.
