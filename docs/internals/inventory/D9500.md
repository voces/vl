### D9500 — one list literal of two un-annotated functions called through its elements at two argument types has no instance per type

**closed 2026-10-27 by the D14438 slice ([D14438](D14438.md)): the list is a tagged set and each call through an element calls that member at its own arguments · was loud emit reject, clause 2 · found closing [D9450](D9450.md) · filed 2026-10-21 against master `56e51b394` · pins: `tests/cases/closures/hole-fn-list-mapped-at-two-argument-types.vl`**

Repro (runs, prints `6` `2.5`):

    function inc(a) { return a + 1 }
    function dbl(a) { return a * 2 }
    const fs = [inc, dbl]
    print(fs.map((f) => f(3))[1])
    print(fs.map((f) => f(1.25))[1])

Want:

    6
    2.5

#### Mechanism

Not traced. `monoPinListElems` (emit_mono.vl) finds two pins for the list's element slot and
refuses. One list value holds one element type, so running this needs the literal built once per
pin or its elements delivered as generic values. A list a function returns takes a copy of the
function per pin ([D9450](D9450.md)); a list bound once at module scope has no such copy.

#### Ablation

| ingredient removed | outcome | needed? |
| --- | --- | --- |

| the `.map` callbacks (`fs[1](3)`, `fs[1](1.25)`) | same refusal | no |
| the `.map` callbacks (two `for f in fs` loops) | same refusal | no |
| the second function (`[inc]`, `.map` at both types) | `call to unknown function` | changes the refusal |
| the second function and the `.map` callbacks (`[inc]`, `fs[0](3)`, `fs[0](1.25)`) | runs, `4` `2.25` | **yes** |
| the list (`const f = inc`, called at both types) | runs, `4` `2.25` | **yes** |

#### Grading list

The returned spelling over one binding (`const v = deliver()` with `deliver() { return [inc,
dbl] }`, both `.map` calls over `v`), which refuses with `a generic function taken as a value
reaches no call that fixes its type`. The `.filter` spelling. The single-function list read by
index or `for`, which must keep running, and the same list read by `.map`.
