### D3863 — a generic record holding a list of records, `Box<A[]>` beside `Box<B[]>` of same-shaped `A` and `B`, reads its element as one of the two, and the other's `self`-function is never called

**check-clean silently wrong value · found grading D3834's nominal-pin matrix · filed 2026-10-08 against master `1af9fe52f`**

Repro:

    // file: r1.vl
    export type A = { x: i32 }
    export function d(self: A): string { "RA" }
    // file: r2.vl
    export type B = { x: i32 }
    export function d(self: B): string { "RB" }
    // file: main.vl
    import { A, d } from "./r1"
    import { B, d } from "./r2"
    type Box<T> = { v: T }
    function h<T>(x: T): string { x.d() }
    const a: A = { x: 1 }
    const b: B = { x: 2 }
    const ba: Box<A[]> = { v: [a] }
    const bb: Box<B[]> = { v: [b] }
    print(h(ba.v[0]))
    print(h(bb.v[0]))
    // vl check: rc 0.  vl run: prints RA, RA

Want:

    RA
    RB

#### Mechanism

Not yet located. `h` is instantiated from the type of `bb.v[0]`, and that read names `A`, so the
`B` instance and its `d` are never reached. A `Box<B>` field, a `B[]` binding and a `B[][]` list
keep the name; only a list field of a generic record loses it. Passing the box to a function
annotated `Box<B[]>` reads it as `B` instead, and then the `A` box prints `RB`: whichever of
the two is written last wins.

#### Ablation

| the generic record (`const bs: B[] = [b]`, `h(bs[0])`) | `RB` | **yes** |
| the call at `A` (only `h(bb.v[0])`) | `RB` | **yes** |
