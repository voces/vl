### D2220 — the else-branch of an inline literal-set `is` over a mixed union reads the box as i32 without unboxing

**check-clean invalid wasm · `type mismatch: expected i32, found (ref $type)` · found reviewing D2205's close · filed 2026-09-23 against master `0d5421468`**

Repro:

    function f(m: "x" | "y" | i32) {
      if m is "x" | "y" {
        print(m)
      } else {
        print(m + 1)
      }
    }
    f("x")
    f(4)

#### Mechanism

The operand is a union box. The else-branch narrows it to `i32` by subtracting the tested set,
and the read uses the box ref as the i32 without unboxing: the emitter's else-narrowing does
not cover an INLINE multi-member literal set as the tested type. A one-literal test, an aliased
test set, or `is i32` in the then-branch all unbox correctly.

#### Ablation

| ingredient removed | outcome | needed? |
| --- | --- | --- |
| the second literal (`"x" \| i32` tested with `is "x"`) | runs | **yes** |
| the inline spelling (`type K = "x" \| "y"`, `m: K \| i32`, `is K`) | runs | **yes** |
| the i32 use in the else (`print(m)` there) | runs | **yes** |
| `m + 1` replaced by `const k: i32 = m` | invalid wasm | no |
