### D14517 — an un-annotated `Map()` takes its value row by name, not from the record its stored call is built as

**closed · now runs, prints `5` / `4` · was check-clean invalid wasm, clause 1 · filed and closed 2026-10-27 against master `eef670449` · closed by `recMapStoresAgree` (check_fit_rules.vl) building the map's values where every stored value a kept delivery builds is built, `recSitesLandAt` serving a call stored into such a map, and `mvShapeOfMapNodeTy` (emit_union_atoms.vl) minting the slot from that build; the by-name pick `mvValRowOfShape` is deleted · fixtures `maps/unannotated-map-set-call-built-at-wider-record.vl`, `maps/unannotated-map-stores-literal-and-call-built-at-wider-record.vl`, `maps/error-unannotated-map-stores-built-apart.vl`**

Repro:

    type J = { f: i32 | null }
    function mk() { { f: 4 } }
    const wideJ: J = mk()
    const m = Map()
    m.set("a", mk())
    const x = m.get("a")
    if x != null { print(x.f + 1) }
    print(wideJ.f ?? 0)

Want:

    5
    4

#### Mechanism

`const wideJ: J = mk()` builds `mk`'s record at `J`. The first `.set` on a bare `Map()` pins
the value type to `mk`'s own shape without a delivery, so the call counted as queued for nowhere,
was not read in place, and `mk` built at its own row: `wideJ` received it as `J`. With a second
store the checker refused instead ("built as J where line 3 delivers it"), and that refusal
depended on which store came first. The map's value slot was minted from its value type's name
(`mvValRowOfShape` picked the declared row of that shape), not from the record the values are
built as.

Now each store into an un-annotated `Map()`, by `.set` or by index and in any order, contributes
its build (`recBuildPush` over `recMapStoredValues`). When they agree, that record is the map's
value row, a stored literal is built at it (`recBuildRowOf`), and a read binding holds it
(`letMapReadHeldTy`). When they land apart, each store refuses at its own row
(`recRefuseAtOwnRow`), as #4944 does for lists. `recSitesLandApart` is keyed on one function's
call sites and does not see two stores into one map, so the agreement is read from the map's
own builds (`recBuildPassAt`).

A call that reaches the map through a binding (`const a = mk()` then `m.set("a", a)`) is not
covered: [D14518](D14518.md).
