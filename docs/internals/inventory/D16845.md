Repro:

    function mk() { return (a) => a + 2.5 }
    const x = mk()
    print(x(3))
    print(x(0.5))
    // vl check: rc 0.  vl run: emit error, `a function-value call has no interned signature — parameter 1 of type `_` has no representation in the function-value ABI`

Want:

    5.5
    3

#### Mechanism

Not traced. The maker's result is one closure value, and its lambda's parameter is fixed by the
calls through the binding, which disagree (`i32`, `f64`), so no one signature closes it. The
lambda literal bound directly (`const f = (a) => a + 2.5`) is built once per signature it is
called at; the maker's call builds one closure.

The contract the fix keeps: a directly bound hole lambda is built once per signature it is called
at, so `const f = (a) => a / 2; f(3); f(3.0)` prints `1` then `1.5`. Widening the maker's lambda
parameter to the join (`f64`) would break that; the maker's closure is built at each signature its
binding is called at, its captures taken once.
