### D2422 — a binding of an assignment's value keeps an `i32` slot when the value is a box's string member

**closed 2026-09-25 by [D2398](D2398.md)'s close — the witness prints `w` · was check-clean invalid wasm, clause 1 · filed 2026-09-25 against master `a20d69104`, the
review residue of [D2391](D2391.md)'s close**

Repro:

    function g() {
      let v: i32 | string = 3
      const r = (v = "w")
      print(r)
    }
    g()
    // vl check: rc 0.  vl run: invalid module inside `g`: type mismatch: expected i32, found (ref $type)

#### Mechanism

Closed by [D2398](D2398.md)'s close: the write moves ahead as `const t = "w"; v = t`,
so `r` binds `t`, a `string`, and no re-read of the box is left to classify. The
`f64 | string` and `i32[] | string` spellings print their string too.

D2391's close reads the value back narrowed to the `string` member, so the value on the stack
is a string ref. The binding `r` classifies its slot from its initializer by a ladder that does
not reach the string member of an `=` node, so the slot stays the `i32` default and the
`local.set` receives a ref. The function-tail spelling runs, because the functype's result
comes through `criClassify`, which does ask the right side. The slot ladder is a prediction
from the close's code path, not yet probed.
