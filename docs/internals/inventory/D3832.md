### D3832 — a never-called lambda with an un-annotated parameter is emitted at an `i32` parameter and its body fails validation

**closed 2026-10-08 by lane SC · was check-clean invalid wasm · found in review of lane SC · filed 2026-10-08 against master `5a281ef27` · pins: `tests/cases/closures/hole-lambda-unread-or-let-aliased.vl` · residue [D3843](D3843.md)**

Repro:

    function mk(x: string) {
      const c = (y) => y + "C"
      x
    }
    print(mk("a"))
    // vl check: rc 0.  vl run: exit 70, invalid module inside `c`:
    //   type mismatch: expected (ref $2), found i32; $2 is `string`

Want:

    a

#### Mechanism

An un-annotated lambda parameter is typed by its call sites. With no call site the hole stays at its `i32` default, and the body `y + "C"` is then emitted as a string concatenation whose left operand is that `i32`. The lambda is emitted as a function even though nothing calls it, so the validator rejects it. The nesting is not needed: a top-level never-called lambda fails the same way.

The close stubs such a lambda, as an uncalled hole function is already stubbed: an
un-instantiated hole lambda that initializes an un-annotated `const` whose name nothing in its
enclosing frame reads (`monoUnreadLamSlots`, `emit_mono.vl`). The search is by name over the
frame, nested functions included, so a shadowing read keeps the lambda ([D3843](D3843.md)).

#### Ablation

| ingredient removed | outcome | needed? |
| --- | --- | --- |
| the enclosing function (`const c = (y) => y + "C"` then `print("a")` at top level) | still invalid, inside `c` | no |
| the `string` concatenation (`(y) => y`) | prints `a` | **yes** |
| the hole (`(y: string) => y + "C"`) | prints `a` | **yes** |
| the lambda never being called (`c(x)` as the result) | prints `aC` | **yes** |
| a second `mk` call (`mk("b")`) | still invalid | no |

#### Grading list

* `(y) => y + 1`, `(y) => y.length`, `(y) => y.x`: the body ops other than `+` on a string.
* An unused lambda stored in a record or returned: both are uses, and should keep running.
* D3833 is the same hole reached through a `let` alias.
