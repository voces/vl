### D2156 — a compare between two values typed as one string literal walks both strings

**closed 2026-09-23 — the witness prints `true` and compiles to a constant · was a working program whose compare called `__str_eq__`, clause 2 under the owner's ruling that comparing two string literals is O(1) · filed 2026-09-23 against master `b5debe165`**

Repro:

    type S = { k: "bb", n: i32 }
    const s: S = { k: "bb", n: 1 }
    function eq(v: "bb", w: "bb"): boolean { v == w }
    print(s.k == "bb" && eq("bb", "bb"))

#### Mechanism

A one-literal type has one value, so its reads need no compare: `staticStrLitLex` names the
literal an operand is known to hold (a string literal, a value typed as one literal, a `const`
bound to one), and `==`/`!=` between two such operands folds to a constant after evaluating both
for their effects. Beside an atom it is the member's interned id, found by decoded value
(`memberLexOfValue`), so an escape and the character it spells agree. The getter contract prices
both at 0 through `nodeCmpsByTag`, the checker-side twin of the same question.

#### Grading list

A single literal beside an inline literal union, and a literal spelled with an escape.
