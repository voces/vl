### D17678 — a hole-typed name delivered to a typed destination inside a nested lambda is not found in the lambda's per-instance re-check

**closed 2026-11-26 · runs, prints `3` · was loud check reject (`undeclared identifier 'y'`), clause 2 · fixed by snapshotting a hole encloser's visible names for the nested declaration's per-instance re-check (`elabNestNote`, keyed `-2`) · case `tests/cases/closures/typed-lambda-reads-hole-encloser-names.vl` · filed 2026-11-26 against master `eaad1cdb2` by COV-CALL, found ablating D17676; traced and fixed by START-2**

Repro:

    function v(y) {
      const b = (): i32 => y
      return b()
    }
    print(v(3))
    // vl check: undeclared identifier 'y'

Want:

    3

#### Mechanism

The refusal comes from the elaboration, not the first walk. A trap in `checkIdentUndeclared`
under a `--names` seed gave this backtrace: `elabNestedPerEncl` → `elabSettle` → `elabOne` →
`elabOneAt` → `monoRecheckBegin`. `monoRecheckBegin` re-checks the nested lambda once per
instance of its encloser.

That re-check resolves the lambda's free names against the snapshot `elabNestNote` took of what
the encloser saw. `elabNestNote` took one only for an open encloser: one with a type variable in
its signature, or a one-parameter lambda.

Inside the lambda, a name of hole type (the parameter, or a plain alias of it) is delivered
straight to a typed destination. That delivery pins the encloser's hole parameter, which closes
the encloser's signature before the lambda is noted, so no snapshot was taken.

`elabNestedPerEncl` still enqueued the lambda per encloser instance, because it reads the
encloser's un-annotated parameter (`elabReadsEnclParam`). It then re-checked the lambda with none
of the encloser's names. A literal local resolved anyway, because a literal is folded.

An encloser with an un-annotated parameter now has its names snapshotted. The snapshot is keyed
apart (`-2`), and `elabOneAt` falls back to it, so `elabNestedPerEncl`'s open-encloser branch,
which reads key `-1`, does not build a nested declaration that reads an open hole per instance
against the template's view.

#### Ablation

`vl check` before the fix, every spelling inside `function v(y)`:

| spelling | outcome |
| --- | --- |
| `const b = (): i32 => y` | `undeclared identifier 'y'` |
| `(): i32 => { return y }` | `undeclared identifier 'y'` |
| `const b: () => i32 = () => y` (the annotation on the binding) | `undeclared identifier 'y'` |
| `(x: i32): i32 => y` (an unused typed parameter) | `undeclared identifier 'y'` |
| `() => { const t: i32 = y; return t }` (no result annotation) | `undeclared identifier 'y'` |
| `const z = y; (): i32 => z` | `undeclared identifier 'z'` |
| `const b = (): i32 => y; return 0` (never called) | `undeclared identifier 'y'` |
| `(x: i32): i32 => y + x` | runs |
| `(): i32 => { const q = 1; return y + q }` | runs |
| `const w = y + 1; (): i32 => w` | runs |
| `const k = 2; (): i32 => k` (a literal local) | runs |
| `() => y` (unannotated) | runs |
| `function v(y: i32)` with `(): i32 => y` | runs |

The trigger is a hole-typed name delivered to a typed destination, not the result annotation.
Arithmetic types the value through the operator and pins nothing.
