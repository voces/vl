### D17678 — a lambda with a result annotation inside a hole function does not see the function's locals

**loud check reject · clause 2 · 1 spelling · filed 2026-11-26 against master `eaad1cdb2` by COV-CALL, found ablating D17676**

Repro:

    function v(y) {
      const b = (): i32 => y
      return b()
    }
    print(v(3))
    // vl check: undeclared identifier 'y'

Want:

    3

#### Mechanism

Not located. The lambda's result annotation is what matters: the same lambda without it resolves
`y`, and so does the annotated lambda inside a generic `<T>(y: T)` or beside an annotated
parameter. A local `const z = y` is not found either, so the scope the annotated lambda's body is
resolved in seems to lack the hole function's frame, not just its parameters.

#### Ablation

| ingredient changed | outcome | needed? |
| --- | --- | --- |
| no `: i32` result annotation | runs, `3` | **yes** |
| `y` annotated, or the function generic `<T>(y: T)` with `(): T` | runs, `3` | **yes** (a hole parameter) |
| a lambda parameter added, `(k: i32) => y` | runs, `3` | no (the result annotation is the trigger) |
| the lambda reads a local `const z = y` | `undeclared identifier 'z'` | no |
| the lambda reads nothing of the frame, `(): i32 => 5` | runs, `8` | **yes** |
| a block body, `(): i32 => { return y }` | `undeclared identifier 'y'` | no |

#### Grading list

- `const b = (): J => y` inside D17676's `viaReturn`, a record-typed hole parameter.
