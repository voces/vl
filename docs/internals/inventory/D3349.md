### D3349 — a fresh function result pushed into a list of a wider record is invalid wasm when a record of its own fields is declared

**closed · runs · was check-clean invalid wasm; the closure-argument, map-value, map-index, field-store, assignment and return faces run too, the generic-argument face is a loud check reject · a function with no declared result called at one site, returning only object literals, now builds them at that call's destination, as its twin with a declared result does (D3444) · fixture `tests/cases/soundness/record-fresh-call-built-at-destination-beside-own-row.vl` · closed 2026-09-30 against master `39097fdcb`**

Repro:

    type I = { f: i32 }
    type J = { f: i32 | null }
    function mk() { { f: 4 } }
    const xs: J[] = []
    xs.push(mk())
    print(xs[0].f ?? 70)
    // vl check: rc 0.  vl run: invalid module, "expected (ref null $type), found (ref $type)"

Want:

    4

#### Mechanism

`mk`'s literal is built at the declared `I` row (D3338's mechanism), and the method argument hands
it to `J`'s slot. At a plain delivery the checker refuses this (`recBuiltAtDeclared`); at a
method or generic argument it declines, because the same shape through `Map.set` runs on master
and a refusal there would lose that run. Building the literal at the call's destination, or
adopting the function's result where no annotated twin breaks (D3342), would close it.

#### Ablation

| ingredient removed | outcome | needed? |
| --- | --- | --- |
| `type I = { f: i32 }` | runs, prints `4` | **yes** |
| the call (`xs.push({ f: 4 })`) | runs | **yes** |
