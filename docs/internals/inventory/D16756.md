### D16756 — a relay of a generic maker whose result an un-annotated binding holds is not built at the binding's call

**closed · runs, prints `41` and `7` · was loads then traps, `vl check` rc 0, `wasm trap: indirect call type mismatch` · clause 1 · a relay call held in an un-annotated `const` that is only called takes the results of those calls (`fvaRelayBindInit`, `fvaRelayRows`, check_assignable.vl), as a maker's `const` binding does; a binding read as a value still gives the relay none · fixture `closures/generic-maker-relay-held-in-unannotated-binding.vl` · found closing [D16710](D16710.md) · filed 2026-11-16 against master `6356d3e7d`**

Repro:

    function k<T>(x: T): T { return x }
    function mk() { return k }
    const o = mk()
    const of: f64 = o(2.5)
    function deliver() { return mk() }
    const v: (x: i32) => i32 = deliver()
    const z = deliver()
    print(v(41))
    print(z(7))
    // vl check: rc 0.  vl run: wasm trap, indirect call type mismatch

Want:

    41
    7

#### Mechanism

A maker call held in an un-annotated `const` that is only called takes the result of those calls
(`fvaMakerCallRows`, through `callOfBind`). `fvaRelayRows` reads a relay's calls only at a closed
delivery type, so `const z = deliver()` gives the relay no result and `mk` stays withdrawn from
twinning. Both calls agree on `i32` here, so the relay's maker call would take one result.

#### Ablation

| ingredient removed | outcome | needed? |
| --- | --- | --- |
| the annotation's absence (`const z: (x: i32) => i32`) | runs, `41` `7` | **yes** |
| the annotated delivery `v` (only `z`) | runs, `7` | **yes** |
| the `f64` use through `o` | runs | **yes** |

#### Grading list

The un-annotated binding called twice at one type, and at two types (which must stay as built).
