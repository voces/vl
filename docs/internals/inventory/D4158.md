### D4158 — two written `let`s of generic functions called at different types share one stale instance

**closed 2026-10-11 by lane SC, with D3961 · runs · was check-clean silently wrong · found by the D3961 position matrix · filed 2026-10-11 against master `3096c492f` · pins: `tests/cases/closures/let-of-generic-written-with-generic-called.vl`**

Repro:

    function inner<U>(u: U) { print("I"); print(u) }
    function other<V>(v: V) { print("O"); print(v) }
    let top = other
    top = inner
    top(true)
    let before = inner
    before(2)
    before = other
    before(3)
    // PRINTS I 1 I 2 O true

Want:

    I
    true
    I
    2
    O
    3

#### Mechanism

With the D3961 coercion in place, instancing `inner` at `(boolean)` for `top` and at `(i32)`
for `before` tripped the D971 guard in `monoInstantiate`, which refuses a second instance of a
generic whenever the callee binding is reassigned. The guard is right for ONE binding called
at two types and wrong across two bindings: the close exempts the call being coerced
(`monoWriteCoercedCall`) when it is the first call to give its binding a signature
(`monoWritesCoercedFirstCall`), so one binding at two types still refuses with the D971 message.
