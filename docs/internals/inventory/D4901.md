### D4901 — a record literal of a `T[]` field mints no row in a generic body that returns a list

**closed · was a loud emit reject (`emitProgram: object literal but no struct type declared`), identical on master `c2dbf639e` · fixture `tests/cases/generics/generic-record-of-list-param-list-return.vl` · filed 2026-10-15**

Repro:

    function h<T>(v: T[]): T[] {
      const r = { xs: v }
      print(r.xs[0])
      return v
    }
    print(h(["e"])[0])
    // vl check: rc 0.  vl run: emitProgram: object literal but no struct type declared

Want:

    e
    e

#### Mechanism

`mintPinnedObjLitRows` skips an instance for which `instRetKeepsRecordsIn` is false, and that
gate declined every body whose return is a constructor over a type parameter (the D2850
rule) — including `T[]`, `T[][]` and a hole's list, which cannot hold a record the body
built. Closed in `emit_collect.vl`: a return type that holds no record (`tyHoldsObj`) keeps
the body's records, so the literal mints its row at each instance.

| the list (`v: T`, `{x: v}`, `: T`) | runs | **yes** |
