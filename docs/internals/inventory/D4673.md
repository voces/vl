### D4673 — the annotation `null | null` resolves to `<error> | null`, not the `null` unit type

**closed — a union annotation whose every member is `null` (inline `null | null`, or a declared `type N = null | null`) resolves to the `null` unit type, so it takes D4550’s `nulnone` cell · graded by `scripts/capability-probes/null-unit-self-union.vl` and the last lines of `tests/cases/types/null-unit-heap-positions.vl` · filed 2026-10-14 against master `1c1740512`**

Repro:

    function f(x: null | null) { print(x == null) }
    f(null)
    // vl check: rc 0.  vl run: emitProgram: bare null needs a struct-typed context

Want:

    true

#### Mechanism

The annotation resolver reads `X | null` as the nullable of `X`, and with `X` itself `null`
the inner type is the error type: a diagnostic that names the parameter prints it as
`<error> | null`. `vl check` raises nothing at the annotation, so the emitter receives a
parameter whose recorded type is neither `null` nor a nullable it has a rep for. `x: null`
runs (D4550).

#### Ablation

| spelling | outcome |
| --- | --- |
| `x: null \| null` | refuses at emit |
| `x: null` | runs |
| `const y: i32 = x` in the body | check reject naming `<error> \| null` |

#### Grading list

`type N = null` then `x: N | null`, and `null | null` as a return and a `let` annotation.
