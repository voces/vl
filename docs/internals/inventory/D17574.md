### D17574 — inside a generic instance, an annotation naming the type parameter reads the check's binding, not the elaboration's key

**runs today and must keep running · the instance-body half of the one-instance-key rule; it must keep running when the elaboration's key becomes the binding everywhere (coordinator ruling 2026-11-26, queued after family C's C1) · filed 2026-11-26 against master `6034afb70` by SOUND**

Repro:

    type II = { f: i32 }
    type J = { f: i32 | null }
    function mk() { return { f: 4 } }
    const wideJ: J = mk()
    function idl<T>(a: T): T {
      const x: T = a
      return x
    }
    const r: J = idl(mk())
    print(r.f ?? 0)
    // vl run: 4.  `VL_INST_KEYS=1`: check-only `idl 25|T={f: i32 | null}`, elab-only `idl 25|T={f: i32}`

Want:

    4

#### Mechanism

The check binds `idl`'s `T` at `J`, the destination's type. The elaboration keys the call at
`{f: i32}`, the row `mk()` is built at. Mono binds `T` from the check unless an argument was built at
a rep other than its checker type (D17641), so it runs today. When the elaboration's key binds `T`
for every call, mono's instance is keyed at `{f: i32}`. But the body's `const x: T` is still typed at
`J`, and the module fails validation inside `idl` (`expected J, found II`). Every reader of the type
parameter inside an instance body has to take the instance's binding before the elaboration's key
can be the single answer.
