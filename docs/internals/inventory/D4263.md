### D4263 — record arms whose shared field is a `Set` in one and a map in the other are refused

**loud check reject · clause 2 · the message concedes a representation, not a design rule · filed 2026-10-12 against master `f6ee50929`**

Repro:

    type A = { s: Set<string> }
    type B = { s: Map<string, i32> }
    function f(u: A | B): i32 {
      if u is A { return 1 }
      2
    }
    print(f({ s: Set() }))
    // vl check: rc 1, "a union cannot hold both A and B yet: field `s` is a Set in one and a map in the other"

Want:

    1

#### Mechanism

A `Set` and a map share one runtime representation, so the field test `is A` would run cannot
tell them apart, and the union is refused when its declaration is checked
(`checkUnionSetMapClash`, `typecheck.vl`). Q4 (c) makes the union legal; a close needs the
`Set` and map reps to be told apart at runtime, or a ruling that the field test answers from
the declared arm.
