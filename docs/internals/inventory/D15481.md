### D15481 — D14160 regressed: an object literal handed to a parameter of a narrower named record is built at the declared row, dropping its excess field, while the elaboration types it at the literal's row

**closed · now runs, prints `true`, as the bound spelling `const r = { f: 3, g: 10 }; look(r)` does · was check-clean silently wrong (printed `false`) · regressed by `12aff27ae` (#5373), bisected over fixpoint seeds (`49155ca6f` prints `true`) · closed 2026-11-05: the width hold on the argument no longer stamps the literal's build row · found by the `monoWalkIdentCall` shadow (architecture-target §3.4) · filed 2026-11-05 against master `f4a596c5`**

Repro:

    type G = { g: i32 }
    type H = { f: i32, g: i32 }
    function look(o: G) { print(o is H) }
    look({ f: 3, g: 10 })
    // PRINTS true (printed false from #5373 to 2026-11-05)

Want:

    true

#### Mechanism

A literal argument that sets a field its named record parameter does not declare is passed
wider: the checker makes the parameter generic (`__W0`) and holds the argument to the declared
`G` as a check. That hold went through `assignableExpr`, which stamps the literal's build row at
its destination, so the literal was built at `G`'s one-field row and `f` was dropped after its
initializer ran. `look`'s instance for it was then bound at `G`.

D14160's 2026-10-31 close never stored `f`. Before `12aff27ae`, `o is H` was folded statically
from mono's exact-sub row (`{ f: i32, g: i32 }`) over a value built at `G`. That is why
`if o is H { print(o.f) }` was an emit refusal (`unknown struct field`) on `49155ca6f`. #5373 made
`exactOperandTyOf` read the elaboration, which closes `__W0` at `G`, and the fold turned `false`.

The fix holds stamps during the check (`stampsHeld`), so the literal is built at its own record
and the instance binds it, as for the bound spelling.
