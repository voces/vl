### D4982 — a closure in a type-parameter list's `is K[]` arm that passes it whole to a generic list parameter is invalid wasm

**closed 2026-10-15 · runs · was check-clean invalid wasm, clause 1 · pin: `tests/cases/generics/is-list-arm-closure-delivers-type-parameter-list.vl` · found closing [D4963](D4963.md) · filed 2026-10-15 against master `d9468f145`**

Repro:

    function lenG<W>(xs: W[]) { xs.length }
    function t<V>(a: V[]) {
      if a is f64[] {
        const k = () => lenG(a) + 10
        print(k())
      }
      print(a.length)
    }
    t([1])
    // vl check: rc 0.  vl run: invalid module, type mismatch inside `__lambda_1`

Want:

    1

#### Mechanism

Outside a closure `lenG(a)` infers `W = f64` from the narrowed read and the checker refuses
delivering `a` as `f64[]` (D4963). Inside the closure the capture is read at its declared
`V[]` (D4935), so the call binds `W = V`, a delivery the list-narrowing ruling allows. The
emitter's capture stand-in for an empty other-arm list (`listFitCaptureStandIn`) still
replaced the capture with the arm's empty `f64[]` and handed it to `lenG<i32>`. An explicit
`lenG<V>(a)` in the arm itself, outside any closure, failed the same way through
`listFitShadowRow`.

#### Ablation

| an empty local `const q: V[] = []` as the receiver | invalid wasm | no |

#### Close

The checker records each narrowed-list read it lets through because the declared type fits
the destination (`narListReadsDecl`, typecheck.vl), and neither stand-in (the capture's in
wasmEmit.vl, the shadow row in emit_classify.vl) replaces such a read: the callee gets the
caller's list. The closure, `lenG<V>(a)` in the arm, and `const w: V[] = a` in a closure run
at empty and non-empty `i32[]` and `f64[]` instances.
