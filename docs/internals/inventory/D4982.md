### D4982 — a closure in a type-parameter list's `is K[]` arm that passes it whole to a generic list parameter is invalid wasm

**check-clean invalid wasm · clause 1 · found closing [D4963](D4963.md): outside a closure the same call is refused by the checker, so the two spellings disagree · filed 2026-10-15 against master `d9468f145`**

Repro:

    function lenG<W>(xs: W[]) { xs.length }
    function t<V>(a: V[]) {
      if a is f64[] {
        const k = () => lenG(a) + 10
        print(k())
      }
      print(a.length)
    }
    t([1])
    // vl check: rc 0.  vl run: invalid module, type mismatch inside `__lambda_1`

#### Mechanism

Outside a closure `lenG(a)` infers `W = f64` from the narrowed read and the checker refuses
delivering `a` as `f64[]` (D4963). Inside the closure the check accepts the call, and at the
`V = i32` instance the lambda hands `lenG` a list at a different heap type than the instance
of `lenG` it calls takes. Which answer is right (the refusal, or `W = V` printing `11` then
`1`) is not settled, so this row has no `Want:` block.

#### Ablation
