#### Mechanism

Two checks judged a spread of anything but a list literal by its element type, an existing list's
existing records (D13960): the record-shape fit (`objShapeListLitAdapts`) and the storage widening
walk (`recWidenLitElems`). A fresh list `const` is a literal nothing else has built, and is judged
by that literal now, as a spread of a literal is (D4871). The build: the literal's own type is
the source's, `{x: i32}[]`, and an annotated `let` or a parameter is no built place
(`recLitPlaceBuiltTy`), but the delivery already rep-stamps the literal at its destination
(`recordRepTyAdopt`, the channel every literal destination uses). The list stamp's no-build arm
reads that stamp as the element, so the `const`'s literal is built there as D16440 builds it.
Stamping inside `recordRepTyAdopt` itself ran before the binding's later deliveries were
recorded and missed refusing `g(s)` at `{x: i32}[]`, an invalid module; the stamp pass does not.

#### Note, 2026-11-15

`[...s, { x: 2.5 }]` into the same annotation runs since D16440, as does `[a, ...s]`: a part of
the literal gives it the wider element, and the spread is built there. Only a literal made of
spreads alone is refused, at the destination's fit check, where the literal's own type is
`{x: i32}[]`; an argument position, `f([...s])` with `f(v: { x: f64 }[])`, is refused the same way.
