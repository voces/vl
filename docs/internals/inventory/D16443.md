### D16443 — a fresh list `const` spread into a list literal delivered at an annotated wider list is refused, though a spread into a push builds it

**loud check reject · clause 2 · `{x: i32} is not {x: f64} (reached through {x: i32}[] into {x: f64}[]): they store field `x` differently` · found with [D16440](D16440.md) · filed 2026-11-15 against master `6adb40099` · open**

Repro:

    const s = [{ x: 1 }]
    const t: { x: f64 }[] = [...s]
    print(t[0].x)
    // vl check: {x: i32} is not {x: f64} (reached through {x: i32}[] into {x: f64}[])

Want:

    1

#### Mechanism

Not yet located. `t.push(...s)` into the same annotated list builds `s` at the wider element
(D15287), and since D16440 so does `[a, ...s]` beside a wider part. Delivered whole at an
annotated destination, the literal's spread is checked against the destination's element before
any build is recorded for `s`, so the refusal fires for a list nothing else holds.

| `const s: { x: f64 }[]` | prints `1` | **yes** |
