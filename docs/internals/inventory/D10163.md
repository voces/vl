### D10163 — an explicit type argument to a generic with a `() => T | string` parameter refuses as an un-annotated union return

**loud check reject · `the returns of f join to i32 | string for this argument — type-valid, but an inferred union return through an un-annotated parameter is not yet supported by codegen; annotate the return type` · clause 2 · CAPABILITY: the refusal concedes the program is type-valid, and the same call with the type argument inferred runs · present on master `6bb8a329f` · found closing [D10133](D10133.md) · filed 2026-10-22 against master `6bb8a329f`**

Repro:

    function len<T>(f: () => T | string) {
      const t = f()
      if t is string { 0 } else { 1 }
    }
    print(len<i32>(() => 4))
    // vl check: the returns of `f` join to i32 | string for this argument — type-valid, but an inferred union return through an un-annotated parameter is not yet supported by codegen; annotate the return type

#### Mechanism

Not traced. The message is raised at `f()` inside `len`, so the explicit-argument path reads
`f`'s call as the un-annotated-parameter case even though `f` is annotated; the argument's own
annotation does not move it.
