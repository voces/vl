### D12580 — an un-annotated record literal whose list field mixes `i32` and `string` gets no ref-list slot for the field

**loud emit reject · `` emitProgram: `.length` receiver's ref-list element does not resolve ``, `vl check` rc 0, clause 2 · CAPABILITY: the same record annotated `{ xs: (i32 | string)[], n: i32 }` prints `2`, and a bare `const xs = [1, "z"]` reads its `.length` · the un-annotated face of the `generic-alias-union-element-list-field` matrix, found closing [D12560](D12560.md) · the same on master `b5589bd0c` · filed 2026-10-24 against master `b5589bd0c`**

Repro:

    const v = { xs: [1, "z"] }
    print(v.xs.length)
    // vl check: rc 0.  vl run: emitProgram: `.length` receiver's ref-list element does not resolve

Want:

    2

#### Mechanism

Not traced. The read's `refListSlotOfExpr` of `v.xs` is `-1` (`emitArrLen`, wasmEmit.vl). The
inferred record is an inline shape, so its field's element name comes from `iisPushFieldElem`
(emit_shape_intern.vl). The suspect is the key it records for a value-union element. A declared
field and a bare list of the same union both find the slot.
