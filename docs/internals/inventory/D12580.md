#### Mechanism

The suspect named at filing (`iisPushFieldElem`) was not it: the un-annotated record is minted
as an `#anon` row (emit_collect.vl), never through the inline-shape interner. Its field code
comes from `anonFieldCodeSyn` (emit_classify.vl). There the first element `1` is a number
literal, the `"z"` counts as a runtime element, and `anonListWiderThanLits` asked only whether
the list's element was another number type or a number box. `i32 | string` is neither, so the
field was coded as an i32 list (4) and recorded no element name. The read then found no
ref-list row. The fix: an element stored by reference also widens the literal, so the field
falls to the arena rung and takes code 5 with the union's key. The ablation's other value
unions ran because `{ k: 1 }` and `true` first never take the number-literal arm, and
`[1, null]` is a number box.
