### D3984 — `for x in downTo downTo` cascades after #3525's `downTo` refusal

**loud check reject (parse error) · from the review of #3525 · filed 2026-10-11 against master `1df3c8f91`**

Repro:

    const downTo = [1, 2]
    for x in downTo downTo {
      print(x)
    }
    // master: two errors ("a `for` body requires braces", "undeclared identifier 'x'").
    // With #3525: five.

#### Mechanism

#3525 recognises `downTo` after a range start as a misspelt `down to` and refuses it once.
When the iterable is itself a binding named `downTo`, the recovery consumes the wrong token,
and the body is parsed out of position. The input is contrived; it is filed so the recovery
is graded on it.
