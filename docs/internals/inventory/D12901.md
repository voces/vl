### D12901 — `.map` has no result list for a nullable-list, map, nullable-map or nullable-closure element

**loud emit reject · `vl check` rc 0 · clause 2 · 4 element kinds · the nullable-list half of [D2193](D2193.md) · filed 2026-10-25 against master `db1d4f849` · until this closes, the container rule's message does not offer the `.map` copy for a nullable-list element (`mapCopyBuilds`)**

Repro:

    const nss: i32[][] = [[1]]
    const w: (i32[] | null)[] = nss.map((x): i32[] | null => x)
    print(w.length)
    // vl check: rc 0.  vl run: emitProgram: unsupported .map/.filter element type

Want:

    1

#### Mechanism

`mfResultKindOf` names a result list for a callback returning a record (bare or nullable, a
union arm included since D12820), a variant, a union, a string, a list and the scalars. A
callback returning `i32[] | null`, a `Map`, a nullable `Map` or a nullable closure falls
through every arm, so `.map` refuses at emit. The checker types each result list correctly;
the lowering has no element row to build it at.

#### Ablation

| `Map<string, i32>` element (`ms.map((m) => m)`) | the same refusal | element kind: no |

#### Grading list

`ms.map((m) => m)` over `ms: Map<string, i32>[]`, its `Map<string, i32> | null` and
`((i32) => i32) | null` twins, and `tests/vl_widen_hint_test.ts`'s `(i32[] | null)[]` case,
which must offer `.map` once this builds.
