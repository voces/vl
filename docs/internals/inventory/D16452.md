### D16452 — a returned `if` or `match` of records of un-annotated functions is judged as one value, where its tail spelling is judged arm by arm

**closed · was a loud check reject, `cannot store 'half' in 'pickHalf().f': … every function a call through 'pickHalf().f' may run must return one type` · clause 2 · bucket (f), a local fix: the tail spelling runs since [D15925](D15925.md) · found from lane D's return-rule migration of `tail-value-join-of-records-of-fn-fields-called-through-result` · filed 2026-11-15 against master `c3049ce76`**

#### Mechanism

D15925 made a tail `if` of records agree with its arms by two facts. The returned-value walk
`a20RetWalk` (`check_nj_gate.vl`) yields each arm's record for a tail `if`, and
`holeCallTailIsJoin` (`check_calls.vl`) declines a callee whose body ends in a value `if`. A
`return if` got neither. The walk yielded the `if` as one value, and the decline read only a
body's last statement. So the place's judge followed the `if` into both arms and refused the
two results. The walk now walks a returned value as a tail. The decline reads the body's tail
value through `lambdaBodyTail`, which takes a last `return`'s argument. With only the walk
changed, the both-`i32` spelling `pick` stops running, so the two changes go together.
