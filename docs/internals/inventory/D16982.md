### D16982 — two calls of a maker joining record literals, each in a different value join delivered at a declared record, leave the maker unbuilt there and build invalid wasm

**closed 2026-11-18 by lane F2 · runs, prints `1` · was check-clean invalid wasm, clause 1 · closed by letting a record-literal arm of a value join leave the join's call arms to land where the join is delivered (`recJoinLandingIn`, `check_fit_rules.vl`): a literal delivered at a record is built there, so every call site of the maker lands at `K` · pin: `tests/cases/records/maker-calls-in-two-joins-at-declared-record.vl` · filed 2026-11-18 against master `47ed1c966` by lane F2**

#### Mechanism

`mk` is built at `K` (D15719) only where every call site lands there (`recSitesLandAt`); one site
skips the check. A site inside a value join landed only through `recJoinLandingIn`, which answered
-1 for any join with an arm that is not a call, so a `{ j: null }` arm left the site unlanded and
`mk` kept its union-box result while the joins took `K`. A record literal delivered at `K` is built
there, so it no longer stops a call arm landing. A call also read at its own type beside the build
now meets the checker's "built as K … one value cannot be both" refusal instead of invalid wasm.
