### D12602 — a literal-discriminant `==` on a member path inside a generic body is not seen by the pin's re-ask of the arm's reads

**loud check reject · clause 2 · CAPABILITY, the program is type-valid · open · `` field 'v' is not on every member of A | B `` at the call, from the D1433 pin re-ask in `check_access.vl` · found by lane L3 closing [D12473](D12473.md), the direct face · present on master `1a747b413` · filed 2026-10-24 against master `1a747b413`**

Repro:

    type A = { k: "a", v: i32 }
    type B = { k: "b", s: string }
    const x: { h: A | B } = { h: { k: "b", s: "bee" } }
    function F<Z>(z: Z) { if z.h.k == "a" { print(z.h.v) } else { print(z.h.s) } }
    F(x)
    // vl check: field 'v' is not on every member of A | B (the body of `F` at the call's argument types)

#### Mechanism

In the body `z.h` is a hole, so `pushDiscrimParentFact` has no member list to filter and
pushes no fact for `z.h.k == "a"`. The arm's read `z.h.v` is then a nested read off a
type-variable root at a place no narrowing touches, so it is recorded and re-asked at the
pin, where `z.h` is `A | B` and nothing narrows it. The `is` spelling pushes a fact on the
hole and runs. A close needs a deferred discriminant remainder, a derived hole resolved at
the pin as `HD_GNOT` is. The checker's `substHoleTyReal` and emit's `holePinReadAt` would
both resolve it, and so would the instance's `pushDiscrimNarrow`.

#### Ablation

| spelling | outcome | needed? |
| --- | --- | --- |
| `if z.h is A` | runs, prints `bee` | **yes**: the `==` discriminant |
| the direct face, `x.h.k == "a"` outside a generic | runs, prints `bee` | **yes**: the generic body |
| `z: { h: A \| B }` annotated | runs | **yes**: the hole |
