### D3912 — calling a generic's returned function value as a statement inside a generic caller is refused at emit

**closed 2026-10-09 by lane SC · runs · was loud emit reject · found by D3909's position matrix (`ret__*`) · filed 2026-10-09 against master `097937914` · pins: `tests/cases/generics/generic-returned-function-called-as-statement.vl`**

Repro:

    function b<U>(y: U) { print(y) }
    function a<T>(x: T): (t: T) => void {
      b
    }
    function pr<T>(x: T) { a(x)(x) }
    pr("s")
    // vl check: rc 0.  vl build: a function-value call statement yields a value the tail-value ladder did not claim

Want:

    s

#### Mechanism

`a(x)(x)` is a value call whose callee is itself a call. `cloCallSigKey` keyed it off the callee's
recorded type, which inside a generic caller's instance is still `(T) => void`, so the statement
found no `$fnsig` and refused. Closed: such a callee is keyed by the declared return type of the
named function it calls (`calledFnDeclRetSigKey`), which an instance spells concretely. This rung
answers only after every other resolver has declined.
