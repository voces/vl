### D3912 — calling a generic's returned function value as a statement inside a generic caller is refused at emit

**closed 2026-10-09 by lane SC · runs · was loud emit reject · found by D3909's position matrix (`ret__*`) · filed 2026-10-09 against master `097937914` · pins: `tests/cases/generics/generic-returned-function-called-as-statement.vl`, `tests/cases/generics/generic-returned-function-called-for-its-value.vl`, `tests/cases/generics/returned-function-call-chain-through-shadowing-parameter.vl`**

Repro:

    function b<U>(y: U) { print(y) }
    function a<T>(x: T): (t: T) => void {
      b
    }
    function pr<T>(x: T) { a(x)(x) }
    pr("s")
    // vl check: rc 0.  vl build: a function-value call statement yields a value the tail-value ladder did not claim

Want:

    s

#### Mechanism

`a(x)(x)` is a value call whose callee is itself a call. Inside a generic caller's instance both
calls kept the template's recorded types, so the statement found no `$fnsig` and refused.
Closed in the monomorphizer (`monoTypeCallOfCall`, `monoCallValueTy`): once the inner call names
its instance, the callee call is typed at that instance's declared return and the outer call at
that function type's result, at any depth (`a(x)(x)(x)`). The emitter then keys the call from
the callee's own type. A parameter or local named like the module function is not resolved to
it, so a call through a shadowing parameter keeps that parameter's type (D3922).
