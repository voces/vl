### D3046 — a hole instance's literal held in a list literal is read back from a list whose element row is another declared record

**closed 2026-11-01 · runs, prints `9` · was check-clean invalid wasm · the list's element row was the first declared record whose field names matched (`shapeNominalRowOf`'s strict field-set rung), while the literal was built at another; one-row step 3 removed the field-set rungs, so the list and its element agree · the #3263 review's `w/o_*.vl` · found reviewing [D3032](D3032.md) · filed 2026-09-28 against master `3a71bb1f9`**

Repro:

    type Xf = { k: f64 }
    type Xi = { k: i32 }
    function h(x) {
      const o = { k: x }
      const xs = [o]
      return xs[0].k
    }
    print(h(7) + 2)
    // vl check: rc 0.  vl run: invalid module, inside `h`

Want:

    9

#### Mechanism

The list literal names its element row without the instance ([D3036](D3036.md)'s reader), so
`[o]` keys a list of the first row whose field names match, while `o` itself is built at
another. D3032 does not mint a row for a literal bound to a name a list literal reads, which
keeps the two agreeing where no declared row fits the pin exactly; where one does, the literal
takes it and the list does not.
