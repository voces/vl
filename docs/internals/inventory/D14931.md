### D14931 — a `slice` of a list of two generics, one never called, runs only through `monoPinListElems`

**closed · the tag path reads a `slice` of a list of a set's ids as a holder read (`ftSlotOp`), so `[id, same]` is tagged with the set `{id, same}`, its copy holds the same ids, and `same` is instanced through the set's dispatch with `monoPinListElems` cut · fixture `tests/cases/closures/generic-list-slice-copy-holds-the-set.vl` · was runs today and must keep running, through `monoPinListElems` alone · step 4 (γ) family D · filed 2026-11-02 against master `ea74167bd`, closed 2026-11-02 against master `4f1080db`**

Repro:

    function id<T>(x: T): T { x }
    function same<T>(x: T): T { x }
    const gs = [id, same]

Want:

    2

#### Mechanism

The copy `gs.slice(1)` makes `same` a value something may reach, while no call fixes its type:
`gs[0](2)` reaches only `id`. The flow-table pin `monoPinListElems` reads closes the source's element
slot at the one call's `(i32) => i32`, and every element, `same` too, is instanced there. Without
it nothing instances `same`. `slice(0)` and a spread copy run with the pin cut.
