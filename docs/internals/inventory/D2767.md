### D2767 — two same-typed callbacks through one un-annotated lambda parameter over a captured list

**closed 2026-09-27 with [D2749](D2749.md) — the repro RUNS and prints `3` then `0` · was check-clean invalid wasm · the #3207 review · filed 2026-09-26 against master `876559d2f`**

Repro:

    type Circle = { r: i32 }
    type Sq = { s: i32 }
    type Shape = Circle | Sq
    function sum(xs: Shape[]): i32 { xs.length * 3 }
    function tot(xs: Shape[]): i32 {
      let t = 0
      t
    }
    function f() {
      const out = [{ r: 3 }]
      const ap = (g) => g(out)
      print(ap(sum))
      print(ap(tot))
    }
    f()
    // vl check: rc 0.  vl run: invalid module inside `f`, expected i32, found (ref $type)

#### Mechanism

The same as [D2749](D2749.md), in the union spelling: `ap` is specialized once per callback,
and the second specialization's closure environment types the captured `out` as `i32`. D2749's
witness has no union at all, so the union and D2748's destination are not ingredients.
