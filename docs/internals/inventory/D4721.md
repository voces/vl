### D4721 — a nullable record element read from an un-annotated record field's list cannot be compared with `null`

**closed 2026-10-14 — the witness prints `true` · the field's list companion keeps `| null` when the literal holds a `null` (`anonFieldElemName`), and an inline record element finds its struct row by field set when the arena index and the literal's row disagree (`rlElemLitStructRow`, `structIndexOfExpr`) · fixtures `tests/cases/objects/anon-field-nullable-record-list.vl` and `tests/cases/closures/nullable-elem-closure-field-array-lambda-sig-twin.vl`, matrices `nullable-inline-record-list-field.matrix.vl` and `nullable-inline-record-list.matrix.vl` (28 un-annotated cells each refused before, 64 of 64 graded run) · also closes [D2642](D2642.md), [D2729](D2729.md) and [D3998](D3998.md) · was loud emit reject · clause 2 · found writing D4688's second delivery position · filed 2026-10-14 against master `a254c3da4`**

Repro:

    const w = { f: [{ x: 1 }, null] }
    const e = w.f[1]
    print(e == null)
    // vl run: emitProgram: struct equality is not supported yet

Want:

    true

#### Mechanism

Two producers. The record field's element key was the literal's struct row name with the `null`
dropped, so the element slot was not a nullable niche and `==` was read as record equality. And
the filed claim that the same list bound to a local runs was false for an inline record: the
local list refused too, because the element's arena index differed from the index the literal's
anonymous row recorded, so the exact lookup missed and the node route read a nullable as a
non-record. A declared `type P` hid both behind its name.
