### D16273 — a `for` over a list literal holding only an empty list literal is refused at emit

**closed 2026-11-16 · runs, prints `0` · was loud emit reject, `a list literal's element type gives its list no element rep` · clause 2 · fixed in check_statements.vl: `checkForInNode` notes a list literal it iterates whose element holds an empty list (`recOpenHolePath`) as pending, so scope close settles that list's element as it does for a binding of it (`flushUninferred`); a write in the body still decides it first · pin: `tests/cases/loops/for-in-list-literal-of-empty-lists.vl` · the expression-position spellings (`print([[]].length)`, `[[]][0].length`) still refuse, as before · found closing [D2508](D2508.md) · filed 2026-11-14 against master `495c1ff80`**

Repro:

    for x in [[]] { print(x.length) }
    // vl check rc 0.  vl run: emit error: a list literal's element type gives its list no element rep

Want:

    0

#### Mechanism

The outer literal's element is the inner literal's list type, whose element is a hole.
[D2508](D2508.md)'s close defaults only an outermost element hole (`defaultReadOnlyContainer`); a
binding of the same literal is noted pending and its nested hole defaulted at scope close, which the
iterated literal was not.
