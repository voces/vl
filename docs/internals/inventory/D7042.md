### D7042 — a module global typed `K | (L | i32)` is initialised with a string box where its slot holds an i32

**closed 2026-10-19 by lane L6 · runs, prints `a` · was check-clean invalid wasm · clause 1 · a union whose own nominal key has no row is a union box when the sequence of its canonical members keys one, and a type with a repeated member declines · pins: `tests/cases/unions/litunion-nested-union-arm-module-global.vl` (both nestings, a string and an i32 initialiser, a module `let` reassigned, a function local) · found by lane L6 step 3's ablations · present on master `e55677bd8` · filed 2026-10-19 against master `6ca1ebc5c`**

Repro:

    type K = "a" | "b"
    type L = "x" | "y"
    const a: K | (L | i32) = "a"
    print(a)
    // vl check: rc 0.  vl run: invalid module, type mismatch: expected i32, found (ref $4); $4 is `string`

Want:

    a

#### Mechanism

The validator reports that the module's top-level code stores a `string` reference where it
expects an `i32`. So the global's slot takes the `i32` rep while its initialiser `"a"` is built as
a string. The same declaration as a function local runs. So does the flat spelling `K | L | i32`
at module scope. The defect is therefore in the module-global initialiser's reading of the nested
member, not in the type's rep. A probe located it. The arena shares one type between `K | (L | i32)` and the canon
spelling `string | i32`, and the rep table minted the box row under the canon spelling. The
nominal key of `K | (L | i32)` has no row, so `isUNameABAt` answered "not a union box" at the
global's slot while the initialiser's own path built the box. The question now also asks for a
row keyed by the type's canonical member sequence (`unRowOfCanonMembers`). It declines when the
type repeats a member, because a positional member set like `T | string` at `T := i32 | string`
is never folded onto the deduplicated row.

#### Grading list

The same global read through `r<T>(x: T): { v: T | K }`, `r<T>(x: T): { v: T }` and
`r<T>(x: T): T | K` is invalid the same way, as is an annotated `{ v: K | L | i32 }` field
initialiser from it. All of them run at the close and are in the pin.
