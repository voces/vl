### D3537 — a record type that declares one field twice is accepted, and a literal at it is refused naming an empty field

**closed by ruling · now a loud check reject at the repeated field name · owner ruling 2026-10-03: D3484's ruling applies to declarations, so a record type declaring a field twice is a check error, in a `type` declaration, a generic one, a union arm, an intersection, a nested record and an inline annotation alike · was accepted, with a literal at the type refused as `this object literal sets , which P does not declare` · fixture `tests/cases/structs/error-duplicate-field.vl` · found 2026-10-03 while closing D3484 · filed and closed against master `f6e17953b`**

Repro:

    type P = { a: i32, a: i32 }
    const p: P = { a: 1 }
    print(p.a)
    // vl check: error [1:20] field `a` is declared twice in this record type (first at 1:12)
    // was: this object literal sets , which P does not declare: ...

#### Mechanism

A record type's field list was not compared with itself, so `type P = { a: i32, a: i32 }` laid
out two fields named `a`, a literal giving `a` once failed the literal-shape check against the
second slot, and `objDroppedFieldList` rendered the mismatch as an empty name. With no literal
at the type the declaration checked clean. Both record-type field loops in the parser (the
`type X = { … }` body and `parseTypeAtom`'s inline record, which every annotation, union arm
and type argument reads) now note each field name; a repeat mints inert anchors on the two
name tokens and records the pair in `recDupField`, and `checkProgramPass` raises
`recDupFieldErrs` from it as a type error spanning the repeated name. Method members of a bound
are not fields and are not compared. A record type takes no quoted keys, so that spelling is a
parse error before any comparison.

#### Ablation

| ingredient changed | outcome before | needed? |
| --- | --- | --- |
| no literal at `P` (a parameter `p: P` only) | check rc 0, runs | the declaration alone was accepted |
| `type P = { a: i32, a: string }` | check rc 0 with no literal | the two fields need not agree |
| a union arm `{ k: "x", a: i32, a: i32 }`, only the other arm built | check rc 0, runs | no |
| `type P = { a: i32 }` | runs | control |

#### Grading list

Every position now refuses with one error at the repeated name: `type` declaration, generic
`type Box<T> = { v: T, v: T }`, union arm, `{ … } & { … }`, a record nested in a field type,
a multi-line body, a parameter, return and binding annotation, a type argument, and a type
declared in an imported module.
