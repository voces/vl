### D16475 — a binding of the tested place's name in a block nested in a deep `is` arm is not scoped by the rewrite's substitution

**open · loud check reject · `a deep `is` arm that rebinds or writes `r` inside an expression is not supported yet — write it as its own statement, or bind the converted value first` · clause 2 · found closing [D16474](D16474.md) · filed 2026-11-15 against master `314123b83` · fixture `unions/error-deep-is-arm-shadows-receiver-in-expression.vl` · bucket (f), a local fix: D1190's scoped substitution, the shadowing face (by ablation, 2026-11-15)**

    print(d(["a", "b"], true))
    // vl check: a deep `is` arm that rebinds or writes `r` inside an expression is not supported yet

Want:

    6

#### Mechanism

The deep `is` rewrite ([D1190](D1190.md), `jwSubstScoped`) treats a binding of the root's name as
the end of the narrowing. A binding in the arm's own block does end it for the rest of the arm.
But a binding in a block nested inside an expression, or in an `if` arm within the arm, shadows the
place only to the end of that block. The rewrite has no scope there: in an expression it refuses,
and in an `if` arm it stops substituting for everything after the `if`. In the second case the
re-check then reads the raw `Json` place where the program reads it narrowed, and refuses it
loudly (`field 'length' is not on every member of Json`).

#### Ablation

| ingredient changed | outcome | needed? |
| --- | --- | --- |
| the inner binding named other than `r` | runs | **yes** |
| the inner block an `if` arm statement, with `print(r.length)` after the `if` | refuses at the re-check: `field 'length' is not on every member of Json` | no (any nested block) |
| a bare nested block `{ const r = 5 … }`, with `print(r.length)` after it | refuses at the re-check | no |
