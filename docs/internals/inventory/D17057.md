### D17057 — `??` over a global read from a map of hole functions, after a narrowed read of it, is refused by emit as an unsupported nullable value

**loud emit reject · found by lane IR-M1 on the coordinator's missing-key test of IR-N9's `mv4` cell · filed 2026-11-22 against master `025ee3dda`**

Repro:

    function inc0(a) { return a + 1 }
    function dbl(a) { return a * 2 }
    let b2 = [inc0, dbl]
    b2 = [dbl]
    const m4 = Map()
    m4["k"] = [inc0, dbl]
    const mv4 = m4["k"]
    if mv4 != null {
      const v4 = mv4
      print(v4.map((f) => f(3))[1])
    } else { print("none") }
    const got = mv4 ?? [inc0]
    print(got[0](3))
    // vl check: no errors. vl build: "`??` over this nullable value is not supported yet —
    // narrow it first" at the `??`.

Want:

    6
    4

#### Mechanism

The `??`'s left side is `mv4`, a global whose cell kind is the non-null `reflist` (D17056) while
its checked type is nullable. Emit's coalesce finds no arm for a nullable value held at a
non-null cell and refuses with a sentence that names a mechanism, not a contract: the same
spelling without `b2`'s reassignment, or with annotated functions, is accepted.

#### Ablation

| ingredient | outcome | needed? |
| --- | --- | --- |
| `b2` reassigned (`b2 = [dbl]` removed) | invalid wasm, D17055 | **yes** |

| the functions un-annotated (`a: i32` on both) | prints `none` then `4` with the key missing | **yes** |
| the key present (`m4["absent"]` instead) | still refused | no |
