### D1622 — a NULLABLE closure returned through two inferred hops has no inferred-return kind

**closed · filed 2026-09-05 against master `ef92ad0c` · closed against `ca9645cc`**

`retKindPri` grew a `nulclosure` tier and `exprNulClosure` an arena rung. All 14 cells of
this row's grid run; the 228 `tests/cases` modules that exercise an inferred nullable
return behave identically, and `emit_sections` needed no branch after all.

Repro:

    function mk(): ((i32) => i32) | null {
      return (n: i32) => n + 1
    }
    function deliver() {
      return mk()
    }
    const v = deliver()
    if v != null { print(v(54)) }
    // vl check: rc 0.  vl run: emitProgram: bare null needs a struct-typed context

#### Mechanism

The inferred-return machinery carries "returns a closure" on TWO channels and neither could
say `nulclosure`. `fnReturnsClosure` is a BOOLEAN, and its consumer in `emit_sections` emits
`fbValtype("closure", -1)` — the non-null `(ref $cloStruct)`, which cannot hold the value.
`fRetKind` could carry the kind, but `retKindPri` assigned `nulclosure` no tier, so
`criSetRetKind(i, "nulclosure")` was refused by its own strict `>` and the slot stayed `"i32"`.

D1620's arena rung deliberately does not reach here: `nodeTyIsFunc` is structural and a
`TyNullable` over a `TyFunc` is excluded by construction, which is what keeps the non-null rep
from claiming a nullable value and emitting a slot that cannot hold `null`.

**`emit_sections` needed NO branch, and that premise was worth testing rather than believing.**
`fbValtype` already has a `"nulclosure"` arm — `(ref null $cloStruct)`, slot ignored — so the
existing `else if fn.fnRet < 0` arm feeds it the inferred kind and lowers correctly the moment
the kind can be recorded.

**The read side needed the second half.** With the tier alone, the ANNOTATED receiver ran and
the un-annotated one still refused: `exprNulClosure`'s `Call` arm reads the callee's
ANNOTATION (`nulCloFlag(cfn.fnRet)`), which an inferred return does not have. The arena does
(`nodeTyIsNulFunc`), so the read rung is the same structural test the write side uses — the
two cannot disagree about a niche they both read from one place.

| 13 | `i64`, `f64`, `f32`, `nulnone` | **D1567** — the `null` type shares the top: every value is a bare `null` or something else, never both |

`nulclosure` joins tier 12 for both of that tier's reasons at once. It must **outrank** the
lower tiers for D937's reason — a niche the name ladder settled must not be lowered by a later
cheap write — and it **shares** with `nulmap` and `nulstr` for D1562's, since a return is one
nullable niche and never two. It is below tier 13 so that a return whose every value is a bare
`null` still settles as `nulnone` (D1567's ruling), which cell `n14` of the grid pins.

The non-null `closure` has no row in this table and gains none: its channel is
`fnReturnsClosure`, a boolean read AHEAD of the inferred kind in `emit_sections`, so the two
arms cannot both claim one return.
