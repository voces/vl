### D1622 — a covariant list delivered to a struct field, a nested element or a return has no claim arm, so an unrelated write leaves the write state unknown and the emitter builds an invalid module

**check-clean invalid wasm (`type mismatch: expected (ref $type), found (ref $type)`, exit 70) · filed 2026-09-05 against master `764e1a2cb` · open · found by the D1610/D1611 grid, which UNMASKED it rather than caused it · 0 corpus cells**

Repro:

    type Circle = { r: i32 }
    type Sq = { s: i32 }
    type Shape = Circle | Sq
    type Box = { xs: Shape[] }
    function f() {
      const other: Shape[] = [{ r: 1 }]
      other.push({ s: 2 })
      const a: Circle[] = [{ r: 7 }]
      const b: Shape[] = a
      const sf: Box = { xs: b }
      print(sf.xs.length)
      print(other.length)
    }
    f()
    // vl check: rc 0.  vl run: exit 70, invalid module.
    // Drop `other` and its push and the same program runs and prints 1.

#### Mechanism

`cwClaimed` is a whitelist: every occurrence of an alias-set name must be a binding
initializer, either side of an assignment, a call argument, a member-access object or an index
array, and anything else leaves the set unclaimed and the write state `2` (unknown). A value
delivered to a STRUCT FIELD (`{ xs: b }`), to a NESTED ELEMENT (`[b]`) or out through a RETURN
has no arm, so any unrelated write in the program — which is all `cwProgramHasWrite` asks —
drops the state to `2`. `rlWidenAllowed` then declines the element-converting copy, since only
a definite 0 overrides the rep-scoped answer, and the emitter goes on to build a module the
engine refuses instead of failing loudly. The whitelist is the right shape (a form nobody
thought of must not read as safe); what is missing is an arm per delivery, and for the return
arm the alias closure has to follow the call result, which today roots at nothing.

#### Ablation
