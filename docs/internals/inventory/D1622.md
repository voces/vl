### D1622 — a NULLABLE closure returned through two inferred hops has no inferred-return kind

**loud emit reject · 1 cell of the `d1620` grid · filed 2026-09-05 against master `ef92ad0c`**

Repro:

    function mk(): ((i32) => i32) | null {
      return (n: i32) => n + 1
    }
    function deliver() {
      return mk()
    }
    const v = deliver()
    if v != null { print(v(54)) }
    // vl check: rc 0.  vl run: emitProgram: bare null needs a struct-typed context

#### Mechanism

The inferred-return machinery carries "returns a closure" on TWO channels and neither can say
`nulclosure`. `fnReturnsClosure` is a BOOLEAN, and its consumer in `emit_sections` emits
`fbValtype("closure", -1)` — the non-null `(ref $cloStruct)`, which cannot hold the value.
`fRetKind` could carry the kind, but `retKindPri` assigns `nulclosure` no tier, so
`criSetRetKind(i, "nulclosure")` is refused by its own strict `>` and the slot stays `"i32"`.

D1620's arena rung deliberately does not reach here: `nodeTyIsFunc` is structural and a
`TyNullable` over a `TyFunc` is excluded by construction, which is what keeps the non-null rep
from claiming a nullable value and emitting a slot that cannot hold `null`. Serving this row
means giving `retKindPri` a `nulclosure` tier and the `emit_sections` arm a branch for it —
a change to a priority table whose ordering carries D937's and D1562's rulings, and therefore
its own row rather than a rider.

#### Ablation

Every row is `vl check` rc 0.

| ingredient removed | outcome | needed? |
| --- | --- | --- |
| the second hop (`const v = mk()` direct) | runs, 55 | **yes** |
| the second hop, receiver annotated | runs, 55 | **yes** |
| the `\| null` (a plain `(i32) => i32` inner) | runs, 55 | **yes** |
| the annotation on the receiver | same refusal | no |

Needed: the nullable rep AND the second inferred hop. One hop at the nullable rep runs, and
two hops at the non-null rep run since D1620.

#### Grading list

* The one-hop nullable control (`const v = mk()`), which must keep running.
* The non-null two-hop chain, which D1620 closed and this must not disturb.
* `fbValtype("nulclosure", -1)` at the inferred-return arm: a kind without a slot its
  consumer understands swaps one refusal for another, which is the lesson
  `tests/cases/closures/capture-unannotated-nullable-reps.vl` records for the capture ladder.
