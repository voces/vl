### D15214 — a function's record result whose nullable nested record field a wider delivery widens, beside an own-type binding, is built at its own record

**closed 2026-11-04 by lane destringify, runs, prints `4` · was check-clean invalid wasm, clause 1 · `recNullWidenedAt` recursed into a nested record field only where the destination field was not nullable; it now reads the nullable field's inner record the same way, so `mk` is built at `K` for both calls and `y` reads its own row back from `K`'s storage · fixture `soundness/nullable-nested-record-built-wider-beside-own-binding-runs.vl` · named set `d15214-nullable-nested-field` · a literal then written into `y.j` is D15246; a number widened behind `| null` is D15247 · found grading the nested-field defect step5 handed the destringify lane · filed 2026-11-04 against master `b4bdefff0`**

Repro:

    type J = { f: i32 | null }
    type K = { j: J | null }
    function mk() { { j: { f: 4 } } }
    const _k: K = mk()
    const y = mk()
    print(y.j.f)

Want:

    4

#### Mechanism

`mk` has two call sites, `_k: K` and `y`, so the record solve builds it at `K` only where every
field of `mk`'s own type reads back from `K`'s storage (`recNullWidened`, check_fit_rules.vl).
Field `j` is `{f: i32}` in `mk`'s own type and `J | null` in `K`, a nullable record, which that
rule does not judge; the build is dropped and `_k` is delivered a record of `mk`'s own type.
