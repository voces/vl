### D2887 — an index read of a union narrowed to its `readonly f64[]` member is invalid wasm

**closed 2026-09-27 — the repro RUNS and prints `1.5` · was check-clean invalid wasm, the same on master `829bd497c` · closed by giving a view the value-atom code of its list (`valueAtomKind` peels the `readonly` marker) and by an `is readonly T[]` complement that also rules out the list spelling the member set carries (`msSubAtomOrView`); D2874's list-union rewrite now takes a readonly member · fixture `tests/cases/unions/readonly-list-member-narrows-and-reads.vl` · found by the #3229 review · filed 2026-09-27 against master `8e10ef58b`**

Repro:

    function mk(b: boolean): readonly f64[] | string[] {
      if b { return [1.5] }
      ["s"]
    }
    const w = mk(true)
    if w is readonly f64[] { print(w[0]) }
    // vl check: rc 0.  vl run: invalid module — expected (ref null $type), found (ref $type)

Want:

    1.5

#### Mechanism

A view and its list are one rep, and the box tags the member with the list's atom (8 for
`f64[]`). The narrowed read asked `valueAtomKind("readonly f64[]")`, which answered -1, so the
read took no unbox and pushed the box itself where the list wrapper belonged. The `else` and
early-return complements failed the same way from the other side: the union's member set spells
the view as its list, so subtracting `readonly f64[]` cleared no bit and the survivor stayed the
whole box. `readonly S[]` over a record element already read through the ref-array arm and ran.
