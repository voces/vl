### D3527 — `==` or `!=` against `null` over a union of numbers is refused as a member-by-member numeric comparison

**closed 2026-10-03 — the witness prints `false` then `true` · was a loud check reject, clause 2 · found by lane LJ's grid (the `i32`/`f64` pins of the `eqnull` and `neq` readers, under a kept-apart lambda join later withdrawn from #3344) · filed and closed against master `331f5e998` · fixture `tests/cases/generics/numeric-union-null-test.vl`**

Repro:

    function pick(k: i32): i32 | f64 { if k == 0 { 3 } else { 2.5 } }
    const x = pick(1)
    print(x == null)
    print(x != null)
    // vl check on master: "operator '==' is not defined for i32 | f64 and null"

Want:

    false
    true

#### Mechanism

A union of numbers dispatches `==` and `!=` member by member (`numUnionBinTy`, and
`binOpDefinedFor` at a pin), and a member paired with `null` has no numeric form, so the test
was refused. `x == null` over `i32` alone, or over `i32 | string`, is a nullness test and runs.
Closed by taking a comparison against `null` out of the numeric dispatch (`nullTestOp`), in
the body and at the pin, so it falls to the ordinary null test.
