### D16277 — a call's record whose field is a list of nullable references, listed where the record's storage builds it, emits invalid wasm

**closed · runs, prints `1` · was check-clean invalid wasm · `type mismatch` · found ablating [D16392](D16392.md)'s list-of-nullable-records spelling · filed 2026-11-15 against master `518cdc66d` · closed 2026-11-15 by lane N with D16392: the copy of a call's record admits a reference element into its `| null` (`recListElemCopies`) · matrix `call-fresh-record-into-nullable-ref-field.matrix.vl`**

Repro:

    type L = { f: ({ g: i32 } | null)[] }
    function mkl() { return { f: [{ g: 4 }] } }
    const wideL: L = mkl()
    const ls = [mkl()]
    print(ls.length)
    // vl check: rc 0.  vl run (filed): invalid module, type mismatch

Want:

    1

#### Mechanism

`wideL` builds `mkl`'s record at `L`, so `[mkl()]` is built there too and the call's result is
copied in. The copy rule for a list element boxed a scalar into its `| null` but had no arm for
a reference (a record, list, function or map) into its nullable. With no copy, the call's result
reached the list in its own storage, which the checker never refused, so the module did not
validate. This is D16392's mechanism at a position with no refusal.
