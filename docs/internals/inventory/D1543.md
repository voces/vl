### D1543 — an anonymous object literal whose STRUCT field is not itself a LITERAL got no row: `const box = { item: r }` is `ref valtype with no interned shape`

**closed — now runs · was `loud emit reject` at `vl check` rc 0, in three sentences (`ref valtype with no interned shape`, `object literal matches no union variant`, `object literal field count does not match struct`) · clause 2 · found 2026-09-03 minimising two day-one sampler cells that turned out to be one mechanism with the pinning, the nullability and the `type` declaration all SCENERY · fixture `tests/cases/objects/anon-shape-nonliteral-struct-field.vl`**

Repro (three lines, no functions, no annotations):

    const r = { name: "ada", n: 3 }
    const box = { item: r }
    print(box.item.n)
    // vl check rc 0; vl run -> emitProgram: ref valtype with no interned shape
    // want: 3

#### "No row minted" or "a row the read site cannot reach"?

**Both, in that order, and the second is the cause.** The struct row for `{name, n}` EXISTS —
`r`'s own literal minted it, and in the sampler's spelling `type Rec` declared it. What was
missing is the reverse lookup from the field VALUE's recorded type to that row; with no
lookup, `anonFieldCode` returned -1 for the field, `collectAnonShapes` requires a code for
EVERY field, and so the OUTER literal got no row minted at all. Reporting only the second
half ("no row for `{item: …}`") names a symptom; the fix is in the lookup.

#### Mechanism

Measured, not read off the ladder — the first two readings of it were wrong. Probing every
return of `anonFieldCode` with an Ident-scoped `emitFail` (an unscoped one reports the FIRST
call in the program, which is the `name: "ada"` field, and says nothing about this one):

    PROBENAME code=-1 tn={name: string, n: i32}

`anonFieldCodeSyn` has an `ObjLit` arm and no arm for an `Ident`/`Call`/`Member`, so the
syntax half declines. `fieldCodeOfTy` has **no `TyObj` arm** — deliberately, its own header
says so. That leaves the NAME ladder, which renders the value's type and codes the
*spelling*; a struct value renders STRUCTURALLY (`{name: string, n: i32}`) even in the
`const ann: Rec = …` spelling, and `fieldCodeOfSpelling` has no code for an inline object
shape. `c` is -1, the mint's `ok` goes false, no row.

Two changes, both keyed to that:

* `anonFieldElemName`'s code-15 arm falls back from `structIndexOfObj` (literal-only) to the
  value's TYPE — the declared name first (`nodeTyCanonObjName` → `structIndexByName`, nominal
  identity the arena cannot recover), then the field-set match (`structRowOfObjFieldSet`).
  Same two rungs, in the same order, that `structIndexOfExpr`'s Call fallback already uses.
* `anonFieldCode` admits code 15 from a declining name ladder **only when that companion
  answers** — the bargain `anonCodeIsSelfContained`'s header names for a code that needs a
  companion, paid rather than relaxed.

#### Residue

The NULLABLE face does not close with it — see [D1544](D1544.md). `{ item: mkMaybe() }` over
a `Rec | null` still refuses, and it is not for want of the code: `fieldCodeForMatch` folds a
nullable-over-struct onto the same code 15 and the peeled companion was built here and does
not clear it, so the remaining rung is downstream of the mint.
