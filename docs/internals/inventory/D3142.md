### D3142 — a hole's field function bound from an inline record literal argument is called with no function type, so `true` prints as `1`

**check-clean silently wrong · clause 1 · found by lane FF beside D3117 · the same on master `07d414042` · filed 2026-09-29 against master `07d414042`**

Repro:

    function F(z) {
      const g = z.f
      print(g())
    }
    F({ f: () => true })
    // PRINTS 1

Want:

    true

#### Mechanism

D3117's close reads the bound callee's function type from the instance's hole binding. When
the argument is a record literal written at the call, the binding is the literal's own checked
type, whose function field the checker typed in the hole's context as another hole
(`{f: _}`), so there is no function type to read. An `f64` or `string` field is refused at
emit with `a function-value call has no interned signature`, the loud face of the same gap.

#### Ablation

| ingredient changed | outcome | needed? |
| --- | --- | --- |
| `const r0 = { f: () => true }` then `F(r0)` | prints `true` (D3117) | **yes** (the literal argument) |
| `print(z.f())`, no binding | prints `true` | **yes** (the bound value) |
| field `() => 2.5` | loud emit reject, no interned signature | no (the loud face) |
| `function F<Z>(z: Z)` | prints `true` | **yes** (the hole) |
