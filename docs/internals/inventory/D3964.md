### D3964 — a written `let` of a generic function is refused when the generic was already instanced at another type by an unrelated call

**loud emit reject · clause 2 · found by the D3960 matrix (`p_shadow_inner_let`) · filed 2026-10-10 against master `eb81bdd89`**

Repro:

    function inner<U>(u: U) { print("I"); print(u) }
    function main() {
      let k = inner
      k = inner
      inner(true)
      k(7)
    }
    main()
    // vl run: emitProgram: the reassigned function binding `k` is called at more than one argument type

Want:

    I
    true
    I
    7

#### Mechanism

`k` is called at one type only. The refusal in `compiler/emit_mono.vl` fires when a call through a
written binding mints a NON-FIRST instance of the generic, and which instance is first depends on
source order: `inner(true)`, a direct call, mints the first, so `k(7)` mints the second and is
refused although nothing else calls through `k`. An inner binding of the same or another name
seeded with `inner` and called at `boolean` does the same.

#### Ablation

| ingredient changed | outcome on master | needed? |
| --- | --- | --- |
| `inner(true)` after `k(7)` | runs | **yes** |
| `k` not written | runs | **yes** |
| `k(true)`, the same type | runs | **yes** |
