### D6020 — a hole function or hole lambda through a hole parameter, into one binding called at two types, gets no slot per type

**closed 2026-10-17 by lane L1 · runs, prints `3 w` · was loud emit reject · clause 2 · a hole function refused as a value asks the split plan for the binding an identity call hands it to, so `q` takes a slot per type as two bindings did · pins: `tests/cases/functions/generic-fn-value-hole-identity-binding-at-two-types.vl` (also inside a function, a never-written `let`, and handed on to two holes) · the lambda spelling is filed as [D6201](D6201.md) · found closing [D6001](D6001.md) · the same on master `bb12c651a` · filed 2026-10-17 against master `bb12c651a`**

Repro:

    function fw(f) { return f }
    function id(x) { return x }
    const q = fw(id)
    print(q(3))
    print(q("w"))
    // vl check: rc 0.  vl run: emitProgram: cannot take the generic function `id` as a value — a function value carries ONE signature, and parameter `x` is un-annotated (it would default to i32)

Want:

    3
    w

#### Mechanism

From the ablation only. D5664 gives a binding of `fw(k)` a slot per type when `k` declares
its type parameter, and a direct alias `const q = id` runs at two types; a hole function
handed through `fw` has neither. With a lambda in place of `id` the refusal is
`monomorphize: unsupported argument type for f in a call to fw`, and it stays even with one
binding per type, so the lambda spelling also lacks the per-binding pin that `id` has.
