### D14490 — an `if` or `match` tail that assigns a number literal to a wider cell returns the cell, not the checker's `i32`

**closed 2026-10-27 by making `armAssignTarget` (emit_local_scope.vl) decline a number-literal right side, as `fnAssignRetTarget`'s straight tail already did · was runs but wrong value, clause 1 · regressed by #4964 (`1810bc326`), which deleted the literal copy that had hidden it · filed 2026-10-27 against master `1810bc326` · pins: `tests/cases/expressions/assign-literal-tail-wider-cell.vl`**

Repro (runs, prints `2`):

    let g: f64 = 0.5
    function arm(c: boolean) { if c { g = 5 } else { g = 7 } }
    print(arm(true) / 2)

#### Mechanism

The checker types `g = 5` at its right side's type, so `arm` returns `i32` and `arm(true) / 2`
is integer division. The emitter gives a function whose tail is an assignment the target cell
as its return (store, then re-read). #4964 taught the straight tail to decline a literal right
side, whose value is the literal at its own type. The `if`/`match` tail asks
`armAssignTarget` instead, which did not decline, so the function returned the `f64` cell and
printed `2.5`. Before #4964 a copied literal stood in the right side and the walk never saw a
literal.

#### Ablation

| ingredient removed | outcome on `1810bc326` | needed? |
| --- | --- | --- |
| the `if` (straight tail `g = 5`) | prints `2` | **yes** |
| the literal (`const v = 5`, arms `g = v`) | prints `2` | **yes** |
| the wider cell (`g: i32`) | prints `2` | **yes** |
| an odd literal (`g = 4`) | prints `2`, same as the wrong value | **yes**, to see it |

#### Grading list

Straight, `if`/`else`, nested `if`, `else if`, `match` with and without braces, labelled
block, `return` in an arm, and an arm mixing a literal with a name, over `f64`, `i64` and
`f32` cells. All are in the pin, and each agrees with the pre-#4964 seed and with the
checker's `i32`.
