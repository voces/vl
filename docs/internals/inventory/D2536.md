### D2536 — a generic wrapper whose tail calls a generic `self`-function over a generic record gets the callee's inferred non-void result at a different heap type

**check-clean invalid wasm · clause 1 · found building `std:idtable` (#3168) · filed 2026-09-25 against master `15be0d1b8`**

Repro:

    type Tbl<V> = { slots: V[], n: i32 }
    function put<V>(self: Tbl<V>, id: i32, v: V) {
      if id > 5 { self.n = self.n + 1 }
      self.slots[id] = v
    }
    function putw<V>(self: Tbl<V>, id: i32, v: V) {
      put(self, id, v)
    }
    type Tex = { w: i32 }
    const t: Tbl<Tex> = { slots: [{ w: 0 }], n: 0 }
    putw(t, 0, { w: 4 })
    print(t.slots[0].w)

#### Mechanism

`put`'s last statement is an index assignment, which yields its right-hand side, so `put` infers
a result; `putw` returns `put`'s result as its own tail. With a statement before the tail
assignment, the two instances disagree about that result's heap type: `putw` requires one
reference type and `put` returns another. `std:idtable`'s `set` ends in an `if` to stay clear of
it.

#### Ablation

| ingredient removed | outcome | needed? |
| --- | --- | --- |
| the `if` before the tail assignment | runs | **yes** |
| the generic record (`xs: V[]` parameters instead) | runs | **yes** |
| the type parameters (a concrete `Tex[]`) | runs | **yes** |
| the wrapper as an operator (`"[]="` instead of `putw`) | the same invalid wasm | no |
