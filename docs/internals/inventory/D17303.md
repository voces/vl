### D17303 — a `print` of an assignment of a `null`-returning call to an annotated `let x: null` is written as an `i32` where the value is `nullref`

**fixed 2026-11-24 · closed, runs `null` · was: check-clean invalid wasm · clause 1 · `type mismatch: expected i32, found nullref` inside `f` · found by IR-N9 grading the captured null-typed call write · filed 2026-11-24 by IR-N9 · fixed by #10004 (IR-N9): `asgYieldsNulNoneValue` (emit_classify.vl) names a `null`-typed assignment of a value `exprIsNulNone` names, and `boxOperandIsNulNone` (wasmEmit.vl) takes it, so `print` takes its `nulNone` arm · fixture `null/write-a-null-typed-call-into-a-null-binding.vl`**

Repro:

    function same<T>(v: T): T {
      return v
    }
    function f() {
      let x: null = null
      print(x = same(null))
    }
    f()
    // vl check: rc 0.  vl run: invalid module.

Want:

    null

#### Mechanism

`print` takes its `nulNone` arm only for a value `boxOperandIsNulNone` names. That names an
assignment of the `null` literal (`asgYieldsNullLit`), and `asgYieldsNulHole` names a write into a
never-filled `let x = null` (D17223), but nothing names a `null`-typed assignment whose right side is
a `null`-returning call. So the print reads the value at another arm's `i32` rep.
