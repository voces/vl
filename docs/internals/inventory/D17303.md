### D17303 — a `print` of an assignment of a `null`-returning call to an annotated `let x: null` is written as an `i32` where the value is `nullref`

**open · now a loud emit reject · clause 2 · `the compiler cannot yet lower this statement (print operand rep)` · an I8 holdout (`scripts/ir-i8-census/holdouts.tsv`)**

Before I8: check-clean invalid wasm · clause 1 · `vl check` rc 0; `vl run`: the emitted module failed to validate inside `f`, `type mismatch: expected i32, found nullref` · found by IR-N9 grading the captured null-typed call write · filed 2026-11-24 against master `14e8942a` by IR-N9

Repro:

    function same<T>(v: T): T {
      return v
    }
    function f() {
      let x: null = null
      print(x = same(null))
    }
    f()
    // vl check: rc 0.  vl run: invalid module.

Want:

    null

#### Mechanism

`print` takes its `nulNone` arm only for a value `boxOperandIsNulNone` names. That names an
assignment of the `null` literal (`asgYieldsNullLit`), and `asgYieldsNulHole` names a write into a
never-filled `let x = null` (D17223), but nothing names a `null`-typed assignment whose right side is
a `null`-returning call. So the print reads the value at another arm's `i32` rep.
