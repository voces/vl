### D3219 — an immediately called lambda taking a nullable-element list, given a list literal, is invalid wasm

**closed 2026-10-03 by [D3605](D3605.md) (lane CL2): a function-value call now seeds each argument's container shape from the callee's parameter, never the enclosing position · fixture `tests/cases/closures/value-call-list-literal-element-storage.vl` · was check-clean invalid wasm · clause 1 · found by the #3287 split-head review (`rv3287s-4099`) as the direct twin of a hole-callee cell · the same on master `94670f728` · filed 2026-09-29 against master `94670f728`**

Repro:

    type N = 1 | 2
    print(((x: (N | null)[]) => x.length)([1, 2]))
    // vl check: rc 0.  vl run: invalid module in the top-level code: type mismatch:
    // expected (ref $type), found (ref $type)

Want:

    2

#### Mechanism

Not localised. The list literal builds at a list type other than the one the lambda's parameter
names, and nothing converts it at the call.

Closed by [D3605](D3605.md): `emitCallRef` and `emitCapturedCall` seeded no list kind or slot from the parameter, so the literal built at whatever the enclosing position had left in `pendingListKind`. Both now seed it from the `$fnsig` key or the declaration, as the direct call seeds it.
