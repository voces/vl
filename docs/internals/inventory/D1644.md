### D1644 — `vl fmt` could not round-trip a bare lambda statement: the printer sent a nameless `FuncDecl` to the `function` header, which has no nameless spelling

**closed 2026-09-05 — the witness runs · was a `vl fmt` round-trip failure (rc 3, `formatter produced invalid output — file left unchanged`) on a `vl check`-clean program · fixed by taking `emitStatement`'s expression arm for a nameless `FuncDecl`, which is the arrow printer · found beside D1643 while grading the three `*.matrix.vl` templates**

Repro (before: `vl fmt` rc 3 and the file is left unchanged; now: rc 0, byte-identical
output, and `vl run` prints `7`):

    (x: i32) => x
    print(7)

#### Mechanism

An arrow lambda parses to a nameless `FuncDecl` — the same node a `function` declaration
parses to, because arrow is the sole lambda syntax and both forms share the node.
`emitStatement`'s `FuncDecl` arm sent both to `emitFunction`, whose `functionHeader` builds
`"function"` plus the name and then the parameter list. With an empty name that is
`function(x: i32)`, and the bare body renders after it, so the printer emitted

    function(x: i32) x

`function` has no nameless spelling in VL, so the output does not re-parse. `formatSrc`'s
round-trip gate catches it and returns `-2`, which the CLI reports as rc 3 and leaves the
file untouched — a formatter that refuses to run on a legal program.

The expression path was already correct: `expr`'s `FuncDecl` arm is `functionExpr`, which
prints `(params): Ret => body`. The arm now tests the NAME rather than the node's shape, so a
nameless one takes the expression path at statement position too.

#### Ablation

`vl fmt` over stdin, graded against master's fixpoint and the candidate's.

| ingredient | before | after |
| --- | --- | --- |
| `(x: i32) => x` at module scope | **rc 3 invalid output** | round-trips |
| with a return annotation | **rc 3 invalid output** | round-trips |
| a block body | **rc 3 invalid output** | round-trips |
| inside a function body | **rc 3 invalid output** | round-trips |
| a `;`-joined lambda | **rc 3 invalid output** | round-trips (reflowed) |
| bound to a `const` (control) | round-trips | round-trips |
| a named `function` (control) | round-trips | round-trips |
| an immediately-called lambda (control) | round-trips | round-trips |

The name is the only ingredient: the return annotation, the body shape and the position all
move nothing, and every control is a `FuncDecl` that either has a name or is already in
expression position.
