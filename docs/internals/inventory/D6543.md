### D6543 — an un-annotated lambda handed through a hole to a declared generic's `(T) => U` parameter is refused at emit

**closed 2026-10-18 by lane L1 · runs, prints `3` · was a loud emit reject · clause 2 · the hole call's instance now binds an un-annotated lambda last, at what the other arguments bind, in the checker and in the flow pin, and the lambda literal is built at that parameter type · pin: `tests/cases/generics/hole-call-generic-lambda-arg.vl` · found closing [D6540](D6540.md) · filed 2026-10-18 against master `fc3856155`**

Repro:

    function app<T, U>(f: (T) => U, v: T): U { f(v) }
    function via(a) {
      print(a((n) => n + 1, 2))
    }
    via(app)
    // vl check: rc 0.  vl run: emitProgram: a function-value call has no interned signature — the callee has no function type to key a signature from

#### Mechanism

The lambda's parameter is still open when the hole's call is read, so its argument bound
nothing, and both readers gave up on the whole call. The flow table kept no closed pin for the
slot call, so the emitter had no instance of `app`. The checker's `holeCallInstOf` and
`holeCallBindsAt` gave up too, so the hole call's result fell back to `app`'s own `U`. A
`print` of that result was then re-recorded at module scope and judged by every later instance
of `app` ([D6600](D6600.md)). The close binds the closed arguments first, then each
un-annotated lambda at the parameter type they give, taking its body's result as `U`
(`holeLamRetAt`, captures read under the call's bindings). The emitter binds the open pin the
same way (`fnFlowDeclPathOnlyPinCall`, `monoHoleGenBindLamArgs`), and the lambda literal is
built at the instanced parameter type (`monoPinOpenCallLams`).
