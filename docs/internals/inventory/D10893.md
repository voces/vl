### D10893 — a hole-function list element past index 0 that calls its parameter at two types reaches the emitter

**loud emit reject · `vl check` rc 0 · clause 2 · DESIGN: the checker owed the refusal, which index 0 gives · found closing [D10795](D10795.md) · present on master `b84cf89cb` · filed 2026-10-23 against master `b84cf89cb`**

Repro:

    function apply2(g) { print(g(1, 2)) }
    function apply3(g) {
      print(g(1.5, 2.5))
      print(g(1, 2))
    }
    const gs = [apply2, apply3]
    gs[1]((a, b) => a + b)
    // vl check: rc 0.  vl run: emitProgram: monomorphize: unsupported argument type for `g` in a call to `apply3`

Want:

    vl check: cannot infer a type for parameter `a`

#### Mechanism

The checker types `gs[1](...)` through element 0's type, so it binds the lambda's parameters
from `apply2`'s one call and accepts the program. The element named, `apply3`, calls `g` at
`(f64, f64)` and at `(i32, i32)`. The same lambda at index 0 is the check reject
`cannot infer a type for parameter `a``. The emitter's rungs find no single parameter list, so
the program fails at emit, where the checker owed the refusal.
