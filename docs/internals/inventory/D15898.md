### D15898 — an un-annotated `const` lambda whose only use is a function slot returning `f64` is refused at emit

**closed 2026-11-12 · runs, prints `1.25` · closed by D15897's fix (#7561: a call through a binding of one lambda is keyed by the closure it is lowered at) together with D15896's result widening · fixture `closures/const-hole-lambda-only-at-f64-result-slot.vl` (binding, parameter, `i64`) · matrix `hole-fn-i32-result-at-f64-fn-type-widens.matrix.vl` `two_instances` annotated runs, 48 of 48 · was loud emit reject, clause 2, `emitProgram: a function value is called at two signatures, and the closure it holds was built for one: this call reads an `i32` result from a wider one` · was a check reject on master `d303c9bcd` (D15896 admitted the widening) · found grading D15896's matrix (`two_instances`) · filed 2026-11-12 against master `d303c9bcd`**

Repro:

    const dbl = (a) => a * 2
    const v: (a: i32) => f64 = dbl
    print(v(5) / 8)

Want:

#### Mechanism

The `f64` spelling of [D15897](D15897.md): the adapter calls `dbl(p)` at `i32`, the closure is
built at the slot's `f64` signature, and the D15338 guard in the closure call refuses the read.
