### D15952 — an `is` test of a `let` a write narrowed to one record arm, which the value also fits structurally, must test the box's contents, not the narrowed arm's tag

**runs today and must keep running · refutation pin · found building the annotated-union face of flow-sensitive reads, whose first prototype lowered the test at the narrowed arm and printed `no` · filed 2026-11-12 against master `06baca0fa`**

Repro:

    type A = { n: i32 | string }
    type B = { n: string }
    function main() {
      const a: A = { n: "now" }
      let w: A | B = a
      if w is B { print("B") } else { print("no") }
      let v: A | B = a
      if v is A { if v is B { print("vB") } else { print("vno") } }
    }
    main()

Want:

    B
    vB

#### Mechanism

`is` tests whether the value fits the type (DECISIONS.md, "`is` tests whether the value fits the
type"), so an `A` whose `n` holds a string fits `B`. The write `w = a` narrows `w` to `A`. A
test lowered at that narrowed type reads one struct and answers by its tag alone, which is a
silent wrong `no`. The test reads the operand at storage instead (`isOperandAtStorage`), and an
`is` over a write-narrowed `let` computes its then and else facts from storage
(`isTestCurTy`), so the inner `v is B` also tests the box.

| --- | --- | --- |
| the write (`w` a `const`) | runs, `B` | **yes** |
| the structural fit (`n` a number) | runs, `no` | **yes** |
