### D2808 — an alias-named union argument into `T | string` prints through a tag dispatch that cannot classify it

**closed · loud emit reject · clause 2 · `gPr/al0_gnar`, `gPr/al1_gnar` of #3208's review · pre-existing on master `2bbc5c412` · filed 2026-09-27 against master `2bbc5c412`**

Repro:

    type U2 = i32 | string
    function k<T>(v: T | string) {
      print(v)
    }
    const x: U2 = 5
    k(x)
    // vl check: rc 0.  vl run: emitProgram: print of a union value whose arms the tag dispatch cannot classify

Want:

    5

#### Mechanism

The monomorphizer bound `T` from the argument's spelling. `monoBindFromAnn` paired `T | string`
with the alias name `U2` as one atom, so `T` took `U2` and the instance's `v` was `U2 | string`, a
member set the print plan's atom list does not flatten. The `i32 | string` spelling ran because
its atoms subtract. `monoPinTyParamComposite` now binds by type through `bindGenWalkFull`, whose
union arm flattens the argument's members and binds the open member to those no fixed member
`tyEq`s, so `T` is `i32` at either spelling (C1 step 3 of the render-parse ledger).

| the narrowing (`if v is string … else …`) | still refuses | no |
