### D9170 — a `let` list of un-annotated functions re-pointed to another list binding leaves its literal un-instanced

**closed · runs, prints `6` · was loud emit reject, `emitProgram: cannot take the generic function inc0 as a value`, `vl check` rc 0 · clause 2 · found closing [D9094](D9094.md) · filed 2026-10-21 against master `c2df9510f` · closed by following a re-point to a binding to that binding's own literal, so both literals are typed from the calls through either (`monoRepointBindingLit` under `monoLetRepointLits`, emit_mono.vl) · fixtures `closures/hole-fn-let-list-repointed-to-list-binding.vl`, `closures/hole-fn-let-list-repointed-to-list-binding-called-at-f64.vl`**

Repro:

    function inc0(a) { return a + 1 }
    function dbl(a) { return a * 2 }
    const ys = [dbl]
    let xs = [inc0]
    xs = ys
    print(xs[0](3))
    // vl check rc 0.  vl run: prints 6

#### Mechanism

D9094's close reads a `let` list's re-point LITERALS (`monoLetRepointLits`); a re-point to a
binding is not a literal, so neither list was typed from the other's calls. The re-point is
now followed to the source binding's initialiser when that is a list literal, and the source
is pinned with the target.

#### Ablation

| ingredient removed | outcome | needed? |
| --- | --- | --- |
| the binding (`xs = [dbl]`) | runs, `6` | **yes** |

#### Grading list

The source declared before or after the `let`, annotated (`ys: ((a: i32) => i32)[] =
[dblA]`), generic (`let xs = [ginc]`), inside a function, and called at f64 (`7`) all run.
`const ys = [half]` with `half(a) { return a / 2.0 }` stays refused.
