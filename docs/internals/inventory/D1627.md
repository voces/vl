### D1627 — a nullable REF value in an INFERRED struct field has no interned shape

**loud emit reject · 5 cells, 4 nullable reps · filed 2026-09-05 against master `2c70883c`**

Repro:

    function mk(): ((i32) => i32) | null {
      return (n: i32) => n + 1
    }
    const w = { f: mk() }
    const v = w.f
    if v != null { print(v(54)) }
    // vl check: rc 0, "Checked 1 file, no errors."
    // vl run:   emitProgram: ref valtype with no interned shape

#### Mechanism

An object literal with no declared type mints its struct row from the literal's field set, and
each field's storage code comes from the value it was given. A field holding a NULLABLE REF —
a closure, a string, a struct, a list — needs an interned shape for its wrapper, and the
inferred-field path mints none, so `fbValtype`'s own bounds guard turns the missing slot into
this refusal rather than a trap. `vl check` returns 0 throughout, so it is a clause-2 violation
by construction.

The message names the arm that fired, not the feature: nothing here is a valtype the design
forbids, and the ANNOTATED spelling of the identical program runs.

The frame-scoped spelling reaches a DIFFERENT floor — inside a function the same literal is
`emitProgram: object literal but no struct type declared`. One gap, two messages, which is why
this row's family is defined by its ablation rather than by either sentence.

Found by `scripts/capability-probes/matrix/one-hop-nullable-closure-return.matrix.vl`'s
`struct_field_init` cell, which is loud in both of its columns and so is nobody's regression.

#### Ablation

Every row is `vl check` rc 0. The value is produced by a call in each case unless stated.

| the field ANNOTATED through a declared `type W` (closure) | runs, 55 |
| the field ANNOTATED through a declared `type W` (string) | runs, 55 |

Needed: the field being INFERRED, and its value being a nullable REF. Not needed: the closure
rep in particular — string, struct and list refuse identically — the call in the initializer,
the read spelling, or module scope. The nullable `i32` runs because its niche is the `-1`
sentinel and needs no interned shape at all, which is what makes "nullable REF" the boundary
rather than "nullable".

#### Grading list

  field at two reps especially, since annotating is what mints the shape today.
* The nullable `i32` field, which must not gain a wrapper it does not need.
* Both messages: a fix that closes the module-scope spelling and leaves the frame-scoped one
