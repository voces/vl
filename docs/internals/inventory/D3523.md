### D3523 — a two-width integer-literal union is refused delivery into `f64`, and into `i64` once it joins an `i32`, though every member converts exactly

**loud check reject · open · clause 2 · 84 cells of lane WD's D3517 matrix (`lit_f64_*`, and `lit_i64_d2_*` where the default is a non-member literal) · pre-existing, the same on master `4c55f1b6a` · found by lane WD · filed 2026-10-03 against master `4c55f1b6a`**

Repro:

    type D = 9000000000 | 1
    function f(a: D): f64 { a }
    print(f(1) / 2)
    // vl check: rc 1, "expected f64, got D"

Want:

    0.5

#### Mechanism

Not confirmed. A numeric union delivers into a wider number through `numUnionConverts`, which
asks `numUnionMembersOf`; a literal union's members are `TyLit`, not numeric primitives, so it
answers no members. `D` into `i64` is accepted by some other rule (every literal fits `i64`),
which `f64` does not share because a VARIABLE `i64` into `f64` is lossy, and which a join with
a non-literal `i32` member (`D | i32`, what `x ?? 5` over `D | null` produces) no longer
satisfies. Every member here converts exactly: the literals are constants, and `i32` widens
to both.
