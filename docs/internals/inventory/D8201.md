### D8201 — a literal-building function called twice into a wider record is refused beside an unused record of its fields

**loud check reject · clause 2 · open · present on master `be738c9f0` · the same program prints `15` once the unused `type Col` is deleted · found closing [D8020](D8020.md) · filed 2026-10-20 against master `be738c9f0`**

Repro:

    type Col = { r: i32, g: i32 }
    type J = { r: i32 | null, g: i32 }
    function mk() { { r: 15, g: 1 } }
    let v: J = mk()
    v = mk()
    print(v.r ?? 0)
    // vl check: {r: i32, g: i32} is not J: they store field `r` differently ... only a fresh record widens

Want:

    15

#### Mechanism

`recFnBuiltAtDst` (check_fit_rules.vl) re-seats a fresh function's literal at the destination
only when the function has one call site. With two, `mk`'s literal stays at its own type, and
`Col` names that type, so `recBuiltAtDeclared` refuses each call as an existing record. Without
`Col` the literal has no declared row and both deliveries adopt. The six positions left in the
`generic-identity-fresh-call-beside-declared-row` matrix after D8020 are this shape through
`idn`: each calls `mk` twice (a struct field, a list element, a local and a global assigned
after their binding).

#### Ablation

| change | outcome | needed? |
| --- | --- | --- |
| delete `type Col` | prints `15` | **yes** |
| delete `v = mk()` | prints `15` | **yes**, the second call |
| route both calls through `idn` | still refuses | no |

#### Grading list

The six refusing cells of `generic-identity-fresh-call-beside-declared-row`, and the same with
the second call into an un-annotated binding (`const m: J = idn(mk())` then `const k = mk()`).
