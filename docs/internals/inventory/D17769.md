### D17769 — a call result of a lone-string-literal return pushed into a list of that literal is refused at emit

**closed 2026-11-28 by COV-UNION · runs, its witness prints its expected value · was a loud emit reject, `cannot yet lower this statement (push element narrow)`, clause 2 · a pushed value typed one string literal is that member's atom, delivered as a literal list element's is, so the push plan no longer asks the string narrow (`litPushNeedsDestNarrow`, wasmEmit.vl) · pinned by `tests/cases/literal-unions/push-lone-literal-call-result.vl` · `lone-literal-result-of-generic-fn-value` matrix 62 → 64 of 66 runs**

Repro:

    function g(): "a" { return "a" }
    const xs: "a"[] = []
    xs.push(g())
    print(xs[0] + "x")
    // vl check: rc 0.  vl run: emit error (push element narrow) at 2:7

Want:

    ax

#### Mechanism

The push plan (`pushPlainWhy`) refuses any value into a literal-set list that is not already an
atom or a string literal (`litPushNeedsDestNarrow`), because a general string needs the
destination's narrow, which the IR does not build. A value typed one string literal is that
member, whose atom the IR's delivery already writes for a list literal's element (`[g()]` ran).

#### Ablation

| ingredient removed | outcome | needed? |
| --- | --- | --- |
| the call (`xs.push("a")`) | runs | **yes** |
| the lone literal widened to `"a" \| "b"` | runs | **yes** |
| the list built by its literal (`const xs: "a"[] = [g()]`) | runs | **yes** |
| the program moved into a function body | still refuses | no |
