### D16034 — a union `==` whose left operand is a `let` of a record union is refused

**loud emit reject · clause 2 · ``emitProgram: `==` over a struct union is not supported yet`` · found by the `==` control of the `identity-eq-record-union` matrix (`local_assign`, annotated), lane E · filed 2026-11-13 against master `0260e578`**

Repro:

    type A = { a: i32 }
    type B = { b: i32 }
    const src: A = { a: 1 }
    const held: A | B = src
    let v: A | B = src
    print(v == held)

Want:

    true

#### Mechanism

Not traced. The refusal is one of the two union-`==` sites in compiler/wasmEmit.vl. Which
operand is a `let` decides the outcome, not where the `let` sits or what it holds. A `const`
left operand runs, and so does the same compare with the operands swapped.
