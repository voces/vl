### D16034 — a union `==` whose left operand is a `let` of a record union is refused

**closed 2026-11-13 · runs, prints `true` · `unionEqOperandTy` reads a narrowed read's arms from the union it is stored in · was loud emit reject · clause 2 · ``emitProgram: `==` over a struct union is not supported yet`` · found by the `==` control of the `identity-eq-record-union` matrix (`local_assign`, annotated), lane E · filed 2026-11-13 against master `0260e578`**

Repro:

    type A = { a: i32 }
    type B = { b: i32 }
    const src: A = { a: 1 }
    const held: A | B = src
    let v: A | B = src
    print(v == held)

Want:

    true

#### Mechanism

The initializer narrows the `let` to `A` (a cast reports "`v` is already `A` here"), yet `v` is
stored as the `A | B` box. `emitUnionUnionEq` took its arm columns from `unionEqOperandTy`, which
returned the narrowed `A`, so `emitStructUnionEq` found no union arms and declined. A
non-narrowable initializer (`let v: A | B = pick()`) ran. The close has `unionEqOperandTy` answer
`unionBoxStoreTyOf` first, the union a narrowed read is stored in. Test cells:
`tests/cases/operators/union-eq-narrowed-let-operand.vl`.
