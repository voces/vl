### D1738 — once a struct is a union VARIANT, its own object literal resolves against another struct's row, and any second declared struct is enough

**loud emit reject · filed 2026-09-06 against master `6de9fd11a` · found grading D1720 and
D1737, whose refusal is the same index-space confusion one reader along · 0 corpus cells**

Repro:

    type A = { r: i32 }
    type W = { g: i32 }
    function st(): A { return { r: 8 } }
    function mkS(): string | null { return null }
    const v = mkS()
    const k = v ?? st()
    print(0)
    // vl check: rc 0.  vl run: exit 1,
    // emitProgram: object literal is missing a struct field

#### Mechanism

`st()`'s body is the literal `{ r: 8 }` and its declared return type is `A`, so nothing about
the literal is ambiguous to a reader that asks the annotation. The `??` join makes `A` a union
member, which routes the literal through the variant-boxing resolution instead, and that
resolution picks a row by scanning rather than by asking the return type — with a second struct
in the table it lands on `W` and reports `A`'s own field as missing.

**Declaration ORDER is not the ingredient**: `A` first and `W` first refuse alike. Neither is
arity — a two-field `W` refuses too. What is needed is a second struct row and the join; with
either one removed the same program runs.

The refusal is `emitFail`'s, on a `vl check`-clean program, so it is a clause-2 violation by
construction. D1737 is the same confusion at the union-ARM lookup rather than the literal's, and
a close that fixes the index space should re-grade both.
