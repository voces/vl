**closed 2026-11-04 by lane G2, runs, prints `true`, `3` · was check-clean silently wrong, printing `true` twice, clause 1, pre-existing on master `eb6c23665` · `print` chose its sink from `exprIsBool`, whose field-call arm asked `fieldCloCallIsBool`, which read the slot `fieldClosureFeOfRecv` resolved (`g`'s `boolean` instance) though the checker typed `b.f(3)` `i32`; every classifier that asked the resolver about a field call's result now asks it only where the call's checked type is open (`callTyClosedIn`), so the checked type decides, as D15114 made it decide in `exprString` · fixture `closures/fn-same-row-records-one-fn-result-by-call-type.vl` · named sets `d15115-bool-then-i32-same-row`, `d15115-field-call-classifiers` · found grading D15113 · filed 2026-11-04**

    const a = { f: g, n: 1 }
    const b = { f: g, n: 1 }

#### Mechanism

The checker's facts are right: `b.f(3)` is typed `i32`. `exprIsBool`'s `Call` arm reached the
field-closure branch (`drwFieldClosure`), and `fieldCloCallIsBool` resolved `b.f` through
`fieldClosureFeOfRecv` to slot 0, `g`'s instance at `boolean` (`fRetBool` 1), so `print` used the
boolean sink. `exprUnionCall` read the same slot's rep, so an `i32` call beside a union one was
classified as a union box. Six sites asked the resolver about a field call's result:
`exprString` (D15114), `exprIsBool`, `exprUnionCall`, `structIndexOfCallExpr`,
`nulVariantIdxOfExpr` and `emitCallStmt`'s drop. Each now asks it only where
`callTyClosedIn` is false, and the checked-type rungs after it answer otherwise.
