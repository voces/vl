### D7182 — a one-element hole-function list called at a computed index with a generic function is refused

**loud emit reject · `vl check` rc 0 · clause 2 · CAPABILITY: the same call at the literal index `fs[0](add)` runs `3 4` · found closing [D7140](D7140.md) · the same on master `6a89bc66d` · filed 2026-10-19 against master `6a89bc66d`**

Repro:

    function add(a, b) { return a + b }
    print(add(1, 2))
    print(add(1.5, 2.5))
    function apply2(g) {
      print(g(1, 2))
      print(g(1.5, 2.5))
    }
    const fs = [apply2]
    const i = fs.length - 1
    fs[i](add)
    // vl check: rc 0.  vl run: emitProgram: a generic function is passed to a function value whose parameter type names a type parameter this closure does not bind

Want:

    3
    4
    3
    4

#### Mechanism

Not probed. The split's exact value-flow question reads an element only at a literal index,
so a computed index answers lost and `apply2` is not split per call type. For a list whose
every element is one function, a computed index reaches that function as surely as `[0]`.
