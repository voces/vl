#### Mechanism

**The refusal names a ref LIST and the failing cell is a `nulstruct`.** Instrumented at the
refusal site, the un-annotated program reads:

    fbValtypeNullable REFUSED kind=[nulstruct] structIdx=-1

so it is `v`'s struct row, not a list wrapper, that is missing. Beside the annotated twin the
cells differ in exactly one column:

    un-annotated  v kind=[nulstruct] structIdx=-1
    annotated     v kind=[nulstruct] structIdx=0

and the ref-list tables say why:

    un-annotated  [0 P|null k1 nul1] [1 {n:i32}|null k1 nul1] [2 ({n:i32}|null)[] k9 nul0]
    annotated     [0 P|null k1 nul1] [1 (P|null)[]  k9 nul0] [2 {n:i32}|null k1 nul1]
                                                             [3 ({n:i32}|null)[] k9 nul0]

The annotated program has the NOMINAL `(P|null)[]` row that the inferred one lacks, so `inner`
resolves to a slot whose element is `{n:i32}|null` — a spelling `structIndexByName` answers
nothing for, while `P|null` peels to the declared `P`.

`arrLitNestedElemName` keys the outer element on `nodeArrayElemName`, the structural render.
`nulRefElemEmitName` is the nominalisation [D1831](D1831.md) already applies one level down;
the nested arm asks it first now, and RECURSES, so three levels need no second rung.
