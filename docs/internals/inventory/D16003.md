### D16003 — the emitter's name-to-type bridge reads a newtype's name as its unbranded base

**runs today and must keep running · 3 corpus programs reached through the deleted field-recorder fallback · filed 2026-11-13 against master `09aede4a`**

Repro:

    type PView = new { base: i32, length: i32 }
    type Holder = { ps: PView[] }
    const h: Holder = { ps: [{ base: 11, length: 1 }] }
    print(h.ps[0].base)
    // vl run: 11. The field's element type is the brand `PView`; the name `PView`
    // resolves (`declTyIxOfName`) to the unbranded record, a different type under `tyEq`.

Want:

    11

#### Mechanism

`declTyIxOfName` answers a declared name from `cUserTypes`, which holds a newtype's base,
not its brand (the brand is the arena index registered in `nwTyIxs`). So a type read back
off a newtype's name is `tySame` with the brand but not `tyEq`. The field recorder's name
fallback reached this before it was deleted (the 2026-11-13 field-elem-hint note); the
remaining callers of `declTyIxOfName` and `fieldElemTyIxOfName` can still reach it with a
newtype's name. A newtype is rep-identical to its base, so nothing that runs today reads
the difference.
