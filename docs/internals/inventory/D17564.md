### D17564 — the IR's claimed call of an un-annotated function read from a `Map()`, in a string interpolation hole, passes the wrong valtype

**check-clean invalid wasm under `VL_IR_STRICT=1` (CI's setting): the IR's claim is an invalid module inside `go`, expected i32, found the `string` ref · clause 1 · a run without strict IR falls back to legacy and prints `i=6` · found by COV-START's Q58 sweep · owner SOUND · filed 2026-11-25 against master `b126d3fe`**

Repro:

    function inc(a) { return a + 1 }
    const m = Map()
    m["k"] = inc
    function go() {
      const f = m["k"]
      if f != null { print("i=\{f(5)}") }
    }
    go()
    // VL_IR_STRICT=1 vl run: invalid module inside `go`, expected i32, found (ref $3) (`string`)

Want:

    i=6

#### Mechanism

Not established. The armed shadow reports `mismatch bytes: call at 0x23 vs 0x20` in `go`: the IR's
call of the closure read from the map, as an interpolation hole, hands the string conversion a value
of another valtype than the call returns, or calls with the hole's string where the `i32` argument
belongs. Legacy's fallback is correct.

#### Ablation

All under `VL_IR_STRICT=1` on master `b126d3fe`.

| spelling | outcome |
| --- | --- |
| `print("i=\{f(5)}")` in a function | invalid |
| the same at module scope | invalid |
| `const l = f(6)` then `print(l)` | runs |
| `const r = { v: f(9) }` then `print(r.v)` | runs |
| `print(f(5))`, `print(f(5) + 1)` | runs |
| `inc` annotated `(a: i32): i32` | runs |
| `const f = inc` (no map) | runs |

#### Grading list

- The interpolation hole with a string-, f64- and record-returning closure from the map.
