Repro:

    function inc(a) { return a + 1 }
    function dbl(a) { return a * 2 }
    function deliver() {
      return [inc, dbl]
    }
    const v = deliver()
    print(v.map((f) => f(3))[1])
    const u = deliver()
    print(u.map((f) => f(1.25))[1])
    // vl check rc 0.  vl run: emit error: emitProgram: cannot take the generic function `inc` as a value

Want:

    6
    2.5

#### Mechanism

`monoRetFnListTy` (emit_mono.vl) instances the returned literal at the one pin its element slot
takes. The two callers' callbacks pin that slot at `i32` and at `f64`, so there is no one pin,
the literal stays open, and the functions inside it are refused. Nothing asked fn_split for a
copy of `deliver` per pin, which is what a returned generic name already gets. The index
spelling runs for a different reason: a constant index into the returned literal is
devirtualised to a direct call of `dbl` at each type, so no list element is delivered at all.
