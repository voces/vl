### D15134 — a function set held in a top-level list and also handed to a hole parameter that lists it needs both reps, and is refused at emit

**loud emit reject · clause 2 · `the reassigned function binding f holds functions called at more than one argument type` · split from D15132 · found closing D15132 · filed 2026-11-03 against master `8af9776f`**

Repro:

    function id<T>(x: T): T { return x }
    function dbl<T>(x: T): T { return x + x }
    function viaHole(a) {
      const zs = [a]
      const ys: ((x: i32) => i32)[] = []
      ys.push(...zs)
      print(ys[0](10))
    }
    let f = id
    f = dbl
    print(f("s"))
    const zs = [f]
    const view: readonly ((x: i32) => i32)[] = zs
    print(view[0](3))
    viaHole(f)
    // vl check: rc 0.  vl run: emit error, with the split plan on and off

Want:

    ss
    6
    20

#### Mechanism

A top-level list holding the set reads it as ids, delivered to its closed readers through
adapters (D15069), while the hole parameter that lists the set keeps it closures
(`ftParamStored`, D15131). One set is decided once, so it cannot be both; either half alone runs.

| --- | --- | --- |
| `viaHole(f)` removed | runs | **yes** |
| the readonly copy `view` removed, `const zs = [f]` kept | still refused | no |
| `const zs = [f]` and `view` removed | runs | **yes** |
