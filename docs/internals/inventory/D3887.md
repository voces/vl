### D3887 — `const k = inner` aliasing a capturing nested generic in the enclosing function's own body, in a program that instantiates the enclosing generic at two reps, emits a call that passes the wrong capture type

**check-clean invalid wasm · found by the rv3466 review of #3465/#3466 · filed 2026-10-08 against master `a1c9be3c4`**

Repro:

    function outer<T>(x: T) {
      function inner<U>(u: U) { print("inner"); print(x); print(u) }
      const k = inner
      k(2)
    }
    outer(7)
    outer("s")
    // vl check: rc 0.  vl run: rc 70, invalid module

Mechanism evidence, the host's message: `the emitted module failed to validate inside `outer`:
type mismatch: expected (ref $2), found i32; $2 is `string``.

#### Mechanism

`inner` captures `x`, so a call to it passes the capture; the call `inner(2)` resolves the
instance for the enclosing instance it is in. The alias `k` is a first-class value of `inner`'s
generic type, and the call through it picks an instance without the enclosing instance's binding
of `T`, so one `outer` instance receives the other's capture type: the `string` instance is
handed an `i32`. A program that instantiates `outer` at one rep, or twice at the same rep, has
nothing to confuse and runs. The reading comes from the ablation below; the instance chosen is
not printed here.
