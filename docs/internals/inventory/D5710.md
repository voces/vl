### D5710 — `match` over a set of integer literals is refused as a union with literal members

**closed 2026-10-17 — the witness prints `two` · was a loud check reject, clause 2 · lane L3 (legality decided in one place): `checkMatchExprByScrut` sends an integer literal set (`matchLitSetTys(st, "int")`, a lone literal, a union, or either with `null`) to `checkMatchIntArms`, which checks each pattern's value against the members, takes `null` on a nullable set, and calls the set complete when every member is named, so no `_` is needed; the `_` arm sees the scrutinee narrowed to what is left · fixtures `tests/cases/match/int-lit-set-dispatch.vl`, `tests/cases/match/int-lit-set-errors.vl` · filed 2026-10-17 against master `bb4448de7`**

Repro:

    function f(k: 1 | 2): string {
      match k { 1 => "one", 2 => "two" }
    }
    print(f(2))

Want:

    two

#### Mechanism

`checkMatchExprByScrut` (`check_match.vl`) knew three scrutinee kinds: a bare `i32`/`i64`
(literal arms plus a required `_`), a union of STRING literals, and a union of types. A union
of integer literals was none of them, so `checkMatchUnionScrut` refused it with the literal-
members sentence, even with a `_` arm. The hand-written `if k == 1 … else …` chain the match
desugars to already ran.

#### Ablation

| ingredient removed | outcome | needed? |
| --- | --- | --- |
| a `_` arm added | still refused | no |
| the set narrowed to a lone `7` | still refused | no |
| `| null` added, with a `null` arm | still refused | no |
| the same chain written as `if k == 1` | runs | **yes** |

#### Grading list

A lone `7`, an alias `type N = 0 | 1 | 2`, `1 | 2 | null`, a set narrowed by `if k != 2`, an
i64-width member `9000000001 | 2`, the `_` arm passing the narrowed rest to a `2` parameter,
and a `const` arm. A non-member pattern, a missing member, a missing `null` and a repeated
member each refuse with their own sentence.
