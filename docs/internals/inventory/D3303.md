### D3303 — an un-annotated generic joining a parameter with an else-if chain or a non-member literal builds invalid wasm at a literal-union pin

**closed 2026-09-30 · was check-clean invalid wasm, clause 1, on master `6e6a5301b` · found by the #3303 review's generator (`rv3303-12883/gen`, 31 cells) · ruled 2026-09-30 (an un-annotated parameter is gradual as a declared one) and built by lane UG · fixture `tests/cases/generics/hole-join-literal-at-literal-union-pin.vl`**

Repro:

    type K = "a" | "b" | "c"
    function show<T>(x: T) { print(x) }
    function g(a, b, c: boolean) {
      const r = if c { a } else { "z" }
      r
    }
    const u: K | null = "a"
    const w: K | null = "b"
    const v0 = g(u, w, true)
    print(v0)
    const v1 = g(u, w, false)
    print(v1)

Want:

    a
    z

#### Mechanism

The checker's typing of the hole, not the emitter. `joinTys` folds the concrete arm into an
inference hole (`"z"` is assignable to `?a`), so `r`, `g`'s result and the call are all typed
`?a`, and at `K | null` the call is typed `K | null`
(`const v1: boolean = g(u, w, false)` reports `cannot assign K | null`) while the value is
`"z"`. No lowering of the instance can agree with a caller typed that way. A declared parameter
beside a concrete type became `T | string` under ruling (A) (`tyParamBesideBare`); a hole has
no such rule, and D2760 keeps two holes collapsed as inference too (D3333). The else-if cells
with a member literal (`if c { a } else if !c { b } else { "c" }` at `K`) are a second slice:
the hole's typing is right there, and the instance builds the `"c"` arm as a string ref inside
a join the pin reads as the atom. A lane JW trial re-typing that join at the pinned literal
union moved the mismatch from `g` to its caller, so it was not kept.

The close (lane UG): a parameter's hole is kept apart from a concrete arm as a declared
parameter is (`tyParamBesideBare`), so the join is `?a | string` and the call at `K | null` is
`string | null`; the instance re-joins it through its holes' binding (D3333). A two-arm join
typed `string | null` is the string niche even when its first arm is a `K | null` atom
(`ifIsChainHeadIn`), which makes `print(if c { a } else { "z" })` run at both spellings. The
else-if cells run too, except a chain with a string literal delivered to a sink (D3365) and a
`??` arm in a chain (D3366).

**The ruling, asked here and given 2026-09-30 (yes):** is an un-annotated parameter gradual the way ruling (A) makes a
declared `T` gradual, so that `if c { a } else { "z" }` is `?a | string` in the body and
re-joins at each pin (`K | null` gives `string | null`)? Recommendation: yes. A hole is an
implicit type parameter, the `<T>` spelling of this witness already prints `a z`, and the
alternative (refusing the call at the pin) turns a program that runs when annotated into a
refusal when not.
