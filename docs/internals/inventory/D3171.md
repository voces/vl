### D3171 — a string literal passed beside a literal-union function value to an un-annotated function reaches the function's `K` parameter as a string

**check-clean invalid wasm · clause 1 · found by lane WV's D3167 parameter grid (`fnparam`, the `K` and `K | null` parameter cells, 80 of 180, every passer) · the same on master `a0b9acaf8` · filed 2026-09-29 against master `a0b9acaf8`**

Repro:

    type K = "a" | "b"
    function H(h, v) {
      return h(v)
    }
    print(H((x: K) => x, "b"))
    // vl check: rc 0.  vl run: invalid module inside `H`: type mismatch: expected i32, found
    // (ref $type)

Want:

    b

#### Mechanism

Not localised past the ablation. The hole `v` is pinned at the literal's own type, a string ref,
while `h`'s parameter is the `K` atom, so `h(v)` inside the instance hands the string to an `i32`
parameter. Nothing converts the member to its atom where the two holes meet.

#### Ablation

| ingredient changed | outcome | needed? |
| --- | --- | --- |
| `const k: K = "b"`, then `H((x: K) => x, k)` | runs | **yes** (the literal argument) |
| `function H<V>(h: (V) => V, v: V)` | runs | **yes** (the holes) |
| `function H<V>(h, v: V)`, only `h` a hole | the same invalid module | no |
| `(x: string) => x` | runs | **yes** (the literal union) |
| `(x: K) => x == "b"`, a `boolean` result | the same invalid module | no |

#### Grading list

The witness, the `K | null` parameter twin, and the instance passers of the `fnparam` grid
(`F<Z, V>(g: Z, v: V)` and `F(g, v)` forwarding to `H`).

#### A fix withdrawn, and what the next attempt must meet

#3287 recorded each argument of a hole callee as a demand on the pinned function's parameter
(`HD_PARAM`), re-asked at the pin, with a literal argument held at its literal type. It was
withdrawn from that PR: it refused programs whose direct twin runs (`rv3287s-4099`: `g3.json`,
`p2/`, `p3/`). The next attempt must meet this design:

- **A literal-originated argument is typed by its context, transitively.** `H((x: K | i32) => x,
  "a")` and `H((x: (N | null)[]) => x.length, [1, null, 2])` run on master and must keep running:
  a literal reaching `h` through the hole `v` is typed by `h`'s parameter, as a literal binding
  takes its type from its uses (owner ruling, 2026-09-29), and `const s = "b"; f(s)` runs directly.
- **A record literal fits by the direct call's rules.** `h({ a: 1 })` into `R = { a: i32, b: i32 |
  null }` is accepted directly (a missing nullable field), and so is an excess field (`f({ v: 3,
  z: 1 })` into `W = { v: i32 | null }`); an exact record type refuses both.
- **Rest and default parameters map correctly.** A rest parameter takes every argument from its
  position on, and an omitted default is filled (D3220, D3221 are the arity rows).

A non-literal argument that does not fit remains a refusal, as the direct call refuses it.
