### D3171 — a string literal passed beside a literal-union function value to an un-annotated function reaches the function's `K` parameter as a string

**check-clean invalid wasm · clause 1 · found by lane WV's D3167 parameter grid (`fnparam`, the `K` and `K | null` parameter cells, 80 of 180, every passer) · the same on master `a0b9acaf8` · filed 2026-09-29 against master `a0b9acaf8`**

Repro:

    type K = "a" | "b"
    function H(h, v) {
      return h(v)
    }
    print(H((x: K) => x, "b"))
    // vl check: rc 0.  vl run: invalid module inside `H`: type mismatch: expected i32, found
    // (ref $type)

Want:

    b

#### Mechanism

Not localised past the ablation. The hole `v` is pinned at the literal's own type, a string ref,
while `h`'s parameter is the `K` atom, so `h(v)` inside the instance hands the string to an `i32`
parameter. Nothing converts the member to its atom where the two holes meet.

#### Ablation

| ingredient changed | outcome | needed? |
| --- | --- | --- |
| `const k: K = "b"`, then `H((x: K) => x, k)` | runs | **yes** (the literal argument) |
| `function H<V>(h: (V) => V, v: V)` | runs | **yes** (the holes) |
| `function H<V>(h, v: V)`, only `h` a hole | the same invalid module | no |
| `(x: string) => x` | runs | **yes** (the literal union) |
| `(x: K) => x == "b"`, a `boolean` result | the same invalid module | no |
