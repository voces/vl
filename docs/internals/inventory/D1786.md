#### Mechanism

**Two earlier readings of this row were wrong, and the probe refuted both.** It is not a
missing arm, and it is not an uncovered `rlElemTyIx`. Instrumented at the element mint, with
every control that runs:

    witness  slot=3 name=[{[string]:{[string]:{n:i32}}}] hint=-1 byName=69 rlTy=69
    one-deep slot=2 name=[{[string]:{n:i32}}]            hint=-1 byName=57 rlTy=57   runs
    string   slot=2 name=[{[string]:{[string]:string}}]  hint=-1 byName=46 rlTy=46   runs
    annot'd  slot=4 name=[{[string]:{[string]:{n:i32}}}] hint=-1 byName=75 rlTy=75   runs

`rlElemTyIx` is a real row in all four — the running controls have the identical
`hint=-1, rlTy=<from the name>` shape, so an uncovered sidecar cannot be the discriminator.
What differs is WHEN the mv row for the element's VALUE is interned. `rlElemMapValMvSlot`
bottoms out at `mvSlotOfValTyK`, a pure find over the mv table, and that table's row for a
struct-valued inner map is minted by the value's own first op — which can fall between the
frame-layout pass and the emit pass. The find then answers `-3` to one and the slot to the
other, and `fbBeginFunc reserved a different slot count than fbEmitLocalsVec declared` is
literally those two passes disagreeing.

The fix is the moment, not the reader: `rlInternNameTy` mints the element's value row beside
the element row it is already pushing, so the row exists before any pass can ask.

**Two candidates were refused first, and their prices are why this one is at the mint.**
Giving `rlElemMapValMvSlot` the `mvShapeOfMapName` its sibling `rlElemMapShape` takes moves the
mint to the READ: 0 cells gained, 3 loud → check-clean invalid wasm. Handing
`arrLitElemHintTy` a map arm reached 32 of 32 on the grid and still lost a program — a plain
shallow-map list refuses once a nested-map function is merely DECLARED in the module. Neither
the grid nor `tests/cases` byte-identity could see that loss, which is why the pair is now a
fixture cell.

**This close does not stand alone.** Without [D1772](D1772.md) it leaves
`struct_index_unann_function_cap` silent — that cell is D1772's struct twin and meets its
`("map", -1)` pair once the slot resolves.
