### D17787 — a typed element read pins a fresh list only through aliases, not through a call or another element read

**loud check reject · clause 2, a mechanism limit of F2's typed reads (coordinator ruling 2026-11-28) · `cannot assign {r: i32} to 'gp' of type {r: N}` · 128 of the F2 census cells (block B) · filed 2026-11-28 against master `35c521c36` by lane CENSUS**

Repro:

    type N = 1 | 2
    function mk() {
      const c = [{ r: 1 }]
      return c
    }
    const d = mk()
    const gp: { r: N } = d[0]
    print(gp.r)
    // vl check: rc 1, "cannot assign {r: i32} to 'gp' of type {r: N}"

Want:

    1

#### Mechanism

`projDests` (`check_rec_fresh.vl`) follows a typed read's root back through un-annotated
aliases (`aliasRoot`) to the fresh binding. A root bound to a call's result (an inferred result,
a generic pass-through such as `idg(c)` or std's `reverse([c])[0]`) or to an element read of
another literal (`const g1 = c[0]`) ends that chain, so the read names no destination.

#### Ablation

| ingredient removed | outcome | needed? |
| --- | --- | --- |
| the call: `const d = c` | runs, prints `1` | **yes** |
| the generic: `idg(c)` for `mk()` | refused, same message | no |
| the element alias: `lv1[0]` read directly | runs | **yes** (for `g1 = c[0]`) |
