    function g<T>(x: T): T { return x }

    // vl check: f64 doesn't fit in f32 at `g(0.1 + 0.2)`

#### Mechanism

D3539 binds a generic's type parameter from the call's destination when every argument that
would bind it is a literal adapting to that type (`dstBindLitTyParams`), and "a literal" is
`argIsLitOnly`: an integer operator tree (`litTreeOps`), a lone float literal, or a literal
`const`. A float constant tree was none of these, so it bound `T` at its own default `f64` before
the fold made it one literal, and the `f32` destination refused the call's `f64` result. A tree
of number literals now counts (`lbiLitTree`), so it folds at the bound `f32` as a lone literal
does. Bucket (f) of the clause-2 map: no hole and no un-annotated parameter is an ingredient, and
the rule is local to which arguments D3539 counts. A lone integer literal at an `f32` destination
stays refused, by D4024's rule that a literal adapts only within its kind.
