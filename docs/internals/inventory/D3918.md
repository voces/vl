### D3918 — a local lambda inside a generic, named like a top-level generic function, is read as that function when delivered

**check-clean invalid wasm · found in review of #3484 (`rv3484/m/m08_shadow_bind`; m09 and m10 are the controls) · filed 2026-10-09 against master `09d7de908`**

Repro:

    function b<U>(y: U) { print(y) }
    function a<T>(x: T) {
      const b = (t: T) => print("local")
      const h: (t: T) => void = b
      h(x)
    }
    a(2.5)
    a("s")
    // vl check: rc 0.  vl run: the emitted module failed to validate inside `__lambda_5`: expected (ref $type), found f64

Want:

    local
    local

#### Mechanism

Not located. The delivery of `b` at `(t: T) => void` resolves the name to the top-level generic
`b` and instances it, although the local `const b` shadows it, so the local lambda is built at the
wrong signature.
