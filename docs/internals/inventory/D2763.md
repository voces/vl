### D2763 — a closure capturing a bare copy of a `for-in` variable inside a generic stores the copy as `i32` in its environment

**closed 2026-09-27 — the repro RUNS and prints `p` · was check-clean invalid wasm inside `run`, `expected i32, found (ref $type)` · identical on master `f6db92e0d` · filed 2026-09-27 from the #3181 review**

Repro:

    function run<T>(xs: T[]) {
      for x in xs {
        const c = x
        const f = () => c
        return f()
      }
      xs[0]
    }
    print(run(["p", "q"]))

#### Mechanism

`captureValKind` types a captured binding from its declaration, and an un-annotated `const c =
x` is classified through `letInitCellKind`, which reads `x`'s cell from the frame's locals. The
type section runs with no frame's locals bound, and the recorded type of `x` inside a generic
is the template's `T`, so the env field fell to `i32` while the local `c` was the string it
holds. Closed by typing a captured bare copy of a `for-in` variable exactly as a capture of the
variable itself (`captureLoopCopySrc`), which `captureLoopVarIterOf` already types off the
loop's iterable, in both `captureValKind` and its slot twin `captureValStructIdx`. A boxed
element (`(i32 | null)[]`) is left out: the closure's narrowed reads of the copy still resolve
its union through the copy's own binding, and that is [D2523](D2523.md), which stays loud.

#### Ablation

| ingredient removed | outcome | needed? |
| --- | --- | --- |
| the copy (`const f = () => x`) | runs | **yes** |
| the generic (`run(xs: string[])`) | runs | **yes** |
| the ref element (`run([7, 8])`) | runs | **yes** — the `i32` default is right by accident |
| the direct call (`fs.push(() => c)`, called later) | same invalid module | no |
| the element type (`run([2.5, 1.5])`, `f64`) | same invalid module | no |
