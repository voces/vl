#### Mechanism

`emitOptMemberValue` dispatches on the result's rep and now carries an arm for every leaf
family but this one: the wide-scalar box, the value-union box, the string niche, the
nested-struct niche and every list wrapper. A map field's storage is `mapTypeIdxOf(refSlot)`,
which `optChainLeafRefHeap` does not read — the slot resolution for a map field lives on
another table than the ref-list one the helper walks, so the arm declines rather than
guessing a heap type.

Whether `{[string]: i32} | null` is a rep the language HAS is the open half: the niche would
be the map struct's own nullable ref, exactly as a list wrapper's is, but no other position
produces one today, so building the `?.` arm alone would mint the first.

Both faces refuse identically, so inference is not an ingredient.
