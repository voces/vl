### D14568 — an instance's or captured frame's binding keeps its type variable in the held type

**runs today and must keep running · refutation pin for the literal-atom Ident arms reading the binding's held type · filed 2026-10-27 against master `c073bbc52` plus #5047**

Repro:

    type K = "a" | "b"
    function h<T0, T1>(a0: T0, a1: T1, k: i32) {
      const f = (j: i32) => if j == 0 { a0 } else { a1 }
      print(f(k))
    }
    const z0: K = "b"
    h(z0, 4, 0)
    h(z0, 4, 1)
    function m<T>(a: T) {
      const r = a
      const g = () => r
      print(g())
    }
    m(z0)
    // vl check: rc 0.  vl run: prints b, 4, b

Want:

    b
    4
    b

#### Mechanism

The program runs because the literal-atom Ident arms answer a `let` from the slot its frame
collected, else the binding storage column (D14569), and a parameter from its annotation. An
arm-by-arm shadow (each arm against `repOfNodeAt` over the binding's held type) disagrees here: the arm says the read is a literal atom, and the
held type of `a0` inside the lambda, `a` at `m`'s instance, and the captured `r` is still the
TyVar, so the rep layer reports it uncovered. The same split shows on the let, captured-let,
module-let and parameter arms of `generics/coalesce-join-tag-in-instance`,
`hole-pin-nullable-literal-union`, `lambda-join-literal-union-pin`,
`join-gated-list-and-lambda`, `one-union-nullable-literal-pin-prints-member`,
`hole-lambda-join-of-two-holes-first-arm`, and on the narrowed reads of `hole-map-read-atom-value`,
`instance-call-of-nullable-literal-union-function` and `pin-non-null-dead-null-test`. The gap is
the producer: `letBindTy` and the parameter type at an instance or captured frame should be the
instance's substituted type. A reader-side TyVar resolve would be a second producer.

#### The held type moves after storage is chosen

The same producer gap has a second shape. An instance binding's held type changes across
type-collection generations after its storage was chosen. In
`scripts/silent-sweep/distilled/named/d3281_join_tp_K_num_bind.vl`, `r` at the `g` instance
is collected at generation 2, when `letBindTy` reads `"a" | "b" | i32`, so its slot is a
union box. At generation 3 the same binding reads `K`, which is the atom. The
`d3281_join_tp_AB_num_*` cells, `d3281_join_tp_K_num_retbind` and
`generics/coalesce-join-at-literal-union-pin` split the same way. They run because the
literal-atom arms read the slot the frame recorded before they consult the storage column;
reading the column first makes them invalid wasm. The column refills each generation, which
is correct for a memo but is not a fix for this. The fix is for the producer to give the
binding its final instance type before storage is chosen.
