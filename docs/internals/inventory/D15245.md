### D15245 — a direct call through a call-bound binding's widened function field is not noted as a call through the set, so the set stays a closure

**open · loud emit reject · `emitProgram: cannot take the generic function id0 as a value — a function value carries ONE signature` · clause 2 · the bound read (`const g = r.f; g(2)`) runs since D15270 · found grading D15270's two-caller witness · filed 2026-11-04 against master `ccfdb7a33` with D15270**

Repro:

    function id0(a) { return a }
    function id1(a) { return a }
    function mk() { return { f: id1 } }
    const r = mk()
    r.f = id0
    print(r.f(2))
    print(r.f(2.5))

Want:

    2
    2.5

#### Mechanism

`r`'s record is widened to `{f: <set {id0, id1}>}` (D15270), but the call `r.f(2)` never reaches
`holeSetCallRetOf`, so `fnTagCallNote` records no set for it. `ftPlan` for the widened set then
fails at `ftCtxOk`, whose callee arm needs `fnTagCallSetOf(call) == s`, the set stays a closure,
and the write `r.f = id0` takes the generic `id0` as a value. Measured with an instrumented
one-level seed. The binding's own literal (`const r = { f: id1 }`) reaches the note and runs.

| a second, unwritten caller (`const s = mk()`) | still refuses | no |
