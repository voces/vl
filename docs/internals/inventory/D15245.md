### D15245 — a direct call through a call-bound binding's widened function field builds the returned literal at its one instance, so the set stays a closure

**closed · runs · was loud emit reject `emitProgram: cannot take the generic function id0 as a value — a function value carries ONE signature` · clause 2 · the bound read (`const g = r.f; g(2)`) runs since D15270 · found grading D15270's two-caller witness · filed 2026-11-04 against master `ccfdb7a33` with D15270 · closed by `holeFieldCallAdopt` declining a call-bound binding's widened field**

Repro:

    function id0(a) { return a }
    function id1(a) { return a }
    function mk() { return { f: id1 } }
    const r = mk()
    r.f = id0
    print(r.f(2))
    print(r.f(2.5))

Want:

    2
    2.5

#### Mechanism

`r`'s record is widened to `{f: <set {id0, id1}>}` (D15270), and the call `r.f(2)` is typed
through that set and noted (`fnTagCallNote`). This row first said the note was missing, after an
instrumented one-level seed; a re-measure logging without `tErr` shows it present. What failed
is the smaller set `{id1}` of `mk`'s literal, which `ftPlan` decides with the wide one: the
field call ran `holeFieldCallAdopt`, which built the receiver's source records, `mk`'s literal
among them, at the call's one closed instance, so the literal's field was a closure, its
`ftRecHolds` check failed, and both sets stayed untagged. The bound read has no field call, so
it adopted nothing. `holeFieldCallAdopt` now declines a receiver bound by a call, directly or
through `const` copies, whose field the elaboration widened.

#### Ablation

| ingredient removed | outcome | needed? |
| --- | --- | --- |

| the direct call (`const g = r.f; g(2)`) | runs (D15270) | **yes** |
| a second, unwritten caller (`const s = mk()`) | still refuses, D15273 | no |
