### D17641 — a kept maker's call in a list handed to a generic identity, beside its own-type instance, delivered at the wider record is invalid wasm

**closed 2026-11-26 by SOUND · runs, prints `13`, the start body claimed under `VL_IR_STRICT=1` · was check-clean invalid wasm, clause 1 · a parameter listing a type parameter (`xs: T[]`) now keys the generic's instance at the elaboration's binding (`monoPreBindNonArrowArgs`), since the list's elements keep the rep they were built at across the call, and where that binding differs from the check's the call takes its instance's result type, which a read of the call (`[0]`) reads · the rule for every call, instance bodies included, is [D17574](D17574.md) · pinned by `tests/cases/generics/kept-maker-list-to-generic-beside-own-type-instance.vl`**

    function mk() { return { r: null } }
    const own = [{ r: null }]

    // vl check: rc 0.  vl run: invalid module at 6:1, expected (ref null $3) `{r:null}[]`, found (ref $1) `Circle[]`

#### Mechanism

The check and the elaboration key `keep`'s one instance apart (`$VL_INST_KEYS=1`):
`check-only keep 9|T={r: null}` and `elab-only differs keep 9|T={r: i32 | null}`. The
elaboration builds the list argument at `Circle[]`, the row `mk()` is kept at. The emitted instance
takes the check key's `{r:null}[]` for its parameter. With no own-type list, `{r:null}` has no row of
its own, so the two lower alike and the module validates.
