### D3919 — a map field over a type parameter, inside a record annotated in a generic body, has no interned map slot

**closed 2026-11-11, runs and prints `s` · was loud emit reject, clause 2, `emitProgram: map value type has no interned slot` · found by D3916's position matrix (`m_in_rec__*`) · filed 2026-10-09 against master `09d7de908` · closed in `collectAnnShapes` (emit_collect.vl): an annotation with no recorded type is no longer shape-walked, so the generic original's `{ m: Map<string, T> }` no longer mints a row by its spelling · fixture `tests/cases/generics/record-map-field-over-type-param-in-generic-body.vl` · not reached: the same record with a function-valued map (`Map<string, (t: T) => void>`) still refuses with the same message**

Repro:

    function a<T>(x: T) {
      const r: { m: Map<string, T> } = { m: Map() }
      r.m.set("k", x)
      const g = r.m.get("k")
      if g != null { print(g) }
    }
    a("s")
    // vl check: rc 0.  vl build: emitProgram: map value type has no interned slot

Want:

    s

#### Mechanism

The generic original's record annotation has no recorded type. `collectAnnShapes` walked it by
its spelling and minted the record's row with a map field whose value is the open `T`. Not
walking an untyped annotation closes it, so that row was what the instance's map lookup
failed on. The same record in a non-generic function runs, and so does the map as a plain
annotated local in a generic.
