### D1730 — `xs[i]` with a `const i` accepts the `is` test and then refuses the read it narrowed, telling the author to do the thing they did

**loud check reject · filed 2026-09-06 against master `5530f6132` · found grading D1719's
close; 12 of that grid's 104 cells · 0 corpus cells · ruled (a) by the owner 2026-09-06 —
a `const` index may key, never a `let`, and only over the built-in index · the MESSAGE half of
that ruling landed 2026-09-06; the KEY half is blocked on the emitter's twin, below**

Repro:

    type A = { r: i32 }
    type M = i32 | A
    function st(): A { return { r: 8 } }
    function pick(b: boolean): M { if b { return st() } return 7 }
    const xs: M[] = [pick(true)]
    const i = 0
    if xs[i] is A { print(xs[i].r) } else { print(0) }
    // vl check: rc 1,
    // field 'r' is not on every member of M — narrow with `is` first (i32 is not an object)

#### Mechanism

A narrowing key is a SPELLING. `placeKeyOf`'s index arm takes `subscriptKeyTextOf`, which
answers only for an integer or string LITERAL — deliberately, since the key is compared as
text and `xs[0]` and `xs[00]` are two keys rather than one. A name subscript answers "", the
place has no key, and no narrowing is recorded for it.

**Whether a NAME may key a place is a design question this row does not decide.** Both
directions have a real argument: a `const` binding of an integer literal is as stable a
cell address as the literal is, and the emitter's own `retireNarrowForIndexCells` already
handles a write invalidating a cell — against which, a key derived from a name needs a
definite-assignment argument the narrowing stack does not make today, and `let i` would need
to be excluded by a rule that does not exist yet.

**The MESSAGE is wrong either way, and that half is not a design question.** The `is` test is
accepted — the same program with `print(8)` in the then-branch runs — so the checker admits
the narrowing expression and then tells the author to write it.

#### Ablation

| spelling | outcome |
| --- | --- |
| `xs[0]` (an integer literal subscript) | **runs**, prints `8` |
| `xs[i]` with `const i = 0`, read in the branch | check reject, `narrow with `is` first` |
| `xs[i]` with `let i = 0`, read in the branch | check reject, identical message |
| `xs[i]` with `const i = 0`, `print(8)` in the branch | **runs**, prints `8` |
| `const v = xs[i]` then `if v is A { v.r }` | **runs**, prints `8` |

#### What landed, and what the key half still needs

The MESSAGE is corrected: the refusal now names the subscript instead of prescribing the `is`
the program already carries — *"the `is` test was accepted; what it could not narrow is the
READ, because `i` is not a literal subscript and so names no one cell. Bind the element first:
`const v = …[i]`, then test and read `v`"*. It fires for every name subscript, so a `let` index
keeps its refusal WITH the reason, which is the half the ruling made unconditional.

The KEY half was built and reverted, measured rather than predicted. `placeKeyOf`'s index arm
takes a `const` name (`isConstName`) over a built-in-indexed receiver and spells `xs[#i]`, a key
a literal can never collide with. The checker then ACCEPTS the read — and the program is
**check-clean invalid wasm**, because the emitter's twin `indexPathKeyOf` still keys only a
literal, so the narrowed read lowers un-narrowed. Widening the emitter's twin is not a mirror
edit: `indexPathKeyOf` lives in `emit_base` and is deliberately frame-free (a pure spelling
function), while `isConstName` is a scope question, and the two keyers must agree exactly or the
emitter narrows what the checker did not. That is the unit of work the key half needs.

#### Grading list

The five ablation rows, plus the three the key half added: a write to the container between the
test and the read (refused by the narrow itself, exactly as the literal-subscript twin
`xs[0] = 7` is), a write to a DIFFERENT cell (`xs[j] = 7`, which the literal twin allows), and
a user-defined `"[]"` receiver, which must keep refusing — index dispatch is user-definable and
a user `"[]"` is a call, never a place. A close that admits the name has to state its rule for
`let i`, for a re-assigned `i`, and for a write to `xs` between the test and the read; the
LITERAL-subscript spelling is the oracle for all three.
