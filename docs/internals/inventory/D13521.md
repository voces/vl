#### Mechanism

The `let` twin of D13320. `forElemArgCstrs` (check_calls.vl) moves the other elements' hole
demands to the caller's holes for a list literal in the `for` header or bound to an
un-annotated `const` (`ctnLitInitOf`), and a `let` reaches neither: a `let` list may be
written or reassigned before the loop, so its literal is not the list the loop walks. A fix
has to decide which writes still leave the elements known (`listElemsWritten` is the
existing reader for element writes).
