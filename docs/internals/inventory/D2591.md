### D2591 — a value `if` whose arm declares a local refuses anywhere but a binding initializer or a `return`, because the collect pass walks only those two positions

**loud emit reject · `vl check` rc 0, clause 2 · the remainder of D2052 · filed 2026-09-26
against master `ed81f8d55`**

Repro:

    function id(x: i32): i32 { x }
    function f(n: i32): i32 {
      return id(if n == 1 {
        const t = n * 5
        t
      } else { 7 })
    }
    print(f(1))
    // vl check: rc 0.  vl run: emit error — an if-expression arm that declares a local is
    // supported only as a binding initializer inside a function (at `const t`)

#### Mechanism

An arm's locals get their slots from `collectLocals`, which reaches an if-expression only as a
binding's initializer or a `return` operand (`collectIfExprLocals`). The emitter takes local
slots from a cursor in the order the collect pass allocated them, so an arm nested anywhere
else in an expression has no slots and `emitIfArmOpen` refuses it. D2052's close lowers every
arm that binds nothing, and positions this refusal at the binding rather than at the function.
The build item is an expression walk in the collect pass that visits nested if-expressions in
the order `emitExpr` reaches them; a desugared `match` arm that binds its pattern is the
common way to reach it (`tests/cases/match/error-binding-arm-nested-in-expression.vl`).

#### Ablation

| ingredient changed | outcome | needed? |
| --- | --- | --- |
| `const t = n * 5; t` → `print(0); n * 5` (no local) | runs, prints `0` then `5` | **yes** |
| `return id(if …)` → `const v = if …` then `return id(v)` | runs, prints `5` | **yes** (the position) |
| the argument → a binary operand, an array element, a field, a condition | still refuses | no |

The two `error-binding-arm-*` fixtures under `tests/cases/match/`, which pin this refusal
today, and D2052's 40-cell grid with a `const` added to each prelude.
