### D5001 — a closure in a generic body that calls a generic function at an explicit `<V>` has no parameter valtype

**closed 2026-11-06 — now prints `1` · was a loud emit reject, clause 2 · the lambda's call is keyed by the elaboration's call-time key, which binds `W` to the enclosing instance's `V`, rather than by mono's pin of the explicit `<V>` · found closing [D4982](D4982.md) · filed 2026-10-15 against master `2f625f31e` · pin: `tests/cases/generics/closure-calls-generic-at-enclosing-explicit-type-arg.vl`**

Repro:

    function lenG<W>(xs: W[]) { xs.length }
    function t<V>(a: V[]) {
      const k = () => lenG<V>(a)
      print(k())
    }
    t([1])
    // vl check: rc 0.  vl run: prints 1

#### Mechanism

The explicit type argument names the enclosing function's type parameter, and the call
inside the lambda reaches the parameter valtype ladder with `V` itself rather than its
instance's binding, so `lenG`'s instance has no parameter type to lower. The inferred call
binds through the argument and runs.
