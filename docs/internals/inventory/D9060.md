Repro:

    function inc0(a) { return a + 1 }
    function half(a) { return a / 2.0 }
    const xs = [inc0]
    xs[0] = half
    print(xs[0](3))
    // vl check: cannot write 'half' to an element of 'xs': called at (i32) it returns f64,
    // where 'inc0', also written to it, returns i32.  Was: vl check rc 0, vl run traps.

#### Mechanism

The element's type is taken from the literal `[inc0]`, `(i32) => i32`; the
write `xs[0] = half` stores `half`'s `(i32) => f64` instance in that slot, and the call
through it expects the first signature. A re-pointed `let` written with the same pair is
refused by the checker (`cannot write 'half' to 'f': called at (i32) it returns f64,
where 'inc0', also written to it, returns i32`, D9003/D9008); the element and field writes
had no such check.

#### Close

Refused at check, as D9003 refuses the `let`. One slot holds one function signature, and
every annotated twin is already a check refusal (`cannot assign (i32) => f64 to (i32) =>
i32`; `push: cannot add (i32) => f64 to ((i32) => i32)[]`), so there is no conversion at
the write for the un-annotated spelling to run by. A call whose callee is a list element or
a field now reaches `holeLetWritesDisagree`, which peels the callee to its root binding
(`cwSlotPath`), collects every function the literal put at that place and every later write
or `push` to it (`cwSlotWrittenValues`), and judges each WRITTEN function's body at the
call's argument types against the earliest one. A literal's own functions are not judged:
`[inc0, half]` with no write keeps running where it ran on master.
