### D9060 — an un-annotated function with another result, written over a list element or record field that holds one, is called at the first function's signature

**loads then traps · `vl check` rc 0 · `wasm trap: indirect call type mismatch` · clause 1 · found closing [D4579](D4579.md) and [D9040](D9040.md) · present on master `16cf779bd` · filed 2026-10-21 against master `16cf779bd`**

Repro:

    function inc0(a) { return a + 1 }
    function half(a) { return a / 2.0 }
    const xs = [inc0]
    xs[0] = half
    print(xs[0](3))
    // vl check rc 0.  vl run: wasm trap: indirect call type mismatch

#### Mechanism

Not traced. The element's type is taken from the literal `[inc0]`, `(i32) => i32`; the
write `xs[0] = half` stores `half`'s `(i32) => f64` instance in that slot, and the call
through it expects the first signature. A re-pointed `let` written with the same pair is
refused by the checker (`cannot write 'half' to 'f': called at (i32) it returns f64,
where 'inc0', also written to it, returns i32`, D9003/D9008); the element and field writes
have no such check.

#### Ablation

| ingredient removed | outcome | needed? |
| --- | --- | --- |
| the list (`const r = { f: inc0 }`, `r.f = half`, `r.f(3)`) | same trap | no |
| the second result (`half` replaced by `function dbl(a) { return a * 2 }`) | runs, `6` | **yes** |
| the write (`const xs = [half]`, `xs[0](3)`) | runs, `1.5` | **yes** |
| the un-annotated element (`const xs: ((a: i32) => i32)[] = [inc0]`) | check refuses, `cannot assign (_) => _ to (i32) => i32` | **yes** |

#### Grading list

The record-field spelling in the ablation above.
