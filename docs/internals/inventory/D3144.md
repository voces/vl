### D3144 — a null argument to a record-pattern generic, with a declared record sharing the pattern's field names, builds the instance at the wrong layout

**closed · a composite pattern substituted at an `#anonN` binding spells that binding by its row's own shape where the shape resolves back to the same row (`monoSubstAnonShapes`) · fixture `tests/cases/generics/null-arg-to-record-pattern-beside-declared-record.vl` · was check-clean invalid wasm · clause 1 · pre-existing on master `fc4b2159f` · found by the #3278 round-3 review · filed 2026-09-29 against master `fc4b2159f`, closed 2026-09-29 against master `995bbc74e`**

Repro:

    import { toString } from "std:fmt"
    type D = { m: string, n: i32 }
    function g<T>(b: { m: T, n: i32 } | null, d: T): T { if b != null { b.m } else { d } }
    const b = g(null, { x: 0, y: 5 })
    print(toString(b.y))
    // vl check: rc 0.  vl run: invalid module inside `g$m0`

Want:

    5

#### Mechanism

`T` binds from `d` to the argument's handle `#anon2`, and the pattern substitutes to
`{m:#anon2,n:i32}|null`. A handle inside a record spelling resolves to nothing, so the lenient
field-set scan in `structIndexOfTypeName` claimed the declared `D` (`m: string`) and the
instance read `b.m` at D's layout. The explicit type argument spelled `{x:i32,y:i32}` there and
ran. The pin is now re-substituted with each `#anonN` binding spelled by its row's own shape,
kept only where that shape resolves back to the same row, so the pattern names the right
layout. The same program without `type D` refused loudly on master and now runs too.

#### Ablation

| ingredient changed | master `fc4b2159f` | needed? |
| --- | --- | --- |
| an explicit type argument `g<{ x: i32, y: i32 }>(null, …)` | runs, `5` | **yes** (inference through the `null` call) |
| `type D` removed | `only i32, i64, f64, f32, boolean, struct, union, array, or string parameters are supported` | **yes** (the declared record) |

#### Price

#3278 unmasks this at a second spelling. With an earlier call that passes a record literal,
`const a = g({ m: { x: 1, y: 2 }, n: 2 }, { x: 0, y: 0 })`, before the witness's call, master
refused at that earlier call (`monomorphize: unsupported argument type for 'b'`). #3278 pins
that call and reaches this defect in `g$m0$1` instead, so that program moves from refused to
check-clean invalid wasm.

#### Grading list

The witness, the unmasked two-call program above, and the explicit-type-argument control.
