### D3352 — a binding declared in a returned if-expression's arm clears the return's nullable seed, so the arm's nullable value is read as non-null

**closed 2026-09-30 (`emitLetDeclStmt` in `compiler/wasmEmit.vl` restores the enclosing value's niche seeds after a binding's initializer instead of clearing them) · was loads then traps · filed 2026-09-30 against master `455e553ca` · fixtures `tests/cases/conditionals/return-if-arm-local-nullable.vl`, `tests/cases/loops/loop-value-runs-out-returned.vl`**

Repro:

    function hv(n: i32) {
      return if n > -5 {
        let z: string | null = null
        if n == 1 { z = "b" }
        z
      } else { null }
    }
    print(hv(1))
    print(hv(7))
    // vl check: rc 0.  vl run: prints b, then traps: a null value was used where a non-null one was required

Want:

    b
    null

#### Mechanism

A `return` of a `string | null` value seeds `pendingNulString` for the value it emits, and an
if-expression's arms inherit it. A `let` in an arm's prelude set its own niche seeds for its
initializer and then reset them to `false`, which cleared the return's seed before the arm's
tail was read, so the tail read the nullable local into a non-null string context and recovered
it with `ref.as_non_null`. The `let` now restores the seeds it found. A `for` loop value in
`return` position lowers to exactly this shape, so `return for … { break "b" }` trapped when
the loop ran out.

#### Ablation

| ingredient removed | outcome | needed? |
| --- | --- | --- |
| the `return` (the if-expression as the function's tail) | runs | **yes** |
| the arm-local binding (the arm reads a `string \| null` parameter) | runs | **yes** |
| the assignment in the arm (`let z: string \| null = null` then `z`) | same trap | no |
| the null else (`else { "q" }`) | same trap | no |
| bound first, then returned (`const r = if …; return r`) | runs | **yes** |
