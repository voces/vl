### D17000 — [CLOSED 2026-11-19] a call through a list of un-annotated functions with different results, before a lambda is written into the list, is typed at one member's result and builds invalid wasm

**closed 2026-11-19 · runs, prints `1.5` · fixed in check_relate_core.vl: `holeSetCallRetOf` types a call ahead of a later lambda member by the members already checked, and `holeSetEarlyCallsJudge`, once every body is checked, records the lambda's result as its arm's or refuses where the call's type cannot take it (`this call is typed … write the lambda before this call`) · pins `closures/set-call-before-later-lambda-member.vl`, `closures/error-set-call-before-later-lambda-of-wider-result.vl`; matrix `hole-lambda-in-record-of-tagged-set` cells `call_before_push_*` · was check-clean invalid wasm, clause 1 · found by lane F2 grading [D16937](D16937.md)'s fix · filed 2026-11-19 against master `938930861`**

Repro:

    function inc0(a) { return a + 1 }
    function half(a) { return a / 2.0 }
    const xs = [inc0, half]
    print(xs[1](3))
    xs.push((x) => x * 3)

Want:

    1.5

#### Mechanism

Before the close, `holeSetCallRetOf` (check_relate_core.vl) gave up on a set whose member is a
lambda not yet checked, "typed by its own callee, and each arm takes its member's result when it is instanced",
so the call was typed at the element's own instance, `i32`. The set is tagged with the lambda,
and the dispatch builds each arm at its member's result: `half`'s `f64` arm has no conversion
into the call's `i32`. The same lambda written before the call runs.

#### Grading list
