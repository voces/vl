### D15190 — a record's list field written a function of another result type through an un-annotated parameter is refused at emit

**closed 2026-11-14 · runs, prints `1.5` · was loud emit reject, `the function written to this element returns another type than the element's`, and loud check reject, `cannot write 'half' to an element of 'r.xs'`, before D15138 · clause 2 · found closing [D15138](D15138.md) · filed 2026-11-03 against master `d467911e` · closed by `fnTagWriteLeavesOf` (check_elab_cap.vl), which reads each record field `elabFnFieldTy` widened at its place path as it reads a widened list, and takes a write as the leaf only where its target is that place · fixtures `closures/record-fn-list-field-written-other-result-through-param.vl`, `closures/record-fn-list-field-read-then-written-other-result-through-param.vl`, `closures/record-fn-list-field-two-elements-one-written-other-result-through-param.vl`**

Repro:

    function inc0(a) { return a + 1 }
    function half(a) { return a / 2.0 }
    function put(o) { o.xs[0] = half }
    const r = { xs: [inc0] }
    put(r)
    print(r.xs[0](3))

Want:

    1.5

#### Mechanism

`elabFnFieldListTy` sees the write through `o` (its write summary follows the record into the parameter, as [D14648](D14648.md)'s list summary does), so the field widens and the check passes, but the decision takes no leaf for `half`: D14648's write leaf (`fnTagWriteLeavesOf`) reads only list bindings, not a record's field.

Late demand: the root call `put(r)` instances `put` at `r`'s own type after `elabRun` returns,
on master as here, as [D15136](D15136.md)'s list does. `late-demands-baseline.txt` counts it once
per fixture, through `closures/error-record-fn-list-field-read-before-write-through-param.vl` and
`closures/error-record-fn-list-field-two-elements-one-written-through-param.vl`. Typing the field
at its one call signature prints `1.5` here and traps in both fixtures, which read `inc0` from the
field. So a fix needs a per-element rep, not the delivered type. The mint exists only on this
refusing build and goes with this row's fix.

#### Close (2026-11-14)

`elabFnFieldTy` now records, beside each widened field, its place path from the binding (`xs`,
`[]`) and the joined element type. `fnTagWriteLeavesOf` reads those as it reads the widened
lists: a write of the member stored at that path of the binding, or of a parameter every call
hands the binding, is the member's leaf, typed as the element. The fields read before the write
and the element left alone keep their own function, now a member of the joined set, so both
fixtures that trapped when the field was typed at its call signature print the right values.
