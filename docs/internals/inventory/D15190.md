### D15190 — a record's list field written a function of another result type through an un-annotated parameter is refused at emit

**loud emit reject · `the function written to this element returns another type than the element's` · clause 2 · open, target `1.5` · was loud check reject, `cannot write 'half' to an element of 'r.xs'`, before D15138 · found closing [D15138](D15138.md) · filed 2026-11-03 against master `d467911e`**

Repro:

    function inc0(a) { return a + 1 }
    function half(a) { return a / 2.0 }
    function put(o) { o.xs[0] = half }
    const r = { xs: [inc0] }
    put(r)
    print(r.xs[0](3))
    // Want: 1.5

#### Mechanism

`elabFnFieldListTy` sees the write through `o` (its write summary follows the record into the parameter, as [D14648](D14648.md)'s list summary does), so the field widens and the check passes, but the decision takes no leaf for `half`: D14648's write leaf (`fnTagWriteLeavesOf`) reads only list bindings, not a record's field.

Late demand: the root call `put(r)` instances `put` at `r`'s own type after `elabRun` returns,
on master as here, as [D15136](D15136.md)'s list does. `late-demands-baseline.txt` counts it once
per fixture, through `closures/error-record-fn-list-field-read-before-write-through-param.vl` and
`closures/error-record-fn-list-field-two-elements-one-written-through-param.vl`. Typing the field
at its one call signature prints `1.5` here and traps in both fixtures, which read `inc0` from the
field. So a fix needs a per-element rep, not the delivered type. The mint exists only on this
refusing build and goes with this row's fix.
