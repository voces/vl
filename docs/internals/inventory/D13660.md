### D13660 — a lambda that captures a hole function parameter and hands it to a generic has no monomorphized argument type

**loud emit reject · `vl check` rc 0 · clause 2 · CAPABILITY: the same call made directly in the enclosing function runs, and so does the lambda calling the captured function itself · found by lane L1 closing [D13520](D13520.md) · present on master `3e3b18500` · filed 2026-10-25 against master `3e3b18500`**

Repro:

    function add(a, b) { return a + b }
    function apply2(g, s) { print(g(s, s)) }
    function outer(h) {
      const run = (x) => { apply2(h, x) }
      run(1.5)
    }
    outer(add)
    // vl check: rc 0.  vl run: emitProgram: monomorphize: unsupported argument type for `g` in a call to `apply2`

Want:

    3

#### Mechanism

Not measured past the ablation. The call `apply2(h, x)` sits in a function nested in
`outer`, and `h` is `outer`'s hole parameter reached through a capture; the monomorphizer
types `apply2`'s `g` from the call's argument and finds no type for a captured hole. A
named nested function refuses the same way, so the lambda is not the ingredient; the
capture is.
