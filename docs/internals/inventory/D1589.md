### D1589 — a hole READ BEFORE ITS FILL banked the hole itself, and a tail `if c { x = 5 }` re-boxed a cell that was already a box

**closed 2026-09-04 — the witness runs and prints `0` · was `check-clean invalid wasm` (`vl check` rc 0, `type mismatch: expected (ref null $type), found i32`) · clause 1 · TWO mechanisms, both required: the `??` over an OPEN A-infer-null hole now answers with its DEFAULT's type and is re-derived at the fill, and an ASSIGNMENT's union-ness is its TARGET CELL's · named as residue (c) on [D1576](D1576.md) (#2513)**

Repro (prints `0`):

    function go(c: boolean) {
      let x = null
      print(x ?? 0)
      if c { x = 5 }
    }
    go(true)

#### Mechanism

Two, in one witness. The ablation separates them: remove the `??` and the program still
refuses (mechanism A alone); move the fill to module scope, where there is no inferred
return, and it still refuses (mechanism B alone).

**A — an assignment's value is its TARGET CELL, and `exprUnion` had no arm for it.** An
else-less tail `if` is a valued return, so `function go(c) { let x: i32 | null = null; if c
{ x = 5 } }` returns `i32 | null` — and `fnAssignRetKind` already gives the functype the
CELL's kind, which for `i32 | null` is the value-union BOX. `emitBinExprNode` lowers the
assignment-as-expression as store-then-RE-READ, so the value it pushes IS `emitExpr` of the
target: the box. Nothing told `emitUnionCoerce` that. Its `exprUnion` raw-pass had a `??`
arm and no `=` arm, so the node fell to the scalar ladder and was boxed a second time:

    before  (return (struct.new $0 (i32.const 0)
              (block (result (ref (exact $1)))
                (local.set $1 (struct.new $0 (i32.const 0) (struct.new $1 (i32.const 5))))
                (struct.new $1 (local.get $1)))))     ;; field i32 <- (ref $0)
    after   (local.set $1 (struct.new $0 (i32.const 0) (struct.new $1 (i32.const 5))))
            (return (local.get $1))

`struct.new $1` takes `(field i32)` and got the box: `expected i32, found (ref $type)`.
`exprUnion` now delegates an `=` node to `e.binLeft`, which is the same expression the
re-read emits — one question, so the two cannot disagree.

**B — `nonNullTy` of an OPEN hole hands back the NULLABLE, and the bank then ALIASES the
node the fill mutates.** `let x = null` binds `mkNullableTy(-1)`; D1575 made `nonNullTy`
bound-test the `-1` inner by RETURNING `cur`, so a `??` typed before the fill got the hole
itself as its result type. `checkNode` banks that arena index; `x = 5` later writes
`nInner` IN PLACE, and the banked node silently becomes `i32 | null`. Every emit-side
consumer keyed on the node type (`unionNameOfExpr` → `exprUnion` → `print`'s tag dispatch)
then built a BOX destination for an expression `emitCoalesce` lowers UNBOXED:

    before  (local.set $3            ;; $3 : (ref null $0), print's box temp
              (if (result i32) (i32.eq (struct.get $0 0 (local.get $1)) (i32.const 6))
                (then (i32.const 0))
                (else (struct.get $1 0 (ref.cast (ref $1) …)))))
    after   (call $fimport$0         ;; __print_i32__, no temp at all
              (if (result i32) (i32.eq (struct.get $0 0 (local.get $1)) (i32.const 6))
                (then (i32.const 0))
                (else (struct.get $1 0 (ref.cast (ref $1) …)))))

The one answer a `??` over an open hole can always give is that the result is NOT NULL — a
non-null default is what the null path yields, whatever the hole becomes — so it now answers
with the DEFAULT's type and records the node. `fillCoalHoleNodes`, called the moment
`nInner` is written, re-derives the result against the resolved inner by the `??` arm's own
rule. It is a VALIDATION as much as a re-bank: the read has already been checked against the
answer it was given, so a fill whose inner does not fit that answer is REFUSED rather than
banked over — without that, `const r: i32 = x ?? 1` followed by `x = 9999999999` moved
`check refuses` → check-clean invalid wasm, trading a clause-2 refusal for a clause-1 one.
