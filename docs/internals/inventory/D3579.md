#### Mechanism

`bindScan` in `compiler/lint.vl` already resolves every name through a lexical scope stack,
so the rule is one probe of that stack when a `let`/`const` or loop variable binds: the
name's innermost visible entry sits at or above the enclosing function's stack mark. The
mark is reset at every `FuncDecl`, lambdas included, so a lambda's own bindings never
answer for the function around it and module-level names (below every mark) never answer
at all. A rebinding whose initialiser READ the binding it hides (`const x = x as f64`) is
skipped: the author demonstrably saw the outer one, which is the thing the rule asks. A chain
of re-shadowings of one name (`{ const m … { const m … } }`) reports its first link only:
D2188's witness nests 10,000 such blocks on one line, and one finding per link made `vl check`
print 9,999 excerpts of a 310 KB line and time out the witness grader.
