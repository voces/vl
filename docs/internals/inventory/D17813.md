#### Mechanism

The call `v(3)` through the parameter's read pinned the map's value slot at `(i32) => f64`, where
the members disagree, so no closed delivery served it and `monoStoredSlotFnTy` raised its internal
error. A read of a stored slot reads it at its stored rep, so that pin is no longer taken: the
stored values decide the slot, as an uncalled slot's do. What is left is the hand of `m`, stored
at its own rep, to the parameter's one instance, which [D17820](D17820.md)'s mechanism closes.
Pinned by `tests/cases/maps/error-function-map-keyed-read*-in-a-hole-parameter.vl`, which flip to
`@run` when it lands.

#### Outcome under D17833 (2026-11-28)

D17833's close (a tag dispatch arm typed by its member's result) does not reach these spellings:
the set is not tagged here, `g` takes its signature only from the read's pin inside `walk`, and
the writes leave `m`'s storage open. They stay loud refusals with no trap. Candidate mechanism:
an untagged set's map storage is closures, and an open hole lambda written into it is instanced
at the signature the slot's calls give it (the per-width lift at a map write, D17820's mechanism),
with `walk` keyed by type alone, so there is no cycle. Owner COV-CLOS-3, after D17832.
