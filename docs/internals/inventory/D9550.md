### D9550 — an inline call of a function with an un-annotated parameter, returning a list of un-annotated functions, read by `.map` calls an unknown function

**closed 2026-10-22 by lane-D9550 · runs, prints `6` · was loud emit reject, `call to unknown function`, `vl check` rc 0 · clause 2 · closed by walking a `.map` / `.filter` call's receiver, when it is a call or an index into one, before its callback is read, so the receiver call has taken its instance and its pin when the callback asks for it (`monoListCbRecvIsCall` from `monoWalk`'s `Call` arm, emit_mono.vl) · fixture `closures/hole-fn-list-returned-inline-call.vl` · residue [D9601](D9601.md) · found closing [D9501](D9501.md) · filed 2026-10-22 against master `6b307f6ac`**

Repro:

    function inc(a) { return a + 1 }
    function dbl(a) { return a * 2 }
    function deliver(n) { return [inc, dbl] }
    print(deliver(1).map((f) => f(3))[1])
    // vl check rc 0.  vl run: emit error: emitProgram: call to unknown function

Want:

    6

#### Mechanism

The `.map` receiver is typed from what `deliver` returns (`monoPinnedRetAnnTy`, emit_mono.vl),
which reads the pin of the returned literal's element slot `e`. `monoWalk`'s `Call` arm read the
callback (`monoCoerceListCbArg`) before it walked the receiver, so the inline call `deliver(1)`
had not yet taken its instance. The template's own frame banks the slot under each of its walk
contexts, the contexts disagree, and the read declined. Bound first, the call is walked as the
binding's initialiser, before any read of it.
