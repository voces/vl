### D9550 — an inline call of a function with an un-annotated parameter, returning a list of un-annotated functions, read by `.map` calls an unknown function

**loud emit reject · `vl check` rc 0 · `call to unknown function` · clause 2 · found closing [D9501](D9501.md) · present on master `6b307f6ac` · filed 2026-10-22 against master `6b307f6ac`**

Repro:

    function inc(a) { return a + 1 }
    function dbl(a) { return a * 2 }
    function deliver(n) { return [inc, dbl] }
    print(deliver(1).map((f) => f(3))[1])
    // vl check rc 0.  vl run: emit error: emitProgram: call to unknown function

Want:

    6

#### Mechanism

Partly traced. The `.map` receiver is typed from what `deliver` returns (`monoPinnedRetAnnTy`,
emit_mono.vl), which reads the pin of the returned literal's element slot `e` in `deliver`'s
frame. A probe on that read counted one pin with the parameter annotated (`n: i32`) and with the
call bound first (`const v = deliver(1)`), and zero pins for this spelling, so the flow table
banks the callback's pin of an inline call to a template somewhere the template's frame does not
read. Where it banks it is not traced.

#### Ablation

| ingredient removed | outcome | needed? |
| --- | --- | --- |
| the un-annotated parameter (`n: i32`) | runs, `6` | **yes** |
| the parameter (`deliver()`) | runs, `6` | **yes** |
| the inline call (`const v = deliver(1)`, `v.map(...)`) | runs, `6` | **yes** |

#### Grading list

The same inline read beside a second read: a `for f in deliver(true)` loop after it (same
refusal), or `const w = deliver(2)` read at `f64` after it, or a second inline
`deliver(2).map((f) => f(1.5))` (both refuse with `a generic function taken as a value reaches no
call that fixes its type`). The bound spelling at two types runs and must keep running.
