### D3656 — an `if` nested in an arm of an ANNOTATED return's join boxes its widened runtime tail at the tail's own type

**closed 2026-10-05 — the witness prints `true`, `-1.5` · was check-clean silently wrong, clause 1 · D3571's mechanism at the return position · found by the #3379 review (`rv79`) · filed 2026-10-05 against master `32b753681` · fixture `tests/cases/conditionals/if-nested-join-annotated-return.vl`**

Repro:

    function mk(q: i32 | null, r: i32 | null): i32 | f64 {
      if q != null { q } else { if r != null { r } else { 2.5 } }
    }
    const x = mk(null, -3)
    print(x is f64)
    print(x / 2)
    // master printed false, -1

Want:

    true
    -1.5

#### Mechanism

Confirmed. A value `if` in tail position of a function is lowered one return per arm
(`emitIfTail`/`emitIfLinkTail`, and in a sinking union function `emitUnionRetIfSink` with
`emitUnionRetIfArm`), and each of those recursed into an inner `if` the same way, so `r` was
returned, and boxed, at its own `i32`. The binding position had stopped doing that for an inner
join typed one wider number in #3379 (`ifJoinAdaptsScalar`); the return path had no such stop.
Fixed by `tailIfReturnsWhole` (wasmEmit.vl): where the function's result is a union box and an
`if` NESTED in an arm of the returned `if` (an arm's tail, an `else if` link, a match arm) is
such a join over an `i32` runtime tail, it is returned as one value, boxed once at its type. The
outermost returned `if` keeps one return per arm: each arm is delivered to the union result as
its own value, as `return q` would be, so `if q != null { q } else { 2.5 }` at `: i32 | f64`
still gives `is i32` for `q` (the #3387 review's blocker, where the first round also applied it
at the outermost `if`). An `f32` tail is left alone because a lambda's join over one can read
`f64` ([D3710](D3710.md)).
