### D9008 — a re-pointed `let` of un-annotated functions with different results, returned and called by the caller, traps

**closed · now a loud check reject, `cannot write 'half' to 'f': called at (i32) it returns f64, where 'inc0', also written to it, returns i32` · was loads then traps (`indirect call type mismatch`), `vl check` rc 0 · clause 1 · found closing [D9003](D9003.md) · present on master `145cabbc6` · filed 2026-10-21 against master `145cabbc6` · closed by `holeLetReadsOf` (check_relate_core.vl), reached from a call whose callee is a call or a list element (check_calls.vl) · fixtures `closures/error-written-let-of-hole-fns-results-differ-returned.vl`, `closures/error-written-let-of-hole-fns-results-differ-list-element.vl`, `closures/written-let-of-hole-fns-results-agree-delivered.vl`**

Repro:

    function inc0(a) { return a + 1 }
    function half(a) { return a / 2.0 }
    function get() {
      let f = inc0
      f = half
      return f
    }
    print(get()(3))
    // master: vl check rc 0, vl run: wasm trap: indirect call type mismatch.  now: cannot write 'half' to 'f': called at (i32) it returns f64, where 'inc0', also written to it, returns i32

#### Mechanism

D9003's refusal read the binding at the parameter types it is called at, and every such call
named the binding. Returned, the value is called as `get()(3)`, whose callee names no
binding, so neither function written to `f` was read at `(i32)`. `get`'s result type is
`inc0`'s signature.

Decision: the same refusal, at the write. A call of `get()` runs whatever `f` held when
`get` returned, so D9003's contract is broken exactly as in the direct call. A call whose
callee is itself a call now asks `holeLetReadsOf` for the bindings the callee may be read
from: the called function's returned values (`collectRetValues`), followed through `let`s,
aliases and parameters. The same walk reads a callee that is an element of a list bound once
to a literal (`xs[0](3)` with `const xs = [f]`), where any element may be the one called.
