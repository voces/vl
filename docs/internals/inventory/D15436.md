#### Mechanism

The tag decision declines the set at `ftInstLeafOk` (check_fn_tag.vl), per-instance identity slice 4b-i's rule for a lambda declared in an instanced body: it refuses any write of the binding from a nested function (`c == b && inFn`), since such a write could run outside the instance. Here `w1` is declared in the same body and never leaves it, so the cell and every id in it stay in one instance. Slice 4b-ii (per-instance-identity-2026-11.md) plans the elaboration's per-cell fact that says so.

Measured 2026-11-04 (not landed): admitting it in `ftInstLeafOk` takes three facts, all available at check time:
- a nested writer declared in the instanced body (`elabEncl`) whose every use is a call;
- a self-write `d1 = d1`;
- a copy `d3 = d1` into a `let` of the same body.

With those, the set is tagged and the build is check-clean **invalid wasm** with the split plan on and off: each generic instance still builds the capture cell at the closure type, and the ids are written into it. The decision may admit this only after the cell's element is the instance's rep.
