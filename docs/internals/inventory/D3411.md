### D3411 — a `<T>` read of an inner `boolean` map, reached through a map read off the parameter, prints the raw i32

**check-clean silently wrong · clause 1 · open · found by the #3318 review (`g2/r8t`) · the same on master `8df60e472`, where the hole spelling printed `1` too · filed 2026-09-30 against master `8df60e472`**

Repro:

    type Nm = { m: {[i32]: {[i32]: boolean}} }
    function mkN(): Nm {
      const inr: {[i32]: boolean} = Map()
      inr[1] = true
      const o: {[i32]: {[i32]: boolean}} = Map()
      o[0] = inr
      { m: o }
    }
    function use<T>(p: T) {
      const q = p.m[0]
      if q != null { print(q[1]) }
    }
    use(mkN())
    // PRINTS 1

Want:

    true

#### Mechanism

Not traced. The outer read `p.m[0]` resolves at the instance's binding (lane MH's `mapRecvTyIn`),
and the un-annotated spelling now prints `true`. The inner read is off the outer read's result,
bound (`q[1]`) or in place (`(p.m[0] ?? Map())[1]`), whose recorded type is a derivation two
levels deep; under `<T>` neither the exact binding nor the banked pin resolves it to the inner
`{[i32]: boolean}`, so the read takes the plain `i32` map's reading and `print` formats a number.
