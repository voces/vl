### D12704 — a `const` bound to one element of a list of hole functions, called at two function types, is refused

**closed 2026-10-25 by lane L1 · runs, prints `x2 2 y20 20` · a `const` bound to an element read holds that list's elements (`monoCalleeElems`, `monoCalleeListRead`, emit_mono.vl), and the per-type copy plan serves it as it serves a `for` variable, the read's index bound once ahead of the binder (`fsElemBinder`, `fsBindIndexCopy`, fn_split.vl) · pin: `tests/cases/closures/hole-fn-list-element-const-called-at-two-fn-types.vl` · was loud emit reject · `vl check` rc 0 · clause 2 · CAPABILITY: two reads `fs[i](cat)` and `fs[i](snd)` run ([D10701](D10701.md)) · found closing [D10791](D10791.md) · filed 2026-10-25 against master `a448ccb42`**

Repro:

    import { toString } from "std:fmt"
    function cat(a, b) { return a + b.toString() }
    function snd(a, b) { return b }
    function apply2(g) { print(g("x", 2)) }
    function apply3(g) { print(g("y", 20)) }
    const fs = [apply2, apply3]
    let i = 0
    while i < fs.length {
      const f = fs[i]
      f(cat)
      f(snd)
      i = i + 1
    }
    // vl check: rc 0.  vl run: emitProgram: a generic function is passed to a function value whose parameter type names a type parameter this closure does not bind

Want:

    x2
    2
    y20
    20

#### Mechanism

`f` is a `const` holding a list element rather than a `for` variable or an index
read, so the element calls (`monoCalleeElems`, emit_mono.vl) do not see through it, and `cat`
reaches the generic-function floor instead.
