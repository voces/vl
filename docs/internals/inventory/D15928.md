#### Mechanism

The tag decision declines `{inc0, half}` at the context check (`ftCtxOk`, check_fn_tag.vl, its
`FieldInit` arm), at `inc0` in the list's record literal `{ f: inc0 }`, a node of the split set.
`bs` carries an annotation the source has none of: record adoption (`recAdPinLet`,
check_rec_rows.vl) pinned it to a closed element type, `{f: (a: i32) => i32}[]`, whose field
carries no set. So `bs` is a closure holder, and the member delivered into its field needs the
route a delivery to a closed function type takes (the closure built there, as `ftNamedAtClosed`
skips), not an id. The set stays closures, and [D15926](D15926.md)'s floor refuses the split call.

Tried on scratch builds, with no change: the holder and context checks' `LetDecl` arms accepting an
adopted binding; the `FieldInit` arm accepting an adopted list's element (it holds no set); and
`ftNamedAtClosed` reading the closed field off the literal's rep or off the adopted binding's
element. The route that runs (D15338): the adopted list is a coerced holder (`ftHolderCoerced` through
`ftLitRecsAtClosed`), so the decision never asks its context, and its field resolves to the
adopted element's closed type (`ftLitAnnotAt`) for `ftNamedAtClosed`; no `ftLate` gate.
