### D3112 — a generic function value stored through a nullable binding or a map index, then called, traps with an indirect-call type mismatch

**closed · a generic function named as a value is instantiated through the adapter's direct call at every delivery · fixture `tests/cases/generics/generic-fn-value-nullable-and-map-slot.vl` · was trap after load · found by #3275's review · filed 2026-09-28 against master `d408f2da4`, closed 2026-09-30 against master `3291e99e1`**

Repro:

    function show<T>(x: T) { print(x * 3) }
    let h: ((i32) => void) | null = null
    h = show
    if h != null { h(2) }
    // vl check: rc 0.  vl run: wasm trap: indirect call type mismatch

Want:

    6

#### Mechanism

Delivered to a written `(i32) => void` binding the generic was built at `T = i32`; delivered
through a nullable binding's assignment, a map value, `push` or `set`, the table slot held a
function of another signature. The [D3073](D3073.md) adapter now takes every delivery of a name
that denotes a generic declaration, whatever type the checker gave the name, and its body's
direct call instantiates the generic as any call does. `bmArgOk` asks it before deferring a
hole-typed `push`/`set` argument, and `argPinRecheck` skips an argument it rewrote. A generic
value that never meets a concrete function type is [D3381](D3381.md).

#### Ablation

| ingredient changed | outcome | needed? |
| --- | --- | --- |
| `const h: (i32) => void = show`, no `null` | prints `6` | **yes** (the nullable or map carrier) |
| `function show(x: i32)`, not generic | prints `6` | **yes** (the type parameter) |
| a map value `{[string]: (i32, string) => void}` holding a two-parameter generic | traps | no |

#### Grading list

The nullable `let` (assigned and initialised), the map value, and a record field of nullable
function type, each holding a generic and called at `i32`.
