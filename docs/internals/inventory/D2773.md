### D2773 — a value `if` joining an `f32` arm with an `f64` one is classified f32 by the emitter while the checker types it f64

**closed 2026-09-27 — the repro RUNS and prints `-3` · was check-clean invalid wasm · 85 of the 132 f32 cells of the lane's f64-consumer grid moved to runs (binding, field, element, operand, argument, print) · filed 2026-09-27 against master `f6db92e0d`**

Repro:

    function f(x: f32, d: f64): f64 {
      const v = if x > 0.0 { d } else { x }
      v * 3.0
    }
    print(f(-1.0, 2.0))

#### Mechanism

The checker joins `f32` and `f64` to `f64`, and `emitIfExpr` builds the `if` at an `f64`
blocktype with the f32 arm promoted. But `exprIsF32`'s `IfStmt` rung answered true when EITHER
arm was f32, so the binding took an f32 local and the `local.set` of the f64 value failed
validation. The same rung made every master f32/float-literal join that reached an f64
consumer invalid wasm (`const d: f64 = if c { raw } else { 0.1 }`). Closed by the rung
deferring to the checker's type: a join the checker typed `f64` is not f32.
