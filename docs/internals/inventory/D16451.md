### D16451 — a generic function's `return` of an empty map pins the hole before grading it, so the second instance reads the first's value type

**closed · was a loud check reject, `return type mismatch: expected {[string]: string}, got {[string]: i32}` · clause 2 · bucket (f), a local fix: the tail spelling runs · found from lane D's return-rule migration of `generic-return-map-value-tyaram` · filed 2026-11-15 against master `c3049ce76`**

Repro:

    function mk<T>(v: T): {[string]: T} { return Map() }
    const a = mk(1)
    const b = mk("s")
    print(b.length)

Want:

    0

#### Mechanism

The `return` path of `checkRetStmtNode` (`check_statements.vl`) ran `constrainEmptyExpr`
before it graded the value against the declared result. The tail path
(`fnTailGradeAgainstRet`, then `fnTailNaturalRet`) grades first and pins after. The empty
map's hole is one node, and it is pinned in the first instance, so the second instance's grade
read the first's value type and refused. The `return` path now grades, then witnesses the
natural type and pins, in the tail's order.
