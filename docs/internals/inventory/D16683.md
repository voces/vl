### D16683 — `s as i32` over a string says only "`as` supports numeric conversions only", with no pointer to `parseI32`

**closed 2026-11-16 · now a loud check reject naming `parseI32` / `parseI64` / `parseF64` from `std:fmt` for a string operand (`strParseCastHint`, check_diag_text.vl) · first-error quality · lane AE conversion audit · filed 2026-11-16 against master `6356d3e7d` · fixture `numerics/error-as-cast-string-operand.vl`**

Repro:

    function f(s: string): i32 {
      return s as i32
    }
    print(f("3"))
    // was: `as` supports numeric conversions only

#### Mechanism

The refusal is owed (a cast does not parse), but the numeric-target arm of the cast ladder
(check_operators.vl) does not distinguish a string operand. Naming `parseI32` / `parseI64` /
`parseF64` from `std:fmt` (each `T | null`) for a string operand and a numeric target is the
fix the author is looking for.
