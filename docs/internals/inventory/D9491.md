### D9491 — a lambda returning a numeric literal union is not taken as returning that union or `null`

**loud check reject · clause 2 · CAPABILITY: the `i32` twin `const h: () => i32 | null = () => a` runs, and a lambda returning `N | null` already runs there · found closing [D9382](D9382.md) · present on master `56e51b394` · filed 2026-10-21 against master `56e51b394`**

Repro:

    type N = 1 | 2
    const a: N = 2
    const h: () => N | null = () => a
    print(h() ?? 0)
    // vl check: cannot assign () => N to 'h' of type () => N | null

Want:

    2

#### Mechanism

Not traced. The lambda's contextual return adoption takes `i32` to `i32 | null`
(`inferRetAdoptNiche`, check_inferred_return.vl) but not `N` to `N | null`, so the lambda
infers `() => N` and the slot refuses the nullability difference (`fnSlotNulDiffers`).

#### Ablation

| ingredient removed | outcome | needed? |
| --- | --- | --- |
| the numeric union (`const a: i32`, `() => i32 \| null`) | runs | **yes** |
| `\| null` (`() => N`) | runs | **yes** |
| the lambda (a `function k(): N` delivered) | same refusal; its `i32` twin refuses too | no |
