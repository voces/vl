#### Mechanism

The lambda's contextual return adoption took `i32` to `i32 | null` (`inferRetAdoptNiche`,
check_inferred_return.vl) but not `N` to `N | null`, so the lambda inferred `() => N` and the
slot refused the nullability difference (`fnSlotNulDiffers`). Adopting the type alone is not
enough: with no recorded return name the body returned a raw `i32` while callers expected the
box, and the program trapped on `indirect call type mismatch`. The cascade rung now records
`i32 | null` for it.

Of the two matrix cells left, `return_inferred` annotated has no expected type where the lambda
is checked (as in D9490), and `argument` un-annotated is D9521: `??` over the call of an
un-annotated parameter bound at `() => N`, refused the same before and after.
