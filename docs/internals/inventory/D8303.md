### D8303 — a fresh call through two nested generic identities into a wider record is refused beside a declared record of its fields

**loud check reject · clause 2 · open · present on master `82bf510a3` · the same program prints `15` once the unused `type Col` is deleted · the clause-1 face was [D8142](D8142.md) · found closing [D8202](D8202.md) · filed 2026-10-20 against master `82bf510a3`**

Repro:

    type Col = { r: i32, g: i32 }
    type J = { r: i32 | null, g: i32 }
    function idn<T>(v: T): T { v }
    function mk() { { r: 15, g: 1 } }
    const m: J = idn(idn(mk()))

#### Mechanism

D8142 made the outer identity refuse when its argument is another identity over a fresh call
beside `Col`, which closed the invalid wasm. D8020 builds the call at the destination through
one identity. Two are not followed. Accepting the delivery in `recAdoptNote`'s nested branch
(check_fit_rules.vl) does not move the outcome, so the refusal is reached on a second path as
well. That path is not yet traced.
