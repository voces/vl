#### Mechanism

D8142 made the outer identity refuse when its argument is another identity over a fresh call
beside `Col`, which closed the invalid wasm. D8020 builds the call at the destination through
one identity. Two are not followed. Accepting the delivery in `recAdoptNote`'s nested branch
(check_fit_rules.vl) does not move the outcome, so the refusal is reached on a second path as
well. That path is not yet traced.

Closed in `recAdoptNote`'s nested-identity branch (check_fit_rules.vl): when each identity in
the chain is pinned by that argument alone (`recSolePinChain`), the call lands on the
destination's own storage and `recFnBuiltAtDst` agrees, the build is queued at the destination
ahead of D8142's refusal. The second path the note above expected was not needed.
