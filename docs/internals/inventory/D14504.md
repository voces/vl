### D14504 — a fresh record with a `null` field, returned and delivered as a record whose field is nullable, is not built at that record

**closed 2026-10-27 · runs, prints `0` · fixed: `recNullWidened` (check_fit_rules.vl) lets a `null` field land on a nullable storage, so `recSitesLandAt` serves the call held by `dd` and `recFnBuiltAtDst` builds `mkcall`'s literal at `Circle` · pins: `tests/cases/soundness/fresh-null-field-call-delivered.vl` · was check-clean invalid wasm at top level, clause 1 (`expected Circle, found #anon1`), on master · filed 2026-10-27 against master `c7baf1103`**

Repro:

    type Circle = { r: i32 | null }
    function sink(_x: Circle) { }
    function mkcall() {
      const cc = { r: null }
      return cc
    }
    sink(mkcall())
    const dd = mkcall()
    if dd.r != null { print(7) } else { print(0) }

#### Mechanism

`sink(mkcall())` delivers the call as `Circle`, and `dd` is a second, un-delivered site that
reads in place. The site check let an un-delivered site be served only when the literal's field
widens to the destination's, and it refused `null` into `i32 | null`, so the literal kept its own
row while `dd` was typed `Circle`. The `{ r: 5 }` twin already ran.

The `{ r: 5 }` twin; the same function delivered at two records that store `r` differently
(still a loud refusal, D8301); the second site stored rather than read (`reverse([mkcall()])[0]`,
corpus cell `b000498`, still invalid with the scan ablated).
