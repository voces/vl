#### Mechanism

`monoCloneBody` rebuilds only the statement spine of an instance whose `let`s are annotated
at a type parameter; every leaf, the reads included, is the template's node. The rebuilt
block and `let`s sit past the parser's arena (`> emitRootIx`), so a positional question asked
of the instance body finds no range around a template read, and the readers fell back to the
name's first binding. `drwWalk`'s copy-on-write spine does the same to a function body. Both
passes now record the rebuilt body's origin (`bodyRebuiltFrom`); `bodyReadLet` follows it to
the parsed body, places the read there, and maps the binding to the rebuilt one written at the
same source position (`parentLetAtPos`).
