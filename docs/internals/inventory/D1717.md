### D1717 — comparing a litunion atom against a member inside an un-annotated parameter is check-clean INVALID WASM, where the same read through `print` is merely a wrong value

**check-clean invalid wasm · `vl check` rc 0, `vl run` exit 70 · clause 1 · filed 2026-09-06
against master `a867d044b` · found while grading D1545's softening question · pre-existing,
identical at master and at this branch · 0 corpus cells**

Repro:

    const srcArr: ("red" | "green")[] = ["green", "red"]
    function take(a) {
      if a == "green" { print("EQ") } else { print("NE") }
    }
    take(srcArr[0])
    // vl check: rc 0.  vl run: invalid module,
    // type mismatch: expected (ref $type), found i32

Swap the `==` for `print(a)` and the same program is [D1545](D1545.md)'s wrong value — it
prints `0`. So one hole parameter carries two outcome classes, decided by which reader
consumes the atom.

#### Mechanism

Predicted, not probed. The value delivered is the interned i32 atom; `exprIsLitAtom` cannot
claim it, because every node reached through a hole parameter records nothing and the pin reads
`string` (canon SOFTENS a literal union to that spelling while its rep stays the atom —
DECISIONS.md, 2026-09-03). `print` then emits an `i32` print of the id, which validates and is
merely wrong; `==` emits the STRING compare core, which wants a `(ref $type)` and gets the
i32 — so the module fails validation. The `+` read is the same shape and is named in
[D1541](D1541.md)'s own text for the module-global face that row closed.

#### Ablation

| ingredient removed | outcome | needed? |
| --- | --- | --- |
| the un-annotated parameter (`a: "red" \| "green"`) | runs, prints `EQ` | **yes** |
| the `==` (`print(a)` instead) | prints `0` — that is [D1545](D1545.md) | **yes** — the reader decides the class |
| the parameter (the comparison inlined at module scope) | runs, prints `EQ` | **yes** |
| the inline spelling (`type K = "red" \| "green"` used for the array) | runs, prints `EQ` | **yes** |

#### Grading list

The four ablation rows above, [D1545](D1545.md)'s own witness as the `print` face of the same
seam, and the six-spelling table in D1545 that established the softening is a GAP and not the

`string` parameter and the named-ALIAS spelling all deliver the member, and only the inline set
through a hole parameter does not.
