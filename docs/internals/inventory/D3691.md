### D3691 — a bare fallible `as` over a hole, called through a `let` re-pointed at a DIFFERENT function, is not re-asked by the checker

**closed 2026-10-24 — now a loud check reject, `` `as u8` propagates null `` at both `k`'s and `m`'s cast · was loud emit reject, clause 2 · DESIGN: a call through a binding whose writes all reach functions re-asks each reached function's parked casts under its own parameter name (`holeCastReachedDecls`, `check_hole_links.vl`; `holeCastPinReached`, `check_calls.vl`); `j(2)` refuses as the direct `k(2)` does, and `as!` in both runs · lane L3 · pins: `tests/cases/numerics/error-as-u8-through-reassigned-fn-binding.vl`, `tests/cases/numerics/as-u8-trap-through-reassigned-fn-binding.vl` · the residue of [D3659](D3659.md) · found by lane C2 · filed 2026-10-05 against master `56af0f07e`**

Repro:

    function k(x) { x as u8 }
    function m(x) { x as u8 }
    let j = k
    j = m
    print(j(2.5))
    // vl run: emit error, bare null needs a struct-typed context

#### Mechanism

`holeCastWrittenDeclOf` (D3659) names the callee of a re-pointed binding only when every write
reaches the same `FuncDecl`. Here the writes reach `k` and `m`, so no parked cast is re-asked;
the call's parameter carries `k`'s hole, so `m`'s parked cast has no path to a pin. The direct
spellings `k(2.5)` and `m(2.5)` are each the check error `` `as u8` propagates null ``. A fix
re-asks the parked casts of every function a write reaches, each under its own parameter name.
