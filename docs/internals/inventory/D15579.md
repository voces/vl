#### Mechanism

The keys looked right, but no set was tagged: the elaboration keyed `take` at `(T) => T` for
both parameters, untagged, and minted `fwd` and `fwd2` again at `(string) => string` and
`(i32) => i32`. A probe on the late decision (`fnTagRedecide`) found `{id}`, the sub-need of
`{id, id2}`, refused at `fwd2(id)` (`ftCtxOk` → `ftLateParamOk`): `ftParamForwardsSet(fwd2, 0)`
saw `g` handed to `fwd`, which has no list of its own, so `ftForwardsToListJoin` answered no.
With one forwarder the same question reaches `take` directly, which is why D15578 ran. Before
D15578's close, it refused at `fwd2(id)` with `a generic function taken as a value reaches no
call that fixes its type`.
