### D15579 — a list join reached through two forwarders is refused, even at one call

**loud emit reject · clause 2 · `vl check` rc 0, then ``emitProgram: monomorphize: unsupported argument type for `a` in a call to `take` `` · found closing [D15578](D15578.md) · filed 2026-11-09 against master `1c0410c7` plus D15577's and D15578's closes**

Repro:

    function id<T>(x: T): T { x }
    function id2<U>(x: U): U { x }
    function use(ys) { print(ys.length) }
    function take(a, b) {
      const xs = [a]
      xs[0] = b
      use(xs)
      print(xs[0]("abc").length + xs[0](2))
    }
    function fwd(f) { take(f, id2) }
    function fwd2(g) { fwd(g) }
    fwd2(id)
    // vl check: rc 0.  vl run: emitProgram: monomorphize: unsupported argument type for `a` in a call to `take`

Want:

    1
    5

#### Mechanism

Not traced past the elaboration. The elaboration's keys are right: `take` is keyed once, at
`{id, id2}` for both parameters, and `fwd2` and `fwd` each at `{id}`. So the refusal is in
mono's pin of `take`'s `a` inside `fwd`'s instance, two forwarders below the root call. Before
D15578's close, it refused at `fwd2(id)` with `a generic function taken as a value reaches no
call that fixes its type`.
