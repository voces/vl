### D2504 — a module-level bare block moves the module bindings after it ahead of the statements between them

**check-clean silently wrong · clause 1 · pre-existing on master `d29a9d220` · found by
[D2505](D2505.md)'s operation grid at module scope · filed 2026-09-25 against master `d29a9d220`**

Repro:

    let x = 1
    {
      const z = 2
    }
    x = 5
    const y = x
    print(y)
    // PRINTS 1
    // vl check: rc 0.  vl run prints `1`; the program means `5`.

#### Mechanism

The start function initialises `const y = x` before `x = 5` runs: the same shape as
[D2431](D2431.md), where a `?.` call statement is the ingredient instead of a bare block. The
order the start function runs top-level nodes in is `startOrderKey`/`topStmtOrderKey`
(`emit_rewrite.vl`, `typecheck.vl`), keyed on the node's arena index, which is where to look;
not traced further. In the grid it read as `m.keys()` returning a deleted key, because the
`const ks = m.keys()` initialiser ran before the `m.delete` statement above it.

#### Ablation

| ingredient removed | outcome | needed? |
| --- | --- | --- |
| the bare block replaced by `if true { const z = 2 }` | prints `5` | **yes** |
| the block's body replaced by `print(0)` | still `1` | no |
| `const y = x` replaced by `print(x)` | prints `5` | **yes** — a module binding |
| the whole program inside a function | prints `5` | **yes** — module level only |
| `x = 5` moved above the block | prints `5` | **yes** — a statement between the block and the binding |

#### Grading list

* [D2431](D2431.md)'s witness, the `?.` twin.
* A map read behind a delete: `m.delete(k)` after a module-level bare block, then
  `const ks = m.keys()` — `ks` holds the deleted key.
