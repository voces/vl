### D3506 — a closure body joining two parameter holes and a `null` drops the null at a record pin

**check-clean invalid wasm · clause 1 · open · split out of [D3504](D3504.md), where it was filed for want of an id; not that row's mechanism · found by #3337's review (the `clo` rows of its `g1` grid, `clo__rec_rec`) · filed 2026-10-03 against master `937445a42`**

Repro:

    type Rec = { x: i32 }
    const r7: Rec = { x: 7 }
    function F(k: i32, a, b) {
      const g = () => { if k == 0 { a } else if k == 1 { b } else { null } }
      g()
    }
    print(F(2, r7, r7) == null)
    // vl check: rc 0.  vl run: invalid module inside `__lambda_1`, "expected (ref $type), found (ref null $type)"

Want:

    true

#### Mechanism

A hole is not kept apart inside a lambda: `tyParamOfInnermostBody` answers false under
`lamCheckDepth` (D3357), so the closure's join of `a`, `b` and `null` does not carry its null
through to the pin, and at a record pin the lambda returns `null` where `(ref $Rec)` is owed.
Lifting the `lamCheckDepth` decline needs the instance to build a kept-apart join inside a
lambda, which D3357 records it does not yet; not attempted here.
