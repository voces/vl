### D2185 — a captured mixed literal-and-scalar union `let` that a closure writes builds an invalid module

**closed by [D2285](D2285.md) · was check-clean invalid wasm, clause 1 · filed 2026-09-23 against master `fa5db1bac`, found reviewing the [D2168](D2168.md) close (#3058)**

Repro:

    type M = "a" | "b" | i32
    function main() {
      let m: M = "a"
      const set = () => {
        m = "b"
      }
      set()
      print(m)
    }
    main()
    // vl check: rc 0.  vl run: rc 70, `set` fails validation: expected (ref $type), found (ref $type)

#### Mechanism

Not ablated. `M` mixes string literals with `i32`, so it is a value union and reps as the boxed
`{tag, payload}`, not as the atom. The boxed cell's element is the box, and the store through
`m[0]` in `set` lowers the member literal as a different heap type than the cell holds. D2168's
cell typing covers only the atom-repped union; the box needs the same element seed.

#### The close

The cell's annotation was spelled `"a" | "b" | i32[]`; [D2285](D2285.md) parenthesizes it, so the
cell is the value-union box list. `m = 7`, the module block and `print(set())` run, the last
because D2285 has a boxed tail write yield its assigned value. Without a capture, the same
tail write into the lambda's OWN `let m: M` is invalid wasm on master and after, and so is
`ms[0] = "b"` into a captured `M[]`. That residue is the value-union tail assignment.

#### Grading list

`m = 7` in the closure; the value used, `print(set())`; a module-block binding.
