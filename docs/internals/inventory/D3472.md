### D3472 — a closure over a guard-narrowed `i32` list cell does not emit: its call result is still read as the nullable cell

**loud emit reject · clause 2 · open · pre-existing, the same on master `c17016a1e` · found beside [D3470](D3470.md), whose program cannot run once its sentence is fixed · filed 2026-10-02 against master `c17016a1e`**

Repro:

    function f() { const g: (i32 | null)[] = [7]
      if g[0] != null { const h = () => g[0] ?? -1
        print(h()) } }
    f()
    // vl check: rc 0.  vl run: emitProgram: print of a union value whose arms the tag dispatch cannot classify

Want:

    7

#### Mechanism

Not localised past the ablation. Inside the guard the checker narrows `g[0]` to `i32` and the closure
captures that narrowing, but the emitter still builds the closure's result at the cell's declared
`i32 | null` box, so `print` meets a union value it cannot dispatch on. Bound first, the same result
is the clause-1 face: invalid wasm, `expected i32, found (ref $type)`. A `string` cell, a
bare-name `i32 | null` local, a closure with no guard, and an `f64` cell all run, so the ingredients
are the guard, the `i32` cell and the closure together.
