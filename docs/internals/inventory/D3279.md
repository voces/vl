### D3279 — a parameter list could name two parameters alike, and the second was silently dead

**closed — now a loud check reject, raised at the PARSE stage, `(parse error)`: the parameter name `a` appears twice in this list · was check-clean silently wrong · found by the #3300 review · fixture `tests/cases/functions/duplicate-param-name.vl`**

Repro:

    function f(a: i32, a: i32) { a }
    print(f(1, 2))

#### Mechanism

`parseParamList` refused a misplaced rest parameter but never compared names, and the body's
scope bound `a` to the first parameter, so `f(1, 2)` printed `1`, and `f(a: 5, a: 6)` failed
as `named argument does not match a parameter`. `dupParamCheck` now refuses the list; `_` may
repeat, since it names nothing. A lambda's list goes through the same parser, and a function
type's names are refused by the same comparison.
