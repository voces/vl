### D3300 — a hole's nullable field passed to another un-annotated function that reads its members is accepted and traps on `null`

**now a loud check reject · the call records a `null` re-ask on the argument when the callee's parameter carries a demanded shape, so the pin refuses as `holeDemandOk` refuses a concrete argument · fixture `tests/cases/generics/error-hole-member-read-through-nullable-field.vl` · was loads then traps · clause 1 · pre-existing, the same on master `e70102886` · found by the #3305 review (`rv3305-16210/x/pass1.vl`) · filed and fixed 2026-09-29 against master `e70102886`**

Repro:

    type O = { n: i32 }
    function no(v: i32): O | null {
      if v < 0 { return null }
      return { n: v }
    }
    function u(q) { return q.n }
    function t(z) { print(u(z.v)) }
    t({ v: no(-1) })
    // vl check: member access '.n' on non-object O | null (the body of `t` at the call's argument types)

#### Mechanism

`u(o)` with a concrete `o: O | null` refuses at the call, because `holeDemandOk` checks the
argument against the shape `u`'s body demanded of `q`. Inside `t`, the argument is `z.v`, a
derived hole, which passes that check vacuously, and nothing re-asked it at `t`'s pin. The call
now records D3287's `null` row on the argument (`noteHoleArgNullRead`) whenever the parameter's
demanded shape has a field; a callee that only reads its parameter under a null test demands no
shape and records nothing, as the direct spelling accepts it. The re-ask covers the callee's own
reads only: a callee that hands the parameter on (`u(q) { return w(q) }` with `w(r) { r.n }`)
demands no shape of `q`, and traps at both spellings, `t(z: R)` included; that is outside this row.

#### Ablation

| ingredient changed | outcome on master | needed? |
| --- | --- | --- |
| `function t(z: { v: O \| null })` | refused | **yes** (a hole) |
| `u(z.xs[0])` or `u(z.f())` | traps the same way | same family |
| `function u(q) { if q != null { return q.n } return 0 }` | traps, D3301 | no, a different defect |
| `function u<Q>(q: Q)` | traps the same way | same family |
| `u(q) { return w(q) }`, `w(r) { return r.n }` | traps, and so does `t(z: R)` | not covered |
