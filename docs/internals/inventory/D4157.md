### D4157 — a call through an alias of a `let` holding a hole lambda keeps the lambda's default instance

**closed 2026-10-11 by lane SC, with D3961 · runs · was check-clean silently wrong · found by the D3961 position matrix · filed 2026-10-11 against master `3096c492f` · pins: `tests/cases/closures/alias-of-hole-lambda-let-called.vl`**

Repro:

    let f = (x) => { print("lA"); print(x) }
    const h = f
    h(true)
    // PRINTS lA 1

Want:

    lA
    true

#### Mechanism

A call through the `let` itself instances the hole lambda at the call; a call through an
alias of it did not, so the `i32` default instance ran and printed the boolean's bits. The
close resolves the alias to the `let` (`monoAliasLetEnd`) and renames the call to an
instance per call, as the direct case does. In a larger program the same shape failed validation.
