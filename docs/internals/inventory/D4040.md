### D4040 — a nullable-record alias nested as one member of a wider union delivers the bare record where the union box is expected

**closed · now runs, prints `false` · was check-clean invalid wasm, clause 1 · found by lane L2's kind grid (`scripts/twin-agreement.vl` KINDS programs) · filed 2026-10-11 against master `5a9535c91` · closed 2026-11-01 against master `4f10ded8`: the declared union's variant list spelled the alias as one name, `{x:i32}|null`, so the emitter registered one variant for both and delivered the bare record into it; a nullable member now names its own members as variants (`collectDeclaredUnion`, emit_collect.vl) · fixture `soundness/union-with-nullable-record-alias-member-runs.vl`**

Repro:

    type A = { x: i32 } | null
    type U = A | { tag: i32 }
    const a: A = { x: 1 }
    const u: U = a
    print(u == null)

Want:

    false

#### Mechanism

Measured at the close: `type U = A | { tag: i32 }` reaches `collectDeclaredUnion` with `A`
already expanded to the one variant name `{x:i32}|null`, which `unionAliasMembers` does not
expand, so the row held one variant for the record and its `null`. The analysis below is the filing's.

The target's spelling nests a nullable-record GROUP (`A`, itself `{ x: i32 } | null`) inside a
wider union. Spelled flat — `{ x: i32 } | null | { tag: i32 }` — the same value delivers and runs,
so the delivery decides the target's rep from how the member group is written rather than from the
flattened member set: the source is kept as its nullable-record niche, never boxed, and stored
straight into a slot typed as the union box. Not yet traced to a function.
