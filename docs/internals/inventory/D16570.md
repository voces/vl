#### Mechanism

`applyGenAliasTys` (`check_relate_core.vl`) records the resolved field type on the generic
declaration's field annotation node, `nodeTySet(fd.fdType, r)`, behind `!inferQuiet`. That node
belongs to the declaration, so every application of the alias writes the same node with its own
instance's type, and the last loud one wins. Applications are memoised in `cUserTypes`. A quiet
first application therefore never writes, and no later application of the same arguments does
either. Which type the node ends up holding, or whether it holds one at all, depends on the order
in which contexts apply the alias and on which of them is quiet.

#### Close

`applyGenAliasTys` no longer writes the node; an instance's field type is the row's. Of the readers
below, `collectVariantFields` cannot reach a generic declaration: `structNameOfTy` names only
`cStructPush` entries, which are non-generic declarations and their brands. `anyLitUnionUsed`
does reach one, and reads an untyped field by its spelling (`annIsOneStrLit`). Hand probes (a
generic alias with a bare string-literal field, built by a generic function and stored in a list,
and a union arm `A<i32>`/`A<T>`) emit byte-identical wasm to master, with and without that leg.

#### Grading list

- The readers of a field annotation node's type: `emit_collect.vl` (`fieldElemHintOf`,
  `collectS`, `collectNestedFieldShapes`, which skips a generic parameter's annotation, and
  `collectVariantFields` through `structNameOfTy`), and `check_leaf_steps.vl`'s
  `anyLitUnionUsed` (`tyIsOneStrLit(nodeTyIxOf(n.fdType))`). A generic alias whose field is a
  bare string literal, applied only quietly, is the spelling that would reach the last one.
- `tests/cases/generics/generic-application-name-grammar.vl`, where the node is never typed.
