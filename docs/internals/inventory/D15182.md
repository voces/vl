### D15182 — a bound value built wider reaches a type parameter through a record or nested-list literal argument that a record literal holding a held value also pins

Repro:

    type Circle = { r: i32 | null }
    type K = { r: null }
    function sink(_x: Circle) { }
    function mkcall() { { r: null } }
    const c = mkcall()
    sink(c)
    const k: K = { r: null }
    function f<T>(a: { f: T }, b: { f: T }): T { a.f }
    print(f({ f: c }, { f: k }).r ?? 6)
    // was: vl check rc 0, then vl run: the emitted module failed to validate

Want:

    vl check refuses: c is built as Circle where line 5 delivers it, and it is handed on here at its own type

#### Grade

DESIGN, not CAPABILITY. `c` is a bound record, and a record is a shared reference (D14532): the
`Circle` view `sink(c)` takes can write `c.r = 5`, which a `K` reading of the same record cannot
hold. A copy would make the program run only by unsharing a value that is not fresh, and
DECISIONS.md §"A fresh record converts at one delivery point" keeps that refused: a value stored
and delivered again is not fresh. The binding spelling (`const d: K = c`) is refused on master by
the same message for the same reason.

#### Mechanism

[D15180](D15180.md)'s close refuses `c` where it reaches a type parameter that another argument
pins at `c`'s own type, and recognises that pin when the other argument is itself a held value or
the call writes its type arguments. Here the pin is a record literal holding the held `k`, and the
close does not count it: counting it refuses `f(c, { f: k })` and `f([c], { f: k })` with `a: T` and
`a: T[]`, which run on master and print `6`, because their instance is built at `Circle`. What
tells those two apart from this one at check time is not yet known; the bound type of `T` is `c`'s
own type in all three.
