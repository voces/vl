#### Mechanism

D1628 claims a container delivery only into a SEALED container — one bound once and used only
by projecting out of it — because `cwEscapedFields` files the escaped value under the
container's own name, and a container reachable under a second name (`const sf2 = sf`) hands
out handles `cwIsEscapedHandle` cannot match. The decline is correct: the answer stays `2`,
nothing is claimed, and no converting copy is licensed.

What was wrong is what `2` cost. `emitRefListWidenSite` returned false and left the source's
rep on the stack for a destination-repped slot, so an unknown answer was a clause-1
miscompile. The site now refuses loudly, and the refusal has to live there rather than in the
checker: the licence is `rlWidenAllowed`, whose first half is the REP-scoped
`rlSlotEverWritten` and only whose second half is `covarValueWriteState`. A checker that
refused on the unknown alone would refuse programs whose source and destination element rows
nothing writes — programs that compile and run today.

The refusal fires only where `rlWidenVariantOf` says the pair genuinely needs the converting
copy; the same slot on both sides, and any pair with no conversion between the element reps,
stay the silent no-op every delivery takes.
