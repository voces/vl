### D1656 — the covariant-write analysis declines a container it cannot name, and the decline is check-clean invalid wasm rather than a refusal

**check-clean invalid wasm (`type mismatch: expected (ref $type), found (ref $type)`, exit 70) · filed 2026-09-05 against master `ea407d11a` · found as D1628's residue · 0 corpus cells**

Repro:

    type Circle = { r: i32 }
    type Sq = { s: i32 }
    type Shape = Circle | Sq
    type Box = { xs: Shape[] }
    function f() {
      const a: Circle[] = [{ r: 7 }]
      const b: Shape[] = a
      const sf: Box = { xs: b }
      const sf2 = sf
      sf2.xs.push({ s: 3 })
      print(a.length)
    }
    f()
    // vl check: rc 0.  vl run: exit 70, invalid module.

#### Mechanism

D1628 claims a container delivery only into a SEALED container — one bound once and used
only by projecting out of it — because `cwEscapedFields` files the escaped value under the
container's own name, and a container reachable under a second name (`const sf2 = sf`) hands
out handles `cwIsEscapedHandle` cannot match. The decline is correct as far as it goes: the
answer stays `2`, nothing is claimed, and no converting copy is licensed.

What is wrong is what `2` COSTS. `rlWidenAllowed` returns false, the emitter builds the
delivery at the plain-struct row anyway, and the module the engine gets is invalid — so an
unknown answer is a clause-1 miscompile rather than a refusal. The same holds for the other
three forms the closure cannot follow: a call result that is not delivered to a name
(`take(hand(b))`), a container passed on (`poke(nn)` over `const nn: Shape[][] = [b]`), and a
container returned. Either the analysis grows to model them, or the emitter owes a loud
refusal where the licence is declined.

#### Ablation

| the `push` deleted | runs | **yes (a write somewhere)** |
| `sf2.xs.push` written as `sf.xs.push` | loud check reject | no (that one is found) |
