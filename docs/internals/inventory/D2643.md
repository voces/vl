### D2643 — a lambda whose result is `v128` is refused by the function-value ABI

**closed 2026-09-27 — the filed repro RUNS and prints `10` · closed with D2811, which gave `v128` a `$fnsig` token · filed 2026-09-27 against master `2bbc5c412`**

Repro:

    import { toString } from "std:fmt"
    const dbl = (v: v128) => __add_i32x4__(v, v)
    print(toString(__extract_lane_i32x4__(dbl(__splat_i32x4__(5)), 1)))
    // master: emitProgram: a function value's signature is not yet supported — parameter `v` of type `v128` has no representation in the function-value ABI

#### Mechanism

A lambda is always a function value, so its lifted function needs a `$fnsig`; with no token
for `v128` at the parameter or at the inferred result, `cloSigKeyExt` answered "" and the
floor refused it. The same token that closes D2811 closes this one: the result key reads
`cloRetValKind`, which already inferred `v128`.

#### Ablation

| ingredient removed | outcome | needed? |
| --- | --- | --- |
| the vector result (an `i32` lane instead) | still refuses, on the parameter | no |
| the vector parameter and result | runs | **yes** |
| the result annotation (as written, inferred) | refuses | no |
