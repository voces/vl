### D1995 — an un-annotated closure whose tail is an `if`/`else` with a statement-only arm (`xs.push(8)` / `print(0)`) traps `unreachable` at run time, whichever arm is taken

**closed — return inference now takes a tail `if`/`else` (or `match`) as the function's value only when every arm that completes yields one, and the emitter reads the checker's verdict (`ifYieldsNoValue`) instead of its own "any arm is a value" · was loads then traps (`vl check` rc 0, then a `wasm unreachable` trap in `f` for either flag value, clause 1) · filed 2026-09-22 against master `a8a104432`, found reviewing [D1965](D1965.md) (#3011) · closed 2026-09-22 against master `af07f4ae0` with [D2013](D2013.md) and [D2018](D2018.md) (plumb PL-011) · `tests/cases/conditionals/tail-if-value-less-arm.vl`**

Repro (runs, prints `0` then `1`):

    function main() {
      const f = (flag: boolean) => {
        const xs: i32[] = []
        if flag { xs.push(8) } else { print(0) }

      f(true)

#### Mechanism

The checker joined the arms to `i32 | void` — `.push` yields its new length, `print` yields
nothing — and recorded that as the closure's inferred return, although DECISIONS.md §`void`
rules `void | i32` a type no value has. The emitter took the closure's functype from that
return (a union box) and lowered the `print` arm into a value position with nothing to put
there, so both arms ended in the compiler's `unreachable`. A top-level function with the same
body ran only because the emitter's own `computeVoidFns` classified `.push` as a statement and
disagreed with the checker in the direction that happened to work.

The rule the close states: **in a function whose return is `void` — declared, a void
context, or inferred void because no other path returns a value — a tail `if`/`else` or
`match` yields a value only when every arm that completes yields one; an arm ending in a void
call, a statement, an empty block, or such an `if` nested as its tail makes the whole tail a
statement, and an arm that always exits (`return`, `break`) contributes nothing to the join.**
It is D1034's empty-arm rule said once: an empty arm and a void arm are the same absence. The
discard is keyed on the CONTEXT being void, never on the tail's shape (DECISIONS.md "void
contexts discard implicit tail values"): in a function that returns a value — annotated
`T | null`, or inferred non-void from an explicit `return` elsewhere — each value arm still
returns its value and a value-less arm falls off the end like any other path, to `null` when
the return type admits it and to `not all code paths return a value` when it does not.

The checker banks the verdict per `if` node (`ifNoValueAt`), rewinds the arm values it had
seeded into the inferred return (`dropTailIfSeeds`) and re-joins them if the function turns
out non-void (`inferDroppedTy`), and clears the verdict down the tail spine of a non-void
function (`clearTailVerdict`); the emitter's `ifTailIsValue` reads the verdict, and also
ignores it under a non-void annotation. Three shapes keep master's behaviour: an `if` under an
explicit `return` is a value slot (`return expects a value, got i32 | void`); an arm ending in
a bare `{ … }` block is the open bare-block-as-expression ruling, so [D1903](D1903.md)'s cells
run as before; and an arm ending in an else-less `if` (`if c { if d { 5 } } else { 6 }`) keeps
master's `void | i32 | null` refusal.

**Open question, with the owner:** is an else-less `if` that ends an ARM a value-less arm (the
reading this rule would give, making the example `void`) or a `T | null` value (the reading a
function-tail else-less `if` gets)? With `if d { return 5 }` inside, the first reading returns
`null` where the source says `6`, which is why the close leaves the shape on master's refusal.

**Price, recorded:** `apply(() => { if true { 5 } else { print(0) } })` with a generic
`apply<T>(f: () => T): T` ran on master (the lambda was `() => void | i32`, a type no value
has) and now gets the owed refusal `cannot bind the void result` when its result is bound —
the same answer `apply(() => { print(0) })` already got.
