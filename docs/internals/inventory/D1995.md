### D1995 — an un-annotated closure whose tail is an `if`/`else` with a statement-only arm (`xs.push(8)` / `print(0)`) traps `unreachable` at run time, whichever arm is taken

**loads then traps · `vl check` rc 0, then a `wasm unreachable` trap in `f` for either flag value, clause 1 · filed 2026-09-22 against master `a8a104432`, found reviewing [D1965](D1965.md) (#3011) · likely the D1034 family, but with two non-empty arms**

Repro:

    function main() {
      const f = (flag: boolean) => {
        const xs: i32[] = []
        if flag { xs.push(8) } else { print(0) }
      }
      f(true)
      print(1)
    }
    main()
    // vl check: rc 0.  vl run: wasm trap, unreachable (in `f`)

#### Mechanism

Not yet traced to a code site. The prediction, to be tested by the fix: the tail `if`/`else` of an
un-annotated closure is taken as its return value, and an arm that yields no value (`print(0)`, or
`.push` in statement use) lowers to `unreachable` in the value position instead of a void return. Annotating the closure `: void`
or adding a trailing `return` prints `1`, and the same body as a top-level function runs, so the
closure's inferred-return path is the one that disagrees.

#### Ablation

| ingredient removed | outcome | needed? |
| --- | --- | --- |
| no annotation → `: void` on the closure | runs, prints `1` | **yes** |
| a trailing `return` after the `if` | runs, prints `1` | **yes** |
| the closure → a top-level function with the same body | runs | **yes** |
| `f(true)` → `f(false)` | still traps | no |
