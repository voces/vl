### D2465 — `is string` over a narrowed `string | null` place traps after an alias writes null

**closed 2026-09-25 — the witness prints `false` · was loads then traps, clause 1 · filed

Repro:

    const xs: (string | null)[] = ["a"]
    if xs[0] is string {
      const al = xs
      al[0] = null
      print(xs[0] is string)
    }
    // vl check: rc 0.  vl run: prints false

#### Mechanism

The re-test read `xs[0]` under the narrowing to `string`, and that read recovers the
`string | null` niche to non-null with `ref.as_non_null`. The write through `al` is one the
narrowing cannot see, so the recovery trapped on the null. D2447's close lifts the narrowing for
the operand of an `is`, so the read is the raw nullable ref and the niche's null test answers.
The read `xs[0].length` in the same place still traps. That is the unsoundness of the narrowing
itself, [D2407](D2407.md)'s question for paths.
