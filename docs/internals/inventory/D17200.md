### D17200 — `??` over a value `if` joining an inferred-null binding with a record is refused at emit

**loud emit reject · clause 2 · found by IR-N4 closing D17130, new with its checker fix (silently wrong before) · owner IR-N4 · filed 2026-11-24 against master `6bf25409`**

Repro:

    type In = { v: i32 }
    const n = null
    const rec: In = { v: 9 }
    function c(f: boolean) { return ((if f { n } else { rec }) ?? { v: 5 }).v }
    print(c(true))
    print(c(false))
    // vl check: rc 0.  vl run: emit error, "`??` over this nullable value is not supported yet"

Want:

    5
    9

#### Mechanism

With D17130's checker fix the join is `In | null`, as it is for a `null` literal or a typed
`In | null` binding in that arm. Its `n` arm is still read at the inferred-null binding's own rep
(`nulnone`), which the `??`-over-a-nullable plan does not deliver at the join's typed null, so the
plan refuses. Before D17130's fix the join was `_ | null` and this printed `5 5`.

#### Ablation

| spelling | outcome |
| --- | --- |
| the arm `null` literal in place of `n` | runs, `5 9` |
| `const n: In \| null = null`, the binding typed | runs, `5 9` |
| `n` on the else side | refused alike |
