### D16023 — a closure that reads a shared scalar `let` before its first write reads the cell's zero

**check-clean silently wrong · clause 1 · the local twin of [D14360](D14360.md) · found grading
[D2340](D2340.md) · filed 2026-11-13 against master `cf5bea807`**

Repro:

    function go() {
      let p: i32
      const g = () => p
      print(g())
      p = 7
    }
    go()
    // vl check: rc 0.  vl run: prints 0

Want:

    `p` read before it is assigned

A trap naming the binding, as a module global read before its first write traps (spec S3.2,
D14360) and as a shared `let` of a type with no zero value traps (D2340).

#### Mechanism

A `let` a closure shares lives in a one-element cell built at the declaration
(`captureBoxRewrite`, emit_rewrite). With no initializer, a scalar or `string` cell is seeded with
the type's zero (`cboxZeroInit`), so a read the closure runs before the first write returns
that zero. The checker's definite-assignment pass does not order a call to the closure against
the write. A type with no zero value takes a `T | null` cell whose reads trap (D2340); a type
that admits `null` is seeded with `null` and reads it.

#### Ablation

| ingredient changed | outcome | needed? |
| --- | --- | --- |
| a record type (`let p: P`, `p.x`) | traps, naming `p` | **yes**: the type has a zero |
| `print(g())` after `p = 7` | prints 7 | **yes** |
| a direct read (`print(p)` for `print(g())`) | check reject, used before it is assigned | **yes**: the read is through a closure |
| `let p: P \| null`, read `p == null` | prints `true` | no: the same zero read |

#### Grading list

The scalar kinds `cboxZeroInit` seeds (`i32`, `i64`, `u8`, `f32`, `f64`, `boolean`, `string`)
and a nullable type, each read by a closure called before the write.
