### D7960 — an un-annotated `??` over a hole's nullable-`i32` map read with an atom default prints the raw payload

**closed 2026-10-20 by lane L6b · runs, prints `a` then `null` · was check-clean silently wrong, printed `0` then `-1` · clause 1 · in the hole instance the `??` result had no pinned join, so the consumer read the box's `i32` payload and the atom's id as one number; the instance's join row is now registered from the hole pin and the result decodes through that box · pin: `tests/cases/literal-unions/coalesce-map-read-joins-atom.vl` · filed 2026-10-20 against master `aec7a5332`**

Repro:

    type AB = "a" | "b"
    type R = { a: {[i32]: i32 | null}, b: {[i32]: AB} }
    function mk(): R {
      const a: {[i32]: i32 | null} = Map()
      const b: {[i32]: AB} = Map()
      b[3] = "a"
      { a: a, b: b }
    }
    function use(p) {
      print(p.a[9] ?? p.b[3])
      print(p.a[9] ?? p.b[8])
    }
    use(mk())

Want:

    a
    null

#### Mechanism

`p` is a hole, so the instance's `p.a[9] ?? p.b[3]` carries the template's unbound type
variable and `holeOperandTyOf` resolves nothing for it. No join row was registered for the
`i32 | AB | null` result, and the print and binding consumers fell back to the operand's
payload: a hit on the atom read printed its id (`0`) and a miss printed the niche (`-1`).
`nodeJoinRowName` and the D3513 registration in `emit_collect` now take the type from the
hole pin.

#### Grading list

The binding spelling, the `return` spelling (`retU` in the pin), the field-operand spelling,
and the string-valued default.
