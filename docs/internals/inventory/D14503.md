### D14503 — a `Map()` binding returned by a function and held by a binding is not adopted at the map the binding is delivered as

**closed 2026-10-27 · runs, prints `1` · fixed: a binding that holds a call or an element read is delivered as that origin is, through one helper (`recHeldCallOrigin`, check_rec_fresh.vl) that both the record note and the map note read; a map delivered through a call adopts the `Map()` bindings of every return of the function · pins: `tests/cases/soundness/fresh-map-held-call-delivered.vl` · was check-clean invalid wasm at top level, clause 1, on master · filed 2026-10-27 against master `c7baf1103`**

Repro:

    type Circle = { r: i32 | null }
    function sink(_x: {[string]: Circle}) { }
    function mk() {
      const lv1 = Map()
      lv1["k0"] = { r: null }
      return lv1
    }
    const mm = mk()
    sink(mm)
    print(1)

#### Mechanism

`sink(mm)` delivers `mm`, a binding holding `mk()`, as `{[string]: Circle}`. The record note
followed such a binding to its call (D8140); the map note did not, so `lv1` kept the row of
`{r: null}` and `mk`'s map was built at a storage `sink`'s parameter does not have. The follow
is now one helper both notes call, and the map note's call arm walks every return of `mk`.
