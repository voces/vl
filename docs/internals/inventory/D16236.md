### D16236 — a `for` straight over a generic maker's bound list of generic-function records loses the first instance's signature

**loud emit reject · `a function-value call has no interned signature — no function value of type (i32) => i32 reaches this call` · clause 2 · open · `vl check` rc 0 · found ablating [D16234](D16234.md) · filed 2026-11-15 against master `55151b054`**

Repro:

    function id<T>(x: T): T { return x }
    function run<T>(x: T) {
      const rs = [{ f: id }]
      return rs
    }
    for r in run(3) { print(r.f(3)) }
    for r in run("ab") { print(r.f("ab")) }
    // vl check: rc 0.  vl run: emit error at the first loop's call, no interned signature

Want:

    3
    ab

#### Mechanism

The call through the loop variable of the first loop finds no closure of its signature interned:
the instance the loop's iterable names was not taken at `i32` where the walk reaches it. The
order and the shape of the read decide it, not the values, so it sits with the per-instance
typing of the bound literal in [D16234](D16234.md). Not root-caused past the ablation.
