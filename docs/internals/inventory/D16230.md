### D16230 — the value of a write through a parameter that a function set's leaf stores is held at the written function's closure type

**check-clean invalid wasm · `the emitted module failed to validate inside 'put'` · clause 1 · found closing [D15136](D15136.md) · filed 2026-11-14 against master `a5624eb2`**

Repro:

    function inc0(a) { return a + 1 }
    function half(a) { return a / 2.0 }
    function put(ys) { ys[0] = half }
    const xs = [inc0]
    const g = put(xs)
    print(xs[0](3))
    // vl check: rc 0.  vl run: the emitted module failed to validate inside `put`:
    // type mismatch: expected (ref $2), found i32

Want:

    1.5

#### Mechanism

`ys[0] = half` is `half`'s leaf in the set `xs` joins (D14648), so it emits `half`'s id. The
assignment is also `put`'s result, which `g` holds, and the tail spill (`spillWrite`,
emit_rewrite.vl) parks that value in a local typed as `half`'s closure, the type the check gave
the assignment. Nothing calls `g`, so no call joins `put`'s result into the set and
`fnTagRetMark` does not mark `put`.

#### Ablation

| ingredient removed | outcome | needed? |
| --- | --- | --- |
| `const g =` (the result is discarded) | runs, `1.5` | **yes** |
| a call through `g` beside the print, `print(g(4))` | runs, `1.5` then `2` | **yes** |
| the parameter (`const g = (xs[0] = half)` at the root) | loud emit reject, `an assignment used as a value whose type is not its target's has no value lowering` | **yes** |
