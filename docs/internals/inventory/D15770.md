### D15770 — a list literal's row keyed by the literal's own checked record type splits the joined set its function returns

**runs today and must keep running · 18 corpus cells (refuted candidate) · filed 2026-11-12 against master `b835dc65`**

Repro:

    function inc0(a) { return a + 1 }
    function dbl(a) { return a * 2 }
    function last(b) {
      const a = [{ fs: [inc0] }]
      if b { return a }
      return [{ fs: [dbl] }]
    }
    print(last(true)[0].fs[0](3))
    print(last(false)[0].fs[0](3))
    // vl run: 4 then 6. With arrLitMintHintTy keying record and literal elements by the literal's own type: invalid module inside `last`, expected (ref $type), found (ref $type)

Want:

    4

#### Mechanism

A refutation pin. `arrLitMintHintTy` (`emit_collect.vl`) declines a record or literal element
type (`tyMentionsLitOrObj`), so `collectAArrayLit` keys those rows by the literal's name. The
refuted candidate drops that exclusion and keys each list by the literal's own checked element
type. Each literal's record carries its own function set, `{fs: (inc0)[]}` and `{fs: (dbl)[]}`.
The name key `#anonN` puts both on one row, which is the joined set `last` returns. The type key
splits them into two rows, so the two returns build two ref types. The right key is the type the
list is built at, its delivery or joined result (`litRepTyAt`), as the repOf contract treats a
delivery. Until collect keys by that type, the name key stays as a named floor.
