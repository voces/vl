#### Mechanism

D1680's close builds the standalone `?.` map leaf as the field's map struct's nullable ref. An
annotated binding takes its map shape from the annotation, so it runs at every position. An
un-annotated binding takes it from `mapShapeOfExpr` of the initializer (compiler/emit_classify.vl),
which answers nothing for an `OptMember`. The binding then falls back to the string-keyed map, and
the first i32-keyed read is refused. A string-keyed map only works by matching that fallback. The
close teaches `mapShapeOfExpr` that `recv?.f` over a map field has `sFieldMapShape` of the
chain's struct. The fused `recv?.f ?? d` has the second gap: `emitCoalesceOptNulRecord` claims
it first and has no map blocktype, so it never reaches the nullable-map arm (D3257's
`exprNullableMap` → `emitCoalesceNulRef`). The close hands a map leaf to `emitCoalesceNulRef` at that shape. In the
`optchain-map-leaf` matrix's i32-keyed variant, 8 cells are this row: the un-annotated binding,
`global_init`, `global_assign`, `is_in_if`, `is_in_while`, `is_in_and`, `is_in_not` and
`else_if`. Two more, `return_inferred` in both faces, are [D1108](D1108.md), an inferred
nullable i32-keyed map return.
