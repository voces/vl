### D16946 — a generic whose `??` default is a list of another element, called from inside another generic, builds invalid wasm at a non-`i32` instance

**check-clean invalid wasm · clause 1 · found ablating [D12455](D12455.md) · filed 2026-11-17 against master `a20683ac3`**

Repro:

    function pc<T>(xs: T[] | null) { return xs ?? [1] }
    function p<T>(t: T) {
      const a: T[] | null = null
      return pc(a)
    }
    const ys = p(true)
    print(ys.length)
    // vl check: no errors.  vl run: invalid module, "type mismatch: current function requires result type [(ref $4)] but callee returns [(ref $3)]" inside `p`

#### Mechanism

`pc`'s `xs ?? [1]` joins `T[]` with `i32[]`. Called with a concrete `boolean[] | null`, check refuses
the join ("the branches of an `if`, `match` or `??` join boolean[] and i32[] (the body of `pc`, used
at …)"): a container never widens implicitly. Called from inside `p<T>`, where `T` is open, that
call binds nothing concrete, and `p`'s instance at `boolean` never re-asks the join. `pc`'s instance
returns one list rep while `p`'s result is built at another, so the module fails to validate.
D12455's witness is the same join refused loudly at emit, where a list literal wraps the call.

#### Ablation

| change from the repro | outcome | needed? |
| --- | --- | --- |
| `pc(n)` called directly with `n: boolean[] \| null` | check reject, the join sentence | **yes** (the outer generic) |
| `p(3)`, an `i32` instance | runs, prints `0` | **yes** (an element other than the default's) |
| `p("s")`, a `string` instance | invalid wasm | no |
| `pc` reached through two generics (`k<T>` calls `p`) | invalid wasm | no |
| a hole parameter instead of `<T>` in the outer function | invalid wasm | no |
| `[p(true)]`, the call inside a list literal | loud emit reject ([D12455](D12455.md)) | no |
