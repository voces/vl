### D15150 — two union arms whose fields are structurally equal but name different records are refused as having different field types

**closed 2026-11-03 by lane column-G1 · runs, prints `1` · was loud emit reject, clause 2 · filed 2026-11-03 against master `4a114e6cd` by lane column-G1, found grading D15098's control**

Repro:

    type R = { r: i32 }
    type S = { r: i32 }
    type A = { n: i32, g: R }
    type B = { n: i32, g: S }
    type U = A | B
    const b: B = { n: 4, g: { r: 1 } }
    print(b.g.r)
    // vl run: 1.
    // Was: vl check rc 0, then emitProgram: union `U` cannot be discriminated — variants `A` and
    // `B` have the same field names but different field types

Want:

    1

#### Fix

`variantFieldTysEq` (`compiler/emit_collect.vl`) takes two arms' field as one type when its record
types share one record-row class (`recordRowClassOf`, which is the heap partition), directly or as
a nullable inner, list element or map key or value; only otherwise does it compare type text and
element names. A pair whose records differ still refuses as before.
`tests/cases/unions/arms-name-one-record-shape-twice.vl` pins every shape in the ablation, a
nested record, a three-arm union, `==` and the differing control.

#### Mechanism

Records are structural: `R` and `S` are one type (`const r: R = s` runs), and so are `A` and `B`
(`const a: A = b` runs). `assignTags` gives two arms of one field-name signature one tag when
`variantFieldTysEq` finds their field types equal, and refuses the union otherwise; it compares a
DIRECT record field nominally, so `g: R` and `g: S` read as different and the union is refused
with a sentence that is false. The same fields inside a map value compare equal, and that union
builds, with `is A` answering true for a `B`, which is correct for two arms of one type. Not
traced further.
