### D4889 — a hole function returning the complement of `is i32[]` over a hole call's two-list join is invalid at the instance

**check-clean invalid wasm · clause 1 · found grading D4886's un-annotated face · identical on master `b8dc4604d` · filed 2026-10-15**

Repro:

    function w(t, b: boolean) {
      if b { return [t, t] }
      [1, 2, 3]
    }
    function ret(t, b: boolean) {
      const v = w(t, b)
      if v is i32[] { return [t] }
      v
    }
    print(ret("a", true)[1])
    // vl check: rc 0.  vl run: invalid module inside `ret`: type mismatch: expected (ref $6), found (ref $0); $6 is `string list`

Want:

    a

#### Mechanism

Not yet located. The tail `v` is delivered as the union box where the instance returns a
`string list`. With both functions spelled with `<T>` and `ret` annotated `: T[]` it runs
since D4886. Reading the complement at an index, through an alias, as a list element or in a
closure in a hole body is invalid too.

| the hole on `w` only (`w<T>`, `ret` a hole) | still invalid, inside `ret` | no |
