### D17463 — an annotated-parameter function whose returns join a nested record literal and a maker's record emits an invalid module

**loud emit reject · clause 2 · `vl check` rc 0; `vl run` an emit error at 4:19, `this branch hands over a record whose field types differ from the record the branches join to` · was an invalid module inside `pick` (clause 1) until branch `legacy-branch-record-join`; the clause-2 close is [D17224](D17224.md) · filed 2026-11-24 against master `ec08ae2c3` by lane IR-P1 (found ablating [D17462](D17462.md))**

Repro:

    function mk2() { return { f: null, g: 7 } }
    function pick(m: boolean) {
      if m { return { a: { f: 1, g: 7 } } }
      return { a: mk2() }
    }
    print(pick(true).a.g)
    // vl check: rc 0.  vl run: emit error at 4:19, this branch hands over a record whose field types differ

Want:

    7

#### Mechanism

The same join as [D17462](D17462.md): `pick`'s returns join `{ a: { f: i32, g: i32 } }` with
`{ a: mk2() }`, whose record `mk2` builds at `{ f: null, g: i32 }`. With the parameter un-annotated,
emit refuses the second branch. With it annotated, emit writes the branch, and the module fails
validation inside `pick`: "expected (ref null $0), found (ref $4)", where `$0` is the join's row
`{f:i32|null,g:i32}` and `$4` is `mk2`'s literal row `#anon0` (`{nullref, i32}`), handed over
unconverted. The IR does not claim `pick` (`uncovered object field coercion`), so it was legacy's:
`auditRecordJoinLeaves` audited a function's returned leaves only under a written result. It now
audits an inferred record result's returns too, and refuses. Running needs the check-time delivery
a written result makes into the maker, [D17224](D17224.md).
