### D17463 — an annotated-parameter function whose returns join a nested record literal and a maker's record emits an invalid module

**check-clean invalid wasm · `vl check` rc 0; `vl run` an invalid module inside `pick` ("type mismatch: expected (ref null $0), found (ref $…)"), claimed and claimless alike · clause 1 · filed 2026-11-24 against master `ec08ae2c3` by lane IR-P1 (found ablating [D17462](D17462.md))**

Repro:

    function mk2() { return { f: null, g: 7 } }
    function pick(m: boolean) {
      if m { return { a: { f: 1, g: 7 } } }
      return { a: mk2() }
    }
    print(pick(true).a.g)
    // vl check: rc 0.  vl run: rc 70, the emitted module failed to validate inside `pick`

Want:

    7

#### Mechanism

The same join as [D17462](D17462.md): `pick`'s returns join `{ a: { f: i32, g: i32 } }` with
`{ a: mk2() }`, whose record `mk2` builds at `{ f: null, g: i32 }`. With the parameter un-annotated,
emit refuses the second branch. With it annotated, emit writes the branch, and the module fails
validation inside `pick`: "expected (ref null $0), found (ref $4)", where `$0` is the join's row
`{f:i32|null,g:i32}` and `$4` is `mk2`'s literal row `#anon0` (`{nullref, i32}`), handed over
unconverted. The IR does not claim `pick` (`uncovered object field coercion`), and a claimless
compiler writes the same invalid module, so it is legacy's. Which arm of the join drops the refusal is the fix's to establish.

#### Ablation

| ingredient changed | outcome | needed? |
| --- | --- | --- |
| the parameter un-annotated (`pick(m)`) | a loud emit reject instead, [D17462](D17462.md) | **yes** |
| `mk2()` inlined as a literal | runs, `7` | **yes**, a maker's built record |
| the wrapper removed (`return { f: 1, g: 7 }` / `return mk2()`, read `pick(true).g`) | still invalid inside `pick` | no |
