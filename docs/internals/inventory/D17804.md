### D17804 — a reassigned `let` holding a maker's two-signature record is no slot the record is kept whole in, so the maker's call is picked with no member

**loud emit reject · `the compiler cannot yet lower this statement (bundle result pick refused)` · clause 2 · open · `vl check` rc 0 · the same store into a map or list runs (D17737) · filed 2026-11-28 against master `191681bfa` · owner COV-IS**

Repro:

    function lap(f) {
      const _a = f(2.5)
      const _b = f(3)
      return f
    }
    function dbl<T>(x: T): T { return x }
    let k = lap((a) => a + 1)
    k = dbl
    print(k(3))
    // vl check: rc 0.  vl run: emit error at `let k = lap(...)` (bundle result pick refused)

Want:

    3

#### Mechanism

The slot-record note (emit_elab `elabSlotRecordNote`) keeps a maker's record whole only for a
map value, a list element or a record field written with it; a `let` the maker's call
initialises and a later assignment rewrites is none of these, so nothing keeps the record and
the call is picked with no member (`bundleResultPickOf`'s `bpHeap` -2). The rewriting value is
not the cause: a hole lambda there refuses the same way.

#### Ablation

| ingredient removed | outcome | needed? |
| --- | --- | --- |
| the maker's second call (`f(3)`), a one-signature maker | runs, `3` | **yes** (the record) |
| `k = (a) => a`, a hole lambda, in place of `dbl` | the same refusal | no |
| the same values in a map (`m["a"] = lap(..)`, `m["b"] = dbl`) | runs, `3` (D17737) | **yes** (the `let`) |

#### Grading list

- `k = (a) => a` in place of `k = dbl`.
