### D12130 — an `as` miss over a literal union propagates only into a return of the literal's own base type

**loud emit reject · clause 2 · CAPABILITY: the same program with an `i32` return runs · found by the L3 legality sweep · filed 2026-10-24 against master `bc8b191a4`**

Repro:

    type K = 1 | 2 | 3
    type AB = 1 | 2
    function f(k: K): i64 {
      const v = k as AB
      print(v)
      return 1
    }
    print(f(1))
    // vl check: rc 0.  vl run: emitProgram: `as AB` over a numeric literal union propagates its miss, and this function returns neither that number type nor a union — write `as!` or `as?`

#### Mechanism

A bare `as` over a literal union returns the missed value from the enclosing function. The
emitter builds that early return only when the function's return type is the literal's own
base (`i32` for a numeric union, `string` for a string one) or a union it already knows how to
box, so a return the missed value widens into (`i64`, `f64`, `string | null`, `string | i32`)
is refused at emit after `vl check` accepted it. Widening the missed value at the return is a
lowering the emitter lacks, not a rule the design states.

#### Ablation

| ingredient removed | outcome | needed? |
| --- | --- | --- |
| the `i64` return (write `i32`) | runs, prints `1` `1` | **yes** |
| the bare `as` (write `as!`) | runs | **yes** |
| the miss at run time (call `f(3)`) | same emit reject | no |

#### Grading list

The string twin: `type K = "a" | "b" | "c"`, `type AB = "a" | "b"`, `function f(k: K): string | null { const v = k as AB; print(v); return "x" }`, `print(f("c"))` — emit reject `over a literal-union atom propagates its miss, and this function returns neither a literal union nor a string`; with a `string` return it runs and prints `c`. Also an `f64` return of the numeric spelling and a `string | i32` return of the string one.
