### D2826 — a function-local `v128` that a closure captures and the function then reassigns lives in an i32 cell

**check-clean invalid wasm · found by #3213's review · identical on master · filed 2026-09-27 against master `2bbc5c412`**

Repro:

    function f(): i32 {
      let v = __splat_i32x4__(10)
      const g = (): i32 => __extract_lane_i32x4__(v, 1)
      v = __splat_i32x4__(100)
      g()
    }
    print(f())
    // vl check: rc 0.  vl run: the emitted module failed to validate inside `f`: type mismatch: expected i32, found v128

#### Mechanism

A captured local that is reassigned is shared through a mutable cell. The cell is a
one-element list of the local's element kind: an `i64` local gets `(array (mut i64))`. A
vector has no list backing (a vector inside an array is refused), so the cell falls to the
i32 list, and the vector is stored into an `i32` slot. The fix is a vector cell, either a
`(struct (field (mut v128)))` or a v128 list backing. Neither exists yet, so this was not
cheap enough to take into D2811.

#### Ablation

| ingredient removed | outcome | needed? |
| --- | --- | --- |
| the reassignment `v = …` (the capture is by value) | runs, prints `10` | **yes** |
| the vector (an `i64` local, reassigned and captured) | runs, prints `100` | **yes** |
| the function (a module-level `let`, which is a global) | runs, prints `100` | **yes** |
