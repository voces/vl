Repro (before: `vl check` rc 0, then the engine refuses the module; now: prints `1.5`):

    function f() {
      let a = __array_new_default__(3)
      let b = __array_new_default__(3)

#### Mechanism

Two open array rows that meet at a store record a LINK rather than a pin, because neither can
answer for the other (D1470). D1512 gave the two defaulting sites one shared pin point,
`arrDefPinHoleElem`, which consulted that link before reaching for `i32`. The consult was ONE
HOP and its header said a longer chain honestly takes the default — but that is only true of a
chain NOTHING pins. Here `c[0] = 1.25` pins `c`, and `flushUninferred` walks the pending
bindings in DECLARATION order: `a` is asked first, its only partner `b` is still open, so `a`
takes `i32` while `b` and `c` land on `f64`. Three rows, two elements, one local — check-clean
invalid wasm.

`resolveHoleLinks` is the fixpoint: every pair, both directions, a resolved row handing its
element to its open partner, repeated until no row moves, and run before any hole is defaulted.
That makes the pin point independent of the order the flush reaches it in, which is what the one
hop could never be. The sweep is skipped outright when no link was recorded — the common case —
so the cost is one length check.

**PROPAGATION IS THE LINK'S INVARIANT; THE `i32` DEFAULT IS THE INTRINSIC'S MEANING.** They were
tangled in the one-hop read and are now two functions. `holeLinkPinFrom` only ever copies an
element a row already RESOLVED to, so it applies to any array row and can never invent one; a
component nothing pins is untouched by it and still takes `i32` at the pin site, which stays
restricted to `__array_new_default__`'s own rows. That is why a cycle is not a special case: an
all-open cycle simply changes nothing and defaults, and the grid grades `a -> b -> c -> a` in
both the pinned and the unpinned spelling.

**THE BOUND IS STRUCTURAL AND ITS FAILURE IS NAMED.** A sweep that changes anything pins at
least one row and a pin never un-pins, so `2 * pairs + 1` sweeps cannot be exceeded. The `tErr`
guarding it is unreachable by that argument and is there because the alternative to a named
failure is a `while` that spins — and a checker that hangs is the one outcome no gate can see
past.

#### Ablation

| ingredient removed | outcome | needed? |
| --- | --- | --- |
| the third hole (`b = a` alone, then `b[0] = 1.25`) | runs `1.5` | **yes** — two is D1512's case, which the one hop served |
| the pin at the chain's TAIL (`a[0] = 1.25` instead of `c[0]`) | runs `1.5` | **yes** — pinning the head resolves the rest on the first hop |
| the pin altogether (`print(c[0])`) | runs `0` | **yes** — an all-open chain takes `i32` and agrees with itself |
| the f64 element (`c[0] = 7`, `print(c[0] + 1)`) | runs `8` | no — the disagreement needs two DIFFERENT elements, and i32-vs-i32 is not one |
| the chain lengthened to four | still invalid wasm before, runs `1.5` now | no — one mechanism, any length |
| a CYCLE closed over the chain (`a = c` added) | runs `1.5` before AND after | no — the cycle gives the head a direct hop to the pinned row |
| the function scope (module scope instead) | still invalid wasm before, runs `1.5` now | no |
| an annotation on ANY ONE binding | runs `1.5` | **yes** — the control: an annotation takes `constrainEmptyD`'s pin arm and records no link at all |
