### D3035 — a nested record literal built at a wider declared record's `f64` leaf is read at its own `i64` inside a closure

**check-clean invalid wasm · 6 cells of the D3031 nested-kind grid (depth 1–3, with and without a union) · identical on master `3a71bb1f9` · found grading [D3031](D3031.md) · filed 2026-09-28 against master `3a71bb1f9`**

Repro:

    type X = { k: { p: f64 }, n: i32 }
    function main() {
      const o = { k: { p: 10000000000 }, n: 2 }
      const f = () => o.k.p
      print(f())
    }
    main()
    // vl check: rc 0.  vl run: invalid module, inside `f`: type mismatch: expected i64, found f64

Want:

    10000000000

#### Mechanism

The widening face of [D2987](D2987.md) one level down, read through a capture. The nested
literal `{ p: 10000000000 }` is checked `{ p: i64 }` and `i64` widens to `f64`, so the declared
row `X` claims the outer literal and its nested row stores `p` as `f64`. The closure reads
`o.k.p` at the checked `i64` and gets the `f64` slot. Every other read position in the grid
converts, and so does the flat record.
