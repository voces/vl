### D16808 — a generic relay of a maker's hole lambda, delivered at two function types whose results differ, builds one closure for both instances

**closed · runs, prints `4` `0.5` · was loads then traps · `vl check` rc 0, prints `4`, then `wasm trap: indirect call type mismatch` · clause 1 · the two-delivery face of [D16780](D16780.md) · fixed by lane INIT: an instanced relay's returned maker calls are noted per twin and the maker banked at each result (`fvaRelayTwinRows`, `elabRelayPerResultNote`), and each instance of the relay builds its own copy of the call at the closed result its call delivers it at (`monoMakeInstanceGo`'s `twinRet`) · fixture `closures/generic-relay-of-maker-at-two-results.vl` · filed 2026-11-16 against master `a9ae9324a`**

Repro:

    function deliver() { return (a) => a + 1 }
    function wrap<T>(x: T) { return deliver() }
    const v: (a: i32) => i32 = wrap(1)
    const w: (a: i32) => f64 = wrap("s")
    print(v(3))
    print(w(3) / 8.0)
    // vl check: rc 0.  vl run: prints 4, then wasm trap, indirect call type mismatch

Want:

    4
    0.5

#### Mechanism

`wrap` is no maker (it has a type parameter), so the relay twin rows declined it, and the call
`deliver()` it returns was built once, at the root's `i32` lambda, for both instances. Each instance
of `wrap` has one delivery of its own; it now builds its copy of `deliver()` at that delivery's
result, which reaches the maker's twin there.
