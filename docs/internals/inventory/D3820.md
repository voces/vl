### D3820 — a generic called only from inside an un-annotated callback lambda is emitted at the type parameter's default representation

**check-clean invalid wasm · filed 2026-10-07 against master `dfe8e92b3` (found by lane OV)**

Repro:

    // file: r1.vl
    export type A = { x: i32 }
    export function d(self: A): string { "RA" }
    // file: main.vl
    import { A, d } from "./r1"
    function h<T>(x: T): string { x.d() }
    const a: A = { x: 1 }
    print([a].map((x) => h(x))[0])
    // vl check: rc 0.  vl run: invalid module inside `h$m0`, `expected (ref $type), found i32`

Want:

    RA

#### Mechanism

Not yet located. The lambda's parameter is seeded from `map`'s element type, but its call of
`h` does not make an instance of `h` at `A`: the template is emitted with `T` at its default
representation while the member call it holds was typed by `d`'s record receiver. An
un-annotated function in the same position (`function k(x)` called as `(x) => k(x)` in a
`filter`) fails the same way.

#### Ablation

| ingredient removed | outcome | needed? |
| --- | --- | --- |
| the lambda's missing annotation (`(x: A) => h(x)`) | runs | **yes** |
| the callback position (call `h(a)` directly) | runs | **yes** |
| a second `d` candidate (receiver overloading) | still invalid with one | no |
