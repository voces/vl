### D3820 — a generic called only from inside an un-annotated callback lambda is emitted at the type parameter's default representation

**closed 2026-10-08 by lane SC · was check-clean invalid wasm · filed 2026-10-07 against master `dfe8e92b3` (found by lane OV) · pins: `tests/cases/generics/unannotated-callback-pins-generic-callee.vl`, `tests/cases/modules/overload-generic-through-unannotated-lambda/`, `tests/cases/modules/generic-through-unannotated-lambda-module-record/`**

Repro:

    // file: r1.vl
    export type A = { x: i32 }
    export function d(self: A): string { "RA" }
    // file: main.vl
    import { A, d } from "./r1"
    function h<T>(x: T): string { x.d() }
    const a: A = { x: 1 }
    print([a].map((x) => h(x))[0])
    // vl check: rc 0.  vl run: invalid module inside `h$m0`, `expected (ref $type), found i32`

Want:

    RA

#### Mechanism

An un-annotated lambda is a hole function to the monomorphizer, instantiated only by a call
through its own binding. A callback is never called that way, so `monomorphize` walked its
body as a template: `h(x)` read `x` at the hole and pinned `h` at the `i32` default, while the
emitter lowered the lambda itself at the contextual type the checker recorded (`(A) => string`).
The close instantiates such a lambda at that recorded type when its body calls a named generic
and every parameter is a primitive, a record or a list of them (`monoPinLamFromCheckedTy`,
`emit_mono.vl`). A declared record pins by its NAME, since two records of one shape render
alike and a receiver-overloaded `self`-function picks by the name; a record nested below the
top whose render two declarations share keeps the template path.
