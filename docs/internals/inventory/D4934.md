### D4934 — an `is K[]` arm that pushes onto an empty list built at another element type has no list to push onto

**loud emit reject · clause 2 · the push face of [D4911](D4911.md): the arm is now entered for an empty list (D4771), and the `i32[]` the caller built cannot hold an `f64` · master printed `0` and `0` (the arm skipped, against the D4771 ruling) · filed 2026-10-15 against master `3a371d739`**

Repro:

    function g<V>(v: V[]) {
      if v is f64[] { v.push(1.5) }
      v.length
    }
    const e: i32[] = []
    print(g(e))
    print(e.length)
    // vl check: rc 0.  vl run: emitProgram: this `is` arm pushes onto an empty list built with another element type, which cannot hold the pushed value

#### Mechanism

`emitListEmptyFitIs` (wasmEmit.vl) hands a reading arm an empty `K[]` in the receiver's place,
but a push through it would have to land in the caller's list, which is an `i32[]` and holds
no `f64`. The `.push` lowering therefore refuses with `LIST_FIT_PUSH_MSG`. Whether the push
should retag the caller's list, or the program is ill-typed, needs a ruling.

#### Grading list

The unbound face: `function s<T, U>(a: T[]) { const q: U[] = []; if q is f64[] { q.push(1.5) }
print(q.length); print(a.length) }` with `s([1])` prints `0` and `1`, the same on master and
under both D4551 defaults. `U` stays unbound there (`monoListIsUnhandable`), so the arm is
not entered.
