### D2957 — a negated `is` for a type the pin cannot hold narrows the else arm to it, and the arm builds invalid wasm

**check-clean invalid wasm · clause 1 · open · exposed by D2950 (a loud check reject on master `e9fdc10d9`) · the #3243 review's `g50` grid, 4 cells · filed 2026-09-28 against master `e9fdc10d9`**

Repro:

    function h<T>(a: T, c: boolean) {
      const r: T | i32 = if c { a } else { 5 }
      if r !is f64 { print("not") } else { print(r + 0.5) }
    }
    h(3, true)
    // vl check: rc 0.  vl run: invalid module inside `h` (expected f64, found i32)

Want:

    not

#### Mechanism

Not localised past the ablation. At the `i32` pin the union is `i32`, so the else arm is dead. But
it is narrowed to `f64` and lowered as `f64` arithmetic over the `i32` local. The positive
spelling, `if r is f64 { print(r + 0.5) }`, runs at the `f64` pin, and the else arm of that
spelling prints nothing typed `f64`.

#### Ablation

| ingredient removed | outcome | needed? |
| --- | --- | --- |
| the arm's use of `r` (`print("f")`) | runs, prints `not` | **yes** |
| the negation (`r is f64`, arms swapped) | runs, prints `not` | **yes** |
| the `i32` pin (`h(2.5, true)`) | runs | **yes** |

`g50`'s `ann_i32_f64_{c,d}_neg` and `match_i32_f64_{c,d}_neg` cells.
