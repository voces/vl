### D2957 — a negated `is` for a type the pin cannot hold narrows the else arm to it, and the arm builds invalid wasm

**closed 2026-09-28 · was check-clean invalid wasm, clause 1, on master `03dcbcfac` · the #3243 review's `g50` grid, 4 cells · fixture `tests/cases/generics/is-test-a-pin-cannot-hold.vl`**

Repro:

    function h<T>(a: T, c: boolean) {
      const r: T | i32 = if c { a } else { 5 }
      if r !is f64 { print("not") } else { print(r + 0.5) }
    }
    h(3, true)

Want:

    not

#### Mechanism

`!is` parses as `!` over the `is` test. At the `i32` pin the instance decides `r is f64` as the
constant `0`, but `!` lowered it as `i32.const 0; i32.eqz`, and the dead-arm skip reads only a
bare constant off an `is` node. So the else arm, narrowed to `f64`, was lowered as `f64`
arithmetic over the `i32` local. Closed in two places: `!` over a decided `is` emits the
inverted constant, and `staticIsGuard` reads a `!` over an `is` as decided. Both statement
forms and both value forms of `if` take it, and a block cuts its tail after a decided-true
`!is` guard whose arm exits, as it already did for a positive guard.

#### Ablation

| ingredient removed | outcome | needed? |
| --- | --- | --- |
| the arm's use of `r` (`print("f")`) | runs, prints `not` | **yes** |
| the negation (`r is f64`, arms swapped) | runs, prints `not` | **yes** |
| the `i32` pin (`h(2.5, true)`) | runs | **yes** |
| the `if` statement (a value `if`, or an early `return` guard) | same invalid wasm | no |

#### Grading list

`g50`'s `ann_i32_f64_{c,d}_neg` and `match_i32_f64_{c,d}_neg` cells, all four now run. The value
`if` and the guard forms are in the fixture.
