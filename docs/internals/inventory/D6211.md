### D6211 — a hole function whose result a hole parameter is called on, at a second instance, has no monomorphized argument type

**closed 2026-10-18 by lane L3 · runs, prints `vv4` · was loud emit reject · clause 2 · closed by [D6210](D6210.md)'s change: the outer call is keyed by the inner call that produced its argument · pins: `tests/cases/functions/hole-fn-called-on-own-result-two-instances.vl` (the witness and its `const y = g(x)` spelling) · the `let` and `const` lambda spellings of `lap` remain refused at emit, the lambda half of [D6212](D6212.md) · found closing [D6190](D6190.md) · filed 2026-10-17 against master `3805fcf57`**

Repro:

    function str(a) { return "v\{a}" }
    function lap(g, x) { return g(g(x)) }
    print(lap(str, 4))
    // vl check: rc 0.  vl run: emitProgram: monomorphize: unsupported argument type for `g` in a call to `lap`

Want:

    vv4

#### Mechanism

From the ablation only. `str` is needed at `i32` for the inner call and at `string` for the
outer one. The direct spelling `str(str(4))` runs. Through the hole, the outer call's argument
is the hole's own result, typed `_`, so the split plan sees one key and mono has no single
argument type for `g`. [D6210](D6210.md) is the same key read where the result is used inside
`lap`, which emits invalid wasm instead of refusing.
