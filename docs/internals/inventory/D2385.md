### D2385 — a binding inside an expression block that shadows a top-level function types the function's later calls

**closed 2026-09-25 · was check-clean invalid wasm · clause 1 · found in review of #3135 (D2289), the same on its base · filed 2026-09-25 against master `02cce0b14`**

Repro:

    function w(): string { return "top" }
    function g(c: boolean) {
      const r = if c {
        const w = () => { return 8 }
        w() + 1
      } else { 0 }
      print(r)
      print(w())
    }
    g(true)
    // vl check: rc 0.  vl run (before the close): invalid module, inside `g`.  Now prints `9`, `top`.

#### Mechanism

The function-scope binding scan (`plScanStmt`, `compiler/emit_base.vl`) walked statements and
the blocks of statement-position `if`/`while`/`for`, never an expression, so the closure `w`
bound in a value `if`'s arm (or a `match` arm) was in no binding index. #3135's positional
shadow test reads that index, so at `w() + 1` it answered the module function: the arm's call
lowered as a string concatenation and `r`'s cell took the string rep. The close walks every
node of the frame and stops at a nested `FuncDecl`, so an expression block's bindings are
recorded with their block as owner. Every reader of the plan (`parentLetOf*`,
`parentLetCoversAt`, `parentLoopCoversAt`, `parentLetOwnedBy`) sees the wider table; the
cases, native and corpus gates grade it.
