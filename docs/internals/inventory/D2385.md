### D2385 — a binding inside an expression block that shadows a top-level function types the function's later calls

**check-clean invalid wasm · clause 1 · found in review of #3135 (D2289), the same on its base · filed 2026-09-25 against master `02cce0b14`**

Repro:

    function w(): string { return "top" }
    function g(c: boolean) {
      const r = if c {
        const w = () => { return 8 }
        w() + 1
      } else { 0 }
      print(r)
      print(w())
    }
    g(true)
    // vl check: rc 0.  vl run: invalid module, inside `g`

#### Mechanism

A prediction until a close confirms it. The function-scope binding scan (`plScanStmt`,
`compiler/emit_base.vl`) walks statements and the blocks of statement-position `if`/`while`/`for`,
but not a block that is an EXPRESSION (a value `if`'s arm, a `match` arm), so the closure `w`
declared there is in no binding index. #3135's positional shadow test reads that index, so it
cannot see the closure either at its own call `w() + 1` or rule it out at `print(w())`; which
reader then types the two calls against the wrong `w` is not yet traced. A loop variable `w`
inside a `match` arm's block fails the same way. The fix belongs in the scan (index expression
blocks with their extents), which every reader of the table would then see.

#### Ablation

| ingredient changed | outcome | needed? |
| --- | --- | --- |
| the `if` a statement (`if c { const w = …; print(w() + 1) }`) | invalid on master; runs, `9`, `top`, with #3135's positional test | **yes** |
| the inner binding renamed `v` | runs, `9`, `top` | **yes** |
