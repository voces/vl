### D17340 — an assignment of one member of a literal-union field or element, used as a value outside a function's `let` or `return`, has no value lowering

**closed 2026-11-24 · runs, prints `ww`, claimed and claimless · was a loud emit reject (clause 2), `emitProgram: an assignment used as a value whose type is not its target's has no value lowering` · fixed in emit_classify.vl: such an assignment re-reads its place's atom (`asgLitUnionMemberReRead` in `assignTargetReReads`); the IR declines it as a compare operand (`assignment-value atom re-read as a compare operand`); a lone-literal binding initialized by an atom reserves the string-op frame (`letWidensAtomToStr`) · pins: `tests/cases/assignment/litunion-member-value-{witness,positions}.vl`, matrix `litunion-member-assignment-value.matrix.vl` · found by V2 (queue) verifying #9912 (D17260) · filed 2026-11-24 against master `2ae11435` by lane IR-N11, closed by lane IR-N11**

Repro:

    type K = "zz" | "ww"
    const o: { f: K } = { f: "zz" }
    const c = (o.f = "ww")
    print(c)
    // vl check: no errors. vl run: rc 0, prints the line below.

Want:

    ww

#### Mechanism

The checker types `o.f = "ww"` as the lone literal `"ww"`, which reps as a string, while the place
`K` reps as an atom. So no arm of `asgValueArmOf` accepted the pair. A function's `let` and
`return` escaped it: `spillValueWrites` spills the value there first. Every other value position
refused: an argument, a print, a concatenation, an element, a module binding.

The fix makes such an assignment re-read its place. The place holds the member's atom, and
`exprIsLitAtom` already keys an assignment on `assignTargetReReads`, so each consumer sees the atom
it expects of a `K` place: `print` decodes it, and a `string` binding, concatenation or
interpolation widens it.

#### Ablation

| ingredient | outcome on the filing seed | needed? |
| --- | --- | --- |
| the binding inside a function (`const c = (o.f = "ww")` in `h()`) | runs (spilled) | **yes**: a function's `let` or `return` is spilled first |
| `print(o.f = "ww")` or `show(o.f = "ww")` inside a function | still refuses | no: any other value position refuses |
| the field `string` for `K` | runs | **yes**: a literal-union place |
| an element `ks[0] = "ww"` for the field | still refuses | no: a field or an element |
| `c` read from a function or a closure for `print(c)` | still refuses | no |
| a claimless compiler | still refuses | no: legacy's |

A `"ww"`-annotated binding initialized this way and captured by a closure was an invalid module inside a
function on the filing seed (`unknown local`), because the string-op frame was not reserved for a
lone-literal annotation. It runs too.
