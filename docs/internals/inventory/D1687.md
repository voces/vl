### D1687 — a callee whose parameter list this program does not spell — a function-typed parameter, a re-pointed binding — ends the covariant-write closure and the read-only copy is declined

**loud emit reject · filed 2026-09-06 against master `c17d0d53e` · D1683's residue · 0 corpus cells**

Repro:

    type Circle = { r: i32 }
    type Sq = { s: i32 }
    type Shape = Circle | Sq
    function __other() {
      const w: Shape[] = []
      w.push({ s: 3 })
      print(w.length)
    }
    function apply(fn: (Shape[]) => void, xs: Shape[]) {
      fn(xs)
    }
    function f() {
      const a: Circle[] = [{ r: 7 }]
      const b: Shape[] = a
      const take = (ys: Shape[]): void => { print(ys.length) }
      apply(take, b)
    }
    f()
    // vl check: rc 0.  vl run: emit error, covariant list delivery.

#### Mechanism

Nothing writes either list, so the copy is unobservable and the program is legal. D1683 made
`cwCalleeDeclOf` read a callee's parameter list off the `FuncDecl` in the arena — the declared
function a name binds, or the lambda a once-bound `const` was initialised with. `fn` is
neither: its value is chosen by `apply`'s caller, so no one parameter list answers for it, and
a binding re-pointed by `take = …` has the same problem for the opposite reason. The closure
stops, `cwGrowCall` answers `2`, and the rep-scoped scan is already disqualified by `__other`.

The TYPE is not the missing input. `(Shape[]) => void` says what the parameter is, not whether
the body writes it, so reading covariance off the type would have to answer "may write" for
every function value — including the lambda D1683 closed, which is read-only and runs. What
the design would owe instead is either a call-site set (every value that can reach `fn`, which
is a whole-program flow analysis this pass is not) or a way to SAY a parameter is read-only in
the type. Until one of those exists the refusal names a contract: a covariant list may be
delivered to a callee whose body this program can point at, and to no other.
