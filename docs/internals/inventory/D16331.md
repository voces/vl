### D16331 — an un-annotated lambda returned by an un-annotated function, its result bound at a wider function type, is refused because a handle reaches a function literal

**loud check reject · `a {z: f64[]} cannot be delivered as {z: f64[] | i32} here: a handle to it reaches a function literal` · clause 2 · the `return_inferred` cell of `lambda-result-at-delivered-result.matrix.vl`, both faces' annotated cell · the refusal [D3088](D3088.md) names · found closing [D16310](D16310.md) · filed 2026-11-14 against master `495c1ff80` · bucket (a), slot store, secondary (e) (by ablation, 2026-11-15)**

Repro:

    function d() { return () => { z: [14.5] } }
    const v: () => { z: f64[] | i32 } = d()
    const r = v().z
    if r is f64[] { print(r[0]) } else { print("OTHER") }

Want:

    14.5

#### Mechanism

Not traced. The lambda reaches the wider function type through `d`'s inferred result, so no
contextual result is recorded for it, and the record covariant-write rule (`rcwErr`) refuses the
delivery of `d()` at the function literal it cannot follow, as it does D3088's capture.

Bucket (a), slot store, of the clause-2 map
(`docs/internals/refactor-notes/2026-11-14-clause2-architecture-map.md`); secondary (e). The
ablated ingredient is the indirection: the lambda delivered straight at the wide type runs, and so
does `d`'s result annotated, which hands the lambda its result at the return. Held in a call
result or an alias, the value reaches the destination already built at its own result, and no
adapter converts a result record stored differently (the alias spelling's refusal says so).
