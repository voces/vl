### D16331 — an un-annotated lambda returned by an un-annotated function, its result bound at a wider function type, is refused because a handle reaches a function literal

#### Mechanism

Not traced. The lambda reaches the wider function type through `d`'s inferred result, so no
contextual result is recorded for it, and the record covariant-write rule (`rcwErr`) refuses the
delivery of `d()` at the function literal it cannot follow, as it does D3088's capture.

#### Closed

The lambda reached the wider type through `d`'s inferred result, so it had no contextual result
for the `lamRet` phase (D16310), and the delivery built a function-value adapter whose record
conversion the covariant-write rule refuses. The checker now notes each call delivered at a
closed function type outside a guess (`callFnDst`, `check_expected.vl`). The `lamRet` phase
types the lambdas `d` returns, its tail included, at that type's result when every use of `d`
is such a call at the same type and `d` is neither exported nor annotated. It then undoes the
adapter the first check built over each call (`fvaAdaptedArg`), since the delivery is exact.
