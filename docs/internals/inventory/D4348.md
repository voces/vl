### D4348 — a call result of a function-arm value union passed to an un-annotated parameter has no monomorphization pin

**closed 2026-10-13 · runs · was loud emit reject, clause 2 · found grading D4347's matrix (`argument` and `early_return_guard`, un-annotated face) · filed 2026-10-13 against the D3269 branch `2e409d121` · pins: `tests/cases/closures/fn-arm-union-call-result-to-hole-param.vl`**

Repro:

    function mk(n: i32): ((x: i32) => i32) | string {
      if n == 0 { return "s" }
      return (x: i32) => x + n
    }
    function t(a) {
      if a is (x: i32) => i32 { print(a(7)) } else { print(a) }
    }
    t(mk(1))
    // vl check: rc 0.  vl run: emitProgram: monomorphize: unsupported argument type for `a` in a call to `t`

Want:

    8

#### Mechanism

`fnReturnsClosure` (emit_classify.vl) answered from the callee's TAIL whenever its return
annotation was not itself a function type, so `mk`, whose tail is `return (x: i32) => x + n`,
read as returning a bare closure. `exprIsClosure` then claimed `mk(1)`, and `monoArgTyName`'s
closure arm asked `sigKeyOfTy` of a union, got "", and floored. A concrete non-function return
annotation now answers false; a type-variable one still defers to the tail. The fix also moved
`fn-arm-union-call-result-generic.matrix.vl` (the call through `idT<T>`) from 0 to 62 of 64.
