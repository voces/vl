### D1854 — an INFERRED anonymous struct holding a `u8[]` mints a row without the packed element's identity

**loud emit reject · filed 2026-09-07 against master `a9d76dee3`**

Repro:

    const src: u8[] = [4, 5, 6]
    const h = { f: src }
    print(h.f[1])
    // vl check: rc 0.  vl build: emitProgram: ref valtype with no interned shape

#### Mechanism

The DECLARED struct field runs — `type H = { f: u8[] }` reads, writes an element, `push`es,
takes a spread initialiser and nests, all five. So the packed list has a struct-field rep, and
what is missing is the anonymous row: an inline shape minted from the literal alone keys on
field names and codes, and the `u8` element does not reach that key, so the row it interns is
not the row the value needs.

**The annotation on the BINDING is the discriminator, not the type's existence.** Writing
`const h: { f: u8[] } = { f: src }` — the same inline shape, spelled at the binding rather than
inferred — runs. So the shape is expressible and the rep exists; only the inference path mints
the wrong row. That places this in the `#anon` element-identity family rather than with the
map-value registration gap it shares a symptom with (D1853).

#### Ablation

| ingredient removed | outcome | needed? |
| --- | --- | --- |
| the `u8` element (`const h = { f: s2 }`, `s2: i32[]`) | runs | **yes** |
| the inference (`const h: { f: u8[] } = …`) | runs | **yes** |
| the inline shape (`type H = { f: u8[] }`) | runs | **yes** |
| the struct (a bare `const c = src`) | runs | **yes** |
