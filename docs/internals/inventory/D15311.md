### D15311 — a `??` default held as a binding of a maker that returns another maker's call is not built at the read's record

**open · check-clean invalid wasm · `type mismatch: expected (ref null $1), found (ref $5); $1 is J` · clause 1 · the one-level binding, the inline two-level call and a direct delivery run · found grading D15240 · filed 2026-11-04 against master `ddb0573bc`**

Repro:

    type J = { f: i32 | null }
    function mk() { { f: 4 } }
    const m = Map()
    m.set("a", mk())
    const wm: {[string]: J} = Map()
    wm.set("a", mk())
    function mk2() { { f: 1 } }
    function mk4() { mk2() }
    const d = mk4()
    const b = m.get("z") ?? d
    print(b.f ?? 0)

Want:

    1

#### Mechanism

Not yet ablated past the table. D15240 builds a call binding's function at the read's record through
`recAdoptNote`, which hands `mk4`'s build on to `mk2` (D8143). A held binding's adoption breaks that
hand-on: the build fails inside `mk4`, and an inline `?? mk4()` that runs alone fails the same way
beside any held call default (`const dA = mkA(); m.get("a") ?? dA`), while one beside a literal
default runs.

| --- | --- | --- |

| the binding (`?? mk4()`), and no held call default anywhere | runs (D15240) | **yes** |
| the `??` (`const k: J = mk4()`) | runs | **yes** |
