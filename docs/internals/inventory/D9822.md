### D9822 — a function with a nullable map parameter or result is refused as a function value

**loud emit reject · `vl check` rc 0 · `emitProgram: a function value's signature is not yet supported — parameter `p` of type `{[string]:i32}|null` has no representation in the function-value ABI; annotate and call it as a named function instead` · clause 2 · found closing [D9772](D9772.md) · present on master `260b24edd` · filed 2026-10-22 against master `260b24edd`**

Repro:

    function g(p: {[string]: i32} | null): i32 {
      if p == null { return 5 }
      p.length
    }
    const m: {[string]: i32} = Map()
    m["a"] = 3
    const gg = g
    print(gg(m))
    print(gg(null))
    // vl check rc 0.  vl run: emit error: pmap.vl:7:7: emitProgram: a function value's signature is not yet supported — parameter `p` of type `{[string]:i32}|null` has no representation in the function-value ABI; annotate and call it as a named function instead

#### Mechanism

The `nulmap` rep has no `$fnsig` token at all (`repSigTokOfKind`, emit_rep.vl), at either
position, so a signature holding one has no function-value key. [D9772](D9772.md) differed: its
`nulclosure` token existed and was withheld at the parameter. Running this needs a new token
that carries the map's shape slot like `m` does, and a decoder for it in `fbValtype` and
`emitSynthCloSig`.

#### Ablation

| ingredient removed | outcome | needed? |
| --- | --- | --- |
| the alias, `print(g(m))` / `print(g(null))` | runs, `1` `5` | **yes** |
| the `\| null`, `p: {[string]: i32}` | runs, `1` | **yes** |

#### Grading list

The parameter above; `p: Set<i32> | null`, which refuses naming `{[i32]:boolean}|null`; a
result `{[string]: i32} | null` taken as a value, which refuses as `its result type has no
representation in the function-value ABI` (called directly it prints `false` `true`).
