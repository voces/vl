#### Mechanism

`call_bind_shadow.vl` compares, at each call where the monomorphizer decides an instance, the
binding the checker recorded (a type) with the one mono chose (a spelling). It runs only when a
host arms it, and changes no build. Mono's binding is a render by construction, with no type
behind it. So when the two differ as text (`P` against `{x:i32}`), `cbsMonoCanonId` parses the
spelling back (`resolveAnnot`) to compare canonical identities. The parse moved here from
`declTyIxOfName` (through the deleted `repNameCanonId`), so that `declTyIxOfName` lost a
render-fed caller. It retires with the shadow, once the checker's column replaces mono's
re-derivation.
