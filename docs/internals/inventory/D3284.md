### D3284 — a two-way join of two type parameters at `K` and `i32 | null` builds invalid wasm

**closed 2026-09-30 · was check-clean invalid wasm, clause 1, on master `b6378e95b` · found by the #3297 round-3 review (`gB3/n2__k_in__none__print.vl`; the `k_in__none` cells of `gB3`, all positions, two and three parameters) · fixture `tests/cases/generics/join-type-params-literal-union-and-nullable.vl`**

Repro:

    type K = "a" | "b"
    function g<T, U>(a: T, b: U, k: i32) {
      const r = if k == 0 { a } else { b }
      return r
    }
    const x0: K = "a"
    const x1: i32 | null = null
    function use(k: i32) {
      print(g(x0, x1, k))
    }
    use(0)
    use(1)

Want:

    a
    null

#### Mechanism

The same collapse as D3268: `T | U` was typed `T`, so the instance lowered the join at the
literal union's `i32` atom while the `U` arm was the nullable box. With the join kept apart it
re-joins at the pin as `i32 | "a" | "b" | null`, a nullable union whose box had no registration
at a binding (`only i32 locals are supported` once the join was apart): the binding, the chain's
join and a record literal's field now register a nullable union's box as they did a union's
(`monoTyIsUnionOrNulUnion`), a nullable literal union staying a niche.
