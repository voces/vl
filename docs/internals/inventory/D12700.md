### D12700 — a function pushed onto a list of hole functions holds the instance an earlier list's calls took

**closed 2026-10-25 by lane L1 · runs, prints `x2 y20 2 20 2` · a value pushed or index-written into an un-annotated `const` list literal is part of that list's elements, so it is instanced at the list's own call type (`monoListStores`, `monoConstListElems`, emit_mono.vl) · pins: `tests/cases/closures/hole-fn-list-pushed-element-run-at-other-list-type.vl`, `tests/cases/closures/hole-fn-list-element-written-in-function-run-at-other-list-type.vl` · a pushed hole lambda is [D12800](D12800.md) · was loads then traps · `vl check` rc 0 · clause 1 · `wasm trap: indirect call type mismatch` · found grading [D10792](D10792.md) · filed 2026-10-25 against master `a448ccb42`**

Repro:

    import { toString } from "std:fmt"
    function cat(a, b) { return a + b.toString() }
    function snd(a, b) { return b }
    function apply2(g) { print(g("x", 2)) }
    function apply3(g) { print(g("y", 20)) }
    const fs = [apply2, apply3]
    const fs2 = [apply2, apply3]
    fs2.push(apply2)
    for f in fs { f(cat) }
    for f in fs2 { f(snd) }
    // vl check: rc 0.  vl run: prints x2 y20 2 20, then wasm trap: indirect call type mismatch at 10:16

Want:

    x2
    y20
    2
    20
    2

#### Mechanism

Each list literal's elements are instanced at the function type its own calls take, so `fs2`'s
literal elements are `apply2` and `apply3` at the `snd` type. The value `push` appends is
coerced to whatever instance its function was first taken at, `apply2` at the `cat` type, so
the loop's third call goes through a reference of the wrong signature and traps.
