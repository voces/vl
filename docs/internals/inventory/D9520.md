### D9520 — a lambda taken as returning a string literal union is checked at its tail only, so a non-member early `return` reaches the emitter

**closed 2026-10-22 by lane-D952x · now a loud check reject, `cannot assign () => string to 'h' of type () => K` · was loud emit reject · clause 2 · the checker owed the refusal: `litUnionAdoptsRet` (check_inferred_return.vl) is now the one rung for a string literal, a string or numeric literal union and that union or null, and adopts it only when every valued return delivers into it (`retValsDeliver`), as D9490's numeric walk did · the same tail-only rung let `const h: () => "a"` with an early `return "b"` print `b` (clause 1), and refused a `K | null` lambda with an early member return before a `null` tail, which now runs · fixtures `literal-unions/error-fn-value-lambda-non-member-as-string-litunion.vl`, `literal-unions/fn-value-lambda-adopts-string-litunion.vl` · found closing [D9490](D9490.md) · filed 2026-10-22 against master `0be192a3f`**

Repro:

    type K = "x" | "y"
    const c = true
    const h: () => K = () => {
      if c { return "z" }
      "y"
    }
    print(h())
    // vl check: cannot assign () => string to 'h' of type () => K

#### Mechanism

The string literal union rung of the lambda's contextual return adoption (`inferRetAdoptNiche`,
check_inferred_return.vl) adopted `K` from the inferred tail alone, so an early `return` of a
string outside `K` passed check and the emitter's member proof refused it. A lone string
literal expected result was adopted the same way and printed the non-member. One helper now
walks every valued return for the string and numeric cases alike.

#### Ablation

| ingredient removed | outcome | needed? |
| --- | --- | --- |
| the non-member early return (`return "x"`) | runs, prints `x` | **yes** |
| the lambda (a `function h(): K` with the same body) | check refuses | **yes** |
| the early return, moving `"z"` to the tail | check refuses | **yes** |
