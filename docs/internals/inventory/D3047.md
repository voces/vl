### D3047 — a hole instance's literal takes a declared row its pin widens to when one of the pin's own kind is declared after it

**closed · was check-clean invalid wasm, identical on master `3a71bb1f9` · [D3032](D3032.md)'s row choice now takes a declared row of the pin's own kind before one the pin widens to, whatever the declaration order · the #3263 review's `w/p_ni.vl`, `p_nfi.vl` and `p_nif.vl` print 8 · fixture `tests/cases/generics/record-literal-type-param-exact-row-wins.vl` · found reviewing [D3032](D3032.md) · filed 2026-09-28 against master `3a71bb1f9`**

Repro:

    type Xn = { k: i32 | null }
    type Xi = { k: i32 }
    function g(x) {
      const o = { k: x }
      return o.k
    }
    print(g(7) + 1)
    // vl check: rc 0.  vl run: invalid module, inside `g`

Want:

    8

#### Mechanism

The literal `{ k: x }` at `x := i32` fits both declared rows: `Xn` holds an `i32` by widening
into its `| null`, and `Xi` holds it exactly. The instance-blind scan took the first, `Xn`, and
the read `o.k + 1` added to its nullable slot.
