### D16453 — a value `if` of records of un-annotated functions of different results, bound to a `const` in a function and returned, is refused when called through the result in both spellings

**open · loud check reject · `cannot store 'half' in 'r.f': called at (i32) it returns f64, where 'inc1', also stored in it, returns i32 — every function a call through 'r.f' may run must return one type` · clause 2 · bucket (a), S's slot store, as its list sibling [D16136](D16136.md) is · the tail `r` and `return r` refuse alike; the join returned directly runs once #8261 lands · found filing the row #8261 closes · filed 2026-11-15 against master `48e4aa96c`**

Repro:

    function inc1(a) { return a + 1 }
    function half(a) { return a / 2.0 }
    function p(b: boolean) {
      const r = if b { { f: inc1 } } else { { f: half } }
      return r
    }
    print(p(false).f(3))
    print(p(true).f(3))

Want:

    1.5
    4

#### Mechanism

The place `r.f` is judged by its binding's writes, so both arms' functions meet at one call
type and their results disagree. Where the join is the value itself, a returned or tail `if`
is declined as a join ([D15925](D15925.md), and a `return if` by #8261) and each arm keeps its own record. Bound
first, nothing marks the binding as holding a join. The same binding at top level, never
returned, runs, so the refusal is reached only where a call reads the binding through the
function's result. Not traced past the judge; the slot store is the expected owner.
