### D2719 — `as?` naming a concrete type is refused over a `T | null` value that `is` accepts

**loud check reject · clause 2 · found by D2684's close · identical on master · filed 2026-09-26 against master `74bd044d7`**

Repro:

    function size<T>(u: T | null): i32 {
      const w = u as? Set<i32>
      if w == null { return 0 }
      w.size
    }
    const s: Set<i32> = Set()
    s.add(3)
    print(size<Set<i32>>(s))
    // vl check: rc 1 — `as Set<i32>` names a type that is not a member of T | null

#### Mechanism

The checker admits `u is Set<i32>` over `T | null`, since `T` may be that type, but its `as`
membership test compares the target against the declared members and finds neither `T` nor
`null` equal to `Set<i32>`. The same check refuses `match` patterns naming a concrete type over
`T | string` (the review's p3 to p6). An exact instance now binds `T` per pin (D2684), so the
emitter has what the test needs; the gate is the checker's membership rule.

#### Ablation

| ingredient removed | outcome | needed? |
| --- | --- | --- |
| `as?` for `is` (`if u is Set<i32>`) | runs | **yes** |
| the `| null` (`u: T`) | refuses (`as` supports numeric conversions only) | no |
