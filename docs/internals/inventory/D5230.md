### D5230 — a binding aliasing a generic, delivered into an annotated `void` function type inside a module-scope block, emits a `drop` after the call

**closed 2026-10-17 — the witness prints `4` · was check-clean invalid wasm, `vl check` rc 0, clause 1 · the statement call's `drop` decision reads the binding's function-type annotation in a module-scope block too · 12 cells of the D5170 and D5171 matrices (the six annotated block positions of each) · found while closing D5170 and D5171 · filed 2026-10-17 against master `697de45d6` · pins: `tests/cases/closures/generic-alias-into-void-fn-type-in-module-block.vl`, `scripts/capability-probes/matrix/written-fn-binding-copy-two-calls.matrix.vl`, `scripts/capability-probes/matrix/written-fn-binding-nullable-litunion.matrix.vl`**

Repro:

    function gA<U>(u: U) { print(u) }
    const x = gA
    {
      const v: (s: i32) => void = x
      v(4)
    }
    // vl check: rc 0.  vl run: the emitted module failed to validate inside the module's top-level code: type mismatch: expected a type but nothing on stack

Want:

    4

#### Mechanism

The start function calls `v` by `call_indirect` at the `void` signature and then emits a
`drop`, as though the call left a value. `emitCallStmt` drops unless `calleeReturnsVoidAt`
says void, and that asks `calleeCloSigKeyAt`. Its annotation rung (`identFnTypeAnnNameAt`)
read a function body's binding and a global, never a module-scope block's. The block's
binding then reached the initializer rung, which keys the alias's own type: the generic, which
has no key. The call itself lowered through `cloCallSigKey`'s fallback, the callee node's
checker type, so the two disagreed. The rung now resolves the binding through `identLetOfAt`
(function frame, global, module frame), so the annotation answers in every frame. A
function-body block and a global already had theirs read, which is why they ran.
