#### Mechanism

Assignment yields its right side (DECISIONS.md), and the checker types every tail write that
way. The emitter's tail predicate `stmtIsTailValue` counted a write as a value only where
`assignTargetReReads` can re-read the target — a name, or a literal index or field on a named
non-map place. A map entry or a computed-index element fell to "statement", so
`computeVoidFns` made the function void while callers used the checker's `i32` result. The
rewrite that delivers such a value already existed: `spillTail` turns a tail `o[i] = r` into
spills, the store and a read of the spilled value, but ran only in functions already non-void.
Counting a field or element write as a tail value (`assignTargetSpills`) closes the loop, direct
and in every arm of a tail `if`/`else if`/`match`. An else-less tail keeps the write a value only
where its fall-through `null` lowers (`inferNullFallsThrough`); elsewhere it stays void as
before ([D2498](D2498.md)). A bare `null` right side is not spilled ([D2497](D2497.md)). An
anonymous lambda's nullable row is keyed by its node, which `computeVoidFns` now also asks.
