### D6760 — two un-annotated parameters copied into bindings annotated with a type parameter no parameter names, called at `string`, build invalid wasm

**closed 2026-10-18 by lane L1 · runs, prints `x`, `y` then `1` · was check-clean invalid wasm · `vl check` rc 0 · clause 1 · the copies were built at the unbound default of `F`, which the D4551 ruling forbids observing; an un-annotated parameter whose bindings are called at more than one type now gives up its type parameter to the split, and each copy is a parameter per call type · the one-binding spelling, a binding chained into another, a returned call, a closed function, a binding called at two types and two such functions side by side run too · pins: `tests/cases/generics/type-param-binding-seeded-from-unannotated-param.vl` · found closing [D6741](D6741.md) · filed 2026-10-18 against master `bd096729d`**

Repro:

    function same<T>(k: T): T { k }
    function mid<F>(a, a2) {
      let b: F = a
      let b2: F = a2
      print(b("x"))
      print(b2("y"))
    }
    mid(same, same)
    print(same(1))
    // vl check: rc 0.  vl run: the emitted module failed to validate inside `mid`: type mismatch: expected i32, found (ref $type)

Want:

    x
    y
    1

#### Mechanism

From the ablation only. `F` is named by no parameter, so nothing binds it from the call, and
the bindings' calls are built at a default `i32` instance that a `string` argument then
contradicts: the default is observable, which the D4551 ruling forbids. Without another use
that interns an `(i32) => i32` signature, or with one binding, it is refused at emit instead.
