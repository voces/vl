### D16551 — a read of a re-pointed generic `let` handed to a builtin method keeps every function written to it

**loud check reject · `cannot assign (V) => void to (boolean) => void` · clause 2 · open · bucket (f), a local fix: the `.push` destination's element is one function type with no type parameter, as D16182's parameter is (by ablation, 2026-11-15) · the method-argument face of [D16182](D16182.md) · filed 2026-11-15 against master `d534d4226`**

Repro:

    function inner<U>(u: U) { print(u) }
    function plus<V>(v: V) { print(v + 1) }
    function main() {
      let k = plus
      k = inner
      const fs: ((b: boolean) => void)[] = []
      fs.push(k)
      fs[0](true)
    }
    main()
    // vl check: cannot assign (V) => void to (boolean) => void

Want:

    true

#### Mechanism

D16182's close narrows a read handed to a call only where the callee is a function declaration
whose parameter is one function type with no type parameter (`cwArgToClosedFnParam`, check_write_scan). A builtin
method has no declaration to read a parameter off, so the binding keeps its whole set and `plus`
is asked at `boolean`. The cells are `array_push` and `map_set` of
`fn-let-read-after-repoint-generic.matrix.vl`.

#### Ablation

| ingredient changed | outcome | needed? |
| --- | --- | --- |
| the list literal `[k]` in place of `.push(k)` | runs, `true` | **yes** (the method argument) |
| `fs.push(inner)` | runs, `true` | **yes** (the re-pointed read) |
