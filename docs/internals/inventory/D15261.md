### D15261 — a generic's parameter handed a tagged function is keyed at the set in one instance and at a closure signature in another, under one elaboration key

**runs today and must keep running · structural: in `written-param-alias-called-at-two-types-runs.vl`, `one<F>(a: F, c: boolean)` called as `one(id, true)` and `one(dup, false)`, beside a `two<F>(a: F, a1: F, c)` called at the same set, is recorded under one elaboration key (`ek0`) by a mono instance keyed at the set (`(T) => T#set1`) and by one keyed at the closure signature (`=>i>i`), so a per-key fact is read for both · found by the slot probe while sizing [D15106](D15106.md) · filed 2026-11-04 against master `32fb1ac01`**

Repro:

    function id<T>(x: T): T { x }
    function dup<T>(x: T): T {
      print("dup")
      x
    }
    function one<F>(a: F, c: boolean) {
      let b = a
      if c { b = a }
      print(a("x"))
      print(b(3) + 1)
    }
    one(id, true)
    one(dup, false)
    function two<F>(a: F, a1: F, c: boolean) {
      let b = a1
      if c { b = a }
      print(a("y"))
      print(b(4) + 1)
    }
    two(id, id, true)
    two(dup, dup, false)

    x

#### Mechanism

Not yet located; `one` alone does not collide, so `two` is an ingredient. The elaboration binds `F` at the call to the set `id` and `dup` form; mono builds
one instance whose parameter is pinned at that set and another, for the same key, whose parameter
is pinned at the closure signature `(i32) => i32` the written copy `b` is called at. It is
[D15177](D15177.md)'s disagreement, a set binding against a signature, inside an instance's walk
rather than at the root.
