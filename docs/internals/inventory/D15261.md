#### Mechanism

The collision exists only under the split plan; with the plan off neither this witness nor its
source file collides. Measured with key and ask probes, 2026-11-04:

1. The plan-off compile keys `one` and `two` at the set (`F=(T) => T`), mono pins both at the
   set, and emit then refuses `two`'s `b(4)`, which asks the plan for `two`'s copy `b`.
2. The re-run splits `b`. With it split, the set `id` and `dup` form is no longer tagged where
   `one` reads it: mono's pin for `one`'s `a` finds no tagged binding (`monoPinAnnotatedParam`),
   falls to `monoHoleGenFnPin`, and asks the plan for `a` (D6091).
3. A third compile splits `one` too: the elaboration keys it `?one.0=(string) => string;
   ?one.1=(i32) => i32` while mono's first instance still records the key at the set.

So a split of one function untags a set an unrelated function shares. Reading the elaboration's
set binding in `monoPinAnnotatedParam` does not change it: the binding is untagged by step 2.
The slot probe with the plan off finds no collision in any of the seven "one key at two template
functions" files either, nor in this one.
