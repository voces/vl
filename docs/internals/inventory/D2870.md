### D2870 — a list literal returned beside a string, with no return annotation, builds invalid wasm

**check-clean invalid wasm · clause 1 · found by the #3225 review · the same on master `93b93319e` · filed 2026-09-27 against master `93b93319e`**

Repro:

    const a: i32[] = [3]
    function g(k: boolean) {
      if k { return [...a, 2.5] }
      "z"
    }
    const v = g(true)
    if v is f64[] { print(v[0] / 2.0) } else { print(v) }
    // vl check: rc 0.  vl run: invalid module inside `g`

Want:

    1.5

#### Mechanism

Not localised. `g` returns `f64[] | string`, a union box, and the list literal returned into it
is built as a bare list with no box around it. The spread is scenery: a plain `[3.0, 2.5]` fails
the same way. With the string arm replaced by a list, the spread runs since D2845.

#### Ablation

| ingredient changed | outcome | needed? |
| --- | --- | --- |
| a plain literal (`[3.0, 2.5]`) | still invalid | no |
| the string arm (`[0.5]` instead of `"z"`) | runs | **yes** |

#### Grading list

`[...a]` returned beside `null`; the same literal in an `if` expression's arm.
