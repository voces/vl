### D16291 — an un-annotated lambda literal written as a function's return value cannot infer its parameter, while the same lambda bound to a `const` and returned runs

**loud check reject · clause 2 · `cannot infer a type for parameter `x`` · found by the 2026-11 engineering review (§3.1, `compose`) · filed 2026-11-14 against master `94f5055d`**

Repro:

    function compose(f, g) { return (x) => f(g(x)) }
    const inc = (n: i32): i32 => n + 1
    const dbl = (n: i32): i32 => n * 2
    const k = compose(inc, dbl)
    print(k(5))
    // vl check rc 1: cannot infer a type for parameter `x` (at 1:34, inside `compose`)

Want:

    11

#### Mechanism

An anonymous lambda's un-annotated parameter becomes an inference hole only when the lambda is
bound to an un-annotated `const`/`let` (`isValBindLambda`) or handed to a parameter; a literal
in a `return` or tail position reaches the last arm of `check_fn_decl.vl`'s parameter typing,
which refuses it outright, before any call through the result could pin it.

#### Ablation

| spelling | outcome | needed? |
| --- | --- | --- |
| the witness | check reject | — |
| `function mk() { return (x) => x + 1 }`, `print(mk()(5))` | check reject | the hole parameters `f`, `g`: no |
| a tail expression `{ (x) => x + 1 }` instead of `return` | check reject | no |
| `const k: (x: i32) => i32 = mk(2)` (a declared delivery) | check reject | no |
| `const h = (x) => …; return h`, result bound then called | runs | the literal in return position: **yes** |
| `(x: i32) => f(g(x))` | runs, prints `11` | the open parameter: **yes** |
| `function ap(f, g, x) { return f(g(x)) }` | runs | the lambda: **yes** |

#### Grading list

`compose`, `adder(n) { return (x) => x + n }`, `konst(v) { return (x) => v }` and
`wrap(f) { return (x) => f(x) }`, each with the result bound and called, called inline, and
delivered to a declared function type. The inline call also needs [D16292](D16292.md).
