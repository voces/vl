#### Mechanism

`elabRun` re-checks `inner`'s instance, where `h` holds `add`'s `Fn#d`. That re-check reaches
`instGenFnHolePins` for `apply2(h, 1)` through `callFtyPinCstrs`, then `genFnHolePinAt` and
`genFnHoleInstance` at `apply2`'s `g`. The family answers -1 there because its row-based
substitution leaves `add`'s variables open, so `g` stays `add`'s signature and is lowered as an
i32 id. The binding answers `(i32, i32) => i32`, which is correct. `g` is then pinned plain and
gets the closure ABI (`(ref $clo)`), while `inner` still passes `h` as the id. The validator
reports `expected i32, found (ref $1)`. At the direct spelling `apply2(add, 1)`, the same plain
pin lowers `g` as an id, because the argument names the declaration.
