### D3290 — a generic's `a ?? d` joined with `b` at a `K | null` pin is typed a non-null `string`, dropping the null `b` carries

**loud emit reject · clause 2 · open · was invalid wasm on master `f5ecc7995` (from `73bbd20bb`, #3290) and a refusal (`` `??` over this nullable value is not supported yet ``) on `313a071b4` · the literal-union face of [D2915](D2915.md) · found by the D3281 lane's grid · filed 2026-09-29**

Repro:

    type K = "a" | "b"
    function g<T>(a: T, b: T, c: boolean) {
      const r = if c { a ?? "z" } else { b }
      r
    }
    const u: K | null = null
    const w: K | null = null
    print(g(u, w, true))
    print(g(u, w, false))
    // vl check: rc 0.  vl run: emitProgram: a string join whose arm is a nullable literal union was typed non-null here

Want:

    z
    null

#### Mechanism

D2915's, at a literal-union pin. The body re-checked at `T := K | null` types `a ?? "z"` as
`string` and joins it with `b` by absorbing `b`, so the join is a non-null `string` while `b`
widens to `string | null`. #3290 built the `??` over the `K | null` niche and the widening of
its `-1` to `null`, which turned the refusal `313a071b4` gave into a `(ref null)` arm stored in a
`(ref $string)` local. The emitter now refuses a string join whose type is non-null while an arm
widens a `K | null` atom (`strJoinDropsNulAtom`), anchored at the `if`'s condition since an
instance's rebuilt `if` has no token of its own. A binding of such a join inside an instance,
whose re-checked annotation says `string`, takes the nullable cell the join builds
(`letIsNulString`), so `if c { a } else { "c" }` at the same pin prints `null`. Typing the
join as the union of the `??` hole and the parameter is the fix D2915's candidate tried and pulled for its price
(`census/d2915-coal-join-price.json`); the same change here moved those 31 named cells the same way.
