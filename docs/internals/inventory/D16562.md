### D16562 — a closure built by a generic call whose type parameter nothing binds is called at another type through a destination the call never sees

**loads then traps · clause 1 · open · `vl check` rc 0 · `wasm trap: indirect call type mismatch` · the positions [D16410](D16410.md)'s close does not cover: `return_inferred` (annotated) and `array_element` (un-annotated) of `generic-fn-at-generic-fn-param-bound-by-destination.matrix.vl` · not a regression: both trap on the seed of #8309's parent · beside [D16411](D16411.md) and [D16531](D16531.md) · owner lane N · filed 2026-11-15 against master `59155c7df`**

Repro:

    function gid<A>(x: A): A { x }
    function sel<A>(f: (x: A) => A): (x: A) => A { f }
    function __deliver() {
      return sel(gid)
    }
    const v: (x: f64) => f64 = __deliver()
    print(v(1.5))
    // vl check: rc 0.  vl run: wasm trap, indirect call type mismatch

Want:

    1.5

#### Mechanism

`sel(gid)` binds `A` from no argument and, here, from no destination: the return is inferred,
so `__deliver`'s result keeps `sel`'s `A` open (`(A) => A`). The emitter builds the one closure at
the `i32` instance, and the call `v(1.5)` is typed and lowered at the `f64` signature the
annotation (or, for the list element, the call's own argument) gives the read. The value and the call
disagree on the signature and `call_indirect` traps. `dstBindOpenFnTyParams` binds an open
parameter only at the call whose destination it sees, and an inferred return hands it none.
The emitter's loud check for a disagreeing value call (D15062, the `i32` parameter case) does not
fire, because the call's own signature is the wider one.
