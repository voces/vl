### D5842 — an un-annotated lambda handed through an un-annotated parameter to a function-typed parameter cannot infer its parameter

**loud check reject · clause 2 · found closing [D5790](D5790.md) · filed 2026-10-17 against master `519a09fef`**

Repro:

    function two(a: i32, b: (n: i32) => i32): i32 { b(a) }
    function apply(g, x, y) { return g(x, y) }
    print(apply(two, 3, (n) => n * 2))
    // vl check: rc 1, cannot infer a type for parameter `n`

Want:

    6

#### Mechanism

From the ablation only. A lambda argument takes its parameter types from the parameter it is
delivered to. Through a value whose type is known, `two`'s `(n: i32) => i32` reaches the
lambda. Through the hole, the lambda is typed at the call of `apply`, before the instance
knows `g` is `two`, and nothing re-types it at the pin.
