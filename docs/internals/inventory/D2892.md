### D2892 — an un-annotated binding of an `if` whose arm is a narrowed list-union name is invalid wasm

**closed 2026-09-27 · was check-clean invalid wasm, clause 1, on master `829bd497c` · found while ablating D2876 · filed 2026-09-27 against master `d39c809c1` · fixture `tests/cases/unions/narrowed-list-union-if-arm-binding.vl`**

Repro:

    function mk(b: boolean): string[] | i32[] {
      if b { return ["z"] }
      [1]
    }
    const v = mk(true)
    const q = if v is string[] { v } else { ["w"] }
    print(q[0])
    // vl check: rc 0.  vl run: invalid module — expected (ref null $type), found (ref $type)

Want:

    z

#### Mechanism

Not localised past the ablation. The then arm reads `v` narrowed to `string[]`, whose storage is
the union box; the join is `string[]`, and the arm is lowered as the box rather than unboxed to
the list the join's blocktype names. Annotating the binding routes it through the delivery that
unboxes.

Closed: `exprUnion` answered an `if` by its then arm's union-ness, asked where no narrowing is
active, so the arm read as the box and the binding took a box cell while `emitIfExpr` lowered
the join as the list. A list join now answers as the list, as a primitive join already did
(D2264). The generic-body spelling on the grading list is still a loud emit reject.

#### Grading list

The generic-body spelling (`function f<T>(t: T, b: boolean)` over an inferred `T[] | i32[]`,
`const q = if v is T[] { v } else { [t] }`), a loud emit reject at `string` and `boolean` pins.
