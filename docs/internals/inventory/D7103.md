### D7103 — a lambda written into a `let` a generic initialized, read into a list beside another instance of the generic, is invalid wasm

**closed 2026-10-19 by lane L1 · runs, prints `L 3 O true` · was check-clean invalid wasm · `vl check` rc 0 · clause 1 · the value-flow question answers the one call type a list literal's open function element reaches (`vrCalleeTy`), and mono records the literal at it (`monoReachLitTys`) · pins: `tests/cases/closures/generic-lambda-written-let-in-list-beside-instance.vl`, `tests/cases/closures/generic-lambda-written-let-in-list-string-arg.vl`, `tests/cases/closures/generic-lambda-written-let-in-list-result-typaram.vl`, `tests/cases/closures/generic-lambda-written-let-in-list-for-loop-var.vl` · found closing [D3978](D3978.md) · the same on master `6ca1ebc5c` · filed 2026-10-19 against master `6ca1ebc5c`**

Repro:

    function other<V>(v: V) { print("O"); print(v) }
    function main() {
      let k = other
      k = (n) => { print("L"); print(n) }
      const fs = [k]
      fs[0](3)
      other(true)
    }
    main()
    // vl check: rc 0.  vl run: the emitted module failed to validate inside `main`: type mismatch: expected structref, found i32

Want:

    L
    3
    O
    true

#### Mechanism

Located by probe, against the single-instance control (no `other(true)`), which names the slot
`((i32)=>void)` and calls it at `i>v`. With the second instance `V` pins two ways, so
`pinResolvedFnTy` of the list's element type `(V) => void` is -1 and `nodeArrayElemName`
(`check_emit_queries.vl`) falls to the D4123 stub `() => void`. The slot is named `(()=>void)`,
the call through `fs[0]` keys `>v` and lowers as `call_indirect (type (param structref))`, and the
argument `3` lands where the closure's environment goes. The elements themselves were emitted at
`(structref, i32)`, which is right.
