### D3631 — a record flows into a narrower record only when the dropped fields sort after the kept ones by name

**loud check reject · clause 2 (the refusal says `type-valid … but not yet supported by codegen`) · found in the #3374 review (lane MV2) · filed 2026-10-04 against master `c8f40cc7c`**

Repro:

    type Pt = { x: i32, y: i32 }
    type V3 = { x: i32, y: i32, z: i32 }
    type V4 = { x: i32, y: i32, z: i32, q: i32 }
    function mk4(k: i32): V4 { ({ x: k, y: k * 2, z: k * 3, q: 1 }) }
    function sumP(p: Pt): i32 { p.x + p.y }
    function sum3(p: V3): i32 { p.x + p.y + p.z }
    print(sumP(mk4(5)))
    print(sum3(mk4(5)))
    // vl check: rc 1, twice: "an object value of shape V4 flowing into Pt drops the field
    // `z`, `q`: type-valid (structural width subtyping) but not yet supported by codegen"

#### Mechanism

Width subtyping is lowered only as a declared WasmGC supertype (D622). The emitter lays a
record's fields out in name order (`fieldNameOrder`), and `buildStructSupers` makes `Narrow`
a supertype of `Wide` only when `Narrow`'s laid-out fields are a proper PREFIX of `Wide`'s.
The checker mirrors this in `objWidthPrefix` (`compiler/typecheck.vl`) and refuses every
other width flow with the message above. So whether a narrower record accepts a wider one
depends on the alphabetical order of the field names. `V4 = { x, y, z, q }` lays out as
`q, x, y, z`, which no `{ x, y }` or `{ x, y, z }` is a prefix of. A field named `zz`
instead of `q` lays out last, and both flows run.

A field-dropping COPY is not a sound substitute: a record's fields are mutable, so a write
through the narrow view would not reach the original (the refusal's own wording). A fix
needs either a layout that keeps every declared width pair a prefix, or a view
representation. That is a design question about the record ABI, not a missing emit arm.

#### Ablation

| variant | outcome |
| --- | --- |
| this witness (`V4`'s extra field `q`) | refused at both flows |
| extra field `w` (still sorts before `x`) | refused |
| extra field `zz` (sorts after `z`) | runs: `15`, `30` |
| `{ x, y, z }` into `{ y, z }` (the dropped `x` sorts first) | refused |
| `{ x, y, z }` into `{ x, y }` (the dropped `z` sorts last) | runs: `15` |

#### Grading list

Both flows of the witness. The return position too (`function up(k): V3 { mk4(k) }`, refused
the same way), plus the argument, binding and field positions of
`scripts/capability-probes/matrix.py` once a lowering exists. The multi-value step (D3630)
admits subtyped records and must be re-graded when this closes: today it only ever sees
prefix pairs.
