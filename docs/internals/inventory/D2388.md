### D2388 — a closure's write to a captured local of a value union with an f64 member is invalid wasm when narrowed to f64

**check-clean invalid wasm · filed 2026-09-25 against master `a8e28a4be`**

Repro:

    function f(): string {
      let out = ""
      let v: boolean | f64 = 1.5
      const g = () => { v = 2.5 }
      g()
      if v is f64 { out = out + "\{v}" } else { out = out + "other" }
      out
    }
    print(f())
    // vl check: rc 0.  vl run: invalid module inside f$m0: type mismatch: expected i32, found f64

#### Mechanism

`v` is a captured local of a value union whose members include `f64`; a closure (`g`)
assigns it a new `f64` value, and the later `is f64` narrowing reads it back. The
assignment through the closure's capture cell writes (or the narrowing reads) `v`'s f64
member using the union's i32 slot, so the two disagree about which wasm type occupies
that position and the module fails to validate.

#### Ablation

| ingredient removed | outcome | needed? |
| --- | --- | --- |
| the f64 member (`boolean \| i32`, closure assigns `i32`) | runs | **yes** |
| the closure (`v = 2.5` inline, no `g`) | runs | **yes** |
| running at module scope instead of inside a function | runs | **yes** |
| the union member spelling (`i32 \| f64` or `string \| f64` in place of `boolean \| f64`) | still invalid wasm | no |

#### Grading list

Any captured value-union local with an f64 member, reassigned through a closure and read
back through an `is f64` narrowing — likely the same family as D2387.
