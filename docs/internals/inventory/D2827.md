### D2827 — a one-member nullable literal union parameter is an i32 atom in the signature and a string in the body

**check-clean invalid wasm · found by #3213's review · identical on master · filed 2026-09-27 against master `2bbc5c412`**

Repro:

    function f(x: "x" | null): i32 { if x == "x" { return 10 } 0 }
    print(f("x"))
    // vl check: rc 0.  vl run: the emitted module failed to validate inside `f`: type mismatch: expected (ref $type), found i32

#### Mechanism

The function's type is `(param i32)`, the interned-atom rep of a nullable literal union.
Inside the body the parameter is read as a string, so the `==` lowers to `struct.get` on it.
The disassembly shows `(struct.get $2 2 (local.tee $12 (local.get $0)))` with `$0` an i32.
The operator is not the ingredient: `x != null` fails the same way. With two members the
union keeps the atom at both sites, so the disagreement is specific to one member: that
spelling is softened to `string | null` at one site and not the other.

#### Ablation

| ingredient removed | outcome | needed? |
| --- | --- | --- |
| the single member (a two-member `"x" \| "y" \| null` instead) | runs, prints `10` | **yes** |
| the `\| null` (`x: "x"`) | runs, prints `10` | **yes** |
| the literal (`x: string \| null`) | runs, prints `10` | **yes** |
| the `== "x"` (an `x != null` test instead) | invalid wasm | no |
