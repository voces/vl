### D14942 — a hole function handed through a hole parameter to a named function that calls its own parameter at two types is refused at emit

**loud emit reject · clause 2 · `vl check` rc 0, then `cannot take the generic function \`id\` as a value` · independent of the split plan: it refuses with the plan on and off · found re-ablating bundle-lam for the split-plan census · filed 2026-11-02 against master `2ce0b824`**

Repro:

    function id(a) { return a }
    function lap(g) {
      print(g(1))
      print(g("s"))
    }
    function use(k) { k(id) }
    use(lap)
    // vl check: rc 0.  vl run: emitProgram: cannot take the generic function `id` as a value

Want:

    1
    s

#### Mechanism

Not located. `lap` is reached only through `use`'s parameter `k`, so the call `k(id)` hands `id` to
`lap`'s `g` through a function value. `g` is called at two types, so `id` needs an instance per
call, which a closure argument with one signature cannot carry. The same shape with a hole lambda in
place of `lap` is bundle-lam's (the split-plan census, §3.2 of architecture-target), which runs
today only through the split plan; with a named `lap` even the split plan does not serve it.

| `lap` a hole lambda in a `const` | runs with the split plan, refused without | different: bundle-lam |
