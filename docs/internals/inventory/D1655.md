### D1655 — a covariant list returned from a function with an INFERRED return type is invalid wasm at the module-scope binding, with no write anywhere in the program

**check-clean invalid wasm (`type mismatch: expected (ref $type), found (ref $type)`, exit 70) · filed 2026-09-05 against master `ea407d11a` · found by `matrix/covar-list-delivery.matrix.vl`, `return_inferred`/un-annotated · 0 corpus cells**

Repro:

    type Circle = { r: i32 }
    type Sq = { s: i32 }
    type Shape = Circle | Sq
    function __deliver() {
      const a: Circle[] = [{ r: 7 }]

      return b
    }

#### Mechanism

Not the covariant-write analysis. The witness has NO list write at all, so
`cwProgramHasWrite` is false, `covarValueWriteState` answers 0 without running the closure,
and `rlWidenAllowed` licenses the converting copy — the same answer it gives the annotated
face, which RUNS. What differs is only `__deliver`'s return-type annotation: with
`function __deliver(): Shape[]` the identical program runs at both spellings of `v`, and
without it the module fails to validate. The rep the caller's binding is built at is therefore
being taken from something other than the inferred return type. Mechanism not yet ablated
past that point; the annotated twin is the control.
