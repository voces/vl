### D3475 — a body whose braces open `{ name, …` was read as a block, so a shorthand-first object literal could not be a function's value

**closed 2026-10-02 (`looksLikeObject` in `compiler/parser.vl` reads a name followed by `,` as an object; DECISIONS.md, "`{ name, … }` is an object too") · was a parse error on a legal program, clause 2 · reported by sunpa (SP-001, `~/sunpa/docs/vl-issues.md`) · filed against master `a8c4dce6d` · fixtures `tests/vl_shorthand_first_field_test.ts` (the shorthand spellings, which `vl fmt` re-spells), `tests/cases/parser/shorthand-lone-name-stays-block.vl`, `tests/cases/parser/shorthand-lone-name-and-empty-braces-stay-blocks.vl`, `tests/vl_label_codemod_test.ts`**

Repro:

    type P = { id: i32, x: f64 }
    function make(id: i32, x: f64): P {
      { id, x: x }
    }
    const p = make(7, 2.5)
    print(p.id)
    print(p.x)
    // was: parse error, `expected an expression but found COMMA` and `` `x: …` starts no
    // statement ``
    // now: prints 7, 2.5

Want:

    7
    2.5

#### Mechanism

Every position where braces may be a block or an object literal — a function or lambda body, an
`if`/`else` branch, a `match` arm, a statement — asks `looksLikeObject`. After #3326 it took a
name followed by `:` as an object and anything else as a block, so `{ id, x: x }` parsed as a
block whose first statement `id` met a `,`. No statement is followed by a comma, so a name then
`,` now reads as an object. The lone `{ name }` is untouched: it is a legal block today and stays
one.

#### Ablation

| ingredient removed | outcome | needed? |
| --- | --- | --- |
| the keyed second field (`{ id, x }`) | still a parse error | no |
| the second field (`{ id, }`) | still a parse error | no |
| the comma (`{ id }`) | a block; `not all code paths return` | **yes** |
| the body position (`return { id, x: x }`, an argument) | runs | **yes** |

#### Grading list

Every body position with the keyed, all-shorthand, trailing-comma and multi-line spellings, and a
nested object (`tests/vl_shorthand_first_field_test.ts`); the lone `{ name }` block in a
branch, an arm and a lambda body, and `{}` as an empty block (the two guard fixtures). The tree
carried no `{ name,` at a body start that master accepted (it was a parse error), so no existing
program changes meaning. Not changed here: `vl fmt` re-spells every shorthand field as `name:
name`, in value position too, as it did before.
