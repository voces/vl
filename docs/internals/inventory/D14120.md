#### Mechanism

mono's `fwdA` clone takes `y` as `f64[]`, which is the parameter of the callee it forwards to.
In `outerB`'s instance, the element type the literal `[v]` reads (`litRepTyAt`) is its own
`i32[]`. With family 3 off, the literal is built as an `i32` list and handed to the `f64` list
parameter. With family 3 on, it keeps mono's threaded pair, so the literal is built as an `f64`
list with `f64.convert_i32_s`, and the program runs. Skipping either the per-instance stamp rung
or the call-parameter rung of `litRepTyAt` alone does not change the outcome. Not yet localised:
whether the elaboration's `fwdA` instance closes `y` at `i32[]` while mono closes it at `f64[]`.
Family 3 keeps mono's pair for a call-argument list literal, or for a list literal nested in
one, wherever that pair differs from the literal's type. It is a workaround for this row, and it
is deleted when the two agree.
