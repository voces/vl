### D3692 — `(x as? f64) ?? d` returned from a generic instance pinned at a non-number is invalid wasm

**check-clean invalid wasm · clause 1 · the same on master `56af0f07e` · found by the #3385 review (`rv85`) · filed 2026-10-05**

Repro:

    function F<T>(x: T) { (x as? f64) ?? 99 }
    print(F("s"))
    // vl check: rc 0.  vl run: invalid module inside `F`, type mismatch: expected i32, found f64

Want:

    99

#### Mechanism

Not traced. At a pin where the cast can never convert (`string`), the instance's returned
`??` mixes an `f64` and an `i32` rep: the always-null cast arm and the default disagree with the
inferred return about which of the two the value is. A cast that reaches `print` inside the
instance runs, and so does an `i32` target. Since [D3654](D3654.md) a hole spelling
(`function F(x)`, or a lambda) reaches this same lowering: 13 cells of the `rv85` `gc` grid
moved from a loud emit reject to this invalid module, the price D3654 records.

#### Ablation

| ingredient changed | outcome | needed? |
| --- | --- | --- |
| `print(F(5))` (a numeric pin) | prints `5` | **yes** (a non-number pin) |
| `x as? i32` | prints `99` | **yes** (a float target) |
| `print((x as? f64) ?? 99)` inside `F` | prints `99` | **yes** (the value returned) |
| `?? 99.0` | same invalid module | no |
