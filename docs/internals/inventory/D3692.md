### D3692 — `(x as? f64) ?? d` returned from a generic instance pinned at a non-number is invalid wasm

**closed 2026-10-05 — the witness prints `99` · was check-clean invalid wasm, clause 1 · found by the #3385 review (`rv85`) · filed 2026-10-05 against master `56af0f07e` · fixture `tests/cases/generics/coalesce-cast-returned-from-instance.vl`**

Repro:

    function F<T>(x: T) { (x as? f64) ?? 99 }
    print(F("s"))
    // vl check: rc 0.  master: invalid module inside `F`, type mismatch: expected i32, found f64

Want:

    99

#### Mechanism

Confirmed. A monomorphized instance's inferred return is classified by `criClassify`
(emit_classify.vl), since the checker saw the body only with a type variable. Its scalar rungs
(`f64`, `f32`, `i64`) skipped every `??` return, to keep a value-union `?? d` (whose result is the
union box) out of them; so the instance's result stayed at the `i32` default while the body's
`??` yields the cast's `f64`. A numeric pin such as `F(2.5)` ran only because another rung typed
it. Fixed by admitting a `??` to the scalar rungs when the `??` itself is not a union
(`exprUnion`), which is the case the skip existed for.
