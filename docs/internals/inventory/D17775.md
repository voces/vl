### D17775 — a `.map` lambda whose annotated result closes a record's function field refuses the element's set field as a type mismatch

**open · loud check reject · clause 2 · `return type mismatch: expected {f: (f64) => f64}, got {f: (i32) => i32} (the callee's return …)` · filed 2026-11-27 against master `a1edbdabf` (lane START-2)**

Repro:

    function id(a) { return a }
    function deliver() { return [{ f: id }] }
    const v: { f: (a: f64) => f64 }[] = deliver().map((r): { f: (a: f64) => f64 } => ({ f: r.f }))
    const u = deliver()
    print(v[0].f(2.5) + u[0].f(2))
    // vl check: return type mismatch

Want:

    4.5

#### Mechanism

The lambda's element `r` is typed at the set's default instance, `{f: (i32) => i32}`, so its field
read meets the annotated result's `(f64) => f64` as another signature instead of being coerced
there (`fnCloCoerce`), as `const g: (a: f64) => f64 = r.f` outside a lambda is. The list half of
[D17764](D17764.md)'s converting copy waits on this: a `.map` is that copy.
