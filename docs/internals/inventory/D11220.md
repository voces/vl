### D11220 — an un-annotated binding of a map read cast `as!` to a numeric literal union takes the union box rep, while the cast yields the bare `i32`

**closed 2026-10-23 — the filed repro RUNS and prints `1` · was check-clean invalid wasm, `expected (ref null $6) union box, found i32` · clause 1 · `exprUnionAs` reads a literal-union `as!`/`as` target as one atom or its base scalar, never a box · filed 2026-10-23 against master `b61294368` · fixture `tests/cases/literal-unions/map-read-as-bang-num-litunion-binding.vl` · remainder: the `map_set` cell of `as-trap-num-litunion-map-read.matrix.vl` is D11241**

Repro:

    type N2 = 1 | 2
    const m: {[string]: N2} = Map()
    m["q"] = 1
    const r = m["q"] as! N2
    print(r)
    // vl check: rc 0.  vl run: invalid module, expected (ref null $6) union box, found i32

Want:

    1

#### Mechanism

A numeric literal union (`1 | 2`) is one `i32` atom, not a box, and the `as!` cast lowers to
that `i32`. The un-annotated binding `r` takes its rep from somewhere that reads `N2` as a
union and gives the global the union box type, so storing the cast's `i32` into the global does
not validate. Inside a function, the same program is a loud emit reject instead (`print of a
union value whose arms the tag dispatch cannot classify`).
