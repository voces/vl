### D12581 — an empty `[]` delivered to a generic `T[]` parameter has no list family in the checked-rep column, so only the ArrayLit shape rung answers it

**closed · runs, prints `0` · was a refutation pin: the ArrayLit shape rung of `syntacticListRep` answered `list` where the column had nothing, and the monomorphizer pinned the parameter from that answer · blocked deleting the shape rung · found closing [D12561](D12561.md) · filed 2026-10-24 against master `b5589bd0c` · closed by the monomorphizer pinning the unbound default's list for an empty literal at an open list (`monoArgTyNameRep`, `monoTyIsOpenList`, emit_mono.vl), with the shape rung deleted · fixture `tests/cases/generics/empty-list-arg-at-unbound-type-param.vl`**

Repro:

    function len<T>(x: T[]): i32 { x.length }
    print(len([]))

Want:

    0

#### Mechanism

The column (`columnListRep`) needs `listRepFamilyOf` to name a family, and at an open type it
names none. The literal is recorded at the type variable it binds, not at the instance's pinned
element. The asker was the monomorphizer: `monoArgPinName` → `monoArgTyNameRep` →
`exprStringArray` → `exprListRep` reached the rung, whose fallthrough `list` made the argument an
`i32[]`. With the rung deleted and nothing in its place, the instance has no parameter type and
the build fails with `a parameter type the valtype ladder has no rung for`.

#### Ablation

An unconditional probe on the rung over the 16,726-file difftree population at `3b72080d8`: 458
files reach it, and in every one the column is uncovered at an open type (`_[]`, `T[]`, `U[]`,
`V[]`) and the rung answers `list`. 453 are `distilled/named/d3125_*` cells; the other five are
`tests/cases/generics` programs.

| class | files (a file can be in several) |
| --- | --- |
| empty `[]`, monomorphizing | 3 |
| non-empty literal, monomorphizing | 454 |
| non-empty literal, monomorphized | 174 |
| arena-final | 2 |

Deleting the rung alone, difftree `--identity` over the 458: 435 built, 2 differ, both
`build_rc 0 → 1` with the valtype-ladder message: `is-list-arm-push-through-literal-pinned.vl` and
`is-list-in-literal-pinned-instance-tests-emptiness.vl`, plus this witness. All three are the
empty class. The non-empty classes' `list` answer moved no file.
