### D12210 — a re-exported dependency function whose parameter has no type, called by nothing, skips the checker's export inference

**now a loud check reject · was a loud emit reject (or an `i32` guess that ran) after `vl check` rc 0 · clause 2 · DESIGN: the same function written in the entry is refused at check (D3817) · found surveying emit refusals for L3 family (d) · filed 2026-10-24 against master `b8e223f93`, closed by the same change**

Repro:

    // file: c.vl
    export function d(x) { x.length }
    // file: main.vl
    export { d } from "./c"
    print(1)

#### Mechanism

`expUncalledExports` (check_pins.vl) took only the entry module's own `export function`s, and
`expObsBegin` (check_exp_obs.vl) observed only those, so a root `export { d } from "./c"` of a
dependency function reached emit with an un-annotated host signature. The emitter either
refused (`'.length' on a receiver the emitter cannot classify`) or guessed `i32` and ran. The
driver now stages the entry's re-exports (`expInfSetReExports`, from `reExpTarget`/`reExpName`)
and both functions treat a re-export target like an own export: inferred when one type fits,
refused with D3817's sentence otherwise. A generic re-export takes the same path and is refused
at check under its public name.
