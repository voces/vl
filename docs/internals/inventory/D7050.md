### D7050 — a generic's `T | B` bound at `T := B` asks a nullable-cell valtype for a `variant` with no row

**loud emit reject · clause 2 · filed 2026-10-19 against master `6e99938e6` · present on master**

Repro:

    type B = { x: i32 }
    function orB<T>(v: T): T | B { return v }
    const b: B = { x: 4 }
    print(orB(b).x)
    // vl check: rc 0.  vl run: emitProgram: ref valtype with no interned shape

#### Mechanism

The instance's return `T | B` at `T := B` is `B`, but a seed whose `fbValtypeNullable` guard
names its inputs reads `variant -1` there: some reader classifies a value of `B` as a union
variant (the generic's annotation names `B` as an arm) and finds no variant row, since the
instance has no union. Measured with an instrumented seed. Lane L6 narrowed it with a second probe: the refusal is
`fbValtype`, reached from `emitOneFuncType` in `emitTypeSection`, for the instance's parameter
`v: T`, whose `vtKindOfParam` reads `variant` with slot -1. Read from the code but not probed:
`vtKindOfType` asks `retVariantFlag`, which asks `nodeTyIsVariant` (`check_node_tys.vl`), and
`cVariantMemberTyIxSet` marks `B` as a variant member because the generic's annotation names
it as an arm. Lane L6's D7040 close, which registers the unions an instance's declared result
reaches, leaves it unchanged: at `T := B` the result is `B` itself and no union exists to
register, so `variantIndexOf("B")` stays `-1`. The fix is the classification, not a registration.
