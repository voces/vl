### D3202 — an un-annotated list literal holding a hole's `string | null` value traps on its `null` after a write or beside another element

**loads then traps · clause 1 · open · the residue of [D3114](D3114.md)'s close, found verifying #3282 · the same on master `2771214c7` · filed 2026-09-29 against master `2771214c7`**

Repro:

    function f(x) { const l = [x]; l[0] = x; print(l[0]) }
    const v0: string | null = null
    f(v0)
    // vl check: rc 0.  vl run: wasm trap: null reference

Want:

    null

#### Mechanism

Not localised past the ablation. D3114's close covers the annotated `(string | null)[]` list.
Without the annotation, the literal's element is the hole, and the list the instance builds, or
a read of it after the write, recovers the parameter non-null. `[x]` read alone keeps the
`null`, so it is the write, or a second element beside the parameter, that brings in the
non-null reading. A flat literal with a string element beside the parameter traps the same way,
at both the hole and the `<T>` spelling:

    function f(x) {
      const l = ["q", x]
      print(l[1])
    }
    const v0: string | null = null
    f(v0)

#### Ablation

| ingredient changed | outcome on master `2771214c7` and #3282 | needed? |
| --- | --- | --- |
| `const l: (string \| null)[] = [x]`, annotated | prints `null` after #3282 (D3114) | **yes** (no annotation) |
| `[x]` read without the write | prints `null` | **yes** (the write) |
| `["q", x]`, read at `l[1]` | traps | no (a second element also triggers it) |
| `function f<T>(x: T)` with `["q", x]` | traps | no |
| `const v0: string \| null = "s"` | prints `s` | **yes** (the `null`) |

#### Grading list

The witness, the `["q", x]` sibling at the hole and at `<T>`, and D3114's annotated fixture,
which must keep printing `null`.
