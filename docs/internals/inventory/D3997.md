### D3997 — a nullable record with a closure field, spelled by its shape, was a union-box list element

**closed 2026-10-11 by lane CK · runs · was check-clean invalid wasm · clause 1 · the residual of D3996, which excluded a shape holding a function type from its fix · found by the #3526 review (`rv3526/s3_closure.vl`) · filed 2026-10-11 against master `20fa382fe` · pins: `tests/cases/arrays/filled-nullable-closure-shape-element-beside-union.vl`**

Repro:

    import { filled } from "std:array"
    type Item = { n: i32, f: (x: i32) => i32 }
    const u: i32 | string = 3
    print(u)
    const a = filled<Item | null>(2, null)
    a[0] = { n: 1, f: (x: i32) => x + 1 }
    const y = a[0]
    if y != null { print(y.f(41)) }
    // vl check: rc 0.  vl run: the emitted module failed to validate inside `filled`

Want:

    3
    42

#### Mechanism

D3996's mechanism, at a record with a closure field. D3996 took a shape-spelled nullable record
element to the struct kind only when the spelling held no `=>`, so `{n:i32,f:(x:i32)=>i32}|null`
kept the union-box kind: with no union in the program the unassigned `$uBoxIdx` happened to name
the record and it ran, beside `i32 | string` it named the box and the module failed to validate,
and on a shared compiler instance a previous compile's union did the same. There was no refusal
on that path to keep; the exclusion is removed.

#### Ablation

| ingredient changed | outcome on master | needed? |
| --- | --- | --- |
| no `i32 \| string` in the program | runs (by the unassigned index) | **yes** |
| `const a: (Item \| null)[] = [null, null]` | runs | **yes** |
| no closure field (`type Item = { n: i32 }`) | D3996 | **yes** |
