### D3707 — a closure's `??` over an `f32 | null` cell a type-parameter value was written into returns `f64`

**closed · runs, prints `2.5` · was check-clean invalid wasm, clause 1 · the `f32` sibling of [D3435](D3435.md) · found by the #3387 review (`rv87`) · filed 2026-10-05 against master `0948a28e3` · closed by lowering a dead `??` whose pin differs from the operand's type as an `if` recorded at the pin (`coalRetypedDeadJoinIf`, wasmEmit.vl), which converts the cell's `f32` to the closure's `f64` result · fixture `generics/coalesce-dead-default-retyped-pin.vl`, with a control that resets the cell to `null` before the closure runs and prints `0.5` · closed with [D9561](D9561.md)**

Repro:

    function g<T>(x: T) {
      let c: f32 | null = null
      c = x
      const h = () => c ?? 0.5
      print(h())
    }
    const v: f32 = 2.5
    g(v)
    // vl check: rc 0.  vl run: invalid module inside `__lambda_1`, type mismatch: expected f64, found f32

Want:

    2.5

#### Mechanism

[D3435](D3435.md)'s close lets an instance's returned `??` take a scalar kind; here
the closure's result is classified `f64` (from the float literal default) while its body yields
the cell's `f32`.

The instance reads `c` as the `f32` written into it, so its `??` cannot take the default, and
the dead-default fold (`coalRetypedDead`, emit_classify.vl) declined because the `f32` is not
the `f64` pin. `coalRetypedDeadJoinIf` lowers the dead `??` as an `if` recorded at the pin,
whose join converts the `f32`.
