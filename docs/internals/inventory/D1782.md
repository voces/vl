#### Mechanism

[D1781](D1781.md) made every return-kind classifier resolve a called NAME through the frame
chain. A binding hop reaches none of them: `const f = k` records the binding's target through
`fieldValueFeOf`, whose `Ident` arm asked the flat `fnIndexOfSid` — the first same-named slot,
which is the template. `identClosureFeAt` reads that target and `calleeCloSigKey` takes the
`$fnsig` off it, so the instance's `f(1)` calls the template's clone under a signature that
validates. The delivery is what separates the family: the same program with `return k(1)` runs
at every pin the matrix covers.

The fix is a positioned twin, `fieldValueFeOfIn(valIx, fnIx)`, resolving through the scope
chain; `identClosureFeAt`'s two frame-scoped arms take it. The struct-field hop needed
`fieldClosureFeOfInit` to carry the frame as well — a position reading the callers does not
find and running them does.
