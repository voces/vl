### D1782 — a per-pin clone of a nested capturing function reached through a BINDING (`const f = k; f(1)`) still resolves the template, so the instance calls the wrong clone

**check-clean invalid wasm — `the emitted module failed to validate inside \`o$1\`: type
mismatch: expected (ref $type), found i32` · clause 1 · 16 cells of the 264-cell
nested-capture matrix, every one of them the `value` delivery at two pins · filed 2026-09-06
against master `be5a79fd2` as the residue [D1781](D1781.md)'s close does not move**

Repro:

    function o(n) {
      function k(x: i32) { return n }
      const f = k
      return f(1)
    }
    print(o(2))
    print(o("a"))
    // vl check: rc 0, "Checked 1 file, no errors."
    // vl run:   the emitted module failed to validate inside `o$1`:
    //           type mismatch: expected (ref $type), found i32

#### Mechanism

[D1781](D1781.md) made every return-kind classifier resolve a called NAME through the frame
chain. A binding hop does not go through that path at all: `const f = k` records a
function-value target for `f`, and the readers that resolve a call THROUGH a binding
(`calleeRetKindSid` and the `fnValTarget` family) key on the name `k` with no frame, so the
instance's `f` names the template's slot. The delivery is what separates the family: the same
program with `return k(1)` runs at every pin the matrix covers.

Three of the sixteen cells changed symptom rather than outcome when [D1780](D1780.md) landed —
a scalar pin now traps at runtime inside `o$1` instead of failing validation, because the
instance's own signature is right and only the callee it reaches is wrong.

| string pin → f64, i64, `i32[]`, `f64[]`, anonymous struct | invalid wasm or a trap | no |
