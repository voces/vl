### D17167 — the IR misses a generic function held in a record a generic maker returns, at two instances

**runs today and must keep running · an IR coverage defect · filed 2026-11-24 against master `aef0be317` by lane IR-N2 (census class `start: field read coercion`, family G, 1 cell)**

Repro:

    function id<T>(x: T): T { return x }
    function run<T>(_x: T) {
      return [{ f: id }]
    }
    print(run("ab")[0].f("ab"))
    print(run(true)[0].f(false))
    // VL_IR_SHADOW=1 vl build: `start uncovered field read coercion` (kid rep closure → closure)

Want:

    ab
    false

#### Mechanism

`buildMember` (`ir_build_ref.vl`) declines a plain struct field read when the field's kid rep is
not the read's rep: here two different closure reps (measured with a probe build naming both). Legacy
builds the read; which decision gives the read its rep is the fix's to establish.
