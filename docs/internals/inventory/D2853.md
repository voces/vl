### D2853 — a record's function-valued field built in a hole-parameter function reads back in the first instance's format at every pin

**check-clean silently wrong · clause 1 · identical on master `721781075` · found by the #3220 round-3 review (`r3_fn/loc_true_7_*`) · filed 2026-09-27**

Repro:

    function mk(x) {
      const r = { f: x, g: () => x }
      return r
    }
    const a = mk(true)
    print(mk(7).g())
    // PRINTS true
    // vl check: rc 0.  vl run: prints `true`, want `7`

Want:

    7

#### Mechanism

Not ablated to a rung. The closure field's lambda is shared by both instances of `mk`, and
the field's call result is classified once, by the first instance's pin (`boolean`), so
the `i32` instance's `7` prints as a boolean. The same closure returned bare runs: it has no
record row between the call and its classifier.

#### Ablation

| ingredient removed | outcome | needed? |
| --- | --- | --- |
| the record (`const g = () => x; return g`) | runs, prints `true` then `7` | **yes** |
| the second pin (`mk(true)` only) | runs | **yes** |

#### Grading list

The review's `mk2` shapes, invalid wasm on both seeds when the closure field's pins differ in
rep: `function mk2(x) { return { f: x, g: () => x } }` with `mk2(7).g()` and `mk2("s").g()`
(`rvp/r3/q2.vl`, `q4.vl`, `rvp/r4/p0b.vl`).
