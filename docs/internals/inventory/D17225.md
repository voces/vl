### D17225 — a generic maker's call is not built at the record its delivery stores a field differently, so the check refuses it

**closed 2026-11-28 by I8-PREP · runs, prints `8` `null` · was: loud check reject · clause 2 · `they store field `f` differently (`null` into `i32 | null`), and a record is shared, not copied` · a generic maker with one instance (`recGenericOneInstance`, check_rec_fresh.vl) is admitted wherever a non-generic maker is, and built at its destination's record; two instances, or one at differing records, stay refused as [D17874](D17874.md) (coordinator ruling) · filed 2026-11-24 against master `2cbee5d4b` by IR-N5 (found grading [D17224](D17224.md)'s ablation)**

Repro:

    type J = { f: i32 | null, g: i32 }
    function mk<T>(x: T) { return { f: null, g: x } }
    const j: J = mk(8)
    print(j.g)
    print(j.f)
    // vl check: rc 1 at 3:14, they store field `f` differently (`null` into `i32 | null`)

Want:

    8
    null

#### Mechanism

A non-generic maker's call delivered at a record that stores a field differently is built there:
the delivery's pend (`recPend` → `recAdoptNote` → `recKeptFnPush`) keeps the maker's result and
builds it at the destination. A generic maker's instance is not reached by that build, so the
call's record stays at its own storage and the check refuses the share. The refusal names the
storage mechanism, not a contract: the same program with `mk(x: i32)` runs.
