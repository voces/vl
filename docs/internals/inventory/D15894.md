### D15894 — a `let` list literal binding returned by an inferred function is refused when the call is delivered as a list of a wider record

**loud check reject, clause 2, `{v: i32}[] is not D[]: a container never widens implicitly …` · the same on master `abcedd2ec` · the `const` spelling runs · found grading D15871's `return_inferred` cell · filed 2026-11-12 against master `abcedd2ec`**

Repro:

    type D = { v: i64 }
    let q = [{ v: 3 }]
    function g() {
      return q
    }
    const v: D[] = g()
    print(v[0].v)

Want:

    3

#### Mechanism

D3340 builds an un-annotated list literal binding at the list a delivery wants. Through an
inferred function's result the `const` binding is followed to its literal, but the `let` is not, so
the call's result is judged at the binding's own type and refused.
