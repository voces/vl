### D16901 — a lambda's record result at a generic's `() => T | string | null` is refused by monomorphization

**closed 2026-11-16 — the witness runs and prints `7` · was: loud emit reject · clause 2 · `vl check` rc 0 · `emitProgram: monomorphize: unsupported argument type for \`f\` in a call to \`get\`` · found grading [D14082](D14082.md) · pre-existing on master `d7a6bf679` · filed 2026-11-16 by lane AE4**

Repro:

    type P = {a: i32}
    function get<T>(f: () => T | string | null) {
      f()
      return 7
    }
    print(get(() => ({a: 2})))

Want:

    7

#### Mechanism

Not traced. The instance's argument type is the lambda's `() => P` handed to
`() => P | string | null`, a union of a record, a scalar and `null`, which monomorphization has
no argument rep for. [D14082](D14082.md)'s `T | string` spelling runs.

#### Fix

`bindGenFnRetUnionArm` (`compiler/check_relate_core.vl`) took a nullable result for the
`() => T | null` default, so `() => T | string | null` bound no union arm and D10133's bound-type
delivery never adapted the lambda. A nullable result around a union, given a non-null result, now
binds at the union inside, and the lambda is delivered through `fvaAdapt` at the bound type.
