#### Mechanism

The list's value is a call result, not a name. `monoFlowLeafGen` followed a `const` chain only
to a name, so the read plan had no generic to rewrite the element call to, and `id` reached
the emitter as an open value. Once the leaf resolved through the call, `id`'s `return` still
refused: it was in `monoRetCopyReads` (D9383), and `monoStubValueOk` refused any such value
even when nothing calls it. The call still runs once; only its result is read by name. The
`return_inferred` cell of `fn-value-generic-pushed-open` is this shape.
