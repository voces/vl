### D1967 — REBINDING a captured list inside a closure (`out = [7, 8]`) is refused at emit: `captureBoxRewrite` boxes only a captured-mutated `let` whose initialiser is a scalar literal

**closed by [D2285](D2285.md) · was a loud emit reject (`emitProgram: assignment target is not a parameter, local, or global`), clause 2 · filed 2026-09-22 against master `a8a104432`, found beside [D1965](D1965.md)**

Repro:

    function main() {
      let out: i32[] = [1]
      const f = () => { out = [7, 8] }
      f()
      print(out.length)
    }
    main()
    // vl check: rc 0.  vl build: emitProgram: assignment target is not a parameter, local, or global

#### Mechanism

A closure's captures are copied into its env at creation, so an ASSIGNMENT to a captured name
has no slot. `captureBoxRewrite` (`compiler/emit_rewrite.vl`) closes that for scalars by rewriting
the `let` into a shared length-1 list, but `cboxInitScalar` admits only a numeric or string
literal initialiser, so a list-, struct- or call-initialised `let` reaches `emitAssign` unboxed.
In-place mutation of the same list (`out.push(x)`) needs no box and runs since D1965.

#### The close

[D2285](D2285.md) boxes every captured-written `let` whatever its initialiser. The grading
list runs: `string[]` prints `2`, `P[]` prints `8`, a struct `let` prints `7`, and a rebind
then a maker-side `.push` prints `3`.

#### Grading list

The same program at `string[]`, `P[]` and a struct `let`; a captured `let` reassigned in the
closure and then `.push`ed by the maker. Note beside it, not a defect of this row: a rebind in
the MAKER after the closure was built (`let n = 1; const f = () => print(n); n = 2; f()` prints
`1`) is the capture-by-value rule the scalar box fixture states; boxing on a closure-side write
only is what makes the two spellings differ, and any change there is a language ruling.
