### D3006 — an `i32 | null` field re-seated at a wider declared `f64 | null` record is read back through `??` at its own type

**check-clean invalid wasm · identical on master `b34730ad9` and on #3253 · found by the #3253 review grid · filed 2026-09-28**

Repro:

    type D = { v: f64 | null }
    const x: i32 | null = 3
    const c: {[string]: D} = Map()
    const o = { v: x }
    c["k"] = o
    print(o.v ?? 0)
    // vl check: rc 0.  vl run: invalid module — type mismatch

Want:

    3

#### Mechanism

The map store builds `o` at `D`, whose `v` is an `f64 | null` box, and `o.v ?? 0` is lowered at the checker's `i32 | null` rep, so the box's payload is read at the wrong width. The D2991 box retag (#3252) converts a box delivered into a wider field; nothing converts one read back out at the narrower type.
