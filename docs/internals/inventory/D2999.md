### D2999 — a list of `string | i32` boxes delivered as `readonly (string | i64)[]` shares boxes the reader casts wrongly

**loads then traps · clause 1 · identical on master `f186a5415` · the readonly arm of [D2982](D2982.md), found by the #3252 review · filed 2026-09-28 against master `f186a5415`**

Repro:

    function view(xs: readonly (string | i64)[]) {
      const v = xs[0]
      if v is i64 { print(v + 1) } else { print(v) }
    }
    function go(c: boolean) {
      const l: (string | i32)[] = [if c { "b" } else { 7 }]
      view(l)
    }
    go(false)
    // vl check: rc 0.  vl run: wasm trap: cast failure

Want:

    8

#### Mechanism

A readonly list is covariant, so the checker delivers the source list as a view, as D965 does for
`i32[]` into `readonly i64[]`. For a scalar element D965 builds a converting copy. For a union
element nothing does: the view shares the `string | i32` boxes, and a read of the `i32` member as
the destination's `i64` casts the wrong box. The fix is D965's converting copy extended to a union
element (each box rebuilt under the widened member, as D2974's delivery retag does). Refusing it
would be a capability refusal, since D965 serves the scalar twin.

#### Ablation

| ingredient changed | outcome | needed? |
| --- | --- | --- |
| a `string` element (`["a"]`) and a length-only reader | runs, prints `1` | **yes** |
| the mutable destination `(string \| i64)[]` | check reject ([D2982](D2982.md), design) | **yes** |
| `(string \| f64)` in place of `(string \| i64)` | traps | no |
