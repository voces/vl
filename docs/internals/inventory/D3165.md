### D3165 — a hole-bound field function whose result is not a scalar or a string has no signature key, and a second instance called it through the all-`i32` functype

**loud emit reject · clause 2 · 63 `emit` cells of lane HF's 714-cell grid (the `hole` spelling, a nullable or record result, or an instance mix holding one; every `use` but `pass`), 19 of which trapped on master · was an indirect-call trap where another instance interned an `i32`-result signature, now refused (`cloCallArityFallbackUnsound` reads the bound type) · filed 2026-09-29 against master `934f169f4`**

#### Mechanism

D3117 keys a call of a hole callee (`const g = z.f`, then `g()`) by the function type the
instance binds it to only when the result is `i32`, `boolean`, `f64` or `string`, the results
whose classifiers read the hole pin. Any other result (`i32 | null`, a literal union, a
record) leaves the call unkeyed, and the value-call lowering then fell back to the all-`i32`
functype of the call's arity whenever one existed. That fallback's soundness test read the
callee's recorded type, which is a hole, so it passed; with an `i32`-result signature interned
elsewhere in the module the call dispatched through it and trapped. The test now reads the
bound type and refuses. What stays open is the capability: keying the call, and the result
consumers (`print`, a `??` operand, a field read `g().v`, a capturing lambda's result) reading
the hole pin for a box, a niche or a record.
