### D16978 — an un-annotated binding of a maker call, the maker built at a declared record its value later reaches, keeps the maker's union cell and builds invalid wasm

**check-clean invalid wasm · clause 1 · found by lane F2 ablating D16972 · filed 2026-11-18 against master `5649630f1` by lane F2**

Repro:

    type J = { a: i32 }
    type K = { j: J | null }
    function mk(b: boolean) { return if b { { j: { a: 1 } } } else { { j: null } } }
    const t = mk(true)
    let v: K = t
    print(v.j?.a ?? 0)
    // vl check: rc 0.  vl run: invalid module, `global.set` of `t` expects the union box, finds K

Want:

    1

#### Mechanism

The maker is built at `K` (D15719), because its value reaches `K` through `t`, so `mk` returns
`(ref K)`. The holder `t` is un-annotated, and its cell is read from the checker's type of the
call, the union of the two literal records, so the cell is the union box and `global.set` gets K.
The record solve's held-build answer for a binding (`recBuildTyOf`, read by `letHeldTyOf`) is not
recorded for a binding whose initialiser is a call of a maker built elsewhere. The checker knows the
build: reading `t` at its own type beside a delivery at `K` is refused with "this value is built as K
where line 5 delivers it".
