### D6792 — a hole function read out of a two-element list and handed a generic is refused at emit

**loud emit reject · `vl check` rc 0 · clause 2 · CAPABILITY: the same call on a one-element list, or on each function by name, runs; with `fs[1](add)` added it runs ([D6832](D6832.md)) · what is left is the other element, `apply3`, taken as a value and never called, the shape that refuses alone as [D6830](D6830.md); that the two are one mechanism is not yet ablated · found closing [D6764](D6764.md) · filed 2026-10-18 against master `a921d55c7`**

Repro:

    function add(a, b) { return a + b }
    function apply2(g) { print(g(1, 2)); print(g(1.5, 2.5)) }
    function apply3(g) { print(g(1, 2)); print(g(1.5, 2.5)) }
    const fs = [apply2, apply3]
    fs[0](add)
    // vl check: rc 0.  vl run: emitProgram: cannot take the generic function `add` as a value — a function value carries ONE signature
    // (on master `a921d55c7`: a generic function is passed to a function value whose parameter type names a type parameter this closure does not bind)

Want:

    3
    4

#### Mechanism

From the ablation only. The split rewrites a list element's call only when the list holds one
hole function; with two the element is a value of one function type whose parameter is still a
hole, and the generic handed to it has no instance to choose, at one call type or two.
