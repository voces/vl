### D2431 — a module-level `const` bound to a map read is initialised ahead of the statements above it when a `?.` call statement precedes them

**closed 2026-09-25 — the filed repro RUNS and prints `v` · was check-clean silently wrong · found while grading A15's `Map<K, V>` position matrix (the nested-map block) · filed 2026-09-25 against master `a277bf7b0`**

Repro:

    let xs: i32[] | null = [1]
    xs?.push(4)
    const n: {[i32]: string} = Map()
    n[1] = "v"
    const q = n[1]
    print(q ?? "null!")
    // was: prints null!
    // vl check: rc 0.  vl run prints `null!`; the program means `v`.

#### Mechanism

The start function interleaves module binding initialisers (`globalStmts`) with the other
top-level statements (`startStmts`) by merging the two lists on an order key, and that key was
the node's ARENA index (`topStmtOrderKey`, plus two side tables for nodes the passes minted:
`asvKeyOf` and `hmsTopBefore`). A pass that replaces a top-level statement with a node it
mints — `dispatchRewrite`'s `drwOptGuard` for a `?.` call, `drwBareBlock` for a bare block, a
top-level compound spill, `cboxModuleFrame` for a block whose binding a closure captures —
hands the merge a node whose arena index is past every source node, so every binding after it
is initialised first, and the statements after it (which the merge only reaches in list order)
move with it. The fix keys the merge on the node's POSITION in the module's statement list as
`collectFns` reads it (`startStmtOrd` / `globalStmtOrd`), one authority that a later
replacement cannot move; the three arena-keyed tables are gone.

#### Ablation

| ingredient removed | outcome | needed? |
| --- | --- | --- |
| `xs?.push(4)` replaced by `if xs != null { xs.push(4) }` | prints `v` | **yes** |
| the map declared ABOVE the `?.push` line | prints `v` | **yes** |
| the whole program inside a `function main()` | prints `v` | **yes** — module level only |
| `const q = n[1]` replaced by a direct `print(n[1] ?? "null!")` | prints `v` | **yes** — a module-level binding |
| `const q = n[1]` replaced by `let q = null` then `q = n[1]` | prints `v` | **yes** — an initialiser, not an assignment |
| `q`'s annotation added (`const q: string \| null = n[1]`) | still `null!` | no |
| the map read replaced by a list `.get(0)` | prints `v` | **yes** |
| `xs` initialised `null` instead of `[1]` | still wrong | no |

#### Grading

A laneO ordering grid: 21 module-level statement kinds (plain call, `?.` call, bare block,
bare block with a binding, assignment, compound assignment on a name / element / field, map
write, `if`, `if`/`else`, `for` range, `for` in, `while`, `match` statement, `match` over a
computed scrutinee, assignment as a value, closure creation and call, a module block whose
binding a closure captures, `print` of a call) x 8 initialiser shapes (`const`, `let`,
annotated, a call, a list, a struct, a `match` initialiser over a computed scrutinee, an
assignment-as-value initialiser) x 2 templates (the statement writes the state itself; the
statement is scenery before a later plain write), each printing the values before and after.
Master: 256 / 336; the 80 failures are exactly the five kinds that mint a replacement node
(a `?.` call in two shapes, a bare block in two, a block whose binding a closure captures). After: 336 / 336.
