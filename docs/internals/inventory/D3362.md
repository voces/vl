### D3362 — a join of type parameters returned into a hole-typed caller answers `"x" is P` true

**check-clean silently wrong · clause 1 · open · on master `455e553ca` the first line is the same and the second call traps on a null reference · found by the #3310 round-3 re-review (`rv3310r3/m/hg1.vl`; the g5 grid's `hole_gen_ret` programs) · filed 2026-09-30**

Repro:

    type P = {x: i32}
    function j<T, U>(a: T, b: U, k: i32) {
      return if k == 0 { a } else { b }
    }
    function h(a, b, k: i32) {
      const r = j(a, b, k)
      print(r is P)
    }
    const x0: string = "x"
    const x1: string | null = null
    h(x0, x1, 0)
    h(x0, x1, 1)
    // today it prints true false

Want:

    false
    false

#### Mechanism

Not localised past the ablation. `h`'s parameters are holes, so `r` is typed by the join `j`
returns with no pin of its own, and the `is P` over it is not folded against the instance's
`string | null`: a string answers as the record.

#### Ablation

| ingredient changed | outcome on master | needed? |
| --- | --- | --- |
| `h(a: string, b: string \| null, k: i32)` | refuses: `is` check type 'P' is not a variant of string \| null | **yes** (the holes) |
| `j` called at top level, no `h` | the same refusal | **yes** (the hole-typed caller) |

The two `hole_gen_ret` `isall` cells of the round-3 g5 grid (`s_sn`, `sn_sn`).
