### D3362 — a join of type parameters returned into a hole-typed caller answers `"x" is P` true

**closed 2026-11-02 · runs, prints `false` `false` · was check-clean silently wrong, clause 1 · fixture `tests/cases/generics/hole-caller-is-record-over-nullable-call-result.vl` · found by the #3310 round-3 re-review (`rv3310r3/m/hg1.vl`; the g5 grid's `hole_gen_ret` programs) · filed 2026-09-30**

Repro:

    type P = {x: i32}
    function j<T, U>(a: T, b: U, k: i32) {
      return if k == 0 { a } else { b }
    }
    function h(a, b, k: i32) {
      const r = j(a, b, k)
      print(r is P)
    }
    const x0: string = "x"
    const x1: string | null = null
    h(x0, x1, 0)
    h(x0, x1, 1)

Want:

    false
    false

#### Mechanism

`r` is a call result, and `nulNicheIsTestImpossible` would not fold a record test over a call
result (`readIsCallResult`), since the instance did not build that join. The receiver's niche
then lowered `is P` as its null test, so a present string answered as the record. The fold now
reads the niche the callee lowers (`callLoweredNicheClass`, through a `const` bound to the call):
a record is never the member of a `string | null` or `boolean | null` result. The same holds for a
one-parameter identity (`idt(a) is P`).

#### Ablation

| ingredient changed | outcome on master | needed? |
| --- | --- | --- |
| `h(a: string, b: string \| null, k: i32)` | refuses: `is` check type 'P' is not a variant of string \| null | **yes** (the holes) |
| `j` called at top level, no `h` | the same refusal | **yes** (the hole-typed caller) |
