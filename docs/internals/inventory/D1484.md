### D1484 — the UFCS spelling of a call loses the declared parameter type for a LAMBDA argument, and the free-call spelling of the same function infers it

**loud check reject · clause 2 · ``cannot infer a type for parameter `a``` · the free-call spelling of the identical call runs · filed 2026-09-03 against master `cdfdc14e`**

Repro (three lines; line 2 runs and prints `true`, line 3 is rejected at 3:17):

    function pick(self: i32[], f: (i32) => boolean) { return f(self[0]) }
    print(pick([1], (a) => a > 0))
    print([1].pick((a) => a > 0))

#### Mechanism

Not generics, and not the callee: the same NON-generic `pick` accepts the un-annotated lambda
at the free-call spelling and rejects it at the UFCS one, so the declared `(i32) => boolean`
is visibly present and reachable at slot 1 either way. What differs is the receiver-shift
rewrite that turns `xs.pick(f)` into `pick(xs, f)` — the contextual type is available for
slot 0 (the receiver type-checks fine) and lost for every argument after it.

The BUILTIN methods do not have this problem — `nums.map((a) => a * 2)` and
`nums.filter((a) => a > 1)` both infer `a` — which is what says the parameter type is
recoverable at a method-shaped call and is simply not consulted on the UFCS path.

The refusal wording is a plain inference message and concedes no capability, so this is a
clause-2 violation the `goal-scoreboard.py` phrase filter cannot see: only the two-spelling
witness settles it.

#### Ablation

| ingredient removed | outcome | needed? |
| --- | --- | --- |
| the UFCS spelling (`pick([1], …)`) | runs | **yes** — the rescue |
| the un-annotated lambda (`(a: i32) => a > 0`) | runs | **yes** — the second rescue |
| the lambda (a named function value `[1].pick(pos)`) | runs | **yes** |
| the non-generic callee (a generic `firstWhere<T>`) | rejects, same message | no — generics are not the axis |
| the user callee (builtin `nums.map` / `nums.filter`) | runs | the builtins DO infer |
| the literal receiver (a named `i32[]` binding) | rejects, same message | no |
| the `i32` element (a struct element with `std:array`'s `sorted`) | rejects, same message | no |

#### Grading list

The three rescues must keep running, and the builtin `.map`/`.filter` inference must not
regress. Grade at BOTH a generic and a non-generic callee and at argument slots beyond the
first — `xs.sorted((a, b) => a.points > b.points)` is the shape a day-one user writes, and
`std/array.vl`'s own module header documents `sort`/`sorted` in exactly that spelling.
