### D14488 — a folded negative constant's 2^31 operand is retyped `i32`, so the emitter re-reads its lexeme

**runs today and must keep running · filed 2026-10-27 against master `4e04cd6de`**

Repro:

    print((-2147483648.0) as i32)

Want:

    -2147483648

#### Mechanism

`cexDeliver` (check_fit_rules.vl) folds the whole float constant at an `i32` destination,
rewriting the `2147483648.0` literal under the negation to `2147483648`, and `cexRetype`
(check_num_lit_state.vl) carries the destination type through the `Unary` into that operand.
The operand's own value, 2^31, is not an `i32`; only the negation is. The checker's type for
the literal node is therefore wrong, and `numLitWidth` (emit_capture_frames.vl) keeps a
lexeme fallback — an integer lexeme past the `i32` range builds `i64` whatever the type says
— that serves this node alone: over the 5,098 `@run` cases it is the only literal typed `i32`
whose lexeme is not an `i32` constant (one file, `numerics/as-cast-constant-fits.vl`). With
the fallback deleted the witness still prints `-2147483648`, so the fallback is a second
producer, not a load-bearing one. The close types the operand at the checker (its own width,
or the negation folded into one signed literal) and deletes the fallback.
