#### Mechanism

The union declaration makes `p` a union ARM (kind 8, a `uVarHeap` ref) rather than a plain
struct, and the struct-field machinery reads the two tables through different resolvers. The
holder literal `{ f: p }` with no annotation is matched against the union's variants by field
set (`objVariantName`), which cannot name a holder whose only field is itself an arm; the
annotated holder resolves, and it is the field WRITE `w.f = p` that then declines, because the
receiver resolver reads the struct table for a name the variant table owns.

The two cells are opposite faces, which is what makes this one row rather than two: the
un-annotated holder refuses at the literal, the annotated holder refuses at the write.
