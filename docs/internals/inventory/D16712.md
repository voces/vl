#### Mechanism

Two different functions make the inner lists a tagged set's ids, so the checker stamps each list
literal with its rep (`fnTagHeldNote`: `i32[][]` outer, `i32[]` inner) and the emitter builds it
there (`arrLitListBuild` reads `heldRepOf`). The un-annotated parameter makes `give` an instance
whose body is a copy, and the copied literals had no stamp: `heldRepOf` answered -1 on them, so each
inner literal was built at the hole type's list row, the outer list's, and its `i32` ids were
written where that row's element was wanted. Measured with a temporary probe: on the copies, held
-1; on the uncopied body (no parameter), the two reps.
