### D3174 — an un-annotated copy of a value narrowed to a union of two literal unions and `null` out of a wider box is invalid wasm

**closed · a read narrowed out of a wider box to a set of literal unions (or the `string` arm the box holds them in) and `null` converts the box to that set's atom niche · fixtures `tests/cases/unions/narrowed-nullable-two-literal-unions.vl`, `tests/cases/generics/hole-list-nullable-literal-element-null-test.vl` · was check-clean invalid wasm · clause 1 · the loud sibling over a bare `K | L | null` stays open (D3189) · filed 2026-09-29 against master `995bbc74e`, closed 2026-09-29 against master `36d233f66`**

Repro:

    type K = "a" | "b"
    type L = "x" | "y"
    function t(e: K | L | null | i32) {
      if !(e is i32) {
        const c = e
        if c == null { print("N") } else { print(c) }
      }
    }
    t("y")
    // vl check: rc 0.  vl run: invalid module inside `t`: type mismatch: expected i32, found
    // (ref $type)

Want:

    y

#### Mechanism

Not localised past the ablation. No closure is involved. The narrowed read of `e` is typed
`K | L | null`, a nullable union of two literal unions, and the copy's cell is sized as an
`i32` atom while the value the narrowed read delivers is the member's string ref. The loud
sibling is the same member set without the box: `if e != null { print(e) }` over
`e: K | L | null` refuses with `print of a union value whose arms the tag dispatch cannot
classify`, so neither spelling of the set reaches a value.

| `K \| null \| i32`, one literal union | runs | **yes** (the second literal union) |
| `e: K \| L \| null`, no box, copied | loud: `tag dispatch cannot classify` | **yes** (the box) |

#### Grading list

The witness, `t(null)`, the annotated copy, and the loud sibling
`function t(e: K | L | null) { if e != null { print(e) } }`.

#### Close

The narrowed read's niche conversion (`narrowedNulLitAlias`) named only `K | null`; it now takes
every literal-union member, or the `string` arm the wider box holds them in, beside one `null`,
so the un-annotated copy's atom cell and the read agree. A list built from a hole parameter now
reads its element at the pin (`holeArrElemPinTyOf`), so `m[0] == null` over it tests the niche.

A first round also flattened `K | L | null` into the atom niche in the annotation route. That
closed the loud sibling but cost four runs at generic pins where the same set is a box, since a
declared `K | L | null` holds a nullable string and a pinned one a box; the flatten was withdrawn
and the sibling is D3189's.
