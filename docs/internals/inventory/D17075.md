### D17075 — a record type with two nullable self fields gives its first field a kid rep `T | null` does not intern to, so a typed `null` there fails verifier rule 3

**closed · the armed shadow's `fail rule 3 … rep is not its type's`, later the builder's `record field null rep`; closed 2026-11-23 against master `714836837` (filed against `6cf67777d`)**

Repro:

    type T = { v: i32, l: T | null, r: T | null }
    function f(t1: T, t2: T): boolean { return t1 == t2 }
    print(f({ v: 1, l: null, r: null }, { v: 1, l: null, r: null }))
    // vl run: prints true. VL_IR_SHADOW=1 vl check --codegen: "fail rule 3 in @start: v0's rep is not its type's".

Want:

    true

#### Mechanism

The record rep of `T` holds a kid rep per field. With two `T | null` fields and a compare over
`T` in the program, the first nullable self field's kid rep is a provisional nullable rep
(`nullable#1` in the IR) while the type `T | null` interns to another (`nullable#3`), which the
second field takes. The IR builds a typed `null` field at its kid rep and types the temp by that
rep's type, so the temp's rep is not its type's rep and the verifier's rule 3 refuses the function.
Legacy's bytes are unaffected; the start falls back. Since the record-compare place operand
(`ir-record-compare-global`), the builder names this case `record field null rep` before the
verifier sees it.

The cause is in the rep layer. The arena does not hash-cons nullables, so the two fields carry two
`T | null` ids. The compare builds `l`'s id first: its nullable node is provisional while `T`'s
record builds `r`'s id as a second node, which interns. The first node completes last, collides with
that twin and is orphaned, but `T`'s first kid still holds it. `rtOfNullable` now keeps one node per
inner type in a generation (`rtNulByInner`), so the second spelling reuses the node under
construction; the start is covered, verified and matched.

#### Ablation

| ingredient | outcome | needed? |

| the literals at a call argument (bound to `const` instead) | rule 3 once the compare is covered | no |
