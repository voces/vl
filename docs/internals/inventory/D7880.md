### D7880 — a closure literal returning a one-literal set's member is refused against that set's function type

**loud check reject · clause 2 · open · `() => "a"` against `() => "a" | "b"` or `() => "a" | null` runs, so only the bare one-member set is refused · found closing [D7452](D7452.md) · present on master `5d224f614` · filed 2026-10-20 against master `5d224f614`**

Repro:

    function one(f: () => "a"): i32 { return 1 }
    print(one(() => "a"))
    // vl check: argument 1: expected () => "a", got () => string

Want:

    1

#### Mechanism

The lambda's return is inferred as `string`. The arm that adopts a contextual literal result
(`inferRetAdoptNiche`, check_inferred_return.vl) guards on `tyIsLitUnion(expRet)`, and an inline
`"a"` result is a bare literal, not a set, so the arm is not taken. An alias `KA = "a"` result
runs. The fix is not contained in the function-type relation. Normalising every function
type's one-literal result to its one-member set (`strLitAsSet` in `mkFuncTy`) was tried by lane
L6 and refused: `function g(): "a"` returns a string ref, so `const h: () => "a" = g` then
trapped on an indirect call signature mismatch, which had run before. A declared one-literal
return would have to move to the set too.

#### Ablation
