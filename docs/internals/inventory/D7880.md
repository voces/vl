### D7880 — a closure literal returning a one-literal set's member is refused against that set's function type

**closed · was loud check reject, clause 2 · found closing [D7452](D7452.md) · filed 2026-10-20 against master `5d224f614` · closed by lane L6 against master `981320f30`**

Repro:

    function one(f: () => "a"): i32 { return 1 }
    print(one(() => "a"))
    // vl check: argument 1: expected () => "a", got () => string

Want:

    1

#### Mechanism

The lambda's return is inferred as `string`. The arm that adopts a contextual literal result
(`inferRetAdoptNiche`, check_inferred_return.vl) guards on `tyIsLitUnion(expRet)`, and an inline
`"a"` result is a bare literal, not a set, so the arm is not taken. An alias `KA = "a"` result
runs. Normalising every function type's one-literal result to its one-member set
(`strLitAsSet` in `mkFuncTy`) was tried and refused: `function g(): "a"` returns a string ref,
so `const h: () => "a" = g` then trapped on an indirect call signature mismatch. The close
leaves the function type alone and takes the adopting arm for a bare string-literal `expRet`
too: the lambda's result becomes `"a"`, a string ref exactly as a declared `: "a"` return is.

#### Ablation

| ingredient changed | outcome on master `5d224f614` | needed? |
| --- | --- | --- |
| `f: () => "a" \| null` | runs, prints `1` | **yes**, the bare one-member set |
| `f: () => "a" \| "b"` | runs, prints `1` | **yes**, one member |
| `one((): "a" => "a")` | runs, prints `1` | **yes**, the un-annotated lambda |

#### Grading list

`tests/cases/literal-unions/closure-literal-adopts-a-one-literal-result.vl` covers an argument,
a call through the parameter, an annotated binding, a list element beside a named `g`, a
returned closure, a record field, a reassignment and a one-parameter callback. `() => "b"`
against `() => "a"` still refuses. A call of a call or of a field with this result type is
check-clean invalid wasm with a named function too; that is [D8001](D8001.md).
