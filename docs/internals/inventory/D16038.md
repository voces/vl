### D16038 — a struct-union `==` whose operands differ only by `| null` reaches the union-against-concrete arm, which refuses it

**loud emit reject · clause 2 · open · found probing D15975's identity operands · filed 2026-11-14 against master `f7758db99`**

Repro:

    type P = { x: i32 }
    type Q = { y: i32 }
    const p: P = { x: 1 }
    function same(a: P | Q, b: P | Q | null) { a == b }
    print(same(p, p))
    print(same(p, null))
    // vl check: rc 0.  vl run: emit error, "emitProgram: `==` over a struct union is not supported yet"

#### Mechanism

The union-against-union compare claims a pair only when both operands carry one union.
`P | Q` beside `P | Q | null` is not that pair, so it falls through to
`emitUnionConcreteEq` (compiler/wasmEmit.vl). That arm reads the nullable union as the
"concrete" side, finds no struct variant for it, and refuses. Both values are the same box
type, and `null` is one more tag arm of it, so the tag-then-payload compare that serves two
`P | Q | null` operands already covers this pair. The `===` spelling of the same program runs
(D15975), since it compares the payloads.

#### Ablation

| ingredient changed | outcome | needed? |
| --- | --- | --- |
| both operands `P \| Q \| null` | runs, `true` `false` | **yes** |
| operands swapped (`P \| Q \| null` first) | the same refusal | no |
| a value union `i32 \| string` beside `i32 \| string \| null` | runs | **yes** (a struct union) |
| `P` beside `P \| null`, no union | runs | **yes** |
