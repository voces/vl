### D14512 — a call delivered to a wider record type also stored by value elsewhere is check-clean invalid wasm when no record type names its shape

**closed · now runs, prints `5` · was check-clean invalid wasm, clause 1 · filed 2026-10-27 against master `8f810b02b` · closed 2026-10-31 against master `54db9267` by deleting the `recReadInPlace` term · fixtures `soundness/call-built-wider-stored-by-value-elsewhere-runs.vl` and `soundness/relayed-call-built-wider-stored-beside-declared-row-runs.vl`**

Repro:

    type J = { f: i32 | null }
    function mk() { { f: 4 } }
    const wideJ: J = mk()
    const wideF: i32 = wideJ.f ?? 0
    const c = mk()
    const v = c
    print(v.f + 1)

Want:

    5

#### Mechanism

`const wideJ: J = mk()` builds `mk`'s record at `J`. A second call that is queued for no
delivery is served from that build only when `recReadInPlace` says it is read for a field
(`recSitesLandAt`, check_fit_rules.vl). An alias, a container or a return stores the value
instead, so the second site keeps `{ f: i32 }` as its type while the function now builds a `J`,
and the module fails to validate on the `const wideJ` line. With `type II = { f: i32 }` declared,
the same programs are a loud check refusal at `wideJ` instead, which is D8302's shape.

#### Grading list

Each program below is the Repro's first four lines followed by the lines shown. All are invalid
wasm on `8f810b02b`, and all run with `|| !recReadInPlace(c)` removed from `recSitesLandAt`, so
this row closes with the D14509 rip.

* Binding and alias (the Repro), and its guarded form `if v.f == 4 { print(v.f + 1) } else
  { print(0) }`. A third form, `const t: i32 = v.f` then `print(t)`, prints `4`.
* List element: `const xs = [mk()]` then `print(xs[0].f + 1)`. Also with `const v = xs[0]`
  then `print(v.f + 1)`, and with `if xs[0].f == 4 { print(1) }`.
* Record field: `const w = { g: mk() }` then `print(w.g.f + 1)`.
* Map value: `const m = Map()`, `m.set("k", mk())`, `const x = m.get("k")`, then
  `if x != null { print(x.f + 1) }`.
* Return through a call: `function d() { return mk() }`, `const v = d()`, then
  `print(v.f + 1)`.

`const c = mk()` followed only by `print(c.f + 1)` runs today, because that is the field-read
case `recReadInPlace` admits. The un-annotated parameter delivery is D14513, which is a separate
defect.
