### D1646 — a comment written BETWEEN two `match` arms is moved by `vl fmt` into the following arm's body, or out of the `match` entirely

**closed 2026-09-05 — the witness runs and its comment stays where it was written · was a `vl fmt` relocation on a `vl check`-clean program · fixed by giving `matchExprFmt` a per-arm comment flush, taking each arm's own trailing comment before the next arm's lead, and splitting the fused `} else if` when a comment sits there**

Repro (runs, prints `3`):

    type A = { a: i32 }
    type B = { b: i32 }
    type N = A | B

    function pick(n: N): i32 {
      match n {
        A => {
          return n.a
        }
        // Both arms hand back the field the arm names — this comment is about the PAIR.
        B => {
          return n.b
        }
      }
    }
    print(pick({ a: 1 }) + pick({ b: 2 }))
    // vl check: rc 0.  vl run: 3.  vl fmt -w: the comment moves INSIDE the `B` arm.

#### Mechanism

The witness RUNS, and the status line says so, because the defect is in a tool
`check-filed-witnesses.py` does not drive: `vl fmt -w` rewrites the file and the comment is
not where it was written. Filing it at any reject-shaped status would report a MOVED row on a
program behaving exactly as filed, so the pin is the runnable half and this is the rest.

`compiler/format.vl` has no slot for a comment that sits between two arms of a `MatchExpr` —
the arms are printed from `matchPats`/`matchBodies`, and a comment attaches to the nearest
following node, which is the next arm's BODY rather than its pattern. It comes out one level
too deep, with a blank line after it. **A braceless arm has no body block to fall into, so the
comment leaves the `match` altogether** and lands after the closing `}`, which is the worse of
the two faces: a comment about one arm ends up describing the statement after the construct.

It is meaning-preserving for the program and lossy for the reader, and it scales with any bulk
conversion of `if` ladders to `match`: the pilot recorded in `docs/internals/kind-ladder-lint.md`
relocated comments in eight of the 31 ladders it rewrote, one of them (`liftFnsInExpr`'s D1085
note, about `AsExpr` AND `IsExpr`) into the first of the two arms it describes.

#### Ablation

Every row is `vl check` rc 0 and prints the same value before and after `vl fmt -w`.

| where the comment sits | before | after |
| --- | --- | --- |
| between two BRACED `match` arms | **into the next arm's body, plus a blank line** | stays put |
| between two BRACELESS arms (`A => 1`) | **out of the `match`, after its closing `}`** | stays put |
| above the FIRST arm | **out of the `match`** | stays put |
| after the LAST arm | **out of the `match`** | stays put |
| TRAILING on an arm's own line | **out of the `match`** | stays on its arm |
| inside an arm body (control) | stays put | stays put |
| directly above the `match` (control) | stays put | stays put |
| inside an `if` clause body (control) | stays put | stays put |
| between an `if` and the next statement (control) | stays put | stays put |
| between two `if` / `else if` arms | **moves** into the `else if` body | stays put — the fused `} else if` splits |
| between `else if` and `else` | **moves** into the `else` body | stays put |
| a fused chain with NO comment (control) | stays fused | stays fused |

Needed: the comment being between two ARMS of a `match`. Not needed: the pattern kind
(literal or type), the arm count, or the enclosing function's shape.

#### The `if`-chain row was a CONTROL that was not one — and it is the third fix

This row filed *"between two `if` / `else if` arms — stays put"*. Run verbatim, that spelling
does not stay put: `if a { … }`, an own-line comment, then `else if b { … }` migrates into the
`else if` body with a blank line, exactly as the `match` form did. Two neighbouring `if`
spellings DO stay put and are the real controls — a comment inside a clause body, and a comment
between an `if` statement and the next statement.

**The ruling: a formatter never relocates a comment across a structural boundary.** The chain's
canonical layout fuses `}` and `else if` onto one line, so the comment has no line to sit on —
and the answer is to give it one. `splitFusedClause` breaks the fusion into `}`, the comment
lines, then the clause, and ONLY when a comment sits there; every chain without one keeps the
fused form. Both faces are pinned, `if`/`else if` and `else if`/`else`, and so is the fused
control.

#### Grading list

* The control rows above, which must stay put, and the fused-chain row, which must stay
  fused.
* [D1647](D1647.md) — the other `match`-printer defect; a rewrite of the arm printer should
  re-grade both, and closing one must not move the other's witness.
* `vl fmt --check` must stay idempotent on its own output: the relocated comment currently
  survives a second pass, so a fix must not trade the relocation for a file that never settles.
