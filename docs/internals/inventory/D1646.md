### D1646 — a comment written BETWEEN two `match` arms is moved by `vl fmt` into the following arm's body, or out of the `match` entirely

**runs today and must keep running · filed 2026-09-05 against master `ce4f063b`**

Repro (runs, prints `3`):

    type A = { a: i32 }
    type B = { b: i32 }
    type N = A | B

    function pick(n: N): i32 {
      match n {
        A => {
          return n.a
        }
        // Both arms hand back the field the arm names — this comment is about the PAIR.
        B => {
          return n.b
        }
      }
    }
    print(pick({ a: 1 }) + pick({ b: 2 }))
    // vl check: rc 0.  vl run: 3.  vl fmt -w: the comment moves INSIDE the `B` arm.

#### Mechanism

The witness RUNS, and the status line says so, because the defect is in a tool
`check-filed-witnesses.py` does not drive: `vl fmt -w` rewrites the file and the comment is
not where it was written. Filing it at any reject-shaped status would report a MOVED row on a
program behaving exactly as filed, so the pin is the runnable half and this is the rest.

`compiler/format.vl` has no slot for a comment that sits between two arms of a `MatchExpr` —
the arms are printed from `matchPats`/`matchBodies`, and a comment attaches to the nearest
following node, which is the next arm's BODY rather than its pattern. It comes out one level
too deep, with a blank line after it. **A braceless arm has no body block to fall into, so the
comment leaves the `match` altogether** and lands after the closing `}`, which is the worse of
the two faces: a comment about one arm ends up describing the statement after the construct.

It is meaning-preserving for the program and lossy for the reader, and it scales with any bulk
conversion of `if` ladders to `match`: the pilot recorded in `docs/internals/kind-ladder-lint.md`
relocated comments in eight of the 31 ladders it rewrote, one of them (`liftFnsInExpr`'s D1085
note, about `AsExpr` AND `IsExpr`) into the first of the two arms it describes.

#### Ablation

Every row is `vl check` rc 0 and prints the same value before and after `vl fmt -w`.

| where the comment sits | what `vl fmt -w` does |
| --- | --- |
| between two BRACED `match` arms | **into the next arm's body, plus a blank line** |
| between two BRACELESS arms (`A => 1`) | **out of the `match`, after its closing `}`, plus a blank line** |
| between two `if` / `else if` arms | stays put |
| inside an arm body | stays put |
| directly above the `match` | stays put |

Needed: the comment being between two ARMS of a `match`. Not needed: the pattern kind
(literal or type), the arm count, or the enclosing function's shape.

#### Grading list
