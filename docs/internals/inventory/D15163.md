### D15163 — a local alias of a map written two functions of different result types, captured by a closure, is refused at emit

**closed 2026-11-03 · runs, prints `1.5` · was loud emit reject, `emitProgram: index receiver is not an array or string` · clause 2 · found closing [D15137](D15137.md) · filed 2026-11-03 against master `b813a46b` · closed by reading the captured env field off the local's own cell ladder, `letCellKindGo`, whose map rung `captureValKind` had skipped · fixture `tests/cases/closures/captured-alias-of-hole-fn-map-runs.vl` · matrix `captured-alias-of-hole-fn-map` · the struct-field and list-element positions are [D15186](D15186.md) and [D15187](D15187.md)**

Repro:

    function inc0(a) { return a + 1 }
    function half(a) { return a / 2.0 }
    const m = Map()
    m.set("a", inc0)
    m.set("b", half)
    function w() {
      const c = m
      const f = () => {
        const g = c.get("b")
        if g != null { print(g(3)) }
      }
      f()
    }
    w()
    // Want: 1.5

#### Mechanism

The closure's `c.get("b")` reached `emitIndex` (wasmEmit.vl), the list and string ladder, so the captured local alias was not classified as the map it copies: `captureValKind` typed the un-annotated env field with `letInitCellKind`, which has no map rung, while the local's own cell came from `letCellKindGo`, whose `letIsMap` rung answers `map`. The env field now reads the same ladder. A top-level alias, an alias read in the function without a closure, and `c[0]` over a widened list all run (measured 2026-11-03).
