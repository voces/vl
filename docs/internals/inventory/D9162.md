### D9162 — a `const` bound to an `if` of two generic functions inside a generic body instanced twice refuses when read at the body's type parameter

**closed 2026-10-21 — the filed repro RUNS and prints `ss`, `6`, `ss`, `5` · was loud emit reject, `emitProgram: a binding of an `if` choosing generic functions is delivered at two function types — annotate the binding`, `vl check` rc 0 · clause 2 · CAPABILITY: the same body instanced once runs ([D9120](D9120.md)) · found closing [D9120](D9120.md) · filed 2026-10-21 against master `4121cc9a7` · closed by the rebase onto [D9131](D9131.md)'s fix (#4335): the PR head refused it and the same head rebased onto master runs it, so the change is that merge; its mechanism was not traced**

Repro:

    function idg<T>(t: T): T { return t }
    function kg<T>(t: T): T { return t + t }
    const c = [1].length > 0
    function f<S>(v: S): S {
      const h = if c { kg } else { idg }
      print(h("s"))
      return h(v)
    }
    print(f(3))
    print(f(2.5))
    // was: emitProgram: a binding of an `if` choosing generic functions is delivered at two function types — annotate the binding

#### Mechanism

The split ([D9120](D9120.md)) rewrites the declaration once, keyed by the concrete function type
of each read, and both instances of `f` share that declaration: the `h(v)` read is `(i32) => i32`
in one instance and `(f64) => f64` in the other, so one source read wants two copies. Not traced
past that point: the refusal fires and no split runs it. Running it needs the read keyed by the body's
type parameter rather than by an instance's binding of it.

| --- | --- | --- |

| the read at `S`, `return h(v)` for `return v` | runs, `ss` `3` `ss` `2.5` | **yes** |
