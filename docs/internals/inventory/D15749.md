### D15749 — a bundle holder read where one member's function type is expected is refused at emit

**closed 2026-11-12, runs and prints `5` `4` · was loud emit reject, clause 2, `a function returning a parameter called at two signatures is called where its result is not used at one of them` · found closing [D15748](D15748.md) · closed in the elaboration and emit: an annotated `const` initialised with a holder's read is one of the holder's reads, at the member its type names (`elabResScanTypedRead`, `elabTypedReadsHold`, emit_elab.vl), and its initialiser picks that member off the record (`emitTypedHolderInit`, wasmEmit.vl), in a function or at the top level · fixture `tests/cases/closures/hole-lambda-bundle-holder-read-at-annotated-binding.vl` · not reached: an annotated parameter ([D15861](D15861.md)), a copy's read ([D15862](D15862.md)), a module holder read in a function ([D15863](D15863.md))**

Repro:

    function lap(f) {
      f(2.5)
      f(3)
      return f
    }
    function main() {
      const k = lap((a) => a + 1)
      const m: (f64) => f64 = k
      print(m(4))
      print(k(3))
    }
    main()

Want:

    5
    4

#### Mechanism

A holder keeps the bundle record whole and picks a member at each call through it (D15144), and
a copy into an un-annotated binding is followed (D15213). An annotated binding was no copy
(`elabResMayHold` takes an un-annotated `const`), so its read of the holder was one the holder
could not account for, and the whole group was refused.

#### Ablation

| spelling | outcome | needed? |
| --- | --- | --- |
| `const m = k` (no annotation) | runs (D15213) | **yes** |
| `function u(f: (f64) => f64) { print(f(4)) }` and `u(k)` | refuses | no |
| `function q(): (f64) => f64 { return c }` with `c` a module holder | refuses | no |
