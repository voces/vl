### D17561 — a hole function's `.map` callback with an un-annotated return over its `null[]` list builds invalid wasm

**check-clean invalid wasm · clause 1 · found grading D17039's close · owner SOUND · filed 2026-11-25 against master `5ca3e2eb`**

Repro:

    function k(x) { return [x].map((e) => e ?? "m")[0] }
    print(k(null))
    // vl check: rc 0.  vl run: invalid module inside `k`, expected i32, found `string`

Want:

    m

#### Mechanism

Traced 2026-11-25 by SOUND. The call's result is typed `"m"[]`: the `??`'s deferred result
(`HD_COAL`) resolves at the `null` pin to the default's own literal type (`coalJoinAtPin`), which a
direct return relies on (`function j(x) { return x ?? "m" }` delivers `j(null)` to a `"m" | "n"`
binding and runs). A one-literal list is stored as atom ids, but the callback's `e ?? "m"` writes
the default as a string, so the list's i32 slot receives a string. Widening the resolved type to
`string` (as the concrete module-level `??` types it) makes the witness run but refuses the `j(null)`
spelling, a runs → not-runs move, so it was not taken. The close is the callback's delivery of its
literal result at the list's atom element: the `??` arm writing the default at the destination's
rep, which is an emitter plan (legacy's is frozen; the IR's claim).
