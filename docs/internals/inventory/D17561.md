### D17561 — a hole function's `.map` callback with an un-annotated return over its `null[]` list builds invalid wasm

**check-clean invalid wasm · clause 1 · found grading D17039's close · owner SOUND · filed 2026-11-25 against master `5ca3e2eb`**

Repro:

    function k(x) { return [x].map((e) => e ?? "m")[0] }
    print(k(null))
    // vl check: rc 0.  vl run: invalid module inside `k`, expected i32, found `string`

Want:

    m

#### Mechanism

Not established. The same `.map` at module level (`const xs: null[] = [null]`,
`xs.map((e) => e ?? "m")[0]`) runs and prints `m`, and the hole function runs with the callback's
return written (`(e): string | i32 => e ?? "n"`). So the lambda's inferred return inside the
hole instance is read at another rep than the one its result list is built at. Before D17039's
close the same program failed earlier, on the element (`expected nullref, found i32`).

#### Ablation

| spelling | outcome |
| --- | --- |
| the witness | invalid inside `k` |
| the callback's return written `string \| i32` | runs, `n` |
| at module level over `const xs: null[]` | runs, `m` |
