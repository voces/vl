### D17561 — a hole function's `.map` callback with an un-annotated return over its `null[]` list builds invalid wasm

**closed 2026-11-25 by SOUND · runs, prints `m` · was check-clean invalid wasm, clause 1 · the `.map` call's element followed the `??`'s deferred result resolved at the `null` pin (`"m"`, stored as atom ids) while the callback's inferred signature, as the emitter lowers it, returns `string`; an un-annotated callback whose every returned value is a `??` with a literal default now builds the literal's base (`mapCoalLitElem`, check_member_call.vl), by the coordinator's ruling of 2026-11-25 · pinned by `tests/cases/generics/map-coalesce-literal-default-in-hole-fn.vl` · found grading D17039's close · filed 2026-11-25 against master `5ca3e2eb`**

    function k(x) { return [x].map((e) => e ?? "m")[0] }

#### Mechanism

Traced 2026-11-25 by SOUND. The call's result is typed `"m"[]`: the `??`'s deferred result
(`HD_COAL`) resolves at the `null` pin to the default's own literal type (`coalJoinAtPin`), which a
direct return relies on (`function j(x) { return x ?? "m" }` delivers `j(null)` to a `"m" | "n"`
binding and runs). A one-literal list is stored as atom ids, but the callback's `e ?? "m"` writes
the default as a string, so the list's i32 slot receives a string. Widening the resolved type to
`string` (as the concrete module-level `??` types it) makes the witness run but refuses the `j(null)`
spelling, a runs → not-runs move, so it was not taken. By the coordinator's ruling the `.map`'s
element follows the callback's inferred signature instead, which types a literal default at its base
(`mapCoalLitElem`); the `??`'s own resolution, and so `j(null)`, is unchanged (D17565).
