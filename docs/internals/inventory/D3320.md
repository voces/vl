### D3320 — a wide integer delivered to a literal-union parameter keeps its `i64` where the union's rep is `i32`

**closed 2026-10-03 — the witness prints `3000000000` · was check-clean invalid wasm, clause 1 · the default spelling was a price of D3246 · found in the #3296 round-4 review · filed 2026-09-29 against #3296 head `fcb70b50e`, closed against master `878f6ebe8` · fixture `tests/cases/literal-unions/mixed-width-litunion-into-i64.vl`**

Repro:

    function f(x: 1 | 3000000000 = 3000000000): i64 { x }
    print(f())
    // vl check: rc 0.  vl run: invalid module at top level,
    // "type mismatch: expected i32, found i64".  Expected: 3000000000

The direct argument reaches the same defect, on master too:

    function f(x: 1 | 3000000000): i64 { x }
    print(f(3000000000))

#### Mechanism

Confirmed and closed with D3491, whose mechanism this is: the parameter lowered as `i32`
while the union has no one base scalar. The parameter now takes the `i32 | i64` box every other
position already used, and the `i64` delivery of `x` converts out of it at the member it holds.

The filed prediction: the literal union `1 | 3000000000` lowers to an `i32`
rep even though one of its members needs 64 bits, and a `3000000000` delivered to it is the
`i64` constant its width asks for. D3246 made a parameter default a delivery like an argument
(so `x: f32 = 0.1` holds the `f32` literal), which is what lets the default spelling past the
checker to the argument spelling's defect.

#### Ablation

| ingredient changed | outcome | needed? |
| --- | --- | --- |
| `x: i64` instead of the union | runs, `3000000000` | **yes** |
| `1 | 2` with a default of `2` | runs, `2` | **yes** (a member past `i32`) |
| the argument written instead of the default | still invalid | no |

#### Grading list

Both spellings above; the union with a member past `i32` returned (`function g(): 1 | 3000000000`)
and stored into a typed binding.
