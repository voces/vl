### D3148 — a hole-bound field function from an inline record literal, called as an operand, is refused for want of a signature

**loud emit reject · clause 2 · found by the #3280 review (`rv3280-17445/p3/h08.vl`, `h10.vl`) · the same on master `07d414042` · filed 2026-09-29 against master `07d414042`**

Repro:

    function F(z) {
      const g = z.f
      print(g() + 1.0)
    }
    F({ f: () => 2.5 })
    // vl check: rc 0.  vl build: emitProgram: a function-value call has no interned signature

Want:

    3.5

#### Mechanism

Not localised past the ablation. The operand position is scenery. What the refusal needs is
D3142's literal argument: the hole's binding is the literal's `{f: _}`, so the callee `g` has
no function type at the pin and no signature to key. With a named record the call is keyed by
the bound function type (D3117) and both `g() + 1.0` and `g() + "!"` run.

#### Ablation

| ingredient changed | outcome | needed? |
| --- | --- | --- |
| `const r = { f: () => 2.5 }` then `F(r)` | prints `3.5` | **yes** (the literal argument) |
| `g() + "!"` over `() => "ok"` | same refusal | no |
| `const v = g()` then `print(v + 1.0)`, named record | prints `3.5` | no |
| `function F<Z>(z: Z)`, named record | prints `3.5` | **yes** (the hole) |
