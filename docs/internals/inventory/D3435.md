### D3435 — a closure's `??` over an `f64 | null` field or cell a type-parameter value was written into returns `i32`

**closed 2026-10-05 by [D3692](D3692.md)'s close — the witness prints `2.5` · was check-clean invalid wasm, clause 1 · 8 cells of lane NW's `nw/g2` grid (`f64_{field,elem}_cap_*_gen`) · filed 2026-09-30 against master `b2a85883d`**

Repro:

    function g<T>(x: T) {
      const q: { s: f64 | null } = { s: null }
      q.s = x
      const f = () => q.s ?? 0.5
      print(f())
    }
    const v: f64 = 2.5
    g(v)
    // vl check: rc 0.  master: the emitted module failed to validate inside `g`: expected f64, found i32

Want:

    2.5

#### Mechanism

Confirmed by its close. The lambda's body lowers the `??` as an `f64`, while the lambda's
signature, built from its inferred return, kept the `i32` default: `criClassify`'s scalar rungs
skipped every returned `??`, the shape [D3692](D3692.md) admits when the `??` is not a union.
The list-cell spelling, a never-written `null` field (`0.5`) and `f() / 2` (`1.25`) run too.
