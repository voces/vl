### D3435 — a closure's `??` over an `f64 | null` field or cell a type-parameter value was written into returns `i32`

**check-clean invalid wasm · clause 1 · open · pre-existing, the same on master `b2a85883d` · 8 cells of lane NW's `nw/g2` grid (`f64_{field,elem}_cap_*_gen`) · filed 2026-09-30 against master `b2a85883d`**

Repro:

    function g<T>(x: T) {
      const q: { s: f64 | null } = { s: null }
      q.s = x
      const f = () => q.s ?? 0.5
      print(f())
    }
    const v: f64 = 2.5
    g(v)
    // vl check: rc 0.  vl run: the emitted module failed to validate inside `g`: expected f64, found i32

#### Mechanism

Not localised past the ablation. The lambda's body lowers the `??` as an `f64`, while the
lambda's signature, built from its inferred return, keeps the `i32` default: the return type is
recorded in the template over the type parameter's read and is not re-derived at the `f64` pin.

#### Ablation

| ingredient changed | outcome on master | needed? |
| --- | --- | --- |
| `function g(x: f64)` | prints `2.5` | **yes** (a type parameter) |
| a bare name `let s: f64 \| null` in place of the field | prints `2.5` | **yes** (a field or list cell) |
| a list cell `a[0]` of `(f64 \| null)[]` | invalid wasm | no |
| `i32 \| null` with `?? 0` | prints `5` | **yes** (a non-`i32` scalar) |
| `print(q.s ?? 0.5)` outside the closure | prints `2.5` | **yes** (the closure) |
