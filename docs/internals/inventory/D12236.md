### D12236 — a hole lambda pushed or written into an un-annotated parameter's list is refused at check with `<error>` types

**loud check reject · `a function of type `(<error>) => <error>` cannot be used as `(i32) => i32` here: calling it through that type needs its arguments or result converted, and a parameter or result type has no spelling to convert through` · clause 2 · CAPABILITY: the same push into the annotated list runs, and so does the lambda with its parameter annotated · found surveying emit refusals for L3 family (d) · filed 2026-10-24 against master `84b98d149`**

Repro:

    function addTo(xs) { xs.push((n) => n * 2) }
    const fs: ((n: i32) => i32)[] = []
    addTo(fs)
    print(fs[0](3))

#### Mechanism

`xs` takes `((n: i32) => i32)[]` from the call, but the lambda inside `addTo`'s body is checked
before that type reaches it, so its parameter `n` has no contextual type and checks as
`<error>`. The conversion rule for function values then refuses the `<error>`-typed function
at the list's element type. The program is well-typed, and the message prints the checker's
internal placeholder.

#### Ablation

| ingredient removed | outcome | needed? |
| --- | --- | --- |
| the hole parameter (`fs.push((n) => n * 2)` at top level) | runs, prints `6` | **yes** |
| `n` un-annotated (`(n: i32) => n * 2`) | runs, prints `6` | **yes** |
| the hole on `xs` (`xs: ((n: i32) => i32)[]`) | runs, prints `6` | **yes** |
| `push` (`xs[0] = (n) => n * 2`) | still refuses, same message | no |

#### Grading list

The element-write spelling; a `Map` value of function type written through a hole parameter.
