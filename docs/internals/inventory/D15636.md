### D15636 — [CLOSED 2026-11-10] `==` over a record that recurses through a nullable field exhausts the compiler's GC heap

    type Node = { v: i32, next: Node | null }
    const a: Node = { v: 1, next: null }
    print(a == a)
    // vl check: rc 0.  vl run: the compiler's wasm exhausts its GC heap while building

Want:

    true

#### Mechanism

A struct `==` is written inline, field by field, and a nested record field recurses one level
deeper under a null guard (`emitStructEqRec` → `emitStructEqField` → `emitStructEqNestedField`).
A row whose compare reads more than 32 leaf fields is written once as a helper `__eq_<row>__`
instead, and the nested compare calls it. `eqHelpPathsOf` counted a row reached again while it
was being counted as -1, "no compare", so a self-referential row got no helper and the inline
expansion never ended. It now saturates at 2^20, so every row on the cycle gets a helper and the
recursion is a wasm call. Recursion through a list already ran: the list core compares elements
through its own staged frame.

The helper compares a 10,000-deep chain and exhausts the call stack at 20,000; the list spelling,
which already ran, exhausts it at 10,000.
