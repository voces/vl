### D3872 — an annotated lambda inside a generic function, that calls a second generic whose body calls a method on its `T`, builds `h` with the method's receiver as an `i32`

**check-clean invalid wasm · found by the rv3461 review of #3454–#3461 (m/m4.vl; b/b11s.vl and b/b20.vl are the same family) · filed 2026-10-08 against master `862c99b79`**

Repro:

    type A = { x: i32 }
    function d(self: A): string { "RA" }
    function h<T>(x: T): string { x.d() }
    function fw<T>(xs: T[]): string { const k = (r: T): string => h(r); k(xs[0]) }
    const a: A = { x: 1 }
    print(fw([a]))
    // vl check: rc 0 (one unused-parameter warning, one hint).
    // vl run: rc 70, `the emitted module failed to validate inside `h$1`: ... type mismatch: expected (ref $0), found i32; $0 is `A``

Want:

    RA

#### Mechanism

`h` is instantiated for the lambda's parameter type, which inside `fw` is the still-open `T`, and
the method call `x.d()` in `h`'s body is built with a receiver that reaches the call as an `i32`
where the struct `A` is expected. Calling `h(xs[0])` directly in `fw`, with no lambda between,
runs, and so does the same lambda when `h` does not use `T` (an identity `h`, `m3.vl`), so what
fails is the body of `h` instantiated through a lambda's `T`, not the lambda or the call. Where in
`h$1` the receiver is lost was not printed, only that the validator names `h$1`.
