### D3705 — `p.o ?? p.a` over a nullable record field with a record-field default is invalid wasm

**check-clean invalid wasm · clause 1 · found by the #3387 review (`rv87`, `w1.vl`) · the same on master `0948a28e3` · filed 2026-10-05 against master `0948a28e3`**

Repro:

    type V = { x: f64, y: f64 }
    type P = { o: V | null, a: V }
    const p: P = { o: null, a: { x: 1.0, y: 2.0 } }
    function f() { p.o ?? p.a }
    print(f().y)
    // vl check: rc 0.  vl run: invalid module inside `f`, type mismatch: expected (ref $type), found (ref null $type)

Want:

    2

#### Mechanism

Not traced. A record field is stored as `(ref null $V)` whatever its declared nullability, so
both operands of the `??` are nullable refs, and the join's result is typed at the non-null `V`
the checker gives it while the value on the stack is the default's raw `(ref null $V)`: the
`??` lowering recovers the left operand past its null test but not a field-read default.
