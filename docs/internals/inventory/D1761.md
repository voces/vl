### D1761 — a capturing function nested TWO frames deep refuses `captured variable not found in enclosing frame`, at every pin kind

**loud emit reject · `vl check` rc 0, `vl run` rc 1, `emitProgram: captured variable not found in enclosing frame` · clause 2: the one-frame spelling runs at every pin kind · filed 2026-09-06 against [D1788](D1788.md)'s close · 44 cells of the 264-cell nested-capture matrix, and the only not-runs left in it · 0 corpus cells**

Repro:

    function o(n) {
      function k(x: i32) { return n }
      function j(y: i32) { return k(y) }
      return j(1)
    }
    print(o({ a: 9 }).a)
    print(o(2))
    // vl check: rc 0.  vl run: emit error,
    // emitProgram: captured variable not found in enclosing frame

Remove `j` and call `k` directly and it runs, printing `9` / `2`, at every pin-kind pair.

#### Mechanism

Predicted, not probed. `n` is free in `k`, which is free in `j`: the capture analysis records
`k`'s capture against the frame that DECLARES `k`, and `j` — a sibling lifted function, not
`k`'s parent — reaches `k` as a call without carrying `n`'s env row. The refusal is the
capture recorder's, not the per-pin clone's, which is why it fires identically at every pin
kind and at both outer-return faces.
