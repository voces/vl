### D1761 — a lifted function calling a SIBLING that captures cannot build its env, because `capRecord` drops the sibling's name and with it every free name behind it

**closed 2026-09-06 — the fold is the sibling direction of what `capScan`'s `FuncDecl` arm already does for depth · filed 2026-09-06 as [D1788](D1788.md)'s residue, closed against `9f22a51d9` · 44 cells of the 264-cell nested-capture matrix, and a plain non-generic program shows it · 0 corpus cells**

Repro:

    function o(n: i32) {
      function k(x: i32) { return n }
      function j(y: i32) { return k(y) }
      return j(1)
    }
    print(o(7))
    // vl check: rc 0.  vl run: rc 0, prints 7

Was: `emitProgram: captured variable not found in enclosing frame`.

#### Mechanism

**The row was first filed against the 264-cell matrix, and its generic framing was wrong.** The
witness above has no generic, no pin and no monomorphization in it, and reproduced identically —
so this is not the per-pin clone machinery, and not a frame-CHAIN walk.

Three runs settle what the ingredient is:

| spelling | before |
| --- | --- |
| `j` calls sibling `k`; `j` does not name `n` | **emit refusal** |
| `j` calls sibling `k` **and** names `n` itself | runs `14` |
| `k` declared INSIDE `j` (depth, not siblings) | runs `7` |
| two siblings, `j` does not call `k` | runs `8` |

So depth already works and the caller naming the captured variable already works. The hole is
exactly a lifted function CALLING A SIBLING that captures.

`capScan`'s `FuncDecl` arm folds a nested body's free names into the enclosing frame, which is
why depth works. An `Ident` naming a lifted function reaches `capRecord`, which drops it —
correctly, since the function itself is addressable directly — and the names BEHIND it go with
it. `j`'s capture set is then empty, and emitting `k(y)` inside `j` must build `k`'s env, which
needs an `n` that `j` never captured.

#### Close

At `capRecord`'s drop, a name that resolves to a NESTED function contributes that function's own
free names to the caller's set. The resolver is the outward frame walk `fnIndexOfInScopeSid`
takes, so a module-level callee resolves to -1 and folds in nothing. The fold is transitive: a
chain of three siblings reaches the capture through two hops.

**It must land with [D1788](D1788.md).** On master alone the fold moves 35 cells to `runs` and
turns **8 loud refusals into check-clean invalid wasm** — the generic face, where `j`'s env row
for the folded name is at the template's kind, which is D1788's mechanism one frame further in.
With D1788's reader family in place the same fold introduces **zero** silent cells and takes the
matrix to 264 of 264.

  language admits can revisit a frame. Without the guard the fold would not terminate the day
  either lands, which is why it is there rather than left to that day.
