### D5920 — a literal test over a non-nullable union of three or more members, one of them a literal, is check-clean invalid wasm

**closed 2026-10-17 by lane L3 · runs, prints `2.5` · was check-clean invalid wasm · clause 1 · introduced by D5714's checker narrowing, which records the literal's complement as `i32 | f64` while the emitter's `litElseNarrow` handled only a two-member union and left the box whole; the emitter now rules the literal's scalar out of the box (`litElseAtom`, `emit_classify.vl`) · pin: `tests/cases/match/litunion-nullable-literal-before-null.vl` (`three`) · found closing [D5890](D5890.md) · filed 2026-10-17 against master `f619864ee`**

Repro:

    function three(k: "a" | i32 | f64): f64 {
      if k == "a" { 1.0 }
      else if k is i32 { 2.0 }
      else { k + 0.5 }
    }
    print(three(2.0))
    // vl run: invalid module — type mismatch inside three

Want:

    2.5

#### Mechanism

`pushLitEqFactAt` narrows the else side of `k == "a"` to `i32 | f64` because `"a"` is the only
member that admits the literal. The emitter's else-complement for a literal `==`
(`litElseNarrow`) served only a two-member union or an all-literal box, so the box kept its
`string` atom, and the later `is i32` complement read an `f64` from a box the checker said had
no other member. On master before D5714 the chain was a loud check refusal.
