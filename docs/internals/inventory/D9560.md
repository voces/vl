### D9560 — arithmetic over an un-annotated parameter bound at a numeric literal union is typed as the union, so a non-member result is accepted where the union is declared

**check-clean silently wrong · clause 1 · the direct spelling `const q: N = a * 2` refuses at check (`cannot assign i32 to 'q' of type N`), and so does an annotated `x: N` · found closing [D9523](D9523.md) · present on master `95725e040` · filed 2026-10-22 against master `95725e040`**

Repro:

    type N = 1 | 2
    const a: N = 2
    function twice(x) { x * 2 }
    const q: N = twice(a)
    print(q)
    print(q == 2)
    // vl run: 4, then false

Want:

    cannot assign i32 to 'q' of type N

#### Mechanism

The body of an un-annotated parameter is checked with `x` a hole, and `checkBinNumTail`
(check_operators.vl) types `x * 2` as the hole's own type. At the pin the hole substitutes to
`N`, so `twice` returns `N` and `4` is stored in an `N`. The direct spelling types `a * 2` at the
union's softened base, `i32`. The pin needs to type an arithmetic result over a hole bound at a
literal union at the union's softened base; [D9523](D9523.md) is the mixed-width spelling of
the same root, where the base is `i64`.

#### Ablation

| ingredient removed | outcome | needed? |
| --- | --- | --- |
| the un-annotated parameter (`x: N`) | check refuses | **yes** |
| the union argument (`twice(1)`) | check refuses | **yes** |
| `function` (an un-annotated lambda `(x) => x * 2`) | prints `4` | no |
| the tail (`return x * 2`) | prints `4` | no |
| `*` (unary `-x`) | prints `-2` | no |
| the numeric union (`K = "x" \| "y"`, `x + "!"`) | check refuses | **yes** |
| the declared `N` (`const q = twice(a)`, `q == 4`) | check refuses `cannot compare N with 4` | **yes** |

A declared type parameter, `function twice<T>(x: T) { x * 2 }`, prints `4` too.
