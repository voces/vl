### D15372 — a list literal whose parts are built at a wider record and at their own, or hold a fresh record binding, is check-clean invalid wasm

**check-clean invalid wasm · `vl check` rc 0 · clause 1 · open, target a check reject naming both parts · found closing [D15371](D15371.md) · filed 2026-11-04 against master `98f227f3`**

Repro:

    type J = { f: i32 | null }
    function mk() { { f: 4 } }
    const wideJ: J = mk()
    const xs = [mk()]
    const os = [{ f: 1 }]
    const ws = [...xs, ...os]
    print(ws[1].f ?? 0)

Want:

    a check reject naming both parts

#### Mechanism

Not ablated past the table. Two halves with different answers.

* **A check refusal is owed (this repro).** `xs`'s records are built at `J` and `os`'s at their own
  `{f: i32}`; a list literal holding both shares records of two storages, which one list cannot
  hold. The checker accepts it and the list stamp (D15371) finds no build its parts agree on, so
  the module fails to validate.
* **A capability to build.** In `[...xs, r]`, `r` a fresh record `const`, nothing else holds `r`
  at its own storage, so `r` can be built at `J` where the list takes it, as D15237 builds one
  pushed into a built list.

| `const r = { f: 7 }; const ws = [...xs, r]` | invalid wasm (target: runs) |
| `[...xs, { f: 7 }]` (D15371) | runs |
