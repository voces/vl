### D17873 — four functions each binding a top-level generic through a type parameter lose the last call's print

**check-clean silently wrong · clause 1 · `vl run` rc 0 · filed 2026-11-28 against master `e5e714cdf` by COV-CLOS-3 (found pinning D17870)**

Repro:

    function same<T>(k: T): T { return k }
    function other<T>(k: T): T { return k }
    function m1<F>(a: F) {
      const b: F = other
      print(a(4))
      print(b("z"))
    }
    m1(same)
    function m2<F>(_a: F) {
      const b: F = other
      print(b("w"))
    }
    m2(same)
    function m3<F>(a: F) {
      const b: F = other
      print(a(6))
      print(b(7))
    }
    m3(same)
    function m4<F>(a: F) {
      const b = other
      print(a(8))
      print(b("v"))
    }
    m4(same)
    // PRINTS 4 z w 6 7 8

Want:

    4
    z
    w
    6
    7
    8
    v

#### Mechanism

Not traced. Each of `m1`, `m2`, `m3` beside `m4` runs and prints all of its lines, and so do the
triples `m1 m2 m4`, `m1 m3 m4` and `m2 m3 m4`; the four together drop `m4`'s `b("v")` with no
error. Each reads `other` at its own types, so the instances of `other` the four frames ask for
are shared across frames, and one of them stands for another.

#### Ablation

| ingredient removed | outcome | needed? |
| --- | --- | --- |
| any one of `m1`, `m2`, `m3` | runs, prints every line | **yes** |
| `m4` | runs | **yes** |

#### Grading list

`m1 m2 m3` with `m5<F, G>(a: F, a1: G) { const b: F = a1; print(a(9)); print(b("u")) }` drops `u`
the same way. `m2 m3 m4` with that `m5` refuses at emit, "call of a non-declaration" (D17323's
IR face).
