### D17873 — a list of un-annotated functions of two result types, bound from a pass-through call and handed on, is refused by the check's one-result rule

**loud check reject · clause 2 · `cannot store 'inc0' in an element of 'q': … every function a call through an element of 'q' may run must return one type` · filed 2026-11-28 against master `0684583dd` by START-2 (from D17569's ablation; coordinator ruling)**

Repro:

    function inc0(a) { return a + 1 }
    function half(a) { return a / 2.0 }
    function id(x) { return x }
    const q = id([half, inc0])
    const r = id(q)
    print(r[1](3))
    // vl check: rc 1, the one-result rule at `[half, inc0]`

Want:

    4

#### Mechanism

Not traced. The check's rule that every function a call through a binding's element may run
returns one type fires at `q`, though a set whose members' results differ is tagged and
dispatched with the join as result (D15791): `const r = id([half, inc0]); r[1](3)` and
`id(id([half, inc0]))[1](3)` run. The binding handed on to a second pass-through call is the
ingredient.
