### D15531 — a second generic written by a helper into an un-annotated map already holding one, read back at two types, reaches no instance

**loud emit reject · `vl check` rc 0 · `indexed-assignment target is not an array` · clause 2 · a helper's write of a declared generic into a parameter's map widens that map's set to two generics, which neither the tag rule's wider-set admission nor mono's map pin serves when the read is called at two types · blocker (3) of `closures/hole-fn-generic-map-stored-through-parameter.vl`'s map-pin hits (architecture-target-2026-10.md §3.4) · filed 2026-11-06 against master `9dfa5874`**

Repro:

    function id<T>(x: T): T { x }
    function id2<T>(x: T): T {
      print("id2")
      x
    }
    function bare(mm) { mm["k"] = id2 }
    const h = Map()
    h["k"] = id
    bare(h)
    const hr = h["k"]
    if hr != null {
      print(hr(7))
      print(hr("w"))
    }
    // vl check rc 0.  vl run: emit error: indexed-assignment target is not an array

Want:

    id2
    7
    id2
    w

#### Mechanism

`h` holds `{id}` from its own write and `{id, id2}` once `bare`'s write lands in it, so its value
is a set of two generics. D15492 admits a helper's write into a holder of a wider set, but only
where the set is decided for every holder the helper is handed. Here the read of the wider set is
called at two types, so mono cannot pin one generic per map and the tag rule leaves the set
untagged; the store `mm["k"] = id2` then reaches emit with no rep for its map.

#### Ablation

| spelling | outcome |
| --- | --- |
| the witness | loud emit reject |
| the read called at one type (`hr(7)` only) | runs, mono pins it |
| no `h["k"] = id` (the map holds `id2` alone) | runs |
| both writes direct, no helper | runs |
| the helper writes `id`, the generic the map already holds | runs |
| the helper writes through `mm.set("k", id2)` | loud emit reject, `callee is not a function name` |
