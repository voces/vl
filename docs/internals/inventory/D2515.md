### D2515 — the second binding of `for k, v in outer` over a map-valued map has no kind, so a check-clean walk refuses in emit

**loud emit reject · clause 2 · pre-existing on master `d29a9d220`, at string and i64 keys ·
found by #3164's review · filed 2026-09-25 against master `aed171ac5`**

Repro:

    const outer: {[string]: {[string]: i32}} = Map()
    const inner: {[string]: i32} = Map()
    inner["x"] = 1
    outer["a"] = inner
    for k, v in outer { print(v.length) }
    // vl check: rc 0.  vl build: emitProgram: unsupported for-in second binding

#### Mechanism

The refusal is the collect pass's `emitFail("emitProgram: unsupported for-in second binding")`,
reached when `forInPairElemKind` returns no kind. That function answers through
`mapValElemKind`, whose ladder names the scalar, string, closure, list, union-box, struct and
variant value kinds and no nested-map value; the missing arm is the predicted cause, not yet
confirmed by a probe. [D2516](D2516.md) is the `.values()` walk's face of it.

#### Ablation

| ingredient removed | outcome | needed? |
| --- | --- | --- |
| the value `{[string]: i32}` replaced by `string[]` | prints `1` | **yes** — a map value |
| `for k, v in outer` replaced by `for k in outer` reading `outer[k] ?? Map()` | prints `1` | **yes** — the pair binding |
| the keys `string` replaced by `i64` (both levels) | still refuses | no |
