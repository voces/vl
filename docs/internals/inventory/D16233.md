### D16233 — a list of records of un-annotated functions handed to a parameter the callee copies into a `const` and walks with `for` called each element's field through its first member's signature

**closed 2026-11-15 · runs, prints `5.5` · was a wasm trap (indirect call type mismatch) on a check-clean program · clause 1 · found closing [D16278](D16278.md) (its witness's `const v = a` copy, through a bound list) · filed 2026-11-15 against master `b75afba1f` · closed by `elabParamRowRoot` (emit_elab.vl): a `for` over an un-annotated alias of the parameter walks the parameter, as a field read through one already did (D15920) · fixture `closures/fn-field-list-param-copied-then-walked.vl`**

Repro:

    function inc0(a) { return a + 1 }
    function half(a) { return a / 2.0 }
    function mk() { return { a: [{ f: inc0 }, { f: half }] } }
    function take(a) {
      const v = a
      let acc = 0.0
      for e in v { acc = acc + e.f(3) }
      print(acc)
    }
    const L = mk().a
    take(L)
    // Was: vl check rc 0.  vl run: wasm trap: indirect call type mismatch

Want:

    5.5

#### Mechanism

The instance's mint fact follows a `for` element to the list the loop walks (`elabForInIterOf`,
D16279) and roots it at the parameter only when that list is the parameter itself. A `const` copy
of the parameter was a root of its own, so the calls through the elements got no fact and dispatched
at the first member's signature.
