### D15710 — a template's cloned `is` test carries one instance's concrete test type, so its arm is asked by spelling only

**runs today and must keep running · 43 cloned tests in 14 `tests/cases` programs · filed 2026-11-11 against master `e42ae722`**

Repro:

    function w<T>(t: T, b: boolean) {
      if b { return [t, t] }
      [1, 2, 3]
    }
    function len<T>(t: T, b: boolean) {
      const v = w(t, b)
      print(v.length)
    }
    len("s", true)
    len(true, false)
    // vl run: prints 2 then 3

Want:

    2
    3

#### Mechanism

`monoFoldLayoutAt`'s `IsExpr` arm substitutes the test's spelling (`T[]`) with the instance's
binding and hands it to `monoSubstIsExpr`, which banks `nameToTy` of the substituted spelling.
A type-first answer would substitute the template node's test type with the instance's exact
bindings (`substTyDeep(isPatTyIxOf(ix), monoFoldSubN, monoFoldSubT)`). But the template's
`is` node is one node shared by every instance, and its `isVarTyIxOf` / `isPatTyIxOf` already
hold one instance's concrete type. At `len<string>` the node says `boolean[]` while the
spelling substitutes to `string[]`. Only the spelling still carries the open test type, so the
arm's row cannot be asked by type until the checker records the open `is`-type per template
node, or each instance's test type is read per instance (`nodeTyAt(ix, fnIx)`). The refused
change is #7117's S4 and step 7 L6 item 5 (`2026-11-11-step7-union-reg-arm-tys.md`). Asking
by type first lost 12 runs.
