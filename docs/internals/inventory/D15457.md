### D15457 — a generic a maker returns, called at two types, is refused when a function only named, never called, returns it in a wider choice

**closed 2026-11-05, runs and prints `v 5` with the split plan on and off · was loud emit reject, `vl check` rc 0, `emitProgram: a generic function taken as a value reaches no call that fixes its type`, clause 2, with the split plan on and off · the wider set `{k, j}` `mkLoop`'s set waits on had no leaf, since nothing calls `mkPick`, and the `const` naming `mkPick` was refused by the scan · closed by taking, as the wider set's leaves, each member a function returns into it (`ftOtherTail` records the function, `ftPlan` reads it), and by admitting a named function read only as an un-annotated `const`'s initialiser whose every read is a call (`ftConstFnOnlyCalled`, check_fn_tag.vl) · fixtures `closures/maker-result-at-two-types-beside-named-uncalled-wider-maker.vl`, `closures/maker-result-at-two-types-beside-exported-uncalled-wider-maker.vl` · the alias called is [D15471](D15471.md) · D15070's witness with the wider maker named · found closing D15070 · filed 2026-11-05 against master `d7080b05`**

Repro:

    function k<T>(x: T): T { return x }
    function j<T>(x: T): T {
      print("j")
      return x
    }
    function mkLoop() { return k }
    function mkPick(f: boolean) {
      if f { return k }
      return j
    }
    function main() {
      const l = mkLoop()
      print(l("v"))
      print(mkLoop()(5))
    }
    const q = mkPick
    main()

Want:

    v
    5

#### Mechanism

`mkLoop`'s set `{k}` is decided with `mkPick`'s result set `{k, j}`, since `return k` in
`mkPick` is a leaf of that wider set (`ftOtherTail`, check_fn_tag.vl). Nothing calls `mkPick`, so
`{k, j}` is never decided and `{k}` waits on it. D15070 closed the spelling where nothing names
`mkPick` at all (`ftFnNeverNamed`). Here `const q = mkPick` names it, so the rule cannot read it as
never returning.
