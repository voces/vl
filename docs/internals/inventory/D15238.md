### D15238 — a fresh record binding assigned into a binding held at a wider record is refused as a type error

**closed 2026-11-04 · runs, prints `6` · was a loud check reject, clause 2 · found closing [D15237](D15237.md), its assignment twin · filed 2026-11-04 against master `549ac7fc` · closed by building the fresh `const` where it is assigned into a held binding by stamping its literal there (`recHeldAsgStamp`: `adoptLitAt` and the own-storage refusal D15230 and D15237 use), from the pass-end adoption for a built read and from the store column for a built call (`storeAsgLitsBuild`, since folded into `recLitPlaceBuiltTy` by [D15282](D15282.md)); its type stays its own · fixtures `tests/cases/soundness/record-binding-assigned-into-held-binding-runs.vl` and `-reject.vl` · open neighbours [D15281](D15281.md), [D15282](D15282.md)**

Repro:

    type J = { f: i32 | null }
    function mk() { { f: 4 } }
    const wideJ: J = mk()
    const xs = [mk()]
    let y = xs[0]
    const r = { f: 6 }
    y = r
    print(y.f)

Want:

    6

#### Mechanism

`y` is typed `{f: i32}` and held at `J`, the build of `xs[0]`. D15237's pass-end adoption builds
`r` at `J` where a read of it is assigned into `y`, which retypes `r`, and the assignment's type
check then refuses `J` into `{f: i32}`. Before D15237 the same program was check-clean invalid
wasm. A literal assigned there is built at `J` by a rep stamp and runs (D15188).
