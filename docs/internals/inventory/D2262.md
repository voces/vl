#### Mechanism

`checkRetStmtNode` read `T.curRet` to decide what a `return`'s value must match, but never
asked whether one existed: `T.curRet` is `-1` only at `initChecker`'s reset and is otherwise
always a real return type or the `-2` inferring sentinel, saved and restored around every
`FuncDecl` body (named function, nested function, method, getter, or lambda) by
`checkFuncDeclNode`. A `return` reached through `checkProgram`'s top-level statement pass
without ever entering a `FuncDecl` body — directly, or through a module-scope `if`/`while`/
`for`/`match` — saw the untouched `-1` and every branch of the old code gated on `want >= 0`,
so it fell through as accepted. The fix adds one check at the top of `checkRetStmtNode`: `want
== -1` refuses, both for a bare `return` and one carrying a value.

#### Ablation

| ingredient removed | outcome | needed? |
| --- | --- | --- |

| a value on the `return` (`return 1`) | still refused | no |
| every enclosing function, lambda, method and getter body | still refused | **yes** |
