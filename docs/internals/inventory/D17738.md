### D17738 — an annotated null-field record's own struct row is minted after the literal it holds is built, so the literal stays at a union arm's variant row

**loud emit reject · filed 2026-11-27 against master `92272509` · owner COV-IS**

Repro:

    type Circle = { r: i32 | null }
    type Sq = { s: i32 }
    type Shape = Circle | Sq
    function f() {
      const xs: {r: null}[] = [{ r: null }]
      print(xs[0].r == null)
    }
    f()
    // vl check: rc 0.  vl run: emit error, "the compiler cannot yet lower this statement (convert record -> record)"

Want:

    true

#### Mechanism

The literal `{ r: null }` is adopted at the union arm `Circle` it is narrower than, and is built at
the destination's own row only once that row exists (`freshLitAt`/`freshRowOf`, D17728). The
annotation `{r: null}` mints its struct row only when a slot first asks for it, after the literal
is delivered, so `structIndexOfTy({r: null})` is still -1 there and the literal stays at Circle's
variant row, which no conversion takes to the row-less record. The same holds for an annotated
`let q: {r: null}` (`convert record -> record` in a function, `global initializer coercion` at top
level). The close registers every declared or annotated record's struct row before any slot is
minted (coordinator ruling 2026-11-27), so a value's layout is a property of the program, not of
mint order.

#### Ablation

| ingredient removed | outcome | needed? |
| --- | --- | --- |
| `type Shape = Circle \| Sq` (the union over the twin arm) | runs, prints `true` | **yes** |
| the null field (`{ r: 3 }` at `{r: i32 \| null}[]`) | runs | **yes** |
| the enclosing function (top level) | `global initializer coercion` | no |
| a list (`let q: {r: null} = { r: null }` then a reassignment) | `convert record -> record` | no |
