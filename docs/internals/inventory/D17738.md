### D17738 — a literal delivered at an annotation of its own record type was re-adopted at a union arm it is narrower than

**runs, prints `true` — CLOSED 2026-11-27: `recArmLitsAdopt` skips a literal whose context type is its own record type; pinned by `tests/cases/records/annotated-own-shape-literal-beside-narrower-arm.vl`. Was: loud emit reject · filed against master `92272509` · owner COV-IS**

Repro:

    type Circle = { r: i32 | null }
    type Sq = { s: i32 }
    type Shape = Circle | Sq
    function f() {
      const xs: {r: null}[] = [{ r: null }]
      print(xs[0].r == null)
    }
    f()
    // vl check: rc 0.  vl run: emit error, "the compiler cannot yet lower this statement (convert record -> record)"

Want:

    true

#### Mechanism

The annotation `{r: null}` has its own struct row and ref-list slot before the literal is built
(measured: rows `{r:null},#ref1,#ref2`, slots `Circle,{r:null}`), so mint order was not the cause.
The literal's delivery at its own type stamps nothing (`litAtDstStorage` declines `own == dstTy`),
so `recArmLitsAdopt` counted it as unadopted and stamped it with `recNarrowRecordOf`'s arm, Circle.
The list's build slot and the let's cell kind followed that stamp to Circle's row, which no
conversion takes to `{r: null}`'s. The close is at the stamp: a literal whose context type is a
record of its own type has been delivered, and no arm adopts it (coordinator ruling 2026-11-27).

| ingredient removed | outcome | needed? |
| --- | --- | --- |

| a list (`let q: {r: null} = { r: null }` then a reassignment) | `convert record -> record` | no |
