### D15810 — an instance-only `??` union's box picks its arm by its own spelling's member order, not the registered row's sequence

**runs today and must keep running · refutation pin for naming `monoPinUnionNameOfTy` by the naming rule · filed 2026-11-12 against master `7ba5162e`**

Repro:

    type J = { f: i32 | null }
    const m = Map()
    m.set("a", { f: 4 })
    function pick(d) { (m.get("z") ?? d).f }
    const j: J = { f: 2 }
    print(pick(j) ?? 0)

Want:

    2

#### Mechanism

Under the refused change, this program builds an invalid module. The change: emit_mono's
`monoPinUnionNameOfTy` returns `monoPinUnionName(monoPinSpellShaped(st))` in place of
`monoPinUnionName(tyToEmitName(st))`.

At the instance `pick` at `J`, the `??` is a union only at the instance (D15713, #7278's row).
Its member records are two distinct heap rows: `#anon1`, the map's `{f: i32}`, and `J`, which
is `{f: i32 | null}`.

- The render names the row `{f:i32}|{f:i32|null}`.
- The naming rule names it `#anon1|J`, members sorted.

The registry's canonical key sorts members (`utkMemberText`), so both spellings key one row. But
the join's box then fails validation: "expected (ref null $5) `#anon1`, found (ref $1) `J`". So
some producer of that box takes its arm by the member order of its own spelling, not by the
row's registered sequence. That breaks ARCHITECTURE §3.4's positional tags. The producer is not
yet located.

The fix that closes the pin is the exact-type tag key (lane w324): a box's arm is the registered
row's member that is `tySame` with the value's type. Once that lands, `monoPinUnionNameOfTy` can
take the rule's spelling and its render is deleted
(`docs/internals/refactor-notes/2026-11-12-step7-l2-mono-anon-shapes-by-fields.md`).

#### Progress

The producer is located and fixed. Under the rule, mono registers the `??` union under
`#anon1|J`. `registerInlineUnionGo` asks `isVariantBoxUnionOfTy`, which aligns the atoms with
the type's members correctly (`#anon1` is `{f:i32}`). But `isVariantBoxUnionAtoms` counted a
struct only by its spelling (`isStructAtom`: a declared struct or an inline `{…}` span). So
`#anon1` read as no boxable member, no row was minted, and the join's lookup by type found
nothing. A member whose aligned type is a record now counts as a struct. With the rule
spelling, the repro prints `2`. The floor itself is w317's to delete.
