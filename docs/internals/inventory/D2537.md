### D2537 — `s += f(v)` with `v` narrowed from a nullable record, inside a loop, is invalid wasm; `s = s + f(v)` runs

**check-clean invalid wasm · clause 1 · found by #3168's second review (`rv3168r2-probe/m1c.vl`) · filed 2026-09-25 against master `15be0d1b8`**

Repro:

    type Tex = { w: i32 }
    function total(xs: (Tex | null)[], f: (Tex) => i32): i32 {
      let s = 0
      let i = 0
      while i < xs.length {
        const v = xs[i]
        if v != null { s += f(v) }
        i += 1
      }
      return s
    }
    const s: (Tex | null)[] = [null, { w: 4 }, { w: 1 }]
    print(total(s, (x: Tex) => x.w))

#### Mechanism

The compound assignment's right operand is a closure call whose argument is `v`, narrowed
from `Tex | null` to `Tex`. The `+=` lowering emits the call argument without the non-null
recovery the plain `s = s + f(v)` spelling applies, so `total` fails validation. The generic
twin (`total<V>(xs: (V | null)[], f: (V) => i32)`, and `std:idtable`'s `IdTable<V>` walked with
`ids()`) reaches the same site. Not yet ablated past the rows below.
