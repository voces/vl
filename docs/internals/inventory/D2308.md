### D2308 — the rep fuzzer has no `u8` leaf, so `rep-fuzz-check.sh` cannot see a packed-byte-list rep

**loud check reject · a gap in the instrument, not in the compiler: `scripts/fuzzgen.vl` generates the leaves `i32 · i64 · f64 · string · f32 · boolean · literal-union atom` and no `u8`, so no fuzzed program holds a `u8[]` or a `u8[] | null` and the mandatory rep gate is blind to the u8 rows D2295 added · the witness pins the storage rule a `u8` leaf has to respect · found in review of #3104 · filed 2026-09-24 against master `e29ffbab7`**

Repro:

    const v: u8 = 7
    print(v)
    // vl check: rc 1, `u8` is a storage type, not a value type.

#### Mechanism

`fuzzgen.vl`'s leaf alphabet (`leaf: 0 i32 · 1 i64 · 2 f64 · 3 string · 4 f32 · 5 boolean · 6
literal-union`) has no `u8`. A `u8` leaf cannot be added as an eighth scalar: `u8` is a storage
type, legal only as an array element, so the witness above is the design refusing a bare `u8`
value. The generator needs `u8[]` as a CONTAINER leaf whose element reads back as `i32`, and whose
printed form wraps a computed value to its low 8 bits. Until it has one, the rep-fuzz baseline
says nothing about the packed byte list or its nullable niche.

#### Grading list

`grep -c u8 scripts/fuzzgen.vl` is non-zero, and a regenerated rep-fuzz baseline holds cells
whose container is `u8[]`, `u8[] | null` and `(u8[] | null)[]`, in record fields and map values.
