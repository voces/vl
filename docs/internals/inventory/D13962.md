### D13962 — a generic body's un-annotated record binding has no argument type when passed to another generic

**closed 2026-10-26 — now prints `7` · was loud emit reject, clause 2 · the binding's per-instance row is interned at the mint · filed against master `f1f48f2e2` · pin: `tests/cases/generics/record-binding-per-instance-into-generic.vl`**

Repro:

    function readX(o) { o.x }
    function viaBinding<T>(v: T) {
      const o = {x: v}
      readX(o)
    }
    print(viaBinding(7))
    // vl check: rc 0.  vl run: emitProgram: monomorphize: unsupported argument type for `o` in a call to `readX`

Want:

    7

#### Mechanism

Inside the instance `viaBinding<i32>`, the binding `o` holds a record literal whose field
type is the type parameter. When the monomorphizer types the argument `o` for the call to
`readX`, it finds no concrete type, so it refuses. The same literal passed inline
(`readX({x: v})`) runs. So does the same binding annotated `{x: T}`. The binding's own type
is not elaborated at the instance's pin where the call argument reads it.

#### Ablation

| ingredient removed | outcome | needed? |
| --- | --- | --- |
| the binding: `readX({x: v})` inline | runs | **yes** |
| the type parameter: `v: i32` | runs | **yes** |
| annotating the binding `const o: {x: T}` | runs | **yes** (missing annotation) |
| `readX` annotated `<U>(o: {x: U}): U` | still refuses | no |
| a second instance (`viaBinding(2.5)`) | still refuses | no |
