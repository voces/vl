### D16563 — a destination does not bind a type parameter its call leaves open when the function type naming it also names one another argument binds

**closed 2026-11-15 — the filed program RUNS and prints `2.5` · was loads then traps, clause 1 (`indirect call type mismatch`), the same on master `c8f0324da` · fixed in `dstOnlyOpenFnArgsName` (`check_assignable.vl`): another argument's binding fixes an open-function slot's result, not its parameter positions · `gfv-bind1-second-open.matrix.vl`: 29 of the 30 traps run, and the one left (`return_inferred`, annotated) is [D16562](D16562.md)'s inferred return · ruling grid 23 of 23 · the open-function face [D16410](D16410.md)'s rule left out · filed 2026-11-15 against master `c8f0324da`**

Repro:

    function first<A, B>(a: A, b: B): A { return a }
    function bind1<A, B>(f: (a: A, b: B) => A, a: A): (b: B) => A { return (b: B) => f(a, b) }
    const v: (b: string) => f64 = bind1(first, 2.5)
    print(v("s"))
    // vl check: rc 0.  vl run: prints 2.5 (was: wasm trap, indirect call type mismatch)

Want:

    2.5

#### Mechanism

`B` is bound by no argument: `first` is generic, so the parameter `f` hands no type for it. The owner
ruling (D16410) has the destination bind such a parameter, and `dstBindOpenFnTyParams` does so only
where `dstOnlyOpenFnArgsName` holds. That predicate also asks that no other argument bind a type
parameter of the function type naming `B`, and `f: (a: A, b: B) => A` names `A`, which `a: 2.5`
binds. So `B` stays unbound, the closure is built at the `i32` default, and the call at `string`
traps. The `i32` destination runs because it agrees with the default.

#### Closed

The predicate's refusal holds where `name` is in the slot's result: there an argument that binds the
slot's other type parameter fixes the open function's instance, and so what it returns (D16410's
`app(hinc2, 1)`). A type parameter only in a parameter position of the slot is one the open function
takes as given, so the destination binds it.
