### D16703 — an `f64` tested against an integer literal is narrowed to that literal, so a float read in the tested branch builds a module that fails to validate

**closed 2026-11-16 · runs, prints `2.5` · was check-clean invalid wasm, `vl check` rc 0, `vl run` invalid module, `type mismatch: expected i32, found f64` · clause 1 · fixed in check_narrow_flow.vl: a float operand tested against integer literals narrows to its members that can hold them by value (`floatIntLitHolders`), keeping the float, where before it narrowed to the literal · pin: `tests/cases/narrowing/float-is-integer-literal-by-value.vl` · found closing [D3689](D3689.md) · filed 2026-11-16 against master `2a0b71c1a`**

Repro:

    const e: f64 = 2.0
    if e is 2 { print(e + 0.5) }
    // was: vl check rc 0, vl run invalid module

Want:

    2.5

#### Mechanism

The tested branch took the literal set as the operand's narrowed type, as it does for an integer
operand, so `e` read as the literal `2`, an `i32`, while its slot held an `f64`. Under the ruling
the test compares by value and the operand keeps its float type.
