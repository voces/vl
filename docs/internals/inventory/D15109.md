### D15109 — a composite parameter in a type-testing generic keys an instance per argument value only when its annotation spells a map or record member first

**runs today and must keep running · structural, a cost not a miscompile: `monoAnonPinDiscrim` adds the argument's exact type to the key only when the pin's spelling starts with `{` or `#`, so `(u: T | null)` at `T = Set<i32>` builds one instance for a `Set` argument and another for `null`, while `(u: null | T)` builds one for both and prints the same · found grading D15107 class B · filed 2026-11-03 against master `c2dcb32ac`**

Repro:

    function isSet<T>(u: null | T) { u is Set<i32> }
    function kind<T>(u: null | T) {
      const v = u
      match v {
        null => "null"
        _ => if v is Set<i32> { "set" } else { "map" }
      }
    }
    const s: Set<i32> = Set()
    s.add(3)
    const b: {[i32]: boolean} = Map()
    print(isSet<{[i32]: boolean}>(b))
    print(isSet<Set<i32>>(s))
    print(kind<{[i32]: boolean}>(b))
    print(kind<Set<i32>>(s))
    print(kind<Set<i32>>(null))

Want:

    false
    true
    map
    set
    null

#### Mechanism

`monoPinTyParamComposite` pins a composite parameter at its substituted annotation and records the argument's exact type beside it. `monoKeyPinSeg` then keys the pin by `monoAnonPinDiscrim`, which appends `=` and that exact type only when the spelling's first character is `{` or `#`. Spelled `T | null`, the pin reads `{[i32]:boolean}|null` and splits `kind<Set<i32>>(s)` from `kind<Set<i32>>(null)`. Spelled `null | T`, it reads `null|{[i32]:boolean}` and does not. Both spellings run correctly, so the split at the first spelling is an instance the program does not need.
