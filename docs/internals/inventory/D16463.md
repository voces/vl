### D16463 — a record literal written into a field, element or name yields the literal's shape, not the record it is built at

**closed 2026-11-15 · runs, prints `3` and `7` · was check-clean invalid wasm, clause 1, wherever another literal minted the shape's `#anon` row, and a loud check reject, clause 2 (`cannot assign {v: i32, left: null} to null`), on a write through the yielded value · fixed in `checkAssignStore` (`check_operators.vl`, `asgLitIsPlaceRecord`) and `spillWrite` (`emit_rewrite.vl`) · fixture `tests/cases/assignment/record-literal-write-yields-place-record.vl` · found grading D16462's close · filed 2026-11-15 against master `41739762`**

Repro:

    type Node = { v: i32, left: Node | null }
    function insert(n: Node, v: i32) {
      n.left = { v: v, left: null }
    }
    const fresh: Node = { v: 1, left: null }
    print(insert(fresh, 3).v)
    const q = { v: 7, left: null }
    print(q.v)

Want:

    3
    7

#### Mechanism

A record literal written into a place that stores one record is built at that record, and the
write yields the stored value (D14890). The checker typed the write at the literal's own shape
`{v: i32, left: null}`. With no record of that shape the emitter fell back to `Node`, the row
the value has; once another literal minted `#anon1`, the function's result was built at that
row while the body delivered a `Node`. The yielded type also refused a later write through the
value (`got.left = …`), which the stored `Node` allows. A record literal written into a place
whose non-null part is one other record now yields that record, and the D2170 spill reads its
temporary at it.
