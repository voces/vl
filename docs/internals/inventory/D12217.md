### D12217 — a lambda written into a list element or record field holding a generic, then called at a type the lambda refuses, passes the checker

**now a loud check reject · was a loud emit reject after `vl check` rc 0 · clause 2 · DESIGN: the same write to a `let` is refused at check (`a function written to this binding takes `string` there`) · closed 2026-10-24 by lane L3 (d): the hole-slot judge (D10152) judges a written lambda's annotated parameters too · residue still at the emit floor: [D12238](D12238.md); write paths the judge does not follow, which trap: [D12239](D12239.md) · pins: `tests/cases/closures/error-generic-list-written-hole-lambda-called-misfit.vl`, `error-generic-field-written-hole-lambda-called-misfit.vl`, `error-generic-list-written-hole-lambda-called-through-param.vl`, `generic-list-written-hole-lambda-called-where-it-fits.vl`, `error-generic-list-written-annotated-lambda-called-misfit.vl`, `error-generic-list-literal-annotated-lambda-beside-generic.vl` · found surveying emit refusals for L3 family (d) · filed 2026-10-24 against master `b8e223f93`**

Repro:

    function pick<A, B>(a: A, b: B): A { a }
    const fs = [pick]
    fs[0] = (x, y: string) => x
    print(fs[0](1, 2))

#### Mechanism

The call passes `2` where the written lambda takes `string`, so the program is ill-typed.
The hole-slot judge (`holeSlotFixedJudge`, check_relate_core.vl) already refused a FIXED
function written beside a generic whose signature differs from the generic's instance at the
call's argument types (D10152), and it follows the slot through aliases, `for`-`in`, `map`,
un-annotated parameters, closures and nested fields. A lambda with an un-annotated parameter
has no fixed signature, so the judge skipped it. It now reads the lambda's annotated
parameters (`holeLamMisfitAt`): each must be the instance's parameter type at that position,
the same rule D10152 applies to a fixed function. `monoPinWrittenLam` (emit_mono.vl) stays as
the floor for a call inside a generic body, which the judge does not see ([D12238](D12238.md)).

Several spellings that the emitter used to build wrong are refused now: `r.f = …` then
`r.f(1, 2)` trapped, and so did a named hole lambda `const l = (x, y: string) => x; fs[0] = l`.
A lambda whose annotated parameter is wider than the call's argument (`y: f64` called with
`2`) was an emit reject and is a check reject now, as the fixed function `(x: i32, y: f64)`
already was.

A lambda that annotates every parameter is now judged as the named function it could have
been (`holeFixedFnTyOf`), except an adapter the checker put in place of a delivered generic
(`fvaDone`). Writing `(x: i32, y: string) => x` to `fs[0]` or `r.f` and calling at `(1, 2)`
trapped after load and is a check reject now. One program that ran moves: the lambda inside the
list literal, `const fs = [pick, (x: i32, y: string) => x]; fs[0](1, 2)`, ran because the call
reaches `pick`. Its direct spellings were already refused at check by D10120: the named
function `function g(x: i32, y: string): i32 { x }; const fs = [pick, g]`, and the lambda
bound first, `const g = (x: i32, y: string) => x; const fs = [pick, g]`.
