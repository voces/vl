### D2704 — an un-annotated list literal passed to a function value takes its element rep from a callee found by NAME

**closed 2026-09-26 — the repro RUNS and prints `1` · was check-clean invalid wasm · the four #3196 review witnesses (alias chain, field callee, shadowing parameter, inner rebinding) and 7 of the lane's 12-cell grid · filed 2026-09-26 against master `90b63b840`**

Repro:

    type Circle = { r: i32 }
    type Sq = { s: i32 }
    type Shape = Circle | Sq
    function sum(xs: Shape[]): i32 { xs.length }
    function f() {
      const a = sum
      const b = a
      const out = [{ r: 3 }]
      print(b(out))
    }
    f()

#### Mechanism

An un-annotated `[{ r: 3 }]` builds a `Circle` list unless a declared destination asks for the
`Shape` box. Three places decided that destination by resolving a NAME rather than reading
what the checker resolved: the destination scan's call form followed a callee only when it was
a module function, a local, a parameter or a one-step alias of a module function, so an alias
of an alias and a field (`o.f(out)`) answered nothing; the
destination PIN (`dstPinCallArgs`) looked a callee up with `fnIndexOf` and so pinned `out` to a
module function its own parameter shadowed; and the scan walked into an inner block that
rebinds the list's own name, reading the inner list's call as the outer list's destination.
Closed by asking the callee's checked function type first (`fnTyParamKindListSlot` of
`nodeTyIxOf(callFn)`), gating the pin on `nameFreeToModule`, and stopping a block walk at a
`let` that rebinds the name (`dsBlockWalk`). The checked type does NOT cover an un-annotated
lambda parameter used as the callee (`const ap = (g) => g(out)`): the checker leaves it an open
hole, so no function type answers. That spelling stayed invalid wasm and is
[D2748](D2748.md).
