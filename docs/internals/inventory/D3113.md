### D3113 — a generic passed as a function value to another generic's function parameter is refused at emit

**closed · the argument is adapted at the parameter's type once `U` is bound, so `show` is called directly at `i32` ([D3112](D3112.md)) · fixture `tests/cases/generics/generic-fn-value-nullable-and-map-slot.vl` · was loud emit reject · found by #3275's review · filed 2026-09-28 against master `d408f2da4`, closed 2026-09-30 against master `3291e99e1`**

Repro:

    function app<U>(f: (U) => void, u: U) { f(u) }
    function show<T>(x: T) { print(x) }
    app(show, 3)
    // vl check: rc 0.  vl run: emitProgram: monomorphize: unsupported argument type for `f` in a call to `app`

Want:

    3

#### Mechanism

Not localised past the ablation. The checker binds `U := i32` from `3` and instantiates `show` at
`(i32) => void`; the monomorphizer has no argument spelling for a generic function value at a
parameter whose type names the callee's own type parameter, so the call is refused. Delivered to a
concrete `(i32) => void` parameter the same value runs.

#### Ablation

| ingredient changed | outcome | needed? |
| --- | --- | --- |
| `function app(f: (i32) => void, u: i32)`, not generic | prints `3` | **yes** (a generic callee) |
| `app(show, "z")` as well | emit reject | no |

#### Grading list

`app(show, 3)`, `app(show, "z")`, and a record `R` pin where `show` prints a field.
