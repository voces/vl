### D1171 — an inline `{}` in a NULLABLE position has no interned shape, while the alias spelling of the same type runs

**closed — `internInlineShapeTy` refused every zero-field split as malformed, so no struct row was minted for `{}` at all · was a loud emit reject at check rc 0, clause 2 (`emitProgram: ref valtype with no interned shape`) · ZERO corpus cells · found 2026-09-02 beside [D1081](D1081.md)**

Repro (runs, prints `11`):

    type U = {} | null
    function f(u: U): i32 {
      if u != null { return 11 }
      return -1
    }
    const e: U = {}
    print(f(e))

#### Mechanism

PRINT THE REP OF BOTH SPELLINGS, and the two disagree about whether the shape EXISTS rather
than about its layout. An instrumented `fbValtype` guard reports the inline spelling arriving
as `kind=nulstruct idx=-1` with **`sHeapIdx.length=0`** — not a row resolved to the wrong
index, but a module with no struct rows at all. The alias spelling (`type E = {}`) mints its
row through the declared-shape collector and runs.

`internInlineShapeTy` guarded `if !ok || names.length == 0 { return -1 }`. `nameIsShapeSpanEnds`
already admits `{}`, `shapeInnerFieldSplit` of its empty body yields no fields, and the
zero-field return then treated a REAL zero-field layout as a malformed split. The guard now
declines only a NON-EMPTY body that split into no fields; an empty one mints the row, and
`annShapeIndexOf` dedups it onto the alias row when both spellings appear.
