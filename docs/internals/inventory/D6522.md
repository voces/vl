### D6522 — [CLOSED 2026-10-18] a hole lambda called at one type and returned into a binding annotated with another calls the first type's body

**closed 2026-10-18 by lane L1 · runs, prints `s 4` · was loads then traps · clause 1 · found by the `hole-lambda-called-first-at-another-type` matrix (`return_inferred`, annotated face) · filed 2026-10-18 against master `d9c8431e5` · a call of an un-annotated function delivered at a function type delivers each of the function's returns at that type, as an annotated result would, when one of them reaches a hole lambda (directly or through further calls, recursion included); a second delivery type is refused loudly, since the one value returned has one signature · the `hole-lambda-called-first-at-another-type` matrix 41 → 42 of 46 runs · pins: `tests/cases/closures/hole-lambda-returned-into-binding-of-another-type.vl`, `tests/cases/closures/error-hole-lambda-returned-into-bindings-of-two-types.vl`**

Repro:

    const h = (u) => { return u }
    print(h("s"))
    function deliver() { return h }
    const v: (n: i32) => i32 = deliver()
    print(v(3) + 1)
    // vl check: rc 0.  vl run: prints s, then wasm trap: indirect call type mismatch at `v(3)`

Want:

    s
    4

#### Mechanism

From the ablation only. `h` is built at `string` for its direct call. Returned through
`deliver`, it reaches `v` with that one instance, and the annotation on `v` asks for an `i32`
signature that the delivery never builds.
