### D3536 — a number literal beside a runtime number adapts by its value in `??` and by its type in the `if` that `??` spells, so the two spellings print different values

**runs today and must keep running until ruled — prints `2.5`, `2`, `1285714285.7142856`, `1285714285` · a language-semantics question beside [D2774](D2774.md) · 54 `??` cells, 76 `??`-chain cells and 18 list cells of the NJ2 twin grid disagree with their `if` or `match` twin · filed 2026-10-03 against master `f6e17953b`, the same with the NJ2 lane applied**

Repro:

    function f(q: f32 | null, r: f64 | null) {
      print((q ?? 5) / 2)
      print((if q != null { q } else { 5 }) / 2)
      print((r ?? 9000000000) / 7)
      print((if r != null { r } else { 9000000000 }) / 7)
    }
    f(null, null)

#### Mechanism

`??` asks whether the default literal fits the left type by its value (`assignableExpr`): `5` is
an exact `f32`, `9000000000` an exact `f64`, so `q ?? 5` is `f32` and `r ?? 9000000000` is `f64`.
The `if` joins the literal arm by its type (`joinArmLit` → `joinTys`): `i32` does not widen into
`f32` exactly and `i64` does not widen into `f64`, so the arm stays its own member and the `if`
is `f32 | i32` or `f64 | i64`. Both spellings keep the literal's value; they disagree on its type,
and so on `/`, `is` and every delivery. A left-grouped `??` chain with a literal tail
(`q ?? r ?? 2.5`) shows the same split, and a right-grouped one (`q ?? (r ?? 5)`) adapts its
literal to the inner link alone where the flat `else if` chain adapts it to the whole chain.
Unchanged by the NJ2 lane, which joins only runtime operands apart.

**Question for the owner.** Should a number literal beside a runtime number adapt by value in
every join (`if`/`match` arms, list elements, return sets), so `if q != null { q } else { 5 }` is
`f32` like `q ?? 5`? Recommendation: yes — "a literal adapts" is the numeric-join ruling's own
first rule, and by value is the reading under which `??` and its `if` agree. It changes the
printed value of the `if` spelling where the literal's type is not a member, which is why it is
filed rather than done; D2774 asks the f32 half of the same question for float literals.
