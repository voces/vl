### D3607 — a direct call above a later local of a builtin's or module function's name called the local

**closed 2026-10-04 · was a loud emit reject (`a function-value call has no interned signature`) of a check-clean program, and check-clean invalid wasm for an integer builtin or a module function · filed and closed by lane SC against master `c473889d1` · fixture `tests/cases/scope/builtin-call-above-later-local-closure.vl`**

Repro:

    function f() { print(sqrt(16.0)); const sqrt = (x: f64) => x; print(sqrt(16.0)) }
    f()
    // master: vl check rc 0, vl run "a function-value call has no interned signature" at 1:10

Want:

    4
    16

#### Mechanism

The checker resolves a call above a local to whatever the name meant before the local: the
builtin, or the module function. The emitter asked whether the name was bound anywhere in the
function, in three places. In `emitCallCore` (`compiler/wasmEmit.vl`), `exprIsClosure` found the
later closure through the flat local lookup, so `sqrt(16.0)` above it was lowered as a call
through a closure that had no signature yet. For a module function `k`, `identIsBoundClosure`
did the same, and the call read a local that was not yet set (invalid module). In
`callIsIntrMinMax` (`compiler/emit_classify.vl`), `identNameIsUserBound` said a later `min`/`abs`
was a binding, so the integer lowering was skipped and the float one ran on `i32` operands
(invalid module), even with a plain value local (`const min = 7`). A new
`identNameIsBoundAt` answers from the arena, at the call's own node: a parameter, a capture, a
body `let` whose scope covers the call, or a loop variable. The module-function arm also
requires a live binding before it dispatches through a closure.
