#### Mechanism

D3240 re-asks a read of a place a `T` write narrowed at each pin (`HD_TVW`), so at a nullable
pin `.length` on a `string | null` place and `.length` or `.includes` on an `i32[] | null` place
are refused, as the direct spelling `g(x: {[string]: i32} | null)` refuses its `.has`. A
method call or an index read whose receiver is a MAP place is not re-asked: the shared body's
narrowing to the non-null map stands, and the instance calls `has` on the null. Settling it
means routing a map receiver's method and index reads through the same pin re-check.

#### Ablation

| ingredient changed | outcome | needed? |
| --- | --- | --- |
| `const v: {[string]: i32} = Map()` (a non-null pin) | prints `false` | **yes** |
| `print(s["k"] ?? 0)` in place of `.has` | the same trap (the direct spelling refuses the index) | no |
| `print(s == null)` | prints `true` | **yes** (a use needing non-null) |
| `let s: i32[] \| null`, `.includes(1)` | loud check reject, as the direct spelling | **yes** (a map) |
| a field `q.s` or a closure read in place of the name | the same trap | no |

#### Close

A map or set method call (`checkMemberCallNode`'s `holeMapMethod` arm) or a map index read
(`checkIndexNode`'s map-key arm) whose receiver is a pin-landed read (`tyIsWriteLandRead`) now
records a null-read constraint (`MC_NULL_READ_MARK`), which each pin answers with the direct
spelling's sentence: `member access '.has' on non-object {[string]: i32} | null`, `cannot index
non-array {[string]: i32} | null`. A non-null pin answers nothing and runs. An optional call
(`s?.has(k)`) records none. The closure and field reads of the ablation refuse the same way.
