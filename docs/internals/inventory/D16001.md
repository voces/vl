### D16001 — lists of a recursive record and of its intersection alias mint two ref-list rows for one type

**closed 2026-11-13 — the witness runs `3` with one ref-list row for the type · a one-member union keys as its member, before it is pushed on the hash-cons stack · filed 2026-11-13 against master `32ab5241`**

Repro:

    type Node = { v: i32, next: Node | null }
    type M = Node & { v: i32 }
    const xs: M[] = [{ v: 1, next: null }]
    const ys: Node[] = [{ v: 2, next: null }]
    print(xs[0].v + ys[0].v)
    // vl run: 3. The ref-list table holds a `Node` row and an `M` row whose element types
    // are `tyEq` but whose `rlElemKey`s differ.

Want:

    3

#### Mechanism

`M` is a one-member union over `Node`'s record (D14162). The `M[]` literal and the `Node[]`
literal each intern a ref-list row, and the dedup key (`repElemIdOfNameTy`) gives the alias and
the record different element ids, so one element type gets two rows. The emitted module has a
single list wrapper type, so no binary difference results.

#### Close

Closed by `repIdOf` peeling a one-member, non-literal union to its member before pushing it
(`repSoleMemberOf`). Keyed through the wrapper, the member met the wrapper on the stack as
itself (`repFoldDepth` → `tyUnrollsTo`, an alias and its body being one type) and keyed as a
back-edge. The duplicate-row probe shows the duplicate gone and none new over the population.

Before the close, it blocked step 7's close: one row per type holds even where the module bytes do not differ. Owner: lane A, after `internArmShapeRow`. The fix shows the duplicate gone under the duplicate-row probe, with a sweep. A newtype's row beside its base's (`NtI32|null` / `i32|null`) is distinct by design and is not this row.
