### D15695 — a record holding a list built at a kept maker's record, handed to an annotated parameter of its own type, emits invalid wasm

**closed 2026-11-11, runs and prints `1` then `1` · was check-clean invalid wasm, clause 1 · found closing D15690 · filed 2026-11-11 against master `ada32709` · closed checker-side: where the store column builds a record literal's binding at another record (D15690), each annotated parameter of the binding's own type that a read of it is handed to, and that its callee reads only for a field, is instanced at that build (`storeHeldArgsAt`, check_store_rep.vl; `recHeldArgTakesRep`, check_fit_rules.vl), as D14532 instances a narrower record's; the read's other deliveries at its own storage are refused (`recHeldReadsOwnRefuse`) · the repro, `.length`, two calls, a second record of its own type handed to the same function, a named `type R`, a second field, and a `for` over the field in the callee run · fixture `tests/cases/soundness/record-holding-built-list-to-annotated-param-runs.vl` · filed: a callee handing the parameter on whole ([D15698](D15698.md), now loud); the literal as the argument refuses as on master**

Repro:

    type J = { f: i32 | null }
    function mk2() { { f: 1 } }
    const dA: J = mk2()
    print(dA.f ?? 0)
    const xs = [mk2()]
    function use(r: { ys: { f: i32 }[] }) { print(r.ys[0].f) }
    const r = { ys: xs }
    use(r)

Want:

    1
    1

#### Mechanism

Not ablated. `r` is built at `{ys: J[]}`, and the parameter takes `{ys: {f: i32}[]}`, which stores the
element's field differently; no delivery copies or refuses it, so the call hands a struct of the
wrong type.
