### D17878 — an instance's per-call parameter table holds one type per parameter, read both as the value's instance and as its type parameter's binding

**runs today and must keep running · refactor target · filed 2026-11-28 against master `caffc73f9` by COV-CLOS-3 (coordinator ruling: split the call row; it is D17323's IR face's fix)**

Repro:

    function same<T>(k: T): T { return k }
    function mid<F, G>(a: F, a1: G) {
      let b: F = a1
      print(a("x"))
      print(b(3))
    }
    function mid3<F, G, H, G1>(a: F, a1: G1, a2: H) {
      let b: G1 = a1
      const c: G = a2
      print(a("x"))
      print(b(3))
      print(c(true))
    }
    mid(same, same)
    mid3(same, same, same)

Want:

    x
    3
    x
    3
    true

#### Mechanism

The elaboration's per-call parameter table (`elabCallParamTy` and its siblings) keeps one type
for each parameter of an instanced call. That one type is read as two different facts: the
instance the argument's VALUE is built at, and the binding of the TYPE PARAMETER that annotates
the parameter. They differ when the value is one nothing calls (D6213's unread default, D6881's
inert stub) and the type parameter is read by something else, such as a binding annotated with it
(D17323's IR face). Five writers then close the type parameter from the value's instance:

1. the check's unread-default trial in `pinUnreadGenFnArgs` (no longer writes `vTys`, and its
   trial rows are cut);
2. `elabSetRepRow`, which re-keys the call at the stub or default rep of an uncalled set;
3. `elabDemandFrom`, whose `bindGenWalk` binds the type parameter from mono's pin;
4. mono's pin ladder, which binds the clone's type parameter (`tvN`) from the parameter's pin;
5. `monoDefaultUnboundTyParams` → `monoBindTyParamElab`, which binds a type parameter left
   unbound to the checker's binding at the call, again the value's instance.

Site fixes to 2–4 were measured and refused: together they lost about 55 runs in `generics`,
`functions` and `closures`, because a parameter is read through lists, records, hand-ons and
choices without a direct call. The fix is to split the row into the type parameter's binding and
the value's instance, re-point each reader to the one it means, and drop no site rung.

#### Grading list

The repro above depends on `tyParamOnlyBareParams` counting `let b: F = a1` as a copy of `F`
although it copies `a1: G`. Narrowing that rule alone loses this program ("a generic function
taken as a value reaches no call that fixes its type" at 24:5), so the narrowing lands with the
split and this program is a required pin. D17323's witness must run on top of the split.
