### D17106 — a map stored two different shapes of closure (two bundles, or a bundle and a plain closure) is declared at one closure

**check-clean invalid wasm · `vl check` rc 0; as shipped (with IR claims) `vl run` an invalid module, claimless (legacy alone) a loud emit refusal at the second store · clause 1 · filed 2026-11-24 against master `b548cb711` (found by [D17094](D17094.md)'s reach sweep)**

Repro:

    function lap(f) {
      const _a = f(2.5)
      const _b = f(3)
      return f
    }
    function lap2(f) {
      const _a = f(true)
      const _b = f(3)
      return f
    }
    const m = Map()
    m["a"] = lap((a) => a + 1)
    m["b"] = lap2((a) => a)
    print(m.has("b"))
    // vl check: rc 0.  vl run: invalid module, type mismatch: the map's slot is the closure struct,
    // the store the bundle record. Claimless: "emitProgram: a function returning a parameter called
    // at two signatures is called where its result is not used at one of them" at the second store

Want:

    true

#### Mechanism

A fresh `Map()` is typed at a bundle record only when every value the slot is written is a call
returning that same record (`elabSlotRecordNote`, `elabTyListSame`). Two stores of different records
(`{c0:(f64)=>f64,c1:(i32)=>i32}` and `{c0:(boolean)=>boolean,c1:(i32)=>i32}`), or of a record and a
plain closure, decline the note, so the map is declared at the single closure while each
`lap(...)` returns its record. Legacy alone refuses at the store; the invalid module is the claimed
start, which skips that refusal (IR-P1's, as in D17094). One value shape per map runs.
