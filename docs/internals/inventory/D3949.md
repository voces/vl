### D3949 — a capture cell written from another capture cell holding a generic function builds invalid wasm

**closed 2026-10-10 by lane SC · runs · was check-clean invalid wasm · clause 1 · pins: `tests/cases/closures/captured-cell-written-from-another-cell.vl` · found in review of #3498 (`rv3498/p25`) · filed 2026-10-10 against master `429e7b093`**

Repro:

    function ci(f: (n: i32) => void, n: i32) { f(n) }
    function inner<U>(u: U) { print("I"); print(u) }
    function other<V>(v: V) { print("O"); print(v) }
    function main() {
      let k = other
      let j = inner
      const flip = () => { k = j; j = other }
      ci(k, 1)
      flip()
      ci(k, 2)
    }
    main()
    // vl check: rc 0.  vl run: the emitted module failed to validate

Want:

    O
    1
    I
    2

#### Mechanism

Both `k` and `j` are capture cells, and the write `k[0] = j[0]` reads another cell rather than a
generic by name, so `j`'s seed `inner` was never instanced at `k`'s delivered type and `j`'s cell
kept the generic's un-pinned element type. D3939's value rule (`monoCellValueTake`) now resolves a
written cell read to its cell and instances that cell at the same type.
