### D15332 — a value `if` of records of un-annotated functions, handed to a parameter annotated at a closed function field, is refused at check

**open · loud check reject · `a {f: (_) => _} cannot be delivered as {f: (i32) => i32} here` · clause 2 · an un-annotated parameter runs since D15301 M2 · found grading D15301 M2 · filed 2026-11-04 against master `6f1693f5`**

Repro:

    function id1(a) { return a }
    function id2(a) { return a }
    const c = 1 > 0
    function gg(r: { f: (a: i32) => i32 }) { return r.f(2) }
    const k = if c { { f: id1 } } else { { f: id2 } }
    print(gg(k))

Want:

    2

#### Mechanism

The design does not owe this refusal: no rule forbids handing an un-annotated function to a
closed function type, and each arm's function takes `(i32) => i32` at the annotation, as
`gg({ f: id1 })` does. What refuses is a mechanism. The choice's joined field type stays the hole
function `(_) => _`, and the checker does not pin it at the destination as it pins a literal's.

| the annotation (`function g(r)`) with `g(k)` | emit reject, D15330 | no |
