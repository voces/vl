### D16365 — an un-annotated parameter handed `[]` and pushed two records of an empty-list field builds that field at `i32` where a later push stores `f64`

**check-clean invalid wasm · `type mismatch: expected (ref $type), found (ref $type)` · clause 1 · the parameter annotated, or one record pushed, runs; the same body over a named `[]` is a loud check reject · found grading `empty-list-shared-record.matrix.vl` (cell `argument`, un-annotated) · filed 2026-11-14 against master `b45a06ef`**

Repro:

    function take(a) {
      a.push({ ys: [] })
      a.push({ ys: [] })
      a[0].ys.push(0.5)
      print(a[0].ys[0])
    }
    take([])
    // vl check: rc 0.  vl run: invalid module inside `take`

Want:

    0.5

#### Mechanism

Not yet traced. The record's `ys: []` is open in both pushes. The second push takes the
element's empty-list default, `i32`, so the record is laid out with an `i32` list while
`a[0].ys.push(0.5)` pins the field `f64`. Handing a named `const l = []` instead refuses at check:
`push: cannot add f64 to i32[]`.
