### D2463 — writing a narrowed name's other member while a nested function reads it is refused as `cannot assign string to i32`

**loud check reject · clause 2 · filed 2026-09-25 against master `2bf40476c`, found by the review
of #3157 · open**

Repro:

    let g: i32 | string = 1
    if g is i32 {
      const c = (): boolean => g is i32
      g = "s"
      print(c())
    }
    // vl check: cannot assign string to i32

#### Mechanism

Not yet ablated to the rung. `g` is declared `i32 | string`, so the write is legal: the same
write with no nested function narrows `g` to `string` and runs. The refusal is the checker
keeping the narrowing live for the nested function `c` and then checking the write against it.
Whether the write should be refused is D2402's question. The narrowing is what makes it unsound,
and the rule there refuses a writing CALL with a sentence that names the nested function. This
sentence names neither the nested function nor the declared type, and it reads as though `g` were
declared `i32`.

#### Ablation

| ingredient removed | outcome | needed? |
| --- | --- | --- |
| the nested function `c` | runs; `g is string` after the write prints `true` (`false` before D2447's close) | **yes** |
| the write | runs, prints `true` | **yes** |
| the storage (a local `let v` inside a function) | the same refusal | no |

#### Grading list

The local spelling; the same with the nested function's body reading `g + 1` rather than testing it.
If a ruling keeps the refusal, the close is a message naming `c` and the declared `i32 | string`.
