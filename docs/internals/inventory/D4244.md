#### Mechanism

A string literal union is a string to the program, and an instance of a generic at it takes the
union's `i32` tag. Two calls through one function value, one with the union and one with a
`string`, therefore want two instances of different wasm types in one slot. Through a written
`let`'s own calls the binding now holds the `string` instance and the union call converts its
argument, whichever comes first. A copy called with the union fixes the copy's type at the tag
(the witness), and so do a list element, a record field, a nullable union, and two different
unions; those refuse. Running them needs every value in the chain held at `string`, with each
narrower call converting its argument.

The binding is widened to `string` only when the call returns `void`. A generic that returns its
type parameter (`idg<T>(t: T): T`) would hand the union call a `string` back where the caller
reads a tag, so it refuses. The decision is a join over every signature recorded for the
binding, not the first one seen, so both call orders give the same outcome. A union of string
literals and numbers (`type M = "p" | 1`) already holds a `string` in its box, so it joins with
`string` at the union's own instance and runs in both orders (master trapped when the union
call came first).

Two different string literal unions (`"p" | "q"` and `"p" | "r"`) number their members apart,
and one instance cannot read both tags, so they refuse. Three cells of the review's grid ran on
master with them only because both literals passed were `"p"`, tag 0 in both unions. With
`const a: S = "q"` master prints `B r B r` for the review's `w_let_b_a` order, `x(b)` then
`y(a)`, where the program means `B r B q`, and each of the other three orders prints one
union's literal for the other's. Those three cells are a loud refusal now, not a run lost.
