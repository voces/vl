### D2382 — an un-annotated record field holding a list concatenation is coded as an arithmetic `i32` field

**closed 2026-09-25 — the witness runs and prints `3.5` · was check-clean invalid wasm (the list stored into an `i32` field), clause 1 · filed 2026-09-25 against master `a277bf7b0` · fixture `tests/cases/objects/anon-field-list-concat.vl`**

Repro:

    const xs = [1.5, 2.5]
    const ys = [3.5]
    const r = { k: xs + ys }
    print(r.k[2])
    // vl check: rc 0.
    // vl run (as filed): Error: invalid module … inside the module's top-level code. Now prints 3.5.

#### Mechanism

`anonFieldCodeSyn`, the literal-syntax rung of an anonymous row's field code, read every `+` it
could not prove a string concatenation as arithmetic and asked `anonArithFieldCode`, whose
fall-back for a non-numeric recorded type is `0`, the `i32` slot. A list concatenation's recorded
type is an array, so the row minted `{k: i32}` and the literal stored a list into it. The `+` arm
now declines (`-1`) when the recorded type is an array (`nodeTyIsArrayish`), and the arena rung
codes the field as it codes any other list-valued one. Annotated destinations never reached the
rung and always ran.

Element grid (`i32`, `f64`, `i64`, `f32`, `u8`, `boolean`, `string`, record, nested list, union,
map), inferred and annotated, plus the field's other positions (nested record, list of records,
closure body, function body, return, argument, `| null`-narrowed operand, three-term chain): the
inferred face ran **2 of 21** before (the `u8[]` element and the argument position, both through
an adopted type) and **21 of 21** after; the annotated face ran 7 of 7 before and after. Of the
19 failures, 15 were invalid wasm and 4 loud emit rejects (`'.length' on a receiver the emitter
cannot classify`: the record, nested-list, union and map elements).
