### D15480 — a `const` lambda handed to a hole parameter and called there with a generic is refused at emit

**open · loud emit reject · `vl check` rc 0, `emitProgram: cannot take the generic function `id` as a value — a function value carries ONE signature`, clause 2, with the split plan on and off · D14943's legal twin, `toString` imported · the named-function spelling runs · found closing D14943 · filed 2026-11-05 against master `3ed87a1a`**

Repro:

    import { toString } from "std:fmt"
    function id(a) { return a }
    const lap = (g) => { const x = g(1); return x.toString() }
    function use(k) { return k(id) }
    print(use(lap))

Want:

    1

#### Mechanism

Not yet probed. With `lap` a named function (`function lap(g)`) the program runs and prints `1`:
`lap` is instanced where `use`'s call `k(id)` binds `g` to `id`'s instance at `i32`. So does the
lambda when `id` is closed. As a `const` lambda handed a generic, nothing builds `lap` at that
call's instance of `id`, and `id` is taken as a value of one signature.
