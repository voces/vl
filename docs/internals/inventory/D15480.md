Repro:

    import { toString } from "std:fmt"
    function id(a) { return a }
    const lap = (g) => { const x = g(1); return x.toString() }
    function use(k) { return k(id) }
    print(use(lap))

Want:

    1

#### Mechanism

The elaboration closes `use`'s parameter `k` at `((i32) => i32) => i32`, and mono delivers the lambda
there (`monoElabPin`). Inside `use`'s instance, `k(id)` is a call through the closure. The pass that
delivers a call's named function arguments at the callee's parameter types
(`monoCoerceAtValueParams`) read only the checker's type of `k`, which is open, so `id` was never
delivered and stayed a generic taken as a value. The named spelling never reaches that pass: `lap`
and `id` travel as tagged sets and `g(1)` dispatches.
