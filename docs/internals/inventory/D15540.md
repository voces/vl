### D15540 — a list whose element is a literal-union map beside its plain twin (`LM | IM`) has no list rep

**loud emit reject · clause 2 · `vl check` rc 0 · found by lane F probing #6658 · filed 2026-11-07 against master `eb8356fe8`**

Repro:

    type LM = {[i32]: 1 | 2}
    type IM = {[i32]: i32}
    const mi: IM = Map()
    const u: LM | IM = mi
    print([u].length)
    // vl check: rc 0.  vl run: emitProgram: '.length' on a receiver the emitter cannot classify as a list, string, map or set

#### Mechanism

`{[i32]: 1 | 2}` reads as its base map `{[i32]: i32}` (D2493), so `LM | IM` is a union of two
members with one box representation. The value itself builds and passes. A list of it does not:
neither the list literal's element nor the declared `(LM | IM)[]` gets a list rep, and every
consumer of the list refuses at emit. The checker refuses the analogous `Set<i32> | {[i32]:
boolean}` at its declaration ("a union cannot hold both … yet") but accepts this pair. Whether
the answer is that refusal at the declaration or a list rep for the twin union waits on a
ruling, so the row has no `Want:`.
