#### Mechanism

A generic called through a value at two types needs its set tagged: a call through a tagged set
dispatches to each member's instance at the call's own types, and an untagged one is pinned by
mono at the one type its flow delivers. Two things kept `{k}` untagged. The elaboration noted a
hand-back (`mintRetNote`) only for a function whose returned value reads its parameter directly,
so `fw2`, which returns `fw(f)`, handed nothing back and the tag rule refused the call `fw2(k)`.
And a hand-back call initialising a binding annotated with a closed function type
(`const a: (x: string) => string = fw2(k)`) was a context no id may reach, which refused the whole
set, every other call through it included.
