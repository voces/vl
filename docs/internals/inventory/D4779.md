### D4779 — `is S[]` over a box union of `string[]` and `S[]` answers by the arm a value was built as

**closed 2026-10-15 — now prints `1` · was check-clean silently wrong value, clause 1 · `is S[]` over a box union now tests the `string[]` arm's tag AND every element against `S`'s members, and the then-branch keeps the union, as D4056 keeps a record union's; the price is that `x.length` in that then-branch now meets the refusal the same union already got with no `is` ([D4917](D4917.md)) · found closing D4771 · related to D3885 (`is` is structural) · filed 2026-10-14 against master `bd9e38039` · pin: `tests/cases/unions/string-list-arm-is-literal-list.vl`**

Repro:

    type S = "a" | "b"
    function f(x: string[] | S[]) {
      if x is S[] { print(1) } else { print(0) }
    }
    const v: string[] = ["a"]
    f(v)
    // vl check: rc 0.  vl run: prints 0

Want:

    1

#### Mechanism

`string[]` and `S[]` are two reps (strings and atoms), so the union is a box and `is S[]`
tests its tag. D4771's ruling makes `is` over a list test every element; a `string[]` whose
elements all fit `S` fits `S[]`, so the `string[]` arm needs the element-wise test too.
