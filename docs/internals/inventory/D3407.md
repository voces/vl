### D3407 — a `+` chain in a generic body costs the checker time exponential in its length

**closed 2026-10-07 as a trap only — the copying collector became the compile default (lane GC), and the witness builds and runs (9.8 s, 298 MB, 103 collections); under `VL_COMPILE_GC=null` it still traps at the 4 GiB heap. The cost in the title is unchanged and still open · was compiler trap (`allocation size too large`) · found by the #3316 review · the same on master `4ff12b994` · filed 2026-09-30 against master `4ff12b994`**

Repro:

    function g<T>(a: T): T {
      a + a + a + a + a + a + a + a + a + a + a + a + a + a + a + a + a + a + a + a + a + a + a + a
    }
    print(g(1))
    // vl check: rc 0.  vl run: the compiler traps (24 terms); 20 terms builds in 6 G fuel

#### Mechanism

Each `+` over a hole operand types as a deferred binary-op hole (`HD_BINOP`, `mkBinOpRetTy`)
whose BASE is the left operand's hole and whose INNER answer is that same left hole again. At a
pin, `substHoleTyReal` (`compiler/typecheck.vl`) substitutes both — `substHoleTy(hdBase)` and
then `substTyDeep(hdInner)` — so the walk over an n-term chain visits 2^n paths. Every visit
banks the derived hole (`notePinnedHole`), which re-runs `argPinRecheck` over every parked
demand, so 80% of a 20-term build is in `argPinRecheck` and `holePinKey`. The emitter's own
classification of the chain is linear since D2445; this is the checker's substitution.

A lambda over `T` in a generic body doubles the same way:

    function g<T>(a: T): T {
      const h = (b: T) => b + b + b + b + b + b + b + b + b + b + b + b
      h(a)
    }
    print(g(1))

at 31 M, 422 M and 1.66 G fuel with 12, 16 and 18 terms. So does a recursive un-annotated function
whose body carries such a chain, the review's `recgrad` family:

    function f(n, x) {
      if n <= 0 { return x }
      x + x + x + x + x + x + x + x + x + x + x + x + x + x + x + f(n - 1, x)
    }
    const a: i32 = 2
    print(f(2, a))

at 2.46 G, 4.87 G and 9.73 G fuel with 15, 16 and 17 terms.

**Plan (not built).** Memoise `substHoleTyReal`'s answer per hole index for one substitution:
stamp the entry with a generation bumped whenever the binding arrays change — each outermost
`substTyDeep`/`substHoleTy` entry, and `argPinRecheck`'s own nested substitution, which must
restore the outer generation when it returns. `notePinnedHole` already ignores a repeated pin,
so skipping a repeated visit changes no bank. Grade on this ladder to 10,000 terms, and on
`tests/cases/generics` byte for byte.
