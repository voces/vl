### D2154 — `is string` over a hole parameter pinned at a literal union answers false

**closed 2026-09-23 — the witness prints `y` · was check-clean silently wrong at the written-alias spelling, clause 1 · filed 2026-09-23 against master `b5debe165`, exposed to inline sets by D2150 · fixture `tests/cases/literal-unions/inferred-array-inline-litunion-hole-param.vl`**

Repro:

    type KZ = "red" | "green"
    function mkval(): KZ { return "red" }
    const srcArr = [mkval()]
    function isStr(p) {
      if p is string { print("y") } else { print("n") }
    }
    isStr(srcArr[0])

#### Mechanism

The parameter pins at the atom, and `emitIs`'s atom arm asked the tested type for member texts to
compare against. `string` has none, so the arm fell through to a test that never matches. Every
member of a literal union is a string, so the atom arm answers `is string` true, and over the
`K | null` niche true exactly when the value is not the `-1` null. Fixture
`tests/cases/literal-unions/is-string-over-atom.vl`.

#### Grading list

The direct spelling `p: KZ` is refused by the checker (`string` is not a variant of `KZ`) and stays so.
