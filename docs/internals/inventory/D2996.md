### D2996 — a record that is not a fresh literal, delivered where a wider declared record stores a field differently, is shared unconverted

**closed by design · now a loud check reject · was check-clean invalid wasm · the owner's ruling ("A, with C eventually", 2026-09-29) answered the question: an existing record is refused at every position, and a record a function with no declared result builds is refused where the destination stores one of its integer fields as a bare float, which it has no conversion into (`recFloatBuiltElsewhere`) · fixtures `tests/cases/soundness/error-record-existing-value-widened.vl`, `tests/cases/soundness/error-record-built-in-function-widened-to-float.vl`, `tests/cases/soundness/record-fresh-value-widens-at-every-position.vl` · closed 2026-09-30**

Repro:

    type D = { v: f64 }
    const x: i32 = 3
    function mk() { return { v: x } }
    const d: D = mk()
    print(d.v / 2.0)
    // vl check: rc 0.  vl run: invalid module — type mismatch

#### Mechanism

The checker admits `{v: i32}` where `{v: f64}` is declared (record depth covariance,
DECISIONS.md D2060, legal where nothing writes a widened slot), and a record is shared, never
rebuilt, so the emitter hands `D`'s slot a struct of the other layout. A fresh literal avoids
this by being built at the destination (D2933, D2990); a call result, an annotated binding or a
declared record has no such build. The same holds when the field keeps its type but changes
storage (`i32` into `i32 | string`, a box). A converting copy is not sound here: the
non-widened fields stay writable through both handles, and a copy would split them.

**Question for the owner.** Should a non-fresh record whose field changes STORAGE (`i32` into
`i64` or `f64`, `f32` into `f64`, a scalar into a union or `| null` box) be refused by the
checker at the delivery, as "No implicit container widening" refuses `i32[]` into `f64[]`?
Recommendation: yes, with the container rule's wording and its two fixes (build the source at
the destination type, or copy it with a literal `{ v: n.v }`). A fresh literal and an
un-annotated binding of one stay legal, since they are built at the destination.
