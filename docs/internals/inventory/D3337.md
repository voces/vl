### D3337 — a list literal written directly as a closure's argument at a `T | null` element list parameter is built at the wrong element storage

**closed 2026-10-03 by [D3605](D3605.md) (lane CL2): a function-value call now seeds each argument's container shape from the callee's parameter, never the enclosing position · fixture `tests/cases/closures/value-call-list-literal-element-storage.vl` · was check-clean invalid wasm · clause 1 · found by #3304's review as a closure-then-cell-write defect, which it is not · the same on master `b6378e95b` · filed 2026-09-30 against master `b6378e95b`**

Repro:

    function f(a: (i32 | null)[][], c: boolean): i32 {
      const kl = (y: (i32 | null)[]) => { a[0] = y }
      if c { kl([5]) }
      a[0][0] = 4
      return a[0][0] + 1
    }
    print(f([[3]], true))
    // vl check: rc 0.  vl run: invalid module inside `f`: type mismatch: expected (ref $type), found (ref $type) (exit 70)

Want:

    5

#### Mechanism

Not traced, and the review's framing (a closure that assigns a row, then a direct cell write) is
refuted by the ablation: the write to `a[0][0]`, the assignment `a[0] = y` and the capture of `a`
are all scenery. The minimal program is a lambda-valued local called with an inline list
literal at a parameter typed `(i32 | null)[]`:

    function f(): i32 {
      const kl = (y: (i32 | null)[]) => y.length
      return kl([5])
    }
    print(f())

which is the same invalid wasm. An argument literal takes its element storage from the callee's
parameter, and a lambda-valued local is a callee the seeding does not resolve: this is
[D2702](D2702.md)'s mechanism (its witness, a `Shape[]` union-arm list, still fails identically
on this master) at a nullable-scalar element, and one close probably serves both. Which storage the literal is
built at instead is not printed here.

`#3304` (flow narrowing) widened this row's reach. The review's `P2_elem_closure_5` and
`P2_elem_closure_nu` (`rv3304r4-17562/g13/`) were check rejects on master `b6378e95b`, because the
call to `kl` ended `a[0][0]`'s narrowing and the `+` then read `i32 | null`. On master `2b30e3674`
(after #3304) `_5` is this invalid wasm and `_nu` is a loud emit reject, `bare null needs a
struct-typed context`. The rest of this row was graded before #3304 and its witness is unchanged.

Closed by [D3605](D3605.md): `emitCallRef` and `emitCapturedCall` seeded no list kind or slot from the parameter, so the literal built at whatever the enclosing position had left in `pendingListKind`. Both now seed it from the `$fnsig` key or the declaration, as the direct call seeds it.
