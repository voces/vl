### D4301 — a second list of the same generic, called through a non-constant index, a `let`, a length read or a `for` loop, reuses the first list's instance

**check-clean invalid wasm · clause 1 · found by the function-value flow table in shadow mode (fn-value-flow-design.md §(f) step 1) over the review witnesses (`rv3505/r7`: x02, x03, x04, x08; `rv3505/r6`: s09h, p03; x01 and `r6/p06` are the controls) · filed 2026-10-13 against master `aa43e52ef` with #3542 applied**

Repro:

    function inner<U>(u: U) { print("I"); print(u) }
    function main() {
      const gs = [inner]
      gs[0](3)
      const fs = [inner]
      let i = 0
      fs[i](true)
    }
    main()
    // vl check: rc 0.  vl run: the emitted module failed to validate inside `main`

Want:

    I
    3
    I
    true

#### Mechanism

Each list literal's element is pinned at the calls through it, but only a call at a constant
index is followed; the call `fs[i](true)` pins nothing, so `fs`'s element falls back to the
instance `gs` already made (`inner` at `i32`) and the `boolean` argument lands in it. The flow
table grades the class `disagree: instance fits no pin | list element`.

#### Ablation

| ingredient removed | outcome | needed? |
| --- | --- | --- |
| the dynamic index (`fs[0](true)`, x01's shape) | runs | **yes** |
| the first list `gs` | loud emit reject (`reaches no call that fixes its type`) | **yes** |

#### Grading list

x03 (`let f = fs[0]`), x04 (a `.length` read beside the call), x08 (`string` and `boolean`),
`r6/s09h` (`for f in fs` in a block shadowing `fs`), and `r6/p03` (both lists hold one
`const` alias of `inner`; the alias is scenery, `[inner]` twice still fails).
