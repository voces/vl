### D2228 — an un-annotated struct-field `[]`-or-`null` join traps the compiler on an unbound element-hole read

**closed 2026-09-23 — the witness runs and prints `0` · was a compiler trap (`vl check` rc 0, then `wasm trap: out of bounds array access` inside `tyIsNulLitUnionArr`, `emit_classify.vl`) · clause 1 · fixed by bound-testing the element hole in `tyIsNulLitUnionArr` and its neighbouring `aElem` reads, and by giving `anonNulFieldCodeOfTy` an arm for an unpinned element: the nullable i32 list (code 18), the rep the same value already takes bound to a plain local; a later use that pins the element (a `push`, an annotated destination) still decides it · found during PR #3069's review via `scripts/capability-probes/matrix.py` on `empty-list-join-null-sibling.matrix.vl` (`struct_field_init`/`struct_field_place`, un-annotated, both now RUNS, 0 cells moved otherwise) · filed against master `07d5e3b66` · fixture `tests/cases/objects/empty-list-join-null-field.vl`**

Repro:

    const w = { f: if 1 == 1 { [] } else { null } }
    print(0)
    // vl check: rc 0 (one warning: unused `w`).
    // vl run (as filed): the host reported a compiler trap — "wasm trap: out of bounds array
    // access", "note: an index outside the bounds of an array". Now prints 0.

#### Mechanism

`w`'s field is an un-annotated `if`/`null` join, so the field's recorded arena type's list
element (`TyArray.aElem`) is left a `-1` hole — nothing pins it, unlike `struct_field_assign`,
which reads the field's TYPE back rather than re-deriving one. A `--names` seed's backtrace
(`vl build compiler/entry.vl --names`) reads `collectAnonShapes` → `anonMintRowFor` →
`anonFieldCode` → `anonNulFieldCodeOfTy` → `tyIsNulLitUnionArr`. `anonNulFieldCodeOfTy`'s
`TyArray` arm (`emit_classify.vl:21088`) calls `tyIsNulLitUnionArr(inner)`, whose body
(`emit_classify.vl:17610`) reads `T.tys[t.aElem]` with a bound check only on `ty` itself
(`ty < 0`), never on the element index `t.aElem` it then indexes with — the
`sentinel-index-unguarded` shape CLAUDE.md's D1440/D1462/D1500 family names. A declared
struct type for the field (`type W = { f: string[] | null }; const w: W = { f: ... }`)
runs, because the field's own TYPE supplies a resolved element instead of the hole.

#### Ablation

| ingredient removed | outcome | needed? |
| --- | --- | --- |

| the `if`/`null` join (`{ f: [] }`, no `null` arm) | different loud reject, no trap | **yes** |
| the struct-field wrapper (join bound to a plain local instead) | runs | **yes** |
| downstream usage of `w`/`w.f` | still traps, identically | no |

#### Residue

The ablation's non-null sibling, `const w = { f: [] }` with no pinning use, is untouched by
this close and still a loud emit reject (`emitProgram: ref valtype with no interned shape`),
as is `{ m: Map() }`; the plain-local twin `const x = []` is a check reject by design (D1470),
so the field form owes either that diagnostic or a rep. Not filed separately yet.
