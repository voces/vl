### D16048 — a shared field read is refused when one record stores a string set beside `null` at the atom niche and the other a nullable number

**closed 2026-11-14 — the niche member boxes its atom as the string, or `-1` as the null box, into the read's box · was loud emit reject, `emitProgram: field access receiver is not a struct` · clause 2 · found grading D15882's neighbours (lane F) · filed 2026-11-14 against master `2509180f3`**

Repro:

    type K = "a" | "b"
    type A = { v: K | null }
    type B = { v: i32 | null }
    const b: B = { v: 3 }
    const u: A | B = b
    print(u.v)

Want:

    3

#### Mechanism

`sharedUnionFieldPlan` sees `A` store the field at the atom niche (code 30) and `B` at a
value-union box (code 16). The read is typed `K | i32 | null`, a box, and no plan converts the
niche into that box: `sharedFieldArmsBoxable` does not admit a code-30 member. The read falls to
the plain struct read and refuses.

#### Closed by

`sharedFieldArmsBoxable` admits a member storing a string set at the atom niche
(`sharedFieldArmNulSet`), and `emitSharedFieldNulSetBox` boxes it: `-1` as the null-tagged box,
any other atom as its string under the string tag. A read typed with `null` (`K | i32 | null`)
names its box by its key (`sharedReadBoxesSetArm`). Graded by
`matrix/shared-nullable-field-set-*.matrix.vl`.
