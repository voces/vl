### D7442 — an un-annotated literal that adopts a declared union's arm row reads its literal-set field as a string

**closed 2026-10-19 by lane L6 · runs, prints `a` · was check-clean invalid wasm · clause 1 · a declared union with a literal-set field on an inline record arm turns the atom classifiers on, as an annotation naming it would · pin: `tests/cases/unions/fresh-literal-adopts-arm-atom-field.vl` · present on master `1c86d0f42` · filed 2026-10-19 against master `1c86d0f42`**

Repro:

    type U = { kind: "a" | "c", q: i32 | null } | { kind: "b" }
    const v = { kind: "a", q: 4 }
    print(v.kind)
    const s: string = v.kind
    print(s)
    print(v.kind == "a")
    // vl check: rc 0.  vl run on master: invalid module, `expected (ref null $6), found i32`

#### Mechanism

The fresh literal `{ kind: "a", q: 4 }` adopts `U`'s first arm row, and that row stores `kind`
as the i32 atom of `"a" | "c"`. The atom classifiers are gated on `gLitUnionUsed`, and
`anyLitUnionUsed` set it only from a literal-union TYPE recorded on some node or annotation.
No node in this program records one: `U` is never named, and the literal's own checked type is
`{kind: string, q: i32}`. So every reader of `v.kind` declined the atom and treated the i32
field as a string ref. `print` printed the id, a string destination and `==` emitted invalid
wasm. The close makes a `UnionDecl` whose inline record arms carry a literal-set field count as
a use, so the classifiers are on wherever such a row can be adopted.
