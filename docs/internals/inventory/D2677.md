### D2677 — `as?` / `as!` over a union with a `null` member refuses a member as "not a member"

**closed · runs, prints `false` · was a loud check reject, clause 2 · found by #3193's review · filed 2026-09-26 against master `525837973` · fixed 2026-11-14: the one test predicate `tyTestMemberFit` (check_fit_rules.vl) answers covered / partly / none for each member of the operand, and `is`, `as` and `match` all ask it: `tyTestMayFit` is `is`'s gate, `tyTestNamesMembers` and `tyTestMeet` are the cast's arms, and `matchPatCover` marks a pattern's members, replacing `markUnionCover`, the cast's `unionCoversTy` test and the `is` gate's own assignability rule; the cast's members are flattened, so the `| null` union `R | S | null` names `S`. Fixture: `tests/cases/narrowing/type-test-one-predicate-is-as-match-runs.vl`**
Repro:

    type R = { a: i32 }
    type S = { b: i32 }
    type U = R | S | null
    const v: U = { b: 2 }
    const q = v as? S
    print(q == null)
    // vl check: rc 1 — `as S` names a type that is not a member of R | S | null

Want:

    false

#### Mechanism

`checkCastNode` tests the target against the operand's union for membership and reports the
false sentence only when the union has a `null` member; the same cast over `R | S` runs. The
likely cause, not yet traced, is that `| null` wraps the union in a `TyNullable` the member walk
does not look through.
