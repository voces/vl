### D17585 — a function's nullable bundle holder (a map read of a two-signature bundle) captured by a lambda is refused at emit

**loud emit reject · `a function returning a parameter called at two signatures is called where its result is not used at one of them` · clause 2 · open · `vl check` rc 0 · found by COV-CLOS's Q58 sweep of the nullable bundle holder · filed 2026-11-25 against master `9ab0eb7bd`**

Repro:

    function lap(f) {
      const _a = f(2.5)
      const _b = f(3)
      return f
    }
    function inFn() {
      const k = Map()
      k["a"] = lap((a) => a + 1)
      const g = k["a"]
      const seen = () => g != null
      print(seen())
    }
    inFn()
    // vl check: rc 0.  vl run: emit error, "emitProgram: a function returning a parameter called
    // at two signatures is called where its result is not used at one of them"

Want:

    true

#### Mechanism

The holder `g` is a map read of `lap`'s two-signature bundle record, so its type holds `null`. The lambda captures it. At module level, and uncaptured inside the function, the same holder runs. Captured from a function frame, legacy's call of `lap` finds no member fact for the use, and the IR claim, built from the same facts, writes an invalid module with a record where the capture's slot is declared. So the refusal is not the IR's. Ablated, not traced into the elaboration.

#### Ablation

| ingredient removed | outcome | needed? |
| --- | --- | --- |
| the lambda (`print(g != null)` in `inFn`) | runs, `true` | **yes** |
| `inFn` (the same lines at module level) | runs, `true` once the nullable-holder PR lands; a trap before it | **yes** |
| the map (`const g = lap(...)`, captured and called) | runs, `2` | **yes** |
| the second signature (`f(3)`) | runs, `true` | **yes** |
| the null test (a narrowed call `if g != null { g(1) } else { 0 }`) | still refuses | no |

#### Grading list

A non-null holder whose one use is a null test, `const g = lap((a) => a + 1)` then `print(g != null)` at module level, is refused with the same sentence with no lambda at all (a warning-level program; possibly a second mechanism). The module-level capture in `tests/cases/maps/map-of-bundles-nullable-holder.vl`.
