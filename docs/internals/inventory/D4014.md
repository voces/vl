### D4014 — an alias of a written generic-seeded `let` is called with no instance at the call's type, and the module does not validate

**check-clean invalid wasm · clause 1 · found in review of #3517 (`rv3517/d04_alias_after_write`) · filed 2026-10-11 against master `20fa382fe` with #3517 applied**

Repro:

    function inner<U>(u: U) { print("I"); print(u) }
    function other<V>(v: V) { print("O"); print(v) }
    function cb(f: (b: boolean) => void, b: boolean) { f(b) }
    function ci(f: (n: i32) => void, n: i32) { f(n) }
    function main() {
      inner(3)
      let f = other
      f = inner
      const g = f
      g(true)
    }
    main()
    // vl check: rc 0.  vl run: invalid module inside `main` (expected structref, found i32)

Want:

    I
    3
    I
    true

#### Mechanism

Not located. D3979 instances a call made through the written `let` itself; `g` is a `const`
alias of it, and the alias chain (`monoGenFnAliasChainFe`) stops at a written binding, so the
call through `g` is neither instanced nor refused, and the closure value and the call disagree
about its representation.
