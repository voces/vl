### D16013 — a list literal's closure, nested-list or nullable element row is keyed by its rendered spelling, whose parse normalizes the element type

**closed 2026-11-13 — runs (prints `ab`); the three render rungs key by `storageNormTy` of the rung's type, which agrees with the name's key and row type in every program · was: runs today, keyed by re-parsing the rendered name · filed 2026-11-13 against master `1ba9fd48e`**

Repro:

    function S(): "ab" { return "ab" }
    const sl = [S]
    const ts: readonly (() => string)[] = sl
    print(ts[0]())

Want:

    ab

#### Mechanism

A list literal with no closed element hint mints its ref-list row under the name
`arrLitElemName` gives it. That name is re-parsed for the row's key (`repElemIdOfNameTy`) and
its stored type (`fieldElemTyIxOfName`). `arrLitElemKeyTy` answers the type each template rung
builds its name from. For three rungs, the rendered name is a lossy normalization of that type:

- the closure render, here `() => "ab"` rendered `(()=>string)`;
- the nested-list leaf render;
- the nullable element render.

The render widens literals and unifies nullable forms, so its parse is another type: a different
key and not `tySame`. Those rungs keep the name's key. They stop needing it only when the
normalization the render performs has a typed form.

#### Grading list

- Every hint-less list mint at the closure (P1), nested-list (P16) and nullable-element (P17)
  rungs of `arrLitElemNameTpl`: 10, 1 and 1 programs.
