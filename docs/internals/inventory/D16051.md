### D16051 — a one-literal array takes three union-box codes for one rep, by how it is spelled

**closed · runs, prints `2` `s` · was a one-literal list whose union-box code came from its spelling (7 programs of the sweep population) · closed by banking `boxTagOfTy` at the member slices (`recordUnMemTys`, `msFreeSlicePush`, emit_rep) · filed 2026-11-13**

Repro:

    function f(x: "x"[] | string) {
      if x is string { print(x) } else { print(x.length) }
    }
    f(["x", "x"])
    f("s")
    // vl run: 2, s. The union row banks `"x"[]` at value-atom code -1. The alias spelling
    // `type X = "x"` renders `string[]` and banks 9; `("x" | "y")[]` banks 7.

Want:

    2
    s

#### Mechanism

The member code is `valueAtomKind` over the member's canon render (`recordUnMemTys`,
`msFreeSlicePush`, emit_rep.vl). A one-literal element has three renders: the quoted literal
(`"x"[]`), which no arm of `valueAtomKind` claims (-1); an alias the canon softens to its base
(`string[]`, 9); and, once a second literal joins, a literal union that `litUnionArrayElemOf`
claims (7). The arena type of all three is a list of string literals, which a type-derived code
answers once. The programs run, so each code is read consistently; the defect is that the code
is a fact about the spelling.


The member slices bank `boxTagOfTy(ty)`, read off the member's arena type. A list of string
literals, one or several, rides the interned-id `i32[]` backing at code 7, whether it is spelled
`"x"[]`, `X[]` over `type X = "x"`, or `("x" | "y")[]`.

#### Ablation

Each program is the repro's shape, with the element replaced. "Banked" is the code
`valueAtomKind` gives the list member; measured with a probe at the producer.

| element | banked | runs |
| --- | --- | --- |
| inline `"x"[]` | -1 | yes, `2` `s` |
| `type X = "x"`, `X[]` | 9 | yes |
| inline `("x" \| "y")[]` | 7 | yes |
| `string[]` | 9 | yes |
