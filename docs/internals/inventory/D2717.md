### D2717 — a call with no type arguments cannot pin a `T | null` parameter from its argument

**loud emit reject · clause 2 · found by D2684's close (the review grid's k4, m13, w1) · identical on master · filed 2026-09-26 against master `74bd044d7`**

Repro:

    function g<T>(u: T | null): boolean { u == null }
    const m: i32[] = []
    print(g(m))
    // vl check: rc 0.  vl run: emitProgram: monomorphize: unsupported argument type for `u` in a call to `g`

#### Mechanism

`monoInstantiate` pins a parameter whose annotation is a composite over a type parameter by
binding the parameter from the argument's spelling (`monoBindFromAnn`) and substituting it back.
For `T | null` against a non-null argument the spelling binds nothing, `monoSubstAnn` answers
`""`, and the call refuses. The checker already bound `T` at this call (its own `bindGenWalk`
walks a nullable against a non-null argument), so the pin exists in the arena; the explicit
spelling `g<i32[]>(m)` runs.

#### Ablation

| ingredient removed | outcome | needed? |
| --- | --- | --- |
| the `| null` (`u: T`) | runs | **yes** |
| the inference (`g<i32[]>(m)`) | runs | **yes** |
| the list (a `string`, a map, a record argument) | still refuses | no |
