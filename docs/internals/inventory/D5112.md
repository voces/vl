### D5112 — a call through a record field holding a written `let` of a generic, from a closure inside a generic function, has no signature

**loud emit reject · `vl check` rc 0 · clause 2 · found closing D5079 · the same on master `4af9eb956` · filed 2026-10-16 against master `4af9eb956`**

Repro:

    function k<T>(x: T): T { return x }
    function use<U>(u: U): U {
      let g = k
      g = k
      const r = { q: g }
      const f = () => r.q(u)
      return f()
    }
    print(use(5))
    print(use("t"))
    // vl check: rc 0.  vl run: emit error, a function-value call has no interned signature

Want:

    5
    t

#### Mechanism

D5079's close keys the pinned type of the field read `r.q` by the read node and the
INSTANCE's function node (`monoFieldReadTys`), because the instances of `use` share the read.
Here the call is in the closure `f`, and the emitter asks for the signature with the lifted
closure's function node, which is one node however many instances of `use` lift it. So the
lookup has no per-instance answer and the call falls back to the open checker type. A fix
keys the read by the lifted closure's instance, or pins the closure per instance first.
