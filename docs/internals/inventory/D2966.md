#### Mechanism

D2860 marks every un-annotated `let`/`const` initialised from a numeric literal and appends a
note when a refused value READS one. A store is the other direction: the binding is the
TARGET, and the refusal is raised at the value, so D2860's read test never saw it. The
assignment arm of `checkBinExprNodeReal` now names its target (`nlAsgTgt`) and the stored type
while it raises `cannot assign …`, while `assignableExpr` raises its own container refusal, and
while a compound assignment's operator refuses to mix the target's type with the operand
(`c *= fl()` is `operator '*' mixes i32 and f32`, not an assignment error). The target may be
the binding whole, one element of a list binding, or one field of a record binding whose field
initialiser is a literal (record literals are now marked too). The note is queued only when
the literal also fits the stored type (`i32` → `i64`/`f32`/`f64`, a list of byte literals →
`u8[]`; `f64` → `f32`), and suggests exactly that type — `let s: i64 = …`, or `x: 0 as i64` for
a field. None for a whole or compound store to a `const`, which `cannot reassign` refuses
already (an element or field store through one keeps its note). It is dropped when any other
store to the same binding and slot (whole, compound, element, field, `push`) within the
top-level statement that declares it holds a value the suggested type would refuse, so two
stores wanting different types get no note, while a same-named binding in another function
does not refute it. The CLI and LSP share the message. The LSP has no code action for
D2860 (quick-fixes dispatch on a diagnostic code; neither note carries one), so none was added.

#### Ablation

| ingredient removed | outcome | needed? |
| --- | --- | --- |
| the un-annotated declaration (`let s: i32 = 0`) | the bare mismatch, no note | **yes** |
| the literal initializer (`let s = f()`) | the bare mismatch, no note | **yes** |
| the fit (`let s = 0.5; s = big()`: `0.5` is no `i64`) | the bare mismatch, no note | **yes** |
| one stored type (`s = big(); s = fl()`) | both bare, no note | **yes** |
| the compound (`s = ld32(…)`) | note, `let s: i64 = …` | no |
| the function scope (a module-level `let`) | note, keeps `export` | no |
| `let` for `const` on a whole store | `cannot reassign`, no note | **yes** |
