### D15339 — [CLOSED 2026-11-10] a map of records of an un-annotated function, the function called at two types, is refused at emit

**closed 2026-11-10, runs and prints `2` then `2.5` · was loud emit reject · `emitProgram: cannot take the generic function id1 as a value — a function value carries ONE signature` · clause 2 · one call type runs · found grading D15336 · filed 2026-11-04 against master `019d4cdd` · closed with [D15533](D15533.md): the `.set` record literal is admitted by the tag rule and keeps the slot's record, so the one member is called at each type through its set · fixture `closures/two-generics-set-as-records-of-one-map-called-at-their-types.vl`**

Repro:

    function id1(a) { return a }
    const m = Map()
    m.set("a", { f: id1 })
    m.set("b", { f: id1 })
    const x = m.get("a")
    if x != null { print(x.f(2)) }
    const y = m.get("b")
    if y != null { print(y.f(2.5)) }

Want:

    2
    2.5

#### Mechanism

Not the field widener's push: one member already refuses. A map's values are read through
`get` into a nullable binding, and the function stored in a record map value is never given a
set or a signature per call type; the list twin (`xs.push`) runs since D15336.
