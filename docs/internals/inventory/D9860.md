#### Mechanism

The monomorphizer substitutes a generic's `T[]` annotation by spelling (`monoSubstAnn`,
emit_base.vl), suffixing the binding through `arrElemSuffixed`. That grouped a union but not a
function type, so `reduce`'s `self: T[]` at `T = (i32)=>i32` was spelled `(i32)=>i32[]`, which
the type parser reads as a function returning `i32[]`. Its ref-list lookup found no row for that
element, though the row `((i32)=>i32)[]` existed. Every generic over `T[]` at a function-type `T`
refused the same way, user generics included (`len<T>(xs: T[])`, `first<T>`). `fill` was
check-clean invalid wasm and now runs too.
