### D15910 — a hole lambda's bundle in an un-annotated record field, both handed whole and called through, is refused at emit

**closed 2026-11-12, runs and prints `5` `2.5` `10` · was loud emit reject · clause 2 · `emitProgram: monomorphize: unsupported argument type for \`b\` in a call to \`take\`` · found closing [D15907](D15907.md) · filed 2026-11-12 against master `b93ddf3d` · closed in the elaboration: a record binding whose field the slot note keeps whole takes that record at the field in its slot fact (`elabSlotRecFieldTy`, written by `elabSlotRecordNote`, emit_elab.vl), so its calls through the field no longer close it at the one member they take · fixture `tests/cases/closures/hole-lambda-bundle-record-field-handed-and-called.vl`**

Repro:

    function lap(f) {
      f(2.5)
      f(3)
      return f
    }
    function take(b) {
      print(b(4))
      print(b(1.5))
    }
    const o = { f: lap((a) => a + 1) }
    take(o.f)
    print(o.f(9))

Want:

    5
    2.5
    10

#### Mechanism

The slot note keeps the record whole in the field, but the elaboration types the binding `o` at
the member its call through the field takes (`{f: (i32) => i32}`), so mono's adoption of `o`'s
type refused (`binding `o` holds another type than the elaboration's`). The binding's slot fact
was closed from its deliveries before the note ran, and the call's member won. The same reads of a
list element ran.

#### Ablation

| spelling | outcome |
| --- | --- |
| `take(o.f)` alone | runs |
| `o.f(9)` and `o.f(2)` alone | runs |
| `take(o.f)` and `o.f(9)` | refuses |
| `const xs = [lap(…)]`, `take(xs[0])` and `xs[0](9)` | runs |
| `const v = o.f`, `take(v)` and `v(9)` | refuses |
