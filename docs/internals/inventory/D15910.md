### D15910 — a hole lambda's bundle in an un-annotated record field, both handed whole and called through, is refused at emit

**loud emit reject · clause 2 · open · `emitProgram: monomorphize: unsupported argument type for `b` in a call to `take``; through a `const` holder of the field, `emitProgram: a function value is called at two signatures, and the closure it holds was built for one` · found closing [D15907](D15907.md) (cell `struct_field_init`/un-annotated of `lambda-bundle-returner.matrix.vl`) · filed 2026-11-12 against master `b93ddf3d`**

Repro:

    function lap(f) {
      f(2.5)
      f(3)
      return f
    }
    function take(b) {
      print(b(4))
      print(b(1.5))
    }
    const o = { f: lap((a) => a + 1) }
    take(o.f)
    print(o.f(9))

Want:

    5
    2.5
    10

#### Mechanism

The slot note keeps the record whole in the field, but the elaboration types the binding `o` at
the member its call through the field takes (`{f: (i32) => i32}`), so mono's adoption of `o`'s
type refuses (`binding `o` holds another type than the elaboration's`). The note therefore
declines this shape, which keeps the earlier refusal. The same reads of a list element run.

#### Ablation

| spelling | outcome |
| --- | --- |
| `take(o.f)` alone | runs |
| `o.f(9)` and `o.f(2)` alone | runs |
| `take(o.f)` and `o.f(9)` | refuses |
| `const xs = [lap(…)]`, `take(xs[0])` and `xs[0](9)` | runs |
| `const v = o.f`, `take(v)` and `v(9)` | refuses |
