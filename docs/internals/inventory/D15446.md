**closed 2026-11-05, runs, prints `a 1 9 a 9 1 a 1`, with the split plan on and off, in both hand orders · was a loud emit reject without the plan, `cannot take the generic function `top` as a value`, clause 2, and a hidden split-plan dependent · one set decided one way: a function that is a member of some set beside a capturing nested function is bundled in every set holding it (`elabBundledBeside`, emit_elab.vl), so `both(top)` hands `top`'s closures at both signatures as the choice does · the two hand orders build the same functions, only the module's top-level calls in source order · fixtures `tests/cases/closures/top-level-generic-handed-alone-and-in-choice-with-nested-capturing-fn.vl` and `top-level-generics-handed-alone-beside-capturing-choices.vl` (the choice at a parameter called at one type, and two capturing members) · filed 2026-11-05 against master `71274700`**

Repro:

    function both(f) {
      print(f("a"))
      print(f(1))
    }
    function top(s) { return s }
    function nested(c: boolean, n: i32) {
      function inner(s) {
        print(n)
        return s
      }
      both(if c { inner } else { top })
    }
    both(top)
    nested(true, 9)
    nested(false, 9)

Want:

    a
    1
    9
    a
    9
    1
    a
    1

#### Mechanism

`both`'s `f` is called at `string` and at `i32`. Handed alone, `top` is a one-member set the tag
decision tags, so `both` dispatches on its id. In the choice, `inner` captures `n`, so `{inner, top}`
is untagged and is delivered as a bundle (D15450). With the split plan off, `both`'s one instance
for a set parameter cannot take `top` both ways, and the value floor refuses the read.

#### Ablation

| --- | --- | --- |

| the choice removed (`nested` hands `inner` alone) | runs | **yes** |
| `inner` captures nothing | runs | **yes** |
