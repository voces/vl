### D15446 — a top-level generic handed alone to a parameter called at two types, and in a choice with a capturing nested function, runs only through the split plan

**runs today and must keep running · runs only through the split plan: with it off (`compileSrc` returning after its first compile) a loud emit reject, `cannot take the generic function `top` as a value`, clause 2, open · `both(top)` alone tags `{top}`, and the choice with `inner` makes `{inner, top}` a bundle, so `top` is read as an id at one hand and as a closure per signature at the other · a hidden split-plan dependent, which no `@run` file held until this row · fixture `tests/cases/closures/top-level-generic-handed-alone-and-in-choice-with-nested-capturing-fn.vl` · filed 2026-11-05 against master `71274700`**

Repro:

    function both(f) {
      print(f("a"))
      print(f(1))
    }
    function top(s) { return s }
    function nested(c: boolean, n: i32) {
      function inner(s) {
        print(n)
        return s
      }
      both(if c { inner } else { top })
    }
    both(top)
    nested(true, 9)
    nested(false, 9)

    a
    1
    9
    a
    9
    1
    a
    1

#### Mechanism

`both`'s `f` is called at `string` and at `i32`. Handed alone, `top` is a one-member set the tag
decision tags, so `both` dispatches on its id. In the choice, `inner` captures `n`, so `{inner, top}`
is untagged and is delivered as a bundle (D15450). With the split plan off, `both`'s one instance
for a set parameter cannot take `top` both ways, and the value floor refuses the read.
