### D2091 — a value-position `else if` chain lowers to one result-typed `if` frame per link, nested, and the host engine's memory to compile that grows super-linearly in the depth

**runs today and must keep running · residue of D1990's close · filed 2026-09-22 against master `ad8712231` + D1990**

Repro (runs, prints `1`):

    function f(x: i32): i32 {
      const r = if x == 0 { 1 } @@repeat(5000, "else if x == 1 { 4 } ")@@else { -1 }
      return r
    }
    print(f(0))
    // vl check: rc 0.  vl build: rc 0, 74 MB peak.  vl run: rc 0, 315 MB peak.

#### Mechanism

`emitIfExprAs` (and its siblings for ref, union and variant results) lowers each link as
`cond; if (result T) …; else <next link>; end`, so an N-link chain is N result-typed frames
nested inside each other in the emitted function. The compiler's side is linear since D1990;
the host engine compiling that module is not: `vl run`'s peak memory is ~2x `vl build`'s at
2,500 links and ~17x at 20,000. A non-dense integer `match` in value position lowers the same
way (a dense one takes the `br_table` path instead). The shape that avoids it is one outer
`block (result T)` with every link a void `if` that `br`s its value out, which nests nothing.

Peak RSS, 2026-09-22, the D1990 seed:

| links | 2,500 | 5,000 | 10,000 | 20,000 |
| --- | ---: | ---: | ---: | ---: |
| `vl build`, the witness's shape | 50 MB | 74 MB | 122 MB | 220 MB |
| `vl run`, the witness's shape | 118 MB | 315 MB | 1,042 MB | 3,808 MB |
| `vl run`, the same chain as statements with `return` arms (void frames) | 68 MB | 104 MB | 173 MB | 317 MB |

#### Ablation

| ingredient changed | outcome | needed? |
| --- | --- | --- |
| the chain in statement position, `return` in each arm | 317 MB at 20,000 — linear | **yes** (the result type) |
| the scrutinee values made sparse (`match` over `i * 1000`, value position) | 3,751 MB at 20,000 | no |
| the values made dense (`match` over `0..N`) | lowers to one `br_table`, not nested `if`s | **yes** |
