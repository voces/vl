### D1963 — a covariant widen of a struct-list field read off an un-narrowed union-ARM receiver emitted the wrong source row, so the module failed validation

**closed 2026-09-22 — the witness prints `300`, `300` · was check-clean invalid wasm (`the emitted module failed to validate inside viaLet: type mismatch: expected (ref $type), found (ref $type)`), clause 1 · found by review of the D1960 fix · filed against master `a8a104432` · fixture `tests/cases/unions/arm-struct-ref-list-field.vl` · witness respelled with a `readonly` destination on 2026-09-23, since only a readonly list is covariant ([D2161](D2161.md)); the mutable spelling is refused by design**

Repro:

    type Circle = { r: i32 }
    type Sq = { side: i32 }

    function look(ys: readonly Shape[]) { let t = 0; for s in ys { t = t + area(s) }; t }
    function viaLet(self: P) { const ys: readonly Shape[] = self.xs; look(ys) }
    function viaArg(self: P) { look(self.xs) }
    const a = mk(3)

#### Mechanism

The third reader of [D1960](D1960.md)'s name miss. `exprEmittedRefListSlot` names the row a
value was actually emitted at, and every covariance widen site copies from that row; its
`Member` arm asked only `structIndexOfExpr`, which is -1 for a union-ARM receiver, so the widen
copied from the wrong source heap type. The fix asks the arm's variant tables first
(`memRecvArmVariantIndex`), the same rung D1960 gave `refListElemNameOfExpr`.
