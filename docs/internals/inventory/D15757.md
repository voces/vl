### D15757 — a function held in an annotated list literal's map and read at another type through a second holder of another map is refused at emit

**open · loud emit reject · `emitProgram: ref valtype with no interned shape` · clause 2 · reading the second map by its own name runs, as do both lists un-annotated and both annotated · found by lane w321 closing D15756, grading `two-map-lists-sharing-a-smaller-set.matrix.vl` (every annotated cell) · filed 2026-11-12 against master `c3c39e3c1`**

Repro:

    function half(a) { return a / 2.0 }
    const m1 = Map()
    m1.set("a", half)
    const m4 = Map()
    m4.set("a", half)
    const ys = [m4]
    const v: ({ [string]: (a: f64) => f64 })[] = [m1]
    const g = v[0].get("a")
    const h = ys[0].get("a")
    if g != null && h != null { print(g(3) + h(3)) }
    // vl check: rc 0.  vl run: emit refusal

Want:

    3

#### Mechanism

Not yet traced. `half` is needed at `(f64) => f64` through `v` and at `(i32) => f64` through `ys`, so
`m1` and `m4` hold it at two signatures. The program reads `m4` through a second holder, the list
`ys`. The refusal names a mechanism, not a contract.
