### D15757 — a function held in an annotated list literal's map and read at another type through a second holder of another map is refused at emit

**closed 2026-11-12 by lane w321 · runs, prints `3` · was a loud emit reject (`emitProgram: ref valtype with no interned shape`), clause 2 · the holder list of maps now takes its closed slot fact when each element names a map already pinned at it (the map-element arm of `monoPinListElems`), and the reads of its maps' values are retyped through it (`monoRetypeMapReads` with the element step `[]`); a `const` alias of a pinned map, or an alias of one, takes the map's type and its reads are retyped (`monoPinMapSlot`) · fixture `tests/cases/maps/pinned-hole-fn-map-read-through-list-or-alias.vl` · matrix `pinned-map-of-hole-fn-read-through-a-holder.matrix.vl`: 11 cells refusal → runs, 0 lost · the holders still refused are [D15758](D15758.md) · found by lane w321 closing D15756 · filed 2026-11-12 against master `c3c39e3c1`**

Repro:

    function half(a) { return a / 2.0 }
    const m1 = Map()
    m1.set("a", half)
    const m4 = Map()
    m4.set("a", half)
    const ys = [m4]
    const v: ({ [string]: (a: f64) => f64 })[] = [m1]
    const g = v[0].get("a")
    const h = ys[0].get("a")
    if g != null && h != null { print(g(3) + h(3)) }
    // vl check: rc 0.  vl run: emit refusal

Want:

    3

#### Mechanism

`half` is needed at `(f64) => f64` through `v` and at `(i32) => f64` through `ys`, so `m1` and `m4`
hold it at two signatures. Probed 2026-11-12 on master `01f723226`, at `monoPinMapValues` and
`monoPinListElems`:

- Both maps pin correctly: `m1` at `{[string]: (f64) => f64}` and `m4` at
  `{[string]: (i32) => f64}`, with `et` = `nt` for each.
- `ys`'s slot fact is closed, `{[string]: (i32) => f64}[]`, but nothing annotates it. Its maps are
  called (`elabSlotUncalled` is false), so D15756's map-element arm skips it, and the function-element
  pin path does not apply to a list of maps.
- Letting that arm also take a called list whose every element is a map already pinned at the
  fact's element (`letType` set and `elabSlotTyAt` of the binding equal to the element) moves the
  witness one layer on. It then refuses as the alias spelling does: `emitProgram: a function-value
  call has no interned signature` (its parameter has no representation). The read
  `h = ys[0].get("a")` stays open, because `monoRetypeMapReads` retypes a pinned map's reads only by
  the map's own name (`monoIsMapValueRead`), never through a second holder: a list element or a
  `const` alias.

So the fix needs both: annotate the holder at its fact, and retype reads through a holder of a pinned
map. That widening alone made no program run, so it was not shipped. The refusal names a mechanism,
not a contract.
