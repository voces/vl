### D16967 — a binding holding a join of `null` and a field read of a built-apart record has no row for its `?.` read

**closed 2026-11-18 by lane F2 · runs, prints `4` · was a loud emit reject, clause 2 · closed with D16965: the store column records a nullable record binding's built read (`storeLetsResolve`, `storeHeldAt`, `check_store_rep.vl`), `storeLetBuiltOf` answers for the field read a `?.` is rewritten to, and the emitter's `letStoreHeldTy` reads that column; its own re-derivation (`letFieldReadHeldTy`) is deleted, so both sides read one fact · pin: `tests/cases/records/built-record-join-binding-read.vl` · graded by `built-record-read-join-opt.matrix.vl` · filed 2026-11-18 against master `12559325b` by lane F2**

Repro:

    type J = { f: i32 | null }
    const m = Map()
    m.set("a", { f: 4 })
    const _wm: {[string]: J} = m
    const d = { f: 1 }

Want:

#### Mechanism

`w3` is built with field `k` at `{x: J}` (D16957), and a read of `w3.k`, bound or through `?.`, takes
that build (`letFieldReadHeldTy`). A binding holding a value `if` of `null` and that read does not:
the join's held type is not read through its tails on the emitter side, so `kk`'s cell is asked for
the checked record `{x: {f: i32}}`, which no literal builds. Reading the tails needs the checker's
`tailValueLeaves`, an import the phase-state census forbids in `emit_classify.vl`; the walk wants a
phase-neutral home first. D16965 is the `??` spelling over the same binding.
