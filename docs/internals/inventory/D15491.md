Repro:

    function k1<T>(x: T): T { x }
    function k2<T>(x: T): T { x }
    function putU(xs, x) { xs.push(x) }
    const v = [k1, k2]
    putU(v, v[1])
    print(v.length)
    print(v[2](5))
    print(v[0]("s"))
    // vl check rc 0.  vl run: emit error: a list holding a generic function is called through its elements at more than one type

Want:

    3
    5
    s

#### Mechanism

A list called through its elements at two types needs its set tagged, so each element is an id
and each call dispatches to the member's own instance. The tag rule refused the element `v[1]`
handed to `putU`'s hole parameter `x`, because `putU` stores `x` into a holder (D15065): a store
whose holder an instance types is outside the decision. Here the holder is `xs`, which the same
call hands `v`, a holder of the set being decided, so the stored slot is one of its ids. The
`put<T>(xs: T[], x: T)` spelling was refused for a second reason: `x`'s parameter is annotated, and
only a bare-only `T` was admitted.
