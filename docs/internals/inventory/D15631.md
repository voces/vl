#### Mechanism

`elabSlotDeliveries` (emit_elab.vl) answers a parameter's slot by asking the same query of each
call's argument binding, and only the depth-0 query is memoised. With W callers per layer, each
holding a list of functions as its own parameter, the query for a push in layer L walks W^L
caller chains, to the depth cap of 8. No chain is a cycle, so D15630's `elabDlvActive` skip does
not apply. The element is a function, so `elabTyFnFree` does not either.

#### Ladder

Three callers per layer, guest fuel of the build on the D15630 compiler:

| layers | fuel |
| --- | --- |
| 4 | 46.2 M |
| 5 | 152.6 M |
| 6 | 549.9 M |

#### Fix direction

Memoise the nested query within one outermost query, keyed by the binding, path, instance, depth
and every mode global the walk reads (`elabDlvAnnOnly`, `elabLitSlotDepth`, `elabNoCallParam`,
`elabGenericByValue`). Use it only when no sink is on (`elabCallSinkOn`, `elabRetSinkOn`,
`elabCallRec`), because those make the walk write. The walk's side outputs
(`elabSlotLastHits`, `elabLitCallHits`) have to be checked before a hit can skip them.
