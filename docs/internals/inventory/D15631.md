#### Mechanism

`elabSlotDeliveries` (emit_elab.vl) answers a parameter's slot by asking the same query of each
call's argument binding, and only the depth-0 query is memoised. With W callers per layer, each
holding a list of functions as its own parameter, the query for a push in layer L walks W^L
caller chains, to the depth cap of 8. No chain is a cycle, so D15630's `elabDlvActive` skip does
not apply. The element is a function, so `elabTyFnFree` does not either.

#### Ladder

#### Fix

`elabSlotDeliveries` (emit_elab.vl) answers a nested plain query once per outermost query
(`elabDlvNest`, cleared at depth 0). The key is the binding, path, instance and depth, plus every
mode the walk reads: `elabDlvAnnOnly`, `elabLitSlotDepth`, `elabNoCallParam`, `elabGenericRead` and
`elabGenericByValue`. Depth is in the key so the depth cap truncates exactly as before. A query
under a sink (`elabCallSinkOn`, `elabRetSinkOn`, `elabCallRec`) or an omit list is not memoised,
because the walk writes there.
