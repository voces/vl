### D14976 — a hole callee's map write under a null-check does not pin an open `Map()` argument

**closed · runs, prints `5` · was loud emit reject, `vl check` rc 0, clause 2 · closed by re-asking the map demand on a hole parameter's non-null face against the argument (`holeKidMapDemands`) · filed 2026-11-02 against master `a6a876cff`**

Repro:

    function take(a) {
      if a == null { print(0) } else {
        a["a"] = 4
        print(a.length + (a["a"] ?? 0))
      }
    }
    take(Map())
    // vl check: rc 0.  vl run: emitProgram: a call passes more arguments than the function it calls takes

Want:

    5

#### Mechanism

The write lands on the parameter's non-null face, a derived hole of its own, so the map
demand the call re-asks on the parameter is empty and the argument's open `Map()` stays
open. The emitter then has no instance for `take` and refuses with a message about arity.
This also blocks the check-side refusal D14973 owes: without this pin, a scope-end
"cannot infer" would fire on this legal program.
