### D2654 — a module global written before its initializer ran lost the write: the initializer overwrote it

**resolved by the D2652 guard on the write chokepoint (owner ruling 2026-09-26: the read-before-init ruling covers writes too) — the witness now loads then traps with "`g` written before its initializer ran (line 4), via w" · was check-clean silently wrong, printing `7` · found beside D2652 · filed 2026-09-26 against master `979323f83` · `tests/cases/globals/write-before-init-traps.vl`**

Repro:

    function seven(): i32 { 7 }
    function w() { g = 5 }
    w()
    let g = seven()
    print(g)

#### Mechanism

`w` stored `5` into `g`'s cell before the start function reached `let g = seven()`, and the
initializer then stored `7` over it with nothing reported. The write chokepoint
(`emitUserGlobalSet`) now takes the D2652 guard for the same guarded globals and the same
reachability, outside the start function, whose own writes are the initializers. A `let` whose
initializer is a constant the module folds (`let g = 7`) is guarded for writes alone: its value
is there from instantiation, so it is never read early, but a write before its declaration used
to survive (nothing at the declaration stores over it) and printed `5`; the start function now
advances the progress cell at that declaration too. The direct
top-level spelling (`g = 5` above `let g`), which the checker used to accept, is now refused:
"`g` is written before its declaration" (`moduleBeforeDecl`, typecheck.vl).

#### Ablation
