### D2654 — a module global written before its initializer ran loses the write: the initializer overwrites it

**check-clean silently wrong · needs a ruling (does the 2026-09-26 read-before-init ruling cover a write?) · found beside D2652 · filed 2026-09-26 against master `979323f83`**

Repro:

    function seven(): i32 { 7 }
    function w() { g = 5 }
    w()
    let g = seven()
    print(g)
    // PRINTS 7

#### Mechanism

`w` stores `5` into `g`'s cell before the start function reaches `let g = seven()`, and the
initializer then stores `7` over it; nothing reports the lost write. Unlike a direct read, a
direct write before the declaration is not refused by the checker either (`g = 5` at top level,
then `let g = seven()`, prints `7`). The D2652 guard covers reads only, because the ruling names
reads.

Question for the owner: is writing a module global before its initializer ran the same runtime
error? Recommendation: yes, the same guard on the write chokepoint (`emitUserGlobalSet`), with
"`g` written before its initializer ran". The write is erased without a trace, which is the
wrong-value class the ruling exists to end; the reachability pass is already built, so the cost
is a second call site, plus a checker refusal for the direct spelling. The alternative, the initializer skipping when the cell was written, would
make an initializer conditional and is harder to explain.

#### Ablation

| ingredient removed | outcome | needed? |
| --- | --- | --- |
| the call before the declaration (`w()` moved after it) | runs, prints `5` | **yes** |
| the function hop (`g = 5` at top level before the declaration) | still prints `7` | no |
