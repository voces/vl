### D2252 — a closure's captured local takes a same-named top-level block binding's arm

**check-clean silently wrong · clause 1, wrong value · the PL-024/D2245 family, closure
case: D2245 fixed the direct-return spelling but not one routed through a closure · filed
2026-09-23 against master `3330dcaa3`**

Repro:

    type Err = { code: i32, msg: string }
    function mk(): () => i32[] | Err {
      const r: i32[] = [4, 5, 6]
      () => r
    }
    const a = mk()()
    let out = "\{a is Err}"
    if !(a is Err) { out = out + " \{a.length}" }
    if true {
      const r: Err | null = { code: 2, msg: "block" }
      out = out + " \{r != null}"
    }
    print(out)
    // expected `false 3` (with the `if true` block removed)
    // PRINTS true true

#### Mechanism

D2245's fix, `moduleLocalLetSeenFrom(fnIx, name)`, declines the module-block lookup when
`fnIx` — the frame doing the read — binds `name` itself. `nulVariantIdxOfExpr` and its
struct twin both ask the CAPTURE arm first (`capturedNulVariantIdx`/`capturedStructIndex`),
but those only recognize a capture that is ITSELF a nullable-variant or struct niche; `r`'s
real type here is a plain `i32[]`, so the capture arm answers "no" correctly and the walk
falls through to `frameLetOf`/`moduleLocalLetSeenFrom`. Both are asked with `fnIx` set to
the CLOSURE's own frame — and the closure has no parameter, `let` or loop variable named
`r` (it only captures `mk`'s), so the guard says "this frame doesn't bind `r`" and the
module-block `r: Err | null` answers instead, boxing the return value under `Err`'s tag.
The guard checks the READING frame's own bindings, not the chain of frames whose captures
it reads through — correct for D2245's direct-return case (frame == the frame that declares
`r`) and wrong here (frame == the closure, one hop from the frame that declares `r`).

#### Ablation

| ingredient removed | outcome | needed? |
| --- | --- | --- |
| the closure (`() => r` replaced by returning `r` directly, no lambda) | prints `false 3` | **yes** |
| renaming the block binding from `r` to a different name | prints `false 3` | **yes** |
| the `if true` block (no same-named module binding at all) | prints `false 3` | **yes** |

#### Grading list

D2245's own grading list (`readFile`/`writeFile`'s PL-024 shape) is unaffected — that
spelling has no closure. A fix should extend `moduleLocalLetSeenFrom`'s declining set (or
its three call sites' capture arms) to also check every frame the reader captures THROUGH,
not just its own, and must keep D2245's fixture and this row's non-closure ablation row
running.
