### D1590 — the `unknown type` diagnostic knew the name it wanted and did not say it; the checker had the candidate list in hand at the moment it refused

**fixed — now a loud check reject that ENDS by naming the VL spelling: `unknown type 'bool'
within '{[i32]:bool}'; did you mean 'boolean'?` · was the same refusal, one word short ·
diagnostics only: emitted wasm byte-identical, distilled corpus 0 classes moved, 0
`runs → not-runs`, 0 `→ silent` · reported by glean as VL-039 · filed 2026-09-04 against
master `0f43eb89`**

Reported by the language's first external consumer: `~/glean/docs/vl-issues.md` §VL-039.
Its own words — "The message is correct and points at the right span, but a reader coming
from almost any other language will try `bool` first, and the compiler knows the name it
wanted." VL-040, filed directly beneath it, is the counter-example the consumer nominated
as the house style: name what went wrong, why, and the construction to use.

Repro (before: the first line only; now: the whole line):

    const seen: {[i32]: bool} = Map()
    print(seen.size)

    // BEFORE: 1:25: unknown type 'bool' within '{[i32]:bool}'
    // NOW:    1:25: unknown type 'bool' within '{[i32]:bool}'; did you mean 'boolean'?

#### Mechanism

**THE CANDIDATE SET WAS ALREADY IN SCOPE AT THE REFUSAL.** `nameToTyReal` bottoms out on a
three-rung leaf ladder — `primTyOfName`, `tpEnvTyOfName`, `declaredTyOfName` — and answers
`-1`; `unknownTyText` then renders the message from the banked failing COMPONENT
(`unkTyPart`). Every name the annotation could legally have used is reachable from that
point: the built-in spellings and `cUserTypes`, the declared-type map the last rung reads.
Nothing had to be collected, threaded or cached — the diagnostic simply never asked.

Two sources, tried in that order, at most ONE suggestion:

1. **A spelling map for newcomers** (`tySpellFrom`/`tySpellTo`, 14 entries), exact and
   ASCII-case-folded: `bool` → `boolean`; `int`/`integer`/`int32`/`i32_t` → `i32`;
   `long`/`int64` → `i64`; `float`/`double`/`number` → `f64`; `str` → `string`;
   `byte` → `u8`. The `boolean` and `string` entries exist so the CAPITALISED spellings
   (`Boolean`, `String`, `Number`) land. **None of these names becomes a type** — the
   refusal is byte-identical, only the sentence grows.
2. **An edit distance** over the names in scope: `builtinTyNames` (this row turned
   `isBuiltinTyName`'s ladder into the LIST it always described, so there is still one home
   for "resolves with no declaration in sight") plus every key of `cUserTypes`, offered
   under the spelling the source holds (`demangleName` cuts the `$mN` module-merge mangle,
   so a suggestion works in module mode). The metric is Levenshtein with adjacent
   TRANSPOSITION — `i23` for `i32` is the typo this exists for and plain Levenshtein charges
   it two, over the budget any three-character name has. Budget by length: **≤ 1 up to 4
   characters, ≤ 2 up to 8, ≤ 3 beyond**; a candidate shorter than 2 characters, and a typed
   name shorter than 2, are never matched. Built-ins are walked first and a tie keeps the
   earlier candidate, so **declared types break ties in registration order**.

The suffix is a SUFFIX, and the two call sites with a clause of their own (`… for field
'f'`, `… in union 'U'`) route through the new `unknownTyTextIn` so their clause lands BEFORE
it — `did you mean` always ends the sentence, and `unknown type '<name>'` is still the
prefix every consumer matches on. A `unkTyClash` refusal (`u8` is a storage type, `Map` is
not a type name, an unsupported map key) already names its remedy and takes no suggestion.

#### Ablation

| ingredient removed | outcome | needed? |
| --- | --- | --- |
| the map spelling (`const b: bool = true`) | `unknown type 'bool'; did you mean 'boolean'?` | no — the map is scenery |
| the spelling map (`i23` instead of `bool`) | `did you mean 'i32'?` — the distance rung answers | no |
| the transposition arm | `i23` loses its suggestion (distance 2, budget 1) | **yes, for `i23`** |
| a NEAR name in scope (`Zork`) | bare `unknown type 'Zork'` | **yes** |
| length ≥ 2 (`const q: Q = 1`) | bare `unknown type 'Q'` | **yes** |
| the demangle (`Square$m0` in module mode) | the mangled key is 4 edits away, no suggestion | **yes** |

**`byte` → `u8` is a TWO-HOP answer in value position, deliberately.** `const n: byte = 1`
now says `did you mean 'u8'?`, and `u8` there says `values are i32`. The alternative is
silence for the one spelling the reader actually typed; the second message is the one that
carries the rule, and it is already written.

**The whole corpus was swept for a suffix nobody asked for**: of every `tests/cases/**.vl`,
exactly ONE pre-existing fixture gains one — `types/boolean-no-bool-alias.vl`, whose subject
IS this spelling — and its `@error` line is updated. The corpus tier matches by SUBSTRING
and therefore cannot see an absence, which is why the negative control's assertion is an
equality in `tests/vl_unknown_type_suggestion_test.ts` rather than a `@error` directive.

* `tests/cases/types/unknown-type-did-you-mean.vl` — glean's witness verbatim, the spelling
  map, and the distance against a declared type, in one program.
* `tests/cases/types/unknown-type-no-near-name.vl` — the negative control's corpus shape.
* `tests/cases/types/boolean-no-bool-alias.vl` — the one existing fixture that moved.
* `tests/vl_unknown_type_suggestion_test.ts` — EXACT message equality on all four, plus the
