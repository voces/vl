### D2304 — `vl fmt` ejects a comment written between two operands of a binary chain to after the statement

**runs today and must keep running · the witness runs under `vl run`; the defect is `vl fmt` on it, which the grader does not drive · found grading the leading-operator ruling · filed 2026-09-24 against master `c2f040366`**

Repro (runs, prints `6`):

    const a = 1
    const b = 2
    const c = 3
    const x = a + // the first term
      b + c
    print(x)
    // vl fmt: the chain fits one line, so it prints `const x = a + b + c` and then
    //   `// the first term` on its own line AFTER the statement, followed by a blank line.
    //   The comment has moved from inside the expression to below it.

#### Mechanism

`flattenChain` (`compiler/format.vl`) collects a chain's operands by rendering each one with
`expr` and never asks the comment table about the gaps between them, so a comment trailing an
operand, or on its own line between two operands, is not claimed by the chain. It is flushed
by the statement printer at the next line boundary, which is after the whole statement. The
same holds when the chain does break (one operand per line): the comment still lands after
the last operand. D1776/D1777 gave list literals, object literals and call arguments a
verbatim anchor over the gaps between items; the binary chain never got one. Independent of
where the operator is printed: it relocates identically with operators trailing (before
2026-09-24) and leading.

#### Ablation

| ingredient removed | outcome | needed? |
| --- | --- | --- |
| the comment | nothing to relocate | **yes** |
| the chain (`const x = a // c` ⏎ nothing) | trailing comment stays | **yes** |
| the chain fitting one line (make it over-width) | still relocated, after the last operand | no |
| the comment on its own line between `a +` and `b` | still relocated | no |

#### Grading list

Both comment positions (trailing an operand, own line between operands), in a chain that
fits and one that breaks, and in the forced-paren `if` condition (`emitCondOperands`, which
flattens the same way).
