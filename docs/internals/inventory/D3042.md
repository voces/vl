### D3042 — an `i32[]` parameter stored into a `readonly i64[]` module binding is check-clean invalid wasm once the caller writes the argument

**closed · the store is a view of the parameter ([D3028](D3028.md)): the scalar delivery site builds one for a named root the write analysis sees written, as well as for one it cannot follow · fixture `tests/cases/arrays/readonly-scalar-view-written-in-loop.vl` · was check-clean invalid wasm · found by the #3264 review · the same on master `3a71bb1f9` · filed 2026-09-28 against master `3a71bb1f9`, closed 2026-09-28 against master `3a71bb1f9`**

Repro:

    let keep: readonly i64[] = []
    function st(x: i32[]) { keep = x }
    const l: i32[] = [1, 2]
    st(l)
    l.push(3)
    print(keep.length)
    // vl check: rc 0.  vl run: invalid module inside `st`: type mismatch

Want:

    3

#### Mechanism

The checker accepted the global assignment with the write state it read, while the emitter's
scalar delivery site read a non-zero state for the same root and declined the copy, leaving the
`i32[]` wrapper in the `i64[]` global: two readers of one analysis disagreeing about a root. A
view is sound under any write state, so the site now builds one for every named root that is not
a fresh unwritten `const`, and declines only where it has no view to build.
