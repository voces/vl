### D2596 — storing a `string | null` value that holds null into a `{[string]: string | null}` map traps

**loads then traps · clause 1 · pre-existing on master `ed81f8d55` · reached by 1 cell of #3175's review grid (named set `rv3175-generic-return-price`) · filed 2026-09-26**

Repro:

    const m: {[string]: string | null} = Map()

    m["k"] = x
    print(m.has("k"))
    // vl check: rc 0.  vl run: wasm trap: null reference at `m["k"] = x`

#### Mechanism

Not located. The write recovers the value to a non-null string before storing it, which
traps when the variable holds null. The literal `m["k"] = null` runs and prints `true`, so the
nullable value slot exists; only the write of a nullable-typed variable recovers. The generic
`f<T>(x: T): {[string]: T} { const m = Map(); m["k"] = x; m }` at `f(B)`, with `B: string | null`
null, was a loud emit reject on master (`unsupported map value type`). #3175 types that `Map()`
at the pin, so it now reaches this trap.
