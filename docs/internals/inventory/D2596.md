**closed 2026-09-26 — the filed repro RUNS and prints `true` · was loads then traps, clause 1 ·

Repro:

    const m: {[string]: string | null} = Map()
    const x: string | null = null
    m["k"] = x
    print(m.has("k"))
    // vl check: rc 0.  vl run: wasm trap: null reference at `m["k"] = x`

#### Mechanism

A `string | null` read recovers a non-null string (`ref.as_non_null`) unless its context says
the destination is nullable (`nulStrReadStaysRaw`: a null test, or a `pendingNulString` seed).
The map store's value context seeded only `nulRefHeap`, which a bare `null` literal reads, so the
literal stored `ref.null` while a variable holding null was recovered and trapped. The close
seeds `nulString` too when the value slot is a nullable string (`emitMapSetValExpr`), the seed
every other nullable-string boundary (binding, assignment, return, argument) already sets. The
`?? default` read of the same map was already raw. The generic `f<T>` at `f(B)` stores through
the same arm.
