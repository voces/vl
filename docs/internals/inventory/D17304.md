### D17304 — an assignment of `null` to a never-filled `let x = null`, as a `null[]` literal's element, is stored as `nullref` in the `i32` cell

**closed 2026-11-24 · runs, prints `null` · was check-clean invalid wasm, clause 1, `type mismatch: expected i32, found nullref` inside `f` · found by IR-N9 grading the captured null-typed call write · filed 2026-11-24 by IR-N9 · fixed by #10016 (IR-N9), under the coordinator's ruling (DECISIONS.md): under a `null[]` destination a list of a never-filled hole is a `null[]` (`nodeArrayElemIsNullUnit`, check_bind_rows.vl; the hole assignment is the sentinel in `emitArrI32` and `idxStoreNullUnitUnstamped`); the un-annotated list is refused at check with `[null]`'s sentence (`flushNullOnlyLits`) · fixtures `arrays/null-list-of-a-never-filled-null-let.vl`, `arrays/error-list-of-a-never-filled-null-let.vl`**

Repro:

    function f() {
      let x = null
      const a: null[] = [x = null]
      print(a[0])
    }
    f()
    // vl run: null  (was: vl check rc 0, vl run invalid module)

Want:

    null

#### Mechanism

A `null[]` cell holds the `i32` sentinel, and a list literal's element is stored at that rep only
when the element classifies as the `null` unit. An assignment into the never-filled hole is typed
at the hole, so the element is written as its `nullref` value.

#### Ablation

| ingredient removed | outcome | needed? |
| --- | --- | --- |
| the assignment, for `[null]` | runs | **yes** |
| `let x = null` for `let x: null = null` | runs | **yes** |
| the annotation `: null[]` | still invalid | no |
| the function (module scope), or a module global written in a function | still invalid | no |
| `null` for a `null`-returning call | still invalid | no |
| the list literal, for an index store `a[0] = (x = null)` | still invalid | no |
| the assignment, for a plain read `[x]`, unannotated | still invalid | no |

same list's `[x][0]` printed `2` where `null` is wanted.

- The un-annotated spellings, `const a = [x]` and `const a = [x = null]` over a never-filled hole: a
  list of only the hole's `null`, which `[null]` refuses at check time. Treating the hole's list as
  `null[]` on the store alone made `[x = null]` print `2`, so the read side must agree.
