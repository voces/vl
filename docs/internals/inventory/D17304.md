**fixed 2026-11-24 · closed, runs `null` · was: check-clean invalid wasm · clause 1 · `type mismatch: expected i32, found nullref` inside `f` · found by IR-N9 grading the captured null-typed call write · filed 2026-11-24 by IR-N9 · fixed by #10016 (IR-N9), under the coordinator's ruling (DECISIONS.md): under a `null[]` destination a list of a never-filled hole is a `null[]` (`nodeArrayElemIsNullUnit`, check_bind_rows.vl; the hole assignment is the sentinel in `emitArrI32` and `idxStoreNullUnitUnstamped`), and un-annotated it is now a loud check reject, `[null]`'s refusal (`flushNullOnlyLits`) · fixtures `arrays/null-list-of-a-never-filled-null-let.vl`, `arrays/error-list-of-a-never-filled-null-let.vl`**

Repro:

    function f() {
      let x = null

    // vl check: rc 0.  vl run: invalid module.

Want:

#### Mechanism

A `null[]` cell holds the `i32` sentinel, and a list literal's element is stored at that rep only
when the element classifies as the `null` unit. An assignment into the never-filled hole is typed
at the hole, so the element is written as its `nullref` value.
