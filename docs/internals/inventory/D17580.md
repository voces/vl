### D17580 — a spread copy of a list holding a generic function, built as a record field in a generic instance, keeps the source's closure signature, so the second instance's call through it traps

**closed 2026-11-25 by SOUND · runs, prints `4` `u` · was trap after load, clause 1, `indirect call type mismatch` in the second instance · mono's flow rewrite (`monoFlowSpreadSet`, emit_mono.vl) expanded the spread into minted reads of `id` once, in the template's host literal, after the instance clones were made; the host held no generic read of its own, so both instances shared it and the minted read took the first instance's closure. A host in a generic function's body now keeps its spread, a copy each instance builds from its own list (`monoFlowSpreadSet`) · pinned by `tests/cases/generics/spread-of-generic-fn-list-in-generic-instances.vl` · found by COV-CLOS's Q58 spread sweep · filed 2026-11-25 against master `7aacbeac`**

Repro:

    function id<T>(x: T): T { return x }
    function pField<T>(x: T) {
      const src = [id]
      const r: { fs: ((x: T) => T)[] } = { fs: [...src] }
      print(r.fs[0](x))
    }
    pField(4)
    pField("u")
    // vl run: 4 u  (was: prints 4, then wasm trap: indirect call type mismatch)

Want:

    4
    u

#### Mechanism

The record field's spread literal is a copy of `src`, a list holding `id`. In the second instance
(`T = string`) the copy's element is still `id`'s closure at the first instance's signature, so the
call through `r.fs[0]` takes the wrong `call_indirect` type. The same program built claimless traps
identically, so the IR's claim does not cause it. Not ablated into the emitter further.
