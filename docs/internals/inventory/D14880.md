### D14880 — an un-annotated lambda literal called only through a function's result is refused at check, while the same lambda bound to a `const` first runs

**loud check reject · clause 2 · `cannot infer a type for parameter `x`` · pre-existing, the same on master `484e98dd8` · found by the mono rung B position grid · filed 2026-11-01 against master `484e98dd8`**

Repro:

    function fw(f) { return f }
    const q = fw((x) => x)
    print(q(3))

Want:

    3

#### Mechanism

The literal's parameter type comes only from the calls through `fw`'s result (`q(3)`), never
from a call of the literal itself or from a delivery to a declared function type. Bound to a
`const` first, the same lambda is a hole lambda whose calls through the binding type it, and mono's
flow pin (`monoOpenFnFlowPin`) lowers it. Inline, the checker asks the literal's parameter for a
type at the literal and refuses there.

#### Ablation

| ingredient changed | outcome | needed? |
| --- | --- | --- |
| `const lam = (x) => x`, then `fw(lam)` | runs, prints `3` | **yes** (the literal inline) |
| `function ap(h) { return h(3) }`, `ap((x) => x)` (called inside the callee) | runs | **yes** (called only through the result) |
| `function fw<F>(f: F): F` | refuses the same | no |
| `print(fw((x) => x)(3))` (called inline) | refuses the same | no |
| `function mk() { return (x) => x }`, `mk()(3)` | refuses the same | no (a returned literal is the same position) |
