### D6241 — two bindings of `fw(lam)`, one per type, are refused at `fw`'s argument

**closed 2026-10-17 by lane L1 · runs, prints `3 w` · was loud emit reject · clause 2 · a `const` lambda handed through identities into bindings that call it at more than one type between them is asked as a whole, and each binding's identity read is keyed by the one type its own reads call it at (or its annotated function type), so the lambda takes a slot per binding type · pins: `tests/cases/functions/hole-lambda-identity-bindings-one-per-type.vl` (three bindings, a capturing lambda inside a function, annotated destinations), `tests/cases/functions/hole-lambda-identity-bindings-two-identities.vl` (two identities, two parameters, a direct call beside the identity) and the `hole-lambda-identity-bindings-one-per-type` matrix · five or more independent splits in one program are [D6262](D6262.md) · found closing [D6201](D6201.md) · the same on master `dfcac226b` · filed 2026-10-17 against master `dfcac226b`**

Repro:

    function fw(f) { return f }
    const lam = (x) => x
    const q = fw(lam)
    const r = fw(lam)
    print(q(3))
    print(r("w"))
    // vl check: rc 0.  vl run: emitProgram: monomorphize: unsupported argument type for `f` in a call to `fw`

Want:

    3
    w

#### Mechanism

From the ablation only. D6201's close gives ONE binding of `fw(lam)` a slot per type, each
holding a copy of the lambda. With two bindings each is called at one type, so neither is
split, and `fw` is instanced once with the lambda pinned at one type for both reads.
