### D16912 — a lambda returning a list literal, at a list result whose element union holds a list-of-records arm, is refused at check

**closed 2026-11-17 · runs, prints `1` · was loud check reject, `a function of type () => f64[] cannot be used as () => ({a: i32}[] | f64)[] here` · clause 2 · fixed in check_inferred_return.vl: `inferRetAdoptUnionElemList` gains a last rung, any list whose element is a union with no type variable or hole left, adopted when the tail literal is assignable to it; the named rungs before it, [D16905](D16905.md)'s function-arm one among them, each take one element shape and a list-of-records arm matched none · pin: `tests/cases/closures/lambda-list-literal-into-record-list-arm-result.vl` · found by the rep fuzzer's declared leg, seed 59198629 cases 331 and 332 · filed 2026-11-17 against master `005926c63`**

Repro:

    const v: () => ({a: i32}[] | f64)[] = () => [1.5]
    print(v().length)
    // vl check: rc 0.  vl run: prints 1

Want:

    1

#### Mechanism

The lambda's result is inferred from its list literal alone, `f64[]`, unless a rung of
`inferRetAdoptUnionElemList` (check_inferred_return.vl) adopts the contextual result. Each rung
names one element shape (value union, variant box, map union, function arm and so on), a
list-of-records arm matched none, and a list never widens, so the conversion was refused.
