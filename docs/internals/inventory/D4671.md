### D4671 — a heap slot of the `null` unit type (struct field, list element, map value) has no storage rep

**closed — a `null`-typed struct field is a `nullref` slot, and a `null` list element or map value rides the i32 list and map with a sentinel, so every read is statically `null`; `filled(n, null)`, a generic `T[]` instance at `T = null` (D4687) and a tail-position `self[0] = v` in one follow the same rep · graded by `scripts/capability-probes/matrix/null-unit.matrix.vl` (61 of 66 position×face cells run, 46 before, 0 silent; the 5 left are the un-annotated `[null]` refusal of owner ruling Q3 and the un-annotated all-null map refusal of D2506) and `tests/cases/types/null-unit-heap-positions.vl` · filed 2026-10-14 against master `1c1740512`**

#### Mechanism

D4550 gave a `null`-typed LOCAL, parameter, return and global the `nulnone` cell (`nullref`),
but every heap slot chooses its storage from a field/element/value rep table that has no
`nulnone` row: the struct-field rep refuses by name, the list element ladder falls to
`only i32[] arrays and struct/union element arrays are supported` (a `null[]` push), and the
map value interner to `unsupported map value type`. A list literal of only `null` is refused
earlier, by the checker (`a list of only \`null\` has no element type; annotate it`) — even
when it IS annotated `null[]`, so the refusal's own advice does not work there.
