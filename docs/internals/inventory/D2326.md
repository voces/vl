### D2326 — a value-union local's member set resolves to a DIFFERENT sibling block's binding of the same name, in the narrowing complement's field access

**loud emit reject · filed 2026-09-24 against master ac25508bd, D2325's own branch — found
while auditing the union-narrowing ladder for the D2325 class of bug.**

`unionNameOfIdentSid`, `unionDeclTyIxOfIdentSid` and `startBlockLetRowOfSid` (all in
`compiler/emit_classify.vl`/`emit_base.vl`) resolve "which value union does a name denote"
through `parentLetOfSid` — the UNPOSITIONED primitive D2316 built `parentLetOfAt` beside,
precisely because `parentLetOfSid` collapses two sibling blocks binding one name onto
whichever the scan visits first. Unlike D2325's ladder (`calleeCloSigKeyAt`), none of these
three callers were repositioned in that fix; `unionNameOfIdentSid` does not even take a
position argument.

Repro:

    type A = { x: i32 }
    type B = { y: string }
    type C = { z: boolean }

    function f(): string {
      let out = ""
      {
        const u: A | B = { x: 5 }
        if u is A { out = "\{u.x}" } else { out = "\{u.y}" }
      }
      {
        const u: C | B = { z: true }
        if u is C { out = out + "|inner" } else { out = out + "|\{u.y}" }
      }
      out
    }
    print(f())
    // vl check: rc 0.  vl run: emit error at the inner else-arm's `u.y`:
    //   emitProgram: field access receiver is not a struct

#### Mechanism

The `else`-arm of `if u is T { … } else { … }` reads the narrowing COMPLEMENT: the receiver's
member set minus `T`. Building that complement needs the receiver's CURRENT union name, read
through `unionNameOfIdentSid`. For the second (inner) block's `u`, that lookup runs
`parentLetOfSid(fn.fnBody, sid("u"))`, which returns whichever `const u` the scan recorded
FIRST — the outer block's `A | B`, not the inner block's `C | B` — regardless of which block
the `else` arm actually sits in. The complement of `A | B` minus `C` is nonsensical (`C` is
not even a member), so the field-access lowering for the survivor member (`B`, but keyed
against the WRONG union's layout) fails with "field access receiver is not a struct" rather
than reading `u.y` off the inner binding.

No parameter is needed — this reproduces with two ordinary sibling blocks, the same shape
D2316 already fixed for the closure-signature ladder. The union ladder was simply never
threaded through `parentLetOfAt` when D2316 landed.

#### Ablation

| ingredient removed | outcome | needed? |
| --- | --- | --- |
| the inner `else` arm's `u.y` field read (kept only the `is`-boolean tests) | runs, `5\|inner` | **yes** |
| a closure-typed parameter of the same name (`union-min.vl`: param `u: i32 \| string`, inner block `u: boolean \| string`) | also emit-rejects the same way — the param path shares the mechanism but is not required to reproduce it | no |

#### Grading list

NOT fixed in this PR — filed for scope reasons, not because a fix is unclear. `paramCloSigKey`
et al. had only three call sites and one caller each; `unionNameOfIdent`/`unionNameOfIdentSid`
have roughly thirty call sites across `emit_classify.vl` and `wasmEmit.vl`, most without a
convenient node to hand in as a position, and `unionDeclTyIxOfIdentSid`/
`startBlockLetRowOfSid` are separate primitives with their own callers. Closing this properly
means: give `unionNameOfIdentSid`/`unionDeclTyIxOfIdentSid` an `*At` sibling exactly as
D2316/D2325 did for the closure ladder, thread a real position through every call site that
has one, and decide what an unpositioned caller (there may legitimately be some) should keep
doing.
