### D3341 — a local a function hands to another place and then returns is delivered as fresh into a wider record

**closed by design · now a loud check reject · was check-clean invalid wasm on master `2b30e3674` (and an emit refusal on the first #3312 candidate) · a returned local that is also passed, stored or put in a literal is shared, so the call is judged by its type, not as fresh · fixture `tests/cases/soundness/error-record-not-fresh-through-coalesce-call-or-escape.vl` · found by the #3312 review · filed and closed 2026-09-30**

Repro:

    type J = { f: i32 | null }
    const keep: { f: i32 }[] = []
    function mk() {
      const s = { f: 4 }
      keep.push(s)
      s
    }
    const b: J = mk()
    print(b.f ?? 77)
    print(keep[0].f + 1)
    // vl check: rc 0.  vl run: invalid module, "expected (ref null $type), found (ref $type)"

#### Mechanism

A function with no declared result that returns only literals is fresh (DECISIONS.md "Record
covariance: only a fresh value widens"), but `s` is also pushed into `keep`, so the record the
call returns is one `keep` shares at `{ f: i32 }`. Widening it would let a write through `J`
break `keep[0]`. `recLeafEscapes` treats a returned local that has an argument, store, element,
field, binding or spread use as existing.

#### Ablation

| ingredient removed | outcome | needed? |
| --- | --- | --- |
| `keep.push(s)` | still invalid wasm on master and here: `keep`'s annotation declares a record of the literal's own fields, D3338's mechanism | no |
| `keep` and its push | runs, prints `4` | **yes** |
| the delivery (`const b = mk()`) | runs | **yes** |

#### Close (2026-09-30)

Refused as an existing record: the message names both fixes, declaring `mk`'s result as `J` or
copying with an object literal.
