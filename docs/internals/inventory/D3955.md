### D3955 — a captured, never-written hole-lambda `let` in a generic body prints the first instance's value at a second instance that shares its representation

**closed 2026-10-18 by lane L1 · runs, prints `L 1 L true` · was check-clean silently wrong · `vl check` rc 0 · clause 1 · the never-written `let` is spelled `const` before the split plans and the monomorphizer read it ([D6472](D6472.md)), so the lambda it holds is instanced per instance of `a` rather than lifted once; the grading list's `a("s")` runs too (master: check-clean invalid wasm) · pins: `tests/cases/generics/unwritten-hole-lambda-let-captured-in-generic-at-three-instances.vl` · found in review of #3498 (`rv3498/round4/e24`) · filed 2026-10-10 against master `429e7b093`**

Repro:

    function a<T>(x: T) {
      let k = (u) => { print("L"); print(u) }
      const rd = () => { k(x) }
      rd()
    }
    a(1)
    a(true)
    // vl check: rc 0.  vl run: prints L 1 L 1

Want:

    L
    1
    L
    true

#### Mechanism

Not located. The hole lambda that seeds `k` names no `T`, so it is lifted once for both
instances of `a`; the call through the closure `rd` pins it at the first instance's `i32`, and
the `boolean` instance, which shares that representation, calls the same body. Nothing writes
`k`, so the capture cell's one-signature check (D3939) never runs.
