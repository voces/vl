### D3249 — a read of a hole's field after a write in an `is` arm is refused at emit, where the checker refused it on master

**loud emit reject · clause 2 · open · introduced by #3289 (D3197's `holePlaceFieldTy` arm in `placeFieldTy`); a loud check reject on master `d48a56b17` · found by the #3289 final review (`rv3289f-32528`: 39 `gd` and 60 `gm` cells, among them `gd/c00201_wr_notA_s_hole` and the `is`-chain `.length` shape) · filed 2026-09-29 against master `d48a56b17`**

Repro:

    type A = { v: i32 }
    type B = { s: string }
    function F(z) {
      if !(z.h is A) { print("then") } else { z.h = { v: 9 }
        print(z.h.s) }
    }
    const x: { h: A } = { h: { v: 3 } }
    F(x)
    // vl run: emitProgram: unknown struct field in field access

#### Mechanism

Not localised past the ablation. On master `placeFieldTy` answers -1 for a hole receiver, so the
write `z.h = { v: 9 }` narrows the path to the written record and the checker refuses `z.h.s`
as `no field 's' on A`, the annotated spelling's words. #3289 lets `placeFieldTy` read a hole's
field (`holePlaceFieldTy`, which D3197 needs for a null test to narrow a function field), so the
store type is now the field's own hole, the write no longer narrows the path to the record,
and the read reaches the emitter. The program is refused either way and no run is lost; the
checker owes the refusal.
