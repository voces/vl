### D17666 — D17665's list one record level down (`[{ r: { f: inc0 }, s: { f: dbl } }]`) still builds an invalid module, and the IR cannot lower the field read it would build

**check-clean invalid wasm · filed 2026-11-26 against D17665's close (lane COV-START)**

Repro:

    function inc0(a) { return a + 1 }
    function dbl(a) { return a * 2 }
    const xs = [{ r: { f: inc0 }, s: { f: dbl } }]
    print(xs[0].r.f(6))
    // vl check: rc 0.  vl run: invalid module, type mismatch: expected (ref null $type), found (ref $type)

#### Mechanism

The element's inner literal `{ f: inc0 }` is laid out at one struct row (row 0, `f` as the set's
id), while the outer row's field `r` targets another row (row 1, `f` as a closure), and the outer
row's own kid for `r` is a third record rep. Legacy writes the inner struct where the outer field
wants the targeted one. Building the inner literal at the outer field's rep, with `f` as the
closure, moves the IR past the build. It then meets the read `xs[0].r.f`: legacy records no struct
field arm for `.f` on that receiver, and the IR lowering reads the field's index off legacy's arm
(`getField` → `fieldIdxAt`), so it misses `field shape`. Closing it needs a struct type for the
targeted rep and a field read lowered by the rep, not by legacy's arm.
