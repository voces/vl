### D15178 — a generic parameter's pin re-derives the record a fresh call is rebuilt at instead of reading the elaboration

**runs today and must keep running · structural: `idn<T>` handed `mkB(false)`, an inferred-result function with two record returns that `const n: J = …` rebuilds at `J` (D8020), is pinned by mono at `J` through `monoRebuiltLitRetName` (`recRebuiltRetRow`), a second derivation beside the elaboration's own call binding; with that rung removed the program is check-clean invalid wasm (`expected (ref $1), found (ref $0)`, `{r:i32,g:i32}` against `J`) · found closing [D15173](D15173.md), whose hole path stopped reaching the rung · filed 2026-11-04 against master `e394c738d`**

Repro:

    type J = { r: i32 | null, g: i32 }
    function idn<T>(v: T): T { v }
    function mkB(b: boolean) {
      if b { return { r: 16, g: 1 } }
      { r: 17, g: 2 }
    }
    const n: J = idn(mkB(false))
    print(n.r ?? 0)

Want:

    17

#### Mechanism

`monoArgTyNameBound` (emit_mono.vl) pins a call argument whose callee has no return annotation at `monoRebuiltLitRetName(callee)`, the row `recRebuiltRetRow` says the callee's literals are built at, before it asks the checker's inferred return. That re-derives a fact the checker already records for the call, and the elaboration's call binding takes the rebuilt row for a type parameter since #6105. A hole parameter handed the same call reads the elaboration's `#r.<param>` entry since D15173 and no longer reaches the rung. A single-return `mk()` builds without the rung, so the two-leaf return is the ingredient this witness needs.
