### D15178 — a generic parameter's pin re-derives the record a fresh call is rebuilt at instead of reading the elaboration

#### Mechanism

`monoArgTyNameBound` (emit_mono.vl) pins a call argument whose callee has no return annotation at `monoRebuiltLitRetName(callee)`, the row `recRebuiltRetRow` says the callee's literals are built at, before it asks the checker's inferred return. That re-derives a fact the checker already records for the call, and the elaboration's call binding takes the rebuilt row for a type parameter since #6105. A hole parameter handed the same call reads the elaboration's `#r.<param>` entry since D15173 and no longer reaches the rung. The elaboration's binding comes from `recRebuiltLeafRow` (check_bind_adopt.vl), whose call arm answers only an argument-free call: for `idn(mk())` it binds `T=J` and the program builds without the rung, for `idn(mk(false))` it binds `T={r: i32, g: i32}`. The callee's argument is the ingredient; a two-return `mkB()` with no argument builds without the rung.
