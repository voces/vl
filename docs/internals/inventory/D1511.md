### D1511 — an INFERRED-empty list pushed struct literals got no ref-list ROW, because a row is minted from a `<shape>[]` SPELLING and this program contains none

**closed 2026-09-03 by giving `collectA`'s empty-literal arm the SHAPE sibling its union and
nested-array arms already had (`arrLitShapeElemName`) · was `emitProgram: field access receiver
is not a struct` at every read and `type mismatch: expected i32, found (ref $type)` with no read
at all, on a `vl check`-clean program · clause 2 at the read, clause 1 at the bare push · the
position matrix goes **25 of 40 → 37 of 40 runs, 0 silent, 0 `runs` lost** · reported by the
glean session as VL-017, `~/glean/docs/vl-issues.md`**

Repro (runs, prints `1`):

    const xs = []
    xs.push({ y: 1, x: 2 })
    print(xs[0].y)
    // was: vl check rc 0, then
    //   emitProgram: field access receiver is not a struct

And the same defect with NO read, which is the clause-1 half (runs, prints nothing):

    const xs = []
    xs.push({ y: 1, x: 2 })
    // was: vl check rc 0, then
    //   Invalid input WebAssembly code: type mismatch: expected i32, found (ref $type)

#### Mechanism

**BOTH REPS, OFF THE BYTES** (`wasm-dis`, binaryen 130, on the two-line witness). The ANNOTATED
spelling `const xs: P[] = []` gives the binding `(struct (mut (ref $5)) (mut i32) (mut i32))`
over `$5 = (array (mut (ref null $0)))` — the ref-list wrapper at the element's own slot, with
`$0` the `{y, x}` struct. The INFERRED spelling gave it `(struct (mut (ref $1)) …)` over
`$1 = (array (mut i32))` — the **i32-list default**, and neither the ref-list backing nor its
wrapper existed anywhere in the module. That is the whole disagreement: the checker had the
element type (it accepted `.y`), and the emitter's read site consulted a wrapper that could not
hold a struct.

**IT IS "NO ROW", NOT "A ROW THE READ SITE CANNOT REACH."** Measured with an `emitFail` probe
inside `synthEmptyListAnn`, on the witness: `synElem={y: i32, x: i32}` — the render —
`nom=#anon0` — the NOMINAL row, which `collectAnonShapes` had already minted and
`arrElemNominalOfTy` resolved correctly — and `rlSlot=-1`. The reverse map answered; the
ref-list row it names did not exist. The A/B is one line: add `function f(a: P[]) {}` anywhere
in the module and the identical un-annotated program runs, because that spelling mints the row.

`collectA` re-mints every ref-list row from a linear arena walk, and it learns about an element
from an array SPELLING (the `TypeRef` arm) or from a non-empty array LITERAL (`arrLitIsRef`,
which declines an empty literal by construction — it has no element to classify). An inferred
empty `[]` has neither. The arm already carried two rescues for exactly this — a registered
UNION element and a nested-ARRAY element — and had no SHAPE one. `synthEmptyListAnn` then
synthesized the right `#anon0[]` annotation over a slot that does not exist, and
`recordAnnRlSlot` banked `-1`: every downstream classifier fell back to the i32 list.

The fix mints the row where its two siblings do, keyed on `shapeNominalOfTy` — the SAME
producer `synthEmptyListAnn` spells its annotation with — so the intern and the resolve cannot
land on different rows. Proof that they do not: the inferred spelling's module on the candidate
is **byte-identical** to the annotated spelling's module on master.

#### Ablation

| ingredient removed | outcome | needed? |
| --- | --- | --- |
| the empty literal (`[{y: 1, x: 2}]` instead) | runs | **yes** |
| the struct element (`push(1)` instead) | runs | **yes** |
| the binding being un-annotated (`const xs: P[] = []`) | runs | **yes** |
| any `<shape>[]` spelling elsewhere (`function f(a: P[]) {}`) | runs | **yes** |
| a `type P` declaration that is never spelled `P[]` | still refuses (`ref valtype with no interned shape`) | no |
| the READ (`print(xs[0].y)`) | still invalid wasm, check-clean | no |
| the read's POSITION (bound / `for`-in / in a function / captured) | refuses at all four | no |

The last two rows are why the message is not the family: with a read it is a loud clause-2
refusal, without one it is a silent clause-1 module, and the four read spellings the consumer
reported are one mechanism wearing one sentence.
