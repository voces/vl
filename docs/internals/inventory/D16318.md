### D16318 — a constant shift-count tree beside an unfolded constant operand skips the count's range check, so the count is masked at run time

**closed 2026-11-15 · now a loud check reject: `shift count 41 is out of range for an i32 operand (0 to 31)`, the refusal E6.2 owes · was check-clean silently wrong (`8388607`) · closed by D16375's `cexFoldOperands` (`check_fit_rules.vl`): the count tree beside an unfolded constant operand folds, so the range check reads it; its radix spellings, where that fold declines (`0xFFFFFFFF >> (40 + 1)`, `0x80000000 << (16 + 16)`, `0xFFFFFFFF >> (32 + 32)` at i64), by lane N's count rule: `checkShiftCounts` grades any count `cexEvalAt` evaluates, by its exact value, whether or not the fold reduced it · pins: `tests/cases/bitwise/error-shift-count-tree-beside-constant.vl` · bucket (f) · found by the 2026-11-15 oracle-fuzz triage (`ar_s21_0127`) · filed 2026-11-15 against master `3d526470a`, closed against master `83a90988d`**

Repro:

    print((-3) >>> (40 + 1))
    // was: PRINTS 8388607; now refused at check

#### Mechanism

`>>>` of a negative constant depends on the width it runs at, so the fold leaves the tree
whole and it computes at its destination. A count past the operand's width is refused when it is
written (`(-3) >>> 41`), when it is a `const` name, and when it is a tree beside an operand that
is not a constant (`x >>> (20 + 20)`, D2725). Beside an operand that is a constant left
unfolded, a tree count is never graded, so it reaches wasm, which masks it to the low five bits:
`(-3) >>> (40 + 1)` shifts by 9, and `(-3) >>> (16 + 16)` by 0, printing `-3`. The design
refuses all of these as `shift count N is out of range` (DECISIONS.md, "Exact constant
arithmetic").

#### Ablation

| spelling | outcome |
| --- | --- |
| the witness | check-clean, prints `8388607` (count 41 masked to 9) |
| `(-3) >>> 41` | refused: `shift count 41 is out of range for an i32` |
| `const K = 41` then `(-3) >>> K` | refused |
| `let x: i32 = 5` then `x >>> (20 + 20)` | refused (D2725) |
| `(-3) >>> (16 + 16)` | check-clean, prints `-3` (count 32 masked to 0) |
| `(~2) >>> (40 + 1)` | check-clean, prints `8388607` |
| `3 >>> (40 + 1)` | runs, prints `0` (a positive operand folds exactly) |
| `(-3) >>> (1 + 1)` | runs, prints `1073741823` (count in range) |
| `function f0(): i32 { ((-3) >>> (1_000 + 2147483647)) }` (the fuzz witness) | check-clean, prints `33554431` |

#### Grading list

- Every shift operator over an unfolded constant operand (`>>>` of a negative constant, `>>` or
  `~` over a radix pattern whose top bit is set) with a tree count past the width.
