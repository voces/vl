### D15041 — a numeric join inside a generic instance whose narrow use is the enclosing type parameter is refused

**loud check reject · clause 2 (pending: the template types the call at its parameter) · the residue of [D2459](D2459.md)'s close · filed 2026-11-02 against master `4e73b063`, pre-existing**

Repro:

    function mix<T>(a: T, b: T): T[] { [a, b] }
    function w2<U>(u: U, v: f64) { return mix(u, v)[0] / 4.0 }
    const one: i32 = 1
    print(w2(one, 0.5))
    // vl check: rc 1: argument 2: expected i32, got f64 (raised by the instance's re-check)

#### Mechanism

The template checks `mix(u, v)` with `u: U`, which is not a number, so no join is asked and the
call is typed `U`; `w2`'s result follows it. The instance `w2<i32>` re-checks the call with
`u: i32`, where D2459's ruling would join `T` at `f64`. Joining there alone hands back `f64`
from a call the template typed `U`, which built invalid wasm when tried, so an instance joins
only a call its template joined, and this one keeps the first-use refusal it had before.

#### Ablation

| ingredient changed | outcome | needed? |
| --- | --- | --- |
| `u: i32` instead of `u: U` | runs, prints `0.25` | the type parameter: **yes** |
| `mix(v, u)` | runs, prints `0.125` | the order: **yes** |
| the call at module scope | runs | the generic body: **yes** |

#### Grading list

The callback twin, `function w<U>(u: U) { return f(u, (i) => i * 1.5) }` with
`f<T>(x: T, g: (i32) => T)`, refuses the same way.
