### D15559 — a returned record binding beside a record of another set, that is also passed to a call, compiles to invalid wasm

**closed 2026-11-08 — the filed repro prints `20`, `6`, `20`, `4` · was check-clean invalid wasm, clause 1 · the checker types every returned record leaf of an un-annotated function, a `const` or never-reassigned `let` of a record literal or a record literal itself, at one record whose function fields carry the union of every leaf's named functions (`elabRetRecTy`, check_elab_cap.vl), so a call, a closure or a `let` reading the binding reads the result's type · a binding of a call result is [D15560](D15560.md) · fixture `tests/cases/closures/returned-record-binding-read-elsewhere-takes-the-joined-set-runs.vl` · found closing [D15557](D15557.md) · filed 2026-11-08 against master `2fce5a50`**

Repro:

    function inc0(a) { return a + 1 }
    function dbl(a) { return a * 2 }
    function use(r) { return r.fs[0](10) }
    function pick(b) {
      const c = { fs: [dbl] }
      print(use(c))
      const a = { fs: [inc0] }
      if b { return a }
      return c
    }
    print(pick(false).fs[0](3))
    print(pick(true).fs[0](3))

Want:

    20
    6
    20
    4

#### Mechanism

The two records' rows differ only by function set. D15557 holds a returned binding at the result row, but `use`'s instance is pinned at the binding's own type, so its parameter is the other row. The binding's type, not its row, has to name the joined set.
