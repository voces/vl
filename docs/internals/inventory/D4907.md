### D4907 — a `for` over a box union's `K[]` arm, `K` a string literal union, finds no ref-list row

**loud emit reject · clause 2 · found closing D4902 · the same refusal on master before D4902's close · filed 2026-10-15 against master `0e1ea34b1`**

Repro:

    type K = "x" | "y"
    function main() {
      const g: f64 | K[] = ["y", "x"]
      if g is K[] { for k in g { print(k) } }
    }
    main()
    // vl check: rc 0.  vl run: emitProgram: a ref list's element row does not resolve

Want:

    y
    x

#### Mechanism

Not yet located. The narrowed `g` is the `K[]` arm, an `i32`-backed list of atom ids, and an
index read `g[0]` on it runs; the `for` lowering asks for a ref-list element row instead, which
a list of atoms never interns.

#### Ablation

| ingredient changed | outcome | needed? |
| --- | --- | --- |
| `g: K[] \| null` (a niche, no box) | prints `y` and `x` | **yes** (a box union) |
| `g: i32[] \| string`, `[3, 4]` | prints `3` and `4` | **yes** (a literal-union element) |
| `print(g[1])` in place of the `for` | prints `x` | **yes** (the `for`) |
| `f64[]` in place of `f64` | same refusal | no |

#### Grading list

The module-scope spelling (`const g` at the top level, the `for` in `main`), and `for i, k in g`.
