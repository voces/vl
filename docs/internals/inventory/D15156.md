### D15156 — two type-based producers code a record field: the declared side and the anonymous/arm side

**runs today and must keep running · structural: the declared-record producer `fieldCodeOfRecField` and the anonymous/arm-row producer `nameFieldCodeTy` still code one field type two ways · filed 2026-11-03 against master `2bb36ff5c` by lane column-G1**

Repro:

    type C = { kind: "c", r: i32 }
    function f(x: { kind: "c", r: i32 }) { print(x.r) }
    const a: C = { kind: "c", r: 1 }
    f(a)
    f({ kind: "c", r: 2 })
    print(a.kind)

Want:

    1
    2
    c

#### Mechanism

`collectS` codes a declared record's field with `fieldCodeOfRecField` (`compiler/emit_rec_field_codes.vl`),
from the record type's own field type. Anonymous literal rows and union arm rows still code
theirs with `nameFieldCodeTy`, which is what `fieldCodeOfRecField` falls back to after the
rules it adds. Measured 2026-11-03 over the declared fields of `tests/cases` and the distilled
corpus, `nameFieldCodeTy` alone disagrees with the declared code on 356 fields in five families:

| family | declared | `nameFieldCodeTy` | fields |
| --- | --- | --- | --- |
| A, a single string literal (`kind: "c"`) | 0, the atom | 3, a string | 296 |
| B, an inline-shape or nullable record field | 15 | -1 | 55 |
| C, a generic application (`Box<i32>`) | 15 | -1 | 2 |
| D, an `i32` list behind `\| null` | 18 | -1 | 1 |
| E, a list of integer literals (`(0 \| 1)[]`) | 4 | 5, a ref list | 2 |

In B, C and D `nameFieldCodeTy` declines where `fieldCodeOfRecField` answers; A and E are
divergences, and moving the anonymous/arm side onto `fieldCodeOfRecField` moves every row they
reach. The price
of that move is family A's atom-versus-string split, to be measured as byte movers by the
change that makes it.

#### Grading list

The witness, which passes a declared `C` and a literal to an inline-shape parameter; the
field-code dump (`rowDumpBuild`'s `codes=` column) over `tests/cases` and the corpus.
