### D15156 — a record field codes as a struct before its row exists only on the declared side, so one field-code rule stays outside the shared producer

**closed 2026-11-03 by lane column-G1 · runs today and must keep running · `fieldCodeOfRecField` is retired: every row codes its fields with `nameFieldCodeTy`, and a record field codes as a struct before its row exists only when the record is closed · filed 2026-11-03 against master `2bb36ff5c` by lane column-G1, narrowed 2026-11-03 against master `879370c3e`**

Repro:

    function f<T>(v: T): i32 {
      const r: { a: { b: { c: T } } } = { a: { b: { c: v } } }
      1
    }
    print(f(1))

Want:

    1

#### Fix

The rule is decided by the type after all: a record with no hole and no type parameter in it
can have a row, so a field of it codes 15 whether or not the row exists yet, which is what the
declared side needs; a record over a hole (`{m: {[string]: (_) => _}}`) or a type parameter
(`{c: T}`) can never have one, so it declines, which is what the anonymous side needs. Every
declaration, generic instance and inline shape the declared side forward-references is closed.
`nameFieldCodeTy` takes the rule for every row and `collectS` calls it directly.

#### Mechanism

The declared side and the anonymous/arm side code a field through one producer,
`nameFieldCodeTy` (`compiler/emit_shape_intern.vl`), except for one rule: a field whose type
is a record, or a nullable record, codes 15. The two sides appeared to need different facts
for it, a split by the caller's phase, until the failing records turned out all to be open:

* **the declared side needs "a row is owed".** `collectS` codes a declaration before the record
  it names has a row: a later declaration, or a generic instance (`type Holder = { c: Box<i32> }`)
  that `gaeEnsure` mints after `collectS`'s loop. Without the rule the field refuses with
  `struct field type `Box<i32>` has no struct-field rep`.
* **the anonymous side needs "a row exists now".** A nested shape interned in
  `collectNestedFieldShapes`, before `collectS`, declines on -1 so its caller interns the nested
  record and asks again. With the rule it codes 15 with no row behind it, and the compile fails
  with `nested-struct field element type is not interned`.

Gating the rule on collectS's declared-record set, or on a row existing, breaks one side or the
other (measured 2026-11-03), and so does keeping the rule ungated and having the anonymous
callers materialize the nested row: a record over a hole is interned with a struct field that
points at nothing.

The other rules the declared side once added (a lone string literal is its atom, an `i32` list
behind `| null` is 18, a list of integer literals the `i32` list) moved into `nameFieldCodeTy` at
0 byte movers over `tests/**` and the distilled corpus.
