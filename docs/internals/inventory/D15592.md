**closed 2026-11-09 · runs, prints `7`, `x` · was loud emit reject, clause 2, `vl check` rc 0, then `emitProgram: a generic function taken as a value reaches no call that fixes its type` · closed in emit_elab.vl: a recorded hand-on call (`elabHandedNote`, D15105) was built only under an instance one call away from the one making it, so a forwarder's instance, off the nested generic's encloser chain, dropped it; `elabHandedAt` now re-records the entry at the forwarder, where its own callers hand it on · fixture `generics/capturing-nested-generic-handed-on-through-forwarder.vl` · D15105's neighbour · filed 2026-11-09 against master `f75d1327`**

Repro:

    function mid<F>(a: F) {
      print(a("x"))
    }
    function fwd<G>(g: G) {
      mid(g)
    }
    function outer<U>(u: U) {
      function same<T>(k: T): T {
        print(u)
        k
      }
      fwd(same)
    }
    outer(7)

Want:

    7
    x

#### Mechanism

`a("x")` in `mid`'s instance runs `same` directly, from an instance whose chain does not hold
`outer`, so D15105 records the call and builds it under each instance whose call hands `mid`'s
instance the value. Here that is `fwd`'s instance, which is not on `same`'s encloser chain
either (`elabParentFor` < 0), so the entry was dropped and `same` got no key.
