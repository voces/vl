### D16002 — two records whose list fields hold one union through a nested layer keep two canonical struct rows

**closed 2026-11-13 — the witness runs `3` with one canonical row for the two records · a nested union layer is flattened, and union members are compared as a set, when two rows compare function sets · filed 2026-11-13 against master `681e8615d`**

Repro:

    type IS = i32 | string
    type U = IS | f64
    type W = i32 | string | f64
    type R1 = { u: U[] }
    type R2 = { u: W[] }
    function count(r: R2) { r.u.length }
    const r1: R1 = { u: [1, "q", 2.5] }
    print(count(r1))
    // vl run: 3. Before the close, R1 and R2, one type on one heap (D15952), kept two
    // canonical struct rows: sRowCanonOf did not fold them.

Want:

    3

#### Mechanism

`sRowsTwin` folds two rows when, among other checks, each field's element rep agrees
(`sRowElemRepSame`). That asks `tySame` and then `fnSetsAgree`, which walks the function sets
through a union's members by position. `U = IS | f64` lists two members (one of them the union
`IS`) and `W = i32 | string | f64` lists three, so the walk paired `IS` with `i32` and the rows
were never twins. The two records stayed apart at the canonical level, although nothing looked
them up wrongly and their heap was shared.

Found by the canonical-key test over the struct-row label table: after `sRowCanonOf`, the only
pair of one type on two canonical rows outside the hole/closure coarseness class.

#### Close

`fnSetParts` flattens nested union layers (`fnUnionLeaves`), and `fnSetsAgree` compares a
union's members as a set (`fnSetsAgreeAsSet`), since member order is not identity (D1712).
