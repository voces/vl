### D2386 — an inferred list literal of a local closure's calls is not collected when a sibling function nests a same-named string function

**closed 2026-09-25 · was loud emit reject · `vl check` rc 0, then `emitProgram: array literal but list type not collected`, clause 2 · found in review of #3135 (D2289), the same on its base · filed 2026-09-25 against master `02cce0b14`**

Repro:

    function b() {
      function w() { "hi" }
      print(w())
    }
    function a() {
      const w = () => { 3 }
      const xs = [w(), w() + 1]
      print(xs[1])
    }
    b()
    a()
    // vl check: rc 0.  vl run (before the close): emit error, "array literal but list type
    // not collected".  Now prints `hi`, `4`.

Repro (the literal indexed inline, no list binding — found in review of #3135):

    function b() {
      function w() { "hi" }
      print(w())
    }
    function a() {
      const w = () => { 3 }
      print([w(), 5][1])
      const m = w() * 2
      print(m)
    }
    b()
    a()
    // vl check: rc 0.  vl run (before the close): emit error, "index access but list type
    // not collected".  Now prints `hi`, `5`, `6`.

#### Mechanism

The mechanism this row first predicted was wrong: the emitter typed the literal correctly, as
the `i32` list. The COLLECT pass did not reserve that list. `collectA` classifies every list
literal with no frame (`arrLitIsStr(i, -1)`), and frameless, `w()` resolves through the flat
function map to `b`'s nested string `w`, so the literal reserved the string pair and not the
`i32` one. The frame pass `collectArrNewFrames` already re-asked the string question in the
literal's own frame (D1740), which can only add a string pair. The close has it reserve the
frame's whole scalar answer (`f64`, `i64`, `f32`, else `i32`) for a non-ref literal as well,
monotone like the rest, so the pair the emitter lowers with always exists.

#### Ablation

| ingredient changed | outcome before the close | needed? |
| --- | --- | --- |
| the binding annotated `const xs: i32[] = …` | runs, `hi`, `4` | **yes** |
| `b`'s nested `w` returning `5` instead of a string | runs, `5`, `4` | **yes** |
| `b`'s nested `w` returning `2.5` or an `i64` | still refuses | no |
| the literal `[w(), w()]` (no arithmetic) | still refuses | no |
| the literal `[w() + 1]` (one element) | still refuses | no |
| `w` a closure PARAMETER instead of a local | still refuses | no |
| the literal returned, or iterated by `for … in` | still refuses | no |
