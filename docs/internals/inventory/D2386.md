### D2386 — an inferred list literal of a local closure's calls is not collected when a sibling function nests a same-named string function

**loud emit reject · `vl check` rc 0, then `emitProgram: array literal but list type not collected`, clause 2 · found in review of #3135 (D2289), the same on its base · filed 2026-09-25 against master `02cce0b14`**

Repro:

    function b() {
      function w() { "hi" }
      print(w())
    }
    function a() {
      const w = () => { 3 }
      const xs = [w(), w() + 1]
      print(xs[1])
    }
    b()
    a()
    // vl check: rc 0.  vl run: emit error, "array literal but list type not collected"
    // (before #3135 the same program read "index access but list type not collected")

Repro (the literal indexed inline, no list binding — found in review of #3135):

    function b() {
      function w() { "hi" }
      print(w())
    }
    function a() {
      const w = () => { 3 }
      print([w(), 5][1])
      const m = w() * 2
      print(m)
    }
    b()
    a()
    // vl check: rc 0.  vl run: emit error, "index access but list type not collected"

#### Mechanism

The emitter's list-literal element-type inference from an inline call: it types `[w(), …]` by
the element call's result through a resolver that answers `b`'s nested string `w` for `a`'s
closure, so the literal asks for a string list the collect pass never registered, while the
elements are `i32`. Confirmed in review of #3135; not the collect-pass twin
`emit_collect.fnIndexOfInScopeChainSid`, whose only callers are the default-argument fill and the
direct-call lowering. The literal need not be bound: the second witness above indexes it inline
and refuses at the index. The annotated spelling runs, so the gap is the inferred element type.

#### Ablation

| ingredient changed | outcome | needed? |
| --- | --- | --- |
| the binding annotated `const xs: i32[] = …` | runs, `hi`, `4` | **yes** |
| `b`'s nested `w` returning `5` instead of a string | runs, `5`, `4` | **yes** |
| the literal `[w(), w()]` (no arithmetic) | still refuses | no |
| the literal `[w() + 1]` (one element) | still refuses | no |
