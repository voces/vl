### D17220 — a `null`-typed place assigned a call's result is written by the claimed IR as the call stored, where legacy drops the call and stores the null

**closed 2026-11-24 by S1's #9943 · runs, claimed bytes now legacy's · was: claimed bytes differ, output the same, not in `scripts/ir-divergence-baseline.txt` · `storeValue` builds a `null` cell's value as `nulNoneEffect` then `RNullOf` · filed 2026-11-24 against master `add0d888e` by IR-N5**

Repro:

    let g: null = null
    function same(x: null): null { return x }
    g = same(null)
    print(g)

Want:

    null

#### Mechanism

The claimed start wrote `global.set g (call $same (ref.null none))`; legacy (and the claimless
compiler) writes `drop (call $same (ref.null none)); global.set g (ref.null none)`, the effect then
the cell's null, as it writes every `null`-typed value. The program printed the same; the bytes the
claim shipped were not legacy's, and no baseline named them. #9943's `storeValue` now writes the
effect and then the null.
