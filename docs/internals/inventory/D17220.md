### D17220 — a `null`-typed place assigned a call's result is written by the claimed IR as the call stored, where legacy drops the call and stores the null

**runs today and must keep running · IR identity, not in `scripts/ir-divergence-baseline.txt` · claimed bytes differ, output the same · filed 2026-11-24 against master `add0d888e` by IR-N5**

Repro:

    let g: null = null
    function same(x: null): null { return x }
    g = same(null)
    print(g)

Want:

    null

#### Mechanism

The claimed start writes `global.set g (call $same (ref.null none))`; legacy (and the claimless
compiler) writes `drop (call $same (ref.null none)); global.set g (ref.null none)`, the effect then
the cell's null, as it writes every `null`-typed value. The program prints the same; the bytes the
claim ships are not legacy's, and no baseline names them. The IR's `print nulNone` arm declines a
frame holding this assignment (`print nulNone after a null-unit assignment from a call`) so the
divergence does not spread; the decline goes with the fix.

#### Ablation

| ingredient removed | outcome | needed? |
| --- | --- | --- |
| the call (`g = null`) | claimed bytes equal legacy's | **yes** |
| the module scope (the assignment inside a function) | still differs | no |
| the `print` | still differs | no |
