### D1703 — a `??` whose default is a STRUCT joins to a mixed scalar-and-struct union, which is not a value-union name, so the boxed shape is never reached and the scalar block type takes a struct ref

**closed 2026-09-06 — the join is LEGAL, and the lowering and the classifier now agree it is a
box, so the destination stops boxing it twice · filed against master `dbd19dd4b` · residues
D1709, D1712 · 0 corpus cells**

Repro:

    type A = { r: i32 }
    type M = i32 | A
    function mkN(): i32 | null { return null }
    function st(): A { return { r: 8 } }
    const v = mkN()
    const w: M = v ?? st()
    if w is A { print(w.r) } else { print(0) }
    // prints 8 since the close; before it, `vl check` rc 0 then exit 70,
    // the emitted module failed to validate: type mismatch: expected i32, found (ref $type)

#### Mechanism

D1699's close asks `isValueUnionName` of the `??` node's recorded type to decide whether the
result is a box. For `i32 | A` that is correctly FALSE — `valueAtomKind` has no atom for a
struct name, and a mixed union is a variant box rather than a value box — so the arm falls to
the scalar tail, picks the operand's `i32` block type, and `emitExprAsKind` puts the struct ref
in it. `emitUnionCoerce` already boxes an object arm as a variant, so the missing half is the
NAME: the mixed union has to resolve for the boxed shape to be selectable, and a declared
`type M = i32 | A` with `const w: M` does not help either.

#### Ablation

| ingredient removed | outcome | needed? |
| --- | --- | --- |
| the struct default (`v ?? ls()`, a `string[]`) | runs, prints `q` | **yes** — a list is a value atom |
| the scalar operand (`A \| null ?? st()`) | runs, prints `8` | **yes** — both sides struct is not mixed |
| the null value (`return 5`, so the default is dead) | refuses identically | no |
| the declaration (`const w = …`, inferring the join) | refuses identically | no — that is D1709 |

#### Grading list

The four ablation rows plus the list-default and struct-operand controls that must keep running,
and the four mixed-union delivery spellings — bound, returned from an annotated function, passed
as an argument, and `is`-discriminated on both arms. An f32 default is the neighbouring case
worth re-grading with it:
`v ?? sm()` over an `i32 | null` is a LOUD emit reject un-annotated (`union box atom test on a
union with no recorded members: i32|f32`) while its declared-`type F = i32 | f32` face runs, so
it is the same "the join has no registered union" question wearing a loud sentence.

**The design ruling is that the join is LEGAL, so the CHECKER must not refuse it.** A mixed
scalar-and-struct union is a union the language has, and it runs at every ordinary spelling —
declared, returned from an annotated function, bound, and discriminated with `is`, both arms —
so `i32 | A` arriving from a `??` is a rep the emitter owes rather than a contract to state.

**And it is not the re-tagging it looks like.** `scalarTagOfKind` is `uVariants.length + k`, so
a scalar atom's tag is program-global rather than per-member-set; the operand's own box already
carries the tag the join wants, exactly as the value-union case does.

**The name resolution alone was a COMPILER TRAP, and the trap named the missing half.** Falling
back to `nodeRegisteredUnionName` in the lowering alone selects the boxed shape and the declared
face then dies inside the compiler. The disassembly says why, and it is not `emitUnionCoerce`'s
variant arm: that arm boxes the struct default correctly, and the `??` result was then boxed a
SECOND time by its destination, so the arm test cast a box to the arm's struct and the cast
failed. `exprUnion` answers through `unionNameOfExpr`, which had the same
`isValueUnionName`-only gate, so the classifier said "not a union" about the value the lowering
had just made one. Both take the registry fallback now — the producer and the consumer of a rep
decision have to be changed together, which is D1702's lesson at a second site.
