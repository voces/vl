### D16486 — an assignment to a vector field of a list element, used as a value, is refused at emit

**closed 2026-11-15 · runs, prints `3` · was a loud emit reject, clause 2: `vl check` rc 0, then emitProgram: an assignment used as a value stores a cell no local can hold its value from · fixed 2026-11-15 by lane L: a field store parks its value for the assignment in the scalar-list value slot of its rep, and a `v128` field now parks in the `v128list` one (`asgParkField`, wasmEmit.vl) · found closing D16485 · filed 2026-11-15**

Repro:

    import { F32x4, splatF32 } from "std:simd"
    type R = { v: F32x4 }
    const rs: R[] = [{ v: splatF32(1.0) }]
    const w = (rs[0].v = splatF32(3.0))
    print(w.x)

Want:

    3

#### Mechanism

A field write's value is re-read only when the field's receiver is a name
(`assignTargetReReads`), so `rs[0].v = …` and `h.r.v = …` take the parked-cell path instead: the
field store tees its value into a scratch local of the field's rep (`asgParkField`). That
ladder parked the scalar and string fields and declined a `v128` one, which had no scratch slot
until the `v128list` kind gave it one. The same write through a record local is re-read and ran.

#### Ablation

| ingredient removed | outcome | needed? |
| --- | --- | --- |
| the list element (a record local `r.v = …`) | runs, `3` | **yes** |
| the vector (an `f32` or `i32` field) | runs, `3` | **yes** |
| the declared type (an anonymous record) | still refuses | no |
| the value position (the write as a statement) | runs | **yes** |
