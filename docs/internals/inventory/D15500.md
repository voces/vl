### D15500 — a generic's `?.get` default `null`, delivered at a `boolean | null` instance, is built as the template's null

**closed · runs, prints `true`, `false` · was check-clean invalid wasm, clause 1, `type mismatch: expected i32, found nullref` inside `f` · closed in wasmEmit.vl: `nullOwnAt` reads the instance's contextual type where the null's stamp is the template's and names a type parameter (`V | null`), as D14640 does where the stamp is the instance's · fixture `generics/generic-optchain-get-null-at-boolean-instance.vl` · filed 2026-11-06 against master `e925b06a`**

Repro:

    function f<V>(k: {[string]: V} | null): V | null { k?.get("a") }
    const b: {[string]: boolean} = Map()
    b["a"] = true
    print(f(b) ?? false)
    const n: {[string]: boolean} | null = null

    // vl check: rc 0.  vl run: invalid module, expected i32, found nullref inside `f`

Want:

    true
    false

#### Mechanism

`m?.get(k)` is rewritten to a guarded index read whose default `null` the call's check mints
(`optReadParts`, `checkCallNodeAt`). In a generic, that `null` carries the template's stamp,
`V | null`, which names no null of its own, and the instance's re-check records only its
contextual type (`boolean | null`), not a rep stamp. `nullOwnAt` read the instance's context only
when the instance had stamped a rep, so the `null` was built as the bottom ref inside a block
whose `boolean | null` rep is the i32 sentinel niche. A `??` written directly over the read fuses
into the guarded read and never builds the `null`, which is why the coalesce fixture
(`generics/generic-optchain-map-get-coalesce-scalar.vl`) ran.
