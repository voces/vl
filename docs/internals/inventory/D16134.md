### D16134 — a `filter` callback over a list of a kept maker's build is instanced at the element's own type, so the read is refused

**open · loud check reject, clause 2 · in D16133's class, a decision made after its consumer · the `filter_lambda` position of `kept-maker-delivery-null-field.matrix.vl` left after D15933 · filed 2026-11-14 against master `b8b695bf`**

Repro:

    type J = { f: i32 | null }
    function mk2() { { f: null } }
    const dA: J = mk2()
    const xs = [mk2()]
    const ys = xs.filter((y) => y.f == null)
    print(ys[0].f)
    // vl check: this container's {f: null} elements are stored at J, ...

Want:

    null

#### Mechanism

`xs` holds `mk2()`'s build, `J`, but the `filter` callback is instanced at the element's own type
`{f: null}` (`recBuiltCallbackRefuse`, D15697's refusal). Lifting the refusal alone gives
"emitProgram: ref valtype with no interned shape", so the close builds the callback's instance
at the container's build.

A probe pass measured why this is not a contained change. When `memberCallMapFilterTy` types the
callback (`recordCbExpected`), both build tables are empty (`recBuildTable()` and
`recBuildPassTable()`, size 0). The list's build is decided by `recStoresAgree` in
check_program's post-pass, after the body is checked, and nothing re-checks it. A hole function
handed a built element by a call (`chk(xs[0])`) runs, because mono reads the argument's built type
from `recBuildTable()` after the post-pass (`recArgBuiltTyIn`). A lambda callback has no such
reader: it is typed once, at the element's own type, and is never instanced
(`monoPinLamAtDelivery` instances only a lambda whose body calls a generic). A named hole callback
and an annotated `(y: J) => …` callback are refused too. The close needs either the list's build
decided before its callbacks are checked, or the callback instanced at the build after the
post-pass: the same class as D16133, and folded into its design item. A prototype is on branch `i-d16134-filter-built-callback`
(reference only, not for merge).
