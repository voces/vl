### D3094 — an un-annotated callee's `is`-guarded return drops out of the call's type when the argument is a union

**closed: a guarded return member stays in the call's type when the union argument has a member of the guard's type, so an `i32` accumulator is refused as the annotated parameter's spelling is, and since D3246 the un-annotated accumulator takes `i64` from that sum and runs · fixtures `tests/cases/inference/hole-guarded-return-union-pin-rejected.vl`, `hole-guarded-return-union-sum.vl` · was check-clean invalid wasm · clause 1 · found by the #3271 review · the same on master `505bb44e0` · filed 2026-09-28 against master `505bb44e0`, closed 2026-09-28 against master `e1e40ac99`**

#### Mechanism

A return reached through `if w is i64` over a hole parameter is a guarded member (`HD_GALT`,
`mkGuardedRetTy`). At a call, `substHoleTyReal` kept it only when the pin was assignable to the
guard's type; a union pin `i64 | string` is not, so the `i64` branch dropped out, the call typed
as the remaining `i32`, and `c = c + g(e)` checked while the instance returned `i64`. The branch
is reachable whenever the pin has a member of the guard's type (`pinHasMemberOf`), and then its
return is a member of the call's type, which is what the annotated parameter's inference gives.
The right answer is the annotated spelling's refusal, so the row carries no `Want`.
