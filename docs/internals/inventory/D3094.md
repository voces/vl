### D3094 — an un-annotated callee whose inferred return is `i64`, added into an `i32` accumulator, passes the checker

**check-clean invalid wasm · clause 1 · found by the #3271 review · the same on master `505bb44e0` · filed 2026-09-28 against master `505bb44e0`**

Repro:

    const zs: (i64 | string)[] = [5, "t", 6]
    function g(w) {
      if w is i64 { return w + 1 }
      return 0
    }
    let c = 0
    for e in zs { c = c + g(e) }
    print(c)
    // vl check: rc 0.  vl run: invalid module: type mismatch: expected i32, found i64

#### Mechanism

Not investigated past the ablation. With `w: i64 | string` annotated, the checker infers `g`'s
return as `i64` and refuses `c = c + g(e)` into the `i32` `c`. With `w` an inference hole the
return is still a hole when the assignment is checked, so the refusal the annotated spelling
owes is never made, and the instance the walk pins returns `i64`. The right answer is the
annotated spelling's refusal, so the row carries no `Want`.

#### Ablation

| ingredient changed | outcome | needed? |
| --- | --- | --- |
| `w` annotated `i64 \| string` | loud check reject, `cannot assign i64 to i32` | **yes** (the hole) |
| `let c: i64 = 0` | runs, prints `13` | **yes** (the `i32` accumulator) |

#### Grading list

Both faces, a `let` accumulator and a compound `+=`.
