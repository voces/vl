### D15440 — a function set called at two types through a returned list, whose member a hole helper pushes onto a wider list, is refused at emit with the split plan off

**closed 2026-11-05, runs with the split plan on and off · was split-plan dependent: with it off a loud emit reject, `a function value is called at two signatures, and the closure it holds was built for one`, clause 2 · closed by the elaboration naming the push's closure at the signature calls through a list binding of the holder's set close (`elabListSigOfSet`, `elabPushDestTy`), and `ftParamStored` (check_fn_tag.vl) taking such a recorded push as no store into a holder · D15062's hole-helper escape, left when its record escape closed · fixture `tests/cases/closures/function-list-element-at-two-types-pushed-through-hole-helper.vl` · filed 2026-11-04 against master `f2599d8e`**

Repro:

    function inc0(a) { return a + 1 }
    function dbl0(a) { return a * 2 }
    function deliver0() { return [inc0] }
    function take0(a) { print(a[0](3)) }
    take0(deliver0())
    print(deliver0()[0](1.25))
    function addTo(xs, f) { xs.push(f) }
    const fs = [dbl0]
    addTo(fs, inc0)
    print(fs[1](5))

Want:

    4
    2.25
    6

#### Mechanism

`{inc0}` has to be tagged for `deliver0()[0]` to be called at `i32` and `f64`. Its hand to
`addTo`'s un-annotated `f` is declined by `ftCtxOk` (`check_fn_tag.vl`): D15065's veto keeps an
id out of a parameter the callee pushes into a holder, and no other reading applies. Inside
`addTo` the push stores into `fs`, whose element set `{dbl0, inc0}` is untagged, so `f` there is a
closure. A close builds `inc0` as that closure at the hand, where the push's destination is a
set no decision tags, as a record literal pushed onto a list of records now is (D15062).

#### Grading list

Measured 2026-11-05 with the split plan off: the check's decision tags `{inc0}`, and the late
decision declines it at `take0(deliver0())` because `mintSetPartial({inc0})` holds. The partial
mark is the elaboration's: `addTo`'s instance reads `f` as `xs.push(f)`'s argument, a read other
than a call, and `elabMintFacts`'s per-read rule marks the parameter's set partial. Deciding `fs`'s
wider element set with `{inc0}` at the hand (`ftSubNeed`) leaves that mark standing, so it does not
close the row. The close is two parts: a parameter read stored into a holder whose element set is
wider or closed does not make the parameter's set partial, and the instance stores a closure there
rather than an id (D15065's veto is right about the id), which is per-instance closure keying.

#### As closed (2026-11-05)

The approved design needed no new inference and no new mono code:

- The elaboration already closes a list binding's element from calls through it
  (`elabListCallSig`). It used that only to mint a candidate instance of the callee at the closed
  list (`elabListSigRow`). The per-round fact `elabListSigOfSet` (set to signature) now keeps it,
  and `elabPushDestTy` names it for a push whose holder element is open. That gives `(i32) => i32`
  for `fs`'s set.
- `elabCloNoteAt` records the push as that set's one member delivered at that signature, and the
  late decision's `ftParamStored` takes such a push as no store into a holder. `{inc0}` is tagged.
- Mono builds `inc0` at the signature through the existing delivery path (`monoCloCoerceBuild`,
  the row's one writer), and the emitter's coercion reads it.

The `addTo` key at `(() => void)[]` that made the earlier attempt flip is a guess and
representation key. `() => void` is the guess default for an unconstrained hole function, so it is
no instance a value reaches. Its push is not a delivery, as the partial rule already treats guess
keys. It was not a per-key overwrite.
