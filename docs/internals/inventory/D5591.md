### D5591 — a scalar parameter handed to a built-in inside an index operator is read as a function value

**closed 2026-10-17 — the witness prints `b5` · was a loud check reject, clause 2 · found from eardstap EV-009 · filed 2026-10-17 against master `44ed9635a` · fixtures `tests/cases/soundness/index-operator-scalar-argument-is-no-function.vl` and `tests/cases/soundness/index-operator-writing-receiver-ends-narrowing-reject.vl`**

Repro:

    type Box = { n: i32 }
    function "[]="(self: Box, i: i32, v: i32) { self.n = max(v, i) }
    function "[]"(self: Box, i: i32): i32 { self.n + i }
    type Intent = { kind: "a" | "b" | "c", n: i32 }
    function poke(b: Box) { b[0] = 5 }
    function act(i: Intent, b: Box): string {
      if i.kind == "a" { return "a" }
      poke(b)
      match i.kind { "b" => "b\{b[0]}", "c" => "c" }
    }
    print(act({ kind: "b", n: 1 }, { n: 0 }))

Want:

    b5

#### Mechanism

`weArgShapes` (`check_write_effects.vl`) maps an argument that names a parameter to `@<n>`,
"whatever the caller passed may be called", before asking whether the argument is a scalar. So
`max(v, i)` charged `"[]="` with possibly calling `v`, and an operator site closes over its
parameters (`weClosed`), which turns `@<n>` into `*`, a write of anything. The scalar test now
runs first: an `i32` is no function value whichever name it has.
