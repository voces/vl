### D16461 — a returned `if` whose nested arm widens an atom to `string` leaves the string frame unreserved

**closed 2026-11-15 · runs, prints `B` · was check-clean invalid wasm, clause 1 (`unknown local 5: local index out of bounds`) · fixed in `blockHasStrOpScan` (`emit_fn_scans.vl`), which asks a returned value `if` the tail scan's question (`tailStmtWidensAtomToStr`) · fixture `tests/cases/conditionals/return-if-lowers-as-tail-if.vl` · found by lane D's return-rule migration · filed 2026-11-15 against master `41739762`**

Repro:

    type K = "A" | "B"
    function t(k: K, c: boolean): string {
      return if c { if c { k } else { "A" } } else { "A" }
    }
    print(t("B", true))

Want:

    B

#### Mechanism

The atom-to-`string` widen stashes the atom in the string scratch frame, which `fnHasStrOp`
reserves. Its tail leg (`tailStmtWidensAtomToStr`) walks a tail `if` into every arm, nested
ones included; the `return` leg asked `retWidensAtomToStr` of the whole `if`, which sees an atom
only at the top arm level. The nested arm's widen then wrote a local past the frame. A returned
value `if` now asks the tail leg's question, as it lowers through the tail's path (D16460).
