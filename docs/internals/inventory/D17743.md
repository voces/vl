#### Mechanism

`elabHeldValTy` closes an open function leaf only at a literal or binding it can trace to the
function's declaration; through `g()`'s result, or the arms of a value `if` of lists, it answers
none, and the holder is laid out at `{f: ((_) => _)[]}`. The uncalled default is also not one
type: the literal `[inc0]` mints its row at the `() => void` stub (`fnElemRowTy`, D4551) in one
program and at `(i32) => i32` (`elabHoleFnClosed`, D9100) in another, so the close needs one
default chosen first. Coordinator ruling 2026-11-27: D9100's default for an uncalled hole function's
closure. The `() => void` stub stays where the row keys a hole lambda whose signature an instance
binds (`fnElemRowTy`, `arrLitClosureElemTy`): replacing it there lost two programs that call
such a lambda per instance.
