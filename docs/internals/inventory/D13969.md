### D13969 — a record field's un-annotated function is not judged at the callee's call of that field

**closed 2026-10-26 — now a loud check reject at the field, as `take0(len0)` is at the argument · was loud emit reject, clause 2 · the field's function is judged at the callee's field calls (`judgeHoleFieldCalls`) · filed against master `5807f0fd7` · pin: `tests/cases/closures/error-hole-fn-in-record-field-judged-at-field-call.vl`**

Repro:

    function len0(a) { return a.length }
    function take0(a) { print(a.f(3)) }
    take0({ f: len0 })
    // vl check: rc 0.  vl run: emitProgram: '.length' on a receiver the emitter cannot
    // classify as a list, string, map or set

#### Mechanism

The callee's `a.f(3)` banks an argument constraint on an `HD_PARAM` derived hole. Its base is
the `HD_FLD` hole `a.f`, not the hole `a` itself. `genFnHoleInstance`, `genFnHoleCallInsts` and
`genFnHoleMovedInsts` match only a base that is the parameter's own hole. So
`judgeFnArgHoleCalls` judges a function handed as the argument (`take0(len0)` with `a(3)`
refuses at check), but not one handed in a field. The emitter then meets the body at `i32`.
Mono's pin (`monoFieldCallPinnedFnTy`, `monoOpenFnRecSrcPin`) settles the same type from the
same calls for programs that are well typed. That is the only place it is settled today.
