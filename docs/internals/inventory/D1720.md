### D1720 — a nullable-struct value stored into a nested-struct FIELD is recovered with `ref.as_non_null`, though that field's slot is nullable for every struct field

**closed 2026-09-06 — `fieldCodeVKind` no longer answers for code 15, so the field layer owes
no recover on a hop whose slot is `(ref null $H)` · filed against master `df777a8b3`, mechanism
corrected the same day by the disassembly · residue D1738 · 0 corpus cells**

Repro:

    type A = { r: i32 }
    function st(): A { return { r: 8 } }
    function mkA(): A | null { return null }
    const w = { f: mkA() }
    const g = w.f ?? st()
    print(g.r)
    // prints 8 since the close; before it, `vl check` rc 0 then exit 1,
    // wasm trap: null reference
    // note: a null value was used where a non-null one was required.

#### Mechanism

**The row was filed against the READ and the trap is at the WRITE.** The disassembly puts the
`ref.as_non_null` inside the holder's own construction —
`(struct.new $2 (ref.as_non_null (call $1)))` — before the `??` is reached at all, and the same
program with no `??` anywhere traps identically. The `??` was scenery.

`nulNicheRecoverOwed` asks the field's destination kind through `fieldCodeVKind`, whose own
comment says only the NON-NULL ref codes answer. Code 15 was in that table and does not belong:
`pushFieldStorage` writes `0x63` for it — a `(ref null $H)` slot — because D1476 folds `inner: S`
and `inner: S | null` onto one hop, while every other code in the table writes `0x64`. So a
nullable-struct value delivered into a nullable-struct field was recovered into a slot that
never needed it, and the recover trapped on exactly the value the niche exists to carry.

Dropping the rung is safe in both directions the code can reach. A well-typed program stores a
nullable value only into a nullable field, whose slot accepts it; an ill-typed one is refused by
the checker (`cannot assign {f: A | null} to 'w' of type W`), so the recover was never the thing
keeping it out. The string niche is the control that shows the table is otherwise right: a
`string | null` field is code 20, absent from the table, and its store has always run.
