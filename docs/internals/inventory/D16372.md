### D16372 — a postfix `x++` or `x--` used as a value on an i64, f64 or f32 binding emits invalid wasm

**check-clean invalid wasm · `type mismatch: expected i32, found i64` · 70 of the 116 programs of the oracle's arithmetic fuzz that build no module carry this spelling (a spelling count; the 19 of the first batch were reduced to it) · found by the independent oracle (`scripts/oracle/gen.ts`) · filed 2026-11-14 against master `de4cfa15f`**

Repro:

    let x: i64 = 5
    print(x++)
    print(x)
    // vl check: rc 0.  vl run: invalid module, type mismatch: expected i32, found i64

Want:

    5
    6

#### Mechanism

E7.3 gives `x++` the old value. As a statement the increment runs at the binding's width; as a
value the old value is produced at i32 whatever the binding's type, so the consumer of the
expression receives an i32 where its type says i64 (or f64, f32).

#### Ablation

| ingredient removed | outcome | needed? |
| --- | --- | --- |
| the width (`let x: i32`) | prints `5` | **yes** |
| the value use (`x++` as a statement) | runs | **yes** |
| postfix (`++x`) | prints `6` | **yes** |
| `print` (`const y: i64 = x++`) | still invalid | no |
| i64 (`let x: f32 = 5.0`, `x--`) | still invalid | no |

#### Grading list

`x--` at each width; a postfix on a field or element once D4055 lets it parse.
