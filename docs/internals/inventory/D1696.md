### D1696 — a DOUBLY-nested object literal takes a declared row one level too shallow, so the outer literal is refused for a field it never had

**closed 2026-09-06 — the capture preference is depth-general and asks the field-name SUBSET
as well as the box · filed against master `ad287fae7` + D1690 + D1694 · found by D1694's own
position matrix at `struct_field_init` · residue D1697 · 0 corpus cells**

Repro:

    type H = { f: { xs: i32 } }
    const w = { f: { f: { xs: 7 } } }
    const v = w.f
    print(v.f.xs)
    // vl check: rc 0.  vl run: rc 0, prints 7

Was: `emitProgram: object literal is missing a struct field`. Deleting `type H` printed `7`
then too, which is what named the ingredient.

#### Mechanism

`type H` is never named by a value; declaring it is the whole ingredient, and no union is
involved — this reproduces at four lines with a plain `i32` leaf, which is what separates it
from D1690 and D1694. The literal is nested TWICE (`{ f: { f: { … } } }`) and each of its two
outer levels has the single field name `f`, so the field-set scan matches BOTH of them against
`H`, whose `f` is the one-field shape `{xs:i32}` — the middle literal fits, the outer one does
not, and the refusal a user reads is about a field the outer literal never claimed to have.

The span is the outer literal and not the declaration, so this one needs the construction —
unlike the declaration-time rep gap the same matrix found at the ref-list arm. A single nesting
level runs (that spelling is D1694, closed), and annotating the outer binding is the rescue at
every depth.

**The family question this row was filed to settle: it is the destination preference one level
down, NOT the object-shape floor's accepting side.** The two are separated by which differences
a re-intern can absorb. It can DROP a field the destination does not want and WIDEN one it
does — that is the accepting side, and `object-shape-unannotated-literal-rebuilt.vl` pins it.
It cannot INVENT a field the source lacks, and it cannot renumber a box's positional tags. So
the comparator asks exactly those two things: the destination row's field NAMES must all be
present in the value's, and every shared box must name one member sequence.

**Depth costs nothing, and that is measured.** Walking the same question into each nested-struct
field (bounded at eight levels, which is lenient for a self-recursive type) fixes a box two and
three levels in and a missing field one level down, while both object-shape re-intern controls
— at depth 1 and at depth 2 — keep printing `4`. `compile(candidate, tests/cases)` differs in
**0 of 3,052** modules. The boundary is not about depth; it is about which difference is asked.
