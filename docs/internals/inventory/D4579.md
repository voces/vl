### D4579 — a generic function, or a container of one, set into an un-annotated `Map()` has no map value representation

**loud emit reject · `vl check` rc 0 · clause 2 · found by `fn-value-generic-list-read.matrix.vl` and `fn-value-generic-optional-read.matrix.vl` (`map_value`, `map_set`, `map_value_place`, un-annotated face) · filed 2026-10-14 against `bd616c03b`**

Repro:

    function id<T>(x: T): T { x }
    const m = Map()
    m.set("k", id)
    const v = m.get("k")
    if v != null { print(v(2)) }
    // vl check: rc 0.  vl run: emitProgram: unsupported map value type (no rep for a union-member struct, …)

Want:

    2

#### Mechanism

The map's value slot is interned from the value type the checker infers for `Map()`, which is
the open `(T) => T`. Flow reads cover literal slots, not map entries, so no read fixes the
instance before the slot needs a representation.

#### Ablation

| ingredient removed | outcome | needed? |
| --- | --- | --- |
| `m` annotated `Map<string, (x: i32) => i32>` | runs, prints `2` | **yes** |
| `id` replaced by a non-generic `inc` in a list, `[inc]` | runs, prints `3` | **yes** |
| `id` wrapped as `[id]` or `{ f: id }` | still refused | no |
