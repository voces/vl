#### Mechanism

The if-of-generics path gives each arm one value: the arm's tail, or the initialiser of an
un-annotated binding the tail reads that the block declares (`monoArmTailValue`, emit_mono.vl).
That one value goes to the readers that pin the arm (`monoFirstArmGenName`, `monoPushArmValues`
and the `Block` arm of `monoCoerceFnValueTys`). A reassigned `let` has two values. The arm
delivers the last write's right side, and the initialiser `ask` is still a function value that
needs a pin. The single-value readers can express neither, so the initialiser reaches the value
floor with no pin.

Closed without a list of values per arm: the readers that ask whether an arm names generics
and which name pins it now treat a tail reading a written generic `let` as delivering that
binding, whose initialiser fixes the signature every write must share
(`monoArmWrittenLetSeed`). The coercion was already per write.
