### D4046 — a join of two type parameters, one pinned at a record and the other at another type, builds invalid wasm in a nested function or out of list elements

**check-clean invalid wasm · clause 1 · open · 18 cells of the distilled corpus's `rv3310-join-price` (the g5 grid's `nested_fn` record pairs and the `list_scalars`, `list_plus_scalar` and `nested_gen` `*_p` pairs) · found triaging the corpus's clause-1 pool · filed 2026-10-11 against master `efd3c3f15`**

Repro:

    type P = {x: i32}
    function outer<T, U>(a: T, b: U, k: i32) {
      function inner(k2: i32) {
        const r = if k2 == 0 { a } else { b }
        print(r == null)
      }

    }
    const x0: i32 = 4
    const x1: P = {x: 8}
    outer(x0, x1, 0)
    outer(x0, x1, 1)
    // vl check: rc 0.  vl run: invalid module inside `inner` (type mismatch: expected i32)

Want:

    false
    false

#### Mechanism

Not localised past the ablation. The kept-apart join of two bare type parameters (D3268) is
not what types this join: inside a function nested in the generic, and over elements read out
of `T[]`/`U[]` parameters (where the kept-apart join is gated off, D3357), the join takes the
first arm's rep, and the record arm is then built where an `i32` (or another record) is
expected. D3361 is the scalar face of the gated list-element and nested-generic shapes; this
one differs in its ablation because it also fails in a nested function that captures the
parameters, where D3361's scalar members answer right.
