### D15608 — `is` outside a branch condition, over a bounded type parameter's field, is refused where the pin makes it false

**closed 2026-11-10, runs and prints `false` · was loud check reject · `vl check` rc 1 at the pin: `` `is` check type 'i32' can never match a value of type string `` · clause 2 · the instance re-check's dead-test exemption asked only whether the operand's own type names a type variable, and a bounded parameter's field is typed by the bound; it now asks the operand's receiver chain too (`isObjReadsTyVar`, check_operators.vl), and `emitIs` (wasmEmit.vl) answers a record or list operand the pin relates to no tested member `false` (`isPinUnrelated`) · fixture `generics/is-value-over-bound-field-pinned-false.vl` · filed 2026-11-09 against master `5f4d4da2`**

Repro:

    function boundShow<T: { x: i32 | string }>(t: T) {
      print(t.x is i32)
    }
    const b: { x: string } = { x: "s" }
    boundShow(b)
    // vl check: the instance's re-check refuses the `is` as never true

Want:

    false

#### Mechanism

The instance re-check types `t.x` as `string`, the pin's field, and the "can never
match" diagnostic fired on the value position: the dead-test exemption (`deadArm`,
check_operators.vl) asked `tyHasTyVar` of the operand's own template type, which the bound types
as `i32 | string`. Fixed by asking every receiver the operand reads through (`isObjReadsTyVar`).
In a branch condition the same re-check treats the test as deciding a dead arm and raises nothing. The generic body is legal for every type its
bound admits, so a pin cannot make it ill-typed.
