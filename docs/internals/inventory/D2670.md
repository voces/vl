#### Mechanism

The site-cached append ([D2625](D2625.md)) remembers ONE buffer per site: the one it allocated
last. When a site's appends alternate between strings (`os[k % 4]`, or plumb's
`groups[g] = groups[g] + …` in `src/render.vl` over four groups), every append finds another
string's buffer in the cache, misses, and copies. A miss costs what the copying lowering did
plus `added + 16` elements of slack, so nothing regressed. A small per-site cache (two to four
entries, replaced round robin) would cover a bounded set; an unbounded set of strings at one
site needs the frontier stored with the buffer, which is a string rep change.
