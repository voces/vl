### D1542 — a lambda whose TAIL reads a MODULE-scope binding is not a closure to `exprIsClosureNoLocal`: `const v = get()` is `call to unknown function`, and its ANNOTATED twin is invalid wasm

**closed — now runs · was `loud emit reject: emitProgram: call to unknown function` (inferred destination) and `check-clean invalid wasm` (annotated destination), `vl check` rc 0 for both · clause 2 and clause 1 of one rung · found 2026-09-03 by the day-one sampler's `closure_capture` pair, minimised to four lines · fixture `tests/cases/functions/module-scope-returned-capture-call.vl`**

Repro:

    const held = (x: i32) => x + 1
    const get = () => held
    const v = get()
    print(v(4))
    // vl check rc 0; vl run -> emitProgram: call to unknown function
    // want: 5

#### Mechanism

`fnReturnsClosure` → `blockTailIsClosure` → `exprIsClosureNoLocal` decides whether a lifted
lambda's RESULT is a closure. Its `Ident` arm resolves the name through
`identBindingNoLocal`, which walks `frameBindingNode` up the `fnParent` chain — and
**`fnParent` is -1 for a top-level lambda**, so the walk ends before reaching the module. The
name then fell to `fnIndexOfSid`, the module-wide FUNCTION lookup, which a LIFTED lambda does
not answer to (it carries a synthesised name, not `held`). Verdict: not a closure.

The caller's `exprIsClosure` reads that same predicate for a CALL result
(`fnReturnsClosure(t)` / `calleeRetKindSid`), which is why the diagnostic lands at
`const v = get()` and names `v`, not `get`. The rung's own header had already written down
both failure modes — *"through a LAMBDA that is check-clean INVALID WASM, and through a NAMED
function a loud `call to unknown function`"* — for the frame chain it DID walk; the module was
the frame it did not.

Two arms added, block-local before global, matching [D1244](D1244.md)'s rule that a
module-scope `if`/`for`/bare BLOCK is a frame whose binding shadows a top-level one:
`moduleLocalLetOf(emitRootIx, name)`, then `globalLetOf(name)`, each answered by the existing
non-recursive `letDeclIsClosureNoLocal`. Asked AFTER the frame chain and after
`moduleBindsLoopVar`, so no shadowing answer changes.

#### Price

None measured. The added arms only ever turn a `false` into a `true` for a name the frame
chain did not bind, and `letDeclIsClosureNoLocal` is the same non-recursive decision the
frame arm already uses, so `const a = a` cannot spin. `moduleLocalLetOf` and `globalLetOf`
are both table reads (`mllMap` is built once per compile), not arena scans.
