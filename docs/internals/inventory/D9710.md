**closed · runs, prints `4` · was loud emit reject, `vl check` rc 0, `monomorphize: unsupported argument type for `f` in a call to `use``, clause 2 · CAPABILITY: the direct call `v[0][0](3)` runs · found closing [D9662](D9662.md) · filed 2026-10-22 against master `e8163edd5` · closed by reading the hole parameter's pin from the returned slot two levels down (`monoNestedRowReadFrame`, `monoHoleGenFnFlowTyAt` at `["e","e"]`, emit_mono.vl) · fixture `closures/hole-fn-nested-list-elem-handed-open.vl` · with [D9711](D9711.md)–[D9716](D9716.md) and [D9765](D9765.md) closed, [D9760](D9760.md)–[D9764](D9764.md) and [D9766](D9766.md) filed open**

Repro:

    function inc(a) { return a + 1 }
    function use(f) { return f(3) }
    function deliver() {
      const u = [[inc]]
      return u
    }
    const v = deliver()
    print(use(v[0][0]))
    // vl check rc 0.  vl run: emit error: emitProgram: monomorphize: unsupported argument type for `f` in a call to `use`

Want:

    4

#### Mechanism

The argument `v[0][0]` is an element read of a binding of the call. `monoOpenFnFlowPin` asked the
flow table for the returned slot one level down (`["e"]`), which for a nested list is the inner
list rather than the function, so no pin was found. It now recognises a read with two literal
indices over an un-annotated binding and asks the slot at `["e","e"]`.
