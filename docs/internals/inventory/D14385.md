### D14385 — a function returning a list literal of record rows, called once un-annotated and once into a record-list binding, builds invalid wasm

**check-clean invalid wasm · clause 1 · needs an owner ruling: is a function result that one call delivers into a wider record built at that record, as a binding is, or refused, as the annotated return is? · the same on master `c444e026e` · filed 2026-10-26 against master `8d0974164`**

Repro:

    type Cir2 = { c2: i32 }
    type Sq2 = { s2: i32 }
    type Shape2 = Cir2 | Sq2
    type Circle = { r: Shape2 }
    function aliased() {
      const t = [{ r: { c2: 1 } }, { r: { s2: 5 } }]
      t
    }
    const h = aliased()
    print(h[1].r is Sq2)
    const h2: Circle[] = aliased()
    print(h2[0].r is Sq2)

Want:

    true
    false

#### Mechanism

`vl check` accepts the program. Its module fails to validate at the second call (11:7):
`array` is `({r:{c2:i32}}|{r:{s2:i32}})[]` where `Circle[]` is expected. The function body is
built once. The un-annotated call keeps the literal at its own row-union list, and the
annotated call gets that list where a `Circle[]` is wanted, without the element conversion a
record-list delivery needs. With only the annotated call, the program runs.

#### Ablation

| ingredient removed | outcome | needed? |
| --- | --- | --- |
| the un-annotated call `const h = aliased()` and its read | runs, prints `false` | **yes** |
| the local `t` routed through an alias `const u = t` (added) | same invalid wasm | no |

#### Needs a ruling

The row is one witness of a family. On master `c444e026e`, an un-annotated function whose result
one call delivers into a wider record (or a list of them) and another use reads at the result's
own type is check-clean invalid wasm. The single-record spelling is enough:

    type Cir2 = { c2: i32 }
    type Sq2 = { s2: i32 }
    type Circle = { r: Cir2 | Sq2 }
    function mk() { return { r: { c2: 1 } } }
    const h = mk()
    print(h.r is Cir2)
    const h2: Circle = mk()
    print(h2.r is Sq2)

The second use can be a bare call (`print(aliased().length)`), a call with no read, either call
order, and a literal returned directly instead of through a local. Only the annotated call alone
runs. The checker accepts the annotated delivery as though the returned literal were built at the
destination (`recWidenWalk`'s call branch), and the other use keeps the body at its own type, so
nothing converts.

The neighbouring spellings disagree, so each answer matches one of them:

* **(A) Refuse, as the annotated return does.** `function aliased(): L[]` beside
  `const h2: Circle[] = aliased()` is refused: `L[] is not Circle[]: a container never widens
  implicitly`. The kept-versus-own refusal in `recKeptConflicts` ("kept at its own type at
  another") is the sentence for the un-annotated face. Programs like this row's witness stop
  compiling.
* **(B) Build it at the destination, as a binding is.** `const t = [{ r: { c2: 1 } }, { r: { s2:
  5 } }]`, read as `t[1].r is Sq2` and delivered as `const h2: Circle[] = t`, runs and prints
  `true` and `false`: the solve builds `t` at `Circle[]` and its own-type reads see that. For a
  function, the inferred result is pinned at the destination and the other call's binding is
  typed at it. This is the Want above. It moves a binding's checked type, so it is an inference
  change.

[D14891](D14891.md) took (A) because there the destination keeps two of a field's numbers as one,
so a build at it loses information. Here a build at `Circle` loses nothing, and (B) is open.
