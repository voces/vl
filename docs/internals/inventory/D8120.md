### D8120 — a map cell of a box holding an alias-named literal union, narrowed to that arm, prints through the atom path while it is still the box

**closed 2026-10-20 by lane L6 · the else of `m[k] is X` subtracts `X` from the cell's registered member set whatever its members are spelled, and a cell read narrowed to its literal-union arm unboxes to the string ref; the repro prints `b`, pinned by `tests/cases/literal-unions/map-read-narrowed-to-litunion-arm-prints.vl` and `scripts/capability-probes/matrix/litunion-arm-of-generic-map-cell.matrix.vl` · was check-clean invalid wasm · clause 1 · found by the `map_value_place` cells of the D7965 position matrix · the same on master `532d50d35` · filed 2026-10-20 against master `532d50d35`**

Repro:

    type AB = "a" | "b"
    const m: { [string]: i32 | AB | null } = Map()
    m["k"] = "b"
    if m["k"] is i32 { print(0) } else { print(m["k"]) }
    // vl check: rc 0.  vl run: invalid module, expected i32, found (ref $N) union box

Want:

    b

#### Mechanism

Two halves, both in `emit_classify.vl`. The else of `m["k"] is i32` pushed no narrowing at
all: `pushIndexMapComplement` gated on `isValueUnionName` of the map value's spelling, which
reads each member by its name and has no kind for an alias such as `AB`. With no narrowing the
read stayed the box while `print` took the checker's `AB | null` type to the atom path. With
the gate on the registered member set instead, the narrowed read reaches the `K | null` niche
conversion (D7965). Where the narrowing leaves `AB` alone (under an enclosing `!= null`, or
`is AB`), the read unboxes to the string the box holds, and `exprIsLitAtomIndex` claimed it as
an atom; it now asks `mapReadNarrowedAtomKind` first, as the list-element arm beside it does
(D4201).
