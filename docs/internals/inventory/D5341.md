### D5341 — an inferred record whose field is a lone literal type has no shape

**closed · was loud emit reject · `vl check` rc 0 · clause 2 · found closing D5289 · filed 2026-10-17 against master `cd07cb6a8`**

Repro:

    type W = "a" | "b"
    const x: "a" = "a"
    const w = { f: x }
    print(w.f)
    // vl check: rc 0.  vl run: emitProgram: object literal matches no union variant

Want:

    a

#### Mechanism

The un-annotated object literal's record type carries the field at the lone literal type
`"a"`, and the record shape lookup has no row for it: with a literal union declared it is
matched against that union's variants and misses, and with none declared the field's ref
valtype has no interned shape (`ref valtype with no interned shape`). Annotating the record
(`const w: { f: "a" } = …`) runs, so the gap is the inferred shape of a lone-literal field.
D5289's `struct_field_init` un-annotated cell reaches it through `src(0) as! "a"`.

The anon-row field code (`anonFieldCode`, `emit_classify.vl`) answered `FC_STR` for a literal
UNION and then put the field through `anonTySpellable`, which declines a `TyLit`, so a lone
literal field coded `-1` and the record interned no row. Fixed there: a lone literal type
stores its base scalar (`litBaseTy`), the slot the declared twin gets through
`tyScalarBaseIs`. Graded by `record-lit-lone-literal-field.matrix.vl` (26 un-annotated cells
refused before, 64 of 64 run after) and `tests/cases/structs/record-lit-lone-literal-field.vl`.
