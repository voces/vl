### D3399 — a `??` over two reads of a hole's `i32 | null` map lowers to the box while its consumer reads the result at the template

**check-clean invalid wasm · clause 1 · open · found by lane MH's map-read grid (`nuli32_coalread` cells) · the same on master `8df60e472` · filed 2026-09-30 against master `8df60e472`**

Repro:

    type H = { m: {[i32]: i32 | null} }
    function mk(): H {
      const v: {[i32]: i32 | null} = Map()
      v[3] = 7
      { m: v }
    }
    function use(r) {
      print(r.m[9] ?? r.m[3])
    }
    use(mk())
    // vl check: rc 0.  vl run: invalid module inside `use`, expected i32, found (ref $type)

Want:

    7

#### Mechanism

The `??` result is a deferred hole (`HD_COAL`), and neither `holePinReadOf` nor any consumer
resolves it at a map pin, so `print` reads the result as the template's `i32`. The fused
lowering (`emitMapGetOrUnionBox`, the value union with a null member) builds the box, since the
default can be null, and `print` receives a ref. The same shape over a plain `i32` map,
`print(e[9] ?? r.m[8])` with both keys missing, runs and prints `0` where the declared
spelling prints `null`: there the lowering declines the box because no value box is registered.
Resolving `HD_COAL` at the pin for every consumer is what #3282 tried and parked; this row is
the map-read slice of it.
