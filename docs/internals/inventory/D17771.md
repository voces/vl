#### Mechanism

Traced, not fixed (COV-CALL, 2026-11-28, time-boxed). The elaboration keys `apN` the same way for
the literal and the bound receiver: `?apN.0 = ((_) => _)[]#6` (the set `{inc6}` held open), plus
the closed `?apN.0 = ((i32) => i32)[]` and `?inc6.0 = i32`; the `.map` callback's value key is
the set-keyed instance in both (`elabValueKeys`). The literal is stamped by the same branch of
`elabHeldFnLitStamps` as the bound one's initialiser, and no set is tagged at emit. The refusal is
the IR's: in the set-keyed instance, `r[0](5)` calls a closure whose type stays `(_) => _`, with
no plain call key (`callRefPlainKey`) and no tag arms, so `callRhs` (ir_build.vl) misses as
`indirect call`. With the list bound, the same instance lowers, so the binding's place closes the
element there (the holder classes, `eplPlaceOf`, as in D17768) where the literal's place does
not. Parked (coordinator, 2026-11-28): the bound receiver's epl place closes the element and the
literal receiver's doesn't; find the edge, the holder-class territory of D17768. Second pass
(START-2, 2026-11-28, time-boxed, WIP on branch `start2-d17771`): the elaboration's stamp lives in
`nodeRepTyIx` (`repStampNode`), not `elabNodeReps`. On COV-CALL's elab stamp of the unbound literal,
three readers taking it make the witness print `6`: `monoWalk`'s generic-element path in the
`ArrayLit` arm (the bound literal's `eplValueSig` path), `monoCoerceListCbArg`'s receiver and lambda
parameter, and `exprTyOf`. It loses nine `@run` cases (`lambda-through-const-list-element*.vl`,
`hole-fn-list-element-past-zero-own-calls.vl`, `map-receiver-builds-at-its-own-type.vl`, …): one
stamp element given to every element of a literal whose elements are at different instances.
The reader must take the stamp per element, or only where the place gives no sig at all.

Third pass (START-2, 2026-11-28, parked by the coordinator after four cuts; branch
`start2-d17771-recut`). The witness needs the literal's stamp to reach its elements (the stamp is
from the held-value path, `ht`): mono's `monoWalk` ArrayLit arm delivers an element whose place
(`eplValueSig`) closes nothing at the stamp's element. Handing that to every stamped literal's
elements loses 7 of the 9 `@run` cases above, so the question is which elements it is owed to.
- Cut 1 (#10830, unlanded): only literals called on in place (`monoRecvLits`). Runs all 9 and the
  witness; refused as a site rung keyed on receiver syntax.
- Cut 2: stamp an element no call instanced (`monoElemTakenSig`, written by `monoOpenCallAtElems`),
  decided after the walk. Loses 7: D10893's constant-element call (`gs[k](…)`, `constListFnElemDecl`)
  instances the element's decl without writing it. Adding elab's call keys (`elabDeclCallKeyed`)
  over-answers: `inc6` is call-keyed through `apN`'s parameter yet has no instance mono delivers.
- Cut 3: one record written at the coercion (`monoCoerceFnValueTys`), stamp after every coercion.
  Loses the same 7: those elements are never delivered as values at all; the call is lowered as a
  direct call to the decl, so a stamp delivery breaks it. The fact owed is "the literal is read as a
  value", not "no instance".
- Cut 4: a literal whose every read is a D10893 constant-element call takes no stamp, decided in elab
  before the call rewrite (`elabLitOnlyElemCalled`; read after the rewrite, the calls name renamed
  instances). 8 of 9 hold; `hole-fn-list-element-past-zero-own-calls.vl` moves: a literal read through
  an index call that is not D10893's (`constListFnElemDecl` -1) has elements instanced by a path that
  writes neither `monoElemTakenSig` nor `monoElemAtSet` (the tagged-set path's own table).
What a close needs: one per-element "delivered or called directly" fact written by every path that
instances a list element (the coercion, `monoElemsAtSet`, D10893's direct call, and the one cut 4
did not find), then the stamp for an element of a value-read literal that none wrote.
