### D4910 — `is K[]` inside a generic instance answers by the instance's element type, so an empty list fails a disjoint `K[]`

**closed 2026-10-15 — now prints `1` · was check-clean silently wrong value, clause 1 · an `is K[]` whose element type is disjoint from the instance's at some list depth now tests the value: true exactly when every list at that depth is empty (D4771), at a `V[]`, a bare `V`, a `V[][]` and a record field; a region it narrows that reads the receiver ([D4911](D4911.md)) and a union receiver ([D4912](D4912.md)) are closed too · found on lane D4551 · related to D4778, D4779 · filed 2026-10-15 against master `687f37dd5` · pin: `tests/cases/generics/is-list-in-instance-tests-emptiness.vl`**

Repro:

    function probe<V>(v: V[]) {
      if v is f64[] { return 1 }
      0
    }
    const e: i32[] = []
    print(probe(e))
    // PRINTS 0

Want:

    1

#### Mechanism

A generic instance folds `v is K[]` statically from the instance's element type
(`monoStaticIsResult`, through `emitIsTest`), so `V = i32` answers `false` for `f64[]` with no
look at the value. The value-fit test D4771 built (`emitListFitIs`) only covers literal-set
leaves over i32/i64/string, so it does not reach this test. An empty list fits every list
type, so the right answer is `true` whenever `v.length == 0`.

#### Why it blocks D4551

The default that option (b) gives an unbound `U` becomes observable through this
test. `const q: U[] = []` followed by `q is f64[]` prints `false` under an i32 default and
`true` under an f64 default. The same holds transitively through any generic that receives
`q` and tests `is`.
