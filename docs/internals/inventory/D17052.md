### D17052 — a union that names a union alias as a member keeps the alias as a nested box in its rep, though its type and storage are the flat union

**runs today and must keep running · IR rep defect · the program runs; an IR record retag of it would be unsound, so the IR leaves the argument a named `argument coercion` miss · found by lane IR-M1's RRowRetag lowering check · filed 2026-11-22 against master `2934a5208`**

Repro:

    type IS = i32 | string
    type U = IS | f64
    type W = i32 | string | f64
    function count(r: { u: W[] }) { return r.u.length }
    const r1: { u: U[] } = { u: [1, "q", 2.5] }
    print(count(r1))
    // vl run: prints 3. Under VL_IR_SHADOW=2 the start body is `uncovered argument coercion`:
    // field `u`'s element rep is a box of `[box(i32, string), f64]` on the argument and a box of
    // `[i32, string, f64]` on the parameter; both record types sit on one struct heap.

Want:

    3

#### Mechanism

`U`'s rep keeps `IS` as one arm, itself a box, where the checker reads `U` as the flat union `W`
and legacy stores both records on one struct heap (`recordHeapOfTy`). The two element reps do not
lower alike kid by kid (`repsLowerAlike` in `compiler/ir.vl`), so the IR may not retag one record
as the other; the nested arm is the rep's, not the storage's.

#### Ablation

| ingredient | outcome | needed? |
| --- | --- | --- |
| `U` names the alias `IS` (`type U = i32 \| string \| f64` instead) | covered | **yes** |
| the parameter spelled apart from the argument (`count(r: { u: U[] })` instead) | covered: one rep on both sides | **yes** |
| the list (`u: U` and `u: W`, a field read under `is`) | same miss at the field's own box | no |
| the record (`count(xs: W[])` with `const xs: U[]`) | still a miss, at the list's own coercion | no |

#### Grading list
