### D3585 — `x! is O` parses as `x !is O`, so a TS-style assertion before `is` silently negates the test

**closed · now a loud check reject at the parse stage (`parse error`): `VL has no postfix `!` (non-null assertion), and `x! is O` is not `x !is O`; write `x is O` to test the type, or `x !is O` to negate the test` · was check-clean silently wrong, printing `false` · owner ruling A, 2026-11-02 · found by the #3356 review · filed 2026-10-03 against master `030a90e52` · fixture `tests/cases/parser/postfix-bang-before-is-is-refused.vl`**

Repro:

    type O = { n: i32 }
    const x: O | null = { n: 1 }
    print(x! is O)
    // was: printed false
    // now: 3:8: VL has no postfix `!` (non-null assertion), and `x! is O` is not `x !is O`; …

#### Mechanism

`parseUnary` reads `BANG` followed by `IS` as the negated guard `!is` whatever the spacing, so
`x! is O` is `!(x is O)`. D3555's postfix-`!` arm cannot take this case, because `!is` is the
legal spelling of the same two tokens. The tokens carry their columns, so `!` written against
its operand and apart from `is` (`x! is`) can be told from `x !is` and refused with D3555's
message. Whether to key a parse on whitespace was a language question. Owner ruling A
(2026-11-02, DECISIONS.md §"`x! is O` is refused"): `postfixBangBeforeIs` refuses a `!` written
against the token before it and apart from `is`, names both spellings, and drops the `!`, so the
parse recovers as `x is O`. `x !is O`, `x!is O` and `x ! is O` stay the negated test.
