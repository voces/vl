### D3585 — `x! is O` parses as `x !is O`, so a TS-style assertion before `is` silently negates the test

**check-clean silently wrong · open · pre-existing, the same on master `fae55dec2` · found by the #3356 review · filed 2026-10-03 against master `030a90e52`**

Repro:

    type O = { n: i32 }
    const x: O | null = { n: 1 }
    print(x! is O)
    // PRINTS false

#### Mechanism

`parseUnary` reads `BANG` followed by `IS` as the negated guard `!is` whatever the spacing, so
`x! is O` is `!(x is O)`. D3555's postfix-`!` arm cannot take this case, because `!is` is the
legal spelling of the same two tokens. The tokens carry their columns, so `!` written against
its operand and apart from `is` (`x! is`) can be told from `x !is` and refused with D3555's
message. Whether to key a parse on whitespace is a language question, so this row waits for
an owner ruling before it is closed.
