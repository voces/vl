### D7181 — a lambda written into a generic-initialized `let` inside a generic called at two types is lifted once, and the second instance's call traps

**loads then traps · `vl check` rc 0 · clause 1 · found closing [D7142](D7142.md) · the same on master `6a89bc66d` · filed 2026-10-19 against master `6a89bc66d`**

Repro:

    function other<V>(v: V) { print("O"); print(v) }
    function g<T>(x: T) {
      let k = other
      k = (n) => { print("L"); print(n) }
      k(x)
    }
    g(3)
    g("s")
    // vl check: rc 0.  vl run: L, 3, then wasm trap: indirect call type mismatch in `g$1`

Want:

    L
    3
    L
    s

#### Mechanism

Partly located. Both instances of `g` reference one lifted `$__lambda_0`, typed at `i32`, so
`g$1`'s call through `k` at `string` makes a `call_indirect` whose type the table entry does
not have. Why the lambda is not lifted per instance has not been probed.
