### D7181 — a lambda written into a generic-initialized `let` inside a generic called at two types is lifted once, and the second instance's call traps

**closed 2026-10-19 by lane L1 · runs, prints `L 3 L s` · was loads then traps · `vl check` rc 0 · clause 1 · a lambda parameter typed at another declaration's type variable now takes, per instance, the one call type its value reaches there (`vrCalleeTy` with the frame's own type parameters held open), so the lambda is lifted once per instance; the same for its result · pins: `tests/cases/closures/generic-lambda-written-let-called-in-two-instances.vl` (direct call; returned; nullable, i32 and f64 instances) · found closing [D7142](D7142.md) · the same on master `6a89bc66d` · filed 2026-10-19 against master `6a89bc66d`**

Repro:

    function other<V>(v: V) { print("O"); print(v) }
    function g<T>(x: T) {
      let k = other
      k = (n) => { print("L"); print(n) }
      k(x)
    }
    g(3)
    g("s")
    // vl check: rc 0.  vl run: L, 3, then wasm trap: indirect call type mismatch in `g$1`

Want:

    L
    3
    L
    s

#### Mechanism

Both instances of `g` referenced one lifted `$__lambda_0`, typed at `i32`. The lambda's
parameter `n` is typed at `other`'s `V`, which no instance binding substitutes, so every
instance lifted it at the default. Each instance now asks the value-flow question for the one
call type the lambda reaches there, with its own type parameters held open, and pins the
parameter and result at it.
