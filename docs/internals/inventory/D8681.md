### D8681 — a literal binding adopted by a declared record that boxes its field is also handed to a hole that reads the field bare

**closed · now runs, prints `5` / `4` · was check-clean invalid wasm, clause 1 · present on master `a0af58b15` · found closing [D8620](D8620.md) · filed 2026-10-20 against master `a0af58b15` · closed 2026-10-31 against master `cb178881` with [D14426](D14426.md): the instance is typed at the checker's binding and the parameter is stored at the record the argument is built at · fixture `generics/hole-instance-typed-at-binding-stored-at-build.vl`**

Repro:

    type J = { f: i32 | null }
    function rd(r) { return r.f + 1 }
    const o = { f: 4 }
    print(rd(o))
    const j: J = o
    print(j.f ?? 0)
    // vl check: rc 0.  vl run: the emitted module failed to validate (inside `rd` before D8620's close, at `const j: J = o` after it)

Want:

    5
    4

#### Mechanism

`o` holds only a literal, so the record covariance ruling lets it adopt `J` at `const j: J = o`,
and the value has `J`'s boxed field. The checker still binds `rd`'s hole at `o`'s own
`{ f: i32 }`, so `r.f + 1` is accepted as `i32` arithmetic over a value whose field is boxed.
Handing `j` to `rd` instead is refused at check (`'+' is not defined for i32 | null and i32`),
which is the answer `rd(o)` is owed once `o` adopts `J`. Emit has no row that serves both uses:
D8620's close builds the literal at its own row for the hole, and the adoption then stores that
row into `J` unconverted. The close is in the checker, which accepts `rd(o)` at the
pre-adoption type.
