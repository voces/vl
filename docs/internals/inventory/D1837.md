### D1837 — the rep descriptor cannot answer `reflist` for a NULLABLE-element list, because a `reflist` answer promises an interned row the collect pass never mints for that shape

**runs today and must keep running · a REFUTATION PIN for the rep-descriptor campaign's third phase-3 landing, refused 2026-09-07 against master `6f76e471a` · the candidate moved 35 modules `runs → not-runs`, six of them compiler traps · `docs/internals/rep-descriptor-campaign.md` §9.6**

#### Mechanism

`repOfArray` declines a nullable element, so `vtKindOfType`'s ladder owns the answer. The
obvious phase-3 move is to cover it: a nullable cell is a reference — a `ref null` niche or a
box — for every inner except the two that niche into a spare i32 (`boolean | null` at sentinel
2, a literal union at `-1`). The oracle endorses it completely: `reflist` LEFT-ONLY falls by
**exactly** its census in each population (4,088 and 185) with **CONTRADICT 0**.

**Byte identity refuses it.** The descriptor is read by more than `vtKindOfType`: the ref-list
slot, shape and collect consumers read it too, and a `reflist` answer sends them to look up an
interned ref-list row. The collect pass mints one for a MAP element and for a NESTED-ARRAY
element — which is why those two landings were byte-identical — and mints **none** for a
nullable element. The answer is therefore a promise the rest of the emitter cannot honour:
`ref index access but ref array type not collected` (16), `ref valtype with no interned shape`
(11), `ref indexed assignment but ref list type not collected` (1), `ref .push but ref list
type not collected` (1), and six compiler traps.

**The contract this row states for the descriptor, and the reason it is a row rather than a
note:** `reflist` is answered ONLY where the collect pass has interned the row. Any producer —
`repOfArray`'s flat arm, `rtListVKind`, or a future one — that answers `reflist` for a shape
collect never minted is making a promise the ref-list slot, shape and collect consumers cannot
keep, and the failure is loud-or-trapping rather than a wrong rep. Covering the nullable element
therefore needs the collect pass to intern the row first — a build, not a projection.

**Its corpus price is already carried by the standing gate**, which is why no new named set is
filed: all 16 corpus cells the candidate moved are already `named/` members from five earlier
sets in this same territory (`d341` x8, `d451` x5, `d775`, `d812`, `d1630`), none from the
derived `cells/` half, and `regress.py` against the candidate reports
`REGRESSION — 16 behavioural class(es) stopped running`.
