### D4032 — a lambda parameter annotated `T[]` in a generic body, passed to a generic function, is refused at emit

**loud emit reject · `vl check` rc 0 · clause 2 · found in the #3538 review (lane DV, D4030) · filed 2026-10-11 against master `98a4ed71b`**

Repro:

    function rev<T>(self: T[]): T[] { self }
    function h<T>(xs: T[]): i32 {
      const k = (ys: T[]) => rev(ys).length
      k(xs)
    }
    print(h([1, 2, 3]))
    // vl check: rc 0. vl run: emitProgram: monomorphize: expected an array argument for
    // `self` in a call to `rev`

Want:

    3

#### Mechanism

Not yet ablated past the table below. The monomorphizer's argument classifier finds no
array type for `ys` at the inner call, so the lambda's annotated `T[]` parameter is not
substituted with the instance's element type where the call to the generic `rev` is
re-pinned. The same refusal fires for `std:array`'s `reverse` and `sorted`, through a
member call (`ys.reverse()`) or a plain one (`sorted(ys, lt)`), with one instance or two,
and when the callee returns `T` instead of `T[]`.

#### Ablation

| ingredient removed | outcome | needed? |
| --- | --- | --- |
| the annotation on `ys` (`(ys) =>`) | runs, prints 3 | **yes** |
| the lambda (a nested `function k(ys: T[])`) | runs, prints 3 | **yes** |
| the generic call inside the lambda (`k(rev(xs))`, `k` reads `ys.length`) | runs, prints 3 | **yes** |
| the type parameter (`h(xs: i32[])`, `ys: i32[]`, `std:array` `reverse`) | runs, prints 3 | **yes** |
| a lambda that CAPTURES `xs` instead of taking `ys` (`() => xs.reverse()`) | runs | **yes** |
| `self` (callee's first parameter is `xs: T[]`) | refuses, naming `xs` | no |

#### Grading list

`std:array`'s `reverse` through `ys.reverse()` and `sorted(ys, lt)` in the same position;
the two-instance spelling (`h([1, 2, 3])` and `h([1.5])`).
