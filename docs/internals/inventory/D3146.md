### D3146 — a nullable field value in a record argument to a record-pattern generic is refused when a declared record shares the field names

**loud emit reject · clause 2 · found by the #3278 round-3 review · filed 2026-09-29 against master `fc4b2159f`**

Repro:

    import { toString } from "std:fmt"
    type D = { m: { x: i32, y: i32 }, n: i32 }
    function g<T>(b: { m: T, n: i32 }): T { b.m }
    const z: i32 | null = 4
    const e = g({ m: z, n: 1 })
    if e != null { print(toString(e)) } else { print("n") }
    // vl check: rc 0.  vl run: emit error, monomorphize: unsupported argument type for `b` in a call to `g`

Want:

    4

#### Mechanism

Not traced. The literal `{ m: z, n: 1 }` has the same field names as `D`, whose `m` has a
different type. The literal's row, or the spelled pin the monomorphiser tries for it, does not
reach a shape that binds `T` at `i32 | null`, so the call refuses.
