### D3146 — a nullable field value in a record argument to a record-pattern generic is refused when a declared record shares the field names

**closed 2026-10-05 by lane C2 with [D3674](D3674.md) — the witness prints `4` · was a loud emit reject, clause 2 · found by the #3278 round-3 review · filed 2026-09-29 against master `fc4b2159f` · fixture `tests/cases/generics/record-pattern-arg-claimed-by-declared-name.vl`**

Repro:

    import { toString } from "std:fmt"
    type D = { m: { x: i32, y: i32 }, n: i32 }
    function g<T>(b: { m: T, n: i32 }): T { b.m }
    const z: i32 | null = 4
    const e = g({ m: z, n: 1 })
    if e != null { print(toString(e)) } else { print("n") }
    // vl check: rc 0.  vl run: emit error, monomorphize: unsupported argument type for `b` in a call to `g`

Want:

    4

#### Mechanism

The literal `{ m: z, n: 1 }` has the same field names as `D`, whose `m` has a different type, so
the argument's pin is the declared name `D`, and a shape pattern has no fields to pair with a
name. Binding against `D`'s own fields would bind `T` to `{ x: i32, y: i32 }`, the wrong record;
the fix binds against the argument's own arena type spelled by its fields (`monoArgBindSpelling`),
which binds `T` at `i32 | null`.
