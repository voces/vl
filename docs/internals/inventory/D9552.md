### D9552 — a list built from an un-annotated function parameter, returned and read by `.map`, calls an unknown function

**closed 2026-10-22 by lane-D9550 · runs, prints `4` · was loud emit reject, `call to unknown function`, `vl check` rc 0 · clause 2 · closed in two steps: the flow table now takes a `.map` callback's pin over a list whose element is an un-annotated parameter's value (`ffIsElemCallback`, fn_flow_shadow.vl), and a call's closed list result is read from the instance its callee was renamed to rather than from the template, a non-list result left to the template since an instance minted at a generic argument can still split (`monoCallInstRetTy` from `monoPinnedRetAnnTy`, emit_mono.vl) · fixture `closures/hole-fn-list-returned-inline-call.vl` · residue [D9602](D9602.md) · found closing [D9501](D9501.md) · filed 2026-10-22 against master `6b307f6ac`**

Repro:

    function inc(a) { return a + 1 }
    function deliver(g) { return [g, g] }
    const v = deliver(inc)
    print(v.map((f) => f(3))[1])
    // vl check rc 0.  vl run: emit error: emitProgram: call to unknown function

Want:

    4

#### Mechanism

Two steps. The flow table takes a callback's pin on a list only when the list's element type
holds a function (`ffIsElemCallback`, fn_flow_shadow.vl), and `[g, g]` with `g` un-annotated
types as a list of a bare type variable, so no pin reached `deliver`'s slot. With the pin taken,
the call `deliver(inc)` is renamed to its instance, whose result is closed, but the receiver was
still typed from the template's open return (`monoPinnedRetAnnTy`, emit_mono.vl).
