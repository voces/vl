### D14428 — a member of a hole-called list that also escapes to a closed function slot loses its per-call split, and a set-typed argument reaches the closure ABI

**loud emit reject · clause 2 · waits on per-tuple instancing of members at a tuple that holds a set (γ) · found grading c-3's un-annotated stamp against the annotated face · filed 2026-10-27 against master `41c611055`**

Repro:

    function add(a, b) { return a + b }
    function cApply4(g, s) { return g(s, 2) }
    function cApply5(g, s) { return g(3, s) }
    const keep: (g: (a: f64, b: f64) => f64, s: f64) => f64 = cApply4
    print(keep(add, 1.0))
    function cThree(k, h) {
      const gs = [cApply4, cApply5]
      for f in gs { print(f(h, k)) }
    }
    cThree(0.5, add)
    // today: emit reject at 10:17, a function-value call has no interned signature — parameter 1 of type `` has no representation in the function-value ABI

#### Mechanism

Without `keep`, `cThree` runs only through the flow pin: `h` is passed as two closures, one
per type `g` is called at inside the members (`(f64, i32)` and `(i32, f64)`), and the list's
elements are closures that forward them. With `cApply4` also delivered to a closed slot, the
name-keyed pin of `cApply4`'s `g` no longer carries that split. The call `f(h, k)` then passes
`h`, a set-typed value with no closed type, to the closure ABI, which has no rep for it.

The direction is to instance each member at the call's tuple, set included, and call it
directly. A token rep for a set-typed closure parameter is not the fix: `add` is reached at two
types here, so no single closed type exists for the token to stand for.

#### Ablation

| ingredient removed | outcome on `41c611055` | needed? |
| --- | --- | --- |
| `keep` (no member escapes to a closed slot) | runs | **yes** |
| `keep` delivered `cApply5` in an annotated list instead | same emit reject | no, any member's escape is enough |
