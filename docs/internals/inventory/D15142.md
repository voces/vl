### D15142 — a parameter called at two signatures and returned has no type to return it at

**closed 2026-11-03 — the repro now RUNS. Was: loud emit reject · clause 2 · `monomorphize: unsupported argument type for f in a call to lap`, with the split plan on and off · filed 2026-11-03 against master `38b42426`**

Repro:

    function lap(f) {
      print(f(2.5))
      print(f(3))
      return f
    }
    function go(k: i32) { const r = lap((a) => a + k); print(r(4)) }
    go(1)

Want:

    3.5
    4
    5

#### Mechanism

`lap` calls `f` at two signatures, so `f` holds a record, and returning it was a read other than
a call, which declined the record. Now `monoBodyReadsOtherThanCalled` admits a return of the
parameter, and the instance returns the record (`monoReturnedBundlePin`). The caller selects:
the elaboration notes, per call, the member its value is used as (`elabCallResultMember`), from
a `const` holder every read of which calls it at one signature, an immediate call, or a dropped
statement, and the holder's member type (`elabHolderMemberTy`). Emit picks the member after the
call and types calls through the holder from that fact. Other uses refuse at the call: D15144,
D15145.

#### Ablation

| ingredient removed | outcome | needed? |
| --- | --- | --- |
| `lap`'s call at `2.5` (one signature) | runs | **yes** |
| the use of the result (`lap(...)` as a statement) | still refuses | no |
| the capture of `k` (a top-level `lap((a) => a + 1)`) | still refuses | no |
| an annotated result type `(x: i32) => i32` | check reject, `f(2.5)` against `i32` | n/a |

#### Grading list

The unused-result spelling `function go(k: i32) { lap((a) => a + k) }`, and the top-level
`const r = lap((a) => a + 1); print(r(4))`.
