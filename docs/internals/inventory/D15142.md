### D15142 — a parameter called at two signatures and returned has no type to return it at

**loud emit reject · clause 2 · `monomorphize: unsupported argument type for f in a call to lap`, with the split plan on and off · filed 2026-11-03 against master `38b42426`**

Repro:

    function lap(f) {
      print(f(2.5))
      print(f(3))
      return f
    }
    function go(k: i32) { const r = lap((a) => a + k); print(r(4)) }
    go(1)
    // vl check: rc 0.  vl run: emitProgram: monomorphize: unsupported argument type for `f` in a call to `lap`

#### Mechanism

`lap` calls `f` at two signatures, so `f` would hold a record, but `lap` also returns it, and a
return is a read other than a call. `monoParamReadOtherThanCalled` declines the record, and the
split plan cannot help either: one instance per signature still returns one function value
whose type the caller has to name. `lap`'s result would be the record, and `r(4)` would select
its member at `(i32) => i32`.

#### Ablation

| ingredient removed | outcome | needed? |
| --- | --- | --- |
| `lap`'s call at `2.5` (one signature) | runs | **yes** |
| the use of the result (`lap(...)` as a statement) | still refuses | no |
| the capture of `k` (a top-level `lap((a) => a + 1)`) | still refuses | no |
| an annotated result type `(x: i32) => i32` | check reject, `f(2.5)` against `i32` | n/a |

#### Grading list

The unused-result spelling `function go(k: i32) { lap((a) => a + k) }`, and the top-level
`const r = lap((a) => a + 1); print(r(4))`.
