### D15181 — a record in a list or record literal argument is not built at the wider instance a held argument pins when a declared type spells the record's own shape

**closed · now runs, prints `7` · was check-clean invalid wasm, clause 1 · a record or nested-list literal holding a record built at a wider row is stamped built at that row (`recObjLitBuild`, `recLitPartBuiltTy`, check_bind_adopt.vl; queued by check_container_lits.vl), and a literal argument the record solve stamped pins its generic's parameter at that build (`monoLitBuiltTy` in `monoArgClosedPin` and `monoArgPinTyIx`, emit_mono.vl) · fixtures `soundness/record-built-wider-in-literal-beside-declared-shape-runs.vl`, `soundness/fresh-call-in-list-at-wider-instance-beside-declared-shape-runs.vl` · found grading [D15180](D15180.md)'s grid · filed 2026-11-03 against master `b8e3f740`, closed 2026-11-03**

Repro:

    type Circle = { r: i32 | null }
    type K = { r: null }
    function mkcall() { { r: null } }
    const cw: Circle = { r: 3 }
    function f<T>(b: T, a: T[]): T { a[0] }
    print(f(cw, [mkcall()]).r ?? 7)
    // was: vl check rc 0, then vl run: the emitted module failed to validate inside `f`

Want:

    7

#### Mechanism

The held `cw` pins `f` at `Circle`, so `a` is a `Circle[]`. The list literal's element is
`mkcall()`'s record, whose own type is `{r: null}`. With `K` declared, that shape has a struct row of
its own, so the element is built at `K`'s row, and the list reaches `f@Circle` without the element
being built at `Circle`. With no declared type of that shape, the element is built at `Circle` and the
program runs. The non-generic spelling, `function f(b: Circle, a: Circle[])`, runs either way.
