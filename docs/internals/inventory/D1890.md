### D1890 — an f64 target has no contextual-literal rule, so an integer literal past the i32 range refuses there while the same literal adopts the strictly LESS precise f32

**loud check reject · 7 delivery positions plus mixed arithmetic · filed 2026-09-07 against master `4b36f61b1`**

Repro:

    const a: f64 = 2147483648
    print(a)
    // vl check: 1:16: i64 doesn't fit in f64 — the conversion is lossy and must be
    // made explicit with `as` (write `x as f64`).
    // `const a: f32 = 2147483648` runs and prints 2147483648.

#### Mechanism

An integer literal types `i32` while it fits and `i64` once it does not, and the only
implicit route into an `f64` slot is the widening lattice's `i32 -> f64` edge
(`numWidensName`, `compiler/typecheck.vl`). So the flow site sees an `i64` VALUE and takes
the lossy-edge rejection, which is right for a value and wrong for a literal: the f32
target does not rely on the lattice at all, it has its own exactness-gated adoption
predicate (`isF32AdoptingLitExpr`, "the single predicate every f32 grant site asks",
`docs/internals/contextual-f32-literals-design.md`), and that predicate reads the LEXEME,
so it spans the whole integer range. f64 was never given the twin — the `i32 -> f64` edge
covered every literal anyone tried, and the literals it does not cover are exactly the ones
between 2^31 and 2^53, every one of which f64 holds exactly.

The refusal is uniform, not positional: binding, return, argument, list element, struct
field, global assignment and a function-local binding all refuse identically, and so does
`print(mkF64() + 9000000000)` (`operator '+' mixes f64 and i64`). The fix therefore belongs
in the shared adoption predicate beside the f32 one, not at a delivery site.

#### Ablation

| ingredient removed | outcome | needed? |
| --- | --- | --- |
| the literal exceeds the i32 range (`2147483647`) | runs, prints `2147483647` | **yes** |
| the target is `f64` (use `i64`) | runs, prints `2147483648` | **yes** |
| the target is `f64` (use `f32`) | **runs**, prints `2147483648` | **yes** |
| it is a bare literal (`9000000000.0`) | runs | **yes** |
| it is a bare literal (`9000000000 as f64`) | runs | **yes** |
| the delivery position (7 of them) | refuses at every one | no |

#### Grading list

`const a: f32 = 2147483649` and `const a: f32 = 16777217` must keep refusing — the f32
predicate is exactness-gated and the f64 twin has to be too, so `const a: f64 =
9007199254740993` (2^53 + 1) must still refuse after the fix while `4503599627370496`
(2^52) starts running. The mixed-arithmetic spelling `mkF64() + 9000000000` is the second
face and is not fixed by the assignment site alone. `const a: f32 = 4294967296` runs today
and is the control that must not move.
