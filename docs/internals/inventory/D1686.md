### D1686 — [CLOSED 2026-09-06] a container the covariant-write closure cannot reach a handle of: its call result is delivered under no name, or an intermediate on the path to it is given one

**now a loud emit reject by DESIGN (that is the close) · was the same refusal with no spelling that lifted it · filed 2026-09-06 against master `c17d0d53e`, closed against `4805d8fae` · D1682's residue · 0 corpus cells · fixture `tests/cases/unions/list-covariant-readonly-view-call-result.vl`**

The owner ruled (2026-09-06, `open-rulings.md` §D) that the design owes a way to SAY a
parameter is read-only rather than a whole-program flow analysis. `readonly T[]` — a
read-only, covariant, shallow list view — is built, and the witness below runs the moment
`mk`'s parameter and `Box.xs` are spelled `readonly Shape[]`. What stays refused is the
MUTABLE spelling, and that refusal is the design's: a mutable list handed somewhere this
program cannot point at may be written there, and the copy would then be observable. The
message names `readonly` as the spelling that works.

Repro:

    type Circle = { r: i32 }
    type Sq = { s: i32 }
    type Shape = Circle | Sq
    type Box = { xs: Shape[] }
    function __other() {
      const w: Shape[] = []
      w.push({ s: 3 })
      print(w.length)
    }
    function mk(v: Shape[]): Box { { xs: v } }
    function f() {
      const a: Circle[] = [{ r: 7 }]
      const b: Shape[] = a
      print(mk(b).xs.length)
    }
    f()
    // vl check: rc 0.  vl run: emit error, covariant list delivery.

#### Mechanism

Nothing writes either list, so the copy is unobservable and the program is legal. D1682 gave a
nameless container an identity by borrowing the ones around it: a returned literal is reached
through the destinations of its function's calls, a nested literal through the enclosing
container's key plus a path. Both borrow a NAME, and two shapes have none to borrow.

`mk(b).xs.length` consumes the call result in place, so `cwCallDestName` has no binding,
assignment or parameter to add and `cwRetDestNames` returns false. `const q = o.inn` breaks the
other one: the escape is filed at `o` under the path `inn.xs`, `q.xs` spells no such key, and
`cwChainSealed` refuses to claim a path whose intermediate is handed a name — correctly, since
a write through `q.xs` is one the scan would otherwise miss.

Closing it is a container identity that is itself a handle rather than a name: the projection
`o.inn` and the call result `mk(b)` are each one value, and the closure would have to carry
NODES beside names. That is the same generalisation both shapes want, which is why they are
one row.
