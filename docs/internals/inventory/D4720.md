### D4720 — a list literal of a string, `null` and a record builds invalid wasm, or is refused when the record comes first

**closed 2026-10-14 — the witness prints `3` · an un-annotated literal whose element the checker types as a nullable union of two or more non-null members now names that union's list (`arrLitNulUnionElemName`), and a record element of such a literal takes the union kind rather than the struct kind (`arrLitElemKind`) · fixture `tests/cases/arrays/mixed-nullable-record-string-literal.vl`, matrices `mixed-nullable-record-string-list.matrix.vl` (27 un-annotated cells refused before, 64 of 64 graded run) and its generic twin · also closes [D2418](D2418.md) and [D3572](D3572.md) · was check-clean invalid wasm · clause 1 · found writing D4688's second delivery position · filed 2026-10-14 against master `a254c3da4`**

Repro:

    const f = ["t", null, { x: 1 }]
    print(f.length)
    // vl check: rc 0.  vl run: invalid module, type mismatch in the module's top-level code

Want:

    3

#### Mechanism

The checker types the element `TyNullable(TyUnion(string, {x: i32}))`. The literal's element
namers answered "" for a nullable over a union, so no union row was registered for the
un-annotated literal and it built a struct list with the string coerced into the record's
`struct.new` — the invalid wasm. With the record first, the object-literal arm of
`arrLitElemKind` answered the struct kind while the element name was the nullable union, and the
`null` then had no struct to take its type from. Every order of a nullable union of two or more
non-null members was the same family: scalars beside a string refused `union atom has no value
box`, and a declared record pair built invalid wasm too.
