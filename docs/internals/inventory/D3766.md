#### Mechanism

The multi-value step follows a record from the op that makes it to the op that uses it, and
an `if`'s `end` was neither. So a producer call ending an arm was "kept", its twin returned a
struct, and `rotateBy`'s field-only `parent` received a box. The step now records an `if`
whose one result is a non-null record and that no branch targets as a MERGE. A merge whose
value reaches a field use (a `struct.get`, a field-only local, a field-only parameter, a
result twin's exit) leaves the record's fields instead: its block type becomes a
multi-value type, an arm ending in a producer call calls the twin that returns fields, an
arm ending in a `struct.new` loses it, an arm ending in a scalarized local reads its slots,
and any other arm (`sk.rootRotation`, a stored record) is read field by field at the arm's
end. Reading early is sound for the reason every twin is: the record type is never written.
A local read as an arm's value counts as a field use when the merge's own value is held as
fields (`lead`).
