### D17676 — a hole function's parameter returned from a closure that captures it, beside a record built from it, builds a module that fails to validate inside the closure

**check-clean invalid wasm · 1 spelling · filed 2026-11-26 against master `dfb9a8026` by COV-CALL, found writing D17578's positions**

Repro:

    type J = { f: i32 | null }
    function mk2() { return { f: null } }
    const dA: J = mk2()
    function viaReturn(y) {
      const b = () => y
      const h = { w: y }
      return b().f == null
    }
    print(viaReturn(mk2()))
    // vl check: rc 0.  vl run: invalid module inside `__lambda_0`, expected `{f:null}`, found `J`

Want:

    true

#### Mechanism

`viaReturn` is keyed at its hole binding `{ f: null }` with `#r.0` = `J` (D15173), so the capture of
`y` is stored at `J`'s row. The closure returns that capture at its own result type, `{f:null}`,
which is another struct. Neither legacy nor the IR converts the stored `J` back to the closure's
result row. D17578's close moves the IR's read of the capture to `J`'s row, which is the start of
the fix; the closure's result is the remaining part. This is the records part of the "place reads
at storage" series.
