### D10132 — an annotated function binding handed through a hole parameter into a generic's function-typed parameter has no instance

**loud emit reject · `vl check` rc 0 · `emitProgram: monomorphize: unsupported argument type for f in a call to app` · clause 2 · CAPABILITY: the same call made directly runs, and so does the hole parameter handing on a scalar · the `argument` un-annotated cell of `fn-result-list-union-narrowed-in-generic` · present on master `3931f9468` · filed 2026-10-22 against master `3931f9468`**

Repro:

    function app<T>(f: () => T): T {
      f()
    }
    const g: () => i32 = () => 4
    function take(a) {
      print(app(a))
    }
    take(g)
    // vl check: rc 0.  vl run: emitProgram: monomorphize: unsupported argument type for `f` in a call to `app`

Want:

    4

#### Mechanism

Not traced. Inside `take`'s instance at `() => i32` the argument `a` is a hole parameter bound to
a function type, and the monomorphizer's argument-type reader for a generic's function-typed
parameter has no arm for a hole carrying a function, so `app` gets no instance.

#### Ablation

| ingredient changed | outcome | needed? |
| --- | --- | --- |
| the hole, `print(app(g))` directly | runs, `4` | **yes** |
| the type parameter, `app(f: () => i32): i32` | runs, `4` | **yes** |
| a scalar through the hole, `app<T>(f: T): T` and `take(4)` | runs, `4` | **yes**, a function value |

#### Grading list

The `argument` un-annotated cell of `fn-result-list-union-narrowed-in-generic` and its `-open`
twin; the same call with `a` passed on to a second hole parameter.
