### D10132 — an annotated function binding handed through a hole parameter into a generic's function-typed parameter has no instance

**closed · runs, prints `4` · was loud emit reject, clause 2, CAPABILITY: the same call made directly runs, and so does the hole parameter handing on a scalar · closed in emit_mono.vl: `monoArgFnTypeName` reads a hole parameter's function type from the instance's pin · fixture `generics/hole-param-fn-value-into-generic.vl`, matrices `fn-result-list-union-narrowed-in-generic` (47 → 48 of 48), `fn-result-list-union-narrowed-in-generic-open` (47 → 48 of 48) and `fn-value-generic-compared-open` (30 → 31) · an un-annotated lambda narrower than a union result, handed on the same way, still refuses ([D10160](D10160.md)) · filed 2026-10-22 against master `3931f9468`**

Repro:

      f()
    }
    const g: () => i32 = () => 4

      print(app(a))

Want:

#### Mechanism

`monoArgFnTypeName` (emit_mono.vl) names the function type an argument delivers to a generic's
function-typed parameter. Inside `take`'s instance the argument `a` is an `Ident` whose node type
is still the hole, and no arm read it through the instance, so `app` got no instance. An
argument whose type carries a type variable now resolves through `monoExactPinTyOf` against the
calling instance's pin, and a closed function type there names the signature.
