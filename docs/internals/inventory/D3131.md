### D3131 — a closure returning a nullable-map record field leaves its result with no rep for the null test

**loud emit reject · clause 2 · pre-existing on master `a29230611` · found by the #3278 review grid's `mn_*_closure` cells · filed 2026-09-28 against master `a29230611`**

Repro:

    type H = { m: {[i32]: i32} | null }
    function f(): H {
      const v: {[i32]: i32} = Map()
      v[3] = 7
      { m: v }
    }
    const r = f()
    const g = () => r.m
    const e = g()
    if e != null { print(e[3] ?? -1) } else { print("null") }
    // vl check: rc 0.  vl run: emit error, emitProgram: bare null needs a struct-typed context

Want:

    7

#### Mechanism

Not traced. The closure's result is `{[i32]: i32} | null`, and the `null` in the `e != null`
test gets no nullable-map context from it. That context is what gives a bare `null` its heap
type, so the emitter refuses.

| the field a plain map, not `\| null` | runs, `7` | **yes** (the nullable map) |
| `e.length` instead of the `??` read | the same refusal | no |
