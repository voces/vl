### D3131 — a closure returning a nullable-map record field leaves its result with no rep for the null test

**closed 2026-11-01 · runs, prints `7` · was loud emit reject · clause 2 · `inferredRetMapSlotCore` (`emit_classify.vl`) reads an inferred map result's shape off the closed checked result type before the tail expression, whose shape for a field read through a nullable record was the string-keyed default · pin: `tests/cases/closures/closure-returning-nullable-map-field.vl` · found by the #3278 review grid's `mn_*_closure` cells · filed 2026-09-28 against master `a29230611`**

Repro:

    type H = { m: {[i32]: i32} | null }
    function f(): H {
      const v: {[i32]: i32} = Map()
      v[3] = 7
      { m: v }
    }
    const r = f()
    const g = () => r.m
    const e = g()
    if e != null { print(e[3] ?? -1) } else { print("null") }
    // vl check: rc 0.  vl run: emit error, emitProgram: bare null needs a struct-typed context

Want:

    7

#### Mechanism

The lifted closure's result valtype came from `inferredRetMapSlotCore`, which asked the tail
expression (`r.m`) for its map shape before the checked result type. Through a nullable record
field that answer was the string-keyed default, so the closure was lowered returning a
string-keyed map while its body built the `i32`-keyed one. Reading the shape off the closed type
first fixes the refusal and its clause-1 spelling (`print(e == null)` was invalid wasm).
