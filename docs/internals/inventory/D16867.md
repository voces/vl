**closed 2026-11-16 · runs, prints `103` · was check-clean invalid wasm, `vl check` rc 0, `vl run` invalid module at the write `b = a` · clause 1 · fixed in check_fit_rules.vl: an alias of a re-pointed literal binding (`recFreshOriginDecl`) is delivered through `recAdPushDecl`, as the binding's own read is, so its writes are handled with its literal; before, `recBuildPush` built only the initialiser at the arm · pin: `tests/cases/records/repointed-let-alias-to-union-arm.vl` · the `global_assign` un-annotated cell of `self-union-nullable-arm-field.matrix.vl` · found grading D16412 · filed 2026-11-16 against master `9648a5f2a`**

Repro:

    type Node = { v: i32, next: Node | null } | { e: i32 }
    function sumNode(n: Node | null): i32 {
      if n == null { return 0 }
      if n is { e: i32 } { return n.e * 100 }
      return n.v + sumNode(n.next)
    }
    let a = { v: 3, next: { e: 1 } }
    let b = { v: 3, next: { e: 1 } }
    b = a
    const v = b
    print(sumNode(v))
    // vl check: rc 0.  vl run: invalid module at `b = a`

Want:

    103

#### Mechanism

`const v = b` delivered to `Node | null` reached `b`'s literal through `recFreshOriginDecl` and
built it at `Node`'s arm (`recBuildPush`). `b` is re-pointed, so `a`'s record, still at its own
type, was written into a slot of the arm's type. The binding read directly (`sumNode(b)`) goes
through `recAdPushDecl`, which handles a re-pointed binding. The alias now does the same.
