#### Close

The backtrace, read off a `--names` seed, is a six-frame loop: `fnAssignRetKind` →
`ifTailAssignName` → `fnAssignCellEq` → `globalCellStructIdx` → `nulVariantIdxOfExpr` →
`cloRetValKind` → `fnAssignRetKind` again. Joining the arms compares `gd`'s cell with `gc`'s,
and `gc`'s cell is whatever `fc` returns. Three changes. The join is guarded per function
(`ifTailAssignNameGuarded`): re-entered, it declines, and the cell it asked about takes its map
shape from the checker's type on the call node, the re-entry answer D30 already gives
`inferredRetMapSlot`. Two map cells are then compared by map SHAPE, not type spelling, so
`gd: {[string]: S}` and an inferred `gc` agree. That also runs the acyclic spelling, which
refused on master (`bare null needs a struct-typed context`) when one arm cell was annotated and
the other was not. The guard alone left the witness as an emit reject, and a guard without the
recorded-shape answer made `fc`'s functype `i32` over a map body (invalid wasm). Graded: string,
`i32`-keyed `f64`, struct, list and string cells; a local cell as the other arm; `else if`; two-
and three-function chains; the witness inside a function. The nullable-cell arm is D2665.

#### Mechanism

`fc` has an inferred map return from its tail `if`, whose arms are assignments, and `gc`'s type
needs that return while the return needs `gc`'s type: D30's cycle. The `retMapFlight` guard
terminates it when both arms assign `gc`. With one arm assigning another cell (`gd`, or a local)
the cycle is not caught and the shape resolution recurses until the compiler's stack runs out.
The same program with both arms assigning `gc` compiles and prints `8`.
