### D2662 — a tail `if` whose arms assign two different module maps, called from one's un-annotated initializer, overflows the compiler's stack

**compiler trap · `call stack exhausted`, exit 70 · found while respelling D30's recursion witness for D2654 · filed 2026-09-26 against master `979323f83`**

Repro:

    type S = { a: i32 }
    function mkR(v: i32): {[string]: S} {
      const m: {[string]: S} = Map()
      m["a"] = { a: v }
      return m
    }
    let gd: {[string]: S} = mkR(0)
    let gc = fc(false)
    function fc(c: boolean) {
      if c { gc = mkR(8) } else { gd = mkR(7) }
    }
    const gcv = gc["a"]
    if gcv != null { print(gcv.a) }

#### Mechanism

`fc` has an inferred map return from its tail `if`, whose arms are assignments, and `gc`'s type
needs that return while the return needs `gc`'s type: D30's cycle. The `retMapFlight` guard
terminates it when both arms assign `gc`. With one arm assigning another cell (`gd`, or a local)
the cycle is not caught and the shape resolution recurses until the compiler's stack runs out.
The same program with both arms assigning `gc` compiles and prints `8`.

#### Ablation

| ingredient removed | outcome | needed? |
| --- | --- | --- |
| the second cell (`gd = mkR(7)` → `gc = mkR(7)`) | compiles; runs until the write-before-init guard (D2654) | **yes** |
| `gc`'s initializer calling `fc` (`let gc = mkR(1)`) | compiles | **yes** |
| `gd`'s annotation | still traps the compiler | no |
