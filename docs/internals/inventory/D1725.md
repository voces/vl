### D1725 — a LIST LITERAL over a hole parameter takes its element rep from nothing, so an atom prints its interned id and a string refuses for want of a collected list type

**closed 2026-09-06 — a container whose own type is not a hole can still have one for its ELEMENT, and every reader asked the container · filed against master `5530f6132`, closed against `#2749`'s tree · residue of [D1545](D1545.md), and the row that records that close's price · 0 corpus cells**
Repro:

    type K = "red" | "green"
    const src: K[] = ["green", "red"]
    function take(a) {
      const xs = [a]

    }

Was: `0`, the interned atom id. Annotating the parameter `a: K` printed `green` all along.

#### Mechanism

Probed, where the row filed it as predicted — and the probe splits it into TWO mechanisms, not
the one this row claimed. At the collector, the failing and working cells read:

| | broken (hole) | working (annotated) |
| --- | --- | --- |
| ATOM face `arrElemLitUnionTy(xs)` | **-1** | **43** (`K`) |
| ATOM face `nodeArrayElemTyIx(xs)` | **59**, a HOLE | 43 |
| STRING face `arrLitIsStr(i, -1)` | 0 | 1 |
| STRING face `nodeTyArrayElemRepName(i)` | **`[]`** | `[string]` |

**The atom face is a READER gap and the collector is identical in both** — `elemRepName=[i32]`
either way. `xs` records `<hole>[]`, so its element is a hole whose PIN is `K`; every rung of
`arrElemLitUnionTyAt` asks the CONTAINER (`nodeTyPinIxOf` answers only when the node's own type
is a hole), and none asks the element's own pin. `print(xs[0])` therefore never widens.

**The string face is a COLLECT gap**, and it is not about literal unions at all: the collect
scan classifies a list literal with `fnIx = -1`, so `exprString(a, -1)` cannot reach a parameter
and the module reserves no string list — `emitProgram: string array literal but string list type
not collected`. The same hole at f64 gives the f64 twin, and a module with ANY other string list
runs, which is what shows the reservation is the whole story.

Both close with the same one-line idea at two sites: resolve the ELEMENT's own pin. The reader
gains an element-pin rung; the collector gains the scalar rescue its EMPTY-literal arm already
performs, through a pin-resolving element-rep reader.
