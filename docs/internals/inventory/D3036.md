### D3036 — a record literal with a type-parameter field inside a list literal takes the list's element row once, for every instance

**check-clean invalid wasm · 60 cells of the D3032 position grid at the `list` position (a declared record, a union or another literal of the same field names beside it) · identical on master `3a71bb1f9` · found grading [D3032](D3032.md) · filed 2026-09-28 against master `3a71bb1f9`**

Repro:

    type X = { k: i32, n: i32 }
    function g<T>(x: T): T {
      const xs = [{ k: x, n: 1 }]
      xs[0].k
    }
    print(g("s"))
    // vl check: rc 0.  vl run: invalid module, inside `g`: type mismatch: expected i32, found (ref $type)

Want:

    s

#### Mechanism

A list literal's element row is named without the instance: `arrLitElemKind`'s struct arm and
its twins ask `structIndexOfObj(elem)`, which cannot see a type parameter's pin, so the `i32`
record `X` claims `{ k: x, n: 1 }` for every instance. D3032 mints each instance's row of a
record literal, but not for one inside a list literal, since the element row would still be
this instance-blind one; without `X` the list therefore refuses loudly
(`ref array literal with no interned element type`). The close is to name the element row per
instance, as `structIndexOfObjCtx` does for the literal itself.

#### Ablation

| ingredient changed | outcome | needed? |
| --- | --- | --- |
| the declared record `X` | loud emit reject | **yes** (for invalid wasm) |
| a hole parameter (`function g(x)`) | invalid wasm | no |
| the list (`const o = { k: x, n: 1 }`) | prints s | **yes** |
| an `i32` pin (`g(1)`) | prints 1 | **yes** |
