### D3517 — a `??` over a nullable numeric box delivered into a wider scalar returns the box where the scalar is owed

**closed 2026-10-03 — the witness prints `5` · was check-clean invalid wasm, clause 1 · found by lane LU while grading the #3340 review · filed 2026-10-03 against master `878f6ebe8`, closed by lane WD against master `4c55f1b6a` · fixture `tests/cases/unions/coalesce-numeric-union-widens.vl`**

Repro:

    function g(x: i32 | i64 | null): i64 { x ?? 5 }
    print(g(null))
    // vl check: rc 0.  vl run: invalid module inside `g`, "expected i32, found (ref $type)"

Want:

    5

#### Mechanism

Confirmed by lane WD, three faults on one path. (1) `numUnionMinted` was never set by a union
with a `null` member, so every numeric-union hook declined `i32 | i64 | null`. (2) The `??`
desugars to `if x != null { x } else { d }`; the `then` read is narrowed by a complement set
(`i32|i64`), which binds no single type, so `narrowExcludesNull` answered false and
`njMembersOf` named no members (the literal union's bases were never read through the
narrowing either). Now `narrowDropsNull` asks the set. (3) Where a widening's fast path
classified the join at the destination's width (`x ?? 9000000000` reads `i64`), the box went
out raw; and a box built under an `i64` argument's pending width minted its `i32` member with
`i64.const`. `njBoxWidens` routes a box through the member-by-member conversion on every fast
path, and `njStash` clears the pending width while it builds the box. `njLitBoxUnwidened` and
its refusal are gone. Matrix (`scratchpad/wd-k7q3/mx`, 540 cells: five unions x defaults x
ten positions x function/top level): master 348 runs / 44 invalid / 60 emit reject / 4 trap;
after 456 runs / 0 invalid / 0 wrong / 0 runs lost. The 84 check rejects left are D3523.

Earlier note, kept for the record: the `return x` arm takes `emitExprAsI64`'s sign-extend
fall-through with the box on the stack. The `??` lowers as `if x != null { return x } else { return 5 }`, and the
`return x` arm takes `emitExprAsI64`'s sign-extend fall-through with the box on the stack. The
widening arm (`njWidensOut`) did not claim it. Its `numUnionMinted` gate is unset when the only
numeric union carries a `null` member, and dropping the gate alone did not fix the witness
(measured), so the desugared read is not recognised as a narrowed numeric box either.

**Held loud by #3340:** `type E = 9000000000 | 1 | null; g(x: E): i64 { x ?? 9000000000 }`
was `emitProgram: bare null needs a struct-typed context` on master and would have become this
row's invalid wasm once the literal union boxes. The widening sites refuse it instead
(`njLitBoxUnwidened`: "a nullable integer-literal union read is not yet widened into a number
type here"); that refusal leaves with this row's fix. The same refusal covers a typed binding,
`const w: i64 = y ?? 9000000000`, whose join the `i64` fast path claimed by its wide arm: loud on
master inside a function, and SILENT on master at top level, so loud there now too.
