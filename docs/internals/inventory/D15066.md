### D15066 — two written bindings of one generic set, delivered through adapters at two closed function types, are typed at one adapter's signature

**loud check reject · clause 2 · `a function of type (T) => T cannot be used as (i32) => i32 here … expected (boolean) => boolean, got (i32) => i32 (the return of $fv…)` · found ablating `written-fn-binding-two-types-delivered-by-value.vl` · filed 2026-11-03 against master `5ba642c3`**

Repro:

    function id<T>(x: T): T { return x }
    function loud<T>(x: T): T {
      print("loud")
      return x
    }
    function mk(): (x: boolean) => boolean {
      let h = id
      h = loud
      print(h("m"))
      return h
    }
    function main() {
      let f = id
      print(f(1))
      const u: (x: i32) => i32 = f
      f = loud
      print(f("s"))
      print(u(10))
      print(mk()(true))
    }
    main()
    // vl check: rc 1, at `const u: (x: i32) => i32 = f`, with the split plan on and off

Want:

    1
    loud
    s
    10
    loud
    m
    loud
    true

#### Mechanism

Not located. `main`'s `f` and `mk`'s `h` are written bindings of the same set `{id, loud}`, each
delivered through an adapter: `f` at `(x: i32) => i32`, `h` returned at `(x: boolean) =>
boolean`. The delivery of `f` is checked against the other adapter's signature, so each delivery
needs its own adapter typing, keyed per binding.
