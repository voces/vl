Repro:

    function outer2<T>(x: T, y: T) {
      let v = x
      const h = (u) => { print(v); print(u) }
      h("s")
      const fs = [h]
      v = y
      fs[0](3)
    }
    outer2(7, 8)
    // vl check: rc 0.  vl run: the emitted module failed to validate inside `outer2`: type mismatch: expected structref, found i32

Want:

    7
    s
    8
    3

#### Mechanism

The un-annotated list's element type was inferred from `h`, whose hole the first call `h("s")`
bound to `string`, while the later call `fs[0](3)` passes an `i32`. The flow table pins the
element slot at `(i32) => void`, but `monoPinListElems` only instanced elements that name a
generic function or a written `let`, so a hole lambda kept its `string` copy and the list was
read with one signature and called with the other. In a generic body the lambda's instance
binds no hole of its recorded type, so the pin's own parameters give the container's type.
The record literal field (`monoPinRecordFields`) had the same gap.
