### D2965 — a `u8[]` spread beside an `i32` in an un-annotated literal has no boxing copy into `(u8 | i32)`

**loud emit reject · clause 2 · the residue of D2868's boxing spread · filed 2026-09-28 against master `03dcbcfac`**

Repro:

    const bs: u8[] = [1, 2, 3]
    const c = [...bs, 9]
    print(c.length)
    // vl check: rc 0.  vl run: emit error: a spread whose elements must each be boxed into a union or nullable element has no lowering yet

Want:

    4

#### Mechanism

The un-annotated literal is typed `(u8 | i32)[]` (a `u8` element read widens, and the join
keeps both). D2868's boxing spread now builds every other inferred union-element spread at its
own union-box row, but `u8` is no value atom (`valueAtomKind` answers -1), so
`spreadSrcBoxAtom` finds no arm for the packed source and the refusal stands. Whether
`[...bs, 9]` should rather be typed `i32[]` or `u8[]` is the question to settle first; the
annotated `u8[]` spelling runs (`u8-spread-annotated-mix.vl`).
