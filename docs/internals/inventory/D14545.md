### D14545 — a read resolved by name answers the namesake the binder did not pick

**closed 2026-10-27 · runs today and must keep running · the env's name map and the binder disagreed at 27 reads in 12 of 17,190 programs; every read now goes through `identDeclOf` · filed 2026-10-27 against master `359ed5a8f`**

Repro:

    function b<U>(y: U) {
      print("generic")
      print(y)
    }
    function a<T>(x: T) {
      const b = (t: T) => print("local")
      const h: (t: T) => void = b
      h(x)
    }
    a(2.5)
    a("s")

Want:

    local
    local

#### Mechanism

A temporary probe at every read that holds a node compared the env's name map
(`envDeclOfNameForFlow`, D14544) with the binder's `identDeclOf`. A control that shifted every
binder declaration by one fired on a three-line program, so the probe could see a disagreement.

Over `tests/cases` and both halves of the distilled corpus (17,190 programs), it found 27
disagreements in 12 programs. Over `~/diderven/src` (75,524 reads) it found none. Every
disagreement is a name with two live declarations: a local shadowing a module generic, a
nested function namesake, a block `const` shadowing a parameter, a duplicate payload binding,
or a redeclaration in an error program. The map answers the latest spelling; the binder
answers the named declaration. The map is wrong in all 27.

#### Fix

The decl-keyed type env reads each node's type through its declaration, so the map is no longer
asked at those sites. Two cascades moved:
- A duplicate payload binding is now bound at the first binding's type.
- A same-frame redeclaration keeps the first declaration bound.

A local `const` named by a parameter default is now `undeclared` at the call site, the same as
a parameter named there, because the binder resolves a default against the module frame.
