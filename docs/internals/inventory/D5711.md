### D5711 — a one-arm `match` in value position has no value

**closed 2026-10-17 — the witness prints `5` · was a loud check reject, clause 2 · lane L3: `desugarMatchAt` (`check_match_desugar.vl`) lowered every match to the else arm's BLOCK, and with one arm there is no `if` around it, so a bare block stood where a value was wanted; a lone arm whose body is an expression now lowers to that expression · fixture `tests/cases/match/one-arm-value-position.vl` · filed 2026-10-17 against master `bb4448de7`**

Repro:

    function f(n: i32): i32 {
      match n { _ => 5 }
    }
    print(f(1))

Want:

    5

#### Mechanism

`desugarMatchAt` builds the chain from the else arm outward. With one arm the chain is just
`matchArmBlockOf(body)`, a `Block`, and VL has no valued bare block: as a function tail it is
"not all code paths return a value", and as an initializer (`const s = match n { _ => 5 }`)
the emitter refuses it as an unsupported expression. The same body in a two-arm match runs.

#### Ablation

| ingredient removed | outcome | needed? |
| --- | --- | --- |
| a second arm `1 => 4` added | runs | **yes** |
| the match used as a statement | runs | **yes** |
| the scrutinee an `"a" \| "b"` or a struct union | still refused | no |

#### Grading list

Over `i32`, a string literal union and a struct union; as a function tail and as an
initializer; an impure scrutinee still evaluated. A lone arm with a BLOCK body is D5713.
