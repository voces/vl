### D16381 — a top-level slot first filled with an un-annotated-parameter function declared later is called at the wrong signature once a function of another result is written into it

**loads then traps · clause 1 · open · a rung of [D16301](D16301.md), the declaration-order family · filed 2026-11-15 against master `3d526470a`**

Repro:

    let f = inc0
    if [1].length > 0 { f = half }
    print(f(3))
    function inc0(a) { return a + 1 }
    function half(a) { return a / 2.0 }
    // vl check: rc 0.  vl run: wasm trap, indirect call type mismatch

Want:

    1.5

#### Mechanism

Not yet located. It is not the return: the return pre-pass infers every top-level un-annotated
return before pass 2, and with the parameters annotated both orders refuse the write the same
way. The ingredient is the un-annotated parameter, which makes the slot a hole-function slot whose
writes join through the elaboration's function sets; with the slot's first member declared after
the statement that makes it, the call lowers at that member's signature alone.
