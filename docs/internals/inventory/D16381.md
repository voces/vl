### D16381 — a top-level slot first filled with an un-annotated-parameter function declared later is called at the wrong signature once a function of another result is written into it

**closed 2026-11-15 — the witness runs and prints `1.5` · was: loads then traps · clause 1 · a rung of [D16301](D16301.md), the declaration-order family · filed 2026-11-15 against master `3d526470a`**

Repro:

    let f = inc0
    if [1].length > 0 { f = half }
    print(f(3))
    function inc0(a) { return a + 1 }
    function half(a) { return a / 2.0 }
    // vl check: rc 0.  vl run: wasm trap, indirect call type mismatch

Want:

    1.5

#### Mechanism

The tag decision. A call through a set whose members return different types needs the set
tagged, so each member is dispatched by id. `fnTagDecide` tags only a set whose noted calls
record that split. The call `f(3)` was checked before `inc0`'s body (declared after it), so
`holeSetCallRetOf` got no result for `inc0` and noted nothing. The set stayed untagged and the
call lowered at one member's signature. The join now checks an un-annotated member's body on
demand when pass 2 has not reached it (`setMemberInfer`), as a forward direct call already does,
and asks again.
