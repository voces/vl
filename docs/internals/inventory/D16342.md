### D16342 — an un-annotated or generic parameter pinned at an empty `i32[]` answers `is f64[]` true

**open · check-clean silently wrong · prints `true` · clause 1 under the D16047 refinement (an annotation fixes an empty list's element type) · found by the `annotated-empty-list-delivered-into-union-is` matrix's un-annotated `argument` and `early_return_guard` cells · filed 2026-11-15 against master `dbbaa6809`**

Repro:

    function take(v) { v is f64[] }
    const m: i32[] = []
    print(take(m))

Want:

    false

#### Mechanism

The instance's receiver is the argument's `i32[]`, whose element its annotation fixes, but the
list test of disjoint elements answers by emptiness (`emitListEmptyFitIs`, D4910), the rule for
a parameter the default left unbound. The emitter does not tell a pinned binding from a defaulted
one there.

#### Ablation

On master `dbbaa6809` plus the D16047 refinement.

| ingredient removed | outcome | needed? |
| --- | --- | --- |
| `const m: i32[] = [1]` (non-empty) | runs, `false` | **yes** |
| `function gen<T>(v: T)` for the hole | the same wrong answer | no |
| `m` delivered into `i32[] \| f64[]` instead of a parameter | runs, `false` | **yes** (the parameter) |
