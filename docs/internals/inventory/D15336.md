### D15336 — a record literal of an un-annotated function pushed onto a list beside another member is refused at emit

**closed · runs, prints `2` then `2.5` · was a loud emit reject (`emitProgram: cannot take the generic function id1 as a value`), clause 2 · found grading D15307 · filed 2026-11-04 · fixed by answering a pushed literal as a write of the list's element: `recAsgFnWidenedTy` (check_fit_rules.vl) walks the push receiver to its widened binding and takes the element record, and fn-tag's `ftSlotOp` takes a push onto a list of such records only when every argument is a literal that fact answers, joining each at the element (`ftRecWriteJoins`). A map `set` is [D15339](D15339.md)**

Repro:

    function id1(a) { return a }
    function id2(a) { return a }
    const xs = [{ f: id1 }]
    xs.push({ f: id2 })
    print(xs[0].f(2))
    print(xs[1].f(2.5))

Want:

    2
    2.5

#### Mechanism

The field widener already reads a push (`cwSlotWritesInto`), so the list binding is widened; what
refused was the build and fn-tag. A push delivers the literal through a call argument, so
`recAsgFnWidenedTy` answered nothing for it, and fn-tag's `ftSlotOp` took a push only onto a list
of the set's ids, not a list of records holding them (`ftHoldKind` 6).

#### Ablation

| ingredient removed | outcome | needed? |
| --- | --- | --- |

| push → `m.set("b", { f: id2 })` beside `m.set("a", { f: id1 })` | still refuses: a different gap, D15339 | no |
