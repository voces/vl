### D1774 — `is <union alias>` has no interned arm representation, so a `vl check`-clean arm test refuses at emit

**closed 2026-09-06 — a union alias arm is a SUBSET of the outer box's tags, never a nested
box, so the test is the tag chain `as?` already emitted for a sub-union target · clause 2**

Repro:

    type U = i32 | string

    function f(d: U | boolean): i32 {
      if d is U { return 1 }
      0
    }
    print(f(5))
    print(f("ab"))
    print(f(true))
    // prints 1, 1, 0 — before the fix, `vl check` rc 0 then `emitProgram: `is` names a
    // declared union member with no interned arm representation`

#### Mechanism

`U` is a member of `U | boolean` under its own name, so `checkIsExprNode`'s arm gate admits
it, and `emitIs` then asks `variantIndexOf` for the arm. That question has no answer, and
`wasm-dis` says why: the rep is FLAT. `as? U` over the same operand emits

    (i32.or (i32.eq (struct.get $0 0 …) (i32.const 0))
            (i32.eq (struct.get $0 0 …) (i32.const 2)))

against one box `(struct (field i32) (field anyref))` whose tags are 0 = i32, 1 = boolean,
2 = string. `U`'s arms take their own tags in the OUTER box side by side with `boolean`;
there is no inner box, so the alias is not one variant but a subset of the outer union's
variants, and a one-name lookup cannot name it. `emitAsCast` already derived that tag list —
its own comment reads "a sub-union target only widens the membership test (a tag chain), with
no unbox at all" — so the derivation moves to `unionArmTagsOfTy` and `emitIs` emits the same
chain where `variantIndexOf` declines. The narrowed binding needs no rep either: `as?`'s
sub-union arm hands back the operand's own box, which is what the narrowing already is.
A layout-twin arm is excluded — its tag alone does not settle membership and the per-arm
discriminant test (D1023) has no home inside an `i32.or` chain — so that spelling keeps the
loud refusal.
