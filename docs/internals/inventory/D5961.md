### D5961 — an inferred return of a nullable numeric literal union is floored by the checker, though the annotated return runs

**closed 2026-10-17 by lane L3 · runs, prints `2` then `0` · was loud check reject · clause 2 · pre-existing, the same on master `60c4d1c43` · the inferred-return floor admits a nullable numeric literal union, and the recorder names it as its base made nullable, the registry key its annotation already uses (`check_inferred_return.vl`, `check_program.vl`) · pin: `tests/cases/unions/inferred-nullable-mixed-litunion-return.vl` (`getL`, `getW`) · found closing [D5922](D5922.md) by the `lambda-inplace-nullable-litunion` position matrix (`return_inferred`) · filed 2026-10-17 against master `f619864ee`**

Repro:

    type LN = 1 | 2
    function pick(n: i32): LN | null {
      if n > 0 { return 2 }
      null
    }
    function get(n: i32) { return pick(n) }
    print(get(1) ?? 0)
    print(get(0) ?? 0)
    // vl check: 'get' infers the nullable return type LN | null — type-valid, but an inferred
    // return of this shape is not yet supported by codegen; annotate the return type

Want:

    2
    0

#### Mechanism

The nullable arm of the inferred-return floor admitted a string literal union or a nameable
value union; a numeric literal union is neither, though its annotated `LN | null` runs as
`i32|null`.

#### Ablation

| ingredient changed | outcome | needed? |
| --- | --- | --- |
| `get` annotated `LN \| null` | runs | **yes** (inferred) |
| `LS = "a" \| "b"` in place of `LN` | runs | **yes** (numeric) |
| inline `1 \| 2 \| null`, or an i64 literal | still floored | no |

#### Grading list

Print, `!= null` arithmetic, passed to an `LN | null` parameter, `match`, captured, a lambda
called in place: all floored on master, all run.
