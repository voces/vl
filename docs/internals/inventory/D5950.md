### D5950 — calling a closure over a narrowed nullable local costs super-quadratically in the number of such closures in one frame

**closed 2026-10-17 — the witness prints `3`; compile cost is near-linear in the closures called in one frame (fuel ×1.99–2.16 per doubling from 50 to 1,600) · was ×5.7–6.7 per doubling, 3.9e10 fuel at 400 · compile cost, not output: the candidate's output is identical to master's over every case and corpus cell · filed 2026-10-17 against master `ba80b13d6` · 0 corpus cells · pin: `tests/vl_scaling_shape_test.ts` axis `called captured narrowed locals` (1.14; master 41.3)**

Repro:

    let acc = 0
    function m() {
      let g0: i32 | null = null
      g0 = 0
      const h0 = () => (g0 ?? 0) + 1

The witness is the shape at three; the cost is at hundreds. `n` repetitions of the four lines
read, in guest fuel of one `vl build`: 50 → 2.2e8, 100 → 1.0e9, 200 → 5.8e9, 400 → 3.9e10
(5.2 s). Each doubling multiplies the cost by 5.7 to 6.7. At 400, `vl check` alone takes
0.73 s of the 5.2, so the cost is past the checker.

#### Mechanism

There was no single loop. Each call of a closure in the frame re-asked a question whose answer
covered the whole frame. That happened at about a dozen sites, in both the checker and the
emitter, and each one alone was linear per call. Each is now answered from an index kept per
frame or per name:

- `compiler/emit_capture_frames.vl` `nestedFnDeclaredIn`: it walked the host frame once per
  question. It now uses an index scoped to the walk (`nfdWalkEnter`/`nfdWalkLeave`), entered by
  `capComputeNamesOf` (`emit_classify.vl`). A frame is scanned the first time a walk asks about
  it and indexed the second time. Indexing every frame a walk asks about once is what took
  `un-annotated callback lambdas per function` from 2.20 to 2.51 on the first candidate.
- `compiler/emit_mv_slots.vl` `capNarrowRecord`: it scanned the whole narrowing stack for each
  closure. It now reads the live slots of the closure's free names (`narrowLiveSlotsUnder`,
  `emit_narrow_slots.vl`). `narrowIdxAdd` no longer appends a slot that is already listed.
- `compiler/emit_value_sites.vl` `capNarrowSeed`: it scanned every recorded closure row. It now
  reads the rows of its own function only.
- `compiler/emit_lift.vl` `clSyntax`: it walked the host once per lifted closure. It now uses an
  index per host.
- `compiler/check_narrow_flow.vl` `crCallCandidates`: a call asked every live banked name
  whether it could retire it. It now asks only the names a call can retire, kept incrementally
  for each nesting level. The cache is keyed by narrowing-row stamps (`check_nar_store.vl`) and a
  declaration log (`check_scopes.vl`).
- The checker's per-name bank reads: `narDeclaredTy`, `noteNarShadow`, `crInnerRowBelow`,
  `narGuardSlot` and `jsonWidestDeclTy` read that name's own rows (`narBankRowsOf`) instead of
  scanning the bank. `crFirstBank` does too, but only for a depth with no bank frame; a depth
  with a frame still scans that frame's span. Reading the name's rows there took `if joins
  nested deep` from 5.42 to 12.29 on the first candidate: a name narrowed at every one of `n`
  nested depths has `n` rows, and the bank asks about it once per depth.
  `crLiveNames` dedups with a map.
- `compiler/check_cr_walk.vl` `crEscapesIn`: the escape set of a body was a `,`-joined string,
  grown and searched with `indexOf`. It is now a set.
