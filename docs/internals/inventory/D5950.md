### D5950 — calling a closure over a narrowed nullable local costs super-quadratically in the number of such closures in one frame

**runs today and must keep running · compile cost, not output · filed 2026-10-17 against master `ba80b13d6` · 0 corpus cells**

Repro:

    let acc = 0
    function m() {
      let g0: i32 | null = null
      g0 = 0
      const h0 = () => (g0 ?? 0) + 1
      acc = acc + h0()
      let g1: i32 | null = null
      g1 = 1
      const h1 = () => (g0 ?? 0) + 1
      acc = acc + h1()
      let g2: i32 | null = null
      g2 = 2
      const h2 = () => (g0 ?? 0) + 1
      acc = acc + h2()
    }
    m()
    print(acc)
    // vl check: rc 0.  vl run: rc 0, prints 3

The witness is the shape at three; the cost is at hundreds. `n` repetitions of the four lines
read, in guest fuel of one `vl build`: 50 → 2.2e8, 100 → 1.0e9, 200 → 5.8e9, 400 → 3.9e10
(5.2 s). Each doubling multiplies the cost by 5.7 to 6.7. At 400, `vl check` alone takes
0.73 s of the 5.2, so the cost is past the checker.

#### Mechanism

Not yet located. It is not the per-name frame walk the `captured narrowed locals` scaling axis
guards (D2529): every closure here captures the same `g0`, and making each capture its own
local moves the cost by 1%. It needs all three of a nullable local, a closure over it, and a
call to that closure in the same frame.
