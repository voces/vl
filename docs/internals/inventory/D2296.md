### D2296 — a list literal passed to a function value built its own rep, not the `u8[]` or `f32[]` parameter's

**closed 2026-09-24 — the witness prints `252` · was check-clean invalid wasm (`expected (ref $type), found (ref $type)`), clause 1 · fixture `tests/cases/closures/list-literal-into-function-value-param.vl` · found while grading D2295 · filed against master `a295cf301`**

Repro:

    const f = (xs: u8[]): i32 => xs[0] + xs.length
    print(f([250, 1]))
    // vl check: rc 0. vl run (as filed): invalid module. Now prints 252.

#### Mechanism

`emitCallRef` coerced each argument to its parameter's wide scalar but threaded no list build
code, so a literal built the list its own elements name. `[250, 1]` names `i32[]` and `[1.5]`
names `f64[]`; only the parameter says `u8[]` or `f32[]`. A named-function call already seeds
it from the annotation (`tyAnnRefListKind`). The fix seeds the parameter's build code, read off
the resolved `$fnsig` token through `listBuildKindOfVKind`, for every distinct-backing list and
nullable list parameter.

#### Ablation

| ingredient changed | outcome | needed? |
| --- | --- | --- |
| `(xs: f32[])` with `f([1.5])` | same invalid module | no |
| `(xs: f32[])` with `f([(1.5 as f32)])` | runs | **yes** (the literal naming another rep) |
| a named `function f(xs: u8[])` | runs | **yes** (the value call) |
| a `u8[]` binding as the argument | runs | **yes** (the literal) |

#### Grading list

The `f32[]` spelling above, both prints of the fixture, and the value-call positions of the
`u8-list-literal` matrices.
