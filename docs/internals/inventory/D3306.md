### D3306 — a call that writes a narrowed outer name from under an inner declaration of that name does not end the narrowing

**now a loud check reject, the refusal the design owes, 2026-09-29 (`crRetireShadowed` in `compiler/typecheck.vl` no longer needs the narrowing on a layer of its own: a binding narrowed at its own depth, by a straight-line write or a join, is shadowable too) · was check-clean invalid wasm on master, clause 1 · sibling of D3020 · filed against master `e70102886` · fixture `tests/cases/unions/error-flow-join-kill-any-path.vl`, hazards `hidden_outer_call*` in `scripts/flow-narrowing/join-hazards.py`**

Repro:

    function nn(v: i32): i32 | null {
      if v < 0 { return null }
      return v
    }
    function f(k: i32): i32 {
      let x = nn(k)
      const clr = () => { x = null }
      x = 3
      {
        const x = 100
        clr()
        print(x)
      }
      return x + 1
    }
    print(f(-1))
    // was: vl check rc 0, then the emitted module failed to validate inside `f`
    // now: operator '+' is not defined for i32 | null and i32 (clr may have stored null)

#### Mechanism

`clr()` writes the captured outer `x`, but at the call the name resolves to the inner `const x`,
which no narrowing covers, so the call retired nothing. D3020 added `crRetireShadowed` for this,
and it required three scope layers: the binding, a narrowing layer above it, and the shadowing
declaration. A straight-line null strip (and a join) narrows at the binding's own depth, leaving
two layers, so the shadowed walk returned before it looked. It now accepts a binding narrowed in
place.
