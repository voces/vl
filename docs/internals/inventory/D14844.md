### D14844 — a function declared in a loop over hole functions, calling the loop variable at a second function type, leans on the split plan for a copy per type

**runs today and must keep running · runs only because the split plan copies the list per call type; with the split plan and the D6210 rung off it refuses at emit (`a function this call reaches through a list or join is already taken at another function type by an earlier call through it`) · γ's backlog gap (b), named by `docs/internals/closure-at-delivery-2026-11.md` and not covered by it · closes when an element called at two function types through a function declared in the loop body is served without a copy per type · filed 2026-11-01 against master `3e36a3c26`**

Repro:

    import { toString } from "std:fmt"
    function cat(a, b) { return a + b.toString() }
    function snd(_a, b) { return b }
    function apply2(g) { print(g("x", 2)) }
    function apply3(g) { print(g("y", 20)) }
    const fs = [apply2, apply3]
    const ks: (() => void)[] = []
    for f in fs {
      function k() { f(snd) }
      ks.push(k)
      f(cat)
    }
    for k in ks { k() }

Want:

    x2
    y20
    2
    20

#### Mechanism

The list's elements are called at `(string, i32) => string` in the loop and at `(string, i32) => i32` from `k`, a function declared in the loop body that captures the loop variable. One element value serves only one of them: the element path refuses the second call (`monoElemTakenSig`), and only the split plan's per-type copy of the list runs both. A `const` lambda in the same place runs.

#### Ablation

| ingredient removed | outcome with the split plan off | needed? |
| --- | --- | --- |
| the escape (`k()` called in the loop, not stored) | still refuses | no |
| `function k` spelled as a `const` lambda, called in the loop | runs | **yes** |
| the second call type (`f(cat)` both times) | runs | **yes** |
