### D10330 — a hole parameter's `const` copy handed to a generic at `null` returns `nullref` where the call's `i32` result goes

**closed 2026-10-26 · runs, prints `5` · fixed when `monoArgTyName` began reading an argument's pin from its closed type before its binding and rep rungs; the mechanism is not traced past that · was check-clean invalid wasm, clause 1 · found closing [D10270](D10270.md) · filed 2026-10-22 against master `cc89864b9` · pin: `tests/cases/generics/hole-param-const-copy-into-generic-at-null.vl`**

Repro:

    function outer<U>(x: U): i32 { 5 }
    function take(a) {
      const v = a
      print(outer(v))
    }
    take(null)
    // vl check: rc 0.  vl run: invalid module inside take

Want:

    5

#### Mechanism

Not traced. The generic's body never reads `x`, so `U` is not the ingredient beyond pinning an
instance at `null`; the `const` copy of the hole parameter is: handed `a` directly, the same
call runs. The capability matrix `fn-value-enclosing-param-into-generic-nullable` reaches it
at its `argument/unann` cell.

#### Ablation

| ingredient changed | outcome | needed? |
| --- | --- | --- |
| `a: null` annotated | runs, `5` | **yes** (the hole) |
| `outer(a)` in place of `const v = a` then `outer(v)` | runs, `5` | **yes** (the copy) |
| no generic, `print(v == null)` | runs, `true` | **yes** (the generic call) |

#### Grading list

The matrices `fn-value-enclosing-param-into-generic-nullable` and its `-open` twin, whose
`argument/unann` cell is this row.
