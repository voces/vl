### D2932 — a lambda capturing a local bound to a hole value, at an `f32` pin, prints through the `i32` import

**closed 2026-09-28 — the filed repro prints `1.5` · was check-clean invalid wasm, clause 1, the same on master `8615a730d` · closed by classifying a closure call returning `f32` in `exprIsF32`, as `exprIsF64` already did · filed 2026-09-28 against master `cab9694f8`**

Repro:

    function h(x) {
      const l = [x]
      const y = l[0]
      const k = () => y
      print(k())
    }
    const v: f32 = 1.5
    h(v)
    // vl check: rc 0.  vl run: invalid module inside `h`

Want:

    1.5

#### Mechanism

[D2918](D2918.md)'s residue at `f32`. The env field of `y` and the lifted lambda's result are
both `f32`, but the call `k()` is typed at the hole's variable, and `exprIsF32`'s `Call` arm asked
only a named callee, so `print` called the `i32` import on an `f32`. `exprIsF64` and `exprIsI64`
already read a function-value callee's result kind (`calleeRetKindAt`); `exprIsF32` now does too.
`const y = x` captured at `f32` closes the same way.
