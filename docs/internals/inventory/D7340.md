### D7340 — a list of one string literal and a list of its one-literal alias are one type, but rep apart: a string list and an i32 list

**check-clean invalid wasm · `vl check` rc 0 · clause 1 · found closing [D7220](D7220.md) · present on master `1c86d0f42` · filed 2026-10-19 against master `c2a8dad65`**

Repro:

    type KC = "circle"
    const xs: "circle"[] = ["circle"]
    const ys: KC[] = xs
    print(ys[0])
    // vl check: rc 0.  vl run: invalid module, expected (ref null $4), found (ref $6);
    // $4 is `list of i32-represented elements`; $6 is `string list`

#### Mechanism

[D7220](D7220.md) at the list-element position. The checker reads `KC` as the literal
`"circle"`, so `"circle"[]` and `KC[]` are one type and the delivery needs no copy. The
emitter reps a list of a named literal union as an i32 atom list, and a list of one inline
literal as a string list, so the delivery hands one list to a slot typed by the other.
Under the owner's `one-literal-union-rep` ruling both are the atom list. D7220's close moves
a record FIELD of one inline literal to the atom; the list element is still asked through
`tyIsLitUnion`, which answers only for a `TyUnion`, and a lone literal is a bare `TyLit`. That
predicate has 196 call sites, and widening it moves every position a lone literal reaches,
not only the list element, so moving the element is its own change.

#### Ablation

| ingredient changed | outcome | needed? |
| --- | --- | --- |
| delivered the other way (`KC[]` into `"circle"[]`) | same invalid wasm | no |
| delivered as an argument to a `KC[]` parameter | same invalid wasm | no |
| a scalar (`const y: KC = x`) or a map value instead of a list | runs, prints `circle` | **yes**, a list |
| both two-literal (`("circle" \| "rect")[]` against an alias of it) | runs, prints `circle` | **yes**, one literal |
| `xs` un-annotated (`["circle"]`, a `string[]`) | loud check reject | **yes**, the literal element type |
