### D6342 — a module record field holding a maker's generic result, called at two types, refuses

**closed 2026-10-18 by lane L1 · runs, prints `1 z` · was loud emit reject · clause 2 · when every read of an un-annotated `const` record reads a field and every read of the field calls it, the field keeps the type its `const` or its first call takes and a call at any other type calls the generic directly · pins: `tests/cases/closures/maker-result-in-module-record-field-at-two-types.vl` (a held `const`, a lambda maker, a maker's effect run once, a tail maker, inside a function, either call order) · open beside it: [D6371](D6371.md) (the record also read whole) · found closing [D6322](D6322.md) · filed 2026-10-18 against master `5e3ba8429`**

Repro:

    function k<T>(x: T): T { return x }
    function mk() { return k }
    const r = { f: mk() }
    print(r.f(1))
    print(r.f("z"))
    // vl check: rc 0.  vl run: emitProgram: a generic function taken as a value reaches no call that fixes its type — annotate the destination's function type

Want:

    1
    z

#### Mechanism

From the ablation only. A binding of the maker's result called at two types takes a slot per
type, and so does a record field holding `k` directly. A record field holding the maker's
result is followed by neither, so `k` meets no call that fixes its type.
