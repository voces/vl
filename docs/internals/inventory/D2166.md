### D2166 — `.map` into a value-union element is check-clean invalid wasm once the program also holds a literal-union list

**check-clean invalid wasm · filed 2026-09-23 against master `9fd219de7`, found while checking that the no-implicit-container-widening refusal's copy hints compile**

Repro:

    type K = "a" | "b"
    const k: K[] = ["a"]
    const l: i32[] = [1]
    const l2: (i32 | null)[] = l.map((x): i32 | null => x)
    print(l2.length)
    // vl check: rc 0.  vl run: failed to parse WebAssembly module — type mismatch: expected (ref $type), found (ref $type)

#### Mechanism

Not yet ablated past the rows below. The `.map` result list is a boxed value-union element
list, and the `K[]` list stores interned literal-union atoms. Each program alone runs, so the
suspicion is a row or signature shared between the two element kinds (both `i32`-backed) that
lets the map's result take the atom list's type. This matters because the refusal for
`i32[]` → `(i32 | null)[]` suggests exactly this `.map` as the copy to write.

#### Ablation

| spelling | outcome | needed? |
| --- | --- | --- |
| the witness | invalid module | — |
| without `const k: K[]` | runs, prints 1 | the atom list: **yes** |
| `const k: K = "a"` (a scalar, not a list) | runs | a LIST of atoms: **yes** |
| `const k = ["a"]` (a `string[]`) | runs | literal-union element: **yes** |
| result `(i32 \| string)[]` instead of `(i32 \| null)[]` | invalid module | which union: no |
| `l.map(f)` with a declared `f(x: i32): i32 \| null` | invalid module | the lambda: no |
| a literal `[l[0]]` built at `(i32 \| null)[]` instead of `.map` | runs | `.map`: **yes** |
| `i64[]` source into `(i64 \| null)[]` | invalid module | element width: no |

#### Grading list

Every ablation row. The refusal's other copy hints (`.map((x) => x as f64)`, `as i64`,
`.map((x): string => x)` over a `K[]`, a `readonly f64[]` destination) each compile and run
alone. This row is the one combination found that does not.
