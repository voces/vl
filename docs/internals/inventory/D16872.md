### D16872 — a call through a list of un-annotated functions of two result types, resolved to one member and bound in a block or function, stores the member's narrower result into a local laid out at the joined one

**closed 2026-11-16 by lane AE — the witness prints `4` · a `let` whose slot is laid out `f64` or `i64` takes its init widened to that slot (`emitLetInitValue`) · was check-clean invalid wasm, clause 1 · found by lane AE grading a nested spelling of the same list · fixture `tests/cases/closures/mixed-result-fn-list-call-bound-in-block.vl` · filed 2026-11-16 against master `8f94d30c2`**

Repro:

    function inc0(a) { return a + 1 }
    function half(a) { return a / 2.0 }
    function id(x) { return x }
    const xs = id([inc0, half])
    {
      const v = xs[0](3)
      print(v)
    }
    // vl check: rc 0.  vl run on master: invalid module, type mismatch: expected f64, found i32

Want:

    4

#### Mechanism

The checker types `xs[0](3)` at the list's joined result, `f64`, so `collectLocals` lays `v` out
`f64`. The value-flow rewrite resolves the read to `inc0` and the call becomes a direct `call`
returning `i32`. `letIsF64` asks the init, now that `i32` call, so the init took the plain arm
and stored an `i32` into the `f64` local. A module-scope binding already converted.

#### Grading list

A reassigned `let u = 0.5`, an `f64` parameter's argument, a declared `f64` return, an inferred
return bound in a block, a list or record literal element, a sum of the two members.
