### D3780 — a constant that overflows `i32` inside a join is reported as the join's `expected i32, got i64`, not as the constant's overflow

**closed, now a loud check reject naming the constant: `constant 2147483648 overflows i32 — write 0x80000000 for its bit pattern`, at `1 << 31` · was `expected i32, got i64` over the whole join (a binding: `i64 doesn't fit in i32 — the conversion is lossy`) · a diagnostic row, no wrong value · sunpa SP-047 (`src/items.vl` bag `gather`, bit 31) · lane FA · filed and closed 2026-10-06 against master `a37097b64`**

Repro:

    function f(h: boolean): i32 { (if h { 1 << 31 } else { 0 }) | 5 }
    print(f(true))
    // vl check: constant 2147483648 overflows i32 — write 0x80000000 for its bit pattern

#### Mechanism

The owner's const-arith ruling (A) folds `1 << 31` to the exact 2147483648, and a constant
delivered straight into `i32` is refused by `cexDeliver` in its own words. Inside an `if`,
`match` or block tail, or under an integer operator, the constant is not the delivered
expression: the arm types `i64` because the constant overflows `i32`, the join and the `|`
take that width, and the delivery fails as a plain type mismatch. `cexJoinMisfit`
(`typecheck.vl`) now runs where `tErrWant` is about to report an `i64` value at an `i32`
destination (a return, a binding, an argument): when every leaf of the value is an integer
constant (through tails, parentheses, negation, `~` and integer operators), the first one
`i32` cannot hold is refused at its own span instead. It cannot run inside `assignableExpr`:
callers ask that non-quietly and take another path on `false` (a `??`-merged row widening a
field, `coalesce-merged-row-numeric-fold.vl`), so a report there refused programs that run. A value in the sign
bit's range also names the hex literal that is its bit pattern (ruling Q6), at every
`overflows` message, so `const x: i32 = 1 << 31` gains the same suffix.

#### Ablation

| ingredient removed | outcome | needed? |
| --- | --- | --- |
| the `if` (`(1 << 31) \| 5`) | `constant 2147483653 overflows i32` (already in its own words) | **yes** |
| the `\| 5` (`if h { 1 << 31 } else { 0 }`) | `constant 2147483648 overflows i32` (already) | **yes** |
| `1 << 31` spelled `2147483648` | the same mismatch | no |
| a variable leaf (`else { x }`, `x: i64`) | `expected i32, got i64`, correctly: the width is the variable's | **yes** |
