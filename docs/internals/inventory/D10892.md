### D10892 — a named un-annotated lambda handed through a hole-function list past index 0 is refused

**loud emit reject · `vl check` rc 0 · clause 2 · CAPABILITY: a neighbouring spelling runs (the ablation) · found closing [D10795](D10795.md) · present on master `b84cf89cb` · filed 2026-10-23 against master `b84cf89cb`**

Repro:

    function apply2(g) { print(g(1, 2)) }
    function apply3(g) { print(g(1.5, 2.5)) }
    const gs = [apply2, apply3]
    const l = (a, b) => a + b
    gs[1](l)
    // vl check: rc 0.  vl run: emitProgram: monomorphize: unsupported argument type for `g` in a call to `apply3`

Want:

    4

#### Mechanism

D10795's rung, `monoHoleLamOwnCallsPin`, pins a hole lambda at the calls of the parameter made
in the named element's body. It reads only a lambda LITERAL argument (`monoHoleLamArgFe`), so an
`Ident` naming an un-annotated lambda never reaches it. The rungs that do follow a named lambda
read the fn-flow class over the whole list, where `apply2`'s `(i32, i32)` and `apply3`'s
`(f64, f64)` disagree.
