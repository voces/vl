### D3003 — a record literal nested in a literal stored at a wider declared record reads its re-seated field at the wider type

**check-clean silently wrong · clause 1 · identical on master `b34730ad9` and on #3253 · found by the #3253 review grid · filed 2026-09-28**

Repro:

    type D = { v: f64 }
    type W = { d: D }
    const x: i32 = 3
    const c: {[string]: W} = Map()
    const o = { d: { v: x } }
    c["k"] = o
    print(o.d.v / 2)
    // PRINTS 1.5

Want:

    1

#### Mechanism

The map store builds `o` at `W`, so its nested literal is built at `D` and `o.d.v` loads an `f64`. The checker types `o.d.v` as `i32`, so `/ 2` is an integer division, but the read classifies as `f64` and divides as one. #3253's read narrowing (`memReadNarrowOp`) takes only a receiver that is itself an object-literal binding, and `o.d` is a field read.
