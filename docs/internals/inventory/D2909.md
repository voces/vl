### D2909 — a list of object literals returned or pushed into a declared record list keeps its own row

**closed · runs, prints `7` · was check-clean invalid wasm · `il` adopts the `I[]` its return delivers it to · fixture `tests/cases/soundness/record-literal-list-returned-at-wider-record-list.vl` · closed 2026-09-30**

Repro:

    const i: { f: i32 } = { f: 4 }
    type I = { f: i64 | null }
    function mk(): I[] {
      const il = [{ f: 7 }]
      il
    }
    print(mk()[0].f)
    // vl check: rc 0.  vl run: invalid module inside `mk`

Want:

    7

#### Mechanism

D2881's destination walk (`dsDestSlotAt`) knows a binding, an argument, a field, an outer list
literal and an assignment, but not a function's return or a `push` argument, so the literal is
built at the `{ f: i32 }` row its elements pick and delivered where `I[]` is expected.

#### Ablation

| ingredient removed | outcome | needed? |
| --- | --- | --- |
| the `{ f: i32 }` record | runs, prints `7` | **yes** |
| the return (`const ic: I[] = il; ic`) | runs, prints `7` | **yes** |

#### Grading list

`const ic: I[][] = []; ic.push(il)` at the top level, which is invalid wasm the same way.

#### Record covariance (2026-09-30)

The destination stores a numeric field at another width or kind, so under the record-covariance ruling the literal-holding binding or function is not adopted and the program keeps its master behaviour until the owner rules on [D3339](D3339.md) (DECISIONS.md "Record covariance: only a fresh value widens").

#### Close under the D3339 ruling (2026-09-30)

Closed by the owner's ruling D3339 (A): a literal-holding binding adopts a record that stores a number at another width or kind, fully (DECISIONS.md "Record covariance: only a fresh value widens"). `il` holds only a literal and is returned where `I[]` is declared, so it adopts `I[]` and is built there; the return and the `push` grading-list face both deliver a list of `I`.
