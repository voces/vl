### D3885 — two same-named-field records `A | B` where one field is the base type and the other a literal set share one tag, so `is B` answers by the field's VALUE: an `A` whose `x` is in B's literal set tests as a `B`

**check-clean silently wrong · found by the rv3465 review of #3463–#3465 · related to D1023 (the all-literal pair) and D3870 (closed by the owner's structural-records ruling; whether `{ x: 1 }` declared as A should test `is B` against `{ x: 1 | 2 }` is a follow-up question that ruling raises) · filed 2026-10-09 against master `1af9fe52f`**

Repro:

    type A = { x: i32 }
    type B = { x: 1 | 2 }
    function f(v: A | B): string { if v is B { return "B" } "A" }
    const a: A = { x: 1 }
    print(f(a))
    // vl check: rc 0 (hints only).  vl run: rc 0
    // PRINTS B

Want:

    A

#### Mechanism

`A` and `B` have the same field names and one storage rep (`x` is an `i32` either way), so the pair
gets ONE tag in `assignTags` (`emit_collect.vl`) instead of the "cannot be discriminated" refusal
that two same-field-name arms with different field types otherwise get. The admission is one of
the literal-set exemptions there (`variantLitDiscriminable`, D1023; `variantLitRepUnifiable`,
D1050), and it treats a literal-typed field as a discriminant even when the OTHER arm's field type
is the base type that contains those literals. With the tag shared, `v is B` can only test the
literal field's membership, so it answers from the value: the declared type `A` of `a` is not
consulted. Two sets that do not intersect are a real discriminant and answer correctly. The same
holds for `{ k: string }` against `{ k: "b" }`, and for two literal sets that overlap
(`{ x: 2 | 3 }` against `{ x: 1 | 2 }`, `a.x == 2`).

#### Ablation

Every row is the witness with one ingredient changed; "outcome" is `vl run`.

#### Grading list

Whether a record `{ x: 1 }` that is both an `A` and a `B` structurally should answer `is B` with
`true` is the design question D3870 asks about same-shaped records; the `Want:` above is the answer
if the declared type of the value is what `is` reports, and the close has to say which it is before
it says what the value of `a` does. Programs that run correctly today and must keep running: the
value outside the set, the disjoint-literal pair, and the string-against-integer-literal check
reject. Grade it at the annotated `f(v: A | B)` above, at an inferred union parameter, and at a
`const v: A | B = a` binding with `print(v is B)`, which prints `true` today.
