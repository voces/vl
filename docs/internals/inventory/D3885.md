### D3885 — two same-named-field records `A | B` where one field is the base type and the other a literal set share one tag, so `is B` answers by the field's VALUE: an `A` whose `x` is in B's literal set tests as a `B`

**closed 2026-10-10 by lane SC · runs · as designed by the owner's ruling (A): `is` is structural · found by the rv3465 review of #3463–#3465 · related to D1023 and D3870 · filed 2026-10-09 against master `1af9fe52f` · pins: `tests/cases/unions/is-contained-arm-tests-the-value.vl`**

Repro:

    type A = { x: i32 }
    type B = { x: 1 | 2 }
    function f(v: A | B): string { if v is B { return "B" } "A" }
    const a: A = { x: 1 }
    print(f(a))
    // vl check: rc 0 (hints only).  vl run: rc 0
    // PRINTS B

Want:

    B

#### Mechanism

The owner's ruling (A), 2026-10-10: `is` is STRUCTURAL; it tests whether the value fits the type,
not which declaration the value was built at. An `A` whose `x` is in `B`'s literal set fits `B`,
so `v is B` is true and the witness prints `B`. That is the program's meaning, not a defect.

What the ruling adds is a hint where the surprise lives: an `is` whose tested record type is
contained in another record arm of the operand's union (`B` in `A`) says so (`` `B` is contained in `A`, so `is B`
tests the value ``, code `contained-arm-is-test`, `recordContainedIsAt`). Disjoint literal sets
are a real discriminant and get no hint, and neither does a scalar, literal or list containment
(`i32` in `i64`, `boolean[]` in `(boolean | null)[]`), which reads as the narrowing it is; the string-against-integer-literal check reject keeps
its behaviour.

The tag-sharing analysis this row first filed (one tag for `A | B` in `assignTags`) is how the
structural answer is produced, and stays correct under the ruling.

#### Grading list

Whether a record `{ x: 1 }` that is both an `A` and a `B` structurally should answer `is B` with
`true` is the design question D3870 asks about same-shaped records; the `Want:` above is the answer
if the declared type of the value is what `is` reports, and the close has to say which it is before
it says what the value of `a` does. Programs that run correctly today and must keep running: the
value outside the set, the disjoint-literal pair, and the string-against-integer-literal check
reject. Grade it at the annotated `f(v: A | B)` above, at an inferred union parameter, and at a
`const v: A | B = a` binding with `print(v is B)`, which prints `true` today.
