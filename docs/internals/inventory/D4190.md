### D4190 — a null-only list literal as a value `match`/`if` tail never receives its typed destination's element rep

**now a loud check reject 2026-10-17 (the design owes it: no implicit container widening, as the same tail with `[1]` into `(i32 | null)[]` already refused) · was check-clean invalid wasm (clause 1) · closed by D5520: a `null[]` arm and a `(K | null)[]` destination differ in storage class · the statement form and a direct `[null]` into the annotated destination still run · filed 2026-10-12 against master `7bce607c6` · found while grading [D1832](D1832.md)'s close over typed delivery positions**

Repro:

    type K = { k: i32 }
    function f(n: i32): (K | null)[] {
      return match n { 0 => [null], _ => [{ k: 1 }] }
    }
    print(f(0).length)
    // vl check on master: rc 0, then invalid module inside `f`.  Now: null[] is not (K | null)[]

#### Mechanism

Not yet ablated to a rung. The destination is annotated, so D1832's refusal correctly lets the
literal through, but the tail delivery does not seed the element rep the statement form
(`if n == 0 { return [null] }`, which runs) does. With a scalar element
(`(string | null)[]`) the same tail is a loud emit reject, `bare null needs a struct-typed
context`; a value `if` into an annotated binding over `(K | null)[]` is invalid wasm too.

#### Ablation

| ingredient removed | outcome | needed? |
| --- | --- | --- |
| the null-only tail (`[null]` → `[null, { k: 2 }]`) | prints `2` | **yes** |
| the value tail (`if n == 0 { return [null] }`) | prints `1` | **yes** |
| the struct element (`(string \| null)[]`) | loud emit reject | no |
