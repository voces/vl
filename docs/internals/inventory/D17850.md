### D17850 — a `let x = null` a hole parameter fills is read after a join at `null`, so its value is lost once it builds

**loud emit reject · clause 1 · `internal: an emit-phase write changed a type an emit memo may hold` / `emitProgram: union atom has no value box` · was check-clean silently wrong on master under #10795 (7ce14c5b), reverted by COV-UNION · `vl check` rc 0 · filed 2026-11-28 against master `45f879eda` by COV-UNION (coordinator ruling)**

Repro:

    function f(a) {
      let t = null
      if a > 5 { t = a }
      return t
    }
    print(f(1))
    print(f(9))
    print(f(1) == null)
    // vl check: rc 0.  under #10795: prints null null true; since the revert: loud emit reject

Want:

    null
    9
    true

#### Mechanism

The store is right: the local is `i32 | null` at each instance and the write lands
(`print(t)` after the `if` prints `9`). The type readers after the join are wrong: the checker's
narrowing join of the then-branch's `_` (the open hole the parameter fills) with the else path's
`null` closes to `null`, dropping the open member, so `t ?? -1`, `t == null` and `return t`
read `null`. `scopeTyAt` returns that closed template type when the elaboration recorded nothing
for the read. The unconditional spelling's caller `f(1) == null` folded the same way to `true`
(the call typed `null`). Before #10795 both were loud (the emit seal's ICE, D17844, or a
missing value box, D17831); #10795's seal fix and union registration let them build. Both halves
are reverted; the re-land waits for the join to keep its open hole (coordinator rule: a join
never drops an open member).
