### D14516 — a queued delivery does not reach a call that an inferred function hands back, so the call counts as delivered nowhere

**closed · now runs, prints `4` / `4` · was check-clean invalid wasm, clause 1 · filed and closed 2026-10-27 against master `7221c9861` · closed by `recLandingIn` (check_fit_rules.vl) following a call of an inferred function into each value it hands back, so `recQueuedLandingOf` and `recQueuedReaches` see the delivery of `relay()` land the `mk()` it returns · fixtures `soundness/relayed-call-lands-with-its-sibling.vl`, `soundness/error-relayed-call-lands-apart.vl`**

Repro:

    type J = { f: i32 | null }
    function mk() { { f: 4 } }
    const wideJ: J = mk()
    function relay() {
      return mk()
    }
    const v: J = relay()
    print(wideJ.f ?? 0)
    print(v.f ?? 0)

Want:

    4
    4

#### Mechanism

`recSitesLandAt` builds `mk`'s record at `J` once every call of `mk` lands there or is queued
for no delivery. The delivery of `relay()` as a `J` is queued on the `relay()` call. `recLandingIn`
followed generic identities, bindings and literal fields from it, but not a call of an inferred
function, so the `mk()` inside `relay` counted as queued for nowhere. It was then served only if
it was read in place (`recReadInPlace`), which a returned call never is. `mk` built at its own
row, and `wideJ` received it as `J`.

#### Grading list

- A two-hop relay (`relay2` returning `relay()`) and a relay delivered as an argument or a list
  element run too.
- A relay delivered as `K = { f: i64 | null }` beside `wideJ: J` stays loud, and refuses at both
  landings, as D8301 does.
- `const v = relay()` read only as `v.f` stays check-clean invalid wasm. It is the D14512 family:
  a field read through a binding or a relay, which the rip in D14515 closes.
- D14515's kind 4 (`return_inferred/ann` of the unlanded-call matrix with the `recReadInPlace` term
  removed) now refuses at check instead of failing validation.
