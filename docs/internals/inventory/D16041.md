### D16041 — a declared union of identical record arms interns one struct row while its checked type stays a two-member union

**closed 2026-11-13 — equal anonymous record arms of a declared union are one member, as the inline spelling's are · was loud emit reject · filed 2026-11-13 against master `0a58b213d`**

Repro:

    type R = { v: i32 } | { v: i32 }
    const r: R = { v: 7 }
    print(r.v)
    // vl check: rc 0.  vl run: emit error, field access receiver is not a struct

Want:

    7

#### Mechanism

There are two sides, and they disagree about what `R` is.
- The emitter interns `R` as ONE struct row. `unionDeclStructAlias` (`emit_collect.vl`) reads its
  arms as one shape spelled twice, so `R` lowers as a plain struct.
- The checker keeps `R` as a `TyUnion` of two members. The declaration route
  (`check_relate_core.vl`, the `UnionDecl` member loop) resolves each arm to its own arena entry,
  and the two are `tyEq` but not deduplicated. The inline spelling's route does collapse them, so
  `{ v: i32 } | { v: i32 }` as an annotation runs.

A receiver whose checked type is a union is not a struct to `structIndexOfExpr`, and `R`
has no union row for the union arms to find. So every consumer that reads the checked type
refuses: the field read, the `is` test, and a store into the record type.

A scratch probe at the field-read floor on `0a58b213d` printed
`union n=2 m=332 m=333 eq Rrows=1 sNames=1`, meaning: two distinct, `tyEq` members, and one row
named `R`. So this is not one type with two rows.

The close deduplicates on the declaration route (`pushDistinctAnonRecord`), but only for records
no declaration, brand or generic application names. The annotation route's broader predicate
(`pushDistinctVariantTy`) also folds `A | B` over two equal named records. On the declaration
route that loses runs: `A` is a variant arm by spelling, so it mints no row of its own, and a
one-member union mints none either.
