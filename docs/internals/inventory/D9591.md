#### Mechanism

The function-flow union-find (fn_flow_shadow.vl) moves a stored value into its container's
slot at a storage method only when the receiver's type names a list, map or set
(`ffMethod`, by `fnFlowElemKind`). Inside `fill`, `mm` is an un-annotated parameter whose
type is a type variable, so `mm.set("k", id)` was an opaque call: `id` never reached the
map's value slot, the `.get` read at module level had no value flowing into it, and the call
through `r` reached the emitter with an open callee. An indexed store is an assignment, not a
member call, and does not go through that arm, which is why `mm["k"] = id` ran. A call of `set` / `add`
(value slot) or `push` / `unshift` / `insert` (element slot) on a type-variable receiver now
takes the storage arm with the slot kind its name implies (`ffStoreKindOfName`,
`ffMethodAt`).
