### D9591 — a generic stored by `.set` through an un-annotated map parameter, read by `.get` at two types, is called as though its read were not a function

**loud emit reject · `vl check` rc 0 · `callee is not a function name` · clause 2 · found closing [D9480](D9480.md) · present on master `49a7d0b10` · filed 2026-10-22 against master `49a7d0b10`**

Repro:

    function id<T>(x: T): T { x }
    function fill(mm) { mm.set("k", id) }
    const m = Map()
    fill(m)
    const r = m.get("k")
    if r != null {
      print(r(2))
      print(r("s"))
    }
    // vl check rc 0.  vl run: emit error: emitProgram: callee is not a function name

Want:

    2
    s

#### Mechanism

Not traced. From the ablation only: the map hand-on walk (`monoFlowMapHandOn`, emit_mono.vl)
counts an indexed assignment through the parameter as a store into the map, and the
`.set` spelling of the same store is not counted, so the read plan has no value for `r` and
the call through it reaches the emitter with an open callee.
