### D16955 — an un-annotated `let x = null` filled only by a function declared before it keeps the type `null`, so every read yields `null`

**closed 2026-11-18 by lane F2 · runs, prints `5` · was check-clean silently wrong, clause 1 · closed by hoisting an un-annotated module `let x = null` at its own A-infer-null hole (`progHoistValues`, `nhHoistNote`) instead of the error placeholder, and binding that hole at the declaration in pass 2 (`letDeclInferredBound`), so a body checked before the binding fills it with its writes; two such writes of different types are now refused as they are after the binding · pins: `tests/cases/null/let-null-filled-by-function-declared-before.vl`, `tests/cases/null/error-let-null-two-functions-write-two-types.vl` · found by grading every capability-matrix template for WRONG cells · filed against master by lane F1**

Repro:

    function take() {
      x = 5
      print(x)
    }
    let x = null
    take()
    // prints `null`

Want:

    5

#### Mechanism

The flow-sensitive `let` rule (DECISIONS.md, "A read of a `let` takes its most recent write's
type") widens an un-annotated `let x = null` by its later writes. A function declared ABOVE
the `let` is checked first, against the hoist's error placeholder (a `null` initialiser kept it),
so its write `x = 5` filled nothing and the binding pass 2 declared stayed typed `null`. The write
was then stored as a `null` and every read yielded `null`.

#### Ablation

| spelling | outcome | needed? |
| --- | --- | --- |
| the repro | prints `null` | — |
| `print(x ?? 0)` in place of `print(x)` | prints `0` | the read form: no |
| `if x != null { print(1) } else { print(0) }` | prints `0` | no |
| `take()` then a module-level `print(x ?? 0)` | prints `0` | the read inside the function: no |
| `let x: i32 \| null = null` | prints `5` | the un-annotated `let`: **yes** |
| `let x = 1` (a number, not `null`) | runs (`x + 1` prints `6`) | the `null` initializer: **yes** |
| the `let` declared before `take` | prints `5` | the function declared first: **yes** |
