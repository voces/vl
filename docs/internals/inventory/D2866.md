### D2866 — two annotated records `{ f: boolean }` and `{ f: i32 }` passed to one hole reader build invalid wasm

    // Was: invalid module inside `R$1` — expected (ref null $type), found (ref $type)

Want:

#### Mechanism

The annotation `{ f: boolean }` mints a row; `{ f: i32 }` mints none, since the interner does not
split code-0 kinds, and `{ f: 3 }` gets an anonymous row of its own. The rendered-spelling reader
(`structIndexOfTypeName`) matched `{f:i32}` to the first row of that layout, the `boolean` one,
so `b` was built and read there, and printed `true` even without a function. The instance's
signature took the `i32` row from the arena type. The strict pass of that reader now passes over a
DECLARED row whose own field type is the other of `i32` and `boolean` when a later row agrees
with the spelling, keeping the first match as the fallback (`code0SpellingFitsRow`). An
anonymous row still wins first-match, as on master: preferring among anonymous rows moved
nested record literals onto a sibling outer row (invalid wasm in the #3230 review's `nest*`
cells).

The literal-set face printed `0` for `"y"`: a literal set used only inside a record annotation
did not turn the emitter's atom classifiers on (`anyLitUnionUsed`), so a hole reader of that
field printed the atom id. Reading it through a local (`const t = o.f; print(t)`) stays
master's refusal.
