### D16965 — a `??` over a binding holding a join of `null` and a built record's field read refuses its default as handed on at its own type

**closed 2026-11-18 by lane F2 · runs, prints `4` · was a loud check reject, clause 2 · closed with D16967 by one built-read reader: `recBuiltReadTy` reads a value join through its non-null tails and a `?.` read as a field read, and a `d` used as a field of a literal default over such a read is skipped by the own-storage refusal (`recCoalesceDefaultsAt`), `check_fit_rules.vl` · pin: `tests/cases/records/built-record-join-binding-read.vl` · graded by `built-record-read-join-coal.matrix.vl`, `built-record-read-nullfield-coal.matrix.vl` · filed 2026-11-18 against master `0ca511a3e` by lane F2**

Repro:

    type J = { f: i32 | null }
    const m = Map()
    m.set("a", { f: 4 })
    const wm: {[string]: J} = m
    const d = { f: 1 }
    const w3 = { k: { x: d } }
    w3.k = { x: m.get("a") ?? d }
    const kk = if w3.k.x.f == 99 { null } else { w3.k }
    print((kk ?? { x: d }).x.f ?? 0)
    // vl check: rc 1, "`d`, which holds only literals, is built as J where line 7 delivers it, and it is handed on here at its own type, which stores a field differently; …"

Want:

    4

#### Mechanism

`recCoalesceDefaultDeliver` delivers a `??` default at the record its left side's read is built at
(`recBuiltReadTy`). That reader follows a container's element, a field of one, and a binding holding
such a read, but not a binding holding a value join of `null` and such a read. So `kk` reads as
unbuilt, the default `{ x: d }` is delivered at its own type, and `d`, built at `J`, is refused there.
