### D3494 — a function reached through a generic or hole wrapper, by value or by recursion still widens its runtime numbers instead of joining them apart

**check-clean silently wrong · held back to master's widening by the numeric-join lane's gate (`njFnReached`) · 72 of the #3327 review's `g3` cells print master's widened values · filed 2026-10-03 against master `a8c4dce6d` with the numeric-join lane applied**

Repro:

    function f<A, B>(k: i32, a: A, b: B) {
      if k == 0 { return a }
      b
    }
    function g<A, B>(k: i32, p: A, q: B) {
      f(k, p, q)
    }
    const x: i32 = 7
    const y: f64 = 2.5
    print(g(0, x, y) / 2)
    // PRINTS 3.5

Want:

    3

#### Mechanism

The numeric-join ruling joins runtime numbers of different types as a union. The lane keeps that
join only where every caller reads the function's own result at concrete pins. A function named
inside a generic, hole or lambda body, read as a value, or naming itself is `njFnReached`
(`compiler/typecheck.vl`). Every join in its body is then master's widening, and the instance
does the same (`njPinGated`). Without the gate, the wrapper's own template typed the call at
the kept-apart `A | B`. `validateEscJoins` then refused it at each pin ("an inferred union
return through an un-annotated parameter is not yet supported by codegen"), so 165 cells that
ran on master were refused, and a recursive one trapped. The direct call `f(0, x, y)` in the
same program also widens: the gate is per function, not per call site.

#### Ablation

| --- | --- | --- |
| `print(f(0, x, y) / 2)` with no `g` in the program | prints `3` | **yes** (the wrapper) |
| `g` non-generic with annotated parameters | prints `3` | **yes** (an open context) |
