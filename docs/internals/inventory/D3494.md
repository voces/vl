### D3494 — a function reached by recursion or by value still widens its runtime numbers instead of joining them apart

**check-clean silently wrong · held back to master's widening by the numeric-join lane's gate (`njFnReached`) · the generic and hole wrapper face fixed by lane HL (D3589) · filed 2026-10-03 against master `a8c4dce6d` with the numeric-join lane applied, narrowed 2026-10-04 against `c473889d1`**

Repro:

    function f<A, B>(k: i32, a: A, b: B) {
      if k == 0 { return a }
      b
    }
    function g<A, B>(k: i32, d: i32, p: A, q: B) {
      if d > 0 { return g(k, d - 1, p, q) }
      f(k, p, q)
    }
    const x: i32 = 7
    const y: f64 = 2.5
    print(g(0, 2, x, y) / 2)
    // PRINTS 3.5

Want:

    3

#### Mechanism

The numeric-join ruling joins runtime numbers of different types as a union. The lane keeps that
join only where every caller reads the function's own result at concrete pins. A function named
inside a lambda body, read as a value, naming itself, or named inside a generic or hole body
whose own function is one of these is `njFnReached` (`njGateScan`, `compiler/typecheck.vl`). Every
join in its body is then master's widening, and the instance does the same (`njPinGated`). Here
`g` names itself, so `f`, named in `g`'s generic body, is held too, and the held call's result is
`njExprHeld`. A generic or hole wrapper reached only directly no longer holds its callee: its
pins re-join the callee's kept-apart return (D3589).
