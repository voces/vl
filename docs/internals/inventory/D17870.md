### D17870 — a binding of a type parameter seeded from a top-level generic, called at a type the parameter's own calls do not take, is built at the parameter's instance

**check-clean invalid wasm · clause 1 · filed 2026-11-28 against master `544daecc0` by COV-CLOS-3 (found pinning D17324)**

Repro:

    function same<T>(k: T): T { return k }
    function other<T>(k: T): T { return k }
    function mid2<F>(a: F) {
      const b: F = other
      print(a(4))
      print(b("z"))
    }
    mid2(same)
    // vl check: rc 0.  vl run: invalid module, "type mismatch: expected i32, found (ref $3)" inside `mid2`

Want:

    4
    z

#### Mechanism

Not traced. The binding holds `other` but its call is built as `a`'s, at the instance `a(4)`
fixes: the string argument meets an `i32` parameter. Seeded from a parameter instead (`a1: G`),
the same program runs, so the top-level generic's read is what the elaboration's alias walk
does not follow.

#### Ablation

| ingredient removed | outcome | needed? |
| --- | --- | --- |
| `a(4)` | runs, prints `z` | **yes** |
| the annotation (`const b = other`) | runs | **yes** |
| `b` at the same type as `a` (`b(5)`) | runs | **yes** |
| a parameter source (`const b: F = a1`, `mid2(same, other)`) | runs | **yes** |
| `let` for `const` | still invalid | no |
| the call order (`b("z")` first) | still invalid | no |

#### Grading list

`const b: F = same` refuses instead, "a generic function taken as a value reaches no call that
fixes its type"; its close must re-grade it.
