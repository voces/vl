    function w(h, x) { return h(x) }
    let f = inc0
    f = half

#### Mechanism

D9007's close judges the functions a hole parameter may hold at the argument types of the
call through it. Here that argument is `x`, itself a hole parameter, so the type is open while
`w`'s body is checked and the judge declines. The type that fixes `(i32)` is `3`, at the call
`w(f, 3)`, in another body.

#### Decision

The judgement moves to the outer call. Where `w(f, 3)` hands a re-pointed `let` to a hole the
body calls, `judgeFnArgHoleCalls` asks `genFnHoleCallInsts` for each instance the body calls
the hole at under that call's bindings (`x = i32`), and refuses at the write through
`holeLetWritesDisagree`, D9003's contract and message. Each outer call is its own copy: two
call sites handing `w` different functions, or one binding at two types, are judged apart and
never as one set.

A body that hands the hole on to another hole function (`v(h, x, y)`) gets its calls moved out
of `v` as rows with no call node, so no call groups their arguments. `genFnHoleSoleInst` reads
them only where each parameter is given exactly one closed type across the body, which is the
one instance every call asks; anything else stays quiet.
