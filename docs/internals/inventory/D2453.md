### D2453 — a top-level write used as a value moves into a block and its narrowing does not reach the next statement

**check-clean invalid wasm · clause 1 · pre-existing on master `20651a88b` · filed 2026-09-25 against master `20651a88b`, found reviewing #3154**

Repro:

    function h(): i32 { 4 }
    let a: i32 | null = null
    print(a = h())
    print(a + 1)
    // vl check: rc 0.  vl run: invalid module, top-level code: type mismatch: expected i32, found (ref $type)

#### Mechanism

Not ablated. The checker narrows `a` to `i32` after the write, so `a + 1` checks. On master the
write's value position already failed; after [D2398](D2398.md) the first line moves its write
into a block of its own (so its spill stays a start-function local), and the post-write
narrowing is scoped to that block, so the second line reads the box as an `i32`. Master fails at
the second line too, so the narrowing was lost before the block existed.

| --- | --- | --- |
| the module scope (inside a function) | prints `4` then `5` with [D2398](D2398.md)'s close; its value position on master | **yes** |
| the value position (`a = h()` as a statement) | runs | **yes** |

#### Grading list

The same with `a: i32 | string`, and with the second read inside a function.
