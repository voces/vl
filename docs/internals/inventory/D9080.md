### D9080 — a `const` bound to an `if` choosing between two generic or un-annotated functions refuses when handed to a generic parameter or `.map`

**loud emit reject · `vl check` rc 0 · clause 2 · CAPABILITY: the same `if` written inline at the argument runs ([D9005](D9005.md), [D9072](D9072.md)), and so does the `const` when its arms are annotated · found closing [D9005](D9005.md) · present on master `8f0df7360` · filed 2026-10-21 against master `8f0df7360`**

Repro:

    function idg<T>(t: T): T { return t }
    function kg<T>(t: T): T { return t + t }
    function app<T>(g: (x: T) => T, v: T): T { return g(v) }
    const c = [1].length > 0
    const h = if c { idg } else { kg }
    print(app(h, 3))
    // vl run: emitProgram: monomorphize: unsupported argument type for `g` in a call to `app`

#### Mechanism

Not traced. The inline `if` is coerced arm by arm at the callee's pin
(`monoArgIsOpenFnChoice`, emit_mono.vl); a name bound to the `if` is an `Ident` whose
declaration is neither generic nor an open binding of one, so the argument is not taken as
riding the type parameters. `monoIfBindingOf` already follows a never-written binding whose
initializer is such an `if`, and is the likely seam.
