#### Mechanism

`emitIs` tests a union's tag only where it can reach the raw box: a frame slot
(`identSlotIsUnionBox`, which excludes globals on purpose), a narrowed member path, or an
operand whose own type is still a union. A narrowed read of any other union place — a module
global, an index cell `xs[0]`, a closure-written local (rewritten to the cell read `v[0]`) — is
already unboxed to the member, so it misses every tag rung and reaches `monoStaticIsResult`.
That fold asks `monoArgTyName`, which does not see narrowing and answers the declared spelling
(`f64|boolean`, printed by an `emitFail` probe on each of the witness, the index cell, the
closure-written cell and D2442's witness), and the fold answers 0. `const w = v` fails the same
way: `w` is a plain `f64` local, but its pin name comes from the union it was initialised from.

The fix makes `emitIs` test the storage and not trust the narrowing. When the operand is
a name or a member or index place with a live narrowing, `emitIs` lifts that narrowing for the
test (`maskNarrowFor`, which marks the slots retired and restores them after). The read is then
the declared box, or the nullable niche, and the existing tag and null rungs answer it. So a
write the narrowing cannot see (through an alias, an argument, or a closure that runs after the
guard, as in D2402, D2407, D2461 and D2462) is answered from the value the place holds now. A
capture whose env field holds the narrowed member, not the box, is not lifted. Separately, an
un-narrowed FRAME LOCAL whose checker type is exactly the tested type is a tautology
(`const w = v`, whose slot holds the member). That rung existed, guarded by `!uDeclared`, for
#1672. A `match` scrutinee is excluded (`matchScrutAt`), because it is one node whose recorded
type is the last arm's.

A first version trusted the checker's narrowing for every place. #3157's review showed that
turned correct answers into wrong `true`s and traps wherever the narrowing is unsound at run
time: 20 cells went right to wrong and 140 went right to trap over its two grids. With the
storage test, those grids read 0 right to wrong and 0 right to trap, with 95 wrong to right and
4 trap to right.
