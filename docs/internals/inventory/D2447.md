### D2447 — a redundant `is` test inside the same narrowing answers false for a boxed value union

**check-clean silently wrong · clause 1 · filed 2026-09-25 against master `20651a88b`, found by the
review of #3150's generated grid · open — a separate lane fixes it**

Repro:

    let v: f64 | boolean = 1.5
    if v is f64 {
      if v is f64 { print("yes") } else { print("no") }
    }
    // PRINTS no

#### Mechanism

Not yet ablated to the rung. The inner test's operand reads under the outer narrowing, so the
operand the emitter tests is the narrowed member rather than the box, and the tag test on it
answers false. It needs a place the emitter does not hold in a plain local: a module
global, an index cell, or a closure-written local (a shared cell, as in #3150's `bare_*` grid
cells). A plain local answers `yes`, and so does `string | i32`.

#### Ablation

| ingredient removed | outcome | needed? |
| --- | --- | --- |
| the outer narrowing | prints `yes` | **yes** |
| the box (`string \| i32`, narrowed to `i32`) | prints `yes` | **yes** |
| the module level (a local inside a function) | prints `yes` | **yes** — an index cell inside a function prints `no` |

#### Grading list

`i64 | boolean`; `f64 | string`; an index cell `xs[0]` of `(f64 | boolean)[]`;
`const w = v; print(w is f64)` under the narrowing (prints `false`); `const b = v is f64`
(prints `true`, the control). It also makes wrong values out of D2390/D2405 re-tests: #3150's
grid cell `cell_002` re-tests `xs[0]` after a writing call and prints `2` for `6`.
