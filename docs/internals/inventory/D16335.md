### D16335 — the result of a call through a hole parameter handed a hole function that calls its own parameter is a hole at check, so any annotated destination accepts it

**check-clean silently wrong · clause 1 · `vl check` passes a `boolean` or `string` binding of an `i32` result · beside [D16334](D16334.md), whose map keeps the same hole as its value type · found grading D16334 · filed 2026-11-14 against master `b09064cee`**

Repro:

    function lap(g) { return g(1) + 1 }
    function use(k) { return k((a) => a * 10) }
    const s: boolean = use(lap)
    print(s)
    // vl check: 0 errors.  PRINTS true

Want:

    a check reject: `use(lap)` is an `i32`, which a `boolean` binding does not take

#### Mechanism

Not traced. `const zz: boolean = use(lap)` raises nothing, so the check types the call's result as an
open hole (`_`), which every destination accepts. A callback that calls no parameter of its own
does not leave the hole open.

#### Ablation

| spelling | outcome |
| --- | --- |
| the witness | prints `true` |
| `const s: string = use(lap)` | check-clean invalid wasm |
| `function use(k) { return k(1) }; function id(x) { return x }; const s: string = use(id)` | loud check reject |
| the same with `inc(x: i32): i32` | loud check reject |
| `const s = use(lap)` | runs, `11` |
