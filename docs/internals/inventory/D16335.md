### D16335 — the result of a call through a hole parameter handed a hole function that calls its own parameter is a hole at check, so any annotated destination accepts it

**closed 2026-11-14 · now a loud check reject, `cannot assign i32 to 's' of type boolean`, which the design owes: `use(lap)` is an `i32` · was: check-clean silently wrong · clause 1 · `vl check` passes a `boolean` or `string` binding of an `i32` result · beside [D16334](D16334.md), whose map keeps the same hole as its value type · found grading D16334 · filed 2026-11-14 against master `b09064cee`**

Repro:

    function lap(g) { return g(1) + 1 }
    function use(k) { return k((a) => a * 10) }
    const s: boolean = use(lap)
    print(s)
    // vl check: 0 errors.  PRINTS true

#### Mechanism

Not traced. `const zz: boolean = use(lap)` raises nothing, so the check types the call's result as an
open hole (`_`), which every destination accepts. A callback that calls no parameter of its own
does not leave the hole open.

**Closed.** The check types a call through a hole parameter from the function bound to it (`holeCallInstOf`, check_relate_core.vl). Bound to a declared un-annotated function, its own open signature carries no lambda's parameter type, so the result stayed open. The parameter's binding now names that function (`holeDeclOfFnTy`, the lone member of its function set, else the function whose own hole its first parameter names), and the call is typed as the direct call is (`holeDeclCallInst`): each lambda argument at the closed types every call of that parameter in the function's body passes, nested functions included and matched by declaration (`ftParamCallsAt`), then the body at the closed arguments. Grid `hole-call-through-declared-hole-fn.matrix.vl`.
