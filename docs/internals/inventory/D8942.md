### D8942 — a generic function declared to return `T` whose body gives `f64` at `T := i32` is accepted at that call

**closed 2026-10-21 by lane L1 · now a loud check reject (`` `w` returns f64 at this call's types ``) · was check-clean invalid wasm · clause 1, present on master `30ff8d9b5` · fixtures `tests/cases/soundness/error-generic-fn-widening-at-i32.vl` and `tests/cases/generics/generic-fn-widening-runs.vl` · filed 2026-10-21 against master `30ff8d9b5`**

Repro:

    function w<T>(x: T): T { return x / 2.0 }
    const r = w(3)
    print(r)
    // vl check: `w` returns f64 at this call's types, which its declared result i32 cannot hold

#### Mechanism

`x / 2.0` over `T` checks as `T`, so the declared `T` result is accepted once at the
declaration, and no call re-checks the body at its binding. At `T := i32` the instance
returns an `f64` from an `i32`-typed function. Closed at the call (`check_calls.vl`):
`genericDeclRetMisfit` (`check_relate_core.vl`) re-derives a generic body whose declared
result mentions a type parameter at the call's bound types. If that body's numeric
result does not fit the substituted declared result, the call is refused and must be
made explicit with `as`. The refusal sits at the call because the declaration is right
at `T := f64`, where the same function runs.
