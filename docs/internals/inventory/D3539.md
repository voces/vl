### D3539 — a type parameter only literal arguments bind ignores the call's destination, so `filled(4, 0.0)` into `f32[]` is an `f64[]`

**closed 2026-10-03 for f32 and every value element type — the witness prints `1.5` and `4` · was loud check reject, clause 2 · sunpa SP-007 · filed and closed by lane FZ against master `f6e17953b` · fixtures `tests/cases/generics/destination-binds-literal-type-param.vl`, `tests/cases/generics/error-destination-literal-type-param-inexact.vl` · the `u8[]` half is D3620, closed by `std:bytes`'s `zeroBytes` under the owner's 2026-10-04 ruling (A)**

Repro:

    import { filled } from "std:array"
    const hs: f32[] = filled(4, 0.0)
    hs[1] = 1.5
    print(hs[1] + hs[0])
    print(hs.length)
    // master: vl check rc 1, "cannot assign f64[] to 'hs' of type f32[]"

Want:

    1.5
    4

#### Mechanism

`checkCallOnFuncTy` bound every type parameter from its arguments alone, first use wins, so
a literal argument bound `T` at the literal's default type (`f64`, `i32`) before anything
looked at where the result was going. `seedExpected`, which every delivery position already
calls with the expected type, reached only lambdas, list and record literals. It now records
the expected type of a call to a generic or a method too (`callDstTy`, also through the arms
of an `if`/`match`/block and a list spread). `dstBindLitTyParams` binds a return type
parameter from it, in the direct and the UFCS spelling, only when all three hold: every
argument binding the parameter is literal-only (a number, an operator tree of them, a literal
`const`, a list literal of those, or a call over them) and holds at the destination's type;
the destination stays within the literal's kind (an integer literal never makes `T` a float,
ruling B′); and the instance the arguments choose on their own CANNOT be delivered there
(`assignable` plus the container rule, `objShapeAdapterlessAt`), which is exactly where master
refused. Wherever master's instance was deliverable, nothing changes, so a body computing on
`T` keeps master's instance: `const r: f64 = half(5)` is still `2`. The literal arguments are
recorded at the substituted parameter type, which the monomorphizer pins the instance by.

literal union, `i32 | string`, `f32 | null` × ten positions (const, local, assignment,
return, tail, argument, field, element, push, map set) × eleven literal kinds × sixteen

2,462 gained, 0 lost, 0 silent (master had 40, all D3584), and every gained cell agrees with

0 lost, 0 changed, 0 newly silent, 248 gained. Every remaining refusal is a literal the
destination cannot hold, an integer literal at a float element, a float literal type, `u8`,
or an index at a non-`i32` instance (D3584).

**`u8[]` needs a ruling.** `const bs: u8[] = filled(4, 0)` still refuses: `u8` is a storage
type and a type parameter never binds it (DECISIONS.md, "`x as u8` is the i64 → i32
narrowing"). Binding `T = u8` would make `filled`'s `v: T` a `u8` VALUE parameter, which that
ruling says does not exist. Options: (A) a `std:bytes` export `zeroBytes(n: i32): u8[]`,
the smallest one-call spelling, built on the same `__array_new_default__` `loadBytes` uses;
(B) let a type parameter bind `u8` when it is used only as a list element and the value
parameter is read as an `i32` stored truncating, a new generic rule; (C) nothing, the push
loop stays the spelling. Recommendation (A). **Ruled (A) by the owner on 2026-10-04**:
`zeroBytes(n: i32): u8[]` landed in `std:bytes` as D3620, and the `filled` spelling above
still refuses, since no generic rule changed.
