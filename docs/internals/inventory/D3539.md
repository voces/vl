### D3539 — a type parameter only literal arguments bind ignores the call's destination, so `filled(4, 0.0)` into `f32[]` is an `f64[]`

**closed 2026-10-03 for f32 and every value element type — the witness prints `1.5` and `4` · was loud check reject, clause 2 · sunpa SP-007 · filed and closed by lane FZ against master `f6e17953b` · fixtures `tests/cases/generics/destination-binds-literal-type-param.vl`, `tests/cases/generics/error-destination-literal-type-param-inexact.vl` · the `u8[]` half waits on a ruling (below)**

Repro:

    import { filled } from "std:array"
    const hs: f32[] = filled(4, 0.0)
    hs[1] = 1.5
    print(hs[1] + hs[0])
    print(hs.length)
    // master: vl check rc 1, "cannot assign f64[] to 'hs' of type f32[]"

Want:

    1.5
    4

#### Mechanism

`checkCallOnFuncTy` bound every type parameter from its arguments alone, first use wins, so
a literal argument bound `T` at the literal's default type (`f64`, `i32`) before anything
looked at where the result was going. `seedExpected`, which every delivery position already
calls with the expected type, reached only lambdas, list and record literals. The fix
records the expected type of a CALL there too (`callDstTy`, also reached through the arms of
an `if`/`match`/block and a list spread), and `dstBindLitTyParams` binds a type parameter of
the generic return from it when every argument binding that parameter is a literal (a number,
an operator tree of them, a literal `const`, a list literal of those, or a call over them)
that holds at the destination's type, and on its own would have bound something else. Both
the direct and the UFCS spelling ask it. The literal arguments are then recorded at the
substituted parameter type, which is what the monomorphizer pins the instance by
(`monoArgPinTyIx`), and an integer literal leaf adopting a float is emitted as that float's
constant whatever its magnitude (`litLeafFloatTy`; without it `3000000000` at an `f64` was an
`i64.const`, check-clean invalid wasm).

#### Grading list

A 7,722-cell matrix — destination element f32, f64, i64, i32, u8, a literal union, a float
literal union, `i32 | string`, `f32 | null` × ten positions (const, local, assignment,
return, tail, argument, field, element, push, map set) × eleven literal kinds (int, float,
negated, hex, operator tree, division, literal const, float const, past-i32, `-(4)`) × eight
callees (`filled`, `concat` both spellings, user `mk`, `id`, `pair`, a UFCS `dup`, nested
`filled`) — graded the implicit spelling on master and on the candidate against the
explicit-type-argument spelling on the candidate: 1,040 master `runs` kept with identical
output, 3,646 gained, 0 lost, 0 silent, 0 disagreeing with the explicit spelling. Every
remaining refusal is a literal the destination cannot hold (a fraction at an integer, an
integer past f32's exact range, `-3` at `1 | 2 | 7`), a float literal type, or `u8`.

**`u8[]` needs a ruling.** `const bs: u8[] = filled(4, 0)` still refuses: `u8` is a storage
type and a type parameter never binds it (DECISIONS.md, "`x as u8` is the i64 → i32
narrowing"). Binding `T = u8` would make `filled`'s `v: T` a `u8` VALUE parameter, which that
ruling says does not exist. Options: (A) a `std:bytes` export `zeroBytes(n: i32): u8[]`,
the smallest one-call spelling, built on the same `__array_new_default__` `loadBytes` uses;
(B) let a type parameter bind `u8` when it is used only as a list element and the value
parameter is read as an `i32` stored truncating, a new generic rule; (C) nothing, the push
loop stays the spelling. Recommendation (A).
