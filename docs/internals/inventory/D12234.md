### D12234 — an un-annotated function returning one hole lambda, delivered at two function types, is refused at emit

**loud emit reject · `vl check` rc 0 · `emitProgram: `deliver` returns one function value and its calls deliver it at two function types, and one function value has one signature — return a separate function for each type` · clause 2 · CAPABILITY: each call builds a fresh closure, so no one value is shared between the two types; a single delivery runs · emit_mono.vl `monoDeliverCallRets` · found surveying emit refusals for L3 family (d) · filed 2026-10-24 against master `84b98d149`**

Repro:

    function deliver() {
      const l = (x) => x
      l
    }
    const f: (x: i32) => i32 = deliver()
    const g: (x: string) => string = deliver()
    print(f(1))
    print(g("s"))

#### Mechanism

A call of an un-annotated function delivered at a function type pins each hole lambda the
function returns at that type, as an annotated result would (D6522). `monoRetDeliveredAt`
records one type per function, and a second delivery at another type refuses, because the
lambda has one lifted body. Two deliveries at one type refuse too, under a sentence that
names two types, so the recorded type and the second delivery's do not compare equal. The
program is well-typed: `deliver` has no parameter and every call evaluates the lambda anew.

#### Ablation

| ingredient removed | outcome | needed? |
| --- | --- | --- |
| the second type (both deliveries at `(x: i32) => i32`) | still refuses, same sentence | no |
| the second delivery | runs, prints `1` | **yes** |
| the `const l` (`function deliver() { (x) => x }`) | check reject, `cannot infer a type for parameter `x`` | no |

#### Grading list

Two deliveries as arguments to annotated parameters; the bare-lambda tail, which the checker
refuses even at one delivery.
