### D16368 — a binding in a function declared above a module `[]` cannot take its type from the list's element, which later top-level code pins

**loud check reject · `'l' takes its type from an element of 'xs' whose type is not decided yet; annotate 'xs' or 'l'` · clause 2 · the same body declared after the push runs, so the order of the declarations decides it · beside D16301 (check order) · found closing D16364 · filed 2026-11-15 against master `63edf3dd`**

Repro:

    function one() {
      const l = xs[0] + 1.0
      print(l)
    }
    const xs = []
    xs.push(1.5)
    one()
    // vl check: 'l' takes its type from an element of 'xs' whose type is not decided yet

Want:

    2.5

#### Mechanism

Not traced past the refusal. Pass 2 checks `one`'s body before `xs.push(1.5)`, so `xs[0]` is an
open-element read (D14497). A statement-level read waits for the pin, but a declaration that
would infer its type from it is refused (`refuseOpenElemDecl`). Functions are hoisted, so their
position should not decide this.

#### Ablation

| `const v = xs; const l = v[0] + 1.0` | the same refusal | no |
| `const l: f64 = xs[0] + 1.0` | runs | **yes** (no annotation) |
