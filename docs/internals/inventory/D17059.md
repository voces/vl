### D17059 — `??` over a nullable number field read off a call evaluates the call again on the present path

**closed 2026-11-23 by lane IR-N2 · runs, prints `mk` then `3` · `emitCoalesceUnionField` keeps a receiver that is no re-readable place (`unionEqOperandOk`) in a lazily minted slot typed at its record's heap (`coalFieldRecvSlot`, code 51) and its present arm reads that slot · fixture `tests/cases/expressions/coalesce-field-off-a-call-evaluates-it-once.vl`; matrix `coalesce-field-off-call-*` (7 templates, 42 graded cells each; `i32` and `f64` fields WRONG at all 42 on master, every template 42 of 42 runs after) · was check-clean silently wrong, clause 1 · filed 2026-11-22 against master `87a19dea`**

Repro:

    type Cat = { meow: i32, foo: i32 | null }
    function mk(v: i32 | null): Cat {
      print("mk")
      return { meow: 1, foo: v }
    }
    print(mk(3).foo ?? -1)

Want:

    mk
    3

#### Mechanism

`emitCoalesceUnionField`'s `unbox` and `boxed` arms write the receiver with `emitCoalArmRecv`
once for the null test and again in the `else` that reads the present field. A name or a field
path re-reads harmlessly; a call runs a second time, its effects with it.

#### Ablation

| ingredient removed | outcome | needed? |
| --- | --- | --- |
| the call receiver (bound to a `const` first) | prints `mk` once | **yes** |
| the number field (a `string \| null`, `boolean \| null`, atom, record or union field) | prints `mk` once | **yes** |
| the top level (inside a function) | prints `mk` twice | no |
