### D1970 — a guard arm's exit counted only as its LAST statement, so an exit inside a bare block (or under `if`/`else`, or `match`) did not narrow the code after the guard

**closed 2026-09-22 (one divergence rule, `stmtAlwaysExits` in `compiler/ast.vl`, shared by the checker's post-guard narrowing, definite assignment, the emitter's `pushPostGuardNarrow` and the unreachable-code lint) · was a loud check reject, clause 2 · reported by plumb (PL-007, `~/plumb/docs/vl-issues.md`) at their pin `a8a1044322b6` · filed against master `a8a104432` · fixtures `tests/cases/unions/post-guard-exit-through-bare-block.vl`, `tests/cases/unions/error-post-guard-conditional-exit-no-narrow.vl`**

Repro:

    type IoError = { msg: string }
    function f(x: i64 | IoError): i64 | null {
      if x is IoError { { print(x.msg)
        return null } }
      x
    }
    print(f(3 as i64))
    // was: vl check rc 1, `expected i64 | null, got i64 | IoError` at the trailing `x`
    // now: prints 3

#### Mechanism

`checkIfStmtNode` decided "the then-arm always exits" by looking only at the arm block's last
statement for a `return`/`break`/`continue`; a bare `{ … }` there, an `if`/`else` whose arms both
exit, or an exhaustive `match` whose arms all exit read as falling through, so the post-guard
complement never applied. Four other copies of the question disagreed with it and with each
other: definite assignment (`daBranchDiverges`, last statement, recursing into blocks), the
lint (`stmtDiverges`, any statement), and the emitter (`blockLastStmtExits` with an `else`,
`blockAlwaysReturns || blockLastStmtExits` without). The fix is one predicate for all of them.
A statement always exits when it is `return`/`break`/`continue`; a block, when ANY of its
statements does (what follows is unreachable); an `if`, only with an `else` and both arms
exiting; a `match`, when every arm body does. A loop never exits for this purpose, since a
`break` inside it leaves only the loop. The emitter rewrites a bare block into `if true { … }`
(`drwBareBlock`) before some of its passes and after others, so that rewrite now goes through
`mkBareBlockIf` and the predicate reads `isBareBlockIf` back as the block it was; without that,
the checker narrowed and the emitter did not, and every bare-block cell was check-clean invalid
wasm (`expected i64, found (ref $type)`).

#### Ablation

A 1,080-cell grid, 15 shapes × 4 exits (`return`, `break`, `continue`, `__trap__()`) × 3
directions (`x is IoError`, `!(x is i64)`, `x == null`) × 3 positions (then exits with no else,
then exits beside an else, else exits) × annotated/un-annotated return:

| shape | before (then positions, 12 per exit) | after |
| --- | --- | --- |
| plain `return` / `break` / `continue` | runs | runs |
| `{ … exit }`, `{ { exit } }`, `{ exit } dead`, `exit dead` | check reject | runs |
| `if/else` both exit, in and out of a block; `else if` chain | check reject | runs |
| `match` every arm exits, in and out of a block | check reject | runs |
| conditional exit: `{ if c { exit } }`, `if c { exit }`, partial `match`, exit in a loop | check reject | check reject (sound) |

The else-exits position was a check reject for every shape before and after: see D1971.
`__trap__()` is not an exit anywhere: see D1972.

#### Grading list

The unreachable-code lint now shares the rule, so it also reports code after a `match` whose
every arm exits: 12 such trailing values in `compiler/` and 6 in
`tests/cases/unions/match-nullable-litunion.vl` were dead and are removed (a function may end
in an exhaustive all-returning `match`, annotated or inferred).
The grid's else-exits column (D1971) and `__trap__` rows (D1972); `while true { return }` as a
guard arm (D1973); plumb's own `x as! i32` spelling after the guard, which now runs.
A lambda guard, `const g = (x: string | null): string => { if x == null { { return "nul" } }; x }`
called as `g(null)`, used to be a check reject. It now reaches the older emit refusal
`bare null needs a struct-typed context`, which the base compiler also gives with the inner braces
removed. That refusal belongs to that construct, not to this row. A dead value after an exiting
statement under a declared return type is invalid wasm on base too (D1974).
