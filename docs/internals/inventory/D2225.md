### D2225 — an un-annotated scalar-element `[]`-or-`null` local is check-clean but the reassignment builds invalid wasm

**check-clean invalid wasm 2026-09-23 — `type mismatch: expected (ref null $type), found (ref $type)` in the module's top-level code · clause 1 · found during PR #3069's review, predicted in [D2209](D2209.md)'s grading list ("`local_assign` / `global_assign` of a scalar-element `[]` beside `null`, un-annotated") · filed against master `07d5e3b66`**

Repro:

    function truthy() { 1 == 1 }
    let x = if truthy() { [] } else { null }
    x = [1.5]
    print(x[0])
    // vl check: rc 0.
    // vl run: Error: invalid module — "the emitted module failed to validate inside the
    // module's top-level code: type mismatch: expected (ref null $type), found (ref $type)"

#### Mechanism

`x`'s un-annotated binding is an `if`/`null` join whose `[]` arm decides the element type
by default; an `i32` element (the wrong default an un-annotated `[]` still falls back to)
is silently correct here, so an `f64` reassignment is what makes the disagreement
observable. The reassignment `x = [1.5]` re-emits the join for the assignment's own
storage slot, and that second emission does not agree with the binding's own slot about
the list's rep, so `local.set`/`global.set` sees a value of the wrong ref type. The same
message fires at *function* scope too (`let x = ...` inside a function, then
`x = [1.5]`) — one mechanism at both `local_assign` and `global_assign`.
