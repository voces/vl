### D6251 — a function handed to a hole called on its own result, and used again elsewhere, is refused at check

**closed 2026-10-18 by lane L3 · runs, prints `4 1` · was loud check reject, graded CAPABILITY (the direct `wrap(true)` is legal, and each line runs alone) · clause 2 · an un-annotated callee's result is read off its own returned hole calls at this call's instances (`holeRetTyOf`), so the caller's index no longer reaches the handed function's raw hole and leaks into its other uses · pins: `tests/cases/functions/hole-fn-own-result-and-direct-call.vl` (the annotated, second-callee and twice-indexed spellings, `if` returns, a `const`-held result, a result handed to another function) · found closing [D6210](D6210.md) · filed 2026-10-18 against master `4090ad9df`**

Repro:

    function wrap(a) { return [a] }
    function lapRet(g, x) { return g(g(x)) }
    print(lapRet(wrap, 4)[0][0])
    print(wrap(true).length)
    // vl check: rc 1, argument 1: expected an array, got boolean

Want:

    4
    1

#### Mechanism

From the ablation only. Each line runs alone. Together, the two uses of `wrap` are not kept
apart: the index on `lapRet`'s result reaches `wrap`'s own parameter, and with an annotated
destination it is the other use's `boolean` that reaches `lapRet`'s result. One wrap of the
argument, `g(x)`, keeps them apart.
