#### Mechanism

`crNoteRhsRetired` (`check_narrow_flow.vl`) is handed the left operand's facts as place ids
and records each one its right operand retired as `placeText(p)`: the per-node list
`crRhsRetired` and the parallel `crRhsNames` column (with `crRhsOps`/`crRhsBys`) hold path
text. Its three readers then compare strings: `crCondRetired` (asked with
`placeText(pl)` by the arm join), `crFilterRhsRetired` (matching the `&&` left facts by text)
and `crRhsRetiredBy`. The text is one spelling per place today, so no program reads a wrong
fact, but it is a second key for a fact the place table already keys. The deletion target is
B3 of Step 6 (architecture-target-2026-10.md): once the clobber ledger and the prefix scans
over `npKeys` are on place ids, these four key on the place id the writer already has, and
`crRhsNames` and the string lists of `crRhsRetired` go.
