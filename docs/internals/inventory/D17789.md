### D17789 — an un-annotated lambda's alias read out of a list in a generic's body, called at the instance's type parameter, is refused at emit

**closed 2026-11-28 by COV-UNION · runs, its witness prints its expected value · was a loud emit reject, `cannot yet lower this statement (call of a non-declaration)` · in a generic instance sharing its body's nodes, the `pop`/`get` alias retype (`monoRetypeElemTakeAliases`) reads and records each node in that instance's frame (`nodeTyIxIn`, `nodeTyRecordIn`), so each instance's alias takes its own signature · pinned by `tests/cases/closures/hole-fn-list-alias-in-generic-at-instance-type.vl`**

Repro:

    function run<T>(y: T) {
      const f = (a) => a
      const m = [f]
      const g = m.pop()
      if g != null { print(g(y)) }
    }
    run(2)
    run("t")
    // vl check: rc 0.  vl run: emit error (call of a non-declaration) at 5:28

Want:

    2
    t

#### Mechanism

Each instance pins the list's element at its own signature (`(i32) => i32`, `(string) => string`),
but D17758's alias retype recorded on the shared nodes' column, where the first instance's record
stood for every other: the string instance's callee read `(i32) => i32` and had no closure call.
