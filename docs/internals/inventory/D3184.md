### D3184 — a `for-in` over a record's field-closure `"[]"` result of a literal-union list is refused

**loud emit reject · clause 2 · the field-closure sibling of [D3164](D3164.md) · found by the #3284 review (`rv3284-24850`, `op/field_fcKl_walk`) · the same on master `a0b9acaf8` · filed 2026-09-29 against master `995bbc74e`**

Repro:

    type K = "a" | "b"
    function mk(ks: K[]) {
      return { "[]": (i: i32): K[] => ks }
    }
    const c = mk(["b", "a"])
    for e in c[0] { print(e) }
    // vl check: rc 0.  vl build: emitProgram: unsupported for-in iterable

Want:

    b
    a

#### Mechanism

Not localised past the ablation. `c[0]` lowers as a call of the record's `"[]"` field closure,
and the for-in element ladder (`forInElemKind`) has no rung for that call's `K[]` result, so it
refuses. The element read `c[0][1]` refuses the same way (`index receiver is not an array or
string`). An `i32[]` result walks, so the gap is the ref-list result of a field-closure call.

#### Ablation

| ingredient changed | outcome | needed? |
| --- | --- | --- |
| `i32[]` in place of `K[]` | runs | **yes** (the literal-union list) |
| `const xs = c[0]`, then `for e in xs` | the same refusal | no |
| inside a function | the same refusal | no |
| `print(c[0][1])`, no loop | loud: `index receiver is not an array or string` | no |

#### Grading list

The witness, the binding twin, and the element read `c[0][1]`.
