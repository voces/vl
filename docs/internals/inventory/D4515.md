### D4515 — an element of a written `let` list holding a generic is instanced once and called at a second type

**check-clean invalid wasm · hand probe, no corpus cell · filed 2026-10-13 against `a8efc18f3`**

Repro:

    function id<T>(x: T): T { x }
    function la() {
      let v = [id]
      v = [id]
      print(v[0](2))
      print(v[0]("s"))
    }
    la()
    // vl check: rc 0.  vl run: the emitted module failed to validate inside `la`: type mismatch: expected structref, found i32

#### Mechanism

The written `let` takes the written-list path in `compiler/emit_mono.vl`
(`monoWrittenLetSeedFe` and the frame it reads), which seeds the list's element type from one
instance of `id`. The element is then called at `i32` and at `string`, but both calls go to
that single instance, so the `string` call passes a ref where the instance takes an `i32`.
The unwritten spellings do not reach this path: a `const` list is instanced per read from the
flow table, and an unwritten `let` refuses loudly.

#### Ablation

| ingredient removed | outcome | needed? |
| --- | --- | --- |
| the write `v = [id]` | loud emit reject (reaches no call) | **yes** |
| `let` made `const` (no write) | runs, prints `2` and `s` | **yes** |
| the second call at `string` (both at `i32`) | runs, prints `2` and `3` | **yes** |
| the element read through `const a = v[0]` first | still invalid wasm | no |
| the enclosing function (module scope) | loud emit reject (reaches no call) | **yes** |

#### Grading list

- The aliased spelling: `const a = v[0]`, then `a(2)` and `a("s")`.
- The module-scope spelling, which refuses loudly today and must not turn silent.
