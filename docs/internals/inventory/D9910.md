### D9910 — a `<T>` body returning `x ?? 1.5` at a never-null `i32` pin returns an `i32` where its caller reads the `f64` the call is typed at

**check-clean invalid wasm · clause 1 · `vl check` rc 0 · the un-annotated `function f(x)` prints `2.5` since [D9870](D9870.md)'s close, and the `f64` pin prints `2.5` · found closing [D9870](D9870.md) · present on master `8700f0727` · filed 2026-10-22 against master `8700f0727`**

Repro:

    function f<T>(x: T) { return x ?? 1.5 }
    const z: i32 = 5
    print(f(z) / 2)
    // vl run: the emitted module failed to validate inside the module's top-level code: type mismatch: expected f64, found i32

Want:

    2.5

#### Mechanism

Not traced. The checker types the call `f64`, as it does the hole face's ([D2951](D2951.md) keeps
the join at its pin). The instance folds the dead default and returns the bare `i32`. The hole
face's instance takes its result annotation from the holes' binding (`monoHoleRetNumPin`,
emit_mono.vl), but a `<T>` template's result is unresolved and has nothing to substitute.

#### Ablation

| ingredient changed | outcome | needed? |
| --- | --- | --- |
| `function f(x)`, no type parameter | runs, prints `2.5` | **yes** |
| the pin `f64` | runs, prints `2.5` | **yes**, a narrower pin |
| the default `2` for `1.5` | runs, prints `2` | **yes**, a wider default |
| `const r = f(z)` / `print(r)` for the division | same failure | no |

#### Grading list

The binding, argument and list positions at an `i32` pin, and an `i64` pin with an `f64`
default (refused by the checker today, which must stay refused or run).
