### D1753 — a nullable READ delivered to an un-annotated parameter gets the bare-null refusal, though its type is `T | null`; a nullable local and a nullable-returning call in the same position run

**loud emit reject · 3 cells of the discovery pass's un-annotated-parameter group · filed
2026-09-06 against master `40334c8cf` · found by the 2026-09-06 discovery pass, by splitting a
16-cell MESSAGE group into the design rule and this**

Repro:

    const m: {[string]: i32} = Map()
    m["k"] = 5
    function take(a) {
      if a != null { print(a) } else { print(0) }
    }
    take(m.get("k"))
    // vl check: rc 0.  vl run: emit error,
    // emitProgram: bare null needs a struct-typed context

#### Mechanism

An un-annotated parameter is a hole the call pins from the argument. `m.get(k)` and `b?.y` are
nullable READS whose type is `T | null`, but the pin does not carry that type, so the argument
lowers as a bare `null` with nothing pinning it and takes the gate meant for a literal `null`.
The message therefore describes a value the program does not contain.

The scope is narrower than the message and narrower than the message group: a nullable LOCAL
and a nullable-returning CALL both pin the same hole and run. What separates them is that the
two failing spellings get their nullability from an inline niche at the read rather than from a
declared `T | null`.

Sixteen cells share this message at the un-annotated parameter. Ten of them pass a value whose
type really is `null` — a literal `null`, a null hole binding, a null-only inferred return —
and those are the language's answer, which several templates' own headers already state. Three
are this row. The remainder are the two rows beside it.

#### Ablation

| ingredient removed | outcome | needed? |
| --- | --- | --- |
| the un-annotated parameter (`take(a: i32 \| null)`) | runs, prints `5` | **yes** |
| the map read, for a nullable LOCAL (`const x: A \| null = …`) | runs, prints `8` | **yes** |
| the map read, for a nullable-returning CALL | runs, prints `8` | **yes** |
| the map read, for a `?.` read (`take(b?.y)`) | still refuses | no — the same row |
| the map read, for a literal `null` | still refuses | no — that one is the design rule |

`map-get-method-bare/argument`, `map-get-method-bare/early_return_guard` and

which are the design rule; the check is that `take(null)` into an un-annotated parameter still
