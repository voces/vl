### D15034 — a capturing lambda written to a slot of a generic's value, in a generic body whose type parameter shares the generic's name, is check-clean invalid wasm

**closed · runs, prints `1`, `4`, `1`, `s`, `4`, `s` · was check-clean invalid wasm, clause 1, `the emitted module failed to validate inside __lambda_2` · found closing D15032 · filed 2026-11-02 · fixture `tests/cases/generics/capturing-lambda-in-generic-value-slot-at-shared-type-parameter-name.vl`**

#### Mechanism

Located and closed. The lambda's result is a derived hole (`_`) whose base is `id`'s `T`. The
lambda's instance inside `w("s")` closed that result through `elabSubstClosed`, and
`substHoleTyReal` bound the derived hole's base through `bindOf` by name, past `substTyDeep`'s
ownership skip (D12212). The base lookup now applies the same skip, and a lambda instance substitutes
as its enclosing generic's (`elabOwnerOf`). Renaming a generic's own type parameters apart at every
value read was tried first, as the class-wide fix: it broke 36 grid cells at emit (`ref valtype with
no interned shape`, `object literal field count does not match struct`), because mono matches a
generic value's rows against the generic's own instances, so it was dropped.

Before the close:  The per-instance clone of the lambda for `w("s")` keeps its parameter at `i32` but
returns `string`: its result, `id`'s open `T` read through `x + x`, is bound to `w`'s
`T = string` by name somewhere after the clone is minted (the clone itself carries no return
annotation and the type `(T) => _`). Making the lambda instance's owner its enclosing generic
(`monoTemplateOwner`) did not move it.
