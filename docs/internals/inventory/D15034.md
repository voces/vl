### D15034 — a capturing lambda written to a slot of a generic's value, in a generic body whose type parameter shares the generic's name, is check-clean invalid wasm

**check-clean invalid wasm · clause 1 · `vl check` rc 0, `vl run`: `the emitted module failed to validate inside __lambda_2: type mismatch: expected (ref $4), found i32` · found closing D15032 · filed 2026-11-02 against master `9f37a9df1`**

Repro:

    function id<T>(x: T): T { x }
    const fs = [id]
    function w<T>(t: T) {
      fs[0] = (x) => {
        print(t)
        return x + x
      }
      print(fs[0](2))
      print(t)
    }
    w(1)
    w("s")

Want:

    1
    4
    1
    s
    4
    s

#### Mechanism

Not located. The per-instance clone of the lambda for `w("s")` keeps its parameter at `i32` but
returns `string`: its result, `id`'s open `T` read through `x + x`, is bound to `w`'s
`T = string` by name somewhere after the clone is minted (the clone itself carries no return
annotation and the type `(T) => _`). Making the lambda instance's owner its enclosing generic
(`monoTemplateOwner`) did not move it.
