### D2714 — a union of two same-struct maps inside a container, delivered as a container of one of them, is not unboxed

**closed by design · now a loud check reject · was check-clean invalid wasm · the owner's record-covariance ruling refuses it: an annotated record is not fresh, and a union of two maps is stored apart from one of them · closed 2026-09-30**

Repro:

    type A = {[string]: string}
    type B = {[string]: string | null}
    const a: A = Map()
    a["k"] = "x"
    const h: { f: A | B } = { f: a }
    const g: { f: B } = h
    print(g.f.length)
    // vl check: rc 0.  vl run: invalid module, "type mismatch: expected (ref null $type), found (ref $type)"

#### Mechanism

The checker accepts the delivery because each member of `A | B` shares `B`'s storage (D2692),
but the field holds the union's box and the destination field holds the bare map. D2692's close
unboxes at the node that is delivered (`recordMapUnbox`), walking list and record LITERALS to
their parts; a container that is already built has no per-element node to unbox at, so it would
need a converting copy, or the checker has to refuse it as a container whose elements store
differently. The same holds for `(A | B)[]` into `readonly B[]`, and for `A | B | null` into
`B | null`, where the destination is a nullable map rather than a box.

#### Ablation

| ingredient removed | outcome | needed? |
| --- | --- | --- |
| the container (`const g: B = h.f`) | runs (D2692) | **yes** |
| the literal (`const g: { f: B } = { f: h.f }`) | runs | **yes** |

#### Grading list

`(A | B)[]` into `readonly B[]`; `A | B | null` into `B | null` at a binding.

#### Close (2026-09-30)

Closed by the owner's record-covariance ruling (DECISIONS.md "Record covariance: only a fresh value widens"): an annotated record is not fresh, and a union of two maps is stored apart from one of them. The refusal names both fixes, building the source at the wider record or copying it with an object literal, so no program the design permits is refused.
