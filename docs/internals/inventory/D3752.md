#### Mechanism

The record escapes into `kept`, so it is a box for as long as `kept` holds boxes. The flat
step (`flat.rs`, S2) would hold `kept`'s fields side by side, but its cost rule refuses any
whole-element read that is not a field read, a field-only argument or a local the multi-value
step scalarizes. `return kept[i]` is none of these: it reaches the function's exit. Once the
multi-value step gives `groundKept` a result twin whose callers all read fields, that exit is a
field use too (the twin reads the returned value's fields at the exit). The two steps decide in
the wrong order for this: flat runs first and cannot see the twin. A fix is the D3736 shape, an
`AUse::Exit` the flat step counts as free, then checks against the multi-value step's own
answer (the function got a result twin and no call site keeps the struct). In sunpa that is
not yet enough: `groundAt` → `groundBelow` → `legsLayer` stores a `footing` result, so the
original `groundKept` stays live and would re-box every hit.

(10.8 a frame), the same on master and this lane.

#### Analysis (lane RA, master `e2443d6b2`)

Removing the miss's box needs `kept` flattened, so the miss stores its fields, and the hit's
`return kept[i]` served as fields. In sunpa that takes three changes, each in a different
step, and each useless alone:

1. **The flat step** must count `return kept[i]` as free (the D3736 shape: an `AUse::Exit`,
   checked against the multi-value step's facts), and count `kept.push(g)` / `kept[next] = g`
   of a scalarized local as stores taken apart at the producer.
2. **The multi-value step** must hold a local returned at the exit as fields in a result
   twin. Today a field-only local's every get must be a field use in every context, and an
   exit is one only in the result twin. `groundAt`'s `const g = groundKept(x, y)` returned
   through `if raise == 0.0 { g } else { … }` (a merge, D3766, whose consumer is the exit)
   and `groundBelow`'s `const g = groundAt(x, y)` returned at two exits are both this. A
   local's plain-context exit would have to re-box from its slots, which costs at most what
   the producer's box cost, since the local is set before the exit.
3. **The callers must hold the result as fields**: `legsLayer` holds `groundBelow`'s result
   in `body`, which reaches `const gr = if st.feet[i].down { footing(…) } else { body }`
   (a merge of a local, D3766) and other uses that keep it.

Without (2) and (3), (1) moves the allocation from the miss to every hit in the original
`groundKept`, which the keeping chain still calls. The table exists because a foot asks the
same point several times a frame, so hits should outnumber misses and (1) alone would be a
loss (the hit count was not measured).
`groundKept` stays at 116,065 `struct.new` (10.6 a frame) under `feet-test` on this lane.
