### D3880 — a call through a module-scope alias of a hole lambda, beside a local `const` that rebinds the lambda's name, is refused

**closed 2026-10-09 by lane SC · runs · was a loud emit reject · the local-binding neighbour of D3861 · filed 2026-10-08 against master `a1c9be3c4` with D3861's fix · pins: `tests/cases/closures/module-alias-call-beside-local-shadow.vl`**

Repro:

    const c = (y) => y + "C"
    const d = c
    function k(s: string) {
      const c = 1
      d(s)
    }
    print(k("z"))
    // vl check: rc 0 (unused-variable warning).  vl build: emitProgram: a function-value call
    // has no interned signature — parameter 1 of type `` has no representation in the
    // function-value ABI

Want:

    zC

#### Mechanism

The monomorphizer pins `c` through the chain and keeps the call through `d` (D3861) whether
the rebinding is a parameter or a local. The emitter's key for the call follows `d`'s copy
source to the module frame (`calleeCloSigKeyAt` with frame -1). There `identBoundAt` asks the
lowering's live scope stack, which belongs to `k` and holds its local `c`, so the module's `c`
read as bound and resolved to nothing. A parameter is not on that stack, which is why it ran.
Closed by resolving a module-scope copy chain read from inside a function through the module's
own bindings (`moduleCopySigKey`), at both of the ladder's copy rungs.
