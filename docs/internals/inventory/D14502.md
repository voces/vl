### D14502 — a `Map()` keyed by a literal union is built string-keyed, while the rep of its checked `{[K]: V}` type is i32-hashed

**runs today and must keep running · 2 fixtures (`maps/litunion-atom-map-key`, `maps/litunion-map-key-every-consumer`) · filed 2026-10-26 against master `e139633e3`**

Repro:

    type K = "red" | "green"
    const src: K[] = ["green", "red"]
    function writes(a) {
      const m = Map()
      m[a] = 1
      print(m["green"] ?? 0)
    }
    function setsIt(a) {
      const m = Map()
      m.set(a, 1)
      print(m["green"] ?? 0)
    }
    writes(src[0])
    setsIt(src[0])

Want:

    1
    1

#### Mechanism

The checker types `m` as `{[K]: i32}`, and `tyLitUnionHashesI32` gives that type's rep an
i32-hashed key. The `Map()` constructor and the string-literal reads build and read the map
string-keyed, widening the atom to its member text at the key boundary (D1724). So the binding's
cell cannot be read off its checked type: `letBindRepClaims` declines through `letMapCtorAtomKey`
and `letLocalSlot`'s `letIsMap` rung reads the shape off the constructor. Deleting that decline
reds the fixture with `i32-keyed map indexed with a string key`.

The fact missing from the checked type is the key rep the constructor commits to. The decline
can go once a literal-union key has one rep at the type and at the constructor.

#### Grading list
