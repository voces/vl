### D3893 — a nested generic called through a lambda parameter's hole with a value of the enclosing `T` is not checked at the enclosing pin

**check-clean silently wrong · found in review of #3468 (`rv3468c-witnesses/a03u.vl`) · filed 2026-10-09 against master `c6ac0a1d2`**

Repro:

    function a<T>(x: T) {
      function b<U>(y: U) { const n: i32 = y; print(n + 1) }
      const g = (q) => b(q)
      g(x)
    }
    a(true)
    // vl check: rc 0.  vl run: prints 2

Want:

    vl check: cannot assign boolean to 'n' of type i32

#### Mechanism

Not located. `b(q)` binds `U` to the lambda parameter's hole, and that constraint is re-recorded
with the hole. `g(x)` then pins the hole to `a`'s `T` inside `a`'s body, but nothing carries that
pin into the re-recorded constraint before `a(true)` validates it. The same on master and after
D3853.
