### D15320 — two returned records of members of different signatures in one program refuse at emit

**closed 2026-11-04 by this PR (lane bundle) — the repro now RUNS and prints the Want below: a bundle record's row is its own, else the row it shares. Was: loud emit reject · clause 2 (`emitProgram: ref valtype with no interned shape`) · found grading D15149 · filed 2026-11-04 against master `f5014ce43`**

Repro:

    function lap(f) {
      const _a = f(2.5)
      const _b = f(3)
      return f
    }
    function lap2(f) {
      const _a = f(true)
      const _b = f(3)
      return f
    }
    const k = lap((a) => a + 1)
    print("\{k(4)} \{k(1.5)}")
    const j = lap2((a) => a)
    print("\{j(4)} \{j(true)}")

Want:

    5 2.5
    4 true

#### Mechanism

Measured by probing mono's record pin. A struct row's identity keys every function type as the
closure cell it is stored as (`repRowId`), so `lap2`'s record of `(boolean)` and `(i32)` closures
shares `lap`'s row of `(f64)` and `(i32)` ones, and no row records its own type. Mono found that
row through `repRowOfTyStruct`, but the emit side looked a bundle record's row up by its own type
alone (`structRowRecordingTy`), got -1 for the second record, and declared its holder's cell with
no row. Records of different arity never share a row, which is why a third signature ran. The
lookup now falls back to the shared row on both sides.

#### Ablation

| spelling | outcome |
| --- | --- |
| `j` removed | runs, prints `5 2.5` |
| `k` removed | runs, prints `4 true` |
| both held in record fields (`{ f: lap(...) }`, `{ f: lap2(...) }`) | refuses at emit, `a call through a held record matches none of its signatures` |
| both held in list elements | the same refusal at the second |
| `lap2` calling `f` at a third signature, `f("s")` | runs |
| `j` built by a maker, `function mk() { lap2(...) }` | refuses at emit, `a function returning a record of members has no row for the record after monomorphization` |
