#### Mechanism

depth-16 `--names` profile puts the cost under `collectA` → `collectAArrayLit` on the nested
literal, in `arrLitIsRef`, `arrLitNestedElemName` and `rlElemStoredName`, each spelling the
element with `tyToStrObj`, `7·2^depth` characters. Neither the record in the literal nor the
call is needed: `g([])` still doubles.

#### Grading list

The witness prints `1` at every depth, and the row closes when the depth-12 to depth-16 fuel
ratio stops being a power of two per level. Re-grade `g([])` and the `const` face.

**Left open by the lane that closed D9512-D9515, 2026-10-22.** The cost is not a signature
token a rung can answer from the type. `collectAArrayLit` on the nested literal spells the
element for the ref-list tables, `rlInternNameTy`, `rlElemStoredName` and
`rlCanonLitUnionAtoms`, and for `arrLitIsRef`, `arrLitNestedElemName`, `ensureRefElemTy` and
`refArrElemName`: those tables are keyed on the element's render, so a close needs them keyed
on the arena type. The fuel is unchanged by that lane (137.8M, 1.52e9 and 22.8e9 at depths 8,
12 and 16; `g([])` 82.3M, 727M and 11.0e9). [D9580](D9580.md), a lambda whose body lists the
record, is spelled by the same literal walk.

**Left open by the lane that closed D9511, 2026-10-22.** The map-value tables now find a deep
declared record's slot from its arena type, but the ref-list table cannot follow without a
wider change: it stores the element's render as `rlElemName`, read by about seventy sites
including the relocation keys and the section writers. The cost sites are unchanged:
`collectAArrayLit` → `arrLitIsRef` → `arrLitNestedElemName` → `nameIsRefArray`,
`refArrShapeKind` and `refArrElemName`; `ensureRefElemTy` → `rlInternNameTy` →

`sigKeyOfTy`, whose `sigDeclRecListTokOfTy` answers a declared-record element but not a list
of them. The fuel is unchanged (137.8M at depth 8, 1.52e9 at 12). With D9511 closed,
`tests/vl_compile_gc_test.ts` takes this row's witness at depth 23, which traps under the null
collector; when this row closes, the test needs a witness that still traps.

#### Close

The ref-list tables stay keyed on spellings; the close makes the spelling cheap where a nominal
one is provably the same row. A list literal whose element is a declared record nested past
depth 8, or a list of such lists, is spelled `deepDeclRecName`'s `A12[]`, and one whose element
is a function type over such a record `fnElemNominalName`'s, unless its signature holds a
literal, which the render softens to its base and the name keeps (`fnSigNamesLit`): the names the annotation side
interns, so the literal reaches the same row without the `7·2^depth`-character render. The
record must own its struct row alone, with no row or variant arm its render could also match
(`sigRowHasNoTwin`, `sigRowHasNoArmTwin`). A parameter or result of the nested list then asks
`sigDeepNestListSlotOfTy`, which answers the empty token without the render when
`rlNestRowsNamed` finds every row that may be the element stored under the nominal name: the
render equals no row's name, so it has no slot either.

A validating seed took both answers at every depth, the old render's and the new rung's, and
trapped on any disagreement: a literal's struct index where the render's own resolver answers
(up to 4,096 characters), its ref-list kind and element kind, for a function the mutual
assignability of both spellings, and a signature token the render would have given. Its first
run trapped on eight corpus files: seven a function element with a literal-union parameter,
which is why `fnSigNamesLit` declines, and this row's fixture, whose depth-10 render is past
that resolver's cap and placed at the wrong row by the validator alone. With the guard, the seed built the 11,241 buildable corpus
files of 16,276 with no disagreement. A control seed trapping wherever the new rungs fire
trapped on 516 of them and on the witnesses of this row and [D9770](D9770.md). The final seed
builds every corpus file to the same module as master's base seed except this row's fixture,
whose module the rung changes, and holds its fixpoint at 6,332,116 bytes, +4,193 on the base.
