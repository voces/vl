### D9172 — a list of un-annotated functions with different results, called inside a `.map` callback, is refused at emit and not at check

**loud emit reject · `vl check` rc 0 · `emitProgram: call to unknown function` · clause 2 · found closing [D9093](D9093.md) · filed 2026-10-21 against master `c2df9510f`**

Repro:

    function inc0(a) { return a + 1 }
    function half(a) { return a / 2.0 }
    const xs = [inc0]
    xs[0] = half
    print(xs.map((f) => f(3))[0])
    // vl check rc 0.  vl run: emit error: emitProgram: call to unknown function

#### Mechanism

Not traced. D9060's judge refuses a write whose function returns another type when the
element is called directly; the call inside a `.map` / `.filter` callback is not one it
reads, so the program reaches emit, where D9093's agreement check declines the pin.

#### Ablation

| ingredient removed | outcome | needed? |
| --- | --- | --- |
| the `.map` (`print(xs[0](3))`) | check refuses | **yes** |
| `half` (`dbl(a) { return a * 2 }` in its place) | runs, `6` | **yes** |

#### Grading list

The literal `[inc0, half]`, a re-pointed `let xs = [inc0]; xs = [half]` (both `call to
unknown function`), a write through a parameter `put(ys) { ys[0] = half }` (refused by the
emit message `the function written to this element returns another type`), and records
`[{ f: inc0 }, { f: half }]` read by `rs.map((r) => r.f(3))` (`cannot take the generic
function inc0 as a value`). Each is the checker's to refuse.
