### D4983 — a `.map` over a type-parameter list delivered straight into a concrete list parameter is invalid wasm

**closed 2026-10-15 · runs · was check-clean invalid wasm, clause 1 · pin: `tests/cases/generics/type-parameter-list-copy-into-concrete-param.vl` · related to [D2214](D2214.md) (a `.map` result delivered straight into a `readonly` list) · filed 2026-10-15 against master `d9468f145`**

Repro:

    function sumF(xs: f64[]) { print(xs.length) }
    function t<V>(q: V[]) {
      sumF(q.map((x) => x))
    }
    t([1])
    // vl check: rc 0.  vl run: invalid module, type mismatch inside `t`

Want:

    1

#### Mechanism

A `V[]` delivered to `f64[]` is gradual to the checker, and at the `V = i32` instance a
direct `sumF(q)` converts each element (`emitScalarListWidenSiteElem`). The converting copy
is declined when the source has no root it can check for other holders, and a call result
has none, so a `.map` result went to the parameter unconverted. `.filter` and `.slice` did
the same.

#### Ablation

| change | outcome | needed? |
| --- | --- | --- |
| `t([1.5])` for `t([1])` | prints `1` | **yes** |
| `const w = q.map((x) => x)` then `sumF(w)` | prints `1` | **yes** |
| `sumF(q)` | prints `1` | **yes** |

#### Close

A `.map`, `.filter` or `.slice` result is a list nothing else holds, so the widen site
converts it as it converts a rooted list (wasmEmit.vl). The pin also grades the same call in a
closure and inside an `is f64[]` arm over an empty `const p: V[] = []`. A non-fresh call
result, such as a generic identity call, is still unconverted: [D5002](D5002.md).
