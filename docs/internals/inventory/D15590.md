### D15590 — a hole parameter's copy read by a function nested two levels in its owner, handed through a set at two instances, refuses at emit

**closed 2026-11-09 · runs, prints `3`, `4`, `2`, `3.75` · was loud emit reject, clause 2, `vl check` rc 0, then `emitProgram: a generic function taken as a value reaches no call that fixes its type` · closed in emit_elab.vl: `elabAliasSetFwd` looked for the nested function's instance whose parent is the owner's; two levels deep its parent is the middle function's, so `elabInstWithin` follows the parent chain. A copy of the copy made in a nested function is followed as one made in the owner · fixture `closures/hole-param-copy-read-two-nested-levels-deep.vl` · found closing D14843 · filed 2026-11-09 against master `f75d1327`**

Repro:

    function add(a, b) { return a + b }
    function mul(a, b) { return a * b }
    function apply2(g) {
      print(g(1, 2))
      print(g(1.5, 2.5))
    }
    function run(h) {
      let hh = h
      function mid() {
        function inner() {
          for f in [apply2] { f(hh) }
        }
        inner()
      }
      mid()
    }
    run(add)
    run(mul)

Want:

    3
    4
    2
    3.75

#### Mechanism

`inner` reads `run`'s copy `hh`, so it is built per instance of `run` (`elabReadsEnclParam`,
through `mid`). The copy's read forwards the set as at that instance only when
`elabAliasSetFwd` finds `inner`'s instance under `run`'s. It asked for the instance whose
parent IS `run`'s, and `inner`'s parent is `mid`'s, so it found none and refused.
