### D15393 — a value if choosing between two maps of un-annotated functions of a set and a smaller set is refused at emit

**closed 2026-11-12, runs and prints `4` then `1.5` · a value join and a function's returns of maps of a set and a smaller set join as a map of the joined set (`elabFnJoinMapTy` in `joinArmTys` and `joinRetTys`), and the tag pass decides the smaller set with it (`ftJoinMapTailsNote`, `ftRetMapSubsNote`, check_fn_tag.vl) · was a loud emit reject, clause 2, `emitProgram: unsupported map value type` · the list literal of the same two maps runs since D15352 · found closing D15352 · filed 2026-11-04 against master `0b489162`**

Repro:

    function inc0(a) { return a + 1 }
    function half(a) { return a / 2.0 }
    const fnMap = Map()
    fnMap.set("a", inc0)
    fnMap.set("b", half)
    const m2 = Map()
    m2.set("a", half)
    function pick(c: boolean) { return if c { m2 } else { fnMap } }
    const g = pick(false).get("a")
    if g != null { print(g(3)) }
    const h = pick(true).get("a")
    if h != null { print(h(3)) }

Want:

    1.5

#### Mechanism

The arm join (`joinArmTys` → `elabFnJoinDeepTy`) keeps the first map's value set: `elabFnJoinDeepAt` has no map arm. Giving it one (the map's value joined as a list's element is) is check-clean invalid wasm on this program and on `const m = if k { m2 } else { fnMap }`: the joined map is a fresh type whose untagged closure values mint a second map storage. So D15352 joins maps only in a list literal (`elabFnJoinMapTy`).
