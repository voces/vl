### D1904 — the missing-return diagnostic names a lambda `''`, because the message interpolates `fnName` with no fallback

**closed — now a loud check reject whose sentence names the lambda by the binding it is assigned to, else by the line it starts on (`fnWhoOf`, check_decl_scan); a named function's sentence is unchanged · the sentence used to name the function `''` · filed 2026-09-07 against master `fbe0b0f01`, closed 2026-11-13**

Repro:

    const c = true
    const f = (): i32 => { if c { 5 } }
    print(f())
    // vl check: [ERROR]: not all code paths return a value in the lambda bound to `f` — add a `return`, …

#### Mechanism

`typecheck.vl`'s totality error builds its sentence as `"… in '" + n.fnName + "'"`. A lambda is
a `FuncDecl` with an empty `fnName`, so the quotes close on nothing and the reader is told which
rule fired but not where. Pre-dates D1902 — an else-less `if` in a lambda already read this way
— and D1902 only made it easier to reach, since a lambda whose body ends in a bare block now
takes the same message. The span is correct; only the name is missing, so the fix is a fallback
noun (the binding the lambda is assigned to, else `a lambda`) rather than a new diagnostic.

#### Ablation

| ingredient removed | outcome | needed? |
| --- | --- | --- |
| the lambda (a named `function` instead) | names `'f'` correctly | **yes** |
| the else-less `if` (a bare block tail) | still `''` | no |
| the return annotation | different error (`void`) | n/a |

#### Grading list

Every diagnostic that interpolates `fnName` — the totality error is one of several, and a
fallback belongs wherever a lambda can reach the sentence, not just here.

Graded on master `1323b99e`. Of the compiler's sentences that interpolate `fnName`, six check-side
ones read it with no `!= ""` guard. Only the totality rule reaches a lambda:

- the two inferred-return refusals (check_inferred_return) are gated on `n.fnName != ""`;
- the two type-parameter sentences (check_assignable `argCstrFixedErr`, check_fn_decl's default
  naming a type parameter) need a generic function, and a lambda takes no type parameters;
- `reassignedFnValueErr` (check_calls) is handed an identifier.

The `emit_mono` sentences never read an empty name, because the emitter names every lambda
`__lambda_N` before monomorphizing.
