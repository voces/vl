### D14815 — a call in a list literal handed to a call that writes its type argument, where another delivery builds the call's record wider, is invalid wasm

**closed · now a loud check reject, `{r: null} is not Circle: they store field r differently`, as the direct twin `first<K>(mkcall())` is · was check-clean invalid wasm, clause 1 · split from [D14814](D14814.md) · filed and closed 2026-11-01 against master `aee22686`: a call writing its type arguments decides its instance, so D14733's list arm (`recListArgTakesRep`) no longer serves the delivery at the build unless the written instance stores the elements as the build does (`recRepArgOf`, check_fit_rules.vl) · fixture `soundness/error-explicit-type-argument-list-of-call-built-elsewhere.vl` · the program is design-legal, and a build per landing that makes it run is [D14760](D14760.md)'s**

Repro:

    type Circle = { r: i32 | null }
    type K = { r: null }
    function sink(_x: Circle) { }
    function mkcall() { { r: null } }
    sink(mkcall())
    function first<T>(xs: T[]): T { xs[0] }
    print(first<K>([mkcall()]).r ?? 1)

#### Mechanism

`sink(mkcall())` builds `mkcall`'s record at `Circle`. `first<K>` is instanced at `K`, as its call
writes, and the list literal is delivered at `K[]`. D14733's list arm counted that delivery as
served at the build, as it is for `first([mkcall()])`, whose instance the rep decides. The `K`
landing was skipped, so `mkcall` was built at `Circle` and handed to `first@K`. Counted, the two
landings disagree and the delivery to `sink` is refused, as the direct twin's is.
