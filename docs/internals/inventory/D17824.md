### D17824 — a `let` bound to a call of a lifted lambda mono splits per width has no storage width, since that width is first known at mono and elab cannot see it

#### Mechanism

The `const` face (D17808) reads each call's width from its sig key, which mono's per-width clone
of the lambda carries (`cloCallSigKey`). A `let`'s width is the join of its init's width and
every write's width, and nothing decides it. The coordinator ruled that elab should decide it
once (`elabLetStorageWidth`). Elab cannot do that: `elabRun` runs before mono, so it never sees
the clone. Its own type for the call stays open in the instance frame (`elabNodeTyAt` gives a
TyVar), because the lambda's two calls disagree on `x` and elab does not split it per call.

Candidate fix (b): decide the one width where the key is first known, in `letOpenCallWidth`,
extended to `let` as the join over the init and the writes. That reader needs the writes
without a new checker import in `emit_classify` (the phase-state rule). It needs a ruling when
someone picks it up.
