### D16011 — a generic parameter's union bound to a literal-union alias has no row by its type key, though the registry holds one by spelling

**runs today and must keep running · 1 program: `generics/generic-union-param-litunion-alias-arm.vl` (D5310) · filed 2026-11-13 against master `0bc200dd5`**

Repro:

    type K = "x" | "y"
    const k: K = "x"
    function nul<T>(p: T | i32 | null, q: T | i32 | null) { p == q }
    print(nul(k, k))
    print(nul(k, null))

Want:

    true
    false

#### Mechanism

Boxing into `nul<K>`'s parameter asks `unionArmTagClash` for the union's members. Its type is the
nullable `K | i32 | null`, so the members come from the row its type key reaches,
`unRowOfTyKey(unionTy)`. That key reaches no row, although the registry holds the union under its
spelling. The type-keyed path then reads no members and answers "no clash". The spelling's row
gives the same verdict only because `K` boxes under the string tag and `i32` under its own, so no
two members claim one tag. An empty member list from `unRowOfTyKey` is not evidence of "no
members".

#### Grading list

- Every reader of `unRowOfTyKey` at a generic parameter's union bound to a literal-union alias,
  with and without `null`.
- The same union with two members that do claim one tag, to see whether a clash is missed.
