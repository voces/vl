**now a loud check reject (`__array_new_default__ fills every slot with the element's default value, and string has none`), the refusal the design owes · was check-clean invalid wasm, clause 1 · census row 11 of the no-default ruling (DECISIONS.md §"No default type") · one producer, `pinOpenReadFromDest` (`check_narrow_flow.vl`): a read of an open list element delivered whole to a closed destination type (an annotated `let`, a typed assignment target) pins the element to that type, so no unbound default settles it and a later use that disagrees is refused at check · fixture `tests/cases/intrinsics/error-array-new-default-element-fixed-string-by-a-read.vl`, beside `error-empty-list-element-fixed-two-ways.vl` and `error-empty-list-element-read-then-pushed-another-type.vl` for the contradictory uses · filed 2026-11-18 against master `ab08356f1` by lane F1**

#### Mechanism

`arrDefHoleToI32` (`check_narrow_flow.vl`) settles an element nothing pinned at the unbound default
`i32` after the read into a `string` was checked against the open hole. Under the ruling the typed
read fixes the element as `string`, which has no zero, so the program owes the existing refusal
(`tests/cases/intrinsics/error-array-new-default-no-zero.vl`), not a run. An element read by nothing that
types it (`print(a[0])`) is the integer literal `0` and keeps `i32` (coordinator, 2026-11-18): the
literal default, not a storage default.
