### D16984 — an `__array_new_default__` list's element takes the unbound default after a typed read was already checked

**check-clean invalid wasm · clause 1 · census row 11 of the no-default ruling (DECISIONS.md §"No default type") · filed 2026-11-18 against master `8c0843c69` by lane F1**

Repro:

    const a = __array_new_default__(2)
    const s: string = a[0]
    print(s)
    // vl check: rc 0.  vl run: invalid module, expected string, found i32

#### Mechanism

`arrDefHoleToI32` (`check_narrow_flow.vl`) settles an element nothing pinned at the unbound default
`i32` after the read into a `string` was checked against the open hole. Under the ruling the typed
read fixes the element as `string`, which has no zero, so the program owes the existing refusal
(`tests/cases/intrinsics/error-array-new-default-no-zero.vl`), not a run. An element read by nothing that
types it (`print(a[0])`) is the integer literal `0` and keeps `i32` (coordinator, 2026-11-18): the
literal default, not a storage default.

#### Ablation

| ingredient changed | outcome | needed? |
| --- | --- | --- |
| the read typed `f64` | runs, prints `0` | **yes** (a type with a zero) |
| `print(a[0])`, untyped | runs, prints `0` | **yes** (the typed destination) |
