### D7964 — an un-annotated `??` of two nullable atoms reads the `-1` niche as a member

**closed 2026-10-20 by lane L6b · runs, prints `null` · was check-clean silently wrong, printed `b` · clause 1 · in the hole instance the `??` result's member texts were found only through an atom map read, so the print took the non-null atom path and `-1` selected the last member; `nulLitAtomTexts` now keeps the niche for a `??` whose nullable default holds the same member set in the same order, and `coalesceDefaultNullable` asks the hole's pinned type · pin: `tests/cases/literal-unions/coalesce-map-read-joins-atom.vl` · filed 2026-10-20 against master `aec7a5332`**

Repro:

    type AB = "a" | "b"
    function use(x, y) { print(x ?? y) }
    const n: AB | null = null
    use(n, n)
    // PRINTS b

Want:

    null

#### Mechanism

Both operands are `AB | null` niches, so the result is the same niche with `-1` for null.
`nulLitAtomTextsAt` resolved a `??` only through `coalMapReadNulAtomTexts`, whose leftmost
operand must be an atom map read; for a hole parameter it returned nothing and the print
fell through to `litAtomWidenTexts`, which treats the value as a member. With three
members the same program prints `c`.
