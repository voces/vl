### D3316 — a write after an `if` that retired a path narrowing did not narrow the path again

**closed 2026-09-29 (the path null strip applies whenever no live overlay covers the place, a join installs over a retired innermost entry even when it equals the storage type, and an assignment's target is written, not read, so a retired narrowing does not refuse it) · runs lost in #3304 round 3, never on master · fixture `tests/cases/unions/flow-join-write-after-retire.vl`, hazards `write_after_join_*`**

Repro:

    type Box = { v: i32 | null }
    function f(a: Box, b: Box, c: boolean): i32 {
      a.v = 1
      b.v = 2
      if c { a.v = null } else { b.v = null }
      a.v = 7
      return a.v + 1

#### Mechanism

Master's join installed an overlay even when it equalled the storage type, and the reads and
writes below resolved through it. #3304 skipped that install and, with the then arm's retirement
left innermost, `a.v = 7` neither re-narrowed (the null strip asked for no narrowing at all) nor
was allowed: the write marked for `b.v` as an alias counts as a call, so the read of the target
was refused. Now the strip asks for no LIVE narrowing, a join installs over a retired
innermost entry, and a write target is not checked as a read of the retired narrowing.
