### D16977 — an un-annotated parameter indexed with an `i32` refuses an `i32`-keyed map argument as ambiguous

**loud check reject · clause 2 · found by the capability-matrix rot sweep (`tail-write-map-element`, `-entry`, `-field`, `argument` un-annotated) · filed 2026-11-18 against master `bb90aa849` by lane F1**

Repro:

    function first(c) { return c[1] ?? 0 }
    const m: {[i32]: i32} = Map()
    m[1] = 5
    print(first(m))

Want:

    5

#### Mechanism

The parameter's `c[1]` demands an `i32` index, which an array and an `i32`-keyed map both take,
and `holeArgArrayErr` (check_demands.vl) refuses a map argument there: "parameter is indexed with an
i32, which is ambiguous between an array and an i32-keyed map — add a type annotation". The
argument's own type settles which: a string-keyed map and a list run through the same parameter.
`docs/internals/collections-representation-design.md` describes this refusal ("it refuses to guess
which one a hole means"), but no DECISIONS entry rules that the design owes it.

#### Ablation

| ingredient changed | outcome | needed? |
| --- | --- | --- |
| `c: {[i32]: i32}` annotated | runs, prints `5` | **yes** (the hole) |
| a `{[string]: i32}` map, `c["k"]` | runs | **yes** (the `i32` key) |
| a list `[4, 5]`, `c[1]` | runs | **yes** (the map) |
