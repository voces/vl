### D2526 — a method-call receiver was checked against a generic `self` whose `V | null` field element was still unbound, so the delivery read as a widened write

**closed 2026-09-25 — the filed repro RUNS and prints `7` · was a loud check reject of a type-valid program · clause 2 · found building `std:idtable` (collections Q4) · filed 2026-09-25 against master `ca544493e` · fixture `tests/cases/generics/ufcs-self-nullable-type-param-field.vl`**

Repro:

    type Tbl<V> = { slots: (V | null)[] }
    function put<V>(self: Tbl<V>, id: i32, v: V) {
      self.slots[id] = v
    }
    const s: (i32 | null)[] = [null, null]
    const t: Tbl<i32> = { slots: s }
    t.put(1, 7)
    print(t.slots[1] ?? -1)

#### Mechanism

The member-call path (`typecheck.vl`, the UFCS arm) pends D2060's covariant-record check with the
DECLARED `self` type, `{slots: (V | null)[]}`, rather than an instantiated one. `rcwCovs` walked
the field's element pair `i32 | null` → `V | null`: a type variable adopts the source only when it
is the whole destination, so a nullable around one fell to the union arm, which marks the slot
widened, and the body's `self.slots[id] = v` then read as a write of a value the source's slot
does not accept. The direct call `put(t, 1, 7)` checks against the instantiated parameter and
always ran. The fix: a nullable source into a nullable type variable compares the inner types, so
`V` adopts `i32` as a bare `V` would. A non-nullable source into `V | null` is still a widening and
still refused (`error-ufcs-self-nullable-widening-refused.vl`).

#### Ablation
