#### Mechanism

A narrowed struct arm of an INFERRED union stays the `{tag, payload}` box, so every delivery
boundary owes it an unbox to the destination's own rep. D1723 gave that to the ARGUMENT and
the RETURN, both through the binding boundary's `armDestHeapOf(kind, slot)` pair. Three
positions still deliver the box whole:

* **a local ASSIGNMENT** (`v = p`, the binding of `v` already unboxed) — the `Ident`-target
  arm of `emitAssign`;
* **a list-element assignment** (`xs[0] = p`) — the `Index`-target arm;
* **a CAPTURE** in an un-annotated closure body.

The module-scope assignment already runs: the GLOBAL-target arm carries the unbox
(`gaKind`/`gaArmIdx`), which is why the same statement at module scope prints `8` and inside a
function does not.

**A first attempt at the local arm was reverted rather than shipped.** Reading the cell's kind
through `identCellVKind` and its row through `structIndexOfExpr` type-checks, self-hosts and
changes nothing — the arm fires on no witness, and dead code with no test is worse than a
filed gap. Which of the two answers is wrong is the open question, and it is what a fix has to
print first.
