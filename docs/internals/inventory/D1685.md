#### Mechanism

A narrowed struct arm of an INFERRED union stays the `{tag, payload}` box, so every delivery
boundary owes it an unbox to the destination's own rep. D1723 gave that to the ARGUMENT and
the RETURN, both through the binding boundary's `armDestHeapOf(kind, slot)` pair. Three
positions still deliver the box whole:

* **a local ASSIGNMENT** (`v = p`, the binding of `v` already unboxed) — the `Ident`-target
  arm of `emitAssign`, which now reads the cell's own `(kind, slot)` columns;
* **a list-element assignment** (`xs[0] = p`) — the `Index`-target arm, which now reads the
  element's own variant or struct row, the same two seeds the value was emitted under.

The third position the row named, a CAPTURE, turned out to be a different defect: the
ingredient is an UN-ANNOTATED binding, and the closure only converts its loud refusal into an
invalid module. Filed as D1741.

The module-scope assignment already runs: the GLOBAL-target arm carries the unbox
(`gaKind`/`gaArmIdx`), which is why the same statement at module scope prints `8` and inside a
function does not.

**Both answers in the reverted first attempt were wrong, and an instrumented build says so.**
At the failing assignment: `armVi=0 narrowTop=1 gate=1 kind=variant row=-1`. The gate fires,
so the arm is identified; the cell's kind is `variant`, not the `struct` that attempt guarded
on; and `structIndexOfExpr` answers **-1** where the binding boundary's `localStructIdx[slot]`
answers **0**. So the KIND reader was right and the ROW reader was not — the destination has to
be read through the SLOT, as the binding reads it, which `identCellSlot` now supplies.

**The probe needed correcting before it could say that.** Only the FIRST `emitFail` surfaces
per run, so arming a probe at the binding and the assignment together showed the binding's and
looked like the assignment site was never reached. Removing the binding's probe is what made
the assignment's readable.
