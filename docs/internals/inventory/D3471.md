### D3471 — an index of a nullable map or list with a string key leads with `array index must be i32, got string`

**loud check reject · clause 2 · open · the refusal is owed, its first sentence is not; pre-existing, the same on master `c17016a1e` · filed 2026-10-02 against master `c17016a1e`**

Repro:

    function f(x: {[string]: i32} | null) { print(x["k"]) }
    f(null)
    // vl check: rc 1, two lines: "array index must be i32, got string", then "cannot index non-array {[string]: i32} | null"

#### Mechanism

Not localised past the ablation. The index arm grades the key against an array's `i32` index before it
asks whether the receiver is indexable at all, so a nullable receiver gets the array sentence first
and the true one second. A map indexed by a string is legal (`x: {[string]: i32}` runs and prints
`null` for a miss), so the sentence read first is wrong about both the key and the receiver; the
second names the receiver's real problem, its `null`, in terms of "non-array".

#### Ablation

| ingredient changed | outcome | needed? |
| --- | --- | --- |
| `x: {[string]: i32}`, not nullable | runs, prints `null` | **yes** (the `\| null`) |
| `x[0]`, an `i32` key | one line, `cannot index non-array {[string]: i32} \| null` | **yes** (the string key) |
| `x: string[] \| null`, `x["k"]` | the same two lines | no |
| the key a `const k = "k"` | `array index must be i32, got "k"` first | no |
| `x.k` or `x.get("k")` | one line, `member access ... on non-object` | n/a |

#### Grading list

The sentence for a nullable indexee should be one line that names the `null`, the way the member
spellings do; `vl check` on each ablation row is its own re-grade.
