### D6070 — a `const` hole lambda handed to an un-annotated parameter that calls it has no monomorphized argument type

**closed 2026-10-17 by lane L1 · runs, prints `x` · was loud emit reject · clause 2 · closed by the hole-lambda pin through a hole parameter that closed [D6001](D6001.md) (branch `l1-d6000`, `92c806c4a`) · pins: `closures/hole-lambda-const-to-hole-param.vl` · found grading [D5611](D5611.md)'s siblings · filed 2026-10-17 against master `3258a6d99`**

Repro:

    function mid(a) {
      print(a("x"))
    }
    const h = (k) => k
    mid(h)
    // vl check: rc 0.  vl run: emitProgram: monomorphize: unsupported argument type for `a` in a call to `mid`

    x

#### Mechanism

From the ablation only. A hole lambda is generic (spec S2.5), and a call through it is
instanced at the call's types. Handed to a hole, it gives `mid`'s instance key no argument
type. This happens at ONE signature, so it is not D5611's two-pin question. A hole FUNCTION
(`function h(k) { k }`) or a generic alias (`const h = same`) handed over the same way runs,
on the path of [D5361](D5361.md) and [D5612](D5612.md). The lambda does not take that path.
