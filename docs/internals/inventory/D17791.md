### D17791 — a `.map` lambda binding an element's function field at another closed signature writes the field's value unconverted

**open · loud emit reject · clause 2 · `vl check` rc 0, `emitProgram: a .map/.filter callback needs an instance at the list's element type, and none was built for this call` · was: check-clean invalid wasm (lane START-2 made it loud, 2026-11-28) · filed 2026-11-28 against master `2693ffdcf` (lane START-2)**

Repro:

    function id(a) { return a }
    function deliver() { return [{ f: id }] }
    const u = deliver()
    print(u[0].f(2))
    const v = deliver().map((r): { f: (a: f64) => f64 } => { const g: (a: f64) => f64 = r.f; return { f: g } })
    print(v[0].f(2.5))
    // vl check: rc 0.  vl build: loud emit reject (was invalid wasm)

Want:

    2
    2.5

#### Mechanism

Inside the lambda the element's field is read at the list's storage and delivered to the
annotated binding `g` without the conversion an annotated module binding gets, so the
lambda's result record is built from a value of another rep. The sibling of
[D17790](D17790.md) and [D17775](D17775.md), at a binding inside a `.map` lambda.
