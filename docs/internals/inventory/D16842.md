### D16842 — an un-annotated function taken as a value where no read resolves it to one function is refused at emit

**open · loud emit reject · clause 2 (`vl check` rc 0) · the general mechanism behind [D16739](D16739.md)'s spellings the value-flow rewrite cannot resolve: a record chosen at run time, an inline read through a call, a declared generic's parameter · filed 2026-11-16 against master `8b8d6a489`**

Repro:

    function inc0(a) { return a + 1 }
    function inc1(a) { return a + 2 }
    function id(x) { return x }
    const n = 3
    const r = id(if n > 2 { { f: inc0 } } else { { f: inc1 } })
    print(r.f(3))
    // vl check: rc 0.  vl run: emit error, `cannot take the generic function `inc0` as a value`

Want:

    4

#### Mechanism

Not traced. A read the value-flow rewrite resolves to one function (`mfrChainFns`) is rewritten to
a direct call, which instances the function at its arguments; a read it cannot resolve leaves the
function a value, which the value floor refuses because a hole function carries no one signature.
Instancing a hole function taken as a value at the concrete function type its reads give it is
the general fix; extending the rewrite covers only reads resolvable before running.

| a declared generic (`function idt<T>(x: T): T`, `idt([inc0])`, `xs[0](3)`) | the same message |
| `inc0` annotated | runs |
