### D15201 — a function written through an alias of a list element or of a field of one builds an invalid module

**closed · runs, prints `1.5` · was an invalid module after a clean `vl check`, clause 1 · found grading D15199's controls · present on master `f6b19ca4` · filed 2026-11-03 against master `f6b19ca4` · fixed with [D15193](D15193.md) by widening an element-rooted slot as a binding's own field is widened: the write scan follows an alias whose initialiser has index steps (`cwSlotAliasPathOf`), and `letLitListsWidenAt` (check_statements.vl) walks a list literal's elements as `[]` down to the `elabFnFieldListTy` leaf. The named set `d15201-element-rooted-alias` holds the positions, the design refusals and the controls**

Repro:

    function inc0(a) { return a + 1 }
    function half(a) { return a / 2.0 }
    const rs = [{ fs: [inc0] }]
    const a = rs[0].fs
    a[0] = half
    print(rs[0].fs[0](3))

Want:

    1.5

#### Mechanism

The alias of a binding's own field (`a = r.fs`) ran: `elabFnFieldListTy` joins what is written through it into the field's set (D15168). An alias rooted at a list element was not followed by the write scan, so the written function reached an element typed at the literal's set, and the call dispatched it at another signature.
