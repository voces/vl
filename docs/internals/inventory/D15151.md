#### Fix

`variantStructHeapTwinAt`, the arm's twin question `collectS` asks mid-loop, answers from the
record-row class (`recordRowClassOf`, D15152): the arm's row and the struct row twin when their
record types have one class. The class is read from the checked types alone, so the question no
longer compares the two rows' map fields by mv slot one phase before `collectA` interns them,
and the field-code walk it replaced is deleted. The arm twins are identical over every
`tests/cases` file and the distilled corpus.

#### Mechanism

A seed built with `--names` reaches the find-only lookup through
`uFieldMapShape ← variantStructHeapTwinAt ← fieldTypeCode ← collectS`: the ARM row's own map
slot is missing when `collectS` asks, though [D15097](D15097.md) interns the arm's map slots
first. A non-null arm value, a record value and a string value all find theirs, so the
nullable arm value is the ingredient. Not traced further.
