### D14888 — a module hole lambda handed through an identity to a generic's `(x: T) => T` binding, the generic called at two types, is refused at emit

**loud emit reject · clause 2 · `vl check` rc 0 · `emitProgram: monomorphize: unsupported argument type for f in a call to fw` · pre-existing, the same with rung B · likely the hole-lambda-as-polymorphic-value family step 7 is scoping · found writing the generic-instance twin of step 5's per-instance list-copy fix for the D14884 coercion · filed 2026-11-01 against master `dcc5caee`**

Repro:

    function fw(f) { return f }
    const lam = (x) => x
    function g<T>(t: T) {
      const v: (x: T) => T = fw(lam)
      print(v(t))
    }
    g(3)
    g("s")

Want:

    3
    s

#### Mechanism

Each instance of `g` delivers `fw(lam)` to a different closed type, `(x: i32) => i32` and
`(x: string) => string`, so `lam` needs one instance per pin of `g` and `fw`'s call needs a key
per instance of `g`. Mono finds no pin for `fw`'s hole parameter inside the generic body, and
refuses. A lambda written inside `g` gets a slot per instance and runs.

#### Ablation

| ingredient changed | outcome | needed? |
| --- | --- | --- |
| `g(3)` alone (one pin) | runs, `3` | **yes** |
| `g(3)` and `g(4)` (one type twice) | runs, `3 4` | **yes** |
| `= lam` without `fw` | runs, `3 s` | **yes** |
| `lam` declared inside `g` | runs, `3 s` | **yes** (module scope) |
| `const v = fw(lam)`, unused | same refusal | no (that is D14887's shape) |
| `deliver()` (an inferred-return wrapper) around `fw(lam)` | same refusal | no |
