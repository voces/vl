### D3065 — a `<T>` for-in over a list literal of an element read binds the loop variable as the `i32` cell at a `boolean` or literal-union pin

**closed 2026-09-28 — the witness prints `true` · was check-clean silently wrong · clause 1 · found grading D3014's shapes (`forinlitidx_g`, 29 cells at the `boolean | null` pins) · the same on master `6c2dafc0b` · `iterElemPinTy` reads a literal of element reads or locals at their pin (`arrLitReadsPinTy`) · fixture `tests/cases/generics/for-in-over-literal-of-element-read-at-pin.vl` · filed 2026-09-28 against master `6c2dafc0b`**

Repro:

    function f<T>(x: T) {
      const l = [x]
      for e in [l[0]] { print(e) }
    }
    const t: boolean | null = true
    f(t)
    // PRINTS 1

Want:

    true

#### Mechanism

A loop variable whose type is a type parameter prints at the pin its list's element holds there
(`loopVarPinTyOf` → `iterElemPinTy`). For a list literal, `iterElemPinTy` knew only a literal of
the instance's own parameter (`[x, x]`); a literal of any other read (`[l[0]]`, `[y]` with
`const y = l[0]`) answered no pin, so the loop variable printed as the `i32` cell a `boolean`,
`boolean | null` or literal union is stored in. It now reads each element's own pin: an element
read's list element, a parameter's pin, or a local's annotation or initializer.

#### Ablation

| ingredient changed | outcome | needed? |
| --- | --- | --- |
| `for e in [x]` | prints `true` | **yes** (a literal of another read) |
| `const m = [l[0]]` then `for e in m` | prints `true` | **yes** (the literal iterable) |
| `print(l[0])` | prints `true` | **yes** (the loop) |
| a plain `boolean` pin | prints `1` | no |
| an `"a" \| "b" \| null` pin | loud emit reject, no member texts | no (the same miss) |
| an un-annotated `function f(x)` | prints `true` | **yes** (`<T>`) |
