### D3958 — a capture cell seeded from a parameter and written with a generic function traps when called after the write

**loads then traps · found in review of #3498 (`rv3498/round4/e13`) · filed 2026-10-10 against master `429e7b093`**

Repro:

    function other<V>(v: V) { print("O"); print(v) }
    function a<T>(x: T, f: (t: T) => void) {
      let k = f
      const w = () => { k = other }
      k(x)
      w()
      k(x)
    }
    a(1, (n: i32) => { print("P"); print(n) })
    // vl check: rc 0.  vl run: prints P 1, then wasm trap: indirect call type mismatch

Want:

    P
    1
    O
    1

#### Mechanism

Not located; D3957 is the same shape with the parameter named like a function. The seed is a
parameter, which `monoCellValueTake` admits as built by its caller, and the generic written by
`w` is instanced at the cell's type; the call after the write still reaches a closure of another
signature.

#### Ablation

| ingredient changed | outcome | needed? |
| --- | --- | --- |
| the write `k = other` removed | runs | **yes** |
| the seed an annotated local (`const f: (n: i32) => void = …`) | see D3953 | — |
