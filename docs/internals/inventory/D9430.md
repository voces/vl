### D9430 — a generic over a function-typed parameter stored in an un-annotated `Map()` has no map value slot

**loud emit reject · clause 2 · `vl check` rc 0 · CAPABILITY: the same generic bound at an annotated destination runs · found closing [D9381](D9381.md) · present on master `3a918d6cc` · filed 2026-10-21 against master `3a918d6cc`**

Repro:

    function call<T>(f: () => T): T { f() }
    const m = Map()
    m["k"] = call
    const mv = m["k"]
    if mv != null {
      const v = mv
      print(v(() => 7))
    }
    // vl run: emitProgram: unsupported map value type (no rep for a union-member struct, a nullable list over an unnamed element rep, or a nullable litunion-result closure; any other value type here interned no mv slot)

Want:

    7

#### Mechanism

Not traced. The map's value type is the generic's function type, fixed only by the read's call,
and no mv slot is interned for it, so `Map()` refuses at its construction. A non-generic
`call(f: () => i32): i32` in the same map runs, and so does a generic over a list parameter
(`first<T>(xs: T[])`).

#### Ablation

| ingredient removed | outcome | needed? |
| --- | --- | --- |
| the generic (`call(f: () => i32): i32`) | runs, `7` | **yes** |
| the function-typed parameter (`first<T>(xs: T[])`, called with `[4]`) | runs | **yes** |
| the direct store (`m["k"] = deliver()`, `deliver` returning `call`) | still refuses | no |

#### Grading list

The `map_value` and `map_set` un-annotated cells of matrix `fn-value-generic-returned-fn-param`.
