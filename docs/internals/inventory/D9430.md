#### Mechanism

`monoStoredSlotFnTy` types an un-annotated map's or list's value slot from the one pin its
reads take. It spelled that pin with `monoSigFnTyName`, which writes each parameter's pin text
as it stands. A function-typed parameter is pinned as a wasm signature (`=>k`), so the slot's
spelling was `(=>k)=>void`, `nameToTy` returned -1, no mv slot was interned, and `Map()` refused
at its construction.

The fix moves `monoSlotPinName`'s pin spelling into `monoSlotPinAnn` and has both callers use
it. A function-value pin is spelled as the closed parameter type the pin was taken at
(`monoPinFnParamTys`). An inline record pin takes the spelling its shape is interned under
(`monoPinShapeSpell`, [D9431](D9431.md)).
