### D4911 — `is K[]` in a generic instance whose arm reads the receiver as `K[]` still answers by the element type

**check-clean silently wrong value · clause 1 · the residual of [D4910](D4910.md): its value test stands down wherever a region the `is` narrows reads the receiver, because the instance's value cannot be read as `K[]` · against the D4771 ruling · pre-existing on master · filed 2026-10-15 against master `687f37dd5`**

Repro:

    function a<V>(v: V[]) {
      if v is f64[] { return v.length + 10 }
      0
    }
    const e: i32[] = []
    print(a(e))
    // PRINTS 0

Want:

    10

#### Mechanism

`emitListEmptyFitIs` (wasmEmit.vl) answers `v is f64[]` by emptiness only when no region the
test narrows reads `v`: the then and else arms, the right of an `&&`/`||`, and the rest of the
block after a negated test that exits. Where one does, the arm would read an `i32[]` value as an
`f64[]`, so the test keeps `monoStaticIsResult`'s fold (`false` at `V = i32`) and the arm is
not lowered. A sound answer needs the arm to read an empty `f64[]` in the receiver's place; a
rebinding minted in `monoCloneBodyRaw` was tried and failed, because the emitter resolves a
same-named mint with no declaration identity to the original.

#### Through D4551's default

A type parameter defaulted at the call (D4551, DECISIONS.md §"An unbound type parameter
defaults at the call") is observable only through this row: `const q: U[] = []` followed by
`if q is f64[] { print(q.length + 10) }` prints nothing under the `i32` default and `10` under
an `f64` one. The `i32` default gives the answer master already gave there.
