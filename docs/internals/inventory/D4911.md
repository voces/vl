### D4911 — `is K[]` in a generic instance whose arm reads the receiver as `K[]` still answers by the element type

**closed 2026-10-15 — now prints `10` · was check-clean silently wrong value, clause 1 · the test is an emptiness test and every region it narrows reads a fresh empty `K[]` in the receiver's place: the `if` arm, the `else` arm, and the rest of a block after a negated test that exits · a push through that list is [D4934](D4934.md) and a closure read is [D4935](D4935.md), both since closed · the residual of [D4910](D4910.md) · pre-existing on master · filed 2026-10-15 against master `687f37dd5` · pin: `tests/cases/generics/is-list-arm-reads-empty-receiver.vl`**

Repro:

    function a<V>(v: V[]) {
      if v is f64[] { return v.length + 10 }
      0
    }
    const e: i32[] = []
    print(a(e))
    // PRINTS 0

Want:

    10

#### Mechanism

Before the fix, `emitListEmptyFitIs` (wasmEmit.vl) answered `v is f64[]` by emptiness only
when no region the test narrows reads `v`. Where one did, the test kept
`monoStaticIsResult`'s fold (`false` at `V = i32`). Now the test sets a shadow local holding
an empty `f64[]`, and `emitIdentNode` redirects the receiver's reads to it inside the
narrowed regions (`fitShRecv`), so the arm reads a real empty list at the arm's type.

#### Through D4551's default

A type parameter defaulted at the call (D4551, DECISIONS.md §"An unbound type parameter
defaults at the call") is observable only through this row: `const q: U[] = []` followed by
`if q is f64[] { print(q.length + 10) }` prints nothing under the `i32` default and `10` under
an `f64` one. The close prints `10` under both defaults.
