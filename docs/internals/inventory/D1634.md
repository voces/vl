### D1634 — a captured closure value whose binding lives in a FUNCTION frame is called with nothing on the stack

**check-clean invalid wasm · 2 cells, `call-through-binding-shadowing-fn-name`'s `fn_body_capture` row, both faces · filed 2026-09-05 against master `abecf8da`**

Repro:

    function __frame() {
      const c: (i32) => void = (n: i32) => { print(n) }
      const f = () => {
        c(8)
      }
      f()
    }
    __frame()
    // vl check: rc 0.  vl run: the emitted module failed to validate inside `f`:
    // type mismatch: expected i32 but nothing on stack

#### Mechanism

Not ablated to a mechanism. What the ablation does establish is the axis: the identical
program at MODULE scope runs, and the only difference is which scope binds the closure
value. The message is an arity one — the call site pushed no argument — so the env field is
not carrying the fat pointer the callee's `$fnsig` expects.

Found by the `fn_body_capture` matrix position, which this PR adds; nothing before it put a
binding, its capture and the capturing lambda all inside one function body.

#### Ablation

Every row is `vl check` rc 0.

| spelling | outcome |
| --- | --- |
| the witness (frame-scoped closure value, called through the capture) | **invalid wasm** |
| the identical program at MODULE scope | runs, 8 |
| the capture rebound first (`const v = c` then `v(8)`) | **invalid wasm** |
| the capture never CALLED (`const v = c`, print something else) | runs |
| a module `function v(): i32` shadowed by the rebind | no effect either way |

Needed: the frame AND the call through the captured closure. The shadowing the template is
named for is scenery here — renaming the rebind and deleting the module function each leave
the outcome unchanged.
