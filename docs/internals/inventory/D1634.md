### D1634 — a captured closure value's `$fnsig` was resolved against the capturing lambda, which never binds it

**closed · filed 2026-09-05 against master `abecf8da` · closed against `d040e263`**

`calleeCloSigKeySid` gained the capture channel: when the callee name is a capture of
`fnIx`, the key is re-asked against the frame that OWNS the binding. Both faces run, and so
do the four other frame-scoped spellings the ablation found.

Repro:

    function __frame() {
      const c: (i32) => void = (n: i32) => { print(n) }
      const f = () => {
        c(8)
      }
      f()
    }
    __frame()
    // vl check: rc 0.  vl run: the emitted module failed to validate inside `f`:
    // type mismatch: expected i32 but nothing on stack

#### Mechanism

**Not an arity failure, and the disassembly is what says so** — the argument IS pushed. The
mismatch is at the lambda's own `return`: `f` was declared `(structref) -> i32` while its
body's tail is a void `call_indirect`.

`stmtIsTailValue` asks `calleeReturnsVoidSid` whether a closure-value tail call yields
anything, and that resolves through `calleeCloSigKeySid`, whose rungs read `fnIx`'s params
and body, the globals registry and the module frame. `c` is in none of them: it lives in the
ENCLOSING frame and reaches `f` through the env. So the key came back "" — the all-i32 arity
fallback, which carries no `>v` — and the void tail read as a value. The same resolver drives
the statement form, so a non-tail `c(8)` emitted a `drop` over an empty stack.

Module scope escaped because `c` is a global there and the globals registry is durable, which
is what makes the enclosing FRAME the axis rather than the capture.

#### Ablation

Every row is `vl check` rc 0. **The table this row was filed with named two ingredients it
does not have**: the shadowing the template is named for and the rebind are both scenery.

| spelling | before | after |
| --- | --- | --- |
| the witness (frame, captured closure, called) | **invalid wasm** | **runs 8** |
| the module `function v(): i32` deleted | **invalid wasm** | **runs 8** |
| the rebind renamed off the module function's name | **invalid wasm** | **runs 8** |
| no rebind at all (`c(8)` straight through the capture) | **invalid wasm** | **runs 8** |
| the captured closure a PARAMETER of the frame | **invalid wasm** | **runs 8** |
| the call not in tail position | **invalid wasm** (`drop`) | **runs 8, 9** |
| the same program at MODULE scope | runs 8 | runs 8 |
| the capture never CALLED | runs 1 | runs 1 |
| the captured closure returning i32 rather than void | runs 9 | runs 9 |
| the closure called with no capture hop | runs 8 | runs 8 |

Needed: the frame AND the capture AND the call. Not needed: the shadow, the rebind, the
tail position, or whether the binding is a `let` or a param. The result kind IS an
ingredient — an i32-returning captured closure ran throughout, so only the void result
reached the missing rung.
