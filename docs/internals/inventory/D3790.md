#### Mechanism

`concat`'s argument is a `slice` result, which no binding annotates, so the instance is pinned
at the floor's render of its type: `{key:i32,blows:{tick:i32,dmg:i32}[]}[]`. That spelling mints
its own struct row, whose `blows` field records the element `{tick:i32,dmg:i32}` at an arena
index no row carries. `buildStructTwins` then compares it with `St`: same canonical key, same
field codes, but `structFieldCodesEq` must find the row behind each named-heap field, and its two
rungs (`sTyIx` identity, then the row name) both missed, so it declined. The instance's
`(ref $St')` met the declared `(ref $St)` and the module failed to validate. The same decline
hits a hand-written inline annotation (`x: {key: i32, blows: {tick: i32, dmg: i32}[]}[]`) with no
generic at all, and a list-of-lists field, whose element is a list rather than a row. The fix
adds a third rung, the element's row by shape (`repRowOfTyStruct`, which keeps its own
collision decline), and peels matching list layers to compare the leaf rows.
