### D3452 — `x++` over a union of numeric types is refused while `x += 1` runs

**loud check reject · clause 2 · open · filed 2026-09-30 against master `028dedb33` with the numeric-join lane applied**

Repro:

    function f(c: boolean, x: f64, y: i32) {
      let r = if c { x } else { y }
      r++
      print(r)
    }
    f(false, 2.5, 7)
    // vl check: '++'/'--' over the numeric union i32 | f64 is not supported; write `x += 1`

#### Mechanism

A postfix `x++` is `Unary p+` over the desugared `x = x + 1`, and its expression value is the
emitter's `(x + 1) - 1` in the `i32` opcode family (`emitUnaryNode`), which has no form over a
union box. The assignment inside it dispatches like `+=` does; only the old-value recovery is
missing, so the checker refuses the operator by name rather than let the box reach an `i32.sub`.

#### Ablation

| ingredient changed | outcome | needed? |
| --- | --- | --- |
| `r++` written `r += 1` | runs, prints `8` | **yes** (the postfix form) |
| `r` narrowed to `i32` first | runs | **yes** (the union operand) |

#### Grading list

`--` over the same binding, and `x++` in expression position (`print(r++)`).
