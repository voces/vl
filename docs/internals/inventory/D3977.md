### D3977 — a call through a list element does not constrain the function value's type, which a later delivery sets

**check-clean silently wrong · clause 1 · found in review of #3501 (`rv3501/round2/q05j`; `q05a`, `q05e`, `q05g`) · filed 2026-10-10 against master `56f77d80f`**

Repro:

    function inner<U>(u: U) { print("I"); print(u) }
    function cb(f: (b: boolean) => void, b: boolean) { f(b) }
    function main() {
      const r = inner
      const fs = [r]
      fs[0](3)
      cb(r, true)
    }
    main()
    // vl check: rc 0.  vl run: prints I true I true

Want:

    I
    3
    I
    true

#### Mechanism

Not located. `r` names the generic `inner`; `[r]` stores it unpinned, and the call `fs[0](3)` is
not one `monoInstantiate` sees as a call of `r`, so it pins nothing. The delivery `cb(r, true)`
then instances `inner` at `boolean`, and the list's element is that instance too, so `3` is read
as `true`. No capture cell is involved; the cell spellings inherit it.
