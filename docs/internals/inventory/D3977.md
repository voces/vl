### D3977 — a call through a list element does not constrain the function value's type, which a later delivery sets

**closed 2026-10-10 by lane SC · runs · was check-clean silently wrong · clause 1 · pins: `tests/cases/closures/list-of-generic-alias-called-then-delivered.vl`, `tests/cases/closures/list-of-generic-called-through-elements.vl`, `tests/cases/closures/error-list-of-generic-called-at-two-types.vl`, `tests/cases/closures/error-captured-cell-in-list-called-then-delivered.vl` · found in review of #3501 (`rv3501/round2/q05j`; `q05a`, `q05e`, `q05g`) · filed 2026-10-10 against master `56f77d80f`**

Repro:

    function inner<U>(u: U) { print("I"); print(u) }
    function cb(f: (b: boolean) => void, b: boolean) { f(b) }
    function main() {
      const r = inner
      const fs = [r]
      fs[0](3)
      cb(r, true)
    }
    main()
    // vl check: rc 0.  vl run: prints I true I true

Want:

    I
    3
    I
    true

#### Mechanism

`r` names the generic `inner`; `[r]` stored it unpinned, and the call `fs[0](3)` was not one
`monoInstantiate` saw as a call of `r`, so it pinned nothing. The delivery `cb(r, true)` then
instanced `inner` at `boolean`, and the list's element was that instance too. An un-annotated
`const` list holding a generic is now given the function type every call of one of its elements
takes, as an annotation would (`monoPinGenericList`), so its elements are instanced at it; a list
read other than by element calls, or called at two types, is refused. A capture cell placed in the
list (`[k]`) is called through the cell, as #3501 does for an alias of one.

#### Ablation

| ingredient changed | outcome | needed? |
| --- | --- | --- |
| the delivery `cb(r, true)` removed | refused on master (`round2/q05i`); runs now | **yes** |
| `k` a written capture cell in the list, `[k]` (`round2/q05a`, after the write `q05e`) | was the same wrong value; now the binding conflict, refused | no |
| the cell seeded with a hole lambda (`round2/q05g`) | was the same wrong value; now refused | no |
