### D9661 — a const bound to a list of un-annotated functions, nested in a list literal, is refused as a nested array

**loud emit reject · `vl check` rc 0 · `nested arrays are not supported` · clause 2 · found closing [D9553](D9553.md) · present on master `abe12f20f` · filed 2026-10-22 against master `abe12f20f`**

Repro:

    function inc(a) { return a + 1 }
    const w = [inc]
    const v = [w]
    print(v[0][0](3))
    // vl check rc 0.  vl run: emit error: emitProgram: nested arrays are not supported

Want:

    4

#### Mechanism

Not traced. The inline spelling `[[inc]]` runs, so a nested list of un-annotated functions has a
lowering. When the inner list is a `const`, the outer literal is typed from `w`'s open binding,
`((_) => _)[]`. The call through `v[0][0]` pins the element, but the pin does not reach the
literal `w` is bound to, and the outer literal's element has no list shape.

#### Ablation

| ingredient removed | outcome | needed? |
| --- | --- | --- |
| the `const` (`const v = [[inc]]`) | runs, `4` | **yes** |
| the un-annotated parameter (`inc(a: i32)`) | runs, `4` | **yes** |
| a second function (`[inc, dbl]`, `v[0][1](3)`) | same refusal | no |
