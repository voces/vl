### D9661 — a const bound to a list of un-annotated functions, nested in a list literal, is refused as a nested array

**closed · runs, prints `4` · was loud emit reject, `vl check` rc 0, clause 2 · found closing [D9553](D9553.md) · filed 2026-10-22 against master `abe12f20f` · closed by typing a nested literal whose elements name `const`s already pinned from those bindings' types (`monoBoundFnListElemsTy`, `monoPinNestedListElems`, emit_mono.vl) · fixture `closures/hole-fn-bound-list-returned-from-hole-param.vl`**

Repro:

    function inc(a) { return a + 1 }
    const w = [inc]
    const v = [w]
    print(v[0][0](3))
    // vl check rc 0.  vl run: emit error: emitProgram: nested arrays are not supported

Want:

    4

#### Mechanism

`monoPinNestedListElems` (emit_mono.vl) typed a nested literal only from its inline inner
literals. Here the inner element is the name `w`, whose own binding the walk has already
annotated at its pin, so the outer literal stayed at `w`'s open type and had no list shape. An
element naming a `const` that is already pinned now gives the literal that binding's type, and
the read is recorded at it (`monoBoundFnListElemsTy`).
