### D3305 — a `null`-only binding passed to a hole or generic parameter pins the instance at `i32`, building invalid wasm

**closed 2026-10-20 by lane L1 · the witness prints `7` · was check-clean invalid wasm · clause 1 · open on master `cd64d5faa` · closed with [D8280](D8280.md) · fixture `tests/cases/generics/null-binding-pins-null.vl` · found by the D3301 lane while ablating D3304 · filed 2026-09-29 against master `e70102886`**

Repro:

    function u(q) { return 7 }
    const x = null
    print(u(x))
    // vl check: rc 0.  vl run: invalid module, type mismatch: expected i32, found nullref

Want:

    7

#### Mechanism

Not yet located; D3304's sibling. `const x = null` binds a `nullref` global, and the pin
`monoArgTyName` names for `u(x)` recurses into the initializer, where a `null` literal matches no
rung and reaches the `"i32"` catch-all. The instance is minted with an `i32` parameter and the
call hands it the `nullref`. The catch-all's own note says a floor (`""`) beats a wrong
instance, so the least fix is a loud refusal there. The real fix is D3304's `null`-typed parameter rep.

Closed with [D8280](D8280.md) in `monoArgPinName`/`monoArgPinTyIx` (emit_mono.vl): a read of a
`null` binding no write fills pins the `null` type, so the instance's parameter is a `nullref`.

#### Ablation (master `e70102886`)

| ingredient changed | outcome | needed? |
