### D14581 — a self-call's instance binding is re-solved from its argument types, not taken from the template's row

**runs today and must keep running · refutation pin: the recursion prints right, and the binding it reaches by is a second producer · deletion target: the self-call binding comes from the same template-row seed (`bindTemplateRow`, check_calls.vl) every other call takes · filed 2026-10-28 against master `ed66480b0`**

Repro:

    function nul<T>(u: T | null, n: i32) {
      if n == 0 { return 0 }
      return nul<T | null>(u, n - 1) + 1
    }
    print(nul<i32>(1, 3))

Want:

    3

#### Mechanism

The elaboration enqueues each closed call in an instance body. For a call to a declaration on
the instance's own chain, `elabSelfRow` (emit_elab.vl) binds the callee's type variables by
walking its parameter types against the arguments' types at the instance, in place of the
call's captured binding. At `nul<T = i32>` the template binds the self-call at `T := T | null`,
which substitutes to `i32 | null`. `elabSelfRow` walks `u: T | null` against `i32 | null` and
answers `T = i32`, so the explicit type argument is ignored and the instance reached is
`nul<T = i32>` again. The count is the same at both bindings, so the witness cannot see the
difference. A call-binding probe comparing each instance call's binding with the template's
binding under substitution reports this as the one event that does not belong to the B′
hole-literal family.
