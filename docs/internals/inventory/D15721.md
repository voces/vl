#### Mechanism

`recKeptFnDecl` holds the last pass's kept functions, and `recKeptFnNote` rewrites it partway
through each pass, so a program's first pass read the previous program's. `batch-before.vl` keeps
`mk` and `w` (declarations 10 and 16), and `main.vl` has `mk` and `w` at the same node indices. So
`recObjLitBuild` read `mk()` in `w`'s literal (node 14) as built at `J` and stamped the literal at
`K`'s row. `storeLetsResolve` then built `const y = w()` at `K` (`callBuiltTy` through
`litRepTyAt`'s stamp), while `mk()` handed its own row: invalid wasm. Found by logging `repStamp`'s
writes to node 14 and `recBuildPush`'s callers in program 2. The build tables
(`recBuildPass`/`recBuildLast`) and the arm-adoption queues (`recArmListLits`, `recObjLits`) carry
node indices across programs the same way, and are emptied with it.
