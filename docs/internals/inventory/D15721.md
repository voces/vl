### D15721 — a list literal built at a wider record leaves node-indexed state that the next program in one batch reads, so a maker built at its own row there is invalid wasm

**check-clean invalid wasm under `vl check --batch --codegen` only · clause 1 · `the emitted module failed to validate inside `w` — … type mismatch: expected (ref null $1), found (ref $2); $1 is `J`, struct {mut (ref $4)}; $2 is `#anon2`, struct {mut i32}` · alone it runs · present on master `2075f310` · found by #7247's nested-copy sweep (`named/d15215_own_arith.vl` after `named/d15215_list_dst.vl`) · filed 2026-11-12 against master `41667183`**

Repro:

    // file: batch-before.vl
    type J = { f: i32 | null }
    type K = { j: J }
    function mk() { { f: 4 } }
    function w() { { j: mk() } }
    const ks: K[] = [w()]
    print(ks[0].j.f ?? 0)
    // file: main.vl
    type J = { f: i32 | null }
    type K = { j: J }
    function mk() { { f: 4 } }
    function w() { { j: mk() } }
    const y = w()
    print(y.j.f + 1)
    // alone: runs, prints 5. After batch-before.vl on one instance (`vl check --batch
    // --codegen batch-before.vl main.vl`, the grader's `batch-*.vl` convention): invalid wasm.

Want:

    5

#### Mechanism

Not found. The defect needs an earlier program on the same compiler instance, so the repro's
`batch-before.vl` is checked first (check-filed-witnesses' `batch-*.vl` convention). The stale state
is keyed by node index: prepending one statement to `main.vl` makes it pass, renaming every type and
function in it does not. Probed at `main.vl`'s check, the checker holds none of the previous
program's state: its types agree with a solo check, its rep, copy and kept-function stamps are
empty, and every checker module's containers match those after a harmless predecessor
(`const k: K = w()`). So the state is the emitter's, a scalar, or in a module no probe reached.
`recArmListLits` and `recBuildPass`/`recBuildLast` do hold the previous program's indices at its
start; clearing them does not fix it.
