### D1473 — [CLOSED 2026-09-03] a union of INLINE arms narrowed on its literal discriminant refuses at emit: `field access but no struct type declared`, where the same union with NAMED arms runs

**runs, prints `2` — CLOSED 2026-09-03 by giving `pushDiscrimNarrow` a `variantIndexOfOwnRender`
fallback for an arm with no `type` name · clause 2 · was a loud emit reject at `vl check` rc 0 ·
a 16-cell grid goes 1 → 16 runs, zero `runs` lost · found by writing ordinary day-one programs
against master `a94037b0`, not from any filed row**

Repro (three lines; runs today, prints `2`):

    type Shape = { kind: "circle", r: f64 } | { kind: "rect", w: f64, h: f64 }
    const s: Shape = { kind: "rect", w: 2.0, h: 3.0 }
    if s.kind == "rect" { print(s.w) }

* **NAMING THE ARMS IS THE WHOLE FIX, AND IT IS THE ONLY DIFFERENCE.** Declaring
  `type Circle = { kind: "circle", r: f64 }` and `type Rect = { … }` and writing
  `type Shape = Circle | Rect` — the identical types, the identical narrowing, the identical
  read — prints `2`. So the union, the literal discriminant, the `==` narrowing and the
  arm-specific read are all supported; only the anonymous SPELLING of the arms is not.

* **NEITHER THE FUNCTION NOR THE `==` IS AN INGREDIENT.** The original witness wrapped this in
  `function area(s: Shape): f64` with two returns; it fails identically at module scope with
  one `if`. The `is` spelling cannot be written here — an inline arm has no name to test — which
  is part of why the gap survived: every fixture for this family names its arms in order to
  discriminate them.

* **THE READ MUST BE ARM-SPECIFIC.** `s.kind` (the shared discriminant) runs, and a field
  present on BOTH arms (`{kind: "circle", r: f64} | {kind: "rect", r: f64}` read as `s.r`) runs.
  Only a field belonging to one arm refuses, at both `s.w` and `s.h`.

* **AN i32 DISCRIMINANT REFUSES LOUDLY IN THE CHECKER INSTEAD**, with
  `field 'r' is not on every member of Shape — narrow with …`. That is a different and better
  outcome, and it shows the literal discriminant is what enables the narrowing that the emitter
  then cannot serve.

* **THE MESSAGE IS SHARED WITH FIVE CLOSED ROWS AND IS NOT THEIR MECHANISM.** D1031, D199,
  D1461, D220 and D38 all print `field access but no struct type declared`; every one is closed
  and none reaches this witness. Grouped by sentence this looks handled — which is the
  "a validator sentence is not a mechanism" rule paying out in the direction that hides work.

#### How it was found

Not from a row, a matrix or a corpus cell. Ten ordinary day-one programs were written against
master and run: a for-loop sum, a longest-string scan, a struct midpoint, a map counter,
recursion, `map`/`filter`, a discriminated-union `area`, an early-return default, a `while`
sum. **Eight ran; this was the one clean defect**, and a second batch of ten found none. That
is the only rate estimate this inventory has for the population no instrument samples — the
capability probes are one hand-written program per already-known gap, and the distilled corpus
is generated over fixed axes, so neither can find a shape nobody has thought of.

#### Mechanism

**IT IS NOT D1242/D1443'S ROUTE.** Those two are `collectAnonShapes` failing to mint an `#anon`
row for an object LITERAL whose field had no code. Here the rows all exist:
`registerInlineUnion` pushes one variant row per struct atom of the union, keyed on the ATOM
SPELLING — an inline arm gets a row exactly as a named one does, `collectVariantFields` fills
its field table, and `uVarHeap` interns its heap type. Nothing about the literal, the field
codes or the shape registry is involved. This is the *reverse map* being name-only.

`pushDiscrimNarrow` derives the surviving arm from `isParentTyIxOf(condIx)` — the type the
CHECKER banked at the condition — and then asks `nominalStructNameOfTy` for its name.
`nominalNameOfObj` scans the program's `TypeDecl`s for a declared name whose shape is
bidirectionally assignable, so an arm nobody named answers `""`, the push declines, and the
read reaches `emitMem` with `narrowTop` untouched. `memIsNarrowed` is then false, the variant
and nullable-variant arms decline, `sharedUnionFieldPlan` cannot serve an ARM-SPECIFIC field,
and the read falls to the `!sDeclared` floor. That floor is why the message names a struct
DECLARATION: the program declares no `type` with an object body at all.

The fix is `variantIndexOfOwnRender(tyToEmitName(dTy))` — canon's own render of the arm, matched
against the variant rows' recorded types — and it banks `uVariants[dvr]`, the ROW's spelling, so
the read side's exact `variantIndexOf` compare cannot miss it. The set-membership guard above
the push is unchanged and still refutes an arm borrowed from another union.

**THE FALLBACK ALSO RUNS WHEN THE NOMINAL NAME RESOLVES BUT NAMES NO VARIANT.** With an unused
`type Rect = { kind: "rect", w: f64, h: f64 }` beside the inline union, the reverse map answers
`Rect`, `variantIndexOf("Rect")` is -1 (no row was registered under that name), and a
nominal-only ladder declined a union it could serve. That cell is in the grid below and moved
with the first.
