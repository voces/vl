### D9070 — a declared generic handed to `.map` is accepted at a destination of the wrong element type

**closed · now a loud check reject, `cannot assign i32[] to 'ys' of type string[]` · was check-clean invalid wasm · clause 1 · found closing [D9004](D9004.md) · present on master `26a6dc669` · filed 2026-10-21 against master `26a6dc669` · closed with D9004 by `memberCallMapFilterTy` (check_member_call.vl) binding the callback's `T` at the element · fixture `closures/error-generic-fn-list-callback-at-wrong-destination.vl`**

Repro:

    function idg<T>(t: T): T { return t }
    const ys: string[] = [3].map(idg)
    print(ys.length)
    // master: vl check rc 0, vl run: invalid module, type mismatch: expected (ref null $type), found (ref $type)

#### Mechanism

The checker typed `.map(idg)` as `T[]`, which an open type variable lets fit any list
destination, so `string[]` accepted an `i32` list and the emitter built the string list's
backing over `i32` elements. With D9004's close the result is `i32[]` and the destination
refuses it.
