### D3256 — an uninitialized function-typed `let` has no local, so a function-valued loop value is refused too

**loud emit reject · filed 2026-09-29 against master `d48a56b17`**

Repro:

    function h(n: i32): i32 {
      let y: (i32) => i32
      y = (x: i32) => x + n
      y(1)
    }
    print(h(4))
    // vl check: rc 0.  vl run: emitProgram: local declaration needs an initializer

Want:

    5

#### Mechanism

`collectLocals` classifies a closure local from its initializer, so a function-typed `let` with
no initializer falls through every rung to `checkLocalI32`. That rung admits an uninitialized
local only for `i32` and `boolean`, and refuses the rest. A loop or labelled-block value whose
type is a function (`const y = C: { (x: i32) => x + n }`) lowers through such a binding, so it
is refused the same way.

#### Ablation

| ingredient removed | outcome | needed? |
| --- | --- | --- |
| the missing initializer (`let y: (i32) => i32 = (x: i32) => x + n`) | runs | **yes** |
| the function type (`let y: i32`) | runs | **yes** |
