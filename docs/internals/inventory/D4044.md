### D4044 — a generic's `T[]` at a function-type pin is refused as an unsupported array element

**open · loud emit reject · clause 2 · found by lane L2's kind grid (`scripts/twin-agreement.py` KINDS programs) · filed 2026-10-11 against master `5a9535c91`**

Repro:

    function gen<T>(t: T): T[] { return [t] }
    print(gen((x: i32) => x).length)
    // vl check: rc 0.  vl run: emitProgram: only i32[] arrays and struct/union element arrays are supported

#### Mechanism

A list of function values builds when it is written directly (`const xs: A[] = [a]` runs), so the
rep exists; the instance of a generic `T[]` at a function-type `T` does not reach it and falls to
the refusal for an element kind it has no arm for. The refusal also carries no source position.

#### Ablation

| ingredient changed | outcome | needed? |
| --- | --- | --- |
| `const xs: ((x: i32) => i32)[] = [a]` directly, no generic | runs, prints `1` | **yes** |
| `gen` returning `T` instead of `T[]`, then `gen(a)(2)` | runs, prints `2` | **yes** |
| argument a named `const a = (x: i32) => x` or an alias `type A = (x: i32) => i32` | still refuses | no |
| read through `const xs = gen(a)` then `xs[0](2)` | still refuses | no |
| `T[]` built through an annotated local `const r: T[] = [t]` | still refuses | no |

#### Grading list

- `print(gen((x: i32) => x)[0](5))`: a close must print `5`, proving the element is callable.
- the positionless refusal: whatever still refuses here should name a span.
