### D12181 — a `for` range whose next step leaves the i32 range wraps and keeps looping

**closed 2026-11-02 · runs, prints `2` · was check-clean silently wrong, clause 1 · fixture `tests/cases/loops/range-edge-step-ends.vl` · a range reaching `2147483647`, or stepping past `-2147483648`, never ended · found folding the `step -2147483648` literal for L3 · filed 2026-10-24 against master `ed5d4f7f7`**

Repro:

    let n = 0
    for i in 2147483646 to 2147483647 {
      n = n + 1
      if n > 5 { break }
    }
    print(n)

Want:

    2

#### Mechanism

The loop advances the counter with a wrapping `i32.add` and then tests it against the bound.
When the bound is within one step of the type's edge, the add wraps to the other end of the
range, which passes the test again, so the loop never exits. The exit test has to be taken
before the add can overflow (compare the distance left to the step), or the add checked.

Closed with the first: where a step can leave the range (`rangeMayWrap`), the rolled loop exits
before the add when `v > INT_MAX - K` (or `v < INT_MIN - K`, chosen by the step's sign when it is
dynamic), which is past every bound. A step can leave it when it is dynamic, when the body writes
the var, or when a bound lets the last admitted value sit within one step of the edge; an `until`
to a runtime bound with a step of 1 or -1, and a constant bound with headroom, cannot, and lower
as before. The 4x partial unroll keeps serving an inclusive runtime bound: its main loop stops one
step short there, so a trip's last step cannot pass the edge, and the guarded rolled loop runs the
rest.

#### Ablation

| ingredient removed | outcome | needed? |
| --- | --- | --- |

| the direction (`-2147483647 to -2147483648 step -1`) | still `6` | no |
