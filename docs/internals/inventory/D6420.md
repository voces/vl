### D6420 — a lambda reached through a chain of aliases, a `let` alias or a function-local alias, called with a generic whose hole it calls at two types, is refused at emit

**loud emit reject · `vl check` rc 0 · clause 2 · CAPABILITY: one module-level `const` alias of the same lambda runs · found closing [D6390](D6390.md) · filed 2026-10-18 against master `066d19373`**

Repro:

    function id(a) { return a }
    const lap = (g) => { print(g(1) + 1); return g("s") }
    const k = lap
    const k2 = k
    print(k2(id))
    // vl check: rc 0.  vl run: emitProgram: a generic function is passed to a function value whose parameter type names a type parameter this closure does not bind, so no instance of it can be chosen — call the function value from the generic function's own body, or pass a function of a concrete type

Want:

    2
    s

#### Mechanism

From the ablation only. The emitter resolves a function-valued identifier to its lambda
(`fieldValueFeOfIn`, `emit_classify.vl`) one hop from a module binding, so a second hop, a `let`
alias, or an alias inside a function body reaches the hole call with one signature.

#### Ablation

| spelling | outcome | needed? |
| --- | --- | --- |
| the witness | loud emit reject | — |
| `print(k(id))`, one alias | runs, `2 s` | **yes** |
| `let k = lap`, one alias | loud emit reject, `cannot take the generic function `id` as a value` | no |
| the lambda and one `const` alias inside `main()` | loud emit reject, the same | no |
