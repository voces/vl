### D9701 — `a[1] ?? 0` over a nullable `f32` element in an un-annotated function is refused at emit

**loud emit reject · clause 2 · CAPABILITY: the same read at top level prints `0`, the `(f64 | null)[]` face prints `0`, and a default spelled `0.5` prints `0.5` · found closing [D3797](D3797.md), the face its ablation recorded as refusing the same · present on master `4fce2a127` · filed 2026-10-22 against master `4fce2a127`**

Repro:

    function take(a) {
      print(a[1] ?? 0)
    }
    const x: f32 = 1.5
    const k: (f32 | null)[] = [x, null]
    take(k)
    // vl check: rc 0.  vl run: emitProgram: `??` over this nullable value is not supported yet — narrow it first, e.g. `if v != null { … }`

Want:

    0

#### Mechanism

As in [D3797](D3797.md), the hole body's `0` keeps `i32`, so the `??` node's pin is the numeric
union `f32 | i32`. D3797's non-null element is a dead `??` and `coalRetypedDeadJoinIf`
(wasmEmit.vl) delivers it into the pin. Here the element can be null, so the `??` is live, and
no arm of the nullable-value lowering tests an `f32 | null` element and boxes either the `f32`
or the `i32` default into the pin's union.
