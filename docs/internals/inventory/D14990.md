Repro:

    const P = 0x7FFFFFFF << 2
    const w: i64 = P
    print(w)
    // PRINTS -4

Want:

    8589934588

#### Mechanism

A radix literal is a bit pattern of its use's width, and the constant fold computes a tree over
one exactly only when the answer is the same pattern at every width: since [D3479](D3479.md),
`+`, `-` and `*` whose exact result fits 32 bits, `<<` that stays inside 32 bits, and `>>>`,
`&`, `|` and `^`. Every other tree is left whole to be computed at the width it is read at
(`cexKeepWhole`). Written at the read, that works (`const w: i64 = 0x7FFFFFFF << 2` prints
`8589934588`). Bound to an un-annotated `const` first, the tree is not a literal `const` whose
reads are rewritten, so the declaration is checked and emitted once at `i32` and an `i64` read
widens the `i32` result. The trees this reaches: a result wider than 32 bits
(`0x7FFFFFFF * 0x7FFFFFFF`, `0x7FFFFFFF + 0xFFFFFFFF`, `(0x7FFFFFFF + 1) * 2`), `/` and `%`
over a pattern (`-1 / 0xFFFFFFFF`), `>>` over a pattern whose top bit is set (`0x80000000 >> 1`),
and `<<` past 32 bits. A close copies the kept-whole tree into each read, as a literal `const`'s
literal is copied today (`lbiInlineLit`), so every read computes it at its own width.
