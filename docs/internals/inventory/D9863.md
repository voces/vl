### D9863 — a `.map` over an inline list literal of an un-annotated function calls an unknown function

**closed · runs, prints `6` · was loud emit reject, `vl check` rc 0, `call to unknown function`, clause 2 · CAPABILITY: the same list bound to a `const` ran · found closing [D9766](D9766.md) · filed 2026-10-22 against master `ba2918226` · closed by building an inline list literal receiver of `.map` / `.filter` at its own element slot's one agreed pin and retyping the literal (`monoOpenFnListLitTy`, emit_mono.vl) · fixture `closures/hole-fn-list-unbound-and-returned.vl`, matrix `fn-value-hole-list-literal-receiver` (0 → 47 of 48) · with [D9760](D9760.md), [D9763](D9763.md) and [D9861](D9861.md) closed**

Repro:

    function inc(a) { return a + 1 }
    print([inc].map((r) => r(5))[0])
    // vl check rc 0.  vl run: emit error: emitProgram: call to unknown function

Want:

#### Mechanism

The callback coercion (`monoCoerceListCbArg`, emit_mono.vl) read the receiver's type from a pin
recorded on it or from a binding's annotation (`monoPinnedListAnnTy`), and an unbound literal has
neither, so its elements stayed generic: a lambda callback called an unknown function, a declared
one refused `inc` as a value.
