### D15455 — a `const` record seeded from a hole parameter the body also calls directly, its field written with another, is refused

**open · loud emit reject · `vl check` rc 0, `emitProgram: a function value is called at two signatures, and the closure it holds was built for one`, clause 2, with the split plan on and off · the record spelling of D15453, whose list spelling builds since its close · found closing D15453 · filed 2026-11-05 against master `755ba974`**

Repro:

    function go(a, b) {
      const r = { f: a }
      r.f = b
      print(r.f(3))
      print(a("x"))
    }
    function same<T>(k: T): T { k }
    function dbl(x) { x }
    go(same, dbl)

Want:

    3
    x

#### Mechanism

The record field never takes what is written into it. The `let` site widens a record literal's
function fields with their writes (`letLitListsWidenAt`, `elabFnFieldTy`) only outside a generic,
and `go`, with hole parameters, is one; the list spelling runs because `elabFnListLetTy` has no such
guard. D15472 lifted it for a literal whose every field names a declared function. Here the field
is `a`'s, which the instance types: the literal's field type carries the generic body's set rather
than the instance's, so widening from it (measured: the guard lifted outright) joins the writes onto
the wrong set, and this witness and the control below become check-clean invalid wasm. A seed note
on the field's set (`elabParamSeedsListSlot`'s record twin) reads the same stale type and does not
help on its own.
