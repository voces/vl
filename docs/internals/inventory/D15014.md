### D15014 — a hole lambda calling a nested generic at two types, in a generic instanced at two types, is refused at emit

**loud emit reject · `vl check` rc 0 · `a call passes more arguments than the function it calls takes` · clause 2 · one instance of `outer` runs · the call-site twin of [D12213](D12213.md), found auditing mono's in-place callee renames · filed 2026-11-02 against master `c8c9c979`**

Repro:

    function outer<T>(x: T) {
      function inner<U>(u: U) { print(x); print(u) }
      const g = (v) => { inner(v) }
      g(3)
      g("q")
    }
    outer(1)
    outer("s")
    // vl check: rc 0.  vl run: emit error, a call passes more arguments than the function it calls takes

Want:

    1
    3
    1
    q
    s
    3
    s
    q

#### Mechanism

Not traced. The shape is D12213's: a call inside a lambda whose body every instance of `outer`
shares, renamed per instance by one of mono's in-place callee renames (`monoMakeInstanceHit`,
`monoMakeInstanceLater`, `monoSpecializeConcrete`, `monoLamCallByName`, `monoRespellLamFe`). The
direct call, the lambda calling `inner` at one type, and a `const` alias of `inner` in the lambda
all run at two instances of `outer`.

#### Ablation

| ingredient removed | outcome | needed? |
| --- | --- | --- |
| `outer("s")` | runs | **yes** |
| `g("q")` (the lambda called at one type) | runs | **yes** |
