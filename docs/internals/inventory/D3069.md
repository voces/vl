### D3069 — a keyword in a binding position was refused as a missing identifier, and every later use of the name re-parsed as the keyword

**now a loud check reject, one parse error at the declaration · closed 2026-09-28 · the diagnostic half of plumb PL-071 · filed against master `6c2dafc0b`, where the witness printed four errors (one with no location) · which programs parse is unchanged: a keyword naming a binding is still refused, and whether it may is the owner's language decision**

Repro (before: `expected an identifier but found \`type\``, then `expected an expression but
found TYPE` at the condition, `expected an identifier but found \`+\`` at the tail and a
location-less `A type alias requires a body`; now: exactly the one line below):

    function f(type: i64) { if type == 0 { return -1 }; type + 1 }
    // vl check: [ERROR]: `type` is a keyword and can't name a parameter — rename it

#### Mechanism

Each binding position (`parseParam`, `parseLet`, `parseFor`'s two names, `parseFuncHead`'s
name; the arrow lambda reaches `parseParam`) did `expect("IDENT")`, which skipped the keyword
and bound nothing. Every later use of the spelling was then lexed as the keyword and dispatched
as one — `type + 1` at statement start became a type declaration, `if type == 0` an operand-less
condition — so one misnamed binding cost one error per use. `bindNameTok` now names the
keyword and the role in one diagnostic and keeps it as the name for recovery; `kwUseAt` reads a
later token of that spelling as the name wherever the keyword could not stand (before an
assignment, a member access, an operator that cannot begin an expression, a call, or the end of
the statement), consulted by `parseStmt`, `parseProgram`, `parsePrimary` and the newline-`is`
continuation. Every such position is a parse error as a keyword, and the set is empty until a
declaration has been refused, so no program that parsed before parses differently. The
diagnostic is not marked lossless, so the checker still does not run on the file.

#### Ablation

| ingredient removed | outcome | needed? |
| --- | --- | --- |
| the keyword name (`t: i64`) | runs | **yes** |
| the uses in the body | one error on master too | no — they are the cascade |
| `type` swapped for any of the 20 hard keywords | one error, same shape | no |
| the parameter position swapped for `let`, `const`, `for`, the second `for` name, a lambda parameter or a function name | one error, same shape | no |

#### Grading list

A 20-keyword by 10-position grid (parameter, `let`, `const`, top-level `let`, `for`-in,
`for`-range, the second `for` name, expression and block arrow lambdas, function name), each
cell using its name in several value positions, graded 200 of 200 at exactly one error at the
declaration; `tests/cases/parser/keyword-binding-name-*.vl` pin the witness, seven positions
in one file, and a genuine later error still being reported.
