### D2945 — a generic call on a list literal's element inside an explicit `<T>` instance prints a `boolean | null` pin as its `i32`

**check-clean silently wrong · clause 1 · open · the TR2 grid's explicit-`<T>` `lit` and `lamlist` cells at `boolean | null` · the same on master `8615a730d` · filed 2026-09-28 against master `8615a730d`**

Repro:

    function id<T>(t: T): T {
      return t
    }
    function h<T>(x: T) {
      const l0 = [x]
      print(id(l0[0]))
    }
    const v0: boolean | null = null
    h(v0)
    // vl check: rc 0.  vl run: prints `2`

Want:

    null

#### Mechanism

Not localised. The explicit twin of [D2919](D2919.md)/[D2921](D2921.md), which closed the hole
spelling through `monoArgTyName`'s hole rung. An explicit instance re-types its body's nodes, but
the pin `id` is given for `l0[0]` still names the niche's `i32` rep, so `id`'s instance returns an
`i32` and `print` takes the `i32` import. At `false` it prints `0`.

#### Ablation

| ingredient changed | outcome | needed? |
| --- | --- | --- |
| `function h(x)` (the hole spelling) | runs, `null` | **yes** (the explicit `<T>`) |
| `print(l0[0])` without `id` | runs | **yes** |
| `print(id(x))` | runs | **yes** (the list element) |
| the same at module scope, no `h` | runs | **yes** |
