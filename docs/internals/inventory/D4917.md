### D4917 — a list read over `string[] | S[]` (`.length`, an index, a `for`) is refused as not on every member

**loud check reject · clause 2 · found closing D4779 · the same refusal on master before D4779's close; that close keeps the union in an `is S[]` then-branch, which before it narrowed to `S[]` and read the list · filed 2026-10-15 against master `23dcd80be`**

Repro:

    type S = "a" | "b"
    function f(x: string[] | S[]) {
      print(x.length)
    }
    const v: string[] = ["a"]
    f(v)
    // vl check: field 'length' is not on every member of string[] | S[] — narrow with `is` first (string[] is a list, not a record)

Want:

    1

#### Mechanism

Not yet located. Every member of the union is a list, and `string[] | i32[]` reads `.length`
without narrowing; with a string-literal-union element in one member the checker treats the
read as a record field. An index reads `cannot index non-array string[] | S[]` and a `for`
reads `for-in expects an array, a map or a string`.

#### Ablation

| ingredient changed | outcome | needed? |
| --- | --- | --- |
| `x: string[] \| i32[]` | prints `1` | **yes** (a literal-union element) |
| `if x is S[] { print(x.length) }` | refused the same way | no (D4779 keeps the union there) |
| `x[0]` in place of `x.length` | `cannot index non-array string[] \| S[]` | no |
