#### Mechanism

The lambda's result is inferred from its body alone (`f64[]`, or `null` for a body of `null`),
and `fnSlotAssignable` (check_relate_core.vl) refuses a function-slot result whose rep differs
from the slot's; `f64[]` and `f64[] | null` lower differently. `i32[] | null` had its own rung
in `finishInferredReturn` and the other element types had none. The close's last rung adopts
the expected result for any inferred result the slot refuses, when every returned value is
delivered to it, so the lambda is typed as the annotated `(x: i32): f64[] | null => [1.5]` is
and its `fnRet` is pinned to that type at emit. A function value whose type is already fixed
before it reaches the slot is not a lambda at the slot and stays refused ([D9781](D9781.md)).
