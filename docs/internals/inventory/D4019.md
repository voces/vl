### D4019 — a module binding of a lambda with an un-annotated parameter, called from a function above the binding, is not checked against the lambda

**check-clean invalid wasm · the residue of [D3899](D3899.md)'s close, found by its position matrix (`d3899/r1`, `r2`) · filed 2026-10-11 against master `98a4ed71b`**

Repro:

    function useK() { const s: string = k(1); print(s) }
    const k = (x) => x + 1
    useK()
    // vl check: rc 0.  vl run: the emitted module failed to validate inside `useK`: type mismatch: expected (ref $2), found i32

#### Mechanism

`globalInitPrePass` (pass 1.65) gives a module global its type before any function body is
checked, but leaves a lambda with an un-annotated parameter to pass 2, since typing it early
would fix those parameters before pass 2 marks them as inference holes. A function body above
the binding therefore reads the hoist's `TyErr` placeholder. Since D3899, `checkCallNode`
checks the call's arguments on their own there; what it cannot check is the argument against
the lambda's body, and the call's result is `TyErr`, so a destination accepts it unchecked.

#### Ablation

| ingredient changed | outcome | needed? |
| --- | --- | --- |
| `const k` moved above `useK` | loud check reject (`cannot assign i32 to 's' of type string`) | **yes** |
| `(x: i32) => x + 1`, parameter annotated | loud check reject (closed by D3899) | **yes** |
| `print(k(true))`, no destination | runs and prints `2`; below the binding it is a check reject (`operator '+' is not defined for boolean and i32`) | no — same hole, other face |
