### D4019 — a module binding of a lambda with an un-annotated parameter, called from a function above the binding, is not checked against the lambda

**closed 2026-11-01: now a loud check reject (`cannot assign i32 to 's' of type string`), the diagnosis the program owes · was check-clean invalid wasm, clause 1 · `globalInitPrePass` skipped a lambda with an un-annotated parameter, so a body above the binding read the hoist's `TyErr` placeholder; it now marks the lambda (`noteValBindLambda`) as pass 2 does and types it like any other global · fixture `tests/cases/functions/error-hole-lambda-called-above-binding.vl`; `global-function-value-called-above-declaration-runs.vl` still runs · the residue of [D3899](D3899.md)'s close, found by its position matrix (`d3899/r1`, `r2`) · filed 2026-10-11 against master `98a4ed71b`**

Repro:

    function useK() { const s: string = k(1); print(s) }
    const k = (x) => x + 1
    useK()
    // vl check: rc 1, cannot assign i32 to 's' of type string

#### Mechanism

`globalInitPrePass` (pass 1.65) gives a module global its type before any function body is
checked, but leaves a lambda with an un-annotated parameter to pass 2, since typing it early
would fix those parameters before pass 2 marks them as inference holes. A function body above
the binding therefore reads the hoist's `TyErr` placeholder. Since D3899, `checkCallNode`
checks the call's arguments on their own there; what it cannot check is the argument against
the lambda's body, and the call's result is `TyErr`, so a destination accepts it unchecked.
