### D2528 — an applied generic record alias keyed a `(S | null)[]` field's element by its parenthesised spelling, which names no list slot

**closed 2026-09-25 — the filed repro RUNS and prints `4` · was a loud emit reject, `emitProgram: ref valtype with no interned shape` · clause 2 · found building `std:idtable` (collections Q4) · filed 2026-09-25 against master `ca544493e` · fixture `tests/cases/generics/generic-alias-nullable-struct-list-field.vl`**

Repro:

    type Box<V> = { slots: (Tex | null)[], tag: V }
    type Tex = { w: i32 }
    const b: Box<i32> = { slots: [null], tag: 1 }
    b.slots[0] = { w: 4 }
    const r = b.slots[0]
    if r != null { print(r.w) }

#### Mechanism

`gaeEnsure` interns an application such as `Box<i32>` as a struct row, recording each ref-list
field's element name from the raw applied spelling (`arrElemNameRaw`), so `(Tex | null)[]`
recorded `(Tex | null)`. A declared record's code-5 field records `refArrElemName`'s paren-free
spelling instead, which is the key the ref-list slot was interned under, and the field's slot
lookup on the applied row found nothing. The fix takes the paren-free spelling for a nullable
record element in `gaeEnsure` as well. The type parameter is scenery: the same field written as
`(V | null)[]` and applied at a record reaches the same row once D2525 lets it build.
