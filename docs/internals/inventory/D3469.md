### D3469 — a closure over a type-parameter-assigned nullable map (or set) local that calls `?.has` builds invalid wasm

**check-clean invalid wasm · clause 1 · open · pre-existing, the same on master `c17016a1e` · a sibling of [D3466](D3466.md) found beside it, without its parentheses · filed 2026-10-02 against master `c17016a1e`**

Repro:

    function g<T>(x: T) { let s: {[string]: i32} | null = null; s = x; const ff = () => s?.has("k"); print(ff()) }
    const v: {[string]: i32} | null = null
    g(v)
    // vl check: rc 0.  vl run: invalid module, "expected i32 but nothing on stack"

Want:

    null

#### Mechanism

Not localised past the ablation. The `?.has` over a nullable map is only built in the closure when
the receiver's type is declared; once `s` takes its value from a `T` parameter pinned to the nullable
map, the optional call yields no value where the closure returns it. The same call outside a
closure is a loud emit reject (`if-expression requires an else arm`), and the declared-parameter
spelling runs, so the type-parameter write is the ingredient. [D3466](D3466.md) needs parentheses
and a string receiver; this row needs neither.

#### Ablation

| no closure, `print(s?.has("k"))` | emit reject, `if-expression requires an else arm` | no (a different outcome) |
| `s == null` in the closure | prints `true` | **yes** (the `?.` call) |
| a `Set<string> \| null` local | the same invalid wasm | no |
| a non-null map argument, `Map()` | the same invalid wasm | no |
| `?? false` after the call in the closure | the same invalid wasm | no |
| the call parenthesized, `(s?.has("k"))` | emit reject, `if-expression requires an else arm` | no (a different outcome) |
| `s?.get("k")` in the closure | emit reject, `callee is not a function name` | no (a different outcome) |
| a guard, `if s != null { print(s.has("k")) }` | prints `false` | **yes** (the optional call) |
| `s: string \| null` with `?.includes` | check reject, `member access '?.includes' on non-object _` | n/a |
