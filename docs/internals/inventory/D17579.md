### D17579 — an uncalled maker returning a hole lambda, in a program where any function returns a bundle record, is declined by the IR

**closed 2026-11-26 · was runs today and must keep running, the IR declining the uncalled maker's `return` (`open temp type`, later `convert closure -> i32`) · fixed in ir_build.vl: a hole function's open function result is the closure legacy returns (`resultFrameTy`), not legacy's `i32` descriptor, wherever the type is not held as tagged ids · fixture `tests/cases/closures/uncalled-maker-beside-bundle-record.vl` · the C1 template under `VL_IR_REQUIRE_CLAIM=1` runs 57 of 66, as the default build does · found grading family C's C1 template under the claim, whose prelude declares a second maker no cell calls · filed 2026-11-26 against master `91332bdff` by SOUND**

Repro:

    function lap(f) {
      const _a = f(2.5)
      const _b = f(3)
      return f
    }
    const h = lap((a) => a + 1)
    print(h(1.5))
    print(h(2))
    function __mkd() { return (a) => a * 2 }
    // vl run: 2.5, 3.  VL_IR_REQUIRE_CLAIM=1: the IR declined `(a) => a * 2` in `__mkd` (open temp type)

Want:

    2.5
    3

#### Mechanism

Not traced. The uncalled maker alone (`function __mkd() { return (a) => a * 2 }` and a `print`) is
claimed; beside a function returning a bundle record (D15144's `lap`, or a C1 maker) the IR builds the
uncalled lambda's body with its parameter open. The template
`maker-fresh-lambda-held-at-two-signatures.matrix.vl` declares `__mkd` in its prelude for its second
face, so under `VL_IR_REQUIRE_CLAIM=1` every un-annotated cell that converts reads this refusal.
