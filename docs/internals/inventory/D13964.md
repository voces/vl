### D13964 — a generic call's kept-apart list join bound to a `const` builds the wrong list rep at a `null` pin

**check-clean invalid wasm · open · clause 1 · found beside the Step 6 container-family PR, a sibling of D4862 · filed 2026-10-26 against master `e769fa165`**

Repro:

    function w3<T>(t: T, k: i32, q: (i32 | null)[]) {
      if k == 0 { return [1, 2] }
      if k == 1 { return q }
      [t]
    }
    function g5<T>(t: T, k: i32, q: (i32 | null)[]) {
      const v = w3(t, k, q)
      print(v.length)
    }
    const q3: (i32 | null)[] = [5, null, 6]
    g5(null, 1, q3)
    g5(null, 2, q3)
    // vl check: rc 0.  vl run: invalid module inside `g5` (expected the `i32` list, found `(i32|null)[]`)

Want:

    3
    1

#### Mechanism

Not yet ablated past the table below. At `T := null` the join of `q`'s `(i32 | null)[]` and
`[t]`'s `null[]` is kept apart, and the binding in `g5` builds an `i32`-element list where the
call delivers `(i32 | null)[]`. Called directly at top level (no binding in a generic body) the
same join runs, so the binding's re-type at the pin is where the two reps part. The `T := i32`
pin runs and is what `tests/cases/generics/type-param-list-join-concrete-list-apart.vl` pins;
there the Step 6 container family unboxes `v` at the checker's `(i32 | null)[]`, which is right
only because the instance returns one rep.

#### Ablation

| ingredient changed | outcome | needed? |
| --- | --- | --- |
| `print(w3(null, k, q3).length)` at top level, no generic binding | runs, `3` `1` | **yes** (the binding in a generic body) |
| the `[1, 2]` literal arm removed from `w3` | the same invalid wasm | no |
| `T := i32` (`g5(3, …)`) | runs | **yes** (the `null` pin) |

#### Grading list

Re-grade the container unbox verdict (`identReadContainerAt`) on this witness the day the box
can hold the other list rep: once `v` is a box of two lists, a read typed `(i32 | null)[]`
must dispatch on the tag, not unbox to one arm. Also D13963, D4883 and D4884 (the `if`-bound
faces of the same join), and
`tests/cases/generics/type-param-list-join-concrete-list-apart.vl`.
