### D16395 — `==` over two records of different field sets passes check and is refused at emit

**loud emit reject · clause 1 (`vl check` rc 0) · bucket (e) · probe `scripts/capability-probes/eq-record-wider-vs-narrower-field-set.vl` · found grading D16394's close · filed 2026-11-15 against master `33ef972d7`**

Repro:

    const a: {f: i32, g: i32} = {f: 1, g: 2}
    const b: {f: i32} = a
    print(a == b)
    // vl check: rc 0.  vl run: emit error, `emitProgram: struct equality is not supported yet`

Want:

    true

#### Mechanism

A record with more fields is assignable to one with fewer, so the checker's `==` accepts the
pair, but the emitter's struct-equality lowering compares one row and refuses two. D16394's
field-wise rewrite needs one field set on both sides and leaves this pair alone: which fields a
wider-against-narrower `==` compares (the narrower side's, or "different field sets are unequal")
is a design question the spec does not answer, and the witness is the one spelling both answers
agree on.

#### Ablation

| spelling | outcome |
| --- | --- |
| the witness | check-clean, loud emit reject |
| `b` a fresh `{f: 1}` instead of `a` | check-clean, loud emit reject (want depends on the ruling) |
| `b: {f: i32, g: i32}` | runs, prints `true` |

#### Grading list

- Both orders, `a == b` and `b == a`, and `!=`.
