#### Mechanism

`compiler/ir_verify.vl` checks a lowered function against facts it asks legacy for, instead of
facts the builder recorded on the IR. At I8, with legacy codegen deleted, those queries have
nothing to answer them. The pattern to retire each: the builder records the fact on the IR node,
variable or global as it builds, as `irGlobalNote`/`irGlobalRepOf` does for a global's rep
(#9550). The verifier then checks against that record, and the import goes. The population, from
ir_verify's imports at `5229077b`. The IR rep vocabulary (`emit_rep`'s `R*` nodes,
`repNodeOfTy`), the AST, `symbols` and `check_types` are shared, not legacy queries, and are not
listed.

Retired so far:

- `letBindTy` (rule 2): the builder records each global's storage-row type beside its rep
  (`globalNoteAt` → `irGlobalStoreNote`), and a second, different type for the same global is a
  named miss. Verifier self-test `global-read-off-store-type` shows rule 2 refusing a read neither type justifies.
- `fnFallThroughPadOf` (rule 5): the builder records the end pad on `IrFn.irEndPad` when it starts
  a function, and rule 5 and the lowering's end pad both read that record. The control is the
  falls-off-end self-test: a valued function whose record is "" and whose body does not leave,
  refused under rule 5 as before.
- `objLitArmOf` (`recIsVariant`): `RMakeRec.mrVariant` now says whether the record's row is a
  variant's on every record, not only one built at a destination's row. The builder fills it from the
  arm it already chose (`objLitArmOf` where the literal has no destination row). The verifier's
  field-box check and the lowering read the field.
- `truncSatPlanOf` (`truncSatCheck`): `RTruncSat` carries the plan the builder made, as
  instruction `tsOp`, float prim `tsFrom` and integer prim `tsTo`. The verifier checks the operand
  and result prims against them, and the lowering writes `truncSatTail(tsOp)`.
- `exprEffectFree` (`rhsCheck`, `RToBox`): the builder records on the box whether its delivery
  node has no effect (`bxFree`), and the verifier refuses an immediate box whose node has one. The
  control is the box-immediate-for-call self-test, `bxFree` false, refused under rule 2 as before.
- `memAccessPlanOf` (`memAccessCheck`) and `atomicPlanOf`, `atomicValPrim`, `atomicResultPrim`
  (`atomicCheck`): `RMemAccess` carries its operand count and width prim, and `RAtomic` its operand
  count, each value operand's prim and its result prim, all as the builder planned them. The
  verifier checks the operands and result against those records. The lowering still writes the
  instruction from legacy's plan; that is not the verifier's debt.
- The five SIMD queries (`simdCheck`): `RSimd` carries a load or store's operand count
  (`sdMemBase`), or else each operand's prim (`sdPrims`) and the result prim (`sdResPrim`), as the
  builder read them off the row.
- Each plan family has a refused self-test (`trunc-sat-operand-off-plan`, `atomic-value-off-plan`,
  `memory-store-value-off-plan`, `simd-operand-off-plan`), which holds once the plan agrees.
- The last 16 (this row's close): facts that only legacy's planners know but that the verifier
  needs for a node, a variable or a rep are noted on the function by one builder-side pass,
  `irNoteVerifyFacts` (ir_verify_facts.vl), run before every `irVerify`:
  - `irFactTy` holds the checked type of a global or field read's node;
  - `irFactInt` holds a memory op's voidness, a literal-arms read count, a narrowed map read's
    unbox and a `null`'s kind;
  - `irFactKidTy` holds a record's site type per layout position;
  - `irRepValtype` holds the valtype of each rep compared stored alike;
  - `irVarHeldIds` holds whether an open variable's open parts are held functions.
  `refRepValtype`, `repStoresAs`, `openRepTakes`, `undeclaredRepTakes` and `irTyHeldOpen` move
  with their legacy imports to ir_verify_facts for the builder; the verifier keeps `irTyOpen`,
  `irUntypedClosure` and fact-reading twins.
