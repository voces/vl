### D15627 — two generics written by `.set` as a function field beside a plain field of one un-annotated map's records reach no instance

**loud emit reject · clause 2 · `vl check` rc 0, then `emitProgram: a generic function taken as a value reaches no call that fixes its type — annotate the destination's function type` · the records with the function field alone run since [D15533](D15533.md) · found closing D15533 · filed 2026-11-10 against master `ce2f9fbb`**

Repro:

    function id<T>(x: T): T { x }
    function k2<T>(x: T): T { x }
    const b = Map()
    b.set("k", { f: id, n: 1 })
    b.set("j", { f: k2, n: 2 })
    const bj = b.get("j")
    if bj != null {
      print(bj.f(3))
      print(bj.f("t"))
      print(bj.n)
    }
    const bk = b.get("k")
    if bk != null { print(bk.f(true)) }

Want:

    3
    t
    2
    true

#### Mechanism

Not traced. D15533's close keeps a `.set` record literal at the slot's joined record when a call
through the field re-validates the stored value (`elabSlotRecSetHolds`), but only where every
field of the literal is a set member; the `n` field is not, so the re-validation adapts `k2` to
the call's closed instance as before.
