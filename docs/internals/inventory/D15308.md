### D15308 — a `const` record of one function, assigned into a binding widened to two, is not built at the binding's row

**closed · runs, prints `2` then `2.5` · was a loud emit reject (`emitProgram: cannot take the generic function id2 as a value`), clause 2 · found grading D15306 · filed 2026-11-04 against master `4eaf52bb` · fixed 2026-11-14: a binding read only where it is written (`cwSoleReadInit`, check_write_scan.vl) is a producer of the place: D15306's assignment stamp answers its initialiser's literal through that read (`recSoleReadOfInit`, check_fit_rules.vl), and fn-tag's whole-record write joins the initialiser's literals, re-typing the read and the binding to the holder (`ftWrittenSourceAt`). The bare spelling `const q = id2; let r = id1; r = q` runs too, where the source names a top-level function outside an instanced function (`ftWrittenNamedSource`); a bare source read twice is [D16220](D16220.md), a source declared in another function [D16221](D16221.md). Fixture: `tests/cases/closures/producers-of-fn-widened-holder-built-at-its-row-runs.vl`**

Repro:

    function id1(a) { return a }
    function id2(a) { return a }
    const q = { f: id2 }
    let r = { f: id1 }
    r = q
    print(r.f(2))
    print(r.f(2.5))

Want:

    2
    2.5

#### Mechanism

D15306 builds a LITERAL written into the widened binding at the binding's row. A binding written
in is a record already built at its own row (`q`'s, of `{id2}` alone), and nothing widens the
source to the destination's set. A source whose own field is widened (`let q`, reassigned) runs.

| `const q` → `let q = { f: id2 }; q = { f: id1 }` | runs | **yes** |
