### D17570 — an indexed call straight on a call's returned list of un-annotated functions of two result types is refused: "the call has no one signature"

**loud emit reject · clause 2 · `this call runs functions that return different types … so the call has no one signature` · found by COV-START's Q58 sweep · owner COV-CALL (IR claim; routed by the coordinator 2026-11-25) · filed 2026-11-25 against master `66d6ea2e`**

Repro:

    function inc0(a) { return a + 1 }
    function half(a) { return a / 2.0 }
    function snd(a, b) { return b }
    print(snd(1, [inc0, half])[1](7))
    // vl check: rc 0.  vl run: emit error, the call has no one signature

Want:

    3.5

#### Mechanism

The refusal is legacy's (`emitCallRefAt`, wasmEmit.vl): a call whose set members return different
types, through a set the tag decision left untagged. The set `[inc0, half]` is tagged in no spelling;
the decision's plan refuses it only in the pass before the elaboration (`arrowSetOpen` /
`arrowSetSplit`). The spelling through a binding runs because the IR claims that start body and,
in a function, legacy's let-held path calls through the untagged split set. The direct spelling is
claimed by neither IR path and reaches legacy's refusal. By the coordinator's ruling (2026-11-25)
the close is the IR claiming the indexed call off a call's result (COV-CALL), not a tag-decision
change; legacy is frozen (O3).
