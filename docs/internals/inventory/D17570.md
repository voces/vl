### D17570 — a call through a list of un-annotated functions of two result types, at any index no constant fold resolves, is refused: no per-member dispatch through an untagged split set

**loud emit reject · clause 2 · `this call runs functions that return different types … so the call has no one signature` · found by COV-START's Q58 sweep · owner COV-CALL · parked until after I8 (coordinator, 2026-11-25) · filed 2026-11-25 against master `66d6ea2e`**

Repro:

    function inc0(a) { return a + 1 }
    function half(a) { return a / 2.0 }
    function snd(a, b) { return b }
    print(snd(1, [inc0, half])[1](7))
    // vl check: rc 0.  vl run: emit error, the call has no one signature

Want:

    3.5

#### Mechanism

The refusal is legacy's `emitCallRefAt` (wasmEmit.vl). A call through a set whose members return
different types, left untagged, has no one signature (`cloCallSigKey` is empty), and nothing
dispatches it per member. The IR declines it in the same place (`indirect call: no key`), since its
closure call takes legacy's key. The spellings that run never call through the set. In
`const l = snd(…); l[1](7)` and `[inc0, half][1](7)`, the read is resolved to the declaration before
emit, and both emitters write a direct `call $half` (measured by COV-CALL on master `4fbb6097`, in a
function and at module scope). That fold needs a constant index into a list it knows, so any other
index meets the refusal. The close is a per-member dispatch through an untagged split set, each
member instanced at the call's argument types. It is a clause-2 capability that does not block I8:
these programs refuse before and after I8 alike (coordinator ruling, 2026-11-25).

#### Grading list

- `snd(1, [inc0, half])[1](7)` and `snd(1, [inc0, half])[0](7)`, at a `const`, an argument and an

- The let-held spelling inside a function, which the IR declines on `uncovered declaration coercion`.
