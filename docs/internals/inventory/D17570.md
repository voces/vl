### D17570 — an indexed call straight on a call's returned list of un-annotated functions of two result types is refused: "the call has no one signature"

**loud emit reject · clause 2 · `this call runs functions that return different types … so the call has no one signature` · found by COV-START's Q58 sweep · owner SOUND · filed 2026-11-25 against master `66d6ea2e`**

Repro:

    function inc0(a) { return a + 1 }
    function half(a) { return a / 2.0 }
    function snd(a, b) { return b }
    print(snd(1, [inc0, half])[1](7))
    // vl check: rc 0.  vl run: emit error, the call has no one signature

Want:

    3.5

#### Mechanism

Not established. The same list read through a binding first (`const l = snd(1, [inc0, half]);
l[1](7)`) runs and prints `3.5`, and so does the direct spelling when both functions return one
type. The refusal (wasmEmit.vl) fires where the indexed callee is a call's result, whose set is held
at no place the call through it can store a function of either result at.

#### Ablation

All under `VL_IR_STRICT=1` on master `66d6ea2e`.

| spelling | outcome |
| --- | --- |
| `snd(1, [inc0, half])[1](7)` | refused |
| `id([inc0, half])[1](7)` | refused |
| `snd(1, [inc0, dbl])[1](7)` (one result type) | runs, `14` |
| `const l = snd(1, [inc0, half]); l[1](7)` | runs, `3.5` |
| `snd(1, [inc0, half]).length` | runs, `2` |

#### Grading list

- The direct call at a `const`, an argument and an interpolation hole.
