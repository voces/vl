### D2636 — `vl run` has no way to supply an `extern let` / `extern const` global, so a program that declares one can only run after a hand-linked build

**open — the witness runs today and must keep running; the gap is in the host CLI, which had no way to give an extern global a value, and is graded by `tests/vl_extern_global_test.ts` · plumb PL-046 (reported by plumb) · filed 2026-09-26 against master `50c627ce4`**

Repro:

    function add(a: i32, b: i32): i32 { a + b }
    print(add(2, 3))
    // runs, prints `5`. Add `extern let CTXB: i32` at the top and `vl run` stops at load with
    // "extern global `CTXB` is declared but `vl run` provides no globals", with no flag to
    // supply it, although nothing reads `CTXB`.

#### Mechanism

`register_extern_imports` in `scripts/vl-host/src/main.rs` refuses every `global` import in the
`extern` namespace. The refusal is right without a value (a zero nobody set is what the extern
contract exists to prevent), but the CLI offered no way to give one, so plumb's tests that
import `src/rt.vl` needed `vl build`, a hand-written WAT, `wasm-as` and `wasm-merge` before
`vl run`.
