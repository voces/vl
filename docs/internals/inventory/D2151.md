### D2151 — a `{f: "x"}` literal sharing the row a literal-union field minted prints through a type with no member texts

**closed 2026-09-23 — the witness prints `green` twice · was a loud emit reject (`print of a literal-union atom whose type carries no member texts`) at the written-alias spelling, clause 2 · filed 2026-09-23 against master `b5debe165`, exposed to inline sets by D2150 · fixture `tests/cases/literal-unions/anon-holder-inline-litunion-field.vl`**

Repro:

    type KZ = "red" | "green"
    const srcArr: KZ[] = ["green", "red"]
    const w1 = { f: srcArr[0] }
    print(w1.f)
    const w7 = { f: "green" }
    print(w7.f)

#### Mechanism

`w7`'s literal name-matches the anonymous row `w1` minted, whose field is an atom (`anonValueFitsField`
admits a member literal into an atom slot), so its read is claimed an atom. The widen then asked
the read's own recorded type for member texts, and that type is `string`. `litAtomWidenTexts` now
falls back to the row's own field sidecar (`memberAtomFieldTexts`): the row, not the read's type,
names the members of the value the row stores.

#### Grading list

The same literal read inside a function, through a closure, and as a list element's field.
