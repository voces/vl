### D16530 — a literal-union value copied off a hole parameter, narrowed by `==` to one member, reads `??` as a string ref

**closed 2026-11-15 — the filed program RUNS and prints `green` · was check-clean invalid wasm, clause 1 (`vl check` rc 0, `type mismatch: expected (ref $0), found i32; $0 is `string``), the same on master `d01496801` · fixed in `emitCoalesceGo` (`wasmEmit.vl`) · `inline-litunion-nullable.matrix.vl` runs 66 of 66, 65 before · the un-annotated `argument` cell, reported by lane L · filed 2026-11-15 against master `ab210efa2`**

Repro:

    function pick(n: i32): "red" | "green" | null {
      if n > 1 { return null }
      if n > 0 { return "green" }
      "red"
    }
    function __take(a) {
      const v = a
      if v == "green" { print(v ?? "none") }

    // vl check: rc 0.  vl run: prints green (was: invalid module, expected (ref $0) `string`, found i32)

#### Mechanism

The literal union reps as an `i32` atom. Inside the hole function, the local copy `v`
narrowed by `== "green"` is handed to `??` as if it were already the string `"green"`, but
the atom was never widened to a string ref; `??` on the parameter itself, or on an
annotated parameter's copy, widens it. From the ablation; the instance's locals have not been
printed.

#### Grading list

`inline-litunion-nullable.matrix.vl`'s un-annotated `argument` cell (must print `green`), and the

#### Closed

The copy's type is the hole, so `emit_rewrite` cannot fold `v ?? d` the way it folds the concrete
spelling, and `emitCoalesceGo` folds it per instance where the left closes to a type with no
`null`. That fold emitted the left at its own rep, the `i32` atom, where the `??` reps as a `string` or
as the box of a join with another type. It now hands the atom to `emitAtomToStr` or
`emitUnionBoxArg` at the `??`'s instance type. The named set
`d16530-litunion-copy-coalesce-fold` holds the witness, the `let`, alias, non-nullable, miss,
`string`-destination and `?? 5` spellings, and the no-copy control.
