### D16037 — an inferred nullable `Set` return floors at check, while its annotated twin runs

**loud check reject · clause 2 · `'pick' infers the nullable return type Set<i32> | null — type-valid, but an inferred return of this shape is not yet supported by codegen; annotate the return type` · the `unsupported-lowering` channel tests' witness since D1108 landed · filed 2026-11-13 against master `110eace0`**

Repro:

    function pick(c: boolean) {
      if c { return null }
      const m: Set<i32> = Set()
      m
    }
    const r = pick(true)
    if r == null { print(0) } else { print(1) }

Want:

    0

#### Mechanism

`nullableRetName`'s map arm (compiler/check_fit_rules.vl) names a nullable map return only when
`mSet == 0`. A `Set` gets no name, and the floor reads that as "no rep exists". D1108 widened
the arm's key kinds to `i32` and `i64`, but left the `Set` out. An annotated
`: Set<i32> | null` runs, so this is a capability gap. It is the witness of
`tests/selfhost_native_diag_code_test.ts` and `tests/lsp_wasm_checker_test.ts`: closing it moves
them a seventh time.
