### D17764 — a returned function value at an annotated closure destination and an un-annotated one is built at one signature and called at the other

**closed 2026-11-28 by lane START-2 — the witness prints `4.5` · with two call sites no one destination chooses the result's layout: the result keeps the set's id, and a fresh one-field record call result delivered to a closed function field is copied there, `{ f: site.f }`, then delivered as a hand-written literal is, so its field is coerced (`fvaRecFnCopy`) · fixture `tests/cases/functions/returned-record-fn-value-converted-at-annotated-destination.vl` · the list form stays open as [D17776](D17776.md) (its copy waits on [D17775](D17775.md)), and a record of two fields as [D17777](D17777.md) · was: loads then traps · clause 1 · filed 2026-11-27 against master `3bdd59b14`**


Repro:

    function id(a) { return a }
    function deliver() { return { f: id } }
    const v: { f: (a: f64) => f64 } = deliver()
    const u = deliver()
    print(v.f(2.5) + u.f(2))
    // vl check: rc 0.  vl run: wasm trap: indirect call type mismatch

Want:

    4.5

#### Mechanism

A function value may be read at two signatures: ids dispatch per instance, and a closed
destination coerces the value to its closure (`fnCloCoerce`), as `const v: (a: f64) => f64 = r.f`
beside `r.f(2)` already runs. Here the result of a function called twice takes the annotated
destination's layout: `id`'s one closure (its `i32` default instance) is held where the IR types an
`f64` closure (the record form), or `deliver`'s returned literal is minted at the `f64` row by name
on a later intern pass and stored as it stands into the un-annotated binding's open cell (the list
form). The rule (coordinator ruling, 2026-11-27): with two or more call sites no one destination
chooses the result's layout; the result is the join, and each annotated destination converts its
fresh value.

Why no guard: a refusal by representation alone loses programs that run. An open-closure → closed
retag test refuses `[id]` delivered beside its un-annotated twin (prints `4.5`) and the single
reads (`2.5`, `2`); a test of the closure value against its instance's own signature fails ten
`tests/cases` (`dead-nested-call-through-binding.vl`, `list-element-handed-to-hole-at-two-types.vl`,
`hole-lambda-to-two-generics-one-param-name.vl`, `stored-hole-fn-default-body-refuses-i32.vl`,
`tail-call-through-capture-cell.vl` among them), whose instance signature is not the one called.
