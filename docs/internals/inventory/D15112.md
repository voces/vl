### D15112 — an un-annotated lambda in a generic body that builds a list of its parameter refuses at emit once two instances type the parameter differently

**loud emit reject · clause 2 · open · 0 corpus cells · filed 2026-11-03 against master `2fc6eddc6`, pre-existing (same on master and S2c, split plan on and off) · found writing D3955's neighbour for S2c's floor deletion**

Repro:

    function a<T>(x: T) {
      const k = (u) => { print([u].length) }
      k(x)
    }
    a(1)
    a(true)
    // vl check: rc 0.  vl run: emitProgram: '.length' on a receiver the emitter cannot classify as a list, string, map or set

#### Mechanism

The lambda is cloned per instance, but the list literal `[u]` in its body takes no element type
from the clone's parameter. So the `.length` (or an index `[u][0]`, which gives `index receiver
is not an array or string`) reads a receiver that has no list rep. It is not the capture, the
`let`, or the D15110 sharing: a direct `k(x)` refuses the same way.

#### Ablation

| ingredient removed | outcome | needed? |
| --- | --- | --- |
| the second instance (`a(true)`) | runs, prints `1` | **yes** |
| the second instance at the same type (`a(2)`) | runs | **yes** (two reps) |
| the parameter's missing annotation (`u: T`) | runs | **yes** |
| the closure `rd` capturing `k` | still refuses | no |
| `let` (`const k`) | still refuses | no |
| `.length` for `[u][0]` | still refuses (index message) | no |
