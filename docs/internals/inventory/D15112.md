### D15112 — an un-annotated lambda in a generic body that builds a list of its parameter refuses at emit once two instances type the parameter differently

**closed 2026-11-03, runs with the split plan on and off, prints `1`, `1` · was a loud emit reject, clause 2 · the template check's hole rows for the lambda were keyed under every instance of `a`, so each instance held both pins and the clone's key was ambiguous; a template row now fills only an instance whose own walk banked no row for the lambda (`elabDrainHoleRows`) · fixture `closures/hole-lambda-list-of-param-at-two-instance-types.vl` · named set `d15112-template-row-cross-key` · filed 2026-11-03 against master `2fc6eddc6`, pre-existing · found writing D3955's neighbour for S2c's floor deletion**

Repro:

    function a<T>(x: T) {
      const k = (u) => { print([u].length) }
      k(x)
    }
    a(1)
    a(true)
    // prints 1, 1

#### Mechanism

The lambda is keyed per instance of `a` (S2a). Each instance's own walk banks a hole row for it, at
`u = i32` under `a<i32>` and `u = boolean` under `a<boolean>`. The template check banks the same pins
again as rows with no instance (`from < 0`), and `elabDrainHoleRows` keyed every such row under every
instance of `a`. So each instance held both pins, which made two cross keys (`T = i32`, `u = boolean`
and the reverse). `elabKeyAt` then had two kids to choose from under the instance, and answered -3.
The clone's `[u]` therefore had no per-instance type, and `exprListRep` found no list.

The fix is in the producer. A template row of a per-encloser lambda is no longer keyed under an
instance whose own walk banked a row for it (`elabOwnHoleRows`, marked as the rows drain). An
instance with no row of its own still takes the template rows, as before.
