**now a loud check reject, `print expects one scalar or string value (…), got i32[] — … (in `lap`, at one of the instances it calls a function argument at)` — fixed 2026-10-18 by lane L3: the hole-instance judgement takes each `print` over a hole call's result at each instance, as it takes each binary operator ([D6300](D6300.md)) · was loud emit reject, `vl check` rc 0, clause 2 · pin: `tests/cases/functions/error-hole-call-print-list-at-instance.vl` (the witness, a lambda literal, a `const x = g(1)` binding printed) · found closing [D6330](D6330.md) · filed 2026-10-18 against master `b48acada7` on lane L3's `l3-d6300` base `25d98fe9c`**

#### Mechanism

From the ablation only. With one instance the print of `g(1)` is judged against the pinned
result type and refused. With two, the instance machinery judged only binary operators over
the calls' results, so the `i32[]` print reached the monomorphizer, which cannot pin either
instance. The program is ill-typed at the `i32` instance; the checker owes the refusal.
