### D2016 — calling a SELF-REFERENTIAL function-typed field (`cb: (Ev) => i32`) on a narrowed union arm refuses at emit

**open · loud emit reject, clause 2: `vl check` rc 0, then `emitProgram: callee is not a function name` · found in review of D1999's fix · filed 2026-09-22 against master `5cd558915`**

Repro:

    type Ev = { kind: "a", cb: (Ev) => i32 } | { kind: "b", n: i32 }
    const e: Ev = { kind: "a", cb: (_x: Ev) => 7 }
    if e.kind == "a" {
      print(e.cb(e))
    }
    // vl check: rc 0.  vl run: emitProgram: callee is not a function name (5:1)

#### Mechanism

Not yet probed. Both ingredients are needed — the field's function type names the union it
is declared in, AND the receiver is a narrowed arm of that union — so the call-through-field
path resolves the callee for a closure field on a plain struct and on a narrowed arm whose
field type is not self-referential, and loses it only when the two meet.

#### Ablation

| ingredient changed | outcome |
| --- | --- |
| as filed | emit reject, `callee is not a function name` |
| `cb: (i32) => i32` (not self-referential), same union and narrowing | runs, prints `7` |
| `cb: (Ev) => i32` on a one-arm struct, no union | runs, prints `7` |
| `const c = e.cb` then `c(e)` inside the narrowing | emit reject, a different message: `field access but no struct type declared` (4:15) |
