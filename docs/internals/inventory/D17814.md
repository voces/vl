### D17814 — a lambda written into a holder `let` of a maker's two-signature record is not built beside the maker's own lambda

**loud emit reject · `the compiler cannot yet lower this statement (bundle result pick refused)` · clause 2 · open · `vl check` rc 0 · a named generic or hole-parameter function written there runs ([D17804](D17804.md)) · filed 2026-11-28 against master `d76847374` · owner COV-IS**

Repro:

    function lap(f) {
      const _a = f(2.5)
      const _b = f(3)
      return f
    }
    let k = lap((a) => a + 1)
    k = (a) => a
    print(k(3))
    // vl check: rc 0.  vl run: emit error at `let k = lap(...)` (bundle result pick refused)

Want:

#### Mechanism

D17804's close counts a holder's plain named-function writes as its writes; a lambda is left out.
Counted (the WIP on branch `cov-is-d17814`), it is registered as a producer of the maker's record,
but three elab paths each also instance every function written to the binding at the binding's own
call types (`(i32)` here), competing with the producer: `elabSetCallRows` (a call through a set
reaches every member), `elabAnnotatedDeliveryRows`' write branch (a whole write instanced at the
binding's call arguments) and `elabCellPeers` (values in one cell instanced alike). The stray
`(i32)` instance leaves the producer's bundle instance unfound (`bundle argument closure`).

**Refactor target** (coordinator ruling 2026-11-28): three instancing paths deciding one question is
a one-reader violation. The close is one structural predicate all three consult, "a write into a
record holder is built as the holder's record". A guard on the producer list is not enough: each
path keys its facts at a different point of `elabRun`, before the holder's producers are recorded.
Guards on the first two alone (`elabResCallHolder`, in the WIP) are a partial rung and do not land.
