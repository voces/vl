### D15638 — a hole function called directly at one type and handed on as a record literal's field to a callee that calls the field at another is refused by the checker

**loud check reject · clause 2 · `argument 1: expected i32, got string (the call of a function value at the call's argument types)` · without the direct call it runs, and the list spelling runs since [D15609](D15609.md) · found closing D15609 · filed 2026-11-10 against master `7b499846`**

Repro:

    function id(v) { return v }
    function call0(r, x) { print(r.f(x)) }
    function run(g) {
      print(g(5))
      call0({ f: g }, "s")
    }
    run(id)

Want:

    5
    s

#### Mechanism

The same as D15609's: `holeBindInstance` sees only the direct call `g(5)`, because the walk does
not follow `g` into the record literal, and so it pins `id` at `(i32) => i32`. D15609's fix
covers list literals only, the hand-on the elaboration forwards (`elabLitFwdTargets`). Whether
the elaboration follows a record field has not been tried.
