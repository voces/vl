#### Fix

`assignTags` (`compiler/emit_collect.vl`) anchors the discrimination refusal at the union's
declaration, which the union registry already records (`unDeclIx`). `monoInstantiate`
(`compiler/emit_mono.vl`), the one entry that has the call being instantiated, arms the
statement cursor at that call for the span of the instantiation and restores it after, so every
`monomorphize:` refusal raised inside names the call (`take(id)`, line 8). The two cases are
in `tests/vl_emit_diag_position_test.ts` again, beside the instance case that shows the cursor
does not outlive the instantiation.

#### Mechanism

The refusal `union \`U\` cannot be discriminated` ([D15150](D15150.md)) is raised after
`collectU`'s and `collectS`'s declaration loops have cleared the cursor D1519 arms, so
`emitFail` has nothing to anchor at and the host prints the file alone. It is the collect
phase's only refusal a check-clean program is known to reach: with D15098 closed, no other
witness for that phase carries a position.

When this is fixed, the refusal should name `U`'s declaration, line 5, and D15150's witness is
the collect-phase case of `tests/vl_emit_diag_position_test.ts` again; if D15150 closes first,
this row needs another collect-time refusal as its witness.

A second refusal has no position for the same reason: `monomorphize:` refusals raised while
instances are planned, before any body is lowered, run with neither cursor armed. A hole
parameter called at two function types through a generic (`function take<T>(a: T)` calling
`a("abc")` and `a(2)`, handed `id`) prints `at <file>` alone.
