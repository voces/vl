### D2669 — a string append outside any loop, reached from a caller's loop, copies the whole string every call

**runs today and must keep running · the witness runs; the defect is its cost (quadratic: 40,000 calls take 0.65 s, where the same append written in the loop takes 0.03 s) · found closing [D2625](D2625.md) · filed 2026-09-26 against master `ea661d2d7`**

Repro:

    import { toString } from "std:fmt"
    type B = { s: string }
    function add(o: B, k: i32) { o.s = o.s + " $t" + toString(k) }
    function build(nt: i32): string {
      const o: B = { s: "" }
      for k in 0 until nt { add(o, k) }
      o.s
    }
    print(build(40000).length)
    // prints 308890, in 0.65 s; the same append written inside the loop takes 0.03 s

#### Mechanism

The site-cached append ([D2625](D2625.md)) keeps its buffer and frontier in two LOCALS of the
function holding the site, so they live one call: `add`'s cache is empty on every entry and each
call would copy the whole string anyway, which is why a site outside a loop of its own function
is not lowered that way at all. The fix is module-lifetime storage for a site's cache — a pair
of globals, or one table global indexed by site — which the emitter cannot mint today: the
global section is written before any body is lowered, and knowing the site count first needs a
typed pre-pass over every function.

#### Ablation

| ingredient removed | outcome | needed? |
| --- | --- | --- |
| the helper (the append inside the loop) | linear | **yes** |
| the field (a module global `out = out + …` in the helper) | quadratic | no — the same gap |

#### Grading list

A helper appending to a module global (`function emit(x: string) { out = out + x }`), and to a
field of a parameter; plumb's `src/emit.vl` `indent(st)` is this shape (short strings, no cost today).
