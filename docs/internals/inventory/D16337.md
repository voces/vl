### D16337 — an un-annotated lambda literal at a generic's function-typed parameter that nothing calls and no other argument binds is refused at monomorphization

**loud emit reject · clause 2 · open · bucket (c), L2 inferred interfaces: with an inferred interface the literal's parameter takes `A` and needs no pin, where the argument-pin ladder gives a literal no name · `vl check` rc 0 · `emitProgram: monomorphize: unsupported argument type for `f` in a call to `cnt`` · beside [D16412](D16412.md), whose parameter escapes · found ablating D16412 · filed 2026-11-15 against master `a735a8b6`**

Repro:

    function cnt<A, B>(f: (x: A) => B): i32 { return 7 }
    print(cnt((x) => x + 1))
    // vl check: rc 0.  vl run: emit error, monomorphize: unsupported argument type for `f` in a call to `cnt`

Want:

    7

#### Mechanism

The literal's parameter is a hole, so its type at `(x: A) => B` names an open `A` that nothing at
the call binds. `cnt` never calls `f`, so no instance needs `A` either. A named un-annotated
function at the same parameter runs. So does the same lambda bound to a `const` first: it is
hoisted into a function the argument-pin ladder names (`monoArgFnTypeName`, emit_mono.vl). A literal
gets no such name, and the ladder refuses (`monoArgTyFail`). `monoInertParamStubPin`, which stubs
an argument a parameter never calls, is asked only at a bare type-parameter parameter (`f: T`).
