### D5922 — an inferred return of a nullable union mixing a literal with a type member is floored by the checker, though the annotated return runs

**closed 2026-10-17 by lane L3 · runs, prints `false` · was loud check reject · clause 2 · pre-existing, the same on master `60c4d1c43` · the value-box leaf test (`litScalarBoxLeaves`, `check_ty_rep.vl`) treats a `null` variant as the box's null tag, so the floor names the box for the emitter · pin: `tests/cases/unions/inferred-nullable-mixed-litunion-return.vl` · found by the `nullable-mixed-litunion-type-member-match` position matrix (`return_inferred`, both faces) · filed 2026-10-17 against master `f619864ee`**

Repro:

    function pick(n: i32): "a" | i32 | null {
      if n > 1 { return n * 10 }
      if n < 0 { return null }
      "a"
    }
    function get() { return pick(3) }
    const v = get()
    if v != null { print(v == "a") }
    // vl check: 'get' infers the nullable return type "a" | i32 | null — type-valid, but an
    // inferred return of this shape is not yet supported by codegen; annotate the return type

Want:

    false

#### Mechanism

The nullable arm of the inferred-return floor admits a `K | null` whose inner is a literal union
or a value union it can name for the emitter; a literal beside a type member is neither, so the
floor fires. The same family as [D4160](D4160.md) and [D2568](D2568.md), at a mixed spelling.
The non-nullable `"a" | i32` inferred return runs at every position of
`mixed-litunion-type-member-match`.
