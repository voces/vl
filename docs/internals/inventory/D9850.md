#### Mechanism

The destination `v` carries no annotation, so its type comes from its calls. Each call pins
`v` at the argument types it passes, and a lambda is pinned as a function value, not as
`((x: i32) => i32) | null`. The pin therefore names no instance of `g`. The copy of the return
(`monoCoerceRetAtPin`) found no instance to take, and the generic stayed unfixed. The same
held for any parameter that admits `null`, such as `string | null` or a record `P | null`
passed a record. The close binds the declared parameter types against every pin. When they
agree on one closed signature, and it differs from a pin only at a parameter that admits
`null`, it takes that instance and retypes the calls.
