#### Mechanism

The checker resolves a callee lexically, so `g` above denotes `tak`'s parameter — a function
value, and `TyFunc` carries no parameter names. Its named-argument arm asked a different
question: `fnParamNamesOf(cfn.identName)` read `fnDeclIx`, the flat map of TOP-LEVEL
declarations with no scope walk, found the module `function g`, and matched `alpha` against
that declaration's parameter list. `vl check` returned 0 and the emitter refused the same
call, which is a clause-2 violation by construction.

Only the unrelated declaration's parameter NAME decided it. Renaming it to `beta` made the
program a type error, and deleting the module function made it the refusal the design owes —
three answers for one call. The scope-aware resolver already existed (`lookupFnDeclNode`, and
`calleeDeclParams` over it, which the same arm's default-arity relaxation already used one
screen above), so the fix is to read the names off the declaration that resolver returns:
`paramNamesOfNodes(dParams)`. This is D1602's shape one layer earlier — that row fixed the
emitter's five by-name callee resolutions; this one is the checker's.

The caller audit found two more by-name sites that decide a call rather than word a
diagnostic, and both are fixed here:

* **the UFCS arity range.** `ufcsCallTy` read `declParamsAfterSelf(name)` by name, so the
  module function's DEFAULTS filled a missing argument in a call through a shadowing binding.
  `function ld(self: {v: i32}, k: i32 = 5)` beside `function go(b, ld: ({v: i32}, i32) => void)
  { b.ld() }` was check-clean invalid wasm — a clause-1 face of the same mechanism, now
  `declParamsInScope`. The UFCS named-argument arm read `fnParamNamesOf(name)` the same way.
* **the unimplemented-memory-intrinsic refusal.** `checkCallNode` gated on
  `fnDeclIx[name] < 0`, so a top-level `function __store_string__` kept its meaning but a
  PARAMETER of that name did not: calling it refused a legal program. Now gated on the callee
  still denoting the default-scope binding (`lookupDepth == 0`).

`declFirstParamIsSelf` stays by name deliberately. It is the UFCS dispatch GATE, not an arity
or naming decision, and making it lexical turns `b.ld(3)` through a shadowing closure binding
from `runs` into `no field 'ld'` — a `runs` cell lost for a question the design has not
answered. Residue below.

`declFirstParamIsSelf` still answers by name, so a UFCS call whose callee a closure binding
shadows dispatches when a same-named module `self`-function exists and refuses `no field` when
none does. Both spellings run through the BINDING once dispatched, which is lexically

`runs` cell either kept or lost, so it needs one before the gate moves.
