### D2792 — `f<T>(v: T, u: T | string)` at a record `T` and a string argument emits an invalid module

**closed 2026-09-27 — the filed repro RUNS and prints `4` · was check-clean invalid wasm · clause 1 · found by #3208's review · closed in #3208 with D2734: the union parameter is minted at the bound `T`, and a union with a record or reference-list arm is registered at the pin · filed 2026-09-27 against master `781f68091` · fixture `tests/cases/generics/pin-inferred-from-union-argument.vl`**

Repro:

    type R = {a: i32}
    function f<T>(v: T, u: T | string): T { v }
    const y: R = {a: 4}
    print(f(y, "q").a)
    // PRINTS 4

#### Mechanism

`T` binds to `R` from `v`, and `u`'s pin `R | string` is a union the pin mints. The mint was gated
on the ARGUMENT's type (`string`), which holds no reference arm, so the union was never
registered and the caller boxed `"q"` into an unknown row. The gate now reads the parameter's
type at the call's bindings (`monoBindBareArenaPins`), and a list of references counts as a
reference arm (`monoTyIsRefArm`), so `f<R[]>("q")` at `T | string` registers too.
