### D3544 — `is string` over a nullable single string literal (`"s" | null`) is refused as "not a variant", while `"a" | "b" | null` is accepted

**closed 2026-10-03 — the witness prints `str` then `null` · was a loud check reject, clause 2 · found by the #3345 review · filed and closed by lane LC against master `f6e17953b` · fixture `tests/cases/unions/litunion-is-base-type.vl`**

Repro:

    function g(x: "s" | null) {
      if x is string { print("str") } else { print("null") }
    }
    g("s")
    g(null)
    // vl check: "`is` check type 'string' is not a variant of "s" | null"

Want:

    str
    null

#### Mechanism

Confirmed: one line. `litBaseMeetTy` (D3522) took the base of a nullable as its inner type and
then required a union, so `"s" | null` (a nullable over one literal) and `1 | null` fell
through while the two-literal set passed. It now accepts a single literal as the base too. The
same line answers the non-nullable `x: "s"`, which was refused as "`is` check type 'string' can
never match a value of type "s"": false, since the test is always true, and now runs.

#### Ablation

| ingredient changed | outcome | needed? |
| --- | --- | --- |
| `"a" \| "b" \| null` | runs (since D3522) | **yes** (a single literal) |
| `x: "s"` (no `null`) | was refused, "can never match" | no (same line) |
| `1 \| null`, `is i32` | was refused | no (same line) |
