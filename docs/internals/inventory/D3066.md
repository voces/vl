### D3066 — a hole function's list literal of its parameter at a boxed pin builds an `i32` list outside a binding or `for`-in

**check-clean invalid wasm · clause 1 · open · found grading D3014 (the residue its close does not reach) · the same on master `6c2dafc0b` · filed 2026-09-28 against master `6c2dafc0b`**

Repro:

    function f(x) {
      print([x].length)
    }
    const v0: i32 | null = 2
    f(v0)
    // vl check: rc 0.  vl run: invalid module inside `f`, expected i32, found (ref $type)

Want:

    1

#### Mechanism

A hole instance shares its template's expression nodes, so `[x]` keeps the recorded type `T[]`
over the hole's variable and every list classifier answers the unpinned `i32` list; the literal
builds an `i32` backing around the parameter's box. The monomorphizer re-makes such a literal at
the instance type only where it is a binding's initializer (`monoHoleListLitCopy`) or a for-in
iterable (`monoHoleIterLitCopy`, D3014), because `monoCloneBody` walks statements and not
expressions. An argument to an annotated parameter runs, because the parameter types the build.

#### Ablation

| ingredient changed | outcome | needed? |
| --- | --- | --- |
| `const l = [x]` then `print(l.length)` | prints `1` | **yes** (no binding) |
| `for e in [x]` | prints `2` | **yes** |
| `print([x][0])`, `[x].slice(0)`, `[x].filter(…)` | invalid wasm | no (the same defect) |
| `g([x])` into `g(l: (i32 \| null)[])` | prints `2` | **yes** |
| `function f<T>(x: T)` | prints `1` | **yes** (the hole) |
| a non-null `i32` pin | prints `1` | **yes** |

#### Grading list

The `lit_len`, `lit_idx`, `lit_slice` and `lit_filter` shapes at every nullable and boxed pin
(`i32 | null`, `f64 | null`, `1 | 2 | null`, `string | null`), single and paired with a second
instance at a scalar pin.
