### D2243 — `?.` into a nullable value-union field of a nullable record, then `??`, is check-clean invalid wasm

**check-clean invalid wasm · clause 1 · filed 2026-09-23 against master `f2234c2e5` · found by the #3077 reviewer**

Repro:

    type I = { a: i32 | null }
    const o: I | null = { a: 3 }
    print(o?.a ?? 8)
    // vl check: rc 0.  vl run: the emitted module failed to validate inside the module's top-level code: type mismatch: expected i32, found (ref $type)

#### Mechanism

Not yet ablated. The validator sentence says an `i32` was expected where a reference was
produced, which fits the `?.` result (`i32 | null`, a boxed nullable value) reaching `??` on
a path that reads it as the bare `i32` — a prediction, not a measurement. Two ingredients
measured at filing: the NULLABLE receiver is needed (`const o: I = …` with `o.a ?? 8` runs,
printing `3`), and the global is not (the same three lines inside a function fail the same way).

#### Grading list

A `string | null` field, and `o?.a` bound to a `const` before the `??`.
