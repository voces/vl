### D17756 — pushing an un-annotated map of two generic functions with different results into a list of union-result function maps reaches the i8 stub

#### Mechanism

Design, ruled by the coordinator (2026-11-27): it RUNS. Generic writes leave the map's function
slot without a closed type of its own, so the closed destination it is delivered at whole fixes
it, as annotating the map at that type does (that spelling prints `1.5`). Non-generic members stay
refused: the first `set` closes the slot. Diagnosis (COV-CALL, branch `cov-call-d17756`, not
landed). Check: `ctnWrittenCstrsAt` (check_assignable.vl), the list-literal and annotated-`let`
re-check, judges each write against the map's own slot at the destination's bindings
(`(i32) => i32`, from `__id`), not against the destination's value type, while `.push` never
runs it; that branch accepts a write fitting the destination's slot, so both spellings pass.
Emit: both then refuse, because `elabSlotFacts` (emit_elab.vl) takes a holder's slot fact only
from the values written; a whole un-annotated holder delivered to a closed destination must take
that destination as its fact, for `monoPinMapValues` to instance each write there. A first cut
(record the delivery in `ctnWrittenCstrsAt`, prefer it in `elabSlotFacts`, accept it in
`monoPinMapValues`) did not reach it; it is not landed. Both halves land in one PR (I8-PREP, as a
D17729 delivery position).

Stop point (I8-PREP, 2026-11-27, branch `d17756-map-slot`, time-boxed, not landed). On top of
that first cut: the held-type reader `letDeliveredSlotTy` (emit_classify.vl, shared with D17729's
list rung) holds and shapes the map at its delivered destination (`letHeldTyOf`, `letMapShapeOf`),
and `ctnWrittenCstrsAt` banks each generic function written into the map at the destination's
slot (`fvaValueRowAt`, every write in `ctnWrRecv`, since BM rows hold only constrained ones). The
list-literal spelling then passes the map store and refuses at the write's own value,
`a generic function taken as a value reaches no call that fixes its type`: the argument `__id` of
`__fm.set("a", __id)` stays typed at its open `(T) => T`, where the annotated spelling's check types
it at the slot. What is left is stamping each write's value at the delivered slot (or the IR
reading the slot fact there). Only the widened result needs this: with one result type
(`(x: i32) => i32`) the literal, `.push` and annotated-`let` spellings all run today. The `.push`
spelling still reaches `i8 stub emitExpr`; the one-member spelling still reaches
`monoPinMapValues`; `const y: <closed map> = __fm` refuses `global initializer coercion`.
