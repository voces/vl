#### Mechanism

Design, ruled by the coordinator (2026-11-27): it RUNS. Generic writes leave the map's function
slot without a closed type of its own, so the closed destination it is delivered at whole fixes
it, as annotating the map at that type does (that spelling prints `1.5`). Non-generic members stay
refused: the first `set` closes the slot. Diagnosis (COV-CALL, branch `cov-call-d17756`, not
landed). Check: `ctnWrittenCstrsAt` (check_assignable.vl), the list-literal and annotated-`let`
re-check, judges each write against the map's own slot at the destination's bindings
(`(i32) => i32`, from `__id`), not against the destination's value type, while `.push` never
runs it; that branch accepts a write fitting the destination's slot, so both spellings pass.
Emit: both then refuse, because `elabSlotFacts` (emit_elab.vl) takes a holder's slot fact only
from the values written; a whole un-annotated holder delivered to a closed destination must take
that destination as its fact, for `monoPinMapValues` to instance each write there. A first cut
(record the delivery in `ctnWrittenCstrsAt`, prefer it in `elabSlotFacts`, accept it in
`monoPinMapValues`) did not reach it; it is not landed. Both halves land in one PR (I8-PREP, as a
D17729 delivery position).

Stop point (I8-PREP, 2026-11-28, branch `d17756-map-slot` at `a03608ad9`, time-boxed, not landed).
On top of COV-CALL's first cut: one held-type reader, `letDeliveredSlotTy` (emit_classify.vl,
shared with D17729's list rung), holds and shapes the map at its delivered destination; mono
instances a delivered map's writes at the destination's value (`monoDeliveredSlotFnTy`, the
instancing loop pulled out as `monoInstanceSlotVals`); `.push` runs the delivery judge
(`genFnValueCstrs` in `checkListPushArgs`); and `ctnWrittenCstrsAt` adapts each generic write at
the delivered slot (`fvaAdapt`). Instancing without the adapter TRAPPED every delivered spelling
(`indirect call type mismatch`: `__id`'s `i32` result stored unconverted in the `i32 | f64` slot),
so that state was never committed alone. At the stop point the annotated-`let` delivery
(`const z: FM = c`, prints `3 1.5`) and the one-member push (prints `7`) run; the push and
list-literal deliveries of two members refuse at check, `a function of type (T) => f64 cannot be
used as (i32) => i32 | f64 … that conversion is refused (set: expected (i32) => i32, got (i32) =>
i32 | f64 (parameter x of __half, used at 6:12))`. `__id`'s adapter builds; `__half`'s adapter
re-check (`checkNodeHook(site)` in `fvaAdapt`) meets an `(i32) => i32` bound attributed to
`__half`'s parameter at its write, which pinning the map row (`tyPinVal`) and re-pointing the
map's BM rows at the delivered slot did not reach. That bound's source is the next step: it must
read the one delivered slot COV-CALL's `fitsDst` judges, not its own.
