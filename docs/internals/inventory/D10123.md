### D10123 — a written list of a generic handed to a function after a call of the generic at another type is typed by that call

**loud check reject · `push: cannot add (i32) => i32 to ((string) => string)[] (the body of `id` at the call's argument types)` · clause 2 · CAPABILITY: the two `print` lines swapped print `3`, `s` · found closing [D10080](D10080.md) · present on master `3931f9468` · filed 2026-10-22 against master `3931f9468`**

Repro:

    function id<T>(x: T): T { x }
    function inc(x: i32): i32 { x + 1 }
    function run(a: ((x: i32) => i32)[]): i32 { a[1](2) }
    const ys = [id]
    ys.push(inc)
    print(id("s"))
    print(run(ys))
    // vl check: push: cannot add (i32) => i32 to ((string) => string)[] (the body of `id` at the call's argument types)

Want:

    s
    3

#### Mechanism

[D10020](D10020.md)'s, at an argument. The push row is re-validated at `id("s")`, which
binds `id`'s `T` by name. `ctnWrUnreachedBy` skips the row only when every read of `ys` is
one it can enumerate, and an argument to a function that READS the list (here `run`'s
element call) is not one of them, so the row is judged at `string`. Order decides it: with
`run(ys)` first the row is judged at `run`'s `i32` and the later call is not reached.
