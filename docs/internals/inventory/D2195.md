### D2195 — a list of read-only views rendered as `readonly T[][]`, which spells a view of `T[][]`, so a diagnostic named a different type than the one it meant

**closed 2026-09-23 · was a wrong type spelling in diagnostics and hints · filed 2026-09-23 against master `66e74235a`**

Repro:

    const y: (readonly i32[])[] = [[1]]
    const z: (readonly i32[])[] = y
    print(z.length)
    // was: the checker printed `(readonly i32[])[]` as `readonly i32[][]` in every message,
    // including `@hint redundant type annotation` and the container rule's `readonly` fix.

#### Mechanism

`tyToStr`'s `TyArray` arm prefixes a view with `readonly ` and groups an element in parentheses
only for a function or a multi-atom union. A view element was neither, so `(readonly i32[])[]`
printed as `readonly i32[][]`, which the parser reads as a view over `i32[][]`: `cannot assign
readonly i32[][] to 'z' of type readonly i32[][]` named two different types with one string. The
display arm now groups a view element; the canonical name renderer (`tyToNameAt`) carries no
`readonly` and is unchanged.
