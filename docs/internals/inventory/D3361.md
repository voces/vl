### D3361 — a join of two type parameters in a generic function nested in another function answers `is boolean` false for `false`

**closed 2026-10-31 — now prints `false true`, and the `string`, `K` and `string | null` second arms answer right · was check-clean silently wrong, clause 1 · a join of two declared type parameters is kept apart in the body declaring them when that body is checked under an enclosing function's constraint owner (a nested generic) or at a lambda depth (`tyParamOfInnermostBody`, D3268) · pin: `tests/cases/generics/nested-generic-join-of-two-type-params-is.vl` · the same on master `7e8296bd2` · found by the #3310 round-3 re-review (`rv3310r3/m/ls1.vl`, `ng1.vl`; the g5 grid's `list_scalars`, `list_plus_scalar` and `nested_gen` programs) · filed 2026-09-30 · the list-element shape (`xs: T[]`, `ys: U[]` read as `xs[0]`, `ys[0]`) runs since the D3357 close**

#### Mechanism

Not localised past the ablation. The same join of two bare parameters answers right since
#3310 (the kept-apart join, D3268) when the generic is declared at top level; declared inside
another function it keeps the older typing, in which the join's `boolean` arm does not survive
to the `is`. The second arm is read at the first's type whatever its
member: a `string` or `K` second arm answers `is string`/`is K` false, and a `string | null`
second arm holding `null` traps on a null reference. A lambda in the generic body joining the
two parameters does the same. A record arm is D4046, whose ablation differs.

The list-element spelling, the row's first witness, ran once the D3357 close lifted the gate
over a body taking a list of a type parameter:

    function g<T, U>(xs: T[], ys: U[], k: i32) {
      const a = xs[0]
      const b = ys[0]
      const r = if k == 0 { a } else { b }
      print(r is boolean)
    }

#### Ablation

| ingredient changed | outcome on master | needed? |
| --- | --- | --- |
| `inner` declared at top level | prints `false true` | **yes** (the nesting) |
| `x1: string = "s"` with `r is string`, or `x1: K` with `r is K` | prints `false false` | no (any second-arm member) |
| `x1: string \| null = null` with `r is null` | prints `true`, then traps on a null reference | no (the trap face) |
| `print(r)` in place of the `is` | prints both arms right | **yes** (an `is` reader) |
