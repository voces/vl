Repro:

    function lap(f) {
      f(2.5)
      f(3)
      return f
    }
    const g = () => lap((a) => a + 1)
    const w = g()

Want:

    5
    2.5

#### Mechanism

Half (b), the same binding inside a function, is closed in the elaboration: `elabCalleeFn`
(emit_elab.vl) follows the lifted lambda as a named function; fixture
`tests/cases/closures/hole-lambda-bundle-returned-from-lambda-in-function.vl`.

At the top level a call through `g` is a `call_indirect` through the closure, whose signature
is the checker's single function type, so it cannot return the bundle record; the elaboration
follows only a named function or a lambda bound inside a function, whose call is a direct call
to the lifted lambda. Closing it needs the closure's `$fnsig` to carry the record row
(`cloSigKeyExt` already keys a struct result) and the call site to pick from it.
`scripts/capability-probes/matrix/lambda-bundle-returner.matrix.vl` grades it: 0 of 48 ran;
42 of 48 run after (a), 0 SILENT. The lifted lambda carries its binding's name by emit time,
so the emit-side test reads the initialiser's shape, not `fnName`; testing the name left the
pick unreached and built 17 SILENT cells.
