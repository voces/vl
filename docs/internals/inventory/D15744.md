### D15744 — a top-level `const` bound to a lambda returning a hole lambda's bundle is refused at emit

**loud emit reject · clause 2 · `a function returning a parameter called at two signatures is called where its result is not used at one of them` · found closing [D15740](D15740.md) · filed 2026-11-11 against master `f570d7f7` · widened 2026-11-12 against `bd129b4d4` to every top-level spelling**

Repro:

    function lap(f) {
      f(2.5)
      f(3)
      return f
    }
    const g = () => lap((a) => a + 1)
    const w = g()
    print(w(4))
    print(w(1.5))

Want:

    5
    2.5

#### Mechanism

Half (b), the same binding inside a function, is closed in the elaboration: `elabCalleeFn`
(emit_elab.vl) follows the lifted lambda as a named function; fixture
`tests/cases/closures/hole-lambda-bundle-returned-from-lambda-in-function.vl`.

At the top level a call through `g` is a `call_indirect` through the closure, whose signature
is the checker's single function type, so it cannot return the bundle record; the elaboration
follows only a named function or a lambda bound inside a function, whose call is a direct call
to the lifted lambda. Closing it needs the closure's `$fnsig` to carry the record row
(`cloSigKeyExt` already keys a struct result) and the call site to pick from it.
`scripts/capability-probes/matrix/lambda-bundle-returner.matrix.vl` grades it: 0 of 48 run.

#### Ablation

| spelling | top level | inside a function |
| --- | --- | --- |
| `const g = () => { return c }` | refuses | runs |
| `const g = () => lap(…)` | refuses | runs |
| `const g = () => { return lap(…) }` | refuses | runs |
| `function g() { return lap(…) }` | runs | runs |
| `function g() { return c }` | runs (D15740) | runs |
