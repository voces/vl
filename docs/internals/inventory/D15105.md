### D15105 — a generic nested in a generic function and capturing its parameter, handed to a type-parameter parameter, gets no function-value signature

**closed · runs, prints `7`, `x` · was loud emit reject, clause 2, `a generic function taken as a value reaches no call that fixes its type` · closed in emit_elab.vl: a nested declaration an instance calls through a hand-on, whose encloser is not on the instance's chain, is built under each encloser instance whose call hands it (`elabHandedNote`), and a type read through `Fn#d` takes those instances where they bind `d`'s own names alike (`elabReachedAgreedOf`, `elabValCallInst`) · fixture `generics/capturing-nested-generic-handed-to-type-parameter.vl` · found as destringify's N1 · filed 2026-11-03 against master `38b424262`**

Repro:

    function mid<F>(a: F) {
      print(a("x"))
    }
    function outer<U>(u: U) {
      function same<T>(k: T): T {
        print(u)
        k
      }
      mid(same)
    }
    outer(7)
    // vl check: rc 0.  vl run: 7, x

Want:

    7
    x

#### Mechanism

The call `a("x")` in `mid`'s instance runs `same` directly through the `Fn#same` binding, from an
instance whose chain does not hold `outer`, so `same` had no parent there (`elabParentFor` −2) and no
key. With two `outer` instances the two `same` keys also made `F`'s closed type read as ambiguous.
Was: not located. The nested `same` is instanced per instance of `outer` (it captures `u`), and handing it to `mid`'s `F` parameter reaches the function-value ABI with a parameter type left empty (``), so no signature is interned. The non-capturing spelling and the non-generic encloser both run, so the empty type is the capture's type in the encloser's instance, not `same`'s own.
