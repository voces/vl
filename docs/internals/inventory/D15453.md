### D15453 — a `const` list seeded from a hole parameter the body also calls directly, its slot written with another, is refused

**closed 2026-11-05, runs and prints `3 x`, with the split plan on and off · was loud emit reject, `vl check` rc 0, `emitProgram: a function value's signature is not known at this call`, clause 2, with the split plan on and off (never a split-plan dependent) · the list-slot spelling of D15460 · found writing the cell-read witnesses after #6383 · filed 2026-11-05 against master `755ba974` · closed by the seed rule's list-slot sibling: a parameter read in a `const` list literal (or a `let` nothing re-points), or assigned to one of its elements, whose slots hold only named functions and parameters and whose every read is an element called in place or an element assignment's target, seeds the list's wider element set (`elabParamSeedsListSlot`, emit_elab.vl), so the tag decision takes the parameter's set with it (`ftParamSeedsWider`) · fixtures `closures/list-seeded-by-hole-param-*.vl`**

Repro:

    function go(a, b) {
      const r = [a]
      r[0] = b
      print(r[0](3))
      print(a("x"))
    }
    function same<T>(k: T): T { k }
    function dbl(x) { x }
    go(same, dbl)

Want:

    3
    x

#### Mechanism

D15460 closed this shape for a written `let` seeded from the parameter: the per-read rule notes the
parameter as seeding the let's wider set (`elabParamFeedsWritten`, `mintSeedNote`), and the tag
decision takes the parameter's set with it (`ftParamSeedsWider`). Here the seeded holder is a list
whose slot is written through `r[0] = b`. Neither read, `a` in the literal or `b` in the element
assignment, met a rule, so `a`'s direct call at `string` and the slot's call at `i32` met at one
closure. The close notes both reads against the list's element set, as the `let` rule does
against the binding's.

#### Ablation

| ingredient removed | outcome | needed? |
| --- | --- | --- |
| `print(a("x"))`, the direct call | runs | **yes** |
| `r[0] = b`, the slot write | runs, `3 x` | **yes** |
| the slot called at `string` too (`r[0]("y")`) | runs, `y x` | **yes** (the second type) |
| `dbl` annotated `(x: i32): i32` | still refuses, same message | no |
| `go(same, same)` | still refuses, `a function value is called at two signatures` | no |
| `go<F>(a: F, b: F)` | still refuses, `parameter `a` of `go` is called at two function types` | no |
| index `0` → `[a, a]` read at `1` | still refuses, same message | no (not the cell spelling) |
| list → record `{ f: a }` written `r.f = b` | still refuses, `a function value is called at two signatures` | no |

#### Grading list

Still refused, and outside this close:
- the record spelling (`r.f = b`) is D15455;
- the `dbl(x: i32)` and `go<F>(a: F, b: F)` spellings refuse because their `let` analogs run only
  through the split plan (D15456, and D15409's two-param shape), so the list cannot be ahead of them.

A list handed on whole (`use(r)`) or a slot written with a lambda stays outside the rule and refuses
as before. D15460's fixture `closures/written-let-seeded-by-hole-param-also-called-directly.vl`
must keep running.
