### D2908 — one un-annotated list of object literals adopted by two declared destinations of different records is invalid wasm

**closed by design · now a loud check reject · was check-clean invalid wasm · the owner's record-covariance ruling refuses it: a list that holds only literals is built at the one type it is delivered to; two that store a field differently are refused, naming both lines · closed 2026-09-30**

Repro:

    type I = { f: i64 | null }
    type J = { f: f64 | null }
    const il = [{ f: 7 }]
    const ic: I[] = il
    const jc: J[] = il
    print(ic[0].f)
    print(jc[0].f)
    // vl check: rc 0.  vl run: invalid module in the top-level code

Want:

    7
    7

#### Mechanism

The checker admits the one list into both `I[]` and `J[]`. A list value has one element
storage, and D2881's destination walk builds it at the first declared record it finds, so the
other destination receives a list of another record. The union-box twin of this refuses loudly
("bound to TWO declared destinations"); the record twin neither refuses nor copies.

#### Ablation

| ingredient removed | outcome | needed? |
| --- | --- | --- |
| the second destination | runs, prints `7` | **yes** |

#### Grading list

The same with a record and a union-box destination, which D381 already refuses.

#### Close (2026-09-30)

Closed by the owner's record-covariance ruling (DECISIONS.md "Record covariance: only a fresh value widens"): a list that holds only literals is built at the one type it is delivered to; two that store a field differently are refused, naming both lines. The refusal names both fixes, building the source at the wider record or copying it with an object literal, so no program the design permits is refused.
