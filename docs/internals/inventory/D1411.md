### D1411 — an inferred object literal MERGES onto a same-fieldset DECLARED row whose field code its value cannot fill

**loud emit reject · check rc 0 · clause 2 · PRE-EXISTING: identical message and column on the
pre-[D1242](#d1242) seed · filed 2026-09-03**

Repro (refuses; deleting the `type Q` line — which the program never mentions again — prints
`5`):

    type Q = { f: i32 }
    const u: i32 | null = 5
    const w = { f: u }
    print(w.f ?? 0)

#### Mechanism

`structIndexOfObjCtxGo` resolves an object literal to a struct row by field-NAME set, and
`anonValueFitsField` is the refutation that stops two same-fieldset literals sharing one row
when their values cannot share its valtypes. It has a TIER rule: the composite value codes
refute only against an ANONYMOUS row, because a DECLARED row's codes come from an annotation
the checker may have reached through adoption. So a code-16 value (`i32 | null`) against
`Q`'s code-0 `i32` field takes `if !anonRow { return true }` and merges — and `w.f` then
reads an i32 slot through the union-box path.

The second face is the same merge with the value code MISSING rather than mismatched:

    type In = { f: i32 | null }
    const inn: In = { f: 5 }
    const w = { f: inn }
    print(w.f.f ?? 0)

`anonFieldCode(inn)` reaches `anonCodeIsSelfContained`, which admits neither 15 nor 5 — so it
answers -1, `anonValueFitsField`'s first line (`vc < 0 { return true }`) declines to refute
on ignorance, and `{ f: inn }` merges onto `In`'s own row. The field is then read as `In`'s
code-16 union rather than as a nested struct.

Both are the leniency, not the codes: there is no annotation anywhere saying these literals
are `Q`s or `In`s, so the merge is a REP decision the program never asked for.
