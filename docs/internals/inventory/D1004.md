### D1004 — the EMPTY member-access diagnostic survives on an UNBOUNDED `<T>` (D952's remaining half)

**loud check reject · the MESSAGE half is FIXED 2026-09-03 — the rung states the rule and names the edit that satisfies it; the program still refuses, and whether it should is the owner question now filed under ROADMAP "Awaiting owner rulings" · ZERO corpus cells**

D952's bounded half closed with constraints phase 1: a bounded parameter names its bound and
what the bound grants. An unbounded `<T>` keeps its pre-existing path by ruling, and that path
still ends at `memberFloorMsg`'s `TyVar` rung returning `""`.

* **THE WORDING IS THE WHOLE FIX and it does not need the language to decide anything.** The
  `?.` twin already prints `member access '?.n' on non-object T`, so `tyToStr` renders the
  parameter and a sentence is one string away. What it should SAY is the open part: an
  unbounded parameter grants nothing, so the actionable clause is "add a bound" — which now
  exists as a spelling.

* **DO NOT CLOSE IT BY MAKING UNBOUNDED `<T>` STRICT.** That is a language change the owner
  has not ruled, and `tests/cases/constraints/unbounded-type-param-unchanged.vl` is the pin
  that says so. Still green after the message fix.

* **THE `""` WAS AN IN-BAND SENTINEL WITH NO READER, AND ONE CALLER FORMATTED IT.**
  `memberFloorMsg` has three callers and `""` means "this read is fine, or is deferred" to
  two of them — `validateMemCstrs` (through `memCstrMsg`) tests `mMsg != ""`, and
  `validateUfcsCstrs` tests `uMsg == ""` and substitutes its own words. Neither can ever
  receive a `TyVar`: both guard on `!tyHasHole(…)` first, and `tyIsHole` answers TRUE for
  every `TyVar`, a declared parameter included. So the rung's `""` reached exactly one
  caller, `memberFloorErr`, which raised it unconditionally — and that is the whole
  diagnostic a user got. 1 of 3.

* **THE FIX IS TWO LAYERS, on purpose.** The rung answers (`tpMemberFloorMsg`), and
  `memberFloorErr` now refuses to raise an empty string at all — so a future rung that
  forgets costs a vague sentence, not a wordless one. The class is closed, not the instance.

* **THE SENTENCE'S SUGGESTION IS MEASURED.** `<T: { n: i32 }>` makes this witness run, at
  two instantiation shapes (`{n: i32}` and `{n: i32, m: i32}`), so "declare a bound" is an
  edit that actually works rather than a hedge.
