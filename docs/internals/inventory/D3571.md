### D3571 — an `if` nested in an `else` arm keeps its runtime arm's own type when the outer join parts it from a literal-adapted sibling, so the value reads at the wrong width

**closed 2026-10-04 — the witness prints `-1.5` · was check-clean silently wrong, clause 1 · found by the #3353 review (`w/nest.vl`) · filed 2026-10-03 against master `3b9319528` · fixture `tests/cases/conditionals/if-nested-join-widened-arm.vl`**

Repro:

    function run(q: i32 | null, r: i32 | null) {
      const x = if q != null { q } else { if r != null { r } else { 2.5 } }
      print(x / 2)
    }
    run(null, -3)
    // master printed -1

Want:

    -1.5

#### Mechanism

Confirmed. The emitter lowers a value `if` delivered into a union box as a union chain: an
inner `if` in an arm (`emitUnionIfArm`), an `else if` link (`emitUnionIfValueLink`, the binding
sink `emitUnionIfBindingSinkLink`, and the nullable binding `emitNullableIfBindingLink`) and an
`if` reaching `emitUnionCoerce` all walked into the inner arms and boxed each tail at its own
type. That is right for a literal tail (DECISIONS.md, the numeric-join ruling: "a literal inside a
union chain boxes at its own type"), and wrong for a runtime tail the inner join widened: `r`
boxed as `i32` where the inner `if` is `f64`. An inner `if` typed one number that a runtime tail
is not, every literal tail already being that number (`ifJoinAdaptsScalar`), is now delivered as
its own value and boxed once at its type. Where a literal tail's own type differs from the inner
join's (`if x > 0.0 { x } else { 0.1 }` over `x: f32`), the chain keeps boxing it at its own type,
as `tests/cases/numerics/f32-f64-join-widens.vl` pins.

The grid (four inner joins × four outer types × block, `else if`, nested-block and return
shapes × three paths, 192 cells, each graded against its hoisted twin `const y = <inner>` on
master): 6 wrong→right, 162 right on both, 0 right→wrong; the 24 wrong-both are the return shape,
which refuses `/` over the held inferred return on both (D3494). The annotated spelling
`const x: i32 | f64 = …` moved with it, from `-1` to `-1.5`, the inner join's own `f64`.
