### D15199 — a record field written through an alias of the field, then read into an annotated list of a wider function type, passes check and traps

**fixed by letting the delivery judge (`holeSlotArgJudge`, check_relate_core.vl, D10150) follow a field or element read to the slot of the binding it reads, as it followed an alias. The named set `d15199-field-read-delivery` holds the positions and the controls. Building the list at the wider type instead is the convert-copy question pending with the owner as [D15093](D15093.md) · loud check reject · `cannot write 'half' to an element of 'r.fs': called at (i32) it returns f64, where 'inc0', also written to it, returns i32 — every function a call through an element of 'r.fs' may run must return one type` · DESIGN, the refusal the alias (`= a`) and the bare list already get · clause 1 until 2026-11-03, when the program loaded and then stopped at the call (`indirect call type mismatch`) after a clean `vl check` · found ablating [D15198](D15198.md) · filed 2026-11-03 against master `2fc6eddc`**

Repro:

    function inc0(a) { return a + 1 }
    function half(a) { return a / 2.0 }
    const r = { fs: [inc0] }
    const a = r.fs
    a[0] = half
    const v: readonly ((x: i32) => i32 | f64)[] = r.fs
    print(v[0](3))

#### Mechanism

`holeSlotDeliveryJudge` judges a list of open functions read into a closed annotated list: every function written to the place must share one result at the annotation's parameters. `holeSlotArgJudge` followed a name through `holeSlotRebase`, so `= a` was refused, but it returned false at any other node, so a field read delivered directly (`= r.fs`, `= r.s.fs`, `g(r.fs)`) was not judged. The field widening (`elabFnFieldListTy`) then admitted the write, and the read handed the widened elements to a call at the annotation's signature. The same read with the write made directly (`r.fs[0] = half`) was a loud emit reject (`ref valtype with no interned shape`) and now gets the same refusal; that move from an emit reject to a check reject is hygiene, not progress on `runs`, and it re-opens with [D15093](D15093.md) if convert-copy is ruled.
