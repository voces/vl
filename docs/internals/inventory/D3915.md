### D3915 — an inline record spelling resolves to another row that only shares a field name, so a callback over it builds invalid wasm

**closed 2026-10-09 by lane SC, with D3898 · runs · was check-clean invalid wasm · found closing D3898 · filed 2026-10-09 against master `606600b25` · pins: `tests/cases/generics/inline-record-spelling-beside-row-sharing-field-name.vl`**

Repro:

    type A = { x: i32 }
    function ap<T, U>(xs: T[], f: (t: T) => U): U[] {
      const r: U[] = []
      for x in xs { r.push(f(x)) }
      r
    }
    const ba: { v: i32[] } = { v: [1] }
    const o: { v: A } = { v: { x: 2 } }
    print(ap([o], (e) => e.v.x)[0])
    // vl check: rc 0.  vl run: the emitted module failed to validate inside `ap`

Want:

    2

#### Mechanism

The callback is pinned at the render `{v:{x:i32}}`, which `structIndexOfTypeName` resolved to the
`{ v: i32[] }` row because a nested inline record's field type was lenient against any non-struct
field code (D3898). The lambda took that row while `ap` calls it at `{ v: A }`'s. Closed with D3898.
