### D6761 — a binding annotated with the parameter's type parameter, called at one type and handed to a closed function type of another, is refused at emit

**closed 2026-10-18 by lane L1 · runs, prints `x` then `1` · was loud emit reject · `vl check` rc 0 · clause 2 · CAPABILITY · the split read the binding's delivery to a closed function type as no call key; it now keys that delivery at the destination's parameter types, and the copy that lands on [D6760](D6760.md)'s shape is built by its close · the un-annotated parameter spelling runs too · pins: `tests/cases/generics/type-param-binding-called-and-handed-closed-fn-type.vl` · found closing [D6741](D6741.md) · filed 2026-10-18 against master `bd096729d`**

Repro:

    function same<T>(k: T): T { k }
    function twice(f: (x: i32) => i32) { f(f(1)) }
    function mid<F>(a: F) {
      let b: F = a

    // vl check: rc 0.  vl run: emitProgram: monomorphize: parameter `a` of `mid` is called at two function types that no parameter per type separates

    1

#### Mechanism

From the ablation only. The split reads `b`'s delivery to `twice` as no call key, so the copy
`let b: F = a` is read at none it can split by and the plan declines. Keying that read at
`twice`'s parameter types was tried: the plan then splits `b` into two bindings annotated `F`
seeded from un-annotated parameters, which is [D6760](D6760.md)'s shape, and the program builds
invalid wasm, so that change was not kept.
