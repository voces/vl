**closed · runs, prints `a` `zz` · was check-clean trap (`indirect call type mismatch`), clause 1 · CAPABILITY: the join annotated at `(x: i32) => string` runs since [D9781](D9781.md)'s close · found closing [D9781](D9781.md) · present on master `ba2918226` · filed 2026-10-22 against master `ba2918226` · closed by adapting each function-value tail of a value `if`, `match` or block to the join's own type (`fvaAdaptJoin`, check_assignable.vl, run from `checkNodeDone`, check_node_rules.vl) · fixture `closures/fn-value-result-widens-to-nullable.vl`**

Repro:

    function n(x: i32): "a" | "b" { return "a" }
    function z(x: i32): string { return "zz" }
    const c = 3 > 2
    const k = if c { n } else { z }
    print(k(1))
    const k2 = if c { z } else { n }
    print(k2(1))
    // vl run: wasm trap: indirect call type mismatch

Want:

    a
    zz

#### Mechanism

`joinTys` collapses two mutually assignable types to the wider, and [D4351](D4351.md) made an
atom-result function assignable to the same function at `string`. The join was typed
`(i32) => string`, but its `n` tail kept its own signature, so the call through `k` reached it
at the wrong `$fnsig`. [D9781](D9781.md)'s nullable widening made `f64[]` beside `f64[] | null`
the same shape. Each tail is now wrapped in the adapter `fvaAdapt` builds at a declared slot.
