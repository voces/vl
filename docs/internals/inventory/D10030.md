### D10030 — `k?.get(…)` over a nullable map passes check and has no lowering

**loud emit reject · `vl check` rc 0 · `emitProgram: union if-expression arm ends in a void call, which yields no value` (bound first, or at a `string` value, `callee is not a function name`) · clause 2 · UNDECIDED between CAPABILITY and DESIGN: narrowing first (`if k == null { … }`, then `k.get("a")`) runs, and the checker refuses `k?.length` on the same receiver because "`?.` reads a declared struct field", so the close is either lowering `?.get` or refusing it at that same rule · found closing [D9990](D9990.md), whose grading list held it · present on master `2c4263380` · filed 2026-10-22 against master `2c4263380`**

Repro:

    function f(k: {[string]: i32} | null): i32 {
      (k?.get("a") ?? 0) + 1
    }
    const m: {[string]: i32} = Map()
    print(f(m))
    // vl check: rc 0.  vl run: emitProgram: union if-expression arm ends in a void call, which yields no value

Want:

    1

#### Mechanism

Not traced. The checker types `k?.get("a")` as the map's nullable value, but no emit path
lowers an optional-chained call on a map receiver. As an operand of `??` the chain is
desugared to an if-expression whose present arm is the `get` call, and that arm is classified
as a statement, so it yields no value. Bound to a `const` first, or at a `string` value, it
fails earlier, at the call's callee. No lambda or context is involved: the same refusal holds
at module scope over a `const m: {[string]: i32} | null`.
