### D16094 — a re-pointed `let` returned and then handed to an open parameter is refused where the binding handed directly dispatches

**loud check reject · clause 2 · `cannot write 'str' to 'f': called at (i32) it returns string, where 'inc', also written to it, returns i32 — every function a call through 'f' may run must return one type` · the residue of [D16009](D16009.md); [D13966](D13966.md)'s witness · filed 2026-11-14 against master `1c8a267ef` · narrowed 2026-11-14: a choice of functions handed on now runs, `closures/choice-of-hole-fns-handed-to-open-param.vl`**

Repro:

    function inc(a) { return a + 1 }
    function str(_a) { return "s" }
    function ap(g, x) { return g(x) }
    function sel(c: boolean) {
      let f = inc
      if c { f = str }
      return f
    }
    print(ap(sel(true), 3))
    // vl check: rc 1, the refusal above

Want:

    s

#### Mechanism

A widened `let` handed directly to an open parameter is left to the tag decision, which tags its
set and dispatches in the callee's instance (D16009). Returned from `sel` and then handed on, the
read is a `return`, not a hand to an open parameter: the decision leaves the set a closure, the
binding is vetoed and re-checked at its initialiser's type, and the let judge refuses. A choice
handed on is left to the decision the same way, and vetoed (`fnChoiceVeto`) only when something
other than an open parameter or a call reads it.
