### D14401 — an un-annotated Map holding a generic used at two instances gets no value slot, although the checker stamps both deliveries

**loud emit reject · filed 2026-10-26 against master `e139633e3` · a different mechanism from D14400**

Repro:

    function id<T>(x: T): T { x }
    function runAll<U>(a: ((x: U) => U)[], u: U): U { a[0](u) }
    const mp = Map()
    mp["k"] = id
    const mpv = mp["k"]
    if mpv != null {
      const p = mpv
      print(runAll([p], 2) + runAll([p], "ab").length)
    }
    // vl check: rc 0.  vl run: emit error at 3:7, emitProgram: unsupported map value type
    //   (no rep for a union-member struct, a nullable list over an unnamed element rep,
    //   or a nullable litunion-result closure; any other value type here interned no mv slot)

#### Mechanism

The checker side is complete here. `runAll` is instantiated at `U = i32` and at
`U = string`, and a probe in `recordRepTyAdopt`'s `Ident` arm shows both element
deliveries stamped, at `(i32) => i32` and at `(string) => string`. What fails is the map's
own value slot. Its type is `(T) => T`, `id`'s signature with `T` free, and with two
instances the emitter finds no single closed type to intern a map value slot at. The same
program over a list container (`const ar = [id]`) runs and prints `4`, so the defect is in
the map's value rep and not in the delivery. D14400 is the reassigned-`let` spelling. There
the call is never instantiated at a closed type, the flow pin settles on one type, and the
program runs. Under the conflict ruling for #4911 each delivery is a use at its own
instance, so this program is legal.

#### Ablation

| ingredient removed | outcome | needed? |
| --- | --- | --- |
| `const` (`let p = mpv`, not reassigned) | still refuses | no |
| the alias (deliver `[mpv]` directly) | still refuses | no |
| the Map (`const ar = [id]`, `const p = ar[0]`) | runs, prints `4` | **yes** |
| the second instance (`runAll([p], 2)` only) | runs | **yes** |
| the differing type (`runAll([p], 2) + runAll([p], 3)`) | runs, prints `5` | **yes** |
| the list element (`run1(p, 2) + run1(p, "ab").length`) | runs, prints `4` | **yes** |
