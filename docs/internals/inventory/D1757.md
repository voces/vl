### D1757 — an INFERRED object literal mints a literal-union field as a union BOX while every reader of that field lowers the ATOM, so reading it out across any boundary is check-clean invalid wasm

**check-clean invalid wasm · clause 1 · filed 2026-09-06 against master `dcbf7521c` · found by `scripts/day-one/sample.py` seeds 3001–3005 (2,500 pairs), 7 of the 25 SILENT programs · 0 corpus cells**

Repro:

    type Color = "red" | "green"
    function mkval(): Color { return "red" }
    const srcBox = { it: mkval() }
    function make() { return srcBox.it }
    print(make())
    // vl check: rc 0.  vl run: exit 70,
    // the emitted module failed to validate inside `make`:
    // type mismatch: expected (ref $type), found (ref $type)

Annotate the object literal — `const srcBox: { it: Color } = { it: mkval() }` — and it prints
`red`. So does giving the holder a declared `type Boxed = { it: Color }`.

#### Mechanism

MEASURED by disassembling both faces. Without the annotation the holder's row is
`(type $0 (struct (field (mut (ref $1)))))` where `$1` is the union BOX
`(struct (field i32) (field anyref))`; with it the row is
`(type $0 (struct (field (mut i32))))` — the literal union's ATOM, an interned id. The
readers do not follow the row: `make`'s body is the atom-ification the annotated face uses,
`(select (i32.const 0) (i32.const 1) (call $streq (struct.get $0 0 …) (global.get $"red")))`,
so it hands the box's `(ref $1)` to a string compare that wants `(ref $4)`. The anonymous
mint claims a litunion value as a box before its atom arms are reached; the DECLARED path
mints the atom. This is [D1715](D1715.md)'s neighbourhood — the same code-0/code-30 pair —
reached through an un-annotated holder rather than through two holders colliding on a row.

**The capture is scenery, and that is what separates this from [D1476](D1476.md).** The
sampler drew it seven times as a closure capture, but the defect fires at every delivery that
crosses a boundary and at none that stays inside one, so it is the FIELD's rep and not the
capture's kind. Annotating the destination does not help — an annotated parameter and an
annotated return both still refuse — which is the opposite polarity from every
`captureValKind` row, where the destination annotation is the whole fix.
