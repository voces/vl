### D1757 — an INFERRED object literal minted a literal-union field as a union BOX while every reader of that field lowers the ATOM, so reading it out across any boundary was check-clean invalid wasm

**closed 2026-09-06 — the witness prints `red` · was check-clean invalid wasm · clause 1 ·
filed 2026-09-06 against master `dcbf7521c`, re-graded as filed on `b35b2a093` · found by
`scripts/day-one/sample.py` seeds 3001–3005 (2,500 pairs), 7 of the 25 SILENT programs ·
fixture `tests/cases/literal-unions/anon-holder-litunion-field.vl` · 0 corpus cells**

Repro:

    type Color = "red" | "green"
    function mkval(): Color { return "red" }
    const srcBox = { it: mkval() }
    function make() { return srcBox.it }
    print(make())
    // vl check: rc 0.  vl run: prints red.

Annotate the object literal — `const srcBox: { it: Color } = { it: mkval() }` — and it prints
`red`. So does giving the holder a declared `type Boxed = { it: Color }`.

#### Mechanism

MEASURED by disassembling both faces and then by probing the mint and one reader. Without the
annotation the holder's row was `(type $0 (struct (field (mut (ref $1)))))` where `$1` is the
union BOX `(struct (field i32) (field anyref))`; with it the row is
`(struct (field (mut i32)))` — the literal union's ATOM. The readers do not follow the row,
because both read the SAME table and the row is what differs:

| holder | row | field code at the read | companion name |
| --- | --- | --- | --- |
| `const srcBox: Boxed = …` | `Boxed` | **0** — the interned atom | `Color` |
| `const srcBox = …` | `#anon0` | **16** — the union box | `Color` |

`anonFieldCode`'s code-16 rung fires above every atom arm, so a literal union — which also
registers as a union NAME — was minted as a box. `fieldCodeOfSpelling` states the opposite
rule for the DECLARED twin in as many words, and that is the rule this ladder lacked. The fix
is that rung, plus the companion `anonFieldElemName` code-0 arm built beside it: the probe
shows the box row already recorded `Color`, so without the paired arm the atom would have
landed with no member set — the failure [D1710](D1710.md)'s code-30 arm exists to prevent.

[D1715](D1715.md)'s own mechanism paragraph named this rung — "`anonFieldCode` claims a
litunion-typed value as a box before its atom arms are reached" — and fixed the FIT rule that
box row then broke. This is the mint itself.

**The capture is scenery, and that is what separates this from [D1476](D1476.md).** The
sampler drew it seven times as a closure capture, but the defect fires at every delivery that
crosses a boundary and at none that stays inside one, so it is the FIELD's rep and not the
capture's kind. Annotating the destination does not help — an annotated parameter and an
annotated return both still refused — which is the opposite polarity from every
`captureValKind` row, where the destination annotation is the whole fix.
