### D3155 — a scalar-valued map read through an un-annotated parameter's instance yields the raw zero on a miss

**closed 2026-09-30 · was check-clean silently wrong, clause 1, on master `8df60e472` · found grading lane TT's map-field grid, beside [D3130](D3130.md) · built by lane MH · fixture `tests/cases/generics/hole-map-read-scalar-miss.vl`**

Repro:

    type H = { m: {[i32]: i32} }
    function mk(): H {
      const v: {[i32]: i32} = Map()
      v[3] = 7
      { m: v }
    }
    function use(r) {
      const e = r.m
      const x = e[9]
      print(x)
    }
    use(mk())
    // PRINTS 0

Want:

    null

#### Mechanism

A read `m[k]` off a hole is typed as an element derivation of it (`HD_ELEMV`), and nothing
resolved that derivation at a map pin: `holePinReadOf` answered for a list or a string and not
a map, and the emitter's map readers (`nodeTyMapVal*`, `mapRecvScalarBoxKindTy`,
`emitMapGetTail`'s miss sentinel) read the receiver's recorded hole. So the instance read the
map as a plain `i32` map: no miss sentinel, no atom texts, no `boolean`, no value box. The close
(lane MH) reads the derivation at a map pin as the value or `null` (`mapPinReadTy`), in the
instance's own binding first (`mapRecvTyIn`) and the program's one banked pin after it, and the
producers and consumers of the read, its binding (`synthNullableAnn`) and its `??` all ask that
reader. A `??` default that the read's atom rep cannot hold keeps the template reading
(`coalMapReadForeignDefault`); that face is [D3127](D3127.md).

#### Ablation

| ingredient changed | outcome | needed? |
| --- | --- | --- |
| the parameter annotated `r: H` | prints `null` | **yes** (the hole) |
| `e[3]`, a hit | prints `7` | **yes** (the miss) |
| an `f64` map value | prints `0` | no |
| a `boolean` map value | prints `0` | no |
| `print(x == null)` | loud emit reject | no (the same unboxed read, refused) |
