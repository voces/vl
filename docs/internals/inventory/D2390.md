### D2390 — an `is` narrowing survives a call to a closure that reassigns the narrowed binding

**loads then traps · clause 1 · pending an owner language ruling · filed 2026-09-25 against
master `3ab3c402f`, found grading [D2387](D2387.md)/[D2388](D2388.md) · pre-existing: master
`3ab3c402f` already traps for most member pairs, and that close moved the rest onto the trap**

Repro:

    function f(): string {
      let v: boolean | f64 = 1.5
      const k = () => { v = true }
      if v is f64 { k(); "\{v}" } else { "no" }
    }
    print(f())
    // vl check: rc 0.  vl run: wasm trap: cast failure

#### Mechanism

The checker narrows `v` to `f64` for the whole then-arm and does not drop the narrowing at
`k()`, although `k` assigns `v` a different member and is called inside the arm. The emitter
reads the cell under the narrowing and casts the box's payload to the narrowed member's struct,
which now holds another member: `cast failure`. On master `3ab3c402f` that was already the
outcome for `string|i32`, `i32|string`, `i32|f64`, `boolean|string`, `string|boolean` and
`string|f64`. The D2387/D2388 close is a PRICE recorded here, not the cause: it moved
`f64|i32`, `i64|string` and `boolean|f64` from check-clean invalid wasm to this trap, and
`i32[]|string` from a loud emit reject (`'.length' on a receiver the emitter cannot
classify`) to this trap. Whether a call to a closure that writes a captured binding should
end a narrowing (TypeScript keeps it, unsoundly) is a language decision awaiting the owner;
until one is made the program is check-clean and traps.

#### Ablation

| ingredient removed | outcome | needed? |
| --- | --- | --- |
| the call `k()` inside the arm | prints `1.5` | **yes** |
| the closure's write (`k` only reads `v`) | runs | **yes** |
| the write's member (`v = 2.5`) | prints `2.5` | **yes** |
