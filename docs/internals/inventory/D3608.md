### D3608 — in a merged compile, a call above a block-local function of a module function's name is undeclared; which function it means waits on a ruling

**closed 2026-10-04 · was a loud check reject in a merged compile and a silently wrong value in a single one · ruled (A) by the owner 2026-10-04: a block-local `function` is in scope from its declaration on · filed 2026-10-04 by lane SC against master `c473889d1`, closed by lane LF · fixtures `tests/cases/scope/block-local-function-visible-from-declaration.vl` and `tests/cases/scope/block-local-function-visible-from-declaration-merged.vl`**

Repro:

    import { hypotF64 } from "std:math"
    function k(): i32 { 1 }
    function f() { print(k()); function k(): i32 { 2 }; print(k()) }
    f()
    print(hypotF64(3.0, 4.0))
    // master: vl check: undeclared identifier 'k' at 3:22. Without the import the program prints 2, 2, 5.

Want:

    1
    2
    5

#### Mechanism

The checker and the emitter disagree about where a block-local `function` is visible, and the
module merge sides with the emitter. The CHECKER does not hoist one. A call above it resolves to
whatever the name meant before. With a module `function k(): string`, `const s: string = k()`
above the nested `function k(): i32` is accepted and `const s: i32 = k()` is refused. With no
module `k`, the call is `undeclared identifier`. Two nested functions cannot call each other
forward (`a` calling a later `b` is `undeclared identifier 'b'`). The EMITTER hoists one over its
whole frame (`nestedFnDeclaredIn`, `compiler/emit_classify.vl`). It has neither position nor block
(D3614). So the single-module `2 2` is the emitter overriding the checker: correct only if the
ruling is "hoisted", and a silent wrong value (`2` where the checker typed `1`) if it is not.
`modRwBlock` (`compiler/driver.vl`) shadows a block-local function's name over the whole block
("being hoisted"). It leaves the call above as `k`, which the checker cannot find once the
module's `k` is renamed `k$m0`.

#### Ablation

| ingredient | outcome on master |
| --- | --- |
| no import (single module) | prints `2 2` (the emitter's answer; the checker typed the first call as the module `k`) |
| module `k` returns `string`, the first call bound to `string` | single: invalid module |
| no module `k` | `undeclared identifier 'k'` at the first call, single or merged |
| the call below the nested function | runs, `2` |

#### Grading list

THE RULING: (A) a block-local `function` is visible from its declaration on, which is what the
checker does today, or (B) it is hoisted to the top of its block, as in JS. **Recommendation
(A).** It is what the checker already enforces. Under (B), a call above the function could run
it before a `const` it captures is initialised, so (B) needs a TDZ rule for captures first. The
fix under (A): `modRwBlock` shadows a function from its declaration, like a `let`, keeping its
own body inside the shadow for recursion. The emitter resolves positionally (D3614). The witness
then prints `1 2 5` in both compiles. The fix under (B): the checker pre-declares a block's
functions, which also admits forward calls between siblings. The witness then prints `2 2 5`.

#### The ruling and the close

The owner ruled (A) on 2026-10-04: a block-local `function` is visible from its declaration
onward, like `const`/`let`; it may capture locals, and local functions cannot call each other
forward. That is what the checker already did, so the close is all emitter and merge:

- `modRwBlock` (`compiler/driver.vl`) shadows a block-local function's name from its
  declaration, as it does a `let`, and before its body is rewritten so a recursive call keeps
  naming it. The call above it keeps naming the module's function (`k$m0`).
- The emitter resolves a block-local function lexically (`lfFnAt`, `compiler/emit_classify.vl`).
  `liftFnsInExpr` records, for each function declared as a block statement, its name, its
  subtree's arena range and its block. The arena is post-order, so a read sees the function
  inside its own subtree (recursion) and from its end to its block's end; the innermost
  declaration wins. A read no block-local function covers takes the top-level function of the
  name, or none (so a builtin), never a block-local one off its scope. `fnIndexOfNode` (37 sites
  that held the callee's node), `emitCallCore`'s callee lookup, a function value's lookup,
  `fnIndexOfInScopeAt` and the capture fold (`capSiblingFrees`) all ask it. A per-pin clone of
  a nested function in a generic instance is still reached through the frame chain
  (`lfResolveAt`), and a node a pass appended past the root keeps the old name-only answer,
  except a UFCS callee, which stands at its originating call (`callOriginOf`).
