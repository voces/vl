**closed 2026-09-28 — the filed repro prints `2.5` · was check-clean invalid wasm, clause 1, the same on master `59cf3b639` · closed by reading a loop variable at its list's element at the instance's pin in `monoArgTyName` (`loopVarArgPinTyOf`), keyed as every other channel keys that pin: a flat literal union at its alias's `i32` atom, and a type sharing the `i32` rep only in an explicit instance, so a callee's result stored back into a `T` slot agrees with the slot; a list literal of the parameter (`[x, x]`) is an iterable `iterElemPinTy` reads, and `forInElemKind` binds a `string | null` pin's element as the nullable string · fixtures `tests/cases/generics/for-in-var-to-hole-callee-at-pin.vl`, `tests/cases/generics/for-in-var-callee-result-stored-at-pin.vl` · found by the LU3 grid, filed 2026-09-28 against master `59cf3b639`**

Repro:

    function idh(z) { return z }
    function f<T>(x: T[]) {
      for e in x { print(idh(e)) }
    }
    const v0: f64[] = [2.5]
    f(v0)
    // vl check: rc 0.  vl run: invalid module, expected i32, found f64

Want:

#### Mechanism

The loop variable carries no annotation and records the type parameter, so no rung of
`monoArgTyName` named its pin and the scalar cascade's `i32` default cloned `idh` at `i32`. The
same miss is invalid wasm at `string`, `i64`, `f32` and `string | null`, a refused field read at a
record, and `1` for `true` at `boolean`. Separately, `const l = [x]; for e in l` at a
`string | null` pin bound the loop variable as a non-null string and trapped on `null`.
