### D17667 — a function returning a guarded call of a value only ever `null` has no checked result type, and legacy declares it `i32`

**closed 2026-11-26 · was check-clean invalid wasm · clause 1 · fixed in emit_elab.vl: an instance whose substituted result stays open takes the type its returned values agree on, one typed `never` there (or in an arm its re-check found dead) left out (`elabRetOfLive`); the IR writes a never call with no dead widening after it (D17667's f64 claim) · fixture `tests/cases/closures/dead-field-call-returned-results.vl` · found by COV-CLOS on `dead-field-call-positions.vl` `returned`, routed to SOUND · filed 2026-11-26 against master `b40af35f5`**

Repro:

    function rf(z) {
      if z.f != null { return z.f() }
      return 2.5
    }
    print(rf({ v: 2, f: null }))
    // vl check: rc 0.  vl run: the emitted module failed to validate inside `rf`: expected i32, found f64

Want:

    2.5

#### Mechanism

The callee `z.f` is typed `null` and the `!= null` guard leaves the call dead, so that return
contributes no type, and the checker records none for the function (`fnCheckedRetTy` and
`fRecRetTy` both -1). Legacy's declared result descriptor (`fRetKind`) is then `i32` whatever
the live return is (also for a string or bool return), so a non-`i32` live return validates
against an `i32` result. The IR declines it (`result rep ?`). The result needs the live return's
type.
