### D15612 — [CLOSED 2026-11-09] a hole function listed to a callee that hands the element on to another at two types is taken as a value with no signature

**closed 2026-11-09, runs and prints `5` then `s` · was loud emit reject, clause 2, `vl check` rc 0, then `emitProgram: a generic function taken as a value reaches no call that fixes its type — annotate the destination's function type` · filed 2026-11-09 against master `d4901c70` · closed in two places: the elaboration's mint facts (emit_elab.vl) note an element read of a list parameter handed to a named function's open parameter as that parameter forwarded there (`elabMintElemFwd`), so the set the second callee calls at reaches the caller's hole; and mono pins that callee's hole at the set the element holds rather than at the closed function type the call binds it to, as it already did for a parameter handed on (`monoPinHoleParam`, emit_mono.vl), which is what the reverted forward lacked · fixture `functions/hole-list-element-handed-on-at-two-types.vl` · the element bound to a `const` first is [D15620](D15620.md), the whole list handed on to a callee that calls its element is [D15621](D15621.md)**

Repro:

    function id(v) { return v }
    function call1(f, x) { print(f(x)) }
    function call0(fs, x) { call1(fs[0], x) }
    function run(g) {
      call0([g], 5)
      call0([g], "s")
    }
    run(id)

Want:

    5
    s

#### Mechanism

Traced while closing. Before the fix: `elabMintFactAt` notes a set for `fs` only at a call through `fs[0]`; here `fs[0]` is
handed to `call1`'s parameter, and no forward from an element read to that parameter is noted.
Noting that forward alone is not the fix: tried while closing D15566, it lets the program build,
and `call1` then fails to validate (`type mismatch` inside `call1`). It does get one instance
per type; what disagreed was its hole's rep. The call binds `f` to the closed `(i32) => i32`, and
mono's rung that swaps such a binding for the tagged set the argument holds fired only for a bare
name argument, so `call1` took a closure while `fs[0]` handed it an id.

With the forward the single-type spelling (`6` for `"s"`) also became a tag set, so it failed
the same way until the mono rung was widened; on master it ran through closures.
