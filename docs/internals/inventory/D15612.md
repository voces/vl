### D15612 — a hole function listed to a callee that hands the element on to another at two types is taken as a value with no signature

**loud emit reject · clause 2 · `vl check` rc 0, then `emitProgram: a generic function taken as a value reaches no call that fixes its type — annotate the destination's function type` · the callee calling the element itself runs since [D15566](D15566.md) · found filing D15609 · filed 2026-11-09 against master `d4901c70`**

Repro:

    function id(v) { return v }
    function call1(f, x) { print(f(x)) }
    function call0(fs, x) { call1(fs[0], x) }
    function run(g) {
      call0([g], 5)
      call0([g], "s")
    }
    run(id)

Want:

    5
    s

#### Mechanism

Not traced. `elabMintFactAt` notes a set for `fs` only at a call through `fs[0]`; here `fs[0]` is
handed to `call1`'s parameter, and no forward from an element read to that parameter is noted.
Noting that forward alone is not the fix: tried while closing D15566, it lets the program build,
and `call1`'s one instance then fails to validate (`type mismatch` inside `call1`), so the
forward needs `call1` instanced per set the element carries.
