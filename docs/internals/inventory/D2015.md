### D2015 — an `extern function` used as a VALUE (`const v = f`) checks clean and the emitter has no binding for it

**open · loud emit reject, clause 2: `vl check` rc 0, then `emitProgram: identifier is not a parameter, local, or global` at the reference · found in review of D1999's fix · filed 2026-09-22 against master `5cd558915`**

Repro:

    extern function nowMillis(): i64
    const v = nowMillis
    print(v() > (0 as i64))
    // vl check: rc 0.  vl run: emitProgram: identifier is not a parameter, local, or global (2:7)

#### Mechanism

Not yet probed; a reading of the message, to be confirmed. The checker types an extern's name as a function value, so the reference
checks; the emitter's function-value path resolves a bare name against the defined functions,
parameters, locals and globals, and an extern is an IMPORT, which is none of them. A fix has
to give the import a function-value form (a funcref to the import, or a synthesised
forwarding function) wherever a defined function's name already gets one.

#### Ablation

| ingredient changed | outcome |
| --- | --- |
| as filed (an extern bound to a `const`) | emit reject, `identifier is not a parameter, local, or global` |
| a defined `function g(a: i32): i64` in the extern's place | runs, prints `true` |
| the extern CALLED inside a lambda (`const v = () => nowMillis()`) | emit reject, a different message: `call to unknown function` |

#### Grading list

The lambda row above is a sibling, not this defect: an extern called from any function body
of a module that uses a function value refuses with `call to unknown function` (found while
closing D1999). Re-grade it when this row closes; it may share the fix or need its own row.
