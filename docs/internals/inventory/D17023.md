### D17023 — struct `==` reads a place operand after the other operand's effects

**check-clean silently wrong · filed 2026-11-19 against master `e2afe038d`, found by IR-REV reviewing #9162 (D17022)**

Repro:

    type P = { a: i32, b: i32 }
    let p: P = { a: 1, b: 1 }
    function f(): P {
      p = { a: 2, b: 2 }
      return { a: 1, b: 1 }
    }
    print(p == f())
    // vl check rc 0; vl run prints false — the compare read `p` after `f` reassigned it.

Want:

    true

#### Mechanism

`emitStructEqRec` (`compiler/wasmEmit.vl`) compares field by field, re-reading a re-readable
place operand (`unionEqOperandOk`) from its root at each field. A place is not staged, so when the
other operand is a call that writes the place, the place is read after that call's effects rather
than before. With D17022's staging the call runs once, before every field read, so every field
of `p` is the new value; before it, the first field read the old `p` and later fields the new.

#### Ablation

| spelling | prints | needed? |
| --- | --- | --- |
| the repro | false | — |
| `f` does not write `p` | true | **yes**: the call writes the place |
| `const m = f()` then `p == m` | false, correctly | **yes**: the call is an operand of the compare |
| `f() == p` | false, correctly | **yes**: the place is the LEFT operand, read first in source order |
| `p != f()` | true | no: `!=` has the same defect |
| `f` writes only field `b` (`p = {a: 1, b: 5}`) | false | no |

#### Grading list

a nullable `P | null` place; a variant-row compare; a place reached through a field path
(`r.p == f()` with `f` writing `r.p`); D17022's fixture must keep running once.
