### D14811 — a by-rep result stored in a list literal read only for fields refuses

**closed · now runs, prints `4` then `4` · was a loud check reject, clause 2 (the refusal said `type-valid but not supported yet`) · the residue of [D14810](D14810.md) · filed 2026-11-01 against master `9d601ea5` · closed 2026-11-01 against master `88e31332`: a result stored as an element of a `const` list literal that is only indexed for a field reads the rep (`recInReadOnlyList`, check_fit_rules.vl), and a type parameter's identity argument is built where its source is (`cbaIdentityArg`, check_bind_adopt.vl) · fixture `soundness/built-container-read-returned-by-rep-stored-in-read-only-list-runs.vl` · comparing, an annotated parameter, `let`, a `const` of an element, a mixed list and a field literal are [D14819](D14819.md)**

Repro:

    type J = { f: i32 | null }
    function mk() { { f: 4 } }
    function back(r) { return r }
    const wideJ: J = mk()
    const xs = [mk()]
    const keep = [back(xs[0])]
    print(keep[0].f)
    print(wideJ.f ?? 0)

Want:

    4
    4

#### Mechanism

`xs`'s elements are built at `J`. A by-rep instance (D14532) serves a hole or type parameter whose
uses read the rep (`recParamTakesRep`). A value it returns reads the rep when the call's result is
read for a field, handed on by rep, or bound to a `const` read only for fields (`recRetTakesRep`).
Every other use hands a `J` on to a position typed `{f: i32}`. `recBuiltReadRefuse` refuses those
deliveries:

* storing the result in a list or a field, as in the Repro;
* comparing it with `==`;
* handing it to an annotated parameter;
* binding it with `let` or an annotation, or handing a `const` of it on;
* storing or capturing the parameter in the callee's own body.

#### Ablation

| ingredient removed | outcome | needed? |
| --- | --- | --- |

| `const wideJ: J = mk()` | runs | **yes** |
| a generic `back<T>(r: T): T` in place of the hole | still refused before the close | no |
