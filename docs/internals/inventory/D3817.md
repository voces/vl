#### Mechanism

`d` had no instance, because nothing calls it, so its template was emitted with the hole
parameter's default `i32` representation. Meanwhile the member call it holds was typed by
`describe`'s `string` result.

The owner's ruling, with the committee's changes, is now in the checker (`expParamInfer`,
`compiler/typecheck.vl`). An entry-module `export function` that no statement outside its own
body names gets each untyped parameter from the type all its PIN uses agree on:
- a member call whose name reaches one function with a concrete receiver;
- an argument to a function's concrete parameter;
- a `return`, or the body's tail, under an annotated result;
- an annotated binding it initializes.

Operators, literals, `==`, `.length`, field access, passing to a generic and an un-annotated
return pin nothing.

One agreed type annotates the parameter (re-checked), with a hint and a `--fix` that writes the
annotation. No pin, or two pins that disagree, is a check error at the parameter naming the
candidates or both sites. An overloaded member call keeps its own refusal. An uncalled exported
generic is refused in the same words, at check time when the checker can see it, and by the
emitter's floor for a re-export.

This changes programs that ran: an export like `e(x) { x * 2 }` ran at `i32` and is now an
error, which the owner accepted. One fixture relied on it and is annotated
(`functions/uncalled-inference-hole-param-pruned.vl`'s `addPub`). No distilled-corpus cell
moved.
