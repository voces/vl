### D16758 — an unwritten un-annotated `[]` binding handed to a generic `V[]` parameter builds invalid wasm

**closed 2026-11-16 by lane AE — the witness prints `0` · a call no longer pins an open list's element to the callee's own unbound type parameter (`constrainEmptyHold`); it binds that parameter at the element the row settles at (`settleHeldPins`) · fixture `tests/cases/soundness/open-list-binding-to-generic-list-parameter.vl` · residue D16759, D16760 · was check-clean invalid wasm · clause 1 · filed 2026-11-16 against master `5503e6f68`**

Repro:

    function probe<V>(v: V[]) { return v.length }
    const e = []
    print(probe(e))
    // vl run: prints 0 (was an invalid module: the top-level local was typed i32)

Want:

    0

#### Mechanism

`callFtyCheckArg` (check_calls.vl) pins an empty-collection argument from the parameter's expected
type (`constrainEmptyExpr`). With `V` not yet bound that type is `V[]`, so the binding's open row
took the callee's own `V` as its element: the caller's `e` became `V[]`, a type no caller can
build, and its local was laid out as `i32`. A literal argument hid it, since no later read sees the
literal's row. The pin now holds the callee's unbound type parameters open, and once every row has
settled the call binds each from the row's element.
