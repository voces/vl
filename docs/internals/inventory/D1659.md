### D1659 — a covariant list nothing writes is refused when an unrelated list of the destination's element type is written and the closure cannot follow the value

**loud emit reject · filed 2026-09-05 against master `d2d7518b6` · D1656's residue · 0 corpus cells**

Repro:

    type Circle = { r: i32 }
    type Sq = { s: i32 }
    type Shape = Circle | Sq
    function __other() {
      const w: Shape[] = []
      w.push({ s: 3 })
      print(w.length)
    }
    function hand(xs: Shape[]): Shape[] { xs }
    function take(ys: Shape[]) { print(ys.length) }
    function f() {
      const a: Circle[] = [{ r: 7 }]
      const b: Shape[] = a
      take(hand(b))
      print(a.length)
    }
    f()
    // vl check: rc 0.  vl run: emit error, covariant list delivery.

#### Mechanism

This program is legal and the copy is safe: nothing writes `b`'s list or `a`'s, `take` only
reads, and the converting copy is unobservable. It is refused because the licence is two
answers and both decline. `rlSlotEverWritten(dstSlot)` is REP-scoped — `__other`'s
`w.push` writes *a* `Shape[]`, so the destination row counts as written — and the per-value
answer that would override it is `covarValueWriteState`, which returns `2` because the closure
cannot follow a call result delivered to no name. Two conservative answers over the same
program, and neither is about this value.

The sharp half is the rep-scoped one: it is asked of the ELEMENT ROW, so any write to any list
of that element type anywhere in the program disqualifies every delivery into it. Closing this
is either making the per-value answer able to follow these deliveries (D1658's closure growth,
which would answer `0` here) or narrowing `rlSlotEverWritten` to writes that can reach this
value. D1656 is why the outcome is loud rather than an invalid module.

#### Ablation

| ingredient removed | outcome | needed? |
| --- | --- | --- |
| `__other` deleted | runs, prints 1 | **yes (an unrelated write to the dest row)** |
| `take(hand(b))` replaced by `take(b)` | runs, prints 1 | **yes (the unfollowable delivery)** |
| `take`'s body given `ys.push({ s: 3 })` | emit reject, and the write really does reach (D1658) | no |
| `__other`'s `w` declared `Circle[]` and pushed a `Circle` | emit reject | no (either row disqualifies) |

#### Grading list

Two witnesses that must RUN after a close: the one above, and the read-only second name —
the same `__other`, `const sf: Box = { xs: b }`, `const sf2 = sf`, then reading
`sf2.xs[0]` under `is Circle`. The control that must keep running either way is the same
program with `__other` deleted, which runs today. D1658's writing witnesses must NOT run.
