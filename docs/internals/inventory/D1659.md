### D1659 — a covariant list nothing writes is refused when an unrelated list of the destination's element type is written and the closure cannot follow the value

**closed 2026-09-06 · was loud emit reject · filed 2026-09-05 against master `d2d7518b6` · D1656's residue · 0 corpus cells**

Repro:

    type Circle = { r: i32 }
    type Sq = { s: i32 }
    type Shape = Circle | Sq
    function __other() {
      const w: Shape[] = []
      w.push({ s: 3 })
      print(w.length)
    }
    function hand(xs: Shape[]): Shape[] { xs }
    function take(ys: Shape[]) { print(ys.length) }
    function f() {
      const a: Circle[] = [{ r: 7 }]
      const b: Shape[] = a
      take(hand(b))
      print(a.length)
    }
    f()
    // vl check: rc 0.  vl run: prints 1 then 1.

#### Mechanism

This program is legal and the copy is safe: nothing writes `b`'s list or `a`'s, `take` only
reads, and the converting copy is unobservable. It was refused because the licence is two
answers and both declined. `rlSlotEverWritten(dstSlot)` is REP-scoped — `__other`'s `w.push`
writes *a* `Shape[]`, so the destination row counted as written — and the per-value answer that
overrides it, `covarValueWriteState`, returned `2` because the closure could not follow a call
result delivered to no name.

Closed on the per-value side, which is the one that decides: a definite `0` grants the licence
whatever the rep row says, so the rep-scoped scan needs no narrowing once the closure can
answer. `hand`'s return is delivered to `take`'s PARAMETER, which is a name — `cwArgParamName`
resolves it, `cwGrow` binds `ys` into the set, and `cwReturnConsumed` counts a call consumed
that way, so the accounting pass claims the return instead of declining it. The read-only
second name is the container half of the same growth (D1658), and a `for … in` over the value
joined the whitelist for the same reason an index read is on it: the loop binds elements, not
the list.
