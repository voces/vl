### D4170 — a generic's `if` join of a `string | null` pin and a string literal drops its null at `??`

**closed · runs, prints `n` `z` · was check-clean silently wrong, clause 1 · closed by keeping `emit_rewrite`'s `x ?? d` fold off an operand whose template type is open, so the instance decides whether the default is dead · fixture `generics/if-join-of-a-nullable-pin-keeps-its-coalesce.vl` · found by the D3336 position matrix (`{match,chain,two}_generic_coal_un`) · filed 2026-10-11**

Repro:

    function g<T>(a1: T, k: i32) {
      const v = if k == 1 { a1 } else { "z" }
      print(v ?? "n")
    }
    const x1: string | null = null
    g(x1, 1)
    g(x1, 2)
    // vl check: rc 0.  vl run: prints `null` then `z`

Want:

    n
    z

#### Mechanism

The template types `v` as `T | string`. `emit_rewrite` folds `x ?? d` to `x` when the operand's
type excludes `null` and it is no read of an open binding. `tyExcludesNull` counts the type
parameter as non-null, and `readOfOpenBinding` sees only an annotated binding, so the shared body
lost its `??` before any instance was lowered. The `null` pin then printed its `null` through.
