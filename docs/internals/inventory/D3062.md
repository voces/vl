    function f1<T>(x: T) { f2(x) }

#### Mechanism

A generic body that prints or interpolates a value of its type
parameter records a deferred constraint (`notePrintCstr` and its interpolation twin), and each
call site re-validates the callee's constraints under its binding (`validatePrintCstrs`,
re-recorded under the caller's parameter when the binding is still open). The constraints are
recorded while the callee's BODY is checked, so a call checked before that body finds none: with
`f2` declared first the program is refused (`` `f1` prints its type parameter here: print expects
one scalar or string value … got R ``), with `f1` first it is accepted and miscompiles. The
emitter's output for such a program varies with the pin: invalid wasm at a record or a list,
a wrong value at `boolean | null` (`[true]` for `null`), a trap at `string | null`. Every
deferred table has the same shape, so every family was order-dependent. The close walks, before
pass 2 checks each top-level statement, the generic declarations that statement names and that
no earlier statement reached, placing each after the ones its own body names, and checks each
body quietly so only its constraint rows survive; a cycle among them iterates while a table
grows. Walking at the statement rather than before pass 2 lets a body see the module values the
statement sees: a pre-pass saw an un-annotated global as its placeholder and stayed
order-dependent there. Re-recording a callee's rows in a caller mints fresh arena copies, so
the tables now compare rows structurally (`tyEqSameHoles`); without that a cycle of 40 generics
cost 3.0e9 guest fuel to check instead of 7.3e7. Deduplicating rows structurally also
collapses two destination rows of one owner that differ only in the binding they name, so a
nested generic sharing its enclosing parameter's name ([D3081](D3081.md)) can report one message
where master reported two, and the one kept can name the wrong binding; the verdict is
unchanged. Keeping the name in the key doubles the guest fuel of a chain whose bodies name each
destination differently (2.04x on the review's `heavy_50_20`, 1.97x on `h_60_6`), so it is not
kept.
