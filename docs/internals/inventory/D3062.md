### D3062 — a call to a generic declared later in the file skips that generic's deferred `print` and interpolation checks

**check-clean invalid wasm · clause 1 · open · 1,000 oracle-refused cells of lane GF's forwarding grid when the caller is declared first, all of them `check reject` with the order reversed · the same on master `6c2dafc0b` · filed 2026-09-28 against master `6c2dafc0b`**

Repro:

    type R = { a: i32 }
    function f1<T>(x: T) { f2(x) }
    function f2<T>(x: T) { print(x) }
    const v: R = { a: 5 }
    f1(v)
    // vl check: rc 0.  vl run: invalid module inside `f2`

#### Mechanism

Not localised past the ablation. A generic body that prints or interpolates a value of its type
parameter records a deferred constraint (`notePrintCstr` and its interpolation twin), and each
call site re-validates the callee's constraints under its binding (`validatePrintCstrs`,
re-recorded under the caller's parameter when the binding is still open). The constraints are
recorded while the callee's BODY is checked, so a call checked before that body finds none: with
`f2` declared first the program is refused (`` `f1` prints its type parameter here: print expects
one scalar or string value … got R ``), with `f1` first it is accepted and miscompiles. The
emitter's output for such a program varies with the pin: invalid wasm at a record or a list,
a wrong value at `boolean | null` (`[true]` for `null`), a trap at `string | null`.

#### Ablation

| ingredient changed | outcome | needed? |
| --- | --- | --- |
| `f2` declared before `f1` | check reject, the direct spelling's words | **yes** (the order) |
| `f1(x)` and `f2(x)` holes | invalid wasm | no |
| `function f1(x: R)`, a non-generic caller | invalid wasm | no |
| `print("[\{x}]")` at `boolean \| null` | prints `[true]` for `null` | no |
| `f2(v)` called directly | check reject | **yes** (a generic caller between) |
