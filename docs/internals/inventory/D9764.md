### D9764 — a returned `let` list of un-annotated functions written whole before the return, handed to an un-annotated parameter, is refused as an argument type

**loud emit reject · `vl check` rc 0 · `monomorphize: unsupported argument type for `a` in a call to `take`` · clause 2 · found closing [D9716](D9716.md) · present on master `e8163edd5` · filed 2026-10-22 against master `60aaa08c0`**

Repro:

    function inc(a) { return a + 1 }
    function dbl(a) { return a * 2 }
    function deliver(_n) {
      let u = [inc, dbl]
      u = [dbl, inc]
      return u
    }
    function take(a) { print(a[1](3)) }
    take(deliver(1))
    // vl check rc 0.  vl run: emit error: emitProgram: monomorphize: unsupported argument type for `a` in a call to `take`

Want:

    4

#### Mechanism

Not traced. [D9716](D9716.md)'s close reads a returned `let` as the list literal it is bound to,
and declines when the `let` is written whole, because the value at the return may then be another
literal. The argument pin has no other way to read the returned list's elements. The call bound
first (`const v = deliver(1)`, `v[1](3)`) and an annotated parameter of `take` both run.

#### Ablation

| ingredient removed | outcome | needed? |
| --- | --- | --- |
| the whole write (`u = [dbl, inc]`) | runs, `6` | **yes** |
| the argument position (`const v = deliver(1)`, `v[1](3)`) | runs, `4` | **yes** |
| the un-annotated parameter of `take` | runs, `4` | **yes** |

#### Grading list

The nested twin; a `let` written whole in a branch.
