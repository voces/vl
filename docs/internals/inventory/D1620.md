### D1620 — a closure returned through TWO inferred-return hops classifies as `i32`

**closed · filed 2026-09-05 against master `153760e1` · closed against `ef92ad0c`**

`blockTailIsClosure` asks the ARENA before the syntax. Both `return_inferred` faces run, the
matrix skip is deleted, and 14 of the 15 cells of this row's grid run — the fifteenth is the
nullable rep, filed as D1622.

Repro:

    function mk() {
      return (n: i32) => n + 1
    }
    function deliver() {
      return mk()
    }
    const v: (i32) => i32 = deliver()
    print(v(54))
    // vl check: rc 0.  vl run: the emitted module failed to validate inside `deliver`:
    // type mismatch: current function requires result type [i32] but callee returns [(ref (id 0))]

#### Mechanism

`exprIsClosureNoLocal` — the restricted predicate return-kind classification uses, because
the full `exprIsClosure` would recurse through the not-yet-built locals registry — has arms
for `Paren`, `FuncDecl`, `Ident` and `ObjLit`, and **no `Call` arm**. So `blockTailIsClosure`
reads `deliver`'s tail `return mk()` as not-a-closure and `deliver`'s inferred result valtype
falls to the `i32` default, while the body actually pushes the `(ref $cloStruct)` `mk` handed
back. One hop is fine: `const v = mk()` classifies through `exprIsClosure`'s own `Call` arm,
which asks `fnReturnsClosure`. It is the SECOND hop — a call in RETURN position, where only
the restricted predicate is available — that has no rung.

**THE RECURSION BOUND THIS ROW ASKED FOR IS NOT NEEDED, and the probe is what said so.**
Instrumenting the inferred-return arm of `emitTypeSection` to print the checker's answer beside
the emitter's, for the function whose result is wrong:

    D1620RUNG fn=deliver ti=1 retExpr=11 CHECKER-arenaTy=(i32) => i32
              CHECKER-nodeTyIsFunc=T EMITTER-inferredRetKindCore=i32 EMITTER-fnReturnsClosure=F

The two faces disagree in exactly the failing cells and agree in the neighbours: `string` reads
`str`/`str` and `i32[]` reads `list`/`list`, both of which run. **The checker recorded the
function type all along.** So the rung is one structural arena read (`nodeTyIsFunc`), not a
syntactic descent through the callee — no recursion, and therefore no bound to get right. It is
also exact by construction: `nodeTyIsFunc` excludes a `TyArray` and a `TyNullable`, so a func
ARRAY and a nullable closure keep their own reps rather than being emitted as `(ref $cloStruct)`.

#### Ablation

Every row is `vl check` rc 0.

| ingredient removed | outcome | needed? |

| the second hop (`const v = mk()` direct) | runs, 55 | **yes** |
| the annotation on `v` (un-annotated face) | `emitProgram: call to unknown function` | no — it moves the cell from clause 1 to clause 2 |
| the lambda's capture (there is none here) | n/a — the witness never captures | no |
| an annotated `function deliver(): (i32) => i32` | runs, 55 | **yes** — the annotation is what `fnReturnsClosure`'s first rung reads |

The capture is deliberately absent: D1608's `emitProgram: call to unknown function` used to
fire on this shape first and mask it, and this row is what the D1608 fix unmasked. The
no-capture witness above fails identically on master `153760e1`, before that fix, which is
what makes the two rows independent.
