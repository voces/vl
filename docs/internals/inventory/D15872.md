### D15872 — a list literal or an `if` that joins an existing record with a narrower declared record emits an invalid module

**now a loud check reject · was check-clean invalid wasm, clause 1 · each list element and each value `if` arm is held to the width floor a binding of it is (`listElemDropsLayout`, check_container_lits.vl; `ifArmDropsLayout`, check_node_rules.vl), so an existing record of another layout is refused; a layout-prefix pair still runs · the refusal is the one this design owes, DECISIONS "Width subtyping of an existing record" (one storage, one layout) · fixtures `tests/cases/objects/error-record-join-two-layouts.vl`, `tests/cases/objects/record-join-layout-prefix-runs.vl` · found by the width-slot lane (w315) · filed 2026-11-12 against master `9575031c0`**

Repro:

    type Pos = { x: f64, y: f64 }
    type A = { k: i32, x: f64, y: f64 }
    const a: A = { k: 7, x: 2.0, y: 3.0 }
    const z: Pos = { x: 1.0, y: 2.0 }
    const arr = [a, z]
    print(arr[1].x)
    // vl check (filed): rc 0.  vl run: invalid module (the emitted module failed to validate)

#### Mechanism

The join of `A` and `Pos` is accepted as the narrower record, but each element keeps its own
struct type, and no width conversion is built for the element of the other shape: the list's
`array.new_fixed` receives a struct of an unrelated type. An annotated destination
(`const arr: Pos[] = [a, z]`) is refused at the delivery; an annotated `if`
(`const w: Pos = if c { a } else { z }`) is not, and fails the same way.

#### Ablation

| ingredient removed | outcome | needed? |
| --- | --- | --- |
| the element order (`[z, a]`) | still invalid | no |
| `z`'s annotation (a literal `{ x: 1.0, y: 2.0 }` in its place) | still invalid | no |
| the element read (`arr.length` only) | still invalid | no |
| the list (an `if` choosing `a` or `z`, bound un-annotated or at `Pos`) | still invalid | no |
| the annotation `Pos[]` on `arr` | loud check reject | **yes** (its absence) |

#### Grading list

The `if` spelling, annotated and not; `[a, z]` delivered as an argument to a `Pos[]` parameter;
the matrix cells `slot_feeds_join` and `mixed_list` (`existing-record-into-narrow-record`).
