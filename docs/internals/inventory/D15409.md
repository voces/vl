### D15409 — a `let` written from two parameters carrying different generics, one parameter also called directly at another type, runs only through the split plan

**runs today and must keep running · runs only through the split plan: with it off (`compileSrc` returning after its first compile) a loud emit reject, `monomorphize: parameter `a` of `one` is called at two function types that no parameter per type separates` · split-plan group F, the residue of D15122 and D15123 · found by the plan-off census at `3f036bfe` (architecture-target-2026-10.md §3.2) · filed 2026-11-05 against master `3f036bfe`**

Repro:

    function id<T>(x: T): T { x }
    function dup<T>(x: T): T {
      print("dup")
      x
    }
    function one<F>(a: F, c: F, k: boolean) {
      let b = a
      if k { b = c }
      print(b(3) + 1)
      print(a("x"))
    }
    one(id, dup, true)

Want:

    dup
    4
    x

#### Mechanism

`b` is written from `a` and `c`, which carry different generics at the call, so it keeps the
written binding's set (D15123's close holds the initialiser's value only where every source carries
the same generic). Calling `b` at `i32` delivers `a` into that set at `(i32) => i32`, while
`a("x")` calls the same parameter at `(string) => string`. Mono's pin of `a` then has two
function types, and with the plan off nothing gives `a` a parameter per type. The plan splits `a`.
Without it, the call must pass `id` as a value of the set at one signature and call `id` directly
at the other, which is the per-instance identity of a parameter's carried generic.
