### D3849 — a call through a `let` alias whose chain is written after its initializer must reach the written value, not the lambda the chain was initialized with

**runs today and must keep running · a refutation pin: #3442 at `acdc4c8ad` printed `aC` twice · found in work on the rv3442b residue · filed 2026-10-08 against master `7eca4407b` · pins: `tests/cases/closures/hole-lambda-alias-written-values.vl`**

Repro:

    function f(x: string) {
      const c = (y) => y + "C"
      const e = (y) => y + "E"
      let d = c
      print(d(x))
      d = e
      let d2 = d
      print(d2(x))
    }
    f("a")
    // vl check: rc 0.  vl run: rc 0

Want:

    aC
    aE

#### Mechanism

The alias walk resolves `d2` through its initializer `d` to `c`, the lambda the chain was
initialized with, to pin `c` at the call's arguments. #3442 then let the instance machinery
re-spell the call to `c`'s instance, since `d2` itself is never written, so the call skipped
the value `e` that `d` held. A call resolved through a chain any link of which is assigned
(`monoAliasChainWritten`, by name, so the safe direction) now keeps its function-value call and
only pins the lambda (`monoNoRename`). An unwritten chain still re-spells, which a lambda
called at two types needs.

#### Ablation

| ingredient removed | outcome | needed? |
| --- | --- | --- |
| the write `d = e` | prints `aC` twice, correctly | **yes** |
| the second alias (`print(d(x))` after the write) | prints `aE` | **yes** |
