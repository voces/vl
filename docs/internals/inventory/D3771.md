### D3771 — an error type reaching an inferred return is reported again as "cannot infer a return type", in the function and in every caller and importer that infers from it

**loud check reject · open, a fix was tried in lane DX (#3402) and withdrawn · filed 2026-10-06 against master `e2443d6b2`**

Repro:

    // file: terrain.vl
    export function height(x: f64) { return nope(x) }
    // file: entry.vl
    import { height } from "./terrain"
    function above(x: f64) { return height(x) + 1.0 }
    function twice(x: f64) { return above(x) * 2.0 }
    const xs = [1.0, 2.0].map((x) => height(x))
    print(twice(1.0))
    print(xs.length)
    // vl check: undeclared identifier 'nope', then "cannot infer a return type" for
    // 'height', 'above', 'twice' and the lambda ''. Only the first is a cause.

#### Mechanism

`finishInferredReturn` refuses a return that saw only error types (`inferSawErr`) unless the
function's own parameters or a bare `{}` explained it. Two kinds of error type reach it. One is
minted beside a diagnosed error, and then the refusal is its echo, in the function and in every
caller and importer whose return infers from it. The other is a recursive cycle's, which no
diagnostic explains: any read of a callee's still-pending return (`-2`) yields `TY_ERR`
silently. Only the second needs the refusal, so a fix has to tell the two apart by where the
error type came from.

The withdrawn attempt parked the refusal in `T.diags` under a pending code, which a speculative
rollback discards. `noBasisFlush` kept it only when no other error stood. Cycles were marked in
`inferCycleFns` at the cycle break and at `checkCallOnFuncTy`'s pending read. Review found
silent pending reads the marking missed, and each one hid a real cycle error behind any
unrelated error. `noteInferCycle` marked only the top of `inferStack` and skipped a lambda's `""`
name, so a cycle through a lambda escaped. `opIdxRetTy`, `ufcsInferCallee`, `opIdxFnFor`,
`opSelfFnKeyFor`, `opSelfFnTy` and `getterReadTy` read pending returns without marking anything.
An earlier round's rule, that any error raised in the body was the cause, hid a base-case-less
recursion behind an unrelated `v = 2.5` in the same body.

Reviewer's suggested fix: route every pending-return read through one helper, which marks every
named frame on `inferStack` (not only the top) as cycle-reached. Then a parked refusal is sound
exactly when its function is unmarked. Re-grade every witness below, each alone and beside an
unrelated `const zz: i32 = "s"`. All must report the cycle both ways.

#### Ablation

Each cycle witness below must keep its own refusal beside an unrelated error. The withdrawn
attempt lost it in every one of these:

| witness | cycle reached through |
| --- | --- |
| `type V = { a: i32 }` `function "[]"(self: V, i: i32) { return self[i] }` `print(v[0])` | `[]` operator, `opIdxRetTy` |
| `function "+"(self: V, o: V) { return self + o }` `print(v + v)` | `+` operator |
| `function f(self: i32) { return self.f() }` | method call, self |
| `function a(self: i32) { return self.b() }` `function b(self: i32) { return self.a() }` | method call, mutual |
| `function f(n: i32) { return [1, 2].map((x) => f(x))[0] }` | a `map` lambda |
| `function f(n: i32) { const h = (k: i32) => f(k); return h(n) }` | a local lambda |
| the local-lambda one in another module, the unrelated error in the entry | the same, across modules |
| `ping`/`pong`, self, mutual `a`/`b`, `let r = f(n); return r`, `v = 2.5` in the body | covered by the attempt |
