### D2917 — a list adopted into a declared record list, whose element is not an object literal, keeps the other record's row

**now a loud emit reject · clause 2, still open · was check-clean invalid wasm, the same on master `a41bd80e8` · the element that is not an object literal is refused (`rsBuiltElemRefuse`) · fixture `tests/cases/soundness/error-reseated-record-list-built-element.vl` · found by the #3235 review · filed 2026-09-27 against master `0284dc2a8`**

Repro:

    const i: { f: i32 } = { f: 4 }
    type I = { f: i64 | null }
    function mk() { { f: 7 } }
    const il = [mk(), { f: 3 }]
    const ic: I[] = il
    print(ic[0].f)
    print(ic[1].f)
    print(i.f)
    // vl check: rc 0.  vl run: invalid module in the top-level code

Want:

    7
    3
    4

#### Mechanism

A call result in the list is a record the call already built at the `{ f: i32 }` row, so no
choice of row for the literal fixes it: the element needs a converting copy into `I`. D2881
re-seats the list only when its first element is an object literal (`letRecordListDestSlot`),
so `[mk(), { f: 3 }]` builds at the call's row; `[{ f: 3 }, mk()]` is re-seated at `I`'s row and
then stores the call's `{ f: i32 }` record into it.

#### Ablation

| ingredient removed | outcome | needed? |
| --- | --- | --- |
| the `{ f: i32 }` record | runs | **yes** |
| the call (`[{ f: 7 }, { f: 3 }]`) | runs, prints `7` `3` `4` | **yes** |

#### Grading list

`[{ f: 3 }, mk()]` and `[mk()]` beside the same prelude, both invalid wasm on master and on
#3235. A 54-program grid (nine element spellings — a call first, second or alone, an annotated
call, an un-annotated or annotated binding, the annotated global itself, and two object
literals as the control — by the six adopting destinations of D2914's grid) graded against
master `a41bd80e8`: 48 invalid modules become loud emit rejects and the 6 controls still run.
The refusal fires only where the destination's record differs from the elements' own, so a
destination of the same record made nullable still runs. Making these run needs the element's
source built at the destination's row (an un-annotated binding or return) or a converting copy,
which a shared record does not have (DECISIONS.md "Record depth covariance"; the pinned face is
D2100's question). Declaring the source at the destination's record (`function mk(): I`) runs.
