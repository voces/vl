#### Mechanism

Traced 2026-11-25 by SOUND. The same program with the parameter annotated (`v: { d: i32 }`) is
the check refusal "{d: i32} is not A: they store field `d` differently … a record is shared, not
copied, so only a fresh record widens", and that is the design's answer here too: `v` escapes into
`held`, typed `{d: i32}`, so no one row can hold the record for both. The hole spelling passes
check because the call of an inferred function is classed as a result the destination may adopt
(D14736's `recInferredFnOf` route) even where `recHoleIdentityArg` declines the body, and emit then
declares the parameter at the literal's row and the result at `A`'s. The close is that refusal, not
`runs`: the row's `Want` names the contract.
