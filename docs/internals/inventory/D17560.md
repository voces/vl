### D17560 — a hole identity whose parameter escapes or is rebound, delivered wider, builds invalid wasm

**check-clean invalid wasm · clause 1 · found grading D17047's close · owner SOUND · filed 2026-11-25 against master `5ca3e2eb`**

Repro:

    type A = { d: i32 | null }
    let held = { d: 0 }
    function keep(x) { held = x }
    function g(v) {
      keep(v)
      return v
    }
    const c: A = g({ d: 5 })
    print(c.d ?? -1)
    print(held.d)
    // vl check: rc 0.  vl run: invalid module inside `g`

Want:

    5
    5

#### Mechanism

`recHoleIdentityArg` (check_fit_rules.vl) adopts the literal argument at the destination's record
only when the body uses the parameter as a field's receiver (D17047). A body that hands the
parameter to a call, stores it, or rebinds it declines, and the instance then declares the
parameter at the literal's row and the result at the destination's, as D17047 did. Adopting here
is not enough on its own: the escaped value is also read at the literal's row (`held.d`).

#### Ablation

| spelling | outcome |
| --- | --- |
| `keep(v)` (handed to a call that stores it) | invalid inside `g` |
| `v = { d: 3 }` (the parameter rebound) | invalid inside `g` |
| `print(h(v))` with `h(x) { return x.d }` | invalid inside `g` |
| `print(v.d)`, `v.d = 7`, an alias's field write | runs (D17047's close) |
| the `: A` on `c` | runs |
