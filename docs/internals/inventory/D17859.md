### D17859 — a function set's row is found by the first row the tag map holds for it, in insertion order

**runs today and must keep running · index-order reader, harmless while nothing reorders the map: S2b keys the reverse map by set when it touches the writers (coordinator ruling) · filed 2026-11-28 against master `8109888ab` · owner COV-IS**

Repro:

    function a(x: i32) { return x + 1 }
    function b(x: i32) { return x * 2 }
    const fs = [a, b]
    const g = fs[1]
    print(g(5))
    print(fs[0](5))
    // vl check: rc 0.  vl run: 10, 6

Want:

    10
    6

#### Mechanism

`fnTagSetTy(s)` (`check_elab_cap.vl`) answers "the row of set `s`" by iterating `elabFnSetTy.keys()`
and returning the first function row tagged `s`. Several writers call it before minting a joined
row so one set keeps one row; which row they get is the map's insertion order, a fact about when
rows were tagged, not about the set. A copy-on-tag (D17858's close) or any reordering would change
the answer. The close is a map from set id to its row, written where a set's row is minted.
