### D2875 — an un-annotated copy of a null-narrowed value union reads its complement arm at the wrong rep

**check-clean invalid wasm · clause 1 · found by the D2874 grid (its nullable position) · filed 2026-09-27 against master `460a67010`**

Repro:

    function mkn(b: boolean): string | i32 | null {
      if b { return "a" }
      3
    }
    const u = mkn(false)
    if u != null {
      const t = u
      if t is string { print(t) } else { print(t + 1) }
    }
    // vl check: rc 0.  vl run: invalid module — expected i32, found (ref $type)

Want:

    4

#### Mechanism

Not localised past the ablation. `u` is `string | i32 | null` narrowed to `string | i32` by the
null test, and `t` is its un-annotated copy. The `else` arm narrows `t` by complement, and its
read is lowered as though the storage were not the box it is: over `string[] | i32[]` the same
program reads `expected (ref null $type), found (ref $type)`. D2874's rewrite annotates the
`const` it binds, which is why it does not reach this.

#### Ablation

| ingredient removed | outcome | needed? |
| --- | --- | --- |
| the copy (narrow `u` itself) | runs, prints `4` | **yes** |
| an annotation on the copy (`const t: string \| i32 = u`) | runs | **yes** |
| the complement arm (`if t is i32 { … }` only) | runs | **yes** |
| the `null` member (a non-nullable union) | runs | **yes** |
| the scalar members (`string[] \| i32[] \| null`, `.length`) | invalid wasm | no |

#### Grading list

The list spelling (`string[] | i32[] | null` with `t.length` in both arms), and the copy inside
a function body rather than at module scope.
