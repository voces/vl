### D14532 — a value read out of a built container and handed on at its own type refuses: the destination does not take the value's rep

**closed · now runs, prints `40` / `4` · was a loud check reject, clause 2 · filed 2026-10-27 against master `41c611055` · closed 2026-10-31 against master `ffda5d24` by the coordinator's ruling (i), an extension of c-2: a read out of a built container, handed to an annotated record parameter that its non-generic function only reads or writes for a field, notes the argument's rep (`recAnnArgTakesRep`, check_fit_rules.vl), the function is instanced per rep (`monoIsGenericDecl` reads `recRepFnHas`), and the copy's parameter is pinned at the rep (`monoPinAnnotatedParam`) while the elaboration types it at the declared type · the container handed on whole, a `??` read with a literal default and the positions that store the value are [D14738](D14738.md) · fixtures `soundness/built-container-read-handed-to-annotated-callee-runs.vl`, `soundness/built-container-read-handed-to-open-param-runs.vl`**

Repro:

    type J = { f: i32 | null }
    function mk() { { f: 4 } }
    function g(r: { f: i32 }) { r.f * 10 }
    const wideJ: J = mk()
    const xs = [mk()]
    print(g(xs[0]))
    print(wideJ.f ?? 0)

Want:

    40
    4

#### Mechanism

`const wideJ: J = mk()` builds `mk`'s record at `J`, so the list `xs` is built at `J[]`
([D14518](D14518.md)). The checker types `xs[0]` at its own type `{f: i32}`, which `g` accepts, but
the value is stored at `J`, whose field `f` is a nullable box. `g` is compiled at `{f: i32}`'s
storage only and is not instanced at `J`, so `recBuiltReadRefuse` refuses the read: `this {f: i32} is stored at J … is type-valid but not supported yet`.

The family is every own-storage delivery of a built container or a read out of one. That covers an
element by index or `.get` (with `??`), a field of a built record binding, and the container itself
(`hs(xs)` with `hs(o: { f: i32 }[])`). `soundness/error-built-container-read-handed-on-at-own-type.vl`
holds five members.

#### Close

Rep flow, as c-2 rules it: type and rep are separate facts, and a value keeps its one rep `J`.
Sequenced after c-2, on lane a4cf's per-instance rep flow; this row is owned by that lane. Not a
converting copy: a record is a shared reference, and a copy would need a second producer deciding
when a reference may silently become a value.

The delivery positions split in two:

- **Rep-taking** destinations take `J`. These are a `let`, annotated or not, an inferred return,
  and a callee parameter, through the callee instanced at the received rep. All five fixture
  members are callee parameters and become runs.
- **Fixed-storage** destinations have no way to take `J`. These are a declared-struct field, an
  annotated module global, a closed fn slot and an exported signature. Their refusal stays
  clause 2, worded as it is today.
