### D14532 — a value read out of a built container and handed on at its own type refuses: no converting delivery exists

**open · loud check reject · clause 2 (the refusal says `type-valid but not supported yet`) · filed 2026-10-27 against master `41c611055`**

Repro:

    type J = { f: i32 | null }
    function mk() { { f: 4 } }
    function g(r: { f: i32 }) { r.f * 10 }
    const wideJ: J = mk()
    const xs = [mk()]
    print(g(xs[0]))
    print(wideJ.f ?? 0)

Want:

    40
    4

#### Mechanism

`const wideJ: J = mk()` builds `mk`'s record at `J`, so the list `xs` is built at `J[]`
([D14518](D14518.md)). The checker types `xs[0]` at its own type `{f: i32}`, which `g` accepts, but
the value is stored at `J`, whose field `f` is a nullable box. Delivering it to `g` needs a copy that
rebuilds the record at `g`'s storage. No delivery site makes one, so `recBuiltReadRefuse` refuses the
read: `this {f: i32} is stored at J … is type-valid but not supported yet`.

The family is every own-storage delivery of a built container or a read out of one. That covers an
element by index or `.get` (with `??`), a field of a built record binding, and the container itself
(`hs(xs)` with `hs(o: { f: i32 }[])`). `soundness/error-built-container-read-handed-on-at-own-type.vl`
holds five members.

#### Close

Make the converting copy at the delivery, through the same rule that already widens a record or a
ref list at a delivery, rather than a new site family. Then lift `recBuiltReadRefuse` and turn the
fixture's five refusals into runs.
