### D3916 — a generic function stored into a parameter's list, an inferred local's list or a map's value inside a generic traps with `indirect call type mismatch`

**closed 2026-10-09 by lane SC · runs · was loads then traps · found in review of #3484 (`rv3484/m`: m01–m07; c01, c03, c05 are the concrete controls) · filed 2026-10-09 against master `09d7de908` · pins: `tests/cases/generics/generic-function-stored-through-parameter-inferred-local-and-map.vl`**

Repro:

    function c<U>(y: U) { print("c"); print(y) }
    function st<T>(fs: ((t: T) => void)[], x: T) {
      fs[0] = c
      fs[0](x)
    }
    const fs: ((t: string) => void)[] = [(t: string) => print(t)]
    st(fs, "s")
    // vl check: rc 0.  vl run: wasm trap: indirect call type mismatch, in `st`

Want:

    c
    s

#### Mechanism

#3484 coerces a function value stored into a slot by reading the slot's type off an annotated
local's annotation, as the instance spells it (`monoStoreAnnName`). Three roots named the type some
other way, and each trapped at one instance: a parameter (m01, m02), an un-annotated local whose
type is inferred (m03, m04), and a map's value (m05–m07).

Closed in `monoLocalAnnName`:
- a parameter's annotation is read as the instance spells it;
- an un-annotated local's inferred type is read at the instance's bindings (`monoPinSubTyOf`);
- an index into a map reads the map's value type;
- `.set(k, v)` coerces `v` at it.
