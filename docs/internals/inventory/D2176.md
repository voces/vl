**closed — `emitExprAsI64` and `emitExprAsF64` lower an integer literal of any radix, bare or negated, straight in the wide rep (`pendingI64`/`pendingF64`), the rule a module const's initializer already used · was check-clean silently wrong · filed 2026-09-23 against master `a453c09c5` + #3057, found reviewing #3057 (whose global path made the module spelling right and left the local one wrong) · closed 2026-09-23 in #3057 · `tests/vl_immutable_const_global_test.ts`**

#### Mechanism

A hex (or binary, octal) literal up to 32 bits lowers as the i32 with that bit pattern, so
`0xFFFFFFFF` is `i32.const -1`. Delivered to an `f64` slot, `emitExprAsF64` re-encoded only a
DECIMAL literal as `f64.const` and sent the rest through `f64.convert_i32_s` (-1); delivered
to an `i64` slot, `emitExprAsI64` re-encoded a bare literal but sent `-lit` through the i32
negation and `i64.extend_i32_s` (`0 - -1` = 1). The module-global path seeds `pendingI64`/
`pendingF64` on the literal instead, and `emitNumLitNode` then encodes the literal's own value.

#### Ablation

| ingredient changed | outcome | needed? |
| --- | --- | --- |
| a decimal literal (`4294967295`) | right value | **yes** (a non-decimal radix) |
| `const h: i64 = 0xFFFFFFFF` (no `-`) | right value | **yes** for i64 (the negation) |
| a module `const` in place of the local | right value (after #3057) | **yes** (a function-body delivery) |
