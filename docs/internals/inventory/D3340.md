### D3340 — a literal list that is pushed another literal is refused as a mutable list when a wider record list is declared for it

**loud check reject · clause 2 · open · identical on master `2b30e3674` · 4 cells of the adoption grid (`push_lit` × four field pairs) · found by the record-covariance lane · filed 2026-09-30 against master `2b30e3674`**

Repro:

    type J = { f: i32 | null }
    const il = [{ f: 4 }]
    const ic: J[] = il
    il.push({ f: 5 })
    print(ic.length)
    // vl check: {f: i32}[] is not J[]: a container never widens implicitly, and only a readonly
    // list is covariant

Want:

    2

#### Mechanism

The container rule treats a literal `const` whose contents are stored into as vouching for
nothing ("No implicit container widening": a stored-into literal is judged at its own type), so
the delivery is refused before the record storage rule asks whether the list holds only fresh
records. Every value `il` ever holds is a literal, so under the record-covariance ruling it would
adopt `J[]` and run, as the same program with the `push` before the delivery already does.

#### Ablation

| ingredient removed | outcome | needed? |
| --- | --- | --- |
| `il.push({ f: 5 })` | runs, prints `1` | **yes** |
| the push moved above `const ic` | runs, prints `2` | **yes** |
| `il.push(i)` with `const i: { f: i32 }` | refused, rightly | no |

#### Grading list

The same with `ic[0] = { f: 6 }` in place of the push, and with a `let` list.
