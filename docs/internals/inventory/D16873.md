### D16873 — an un-annotated lambda handed to a generic at module scope, whose body passes its parameter to a function, is checked at another call's closed lambda parameter type

**closed 2026-11-16 · runs, prints `8` `a!` · was loud check reject, `vl check` rc 1, `argument of type string flows into dbl expecting i32` (`dbl` written in backticks in the message) · clause 2 · fixed in check_cstr_rows.vl: a hole argument's bound now keeps the argument node it came from (`noteArgCstrFrom`, `argCstrFromOf`), so `validateArgCstrs` skips it at another call of the same callee, as [D16855](D16855.md)'s guard does for an operator bound · pin: `tests/cases/generics/lambda-to-generic-arg-at-one-call-judged-at-another-call.vl` · found grading the D16855 fix · filed 2026-11-16 against master `ee6e3a4d6`**

Repro:

    function sel<A>(f: (x: A) => A): (x: A) => A { return f }
    function dbl(n: i32): i32 { return n * 2 }
    print(sel((x) => dbl(x))(4))
    const g = sel((s: string) => s + "!")
    print(g("a"))
    // vl check: rc 1, argument of type string flows into `dbl` expecting i32 (the call's argument types)

Want:

    8
    a!

#### Mechanism

The first call's lambda takes `sel`'s open parameter type, so `dbl(x)` records an argument bound
`A` into `i32` at module scope, and every later call of `sel` judged it at its own `A`. The bound
kept no node (`noteArgCstr(…, -1)` in `check_calls.vl`), so D16855's guard could not place it; it
now keeps the argument node in a column beside the row.
