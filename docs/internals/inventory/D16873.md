### D16873 — an un-annotated lambda handed to a generic at module scope, whose body passes its parameter to a function, is checked at another call's closed lambda parameter type

**loud check reject · `vl check` rc 1, `argument of type string flows into dbl expecting i32` (`dbl` written in backticks in the message) · clause 2 · either call alone is accepted · the operator spelling, [D16855](D16855.md), runs since its fix · found grading the D16855 fix · filed 2026-11-16 against master `ee6e3a4d6`**

Repro:

    function sel<A>(f: (x: A) => A): (x: A) => A { return f }
    function dbl(n: i32): i32 { return n * 2 }
    print(sel((x) => dbl(x))(4))
    const g = sel((s: string) => s + "!")
    print(g("a"))
    // vl check: rc 1, argument of type string flows into `dbl` expecting i32 (the call's argument types)

Want:

    8
    a!

#### Mechanism

The first call's lambda takes `sel`'s open parameter type, so `dbl(x)` records an argument bound
`A` into `i32` at module scope, and every later call of `sel` judges it at its own `A`. D16855's
guard skips such a bound at another call by the node it was recorded at; this argument bound is
recorded with no node (`noteArgCstr(…, -1)` in `check_calls.vl`), so the guard cannot place it.
