### D16560 — a value `if` or `match` of literals nested as a tail of a join with an `i64` value keeps its own `i32` type while its literals take `i64`, and builds an invalid module

**closed · runs, prints `1` · was check-clean invalid wasm · clause 1 · found by the arith fuzz (`ar_s11_0195`, seed 11) · filed 2026-11-15 against master `bcc1a353f` · closed 2026-11-15 by lane N: a join's literal tails adopted the join's type through a nested join without retyping it; `numLitJoinSpineSync` types each nested `if` or `match` whose every tail adopted the type · fixture `literals/nested-literal-join-adopts-outer-width.vl`**

Repro:

    const c = true
    const k: i64 = 5
    const v = if c { if c { 1 } else { 2 } } else { k }
    print(v)

Want:

    1

#### Mechanism

The join `if c { … } else { k }` is `i64`, and `numLitAdoptJoin` retypes each of its literal tails
(`valueTailLeaves`, which reaches through the inner `if`) as `i64`. The inner `if` node kept the
`i32` its own arms joined to, so the emitter built it as `(if (result i32) … (i64.const 1) …)` and
widened that with `i64.extend_i32_s`: a type mismatch the validator rejects.
