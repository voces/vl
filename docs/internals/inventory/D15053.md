#### Mechanism

With the plan off, a direct call (`a("s"); a(7)`), a `const b = a` copy, an un-seeded `let b = a`
and copy chains all run: the parameter holds its set's id and each call dispatches to the
member's instance. Seeded with `id` and then written with `a`, the parameter is not tagged, so
mono's copy check (`monoCopyDeclOf`, `monoHoleCopyCallsMisfit`) sees `b = a` called at two types
against the parameter's one pin. The producer is the tag decision taking the written `let` as a
holder of the set's id, as it takes the `let b = a` initialiser. Warning: recording the call on
the parameter's hole instead (`noteArgCstrAt` / `noteMemCstr` at a call through `b`) does not
move the witness, and turns the second spelling below into check-clean invalid wasm with the
plan ON.

#### Grading list

* `print(a("s"))` in place of `print(b("s"))` (the parameter called at one type, the copy at
  another): must keep running, and must not become invalid wasm with the plan on.
* `turns(a, c) { let b = same; b = a; print(b("w")); b = c; print(b(6)) }` with
  `turns(same, other)`: the same refusal with the plan off.
