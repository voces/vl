#### Mechanism

The literal is built at `II`, the declared record of its own field storage. The hole hands it
back, and the result is stored into `A` unconverted. The generic spelling
`function f<T>(v: T) { return v }` is refused at check: `{d: i32} is not A: they store field d
differently`. So is `f(v: II)`. `recBuiltAtDeclared` refuses a literal handed through a generic
call, and the hole's call does not reach it. The close is in the checker.

#### Close

The brief preferred honouring the adoption over a refusal, and the annotated generic identity
`function f<T>(v: T): T { return v }` already runs `3`: its literal argument adopts `A` at the
call (`recPassThroughArg`). The hole identity now takes the same path. `recHoleIdentityArg`
recognises a non-generic function with no return annotation whose body only returns its
un-annotated parameter, directly or through un-annotated rebindings, and `recHoleIdentityAt`
adopts a literal argument at the landing record, or re-notes a literal binding argument
against it. Writing through the adopted value (`b.d = null` after `const b: A = f(x)`) is still
refused at check, as it is through the generic identity.
