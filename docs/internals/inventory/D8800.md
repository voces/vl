### D8800 — a record literal handed through an un-annotated identity hole into a record that stores its field differently is accepted by the checker

**check-clean invalid wasm · clause 1 · open · present on master `3f8abb772` · found closing [D8680](D8680.md) · filed 2026-10-21 against master `3f8abb772`**

Repro:

    type A = { d: i32 | null }
    type II = { d: i32 }
    function f(v) { return v }
    const a: A = f({ d: 3 })
    print(a.d ?? 0)
    // vl check: rc 0.  vl run: the emitted module failed to validate inside the module's top-level code: expected (ref null $0), found (ref $1); $0 is `A`, $1 is `II`

Want:

    loud check reject

#### Mechanism

The literal is built at `II`, the declared record of its own field storage. The hole hands it
back, and the result is stored into `A` unconverted. The generic spelling
`function f<T>(v: T) { return v }` is refused at check: `{d: i32} is not A: they store field d
differently`. So is `f(v: II)`. `recBuiltAtDeclared` refuses a literal handed through a generic
call, and the hole's call does not reach it. The close is in the checker.
