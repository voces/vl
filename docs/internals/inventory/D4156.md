### D4156 — a call through an un-annotated alias of a written `let` stores the writes un-instanced

**closed 2026-10-11 by lane SC, with D3961 · runs · was check-clean invalid wasm · found by the D3961 position matrix · filed 2026-10-11 against master `3096c492f` · pins: `tests/cases/closures/alias-of-written-let-called.vl`**

Repro:

    function gA<U>(u: U) { print("gA"); print(u) }
    function gB<V>(v: V) { print("gB"); print(v) }
    let f = gA
    f = gB
    const h = f
    h(7)
    // vl check: rc 0.  vl run: invalid module, expected structref, found i32

Want:

    gB
    7

#### Mechanism

The call `h(7)` found no seed through `h` itself, so neither the seed nor the writes of the
`let` behind the alias were instanced at the call. The close follows un-annotated alias links
(`monoAliasLetEnd`) to the first written `let`, or the first `let` bound to a hole lambda (D4157),
and treats the call as a call through that binding. A hole-lambda seed with a generic write
trapped rather than failing validation.
