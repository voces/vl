### D15882 — a `K | null` literal-union field read through an un-narrowed union of records is refused at emit, where a `string | null` or `boolean | null` field there runs

**closed 2026-11-14 — a `K | null` field read through an un-narrowed union of records dispatches on the box tag and reads the atom niche · was loud emit reject, `emitProgram: field access receiver is not a struct` · clause 2 · found probing `readFieldStoreKind`'s re-tag for the step-7 codecs (w314) · filed 2026-11-12 against master `8f3814d1`**

Repro:

    type K = "a" | "b"
    type R = { k: K | null, s: string }
    type S = { k: K | null, s: string, extra: i32 }
    const n: R = { k: null, s: "lo" }
    const u: R | S = n
    print(u.k == null)

Want:

    true

#### Mechanism

`sharedUnionFieldPlan` answered `FC_NUL_LIT_UNION` (code 30) for every member, but
`sharedFieldPlanDispatchable` admitted that code only when some member stored a bare `null`, so
the read fell through to the plain struct read. Atoms are interned program-wide and the niche's
`-1` is `null` in every member, so the plan dispatches whatever its members store. The same
dispatch now widens a member's atom to the string when the other member stores `string | null`.

Before the fix the read is a shared field of an un-narrowed union of records (`memberFieldPos`
answers `FPOS_SHARED`). The field is the `K | null` niche, code 30. The ablation pins the family
to that one storage: the same read of a `string | null`, `boolean | null` or plain `K` field
runs, and so does the read under `is` narrowing.

#### Ablation

| spelling | outcome |
| --- | --- |
| this repro | loud emit reject |
| `u.k ?? "none"`, `const kk = u.k` then `kk == null`, or a non-null value in `k` | loud emit reject |
| `S` sharing only `k` with `R` (`{ k: K \| null, t: i32 }`) | loud emit reject |
| `k: string \| null` | runs, prints `true` |
| `k: boolean \| null` | runs, prints `true` |
| `k: K` (no `null`) | runs |
| `if u is R { print(u.k == null) }` | runs, prints `true` |
