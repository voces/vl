### D3450 — a union of numeric types does not deliver into a number type its every member widens to, and `as f64` over it is a member cast

**closed · runs, prints `3.5`, `7`, `2.5` · was a loud check reject · owner ruling on numeric joins, 2026-09-30: a numeric union converts into a single numeric type only when every member converts exactly · fixture `tests/cases/numerics/numeric-union-delivery.vl` · closed 2026-09-30**

Repro:

    function f(c: boolean, x: f64, y: i32, w: i64) {
      const u: i32 | f64 = if c { x } else { y }
      const z: f64 = u
      print(z / 2)
      const v: i32 | i64 = if c { w } else { y }
      const k: i64 = v
      print(k)
      const r: i32 | f64 = if c { x } else { y }
      print(r as f64)
    }
    f(false, 2.5, 7, 9)
    f(true, 2.5, 7, 9)
    // vl check: cannot assign i32 | f64 to 'z' of type f64

Want:

    3.5
    7
    7
    1.25
    9
    2.5

#### Mechanism

`assignable` has no edge from a union to a scalar (the refusal D2611 recorded). `assignableExpr`, the seam every binding,
argument, return, field, element and store delivers through, now admits a numeric union into a
numeric primitive every member is or widens to exactly (`numUnionConverts`), and the emitter's
`emitExprAsF64`/`AsI64`/`AsF32`, which those deliveries already call for a number destination,
convert at the member held (`emitNumUnionConvert`). A lossy one (`i64 | f64` into `f64`) is refused
with a note naming `x as f64`. `as T` over a numeric union converts at the member held when no
member's conversion can fail (a float target, or `i64` over integer members); otherwise it stays
the member cast it is over any union (DECISIONS.md, "Runtime numbers of different types join as a
union").
