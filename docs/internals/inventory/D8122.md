### D8122 — an un-annotated parameter bound at `i32 | K | null` has no print dispatch for the arm `is i32` leaves

**closed 2026-10-20 by lane L6 · a print or a `K | null` destination of a narrowed read asks the read's type at its instance (an exact instance's substitution, the type a hole's calls agree on, else the hole instance's binding) rather than the hole's recorded type variable; the repro prints `b`, pinned by `tests/cases/literal-unions/nullable-litunion-arm-of-inferred-box.vl` · was loud emit reject · clause 2 · found by the un-annotated `argument`, `map_value`, `map_set` and `early_return_guard` cells of `nullable-litunion-arm-of-generic-box.matrix.vl` · filed 2026-10-20 against master `532d50d35`**

Repro:

    type AB = "a" | "b"
    function take(v) {
      if v is i32 { print(0) } else { print(v) }
    }
    const r: i32 | AB | null = "b"
    take(r)
    // vl check: rc 0.  vl run: emitProgram: print of a union value whose arms the tag dispatch cannot classify

Want:

    b

#### Mechanism

The parameter's type is inferred from its one call. Inside `take` the read `v` is recorded at
the hole's type variable, so `narrowedNulLitBoxKey`'s `K | null` test (`nodeTyIsNulLitUnion`)
declines it and `print` falls to the box dispatch, which has no arm set for the narrowed read.
The print, its string-scratch reservation, the niche read's member texts and the destination
conversion now read `instanceReadTyOf`. A binding's cell is still classified at the recorded
type, so `const w = v` keeps its box cell, which is why the gate is a second key and not a
change to `narrowedNulLitBoxKey`.

The `map_value` and `map_set` cells copy the null-narrowed box into a `const` first, and that
copy refuses the same way with no hole and no generic at all: [D8180](D8180.md). They are not
this row's.
