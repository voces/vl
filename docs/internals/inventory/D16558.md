#### Mechanism

A field is found by name with a linear scan (`objFieldType` over a `TyObj`'s names, `objFieldVal`
over an `ObjLit`'s fields), and about six passes ask once per field, so each pass is F². At
F = 1600, 63% of samples are `__str_eq__` self and `objFieldType` is 31% inclusive, from:
`recObjLitBuild` < `recListLitsBuild` (check), `recordRepTyAdopt` < `assignableExprIn`,
`listFieldWidenDst`, `objLitEarlierKey`, `bareBraceDeliverFields`, `objFieldVal` <
`structIndexOfObjCtx` and `objFieldSrcOrder` < `objLitNeedsOrderStash` (emit), and the parser's
`recFieldSeen`. The by-name readers are called from about 40 files, so no one site carries it: a
positional fast path in `listFieldWidenDst` alone bought 4% (0.334G to 0.319G at F = 400).

#### Design (parked)

Give each `TyObj` row a field-name id per field, an interned `i32` beside `objFieldNames`, and
dispatch `objFieldType`, `tyFieldTyOf` and the literal readers through an id compare instead of a
string compare, with a per-row name → first index answer built on first ask. A refused duplicate
field still mints a row that repeats a name, so the index keeps the FIRST position a name takes
(`objRowNamesDistinct` already tells a row with repeats apart), and a by-name read answers what the
scan answered. `objFieldType` takes a `TyObj` value, not a row, so the id column rides the value
and the index is keyed by row through `tyFieldTyOf`; callers that hold only the value keep the scan
until they pass the row. Each caller stays byte-identical; the grid above and the corpus grade it.
