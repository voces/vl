### D2535 — a closure returning a nullable integer literal union yields a boxed value that a narrowed `print` reads as the i32 atom

**check-clean invalid wasm · clause 1 · found by #3168's review (the concrete twin of its `l2` witness) · filed 2026-09-25 against master `15be0d1b8`**

Repro:

    type LI = 1 | 2 | 3
    function mkGet(xs: (LI | null)[]): (i32) => LI | null {
      return (i: i32) => xs[i]
    }
    const s: (LI | null)[] = [null, 2]
    const g = mkGet(s)
    const r = g(1)
    if r != null { print(r) }

#### Mechanism

The closure's result `LI | null` is a boxed reference, while `r` narrowed to `LI` is read at the
i32 atom rep, so `print(r)` receives the box: `expected i32, found (ref $type)`. A plain function
returning `LI | null` from the same list runs, so the closure-call result is the ingredient. The
generic spelling (`mkGet<V>(xs: (V | null)[])`) reaches the same site, and is refused at the
instance by `monoLamNulUnionListCheck` (D2525's boundary) until this row closes.

#### Ablation

| ingredient removed | outcome | needed? |
| --- | --- | --- |
| the closure (a function returning `xs[1]` directly) | runs | **yes** |
| the literal union (`i32` elements) | runs | **yes** |
