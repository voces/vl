### D2686 — every redundant `let` annotation scanned the rest of the program's tokens for its `=`

**closed 2026-09-26 — runs today and must keep running · the defect was its cost: the checker recorded each `redundant-type` hint on a `let` by scanning from the name to the END of the token stream, so annotating made a program quadratic; master's own self-compile fell 51.68G to 50.25G fuel (-2.8%) with the fix, output byte-identical · filed 2026-09-26 against master `f8709e41c`**

Repro:

    function pick(n: i32): i32[] {
      if n == 0 {
        const a: i32[] = [n, 1]
        return a
      }
      const b: i32[] = [n]
      b
    }
    print(pick(0).length + pick(1).length)
    // prints 3; `vl check --severity hint` reports both annotations as redundant

#### Mechanism

`recordRedundantAnnot` (compiler/typecheck.vl) finds the span a `redundant-type` hint deletes
— `:` up to the binding's `=` — by walking tokens from the name. The loop guarded its BODY on
`eqTok < 0` but not its CONDITION, so after finding the `=` it ran on to `P.toks.length`
doing nothing: every annotated binding whose annotation equals its initializer's type cost
one pass over every token after it. Closed by stopping the loop at the `=`; the span it
records is the same one.
