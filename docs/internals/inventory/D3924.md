### D3924 — a block `const` shadowing a function-list parameter makes the parameter's later call build invalid wasm

**check-clean invalid wasm · found in review of #3487 (`rv3487/v01_shadow_nongen`, `p05b`) · filed 2026-10-09 against master `dacc580c8`**

Repro:

    function st(fs: ((t: i32) => void)[], x: i32) {
      if true {
        const fs: ((t: string) => void)[] = [(t: string) => print(t)]
        fs[0]("z")
      }
      fs[0](x)
    }
    const gs: ((t: i32) => void)[] = [(t: i32) => print(t)]
    st(gs, 7)
    // vl check: rc 0.  vl run: the emitted module failed to validate inside `st`

Want:

    z
    7

#### Mechanism

Not located. The block's `const fs` shadows the parameter for the block only, but the call after
the block reads the inner binding's element type. It is a sibling of D2114, where a `for` loop
variable shadows a function-typed parameter under callback specialization; here there is no
specialization and no generic.

#### Ablation

| ingredient changed | outcome | needed? |
| --- | --- | --- |
| the inner binding renamed | runs | **yes** |
| `st` generic over the element (p05b) | invalid wasm, the same | no |
