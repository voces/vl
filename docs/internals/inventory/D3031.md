### D3031 — a record literal nesting a record is built as a union arm whose nested field has another scalar kind

**check-clean invalid wasm · clause 1 · identical on master `cac5e4ad5` and on #3259 · the nested-record twin of [D3024](D3024.md), found by the #3259 review · filed 2026-09-28**

Repro:

    type X = { k: { p: i32 }, n: i32 }
    type U = X | { z: i32 }
    const o = { k: { p: "s" }, n: 2 }
    print(o.k.p)
    // vl check: rc 0.  vl run: failed to parse WebAssembly module

Want:

    s

#### Mechanism

D3024's matcher, one level down. `objMatchesVariantIdx` now refutes a scalar field of another
kind, but a nested-record field (code 15) is tightened by `objNestedFieldCompat`, which compares
the nested literal's field NAMES with the target row's and never their kinds. So `{ p: "s" }`
matches `{ p: i32 }`, the outer literal is built as the arm `X`, and the string is stored into
the nested `i32` slot. The likely close is the same kind refutation applied per nested field.

#### Ablation

| ingredient removed | outcome | needed? |
| --- | --- | --- |
| the union (`X` alone, no `U`) | prints `s` | **yes** |
| the nested field's kind mismatch (`{ p: 1 }`) | prints 1 | **yes** |
