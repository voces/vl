### D3031 — a record literal nesting a record is built as a union arm whose nested field has another scalar kind

**closed · was check-clean invalid wasm, identical on master `3a71bb1f9` · a nested literal fits a row only where each leaf's kind does, to any depth (`objLitFitsRow`), for a union arm and for a declared record alike · the 900-cell nested-kind grid (5 arm kinds x 5 literal kinds x depth 1-3 x with and without a union x 6 positions) moves 321 invalid and 42 wrong cells to runs, and loses none · fixture `tests/cases/unions/record-literal-nested-kind-not-an-arm.vl` · residue [D3035](D3035.md) · filed 2026-09-28**

Repro:

    type X = { k: { p: i32 }, n: i32 }
    type U = X | { z: i32 }
    const o = { k: { p: "s" }, n: 2 }
    print(o.k.p)
    // vl check: rc 0.  vl run: failed to parse WebAssembly module

Want:

    s

#### Mechanism

D3024's matcher, one level down. `objMatchesVariantIdx` now refutes a scalar field of another
kind, but a nested-record field (code 15) is tightened by `objNestedFieldCompat`, which compares
the nested literal's field NAMES with the target row's and never their kinds. So `{ p: "s" }`
matches `{ p: i32 }`, the outer literal is built as the arm `X`, and the string is stored into
the nested `i32` slot. The close applies `declRowFieldKindFits` to each nested leaf, to any
depth, in the arm matcher and in the declared-record scan, where without a union a `boolean`,
`f64` or `i64` leaf was taken the same way. A leak it exposed in the shared-instance test
runner is closed with it: `collectU` read the previous program's struct table.

#### Ablation

| ingredient removed | outcome | needed? |
| --- | --- | --- |
| the union (`X` alone, no `U`) | prints `s` | **yes** |
| the nested field's kind mismatch (`{ p: 1 }`) | prints 1 | **yes** |
