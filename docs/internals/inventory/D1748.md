### D1748 — a literal-union-keyed map is refused at CHECK, and the gate reads the key's SPELLING where the hash reads its rep

**closed 2026-09-06 — a literal union hashes as i32 because it REPS as i32, and one gate covered every consumer · filed against `#2749`'s tree, re-measured on `#2753`'s, closed against master `b4430e688` · the residue [D1724](D1724.md)'s close left · 0 corpus cells**

Repro:

    type K = "red" | "green"
    function take(a: K) {
      const m = Map()
      m[a] = 7
      print(m[a] ?? 0)
    }
    take("green")
    // vl check: rc 0.  vl run: rc 0, prints 7

Was: `A K-keyed Map isn't supported yet — Map/Set keys must be string or i32`, while every read
through the same key already printed correctly at [D1724](D1724.md)'s close.

#### Mechanism

The refusal is a CHECK-level gate naming the map's declared KEY TYPE, and its wording admits the
gap. `mapKeyRepTy` is the one home of which hash a key takes, and it answered -1 for a literal
union; every gate projects that answer. A 36-cell grid over every consumer that takes a key and
every one that hands a key back, at both the annotated `{[K]: i32}` and inferred `Map()` faces,
put **27 of 32 cells on ONE first error** — this row's; the extra errors on the annotated face
are cascades from the annotation resolving to -1. The five that ran did so because a
`string`-spelled write pinned the key hole first, leaving a string-keyed map for
[D1724](D1724.md)'s widen to carry.

**The design question was settled by measurement, not argument.** A plain `string` is NOT
assignable to `K`, so every key of a `{[K]: V}` map is either a `K`-typed value (already an
interned atom) or a member string LITERAL whose atom id is known at compile time — the key set
is CLOSED and needs no runtime intern. And the atom id is GLOBAL, keyed on member text
(`internAtom` over `litAtomId`), so `m["green"] = 1` interns to exactly the id a `K`-returning
call yields. The map therefore stores the ATOM and `.keys()` hands atoms back, which closes
`m[m.keys()[0]]` with no widen at either end.

#### The two refused routes, and why the third is free

Both routes tried before the close assumed the map stores the member STRINGS, and both were
built and measured. Recorded because the price is the thing worth keeping.

| route | result |
| --- | --- |
| `mapKeyRepTy` answers `TY_STR` for a literal union | six cells move to RUNS, and `m.keys()` on that map is **check-clean invalid wasm** — `.keys()` is typed `mkArrayTy(rt.mKey)`, so its element is the union, whose rep is the interned ATOM, while the map stores the widened strings |
| type `.keys()` by the STORED rep instead | fixes that cell and **loses a `runs`**: `m[m.keys()[0]]` becomes `map key must be K, got string` |
| **store the ATOM (`TY_I32`)** | **both cells run, and `.keys()` needs no retyping at all** |

The third route is free at `.keys()` precisely because that method already returns
`mkArrayTy(rt.mKey)`: a `K[]` of atoms IS the i32 list the i32-keyed `.keys()` builds. The two
refused routes were fighting a widen the atom design never performs.

#### Close

Four changes, one sentence: **a literal union hashes as i32 because its values rep as i32.**

* `mapKeyRepTy` answers `TY_I32` for a member set whose values rep as an i32 — a string set as
  the interned atom, a numeric set as its own base, and only where that base IS i32. An
  `f64`/`i64`-based member set reps as neither and still refuses.
* The map INDEX check and the `KEYMUST`/`SETKEY` builtin-argument forms take `assignableExpr`
  rather than the bare `assignable`, so a member LITERAL is admitted by its literal type. This
  is the row's own "third consequence" — `m["green"]` on a `{[K]: i32}` map was refused while
  the identical literal was accepted as a `K` argument and a `K` binding, because `checkNode`
  types a string literal as the widened `string` with no destination to narrow it against.
* `emitMapRecvKey`'s i32 arm lowers a member literal through the atom context instead of
  refusing `exprString`. [D1724](D1724.md)'s widen is on the STRING-keyed arm and is untouched.
* `nameIsI32KeyedMap` — the emitter's spelling-side key question — learns what the arena
  already said. It read `mapSpellKeyName(name) == "i32"`, and `{[K]: i32}` spells its key `K`,
  so the annotated face resolved a STRING-keyed shape while the hash was i32: `.keys()` built a
  string list a consumer read as i32, check-clean invalid wasm.

And the loop-var atom flag gains its third member: a literal-union array, its nullable element,
and a bare literal-union-keyed MAP, whose walk yields its keys. Without it `for k in m` bound
the raw interned id and printed a number, a wrong value at both faces.

#### Ablation

Every row measured 2026-09-06 on `#2753`'s tree, before the close.

| ingredient removed | outcome | needed? |
| --- | --- | --- |
| the literal union (`a: string`) | runs `7` | **yes** |
| the write (any of the four reads instead) | runs at [D1724](D1724.md)'s close | **yes** |
| the annotation (a hole parameter) | runs `7` at D1724's close | **yes** |
| the alias (an inline `"red" \| "green"` set) | still refuses, naming the set | no |
| the Map (`Set` with `.add`) | still refuses, naming `Set` | no |
| the string half (a NUMERIC litunion `1 \| 2` key) | still refuses, same words | no |

The fourth row is a SURFACE fact rather than a rep one, and the close does not change it: an
inline union cannot be spelled in map-key position at all (`{["red" \| "green"]: i32}` is a
PARSE error, `expected an identifier`). Only an alias can name a union key.

The sixth row moved with the string half: a numeric member set reps as its own base, so it
hashes for the same reason and needed no widen of its own — but only where that base is i32.

#### Grading list

* **`m.keys()` and `m[m.keys()[0]]` on a `{[K]: i32}` map are the two cells any close must
