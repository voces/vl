### D14822 — a string literal assigned into a literal-union place is typed `string` as the assignment's value

**loud check reject · clause 2 · pre-existing on master `e1c2d5cff` · found closing D14821 · filed 2026-11-01 against master `e1c2d5cff`**

Repro:

    let s: "a" | "b" = "a"
    const q: "a" | "b" = (s = "b")
    print(q)
    // vl check: rc 1, cannot assign string to 'q' of type "a" | "b"

Want:

    b

#### Mechanism

Not traced. The store is checked against the place's literal union and accepted, but the
assignment's value is typed as the right side widened to `string`, though the right side is the
literal `"b"` and the cell holds that union's atom. Annotated, the binding refuses; un-annotated
at module scope, the `string`-typed binding over the atom refuses at emit (`print of a
literal-union atom whose type carries no member texts`).

#### Ablation

| ingredient changed | outcome on master `e1c2d5cff` | needed? |
| --- | --- | --- |
| a non-literal right side (`s = v`, `v: "a" \| "b"`) | runs, `b` | **yes** (the literal) |
| un-annotated `q`, inside a function | runs, `b` | no (the same type; the refusal moves to emit at module scope) |
| `print(s = "b")` directly | runs, `b` | **yes** (a binding of the value) |
| `q == "b"` instead of `print(q)` | runs, `true` | **yes** (a reader that needs member texts) |

#### Grading list

Annotated and un-annotated `q`, at module scope and inside a function, with an inline union and
a `type K = "a" | "b"` alias.
