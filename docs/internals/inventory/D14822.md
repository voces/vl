### D14822 — a string literal assigned into a literal-union place is typed `string` as the assignment's value

**closed 2026-11-01 · runs, prints `b` · was loud check reject · clause 2 · `checkAssignStore` (`check_operators.vl`) yields `asgLitRhsTy` — the literal's own type where the place is literal-bearing — as the assignment's value, the type its store was already checked at · pin: `tests/cases/literal-unions/assignment-value-into-literal-union-place.vl` · found closing D14821 · filed 2026-11-01 against master `e1c2d5cff`**

Repro:

    let s: "a" | "b" = "a"
    const q: "a" | "b" = (s = "b")
    print(q)
    // vl check: rc 1, cannot assign string to 'q' of type "a" | "b"

Want:

    b

#### Mechanism

`checkAssignStore` checked the store at `asgLitRhsTy` — the literal's own type where the place is
literal-bearing — and then yielded `rt`, the right side widened to `string`, as the assignment's
value, though the cell holds that union's atom. The direct spelling `const q: "a" | "b" = "b"`
already ran. Annotated, the binding refuses; un-annotated
at module scope, the `string`-typed binding over the atom refuses at emit (`print of a
literal-union atom whose type carries no member texts`).

#### Ablation

| ingredient changed | outcome on master `e1c2d5cff` | needed? |
| --- | --- | --- |
| a non-literal right side (`s = v`, `v: "a" \| "b"`) | runs, `b` | **yes** (the literal) |
| un-annotated `q`, inside a function | runs, `b` | no (the same type; the refusal moves to emit at module scope) |
| `print(s = "b")` directly | runs, `b` | **yes** (a binding of the value) |
| `q == "b"` instead of `print(q)` | runs, `true` | **yes** (a reader that needs member texts) |

#### Grading list

Annotated and un-annotated `q`, at module scope and inside a function, with an inline union and
a `type K = "a" | "b"` alias.
