### D9911 — a record field holding `x ?? <default>` in an un-annotated or `<T>` body at a never-null pin has no struct shape at emit

**closed · runs, prints `5` · was loud emit reject, `vl check` rc 0, clause 2 · CAPABILITY: the same body at an `i32 | null` pin prints `5`, and `function f(x: i32)` prints `5` · found closing [D9870](D9870.md) · present on master `8700f0727` · filed 2026-10-22 against master `8700f0727` · closed by keeping the template's type on a record literal the never-null fold of a `??` rebuilds, so the instance mints its row (`monoPinBinOps`, emit_mono.vl) · fixture `generics/coalesce-hole-record-field-at-never-null-pin.vl`, matrices `hole-coalesce-record-field-at-never-null-pin` (38 → 64 of 64) and `generic-coalesce-record-field-at-never-null-pin` (38 → 64 of 64)**

Repro:

    function f(x) { return { v: x ?? 1.5 } }
    const z: i32 = 5
    print(f(z).v)
    // vl run: emitProgram: ref valtype with no interned shape

Want:

    5

#### Mechanism

At a never-null pin `monoPinBinOps` folds the `??` to its left operand and rebuilds every
parent it changed. Its object-literal arm built the new literal with no recorded type, so
`mintPinnedObjLit` read no type and minted no row for the instance's record.

The two rows of the ablation that read `same refusal` for a `const w = x ?? 1.5` and an
integer default ran on master `00cbfe00b`. A record nested in a record, `{ v: { w: x ?? 1.5 } }`,
still refuses: it refuses identically without the `??`, so it is the nested-literal shape of
open [D3037](D3037.md), not this row.
With the hole called at `i32`, `i64`, `f64` and `i32 | null` together, master built
check-clean invalid wasm (`expected i32, found i64`) where one pin refused.
