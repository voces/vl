### D16413 — a generic whose result wraps its function parameter's result, handed a generic declared after the call, builds invalid wasm

**check-clean invalid wasm · clause 1 · open · `the emitted module failed to validate inside the module's top-level code: ... type mismatch: expected i32, found f64` · declaration order is the ingredient · found by the independent oracle's higher-order generator (`scripts/oracle/gen_hof.ts`, case 7) · filed 2026-11-15 against master `33ef972d7`**

Repro:

    function k<A, B>(x: A, f: (x: A) => B): B[] { [f(x)] }
    print(k(1.5, gid)[0])
    function gid<A>(x: A): A { x }
    // vl check: rc 0.  vl run: invalid module, type mismatch: expected i32, found f64

Want:

    1.5

#### Mechanism

With `gid` declared after the call, the call's `B` reaches the use `[0]` at `i32` while the
instance of `k` builds an `f64` list. Declaring `gid` first runs, so the result's type is
read before `gid`'s declaration gives `B`. From the ablation; the call's recorded result type
has not been printed.
