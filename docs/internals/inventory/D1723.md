Repro:

    type A = { r: i32 }
    function st(): A { return { r: 8 } }
    function pick(b: boolean) { if b { return st() } return 7 }
    function takeA(a: A) { print(a.r) }
    const p = pick(true)
    if p is A { takeA(p) } else { print(0) }
    // was: vl check rc 0, then exit 70 — the emitted module failed to validate,
    // type mismatch: expected (ref $type), found (ref $type). Now prints 8.

#### Mechanism

A narrowed struct arm stays the `{tag, payload}` box, so an argument boundary recovers the
payload itself. `emitCall` does that under `cVi >= 0` — the PARAMETER's variant row.

The row placed the fault at `cVi` rather than the `exprUnion` gate beside it, and an
instrumented build confirms it and sharpens it. Both faces, printed at the argument:

| face | `cVi` | gate | `narrowedStructArmVi` | param kind | param row |
| --- | --- | --- | --- | --- | --- |
| inferred | **-1** | 1 | 0 | **struct** | **0** |
| declared | 0 | 1 | 0 | **variant** | 0 |

So the gate answers 1 in BOTH faces, and the arm is identified in both — the inferred union's
arm does have a variant row. **`cVi` is never assigned**, because the line that assigns it
sits behind `vtKindOfParam(...) == "variant"`, and a parameter annotated `a: A` is a plain
struct unless `A` is a registered union member. And `paramRow` is 0 in both faces: the
destination the unbox needs is available and simply never consulted.

The fix is the BINDING boundary's own pair — `armDestHeapOf(kind, slot)` over the
destination's own rep and table slot, which needs no variant row (for a struct cell it reads
`sHeapIdx[row]`). One arm on `emitCall`'s argument loop, guarded on `cVi < 0 &&
cParamNulVariantIdx < 0` so the three arms stay mutually exclusive. The RETURN boundary
carried the same hole and takes the same pair, annotated (`vtKindOfType` + `annValtypeSlotOf`)
and inferred (`fRetKind` + `fRetStructIdx`).
