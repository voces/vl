### D3658 — `e is U` with an `i64` receiver over an `i32` literal union folds to `false`

**check-clean silently wrong · clause 1 · found by the #3379 review (`rv79`) · the same on master `32b753681` and with #3379 · filed 2026-10-05**

Repro:

    type U = 1 | 2
    const e: i64 = 1
    print(e is U)
    // PRINTS false

Want:

    true

#### Mechanism

A prediction until a close confirms it. The numeric literal-union `is` arm in `emitIsTest`
compares only when the receiver's base equals the union's (`isNumRecvBaseName(...) == nlBase`):
an `i64` receiver over the `i32` base misses it and falls to `monoStaticIsResult`'s name fold,
which answers `false` without reading `e`. #3379 compares an `i64` receiver at `i64` only for a
union with no single base (`tyIntLitWideTexts`); an `i32`-base union needs the same widening.

#### Ablation

| ingredient changed | outcome | needed? |
| --- | --- | --- |
| `const e: i32 = 1` | `true` | **yes** (the `i64` receiver) |
| `type U = 1 \| 3000000000` | `true` with #3379 | **yes** (an `i32` base) |

#### Grading list

The inline spelling `print(e is 1 | 2)`, and `1 | 300`: twelve cells of the #3385 review's `gb`
grid (`i64_s0_*`, `i64_s2_*`: alias, inline, `if`, `!(… is …)`, list element, parameter) print
`false` where `true` is owed, the same on master and with #3385.
