### D3658 — `e is U` with an `i64` receiver over an `i32` literal union folds to `false`

**closed 2026-10-05 — the witness prints `true` · was check-clean silently wrong, clause 1 · found by the #3379 review (`rv79`) · filed 2026-10-05 against master `32b753681` · fixture `tests/cases/literal-unions/i64-receiver-i32-literal-union-is.vl`**

Repro:

    type U = 1 | 2
    const e: i64 = 1
    print(e is U)
    // master printed false

Want:

    true

#### Mechanism

Confirmed. The numeric literal-union `is` arm in `emitIsTest` (wasmEmit.vl) compared only when
the receiver's base equalled the union's (`isNumRecvBaseName(...) == nlBase`). #3379 widened an
`i64` receiver to `i64` only for a union with no single base (`tyIntLitWideTexts`); an `i64`
receiver over an `i32`-base union missed the arm and fell to `monoStaticIsResult`'s name fold,
which answers `false` without reading `e`. Fixed by comparing an `i64` receiver at `i64` over an
`i32`-base union too: every `i32` member is an `i64` value, and `emitNumLitEq` already widens the
literal to the receiver.
