* **IT WAS NOT [D1141](#d1141)'S SHAPE, AND THE ROW'S OWN HEADLINE WAS THE MESSAGE'S SCOPE, NOT
  THE DEFECT'S.** D1141 was ONE missing rep rung in a ladder that had every other rep. Running
  the plainest program this sentence forbids — `const b: i32[] = [1, 2]  print(b.get(0))` —
  refuses identically, and so do `i64` / `f64` / `f32` / `boolean` / `string` / `("a"|"b")[]`.
  The bare `.get` was built for the STRUCT-element ref list and for nothing else; the scalar
  family had only the FUSED `xs.get(i) ?? d` (`emitListGetOr`), so the unfused call fell out of
  `emitCallNode`'s member ladder at 32 of the 36 gradeable cells. CLAUDE.md's "before believing

* **THE FAILING RUNG RECEIVED A LIST IT WAS NEVER OFFERED.** `emitCallNode`'s `get` arm asked
  `structListPopGetElem(exprIx, fnIx) >= 0`, which is `rlElemKindTbl == 1` — a plain-struct
  element. A `u8[]` (or any scalar list) answers -1, the arm declines, and the call reaches
  `emitCall`, whose sentence names neither `get` nor lists.

* **`.pop()` IS NOT JUST THE CONTROL, IT IS THE FIX.** The checker types `xs.pop()` and
  `xs.get(i)` identically (`T | null`), and the two lowerings differ in exactly three places:
  the condition (`len != 0` vs `i u< len`), the element index, and whether the length is
  decremented. Those three are now `pushTakeCond` / `pushTakeElem`, and `emitPop` takes a
  `getIdx` (-1 for `.pop`). All four result reps — the boolean i32 niche, the `{tag, anyref}`
  value box, the ref/string typed null, and the unchecked tail — serve both faces by
  construction, so `.get` cannot lag `.pop` at a rep again. `emitListGet` is deleted.

* **THREE MORE SITES THE MEMBER NAME KEYED, EACH FOUND BY RUNNING, NOT BY READING.**
  `emit_collect`'s value-union walk registered the unspoken `i32|null` box for `.pop` only;
