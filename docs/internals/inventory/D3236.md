### D3236 — an inferred return classified its returned name by the first same-named binding in the function, in any scope

**closed · the return classifier resolves a returned name at its own position (`parentLetOfAt`), in `retLocalCellKind` and in `exprIsBool`'s `boundBoolByName` · fixture `tests/cases/inference/inferred-return-shadowed-binding-kind.vl` · was check-clean invalid wasm (and check-clean silently wrong for a boolean shadow) · clause 1 · plumb PL-076, the same at plumb's pin `b09566e16c7e` and master `94670f728` · filed and closed 2026-09-29 against master `94670f728`**

Repro:

    function pick(c: boolean, big: i64, small: i32) {
      if c {
        const s = big + 1
      }
      if !c {
        let s = small
        return s
      }
      0
    }
    function main(): i32 {
      const r = pick(false, 9, 7)
      if r >= 0 { return r }
      0
    }
    print(main())
    // vl check: rc 0.  vl run on master: invalid module inside `main`, expected i32, found i64

Want:

    7

#### Mechanism

The checker types `pick` as returning `i32`. The emitter classifies an un-annotated function's
result on its own, in `computeRetInference` → `criClassify`. That pass keeps no scope stack.
Its last-resort arm, `retLocalCellKind`, found the returned `s`'s declaration with
`parentLetOf(body, "s")`. That returns the name's first `LetDecl` anywhere in the body: the
dead-scoped `i64` one. So the function got an `i64` result. The callee stayed self-consistent
because it widened its `i32` return, and its `i32` caller failed validation. `exprIsBool`'s
`boundBoolByName` made the same unpositioned lookup, so a `boolean` shadow set `fRetBool` and
printed `true` for `8`. Both now take the binding in scope at the read's own node.
