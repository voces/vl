### D1654 — D1570's `ufcs-not-method` sentence is lost the moment a file imports anything: the gate looks up a bare name in a table a merge renames

**loud check reject · the verdict is right and the SENTENCE reverts to the one D1570 replaced · filed 2026-09-05 against master `ea407d11a`**

Repro:

    // file: dep.vl
    export function d0(a: i32): i32 { a + 1 }
    // file: entry.vl
    import { d0 } from "./dep"
    type Cursor = { pos: i32 }
    function skipTags(c: Cursor): i32 { return c.pos + d0(1) }
    const cur: Cursor = { pos: 3 }
    print(cur.skipTags())
    // vl check: rc 2, `no field 'skipTags' on Cursor`
    // Without the import, the same five lines say: `'skipTags' is not a method — its
    // first parameter is named `c`, not `self` …` with the `ufcs-not-method` code.

#### Mechanism

`ufcsNotMethodKind` opens with `if (fnDeclIx[name] ?? -1) < 0 { return 0 }`, and `name` is the
property as the author wrote it. A module merge renames every declaration (`skipTags$m0`), so
the bare spelling misses, the classifier answers "no gate claims this call", and
`noteUfcsNotMethod` stays silent — leaving the plain `no field` sentence D1570 exists to
replace, plus its whole `ufcs-not-method` data channel (`reason`, `param`, `declLine`,
`declCol`), which is what a rename quick-fix dispatches on.

#### Ablation

| ingredient removed | outcome | needed? |
| --- | --- | --- |
| the `import` (single source) | the D1570 sentence, with its payload | **yes** |
| the import replaced by a template hole (`print(\`x=\{1}\`)`) | still the plain sentence — the hole's implicit `std:fmt` edge merges too | no |
| the declaration moved into `dep.vl` | still the plain sentence | no |
| the first parameter renamed to `self` | the call resolves, no diagnostic | **yes** |
