Repro:

    // file: entry.vl
    import { d0 } from "./dep"
    type Cursor = { pos: i32 }

    // the same sentence and `ufcs-not-method` payload the import-free spelling always gave.

#### Mechanism

`ufcsNotMethodKind` opens with `if (fnDeclIx[name] ?? -1) < 0 { return 0 }`, and a module merge
renames every declaration, so the table is keyed on `skipTags$m0` while the classifier is handed
the property as written. The caller does pass `ufcsAliasAtSite`, but that resolver reads the
UFCS scope table, and `modBankUfcsScope` banks a rename row only when its target is a
`self`-function — which the `self`-NAME gate is by definition not. Gates 2 and 3 (arity,
receiver) fired under a merge all along, because their names ARE self-functions; gate 1 could
not. `noteUfcsNotMethod` now falls back to `ufcsMergedDeclOf`, which finds the key whose
`demangleName` is the property and which `lookup` can see — the same demangle-the-keys reader
D1599's `selfFnNamesFor` uses for the did-you-mean pool. `ufcsDeclParamTok` moves to
`nodeStartTok` in the same change, since the payload now resolves across a module boundary and
`tokIndexAt` is unsound there (D1652).

#### Ablation

| ingredient | before | after |
| --- | --- | --- |
| single source (the control) | the D1570 sentence + payload | unchanged |
| an `import` of an unrelated name | **`no field 'skipTags' on Cursor`** | the sentence + payload |
| a template hole's implicit `std:fmt` edge, no `import` written | **`no field …`** | the sentence + payload |
| the declaration moved into the dependency | **`no field …`** | the sentence, `declLine`/`declCol` in that file |
| the first parameter renamed to `self` | the call resolves, no diagnostic | unchanged |

The ingredient is the MERGE, not the import statement: a template hole reaches it too.
