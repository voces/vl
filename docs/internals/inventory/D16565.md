### D16565 — a `for` over `.values()` or `.keys()` of an un-annotated parameter reports its own loop variable as undeclared

**closed 2026-11-15 — the loop variable binds: a read-only body now meets only the map-parameter floor ([D15161](D15161.md)), and a body that pins the map runs · was loud check reject, `undeclared identifier` for the loop's own variable, clause 2, the same on master `e56efd8c2` · fixed in `checkMemberCallNode` (`check_member_call.vl`): a hole's open `.keys()` / `.values()` are lists of the iteration holes a loop over it binds · `ms-map-of-lists` and `ms-map-of-nullable-i32`: the `argument`/un-annotated cell moves to the floor's sentence, no other cell moves · filed 2026-11-15 against master `e56efd8c2`**

Repro:

    function mk(): {[string]: i32[]} { const m: {[string]: i32[]} = Map(); m["a"] = [7]; return m }
    function t(a) { for xs in a.values() { print(xs[0]) }; a["b"] = [8] }
    t(mk())
    // vl check: rc 0.  vl run: prints 7 (was: undeclared identifier 'xs')

Want:

    7

#### Mechanism

The iterable is a method call on a hole parameter, `a.values()` or `a.keys()`, whose type is a
derived hole. The loop binds its variable from the iterable's element type, and over that hole it binds
none, so the body's read of the variable is reported as undeclared. A key-value loop over the parameter
itself (`for k, xs in a`) binds its variables and runs. With the variable bound, a read-only body would
still meet the un-annotated map-parameter floor, since lifted ([D16714](D16714.md),
[D15161](D15161.md)); the defect here is the first sentence, which names a scope error the program does
not have.

#### Closed

`a.values()` over a hole typed as a list whose element was the open map's open value, a slot with no
type yet, so the loop declared its variable at nothing. The hole's open keys and values are now the
`HD_ITER1` / `HD_ITER2` holes a `for k, v in a` binds, and a set's values are its keys, so the loop
variable resolves at the pin as the key-value walk's does. A map written after the loop
(`d16565_values_pinned_after`) now runs; one written before it ran already. Named set
`d16565-hole-keys-values-loop`.
