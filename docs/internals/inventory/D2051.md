### D2051 — a returned `else if` chain whose last link has no `else` is refused at emit under a nullable-union return, though an else-less `if` is `T | null`

**loud emit reject · `vl check` rc 0, then `emitProgram: union if-expression requires an else arm`, clause 2 · filed 2026-09-22 against master `48a295c72`, found reviewing #3032 (D1990), which leaves it unchanged**

Repro:

    function g(k: i32): i32 | null {
      return if k == 0 { 5 } else if k == 1 { 6 }
    }
    print(g(0) ?? -1)
    print(g(2) ?? -1)
    // vl check: rc 0.  vl run: emit error — union if-expression requires an else arm

#### Mechanism

`emitUnionRetIfSink` (compiler/wasmEmit.vl) lowers a union-returning `if` value by sinking each
arm into the return box, and refuses any link with no else instead of sinking `null` into the
box for the fall-through. The checker already types the chain as `i32 | null`: an else-less
`if` used as a value is `T | null` in every position (DECISIONS.md, D1086). The emitter's
single-link spelling already runs. What the chain adds is the else-less `if` as the last link,
which is the shape of D1995's open question, and that question's reading (b) says it is a
`T | null` value. This row belongs to that lane: the fall-through arm should box `null` as the
non-sink else-less emitters already do.

#### Ablation

| ingredient changed | outcome | needed? |
| --- | --- | --- |
| the chain cut to one else-less link (`return if k == 1 { 6 }`) | runs, prints `6` then `-1` | **yes** (a chain) |
| an `else { null }` added to the last link | runs | **yes** (the missing else) |
