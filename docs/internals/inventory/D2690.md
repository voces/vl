### D2690 — `{[string]: V} | {[string]: V | null}` for a ref-repped `V` answers `is` true for both arms: the two maps share one tag the same-rep refusal does not see

**check-clean silently wrong · clause 1 · found in the #3194 review · identical on master
`1be1363d9` · filed 2026-09-26 by the W2 lane**

Repro:

    const m: {[string]: string | null} = Map()
    m["k"] = null
    const u: {[string]: string} | {[string]: string | null} = m
    print(u is {[string]: string})
    // PRINTS true

#### Mechanism

Not yet measured. A nullable-ref value (`string | null`, `Circle | null`, `i32[] | null`) is stored
in the same `(ref null …)` slot its non-null twin's map uses, so the two map types are one struct
and one tag. #3193's same-rep refusal (`a union cannot hold both …`) catches the scalar twins and
the literal-union twin, but not this nullable-ref pair, so the union is accepted and `is` reads a
tag both arms carry. The prediction is that the refusal's "shares one representation" test
compares value store classes and a nullable ref classes as the ref.

#### Ablation

| ingredient removed | outcome | needed? |
| --- | --- | --- |
| the ref value (`boolean` / `boolean \| null`, a niche) | prints `false` | **yes** |
| `string` for `Circle` or `i32[]` | prints `true` | no |
