### D2690 — `{[string]: V} | {[string]: V | null}` for a ref-repped `V` answers `is` true for both arms: the two maps share one tag the same-rep refusal does not see

**closed 2026-09-26 by the NR lane — the filed repro RUNS and prints `false` · was check-clean
silently wrong, clause 1 · found in the #3194 review · identical on master `1be1363d9` · filed
2026-09-26 by the W2 lane**

Repro:

    const m: {[string]: string | null} = Map()
    m["k"] = null
    const u: {[string]: string} | {[string]: string | null} = m
    print(u is {[string]: string})
    // PRINTS true

#### Mechanism

A nullable-ref value (`string | null`, `Circle | null`, `i32[] | null`) is stored
in the same `(ref null …)` slot its non-null twin's map uses, so the two map types are one struct
and one tag. #3193's same-rep refusal (`a union cannot hold both …`) catches the scalar twins and
the literal-union twin, but not this nullable-ref pair, so the union is accepted and `is` reads a
tag both arms carry. Measured: the two maps intern two value slots, and `mvCanonRepOf` folds
them to one struct, so `mapSlotTag` hands both one tag. D2493's per-type family table
(`mapTwinNote`) registered only the three mono shapes, so no value-slot pair ever reached it.

The close extends that table to every value-slot map arm. Which slots emit one struct is
known only once collection ends (asking `mvCanonRepOf` at `collectA` trapped the compiler on a
module holding value-slot maps of two integer key reps), so a slot arm is recorded with no
code and `mapTwinSettle`, run just before `emitModule`, groups the rows by canonical struct:
the first type of a struct keeps its slot's tag, every other claims a code above the
value-atom band. A module with no such pair is byte-identical.
