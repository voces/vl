### D15451 — D15450's choice bound to a `const` before the hand is refused at emit even with the split plan

**loud emit reject · clause 2, open · check-clean, then `monomorphize: unsupported argument type for `f` in a call to `both`` with the split plan on and off · the split plan gives each of `both`'s calls its own copy only when the choice is the argument itself (D15450) · found filing D15450 · filed 2026-11-05 against master `6474c12f`**

Repro:

    function both(f) {
      print(f("a"))
      print(f(1))
    }
    function nested(c: boolean, n: i32) {
      function inner(s) {
        print(n)
        return s
      }
      function ask(s) { return s }
      const g = if c { inner } else { ask }
      both(g)
    }
    nested(true, 9)
    // vl check: rc 0.  vl run: emitProgram: monomorphize: unsupported argument type for `f` in a call to `both`

Want:

    9
    a
    9
    1

#### Mechanism

D15450's: `{inner, ask}` stays untagged because `inner` captures `n`, so `g` holds one closure, and
`both` calls it at two signatures. Bound to a `const`, the value has one declaration that the split
plan does not copy per call, so the plan does not serve it either.
