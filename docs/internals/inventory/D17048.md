### D17048 — the IR's narrowed box-field read takes the node's rep, not the field's storage, and claims an atom id as a string

**closed 2026-11-22 by lane IR-N1 · runs, prints `a` · the narrowed box-field read takes the plain struct arm's kid-rep check (`fieldReadsAt`, `ir_build_ref.vl`), so a node rep that is not the field's storage is the named miss `narrowed field read coercion` · fixture `tests/cases/unions/narrowed-field-atom-read-at-string.vl`, shadow row `tests/ir-shadow-rows/narrowed-field-read-rep.vl` · was check-clean invalid wasm, clause 1 · filed 2026-11-22 against master `d78eca95`**

Repro:

    type A = { kind: "circle" | "round", r: f64 }
    type B = { kind: "a", r: f64 }
    function f(n: i32): A | B {
      if n == 0 { return { kind: "circle", r: 1.0 } }
      return { kind: "a", r: 2.0 }
    }
    function h(b: A | B): string {
      if b.kind == "a" { return b.kind }
      return "x"
    }
    print(h(f(2)))
    // vl check: rc 0. vl run: the emitted module failed to validate inside `h`: type mismatch:
    // expected (ref $0), found i32

Want:

    a

#### Mechanism

`b.kind` under `b.kind == "a"` is a box local narrowed to `B`, so the IR builds it as
`RBoxField` (`buildMember`'s `narrowedFieldPlain` arm). That arm types the read at the rep it was
asked for, the node's `str`. It checks a union-box field's unbox rep (`narrowUnboxRepIs`) and
nothing for any other field. The field stores an atom id, so the IR claims an i32 as a string and
writes no decode, where legacy decodes it (`emitAtomToStr`). The plain struct arm refuses the same
disagreement (`field read coercion`). The armed shadow sees it as a claimable function that does not
match, and the unarmed build ships it.
