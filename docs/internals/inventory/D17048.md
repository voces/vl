### D17048 — the IR's atom-to-string decode at a list-literal element omits legacy's stash before the atom-table read

**runs today and must keep running · filed 2026-11-22 against master `4fbcb806` · armed shadow: `node-in array: differ`**

Repro:

    type K1 = "circle" | "round"
    type A = { kind: K1, r: f64 }
    type B = { kind: "a", r: f64 }
    function f(n: i32): A | B {
      if n == 0 { return { kind: "circle", r: 1.0 } }
      const v: B = { kind: "a", r: 2.0 }

#### Mechanism

`b.kind` is an atom delivered at a `string` element, so it is decoded through the atom table
(`RAtomStr`). At a list-literal element legacy stashes the atom (`local.set`) before reading the
table (`global.get 2`). The IR's lowering of the same `RAtomStr` writes the read with no stash, so
the element's bytes differ from legacy's. The function is not claimed on the element's account, and
its output is correct. Only byte identity at that node is lost. A narrowed global `b` shows the
same row: `tests/cases/unions/discriminant-mixed-litunion-bare-literal-arm.vl` under the armed
shadow, once a union-box global's narrowed read is built.
