### D17048 — the IR's node-in fragment of a list literal writes a narrowed atom field's raw id at a string element, with no decode

**runs today and must keep running · filed 2026-11-22 against master `5229077b` · armed shadow: `node-in array: differ`**

Repro:

    type K1 = "circle" | "round"
    type A = { kind: K1, r: f64 }
    type B = { kind: "a", r: f64 }
    function f(n: i32): A | B {
      if n == 0 { return { kind: "circle", r: 1.0 } }
      const v: B = { kind: "a", r: 2.0 }
      return v
    }
    function g() {
      const b = f(2)
      if b is B {
        const xs: string[] = [b.kind]
        print(xs[0])
      }
    }
    g()
    // vl run: prints a. $VL_IR_SHADOW=1: `g` covers and matches, with one `node-in array: differ`
    // row for the element `b.kind`.

Want:

    a

#### Mechanism

`b.kind` is an atom (an i32 id) delivered at a `string` element. Legacy stashes the id
(`local.set`) and writes the one member's string constant (`global.get`), the one-member tower of
`emitAtomToStr`. The whole function `g` lowered by the IR matches those bytes. The node-in probe
lowers the array literal alone, as a fragment, and that fragment writes the `struct.get` of the id
straight into `array.new_fixed` of strings, with no decode. So the defect is in how the fragment
decides the element's delivery, not in `RAtomStr`'s tail. Nothing is claimed through the fragment,
and the program prints the right value. A narrowed global `b` shows the same row:
`tests/cases/unions/discriminant-mixed-litunion-bare-literal-arm.vl` under the armed shadow, once a
union-box global's narrowed read is built.
