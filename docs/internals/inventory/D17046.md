### D17046 — checking a `match` or `is` over a wide union costs about members × arms, so widening one union reprices every match over it

**runs today and must keep running · a performance row, for after I8 · widening the IR's `Rhs` by two members (#9441) costs 0.24G of L2 `checkProgram` fuel with no new node built · filed 2026-11-22 against master `b77be8fd`**

Repro:

    type A = { a: i32 }
    type B = { b: i32 }
    type C = { c: i32 }
    type U = A | B | C
    function f(u: U) {
      return match u {
        A => u.a
        B => u.b
        C => u.c
      }
    }
    print(f({ b: 2 }))

Want:

    2

#### Mechanism

#9441 adds two members, `RAtomic` and `RTruncSat`, to the IR's `Rhs` union of about 80 records,
and an arm for each in the matches over it. Its L2 self-compile fuel rises 452M (+0.42% on
108,270,449,226).

The head's seed compiles the base tree at exactly the base's fuel. So the built compiler is no
slower, and the whole rise is the compile of the new source. By phase, head on head against base
on base:
- `checkProgram` +0.24G;
- the code payload +0.13G;
- emit +0.06G.

The new lines check at about 7x the average line, about 770k fuel against 110k.

`checkProgram` pays for each `match` and `is` over `Rhs` against the wider member set, roughly
members × arms per match, wherever that match sits.
