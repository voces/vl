### D15482 — a call of an inferred function with an un-annotated parameter, handed through a generic identity into a wider record, is check-clean invalid wasm

**closed · now runs, prints `15` · was check-clean invalid wasm, clause 1 (`expected (ref $2), found (ref $0)` inside `idn`, `{r: i32, g: i32}` against `J`) · found narrowing the `idn` pair of the `monoWalkIdentCall` shadow (architecture-target §3.4), where the elaboration answered `{r: i32, g: i32}` and mono `J` · filed 2026-11-05 against master `8d08943d2` · closed 2026-11-05: `recRebuiltCallRow` (check_bind_adopt.vl) answers a callee with an un-annotated parameter too, where its rebuilt row widens the call's own closed record**

Repro:

    type J = { r: i32 | null, g: i32 }
    function idn<T>(v: T): T { v }
    function mk(n: i32) { { r: n, g: 1 } }
    function mkM(n: i32, c) { { r: n, g: c } }
    const m: J = idn(mkM(15, 1))
    print(m.r ?? 0)

Want:

    15

#### Mechanism

`mkM`'s literal is rebuilt at `J`, the record its call is delivered to (D8020), so `mkM` returns a
`J`. The elaboration binds `idn`'s `T` through `recRebuiltLeafRow`, whose call arm answered only a
callee whose parameters are all annotated (D15178), so a callee with a hole parameter kept the
call's own `{r: i32, g: i32}`. `idn`'s instance was then built at that record while its argument was
a `J`. The guard exists because a hole argument can change the record the callee's literal is built
at, so the arm now answers such a callee only where the rebuilt row widens the call's own closed
record.
