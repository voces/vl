### D3375 — an exported function whose name is past 100,000 bytes builds a module no engine parses

**closed 2026-11-12 by `exportNameFits` (`compiler/parser.vl`) · now a loud check reject, raised at the parse stage so `vl check` prints `(parse error)`: `an exported name is at most 100000 bytes, the limit WebAssembly engines place on an export's name; this one is 100001 bytes` · was check-clean invalid wasm, clause 1 · found by lane CT while grading D1978's residual · filed 2026-09-30 against master `4ff12b994`**

Repro (a 100,001-byte identifier, written as `@@repeat` so the row can hold it):

    export function f@@repeat(100000, "x")@@(): i32 { 1 }
    print(1)
    // before: vl check rc 0, then vl run "failed to parse WebAssembly module", exit 70
    // now: a parse error naming the engines' limit

#### Mechanism

The export section spells each export by its source name (`emitExportSection`,
`compiler/emit_sections.vl`), and wasmtime's parser (like V8's) refuses a name string longer
than 100,000 bytes. The checker has no limit on an identifier's length, so the program checks
clean and the module does not load. The same name at 99,999 bytes runs and prints `1`. Whether
the answer is a loud refusal naming the engines' limit or an export spelled some other way is a
design question; the checker's silence is the defect either way.

Closed as a refusal of the contract: an export's name is what the host sees, so spelling it
another way would change the module's interface. The parser refuses an exported declaration's
name, and every name in a re-export clause, past 100,000 bytes (`exportNameFits`).

#### Ablation

| ingredient removed | outcome | needed? |
| --- | --- | --- |
| two characters of the name (99,999 bytes) | runs, prints `1` | **yes** |
| `export` (a plain function of the same name, called) | runs, prints `1` | **yes** |
| a name of exactly 100,000 bytes | runs, prints `1` | the boundary |
| `export const` of a 100,001-byte name | was invalid wasm, now the same parse error | the same defect |
| `export { g as <100,001 bytes> } from "./m"` | was invalid wasm, now the same parse error | the same defect |
