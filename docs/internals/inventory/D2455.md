### D2455 — a `u8[]` result of a curried or listed closure does not take its element type from context

**closed · runs, prints `2` · was loud check reject, clause 2 · pre-existing on master `20651a88b` · filed 2026-09-25 against master `20651a88b`, found reviewing #3154 · closed with [D9742](D9742.md): the inner lambda's inferred `i32[]` is a result the `u8[]` slot's rep refuses, so it takes the slot's result when every value it returns is delivered to it (`finishInferredReturn`, check_inferred_return.vl) · fixture `closures/lambda-result-adopts-slot-result.vl`**

Repro:

    const mk: () => () => u8[] = () => () => [1, 2]
    print(mk()().length)
    // vl run: 2

#### Mechanism

Not ablated. The inner lambda's list literal is typed at its own `i32[]` because the expected
result is not threaded through the outer lambda or a list element into the inner one. The same
spellings at `i64[]` and `f32[]` run today, so the threading exists and only the `u8` storage
type misses it.

#### Ablation

| ingredient removed | outcome on `20651a88b` | needed? |
| --- | --- | --- |
| `u8` for `i64` | prints `2` | **yes** |
| the currying, for a list (`const fs: (() => u8[])[] = [() => [1, 2]]`) | still refuses | no |

#### Grading list

The two spellings above, and a `u8[]`-returning closure passed as an argument.
