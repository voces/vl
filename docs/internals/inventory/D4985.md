### D4985 — an undeclared callee handed a non-scalar local makes every caller's write summary opaque, so one undeclared name also reports a narrowing kill in another function

**loud check reject · filed 2026-10-15 against master `d826b6339` · diagnostic cascade, no check-clean program reaches it**

Repro:

    type Mode = "a" | "b" | "c"
    type E = { mode: Mode, n: i32 }

    function g(x: i32): boolean {
      const xs: string[] = []
      nope(x, xs)
      x > 0
    }

    function f(e: E): i32 {
      if e.mode == "a" { return 1 }
      if g(e.n) {
        if e.mode == "b" { return 2 }
      }
      3
    }

    print(f({ mode: "b", n: 1 }))
    // vl check: rc 1, two errors. The first, `undeclared identifier 'nope'`, is the program's
    // defect. The second, `'e.mode' was narrowed by a guard, but the call to 'g' on line 12 can
    // write it`, is a cascade from it: declare `nope` and the second disappears.

#### Mechanism

`callDeclFnIx` answers `-2` ("an intrinsic named by a bare identifier") for any bare callee with
no declaration and no binding, an undeclared name included. `callWriteShapes` then charges each
argument through `weArgShapes`, which answers `"*"` for a non-scalar local of the summarised
function (`strListHas(bound, …)`). So `g`'s shape summary is opaque, every caller's summary built
over it is opaque too, and the narrowing kill in `f` reports a write nobody makes. The cascade
crosses modules: on 2026-10-15 a missing import in `compiler/typecheck.vl` (`fnBoundNames(cbIx,
bound)`) made `compiler/wasmEmit.vl`'s `emitAsCast` report two narrowing kills of `e.asMode`
through `asExprIsUnionCastIn`, which reaches the checker transitively.

#### Ablation

| ingredient removed | outcome | needed? |
| --- | --- | --- |
| the list argument `xs` (`nope(x)`) | only the undeclared-identifier error | **yes** |
| the read of `e.mode` after the call | only the undeclared-identifier error | **yes** |
| the undeclared name (`xs.push("q")` instead) | runs, prints `2` | **yes** |
| `g` in another module | still two errors | no |
