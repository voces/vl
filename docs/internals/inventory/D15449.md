### D15449 — a `let` seeded with a function that returns nothing, written one returning a value and called at two types, runs only through the split plan

**closed 2026-11-05, runs with the split plan on and off · was split-plan dependent: with it off a loud emit reject, `the reassigned function binding `m` holds functions called at more than one argument type`, clause 2 · the call's members split as `void` against `i32`, and the tag decision declined a written `let`'s set on any split (D9003's one-result rule), so mono refused it · closed by `fnTagCallNote` and `mintFactNote` record a call whose members split only as `void` against one value type (`rsVoidSplit`), and `ftPlan` keeps a written `let`'s set tagged through such a split, so each call dispatches at its own signature and drops the value; fixture `closures/void-seeded-let-written-value-fn-called-at-two-types.vl` · filed 2026-11-05 against master `d7080b052`**

Repro:

    function inner(u) { print("I"); print(u) }
    function retV(v) { print("R"); print(v); v }
    let m = inner
    m = retV
    m(7)
    m("t")

Want:

    R
    7
    R
    t

#### Mechanism

Under ruling B2 the write is accepted and each call drops `retV`'s result. Mono instances the
written functions at one signature per binding (`monoLetPinTake`), and the two calls pin two, so
it refuses (`monoBindSigFail`) and asks the split plan, which gives each call its own instance.
Without the plan the refusal stands.
