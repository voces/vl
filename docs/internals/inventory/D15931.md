### D15931 — a `.map` whose callback returns only `null` builds a list of only `null` and invalid wasm

**closed · now a loud check reject, `map callback returns only \`null\`, so the list it builds has no element type` · was check-clean invalid wasm, clause 1, `expected i32, found nullref` · DESIGN: a list of only `null` has no element type, as the literal `[null]` is refused; the annotated spelling `(y): i32 | null => null` runs · filed 2026-11-12 against master `22d35fe4` · closed the same day by refusing it where `.map` types its result (`memberCallMapFilterTy`, check_member_call.vl) · fixture `arrays/error-map-callback-only-null.vl` · found grading [D14890](D14890.md)'s `kept-maker-delivery-null-field` template, whose `field_map` and `map_lambda` cells it made silent where a row refusal had masked it**

Repro:

    const ns = [1].map((y) => null)
    print(ns.length)
    // vl check: map callback returns only `null`, so the list it builds has no element type

#### Mechanism

`.map` types its result `mkArrayTy(cbRet)`, so a callback whose result is the `null` unit gives
`null[]`. The literal rule (`flushNullOnlyLits`) refuses that list when no typed destination
names its element; `.map` had no such rule, and the emitter stored the callback's `nullref`
into an `i32` element slot.
