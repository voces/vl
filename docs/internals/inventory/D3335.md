### D3335 — a `match` over a value typed `null` traps the compiler

**closed · runs: a `null`-only scrutinee has the one member `null` (`matchScrutOnlyNull`, `check_match.vl`) · pins `tests/cases/match/match-over-bare-null.vl` · was a compiler trap in `vl check` (exit 70), clause 1 · the same on master `b6378e95b` · found by the lane JW grid (the `match` reader of the `n-n` and `n-n-n` pins, every spelling) · filed 2026-09-30**

Repro:

    const v = null
    print(match v {
      null => "null"
    })

Want:

    null

#### Mechanism

`const v = null` types `v` as a `| null` over an inner hole (`nInner` -1). The `match` check
flattened that into the members `-1` and `null` and read `T.tys[-1]` in `unionHasLitMember`. A
scrutinee that is `null` alone now has the one member `null`, so its `null` arm checks as a type
arm and an `i32` arm is refused as not a member.
