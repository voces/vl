### D4784 — `std:fmt` `toString` over an integer allocates a new string per digit: `bench/strings/int-format` is 4.2x slower than the retired ambient builtin and 4.9x Deno

#### Mechanism

`renderI64` in `std/fmt.vl` builds the result as `out = digitChar(d) + out`, one digit at a
time, then `"-" + out`. Each step allocates a string header and a backing copy, and
`digitChar` is a ten-arm ladder. The ambient `toString(i32)` that counted digits and filled
one exact-fit array was retired (owner ruling 2026-09-01). No compiler path builds a string
from a byte buffer without copying: `decodeUtf8` goes through `fromCodePoints`.

#### Ablation

vidi (Apple M1, 5 interleaved reps, median ms), the bench at N = 30,000,000, master compiler.

| variant | ms |
| --- | --- |
| bench as written | 4338 |
| digits into an `i32[]` + `fromCodePoints` | 3779 |
| 3-digit string table, prepend concat | 2481 |
| digit table, forward append from the highest power of 10 | 2420 |
| the August builtin's wasm on today's host | 1021 |

Startup is about 10 ms for VL and 20 ms for Deno.

#### Grading list

Two fixes, either of which closes the row: a std-internal intrinsic that builds a string
from a byte range in one exact-fit backing (std renderer counts digits and fills once,
graded against the 1021 ms proxy), or the forward-append body alone as an interim (no
signature change, so no std-api review). Grade on the bench and on the witness's output.

#### Fix

`__str_from_bytes__(src: u8[], at: i32, count: i32): string` is a checker builtin (not a scope
declaration, so a call is no opaque function value to the narrowing rule) lowered to one call
of the `__str_from_bytes__` helper: bounds-check the range against `src`'s length and trap past
it, `array.new_default` an exact-size backing, one `array.copy`, one string header. It is
reserved by `nameIsEmitterIntrinsic` and spelled with `__`, so it is std's floor and not
surface. `renderI64` writes digits into a module-level `u8[20]` from the right, prepends `-`,
and builds the string once. `std/test.vl`'s `vltI64Str` keeps the per-digit form: it is
self-contained by design and not on a hot path. There are no unsigned or hex integer renderers
with the same shape.

before and after.

Ablation at N = 30,000,000 on `render(i64)` called directly: the shipped body about 1170 ms;
an `i32` fast path for the low digits about 1200 ms; two digits per step from a 200-byte pair

f64` argument is boxed at each call (`struct.new` twice in the caller, unboxed in
`toString`), which is a union-parameter cost rather than this row's.
