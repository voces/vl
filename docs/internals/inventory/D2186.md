### D2186 — a generic whose tail `if` joins two locals of its type parameter declares an `i32` result at a string or f64 pin

**closed 2026-09-26 — the filed repro RUNS and prints `1.5` then `s` · was check-clean invalid
wasm, clause 1 · filed 2026-09-23 against master `fa5db1bac`, found reviewing the
[D2170](D2170.md) close (#3058); widened by the #3175 review · fixture
`tests/cases/generics/tail-join-locals-and-empty-list-arg.vl`**

Repro:

    function id<T>(c: boolean, x: T, y: T) {
      const a = x
      const b = y
      if c { a } else { b }
    }
    print(id(true, 1.5, 2.5))
    print(id(true, "s", "t"))
    // vl check: rc 0.  vl run: rc 70, `id` fails validation: expected i32, found f64

#### Mechanism

The checker types the join of the two locals as `T | T`: two variable nodes of one name, which
the union does not collapse. #3175's rung that spells a bare-`T` inferred return as the `: T`
annotation (`monoCheckedRetTyParam`) accepted only a bare variable, and D2037's rung pins only a
join bearing `null`, so no instance result was pinned and return inference, which cannot
classify a local whose kind no global pass has collected, fell to `i32`. The close reads a join
whose every member is the same variable as that variable (`monoSoleTyVarName`).
