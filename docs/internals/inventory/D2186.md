### D2186 — a generic whose tail `if` joins two locals of its type parameter declares an `i32` result at a string or f64 pin

**check-clean invalid wasm · clause 1 · filed 2026-09-23 against master `fa5db1bac`, found reviewing the [D2170](D2170.md) close (#3058), which leaves it as filed**

Repro:

    function id<T>(c: boolean, x: T, y: T) {
      const a = x
      const b = y
      if c { a } else { b }
    }
    print(id(true, 1.5, 2.5))
    print(id(true, "s", "t"))
    // vl check: rc 0.  vl run: rc 70, `id` fails validation: expected i32, found f64

#### Mechanism

Not ablated. The same family as D2170's second defect, in a monomorphized instance: the return
walk cannot classify a returned local whose kind no global pass has collected, and the
instance's function type still names the type parameter, so D2170's fallback (the struct row of
the checker's result) has nothing to read. The `i32` pin runs; the string and `f64` pins
declare an `i32` result over a body yielding the pinned rep.

#### Grading list

The string pin alone; the same join returned directly as `if c { x } else { y }`.
