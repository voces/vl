### D10250 — an inline list literal of a generic handed to a generic function at two types is refused by emit as an internal error

**loud emit reject · `vl check` rc 0 · `emitProgram: internal: a parameter type the valtype ladder has no rung for — every parameter type the checker accepts has one above` · clause 2 · CAPABILITY: the calls spelled `run<string>([id], "s")` and `run<i32>([id], 5)` print `s`, `5`, and so does a `const` list per call · found closing [D10204](D10204.md) · present on master `d5576d929` · filed 2026-10-22 against master `d5576d929`**

Repro:

    function id<T>(x: T): T { x }
    function run<U>(a: ((x: U) => U)[], u: U): U { a[0](u) }
    print(run([id], "s"))
    print(run([id], 5))
    // vl check rc 0.  vl build: internal: a parameter type the valtype ladder has no rung for

Want:

    s
    5

#### Mechanism

Not traced. Since the close of [D10204](D10204.md) the literal binds `U` after the other
argument, and the first call alone runs, as do two calls at one type; with calls at two types the instance of `run`
emit builds still carries a type variable in its parameter type.

#### Ablation

| ingredient removed | outcome | needed? |
| --- | --- | --- |
| the second call `run([id], 5)` | runs, `s`, since [D10204](D10204.md) | **yes** |
| the second call's other type: `run([id], 5)`, `run([id], 6)` | runs, `5`, `6`, since [D10204](D10204.md) | **yes** |
| explicit `run<string>` and `run<i32>` | runs, `s`, `5` | **yes** |
| `const xs = [id]`, `const ys = [id]`, `run(xs, "s")`, `run(ys, 5)` | runs, `s`, `5` | **yes** |
