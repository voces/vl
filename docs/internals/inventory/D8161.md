**now a loud check reject · filed 2026-10-20 against master `da93ef793` · clause 1, present on master · made loud by `directHoleBodyRet` taking the direct call's result from the body at the bound arguments · fixture `functions/error-direct-hole-fn-widening-at-i32.vl`**

Repro:

    function half(a) { return a / 2.0 }
    const r: i32 = half(3)
    print(r)
    // master: vl check rc 0, vl run: the emitted module failed to validate: type mismatch: expected i32, found f64.  now: f64 doesn't fit in i32

#### Mechanism

The direct call's result was `half`'s signature result `T` substituted at the argument's
`i32` (`callFtyPinCstrs`, `check_calls.vl`), because the checker types `a / 2.0` as the hole
`T`. The emitter's instance of `half` at `i32` returns `f64`. The call now takes the result
the body gives at the bound arguments (`holeLamRetAt`, as D8100's hole call does), for a
named function, a `const` lambda and a `const` alias of either.
