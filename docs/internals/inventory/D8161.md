### D8161 — a direct call of an un-annotated function widening `i32` to `f64` is accepted at an `i32` binding

**check-clean invalid wasm · filed 2026-10-20 against master `da93ef793` · clause 1, present on master**

Repro:

    function half(a) { return a / 2.0 }
    const r: i32 = half(3)
    print(r)
    // vl check: rc 0.  vl run: the emitted module failed to validate: type mismatch: expected i32, found f64

#### Mechanism

The direct call's result is `half`'s signature result `T` substituted at the argument's
`i32` (`check_calls.vl`, the call's result substitution). The body is not re-derived there,
though the emitter's instance of `half` at `i32` returns `f64`. The hole-call spelling
(`function p(h) { const r: i32 = h(3) }`, `p(half)`) refuses correctly since D8100, through
`genFnHoleBodyRet`. The direct call needs the same result at its call site, in
`check_calls.vl`, which is outside lane L1's file boundary.

#### Ablation

| ingredient removed | outcome | needed? |
| --- | --- | --- |
| `a: i32` on `half` | check refuses (lossy conversion) | **yes** |
| the `: i32` on `r` | runs, `1.5` | **yes** |
| the direct call for a hole call `h(3)` | check refuses | **yes** |

#### Grading list

`const f = half; const q: i32 = f(3)`, the same call through a binding.
