### D4577 — a list of a generic passed to an un-annotated parameter reaches no call

**closed 2026-10-14 by lane SC · runs · was loud emit reject · an un-annotated parameter of a non-exported function whose every use is a direct call is a flow-read candidate whose values are its arguments' (`monoFlowParamVals`), and the flow-shadow table banks parameter slots (`fn-value-flow-design.md` §(f) step 4) · pins: `tests/cases/closures/generic-list-to-unannotated-param.vl` · found by `fn-value-generic-list-read.matrix.vl` (`argument` and `early_return_guard`, un-annotated face) · filed 2026-10-14 against `bd616c03b`**

Repro:

    function id<T>(x: T): T { x }
    function use(v) { print(v[0](2)) }
    use([id])
    // vl check: rc 0.  vl run: emitProgram: a generic function taken as a value reaches no call that fixes its type

Want:

#### Mechanism

Flow reads rewrite a read whose root is a binding of literals (`monoFlowLitRoot`); a parameter
is not such a binding, so the call `v[0](2)` inside `use` is never traced back to the argument
literal, and nothing instances `id`. It is the "argument" row of `fn-value-flow-design.md` §(e)
for a container rather than a bare function.
