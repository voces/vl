**closed 2026-11-26 by lane COV-UNION · runs, prints `true` `false`, claimed by the IR · was: the claim fell back with `unlowered: operand above a valued if's value`, and legacy wrote the function · `atomCompare` stages the literal's member id below the `??`'s valued `if` (`stagedStaticId`, `aeStatic` 4), and the ids arm stages its left operand (`stageLeftBelow`) · sweep `literal-unions/atom-compare-left-staged-below-coalesce-right-positions.vl` · filed 2026-11-24 against master `6e7d4a654` by lane IR-N6**

Repro:

    type K = "a" | "b"
    function p(s: K | null): boolean { return "a" == (s ?? "b") }
    print(p("a"))
    print(p(null))

Want:

    true

#### Mechanism

Legacy's `atomEqPlanOf` takes the `static` arm with the literal on the left (`aqStaticLeft`). It
writes the literal's atom id, then the `??` over the atom, whose join is a valued `if`. The IR's
`atomCompare` builds the static side, then `atomSide` of the `??`. The lowering then finds the static
operand on the stack above the `??`'s valued `if` and refuses: `unlowered: operand above a valued
if's value`. The program runs because legacy writes `p`. Before D17241 closed, this same fallback
left the shipped atom ids unlike the claimless build's.
