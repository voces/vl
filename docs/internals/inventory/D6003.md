### D6003 — a function returning a generic, called in a generic body at the body's own type parameter, has no signature per instance

**loud emit reject · `vl check` rc 0 · clause 2 · found closing [D5970](D5970.md) · the same on master `200c89ff8` · filed 2026-10-17 against master `200c89ff8`**

Repro:

    function k<T>(x: T): T { return x }
    function mk() { return k }
    function g<U>(u: U) {
      const a = mk()
      print(a(u))
    }
    g(1)
    // vl check: rc 0.  vl run: emitProgram: a function-value call has no interned signature — parameter 1 of type `` has no representation in the function-value ABI

Want:

    1

#### Mechanism

From the ablation and D5970's close. D5970 banks one signature for `a`, which every instance
of `g` shares; that is sound only when the call's types are closed. Here the call's argument
is `U`, so the signature differs per instance and the template's read has no closed one to
bank. With `g(1)` and `g("z")` the refusal is `a generic function taken as a value reaches
no call that fixes its type` at `return k`.
