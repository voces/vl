### D16863 — one module `let` of a record union costs the self-compile about 4% fuel, and the mono pass's gate assumes the compiler has no higher-order function

**runs today and must keep running · compile cost of the compiler's own source, not a wrong program · filed 2026-11-16 against `ir-i8b2-sink` `6a254986f`**

Repro:

    type OVar = { ov: i32 }
    type OImm = { oiRep: i32, oiBits: i64 }
    type Opnd = OVar | OImm
    let held: Opnd = { ov: -1 }
    function hold(o: Opnd) {
      held = o
      return 0
    }
    function read(): i32 {
      const h = held
      if h is OVar { return h.ov }
      return -2
    }
    hold({ ov: 7 })
    print(read())

Want:

    7

#### Mechanism

Two spellings in I8b part 1 each cost about 4% of L2 self-compile fuel (`vl build
compiler/entry.vl`), measured by compiling each tree with one fixed compiler. `vl check` fuel was
flat, so both land after the checker. (1) `let lwHoleOpnd: Opnd` in `ir_lower.vl`, the IR's
three-record operand union, cost about 2G to assign from a record field and about 2G to hold. This
was not traced. Holding the same value as an `Rhs[]` costs nothing measurable. (2) A closure
parameter on a function with an annotated return (`emitBoxAroundHole(…, write: () => i32): i32`)
makes `monoHasConcreteHOFParam` true. That gate turns callback specialization on for the whole
program, and its comment says it holds because "the compiler itself has none". Any compiler
change can falsify that assumption. A guest profile showed `monomorphize` rising from 52 samples
to 862, under `monoFlowReads`, `monoPruneTemplates` and `monoProgTopMark`.

#### Grading list

Whoever traces (1) also judges whether the gate in (2) should be a measurement, made from the
program's actual higher-order functions and their cost, rather than an assumption about the compiler.
`scripts/self-compile-time.sh` is the gate that caught both.
