### D5017 — a call through a binding to a NAMED function writes anything, so it cancels every narrowing

**loud check reject · filed 2026-10-16 against master `a692bd212`**

Repro:

    type Box = { m: string | null }

    function countNone(n: i32): i32 { 0 }
    const counter: (n: i32) => i32 = countNone

    function tally(n: i32): i32 { counter(n) }

    function show(b: Box): i32 {
      if b.m != null {
        const k = tally(1)
        return b.m.length + k
      }
      -1
    }

    print(show({ m: "abc" }))
    // vl check: 'b.m' is no longer narrowed to string: the call to 'tally' on line 10 may reassign it

#### Mechanism

`callDeclFnIx` (`check_callee.vl`) resolves a call's target only for a declared function or a
binding bound once to a LAMBDA (`cwLambdaDeclOf`). A binding to a named function, `const` or
`let`, answers -1. `callWriteShapes`, `callFreeEffects` and `callInvalidatesReal` read -1 as
"may write anything", so `tally`'s summary is opaque and every narrowing its callers hold ends
at the call, although no function the binding can hold writes `b.m`. This blocks the L9 checker
hook: a fn-typed slot inside `checkNode`'s closure makes the whole checker opaque, and
`vl check compiler/entry.vl` then refuses two narrowed reads of `e.asMode` in `emitAsCast`.

#### Ablation

| variant | outcome | needed? |
| --- | --- | --- |
| a `let` re-pointed through an exported setter `counterSet(bump)` | still refuses | no |
| a `let` re-pointed by a top-level `counter = bump` | still refuses | no |
| the `const` above (no re-pointing at all) | still refuses | no |
| `let counter = (n: i32): i32 => 0`, a lambda bound once | runs, prints 3 | **yes** |
| `tally` calls `bump(n)` directly | runs, prints 5 | **yes** |

#### Grading list

- The setter spelling, which is the shape the checker hook needs: `let counter: (n: i32) => i32 =
  countNone`, `export function counterSet(f: (n: i32) => i32) { counter = f }`, a top-level
  `counterSet(bump)` with `function bump(n: i32): i32 { n + 1 }`, then the same `show`. It must
  keep the narrowing, because neither function the slot can hold writes `b.m`.
- The negative control: the same setter shape where the installed function writes a `Box` it
  can reach must still cancel the narrowing.
