### D12902 — an identity `.map` over a `u8[]` builds its result at a different list type from the one it stores

**closed 2026-10-25 — the witness prints `2` · was check-clean invalid wasm, clause 1: `mfResultKindOf` answers `"u8"` for a `.map` whose call is typed `u8[]`, so the result is built at the packed byte list the binding holds · fixture `tests/cases/arrays/u8-list-map-positions.vl` (14 delivery positions, each silent before) · found closing [D12820](D12820.md) · filed 2026-10-25 against master `db1d4f849`**

Repro:

    const xs: u8[] = [1, 2]
    const m = xs.map((e) => e)
    print(m.length)
    // vl check: rc 0.  vl run: invalid module, type mismatch: expected (ref null $type), found (ref $type)

Want:

    2

#### Mechanism

The checker types the result `u8[]`, the callback's return is a `u8`, and the map lowering
builds the result list at a different array type from the one the binding's local holds, so
the module fails validation at the store. The arm is `mfResultKindOf`'s callback ladder: a
`u8` return reads as `i32` in both `cloRetKindOf` and `cloRetValKind`, so the call took the
`"i32"` result kind and `emitMapFilter` built an `(array (mut i32))` backing under the `i32`
list wrapper, then stored it where the `u8[]` wrapper belongs (disassembly: `array.new_default`
of the i32 array, `struct.new` of the i32 list, `global.set` of the u8-list global). `.filter`
was immune because its result kind forwards the receiver's. The call's recorded type now
answers first.

#### Ablation

| ingredient changed | outcome | needed? |
| --- | --- | --- |
| `xs: i32[]` | prints `2` | **yes** (the `u8` element) |
| `print(m[1])` in place of `m.length` | the same invalid module | no |
| `(e) => "x"` (a string result) | prints `2` | **yes** (a `u8` result) |
| `.filter((e) => true)` in place of `.map` | prints `2` | **yes** |
| `(e) => e + 1` or `(e): i32 => e` | loud check reject (D2299's design) | — |
