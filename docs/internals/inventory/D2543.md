### D2543 — an unannotated generic function's tail built-in method call is compiled as a statement, not the implicit return

**closed 2026-09-26 by [D2566](D2566.md)'s close — the filed repro RUNS and prints `1` · was check-clean invalid wasm · clause 1 · found by review · filed 2026-09-25 against master `a09d1f6bc` · fixture `tests/cases/functions/expression-body-member-call-result.vl`**

Repro:

    function f<T>(x: T[]) { x.slice(0, 1) }
    const r = f([1, 2, 3])
    print(r.length)
    // vl check: rc 0.  vl run: invalid module inside `f`, type mismatch: expected i32, found
    // (ref $type)

#### Mechanism

The checker types `f<T>`'s return as `T[]` from the tail expression `x.slice(0, 1)` and accepts
`r.length` against it — the value-level answer is right. At emit, the same tail statement is a
call to a BUILT-IN array method with no declared return annotation on `f`, and the function's
own return-kind classification treats it as a plain statement (an implicit `void`), so the
compiled body drops the slice's value instead of leaving it as the return. The wasm function
signature still carries whatever the checker's answer produced, so the body's dropped value
against a non-void signature fails validation.

#### Ablation

| ingredient removed | outcome | needed? |
| --- | --- | --- |
| the return annotation (`function f<T>(x: T[]): T[] { ... }`) | runs, prints `1` | **yes** |
| the generic (`function f(x: i32[]) { x.slice(0, 1) }`, unannotated, concrete) | runs, prints `1` | **yes** — genericity is required |
| the built-in call in tail position (`function f<T>(x: T[]) { x }`, bare identity tail) | runs, prints `3` | **yes** — a plain tail expression is fine |
| tail position (the call followed by another statement, so `f` infers `void`) | correctly refused: "cannot bind the void result of `r`" | no — confirms non-tail position is handled right |

#### Grading list

Any built-in method (not just `Array.slice`) called in tail position of an unannotated generic
function whose return type must be inferred from that call.

#### Close

The same mechanism as [D2566](D2566.md): `computeRetInference` classified no member-call tail,
so the result kind came only from the checker-name cascade, which has no arm for a `T[]` at the
template. A value-yielding member-call tail is now classified as `return <tail>` is; `.slice`,
`.filter` and `.map` at `i32`, `string` and `boolean` instances all run.
