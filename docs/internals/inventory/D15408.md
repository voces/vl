### D15408 — a `let` of generics written from a closure and handed at the enclosing generic's type parameter is refused by mono

**loud emit reject · `vl check` rc 0, `vl run`: `emitProgram: monomorphize: unsupported argument type for `g` in a call to `app`` · clause 2 · CAPABILITY: the same `let` written directly runs, and so does the closure-written one handed at a concrete type or called directly · same with the split plan on and off · found grading D15103's close · filed 2026-11-05 against master `bb62844d`**

Repro:

    function fst<T>(xs: T[]): T { return xs[0] }
    function lst<T>(xs: T[]): T { return xs[xs.length - 1] }
    function app<T>(g: (x: T[]) => T, v: T[]): T { return g(v) }
    function both<U>(u: U[]): U {
      let f = fst
      const flip = () => { f = lst }
      flip()
      app(f, u)
    }
    print(both(["x", "y"]))
    // emitProgram: monomorphize: unsupported argument type for `g` in a call to `app`

Want:

    y

#### Mechanism

A closure writing `f` makes the binding a capture cell, and the tag decision declines the set
`{fst, lst}` in it, so `f` stays a closure value. Its hand at `(x: U[]) => U` is closed only
per instance of `both`. Neither the per-node adapter record nor mono's pin of the argument
covers a closure value delivered at a type that differs per instance. D15103's close does not
reach it, because a `let` some closure writes is not settled at the hand
(`cwLetSettledAt`). The capability belongs to the per-instance closure work
(per-instance-identity-2026-11.md, slice 4b-ii: an id written into a capture cell).
