### D15408 — a `let` of generics written from a closure and handed at the enclosing generic's type parameter is refused by mono

**closed 2026-11-05, runs with the split plan on and off, prints `y` · was loud emit reject, `vl check` rc 0, `emitProgram: monomorphize: unsupported argument type for `g` in a call to `app``, in both plan states · clause 2 · found grading D15103's close · filed 2026-11-05 against master `cd407210` · closed by building the adapter for a set at the enclosing generic's types over a `const` copy of the value, read once in an if-expression arm (`fvaAdapt`, check_assignable.vl), so the closure's later write cannot reach the delivered adapter · fixture `closures/written-let-handed-at-enclosing-type-param-then-written-again.vl`**

Repro:

    function fst<T>(xs: T[]): T { return xs[0] }
    function lst<T>(xs: T[]): T { return xs[xs.length - 1] }
    function app<T>(g: (x: T[]) => T, v: T[]): T { return g(v) }
    function both<U>(u: U[]): U {
      let f = fst
      const flip = () => { f = lst }
      flip()
      app(f, u)
    }
    print(both(["x", "y"]))
    // was: emitProgram: monomorphize: unsupported argument type for `g` in a call to `app`

Want:

    y

#### Mechanism

A closure writing `f` makes the binding a capture cell, and the tag decision declines the set
`{fst, lst}` in it, so `f` stays a closure value. Its hand at `(x: U[]) => U` is closed only
per instance of `both`. Neither the per-node adapter record nor mono's pin of the argument
covers a closure value delivered at a type that differs per instance. D15103's first close did not reach it: its adapter called the `let` itself, which a closure's later write would re-point, so it served only a `let` no later write reached. The close copies the value into a `const` beside the adapter instead.
