### D2067 — a getter-contract refusal is reported once per sub-expression, so one string `+` prints the same error twice at the same column

**closed 2026-09-22 — now a loud check reject, reported once, naming the rule and the method to write instead · diagnostics quality · filed 2026-09-22 against master `31ea77721`, found by three lenses of the getters/effects persona review (Swift `p8`, TypeScript `p1`, beginner `p04`/`p05`) · fixture `tests/cases/getters/getter-refusal-shape.vl`**

Repro:

    type Name = new { first: string, last: string }
    get full(self: Name): string { self.first + " " + self.last }
    const n: Name = { first: "a", last: "b" }
    print(n.full)
    // vl check, filed: "the getter `full` on Name concatenates strings, which allocates — …"
    // twice, both at 2:32, one spanning the whole `+` chain and one its left operand
    // vl check, closed: once, at 2:32 over the whole chain: the getter `full` on Name
    // concatenates strings, and a getter must not allocate — make it a method:
    // `function full(self: Name): string`, called as `.full()`

#### Mechanism

The walk reported at every `+` node whose operands are strings, and `a + b + c` is two nested
nodes starting at the same column, so one mistake yielded two identical lines. The
nullable-result refusal had the same shape: `get positive(self: Cell): i32 | null { … }`
reported once at the return type ("returns `i32 | null`, whose representation is boxed") and
again at the body ("computes a value of type `i32 | null`"). Every contract message also ended
in the same 110-character restatement of the whole rulebook, used "pure" (the contract is not
`pure`) and "null niche", and none named the one fix that always works,
`function full(self: Name): string` read as `n.full()`.

#### The close

`getterContractErr` takes the rule the construct breaks and raises each distinct fact once per
getter (`gwSaid`), so the outer `+` of a chain speaks and the nested one is silent, and a callee
called three times (`sq(self.x)` ×3, game-perf `p2b`) is one error. The boxed-result refusal
marks its type as already refused before the body walk, and the boxed-type memo compares
spellings, so `i32 | null` is one error at the return type. Every refusal now reads "the getter
`p` on T <construct>, and <one rule> — make it a method: `function p(self: T): R`, called as
`.p()`", with the rules "must not allocate", "must not loop", "must not recurse", "must not
have side effects", "must not read mutable state", "may call only other getters and the load
and SIMD intrinsics". A boxed result adds "return a type without `| null`" (or "a type that
needs no allocation" for a value union) before the method fix.
