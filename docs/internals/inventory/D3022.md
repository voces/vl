### D3022 — a block-scoped `type` used as an annotation is an unknown type once the program imports `std` (string interpolation is enough)

**loud check reject · clause 2 · found writing the [D3021](D3021.md) fixture · the same on master `ad64c62c1` · filed 2026-09-28**

Repro:

    function local() {
      type U = { ty: i32 }
      const u: U = { ty: 3 }
      print(u.ty)
    }
    local()
    print("n \{2}")
    // vl check: unknown type 'U'.  Without the interpolation it prints 3, then nothing else

#### Mechanism

Not yet located. A body-scoped `type` is minted under a unique name (`U` → `U$b1`, D1045) and
hoisted into `progStmts`, and the annotation is spelled at that name. The interpolation pulls
`std:fmt` into the program, so the module merge runs (`modRwStmt`, `modTypeRenamed` in
`driver.vl`), and it is the merge that loses the reference: the hoisted declaration is skipped
at program level and renamed at its lexical position, and the annotation `U` is then resolved
against a table that no longer holds the name it was spelled at. Where exactly the two spellings
part is the first thing to print.

#### Ablation

| ingredient removed | outcome | needed? |
| --- | --- | --- |
| the interpolation (the `std` import) | prints 3 | **yes** |
| the annotation `: U` | prints 3 and `n 2` | **yes** |
| the order (interpolation first) | still refused | no |
