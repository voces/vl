### D4037 — an un-annotated `const` of an `if` joining a literal-union arm and a string literal is `string`

**loud check reject · clause undecided (owner surface ruling pending) · found closing DV-1207 · filed 2026-10-11 against master `98a4ed71b`**

Repro:

    type Look = "knife" | "none"
    type Holder = { look: Look }
    function pick(ok: boolean, h: Holder): Look {
      const look = if ok { h.look } else { "none" }
      look
    }
    print(pick(false, { look: "knife" }))
    // vl check: "expected Look, got string"

#### Mechanism

DV-1207 types a join whose arms are a literal-union value and string literals of it as the
union only when the join has a destination of that union: an annotated binding, a return, an
argument, a field, an element or a store. With no destination the join keeps `string`, as an
un-annotated function tail and a closure body already do, so a later `look` delivered to `Look`
refuses. Whether an un-annotated join should infer the union is a surface question for the
owner, and this row stays loud until it is answered.

#### Ablation

| ingredient removed | outcome | needed? |
| --- | --- | --- |
| the un-annotation (`const look: Look = …`) | runs, prints none | **yes** |
| the binding (the `if` as the function's tail) | runs, prints none | **yes** |
| the join (`const look = h.look`) | runs, prints knife | **yes** |

#### Grading list

The same join spelled with `match` arms, and with an `else if` link of literals.
