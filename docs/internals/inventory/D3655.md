### D3655 — `e is C` with `e: i32` over an integer literal union spanning two widths is refused as "can never match"

**closed 2026-10-05 — the witness prints `true` · was a loud check reject, clause 2 · found by lane WV while closing [D3590](D3590.md) · filed 2026-10-04 against master `32b753681` · fixture `tests/cases/literal-unions/is-mixed-width-union-narrow-receiver.vl`**

Repro:

    type C = 1 | 3000000000
    const d: i32 = 1
    print(d is C)
    // vl check: `is` check type 'C' can never match a value of type i32

Want:

    true

#### Mechanism

`checkIs` (typecheck.vl) gates the test on `assignable(C, i32)`, which fails because
`3000000000` is not an `i32`. The two literal meets that rescue a partial overlap both declined:
`litSetMeetTy` needs the receiver to hold literals, `litBaseMeetTy` needs the TEST to be a
primitive. A plain primitive receiver against a literal set had no meet at all. Fixed by
`litPrimMeetTy`: the members of the set the primitive can hold, banked as the test's type when
some but not all fit, for an `i32` or `i64` receiver and a set of integer literals only; a set
none of whose members fit keeps the "can never match" refusal. A float receiver is left out on
purpose: its answer against an integer literal waits on [D3689](D3689.md), and admitting it
turned `f64 is 1 | 3000000000` from a check error into D3689's invalid module. The
`i64` receiver of the same union runs since D3590. Neighbour found while grading: [D3689](D3689.md).
