### D15598 — a capturing nested hole handed to two parameters of one type parameter, called at two types, refuses because `F` takes one

**loud emit reject · clause 2, `vl check` rc 0, then `emitProgram: monomorphize: a generic function handed to two parameters of type `F` in a call to `mid` is called at two types, and `F` takes one` · D15596's neighbour · filed 2026-11-09 against master `82d99608`**

Repro:

    function mid<F>(a: F, b: F) {
      print(a("x"))
      print(b(2))
    }
    function outer<U>(u: U) {
      function same(k) {
        print(u)
        k
      }
      mid(same, same)
    }
    outer(7)
    outer(true)

Want:

    7
    x
    7
    2
    true
    x
    true
    2

#### Mechanism

Both arguments are the one singleton `Fn#same`, so `F` binds once. A hole handed `Fn#d` is
bound per call as `Fn#d` (orchestrator ruling), and the call through `a` and the call through
`b` each pick their own instance, as the one-parameter spelling does with a bundle (D15596).
Mono refuses instead. Not yet traced past the message.
