### D1592 — the checker types `.push` `i32` and the emitter had no value lowering for it, so its result is INVALID WASM where a function's tail returns it and a loud reject everywhere else

**closed · both faces run · found 2026-09-04 against master `0a1f144f` · closes [D1301](D1301.md)**

Repro:

    const xs: i32[] = []
    function f() { xs.push(1) }
    const v = f()
    print(xs.length)

#### Mechanism

**The CHECKER's own typing selected the branch.** `typecheck.vl`'s array-method arm returns
`TY_I32` for `push`, and three witnesses agree: `const w: i32 = xs.push(1)` is `vl check` rc 0
with `@hint redundant type annotation: 'w' is inferred as i32`, `const w: string = xs.push(1)`
is `cannot assign i32 to 'w' of type string`, and `const v: i32 = f()` over the repro's own
un-annotated `f` hints redundant too — the inferred return of a function whose tail is a push
IS `i32`. So the value is owed, and the fix is the emitter delivering it, not the checker
being narrowed.

`emitPush` wrote the append and left an EMPTY stack, and `emitCallNode`'s member ladder had no
`push` rung, so the value could be delivered nowhere. That splits into two outcomes by
position. **Bound / argument / returned** (`const w = xs.push(1)`) fell out of the ladder onto
`emitCall`'s Ident-only floor: `emitProgram: callee is not a function name`, a loud emit
reject at `vl check` rc 0. **As a function's inferred TAIL** it was worse: `.push` was the ONE
name `memberCallYieldsValue` excluded, so `computeVoidFns` classified `f` void and emitted it
`(func)`, while the caller — reading the checker's `i32` — emitted `local.set` after the
`call`. The functype and the call site disagreed and the module was **check-clean invalid
wasm**: `type mismatch: expected i32 but nothing on stack`.

`emitPush` now takes a `wantValue` flag and reads the new length back from the `len` field the
same sequence just wrote, `emitCallNode` routes `.push` through it on `popRecvIsList` (the
receiver test `.pop` already uses, so a function-valued struct field named `push` still falls
through per D1087), and the `memberCallYieldsValue` exclusion is deleted. The scratch-frame
walks had to follow: `callPushBits` (was `stmtPushBits`) is now asked by `exprPopBits` at every
VALUE position, and `collectMemberPopRefSlotsExpr` records a ref-list push's slot there too —
without those a bound push staged into a frame `fbBeginFunc` never reserved.

**AND THE VALUE POSITION REACHED A SECOND MECHANISM, which predates this row and was already
filed as [D1280](D1280.md).** A list op whose receiver is not a bare local parks the wrapper
ref in the frame's ONE `recvRef` slot, so a NESTED op inside the pushed value overwrites it and
the append lands on the INNER list. Giving `.push` a value made `n1.push(n2.push(7))` a second
spelling of it — over two globals `n1` stayed empty and `n2` took both pushes — where D1280's
own witness reaches it with a `.pop`, no value lowering involved. `emitPush` now stages its
receiver AFTER the value when `exprStagesListRecv` says the value stages one; source order is
unchanged for every program that was already right, so only the programs D1280 filed as wrong
evaluate the receiver late. Both of D1280's faces run.
