### D2980 — `==` refuses an `f32` against an integer literal that `<` accepts

**loud check reject · open, possibly a clause-2 refusal; the literal rule for `==` may need a ruling · found by the #3249 review grid · filed 2026-09-28 against master `264fd86f1`**

Repro:

    const B: f32 = 3
    print(B == 3)
    // vl check: cannot compare f32 with i32   (while `print(B < 2)` checks and runs)

#### Mechanism

An ordering operator adapts a bare numeric literal to the other operand's type; `==`/`!=` take
the literal at its default type and then require a lossless widening one way, which `i32` and
`f32` do not have. So `f32 == 3` and `f32 != 3` are refused, while `f64 == 3` (`i32` widens to
`f64`), `f32 == 3.0` and `f32 < 2` all check. Whether equality should adapt the literal as
ordering does is the question; the same program with `3.0` runs.

#### Ablation

| ingredient removed | outcome | needed? |
| --- | --- | --- |
| `==` for `<` | checks | **yes** |
| the integer literal (`B == 3.0`) | checks | **yes** |
| `f32` for `f64` (`const B: f64 = 3`) | checks | **yes** |
