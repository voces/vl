### D16072 — a hole lambda returned by a call through a binding is never pinned at the binding's later calls; only a call naming its function directly pins it

**closed — runs, prints `42` · `calleeCloSigKeyOfRead`'s rung for a binding initialized by a call falls back to the binding's own elaboration slot fact when the call's recorded type is open · was a loud emit reject (`a function-value call has no interned signature`), clause 2 · lambda twin 33 → 45 of 48, named twin 39 → 46 of 48 · found by lane I grading D16070 · filed 2026-11-13 against master `38c310cd`, closed 2026-11-14**

Repro:

    const outer = () => {
      const l = (x) => x
      return l
    }
    const v = outer()
    print(v(41) + 1)

Want:

    42

#### Mechanism

The named spelling, `function outer()`, runs and prints `42`. The checker types `v` as `(_) => _`
in both spellings. This is not a gap in resolving the callee: the same refusal follows a NAMED
function called through a `const` alias (`const o2 = outer; const v = o2()`). Routing the
emit-side callee resolvers through the lambda-aware `calleeFnOfDecl` moves none of the six cells
either, and it stops two programs from running (`refactor-notes/2026-11-14-one-callee-rule.md`).
The gap was in the signature key. The elaboration closes `v`'s slot to `(i32) => i32` in
every spelling: a trap probe on `elabSlotFacts` fired with the fact closed for the named
direct call, the named alias and the lambda. But `calleeCloSigKeyOfRead`'s rung for a binding
initialized by a call read only the call's recorded type. Only a call naming its function
directly has that type closed (`monoCloseRetFnTy`); through a binding it stays open, so the key
was `""`. The rung now falls back to the binding's own slot fact.

#### Ablation

| ingredient removed | outcome | needed? |
| --- | --- | --- |
| the lambda deliverer (`function outer()` instead) | runs, prints `42` | **yes** |
| the inner `const l` (`return (x) => x`) | check reject, `cannot infer a type for parameter `x`` | no |
| an annotation on `v` (`(x: i32) => i32`) | runs, prints `42` | **yes** |
| the lambda deliverer, kept as a named `function outer()` called through `const o2 = outer` | same refusal | no: a named function through a binding refuses too |
