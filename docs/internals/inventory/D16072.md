### D16072 — a hole lambda returned by a call through a binding is never pinned at the binding's later calls; only a call naming its function directly pins it

**loud emit reject · `vl check` rc 0 · `emitProgram: a function-value call has no interned signature — parameter 1 of type `_` has no representation in the function-value ABI` · clause 2 · six un-annotated cells of `hole-lambda-returned-by-lambda-at-two-types.matrix.vl` (`binding`, `block_if`, `block_while`, `block_bare`, `fn_body`, `two_instances`), each of which runs in the named twin · found by lane I grading D16070 · filed 2026-11-13 against master `38c310cd`**

Repro:

    const outer = () => {
      const l = (x) => x
      return l
    }
    const v = outer()
    print(v(41) + 1)
    // vl check: rc 0.  vl build: emitProgram: a function-value call has no interned signature …

#### Mechanism

The named spelling, `function outer()`, runs and prints `42`. The checker types `v` as `(_) => _`
in both spellings. This is not a gap in resolving the callee: the same refusal follows a NAMED
function called through a `const` alias (`const o2 = outer; const v = o2()`). Routing the
emit-side callee resolvers through the lambda-aware `calleeFnOfDecl` moves none of the six cells
either, and it stops two programs from running (`refactor-notes/2026-11-14-one-callee-rule.md`).
The gap is in the pin path. A call naming
`outer` directly gives its result the returned lambda's pin at `v`'s calls; a call through a
binding gives it none, so the call through `v` has no signature. Where the direct call's pin
comes from (the result's function-tag set, or the elaboration's key for the call) is not yet
located.

#### Ablation

| ingredient removed | outcome | needed? |
| --- | --- | --- |
| the lambda deliverer (`function outer()` instead) | runs, prints `42` | **yes** |
| the inner `const l` (`return (x) => x`) | check reject, `cannot infer a type for parameter `x`` | no |
| an annotation on `v` (`(x: i32) => i32`) | runs, prints `42` | **yes** |
| the lambda deliverer, kept as a named `function outer()` called through `const o2 = outer` | same refusal | no: a named function through a binding refuses too |
