### D3844 — a hole lambda called through a chain of aliases with a `let` in it (`const c2 = c; let d = c2`, `let d = c; let d2 = d`) keeps its `i32` parameter default

**closed 2026-10-08 by lane SC · was check-clean invalid wasm · found in review of #3441 (`l6`, `l7`) · filed 2026-10-08 against master `52c8e492d` · pins: `tests/cases/closures/hole-lambda-alias-chain-and-cell.vl`**

Repro:

    function f(x: string) {
      const c = (y) => y + "C"
      const c2 = c
      let d = c2
      d(x)
    }
    print(f("a"))
    // vl check: rc 0.  vl run: invalid module inside `f`, `expected i32, found (ref $type)`

Want:

    aC

#### Mechanism

D3833's close resolved a call through an un-annotated `let` to the lambda its initializer
names, one link only. A `const` alias before the `let`, or a `let` of a `let`, ended the walk,
so the lambda was never instantiated at the call. `monoAliasChainLamFe` now follows the chain
link by link (up to eight), through un-annotated `const` and `let` bindings, each possibly read
as a capture, and answers once it has crossed a `let`. A chain of `const`s alone stays
`monoRespellLamAlias`'s.
