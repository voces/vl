### D5062 — a written `let` of a generic returned from an un-annotated function reaches its caller's call as an open type

**closed 2026-10-17 — the witness prints `1` · was loud emit reject, `vl check` rc 0, clause 2 · the pin's call is recorded in the flow table and the open callee is typed at that call's arguments and result · 22 cells of the `written-fn-binding-inferred-return` matrix (36 → 58 of 64 runs) · found grading D4891's return position · filed 2026-10-16 against master `c604c1179` · pins: `tests/cases/closures/written-let-of-generic-returned-to-an-inferred-caller.vl`, `scripts/capability-probes/matrix/written-fn-binding-inferred-return.matrix.vl`**

Repro:

    function k<T>(x: T): T { return x }
    function mk() {
      let g = k
      g = k
      return g
    }
    function main() {
      const h = mk()
      print(h(1))
    }
    main()
    // vl check: rc 0.  vl run: emit error, a function-value call has no interned signature

Want:

    1

#### Mechanism

`mk`'s inferred return is `g`'s open `(T) => T`, and nothing in `mk` pins `g`: the call
`h(1)` that fixes the type is in `main`, through a call result. The emitter reaches `h(1)` with
a hole parameter and refuses there, naming the call rather than the return. The never-written
spelling (`const g = k`) refuses earlier and names the position (`a generic function taken as a
value reaches no call that fixes its type`), which is the refusal the design's (c) literal
asks for at every such fall-through.

#### Ablation

| ingredient changed | outcome | needed? |
| --- | --- | --- |
| `mk` annotated `(): (x: i32) => i32` | runs, `1` | **yes** |
| `g` a `const` alias, or a `let` never written | refuses at `mk`'s binding, naming the position | **yes** |
| another binding calls `k` at `string` first, in `mk` | still refuses the same way | no |

#### Grading list

- a call result delivered into a record field or a list before the call
- the same return through a written `let` holding a lambda instead of a generic

#### Left open by L1 (2026-10-16)

Still the same emit reject on master `502f8daa8`. The call that fixes `g`'s type is in the
CALLER, through `mk()`'s result, so pinning it means carrying a pin back across an inferred
return. D5061's close pins a read within the frame that declares the binding. The cheaper half
is the (c) literal: the written spelling should refuse at `mk`'s binding, naming the position,
as the `const` spelling already does.

Rechecked after D5079's close, on master `4af9eb956`: the same emit reject. The written spelling
gets to the caller because the stub-value check (`monoStubValueOk`) is skipped for a written
`let`'s initializer and for a write's right-hand side (`stubWriteRhs`, `wasmEmit.vl`). A real
lowering still has to carry the caller's pin back across `mk`'s inferred return. D5079's table
is keyed within one frame, so it does not cover that.

Rechecked closing D5111/D5112, on master `40ea46748`: the same emit reject, and every delivery
of `mk()`'s result to a fixing call refuses the same way — `return g` instead of the binding,
`const h: (x: i32) => i32 = mk()` at the caller, and `mk()` passed to a parameter annotated
`(x: i32) => i32`. Dropping the stub exemption for the write's right-hand side moves none of
them, so the exemption is not the cause. The explicit generic spelling (`function mk<T>():
(x: T) => T`) is the checker's by-design refusal of a return-only type parameter. A refusal at
`mk` would be a capability refusal (fn-value-flow-design §(c)), so the open part is the lowering:
a pin carried from the caller's destination back onto the inferred return, which the
fn-value flow table, keyed within one frame, does not reach.

Rechecked closing D4892/D4893 (L1), on master `83752e744`: the same emit reject. Neither
mechanism of that close reaches it. The write adapter needs a call through the binding in the
binding's own frame, and here `g` has none. The per-instance atom texts need an instance, and
`k` has none until a pin arrives from `main`. The open part is the same: a pin carried across
`mk`'s inferred return from the caller's destination. The literal-union L1 matrix's
`return_inferred` cells still refuse at emit (`a generic function taken as a value reaches no
call that fixes its type`), the same on master and after the close.

#### Closed by L1 (2026-10-17)

`ffSlotCall` records, with each pin it adds to a `ret(fn)` slot, the call that made it, so the
pin carried back across `mk`'s inferred return names `h(1)`. `monoBindingAtPin` then types the
open callee at that call's arguments and result (`monoRetypePinCalls`), and `k` gets an
instance. The retype is skipped when a write of the binding was already given a closed function
type at other parameters (`monoWritesTypedAt`). That case is D5290, a type variable bound by
name across two returns of one generic, and its written face keeps the emit reject.

| `monoWritesTypedAt` | runs, and D5290's written face loads then traps |
