### D10360 — a generic's bound map read at a `boolean` pin takes a miss as `false`

**closed · runs, prints `null` · was check-clean silently wrong, clause 1 · found closing [D10292](D10292.md) · present on master `a72f9a7fe` · filed 2026-10-22 against master `a72f9a7fe` · closed by reading the miss's sentinel from the instance's binding of the map's value type (`emitMapGetTail`, wasmEmit.vl) · fixture `maps/generic-map-read-bound-scalar-pin.vl`**

Repro:

    function g<V>(m: Map<string, V>, k: string): V | null {
      const x: V | null = m.get(k)
      x
    }
    const mb: Map<string, boolean> = Map()
    mb.set("k", true)
    print(g(mb, "z"))
    // PRINTED false on master `a72f9a7fe`

Want:

    null

#### Mechanism

A `boolean` map value takes its miss as the sentinel `2`. In a generic body, `emitMapGetTail`
read the receiver's map type as `Map<string, V>` and did not resolve `V` at the instance.
So it emitted the sentinel for an unknown value type, `0`, and a miss read back as `false`.
The direct `print(m.get(k))` goes through another arm and prints `null`.

#### Ablation

| ingredient changed | outcome | needed? |
| --- | --- | --- |
| `Map<string, boolean>` with no type parameter, bound | prints `null` | **yes** |
| `print(m.get(k))` in the generic, no binding | prints `null` | **yes** |
| `V = i32` for `V = boolean` | prints `null` | **yes** (the niche-bearing pin) |
| `const x = m.get(k)`, un-annotated | printed `false` on master | no |
