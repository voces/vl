### D17833 — a hole parameter reading a map whose storage holds a tagged set's ids is instanced as if the map held closures

**loud emit reject · `internal compiler error: the IR built for this function breaks verifier rule 3 (v8's rep is not its type's)` · clause 1 (`vl check` rc 0) · open · owner I8-PREP, after 3b (coordinator ruling 2026-11-28: the extension of #10765, a hole parameter keyed by its argument's storage rep, the set plus its signature) · filed 2026-11-28 against branch `cov-clos-d17820` (568a1ca71) by COV-CLOS-3, moved out of [D17820](D17820.md)'s grading list (COV-IS's spelling (c))**

Repro:

    function dbl(a: f64): f64 { return a * 2.0 }
    const g = (a) => a + 1
    const m = Map()
    m["a"] = g
    m["b"] = dbl

    if t != null { print(t(3)) }
    function walk(mm) { const v = mm["a"]; if v != null { print(v(3)) } }
    walk(m)
    // vl check: rc 0.  vl run: emit error at walk's read, verifier rule 3

    4

#### Mechanism

The module-level call `t(3)` beside `walk(m)` splits the calls of the map's values, so the
values are a tagged set and `m`'s storage holds the set's ids. `walk`'s one instance types its
read `v` as a closure, at the map's checker type, and the IR's rep for `v` is not its type's.
D17820's close builds a hole lambda at each LIST's element type and does not touch this: the
storage here is one map written by assignment, not one lambda in two storages of two widths.
The close keys the hole parameter's instance by its argument's storage rep (the set and its
closed signature), as #10765 keys a storage.
