### D3160 — a closure returning a generic call on a literal union narrowed out of a box is invalid wasm

**check-clean invalid wasm · open · clause 1 · found by the #3281 round-2 review (`rv3281r2-5785/a/p01.vl`) · the same on master `b1794003a` · filed 2026-09-29 against master `b1794003a`**

Repro:

    type K = "a" | "b"
    function id<X>(a: X): X { return a }
    function t(e: K | i32) {
      if !(e is i32) {
        const f = () => id(e)
        print(f())
      }
    }
    t("a")
    // vl check: rc 0.  vl run: invalid module inside `f`: type mismatch: expected i32, found
    // (ref $type)

Want:

    a

#### Mechanism

Not localised past the ablation. The narrowed read of `e` delivers the member's string out of
the box, and the lambda's result is the `K` atom. #3281 converts a bare `() => e` at that
return ([D3120](D3120.md)). A generic call in the same position still hands back the string
the instance was pinned at, and nothing converts it.

#### Ablation

| ingredient changed | outcome | needed? |
| --- | --- | --- |
| `print(id(e))`, no closure | runs | **yes** (the closure) |
| `(): K => id(e)` | runs | **yes** (the inferred result) |
| `() => e`, no generic call | runs on #3281 (invalid on master) | **yes** (the generic call) |
| `e: K`, no box | runs | **yes** (the narrowing out of a box) |
| `string` in place of `K` | runs | **yes** (the literal union) |

#### Grading list

The witness and the `() => e` twin.
