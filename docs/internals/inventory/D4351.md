### D4351 — a function value whose result is a string literal union is refused at a function type returning `string`

**loud check reject · clause 2 · pre-existing, the same on master `d92163e47` · found probing the `one-literal-union-rep` ruling · filed 2026-10-13 against master `d92163e47`**

Repro:

    type K = "x" | "y"
    function t(k: K): K { k }
    const h: (k: K) => string = t
    print(h("x"))
    // vl check: cannot assign (K) => K to 'h' of type (k: K) => string
    // want: x

#### Mechanism

The checker's function-type assignability does not take a literal-union result as a subtype of
`string`, though a value of that union is assignable to `string` everywhere else. The reps
differ (the atom against a string ref), so admitting it needs the adapter D3073 builds for a
function value delivered at a function type of another rep, which already exists for record
results.

#### Ablation

| ingredient removed | outcome | needed? |
| --- | --- | --- |
| the alias (inline `"x" \| "y"` result) | still refuses | no |
| the named callee (a lambda `(k: K) => k`) | still refuses | no |
| the literal-union result (`t` returns `string`) | runs | **yes** |

#### Grading list

The lambda spelling `const h: (k: K) => string = (k: K) => k`, the same value stored into a
`(K => string)[]` list and a `Map<string, (K) => string>`, and the nullable result
`(k: K) => string | null`.
