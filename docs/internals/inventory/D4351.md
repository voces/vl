### D4351 — a function value whose result is a string literal union is refused at a function type returning `string`

**closed 2026-10-13 — the witness prints `x` · a function slot takes an atom result at `string` and the delivery is wrapped in the D3073 adapter, at a union's function arm too · fixture `tests/cases/closures/litunion-result-as-string-fn.vl`, matrices `fn-value-litunion-result-as-string{,-generic}.matrix.vl` · was loud check reject · clause 2 · filed 2026-10-13 against master `d92163e47`**

Repro:

    type K = "x" | "y"
    function t(k: K): K { k }
    const h: (k: K) => string = t
    print(h("x"))
    // was: vl check: cannot assign (K) => K to 'h' of type (k: K) => string

#### Mechanism

`fnSlotAssignable` (`compiler/typecheck.vl`) held every function slot invariant in its store
class (#1921, before D3073's adapter existed), so an atom result never met `string`. It now
admits an atom at `string` or `string | null` (`fnSlotAtomToString`) and an atom at its own
nullable (`fnSlotNulDiffers`: the null niche is the same i32), and `fvaAdapt` converts at the
call. Two gaps the admission exposed are closed with it: `fvaAdapt` now recurses into the
one function arm of a union destination that the value converts into (without it,
`((k: K) => string) | i32 = t` was check-clean and printed nothing), and refuses a value that
converts into two arms, and `luSpell` tries the display name with its arrow tightened, since
`(K) => K` round-trips through no other spelling and a lambda or a `let` was refused for want
of one. A function held inside a container converted to another (`((K) => K)[]` at
`((K) => string)[]`) is refused loudly by `fvaRefuseNested`, as its record twin is.

#### Grading list

The lambda spelling `const h: (k: K) => string = (k: K) => k`, the same value stored into a
`(K => string)[]` list and a `Map<string, (K) => string>`, and the nullable result
`(k: K) => string | null`.
