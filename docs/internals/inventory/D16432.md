### D16432 — a hole lambda bound to a `const` and returned from a function whose inferred result closes is built with no instance, so a call through the result traps

**closed 2026-11-15 by lane J · runs, prints `6` · was trap after load, clause 1 · `tests/cases/closures/maker-returns-bound-lambda-pinned-by-captured-call.vl` · found re-running [D16295](D16295.md)'s ablation, whose annotated-parameter face it is · filed 2026-11-15 against master `c607b893c`**

Repro:

    function wrap(f: (n: i32) => i32) {
      const l = (x) => f(x)
      return l
    }
    const inc = (n: i32): i32 => n + 1
    const c = wrap(inc)
    print(c(5))
    // vl check: rc 0.  vl run: wasm trap, indirect call type mismatch (before the close).

Want:

    6

#### Mechanism

The body's call `f(x)` pins `x` to `i32`, so the checker types `wrap`'s result as the
closed `(i32) => i32`, and no maker row is banked (the result is not open). The only use of
the `const`-bound hole lambda `l` is `return l`, a value read, so mono gave it no instance. The
closure was built from the parameterless template (`$l@7`, no parameter and no result) and
called through the `(i32) => i32` table type. A returned literal (`return (x) => f(x)`) was
built at the result. An annotated result delivers the returned value there (`monoNoteRetDeliveries`,
D3862), and an inferred result that is closed now does the same.
