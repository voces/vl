### D2339 — a closure captured a local by value unless some closure also wrote it, so a later write by the maker was invisible to it

**closed 2026-09-24 — the witness prints `5`. Was check-clean silently wrong (it printed `1`),
filed against master `90c3ba566`. Closed under the owner's ruling (a), closures capture by
reference everywhere (DECISIONS.md, "Closures capture variables by reference"). Fixture
`tests/cases/closures/capture-by-reference.vl`**

Repro:

    function main() {
      let k = 1
      const g = () => k
      k = 5
      print(g())
    }
    main()
    // prints 5

#### Mechanism

A closure copies each captured local into its environment when it is created. D2285's
`captureBoxRewrite` (`compiler/emit_rewrite.vl`) moved a local into a shared length-1 cell only
when a nested function ASSIGNED it, so the behaviour depended on an unrelated write: adding a
never-called `const w = (v: i32) => { k = v }` made the witness print 5, and a module-scope
`let` (a global) always printed 5. The rewrite now boxes a binding when a closure captures it
and it can be assigned after the capture — later in the frame, by any closure, or in a loop that
re-runs the capture — and covers parameters and loop variables as well as `let`s.

#### Ablation

| ingredient removed | outcome | needed? |
| --- | --- | --- |
| the write `k = 5` after the capture | prints 1, correctly | **yes** |
| the function frame (the same four lines at module scope) | printed 5 on master | **yes** |
| a second closure that writes `k` | printed 5 on master | the defect needs its ABSENCE |

#### Grading list

Every case of the semantics table in DECISIONS.md, all in the fixture: a `let` inside and
outside a loop, for-in and range variables (with a write, a closure write, and `continue`),
parameters (plain, optional, lambda), compound assignment and `++`, nested closures, a
closure's own local, a returned closure, a `let` with no initializer, and a narrowed read.
