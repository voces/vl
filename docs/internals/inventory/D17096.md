### D17096 — a map of two-signature bundles handed whole to a function is declared at the closure struct its values are not

**check-clean invalid wasm · `vl check` rc 0, `vl run` invalid module · clause 1 · filed 2026-11-24 against master `84170c683` (a sibling of [D17094](D17094.md), found by its reach sweep)**

Repro:

    function lap(f) {
      const _a = f(2.5)
      const _b = f(3)
      return f
    }
    function h(x) { return x.has("a") }
    const m = Map()
    m["a"] = lap((a) => a + 1)
    print(h(m))
    // vl check: rc 0.  vl run: invalid module, type mismatch: expected (ref null $7) (the closure
    // struct), found the bundle record `{c0:(f64)=>f64,c1:(i32)=>i32}`, in top-level code

Want:

    true

#### Mechanism

A fresh `Map()` is typed at the bundle record its values hold only when the elaboration notes the
map as holding the record whole (`elabSlotRecordNote`). Its walk refuses a use of the map that is
not a slot read, and an argument is one, so handing the map whole declines the note. The map is
then declared at the single closure, while the store still writes the bundle record. It holds at
module scope and inside a function alike, so it is not D17094's cross-frame decline.
