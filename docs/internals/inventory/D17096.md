#### Mechanism

A fresh `Map()` is typed at the bundle record its values hold only when the elaboration notes the
map as holding the record whole (`elabSlotRecordNote`). Its walk refuses a use of the map that is
not a slot read, and an argument is one, so handing the map whole declines the note. The map is
then declared at the single closure while `lap(...)` returns the bundle record. Legacy alone
refuses at the store ("a function returning a parameter called at two signatures is called where
its result is not used at one of them"); the invalid module is the claimed start, which skips that
refusal (IR-P1's, as in [D17094](D17094.md)). It holds at
module scope and inside a function alike, so it is not D17094's cross-frame decline.

#### Grading list

- The callee reading the value and calling it (`const v = x["a"]; if v != null { print(v(4)) }`),
  and the map local to the caller.
- Design follow-up (queue ruling 2026-11-24: FREE as "D17096 map-of-record argument hand (design)",
  not an express). The walk declines at the use's up-kind (`CW_UP_ARG`, not `CW_UP_OBJ`). The hand
  path (`elabHandCanTakeRecord`, `elabBundleSigs` per callee instance and parameter) types only a
  parameter called at the record's signatures. A lift needs three pieces: an elaboration note that
  callee instance k's parameter i receives a map of record R; mono pinning that parameter at
  `Map<K, R>` per instance; and the callee frame's slot reads retyped per instance (a generic's
  read nodes are shared). At risk: the hand rows [D15903](D15903.md) and [D15907](D15907.md).
