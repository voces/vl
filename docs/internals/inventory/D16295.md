### D16295 — a maker that captures a hole function parameter and returns a lambda calling it has no interned signature when its result is bound and called

**loud emit reject · clause 2 · `vl check` rc 0 · pre-existing: the bound-in-body spelling refuses the same on master `51f894bf3` · found ablating [D16291](D16291.md) · filed 2026-11-14 against master `51f894bf3`**

Repro:

    function wrap(f) {
      const l = (x) => f(x)
      return l
    }
    const inc = (n: i32): i32 => n + 1
    const c = wrap(inc)
    print(c(5))
    // vl run: emit error 7:7: emitProgram: a function-value call has no interned signature —
    // parameter 1 of type `_` has no representation in the function-value ABI

Want:

    6

#### Mechanism

The maker instance that types a returned hole lambda by its result's calls
([D14881](D14881.md)) is built only for a maker whose parameters are all annotated (`fvaIsMaker`,
check_assignable.vl). Here `f` is a hole bound by the call `wrap(inc)`, so no maker instance is
banked, and the call through `c` reaches emit with the lambda's open parameter.

#### Ablation

| spelling | outcome | needed? |
| --- | --- | --- |
| the witness | emit reject | — |
| `return (x) => f(x)` (the literal, after D16291) | emit reject | the binding: no |
| `compose(f, g)` returning `(x) => f(g(x))` | emit reject | no |
| `const c: (x: i32) => i32 = wrap(inc)` | runs, prints `6` | the un-annotated result: **yes** |
| `function wrap(f: (n: i32) => i32)` | trapped (it was not a run: [D16434](D16434.md)); runs, prints `6`, since D16434 | the hole parameter: **yes** |
| `(x: i32) => f(x)` | runs, prints `6` | the open lambda parameter: **yes** |
| `adder(n)` returning `(x) => x + n` (a value hole, called at `adder(2)`) | runs, prints `7` | a FUNCTION hole: **yes** |

The annotated-parameter line was first filed as "runs, prints `6`". It trapped, then and at the
filing commit, with `indirect call type mismatch`: the defect is [D16434](D16434.md), closed with
its own fix, after which that spelling runs.
