### D16423 — a body's `[]` pushed onto a hole parameter takes one element type for every call, so a second call at another element type is refused

**loud check reject · clause 2 · found grading D16421's close · filed 2026-11-15 against master `d568db1d` · open**

Repro:

    function f(a, x) { a.push([]); a[0].push(x); return a[0][0] }
    print(f([], 0.5))
    print(f([], "s"))
    // vl check: push: cannot add string to f64[] (the body of `f` at the call's argument types)

Want:

    0.5
    s

#### Mechanism

Not yet located. Each call hands `f` its own `[]`, but the inner `[]` the body pushes is one
literal checked once, and the first call's pin of its element stands for the second call.
Before D16421's close the same program was refused with "the callee's body writes string into
the list passed here, whose element is f64".

#### Ablation

| ingredient changed | outcome | needed? |
| --- | --- | --- |
| `a.push(x); return a[0]`, a flat list | prints `0.5`, `s` | **yes** (the nested list) |
| both calls at `f64` | runs | **yes** (two element types) |
| the calls swapped | `push: cannot add f64 to string[]` | no (the order) |
