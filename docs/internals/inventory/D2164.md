### D2164 — a spread of a narrower-element list into a wider-element list literal is check-clean invalid wasm, though it is the explicit copy the ruling asks for

**check-clean invalid wasm · clause 1 · every element pair tried · filed 2026-09-23 against master `b52b14e83`**

Repro:

    const a: i32[] = [1, 2]
    const b: f64[] = [...a]
    print(b[0])
    // vl check: rc 0.  vl run: invalid module — type mismatch: expected (ref null $type), found (ref $type)

#### Mechanism

Not yet ablated past the rows below. A list literal is built at the type it flows into, and a
spread element copies its source's elements one by one into the new list; the checker accepts
each spread element against the destination's element type, and the emitted copy appends the
source's elements without converting them. This matters more after the 2026-09-23 ruling (no
implicit container widening): the refusal tells the user to build the list at the wide type or
copy it, and `[...a]` is the first copy most users will write.

#### Ablation

| spelling | outcome |
| --- | --- |
| the witness (`i32[]` spread into `f64[]`) | invalid module |
| spread into `(i32 \| null)[]`, then `b[0] = null` | invalid module |
| `K[]` spread into `string[]` | invalid module |
| `f([...a])` with `f(xs: f64[])` | invalid module |
| `a.map((x) => x as f64)` into the same `f64[]` | runs |
| `[...a]` into `i32[]`, the same element type | runs |

#### Grading list

Every ablation row, at a binding, an argument and a return. The nested copy the refusal's
`.map` hint implies for a list of lists (`a.map((r): f64[] => r.map((x) => x as f64))`) is a
loud emit reject, `unsupported .map/.filter element type`, the literal D1482 files for a closure
result; re-grade it with whichever row closes first.
