### D16615 — a spread alone of a maker's fresh record list into an annotated wider list is refused, though a delivery of the call itself copies

**loud check reject · clause 2 · `{x: i32} is not {x: f64} (reached through {x: i32}[] into {x: f64}[]): they store field x differently ... a record is shared, not copied` · a call's result is fresh, so nothing is shared · found by lane J closing D16613 · filed 2026-11-15 against master `9a7f37ef3` · open**

Repro:

    function mk() { return [{ x: 1 }] }
    const v: { x: f64 }[] = [...mk()]
    print(v[0].x + 0.25)
    // vl check: {x: i32} is not {x: f64} (reached through {x: i32}[] into {x: f64}[]) ...

Want:

    1.25

#### Mechanism

The spread argument is judged as a list delivered into the annotated destination's list type,
and a call's list there is refused by the shared-record rule. Nothing is shared: the call's
result is fresh, and `const v: { x: f64 }[] = mk()` (the call delivered whole) copies it and
runs. The spread position has no copy arm.

#### Ablation

| ingredient changed | outcome | needed? |
| --- | --- | --- |
| `= mk()`, the call without the spread | prints `1.25` | **yes** (a spread) |
| `= [{ x: 2.5 }, ...mk()]`, a wider part beside it | prints `1` since D16444 | **yes** (the spread alone) |
| `mk` returning `[{ x: 1 }, null]` into `({ x: f64 } \| null)[]` | the same refusal | no |
