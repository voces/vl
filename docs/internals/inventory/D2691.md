### D2691 — a direct delivery of `{[string]: Circle}` into `{[string]: Circle | Sq}` builds invalid wasm

**closed 2026-09-26 by the NR lane — the repro is now a loud check reject, the design's
no-implicit-container-widening rule · was check-clean invalid wasm, clause 1 · found in the
#3194 review · identical on master `1be1363d9` · filed 2026-09-26 by the W2 lane**

Repro:

    type Circle = { r: i32 }
    type Sq = { s: i32 }
    const m: {[string]: Circle} = Map()
    m["a"] = { r: 3 }
    const w: {[string]: Circle | Sq} = m
    print(w.length)
    // vl check: rc 1 — {[string]: Circle} is not {[string]: Circle | Sq}: a container never widens implicitly

#### Mechanism

The checker lets the delivery through because both values classify as a ref
(`containerElemClassDiffers` is false for `Circle` against `Circle | Sq`), but the `Circle | Sq`
map stores each value as the union box while the source map stores the bare `Circle` struct, so
the two maps are different structs. The close makes the map arm of the delivery check see
the box (`mapValBoxDiffers`: a value with one non-null member against a union of two or more),
so the pair is refused as `{[string]: i32}` into `{[string]: i32 | string}` already is
(DECISIONS.md §"No implicit container widening"): a map is shared, and no converting map copy
exists for any value pair. The same test makes a join of the two maps their union rather than
the wider map (`joinWidensMap`), which ran on the NR lane's probe where master built invalid wasm.
