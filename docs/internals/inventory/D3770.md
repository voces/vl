### D3770 — a re-check after canon reads every rewritten annotation with its spelling tree dropped, so a `readonly T[]` parameter names no `T`

**closed · loud check reject on a valid program, and the cross-module cascade in sunpa's missing-import report (lane DX) · filed 2026-10-06 against master `e2443d6b2`**

Repro:

    import { concat } from "std:array"
    type Ob = { x: f64, n: i64 }
    const placed: Ob[] = []
    function place(x: f64) {
      const o = { x, n: 1 }
      placed.push(o)
    }
    place(2.5)
    const A: f64[] = [1.0, 2.0]
    const B: f64[] = A.concat(A)
    print(B.length)
    print(placed[0].n + 40)
    // master: cannot infer type parameter `T`: `concat`'s return type names it and no
    // parameter does

Want:

    4
    41

#### Mechanism

`canonEmitTypeNames` rewrites a `TypeRef`'s name in place and drops its parser spelling tree
(`clearAnnTs`, and `clearUdTs` for union members). Three paths then re-check the program:
`checkProgramAgain` (record adoption and literal-binding pins), the deep-`is` second pass, and
the lint replay. Each calls `canonRestoreSpellings`, which put the names back but not the trees,
so the re-check read `annTsOf == -1` for every rewritten annotation. `readonly T[]` is one that
canon rewrites, so `anyParamMentionsTyParam` found no `T` in `concat`'s parameters and
`checkRetTyParamBound` refused every call. In sunpa the adoption was set off by a record literal
whose field held the unresolved `groundHeight(x, y)`, and every `concat` in every module was
refused beside the one real error. The fix is `restoreAnnTsAll` (ast.vl), which
`canonRestoreSpellings` now calls so each root reads what the parser banked again.
