### D15822 — a call's record result written into a field built wider is refused when its function has another call

**loud check reject · clause 2 · filed 2026-11-11 with D15821's close**

Repro:

    type J = { f: i32 | null }
    type K = { j: J | null }
    function mk() { { j: { f: 4 } } }
    const _k: K = mk()
    print(_k.j?.f ?? 0)
    const y = mk()
    function mj() { { f: 6 } }
    y.j = mj()
    const z = mj()
    print(y.j.f)
    print(z.f)
    // vl check: rc 1 — this call's result is stored as J by the field it is written into, whose
    //   record is built wider than its own type, and its function also builds it as {f: i32}

Want:

    4
    6
    6

#### Mechanism

D15821 builds a written call's result at the field's stored record by keeping its function at that
record, which is sound only when the call is the function's one call. With a second call, the
function's result is also delivered at its own type, here bound to `z`. Building every result at
`J` runs this witness, since `z`'s reads go through `J`'s storage. It is not sound in general,
though: `z` handed to a parameter of its own type receives a `J` (measured: invalid wasm). Closing
it needs the write to enter the record solve as a delivery, so the solve's conflict check
(`recKeptConflicts`) judges it beside the function's other deliveries. Was check-clean invalid
wasm before D15821.
