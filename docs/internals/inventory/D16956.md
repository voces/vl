### D16956 — [CLOSED 2026-11-18] a shared field read boxes a nested boolean-list arm under a tag its `is` test does not read

**closed 2026-11-18 · was check-clean silently wrong · found measuring the shared-field-read tag rule · filed 2026-11-18 against master `944a8d60f` · fixed by boxing every ref arm under the tag its `is` test reads (`sharedFieldArmTag`) · fixture `tests/cases/records/shared-field-read-nested-bool-list-arm.vl` · matrix `shared-field-read-list-arm`**

Repro:

    function q(b: boolean): {f: i32} | {f: boolean[][]} {
      if b { return { f: 5 } }
      return { f: [[true]] }
    }
    const v = q(false).f
    if v is boolean[][] { print(1) } else { print(0) }
    // PRINTS 0

Want:

    1

#### Mechanism

A boxing shared read tags a non-null list arm `scalarTagOfKind(boxTagOfTy(..))`
(`sharedFieldArmListKind`, D16951). The `is` test reads `isArmTagOfTy`, which gives a nested
boolean-leaf list its own `boolListArmTag(depth)`. The two tags differ, so the boxed list answers
no `is` against its own type. The nullable arm (`boolean[][] | null`) took the same kind through
`sharedFieldArmNulListTag` and answered the same way. Every ref arm now asks one function,
`sharedFieldArmTag`, for the tag the read's union assigns its type, which is `isArmTagOfTy`'s.

#### Ablation

| ingredient removed | outcome | needed? |
| --- | --- | --- |
| the nesting (`boolean[]`) | prints `1` | **yes** |
| the boolean leaf (`i32[][]`) | prints `1` | **yes** |
| the `i32` arm (a `string` or a record arm instead) | prints `0` | no |
| one more level (`boolean[][][]`) | prints `0` | no |
| `null` added to the list arm | the same wrong answer | no |
