### D4981 — a bare type parameter narrowed by `is K[]` is delivered as `K[]` at an instance whose list cannot be one

**check-clean silently wrong · the bare-`V` and un-annotated face of the `V[]` receiver delivery, which the checker now refuses as D4928 refuses a concrete one · filed 2026-10-15 against master `d826b6339`**

Repro:

    function pushOne(xs: f64[]) { xs.push(1.5) }
    function g<V>(v: V) {
      if v is f64[] { pushOne(v) }
      print(v.length)
    }
    const e: i32[] = []
    g(e)
    // PRINTS 0

#### Mechanism

`v is f64[]` over a bare `V` narrows the whole value, since `V` may be `f64[]` or a union
holding one, and the delivery is right at those instances. At `V = i32[]` the test is true
for an empty list (D4771), and the arm hands `pushOne` a list the caller does not hold, so
the push is lost. A `V[]` receiver is refused by the checker (D4928), but that refusal would
cost a bare `V` every instance where the delivery is sound, such as `V = f64[] | string`,
so the answer has to come from the instance. Which answer (an instance refusal, or a design
ruling) is open, so this row has no `Want:` block.

#### Ablation

| change | outcome | needed? |
| --- | --- | --- |
| `function g(v)` (un-annotated) for `g<V>(v: V)` | prints `0` | no, same defect |

| the concrete `i32[] \| string` receiver | check refuses (D4928) | **yes** |
