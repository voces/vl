### D1690 — an inline-shape row nothing constructs takes an anonymous union-box literal, and the literal's payload is then read against that row's box tags

**closed 2026-09-06 — an anonymous literal PREFERS the row its own destination names, so a
declared box row nothing constructs cannot capture it · filed against master `ddc4b852a` ·
D1675's residue at the third reader, D1674's family one companion column over · 0 corpus
cells**

Repro:

    type U1 = i32 | boolean
    type U2 = string | boolean
    type H = { xs: U2 }
    function u1(): U1 { return 7 }
    const b = { xs: u1() }
    print(b.xs)
    // vl check: rc 0.  vl run: rc 0, prints 7

Was: `PRINTS true`. `b.xs` holds the i32 `7` and printed `true` because the box the literal
was built into was `U2`'s, whose tag 1 is `boolean` — `U1`'s tag 1 is `i32`.

#### Mechanism

`type H` is never named by a value here; DECLARING it is the whole ingredient.
`internInlineShape` mints its row with the field key `shapeFieldElemName("U2", 16)`, the
spelling as written, and the anonymous literal then field-set and code matches it — code 16
against code 16, with nothing comparing the two member sets. The box arm that would separate
them is `anonValueFitsField`'s, gated on `sIsAnonRow`, and `H` is not an anon row. The probe,
on the two-holder spelling of this witness:

    ROW 0 H [xs:16:<U2> ] render={xs:string|boolean} -> nameRow0
    LIT node18 -> row0 lit-fields[xs:16:<string|boolean> ]
    LIT node27 -> row0 lit-fields[xs:16:<i32|boolean> ]

Delete `type H` and the literals mint `#anon` rows of their own and print correctly, so this
is neither D1689 (the anonymous-row reader) nor D1675 (the rendered-name reader) — both of
those are closed and both readers answer correctly here. This is the THIRD reader in D1675's
own table: the arena/field-set scan `structRowOfObjFieldSetK`, where a code-16 field is
matched on its code alone and `rowElemDeclConflicts` covers only the named-heap codes 15, 5
and 28.

**The fix is a PREFERENCE, not a refutation**, for the reason D1674's row already measured on
the ref-list arm: a declared box field may legitimately be WIDER than the value's own union,
and that widening runs — 

    type U1 = i32 | boolean
    type W = { xs: string | boolean | i32 }
    function u1(): U1 { return 7 }
    const w: W = { xs: u1() }
    print(w.xs)          // prints 7 at this seed

A comparator refuting `i32|boolean` against `string|boolean|i32` leaves that literal no row
at all. So the close conditions the refutation on the literal's OWN destination:
`structIndexOfObjCtxGo` computes `repRowOfTyStruct(nodeRepTyIxOf(objIx))` — the row the
checker's adopted destination names, asked once per literal and only when a union-box field
on a declared row is actually reached — and refuses the capture only where that row is not
this one. `unionMemberSetsCompat` (D1675) is the comparator, alias resolve and all, so `U2`
and `string|boolean` stay one key.

The two outcomes are the same ingredient and had to be graded together: a two-member mismatch
mis-reads a scalar tag and prints the WRONG VALUE, while a three-member one differing in a ref
member is a run-time cast trap. Two position matrices, both graded by PRINTED value, go
**27 of 46 to 46 of 46** — nineteen wrong-value cells and nineteen compiler-trap cells, every
one the un-annotated face, with `runs -> not-runs` 0 and `-> silent` 0 on both.

Two neighbouring spellings were measured NOT to be defects, which is why neither is a
template: the same three members in a different ORDER (the two unions coincide) and a
two-member value against a three-member row that contains it (the tags align).

#### Ablation

| ingredient removed | outcome | needed? |
| --- | --- | --- |
| the declared `type H` | runs, prints `7` | **yes** — an unused declaration is the ingredient |
| the differing member set (`type H = { xs: U1 }`) | runs, prints `7` | **yes** |
| the `type` alias (an uncalled `function takeIt(h: { xs: U2 })` instead) | prints `true`, unchanged | no — any inline-shape row will do |
| the annotation on the literal (`const b: { xs: U1 } = …`) | runs, prints `7` | no — the rescue |
| a second holder constructing `H` | prints `hi` then `true` | no — the same defect, one line longer |

Both faces are the same outcome, which is what separates this from D1674, where the annotated
face was the loud one: annotating the literal with the OTHER shape is the rescue, and leaving
it inferred is the defect, at module scope and inside a function alike.
