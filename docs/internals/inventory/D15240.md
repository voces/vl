### D15240 — a read of a container built wider, defaulted with `??` to a binding of a function's fresh record result, is not built at the container's record

**closed 2026-11-04 by lane destringify, runs, prints `4` · was check-clean invalid wasm, clause 1 · D15217's held-default rule took only a `const` of a record literal; `recCoalesceHeldInit` also takes a `const` of an inferred function's call, whose function `recAdoptNote` builds at the read's record, and a call written as the default is built the same way (since D15248 by `recCoalesceDefaultDeliver`) · fixture `soundness/built-map-read-held-call-default-runs.vl` · matrix `coalesce-built-read-held-call-default` · named set `d15240-held-call-default` · a `let` default is D15248, a number stored wider D15249, a nested record D15310, a held two-level maker D15311, a join inside a literal D15312 · filed 2026-11-04 against master `2b449f004`**

Repro:

    type J = { f: i32 | null }
    function mk() { { f: 4 } }
    const m = Map()
    m.set("a", mk())
    const wm: {[string]: J} = Map()
    wm.set("a", mk())
    function mk2() { { f: 1 } }
    const d = mk2()
    const b = m.get("a") ?? d
    print(b.f)

Want:

    4

#### Mechanism

`m.get("a")` reads a record of `J`'s storage, and `d` holds `mk2()`'s result, built at `mk2`'s own
`{f: i32}`. D15217's rule builds the default binding at the read's record only where it is a
`const` of a record literal (`recCoalesceHeldOf`, check_fit_rules.vl); a binding of a call needs
the call's function built there instead, as `recFnBuiltAtDst` builds one for a wider delivery.
