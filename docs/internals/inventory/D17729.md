### D17729 — an un-annotated list a generic body pushes a generic function onto is refused when the body has two instances

**loud emit reject · `ref valtype with no interned shape` · clause 2 · open · `vl check` rc 0 · one instance runs · found grading [D16699](D16699.md)'s close · filed 2026-11-27 against master `b71fd7b8f` by I8-PREP**

Repro:

    function id<T>(x: T): T { return x }
    function run<T>(_x: T) {
      const rs = []
      rs.push(id)
      return rs
    }
    print(run(3)[0](3))
    print(run("ab")[0]("ab"))
    // vl check: rc 0.  vl run: emitProgram: ref valtype with no interned shape

Want:

    3
    ab

#### Mechanism

Mono splits `run` into `run` and `run$1` (a closed `sq` pushed instead runs at both), but in each
instance the elaboration's type for `rs` (`nodeTyAt(rs, instance)`) stays the open
`((T) => T)[]`: the element's type is `id`'s own `T`, which only a caller's use of the result
closes, `run(3)[0](3)` at `(i32)`. With one instance the template itself is closed there and
D16699's close builds it; with two, no delivery carries each caller's call through the
returned list's element back to its own instance's `rs`, so neither closes and the instance's
result has no ref-list row.

#### Ablation

| ingredient removed | outcome | needed? |
| --- | --- | --- |
| the second instance (`run("ab")` alone) | runs, `ab` | **yes** |
| the list annotated `((x: T) => T)[]` | runs | **yes** (the un-annotated list) |
| a closed `sq` pushed in place of `id` | runs | **yes** (the generic function) |
| `const rs = [id]`, the literal initialiser | runs | **yes** (the push) |
