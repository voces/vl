### D9590 — an un-annotated map a function stores a generic into, read only by `.length`, reaches no call that fixes the generic's type

**loud emit reject · `vl check` rc 0 · `a generic function taken as a value reaches no call that fixes its type` · clause 2 · found closing [D9480](D9480.md) · present on master `49a7d0b10` · filed 2026-10-22 against master `49a7d0b10`**

Repro:

    function id<T>(x: T): T { x }
    function fill(mm) { mm["k"] = id }
    const m = Map()
    fill(m)
    print(m.length)
    // vl check rc 0.  vl run: emit error: emitProgram: a generic function taken as a value reaches no call that fixes its type

Want:

    1

#### Mechanism

Not traced. From the ablation only: a stored generic that nothing calls is typed at the
uncalled slot type only when it is noted inert, and the store through `fill`'s parameter is
noted only by a read plan, which needs a read of the entry. With no read of `m["k"]` there is
no plan, and `id` reaches the emitter open.

#### Ablation

| ingredient removed | outcome | needed? |
| --- | --- | --- |
| `fill` (`m["k"] = id` at module level) | runs, `1` | **yes** |
| no read of the entry (add `const r = m["k"]` and `r(2)`) | runs, `1` and `2` | **yes** |

#### Grading list

The two-map spelling (`fill(m)` and `fill(m2)`, both read only by `.length`), which refuses the
same way.
