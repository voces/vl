#### Mechanism

A map nothing but reads ever uses took the unbound default for its value at its declaration
(`defaultReadOnlyContainer`), and its key at the first key read or iteration (`pinIterKey`,
`pinReadKey`, `check_narrow_flow.vl`). A key or value read into a `string` was then refused.
D16993's list path does not cover a map: the key iterates through `keys()` or `for k, v in`, and
a value read goes through `?? d`, neither of them an element read delivered whole.

The close reads the uses before the default: a loop over the map (its first variable a key, its
second a value), a loop over `keys()` or `values()`, and a `m[k] ?? d` or `m.get(k) ?? d`
initializer of an annotated `let`. The earliest such `let`'s type pins the key or value; a later
read of another type is refused there. A set is a map with no value and takes the key half.
