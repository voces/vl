### D3967 — an argument typed by a generic's parameter, calling a module binding above its declaration, was not re-asked per instance

**closed 2026-10-10 by lane CK · now a loud check reject · was check-clean silently wrong · clause 1 · found in review of #3500 (`rv3500/r4/genT_bad__above`; `genT_bad__after` and `genT_ok__above` are the controls) · filed 2026-10-10 against master `56f77d80f` · pins: `tests/cases/functions/error-let-of-generic-called-at-tparam-above-declaration.vl`**

Repro:

    function inner<U>(u: U) { print("I"); print(u) }
    function cI32(n: i32) { print("C"); print(n) }
    function useK<T>(x: T) { k(x) }
    let k = inner
    k = cI32
    useK(true)
    // vl check: rc 0 before the fix.  vl run: prints `C` then `1`

#### Mechanism

D3960 grades a call through a `let` seeded with a generic against the concrete function written
to it, and an argument typed by the enclosing generic's parameter is left for each instance to
re-ask (`noteLetCstr`). Above the module binding's declaration the call has no type for `x`, so
the early read typed only names with no type variable and dropped `x`; and the pair, graded later
when the write is seen, was recorded outside `useK`, where no instance re-asks it. The early read
now keeps a name typed by the enclosing generic's own parameters (`fsbNameTy`), and each use keeps
the generic body it stands in, which owns its pair (`fsbNoteCstr`).
