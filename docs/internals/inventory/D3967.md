### D3967 — an argument typed by a generic's parameter, calling a module binding above its declaration, was not re-asked per instance

**closed 2026-10-10 by lane CK · now a loud check reject, by the owner's ruling C (D3960: the concrete write is refused, whatever calls through the binding) · was check-clean silently wrong · clause 1 · found in review of #3500 (`rv3500/r4/genT_bad__above`; `genT_bad__after` is the control) · filed 2026-10-10 against master `56f77d80f`**

Repro:

    function inner<U>(u: U) { print("I"); print(u) }
    function cI32(n: i32) { print("C"); print(n) }
    function useK<T>(x: T) { k(x) }
    let k = inner
    k = cI32
    useK(true)
    // vl check: rc 0 under #3500's first rule.  vl run: prints `C` then `1`

#### Mechanism

Under #3500's first rule (the first concrete write fixes the binding's type) the call `k(x)`
above the module binding's declaration had no type for `x`, and its pair was recorded outside
`useK`, so no instance of `useK` re-asked it. Ruling C refuses the write `k = cI32` itself, so
the call is never graded against a written function; #3502, which fixed the old rule, was closed.
