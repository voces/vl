### D17163 — the IR misses a hole function's record field called inline off a maker call's result

**runs today and must keep running · an IR coverage defect · filed 2026-11-24 against master `aef0be317` by lane IR-N2 (census class `start: field read coercion`, family H, 6 cells)**

Repro:

    function inc0(a) { return a + 1 }
    function mk(f) { return { f: f } }
    print(mk(inc0).f(3))
    // VL_IR_SHADOW=1 vl build: `start uncovered field read coercion` (kid rep closure → closure)

Want:

    4

#### Mechanism

`buildMember` (`ir_build_ref.vl`) declines a plain struct field read when the field's kid rep is
not the read's rep: here two different closure reps (measured with a probe build naming both). Legacy
builds the read; which decision gives the read its rep is the fix's to establish.

#### Ablation

| ingredient changed | outcome | needed? |
| --- | --- | --- |
| the call result bound first (`const r = mk(inc0)`, then `r.f(3)`) | covered | **yes**, read off the call |
| `inc0`'s parameter annotated `a: i32` | covered | **yes**, a hole function |
| the field read but not called (`const _x = mk(inc0).f`) | covered | **yes**, the call |
| a local record `{ f: inc0 }` in place of the maker | covered | **yes**, the maker |
| the read inside a function body | still `field read coercion` | no |
