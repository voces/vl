### D17163 — the IR misses a hole function's record field called inline off a maker call's result

**closed 2026-11-24 by lane IR-N2 · runs, `4`, matched in mode 6 · `buildMember` takes its receiver at the type `irBExpr` builds it at (`builtRecvTy` → `exprTyOf`), and `exprTyOf` types an open field of a call-built receiver at its kid type there (`builtFieldTy`) · fixture `tests/cases/closures/hole-fn-field-called-off-a-maker-call.vl`, shadow rows `tests/ir-shadow-rows/hole-fn-field-called-off-a-maker-call.vl` and `hole-fn-field-called-off-nested-maker-fields.vl` · was an IR coverage defect (runs under legacy) · filed 2026-11-24 against master `aef0be317` by lane IR-N2 (census class `start: field read coercion`, family H, 6 cells) · still `field read coercion`, unchanged from base, cause not established: a module binding of the field (`const r = mk2(inc0).r; r.f(5)`)**

Repro:

    function inc0(a) { return a + 1 }
    function mk(f) { return { f: f } }
    print(mk(inc0).f(3))
    // VL_IR_SHADOW=1 vl build: `start uncovered field read coercion` (kid rep closure → closure)

Want:

    4

#### Mechanism

`buildMember` (`ir_build_ref.vl`) declines a plain struct field read when the field's kid rep is
not the read's rep: here two different closure reps (measured with a probe build naming both). Legacy
builds the read; which decision gives the read its rep is the fix's to establish.
