#### Mechanism

A `let` a closure writes after capturing it is rewritten into a capture cell: `let k = [inner]`,
each read `k[0]`, each write `k[0] = v`. D3930's written-let rung reads a delivered `Ident`, so a
delivered cell read reached no rung, the seed `inner` was never instanced, and the cell kept the
generic's un-pinned element type (an `i32` array holding a closure). A call `k[0](x)` through the
cell had only the hole-lambda rung (D3845), so the seed was instanced at a default signature and
the call trapped. `monoCoerceWrittenCell` now reads a delivered cell read as its `let`: the seed and
every `k[0] = g` naming a declared generic are instanced at the delivered type, and the cell and
its reads are retyped to the instance (`monoRetypeCell`). A call through the cell takes the
signature the call's arguments instance the seed at (`monoCellSeedGenFe`), and records it on the
binding, so a cell called at two signatures is the binding conflict and refused. A call through
a cell inside a generic body gets its own nodes per instance (`monoCopyCellRead`). A value node
asked for two function types — a write in a closure the instances of the enclosing generic share,
or one instance's cell called at two types — is refused (D3953). A value written into
a cell, or seeding one, must be a generic or instance by name, an alias or another cell resolving
to one, a hole lambda, a parameter, or a value of a settled type; anything else is refused rather
than stored at an unknown type (`monoCellValueTake`).
