### D3939 — a let holding a generic function, written inside a closure and delivered as a value, builds invalid wasm

**check-clean invalid wasm · clause 1 · found in review of #3493 (`rv3493/e4`; also l1, l2, d03, d03c, e5, b6; m1, m2, e1, e2 are controls) · filed 2026-10-10 against master `00bf1871f`**

Repro:

    function ci(f: (n: i32) => void, n: i32) { f(n) }
    function inner<U>(u: U) { print("I"); print(u) }
    function q(n: i32) { print("Q"); print(n) }
    function main() {
      let k = inner
      const flip = () => { k = q }
      ci(k, 1)
    }
    main()
    // vl check: rc 0.  vl run: the emitted module failed to validate inside `main`

Want:

    I
    1

#### Mechanism

Not located. A `let` a closure writes becomes a capture cell, and the read `k` delivered to
`ci` is the cell read, which D3930's written-let rung does not recognise as the binding: the
generic `inner` is not instanced at `(n: i32) => void`, and the cell element is read at the
wrong type. Captured and only read (m1), it runs.
