### D17085 — legacy boxes a generic instance's re-associated `??` link under one member's tag

**closed · `emitUnionIfArm` joins a hole's map read `??` with no type of its own into the same box as its null-test `if` (`untypedHoleMapCoalIf`) · fixture `tests/cases/generics/coalesce-chain-of-hole-map-reads-of-mixed-kinds.vl` · was check-clean silently wrong, a `string` face whose module failed to validate · clause 1 · the same on master `cc27c3ea8` · filed 2026-11-23 against master `09efa76d9`, closed 2026-11-23**

Repro:

    function use(a, b) { print(a[9] ?? a[8] ?? b[3]) }
    const a: {[i32]: boolean} = Map()
    a[8] = true
    const b: {[i32]: i32} = Map()
    use(a, b)
    // vl check: rc 0.  vl run: PRINTS 1

Want:

    true

#### Mechanism

Legacy re-associates `a ?? b ?? d` to `a ?? (b ?? d)` (`coalChainMint`). In a hole instance the
minted inner link `b ?? d` has no type of its own (D17077). The outer link is a union join at the
`boolean | i32` box, and `emitUnionIfArm` boxes the link whole through `emitUnionBoxOwed`. That writes
one `if (result i32)` over both operands and boxes it under the `i32` member's tag, so a `boolean`
payload is read back as an integer. With a `string` operand the `if` holds a reference at `i32`, and
the module fails to validate. The IR's builder misses the arm (`union if arm coalesce chain`). Lifted,
it builds the link as a join into the same box and tags each arm at its own member, which prints `true`
and `s`.
