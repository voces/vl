### D2772 — a value of two list types handed to a generic `T[]` parameter

**loud emit reject (`monomorphize: expected an array argument for 'xs'`) · the #3207 round-2 review · filed 2026-09-27 against master `f6db92e0d`**

Repro:

    function h(c: boolean, t: string) {
      if c { return [t] }
      [1]
    }
    function glen<T>(xs: T[]): i32 { xs.length }
    const q = h(true, "s")
    print(glen(q))

#### Mechanism

`q` is `string[] | i32[]`, which binds no one `T` in `T[]`; the checker admits the call and the
monomorphizer refuses it with a sentence naming its own mechanism. The design owes either a
checker refusal at the argument (as `.length` on `q` has) or a meaning for binding `T` over a
union of lists. The generic spelling (`h<T>`) is refused at the argument since #3207
(`argument 1: … is two list types, not one list`).

| --- | --- | --- |
