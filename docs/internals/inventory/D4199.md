### D4199 — an element of a list of a mixed number/string literal union is claimed as an atom, so its binding gets an `i32` slot holding a box

**closed 2026-10-12 by lane CK · runs · was check-clean invalid wasm · found reviewing #3577 (12 cells of the reviewer's grid went runs → invalid wasm once `==` narrowed) · filed 2026-10-12 against master `0bf4c3bb6` · pins: `tests/cases/literal-unions/mixed-literal-element-is-the-box.vl`**

Repro:

    type M = 1 | "a" | "b"
    type K = "x" | "y"
    function g(k: K) { print(k) }
    function f(xs: M[]) {
      const v = xs[0]
      if v is 1 { print("one") } else { print(v) }
    }
    f([1])
    f(["a"])
    g("x")

Want:

    one
    a
    x

#### Mechanism

`nodeTyIsPureLitUnion` (`compiler/typecheck.vl`) answered true for `1 | "a" | "b"` once any
literal union in the program registered its atoms (`gLitUnionUsed`). `exprIsLitAtom`'s Index rung
then claimed `xs[0]` as an atom, `collectLocals` gave `v` an `i32` slot, and the stored value is the
union's box. A union whose members need a box is never a pure literal union now. The `K` alias and
`g("x")` are only there to register atoms. `==` narrowing in #3577 registered them in many more programs.
