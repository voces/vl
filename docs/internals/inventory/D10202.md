### D10202 — a `let` list of a generic pushed a fixed-type function, delivered at another element type and assigned only after the delivery, passes check and traps

**trap after load · `vl check` rc 0 · `wasm trap: indirect call type mismatch` · clause 1 · DESIGN: the same program without the trailing assignment refuses, `push: cannot add (i32) => i32 to ((string) => string)[] (written into `zs`, delivered at ((string) => string)[])` · found closing [D10150](D10150.md) · present on master `7f3985aad` · filed 2026-10-22 against master `7f3985aad`**

Repro:

    function id<T>(x: T): T { x }
    function inc(x: i32) { x + 1 }
    let zs = [id]
    zs.push(inc)
    function runS(a: ((x: string) => string)[]) { print(a[1]("s")) }
    runS(zs)
    zs = [id, id]
    // vl check rc 0.  vl run: wasm trap: indirect call type mismatch, in `runS`

The owed outcome is a check refusal, as without the last line.

#### Mechanism

[D10080](D10080.md)'s delivery judge declines a `let` assigned anywhere after its declaration
(`ctnRebound`, check_decl_scan.vl), not only one assigned between the write and the
delivery, so an assignment after the delivery switches the judge off. The place judge of
[D10201](D10201.md) declines a `let` assigned anything but another binding's name the same
way (`ctnReboundFresh`), so the alias spelling, `const ws = zs` delivered instead, traps too.

#### Ablation

| ingredient removed | outcome | needed? |
| --- | --- | --- |
| the trailing `zs = [id, id]` | check refuses ([D10080](D10080.md)) | **yes** |
| the assignment moved before `runS(zs)` | runs, `s` | **yes** |
| `zs.push(id)` instead of `zs.push(inc)` | runs, `s` | **yes** |
