### D16924 — a lambda's list literal at a generic's `() => (T | null)[]` is refused at check

**closed 2026-11-17 — the witness runs and prints `1` · was: loud check reject · clause 2 · `a function of type () => i32[] cannot be used as () => (i32 | null)[] here` · pre-existing on master `3f567259f` · found grading [D16918](D16918.md) · filed 2026-11-17 by lane AE4**

Repro:

    function gen<T>(f: () => (T | null)[]) { return f().length }
    print(gen(() => [1]))

Want:

    1

#### Mechanism

A bare `T` inside the nullable binds through the ordinary walk at the argument's check, not through
a union arm, so [D16918](D16918.md)'s re-type inside D10133's bound-type delivery was never reached;
the argument went to `fvaAdapt`, whose adapter a list result cannot take (a list never widens).

#### Fix

The re-type moves into `fvaAdapt` (`compiler/check_assignable.vl`), the one delivery adapter both
paths reach: a lambda whose every return is a fresh list or record literal delivered to the
destination's result is typed at the destination (`lamRetFreshRetype`, through the
`lamRetFreshFn` hook, since `check_inferred_return.vl` imports this module), and a returned
null-only list is recorded as delivered there.

| `() => (T \| boolean)[]` | runs | **yes** (`null` in place of a value arm) |
| not generic, `f: () => (i32 \| null)[]` | runs | **yes** (generic) |
