### D9602 — a list built from an un-annotated function parameter, returned from two calls and read by `.map` at two types, has no list type

**loud emit reject · `vl check` rc 0 · `index access but list type not collected` · clause 2 · found closing [D9552](D9552.md) · present on master `8789642ad`, refusing earlier there as [D9552](D9552.md) · filed 2026-10-22 against master `8789642ad`**

Repro:

    function inc(a) { return a + 1 }
    function deliver(g) { return [g, g] }
    const v = deliver(inc)
    print(v.map((f) => f(3))[1])
    const w = deliver(inc)
    print(w.map((f) => f(1.5))[0])
    // vl check rc 0.  vl run: emit error: emitProgram: index access but list type not collected

Want:

    4
    2.5

#### Mechanism

Not traced. Both calls hand `deliver` the same un-annotated `inc`, so they take one instance of
`deliver` while its returned slot `e` is pinned at `(i32) => i32` by one read and at
`(f64) => f64` by the other. That is the shape [D9450](D9450.md)'s copy of the template per pin
serves for a returned literal of function names; whether that copy is asked for when the
literal's elements are the parameter is not probed.

#### Grading list

Two functions of different types, `deliver(inc)` read at `i32` and `deliver(half)` with
`half(a) { return a / 2.0 }` read at `f64`, refuse the same way. On master both spellings
refuse earlier, with `call to unknown function`, as [D9552](D9552.md). So does the list of a
generic `function id<T>(x: T) { x }` handed in (`sel(id)`) and read by `.map` at `i32` and at
`string`, bound or inline, now with `string index access but string list type not collected`.
