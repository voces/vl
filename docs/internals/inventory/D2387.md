### D2387 — a `for` loop variable's closure-assigned value reads back as the wrong member

**check-clean silently wrong · filed 2026-09-25 against master `d5a30be9e`**

Repro:

    function f(): string {
      let out = ""
      const ys: (boolean | string)[] = [true]
      for v in ys {
        const k = () => {
          v = false
        }
        k()
        if v is boolean { out = out + "\{v}" }
      }
      out
    }
    print(f())
    // PRINTS 0
    // vl check: rc 0.  vl run: prints "0" instead of "false"

#### Mechanism

`v` is a `for ... in` loop variable of union type `boolean | string`, captured and
reassigned by closure `k`. The `is boolean` narrowing after the call reads back a value
whose printed form (`0`) matches neither `true` nor `false`'s usual rendering, nor the
loop's own initial element — the closure's write to the captured loop variable is not
landing where the later `is`/read expects it.

#### Ablation

| ingredient removed | outcome | needed? |
| --- | --- | --- |
| the closure (`v = false` inline, no `k`) | prints `false` correctly | **yes** |
| the `for ... in` loop (a plain `let v` instead) | prints `false` correctly | **yes** |
| the union type (`ys: boolean[]`) | prints `false` correctly | **yes** |

#### Grading list

Any closure that reassigns a captured `for`/`for in` loop variable of union type, read back
through a narrowing (`is`) after the call.
