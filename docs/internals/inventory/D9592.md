### D9592 — a call returning a generic, written directly as an un-annotated list's element and called through it at two types, reaches no call that fixes its type

**loud emit reject · `vl check` rc 0 · `a generic function taken as a value reaches no call that fixes its type` · clause 2 · found closing [D9481](D9481.md) · present on master `49a7d0b10` · filed 2026-10-22 against master `49a7d0b10`**

Repro:

    function id<T>(x: T): T { x }
    function mk() {
      return id
    }
    const xs = [mk()]
    if xs[0](2) == 2 {
      print(xs[0]("abc"))
    }
    // vl check rc 0.  vl run: emit error: emitProgram: a generic function taken as a value reaches no call that fixes its type

Want:

    abc

#### Mechanism

`monoFlowLeafGen` (emit_mono.vl) resolves a list element through a `const` chain to the call
that initializes it (`monoFlowCallLeaf`, D9481), but an element that is the call itself is not
a chain, so the read plan has no generic to rewrite the element call to and `id` reaches the
emitter open.

#### Ablation

| ingredient removed | outcome | needed? |
| --- | --- | --- |
| the call as the element (`const v = mk()`, `[v]`) | runs, `abc` | **yes** |
| the second call's type | runs | **yes** |

#### Grading list

The element call inside a nested list, and a call that prints, which must still run once.
