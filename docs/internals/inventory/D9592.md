Want:

#### Mechanism

`monoFlowLeafGen` (emit_mono.vl) resolves a list element through a `const` chain to the call
that initializes it (`monoFlowCallLeaf`, D9481), but an element that is the call itself is not
a chain, so the read plan has no generic to rewrite the element call to and `id` reaches the
emitter open. The close resolves a `Call` element through `monoFlowCallLeaf` directly, and
notes inert the `return` operands of the function it calls when that function is called only
there (`monoFlowNoteCallRets`, the body `monoFlowNoteInertRets` already ran for a bound
call). The element call itself is left in place, so it runs once: a `mk` that prints prints
once.
