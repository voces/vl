### D3199 — a literal-union function held in a list, called in a hole instance, prints the member's atom

**closed · `anyLitUnionUsed` peels list elements and map values before asking whether a function type's result, or a record's field function's, is a literal union · fixture `tests/cases/generics/instance-call-of-literal-union-function-in-list.vl` · was check-clean silently wrong · clause 1 · pre-existing, the same on master `2771214c7` · a D3193 sibling found by the #3288 review · filed and closed 2026-09-29 against master `2771214c7`**

Repro:

    function F(z) { print(z[0]()) }
    const fs: (() => "a" | "b")[] = [() => "a"]
    F(fs)
    // printed 0 on master

Want:

    a

#### Mechanism

[D3193](D3193.md)'s gate, one layer down. `anyLitUnionUsed` counted a function type whose
result is a literal union only when the annotation was that function type or a record holding
one. A list of such functions, a nested list, and a list of records with such a field left the
gate off, so the instance's call printed its atom. The gate now peels up to four list-element
and map-value layers first.
