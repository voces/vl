#### Mechanism

D9331's rung answers a plain record parameter, D9420's a nullable one and D9422's a list of a
record-and-scalar union. A list of the record is none of them, so `sigParamTokOfTy` renders
the parameter with `tyToEmitName`, `7·2^depth` characters, and `annParamKindTy` classifies that
spelling. A depth-16 `--names` profile of `g([])` puts the cost under `sigKeyOfTyGo` →
`annParamKindTy`, in `scalarListRepOfName` → `arrElemIs`, `nameIsRefArray` →
`refArrShapeKind` and `refArrElemName` → `structIndexOfTypeName`, each scanning the render
with `tyTopIndexOf`. The nullable list adds `isUName` → `canonUnionKeyOfName`, and a list
literal's walk (`collectAArrayLit` → `arrLitElemKind`, `arrLitElemHintTy`,
`arrLitUnionElemName`) spells it again. Under the null collector the spelling outgrows the
64 MiB object cap at depth 22, which `tests/vl_compile_gc_test.ts` uses as its trap witness.

**After a list of a declared record reads its element's ref-list slot, 2026-10-22.**
`sigParamTokOfTy` and `sigRetTokOfTy` ask `sigDeclRecListTokOfTy` after D9420's rung: a list
whose element is a declared record owning its struct row, bare or made nullable, gets the
`reflist` token of that element's ref-list slot, and the list made nullable gets
`nulreflist`, the answers `annRefListSlot` gives its render. The render's lookup tries an
exact stored-name match before the element key, so the rung declines unless no other ref-list
row's element can be the same record with the same nullability: `rlSoleSlotOfRecTy` declines
on a row whose element is a type variable, an error type, a union with such a member, a record
of no row, or one outside the sidecar, and `sigRowHasNoTwin` on a twin struct row. Before
landing, a validating seed computed both answers wherever the rung fired and trapped on any
disagreement, with a control that trapped whenever it fired. The control fired on 62 of
16,213 files. A first guard without the ref-list check disagreed on two `tests/cases/arrays/`
files, where a `filled<T>` instance leaves a row whose element is a type variable and whose
stored name equals the record's render, which the exact-name match picks first. The validator
skips a render over 4096 characters, where the element key turns nominal and master answers
no ref-list token from depth 10; both answers build and run alike. Every file (16,213 under
`distilled/` and `tests/cases/`) builds byte-identically to master's under both the validating
and the final seed, `scripts/rep-fuzz-check.sh` is exact, and the compiler builds itself
byte-identically. The list result `A[] | null` closes with it. At depth 22 the witness builds
under `VL_COMPILE_GC=null`; the test's trap witness moved to [D9512](D9512.md). Fuel,
`VL_FUEL=1`, one build each, after:
