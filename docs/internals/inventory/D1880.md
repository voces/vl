### D1880 — a mid-file `import` is hoisted to the top by `vl fmt` and takes every comment written above it, stranding each one away from the declaration it belonged to

**closed 2026-09-07 — the witness runs and each comment stays where it was written · was a `vl
fmt` relocation on a `vl check`-clean program · fixed by giving the import hoist a lead of its
own: the contiguous own-line run directly above the `import`, and nothing earlier · filed
against master `b9df7976b`**

Repro (runs, prints `3`):

    const a = 1

    // this comment belongs to `b`
    const b = 2

    import { toString } from "std:fmt"

    print(toString(a + b))

`vl fmt` returned:

    // this comment belongs to `b`

    import { toString } from "std:fmt"

    const a = 1

    const b = 2

    print(toString(a + b))

#### Mechanism

`emitImports` runs before the statement walk and scans the whole token stream, so every
`import` is emitted at the top whatever line it was written on. For each it called
`emitLeadingComments(0, startLine)`, which flushes **every** pending comment before that line —
and for a mid-file import that is every comment in the file so far. The comments were emitted
into the import region, and the declarations they described were then printed bare.

The rule the formatter family keeps is that a comment is never relocated. A hoist necessarily
moves the `import` line; it must move only that line, plus the comment block that is the
import's OWN — the contiguous run of own-line comments ending on the line directly above it,
with no blank line inside it. Anything earlier belongs to the declaration it was written above
and stays pending for the statement walk.

Two cases are told apart by adjacency, not by position: with a blank line between them the
comment is the previous declaration's, without one it is the import's. An import in the file's
LEADING region — nothing but comments and blank lines before it — is not hoisted past anything,
so it keeps the old behaviour and a file-header comment separated by a blank line still prints
above the imports.

The comments the hoist does take are recorded as a verbatim span (`vbStart`/`vbStop`), the
mechanism the formatter already uses for text it reproduced itself, so the statement walk does
not print them a second time. The comment cursor is left where it was, which is what lets the
earlier comments stay pending.

#### Ablation

| ingredient removed | outcome | needed? |
| --- | --- | --- |
| the mid-file position — the same import at the top | formatted correctly before and after | **yes** |
| the earlier comment — an import whose own lead is its only comment | its lead moves WITH it, before and after | **yes** |
| the blank line between the comment and the import | the comment is the import's and moves with it | **yes** |
| the second declaration (`const b`) | the comment still stranded | no |

#### Grading list

* The two-line own lead: `// the string renderer` / `// on two lines` directly above a mid-file
  import moves with it, and `const b`'s comment stays — both in one file.
* A file-header comment separated from top-of-file imports by a blank line, which printed above
  them before this close and must keep doing so.
* `vl fmt` idempotence on all three, and over `compiler/`, `std/`, `scripts/`, `tests/` and
  `bench/`: the candidate's output re-formats to itself.
* Codegen byte identity — a formatter change must not move one module's bytes.
