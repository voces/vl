### D15563 — a function returning a list of records over an uncalled function set, beside a called one, takes the called set's row as its result

**closed 2026-11-08 — the filed repro prints `20` · was check-clean invalid wasm, clause 1 · the result's ref-list row was found by `rlSlotOfRowTy`'s structural scan, which matched the row of a record holding a tagged set's ids for a record whose set is untagged and stores closures; the scan now also needs the two to agree on tagging at every function position (`fnTagRepAgree`, emit_shape_rows.vl) · fixture `tests/cases/closures/list-of-untagged-records-returned-beside-a-called-set-runs.vl` · found closing D15561 · filed 2026-11-08 against master `30915154`**

Repro:

    function inc0(a) { return a + 1 }
    function dbl(a) { return a * 2 }
    function passed() {
      const c = [{ fs: [dbl] }]
      print(c[0].fs[0](10))
      return [{ fs: [inc0] }]
    }
    passed()

Want:

    20

#### Mechanism

`c`'s set `{dbl}` is called through, so it is tagged and `c` is built at row `#anon0`, a list of records whose `fs` holds the set's ids. The returned literal's set `{inc0}` is never called, so it stays untagged and the literal is built at the closure row `{fs: ((i32) => i32)[]}`. `passed`'s result row is read off its recorded type `{fs: {inc0}[]}[]`. No row is keyed like that type and no struct row twins it, so `repSlotOfKind` fell to `rlSlotOfRowTy`. That scan takes the first row whose element `tyEq`s the type, and `tyEq` does not compare function sets, so it returned `#anon0`. The function's result was then the ids row while its one return built the closure row.
