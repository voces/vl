### D3922 — a generic's returned function called for its value inside a generic caller prints a boolean as `1`

**closed 2026-10-09 by lane SC, with D3912 · runs · was check-clean silently wrong · found in review of #3487 (`rv3487/w01_bool_wrong`; w01c, w01d are the controls) · filed 2026-10-09 against master `dacc580c8` · pins: `tests/cases/generics/generic-returned-function-called-for-its-value.vl`**

Repro:

    function a<T>(x: T): (t: T) => T { (t: T) => t }
    function pr<T>(x: T) { print(a(x)(x)) }
    pr(true)
    // vl check: rc 0.  vl run: prints 1

Want:

    true

#### Mechanism

The call `a(x)(x)` kept the template's recorded type, an inference hole, in `pr`'s instance, and
the hole lowers as `i32`: a `boolean` result printed as a number. At `string`, `f64` and `i64`
the same mismatch was a loud refusal on master and invalid wasm once D3912 keyed the call.
Closed with D3912: the call chain is typed at the instance's declared return, at any depth, and
not through a parameter or local that shadows the function's name.
