### D2090 — a local name declared in many sibling blocks of one function resolves its slot by scanning every local, so the function compiles in super-linear time

**closed 2026-09-22 — the sibling-statement spelling builds in 0.07 s CPU where master ran past 300 s; plumb's `chunk_142` 1,877 s → 3.9 s, `chunk_143` 2,390 s then a 4 GiB heap trap → 2.7 s, `chunk_73` 4,993 s then the same trap → 4.1 s, each at 0.43 GB peak RSS, output byte-identical · was a compile-time cost, not a miscompile: every spelling ran · residue of D1990's close · filed 2026-09-22 against master `ad8712231` + D1990**

Repro (runs, prints `1`):

    function f(x: i32): i32 {
      if x == 0 { const t = 1; return t } @@repeat(2500, "else if x == 1 { const t = 4; return t } ")@@
      return -1
    }
    print(f(0))
    // vl build: 2.7 s CPU before the fix. The sibling-statement spelling of the same cost,
    // `if x == 1 { const t = 4; acc = acc + t }` 1,250 times, ran past 300 s; it takes 0.07 s.

#### Mechanism

Three costs, one per lookup table the emitter keeps per function, and a fourth that multiplied
them.

* `declaredSlotOf` / `declaredSlotLive` (compiler/emit_classify.vl) answered a name's slot by a
  linear scan of the frame's `localNames`, comparing strings, and `frameHasDupLocalName` was a
  pairwise scan of the same table. Each read cost O(locals).
* `capScan`'s `bound` list (compiler/emit_classify.vl, `capIsBound` in emit_base.vl) grew by one
  entry per `let` — duplicates included — and every identifier was a linear membership test.
  `cboxScan`'s `dlets` dedupe (emit_rewrite.vl) was the same shape.
* **The multiplier:** `dupScanRun` (emit_sections.vl, D1595) re-runs the whole scratch-detection
  sweep once per same-named slot position while a later slot "differs", and `localRepDiffers`
  counted the `LetDecl` itself as an axis — so two `const t = 4` in sibling blocks always
  differed, and n redeclarations meant n full sweeps of an n-statement body, each lookup O(n):
  cubic. It is also why `chunk_143` trapped: each sweep allocates, and the null collector's
  4 GiB ceiling arrived before the end.

Measured on the pre-fix seed (the `--names` guest profile of 250 sibling blocks): 90.7%
inclusive in `declaredSlotOf`, 58.5% self in `__str_eq__`, under `leqScanExpr` / `leqScanBlock`
(the detection sweep). With unique names instead, `declaredSlotOf` 65% and `capIsBound` 17%.

#### Fix

* A per-frame name index (`lixFirst` / `lixNext`): a name's slots are a chain, so a lookup costs
  its same-named slots, not the frame. It rebuilds itself whenever `localNames` has been reset
  behind it, so no reset site needs a hook.
* `capScan`'s `bound` and `cboxScan`'s `dlets` dedupe are string-keyed maps.
* `localRepKey` replaces the declaration axis with its CLASS: a `LetDecl` every declaration
  reader (`bindingDeclInScope`'s three callers, which ask only for a literal-union type or a
  string-list literal) answers nothing for is class `-2`, so those declarations are
  interchangeable. The predicate is conservative — an `Index`, a list literal, or a chain past
  depth 8 keeps the declaration its own class.
* `dupScanRun` skips a bias whose every multiply-bound name resolves to the same classes as an
  already-swept bias: flags only set and lists dedupe (the sweep's documented invariant), so the
  repeat adds nothing. Its `dupSlotMore` is answered from the names the twin sweep looked up.
  `chunk_142`'s largest function went from 398 sweeps to the handful of distinct class tuples.

Byte identity, the whole proof that this is performance only: the self-compile is a fixpoint and
equals master's output on the same source; 6,386 programs (every derived corpus cell, a quarter
of the named cells, every `.vl` under `tests/`, `std/`) build to identical bytes, return codes
and messages against master's seed; `chunk_142`, `chunk_143`, `chunk_73` and `chunk_1` hash identical to a
build with the index alone and the original per-position sweep (which is master's semantics at
master's lookup order).

#### Scaling, `vl build` user CPU (s)

A generator: one function of n sibling blocks, each `{ const m = a + g + i; const x = m * 3;
const y = x - acc; const r = y ^ m; acc = acc + r }` (`same`), the same with per-block names
(`unique`), or four function-scope `let`s assigned in each block (`hoisted`). Master rows were
measured with a 300 s timeout (`>300`).

| shape | 250 | 500 | 1,000 | 2,000 | 4,000 | 8,000 |
| --- | ---: | ---: | ---: | ---: | ---: | ---: |
| same, master | 44.2 | >300 | >300 | | | |
| unique, master | 0.26 | 1.02 | 4.60 | 20.3 | 168 | >300 |
| hoisted, master | 0.04 | 0.06 | 0.14 | 0.28 | 0.59 | 1.29 |
| same, fixed | 0.04 | 0.07 | 0.18 | 0.33 | 0.65 | 1.39 |
| unique, fixed | 0.04 | 0.09 | 0.18 | 0.31 | 0.70 | 1.30 |
| hoisted, fixed | 0.04 | 0.10 | 0.15 | 0.33 | 0.65 | 1.42 |

`tests/vl_scaling_shape_test.ts` guards both axes: `sibling blocks redeclaring locals` (same
against hoisted, with a fifth temp alternating `f64` and `i32` so the sweep dedupe is load-bearing)
and `locals per function` (unique against hoisted).
