### D16908 — a list of only `null` in a record literal annotated by a union of a record and a scalar takes no element type from the annotation

**closed 2026-11-17 — the witness runs and prints `false` · was: loud check reject · `a list of only null has no element type; annotate it` · clause 2 · found by the rep fuzzer's declared leg, seed 32817471 cases 61 and 62 · filed 2026-11-16 against master `6cd505a50`**

Repro:

    const g: {f: (i64 | null)[]} | string = { f: [null] }
    print(g is string)

Want:

    false

#### Mechanism

Not traced. A record literal bound at a union annotation does not pass the record arm's field
type down to the list literal. So `[null]` is typed on its own, and a list of only `null` has
no element. The same literal at the record annotation alone takes the field's element type.

#### Fix

`nolPushParts` (`compiler/check_bind_rows.vl`) walks a delivery's destination beside the value and
marks a null-only list taken where the destination names its element. It descended into an object
literal only at a record destination; at a union it now descends into the record arm the literal
is built at (`nolObjArmOf`): the one whose field names equal the literal's, else the one declaring
every name it has.
