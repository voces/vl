### D3253 — a spread element in a list literal is not checked against the declared element type

**check-clean silently wrong · clause 1 · open · found by the #3294 review (`rv3294-k7q2`), the same on master `d48a56b17` and after the A7 retirement · filed 2026-09-29 against master `313a071b4`**

Repro:

    const bs = [3 > 2]
    const a: f64[] = [...bs]
    print(a[0] / 4.0)
    // PRINTS 0.25

Want:

    check reject: cannot assign

#### Mechanism

A prediction. `assignableExpr`'s array-literal recursion fits each element against the
destination's element type, but a `...xs` element contributes its list's element type without
being asked, so a `boolean[]` spread into `f64[]` is accepted and its i32 `1` is read as `1.0`.
The same gap reaches a rest parameter: `function r(...xs: i64[])` called as `r(...bs)` prints
`1`. A `string[]` spread into `i32[]` is check-clean invalid wasm (`expected (ref null $type),
found (ref $type)` in the top-level code).

#### Ablation

| ingredient changed | outcome | needed? |
| --- | --- | --- |
| `const d: f64[] = c` over `const c = [...bs]` (a value, no literal at the slot) | loud check reject | **yes** (the spread at the slot) |
| `[0.5, ...bs]`, a spread beside an element | prints `0.25` the same way | no |
| `r(...bs)` into `...xs: i64[]` | prints `1` | no, the rest-parameter face |
| `const ss = ["x"]`, `const a: i32[] = [...ss]` | check-clean invalid wasm | no, a second face |

#### Grading list

The rest-parameter face (`r(...bs)`), the `string` face, and the generic twin of each (a spread
of `T[]` at a pin), per the rest-parameter matrices under `scripts/capability-probes/matrix/`.
