### D14940 — a maker nested in a function is not tagged, so its result called at two types leans on the split plan

**runs today and must keep running · runs only because the split plan copies the maker per result type (`fsPlanFn`); with the split plan and the D6210 rung off it refuses at emit (`a function-value call has no interned signature`) · closes when a nested maker's result is a tagged set as a top-level maker's is (step 4, γ) · filed 2026-11-02 against master `a7c52672`**

Repro:

    function k<T>(x: T): T { return x }
    function f() {
      function mkL() { return k }
      const a = mkL()
      print(a(1))
      print(a("s"))
    }
    f()

Want:

    1
    s

#### Mechanism

A top-level maker returning a named generic returns that generic's tagged set id (`(result i32)`),
and each call through the result dispatches through its own arms, so its results run at any number
of types with the split plan off. The same maker nested in a function returns a closure
(`(result (ref $clo))`): the tag decision does not tag it, and one closure cannot serve the two
types its results are called at. Found grading D14825's acceptance file for closure-at-delivery
step (c); this is not a result-signature instance (no use closes the result's signature).

#### Ablation

With the split plan off:

| spelling | outcome |
| --- | --- |
| the witness | refuses |
| `mkL` at module scope (`function mkL() { return k }` beside `f`) | runs, through the tag |
| results called at one type (`a(1)`, then `b(2)`) | runs |
| two bindings, one call each (`a = mkL(); b = mkL(); a(1); b("s")`) | refuses |
| the maker in a block at module scope | refuses (`a generic function taken as a value reaches no call that fixes its type`) |
