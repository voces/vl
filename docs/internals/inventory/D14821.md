### D14821 — a string assignment used as a value is invalid wasm as a `print` argument or at module scope

**closed 2026-11-01 · runs, prints `hi` · was check-clean invalid wasm · clause 1 · `exprString` (`emit_classify.vl`) answers an assignment by its target cell, as the sibling classifiers already did (D2603) · pin: `tests/cases/expressions/string-assignment-value.vl` · found writing D14820's fixture · filed 2026-11-01 against master `0a983e646`**

Repro:

    let s = ""
    const q = (s = "hi")
    print(q)
    // vl check: rc 0.  vl run: invalid module, the emitted module failed to validate inside the module's top-level code

Want:

    hi

#### Mechanism

One mechanism, not two. `exprString` had no arm for an assignment, so an un-annotated reader of
the value — a `const` binding's rep, `print`'s import — took it as `i32` while the emitter left
the re-read string cell on the stack. The sibling classifiers (`nulVariantIdxOfExpr`,
`exprUnionBin`, `mapShapeOfExpr`) already answer an assignment by its target cell (D2603). A
binding inside a function only appeared to run because its rep came from a different path.

#### Ablation

| ingredient changed | outcome on master `0a983e646` | needed? |
| --- | --- | --- |
| inside a function, bound first (`const q = (s = "hi")`) | runs, `hi` | **yes** (module scope, or…) |
| inside a function, as a `print` argument (`print(s = "hi")`) | invalid wasm, `expected i32, found (ref $string)` | no (…or a `print` argument) |
| a field target (`o.s = "hi"`) instead of a name | the same in each position | no |
| an `i32` value (`n = 7`) | runs, `7` | **yes** (the string) |
| a non-literal right side (`s = t`) | the same refusal at module scope | no |

#### Grading list

Each position (module-scope binding, module-scope `print` argument, function-scope `print`
argument) for a name target and a field target.
