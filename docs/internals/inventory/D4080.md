### D4080 — a generic function stored in a record field inside a generic body is called through the field at the wrong signature

**loud emit reject · `vl check` rc 0 · clause 2 · OPEN · `a generic function taken as a value reaches no call that fixes its type` since [D4123](D4123.md)'s refusal (#3569); was clause 1 before it**

Repro:

    function twice<T>(x: T): T { x }
    function g<T>(x: T): T {
      const ops = { run: twice }
      ops.run(x)
    }
    print(g(7))
    // vl check: rc 0.  vl run: wasm trap: indirect call type mismatch

#### Mechanism

The record literal `{ run: twice }` takes a reference to the generic `twice` with no
instantiation to point at, because nothing pins its `T` at the store. The call
`ops.run(x)` then goes through `call_indirect` at the signature `g`'s instance gives `x`,
which the stored table entry does not have. The same store at module scope, or in a
non-generic function, is refused at emit (`a function-value call has no interned
signature`). So this is the generic-body face of that refusal, and here it traps instead.
The body of `twice` plays no part.

#### Ablation

| ingredient changed | outcome | needed? |
| --- | --- | --- |
| `twice` non-generic (`x: i32`) | runs, prints `7` | **yes** |
| `g` non-generic (`x: i32`) | loud emit reject (no interned signature) | **yes** |
| the record: `const run = twice; run(x)` | runs | **yes** |
| the record field annotated `{ run: (a: T) => T }` | runs | **yes** |
| the call (`return x`, record unused) | runs | **yes** |
| body `x + x` instead of `x` | same trap | no |

#### Grading list

The module-scope and non-generic spellings in the ablation, which are loud emit rejects
today and should run once the field read instantiates the generic. Also rv3535 `e24`
(`const k: K = g(7)` into a literal union), which is a check reject on the #3535 branch
because its body is not proven closed.
