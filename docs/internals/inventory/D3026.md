### D3026 — a written or unknown-provenance list of union boxes delivered as a `readonly` list with a widened member still shares its boxes, and a read of that member traps

**closed · the list stays shared, and a box read out of a list of a union that holds a scalar member only widened is rebuilt at the read under that member (`staleBoxFrom`, `emitStaleBoxRetag`): at an index read, a `for` walk, a `.map`/`.filter` element, `.get` and `.pop` · fixture `tests/cases/unions/readonly-union-view-reads-widened.vl` · matrix `readonly-union-view-written.matrix.vl` · was loads then traps · the residue of [D2999](D2999.md)'s close · filed 2026-09-28 against master `cac5e4ad5`, closed 2026-09-28 against master `3a71bb1f9`**

Repro:

    function k(c: boolean): string | i32 {
      if c { return "s" }
      return 3
    }
    function first(xs: readonly (string | i64)[]) {
      const v = xs[0]
      if v is string { print(v) } else { print(v + 1) }
    }
    const m: (string | i32)[] = [k(false)]
    m.push(k(true))
    first(m)
    // vl check: rc 0.  vl run: wasm trap: cast failure

Want:

    4

#### Mechanism

D2999's copy is a snapshot, so it is built only for a `const` bound to a list literal that the
covariant-write analysis proves nothing writes (`covarRootFreshLocal`). Every other source keeps
sharing the list: one pushed to, as here, a call result, a parameter, a field or an index read,
whose other handles that analysis does not see. The destination then reads the `i32` box as its
`i64`. A trap there is kept on purpose, since a snapshot would print a stale value.
D965 refuses its scalar twin at both. Refusing this one would lose the programs that run today
(a reader of the length or of the `string` member), and a snapshot would miss a later write, so
the fix is on the READ side: an element read of a union list whose member set holds a widened
scalar rebuilds a box carrying the narrower member's tag, which is sound for a shared view. The
rebuild is keyed on the element's union, not on `readonly`, so a spread or slice copy of the view
(which copies the boxes as they are) reads right too; it runs only in a module with such a
delivery (`listWidenRetagAny`).
