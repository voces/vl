### D17728 — a null-field record literal stored into a map whose value has its own row was built at a union arm's variant row

**runs, prints `true` — CLOSED 2026-11-27: a record literal the map's value row holds is built at that row (`mapSetValue`), not at the variant row its adoption names; pinned by `tests/cases/maps/null-field-record-stored-at-the-map-value-row.vl`. Was: check-clean invalid wasm · filed against master `2675cec5` · owner CENSUS**

Repro:

    type Circle = { r: i32 | null }
    type Sq = { s: i32 }
    type Shape = Circle | Sq
    const m: {[string]: {r: null}} = Map()
    m["k"] = { r: null }
    const n: {r: null} | null = m["q"]
    print(n == null)
    // vl check: rc 0.  vl run: invalid module, "type mismatch: expected (ref null $type), found (ref $type)"

Want:

    true

#### Mechanism

The annotated map's value type `{r: null}` has a struct row of its own, and the map's backing
array holds that row (`array (ref null $R)`, `$R = struct{nullref}`). The literal `{ r: null }` is
adopted at the union arm `Circle` it is narrower than, so the map store's plain arm built it at
Circle's variant row (its `r: i32 | null` boxed) and stored it into that array unconverted; the
module fails validation at the store. Found from a raw dump of the module (the seed's
`compileSrc`/`rbyteAt`), which `vl build` validates before writing.
