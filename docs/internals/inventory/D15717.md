### D15717 — a maker joining a record holding a nested record with one holding `null` reads that field as no struct

**closed 2026-11-11, runs and prints `1` · was a loud emit reject, check-clean, clause 2, `emitProgram: field access receiver is not a struct`, master too · closed by a shared-field plan for a record-or-`null` field (`sharedFieldNulStructPlan`, emit_obj_lit_fits.vl): the union's members store the field as one record or as `null`, so the read dispatches on the box tag into the record's nullable ref, a `null` member reading the null ref · graded by `scripts/capability-probes/matrix/union-of-records-null-record-field.matrix.vl` and the un-annotated face of `record-literal-join-at-declared-record.matrix.vl` · found closing D15265 (its nested leg) · filed 2026-11-11 against master `161d481c` plus #7200**

Repro:

    type J = { a: i32 }
    const go = [1].length > 0
    const v = if go { { j: { a: 1 } } } else { { j: null } }
    print(v.j?.a ?? 5)

Want:

    1

#### Mechanism

Not ablated. The join of a record literal holding `{ a: 1 }` with one holding `null` is the union
`{j: {a: i32}} | {j: null}`. The read `v.j?.a` is shared over its members, and no shared-field plan
reads a field one member stores as a record and another as `null`.
