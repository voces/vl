### D15717 — a shared read of a field one union member stores as a record and another as `null` names no struct

**closed 2026-11-11, runs and prints `1` · was a loud emit reject, check-clean, clause 2, `emitProgram: field access receiver is not a struct`, master too · closed by a shared-field plan for a record-or-`null` field (`sharedFieldNulStructPlan`, emit_obj_lit_fits.vl): the union's members store the field as one record or as `null`, so the read dispatches on the box tag into the record's nullable ref, a `null` member reading the null ref · graded by `scripts/capability-probes/matrix/union-of-records-null-record-field.matrix.vl` · the repro dropped `type J`, `type K` and `const _k: K = mk(false)`, which the ablation showed unneeded; that delivery is its own defect, [D15719](D15719.md) · found closing D15265 (its nested leg) · filed 2026-11-11 against master `161d481c` plus #7200**

Repro:

    function mk(b: boolean) { if b { { j: { a: 1 } } } else { { j: null } } }
    const y = mk(true)
    print(y.j?.a ?? 0)

Want:

    1

#### Mechanism

Not ablated. `mk` joins a record literal holding `{ a: 1 }` with one holding `null`, so its result
is `{ j: { a: i32 } | null }`. The read `y.j?.a` reaches emit with a receiver no struct row
answers. The read is shared over the union `{j: {a: i32}} | {j: null}`, and no shared-field plan read a
field stored as a record in one member and `null` in the other.
