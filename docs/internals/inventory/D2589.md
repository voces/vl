#### Mechanism

`&&` checks its right operand under the left operand's facts, in a scope of their own, and a
write there retires the fact in that scope as it should. The then-arm, though, gets its facts
from `collectThenNarrows` walking the condition again afterwards, which re-derives `p.f != null`
from the syntax and never saw the retirement. The close records, at each `&&`/`||` node, the
left facts its right operand retired (`crNoteRhsRetired`: an overlay entry a write marked, or a
bare name whose scope entry no longer holds the fact), drops them from the facts that `&&`'s
left operand contributes (`crFilterRhsRetired`), and keeps the `if`'s arm join from installing
the in-condition entry type below the `if` (`crCondRetired`). The emitter retires the same
pushes at the same node (`retireRhsWritten`, over `condRhsRetiredOf`), not over the whole
condition, so a re-test after the write narrows again in both halves; and a post-guard fact is
voided only by a write in an arm, not by one in the condition, which the drop already answered.
A field's or cell's fact survives a write it admits; a bare name's does not (DECISIONS.md).
The emit refusal it hid is D2052, closed in the same change for every arm that declares no
local; the remainder is D2591.
