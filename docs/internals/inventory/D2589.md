### D2589 — a write inside an expression of a narrowing condition does not retire the narrowing, and only an emit floor stops the stale read

**loud emit reject · clause 2 (and a latent clause 1: the checker accepts a stale read) · found
by the review of #3177 · the same on master `c189dfb28` · filed 2026-09-26 against master
`c189dfb28`**

Repro:

    type A = { r: i32 }
    type R = { f: A | null }
    function mkA(n: i32): A | null {
      if n == 0 { return null }
      { r: n }
    }
    function go(n: i32) {
      const p: R = { f: mkA(7) }
      if p.f != null && (if n == 1 { p.f = null; true } else { false }) { print(p.f.r) }
    }
    go(1)
    // vl check: rc 0.  vl run: emit error, "an if-expression arm that declares a local is
    // supported only as a binding initializer inside a function" (positioned at the `function` line)

#### Mechanism

A prediction. `vl check` accepts `p.f.r` in the then-arm: the `&&` narrowing of `p.f` is formed
from the left operand and survives the write in the right operand, because a write inside an
if-expression arm (and, per the review, a `match` arm or a `while` in the condition) is not a
statement the retirement is attached to. The program would read `null` at the narrowed type; it
is stopped only because the emitter cannot lower an if-expression arm holding a statement
there, and that refusal's position is the enclosing `function` line, not the arm. Lifting that
floor without retiring the narrowing would ship a trap.

#### Ablation

| ingredient changed | outcome | needed? |
| --- | --- | --- |
| the write made a statement in the then-arm, before the read | refused at `p.f.r`, correctly | **yes** |
| the write removed from the arm (`true` alone) | runs, prints `7` | **yes** |

#### Grading list

The `match`-arm and `while`-in-condition spellings from the review; the same write in the
condition of a `while` loop's own test.
