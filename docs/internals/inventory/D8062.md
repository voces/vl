Repro:

    function add(a, b) { return a + b }
    function apply2(g) {
      print(g(1, 2))
      print(g(1, 3))
    }
    function apply3(g) { print(g(10, 20)) }
    for f in [apply2, apply3] { f(add) }

Want:

    3
    4
    30

#### Mechanism

Traced. The split plan was not the gap. The call `f(add)` is typed by `monoOpenCallAtElems`,
which reads the callee's elements through `monoCalleeElems`; its `for` arm handed the iterable
to `monoConstListElems`, which accepted only an identifier naming an un-annotated `const` list.
An inline literal returned no elements, so the call fell through to `monoGenArgOpenFail`. The
reader now takes a list literal as it stands, which the `Index` arm shares
(`[apply3, apply2][1](add)` was refused the same way and now runs).
