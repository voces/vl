### D15106 — mono specializes a generic's instance per non-capturing callback, which the elaboration key does not carry

**runs today and must keep running · structural: two mono instances record ONE elaboration key, so a reader mapping a key back to its instance is ambiguous (per-instance identity, `docs/internals/per-instance-identity-2026-11.md`) · measured by a probe in `elabSlotNote` over the 1,519 `@run` files declaring a type parameter or a nested function: 78 files note one key at two slots, 33 by this mechanism and 45 by the other row's · filed 2026-11-03 against master `de3bfa8b8`**

Repro:

    function app<T>(g: (x: T) => T, v: T): T { return g(v) }
    function inc(a: i32) { return a + 1 }
    function dbl(a: i32) { return a * 2 }
    print(app(inc, 3))
    print(app(dbl, 3))

Want:

    4
    6

#### Mechanism

Both calls elaborate `app` at one key (`T=i32`), and mono builds `app` and `app$1`: `monoMakeInstanceKey` extends the registry key with each baked non-capturing callback (`@inc`, `@dbl`). The elaboration has no such component, so `elabSlotNote` records key 0 at both slots.
