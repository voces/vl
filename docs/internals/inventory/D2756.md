### D2756 — a call at a second pin re-checks a function-typed binding of the same generic and names that binding

**loud check reject · clause 2 · found by #3202's review (`p1`) · identical on master · filed 2026-09-26 against master `876559d2f`**

Repro:

    function f<T>(u: T | string): boolean { u is string }
    const s: Set<i32> = Set()
    const m: {[i32]: boolean} = Map()
    const fs: (Set<i32> | string) => boolean = f
    print(fs(s))
    print(f<{[i32]: boolean}>(m))
    // vl check: rc 1 at 6:7: cannot assign ({[i32]: boolean} | string) => boolean to 'fs' of type (Set<i32> | string) => boolean (the body of `f` at the call's argument types)

#### Mechanism

Binding `fs` to the generic records a deferred destination constraint (the value's type against
`fs`'s annotation) that names `f`'s type parameter. A later call `f<M>(m)` re-validates every
constraint naming `f`'s holes under the call's bindings, including that one, which belongs to the
binding and was settled at `T := Set<i32>`. The diagnostic lands on the call and names `fs`, a
binding the call never touches. The program is well typed.

#### Ablation

| ingredient removed | outcome | needed? |
| --- | --- | --- |
| the call at a second pin | check passes | **yes** |
| the binding | check passes | **yes** |
| the call at the binding's own pin (`f<Set<i32>>(s)`) | check passes | **yes** |
| the `is` in `f`'s body (`u is string` for `u is Set<i32>`) | still refuses | no |
