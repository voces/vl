### D1790 — the inline-union registrar returns success having minted nothing when a member is itself a union alias, so an un-annotated list literal reps its element `i32` while the value is a box

**check-clean invalid wasm · found 2026-09-06 by D1774's position matrix, which is silent at
this cell on BOTH seeds with no `is` anywhere in the program · clause 1**

Repro:

    type U = i32 | string
    function mkU(): U | boolean { return "ab" }
    const xs = [mkU()]
    print(1)
    // vl check: rc 0.  vl run: the emitted module failed to validate inside the module's
    // top-level code: type mismatch: expected i32, found (ref $type)

#### Mechanism

Not the classifier keying by name, which is where this was first read. `arrLitIsRef`'s union
rung asks `isUNameAB(16, cen, elemTy)` and an instrumented compiler says **both legs miss** —
`cen=[U|boolean] rowOfName=-1 rowOfTyAB=-1` — so there is no row to find and this is not a
keying defect. The registrar that should mint one runs and reports success:

    witness  D1790 box=[U|boolean]          infer=[U|boolean] isRefBefore=0 hadRow=0 members=0   register=0   rowNow=-1
    control  D1790 box=[i32|string|boolean] infer=[]          isRefBefore=1 hadRow=0 members=999 register=999 rowNow=0

`registerInlineUnionAt` splits the name into atoms, and `U` is neither a struct atom nor a
value atom, so `isVariantBoxUnionAtoms` declines and the function returns `0` — the code
success takes. (`999` marks a branch that never ran: the control never asks for a mint, its
flattened spelling already has a row, which is why its `arrLitIsRef` was already 1.) The
literal then falls to the i32 list default and stores the union box into an `i32` backing.
