### D4070 — an object literal with an extra field, delivered to a record with a literal-typed field, skips the excess-field check and builds invalid wasm

**closed 2026-10-11 — now a loud check reject, with the #1460 wording (`this object literal sets `w`, which {k: "a", v: i32} does not declare`) · was check-clean invalid wasm · found by the October code-quality survey (`docs/internals/code-quality-2026-10.md` L3) · filed 2026-10-11 against the shared `~/vl` seed (compiler source hash `0027a12458222156`) · fixture `tests/cases/objects/error-excess-field-literal-typed-destination.vl`**

Repro:

    type U = { k: "a", v: i32 } | { k: "b", s: string }
    const u: U = { k: "a", v: 1, w: 2 }
    if u.k == "a" { print("a") }
    // WAS: vl check rc 0, no errors.  vl run: type mismatch: expected (ref $type), found (ref $type)
    // NOW: this object literal sets `w`, which {k: "a", v: i32} does not declare (reached through
    // {k: string, v: i32, w: i32} into U)

Want:

    a check error at the literal: it sets `w`, which the destination does not declare

#### Mechanism

The checker already owns this rule: `const u: A = { v: 1, w: 2 }` with `type A = { v: i32 }`
is refused with `this object literal sets \`w\`, which A does not declare`. The refusal is
skipped when the destination record has a literal-typed field (`k: "a"`), and the literal then
reaches the emitter carrying a field its destination has no slot for; the emitter's guard on
that delivery fails open and the module does not validate.

Located and closed: the excess-field check (`objLitUndeclaredErr`) ran only when the literal's
inferred type was assignable to the destination as a plain record. A literal infers `k: string`,
which is not assignable to `k: "a"`, so the delivery took the literal-adapting path, which built
the declared shape without the check. At a plain record inside a function the program ran, the
extra initializer evaluated; at a union or a module-scope global the module did not validate. The
check now runs on that path too. For a union it runs twice: once to pick the arm the tag selects,
then once to report against that arm.
