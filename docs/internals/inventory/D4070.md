### D4070 — an object literal with an extra field, delivered to a record with a literal-typed field, skips the excess-field check and builds invalid wasm

**check-clean invalid wasm · found by the October code-quality survey (`docs/internals/code-quality-2026-10.md` L3) · filed 2026-10-11 against the shared `~/vl` seed (compiler source hash `0027a12458222156`)**

Repro:

    type U = { k: "a", v: i32 } | { k: "b", s: string }
    const u: U = { k: "a", v: 1, w: 2 }
    if u.k == "a" { print("a") }
    // vl check: rc 0, no errors.  vl run: type mismatch: expected (ref $type), found (ref $type)

Want:

    a check error at the literal: it sets `w`, which the destination does not declare

#### Mechanism

The checker already owns this rule: `const u: A = { v: 1, w: 2 }` with `type A = { v: i32 }`
is refused with `this object literal sets \`w\`, which A does not declare`. The refusal is
skipped when the destination record has a literal-typed field (`k: "a"`), and the literal then
reaches the emitter carrying a field its destination has no slot for; the emitter's guard on
that delivery fails open and the module does not validate. Where the check is skipped is not
located.

#### Ablation

All on the same seed; `vl check` / `vl run`.

| ingredient changed | outcome | needed? |
| --- | --- | --- |
| drop the extra field `w: 2` | runs, prints `a` | **yes** |
| destination a single record `{ k: "a", v: i32 }`, no union | invalid wasm | no |
| drop the `if u.k == "a"` read (print a constant) | invalid wasm | no |
| `k: string` instead of `k: "a"` | check reject (excess field) | **yes** |
| no `k` field: `type A = { v: i32 }` | check reject (excess field) | **yes** |
| literal bound to an un-annotated `const t` first, then `const u: A = t` | runs | **yes** |

#### Grading list

Re-grade the call-argument position (`g({ k: "a", v: 1, w: 2 })` into `g(a: A)`), a return
position, and a struct-field position, each with a literal-typed field on the destination; and
the un-annotated two-step spelling above, which must keep running.
