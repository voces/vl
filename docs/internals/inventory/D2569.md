### D2569 — `[x, null][i]` inside a generic refuses at an `i32` pin, though the concrete `i32` twin runs

**loud emit reject · clause 2 · pre-existing on master `dcc88a350` (as `bare null needs a struct-typed context`) · filed 2026-09-26 while closing [D2566](D2566.md)**

Repro:

    function g<T>(x: T) { return [x, null][1] == null }
    print(g(5))
    // vl check: rc 0.  vl run: emitProgram: union atom has no value box

#### Mechanism

Not located. On master the list literal kept the template's type at the pin (D2554's
null-literal exclusion in `monoPinRecvLit`) and refused with `bare null needs a struct-typed
context`. D2566's close removes that exclusion, so the literal is re-typed `(i32 | null)[]` at
the pin, and the element read now refuses asking for a value box the pin's `i32 | null` never
minted. The concrete `function g(x: i32) { return [x, null][1] == null }` runs and prints
`true`, and so does the generic at `g("s")`.

Whether the program refuses depends on unrelated code. If an unused
`function su(n: i32): string | i32 { if n > 5 { return "s" } return n }` is declared anywhere,
the filed repro runs and prints `true`, and so does it beside an unused
`function ni(n: i32): i32 | null`. The box this pin reads appears to be minted only when some
other declaration mints it.

#### Ablation

| ingredient removed | outcome | needed? |
| --- | --- | --- |
| the generic (`x: i32`) | runs, prints `true` | **yes** |
| the `i32` pin (`g("s")`) | runs, prints `true` | **yes** |
| the direct index read (`[x, null].map((e) => e == null)[1]`) | runs, prints `true` | **yes** |

#### Grading list

* `g(5)` and `g("s")` in one program.
