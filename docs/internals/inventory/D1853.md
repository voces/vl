### D1853 — a `u8[]` map VALUE had no rep, because two classifier ladders enumerated five scalar backings and the packed one is a sixth

**closed · filed 2026-09-07 against master `a9d76dee3`, closed against `678f578e3`**

Repro:

    const src: u8[] = [4, 5, 6]
    const m: { [string]: u8[] } = Map()
    m["k"] = src
    const v = m["k"]
    if v != null { print(v[1]) } else { print(0) }
    // prints 5

#### Mechanism

`scalarListKindOfName` is "the one home of the scalar-element list classification" and names
five backings — i32, string, f64, i64, f32. The packed byte list is a sixth and is deliberately
NOT in it: `fieldCodeOfSpelling` already says why, giving `u8[]` its own field code 35 "rather
than a sixth `scalarListKindOfName` entry, which would misread silently until each of its four
readers grew a matching arm (D1008)". So each reader must name `u8[]` itself, and the map-value
readers never had.

Measured before editing rather than read off the ladder: an `emitFail` on the `-3` path prints
`mvValKindOfName received [u8[]]`, and the `i32[]` twin never reaches that path at all. Two
sites needed the arm, not one — `mvValKindOfName` for the non-null value, and
`nulRefMapValInnerOf` for the niche, whose inner-extraction returned `""` for `u8[]` and so
never reached the kind-6 rung. The niche site's own comment requires the pair to admit the same
element reps, so fixing one without the other splits an invariant the code states.

The value is the `$bl8` wrapper ref on the existing kind-6 ref-value spine — no new rep, and a
`u8[][]` binding already reps a `u8[]` element, which is what said the spine would take it.

#### Ablation

| ingredient removed | outcome | needed? |
| --- | --- | --- |
| the `u8` element (`{[string]: i32[]}`) | ran before the fix too | **yes** |
| the map (a bare `const c = src`) | ran before the fix too | **yes** |
| the write (a `.get` instead of `m[k] = v`) | refused before the fix too | no |
| the nullable niche (`u8[] \| null`) | needed its OWN arm, one function up | **yes** |
