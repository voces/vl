### D1853 — a `u8[]` map VALUE has no rep, at the fully declared spelling, for a set and for a get

**loud emit reject · filed 2026-09-07 against master `a9d76dee3`**

Repro:

    const src: u8[] = [4, 5, 6]
    const m: { [string]: u8[] } = Map()
    m["k"] = src
    print(1)
    // vl check: rc 0.  vl build: emitProgram: unsupported map value type (no rep for a union-member struct)

#### Mechanism

The packed byte list is a `(ref $bl8TypeIdx)` over `(array (mut i8))`, and the map-value rep
table has no row for it: the classifier falls through its scalar-list arms to a default that
reports a union-member struct, which is not what this value is. The map's own key half is fine
and the `i32[]` twin runs, so nothing about the map is missing — only the value type's row.

**It is not a spread defect and not an inference defect.** The witness declares every type it
uses; a `bs.slice(0)` source fails the same way, and so does a build from a commit with no
`...` token in it. `.get` refuses identically to `m[k] = v`, so it is the value type and not
the direction.

Scope, graded one spelling per row rather than taken from the position's name: a `u8[]` in a
DECLARED struct field runs at read, element write, `push`, spread initialiser and nested — so
"a struct field or a map value" was a position label, not a mechanism, and the struct half is
its own row (D1854).

#### Ablation

| ingredient removed | outcome | needed? |
| --- | --- | --- |
| the `u8` element (`{[string]: i32[]}`) | runs | **yes** |
| the map (a bare `const c = src`) | runs | **yes** |
| the write (a `.get` instead) | still refuses, same message | no |
| the spread (`src` declared, no `...` anywhere) | still refuses | no |

#### Grading list

`scripts/capability-probes/matrix/spread-u8-packed-list.matrix.vl` skips its two `map_value`
cells with this row as the reason; a close here deletes those two `@@SKIP@@` lines and the
matrix goes 42 of 42 to 44 of 44. `tests/cases/lists/spread-u8-packed-list.vl` covers the six
deliveries that run and must be unmoved — this row is a container's value type, not the packed
list's own rep, so a fix reaching into the list's backing would be the wrong shape. D1854 is
the struct half and must be graded beside it: they share a symptom and not a mechanism.
