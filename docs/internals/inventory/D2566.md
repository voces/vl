### D2566 — a function whose expression body is a `.map` with a boolean-valued callback declares an `i32` result and returns the list

**closed 2026-09-26 — the filed repro RUNS and prints `true` · was check-clean invalid wasm · clause 1 · found building #3171 (D2554's close) · filed 2026-09-26 against master `cf1c0dff3` · fixture `tests/cases/functions/expression-body-member-call-result.vl`**

Repro:

    function g(x: i32) { [x, 7].map((e) => e == 7) }
    print(g(5)[1])

#### Mechanism

`computeRetInference` classified a function's tail only when `stmtIsTailValue` claimed it, and
that predicate declines member calls on purpose (it feeds the void fixpoint). `computeVoidFns`
already kept such a function non-void through `memberCallYieldsValue` (D1240), so its result
kind came only from the checker-name cascade in `buildFnMap`, which has arms for `i32[]`,
`string[]` and the wide scalar lists but none for `boolean[]` or a literal-union list, and the
result stayed at the `i32` default. Closed by classifying a value-yielding member-call tail
exactly as `return <tail>` classifies it. The disassembly shows `g` declared with the SAME functype as its own callback,
`(structref, i32) -> i32`, while its body builds and returns the mapped list: the inferred
result of `g` is read off the callback's boolean tail rather than the `.map` call. Only the
expression-body spelling fails; `return` and a bound result run.

It is why D2554's close leaves a list literal holding `null` itself (`[x, null]`, typed
`(V | null)[]`) at the template's type: re-typed at the pin, `[x, null].map((e) => e == null)`
in an expression body reaches this row and becomes silent, where master refused it loudly.
The generic spelling without the `null` (`function g<T>(x: T) { [x, x].map((e) => e == x) }`)
reaches it on master too.

#### Ablation

| ingredient removed | outcome | needed? |
| --- | --- | --- |
| the expression body (`{ return [x, 7].map(…) }`) | runs, prints `true` | **yes** |
| the call's result bound first (`const a = …; return a`) | runs | **yes** |
| the boolean result (`(e) => 1`) | runs, prints `1` | **yes** |
| the callback's result annotated (`(e): boolean => e == 7`) | still invalid wasm | no |
| the literal (`[x == 7, true]` as the body) | runs | **yes** |

#### Grading list

* `function g<T>(x: T) { [x, null].map((e) => e == null) }` at `g(5)` and `g("s")` — then
  D2554's null-literal exclusion in `monoPinRecvLit` can come out.
* The generic spelling `function g<T>(x: T) { [x, x].map((e) => e == x) }`.

#### Close

The expression body now matches the `return` spelling at every shape tried: `boolean[]` from
`.map`, an annotated boolean callback, a `K[]` map, `!e` over a boolean list, a chained
`.filter`, and `boolean[].slice`. D2554's null-literal exclusion in `monoPinRecvLit` is removed:
`g<T>(x: T) { [x, null].map((e) => e == null) }` runs at `g(5)` and `g("s")` in both the
expression-body and `return` spellings, and `[x, x].map((e) => e == x)` runs. Two shapes stay
loud in BOTH spellings and are outside this row: a struct-element `.map` result read by field
(`field access receiver is not a struct`) and a union-element one (`ref valtype with no
interned shape`). The index read `[x, null][1]` at an `i32` pin moved between two loud
messages and is [D2569](D2569.md).

It also closes [D2543](D2543.md), the generic `T[]` spelling of the same tail.
