### D2566 — a function whose expression body is a `.map` with a boolean-valued callback declares an `i32` result and returns the list

**check-clean invalid wasm · clause 1 · found building #3171 (D2554's close) · filed 2026-09-26 against master `cf1c0dff3`**

Repro:

    function g(x: i32) { [x, 7].map((e) => e == 7) }
    print(g(5)[1])

#### Mechanism

Not yet located. The disassembly shows `g` declared with the SAME functype as its own callback,
`(structref, i32) -> i32`, while its body builds and returns the mapped list: the inferred
result of `g` is read off the callback's boolean tail rather than the `.map` call. Only the
expression-body spelling fails; `return` and a bound result run.

It is why D2554's close leaves a list literal holding `null` itself (`[x, null]`, typed
`(V | null)[]`) at the template's type: re-typed at the pin, `[x, null].map((e) => e == null)`
in an expression body reaches this row and becomes silent, where master refused it loudly.
The generic spelling without the `null` (`function g<T>(x: T) { [x, x].map((e) => e == x) }`)
reaches it on master too.

#### Ablation

| ingredient removed | outcome | needed? |
| --- | --- | --- |
| the expression body (`{ return [x, 7].map(…) }`) | runs, prints `true` | **yes** |
| the call's result bound first (`const a = …; return a`) | runs | **yes** |
| the boolean result (`(e) => 1`) | runs, prints `1` | **yes** |
| the callback's result annotated (`(e): boolean => e == 7`) | still invalid wasm | no |
| the literal (`[x == 7, true]` as the body) | runs | **yes** |
