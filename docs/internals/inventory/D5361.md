### D5361 — an alias of a generic passed to an un-annotated parameter is not instanced at the calls the body makes

**loud emit reject · `vl check` rc 0 · clause 2 · found closing [D5290](D5290.md), auditing the places a generic function value is recognised by its spelling · filed 2026-10-17 against master `15bd386db`**

Repro:

    function same<T>(x: T): T { return x }
    function take(a) { print(a("x")) }
    function main() { const h = same; take(h) }
    main()
    // vl check: rc 0.  vl run: emitProgram: monomorphize: unsupported argument type for `a` in a call to `take`

Want:

    x

#### Mechanism

From the ablation and one reading. `instGenFnHolePins` instances a generic passed to an
un-annotated parameter at the calls the body makes (D4420), but recognises the generic by its
argument's SPELLING (`argIsOwnGenericFnValue`: an `Ident` naming a generic declaration), so an
alias carries the open `(T) => T` to the parameter. Recognising it by its type instead
(`tyIsForeignGenericSig`, D5290) moves the checker but not the monomorphizer, which still
refuses the parameter: both halves are needed.
