### D16400 — a lambda's declared record parameter takes no wider row: the width rewrite respells named declarations only

**closed 2026-11-15 · runs, prints `a` · was a loud check reject, clause 2, `an object value of shape … flowing into P drops the field …` · closed by resolving a call through a once-bound lambda binding as that lambda's declaration (`wsCalleeDecl`, `check_width.vl`) · found by lane I in L3 PR A · filed 2026-11-15 against master `3d526470a`**

Repro:

    type P = { name: string }
    const show = (p: P) => print(p.name)
    const v: { age: i32, name: string } = { age: 3, name: "a" }
    show(v)
    // vl check (before the close): rc 1, the field-dropping refusal at `show(v)`

Want:

    a

#### Mechanism

The record-width rewrite notes a candidate by the callee's declaration (`wsCalleeDecl`), which
answered a top-level function's name only, so a call through `const show = (p: P) => …` noted
nothing and the field-dropping refusal stood. It now follows a binding bound once to a lambda
(`cwLambdaDeclOf`, as `callDeclFnIx` already does), and the lambda's parameter takes the same row
slot a function's does: a type parameter on the lambda bound by `P`, printed as `P`, each call
instanced at its own row. A re-pointed `let` is no once-bound binding and keeps the refusal.
