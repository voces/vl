### D2305 — an inferred object literal whose field is a concatenation of string VARIABLES is check-clean invalid wasm

**closed 2026-09-24 — the witness prints `xx` · was check-clean invalid wasm, clause 1 · found by the
leading-operator parse grid · filed 2026-09-24 against master `c2f040366` · fixture
`tests/cases/objects/anon-field-string-concat-of-values.vl`**

Repro:

    let a: string = "x"
    const o = { k: a + a }
    print(o.k)
    // vl check: rc 0.  vl run: invalid module, the top-level code fails validation:
    //   type mismatch: expected i32, found (ref $type)

#### Close

The producer was `anonFieldCodeSyn`, the syntax rung that codes an inferred record's field
before the recorded type is asked: its `+` arm declined only a chain holding a string LITERAL
and coded every other `+` as arithmetic, so a concat of string values minted `{ k: i32 }`. It
now declines when the `+`'s recorded type is `string`, and the arena rung codes the string
slot. The `.length`, `a + "!"`, template, array-element and call-argument spellings run.
[D2307](D2307.md) was the same field code reached from an operator body.

#### Mechanism

Not yet located. The field's value is a runtime string concatenation, and the row the
inferred literal is built at appears to take the field as `i32`: reading it through a
DECLARED row (`type O = { k: string }`, `const o: O = …`) runs, and so does a field that is a
literal concatenation (`"x" + "y"`, folded at compile time) or a bare string variable. Which
producer types the field is a prediction, not a finding.

#### Ablation

| ingredient removed | outcome | needed? |
| --- | --- | --- |
| the concatenation (`{ k: a }`) | runs, prints `x` | **yes** |
| the variables (`{ k: "x" + "y" }`) | runs, prints `xy` | **yes** |
| inference (`const o: O = …` with `type O = { k: string }`) | runs, prints `xx` | **yes** |
| module scope (the same three lines inside `function main`) | still invalid | no |
| the read of `o.k` (a second field `n: 1`, print `o.n`) | still invalid | no |
| `print(o.k)` replaced by `print(o.k.length)` | loud emit reject: `'.length' on a receiver the emitter cannot classify` | the same mistyped field, loud |

#### Grading list

The `.length` spelling above; `+` of a string variable and a literal (`a + "!"`); a
template (`"\{a}!"`); the same field in an array element literal and a call argument.
