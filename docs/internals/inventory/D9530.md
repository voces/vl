### D9530 — a record literal of an un-annotated function handed to an un-annotated parameter beside a declared record type of the same field name is built as invalid wasm

**check-clean invalid wasm · `vl check` rc 0 · `the emitted module failed to validate inside `take`: type mismatch: expected f64, found i32` · clause 1 · found closing [D9471](D9471.md) · present on master `1cf53e320` · filed 2026-10-22 against master `1cf53e320`**

Repro:

    type R = { f: (a: i32) => f64 }
    function inc0(a) { return a + 1 }
    function take(a) {
      print(a.f(3))
    }
    take({ f: inc0 })
    // vl check rc 0.  vl run: the emitted module failed to validate inside `take`: expected f64, found i32

#### Mechanism

Not traced. `R` is never used, yet removing it makes the program run, so the literal
`{ f: inc0 }` or the parameter `a` appears to be laid out at `R`'s row, whose `f` returns f64,
while `inc0` returns i32.

#### Ablation

| ingredient removed | outcome | needed? |
| --- | --- | --- |
| the declaration of `R` | runs, `4` | **yes** |
| `R`'s field renamed (`type R = { g: i32 }`) | runs, `4` | **yes** |
| the hole in `inc0` (`inc0(a: i32): i32`) | runs, `4` | **yes** |
| the literal, bound first (`const r = { f: inc0 }`, `take(r)`) | same invalid wasm | no |
