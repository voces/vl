Repro:

    type R = { f: (a: i32) => f64 }
    function inc0(a) { return a + 1 }
    function take(a) {
      print(a.f(3))
    }
    take({ f: inc0 })

Want:

    4

#### Mechanism

The emitter lays a record literal out at a declared row whose field names and kinds fit
(`declRowFieldKindFits`, emit_atom_kinds.vl), and a function field with holes fits any function
field type (`fnFieldTyFits`). So `{ f: inc0 }` was built at `R`'s row, whose `f` returns f64,
and `take`'s instance called `inc0`'s i32 result through an f64-result signature. The row is
now refuted when the field's function, called at the row's parameter types
(`holeFnArgRetAtParams`), has a closed, non-literal result that is not the row's; the literal
then gets its own row. The checker owed nothing: the annotated twin
(`inc0(a: i32): i32`), the bound twin and the program without `R` all run.
