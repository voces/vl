### D15253 — emit decides a literal `is` pattern from its text, not from the checker's tested type

**runs today and must keep running · residue of [D15250](D15250.md) · filed 2026-11-04 against master `306ef2b8f` by lane column-G1**

Repro:

    type K = 1 | 2 | "a"
    function f(x: K) {
      if x is i32 { print("num") } else { print("str") }
      if x is "a" { print("is a") }
    }
    f(1)
    f("a")
    // vl run: num, str, is a

#### Mechanism

D15250 moved the variant row an `is` names onto the checker's tested type (`isTestedRowOf`).
Three emit sites still read the pattern's own text (`IsExpr.isVariant`) to tell a literal
pattern apart, a fact the tested type already carries:

* `wasmEmit.vl`, the literal-box arm before `emitIsTestNumLit`: `primNameStr(...) == isVariant`
  picks the literals of a base scalar (`x is i32` over `1 | 2 | "a"`, D3522).
* `wasmEmit.vl`, `emitIs`: `isLitVariantName(isVariant)` sends a literal pattern to
  `emitLitMemberEq`, which compares the receiver to that text.
* `emit_sections.vl` and `emit_fn_scans.vl`: a pattern whose text starts with a quote is a string
  literal.

#### Progress

The first two sites read stamps (2026-11-04, lane column-G1). The literal pattern is
`isTestedLitLex(isVarTyIx)`. The base-scalar test reads the pattern's own type, `isPatTyIx`, which
`checkIsExprNode` banks beside the meet: `x is i32` over `7 | 1` is met to `1`, so `isVarTyIx`
cannot tell it from `x is 1`. Probed over the 7,770 files with an `is`: 0 disagreements at either.

Still open: the string pool and the scratch-frame scan. Both ask whether a literal set was
spelled inline or named (`x is "debug" | "x"` against `x is Mode`), which no type carries,
since the arena has no alias kind.

#### Grading list

The witness, and every `is` fixture under `tests/cases/`: none may change outcome when the
site reads a stamp instead of the text.
