### D3039 — an un-annotated `.filter`/`.map` callback over a list of union boxes takes the member set of another union the module declares, and folds its `is` test

**closed · an un-annotated parameter whose recorded type is a union pins its OWN union's registered row (`unionParamPinName` asks `unRowOfCanon` first), not the first boxed alias `unNames` holds · fixture `tests/cases/unions/callback-param-pins-its-own-union.vl` · was check-clean silently wrong · found building D3026's grid (its filter and map readers) · filed 2026-09-28 against master `3a71bb1f9`, closed 2026-09-28 against master `6c2dafc0b`**

Repro:

    function mk(): string | f64 { return 1.5 }
    const z: (string | i64)[] = [5, "t"]
    for v in z.filter((w) => w is i64) { print(v) }
    print(z.length)
    // PRINTS 2

Want:

    5
    2

#### Mechanism

The callback's parameter `w` is typed from the receiver's element, `string | i64`, but the
lambda's body is checked with `w` at a different union: the one `mk` returns, the only other
union in the module. There `w is i64` is impossible, so the test folds to `false` and the
lambda compiles to `return 0` (disassembly: `$__lambda_0` is `(return (i32.const 0))`). The
same binding printed `"s"` through `(w) => !(w is string)` when `std:fmt` was imported, whose
unions hold no `string`, and made `(q) => if q is string { 0 } else { q }` invalid wasm
(`expected i64, found f32`) beside a function returning `string | f32`. Not investigated past
the ablation: where the lambda's parameter type is resolved from.

Resolved at the close: `synthParamAnnots` (`emit_rewrite.vl`) gives each un-annotated parameter an
annotation spelled by `recordedParamPinName`. For a boxed union it took the FIRST registered union
alias that was not a literal union, on the ground that every boxed union shares `$uBox`. The box
is shared, but the spelling is what an `is` in the body is decided against, so the lambda's `w`
read as `mk`'s `string | f64` and `w is i64` folded to `false`. The pin now takes the parameter's
own row first (`unRowOfCanon` of its recorded type), and falls back to the old walk only where the
union has no row of its own. The fix is at the pin, so it is not specific to `.filter`/`.map`:
every un-annotated union parameter a context pins (a user function's callback argument, a typed
`const` binding, a record field of function type) took the same wrong spelling.

#### Ablation

| ingredient changed | outcome | needed? |
| --- | --- | --- |
| annotate the parameter `(w: string \| i64)` | prints `5`, `2` | **yes** |
| no `mk` | prints `5`, `2` | **yes** |
| `mk` returns `f64`, not a union | prints `5`, `2` | **yes** (a union) |
| `mk` returns `boolean \| i32`, or a three-member union | still wrong | no (which union) |
| `(w) => !(w is string)` | prints `5`, `2` | the test must be one the other union decides |
| `.map((w) => w is i64)` | prints `false`, `false` | no (map too) |
| `mk` declared after the use | prints `5`, `2` | **yes** (the other union registered first) |
| the element union declared as `type U = string \| i64` before `mk` | prints `1` (right) | **yes** (same cause) |
