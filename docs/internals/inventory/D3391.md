### D3391 — an if-expression whose arm ends in `??` over the arm's own nullable map local cannot be read as a map

**loud emit reject · pre-existing · 4 cells of the D3370 position grid (the map value read directly, every loop kind) · filed 2026-09-30 against master `4ff12b994`**

Repro:

    function mk(k: i32): Map<string, i32> {
      const m: Map<string, i32> = Map()
      m["a"] = k
      m
    }
    function h(n: i32) {
      print((if n > -1 {
        let o: Map<string, i32> | null = null
        if n == 2 { o = mk(100) }
        o ?? mk(102)
      } else { mk(0) })["a"] ?? 0)
    }
    h(0)
    h(2)
    // vl check: rc 0.  vl run: emitProgram: `??` over this nullable value is not supported yet

Want:

    102
    100

#### Mechanism

Not traced. The outer `m[k] ?? 0` asks the map shape of its receiver, the if-expression, which
reads it through the then arm's tail `o ?? mk(102)`, whose left operand is a local of the arm
that no scope binds until the arm lowers, so no nullable-map shape answers. With a non-null arm
local (`const o = mk(100 + n); o`) the receiver resolves and runs. A nullable loop value read
directly (`((for …) ?? mk(102))["a"]`) lowers to this shape since D3370's close.

#### Ablation

| ingredient changed | outcome | needed? |
| --- | --- | --- |
| the arm tail a non-null local, `const o = mk(100 + n); o` | runs | **yes** (a nullable arm local) |
