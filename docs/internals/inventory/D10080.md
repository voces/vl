### D10080 — a list of a generic pushed a fixed-type function, then handed to an annotated parameter or return, passes check and traps at the call

**trap after load · `vl check` rc 0 · `wasm trap: indirect call type mismatch` · clause 1 · found closing [D10020](D10020.md) · present on master `e0eecffc4`, unchanged by its close · filed 2026-10-22 against master `e0eecffc4`**

Repro:

    function id<T>(x: T): T { x }
    function inc(x: i32): i32 { x + 1 }
    const ys = [id]
    ys.push(inc)
    function run(a: ((string) => string)[]) { print(a[1]("s")) }
    run(ys)
    // vl check rc 0.  vl run: wasm trap: indirect call type mismatch, in `run`

The owed outcome is a check refusal: `inc` reaches a call at `string`, which `vl check` refuses with `run` inlined.

#### Mechanism

Not traced. The push of `inc` is a deferred row against the list's element `(T) => T`,
re-validated only at a call that binds `id`'s `T`. Once the list is handed to a function, the
element call inside it binds no `T` of `id`'s at a call the row is checked at, so the row is
never adjudicated against `string`, and the call reaches `inc`. The same with
`function get(): (string) => string { ys[1] }` and `get()("s")` at module scope.

#### Ablation

| ingredient removed | outcome | needed? |
| --- | --- | --- |
| the push of `inc` | runs, `s` | **yes** |
| the annotation on `a` (`function run(a)`) | traps the same | no |
| `run` inlined as `print(ys[1]("s"))` | check refuses, `push: cannot add` | **yes** |

#### Grading list

- `function get(): (string) => string { ys[1] }` with `print(get()("s"))`: the return position, same trap.
