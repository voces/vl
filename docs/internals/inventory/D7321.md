### D7321 — `vl check <dir>` re-checks each shared module once per root it is not served to, 41 times the work of the largest single root on diderven

**runs today and must keep running · open, narrowed · a cost row, no wrong value: the witness prints its Want, and the cost is the directory's multiplicity · owner lane S5 · filed against master `966471462`**

Repro:

    import { includes } from "std:array"

    // The cost needs a directory of many roots that share modules: diderven's src/ has 330.

Want:

#### Mechanism

`vl check src` treats each of diderven's 330 files as a root (`check_roots_pooled`, two workers).
S5's serving (#4155) lets a root reuse a module another root already checked, but only from the
same worker's bank. On master `966471462`, at two workers, 97 of 330 roots were served and the run
did 12,864 module checks: `rng.vl` was checked 150 times and `std:array` 191 times. Declines on
an earlier run: 112 `unseen`, 50 `demand`, 61 `ambient`. Serial guest fuel for the whole
directory is 192.3G, against 4.64G for `vl check src/game.vl`, the largest root, alone. Warm
pooled `vl check src` reads about 31 s user and 13–18 s wall at load 10–22.

Two instrument gaps make this hard to measure. `VL_FUEL=1` and `VL_PROFILE_GUEST` both turn
off the pool and the importers-first order, so neither one measures the default schedule. And
the check path never calls `report_guest_fuel`, so `vl check` under `VL_FUEL=1` prints no
`[fuel]` line. These numbers came from a scratch host that adds that call.

#### Grading list

Re-run `vl check src` over a copy of diderven with the serving trace, and count served roots and
total module checks.

#### Narrowed (lane S5, 2026-10-19)

The instruments now measure the default schedule. `VL_FUEL=1` keeps the check pool on, and
`[fuel] guest:` sums the parent and every worker. `VL_CHECK_STATS=1` prints roots and module
checks per serving reason, and `VL_CHECK_STATS=trace` prints each decline with the module and
name it blames.

Attribution on the diderven copy, two workers, before the fix: 10,059 to 10,527 module checks
across runs (the pool's schedule moves a few roots).

* `unseen`: 112 to 114 roots, about 5,300 checks. 110 of the 330 files are imported by no other
  file (102 are tests), so no importer's check can serve them. One bank for every root
  (`VL_JOBS=1`) serves 100 roots against 96 at two workers, so no pool order or shared bank can
  move this much.
* `demand`: 46 to 47 roots, 3,460 to 3,676 checks. Every culprit was an un-annotated exported
  binding: a signed literal (`WHITE = -1`, 11 roots), a list of scalars (`DEATH_TILT`), a call of
  a closed function (`FIRE = rgba(…)`) or of a generic one (`poseSpr = filled(…)`).
* `ambient`: 57 to 65 roots, 1,266 to 1,431 checks.

The fix serves the first three kinds of binding: `skClosed` shuts a signed number literal, and
`wiDemandShut` admits a non-empty list of scalar literals and primitive names, or a call of a
closed, non-generic, non-overloaded function with a declared return (mask 2048). After it,
`demand` holds 16 to 17 roots, all `filled` bindings, and the total is 9,600. Under `VL_FUEL=1`,
10,527 → 9,602 module checks and 213.8G → 197.3G guest fuel (−7.7%). Heregeat moves 1,327 →
1,319. Output is byte-identical on both copies at 1, 2 and 6 jobs, and on
`vl check compiler std scripts`.

What is left: `unseen` needs a root's imports served one module at a time, not whole roots. And
`ambient` now holds 83 to 90 roots, with blame spread over many modules (`rng.vl` 14, the next 7).
