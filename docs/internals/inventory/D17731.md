**runs, prints `4` `6` — CLOSED 2026-11-28: the walk reads at the map's stored closure rep (ir_build's map walk), and the tag judge admits a map's `values()` as a slot op of a map of the set's ids (check_fn_tag `ftSlotOp`), copying them into a list of the same set as a list's `slice` does, so a split call through the values is tagged as one through a list's element is; pinned by `tests/cases/maps/values-walk-over-map-of-function-set-reads-stored-closure.vl` and `tests/cases/maps/split-call-through-map-of-function-set-values.vl`. #### Mechanism

Two halves. The walk bound `v` at the rep of the checker's set type, a closure rep other than the
`(f64) => f64` the map stores its values at (`mapWalkValRep`). And `v(3)` is a split call (`g` at
`i32` gives `i32`, `dbl` gives `f64`), which only a tagged set dispatches; the judge declined to tag
the map's set because `values()` was no slot op it admits on a map (`ftSlotOp`), where a list's
walk and copies are. The close admits it, so one rule tags a split call through a list element, a
map value read by key, `get` or a pair walk, and a values walk, bound first or off a record field.
A map handed to an un-annotated parameter and walked there refuses `convert map -> map`, before
any call, on master too.
