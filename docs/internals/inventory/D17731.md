### D17731 — a values walk over a map of a tagged function set is refused at the walk

**loud emit reject · `this call runs functions that return different types, and one of them is also held where it cannot be stored as one of the functions this value may hold, so the call has no one signature` · clause 2 · open (the tag judge's half) · `vl check` rc 0 · the walk's own refusal (`for in map element rep`) is fixed: a closure-element values walk reads at the map's stored closure rep, pinned by `tests/cases/maps/values-walk-over-map-of-function-set-reads-stored-closure.vl`; `v(3.0)` runs · the keys walk, a list of the same set, and a closure set all run · found grading [D17726](D17726.md) · filed 2026-11-27 against master `b71fd7b8f` by I8-PREP · owner COV-IS**

Repro:

    function dbl(a: f64): f64 { return a * 2.0 }
    const g = (a) => a + 1
    const _a = g(2.5)
    const _b = g(3)
    const m = Map()
    m["a"] = g
    m["b"] = dbl
    for v in m.values() { print(v(3)) }
    // vl check: rc 0.  vl run: emitProgram: this call runs functions that return different types, … so the call has no one signature

Want:

    4
    6

#### Mechanism

Two halves. The walk bound `v` at the rep of the checker's set type, a closure rep other than the
`(f64) => f64` the map stores its values at (`mapWalkValRep`), and refused; it now reads at the
stored rep. What remains is the tag judge: `v(3)` is a split call (`g` at `i32` gives `i32`, `dbl`
gives `f64`), and the map's set is left a closure set, so `callRefSplitKind` refuses. The same set
in a list is tagged and its call dispatches per member; the close is one tagging rule for a split
call read through any holder (coordinator ruling 2026-11-27).

#### Ablation

| ingredient removed | outcome | needed? |
| --- | --- | --- |
| `g`, two declared `f64` functions in the map (a closure set) | runs, `4` `6` | **yes** (the tagged set) |
| a keys walk reading `m[k]` | runs | **yes** (the values walk) |
| the same two in a list, `for v in [g, dbl]` | runs, `4` `6` | **yes** (the map) |
