### D15120 — a call through an un-annotated `let` copy of a type-parameter function parameter, at two members, is not tagged, so it leans on the split plan

**runs today and must keep running · split-plan census F-B · filed 2026-11-03 against master `12de83558`**

Repro:

    function id<T>(x: T): T { x }
    function dup<T>(x: T): T {
      print("dup")
      x
    }
    function one<F>(a: F) {
      let b = a
      print(a("x"))
      print(b(3) + 1)
    }
    one(id)
    one(dup)

Want:

    x
    4
    dup
    x
    dup
    4

#### Mechanism

With the split plan off (`compileSrc` returning after its first compile) this refuses at emit: `a
function-value call has no interned signature` at `b(3)`. With `const b = a` or `let b: F = a` the
late tag decision (`fnTagRedecide` from `elabPrepare`, `ftTry` → `ftCommit` → `ftBuildArmsAt`)
rewrites `b(3)` into its members' calls. With `let b = a` `ftPlan` refuses the set at "a member call
names the member as its leaves do": one member has no leaf the scan reaches through the binding, so
`b(3)` stays a call through a closure whose type is the open generic `(T) => T`. Widening
`fnTagParamCopyOf` to an unwritten `let` alone does not move it; the scan's leaf for that member is
the open question.
