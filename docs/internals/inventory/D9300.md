### D9300 — a list literal of records holding a list of un-annotated functions mints two list types for one field

**check-clean invalid wasm · `vl check` rc 0 · `type mismatch: expected (ref $4), found (ref $6)` · clause 1 · found closing [D9253](D9253.md) · present on master `cf1b1a8d3` · filed 2026-10-21 against master `cf1b1a8d3`**

Repro:

    function inc0(a) { return a + 1 }
    const hl = [inc0]
    const xs = [{ m: hl }]
    print(xs.length)
    // vl check rc 0.  vl run: invalid module: type mismatch: expected (ref $4), found (ref $6); $4 is ` ((i32)=>i32)[]`

#### Mechanism

Not traced. The validator names the two list types: one spelled ` ((i32)=>i32)[]` with a
leading space, the field type the record row was minted with, and one spelled
`((i32)=>i32)[]`, the type `hl` holds. They are the same list, given two rows by two spellings.
The leading space suggests a pin spelling built by concatenation. That area (the instance
and pin names) was being rewritten by another lane when this row was filed, so it was not
chased here.
