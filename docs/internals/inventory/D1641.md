### D1641 — `[] as u8[]` refuses at the numeric-only `as` arm, and the message does not say the cast is what is wrong

**loud check reject · both faces · filed 2026-09-05 against master `df312ed6b` · found by glean, VL's first external consumer**

Repro:

    function f(m: u8[], off: i32): u8[] { if off < 0 { return [] as u8[] } m.slice(off, off + 2) }
    const b: u8[] = [1, 2, 3, 4]
    print(f(b, 0 - 1).length)
    print(f(b, 1).length)
    // vl check: `as` supports numeric conversions only

#### Mechanism

`as` is numeric-only by design, so the refusal is CORRECT and this is not a capability
gap — the program is ill-typed and the checker owes the diagnosis. What the row asks for
is the diagnosis's second half. An empty array literal takes its element type from its
DESTINATION, so the cast the author reached for is not merely unsupported, it is
unnecessary: deleting `as u8[]` makes the same program run. The message says what `as`
does not do and leaves the reader looking for a different cast spelling, which is the
one thing that cannot work.

Asked for: a suffix on the `as` refusal when the operand is an empty array literal —
`; write \`[]\` — an empty array literal takes its element type from its destination`.
That is `typecheck.vl`'s `as` arm, not this lane.

#### Ablation

| ingredient removed | outcome | needed? |
| --- | --- | --- |
| `as u8[]`, leaving a bare `return []` | runs, prints `0` then `2` | **yes** |
| the parameter and return annotations (`function f(m: u8[], off)`) | still refuses, same message | no |
| the annotation AND the cast together | runs, prints `0` then `2` | — |

BOTH FACES REFUSE and BOTH FACES RUN once the cast goes, so the destination's element
type reaches the empty literal with or without the annotation. Nothing about the
inference is at issue; only the wording is.

#### Grading list

The two controls above — the annotated and un-annotated `return []` — run today and must
keep running; they are the evidence that the suffix's advice is true. A fix must also
leave the message unchanged where the operand is NOT an empty array literal (`"x" as
i32`, `xs as u8[]` over a non-empty list), since the suffix would be false advice there.
