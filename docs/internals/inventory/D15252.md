### D15252 — `is` has no one relation: the checker's narrowing and mono's static answer each decide it their own way

**runs today and must keep running · design row for [D15250](D15250.md)'s `monoStaticIsResult` half · filed 2026-11-04 against master `891fb463` by lane column-G1**

Repro:

#### Mechanism

The checker narrows an `is` per kind (`collectThenNarrows` / `collectElseNarrows`,
`compiler/check_narrow_flow.vl`): a literal-set meet, a record fit meet, a covering union, a fit
across tags. Mono's static answer (`monoStaticIsResult`, `compiler/wasmEmit.vl`) re-decides the
same question from spellings: the pin's name against the pattern text, its render, a name-keyed
row match. Neither is the checker's `assignable`: an `i32` is assignable to `f64`, but a value at
an `f64` pin never `is i32`, and a `B` that fits `A` takes its own arm (D3235, the witness).

#### Design: `isTestAnswer(operandTy, testTy)` → 1 always, 0 never, -1 the stored value decides

`compiler/check_narrow_flow.vl`. The operand is flattened into its members
(`flattenVariantsInto`). The answer is 1 when every member answers 1, 0 when every member answers
0, and -1 otherwise. A member `m` against `t`, first rule that applies:

#### Two relations, not one: the checker's narrowing does not call `isTestAnswer`

They answer different questions, and this section exists so nobody merges them again.

* **`tyUnionCovers(t, cur)` in `collectThenNarrows` (D3360) is the REP question**: is the tested
  type already the operand's own member, so that the then arm keeps the operand as it is and
  narrowing pushes no fact.
* **`isTestAnswer` is the VALUE question**: does the test always hold, never hold, or depend on
  the stored value. Mono's static fold (`monoStaticIsResult`) asks it at an instance's pin.

Swapping the first for `isTestAnswer(...) == 1` was tried and changed emitted code, in three
families where a test that always holds still has to narrow:

* **F1, one type:** `f64` / `f64`, `C` / `C`, `T[]` / `T[]`. The then arm still needs the fact.
* **F2, record unions where every member fits:** `U` against `A`, `A | B` against `B`, `U` against
  `Cat`, `W` against `Boxed`. Narrowing picks the tagged arm, which is a different rep.
* **F3, list unions:** `(i32 | null)[] | null[]` against `(i32 | null)[]`, and
  `readonly f64[] | f64[]` against `readonly f64[]`. Narrowing picks the rep.

#### Plan

1. PR 1: `isTestAnswer` in the checker, and `monoStaticIsResult` as its reader. Its spelling
   rungs after the join rung (the sigkey, `isVariant` and render-name tests, the name-keyed row
   match, the default 0) are deleted. A sigkey pin keeps its one text test, since it has no row
   to test. Acceptance: the nine rows above, each already a `tests/cases/` fixture, keep their
   output, and none of the 38 programs an earlier relation-free rewrite moved may refuse.
2. The rungs before the join rung (the variant-spelling test, `exprUnion`, the one-list union,
   the exact instance) stay. Moving them is [D15250](D15250.md)'s `emitIsTestVariant` half.
