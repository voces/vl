### D1621 — an un-annotated capture initialised from a field, element or map read types its env cell as `i32`

**closed · filed 2026-09-05 against master `153760e1` · closed against `ef92ad0c`**

`letInitCellKind` asks the ARENA beside its syntactic closure arms, at both the plain and the
nullable rep. All three container reads run un-annotated, and the `@hint` declarations that
marked their annotations load-bearing are deleted.

Repro:

    function go() {
      const w = { f: (n: i32) => n + 4 }
      const v = w.f
      const g = (n: i32) => v(n)
      print(g(40))
    }
    go()
    // vl check: rc 0.  vl run: emitProgram: call to unknown function

#### Mechanism

`captureValKind` types an ANNOTATED env field through `vtKindOfType` and an un-annotated one
through `letInitCellKind`. That second ladder claims a lambda literal, a bare function name
and a closure-typed param, and has **no arm for a container or field READ** — `w.f`, `xs[0]`,
`m["k"]`. So the env field is typed `i32`, `capturedKindOf` answers `"i32"`, and the capture
rung D1608 built declines a value that really is a closure.

This is the same divergence `tests/cases/closures/capture-unannotated-nullable-reps.vl`
documents for the nullable reps: `collectLocals` types the binding one way and
`letInitCellKind` another, and the annotation is what papers over the gap. A fix owes the
companion index too (`captureValStructIdx`), or the kind arrives with no interned shape and
one refusal is swapped for another.

#### Ablation

Every row is `vl check` rc 0. The lambda captures `v` and calls it.

| spelling | outcome |
| --- | --- |
| `const v = w.f` (struct field, un-annotated) | **emit reject** |
| `const v = xs[0]` (list element, un-annotated) | **emit reject** |
| `const mv = m["k"]` (map read, un-annotated) | **emit reject** |
| `const v: (i32) => i32 = w.f` | runs, 44 |
| `const v: (i32) => i32 = xs[0]` | runs, 55 |
| `const mv: ((i32) => i32) \| null = m["k"]` | runs, 33 |
| `w.f(n)` called directly in the lambda, no binding | runs, 44 |
| `const v = w.inner.f` (a nested field, two hops down) | **emit reject** |
| `const v = deliver()` where `deliver` is annotated | runs, 77 |
| `const v = (n: i32) => n + 8` (a literal) | runs, 88 |

Needed: the capture's parent binding being UN-ANNOTATED **and** its initializer being a
field, element or map read. Not needed: which container, the call position, or the nesting
depth. The checker emits `@hint redundant type annotation` on each annotation that rescues
these — it agrees about the TYPE and says nothing about the REP.

#### Grading list

* The three cells in `tests/cases/closures/call-captured-closure-positions.vl` are now
  UN-annotated and their `@hint` declarations are deleted — the fixture would be blind to this
  rung with them, so the un-annotated spelling is what pins it.
* `captureValStructIdx` alongside `captureValKind`: not needed here after all. The `closure`
  and `nulclosure` kinds both take slot `-1` at `fbValtype`, so this kind has no companion
  index to keep in step, unlike the `S[] | null` rep that lesson came from.
* The nullable spelling (`m["k"]` narrowed) as well as the bare one: both run, through
  `nodeTyIsNulFunc` and `nodeTyIsFunc` respectively — the same arena question at two reps.
  `tests/cases/closures/capture-from-container-read.vl` is the fixture and
  `scripts/capability-probes/capture-from-container-read.vl` the probe.
