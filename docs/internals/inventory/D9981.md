### D9981 — a loop variable over a nested list of an un-annotated function, bound to a `const` in the body, beside a read at another type, is an unsupported iterable

**loud emit reject · `vl check` rc 0 · `unsupported for-in iterable` · clause 2 · the same loop reading `r[0](3)` directly runs, and so does the flat list's alias · found closing [D9901](D9901.md) · present on master `0f0face1e` · filed 2026-10-22 against master `0f0face1e`**

Repro:

    function inc(a) { return a + 1 }
    const u = [[inc]]
    for r in u {
      const q = r
      print(q[0](3))
    }
    print(u[0][0](2.5))
    // vl check: rc 0.  vl run: emit error unsupported for-in iterable

Want:

    4
    3.5

#### Mechanism

Read off the code, not yet probed: [D9901](D9901.md)'s close rewrites a binding that a rewritten read wholly initializes only when
every use of it is a CALL (`monoFlowAliasCallsSet`). Here the alias `q` of a row is used as an
index receiver, `q[0](3)`, so `q` is not rewritten, the loop's rows are planned at two types,
and the loop over `u` has no single element rep to iterate.
