#### Mechanism

Located, not fixed. Legacy builds `v`'s literal at row `$0 = {r: ref $1, s: ref $4}`, whose `r`
holds a tagged id (`inc0`, id 6) and whose `s` holds a closure struct; `let m = v` takes that
row. The reassigned literal `{ r: { f: dbl }, s: { f: dbl } }` is built at its own row
`$5 = {ref $4, ref $4}` and stored into `m`'s `(ref $0)` local, which fails validation.

With `let m = <the literal>` directly, the record solve (`recBuildTyOf`, `check_rec_rows.vl`)
counts the reassignment as a build of `m`'s binding. It builds it at `$0`, with `dbl` at id 13 in
`r`'s set, and the program runs. Through the `const` copy, nothing links the write into `m` to `v`'s
literal. `recBuildRowOf` (`emit_classify.vl`) covers `m.f = {…}`, `m[k] = {…}` and
`m.set(k, {…})`, but not a whole-binding `m = {…}`, and the solve does not follow the alias.
