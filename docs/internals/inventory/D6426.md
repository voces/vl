### D6426 — a generic called with values of two distinct type parameters at one of its own is check-clean invalid wasm

**now a loud check reject, `argument of type string flows into `g` expecting i32 (the call's argument types)` — fixed 2026-10-18 by lane L3: DESIGN at the instance, not at the definition. A generic body is judged per instance, so `T` meeting `U` in the uninstanced body is accepted by design (`return b` with no call is check-clean, and `f(1, 2)` runs); what was missing is that a pair of two distinct DECLARED type parameters recorded no argument constraint for the instance to re-ask (`tyParamsApart`, `check_hole_pins.vl`; recorded in `check_calls.vl`, carried to an outer generic's instance in `validateArgCstrs`) · was check-clean invalid wasm, clause 1 · pins: `tests/cases/generics/error-distinct-type-params-at-one-instance.vl`, `tests/cases/generics/distinct-type-params-at-one-same-type-instance.vl` · the un-annotated spelling is filed as [D6482](D6482.md), a function-typed binding as [D6483](D6483.md) · found grading [D6372](D6372.md) · filed 2026-10-18 against master `066d19373`**

Repro:

    function g<T>(x: T, y: T): T { return y }
    function f<T, U>(a: T, b: U): T { return g(a, b) }
    print(f(1, "s"))
    // vl check: rc 0.  vl run: the emitted module failed to validate inside `f`: type mismatch: expected i32, found (ref $2); $2 is `string`

#### Mechanism

From the ablation only. The checker accepts `g(a, b)` with `a: T` and `b: U` as a call of
`g` at one type, so `f`'s result, typed `T`, holds the `U` value. Read directly, the same
mismatch is refused at check.
