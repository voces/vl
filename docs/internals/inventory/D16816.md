### D16816 — a maker's call result handed to an un-annotated parameter is refused at emit

**open · loud emit reject · clause 2 (`vl check` rc 0) · the un-annotated `argument` face of `maker-hole-param-at-two-results.matrix.vl` and `maker-generic-at-two-results.matrix.vl` · filed 2026-11-16 against master `05e6da185`**

Repro:

    function adder(n) { return (a) => a + n }
    function take(a) {
      const v = a
      print(v(3))
    }
    take(adder(2))
    // vl check: rc 0.  vl run: emit error, `monomorphize: unsupported argument type for `a` in a call to `take``

Want:

    5

#### Mechanism

Not traced. The maker's result is pinned by its call (`adder(2)` pins `n` at `i32`), but the
parameter `a` it is handed to has no type of its own, so the instance of `take` is asked of a
function type whose parameter the maker call has not closed. A plain call result reaches the same
parameter and runs, so the refusal is not about call arguments.

#### Ablation

| ingredient changed | outcome | needed? |
| --- | --- | --- |
| `take(a: (a: i32) => i32)` | runs, `5` | **yes**: the un-annotated parameter |
| a lambda literal `take((a) => a + 2)` | runs, `5` | **yes**: the maker |
| a parameterless maker `function mk() { return (a) => a + 2 }` | runs, `5` | **yes**: the maker's parameter |
| generic `adder<T>(n: T)` in place of `adder(n)` | the same message | no |
| a call result with no lambda (`function g(n) { return n + 1 }`, `take(g(2))` with `print(a + 1)`) | runs, `4` | **yes**: a function value |
| the maker's parameter annotated (`adder(n: i32)`), the lambda not | runs, `5` | **yes**: the maker's un-annotated parameter |
| the lambda's parameter annotated (`(a: i32) => a + n`), the maker's not | runs, `5` | **yes**: the hole lambda |
| the maker's call bound first (`const v = adder(2)`, `take(v)`) | runs, `5` | **yes**: the call handed directly |
