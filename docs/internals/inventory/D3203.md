### D3203 — a guarded call through a hole's `(() => string) | null` field has no signature, and then prints its result as an i32, where no closure of that signature exists

**closed · the string classifier reads a hole instance's value call through a field as it reads one through a name · fixture `tests/cases/generics/hole-guarded-string-call-with-no-closure-of-its-signature.vl` · was a loud emit reject on master, and check-clean invalid wasm under D3197's narrowing alone · clause 2 · pre-existing, the same on master `94670f728` · found by the NF lane's grid (`n0516_str_N_hole_guard_null_bound`) · filed and closed 2026-09-29 against master `94670f728`**

Repro:

    type R = { v: i32, f: (() => string) | null }
    function F(z) {
      if z.f != null { print(z.f()) } else { print("none") }
    }
    const r0: R = { v: 7, f: null }
    F(r0)

Want:

    none

#### Mechanism

On master the call's callee is the hole's field (`HD_FLD`), which the instance binds to
`(() => string) | null`, so `cloCallSigKey` finds no function type and the call refuses. D3197
narrows the guarded field to its non-null face, so the call is keyed at `() => string`; but
`exprString` asked the hole instance's pin (D3117's arm) only for a callee that is a NAME, and a
field callee reached `fieldClosureFeOfRecv`, which finds no closure of that signature in the
program, so `print` took the i32 sink over a string ref: invalid wasm. The pin arm now covers a
field callee too.

#### Ablation

| ingredient changed | outcome on master | needed? |
| --- | --- | --- |
| a `() => string` closure or named function stored anywhere | prints `none` | **yes** |
| `const g = z.f; if g != null { print(g()) }` | prints `none` | **yes** (a field callee) |
| `(() => boolean) \| null` | prints `none` | **yes** (a ref result) |
| `function F<Z>(z: Z)` | refuses at emit | no |
