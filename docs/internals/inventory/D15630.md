#### Mechanism

The mono pass runs only when the program has a generic or a concrete higher-order function
(`monomorphize`, emit_mono.vl). An un-annotated-return function with a function-typed parameter
counts as one only when the program uses a nested function or lambda; an annotated return
counts always (`feHasClosureParam`'s
`fnNestUsed`). The compiler has nine such setters (`rlLateRowsOn` and kin, emit_state.vl), so one
lambda anywhere switched the pass on over the whole compiler.

Once on, every `xs.push(v)` asks `elabSlotDeliveries(xs, ["e"])` (`monoNotePushDeliveries` →
`monoSlotPinNameTys` → `monoDeclPathKeysIn`). For a parameter, `elabSlotDeliveriesInto` asks the
same query of each call's argument binding, and that nested query is below the depth-0 memo. A
recursive walker with K self-calls handing its own list on cost K^8 steps per push, to the depth cap
of 8. A list handed down L layers of W callers cost W^L. A sampled profile of the slow L2 build read
82.5% inclusive in `elabSlotDeliveries`, and 85% of its samples sat at the depth cap.

The fix has two parts, both in emit_elab.vl:

* A slot whose checked type is closed and holds no function answers no delivery
  (`elabTyFnFree`). `elabRetsAdd` only ever keeps a function type, so such a slot could only get
  one through an ill-typed flow. This is the compiler's case: its lists are `i32[]` and `string[]`.
* A parameter's call that hands it a binding already being expanded on the current query stack is
  skipped (`elabDlvActive`). The skipped edge answers a subset of what the outer level gathers.
  This is the repro's case, a list of functions.
