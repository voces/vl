### D2592 — a value union narrowed to a struct arm plus `null` is still read as the union box where `Arm | null` is wanted

**check-clean invalid wasm · clause 1 · the struct-variant arm of D2590 · filed 2026-09-26 against
master `ed81f8d55`**

Repro:

    type Circle = { r: i32 }
    function mk(n: i32): Circle | i32 | null {
      if n == 1 { return { r: 5 } }
      if n == 2 { return 3 }
      null
    }
    function take(c: Circle | null) { if c != null { print(c.r) } else { print(0) } }
    function go(n: i32) {
      const x = mk(n)
      if !(x is i32) { take(x) }
    }
    go(1)
    // vl check: rc 0.  vl run: invalid module, inside `go`:
    // "type mismatch: expected (ref null $type), found (ref $type)"

#### Mechanism

A prediction, from D2590's close. `Circle | null` over a union arm is the `nulvariant` niche,
a `(ref null $uVarHeap[vi])`, and the read of a union narrowed to it hands over the box.
D2590 converts only the two value-atom niches (`boolean | null`, `string | null`); the arm
case needs the same conversion to a typed null or the cast payload, and the consumers that
recognise a `nulvariant` value (`exprNullableVariant`, `nulVariantIdxOfExpr`, the binding
ladder's `letIsNulVariant`) taught to recognise the narrowed read.
