### D14752 — two same-tag record arms keep a literal-set field at the string rep, so the set arm has a second layout

**runs today and must keep running · refutation pin: deleting the same-tag half of D1050's demotion (`unifyMixedLitRepArms`'s `variantFieldLitRepStrMixed` arm) traps this program with `cast failure` at the `zzz` read · the residue of [D14746](D14746.md) · filed 2026-11-01 against master `cd15b5eb`**

Want:

#### Mechanism

`A` and `B` have one field-name set with the same storage outside `kind`, so they share one tag
and one layout, and `is A` tells them apart by `kind`'s value. That shared layout holds
`kind` at the string, because `B`'s plain `string` has no interned id. `A` built on its own
stores `kind` at the atom, so `A` has two layouts: its own, and the shared arm's. Without the
demotion the two arms keep different layouts under one tag, and the read casts a `B` to `A`'s
heap type. Giving `A` one layout here needs the pair laid out apart under two tags, with `is A`
still deciding by value.
