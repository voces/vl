### D4130 — a call that hands a scalar local to an intrinsic is summarised as writing anything, so `toString` ends every live narrowing

**closed 2026-10-11 — runs, prints `5 1` · was a loud check reject (`'a.x' is no longer narrowed to i32: the call to 'toString' on line 6 may reassign it`) · found grading a binding-narrowing retirement matrix · filed 2026-10-11 against master `efd3c3f15` · fixture `tests/cases/soundness/narrowing-survives-call-taking-scalar-local.vl`**

Repro:

    import { toString } from "std:fmt"
    type A = { x: i32 | string }
    const a: A = { x: 1 }
    const k = 5
    if a.x is i32 {
      const s = k.toString()
      const y: i32 = a.x
      print(s + " " + y.toString())
    }
    // WAS: check reject, the call to 'toString' may reassign 'a.x'.  NOW: prints 5 1

#### Mechanism

A call's write summary (`weArgShapes`) reads each argument handed to a callee it cannot see
into as a possible function value, and a bound local there answered `"*"` (writes anything)
whatever its type. std:fmt's `toString` reaches `renderF64` → `shortestDigits`, which calls
the intrinsic `clz(m)` on an `i64` local, so every `toString` call ended every live path
narrowing in its caller. A local whose recorded type is scalar is now no function value.

#### Ablation

| ingredient changed | outcome on master | needed? |
| --- | --- | --- |
| `toString(3)` instead of `k.toString()` | same refusal | no |
| an imported user function, or std `padLeft`, instead of `toString` | runs | **yes** |
| `toString`'s body reduced to `const m: i64 = 5; clz(m)` | same refusal | **yes** (the `clz` of a local) |
| a callee that writes `a.x` itself, or through a closure argument | refused, before and after | control |
