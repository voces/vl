### D16433 — a `let` of an open `Set()` re-pointed at another open `Set()` answers `is Set<string>` false

**check-clean silently wrong · clause 1 · open · prints `false` · an open empty set matches every test of its kind (D16047), but after the re-point it tests as an `i32` set · the `Map()` twin is the same · found by the `empty-set-literal-delivered-into-union-is` matrix's un-annotated `global_assign` cell, graded by the independent oracle · filed 2026-11-15 against master `a74e9c496`**

Repro:

    const a = Set()
    let b = Set()
    b = a
    print(b is Set<string>)
    // vl check: rc 0.  vl run: prints `false`.

Want:

    true

#### Mechanism

Both bindings hold sets whose element no write fixes, so each is open and its `is` should
match vacuously; after `b = a` the test answers as the default `i32` element would
(`b is Set<i32>` prints `true`). The checker agrees the test always holds: with an `else` it
warns that the `else` can never run, and the matrix cell then prints neither arm. From the
ablation.

#### Ablation

| `Map()` and `b is {[string]: i32}` | prints neither arm of an `if` | no |
