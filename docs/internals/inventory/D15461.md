### D15461 — a result chosen between two parameters one type parameter annotates, called at two types, is refused

**open · loud emit reject, `vl check` rc 0, `emitProgram: monomorphize: parameter `a` of `pick` is called at two function types that no parameter per type separates`, clause 2, with the split plan on and off · found folding the annotated-parameter gates into the joined-set rule (D15409, architecture-target-2026-10.md §2.4) · filed 2026-11-05 against master `d7080b05`**

Repro:

    function id<T>(x: T): T { x }
    function pick<F>(a: F, c: F, k: boolean): F {
      if k { return a }
      c
    }
    const h = pick(id, id, true)
    print(h(3))
    print(h("x"))

Want:

    3
    x

#### Mechanism

`pick`'s result is one of two parameters `F` annotates, and the caller calls it at `i32` and at
`string`. Handing one parameter back unconditionally runs (`ftOwnTyParamJoins` takes it as the
argument's set), but the choice reaches the result through a join, so the tag decision does not
take the set and mono's pin of `a` has two function types with nothing to give it a parameter per
type. The joined-set rule does not reach it: it excludes a result naming the type parameter, and
the one-function case refuses the same way.

#### Ablation

| --- | --- | --- |

| one parameter, `back<F>(a: F): F { a }` | runs, `3 x` | **yes** |
| the parameters and result un-annotated | still refuses, `a generic function taken as a value reaches no call that fixes its type` | no |
