### D7700 — a capturing nested function read from inside another function compares unequal to its read in the declaring frame

**check-clean silently wrong · wrong value · `vl check` rc 0 · clause 1 · under the [D7180](D7180.md) ruling a function value's identity is its declaration and captures, and both reads capture the same `n`, so `a == c()` is `true` · two reads in the declaring frame compare equal since [D7480](D7480.md) · found closing [D7480](D7480.md) · present on master `18100a6d2` · filed 2026-10-20 against master `18100a6d2`**

Repro:

    function outer(n: i32) {
      function inner(x: i32) { return x + n }
      const a = inner
      const c = () => inner
      print(a == c())
    }
    outer(3)
    // PRINTS false

Want:

    true

#### Mechanism

[D7480](D7480.md)'s close keeps one env per capturing declaration in a local of the frame
that declares it (`envCacheOpen`, emit_sections.vl). A read inside another function runs in
that function's frame, which has no such local, so it builds a fresh env from its own copies
of the captures, and the comparison of envs by reference fails. A fix makes the declared env
itself the captured value, so every frame that reads the function reads one env.

#### Ablation
