### D15895 — a held list of records whose function field holds an un-annotated function, read at a wider function type, passes check and traps

**closed 2026-11-12 · now a loud check reject, a `{f: (_) => _}[]` cannot be used as `{f: (i32) => i32 | null}[]` here, the held-container refusal (fixtures `closures/error-hole-fn-record-list-held-at-wider-fn-field.vl`, `closures/error-hole-fn-record-list-held-at-f64-fn-field.vl`) · was trap after load, clause 1, `wasm trap: indirect call type mismatch`, `vl check` rc 0 on master `d303c9bcd` · closed by applying `fvaHeldHoleFnDiffers` to a list of records as to a record · found ruling D15896 · filed 2026-11-12 against master `d303c9bcd`**

Repro:

    function inc0(a) { return a + 1 }
    const xs = [{ f: inc0 }]
    const rs: { f: (a: i32) => i32 | null }[] = xs
    print(rs[0].f(3) ?? 0)

Want:

    a loud check reject: the functions inside a held container are not converted on the way

#### Mechanism

A function delivered at a function type of another rep is wrapped in an adapter, but one held in
a container would need a copy, so the check refuses it (`fvaRefuseNested`, DECISIONS "A function
value at another function type is adapted where it is delivered"). For a function of open
parameters held in a record (D15198, `fvaHeldHoleFnDiffers`) the refusal ran only where the
delivered value is itself a record, so a list of such records reached the emitter unconverted,
and the call through the wider type trapped.
