### D2374 — `parentLetOf`'s single-entry cache can serve a function body's plan from before a later rewrite grew it

**check-clean invalid wasm · filed 2026-09-25 against master `d5a30be9e`**

Repro:

    type Node = { v: i32, left: Node | null }
    function insert(n: Node, v: i32) {
      if n.left == null { n.left = { v: v, left: null } } else { insert(n.left, v) }
    }
    const root: Node = { v: 5, left: null }
    insert(root, 3)
    print(1)
    // vl check: rc 0.  vl run: invalid module inside `insert`:
    //   type mismatch: expected i32, found (ref $type)

#### Mechanism

`parentLetOfAt`/`parentLetOfSid` share one single-entry plan cache keyed only by `blockIx`
(`plCacheBlock`): a call rebuilds the plan when `blockIx != plCacheBlock`, else it reuses
whatever was last built for that exact `blockIx`. `dispatchRewrite`'s tail-spill mints a
fresh `LetDecl` inside a function's own body (`insert`'s recursive-call arm) to hold the
assignment's yielded value. If an earlier `parentLetOfAt(insert's body, ...)` call already
cached `insert`'s plan (built before the spill ran), and nothing asks about a *different*
`blockIx` in between, a later query for the spilled name reads the stale, pre-spill plan —
answering `-1` for a binding that now exists — rather than rebuilding. This was found via a
D2326 perf fix: the fix's new fast path answers a module-scope query without visiting any
function body, and (correctly) never evicts `plCacheBlock`, which exposed that a query
*must not assume* a same-`blockIx` cache hit reflects the current arena.

#### Ablation

| ingredient removed | outcome | needed? |
| --- | --- | --- |
| the recursive `else` arm | runs, prints `1` | **yes** |
| a declared result, `function insert(n: Node, v: i32): void` | runs | **yes** |
| a query for a *different* `blockIx` between the tail-spill and the failing read | runs | **yes** (forces the eviction that hides this) |

#### Grading list

Any caller of `parentLetOfAt`/`parentLetOfSid` for a function body whose plan a rewrite
minted a new binding into *after* an earlier query already cached it, with no intervening
query for a different `blockIx` to force a rebuild.
