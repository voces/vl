### D16319 — a radix literal beside an `if` or `match` of integer constants, at an `i64` destination, computes at `i32`

**closed · runs, prints `4294967302` · was check-clean silently wrong · clause 1 · bucket (f) · 3 DISAGREE verdicts of the 2026-11-15 oracle-fuzz triage (`ar_s10_0105`, `ar_s45_0161`, `ar_s40_0145`) · filed 2026-11-15 against master `3d526470a` · closed 2026-11-15 on master `5683d3b2c` by lane N: a value `if`, `match` or block whose every tail is a tree of literals is a constant of the literal tree it stands in (`litTreeOps`, check_num_lits.vl), built at the tree's width with its spine and parentheses (`litTreeAdopt`, check_num_adopt.vl) · fixture `literals/radix-tree-beside-constant-join-at-destination.vl` · matrices `radix-plus-const-if-at-i64` and `-paren-` 22 annotated cells WRONG → RUNS each**

Repro:

    let c = true
    const v: i64 = 0xFFFFFFFF + if c { 7 } else { 5 }
    print(v)
    // PRINTS 6

Want:

    4294967302

#### Mechanism

An `if` whose tails are all constants takes the destination its literals adopt (D16373), so
beside a decimal peer the join is `i64` and the sum is exact. Beside a radix peer it is not: the
pattern's width is left to its use, the join keeps its arms' default `i32`, and the operation runs
at `i32`, so `0xFFFFFFFF` reads as `-1`. The result is then widened to the destination. Binding the
`if` to an `i64` first, or spelling the peer in decimal, gives the exact value.

#### Ablation

| spelling | outcome |
| --- | --- |
| the witness | prints `6` |
| `4294967295 + if c { 7 } else { 5 }` (decimal peer) | prints `4294967302` |
| `let x: i64 = if c { 7 } else { 5 }` then `0xFFFFFFFF + x` | prints `4294967302` |
| `0xFFFFFFFF * if c { 7 } else { 5 }` | prints `-7`, want `30064771065` |
| `0xFFFFFFFF + match k { 1 => 7, _ => 5 }` | prints `6` |
| `(if c { 1 } else { 0xFFFFFFFF }) * 0xFFFFFFFF` | prints `-1`, want `4294967295` |
| `print(0xFFFFFFFF + if c { 7 } else { 5 })` (no destination) | prints `6`, as an `i32` sum should |
