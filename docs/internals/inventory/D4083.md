### D4083 — a binding narrowed to a record by `is` stays narrowed after a write through an alias or a closure

**check-clean silently wrong value · clause 1 · found reviewing the D4058 close (#3549) · filed 2026-10-11 against master `5a9535c91`**

Repro:

    type A = { x: i32 }
    type B = { x: 1 | 2 }
    const a: A = { x: 1 }
    const al = a
    if a is B {
      al.x = 7
      const y: 1 | 2 = a.x
      print(y)
    }
    // vl check: rc 0.  vl run: rc 0
    // PRINTS 7

#### Mechanism

`if a is B` narrows the BINDING `a` to `B` for the then-arm, and a field read through it is
typed by `B`'s literal set. Nothing retires that narrowing when the record is written by
another route: an alias (`al.x = 7`), a closure that writes `a.x`, or a second parameter
holding the same record. A PATH narrowing already is retired by each of those (`if o.v is i32`
followed by `al.v = "s"` refuses the later read, the D2390(a) hook through
`callMayWrite` / `callInvalidatesNarrowedPath`); the binding-level narrowing to a record has
no such hook. Not introduced by D4058: with `a: A | B` declared, base prints 7 too.

#### Ablation

| variant | outcome |
| --- | --- |
| alias write `al.x = 7` (the repro) | prints 7 |
| a closure `const k = () => { a.x = 7 }` called in the arm | prints 7 |
| `function g(a: A, al: A)` called as `g(a, a)`, write through `al` | prints 7 |
| operand declared `a: A \| B`, alias or closure write | prints 7, on base too |
| no write in the arm | prints 1 |
| path narrowing `if o.v is i32`, alias write `al.v = "s"` | check reject, correct |

#### Grading list

Each ablation row's write must end the narrowing, so the `const y: 1 | 2 = a.x` read
refuses; the closure spelling and the two-parameter spelling separately. D4084 (the value
escaping as `B`) is a different mechanism and is not expected to fall out.
