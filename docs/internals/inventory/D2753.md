#### Mechanism

D2684's exact key gives the two pins two instances, but a record whose field is a Set and one
whose field is its boolean map share a variant row, so the tag compare answers `true` in both.
Anonymous records of the same field names share a row too, whatever their field types
(`{a: i32}` beside `{a: string}`). An exact instance knows the operand's type: where it holds a
twin of the pattern and not the pattern itself, the answer is `false` (`exactUnionLacksTwin`).
Two neighbours had the same hole. `id(u) is P` records no type in a generic body, so its exact
type is now the callee template's return with its bindings (`exactCallResultTyOf`). And `is Set<i32>[]` in a nested generic read the boolean map's element
slot; `isArmTagOfTy` now gives a list of Sets no tag, so it refuses as the direct spelling does.
