### D15365 — an element of a widened list of functions of different results, bound inside an un-annotated function and called, traps

**closed · runs, prints `1.5` · was trap after load, `vl check` rc 0, `wasm trap: indirect call type mismatch` · clause 1 · found closing [D15364](D15364.md) · filed 2026-11-04 against master `73062b831` · closed 2026-11-04: the per-instance mint reads a binding initialised by an element read of a parameter, and only ever called, as the callee chain it stands for (`elabElemCallAlias`, emit_elab.vl), so it marks the set's call and not the set partial, and the set is tagged · fixture `tests/cases/closures/widened-fn-list-element-bound-in-hole-fn-called-runs.vl`**

Repro:

    function inc0(a) { return a + 1 }
    function half(a) { return a / 2.0 }
    function run(xs) {
      const g = xs[1]
      print(g(3))
    }
    const xs = [inc0]
    xs.push(half)
    run(xs)

Want:

    1.5

#### Mechanism

The checker is right and the representation is not. Inside the instance, `g(3)` types `f64`, and
the call sees the set of both members (`liveSet`, 2 members, the same as the literal spelling
that runs). The emitted module differs in how it stores the list:

* called in place, `print(xs[1](3))`, the list holds the set's ids and the call dispatches on the
  id, `if (i32.eq …) call $inc0 else call $half`, joined to `f64`;
* bound first, `const g = xs[1]; g(3)`, the same list holds closures, and the call is a
  `call_indirect` at the first member's signature, `(i32) -> i32`, printed with `__print_i32__`.
  Reading `half`'s closure there is the trap.

So the set is left untagged when the body binds an element to a local before calling it, and the
closure path then lowers a set of two signatures at one.

The decline is in `ftScan` (check_fn_tag.vl), at the argument `xs` of `run(xs)`: the holder rule
`ftHoldCtxOk`. Its `Call` arm accepts a list handed to a hole parameter only while
`!mintSetPartial(s)`. A counter probe, validated on the in-place spelling that tags, reads:

| spelling | `ftDeclsOnly` | `mintSetPartial` | tagged |
| --- | --- | --- | --- |
| `print(xs[1](3))` in `run` | 1 | 0 | yes |
| `const g = xs[1]; print(g(3))` | 1 | 1 | no, traps |
| `const g = xs[0]; print(g(3))` | 1 | 1 | no, runs only because slot 0 is the first member's |

So the per-instance mint marks the set partial when an element is bound before its call, and that
fact (check_mint) is what leaves the set untagged.

The mint's walk reads a callee's element chain (`xs[1](3)`) as the holder's slot, and notes the
call on the set. A binding `g = xs[1]` read only as a callee is that chain under a name, so it now
takes the same two reads: the walk reads its initialiser as a callee chain, and the call through
`g` roots its fact at the element read. A binding that is written, or read other than as a callee,
keeps the old path. `xs[0]` bound now tags too, rather than running on the first member's closure.
