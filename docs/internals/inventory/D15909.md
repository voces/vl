### D15909 — a parameter holding a bundle handed on from inside a lambda in its function is refused by mono

**closed 2026-11-12, runs and prints `5` `2.5` · was loud emit reject · clause 2 · `emitProgram: monomorphize: unsupported argument type for \`b\` in a call to \`take\`` · found closing [D15902](D15902.md) · filed 2026-11-12 against master `96590b46` · closed in the elaboration: a parameter taking its record whole hands it on from a lambda nested in its function through lambdas alone, from each of that lambda's instances below the parameter's (`elabHandFromKeys`, in `elabParamHandsNote`, emit_elab.vl) · fixture `tests/cases/closures/hole-lambda-bundle-param-handed-on-from-a-lambda.vl` · still refused: a `const` copy of the parameter inside the lambda, filed as [D15911](D15911.md)**

Repro:

    function lap(f) {
      f(2.5)
      f(3)
      return f
    }
    function take(b) {
      print(b(4))
      print(b(1.5))
    }
    function fw(a) {
      const k = () => take(a)
      k()
    }
    fw(lap((a) => a + 1))

Want:

    5
    2.5

#### Mechanism

A parameter taking its record whole hands it on only from its own function's body
(`elabParamHandsNote` tests `elabEnclosingFn`); the lambda's call `take(a)` is the lambda
instance's, whose key is not the parameter's.
