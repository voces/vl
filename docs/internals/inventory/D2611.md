### D2611 — a value of a union of numeric types is accepted where one of its wider members is expected, and the box is passed as that number

**check-clean invalid wasm · clause 1 · filed 2026-09-26 against master `e289f84d7`, found by the
narrowed-write grid of D2609**

Repro:

    function useF(v: f64) { print(v * 2.0) }
    function src(): i32 | f64 { return 7 }
    useF(src())
    // vl check: rc 0.  vl run: the emitted module fails to validate (expected f64, found a ref)

#### Mechanism

A prediction. `assignable` accepts a union when every member is assignable, and `i32` widens to
`f64`, so `i32 | f64` is assignable to `f64`. No delivery position converts the value box: the
argument, the binding and the return pass the box where an `f64` is expected. The fix is a
lowering, not a ruling: unbox by tag and convert the `i32` payload (`f64.convert_i32_s`), which
is what the plain `i32` widening already does. A checker refusal would take away a program
the type rules admit.
