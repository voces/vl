### D6793 — a parameter copied into bindings of two type parameters, each called at another type, is refused at emit

**loud emit reject · `vl check` rc 0 · clause 2 · UNDECIDED: whether `b: F = a` with `a: G` may hold `a` at another instance than `G`'s is not settled · found closing [D6760](D6760.md) · filed 2026-10-18 against master `a921d55c7`**

Repro:

    function same<T>(k: T): T { k }
    function mid<F, G>(a: G) {
      let b: F = a
      let b2: G = a
      print(b("w"))
      print(b2(3))
    }
    mid(same)
    // vl check: rc 0.  vl run: emitProgram: monomorphize: parameter `a` of `mid` is called at two function types that no parameter per type separates

Want:

    w
    3

#### Mechanism

From the ablation only. `a` is annotated `G`, so the split keeps it one parameter, and its two
copies are called at `string` and `i32`. On master the copy into `F` was built at `G`'s instance
and the module failed to validate; the split now refuses it.
