### D8300 — `is` over a type parameter bound to a record literal is folded false where the tested record stores a field more widely

**check-clean silently wrong · prints `0` · clause 1 · open · present on master `82bf510a3` · found grading D8141's matrix, whose `early_return_guard` un-annotated cell prints `0` on both seeds · filed 2026-10-20 against master `82bf510a3`**

Repro:

    type J = { r: i32 | null, g: i32 }
    function gd<T>(v: T) {
      if v is J { print(v.r ?? 0) } else { print(0) }
    }
    gd({ r: 15, g: 1 })
    // vl run: 0

Want:

    15

#### Mechanism

The literal is built at `J`'s storage (in the disassembly, the instance's parameter is `J`'s
struct), but the instance's test is emitted as `(if (i32.const 0) ...)`. The receiver's type is
the literal's row `{ r: i32, g: i32 }`, which stores `r` as a flat `i32`, and the static answer
judges that row against `J` by storage rather than by value fit. The direct spelling
(`const o = { r: 15, g: 1 }; if o is J`) prints `15`. The fold is in `emitIsTest`
(wasmEmit.vl), outside lane L1's file boundary.
