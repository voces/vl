### D16143 — a call result's un-annotated function handed to a generic `(x: T) => i32` parameter whose `T` only the call's result type fixes is refused at emit

**closed 2026-11-15 by lane S (slot store stage 2b part 2b(i), #8292) · runs, prints `3` · was loud emit reject, clause 2, ``emitProgram: cannot take the generic function `inc` as a value — a function value carries ONE signature`` · the place classes bound a holder written in a generic at its place's instance, so `apt`'s `g: (x: T) => i32` at `T = i32` delivers `inc` at `(i32) => i32` (`eplRootK`, `eplBoundOf`, emit_elab.vl) · the grading list's annotated `inc` ran before and still runs · found closing [D16099](D16099.md) · filed 2026-11-14 against master `7cdda1fef`**

Repro:

    function inc(a) { return a + 1 }
    function pick1(_c: boolean) { return inc }
    function apt<T>(g: (x: T) => i32, v: T): T { return v }
    const q = apt(pick1(true), 3)
    print(q)
    // vl run: prints 3 (was the emit refusal above)

Want:

    3

#### Mechanism

Not ablated to a line. `apt` never calls `g`, so no call through it pins `inc`'s parameter. The
checker now types the call at `T = i32` (D16099), but the emitter takes `inc` as a closure
value with its parameter still open.

#### Ablation

| change | outcome |
| --- | --- |
| witness | emit reject |
| `apt` calls `g(v)` in its body | not graded |
| `const g = pick1(true); apt(g, 3)` | not graded |

#### Grading list

The witness with `inc` annotated `a: i32` (want `3`).
