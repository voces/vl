### D9721 — a list of a generic with one element written with a non-generic, the other element called at another type, refuses

**loud emit reject · `vl check` rc 0 · `a list holding a generic function is called through its elements at more than one type` · clause 2 · found closing [D9650](D9650.md) · present on master `4fce2a127` · filed 2026-10-22 against master `4fce2a127`**

Repro:

    function id<T>(x: T): T { x }
    function inc(x: i32): i32 { x + 1 }
    const xs = [id, id]
    xs[0] = inc
    print(xs[0](2))
    print(xs[1]("abc"))
    // vl check rc 0.  vl run: emit error: emitProgram: a list holding a generic function is called through its elements at more than one type, so its elements have no one instance — annotate the list's element type

Want:

    3
    abc

#### Mechanism

Not traced. The write declines `monoFlowReads`'s plan for the list (`monoFlowDeclClean`,
emit_mono.vl), the same tie that keeps [D9595](D9595.md) refused. So both elements reach
`monoPinListElems` as one slot pinned at `(i32) => i32` and at `(string) => string`. Running
it needs a slot that holds functions as values and calls each at the type of the call that
reaches it. Alternatively, the written element's type could be checked against each call
type that its index reaches.

| --- | --- | --- |

| the call at `string` (`xs[1](4)`) | runs | **yes** |
