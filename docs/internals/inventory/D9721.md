### D9721 — a list of a generic with one element written with a non-generic, the other element called at another type, refuses

**loud check reject · `cannot write 'inc' to an element of 'xs': a call through it at (string) runs it, and it is (i32) => i32` · DESIGN: a list has one element type, so the literal `[inc, id]` called through `xs[1]` at `string` refuses at check (`argument 1: expected i32, got string`), and so does a written element; graded on master `e811cd6da` · found closing [D9650](D9650.md) · present on master `4fce2a127` · filed 2026-10-22 against master `4fce2a127`, refused then by the emitter, `a list holding a generic function is called through its elements at more than one type`; a check reject since [D10120](D10120.md), which the same lines inside a function already were on master `17b0be5a8` (`cannot assign (i32) => i32 to (string) => string`), since an element write is judged at every call through the list, whichever index it names · matrix `fn-value-generic-list-written-fixed-other-element-at-string-refused` 0 of 46 runs, every position refused**

Repro:

    function id<T>(x: T): T { x }
    function inc(x: i32): i32 { x + 1 }
    const xs = [id, id]
    xs[0] = inc
    print(xs[0](2))
    print(xs[1]("abc"))
    // vl check: cannot write 'inc' to an element of 'xs': a call through it at (string) runs it, and it is (i32) => i32

#### Mechanism

A list's elements share one slot, and the hole-slot judge (`holeSlotFixedJudge`,
check_relate_core.vl) judges a written element at every call through that slot, whichever
index the call names. `inc` fixes the slot at `(i32) => i32`, so the call at `string` through
`xs[1]` is ill-typed, the same refusal the literal `[inc, id]` gets without any write, and the
one [D10202](D10202.md) keeps for a delivery. Running it would need a list whose elements have
different function types, which the language does not have.

#### Ablation

| ingredient removed | outcome | needed? |
| --- | --- | --- |
| the write `xs[0] = inc` | runs | **yes** |
| the call at `string` (`xs[1](4)`) | runs | **yes** |
| the write, with `inc` in the literal instead (`[inc, id]`) | refuses, `argument 1: expected i32, got string` | no |
