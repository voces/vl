### D9721 — a list of a generic with one element written with a non-generic, the other element called at another type, refuses

**loud check reject · `cannot write 'inc' to an element of 'xs': a call through it at (string) runs it, and it is (i32) => i32` · clause 2 · found closing [D9650](D9650.md) · present on master `4fce2a127` · filed 2026-10-22 against master `4fce2a127`, refused then by the emitter, `a list holding a generic function is called through its elements at more than one type`; a check reject since [D10120](D10120.md), which the same lines inside a function already were on master `17b0be5a8` (`cannot assign (i32) => i32 to (string) => string`), since an element write is judged at every call through the list, whichever index it names**

Repro:

    function id<T>(x: T): T { x }
    function inc(x: i32): i32 { x + 1 }
    const xs = [id, id]
    xs[0] = inc
    print(xs[0](2))
    print(xs[1]("abc"))
    // vl check: cannot write 'inc' to an element of 'xs': a call through it at (string) runs it, and it is (i32) => i32

Want:

    3
    abc

#### Mechanism

Not traced. The write declines `monoFlowReads`'s plan for the list (`monoFlowDeclClean`,
emit_mono.vl), the same tie that keeps [D9595](D9595.md) refused. So both elements reach
`monoPinListElems` as one slot pinned at `(i32) => i32` and at `(string) => string`. Running
it needs a slot that holds functions as values and calls each at the type of the call that
reaches it. Alternatively, the written element's type could be checked against each call
type that its index reaches.
