### D14494 — a list literal of fresh calls into a union-element list builds at the record's list when that list exists elsewhere

**closed 2026-10-27 · runs today and must keep running · fixed: the checker records the destination of a record-element list literal (`ulLitN` counts it, so `ulTaken` is kept), and `arrLitBuild` builds a literal whose destination boxes its elements at that destination's list · was check-clean invalid wasm · clause 1 · filed 2026-10-27 against master `1558e9ab0` · pin: `tests/cases/soundness/fresh-call-list-into-union-element-list.vl`**

Repro:

    type R = { v: f64 }
    function mk3() { { v: 7 } }
    function main() {
      const ys: R[] = [{ v: 1.5 }]
      print(ys[0].v)
      const xs: (R | string)[] = [mk3(), mk3()]
      const a = xs[1]
      if a is R { print(a.v / 2) }
    }
    main()
    // vl check: rc 0.  vl run: invalid module, the `R[]` list stored into the `(R | string)[]` local

Want:

    1.5
    3.5

#### Mechanism

The checker types `[mk3(), mk3()]` as `R[]`. `arrLitBuild` asked `listBuildOfTy` of that type
first, and it names a row only when some other `R[]` list was collected, so the build depended
on what else the program holds. The destination `(R | string)[]` was not recorded for this
literal, because the checker kept `ulTaken` only while some literal's own element was a union.
`arrLitBuild` also kept the caller's build pair when `recBuildRowOf` answered for the first
element, which is a question about an object literal and was being asked of a call.
