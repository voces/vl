### D14911 — a narrowed value read of a union-boxed map's cell was stored as `litatom`

**closed 2026-11-01 by `idxReadIsLitAtom` refusing a map whose values are a value-union box · runs, prints `b` · was a wrong store answer no consumer acted on: `readIndexStoreKind` said `litatom` for `m["k"]` over `{[string]: i32 | AB}` narrowed to `AB | null`, while the cell is the union box and the emitter delivers the box · found by the error-channel lane's exprUnion flip, which built `expected i32, found (ref $union box)` when it believed the store · filed 2026-11-01 against master `9d1d7374`**

Repro:

    type AB = "a" | "b"
    const w: { [string]: i32 | AB } = Map()
    w["k"] = "b"
    if w["k"] != null {
      if w["k"] is i32 { print(0) } else { print(w["k"]) }
    }

Want:

    b

#### Mechanism

`idxReadIsLitAtom` claims an atom from the read's TYPE (`nodeRepIsAtom` / `nodeRepIsNulAtom`),
and a narrowing out of a union-boxed map value leaves that type a literal union. The array
receiver already declined a box element (D4201); a map receiver had no such rung, so the store
column (`readStoreOf`) said `litatom` for a cell holding the box. The rung added reads the map's
value type: a value-union box there is the store, whatever arm the read is narrowed to.
