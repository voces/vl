### D14742 — a recursive union alias cannot share the row its expansion registered, because its lists are registered under the alias's name

**closed 2026-11-11 — the witness prints `3` and `2` · was a refutation pin, runs today and must keep running · a recursive alias with list or map arms now binds to its expansion's row, its arms registered off the row's type (`collectDeclaredUnion`) · found deduping union rows by type key (#5364) · filed 2026-10-31 against master `5065c850`**

Repro:

    import { Json, parseJson } from "std:json"
    const r = parseJson("[1, [2, 3], {\"a\": true}]")
    if r is Json[] {
      print(r.length)
      const inner = r[1]
      if inner is Json[] { print(inner.length) }
    }

Want:

    3
    2

#### Mechanism

`std:json`'s `Json` is `null | boolean | f64 | string | Json[] | { [string]: Json }`. Its
expansion is registered as an inline row before the declaration is collected, with the same
type key, and no variants. Binding the name `Json` to that row skips `collectDeclaredUnion`'s
own registration, which is where the `Json[]` ref-list row and the map arm are interned under
the alias's name. The `is Json[]` read then finds no list row and refuses. So an alias binds only
when it holds no list, map or function arm, and the 31 corpus files with a recursive alias beside its
expansion keep two rows of one type until those arms register off the row's type.
