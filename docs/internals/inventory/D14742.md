### D14742 — a lone-literal record field is stored as the atom while its type reps as a string

**runs today and must keep running · step 5 `ctxTy` field decline · filed 2026-11-01 against master `5b24d58b`**

Repro:

    type C = { kind: "circle", r: i32 }
    const c: C = { kind: "circle", r: 1 }
    print(c.kind)
    const k: "circle" = "circle"
    print(k)

Want:

    circle
    circle

#### Mechanism

The record row stores a field typed by one string literal as its one-member set's i32 atom
(D7446), while the checker types the field as the bare literal, whose `repOfTy` is a string. A
`"circle"` binding stays a string. So a literal delivered to the field lowers as the atom only
because the delivery context says so, and a reader asking `repOfTy` of the field's contextual
type gets the string. `ctxFieldStorageAgrees` declines every record field until this agrees. The
proposed fix is a type fix: the checker types a lone-literal field as its one-member set.
