### D16462 — a recursive function with no declared result that returns an `if` reads its result from the join, not the arms

**closed 2026-11-15 · runs, prints `3` · was loud emit reject, clause 2 (`field access receiver is not a struct`), and check-clean invalid wasm, clause 1, when the result is unused · fixed in `a20RetWalkGo` (`check_nj_gate.vl`), which walks a returned value as a tail · fixture `tests/cases/conditionals/return-if-lowers-as-tail-if.vl` · found by lane D's return-rule migration · filed 2026-11-15 against master `41739762`**

Repro:

    type Node = { v: i32, left: Node | null }
    function ins(n: Node, v: i32) {
      return if n.left == null { n.left = { v: v, left: null } } else { ins(n.left, v) }
    }
    const r: Node = { v: 1, left: null }
    print(ins(r, 3).v)

Want:

    3

#### Mechanism

`collectRetValues` (`a20RetWalk`) lists the values a body yields: each arm of a tail `if`, but a
returned expression whole. A returned `if` was one value, so the result recorded for an
un-annotated function was the join's type, which for a recursive arm and a field write is not
the record the arms deliver; the tail spelling's arms gave the right one. A returned value is now
walked as a tail, so a returned `if` lists its arms.
