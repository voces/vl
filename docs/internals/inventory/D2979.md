### D2979 — an un-annotated record literal of a defaulted literal takes an unrelated `f32` record's row, and its `i32` read is invalid wasm

**check-clean invalid wasm · open · found by the #3249 review grid · filed 2026-09-28 against master `264fd86f1`**

Repro:

    type R32 = { v: f32 }
    function ti(a: i32): i32 { a }
    const B = 3
    const q = { v: B }
    print(ti(q.v))
    // vl check: rc 0.  vl run: invalid module — type mismatch: expected i32, found f32

#### Mechanism

`q` is checked as `{v: i32}`, so `ti(q.v)` checks. The emitter builds the literal at the declared
record whose field set matches by name, `R32`, although nothing hands `q` to it, so `q.v` is read
as an `f32` into an `i32` parameter. The defect is the record-row choice for an un-annotated
literal; the literal binding is scenery (a bare `{ v: 3 }` fails the same way).

#### Ablation

| ingredient removed | outcome | needed? |
| --- | --- | --- |
| `type R32` | runs, prints 3 | **yes** |
| the binding `B` (`const q = { v: 3 }`) | invalid module, same message | no |
| the `i32` read (`print(q.v)`) | runs, prints 3 | **yes** |
| `f32` field for `f64` (`type R64 = { v: f64 }`) | runs, prints 3 | **yes** |
