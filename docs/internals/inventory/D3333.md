### D3333 — a join of two un-annotated parameters collapses to the first, so an instance binding them apart reads the second as the first

**check-clean silently wrong · clause 1 · open, needs the ruling D3303 asks for · the same on master `b6378e95b` · found by the lane JW grid (the `hole` spelling of every two- and three-parameter join: 2,809 of its 8,232 hole cells fail on master, invalid wasm or a wrong value) · filed 2026-09-30**

Repro:

    function g(a0, a1, k: i32) {
      const r = if k == 0 { a0 } else { a1 }
      print(r)
    }
    g(true, 4, 0)
    g(true, 4, 1)
    // today it prints true true

Want:

    true
    4

#### Mechanism

`joinTys` folds one inference hole into another (a hole is assignable either way), and D2760
kept that collapse for holes on purpose ("a hole is inference"), so `r` is typed `?a0`. Each
call pins `?a0` and `?a1` apart, and the instance stores the second arm in the first's cell:
`4` read as a boolean prints `true`, and at `i32` and `string` the string arm is invalid wasm.
The declared spelling `g<A, B>` prints `true 4`, and this lane parts two bare declared
parameters in the checker too (D3268). Parting two holes the same way is the question D3303 parks: whether an un-annotated
parameter is gradual as ruling (A) makes a declared one.
