### D3333 — a join of two un-annotated parameters collapses to the first, so an instance binding them apart reads the second as the first

**closed 2026-09-30 · was check-clean silently wrong, clause 1, on master `6e6a5301b` (`true true`) · found by the lane JW grid (the `hole` spelling of every two- and three-parameter join) · closed by lane UG under the D3303 ruling: a parameter's hole is an implicit type parameter · fixture `tests/cases/generics/hole-join-two-params-part.vl`**

Repro:

    function g(a0, a1, k: i32) {
      const r = if k == 0 { a0 } else { a1 }
      print(r)
    }
    g(true, 4, 0)
    g(true, 4, 1)

Want:

    true
    4

#### Mechanism

`joinTys` folds one inference hole into another (a hole is assignable either way), and D2760
kept that collapse for holes on purpose ("a hole is inference"), so `r` is typed `?a0`. Each
call pins `?a0` and `?a1` apart, and the instance stores the second arm in the first's cell:
`4` read as a boolean prints `true`, and at `i32` and `string` the string arm is invalid wasm.
The declared spelling `g<A, B>` prints `true 4`.

The close: a named function's parameter hole (`tyIsNamedParamHole`) is gradual as a declared
parameter is, in the body declaring it: `tpOpenJoin` and `tyParamBesideBare` keep it apart from
another hole, a concrete type or a null, and `holeTpJoinNames` records it. An instance of a
function whose join names such a hole walks its body with the holes' binding joined to its
parameters' (`monoMakeInstance`), so the join re-joins at the pin, and an inferred return of the
join is read through the same binding (`monoHoleRetSubst`). Lambda bodies and their deferred
returns keep master's collapse (D3358).
