### D3957 — a parameter named like a function seeds a written capture cell, and the call after the write traps

**closed 2026-10-13 by lane SC · runs · was loads then traps · pins: `tests/cases/closures/written-let-seeded-from-parameter-written-with-generic.vl`, `tests/cases/closures/capture-cell-annotated-written-with-generic-by-shared-closure.vl` · found in review of #3498 (`rv3498/round4/d07`, `d15`) · filed 2026-10-10 against master `429e7b093`**

Repro:

    function other<V>(v: V) { print("O"); print(v) }
    function third<Z>(z: Z) { print("T"); print(z) }
    function a<T>(x: T, inner: (t: T) => void) {
      let k = inner
      const w = () => { k = other }
      k(x)
      w()
      k(x)
    }
    a(1, third)
    // vl check: rc 0.  vl run: prints T 1, then wasm trap: indirect call type mismatch

Want:

    T
    1
    O
    1

#### Mechanism

A capture cell's element store `k[0] = other` recorded its delivery but never instanced the
written generic, and a call through the cell, whose rewritten callee `k[0]` has no recorded type,
took no type at all; each instance of the enclosing generic needs `other` at the cell's type as
that instance spells it. Closed by lane SC (fn-value-flow §(f) step 3): `monoWalk`'s Index arm
coerces the stored value at the element's type, and `monoCellCall` reads the cell's type at the
instance's bindings (`monoCellFnTyNameAt`). Either change alone closes this witness;
removing both restores the trap. The no-capture spelling needed a third: an un-annotated `let`'s
write is coerced at the binding's own type at the instance (`monoWalk`'s Ident arm). The annotated
spelling written through `w` needed a fourth: `monoCoerceLetValues` takes an annotated cell in a
generic function's frame.
