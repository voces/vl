### D3957 — a parameter named like a function seeds a written capture cell, and the call after the write traps

**loads then traps · found in review of #3498 (`rv3498/round4/d07`, `d15`) · filed 2026-10-10 against master `429e7b093`**

Repro:

    function other<V>(v: V) { print("O"); print(v) }
    function third<Z>(z: Z) { print("T"); print(z) }
    function a<T>(x: T, inner: (t: T) => void) {
      let k = inner
      const w = () => { k = other }
      k(x)
      w()
      k(x)
    }
    a(1, third)
    // vl check: rc 0.  vl run: prints T 1, then wasm trap: indirect call type mismatch

Want:

    T
    1
    O
    1

#### Mechanism

Not located, and not a naming defect: re-graded 2026-10-13 (lane SC, step 2) it traps with the
parameter renamed `g` and with no capture cell at all (`let k = g; k(x); k = other; k(x)`), on
master and on step 2 alike. A `let` seeded from a function-typed parameter and then written with a
generic is called after the write at the seed's instance. Seeded from a named function, or
annotated, it runs. That is fn-value-flow §(f) step 3 (let / written), not step 2.
