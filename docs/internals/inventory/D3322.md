### D3322 — a default naming a module `const` declared below its function is accepted or refused by where the first call stands, and the refusal says it is not a module `const`

**loud check reject · clause 2, with a false message: `K` IS a module-level `const` · on master `e70102886` every spelling is refused; on #3296 head `fcb70b50e` a first call in a `const` initializer (`const r = f(); print(r)`) prints `5` · found in the #3296 round-4 review · filed 2026-09-29 against #3296 head `fcb70b50e`**

Repro:

    function f(x: i32 = K): i32 { x }
    const K = 5
    print(f())
    // vl check: rc 1, "a default value must be a literal, a module-level `const`, or
    // `__callsite__` — `x`'s default is substituted at each call site, so it cannot name a
    // parameter, a local, or a call".  Expected: 5

Want:

    5

`f(7)` in place of `f()` is refused the same way; `const r = f()` then `print(r)` prints `5`.

#### Mechanism

A prediction until a close confirms it. The default's legality test (`paramDefaultIsLiteral`)
accepts a bare name only when `isModuleScopeConst` already answers yes for it, so its answer
depends on whether the checker has reached `const K` by the time a call first makes it validate
`f`'s defaults. A call inside a `const` initializer is checked after the declaration's row is in
place; a call in a statement is checked before it, and the refusal then names a rule the
program keeps.

#### Ablation

| ingredient changed | outcome | needed? |
| --- | --- | --- |
| `const K = 5` above the function | runs, `5` | **yes** (the order) |
| `const r = f()` then `print(r)` | runs, `5` | **yes** (where the first call stands) |
| `f(7)` instead of `f()` | still refused | no |
