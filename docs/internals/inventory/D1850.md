### D1850 — an un-annotated binding of a spread literal over a `u8[]` binds the i32 cell, so the packed byte wrapper lands in the wrong slot

**loud check reject · filed 2026-09-06 against master `180d67365`**

Repro:

    const b: u8[] = [1, 2]
    const c = [...b]
    print(c.length)

#### Mechanism

`u8[]` is the one list whose ELEMENT does not identify its rep: its backing is
`(array (mut i8))` where every other i32-element list is `(array (mut i32))`, which is why
`letIsU8Array` is documented annotation-only. `emitArrSpread` resolves a spread literal's rep
from the spread's SOURCE, so it correctly builds the packed wrapper — but the binding's own
cell is chosen by the classifier ladder, whose u8 arm is reached only through an annotation,
so an un-annotated `const c = [...b]` takes the i32 cell and the `global.set` is invalid wasm
(`expected (ref null $type), found (ref $type)`, both names elided).

Teaching `exprU8Array` and `exprArray` to answer from `spreadDestKind` was tried and does not
move it, so the cell is decided somewhere those two do not reach — that is the thing to find.
Until then the spread is refused in the checker at EVERY spelling, annotated included, so no
program can reach the emitter with one: `xs.slice(0)` builds the same fresh copy at every rep
and is what the refusal names.

#### Ablation

| ingredient removed | outcome | needed? |
| --- | --- | --- |
| the `u8` element (an `i32[]` source instead) | runs | **yes** |
| the annotation on `b` | `b` is no longer a `u8[]`, so the row evaporates | **yes** |
| the spread (`const c = b`) | runs | **yes** |

#### Grading list

The annotated destination (`const c: u8[] = [...b]`) built correctly before the refusal
landed and must run again when this closes. Every other element rep — `i32`, `i64`, `f64`,
`f32`, `string`, and a struct ref list — must keep running un-annotated: they are
`tests/cases/lists/spread-list-literal-elem-reps.vl`, and they are what says this row is the
`u8` cell and not the spread lowering.
