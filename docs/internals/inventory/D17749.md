### D17749 — a lambda with an un-annotated parameter, called through an in-place list literal's element, is refused at emit

**closed 2026-11-27 by COV-UNION · runs, its witness prints its expected value · was a loud emit reject, `cannot yet lower this statement (indirect call)` · a call straight through an element of a list literal written in place types each open element at the call's closed argument types (`monoInlineListCallAt`, emit_mono.vl), so the callee has one closure signature · pinned by `tests/cases/closures/hole-fn-list-literal-element-called-in-place.vl`**

Repro:

    const f = (a) => a + 1
    print([f][0](3))
    // vl check: rc 0.  vl run: emit error (indirect call) at 1:7

Want:

    4

#### Mechanism

The checker leaves the literal's element type `(_) => _`. A bound list (`const xs = [f]; xs[0](3)`)
is pinned from its slot's calls (`monoPinListElems`); the pass over calls through list elements
(`monoOpenCallAtElems`) reads only function arguments. An in-place literal has no slot, so the
callee keeps a holed type and `cloCallSigKey` finds no signature. A named generic member (`inc0`)
reaches the same refusal once its set is not tagged (COV-CLOS-3's F-C).

#### Ablation

| ingredient removed | outcome | needed? |
| --- | --- | --- |
| the literal, named first (`const xs = [f]; xs[0](3)`) | runs | **yes** |
| `(a)` annotated `(a: i32)` | runs | **yes** |
| a capture added (`a + k`, `k` a `let` written later) | refused | no |
| the call through the list, `f(3)` | runs | **yes** |
| the list read as a field, `{ g: f }.g(3)` | runs | **yes** |
