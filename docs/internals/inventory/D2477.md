### D2477 — a `self`-function over a map or a set is unreachable: `m.name(…)` refuses every name the map arm does not own

**closed 2026-09-25 — the witness prints `30` · was a loud check reject (`unknown property`), clause 2 · filed 2026-09-25 against master `0a0d24ac9` while grading [D2475](D2475.md) · fixtures `tests/cases/maps/self-fn-on-map-receiver.vl`, `tests/cases/methods/self-fn-not-shadowed-controls.vl`**

Repro:

    function total(self: {[string]: i32}) {
      let t = 0
      for k in self.keys() { t = t + (self[k] ?? 0) }
      t
    }
    const m: {[string]: i32} = Map()
    m["a"] = 10
    m["b"] = 20
    print(m.total())
    // vl check, filed: unknown property `total` on {[string]: i32}.  Now prints 30.

#### Mechanism

`checkMemberCallNode`'s map arm ends in `unknown property` for any name it does not own. The
list and string arms ask `ufcsCallTy` first, and so does the general arm; the map arm alone
never did, so no `self`-function over a `{[K]: V}` or a `Set<T>` could be called as a method,
while `total(m)` ran. The emitter's rewrite already dispatched map receivers, so the fix is
the one missing rung in the checker, banked like the others ([D2476](D2476.md)). A name a map
owns and a set does not (`get`, `set`) now reaches a function on a `Set` receiver, and `add` on
a boolean-valued map reaches a function before the "`.add` is a `Set` method" hint fires.

#### Ablation

| ingredient removed | outcome | needed? |
| --- | --- | --- |
| the map receiver (`self: string[]`, list receiver) | runs | **yes** |
| the method spelling (`total(m)`) | runs | **yes** |
| a set instead of a map (`Set<i32>`, `s.total()`) | same refusal | no |

#### Grading list

`s.get(1)` and `s.set(4, 5)` on a `Set<i32>` with `get`/`set(self: Set<i32>, …)` declared (reach
the functions, and D1522's index fold must not fire); `b.get(4)` on a `{[i32]: boolean}` map
(stays the built-in read); `b.add(5)` with `add(self: {[i32]: boolean}, …)` (reaches it).
