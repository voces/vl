**closed · the narrowed-arm rungs ask whether the initializer is a walk variable over box elements by the loop enclosing the read, which a capture's classifier can see without the frame's locals · fixture `tests/cases/closures/capture-narrowed-box-copy.vl` · was check-clean invalid wasm · clause 1 · found by lane NB's position grid (`nulrec__bind_un_capt__walk`) and the #3279 review · the same on master `a29230611` · filed 2026-09-28 against master `a29230611`, closed 2026-09-29 against master `07d414042`**

#### Mechanism

`letInitTyIsNarrowedNulArm` gates the `nulvariant` cell on the initializer being the box, and
asked `exprUnion`, whose loop-variable answer reads the live local table. The env field is typed
in the type section, where no frame's locals are registered, so `c` got an `i32` field while the
frame gave it the `nulvariant` cell. `letInitIsBox` (`emit_classify.vl`) adds `readIsLoopBox`:
the `for-in` loop enclosing the read, in the frame or at module scope, whose element kind is the
box. It declines when the frame also binds the name with a `let`. The arm, `nulvariant` and
literal-union rungs all ask it.

#### Ablation

| ingredient changed | outcome | needed? |
| --- | --- | --- |
| `print(show(c))`, no closure | runs | **yes** (the capture) |

| `e` a parameter `Circle \| null \| string`, not a walk variable | runs | **yes** (the walk) |
| the loop inside a function | invalid module inside the enclosing function, `expected i32, found (ref null $type)` | no |
