**check-clean invalid wasm · `vl check` rc 0 · clause 1 · filed 2026-09-08, surfaced by D1933's fix (a field-source capture chain now emits, so its name-collision fragility is reachable) · remedy named, deferred to a future `(name, frame)` sweep**

#### Mechanism

A field-source binding (`held = box.it`) is classified `nulstruct` — the field's storage is
`(ref null $S)` (D1476/D1759), so its read-back is nullable and `v = get()` reps nullable while
the checker types `v` non-null. The read `v.m` needs `ref.as_non_null`, gated on
`exprNullableStruct(v)`. Under a duplicate block-local name (both blocks bind `srcBox`/`held`/
`get`/`v`), `letInitCellKind(v = get())` resolves the closure-return chain `get → held → srcBox`
by BARE NAME; the collision flips `exprNullableStruct(get())` to non-nullable, so `v`'s cell is
committed `struct` at COLLECT time (instrument: `flat=struct live=struct` under collision vs
`nulstruct` alone). The read then reads that `struct` cell, skips recovery, and the nullable
value fails validation. It is a `(name, frame)`-keying fragility (the #2629 class), NOT the
classification disagreeing with the checker — that disagreement is present and HARMLESS with
unique names.
