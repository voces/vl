### D15760 — a let union spelled in another member order misses its row at the one-list sites and stores its init unboxed

**runs today and must keep running · refutation pin for spelling `monoSubstLetType` by the naming rule · filed 2026-11-12 against master `078abd54`**

Repro:

    type Circle = { r: i32 }
    function tag<T>(v: T): string {
      const aw: i32 | string | T = v
      if aw is string { return "\"" + aw + "\"" }
      "o"
    }
    const c: Circle = { r: 3 }
    print(tag(c))
    print(tag("hi"))

Want:

    o
    "hi"

#### Mechanism

Under the refused change, this program builds an invalid module. The change: emit_mono's
`monoSubstLetType` spells the instance's let annotation `monoPinSpellShaped(sty)`
(`Circle|i32|string`) in place of the substitution (`i32|string|Circle`).

One row is minted, under the rule's spelling. The let's box decision (`emitLetDecl`, via
`isUNameAnnAB(27)` and `(28)`) asks the softened key (`unRowOfSoftKey`). That key comes from
canon's render, which keeps member order, so the type `{r:i32}|i32|string` keys apart from the
row. The binding takes no box, and its init is stored raw: "expected (ref $4) `union box`,
found (ref $5) `Circle`". A union is a set (D1712), so the row is the row of every order.
