### D15654 — a join whose every arm is a call of a maker an annotated binding builds wider is typed at the maker's own record row when one is declared

**check-clean invalid wasm · clause 1 · `the emitted module failed to validate inside the module's top-level code: … type mismatch: expected (ref $1), found (ref $0); $1 is \`{f:i32}\`, struct {mut i32}; $0 is \`J\`, struct {mut (ref $3)}` · found closing D15653 · filed 2026-11-10 against master `e7ebdb52`**

Repro:

    type J = { f: i32 | null }
    type K = { f: i32 }
    function mk2() { { f: 1 } }
    const dA: J = mk2()
    print(dA.f ?? 0)
    const k = 1
    const b = if k > 0 { mk2() } else { mk2() }
    print(b.f ?? 0)

Want:

    1
    1

#### Mechanism

Not ablated past the table. `mk2` is kept at `J`, so each arm's call hands over a `J`. With no
declared `{f: i32}` row the join and `b` are built at `J` and the program runs. Once any
annotation spells `{f: i32}` (an alias, a parameter, a binding), the join is typed at that row
and the arms do not fit it. The checker judges no arm: both arms store as the join, and the
join is the kept maker's own (`recArmLandsAt`, D15653).
