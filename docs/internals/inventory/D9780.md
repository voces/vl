### D9780 — a function value whose result is a nullable map has no token in the function-value ABI

**loud emit reject · `vl check` rc 0 · clause 2 · CAPABILITY: the same function at a non-nullable `{[string]: i32}` result runs, and a nullable list result runs · found closing [D9742](D9742.md) · present on master `60aaa08c0` and `260b24edd` · filed 2026-10-22 against master `60aaa08c0`**

Repro:

    function g(f: (x: i32) => {[string]: i32} | null): i32 { const m = f(1)

      m.length }

    // vl run: emitProgram: a function-value call has no interned signature — its result type `{[string]:i32}|null` has no representation in the function-value ABI

Want:

    1

#### Mechanism

Traced, not fixed. The function-value signature key is built from one result token per
result type (`retTokOfTy`, `sigRetTokOfTy`, emit_sig_tokens.vl), and a nullable map has none,
so the call site finds no interned `$fnsig` and `cloCallSigRejectWhat` (emit_closure_sites.vl)
refuses. A map is already a nullable reference, so the token can be the map's own. The
lambda spellings `(x: i32) => Map()` and `(x: i32) => null` now check against this slot
([D9742](D9742.md)) and reach this refusal too.
