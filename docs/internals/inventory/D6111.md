### D6111 — a generic handed to a written `let` lambda whose write calls it on its own result is refused at emit

**closed 2026-10-17 by lane L3 · runs, prints `4` · was a loud emit reject · clause 2 · `genFnHoleInstance` (`check_relate_core.vl`) now asks a call whose argument is the hole's own result again once the other calls have bound the generic, so the instance closes · pin: `tests/cases/functions/written-let-hole-lambda-generic-called-on-own-result.vl` · found closing [D5933](D5933.md) · filed 2026-10-17 against `f3ea6a58f`, the D5932 head**

Repro:

    function neg(a) { return 0 - a }
    let lap = (g, x) => x + 1
    lap = (g, x) => g(g(x))
    print(lap(neg, 4))
    // vl check: rc 0.  vl run: emitProgram: cannot take the generic function `neg` as a value

#### Mechanism

From the ablation only. The write's outer call passes `g`'s own result, which is still open
when the instance is read off the calls the write makes, so no instance is taken; the
single call `g(x)` runs (D5933), and a `const` lambda making the nested call runs.
