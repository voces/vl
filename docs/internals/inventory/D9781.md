### D9781 — a function value is refused at a function type whose result is its own result or `null`

**loud check reject · clause 2 · CAPABILITY: the same function declared to return `f64[] | null` runs, a lambda written directly at the slot runs ([D9742](D9742.md)), and a string literal union result is taken at `string` through an adapter ([D4351](D4351.md)) · found closing [D9742](D9742.md) · present on master `60aaa08c0` and `260b24edd` · filed 2026-10-22 against master `60aaa08c0`**

Repro:

    function n(x: i32): f64[] { return [1.5, 2.5] }
    const v: (x: i32) => f64[] | null = n
    const r = v(1)
    if r != null { print(r[0] + r[1]) }
    // vl check: cannot assign (i32) => f64[] to 'v' of type (x: i32) => f64[] | null

Want:

    4

#### Mechanism

Traced, not fixed. `fnSlotAssignable` (check_relate_core.vl) refuses a function-slot result
whose rep differs from the slot's, and `f64[]` and `f64[] | null` lower to different reps, so a
function value that already has its type cannot be delivered. A lambda written at the slot
avoids it by taking the slot's result as its own, which a value with a fixed type cannot.
Running it needs a result-widening adapter at the delivery, as [D4351](D4351.md)'s atom result
has. The capability matrices reach it at `return_inferred`, where
`function __deliver() { return (x: i32) => … }` fixes the lambda's type before the binding;
for a `Map()` result the type it fixes holds a hole and the refusal is the emitter's map value
slot instead.

#### Ablation

| ingredient removed | outcome | needed? |
| --- | --- | --- |
| the result's widening (`function n(x: i32): f64[] \| null`) | runs, `4` | **yes** |
| the named function (`function d() { return (x: i32) => [1.5, 2.5] }`, `const v: … = d()`) | still refuses | no |
| the binding (the lambda written directly at `v`) | runs, `4` | **yes** |

#### Grading list

`return_inferred` in the matrices `fn-value-lambda-result-{f64,string,record}-list-nullable`,
`-map`, and the scalar controls `-i32-nullable` and `-string-nullable`, which refuse the same way;
a `string[]` and an `R[]` result; the argument position, `g(n)` for
`g(f: (x: i32) => f64[] | null)`.
