### D15322 — a call through a narrowed record field holding a function is taken to write every narrowed place

**closed 2026-11-04 by this PR (lane bundle) — the repro now RUNS and prints the Want below: a call through a field of a `let` binding is charged the functions stored in that field (`callFnValueDecls`). Was: loud check reject · clause 2 (`'r.f' was narrowed by a guard, but the call to 'f' on line 4 can write it — re-test 'r.f' after the call`) · the field-callee twin of [D15148](D15148.md) · filed 2026-11-04 against master `bf39d33f0`**

Repro:

    type R = { f: ((a: i32) => i32) | null }
    const r: R = { f: (a: i32) => a + 1 }
    if r.f != null {
      if r.f(4) == 5 {
        print(r.f(4))
      }
    }

Want:

    5

#### Mechanism

`callDeclFnIx` answers a struct field holding a function as opaque (`memberCalleeKind`), and an
opaque callee retires every live narrowing. D15148 charged an index callee the functions stored in
its slot (`callFnValueDecls`, `cwPathFnTargets`); a `Member` callee now asks the same of the
field (binding, [field]). A set holding a value that is not a known function, or a field with no
known store, stays opaque, and so does a field of a parameter, whose stores the scan does not see.

#### Ablation

| spelling | outcome |
| --- | --- |
| the field not narrowed (`{ f: (a: i32) => a + 1 }`, no guard) | runs |
| `r` a parameter, `function show(r: R)` | the same refusal, before and after the fix |
| a narrowed sibling `r.g: string \| null` read after `r.f(4)` | refused: `'r.g' is no longer narrowed to string: the call to 'f' on line 4 may reassign it` |
