### D1522 — a BARE map `.get(k)` has no value-position lowering, only the `??`-fused one

**loud emit reject · clause 2 · reported by the `~/glean` WC3 replay player as **VL-003**, VL's first external consumer, at their pin `2fb8b271` · filed against master `bd500845` · ZERO corpus cells**

Repro:

    const m = Map()
    m.set("a", 1)
    print(m.get("a"))
    // vl check: rc 0.  vl run: emitProgram: callee is not a function name

#### Mechanism

`.get` on a map is a DESIGNED builtin, not UFCS: the checker's `TyMap` member arm admits
exactly `set`/`get`/`has`/`delete`/`keys`/`values` and types `m.get(k)` as `V | null`
(`docs/guide/collections-design.md` §C2.1, and `Map[k]` returning an optional at §"indexing").
Every one of those but `get` has an emit arm. `get` lowers only when it is FUSED with `??`
(`emitMapGetOr`, the same path `m[k] ?? d` takes), so a bare one falls out of the member
ladder into `emitCall`'s UFCS fallback, which looks for a free `self`-function named `get`,
finds none, and reports `callee is not a function name` — a sentence about UFCS on a call
that was never UFCS. `ROADMAP.md` B6a already names the gap; no row carried it.

The refusal is therefore not about the un-annotated `Map()` the consumer suspected: the
ANNOTATED spelling refuses identically, and it is the missing `??` that decides.

#### Grading list

Every delivery position for the bare `.get`, not just `print`: binding, return, argument,
struct field, element, global init — the value is a `V | null` box and each position has to
receive it. Both key reps (string and i32) and a non-`i32` value rep.
