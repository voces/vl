### D15521 — a const copy of a written let is rewritten to the let's initialiser, not the value it holds when copied

**runs today and must keep running · a REFUTATION PIN for option B′ of the `monoFlow*` rewrite (the elaboration's answer admitted where the walkers decline, refused 2026-11-06) · filed 2026-11-06 against master `6c59497a`**

Repro:

    function id(a) { return a }
    function apply5(g) { return g(5) }
    function apply1(g) { return g(1) + 1 }
    let lap2 = apply1
    lap2 = apply5
    const k3 = lap2
    print(k3(id))

Want:

    5

#### Mechanism

`k3` is a `const` and nothing writes it, so B′'s fixed-value gate passes. That gate checks only the read's own root. The elaboration's set for `k3` comes from the fn tags on its type, and those carry `lap2`'s initialiser (`apply1`), not the `lap2 = apply5` write. So the read is renamed to `apply1` and prints 2. This is a flow-sensitive fact (the value at the copy) that the elaboration does not have. A twice-written map key copied out (`b["k"] = …; b["k"] = …; const br = b["k"]`) is the same mechanism.
