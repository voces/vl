### D4153 — the `.map((x): J => x)` copy the container rule offers for `J[][]` to `J[]` fails at emit

**closed 2026-10-23 by lane D1 · runs · was loud emit reject (clause 2, `vl check` rc 0) · filed 2026-10-11 against master `66f24dbe6` · found by #3563's review (probe `h14`) · sibling of [D2193](D2193.md) · pins: `tests/cases/unions/recursive-alias-nested-list-copied-with-map.vl`**

Repro:

    type J = null | string | J[]
    const xs: J[][] = [["a"]]
    const y: J[] = xs.map((x): J => x)
    print(y[0] is J[])
    y.push("z")
    print(y.length)
    // vl run: true, 2. Before the D1 slice: emitProgram: array value does not match any array member of the union (leaf-scalar widening across a nested array is unsupported)

#### Mechanism

The container-widening message recommends exactly this copy, so the program is the one the
design points to, and the checker accepts it. The `.map` result element is the recursive alias
`J`, whose list arm `J[]` receives a `J[]` element; the emitter does not build that arm from a
nested-array value and refuses.

#### Grading list

`#3563` fixture `recursive-alias-list-copied-with-map.vl` pins the non-nested copy; the nested
element case here must keep its own face.
