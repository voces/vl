### D14560 — an un-annotated function returning a read of an open list element, checked before the store that decides the element, infers `void`

**closed · now a loud check reject, `'h' returns a value taken from an element of 'a' whose type is not decided yet; annotate 'a' or h's return type` · DESIGN (coordinator ruling 2026-10-27, "later-decided element binding", extended to the return site): an inferred return commits a type the way a binding does, so it gets the same refusal, and no path infers `void` from an unresolved read · was a loud check reject at the caller (`print expects a value, got void`) and, through `const r = h()`, `cannot bind the void result of 'r'`, on master `fcfeab5fc`; on `67905160e` the same spellings ran by accident or were check-clean invalid wasm · filed 2026-10-27**

Repro:

    function g() {
      let a = __array_new_default__(3)
      function h() { return a[0] + 1 }
      a[0] = 1.5
      print(h())
    }
    g()
    // vl check: 'h' returns a value taken from an element of 'a' whose type is not decided yet; annotate 'a' or h's return type

#### Mechanism

`h`'s body is checked where it is declared, before `a[0] = 1.5` pins the element, so the
return's operand is a pending open-element read and checks to `-1`. `noteInferredRet` ignores a
`-1`, nothing is observed, and `finishInferredReturn` leaves its `TY_VOID` default in place: the
function infers `void` from a read it could not type, and the error surfaces at the caller.

The rule now has one predicate, `oerDeclWaits` (check_asg_rows.vl): a declaration whose
inferred type depends on an open-element read that has not resolved. `refuseOpenElemDecl`
(check_node_rules.vl) reports it, and the `let` binding (D14497) and every point that observes
an inferred return ask it: the explicit `return`, the trailing expression of a block or
expression-bodied lambda, and both arms of a tail `if`. A refused return is noted as an error
type, so the function infers no `void` and its callers report nothing further.

The other places inference reaches `void`, none of which turns a `-1` into it now:
`finishInferredReturn`'s default when nothing was observed (a body with no value return), its
recursive-cycle branch (a tentative `void` the binding-group fixpoint re-infers), the
`return <void expr>` path (`inferVoidRetSites`, a value that is genuinely `void`),
`checkFuncDeclNode`'s early `TY_VOID` for a body already inferred on demand (the declaration
statement's own type), and the `TY_VOID` a non-inferring declaration with no return annotation
starts from.
