### D7011 — an `if` expression of an uncalled hole function returned directly and called by the caller is refused at emit

**closed 2026-10-19 by lane L1 · runs, prints `a!` · was loud emit reject · `vl check` rc 0 · clause 2 · CAPABILITY: the same function binding the `if` first and returning the binding runs ([D7001](D7001.md)), and `exclaim(s: string)` runs · the return-site pin takes a returned `if` naming generic functions as it takes a returned binding of one, keyed by the first arm's read, and two pins past the return ask for a copy of the function per result type, bound or direct · pins: `tests/cases/closures/hole-fn-if-returned-directly-called.vl` · found closing [D7001](D7001.md) · present on master `3fbefe6d6` · filed 2026-10-19 against master `3fbefe6d6`**

Repro:

    function exclaim(s) { return s + "!" }
    function pick() { return if true { exclaim } else { exclaim } }
    print(pick()("a"))
    // vl check: rc 0.  vl run: emitProgram: cannot take the generic function `exclaim` as a value

Want:

    a!

#### Mechanism

From the code path. The return-site pin (`monoCoerceRetAtPin`) instances each arm of an `if` it
reaches through a binding (`monoIfBindingOf`, D7001), but a returned `if` expression is no
binding, so neither arm is pinned at the caller's call and the value refuses.
