### D8341 — an inferred-return function returning a generic identity's record literal is typed at the literal's row while its instance returns the union member's

**closed 2026-10-20 by lane emit-collect · runs, prints `4` · was check-clean invalid wasm · `vl check` rc 0 · clause 1 · a call whose inferred-return callee returns a union arm's variant row is not also given the checked type's struct row (`structIndexOfCallExpr`, `emit_classify.vl`), so the caller reads the row the instance returns · pins: `tests/cases/generics/inferred-return-identity-literal-into-record-union-unann.vl` and its annotated twin · found [D8380](D8380.md) closing · present on master `38ea07302` · the `return_inferred` annotated cell of `generic-identity-literal-into-record-union-own-row` · filed 2026-10-20 against master `38ea07302`**

Repro:

    type J = { r: i32 | null }
    function idn<T>(v: T): T { v }
    const w0 = idn({ r: 5 })
    function deliver() {
      return idn({ r: 4 })
    }
    const v: J | string = deliver()
    if v is J { print(v.r ?? 0) } else { print(0) }
    // vl check: rc 0.  vl run: invalid module, "expected (ref null $6), found (ref $3)": `{r:i32}` expected, `J` found

Want:

    4

#### Mechanism

The call inside `deliver` is built at `idn<J>` (D8021 chases the delivery through the return),
so `deliver` returns a `J`. Its inferred return is banked from the checker's inference,
`{r: i32}`, and `w0` gave that type a row, so the caller reads the `J` as a `{r: i32}`.
`structIndexOfCallExpr` answered the call's struct row from that checked type even though
`fnRetVariantIndexSid` already named the variant row the instance returns; when the callee declares no record return it now declines
there, and the call reads as the variant row.
