### D8341 — an inferred-return function returning a generic identity's record literal is typed at the literal's row while its instance returns the union member's

**check-clean invalid wasm · `vl check` rc 0 · clause 1 · open · present on master `38ea07302` · the `return_inferred` annotated cell of `generic-identity-literal-into-record-union-own-row` · filed 2026-10-20 against master `38ea07302`**

Repro:

    type J = { r: i32 | null }
    function idn<T>(v: T): T { v }
    const w0 = idn({ r: 5 })
    function deliver() {
      return idn({ r: 4 })
    }
    const v: J | string = deliver()
    if v is J { print(v.r ?? 0) } else { print(0) }
    // vl check: rc 0.  vl run: invalid module, "expected (ref null $6), found (ref $3)": `{r:i32}` expected, `J` found

Want:

    4

#### Mechanism

The call inside `deliver` is built at `idn<J>` (D8021 chases the delivery through the return),
so `deliver` returns a `J`. Its inferred return is banked from the checker's inference,
`{r: i32}`, and `w0` gave that type a row, so the caller reads the `J` as a `{r: i32}`. The row
`deliver` is given comes from the inferred-return collection in `emit_collect.vl`, outside lane
L6; the checker's inferred type and the instance the call is built at disagree.
