### D17208 — a module inferred-null binding filled with a width subtype of the record a function's join reads it beside builds invalid wasm

**closed 2026-11-25 by SOUND · runs, prints `9` `4` · was check-clean invalid wasm, clause 1, then the stopgap's loud check reject (#10181) · the fill re-banked the returned `if` at `Sub | In | null` while the function's inferred return stayed at the `In | null` it was settled at before the fill; `fillIfHoleNodes` (check_relate_core.vl) now moves an un-annotated function's return, both its bound type and its node's, to the re-banked join when the `if` is its sole returned value and no call has read the return yet (coordinator ruling 2026-11-25, option A); a call checked before the fill is refused with the order that runs (`call … after the assignment`), and a declared one-record return keeps the stopgap · pinned by `tests/cases/types/null-hole-fill-widens-returned-join-runs.vl` · pre-existing, the same before and after #9975 · found by V4 verifying #9975 (LAF2) · owner IR-N4 · filed 2026-11-24 against #9975's head `915156c9e` and master `09e329d2b`**

Repro:

    type In = { v: i32 }
    type Sub = { v: i32, k: i32 }
    const rec: In = { v: 9 }
    const sub: Sub = { v: 4, k: 1 }
    let m = null
    function pick(flag: boolean) { return if flag { m } else { rec } }
    m = sub
    print(pick(false)?.v ?? -1)
    print(pick(true)?.v ?? -1)
    // vl run: 9, 4

Want:

    9
    4

#### Mechanism

The fill makes `m` `Sub | null`, and `Sub` is a width subtype of `In`, so the re-derived join
(`fillIfHoleNodes`, [D17203](D17203.md)) fits the `In | null` the `if` was typed and is re-banked.
The `m` arm still holds a `Sub` struct, which is not declared a wasm subtype of `In`'s, so the
join's `In` block receives a `Sub` reference. Not yet ablated past the four faces.

Traced 2026-11-25 by SOUND (parked, coordinator 2026-11-25): re-asking the join at the fill with the
`if`'s own `joinArmLit` (`fillIfHoleNodes` passing whether the other arm is a literal) does keep the
arms apart, `Sub | In | null`, as the annotated `let m: Sub | null` spelling's join is (that spelling
runs). The module stays invalid: `pick`'s inferred return was settled at `In | null` before the
later fill, so the `if` is delivered into it with the `Sub` arm unconverted. A close needs the
return re-inferred after a fill that changes a join it returns, which is architectural.
