### D1623 — an indexed closure element called with no intermediate binding is `bare call statement`

**loud emit reject · 1 hand-written witness · filed 2026-09-05 against master `ef92ad0c`**

Repro:

    function go() {
      const xs = [(n: i32) => n + 5]
      const g = (n: i32) => xs[0](n)
      print(g(50))
    }
    go()
    // vl check: rc 0.  vl run: emitProgram: bare call statement is not supported

#### Mechanism

The callee is an `Index` whose receiver is a captured closure array, and the call reaches a
statement-position arm that refuses any callee it cannot name. Binding the element first
(`const e = xs[0]` then `e(n)`) runs, and so does the same `xs[0](n)` written in the frame
that DECLARES `xs` rather than in a lambda capturing it — so the ingredients are the callee
being an indexed element and the receiver reaching this frame as a capture. The message names
the arm that fired, not the feature: nothing about this program is a bare call statement.

#### Ablation

Every row is `vl check` rc 0.

| spelling | outcome |
| --- | --- |
| `xs[0](n)` inside a lambda capturing `xs` | **emit reject** |
| `const e = xs[0]` then `e(n)`, same lambda | runs, 55 |
| `xs[0](n)` in the frame that declares `xs` | runs, 55 |
| `w.f(n)` — the struct-field twin, captured | runs, 55 |

Needed: the indexed element AND the call with no binding AND the receiver being a capture.
The struct-field twin at the same three ingredients runs, which is what makes this the index
arm's own gap rather than the capture ladder's.

#### Grading list

* The struct-field twin `w.f(n)`, which runs and must keep running.
* The bound spelling `const e = xs[0]; e(n)`, likewise.
* The message, which should name the callee shape rather than `bare call statement`: narrowing
  it is part of the close, not a substitute for one.
