### D1623 — an indexed closure element called with no intermediate binding is `bare call statement`

**closed · filed 2026-09-05 against master `ef92ad0c` · closed against `8a7b2872`**

`stmtIsTailValue` grew the arm for every function-valued callee shape, and `emitCallStmt`'s
floor grew its discarded twin. 13 of 13 cells of this row's grid run; both position
templates grade with 0 silent. **The ablation filed with this row was WRONG in both halves**
and the corrected one is below.

Repro:

    function go() {
      const xs = [(n: i32) => n + 5]
      const g = (n: i32) => xs[0](n)
      print(g(50))
    }
    go()
    // vl check: rc 0.  vl run: emitProgram: bare call statement is not supported

#### Mechanism

**Neither the capture nor the indexed element is an ingredient**, and this row's own grid
refutes both: the same call with NO capture anywhere refuses, and a plain `(f)(n)` with no
container in the program refuses identically. What the filed ablation actually measured was
that `const e = xs[0]; e(n)` and `print(xs[0](50))` are both EXPRESSION positions, where the
call never reaches the statement ladder at all.

The real ingredients are the callee SHAPE and STATEMENT position. Two ladders decide statement
position and each had arms for exactly a `Member` callee and an `Ident` callee:
`stmtIsTailValue`, which routes a tail value to `emitReturnExit`, and `emitCallStmt`, which
lowers a genuine statement. An `Index`, `Call` or `Paren` callee is claimed by neither, so the
tail was not routed and the statement fell to `emitFail`.

The rung-input probe on that floor showed the expression path already had everything:

    D1623RUNG calleeKind=Index exprIsClosure=T cloCallSigKey=[i>i] sigRetIsVoid=F
    D1623RUNG calleeKind=Call  exprIsClosure=T cloCallSigKey=[i>i] sigRetIsVoid=F
    D1623RUNG calleeKind=Paren exprIsClosure=T cloCallSigKey=[i>i] sigRetIsVoid=F
    D1623RUNG calleeKind=Index exprIsClosure=T cloCallSigKey=[i>v] sigRetIsVoid=T

The last line is the void element, and `sigRetIsVoid` separates it correctly from the other
three — which is the drop decision both new arms take. `emitCallStmt`'s arm REFUSES rather
than drops a non-void result: reaching it with a value means the tail ladder declined, and
dropping there would leave a function promising a result with nothing on the stack. That
guard is not theoretical — without it, D1626's cells are check-clean invalid wasm.
