### D14970 — a named call that skips a defaulted middle parameter hands a generic as a closure, so it leans on the split plan

**closed · the check's positional rewrite (`namedCallPositional`) fills a skipped parameter with its default where that is a literal, the node `fillArgDefaults` shares with every call at emit, so `three(g: add, m: 5)` reads as `three(add, 1, 5)` and hands `{add}` as the set's id; a default that is not a literal leaves the call named as before · fixture `tests/cases/functions/named-call-middle-default-hands-generic.vl` · was runs only through the split plan · filed 2026-11-02 against master `cd74109e`, closed 2026-11-02 against master `3f09cb9b`**

Repro:

    function add(a, b) { return a + b }
    function three(g, n: i32 = 1, m: i32 = 2) {
      print(g(n, m))
      print(g("a", "b"))
    }
    three(g: add, m: 5)

Want:

    6
    ab

#### Mechanism

D14950's sibling. The check's last stage turns a named call positional (`namedCallPositional`), so
every pass after it reads argument `i` as parameter `i`; since D14950 that includes a call leaving
trailing defaults out. A call that skips a parameter before a supplied one cannot be spelled
positionally without the skipped default, and the default is filled only at emit
(`emit_rewrite`), after the tag path, so the call stays named and every positional reader of the
tag path declines it.

#### Ablation

With the split plan off, the callee a hole function or a declared generic alike:

| spelling | outcome |
| --- | --- |
| the witness, `three(g: add, m: 5)` | refuses |
| `three(g: add, n: 1, m: 5)`, the middle supplied | runs |
| `three(g: add)`, trailing defaults left out | runs (D14950) |
