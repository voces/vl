### D10204 — a list literal of a generic and a fixed-type function handed to a generic function's list parameter is refused by emit as an internal error

**loud emit reject · `vl check` rc 0 · `emitProgram: internal: a parameter type the valtype ladder has no rung for — every parameter type the checker accepts has one above` · clause 2 · at `U = i32` the program is owed a run printing `3`; at `U = string` it is owed the check refusal the non-generic twin `run(a: ((x: string) => string)[], …)` gives, `a function of type `(i32) => i32` cannot be used as `(string) => string` here` · found closing [D10150](D10150.md) · present on master `7f3985aad` · filed 2026-10-22 against master `7f3985aad`**

Repro:

    function id<T>(x: T): T { x }
    function inc(x: i32): i32 { x + 1 }
    function run<U>(a: ((x: U) => U)[], u: U): U { a[1](u) }
    print(run([id, inc], 2))
    // vl check rc 0.  vl build: internal: a parameter type the valtype ladder has no rung for

#### Mechanism

Not yet ablated past the table below: the argument binds `U` to `id`'s own type variable
(first use wins, as in [D10150](D10150.md)), so the instance of `run` emit builds has a
parameter type still carrying a type variable.

#### Ablation

| ingredient removed | outcome | needed? |
| --- | --- | --- |
| the literal bound first, `const ys = [id]; ys.push(inc)`, `run(ys, 2)` | runs, `3` | **yes** |
| `run([id, inc], "s")` | the same emit reject | no |
