### D2427 — a generic function value into a generic HOF with an inferred return pins the instance's return off the value's generic type

**closed · clause 1 · found closing D2425, filed 2026-09-25 against master `a277bf7b0`**

Repro:

    function idf<U>(x: U) { return x }
    function run<T>(cb: (T) => T, v: T) { return cb(v) }
    print(run(idf, 1.5))
    // vl check: rc 0.
    // vl run: Error: invalid module … inside `run`: type mismatch: expected i32, found f64.

#### Mechanism

`monoInstantiate` pins an arrow parameter riding the callee's type parameters to the
substituted spelling (`(f64)=>f64`), and records beside it the arena row of the argument's
own type (`monoArgPinTyIx`). For a generic function value that row is the value's GENERIC
type, `(U) => U`, or `(T) => i32` for `x + x`. `monoMakeInstance` types an un-annotated
`return cb(v)` from that row's return in preference to the pinned name, so the instance
returned `U` (lowered as i32) or `i32`. The row is now dropped (-1, the name-resolution
fallback) when it still carries a type variable.

#### Ablation

| ingredient changed | outcome | needed? |
| --- | --- | --- |
| a concrete `d(x: f64)` for `idf` | runs, prints 3 | the generic value: **yes** |
| `run(...): T` annotated | runs | the inferred return: **yes** |
| `const r = cb(v); return r` | runs | the direct `return cb(v)`: **yes** |
| an un-annotated lambda for `idf` | runs | no |
| `idf<U>` renamed `idf<T>` | same invalid module | no |
| `run(idf, 3)` | runs | the non-i32 binding: **yes** |
