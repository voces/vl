### D16076 — a call noted before its arguments had types poisoned its slot's one signature: a maker's result called through an alias inside a top-level lambda had no key

**closed · the `closure_capture` un-annotated cell of both `hole-lambda-returned-by-{function,lambda}-at-two-types` matrices · found by lane I from the matrix · filed 2026-11-14 against master `bdef11fa`**

Repro:

    function outer() {
      const l = (x) => x
      return l
    }
    const c = outer()
    const f = () => {
      const v = c
      print(v(41) + 1)
    }
    f()

Want:

    42

#### Mechanism

`checkCallNode` notes each call through a binding's slot with its argument types
(`fnSlotCallNote`). The elaboration closes the slot at the one tuple every note agrees on
(`fnSlotCallArgsOf`), and treats an argument with no type as open, which refuses. A quiet probe
re-checked the top-level lambda's body before the alias `v` had a type. Its call noted `[-1]`
beside the standing pass's `[i32]`, so `c` got no slot fact, `calleeCloSigKeyOfRead` found no
key, and emit refused with "a function-value call has no interned signature". The named-function
spelling's body is not probed, which is why `function f() { … }` ran. Now `fnSlotCallNote`
returns under `inferQuiet` before it notes a tuple, as `fnSlotAnnNote` already did, and the
standing pass notes the call again.
