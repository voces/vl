### D5470 — `is` at a second element type over an un-annotated record's empty list field is refused by the emitter

**loud emit reject · `vl check` rc 0 · clause 2 · OPEN · found closing D5344 · filed 2026-10-17 against `ae9bb33e2` (PR #3980's head)**

Repro:

    const r = { n: 1, kids: [] }
    print(r.kids is string[])
    // vl check: rc 0.  vl run: emitProgram: this `is` arm reads an empty list at an element type it was not built with, and only a variable read directly in its own function can be handed one

#### Mechanism

The checker reads `r.kids` as an open hole `_[]`, and every list type fits that, so it admits
the test. At program end D5344's default builds the field as `i32[]`, and the `is` arm then
asks for an empty list at `string[]`. The emitter serves that only for a variable read directly
in its own function, not for a field read. Before D5344 the same program refused earlier, with
`object literal but no struct type declared`. There are two answers, and a ruling decides
between them. Under the D4771 ruling an empty list fits every `K[]`, so the program prints
`true`. Or the checker owes the refusal its annotated twin gets (`can
never match a value of type i32[]`), so the test must be graded after the default.

#### Ablation

| spelling | outcome | needed? |
| --- | --- | --- |
| `r.kids is i32[]` (the default's own element) | runs, prints `true` | **yes** (a second element type) |
| `const r: { n: i32, kids: i32[] } = …` | loud check reject, `can never match` | **yes** (the inference) |
