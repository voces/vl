### D5470 — `is` at a second element type over an un-annotated record's empty list field is refused by the emitter

**closed · was loud emit reject · `vl check` rc 0 · clause 2 · found closing D5344 · filed 2026-10-17 against `ae9bb33e2` (PR #3980's head)**

Repro:

    const r = { n: 1, kids: [] }
    print(r.kids is string[])
    // vl check: rc 0.  vl run: emitProgram: this `is` arm reads an empty list at an element type it was not built with, and only a variable read directly in its own function can be handed one

Want:

    true

#### Mechanism

The checker reads `r.kids` as an open hole `_[]`, and every list type fits that, so it admits
the test. At program end D5344's default builds the field as `i32[]`, and the `is` arm then
asks for an empty list at `string[]`. The emitter serves that through a shadow local for the
arm's narrowed reads, which exists only for a variable read in its own function. Before D5344
the same program refused earlier, with `object literal but no struct type declared`.

The owner's D4771 ruling (a) decides which of the two possible answers is right: an empty list
fits every `K[]`, so the test is the runtime emptiness test and the program prints `true`. The
checker owes no refusal. The annotated twin's `can never match a value of type i32[]` is about a
DECLARED element, which this binding does not have.

Fixed in the emitter. The arm needed the shadow only because `listNarrowReadDisjoint`
(`wasmEmit.vl`) answered "a narrowed read may exist" for the start function, which it never
scanned. It now scans the program root when `fnIx` is -1, so a top-level test with no narrowed
read in its arm lowers as the plain emptiness test, the same as one inside a function already
did. Graded by `record-lit-empty-list-field-is.matrix.vl` (19 un-annotated cells refused before,
64 of 64 run after), the `record-lit-*` and `recursive-record-eq` matrices (0 runs→not-runs) and
`tests/cases/structs/record-lit-empty-list-field-is.vl` (top level, a function body, a binding,
an `if`, a return at `f64[]`, a negation, a list element's field and a hole parameter's field).

A narrowed read OF THE FIELD inside the arm (`if r.kids is string[] { print(r.kids.length) }`)
still refuses with the shadow message, at the top level and in a function alike. That is the
field-receiver half of D4964, unchanged by this fix.
