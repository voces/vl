### D15646 — a record of a set of hole functions and a record of a plain function, handed to one hole callee, build invalid wasm

**check-clean invalid wasm · clause 1 · `the emitted module failed to validate inside \`call0\`: … expected (ref null $5), found (ref $6); $5 is \`#anon0\`, struct {mut (ref $2)}; $6 is \`#anon1\`, struct {mut (ref $2)}` · found closing D15642 · filed 2026-11-10 against master `ee66b4ec`**

Repro:

    function id(v) { return v }
    function dbl(v) { return v + v }
    function inc(v: i32) { return v + 1 }
    function call0(r, x) { print(r.f(x)) }
    function run(b) {
      const g = if b { id } else { dbl }
      call0({ f: g }, 3)
    }
    run(true)
    call0({ f: inc }, 3)

Want:

    3
    4

#### Mechanism

Measured on master `21bd6cb5`, with `--names` dumps of the elaboration's instances, mono's pin keys
and the struct rows.

1. **The elaboration.** It has two `call0` instances: `K0` at `{f: set{id,dbl}}, i32` and `K2` at
   `{f: (i32) => i32}, i32`. `K2` is reached by `call0({ f: inc }, 3)`. It is also the set's
   closure-rep instance (`elabRepRowCalls[K2]` is non-empty, `elabSetRepRow`).
2. **The partial rule.** `K2` never calls through the set, so the partial rule in `elabMintFacts`
   marks `{id, dbl}` partial and the set stays untagged. None of the rule's exemptions apply:
   `elabKeyCallsHandClosure` reads only an `Ident` callee, and `K2` is a rep-row instance. A
   record-field twin of that exemption was tried and stops at the same rep-row guard.
3. **Mono.** It pins both instances at `{f: (i32) => i32}`, so `monoKeyPinSeg` gives them one key
   and builds one `call0`.
4. **The struct rows.** The two literals still mint two `#anon` rows of one layout.
   `{ f: g }`'s adopted rep `{f: _}` holds a hole, and `structIndexOfObjCtxGo` ignores such a rep,
   though `repRowOfTyStruct` finds `#anon0` for it by key. So `call0` reads one row and is handed
   the other. That is the invalid wasm.
5. **A shared row alone exposes the next layer.** Letting the hole rep name that row gives a valid
   module that traps with `indirect call type mismatch`. The untagged set's closures wrap `id` and
   `dbl` templates that were never instanced at `i32`.

The fix has to keep the set's instance apart from the closure record's: tag `{id, dbl}` and key
`K0` apart from `K2`. Alternatively, build the set's closures at the signature the merged instance
fixes, as `ftLateCloAt` / `monoCloCoerceMemberFe` do for a closed function destination (D15642).
