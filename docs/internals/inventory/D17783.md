### D17783 — a `const` lambda called with an `if` join of two functions whose results differ traps at run time

**closed 2026-11-28 — an argument handed to the lambda a `const` holds binds that lambda's un-annotated parameter as a named function's does (`ftHoleParamOf`, check_fn_tag.vl), so the `if` join is tagged and the call dispatches per member · was trap after load, clause 1 · found grading D15777 · filed 2026-11-28 against master `885e9e60` by COV-CALL**

Repro:

    function inc0(a) { return a + 1 }
    function half(a) { return a / 2.0 }
    function two() { return [1, 2].length }
    const take = (r) => r(3)
    const q = if two() > 5 { half } else { inc0 }
    print(take(q))
    // was: vl check rc 0, then a wasm trap (indirect call type mismatch)

Want:

    4

#### Mechanism

`ftHoleParamOf` asks whether an argument binds an un-annotated parameter of the function a call
names. Through a `const`, `ftCalleeSource` reaches the lambda's own declaration, which
`ftCalleeFn` names only as an identifier, so the answer was no: the plan for `{inc0, half}` failed
at `ftCtxOk`'s call arm, the join stayed closures, and the lambda's body called it at the joined
`(i32) => f64` while `inc0`'s closure returns `i32`. The lambda reached through a `const` is now
the callee there; a lambda node the call names directly keeps the old answer (widening that to
`ftCalleeFn` broke three choice-through-generic cases). Witnesses: `named/d17783_*`.
