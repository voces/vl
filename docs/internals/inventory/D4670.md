### D4670 — a hole function whose tail is a `.map` over a hole-typed call result traps or builds invalid wasm

**loads then traps · clause 1 · found closing D4637, which unmasked it in 70 cells of the `d3125-lift-price` named set · filed 2026-10-14 against master `1c1740512`**

Repro:

    function mk(v) {
      return [v]
    }
    function t(x) {
      mk(x).map((e) => "v")
    }
    print(t(4).length)
    // vl check: rc 0.  vl run: wasm trap: unreachable

Want:

    1

#### Mechanism

Not localised past the ablation. The tail value of `t`'s instance is lost: binding it first and
naming the binding as the tail runs, and so does `return`. An `if`/`else` tail whose arms are
both such `.map` calls fails validation instead (`values remaining on stack at end of block`).

#### Ablation

| ingredient changed | outcome | needed? |
| --- | --- | --- |
| `return mk(x).map(…)` | prints `1` | **yes** (the tail position) |
| `const r = mk(x).map(…)` then `r` as the tail | prints `1` | **yes** |
| `function t(x: i32)` | prints `1` | **yes** (the hole) |
| `function mk(v: i32): i32[]` | prints `1` | **yes** (a hole-typed receiver) |
| `function mk<U>(v: U): U[]`, or `t<T>(x: T)` | still traps | no |
| `[x].map(…)` in place of `mk(x).map(…)` | prints `1` | **yes** |
| `mk(x).length` in place of `.map(…)` | prints `1` | **yes** |
| the callback returns `7` in place of `"v"` | still traps | no |
| `if 1 > 0 { mk(x).map(…) } else { mk(x).map(…) }` as the tail | invalid wasm | no |
