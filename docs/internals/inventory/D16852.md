### D16852 — two maker calls at two pins, one called directly and one handed to an un-annotated parameter, are refused at emit

**open · loud emit reject · clause 2 (`vl check` rc 0) · the residual of [D16846](D16846.md): one binding's call is noted by the check, the other only by the elaboration · filed 2026-11-16 against master `a8512d420`**

Repro:

    function adder(n) { return (a) => a + n }
    function half(a) { print(a(0.5)) }
    const x = adder(2)
    print(x(3))
    const z = adder(2.25)
    half(z)
    // vl check: rc 0.  vl run: emit error, `a function value is called at two signatures, and the closure it holds was built for one: this call passes a wider number than its `i32` parameter`

Want:

    5
    2.75

#### Mechanism

Partly traced. The elaboration twins each call (`adder` returning `(i32) => i32` and `(f64) => f64`),
but the check typed the returned lambda's parameter `i32` from the direct call `x(3)`, and mono
pins the lambda only where the check left its parameter open, so the `f64` twin's lambda keeps the
`i32` parameter and no closure has the signature `half` calls.
