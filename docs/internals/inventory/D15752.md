### D15752 — a map of an un-annotated function pushed onto an annotated list of maps of functions is check-clean invalid wasm

**open · check-clean invalid wasm · clause 1 · `type mismatch: expected (ref $11), found (ref $9)` in the module's top-level code; at the default signature it loads, then traps on the call · the same map in the list's literal, or bound to an annotated map, runs · found by lane w321 grading D15353's matrix (`array_push`, `map_set`) · filed 2026-11-12 against master `8fbf0d78`**

#### Mechanism

Not yet traced. The push hands the map over at its own storage, built for the
un-annotated function's closure, while the list's element is the annotated map's storage. A
literal `[fnMap]` and an annotated binding `const m: {[string]: (a: f64) => f64} = fnMap`
convert the map at the delivery, and the push does not. A map value written with `set` into an
annotated map of such maps is the same defect (`__m.set("k", fnMap)`).
