### D15977 — `valueUnionVerdict` has no kind for a list of a literal union, so the type declines what the spelling calls a value union

**runs today and must keep running · 1 distilled cell (`d362al_numlitun_unionmem`) · filed 2026-11-12 against master `25ddb6cb`**

Repro:

    type Z = 0 | 1
    type L = Z[]
    function rd(c: L | i32) {
      if c is i32 { print(0) } else { if c[0] == 1 { print(7) } else { print(0) } }
    }
    rd([1])
    // vl check: rc 0.  vl run: 7

#### Mechanism

`isValueUnionTyOr` (`check_ty_rep.vl`) decides whether a union type is a value union from its
members' value kinds (`valueUnionVerdict` over `valueRowKind`). `valueRowKind` has no kind for a
list whose element is a literal union (`Z[]`), so the verdict declines (-1) on `Z[] | i32`. The
union's spelling softens `Z[]` to `i32[]`, and `isValueUnionName` calls `i32[]|i32` a value union.
The two disagree.

Since lane G's cut 4b (#7638), the inline union registrar reads only the type's verdict, so this
union is no longer registered there as a value union. The program builds byte-identically (the
registration was redundant). Every other consumer that asks the type gets -1 for this shape.

#### Ablation

| ingredient removed | the verdict on the type | needed? |
| --- | --- | --- |
| the literal-union element (`L = i32[]`) | 1 (value union) | **yes** |
| the scalar arm (`c: L`) | not a union | **yes** |

#### Grading list

The close teaches `valueUnionVerdict` that a list of one literal base is that base's list kind.
It re-grades `isValueUnionTyOr` against `isValueUnionName` over the sweep population: every
declined union whose spelling is a value union.
