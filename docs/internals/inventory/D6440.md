### D6440 — a string map key holding a comma splits the after-call retire bank, so its narrowing survives a call that writes it

**closed 2026-10-18 by lane L5 · runs, prints `null` · was check-clean, `vl run`: wasm trap: cast failure · clause 1 · the capture and narrowing banks are string lists rather than comma-joined strings · pin: `tests/cases/maps/comma-key-retired-after-call.vl` · filed 2026-10-18 against master `066d19373`**

Repro:

    const m: {[string]: i32 | null} = Map()
    m["a,b"] = 1
    function clr() { m["a,b"] = null }
    if m["a,b"] != null {
      clr()
      print(m["a,b"])
    }
    // vl check: rc 0.  vl run: wasm trap: cast failure

#### Mechanism

The checker banked the names a call retires after its statement as one comma-joined string,
and the emitter split it on commas. The key `m["a,b"]` came back as `m["a` and `b"]`, neither
matched the live narrowing, and the emitter kept reading `m["a,b"]` at `i32` after `clr()`
had stored `null`.
