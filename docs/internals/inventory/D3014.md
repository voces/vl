### D3014 — a hole `for`-in over a list literal of the parameter at a boxed or nullable pin binds the loop variable as a bare `i32`

**check-clean invalid wasm · clause 1 · the LU3 grid's `S_forinlit_h` row, 110 invalid and 19 trapping cells at the `i32 | null`, `f64 | null`, `1 | 2 | null` and `string | null` pins · the same on master `59cf3b639` · filed 2026-09-28 against master `59cf3b639`**

Repro:

    function f(x) {
      for e in [x] { print(e) }
    }
    const v0: i32 | null = 2
    f(v0)
    // vl check: rc 0.  vl run: invalid module, expected i32, found (ref $type)

Want:

    2

#### Mechanism

Not localised past the ablation. The literal `[x]` is built at the pin, a list of `i32 | null`
boxes, but `forInElemKind` classifies an ARRAY-LITERAL iterable through `exprListRep`, which at a
hole answers no ref list, so the loop variable is declared an `i32` local and the element read
does not fit it. A local list (`const l = [x]`) is classified through its local and runs. At a
`string | null` pin the same miss binds a non-null string, and a `null` traps (null reference).

#### Ablation

| ingredient changed | outcome | needed? |
| --- | --- | --- |
| `const l = [x]` then `for e in l` | prints `2` | **yes** (the literal iterable) |
| `function f<T>(x: T)` | prints `2` | **yes** (the hole) |
| a non-null `i32` pin | prints `2` | **yes** |
| a `1 \| 2 \| null` or `f64 \| null` pin | invalid wasm | no (the same defect) |
| a `string \| null` pin at `null` | wasm trap, null reference | no (the niche twin) |

#### Grading list

The LU3 grid's `S_forinlit_h` row (`scratchpad/lu3b-work/gen_grid2.py`) at every nullable or boxed
pin, single and paired: the pairs with a literal-union pin moved from a loud emit reject to this
invalid module when that half started running.
