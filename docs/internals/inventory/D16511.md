#### Mechanism

`elabLateNames` records a key minted after `elabRun` returned, except while
`elabSpecChecking` is set, which is when an argument-keyed instance's body is being checked
(`emit_elab.vl`). Mono's walk demands those instances itself: `monoInstantiateCallIn` →
`elabSpecDemand` (`elab_fn_id.vl`) → `elabSpecInst` → `elabOne` → `monoRecheckBegin`. The body's
re-check then pins list elements (`tyPinElem`) and publishes inferred returns (`inferRetPublish`)
during emit. That is work demanded after the elaboration finished, and the ratchet cannot see it.

The stage 4e census, a scratch seed counting each `tyMutEpoch` bump site by phase over 19,779
files, found 55 programs whose emit-phase bumps come from these re-checks. Trapped stacks: 48 of
the 55 show `elabSpecDemand`, and all 55 run through `monoRecheckBegin`. `late-demands.vl` reads
0 for all 55.

#### Grading list
