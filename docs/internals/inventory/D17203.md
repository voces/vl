### D17203 — an inferred-null binding read before a later write fills it with a different type keeps the read checked at the open hole, then emitted at the filled type

**closed 2026-11-24 · runs, prints `true` `false` · was check-clean invalid wasm (clause 1) · inside a function the checker already types the read before the write `null`; emit now delivers it as the destination's own null where the destination's struct row differs from the storage's (`nullReadDstOwnOf`), takes the join's rep off its record arm (`exprIsNullLike`), and boxes it as the union's null (`holeBoxPlanOf`). The module-scope spelling, where the read is not narrowed, is re-asked at the fill (`fillIfHoleNodes`) and is now a loud check reject, "annotate the binding" (coordinator ruling, DECISIONS.md) · fixtures `tests/cases/types/null-hole-fill-after-join-{runs,refused}.vl` · still open: `??` and the alias, [D17205](D17205.md) · found by V4 verifying #9936 (LB2 item 3), ablated by IR-N4 · owner IR-N4 · filed 2026-11-24 against master `6aabbd9ac`, the same before #9936 (`4e84cecc`) except the module-scope join**

Repro:

    type In = { v: i32 }
    type Out = { w: string, k: i32 }
    const rec: In = { v: 9 }
    function run(f: boolean) {
      let m = null
      const j = if f { m } else { rec }
      m = { w: "z", k: 4 }
      return j == null
    }
    print(run(true))
    print(run(false))
    // vl run: true, false

Want:

    true
    false

#### Mechanism

`let m = null` binds the open hole `mkNullableTy(-1)`, and the later write fills it in place
(`nhFillLinked`), so `m`'s storage is `Out | null`. Inside a function the checker flow-narrows
the read before the write to `null`, so the join is a correct `In | null`. Emit then read the
value off the storage: `nullReadDstOwnOf` compared only rep kinds (both nulstruct), the join's
rep was taken off the `m` arm, and a union box tagged it as `Out`. A function reading a module
binding is not narrowed, so its read is the hole when the join is typed, and nothing re-asked the
join at the fill (a `??` is re-asked, `fillCoalHoleNodes`). Before #9936 that join was the hole
itself, filled to `Out | null`, which dropped `In` and made `?.v` a loud check reject.
