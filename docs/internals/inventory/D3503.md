### D3503 — a declared `A | B | null` at two nullable-list pins builds a value box of two list arms inside the instance

**closed 2026-10-03 — the witness prints `false` · was check-clean invalid wasm · clause 1 · fixture `tests/cases/generics/annotated-param-union-at-nullable-list-pins.vl` · the same on master `04ec2ef6f` and with #3337 · the list case of [D3499](D3499.md) · found by #3337's review (its `g3` grid, the `nl` pins) · filed 2026-10-03 against master `04ec2ef6f`**

Repro:

    const nl: i32[] | null = [1, 2]
    function F<A, B>(k: i32, a: A, b: B): A | B | null {
      if k == 0 { return a }
      if k == 1 { return b }
      return null
    }
    const u = F(0, nl, nl)
    print(u == null)
    // vl check: rc 0.  vl run: invalid module inside `F`, "expected struct type at index 0, found (array (mut i32))"

Want:

    false

#### Mechanism

Not localised past the ablation; D3499's message and D3499's instance. D3499's fold
(`nullableFlatInner`) drops the nulls the pins put inside the union and keeps each member once
by arena identity, so two `string` arms become one. Two list pins substitute two list rows, and
the list types are apparently not one arena row, so the fold keeps both and the instance builds
a box of two list arms that no collect pass registered. Two `string[] | null` pins fail the
same way. Confirmed and closed: the fold now keeps one member per list type as the union arm's
dedupe does (`substListTwin`), so the two pins are one `i32[] | null`.
