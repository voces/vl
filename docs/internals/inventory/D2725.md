### D2725 — a shift count written as a literal tree (`x << (16 + 16)`) is taken modulo the width with no refusal

**closed 2026-09-30 — now a loud check reject: the count `(16 + 16)` is a constant tree, folded to `32` before D2710's count check reads it, so it is refused as `x << 32` is (`shift count 32 is out of range for an i32 operand`); `x << (1 << 5)` and `x >>> (40 - 8)` refuse the same way · owner's exact-constant ruling (A) · fixture `tests/cases/bitwise/error-shift-count-constant.vl` · was check-clean silently wrong · clause 1 · found in the #3201 review (h06) · filed 2026-09-26 by lane PL47**

Repro:

    function f(x: i32): i32 { x << (16 + 16) }
    print(f(1))
    // PRINTS 1

#### Mechanism

Not yet measured. D2710's refusal reads a count's lexeme (`intLitLexemeOf`, which peels only
parentheses and unary minus), so `x << (32)` refuses and `x << (16 + 16)` does not: the tree has a
constant value the checker never folds. The fix is a fold of a literal tree's value at the count,
the same walk `litTreeOps` already makes over the tree's shape.
