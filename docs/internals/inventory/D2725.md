### D2725 — a shift count written as a literal tree (`x << (16 + 16)`) is taken modulo the width with no refusal

**check-clean silently wrong · clause 1 · found in the #3201 review (h06) · identical on master
`74bd044d7` · filed 2026-09-26 by lane PL47**

Repro:

    function f(x: i32): i32 { x << (16 + 16) }
    print(f(1))
    // PRINTS 1

#### Mechanism

Not yet measured. D2710's refusal reads a count's lexeme (`intLitLexemeOf`, which peels only
parentheses and unary minus), so `x << (32)` refuses and `x << (16 + 16)` does not: the tree has a
constant value the checker never folds. The fix is a fold of a literal tree's value at the count,
the same walk `litTreeOps` already makes over the tree's shape.

#### Ablation

| ingredient changed | outcome | needed? |
| --- | --- | --- |
| `(16 + 16)` → `(32)` | refused (D2710) | **yes** (a tree, not a literal) |
| `(16 + 16)` → `(16 + 15)` | `-2147483648` | **yes** (a value at or above the width) |

#### Grading list

`x << (1 << 5)` and `x >>> (40 - 8)` beside the witness.
