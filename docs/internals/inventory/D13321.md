### D13321 — one read of a forwarded hole handed to two hole parameters of list elements, each called at its own key, has no interned signature

**loud emit reject · `vl check` rc 0 · clause 2 · CAPABILITY: handing `add` in either position, or calling one parameter in both elements, runs · found by lane L1 closing [D13200](D13200.md) and [D13261](D13261.md) · present on master and after lane L1's D13261/D13200 PR · filed 2026-10-25 against master `ea2c435a3`**

Repro:

    function add(a, b) { return a + b }
    function apply2(g, gb, s) {
      print(g(s, s))
    }
    function apply4(g, gb, s) {
      print(gb(s, 2))
    }
    function innerThree(k, h) {
      for f in [apply2, apply4] { f(h, h, k) }
    }
    innerThree(0.5, add)
    // vl check: rc 0.  vl run: emitProgram: a function-value call has no interned signature — parameter 1 of type `` has no representation in the function-value ABI

Want:

    1
    2.5

#### Mechanism

Measured with a debug probe on the split round (fn_split.vl). The hole plan gives
`innerThree` an extra `h$…` parameter for the second key, but the list call `f(h, h, k)` is not
rewritten to hand it: the one read `h` reaches two distinct one-key parameters, `g` (called at
`f64, f64`) and `gb` (called at `f64, i32`), and the hand-out assumes one read feeds one slot.
The apply round then refuses at `innerThree(0.5, add)`.
