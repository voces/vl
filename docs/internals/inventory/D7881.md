### D7881 — a hole function returning a read off an atom-valued map loses the read's nullability at its caller

**closed 2026-10-20 by lane L6b · runs, prints `null` · the hole's atom map read keeps its nullability at the caller (`coalesceDefaultNullable` asks the instance's hole type) · was check-clean silently wrong · clause 1 · the annotated `function pick1(p: R)` runs and prints `null`, so the owed result is `null` · binding the call and testing `r == null` is a loud emit reject (`bare null needs a struct-typed context`) · found closing [D7444](D7444.md) · an earlier checker-side close was refused for 116 `d3127` cells (below) · present on master `5d224f614` · filed 2026-10-20 against master `5d224f614`**

Repro:

    type AB = "a" | "b"
    type R = { m: {[i32]: AB} }
    function mk(): R {
      const m: {[i32]: AB} = Map()
      m[3] = "b"
      { m: m }
    }
    function pick1(p) { return p.m[9] }
    print(pick1(mk()))
    // PRINTS b

Want:

    null

#### Mechanism

The checker types a map read off a hole parameter as the map's bare value, not as the value or
`null`. When no write pinned the value, `checkIndexHole` returns an `HD_ELEMV` derived hole, and
`substHoleTyReal` resolves that hole at a map pin to neither the value nor `V | null`: it stays a
hole. The emitter's `holePinReadOf` already reads it as `mapPinReadTy`'s `V | null`, so the two
disagree, and the instance's inferred result (`monoInferRetExprTy`) is a non-null atom whose `-1`
miss decodes as a member.

#### Refused candidate

Lane L6 (PR #4217) made the checker agree with the emitter. `checkIndexHole` returned the
`HD_ELEMV` hole for an unpinned value, `substHoleTyReal` resolved `HD_ELEMV` at a map pin through
`mapPinReadTy`, `monoInferRetExprTy` kept a nullable literal union as an instance's result, and
`monoRetJoinDisagrees` stopped vetoing an open `_ | null`. That closed this row, D3397, D3399,
D3411 and D3413, and made D3400 the check reject it owed. The distilled corpus refused it: **116
`d3127` cells runs → not-runs** (r1 3, r2 13, r3 75, r4 25). Every one is a `??` over a hole's
map read. The `??` lowerings at a pin cannot take a `V | null` operand there:

| outcome at the candidate | cells |
| --- | --- |
| loud emit reject, `` `??` over this nullable value is not supported yet `` | 75 |
| loud emit reject, `` `??` joins a nullable value into a union with no arm for the value's own type `` | 16 |
| loud emit reject, `monomorphize: unsupported argument type for x in a call to show` | 14 |
| check-clean invalid wasm inside `use` | 11 |
| loud check reject, an interpolation hole of `"a" \| "b" \| i32` | 1 |

The `substHoleTyReal` arm alone cost 40 of the 116. Dropping only that arm and keeping
`checkIndexHole`'s cost 145. With both reverted, the 215 `d3127` cells all run. Some direct
spellings run where the hole spelling refused. `p.a[3] ?? p.a[4]` over `{[i32]: f64}` prints
`2.5` annotated and is invalid wasm (`expected (ref $union box), found f64`) at the hole. So
the close needs every `??` lowering to take a pinned `V | null` operand first, and only then
the checker change. The price is already in `distilled/named/` as the `d3127_*` cells.
