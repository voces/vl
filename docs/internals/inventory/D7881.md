### D7881 — a hole function returning a read off an atom-valued map loses the read's nullability at its caller

**check-clean silently wrong · clause 1 · open · the annotated `function pick1(p: R)` runs and prints `null`, so the owed result is `null` · binding the call and testing `r == null` is a loud emit reject (`bare null needs a struct-typed context`) · found closing [D7444](D7444.md) · present on master `5d224f614` · filed 2026-10-20 against master `5d224f614`**

Repro:

    type AB = "a" | "b"
    type R = { m: {[i32]: AB} }
    function mk(): R {
      const m: {[i32]: AB} = Map()
      m[3] = "b"
      { m: m }
    }
    function pick1(p) { return p.m[9] }
    print(pick1(mk()))
    // PRINTS b

Want:

    null

#### Mechanism

Not traced past the ablation. The lead is the call rung of `nulLitAtomTextsAt`, which reads
a nullable atom's member texts only off an annotated return, so the hole function's inferred
`AB | null` result prints as a non-null atom and its `-1` miss decodes as a member.
