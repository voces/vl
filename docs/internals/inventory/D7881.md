### D7881 — a hole function returning a read off an atom-valued map loses the read's nullability at its caller

**closed · was check-clean silently wrong, clause 1 · the annotated `function pick1(p: R)` ran and printed `null`, so the owed result is `null` · binding the call and testing `r == null` was a loud emit reject (`bare null needs a struct-typed context`) · found closing [D7444](D7444.md) · filed 2026-10-20 against master `5d224f614` · closed by lane L6 against master `6d9597a6e`**

Repro:

    type AB = "a" | "b"
    type R = { m: {[i32]: AB} }
    function mk(): R {
      const m: {[i32]: AB} = Map()
      m[3] = "b"
      { m: m }
    }
    function pick1(p) { return p.m[9] }
    print(pick1(mk()))

Want:

    null

#### Mechanism

A map read off a hole parameter typed as the map's bare value, not as the value or `null`. The
checker's `checkIndexHole` returned the value type when a write had pinned it and an `HD_ELEMV`
derived hole otherwise, and `substHoleTyReal` resolved that hole at a call to the element, not
to `mapPinReadTy`'s `V | null`. The instance's result rung `monoInferRetExprTy` then also
declined a `K | null` result as not needing a box. The close has three parts. `checkIndexHole`
reads a pinned value as `V | null`. `substHoleTyReal` resolves an `HD_ELEMV` hole through
`mapPinReadTy`, the reader the emitter's `holePinReadAt` already used. `monoInferRetExprTy`
keeps a nullable literal union as the instance's result. `monoRetJoinDisagrees` no longer vetoes
a result that holds a nullable atom.

#### Ablation
