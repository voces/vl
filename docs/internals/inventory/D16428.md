### D16428 — an un-annotated function that recurses at a second, fixed type (bounded polymorphic recursion) runs, which an HM-monomorphic recursive group would refuse

**runs today and must keep running · until the owner rules on L2's choice 3 (`l2-inferred-interfaces-design.md` §9): HM-monomorphic recursion inside a strongly connected component, or keep bounded polymorphic recursion · found measuring L2 S0 · filed 2026-11-15 against master `5e45620f`**

Repro:

    function f(x, n: i32) {
      if n <= 0 { return 0 }
      return f("s", n - 1) + 1
    }
    print(f(1, 3))

Want:

    3

#### Mechanism

Mono builds `f` at `i32` and `f$1` at `string`. The `i32` instance calls the `string` one, which
recurses on itself. Under HM's rule a recursive call inside the component sees the component's own
monomorphic variables, so `x: i32` meets `"s"` and the program is refused. Recursion whose type
grows without bound (`f([x], n - 1)`) is already refused ("binds the type of an un-annotated
parameter of `f` to a type built from itself"); only the bounded form runs.

#### Ablation

| ingredient changed | outcome | needed? |
| --- | --- | --- |
| `f(x, n - 1)`, the same type | runs, one instance | **yes** (a second type) |
| `f([x], n - 1)`, a type built from `x` | refused, unbounded | no (a different rule) |
| `function f<T>(x: T, n: i32)` | runs | no (an annotated generic stays polymorphic) |
