### D3265 — a brace whose first statement is a labelled block opening with another labelled block parsed as an object literal

**closed 2026-09-29 (`labelBraceOpensStmt` in `compiler/parser.vl` decides a leading `name: {` recursively, and a token no object field starts with opens statements) · was a parse error of a legal program, clause 2, new with #3293 · plumb PL-077 (chunk_97/98/99) · filed against master `569caa36c` · fixture `tests/cases/loops/labelled-block-nested-first.vl`**

Repro:

    function f(c: boolean) {
      let n = 0
      {
        B: {
          C: {
            n = 2
            break :B
          }
        }
      }
      n
    }
    print(f(true))
    // was: parse error, expected `}` but found `=`
    // now: prints 2

Want:

    2

#### Mechanism

A `{` in a body that may be an object literal (a bare statement block, an `else` body, a function
or lambda body, a top-level block) asks `looksLikeObject`; `if`, loop and `match`-arm bodies call
`parseBlock` directly, which is why they never failed. For `{ B: { … } }` it asks
`labelBraceOpensStmt` whether the inner brace holds statements, and that looked at one token: a
name followed by `:` read as an object key, so `B: { C: { n = 2 } }` and `B: { { … } }` made the
outer brace an object. The inner brace is now decided the same way before the outer one, and a
first token no object field can start with (anything but a name, `type`, a string or `}`) is a
statement. `{ a: { type: 1 } }` read as a `type` declaration there and is an object again.
