### D5343 — `==` over a record whose nested record holds a list of records reserves no compare frame

**closed · was loud emit reject · `vl check` rc 0 · clause 2 · found closing D5282 · filed 2026-10-17 against master `cd07cb6a8`**

Repro:

    type S = { k: i32, name: string }
    type C = { ss: S[] }
    type T = { v: i32, sub: C }
    const a: T = { v: 1, sub: { ss: [{ k: 2, name: "x" }] } }
    const b: T = { v: 1, sub: { ss: [{ k: 2, name: "x" }] } }
    print(a == b)
    // vl check: rc 0.  vl run: emitProgram: list compare frame was not reserved for this rep

Want:

    true

#### Mechanism

The inline record compare walks a nested record's fields, so `sub.ss` compares through the
list core of `S`. The frame scan for a record `==` walked only the top row's own fields, so
no frame was reserved for a list one record down. The scan now follows nested-record fields,
each row once (`leqNoteStructRowFields`).
