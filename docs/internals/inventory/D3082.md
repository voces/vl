### D3082 — a `<T>` for-in over a list literal mixing an element read with the parameter prints the `i32` cell at a `boolean` or literal-union pin

**closed 2026-09-28 — the witness prints `true` twice` · was check-clean silently wrong · `valueReadPinTy` reads a loop variable at its list's element pin and `arrLitReadsPinTy` compares element pins by `tyEq`, so `iterElemPinTy` answers a literal mixing reads, locals and the parameter · grid rows graded against master `d408f2da4`, 0 runs lost · fixture `tests/cases/generics/for-in-over-mixed-reads-at-pin.vl` · first filed as: check-clean silently wrong · clause 1 · the D3065 residue, found by the #3269 review · the same on master `67ca68cf3` · filed 2026-09-28 against master `67ca68cf3`**

Repro:

    function f<T>(x: T) {
      const l = [x]
      for e in [l[0], x] { print(e) }
    }
    const t: boolean | null = true
    f(t)
    // vl check: rc 0.  vl run: prints `1` twice

Want:

    true
    true

#### Mechanism

`iterElemPinTy` answered a literal of element reads or locals (`arrLitReadsPinTy`) only when every element's pin was the same type index, and `valueReadPinTy` had no answer for a loop variable. It now compares element pins by `tyEq` and reads a loop variable at its list's element pin, and a `.filter` or `.slice` receiver answers its receiver's element.
