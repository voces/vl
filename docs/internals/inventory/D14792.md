### D14792 — a `?.` method call on a `string | null` value that may be `null` builds invalid wasm

**closed 2026-11-01 by the `?.` rewrite giving a built-in method call the receiver's non-null clone in the guarded arm, as it already gave a UFCS call · the witness prints `null`, `true` · was check-clean invalid wasm, clause 1, on master `4c4e4225f` · fixture `tests/cases/strings/optional-builtin-method-on-nullable-receiver.vl` · found by step 4's tail-value grid around D3466 · filed 2026-11-01 against master `4c4e4225f`**

Repro:

    function g(a: string | null) { print(a?.includes("b")) }
    g(null)
    g("abc")
    // vl check: rc 0.  vl run: invalid module, expected (ref $string), found (ref null $string)

Want:

    null
    true

#### Mechanism

`drwWalk` desugars `recv?.m(args)` into `if recv != null { recv.m(args) } else { null }`. A
UFCS call took a fresh receiver at its non-null type for the guarded arm, but a built-in method
kept the original `recv` node, which the checker types nullable, so the arm handed the
emitter's string lowering a `ref null` receiver. A user `self` method (the UFCS path) ran.
