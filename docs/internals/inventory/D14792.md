### D14792 — a `?.` method call on a `string | null` value that may be `null` builds invalid wasm

**check-clean invalid wasm · clause 1 · open · pre-existing on master `4c4e4225f` · found by step 4's tail-value grid around D3466 · filed 2026-11-01 against master `4c4e4225f`**

Repro:

    function g(a: string | null) { print(a?.includes("b")) }
    g(null)
    g("abc")
    // vl check: rc 0.  vl run: invalid module, expected (ref $string), found (ref null $string)

Want:

    null
    true

#### Mechanism

Not yet traced. The validator reports the string method's `self` receiving a `ref null` string,
so the call arm of the `?.` lowering is handed the operand before its null test narrows it. The
ablation is what is known: a receiver that may really be `null` at the call is the ingredient.

#### Ablation

| ingredient changed | outcome | needed? |
| --- | --- | --- |
| a receiver narrowed to `string` (`let a: string \| null = null; a = "abc"`) | runs, prints `true` | **yes** |
| a `let` holding `null` instead of the parameter | same invalid wasm | no |
| the read inside a closure (`const f = () => a?.includes("b")`) | same invalid wasm | no |
| the result bound (`const r = a?.includes("b")`) instead of printed | same invalid wasm | no |
| `?.slice(0, 1)` instead of `?.includes` | same invalid wasm | no |
| an `i32[] \| null` receiver (`?.includes(1)`) | check reject | — |
