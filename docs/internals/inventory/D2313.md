### D2313 — a `for`-in map walk read its map's `live` and `vals` through the shared mapRef scratch, which any same-shape map op in the body overwrote

**closed 2026-09-24 — the witness prints `40`. Reported by plumb as PL-035 (`~/plumb/docs/vl-issues.md`);
filed against master `403fcd5e8`, where it loads then traps with `index outside the bounds of an
array`. Not a regression from D2280/D2291: an archive build of `2d8341305` (before #3101), of
`a8a104432` (2026-09-08) and of `042624e1b` (2026-08-29) all trap the same way, and the shape
of the read dates from the tombstone skip (#316)**

Repro:

    import { toString } from "std:fmt"
    const m: {[string]: i32} = Map()
    for i in 0 until 40 { m["k" + toString(i)] = i }
    const d: {[string]: boolean} = Map()
    for r in 0 until 3 {
      for k, v in m { if !d.has(k) { d[k] = true } }
    }
    print(d.size)
    // prints 40

#### Mechanism

`emitForInStmt` evaluated the walked map once into the op's mapRef local (`cmMapRefLocal()`),
then read `M.live[cursor]` for the tombstone skip and `M.vals` for the pair's value off that
local on EVERY step. But the mapRef local is a per-shape scratch slot shared by every map op in
the function (`mapScratchBase`, or the mv slot's frame for a ref-valued map), and `d.has(k)` /
`d[k] = …` store `d` into it. From the second step on, the walk read `d.live[cursor]` and
`d.vals[cursor]`: out of bounds while `d` is shorter than `m`, and silently wrong once it is
not. Master printed `3` and `0` for the compaction leg of the fixture, no trap. The walk now
mints a fresh `(ref null <mapTy>)` lazy-frame slot per loop (`forInMapStashSlot`, `liBack` 22)
and reads `live` and `vals` from it; the -O3 modules of the three map benches are byte-identical.

#### Ablation

| ingredient removed | outcome | needed? |
| --- | --- | --- |
| the body's map op (walk `m` alone) | runs | **yes** |
| `d` sharing `m`'s shape (`{[string]: string}` for `d`) | runs, separate mapRef slot | **yes** |
| the pair (`for k in m` with `m[k]`) | still traps | no |
| the string key (`{[i32]: i32}` / `{[i32]: boolean}`) | still traps | no |
| the insert (`d.has(k)` only, or `d.delete(k)`) | still traps | no |
| the outer `for r` loop | still traps | no |
