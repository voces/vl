### D15244 — a function delivered to a wider-number record both directly and through another function returns a record of its own row from a function built wide

**closed · runs, prints `12000000003` · was check-clean invalid wasm, clause 1 · found closing [D15216](D15216.md) · filed 2026-11-04 against master `fc6645cfd` · closed 2026-11-04: the call arm's last delivery push (check_fit_rules.vl) kept `fb` and `g` at `R`, though `fb` only relays `mk()`, which `own` keeps at its own row; `fb` was emitted at its own row while `litKeptCallRep` stamped the `fb()` in `g` at `R`. That push now leaves a function to its converting copy when a value leaf calls a function that cannot be built at the destination (`recRelayLeavesToCopy`, D15216's per-leaf test), so both deliveries copy**

Repro:

    type R = { n: i64, s: string }
    function mk() { { n: 3, s: "a" } }
    const own = mk()
    const ownN: i32 = own.n + 1
    function fb() { mk() }
    const vb: R = fb()
    function g() { fb() }
    const vg: R = g()
    print(vg.n * 4000000000 + vb.n)

Want:

    12000000003

#### Mechanism

`mk` is read at its own row by `own` (`n: i32`), and `fb` hands back `mk()`. `fb` is delivered
to `R` (`n: i64`) twice: directly at `vb` and through `g` at `vg`. On master the module fails inside
`fb`; with D15216's rule, which keeps `fb` and `g` from being built wide by `recFnBuiltAtDst`, it
fails inside `g` instead: `g`'s result is `R`'s struct while the `fb()` it tail-calls returns
`mk`'s own row. A probe on `recFnBuiltAtDst`'s success path never fires for this program, so
another producer builds `g`'s result at `R`. Measured on 2026-11-04: the call arm's last
`recAdPushDecl` keeps both `fb` and `g` at `R`; `fb`'s emission keeps its own row, because it
returns `mk()`, while `litKeptCallRep` reads `fb`'s kept record for the `fb()` call `g` returns.

| --- | --- | --- |

| `g` and `vg` (`fb` delivered only directly) | runs | **yes** |
