### D17742 — a record literal of an uncalled hole function's closure pushed or stored into a nested holder reaches mono at its open type

**runs, prints `9` — CLOSED 2026-11-27: `monoDeliverLitAtPlace` delivers a pushed or stored list or record literal at its own closed stamp where the place's type is still open; pinned by `tests/cases/closures/uncalled-hole-fn-holder-literal-pushed-or-stored.vl`. Was: loud emit reject · filed 2026-11-27 against master `1458514a` · owner COV-CLOS-3**

Repro:

    function inc0(a) { return a + 1 }
    const r = [[{ n: 7, fs: [inc0] }]]
    r[0].push({ n: 9, fs: [inc0] })
    print(r[0][1].n)
    // vl check: rc 0.  vl run: emit error, "cannot take the generic function `inc0` as a value"

Want:

    9

#### Mechanism

Mono coerces a hole function's value inside a literal (`monoCoerceLitPart`) only at the
positions it routes there; a record literal handed straight to `push`, or stored by `r[0][0] =`,
is not one, so `inc0` is emitted as the template's closure. Neighbours that run: the record bound
first (`const x = {…}; r[0].push(x)`) and a list literal pushed (`r.push([{…}])`). On master the
holder's own declaration fails first (D17384).

#### Grading list

`r[0][0] = { n: 9, fs: [inc0] }` (store), `r[0].push({ n: 9, fs: [inc0] })` (push).
