### D15756 — a function stored in two maps, one map in an annotated list literal and the other in an un-annotated one, is refused at emit

**open · loud emit reject · `monoPinMapValues: the map's stored functions close at another type than its slot fact` · clause 2 · either list alone runs once the annotated one's map closes at its delivery (D15752's close, #7490), as do both lists annotated and the same function in two function lists · found by lane w321 closing D15754, grading `two-map-lists-sharing-a-smaller-set.matrix.vl` (every annotated cell) · filed 2026-11-12 against master `c3c39e3c1`**

Repro:

    function half(a) { return a / 2.0 }
    const m1 = Map()
    m1.set("a", half)
    const m4 = Map()
    m4.set("a", half)
    const ys = [m4]
    const v: ({ [string]: (a: f64) => f64 })[] = [m1]
    const g = v[0].get("a")
    if g != null { print(g(3)) }
    // vl check: rc 0.  vl run: monoPinMapValues refusal

Want:

    1.5

#### Mechanism

Not yet traced. `half` is held by `m1`, delivered at `(f64) => f64`, and by `m4`, an element of an
un-annotated list literal that nothing pins. With D15752's close (#7490) and D15754's applied, the
refusal moves to `emitProgram: ref valtype with no interned shape`: the program then needs `half`
at two signatures across two map storages, and the un-annotated list's row keys none. The
refusal names a mechanism, not a contract.
