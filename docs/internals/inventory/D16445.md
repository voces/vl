#### Mechanism

D16444 copies a spread's call into the list's element. A binding of the call cannot take that
copy: the binding's row is read from its initialiser (`listRowOfExpr`), the call's own `{x: i32}`
list, so a copy at the initialiser builds an invalid module. A maker called once is instead built
where its call lands (D3444): delivering the call into the literal's element list builds the
maker's returned literal there, so the binding itself is the `{x: f64}` list and still shares its
records with the spread. Disassembly: the maker's literal is `f64.const 1`, both globals the
`{x: f64}` list's row, no copy loop.
