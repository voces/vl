### D2944 — a lambda capturing an element read off a hole parameter at a `boolean[]` pin prints `1`

**closed 2026-09-28 — the filed repro prints `true` · was check-clean silently wrong, clause 1, the same on master `8615a730d` · closed with [D2943](D2943.md), by reading an element-value derivation off a hole at the instance's binding · filed 2026-09-28 against master `cab9694f8`**

Repro:

    function h(x) {
      const y0 = x[0]
      const k = () => y0
      print(k())
    }
    const v: boolean[] = [true]
    h(v)
    // vl check: rc 0.  vl run: prints `1`

Want:

    true

#### Mechanism

The call `k()` is typed at `y0`'s type, the element-value derivation off the hole (`HD_ELEMV`),
which `holePinReadOf` did not follow, so `exprIsBool` could not read it at the instance and
`print` took the `i32` path. The mechanism is [D2943](D2943.md)'s; the same close covers the
capture at `(boolean | null)[]` (printed `2`), `f32[]` (invalid wasm) and `("a" | "b")[]` (a loud
emit reject), which now print `null`, `1.5` and `b`.

| --- | --- | --- |

| `h(x: boolean[])` | runs, `true` | **yes** (the hole) |
