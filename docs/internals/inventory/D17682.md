Deleting `getField`'s AST rung outright (the ruling's last step) breaks 6,057 distilled classes and the self-compile: most receivers have no row, so the rung stays · fixture `tests/cases/functions/hole-param-returned-at-its-delivered-row-positions.vl` (`fieldClosureDirect`, `fieldClosureAlone`)**

Repro:

    type J = { f: i32 | null }
    function mk2() { return { f: null } }
    const dA: J = mk2()
    function viaField(y) {
      const h = { w: y }
      const o = { b: () => y }
      return o.b().f == null
    }
    print(viaField(mk2()))
    // vl check: rc 0.  vl run: invalid module (expected `{f:null}`, found `J`)

Want:

    true

#### Mechanism

`viaField`'s hole parameter `y` is stored at `J`'s row (D15173's key), and the lambda returns it
there (D17676). The record field `b` keys its closure's signature by the field's type, whose
result is `{f:null}`'s row, so the call through the field reads a `J` value at `{f:null}`. A
lambda bound to a local is keyed by the lambda (`capRowLetFe`); one held in a field is not.

#### Finding (COV-CALL, 2026-11-28, master `883733f8f`, time-boxed)

Spelling 1 (the repro, `o.b().f`): the `.f` read is an `RGetField`, which lowers through
`getField` (ir_lower.vl). That takes its struct from the receiver temp's row (`recvStructRow`, the
call temp's `irVarRow`/`irVarHeapOf`), and otherwise from the AST (`fieldIdxAt` on `gfAt`, the
checked `{f:null}` of `o.b()`). Stamping the call at the capture row in the elaboration
(`elabCallReadRow` taking a `Member` callee: the call is stamped at `J`'s row) did not move the
failure. Typing the call at the capture row in the builder (`exprTyOf`, for a call through a
closure field) did not move it either. The row the struct read takes is therefore the lowering's
AST rung over `m.memObj`, the next thing to make the call's stamped row.

Second hour, on that step (coordinator ruling: `getField` reads the receiver's row as its one
reader). A probe at `getField` shows the receiver, the call's temp, has no row:
`recvStructRow` is -1, `irVarRow` and `irVarHeapOf` are -1. So the AST rung decides, as filed.
The temp has no row because it is built at `{f:null}`'s record: rep 6, type 349. `J` is rep 4,
type 335.
- The capture row is known at the call: a `fieldCallCaptureRow(ix)` (emit_classify.vl, reading
  `capRowFieldFe`) answers row 0, which is `J`.
- `exprTyOf` answering that row's type moves `outTyOf` nothing: the temp is still built by
  `irBLetTemp` at rep 6, type 349.
- Keeping the rep in `rowlessRecordRep` for such a call moved nothing either.
- So the rep is decided in `valueExpr`'s rep choice (the `own`/`pr`/`mr` ladder), upstream of
  `exprRepOf`. That ladder is next. Then the temp is noted at the row (`irBNoteRow`), so
  `recvStructRow` answers it and the AST rung can be deleted.
Both attempts were reverted; the probes ran on master `ccc3531ee`.

Spelling 2 (no `h`): `viaField`'s miss is the stack order. The pending temps are `o.b`'s field
read and the call, ahead of two temps the compare consumes. A prototype general spill (a temp the
stack cannot hold in order gets a local of its own, then the body is lowered again) gets past it:
it spills the call's temp. The spill local then cannot be declared, because the call's temp is
typed at `{f:null}`, a record with no interned row (`ref valtype with no interned shape`). That is
spelling 1's mismatch, so spelling 2 waits on spelling 1. No other live program is refused
`non-stack temp` (`check-filed-witnesses`: D17082, D17420 and D17730 all run), so the spill has
no witness of its own yet and is not landed.


The general spill was prototyped and dropped (coordinator ruling): spelling 2 runs without it
once spelling 1's call temp takes its stamped row, and no live program needs it. The prototype is
commit `f8ed7c179` (branch `cov-call-spill-dropped`, one diff to `compiler/ir_lower.vl` on master
`78f357f58`), kept in case a program turns up that the stack order refuses.
