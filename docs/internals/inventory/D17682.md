### D17682 — a hole function returning its own parameter, which the caller's hole stores at another record's row, builds a module that fails to validate

**check-clean invalid wasm · 2 spellings · filed 2026-11-26 against master `9044360b6` by COV-CLOS, found writing D17676's positions**

Repro:

    type J = { f: i32 | null }
    function mk2() { return { f: null } }
    const dA: J = mk2()
    function top(y) { return y }
    function tb(y) {
      const h = { w: y }
      return top(y).f == null
    }
    print(tb(mk2()))
    // vl check: rc 0.  vl run: invalid module (expected `{f:null}`, found `J`)

Want:

    true

#### Mechanism

The sibling of D17676 without a closure. `tb`'s hole parameter `y` is stored at `J`'s row (D15173's
key). `top` returns its parameter, whose result is read at the type's own row, `{f:null}`. D17676
moves a closure's result to its capture slot's row (`fnRetCaptureRow`); a function returning its
own parameter, held at another row, has no such rule. The same holds when the call's result is
bound to a local or held in a record field, closure or not (`const r = top(y)`, `{ v: b() }`).
