### D3211 — two bindings of one name holding joins of a type parameter at different types read each other's slot inside an instance

**closed 2026-09-29 · was a loud emit reject, clause 2, on master `94670f728` · found by the GU lane re-grading the rv3236 `k3` grid's `shadow` cells · fixture `tests/cases/generics/gradual-type-parameter-union.vl`**

Repro:

    function g<T>(a: T, c: boolean) {
      if c {
        const r = if c { a } else { "s" }
        print(r)
      }
      const r = if c { a } else { 5 }
      print(r)
    }
    const u: i32 | null = 7
    g(u, true)
    g(u, false)
    // master: emitProgram: print of a union value whose arms the tag dispatch cannot classify

Want:

    7
    7
    5

#### Mechanism

An instance shares the template's name reads, which keep the template's type, so the emitter
answers a read of `r` by the name's slot. The two `r`s are a `i32 | null | string` box and an
`i32 | null` niche at this pin, and each read took the other's plan. A read of a binding whose
template type is a join of a type parameter kept apart (`T | string`, `T | i32`) is now re-typed
at the instance's pin, so the read carries its own type.
