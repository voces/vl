### D2868 — a spread into a list literal whose element is a union copies the source list without boxing its elements

**check-clean invalid wasm · clause 1 · the filed record face (`const q: S[] = [...a]`) runs since D2869's boxing spread; the repro is now the literal-union face, the same on master `8e10ef58b` · found closing D2845 · filed 2026-09-27 against master `1df19732b`**

Repro:

    type K = "x" | "y"
    const ks: K[] = ["x"]
    const q: string[] = [...ks, "z"]
    print(q[1])
    // vl check: rc 0.  vl run: invalid module in the top-level code

Want:

    z

#### Mechanism

`emitArrSpread` builds the literal at its first source's rep and joins the groups with one
`array.copy`. When the literal's element is a union, each source element has to be boxed into
it, and no per-element boxing copy exists. The un-annotated face (`[...bools, 2]`, typed
`(boolean | i32)[]`, and `[...ints, "s"]`, `[...ints, null]`, `[...cs, d]`) is refused loudly
since D2845 (`spreadBoxingSource`): it was invalid or loud on master. A nullable-ref element
shares the source's storage and runs (`[...cs, null]`). The annotated face above still reaches
the copy, because the literal's recorded type is the source's list and only the destination
names the union. D2869 closed that face for a destination that threads a list of union boxes:
the record and scalar sources are boxed per element there. Still open: a literal-union list
spread into a `string[]` (this repro), whose atoms need re-encoding as strings rather than
boxing, and the un-annotated faces, which stay refused because nothing threads their row.

#### Ablation

| ingredient changed | outcome | needed? |
| --- | --- | --- |

| a nullable element (`[...a, null]`) | runs | **yes** |
| a scalar source into a scalar list (`[...ints, 2.5]`) | runs (D2845) | **yes** |
