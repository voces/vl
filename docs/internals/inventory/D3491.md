### D3491 — a function declared to RETURN a literal union with a member past `i32` is invalid wasm, while a binding, a field and a lambda of the same type run

**closed 2026-10-03 — the witness prints `9000000000` · was check-clean invalid wasm, clause 1 · found by lane FR5 while grading the D3320 family · filed 2026-10-03 against master `937445a42`, closed against master `878f6ebe8` · fixtures `tests/cases/literal-unions/mixed-width-litunion-function-boundary.vl`, `tests/cases/generics/union-alias-pin-eq-needle.vl`**

Repro:

    type D = 9000000000 | 1
    function f(): D { return ds[1] }
    const ds: D[] = [1, 9000000000]
    print(f())
    // vl check: rc 0.  vl run: invalid module, "the emitted module failed to validate inside `f`:
    // type mismatch: expected i32, found (ref $type)"

Want:

    9000000000

#### Mechanism

Confirmed by the close (lane LU). Two producers disagreed about the rep. `isValueUnionBox`
called an all-integer-literal union homogeneous by `litKind` alone, so the annotation ladder
(`repOfTy` → `vtKindOfType`) gave a declared parameter or result the `"i32"` fall-through,
while the binding, field and element paths boxed the same type as `i32 | i64`, since
`softenLitTy` declines to soften members of two bases. The predicate now compares each
member's base scalar (`litBaseTy`), so the signature boxes too. A lambda's result had looked
like it ran only because `(): D => 1` returned an unboxed `i32` that `print` then read as one;
`(): D => 9000000000` was the same defect. A delivery of the box into an `i64` (D3320) needed
the second half: `emitExprAsI64` and its two float siblings now convert out of an
integer-literal union over two bases member by member (`intLitUnionBasesOf`, `njWidensOut`),
since that union mints no numeric union for the `numUnionMinted` gate to see.

The record of the filing, kept for the ablation below: The ablation places the defect at a DECLARED function RESULT of
the literal union, not at the list element read: `return 1` and `return 9000000000` fail the
same way, as does `g(d: D): D { return d }` called with `1`, while the same union as a binding,
a record field, a list element and a lambda's result all run. The mixed-width union has two
candidate reps (an `i32` niche when every member fits, a wider one when a member does not), and
the function signature and its caller's reading of the result disagree about which. A
PARAMETER of type `D` is a different position: `g(1)` runs, `g(9000000000)` is D3320's defect,
and a `D`-typed binding passed in (`const x: D = 1; g(x)`) is invalid wasm with a
`(ref $type)` mismatch, which this row does not claim to explain.
