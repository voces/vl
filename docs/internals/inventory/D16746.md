### D16746 — a `for i in a until b` loop indexing an un-annotated list parameter is refused at emit with an internal message

**closed 2026-11-16 · runs, prints `2` `3` · fixed by lane AE4: each mono rewrite that rebuilds a range loop records the copy as standing for the template's loop (`monoCopyOf`), so the instance frame gives the template's loop variable its slot · fixture `tests/cases/loops/range-loop-in-hole-instance.vl` · was loud emit reject · clause 1 (check accepts what emit refuses) and clause 2 · found closing [D16744](D16744.md) · filed 2026-11-16 against master `7de99c68a`**

Repro:

    function run(xs) { for i in 0 until 2 { print(xs[i] + 1) } }
    run([1, 2])
    // vl check: rc 0.  vl run: emit error, "emitProgram: identifier is not a parameter, local, or global"

Want:

    2
    3

#### Mechanism

A range loop is its own variable's declaration. When an instance's body is rewritten, mono
rebuilds a loop whose body changed with a plain `mkForRange`. The rewrite passes are
`monoCloneBodyRaw`, `monoPinBodyLambdasRaw`, `monoPinMapLambdas`, `monoBakeCallback`,
`monoCloneGenericCallsRaw`, `monoPinBinOps` and `monoFoldLayoutAt`. The loop variable's reads
are shared and still name the template's loop, but the frame gave its slot to the copy, with no
origin to map back (`declaredSlotOfDecl`). A `for x in xs` loop keeps its `LoopVar` declaration
node, and a copied `let` goes through `monoCopyOf`, so both resolved. Any element read of the
parameter forces the rewrite, which is why `xs[0] + i` fails as well as `xs[i]`. Each rebuild
now goes through `monoCopyOf`, which records the origin, and the frame registers both.

#### Ablation

| ingredient changed | outcome | needed? |
| --- | --- | --- |
| parameter annotated `xs: i32[]` | runs | **yes** |
| the element read dropped (`print(i)`) | runs | **yes** |
| the bound `xs.length` or a `const n` instead of `2` | still refused | no |
| `xs[0] + i` instead of `xs[i]` | still refused | no |
| elements functions instead of numbers | still refused | no |

#### Grading list

- `for i in 0 until xs.length { print(xs[i](3)) }` over a list of functions.
