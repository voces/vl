### D16424 — a call of an un-annotated function above its declaration, pushing a record with an empty list field onto its `[]` argument, is refused by the monomorphizer

**loud emit reject · clause 2 · `emitProgram: monomorphize: unsupported argument type` · a declaration-order face of D16301 · found grading D16421's close with `scripts/decl-order-ab.vl` · filed 2026-11-15 against master `b1c8cb00` · open**

Repro:

    g([])
    function g(a) { a.push({ ys: [] }); print(a[0].ys.length) }
    // vl run: emitProgram: monomorphize: unsupported argument type for `a` in a call to `g`

Want:

    0

#### Mechanism

Not yet located. With the declaration first it runs, so the argument's `[]` gets the record
element at the call in that order only. D16421's pin of a body's own lists at the call is
withheld from a call above its callee's declaration, since there pinning the record's field
alone builds an invalid module instead of this refusal.

#### Ablation

| ingredient changed | outcome | needed? |
| --- | --- | --- |
| the declaration first | prints `0` | **yes** (the order) |
| `{ y: 0.5 }`, no list field | runs | **yes** (a list field) |
| `a.push([])`, a bare list | runs | **yes** (a record) |
| `function g(a: { ys: f64[] }[])` | runs | **yes** (the hole parameter) |
| `a[0].ys.push(0.5)` or `push(5)` after the push | the same refusal | no |
