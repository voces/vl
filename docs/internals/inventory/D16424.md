### D16424 — a call of an un-annotated function above its declaration, pushing a record with an empty list field onto its `[]` argument, is refused by the monomorphizer

**closed 2026-11-15 — the witness runs and prints `0` · runs today and must keep running, an L2 acceptance witness ([engineering-review-2026-11.md](../engineering-review-2026-11.md) §6, L2) · was: loud emit reject · clause 2 · `emitProgram: monomorphize: unsupported argument type` · a declaration-order face of D16301 · found grading D16421's close with `scripts/decl-order-ab.vl` · filed 2026-11-15 against master `b1c8cb00` · closed with [D16426](D16426.md): a later-declared function that writes an element into an un-annotated parameter is checked before the statement that calls it, and the call's pins of the body's lists no longer wait for the declaration · fixture `tests/cases/closures/hole-param-record-pushed-above-its-declaration.vl` (`pushIntoEmpty`)**

Repro:

    g([])
    function g(a) { a.push({ ys: [] }); print(a[0].ys.length) }
    // was: vl run: emitProgram: monomorphize: unsupported argument type for `a` in a call to `g`

Want:

    0

#### Mechanism

With the declaration first it runs, so the argument's `[]` gets the record element at the call
in that order only. Above the declaration the body was checked after the call, so the call had no
deferred push to replay, and D16421's pin of the body's own lists was withheld there; withholding
it turned an invalid module into this refusal. D16426's close checks the body first and lifts the
withholding, and the two cells below run declarations last.
