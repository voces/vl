### D978 — an `f32` delivered into a union whose only float arm is `f64`: the coerce ladder never asked which arm stores it

**closed — the ladder now asks the union · found by std:fmt's `toStr` growing an `f64` arm (serde stage 0), which made this reachable from the most-used export in std**

`function show(v: i32 | f64)` called with an `f32` binding was `vl check` rc 0 and
`emitProgram: union atom has no value box` — a message that reads like an internal invariant,
so `--sites` never counted it (D964's note about the count being a lower bound).

* **THE LADDER READ THE VALUE, NOT THE DESTINATION.** `exprIsF32` set the coerce atom kind to
  5 unconditionally, so the emitter wanted an f32 value box that a module whose union has no
  f32 arm never mints. The widening is LOSSLESS, so clause 2 says the program must compile —
  narrowing the checker would have been the wrong end state.

* **AND THE SHARED MAPPER WAS THE WRONG PLACE TO FIX IT — the corpus said so.**
  `unionStoreAtomKind` already widens i32 into an `i64` / `f64` / `f32` arm and even f64 into
  f32; adding the f32→f64 direction there moved a case it should not have. `d901_fold_f32_dest`
  — a `{q: f32} | null` whose f32 is a FIELD and not an arm — went **`runs -> loud emit
  reject`**, which the distilled gate blocks on, and the fixture
  `types/coalesce-merged-row-numeric-fold.vl` failed with it. The test is spelled out at the one
  site that needed it instead.

* **THE FIXTURE CHECKS THE VALUE, not just the tag.** `pass(x)` returns the widened `f64` and
  prints `0.5`; a tag-only assertion would pass with a garbage payload. A union that DOES have
  an f32 arm still uses it, and the i32 / f64 arms are unchanged.

Repro (runs, prints `1`):

    function show(v: i32 | f64): i32 {
      if v is f64 { return 1 }
      0
    }
    const x: f32 = 0.5
    print(show(x))
    // PRINTS 1
