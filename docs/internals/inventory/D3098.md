### D3098 — a generic called with a value narrowed out of a `K | i32` box pins its type parameter at the box

**check-clean invalid wasm · clause 1 · the generic twin of [D3076](D3076.md) · 1 cell of the lane-LP lambda grid invalid, 2 more refused at emit · filed 2026-09-28 against master `e1e40ac99`**

Repro:

    type K = "a" | "b"
    function app<T>(x: T, f: (T) => boolean): boolean { return f(x) }
    const q: K | i32 = "a"
    if !(q is i32) { print(app(q, (w: K) => w == "a")) }
    // vl check: rc 0.  vl run: invalid module inside `app`: type mismatch

Want:

    true

#### Mechanism

Not fixed here. The instance of `app` takes `x` as the `K | i32` box and hands it straight to the
lambda, whose `(w: K)` parameter is the `i32` atom: the monomorphiser pins `T` from `q`'s declared
type, not from the narrowed `K` the checker typed the argument at. Un-annotated, the lambda keys
its signature at the pin as well, and the call refuses loudly with `no function value of type
(K|i32)=>boolean` (and `(string)=>boolean` for a walk variable). One mechanism, the pin's source.

#### Ablation

| the lambda un-annotated | loud emit reject, `no function value of type (K\|i32)=>boolean` | no (the other face) |
