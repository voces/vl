### D3098 — a generic called with a value narrowed out of a `K | i32` box pins its type parameter at the box

**closed · narrowing a `K | i32` box to `K`'s members is stamped a copy of `K`, and the monomorphiser pins `T` at the alias · fixture `tests/cases/generics/narrowed-literal-union-pin.vl` · was check-clean invalid wasm · clause 1 · the generic twin of [D3076](D3076.md) · 1 cell of the lane-LP lambda grid invalid, 2 more refused at emit · filed 2026-09-28 against master `e1e40ac99`, closed 2026-09-28 against master `f14a8cca2`**

Repro:

    type K = "a" | "b"
    function app<T>(x: T, f: (T) => boolean): boolean { return f(x) }
    const q: K | i32 = "a"
    if !(q is i32) { print(app(q, (w: K) => w == "a")) }
    // vl check: rc 0.  vl run: invalid module inside `app`: type mismatch

Want:

    true

#### Mechanism

The monomorphiser pinned `T` from `q`'s declared `K | i32`, because the narrowed type's
render softens a literal union to `string` and `monoNarrowedPinName` declined on that. Two
halves: the checker's `litUnionProvSrcAlias` now reads a wider union holding exactly one
literal-union alias (`litUnionMemberAlias`), so the narrowed result is recorded as a copy of
`K`; and `monoNarrowedPinName` answers a softened render with `monoNarrowedLitPinName`, the
alias when it is a member of the wide union. `monoPinAnnSpelling` spells a pinned literal union
by its alias, which keys the un-annotated lambda's signature at `(K)=>boolean`.
