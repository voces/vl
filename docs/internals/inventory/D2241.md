### D2241 — interpolating a hole parameter pinned at `string` is refused at the pin as a `toString` argument

**loud check reject · clause 2 · found while closing D2238 · filed 2026-09-23 against master `f2234c2e5`**

Repro:

    function show(a) { print("v=\{a}") }
    show("s")
    // vl check: rc 1: argument of type string flows into `toString` expecting i32 | i64 |
    // boolean | f64 (the call's argument types)

#### Mechanism

Not yet located. An interpolated hole appears to be checked as a `toString` call whose
parameter set is the numeric and boolean primitives, and the pin re-check then finds a `string`
argument outside it. The annotated parameter (`a: string`) and a `+` concatenation over the same
hole both print `v=s`, and a hole pinned at `5` prints `v=5`, so the refusal is the
interpolation of a string-pinned hole, not string interpolation or the hole.

#### Ablation

| ingredient changed | outcome | needed? |
| --- | --- | --- |
| `a: string` | runs, `v=s` | **yes** |
| `print("v=" + a)` | runs, `v=s` | **yes** |
| `show(5)` | runs, `v=5` | **yes** |
| the hole a `string[]`, interpolating `a[0]` | same refusal | no |
