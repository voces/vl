### D3974 — a narrowed nullable function written by a closure into a non-null annotated capture cell traps

**closed 2026-10-13 by [D4349](D4349.md) · runs, prints P 1 O 2 · was loads then traps · found in review of #3498 (`rv3498/round6/n08`, `n09`) · filed 2026-10-10 against master `56f77d80f` · pins: `tests/cases/closures/nullable-closure-return-fallthrough.vl`**

Repro:

    function inner<U>(u: U) { print("I"); print(u) }
    function other<V>(v: V) { print("O"); print(v) }
    function main() {
      let k: (n: i32) => void = (n: i32) => { print("P"); print(n) }
      const f: ((n: i32) => void) | null = other
      const w = () => { if f != null { k = f } }
      k(1)
      w()
      k(2)
    }
    main()
    // vl check: rc 0.  vl run: prints P 1, then wasm trap: wasm `unreachable` instruction executed in `w`

Want:

    P
    1
    O
    2

#### Mechanism

Not located; D3973 with the cell annotated `(n: i32) => void`. The narrowed read of `f` keeps
its nullable representation where the cell's element is a plain function, and the store in the
closure `w` traps.

#### Close

The closure `w` ends in an else-less `if` that writes a function, so its inferred return is
that function with `null`, and its fall-through was `unreachable` padding: `fnRetNullBearing`
did not answer for a nullable closure. It does since [D4349](D4349.md), as for [D2499](D2499.md).
