### D1567 — a function whose every returned value is a bare `null` has the `null` TYPE, and the `null` type had no rep

**closed 2026-09-03 — the witness runs and prints `none` then `4` · was `loud emit reject` (`emitProgram: bare null needs a struct-typed context`, `vl check` rc 0) · clause 2 · fixed by giving the `null` type the `nullref` rep: a recorder rung in the checker, the `nulnone` `VKind`, and a call-site conversion for the three i32-repped nullable destinations · left loud by [D1563](D1563.md) (#2497), previously papered over by the leaked seed**

Repro (prints `none` then `4`):

    type C = { a: i32, b: i32 }
    function np() {
      return null
    }
    function some(): C | null {
      return { a: 4, b: 5 }
    }
    const v: C | null = np()
    if v != null { print(v.a) } else { print("none") }
    const v2: C | null = some()
    if v2 != null { print(v2.a) } else { print("none") }

#### Mechanism

The checker types `np`'s return `TyPrim:null` — the `null` TYPE, which is not `T | null` for
any `T`. Measured, not inferred from the code: an instrumented `tyToStructStr(er)` at the A20
recorder prints `er=null tag=TyPrim:null` for this function and `er={a: i32, b: i32} | null
tag=TyNullable` for the two-arm `if ok { return null } return { … }` beside it, which is why
the two-arm shape has run since D887 and this one never did.

`null` matches no producer in the recorder's cascade — not `isClassifiableRetName` (six
scalar spellings plus two arrays), not `valueUnionRetName`, not `structUnionRetName` — so no
inferred-return ROW was banked at all. With no row, `emit_collect`'s classifier reads
`inferRetTyAt(-1) == ""`, every arm declines, and `fRetKind` keeps the `"i32"` default it was
seeded with. `emitOneFuncType` therefore writes `(result i32)` and the body's own `null`
reaches `emitNullLitNode` with every seed unset. **The seed state, printed at that node in
both faces:** the annotated `function np(): C | null` arrives with `pendingStructIdx = <C's
row>` (armed by `emitReturnValue`'s `retNulRefFlag` arm) and lowers; the un-annotated one
arrives with `fnRet=-1 inm=? kind=i32 pStruct=-1 pVar=-1 pNulRefHeap=-1` and every niche flag
`false` — nothing at all. That is the whole defect: **an annotation pins the rep, and there
was no producer for the case where inference has to.**

The rep is `nullref` (`(ref null none)`), the bottom of the GC hierarchy — one value, no
fields, and a subtype of every nullable REF valtype. So one result serves a struct, variant,
string, list, map or closure destination with no coercion. The three i32-repped nullables are
NOT its subtypes and are converted at the call: `boolean | null` is the sentinel `2`,
`K | null` the sentinel `-1` (both a `drop` plus the constant, off the same two seeds
`emitNullLitNode` reads), and a value-union destination is the null-TAGGED box whose payload
is the call itself — `nullref` is an `anyref`, so it rides the slot the null tag leaves
unread and the call's side effects still happen.

#### Ablation

Graded on the pre-fix seed, one ingredient per row.

| ingredient removed | outcome | needed? |
| --- | --- | --- |
| the second arm — `if ok { return null } return { a: 1, b: 2 }` | **runs** | **yes** — a `T \| null` inference has a row (D887) |
| `return null` written as the tail `null` | still refuses | no (both spellings) |
| the destination annotation `: C \| null` | still refuses, at the `.a` check | no |
| the destination changed to `string \| null` / `i32[] \| null` / map / closure | still refuses | no |
| the destination changed to `boolean \| null` / `K \| null` / `i32 \| null` | still refuses | no |
| the call put in statement position (`np()`) | still refuses | no |
| an annotated `function np(): C \| null` | **runs** | **yes** — the annotation is the missing producer |
